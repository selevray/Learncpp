25.9 — Découpage d'objets (object slicing)

Revenons sur un exemple vu précédemment :

#include <iostream>
#include <string_view>

class Base
{
protected:
    int m_value{};

public:
    Base(int value)
        : m_value{ value }
    {
    }

    virtual ~Base() = default;

    virtual std::string_view getName() const { return "Base"; }
    int getValue() const { return m_value; }
};

class Derived: public Base
{
public:
    Derived(int value)
        : Base{ value }
    {
    }

   std::string_view getName() const override { return "Derived"; }
};

int main()
{
    Derived derived{ 5 };
    std::cout << "derived is a " << derived.getName() << " and has value " << derived.getValue() << '\n';

    Base& ref{ derived };
    std::cout << "ref is a " << ref.getName() << " and has value " << ref.getValue() << '\n';

    Base* ptr{ &derived };
    std::cout << "ptr is a " << ptr->getName() << " and has value " << ptr->getValue() << '\n';

    return 0;
}

Dans l'exemple ci-dessus, ref est une référence et ptr un pointeur, tous deux vers derived, qui possède une partie Base et une partie Derived. Comme ref et ptr sont de type Base, ils ne peuvent voir que la partie Base de derived : la partie Derived existe toujours, mais elle n'est tout simplement pas visible à travers ref ou ptr. Cependant, grâce aux fonctions virtuelles, on peut accéder à la version la plus dérivée d'une fonction. Par conséquent, le programme ci-dessus affiche :


derived is a Derived and has value 5
ref is a Derived and has value 5
ptr is a Derived and has value 5

Mais que se passe-t-il si, au lieu d'initialiser une référence ou un pointeur de type Base avec un objet Derived, on affecte directement un objet Derived à un objet Base ?

int main()
{
    Derived derived{ 5 };
    Base base{ derived }; // que se passe-t-il ici ?
    std::cout << "base is a " << base.getName() << " and has value " << base.getValue() << '\n';

    return 0;
}

Rappelez-vous que derived possède une partie Base et une partie Derived. Lorsque l'on affecte un objet Derived à un objet Base, seule la partie Base de l'objet Derived est copiée, pas la partie Derived. Dans l'exemple ci-dessus, base reçoit une copie de la partie Base de derived, mais pas de sa partie Derived. Cette partie Derived a été effectivement « découpée » (sliced off). C'est pourquoi l'affectation d'un objet de classe Derived à un objet de classe Base est appelée découpage d'objets (object slicing), ou simplement slicing.

Comme base était et reste un simple Base, le pointeur virtuel de base pointe toujours vers Base. Ainsi, base.getName() se résout en Base::getName().

L'exemple ci-dessus affiche :


base is a Base and has value 5

Utilisé à bon escient, le découpage peut être sans conséquence. Mais employé à tort, il peut provoquer des résultats inattendus de plusieurs façons. Examinons quelques-uns de ces cas.

Découpage et fonctions

Vous pensez peut-être que l'exemple ci-dessus est un peu absurde. Après tout, pourquoi affecter derived à base de cette façon ? Vous ne le feriez probablement pas. Cependant, le découpage se produit beaucoup plus facilement, et souvent par accident, avec les fonctions.

Considérons la fonction suivante :

void printName(const Base base) // note : base passé par valeur, et non par référence
{
    std::cout << "I am a " << base.getName() << '\n';
}

Il s'agit d'une fonction assez simple, dont le paramètre base est un objet const passé par valeur. Si nous appelons cette fonction de la façon suivante :

int main()
{
    Derived d{ 5 };
    printName(d); // oups, je n'ai pas remarqué que c'était un passage par valeur côté appelant

    return 0;
}

Lorsque vous avez écrit ce programme, vous n'avez peut-être pas remarqué que base est un paramètre par valeur, et non par référence. Par conséquent, lors de l'appel printName(d), alors que l'on pourrait s'attendre à ce que base.getName() appelle la fonction virtuelle getName() et affiche « I am a Derived », ce n'est pas ce qui se produit. L'objet Derived d est découpé et seule la partie Base est copiée dans le paramètre base. Lorsque base.getName() s'exécute, même si getName() est virtuelle, il n'existe plus de partie Derived à laquelle la résolution pourrait se rattacher. Par conséquent, ce programme affiche :

I am a Base

Dans ce cas, ce qui s'est passé est assez évident, mais si vos fonctions n'affichent pas d'informations permettant de les identifier de cette façon, la recherche de l'erreur peut se révéler difficile.

Bien sûr, dans cet exemple, le découpage peut être facilement évité en faisant du paramètre de fonction une référence plutôt qu'un passage par valeur (une raison supplémentaire de toujours passer les classes par référence plutôt que par valeur).

void printName(const Base& base) // note : base est maintenant passé par référence
{
    std::cout << "I am a " << base.getName() << '\n';
}

int main()
{
    Derived d{ 5 };
    printName(d);

    return 0;
}

Ce programme affiche :


I am a Derived

Découpage et vecteurs

Autre domaine où les programmeurs débutants rencontrent des difficultés avec le découpage : la tentative d'implémenter le polymorphisme avec std::vector. Considérons le programme suivant :

#include <vector>

int main()
{
    std::vector<Base> v{};
    v.push_back(Base{ 5 });    // ajoute un objet Base à notre vecteur
    v.push_back(Derived{ 6 }); // ajoute un objet Derived à notre vecteur

        // Affiche tous les éléments de notre vecteur
    for (const auto& element : v)
        std::cout << "I am a " << element.getName() << " with value " << element.getValue() << '\n';

    return 0;
}

Ce programme compile sans problème. Mais à l'exécution, il affiche :


I am a Base with value 5
I am a Base with value 6

Comme dans les exemples précédents, parce que std::vector a été déclaré comme un vecteur de type Base, lorsque Derived{ 6 } a été ajouté au vecteur, il a été découpé.

Corriger ce problème est un peu plus délicat. Beaucoup de programmeurs débutants essaient de créer un std::vector de références vers un objet, comme ceci :

std::vector<Base&> v{};

Malheureusement, cela ne compile pas. Les éléments d'un std::vector doivent être affectables, alors qu'une référence ne peut pas être réaffectée (seulement initialisée).

Une façon de résoudre ce problème consiste à créer un vecteur de pointeurs :

#include <iostream>
#include <vector>

int main()
{
    std::vector<Base*> v{};

    Base b{ 5 }; // b et d ne peuvent pas être des objets anonymes
    Derived d{ 6 };

    v.push_back(&b); // ajoute un objet Base à notre vecteur
    v.push_back(&d); // ajoute un objet Derived à notre vecteur

    // Affiche tous les éléments de notre vecteur
    for (const auto* element : v)
        std::cout << "I am a " << element->getName() << " with value " << element->getValue() << '\n';

    return 0;
}

Ce programme affiche :


I am a Base with value 5
I am a Derived with value 6

ce qui fonctionne ! Quelques remarques à ce sujet. Premièrement, nullptr est maintenant une valeur possible, ce qui peut être souhaitable ou non. Deuxièmement, il faut maintenant gérer la sémantique des pointeurs, ce qui peut être pénible. Mais l'avantage est que l'utilisation de pointeurs permet de placer dans le vecteur des objets alloués dynamiquement (n'oubliez simplement pas de les supprimer explicitement avec delete).

Une autre option consiste à utiliser std::reference_wrapper, une classe qui imite une référence réaffectable :

#include <functional> // pour std::reference_wrapper
#include <iostream>
#include <string_view>
#include <vector>

class Base
{
protected:
    int m_value{};

public:
    Base(int value)
        : m_value{ value }
    {
    }
    virtual ~Base() = default;

    virtual std::string_view getName() const { return "Base"; }
    int getValue() const { return m_value; }
};

class Derived : public Base
{
public:
    Derived(int value)
        : Base{ value }
    {
    }

    std::string_view getName() const override { return "Derived"; }
};

int main()
{
    std::vector<std::reference_wrapper<Base>> v{}; // un vecteur de références réaffectables vers Base

    Base b{ 5 }; // b et d ne peuvent pas être des objets anonymes
    Derived d{ 6 };

    v.push_back(b); // ajoute un objet Base à notre vecteur
    v.push_back(d); // ajoute un objet Derived à notre vecteur

    // Affiche tous les éléments de notre vecteur
    // on utilise .get() pour extraire l'élément du std::reference_wrapper
    for (const auto& element : v) // element a le type const std::reference_wrapper<Base>&
        std::cout << "I am a " << element.get().getName() << " with value " << element.get().getValue() << '\n';

    return 0;
}

Le Frankenobjet

Dans les exemples précédents, nous avons vu des cas où le découpage a conduit à un mauvais résultat parce que la partie dérivée avait été supprimée. Examinons maintenant un autre cas dangereux, où l'objet dérivé existe encore !

Considérons le code suivant :

int main()
{
    Derived d1{ 5 };
    Derived d2{ 6 };
    Base& b{ d2 };

    b = d1; // cette ligne pose problème

    return 0;
}

Les trois premières lignes de la fonction sont assez directes : on crée deux objets Derived et on fait pointer une référence de type Base vers le second.

C'est à la quatrième ligne que les choses se gâtent. Comme b référence d2 et que nous affectons d1 à b, on pourrait penser que d1 serait copié dans d2, et ce serait effectivement le cas si b était un Derived. Mais b est un Base, et l'opérateur operator= que C++ fournit pour les classes n'est pas virtuel par défaut. Par conséquent, c'est l'opérateur d'affectation qui copie un Base qui est invoqué, et seule la partie Base de d1 est copiée dans d2.

Le résultat est que d2 contient maintenant la partie Base de d1 et la partie Derived de d2. Dans cet exemple particulier, ce n'est pas un problème (puisque la classe Derived n'a pas de données propres), mais dans la plupart des cas, vous aurez créé un Frankenobjet, composé de morceaux de plusieurs objets.

Pire encore, il n'existe pas de moyen simple d'empêcher cela (à part éviter autant que possible ce genre d'affectations).

Astuce

Si la classe Base n'est pas conçue pour être instanciée seule (par exemple, s'il s'agit simplement d'une classe d'interface), on peut éviter le découpage en rendant la classe Base non copiable (en supprimant le constructeur de copie et l'opérateur d'affectation de Base).

Conclusion

Bien que C++ permette d'affecter des objets dérivés à des objets de base par découpage, cela ne produit en général que des ennuis, et il faut donc éviter autant que possible le découpage. Veillez à ce que les paramètres de vos fonctions soient des références (ou des pointeurs), et évitez tout passage par valeur lorsqu'il s'agit de classes dérivées.
