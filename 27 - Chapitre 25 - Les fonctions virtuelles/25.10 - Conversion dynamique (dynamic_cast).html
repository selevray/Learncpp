25.10 — Conversion dynamique (dynamic_cast)

Au chapitre 10.6 -- Explicit type conversion (casting) and static_cast, nous avons étudié le concept de conversion de type (cast) et l'utilisation de static_cast pour convertir des variables d'un type à un autre.

Dans cette leçon, nous allons poursuivre avec un autre type de conversion : dynamic_cast.

Le besoin de dynamic_cast

Lorsque vous travaillez avec le polymorphisme, vous rencontrerez souvent des cas où vous disposez d'un pointeur vers une classe de base, mais où vous voulez accéder à des informations qui n'existent que dans une classe dérivée.

Considérons le programme suivant (un peu artificiel) :

#include <iostream>
#include <string>
#include <string_view>

class Base
{
protected:
    int m_value{};

public:
    Base(int value)
        : m_value{value}
    {
    }

    virtual ~Base() = default;
};

class Derived : public Base
{
protected:
    std::string m_name{};

public:
    Derived(int value, std::string_view name)
        : Base{value}, m_name{name}
    {
    }

    const std::string& getName() const { return m_name; }
};

Base* getObject(bool returnDerived)
{
    if (returnDerived)
        return new Derived{1, "Apple"};
    else
        return new Base{2};
}

int main()
{
    Base* b{ getObject(true) };

    // comment afficher le nom de l'objet Derived ici, alors que nous n'avons qu'un pointeur Base ?

    delete b;

    return 0;
}

Dans ce programme, la fonction getObject() renvoie toujours un pointeur Base, mais ce pointeur peut pointer soit vers un objet Base, soit vers un objet Derived. Dans le cas où le pointeur Base pointe effectivement vers un objet Derived, comment appeler Derived::getName() ?

Une solution consisterait à ajouter à Base une fonction virtuelle appelée getName() (ainsi nous pourrions l'appeler avec un pointeur ou une référence Base, et elle se résoudrait dynamiquement en Derived::getName()). Mais que renverrait cette fonction si on l'appelait avec un pointeur ou une référence Base pointant en réalité vers un objet Base ? Il n'existe pas vraiment de valeur qui ait un sens. De plus, nous encombrerions la classe Base avec des éléments qui ne devraient réellement concerner que la classe Derived.

Nous savons que C++ vous permet de convertir implicitement un pointeur Derived en pointeur Base (c'est d'ailleurs ce que fait getObject()). Ce processus est parfois appelé upcasting (conversion ascendante). Mais que se passerait-il s'il existait un moyen de reconvertir un pointeur Base en pointeur Derived ? Nous pourrions alors appeler Derived::getName() directement à l'aide de ce pointeur, sans nous soucier de la résolution des fonctions virtuelles.

dynamic_cast

C++ fournit un opérateur de conversion nommé dynamic_cast qui peut être utilisé précisément dans ce but. Bien que les conversions dynamiques aient plusieurs capacités, leur usage le plus courant est de convertir des pointeurs de classe de base en pointeurs de classe dérivée. Ce processus est appelé downcasting (conversion descendante).

L'utilisation de dynamic_cast fonctionne comme celle de static_cast. Voici notre main() précédent, qui utilise un dynamic_cast pour reconvertir notre pointeur Base en pointeur Derived :

int main()
{
    Base* b{ getObject(true) };

    Derived* d{ dynamic_cast<Derived*>(b) }; // utilise un cast dynamique pour convertir le pointeur Base en pointeur Derived

    std::cout << "The name of the Derived is: " << d->getName() << '\n';

    delete b;

    return 0;
}

Ce programme affiche :


The name of the Derived is: Apple

Échec de dynamic_cast

L'exemple ci-dessus fonctionne parce que b pointe effectivement vers un objet Derived, donc la conversion de b en pointeur Derived réussit.

Cependant, nous avons fait une hypothèse très dangereuse : que b pointe vers un objet Derived. Que se passerait-il si b ne pointait pas vers un objet Derived ? Il suffit pour le vérifier de remplacer l'argument de getObject() de true à false. Dans ce cas, getObject() renverra un pointeur Base vers un objet Base. Lorsque nous essaierons de faire un dynamic_cast de celui-ci vers Derived, il échouera, car la conversion ne peut pas être effectuée.

Si un dynamic_cast échoue, le résultat de la conversion est un pointeur nul.

Comme nous n'avons pas vérifié si le résultat était un pointeur nul, nous accédons à d->getName(), ce qui tente de déréférencer un pointeur nul, entraînant un comportement indéfini (probablement un plantage).

Pour rendre ce programme sûr, nous devons nous assurer que le résultat du dynamic_cast a bien réussi :

int main()
{
    Base* b{ getObject(true) };

    Derived* d{ dynamic_cast<Derived*>(b) }; // utilise un cast dynamique pour convertir le pointeur Base en pointeur Derived

    if (d) // vérifie que d n'est pas nul
        std::cout << "The name of the Derived is: " << d->getName() << '\n';

    delete b;

    return 0;
}

Règle

Vérifiez toujours que vos conversions dynamiques ont réussi en testant si le résultat est un pointeur nul.

Notez que, comme dynamic_cast effectue une vérification de cohérence à l'exécution (pour s'assurer que la conversion est possible), son utilisation entraîne une pénalité de performance.

Notez également qu'il existe plusieurs cas où la conversion descendante avec dynamic_cast ne fonctionne pas :

  1. En cas d'héritage protégé (protected) ou privé (private).
  2. Pour les classes qui ne déclarent ni n'héritent aucune fonction virtuelle (et qui n'ont donc pas de table virtuelle).
  3. Dans certains cas impliquant des classes de base virtuelles (consultez cette page pour un exemple de ces cas et la manière de les résoudre).

Conversion descendante avec static_cast

Il s'avère que la conversion descendante peut aussi être réalisée avec static_cast. La principale différence est que static_cast n'effectue aucune vérification de type à l'exécution pour s'assurer que ce que vous faites a un sens. Cela rend static_cast plus rapide, mais plus dangereux. Si vous convertissez un Base* en Derived*, la conversion « réussira » même si le pointeur Base ne pointe pas vers un objet Derived. Cela entraînera un comportement indéfini lorsque vous tenterez d'accéder au pointeur Derived obtenu (qui pointe en réalité vers un objet Base).

Si vous êtes absolument certain que la conversion descendante du pointeur réussira, l'utilisation de static_cast est acceptable. Une façon de vous assurer de connaître le type de l'objet pointé est d'utiliser une fonction virtuelle. Voici une façon (pas très bonne) d'y parvenir :

#include <iostream>
#include <string>
#include <string_view>

// Identifiant de classe
enum class ClassID
{
    base,
    derived
    // D'autres pourront être ajoutés ici plus tard
};

class Base
{
protected:
    int m_value{};

public:
    Base(int value)
        : m_value{value}
    {
    }

    virtual ~Base() = default;
    virtual ClassID getClassID() const { return ClassID::base; }
};

class Derived : public Base
{
protected:
    std::string m_name{};

public:
    Derived(int value, std::string_view name)
        : Base{value}, m_name{name}
    {
    }

    const std::string& getName() const { return m_name; }
    ClassID getClassID() const override { return ClassID::derived; }

};

Base* getObject(bool bReturnDerived)
{
    if (bReturnDerived)
        return new Derived{1, "Apple"};
    else
        return new Base{2};
}

int main()
{
    Base* b{ getObject(true) };

    if (b->getClassID() == ClassID::derived)
    {
        // Nous savons déjà que b pointe vers un objet Derived, donc cela devrait toujours réussir
        Derived* d{ static_cast<Derived*>(b) };
        std::cout << "The name of the Derived is: " << d->getName() << '\n';
    }

    delete b;

    return 0;
}

Mais si vous vous donnez tant de mal pour implémenter cela (et que vous acceptez le coût d'un appel de fonction virtuelle et du traitement de son résultat), autant utiliser directement dynamic_cast.

Considérez aussi ce qui se passerait si notre objet était en réalité une classe dérivée de Derived (appelons-la D2). La vérification b->getClassID() == ClassID::derived ci-dessus échouerait, car getClassId() renverrait ClassID::D2, qui n'est pas égal à ClassID::derived. Or, la conversion dynamique de D2 en Derived réussirait, puisqu'un D2 est un Derived !

dynamic_cast et références

Bien que tous les exemples ci-dessus montrent la conversion dynamique de pointeurs (cas plus courant), dynamic_cast peut aussi être utilisé avec des références. Le fonctionnement est analogue à celui des pointeurs.

#include <iostream>
#include <string>
#include <string_view>

class Base
{
protected:
    int m_value;

public:
    Base(int value)
        : m_value{value}
    {
    }

    virtual ~Base() = default;
};

class Derived : public Base
{
protected:
    std::string m_name;

public:
    Derived(int value, std::string_view name)
        : Base{value}, m_name{name}
    {
    }

    const std::string& getName() const { return m_name; }
};

int main()
{
    Derived apple{1, "Apple"}; // crée une pomme
    Base& b{ apple }; // la référence de base désigne l'objet
    Derived& d{ dynamic_cast<Derived&>(b) }; // conversion dynamique utilisant une référence au lieu d'un pointeur

    std::cout << "The name of the Derived is: " << d.getName() << '\n'; // nous pouvons accéder à Derived::getName via d

    return 0;
}

Comme C++ n'a pas de « référence nulle », dynamic_cast ne peut pas renvoyer de référence nulle en cas d'échec. À la place, si la conversion dynamique d'une référence échoue, une exception de type std::bad_cast est lancée. Nous parlerons des exceptions plus tard dans ce tutoriel.

dynamic_cast ou static_cast

Les nouveaux programmeurs hésitent parfois entre static_cast et dynamic_cast. La réponse est assez simple : utilisez static_cast sauf si vous effectuez une conversion descendante, auquel cas dynamic_cast est généralement le meilleur choix. Cependant, vous devriez aussi envisager d'éviter toute conversion et d'utiliser simplement des fonctions virtuelles.

Conversion descendante ou fonctions virtuelles

Certains développeurs estiment que dynamic_cast est un mal et révèle une mauvaise conception de classes. Ils préconisent plutôt l'usage des fonctions virtuelles.

En général, l'usage d'une fonction virtuelle devrait être préféré à la conversion descendante. Cependant, il existe des situations où la conversion descendante est le meilleur choix :

  • Lorsque vous ne pouvez pas modifier la classe de base pour y ajouter une fonction virtuelle (par exemple parce que la classe de base fait partie de la bibliothèque standard)
  • Lorsque vous avez besoin d'accéder à quelque chose de spécifique à la classe dérivée (par exemple une fonction d'accès qui n'existe que dans la classe dérivée)
  • Lorsque l'ajout d'une fonction virtuelle à la classe de base n'a pas de sens (par exemple parce qu'il n'existe aucune valeur appropriée que la classe de base pourrait renvoyer). Utiliser une fonction virtuelle pure peut être une option ici si vous n'avez pas besoin d'instancier la classe de base.

Attention à dynamic_cast et RTTI

L'identification de type à l'exécution (RTTI, Run-time type information) est une fonctionnalité de C++ qui expose des informations sur le type de données d'un objet à l'exécution. Cette capacité est exploitée par dynamic_cast. Comme la RTTI a un coût non négligeable en mémoire, certains compilateurs permettent de la désactiver comme optimisation. Inutile de dire que, si vous faites cela, dynamic_cast ne fonctionnera plus correctement.
