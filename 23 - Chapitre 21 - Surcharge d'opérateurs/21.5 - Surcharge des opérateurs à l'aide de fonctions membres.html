21.5 — Surcharge des opérateurs à l'aide de fonctions membres

Dans la leçon 21.2 -- Surcharge des opérateurs arithmétiques à l'aide de fonctions amies, vous avez appris à surcharger les opérateurs arithmétiques à l'aide de fonctions amies. Vous avez également appris qu'il est possible de surcharger des opérateurs sous forme de fonctions ordinaires. De nombreux opérateurs peuvent être surchargés d'une autre manière : sous forme de fonction membre.

Surcharger un opérateur à l'aide d'une fonction membre ressemble beaucoup à la surcharge à l'aide d'une fonction amie. Lorsque vous surchargez un opérateur à l'aide d'une fonction membre :

  • L'opérateur surchargé doit être ajouté comme fonction membre de l'opérande de gauche.
  • L'opérande de gauche devient l'objet *this implicite.
  • Tous les autres opérandes deviennent des paramètres de la fonction.

Pour rappel, voici comment nous avons surchargé operator+ à l'aide d'une fonction amie :

#include <iostream>

class Cents
{
private:
    int m_cents {};

public:
    Cents(int cents)
        : m_cents { cents } { }

    // Surcharge de Cents + int
    friend Cents operator+(const Cents& cents, int value);

    int getCents() const { return m_cents; }
};

// remarque : cette fonction n'est pas une fonction membre !
Cents operator+(const Cents& cents, int value)
{
    return Cents(cents.m_cents + value);
}

int main()
{
    const Cents cents1 { 6 };
    const Cents cents2 { cents1 + 2 };
    std::cout << "I have " << cents2.getCents() << " cents.\n";

    return 0;
}

Convertir une surcharge d'opérateur amie en surcharge membre est facile :

  1. L'opérateur surchargé est défini comme membre au lieu d'être amie (Cents::operator+ au lieu de friend operator+).
  2. Le paramètre de gauche est supprimé, car ce paramètre devient désormais l'objet *this implicite.
  3. Dans le corps de la fonction, toutes les références au paramètre de gauche peuvent être supprimées (par exemple, cents.m_cents devient m_cents, qui fait implicitement référence à l'objet *this).

Voici maintenant le même opérateur surchargé à l'aide d'une fonction membre :

#include <iostream>

class Cents
{
private:
    int m_cents {};

public:
    Cents(int cents)
        : m_cents { cents } { }

    // Surcharge de Cents + int
    Cents operator+(int value) const;

    int getCents() const { return m_cents; }
};

// remarque : cette fonction est une fonction membre !
// le paramètre cents de la version amie devient ici le paramètre implicite *this
Cents Cents::operator+ (int value) const
{
    return Cents { m_cents + value };
}

int main()
{
    const Cents cents1 { 6 };
    const Cents cents2 { cents1 + 2 };
    std::cout << "I have " << cents2.getCents() << " cents.\n";

    return 0;
}

Notez que l'utilisation de l'opérateur ne change pas (dans les deux cas, cents1 + 2) : nous avons simplement défini la fonction différemment. Notre fonction amie à deux paramètres devient une fonction membre à un paramètre, le paramètre le plus à gauche de la version amie (cents) devenant le paramètre implicite *this de la version membre.

Examinons de plus près l'évaluation de l'expression cents1 + 2.

Dans la version à fonction amie, l'expression cents1 + 2 devient l'appel de fonction operator+(cents1, 2). Notez qu'il y a deux paramètres. C'est direct.

Dans la version à fonction membre, l'expression cents1 + 2 devient l'appel cents1.operator+(2). Notez qu'il n'y a plus qu'un seul paramètre explicite, et que cents1 est devenu un préfixe d'objet. Cependant, dans la leçon 15.1 -- Le pointeur caché « this » et l'enchaînement des fonctions membres, nous avons mentionné que le compilateur convertit implicitement un préfixe d'objet en un paramètre caché le plus à gauche nommé *this. En réalité, cents1.operator+(2) devient donc operator+(&cents1, 2), ce qui est presque identique à la version amie.

Les deux cas produisent le même résultat, simplement par des moyens légèrement différents.

Alors, si nous pouvons surcharger un opérateur sous forme de fonction amie ou de fonction membre, lequel faut-il choisir ? Pour répondre à cette question, il vous faut encore connaître quelques points.

Tout ne peut pas être surchargé sous forme de fonction amie

Les opérateurs d'affectation (=), d'indexation ([]), d'appel de fonction (()) et de sélection de membre (->) doivent être surchargés sous forme de fonctions membres, car le langage l'exige.

Tout ne peut pas être surchargé sous forme de fonction membre

Dans la leçon 21.4 -- Surcharge des opérateurs d'entrée/sortie, nous avons surchargé operator<< pour notre classe Point à l'aide de la méthode de la fonction amie. Voici un rappel de la manière dont nous l'avons fait :

#include <iostream>

class Point
{
private:
    double m_x {};
    double m_y {};
    double m_z {};

public:
    Point(double x=0.0, double y=0.0, double z=0.0)
        : m_x { x }, m_y { y }, m_z { z }
    {
    }

    friend std::ostream& operator<< (std::ostream& out, const Point& point);
};

std::ostream& operator<< (std::ostream& out, const Point& point)
{
    // Comme operator<< est une amie de la classe Point, nous pouvons accéder directement à ses membres.
    out << "Point(" << point.m_x << ", " << point.m_y << ", " << point.m_z << ")";

    return out;
}

int main()
{
    Point point1 { 2.0, 3.0, 4.0 };

    std::cout << point1;

    return 0;
}

En revanche, nous ne pouvons pas surcharger operator<< sous forme de fonction membre. Pourquoi ? Parce que l'opérateur surchargé doit être ajouté comme membre de l'opérande de gauche. Ici, l'opérande de gauche est un objet de type std::ostream. std::ostream fait partie de la bibliothèque standard, et nous ne pouvons pas modifier sa déclaration de classe pour y ajouter la surcharge comme fonction membre.

Cela impose de surcharger operator<< sous forme de fonction ordinaire (solution préférée) ou de fonction amie.

De même, bien que nous puissions surcharger operator+(Cents, int) comme fonction membre (comme nous l'avons fait ci-dessus), nous ne pouvons pas surcharger operator+(int, Cents) comme fonction membre, car int n'est pas une classe à laquelle nous pouvons ajouter des membres.

En règle générale, nous ne pourrons pas utiliser une surcharge membre si l'opérande de gauche n'est pas une classe (par exemple int), ou s'il s'agit d'une classe que nous ne pouvons pas modifier (par exemple std::ostream).

Quand utiliser une surcharge sous forme de fonction ordinaire, amie ou membre

Dans la plupart des cas, le langage vous laisse le choix entre la version ordinaire/amie et la version membre de la surcharge. Cependant, l'une des deux est généralement un meilleur choix que l'autre.

Pour les opérateurs binaires qui ne modifient pas l'opérande de gauche (par exemple operator+), la version à fonction ordinaire ou amie est généralement préférée, car elle fonctionne pour tous les types de paramètres (même lorsque l'opérande de gauche n'est pas un objet de classe, ou qu'il s'agit d'une classe non modifiable). La version à fonction ordinaire ou amie présente en outre l'avantage de la « symétrie », puisque tous les opérandes deviennent des paramètres explicites (au lieu de faire de l'opérande de gauche le *this et de l'opérande de droite un paramètre explicite).

Pour les opérateurs binaires qui modifient l'opérande de gauche (par exemple operator+=), la version à fonction membre est généralement préférée. Dans ces cas, l'opérande le plus à gauche est toujours d'un type classe, et il est naturel que l'objet modifié soit celui pointé par *this. Comme l'opérande de droite devient un paramètre explicite, il n'y a aucune ambiguïté sur celui qui est modifié et celui qui est simplement évalué.

Les opérateurs unaires sont également généralement surchargés sous forme de fonctions membres, puisque la version membre n'a pas de paramètres.

Les règles empiriques suivantes peuvent vous aider à déterminer la forme la plus adaptée à une situation donnée :

  • Si vous surchargez l'affectation (=), l'indexation ([]), l'appel de fonction (()) ou la sélection de membre (->), faites-le sous forme de fonction membre.
  • Si vous surchargez un opérateur unaire, faites-le sous forme de fonction membre.
  • Si vous surchargez un opérateur binaire qui ne modifie pas son opérande de gauche (par exemple operator+), faites-le sous forme de fonction ordinaire (solution préférée) ou de fonction amie.
  • Si vous surchargez un opérateur binaire qui modifie son opérande de gauche, mais que vous ne pouvez pas ajouter de membres à la définition de classe de cet opérande (par exemple operator<<, dont l'opérande de gauche est de type ostream), faites-le sous forme de fonction ordinaire (solution préférée) ou de fonction amie.
  • Si vous surchargez un opérateur binaire qui modifie son opérande de gauche (par exemple operator+=), et que vous pouvez modifier la définition de classe de cet opérande, faites-le sous forme de fonction membre.
