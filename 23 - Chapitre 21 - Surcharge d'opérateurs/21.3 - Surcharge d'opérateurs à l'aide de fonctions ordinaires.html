21.3 — Surcharge d'opérateurs à l'aide de fonctions ordinaires

Dans la leçon précédente, nous avons surchargé operator+ sous forme de fonction amie :

#include <iostream>

class Cents
{
private:
  int m_cents{};

public:
  Cents(int cents)
    : m_cents{ cents }
  {}

  // add Cents + Cents using a friend function
  friend Cents operator+(const Cents& c1, const Cents& c2);

  int getCents() const { return m_cents; }
};

// note: this function is not a member function!
Cents operator+(const Cents& c1, const Cents& c2)
{
  // use the Cents constructor and operator+(int, int)
  // we can access m_cents directly because this is a friend function
  return { c1.m_cents + c2.m_cents };
}

int main()
{
  Cents cents1{ 6 };
  Cents cents2{ 8 };
  Cents centsSum{ cents1 + cents2 };
  std::cout << "I have " << centsSum.getCents() << " cents.\n";

  return 0;
}

Utiliser une fonction amie pour surcharger un opérateur est pratique, car elle donne un accès direct aux membres internes des classes sur lesquelles elle opère. Dans l'exemple initial de Cents ci-dessus, notre version amie de operator+ accède directement à la variable membre m_cents.

Cependant, si vous n'avez pas besoin de cet accès, vous pouvez écrire vos opérateurs surchargés sous forme de fonctions ordinaires. Remarquez que la classe Cents ci-dessus contient une fonction d'accès (getCents()) qui nous permet d'obtenir m_cents sans avoir un accès direct aux membres privés. Pour cette raison, nous pouvons écrire notre operator+ surchargé comme une fonction non amie :

#include <iostream>

class Cents
{
private:
  int m_cents{};

public:
  Cents(int cents)
    : m_cents{ cents }
  {}

  int getCents() const { return m_cents; }
};

// note: this function is not a member function nor a friend function!
Cents operator+(const Cents& c1, const Cents& c2)
{
  // use the Cents constructor and operator+(int, int)
  // we don't need direct access to private members here
  return Cents{ c1.getCents() + c2.getCents() };
}

int main()
{
  Cents cents1{ 6 };
  Cents cents2{ 8 };
  Cents centsSum{ cents1 + cents2 };
  std::cout << "I have " << centsSum.getCents() << " cents.\n";

  return 0;
}

Comme les fonctions ordinaires et les fonctions amies fonctionnent presque de la même manière (elles n'ont simplement pas le même niveau d'accès aux membres privés), nous ne les différencierons généralement pas. La seule différence est que la déclaration de la fonction amie à l'intérieur de la classe sert également de prototype. Avec la version en fonction ordinaire, vous devrez fournir vous-même le prototype de la fonction.

Cents.h :

#ifndef CENTS_H
#define CENTS_H

class Cents
{
private:
  int m_cents{};

public:
  Cents(int cents)
    : m_cents{ cents }
  {}

  int getCents() const { return m_cents; }
};

// Need to explicitly provide prototype for operator+ so uses of operator+ in other files know this overload exists
Cents operator+(const Cents& c1, const Cents& c2);

#endif

Cents.cpp :

#include "Cents.h"

// note: this function is not a member function nor a friend function!
Cents operator+(const Cents& c1, const Cents& c2)
{
  // use the Cents constructor and operator+(int, int)
  // we don't need direct access to private members here
  return { c1.getCents() + c2.getCents() };
}

main.cpp :

#include "Cents.h"
#include <iostream>

int main()
{
  Cents cents1{ 6 };
  Cents cents2{ 8 };
  Cents centsSum{ cents1 + cents2 }; // without the prototype in Cents.h, this would fail to compile
  std::cout << "I have " << centsSum.getCents() << " cents.\n";

  return 0;
}

En général, une fonction ordinaire doit être préférée à une fonction amie lorsqu'il est possible de le faire avec les fonctions membres existantes disponibles (moins il y a de fonctions qui touchent aux éléments internes de vos classes, mieux c'est). Cependant, n'ajoutez pas de fonctions d'accès supplémentaires uniquement pour surcharger un opérateur sous forme de fonction ordinaire plutôt que sous forme de fonction amie !

Bonne pratique

Préférez surcharger les opérateurs sous forme de fonctions ordinaires plutôt que de fonctions amies, lorsque c'est possible sans ajouter de fonctions supplémentaires.
