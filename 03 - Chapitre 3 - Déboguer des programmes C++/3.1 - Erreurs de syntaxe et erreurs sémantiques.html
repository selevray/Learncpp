3.1 — Erreurs de syntaxe et erreurs sémantiques

Les erreurs logicielles sont courantes. Elles sont faciles à commettre et difficiles à trouver. Dans ce chapitre, nous explorerons les sujets liés à la recherche et à la suppression des bogues dans nos programmes C++, notamment l'apprentissage de l'utilisation du débogueur intégré à notre environnement de développement (IDE).

Bien que les outils et techniques de débogage ne fassent pas partie de la norme C++, apprendre à trouver et à supprimer les bogues dans les programmes que vous écrivez est une partie extrêmement importante du parcours d'un programmeur accompli. Nous allons donc consacrer un peu de temps à ces sujets, afin que, à mesure que vos programmes deviendront plus complexes, votre capacité à diagnostiquer et à corriger les problèmes progresse au même rythme.

Si vous avez déjà débogué des programmes dans un autre langage de programmation, une grande partie de ce qui suit vous sera familière.

Erreurs de syntaxe

La programmation peut être difficile, et le C++ est un langage quelque peu singulier. Associez ces deux éléments, et les façons de faire des erreurs sont nombreuses. Les erreurs se répartissent généralement en deux catégories : les erreurs de syntaxe et les erreurs sémantiques (erreurs de logique).

Une erreur de syntaxe survient lorsque vous écrivez une instruction qui n'est pas valide selon la grammaire du langage C++. Cela inclut des erreurs telles que des points-virgules manquants, des parenthèses ou accolades non appariées, etc. Par exemple, le programme suivant contient plusieurs erreurs de syntaxe :

#include <iostream>

int main( // il manque l'accolade fermante
{
    int 1x; // le nom d'une variable ne peut pas commencer par un chiffre
    std::cout << "Hi there"; << x +++ << '\n'; // point-virgule superflu, l'opérateur+++ n'existe pas
    return 0 // point-virgule manquant à la fin de l'instruction
}

Heureusement, le compilateur détecte les erreurs de syntaxe et émet un avertissement ou une erreur de compilation, ce qui vous permet de les identifier et de les corriger facilement. Il suffit ensuite de recompiler jusqu'à ce que toutes les erreurs aient disparu.

Erreurs sémantiques

Une erreur sémantique est une erreur de sens. Elle survient lorsqu'une instruction est syntaxiquement valide, mais qu'elle viole d'autres règles du langage ou ne fait pas ce que le programmeur avait prévu.

Certaines erreurs sémantiques peuvent être détectées par le compilateur. Les exemples courants incluent l'utilisation d'une variable non déclarée, les incompatibilités de types (lorsqu'on utilise un objet d'un mauvais type à un endroit donné), etc.

Par exemple, le programme suivant contient plusieurs erreurs sémantiques détectables à la compilation :

int main()
{
    5 = x; // x n'est pas déclaré, on ne peut pas affecter une valeur à 5
    return "hello"; // "hello" ne peut pas être converti en int
}

D'autres erreurs sémantiques ne se manifestent qu'à l'exécution. Parfois, elles provoquent le plantage du programme, comme dans le cas d'une division par zéro :

#include <iostream>

int main()
{
    int a { 10 };
    int b { 0 };
    std::cout << a << " / " << b << " = " << a / b << '\n'; // la division par 0 n'est pas définie en mathématiques
    return 0;
}

Plus souvent, elles produisent simplement une valeur ou un comportement erroné :

#include <iostream>

int main()
{
    int x; // aucune valeur initiale fournie
    std::cout << x << '\n'; // l'utilisation d'une variable non initialisée conduit à un résultat indéfini

    return 0;
}

ou

#include <iostream>

int add(int x, int y) // cette fonction est censée effectuer une addition
{
    return x - y; // mais ce n'est pas le cas, à cause de l'opérateur utilisé
}

int main()
{
    std::cout << "5 + 3 = " << add(5, 3) << '\n'; // devrait afficher 8, mais affiche 2

    return 0;
}

ou

#include <iostream>

int main()
{
    return 0; // la fonction se termine ici

    std::cout << "Hello, world!\n"; // donc cette instruction ne s'exécute jamais
}

Dans les exemples ci-dessus, les erreurs sont assez faciles à repérer. Mais dans la plupart des programmes non triviaux, les erreurs sémantiques d'exécution ne se trouvent pas facilement à l'œil nu. C'est là que les techniques de débogage deviennent utiles.
