3.2 — Le processus de débogage

Supposons que vous ayez écrit un programme qui ne fonctionne pas correctement : le code compile sans problème, mais à l'exécution, le résultat est incorrect. Il doit y avoir une erreur sémantique quelque part. Comment la trouver ? Si vous avez suivi les bonnes pratiques, en écrivant un peu de code puis en le testant, vous savez peut-être où se situe l'erreur. Sinon, vous n'en avez peut-être aucune idée.

Tous les bogues reposent sur un principe simple : quelque chose que vous pensiez correct ne l'est pas. Déterminer exactement où se situe cette erreur peut être difficile. Dans cette leçon, nous allons décrire la démarche générale de débogage d'un programme.

Comme nous n'avons pas encore abordé beaucoup de sujets du C++, les programmes d'exemple de ce chapitre sont assez simples. Il se peut donc que certaines techniques présentées ici vous paraissent excessives. Gardez toutefois à l'esprit que ces techniques sont conçues pour des programmes plus grands et plus complexes, et qu'elles seront bien plus utiles dans ce contexte (c'est là que vous en avez le plus besoin).

Une démarche générale de débogage

Une fois qu'un problème a été identifié, le débogage se déroule généralement en six étapes :

  1. Trouver la cause première du problème (il s'agit généralement de la ligne de code qui ne fonctionne pas). Nous verrons quelques stratégies pour y parvenir dans la prochaine leçon.
  2. S'assurer de bien comprendre pourquoi le problème survient.
  3. Déterminer comment vous allez corriger le problème.
  4. Réparer le problème à l'origine de l'erreur.
  5. Retester pour vérifier que le problème a été corrigé.
  6. Retester pour vérifier qu'aucun nouveau problème n'est apparu.

Prenons une analogie tirée de la vie courante. Un soir, vous allez chercher des glaçons dans le distributeur de votre congélateur. Vous placez votre verre sous le distributeur, appuyez sur le levier, et... rien ne sort. Zut. Vous venez de découvrir un défaut. Que faites-vous ? Vous commencez probablement une enquête pour tenter d'identifier la cause première du problème.

Trouver la cause première : Comme vous entendez le distributeur tenter de délivrer de la glace, le mécanisme de distribution n'est probablement pas en cause. Vous ouvrez donc le congélateur et examinez le bac à glaçons : aucun glaçon. Est-ce la cause première ? Non, ce n'est qu'un symptôme. Après un examen plus approfondi, vous constatez que la machine à glaçons ne semble pas fabriquer de glace. Le problème vient-il de la machine à glaçons ou d'autre chose ? Le congélateur est toujours froid, la conduite d'eau n'est pas bouchée, et tout le reste semble fonctionner. Vous en concluez donc que la cause première est que la machine à glaçons ne fonctionne plus.

Comprendre le problème : Dans ce cas, c'est simple. Une machine à glaçons en panne ne fabrique pas de glace.

Déterminer une solution : À ce stade, plusieurs options s'offrent à vous : vous pourriez contourner le problème (acheter des sacs de glaçons au magasin). Vous pourriez tenter de diagnostiquer la machine plus en détail, pour voir si une pièce peut être réparée. Vous pourriez acheter une nouvelle machine à glaçons et la installer à la place de l'ancienne. Ou encore, acheter un nouveau congélateur. Vous décidez d'acheter une nouvelle machine à glaçons.

Réparer le problème : Une fois la machine à glaçons arrivée, vous l'installez.

Retester : Après avoir rétabli l'alimentation électrique et attendu toute la nuit, votre nouvelle machine se met à fabriquer de la glace. Aucun nouveau problème n'apparaît.

Appliquons maintenant ce processus à notre programme simple de la leçon précédente :

#include <iostream>

int add(int x, int y) // this function is supposed to perform addition
{
    return x - y; // but it doesn't due to the wrong operator being used
}

int main()
{
    std::cout << "5 + 3 = " << add(5, 3) << '\n'; // should produce 8, but produces 2

    return 0;
}

Ce code a un avantage : le bogue est très visible, car la mauvaise réponse s'affiche à l'écran via la ligne 10. Cela nous donne un point de départ pour notre investigation.

Trouver la cause première : À la ligne 10, nous voyons que nous passons des littéraux en arguments (5 et 3), il n'y a donc aucune erreur possible à ce niveau. Comme les entrées de la fonction add sont correctes mais que la sortie ne l'est pas, il est assez évident que la fonction add produit la mauvaise valeur. La seule instruction de la fonction add est l'instruction return, c'est elle qui est coupable. Nous avons trouvé la ligne problématique. Maintenant que nous savons où concentrer notre attention, remarquer que nous soustrayons au lieu d'additionner est quelque chose que vous trouverez probablement par simple inspection.

Comprendre le problème : Dans ce cas, il est évident pourquoi la mauvaise valeur est produite : nous utilisons le mauvais opérateur.

Déterminer une solution : Nous allons simplement remplacer operator- par operator+.

Réparer le problème : Il s'agit de remplacer operator- par operator+ et de s'assurer que le programme se recompile.

Retester : Après avoir effectué ce changement, relancer le programme doit afficher la valeur correcte, 8. Pour un programme aussi simple, c'est là tout le test nécessaire.

Cet exemple est trivial, mais il illustre le processus de base que vous suivrez pour diagnostiquer n'importe quel programme.
