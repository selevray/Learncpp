3.4 — Tactiques de débogage de base

Dans la leçon précédente, nous avons vu une stratégie pour trouver les problèmes : exécuter nos programmes et procéder par déductions successives pour localiser l'erreur. Dans cette leçon, nous allons découvrir quelques tactiques de base pour formuler ces hypothèses et recueillir les informations qui aident à trouver les problèmes.

Tactique de débogage n° 1 : mettre du code en commentaire

Commençons par une tactique simple. Si votre programme présente un comportement erroné, une façon de réduire le code à examiner consiste à mettre une partie du code en commentaire, puis à vérifier si le problème persiste. Si le problème reste inchangé, le code mis en commentaire n'en est probablement pas responsable.

Considérons le code suivant :

int main()
{
    getNames(); // demande à l'utilisateur d'entrer une liste de noms
    doMaintenance(); // effectue des opérations diverses
    sortNames(); // les trie par ordre alphabétique
    printNames(); // affiche la liste triée des noms

    return 0;
}

Supposons que ce programme doive afficher les noms saisis par l'utilisateur par ordre alphabétique, mais qu'il les affiche par ordre alphabétique inverse. Où se trouve le problème ? getNames saisit-elle les noms incorrectement ? sortNames les trie-t-elle à l'envers ? printNames les affiche-t-elle à l'envers ? Cela pourrait être l'une de ces causes. Mais nous pouvons supposer que doMaintenance() n'a rien à voir avec le problème. Mettons donc cet appel en commentaire.

int main()
{
    getNames(); // demande à l'utilisateur d'entrer une liste de noms
//    doMaintenance(); // effectue des opérations diverses
    sortNames(); // les trie par ordre alphabétique
    printNames(); // affiche la liste triée des noms

    return 0;
}

Il y a trois issues possibles :

  • Si le problème disparaît, c'est que doMaintenance est à l'origine du problème, et nous devons concentrer notre attention sur cette fonction.
  • Si le problème reste inchangé (ce qui est plus probable), nous pouvons raisonnablement supposer que doMaintenance n'est pas en cause, et nous pouvons exclure toute la fonction de notre recherche pour le moment. Cela ne nous indique pas si le problème réel se situe avant ou après l'appel à doMaintenance, mais cela réduit la quantité de code à examiner par la suite.
  • Si la mise en commentaire de doMaintenance transforme le problème en un autre problème lié (par exemple, le programme cesse d'afficher les noms), il est probable que doMaintenance fasse quelque chose d'utile dont dépend un autre code. Dans ce cas, nous ne pouvons probablement pas déterminer si le problème se trouve dans doMaintenance ou ailleurs. Nous pouvons alors décommenter doMaintenance et essayer une autre approche.

Attention

N'oubliez pas quelles fonctions vous avez mises en commentaire, afin de pouvoir les rétablir plus tard !

Après avoir effectué de nombreuses modifications liées au débogage, il est très facile d'en oublier une ou deux. Si cela arrive, vous corrigerez un bogue tout en en introduisant d'autres !

Disposer d'un bon système de gestion de versions est extrêmement utile ici : vous pouvez comparer votre code avec la branche principale pour voir toutes les modifications liées au débogage que vous avez faites (et vérifier qu'elles sont annulées avant de valider votre changement).

Astuce

Une autre approche, plutôt que d'ajouter et de retirer répétitivement des instructions de débogage ou de les décommenter et les commenter, consiste à utiliser une bibliothèque tierce qui vous permet de laisser des instructions de débogage dans votre code, mais de les exclure à la compilation en mode version via une macro du préprocesseur. dbg est une telle bibliothèque, réduite à un seul fichier d'en-tête, conçue pour faciliter cette approche (via la macro du préprocesseur DBG_MACRO_DISABLE).

Nous abordons les bibliothèques réduites à un fichier d'en-tête dans la leçon 7.9 -- Fonctions et variables en ligne.

Tactique de débogage n° 2 : valider le flux d'exécution de votre code

Un autre problème fréquent dans les programmes plus complexes est que le programme appelle une fonction trop souvent ou trop rarement (voire pas du tout).

Dans ce cas, il peut être utile de placer des instructions en début de vos fonctions pour afficher le nom de la fonction. Ainsi, lorsque le programme s'exécute, vous pouvez voir quelles fonctions sont appelées.

Astuce

Pour afficher des informations à des fins de débogage, utilisez std::cerr au lieu de std::cout. L'une des raisons est que std::cout peut être bufferisé, ce qui signifie qu'un certain temps peut s'écouler entre le moment où vous demandez à std::cout d'afficher du texte et celui où il le fait effectivement. Si vous affichez avec std::cout puis que votre programme plante immédiatement après, std::cout peut ou non avoir déjà affiché le texte. Cela peut vous induire en erreur quant à l'emplacement du problème. En revanche, std::cerr n'est pas bufferisé : tout ce que vous lui envoyez s'affiche immédiatement. Cela garantit que toutes les sorties de débogage apparaissent le plus tôt possible (au prix d'une certaine perte de performance, qui nous importe généralement peu pendant le débogage).

Utiliser std::cerr permet également de signaler clairement que les informations affichées concernent un cas d'erreur et non un cas normal.

Nous revenons sur le choix entre std::cout et std::cerr dans la leçon 9.4 -- Détection et gestion des erreurs.

Considérons le programme simple suivant, qui ne fonctionne pas correctement :

#include <iostream>

int getValue()
{
    return 4;
}

int main()
{
    std::cout << getValue << '\n';

    return 0;
}

Vous devrez peut-être désactiver l'option « Traiter les avertissements comme des erreurs » pour que le code ci-dessus se compile.

Bien que nous nous attendions à ce que ce programme affiche la valeur 4, il affiche en fait la valeur :


1

Sous Visual Studio (et peut-être avec certains autres compilateurs), il peut plutôt afficher ceci :


00101424

Contenu associé

Nous expliquons pourquoi certains compilateurs affichent 1 au lieu d'une adresse (et que faire si votre compilateur affiche 1 alors que vous voulez une adresse) dans la leçon 20.1 -- Pointeurs de fonctions.

Ajoutons quelques instructions de débogage à ces fonctions :

#include <iostream>

int getValue()
{
std::cerr << "getValue() called\n";
    return 4;
}

int main()
{
std::cerr << "main() called\n";
    std::cout << getValue << '\n';

    return 0;
}

Astuce

Lorsque vous ajoutez des instructions de débogage temporaires, il peut être utile de ne pas les indenter. Elles sont ainsi plus faciles à repérer pour les supprimer plus tard.

Si vous utilisez clang-format pour formater votre code, il tentera d'indenter automatiquement ces lignes. Vous pouvez désactiver le formatage automatique comme ceci :

// clang-format off
std::cerr << "main() called\n";
// clang-format on

Désormais, lorsque ces fonctions s'exécutent, elles affichent leur nom, ce qui indique qu'elles ont été appelées :


main() called
1

Nous constatons maintenant que la fonction getValue n'a jamais été appelée. Il doit y avoir un problème dans le code qui appelle cette fonction. Examinons de plus près cette ligne :

    std::cout << getValue << '\n';

Ah, nous avons oublié les parenthèses de l'appel de fonction. Il faut écrire :

#include <iostream>

int getValue()
{
std::cerr << "getValue() called\n";
    return 4;
}

int main()
{
std::cerr << "main() called\n";
    std::cout << getValue() << '\n'; // ajout des parenthèses ici

    return 0;
}

Ce code produit maintenant la sortie correcte :


main() called
getValue() called
4

Nous pouvons alors supprimer les instructions de débogage temporaires.

Tactique de débogage n° 3 : afficher des valeurs

Avec certains types de bogues, le programme peut calculer ou transmettre une valeur incorrecte.

Nous pouvons aussi afficher la valeur de variables (y compris de paramètres) ou d'expressions pour vérifier qu'elles sont correctes.

Considérons le programme suivant, censé additionner deux nombres, mais qui ne fonctionne pas correctement :

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

void printResult(int z)
{
    std::cout << "The answer is: " << z << '\n';
}

int getUserInput()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    return x;
}

int main()
{
    int x{ getUserInput() };
    int y{ getUserInput() };

    int z{ add(x, 5) };
    printResult(z);

    return 0;
}

Voici un exemple de sortie de ce programme :


Enter a number: 4
Enter a number: 3
The answer is: 9

Ce n'est pas correct. Voyez-vous l'erreur ? Même dans ce court programme, elle est difficile à repérer. Ajoutons du code pour déboguer nos valeurs :

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

void printResult(int z)
{
    std::cout << "The answer is: " << z << '\n';
}

int getUserInput()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    return x;
}

int main()
{
    int x{ getUserInput() };
std::cerr << "main::x = " << x << '\n';
    int y{ getUserInput() };
std::cerr << "main::y = " << y << '\n';

    int z{ add(x, 5) };
std::cerr << "main::z = " << z << '\n';
    printResult(z);

    return 0;
}

Voici la sortie ci-dessus :


Enter a number: 4
main::x = 4
Enter a number: 3
main::y = 3
main::z = 9
The answer is: 9

Les variables x et y ont les bonnes valeurs, mais pas la variable z. Le problème doit se situer entre ces deux points, ce qui fait de la fonction add un suspect principal.

Modifions la fonction add :

#include <iostream>

int add(int x, int y)
{
std::cerr << "add() called (x=" << x <<", y=" << y << ")\n";
    return x + y;
}

void printResult(int z)
{
    std::cout << "The answer is: " << z << '\n';
}

int getUserInput()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    return x;
}

int main()
{
    int x{ getUserInput() };
std::cerr << "main::x = " << x << '\n';
    int y{ getUserInput() };
std::cerr << "main::y = " << y << '\n';

    int z{ add(x, 5) };
std::cerr << "main::z = " << z << '\n';
    printResult(z);

    return 0;
}

Nous obtenons maintenant la sortie suivante :


Enter a number: 4
main::x = 4
Enter a number: 3
main::y = 3
add() called (x=4, y=5)
main::z = 9
The answer is: 9

La variable y valait 3, mais la fonction add a reçu la valeur 5 pour son paramètre y. Nous avons dû passer un mauvais argument. En effet :

    int z{ add(x, 5) };

Le voilà. Nous avons passé le littéral 5 au lieu de la valeur de la variable y comme argument. C'est une correction facile ; il ne reste plus qu'à supprimer les instructions de débogage.

Un exemple de plus

Ce programme ressemble beaucoup au précédent, mais il ne fonctionne pas non plus comme il le devrait :

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

void printResult(int z)
{
    std::cout << "The answer is: " << z << '\n';
}

int getUserInput()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    return --x;
}

int main()
{
    int x{ getUserInput() };
    int y{ getUserInput() };

    int z { add(x, y) };
    printResult(z);

    return 0;
}

Si nous exécutons ce code et obtenons la sortie suivante :


Enter a number: 4
Enter a number: 3
The answer is: 5

Hmm, quelque chose ne va pas. Mais où ?

Instrumentons ce code avec des instructions de débogage :

#include <iostream>

int add(int x, int y)
{
std::cerr << "add() called (x=" << x << ", y=" << y << ")\n";
    return x + y;
}

void printResult(int z)
{
std::cerr << "printResult() called (z=" << z << ")\n";
    std::cout << "The answer is: " << z << '\n';
}

int getUserInput()
{
std::cerr << "getUserInput() called\n";
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    return --x;
}

int main()
{
std::cerr << "main() called\n";
    int x{ getUserInput() };
std::cerr << "main::x = " << x << '\n';
    int y{ getUserInput() };
std::cerr << "main::y = " << y << '\n';

    int z{ add(x, y) };
std::cerr << "main::z = " << z << '\n';
    printResult(z);

    return 0;
}

Exécutons maintenant à nouveau le programme avec les mêmes entrées :


main() called
getUserInput() called
Enter a number: 4
main::x = 3
getUserInput() called
Enter a number: 3
main::y = 2
add() called (x=3, y=2)
main::z = 5
printResult() called (z=5)
The answer is: 5

Nous voyons immédiatement quelque chose qui cloche : l'utilisateur saisit la valeur 4, mais la variable x de main reçoit la valeur 3. Il doit y avoir un problème entre le moment où l'utilisateur saisit la valeur et celui où elle est affectée à la variable x de main. Vérifions que le programme reçoit bien la valeur correcte de l'utilisateur en ajoutant du code de débogage à la fonction getUserInput :

#include <iostream>

int add(int x, int y)
{
std::cerr << "add() called (x=" << x << ", y=" << y << ")\n";
    return x + y;
}

void printResult(int z)
{
std::cerr << "printResult() called (z=" << z << ")\n";
    std::cout << "The answer is: " << z << '\n';
}

int getUserInput()
{
std::cerr << "getUserInput() called\n";
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
std::cerr << "getUserInput::x = " << x << '\n'; // ajout de cette ligne de débogage supplémentaire
    return --x;
}

int main()
{
std::cerr << "main() called\n";
    int x{ getUserInput() };
std::cerr << "main::x = " << x << '\n';
    int y{ getUserInput() };
std::cerr << "main::y = " << y << '\n';

    int z{ add(x, y) };
std::cerr << "main::z = " << z << '\n';
    printResult(z);

    return 0;
}

Et la sortie :


main() called
getUserInput() called
Enter a number: 4
getUserInput::x = 4
main::x = 3
getUserInput() called
Enter a number: 3
getUserInput::x = 3
main::y = 2
add() called (x=3, y=2)
main::z = 5
printResult() called (z=5)
The answer is: 5

Grâce à cette ligne de débogage supplémentaire, nous constatons que la saisie de l'utilisateur est bien reçue dans la variable x de getUserInput. Pourtant, la variable x de main reçoit une valeur incorrecte. Le problème doit se situer entre ces deux points. Le seul coupable restant est la valeur de retour de la fonction getUserInput. Examinons cette ligne de plus près :

    return --x;

Hmm, c'est étrange. Que signifie ce symbole -- devant x ? Nous n'avons pas encore abordé ce point dans ces tutoriels, donc ne vous inquiétez pas si vous ne savez pas ce qu'il signifie. Mais même sans le savoir, grâce à votre démarche de débogage, vous pouvez raisonnablement affirmer que cette ligne précise est en cause, et donc que ce symbole -- est probablement à l'origine du problème.

Comme nous voulons vraiment que getUserInput renvoie uniquement la valeur de x, supprimons le -- et voyons ce qui se passe :

#include <iostream>

int add(int x, int y)
{
std::cerr << "add() called (x=" << x << ", y=" << y << ")\n";
    return x + y;
}

void printResult(int z)
{
std::cerr << "printResult() called (z=" << z << ")\n";
    std::cout << "The answer is: " << z << '\n';
}

int getUserInput()
{
std::cerr << "getUserInput() called\n";
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
std::cerr << "getUserInput::x = " << x << '\n';
    return x; // suppression du -- devant x
}

int main()
{
std::cerr << "main() called\n";
    int x{ getUserInput() };
std::cerr << "main::x = " << x << '\n';
    int y{ getUserInput() };
std::cerr << "main::y = " << y << '\n';

    int z{ add(x, y) };
std::cerr << "main::z = " << z << '\n';
    printResult(z);

    return 0;
}

Et voici maintenant la sortie :


main() called
getUserInput() called
Enter a number: 4
getUserInput::x = 4
main::x = 4
getUserInput() called
Enter a number: 3
getUserInput::x = 3
main::y = 3
add() called (x=4, y=3)
main::z = 7
printResult() called (z=7)
The answer is: 7

Le programme fonctionne maintenant correctement. Sans même comprendre ce que faisait --, nous avons pu identifier la ligne de code précise à l'origine du problème, puis le corriger.

Pourquoi utiliser des instructions d'affichage pour déboguer n'est pas idéal

Bien que l'ajout d'instructions de débogage à un programme à des fins de diagnostic soit une technique courante et rudimentaire, et qu'elle fonctionne (surtout lorsqu'aucun débogueur n'est disponible pour une raison ou une autre), elle n'est pas idéale pour plusieurs raisons :

  1. Les instructions de débogage encombrent votre code.
  2. Les instructions de débogage encombrent la sortie de votre programme.
  3. Les instructions de débogage nécessitent de modifier votre code pour être ajoutées et retirées, ce qui peut introduire de nouveaux bogues.
  4. Les instructions de débogage doivent être supprimées une fois que vous n'en avez plus besoin, ce qui les rend non réutilisables.

Nous pouvons faire mieux. Nous verrons comment dans les prochaines leçons.
