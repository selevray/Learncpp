15.5 — Modèles de classes avec fonctions membres

Dans la leçon 11.6 -- Modèles de fonctions, nous avons étudié les modèles de fonctions :

template <typename T> // this is the template parameter declaration
T max(T x, T y) // this is the function template definition for max<T>
{
    return (x < y) ? y : x;
}

Avec un modèle de fonction, nous pouvons définir des paramètres de modèle de type (par exemple typename T) et les utiliser comme types des paramètres de notre fonction (T x, T y).

Dans la leçon 13.13 -- Modèles de classes, nous avons vu les modèles de classes, qui permettent d'utiliser des paramètres de modèle de type pour le type des membres de données de types classe (struct, classes et unions) :

#include <iostream>

template <typename T>
struct Pair
{
    T first{};
    T second{};
};

// Voici un guide de déduction pour notre Pair (requis en C++17 ou antérieur)
// Les objets Pair initialisés avec des arguments de type T et T doivent se déduire en Pair<T>
template <typename T>
Pair(T, T) -> Pair<T>;

int main()
{
    Pair<int> p1{ 5, 6 };        // instancie Pair<int> et crée l'objet p1
    std::cout << p1.first << ' ' << p1.second << '\n';

    Pair<double> p2{ 1.2, 3.4 }; // instancie Pair<double> et crée l'objet p2
    std::cout << p2.first << ' ' << p2.second << '\n';

    Pair<double> p3{ 7.8, 9.0 }; // crée l'objet p3 en utilisant la définition précédente de Pair<double>
    std::cout << p3.first << ' ' << p3.second << '\n';

    return 0;
}

Contenu connexe

Nous traitons des guides de déduction dans la leçon 13.14 -- Déduction d'arguments de modèle de classe (CTAD) et guides de déduction.

Dans cette leçon, nous allons combiner des éléments des modèles de fonctions et des modèles de classes en étudiant de plus près les modèles de classes qui possèdent des fonctions membres.

Paramètres de modèle de type dans les fonctions membres

Les paramètres de modèle de type définis dans la déclaration de paramètres d'un modèle de classe peuvent être utilisés à la fois comme types des membres de données et comme types des paramètres des fonctions membres.

Dans l'exemple suivant, nous réécrivons le modèle de classe Pair ci-dessus en le convertissant d'une struct en une classe :

#include <ios>       // pour std::boolalpha
#include <iostream>

template <typename T>
class Pair
{
private:
    T m_first{};
    T m_second{};

public:
    // Lorsque nous définissons une fonction membre à l'intérieur de la définition de la classe,
    // la déclaration de paramètres de modèle appartenant à la classe s'applique
    Pair(const T& first, const T& second)
        : m_first{ first }
        , m_second{ second }
    {
    }

    bool isEqual(const Pair<T>& pair);
};

// Lorsque nous définissons une fonction membre en dehors de la définition de la classe,
// nous devons fournir à nouveau une déclaration de paramètres de modèle
template <typename T>
bool Pair<T>::isEqual(const Pair<T>& pair)
{
    return m_first == pair.m_first && m_second == pair.m_second;
}

int main()
{
    Pair p1{ 5, 6 }; // utilise le CTAD pour déduire le type Pair<int>
    std::cout << std::boolalpha << "isEqual(5, 6): " << p1.isEqual( Pair{5, 6} ) << '\n';
    std::cout << std::boolalpha << "isEqual(5, 7): " << p1.isEqual( Pair{5, 7} ) << '\n';

    return 0;
}

Ce qui précède devrait être assez clair, mais il y a quelques points à noter.

Premièrement, comme notre classe possède des membres privés, ce n'est pas un agrégat, et elle ne peut donc pas utiliser l'initialisation d'agrégat. Nous devons à la place initialiser nos objets de classe à l'aide d'un constructeur.

Comme les membres de données de notre classe sont de type T, nous donnons aux paramètres de notre constructeur le type const T&, afin que l'utilisateur puisse fournir des valeurs d'initialisation de ce même type. Comme T peut être coûteux à copier, il est plus sûr de le passer par référence constante que par valeur.

Notez que lorsque nous définissons une fonction membre à l'intérieur de la définition du modèle de classe, nous n'avons pas besoin de fournir une déclaration de paramètres de modèle pour cette fonction membre. Ces fonctions membres utilisent implicitement la déclaration de paramètres de modèle de la classe.

Deuxièmement, nous n'avons pas besoin de guides de déduction pour que le CTAD fonctionne avec les classes qui ne sont pas des agrégats. Un constructeur correspondant fournit au compilateur les informations dont il a besoin pour déduire les paramètres de modèle à partir des initialiseurs.

Troisièmement, examinons de plus près le cas où nous définissons une fonction membre d'un modèle de classe en dehors de la définition du modèle de classe :

template <typename T>
bool Pair<T>::isEqual(const Pair<T>& pair)
{
    return m_first == pair.m_first && m_second == pair.m_second;
}

Comme cette définition de fonction membre est séparée de la définition du modèle de classe, nous devons fournir à nouveau une déclaration de paramètres de modèle (template <typename T>) pour que le compilateur sache ce qu'est T.

De plus, lorsque nous définissons une fonction membre en dehors de la classe, nous devons qualifier le nom de la fonction membre avec le nom complet paramétré du modèle de classe (Pair<T>::isEqual, et non Pair::isEqual).

Noms de classe injectés

Dans une leçon précédente, nous avons indiqué que le nom d'un constructeur doit correspondre au nom de la classe. Pourtant, dans notre modèle de classe Pair<T> ci-dessus, nous avons nommé notre constructeur Pair, et non Pair<T>. Cela fonctionne malgré tout, alors même que les noms ne correspondent pas.

Dans la portée d'une classe, le nom non qualifié de la classe s'appelle un nom de classe injecté (injected class name). Dans un modèle de classe, le nom de classe injecté sert d'abréviation pour le nom complet paramétré.

Comme Pair est le nom de classe injecté de Pair<T>, dans la portée de notre modèle de classe Pair<T>, toute utilisation de Pair est traitée comme si nous avions écrit Pair<T>. Ainsi, bien que nous ayons nommé le constructeur Pair, le compilateur le traite comme si nous avions écrit Pair<T>. Les noms correspondent maintenant !

Cela signifie que nous pouvons aussi définir notre fonction membre isEqual() de cette manière :

template <typename T>
bool Pair<T>::isEqual(const Pair& pair) // notez que le paramètre a le type Pair, et non Pair<T>
{
    return m_first == pair.m_first && m_second == pair.m_second;
}

Comme il s'agit de la définition d'une fonction membre de Pair<T>, nous sommes dans la portée du modèle de classe Pair<T>. Par conséquent, toute utilisation de Pair est une abréviation de Pair<T> !

Point clé

Dans la leçon 13.14 -- Déduction d'arguments de modèle de classe (CTAD) et guides de déduction, nous avons noté que le CTAD ne fonctionne pas avec les paramètres de fonction (puisqu'il s'agit de déduction d'arguments et non de déduction de paramètres). Cependant, utiliser un nom de classe injecté comme paramètre de fonction est correct, car il s'agit d'une abréviation pour le nom complet paramétré, et non d'une utilisation du CTAD.

Où définir les fonctions membres des modèles de classes en dehors de la classe

Pour les fonctions membres des modèles de classes, le compilateur doit voir à la fois la définition de la classe (pour s'assurer que le modèle de fonction membre est déclaré comme faisant partie de la classe) et la définition du modèle de fonction membre (pour savoir comment l'instancier). Nous voulons donc généralement définir la classe et ses modèles de fonctions membres au même endroit.

Lorsqu'un modèle de fonction membre est défini à l'intérieur de la définition de la classe, la définition du modèle de fonction membre fait partie de la définition de la classe, donc partout où la définition de la classe est visible, la définition du modèle de fonction membre l'est aussi. Cela simplifie les choses (au prix d'un alourdissement de la définition de la classe).

Lorsqu'un modèle de fonction membre est défini à l'extérieur de la définition de la classe, il doit en général être défini immédiatement sous la définition de la classe. Ainsi, partout où la définition de la classe est visible, les définitions des modèles de fonctions membres placées immédiatement sous la définition de la classe le seront aussi.

Dans le cas typique où une classe est définie dans un fichier d'en-tête, cela signifie que les modèles de fonctions membres définis en dehors de la classe doivent aussi être définis dans ce même fichier d'en-tête, sous la définition de la classe.

Point clé

Dans la leçon 11.7 -- Instanciation des modèles de fonctions, nous avons noté que les fonctions instanciées implicitement à partir de modèles sont implicitement inline. Cela concerne aussi bien les modèles de fonctions non membres que les modèles de fonctions membres. Il n'y a donc aucun problème à inclure dans plusieurs fichiers source des modèles de fonctions membres définis dans des fichiers d'en-tête, puisque les fonctions instanciées à partir de ces modèles seront implicitement inline (et l'éditeur de liens (linker) élimine les doublons).

Bonne pratique

Tout modèle de fonction membre défini en dehors de la définition de la classe doit être défini juste sous la définition de la classe (dans le même fichier).

Quiz

Question n° 1

Écrivez un modèle de classe nommé Triad qui possède 3 membres de données privés avec des paramètres de modèle de type indépendants. La classe doit avoir un constructeur, des fonctions d'accès et une fonction membre print() définie en dehors de la classe.

Le programme suivant doit compiler et s'exécuter :

#include <iostream>
#include <string>

int main()
{
    Triad<int, int, int> t1{ 1, 2, 3 };
    t1.print();
    std::cout << '\n';
    std::cout << t1.first() << '\n';

    using namespace std::literals::string_literals;
    const Triad t2{ 1, 2.3, "Hello"s };
    t2.print();
    std::cout << '\n';

    return 0;
}

et produire la sortie :


[1, 2, 3]
1
[1, 2.3, Hello]
Solution 
#include <iostream>
#include <string>

template <typename T, typename U, typename V>
class Triad
{
private:
    T m_first{};
    U m_second{};
    V m_third{};

public:
    Triad(const T& first, const U& second, const V& third)
        : m_first{ first }
        , m_second{ second }
        , m_third{ third }
    {
    }

    const T& first() const { return m_first; }
    const U& second() const { return m_second; }
    const V& third() const { return m_third; }

    void print() const;
};

template <typename T, typename U, typename V>
void Triad<T, U, V>::print() const
{
    std::cout << '[' << m_first << ", " << m_second << ", " << m_third << ']' ;
}

int main()
{
    Triad<int, int, int> t1{ 1, 2, 3 };
    t1.print();
    std::cout << '\n';
    std::cout << t1.first() << '\n';

    using namespace std::literals::string_literals;
    const Triad t2{ 1, 2.3, "Hello"s };
    t2.print();
    std::cout << '\n';

    return 0;
}

Question n° 2

Si nous retirons le const de la déclaration et de la définition de la fonction print(), le programme ne compile plus. Pourquoi ?

Solution

t2 est un objet constant, donc seules les fonctions membres constantes peuvent être appelées sur t2. Si nous faisons de print() une fonction membre non constante, alors t2 n'est pas autorisé à l'appeler. En effet, une fonction membre non constante pourrait modifier l'objet implicite, ce qui violerait la constance de l'objet constant (ici t2).
