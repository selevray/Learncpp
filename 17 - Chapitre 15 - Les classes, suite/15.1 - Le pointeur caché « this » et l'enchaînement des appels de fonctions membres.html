15.1 — Le pointeur caché « this » et l'enchaînement des appels de fonctions membres

Une question que se posent souvent les programmeurs débutants à propos des classes est : « Quand une fonction membre est appelée, comment C++ sait-il sur quel objet elle a été appelée ? ».

Commençons par définir une classe simple. Cette classe encapsule un entier et fournit quelques fonctions d'accès pour lire et modifier cette valeur :

#include <iostream>

class Simple
{
private:
    int m_id{};

public:
    Simple(int id)
        : m_id{ id }
    {
    }

    int getID() const { return m_id; }
    void setID(int id) { m_id = id; }

    void print() const { std::cout << m_id; }
};

int main()
{
    Simple simple{1};
    simple.setID(2);

    simple.print();

    return 0;
}

Comme vous pouvez vous y attendre, ce programme produit le résultat :


2

D'une manière ou d'une autre, lorsque nous appelons simple.setID(2);, C++ sait que la fonction setID() doit opérer sur l'objet simple, et que m_id désigne en réalité simple.m_id.

La réponse est que C++ utilise un pointeur caché nommé this ! Dans cette leçon, nous allons examiner this plus en détail.

Le pointeur caché this

Dans chaque fonction membre, le mot-clé this est un pointeur constant qui contient l'adresse de l'objet implicite courant.

La plupart du temps, nous ne mentionnons pas explicitement this, mais pour prouver que nous le pouvons :

#include <iostream>

class Simple
{
private:
    int m_id{};

public:
    Simple(int id)
        : m_id{ id }
    {
    }

    int getID() const { return m_id; }
    void setID(int id) { m_id = id; }

    void print() const { std::cout << this->m_id; } // utilise le pointeur `this` pour accéder à l'objet implicite, et l'opérateur -> pour sélectionner le membre m_id
};

int main()
{
    Simple simple{ 1 };
    simple.setID(2);

    simple.print();

    return 0;
}

Ce programme fonctionne exactement comme l'exemple précédent et affiche :


2

Notez que les fonctions membres print() des deux exemples précédents font exactement la même chose :

    void print() const { std::cout << m_id; }       // utilisation implicite de this
    void print() const { std::cout << this->m_id; } // utilisation explicite de this

Il s'avère que la première forme est un raccourci pour la seconde. Lorsque nous compilons nos programmes, le compilateur préfixe implicitement par this-> tout membre qui fait référence à l'objet implicite. Cela permet de garder notre code plus concis et évite d'avoir à écrire this-> explicitement encore et encore.

Rappel

Nous utilisons -> pour sélectionner un membre à partir d'un pointeur vers un objet. this->m_id est équivalent à (*this).m_id.

Nous abordons operator-> dans la leçon 13.12 -- Sélection de membres à l'aide de pointeurs et de références.

Comment this est-il initialisé ?

Examinons de plus près cet appel de fonction :

    simple.setID(2);

Bien que l'appel setID(2) ne semble avoir qu'un seul argument, il en a en réalité deux ! À la compilation, le compilateur réécrit l'expression simple.setID(2); de la façon suivante :

    Simple::setID(&simple, 2); // notez que simple est passé du préfixe d'objet à un argument de fonction !

Notez qu'il s'agit maintenant d'un simple appel de fonction standard, et que l'objet simple (qui était auparavant un préfixe d'objet) est désormais passé par adresse en tant qu'argument de la fonction.

Mais ce n'est que la moitié de la réponse. Puisque l'appel de fonction possède maintenant un argument supplémentaire, la définition de la fonction membre doit aussi être modifiée pour accepter (et utiliser) cet argument comme paramètre. Voici notre définition originale de la fonction membre setID() :

    void setID(int id) { m_id = id; }

La manière dont le compilateur réécrit les fonctions est un détail propre à chaque implémentation, mais le résultat final ressemble à ceci :

    static void setID(Simple* const this, int id) { this->m_id = id; }

Notez que notre fonction setID possède un nouveau paramètre le plus à gauche nommé this, qui est un pointeur constant (ce qui signifie qu'il ne peut pas être redirigé vers un autre objet, mais que le contenu pointé peut être modifié). Le membre m_id a également été réécrit en this->m_id, en utilisant le pointeur this.

Pour les lecteurs avancés

Dans ce contexte, le mot-clé static signifie que la fonction n'est pas associée aux objets de la classe, mais qu'elle est traitée comme une fonction ordinaire située dans la région de portée de la classe. Nous abordons les fonctions membres statiques dans la leçon 15.7 -- Fonctions membres statiques.

En résumé :

  1. Lorsque nous appelons simple.setID(2), le compilateur appelle en réalité Simple::setID(&simple, 2), et simple est passé par adresse à la fonction.
  2. La fonction possède un paramètre caché nommé this qui reçoit l'adresse de simple.
  3. Les variables membres à l'intérieur de setID() sont préfixées par this->, qui pointe vers simple. Ainsi, lorsque le compilateur évalue this->m_id, cela correspond en réalité à simple.m_id.

La bonne nouvelle est que tout cela se fait automatiquement, et il n'est pas vraiment important de se souvenir du fonctionnement interne. Il suffit de retenir que toutes les fonctions membres non statiques possèdent un pointeur this qui désigne l'objet sur lequel la fonction a été appelée.

Point clé

Toutes les fonctions membres non statiques possèdent un pointeur constant this qui contient l'adresse de l'objet implicite.

this désigne toujours l'objet sur lequel on opère

Les programmeurs débutants se demandent parfois combien de pointeurs this existent. Chaque fonction membre possède un seul paramètre pointeur this qui désigne l'objet implicite. Considérons :

int main()
{
    Simple a{1}; // this = &a à l'intérieur du constructeur de Simple
    Simple b{2}; // this = &b à l'intérieur du constructeur de Simple
    a.setID(3); // this = &a à l'intérieur de la fonction membre setID()
    b.setID(4); // this = &b à l'intérieur de la fonction membre setID()

    return 0;
}

Notez que le pointeur this contient alternativement l'adresse de l'objet a ou de l'objet b, selon que nous avons appelé une fonction membre sur l'objet a ou sur l'objet b.

Comme this n'est qu'un paramètre de fonction (et non un membre), il n'augmente pas la taille en mémoire des instances de votre classe.

Référencer explicitement this

La plupart du temps, vous n'aurez pas besoin de référencer explicitement le pointeur this. Cependant, il existe quelques situations où cela peut être utile :

D'abord, si une fonction membre possède un paramètre portant le même nom qu'un membre de données, vous pouvez les distinguer en utilisant this :

struct Something
{
    int data{}; // pas de préfixe m_ car il s'agit d'une struct

    void setData(int data)
    {
        this->data = data; // this->data est le membre, data est le paramètre local
    }
};

Cette classe Something possède un membre nommé data. Le paramètre de la fonction setData() porte également le nom data. Dans la fonction setData(), data désigne le paramètre de la fonction (car le paramètre masque le membre de données), donc si nous voulons référencer le membre data, nous utilisons this->data.

Certains développeurs préfèrent ajouter explicitement this-> devant tous les membres de la classe, pour bien montrer qu'ils référencent un membre. Nous recommandons d'éviter cette pratique, car elle tend à rendre le code moins lisible pour un bénéfice minime. Utiliser le préfixe « m_ » est une manière plus concise de distinguer les variables membres privées des variables non membres (locales).

Renvoyer *this

Ensuite, il peut être utile qu'une fonction membre renvoie l'objet implicite comme valeur de retour. La raison principale est de permettre d'« enchaîner » les fonctions membres, de sorte que plusieurs fonctions membres puissent être appelées sur le même objet dans une seule expression ! C'est ce qu'on appelle un enchaînement de fonctions (ou enchaînement de méthodes, function chaining ou method chaining).

Considérons cet exemple courant où l'on affiche plusieurs morceaux de texte à l'aide de std::cout :

std::cout << "Hello, " << userName;

Le compilateur évalue l'extrait ci-dessus de cette façon :

(std::cout << "Hello, ") << userName;

D'abord, operator<< utilise std::cout et la chaîne littérale "Hello, " pour afficher "Hello, " dans la console. Cependant, comme il s'agit d'une partie d'une expression, operator<< doit aussi renvoyer une valeur (ou void). Si operator<< renvoyait void, l'expression partiellement évaluée serait :

void{} << userName;

ce qui n'a manifestement aucun sens (et le compilateur produirait une erreur). À la place, operator<< renvoie l'objet flux qui lui a été passé, c'est-à-dire ici std::cout. Ainsi, après l'évaluation du premier operator<<, nous obtenons :

(std::cout) << userName;

qui affiche ensuite le nom de l'utilisateur.

De cette manière, nous n'avons besoin de spécifier std::cout qu'une seule fois, puis nous pouvons enchaîner autant de morceaux de texte que nous le voulons avec operator<<. Chaque appel à operator<< renvoie std::cout, de sorte que l'appel suivant à operator<< utilise std::cout comme opérande de gauche.

Nous pouvons implémenter ce type de comportement dans nos propres fonctions membres. Considérons la classe suivante :

class Calc
{
private:
    int m_value{};

public:

    void add(int value) { m_value += value; }
    void sub(int value) { m_value -= value; }
    void mult(int value) { m_value *= value; }

    int getValue() const { return m_value; }
};

Si vous voulez ajouter 5, soustraire 3 et multiplier par 4, vous devez procéder ainsi :

#include <iostream>

int main()
{
    Calc calc{};
    calc.add(5); // renvoie void
    calc.sub(3); // renvoie void
    calc.mult(4); // renvoie void

    std::cout << calc.getValue() << '\n';

    return 0;
}

Cependant, si nous faisons en sorte que chaque fonction renvoie *this par référence, nous pouvons enchaîner les appels. Voici la nouvelle version de Calc avec des fonctions « enchaînables » :

class Calc
{
private:
    int m_value{};

public:
    Calc& add(int value) { m_value += value; return *this; }
    Calc& sub(int value) { m_value -= value; return *this; }
    Calc& mult(int value) { m_value *= value; return *this; }

    int getValue() const { return m_value; }
};

Notez que add(), sub() et mult() renvoient maintenant *this par référence. Par conséquent, nous pouvons écrire :

#include <iostream>

int main()
{
    Calc calc{};
    calc.add(5).sub(3).mult(4); // enchaînement de méthodes

    std::cout << calc.getValue() << '\n';

    return 0;
}

Nous avons effectivement condensé trois lignes en une seule expression ! Examinons de plus près le fonctionnement de ce code.

D'abord, calc.add(5) est appelé, ce qui ajoute 5 à m_value. add() renvoie ensuite une référence à *this, c'est-à-dire une référence à l'objet implicite calc, de sorte que calc est l'objet utilisé pour la suite de l'évaluation. Ensuite, calc.sub(3) s'évalue, ce qui soustrait 3 de m_value et renvoie de nouveau calc. Enfin, calc.mult(4) multiplie m_value par 4 et renvoie calc, valeur qui n'est plus utilisée et qui est donc ignorée.

Comme chaque fonction a modifié calc lors de son exécution, la valeur de m_value de calc contient maintenant (((0 + 5) - 3) * 4), soit 8.

C'est probablement l'utilisation explicite la plus courante de this, et c'est celle que vous devriez envisager chaque fois qu'il est pertinent de disposer de fonctions membres enchaînables.

Comme this désigne toujours l'objet implicite, nous n'avons pas besoin de vérifier s'il s'agit d'un pointeur nul avant de le déréférencer.

Remettre une classe dans son état par défaut

Si votre classe possède un constructeur par défaut, vous pouvez souhaiter fournir un moyen de ramener un objet existant à son état par défaut.

Comme indiqué dans les leçons précédentes (14.12 -- Constructeurs délégants), les constructeurs ne servent qu'à initialiser de nouveaux objets et ne doivent pas être appelés directement. Le faire conduira à un comportement inattendu.

La meilleure façon de remettre une classe dans un état par défaut est de créer une fonction membre reset(), qui crée un nouvel objet (à l'aide du constructeur par défaut), puis affecte ce nouvel objet à l'objet implicite courant, comme ceci :

    void reset()
    {
        *this = {}; // initialise par valeur un nouvel objet et écrase l'objet implicite
    }

Voici un programme complet qui illustre le fonctionnement de cette fonction reset() :

#include <iostream>

class Calc
{
private:
    int m_value{};

public:
    Calc& add(int value) { m_value += value; return *this; }
    Calc& sub(int value) { m_value -= value; return *this; }
    Calc& mult(int value) { m_value *= value; return *this; }

    int getValue() const { return m_value; }

    void reset() { *this = {}; }
};


int main()
{
    Calc calc{};
    calc.add(5).sub(3).mult(4);

    std::cout << calc.getValue() << '\n'; // affiche 8

    calc.reset();

    std::cout << calc.getValue() << '\n'; // affiche 0

    return 0;
}

this et les objets constants

Pour les fonctions membres non constantes, this est un pointeur constant vers une valeur non constante (ce qui signifie que this ne peut pas pointer vers autre chose, mais que l'objet pointé peut être modifié). Pour les fonctions membres constantes, this est un pointeur constant vers une valeur constante (ce qui signifie que le pointeur ne peut pas pointer vers autre chose, et que l'objet pointé ne peut pas non plus être modifié).

Les erreurs générées lorsqu'on tente d'appeler une fonction membre non constante sur un objet constant peuvent être un peu obscures :


error C2662: 'int Something::getValue(void)': cannot convert 'this' pointer from 'const Something' to 'Something &'
error: passing 'const Something' as 'this' argument discards qualifiers [-fpermissive]

Lorsque nous appelons une fonction membre non constante sur un objet constant, le paramètre implicite this est un pointeur constant vers un objet non constant. Or l'argument est de type pointeur constant vers un objet constant. Convertir un pointeur vers un objet constant en un pointeur vers un objet non constant nécessite de supprimer le qualificatif const, ce qui ne peut pas se faire implicitement. L'erreur de compilation produite par certains compilateurs traduit le fait que le compilateur refuse d'effectuer une telle conversion.

Pourquoi this est-il un pointeur et non une référence ?

Comme le pointeur this désigne toujours l'objet implicite (et ne peut jamais être un pointeur nul, sauf si nous avons provoqué un comportement indéfini), vous vous demandez peut-être pourquoi this est un pointeur plutôt qu'une référence. La réponse est simple : lorsque this a été ajouté à C++, les références n'existaient pas encore.

Si this était ajouté au langage C++ aujourd'hui, il serait sans aucun doute une référence plutôt qu'un pointeur. Dans d'autres langages modernes proches de C++, comme Java et C#, this est implémenté sous forme de référence.
