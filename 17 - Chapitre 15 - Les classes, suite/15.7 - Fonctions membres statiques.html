15.7 — Fonctions membres statiques

Dans la leçon précédente, 15.6 -- Variables membres statiques, vous avez appris que les variables membres statiques appartiennent à la classe et non aux objets de cette classe. Si une variable membre statique est publique, on peut y accéder directement avec le nom de la classe et l'opérateur de résolution de portée :

#include <iostream>

class Something
{
public:
    static inline int s_value { 1 };
};

int main()
{
    std::cout << Something::s_value; // s_value est publique, nous pouvons y accéder directement
}

Mais que se passe-t-il si une variable membre statique est privée ? Considérez l'exemple suivant :

#include <iostream>

class Something
{
private: // désormais privée
    static inline int s_value { 1 };
};

int main()
{
    std::cout << Something::s_value; // erreur : s_value est privée et ne peut pas être utilisée directement en dehors de la classe
}

Dans ce cas, nous ne pouvons pas accéder directement à Something::s_value depuis main(), puisqu'elle est privée. Normalement, on accède aux membres privés через des fonctions membres publiques. Nous pourrions créer une fonction membre publique ordinaire pour accéder à s_value, mais il faudrait alors instancier un objet de la classe pour appeler cette fonction !

#include <iostream>

class Something
{
private:
    static inline int s_value { 1 };

public:
    int getValue() { return s_value; }
};

int main()
{
    Something s{};
    std::cout << s.getValue(); // fonctionne, mais nous oblige à instancier un objet pour appeler getValue()
}

Nous pouvons faire mieux.

Fonctions membres statiques

Les variables membres ne sont pas les seuls membres pouvant être déclarés statiques. Les fonctions membres peuvent elles aussi être statiques. Voici l'exemple précédent avec une fonction d'accès membre statique :

#include <iostream>

class Something
{
private:
    static inline int s_value { 1 };

public:
    static int getValue() { return s_value; } // fonction membre statique
};

int main()
{
    std::cout << Something::getValue() << '\n';
}

Comme les fonctions membres statiques ne sont pas associées à un objet particulier, elles peuvent être appelées directement avec le nom de la classe et l'opérateur de résolution de portée (par exemple Something::getValue()). Comme les variables membres statiques, elles peuvent aussi être appelées via des objets de la classe, bien que cela ne soit pas recommandé.

Les fonctions membres statiques n'ont pas de pointeur this

Les fonctions membres statiques présentent deux particularités intéressantes. Premièrement, comme elles ne sont pas attachées à un objet, elles n'ont pas de pointeur this ! Cela a du sens si l'on y réfléchit : le pointeur this pointe toujours vers l'objet sur lequel travaille la fonction membre. Or une fonction membre statique ne travaille sur aucun objet, le pointeur this n'est donc pas nécessaire.

Deuxièmement, les fonctions membres statiques peuvent accéder directement aux autres membres statiques (variables ou fonctions), mais pas aux membres non statiques. En effet, les membres non statiques doivent appartenir à un objet de la classe, et une fonction membre statique ne dispose d'aucun objet de la classe avec lequel travailler !

Membres statiques définis en dehors de la définition de la classe

Les fonctions membres statiques peuvent aussi être définies en dehors de la déclaration de la classe. Cela fonctionne de la même manière que pour les fonctions membres ordinaires.

#include <iostream>

class IDGenerator
{
private:
    static inline int s_nextID { 1 };

public:
     static int getNextID(); // Voici la déclaration de la fonction statique
};

// Voici la définition de la fonction statique en dehors de la classe. Notez que nous n'utilisons pas le mot-clé static ici.
int IDGenerator::getNextID() { return s_nextID++; }

int main()
{
    for (int count{ 0 }; count < 5; ++count)
        std::cout << "The next ID is: " << IDGenerator::getNextID() << '\n';

    return 0;
}

Ce programme affiche :


The next ID is: 1
The next ID is: 2
The next ID is: 3
The next ID is: 4
The next ID is: 5

Notez que, comme toutes les données et fonctions de cette classe sont statiques, nous n'avons pas besoin d'instancier un objet de la classe pour utiliser ses fonctionnalités ! Cette classe utilise une variable membre statique pour conserver la valeur du prochain identifiant à attribuer, et fournit une fonction membre statique qui renvoie cet identifiant puis l'incrémente.

Comme indiqué dans la leçon 15.2 -- Classes et fichiers d'en-tête, les fonctions membres définies dans la définition de la classe sont implicitement inline. Les fonctions membres définies en dehors de la définition de la classe ne le sont pas implicitement, mais peuvent le devenir grâce au mot-clé inline. Ainsi, une fonction membre statique définie dans un fichier d'en-tête doit être déclarée inline, afin de ne pas violer la règle de définition unique (ODR, One Definition Rule) si cet en-tête est inclus dans plusieurs unités de traduction.

Une mise en garde sur les classes ne contenant que des membres statiques

Soyez prudent lorsque vous écrivez des classes ne contenant que des membres statiques. Bien que ces « classes purement statiques » (aussi appelées « monostates ») puissent être utiles, elles présentent certains inconvénients potentiels.

Premièrement, comme tous les membres statiques ne sont instanciés qu'une seule fois, il est impossible d'avoir plusieurs copies d'une classe purement statique (sans cloner la classe et la renommer). Par exemple, si vous aviez besoin de deux IDGenerator indépendants, cela ne serait pas possible avec une classe purement statique.

Deuxièmement, dans la leçon sur les variables globales, vous avez appris que ces dernières sont dangereuses, car n'importe quel morceau de code peut modifier leur valeur et casser ainsi une autre partie du programme qui semblait sans rapport. Il en va de même pour les classes purement statiques. Comme tous les membres appartiennent à la classe (et non à un objet de la classe), et que les déclarations de classes ont généralement une portée globale, une classe purement statique équivaut essentiellement à déclarer des fonctions et des variables globales dans un espace de noms accessible globalement, avec tous les inconvénients inhérents aux variables globales.

Plutôt que d'écrire une classe ne contenant que des membres statiques, envisagez d'écrire une classe ordinaire et d'instancier une instance globale de cette classe (les variables globales ont une durée de stockage statique). Ainsi, l'instance globale peut être utilisée lorsque c'est approprié, tout en permettant de créer des instances locales lorsque cela s'avère utile.

Classes purement statiques et espaces de noms

Les classes purement statiques recoupent largement les espaces de noms. Les deux permettent de définir des variables à durée de stockage statique et des fonctions dans leur région de portée. Une différence importante est toutefois que les classes disposent de contrôles d'accès, contrairement aux espaces de noms.

En général, une classe statique est préférable lorsque vous disposez de membres de données statiques et/ou que vous avez besoin de contrôles d'accès. Dans le cas contraire, privilégiez un espace de noms.

Le C++ ne prend pas en charge les constructeurs statiques

Si vous pouvez initialiser des variables membres ordinaires via un constructeur, il est logique, par extension, de pouvoir initialiser des variables membres statiques via un constructeur statique. Et si certains langages modernes prennent effectivement en charge les constructeurs statiques dans ce but précis, le C++ n'en fait malheureusement pas partie.

Si votre variable statique peut être initialisée directement, aucun constructeur n'est nécessaire : vous pouvez initialiser la variable membre statique au moment de sa définition (même si elle est privée). C'est ce que nous avons fait dans l'exemple IDGenerator ci-dessus. Voici un autre exemple :

#include <iostream>

struct Chars
{
    char first{};
    char second{};
    char third{};
    char fourth{};
    char fifth{};
};

struct MyClass
{
    static inline Chars s_mychars { 'a', 'e', 'i', 'o', 'u' }; // initialisation de la variable statique au moment de sa définition
};

int main()
{
    std::cout << MyClass::s_mychars.third; // affiche i

    return 0;
}

Si l'initialisation de votre variable membre statique nécessite l'exécution de code (par exemple une boucle), il existe plusieurs méthodes différentes, assez alambiquées. Une méthode qui fonctionne avec toutes les variables, statiques ou non, consiste à utiliser une fonction qui crée un objet, le remplit de données et le renvoie à l'appelant. Cette valeur renvoyée peut ensuite être copiée dans l'objet en cours d'initialisation.

#include <iostream>

struct Chars
{
    char first{};
    char second{};
    char third{};
    char fourth{};
    char fifth{};
};

class MyClass
{
private:
    static Chars generate()
    {
        Chars c{}; // création d'un objet
        c.first = 'a'; // remplissage de l'objet avec les valeurs de votre choix
        c.second = 'e';
        c.third = 'i';
        c.fourth = 'o';
        c.fifth = 'u';

        return c; // renvoi de l'objet
    }

public:
    static inline Chars s_mychars { generate() }; // copie de l'objet renvoyé dans s_mychars
};

int main()
{
    std::cout << MyClass::s_mychars.third; // affiche i

    return 0;
}

Solution 
#include <chrono>
#include <random>
#include <iostream>

class Random
{
private: // pourrait être publique si nous voulons que ces fonctions soient accessibles
    static std::mt19937 generate()
    {
        std::random_device rd{};

        // Création d'un seed_seq avec l'horloge haute résolution et 7 nombres aléatoires issus de std::random_device
        std::seed_seq ss{
            static_cast<std::seed_seq::result_type>(std::chrono::steady_clock::now().time_since_epoch().count()),
                rd(), rd(), rd(), rd(), rd(), rd(), rd() };

        return std::mt19937{ ss };
    }

    static inline std::mt19937 mt{ generate() }; // génère un std::mt19937 initialisé et le copie dans notre objet global

public:
    // Génère un int aléatoire dans [min, max] (bornes incluses)
    static int get(int min, int max)
    {
        return std::uniform_int_distribution{min, max}(mt);
    }
};

int main()
{
    // Affiche une série de nombres aléatoires
    for (int count{ 1 }; count <= 10; ++count)
        std::cout << Random::get(1, 6) << '\t';

    std::cout << '\n';

    return 0;
}

Tout objet déclaré dans un espace de noms est une variable globale. Lorsque nous déclarons inline std::mt19937 mt dans un espace de noms, nous déclarons mt comme une variable globale inline. Cela permet à l'ensemble du programme d'utiliser une seule instance de std::mt19937 (via la variable globale mt).

En revanche, lorsqu'un objet de classe est instancié, celui-ci contient une copie de chaque membre de données non statique. Nous ne voulons pas que chaque objet de la classe possède sa propre copie de std::mt19937. Nous déclarons donc static inline std::mt19937 mt, ce qui indique au compilateur qu'une seule instance de std::mt19937 doit exister en tant que partie de la classe Random. Définir mt comme static inline en fait une variable inline, ce qui nous permet de l'initialiser dans la définition de la classe (nous abordons ce point dans la leçon 15.6 -- Variables membres statiques).

Nous déclarons également les fonctions membres static afin de pouvoir les utiliser sans instancier d'objet Random.
