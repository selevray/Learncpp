0.8 — Quelques problèmes courants en C++

Dans cette section, nous abordons certains problèmes que rencontrent souvent les nouveaux programmeurs. Il ne s'agit pas d'une liste exhaustive des erreurs de compilation ou d'exécution, mais plutôt d'une liste pratique de solutions à des problèmes très élémentaires. Si vous avez des suggestions d'autres problèmes à ajouter à cette liste, publiez-les dans la section des commentaires ci-dessous.

Problèmes généraux à l'exécution

Q : Lors de l'exécution de mon programme, la fenêtre de console clignote puis se ferme immédiatement.

Tout d'abord, ajoutez ou vérifiez la présence des lignes suivantes en haut de votre programme (utilisateurs de Visual Studio, assurez-vous que ces lignes apparaissent après #include “pch.h” ou #include “stdafx.h”, si ces fichiers existent) :

#include <iostream>
#include <limits>

Ensuite, ajoutez le code suivant à la fin de votre fonction main() (juste avant l'instruction return) :

std::cin.clear(); // réinitialise les indicateurs d'erreur
std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n'); // ignore les caractères du tampon d'entrée jusqu'à trouver un caractère entrée
std::cin.get(); // lit un caractère de plus auprès de l'utilisateur

Cela obligera votre programme à attendre que l'utilisateur appuie sur une touche avant de continuer, ce qui vous laissera le temps d'examiner la sortie de votre programme avant que votre système d'exploitation ne ferme la fenêtre de console.

D'autres solutions, comme la solution souvent suggérée system(“pause”), ne fonctionnent parfois que sur certains systèmes d'exploitation et doivent donc être évitées.

Les anciennes versions de Visual Studio peuvent ne pas marquer de pause lorsque le programme est exécuté en mode Start With Debugging (F5). Essayez alors le mode Start Without Debugging (Ctrl-F5).

Q : J'ai lancé mon programme, j'obtiens une fenêtre mais aucune sortie.

Votre antivirus ou votre logiciel anti-malware bloque peut-être l'exécution. Essayez de le désactiver temporairement pour voir si c'est la cause du problème.

Q : Mon programme compile, mais il ne fonctionne pas correctement. Que dois-je faire ?

Déboguez-le ! Vous trouverez plus loin, dans le chapitre 3, des conseils pour diagnostiquer et déboguer vos programmes.

Problèmes généraux à la compilation

Q : Lors de la compilation, j'obtiens une erreur indiquant unresolved external symbol _main ou _WinMain@16.

Cela signifie que votre compilateur ne trouve pas votre fonction main(). Tout programme doit contenir une fonction main().

Il y a plusieurs points à vérifier :
a) Votre code contient-il une fonction nommée main ?
b) Le nom main est-il orthographié correctement ?
c) Lors de la compilation, voyez-vous le fichier qui contient la fonction main() être compilé ? Sinon, déplacez la fonction main() dans un fichier compilé, ou ajoutez ce fichier à votre projet (voir la leçon 2.8 -- Programmes avec plusieurs fichiers de code pour plus d'informations sur la façon de procéder).
d) Avez-vous créé un projet de type console ? Essayez de créer un nouveau projet de console.

Q : Lors de la compilation, j'obtiens une erreur indiquant que main est déjà défini, ou des définitions multiples pour main.

Un programme C++ ne peut comporter qu'une seule fonction nommée main. Votre programme en contient plusieurs. Examinez les fichiers de votre projet et supprimez toutes les fonctions main sauf une.

Q : J'essaie d'utiliser une fonctionnalité de C++11/14/17/XX, mais elle ne fonctionne pas.

Si votre compilateur est ancien, il ne prend peut-être pas en charge ces ajouts plus récents du langage. Dans ce cas, mettez votre compilateur à jour.

Pour les IDE et compilateurs modernes, il est possible que votre compilateur utilise par défaut une ancienne norme du langage. Nous expliquons comment changer la norme du langage dans la leçon 0.12 -- Configurer votre compilateur : choisir une norme du langage.

Q : Lors de la compilation, j'obtiens une erreur indiquant que le fichier .exe ne peut pas être ouvert en écriture.

Cela signifie que l'éditeur de liens (linker) tente de créer votre exécutable, mais n'y parvient pas. Cela peut avoir plusieurs causes :

  • Le cas le plus fréquent : le fichier .exe est en cours d'exécution. Un exécutable en cours d'exécution ne peut pas être remplacé. Fermez le .exe en cours d'exécution, puis recompilez.
  • Votre antivirus ou votre protection anti-malware empêche la création ou le remplacement de l'exécutable.
  • Le fichier .exe existe déjà et est verrouillé pour une autre raison. Essayez de redémarrer votre machine (pour libérer les verrous), puis recompilez.

Dans Visual Studio, cette erreur correspond à LNK1168.

Q : Lorsque j'utilise cin, cout ou endl, le compilateur indique que cin, cout ou endl est un « identifiant non déclaré » (undeclared identifier).

Tout d'abord, assurez-vous d'avoir inclus la ligne suivante en haut de votre fichier :

#include <iostream>

Ensuite, vérifiez que chaque utilisation de cin, cout et endl est précédée de « std:: ». Par exemple :

std::cout << "Broccoli" << std::endl;

Si cela ne résout pas le problème, il se peut que votre compilateur soit obsolète ou que son installation soit corrompue. Essayez de le réinstaller et/ou de le mettre à jour vers la dernière version.

Q : Lorsque j'essaie d'utiliser endl pour terminer une ligne affichée, le compilateur indique que end1 est un « identifiant non déclaré » (undeclared identifier).

Assurez-vous de ne pas confondre la lettre l (l minuscule) de endl avec le chiffre 1. endl ne contient que des lettres. Vérifiez que votre éditeur utilise une police qui distingue clairement la lettre l minuscule, le i majuscule et le chiffre 1. De même, la lettre O majuscule et le chiffre zéro peuvent facilement être confondus dans de nombreuses polices non destinées à la programmation.

Problèmes liés à Visual Studio

Q : Lors de la compilation avec Microsoft Visual C++, j'obtiens une erreur fatale C1010, avec un message du type « c:\vcprojects\test.cpp(263) :fatal error C1010: unexpected end of file while looking for precompiled header directive »

Cette erreur se produit lorsque le compilateur Microsoft Visual C++ est configuré pour utiliser des en-têtes précompilés, mais qu'un ou plusieurs de vos fichiers de code C++ n'incluent pas « stdafx.h » ou « pch.h » comme première ligne.

Notre solution suggérée consiste à désactiver les en-têtes précompilés, ce que nous montrons comment faire dans la leçon 0.7 -- Compiler votre premier programme.

Si vous souhaitez conserver les en-têtes précompilés activés, pour résoudre ce problème, localisez simplement le ou les fichiers à l'origine de l'erreur (dans l'erreur ci-dessus, c'est test.cpp) et ajoutez la ligne suivante tout en haut de ces fichiers :

#include "pch.h"

Les anciennes versions de Visual Studio utilisent « stdafx.h » au lieu de « pch.h ». Si pch.h ne résout pas le problème, essayez donc stdafx.h.

Notez que, pour les programmes composés de plusieurs fichiers, chaque fichier de code C++ doit commencer par cette ligne.

Q : Visual Studio affiche une erreur du type : « 1MSVCRTD.lib(exe_winmain.obj) : error LNK2022: unresolved external symbol _WinMain@16 referenced in function "int __cdecl invoke_main(void)" (?invoke_main@@YAHXZ) »

Vous avez probablement créé une application graphique Windows plutôt qu'une application console. Recréez votre projet et assurez-vous de le créer sous forme de projet Windows (ou Win32) Console.

Q : Lors de la compilation, j'obtiens un avertissement indiquant « Cannot find or open the PDB file ».

Il s'agit d'un avertissement et non d'une erreur, il ne devrait donc pas affecter votre programme. Il est toutefois gênant. Pour le corriger, allez dans le menu Debug -> Options and Settings -> Symbols, puis cochez « Microsoft Symbol Server ».

Autre chose

Q : J'ai un autre problème que je n'arrive pas à résoudre. Comment obtenir rapidement une réponse ?

À mesure que vous avancez dans le cours, vous aurez sans doute des questions ou rencontrerez des problèmes inattendus. Que faire ensuite dépend du problème. Dans l'ensemble, vous pouvez toutefois essayer plusieurs choses.

Premièrement, interrogez un moteur de recherche. Formulez bien votre question, puis lancez une recherche. Si vous recherchez un message d'erreur, copiez-le exactement entre guillemets (sans les noms de fichiers ni les numéros de ligne). Il y a de fortes chances que quelqu'un ait déjà posé la même question et qu'une réponse vous attende.

Deuxièmement, interrogez une IA, comme ChatGPT via Bing. Commencez votre question par « En C++, » pour obtenir une réponse spécifique au C++. Voici quelques exemples de demandes :

  • Une explication d'un concept (par exemple « En C++, qu'est-ce qu'une variable locale ? »).
  • La différence entre deux notions (par exemple « En C++, quelle est la différence entre un pointeur et une référence ? »).
  • Une démonstration d'un concept (par exemple « En C++, écris un court programme qui additionne deux nombres »).

Gardez à l'esprit que les IA peuvent fournir des informations inexactes ou obsolètes, et que les programmes qu'elles écrivent ne suivront probablement pas les bonnes pratiques modernes.

Si les solutions précédentes échouent, posez votre question sur un forum de questions-réponses. Il existe des sites conçus pour les questions et réponses de programmation, comme Stack Overflow. Essayez d'y publier votre question. Pensez à bien décrire votre problème et à fournir toutes les informations utiles, comme le système d'exploitation que vous utilisez et l'IDE employé.
