7.4 — Introduction aux variables globales

Dans la leçon 7.3 -- Variables locales, nous avons vu que les variables locales sont des variables définies à l'intérieur du corps d'une fonction. Les variables locales ont une portée de bloc (elles ne sont visibles qu'à l'intérieur du bloc où elles sont déclarées) et une durée automatique (elles sont créées au point de leur définition et détruites à la sortie du bloc).

En C++, des variables peuvent aussi être déclarées en dehors d'une fonction. On les appelle des variables globales.

Déclaration de variables globales

Par convention, les variables globales sont déclarées en haut d'un fichier, après les directives #include, dans l'espace de noms global (global namespace). Voici un exemple de définition d'une variable globale :

#include <iostream>

// Les variables déclarées en dehors d'une fonction sont des variables globales
int g_x {}; // variable globale g_x

void doSomething()
{
    // les variables globales sont visibles et utilisables partout dans le fichier
    g_x = 3;
    std::cout << g_x << '\n';
}

int main()
{
    doSomething();
    std::cout << g_x << '\n';

    // les variables globales sont visibles et utilisables partout dans le fichier
    g_x = 5;
    std::cout << g_x << '\n';

    return 0;
}
// g_x sort de portée ici

La portée des variables globales

Les identificateurs déclarés dans l'espace de noms global ont une portée d'espace de noms global (couramment appelée portée globale (global scope), et parfois informellement portée de fichier (file scope)). Cela signifie qu'ils sont visibles depuis le point de déclaration jusqu'à la fin du fichier dans lequel ils sont déclarés.

Une fois déclarée, une variable globale peut être utilisée n'importe où dans le fichier à partir de ce point ! Dans l'exemple ci-dessus, la variable globale g_x est utilisée à la fois dans la fonction doSomething() et dans main().

Les variables globales peuvent aussi être définies à l'intérieur d'un espace de noms défini par l'utilisateur. Voici le même exemple que précédemment, mais g_x a été déplacée de la portée globale vers l'espace de noms Foo défini par l'utilisateur :

#include <iostream>

namespace Foo // Foo est défini dans la portée globale
{
    int g_x {}; // g_x est maintenant à l'intérieur de l'espace de noms Foo, mais reste une variable globale
}

void doSomething()
{
    // les variables globales sont visibles et utilisables partout dans le fichier
    Foo::g_x = 3;
    std::cout << Foo::g_x << '\n';
}

int main()
{
    doSomething();
    std::cout << Foo::g_x << '\n';

    // les variables globales sont visibles et utilisables partout dans le fichier
    Foo::g_x = 5;
    std::cout << Foo::g_x << '\n';

    return 0;
}

Bien que l'identificateur g_x soit maintenant limité à la portée de l'espace de noms Foo, ce nom reste accessible globalement (via Foo::g_x), et g_x reste une variable globale.

Point clé

Les variables déclarées à l'intérieur d'un espace de noms sont aussi des variables globales.

Bonne pratique

Préférez définir les variables globales à l'intérieur d'un espace de noms plutôt que dans l'espace de noms global.

Les variables globales ont une durée statique

Les variables globales sont créées au démarrage du programme (avant que main() ne commence son exécution) et détruites à sa fin. C'est ce qu'on appelle la durée statique (static duration). Les variables ayant une durée statique sont parfois appelées variables statiques (static variables).

Nommage des variables globales

Par convention, certains développeurs préfixent les identificateurs des variables globales avec « g » ou « g_ » pour indiquer qu'elles sont globales. Ce préfixe a plusieurs utilités :

  • Il permet d'éviter les collisions de noms avec d'autres identificateurs de l'espace de noms global.
  • Il aide à prévenir les masquages de noms involontaires (nous en discutons plus en détail dans la leçon 7.5 -- Masquage de variables (name hiding)).
  • Il indique que les variables ainsi préfixées persistent au-delà de la portée de la fonction, et donc que toute modification que nous leur apportons persistera également.

Les variables globales définies dans un espace de noms défini par l'utilisateur omettent souvent le préfixe (puisque les deux premiers points ci-dessus ne posent pas de problème dans ce cas, et qu'on peut déduire qu'une variable est globale en voyant le nom de l'espace de noms qui la précède). Cependant, rien n'empêche de garder le préfixe comme rappel plus visible du troisième point.

Bonne pratique

Envisagez d'utiliser le préfixe « g » ou « g_ » pour nommer les variables globales (en particulier celles définies dans l'espace de noms global), afin de les distinguer des variables locales et des paramètres de fonction.

Note de l'auteur

Nous recevons parfois des retours de lecteurs qui demandent si des préfixes comme g_ sont acceptables, car on leur a dit que les préfixes sont une forme de notation hongroise et que « la notation hongroise est mauvaise ».

L'objection à la notation hongroise vient principalement de son usage pour encoder le type de la variable dans son nom, par exemple nAge, où n signifie int. Cela n'est pas très utile en C++ moderne.

En revanche, utiliser des préfixes (typiquement g/g_, s/s_ et m/m_) pour représenter la portée ou la durée d'une variable apporte une réelle valeur, pour les raisons évoquées dans cette section.

Initialisation des variables globales

Contrairement aux variables locales, qui ne sont pas initialisées par défaut, les variables ayant une durée statique sont initialisées à zéro par défaut (zero-initialized).

Les variables globales non constantes peuvent être initialisées de manière facultative :

int g_x;       // aucun initialiseur explicite (initialisée à zéro par défaut)
int g_y {};    // initialisée par valeur (ce qui donne une initialisation à zéro)
int g_z { 1 }; // initialisée par liste avec une valeur précise

Variables globales constantes

Comme les variables locales, les variables globales peuvent être constantes. Comme pour toutes les constantes, les variables globales constantes doivent être initialisées.

#include <iostream>

const int g_x;     // erreur : les variables constantes doivent être initialisées
constexpr int g_w; // erreur : les variables constexpr doivent être initialisées

const int g_y { 1 };     // variable globale constante g_y, initialisée avec une valeur
constexpr int g_z { 2 }; // variable globale constexpr g_z, initialisée avec une valeur

void doSomething()
{
    // les variables globales sont visibles et utilisables partout dans le fichier
    std::cout << g_y << '\n';
    std::cout << g_z << '\n';
}

int main()
{
    doSomething();

    // les variables globales sont visibles et utilisables partout dans le fichier
    std::cout << g_y << '\n';
    std::cout << g_z << '\n';

    return 0;
}
// g_y et g_z sortent de portée ici

Une mise en garde au sujet des variables globales (non constantes)

Les nouveaux programmeurs sont souvent tentés d'utiliser beaucoup de variables globales, car elles peuvent être utilisées sans avoir à les passer explicitement à chaque fonction qui en a besoin. Cependant, l'usage de variables globales non constantes doit généralement être évité complètement ! Nous expliquerons pourquoi dans la prochaine leçon 7.8 -- Pourquoi les variables globales (non const) sont mauvaises.

Résumé rapide

// Variables globales non constantes
int g_x;                 // définit une variable globale non initialisée (initialisée à zéro par défaut)
int g_x {};              // définit une variable globale explicitement initialisée par valeur
int g_x { 1 };           // définit une variable globale explicitement initialisée

// Variables globales constantes
const int g_y;           // erreur : les variables const doivent être initialisées
const int g_y { 2 };     // définit une variable globale const initialisée

// Variables globales constexpr
constexpr int g_y;       // erreur : les variables constexpr doivent être initialisées
constexpr int g_y { 3 }; // définit une variable globale constexpr initialisée
