7.11 — Variables locales statiques

Le mot-clé static est l'un des termes les plus déroutants du langage C++, en grande partie parce qu'il a des significations différentes selon le contexte.

Dans les leçons précédentes, nous avons vu que les variables globales ont une durée de vie statique, ce qui signifie qu'elles sont créées au démarrage du programme et détruites à sa fin.

Nous avons également vu que le mot-clé static donne à un identifiant global un lien interne (internal linkage), ce qui signifie que cet identifiant ne peut être utilisé que dans le fichier où il est défini.

Dans cette leçon, nous allons explorer l'utilisation du mot-clé static appliqué à une variable locale.

Variables locales statiques

Dans la leçon 2.5 -- Introduction à la portée locale, vous avez appris que les variables locales ont par défaut une durée de vie automatique, ce qui signifie qu'elles sont créées au point de leur définition et détruites à la sortie du bloc.

Utiliser le mot-clé static sur une variable locale change sa durée de vie, qui passe de automatique à statique. La variable est alors créée au début du programme et détruite à la fin de celui-ci (exactement comme une variable globale). Par conséquent, une variable statique conserve sa valeur même après être sortie de sa portée !

La meilleure façon de montrer la différence entre une variable locale à durée automatique et une variable locale à durée statique est de passer par un exemple.

Durée automatique (par défaut) :

#include <iostream>

void incrementAndPrint()
{
    int value{ 1 }; // durée automatique par défaut
    ++value;
    std::cout << value << '\n';
} // value est détruite ici

int main()
{
    incrementAndPrint();
    incrementAndPrint();
    incrementAndPrint();

    return 0;
}

À chaque appel de incrementAndPrint(), une variable nommée value est créée et initialisée à 1. incrementAndPrint() incrémente value à 2, puis affiche la valeur 2. Lorsque incrementAndPrint() a fini de s'exécuter, la variable sort de sa portée et est détruite. Ce programme affiche donc :


2
2
2

Considérons maintenant une version de ce programme qui utilise une variable locale statique. La seule différence avec le programme ci-dessus est que nous avons fait passer la variable locale d'une durée automatique à une durée statique en utilisant le mot-clé static.

Durée statique (avec le mot-clé static) :

#include <iostream>

void incrementAndPrint()
{
    static int s_value{ 1 }; // durée statique grâce au mot-clé static. Cet initialisateur n'est exécuté qu'une seule fois.
    ++s_value;
    std::cout << s_value << '\n';
} // s_value n'est pas détruite ici, mais devient inaccessible car elle sort de sa portée

int main()
{
    incrementAndPrint();
    incrementAndPrint();
    incrementAndPrint();

    return 0;
}

Dans ce programme, comme s_value est déclarée static, elle est créée au démarrage du programme.

Les variables locales statiques initialisées à zéro ou dont l'initialisateur est constexpr peuvent être initialisées au démarrage du programme.

Les variables locales statiques sans initialisateur, ou dont l'initialisateur n'est pas constexpr, sont initialisées à zéro au démarrage du programme. Les variables locales statiques dont l'initialisateur n'est pas constexpr sont réinitialisées la première fois que la définition de la variable est rencontrée. La définition est ignorée lors des appels suivants, donc aucune autre réinitialisation n'a lieu. Comme elles ont une durée statique, les variables locales statiques qui ne sont pas explicitement initialisées sont initialisées à zéro par défaut.

Comme s_value a pour initialisateur la constante constexpr 1, s_value est initialisée au démarrage du programme.

Lorsque s_value sort de sa portée à la fin de la fonction, elle n'est pas détruite. À chaque appel de la fonction incrementAndPrint(), la valeur de s_value reste celle que nous lui avons laissée précédemment. Ce programme affiche donc :


2
3
4

Point clé

Les variables locales statiques sont utilisées lorsque vous avez besoin qu'une variable locale se souvienne de sa valeur d'un appel de fonction à l'autre.

Bonne pratique

Initialisez vos variables locales statiques. Elles ne sont initialisées que la première fois que le code est exécuté, et non lors des appels suivants.

Astuce

De même que l'on utilise le préfixe « g_ » pour les variables globales, il est courant d'utiliser le préfixe « s_ » pour les variables locales statiques (à durée statique).

Génération d'identifiants

L'un des usages les plus courants des variables locales à durée statique est la génération d'identifiants uniques. Imaginez un programme dans lequel vous manipulez de nombreux objets similaires (par exemple un jeu où vous êtes attaqué par de nombreux zombies, ou une simulation qui affiche de nombreux triangles). Si vous remarquez un défaut, il peut être presque impossible de déterminer quel objet pose problème. En revanche, si chaque objet reçoit un identifiant unique à sa création, il devient plus facile de distinguer les objets pour poursuivre le débogage.

Générer un numéro d'identifiant unique est très simple avec une variable locale à durée statique :

int generateID()
{
    static int s_itemID{ 0 };
    return s_itemID++; // effectue une copie de s_itemID, incrémente le véritable s_itemID, puis renvoie la valeur de la copie
}

La première fois que cette fonction est appelée, elle renvoie 0. La deuxième fois, elle renvoie 1. À chaque appel, elle renvoie un nombre supérieur d'une unité à celui renvoyé lors de l'appel précédent. Vous pouvez attribuer ces numéros comme identifiants uniques à vos objets. Comme s_itemID est une variable locale, elle ne peut pas être « modifiée à mauvais escient » par d'autres fonctions.

Les variables statiques offrent une partie des avantages des variables globales (elles ne sont détruites qu'à la fin du programme) tout en limitant leur visibilité au bloc dans lequel elles sont définies. Cela les rend plus faciles à comprendre et plus sûres à utiliser.

Point clé

Une variable locale statique a une portée de bloc comme une variable locale, mais sa durée de vie s'étend jusqu'à la fin du programme, comme une variable globale.

Constantes locales statiques

Les variables locales statiques peuvent être déclarées const (ou constexpr). Une bonne utilisation d'une variable locale statique constante est le cas où une fonction a besoin d'une valeur constante, mais où la création ou l'initialisation de l'objet est coûteuse (par exemple, si vous devez lire la valeur dans une base de données). Avec une variable locale ordinaire, la variable serait créée et initialisée à chaque exécution de la fonction. Avec une variable locale statique const/constexpr, vous pouvez créer et initialiser cet objet coûteux une seule fois, puis le réutiliser à chaque appel de la fonction.

Point clé

Les variables locales statiques sont surtout utiles pour éviter une initialisation coûteuse d'objets locaux à chaque appel de fonction.

Ne pas utiliser les variables locales statiques pour modifier le flux d'exécution

Considérez le code suivant :

#include <iostream>

int getInteger()
{
    static bool s_isFirstCall{ true };

    if (s_isFirstCall)
    {
        std::cout << "Enter an integer: ";
        s_isFirstCall = false;
    }
    else
    {
        std::cout << "Enter another integer: ";
    }

    int i{};
    std::cin >> i;
    return i;
}

int main()
{
    int a{ getInteger() };
    int b{ getInteger() };

    std::cout << a << " + " << b << " = " << (a + b) << '\n';

    return 0;
}

Exemple de sortie :


Enter an integer: 5
Enter another integer: 9
5 + 9 = 14

Ce code fait ce qu'il est censé faire, mais parce que nous avons utilisé une variable locale statique, nous l'avons rendu plus difficile à comprendre. Si quelqu'un lit le code de main() sans lire l'implémentation de getInteger(), il n'a aucune raison de supposer que les deux appels à getInteger() font des choses différentes. Pourtant, les deux appels font bien des choses différentes, ce qui peut être très déroutant si la différence va au-delà d'une simple invite modifiée.

Imaginez que vous appuyez sur le bouton +1 de votre micro-ondes, qui ajoute 1 minute au temps restant. Votre repas est chaud et vous êtes content. Avant de sortir votre plat, vous apercevez un chat à travers la fenêtre et l'observez un instant, parce que les chats sont géniaux. Ce moment a duré plus longtemps que prévu, et lorsque vous prenez la première bouchée, votre repas est de nouveau froid. Pas de problème, il suffit de le remettre au micro-ondes et d'appuyer sur +1 pour le chauffer une minute. Mais cette fois, le micro-ondes n'ajoute qu'une seconde au lieu d'une minute. C'est là que vous vous dites « je n'ai rien changé et maintenant ça ne marche plus » ou « la dernière fois, ça marchait ». Si vous refaites exactement la même chose, vous vous attendez au même comportement que la fois précédente. Il en va de même pour les fonctions.

Supposons que nous voulions ajouter la soustraction à notre calculatrice, de sorte que la sortie ressemble à ceci :


Addition
Enter an integer: 5
Enter another integer: 9
5 + 9 = 14
Subtraction
Enter an integer: 12
Enter another integer: 3
12 - 3 = 9

Nous pourrions essayer d'utiliser getInteger() pour lire les deux entiers suivants, comme nous l'avons fait pour l'addition.

int main()
{
  std::cout << "Addition\n";

  int a{ getInteger() };
  int b{ getInteger() };

  std::cout << a << " + " << b << " = " << (a + b) << '\n';

  std::cout << "Subtraction\n";

  int c{ getInteger() };
  int d{ getInteger() };

  std::cout << c << " - " << d << " = " << (c - d) << '\n';

  return 0;
}

Mais cela ne donnera pas le résultat souhaité, car la sortie est :


Addition
Enter an integer: 5
Enter another integer: 9
5 + 9 = 14
Subtraction
Enter another integer: 12
Enter another integer: 3
12 - 3 = 9

(L'avant-dernière ligne affiche « Enter another integer » au lieu de « Enter an integer »)

getInteger() n'est pas réutilisable, car elle possède un état interne (la variable locale statique s_isFirstCall) qui ne peut pas être réinitialisé depuis l'extérieur. s_isFirstCall n'est pas une variable qui devrait être unique dans tout le programme. Bien que notre programme ait parfaitement fonctionné lors de sa première écriture, la variable locale statique nous empêche de réutiliser la fonction plus tard.

Une meilleure façon d'implémenter getInteger consiste à passer s_isFirstCall en paramètre. Cela permet à l'appelant de choisir l'invite qui sera affichée :

#include <iostream>

// Nous allons définir une constante symbolique avec un nom plus parlant
constexpr bool g_firstCall { true };

int getInteger(bool bFirstCall)
{
    if (bFirstCall)
    {
        std::cout << "Enter an integer: ";
    }
    else
    {
        std::cout << "Enter another integer: ";
    }

    int i{};
    std::cin >> i;
    return i;
}

int main()
{
    int a{ getInteger(g_firstCall) };  // pour que l'on comprenne mieux ce que représente l'argument ici
    int b{ getInteger(!g_firstCall) };

    std::cout << a << " + " << b << " = " << (a + b) << '\n';

    return 0;
}

Les variables locales statiques non constantes ne doivent être utilisées que si, dans l'ensemble de votre programme et dans un avenir prévisible, la variable est unique et qu'il n'aurait aucun sens de la réinitialiser.

Bonne pratique

Les variables locales statiques const peuvent généralement être utilisées sans problème.

Les variables locales statiques non const doivent généralement être évitées. Si vous les utilisez, assurez-vous que la variable n'a jamais besoin d'être réinitialisée et qu'elle ne sert pas à modifier le flux d'exécution du programme.

Astuce

Une solution encore plus réutilisable consisterait à remplacer le paramètre bool par un std::string_view et à laisser l'appelant fournir le texte de l'invite à utiliser !

Pour les lecteurs avancés

Lorsque vous avez besoin de plusieurs instances d'une variable non constante qui conserve sa valeur (par exemple pour disposer de plusieurs générateurs d'identifiants), un foncteur est une bonne solution (voir la leçon 21.10 -- Surcharge de l'opérateur parenthèse).

Quiz

Question n° 1

Quel effet le mot-clé static a-t-il sur une variable globale ? Quel effet a-t-il sur une variable locale ?

Solution

Appliqué à une variable globale, le mot-clé static donne à cette variable un lien interne, ce qui signifie qu'elle ne peut pas être exportée vers d'autres fichiers.

Appliqué à une variable locale, le mot-clé static donne à cette variable une durée de vie statique, ce qui signifie qu'elle n'est créée qu'une seule fois et qu'elle n'est détruite qu'à la fin du programme.
