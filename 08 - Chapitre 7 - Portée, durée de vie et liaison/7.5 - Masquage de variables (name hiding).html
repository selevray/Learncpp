7.5 — Masquage de variables (name hiding)

Chaque bloc définit sa propre région de portée. Que se passe-t-il alors lorsqu'une variable située dans un bloc imbriqué porte le même nom qu'une variable d'un bloc englobant ? Dans ce cas, la variable imbriquée « masque » la variable externe dans les zones où les deux sont visibles. C'est ce qu'on appelle le masquage de nom (name hiding) ou shadowing.

Masquage de variables locales

#include <iostream>

int main()
{ // bloc externe
    int apples { 5 }; // voici les pommes du bloc externe

    { // bloc imbriqué
        // apples désigne ici les pommes du bloc externe
        std::cout << apples << '\n'; // affiche la valeur des pommes du bloc externe

        int apples{ 0 }; // définit apples dans la portée du bloc imbriqué

        // apples désigne maintenant les pommes du bloc imbriqué
        // les pommes du bloc externe sont temporairement masquées

        apples = 10; // affecte la valeur 10 aux pommes du bloc imbriqué, et non à celles du bloc externe

        std::cout << apples << '\n'; // affiche la valeur des pommes du bloc imbriqué
    } // les pommes du bloc imbriqué sont détruites


    std::cout << apples << '\n'; // affiche la valeur des pommes du bloc externe

    return 0;
} // les pommes du bloc externe sont détruites

Si vous exécutez ce programme, il affiche :


5
10
5

Dans le programme ci-dessus, nous déclarons d'abord une variable nommée apples dans le bloc externe. Cette variable est visible dans le bloc interne, ce que l'on constate en affichant sa valeur (5). Ensuite, nous déclarons une autre variable (également nommée apples) dans le bloc imbriqué. À partir de ce point et jusqu'à la fin du bloc, le nom apples désigne les pommes du bloc imbriqué, et non celles du bloc externe.

Ainsi, lorsque nous affectons la valeur 10 à apples, nous l'affectons à la variable du bloc imbriqué. Après avoir affiché cette valeur (10), le bloc imbriqué se termine et sa variable apples est détruite. L'existence et la valeur de la variable apples du bloc externe ne sont pas affectées, comme le prouve l'affichage de sa valeur (5).

Notez que si la variable apples du bloc imbriqué n'avait pas été définie, le nom apples dans ce bloc désignerait toujours la variable du bloc externe, et l'affectation de la valeur 10 aurait donc porté sur celle-ci :

#include <iostream>

int main()
{ // bloc externe
    int apples{5}; // voici les pommes du bloc externe

    { // bloc imbriqué
        // apples désigne ici les pommes du bloc externe
        std::cout << apples << '\n'; // affiche la valeur des pommes du bloc externe

        // aucune variable apples n'est définie dans le bloc imbriqué dans cet exemple

        apples = 10; // cela s'applique aux pommes du bloc externe

        std::cout << apples << '\n'; // affiche la valeur des pommes du bloc externe
    } // les pommes du bloc externe conservent leur valeur après la sortie du bloc imbriqué

    std::cout << apples << '\n'; // affiche la valeur des pommes du bloc externe

    return 0;
} // les pommes du bloc externe sont détruites

Le programme ci-dessus affiche :


5
10
10

Lorsque l'on se trouve dans le bloc imbriqué, il n'existe aucun moyen d'accéder directement à la variable masquée du bloc externe.

Masquage de variables globales

De la même manière que les variables d'un bloc imbriqué peuvent masquer celles d'un bloc externe, une variable locale portant le même nom qu'une variable globale masquera cette dernière partout où la variable locale est visible :

#include <iostream>
int value { 5 }; // variable globale

void foo()
{
    std::cout << "valeur de la variable globale : " << value << '\n'; // value n'est pas masquée ici, donc cela désigne la valeur globale
}

int main()
{
    int value { 7 }; // masque la variable globale value (partout où la variable locale value est visible)

    ++value; // incrémente la valeur locale, et non la valeur globale

    std::cout << "valeur de la variable locale : " << value << '\n';

    foo();

    return 0;
} // la valeur locale est détruite

Ce code affiche :


valeur de la variable locale : 8
valeur de la variable globale : 5

Toutefois, comme les variables globales font partie de l'espace de noms global, nous pouvons utiliser l'opérateur de résolution de portée (::) sans préfixe pour indiquer au compilateur que nous voulons désigner la variable globale plutôt que la variable locale.

#include <iostream>
int value { 5 }; // variable globale

int main()
{
    int value { 7 }; // masque la variable globale value
    ++value; // incrémente la valeur locale, et non la valeur globale

    --(::value); // décrémente la valeur globale, et non la valeur locale (parenthèses ajoutées pour la lisibilité)

    std::cout << "valeur de la variable locale : " << value << '\n';
    std::cout << "valeur de la variable globale : " << ::value << '\n';

    return 0;
} // la valeur locale est détruite

Ce code affiche :


valeur de la variable locale : 8
valeur de la variable globale : 4

Éviter le masquage de variables

Le masquage de variables locales doit généralement être évité, car il peut entraîner des erreurs involontaires où la mauvaise variable est utilisée ou modifiée. Certains compilateurs émettent un avertissement lorsqu'une variable est masquée.

Pour la même raison que celle qui nous conduit à éviter de masquer des variables locales, nous recommandons également d'éviter de masquer des variables globales. Cela est très facile à éviter si tous vos noms globaux utilisent le préfixe « g_ ».

Bonne pratique

Évitez le masquage de variables.

Pour les utilisateurs de gcc

GCC et Clang prennent en charge l'option -Wshadow, qui génère des avertissements lorsqu'une variable est masquée. Il existe plusieurs sous-variantes de cette option (-Wshadow=global, -Wshadow=local et -Wshadow=compatible-local). Consultez la documentation de GCC pour une explication des différences.

Visual Studio active ces avertissements par défaut.
