7.1 — Instructions composées (blocs)

Une instruction composée (appelée aussi bloc, ou instruction de bloc) est un groupe de zéro instruction ou plus que le compilateur traite comme s'il s'agissait d'une seule instruction.

Les blocs commencent par un symbole { et se terminent par un symbole }, les instructions à exécuter étant placées entre les deux. Les blocs peuvent être utilisés partout où une seule instruction est autorisée. Aucun point-virgule n'est nécessaire à la fin d'un bloc.

Vous avez déjà rencontré un exemple de bloc lorsque vous avez écrit des fonctions, puisque le corps d'une fonction est un bloc :

int add(int x, int y)
{ // début du bloc
    return x + y;
} // fin du bloc (pas de point-virgule)

int main()
{ // début du bloc

    // plusieurs instructions
    int value {}; // ceci est une initialisation, pas un bloc
    add(3, 4);

    return 0;

} // fin du bloc (pas de point-virgule)

Blocs imbriqués dans d'autres blocs

Bien que les fonctions ne puissent pas être imbriquées dans d'autres fonctions, les blocs peuvent être imbriqués dans d'autres blocs :

int add(int x, int y)
{ // bloc
    return x + y;
} // fin du bloc

int main()
{ // bloc externe

    // plusieurs instructions
    int value {};

    { // bloc interne/imbriqué
        add(3, 4);
    } // fin du bloc interne/imbriqué

    return 0;

} // fin du bloc externe

Lorsque des blocs sont imbriqués, le bloc englobant est généralement appelé bloc externe et le bloc contenu est appelé bloc interne ou bloc imbriqué.

Utiliser des blocs pour exécuter plusieurs instructions conditionnellement

L'un des cas d'utilisation les plus courants des blocs concerne les if (instructions conditionnelles). Par défaut, une instruction if exécute une seule instruction si la condition est évaluée à true. Cependant, nous pouvons remplacer cette instruction unique par un bloc d'instructions si nous voulons que plusieurs instructions s'exécutent lorsque la condition est évaluée à true.

Par exemple :

#include <iostream>

int main()
{ // début du bloc externe
    std::cout << "Entrez un entier : ";
    int value {};
    std::cin >> value;

    if (value >= 0)
    { // début du bloc imbriqué
        std::cout << value << " est un entier positif (ou nul)\n";
        std::cout << "Le double de ce nombre est " << value * 2 << '\n';
    } // fin du bloc imbriqué
    else
    { // début d'un autre bloc imbriqué
        std::cout << value << " est un entier négatif\n";
        std::cout << "L'opposé de ce nombre est " << -value << '\n';
    } // fin de l'autre bloc imbriqué

    return 0;
} // fin du bloc externe

Si l'utilisateur saisit le nombre 3, ce programme affiche :


Entrez un entier : 3
3 est un entier positif (ou nul)
Le double de ce nombre est 6

Si l'utilisateur saisit le nombre -4, ce programme affiche :


Entrez un entier : -4
-4 est un entier négatif
L'opposé de ce nombre est 4

Niveaux d'imbrication des blocs

Il est même possible de placer des blocs à l'intérieur de blocs, eux-mêmes à l'intérieur d'autres blocs :

#include <iostream>

int main()
{ // bloc 1, niveau d'imbrication 1
    std::cout << "Entrez un entier : ";
    int value {};
    std::cin >> value;

    if (value >  0)
    { // bloc 2, niveau d'imbrication 2
        if ((value % 2) == 0)
        { // bloc 3, niveau d'imbrication 3
            std::cout << value << " est positif et pair\n";
        }
        else
        { // bloc 4, également niveau d'imbrication 3
            std::cout << value << " est positif et impair\n";
        }
    }

    return 0;
}

Le niveau d'imbrication (appelé aussi profondeur d'imbrication) d'une fonction correspond au nombre maximal de blocs imbriqués dans lesquels vous pouvez vous trouver à un instant donné de la fonction (en comptant le bloc externe). Dans la fonction ci-dessus, il y a 4 blocs, mais le niveau d'imbrication est de 3, car dans ce programme vous ne pouvez jamais vous trouver à l'intérieur de plus de 3 blocs à la fois.

La norme C++ indique que les compilateurs C++ devraient prendre en charge 256 niveaux d'imbrication, mais tous ne le font pas (par exemple, au moment de la rédaction, Visual Studio en prend en charge moins).

Il est judicieux de limiter le niveau d'imbrication à 3 ou moins. De même que les fonctions trop longues sont de bons candidats à la refactorisation (découpage en fonctions plus petites), les blocs trop imbriqués sont difficiles à lire et sont de bons candidats à la refactorisation (les blocs les plus imbriqués devenant des fonctions distinctes).

Bonne pratique

Limitez le niveau d'imbrication de vos fonctions à 3 ou moins. Si une fonction nécessite davantage de niveaux d'imbrication, envisagez de la refactoriser en sous-fonctions.
