24.3 — Ordre de construction des classes dérivées

Dans la leçon précédente sur l'héritage de base en C++, vous avez appris que des classes peuvent hériter des membres et des fonctions d'autres classes. Dans cette leçon, nous allons examiner de plus près l'ordre de construction qui se produit lorsqu'une classe dérivée est instanciée.

Commençons par introduire de nouvelles classes qui nous aideront à illustrer certains points importants.

class Base
{
public:
    int m_id {};

    Base(int id=0)
        : m_id { id }
    {
    }

    int getId() const { return m_id; }
};

class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0)
        : m_cost { cost }
    {
    }

    double getCost() const { return m_cost; }
};

Dans cet exemple, la classe Derived dérive de la classe Base.

Comme Derived hérite des fonctions et des variables de Base, vous pourriez supposer que les membres de Base sont copiés dans Derived. Ce n'est pas le cas. On peut plutôt considérer Derived comme une classe en deux parties : une partie Derived et une partie Base.

Vous avez déjà vu de nombreux exemples de ce qui se passe lorsque l'on instancie une classe normale (non dérivée) :

int main()
{
    Base base;

    return 0;
}

Base est une classe non dérivée, car elle n'hérite d'aucune autre classe. C++ alloue de la mémoire pour Base, puis appelle le constructeur par défaut de Base pour effectuer l'initialisation.

Examinons maintenant ce qui se passe lorsque l'on instancie une classe dérivée :

int main()
{
    Derived derived;

    return 0;
}

Si vous essayez ce code vous-même, vous ne remarquerez aucune différence avec l'exemple précédent où nous instancions la classe non dérivée Base. Pourtant, en coulisse, les choses se déroulent légèrement différemment. Comme mentionné plus haut, Derived est en réalité composée de deux parties : une partie Base et une partie Derived. Lorsque C++ construit un objet dérivé, il le fait en plusieurs phases. D'abord, la classe la plus basse (au sommet de l'arbre d'héritage) est construite. Ensuite, chaque classe enfant est construite à son tour, jusqu'à la classe la plus dérivée (au bas de l'arbre d'héritage), qui est construite en dernier.

Ainsi, lorsque nous instancions un objet de Derived, la partie Base de Derived est d'abord construite (à l'aide du constructeur par défaut de Base). Une fois la partie Base terminée, la partie Derived est construite (à l'aide du constructeur par défaut de Derived). À ce stade, il n'existe plus de classe dérivée, la construction est donc terminée.

Ce processus est facile à illustrer.

#include <iostream>

class Base
{
public:
    int m_id {};

    Base(int id=0)
        : m_id { id }
    {
        std::cout << "Base\n";
    }

    int getId() const { return m_id; }
};

class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0)
        : m_cost { cost }
    {
        std::cout << "Derived\n";
    }

    double getCost() const { return m_cost; }
};

int main()
{
    std::cout << "Instantiating Base\n";
    Base base;

    std::cout << "Instantiating Derived\n";
    Derived derived;

    return 0;
}

Ce programme produit le résultat suivant :


Instantiating Base
Base
Instantiating Derived
Base
Derived

Comme vous pouvez le voir, lorsque Derived est construite, la partie Base de Derived est construite en premier. Cela a du sens : logiquement, un enfant ne peut pas exister sans son parent. C'est aussi la manière sûre de procéder : la classe enfant utilise souvent des variables et des fonctions du parent, alors que la classe parent ne connaît rien de l'enfant. Instancier la classe parent en premier garantit que ces variables sont déjà initialisées au moment où la classe dérivée est créée et prête à les utiliser.

Ordre de construction pour les chaînes d'héritage

Il arrive que des classes dérivent d'autres classes, qui dérivent elles-mêmes d'autres classes. Par exemple :

#include <iostream>

class A
{
public:
    A()
    {
        std::cout << "A\n";
    }
};

class B: public A
{
public:
    B()
    {
        std::cout << "B\n";
    }
};

class C: public B
{
public:
    C()
    {
        std::cout << "C\n";
    }
};

class D: public C
{
public:
    D()
    {
        std::cout << "D\n";
    }
};

Rappelez-vous que C++ construit toujours en premier la classe « la première » ou « la plus basse ». Il parcourt ensuite l'arbre d'héritage dans l'ordre et construit chaque classe dérivée successive.

Voici un court programme qui illustre l'ordre de création tout au long de la chaîne d'héritage.

int main()
{
    std::cout << "Constructing A: \n";
    A a;

    std::cout << "Constructing B: \n";
    B b;

    std::cout << "Constructing C: \n";
    C c;

    std::cout << "Constructing D: \n";
    D d;
}

Ce code affiche :


Constructing A:
A
Constructing B:
A
B
Constructing C:
A
B
C
Constructing D:
A
B
C
D

Conclusion

C++ construit les classes dérivées en plusieurs phases, en commençant par la classe la plus basse (au sommet de l'arbre d'héritage) et en terminant par la classe la plus dérivée (au bas de l'arbre d'héritage). À mesure que chaque classe est construite, le constructeur approprié de cette classe est appelé pour initialiser cette partie de l'objet.

Vous remarquerez que les classes d'exemple de cette section utilisent toutes le constructeur par défaut des classes de base (par souci de simplicité). Dans la prochaine leçon, nous examinerons de plus près le rôle des constructeurs dans le processus de construction des classes dérivées (notamment la manière de choisir explicitement le constructeur de la classe de base que votre classe dérivée doit utiliser).
