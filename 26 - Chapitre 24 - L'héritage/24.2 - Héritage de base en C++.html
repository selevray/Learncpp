24.2 — Héritage de base en C++

Maintenant que nous avons vu ce qu'est l'héritage d'un point de vue abstrait, voyons comment il s'utilise en C++.

En C++, l'héritage se produit entre classes. Dans une relation d'héritage (relation « est un »), la classe dont on hérite est appelée classe parente, classe de base ou superclasse, et la classe qui hérite est appelée classe enfant, classe dérivée ou sous-classe.

Dans le diagramme ci-dessus, Fruit est le parent, et Apple et Banana sont tous deux des enfants.

Dans ce diagramme, Triangle est à la fois un enfant (de Shape) et un parent (de Right Triangle).

Une classe enfant hérite à la fois des comportements (fonctions membres) et des propriétés (variables membres) de son parent (sous réserve de certaines restrictions d'accès, que nous verrons dans une prochaine leçon). Ces variables et fonctions deviennent des membres de la classe dérivée.

Comme les classes enfants sont des classes à part entière, elles peuvent (bien sûr) avoir leurs propres membres, spécifiques à cette classe. Nous en verrons un exemple dans un instant.

Une classe Person

Voici une classe simple représentant une personne générique :

#include <string>
#include <string_view>

class Person
{
// Dans cet exemple, nous rendons nos membres publics par souci de simplicité
public:
    std::string m_name{};
    int m_age{};

    Person(std::string_view name = "", int age = 0)
        : m_name{ name }, m_age{ age }
    {
    }

    const std::string& getName() const { return m_name; }
    int getAge() const { return m_age; }

};

Comme cette classe Person est conçue pour représenter une personne générique, nous n'y avons défini que les membres communs à tout type de personne. Toute personne (quels que soient son sexe, sa profession, etc.) a un nom et un âge, c'est pourquoi ils sont représentés ici.

Notez que dans cet exemple, nous avons rendu toutes nos variables et fonctions publiques. Ce n'est que pour garder ces exemples simples pour l'instant. Normalement, nous rendrions les variables privées. Nous verrons plus tard dans ce chapitre les contrôles d'accès et leur interaction avec l'héritage.

Une classe BaseballPlayer

Supposons que nous voulions écrire un programme qui gère des informations sur des joueurs de baseball. Les joueurs de baseball ont besoin de données spécifiques à leur sport : par exemple, nous pourrions vouloir stocker la moyenne au bâton d'un joueur et le nombre de coups de circuit qu'il a réussis.

Voici notre classe BaseballPlayer incomplète :

class BaseballPlayer
{
// Dans cet exemple, nous rendons nos membres publics par souci de simplicité
public:
    double m_battingAverage{};
    int m_homeRuns{};

    BaseballPlayer(double battingAverage = 0.0, int homeRuns = 0)
       : m_battingAverage{battingAverage}, m_homeRuns{homeRuns}
    {
    }
};

Nous voulons maintenant aussi conserver le nom et l'âge d'un joueur de baseball, et ces informations existent déjà dans notre classe Person.

Nous avons trois possibilités pour ajouter le nom et l'âge à BaseballPlayer :

  1. Ajouter directement le nom et l'âge à la classe BaseballPlayer en tant que membres. C'est probablement le pire choix, car nous dupliquons du code qui existe déjà dans la classe Person. Toute modification de Person devrait alors être répercutée dans BaseballPlayer.
  2. Ajouter Person comme membre de BaseballPlayer par composition. Mais il faut se demander : « un BaseballPlayer possède-t-il un Person ? » Non. Ce n'est donc pas le bon paradigme.
  3. Faire hériter BaseballPlayer de ces attributs de Person. Rappelez-vous que l'héritage représente une relation « est un ». Un BaseballPlayer est-il une Person ? Oui. L'héritage est donc un bon choix ici.

Faire de BaseballPlayer une classe dérivée

Pour que BaseballPlayer hérite de notre classe Person, la syntaxe est assez simple. Après la déclaration class BaseballPlayer, on écrit deux-points, le mot « public », puis le nom de la classe dont on veut hériter. On parle d'héritage public. Nous reviendrons plus en détail sur la signification de l'héritage public dans une prochaine leçon.

// BaseballPlayer hérite publiquement de Person
class BaseballPlayer : public Person
{
public:
    double m_battingAverage{};
    int m_homeRuns{};

    BaseballPlayer(double battingAverage = 0.0, int homeRuns = 0)
       : m_battingAverage{battingAverage}, m_homeRuns{homeRuns}
    {
    }
};

Avec un diagramme de dérivation, notre héritage ressemble à ceci :

Lorsque BaseballPlayer hérite de Person, BaseballPlayer acquiert les fonctions membres et les variables membres de Person. De plus, BaseballPlayer définit deux membres qui lui sont propres : m_battingAverage et m_homeRuns. C'est logique, car ces propriétés sont propres à un BaseballPlayer, et non à n'importe quelle Person.

Ainsi, les objets BaseballPlayer auront 4 variables membres : m_battingAverage et m_homeRuns de BaseballPlayer, et m_name et m_age de Person.

C'est facile à vérifier :

#include <iostream>
#include <string>
#include <string_view>

class Person
{
public:
    std::string m_name{};
    int m_age{};

    Person(std::string_view name = "", int age = 0)
        : m_name{name}, m_age{age}
    {
    }

    const std::string& getName() const { return m_name; }
    int getAge() const { return m_age; }

};

// BaseballPlayer hérite publiquement de Person
class BaseballPlayer : public Person
{
public:
    double m_battingAverage{};
    int m_homeRuns{};

    BaseballPlayer(double battingAverage = 0.0, int homeRuns = 0)
       : m_battingAverage{battingAverage}, m_homeRuns{homeRuns}
    {
    }
};

int main()
{
    // Créer un nouvel objet BaseballPlayer
    BaseballPlayer joe{};
    // Lui attribuer un nom (on peut le faire directement car m_name est public)
    joe.m_name = "Joe";
    // Afficher le nom
    std::cout << joe.getName() << '\n'; // on utilise la fonction getName() acquise de la classe de base Person

    return 0;
}

Ce programme affiche la valeur :


Joe

Ce code compile et s'exécute parce que joe est un BaseballPlayer, et que tous les objets BaseballPlayer possèdent une variable membre m_name et une fonction membre getName() héritées de la classe Person.

Une classe dérivée Employee

Écrivons maintenant une autre classe qui hérite également de Person. Cette fois, nous allons écrire une classe Employee. Un employé « est une » personne, donc l'héritage est approprié :

// Employee hérite publiquement de Person
class Employee: public Person
{
public:
    double m_hourlySalary{};
    long m_employeeID{};

    Employee(double hourlySalary = 0.0, long employeeID = 0)
        : m_hourlySalary{hourlySalary}, m_employeeID{employeeID}
    {
    }

    void printNameAndSalary() const
    {
        std::cout << m_name << ": " << m_hourlySalary << '\n';
    }
};

Employee hérite de m_name et m_age de Person (ainsi que des deux fonctions d'accès), et ajoute deux variables membres et une fonction membre qui lui sont propres. Notez que printNameAndSalary() utilise des variables à la fois de la classe à laquelle il appartient (Employee::m_hourlySalary) et de la classe parente (Person::m_name).

On obtient ainsi un diagramme de dérivation de ce type :

Notez que Employee et BaseballPlayer n'ont aucun lien direct, bien qu'ils héritent tous deux de Person.

Voici un exemple complet utilisant Employee :

#include <iostream>
#include <string>
#include <string_view>

class Person
{
public:
    std::string m_name{};
    int m_age{};

    Person(std::string_view name = "", int age = 0)
        : m_name{name}, m_age{age}
    {
    }

    const std::string& getName() const { return m_name; }
    int getAge() const { return m_age; }

};

// Employee hérite publiquement de Person
class Employee: public Person
{
public:
    double m_hourlySalary{};
    long m_employeeID{};

    Employee(double hourlySalary = 0.0, long employeeID = 0)
        : m_hourlySalary{hourlySalary}, m_employeeID{employeeID}
    {
    }

    void printNameAndSalary() const
    {
        std::cout << m_name << ": " << m_hourlySalary << '\n';
    }
};

int main()
{
    Employee frank{20.25, 12345};
    frank.m_name = "Frank"; // on peut le faire car m_name est public

    frank.printNameAndSalary();

    return 0;
}

Ce programme affiche :


Frank: 20.25

Chaînes d'héritage

Il est possible d'hériter d'une classe qui dérive elle-même d'une autre classe. Il n'y a rien de particulier à cela : tout se déroule comme dans les exemples précédents.

Par exemple, écrivons une classe Supervisor. Un Supervisor est un Employee, lequel est une Person. Nous avons déjà écrit une classe Employee, utilisons-la comme classe de base pour dériver Supervisor :

class Supervisor: public Employee
{
public:
    // Ce Supervisor peut superviser au maximum 5 employés
    long m_overseesIDs[5]{};
};

Notre diagramme de dérivation ressemble maintenant à ceci :

Tous les objets Supervisor héritent des fonctions et variables d'Employee et de Person, et ajoutent leur propre variable membre m_overseesIDs.

En construisant de telles chaînes d'héritage, nous pouvons créer un ensemble de classes réutilisables, très générales en haut de la hiérarchie et de plus en plus spécifiques à mesure que l'on descend dans les niveaux d'héritage.

Pourquoi cette forme d'héritage est-elle utile ?

Hériter d'une classe de base signifie que nous n'avons pas à redéfinir dans nos classes dérivées les informations de la classe de base. Nous recevons automatiquement les fonctions membres et les variables membres de la classe de base par héritage, et nous ajoutons ensuite simplement les fonctions ou variables membres supplémentaires dont nous avons besoin. Cela ne fait pas seulement gagner du temps : si nous mettons un jour à jour ou modifions la classe de base (par exemple, en ajoutant de nouvelles fonctions ou en corrigeant un bogue), toutes nos classes dérivées hériteront automatiquement de ces changements !

Par exemple, si nous ajoutions une nouvelle fonction à Person, Employee, Supervisor et BaseballPlayer y auraient automatiquement accès. Si nous ajoutions une nouvelle variable à Employee, Supervisor y aurait également accès. Cela nous permet de construire de nouvelles classes de manière simple, intuitive et peu coûteuse en maintenance !

Conclusion

L'héritage permet de réutiliser des classes en faisant hériter d'autres classes de leurs membres. Dans les prochaines leçons, nous continuerons d'explorer son fonctionnement.
