14.3 — Les fonctions membres

Dans la leçon 13.7 -- Introduction aux structures, aux membres et à la sélection de membre, nous avons présenté le type défini par le programmeur struct, qui peut contenir des variables membres. Voici un exemple de structure servant à représenter une date :

struct Date
{
    int year {};
    int month {};
    int day {};
};

Si nous voulons afficher la date à l'écran (ce que nous ferons probablement souvent), il est logique d'écrire une fonction pour cela. Voici un programme complet :

#include <iostream>

struct Date
{
    // voici nos variables membres
    int year {};
    int month {};
    int day {};
};

void print(const Date& date)
{
    // variables membres accédées à l'aide de l'opérateur de sélection de membre (.)
    std::cout << date.year << '/' << date.month << '/' << date.day;
}

int main()
{
    Date today { 2020, 10, 14 }; // initialisation par agrégat de notre structure

    today.day = 16; // variables membres accédées à l'aide de l'opérateur de sélection de membre (.)
    print(today);   // fonction non membre appelée avec la convention d'appel habituelle

    return 0;
}

La séparation des propriétés et des actions

Regardez autour de vous : partout se trouvent des objets, des livres, des bâtiments, de la nourriture, et même vous. Les objets du monde réel ont deux composantes principales : 1) un certain nombre de propriétés observables (par exemple le poids, la couleur, la taille, la solidité, la forme, etc.), et 2) un certain nombre d'actions qu'ils peuvent accomplir ou subir (par exemple être ouvert, endommager autre chose, etc.), en fonction de ces propriétés. Ces propriétés et ces actions sont indissociables.

En programmation, nous représentons les propriétés par des variables et les actions par des fonctions.

Dans l'exemple Date ci-dessus, remarquez que nous avons défini séparément nos propriétés (les variables membres de Date) et les actions que nous effectuons à l'aide de ces propriétés (la fonction print()). Nous devons déduire le lien entre Date et print() uniquement à partir du paramètre const Date& de print().

Nous pourrions bien sûr placer Date et print() dans un espace de noms (pour indiquer plus clairement que les deux vont ensemble), mais cela ajouterait encore des noms à notre programme ainsi que des préfixes d'espace de noms, ce qui alourdirait le code.

Il serait bien pratique de pouvoir définir nos propriétés et nos actions ensemble, dans un seul bloc.

Les fonctions membres

En plus de posséder des variables membres, les types classe (ce qui inclut les structures, les classes et les unions) peuvent aussi avoir leurs propres fonctions ! Les fonctions qui appartiennent à un type classe sont appelées fonctions membres (member functions).

En passant…

Dans d'autres langages orientés objet (comme Java et C#), on parle de méthodes. Bien que le terme « méthode » ne soit pas utilisé en C++, les programmeurs ayant d'abord appris l'un de ces autres langages peuvent encore l'employer.

Les fonctions qui ne sont pas membres sont appelées fonctions non membres (non-member functions), ou parfois fonctions libres (free functions), afin de les distinguer des fonctions membres. La fonction print() ci-dessus est une fonction non membre.

Note de l'auteur

Dans cette leçon, nous utiliserons des structures pour montrer des exemples de fonctions membres, mais tout ce que nous présentons ici s'applique tout aussi bien aux classes. Pour des raisons qui deviendront évidentes lorsque nous y arriverons, nous montrerons des exemples de classes avec fonctions membres dans une prochaine leçon (14.5 -- Membres publics et privés et spécificateurs d'accès).

Les fonctions membres doivent être déclarées à l'intérieur de la définition du type classe, et elles peuvent être définies à l'intérieur ou à l'extérieur de cette définition. Pour rappel, une définition est aussi une déclaration : si nous définissons une fonction membre à l'intérieur de la classe, cela vaut donc déclaration.

Pour rester simple, nous définirons nos fonctions membres à l'intérieur de la définition du type classe pour le moment.

Contenu connexe

Nous montrons comment définir des fonctions membres à l'extérieur de la définition du type classe dans la leçon 15.2 -- Classes et fichiers d'en-tête.

Un exemple de fonction membre

Réécrivons l'exemple Date du début de la leçon en transformant print() d'une fonction non membre en fonction membre :

// Version avec fonction membre
#include <iostream>

struct Date
{
    int year {};
    int month {};
    int day {};

    void print() // définit une fonction membre nommée print
    {
        std::cout << year << '/' << month << '/' << day;
    }
};

int main()
{
    Date today { 2020, 10, 14 }; // initialisation par agrégat de notre structure

    today.day = 16; // variables membres accédées à l'aide de l'opérateur de sélection de membre (.)
    today.print();  // fonctions membres également accédées à l'aide de l'opérateur de sélection de membre (.)

    return 0;
}

Il y a trois différences essentielles entre les exemples avec fonction non membre et avec fonction membre :

  1. L'endroit où nous déclarons (et définissons) la fonction print()
  2. La manière dont nous appelons la fonction print()
  3. La manière dont nous accédons aux membres à l'intérieur de la fonction print()

Examinons chacune de ces différences.

Les fonctions membres sont déclarées dans la définition du type classe

Dans l'exemple avec fonction non membre, la fonction non membre print() est définie en dehors de la structure Date, dans l'espace de noms global. Par défaut, elle a une liaison externe (external linkage) : elle peut donc être appelée depuis d'autres fichiers source, moyennant une déclaration anticipée appropriée.

Dans l'exemple avec fonction membre, la fonction membre print() est déclarée (et, dans ce cas, définie) à l'intérieur de la définition de la structure Date. Comme print() est déclarée dans le cadre de Date, cela indique au compilateur que print() est une fonction membre.

Les fonctions membres définies à l'intérieur de la définition du type classe sont implicitement inline. Elles ne provoquent donc pas de violation de la règle de la définition unique (one-definition rule) si la définition du type classe est incluse dans plusieurs fichiers de code.

Contenu connexe

Les fonctions membres peuvent aussi être déclarées (de manière anticipée) à l'intérieur de la définition de la classe, et définies après celle-ci. Nous traitons ce point dans la leçon 15.2 -- Classes et fichiers d'en-tête.

Appeler des fonctions membres (et l'objet implicite)

Dans l'exemple avec fonction non membre, nous appelons print(today), où today est passé (explicitement) en argument.

Dans l'exemple avec fonction membre, nous appelons today.print(). Cette syntaxe, qui utilise l'opérateur de sélection de membre (.) pour désigner la fonction membre à appeler, est cohérente avec la manière dont nous accédons aux variables membres (par exemple today.day = 16;).

Toutes les fonctions membres (non statiques) doivent être appelées à l'aide d'un objet de ce type classe. Ici, today est l'objet sur lequel print() est appelée.

Remarquez que, dans le cas de la fonction membre, nous n'avons pas besoin de passer today en argument. L'objet sur lequel une fonction membre est appelée est implicitement transmis à cette fonction membre. C'est pourquoi l'objet sur lequel une fonction membre est appelée est souvent appelé l'objet implicite (implicit object).

Autrement dit, lorsque nous écrivons today.print(), today est l'objet implicite, et il est transmis implicitement à la fonction membre print().

Contenu connexe

Nous expliquons en détail comment l'objet associé est effectivement transmis à une fonction membre dans la leçon 15.1 -- Le pointeur caché « this » et le chaînage des appels de fonctions membres.

Accéder aux membres dans une fonction membre utilise l'objet implicite

Voici à nouveau la version non membre de print() :

// version non membre de print
void print(const Date& date)
{
    // variables membres accédées à l'aide de l'opérateur de sélection de membre (.)
    std::cout << date.year << '/' << date.month << '/' << date.day;
}

Cette version de print() possède le paramètre par référence const Date& date. Dans la fonction, nous accédons aux membres à travers ce paramètre référence, sous la forme date.year, date.month et date.day. Lorsque print(today) est appelée, le paramètre référence date est lié à l'argument today, et date.year, date.month et date.day correspondent respectivement à today.year, today.month et today.day.

Regardons maintenant à nouveau la définition de la fonction membre print() :

    void print() // définit une fonction membre nommée print()
    {
        std::cout << year << '/' << month << '/' << day;
    }

Dans l'exemple avec fonction membre, nous accédons aux membres sous la forme year, month et day.

À l'intérieur d'une fonction membre, tout identifiant de membre qui n'est pas précédé de l'opérateur de sélection de membre (.) est associé à l'objet implicite.

Autrement dit, lorsque today.print() est appelée, today est notre objet implicite, et year, month et day (non précédés) correspondent respectivement aux valeurs de today.year, today.month et today.day.

Point clé

Avec les fonctions non membres, nous devons passer explicitement un objet à la fonction pour qu'elle travaille dessus, et les membres sont accédés explicitement à travers cet objet.

Avec les fonctions membres, nous passons implicitement un objet à la fonction pour qu'elle travaille dessus, et les membres sont accédés implicitement à travers cet objet.

Un autre exemple de fonction membre

Voici un exemple avec une fonction membre un peu plus complexe :

#include <iostream>
#include <string>

struct Person
{
    std::string name{};
    int age{};

    void kisses(const Person& person)
    {
        std::cout << name << " kisses " << person.name << '\n';
    }
};

int main()
{
    Person joe{ "Joe", 29 };
    Person kate{ "Kate", 27 };

    joe.kisses(kate);

    return 0;
}

Ce programme produit la sortie suivante :


Joe kisses Kate

Examinons le fonctionnement. Tout d'abord, nous définissons deux structures Person, joe et kate. Ensuite, nous appelons joe.kisses(kate). Ici, joe est l'objet implicite, et kate est passé en argument explicite.

Lorsque la fonction membre kisses() s'exécute, l'identifiant name n'utilise pas l'opérateur de sélection de membre (.) ; il désigne donc l'objet implicite, c'est-à-dire joe. Il correspond donc à joe.name. person.name utilise l'opérateur de sélection de membre, il ne désigne donc pas l'objet implicite. Comme person est une référence à kate, cela correspond à kate.name.

Point clé

Sans fonction membre, nous aurions écrit kisses(joe, kate). Avec une fonction membre, nous écrivons joe.kisses(kate). Remarquez à quel point la seconde écriture est plus lisible, et comment elle indique clairement quel objet initie l'action et lequel la soutient.

Les variables membres et les fonctions membres peuvent être définies dans n'importe quel ordre

Le compilateur C++ traite normalement le code de haut en bas. Pour chaque nom rencontré, le compilateur détermine s'il a déjà vu une déclaration de ce nom, afin de pouvoir effectuer une vérification correcte des types.

Les entités non membres doivent être déclarées avant d'être utilisées, sans quoi le compilateur émettra une erreur :

int x()
{
    return y(); // erreur : y n'est pas encore déclarée, le compilateur ne sait donc pas ce que c'est
}

int y()
{
    return 5;
}

Pour contourner ce problème, nous définissons habituellement nos entités non membres dans un ordre proche de leur utilisation (ce qui demande un effort chaque fois que cet ordre doit changer), ou nous utilisons des déclarations anticipées (ce qui demande un effort pour les ajouter).

En revanche, à l'intérieur de la définition d'une classe, cette restriction ne s'applique pas : vous pouvez accéder aux variables membres et aux fonctions membres avant leur déclaration. Cela signifie que vous pouvez définir les variables membres et les fonctions membres dans l'ordre que vous souhaitez !

Par exemple :

struct Foo
{
    int z() { return m_data; } // Nous pouvons accéder aux membres de données avant leur définition
    int x() { return y(); }    // Nous pouvons accéder aux fonctions membres avant leur définition

    int m_data { y() };        // Cela fonctionne même dans les initialisateurs de membres par défaut (voir l'avertissement ci-dessous)
    int y() { return 5; }
};

Nous abordons un ordre recommandé pour la définition des membres dans la prochaine leçon 14.8 -- Les avantages de la dissimulation des données (encapsulation).

Avertissement

Les membres de données sont initialisés dans l'ordre de leur déclaration. Si l'initialisation d'un membre de données accède à un autre membre de données qui n'est déclaré que plus loin (et qui n'a donc pas encore été initialisé), cette initialisation provoque un comportement indéfini.

struct Bad
{
    int m_bad1 { m_data }; // comportement indéfini : m_bad1 est initialisé avant m_data
    int m_bad2 { fcn() };  // comportement indéfini : m_bad2 est initialisé avant m_data (accédé via fcn())

    int m_data { 5 };
    int fcn() { return m_data; }
};

Pour cette raison, il est généralement judicieux d'éviter d'utiliser d'autres membres dans les initialisateurs de membres par défaut.

Pour les lecteurs avancés

Pour permettre de définir les membres de données et les fonctions membres dans n'importe quel ordre, les compilateurs utilisent une astuce ingénieuse. Lorsque le compilateur rencontre une fonction membre définie à l'intérieur de la définition de la classe :

  • La fonction membre est implicitement déclarée à l'avance.
  • La définition de la fonction membre est déplacée immédiatement après la fin de la définition de la classe.

Ainsi, au moment où le compilateur compile réellement les définitions des fonctions membres, il a déjà vu la définition complète de la classe (contenant les déclarations de tous les membres !)

Par exemple, lorsque le compilateur rencontre ceci :

struct Foo
{
    int z() { return m_data; } // m_data n'est pas encore déclarée
    int x() { return y(); }    // y n'est pas encore déclarée
    int y() { return 5; }

    int m_data{};
};

Il compile l'équivalent de ceci :

struct Foo
{
    int z(); // déclaration anticipée de Foo::z()
    int x(); // déclaration anticipée de Foo::x()
    int y(); // déclaration anticipée de Foo::y()

    int m_data{};
};

int Foo::z() { return m_data; } // m_data déjà déclarée ci-dessus
int Foo::x() { return y(); }    // y déjà déclarée ci-dessus
int Foo::y() { return 5; }

Les fonctions membres peuvent être surchargées

Tout comme les fonctions non membres, les fonctions membres peuvent être surchargées, à condition que chacune d'elles puisse être distinguée des autres.

Contenu connexe

Nous traitons de la distinction entre fonctions surchargées dans la leçon 11.2 -- Distinction entre fonctions surchargées.

Voici un exemple de structure Date avec des fonctions membres print() surchargées :

#include <iostream>
#include <string_view>

struct Date
{
    int year {};
    int month {};
    int day {};

    void print()
    {
        std::cout << year << '/' << month << '/' << day;
    }

    void print(std::string_view prefix)
    {
        std::cout << prefix << year << '/' << month << '/' << day;
    }
};

int main()
{
    Date today { 2020, 10, 14 };

    today.print(); // appelle Date::print()
    std::cout << '\n';

    today.print("The date is: "); // appelle Date::print(std::string_view)
    std::cout << '\n';

    return 0;
}

Ce programme affiche :


2020/10/14
The date is: 2020/10/14

Les structures et les fonctions membres

En C, les structures ne contiennent que des membres de données, et non des fonctions membres.

En C++, lors de la conception des classes, Bjarne Stroustrup a longuement réfléchi à la question de savoir si les structures (héritées du C) devaient pouvoir posséder des fonctions membres. Après réflexion, il a conclu qu'elles le devaient.

En passant…

Cette décision a entraîné une série d'autres questions sur les autres nouvelles capacités du C++ auxquelles les structures devaient avoir accès. Bjarne craignait qu'accorder aux structures seulement un sous-ensemble limité de capacités n'ajoute de la complexité et des cas particuliers au langage. Par souci de simplicité, il a finalement décidé que les structures et les classes suivraient un ensemble de règles unifié (ce qui signifie qu'une structure peut faire tout ce qu'une classe peut faire, et inversement), la convention dictant alors la manière dont les structures seraient réellement utilisées.

En C++ moderne, il est tout à fait acceptable que les structures possèdent des fonctions membres. Cela exclut les constructeurs, qui sont un type particulier de fonctions membres que nous présentons dans la prochaine leçon 14.9 -- Introduction aux constructeurs. Un type classe disposant d'un constructeur n'est plus un agrégat, et nous voulons que nos structures restent des agrégats.

Bonne pratique

Les fonctions membres peuvent être utilisées aussi bien avec les structures qu'avec les classes.

Cependant, les structures doivent éviter de définir des fonctions membres constructeurs, car cela en ferait des non-agrégats.

Types classe sans membres de données

Il est possible de créer des types classe sans membres de données (par exemple des types classe qui ne possèdent que des fonctions membres). Il est également possible d'instancier des objets de ce type classe :

#include <iostream>

struct Foo
{
    void printHi() { std::cout << "Hi!\n"; }
};

int main()
{
    Foo f{};
    f.printHi(); // nécessite un objet pour être appelée

    return 0;
}

Cependant, si un type classe ne possède aucun membre de données, utiliser un type classe est probablement excessif. Dans ce cas, envisagez plutôt un espace de noms (contenant des fonctions non membres). Cela indique plus clairement au lecteur qu'aucune donnée n'est gérée, et il n'est pas nécessaire d'instancier un objet pour appeler les fonctions.

#include <iostream>

namespace Foo
{
    void printHi() { std::cout << "Hi!\n"; }
};

int main()
{
    Foo::printHi(); // aucun objet nécessaire

    return 0;
}

Bonne pratique

Si votre type classe ne possède aucun membre de données, préférez utiliser un espace de noms.

Question n° 2

Ajoutez à IntPair une nouvelle fonction membre nommée isEqual qui renvoie un booléen indiquant si un IntPair est égal à un autre.

Le programme suivant doit pouvoir se compiler :

#include <iostream>

// Donnez ici la définition de IntPair et des fonctions membres

int main()
{
    IntPair p1 {1, 2};
    IntPair p2 {3, 4};

    std::cout << "p1: ";
    p1.print();

    std::cout << "p2: ";
    p2.print();

    std::cout << "p1 and p1 " << (p1.isEqual(p1) ? "are equal\n" : "are not equal\n");
    std::cout << "p1 and p2 " << (p1.isEqual(p2) ? "are equal\n" : "are not equal\n");

    return 0;
}

et produire la sortie :


p1: Pair(1, 2)
p2: Pair(3, 4)
p1 and p1 are equal
p1 and p2 are not equal
Solution 
#include <iostream>

struct IntPair
{
    int first{};
    int second{};

    void print()
    {
        std::cout << "Pair(" << first << ", " << second << ")\n";
    }

    bool isEqual(IntPair a)
    {
        return (first == a.first) && (second == a.second);
    }
};

int main()
{
    IntPair p1 {1, 2};
    IntPair p2 {3, 4};

    std::cout << "p1: ";
    p1.print();

    std::cout << "p2: ";
    p2.print();

    std::cout << "p1 and p1 " << (p1.isEqual(p1) ? "are equal\n" : "are not equal\n");
    std::cout << "p1 and p2 " << (p1.isEqual(p2) ? "are equal\n" : "are not equal\n");

    return 0;
}
