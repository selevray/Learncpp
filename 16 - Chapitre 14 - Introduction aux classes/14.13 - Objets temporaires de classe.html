14.13 — Objets temporaires de classe

Considérons l'exemple suivant :

#include <iostream>

int add(int x, int y)
{
    int sum{ x + y }; // stores x + y in a variable
    return sum;       // returns value of that variable
}

int main()
{
    std::cout << add(5, 3) << '\n';

    return 0;
}

Dans la fonction add(), la variable sum sert à stocker le résultat de l'expression x + y. Cette variable est ensuite évaluée dans l'instruction return pour produire la valeur renvoyée. Bien que cela puisse parfois être utile pour le débogage (afin de pouvoir inspecter la valeur de sum si besoin), cela rend en réalité la fonction plus complexe qu'il ne le faut, en définissant un objet qui n'est utilisé qu'une seule fois.

Dans la plupart des cas où une variable n'est utilisée qu'une seule fois, nous n'avons pas réellement besoin de variable. Nous pouvons à la place remplacer la variable par l'expression qui servait à l'initialiser, à l'endroit où elle aurait été utilisée. Voici la fonction add() réécrite de cette manière :

#include <iostream>

int add(int x, int y)
{
    return x + y; // just return x + y directly
}

int main()
{
    std::cout << add(5, 3) << '\n';

    return 0;
}

Cela fonctionne non seulement pour les valeurs de retour, mais aussi pour la plupart des arguments de fonction. Par exemple, au lieu de ceci :

#include <iostream>

void printValue(int value)
{
    std::cout << value;
}

int main()
{
    int sum{ 5 + 3 };
    printValue(sum);

    return 0;
}

Nous pouvons écrire ceci :

#include <iostream>

void printValue(int value)
{
    std::cout << value;
}

int main()
{
    printValue(5 + 3);

    return 0;
}

Remarquez à quel point cela rend notre code plus clair. Nous n'avons pas à définir et nommer une variable. Et nous n'avons pas à parcourir toute la fonction pour déterminer si cette variable est utilisée ailleurs. Comme 5 + 3 est une expression, nous savons qu'elle n'est utilisée que sur cette ligne.

Notez que cela ne fonctionne que dans les cas où une expression de type rvalue est acceptée. Lorsqu'une expression de type lvalue est requise, nous devons disposer d'un objet :

#include <iostream>

void addOne(int& value) // pass by non-const references requires lvalue
{
    ++value;
}

int main()
{
    int sum { 5 + 3 };
    addOne(sum);   // okay, sum is an lvalue

    addOne(5 + 3); // compile error: not an lvalue

    return 0;
}

Objets temporaires de classe

Le même problème se pose dans le contexte des types classe.

Note de l'auteur

Nous utiliserons ici une classe, mais tout ce qui est dit dans cette leçon à propos de l'initialisation par liste s'applique également aux structures initialisées par initialisation d'agrégat.

L'exemple suivant est similaire aux précédents, mais utilise le type de classe défini par le programme IntPair à la place de int :

#include <iostream>

class IntPair
{
private:
    int m_x{};
    int m_y{};

public:
    IntPair(int x, int y)
        : m_x { x }, m_y { y }
    {}

    int x() const { return m_x; }
    int y() const { return m_y; }
};

void print(IntPair p)
{
    std::cout << "(" << p.x() << ", " << p.y() << ")\n";
}

int main()
{
    // Case 1: Pass variable
    IntPair p { 3, 4 };
    print(p); // prints (3, 4)

    return 0;
}

Dans le cas 1, nous instancions la variable IntPair p puis nous passons p à la fonction print().

Cependant, p n'est utilisée qu'une seule fois, et la fonction print() accepte des rvalues, donc il n'y a aucune raison réelle de définir une variable ici. Supprimons donc p.

Nous pouvons le faire en passant un objet temporaire au lieu d'une variable nommée. Un objet temporaire (parfois appelé objet anonyme ou objet sans nom) est un objet qui n'a pas de nom et qui n'existe que le temps d'une seule expression.

Il existe deux façons courantes de créer des objets temporaires de type classe :

#include <iostream>

class IntPair
{
private:
    int m_x{};
    int m_y{};

public:
    IntPair(int x, int y)
        : m_x { x }, m_y { y }
    {}

    int x() const { return m_x; }
    int y() const{ return m_y; }
};

void print(IntPair p)
{
    std::cout << "(" << p.x() << ", " << p.y() << ")\n";
}

int main()
{
    // Case 1: Pass variable
    IntPair p { 3, 4 };
    print(p);

    // Case 2: Construct temporary IntPair and pass to function
    print(IntPair { 5, 6 } );

    // Case 3: Implicitly convert { 7, 8 } to a temporary Intpair and pass to function
    print( { 7, 8 } );

    return 0;
}

Dans le cas 2, nous demandons au compilateur de construire un objet IntPair, en l'initialisant avec { 5, 6 }. Comme cet objet n'a pas de nom, c'est un temporaire. L'objet temporaire est ensuite passé au paramètre p de la fonction print(). Lorsque l'appel de fonction se termine, l'objet temporaire est détruit.

Dans le cas 3, nous créons également un objet temporaire IntPair à passer à la fonction print(). Cependant, comme nous n'avons pas explicitement indiqué le type à construire, le compilateur déduit le type nécessaire (IntPair) à partir du paramètre de la fonction, puis convertit implicitement { 7, 8 } en objet IntPair.

En résumé :

IntPair p { 1, 2 }; // create named object p initialized with { 1, 2 }
IntPair { 1, 2 };   // create temporary object initialized with { 1, 2 }
{ 1, 2 };           // compiler will try to convert { 1, 2 } to temporary object matching expected type (typically a parameter or return type)

Nous reviendrons plus en détail sur ce dernier cas dans la leçon 14.16 -- Constructeurs de conversion et le mot-clé explicit.

Quelques exemples supplémentaires :

std::string { "Hello" }; // create a temporary std::string initialized with "Hello"
std::string {};          // create a temporary std::string using value initialization / default constructor

Création d'objets temporaires par initialisation directe (facultatif)

Puisque nous pouvons créer des objets temporaires par initialisation directe par liste, vous vous demandez peut-être s'il est possible de créer des objets temporaires avec les autres formes d'initialisation. Il n'existe aucune syntaxe permettant de créer des objets temporaires par initialisation par copie.

En revanche, vous pouvez créer des objets temporaires par initialisation directe. Par exemple :

Foo (1, 2); //  temporary Foo, direct-initialized with (1, 2) (similar to `Foo { 1, 2 }`)

Mis à part le fait qu'à première vue cela ressemble à un appel de fonction, cela produit le même résultat que Foo { 1, 2 } (simplement sans la prévention des conversions restrictives). Assez normal, non ?

Nous allons maintenant consacrer le reste de cette section à vous expliquer pourquoi vous ne devriez probablement pas faire cela.

Note de l'auteur

Cette partie est surtout là pour votre plaisir de lecture, pas comme un élément que vous devez assimiler, mémoriser et savoir expliquer.

Même si vous ne vous amusez pas beaucoup à la lire, elle peut vous aider à comprendre pourquoi l'initialisation par liste est privilégiée en C++ moderne !

Regardons maintenant le cas où nous n'avons aucun argument :

Foo();     // temporary Foo, value-initialized (identical to `Foo {}`)

Vous ne vous attendiez probablement pas à ce que Foo() crée un temporaire initialisé par valeur, comme le fait Foo {}. Et c'est sans doute parce que cette syntaxe a un sens totalement différent lorsqu'elle est utilisée avec une variable nommée !

Foo bar{}; // definition of variable bar, value-initialized
Foo bar(); // declaration of function bar that has no parameters and returns a Foo (inconsistent with `Foo bar{}` and `Foo()`)

Prêt pour quelque chose de vraiment bizarre ?

Foo(1);    // Function-style cast of literal 1, returns temporary Foo (similar to `Foo { 1 }`)
Foo(bar);  // Defines variable bar of type Foo (inconsistent with `Foo { bar }` and `Foo(1)`)

Comment ça ?

  • La version avec le littéral 1 entre parenthèses se comporte de manière cohérente avec toutes les autres versions de cette syntaxe qui créent des objets temporaires.
  • La version avec l'identificateur bar entre parenthèses définit une variable nommée bar (identique à Foo bar;). Si bar est déjà défini, cela provoquera une erreur de compilation due à une redéfinition.

Le compilateur sait que les littéraux ne peuvent pas être utilisés comme identificateurs de variables, il peut donc traiter ce cas de façon cohérente avec les autres.

En passant…

Si vous vous demandez pourquoi Foo(bar); se comporte exactement comme Foo bar;…

L'un des usages les plus courants des parenthèses est de regrouper des éléments. Par exemple, en mathématiques : (1 + 2) * 3 donne le résultat 9, qui est différent de 1 + 2 * 3, qui donne 7. Si nous pouvons écrire (1 + 2) * 3, rien ne nous empêche d'écrire (3) * 3.

Pour des raisons similaires, la syntaxe des déclarations autorise le regroupement par parenthèses, et ces groupes peuvent ne contenir qu'un seul élément. Foo(bar) est interprété comme la définition d'une variable de type Foo, suivie d'un groupe qui ne contient que l'identificateur bar. Cela nous paraît simplement étrange, principalement parce que les parenthèses n'ont dans ce cas aucune utilité. Mais il n'existe pas de raison impérieuse d'interdire cette écriture (cela ne ferait que compliquer davantage la syntaxe du langage).

Pour les lecteurs avancés

Examinons un cas un peu plus compliqué. Considérons l'instruction Foo * bar();. En utilisant (ou non) des parenthèses, nous pouvons complètement changer le sens de cette instruction :

  • Foo * bar(); (sans parenthèses supplémentaires) regroupe par défaut le * avec Foo. Foo* bar(); est la déclaration d'une fonction nommée bar qui ne prend aucun paramètre et renvoie un Foo*.
  • Foo (*bar)(); regroupe explicitement le * avec bar. Cela définit un pointeur de fonction nommé bar qui contient l'adresse d'une fonction ne prenant aucun paramètre et renvoyant un Foo.
  • Foo (* bar()); est équivalent à Foo * bar(); -- les parenthèses sont superflues dans ce cas.

Enfin :

  • (Foo *) bar();. Vous pourriez penser que cela équivaut à Foo* bar(), mais il s'agit en réalité d'une instruction d'expression qui appelle la fonction bar(), convertit la valeur de retour en type Foo* à l'aide d'un cast de style C, puis la jette !

Le C++ est parfois vraiment étrange.

Point clé

Les parenthèses sont complexes parce qu'elles sont tellement surchargées et utilisées dans la syntaxe de choses très différentes. Cela inclut les appels de fonction, l'initialisation directe d'objets, l'initialisation par valeur de temporaires, les casts de style C, les regroupements de symboles ou d'identificateurs, et les définitions de variables. Ainsi, lorsque vous voyez des parenthèses dans une syntaxe… ce que vous obtiendrez n'est pas toujours évident !

En revanche, lorsque nous voyons des accolades, nous savons que nous manipulons des objets.

Bon, la récréation est terminée. Retour aux choses sérieuses.

Objets temporaires et retour par valeur

Lorsqu'une fonction renvoie par valeur, l'objet renvoyé est un objet temporaire (initialisé à partir de la valeur ou de l'objet identifié dans l'instruction return).

Voici quelques exemples :

#include <iostream>

class IntPair
{
private:
    int m_x{};
    int m_y{};

public:
    IntPair(int x, int y)
        : m_x { x }, m_y { y }
    {}

    int x() const { return m_x; }
    int y() const { return m_y; }
};

void print(IntPair p)
{
    std::cout << "(" << p.x() << ", " << p.y() << ")\n";
}

// Case 1: Create named variable and return
IntPair ret1()
{
    IntPair p { 3, 4 };
    return p; // returns temporary object (initialized using p)
}

// Case 2: Create temporary IntPair and return
IntPair ret2()
{
    return IntPair { 5, 6 }; // returns temporary object (initialized using another temporary object)
}

// Case 3: implicitly convert { 7, 8 } to IntPair and return
IntPair ret3()
{
    return { 7, 8 }; // returns temporary object (initialized using another temporary object)
}

int main()
{
    print(ret1());
    print(ret2());
    print(ret3());

    return 0;
}

Dans le cas 1, lorsque nous écrivons return p, un objet temporaire est créé et initialisé à partir de p.

Les cas de cet exemple sont analogues à ceux de l'exemple précédent.

Quelques remarques

Tout d'abord, comme dans le cas d'un int, un objet temporaire de classe utilisé dans une expression est une rvalue. Ainsi, de tels objets ne peuvent être utilisés que là où des expressions de type rvalue sont acceptées.

Ensuite, les objets temporaires sont créés au point de leur définition et détruits à la fin de l'expression complète dans laquelle ils sont définis. Une expression complète est une expression qui n'est pas une sous-expression.

static_cast ou instanciation explicite d'un objet temporaire

Lorsque nous devons convertir une valeur d'un type vers un autre sans qu'interviennent de conversions restrictives, nous avons souvent le choix entre static_cast et l'instanciation explicite d'un objet temporaire.

Par exemple :

#include <iostream>

int main()
{
    char c { 'a' };

    std::cout << static_cast<int>( c ) << '\n'; // static_cast returns a temporary int direct-initialized with value of c
    std::cout << int { c } << '\n';             // explicitly creates a temporary int list-initialized with value c

    return 0;
}

static_cast<int>(c) renvoie un int temporaire initialisé directement avec la valeur de c. int { c } crée un int temporaire initialisé par liste avec la valeur de c. Dans les deux cas, nous obtenons un int temporaire initialisé avec la valeur de c, ce qui est bien ce que nous voulons.

Voyons un exemple légèrement plus complexe :

printString.h :

#include <string>
void printString(const std::string &s)
{
    std::cout << s << '\n';
}

main.cpp :

#include "printString.h"
#include <iostream>
#include <string>
#include <string_view>

int main()
{
    std::string_view sv { "Hello" };

    // We want to print sv using the printString() function

//    printString(sv); // compile error: a std::string_view won't implicitly convert to a std::string

    printString( static_cast<std::string>(sv) ); // Case 1: static_cast returns a temporary std::string direct-initialized with sv
    printString( std::string { sv } );           // Case 2: explicitly creates a temporary std::string list-initialized with sv
    printString( std::string ( sv ) );           // Case 3: C-style cast returns temporary std::string direct-initialized with sv (avoid this one!)

    return 0;
}

Supposons que le code du fichier d'en-tête printString.h ne soit pas un code que nous pouvons modifier (par exemple parce qu'il est distribué avec une bibliothèque tierce que nous utilisons, et qu'il a été écrit pour être compatible avec C++11, qui ne prend pas en charge std::string_view). Comment appeler alors printString() avec sv ? Comme un std::string_view ne se convertit pas implicitement en std::string (pour des raisons d'efficacité), nous ne pouvons pas simplement utiliser sv comme argument. Nous devons employer une forme de conversion explicite.

Dans le cas 1, static_cast<std::string>(sv) invoque l'opérateur de conversion static_cast pour convertir sv en std::string. Cela renvoie un std::string temporaire initialisé directement à partir de sv, qui est ensuite utilisé comme argument de l'appel de fonction.

Dans le cas 2, std::string { sv } crée un std::string temporaire initialisé par liste à partir de sv. Comme il s'agit d'une construction explicite, la conversion est autorisée. Ce temporaire est ensuite utilisé comme argument de l'appel de fonction.

Dans le cas 3, std::string ( sv ) utilise un cast de style C pour convertir sv en std::string. Bien que cela fonctionne ici, les casts de style C peuvent être dangereux en général et doivent être évités. Remarquez à quel point cela ressemble au cas précédent !

Bonne pratique

Pour faire simple : préférez static_cast lorsque vous convertissez vers un type fondamental, et un temporaire initialisé par liste lorsque vous convertissez vers un type classe.

Préférez static_cast pour créer un objet temporaire lorsque l'une au moins des conditions suivantes est vraie :

  • Nous devons effectuer une conversion restrictive.
  • Nous voulons rendre évident que nous convertissons vers un type qui produira un comportement différent (par exemple un char vers un int).
  • Nous voulons utiliser l'initialisation directe pour une raison quelconque (par exemple pour éviter que des constructeurs de liste ne soient prioritaires).

Préférez créer un nouvel objet (par initialisation par liste) plutôt qu'un objet temporaire lorsque l'une au moins des conditions suivantes est vraie :

  • Nous voulons utiliser l'initialisation par liste (par exemple pour la protection contre les conversions restrictives, ou parce que nous devons invoquer un constructeur de liste).
  • Nous devons fournir des arguments supplémentaires à un constructeur pour faciliter la conversion.
