14.16 — Constructeurs de conversion et le mot-clé explicit

Dans la leçon 10.1 -- Conversion de type implicite, nous avons présenté la conversion de type et le concept de conversion de type implicite, où le compilateur convertit implicitement une valeur d'un type en une valeur d'un autre type lorsque c'est nécessaire et qu'une telle conversion existe.

Cela nous permet d'écrire des choses comme ceci :

#include <iostream>

void printDouble(double d) // possède un paramètre de type double
{
    std::cout << d;
}

int main()
{
    printDouble(5); // nous fournissons un argument de type int

    return 0;
}

Dans l'exemple ci-dessus, notre fonction printDouble possède un paramètre de type double, mais nous lui passons un argument de type int. Comme les types du paramètre et de l'argument ne correspondent pas, le compilateur vérifie s'il peut convertir implicitement le type de l'argument en type du paramètre. Ici, grâce aux règles de conversion numérique, la valeur entière 5 est convertie en valeur double 5.0, et comme nous passons par valeur, le paramètre d est initialisé par copie avec cette valeur.

Conversions définies par l'utilisateur

Considérons maintenant l'exemple similaire suivant :

#include <iostream>

class Foo
{
private:
    int m_x{};
public:
    Foo(int x)
        : m_x{ x }
    {
    }

    int getX() const { return m_x; }
};

void printFoo(Foo f) // possède un paramètre de type Foo
{
    std::cout << f.getX();
}

int main()
{
    printFoo(5); // nous fournissons un argument de type int

    return 0;
}

Dans cette version, printFoo possède un paramètre de type Foo, mais nous lui passons un argument de type int. Comme ces types ne correspondent pas, le compilateur tente de convertir implicitement la valeur entière 5 en objet Foo afin de pouvoir appeler la fonction.

Contrairement au premier exemple, où le paramètre et l'argument étaient tous deux de types fondamentaux (et pouvaient donc être convertis à l'aide des règles de promotion et de conversion numériques intégrées), ici l'un des types est défini par le programme. La norme C++ ne contient pas de règles spécifiques indiquant au compilateur comment convertir des valeurs vers (ou depuis) un type défini par le programme.

À la place, le compilateur cherche si nous avons défini une fonction qu'il peut utiliser pour effectuer cette conversion. Une telle fonction est appelée conversion définie par l'utilisateur (user-defined conversion).

Constructeurs de conversion

Dans l'exemple ci-dessus, le compilateur trouve une fonction lui permettant de convertir la valeur 5 de type int en objet Foo. Cette fonction est le constructeur Foo(int).

Jusqu'à présent, nous avons généralement utilisé les constructeurs pour construire explicitement des objets :

    Foo x { 5 }; // convertit explicitement la valeur int 5 en Foo

Réfléchissez à ce que cela fait : nous fournissons une valeur de type int (5) et nous obtenons en retour un objet Foo.

Dans le contexte d'un appel de fonction, nous cherchons à résoudre le même problème :

    printFoo(5); // convertit implicitement la valeur int 5 en Foo

Nous fournissons une valeur int (5) et nous voulons un objet Foo en retour. Le constructeur Foo(int) a été conçu exactement pour cela !

Ainsi, lorsque printFoo(5) est appelée, le paramètre f est initialisé par copie à l'aide du constructeur Foo(int) avec 5 comme argument !

En passant…

Avant C++17, lorsque printFoo(5) est appelée, 5 est implicitement converti en un Foo temporaire à l'aide du constructeur Foo(int). Ce Foo temporaire est ensuite copié par construction dans le paramètre f.

À partir de C++17, la copie est obligatoirement élidée. Le paramètre f est initialisé par copie avec la valeur 5, et aucun appel au constructeur de copie n'est nécessaire (cela fonctionne même si le constructeur de copie est supprimé).

Un constructeur pouvant être utilisé pour effectuer une conversion implicite est appelé constructeur de conversion (converting constructor). Par défaut, tous les constructeurs sont des constructeurs de conversion.

Une seule conversion définie par l'utilisateur peut être appliquée

Considérons maintenant l'exemple suivant :

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
    std::string m_name{};

public:
    Employee(std::string_view name)
        : m_name{ name }
    {
    }

    const std::string& getName() const { return m_name; }
};

void printEmployee(Employee e) // possède un paramètre de type Employee
{
    std::cout << e.getName();
}

int main()
{
    printEmployee("Joe"); // nous fournissons un argument de type chaîne littérale

    return 0;
}

Dans cette version, nous avons remplacé la classe Foo par une classe Employee. printEmployee possède un paramètre de type Employee, et nous lui passons une chaîne littérale de style C. Nous disposons également d'un constructeur de conversion : Employee(std::string_view).

Vous pourriez être surpris de constater que cette version ne compile pas. La raison est simple : une seule conversion définie par l'utilisateur peut être appliquée pour effectuer une conversion implicite, et cet exemple en nécessite deux. D'abord, notre chaîne littérale de style C doit être convertie en std::string_view (à l'aide d'un constructeur de conversion de std::string_view), puis notre std::string_view doit être convertie en Employee (à l'aide du constructeur de conversion Employee(std::string_view)).

Il existe deux façons de faire fonctionner cet exemple :

  1. Utiliser un littéral std::string_view :
int main()
{
    using namespace std::literals;
    printEmployee( "Joe"sv); // désormais un littéral std::string_view

    return 0;
}

Cela fonctionne car une seule conversion définie par l'utilisateur est maintenant nécessaire (de std::string_view vers Employee).

  1. Construire explicitement un Employee plutôt que d'en créer un implicitement :
int main()
{
    printEmployee(Employee{ "Joe" });

    return 0;
}

Cela fonctionne également, car une seule conversion définie par l'utilisateur est maintenant nécessaire (de la chaîne littérale vers le std::string_view utilisé pour initialiser l'objet Employee). Passer à la fonction notre objet Employee explicitement construit ne nécessite pas de seconde conversion.

Ce dernier exemple illustre une technique utile : il est trivial de transformer une conversion implicite en définition explicite. Nous verrons d'autres exemples plus loin dans cette leçon.

Point clé

Une conversion implicite peut être transformée trivialement en définition explicite en utilisant l'initialisation directe par liste (ou l'initialisation directe).

Quand les constructeurs de conversion posent problème

Considérons le programme suivant :

#include <iostream>

class Dollars
{
private:
    int m_dollars{};

public:
    Dollars(int d)
        : m_dollars{ d }
    {
    }

    int getDollars() const { return m_dollars; }
};

void print(Dollars d)
{
    std::cout << "$" << d.getDollars();
}

int main()
{
    print(5);

    return 0;
}

Lorsque nous appelons print(5), le constructeur de conversion Dollars(int) est utilisé pour convertir 5 en objet Dollars. Ainsi, ce programme affiche :


$5

Bien que ce soit peut-être l'intention de l'appelant, cela est difficile à deviner, car l'appelant n'a fourni aucune indication qu'il voulait réellement cela. Il est tout à fait possible que l'appelant ait supposé que cela afficherait 5, et ne s'attendait pas à ce que le compilateur convertisse silencieusement et implicitement notre valeur int en objet Dollars pour satisfaire cet appel de fonction.

Bien que cet exemple soit trivial, dans un programme plus grand et plus complexe, il est assez facile d'être surpris par une conversion implicite inattendue effectuée par le compilateur, ce qui entraîne un comportement inattendu à l'exécution.

Il serait préférable que notre fonction print(Dollars) ne puisse être appelée qu'avec un objet Dollars, et non avec n'importe quelle valeur pouvant être convertie implicitement en Dollars (en particulier un type fondamental comme int). Cela réduirait le risque d'erreurs involontaires.

Le mot-clé explicit

Pour résoudre ce type de problème, nous pouvons utiliser le mot-clé explicit (explicite) pour indiquer au compilateur qu'un constructeur ne doit pas être utilisé comme constructeur de conversion.

Rendre un constructeur explicit a deux conséquences notables :

  • Un constructeur explicite ne peut pas être utilisé pour effectuer une initialisation par copie ou une initialisation par copie de liste.
  • Un constructeur explicite ne peut pas être utilisé pour effectuer des conversions implicites (puisque celles-ci utilisent l'initialisation par copie ou l'initialisation par copie de liste).

Mettons à jour le constructeur Dollars(int) de l'exemple précédent pour en faire un constructeur explicite :

 #include <iostream>

class Dollars
{
private:
    int m_dollars{};

public:
    explicit Dollars(int d) // désormais explicit
        : m_dollars{ d }
    {
    }

    int getDollars() const { return m_dollars; }
};

void print(Dollars d)
{
    std::cout << "$" << d.getDollars();
}

int main()
{
    print(5); // erreur de compilation car Dollars(int) est explicit

    return 0;
}

Comme le compilateur ne peut plus utiliser Dollars(int) comme constructeur de conversion, il ne peut pas trouver de moyen de convertir 5 en Dollars. Par conséquent, il génère une erreur de compilation.

Pour les constructeurs dont la déclaration (dans la classe) et la définition (hors de la classe) sont séparées, le mot-clé explicit n'est utilisé que sur la déclaration.

Les constructeurs explicites peuvent être utilisés pour l'initialisation directe et l'initialisation directe par liste

Un constructeur explicite peut néanmoins être utilisé pour l'initialisation directe et l'initialisation directe par liste :

// En supposant que Dollars(int) est explicit
int main()
{
    Dollars d1(5); // ok
    Dollars d2{5}; // ok
}

Revenons maintenant à notre exemple précédent, où nous avions rendu le constructeur Dollars(int) explicite, ce qui faisait que l'instruction suivante générait une erreur de compilation :

    print(5); // erreur de compilation car Dollars(int) est explicit

Et si nous voulons réellement appeler print() avec la valeur int 5 alors que le constructeur est explicite ? La solution de contournement est simple : au lieu de laisser le compilateur convertir implicitement 5 en Dollars pour le passer à print(), nous pouvons nous-mêmes définir explicitement l'objet Dollars :

    print(Dollars{5}); // ok : création explicite d'un Dollars

Cela est permis, car nous pouvons toujours utiliser les constructeurs explicites pour initialiser des objets par liste. Et comme nous avons maintenant construit explicitement un Dollars, le type de l'argument correspond au type du paramètre, donc aucune conversion n'est nécessaire !

Cette version non seulement compile et s'exécute, mais elle documente aussi mieux notre intention, car elle indique explicitement que nous voulions appeler cette fonction avec un objet Dollars.

Notez que static_cast renvoie un objet initialisé directement, il prend donc en compte les constructeurs explicites lors de la conversion :

    print(static_cast<Dollars>(5)); // ok : static_cast utilise les constructeurs explicites

Retour par valeur et constructeurs explicites

Lorsque nous renvoyons une valeur depuis une fonction, si cette valeur ne correspond pas au type de retour de la fonction, une conversion implicite a lieu. Comme pour le passage par valeur, ces conversions ne peuvent pas utiliser de constructeurs explicites.

Le programme suivant montre quelques variantes de valeurs de retour et leurs résultats :

#include <iostream>

class Foo
{
public:
    explicit Foo() // remarque : explicit (uniquement pour l'exemple)
    {
    }

    explicit Foo(int x) // remarque : explicit
    {
    }
};

Foo getFoo()
{
    // cas avec explicit Foo()
    return Foo{ };   // ok
    return { };      // erreur : impossible de convertir implicitement une liste d'initialisation en Foo

    // cas avec explicit Foo(int)
    return 5;        // erreur : impossible de convertir implicitement int en Foo
    return Foo{ 5 }; // ok
    return { 5 };    // erreur : impossible de convertir implicitement une liste d'initialisation en Foo
}

int main()
{
    return 0;
}

Peut-être de façon surprenante, return { 5 } est considéré comme une conversion.

Bonnes pratiques d'utilisation de explicit

La bonne pratique moderne consiste à rendre explicit par défaut tout constructeur acceptant un seul argument. Cela inclut les constructeurs à plusieurs paramètres dont la plupart, voire tous, possèdent des valeurs par défaut. Cela empêche le compilateur d'utiliser ce constructeur pour des conversions implicites. Si une conversion implicite est nécessaire, seuls les constructeurs non explicites seront pris en compte. Si aucun constructeur non explicite ne permet d'effectuer la conversion, le compilateur génère une erreur.

Si une telle conversion est réellement souhaitée dans un cas particulier, il est trivial de transformer la conversion implicite en définition explicite à l'aide de l'initialisation directe par liste.

Les constructeurs suivants ne doivent pas être rendus explicites :

  • Les constructeurs de copie (et de déplacement), car ils n'effectuent pas de conversions.

Les constructeurs suivants ne sont en général pas rendus explicites :

  • Les constructeurs par défaut sans paramètre (car ils ne servent qu'à convertir {} en objet par défaut, ce que nous n'avons généralement pas besoin de restreindre).
  • Les constructeurs qui n'acceptent que plusieurs arguments (car ils ne sont en général pas candidats à des conversions de toute façon).

Cependant, si vous le préférez, les constructeurs ci-dessus peuvent être marqués explicit pour empêcher les conversions implicites à partir de listes vides et de listes à plusieurs arguments.

Les constructeurs suivants devraient en général être rendus explicites :

  • Les constructeurs qui prennent un seul argument.

Il arrive qu'il soit pertinent de rendre non explicite un constructeur à un seul argument. Cela peut être utile lorsque toutes les conditions suivantes sont réunies :

  • L'objet construit est sémantiquement équivalent à la valeur de l'argument.
  • La conversion est performante.

Par exemple, le constructeur de std::string_view qui accepte une chaîne de style C en argument n'est pas explicite, car il est peu probable que nous ne soyons pas d'accord pour qu'une chaîne de style C soit traitée comme un std::string_view. En revanche, le constructeur de std::string qui prend un std::string_view est marqué explicite, car si une valeur std::string est sémantiquement équivalente à une valeur std::string_view, construire un std::string n'est pas performant.

Bonne pratique

Rendez explicit par défaut tout constructeur acceptant un seul argument. Si une conversion implicite entre deux types est à la fois sémantiquement équivalente et performante, vous pouvez envisager de rendre le constructeur non explicite.

Ne rendez pas explicites les constructeurs de copie ou de déplacement, car ils n'effectuent pas de conversions.
