14.9 — Introduction aux constructeurs

Lorsqu'un type de classe est un agrégat, nous pouvons utiliser l'initialisation d'agrégat pour initialiser directement le type de classe :

struct Foo // Foo est un agrégat
{
    int x {};
    int y {};
};

int main()
{
    Foo foo { 6, 7 }; // utilise l'initialisation d'agrégat

    return 0;
}

L'initialisation d'agrégat procède membre par membre (les membres sont initialisés dans l'ordre de leur définition). Ainsi, lorsque foo est instancié dans l'exemple ci-dessus, foo.x est initialisé à 6 et foo.y à 7.

Contenu associé

Nous abordons la définition d'un agrégat et l'initialisation d'agrégat dans la leçon 13.8 -- Initialisation d'agrégat des structures.

Cependant, dès que nous rendons privée une variable membre (pour masquer nos données), notre type de classe n'est plus un agrégat (car les agrégats ne peuvent pas avoir de membres privés). Nous ne pouvons alors plus utiliser l'initialisation d'agrégat :

class Foo // Foo n'est pas un agrégat (il a des membres privés)
{
    int m_x {};
    int m_y {};
};

int main()
{
    Foo foo { 6, 7 }; // erreur de compilation : l'initialisation d'agrégat n'est pas possible

    return 0;
}

Interdire l'initialisation d'agrégat des types de classe possédant des membres privés se justifie pour plusieurs raisons :

  • L'initialisation d'agrégat exige de connaître l'implémentation de la classe (puisqu'il faut connaître ses membres et leur ordre de définition), ce que nous cherchons précisément à éviter en masquant nos membres de données.
  • Si notre classe possède un invariant, nous compterions sur l'utilisateur pour initialiser la classe d'une manière qui préserve cet invariant.

Comment alors initialiser une classe dotée de variables membres privées ? Le message d'erreur du compilateur pour l'exemple précédent donne un indice : « error: no matching constructor for initialization of 'Foo' » (erreur : aucun constructeur correspondant pour l'initialisation de « Foo »).

Il nous faut un constructeur correspondant. Mais qu'est-ce donc que c'est ?

Les constructeurs

Un constructeur (constructor) est une fonction membre spéciale qui est automatiquement appelée après la création d'un objet d'un type de classe non agrégat.

Lorsqu'un objet d'un type de classe non agrégat est défini, le compilateur cherche un constructeur accessible qui corresponde aux valeurs d'initialisation fournies par l'appelant (s'il y en a).

  • Si un constructeur accessible et correspondant est trouvé, la mémoire de l'objet est allouée, puis la fonction constructeur est appelée.
  • Si aucun constructeur accessible et correspondant ne peut être trouvé, une erreur de compilation est générée.

Point clé

Beaucoup de programmeurs débutants se demandent si les constructeurs créent ou non les objets. Ce n'est pas le cas : le compilateur prépare la mémoire de l'objet avant l'appel du constructeur. Le constructeur est ensuite appelé sur un objet non initialisé.

Cependant, si aucun constructeur correspondant ne peut être trouvé pour un ensemble d'initialiseurs, le compilateur signale une erreur. Ainsi, bien que les constructeurs ne créent pas les objets, l'absence de constructeur correspondant empêche la création de l'objet.

Au-delà de la détermination de la manière dont un objet peut être créé, les constructeurs remplissent généralement deux fonctions :

  • Ils initialisent en général les variables membres (via une liste d'initialisation des membres).
  • Ils peuvent effectuer d'autres tâches de préparation (via des instructions dans le corps du constructeur). Cela peut inclure la vérification des valeurs d'initialisation, l'ouverture d'un fichier ou d'une base de données, etc.

Une fois l'exécution du constructeur terminée, on dit que l'objet a été « construit », et il doit maintenant être dans un état cohérent et utilisable.

Notez que les agrégats ne peuvent pas avoir de constructeurs : si vous ajoutez un constructeur à un agrégat, celui-ci n'est plus un agrégat.

Nommer les constructeurs

Contrairement aux fonctions membres ordinaires, les constructeurs obéissent à des règles précises de nommage :

  • Un constructeur doit porter le même nom que la classe (avec la même casse). Pour les classes modèles, ce nom exclut les paramètres de modèle.
  • Un constructeur n'a pas de type de retour (pas même void).

Comme les constructeurs font en général partie de l'interface de votre classe, ils sont habituellement publics.

Un exemple simple de constructeur

Ajoutons un constructeur simple à notre exemple précédent :

#include <iostream>

class Foo
{
private:
    int m_x {};
    int m_y {};

public:
    Foo(int x, int y) // voici notre fonction constructeur qui prend deux initialiseurs
    {
        std::cout << "Foo(" << x << ", " << y << ") construit\n";
    }

    void print() const
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ")\n";
    }
};

int main()
{
    Foo foo{ 6, 7 }; // appelle le constructeur Foo(int, int)
    foo.print();

    return 0;
}

Ce programme compile désormais et produit le résultat :


Foo(6, 7) construit
Foo(0, 0)

Lorsque le compilateur rencontre la définition Foo foo{ 6, 7 }, il cherche un constructeur Foo correspondant qui accepte deux arguments de type int. Foo(int, int) correspond, donc le compilateur accepte la définition.

À l'exécution, lorsque foo est instancié, la mémoire de foo est allouée, puis le constructeur Foo(int, int) est appelé avec le paramètre x initialisé à 6 et le paramètre y initialisé à 7. Le corps de la fonction constructeur s'exécute alors et affiche Foo(6, 7) construit.

Lorsque nous appelons la fonction membre print(), vous remarquerez que les membres m_x et m_y valent 0. Cela tient au fait que, bien que la fonction constructeur Foo(int, int) ait été appelée, elle n'a pas réellement initialisé les membres. Nous montrerons comment le faire dans la prochaine leçon.

Conversion implicite des arguments d'un constructeur

Dans la leçon 10.1 -- Conversion implicite de type, nous avons indiqué que le compilateur effectue si nécessaire une conversion implicite des arguments d'un appel de fonction afin de correspondre à une définition de fonction dont les paramètres sont d'un type différent :

void foo(int, int)
{
}

int main()
{
    foo('a', true); // correspond à foo(int, int)

    return 0;
}

Il en va de même pour les constructeurs : le constructeur Foo(int, int) correspondra à tout appel dont les arguments sont implicitement convertibles en int :

class Foo
{
public:
    Foo(int x, int y)
    {
    }
};

int main()
{
    Foo foo{ 'a', true }; // correspond au constructeur Foo(int, int)

    return 0;
}

Les constructeurs ne doivent pas être const

Un constructeur doit pouvoir initialiser l'objet en cours de construction ; un constructeur ne doit donc pas être const.

#include <iostream>

class Something
{
private:
    int m_x{};

public:
    Something() // les constructeurs doivent être non const
    {
        m_x = 5; // il est permis de modifier les membres dans un constructeur non const
    }

    int getX() const { return m_x; } // const
};

int main()
{
    const Something s{}; // objet const, appelle implicitement le constructeur (non const)

    std::cout << s.getX(); // affiche 5

    return 0;
}

Normalement, une fonction membre non const ne peut pas être appelée sur un objet const. Cependant, la norme C++ précise explicitement (selon class.ctor.general#5) que const ne s'applique pas à un objet en cours de construction, et ne prend effet qu'une fois le constructeur terminé.

Constructeurs et setters

Les constructeurs sont conçus pour initialiser un objet entier au moment de son instanciation. Les setters sont conçus pour affecter une valeur à un seul membre d'un objet existant.
