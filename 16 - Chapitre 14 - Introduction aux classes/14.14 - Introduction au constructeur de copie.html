14.14 — Introduction au constructeur de copie

Considérez le programme suivant :

#include <iostream>

class Fraction
{
private:
    int m_numerator{ 0 };
    int m_denominator{ 1 };

public:
    // Constructeur par défaut
    Fraction(int numerator=0, int denominator=1)
        : m_numerator{numerator}, m_denominator{denominator}
    {
    }

    void print() const
    {
        std::cout << "Fraction(" << m_numerator << ", " << m_denominator << ")\n";
    }
};

int main()
{
    Fraction f { 5, 3 };  // Appelle le constructeur Fraction(int, int)
    Fraction fCopy { f }; // Quel constructeur est utilisé ici ?

    f.print();
    fCopy.print();

    return 0;
}

Vous serez peut-être surpris de constater que ce programme se compile sans problème et produit le résultat suivant :


Fraction(5, 3)
Fraction(5, 3)

Examinons de plus près le fonctionnement de ce programme.

L'initialisation de la variable f est une simple initialisation par accolades qui appelle le constructeur Fraction(int, int).

Mais qu'en est-il de la ligne suivante ? L'initialisation de la variable fCopy est elle aussi clairement une initialisation, et vous savez que les constructeurs servent à initialiser les classes. Quel constructeur cette ligne appelle-t-elle donc ?

La réponse est : le constructeur de copie.

Le constructeur de copie

Un constructeur de copie (copy constructor) est un constructeur utilisé pour initialiser un objet à partir d'un objet existant du même type. Une fois le constructeur de copie exécuté, le nouvel objet doit être une copie de l'objet passé en initialiseur.

Un constructeur de copie implicite

Si vous ne fournissez pas de constructeur de copie pour vos classes, le C++ en crée un constructeur de copie implicite (implicit copy constructor) public à votre place. Dans l'exemple ci-dessus, l'instruction Fraction fCopy { f }; invoque le constructeur de copie implicite pour initialiser fCopy avec f.

Par défaut, le constructeur de copie implicite effectue une initialisation membre à membre (memberwise initialization). Cela signifie que chaque membre est initialisé à l'aide du membre correspondant de la classe passée en initialiseur. Dans l'exemple ci-dessus, fCopy.m_numerator est initialisé avec f.m_numerator (qui vaut 5), et fCopy.m_denominator est initialisé avec f.m_denominator (qui vaut 3).

Une fois le constructeur de copie exécuté, les membres de f et de fCopy ont les mêmes valeurs, donc fCopy est une copie de f. Par conséquent, appeler print() sur l'un ou l'autre donne le même résultat.

Définir votre propre constructeur de copie

Nous pouvons aussi définir explicitement notre propre constructeur de copie. Dans cette leçon, nous ferons afficher un message par notre constructeur de copie, afin de vous montrer qu'il s'exécute bien lors de la création de copies.

Le constructeur de copie ressemble à ce que vous attendez :

#include <iostream>

class Fraction
{
private:
    int m_numerator{ 0 };
    int m_denominator{ 1 };

public:
    // Constructeur par défaut
    Fraction(int numerator=0, int denominator=1)
        : m_numerator{numerator}, m_denominator{denominator}
    {
    }

    // Constructeur de copie
    Fraction(const Fraction& fraction)
        // Initialise nos membres à l'aide du membre correspondant du paramètre
        : m_numerator{ fraction.m_numerator }
        , m_denominator{ fraction.m_denominator }
    {
        std::cout << "Copy constructor called\n"; // juste pour prouver que ça fonctionne
    }

    void print() const
    {
        std::cout << "Fraction(" << m_numerator << ", " << m_denominator << ")\n";
    }
};

int main()
{
    Fraction f { 5, 3 };  // Appelle le constructeur Fraction(int, int)
    Fraction fCopy { f }; // Appelle le constructeur de copie Fraction(const Fraction&)

    f.print();
    fCopy.print();

    return 0;
}

Lorsque ce programme est exécuté, vous obtenez :


Copy constructor called
Fraction(5, 3)
Fraction(5, 3)

Le constructeur de copie que nous avons défini ci-dessus est fonctionnellement équivalent à celui que nous obtiendrions par défaut, à ceci près que nous avons ajouté une instruction d'affichage pour prouver que le constructeur de copie est bien appelé. Ce constructeur de copie est invoqué lorsque fCopy est initialisé avec f.

Rappel

Les contrôles d'accès fonctionnent par classe (et non par objet). Cela signifie que les fonctions membres d'une classe peuvent accéder aux membres privés de n'importe quel objet de ce même type (et pas seulement à l'objet implicite).

Nous tirons parti de ce fait dans le constructeur de copie de Fraction ci-dessus afin d'accéder directement aux membres privés du paramètre fraction. Sinon, nous n'aurions aucun moyen d'accéder directement à ces membres (sans ajouter de fonctions d'accès, ce que nous pourrions ne pas vouloir faire).

Un constructeur de copie ne devrait rien faire d'autre que copier un objet. En effet, le compilateur peut supprimer (optimiser) le constructeur de copie dans certains cas. Si vous comptez sur le constructeur de copie pour un comportement autre que la simple copie, ce comportement peut ou non se produire. Nous revenons sur ce point dans la leçon 14.15 -- Initialisation de classe et élision de copie.

Bonne pratique

Les constructeurs de copie ne devraient avoir aucun effet de bord autre que la copie.

Préférer le constructeur de copie implicite

Contrairement au constructeur par défaut implicite, qui ne fait rien (et n'est donc que rarement ce que nous voulons), l'initialisation membre à membre effectuée par le constructeur de copie implicite correspond généralement exactement à ce que nous souhaitons. Par conséquent, dans la plupart des cas, utiliser le constructeur de copie implicite est parfaitement acceptable.

Bonne pratique

Préférez le constructeur de copie implicite, sauf si vous avez une raison précise d'en créer un vous-même.

Nous verrons des cas où le constructeur de copie doit être redéfini lorsque nous aborderons l'allocation dynamique de mémoire (21.13 -- Copie superficielle et copie profonde).

Le paramètre du constructeur de copie doit être une référence

Le paramètre d'un constructeur de copie doit obligatoirement être une référence lvalue ou une référence lvalue constante. Comme le constructeur de copie ne doit pas modifier son paramètre, l'utilisation d'une référence lvalue constante est préférable.

Bonne pratique

Si vous écrivez votre propre constructeur de copie, le paramètre doit être une référence lvalue constante.

Passage par valeur et constructeur de copie

Lorsqu'un objet est passé par valeur, l'argument est copié dans le paramètre. Lorsque l'argument et le paramètre sont du même type de classe, la copie est effectuée par l'invocation implicite du constructeur de copie.

Cela est illustré dans l'exemple suivant :

#include <iostream>

class Fraction
{
private:
    int m_numerator{ 0 };
    int m_denominator{ 1 };

public:
    // Constructeur par défaut
    Fraction(int numerator = 0, int denominator = 1)
        : m_numerator{ numerator }, m_denominator{ denominator }
    {
    }

    // Constructeur de copie
    Fraction(const Fraction& fraction)
        : m_numerator{ fraction.m_numerator }
        , m_denominator{ fraction.m_denominator }
    {
        std::cout << "Copy constructor called\n";
    }

    void print() const
    {
        std::cout << "Fraction(" << m_numerator << ", " << m_denominator << ")\n";
    }
};

void printFraction(Fraction f) // f est passé par valeur
{
    f.print();
}

int main()
{
    Fraction f{ 5, 3 };

    printFraction(f); // f est copié dans le paramètre de la fonction à l'aide du constructeur de copie

    return 0;
}

Sur la machine de l'auteur, cet exemple affiche :


Copy constructor called
Fraction(5, 3)

Dans l'exemple ci-dessus, l'appel printFraction(f) passe f par valeur. Le constructeur de copie est invoqué pour copier f depuis main dans le paramètre f de la fonction printFraction().

Renvoi par valeur et constructeur de copie

Dans la leçon 2.5 -- Introduction à la portée locale, nous avons indiqué qu'un renvoi par valeur crée un objet temporaire (contenant une copie de la valeur de retour) qui est transmis à l'appelant. Lorsque le type de retour et la valeur retournée sont du même type de classe, l'objet temporaire est initialisé par l'invocation implicite du constructeur de copie.

Par exemple :

#include <iostream>

class Fraction
{
private:
    int m_numerator{ 0 };
    int m_denominator{ 1 };

public:
    // Constructeur par défaut
    Fraction(int numerator = 0, int denominator = 1)
        : m_numerator{ numerator }, m_denominator{ denominator }
    {
    }

    // Constructeur de copie
    Fraction(const Fraction& fraction)
        : m_numerator{ fraction.m_numerator }
        , m_denominator{ fraction.m_denominator }
    {
        std::cout << "Copy constructor called\n";
    }

    void print() const
    {
        std::cout << "Fraction(" << m_numerator << ", " << m_denominator << ")\n";
    }
};

void printFraction(Fraction f) // f est passé par valeur
{
    f.print();
}

Fraction generateFraction(int n, int d)
{
    Fraction f{ n, d };
    return f;
}

int main()
{
    Fraction f2 { generateFraction(1, 2) }; // Fraction est renvoyé via le constructeur de copie

    printFraction(f2); // f2 est copié dans le paramètre de la fonction à l'aide du constructeur de copie

    return 0;
}

Lorsque generateFraction renvoie un Fraction à main, un objet Fraction temporaire est créé et initialisé à l'aide du constructeur de copie.

Comme ce temporaire sert à initialiser Fraction f2, le constructeur de copie est invoqué une nouvelle fois pour copier le temporaire dans f2.

Et lorsque f2 est passé à printFraction(), le constructeur de copie est appelé une troisième fois.

Ainsi, sur la machine de l'auteur, cet exemple affiche :


Copy constructor called
Copy constructor called
Copy constructor called
Fraction(1, 2)

Si vous compilez et exécutez l'exemple ci-dessus, vous constaterez peut-être que seuls deux appels au constructeur de copie ont lieu. Il s'agit d'une optimisation du compilateur connue sous le nom d'élision de copie (copy elision). Nous étudions plus en détail l'élision de copie dans la leçon 14.15 -- Initialisation de classe et élision de copie.

Utiliser = default pour générer un constructeur de copie par défaut

Si une classe n'a pas de constructeur de copie, le compilateur en génère implicitement un pour nous. Si nous le souhaitons, nous pouvons demander explicitement au compilateur de créer un constructeur de copie par défaut à l'aide de la syntaxe = default :

#include <iostream>

class Fraction
{
private:
    int m_numerator{ 0 };
    int m_denominator{ 1 };

public:
    // Constructeur par défaut
    Fraction(int numerator=0, int denominator=1)
        : m_numerator{numerator}, m_denominator{denominator}
    {
    }

    // Demande explicitement le constructeur de copie par défaut
    Fraction(const Fraction& fraction) = default;

    void print() const
    {
        std::cout << "Fraction(" << m_numerator << ", " << m_denominator << ")\n";
    }
};

int main()
{
    Fraction f { 5, 3 };
    Fraction fCopy { f };

    f.print();
    fCopy.print();

    return 0;
}

Utiliser = delete pour empêcher les copies

Il arrive que nous ne voulions pas que les objets d'une certaine classe soient copiables. Nous pouvons l'empêcher en marquant la fonction constructeur de copie comme supprimée, à l'aide de la syntaxe = delete :

#include <iostream>

class Fraction
{
private:
    int m_numerator{ 0 };
    int m_denominator{ 1 };

public:
    // Constructeur par défaut
    Fraction(int numerator=0, int denominator=1)
        : m_numerator{numerator}, m_denominator{denominator}
    {
    }

    // Supprime le constructeur de copie afin qu'aucune copie ne soit possible
    Fraction(const Fraction& fraction) = delete;

    void print() const
    {
        std::cout << "Fraction(" << m_numerator << ", " << m_denominator << ")\n";
    }
};

int main()
{
    Fraction f { 5, 3 };
    Fraction fCopy { f }; // erreur de compilation : le constructeur de copie a été supprimé

    return 0;
}

Dans cet exemple, lorsque le compilateur cherche un constructeur pour initialiser fCopy avec f, il constate que le constructeur de copie a été supprimé. Cela provoque l'émission d'une erreur de compilation.

En passant…

Vous pouvez également empêcher le public de copier un objet de classe en rendant le constructeur de copie privé (les fonctions privées ne sont pas accessibles au public). Cependant, un constructeur de copie privé peut toujours être utilisé par les autres membres de la classe, donc cette solution n'est pas recommandée, sauf si ce comportement est souhaité.

Pour les lecteurs avancés

La règle du trois (rule of three) est un principe bien connu du C++ qui énonce que si une classe nécessite un constructeur de copie, un destructeur ou un opérateur d'affectation par copie définis par l'utilisateur, alors elle en nécessite probablement les trois. En C++11, cette règle a été étendue à la règle du cinq (rule of five), qui ajoute à la liste le constructeur de déplacement et l'opérateur d'affectation par déplacement.

Ne pas respecter la règle du trois ou la règle du cinq risque de produire un code défectueux. Nous reverrons ces règles lorsque nous étudierons l'allocation dynamique de mémoire.

Nous abordons les destructeurs dans les leçons 15.4 -- Introduction aux destructeurs et 19.3 -- Destructeurs, et l'affectation par copie dans la leçon 21.12 -- Surcharge de l'opérateur d'affectation.

Quiz

Question n° 1

Dans la leçon ci-dessus, nous avons indiqué que le paramètre d'un constructeur de copie doit être une référence (constante ou non). Pourquoi n'est-il pas permis d'utiliser un passage par valeur ?

Indice

Indice : réfléchissez à ce qui se passe lorsqu'on passe un argument de type classe par valeur.

Solution

Lorsqu'un argument de type classe est passé par valeur, le constructeur de copie est invoqué implicitement pour copier l'argument dans le paramètre.

Si le constructeur de copie utilisait un passage par valeur, il devrait s'appeler lui-même pour copier l'argument initialiseur dans son paramètre. Mais cet appel au constructeur de copie serait lui aussi un passage par valeur, ce qui invoquerait à nouveau le constructeur de copie pour copier l'argument dans le paramètre. On obtiendrait alors une chaîne infinie d'appels au constructeur de copie.
