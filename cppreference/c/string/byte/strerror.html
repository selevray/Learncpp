strerror, strerror_s, strerrorlen_s

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <string.h>

char* strerror( int errnum );  // (1)

errno_t strerror_s( char *buf, rsize_t bufsz, errno_t errnum );  // (2) (depuis C11)

size_t strerrorlen_s( errno_t errnum );  // (3) (depuis C11)
  1. Renvoie un pointeur vers la description textuelle du code d'erreur système errnum, identique à la description qu'afficherait perror().

errnum est généralement obtenu à partir de la variable errno, mais la fonction accepte toute valeur de type int. Le contenu de la chaîne dépend des paramètres régionaux.

La chaîne renvoyée ne doit pas être modifiée par le programme, mais peut être écrasée par un appel ultérieur à la fonction strerror. strerror n'est pas tenue d'être thread-safe. Les implémentations peuvent renvoyer différents pointeurs vers des littéraux de chaînes statiques en lecture seule, ou renvoyer toujours le même pointeur, pointant vers un tampon statique dans lequel strerror place la chaîne.

  1. Identique à (1), à ceci près que le message est copié dans le stockage fourni par l'utilisateur buf. Au plus bufsz-1 octets sont écrits, le tampon est toujours terminé par un caractère nul. Si le message a dû être tronqué pour tenir dans le tampon et que bufsz est supérieur à 3, alors seuls bufsz-4 octets sont écrits, et les caractères "..." sont ajoutés avant le caractère nul de fin. De plus, les erreurs suivantes sont détectées à l'exécution et appellent la fonction gestionnaire de contraintes actuellement installée :
  • buf est un pointeur nul
  • bufsz vaut zéro ou est supérieur à RSIZE_MAX

Le comportement est indéfini si l'écriture dans buf dépasse la fin du tableau, ce qui peut se produire lorsque la taille du tampon pointé par buf est inférieure au nombre de caractères du message d'erreur, lui-même inférieur à bufsz.

  1. Calcule la longueur du message d'erreur spécifique aux paramètres régionaux non tronqué que strerror_s écrirait si elle était appelée avec errnum. La longueur n'inclut pas le caractère nul de fin.Comme pour toutes les fonctions à vérification des bornes, strerror_s et strerrorlen_s ne sont garantis disponibles que si __STDC_LIB_EXT1__ est défini par l'implémentation et si l'utilisateur définit __STDC_WANT_LIB_EXT1__ comme la constante entière 1 avant d'inclure <string.h>.

Paramètres

  • errnum — valeur entière désignant un code d'erreur
  • buf — pointeur vers un tampon fourni par l'utilisateur
  • bufsz — taille du tampon fourni par l'utilisateur

Valeur de retour

  1. Pointeur vers une chaîne d'octets terminée par un caractère nul correspondant au code d'erreur errno errnum.

  2. Zéro si le message entier a été stocké avec succès dans buf, non nul sinon.

  3. Longueur (sans le terminateur nul) du message que strerror_s renverrait

Notes

POSIX autorise les appels ultérieurs à strerror à invalider le pointeur renvoyé par un appel précédent. Il précise également que c'est la facette LC_MESSAGES de la locale qui contrôle le contenu de ces messages.

strerror_s est la seule fonction à vérification de bornes qui permet la troncature, car fournir le plus d'informations possible sur un échec a été jugé plus souhaitable. POSIX définit également strerror_r dans des buts similaires.

Exemple

#define __STDC_WANT_LIB_EXT1__ 1
#include <stdio.h>
#include <errno.h>
#include <string.h>
#include <locale.h>

int main(void)
{
    FILE *fp = fopen(tmpnam((char[L_tmpnam]){0}), "r");
    if(fp==NULL) {
        printf("File opening error: %s\n", strerror(errno));
        setlocale(LC_MESSAGES, "de_DE.utf8");
        printf("Now in German: %s\n", strerror(errno));
#ifdef __STDC_LIB_EXT1__
        setlocale(LC_ALL, "ja_JP.utf8"); // printf a besoin de CTYPE pour la sortie multioctet
        size_t errmsglen = strerrorlen_s(errno) + 1;
        char errmsg[errmsglen];
        strerror_s(errmsg, errmsglen, errno);
        printf("Now in Japanese: %s\n", errmsg);
#endif
    }
}

Sortie possible :

File opening error: No such file or directory
Now in German: Datei oder Verzeichnis nicht gefunden
Now in Japanese: そのようなファイル、又はディレクトリはありません
