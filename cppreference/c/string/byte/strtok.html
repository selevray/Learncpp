strtok, strtok_s

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <string.h>

char* strtok( char* str, const char* delim );  // (jusqu'à C99)

char* strtok( char* restrict str, const char* restrict delim );  // (depuis C99)

char* strtok_s( char* restrict str, rsize_t* restrict strmax,
                const char* restrict delim, char** restrict ptr );  // (2) (depuis C11)
  1. Trouve le jeton suivant dans une chaîne d'octets terminée par un caractère nul pointée par str. Les caractères séparateurs sont identifiés par la chaîne d'octets terminée par un caractère nul pointée par delim.

Cette fonction est conçue pour être appelée plusieurs fois afin d'obtenir les jetons successifs d'une même chaîne.

  • Si str n'est pas un pointeur nul, l'appel est traité comme le premier appel à strtok pour cette chaîne particulière. La fonction recherche le premier caractère qui n'est pas contenu dans delim.

    • Si aucun tel caractère n'est trouvé, il n'y a aucun jeton dans str et la fonction renvoie un pointeur nul.
    • Si un tel caractère est trouvé, il constitue le début du jeton. La fonction recherche ensuite, à partir de ce point, le premier caractère qui est contenu dans delim.
      • Si aucun caractère de ce type n'a été trouvé, str ne comporte qu'un seul jeton, et les appels futurs à strtok retourneront un pointeur nul
      • Si un tel caractère est trouvé, il est remplacé par le caractère nul '\0' et le pointeur vers le caractère suivant est stocké dans un emplacement statique pour les invocations suivantes.
    • La fonction retourne ensuite le pointeur vers le début du jeton

  • Si str est un pointeur nul, l'appel est traité comme un appel ultérieur à strtok : la fonction reprend là où elle s'était arrêtée lors de l'invocation précédente. Le comportement est le même que si le pointeur précédemment stocké était passé comme str.

Le comportement est indéfini si str ou delim n'est pas un pointeur vers une chaîne d'octets terminée par un caractère nul.

  1. Identique à (1), sauf qu'à chaque étape, écrit dans *strmax le nombre de caractères restant à lire dans str et écrit l'état interne du tokeniseur dans *ptr. Les appels répétés (avec str nul) doivent passer strmax et ptr avec les valeurs stockées par l'appel précédent. De plus, les erreurs suivantes sont détectées à l'exécution et appellent la fonction gestionnaire de contraintes actuellement installée, sans rien stocker dans l'objet pointé par ptr
  • strmax, delim ou ptr est un pointeur nul
  • lors d'un appel non initial (avec str nul), *ptr est un pointeur nul
  • lors du premier appel, *strmax vaut zéro ou est supérieur à RSIZE_MAX
  • la recherche de la fin d'un jeton atteint la fin de la chaîne source (mesurée par la valeur initiale de *strmax) sans rencontrer le caractère nul de fin

Le comportement est indéfini si str pointe vers un tableau de caractères dépourvu de caractère nul et si strmax pointe vers une valeur supérieure à la taille de ce tableau de caractères.Comme pour toutes les fonctions à vérification de bornes, strtok_s n'est garantie disponible que si __STDC_LIB_EXT1__ est défini par l'implémentation et si l'utilisateur définit __STDC_WANT_LIB_EXT1__ comme la constante entière 1 avant d'inclure <string.h>.

Paramètres

  • str — pointeur vers la chaîne d'octets terminée par un caractère nul à découper en jetons
  • delim — pointeur vers la chaîne d'octets terminée par un caractère nul identifiant les délimiteurs
  • strmax — pointeur vers un objet contenant initialement la taille de str : strtok_s stocke le nombre de caractères restant à examiner
  • ptr — pointeur vers un objet de type char*, utilisé par strtok_s pour stocker son état interne

Valeur de retour

Retourne un pointeur vers le début du jeton suivant, ou un pointeur nul s'il n'y a plus de jetons.

Note

Cette fonction est destructive : elle écrit les '\0' caractères dans les éléments de la chaîne str. En particulier, un littéral de chaîne ne peut pas être utilisé comme premier argument de strtok.

Chaque appel à strtok modifie une variable statique : elle n'est pas thread-safe.

Contrairement à la plupart des autres découpeurs, les délimiteurs dans strtok peuvent être différents pour chaque jeton suivant, et peuvent même dépendre du contenu des jetons précédents.

La fonction strtok_s diffère de la fonction POSIX strtok_r en empêchant l'écriture en dehors de la chaîne tokenisée, et en vérifiant les contraintes d'exécution. La signature Microsoft CRT strtok_s correspond à cette définition POSIX strtok_r, et non à celle de C11 strtok_s.

Exemple

#define __STDC_WANT_LIB_EXT1__ 1
#include <stdio.h>
#include <string.h>

int main(void)
{
    char input[] = "A bird came down the walk";
    printf("Parsing the input string '%s'\n", input);
    char* token = strtok(input, " ");
    while (token)
    {
        puts(token);
        token = strtok(NULL, " ");
    }

    printf("Contents of the input string now: '");
    for (size_t n = 0; n < sizeof input; ++n)
        input[n] ? putchar(input[n]) : fputs("\\0", stdout);
    puts("'");

#ifdef __STDC_LIB_EXT1__
    char str[] = "A bird came down the walk";
    rsize_t strmax = sizeof str;
    const char* delim = " ";
    char* next_token;
    printf("Parsing the input string '%s'\n", str);
    token = strtok_s(str, &strmax, delim, &next_token);
    while (token)
    {
        puts(token);
        token = strtok_s(NULL, &strmax, delim, &next_token);
    }

    printf("Contents of the input string now: '");
    for (size_t n = 0; n < sizeof str; ++n)
        str[n] ? putchar(str[n]) : fputs("\\0", stdout);
    puts("'");
#endif
}
