Type

Les objets, les fonctions et les expressions ont une propriété appelée type, qui détermine l'interprétation de la valeur binaire stockée dans un objet ou évaluée par l'expression.

Classification des types

Le système de types du C se compose des types suivants :

  • le type void
  • types de base
    • le type char
    • types entiers signés
      • standard : signed char, short, int, long, long long (depuis C99)
  • de précision binaire : _BitInt(N) où N est une expression constante entière qui spécifie le nombre de bits utilisés pour représenter le type, bit de signe inclus. Chaque valeur de N désigne un type distinct.

(depuis C23)

  • étendus : défini par l'implémentation, par ex. __int128

(depuis C99)

  • types entiers non signés
    • standard : _Bool, (depuis C99) unsigned char, unsigned short, unsigned int, unsigned long, unsigned long long (depuis C99)
  • de précision binaire : unsigned _BitInt(N) où N est une expression constante entière qui spécifie le nombre de bits utilisés pour représenter le type. Chaque valeur de N désigne un type distinct. Cette catégorie comprend le type unsigned _BitInt(1), qui n'a pas de type entier signé de précision binaire correspondant.

(depuis C23)

  • étendus : défini par l'implémentation, par ex. __uint128

(depuis C99)

  • types à virgule flottante
    • types réels à virgule flottante : float, double, long double
  • types réels décimaux à virgule flottante : _Decimal32, _Decimal64, _Decimal128

(depuis C23)

  • types complexes : float _Complex, double _Complex, long double _Complex
  • types imaginaires : float _Imaginary, double _Imaginary, long double _Imaginary

(depuis C99)

  • types énumérés

  • types dérivés

    • types tableau
    • types structure
    • types union
    • types fonction
    • types pointeurs
  • types atomiques

(depuis C11)

Pour chaque type listé ci-dessus, plusieurs versions qualifiées de ce type peuvent exister, correspondant aux combinaisons d'un, deux ou des trois qualificateurs const, volatile et restrict (lorsque la sémantique du qualificateur le permet).

Groupes de types

  • types objets : tous les types qui ne sont pas des types fonction
  • types caractères : char, signed char, unsigned char
  • types entiers : char, types entiers signés, types entiers non signés, types énumérés
  • types réels : types entiers et types réels à virgule flottante
  • types arithmétiques : types entiers et types à virgule flottante
  • types scalaires : types arithmétiques, types pointeurs, et nullptr_t (depuis C23)
  • types agrégats : types tableau et types structure
  • types dérivés de déclarateur : types tableau, types fonction et types pointeur

La construction d'un type objet complet tel que le nombre d'octets de sa représentation d'objet ne soit pas représentable dans le type size_t (c'est-à-dire le type résultant de l'opérateur sizeof), y compris la création d'un tel type VLA à l'exécution, (depuis C99) est un comportement indéfini.

Types compatibles

Dans un programme C, les déclarations qui désignent le même objet ou la même fonction dans des unités de traduction différentes n'ont pas besoin d'utiliser le même type. Il suffit qu'elles utilisent des types suffisamment similaires, appelés formellement types compatibles. Il en va de même pour les appels de fonction et les accès par lvalue ; les types des arguments doivent être compatibles avec les types des paramètres, et le type de l'expression lvalue doit être compatible avec le type de l'objet auquel on accède.

Les types T et U sont compatibles si

  • ils sont le même type (même nom ou alias introduits par un typedef)

  • ils sont des versions identiquement qualifiées cvr de types non qualifiés compatibles

  • ce sont des types pointeurs qui pointent vers des types compatibles

  • ce sont des types tableau, et

    • leurs types d'éléments sont compatibles, et
    • si les deux ont une taille constante, cette taille est la même. Note : les tableaux de borne inconnue sont compatibles avec tout tableau d'un type d'élément compatible. Un VLA est compatible avec tout tableau d'un type d'élément compatible. (depuis C99)

  • ce sont tous deux des types structure/union/énumération, et

    • (C99) si l'un est déclaré avec une étiquette, l'autre doit aussi être déclaré avec la même étiquette.
    • si les deux sont des types complets, leurs membres doivent correspondre exactement en nombre, être déclarés avec des types compatibles et avoir des noms correspondants.
    • de plus, si ce sont des énumérations, les membres correspondants doivent aussi avoir les mêmes valeurs.
    • de plus, si ce sont des structures ou des unions,
      • Les membres correspondants doivent être déclarés dans le même ordre (structures uniquement)
      • Les champs de bits correspondants doivent avoir les mêmes largeurs.

  • l'un est un type énuméré et l'autre est le type sous-jacent de cette énumération

  • ce sont des types fonction, et

    • leurs types de retour sont compatibles
    • ils utilisent tous deux des listes de paramètres, le nombre de paramètres (y compris l'utilisation de l'ellipse) est le même, et les paramètres correspondants, après application des ajustements de type tableau-vers-pointeur et fonction-vers-pointeur et après suppression des qualificateurs de niveau supérieur, ont des types compatibles
  • l'un est une définition à l'ancienne (sans liste de paramètres), l'autre possède une liste de paramètres, la liste de paramètres n'utilise pas d'ellipse et chaque paramètre est compatible (après ajustement de type du paramètre de fonction) avec le paramètre à l'ancienne correspondant après promotions d'arguments par défaut
  • l'un est une déclaration à l'ancienne (sans liste de paramètres), l'autre possède une liste de paramètres, la liste de paramètres n'utilise pas d'ellipse, et tous les paramètres (après ajustement de type du paramètre de fonction) ne sont pas affectés par les promotions d'arguments par défaut

(jusqu'à C23)

Le type char n'est pas compatible avec signed char et n'est pas compatible avec unsigned char.

Si deux déclarations font référence au même objet ou à la même fonction et n'utilisent pas des types compatibles, le comportement du programme est indéfini.

// Unité de traduction 1
struct S { int a; };
extern struct S *x; // compatible avec le x de TU2, mais pas avec le x de TU3

// Unité de traduction 2
struct S;
extern struct S *x; // compatible avec les deux x

// Unité de traduction 3
struct S { float a; };
extern struct S *x; // compatible avec le x de TU2, mais pas avec le x de TU1

// le comportement est indéfini

// Unité de traduction 1
#include <stdio.h>

struct s { int i; }; // compatible avec le s de TU3, mais pas avec celui de TU2
extern struct s x = {0}; // compatible avec le x de TU3
extern void f(void); // compatible avec le f de TU2

int main()
{
    f();
    return x.i;
}

// Unité de traduction 2
struct s { float f; }; // compatible avec le s de TU4, mais pas avec celui de TU1
extern struct s y = {3.14}; // compatible avec le y de TU4
void f() // compatible avec le f de TU1
{
    return;
}

// Unité de traduction 3
struct s { int i; }; // compatible avec le s de TU1, mais pas avec celui de TU2
extern struct s x; // compatible avec le x de TU1

// Unité de traduction 4
struct s { float f; }; // compatible avec le s de TU2, mais pas avec celui de TU1
extern struct s y; // compatible avec le y de TU2

// le comportement est bien défini : seules des déclarations multiples
// d'objets et de fonctions doivent avoir des types compatibles, et non les types eux-mêmes

Note : C++ n'a pas de notion de types compatibles. Un programme C qui déclare dans différentes unités de traduction deux types compatibles mais non identiques n'est pas un programme C++ valide.

Types composites

Un type composite peut être construit à partir de deux types compatibles ; c'est un type compatible avec les deux types et qui satisfait les conditions suivantes :

  • Si les deux types sont des types tableau, les règles suivantes s'appliquent :
    • Si l'un des types est un tableau de taille constante connue, le type composite est un tableau de cette taille.
  • Sinon, si l'un des types est un VLA dont la taille est spécifiée par une expression non évaluée, un programme nécessitant le type composite des deux types a un comportement indéfini.
  • Sinon, si l'un des types est un VLA dont la taille est spécifiée, le type composite est un VLA de cette taille.
  • Sinon, si l'un des types est un VLA de taille non spécifiée, le type composite est un VLA de taille non spécifiée.

(depuis C99)

  • Sinon, les deux types sont des tableaux de taille inconnue et le type composite est un tableau de taille inconnue. Le type d'élément du type composite est le type composite des deux types d'éléments.
  • Si un seul des types est un type fonction avec une liste de types de paramètres (un prototype de fonction), le type composite est un prototype de fonction avec cette liste de types de paramètres.

(jusqu'à C23)

  • Si les deux types sont des types fonction avec des listes de types de paramètres, le type de chaque paramètre dans la liste composite de types de paramètres est le type composite des paramètres correspondants.

Ces règles s'appliquent récursivement aux types dont dérivent les deux types.

// Étant donné les deux déclarations de portée fichier suivantes :
int f(int (*)(), double (*)[3]);
int f(int (*)(char *), double (*)[]); // C23 : Erreur : types en conflit pour 'f'
// Le type composite résultant pour la fonction est :
int f(int (*)(char *), double (*)[3]);

Pour un identifiant à liaison interne ou externe déclaré dans une portée où une déclaration antérieure de cet identifiant est visible, si la déclaration antérieure spécifie une liaison interne ou externe, le type de l'identifiant à la déclaration ultérieure devient le type composite.

Types incomplets

Un type incomplet est un type objet qui ne possède pas suffisamment d'informations pour déterminer la taille des objets de ce type. Un type incomplet peut être complété à un moment donné de l'unité de traduction.

Les types suivants sont incomplets :

  • le type void. Ce type ne peut pas être complété.
  • type tableau de taille inconnue. Il peut être complété par une déclaration ultérieure qui spécifie la taille.
extern char a[]; // le type de a est incomplet (ceci apparaît généralement dans un en-tête)
char a[10];      // le type de a est maintenant complet (ceci apparaît généralement dans un fichier source)
  • type structure ou union au contenu inconnu. Il peut être complété par une déclaration de la même structure ou union qui définit son contenu plus tard dans la même portée.
struct node
{
    struct node* next; // struct node est incomplet à ce point
}; // struct node est complet à ce point

Noms de types

Un type peut devoir être nommé dans un contexte autre que la déclaration. Dans ces situations, on utilise un nom de type, qui est, grammaticalement, exactement une liste de spécificateurs de type et de qualificateurs de type, suivie du déclarateur (voir déclarations) tel qu'il serait utilisé pour déclarer un seul objet ou une seule fonction de ce type, à ceci près que l'identifiant est omis :

int n; // déclaration d'un int
sizeof(int); // utilisation du nom de type

int *a[3]; // déclaration d'un tableau de 3 pointeurs vers int
sizeof(int *[3]); // utilisation du nom de type

int (*p)[3]; // déclaration d'un pointeur vers un tableau de 3 int
sizeof(int (*)[3]); // utilisation du nom de type

int (*a)[*] // déclaration d'un pointeur vers un VLA (dans un paramètre de fonction)
sizeof(int (*)[*]) // utilisation du nom de type (dans un paramètre de fonction)

int *f(void); // déclaration de fonction
sizeof(int *(void)); // utilisation du nom de type

int (*p)(void); // déclaration de pointeur vers une fonction
sizeof(int (*)(void)); // utilisation du nom de type

int (*const a[])(unsigned int, ...) = {0}; // tableau de pointeurs vers des fonctions
sizeof(int (*const [])(unsigned int, ...)); // utilisation du nom de type

Sauf que les parenthèses redondantes autour de l'identifiant sont significatives dans un nom de type et représentent « fonction sans spécification de paramètre » :

int (n); // déclare n de type int
sizeof(int ()); // utilise le type « fonction retournant int »

Les noms de types sont utilisés dans les situations suivantes :

  • cast
  • sizeof
  • littéral composé

(depuis C99)

  • sélection générique
  • [_Alignof (jusqu'à C23) | alignof (depuis C23)]
  • [_Alignas (jusqu'à C23) | alignas (depuis C23)]
  • _Atomic (lorsqu'utilisé comme spécificateur de type)

(depuis C11)

Un nom de type peut introduire un nouveau type :

void* p = (void*)(struct X { int i; } *)0;
// le nom de type « struct X {int i;}* » utilisé dans l'expression de conversion
// introduit le nouveau type « struct X »
struct X x = {1}; // struct X est maintenant dans la portée
