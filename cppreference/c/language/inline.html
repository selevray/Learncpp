spécificateur de fonction inline

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Déclare une fonction inline.

Syntaxe

| | | | inline function_declaration | | (depuis C99) | |

Explication

Le spécificateur inline a pour but de servir d'indication au compilateur pour effectuer des optimisations, telles que l'inlining de fonction, qui exigent généralement que la définition d'une fonction soit visible au site d'appel. Les compilateurs peuvent (et le font généralement) ignorer la présence ou l'absence du spécificateur inline à des fins d'optimisation.

Si le compilateur effectue l'inlining de fonction, il remplace un appel de cette fonction par son corps, évitant le surcoût d'un appel de fonction (placement des données sur la pile et récupération du résultat), ce qui peut entraîner un exécutable plus volumineux, car le code de la fonction doit être répété plusieurs fois. Le résultat est similaire aux macros de type fonction, sauf que les identifiants et les macros utilisés dans la fonction désignent les définitions visibles au point de définition, et non au point d'appel.

Indépendamment du fait que l'inlining ait lieu ou non, la sémantique suivante des fonctions inline est garantie :

Toute fonction à liaison interne peut être déclarée static inline sans autre restriction.

Une fonction inline non statique ne peut pas définir un static local à la fonction non const, et ne peut pas référencer un static de portée fichier.

static int x;

inline void f(void)
{
    static int n = 1; // erreur : static non const dans une fonction inline non statique
    int k = x; // erreur : fonction inline non statique accède à une variable statique
}

Si une fonction non statique est déclarée inline, elle doit alors être définie dans la même unité de traduction. La définition inline qui n'utilise pas extern n'est pas visible à l'extérieur et n'empêche pas d'autres unités de traduction de définir la même fonction. Cela fait du mot-clé inline une alternative à static pour définir des fonctions à l'intérieur des en-têtes, qui peuvent être inclus dans plusieurs unités de traduction du même programme.

Si une fonction est déclarée inline dans certaines unités de traduction, elle n'a pas besoin d'être déclarée inline partout : au plus une unité de traduction peut aussi fournir une fonction ordinaire, non inline et non statique, ou une fonction déclarée extern inline. On dit que cette unité de traduction fournit la définition externe. Afin d'éviter un comportement indéfini, une définition externe doit exister dans le programme si le nom de la fonction à liaison externe est utilisé dans une expression, voir règle de la définition unique.

L'adresse d'une fonction inline à liaison externe est toujours celle de la définition externe, mais lorsque cette adresse est utilisée pour effectuer un appel de fonction, il n'est pas spécifié si la définition inline (si elle est présente dans l'unité de traduction) ou la définition externe est appelée. Les objets statiques définis dans une définition inline sont distincts des objets statiques définis dans la définition externe :

inline const char *saddr(void) // la définition inline à utiliser dans ce fichier
{
    static const char name[] = "saddr";
    return name;
}

int compare_name(void)
{
    return saddr() == saddr(); // comportement non spécifié, un appel pourrait être externe
}

extern const char *saddr(void); // une définition externe est aussi générée

Un programme C ne doit pas dépendre de l'appel de la version inline ou de la version externe d'une fonction, sinon le comportement est non spécifié.

Mots-clés

inline

Notes

Le mot-clé inline a été repris de C++, mais en C++, si une fonction est déclarée inline, elle doit être déclarée inline dans chaque unité de traduction, et de plus chaque définition d'une fonction inline doit être exactement identique (en C, les définitions peuvent différer, et selon les différences cela ne produit qu'un comportement non spécifié). En revanche, C++ autorise les variables statiques locales non const, et toutes les variables statiques locales issues de différentes définitions d'une fonction inline sont identiques en C++ mais distinctes en C.

Exemple

En-tête « test.h »

#ifndef TEST_H_INCLUDED
#define TEST_H_INCLUDED

inline int sum(int a, int b)
{
    return a + b;
}

#endif

Fichier source « sum.c »

#include "test.h"

extern inline int sum(int a, int b); // fournit la définition externe

Fichier source « test1.c »

#include <stdio.h>
#include "test.h"

extern int f(void);

int main(void)
{
    printf("%d\n", sum(1, 2) + f());
}

Fichier source « test2.c »

#include "test.h"

int f(void)
{
    return sum(3, 4);
}
