Recherche de noms et espaces de noms

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Lorsqu'un identificateur est rencontré dans un programme C, une recherche est effectuée pour localiser la déclaration qui a introduit cet identificateur et qui est actuellement dans la portée. C permet à plusieurs déclarations pour un même identificateur d'être dans la portée simultanément si ces identificateurs appartiennent à des catégories différentes, appelées espaces de noms :

  1. Espace de noms des étiquettes : tous les identificateurs déclarés comme étiquettes.

  2. Noms de tags : tous les identificateurs déclarés comme noms de struct, union et types énumérés. Notez que les trois sortes de tags partagent un même espace de noms.

  3. Noms de membres : tous les identificateurs déclarés comme membres d'une même struct ou union. Chaque struct et union introduit son propre espace de noms de ce type.

  1. Espace de noms global des attributs : jetons d'attribut définis par la norme ou par les préfixes d'attributs définis par l'implémentation.

  2. Noms d'attributs non standard : noms d'attributs suivant les préfixes d'attributs. Chaque préfixe d'attribut possède un espace de noms distinct pour les attributs définis par l'implémentation qu'il introduit.

(depuis C23)

  1. Tous les autres identificateurs, appelés identificateurs ordinaires pour les distinguer de (1-5) (noms de fonctions, noms d'objets, noms de typedef, constantes d'énumération).

Au point de recherche, l'espace de noms d'un identificateur est déterminé par la manière dont il est utilisé :

  1. identificateur apparaissant comme opérande d'une instruction goto est recherché dans l'espace de noms des étiquettes.

  2. identificateur qui suit le mot-clé struct, union ou enum est recherché dans l'espace de noms des tags.

  3. identificateur qui suit l'accès à un membre ou l'opérateur d'accès à un membre via un pointeur est recherché dans l'espace de noms des membres du type déterminé par l'opérande gauche de l'opérateur d'accès au membre.

  1. identificateur qui apparaît directement dans un spécificateur d'attribut ([[...]]) est recherché dans l'espace de noms global des attributs.

  2. identificateur qui suit le jeton :: suivant un préfixe d'attribut est recherché dans l'espace de noms introduit par le préfixe d'attribut.

(depuis C23)

  1. tous les autres identificateurs sont recherchés dans l'espace de noms des identificateurs ordinaires.

Notes

Les noms de macros ne font partie d'aucun espace de noms, car ils sont remplacés par le préprocesseur avant l'analyse sémantique.

Il est courant d'injecter les noms de struct/union/enum dans l'espace de noms des identificateurs ordinaires à l'aide d'une déclaration typedef :

struct A { };       // introduit le nom A dans l'espace de noms des tags
typedef struct A A; // d'abord, la recherche de A après « struct » trouve un nom dans l'espace de noms des tags
                    // introduit ensuite le nom A dans l'espace de noms ordinaire
struct A* p;        // OK, ce A est recherché dans l'espace de noms des tags
A* q;               // OK, ce A est recherché dans l'espace de noms ordinaire

Un exemple bien connu de même identificateur utilisé dans deux espaces de noms est l'identificateur stat de l'en-tête POSIX sys/stat.h. Il désigne une fonction lorsqu'il est utilisé comme identificateur ordinaire et désigne une struct lorsqu'il est utilisé comme tag.

Contrairement au C++, les constantes d'énumération ne sont pas des membres de struct ; elles appartiennent à l'espace de noms des identificateurs ordinaires et, comme il n'existe pas de portée de struct en C, leur portée est celle dans laquelle la déclaration de struct apparaît :

struct tagged_union {
   enum {INT, FLOAT, STRING} type;
   union {
      int integer;
      float floating_point;
      char *string;
   };
} tu;

tu.type = INT; // OK en C, erreur en C++

Si un attribut standard, un préfixe d'attribut ou un nom d'attribut non standard n'est pas pris en charge, l'attribut invalide est ignoré sans provoquer d'erreur.

(depuis C23)

Exemple

void foo (void) { return; } // espace de noms ordinaire, portée de fichier
struct foo {      // espace de noms des étiquettes, portée de fichier
    int foo;      // espace de noms des membres pour cette struct foo, portée de fichier
    enum bar {    // espace de noms des étiquettes, portée de fichier
        RED       // espace de noms ordinaire, portée de fichier
    } bar;        // espace de noms des membres pour cette struct foo, portée de fichier
    struct foo* p; // OK : utilise le nom « foo » de la portée d'étiquette/de fichier
};
enum bar x; // OK : utilise bar de la portée d'étiquette/de fichier
// int foo; // Erreur : l'espace de noms ordinaire contient déjà foo dans la portée
//union foo { int a, b; }; // Erreur : foo est déjà présent dans l'espace de noms des étiquettes de la portée

int main(void)
{
    goto foo; // OK : utilise « foo » de l'espace de noms des étiquettes/portée de fonction

    struct foo { // espace de noms des étiquettes, portée de bloc (masque la portée de fichier)
       enum bar x; // OK : utilise « bar » de l'espace de noms des étiquettes/portée de fichier
    };
    typedef struct foo foo; // OK : utilise foo de l'espace de noms des étiquettes/portée de bloc
                            // définit foo ordinaire de portée de bloc (masque la portée de fichier)
    (foo){.x=RED}; // utilise foo ordinaire/de portée de bloc et RED ordinaire/de portée de fichier

foo:; // espace de noms des étiquettes, portée de fonction
}
