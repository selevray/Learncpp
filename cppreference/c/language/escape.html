Séquences d'échappement

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les séquences d'échappement servent à représenter certains caractères spéciaux dans les littéraux de chaîne et les constantes de caractère.

Les séquences d'échappement suivantes sont disponibles. L'ISO C exige un diagnostic si le backslash est suivi d'un caractère qui n'est pas listé ici :

Séquence
d'échappement | Description | Représentation

Séquences d'échappement simples

\' | apostrophe | octet 0x27 en codage ASCII

\" | guillemet double | octet 0x22 en codage ASCII

\? | point d'interrogation | octet 0x3f en codage ASCII

\\ | backslash | octet 0x5c en codage ASCII

\a | sonnerie (bell) | octet 0x07 en codage ASCII

\b | backspace | octet 0x08 en codage ASCII

\f | saut de page - nouvelle page | octet 0x0c en codage ASCII

\n | saut de ligne - nouvelle ligne | octet 0x0a en codage ASCII

\r | retour chariot | octet 0x0d en codage ASCII

\t | tabulation horizontale | octet 0x09 en codage ASCII

\v | tabulation verticale | octet 0x0b en codage ASCII

Séquences d'échappement numériques

\nnn | valeur octale arbitraire | unité de code nnn

\xn... | valeur hexadécimale arbitraire | unité de code n... (nombre arbitraire de chiffres hexadécimaux)

Noms de caractères universels

\unnnn (depuis C99) | Valeur Unicode dans la plage autorisée ;
peut donner lieu à plusieurs unités de code | point de code U+nnnn

\Unnnnnnnn (depuis C99) | Valeur Unicode dans la plage autorisée ;
peut donner lieu à plusieurs unités de code | point de code U+nnnnnnnn

Plage des noms de caractères universels

Si un nom universel de caractère correspond à un point de code qui n'est pas 0x24 ('$'), 0x40 ('@'), ni 0x60 ( '' ) et inférieur à 0xA0, ou à un point de code de substitution (la plage 0xD800-0xDFFF, bornes incluses), ou supérieur à 0x10FFFF, c'est-à-dire qui n'est pas un point de code Unicode *(depuis C23)*, le programme est mal formé. En d'autres termes, les membres de [l'ensemble de caractères source de base](translation_phases.html) et les caractères de contrôle (dans les plages 0x0-0x1Fet0x7F-0x9F`) ne peuvent pas être exprimés par des noms universels de caractères.

(depuis C99)

Notes

\0 est la séquence d'échappement octale la plus couramment utilisée, car elle représente le caractère nul de fin dans les chaînes terminées par un caractère nul.

Le caractère de saut de ligne \n a une signification particulière lorsqu'il est utilisé dans les E/S en mode texte : il est converti en l'octet ou la séquence d'octets de fin de ligne propre au système d'exploitation.

Les séquences d'échappement octales ont une limite de longueur de trois chiffres octaux, mais se terminent au premier caractère qui n'est pas un chiffre octal valide s'il est rencontré plus tôt.

Les séquences d'échappement hexadécimales n'ont pas de limite de longueur et se terminent au premier caractère qui n'est pas un chiffre hexadécimal valide. Si la valeur représentée par une seule séquence d'échappement hexadécimale ne rentre pas dans la plage de valeurs représentée par le type de caractère utilisé dans ce littéral de chaîne ou cette constante de caractère (char[, char8_t (depuis C23) | , char16_t, char32_t (depuis C11)], ou wchar_t), le résultat est non spécifié.

Un nom universel de caractère dans un littéral de chaîne étroit ou un littéral de chaîne 16 bits (depuis C11) peut correspondre à plusieurs unités de code, par ex. \U0001f34c représente 4 unités de code char en UTF-8 (\xF0\x9F\x8D\x8C)et 2 unités de code char16_t en UTF-16 (\xD83C\xDF4C) (depuis C11).

(depuis C99)

Un nom universel de caractère correspondant à un point de code supérieur à 0x10FFFF (qui n'est pas défini dans ISO/ISC 10646) peut être utilisé dans les constantes de caractère et les littéraux de chaîne. Cet usage n'est pas autorisé en C++20.

(depuis C99) (jusqu'à C23)

La séquence d'échappement du point d'interrogation \? sert à empêcher que les trigraphes ne soient interprétés à l'intérieur des littéraux de chaîne : une chaîne telle que "??/" est compilée comme "\", mais si le second point d'interrogation est échappé, comme dans "?\?/", elle devient "??/"

(jusqu'à C23)

Exemple

#include <stdio.h>

int main(void)
{
    printf("This\nis\na\ntest\n\nShe said, \"How are you?\"\n");
}

Output:

This
is
a
test

She said, "How are you?"
