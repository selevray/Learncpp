Littéraux composés (depuis C99)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Construit un objet sans nom du type spécifié (qui peut être une struct, une union, voire un type tableau) directement en place.

Syntaxe

| | | | ( storage-class-specifiers ﻿*(facultatif)* (depuis C23) type ) { initializer-list } | | (depuis C99) | | | ( storage-class-specifiers ﻿*(facultatif)* (depuis C23) type ) { initializer-list , } | | (depuis C99) | | | ( storage-class-specifiers ﻿*(facultatif)* type ) { } | | (depuis C23) | |

where

  • storage-class-specifiers — (depuis C23) Une liste de spécificateurs de classe de stockage ne pouvant contenir que constexpr, static, register ou thread_local
  • type — un nom de type désignant tout type objet complet ou un tableau de taille inconnue, mais pas un VLA
  • initializer-list — liste d'initialiseurs adaptée à l'initialisation d'un objet de type

Explication

L'expression de littéral composé construit un objet sans nom du type spécifié par type et l'initialise comme indiqué par initializer-list. Les initialiseurs désignés sont acceptés.

Le type du littéral composé est type (sauf lorsque type est un tableau de taille inconnue ; sa taille est déduite de initializer-list comme dans l'initialisation de tableau).

La catégorie de valeur d'un littéral composé est lvalue (son adresse peut être prise).

L'objet sans nom auquel le littéral composé est évalué a une durée de stockage statique si le littéral composé apparaît dans la portée de fichier, et une durée de stockage automatique s'il apparaît dans la portée de bloc (auquel cas la durée de vie de l'objet se termine à la fin du bloc englobant).

(jusqu'à C23)

Si le littéral composé est évalué en dehors du corps d'une fonction et en dehors de toute liste de paramètres, il est associé à la portée de fichier ; sinon, il est associé au bloc englobant. Selon cette association, les spécificateurs de classe de stockage (éventuellement vides), le nom de type et la liste d'initialiseurs, s'il y en a, doivent être des spécificateurs valides pour une définition d'objet en portée de fichier ou de bloc respectivement, de la forme suivante,

   storage-class-specifiers typeof(type) ID = { initializer-list };

où ID est un identifiant unique pour l'ensemble du programme. Un littéral composé fournit un objet sans nom dont la valeur, le type, la durée de stockage et les autres propriétés sont ceux qui seraient donnés par la syntaxe de définition ci-dessus ; si la durée de stockage est automatique, la durée de vie de l'instance de l'objet sans nom correspond à l'exécution courante du bloc englobant. Si les spécificateurs de classe de stockage contiennent d'autres spécificateurs que constexpr, static, register ou thread_local, le comportement est indéfini.

(depuis C23)

Notes

Les littéraux composés de types tableaux de caractères ou de caractères larges qualifiés const peuvent partager le stockage avec les littéraux de chaîne.

(const char []){"abc"} == "abc" // peut valoir 1 ou 0, non spécifié

Chaque littéral composé ne crée qu'un seul objet dans sa portée :

int f (void)
{
    struct s {int i;} *p = 0, *q;
    int j = 0;
again:
    q = p, p = &((struct s){ j++ });
    if (j < 2) goto again; // remarque ; si une boucle était utilisée, la portée se terminerait ici,
                           // ce qui mettrait fin à la durée de vie du littéral composé
                           // laissant p comme pointeur pendant
    return p == q && q->i == 1; // retourne toujours 1
}

Les littéraux composés étant sans nom, un littéral composé ne peut pas se référencer lui-même (une struct nommée peut contenir un pointeur vers elle-même)

Bien que la syntaxe d'un littéral composé ressemble à celle d'une conversion, la distinction importante est qu'une conversion est une expression non lvalue, alors qu'un littéral composé est une lvalue.

Exemple

#include <stdio.h>

int *p = (int[]){2, 4}; // crée un tableau statique sans nom de type int[2]
                        // initialise le tableau avec les valeurs {2, 4}
                        // crée le pointeur p pointant vers le premier élément de
                        // le tableau
const float *pc = (const float []){1e0, 1e1, 1e2}; // littéral composé en lecture seule

struct point {double x,y;};

int main(void)
{
    int n = 2, *p = &n;
    p = (int [2]){*p}; // crée un tableau automatique sans nom de type int[2]
                       // initialise le premier élément avec la valeur auparavant
                       // contenue dans *p
                       // initialise le second élément à zéro
                       // stocke l'adresse du premier élément dans p

    void drawline1(struct point from, struct point to);
    void drawline2(struct point *from, struct point *to);
    drawline1(
        (struct point){.x=1, .y=1},  // crée deux structures à portée de bloc et
        (struct point){.x=3, .y=4}); // appelle drawline1, en leur passant par valeur
    drawline2(
        &(struct point){.x=1, .y=1},  // crée deux structures à portée de bloc et
        &(struct point){.x=3, .y=4}); // appelle drawline2, en leur passant leurs adresses
}

void drawline1(struct point from, struct point to)
{
    printf("drawline1: `from` @ %p {%.2f, %.2f}, `to` @ %p {%.2f, %.2f}\n",
        (void*)&from, from.x, from.y, (void*)&to, to.x, to.y);
}

void drawline2(struct point *from, struct point *to)
{
    printf("drawline2: `from` @ %p {%.2f, %.2f}, `to` @ %p {%.2f, %.2f}\n",
        (void*)from, from->x, from->y, (void*)to, to->x, to->y);
}

Sortie possible :

drawline1: `from` @ 0x7ffd24facea0 {1.00, 1.00}, `to` @ 0x7ffd24face90 {3.00, 4.00}
drawline2: `from` @ 0x7ffd24facec0 {1.00, 1.00}, `to` @ 0x7ffd24faced0 {3.00, 4.00}
