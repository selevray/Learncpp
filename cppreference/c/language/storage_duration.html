Spécificateurs de classe de stockage

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Spécifient la durée de stockage et la liaison des objets et des fonctions :

  • auto - durée automatique et pas de liaison
  • register - durée automatique et pas de liaison ; l'adresse de cette variable ne peut pas être prise
  • static - durée statique et liaison interne (sauf à portée de bloc)
  • extern - durée statique et liaison externe (sauf si déjà déclaré interne)
  • [_Thread_local (jusqu'à C23) | thread_local (depuis C23)] - durée de stockage de thread

(depuis C11)

Explication

Les spécificateurs de classe de stockage apparaissent dans les déclarationset les expressions de littéral composé (depuis C23). Au plus un spécificateur peut être utilisé, sauf que [_Thread_local (jusqu'à C23) | thread_local (depuis C23)] peut être combiné avec static ou extern pour ajuster la liaison (depuis C11). Les spécificateurs de classe de stockage déterminent deux propriétés indépendantes des noms qu'ils déclarent : la durée de stockage et la liaison.

  1. Le spécificateur auto n'est autorisé que pour les objets déclarés à portée de bloc (sauf dans les listes de paramètres de fonction). Il indique une durée de stockage automatique et pas de liaison, qui sont les valeurs par défaut pour ce genre de déclarations.

  2. Le spécificateur register n'est autorisé que pour les objets déclarés à portée de bloc, y compris dans les listes de paramètres de fonction. Il indique une durée de stockage automatique et pas de liaison (qui est la valeur par défaut pour ce genre de déclarations), mais suggère en plus à l'optimiseur de stocker la valeur de cette variable dans un registre du processeur si possible. Qu'il y ait ou non cette optimisation, les variables déclarées register ne peuvent pas être utilisées comme arguments de l'opérateur d'adresse, ne peuvent pas utiliser [_Alignas (jusqu'à C23) | alignas (depuis C23)] (depuis C11), et les tableaux register ne sont pas convertibles en pointeurs.

  3. Le spécificateur static spécifie à la fois une durée de stockage statique(sauf combiné avec _Thread_local) (depuis C11) et une liaison interne (sauf si utilisé à portée de bloc). Il peut être utilisé avec des fonctions à portée de fichier et avec des variables à portée de fichier comme de bloc, mais pas dans les listes de paramètres de fonction.

  4. Le spécificateur extern spécifie une durée de stockage statique(sauf combiné avec [_Thread_local (jusqu'à C23) | thread_local (depuis C23)]) (depuis C11) et une liaison externe. Il peut être utilisé avec des déclarations de fonctions et d'objets à portée de fichier comme de bloc (hors listes de paramètres de fonction). Si extern apparaît dans une redéclaration d'un identifiant déjà déclaré avec une liaison interne, la liaison reste interne. Sinon (si la déclaration précédente était externe, sans liaison, ou n'est pas dans la portée), la liaison est externe.

  1. [_Thread_local (jusqu'à C23) | thread_local (depuis C23)] indique une durée de stockage de thread. Il ne peut pas être utilisé avec des déclarations de fonctions. S'il est utilisé dans la déclaration d'un objet, il doit figurer dans chaque déclaration du même objet. S'il est utilisé dans une déclaration à portée de bloc, il doit être combiné avec static ou extern pour déterminer la liaison.

(depuis C11)

Si aucun spécificateur de classe de stockage n'est fourni, les valeurs par défaut sont :

extern pour toutes les fonctionsextern pour les objets à portée de fichierauto pour les objets à portée de bloc

Pour toute struct ou union déclarée avec un spécificateur de classe de stockage, la durée de stockage (mais pas la liaison) s'applique récursivement à ses membres.

Les déclarations de fonctions à portée de bloc peuvent utiliser extern ou aucun spécificateur. Les déclarations de fonctions à portée de fichier peuvent utiliser extern ou static.

Les paramètres de fonction ne peuvent utiliser aucun spécificateur de classe de stockage autre que register. Notez que static a une signification particulière dans les paramètres de fonction de type tableau.

Durée de stockage

Chaque objet possède une propriété appelée durée de stockage, qui limite la durée de vie de l'objet. Il existe quatre types de durée de stockage en C :

  • Durée de stockage automatique. Le stockage est alloué lorsque le bloc dans lequel l'objet a été déclaré est entré, et désalloué lorsqu'on en sort par quelque moyen que ce soit (goto, return, fin du bloc). Une exception concerne les VLA ; leur stockage est alloué lorsque la déclaration est exécutée, et non à l'entrée du bloc, et désalloué lorsque la déclaration sort de sa portée, et non lorsque le bloc est quitté (depuis C99). Si le bloc est entré récursivement, une nouvelle allocation est effectuée pour chaque niveau de récursion. Tous les paramètres de fonction et les objets non-static à portée de bloc ont cette durée de stockage, ainsi que les littéraux composés utilisés à portée de bloc (jusqu'à C23)
  • Durée de stockage statique. La durée de stockage correspond à toute l'exécution du programme, et la valeur stockée dans l'objet n'est initialisée qu'une seule fois, avant la fonction main. Tous les objets déclarés static et tous les objets ayant une liaison interne ou externequi ne sont pas déclarés [_Thread_local (jusqu'à C23) | thread_local (depuis C23)] (depuis C11) ont cette durée de stockage.
  • Durée de stockage thread. La durée de stockage correspond à toute l'exécution du thread dans lequel l'objet a été créé, et la valeur stockée dans l'objet est initialisée au démarrage du thread. Chaque thread possède son propre objet, distinct. Si le thread qui exécute l'expression accédant à cet objet n'est pas celui qui a exécuté son initialisation, le comportement est défini par l'implémentation. Tous les objets déclarés [_Thread_local (jusqu'à C23) | thread_local (depuis C23)] ont cette durée de stockage.

(depuis C11)

  • Durée de stockage allouée. Le stockage est alloué et désalloué sur demande, à l'aide des fonctions d'allocation dynamique de mémoire.

Liaison

La liaison désigne la capacité d'un identifiant (variable ou fonction) à être référencé dans d'autres portées. Si une variable ou une fonction portant le même identifiant est déclarée dans plusieurs portées, sans pouvoir être référencée depuis toutes, alors plusieurs instances de la variable sont générées. Les liaisons suivantes sont reconnues :

  • Absence de liaison. La variable ou la fonction ne peut être référencée que depuis la portée dans laquelle elle se trouve (portée de bloc). Toutes les variables à portée de bloc qui ne sont pas déclarées extern ont cette liaison, ainsi que tous les paramètres de fonction et tous les identifiants qui ne sont ni des fonctions ni des variables.

  • Liaison interne. La variable ou la fonction peut être référencée depuis toutes les portées de l'unité de traduction courante. Toutes les variables à portée de fichier déclarées static ou constexpr (depuis C23) ont cette liaison, ainsi que toutes les fonctions à portée de fichier déclarées static (les déclarations de fonctions statiques ne sont autorisées qu'à portée de fichier).

  • Liaison externe. La variable ou la fonction peut être référencée depuis toutes les autres unités de traduction du programme entier. Toutes les variables à portée de fichier qui ne sont pas déclarées staticou constexpr (depuis C23) ont cette liaison, de même que toutes les déclarations de fonctions à portée de fichier qui ne sont pas déclarées static, toutes les déclarations de fonctions à portée de bloc et, en outre, toutes les variables ou fonctions déclarées extern, sauf si une déclaration antérieure à liaison interne est visible à cet endroit.

Si le même identifiant apparaît à la fois avec une liaison interne et une liaison externe dans la même unité de traduction, le comportement est indéfini. Cela est possible lorsque des définitions provisoires sont utilisées.

Les déclarations à liaison externe sont couramment rendues disponibles dans des fichiers d'en-tête, afin que toutes les unités de traduction qui #include le fichier puissent référencer le même identifiant, défini ailleurs.

Toute déclaration à liaison interne figurant dans un fichier d'en-tête produit un objet distinct dans chaque unité de traduction qui inclut ce fichier.

Interface de la bibliothèque, fichier d'en-tête « flib.h » :

#ifndef FLIB_H
#define FLIB_H
void f(void);              // déclaration de fonction à liaison externe
extern int state;          // déclaration de variable à liaison externe
static const int size = 5; // définition d'une variable en lecture seule à liaison interne
enum { MAX = 10 };         // définition de constante
inline int sum (int a, int b) { return a + b; } // définition de fonction inline
#endif // FLIB_H

Implémentation de la bibliothèque, fichier source « flib.c » :

#include "flib.h"

static void local_f(int s) {} // définition à liaison interne (utilisée uniquement dans ce fichier)
static int local_state;       // définition à liaison interne (utilisée uniquement dans ce fichier)

int state;                       // définition à liaison externe (utilisée par main.c)
void f(void) { local_f(state); } // définition à liaison externe (utilisée par main.c)

Code de l'application, fichier source « main.c » :

#include "flib.h"

int main(void)
{
    int x[MAX] = {size}; // utilise la constante et la variable en lecture seule
    state = 7;           // modifie l'état dans flib.c
    f();                 // appelle f() dans flib.c
}

Mots-clés

auto, register, static, extern, _Thread_local thread_local

Notes

Le mot-clé _Thread_local est généralement utilisé par l'intermédiaire de la macro pratique thread_local, définie dans l'en-tête <threads.h>.

(jusqu'à C23)

Les spécificateurs typedefet constexpr (depuis C23) sont formellement listés comme spécificateurs de classe de stockage dans la grammaire du langage C, mais ils ne spécifient aucun stockage.

Le spécificateur auto est également utilisé pour l'inférence de type.

(depuis C23)

Les noms à portée de fichier qui sont const et non extern ont une liaison externe en C (par défaut pour toutes les déclarations à portée de fichier), mais une liaison interne en C++.

Exemple

#include <stdio.h>
#include <stdlib.h>

// durée de stockage statique
int A;

int main(void)
{
    printf("&A = %p\n", (void*)&A);

    // durée de stockage automatique
    int A = 1;   // masque le global A
    printf("&A = %p\n", (void*)&A);

    // durée de stockage allouée
    int* ptr_1 = malloc(sizeof(int));   // début de la durée de stockage allouée
    printf("address of int in allocated memory = %p\n", (void*)ptr_1);
    free(ptr_1);                        // fin de la durée de stockage allouée
}

Sortie possible :

&A = 0x600ae4
&A = 0x7ffefb064f5c
address of int in allocated memory = 0x1f28c30
