Attribut C : unsequenced, reproducible (depuis C23)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Fournit au compilateur des informations sur l'accès aux objets par une fonction, permettant de déduire certaines propriétés des appels de fonction.

Syntaxe

| | | | [[ unsequenced ]] [[ __unsequenced__ ]] | (1) | | | | [[ reproducible ]] [[ __reproducible__ ]] | (2) | | |

  1. indique qu'une fonction est sans effet, idempotente, sans état et indépendante.

  2. indique qu'une fonction est sans effet et idempotente.

Explication

Ces attributs s'appliquent à un déclarateur de fonction ou à un spécificateur de type ayant un type fonction. L'attribut correspondant est une propriété du type fonction.

Sans effet

Une évaluation d'un appel de fonction est sans effet si toute opération d'écriture séquencée pendant l'appel est la modification d'un objet qui se synchronise avec l'appel ; si de plus l'opération est observable, tout accès à l'objet doit être fondé sur un paramètre pointeur unique de la fonction.

Idempotent

Une évaluation E est idempotente si une seconde évaluation de E peut être séquencée immédiatement après la première sans modifier la valeur résultante, le cas échéant, ni l'état observable de l'exécution.

Sans état

Une fonction F est sans état si toute définition d'un objet à durée de stockage statique ou thread durée de stockage dans F ou dans une fonction appelée par F est const mais non qualifiée volatile.

Indépendant

Une fonction F est indépendante si pour tout objet X observé par un appel à F au moyen d'une lvalue non fondée sur un paramètre de l'appel, tous les accès à X dans tous les appels à F durant la même exécution du programme observent la même valeur ; sinon, si l'accès est fondé sur un paramètre pointeur, il doit exister un unique tel paramètre pointeur P tel que tout accès à X soit une lvalue fondée sur P.

Un objet X est observé par un appel de fonction si les deux se synchronisent, si X n'est pas local à l'appel, si X a une durée de vie commençant avant l'appel de fonction, et si un accès à X est séquencé pendant l'appel ; la dernière valeur de X, le cas échéant, enregistrée avant l'appel est dite être la valeur de X observée par l'appel.

Notes

Ces attributs existent dans le but d'optimiser la compilation.

Si une fonction est reproductible, plusieurs appels successifs peuvent être traités comme un seul appel.

Si une fonction est unsequenced, plusieurs appels successifs peuvent être traités comme un seul appel, et les appels peuvent être parallélisés et réordonnés arbitrairement.
