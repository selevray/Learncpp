Effectue une conversion de type explicite

Syntaxe

| | | | ( type-name ) expression | | | |

where

  • type-name — soit le type void, soit tout type scalaire
  • expression — toute expression de type scalaire (sauf si type-name est void, auquel cas elle peut être quelconque)

Explication

Si type-name est void, alors expression est évaluée pour ses effets de bord et sa valeur de retour est ignorée, comme lorsque expression est utilisée seule, en tant qu'instruction d'expression.

Sinon, si type-name est exactement du type de expression, rien n'est fait (sauf si expression est de type flottant et est représentée avec une plage et une précision supérieures à celles indiquées par son type -- voir ci-dessous)

Sinon, la valeur de expression est convertie vers le type désigné par type-name, de la manière suivante :

Toute conversion implicite comme lors d'une affectation est autorisée.

En plus des conversions implicites, les conversions suivantes sont autorisées :

  • Tout entier peut être converti en tout type de pointeur. Sauf pour les constantes de pointeur nul telles que NULL (qui n'ont pas besoin de conversion), le résultat est défini par l'implémentation, peut ne pas être correctement aligné, peut ne pas pointer vers un objet du type référencé, et peut être une représentation piège.
  • Tout type de pointeur peut être converti en tout type entier. Le résultat est défini par l'implémentation, même pour les valeurs de pointeur nul (elles ne donnent pas nécessairement la valeur zéro). Si le résultat ne peut pas être représenté dans le type cible, le comportement est indéfini (les entiers non signés n'implémentent pas l'arithmétique modulo lors d'une conversion depuis un pointeur)
  • Tout pointeur vers un objet peut être converti en tout autre pointeur vers un objet. Si la valeur n'est pas correctement alignée pour le type cible, le comportement est indéfini. Sinon, si la valeur est reconvertie dans le type d'origine, elle est égale à la valeur d'origine. Si un pointeur vers un objet est converti en pointeur vers un type caractère quelconque, le résultat pointe vers l'octet de plus faible adresse de l'objet et peut être incrémenté jusqu'à sizeof du type cible (autrement dit, il peut servir à examiner la représentation d'objet ou à en faire une copie via memcpy ou memmove).
  • Tout pointeur vers une fonction peut être converti en pointeur vers tout autre type de fonction. Si le pointeur résultant est reconverti dans le type d'origine, il est égal à la valeur d'origine. Si le pointeur converti est utilisé pour effectuer un appel de fonction, le comportement est indéfini (sauf si les types de fonction sont compatibles)
  • Lors d'une conversion entre pointeurs (objet ou fonction), si la valeur d'origine est une valeur de pointeur nul de son type, le résultat est la valeur de pointeur nul correcte pour le type cible.

Dans tous les cas (qu'il s'agisse d'une conversion implicite ou d'une conversion vers le même type), si expression et type-name sont des types flottants et que expression est représentée avec une plage et une précision supérieures à celles indiquées par son type (voir FLT_EVAL_METHOD), la plage et la précision sont supprimées pour correspondre au type cible.

La catégorie de valeur de l'expression de conversion est toujours non-lvalue.

Notes

Comme les qualificateurs const, volatile, restrict et _Atomic n'ont d'effet que sur les lvalues, une conversion vers un type qualifié cvr ou atomique est exactement équivalente à la conversion vers le type non qualifié correspondant.

La conversion vers void est parfois utile pour faire taire les avertissements du compilateur concernant les résultats inutilisés.

Les conversions non listées ici ne sont pas autorisées. En particulier,

  • il n'existe aucune conversion entre pointeurs et types flottants
  • il n'existe aucune conversion entre pointeurs vers des fonctions et pointeurs vers des objets (y compris void*)

Si l'implémentation fournit intptr_t et/ou uintptr_t, alors une conversion depuis un pointeur vers un type objet (y compris cv void) vers ces types est toujours bien définie. Ce n'est toutefois pas garanti pour un pointeur de fonction.

(depuis C99)

Notez que les conversions entre pointeurs de fonctions et pointeurs d'objets sont acceptées comme extensions par de nombreux compilateurs, et attendues par certains usages de la fonction POSIX dlsym().

Exemple

#include <stdio.h>

int main(void)
{
    // examiner la représentation d'objet est un usage légitime de la conversion
    double d = 3.14;
    printf("The double %.2f (%a) is: ", d, d);
    for (size_t n = 0; n < sizeof d; ++n)
        printf("0x%02x ", ((unsigned char*)&d)[n]);

    // cas limites
    struct S { int x; } s;
//    (struct S)s; // erreur ; ce n'est pas un type scalaire
                   // bien que la conversion vers le même type ne fasse rien
    (void)s; // il est permis de convertir n'importe quel type en void
}

Sortie possible :

The double 3.14 (0x1.91eb851eb851fp+1) is: 0x1f 0x85 0xeb 0x51 0xb8 0x1e 0x09 0x40
