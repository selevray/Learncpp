Initialisation de tableau

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Lors de l'initialisation d'un objet de type tableau, l'initialiseur doit être soit un littéral de chaîne (éventuellement entouré d'accolades), soit une liste entre accolades d'initialiseurs pour les membres du tableau :

| | | | = string-literal | (1) | | | | = { expression , ... } | (2) | (jusqu'à C99) | | | = { designator(optionnel) expression , ... } | (2) | (depuis C99) | | | = { } | (3) | (depuis C23) | |

  1. initialiseur par littéral de chaîne pour les tableaux de caractères et de caractères larges

  2. liste séparée par des virgules d'expressions constantes (jusqu'à C99) servant d'initialiseurs pour les éléments du tableau, utilisant éventuellement des désignateurs de tableau de la forme [ constant-expression ] = (depuis C99)

  3. l'initialiseur vide initialise à vide chaque élément du tableau

Les tableaux de taille connue et de taille inconnue peuvent être initialisés, mais pas les VLA (depuis C99) (jusqu'à C23).Un VLA ne peut être initialisé que vide. (depuis C23)

Tous les éléments du tableau qui ne sont pas initialisés explicitement sont initialisés à vide.

Initialisation à partir de chaînes

Un littéral de chaîne (éventuellement entouré d'accolades) peut être utilisé comme initialiseur d'un tableau de type correspondant :

  • les littéraux de chaîne ordinaireset les littéraux de chaîne UTF-8 (depuis C11) peuvent initialiser des tableaux de n'importe quel type de caractère (char, signed char, unsigned char)
  • les littéraux de chaîne larges préfixés par L peuvent être utilisés pour initialiser des tableaux de tout type compatible avec (sans tenir compte des qualificateurs cv) wchar_t
  • les littéraux de chaîne larges préfixés par u peuvent être utilisés pour initialiser des tableaux de tout type compatible avec (sans tenir compte des qualificateurs cv) char16_t
  • les littéraux de chaîne larges préfixés par U peuvent être utilisés pour initialiser des tableaux de tout type compatible avec (sans tenir compte des qualificateurs cv) char32_t

(depuis C11)

Les octets successifs du littéral de chaîne ou les caractères larges du littéral de chaîne large, y compris l'octet ou caractère nul terminal, initialisent les éléments du tableau :

char str[] = "abc"; // str a le type char[4] et contient 'a', 'b', 'c', '\0'
wchar_t wstr[4] = L"猫"; // str a le type wchar_t[4] et contient L'猫', '\0', '\0', '\0'

Si la taille du tableau est connue, elle peut être inférieure d'une unité à celle du littéral de chaîne, auquel cas le caractère nul terminal est ignoré :

char str[3] = "abc"; // str a le type char[3] et contient 'a', 'b', 'c'

Notez que le contenu d'un tel tableau est modifiable, contrairement à l'accès direct à un littéral de chaîne avec char* str = "abc";.

Initialisation à partir de listes entre accolades

Lorsqu'un tableau est initialisé avec une liste entre accolades d'initialiseurs, le premier initialiseur de la liste initialise l'élément d'indice zéro(sauf si un désignateur est spécifié) (depuis C99), et chaque initialiseur suivant sans désignateur *(depuis C99)*initialise l'élément d'indice supérieur d'un à celui initialisé par l'initialiseur précédent.

int x[] = {1,2,3}; // x a le type int[3] et contient 1,2,3
int y[5] = {1,2,3}; // y a le type int[5] et contient 1,2,3,0,0
int z[4] = {1}; // z a le type int[4] et contient 1,0,0,0
int w[3] = {0}; // w a le type int[3] et contient uniquement des zéros

Il est une erreur de fournir plus d'initialiseurs que d'éléments lors de l'initialisation d'un tableau de taille connue (sauf lors de l'initialisation de tableaux de caractères à partir de littéraux de chaîne).

Un désignateur fait que l'initialiseur suivant initialise l'élément de tableau décrit par le désignateur. L'initialisation se poursuit ensuite dans l'ordre, à partir de l'élément suivant celui décrit par le désignateur.

int n[5] = {[4]=5,[0]=1,2,3,4}; // holds 1,2,3,4,5

int a[MAX] = { // commence l'initialisation a[0] = 1, a[1] = 3, ...
    1, 3, 5, 7, 9, [MAX-5] = 8, 6, 4, 2, 0
};
// pour MAX=6, le tableau contient 1,8,6,4,2,0
// pour MAX=13, le tableau contient 1,3,5,7,9,0,0,0,8,6,4,2,0 (« tableau clairsemé »)

(depuis C99)

Lors de l'initialisation d'un tableau de taille inconnue, le plus grand indice pour lequel un initialiseur est spécifié détermine la taille du tableau déclaré.

Tableaux imbriqués

Si les éléments d'un tableau sont des tableaux, des structs ou des unions, les initialiseurs correspondants dans la liste entre accolades d'initialiseurs sont tous les initialiseurs valides pour ces membres, sauf que leurs accolades peuvent être omises comme suit :

Si l'initialiseur imbriqué commence par une accolade ouvrante, tout l'initialiseur imbriqué jusqu'à son accolade fermante initialise l'élément de tableau correspondant :

int y[4][3] = { // tableau de 4 tableaux de 3 int chacun (matrice 4x3)
    { 1 },      // ligne 0 initialisée à {1, 0, 0}
    { 0, 1 },   // ligne 1 initialisée à {0, 1, 0}
    { [2]=1 },  // ligne 2 initialisée à {0, 0, 1}
};              // ligne 3 initialisée à {0, 0, 0}

Si l'initialiseur imbriqué ne commence pas par une accolade ouvrante, seuls assez d'initialiseurs de la liste sont pris en compte pour les éléments ou membres du sous-tableau, struct ou union ; les initialiseurs restants servent à initialiser l'élément de tableau suivant :

int y[4][3] = {    // tableau de 4 tableaux de 3 int chacun (matrice 4x3)
1, 3, 5, 2, 4, 6, 3, 5, 7 // ligne 0 initialisée à {1, 3, 5}
};                        // ligne 1 initialisée à {2, 4, 6}
                          // ligne 2 initialisée à {3, 5, 7}
                          // ligne 3 initialisée à {0, 0, 0}

struct { int a[3], b; } w[] = { { 1 }, 2 }; // tableau de structures
   // { 1 } est considéré comme un initialisateur entièrement entre accolades pour l'élément #0 du tableau
   // cet élément est initialisé à { {1, 0, 0}, 0}
   // 2 est considéré comme le premier initialisateur de l'élément #1 du tableau
   // cet élément est initialisé à { {2, 0, 0}, 0}

Les désignateurs de tableau peuvent être imbriqués ; l'expression constante entre crochets pour les tableaux imbriqués suit l'expression constante entre crochets du tableau externe :

int y[4][3] = {[0][0]=1, [1][1]=1, [2][0]=1};  // ligne 0 initialisée à {1, 0, 0}
                                               // ligne 1 initialisée à {0, 1, 0}
                                               // ligne 2 initialisée à {1, 0, 0}
                                               // ligne 3 initialisée à {0, 0, 0}

(depuis C99)

Notes

L'ordre d'évaluation des sous-expressions dans un initialisateur de tableau est indéterminément séquencé en C (mais pas en C++ depuis C++11) :

int n = 1;
int a[2] = {n++, n++}; // comportement non spécifié, mais bien défini,
                       // n est incrémenté deux fois (dans un ordre arbitraire)
                       // a initialisé à {1, 2} et à {2, 1} sont tous deux valides
puts((char[4]){'0'+n} + n++); // comportement indéfini :
                              // l'incrémentation et la lecture de n sont non séquencées

En C, la liste entre accolades d'un initialisateur ne peut pas être vide. C++ autorise la liste vide :

(jusqu'à C23)

Un initialisateur vide peut être utilisé pour initialiser un tableau :

(depuis C23)

int a[3] = {0}; // façon valide en C et en C++ de mettre à zéro un tableau à portée de bloc
int a[3] = {}; // façon valide en C++ de mettre à zéro un tableau à portée de bloc ; valide en C depuis C23

Comme pour toute autre initialisation, chaque expression de la liste d'initialisation doit être une expression constante lors de l'initialisation de tableaux de durée de stockage statique ou thread_local :

static char* p[2] = {malloc(1), malloc(2)}; // error

Exemple

int main(void)
{
    // Les quatre déclarations de tableau suivantes sont identiques
    short q1[4][3][2] = {
        { 1 },
        { 2, 3 },
        { 4, 5, 6 }
    };

    short q2[4][3][2] = {1, 0, 0, 0, 0, 0, 2, 3, 0, 0, 0, 0, 4, 5, 6};

    short q3[4][3][2] = {
        {
            { 1 },
        },
        {
            { 2, 3 },
        },
        {
            { 4, 5 },
            { 6 },
        }
    };

    short q4[4][3][2] = {1, [1]=2, 3, [2]=4, 5, 6};

    // Des noms de caractères peuvent être associés à des constantes d'énumération
    // utilisation de tableaux avec des désignateurs :
    enum { RED, GREEN, BLUE };
    const char *nm[] = {
        [RED] = "red",
        [GREEN] = "green",
        [BLUE] = "blue",
    };
}
