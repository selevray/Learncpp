Déclarations

Une déclaration est une construction du langage C qui introduit un ou plusieurs identifiants dans le programme et spécifie leur signification et leurs propriétés.

Les déclarations peuvent apparaître dans toute portée. Chaque déclaration se termine par un point-virgule (comme une instruction) et se compose de [deux (jusqu'à C23) | trois (depuis C23)] parties distinctes :

| | | | specifiers-and-qualifiers declarators-and-initializers ﻿*(facultatif)* ; | (1) | | | | attr-spec-seq specifiers-and-qualifiers declarators-and-initializers ; | (2) | (depuis C23) | | | attr-spec-seq ; | (3) | (depuis C23) | |

where

  • specifiers-and-qualifiers — liste séparée par des espaces, dans n'importe quel ordre,
    • spécificateurs de type :
      • void
      • le nom d'un type arithmétique
      • le nom d'un type atomique
      • un nom précédemment introduit par une déclaration typedef
      • un spécificateur struct, union ou enum
      • un spécificateur typeof (depuis C23)
    • zéro ou un spécificateur de classe de stockage : typedef, constexpr, auto, register, static, extern, _Thread_local
    • zéro ou plusieurs qualificateurs de type : const, volatile, restrict, _Atomic
    • (uniquement lors de la déclaration de fonctions), zéro ou plusieurs spécificateurs de fonction : inline, _Noreturn
    • zéro ou plusieurs spécificateurs d'alignement : [_Alignas (depuis C11) (jusqu'à C23) | alignas (depuis C23)]
  • declarators-and-initializers — liste séparée par des virgules de declarators (chaque déclarateur fournit des informations de type supplémentaires et/ou l'identifiant à déclarer). Les déclarateurs peuvent être accompagnés d'initialiseurs. Les déclarations enum, struct et union peuvent omettre declarators, auquel cas elles n'introduisent que les constantes d'énumération et/ou les étiquettes.
  • attr-spec-seq — (C23) liste facultative d'attributs, appliqués aux entités déclarées, ou forme une déclaration d'attribut si elle apparaît seule.

1,2) Déclaration simple. Introduit un ou plusieurs identifiants qui désignent des objets, des fonctions, des étiquettes struct/union/enum, des typedef ou des constantes d'énumération.

  1. Déclaration d'attribut. Ne déclare aucun identifiant et a une signification définie par l'implémentation si celle-ci n'est pas spécifiée par la norme.

Par exemple,

int a, *b=NULL; // "int" est le spécificateur de type,
                // "a" est un déclarateur
                // "*b" est un déclarateur et NULL est son initialiseur
const int *f(void); // "int" est le spécificateur de type
                    // « const » est le qualificateur de type
                    // « *f(void) » est le déclarateur
enum COLOR {RED, GREEN, BLUE} c; // « enum COLOR {RED, GREEN, BLUE} » est le spécificateur de type
                                 // « c » est le déclarateur

Le type de chaque identifiant introduit dans une déclaration est déterminé par une combinaison du type spécifié par type specifier et des modifications de type appliquées par ses declarator. Le type d'une variable peut aussi être déduit si le spécificateur auto est utilisé. (depuis C23)

Les attributs (depuis C23) peuvent apparaître dans specifiers-and-qualifiers, auquel cas ils s'appliquent au type déterminé par les spécificateurs précédents.

Déclarateurs

Chaque déclarateur est l'un des suivants :

identifier attr-spec-seq ﻿*(facultatif)* | (1)

( declarator ) | (2)

* attr-spec-seq ﻿*(optionnel)* qualifiers ﻿*(optionnel)* declarator | (3)

noptr-declarator [ static(facultatif) qualifiers ﻿*(facultatif)* expression ]

noptr-declarator [ qualifiers ﻿*(facultatif)* * ]

| (4)

noptr-declarator ( parameters-or-identifiers ) | (5)

  1. l'identifiant que ce déclarateur introduit.

  2. tout déclarateur peut être entouré de parenthèses ; cela est requis pour introduire des pointeurs vers des tableaux et des pointeurs vers des fonctions.

  3. déclarateur de pointeur : la déclaration S * cvr D; déclare D comme un pointeur qualifié cvr vers le type déterminé par S.

  4. déclarateur de tableau : la déclaration S D[N] déclare D comme un tableau de N objets du type déterminé par S. noptr-declarator est tout autre déclarateur, à l'exception du déclarateur de pointeur non parenthésé.

  5. déclarateur de fonction : la déclaration S D(params) déclare D comme une fonction prenant les paramètres params et retournant S. noptr-declarator est tout autre déclarateur, à l'exception du déclarateur de pointeur non parenthésé.

La logique derrière cette syntaxe est que, lorsque l'identifiant déclaré par le déclarateur apparaît dans une expression de la même forme que le déclarateur, il aurait le type spécifié par la séquence de spécificateurs de type.

struct C
{
    int member; // "int" est le spécificateur de type
                // « member » est le déclarateur
} obj, *pObj = &obj;
// « struct C { int member; } » est le spécificateur de type
// le déclarateur « obj » définit un objet de type struct C
// le déclarateur « *pObj » déclare un pointeur vers C,
// l'initialiseur « = &obj » fournit la valeur initiale de ce pointeur

int a = 1, *p = NULL, f(void), (*pf)(double);
// le spécificateur de type est « int »
// le déclarateur « a » définit un objet de type int
//   l'initialiseur « =1 » fournit sa valeur initiale
// le déclarateur « *p » définit un objet de type pointeur vers int
//   l'initialiseur « =NULL » fournit sa valeur initiale
// le déclarateur « f(void) » déclare une fonction prenant void et renvoyant int
// le déclarateur « (*pf)(double) » définit un objet de type pointeur
//   vers une fonction prenant double et renvoyant int

int (*(*foo)(double))[3] = NULL;
// le spécificateur de type est int
// 1. le déclarateur « (*(*foo)(double))[3] » est un déclarateur de tableau :
//    le type déclaré est « /déclarateur imbriqué/ tableau de 3 int »
// 2. le déclarateur imbriqué est « *(*foo)(double)) », qui est un déclarateur de pointeur
//    le type déclaré est « /déclarateur imbriqué/ pointeur vers tableau de 3 int »
// 3. le déclarateur imbriqué est « (*foo)(double) », qui est un déclarateur de fonction
//    le type déclaré est « /déclarateur imbriqué/ fonction prenant double et renvoyant
//        pointeur vers tableau de 3 int »
// 4. le déclarateur imbriqué est « (*foo) », qui est un déclarateur de pointeur (entre parenthèses, comme l'exige
//        la syntaxe des déclarateurs de fonction).
//    le type déclaré est « /déclarateur imbriqué/ pointeur vers fonction prenant double
//        et renvoyant pointeur vers tableau de 3 int »
// 5. le déclarateur imbriqué est « foo », qui est un identifiant.
// La déclaration introduit l'identifiant « foo » pour désigner un objet de type
// « pointeur vers fonction prenant double et renvoyant pointeur vers tableau de 3 int »
// L'initialiseur « = NULL » fournit la valeur initiale de ce pointeur.

// Si « foo » est utilisé dans une expression de la forme du déclarateur, son type serait
// int.
int x = (*(*foo)(1.2))[0];

La fin de chaque déclarateur qui ne fait pas partie d'un autre déclarateur est un point de séquence.

Dans tous les cas, attr-spec-seq est une séquence facultative d'attributs (depuis C23) . Lorsqu'elle apparaît immédiatement après l'identifiant, elle s'applique à l'objet ou à la fonction déclaré.

Définitions

Une définition est une déclaration qui fournit toutes les informations sur les identifiants qu'elle déclare.

Toute déclaration d'un enum ou d'un typedef est une définition.

Pour les fonctions, une déclaration incluant le corps de la fonction est une définition de fonction :

int foo(double); // declaration
int foo(double x) { return x; } // definition

Pour les objets, une déclaration qui alloue un espace de stockage (automatique ou statique, mais pas extern) est une définition, tandis qu'une déclaration qui n'alloue pas d'espace de stockage (déclaration externe) n'en est pas une.

extern int n; // declaration
int n = 10; // definition

Pour les struct et les union, les déclarations qui spécifient la liste des membres sont des définitions :

struct X; // declaration
struct X { int n; }; // definition

Redéclaration

Une déclaration ne peut pas introduire un identifiant si une autre déclaration du même identifiant apparaît plus tôt dans la même portée, sauf que

  • Les déclarations d'objets avec liaison (externe ou interne) peuvent être répétées :
extern int x;
int x = 10; // OK
extern int x; // OK

static int n;
static int n = 10; // OK
static int n; // OK
  • Un typedef non VLA peut être répété tant qu'il désigne le même type :
typedef int int_t;
typedef int int_t; // OK
  • Les déclarations struct et union peuvent être répétées :
struct X;
struct X { int n; };
struct X;

Ces règles simplifient l'utilisation des fichiers d'en-tête.

Notes

En C89, les déclarations à l'intérieur de toute instruction composée (portée de bloc) doivent apparaître au début du bloc, avant toute instruction.

De plus, en C89, les fonctions retournant int peuvent être déclarées implicitement par l'opérateur d'appel de fonction, et les paramètres de fonction de type int n'ont pas besoin d'être déclarés lors de l'utilisation de définitions de fonctions à l'ancienne.

(jusqu'à C99)

Les déclarateurs vides sont interdits ; une déclaration simple doit avoir au moins un déclarateur, ou déclarer au moins une étiquette struct/union/enum, ou introduire au moins une constante d'énumération.

Si une partie d'un déclarateur est un déclarateur de tableau de longueur variable (VLA), le type de l'ensemble du déclarateur est appelé « type à modification variable ». Les types définis à partir de types à modification variable sont également à modification variable (VM).

Les déclarations de types à modification variable ne peuvent apparaître qu'en portée de bloc ou en portée de prototype de fonction, et ne peuvent pas être membres de struct ou d'union. Bien qu'un VLA ne puisse avoir qu'une durée de stockage automatique ou allouée, un type VM tel qu'un pointeur vers un VLA peut être statique. D'autres restrictions s'appliquent à l'utilisation des types VM, voir goto, switch. longjmp

(depuis C99)

Les static_asserts sont considérés comme des déclarations du point de vue de la grammaire C (ils peuvent donc apparaître partout où une déclaration peut apparaître), mais ils n'introduisent aucun identifiant et ne suivent pas la syntaxe des déclarations.

(depuis C11)

Les déclarations d'attribut sont également considérées comme des déclarations (elles peuvent donc apparaître partout où une déclaration peut apparaître), mais elles n'introduisent aucun identifiant. Un simple ; sans attr-spec-seq n'est pas une déclaration d'attribut, mais une instruction.

(depuis C23)
