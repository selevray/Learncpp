Littéraux de chaîne

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Construit un objet anonyme du type tableau de caractères spécifié, sur place ; utilisé lorsqu'une chaîne de caractères doit être intégrée dans le code source.

Syntaxe

| | | | " s-char-sequence " | (1) | | | | u8" s-char-sequence " | (2) | (depuis C11) | | | u" s-char-sequence " | (3) | (depuis C11) | | | U" s-char-sequence " | (4) | (depuis C11) | | | L" s-char-sequence " | (5) | | |

where

  • s-char-sequence — zéro caractère ou plus, chacun étant soit un caractère multioctet du jeu de caractères source (à l'exclusion de ("), \ et du saut de ligne), soit un échappement de caractère, un échappement hexadécimal, un échappement octal, ou un nom universel de caractère (depuis C99) tels que définis dans séquences d'échappement.

  1. littéral de chaîne de caractères : le type du littéral est char[N], où N est la taille de la chaîne en unités de code du encodage étroit d'exécution, y compris le terminateur nul. Chaque élément char du tableau est initialisé à partir du caractère suivant de s-char-sequence en utilisant le jeu de caractères d'exécution.

  2. littéral de chaîne UTF-8 : le type du littéral est [char[N] (jusqu'à C23) | char8_t[N] (depuis C23)], où N est la taille de la chaîne en unités de code UTF-8, y compris le terminateur nul. Chaque [char (jusqu'à C23) | char8_t (depuis C23)] élément du tableau est initialisé à partir du caractère multioctet suivant de s-char-sequence en utilisant l'encodage UTF-8.

  1. littéral de chaîne large 16 bits : le type du littéral est char16_t[N], où N est la taille de la chaîne en unités de code d'un encodage 16 bits défini par l'implémentation (typiquement UTF-16), y compris le terminateur nul. Chaque élément char16_t du tableau est initialisé comme si l'on exécutait mbrtoc16 dans une locale définie par l'implémentation.

  2. littéral de chaîne large 32 bits : le type du littéral est char32_t[N], où N est la taille de la chaîne en unités de code d'un encodage 32 bits défini par l'implémentation (typiquement UTF-32), y compris le terminateur nul. Chaque élément char32_t du tableau est initialisé comme si l'on exécutait mbrtoc32 dans une locale définie par l'implémentation.

(jusqu'à C23)

  1. littéral de chaîne UTF-16 : le type du littéral est char16_t[N], où N est la taille de la chaîne en unités de code UTF-16, y compris le terminateur nul. Chaque élément char16_t du tableau est initialisé à partir du caractère multioctet suivant de s-char-sequence en utilisant l'encodage UTF-16.

  2. littéral de chaîne UTF-32 : le type du littéral est char32_t[N], où N est la taille de la chaîne en unités de code UTF-32, y compris le terminateur nul. Chaque élément char32_t du tableau est initialisé à partir du caractère multioctet suivant de s-char-sequence en utilisant l'encodage UTF-32.

(depuis C23)

  1. littéral de chaîne large : le type du littéral est wchar_t[N], où N est la taille de la chaîne en unités de code de l'encodage large d'exécution, y compris le terminateur nul. Chaque élément wchar_t du tableau est initialisé comme si l'on exécutait mbstowcs dans une locale définie par l'implémentation.

Explication

D'abord, à la phase de traduction 6 (après expansion des macros), les littéraux de chaîne adjacents (c'est-à-dire séparés uniquement par des espaces) sont concaténés.

Seuls deux littéraux de chaîne étroits, ou deux littéraux de chaîne larges, peuvent être concaténés.

(jusqu'à C99)

Si un littéral n'a pas de préfixe, la chaîne résultante a la largeur et l'encodage spécifiés par le littéral préfixé.

L"Δx = %" PRId16 // à la phase 4, PRId16 se développe en "d"
                 // à la phase 6, L"Δx = %" et "d" forment L"Δx = %d"

(depuis C99)

Si les deux littéraux de chaîne ont des préfixes d'encodage différents, la concaténation est définie par l'implémentation, sauf qu'un littéral de chaîne UTF-8 et un littéral de chaîne large ne peuvent pas être concaténés.

(depuis C11) (jusqu'à C23)

Si les deux littéraux de chaîne ont des préfixes d'encodage différents, la concaténation est mal formée.

(depuis C23)

Ensuite, à la phase de traduction 7, un caractère nul de fin est ajouté à chaque littéral de chaîne, puis chaque littéral initialise un tableau anonyme à durée de stockage statique et de longueur juste suffisante pour contenir le contenu du littéral de chaîne, plus un pour le terminateur nul.

char* p = "\x12" "3"; // crée un tableau statique char[3] contenant {'\x12', '3', '\0'}
                      // fait pointer p vers le premier élément du tableau

Les littéraux de chaîne sont non modifiables (et peuvent en fait être placés dans une mémoire en lecture seule, telle que .rodata). Si un programme tente de modifier le tableau statique formé par un littéral de chaîne, le comportement est indéfini.

char* p = "Hello";
p[1] = 'M'; // Comportement indéfini
char a[] = "Hello";
a[1] = 'M'; // OK : a n'est pas un littéral de chaîne

Il n'est ni requis ni interdit que des littéraux de chaîne identiques fassent référence au même emplacement mémoire. De plus, des littéraux de chaîne qui se chevauchent, ou qui sont des sous-chaînes d'autres littéraux de chaîne, peuvent être fusionnés.

"def" == 3+"abcdef"; // peut valoir 1 ou 0, défini par l'implémentation

Notes

Un littéral de chaîne n'est pas nécessairement une chaîne ; si un littéral de chaîne contient des caractères nuls intégrés, il représente un tableau qui contient plusieurs chaînes :

char* p = "abc\0def"; // strlen(p) == 3, mais le tableau a une taille de 8

Si un chiffre hexadécimal valide suit un échappement hexadécimal dans un littéral de chaîne, la compilation échouerait car la séquence d'échappement est invalide, mais la concaténation de chaînes peut servir de solution de contournement :

//char* p = "\xfff"; // erreur : séquence d'échappement hexadécimale hors de portée
char* p = "\xff""f"; // correct, le littéral est char[3] contenant {'\xff', 'f', '\0'}

Les littéraux de chaîne peuvent servir à initialiser des tableaux, et si la taille du tableau est inférieure d'une unité à celle du littéral de chaîne, le terminateur nul est ignoré :

char a1[] = "abc"; // a1 est char[4] contenant {'a', 'b', 'c', '\0'}
char a2[4] = "abc"; // a2 est char[4] contenant {'a', 'b', 'c', '\0'}
char a3[3] = "abc"; // a3 est char[3] contenant {'a', 'b', 'c'}

L'encodage des littéraux de chaîne de caractères (1) et des littéraux de chaîne larges (5) est défini par l'implémentation. Par exemple, gcc les sélectionne avec les options de ligne de commande -fexec-charset et -fwide-exec-charset.

Bien que la concaténation mixte de littéraux de chaîne larges soit autorisée en C11, presque tous les compilateurs la rejettent (la seule exception connue est SDCC), et son usage n'est pas connu. En conséquence, l'autorisation de la concaténation mixte de littéraux de chaîne larges est supprimée en C23.
