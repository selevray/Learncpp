Type booléen

  • [_Bool (également accessible via la macro bool) (jusqu'à C23) | bool (depuis C23)] — type pouvant contenir l'une des deux valeurs : [1 et 0 (également accessibles via les macros true et false) (jusqu'à C23) | true et false (depuis C23)].

Notez que la conversion vers [_Bool (jusqu'à C23) | bool (depuis C23)] ne fonctionne pas comme la conversion vers les autres types entiers : (bool)0.5 donne true, alors que (int)0.5 donne 0.

(depuis C99)

Types de caractères

  • signed char — type pour la représentation d'un caractère signé.
  • unsigned char — type pour la représentation d'un caractère non signé. Il sert également à inspecter les représentations d'objets (mémoire brute).
  • char — type pour la représentation des caractères. Équivalent à signed char ou unsigned char (lequel est défini par l'implémentation et peut être contrôlé par une option de ligne de commande du compilateur), mais char est un type distinct, différent de signed char comme de unsigned char.

Notez que la bibliothèque standard définit aussi les noms typedef wchar_t, char16_t et char32_t (depuis C11) pour représenter les caractères larges et char8_t pour les caractères UTF-8 (depuis C23).

Types entiers

  • short int (également accessible via short, peut utiliser le mot-clé signed)

  • unsigned short int (également accessible via unsigned short)

  • int (également accessible via signed int) C'est le type entier le plus optimal pour la plateforme, et il est garanti d'avoir au moins 16 bits. La plupart des systèmes actuels utilisent 32 bits (voir Modèles de données ci-dessous).

  • unsigned int (également accessible via unsigned), la contrepartie non signée de int, implémentant l'arithmétique modulo. Adapté aux manipulations de bits.

  • long int (également accessible via long)

  • unsigned long int (également accessible via unsigned long)

  • long long int (également accessible via long long)
  • unsigned long long int (également accessible via unsigned long long)

(depuis C99)

  • _BitInt(n) (également accessible via signed _BitInt(n)), les types entiers signés de précision binaire (où n est remplacé par une expression constante entière indiquant la largeur précise (bit de signe inclus), qui ne peut pas être supérieure à BITINT_MAXWIDTH de <limits.h>)
  • unsigned _BitInt(n), les types entiers non signés de précision binaire (où n est remplacé par une expression constante entière indiquant la largeur précise, qui ne peut pas être supérieure à BITINT_MAXWIDTH de <limits.h>)

(depuis C23)

Remarque : comme pour tous les spécificateurs de type, n'importe quel ordre est permis : unsigned long long int et long int unsigned long désignent le même type.

Remarque : cela autorise le cas extrême où les octets font 64 bits, tous les types (y compris char) font 64 bits de large, et sizeof renvoie 1 pour chaque type.

Note : l'arithmétique entière est définie différemment pour les types entiers signés et non signés. Voir opérateurs arithmétiques, en particulier dépassements d'entiers.

Modèles de données

Les choix faits par chaque implémentation concernant les tailles des types fondamentaux sont collectivement appelés modèle de données. Quatre modèles de données sont largement adoptés :

Systèmes 32 bits :

  • LP32 ou 2/4/4 (int est sur 16 bits, long et le pointeur sont sur 32 bits)

    • API Win16

  • ILP32 ou 4/4/4 (int, long et le pointeur sont sur 32 bits) ;

    • API Win32
    • Systèmes Unix et de type Unix (Linux, Mac OS X)

Systèmes 64 bits :

  • LLP64 ou 4/4/8 (int et long sont sur 32 bits, le pointeur sur 64 bits)

    • API Win64

  • LP64 ou 4/8/8 (int est sur 32 bits, long et le pointeur sur 64 bits)

    • Systèmes Unix et de type Unix (Linux, Mac OS X)

Les autres modèles sont très rares. Par exemple, ILP64 (8/8/8 : int, long et les pointeurs sont sur 64 bits) n'est apparu que dans quelques premiers systèmes Unix 64 bits (par ex. Unicos sur Cray).

Notez que les types entiers de largeur exacte sont disponibles dans <stdint.h> depuis C99.

Types flottants réels

C possède trois ou six (depuis C23) types pour représenter les valeurs réelles à virgule flottante :

  • float — type à virgule flottante en simple précision. Correspond au format IEEE-754 binary32 si pris en charge.
  • double — type à virgule flottante en double précision. Correspond au format IEEE-754 binary64 si pris en charge.
  • long double — type à virgule flottante en précision étendue. Correspond au format IEEE-754 binary128 si pris en charge, sinon correspond au format IEEE-754 binary64-étendu si pris en charge, sinon correspond à un format étendu non IEEE-754 à condition que sa précision soit meilleure que binary64 et que son intervalle soit au moins aussi bon que binary64, sinon correspond au format IEEE-754 binary64.
    • Le format binary128 est utilisé par certaines implémentations HP-UX, SPARC, MIPS, ARM64 et z/OS.
    • Le format IEEE-754 binary64-étendu le plus connu est le format à précision étendue 80 bits x87. Il est utilisé par de nombreuses implémentations x86 et x86-64 (une exception notable est MSVC, qui implémente long double dans le même format que double, soit binary64).

Si l'implémentation prédéfinit la constante macro __STDC_IEC_60559_DFP__, les types à virgule flottante décimale suivants sont aussi pris en charge.

  • _Decimal32 — Représente le format IEEE-754 decimal32.
  • _Decimal64 — Représente le format IEEE-754 decimal64.
  • _Decimal128 — Représente le format IEEE-754 decimal128. Sinon, ces types à virgule flottante décimale ne sont pas pris en charge.

(depuis C23)

Les types à virgule flottante peuvent prendre en charge des valeurs spéciales :

  • infini (positif et négatif), voir INFINITY
  • le zéro négatif, -0.0. Il est égal au zéro positif lors de la comparaison, mais il a un sens dans certaines opérations arithmétiques, par ex. 1.0 / 0.0 == INFINITY, alors que 1.0 / -0.0 == -INFINITY)
  • non-nombre (NaN), qui n'est égal à rien (y compris lui-même) lors d'une comparaison. Plusieurs motifs de bits représentent des NaN, voir nan, NAN. Notez que C ne tient aucun compte particulier des NaN signalants (définis par IEEE-754) et traite tous les NaN comme silencieux.

Les nombres réels à virgule flottante peuvent être utilisés avec les opérateurs arithmétiques + - / * et diverses fonctions mathématiques de <math.h>. Les opérateurs intégrés comme les fonctions de la bibliothèque peuvent lever des exceptions à virgule flottante et positionner errno comme décrit dans math_errhandling.

Les expressions à virgule flottante peuvent avoir une plage et une précision supérieures à celles indiquées par leur type, voir FLT_EVAL_METHOD. L'affectation, le retour et le transtypage imposent la plage et la précision associées au type déclaré.

Les expressions à virgule flottante peuvent aussi être contractées, c'est-à-dire calculées comme si toutes les valeurs intermédiaires avaient une plage et une précision infinies, voir #pragma STDC FP_CONTRACT.

Certaines opérations sur les nombres à virgule flottante sont affectées par l'environnement à virgule flottante et modifient son état (notamment le sens d'arrondi).

Des conversions implicites sont définies entre les types flottants réels et les types entiers, complexes et imaginaires.

Voir Limites des types à virgule flottante et la bibliothèque <math.h> pour des détails, limites et propriétés supplémentaires des types à virgule flottante.

Types flottants complexes

Les types flottants complexes modélisent le nombre complexe mathématique, c'est-à-dire les nombres qui s'écrivent comme la somme d'un nombre réel et d'un nombre réel multiplié par l'unité imaginaire : a + bi

Les trois types complexes sont

  • float _Complex (également disponible sous le nom float complex si <complex.h> est inclus)
  • double _Complex (également disponible sous le nom double complex si <complex.h> est inclus)
  • long double _Complex (également disponible sous le nom long double complex si <complex.h> est inclus)

Remarque : comme pour tous les spécificateurs de type, n'importe quel ordre est permis : long double complex, complex long double et même double complex long désignent le même type.

#include <complex.h>
#include <stdio.h>

int main(void)
{
    double complex z = 1 + 2*I;
    z = 1 / z;
    printf("1/(1.0+2.0i) = %.1f%+.1fi\n", creal(z), cimag(z));
}

Output:

1/(1.0+2.0i) = 0.2-0.4i

Si la constante macro __STDC_NO_COMPLEX__ est définie par l'implémentation, les types complexes (ainsi que l'en-tête de bibliothèque <complex.h>) ne sont pas fournis.

(depuis C11)

Chaque type complexe a la même représentation d'objet et les mêmes exigences d'alignement qu'un tableau de deux éléments du type réel correspondant (float pour float complex, double pour double complex, long double pour long double complex). Le premier élément du tableau contient la partie réelle, et le second élément contient la partie imaginaire.

float a[4] = {1, 2, 3, 4};
float complex z1, z2;
memcpy(&z1, a, sizeof z1); // z1 devient 1.0 + 2.0i
memcpy(&z2, a+2, sizeof z2); // z2 devient 3.0 + 4.0i

Les nombres complexes peuvent être utilisés avec les opérateurs arithmétiques + - * et /, éventuellement mélangés avec des nombres imaginaires et réels. De nombreuses fonctions mathématiques sont définies pour les nombres complexes dans <complex.h>. Les opérateurs intégrés comme les fonctions de la bibliothèque peuvent lever des exceptions à virgule flottante et positionner errno comme décrit dans math_errhandling.

L'incrémentation et la décrémentation ne sont pas définies pour les types complexes.

Les opérateurs relationnels ne sont pas définis pour les types complexes (il n'existe pas de notion de « inférieur à »).

Des conversions implicites sont définies entre les types complexes et les autres types arithmétiques.

Afin de prendre en charge le modèle un-infini de l'arithmétique des nombres complexes, C considère toute valeur complexe ayant au moins une partie infinie comme un infini, même si son autre partie est un NaN, garantit que tous les opérateurs et fonctions respectent les propriétés de base des infinis, et fournit cproj pour ramener tous les infinis à l'infini canonique (voir opérateurs arithmétiques pour les règles exactes).

#include <complex.h>
#include <math.h>
#include <stdio.h>

int main(void)
{
    double complex z = (1 + 0*I) * (INFINITY + I*INFINITY);
//  la formule de manuel donnerait
//  (1+i0)(∞+i∞) ⇒ (1×∞ – 0×∞) + i(0×∞+1×∞) ⇒ NaN + I*NaN
//  mais C donne un infini complexe
    printf("%f%+f*i\n", creal(z), cimag(z));

//  la formule de manuel donnerait
//  cexp(∞+iNaN) ⇒ exp(∞)×(cis(NaN)) ⇒ NaN + I*NaN
//  mais C donne ±∞+i*nan
    double complex y = cexp(INFINITY + I*NAN);
    printf("%f%+f*i\n", creal(y), cimag(y));
}

Sortie possible :

inf+inf*i
inf+nan*i

C traite aussi les infinis multiples de manière à préserver, lorsque c'est possible, l'information directionnelle, malgré les limites inhérentes à la représentation cartésienne :

multiplier l'unité imaginaire par un infini réel donne l'infini imaginaire au signe correct : i × ∞ = i∞. De même, i × (∞ – i∞) = ∞ + i∞ indique le quadrant raisonnable.

Types flottants imaginaires

Les types flottants imaginaires modélisent les nombres imaginaires mathématiques, c'est-à-dire les nombres qui s'écrivent comme un nombre réel multiplié par l'unité imaginaire : bi Les trois types imaginaires sont

  • float _Imaginary (également disponible sous le nom float imaginary si <complex.h> est inclus)
  • double _Imaginary (également disponible sous le nom double imaginary si <complex.h> est inclus)
  • long double _Imaginary (également disponible sous le nom long double imaginary si <complex.h> est inclus)

Remarque : comme pour tous les spécificateurs de type, n'importe quel ordre est permis : long double imaginary, imaginary long double et même double imaginary long désignent le même type.

#include <complex.h>
#include <stdio.h>

int main(void)
{
    double imaginary z = 3*I;
    z = 1 / z;
    printf("1/(3.0i) = %+.1fi\n", cimag(z));
}

Output:

1/(3.0i) = -0.3i

Une implémentation qui définit __STDC_IEC_559_COMPLEX__ est recommandée, sans être obligatoire, pour prendre en charge les nombres imaginaires. POSIX recommande de vérifier si la macro _Imaginary_I est définie pour identifier la prise en charge des nombres imaginaires.

(jusqu'à C11)

Les nombres imaginaires sont pris en charge si [__STDC_IEC_559_COMPLEX__ (jusqu'à C23) | __STDC_IEC_60559_COMPLEX__ (depuis C23)] est défini.

(depuis C11)

Chacun des trois types imaginaires a la même représentation d'objet et la même exigence d'alignement que son type réel correspondant (float pour float imaginary, double pour double imaginary, long double pour long double imaginary).

Remarque : malgré cela, les types imaginaires sont distincts et non compatibles avec leurs types réels correspondants, ce qui interdit l'aliasing.

Les nombres imaginaires peuvent être utilisés avec les opérateurs arithmétiques + - * et /, éventuellement mélangés avec des nombres complexes et réels. De nombreuses fonctions mathématiques sont définies pour les nombres imaginaires dans <complex.h>. Les opérateurs intégrés comme les fonctions de la bibliothèque peuvent lever des exceptions à virgule flottante et positionner errno comme décrit dans math_errhandling.

L'incrémentation et la décrémentation ne sont pas définies pour les types imaginaires.

Des conversions implicites sont définies entre les types imaginaires et les autres types arithmétiques.

Les nombres imaginaires permettent d'exprimer tous les nombres complexes avec la notation naturelle x + I*y (où I est défini comme _Imaginary_I). Sans types imaginaires, certaines valeurs complexes particulières ne peuvent pas être créées naturellement. Par exemple, si I est défini comme _Complex_I, alors écrire 0.0 + I*INFINITY donne NaN comme partie réelle, et CMPLX(0.0, INFINITY) doit être utilisé à la place. Il en va de même pour les nombres dont la partie imaginaire est un zéro négatif, qui ont un sens lorsqu'on travaille avec les fonctions de la bibliothèque à lignes de coupure, telles que csqrt : 1.0 - 0.0*I donne une partie imaginaire en zéro positif si I est défini comme _Complex_I, et la partie imaginaire en zéro négatif nécessite l'utilisation de CMPLX ou conj.

Les types imaginaires simplifient aussi les implémentations ; la multiplication d'un imaginaire par un complexe peut être implémentée directement avec deux multiplications si les types imaginaires sont pris en charge, au lieu de quatre multiplications et deux additions.

(depuis C99)
