Phases de traduction

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Le fichier source C est traité par le compilateur comme si les phases suivantes avaient lieu, dans cet ordre exact. L'implémentation réelle peut combiner ces actions ou les traiter différemment, tant que le comportement reste le même.

Phase 1

  1. Les octets individuels du fichier de code source (en général un fichier texte dans un codage multi-octets tel que UTF-8) sont mis en correspondance, de manière définie par l'implémentation, avec les caractères du jeu de caractères source. En particulier, les indicateurs de fin de ligne dépendants du système d'exploitation sont remplacés par des caractères de saut de ligne.Le jeu de caractères source est un jeu de caractères multi-octets qui inclut le jeu de caractères source de base comme sous-ensemble à un octet, composé des 96 caractères suivants :

a) 5 caractères d'espacement (espace, tabulation horizontale, tabulation verticale, saut de page, saut de ligne)

b) 10 chiffres de '0' à '9'

c) 52 lettres de 'a' à 'z' et de 'A' à 'Z'

d) 29 caractères de ponctuation : _ { } [ ] # ( ) < > % : ; . ? * + - / ^ & | ~ ! = , \ " '

  1. Les séquences de trigraphes sont remplacées par les représentations à caractère unique correspondantes. (jusqu'à C23)

Phase 2

  1. Chaque fois qu'une barre oblique inverse apparaît en fin de ligne (immédiatement suivie du caractère de saut de ligne), la barre oblique inverse et le saut de ligne sont supprimés, ce qui fusionne deux lignes physiques du code source en une seule ligne logique. Il s'agit d'une opération en une seule passe : une ligne se terminant par deux barres obliques inverses suivie d'une ligne vide ne fusionne pas trois lignes en une seule.
#include <stdio.h>

#define PUTS p\
u\
t\
s
/* La jonction de lignes a lieu en phase 2, alors que les macros
 * sont découpées en jetons en phase 3 et développées en phase 4,
 * donc ce qui précède équivaut à #define PUTS puts
 */

int main(void)
{
 /* Utilisez la jonction de lignes pour appeler puts */ PUT\
S\
("Output ends here\\
0Not printed" /* Après la jonction de lignes, la barre oblique inverse restante
               * échappe le 0, ce qui termine la chaîne plus tôt.
               */
);
}
  1. Si un fichier source non vide ne se termine pas par un caractère de saut de ligne après cette étape (qu'il n'en ait jamais eu un, ou qu'il se termine par une barre oblique inverse), le comportement est indéfini.

Phase 3

  1. Le fichier source est décomposé en commentaires, en séquences de caractères d'espacement (espace, tabulation horizontale, saut de ligne, tabulation verticale et saut de page) et en jetons de prétraitement, qui sont les suivants

a) noms d'en-têtes : <stdio.h> ou "myfile.h"

b) identifiants

c) nombres de prétraitement, qui couvrent les constantes entières et les constantes flottantes, mais aussi certains jetons invalides tels que 1..E+3.foo ou 0JBK

d) constantes caractères et littéraux de chaîne

e) opérateurs et ponctuateurs, tels que +, <<=, <% ou ##.

f) caractères individuels autres que d'espacement qui n'entrent dans aucune autre catégorie

  1. Chaque commentaire est remplacé par un caractère espace

  2. Les sauts de ligne sont conservés, et il est défini par l'implémentation de savoir si les séquences d'espacement autres que les sauts de ligne peuvent être réduites en un seul caractère espace.

Si l'entrée a été analysée en jetons de prétraitement jusqu'à un caractère donné, le jeton de prétraitement suivant est en général la plus longue séquence de caractères pouvant constituer un jeton de prétraitement, même si cela devait faire échouer l'analyse ultérieure. C'est ce que l'on appelle communément maximal munch.

int foo = 1;
// int bar = 0xE+foo; // erreur : nombre de prétraitement invalide 0xE+foo
int bar = 0xE/*Le commentaire se développe en un espace*/+foo; // OK : 0xE + foo
int baz = 0xE + foo; // OK : 0xE + foo
int pub = bar+++baz; // OK : bar++ + baz
int ham = bar++-++baz; // OK : bar++ - ++baz
// int qux = bar+++++baz; // erreur : bar++ ++ +baz, et non bar++ + ++baz
int qux = bar+++/*Enregistrement du commentaire*/++baz; // OK : bar++ + ++baz

La seule exception à la règle du maximal munch est :

  • Les jetons de prétraitement de nom d'en-tête ne sont formés qu'à l'intérieur d'une directive #include ou #embed (depuis C23), dans les expressions __has_include et __has_embed (depuis C23) et aux emplacements définis par l'implémentation d'une directive #pragma.
#define MACRO_1 1
#define MACRO_2 2
#define MACRO_3 3
#define MACRO_EXPR (MACRO_1 <MACRO_2> MACRO_3) // OK: <MACRO_2> is not a header-name

Phase 4

  1. Le préprocesseur est exécuté.

  2. Chaque fichier introduit par la directive #include traverse récursivement les phases 1 à 4.

  3. À la fin de cette phase, toutes les directives du préprocesseur sont supprimées du code source.

Phase 5

  1. Tous les caractères et séquences d'échappement des constantes caractères et des littéraux de chaîne sont convertis du jeu de caractères source vers le jeu de caractères d'exécution (qui peut être un jeu de caractères multi-octets tel que UTF-8, à condition que les 96 caractères du jeu de caractères source de base listés en phase 1 aient des représentations sur un seul octet). Si le caractère désigné par une séquence d'échappement n'appartient pas au jeu de caractères d'exécution, le résultat est défini par l'implémentation, mais il est garanti de ne pas être un caractère nul (large).

Note : la conversion effectuée à cette étape peut être contrôlée par des options de ligne de commande dans certaines implémentations : gcc et clang utilisent -finput-charset pour spécifier l'encodage du jeu de caractères source, -fexec-charset et -fwide-exec-charset pour spécifier les encodages du jeu de caractères d'exécution dans les littéraux de chaîne et les constantes caractères qui n'ont pas de préfixe d'encodage (depuis C11).

Phase 6

Les littéraux de chaîne adjacents sont concaténés.

Phase 7

La compilation a lieu : les jetons sont analysés syntaxiquement et sémantiquement, puis traduits en tant qu'unité de traduction.

Phase 8

L'édition des liens a lieu : les unités de traduction et les composants de bibliothèque nécessaires pour satisfaire les références externes sont rassemblés en une image de programme qui contient les informations nécessaires à l'exécution dans son environnement d'exécution (le système d'exploitation).
