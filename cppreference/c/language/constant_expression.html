Expressions constantes

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Plusieurs variétés d'expressions sont appelées expressions constantes

Expression constante du préprocesseur

L'expression suivant #if ou #elif doit se développer en

  • opérateurs autres que l'affectation, l'incrémentation, la décrémentation, l'appel de fonction ou la virgule, dont les arguments sont des expressions constantes du préprocesseur
  • constantes entières
  • constantes caractères
  • l'opérateur de préprocesseur spécial defined

Les constantes caractères, lorsqu'elles sont évaluées dans des expressions #if, peuvent être interprétées dans le jeu de caractères source, le jeu de caractères d'exécution ou un autre jeu de caractères défini par l'implémentation.

L'arithmétique entière dans les expressions #if est effectuée selon la sémantique de intmax_t pour les types signés et de uintmax_t pour les types non signés.

(depuis C99)

Expression constante entière

Une expression constante entière est une expression qui ne consiste qu'en

  • opérateurs autres que l'affectation, l'incrémentation, la décrémentation, l'appel de fonction ou la virgule, à l'exception des opérateurs de transtypage qui ne peuvent convertir que des types arithmétiques en types entiers, sauf s'ils font partie d'un opérande de l'opérateur sizeof [, _Alignof (depuis C11) (jusqu'à C23) | , alignas (depuis C23) | ou typeof/typeof_unqual (depuis C23)].
  • constantes entières
  • constantes d'énumération
  • constantes caractères
  • constantes flottantes, mais seulement si elles sont immédiatement utilisées comme opérandes de transtypages vers un type entier
  • sizeof opérateurs dont les opérandes ne sont pas des VLA (depuis C99)
  • [_Alignof (jusqu'à C23) | alignas (depuis C23)] opérateurs

(depuis C11)

  • constantes littérales nommées et composées de type entier, ou de type arithmétique et qui sont les opérandes immédiats de transtypages

(depuis C23)

Les expressions constantes entières sont évaluées à la compilation. Les contextes suivants exigent des expressions dites expressions constantes entières :

  • La taille d'un champ de bits.
  • La valeur d'une constante d'énumération
  • L'étiquette case d'une instruction switch
  • La taille d'un tableau non VLA (depuis C99)
  • Conversion implicite d'entier en pointeur.
  • L'indice dans un désignateur de tableau

(depuis C99)

  • Le premier argument de _Static_assert
  • L'argument entier de [_Alignof (jusqu'à C23) | alignof (depuis C23)]

(depuis C11)

  • Le nombre de bits N d'un type entier de précision binaire (_BitInt(N))

(depuis C23)

Initialiseur statique

Les expressions utilisées dans les initialiseurs des objets à durée de stockage statique et thread_local ou déclarés avec le spécificateur de classe de stockage constexpr (depuis C23) doivent être soit des littéraux de chaîne, soit des expressions pouvant être l'une des suivantes

  1. expression constante arithmétique, c'est-à-dire une expression de n'importe quel type arithmétique qui consiste en
  • opérateurs autres que l'affectation, l'incrémentation, la décrémentation, l'appel de fonction ou la virgule, à l'exception des opérateurs de transtypage qui doivent convertir des types arithmétiques en d'autres types arithmétiques, sauf s'ils font partie d'un opérande de l'opérateur sizeof [, _Alignof (depuis C11) (jusqu'à C23) | , alignof (depuis C23) | ou typeof/typeof_unqual (depuis C23)]
  • constantes entières
  • constantes flottantes
  • constantes d'énumération
  • constantes caractères
  • sizeof opérateurs dont les opérandes ne sont pas des VLA (depuis C99)
  • [_Alignof (jusqu'à C23) | alignof (depuis C23)] opérateurs

(depuis C11)

  • constantes littérales nommées ou composées de type arithmétique

(depuis C23)

  1. une constante de pointeur nul (par exemple NULL)

  2. expression constante d'adresse, qui est

  • un pointeur nul
  • une lvalue désignant un objet à durée de stockage statique ou un désignateur de fonction, convertie en pointeur soit
    • en utilisant l'opérateur unaire d'adresse
    • en transtypant une constante entière en pointeur
    • par conversion implicite de tableau en pointeur ou de fonction en pointeur
  1. expression constante d'adresse d'un type objet complet quelconque, plus ou moins une expression constante entière
  1. une constante nommée, c'est-à-dire un identifiant qui est
  • une constante d'énumération
  • une constante prédéfinie (l'une de true, false ou nullptr)
  • déclaré avec le spécificateur de classe de stockage constexpr et de type objet ou une expression postfixée qui applique l'opérateur d'accès membre . à une constante nommée de type structure ou union, même de manière récursive.
  1. une constante littérale composée, c'est-à-dire
  • un littéral composé avec le spécificateur de classe de stockage constexpr
  • une expression postfixée qui applique l'opérateur d'accès membre . à une constante littérale composée de type structure ou union, même de manière récursive.

Une constante de structure ou d'union est une constante nommée ou une constante littérale composée de type structure ou union, respectivement. Si l'opérateur d'accès membre . accède à un membre d'une constante d'union, le membre accédé doit être le même que le membre initialisé par l'initialiseur de la constante d'union.

(depuis C23)

  1. expression constante de l'une des autres formes acceptées par l'implémentation.

Contrairement aux expressions constantes entières, les expressions d'initialisation statique ne sont pas tenues d'être évaluées à la compilation ; le compilateur est libre de transformer ces initialiseurs en code exécutable, invoqué avant le démarrage du programme.

static int i = 2 || 1 / 0; // initialise i à la valeur 1

La valeur d'un initialiseur statique de type virgule flottante n'est jamais moins précise que la valeur de la même expression exécutée à l'exécution, mais elle peut être meilleure.

Expressions constantes en virgule flottante

Les expressions constantes arithmétiques de types à virgule flottante qui ne sont pas utilisées dans des initialiseurs statiques sont toujours évaluées comme si elles l'étaient à l'exécution et sont affectées par l'arrondi courant (si FENV_ACCESS est activé) et signalent les erreurs comme spécifié dans math_errhandling.

void f(void)
{
#pragma STDC FENV_ACCESS ON
    static float x = 0.0 / 0.0; // initialiseur statique : ne lève pas d'exception
    float w[] = { 0.0 / 0.0 };  // lève une exception
    float y = 0.0 / 0.0;        // lève une exception
    double z = 0.0 / 0.0;       // lève une exception
}

Notes

Si une expression s'évalue à une valeur qui n'est pas représentable par son type, elle ne peut pas être utilisée comme expression constante.

Les implémentations peuvent accepter d'autres formes d'expressions constantes. Cependant, ces expressions constantes ne sont pas considérées comme des expressions constantes entières, des expressions constantes arithmétiques ou des expressions constantes d'adresse, et ne peuvent donc pas être utilisées dans les contextes exigeant ces types d'expressions constantes. Par exemple, int arr[(int)+1.0]; déclare un VLA.
