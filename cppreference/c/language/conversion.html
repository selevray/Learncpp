Conversions implicites

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Lorsqu'une expression est utilisée dans un contexte où une valeur d'un autre type est attendue, une conversion peut avoir lieu :

int n = 1L; // l'expression 1L est de type long, int est attendu
n = 2.1; // l'expression 2.1 est de type double, int est attendu
char *p = malloc(10); // l'expression malloc(10) est de type void*, char* est attendu

Les conversions ont lieu dans les situations suivantes :

Conversion comme par affectation

  • Dans l'opérateur d'affectation, la valeur de l'opérande de droite est convertie vers le type non qualifié de l'opérande de gauche.
  • Dans l'initialisation scalaire, la valeur de l'expression d'initialisation est convertie vers le type non qualifié de l'objet initialisé
  • Dans une expression d'appel de fonction, vers une fonction possédant un prototype, la valeur de chaque expression d'argument est convertie vers le type non qualifié du paramètre correspondant déclaré
  • Dans une instruction return, la valeur de l'opérande de return est convertie en un objet ayant le type de retour de la fonction

Notez que l'affectation effective, en plus de la conversion, supprime aussi l'intervalle et la précision supplémentaires des types à virgule flottante et interdit les chevauchements ; ces caractéristiques ne s'appliquent pas à la conversion comme par affectation.

Promotions d'arguments par défaut

Dans une expression d'appel de fonction lorsque l'appel est effectué vers

  1. une fonction sans prototype (jusqu'à C23)

  2. une fonction variadique, où l'expression d'argument est l'un des arguments finaux correspondant au paramètre de points de suspension

Chaque argument de type entier subit une promotion entière (voir ci-dessous), et chaque argument de type float est implicitement converti en type double

int add_nums(int count, ...);
int sum = add_nums(2, 'c', true); // add_nums est appelée avec trois int : (2, 99, 1)

Notez que float complex et float imaginary ne sont pas promus en double complex et double imaginary dans ce contexte.

(depuis C99)

Conversions arithmétiques usuelles

Les arguments des opérateurs arithmétiques suivants subissent des conversions implicites afin d'obtenir le type réel commun, c'est-à-dire le type dans lequel le calcul est effectué :

  • arithmétique binaire *, /, %, +, -
  • opérateurs relationnels <, >, <=, >=, ==, !=
  • arithmétique binaire bit à bit &, ^, |,
  • l'opérateur conditionnel ?:
  1. Si un opérande a un type à virgule flottante décimale, l'autre opérande ne doit pas avoir de type à virgule flottante standard,

complexe ou imaginaire.

  • Premièrement, si le type de l'un des opérandes est _Decimal128, l'autre opérande est converti en _Decimal128.
  • Sinon, si le type de l'un des opérandes est _Decimal64, l'autre opérande est converti en _Decimal64.
  • Sinon, si le type de l'un des opérandes est _Decimal32, l'autre opérande est converti en _Decimal32.

(depuis C23)

  1. Sinon, si un opérande est long double, long double complex, ou long double imaginary (depuis C99), l'autre opérande est implicitement converti comme suit :
  • entier ou type à virgule flottante réel vers long double
  • type complexe vers long double complex
  • type imaginaire vers long double imaginary

(depuis C99)

  1. Sinon, si un opérande est double, double complex, ou double imaginary (depuis C99), l'autre opérande est implicitement converti comme suit :
  • entier ou type à virgule flottante réel vers double
  • type complexe vers double complex
  • type imaginaire vers double imaginary

(depuis C99)

  1. Sinon, si un opérande est float, float complex, ou float imaginary (depuis C99), l'autre opérande est implicitement converti comme suit :
  • type entier vers float (le seul type réel possible est float, qui reste inchangé)
  • le type complexe reste float complex
  • le type imaginaire reste float imaginary

(depuis C99)

  1. Sinon, les deux opérandes sont des entiers. Les deux opérandes subissent des promotions entières (voir ci-dessous) ; ensuite, après promotion entière, l'un des cas suivants s'applique :
  • Si les types sont identiques, ce type est le type commun.
  • Sinon, les types sont différents :
    • Si les types ont la même signature (tous deux signés ou tous deux non signés), l'opérande dont le type a le rang de conversion le plus faible1 est implicitement converti2 vers l'autre type.
    • Sinon, les opérandes ont des signatures différentes :
      • Si le type non signé a un rang de conversion supérieur ou égal au rang du type signé, alors l'opérande de type signé est implicitement converti vers le type non signé.
      • Sinon, le type non signé a un rang de conversion inférieur à celui du type signé :
        • Si le type signé peut représenter toutes les valeurs du type non signé, alors l'opérande de type non signé est implicitement converti vers le type signé.
        • Sinon, les deux opérandes subissent une conversion implicite vers le type non signé correspondant au type de l'opérande signé.
  1. Voir « promotions entières » ci-dessous pour les règles de classement.2. Voir « conversions entières » sous « sémantique de conversion implicite » ci-dessous.
1.f + 20000001; // int est converti en float, donnant 20000000.00
                // l'addition puis l'arrondi en float donnent 20000000.00

(char)'a' + 1L; // d'abord, le char 'a', qui vaut 97, est promu en int
                // types différents : int et long
                // même signe : les deux sont signés
                // rang différent : long a un rang supérieur à int
                // par conséquent, l'int 97 est converti en long 97
                // le résultat est 97 + 1 = 98 de type long signé

2u - 10; // types différents : unsigned int et signed int
         // signes différents
         // même rang
         // par conséquent, l'int signé 10 est converti en unsigned int 10
         // puisque l'opération arithmétique est effectuée sur des entiers non signés
         // (voir la rubrique « Opérateurs arithmétiques »), le calcul effectué est (2 - 10)
         // modulo (2 puissance n), où n est le nombre de bits de valeur de unsigned int
         // si unsigned int fait 32 bits et qu'il n'y a aucun bit de bourrage dans sa représentation d'objet
         // alors le résultat est (-8) modulo (2 puissance 32) = 4294967288
         // de type unsigned int

5UL - 2ULL; // types différents : unsigned long et unsigned long long
            // même signe
            // rang différent : le rang de unsigned long long est supérieur
            // par conséquent, l'unsigned long 5 est converti en unsigned long long 5
            // puisque l'opération arithmétique est effectuée sur des entiers non signés
            // (voir la rubrique « Opérateurs arithmétiques »),
            // si unsigned long long fait 64 bits, alors
            // le résultat est (5 - 2) modulo (2 puissance 64) = 3 de type
            // unsigned long long

0UL - 1LL; // types différents : unsigned long et signed long long
           // signes différents
           // rang différent : le rang de signed long long est supérieur.
           // si ULONG_MAX > LLONG_MAX, alors signed long long ne peut pas représenter toutes
           // les valeurs de unsigned long ; c'est donc le dernier cas : les deux opérandes sont convertis
           // en unsigned long long : unsigned long 0 est converti en unsigned long long 0
           // long long 1 est converti en unsigned long long 1, puisque l'opération arithmétique
           // est effectuée sur des entiers non signés
           // (voir la rubrique « Opérateurs arithmétiques »),
           // si unsigned long long fait 64 bits, alors
           // le calcul est (0 - 1) modulo (2 puissance 64)
           // ainsi, le résultat est 18446744073709551615 (ULLONG_MAX) de type
           // unsigned long long

Le type du résultat est déterminé comme suit :

  • si les deux opérandes sont complexes, le type du résultat est complexe
  • si les deux opérandes sont imaginaires, le type du résultat est imaginaire
  • si les deux opérandes sont réels, le type du résultat est réel
  • si les deux opérandes à virgule flottante ont des domaines de type différents (complexe et réel, complexe et imaginaire, ou imaginaire et réel), le type du résultat est complexe
double complex z = 1 + 2*I;
double f = 3.0;
z + f; // z reste inchangé, f est converti en double, le résultat est de type complexe double

(depuis C99)

Comme toujours, le résultat d'un opérateur à virgule flottante peut avoir une plage et une précision supérieures à celles indiquées par son type (voir FLT_EVAL_METHOD).

Remarque : les opérandes réels et imaginaires ne sont pas implicitement convertis en complexes, car cela nécessiterait des calculs supplémentaires et produirait des résultats indésirables dans certains cas impliquant des infinis, des NaN et des zéros signés. Par exemple, si les réels étaient convertis en complexes, 2.0×(3.0+i∞) serait évalué comme (2.0+i0.0)×(3.0+i∞) ⇒ (2.0×3.0–0.0×∞) + i(2.0×∞+0.0×3.0) ⇒ NaN+i∞ au lieu de la valeur correcte 6.0+i∞. Si les imaginaires étaient convertis en complexes, i2.0×(∞+i3.0) serait évalué comme (0.0+i2.0) × (∞+i3.0) ⇒ (0.0×∞ – 2.0×3.0) + i(0.0×3.0 + 2.0×∞) ⇒ NaN + i∞ au lieu de –6.0 + i∞.

(depuis C99)

Remarque : indépendamment des conversions arithmétiques usuelles, le calcul peut toujours être effectué dans un type plus étroit que celui spécifié par ces règles, selon la règle as-if

Transformations de valeur

Conversion lvalue

Toute expression lvalue de tout type non tableau, lorsqu'elle est utilisée dans un contexte autre que

  • en tant qu'opérande de l'opérateur d'adresse (si autorisé)
  • en tant qu'opérande des opérateurs d'incrémentation et de décrémentation préfixes et postfixes.
  • en tant qu'opérande gauche de l'opérateur d'accès membre (point).
  • en tant qu'opérande gauche des opérateurs d'affectation et d'affectation composée.
  • en tant qu'opérande de sizeof

subit une conversion lvalue : le type reste le même, mais perd les qualificateurs const/volatile/restrict et les propriétés atomic, le cas échéant. La valeur reste la même, mais perd ses propriétés de lvalue (l'adresse ne peut plus être prise).

Si la lvalue a un type incomplet, le comportement est indéfini.

Si la lvalue désigne un objet à durée de stockage automatique dont l'adresse n'a jamais été prise, et si cet objet n'était pas initialisé (non déclaré avec un initialiseur et aucune affectation ne lui a été faite avant utilisation), le comportement est indéfini.

Cette conversion modélise le chargement en mémoire de la valeur de l'objet depuis son emplacement.

volatile int n = 1;
int x = n;            // la conversion lvalue sur n lit la valeur de n
volatile int* p = &n; // pas de conversion lvalue : la valeur de n n'est pas lue

Conversion tableau vers pointeur

Toute expression lvalue de type tableau, lorsqu'elle est utilisée dans un contexte autre que

  • comme opérande de l'opérateur d'adresse
  • en tant qu'opérande de sizeof
  • en tant qu'opérande de typeof et typeof_unqual (depuis C23)
  • comme littéral de chaîne utilisé pour l'initialisation de tableau

subit une conversion en pointeur non lvalue vers son premier élément.

Si le tableau a été déclaré register, le comportement est indéfini.

int a[3], b[3][4];
int* p = a;      // conversion en &a[0]
int (*q)[4] = b; // conversion en &b[0]

Conversion fonction vers pointeur

Toute expression désignant une fonction, lorsqu'elle est utilisée dans un contexte autre que

  • comme opérande de l'opérateur d'adresse
  • en tant qu'opérande de sizeof
  • en tant qu'opérande de typeof et typeof_unqual (depuis C23)

subit une conversion en pointeur non lvalue vers la fonction désignée par l'expression.

int f(int);
int (*p)(int) = f; // conversion en &f
(***p)(1); // déréférencement répété de f puis reconversion en &f

Sémantique des conversions implicites

La conversion implicite, qu'elle soit comme par affectation ou une conversion arithmétique usuelle, se déroule en deux étapes :

  1. transformation de la valeur (si applicable)

  2. l'une des conversions listées ci-dessous (si elle peut produire le type cible)

Types compatibles

La conversion d'une valeur de tout type vers tout type compatible est toujours une opération nulle et ne modifie pas la représentation.

uint8_t (*a)[10];         // si uint8_t est un typedef de unsigned char
unsigned char (*b)[] = a; // alors ces types de pointeurs sont compatibles

Promotions entières

La promotion entière est la conversion implicite d'une valeur de tout type entier de rang inférieur ou égal au rang de int, ou d'un champ de bits de type [_Bool (jusqu'à C23) | bool (depuis C23)], int, signed int, unsigned int, vers la valeur de type int ou unsigned int.

Si int peut représenter l'intégralité de la plage de valeurs du type d'origine (ou de la plage de valeurs du champ de bits d'origine), la valeur est convertie vers le type int. Sinon, la valeur est convertie vers unsigned int.

La valeur provenant d'un champ de bits d'un type entier à précision exacte est convertie vers le type entier à précision exacte correspondant. Sinon, les types entiers à précision exacte sont exemptés des règles de promotion entière.

(depuis C23)

Les promotions entières préservent la valeur, y compris le signe :

int main(void)
{
    void f(); // déclaration de fonction à l'ancienne
              // depuis C23, void f(...) a le même comportement vis-à-vis des promotions
    char x = 'a'; // conversion entière de int vers char
    f(x); // promotion entière de char vers int
}

void f(x) int x; {} // la fonction attend un int

Le rang ci-dessus est une propriété de chaque type entier et est défini comme suit :

  1. les rangs de tous les types entiers signés sont différents et croissent avec leur précision : rang de signed char < rang de short < rang de int < rang de long int < rang de long long int

  2. les rangs de tous les types entiers signés sont égaux aux rangs des types entiers non signés correspondants

  3. le rang de tout type entier standard est supérieur au rang de tout type entier étendu ou type entier à précision exacte (depuis C23) de même taille (c'est-à-dire rang de __int64 < rang de long long int, mais rang de long long < rang de __int128 en raison de la règle (1))

  4. le rang de char est égal au rang de signed char et au rang de unsigned char

  5. le rang de [_Bool (jusqu'à C23) | bool (depuis C23)] est inférieur au rang de tout autre type entier standard

  6. le rang de tout type énuméré est égal au rang de son type entier compatible

  7. le classement est transitif : si rang de T1 < rang de T2 et rang de T2 < rang de T3, alors rang de T1 < rang de T3

  1. le rang d'un type entier signé à précision exacte doit être supérieur au rang de tout type entier standard de largeur inférieure ou de tout type entier à précision exacte de largeur inférieure.

  2. le rang de tout type entier à précision exacte par rapport à un type entier étendu de même largeur est défini par l'implémentation.

(depuis C23)

  1. tous les aspects du classement relatif des types entiers étendus non couverts ci-dessus sont définis par l'implémentation.

Remarque : les promotions entières ne sont appliquées que

  • dans le cadre des conversions arithmétiques usuelles (voir ci-dessus)
  • dans le cadre des promotions d'arguments par défaut (voir ci-dessus)
  • à l'opérande des opérateurs arithmétiques unaires + et -
  • à l'opérande de l'opérateur bit à bit unaire ~
  • aux deux opérandes des opérateurs de décalage << et >>

Conversion booléenne

Une valeur de tout type scalaire peut être implicitement convertie en [_Bool (jusqu'à C23) | bool (depuis C23)]. Les valeurs qui [se comparent égales à une expression constante entière de valeur zéro (jusqu'à C23) | sont un zéro (pour les types arithmétiques), un pointeur nul (pour les types pointeur) ou ont un type de nullptr_t (depuis C23)] sont converties en [0 (jusqu'à C23) | false (depuis C23)], toutes les autres valeurs sont converties en [1 (jusqu'à C23) | true (depuis C23)].

bool b1 = 0.5;              // b1 == 1 (0.5 converti en int donnerait zéro)
bool b2 = 2.0*_Imaginary_I; // b2 == 1 (mais converti en int donnerait zéro)
bool b3 = 0.0 + 3.0*I;      // b3 == 1 (mais converti en int donnerait zéro)
bool b4 = 0.0/0.0;          // b4 == 1 (NaN n'est pas égal à zéro)
bool b5 = nullptr;          // b5 == 0 (depuis C23 : nullptr est converti en false)

(depuis C99)

Conversions entières

Une valeur de tout type entier peut être implicitement convertie en tout autre type entier. Sauf dans les cas couverts par les promotions et les conversions booléennes ci-dessus, les règles sont :

  • si le type cible peut représenter la valeur, la valeur est inchangée
  • sinon, si le type cible est non signé, la valeur 2b
    , où b est le nombre de bits de valeur du type cible, est soustraite ou ajoutée de manière répétée à la valeur source jusqu'à ce que le résultat tienne dans le type cible. En d'autres termes, les entiers non signés implémentent une arithmétique modulo.
  • sinon, si le type cible est signé, le comportement est défini par l'implémentation (ce qui peut inclure le déclenchement d'un signal)
char x = 'a'; // int -> char, résultat inchangé
unsigned char n = -123456; // la cible est non signée, le résultat vaut 192 (soit -123456+483*256)
signed char m = 123456;    // la cible est signée, le résultat est défini par l'implémentation
assert(sizeof(int) > -1);  // l'assertion échoue :
                           // operator > demande la conversion de -1 en size_t,
                           // la cible est non signée, le résultat vaut SIZE_MAX

Conversions entier-flottant réel

Une valeur finie de tout type flottant réel peut être implicitement convertie en tout type entier. Sauf dans les cas couverts par la conversion booléenne ci-dessus, les règles sont :

  • La partie fractionnaire est supprimée (troncature vers zéro).
    • Si la valeur résultante peut être représentée par le type cible, cette valeur est utilisée
    • sinon, le comportement est indéfini
int n = 3.14; // n == 3
int x = 1e10; // comportement indéfini pour un int de 32 bits

Une valeur de tout type entier peut être implicitement convertie en tout type flottant réel.

  • si la valeur peut être représentée exactement par le type cible, elle est inchangée
  • si la valeur peut être représentée, mais pas exactement, le résultat est un choix défini par l'implémentation entre la valeur supérieure la plus proche et la valeur inférieure la plus proche, bien que si l'arithmétique IEEE est prise en charge, l'arrondi se fasse au plus proche. Il n'est pas spécifié si FE_INEXACT est levé dans ce cas.
  • si la valeur ne peut pas être représentée, le comportement est indéfini, bien que si l'arithmétique IEEE est prise en charge, FE_INVALID est levé et la valeur résultante n'est pas spécifiée.

Le résultat de cette conversion peut avoir une plage et une précision supérieures à celles indiquées par son type cible (voir FLT_EVAL_METHOD).

Si un contrôle sur FE_INEXACT est nécessaire lors des conversions flottant-vers-entier, rint et nearbyint peuvent être utilisés.

double d = 10; // d = 10.00
float f = 20000001; // f = 20000000.00 (FE_INEXACT)
float x = 1+(long long)FLT_MAX; // comportement indéfini

Conversions flottantes réelles

Une valeur de tout type flottant réel peut être implicitement convertie en tout autre type flottant réel.

  • Si la valeur peut être représentée exactement par le type cible, elle est inchangée

  • si la valeur peut être représentée, mais pas exactement, le résultat est la valeur supérieure la plus proche ou la valeur inférieure la plus proche (autrement dit, le sens de l'arrondi est défini par l'implémentation), bien que si l'arithmétique IEEE est prise en charge, l'arrondi se fasse au plus proche

  • si la valeur ne peut pas être représentée, le comportement est indéfini

Le résultat de cette conversion peut avoir une plage et une précision supérieures à celles indiquées par son type cible (voir FLT_EVAL_METHOD).

double d = 0.1; // d = 0.1000000000000000055511151231257827021181583404541015625
float f = d;    // f = 0.100000001490116119384765625
float x = 2*(double)FLT_MAX; // undefined

Conversions de types complexes

Une valeur de tout type complexe peut être implicitement convertie en tout autre type complexe. Les parties réelle et imaginaire suivent individuellement les règles de conversion des types flottants réels.

double complex d = 0.1 + 0.1*I;
float complex f = d; // f vaut (0.100000001490116119384765625, 0.100000001490116119384765625)

Conversions de types imaginaires

Une valeur de tout type imaginaire peut être implicitement convertie en tout autre type imaginaire. La partie imaginaire suit les règles de conversion des types flottants réels.

double imaginary d = 0.1*_Imaginary_I;
float imaginary f = d; // f vaut 0.100000001490116119384765625*I

Conversions réel-complexe

Une valeur de tout type flottant réel peut être implicitement convertie en tout type complexe.

  • La partie réelle du résultat est déterminée par les règles de conversion des types flottants réels
  • La partie imaginaire du résultat est un zéro positif (ou un zéro non signé sur les systèmes non IEEE)

Une valeur de tout type complexe peut être convertie implicitement en tout type flottant réel

  • La partie réelle est convertie selon les règles des types flottants réels
  • La partie imaginaire est ignorée

Note : lors de la conversion complexe vers réel, un NaN dans la partie imaginaire ne se propage pas au résultat réel.

double complex z = 0.5 + 3*I;
float f = z;  // la partie imaginaire est supprimée, f reçoit 0.5
z = f;        // affecte 0.5 + 0*I à z

Conversions réel-imaginaire

Une valeur de tout type imaginaire peut être convertie implicitement en tout type réel (entier ou à virgule flottante). Le résultat est toujours un zéro positif (ou non signé), sauf lorsque le type cible est [_Bool (jusqu'à C23) | bool (depuis C23)], auquel cas les règles de conversion booléenne s'appliquent.

Une valeur de tout type réel peut être convertie implicitement en tout type imaginaire. Le résultat est toujours un zéro imaginaire positif.

double imaginary z = 3*I;
bool b = z;  // Conversion booléenne : affecte true à b
float f = z; // Conversion réel-imaginaire : affecte 0.0 à f
z = 3.14;    // Conversion imaginaire-réel : affecte 0*_Imaginary_I à z

Conversions complexe-imaginaire

Une valeur de tout type imaginaire peut être convertie implicitement en tout type complexe.

  • La partie réelle du résultat est le zéro positif
  • La partie imaginaire du résultat suit les règles de conversion des types réels correspondants

Une valeur de tout type complexe peut être convertie implicitement en tout type imaginaire

  • La partie réelle est ignorée
  • La partie imaginaire du résultat suit les règles de conversion des types réels correspondants
double imaginary z = I * (3*I); // le résultat complexe -3.0+0i perd sa partie réelle
                                // affecte 0*_Imaginary_I à z

(depuis C99)

Conversions de pointeurs

Un pointeur vers void peut être converti implicitement vers et depuis tout pointeur vers un type objet, avec la sémantique suivante :

  • Si un pointeur vers un objet est converti en pointeur vers void puis reconverti, sa valeur est égale à celle du pointeur d'origine.
  • Aucune autre garantie n'est offerte
int* p = malloc(10 * sizeof(int)); // malloc retourne void*

Un pointeur vers un type non qualifié peut être converti implicitement en pointeur vers la version qualifiée de ce type (autrement dit, les qualificateurs const, volatile et restrict peuvent être ajoutés). Le pointeur d'origine et le résultat sont égaux.

int n;
const int* p = &n; // &n est de type int*

Toute expression constante entière de valeur 0, ainsi qu'une expression de pointeur entier de valeur zéro convertie en type void*, peut être convertie implicitement en tout type de pointeur (pointeur vers objet comme pointeur vers fonction). Le résultat est la valeur de pointeur nul de son type, garantie comme différente de toute valeur de pointeur non nul de ce type. Cette expression entière ou void* est appelée pointeur nul constant, et la bibliothèque standard en fournit une seule définition sous forme de macro NULL.

int* p = 0;
double* q = NULL;

Notes

Bien que le dépassement de capacité d'un entier signé dans un opérateur arithmétique soit un comportement indéfini, le dépassement d'un type entier signé lors d'une conversion entière est simplement un comportement non spécifié.

En revanche, bien que le dépassement de capacité d'un entier non signé dans un opérateur arithmétique (et dans une conversion entière) soit une opération bien définie suivant les règles de l'arithmétique modulo, le dépassement d'un entier non signé lors d'une conversion flottant vers entier est un comportement indéfini : les valeurs de type flottant réel pouvant être converties en entier non signé sont celles de l'intervalle ouvert (-1; Unnn_MAX+1).

unsigned int n = -1.0; // comportement indéfini

Les conversions entre pointeurs et entiers (sauf d'un pointeur vers [_Bool (jusqu'à C23) | bool (depuis C23)] et *(depuis C99)*d'une expression constante entière de valeur zéro vers un pointeur), entre pointeurs vers objets (sauf lorsque l'un des deux types est un pointeur vers void) et entre pointeurs vers fonctions (sauf lorsque les fonctions ont des types compatibles) ne sont jamais implicites et nécessitent un opérateur de conversion explicite.

Il n'existe aucune conversion (implicite ou explicite) entre pointeurs vers fonctions et pointeurs vers objets (y compris void*) ou entiers.
