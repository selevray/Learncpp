Définitions externes et définitions provisoires

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Au niveau le plus haut d'une unité de traduction (c'est-à-dire un fichier source avec tous les #include après le préprocesseur), chaque programme C est une suite de déclarations, qui déclarent des fonctions et des objets ayant une liaison externe ou interne. Ces déclarations sont appelées déclarations externes car elles apparaissent en dehors de toute fonction.

extern int n; // déclaration externe à liaison externe
int b = 1;    // définition externe à liaison externe
static const char *c = "abc"; // définition externe à liaison interne

int f(void)    // définition externe à liaison externe
{
    int a = 1; // non externe
    return b;
}

static void x(void) // définition externe à liaison interne
{
}

Les objets déclarés par une déclaration externe ont une durée de stockage statique, et ne peuvent donc pas utiliser les spécificateurs auto ou register sauf que auto peut être utilisé pour l'inférence de type (depuis C23). Les identificateurs introduits par des déclarations externes ont une portée de fichier.

Définitions provisoires

Une définition provisoire est une déclaration externe sans initialiseur, et soit sans spécificateur de classe de stockage, soit avec le spécificateur static.

Une définition provisoire est une déclaration qui peut ou non agir comme une définition. Si une véritable définition externe est trouvée plus tôt ou plus tard dans la même unité de traduction, alors la définition provisoire agit simplement comme une déclaration.

int i1 = 1;     // définition, liaison externe
int i1;         // définition provisoire, agit comme déclaration car i1 est définie
extern int i1;  // déclaration, se réfère à la définition précédente

extern int i2 = 3; // définition, liaison externe
int i2;            // définition provisoire, agit comme déclaration car i2 est définie
extern int i2;     // déclaration, se réfère à la définition à liaison externe

S'il n'existe aucune définition dans la même unité de traduction, alors la définition provisoire agit comme une véritable définition qui initialise à vide l'objet.

int i3;        // définition provisoire, liaison externe
int i3;        // définition provisoire, liaison externe
extern int i3; // déclaration, liaison externe
// dans cette unité de traduction, i3 est définie comme si par « int i3 = 0; »

Contrairement aux déclarations extern, qui ne modifient pas la liaison d'un identificateur si une déclaration précédente l'a établie, les définitions provisoires peuvent avoir une liaison différente d'une autre déclaration du même identificateur. Si deux déclarations du même identificateur sont dans la portée et ont des liaisons différentes, le comportement est indéfini :

static int i4 = 2; // définition, liaison interne
int i4;            // Comportement indéfini : liaison en désaccord avec la ligne précédente
extern int i4;     // déclaration, se réfère à la définition à liaison interne

static int i5; // définition provisoire, liaison interne
int i5;        // Comportement indéfini : liaison en désaccord avec la ligne précédente
extern int i5; // se réfère à la précédente, dont la liaison est interne

Une définition provisoire à liaison interne doit avoir un type complet.

static int i[]; // Erreur, type incomplet dans une définition provisoire statique
int i[]; // OK, équivalent à int i[1] = {0}; sauf si redéclaré plus loin dans ce fichier

Règle de la définition unique

Chaque unité de traduction peut avoir zéro ou une définition externe de chaque identificateur à liaison interne (un static global).

Si un identificateur à liaison interne est utilisé dans une expression autre qu'une non-VLA, (depuis C99) sizeof[, _Alignof (depuis C11) (jusqu'à C23) | , alignof (depuis C23) | , ou typeof (depuis C23)], il doit exister une et une seule définition externe pour cet identificateur dans l'unité de traduction.

L'ensemble du programme peut avoir zéro ou une définition externe de chaque identificateur à liaison externe.

Si un identificateur à liaison externe est utilisé dans une expression autre qu'une non-VLA, (depuis C99) sizeof[, _Alignof (depuis C11) (jusqu'à C23) | , alignof (depuis C23) | , ou typeof (depuis C23)], il doit exister une et une seule définition externe pour cet identificateur quelque part dans l'ensemble du programme.

Notes

Les définitions inline dans différentes unités de traduction ne sont pas soumises à la règle de la définition unique. Voir inline pour les détails sur les définitions de fonctions inline.
