Définit la sémantique du stockage mémoire de l'ordinateur pour les besoins de la machine abstraite C.

Les données (mémoire) disponibles pour un programme C forment une ou plusieurs suites contiguës de octets. Chaque octet en mémoire possède une adresse unique.

Octet

Un octet est la plus petite unité de mémoire adressable. Il est défini comme une suite contiguë de bits, suffisamment grande pour contenir n'importe quel membre du jeu de caractères d'exécution de base (les 96 caractères qui doivent tenir sur un seul octet). C prend en charge des octets de 8 bits ou plus.

Les types char, unsigned char et signed char utilisent un octet à la fois pour le stockage et pour la représentation des valeurs. Le nombre de bits d'un octet est accessible via CHAR_BIT.

Pour l'utilisation des octets afin de représenter les valeurs d'autres types fondamentaux (y compris les dispositions mémoire big-endian et little-endian), voir représentation des objets

Emplacement mémoire

Un emplacement mémoire est

  • un objet de type scalaire (type arithmétique, type pointeur, type énumération)
  • ou la plus grande suite contiguë de champs de bits de longueur non nulle
struct S
{
    char a;     // emplacement mémoire #1
    int b : 5;  // emplacement mémoire #2
    int c : 11, // emplacement mémoire #2 (suite)
          : 0,
        d : 8;  // emplacement mémoire #3
    struct
    {
        int ee : 8; // emplacement mémoire #4
    } e;
} obj; // L'objet 'obj' est constitué de 4 emplacements mémoire distincts

Threads et courses de données

Un fil d'exécution est un flot de contrôle au sein d'un programme qui commence par l'invocation d'une fonction de niveau supérieur par thrd_create ou par d'autres moyens.

Tout thread peut potentiellement accéder à n'importe quel objet du programme (les objets à durée de stockage automatique et local au thread peuvent néanmoins être accédés par un autre thread via un pointeur).

Différents fils d'exécution sont toujours autorisés à accéder (en lecture et en modification) à des emplacements mémoire différents de façon concurrente, sans interférence ni exigence de synchronisation. (notez qu'il n'est pas sûr de mettre à jour simultanément deux champs de bits non atomiques d'une même structure si tous les membres déclarés entre eux sont aussi des champs de bits (de longueur non nulle), quelles que soient les tailles de ces champs intermédiaires)

Lorsqu'une évaluation d'expression écrit dans un emplacement mémoire et qu'une autre évaluation lit ou modifie ce même emplacement, les expressions sont dites en conflit. Un programme qui comporte deux évaluations en conflit présente une course de données, sauf si l'une des conditions suivantes est remplie :

  • les deux évaluations en conflit sont des opérations atomiques
  • l'une des évaluations en conflit arrive avant l'autre (voir memory_order)

Si une course de données se produit, le comportement du programme est indéfini.

(en particulier, mtx_unlock est synchronisé avec, et donc arrive avant mtx_lock du même mutex par un autre thread, ce qui permet d'utiliser des verrous mutex pour se prémunir contre les courses de données)

Ordre mémoire

Lorsqu'un fil lit une valeur depuis un emplacement mémoire, il peut voir la valeur initiale, la valeur écrite dans le même fil, ou la valeur écrite dans un autre fil. Voir memory_order pour les détails sur l'ordre dans lequel les écritures effectuées par les fils deviennent visibles pour les autres fils.

(depuis C11)
