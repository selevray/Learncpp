Initialisation de struct et d'union

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Lors de l'initialisation d'un objet de type struct ou union, l'initialiseur doit être une liste non vide, (jusqu'à C23) entre accolades, séparée par des virgules, d'initialiseurs pour les membres :

| | | | = { expression , ... } | (1) | (jusqu'à C99) | | | = { designator(optionnel) expression , ... } | (2) | (depuis C99) | | | = { } | (3) | (depuis C23) | |

où le designator est une suite (séparée par des espaces ou contiguë) de désignateurs de membres individuels de la forme . member et de désignateurs de tableau de la forme [ index ].

Tous les membres non initialisés explicitement sont initialisés à vide.

Explication

Lors de l'initialisation d'une union, la liste d'initialisation ne doit contenir qu'un seul membre, qui initialise le premier membre de l'unionsauf si un désignateur est utilisé (depuis C99).

union { int x; char c[4]; }
  u = {1},           // rend u.x actif avec la valeur 1
 u2 = { .c={'\1'} }; // rend u2.c actif avec la valeur {'\1','\0','\0','\0'}

Lors de l'initialisation d'une struct, le premier initialiseur de la liste initialise le premier membre déclaré(sauf si un désignateur est spécifié) (depuis C99), et tous les initialiseurs suivants sans désignateurs *(depuis C99)*initialisent les membres de la struct déclarés après celui initialisé par l'expression précédente.

struct point {double x,y,z;} p = {1.2, 1.3}; // p.x=1.2, p.y=1.3, p.z=0.0
div_t answer = {.quot = 2, .rem = -1 };      // l'ordre des éléments de div_t peut varier

Un désignateur fait que l'initialiseur suivant initialise le membre de struct décrit par le désignateur. L'initialisation se poursuit ensuite dans l'ordre de déclaration, en commençant par l'élément déclaré après celui décrit par le désignateur.

struct {int sec,min,hour,day,mon,year;} z
   = {.day=31,12,2014,.sec=30,15,17}; // initialise z à {30,15,17,31,12,2014}

(depuis C99)

C'est une erreur de fournir plus d'initialiseurs que de membres.

Initialisation imbriquée

Si les membres de la struct ou de l'union sont des tableaux, des structs ou des unions, les initialiseurs correspondants dans la liste d'initialiseurs entre accolades sont tous les initialiseurs valides pour ces membres, sauf que leurs accolades peuvent être omises comme suit :

Si l'initialiseur imbriqué commence par une accolade ouvrante, tout l'initialiseur imbriqué jusqu'à son accolade fermante initialise le sous-objet correspondant. Chaque accolade ouvrante établit un nouvel objet courant. Les membres de l'objet courant sont initialisés dans leur ordre naturel, sauf si des désignateurs sont utilisés (depuis C99) : éléments de tableau dans l'ordre des indices, membres de struct dans l'ordre de déclaration, seul le premier membre déclaré de toute union. Les sous-objets de l'objet courant qui ne sont pas explicitement initialisés avant l'accolade fermante sont initialisés à vide.

struct example {
    struct addr_t {
       uint32_t port;
    } addr;
    union {
       uint8_t a8[4];
       uint16_t a16[2];
    } in_u;
};
struct example ex = { // début de la liste d'initialisation pour la structure example
                     { // début de la liste d'initialisation pour ex.addr
                        80 // unique membre de la structure initialisée
                     }, // fin de la liste d'initialisation pour ex.addr
                     { // début de la liste d'initialisation pour ex.in_u
                        {127,0,0,1} // initialise le premier élément de l'union
                     } };

Si l'initialiseur imbriqué ne commence pas par une accolade ouvrante, seuls assez d'initialiseurs de la liste sont pris en compte pour les éléments ou membres du tableau, de la struct ou de l'union membre ; les initialiseurs restants servent à initialiser le membre de struct suivant :

struct example ex = {80, 127, 0, 0, 1}; // 80 initialise ex.addr.port
                                        // 127 initialise ex.in_u.a8[0]
                                        // 0 initialise ex.in_u.a8[1]
                                        // 0 initialise ex.in_u.a8[2]
                                        // 1 initialise ex.in_u.a8[3]

Lorsque les désignateurs sont imbriqués, les désignateurs des membres suivent les désignateurs des structs/unions/tableaux englobants. Dans une liste d'initialisation entre crochets imbriquée, le désignateur le plus externe fait référence à l'objet courant et ne sélectionne le sous-objet à initialiser que dans l'objet courant.

struct example ex2 = { // l'objet courant est ex2, les désignateurs concernent les membres de example
                       .in_u.a8[0]=127, 0, 0, 1, .addr=80};
struct example ex3 = {80, .in_u={ // change l'objet courant en l'union ex.in_u
                           127,
                           .a8[2]=1 // ce désignateur désigne le membre de in_u
                      } };

Si un sous-objet est explicitement initialisé deux fois (ce qui peut arriver lorsque des désignateurs sont utilisés), l'initialiseur qui apparaît plus loin dans la liste est celui utilisé (le précédent peut ne pas être évalué) :

struct {int n;} s = {printf("a\n"), // ceci peut être affiché ou omis
                     .n=printf("b\n")}; // toujours affiché

Bien que les sous-objets non initialisés soient initialisés implicitement, l'initialisation implicite d'un sous-objet ne remplace jamais l'initialisation explicite de ce même sous-objet si elle apparaît plus tôt dans la liste (choisissez clang pour observer la sortie correcte) :

#include <stdio.h>
typedef struct { int k; int l; int a[2]; } T;
typedef struct { int i;  T t; } S;
T x = {.l = 43, .k = 42, .a[1] = 19, .a[0] = 18 };
 // x initialisé à {42, 43, {18, 19} }
int main(void)
{
    S l = { 1,          // initialise l.i à 1
           .t = x,      // initialise l.t à {42, 43, {18, 19} }
           .t.l = 41,   // change l.t en {42, 41, {18, 19} }
           .t.a[1] = 17 // change l.t en {42, 41, {18, 17} }
          };
    printf("l.t.k is %d\n", l.t.k); // .t = x fixe explicitement l.t.k à 42
                                    // .t.l = 41 remettrait implicitement l.t.k à zéro
}

Output:

l.t.k is 42

Cependant, lorsqu'un initialiseur commence par une accolade ouvrante, son objet courant est entièrement réinitialisé et tous les initialiseurs explicites antérieurs pour l'un de ses sous-objets sont ignorés :

struct fred { char s[4]; int n; };
struct fred x[ ] = { { { "abc" }, 1 }, // initialise x[0] à { {'a','b','c','\0'}, 1 }
                      [0].s[0] = 'q'   // change x[0] en { {'q','b','c','\0'}, 1 }
                   };
struct fred y[ ] = { { { "abc" }, 1 }, // initialise y[0] à { {'a','b','c','\0'}, 1 }
                     [0] = { // l'objet courant est maintenant la totalité de y[0]
                             .s[0] = 'q'
                            } // remplace y[0] par { {'q','\0','\0','\0'}, 0 }
                    };

(depuis C99)

Notes

La liste d'initialisation peut se terminer par une virgule, qui est ignorée.

struct {double x,y;} p = {1.0,
                          2.0, // virgule finale acceptée
                          };

En C, la liste d'initialiseurs entre accolades ne peut pas être vide (notez que C++ autorise les listes vides, et notez aussi qu'une struct en C ne peut pas être vide) :

(jusqu'à C23)

La liste d'initialisation peut être vide en C comme en C++ :

(depuis C23)

struct {int n;} s = {0}; // OK
struct {int n;} s = {}; // Erreur jusqu'en C23 : la liste d'initialisation ne peut pas être vide
                        // OK depuis C23 : s.n est initialisé à 0
struct {} s = {}; // Erreur : la structure ne peut pas être vide

Chaque expression de la liste d'initialisation doit être une expression constante lors de l'initialisation d'agrégats de n'importe quelle durée de stockage.

(jusqu'à C99)

Comme pour toute autre initialisation, chaque expression de la liste d'initialisation doit être une expression constante lors de l'initialisation d'agrégats à durée de stockage statiqueou thread-local (depuis C11) durée de stockage :

static struct {char* p} s = {malloc(1)}; // error

L'ordre d'évaluation des sous-expressions de tout initialiseur est séquencé de façon indéterminée (mais pas en C++ depuis C++11) :

int n = 1;
struct {int x,y;} p = {n++, n++}; // non spécifié, mais comportement bien défini :
                                  // n est incrémenté deux fois dans un ordre arbitraire
                                  // p égal à {1,2} et {2,1} sont tous deux valides

(depuis C99)

#include <stdio.h>

int main(void)
{
    char buff[70];
    // les initialiseurs désignés simplifient l'utilisation des structures dont
    // l'ordre des membres est non spécifié
    struct tm my_time = { .tm_year=2012-1900, .tm_mon=9, .tm_mday=9,
                          .tm_hour=8, .tm_min=10, .tm_sec=20 };
    strftime(buff, sizeof buff, "%A %c", &my_time);
    puts(buff);
}
