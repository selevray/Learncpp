Objets et alignement

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les programmes C créent, détruisent, accèdent et manipulent des objets.

Un objet en C est une zone de stockage de données dans l'environnement d'exécution, dont le contenu peut représenter des valeurs (une valeur est la signification du contenu d'un objet, lorsqu'il est interprété comme ayant un type spécifique).

Chaque objet possède

  • une taille (peut être déterminée avec sizeof)
  • une exigence d'alignement(peut être déterminée par [_Alignof (jusqu'à C23) | alignof (depuis C23)]) (depuis C11)
  • durée de stockage (automatique, statique, allouée, thread-local)
  • durée de vie (égale à la durée de stockage ou temporaire)
  • type effectif (voir ci-dessous)
  • valeur (qui peut être indéterminée)
  • optionnellement, un identifiant qui désigne cet objet.

Les objets sont créés par des déclarations, des fonctions d'allocation, des littéraux de chaîne, des littéraux composés, et par des expressions non-lvalue qui renvoient des structures ou unions avec des membres tableaux.

Représentation de l'objet

Sauf pour les champs de bits, les objets sont composés de séquences contiguës d'un ou plusieurs octets, chacun constitué de CHAR_BIT bits, et peuvent être copiés avec memcpy dans un objet de type unsigned char[n], où n est la taille de l'objet. Le contenu du tableau résultant est connu sous le nom de représentation de l'objet.

Si deux objets ont la même représentation d'objet, ils se comparent égaux (sauf s'il s'agit de NaN à virgule flottante). La réciproque n'est pas vraie : deux objets qui se comparent égaux peuvent avoir des représentations d'objet différentes, car tous les bits de la représentation d'objet ne participent pas nécessairement à la valeur. De tels bits peuvent servir de bourrage pour satisfaire l'exigence d'alignement, aux contrôles de parité, pour indiquer des représentations de piège, etc.

Si une représentation d'objet ne représente aucune valeur du type de l'objet, elle est appelée représentation de piège. Accéder à une représentation de piège de toute autre manière que sa lecture via une expression lvalue de type caractère est un comportement indéfini. La valeur d'une structure ou d'une union n'est jamais une représentation de piège, même si l'un de ses membres en est une.

Pour les objets de type char, signed char et unsigned char, chaque bit de la représentation d'objet doit participer à la représentation de valeur et chaque motif de bits possible représente une valeur distincte (aucun bourrage, bit de piège ou représentation multiple n'est autorisé).

Lorsque des objets de types entiers (short, int, long, long long) occupent plusieurs octets, l'utilisation de ces octets est définie par l'implémentation, mais les deux implémentations dominantes sont le big-endian (POWER, Sparc, Itanium) et le little-endian (x86, x86_64) : une plateforme big-endian stocke l'octet de poids fort à l'adresse la plus basse de la zone de stockage occupée par l'entier, une plateforme little-endian stocke l'octet de poids faible à l'adresse la plus basse. Voir Endianness pour plus de détails. Voir aussi l'exemple ci-dessous.

Bien que la plupart des implémentations n'autorisent ni représentations pièges, ni bits de remplissage, ni représentations multiples pour les types entiers, il existe des exceptions ; par exemple, une valeur d'un type entier sur Itanium peut être une représentation piège.

Type effectif

Chaque objet possède un type effectif, qui détermine quels accès lvalue sont valides et lesquels violent les règles d'aliasing strict.

Si l'objet a été créé par une déclaration, le type déclaré de cet objet est le type effectif de l'objet.

Si l'objet a été créé par une fonction d'allocation (y compris realloc), il n'a pas de type déclaré. Un tel objet acquiert un type effectif comme suit :

  • La première écriture dans cet objet via une lvalue ayant un type autre que caractère, moment où le type de cette lvalue devient le type effectif de cet objet pour cette écriture et toutes les lectures suivantes.
  • memcpy ou memmove copient un autre objet dans cet objet, ou copient un autre objet dans cet objet sous forme de tableau de type caractère, moment où le type effectif de l'objet source (s'il en avait un) devient le type effectif de cet objet pour cette écriture et toutes les lectures suivantes.
  • Tout autre accès à l'objet sans type déclaré : le type effectif est le type de la lvalue utilisée pour l'accès.

Alias strict

Étant donné un objet de type effectif T1, utiliser une expression lvalue (typiquement, le déréférencement d'un pointeur) d'un type différent T2 est un comportement indéfini, sauf si :

  • T2 et T1 sont des types compatibles.
  • T2 est une version qualifiée cvr d'un type compatible avec T1.
  • T2 est une version signée ou non signée d'un type compatible avec T1.
  • T2 est un type agrégat ou un type union qui inclut parmi ses membres l'un des types précédents (y compris, récursivement, un membre d'un sous-agrégat ou d'une union contenue).
  • T2 est un type caractère (char, signed char ou unsigned char).
int i = 7;
char* pc = (char*)(&i);

if (pc[0] == '\x7') // l'aliasing via char est OK
    puts("This system is little-endian");
else
    puts("This system is big-endian");

float* pf = (float*)(&i);
float d = *pf; // UB : une lvalue float *p ne peut pas être utilisée pour accéder à un int

Ces règles déterminent si, lors de la compilation d'une fonction recevant deux pointeurs, le compilateur doit émettre du code qui relit l'un après avoir écrit via l'autre :

// int* et double* ne peuvent pas être en alias
void f1(int* pi, double* pd, double d)
{
    // la lecture de *pi ne peut être faite qu'une seule fois, avant la boucle
    for (int i = 0; i < *pi; i++)
        *pd++ = d;
}

struct S { int a, b; };

// int* et struct S* peuvent être en alias car S est un type agrégat avec un membre de type int
void f2(int* pi, struct S* ps, struct S s)
{
    // la lecture de *pi doit avoir lieu après chaque écriture effectuée via *ps
    for (int i = 0; i < *pi; i++)
        *ps++ = s;
}

Notez que le qualificateur restrict peut être utilisé pour indiquer que deux pointeurs ne se recouvrent pas (alias), même si les règles ci-dessus le permettraient.

Notez que le type-punning peut aussi être effectué via le membre inactif d'une union.

Alignement

Chaque type d'objet complet possède une propriété appelée exigence d'alignement, qui est une valeur entière de type size_t représentant le nombre d'octets entre des adresses successives auxquelles des objets de ce type peuvent être alloués. Les valeurs d'alignement valides sont les puissances entières non négatives de deux.

L'exigence d'alignement d'un type peut être interrogée avec [_Alignof (jusqu'à C23) | alignof (depuis C23)].

(depuis C11)

Afin de satisfaire les exigences d'alignement de tous les membres d'une struct, un bourrage peut être inséré après certains de ses membres.

#include <stdalign.h>
#include <stdio.h>

// les objets de la structure S peuvent être alloués à n'importe quelle adresse
// car S.a et S.b peuvent tous deux être alloués à n'importe quelle adresse
struct S
{
    char a; // size: 1, alignment: 1
    char b; // size: 1, alignment: 1
}; // size: 2, alignment: 1

// les objets de la structure X doivent être alloués à des frontières de 4 octets
// car X.n doit être alloué sur des frontières de 4 octets
// car l'exigence d'alignement de int est (généralement) 4
struct X
{
    int n;  // size: 4, alignment: 4
    char c; // size: 1, alignment: 1
    // trois octets de remplissage
}; // size: 8, alignment: 4

int main(void)
{
    printf("sizeof(struct S) = %zu\n", sizeof(struct S));
    printf("alignof(struct S) = %zu\n", alignof(struct S));
    printf("sizeof(struct X) = %zu\n", sizeof(struct X));
    printf("alignof(struct X) = %zu\n", alignof(struct X));
}

Sortie possible :

sizeof(struct S) = 2
alignof(struct S) = 1
sizeof(struct X) = 8
alignof(struct X) = 4

Chaque type d'objet impose son exigence d'alignement à chaque objet de ce type. L'alignement le plus faible (le plus petit) est celui des types char, signed char et unsigned char, et est égal à 1. L'alignement fondamental le plus strict (le plus grand) de tout type est défini par l'implémentationet égal à l'alignement de max_align_t (depuis C11).

Les alignements fondamentaux sont pris en charge pour les objets de tous les types de durées de stockage.

Si l'alignement d'un objet est rendu plus strict (plus grand) que max_align_t à l'aide de [_Alignof (jusqu'à C23) | alignof (depuis C23)], il possède une exigence d'alignement étendue. Un type struct ou union dont un membre possède un alignement étendu est un type sur-aligné. Il est défini par l'implémentation si les types sur-alignés sont pris en charge, et leur prise en charge peut varier selon chaque durée de stockage.

Si un type struct ou union S ne possède aucun membre d'un type sur-aligné et n'est pas déclaré avec un spécificateur d'alignement qui spécifie un alignement étendu, S possède un alignement fondamental.

La version atomique de chaque type arithmétique ou pointeur possède un alignement fondamental.

(depuis C11)
