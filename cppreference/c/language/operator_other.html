Appel de fonction

L'expression d'appel de fonction a la forme

| | | | expression ( argument-list ﻿*(facultatif)* ) | | | |

where

  • expression — toute expression de type pointeur vers fonction (après conversions lvalue)
  • argument-list — liste d'expressions séparées par des virgules (qui ne peuvent pas être des opérateurs virgule) de tout type objet complet. Peut être omise lors de l'appel de fonctions sans argument.

Le comportement de l'expression d'appel de fonction dépend de si le prototype de la fonction appelée est dans la portée au point d'appel.

Appel d'une fonction avec prototype

  1. Le nombre de paramètres doit être égal au nombre d'arguments (sauf si le paramètre d'ellipse est utilisé).

  2. Le type de chaque paramètre doit être un type tel que la conversion implicite comme par affectation existe et convertisse le type non qualifié de l'argument correspondant en le type du paramètre.

De plus, pour chaque paramètre de type tableau qui utilise le mot-clé static entre [ et ], l'expression d'argument doit désigner un pointeur vers l'élément d'un tableau ayant au moins autant d'éléments que spécifié dans l'expression de taille du paramètre.

(depuis C99)

  1. Les arguments sont évalués dans un ordre non spécifié et sans séquencement.

  2. L'affectation est effectuée pour copier la valeur de chaque argument dans le paramètre de fonction correspondant, en ignorant les qualificateurs de type du type du paramètre et, le cas échéant, de ses éléments ou membres éventuellement récursifs (note : la fonction peut modifier ses paramètres, et ces modifications n'affectent pas les arguments ; les appels de fonction en C ne sont que par valeur).

  • s'il existe un paramètre d'ellipse finale, les promotions d'arguments par défaut sont effectuées sur les arguments restants, qui sont rendus disponibles à va_list.
  1. La fonction est exécutée, et la valeur qu'elle retourne devient la valeur de l'expression d'appel de fonction (si la fonction retourne void, l'expression d'appel de fonction est une expression de type void)
void f(char* p, int x) {}
int main(void)
{
    f("abc", 3.14); // conversions tableau en pointeur et flottant en entier
}

Appel d'une fonction sans prototype

  1. Les arguments sont évalués dans un ordre non spécifié et sans séquencement.

  2. Les promotions d'arguments par défaut sont effectuées sur chaque expression d'argument.

  3. L'affectation est effectuée pour copier la valeur de chaque argument dans le paramètre de fonction correspondant, en ignorant les qualificateurs de type du type du paramètre et, le cas échéant, de ses éléments ou membres éventuellement récursifs.

  4. La fonction est exécutée, et la valeur qu'elle retourne devient la valeur de l'expression d'appel de fonction (si la fonction retourne void, l'expression d'appel de fonction est une expression de type void)

void f(); // sans prototype
int main(void)
{
    f(1, 1.0f); // UB sauf si f est définie pour prendre un int et un double
}
void f(int a, double c) {}

Le comportement d'un appel de fonction vers une fonction sans prototype est indéfini si

  • le nombre d'arguments ne correspond pas au nombre de paramètres.
  • les types promus des arguments ne sont pas compatibles avec les types promus des paramètres, à l'exception du cas suivant :
  • les versions signée et non signée d'un même type entier sont considérées comme compatibles si la valeur de l'argument est représentable par les deux types.
  • les pointeurs vers void et les pointeurs vers des types caractères (éventuellement qualifiés cvr) sont considérés comme compatibles

(jusqu'à C23)

Notes

Les évaluations de expression désignant la fonction à appeler et de tous les arguments sont non séquencées les unes par rapport aux autres (mais il existe un point de séquence avant le début de l'exécution du corps de la fonction)

(*pf[f1()]) (f2(), f3() + f4()); // f1, f2, f3, f4 peuvent être appelées dans n'importe quel ordre

Bien que l'appel de fonction ne soit défini que pour les pointeurs vers des fonctions, il fonctionne avec les désignateurs de fonction grâce à la conversion implicite fonction-vers-pointeur.

int f(void) { return 1; }
int (*pf)(void) = f;

int main(void)
{
    f();    // convertir f en pointeur, puis appeler
    (&f)(); // créer un pointeur vers la fonction, puis appeler

    pf();    // appeler la fonction
    (*pf)(); // obtenir le désignateur de fonction, le convertir en pointeur, puis appeler

    (****f)(); // convertir en pointeur, obtenir la fonction, répéter 4 fois, puis appeler
    (****pf)(); // aussi OK
}

Les fonctions qui ignorent les arguments inutilisés, comme printf, doivent être appelées avec un prototype en portée (le prototype de ces fonctions utilise nécessairement le paramètre d'ellipse finale) afin d'éviter d'invoquer un comportement indéfini.

La formulation actuelle de la norme concernant la sémantique de préparation des paramètres de fonction est défectueuse, car elle spécifie que les paramètres sont affectés à partir des arguments lors de l'appel, ce qui rejette à tort les types de paramètres ou de membres qualifiés const, et applique de manière inappropriée la sémantique de volatile, impossible à implémenter pour les paramètres de fonction sur de nombreuses plateformes. Un rapport de défaut post-C11 DR427 proposait de remplacer cette sémantique, de l'affectation vers l'initialisation, mais il a été clos comme n'étant pas un défaut.

Une expression d'appel de fonction dont expression est entièrement constitué d'un identifiant, et que cet identifiant n'est pas déclaré, agit comme si l'identifiant était déclaré comme

extern int identifier(); // renvoie int et n'a pas de prototype

Ainsi, le programme complet suivant est valide en C89 :

main()
{
    int n = atoi("123"); // déclare implicitement atoi comme int atoi()
}

(jusqu'à C99)

Opérateur virgule

L'expression de l'opérateur virgule a la forme

| | | | lhs , rhs | | | |

where

  • lhs — une expression quelconque
  • rhs — une expression quelconque autre qu'un autre opérateur virgule (autrement dit, l'associativité de l'opérateur virgule est de gauche à droite)

D'abord, l'opérande de gauche, lhs, est évalué et sa valeur de résultat est ignorée.

Ensuite, un point de séquence intervient, de sorte que tous les effets de bord de lhs sont achevés.

Puis, l'opérande de droite, rhs, est évalué et son résultat est renvoyé par l'opérateur virgule en tant que non-lvalue.

Notes

Le type de lhs peut être void (c'est-à-dire qu'il peut s'agir d'un appel à une fonction retournant void, ou d'une expression transtypée vers void)

L'opérateur virgule peut être une lvalue en C++, mais jamais en C

L'opérateur virgule peut retourner une struct (les seules autres expressions retournant des struct sont les littéraux composés, les appels de fonction, les affectations et l'opérateur conditionnel)

Dans les contextes suivants, l'opérateur virgule ne peut pas apparaître au niveau supérieur d'une expression, car la virgule a une signification différente :

  • liste d'arguments d'un appel de fonction
  • expression d'initialisation ou liste d'initialisation
  • sélection générique

Si l'opérateur virgule doit être utilisé dans un tel contexte, il doit être mis entre parenthèses :

// int n = 2,3; // erreur, la virgule est considérée comme le début du déclarateur suivant
// int a[2] = {1,2,3}; // erreur : plus d'initialiseurs que d'éléments
int n = (2,3), a[2] = {(1,2),3}; // OK

f(a, (t=3, t+2), c); // OK, d'abord, stocke 3 dans t, puis appelle f avec trois arguments

L'opérateur virgule de niveau supérieur est également interdit dans les bornes de tableau

// int a[2,3]; // erreur
int a[(2,3)]; // OK, tableau VLA de taille 3 (VLA car (2,3) n'est pas une expression constante)

L'opérateur virgule n'est pas autorisé dans les expressions constantes, qu'il se trouve au niveau supérieur ou non

// static int n = (1,2); // Erreur : une expression constante ne peut pas appeler l'opérateur virgule

Opérateur conditionnel

L'expression de l'opérateur conditionnel a la forme

| | | | condition ? expression-true : expression-false | | | |

where

  • condition — une expression de type scalaire
  • expression-true — l'expression évaluée si la condition est différente de zéro
  • expression-false — l'expression évaluée si la condition est égale à zéro

Seules les expressions suivantes sont autorisées comme expression-true et expression-false

  • deux expressions de n'importe quel type arithmétique
  • deux expressions du même type struct ou union
  • deux expressions de type void
  • deux expressions de type pointeur, pointant vers des types compatibles, en ignorant les qualificateurs cvr
  • deux expressions de type nullptr_t

(depuis C23)

  • une expression est un pointeur et l'autre est la constante de pointeur nul (telle que NULL)ou une valeur nullptr_t (depuis C23)
  • une expression est un pointeur vers un objet et l'autre est un pointeur vers void (éventuellement qualifié)

  1. Évalue d'abord condition. Il existe un point de séquence après cette évaluation.

  2. Si le résultat de condition est différent de zéro, exécute expression-true, sinon exécute expression-false

  3. Effectue une conversion du résultat de l'évaluation vers le type commun, défini comme suit :

  4. si les expressions ont un type arithmétique, le type commun est le type obtenu après les conversions arithmétiques usuelles

  5. si les expressions ont un type struct/union, le type commun est ce même type struct/union

  6. si les expressions sont toutes deux void, l'expression entière de l'opérateur conditionnel est une expression de type void

  7. si l'une est un pointeur et l'autre une constante de pointeur nulou une valeur nullptr_t (depuis C23), le type est celui de ce pointeur

  8. si les deux sont des pointeurs, le résultat est le pointeur vers le type qui combine les qualificateurs cvr des deux types pointés (c'est-à-dire que si l'un est const int* et l'autre volatile int*, le résultat est const volatile int*), et si les types étaient différents, le type pointé est le type composite.

  9. si l'un est un pointeur vers void, le résultat est un pointeur vers void avec les qualificateurs cvr combinés

  1. si les deux ont un type nullptr_t, le type commun est également nullptr_t

(depuis C23)

#define ICE(x) (sizeof(*(1 ? ((void*)((x) * 0l)) : (int*)1)))

// si x est une expression constante entière alors la macro se développe en

sizeof(*(1 ? NULL : (int *) 1))  // (void *)((x)*0l)) -> NULL

// selon le point (4), ceci se convertit ensuite en

sizeof(int)

// si x n'est pas une expression constante entière alors la macro se développe en
// selon le point (6)

(sizeof(*(void *)(x))           // Erreur due à un type incomplet

Notes

L'opérateur conditionnel n'est jamais une expression lvalue, bien qu'il puisse renvoyer des objets de type struct/union. Les seules autres expressions pouvant renvoyer des struct sont l'affectation, la virgule, l'appel de fonction et le littéral composé.

Notez qu'en C++, il peut s'agir d'une expression lvalue.

Voir priorité des opérateurs pour les détails sur la priorité relative de cet opérateur et de l'affectation.

L'opérateur conditionnel a une associativité de droite à gauche, ce qui permet de les enchaîner

#include <assert.h>

enum vehicle { bus, airplane, train, car, horse, feet };

enum vehicle choose(char arg)
{
    return arg == 'B' ? bus      :
           arg == 'A' ? airplane :
           arg == 'T' ? train    :
           arg == 'C' ? car      :
           arg == 'H' ? horse    :
                        feet     ;
}

int main(void)
{
    assert(choose('H') == horse && choose('F') == feet);
}
