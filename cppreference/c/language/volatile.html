qualificateur de type volatile

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Chaque type individuel du système de types C possède plusieurs versions qualifiées de ce type, correspondant à un, deux, ou les trois qualificateurs const, volatile, et, pour les pointeurs vers des types objets, restrict. Cette page décrit les effets du qualificateur volatile.

Chaque accès (lecture comme écriture) effectué via une expression lvalue de type qualifié volatile est considéré comme un effet de bord observable aux fins de l'optimisation et est évalué strictement selon les règles de la machine abstraite (c'est-à-dire que toutes les écritures sont achevées à un moment donné avant le prochain point de séquence). Cela signifie qu'au sein d'un même fil d'exécution, un accès volatile ne peut être ni optimisé ni réordonné par rapport à un autre effet de bord visible séparé de cet accès par un point de séquence.

Un transtypage d'une valeur non volatile vers un type volatile n'a aucun effet. Pour accéder à un objet non volatile avec la sémantique volatile, son adresse doit être convertie en pointeur vers volatile, puis l'accès doit être effectué par l'intermédiaire de ce pointeur.

Toute tentative de lecture ou d'écriture d'un objet dont le type est qualifié volatile à travers une lvalue non volatile entraîne un comportement indéfini :

volatile int n = 1; // objet de type qualifié volatile
int* p = (int*)&n;
int val = *p; // comportement indéfini

Un membre d'une structure ou d'une union de type qualifié volatile acquiert le qualificateur du type auquel il appartient (que l'accès se fasse via l'opérateur . ou l'opérateur ->) :

struct s { int i; const int ci; } s;
// le type de s.i est int, le type de s.ci est const int
volatile struct s vs;
// les types de vs.i et vs.ci sont volatile int et const volatile int

Si un type tableau est déclaré avec le qualificateur de type volatile (par l'utilisation de typedef), le type tableau n'est pas qualifié volatile, mais son type d'élément l'est.

(jusqu'à C23)

Un type tableau et son type d'élément sont toujours considérés comme ayant le même qualificatif volatile.

(depuis C23)

typedef int A[2][3];
volatile A a = {{4, 5, 6}, {7, 8, 9}}; // tableau de tableaux de volatile int
int* pi = a[0]; // Erreur : a[0] a le type volatile int*
void *unqual_ptr = a; // OK jusqu'à C23 ; erreur depuis C23
// Notes : clang applique la règle en C++/C23 même en modes C89-C17

Si un type fonction est déclaré avec le qualificateur volatile (par l'utilisation de typedef), le comportement est indéfini.

Dans une déclaration de fonction, le mot-clé volatile peut apparaître à l'intérieur des crochets utilisés pour déclarer un type tableau d'un paramètre de fonction. Il qualifie le type pointeur vers lequel le type tableau est transformé.

Les deux déclarations suivantes déclarent la même fonction :

void f(double x[volatile], const double y[volatile]);
void f(double * volatile x, const double * volatile y);

(depuis C99)

Un pointeur vers un type non volatile peut être implicitement converti en pointeur vers la version qualifiée volatile du même type ou d'un type compatible. La conversion inverse nécessite une expression de transtypage.

int* p = 0;
volatile int* vp = p; // OK : ajoute des qualificateurs (int vers volatile int)
p = vp; // Erreur : supprime des qualificateurs (volatile int vers int)
p = (int*)vp; // OK : transtypage

Notez qu'un pointeur vers pointeur vers T n'est pas convertible en pointeur vers pointeur vers volatile T ; pour que deux types soient compatibles, leurs qualificateurs doivent être identiques :

char *p = 0;
volatile char **vpp = &p; // Erreur : char* et volatile char* ne sont pas des types compatibles
char * volatile *pvp = &p; // OK, ajoute des qualificateurs (char* vers char*volatile)

Utilisations de volatile

Les objets 1) static volatile modélisent des ports d'E/S mappés en mémoire, et les objets static const volatile modélisent des ports d'entrée mappés en mémoire, comme une horloge temps réel :

volatile short *ttyport = (volatile short*)TTYPORT_ADDR;
for(int i = 0; i < N; ++i)
    *ttyport = a[i]; // *ttyport est une lvalue de type volatile short

Les objets 2) static volatile de type sig_atomic_t servent à communiquer avec les gestionnaires signal.

Les variables 3) volatile locales à une fonction contenant un appel de la macro setjmp sont les seules variables locales garanties de conserver leur valeur après le retour de longjmp.

  1. De plus, les variables volatile peuvent servir à désactiver certaines formes d'optimisation, par exemple pour désactiver l'élimination des écritures mortes ou le pliage de constantes dans des micro-benchmarks.

Notez que les variables volatile ne conviennent pas à la communication entre threads ; elles n'offrent ni atomicité, ni synchronisation, ni ordre mémoire. La lecture d'une variable volatile modifiée par un autre thread sans synchronisation, ou une modification concurrente depuis deux threads non synchronisés, est un comportement indéfini dû à une course aux données.

volatile

Exemple

montre l'utilisation de volatile pour désactiver les optimisations

#include <stdio.h>
#include <time.h>

int main(void)
{
    clock_t t = clock();
    double d = 0.0;
    for (int n = 0; n < 10000; ++n)
        for (int m = 0; m < 10000; ++m)
            d += d * n * m; // lit et écrit dans une variable non volatile
    printf("Modified a non-volatile variable 100m times. "
           "Time used: %.2f seconds\n",
           (double)(clock() - t)/CLOCKS_PER_SEC);

    t = clock();
    volatile double vd = 0.0;
    for (int n = 0; n < 10000; ++n)
        for (int m = 0; m < 10000; ++m) {
            double prod = vd * n * m; // lit une variable volatile
            vd += prod; // lit et écrit dans une variable volatile
        }
    printf("Modified a volatile variable 100m times. "
           "Time used: %.2f seconds\n",
           (double)(clock() - t)/CLOCKS_PER_SEC);
}

Sortie possible :

Modified a non-volatile variable 100m times. Time used: 0.00 seconds
Modified a volatile variable 100m times. Time used: 0.79 seconds
