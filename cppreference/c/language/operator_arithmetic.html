Débordements

L'arithmétique des entiers non signés est toujours effectuée modulo 2n
où n est le nombre de bits de cet entier particulier. Par exemple, pour unsigned int, ajouter un à UINT_MAX donne 0, et soustraire un à 0 donne UINT_MAX.

Lorsqu'une opération arithmétique sur entiers signés déborde (le résultat ne tient pas dans le type du résultat), le comportement est indéfini : il peut y avoir un retour à zéro selon les règles de la représentation (généralement le complément à deux), un piège peut se déclencher sur certaines plateformes ou en raison des options du compilateur (par exemple -ftrapv dans GCC et Clang), ou le calcul peut être entièrement supprimé par l'optimisation du compilateur.

Environnement en virgule flottante

Si #pragma STDC FENV_ACCESS est défini à ON, tous les opérateurs arithmétiques sur nombres à virgule flottante respectent le sens d'arrondi courant et signalent les erreurs arithmétiques en virgule flottante comme spécifié dans math_errhandling, sauf s'ils font partie d'un initialiseur statique (auquel cas les exceptions en virgule flottante ne sont pas levées et le mode d'arrondi est l'arrondi au plus proche)

Contraction en virgule flottante

Sauf si #pragma STDC FP_CONTRACT est défini à OFF, toute opération arithmétique en virgule flottante peut être effectuée comme si les résultats intermédiaires avaient une étendue et une précision infinies, c'est-à-dire avec des optimisations qui omettent les erreurs d'arrondi et les exceptions en virgule flottante qui seraient observées si l'expression était évaluée exactement telle qu'écrite. Par exemple, cela permet d'implémenter (x*y) + z avec une seule instruction processeur d'multiplication-addition fusionnée, ou d'optimiser a = x*x*x*x; en tmp = x*x; a = tmp*tmp.

Indépendamment de la contraction, les résultats intermédiaires des opérations arithmétiques en virgule flottante peuvent avoir une étendue et une précision différentes de celles indiquées par leur type, voir FLT_EVAL_METHOD

Arithmétique unaire

Les expressions d'opérateurs arithmétiques unaires ont la forme

| | | | + expression | (1) | | | | - expression | (2) | | |

  1. plus unaire (promotion)

  2. moins unaire (négation)

  • expression — expression de n'importe quel type arithmétique

Le plus unaire et le moins unaire appliquent d'abord les promotions entières à leur opérande, puis

  • le plus unaire renvoie la valeur après promotion
  • le moins unaire renvoie l'opposé de la valeur après promotion (sauf que l'opposé d'un NaN est un autre NaN)

Le type de l'expression est le type après promotion, et la catégorie de valeur est non-lvalue.

Notes

Le moins unaire provoque un comportement indéfini en raison du débordement d'entier signé lorsqu'il est appliqué à INT_MIN, LONG_MIN ou LLONG_MIN, sur les plateformes typiques (complément à deux).

En C++, l'opérateur unaire + peut également être utilisé avec d'autres types intégrés tels que les tableaux et les fonctions, ce qui n'est pas le cas en C.

#include <stdio.h>
#include <complex.h>
#include <limits.h>

int main(void)
{
    char c = 'a';
    printf("sizeof char: %zu sizeof int: %zu\n", sizeof c, sizeof +c);

    printf("-1, where 1 is signed: %d\n", -1);

    // Comportement défini, car l'arithmétique est effectuée pour un entier non signé.
    // Par conséquent, le calcul vaut (-1) modulo (2 puissance n) = UINT_MAX, où n est
    // le nombre de bits de unsigned int. Si unsigned int a une longueur de 32 bits, alors cela
    // donne (-1) modulo (2 puissance 32) = 4294967295
    printf("-1, where 1 is unsigned: %u\n", -1u);

    // Comportement indéfini, car la valeur mathématique de -INT_MIN = INT_MAX + 1
    // (c'est-à-dire 1 de plus que la valeur maximale possible pour signed int)
    //
    // printf("%d\n", -INT_MIN);

    // Comportement indéfini, car la valeur mathématique de -LONG_MIN = LONG_MAX + 1
    // (c'est-à-dire 1 de plus que la valeur maximale possible pour signed long)
    //
    // printf("%ld\n", -LONG_MIN);

    // Comportement indéfini, car la valeur mathématique de -LLONG_MIN = LLONG_MAX + 1
    // (c'est-à-dire 1 de plus que la valeur maximale possible pour signed long long)
    //
    // printf("%lld\n", -LLONG_MIN);

    double complex z = 1 + 2*I;
    printf("-(1+2i) = %.1f%+.1f\n", creal(-z), cimag(-z));
}

Sortie possible :

sizeof char: 1 sizeof int: 4
-1, where 1 is signed: -1
-1, where 1 is unsigned: 4294967295
-(1+2i) = -1.0-2.0

Opérateurs additifs

Les expressions d'opérateurs arithmétiques additifs binaires ont la forme

| | | | lhs + rhs | (1) | | | | lhs - rhs | (2) | | |

  1. addition : lhs et rhs doivent être l'un des cas suivants
  • les deux ont des types arithmétiques, y compris complexes et imaginaires
  • l'un est un pointeur vers un type objet complet, l'autre a un type entier
  1. soustraction : lhs et rhs doivent être l'un des cas suivants
  • les deux ont des types arithmétiques, y compris complexes et imaginaires
  • lhs a un pointeur vers un type objet complet, rhs a un type entier
  • les deux sont des pointeurs vers des objets complets de types compatibles, en ignorant les qualificateurs

Addition et soustraction arithmétiques

Si les deux opérandes ont des types arithmétiques, alors

  • d'abord, les conversions arithmétiques usuelles sont effectuées
  • ensuite, les valeurs des opérandes après conversions sont additionnées ou soustraites selon les règles usuelles des mathématiques (pour la soustraction, rhs est soustrait de lhs), à l'exception de ce qui suit
    • si l'un des opérandes est NaN, le résultat est NaN
    • l'infini moins l'infini est NaN et FE_INVALID est levée
    • l'infini plus l'infini négatif est NaN et FE_INVALID est levée

L'addition et la soustraction complexes et imaginaires sont définies comme suit (notez que le type du résultat est imaginaire si les deux opérandes sont imaginaires, et complexe si un opérande est réel et l'autre imaginaire, comme spécifié par les conversions arithmétiques usuelles) :

+ or - u iv u + iv
x x ± u x ± iv (x ± u) ± iv
iy ±u + iy i(y ± v) ±u + i(y ± v)
x + iy (x ± u) + iy x + i(y ± v) (x ± u) + i(y ± v)

Arithmétique des pointeurs

  • Si le pointeur P pointe sur un élément d'un tableau d'indice I, alors
    • P+N et N+P sont des pointeurs qui pointent sur un élément du même tableau d'indice I+N
    • P-N est un pointeur qui pointe sur un élément du même tableau d'indice I-N

Le comportement n'est défini que si le pointeur d'origine et le pointeur résultat pointent tous deux sur des éléments du même tableau ou sur un emplacement juste après la fin de ce tableau. Notez que l'exécution de p-1 lorsque p pointe sur le premier élément d'un tableau est un comportement indéfini et peut échouer sur certaines plateformes.

  • Si le pointeur P1 pointe sur un élément d'un tableau d'indice I (ou sur un emplacement juste après la fin) et P2 pointe sur un élément du même tableau d'indice J (ou sur un emplacement juste après la fin), alors
    • P1-P2 a la valeur égale à I-J et le type ptrdiff_t (qui est un type entier signé, généralement deux fois plus petit que la taille du plus grand objet pouvant être déclaré)

Le comportement n'est défini que si le résultat tient dans ptrdiff_t.

Pour l'arithmétique des pointeurs, un pointeur vers un objet qui n'est un élément d'aucun tableau est traité comme un pointeur vers le premier élément d'un tableau de taille 1.

// travail en cours
int n = 4, m = 3;
int a[n][m];     // VLA de 4 VLA de 3 int chacun
int (*p)[m] = a; // p == &a[0]
p = p + 1;       // p == &a[1] (l'arithmétique des pointeurs fonctionne de la même manière avec les VLA)
(*p)[2] = 99;    // modifie a[1][2]

Opérateurs multiplicatifs

Les expressions d'opérateurs arithmétiques multiplicatifs binaires ont la forme

| | | | lhs * rhs | (1) | | | | lhs / rhs | (2) | | | | lhs % rhs | (3) | | |

  1. multiplication. lhs et rhs doivent avoir des types arithmétiques

  2. division. lhs et rhs doivent avoir des types arithmétiques

  3. reste. lhs et rhs doivent avoir des types entiers

  • tout d'abord, les conversions arithmétiques usuelles sont effectuées. Ensuite...

Multiplication

L'opérateur binaire * effectue la multiplication de ses opérandes (après les conversions arithmétiques usuelles) selon les définitions arithmétiques habituelles, à l'exception de ce qui suit

  • si l'un des opérandes est un NaN, le résultat est un NaN
  • la multiplication de l'infini par zéro donne NaN et FE_INVALID est levée
  • la multiplication de l'infini par un non-nul donne l'infini (même pour des arguments complexes)

Comme en C, toute valeur complexe ayant au moins une partie infinie est un infini même si son autre partie est un NaN, les règles arithmétiques usuelles ne s'appliquent pas à la multiplication complexe-complexe. Les autres combinaisons d'opérandes flottants suivent le tableau suivant :

* u iv u + iv
x xu i(xv) (xu) + i(xv)
iy i(yu) −yv (−yv) + i(yu)
x + iy (xu) + i(yu) (−yv) + i(xv) règles particulières

Outre la gestion de l'infini, la multiplication complexe ne doit pas provoquer de dépassement de capacité des résultats intermédiaires, sauf lorsque #pragma STDC CX_LIMITED_RANGE est mis à ON, auquel cas la valeur peut être calculée comme par (x+iy)×(u+iv) = (xu-yv)+i(yu+xv), le programmeur assumant la responsabilité de limiter l'intervalle des opérandes et de gérer les infinis.

Malgré l'interdiction d'un dépassement abusif, la multiplication complexe peut lever des exceptions flottantes parasites (sinon il serait extrêmement difficile d'implémenter des versions sans dépassement)

#include <stdio.h>
#include <stdio.h>
#include <complex.h>
#include <math.h>
int main(void)
{

// TODO cas plus simples, en prendre certains du C++

   double complex z = (1 + 0*I) * (INFINITY + I*INFINITY);
// la formule de manuel donnerait
// (1+i0)(∞+i∞) ⇒ (1×∞ – 0×∞) + i(0×∞+1×∞) ⇒ NaN + I*NaN
// mais C donne un infini complexe
   printf("%f + i*%f\n", creal(z), cimag(z));

// la formule de manuel donnerait
// cexp(∞+iNaN) ⇒ exp(∞)×(cis(NaN)) ⇒ NaN + I*NaN
// mais C donne ±∞+i*nan
   double complex y = cexp(INFINITY + I*NAN);
   printf("%f + i*%f\n", creal(y), cimag(y));

}

Sortie possible :

inf + i*inf
inf + i*nan

Division

L'opérateur binaire / divise le premier opérande par le second (après les conversions arithmétiques usuelles) selon les définitions arithmétiques habituelles, à l'exception de ce qui suit

  • lorsque le type après les conversions arithmétiques usuelles est un type entier, le résultat est le quotient algébrique (et non une fraction), [arrondi dans une direction définie par l'implémentation (jusqu'à C99) | tronqué vers zéro (depuis C99)]
  • si l'un des opérandes est un NaN, le résultat est un NaN
  • si le premier opérande est un infini complexe et que le second opérande est fini, le résultat de l'opérateur / est un infini complexe
  • si le premier opérande est fini et que le second opérande est un infini complexe, le résultat de l'opérateur / est un zéro.

Comme en C, toute valeur complexe ayant au moins une partie infinie est un infini même si son autre partie est un NaN, les règles arithmétiques usuelles ne s'appliquent pas à la division complexe-complexe. Les autres combinaisons d'opérandes flottants suivent le tableau suivant :

/ u iv
x x/u i(−x/v)
iy i(y/u) y/v
x + iy (x/u) + i(y/u) (y/v) + i(−x/v)

Outre la gestion de l'infini, la division complexe ne doit pas provoquer de dépassement de capacité des résultats intermédiaires, sauf lorsque #pragma STDC CX_LIMITED_RANGE est mis à ON, auquel cas la valeur peut être calculée comme par (x+iy)/(u+iv) = [(xu+yv)+i(yu-xv)]/(u2
+v2
), le programmeur assumant la responsabilité de limiter l'intervalle des opérandes et de gérer les infinis.

Malgré l'interdiction d'un dépassement abusif, la division complexe peut lever des exceptions flottantes parasites (sinon il serait extrêmement difficile d'implémenter des versions sans dépassement)

Si le second opérande est nul, le comportement est indéfini, sauf si l'arithmétique flottante IEEE est prise en charge et que la division flottante a lieu, auquel cas

  • la division d'un nombre non nul par ±0.0 donne l'infini avec le bon signe et FE_DIVBYZERO est levée
  • la division de 0.0 par 0.0 donne NaN et FE_INVALID est levée

Reste

L'opérateur binaire % donne le reste de la division du premier opérande par le second (après les conversions arithmétiques usuelles).

Le signe du reste est défini de telle sorte que, si le quotient a/b est représentable dans le type du résultat, alors (a/b)*b + a%b == a.

Si le second opérande est nul, le comportement est indéfini.

Si le quotient a/b n'est pas représentable dans le type du résultat, le comportement de a/b et de a%b est indéfini (cela signifie que INT_MIN%-1 est indéfini sur les systèmes à complément à deux)

Note : l'opérateur de reste ne fonctionne pas sur les types flottants, c'est la fonction de bibliothèque fmod qui fournit cette fonctionnalité.

Logique binaire

Les expressions d'opérateurs arithmétiques binaires ont la forme

| | | | ~ rhs | (1) | | | | lhs & rhs | (2) | | | | lhs | rhs | (3) | | | | lhs ^ rhs | (4) | | |

  1. NON binaire

  2. ET binaire

  3. OU binaire

  4. OU exclusif binaire

where

  • lhs, rhs — expressions de type entier

Tout d'abord, les opérateurs &, ^ et | effectuent des conversions arithmétiques usuelles sur les deux opérandes, et l'opérateur ~ effectue des promotions entières sur son unique opérande.

Ensuite, les opérateurs logiques binaires correspondants sont appliqués bit à bit ; c'est-à-dire que chaque bit du résultat est mis à 1 ou à 0 selon l'opération logique (NON, ET, OU ou OU exclusif), appliquée aux bits correspondants des opérandes.

Note : les opérateurs binaires sont couramment utilisés pour manipuler des ensembles de bits et des masques de bits.

Note : pour les types non signés (après promotion), l'expression ~E est équivalente à la valeur maximale représentable par le type du résultat moins la valeur d'origine de E.

#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint32_t a = 0x12345678;
    uint16_t mask = 0x00f0;

    printf("Promoted mask:\t%#010x\n"
           "Value:\t\t%#x\n"
           "Setting bits:\t%#x\n"
           "Clearing bits:\t%#x\n"
           "Selecting bits:\t%#010x\n"
           , mask
           , a
           , a | mask
           , a & ~mask
           , a & mask
    );
}

Sortie possible :

Promoted mask:  0x000000f0
Value:          0x12345678
Setting bits:   0x123456f8
Clearing bits:  0x12345608
Selecting bits: 0x00000070

Opérateurs de décalage

Les expressions à opérateurs de décalage binaire ont la forme

| | | | lhs << rhs | (1) | | | | lhs >> rhs | (2) | | |

  1. décalage à gauche de lhs de rhs bits

  2. décalage à droite de lhs de rhs bits

where

  • lhs, rhs — expressions de type entier

Tout d'abord, des promotions entières sont effectuées, individuellement, sur chaque opérande (Note : contrairement aux autres opérateurs arithmétiques binaires, qui effectuent tous des conversions arithmétiques usuelles). Le type du résultat est le type de lhs après promotion.

Le comportement est indéfini si rhs est négatif ou s'il est supérieur ou égal au nombre de bits de lhs promu.

Pour lhs non signé, la valeur de LHS << RHS est la valeur de LHS * 2RHS
, réduite modulo la valeur maximale du type de retour plus 1 (c'est-à-dire qu'un décalage binaire à gauche est effectué et que les bits sortis du type de destination sont éliminés). Pour lhs signé à valeurs non négatives, la valeur de LHS << RHS est LHS * 2RHS
si elle est représentable dans le type promu de lhs, sinon le comportement est indéfini.

Pour lhs non signé et pour lhs signé à valeurs non négatives, la valeur de LHS >> RHS est la partie entière de LHS / 2RHS
. Pour LHS négatif, la valeur de LHS >> RHS est définie par l'implémentation : dans la plupart des implémentations, cela effectue un décalage arithmétique à droite (de sorte que le résultat reste négatif). Ainsi, dans la plupart des implémentations, le décalage à droite d'un LHS signé remplit les nouveaux bits de poids fort avec le bit de signe d'origine (c'est-à-dire avec 0 s'il était non négatif et 1 s'il était négatif).

#include <stdio.h>
enum {ONE=1, TWO=2};
int main(void)
{
    char c = 0x10;
    unsigned long long ulong_num = 0x123;
    printf("0x123 << 1  = %#llx\n"
           "0x123 << 63 = %#llx\n"   // le dépassement tronque les bits de poids fort pour les nombres non signés
           "0x10  << 10 = %#x\n",    // char est promu en int
           ulong_num << 1, ulong_num << 63, c << 10);
    long long long_num = -1000;
    printf("-1000 >> 1 = %lld\n", long_num >> ONE);  // défini par l'implémentation
}

Sortie possible :

0x123 << 1  = 0x246
0x123 << 63 = 0x8000000000000000
0x10  << 10 = 0x4000
-1000 >> 1 = -500
