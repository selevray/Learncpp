Comportement indéfini

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

La norme du langage C spécifie précisément le comportement observable des programmes en langage C, à l'exception de ceux appartenant aux catégories suivantes :

  • comportement indéfini - il n'existe aucune restriction sur le comportement du programme. Exemples de comportement indéfini : accès mémoire en dehors des bornes d'un tableau, dépassement de capacité d'un entier signé, déréférencement d'un pointeur nul, modification d'un même scalaire plus d'une fois dans une expression sans points de séquence, accès à un objet via un pointeur d'un type différent, etc. Les compilateurs ne sont pas tenus de diagnostiquer un comportement indéfini (bien que de nombreuses situations simples soient diagnostiquées), et le programme compilé n'est pas tenu de faire quoi que ce soit de significatif.

  • comportement non spécifié - deux comportements ou plus sont permis et l'implémentation n'est pas tenue de documenter les effets de chacun. Par exemple, l'ordre d'évaluation, le fait que des littéraux de chaîne identiques soient distincts, etc. Chaque comportement non spécifié produit l'un d'un ensemble de résultats valides et peut produire un résultat différent lorsqu'il est répété dans le même programme.

  • comportement défini par l'implémentation - comportement non spécifié pour lequel chaque implémentation documente la manière dont le choix est effectué. Par exemple, le nombre de bits dans un octet, ou le fait qu'un décalage à droite d'un entier signé soit arithmétique ou logique.

  • comportement propre aux paramètres régionaux - comportement défini par l'implémentation qui dépend de la locale actuellement choisie. Par exemple, le fait que islower renvoie true pour tout caractère autre que les 26 lettres latines minuscules.

(Note : les programmes strictement conformes ne dépendent d'aucun comportement non spécifié, indéfini ou défini par l'implémentation)

Les compilateurs sont tenus d'émettre des messages de diagnostic (erreurs ou avertissements) pour tout programme qui viole une règle de syntaxe C ou une contrainte sémantique, même si son comportement est spécifié comme indéfini ou défini par l'implémentation, ou si le compilateur fournit une extension du langage qui lui permet d'accepter un tel programme. Les diagnostics pour un comportement indéfini ne sont pas exigés par ailleurs.

UB et optimisation

Parce que les programmes C corrects sont exempts de comportement indéfini, les compilateurs peuvent produire des résultats inattendus lorsqu'un programme qui contient effectivement un comportement indéfini est compilé avec l'optimisation activée :

Par exemple,

Dépassement de capacité signé

int foo(int x)
{
    return x + 1 > x; // soit vrai, soit UB dû au dépassement de capacité signé
}

peut être compilé comme (démo)

foo:
        mov     eax, 1
        ret

Accès hors bornes

int table[4] = {0};
int exists_in_table(int v)
{
    // return 1 lors d'une des 4 premières itérations, ou comportement indéfini dû à un accès hors limites
    for (int i = 0; i <= 4; i++)
        if (table[i] == v)
            return 1;
    return 0;
}

Peut être compilé comme (démo)

exists_in_table:
        mov     eax, 1
        ret

Scalaire non initialisé

_Bool p; // variable locale non initialisée
if (p) // accès UB à un scalaire non initialisé
    puts("p is true");
if (!p) // accès UB à un scalaire non initialisé
    puts("p is false");

Peut produire la sortie suivante (observée avec une version ancienne de gcc) :

p is true
p is false

size_t f(int x)
{
    size_t a;
    if (x) // soit x non nul, soit UB
        a = 42;
    return a;
}

Peut être compilé comme (démo)

f:
        mov     eax, 42
        ret

Scalaire invalide

int f(void)
{
    _Bool b = 0;
    unsigned char* p = (unsigned char*)&b;
    *p = 10;
    // la lecture de b est désormais UB
    return b == 0;
}

Peut être compilé comme (démo)

f:
        mov     eax, 11
        ret

Déréférencement d'un pointeur nul

int foo(int* p)
{
    int x = *p;
    if (!p)
        return x; // Soit UB ci-dessus, soit cette branche n'est jamais prise
    else
        return 0;
}

int bar()
{
    int* p = NULL;
    return *p;    // UB inconditionnel
}

peut être compilé comme (démo)

foo:
        xor     eax, eax
        ret
bar:
        ret

Boucle infinie sans effets de bord

Choisissez clang pour observer la sortie présentée

#include <stdio.h>

int fermat()
{
    const int MAX = 1000;
    // Une boucle infinie sans effets de bord est un comportement indéfini
    for (int a = 1, b = 1, c = 1; 1;)
    {
        if (((a * a * a) == ((b * b * b) + (c * c * c))))
            return 1;
        ++a;
        if (a > MAX)
        {
            a = 1;
            ++b;
        }
        if (b > MAX)
        {
            b = 1;
            ++c;
        }
        if (c > MAX)
            c = 1;
    }
    return 0;
}

int main(void)
{
    if (fermat())
        puts("Fermat's Last Theorem has been disproved.");
    else
        puts("Fermat's Last Theorem has not been disproved.");
}
