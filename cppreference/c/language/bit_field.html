Champs de bits

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Déclare un membre de largeur explicite, en bits. Des membres champs de bits adjacents peuvent être empaquetés pour partager et chevaucher les octets individuels.

Une déclaration de champ de bits est une déclaration de membre de struct ou d'union qui utilise le déclarateur suivant :

| | | | identifier ﻿*(facultatif)* : width | | | |

  • identifier — un nom du champ de bits en cours de déclaration. Le nom est facultatif : les champs de bits sans nom introduisent le nombre de bits de bourrage spécifié
  • width — une expression constante entière dont la valeur est supérieure ou égale à zéro et inférieure ou égale au nombre de bits du type sous-jacent. Lorsqu'elle est strictement positive, il s'agit du nombre de bits qu'occupera ce champ de bits. La valeur zéro n'est autorisée que pour les champs de bits sans nom et a une signification particulière : elle indique que le champ de bits suivant dans la définition de la classe commencera à la frontière d'une unité d'allocation.

Explication

Les champs de bits ne peuvent avoir qu'un seul des types suivants (éventuellement qualifié const ou volatile) :

  • unsigned int, pour les champs de bits non signés (par ex. unsigned int b : 3; a pour intervalle [0,7])
  • signed int, pour les champs de bits signés (signed int b : 3; a pour intervalle [-4,3])
  • int, pour les champs de bits dont la signature est définie par l'implémentation (notez que cela diffère de la signification du mot-clé int partout ailleurs, où il signifie « signed int »). Par exemple, int b : 3; peut avoir pour intervalle de valeurs [0,7] ou [-4,3].
  • _Bool, pour les champs de bits d'un seul bit (par ex. bool x : 1;) a pour intervalle [0,1] et les conversions implicites vers et depuis ce type suivent les règles de conversion booléenne.

(depuis C99)

  • types entiers à précision binaire (par ex. _BitInt(5) : 4; a pour intervalle [-8,7] et unsigned _BitInt(5) : 4; a pour intervalle [0,15]).

(depuis C23)

D'autres types définis par l'implémentation peuvent être acceptables. Il est également défini par l'implémentation qu'un champ de bits puisse être de type atomique. (depuis C11) Le nombre de bits d'un champ de bits (width) fixe la limite de l'intervalle des valeurs qu'il peut contenir :

#include <stdio.h>

struct S
{
    // champ non signé de trois bits,
    // les valeurs autorisées sont 0...7
    unsigned int b : 3;
};

int main(void)
{
    struct S s = {7};
    ++s.b; // dépassement de capacité non signé
    printf("%d\n", s.b); // output: 0
}

Plusieurs champs de bits adjacents peuvent (et sont généralement) empaquetés ensemble :

#include <stdio.h>

struct S
{
    // occupera généralement 4 octets :
    // 5 bits : valeur de b1
    // 11 bits : inutilisés
    // 6 bits : valeur de b2
    // 2 bits : valeur de b3
    // 8 bits : inutilisés
    unsigned b1 : 5, : 11, b2 : 6, b3 : 2;
};

int main(void)
{
    printf("%zu\n", sizeof(struct S)); // affiche généralement 4
}

Le champ de bits sans nom spécial de width de valeur zéro interrompt le bourrage : il indique que le champ de bits suivant commence au début de l'unité d'allocation suivante :

#include <stdio.h>

struct S
{
    // occupera généralement 8 octets :
    // 5 bits : valeur de b1
    // 27 bits : inutilisés
    // 6 bits : valeur de b2
    // 15 bits : valeur de b3
    // 11 bits : inutilisés
    unsigned b1 : 5;
    unsigned    : 0; // commence un nouvel unsigned int
    unsigned b2 : 6;
    unsigned b3 : 15;
};

int main(void)
{
    printf("%zu\n", sizeof(struct S)); // affiche généralement 8
}

Comme les champs de bits ne commencent pas nécessairement au début d'un octet, l'adresse d'un champ de bits ne peut pas être prise. Les pointeurs vers des champs de bits sont impossibles. Les champs de bits ne peuvent pas être utilisés avec sizeofet [_Alignas (depuis C11) (jusqu'à C23) | alignas (depuis C23)] (depuis C11).

Notes

Les utilisations suivantes de champs de bits provoquent un comportement indéfini :

  • Appel de offsetof sur un champ de bits.

Les propriétés suivantes des champs de bits sont non spécifiées :

  • Alignement de l'unité d'allocation qui contient un champ de bits.

Les propriétés suivantes des champs de bits sont définies par l'implémentation :

  • Indique si les champs de bits de type int sont traités comme signés ou non signés.
  • Indique si des types autres que int, signed int, unsigned int[, _Bool (depuis C99) | , et (éventuellement unsigned) _BitInt(N) (depuis C23)] sont autorisés.
  • Indique si les types atomiques sont autorisés.

(depuis C11)

  • Indique si un champ de bits peut chevaucher la frontière d'une unité d'allocation.
  • L'ordre des champs de bits au sein d'une unité d'allocation (sur certaines plateformes, les champs de bits sont empaquetés de gauche à droite, sur d'autres de droite à gauche).

Bien que le nombre de bits de la représentation objet de _Bool soit au moins CHAR_BIT, la width du champ de bits de type _Bool ne peut pas être supérieure à 1.

(depuis C99)

En langage C++, la largeur d'un champ de bits peut dépasser la largeur du type sous-jacent (mais les bits supplémentaires sont des bits de bourrage), et les champs de bits de type int sont toujours signés.
