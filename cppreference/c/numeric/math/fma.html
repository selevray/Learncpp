fma, fmaf, fmal

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <math.h>

float       fmaf( float x, float y, float z );  // (1) (depuis C99)

double      fma( double x, double y, double z );  // (2) (depuis C99)

long double fmal( long double x, long double y, long double z );  // (3) (depuis C99)

#define FP_FAST_FMA  /* implementation-defined */  // (4) (depuis C99)

#define FP_FAST_FMAF /* implementation-defined */  // (5) (depuis C99)

#define FP_FAST_FMAL /* implementation-defined */  // (6) (depuis C99)

Défini dans l'en-tête <tgmath.h>

#define fma( x, y, z )  // (7) (depuis C99)

1-3) Calcule (x * y) + z comme si la précision était infinie, et n'arrondit qu'une seule fois pour correspondre au type du résultat.

4-6) Si les constantes macro FP_FAST_FMA, FP_FAST_FMAF ou FP_FAST_FMAL sont définies, la fonction correspondante fma, fmaf ou fmal s'évalue plus rapidement (en plus d'être plus précise) que l'expression x * y + z pour des arguments double, float et long double respectivement. Lorsqu'elles sont définies, ces macros s'évaluent en 1 entier.

  1. Macro générique au type : si un argument est de type long double, fmal est appelée. Sinon, si un argument est de type entier ou de type double, fma est appelée. Sinon, fmaf est appelée.

Paramètres

  • x, y, z — valeurs à virgule flottante

Valeur de retour

En cas de succès, renvoie la valeur de (x * y) + z comme si elle était calculée avec une précision infinie et arrondie une seule fois pour tenir dans le type du résultat (ou, de manière équivalente, calculée comme une unique opération ternaire à virgule flottante).

Si une erreur d'intervalle due à un dépassement se produit, ±HUGE_VAL, ±HUGE_VALF ou ±HUGE_VALL est renvoyé.

Si une erreur de plage due à un sous-dépassement se produit, la valeur correcte (après arrondi) est renvoyée.

Gestion des erreurs

Les erreurs sont signalées comme spécifié dans math_errhandling.

Si l'implémentation prend en charge l'arithmétique à virgule flottante IEEE (CEI 60559),

  • Si x vaut zéro et y est infini, ou si x est infini et y vaut zéro, et
    • si z n'est pas un NaN, alors NaN est renvoyé et FE_INVALID est levé,
    • si z est un NaN, alors NaN est renvoyé et FE_INVALID peut être levé.
  • Si x * y est exactement un infini et z est un infini de signe opposé, NaN est renvoyé et FE_INVALID est levé.
  • Si x ou y valent NaN, NaN est renvoyé.
  • Si z vaut NaN, et x * y n'est ni 0 * Inf ni Inf * 0, alors NaN est renvoyé (sans FE_INVALID).

Notes

Cette opération est couramment implémentée au niveau matériel par l'instruction CPU multiplication-addition fusionnée. Si elle est prise en charge par le matériel, les macros FP_FAST_FMA* appropriées sont censées être définies, mais de nombreuses implémentations utilisent l'instruction CPU même lorsque les macros ne sont pas définies.

POSIX précise que la situation où la valeur x * y est invalide et z est un NaN est une erreur de domaine.

En raison de sa précision intermédiaire infinie, fma est un élément de base courant d'autres opérations mathématiques à arrondi correct, comme sqrt ou même la division (lorsqu'elle n'est pas fournie par le CPU, par exemple Itanium).

Comme pour toutes les expressions en virgule flottante, l'expression (x * y) + z peut être compilée sous forme de multiplication-addition fusionnée, sauf si le #pragma STDC FP_CONTRACT est désactivé.

Exemple

#include <fenv.h>
#include <float.h>
#include <math.h>
#include <stdio.h>
// #pragma STDC FENV_ACCESS ON

int main(void)
{
    // démontre la différence entre fma et les opérateurs intégrés
    double in = 0.1;
    printf("0.1 double is %.23f (%a)\n", in, in);
    printf("0.1*10 is 1.0000000000000000555112 (0x8.0000000000002p-3),"
           " or 1.0 if rounded to double\n");
    double expr_result = 0.1 * 10 - 1;
    printf("0.1 * 10 - 1 = %g : 1 subtracted after "
           "intermediate rounding to 1.0\n", expr_result);
    double fma_result = fma(0.1, 10, -1);
    printf("fma(0.1, 10, -1) = %g (%a)\n", fma_result, fma_result);

    // utilisation de fma en arithmétique double-double
    printf("\nin double-double arithmetic, 0.1 * 10 is representable as ");
    double high = 0.1 * 10;
    double low = fma(0.1, 10, -high);
    printf("%g + %g\n\n", high, low);

    // gestion des erreurs
    feclearexcept(FE_ALL_EXCEPT);
    printf("fma(+Inf, 10, -Inf) = %f\n", fma(INFINITY, 10, -INFINITY));
    if (fetestexcept(FE_INVALID))
        puts("    FE_INVALID raised");
}

Sortie possible :

0.1 double is 0.10000000000000000555112 (0x1.999999999999ap-4)
0.1*10 is 1.0000000000000000555112 (0x8.0000000000002p-3), or 1.0 if rounded to double
0.1 * 10 - 1 = 0 : 1 subtracted after intermediate rounding to 1.0
fma(0.1, 10, -1) = 5.55112e-17 (0x1p-54)

in double-double arithmetic, 0.1 * 10 is representable as 1 + 5.55112e-17

fma(+Inf, 10, -Inf) = -nan
    FE_INVALID raised
