Inclusion de fichier source

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Inclut un autre fichier source dans le fichier source courant, à la ligne immédiatement après la directive.

Syntaxe

| | | | #include < h-char-sequence > new-line | (1) | | | | #include " q-char-sequence " new-line | (2) | | | | #include pp-tokens new-line | (3) | | | | __has_include ( " q-char-sequence " ) __has_include ( < h-char-sequence > ) | (4) | (depuis C23) | | | __has_include ( string-literal ) __has_include ( < h-pp-tokens > ) | (5) | (depuis C23) | |

  1. Recherche un en-tête identifié de manière unique par h-char-sequence et remplace la directive par le contenu complet de l'en-tête.

  2. Recherche un fichier source identifié par q-char-sequence et remplace la directive par le contenu complet du fichier source. Elle peut revenir à (1) et traiter q-char-sequence comme identifiant d'en-tête.

  3. Si ni (1) ni (2) ne correspondent, pp-tokens subit un remplacement de macro. La directive obtenue après remplacement est à nouveau comparée à (1) ou (2).

  4. Vérifie si un en-tête ou un fichier source est disponible pour l'inclusion.

  5. Si (4) ne correspond pas, h-pp-tokens subit un remplacement de macro. La directive obtenue après remplacement est à nouveau comparée à (4).

  • new-line — Le caractère de fin de ligne
  • h-char-sequence — Une suite d'un ou plusieurs h-char, où l'apparition de l'un des éléments suivants provoque un comportement indéfini :
    • le caractère '
    • le caractère "
    • le caractère \
    • la séquence de caractères //
    • la séquence de caractères /*
  • h-char — Tout membre du jeu de caractères source, à l'exception du saut de ligne et de >
  • q-char-sequence — Une suite d'un ou plusieurs q-char, où l'apparition de l'un des éléments suivants provoque un comportement indéfini :
    • le caractère '
    • le caractère \
    • la séquence de caractères //
    • la séquence de caractères /*
  • q-char — Tout membre du jeu de caractères source, à l'exception du saut de ligne et de "
  • pp-tokens — Une séquence d'un ou plusieurs unités lexicales de prétraitement
  • string-literal — Un littéral de chaîne
  • h-pp-tokens — Une séquence d'un ou plusieurs unités lexicales de prétraitement à l'exception de >

Explication

  1. Recherche le fichier identifié par h-char-sequence de manière définie par l'implémentation. Cette syntaxe vise à rechercher les fichiers contrôlés par l'implémentation. Les implémentations typiques ne recherchent que dans les répertoires d'en-têtes standard. La bibliothèque standard C est implicitement incluse dans ces répertoires standard. Ces répertoires peuvent généralement être contrôlés par l'utilisateur via les options du compilateur.

  2. Recherche le fichier identifié par q-char-sequence de manière définie par l'implémentation. Cette syntaxe vise à rechercher les fichiers non contrôlés par l'implémentation. Les implémentations typiques recherchent d'abord dans le répertoire où se trouve le fichier courant et, seulement si le fichier n'est pas trouvé, dans les répertoires d'en-têtes standard comme avec (1).

  3. Les jetons de prétraitement suivant include dans la directive sont traités comme du texte normal (c'est-à-dire que chaque identificateur actuellement défini comme nom de macro est remplacé par sa liste de remplacement de jetons de prétraitement). La directive résultant de tous les remplacements doit correspondre à l'une des deux formes précédentes. La méthode par laquelle une suite de jetons de prétraitement comprise entre < et >, ou entre une paire de caractères ", est combinée en un seul jeton de prétraitement de nom d'en-tête est définie par l'implémentation.

  4. L'en-tête ou le fichier source identifié par h-char-sequence ou q-char-sequence est recherché comme si cette séquence d'unités lexicales de prétraitement était le pp-tokens de la syntaxe (3), sauf qu'aucun autre développement de macro n'est effectué. Si une telle directive ne satisfait pas aux exigences syntaxiques d'une directive #include, le programme est mal formé. L'expression __has_include s'évalue à 1 si la recherche du fichier source réussit, et à 0 si la recherche échoue.

  5. Cette forme n'est considérée que si la syntaxe (4) ne correspond pas, auquel cas les jetons de prétraitement sont traités comme du texte normal.

Si le fichier n'est pas trouvé, le programme est mal formé.

__has_include peut être développée dans l'expression de #if et de #elif. Elle est traitée comme une macro définie par #ifdef, #ifndef, #elifdef, #elifndef et defined, mais ne peut pas être utilisée ailleurs.

(depuis C23)

Notes

Les implémentations typiques ne recherchent que dans les répertoires d'en-têtes standard pour la syntaxe (1). La bibliothèque standard C est implicitement incluse dans ces répertoires standard. Ces répertoires peuvent généralement être contrôlés par l'utilisateur via les options du compilateur.

L'objectif de la syntaxe (2) est de rechercher les fichiers qui ne sont pas contrôlés par l'implémentation. Les implémentations typiques recherchent d'abord le répertoire où se trouve le fichier courant, puis reviennent à (1).

Lorsqu'un fichier est inclus, il est traité par les phases de traduction 1 à 4, ce qui peut inclure, de manière récursive, le développement des directives #include imbriquées, jusqu'à une limite d'imbrication définie par l'implémentation. Pour éviter l'inclusion répétée du même fichier et une récursion infinie lorsqu'un fichier s'inclut lui-même, éventuellement de manière transitive, des gardes d'en-tête sont couramment utilisées : l'en-tête entier est enveloppé dans

#ifndef FOO_H_INCLUDED /* any name uniquely mapped to file name */
#define FOO_H_INCLUDED
// le contenu du fichier est ici
#endif

De nombreux compilateurs implémentent aussi le pragma non standard pragma #pragma once, avec des effets similaires : il désactive le traitement d'un fichier si le même fichier (dont l'identité est déterminée de manière propre au système d'exploitation) a déjà été inclus.

Un résultat __has_include de 1 signifie seulement qu'un en-tête ou un fichier source portant le nom indiqué existe. Cela ne signifie pas que l'en-tête ou le fichier source, lorsqu'il est inclus, ne provoquera pas d'erreur ni ne contiendra quoi que ce soit d'utile.
