Remplacement de macros textuelles

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Le préprocesseur prend en charge le remplacement de macros textuelles et le remplacement de macros textuelles de type fonction.

Syntaxe

| | | | #define identifier replacement-list ﻿*(facultatif)* | (1) | | | | #define identifier ﻿( parameters ) replacement-list | (2) | | | | #define identifier ﻿( parameters, ... ) replacement-list | (3) | (depuis C99) | | | #define identifier ﻿( ... ) replacement-list | (4) | (depuis C99) | | | #undef identifier | (5) | | |

Explication

directives #define

Les directives #define définissent le identifier comme une macro, c'est-à-dire qu'elles demandent au compilateur de remplacer toutes les occurrences successives de identifier par replacement-list, qui peut éventuellement être traité davantage. Si l'identifiant est déjà défini comme macro de n'importe quel type, le programme est mal formé, sauf si les définitions sont identiques.

Macros de type objet

Les macros de type objet remplacent chaque occurrence d'un identifier défini par replacement-list. La version (1) de la directive #define se comporte exactement ainsi.

Macros de type fonction

Les macros de type fonction remplacent chaque occurrence d'un identifier défini par replacement-list, en prenant en plus un certain nombre d'arguments, qui remplacent ensuite les occurrences correspondantes de l'un des parameters dans replacement-list.

La syntaxe d'un appel de macro de type fonction ressemble à celle d'un appel de fonction : chaque occurrence du nom de la macro suivie d'une ( comme jeton de prétraitement suivant introduit la séquence de jetons qui est remplacée par la liste de remplacement. La séquence se termine par le jeton ) correspondant, en ignorant les paires de parenthèses gauches et droites correspondantes intermédiaires.

Le nombre d'arguments doit être identique au nombre d'arguments de la définition de macro (parameters), sinon le programme est mal formé. Si l'identifiant n'est pas en notation fonctionnelle, c'est-à-dire s'il n'est pas suivi de parenthèses, il n'est pas du tout remplacé.

La version (2) de la directive #define définit une macro de type fonction simple.

La version (3) de la directive #define définit une macro de type fonction à nombre variable d'arguments. Les arguments supplémentaires sont accessibles au moyen de l'identifiant __VA_ARGS__, qui est alors remplacé par les arguments fournis avec l'identifiant à remplacer.

La version (4) de la directive #define définit une macro de type fonction à nombre variable d'arguments, mais sans arguments ordinaires. Les arguments ne sont accessibles qu'au moyen de l'identifiant __VA_ARGS__, qui est alors remplacé par les arguments fournis avec l'identifiant à remplacer.

Pour les versions (3,4), replacement-list peut contenir la séquence de jetons __VA_OPT__ ( content ), qui est remplacée par content si __VA_ARGS__ est non vide, et ne se développe en rien sinon.

#define F(...) f(0 __VA_OPT__(,) __VA_ARGS__)
F(a, b, c) // remplacé par f(0, a, b, c)
F()        // remplacé par f(0)

#define G(X, ...) f(0, X __VA_OPT__(,) __VA_ARGS__)
G(a, b, c) // remplacé par f(0, a, b, c)
G(a, )     // remplacé par f(0, a)
G(a)       // remplacé par f(0, a)

#define SDEF(sname, ...) S sname __VA_OPT__(= { __VA_ARGS__ })
SDEF(foo);       // remplacé par S foo;
SDEF(bar, 1, 2); // remplacé par S bar = { 1, 2 };

(depuis C23)

Remarque : si un argument d'une macro de type fonction contient des virgules non protégées par des paires de parenthèses correspondantes (comme macro(array[x = y, x + 1]) ou atomic_store (p, (struct S){ a, b });), la virgule est interprétée comme séparateur d'arguments de macro, ce qui provoque un échec de compilation dû à un nombre d'arguments incorrect.

Opérateurs # et ##

Dans les macros de type fonction, un opérateur # placé devant un identifiant de replacement-list applique le remplacement de paramètre à cet identifiant, puis entoure le résultat de guillemets, ce qui crée en pratique un littéral de chaîne. En outre, le préprocesseur ajoute des barres obliques inverses pour échapper les guillemets entourant les littéraux de chaîne éventuellement inclus, et double les barres obliques inverses à l'intérieur de la chaîne si nécessaire. Tous les espaces en début et en fin de texte sont supprimés, et toute suite d'espaces au milieu du texte (mais pas à l'intérieur des littéraux de chaîne inclus) est réduite à un seul espace. Cette opération est appelée « transformation en chaîne ». Si le résultat de la transformation n'est pas un littéral de chaîne valide, le comportement est indéfini.

Lorsque # apparaît devant __VA_ARGS__, l'intégralité de __VA_ARGS__ développé est entourée de guillemets :

#define showlist(...) puts(#__VA_ARGS__)
showlist();            // se développe en puts("")
showlist(1, "x", int); // se développe en puts("1, \"x\", int")

(depuis C99)

Un opérateur ## entre deux identifiants successifs dans la liste de remplacement replacement-list effectue le remplacement des paramètres sur les deux identifiants, puis concatène le résultat. Cette opération est appelée « concaténation » ou « collage de jetons ». Seuls les jetons qui forment ensemble un jeton valide peuvent être collés : des identifiants qui forment un identifiant plus long, des chiffres qui forment un nombre, ou les opérateurs + et = qui forment un +=. Un commentaire ne peut pas être créé en collant / et *, car les commentaires sont supprimés du texte avant que la substitution de macros soit examinée. Si le résultat de la concaténation n'est pas un jeton valide, le comportement est indéfini.

Remarque : certains compilateurs offrent une extension qui permet à ## d'apparaître après une virgule et avant __VA_ARGS__, auquel cas le ## ne fait rien lorsque __VA_ARGS__ est non vide, mais supprime la virgule lorsque __VA_ARGS__ est vide : cela permet de définir des macros telles que fprintf (stderr, format, ##__VA_ARGS__).

L'ordre d'évaluation des opérateurs # et ## n'est pas spécifié.

directive #undef

La directive #undef annule la définition de identifier, c'est-à-dire qu'elle annule la définition précédente de identifier faite par la directive #define. Si l'identifiant n'a pas de macro associée, la directive est ignorée.

Macros prédéfinies

Les noms de macros suivants sont prédéfinis dans toute unité de traduction :

  • STDC — se développe en la constante entière 1. Cette macro est destinée à indiquer une implémentation conforme (constante macro)
  • STDC_VERSION (C95) — se développe en une constante entière de type long dont la valeur augmente avec chaque version de la norme C :
    • 199409L (C95)
    • 199901L (C99)
    • 201112L (C11)
    • 201710L (C17)
    • 202311L (C23) (constante macro)
  • STDC_HOSTED (C99) — se développe en la constante entière 1 si l'implémentation est hébergée (fonctionne sous un système d'exploitation), 0 si elle est autonome (fonctionne sans système d'exploitation) (constante de macro)
  • FILE — se développe en le nom du fichier courant, sous forme de littéral de chaîne de caractères, qui peut être modifié par la directive #line (constante macro)
  • LINE — se développe en le numéro de ligne du fichier source, une constante entière, peut être modifié par la directive #line (constante macro)
  • DATE — se développe en la date de traduction, un littéral de chaîne de caractères de la forme "Mmm dd yyyy". Le nom du mois est tel que généré par asctime, et le premier caractère de "dd" est un espace si le jour du mois est inférieur à 10 (constante macro)
  • TIME — se développe en l'heure de traduction, un littéral de chaîne de caractères de la forme "hh:mm:ss", comme dans l'heure générée par asctime() (constante macro)
  • STDC_UTF_16 (C23) — se développe en 1 pour indiquer que char16_t utilisent l'encodage UTF-16 (constante macro)
  • STDC_UTF_32 (C23) — se développe en 1 pour indiquer que char32_t utilisent l'encodage UTF-32 (constante macro)
  • STDC_EMBED_NOT_FOUND____STDC_EMBED_FOUND____STDC_EMBED_EMPTY (C23) — se développent respectivement en 0, 1 et 2 (constante macro)

Les noms de macros supplémentaires suivants peuvent être prédéfinis par l'implémentation :

  • STDC_ISO_10646 (C99) — se développe en une constante entière de la forme yyyymmL, si wchar_t utilise Unicode ; la date indique la dernière révision d'Unicode prise en charge (constante macro)
  • STDC_IEC_559 (C99) — se développe en 1 si IEC 60559 est pris en charge (obsolète) (depuis C23) (constante macro)
  • STDC_IEC_559_COMPLEX (C99) — se développe en 1 si l'arithmétique complexe IEC 60559 est prise en charge (obsolète) (depuis C23) (constante macro)
  • STDC_UTF_16 (C11) — se développe en 1 si char16_t utilisent l'encodage UTF-16 (constante macro)
  • STDC_UTF_32 (C11) — se développe en 1 si char32_t utilisent l'encodage UTF-32 (constante macro)
  • STDC_MB_MIGHT_NEQ_WC (C99) — se développe en 1 si 'x' == L'x' peut être faux pour un membre de l'ensemble de caractères de base, comme sur les systèmes basés sur EBCDIC qui utilisent Unicode pour wchar_t (constante de macro)
  • STDC_ANALYZABLE (C11) — se développe en 1 si l'analysabilité est prise en charge (constante macro)
  • STDC_LIB_EXT1 (C11) — se développe en une constante entière 201112L si les interfaces de vérification des bornes sont prises en charge (constante macro)
  • STDC_NO_ATOMICS (C11) — se développe en 1 si les types atomic et la bibliothèque des opérations atomiques ne sont pas pris en charge (constante macro)
  • STDC_NO_COMPLEX (C11) — se développe en 1 si les types complexes et la bibliothèque mathématique complexe ne sont pas pris en charge (constante macro)
  • STDC_NO_THREADS (C11) — se développe en 1 si le multithreading n'est pas pris en charge (constante macro)
  • STDC_NO_VLA (C11) — se développe en 1 si les tableaux de longueur variable [et les types à modification variable (jusqu'à C23) | à durée de stockage automatique (depuis C23)] ne sont pas pris en charge (constante macro)
  • STDC_IEC_60559_BFP (C23) — se développe en 202311L si l'arithmétique à virgule flottante binaire IEC 60559 est prise en charge (constante macro)
  • STDC_IEC_60559_DFP (C23) — se développe en 202311L si l'arithmétique à virgule flottante décimale IEC 60559 est prise en charge (constante macro)
  • STDC_IEC_60559_COMPLEX (C23) — se développe en 202311L si l'arithmétique complexe IEC 60559 est prise en charge (constante macro)
  • STDC_IEC_60559_TYPES (C23) — se développe en 202311L si les types d'échange et étendus IEC 60559 sont pris en charge (constante macro)

Les valeurs de ces macros (sauf pour __FILE__ et __LINE__) restent constantes dans toute l'unité de traduction. Toute tentative de redéfinir ou d'annuler ces macros entraîne un comportement indéfini.

La variable prédéfinie __func__ (voir définition de fonction pour plus de détails) n'est pas une macro du préprocesseur, bien qu'elle soit parfois utilisée avec __FILE__ et __LINE__, par exemple par assert.

(depuis C99)

Exemple

#include <stdio.h>

// créer une fonction fabrique et l'utiliser
#define FUNCTION(name, a) int fun_##name(int x) { return (a) * x; }

FUNCTION(quadruple, 4)
FUNCTION(double, 2)

#undef FUNCTION
#define FUNCTION 34
#define OUTPUT(a) puts( #a )

int main(void)
{
    printf("quadruple(13): %d\n", fun_quadruple(13) );
    printf("double(21): %d\n", fun_double(21) );
    printf("%d\n", FUNCTION);
    OUTPUT(billion);               // remarquer l'absence de guillemets
}

Output:

quadruple(13): 52
double(21): 42
34
billion
