Inclusion de ressources binaires (depuis C23)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

#embed est une directive du préprocesseur permettant d'inclure des ressources (binaires) dans la compilation, où une ressource est définie comme une source de données accessible depuis l'environnement de traduction.

Syntaxe

| | | | #embed < h-char-sequence > embed-parameter-sequence ﻿*(facultatif)* new-line | (1) | | | | #embed " q-char-sequence " embed-parameter-sequence ﻿*(facultatif)* new-line | (2) | | | | #embed pp-tokens new-line | (3) | | | | __has_embed ( " q-char-sequence " embed-parameter-sequence ﻿*(facultatif)* ) __has_embed ( < h-char-sequence > embed-parameter-sequence ﻿*(facultatif)* ) | (4) | | | | __has_embed ( string-literal pp-balanced-token-sequence ﻿*(facultatif)* ) __has_embed ( < h-pp-tokens > pp-balanced-token-sequence ﻿*(facultatif)* ) | (5) | | |

  1. Recherche une ressource identifiée de manière unique par h-char-sequence et remplace la directive par une liste d'entiers séparés par des virgules correspondant aux données de la ressource.

  2. Recherche une ressource identifiée par q-char-sequence et remplace la directive par une liste d'entiers correspondant aux données de la ressource. Elle peut revenir à (1).

  3. Si ni (1) ni (2) ne correspondent, pp-tokens subit un remplacement de macro. La directive obtenue après remplacement est à nouveau comparée à (1) ou (2).

  4. Vérifie si une ressource est disponible pour l'intégration, si elle est vide ou non, et si les paramètres passés sont pris en charge par l'implémentation.

  5. Si (4) ne correspond pas, h-pp-tokens et pp-balanced-token-sequence subissent le remplacement de macros. La directive après remplacement sera à nouveau comparée à (4).

  • new-line — Le caractère de fin de ligne
  • h-char-sequence — Une suite d'un ou plusieurs h-char, où l'apparition de l'un des éléments suivants provoque un comportement indéfini :
    • le caractère '
    • le caractère "
    • le caractère \
    • la séquence de caractères //
    • la séquence de caractères /*
  • h-char — Tout membre du jeu de caractères source, à l'exception du saut de ligne et de >
  • q-char-sequence — Une suite d'un ou plusieurs q-char, où l'apparition de l'un des éléments suivants provoque un comportement indéfini :
    • le caractère '
    • le caractère \
    • la séquence de caractères //
    • la séquence de caractères /*
  • q-char — Tout membre du jeu de caractères source, à l'exception du saut de ligne et de "
  • pp-tokens — Une séquence d'un ou plusieurs unités lexicales de prétraitement
  • string-literal — Un littéral de chaîne
  • h-pp-tokens — Une séquence d'un ou plusieurs unités lexicales de prétraitement à l'exception de >
  • embed-parameter-sequence — Une suite d'un ou plusieurs pp-parameter. Notez que, contrairement à un attribute-list, cette suite n'est pas séparée par des virgules.
  • pp-parameter — Un attribute-token (voir : attributs) mais composé de jetons de prétraitement au lieu de jetons.
  • pp-balanced-token-sequence — Un balanced-token-sequence (voir : attributs) mais composé de jetons de prétraitement au lieu de jetons

Explication

  1. Recherche la ressource identifiée par h-char-sequence de manière définie par l'implémentation.

  2. Recherche la ressource identifiée par q-char-sequence de manière définie par l'implémentation. Pour (1,2), les implémentations utilisent généralement un mécanisme similaire, mais distinct, aux chemins de recherche définis par l'implémentation utilisés pour l'inclusion de fichiers source. La construction __has_embed(__FILE__ ... apparaît dans l'un des exemples de la norme, suggérant, au moins dans le cas de (2), que le répertoire où se trouve le fichier courant est censé être recherché.

  3. Les jetons de prétraitement suivant embed dans la directive sont traités comme du texte normal (c'est-à-dire que chaque identificateur actuellement défini comme nom de macro est remplacé par sa liste de remplacement de jetons de prétraitement). La directive résultant de tous les remplacements doit correspondre à l'une des deux formes précédentes. La méthode par laquelle une suite de jetons de prétraitement comprise entre < et >, ou entre une paire de caractères ", est combinée en un seul jeton de prétraitement de nom d'en-tête est définie par l'implémentation.

  4. La ressource identifiée par h-char-sequence ou q-char-sequence est recherchée comme si cette suite de jetons de prétraitement était le pp-tokens dans la syntaxe (3), sauf qu'aucune autre expansion de macro n'est effectuée. Si une telle directive ne satisfait pas aux exigences syntaxiques d'une directive #embed, le programme est mal formé. L'expression __has__embed vaut __STDC_EMBED_FOUND__ si la recherche de la ressource réussit, que la ressource n'est pas vide et que tous les paramètres sont pris en charge, vaut __STDC_EMBED_EMPTY__ si la ressource est vide et que tous les paramètres sont pris en charge, et vaut __STDC_EMBED_NOT_FOUND__ si la recherche échoue ou si l'un des paramètres passés n'est pas pris en charge par l'implémentation.

  5. Cette forme n'est considérée que si la syntaxe (4) ne correspond pas, auquel cas les jetons de prétraitement sont traités comme du texte normal.

Si la ressource n'est pas trouvée ou si l'un des paramètres n'est pas pris en charge par l'implémentation, le programme est mal formé.

__has_embed peut être développée dans l'expression de #if et de #elif. Elle est traitée comme une macro définie par #ifdef, #ifndef, #elifdef, #elifndef et defined, mais ne peut pas être utilisée ailleurs.

Une ressource a une largeur de ressource d'implémentation, qui est la taille en bits, définie par l'implémentation, de la ressource localisée. Sa largeur de ressource est la largeur de ressource d'implémentation, sauf modification par un paramètre limit. Si la largeur de ressource vaut 0, la ressource est considérée comme vide. La largeur d'élément embed est égale à CHAR_BIT, sauf modification par un paramètre défini par l'implémentation. La largeur de ressource doit être divisible par la largeur d'élément embed.

L'expansion d'une directive #embed est une suite de jetons formée à partir de la liste des expressions constantes entières décrites ci-dessous. Le groupe de jetons de chaque expression constante entière de la liste est séparé dans la suite de jetons du groupe de jetons de l'expression constante entière précédente par une virgule. La suite ne commence ni ne se termine par une virgule. Si la liste des expressions constantes entières est vide, la suite de jetons est vide. La directive est remplacée par son expansion et, en présence de certains paramètres embed, par des suites de jetons supplémentaires ou de remplacement.

La valeur des expressions constantes entières de la suite développée est déterminée par une correspondance définie par l'implémentation avec les données de la ressource. La valeur de chaque expression constante entière appartient à l'intervalle [0,2largeur d'élément embed). Si :

  1. La liste des expressions constantes entières sert à initialiser un tableau d'un type compatible avec unsigned char, ou compatible avec char si char ne peut pas contenir de valeurs négatives, et
  2. La largeur d'élément embed est égale à CHAR_BIT,

alors le contenu des éléments initialisés du tableau est comme si les données binaires de la ressource étaient fread dans le tableau au moment de la traduction.

Les implémentations sont encouragées à tenir compte de l'ordre des bits et des octets au moment de la traduction ainsi que de l'ordre des bits et des octets au moment de l'exécution, afin de mieux représenter les données binaires de la ressource à partir de la directive. Cela maximise la probabilité que, si la ressource référencée au moment de la traduction par la directive #embed est la même que celle accédée par des moyens à l'exécution, les données qui sont par exemple fread ou similaires dans un stockage contigu soient égales bit à bit à un tableau de type caractère initialisé à partir du contenu développé d'une directive #embed.

Paramètres

La norme définit les paramètres limit, prefix, suffix et if_empty. Tout autre paramètre qui apparaît dans la directive doit être défini par l'implémentation, sinon le programme est mal formé. Les paramètres embed définis par l'implémentation peuvent modifier la sémantique de la directive.

limit

| | | | limit( constant-expression ) | (1) | | | | __limit__( constant-expression ) | (2) | | |

Le paramètre embed limit peut apparaître au plus une fois dans la séquence de paramètres embed. Il doit avoir un argument, qui doit être une expression constante entière (de prétraitement) qui s'évalue à un nombre non négatif et qui ne contient pas le jeton defined. La largeur de la ressource est fixée au minimum entre la constante entière multipliée par la largeur de l'élément embed et la largeur de ressource de l'implémentation.

suffix

| | | | suffix( pp-balanced-token-sequence ﻿*(facultatif)* ) | (1) | | | | __suffix__( pp-balanced-token-sequence ﻿*(facultatif)* ) | (2) | | |

Le paramètre embed suffix peut apparaître au plus une fois dans la séquence de paramètres embed. Il doit avoir une clause d'argument de prétraitement (éventuellement vide). Si la ressource est non vide, le contenu de la clause de paramètre est placé immédiatement après le développement de la directive. Sinon, il n'a aucun effet.

prefix

| | | | prefix( pp-balanced-token-sequence ﻿*(facultatif)* ) | (1) | | | | __prefix__( pp-balanced-token-sequence ﻿*(facultatif)* ) | (2) | | |

Le paramètre embed prefix peut apparaître au plus une fois dans la séquence de paramètres embed. Il doit avoir une clause d'argument de prétraitement (éventuellement vide). Si la ressource est non vide, le contenu de la clause de paramètre est placé immédiatement avant le développement de la directive. Sinon, il n'a aucun effet.

if_empty

| | | | if_empty( pp-balanced-token-sequence ﻿*(facultatif)* ) | (1) | | | | __if_empty__( pp-balanced-token-sequence ﻿*(facultatif)* ) | (2) | | |

Le paramètre embed if_empty peut apparaître au plus une fois dans la séquence de paramètres embed. Il doit avoir une clause d'argument de prétraitement (éventuellement vide). Si la ressource est vide, le contenu de la clause de paramètre remplace la directive. Sinon, il n'a aucun effet.

Exemple

#include <stdint.h>
#include <stdio.h>

const uint8_t image_data[] = {
#embed "image.png"
};

const char message[] = {
#embed "message.txt" if_empty('M', 'i', 's', 's', 'i', 'n', 'g', '\n')
,'\0' // terminateur nul
};

void dump(const uint8_t arr[], size_t size)
{
    for (size_t i = 0; i != size; ++i)
        printf("%02X%c", arr[i], (i + 1) % 16 ? ' ' : '\n');
    puts("");
}

int main()
{
    puts("image_data[]:");
    dump(image_data, sizeof image_data);
    puts("message[]:");
    dump((const uint8_t*)message, sizeof message);
}
