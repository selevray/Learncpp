signal

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <signal.h>

void (*signal( int sig, void (*handler) (int))) (int);

Définit le gestionnaire d'erreurs pour le signal sig. Le gestionnaire de signal peut être défini de sorte que le traitement par défaut ait lieu, que le signal soit ignoré, ou qu'une fonction définie par l'utilisateur soit appelée.

Lorsqu'un gestionnaire de signal est défini comme une fonction et qu'un signal survient, il est défini par l'implémentation que signal(sig, SIG_DFL) soit exécuté immédiatement avant le début du gestionnaire de signal. De plus, l'implémentation peut empêcher certains ensembles de signaux définis par l'implémentation de survenir pendant l'exécution du gestionnaire de signal.

Paramètres

  • sig — le signal pour lequel définir le gestionnaire de signal. Il peut s'agir d'une valeur définie par l'implémentation ou de l'une des valeurs suivantes :

    • SIGABRTSIGFPESIGILLSIGINTSIGSEGVSIGTERM — définit les types de signaux (constante macro)

  • handler — le gestionnaire de signal. Il doit s'agir de l'une des valeurs suivantes :

    • macro SIG_DFL. Le gestionnaire de signal est défini sur le gestionnaire de signal par défaut.
    • macro SIG_IGN. Le signal est ignoré.
    • pointeur vers une fonction. La signature de la fonction doit être équivalente à ce qui suit :
    void fun(int sig);

Valeur de retour

Gestionnaire de signal précédent en cas de succès, ou SIG_ERR en cas d'échec (la définition d'un gestionnaire de signal peut être désactivée sur certaines implémentations).

Gestionnaire de signal

Les limitations suivantes sont imposées à la fonction définie par l'utilisateur installée comme gestionnaire de signal.

Si la fonction définie par l'utilisateur retourne lors du traitement de SIGFPE, SIGILL ou SIGSEGV, le comportement est indéfini.

Si le gestionnaire de signal est appelé suite à abort ou raise, le comportement est indéfini si le gestionnaire de signal appelle raise.

Si le gestionnaire de signal est appelé PAS suite à abort ou raise (autrement dit, le gestionnaire de signal est asynchrone), le comportement est indéfini si

  • le gestionnaire de signal appelle une fonction quelconque de la bibliothèque standard, à l'exception de

    • abort
    • _Exit
    • quick_exit
    • signal avec pour premier argument le numéro du signal actuellement traité (le gestionnaire asynchrone peut se réenregistrer lui-même, mais pas d'autres signaux).
    • les fonctions atomiques de <stdatomic.h> si les arguments atomiques sont sans verrou
    • atomic_is_lock_free (avec tout type d'arguments atomiques)

  • le gestionnaire de signal fait référence à tout objet à durée de stockage statique [ou thread-local (depuis C11) | qui n'est pas un atomique sans verrou (depuis C11)] autrement qu'en affectant une valeur à un volatile sig_atomic_t statique.

À l'entrée dans le gestionnaire de signal, l'état de l'environnement en virgule flottante et les valeurs de tous les objets sont non spécifiés, sauf pour

  • objets de type volatile sig_atomic_t
  • les objets de types atomiques sans verrou (depuis C11)
  • les effets de bord rendus visibles via atomic_signal_fence (depuis C11)

Au retour d'un gestionnaire de signal, la valeur de tout objet modifié par le gestionnaire de signal qui n'est pas volatile sig_atomic_t ni un atomique sans verrou (depuis C11) est indéfinie.

Le comportement est indéfini si signal est utilisé dans un programme multithreadé. Il n'est pas requis qu'elle soit sûre pour les threads.

Notes

POSIX exige que signal soit thread-safe, et spécifie une liste de fonctions de bibliothèque async-signal-safe qui peuvent être appelées depuis n'importe quel gestionnaire de signal.

En plus de abort et raise, POSIX précise que kill, pthread_kill et sigqueue génèrent des signaux synchrones.

POSIX recommande sigaction plutôt que signal, en raison de son comportement insuffisamment spécifié et des variations importantes entre implémentations concernant la livraison des signaux pendant l'exécution d'un gestionnaire de signal.

Exemple

#include <signal.h>
#include <stdio.h>

volatile sig_atomic_t gSignalStatus;

void signal_handler(int signal)
{
  gSignalStatus = signal;
}

int main(void)
{
  signal(SIGINT, signal_handler);

  printf("SignalValue: %d\n", gSignalStatus);
  printf("Sending signal: %d\n", SIGINT);
  raise(SIGINT);
  printf("SignalValue: %d\n", gSignalStatus);
}

Output:

SignalValue: 0
Sending signal: 2
SignalValue: 2
