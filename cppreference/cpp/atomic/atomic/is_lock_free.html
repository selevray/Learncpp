std::atomic<T>::is_lock_free

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

bool is_lock_free() const noexcept;  // (1) (depuis C++11)

bool is_lock_free() const volatile noexcept;  // (2) (depuis C++11)

Vérifie si les opérations atomiques sur tous les objets de ce type sont sans verrou.

Paramètres

(aucune)

Valeur de retour

true si les opérations atomiques sur les objets de ce type sont sans verrou, false sinon.

Notes

Tous les types atomiques, à l'exception de std::atomic_flag, peuvent être implémentés à l'aide de mutex ou d'autres opérations de verrouillage, plutôt que d'instructions atomiques sans verrou du processeur. Les types atomiques peuvent aussi être parfois sans verrou, par exemple si seuls les accès mémoire alignés sont naturellement atomiques sur une architecture donnée ; les objets non alignés de ce même type doivent alors utiliser des verrous.

La norme C++ recommande (sans l'imposer) que les opérations atomiques sans verrou soient aussi indépendantes de l'adresse, c'est-à-dire utilisables pour la communication entre processus via une mémoire partagée.

Exemple

#include <atomic>
#include <iostream>
#include <utility>

struct A { int a[100]; };
struct B { int x, y; };

int main()
{
    std::cout << std::boolalpha
              << "std::atomic<A> is lock free? "
              << std::atomic<A>{}.is_lock_free() << '\n'
              << "std::atomic<B> is lock free? "
              << std::atomic<B>{}.is_lock_free() << '\n';
}

Sortie possible :

std::atomic<A> is lock free? false
std::atomic<B> is lock free? true
