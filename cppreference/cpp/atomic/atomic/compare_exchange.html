Compare atomiquement la [représentation d'objet (jusqu'à C++20) | représentation de valeur (depuis C++20)] de *this avec celle de expected. Si elles sont égales bit à bit, remplace la première par desired (effectue une opération de lecture-modification-écriture). Sinon, charge la valeur réelle stockée dans *this dans expected (effectue une opération de chargement).

Elle est obsolète si std::atomic<T>::is_always_lock_free vaut false et qu'une surcharge volatile participe à la résolution de surcharge.

(depuis C++20)

Paramètres

  • expected — référence vers la valeur attendue dans l'objet atomique
  • desired — la valeur à stocker dans l'objet atomique si elle est celle attendue
  • success — l'ordre de synchronisation mémoire pour l'opération de lecture-modification-écriture si la comparaison réussit
  • failure — l'ordre de synchronisation mémoire pour l'opération de chargement si la comparaison échoue
  • order — l'ordre de synchronisation mémoire pour les deux opérations

Valeur de retour

true si la valeur atomique sous-jacente a été modifiée avec succès, false sinon.

Notes

La comparaison et la copie sont bit à bit (similaires à std::memcmp et std::memcpy) ; aucun constructeur, opérateur d'affectation ou opérateur de comparaison n'est utilisé.

compare_exchange_weak peut échouer de façon fallacieuse, c'est-à-dire se comporte comme si *this != expected même si elles sont égales. Lorsqu'une compare-and-exchange est dans une boucle, compare_exchange_weak offrira de meilleures performances sur certaines plateformes.

Lorsque compare_exchange_weak nécessiterait une boucle et que compare_exchange_strong n'en nécessite pas, compare_exchange_strong est préférable, sauf si la représentation d'objet de T peut inclure des bits de remplissage, (jusqu'à C++20) des bits de piège, ou offre plusieurs représentations d'objet pour une même valeur (par exemple NaN en virgule flottante). Dans ces cas, compare_exchange_weak fonctionne généralement, car il converge rapidement vers une représentation d'objet stable.

Pour une union dont certains bits participent à la représentation de valeur de certains membres mais pas des autres, compare-and-exchange peut toujours échouer, car ces bits de remplissage ont des valeurs indéterminées lorsqu'ils ne participent pas à la représentation de valeur du membre actif.

Les bits de remplissage qui ne participent jamais à la représentation de valeur d'un objet sont ignorés.

(depuis C++20)

Exemple

Les opérations compare-and-exchange sont souvent utilisées comme briques de base des structures de données sans verrou.

#include <atomic>

template<typename T>
struct node
{
    T data;
    node* next;
    node(const T& data) : data(data), next(nullptr) {}
};

template<typename T>
class stack
{
    std::atomic<node<T>*> head;
public:
    void push(const T& data)
    {
        node<T>* new_node = new node<T>(data);

        // place la valeur courante de head dans new_node->next
        new_node->next = head.load(std::memory_order_relaxed);

        // fais maintenant de new_node la nouvelle tête, mais si la tête
        // n'est plus ce qui est stocké dans new_node->next
        // (un autre thread a dû insérer un nœud à l'instant)
        // alors place cette nouvelle tête dans new_node->next et réessaie
        while (!head.compare_exchange_weak(new_node->next, new_node,
                                           std::memory_order_release,
                                           std::memory_order_relaxed))
            ; // le corps de la boucle est vide

// Remarque : l'utilisation ci-dessus n'est pas thread-safe dans au moins
// GCC antérieur à 4.8.3 (bug 60272), clang antérieur au 2014-05-05 (bug 18899)
// MSVC antérieur au 2014-03-17 (bug 819819). Voici une solution de contournement :
//      node<T>* old_head = head.load(std::memory_order_relaxed);
//      do
//      {
//          new_node->next = old_head;
//      }
//      while (!head.compare_exchange_weak(old_head, new_node,
//                                         std::memory_order_release,
//                                         std::memory_order_relaxed));
    }
};

int main()
{
    stack<int> s;
    s.push(1);
    s.push(2);
    s.push(3);
}
