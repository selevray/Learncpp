Compare atomiquement la [représentation d'objet (jusqu'à C++20) | représentation de valeur (depuis C++20)] de l'objet pointé par obj avec celle de l'objet pointé par expected, et si elles sont égales bit à bit, remplace la première par desired (effectue une opération de lecture-modification-écriture). Sinon, charge la valeur réelle pointée par obj dans *expected (effectue une opération de lecture).

Surcharges | Modèle mémoire pour

opération de lecture-modification-écriture | opération de chargement

(1-4) | std::memory_order_seq_cst |  std::memory_order_seq_cst

(5-8) | success | failure

Ces fonctions sont définies à l'aide des fonctions membres de std::atomic :

1,2) obj->compare_exchange_weak(*expected, desired)

3,4) obj->compare_exchange_strong(*expected, desired)

5,6) obj->compare_exchange_weak(*expected, desired, success, failure)

7,8) obj->compare_exchange_strong(*expected, desired, success, failure)

Si failureest plus fort que success ou (jusqu'à C++17) est l'un de std::memory_order_release et std::memory_order_acq_rel, le comportement est indéfini.

Paramètres

  • obj — pointeur vers l'objet atomique à tester et modifier
  • expected — pointeur vers la valeur attendue dans l'objet atomique
  • desired — la valeur à stocker dans l'objet atomique si elle est celle attendue
  • success — l'ordre de synchronisation mémoire pour l'opération de lecture-modification-écriture si la comparaison réussit
  • failure — l'ordre de synchronisation mémoire pour l'opération de chargement si la comparaison échoue

Valeur de retour

Le résultat de la comparaison : true si *obj était égal à *expected, false sinon.

Notes

std::atomic_compare_exchange_weak et std::atomic_compare_exchange_weak_explicit (les versions faibles) peuvent échouer sans raison, c'est-à-dire agir comme si *obj != *expected même lorsqu'elles sont égales. Lorsqu'un compare-and-exchange est dans une boucle, elles offrent de meilleures performances sur certaines plateformes.

Lorsqu'un compare-and-exchange faible nécessiterait une boucle et qu'un fort n'en nécessiterait pas, le fort est préférable, sauf si la représentation d'objet de T peut comporter des bits de remplissage, (jusqu'à C++20) des bits de piège, ou offre plusieurs représentations d'objet pour la même valeur (par ex. NaN à virgule flottante). Dans ces cas, le compare-and-exchange faible fonctionne généralement, car il converge rapidement vers une représentation d'objet stable.

Pour une union dont certains bits participent à la représentation de valeur de certains membres mais pas des autres, compare-and-exchange peut toujours échouer, car ces bits de remplissage ont des valeurs indéterminées lorsqu'ils ne participent pas à la représentation de valeur du membre actif.

Les bits de remplissage qui ne participent jamais à la représentation de valeur d'un objet sont ignorés.

(depuis C++20)

Exemple

Les opérations de comparaison et d'échange sont souvent utilisées comme briques de base des structures de données sans verrou.

#include <atomic>

template<class T>
struct node
{
    T data;
    node* next;
    node(const T& data) : data(data), next(nullptr) {}
};

template<class T>
class stack
{
    std::atomic<node<T>*> head;
public:
    void push(const T& data)
    {
        node<T>* new_node = new node<T>(data);

        // place la valeur courante de head dans new_node->next
        new_node->next = head.load(std::memory_order_relaxed);

        // fais maintenant de new_node la nouvelle tête, mais si la tête
        // n'est plus ce qui est stocké dans new_node->next
        // (un autre thread a dû insérer un nœud à l'instant)
        // alors place cette nouvelle tête dans new_node->next et réessaie
        while (!std::atomic_compare_exchange_weak_explicit(
                   &head, &new_node->next, new_node,
                   std::memory_order_release, std::memory_order_relaxed))
            ; // le corps de la boucle est vide
// remarque : la boucle ci-dessus n'est pas thread-safe, du moins dans
// GCC antérieur à 4.8.3 (bug 60272), clang antérieur au 2014-05-05 (bug 18899)
// MSVC antérieur au 2014-03-17 (bogue 819819). Voir la version fonction membre pour le contournement
    }
};

int main()
{
    stack<int> s;
    s.push(1);
    s.push(2);
    s.push(3);
}
