std::atomic_thread_fence

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <atomic>

extern "C" void atomic_thread_fence( std::memory_order order ) noexcept;  // (depuis C++11)

Établit un ordre de synchronisation mémoire des accès non atomiques et des accès atomiques relâchés, comme indiqué par order, sans opération atomique associée. Notez cependant qu'au moins une opération atomique est nécessaire pour mettre en place la synchronisation, comme décrit ci-dessous.

Synchronisation fence-atomic

Une barrière release F dans le thread A se synchronise avec une opération acquire atomique Y dans le thread B, si

  • il existe un stockage atomique X (avec un ordre mémoire quelconque),
  • Y lit la valeur écrite par X (ou la valeur qui serait écrite par la séquence de release dont X est la tête si X était une opération release),
  • F est séquencée avant X dans le thread A.

Dans ce cas, tous les stockages non atomiques et atomiques relâchés séquencés avant F dans le thread A se produisent avant tous les chargements non atomiques et atomiques relâchés des mêmes emplacements effectués dans le thread B après Y.

Synchronisation atomic-fence

Une opération release atomique X dans le thread A se synchronise avec une barrière acquire F dans le thread B, si

  • il existe une lecture atomique Y (avec un ordre mémoire quelconque),
  • Y lit la valeur écrite par X (ou par la séquence de release dont X est la tête),
  • Y est séquencée avant F dans le thread B.

Dans ce cas, tous les stockages non atomiques et atomiques relâchés séquencés avant X dans le thread A se produisent avant tous les chargements non atomiques et atomiques relâchés des mêmes emplacements effectués dans le thread B après F.

Synchronisation fence-fence

Une barrière release FA dans le thread A se synchronise avec une barrière acquire FB dans le thread B, si

  • il existe un objet atomique M,
  • il existe une écriture atomique X (avec un ordre mémoire quelconque) qui modifie M dans le thread A,
  • FA est séquencée avant X dans le thread A,
  • il existe une lecture atomique Y (avec un ordre mémoire quelconque) dans le thread B,
  • Y lit la valeur écrite par X (ou la valeur qui serait écrite par la séquence de release dont X est la tête si X était une opération release),
  • Y est séquencée avant FB dans le thread B.

Dans ce cas, tous les stockages non atomiques et atomiques relâchés séquencés avant FA dans le thread A se produisent avant tous les chargements non atomiques et atomiques relâchés des mêmes emplacements effectués dans le thread B après FB.

Paramètres

  • order — l'ordre mémoire exécuté par cette barrière

Valeur de retour

(aucune)

Notes

Sur x86 (y compris x86-64), les fonctions atomic_thread_fence n'émettent aucune instruction CPU et n'affectent que le déplacement de code à la compilation, sauf pour std::atomic_thread_fence(std::memory_order_seq_cst).

atomic_thread_fence impose des contraintes de synchronisation plus fortes qu'une opération de stockage atomique avec le même std::memory_order. Alors qu'un stockage atomique release empêche toutes les lectures et écritures précédentes de dépasser le stockage release, une atomic_thread_fence avec l'ordre std::memory_order_release empêche toutes les lectures et écritures précédentes de dépasser tous les stockages suivants.

La synchronisation fence-fence peut servir à ajouter de la synchronisation à une suite de plusieurs opérations atomiques relâchées, par exemple :

// Global
std::string computation(int);
void print(std::string);

std::atomic<int> arr[3] = {-1, -1, -1};
std::string data[1000]; //données non atomiques

// Thread A, calcule 3 valeurs.
void ThreadA(int v0, int v1, int v2)
{
//  assert(0 <= v0, v1, v2 < 1000);
    data[v0] = computation(v0);
    data[v1] = computation(v1);
    data[v2] = computation(v2);
    std::atomic_thread_fence(std::memory_order_release);
    std::atomic_store_explicit(&arr[0], v0, std::memory_order_relaxed);
    std::atomic_store_explicit(&arr[1], v1, std::memory_order_relaxed);
    std::atomic_store_explicit(&arr[2], v2, std::memory_order_relaxed);
}

// Thread B, affiche entre 0 et 3 valeurs déjà calculées.
void ThreadB()
{
    int v0 = std::atomic_load_explicit(&arr[0], std::memory_order_relaxed);
    int v1 = std::atomic_load_explicit(&arr[1], std::memory_order_relaxed);
    int v2 = std::atomic_load_explicit(&arr[2], std::memory_order_relaxed);
    std::atomic_thread_fence(std::memory_order_acquire);
//  v0, v1, v2 peuvent valoir -1, certaines ou toutes.
//  Sinon, il est sûr de lire les données non atomiques grâce aux barrières :
    if (v0 != -1)
        print(data[v0]);
    if (v1 != -1)
        print(data[v1]);
    if (v2 != -1)
        print(data[v2]);
}

Exemple

Parcourir un tableau de boîtes aux lettres et ne traiter que celles qui nous sont destinées, sans synchronisation inutile. Cet exemple utilise la synchronisation atomic-fence.

const int num_mailboxes = 32;
std::atomic<int> mailbox_receiver[num_mailboxes];
std::string mailbox_data[num_mailboxes];

// Les threads écrivains mettent à jour les données partagées non atomiques
// puis mettent à jour mailbox_receiver[i] comme suit :
mailbox_data[i] = ...;
std::atomic_store_explicit(&mailbox_receiver[i], receiver_id, std::memory_order_release);

// Le thread lecteur doit vérifier tous les mailbox[i], mais n'a besoin de se synchroniser qu'avec un seul.
for (int i = 0; i < num_mailboxes; ++i)
    if (std::atomic_load_explicit(&mailbox_receiver[i],
        std::memory_order_relaxed) == my_id)
    {
        // se synchroniser avec un seul écrivain
        std::atomic_thread_fence(std::memory_order_acquire);
        // garanti d'observer tout ce qui a été fait dans le thread écrivain
        // avant atomic_store_explicit()
        do_work(mailbox_data[i]);
    }
