1,2) Détermine si l'objet atomique pointé par obj est implémenté sans verrou, comme en appelant obj->is_lock_free(). Dans une exécution donnée du programme, le résultat de la requête sans verrou est le même pour tous les objets atomiques du même type.

3,4) Se développe en une expression constante entière de valeur

  • 0 pour les types atomiques natifs qui ne sont jamais sans verrou,
  • 1 pour les types atomiques natifs qui sont parfois sans verrou,
  • 2 pour les types atomiques natifs qui sont toujours sans verrou.

Paramètres

  • obj — pointeur vers l'objet atomique à examiner

Valeur de retour

true si *obj est un atomique sans verrou, false sinon.

Notes

Tous les types atomiques, à l'exception de std::atomic_flag, peuvent être implémentés à l'aide de mutex ou d'autres opérations de verrouillage, plutôt que des instructions atomiques sans verrou du processeur. Les types atomiques peuvent aussi être parfois sans verrou : par exemple, si seuls certains sous-architectures prennent en charge l'accès atomique sans verrou pour un type donné (comme l'instruction CMPXCHG16B sur x86-64), le fait que les atomiques soient sans verrou peut n'être connu qu'à l'exécution.

La norme C++ recommande (sans l'imposer) que les opérations atomiques sans verrou soient aussi indépendantes de l'adresse, c'est-à-dire utilisables pour la communication entre processus via une mémoire partagée.

Exemple

#include <atomic>
#include <iostream>
#include <utility>

struct A { int a[100]; };
struct B { int x, y; };

int main()
{
    std::atomic<A> a;
    std::atomic<B> b;
    std::cout << std::boolalpha
              << "std::atomic<A> is lock free? "
              << std::atomic_is_lock_free(&a) << '\n'
              << "std::atomic<B> is lock free? "
              << std::atomic_is_lock_free(&b) << '\n';
}

Sortie possible :

std::atomic<A> is lock free? false
std::atomic<B> is lock free? true

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 3249 C++11 atomic_is_lock_free a été spécifié via des pointeurs, ce qui était ambigu et pouvait accepter des valeurs de pointeur invalides spécifié via des objets atomiques
