Exigences nommées C++ : SequenceContainer

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un SequenceContainer est un Container qui stocke des objets de même type dans un agencement linéaire.

Exigences

Étant donnés les types et valeurs suivants :

Type Définition

  • C — une classe de conteneur de séquence
  • T — le type d'élément de C
  • A — le type d'allocateur de C :
    • C::allocator_type s'il existe,
    • sinon std::allocator<T>
  • R (depuis C++23) — un type qui modélise container-compatible-range ﻿<T>
  • Args (depuis C++11) — un paquet de paramètres de modèle
  • Iter — C::iterator
  • Ref — C::reference
  • CRef — C::const_reference

Valeur Définition

  • v — une valeur de type C
  • cv — une valeur de type const C
  • i, j — LegacyInputIterators tels que [i,j) est un intervalle valide et que les itérateurs désignent des éléments implicitement convertibles en C::value_type
  • rg (depuis C++23) — une valeur de type R
  • il (depuis C++11) — une valeur de type std::initializer_list<C::value_type>
  • n — une valeur de type C::size_type
  • p — un itérateur constant valide dans v
  • q — un itérateur constant valide et déréférençable dans v
  • q1, q2 — des itérateurs constants dans v tels que [q1,q2) est un intervalle valide
  • t — [une valeur (jusqu'à C++11) | une lvalue ou une rvalue constante (depuis C++11)] de type C::value_type
  • rv (depuis C++11) — une rvalue non const de type C::value_type
  • args (depuis C++11) — un paquet de paramètres de fonction avec le motif Arg&&

C satisfait les exigences de SequenceContainer si toutes les conditions suivantes sont satisfaites :

  • C satisfait les exigences de Container.
  • Les instructions et expressions suivantes sont bien formées et ont la sémantique indiquée :

Notes

  1. ↑ Pour une expression dont l'effet est équivalent à d'autres opérations, les conditions des expressions à l'intérieur de ces opérations sont héritées en plus des conditions listées dans le tableau.
  2. ↑ std::array prend en charge l'affectation à partir d'une liste d'initialisation entre accolades, mais pas à partir d'un std::initializer_list.
  3. ↑ Toutes les opérations ci-dessoussauf prepend_range et append_range (depuis C++23) s'exécutent en temps constant amorti.
  4. ↑ En C++98, tmp était déclaré avec le type C::iterator.
  5. ↑ En C++98, tmp était déclaré avec le type C::const_iterator.
  6. ↑ 6.0 6.1 L'ordre d'insertion, par rapport à l'ordre des éléments de rg, n'est pas inversé.

De plus, pour chaque conteneur de séquence :

  • Un modèle de constructeur prenant deux itérateurs d'entrée, ainsi que les surcharges de modèles de fonctions membres de insert, append, assign, replace prenant deux itérateurs d'entrée, ne participent pas à la résolution de surcharge si l'argument de modèle correspondant ne satisfait pas LegacyInputIterator.
  • Un guide de déduction qui possède soit un paramètre de modèle LegacyInputIterator, soit un paramètre de modèle Allocator, ne participe pas à la résolution de surcharge si le type qui ne satisfait pas à la condition d'itérateur d'entrée ou d'allocateur, respectivement, est déduit pour ce paramètre.

(depuis C++17)

Bibliothèque standard

Les types de chaînes et conteneurs suivants de la bibliothèque standard satisfont aux exigences SequenceContainer :

  • basic_string — stocke et manipule des séquences de caractères (modèle de classe)
  • array (C++11) — tableau contigu en place de taille fixe (modèle de classe)
  • vector — tableau dynamique contigu (modèle de classe)
  • inplace_vector (C++26) — tableau contigu redimensionnable à capacité fixe, en place (modèle de classe)
  • deque — file à double extrémité (modèle de classe)
  • forward_list (C++11) — liste simplement chaînée (modèle de classe)
  • list — liste doublement chaînée (modèle de classe)

Notes d'utilisation

Conteneur Avantages Inconvénients
std::vector Accès rapide, stockage contigu Insertions/suppressions généralement peu efficaces
std::inplace_vector Accès rapide, stockage contigu en place Capacité fixe et insertions/suppressions généralement peu efficaces
std::array Accès rapide, stockage contigu en place Nombre d'éléments fixe et aucune insertion/suppression
std::deque Accès rapide, insertion/suppression efficaces au début/à la fin Insertion/suppression peu efficaces au milieu de la séquence
std::list std::forward_list Insertion/suppression efficaces au milieu de la séquence L'accès est généralement en temps linéaire

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 139 C++98 les opérations facultatives n'étaient pas tenues d'être implémentées pour les conteneurs désignés requis avec un temps amorti
LWG 149 C++98 v.insert(p, t) renvoyait Iter tandis que v.insert(p, n, t) et v.insert(p, n, t) renvoyaient void elles renvoient toutes Iter
LWG 151 C++98 q1 devait être déréférençable[1] il peut être non déréférençable
LWG 355 C++98 appeler v.back() ou v.pop_back() reviendrait à exécuter --v.end(), ce qui est dangereux[2] décrémente une copie de v.end() à la place
LWG 589 C++98 les éléments désignés par i et j pourraient ne pas être convertibles en C::value_type elles sont implicitement convertibles en C::value_type
LWG 2194 C++11 std::queue, std::priority_queue et std::stack étaient aussi des SequenceContainers[3] elles ne sont pas des SequenceContainers
LWG 2231 C++11 l'exigence de complexité de v.clear() a été omise par erreur en C++11 complexité réaffirmée comme linéaire
LWG 3927 C++98 operator[] n'avait aucune exigence implicite ajout de l'exigence implicite
