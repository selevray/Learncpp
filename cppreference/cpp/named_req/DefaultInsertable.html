Exigences nommées C++ : DefaultInsertable (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Spécifie qu'un objet du type peut être construit par défaut sur place par un allocateur donné.

Exigences

Étant donnés les types, valeurs et expressions suivants :

Type Définition

  • T — un type objet
  • A — un type d'allocateur
  • X — un type de conteneur satisfaisant toutes les conditions suivantes :
    • X::value_type est le même que T.
    • X::allocator_type est le même que std::allocator_traits<A>::rebind_alloc<T>.

Valeur Définition

  • m — une lvalue de type A
  • p — un pointeur de type T*

Si l'expression std::allocator_traits<A>::construct(m, p) est bien formée, T est DefaultInsertable dans X.

Notes

Par défaut, cela va initialiser par valeur l'objet, comme par [::new((void*)p) T() (jusqu'à C++20) | std::construct_at(p) (depuis C++20)].

Si l'initialisation par valeur n'est pas souhaitable, par exemple si l'objet est de type non classe et que la mise à zéro n'est pas nécessaire, elle peut être évitée en fournissant un un Allocator::construct personnalisé.

Bien qu'il soit exigé que construct personnalisé soit utilisé lors de la construction des éléments de std::basic_string jusqu'en C++23, toutes les implémentations n'utilisaient que le mécanisme par défaut. L'exigence est corrigée par P1072R10 pour correspondre à la pratique existante.

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.
