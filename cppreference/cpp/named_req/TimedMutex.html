Exigences nommées C++ : TimedMutex (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les exigences TimedMutex étendent les exigences TimedLockable pour inclure la synchronisation entre threads.

Exigences

  • TimedLockable
  • Mutex

De plus, pour un objet m de type TimedMutex :

  • L'expression m.try_lock_for(duration) possède les propriétés suivantes

    • Se comporte comme une opération atomique.
    • Tente d'obtenir la propriété exclusive du mutex dans la durée spécifiée par duration. Si duration est inférieur ou égal à duration.zero(), tente d'obtenir la propriété sans bloquer (comme avec try_lock()). Sinon, cette fonction bloque jusqu'à ce que le mutex soit acquis ou jusqu'à ce que le temps spécifié par duration soit écoulé. Elle ne retourne dans duration que si elle réussit, mais elle peut échouer à acquérir le mutex même si, à un moment pendant duration, il n'était pas possédé par un autre thread. Dans tous les cas, elle retourne true si le mutex a été acquis et false sinon.
    • Si try_lock_for(duration) réussit, les opérations unlock() précédentes sur le même objet synchronize-with cette opération (équivalent à release-acquire std::memory_order).
    • Le comportement est indéfini si le thread appelant possède déjà le mutex (sauf si m est std::recursive_timed_mutex).
    • Une exception peut être levée par l'horloge, le point temporel ou la durée pendant l'exécution (les horloges, points temporels et durées fournis par la bibliothèque standard ne lèvent jamais d'exception).

  • L'expression m.try_lock_until(time_point) possède les propriétés suivantes

    • Se comporte comme une opération atomique.
    • Tente d'obtenir la propriété exclusive du mutex dans le temps restant jusqu'à time_point. Si time_point est déjà passé, tente d'obtenir la propriété sans bloquer (comme avec try_lock()). Sinon, cette fonction bloque jusqu'à ce que le mutex soit acquis ou jusqu'à ce que le temps spécifié par time_point soit écoulé. Elle ne retourne avant time_point que si elle réussit, mais elle peut échouer à acquérir le mutex même si, à un moment avant time_point, il n'était pas possédé par un autre thread. Dans tous les cas, elle retourne true si le mutex a été acquis et false sinon.
    • Si try_lock_until(time_point) réussit, les opérations unlock() précédentes sur le même objet synchronize-with cette opération (équivalent à release-acquire std::memory_order).
    • Le comportement est indéfini si le thread appelant possède déjà le mutex (sauf si m est std::recursive_timed_mutex).
    • Une exception peut être levée par l'horloge, le point temporel ou la durée pendant l'exécution (les horloges, points temporels et durées fournis par la bibliothèque standard ne lèvent jamais d'exception).

Bibliothèque standard

Les types de la bibliothèque standard suivants satisfont les exigences TimedMutex :

  • recursive_timed_mutex (C++11) — fournit un mécanisme d'exclusion mutuelle pouvant être verrouillé récursivement par le même thread et implémentant le verrouillage avec délai d'attente (classe)
  • shared_timed_mutex (C++14) — fournit un mécanisme d'exclusion mutuelle partagée et implémente le verrouillage avec délai d'attente (classe)
  • timed_mutex (C++11) — fournit un mécanisme d'exclusion mutuelle qui implémente le verrouillage avec délai d'attente (classe)
