Exigences nommées C++ : LiteralType (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Spécifie qu'un type est un type littéral. Les types littéraux sont les types des variables constexpr et peuvent être construits, manipulés et renvoyés par les fonctions constexpr.

Note : la norme ne définit pas d'exigence nommée portant ce nom. Il s'agit d'une catégorie de types définie par le langage de base. Elle n'est incluse ici comme exigence nommée que par cohérence.

Exigences

Un type littéral est l'un des suivants :

  • void éventuellement qualifié cv (afin que les fonctions constexpr puissent renvoyer void) ;

(depuis C++14)

  • type scalaire ;
  • type référence ;
  • un tableau de type littéral ;
  • un type classe éventuellement qualifié cv possédant toutes les propriétés suivantes :
    • possède un destructeur [trivial (jusqu'à C++20) | constexpr (depuis C++20)],
    • tous ses membres de données non statiques et non variant ainsi que ses classes de base sont de types littéraux non volatils, et
    • est l'un des suivants
  • un type lambda,

(depuis C++17)

  • un type union agrégat qui

    • n'a aucun membre variant, ou
    • possède au moins un membre variant de type littéral non volatile,

  • un type agrégat qui n'est pas une union, et dont chacun de ses membres union anonyme

    • n'a aucun membre variant, ou
    • possède au moins un membre variant de type littéral non volatile,

  • un type possédant au moins un constructeur (éventuellement modèle) constexpr qui n'est ni un constructeur de copie ni un constructeur de déplacement.

Notes

Un type peut être littéral même si tous ses constructeurs constexpr sont supprimés, inaccessibles, ou ne peuvent pas participer à la résolution de surcharge.

struct A { constexpr A(int) = delete; char c; }; // A est un type littéral
constexpr A v = std::bit_cast<A>('0'); // OK en C++20
                                       // v a un type littéral et peut donc être constexpr

Exemple

Type littéral qui étend les littéraux de chaîne :

#include <cstddef>
#include <iostream>
#include <stdexcept>

class conststr // conststr est un type littéral
{
    const char* p;
    std::size_t sz;
public:
    template<std::size_t N>
    constexpr conststr(const char(&a)[N]) : p(a), sz(N - 1) {}

    constexpr char operator[](std::size_t n) const
    {
        return n < sz ? p[n] : throw std::out_of_range("");
    }

    constexpr std::size_t size() const { return sz; }
};

constexpr std::size_t count_lower(conststr s)
{
    std::size_t c{};
    for (std::size_t n{}; n != s.size(); ++n)
        if ('a' <= s[n] && s[n] <= 'z')
            ++c;
    return c;
}

// Une fonction de sortie qui exige une constante de compilation N, à des fins de test
template<int N>
struct constN
{
    constN() { std::cout << N << '\n'; }
};

int main()
{
    std::cout << "The number of lowercase letters in \"Hello, world!\" is ";
    constN<count_lower("Hello, world!")>(); // le littéral de chaîne est implicitement
                                            // converti en conststr
}

Output:

The number of lowercase letters in "Hello, world!" is 9

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 1453 C++11 une classe littérale pouvait avoir des membres de données volatils non autorisé
CWG 1951 C++11 C++14 on ne savait pas si les types void (depuis C++14) et les types classe (depuis C++11) sont des types littéraux, lorsqu'ils sont qualifiés cv ils le sont
CWG 2096 C++11 pour qu'un type union soit littéral, tous ses membres de données non statiques doivent être littéraux un seul membre de données non statique doit l'être
CWG 2598 C++11 pour qu'un type union soit littéral, il doit posséder au moins un membre de données non statique il peut ne posséder aucun membre de données non statique
