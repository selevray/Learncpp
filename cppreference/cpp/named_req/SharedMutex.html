Exigences nommées C++ : SharedMutex (depuis C++17)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les exigences SharedMutex étendent les exigences Mutex pour inclure le mode de propriété de verrou partagé.

Exigences

  • Mutex

De plus, un objet m de type SharedMutex prend en charge un autre mode de propriété : partagé. Plusieurs threads (ou, plus généralement, agents d'exécution) peuvent posséder simultanément ce mutex en mode partagé, mais aucun thread ne peut obtenir la propriété partagée si un thread la possède en mode exclusif, et aucun thread ne peut obtenir la propriété exclusive si un thread la possède en mode partagé. Si plus de N threads (défini par l'implémentation, et au moins 10000) détiennent un verrou partagé, une nouvelle tentative d'acquisition du mutex en mode partagé se bloque jusqu'à ce que le nombre de propriétaires partagés repasse sous ce seuil.

  • L'expression m.lock_shared() possède les propriétés suivantes :

    • Se comporte comme une opération atomique.
    • Bloque le thread appelant jusqu'à ce que la propriété partagée du mutex puisse être obtenue.
    • Les opérations m.unlock() antérieures sur le même mutex synchronize-with cette opération de verrouillage (équivalent à release-acquire std::memory_order).
    • Le comportement est indéfini si le thread appelant possède déjà le mutex, quel que soit le mode.
    • Si une exception est levée, le verrou partagé n'est pas acquis.

  • L'expression m.try_lock_shared() possède les propriétés suivantes :

    • Se comporte comme une opération atomique.
    • Tente d'obtenir la propriété partagée du mutex pour le thread appelant sans bloquer. Si la propriété n'est pas obtenue, retourne immédiatement. La fonction peut échouer de façon spurious et retourner même si le mutex n'est actuellement possédé par aucun thread, quel que soit le mode.
    • Si try_lock_shared() réussit, les opérations unlock() précédentes sur le même objet synchronize-with cette opération (équivalent à release-acquire std::memory_order).
    • Le comportement est indéfini si le thread appelant possède déjà le mutex, quel que soit le mode.

  • L'expression m.unlock_shared() possède les propriétés suivantes :

    • Se comporte comme une opération atomique.
    • Libère la propriété du mutex par le thread appelant et synchronise-with les opérations de verrouillage réussies ultérieures sur le même objet.
    • Le comportement est indéfini si le thread appelant ne possède pas le mutex.

  • Toutes les opérations de verrouillage et de déverrouillage sur un même mutex se produisent dans un ordre total unique.

Bibliothèque standard

Les types de la bibliothèque standard suivants satisfont les exigences SharedMutex :

  • shared_mutex (C++17) — fournit un mécanisme d'exclusion mutuelle partagée (classe)
  • shared_timed_mutex (C++14) — fournit un mécanisme d'exclusion mutuelle partagée et implémente le verrouillage avec délai d'attente (classe)
