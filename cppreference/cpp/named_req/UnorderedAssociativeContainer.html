Exigences nommées C++ : UnorderedAssociativeContainer (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les conteneurs associatifs non ordonnés sont des Containers qui fournissent une recherche rapide d'objets à partir de clés. La complexité dans le pire cas est linéaire, mais en moyenne elle est beaucoup plus rapide pour la plupart des opérations.

Les conteneurs associatifs non ordonnés sont paramétrés par Key ; Hash, un objet fonction Hash qui agit comme fonction de hachage sur Key ; et Pred, un BinaryPredicate évaluant l'équivalence entre les Keys. std::unordered_map et std::unordered_multimap ont également un type mappé T associé à Key.

Si deux Keys sont égales selon Pred, Hash doit renvoyer la même valeur pour les deux clés.

Si Hash::is_transparent et Pred::is_transparent existent et désignent chacun un type, les fonctions membres find, contains, count, equal_range et bucket acceptent des arguments de types autres que Key et attendent que Hash soit appelable avec des valeurs de ces types, et que Pred soit une fonction de comparaison transparente telle que std::equal_to<>.

(depuis C++20)

std::unordered_map et std::unordered_set ne peuvent contenir qu'au plus un élément pour une clé donnée, std::unordered_multiset et std::unordered_multimap peuvent au contraire avoir plusieurs éléments de même clé (qui doivent toujours être adjacents lors des itérations).

Pour std::unordered_set et std::unordered_multiset, le type de valeur est le même que le type de clé, et iterator et const_iterator sont tous deux des itérateurs constants. Pour std::unordered_map et std::unordered_multimap, le type de valeur est std::pair<const Key, T>.

Les éléments d'un conteneur associatif non ordonné sont organisés en compartiments ; les clés ayant le même hachage se retrouvent dans le même compartiment. Le nombre de compartiments est augmenté lorsque la taille du conteneur croît, afin de maintenir le nombre moyen d'éléments par compartiment sous une certaine valeur.

Le rehachage invalide les itérateurs et peut provoquer la réorganisation des éléments dans des compartiments différents, mais il n'invalide pas les références aux éléments.

Les conteneurs associatifs non ordonnés satisfont les exigences de AllocatorAwareContainer. Pour std::unordered_map et std::unordered_multimap, les exigences de value_type dans AllocatorAwareContainer s'appliquent à key_type et mapped_type (et non à value_type).

##### Légende {#Legend}

  • X — Une classe de conteneur associatif non ordonné

  • a — Une valeur de type X

  • a2 — Une valeur d'un type dont les nœuds sont compatibles avec le type X

  • b — Une valeur de type X ou const X

  • a_uniq — Une valeur de type X lorsque X prend en charge les clés uniques

  • a_eq — Une valeur de type X lorsque X prend en charge les clés équivalentes

  • a_tran — Une valeur de type X ou const X lorsque les identifiants qualifiés X::key_equal::is_transparent et X::hasher::is_transparent sont tous deux valides et désignent des types

  • i, j — Itérateurs d'entrée qui font référence à value_type

  • [i,j) — Un intervalle valide

  • rg (depuis C++23) — Une valeur d'un type R qui modélise container-compatible-range<value_type>

  • p, q2 — Itérateurs constants valides vers a

  • q, q1 — Itérateurs constants valides et déréférençables vers a

  • r — Un itérateur déréférençable valide vers a

  • [q1,q2) — Un intervalle valide dans a

  • il — Une valeur de type std::initializer_list<value_type>

  • t — Une valeur de type X::value_type

  • k — Une valeur de type key_type

  • hf — Une valeur de type hasher ou const hasher

  • eq — Une valeur de type key_equal ou const key_equal

  • ke — Une valeur telle que

    • eq(r1, ke) == eq(ke, r1),
    • hf(r1) == hf(ke) si eq(r1, ke) est true, et
    • si deux quelconques parmi eq(r1, ke), eq(r2, ke) et eq(r1, r2) sont true, alors les trois sont true,

    où r1 et r2 sont des clés d'éléments dans a_tran

  • kx (depuis C++23) — Une valeur telle que

    • eq(r1, kx) == eq(kx, r1),
    • hf(r1) == hf(kx) si eq(r1, kx) est true,
    • si deux quelconques parmi eq(r1, kx), eq(r2, kx) et eq(r1, r2) sont true, alors les trois sont true, et
    • kx n'est convertible ni en iterator ni en const_iterator,

    où r1 et r2 sont des clés d'éléments dans a_tran

  • n — Une valeur de type size_type

  • z — Une valeur de type float

  • nh (depuis C++17) — Une rvalue de type X::node_type

Bibliothèque standard

Les conteneurs de la bibliothèque standard suivants satisfont aux exigences UnorderedAssociativeContainer :

  • unordered_set (C++11) — collection de clés uniques, hachées par clés (modèle de classe)
  • unordered_multiset (C++11) — collection de clés, hachées par clés (modèle de classe)
  • unordered_map (C++11) — collection de paires clé-valeur, hachées par clés, les clés étant uniques (modèle de classe)
  • unordered_multimap (C++11) — collection de paires clé-valeur, hachée par clés (modèle de classe)
