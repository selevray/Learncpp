Exigences nommées C++ : LegacyOutputIterator

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un LegacyOutputIterator est un LegacyIterator pouvant écrire dans l'élément pointé.

Un exemple de type implémentant LegacyOutputIterator est std::ostream_iterator.

Lorsque LegacyForwardIterator, LegacyBidirectionalIterator ou LegacyRandomAccessIterator satisfait aux exigences de LegacyOutputIterator en plus de ses propres exigences, il est dit mutable.

Exigences

Le type X satisfait LegacyOutputIterator si

  • Le type X satisfait LegacyIterator
  • X est un type classe ou un type pointeur

Et, étant donnés

  • o, une valeur d'un certain type pouvant être écrite dans l'itérateur de sortie (il peut y avoir plusieurs types inscriptibles, par exemple si operator= peut être un modèle. Il n'existe pas de notion de value_type comme pour les itérateurs d'entrée)
  • r, une lvalue de type X,

Les expressions suivantes doivent être valides et produire les effets spécifiés

*r = o (non utilisé) r est déréférençable r est incrémentable Après cette opération, r n'est pas tenu d'être déréférençable, et toute copie de la valeur précédente de r n'est plus tenue d'être déréférençable ou incrémentable.

*r++ = o (non utilisé) *r = o; ++r;

Notes

La seule utilisation valide de operator* avec un itérateur de sortie est à gauche d'une affectation : operator* peut renvoyer un objet proxy, qui définit un membre operator= (qui peut être un modèle).

L'égalité et l'inégalité ne peuvent pas être définies pour les itérateurs de sortie. Même si un operator== est défini, x == y n'implique pas nécessairement ++x == ++y.

L'affectation via la même valeur d'un itérateur de sortie n'a lieu qu'une fois : les algorithmes sur les itérateurs de sortie doivent être des algorithmes à passage unique.

L'affectation via un itérateur de sortie doit alterner avec l'incrémentation. Une double incrémentation est un comportement indéfini (la norme C++ affirme actuellement que la double incrémentation est prise en charge, contrairement à la documentation de la STL ; il s'agit du LWG issue 2035).

Un itérateur de sortie purement en écriture peut déclarer ses iterator_traits<X>::value_type, iterator_traits<X>::difference_type, iterator_traits<X>::pointer et iterator_traits<X>::reference comme étant void (et des itérateurs tels que std::back_insert_iterator le font justementsauf pour difference_type, qui est désormais défini pour satisfaire std::output_iterator (depuis C++20)).

Bibliothèque standard

Les itérateurs de la bibliothèque standard suivants sont des itérateurs de sortie qui ne sont pas des itérateurs avant :

  • ostream_iterator — itérateur de sortie qui écrit dans std::basic_ostream (modèle de classe)
  • ostreambuf_iterator — itérateur de sortie qui écrit dans std::basic_streambuf (modèle de classe)
  • insert_iterator — adaptateur d'itérateur pour l'insertion dans un conteneur (modèle de classe)
  • back_insert_iterator — adaptateur d'itérateur pour l'insertion à la fin d'un conteneur (modèle de classe)
  • front_insert_iterator — adaptateur d'itérateur pour l'insertion au début d'un conteneur (modèle de classe)
