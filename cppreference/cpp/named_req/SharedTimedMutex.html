Exigences nommées C++ : SharedTimedMutex (depuis C++14)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les exigences SharedTimedMutex étendent les exigences TimedMutex pour inclure le mode de propriété de verrou partagé.

Exigences

  • TimedMutex
  • SharedMutex

De plus, un objet m de type SharedTimedMutex prend en charge les opérations partagées temporisées :

  • L'expression m.try_lock_shared_for(duration) possède les propriétés suivantes

    • Se comporte comme une opération atomique.
    • Tente d'obtenir la propriété partagée du mutex dans la durée spécifiée par duration. Si duration est inférieur ou égal à duration.zero(), tente d'obtenir la propriété sans attendre (comme avec try_lock()). Sinon, cette fonction bloque jusqu'à ce que le mutex soit acquis ou jusqu'à ce que le temps spécifié par duration soit écoulé. Elle ne retourne dans duration que si elle réussit, mais elle peut échouer à acquérir le mutex même si, à un moment pendant duration, il n'était pas possédé par un autre thread. Dans tous les cas, elle retourne true si le mutex a été acquis et false sinon.
    • Si try_lock_shared_for(duration) réussit, les opérations unlock() précédentes sur le même objet synchronize-with cette opération (équivalent à release-acquire std::memory_order).
    • Le comportement est indéfini si le thread appelant possède déjà le mutex, quel que soit le mode.
    • Une exception peut être levée par l'horloge, le point temporel ou la durée pendant l'exécution (les horloges, points temporels et durées fournis par la bibliothèque standard ne lèvent jamais d'exception).
    • Si une exception est levée, le verrou partagé n'est pas acquis.

  • L'expression m.try_lock_shared_until(time_point) possède les propriétés suivantes

    • Se comporte comme une opération atomique.
    • Tente d'obtenir la propriété partagée du mutex dans le temps restant jusqu'à time_point. Si time_point est déjà passé, tente d'obtenir la propriété sans verrouillage (comme avec try_lock()). Sinon, cette fonction bloque jusqu'à ce que le mutex soit acquis ou jusqu'à ce que le temps spécifié par time_point soit écoulé. Elle ne retourne avant time_point que si elle réussit, mais elle peut échouer à acquérir le mutex même si, à un moment avant time_point, il n'était pas possédé par un autre thread. Dans tous les cas, elle retourne true si le mutex a été acquis et false sinon.
    • Si try_lock_shared_until(time_point) réussit, les opérations unlock() précédentes sur le même objet synchronize-with cette opération (équivalent à release-acquire std::memory_order).
    • Le comportement est indéfini si le thread appelant possède déjà le mutex, quel que soit le mode.
    • Une exception peut être levée par l'horloge, le point temporel ou la durée pendant l'exécution (les horloges, points temporels et durées fournis par la bibliothèque standard ne lèvent jamais d'exception).
    • Si une exception est levée, le verrou partagé n'est pas acquis.

Bibliothèque standard

Les types de la bibliothèque standard suivants satisfont les exigences SharedTimedMutex :

  • shared_timed_mutex (C++14) — fournit un mécanisme d'exclusion mutuelle partagée et implémente le verrouillage avec délai d'attente (classe)
