Exigences nommées C++ : Lockable (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les exigences Lockable étendent les exigences BasicLockable pour inclure la tentative de verrouillage.

Exigences

  • BasicLockable

Pour que le type L soit Lockable, il doit satisfaire la condition ci-dessus ainsi que ce qui suit :

Expression Effets Valeur de retour
m.try_lock() Tente d'acquérir le verrou pour l'agent d'exécution courant (thread, processus, tâche) sans blocage. Si une exception est levée, aucun verrou n'est obtenu. true si le verrou a été acquis, false sinon

Notes

Les fonctions membres try_lock obtiennent un verrou non partagé sur m en cas de succès.

Bibliothèque standard

Les types de la bibliothèque standard suivants satisfont les exigences Lockable :

  • mutex (C++11) — fournit un mécanisme d'exclusion mutuelle de base (classe)
  • recursive_mutex (C++11) — fournit un mécanisme d'exclusion mutuelle pouvant être verrouillé récursivement par le même thread (classe)
  • recursive_timed_mutex (C++11) — fournit un mécanisme d'exclusion mutuelle pouvant être verrouillé récursivement par le même thread et implémentant le verrouillage avec délai d'attente (classe)
  • shared_mutex (C++17) — fournit un mécanisme d'exclusion mutuelle partagée (classe)
  • shared_timed_mutex (C++14) — fournit un mécanisme d'exclusion mutuelle partagée et implémente le verrouillage avec délai d'attente (classe)
  • timed_mutex (C++11) — fournit un mécanisme d'exclusion mutuelle qui implémente le verrouillage avec délai d'attente (classe)
