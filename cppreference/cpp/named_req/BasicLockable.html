Exigences nommées C++ : BasicLockable (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les exigences BasicLockable décrivent les caractéristiques minimales des types qui fournissent une sémantique de blocage exclusif pour les agents d'exécution (c'est-à-dire les threads).

Exigences

Pour que le type L soit BasicLockable, les conditions suivantes doivent être satisfaites pour un objet m de type L :

Expression | Préconditions | Effets

m.lock() | Bloque jusqu'à ce qu'un verrou puisse être acquis pour l'agent d'exécution courant (thread, processus, tâche). Si une exception est levée, aucun verrou n'est acquis.

m.unlock() | L'agent d'exécution courant détient un verrou non partagé sur m. | Libère le verrou non partagé détenu par l'agent d'exécution.

Ne lève aucune exception.

Verrous non partagés

Un verrou sur un objet est dit verrou non partagé s'il est acquis par un appel à la fonction membre lock, try_lock, try_lock_for ou try_lock_until.

Bibliothèque standard

Les types de la bibliothèque standard suivants satisfont les exigences BasicLockable :

  • mutex (C++11) — fournit un mécanisme d'exclusion mutuelle de base (classe)
  • recursive_mutex (C++11) — fournit un mécanisme d'exclusion mutuelle pouvant être verrouillé récursivement par le même thread (classe)
  • recursive_timed_mutex (C++11) — fournit un mécanisme d'exclusion mutuelle pouvant être verrouillé récursivement par le même thread et implémentant le verrouillage avec délai d'attente (classe)
  • shared_mutex (C++17) — fournit un mécanisme d'exclusion mutuelle partagée (classe)
  • shared_timed_mutex (C++14) — fournit un mécanisme d'exclusion mutuelle partagée et implémente le verrouillage avec délai d'attente (classe)
  • timed_mutex (C++11) — fournit un mécanisme d'exclusion mutuelle qui implémente le verrouillage avec délai d'attente (classe)
