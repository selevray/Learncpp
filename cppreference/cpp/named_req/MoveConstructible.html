Exigences nommées C++ : MoveConstructible (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Précise qu'une instance du type peut être construite à partir d'un argument rvalue.

Exigences

Le type T satisfait MoveConstructible si

Soient

  • rv, une expression rvalue de type T,
  • u, un identifiant quelconque.

Les expressions suivantes doivent être valides et produire les effets spécifiés.

Expression | Post-conditions

T u = rv; | La valeur de u est équivalente à la valeur de rv avant l'initialisation.

La nouvelle valeur de rv est non spécifiée.

T(rv) | La valeur de T(rv) est équivalente à la valeur de rv avant l'initialisation.

La nouvelle valeur de rv est non spécifiée.

Notes

Une classe n'a pas besoin d'implémenter un constructeur de déplacement pour satisfaire cette exigence de type : un constructeur de copie qui prend un argument const T& peut lier des expressions rvalue.

Si une classe MoveConstructible implémente un constructeur de déplacement, elle peut également implémenter la sémantique de déplacement pour tirer parti du fait que la valeur de rv après la construction est non spécifiée.

Contenu étendu

Être une classe MoveConstructible implique std::is_move_constructible mais pas l'inverse, car std::is_move_constructible vérifie seulement la possibilité d'appeler le constructeur avec les bons arguments, et non une valeur de postcondition.

#include <iostream>

struct S
{
    int n;
    S(int in) : n{in} {}
    S(S&& other) { n = other.n + 1; }
};
static_assert(std::is_move_constructible_v<S>);

int main()
{
    S v{1};
    std::cout << "v.n = " << v.n << '\n';
    S u = std::move(v);

    // La classe `S` ne satisfait pas une exigence MoveConstructible
    // La valeur de `u` n'est PAS équivalente à la valeur de `v` avant l'initialisation de `u`
    std::cout << "u.n = " << u.n << '\n';
}

Output:

v.n = 1
u.n = 2
