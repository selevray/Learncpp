Exigences nommées C++ : LegacyForwardIterator

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un LegacyForwardIterator est un LegacyIterator pouvant lire des données depuis l'élément pointé.

Contrairement à LegacyInputIterator et LegacyOutputIterator, il peut être utilisé dans des algorithmes à passes multiples.

Si un LegacyForwardIterator it provient d'un Container, alors le type de valeur de it est le même que celui du conteneur, de sorte que le déréférencement (*it) obtient le type de valeur du conteneur.

Exigences

Type Définition

  • X — Un type d'itérateur avant
  • T — Le type de valeur de X (c'est-à-dire std::iterator_traits<X>::value_type)
  • Ref — std::iterator_traits<X>::reference

Valeur Définition

  • i, j — Valeurs de type X ou const X
  • r — Une valeur de type X&

X satisfait LegacyForwardIterator si toutes les conditions suivantes sont remplies :

  • X satisfait LegacyInputIterator.
  • X satisfait DefaultConstructible.
  • Si X est un itérateur modifiable, Ref est une référence vers T.
  • Si X est un itérateur constant, Ref est une référence vers const T.
  • Les objets de type X fournissent la garantie de passes multiples.
  • Si i et j sont égaux, alors soit i et j sont toutes deux déréférençables, soit aucune des deux ne l'est.
  • Si i et j sont toutes deux déréférençables, alors i == j si et seulement si *i et *j sont liées au même objet.
  • Les expressions suivantes doivent être valides et avoir les effets spécifiés :
Expression Type Effets
r++ convertible en const X& Équivalent à X x = r;++r;return x;.
*i++ Ref

Domaine d'égalité

Le domaine de == pour les itérateurs avant est celui des itérateurs sur la même séquence sous-jacente.

Cependant, les itérateurs avant initialisés par valeur peuvent être comparés, et doivent être égaux à tout autre itérateur initialisé par valeur du même type.

En d'autres termes, les itérateurs avant initialisés par valeur se comportent comme s'ils référençaient au-delà de la fin de la même séquence vide.

(depuis C++14)

Garantie de passes multiples

Deux itérateurs déréférençables a et b de type X offrent la garantie de passes multiples si toutes les conditions suivantes sont remplies :

  • a == b implique ++a == ++b.
  • L'une quelconque des conditions suivantes est satisfaite :
    • X est un type pointeur.
    • L'expression (void)++X(a), *a est équivalente à l'expression *a.

Concept

Pour la définition de std::iterator_traits, le concept d'exposition suivant est défini.

template<class It>
concept __LegacyForwardIterator =
    __LegacyInputIterator<It> && std::constructible_from<It> &&
    std::is_reference_v<std::iter_reference_t<It>> &&
    std::same_as<
        std::remove_cvref_t<std::iter_reference_t<It>>,
        typename std::indirectly_readable_traits<It>::value_type> &&
    requires(It it) {
        {  it++ } -> std::convertible_to<const It&>;
        { *it++ } -> std::same_as<std::iter_reference_t<It>>;
    };

où le concept __LegacyInputIterator<T>, réservé à l'exposition, est décrit dans LegacyInputIterator.

(depuis C++20)

Notes

Contrairement au concept std::forward_iterator, les exigences LegacyForwardIterator imposent que le déréférencement renvoie une référence.

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.
