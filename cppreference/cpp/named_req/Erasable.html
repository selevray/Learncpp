Exigences nommées C++ : Erasable (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Spécifie qu'un objet du type peut être détruit par un Allocator donné.

Exigences

Étant donnés les types, valeurs et expressions suivants :

Type Définition

  • T — un type objet
  • A — un type d'allocateur
  • X — un type de conteneur satisfaisant toutes les conditions suivantes :
    • X::value_type est le même que T.
    • X::allocator_type est le même que std::allocator_traits<A>::rebind_alloc<T>.

Valeur Définition

  • m — une lvalue de type A
  • p — un pointeur de type T*

Si l'expression std::allocator_traits<A>::destroy(m, p) est bien formée, T est Erasable depuis X.

Notes

Tous les conteneurs de la bibliothèque standard exigent que leurs types de valeur satisfassent Erasable.

Avec l'allocateur par défaut, cette exigence est équivalente à la validité de p->~T(), qui accepte les types classe avec destructeurs accessibles et tous les types scalaires, mais rejette les types tableau, les types fonction, les types référence et void.

(jusqu'à C++20)

Avec l'allocateur par défaut, cette exigence est équivalente à la validité de std::destroy_at(p), qui accepte les types classe avec destructeurs accessibles et tous les types scalaires, ainsi que les tableaux de ceux-ci.

(depuis C++20)

Bien qu'il soit requis que destroy personnalisé soit utilisé lors de la destruction des éléments de std::basic_string jusqu'à C++23, toutes les implémentations n'utilisaient que le mécanisme par défaut. L'exigence est corrigée par P1072R10 pour correspondre à la pratique existante.
