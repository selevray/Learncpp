Signature d'appel

execution::sender auto read_env( auto&& query );  // (depuis C++26)

Une fabrique d'émetteurs qui retourne un émetteur allant chercher dans l'environnement d'un récepteur la valeur courante associée à un objet de requête donné.

Pour tout objet de requête q, l'expression read_env(q) est équivalente à une expression à /*make-sender*/(read_env, q).

Objets de point de personnalisation

Le nom execution::read_env désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __read_env_fn.

Toutes les instances de __read_env_fn sont égales. Les effets de l'invocation de différentes instances du type __read_env_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, execution::read_env peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de execution::read_env ci-dessus, alors __read_env_fn modélise

  • std::invocable<__read_env_fn, Args...>,
  • std::invocable<const __read_env_fn, Args...>,
  • std::invocable<__read_env_fn&, Args...>, and
  • std::invocable<const __read_env_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __read_env_fn ne participe à la résolution de surcharge.

Exemple

Un exemple d'utilisation de cette fabrique consiste à planifier un travail dépendant sur l'ordonnanceur du récepteur, que l'on peut obtenir avec read_env(get_scheduler) :

std::execution::sender auto task =
  std::execution::read_env(std::execution::get_scheduler)
    | std::execution::let_value([](auto sched) {
        return std::execution::starts_on(sched, /*du travail imbriqué ici*/);
    });

std::this_thread::sync_wait( std::move(task) ); // attendre sa fin
