Une fabrique d'émetteurs qui retourne un émetteur qui s'achève immédiatement en appelant le set_error() du récepteur.

Soit e une sous-expression représentée par une erreur d'entrée qui sera injectée et retournée par le récepteur. L'expression just_error(e) est équivalente à une expression à /*make-sender*/(just_error, /*product-type*/(e))

Objets de point de personnalisation

Le nom execution::just_error désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. La version sans qualificateurs cv de son type est un type d'étiquette désigné par execution::just_error_t.

Toutes les instances de execution::just_error_t sont égales. Les effets de l'invocation de différentes instances du type execution::just_error_t sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, execution::just_error peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de execution::just_error ci-dessus, alors execution::just_error_t modélise

  • std::invocable<execution::just_error_t, Args...>,
  • std::invocable<const execution::just_error_t, Args...>,
  • std::invocable<execution::just_error_t&, Args...>, and
  • std::invocable<const execution::just_error_t&, Args...>.

Sinon, aucun opérateur d'appel de fonction de execution::just_error_t ne participe à la résolution de surcharge.

Notes

Si l'erreur fournie est une référence lvalue, une copie est faite à l'intérieur de l'émetteur retourné et une référence lvalue non const vers la copie est envoyée à set_error du récepteur. Si la valeur fournie est une référence rvalue, elle est déplacée dans l'émetteur retourné et une référence rvalue vers celle-ci est envoyée à set_error du récepteur.
