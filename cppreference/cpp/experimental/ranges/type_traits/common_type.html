std::experimental::ranges::common_type

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <experimental/ranges/type_traits>

template< class... T >
struct common_type;  // (ranges TS)

Détermine le type commun parmi tous les types T..., c'est-à-dire le type vers lequel tous les T... peuvent être implicitement convertis. Si un tel type existe (selon les règles ci-dessous), le membre type désigne ce type. Sinon, il n'existe aucun membre type. Le comportement est indéfini si l'un des types de T... est un type incomplet autre que void (éventuellement qualifié cv).

  • Si sizeof...(T) vaut zéro, il n'existe aucun membre type.

  • Si sizeof...(T) vaut un (c'est-à-dire que T... ne contient qu'un seul type T0), le membre type désigne le même type que std::decay_t<T0>.

  • Si sizeof...(T) vaut deux (c'est-à-dire que T... contient exactement deux types T1 et T2),

    • Si l'application de std::decay à au moins l'un de T1 et T2 produit un type différent, le membre type désigne le même type que ranges::common_type_t<std::decay_t<T1>, std::decay_t<T2>>, s'il existe ; sinon, il n'existe aucun membre type ;
    • Sinon, (et sauf s'il existe une spécialisation utilisateur pour ranges::common_type<T1, T2>), si std::common_type_t<T1, T2> est bien formé, alors le membre type désigne ce type ;
    • Sinon, le membre type désigne le type std::decay_t<decltype(false ? std::declval<const T1&>() : std::declval<const T2&>())>, si cette expression conditionnelle est bien formée ; sinon, il n'existe aucun membre type.

  • Si sizeof...(T) est supérieur à deux (c'est-à-dire que T... est constitué des types T1, T2, R...), alors, si ranges::common_type_t<T1, T2> existe, le membre type désigne ranges::common_type_t<ranges::common_type_t<T1, T2>, R...> si un tel type existe. Dans tous les autres cas, il n'existe aucun membre type.

  • type — le type commun pour tous les T...

Types auxiliaires

template< class... T >
using common_type_t = typename common_type<T...>::type;

Spécialisations

Les utilisateurs peuvent spécialiser common_type pour les types T1 et T2 si

  • au moins l'un de T1 et T2 dépend d'un type défini par l'utilisateur, et
  • std::decay est une transformation identité pour T1 et T2.

Si une telle spécialisation possède un membre nommé type, il doit s'agir d'un type membre public et non ambigu désignant un type non référence, non qualifié cv, vers lequel T1 et T2 sont tous deux explicitement convertibles. De plus, ranges::common_type_t<T1, T2> et ranges::common_type_t<T2, T1> doivent désigner le même type.

Un programme qui ajoute des spécialisations common_type en violation de ces règles a un comportement indéfini.

Notes

Pour les types arithmétiques non soumis à promotion, le type commun peut être vu comme le type de l'expression arithmétique (éventuellement en mode mixte) telle que T0() + T1() + ... + Tn().
