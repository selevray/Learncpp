template< class T >
concept bool EqualityComparable = WeaklyEqualityComparableWith<T, T>;  // (1) (ranges TS)

template< class T, class U >
concept bool EqualityComparableWith =
    EqualityComparable<T> &&
    EqualityComparable<U> &&
    CommonReference<
        const std::remove_reference_t<T>&,
        const std::remove_reference_t<U>&> &&
    EqualityComparable<
        ranges::common_reference_t<
            const std::remove_reference_t<T>&,
            const std::remove_reference_t<U>&>> &&
    WeaklyEqualityComparableWith<T, U>;  // (2) (ranges TS)
  1. Le concept EqualityComparable<T> spécifie que les opérateurs de comparaison == et != sur T reflètent l'égalité : == donne true si et seulement si les opérandes sont égaux.

EqualityComparable<T> n'est satisfait que si, étant donnés des objets a et b de type T, bool(a == b) est true si et seulement si a et b sont égaux. Avec l'exigence que a == b préserve l'égalité, cela implique que == est symétrique et transitive, et en outre que == est réflexive pour tous les objets a égaux à au moins un autre objet.

  1. Le concept EqualityComparableWith<T, U> spécifie que les opérateurs de comparaison == et != sur des opérandes T et U (éventuellement de types mixtes) donnent des résultats cohérents avec l'égalité. La comparaison d'opérandes mixtes donne des résultats équivalents à la comparaison des opérandes convertis en leur type commun.

Formellement, EqualityComparableWith<T, U> n'est satisfait que si, étant données une lvalue quelconque t de type const std::remove_reference_t<T> et une lvalue quelconque u de type const std::remove_reference_t<U>, et en posant C égal à ranges::common_reference_t<const std::remove_reference_t<T>&, const std::remove_reference_t<U>&>, bool(t == u) == bool(C(t) == C(u)).

Préservation de l'égalité

Une expression est préservant l'égalité si elle produit des sorties égales pour des entrées égales.

  • Les entrées d'une expression sont constituées de ses opérandes.
  • Les sorties d'une expression sont constituées de son résultat et de tous les opérandes modifiés par l'expression (le cas échéant).

Toute expression devant préserver l'égalité doit en outre être stable : deux évaluations d'une telle expression avec les mêmes objets d'entrée doivent produire des sorties égales, en l'absence de toute modification explicite intermédiaire de ces objets d'entrée.

Variations implicites d'expressions

Une requires-expression qui utilise une expression non modifiante pour une lvalue constante en opérande exige aussi implicitement des variantes supplémentaires de cette expression acceptant une lvalue non constante ou une rvalue (éventuellement constante) pour l'opérande donné, à moins qu'une telle variante ne soit explicitement exigée avec une sémantique différente. Ces variations implicites d'expressions doivent respecter les mêmes exigences sémantiques que l'expression déclarée. La mesure dans laquelle une implémentation valide la syntaxe de ces variantes n'est pas spécifiée.
