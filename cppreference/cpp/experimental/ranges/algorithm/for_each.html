std::experimental::ranges::for_each

template< InputIterator I, Sentinel<I> S, class Proj = ranges::identity,
          IndirectUnaryInvocable<projected<I, Proj>> Fun >
ranges::tagged_pair<tag::in(I), tag::fun(Fun)>
    for_each( I first, S last, Fun f, Proj proj = Proj{} );  // (1) (ranges TS)

template< InputRange R, class Proj = ranges::identity,
          IndirectUnaryInvocable<projected<ranges::iterator_t<R>, Proj>> Fun >
ranges::tagged_pair<tag::in(ranges::safe_iterator_t<R>), tag::fun(Fun)>
    for_each( R&& r, Fun f, Proj proj = Proj{} );  // (2) (ranges TS)

  1. Invoque l'objet fonction f donné sur le résultat de l'invocation de la projection proj sur le déréférencement de chaque itérateur de l'intervalle [first,last) (c'est-à-dire ranges::invoke(f, ranges::invoke(proj, *i))), dans l'ordre.

  2. Identique à (1), mais utilise r comme intervalle source, comme si l'on utilisait ranges::begin(r) comme first et ranges::end(r) comme last.

Pour les deux surcharges, si le type d'itérateur est modifiable, f peut modifier les éléments de l'intervalle via l'itérateur déréférencé. Si f renvoie un résultat, celui-ci est ignoré.

Contrairement aux autres algorithmes, for_each n'est pas autorisé à copier les éléments de la séquence, même s'ils sont trivialement copiables.

Contrairement à std::for_each (qui n'exige que MoveConstructible), ces fonctions exigent que Fun modélise CopyConstructible.

Indépendamment des déclarations présentées ci-dessus, le nombre réel et l'ordre des paramètres de modèle des déclarations d'algorithmes sont non spécifiés. Ainsi, si des arguments de modèle explicites sont utilisés lors de l'appel d'un algorithme, le programme n'est probablement pas portable.

Paramètres

  • first, last — l'intervalle auquel appliquer la fonction
  • r — l'intervalle auquel appliquer la fonction
  • f — objet appelable à appliquer à chaque élément projeté de l'intervalle
  • proj — projection à appliquer aux éléments

Valeur de retour

Un objet tagged_pair contenant les deux membres suivants :

  • Le premier membre, portant l'étiquette tag::in, est l'itérateur past-the-end de l'intervalle source (c'est-à-dire un itérateur de type I qui compare égal à la sentinelle last).
  • Le second membre, portant l'étiquette tag::fun, est initialisé à partir de std::move(f) (après toutes les applications de l'objet fonction).

Complexité

Exactement last - first applications de f et proj.

Implémentation possible

template<InputIterator I, Sentinel<I> S, class Proj = ranges::identity,
         IndirectUnaryInvocable<ranges::projected<I, Proj>> Fun>
auto for_each(I first, S last, Fun f, Proj proj = Proj{})
    -> ranges::tagged_pair<tag::in(I), tag::fun(Fun)>
{
    for (; first != last; ++first)
        ranges::invoke(f, ranges::invoke(proj, *first));
    return {std::move(first), std::move(f)};
}
