template< RandomAccessIterator I, Sentinel<I> S,
          class Comp = ranges::less<>, class Proj = ranges::identity >
    requires Sortable<I, Comp, Proj>
I sort( I first, S last, Comp comp = Comp{}, Proj proj = Proj{} );  // (1) (ranges TS)

template< RandomAccessRange R,
          class Comp = ranges::less<>, class Proj = ranges::identity >
    requires Sortable<ranges::iterator_t<R>, Comp, Proj>
ranges::safe_iterator_t<R> sort( R&& r, Comp comp = Comp{}, Proj proj = Proj{} );  // (2) (ranges TS)

  1. Trie les éléments de l'intervalle [first,last) par ordre croissant. L'ordre des éléments égaux n'est pas garanti d'être conservé. Les éléments sont comparés à l'aide de comp après application de la projection proj.

  2. Trie les éléments de l'intervalle r, comme si par return ranges::sort(ranges::begin(r), ranges::end(r), comp, proj);.

Indépendamment des déclarations présentées ci-dessus, le nombre réel et l'ordre des paramètres de modèle des déclarations d'algorithmes sont non spécifiés. Ainsi, si des arguments de modèle explicites sont utilisés lors de l'appel d'un algorithme, le programme n'est probablement pas portable.

Paramètres

  • first, last — l'intervalle des éléments à trier
  • r — l'intervalle des éléments à trier
  • comp — le comparateur à utiliser
  • proj — la projection à appliquer aux éléments de l'intervalle

Valeur de retour

Un itérateur pointant après la fin de l'intervalle (c'est-à-dire qu'il se compare égal à last pour la surcharge (1), et à ranges::end(r) pour la surcharge (2)).

Complexité

O(N·log(N)) comparaisons, où N est égal au nombre d'éléments de l'intervalle.
