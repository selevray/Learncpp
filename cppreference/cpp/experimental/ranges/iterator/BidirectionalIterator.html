std::experimental::ranges::BidirectionalIterator

Défini dans l'en-tête <experimental/ranges/iterator>

template< class I >
concept bool BidirectionalIterator =
    ForwardIterator<I> &&
    DerivedFrom<ranges::iterator_category_t<I>, ranges::bidirectional_iterator_tag> &&
    requires(I i) {
        { --i } -> Same<I>&;
        { i-- } -> Same<I>&&;
    };  // (ranges TS)

Le concept BidirectionalIterator<I> affine ForwardIterator en ajoutant la capacité de déplacer un itérateur en arrière.

Un itérateur bidirectionnel r est dit décrémentable si et seulement s'il existe un s tel que ++s == r. Tous les itérateurs décrémentables r doivent appartenir au domaine des expressions --r et r--.

Soient a et b des objets décrémentables de type I. BidirectionalIterator<I> est satisfait uniquement si :

  • La pré-décrémentation produit une lvalue qui fait référence à l'opérande : std::addressof(--a) == std::addressof(a).
  • La post-décrémentation produit la valeur précédente de l'opérande : si bool(a == b), alors bool(a-- == b).
  • La post-décrémentation et la pré-décrémentation effectuent la même modification sur leur opérande : si bool(a == b), alors après évaluation de a-- et --b, bool(a == b) reste vrai.
  • L'incrémentation et la décrémentation sont inverses l'une de l'autre :
    • Si a est incrémentable et bool(a == b), alors bool(--(++a) == b).
    • Si bool(a == b), alors bool(++(--a) == b).

Préservation de l'égalité

Une expression est préservant l'égalité si elle produit des sorties égales pour des entrées égales.

  • Les entrées d'une expression sont constituées de ses opérandes.
  • Les sorties d'une expression sont constituées de son résultat et de tous les opérandes modifiés par l'expression (le cas échéant).

Toute expression devant préserver l'égalité doit en outre être stable : deux évaluations d'une telle expression avec les mêmes objets d'entrée doivent produire des sorties égales, en l'absence de toute modification explicite intermédiaire de ces objets d'entrée.

Sauf indication contraire, toute expression utilisée dans une requires-expression doit préserver l'égalité et être stable, et l'évaluation de l'expression ne peut modifier que ses opérandes non constants. Les opérandes constants ne doivent pas être modifiés.
