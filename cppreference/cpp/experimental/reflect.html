Extensions pour la réflexion

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les extensions C++ pour la réflexion, ISO/IEC TS 23619:2021, spécifient des modifications du langage de base et définissent de nouveaux composants pour la bibliothèque standard C++ listés sur cette page.

Le TS de réflexion est basé sur la norme C++20 (sauf que la définition des concepts est spécifiée dans le style du Concepts TS).

Modifications du langage de base

reflexpr-specifier

Un reflexpr-specifier a la forme reflexpr ( reflexpr-operand ) et désigne un type d'objet méta (voir ci-dessous).

reflexpr-operand peut être l'une des formes suivantes :

| | | | :: | (1) | | | | type-id | (2) | | | | nested-name-specifier(optionnel) namespace-name | (3) | | | | id-expression | (4) | | | | ( expression ) | (5) | | | | function-call-expression | (6) | | | | functional-type-conv-expression | (7) | | |

où function-call-expression est

| | | | postfix-expression ( expression-list(optionnel) ) | | | |

et functional-type-conv-expression sont les sortes d'expressions suivantes qui effectuent une conversion explicite :

| | | | simple-type-specifier ( expression-list(optionnel) ) | (1) | | | | typename-specifier ( expression-list(optionnel) ) | (2) | | | | simple-type-specifier braced-init-list | (3) | | | | typename-specifier braced-init-list | (4) | | |

L'opérande de reflexpr-specifier doit être un type, un espace de noms, un énumérateur, une variable, un membre de données, un paramètre de fonction, une entité capturée, function-call-expression ou functional-type-conv-expression, ou une expression entre parenthèses. reflexpr(::) représente l'espace de noms global.

Pour un reflexpr-operand de la forme ( expression ), le expression doit être un function-call-expression (éventuellement entre plusieurs parenthèses) ou functional-type-conv-expression.

Si un opérande non entre parenthèses peut être traité soit comme un type-id, soit comme un functional-type-conv-expression, il est traité comme un type-id. Les parenthèses peuvent servir à lever l'ambiguïté entre une conversion de style fonctionnel et un type-id. Par exemple, étant donné un type de classe X avec constructeur par défaut, reflexpr(X()) représente le type de fonction X(), et reflexpr((X())) représente l'expression X().

Si l'opérande désigne à la fois un alias et un nom de classe, le type représenté par le reflexpr-specifier reflète l'alias et satisfait reflect::Alias.

Si l'opérande désigne un nom dont la déclaration est contenue dans une portée de bloc et que l'entité nommée n'est ni capturée ni un paramètre de fonction, le programme est mal formé.

Types d'objets méta

Un type d'objet méta est un type de classe sans nom, incomplet, de portée d'espace de noms. Un type satisfait le concept reflect::Object si et seulement s'il est un type d'objet méta. Les types d'objets méta peuvent satisfaire d'autres concepts, selon l'opérande de reflexpr.

Il n'est pas spécifié si l'application répétée de reflexpr au même opérande donne le même type ou un type différent. Si un type d'objet méta reflète un type de classe incomplet, certaines transformations de type ne peuvent pas être appliquées.

Un type d'objet méta permet d'inspecter certaines propriétés de l'opérande de reflexpr au moyen de traits de type ou de transformations de type appliqués à celui-ci.

Résolution de surcharge

Si le postfix-expression de function-call-expression est de type classe, c'est-à-dire si e dans function-call-expression e(args) est de type classe, alors la fonction de conversion définie par l'utilisateur du type de postfix-expression (e) ne doit pas être utilisée.

Si postfix-expression n'est pas de type classe, il doit désigner une fonction qui est le résultat unique de la résolution de surcharge.

struct Functor
{
    void operator()(int) const;

    using fptr_t = void(*)(std::nullptr_t);
    operator fptr_t() const;
};

using Meta0 = reflexpr(Functor{}(0));          // OK
// using Meta1 = reflexpr(Functor{}(nullptr)); // erreur : fonction de conversion utilisée

Liées à la réflexion

Un alias est un nom introduit par une déclaration typedef, une déclaration d'alias, ou une déclaration using.

Une entité ou un alias B est lié par réflexion à une entité ou un alias A si

  1. A et B sont la même entité ou le même alias,
  2. A est une variable ou un énumérateur et B est le type de A,
  3. A est une énumération et B est le type sous-jacent de A,
  4. A est une classe et B est un membre ou une classe de base de A,
  5. A est un alias qui ne désigne pas un modèle et qui désigne l'entité B,
  6. A n'est pas l'espace de noms global et B est une classe ou un espace de noms englobant de A,
  7. A est l'expression entre parenthèses ( B ),
  8. A est une capture de lambda du type de fermeture B,
  9. A est le type de fermeture de la capture de lambda B,
  10. B est le type spécifié par le functional-type-conv-expression A,
  11. B est la fonction sélectionnée par la résolution de surcharge pour un function-call-expression A,
  12. B est le type de retour, un type de paramètre, ou le type de fonction de la fonction A, ou
  13. B est lié par réflexion à une entité ou un alias X et X est lié par réflexion à A.

La relation de liaison par réflexion est réflexive et transitive, mais non symétrique.

De façon informelle, le cas où B est lié par réflexion à A signifie que B participe à la déclaration ou à la définition de A.

Zéro ou plusieurs applications successives de transformations de type produisant des types d'objets méta, appliquées au type désigné par un reflexpr-specifier, permettent d'inspecter les entités et alias liés par réflexion à l'opérande ; un tel type d'objet méta est dit refléter l'entité ou l'alias lié par réflexion correspondant.

struct X;
struct B
{
    using X = ::X;
    typedef X Y;
};
struct D : B
{
    using B::Y;
};
// ::X, mais ni B::X ni B::Y ne sont liés par réflexion à D::Y

Divers

  • Une expression utilisée comme reflexpr-operand est une expression non évaluée et potentiellement évaluée à la compilation.
  • Pour la détermination des variables capturées dans une expression lambda par un capture-default, un opérande reflexpr n'est pas considéré comme un opérande non évalué.
  • Une fonction ou variable de durée de stockage statique reflétée par le type d'objet méta T est utilisée au sens ODR par la spécialisation std::experimental::reflect::get_pointer<T>, comme si l'on prenait l'adresse d'une id-expression désignant la fonction ou la variable.
  • Il peut y avoir plus d'une définition d'un type d'objet méta, tant que toutes les opérations sur ce type donnent les mêmes résultats d'expressions constantes.
  • Un type est dépendant s'il est désigné par un reflexpr-specifier et que l'opérande
    • est une expression dépendante du type ou une expression entre parenthèses (éventuellement) functional-type-conv-expression ayant au moins une sous-expression immédiate dépendante du type, ou
    • désigne un type dépendant ou un membre d'une spécialisation inconnue ou une expression constante dépendante de la valeur.
