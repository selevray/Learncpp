Compare atomiquement le shared_ptr sous-jacent dans *this avec expected et, s'ils sont équivalents, remplace le premier par desired (effectue une opération de lecture-modification-écriture). Sinon, charge la valeur réelle stockée dans *this dans expected (effectue une opération de chargement). Le remplacement est effectué comme par l'opérateur d'affectation par copie ou par déplacement de shared_ptr, selon le cas.

Deux shared_ptr sont équivalents si et seulement s'ils stockent la même valeur de pointeur et partagent la propriété.

Les modèles de mémoire des opérations de lecture-modification-écriture et de chargement sont success et failure respectivement. Pour les surcharges (3,4,7,8), order est utilisé pour les opérations de lecture-modification-écriture et de chargement, sauf que std::memory_order_acquire et std::memory_order_relaxed sont utilisés pour l'opération de chargement si order == std::memory_order_acq_rel, ou order == std::memory_order_release respectivement.

Les versions faibles (1-4) peuvent échouer de façon parasite.

Paramètres

  • expected — référence vers la valeur attendue dans l'objet atomique
  • desired — la valeur à stocker dans l'objet atomique si elle est celle attendue
  • success — l'ordonnancement de synchronisation mémoire pour l'opération de lecture-modification-écriture si la comparaison réussit. Toutes les valeurs sont permises
  • failure — l'ordonnancement de synchronisation mémoire pour l'opération de chargement si la comparaison échoue. Ne peut pas être std::memory_order_release ni std::memory_order_acq_rel et ne peut pas spécifier un ordonnancement plus fort que success
  • order — l'ordre de synchronisation mémoire pour les deux opérations

Valeur de retour

true si la valeur atomique sous-jacente a été modifiée, false sinon.

Remarques

Toutes les modifications de l'objet atomic_shared_ptr lui-même, et tous les incréments use_count associés, sont garantis d'être effectués de manière atomique. Les décréments use_count associés ont lieu après l'opération atomique, mais ne sont pas tenus d'en faire partie. Toutes les opérations de destruction ou de désallocation associées ont lieu après l'opération atomique et n'en font pas partie.

Si l'opération de comparaison-échange renvoie true, expected n'est pas accédé après l'étape de mise à jour atomique. Si elle renvoie false, expected est mis à jour avec la valeur existante lue depuis l'objet atomic_shared_ptr lors de la tentative de mise à jour atomique. L'incrément use_count correspondant à l'écriture dans expected fait partie de l'opération atomique, mais l'écriture dans expected elle-même n'est pas tenue d'en faire partie.

Pour les surcharges (1,3,5,7), desired n'est pas accédé après l'étape de mise à jour atomique.

Pour les surcharges (2,4,6,8), desired n'est déplacé que si l'opération de comparaison-échange renvoie true ; le déplacement a lieu après l'étape de mise à jour atomique.

Notes

Les formes faibles (1-4) des fonctions peuvent échouer de façon parasite, c'est-à-dire agir comme si *this et expected n'étaient pas équivalents même lorsqu'ils le sont. Lorsqu'une comparaison-échange se trouve dans une boucle, la version faible offre de meilleures performances sur certaines plates-formes.
