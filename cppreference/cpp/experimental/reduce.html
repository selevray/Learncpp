  1. Identique à reduce(first, last, typename std::iterator_traits<InputIt>::value_type{}).

  2. Identique à reduce(first, last, init, std::plus<>()).

  3. Réduit l'intervalle [first,last), éventuellement permuté et agrégé de manière non spécifiée, avec la valeur initiale init sur binary_op.

2,4,6) Identique à (1,3,5), mais exécuté selon policy.

Le comportement est non déterministe si binary_op n'est pas associatif ou n'est pas commutatif.

Le comportement est indéfini si binary_op modifie un élément ou invalide un itérateur dans [first,last).

Paramètres

  • first, last — l'intervalle d'éléments auquel appliquer l'algorithme
  • init — la valeur initiale de la somme généralisée
  • policy — la politique d'exécution
  • binary_op — opération binaire FunctionObject qui sera appliquée dans un ordre non spécifié au résultat de la déréférenciation des itérateurs d'entrée, aux résultats des autres binary_op et init

Exigences sur les types

  • InputIt doit satisfaire aux exigences de LegacyInputIterator.

Valeur de retour

Somme généralisée de init et *first, *(first + 1), ... *(last - 1) sur binary_op,

où la somme généralisée GSUM(op, a1, ..., aN) est définie comme suit :

  • if N=1, a1
  • si N > 1, op(GSUM(op, b1, ..., bK), GSUM(op, bM, ..., bN)) où
    • b1, ..., bN peut être n'importe quelle permutation de a1, ..., aN et
    • 1 < K+1 = M ≤ N

en d'autres termes, les éléments de l'intervalle peuvent être regroupés et réarrangés dans un ordre arbitraire.

Complexité

O(last - first) applications de binary_op.

Exceptions

  • Si l'exécution d'une fonction invoquée dans le cadre de l'algorithme lève une exception,

    • si policy est parallel_vector_execution_policy, std::terminate est appelée.
    • si policy est sequential_execution_policy ou parallel_execution_policy, l'algorithme se termine en levant un exception_list contenant toutes les exceptions non interceptées. S'il n'y a eu qu'une seule exception non interceptée, l'algorithme peut la relancer sans l'envelopper dans exception_list. Le travail que l'algorithme effectuera avant de revenir après la première exception rencontrée n'est pas spécifié.
    • si policy est un autre type, le comportement est défini par l'implémentation.

  • Si l'algorithme ne parvient pas à allouer de la mémoire (pour lui-même ou pour construire un exception_list lors du traitement d'une exception utilisateur), std::bad_alloc est levée.

Notes

Si l'intervalle est vide, init est renvoyé, sans modification.

  • Si policy est une instance de sequential_execution_policy, toutes les opérations sont effectuées dans le thread appelant.
  • Si policy est une instance de parallel_execution_policy, les opérations peuvent être effectuées dans un nombre non spécifié de threads, séquencées de manière indéterminée les unes par rapport aux autres.
  • Si policy est une instance de parallel_vector_execution_policy, l'exécution peut être à la fois parallélisée et vectorisée : les frontières du corps de fonction ne sont pas respectées et le code utilisateur peut être recouvert et combiné de manière arbitraire (en particulier, cela implique qu'un Callable fourni par l'utilisateur ne doit pas acquérir un mutex pour accéder à une ressource partagée).

Exemple

reduce est la version à ordre non garanti de std::accumulate :

#include <chrono>
#include <experimental/execution_policy>
#include <experimental/numeric>
#include <iostream>
#include <numeric>
#include <vector>

int main()
{
    std::vector<double> v(10'000'007, 0.5);

    {
        auto t1 = std::chrono::high_resolution_clock::now();
        double result = std::accumulate(v.begin(), v.end(), 0.0);
        auto t2 = std::chrono::high_resolution_clock::now();
        std::chrono::duration<double, std::milli> ms = t2 - t1;
        std::cout << std::fixed << "std::accumulate result " << result
                  << " took " << ms.count() << " ms\n";
    }

    {
        auto t1 = std::chrono::high_resolution_clock::now();
        double result = std::experimental::parallel::reduce(
                            std::experimental::parallel::par,
                            v.begin(), v.end());
        auto t2 = std::chrono::high_resolution_clock::now();
        std::chrono::duration<double, std::milli> ms = t2 - t1;
        std::cout << "parallel::reduce result "
                  << result << " took " << ms.count() << " ms\n";
    }
}

Sortie possible :

std::accumulate result 5000003.50000 took 12.7365 ms
parallel::reduce result 5000003.50000 took 5.06423 ms
