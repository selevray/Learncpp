std::experimental::filesystem::copy_file

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <experimental/filesystem>

bool copy_file( const path& from, const path& to );
bool copy_file( const path& from, const path& to, error_code& ec );  // (1) (TS sur le système de fichiers)

bool copy_file( const path& from, const path& to, copy_options options );
bool copy_file( const path& from, const path& to, copy_options options, error_code& ec );  // (2) (TS sur le système de fichiers)

  1. Le comportement par défaut, équivalent à (2) avec copy_options::none utilisé comme options.

  2. Copie un seul fichier de from vers to, en utilisant les options de copie indiquées par options. Le comportement est indéfini s'il y a plus d'une option dans l'un quelconque des groupes d'options copy_options présents dans options (même dans les groupes non pertinents pour copy_file).

  • Si le fichier de destination n'existe pas,

    • copie le contenu et les attributs du fichier vers lequel from se résout vers le fichier vers lequel to se résout (les liens symboliques sont suivis).

  • Sinon, si le fichier de destination existe déjà :

    • Si to et from sont identiques tel que déterminé par equivalent(from, to), signale une erreur.
    • Sinon, si aucune des options de contrôle copy_file n'est positionnée dans options, signale une erreur.
    • Sinon, si copy_options::skip_existing est positionnée dans options, ne fait rien.
    • Sinon, si copy_options::overwrite_existing est positionnée dans options, copie le contenu et les attributs du fichier vers lequel from se résout vers le fichier vers lequel to se résout.
    • Sinon, si copy_options::update_existing est positionnée dans options, copie le fichier seulement si from est plus récent que to, tel que défini par last_write_time().

Les surcharges non lançantes renvoient false si une erreur survient.

Paramètres

  • from — chemin vers le fichier source
  • to — chemin vers le fichier cible
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

true si le fichier a été copié, false sinon.

Exceptions

La surcharge qui ne prend pas de paramètre error_code& lève filesystem_error en cas d'erreurs de l'API du système d'exploitation sous-jacente, construite avec from comme premier argument, to comme second argument, et le code d'erreur du système d'exploitation comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le fixe au code d'erreur de l'API du système d'exploitation si un appel à cette API échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Notes

Les fonctions effectuent au plus un appel direct ou indirect à status(to) (utilisé à la fois pour déterminer si le fichier existe et, pour l'option copy_options::update_existing, sa date de dernière écriture).

Une erreur est signalée lorsque copy_file est utilisée pour copier un répertoire : utilisez copy pour cela.

copy_file suit les liens symboliques : utilisez copy_symlink ou copy avec copy_options::copy_symlinks pour cela.

Exemple

#include <experimental/filesystem>
#include <fstream>
#include <iostream>
namespace fs = std::experimental::filesystem;

int main()
{
    fs::create_directory("sandbox");
    std::ofstream("sandbox/file1.txt").put('a');

    fs::copy_file("sandbox/file1.txt", "sandbox/file2.txt");

    // il y a maintenant deux fichiers dans sandbox :
    std::cout << "file1.txt holds : "
              << std::ifstream("sandbox/file1.txt").rdbuf() << '\n';
    std::cout << "file2.txt holds : "
              << std::ifstream("sandbox/file2.txt").rdbuf() << '\n';

    // échec de la copie du répertoire
    fs::create_directory("sandbox/abc");
    try
    {
        fs::copy_file("sandbox/abc", "sandbox/def");
    }
    catch (fs::filesystem_error& e)
    {
        std::cout << "Could not copy sandbox/abc: " << e.what() << '\n';
    }
    fs::remove_all("sandbox");
}

Sortie possible :

file1.txt holds : a
file2.txt holds : a
Could not copy sandbox/abc: copy_file: Is a directory: "sandbox/abc", "sandbox/def"
