std::experimental::filesystem::create_symlink, std::experimental::filesystem::create_directory_symlink

void create_symlink( const path& target, const path& link );

Crée un lien symbolique link dont la cible est target, comme avec POSIX symlink() : le chemin target peut être invalide ou inexistant.

Certains systèmes d'exploitation exigent d'indiquer lors de la création du lien qu'il pointe vers un répertoire. Le code portable doit utiliser (2) pour créer des liens symboliques vers des répertoires plutôt que (1), bien qu'il n'y ait aucune distinction sur les systèmes POSIX.

Paramètres

  • target — chemin vers lequel pointe le lien symbolique, n'a pas besoin d'exister
  • link — chemin du nouveau lien symbolique
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

(aucune)

Exceptions

La surcharge qui ne prend pas de paramètre error_code& lève filesystem_error en cas d'erreurs de l'API du système d'exploitation sous-jacente, construite avec target comme premier argument, link comme second argument, et le code d'erreur du système d'exploitation comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le fixe au code d'erreur de l'API du système d'exploitation si un appel à cette API échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Notes

Certains systèmes d'exploitation ne prennent pas en charge les liens symboliques, ou ne les prennent en charge que pour les fichiers réguliers.

Certains systèmes de fichiers ne prennent pas en charge les liens symboliques, quel que soit le système d'exploitation, par exemple le système FAT utilisé sur certaines cartes mémoire et clés USB.

Comme un lien physique, un lien symbolique permet à un fichier d'avoir plusieurs noms logiques. La présence d'un lien physique garantit l'existence d'un fichier, même après la suppression du nom d'origine. Un lien symbolique n'offre aucune garantie de ce type; en fait, le fichier désigné par l'argument target n'a pas besoin d'exister au moment de la création du lien. Un lien symbolique peut franchir les frontières des systèmes de fichiers.

Exemple

#include <experimental/filesystem>
#include <iostream>
namespace fs = std::experimental::filesystem;

int main()
{
    fs::create_directories("sandbox/subdir");
    fs::create_symlink("target", "sandbox/sym1");
    fs::create_directory_symlink("subdir", "sandbox/sym2");

    for (auto it = fs::directory_iterator("sandbox"); it != fs::directory_iterator(); ++it)
        if (is_symlink(it->symlink_status()))
            std::cout << *it << "->" << read_symlink(*it) << '\n';

    fs::remove_all("sandbox");
}

Sortie possible :

"sandbox/sym1"->"target"
"sandbox/sym2"->"subdir"
