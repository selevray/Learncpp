Les objets de type path représentent des chemins sur un système de fichiers. Seuls les aspects syntaxiques des chemins sont traités : le nom de chemin peut représenter un chemin inexistant, voire un chemin qui n'est pas autorisé à exister sur le système de fichiers ou le système d'exploitation actuel.

La syntaxe du nom de chemin est la suivante :

  1. root-name(facultatif) : identifie la racine sur un système de fichiers possédant plusieurs racines (comme "C:" ou "//myserver". Les systèmes de fichiers POSIX n'ont qu'une seule racine.
  2. root-directory(facultatif) : un séparateur de répertoire qui, s'il est présent, marque ce chemin comme absolu. S'il est absent (et que le premier élément autre que le nom de racine est un nom de fichier), alors le chemin est relatif et nécessite un autre chemin comme emplacement de départ pour être résolu en nom de fichier.
  3. Zéro ou plusieurs des éléments suivants :
    • file-name : suite de caractères qui ne sont ni des séparateurs de répertoire ni des séparateurs de répertoire préférés (le système d'exploitation ou le système de fichiers peut imposer des limitations supplémentaires). Ce nom peut désigner un fichier, un lien physique, un lien symbolique ou un répertoire. Deux file-name particuliers sont reconnus :
      • dot : le nom de fichier constitué d'un seul caractère point . est un nom de répertoire qui désigne le répertoire courant.
      • dot-dot : le nom de fichier constitué de deux caractères point .. est un nom de répertoire qui désigne le répertoire parent.
    • directory-separator : le caractère barre oblique / ou le caractère alternatif fourni sous la forme path::preferred_separator. Si ce caractère est répété, il est traité comme un seul séparateur de répertoire : /usr///////lib est identique à /usr/lib.

On peut parcourir le chemin élément par élément à l'aide des itérateurs renvoyés par les fonctions begin() et end(), qui parcourent le nom de racine, le répertoire racine et les éléments de nom de fichier suivants (les séparateurs de répertoire sont ignorés, sauf celui qui identifie le répertoire racine). Si le tout dernier élément du chemin est un séparateur de répertoire, le dernier itérateur déréférencé donnera un nom de fichier dot.

Appeler une fonction membre non constante de path invalide tous les itérateurs faisant référence aux éléments de cet objet.

Si le système d'exploitation utilise une syntaxe native différente de la syntaxe générique portable décrite ci-dessus, toutes les fonctions de la bibliothèque acceptent les noms de chemin dans les deux formats.

Les chemins sont implicitement convertibles vers et depuis des std::basic_string, ce qui permet de les utiliser avec d'autres API de fichiers, par exemple comme argument de std::ifstream::open.
