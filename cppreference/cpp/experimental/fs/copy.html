std::experimental::filesystem::copy

Copie des fichiers et des répertoires, avec diverses options :

  1. Le comportement par défaut, équivalent à (2) avec copy_options::none utilisé comme options.

  2. Copie le fichier ou le répertoire from vers le fichier ou le répertoire to, en utilisant les options de copie indiquées par options. Le comportement est indéfini s'il y a plus d'une option dans l'un quelconque des groupes d'options copy_options présents dans options (même dans le groupe copy_file, qui n'est pas pertinent pour copy).

Le comportement est le suivant :

  • Tout d'abord, avant toute autre action, obtient le type et les permissions de from par au plus un seul appel à status (ou, si copy_options::skip_symlinks ou copy_options::create_symlinks sont présents dans options, par un appel à symlink_status).

  • Si nécessaire, obtient de la même façon l'état de to, par au plus un seul appel à status ou symlink_status.

  • Si from n'existe pas, signale une erreur.

  • Si from et to sont le même fichier tel que déterminé par equivalent(), signale une erreur.

  • Si from ou to n'est ni un fichier ordinaire, ni un répertoire, ni un lien symbolique, tel que déterminé par is_other, signale une erreur.

  • Si from est un répertoire, mais que to est un fichier ordinaire, signale une erreur.

  • Si from est un lien symbolique, alors

    • Si copy_options::skip_symlink est présent dans options, ne fait rien.
    • Sinon, si to n'existe pas et que copy_options::copy_symlinks est présent dans options, alors se comporte comme si copy_symlink(from, to).
    • Sinon, signale une erreur.

  • Sinon, si from est un fichier ordinaire, alors

    • Si copy_options::directories_only est présent dans options, ne fait rien.
    • Sinon, si copy_options::create_symlinks est présent dans options, crée un lien symbolique vers to. Remarque : from doit être un chemin absolu, sauf si to se trouve dans le répertoire courant.
    • Sinon, si copy_options::create_hard_links est présent dans options, crée un lien physique vers to.
    • Sinon, si to est un répertoire, alors se comporte comme si copy_file(from, to/from.filename(), options) (crée une copie de from sous forme de fichier dans le répertoire to).
    • Sinon, se comporte comme si copy_file(from, to, options) (copie le fichier).

  • Sinon, si from est un répertoire et que options possède copy_options::recursive ou est copy_options::none.

    • Si to n'existe pas, exécute d'abord create_directory(to, from) (crée le nouveau répertoire avec une copie des attributs de l'ancien répertoire).
    • Ensuite, que to existait déjà ou vient d'être créé, itère sur les fichiers contenus dans from comme si par for (const directory_entry& x : directory_iterator(from)) et, pour chaque entrée de répertoire, appelle récursivement copy(x.path(), to/x.path().filename(), options | unspecified), où unspecified est un bit spécial qui n'a aucun autre effet lorsqu'il est positionné dans options (le seul but de ce bit est d'empêcher la copie récursive des sous-répertoires si options est copy_options::none).

  • Sinon, ne fait rien.

Paramètres

  • from — chemin vers le fichier, répertoire ou lien symbolique source
  • to — chemin vers le fichier, répertoire ou lien symbolique cible
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

(aucune)

Exceptions

La surcharge qui ne prend pas de paramètre error_code& lève filesystem_error en cas d'erreurs de l'API du système d'exploitation sous-jacente, construite avec from comme premier argument, to comme second argument, et le code d'erreur du système d'exploitation comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le fixe au code d'erreur de l'API du système d'exploitation si un appel à cette API échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Notes

Le comportement par défaut lors de la copie de répertoires est la copie non récursive : les fichiers sont copiés, mais pas les sous-répertoires :

// Soient
// /dir1 contient /dir1/file1, /dir1/file2, /dir1/dir2
// et /dir1/dir2 contient /dir1/dir2/file3
// Après
std::experimental::filesystem::copy("/dir1", "/dir3");
// /dir3 est créé (avec les attributs de /dir1)
// /dir1/file1 est copié vers /dir3/file1
// /dir1/file2 est copié vers /dir3/file2

Alors qu'avec copy_options::recursive, les sous-répertoires sont également copiés, avec leur contenu, de manière récursive.

// ...mais ensuite
std::experimental::filesystem::copy("/dir1", "/dir3", copy_options::recursive);
// /dir3 est créé (avec les attributs de /dir1)
// /dir1/file1 est copié vers /dir3/file1
// /dir1/file2 est copié vers /dir3/file2
// /dir3/dir2 est créé (avec les attributs de /dir1/dir2)
// /dir1/dir2/file3 est copié vers /dir3/dir2/file3

Exemple

#include <experimental/filesystem>
#include <fstream>
#include <iostream>
namespace fs = std::experimental::filesystem;

int main()
{
    fs::create_directories("sandbox/dir/subdir");
    std::ofstream("sandbox/file1.txt").put('a');
    fs::copy("sandbox/file1.txt", "sandbox/file2.txt"); // copie de fichier
    fs::copy("sandbox/dir", "sandbox/dir2"); // copie de répertoire (non récursive)
    // sandbox contient 2 fichiers et 2 répertoires, dont l'un possède un sous-répertoire
    // sandbox/file1.txt
    // sandbox/file2.txt
    // sandbox/dir2
    // sandbox/dir
    //    sandbox/dir/subdir
    fs::copy("sandbox", "sandbox/copy", fs::copy_options::recursive);
    // sandbox/copy contient des copies des fichiers et sous-répertoires ci-dessus
    fs::remove_all("sandbox");
}
