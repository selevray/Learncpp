  1. Détermine le type et les attributs de l'objet du système de fichiers identifié par p comme le fait POSIX stat (les liens symboliques sont suivis jusqu'à leur cible).
  • Si p est un fichier régulier, renvoie file_status(file_type::regular).
  • Si p est un répertoire, renvoie file_status(file_type::directory).
  • Si p est un fichier spécial de type bloc, renvoie file_status(file_type::block).
  • Si p est un fichier spécial de type caractère, renvoie file_status(file_type::character).
  • Si p est un fichier fifo ou un tube, renvoie file_status(file_type::fifo).
  • Si p est une socket, renvoie file_status(file_type::socket).
  • Si p n'existe pas, renvoie file_status(file_type::not_found).
  • Si p existe mais que ses attributs de fichier ne peuvent pas être déterminés, par exemple faute de permissions, renvoie file_status(file_type::unknown).
  • Si des erreurs empêchent même de savoir si p existe, la surcharge non lançante définit ec et renvoie file_status(file_type::none), et la surcharge lançante lève filesystem_error.
  • Sinon, renvoie file_status(file_type::unknown).
  1. Identique à (1), sauf que le comportement est celui de POSIX lstat (les liens symboliques ne sont pas suivis) :
  • Si p est un lien symbolique, renvoie file_status(file_type::symlink).

Paramètres

  • p — chemin à examiner
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

L'état du fichier (un objet file_status).

Exceptions

La surcharge qui ne prend pas de paramètre error_code& lève filesystem_error en cas d'erreur de l'API du système d'exploitation sous-jacente, construite avec p comme premier argument et le code d'erreur du système d'exploitation comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le positionne au code d'erreur de l'API du système d'exploitation si un appel échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Notes

Les informations fournies par cette fonction sont généralement aussi fournies comme sous-produit de l'itération sur un répertoire, et peuvent être obtenues par les fonctions membres de directory_entry. Pendant l'itération sur un répertoire, appeler status à nouveau est inutile.

Exemple

#include <cstdio>
#include <cstring>
#include <experimental/filesystem>
#include <fstream>
#include <iostream>
#include <sys/socket.h>
#include <sys/stat.h>
#include <sys/un.h>
#include <unistd.h>

namespace fs = std::experimental::filesystem;

void demo_status(const fs::path& p, fs::file_status s)
{
    std::cout << p;
    // alternative : switch(s.type()) { case fs::file_type::regular: ... }
    if (fs::is_regular_file(s))
        std::cout << " is a regular file\n";
    if (fs::is_directory(s))
        std::cout << " is a directory\n";
    if (fs::is_block_file(s))
        std::cout << " is a block device\n";
    if (fs::is_character_file(s))
        std::cout << " is a character device\n";
    if (fs::is_fifo(s))
        std::cout << " is a named IPC pipe\n";
    if (fs::is_socket(s))
        std::cout << " is a named IPC socket\n";
    if (fs::is_symlink(s))
        std::cout << " is a symlink\n";
    if (!fs::exists(s))
        std::cout << " does not exist\n";
}

int main()
{
    // créer des fichiers de différents types
    fs::create_directory("sandbox");
    std::ofstream("sandbox/file"); // créer un fichier régulier
    fs::create_directory("sandbox/dir");
    mkfifo("sandbox/pipe", 0644);
    struct sockaddr_un addr;
    addr.sun_family = AF_UNIX;
    std::strcpy(addr.sun_path, "sandbox/sock");
    int fd = socket(PF_UNIX, SOCK_STREAM, 0);
    bind(fd, (struct sockaddr*)&addr, sizeof addr);
    fs::create_symlink("file", "sandbox/symlink");

    // démonstration des différents accesseurs de statut
    for (auto it = fs::directory_iterator("sandbox"); it != fs::directory_iterator(); ++it)
        demo_status(*it, it->symlink_status()); // utiliser le statut mis en cache de l'entrée de répertoire
    demo_status("dev/null", fs::status("/dev/null")); // appels directs à status
    demo_status("dev/sda", fs::status("/dev/sda"));
    demo_status("sandbox/no", fs::status("/sandbox/no"));

    // cleanup
    close(fd);
    fs::remove_all("sandbox");
}

"sandbox/dir" is a directory
"sandbox/pipe" is a named IPC pipe
"sandbox/sock" is a named IPC socket
"sandbox/symlink" is a symlink
"dev/null" is a character device
"dev/sda" is a block device
"sandbox/no" does not exist
