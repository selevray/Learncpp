std::experimental::filesystem::remove, std::experimental::filesystem::remove_all

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <experimental/filesystem>

bool remove( const path& p );
bool remove( const path& p, error_code& ec );  // (1) (TS sur le système de fichiers)

std::uintmax_t remove_all( const path& p );
std::uintmax_t remove_all( const path& p, error_code& ec );  // (2) (TS sur le système de fichiers)

  1. Le fichier ou le répertoire vide identifié par le chemin p est supprimé comme par le remove POSIX. Les liens symboliques ne sont pas suivis (le lien symbolique est supprimé, pas sa cible).

  2. Supprime le contenu de p (s'il s'agit d'un répertoire) et le contenu de tous ses sous-répertoires, récursivement, puis supprime p lui-même comme en appliquant répétitivement le remove POSIX. Les liens symboliques ne sont pas suivis (le lien symbolique est supprimé, pas sa cible).

Paramètres

  • p — chemin à supprimer
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

  1. true si le fichier a été supprimé, false s'il n'existait pas. La surcharge qui prend l'argument error_code& renvoie false en cas d'erreur.

  2. Renvoie le nombre de fichiers et de répertoires supprimés (qui peut être zéro si p n'existait pas à l'origine). La surcharge qui prend l'argument error_code& renvoie static_cast<std::uintmax_t>(-1) en cas d'erreur.

Exceptions

La surcharge qui ne prend pas de paramètre error_code& lève filesystem_error en cas d'erreur de l'API du système d'exploitation sous-jacente, construite avec p comme premier argument et le code d'erreur du système d'exploitation comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le positionne au code d'erreur de l'API du système d'exploitation si un appel échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Notes

Sur les systèmes POSIX, cette fonction appelle généralement unlink et rmdir si nécessaire, sous Windows RemoveDirectoryW et DeleteFileW.

Exemple

#include <cstdint>
#include <experimental/filesystem>
#include <iostream>
namespace fs = std::experimental::filesystem;

int main()
{
    fs::path dir = fs::temp_directory_path();
    fs::create_directories(dir / "abcdef/example");
    std::uintmax_t n = fs::remove_all(dir / "abcdef");
    std::cout << "Deleted " << n << " files or directories\n";
}
