std::experimental::filesystem::file_size

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <experimental/filesystem>

std::uintmax_t file_size( const path& p );
std::uintmax_t file_size( const path& p, error_code& ec );  // (1) (TS sur le système de fichiers)

Renvoie la taille du fichier ordinaire p, déterminée comme si elle était obtenue en lisant le membre st_size de la structure obtenue par POSIX stat (les liens symboliques sont suivis).

Tenter de déterminer la taille d'un répertoire (ainsi que de tout autre fichier qui n'est ni un fichier ordinaire ni un lien symbolique) est traité comme une erreur.

La surcharge ne lançant pas d'exception renvoie -1 en cas d'erreur.

Paramètres

  • p — chemin à examiner
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

La taille du fichier, en octets.

Exceptions

La surcharge qui ne prend pas de paramètre error_code& lève filesystem_error en cas d'erreur de l'API du système d'exploitation sous-jacente, construite avec p comme premier argument et le code d'erreur du système d'exploitation comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le positionne au code d'erreur de l'API du système d'exploitation si un appel échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Exemple

#include <experimental/filesystem>
#include <fstream>
#include <iostream>
namespace fs = std::experimental::filesystem;

int main()
{
    fs::path p = fs::current_path() / "example.bin";
    std::ofstream(p).put('a'); // créer un fichier de taille 1
    std::cout << "File size = " << fs::file_size(p) << '\n';
    fs::remove(p);

    try
    {
        fs::file_size("/dev"); // tenter d'obtenir la taille d'un répertoire
    }
    catch (fs::filesystem_error& e)
    {
        std::cout << e.what() << '\n';
    }
}
