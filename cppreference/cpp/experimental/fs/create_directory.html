std::experimental::filesystem::create_directory, std::experimental::filesystem::create_directories

bool create_directory( const path& p );

bool create_directory( const path& p, const path& existing_p );
bool create_directory( const path& p, const path& existing_p, error_code& ec );  // (2) (TS sur le système de fichiers)

bool create_directories( const path& p );
bool create_directories( const path& p, error_code& ec );  // (3) (TS sur le système de fichiers)

  1. Crée le répertoire p comme avec POSIX mkdir() avec un second argument valant static_cast<int>(fs::perms::all) (le répertoire parent doit déjà exister). Si p existe déjà et est déjà un répertoire, la fonction ne fait rien (cette condition n'est pas traitée comme une erreur).

  2. Identique à (1), sauf que les attributs du nouveau répertoire sont copiés depuis existing_p (qui doit être un répertoire existant). Les attributs copiés dépendent du système : sur les systèmes POSIX, les attributs sont copiés comme avec

stat(existing_p.c_str(), &attributes_stat)
mkdir(p.c_str(), attributes_stat.st_mode)

Sous Windows, les attributs sont copiés comme avec

CreateDirectoryExW(existing_p.c_str(), p.c_str(), 0)
  1. Exécute (1) pour chaque élément de p qui n'existe pas encore.

Les surcharges sans exception renvoient false si une erreur survient.

Paramètres

  • p — le chemin du nouveau répertoire à créer
  • existing_p — le chemin d'un répertoire dont copier les attributs
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

1,2) true si la création du répertoire réussit, false sinon.

Exceptions

1,3) La surcharge sans paramètre error_code& lève filesystem_error en cas d'erreur de l'API du système sous-jacent, construite avec p comme premier argument et le code d'erreur du système comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le définit au code d'erreur de l'API du système si un appel à l'API échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

  1. La surcharge sans paramètre error_code& lève filesystem_error en cas d'erreur de l'API du système sous-jacent, construite avec p comme premier argument, existing_p comme deuxième argument et le code d'erreur du système comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le définit au code d'erreur de l'API du système si un appel à l'API échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Notes

La surcharge (2) préservant les attributs est appelée implicitement par copy() lors de la copie récursive de répertoires. Son équivalent dans boost.filesystem est copy_directory (avec l'ordre des arguments inversé).

Exemple

#include <cstdlib>
#include <experimental/filesystem>
#include <fstream>
#include <iostream>
namespace fs = std::experimental::filesystem;

int main()
{
    fs::create_directories("sandbox/1/2/a");
    fs::create_directory("sandbox/1/2/b");
    fs::permissions("sandbox/1/2/b", fs::perms::remove_perms | fs::perms::others_all);
    fs::create_directory("sandbox/1/2/c", "sandbox/1/2/b");
    std::system("ls -l sandbox/1/2");
    fs::remove_all("sandbox");
}
