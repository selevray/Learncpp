std::experimental::filesystem::absolute, std::experimental::filesystem::system_complete

Défini dans l'en-tête <experimental/filesystem>

path absolute( const path& p, const path& base = current_path() );  // (1) (TS sur le système de fichiers)

path system_complete( const path& p );
path system_complete( const path& p, error_code& ec );  // (2) (TS sur le système de fichiers)
  1. Renvoie le chemin absolu de p relativement à base selon les règles suivantes :
  • Si p possède à la fois un nom de racine et un répertoire racine (par exemple "C:\users"), le chemin est renvoyé sans modification.
  • Si p possède un nom de racine non suivi d'un répertoire racine (par exemple "C:text.txt"), alors base est inséré entre le nom de racine de p et le reste de p. Formellement, p.root_name() / fs::absolute(base).root_directory() / fs::absolute(base).relative_path() / p.relative_path() est renvoyé,
  • Si p ne possède pas de nom de racine, mais possède un répertoire racine (par exemple "/var/tmp/file.txt" sur un système POSIX ou "\users\ABC\Document.doc" sous Windows), alors le nom de racine de base, s'il en possède un, est placé devant p (sur un système POSIX, p n'est pas modifié ; sous Windows, "\users\ABC\Document.doc" devient "C:\users\ABC\Document.doc"). Formellement, fs::absolute(base).root_name() / p est renvoyé.
  • Si p ne possède ni nom de racine ni répertoire racine (par exemple "../file.txt"), alors l'intégralité de base est placée devant p. Formellement, absolute(base) / p est renvoyé.
  1. Obtient le chemin absolu identifiant le fichier auquel l'API d'ouverture de fichiers du système d'exploitation accéderait pour le nom de chemin p. Sur les systèmes POSIX, cela équivaut à (1) avec le base par défaut (fs::current_path()). Sous Windows, chaque lecteur logique possède son propre répertoire de travail courant ; ainsi, si p n'est pas déjà absolu et possède un composant de nom de racine (par exemple "E:filename.txt"), c'est le répertoire de travail courant de ce lecteur qui est utilisé, lequel a pu être défini par un programme exécuté précédemment.

Paramètres

  • p — chemin à convertir en forme absolue
  • base — chemin (pas nécessairement absolu) servant de point de départ
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

Renvoie un chemin absolu (mais pas nécessairement canonique) formé en combinant p et base, comme décrit ci-dessus.

Exceptions

La surcharge qui ne prend pas de paramètre error_code& lève filesystem_error en cas d'erreurs de l'API du système d'exploitation sous-jacente, construite avec p comme premier argument, base comme second argument, et le code d'erreur du système d'exploitation comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le fixe au code d'erreur de l'API du système d'exploitation si un appel à cette API échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Notes

Sur les systèmes qui prennent en charge les noms de racine (par exemple Windows), le résultat de l'appel de absolute sur un chemin relatif possédant un nom de racine (par exemple "D:file.txt") lorsque le nom de racine de base est différent aboutira généralement à un chemin inexistant.

Exemple

#include <filesystem>
#include <iostream>
namespace fs = std::experimental::filesystem;

int main()
{
    fs::path p = "C:cl.exe";
    std::cout << "Current path is " << fs::current_path() << '\n'
              << "Absolute path for " << p << " is " << fs::absolute(p) << '\n'
	      << "System complete path for " << p << " is "
              << fs::system_complete(p) << '\n';
}

Sortie possible :

Current path is "D:/local/ConsoleApplication1"
Absolute path for "C:cl.exe" is "C:/local/ConsoleApplication1/cl.exe"
System complete path for "C:cl.exe" is "C:\Program Files (x86)\Microsoft Visual Studio 12.0\VC\bin\cl.exe"
