std::experimental::filesystem::permissions

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <experimental/filesystem>

void permissions( const path& p, perms prms );
void permissions( const path& p, perms prms, error_code& ec );  // (TS sur le système de fichiers)

Modifie les permissions d'accès du fichier vers lequel p pointe, comme le ferait POSIX fchmodat. Les liens symboliques sont suivis si prms::resolve_symlinks est défini.

Les effets dépendent de prms de la manière suivante :

  • Si ni perms::add_perms ni perms::remove_perms ne sont définis, les permissions du fichier sont fixées exactement à prms & fs::perms::mask (c'est-à-dire que chaque bit valide de prms est appliqué).
  • Si perms::add_perms, les permissions du fichier sont fixées exactement à status(p).permissions() | (prms & perms::mask) (c'est-à-dire que tout bit valide défini dans prms, mais absent des permissions actuelles du fichier, est ajouté aux permissions du fichier).
  • Si perms::remove_perms est défini, les permissions du fichier sont fixées exactement à status(p).permissions() & ~(prms & perms::mask) (c'est-à-dire que tout bit valide absent de prms, mais défini dans les permissions actuelles du fichier, est effacé des permissions du fichier).
  • Si perms::add_perms et perms::remove_perms sont tous deux définis, une erreur se produit.

La surcharge sans exception ne prend aucune action particulière en cas d'erreur.

Paramètres

  • p — chemin à examiner
  • prms — permissions à définir, ajouter ou retirer
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

(aucune)

Exceptions

La surcharge qui ne prend pas de paramètre error_code& lève filesystem_error en cas d'erreur de l'API du système d'exploitation sous-jacente, construite avec p comme premier argument et le code d'erreur du système d'exploitation comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le positionne au code d'erreur de l'API du système d'exploitation si un appel échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Notes

Les permissions ne sont pas nécessairement implémentées sous forme de bits, mais elles sont conceptuellement traitées de cette façon.

Certains bits de permission peuvent être ignorés sur certains systèmes, et la modification de certains bits peut en modifier automatiquement d'autres (par exemple, sur les plateformes ne distinguant pas propriétaire/groupe/tous, définir l'un des trois bits d'écriture définit les trois).

Exemple

#include <bitset>
#include <experimental/filesystem>
#include <fstream>
#include <iostream>
namespace fs = std::experimental::filesystem;

void demo_perms(fs::perms p)
{
     std::cout << ((p & fs::perms::owner_read) != fs::perms::none ? "r" : "-")
               << ((p & fs::perms::owner_write) != fs::perms::none ? "w" : "-")
               << ((p & fs::perms::owner_exec) != fs::perms::none ? "x" : "-")
               << ((p & fs::perms::group_read) != fs::perms::none ? "r" : "-")
               << ((p & fs::perms::group_write) != fs::perms::none ? "w" : "-")
               << ((p & fs::perms::group_exec) != fs::perms::none ? "x" : "-")
               << ((p & fs::perms::others_read) != fs::perms::none ? "r" : "-")
               << ((p & fs::perms::others_write) != fs::perms::none ? "w" : "-")
               << ((p & fs::perms::others_exec) != fs::perms::none ? "x" : "-")
               << '\n';
}

int main()
{
    std::ofstream("test.txt"); // créer un fichier

    std::cout << "Created file with permissions: ";
    demo_perms(fs::status("test.txt").permissions());

    fs::permissions("test.txt", fs::perms::add_perms |
                                fs::perms::owner_all | fs::perms::group_all);

    std::cout << "After adding o+rwx and g+rwx:  ";
    demo_perms(fs::status("test.txt").permissions());

    fs::remove("test.txt");
}

Sortie possible :

Created file with permissions: rw-r--r--
After adding o+rwx and g+rwx:  rwxrwxr--
