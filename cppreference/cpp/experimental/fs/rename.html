std::experimental::filesystem::rename

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <experimental/filesystem>

void rename( const path& old_p, const path& new_p );
void rename( const path& old_p, const path& new_p, std::error_code& ec );  // (TS sur le système de fichiers)

Déplace ou renomme l'objet du système de fichiers identifié par old_p en new_p comme par le rename POSIX :

  • Si old_p est un fichier qui n'est pas un répertoire, alors new_p doit être l'un des cas suivants :

    • le même fichier que old_p ou un lien physique vers celui-ci : rien n'est fait dans ce cas.
    • fichier non répertoire existant : new_p est d'abord supprimé, puis, sans permettre aux autres processus d'observer new_p comme supprimé, le chemin new_p est lié au fichier et old_p est délié du fichier. Des droits d'écriture sont requis à la fois sur le répertoire contenant old_p et sur le répertoire contenant new_p.
    • fichier inexistant dans un répertoire existant : le chemin new_p est lié au fichier et old_p est délié du fichier. Des droits d'écriture sont requis à la fois sur le répertoire contenant old_p et sur le répertoire contenant new_p.

  • Si old_p est un répertoire, alors new_p doit être l'un des cas suivants :

    • le même répertoire que old_p ou un lien physique vers celui-ci : rien n'est fait dans ce cas.
    • répertoire existant : new_p est supprimé s'il est vide sur les systèmes POSIX, mais cela peut être une erreur sur d'autres systèmes. Si ce n'est pas une erreur, alors new_p est d'abord supprimé, puis, sans permettre aux autres processus d'observer new_p comme supprimé, le chemin new_p est lié au répertoire et old_p est délié du répertoire. Des droits d'écriture sont requis à la fois sur le répertoire contenant old_p et sur le répertoire contenant new_p.
    • répertoire inexistant, ne se terminant pas par un séparateur de répertoire, et dont le répertoire parent existe : le chemin new_p est lié au répertoire et old_p est délié du répertoire. Des droits d'écriture sont requis à la fois sur le répertoire contenant old_p et sur le répertoire contenant new_p.

  • Les liens symboliques ne sont pas suivis : si old_p est un lien symbolique, c'est lui qui est renommé, pas sa cible. Si new_p est un lien symbolique existant, c'est lui qui est effacé, pas sa cible.

Le renommage échoue si

  • new_p se termine par dot ou par dot-dot.
  • new_p désigne un répertoire inexistant se terminant par un séparateur de répertoire.
  • old_p est un répertoire qui est un ancêtre de new_p.

Paramètres

  • old_p — chemin à déplacer ou renommer
  • new_p — chemin cible de l'opération de déplacement/renommage
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

(aucune)

Exceptions

La surcharge qui ne prend pas de paramètre error_code& lève filesystem_error en cas d'erreurs de l'API du système d'exploitation sous-jacente, construite avec old_p comme premier argument, new_p comme second argument, et le code d'erreur du système d'exploitation comme argument de code d'erreur. std::bad_alloc peut être levée si l'allocation mémoire échoue. La surcharge prenant un paramètre error_code& le fixe au code d'erreur de l'API du système d'exploitation si un appel à cette API échoue, et exécute ec.clear() si aucune erreur ne survient. Cette surcharge anoexcept specification:noexcept

Exemple

#include <experimental/filesystem>
#include <fstream>
#include <iostream>
namespace fs = std::experimental::filesystem;

int main()
{
    fs::path p = fs::current_path() / "sandbox";
    fs::create_directories(p/"from");
    std::ofstream(p/"from/file1.txt").put('a');
    fs::create_directory(p/"to");

//  fs::rename(p/"from/file1.txt", p/"to/"); // erreur : to est un répertoire
    fs::rename(p/"from/file1.txt", p/"to/file2.txt"); // OK
//  fs::rename(p/"from", p/"to"); // erreur : to n'est pas vide
    fs::rename(p/"from", p/"to/subdir"); // OK

    fs::remove_all(p);
}
