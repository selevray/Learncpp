std::experimental::scope_success

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <experimental/scope>

template< class EF >
class scope_success;  // (spécification technique des fondamentaux de bibliothèque v3)

Le modèle de classe scope_success est un garde de portée à usage général destiné à appeler sa fonction de sortie lorsqu'une portée est quittée normalement.

scope_success n'est pas CopyConstructible, CopyAssignable ou MoveAssignable, cependant il peut être MoveConstructible si EF satisfait certaines exigences, ce qui permet d'encapsuler un scope_success dans un autre objet.

Un scope_success peut être actif, c'est-à-dire appeler sa fonction de sortie à la destruction, ou inactif, c'est-à-dire ne rien faire à la destruction. Un scope_success est actif après sa construction à partir d'une fonction de sortie.

Un scope_success peut devenir inactif en appelant release() dessus, manuellement ou automatiquement (par le constructeur de déplacement). Un scope_success inactif peut aussi être obtenu en l'initialisant avec un autre scope_success inactif. Une fois qu'un scope_success est inactif, il ne peut plus redevenir actif.

Un scope_success contient en pratique une EF et un indicateur bool indiquant s'il est actif, ainsi qu'un compteur d'exceptions non capturées utilisé pour détecter si le destructeur est appelé pendant le déroulement de la pile.

Paramètres de modèle

  • EF — type de la fonction de sortie stockée

Exigences sur les types

  • EF doit être soit :
    • un type Destructible FunctionObject,
    • une référence lvalue vers FunctionObject,
    • une référence lvalue vers une fonction.
  • L'appel d'une lvalue de std::remove_reference_t<EF> sans argument doit être bien formé.

Fonctions membres

  • (constructeur) — construit un nouveau scope_success (fonction membre publique)
  • (destructeur) — appelle la fonction de sortie lorsque la portée est quittée normalement si le scope_success est actif, puis détruit le scope_success (fonction membre publique)
  • operator=[deleted] — scope_success n'est pas affectable (fonction membre publique)

##### Modificateurs {#Modifiers}

  • release — rend le scope_success inactif (fonction membre publique)

Guides de déduction

Notes

Construire un scope_success de durée de stockage dynamique peut conduire à un comportement inattendu.

Construire un scope_success à partir d'un autre scope_success créé dans un thread différent peut également conduire à un comportement inattendu, car le nombre d'exceptions non capturées obtenu dans différents threads peut être comparé lors de la destruction.

Si le EF stocké dans un objet scope_success fait référence à une variable locale de la fonction où il est défini, par exemple sous la forme d'une lambda capturant la variable par référence, et que cette variable est utilisée comme opérande de retour dans cette fonction, cette variable peut déjà avoir été retournée lorsque le destructeur de scope_success s'exécute en appelant la fonction de sortie. Cela peut conduire à un comportement surprenant.

Exemple

#include <iostream>
#include <cstdlib>
#include <string_view>
#include <experimental/scope>

void print_exit_status(std::string_view name, bool exit_status, bool did_throw) {
  std::cout << name << ":\n";
  std::cout << "  Throwed exception  " << (did_throw ? "yes" : "no") << "\n";
  std::cout << "  Exit status        " << (exit_status ? "finished" : "pending") << "\n\n";
}

// Lever aléatoirement une exception (50 % de chances)
void maybe_throw() {
    if (std::rand() >= RAND_MAX / 2)
        throw std::exception{};
}

int main() {
  bool exit_status{false}, did_throw{false};

  // Gestion manuelle à la « fin de portée »
  try {
    maybe_throw();
    exit_status = true;
  } catch (...) { did_throw = true; }
  print_exit_status("Manual handling", exit_status, did_throw);

  // Avec scope_exit : s'exécute à la sortie de portée (succès ou exception)
  exit_status = did_throw = false;
  try {
    auto guard = std::experimental::scope_exit{[&]{ exit_status = true; } };
    maybe_throw();
  } catch (...) { did_throw = true; }
  print_exit_status("scope_exit", exit_status, did_throw);

  // Avec scope_fail : s'exécute uniquement si une exception survient
  exit_status = did_throw = false;
  try {
    auto guard = std::experimental::scope_fail{[&]{ exit_status = true; } };
    maybe_throw();
  } catch (...) { did_throw = true; }
  print_exit_status("scope_fail", exit_status, did_throw);

  // Avec scope_success : s'exécute uniquement si aucune exception ne survient
  exit_status = did_throw = false;
  try {
    auto guard = std::experimental::scope_success{[&]{ exit_status = true; } };
    maybe_throw();
  } catch (...) { did_throw = true; }
  print_exit_status("scope_success", exit_status, did_throw);
}

Output:

Manual handling:
  Throwed exception  yes
  Exit status        pending

scope_exit:
  Throwed exception  no
  Exit status        finished

scope_fail:
  Throwed exception  yes
  Exit status        finished

scope_success:
  Throwed exception  yes
  Exit status        pending
