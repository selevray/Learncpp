std::move

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <utility>

template< class T >
typename std::remove_reference<T>::type&& move( T&& t ) noexcept;  // (depuis C++11) (jusqu'à C++14)

template< class T >
constexpr std::remove_reference_t<T>&& move( T&& t ) noexcept;  // (depuis C++14)

std::move est utilisé pour indiquer qu'un objet t peut être « déplacé », c'est-à-dire permettre le transfert efficace des ressources de t vers un autre objet.

En particulier, std::move produit une expression xvalue qui identifie son argument t. Elle est exactement équivalente à un static_cast vers un type de référence rvalue.

Paramètres

  • t — l'objet à déplacer

Valeur de retour

static_cast<typename std::remove_reference<T>::type&&>(t)

Notes

Les fonctions qui acceptent des paramètres de référence rvalue (y compris les constructeurs de déplacement, les opérateurs d'affectation par déplacement et les fonctions membres ordinaires telles que std::vector::push_back) sont sélectionnées, par résolution de surcharge, lorsqu'elles sont appelées avec des arguments rvalue (soit des prvalues, comme un objet temporaire, soit des xvalues, comme celle produite par std::move). Si l'argument identifie un objet propriétaire de ressources, ces surcharges ont la possibilité, sans y être obligées, de déplacer les ressources détenues par l'argument. Par exemple, un constructeur de déplacement d'une liste chaînée peut copier le pointeur vers la tête de la liste et stocker nullptr dans l'argument, au lieu d'allouer et de copier les nœuds un à un.

Les noms des variables de référence rvalue sont des lvalues et doivent être convertis en xvalues pour être liés aux surcharges de fonctions qui acceptent des paramètres de référence rvalue, ce qui explique pourquoi les constructeurs de déplacement et les opérateurs d'affectation par déplacement utilisent généralement std::move :

// Constructeur de déplacement simple
A(A&& arg) : member(std::move(arg.member)) // l'expression « arg.member » est une lvalue
{}

// Opérateur d'affectation par déplacement simple
A& operator=(A&& other)
{
    member = std::move(other.member);
    return *this;
}

Une exception existe lorsque le type du paramètre de fonction est une référence de transfert (qui ressemble à une référence rvalue vers un paramètre de modèle de type), auquel cas std::forward est utilisé à la place.

Sauf indication contraire, tous les objets de la bibliothèque standard qui ont été déplacés sont placés dans un « état valide mais non spécifié », ce qui signifie que les invariants de classe de l'objet sont respectés (ainsi, les fonctions sans préconditions, comme l'opérateur d'affectation, peuvent être utilisées sans risque sur l'objet après son déplacement) :

std::vector<std::string> v;
std::string str = "example";
v.push_back(std::move(str)); // str est désormais valide mais non spécifié
str.back(); // comportement indéfini si size() == 0 : back() a pour précondition !empty()
if (!str.empty())
    str.back(); // OK, empty() n'a pas de précondition et la précondition de back() est respectée

str.clear(); // OK, clear() n'a pas de préconditions

De plus, les fonctions de la bibliothèque standard appelées avec des arguments xvalue peuvent supposer que l'argument est la seule référence vers l'objet ; s'il a été construit à partir d'une lvalue avec std::move, aucune vérification d'aliasing n'est effectuée. Toutefois, l'auto-affectation par déplacement des types de la bibliothèque standard place garanti l'objet dans un état valide (mais généralement non spécifié) :

std::vector<int> v = {2, 3, 3};
v = std::move(v); // la valeur de v est non spécifiée

Exemple

#include <iomanip>
#include <iostream>
#include <string>
#include <utility>
#include <vector>

int main()
{
    std::string str = "Salut";
    std::vector<std::string> v;

    // utilise la surcharge push_back(const T&), ce qui signifie
    // nous supportons le coût de la copie de str
    v.push_back(str);
    std::cout << "After copy, str is " << std::quoted(str) << '\n';

    // utilise la surcharge à référence rvalue push_back(T&&),
    // ce qui signifie qu'aucune chaîne n'est copiée ; à la place, le contenu
    // de str est déplacé dans le vecteur. Ceci est moins
    // coûteux, mais signifie aussi que str peut maintenant être vide.
    v.push_back(std::move(str));
    std::cout << "After move, str is " << std::quoted(str) << '\n';

    std::cout << "The contents of the vector are {" << std::quoted(v[0])
              << ", " << std::quoted(v[1]) << "}\n";
}

Sortie possible :

After copy, str is "Salut"
After move, str is ""
The contents of the vector are {"Salut", "Salut"}
