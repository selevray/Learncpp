std::compare_strong_order_fallback

Signature d'appel

template< class T, class U >
    requires /* voir ci-dessous */
constexpr std::strong_ordering
    compare_strong_order_fallback( T&& t, U&& u ) noexcept(/* voir ci-dessous */);  // (depuis C++20)

Effectue une comparaison à trois voies sur les sous-expressions t et u et produit un résultat de type std::strong_ordering, même si l'opérateur <=> est indisponible.

Si std::decay_t<T> et std::decay_t<U> sont du même type, std::compare_strong_order_fallback(t, u) est expression-équivalente à :

  • std::strong_order(t, u), si c'est une expression bien formée ;
  • sinon, t == u ? std::strong_ordering::equal :t < u ? std::strong_ordering::less : std::strong_ordering::greater si les expressions t == u et t < u sont toutes deux bien formées et que chacun de decltype(t == u) et decltype(t < u) modélise boolean-testable, sauf que t et u ne sont évaluées qu'une seule fois.

Dans tous les autres cas, std::compare_strong_order_fallback(t, u) est mal formé, ce qui peut entraîner un échec de substitution lorsqu'il apparaît dans le contexte immédiat d'une instanciation de modèle.

Objets de point de personnalisation

Le nom std::compare_strong_order_fallback désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __compare_strong_order_fallback_fn.

Toutes les instances de __compare_strong_order_fallback_fn sont égales. Les effets de l'invocation de différentes instances du type __compare_strong_order_fallback_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, std::compare_strong_order_fallback peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de std::compare_strong_order_fallback ci-dessus, alors __compare_strong_order_fallback_fn modélise

  • std::invocable<__compare_strong_order_fallback_fn, Args...>,
  • std::invocable<const __compare_strong_order_fallback_fn, Args...>,
  • std::invocable<__compare_strong_order_fallback_fn&, Args...>, and
  • std::invocable<const __compare_strong_order_fallback_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __compare_strong_order_fallback_fn ne participe à la résolution de surcharge.
