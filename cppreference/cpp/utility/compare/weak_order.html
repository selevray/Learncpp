Compare deux valeurs à l'aide de la comparaison à trois voies et produit un résultat de type std::weak_ordering.

Soient t et u des expressions, et T et U désignant respectivement decltype((t)) et decltype((u)) ; std::weak_order(t, u) est équivalent à l'expression :

  • Si std::is_same_v<std::decay_t<T>, std::decay_t<U>> est true :
    • std::weak_ordering(weak_order(t, u)), si c'est une expression bien formée avec résolution de surcharge effectuée dans un contexte ne contenant pas de déclaration de std::weak_order,
    • sinon, si T est un type à virgule flottante :
      • si std::numeric_limits<T>::is_iec559 est true, effectue la comparaison d'ordre faible des valeurs à virgule flottante (voir ci-dessous) et renvoie ce résultat comme une valeur de type std::weak_ordering,
      • sinon, produit une valeur de type std::weak_ordering cohérente avec l'ordre observé par les opérateurs de comparaison de T,
    • sinon, std::weak_ordering(std::compare_three_way()(t, u)), si elle est bien formée,
    • sinon, std::weak_ordering(std::strong_order(t, u)), si elle est bien formée.
  • Dans tous les autres cas, l'expression est mal formée, ce qui peut entraîner un échec de substitution lorsqu'elle apparaît dans le contexte immédiat d'une instanciation de modèle.

Objets de point de personnalisation

Le nom std::weak_order désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __weak_order_fn.

Toutes les instances de __weak_order_fn sont égales. Les effets de l'invocation de différentes instances du type __weak_order_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, std::weak_order peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de std::weak_order ci-dessus, alors __weak_order_fn modélise

  • std::invocable<__weak_order_fn, Args...>,
  • std::invocable<const __weak_order_fn, Args...>,
  • std::invocable<__weak_order_fn&, Args...>, and
  • std::invocable<const __weak_order_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __weak_order_fn ne participe à la résolution de surcharge.

Ordre faible strict des types à virgule flottante IEEE

Soient x et y des valeurs du même type à virgule flottante IEEE, et weak_order_less(x, y) le résultat booléen indiquant si x précède y dans l'ordre faible strict défini par la norme C++.

  • Si ni x ni y n'est NaN, alors weak_order_less(x, y) == true si et seulement si x < y, c'est-à-dire que toutes les représentations d'une même valeur à virgule flottante sont équivalentes ;
  • Si x est un NaN négatif et y n'est pas un NaN négatif, alors weak_order_less(x, y) == true ;
  • Si x n'est pas un NaN positif et y est un NaN positif, alors weak_order_less(x, y) == true ;
  • Si x et y sont tous deux des NaN de même signe, alors (weak_order_less(x, y) || weak_order_less(y, x)) == false, c'est-à-dire que tous les NaN de même signe sont équivalents.
