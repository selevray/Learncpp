template< class T, class U >

constexpr std::strong_ordering strong_order( T&& t, U&& u ) noexcept(/* voir ci-dessous */);

Compare deux valeurs à l'aide de la comparaison à trois voies et produit un résultat de type std::strong_ordering.

Soient t et u des expressions, et T et U désignant respectivement decltype((t)) et decltype((u)) ; std::strong_order(t, u) est équivalent à l'expression :

  • Si std::is_same_v<std::decay_t<T>, std::decay_t<U>> est true :
    • std::strong_ordering(strong_order(t, u)), si c'est une expression bien formée avec résolution de surcharge effectuée dans un contexte ne contenant pas de déclaration de std::strong_order,
    • sinon, si T est un type à virgule flottante :
      • si std::numeric_limits<T>::is_iec559 est true, effectue la comparaison totalOrder ISO/IEC/IEEE 60559 des valeurs à virgule flottante et renvoie ce résultat sous forme de valeur de type std::strong_ordering (remarque : cette comparaison peut distinguer le zéro positif du zéro négatif, et les NaN de représentations différentes),
      • sinon, produit une valeur de type std::strong_ordering cohérente avec l'ordre observé par les opérateurs de comparaison de T,
    • sinon, std::strong_ordering(std::compare_three_way()(t, u)) si elle est bien formée.
  • Dans tous les autres cas, l'expression est mal formée, ce qui peut entraîner un échec de substitution lorsqu'elle apparaît dans le contexte immédiat d'une instanciation de modèle.

Objets de point de personnalisation

Le nom std::strong_order désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __strong_order_fn.

Toutes les instances de __strong_order_fn sont égales. Les effets de l'invocation de différentes instances du type __strong_order_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, std::strong_order peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de std::strong_order ci-dessus, alors __strong_order_fn modélise

  • std::invocable<__strong_order_fn, Args...>,
  • std::invocable<const __strong_order_fn, Args...>,
  • std::invocable<__strong_order_fn&, Args...>, and
  • std::invocable<const __strong_order_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __strong_order_fn ne participe à la résolution de surcharge.

Ordre total strict des types à virgule flottante IEEE

Soient x et y des valeurs d'un même type à virgule flottante IEEE, et total_order_less(x, y) le résultat booléen indiquant si x précède y dans l'ordre total strict défini par totalOrder dans ISO/IEC/IEEE 60559.

(total_order_less(x, y) || total_order_less(y, x)) == false si et seulement si x et y ont le même motif de bits.

  • si ni x ni y n'est NaN :
    • si x < y, alors total_order_less(x, y) == true ;
    • si x > y, alors total_order_less(x, y) == false ;
    • if x == y,
      • si x est un zéro négatif et y un zéro positif, total_order_less(x, y) == true,
      • si x n'est pas nul et que le champ exposant de x est inférieur à celui de y, alors total_order_less(x, y) == (x > 0) (uniquement pertinent pour les nombres à virgule flottante décimaux) ;
  • si x ou y est NaN :
    • si x est un NaN négatif et y n'est pas un NaN négatif, alors total_order_less(x, y) == true,
    • si x n'est pas un NaN positif et y est un NaN positif, alors total_order_less(x, y) == true,
    • si x et y sont tous deux des NaN de même signe et que le champ mantisse de x est inférieur à celui de y, alors total_order_less(x, y) == !std::signbit(x).
