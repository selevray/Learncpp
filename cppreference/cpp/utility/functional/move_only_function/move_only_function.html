Crée un nouveau std::move_only_function.

1,2) Le constructeur par défaut et le constructeur prenant nullptr construisent un std::move_only_function vide.

  1. Le constructeur de déplacement construit un std::move_only_function dont la cible est celle de other. other est dans un état valide mais non spécifié après la construction par déplacement.

  2. Le constructeur de copie est supprimé. std::move_only_function ne satisfait pas CopyConstructible.

  3. Soit VT égal à std::decay_t<F>. Si f est un pointeur de fonction nul, une valeur de pointeur vers membre nulle, ou un std::move_only_function vide (pouvant être toute autre spécialisation), alors construit un std::move_only_function vide. Sinon, construit un std::move_only_function dont la cible est de type VT et initialisée par initialisation directe non de liste avec std::forward<F>(f).

  • Cette surcharge ne participe à la résolution de surcharge que si VT n'est ni identique à move_only_function ni une spécialisation de std::in_place_type_t, et /*is-callable-from*/<VT> (voir ci-dessous) est true.
  • Le programme est mal formé si std::is_constructible_v<VT, F> n'est pas true.
  1. Soit VT égal à std::decay_t<T>. Construit un std::move_only_function dont la cible est de type VT et initialisée par initialisation directe non de liste avec std::forward<CArgs>(args)....
  • Cette surcharge ne participe à la résolution de surcharge que si std::is_constructible_v<VT, CArgs...> et /*is-callable-from*/<VT> (voir ci-dessous) sont true.
  • Le programme est mal formé si VT n'est pas du même type que T.
  1. Soit VT égal à std::decay_t<T>. Construit un std::move_only_function dont la cible est de type VT et initialisée par initialisation directe non de liste avec il, std::forward<CArgs>(args)....
  • Cette surcharge ne participe à la résolution de surcharge que si std::is_constructible_v<VT, std::initializer_list<U>&, CArgs...> et /*is-callable-from*/<VT> (voir ci-dessous) sont true.
  • Le programme est mal formé si VT n'est pas du même type que T.

Pour les constructeurs (5-7), le comportement est indéfini si VT ne satisfait pas les exigences Destructible, ou si std::is_move_constructible_v<VT> est true mais que VT ne satisfait pas les exigences MoveConstructible.

La constante /*is-callable-from*/<VT> dépend de cv, ref et noex dans le paramètre de modèle de std::move_only_function comme suit :

noexcept(false) std::is_invocable_r_v<R, VT, Args...> && std::is_invocable_r_v<R, VT&, Args...>
noexcept(true) std::is_nothrow_invocable_r_v<R, VT, Args...> && std::is_nothrow_invocable_r_v<R, VT&, Args...>
const noexcept(false) std::is_invocable_r_v<R, const VT, Args...> && std::is_invocable_r_v<R, const VT&, Args...>
const noexcept(true) std::is_nothrow_invocable_r_v<R, const VT, Args...> && std::is_nothrow_invocable_r_v<R, const VT&, Args...>
& noexcept(false) std::is_invocable_r_v<R, VT&, Args...>
& noexcept(true) std::is_nothrow_invocable_r_v<R, VT&, Args...>
const & noexcept(false) std::is_invocable_r_v<R, const VT&, Args...>
const & noexcept(true) std::is_nothrow_invocable_r_v<R, const VT&, Args...>
&& noexcept(false) std::is_invocable_r_v<R, VT, Args...>
&& noexcept(true) std::is_nothrow_invocable_r_v<R, VT, Args...>
const && noexcept(false) std::is_invocable_r_v<R, const VT, Args...>
const && noexcept(true) std::is_nothrow_invocable_r_v<R, const VT, Args...>

Paramètres

  • other — un autre std::move_only_function à partir duquel déplacer
  • f — une fonction ou un objet Callable à encapsuler
  • args — arguments pour construire l'objet cible
  • il — std::initializer_list pour construire l'objet cible

Exceptions

5-7) Peut lever std::bad_alloc en cas d'échec d'allocation ou propager l'exception levée par l'initialisation de la cible. Aucune exception n'est levée si VT est un type de pointeur de fonction ou une spécialisation de std::reference_wrapper.
