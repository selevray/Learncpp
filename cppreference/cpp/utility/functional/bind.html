std::bind

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <functional>

template< class F, class... Args >
/* unspecified */ bind( F&& f, Args&&... args );  // (1) (depuis C++11) (constexpr depuis C++20)

template< class R, class F, class... Args >
/* unspecified */ bind( F&& f, Args&&... args );  // (2) (depuis C++11) (constexpr depuis C++20)

Le modèle de fonction std::bind génère un wrapper d'appel à transmission pour f. Appeler ce wrapper est équivalent à invoquer f avec certains de ses arguments liés à args.

Si std::is_constructible<std::decay<F>::type, F>::value vaut false, ou si std::is_constructible<std::decay<Arg_i>::type, Arg_i>::value vaut false pour un type quelconque Arg_i dans Args, le programme est mal formé.

Si std::decay<Ti>::type ou un type quelconque de Args n'est pas MoveConstructible ou Destructible, le comportement est indéfini.

Paramètres

  • f — Callable objet (objet fonction, pointeur vers fonction, référence vers fonction, pointeur vers fonction membre ou pointeur vers membre de données) qui sera lié à certains arguments
  • args — liste des arguments à lier, les arguments non liés étant remplacés par les substituts _1, _2, _3... de l'espace de noms std::placeholders

Valeur de retour

Un objet fonction g de type non spécifié T, pour lequel std::is_bind_expression<T>::value vaut true. Il possède les membres suivants :

std::bind type de retour

Objets membres

Le type de retour de std::bind contient un objet membre de type std::decay<F>::type construit à partir de std::forward<F>(f), et un objet par chacun de args..., de type std::decay<Arg_i>::type, construit de manière similaire à partir de std::forward<Arg_i>(arg_i).

Constructeurs

Le type de retour de std::bind est CopyConstructible si tous ses objets membres (spécifiés ci-dessus) sont CopyConstructible, et MoveConstructible sinon. Ce type définit les membres suivants :

Type membre result_type

  1. (obsolète en C++17) Si F est un pointeur vers fonction ou un pointeur vers fonction membre, result_type est le type de retour de F. Si F est un type classe possédant un typedef imbriqué result_type, alors result_type est F::result_type. Sinon, aucun result_type n'est défini.

  2. (obsolète en C++17) result_type est exactement R.

(jusqu'à C++20)

Fonction membre operator()

Lorsque g est invoqué dans une expression d'appel de fonction g(u1, u2, ... uM), l'objet stocké est invoqué comme si l'on exécutait

  1. INVOKE(fd, std::forward<V1>(v1), std::forward<V2>(v2), ..., std::forward<VN>(vN)), or

  2. INVOKE<R>(fd, std::forward<V1>(v1), std::forward<V2>(v2), ..., std::forward<VN>(vN)),

où fd est une valeur de type std::decay<F>::type, les valeurs et types des arguments liés v1, v2, ..., vN sont déterminés comme spécifié ci-dessous.

Si certains arguments fournis lors de l'appel à g() ne sont associés à aucun substitut stocké dans g, les arguments inutilisés sont évalués puis ignorés.

Un appel de operator() est sans lever d'exception ou est une sous-expression constante (depuis C++20) si et seulement si l'opération INVOKE sous-jacente l'est. operator() participe à la résolution de surcharge uniquement si l'opération INVOKE est bien formée lorsqu'elle est traitée comme une opérande non évaluée.

Si g est qualifié volatile, le programme est mal formé.

Si INVOKE(fd, w1, w2, ..., wN) ne peut jamais être une expression valide pour aucune valeur possible de w1, w2, ..., wN, le comportement est indéfini.

Arguments liés

Pour chaque argument mémorisé arg_i, l'argument lié correspondant v_i dans l'opération INVOKE ou INVOKE<R> est déterminé comme suit :

Cas 1 : wrappers de référence

Si arg_i est de type std::reference_wrapper<T> (par exemple, std::ref ou std::cref a été utilisé dans l'appel initial à std::bind), alors v_i est arg_i.get() et son type V_i est T& : l'argument mémorisé est passé par référence dans l'objet fonction invoqué.

Cas 2 : expressions bind

Si arg_i est de type T pour lequel std::is_bind_expression<T>::value est true (par exemple, une autre expression std::bind a été passée directement dans l'appel initial à std::bind), alors std::bind réalise une composition de fonctions : au lieu de passer l'objet fonction que la sous-expression bind renverrait, la sous-expression est invoquée immédiatement, et sa valeur de retour est passée à l'objet invocable externe. Si la sous-expression bind possède des arguments substituts, ils sont partagés avec le bind externe (sélectionnés parmi u1, u2, ...). Plus précisément, v_i est arg_i(std::forward<Uj>(uj)...) et son type V_i est [std::result_of<T cv ﻿&(Uj&&...)>::type&& (jusqu'à C++17) | std::invoke_result_t<T cv ﻿&, Uj&&...>&& (depuis C++17)] (la qualification cv est la même que celle de g).

Cas 3 : substituts

Si arg_i est de type T, pour lequel std::is_placeholder<T>::value n'est pas 0 (c'est-à-dire qu'un substitut tel que std::placeholders::_1, _2, _3, ... a été utilisé comme argument de l'appel initial à std::bind), alors l'argument désigné par le substitut (u1 pour _1, u2 pour _2, etc.) est passé à l'objet invocable : v_i est std::forward<Uj>(uj) et son type V_i est Uj&&.

Cas 4 : arguments ordinaires

Sinon, arg_i est passé à l'objet invocable comme argument lvalue : v_i est simplement arg_i et son type V_i est T cv ﻿&, où cv est la même qualification cv que celle de g.

Exceptions

Ne lève une exception que si la construction de std::decay<F>::type à partir de std::forward<F>(f) lève une exception, ou si l'un des constructeurs de std::decay<Arg_i>::type à partir du std::forward<Arg_i>(arg_i) correspondant lève une exception, où Arg_i est le i-ème type et arg_i le i-ème argument de Args... args.

Notes

Comme décrit dans Callable, lors de l'invocation d'un pointeur vers fonction membre non statique ou d'un pointeur vers donnée membre non statique, le premier argument doit être une référence ou un pointeur (y compris, éventuellement, un pointeur intelligent comme std::shared_ptr et std::unique_ptr) vers un objet dont le membre sera accédé.

Les arguments de bind sont copiés ou déplacés, et ne sont jamais passés par référence sauf s'ils sont encapsulés dans std::ref ou std::cref.

Les substituts en double dans une même expression bind (plusieurs _1 par exemple) sont autorisés, mais les résultats ne sont bien définis que si l'argument correspondant (u1) est une lvalue ou une rvalue non déplaçable.

Exemple

#include <functional>
#include <iostream>
#include <memory>
#include <random>

void f(int n1, int n2, int n3, const int& n4, int n5)
{
    std::cout << n1 << ' ' << n2 << ' ' << n3 << ' ' << n4 << ' ' << n5 << '\n';
}

int g(int n1)
{
    return n1;
}

struct Foo
{
    void print_sum(int n1, int n2)
    {
        std::cout << n1 + n2 << '\n';
    }

    int data = 10;
};

int main()
{
    using namespace std::placeholders;  // pour _1, _2, _3...

    std::cout << "1) argument reordering and pass-by-reference: ";
    int n = 7;
    // (_1 et _2 proviennent de std::placeholders, et représentent des arguments futurs
    // arguments qui seront passés à f1)
    auto f1 = std::bind(f, _2, 42, _1, std::cref(n), n);
    n = 10;
    f1(1, 2, 1001); // 1 est lié par _1, 2 est lié par _2, 1001 est inutilisé
                    // effectue un appel à f(2, 42, 1, n, 7)

    std::cout << "2) achieving the same effect using a lambda: ";
    n = 7;
    auto lambda = [&ncref = n, n](auto a, auto b, auto /*unused*/)
    {
        f(b, 42, a, ncref, n);
    };
    n = 10;
    lambda(1, 2, 1001); // équivalent à un appel à f1(1, 2, 1001)

    std::cout << "3) nested bind subexpressions share the placeholders: ";
    auto f2 = std::bind(f, _3, std::bind(g, _3), _3, 4, 5);
    f2(10, 11, 12); // effectue un appel à f(12, g(12), 12, 4, 5);

    std::cout << "4) bind a RNG with a distribution: ";
    std::default_random_engine e;
    std::uniform_int_distribution<> d(0, 10);
    auto rnd = std::bind(d, e); // une copie de e est stockée dans rnd
    for (int n = 0; n < 10; ++n)
        std::cout << rnd() << ' ';
    std::cout << '\n';

    std::cout << "5) bind to a pointer to member function: ";
    Foo foo;
    auto f3 = std::bind(&Foo::print_sum, &foo, 95, _1);
    f3(5);

    std::cout << "6) bind to a mem_fn that is a pointer to member function: ";
    auto ptr_to_print_sum = std::mem_fn(&Foo::print_sum);
    auto f4 = std::bind(ptr_to_print_sum, &foo, 95, _1);
    f4(5);

    std::cout << "7) bind to a pointer to data member: ";
    auto f5 = std::bind(&Foo::data, _1);
    std::cout << f5(foo) << '\n';

    std::cout << "8) bind to a mem_fn that is a pointer to data member: ";
    auto ptr_to_data = std::mem_fn(&Foo::data);
    auto f6 = std::bind(ptr_to_data, _1);
    std::cout << f6(foo) << '\n';

    std::cout << "9) use smart pointers to call members of the referenced objects: ";
    std::cout << f6(std::make_shared<Foo>(foo)) << ' '
              << f6(std::make_unique<Foo>(foo)) << '\n';
}

Output:

1) argument reordering and pass-by-reference: 2 42 1 10 7
2) achieving the same effect using a lambda: 2 42 1 10 7
3) nested bind subexpressions share the placeholders: 12 12 12 4 5
4) bind a RNG with a distribution: 0 1 8 5 5 2 0 7 7 10
5) bind to a pointer to member function: 100
6) bind to a mem_fn that is a pointer to member function: 100
7) bind to a pointer to data member: 10
8) bind to a mem_fn that is a pointer to data member: 10
9) use smart pointers to call members of the referenced objects: 10 10
