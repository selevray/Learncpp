Spécification de format standard (depuis C++20)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Pour les types de base et les types chaîne, la spécification de format est fondée sur la spécification de format en Python.

La syntaxe des spécifications de format est :

| | | | fill-and-align ﻿*(facultatif)* sign ﻿*(facultatif)* #(facultatif) 0(facultatif) width ﻿*(facultatif)* precision ﻿*(facultatif)* L(facultatif) type ﻿*(facultatif)* | | | |

Les options sign, # et 0 ne sont valides que lorsqu'un type de présentation entier ou à virgule flottante est utilisé.

Remplissage et alignement

fill-and-align est un caractère de remplissage facultatif (qui peut être n'importe quel caractère autre que { ou }), suivi de l'une des options d'alignement <, >, ^.

Si aucun caractère de remplissage n'est spécifié, il vaut par défaut le caractère espace. Pour une spécification de format dans un encodage Unicode, le caractère de remplissage doit correspondre à une seule valeur scalaire Unicode.

La signification des options d'alignement est la suivante :

  • < : Force l'argument formaté à être aligné au début de l'espace disponible en insérant n caractères de remplissage après l'argument formaté. C'est la valeur par défaut lorsqu'un type de présentation autre qu'entier et autre que à virgule flottante est utilisé.

  • > : Force l'argument formaté à être aligné à la fin de l'espace disponible en insérant n caractères de remplissage avant l'argument formaté. C'est la valeur par défaut lorsqu'un type de présentation entier ou à virgule flottante est utilisé.

  • ^ : Force l'argument formaté à être centré dans l'espace disponible en insérant ⌊

    n

    2

    ⌋ caractères avant et ⌈

    n

    2

    ⌉ caractères après l'argument formaté.

Dans chaque cas, n est la différence entre la largeur minimale du champ (spécifiée par width) et la largeur estimée de l'argument formaté, ou 0 si la différence est inférieure à 0.

#include <cassert>
#include <format>

int main()
{
    char c = 120;
    assert(std::format("{:6}", 42)    == "    42");
    assert(std::format("{:6}", 'x')   == "x     ");
    assert(std::format("{:*<6}", 'x') == "x*****");
    assert(std::format("{:*>6}", 'x') == "*****x");
    assert(std::format("{:*^6}", 'x') == "**x***");
    assert(std::format("{:6d}", c)    == "   120");
    assert(std::format("{:6}", true)  == "true  ");
}

Signe, #, et 0

L'option sign peut être l'une des suivantes :

  • + : Indique qu'un signe doit être utilisé pour les nombres positifs et négatifs. Le signe + est inséré avant la valeur de sortie pour les nombres positifs ou nuls.
  • - : Indique qu'un signe doit être utilisé uniquement pour les nombres négatifs (c'est le comportement par défaut).
  • espace : Indique qu'une espace initiale doit être utilisée pour les nombres positifs ou nuls, et un signe moins pour les nombres négatifs.

Le zéro négatif est traité comme un nombre négatif.

L'option sign s'applique à l'infini et à NaN à virgule flottante.

#include <cassert>
#include <format>
#include <limits>

int main()
{
    double inf = std::numeric_limits<double>::infinity();
    double nan = std::numeric_limits<double>::quiet_NaN();
    assert(std::format("{0:},{0:+},{0:-},{0: }", 1)   == "1,+1,1, 1");
    assert(std::format("{0:},{0:+},{0:-},{0: }", -1)  == "-1,-1,-1,-1");
    assert(std::format("{0:},{0:+},{0:-},{0: }", inf) == "inf,+inf,inf, inf");
    assert(std::format("{0:},{0:+},{0:-},{0: }", nan) == "nan,+nan,nan, nan");
}

L'option # fait utiliser la forme alternative pour la conversion.

  • Pour les types entiers, lorsque le type de présentation binaire, octal ou hexadécimal est utilisé, la forme alternative insère le préfixe (0b, 0 ou 0x) dans la valeur de sortie après le caractère de signe (éventuellement une espace) s'il y en a un, ou l'ajoute avant la valeur de sortie sinon.
  • Pour les types à virgule flottante, la forme alternative fait que le résultat de la conversion des valeurs finies contient toujours un caractère de séparation décimale, même si aucun chiffre ne le suit. Normalement, un caractère de séparation décimale n'apparaît dans le résultat de ces conversions que si un chiffre le suit. De plus, pour les conversions g et G, les zéros de fin ne sont pas supprimés du résultat.

L'option 0 complète le champ avec des zéros initiaux (après toute indication de signe ou de base) jusqu'à la largeur du champ, sauf lorsqu'elle est appliquée à un infini ou à NaN. Si le caractère 0 et une option d'alignement apparaissent tous deux, le caractère 0 est ignoré.

#include <cassert>
#include <format>

int main()
{
    char c = 120;
    assert(std::format("{:+06d}", c)   == "+00120");
    assert(std::format("{:#06x}", 0xa) == "0x000a");
    assert(std::format("{:<06}", -42)  == "-42   "); // 0 est ignoré à cause de '<'
}

Largeur et précision

width est soit un nombre décimal positif, soit un champ de remplacement imbriqué ({} ou {n}). S'il est présent, il spécifie la largeur minimale du champ.

precision est un point (.) suivi soit d'un nombre décimal non négatif, soit d'un champ de remplacement imbriqué. Ce champ indique la précision ou la taille maximale du champ. Il ne peut être utilisé qu'avec les types à virgule flottante et chaîne.

  • Pour les types à virgule flottante, ce champ spécifie la précision de formatage.
  • Pour les types chaîne, il fournit une borne supérieure à la largeur estimée (voir ci-dessous) du préfixe de la chaîne à copier vers la sortie. Pour une chaîne dans un encodage Unicode, le texte à copier vers la sortie est le plus long préfixe de groupes de graphèmes étendus entiers dont la largeur estimée n'excède pas la précision.

Si un champ de remplacement imbriqué est utilisé pour width ou precision, et que l'argument correspondant n'est pas de [type entier (jusqu'à C++23) | type entier signé ou non signé standard (depuis C++23)], ou est négatif, une exception de type std::format_error est levée.

float pi = 3.14f;
assert(std::format("{:10f}", pi)           == "  3.140000"); // width = 10
assert(std::format("{:{}f}", pi, 10)       == "  3.140000"); // width = 10
assert(std::format("{:.5f}", pi)           == "3.14000");    // precision = 5
assert(std::format("{:.{}f}", pi, 5)       == "3.14000");    // precision = 5
assert(std::format("{:10.5f}", pi)         == "   3.14000"); // width = 10, precision = 5
assert(std::format("{:{}.{}f}", pi, 10, 5) == "   3.14000"); // width = 10, precision = 5

auto b1 = std::format("{:{}f}", pi, 10.0); // lève une exception : width n'est pas de type entier
auto b2 = std::format("{:{}f}", pi, -10);  // lève une exception : width est négatif
auto b3 = std::format("{:.{}f}", pi, 5.0); // lève une exception : precision n'est pas de type entier

La largeur d'une chaîne est définie comme le nombre estimé de colonnes appropriées pour l'afficher dans un terminal.

Pour le calcul de la largeur, une chaîne est supposée être dans un encodage défini par l'implémentation. La méthode de calcul de la largeur n'est pas spécifiée, mais pour une chaîne dans un encodage Unicode, l'implémentation doit estimer la largeur de la chaîne comme la somme des largeurs estimées des premiers points de code de ses groupes de graphèmes étendus. La largeur estimée vaut 2 pour les points de code suivants, et 1 sinon :

  • Tout point de code dont la propriété Unicode East_Asian_Width a la valeur Fullwidth (F) ou Wide (W)
  • U+4DC0 - U+4DFF (Symboles des hexagrammes du Yijing)
  • U+1F300 – U+1F5FF (Symboles divers et pictogrammes)
  • U+1F900 – U+1F9FF (Symboles et pictogrammes supplémentaires)
#include <cassert>
#include <format>

int main()
{
    assert(std::format("{:.^5s}",   "🐱")    == ".🐱..");
    assert(std::format("{:.5s}",    "🐱🐱🐱") == "🐱🐱");
    assert(std::format("{:.<5.5s}", "🐱🐱🐱") == "🐱🐱.");
}

L (formatage propre à la locale)

L'option L fait utiliser la forme propre à la locale. Cette option n'est valide que pour les types arithmétiques.

  • Pour les types entiers, la forme propre à la locale insère les caractères séparateurs de groupes de chiffres appropriés selon la locale du contexte.
  • Pour les types à virgule flottante, la forme propre à la locale insère les caractères séparateurs de groupes de chiffres et de séparateur décimal appropriés selon la locale du contexte.
  • Pour la représentation textuelle de bool, la forme propre à la locale utilise la chaîne appropriée, comme si elle était obtenue par std::numpunct::truename ou std::numpunct::falsename.

Type

L'option type détermine la manière dont les données doivent être présentées.

Les types de présentation de chaîne disponibles sont :

  • none, s : Copie la chaîne vers la sortie.
  • ? : Copie la chaîne échappée (voir ci-dessous) vers la sortie.

(depuis C++23)

Les types de présentation entiers disponibles pour les types entiers autres que char, wchar_t et bool sont :

  • b : Format binaire. Produit la sortie comme si l'on appelait std::to_chars(first, last, value, 2). Le préfixe de base est 0b.
  • B : identique à b, sauf que le préfixe de base est 0B.
  • c : Copie le caractère static_cast<CharT>(value) vers la sortie, où CharT est le type de caractère de la chaîne de format. Lève std::format_error si la valeur n'est pas dans l'intervalle des valeurs représentables pour CharT.
  • d : Format décimal. Produit la sortie comme si l'on appelait std::to_chars(first, last, value).
  • o : Format octal. Produit la sortie comme si l'on appelait std::to_chars(first, last, value, 8). Le préfixe de base est 0 si la valeur de l'argument correspondant est non nulle, et vide sinon.
  • x : Format hexadécimal. Produit la sortie comme si l'on appelait std::to_chars(first, last, value, 16). Le préfixe de base est 0x.
  • X : identique à x, sauf qu'il utilise des lettres majuscules pour les chiffres supérieurs à 9 et que le préfixe de base est 0X.
  • none : identique à d.

Les types de présentation disponibles de char et wchar_t sont :

  • none, c : copie le caractère vers la sortie.
  • b, B, d, o, x, X : utilise les types de présentation entiers avec la valeur static_cast<unsigned char>(value) ou static_cast<std::make_unsigned_t<wchar_t>>(value) respectivement.
  • ? : copie le caractère échappé (voir ci-dessous) vers la sortie.

(depuis C++23)

Les types de présentation disponibles de bool sont :

  • none, s : copie la représentation textuelle (true ou false, ou la forme propre à la locale) vers la sortie.
  • b, B, d, o, x, X : utilise les types de présentation entiers avec la valeur static_cast<unsigned char>(value).

Les types de présentation à virgule flottante disponibles sont :

  • a : si precision est spécifiée, produit la sortie comme par un appel à std::to_chars(first, last, value, std::chars_format::hex, precision) où precision est la précision spécifiée ; sinon, la sortie est produite comme par un appel à std::to_chars(first, last, value, std::chars_format::hex).
  • A : identique à a, sauf qu'il utilise des lettres majuscules pour les chiffres supérieurs à 9 et utilise P pour indiquer l'exposant.
  • e : produit la sortie comme par un appel à std::to_chars(first, last, value, std::chars_format::scientific, precision) où precision est la précision spécifiée, ou 6 si precision n'est pas spécifiée.
  • E : identique à e, sauf qu'il utilise E pour indiquer l'exposant.
  • f, F : produit la sortie comme par un appel à std::to_chars(first, last, value, std::chars_format::fixed, precision) où precision est la précision spécifiée, ou 6 si precision n'est pas spécifiée.
  • g : produit la sortie comme par un appel à std::to_chars(first, last, value, std::chars_format::general, precision) où precision est la précision spécifiée, ou 6 si precision n'est pas spécifiée.
  • G : identique à g, sauf qu'il utilise E pour indiquer l'exposant.
  • none : si precision est spécifiée, produit la sortie comme par un appel à std::to_chars(first, last, value, std::chars_format::general, precision) où precision est la précision spécifiée ; sinon, la sortie est produite comme par un appel à std::to_chars(first, last, value).

Pour les types de présentation en minuscules, l'infini et NaN sont formatés respectivement en inf et nan. Pour les types de présentation en majuscules, l'infini et NaN sont formatés respectivement en INF et NAN.

Les types de présentation de pointeur disponibles (également utilisés pour std::nullptr_t) sont :

  • none, p : si std::uintptr_t est définie, produit la sortie comme par un appel à std::to_chars(first, last, reinterpret_cast<std::uintptr_t>(value), 16) avec le préfixe 0x ajouté à la sortie ; sinon, la sortie est définie par l'implémentation.
  • P : identique à p, sauf qu'il utilise des lettres majuscules pour les chiffres supérieurs à 9 et que le préfixe de base est 0X.

(depuis C++26)

Formatage des caractères et chaînes échappés

Un caractère ou une chaîne peut être formaté en échappé pour le rendre plus adapté au débogage ou à la journalisation.

L'échappement s'effectue comme suit :

  • Pour chaque séquence d'unités de code bien formée qui encode un caractère C :
  • Si C est l'un des caractères du tableau suivant, la séquence d'échappement correspondante est utilisée.

Caractère | Séquence d'échappement | Notes

tabulation horizontale (octet 0x09 en encodage ASCII) | \t

saut de ligne - nouvelle ligne (octet 0x0a en encodage ASCII) | \n

retour chariot (octet 0x0d en encodage ASCII) | \r

guillemet double (octet 0x22 en encodage ASCII) | \" | Utilisé uniquement si la sortie est une chaîne entre guillemets doubles

apostrophe (octet 0x27 en encodage ASCII) | \' | Utilisé uniquement si la sortie est une chaîne entre apostrophes

barre oblique inverse (octet 0x5c en encodage ASCII) | \\

  • Sinon, si C n'est pas le caractère espace (octet 0x20 en encodage ASCII), et que

  • l'encodage de caractères associé est un encodage Unicode et

  • C correspond à une valeur scalaire Unicode dont la propriété Unicode General_Category a une valeur dans les groupes Separator (Z) ou Other (C), ou

  • C n'est pas immédiatement précédé d'un caractère non échappé, et C correspond à une valeur scalaire Unicode qui possède la propriété Unicode Grapheme_Extend=Yes, ou

  • l'encodage de caractères associé n'est pas un encodage Unicode et C est l'un des ensembles de séparateurs ou de caractères non imprimables défini par l'implémentation la séquence d'échappement est \u{hex-digit-sequence}, où hex-digit-sequence est la représentation hexadécimale la plus courte de C en utilisant des chiffres hexadécimaux en minuscules.

  • Sinon, C est copié tel quel.

  • Une séquence d'unités de code qui est une séquence de décalage a un effet non spécifié sur la sortie et sur le décodage ultérieur de la chaîne.

  • Les autres unités de code (c'est-à-dire celles des séquences d'unités de code mal formées) sont chacune remplacées par \x{hex-digit-sequence}, où hex-digit-sequence est la représentation hexadécimale la plus courte de l'unité de code en utilisant des chiffres hexadécimaux en minuscules.

La représentation échappée d'une chaîne est construite en échappant les séquences d'unités de code de la chaîne, comme décrit ci-dessus, puis en entourant le résultat de guillemets doubles.

La représentation échappée d'un caractère est construite en l'échappant comme décrit ci-dessus, puis en entourant le résultat d'apostrophes.

Démonstration sur Compiler Explorer :

#include <print>

int main()
{
    std::println("[{:?}]", "h\tllo");             // affiche : ["h\tllo"]
    std::println("[{:?}]", "Спасибо, Виктор ♥!"); // prints: ["Спасибо, Виктор ♥!"]
    std::println("[{:?}] [{:?}]", '\'', '"');     // prints: ['\'', '"']

    // Les exemples suivants supposent l'utilisation de l'encodage UTF-8
    std::println("[{:?}]", std::string("\0 \n \t \x02 \x1b", 9));
                                             // prints: ["\u{0} \n \t \u{2} \u{1b}"]
    std::println("[{:?}]", "\xc3\x28");      // UTF-8 invalide
                                             // prints: ["\x{c3}("]
    std::println("[{:?}]", "\u0301");        // prints: ["\u{301}"]
    std::println("[{:?}]", "\\\u0301");      // prints: ["\\\u{301}"]
    std::println("[{:?}]", "e\u0301\u0323"); // prints: ["ẹ́"]
}

(depuis C++23)

Notes

Dans la plupart des cas la syntaxe est similaire à l'ancien formatage %, avec l'ajout de {} et avec : utilisé à la place de %. Par exemple, "%03.2f" peut être traduit en "{:03.2f}".
