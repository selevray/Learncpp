std::exit

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <cstdlib>

void exit( int exit_code );  // (jusqu'à C++11)

[[noreturn]] void exit( int exit_code );  // (depuis C++11)

Provoque la terminaison normale du programme.

Plusieurs étapes de nettoyage sont effectuées :

  1. Les objets à durée de stockage statique sont détruits et les fonctions enregistrées par l'appel à std::atexit sont appelées :

a) Les objets non locaux à durée de stockage statique sont détruits dans l'ordre inverse de la fin de leur constructeur.

b) Les fonctions enregistrées avec std::atexit sont appelées dans l'ordre inverse de leur enregistrement, sauf qu'une fonction est appelée après toutes les fonctions enregistrées précédemment qui avaient déjà été appelées au moment de son enregistrement.

c) Pour chaque fonction f enregistrée avec std::atexit et chaque objet non local obj à durée de stockage statique,

  • si f est enregistrée avant l'initialisation de obj, f ne sera appelée qu'après la destruction de obj ;
  • si f est enregistrée après l'initialisation de obj, f ne sera appelée qu'avant la destruction de obj.

d) Pour chaque objet local obj à durée de stockage statique, obj est détruit comme si une fonction appelant le destructeur de obj avait été enregistrée avec std::atexit à la fin du constructeur de obj.

(jusqu'à C++11)

  1. Les destructeurs des objets à durée de stockage thread local associés au thread courant, les destructeurs des objets à durée de stockage statique et les fonctions enregistrées avec std::atexit sont exécutés de façon concurrente, tout en respectant les garanties suivantes :

a) Le dernier destructeur des objets thread local est séquencé avant le premier destructeur d'un objet statique.

b) Si la fin du constructeur ou de l'initialisation dynamique de l'objet thread local ou statique A est séquencée avant celle de l'objet thread local ou statique B, la fin de la destruction de B est séquencée avant le début de la destruction de A.

c) Si la fin de l'initialisation d'un objet statique A est séquencée avant l'appel à std::atexit pour une fonction F, l'appel à F pendant la terminaison est séquencé avant le début de la destruction de A.

d) Si l'appel à std::atexit pour une fonction F est séquencé avant la fin de l'initialisation d'un objet statique A, le début de la destruction de A est séquencé avant l'appel à F pendant la terminaison.

e) Si un appel à std::atexit pour une fonction F1 est séquencé avant l'appel à std::atexit pour une fonction F2, alors l'appel à F2 pendant la terminaison est séquencé avant l'appel à F1.

(depuis C++11)

  • Dans ce qui précède,
    • Si une fonction enregistrée avec atexit ou un destructeur d'objet statique/thread local lève une exception, std::terminate est appelée.
    • Si le compilateur a choisi de déplacer l'initialisation dynamique d'un objet vers la phase d'initialisation statique de l'initialisation non locale, le séquencement de la destruction respecte son initialisation dynamique théorique.
    • Si un objet statique local à un bloc (de portée de bloc) a été détruit, puis que cette fonction est appelée depuis le destructeur d'un autre objet statique et que le flot de contrôle passe par la définition de cet objet (ou s'il est utilisé indirectement, via un pointeur ou une référence), le comportement est indéfini.
    • Si un objet statique local à un bloc a été initialisé pendant la construction d'un sous-objet d'une classe ou d'un tableau, il n'est détruit qu'après la destruction de tous les sous-objets de cette classe ou de tous les éléments de ce tableau.

  1. Tous les flux C sont vidés et fermés.

  2. Les fichiers créés par std::tmpfile sont supprimés.

  3. Le contrôle est rendu à l'environnement hôte. Si exit_code vaut 0 ou EXIT_SUCCESS, un statut défini par l'implémentation indiquant une terminaison réussie est renvoyé. Si exit_code vaut EXIT_FAILURE, un statut défini par l'implémentation indiquant une terminaison non réussie est renvoyé. Dans les autres cas, une valeur de statut définie par l'implémentation est renvoyée.

La pile n'est pas déroulée : les destructeurs des variables à durée de stockage automatique ne sont pas appelés.

Relation avec la fonction main

Le retour depuis la fonction main, soit par une instruction return, soit en atteignant la fin de la fonction, effectue la terminaison normale de la fonction (appelle les destructeurs des variables à durée de stockage automatique), puis exécute std::exit, en passant l'argument de l'instruction return (ou 0 si un retour implicite a été utilisé) comme exit_code.

Paramètres

  • exit_code — statut de sortie du programme

Valeur de retour

(aucune)

Exemple

#include <cstdlib>
#include <iostream>

struct Static
{
    ~Static()
    {
        std::cout << "Static destructor\n";
    }
};

struct Local
{
    ~Local()
    {
        std::cout << "Local destructor\n";
    }
};

Static static_variable; // Le destructeur de cet objet *sera* appelé

void atexit_handler()
{
    std::cout << "atexit handler\n";
}

int main()
{
    Local local_variable; // Le destructeur de cet objet *ne sera pas* appelé
    const int result = std::atexit(atexit_handler); // Le gestionnaire sera appelé

    if (result != 0)
    {
        std::cerr << "atexit registration failed\n";
        return EXIT_FAILURE;
    }

    std::cout << "test\n";
    std::exit(EXIT_FAILURE);

    std::cout << "this line will *not* be executed\n";
}

Output:

test
atexit handler
Static destructor
