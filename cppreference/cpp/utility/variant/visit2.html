Applique le visiteur v (un Callable pouvant être appelé avec n'importe quelle combinaison de types issus de Variants) aux variants values.

Étant donné VariantBases sous la forme decltype(as-variant(std::forward<Variants>(values))... (un paquet de sizeof...(Variants) types) :

  1. Invoque v comme si cela était fait par

INVOKE(std::forward<Visitor>(v), std::get<indices>(std::forward<VariantBases>(values))...),

où indices vaut as-variant(values).index()....

  1. Invoque v comme si cela était fait par

INVOKE<R>(std::forward<Visitor>(v), std::get<indices>(std::forward<VariantBases>(values))...),

où indices vaut as-variant(values).index()....

Ces surcharges ne participent à la résolution de surcharge que si chaque type de VariantBases est un type valide. Si l'expression désignée par INVOKEou INVOKE<R> (depuis C++20) est invalide, ou si les résultats de INVOKEou INVOKE<R> (depuis C++20) ont des types ou des catégories de valeur différents selon les indices, le programme est mal formé.

3-6) Les modèles de fonction as-variant réservés à l'exposé acceptent une valeur dont le type peut être déduit pour std::variant<Ts...> (c'est-à-dire soit std::variant<Ts...>, soit un type dérivé de std::variant<Ts...>), et renvoient la valeur std::variant avec la même qualification const et la même catégorie de valeur.

3,4) Renvoie value.

5,6) Renvoie std::move(value).

Paramètres

  • v — un Callable acceptant chaque alternative possible de chaque variant de Variants
  • values — liste des variants à transmettre au visiteur

Valeur de retour

  1. Le résultat de l'opération INVOKE. Le type de retour est le type obtenu en appliquant decltype au résultat.

  2. Rien si R est (éventuellement qualifié cv) void ; sinon le résultat de l'opération INVOKE<R>.

3-6) Une valeur std::variant convertie depuis value.

Exceptions

Lève std::bad_variant_access si as-variant(value_i).valueless_by_exception() est true pour un variant value_i quelconque de values.

Complexité

Lorsque le nombre de variants est égal à zéro ou un, l'invocation de l'objet appelable est implémentée en temps constant ; c'est-à-dire qu'elle ne dépend pas du nombre de types pouvant être stockés dans le variant.

Si le nombre de variants est supérieur à un, l'invocation de l'objet appelable n'a aucune exigence de complexité.

Notes

Soit n égal à (1 * ... * std::variant_size_v<std::remove_reference_t<VariantBases>>), les implémentations génèrent généralement une table équivalente à un tableau (éventuellement multidimensionnel) de n pointeurs de fonction pour chaque spécialisation de std::visit, ce qui est similaire à l'implémentation des fonctions virtuelles.

Les implémentations peuvent aussi générer une instruction switch comportant n branches pour std::visit (par exemple, l'implémentation de la STL de MSVC utilise une instruction switch lorsque n n'est pas supérieur à 256).

Sur les implémentations usuelles, la complexité temporelle de l'invocation de v peut être considérée comme égale à celle de l'accès à un élément d'un tableau (éventuellement multidimensionnel) ou de l'exécution d'une instruction switch.

Exemple

#include <iomanip>
#include <iostream>
#include <string>
#include <type_traits>
#include <variant>
#include <vector>

// la variante à visiter
using value_t = std::variant<int, long, double, std::string>;

// type auxiliaire pour le visiteur #4
template<class... Ts>
struct overloaded : Ts... { using Ts::operator()...; };
// guide de déduction explicite (non nécessaire depuis C++20)
template<class... Ts>
overloaded(Ts...) -> overloaded<Ts...>;

int main()
{
    std::vector<value_t> vec = {10, 15l, 1.5, "hello"};

    for (auto& v: vec)
    {
        // 1. visiteur void, appelé uniquement pour ses effets de bord (ici, pour les E/S)
        std::visit([](auto&& arg){ std::cout << arg; }, v);

        // 2. visiteur renvoyant une valeur, illustre l'idiome consistant à renvoyer un autre variant
        value_t w = std::visit([](auto&& arg) -> value_t { return arg + arg; }, v);

        // 3. visiteur par correspondance de types : une lambda qui traite chaque type différemment
        std::cout << ". After doubling, variant holds ";
        std::visit([](auto&& arg)
        {
            using T = std::decay_t<decltype(arg)>;
            if constexpr (std::is_same_v<T, int>)
                std::cout << "int with value " << arg << '\n';
            else if constexpr (std::is_same_v<T, long>)
                std::cout << "long with value " << arg << '\n';
            else if constexpr (std::is_same_v<T, double>)
                std::cout << "double with value " << arg << '\n';
            else if constexpr (std::is_same_v<T, std::string>)
                std::cout << "std::string with value " << std::quoted(arg) << '\n';
            else
                static_assert(false, "non-exhaustive visitor!");
        }, w);
    }

    for (auto& v: vec)
    {
        // 4. autre visiteur par correspondance de types : une classe avec 3 operator() surchargés
        // Note : L'operator() template `(auto arg)` se liera à `int` et `long`
        //       dans ce cas, mais en son absence, l'operator() `(double arg)`
        //       *se liera aussi* à `int` et `long` car les deux sont implicitement
        //       convertibles en double. Avec cette forme, il faut veiller
        //       à ce que les conversions implicites soient gérées correctement.
        std::visit(overloaded{
            [](auto arg) { std::cout << arg << ' '; },
            [](double arg) { std::cout << std::fixed << arg << ' '; },
            [](const std::string& arg) { std::cout << std::quoted(arg) << ' '; }
        }, v);
    }
}

Output:

10. After doubling, variant holds int with value 20
15. After doubling, variant holds long with value 30
1.5. After doubling, variant holds double with value 3
hello. After doubling, variant holds std::string with value "hellohello"
10 15 1.500000 "hello"
