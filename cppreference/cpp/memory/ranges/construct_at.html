std::ranges::construct_at

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <memory>

Signature d'appel

template< class T, class... Args >
constexpr T* construct_at( T* location, Args&&... args );  // (depuis C++20)

Crée un objet T initialisé avec les arguments de args à l'adresse donnée location.

Équivalent à if constexpr (std::is_array_v<T>) return ::new (voidify ﻿(*location)) T[1](); else return ::new (voidify ﻿(*location)) T(std::forward<Args>(args)...);, sauf que construct_at peut être utilisé dans l'évaluation d'expressions constantes (jusqu'à C++26).

Lorsque construct_at est appelé dans l'évaluation d'une expression constante expr, location doit pointer soit vers un stockage obtenu par std::allocator<T>::allocate, soit vers un objet dont la durée de vie a commencé durant l'évaluation de expr.

Cette surcharge ne participe à la résolution de surcharge que si toutes les conditions suivantes sont satisfaites :

  • std::is_unbounded_array_v<T> is false.
  • ::new(std::declval<void*>()) T(std::declval<Args>()...) est bien formé lorsqu'il est traité comme une opérande non évaluée.

Si std::is_array_v<T> vaut true et que sizeof...(Args) est non nul, le programme est mal formé.

Les entités de type fonction décrites sur cette page sont des objets fonctions d'algorithme (appelés de manière informelle niebloids), c'est-à-dire :

  • Les listes d'arguments de modèle explicites ne peuvent pas être spécifiées lors de l'appel de l'un d'entre eux.
  • Aucun d'entre eux n'est visible par la recherche dépendante des arguments.
  • Lorsque l'un d'entre eux est trouvé par la recherche non qualifiée normale comme nom situé à gauche de l'opérateur d'appel de fonction, la recherche dépendante des arguments est inhibée.

Paramètres

  • location — pointeur vers le stockage non initialisé sur lequel un objet T sera construit
  • args... — arguments utilisés pour l'initialisation

Valeur de retour

location

Notes

std::ranges::construct_at se comporte exactement comme std::construct_at, sauf qu'il est invisible pour la recherche dépendante des arguments.

Exemple

#include <iostream>
#include <memory>

struct S
{
    int x;
    float y;
    double z;

    S(int x, float y, double z) : x{x}, y{y}, z{z} { std::cout << "S::S();\n"; }

    ~S() { std::cout << "S::~S();\n"; }

    void print() const
    {
        std::cout << "S { x=" << x << "; y=" << y << "; z=" << z << "; };\n";
    }
};

int main()
{
    alignas(S) unsigned char buf[sizeof(S)];

    S* ptr = std::ranges::construct_at(reinterpret_cast<S*>(buf), 42, 2.71828f, 3.1415);
    ptr->print();

    std::ranges::destroy_at(ptr);
}

Output:

S::S();
S { x=42; y=2.71828; z=3.1415; };
S::~S();
