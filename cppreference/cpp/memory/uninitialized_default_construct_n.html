std::uninitialized_default_construct_n

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <memory>

template< class NoThrowForwardIt, class Size >
NoThrowForwardIt uninitialized_default_construct_n
    ( NoThrowForwardIt first, Size count );  // (1) (depuis C++17) (constexpr depuis C++26)

template< class ExecutionPolicy, class NoThrowForwardIt, class Size >
NoThrowForwardIt uninitialized_default_construct_n
    ( ExecutionPolicy&& policy, NoThrowForwardIt first, Size count );  // (2) (depuis C++17)
  1. Construit des objets de type typename std::iterator_traits<NoThrowForwardIt>::value_type dans la zone mémoire non initialisée first+[0,count) par initialisation par défaut, comme si par

for (; count > 0; (void)++first, --count) ::new (voidify(*first)) typename std::iterator_traits<NoThrowForwardIt>::value_type; return first;

Si une exception est levée pendant l'initialisation, les objets déjà construits sont détruits dans un ordre non spécifié.

  1. Identique à (1), mais exécuté selon policy.

Cette surcharge ne participe à la résolution de surcharge que si toutes les conditions suivantes sont satisfaites :

std::is_execution_policy_v<std::decay_t<ExecutionPolicy>> is true.

(jusqu'à C++20)

std::is_execution_policy_v<std::remove_cvref_t<ExecutionPolicy>> is true.

(depuis C++20)

Paramètres

  • first — le début de l'intervalle des éléments à initialiser
  • count — le nombre d'éléments à construire
  • policy — la politique d'exécution à utiliser

Exigences sur les types

  • NoThrowForwardIt doit satisfaire aux exigences de LegacyForwardIterator.
  • Aucun incrément, affectation, comparaison ou déréférencement via des instances valides de NoThrowForwardIt ne peut lever d'exception.

Valeur de retour

Comme décrit ci-dessus.

Complexité

Linéaire en n.

Exceptions

La surcharge avec un paramètre de modèle nommé ExecutionPolicy signale les erreurs comme suit :

  • Si l'exécution d'une fonction invoquée dans le cadre de l'algorithme lève une exception et ExecutionPolicy est l'une des politiques standard, std::terminate est appelée. Pour toute autre ExecutionPolicy, le comportement est défini par l'implémentation.
  • Si l'algorithme échoue à allouer de la mémoire, std::bad_alloc est levée.

Implémentation possible

template<class NoThrowForwardIt, class Size>
constexpr ForwardIt uninitialized_default_construct_n(NoThrowForwardIt first, Size count)
{
    using T = typename std::iterator_traits<NoThrowForwardIt>::value_type;
    NoThrowForwardIt current = first;

    try
    {
        for (; countn > 0; (void) ++current, --count)
            ::new (static_cast<void*>(std::addressof(*current))) T;
        return current;
    }
    catch (...)
    {
        std::destroy(first, current);
        throw;
    }
}

Exemple

#include <cstring>
#include <iostream>
#include <memory>
#include <string>

struct S
{
    std::string m{"default value"};
};

int main()
{
    constexpr int n{3};
    alignas(alignof(S)) unsigned char mem[n * sizeof(S)];

    try
    {
        auto first{reinterpret_cast<S*>(mem)};
        auto last = std::uninitialized_default_construct_n(first, n);

        for (auto it{first}; it != last; ++it)
            std::cout << it->m << '\n';

        std::destroy(first, last);
    }
    catch(...)
    {
        std::cout << "Exception!\n";
    }

    // Pour les types scalaires, uninitialized_default_construct_n
    // ne met généralement pas à zéro la zone mémoire non initialisée donnée.
    int v[]{1, 2, 3, 4};
    const int original[]{1, 2, 3, 4};
    std::uninitialized_default_construct_n(std::begin(v), std::size(v));

    // Un accès à v pourrait être un comportement indéfini,
    // en attendant la résolution de CWG 1997 :
    // for (const int i : v)
    //     std::cout << i << ' ';

    // Le résultat n'est pas spécifié :
    std::cout << (std::memcmp(v, original, sizeof(v)) == 0 ? "un" : "") << "modified\n";
}
