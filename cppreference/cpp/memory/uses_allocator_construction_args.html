Prépare la liste d'arguments nécessaire à la création d'un objet du type donné T au moyen de la construction avec allocateur.

  1. Cette surcharge participe à la résolution de surcharge seulement si T n'est pas une spécialisation de std::pair. Renvoie std::tuple déterminé comme suit :
  • Si std::uses_allocator_v<T, Alloc> est false et std::is_constructible_v<T, Args...> est true, renvoie std::forward_as_tuple(std::forward<Args>(args)...).
  • Sinon, si std::uses_allocator_v<T, Alloc> est true et std::is_constructible_v<T, std::allocator_arg_t, const Alloc&, Args...> est true, renvoie
    std::tuple<std::allocator_arg_t, const Alloc&, Args&&...>(std::allocator_arg, alloc, std::forward<Args>(args)...).
  • Sinon, si std::uses_allocator_v<T, Alloc> est true et std::is_constructible_v<T, Args..., const Alloc&> est true, renvoie std::forward_as_tuple(std::forward<Args>(args)..., alloc).
  • Sinon, le programme est mal formé.
  1. Cette surcharge participe à la résolution de surcharge seulement si T est une spécialisation de std::pair. Pour T qui vaut std::pair<T1, T2>, équivalent à
return std::make_tuple(std::piecewise_construct,
    std::apply([&alloc](auto&&... args1)
        {
            return std::uses_allocator_construction_args<T1>(alloc,
                       std::forward<decltype(args1)>(args1)...);
        }, std::forward<Tuple1>(x)
    ),
    std::apply([&alloc](auto&&... args2)
        {
            return std::uses_allocator_construction_args<T2>(alloc,
                       std::forward<decltype(args2)>(args2)...);
        }, std::forward<Tuple2>(y)
    )
);
  1. Cette surcharge participe à la résolution de surcharge seulement si T est une spécialisation de std::pair. Équivalent à
return std::uses_allocator_construction_args<T>(alloc,
    std::piecewise_construct, std::tuple<>{}, std::tuple<>{}
);
  1. Cette surcharge participe à la résolution de surcharge seulement si T est une spécialisation de std::pair. Équivalent à
return std::uses_allocator_construction_args<T>(alloc,
    std::piecewise_construct,
    std::forward_as_tuple(std::forward<U>(u)),
    std::forward_as_tuple(std::forward<V>(v))

5,6) Cette surcharge participe à la résolution de surcharge seulement si T est une spécialisation de std::pair. Équivalent à

return std::uses_allocator_construction_args<T>(alloc,
    std::piecewise_construct,
    std::forward_as_tuple(pr.first),
    std::forward_as_tuple(pr.second)

7,8) Cette surcharge participe à la résolution de surcharge seulement si T est une spécialisation de std::pair. Équivalent à

return std::uses_allocator_construction_args<T>(alloc,
    std::piecewise_construct,
    std::forward_as_tuple(std::get<0>(std::move(pr))),
    std::forward_as_tuple(std::get<1>(std::move(pr)))
);
  1. Cette surcharge participe à la résolution de surcharge seulement si T est une spécialisation de std::pair, et étant donné le modèle de fonction à fin d'exposition
template<class A, class B>
void /*deduce-as-pair*/(const std::pair<A, B>&);

, /*deduce-as-pair*/(non_pair) est mal formé lorsqu'il est considéré comme opérande non évalué.
Soit la classe à fin d'exposition pair-constructor définie comme

class /*pair-constructor*/
{
    const Alloc& alloc_; // exposition uniquement
    NonPair&     u_;     // exposition uniquement

    constexpr reconstruct(const std::remove_cv<T>& p) const // exposition uniquement
    {
        return std::make_obj_using_allocator<std::remove_cv<T>>(alloc_, p);
    }

    constexpr reconstruct(std::remove_cv<T>&& p) const // exposition uniquement
    {
        return std::make_obj_using_allocator<std::remove_cv<T>>(alloc_, std::move(p));
    }

public:
    constexpr operator std::remove_cv<T>() const
    {
        return reconstruct(std::forward<NonPair>(u_));
    }
};

Cette surcharge équivaut à return std::make_tuple(pair_construction);, où pair_construction est une valeur de type pair-constructor dont les membres alloc_ et u_ valent respectivement alloc et non_pair.

Paramètres

  • alloc — l'allocateur à utiliser
  • args — les arguments à passer au constructeur de T
  • x — tuple des arguments à passer aux constructeurs du membre de données first de T
  • y — tuple des arguments à passer aux constructeurs du membre de données second de T
  • u — argument unique à passer au constructeur du membre de données first de T
  • v — argument unique à passer au constructeur du membre de données second de T
  • pr — une paire dont le membre de données first sera passé au constructeur du membre de données first de T, et dont le membre de données second sera passé au constructeur du membre de données second de T
  • non_pair — argument unique à convertir en std::pair pour une construction ultérieure

Valeur de retour

std::tuple d'arguments adaptés à passer au constructeur de T.

Notes

Les surcharges (2-9) assurent la propagation de l'allocateur dans std::pair, qui ne prend en charge ni la convention d'allocateur en tête ni celle en queue (contrairement, par exemple, à std::tuple, qui utilise la convention d'allocateur en tête).

Lorsqu'elle est utilisée dans la construction avec allocateur, la fonction de conversion de pair-constructor convertit d'abord l'argument fourni en std::pair, puis construit le résultat à partir de ce std::pair par construction avec allocateur.
