std::get_temporary_buffer

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <memory>

template< class T >
std::pair<T*, std::ptrdiff_t>
    get_temporary_buffer( std::ptrdiff_t count );  // (jusqu'à C++11)

template< class T >
std::pair<T*, std::ptrdiff_t>
    get_temporary_buffer( std::ptrdiff_t count ) noexcept;  // (depuis C++11) (obsolète en C++17) (supprimé en C++20)

Si count est négatif ou nul, ne fait rien.

Sinon, demande l'allocation d'un stockage contigu non initialisé pour count objets adjacents de type T. La demande n'est pas contraignante : l'implémentation peut à la place allouer le stockage pour un autre nombre (y compris zéro) d'objets adjacents de type T.

Il est défini par l'implémentation de savoir si les types à alignement excessif sont pris en charge.

(depuis C++11)

Paramètres

  • count — le nombre d'objets souhaité

Valeur de retour

Un std::pair, le membre first est un pointeur vers le début du stockage alloué et le membre second est le nombre d'objets qui tiennent dans le stockage réellement alloué.

Si count <= 0 ou le stockage alloué ne suffit pas à stocker un seul élément de type T, le membre first du résultat est un pointeur nul et le membre second vaut zéro.

Notes

Cette API a été conçue à l'origine dans l'intention de fournir une implémentation plus efficace que le générique operator new, mais aucune telle implémentation n'a été créée et l'API a été rendue obsolète puis supprimée.

Exemple

#include <algorithm>
#include <iostream>
#include <iterator>
#include <memory>
#include <string>

int main()
{
    const std::string s[] = {"string", "1", "test", "..."};
    const auto p = std::get_temporary_buffer<std::string>(4);
    // exige que p.first soit passé à return_temporary_buffer
    // (attention aux points de sortie anticipée et aux exceptions), ou mieux, utiliser :
    std::unique_ptr<std::string, void(*)(std::string*)> on_exit(p.first,
    [](std::string* p)
    {
        std::cout << "returning temporary buffer...\n";
        std::return_temporary_buffer(p);
    });

    std::copy(s, s + p.second,
              std::raw_storage_iterator<std::string*, std::string>(p.first));
    // a le même effet que : std::uninitialized_copy(s, s + p.second, p.first);
    // exige que chaque chaîne de p soit détruite individuellement
    // (attention aux points de sortie anticipée et aux exceptions)

    std::copy(p.first, p.first + p.second,
              std::ostream_iterator<std::string>{std::cout, "\n"});

    std::for_each(p.first, p.first + p.second, [](std::string& e)
    {
        e.~basic_string<char>();
    }); // identique à : std::destroy(p.first, p.first + p.second);

    // libérer manuellement la mémoire si la technique de type unique_ptr n'est pas utilisée :
    // std::return_temporary_buffer(p.first);
}

Output:

string
1
test
...
returning temporary buffer...

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 425 C++98 le comportement lorsque count <= 0 était peu clair rendu clair
LWG 2072 C++98 il n'était pas permis d'allouer une mémoire insuffisante allowed
