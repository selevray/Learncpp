Désalloue le stockage précédemment alloué par un operator new correspondant. Ces fonctions de désallocation sont appelées par les expressions delete et par les expressions new pour désallouer la mémoire après la destruction (ou l'échec de construction) d'objets à durée de stockage dynamique. Elles peuvent aussi être appelées avec la syntaxe d'appel de fonction ordinaire.

  1. Appelée par les expressions delete pour désallouer le stockage précédemment alloué pour un seul objet.

Le comportement de l'implémentation de la bibliothèque standard de cette fonction est indéfini, sauf si ptr est un pointeur nul ou un pointeur précédemment obtenu de l'implémentation de la bibliothèque standard de operator new(std::size_t) ou operator new(std::size_t, std::nothrow_t).

  1. Appelée par les expressions delete[] pour désallouer le stockage précédemment alloué pour un tableau d'objets.

Le comportement de l'implémentation de la bibliothèque standard de cette fonction est indéfini, sauf si ptr est un pointeur nul ou un pointeur précédemment obtenu de l'implémentation de la bibliothèque standard de operator new[](std::size_t) ou operator new[](std::size_t, std::nothrow_t).

3,4) Identique à (1,2), sauf qu'elle est appelée si l'exigence d'alignement dépasse __STDCPP_DEFAULT_NEW_ALIGNMENT__.

5,6) Appelée à la place de (1,2) si un remplacement défini par l'utilisateur est fourni, sauf qu'il n'est pas spécifié si (1,2) ou (5,6) est appelée lors de la suppression d'objets de type incomplet ou de tableaux de types classes non-classes et trivialement destructibles. Un allocateur mémoire peut utiliser la taille donnée pour être plus efficace.

Les implémentations de la bibliothèque standard sont identiques à (1,2).

7,8) Identique à (5,6), sauf qu'elle est appelée si l'exigence d'alignement dépasse __STDCPP_DEFAULT_NEW_ALIGNMENT__.

  1. Appelée par les expressions new non lançantes pour un seul objet si un constructeur de l'objet lève une exception.

L'implémentation de la bibliothèque standard se comporte de la même manière que (1).

  1. Appelée par les expressions new[] non lançantes pour tableaux si un constructeur de l'un des objets lève une exception (après exécution des destructeurs de tous les objets du tableau qui ont été construits avec succès).

L'implémentation de la bibliothèque standard se comporte de la même manière que (2).

11,12) Identique à (9,10), sauf qu'elle est appelée si l'exigence d'alignement dépasse __STDCPP_DEFAULT_NEW_ALIGNMENT__.

  1. Appelée par l'expression placement new standard pour un seul objet si le constructeur de l'objet lève une exception.

L'implémentation de la bibliothèque standard de cette fonction ne fait rien.

  1. Appelée par la forme tableau standard de l'expression placement new[] si l'un des constructeurs des objets lève une exception (après exécution des destructeurs de tous les objets construits avec succès).

L'implémentation de la bibliothèque standard de cette fonction ne fait rien.

  1. Si elle est définie, appelée par l'expression placement new personnalisée pour un seul objet, avec la signature correspondante, si le constructeur de l'objet lève une exception.

  1. Si elle est définie, appelée par la forme tableau personnalisée de l'expression placement new[] avec la signature correspondante si l'un des constructeurs des objets lève une exception (après exécution des destructeurs de tous les objets construits avec succès).

Si une version spécifique à la classe (26) est définie, elle est appelée de préférence à (10).

Voir expression delete pour les règles exactes de résolution de surcharge entre les surcharges conscientes de l'alignement et celles qui ne le sont pas, pour les fonctions de désallocation usuelles (non placement).

(depuis C++17)

Dans tous les cas, si ptr est un pointeur nul, les fonctions de désallocation de la bibliothèque standard ne font rien. Si le pointeur passé à la fonction de désallocation de la bibliothèque standard n'a pas été obtenu de la fonction d'allocation correspondante de la bibliothèque standard, le comportement est indéfini.

Une fois que la fonction de désallocation de la bibliothèque standard a retourné, tous les pointeurs référençant une partie du stockage désalloué deviennent invalides.

Déréférencer un pointeur devenu invalide de cette manière et le passer à une fonction de désallocation (double suppression) est un comportement indéfini. Tout autre usage est défini par l'implémentation.

Paramètres

  • ptr — pointeur vers un bloc mémoire à désallouer, ou pointeur nul
  • sz — la taille passée à la fonction d'allocation correspondante
  • place — pointeur utilisé comme paramètre de placement dans le placement new correspondant
  • tag — étiquette de désambiguïsation de surcharge correspondant à l'étiquette utilisée par le operator new non lançant
  • al — alignement de l'objet ou de l'élément de tableau alloué
  • args — paramètres arbitraires correspondant à une fonction d'allocation placement (peuvent inclure std::size_t et std::align_val_t)

Valeur de retour

(aucune)

Exceptions

Toutes les fonctions de désallocation sont noexcept(true), sauf indication contraire dans la déclaration.

(depuis C++11)

Si une fonction de désallocation se termine en levant une exception, le comportement est indéfini, même si elle est déclarée avec noexcept(false) (depuis C++11).

Remplacements globaux

Les fonctions de désallocation remplaçables (1-12) sont implicitement déclarées dans chaque unité de traduction, même si l'en-tête <new> n'est pas inclus. Ces fonctions sont remplaçables : une fonction non membre fournie par l'utilisateur avec la même signature, définie n'importe où dans le programme, dans n'importe quel fichier source, remplace la version implicite correspondante pour l'ensemble du programme. Sa déclaration n'a pas besoin d'être visible.

Le programme est mal formé, aucun diagnostic requis, si plus d'un remplacement est fourni dans le programme ou si un remplacement est déclaré avec le spécificateur inline. Le programme est mal formé si un remplacement est défini dans un espace de noms autre que l'espace de noms global, ou s'il est défini comme fonction non membre statique à portée globale.

Les implémentations de la bibliothèque standard des versions nothrow (9,10) appellent directement les versions lançantes correspondantes (1,2). Les implémentations de la bibliothèque standard des fonctions de désallocation conscientes de la taille (5-8) appellent directement les fonctions de désallocation non conscientes de la taille correspondantes (1-4). Les implémentations de la bibliothèque standard des formes tableau lançantes non conscientes de la taille (2,4) appellent directement les formes objet unique correspondantes (1,3). Ainsi, remplacer les fonctions de désallocation lançantes d'objet unique (1,3) suffit à gérer toutes les désallocations.

Remplacement global des operators new/delete :

#include <cstdio>
#include <cstdlib>
#include <new>

// pas de inline, requis par [replacement.functions]/3
void* operator new(std::size_t sz)
{
    std::printf("1) new(size_t), size = %zu\n", sz);
    if (sz == 0)
        ++sz; // éviter std::malloc(0) qui peut renvoyer nullptr en cas de succès

    if (void *ptr = std::malloc(sz))
        return ptr;

    throw std::bad_alloc{}; // requis par [new.delete.single]/3
}

// pas de inline, requis par [replacement.functions]/3
void* operator new[](std::size_t sz)
{
    std::printf("2) new[](size_t), size = %zu\n", sz);
    if (sz == 0)
        ++sz; // éviter std::malloc(0) qui peut renvoyer nullptr en cas de succès

    if (void *ptr = std::malloc(sz))
        return ptr;

    throw std::bad_alloc{}; // requis par [new.delete.single]/3
}

void operator delete(void* ptr) noexcept
{
    std::puts("3) delete(void*)");
    std::free(ptr);
}

void operator delete(void* ptr, std::size_t size) noexcept
{
    std::printf("4) delete(void*, size_t), size = %zu\n", size);
    std::free(ptr);
}

void operator delete[](void* ptr) noexcept
{
    std::puts("5) delete[](void* ptr)");
    std::free(ptr);
}

void operator delete[](void* ptr, std::size_t size) noexcept
{
    std::printf("6) delete[](void*, size_t), size = %zu\n", size);
    std::free(ptr);
}

int main()
{
    int* p1 = new int;
    delete p1;

    int* p2 = new int[10]; // appel garanti du remplacement en C++11
    delete[] p2;
}

Les surcharges de operator delete et operator delete[] avec des paramètres supplémentaires définis par l'utilisateur (« formes placement », (15,16)) peuvent être déclarées à portée globale comme d'habitude, et sont appelées par les formes placement correspondantes des expressions new si un constructeur de l'objet en cours d'allocation lève une exception.

Les formes placement de la bibliothèque standard de operator delete (13,14) ne peuvent pas être remplacées et ne peuvent être personnalisées que si l'expression new placement n'a pas utilisé la syntaxe ::new, en fournissant une fonction delete placement spécifique à la classe (25,26) avec la signature correspondante : void T::operator delete(void*, void*) ou void T::operator delete[](void*, void*).

Surcharges spécifiques à la classe

Les fonctions de désallocation (17-24) peuvent être définies comme fonctions membres statiques d'une classe. Ces fonctions de désallocation, si elles sont fournies, sont appelées par les expressions delete lors de la destruction d'objets (17,19,21) et de tableaux (18,20,22) de cette classe, sauf si l'expression delete utilise la forme ::delete qui contourne la recherche au niveau de la portée de la classe. Le mot-clé static est facultatif pour ces déclarations de fonctions : que ce mot-clé soit utilisé ou non, la fonction de désallocation est toujours une fonction membre statique.

L'expression delete recherche le nom de la fonction de désallocation appropriée à partir de la portée de la classe (la forme tableau recherche dans la portée de la classe de l'élément du tableau) et passe à la portée globale si aucun membre n'est trouvé, comme d'habitude. Notez que, selon les règles de recherche de noms, toute fonction de désallocation déclarée dans la portée de la classe masque toutes les fonctions de désallocation globales.

Si le type statique de l'objet détruit diffère de son type dynamique (par exemple lors de la destruction d'un objet polymorphe via un pointeur vers la classe de base), et si le destructeur du type statique est virtuel, la forme à objet unique de delete commence la recherche du nom de la fonction de désallocation à partir du point de définition du substitut final de son destructeur virtuel. Quelle que soit la fonction de désallocation qui serait exécutée à l'exécution, la version statiquement visible de operator delete doit être accessible pour que le code compile. Dans les autres cas, lors de la destruction d'un tableau via un pointeur vers la classe de base, ou lors de la destruction via un pointeur vers la classe de base dont le destructeur n'est pas virtuel, le comportement est indéfini.

Si la surcharge à un seul argument (17,18) n'est pas fournie, mais que la surcharge tenant compte de la taille, prenant std::size_t comme second paramètre (21,22), est fournie, la forme tenant compte de la taille est appelée pour la désallocation normale, et le runtime C++ passe la taille de l'objet à désallouer comme second argument. Si les deux formes sont définies, la version ne tenant pas compte de la taille est appelée.

#include <cstddef>
#include <iostream>

// fonctions de désallocation spécifiques à la classe tenant compte de la taille
struct X
{
    static void operator delete(void* ptr, std::size_t sz)
    {
        std::cout << "custom delete for size " << sz << '\n';
        ::operator delete(ptr);
    }

    static void operator delete[](void* ptr, std::size_t sz)
    {
        std::cout << "custom delete for size " << sz << '\n';
        ::operator delete[](ptr);
    }
};

int main()
{
    X* p1 = new X;
    delete p1;

    X* p2 = new X[10];
    delete[] p2;
}

Des surcharges de operator delete et operator delete[] avec des paramètres supplémentaires définis par l'utilisateur ("formes de placement", (25,26)) peuvent également être définies comme membres de classe. Lorsque l'expression placement new échouée recherche la fonction placement delete correspondante à appeler, la recherche commence au niveau de la portée de la classe avant d'examiner la portée globale, et recherche la fonction dont la signature correspond au placement new :

#include <cstddef>
#include <iostream>
#include <stdexcept>

struct X
{
    X() { throw std::runtime_error("X(): std::runtime_error"); }

    // placement new personnalisé
    static void* operator new(std::size_t sz, bool b)
    {
        std::cout << "custom placement new called, b = " << b << '\n';
        return ::operator new(sz);
    }

    // placement delete personnalisé
    static void operator delete(void* ptr, bool b)
    {
        std::cout << "custom placement delete called, b = " << b << '\n';
        ::operator delete(ptr);
    }
};

int main()
{
    try
    {
        [[maybe_unused]] X* p1 = new (true) X;
    }
    catch (const std::exception& ex)
    {
        std::cout << ex.what() << '\n';
    }
}

Output:

custom placement new called, b = 1
custom placement delete called, b = 1
X(): std::runtime_error

Si operator delete au niveau de la classe est un modèle de fonction, il doit avoir le type de retour void, le premier argument void*, et il doit avoir deux paramètres ou plus. En d'autres termes, seules les formes de placement peuvent être des modèles. Une instance de modèle n'est jamais une fonction de désallocation usuelle, quelle que soit sa signature. La spécialisation du modèle operator delete est choisie par déduction d'arguments de modèle.

Notes

L'appel de T::operator delete propre à la classe sur une classe polymorphe est le seul cas où une fonction membre statique est appelée par liaison dynamique.

Si le comportement d'une fonction de désallocation ne satisfait pas les contraintes par défaut, le comportement est indéfini.

Les fonctions suivantes doivent être thread-safe :

  • Les versions de la bibliothèque de operator new et de operator delete
  • Les versions de remplacement définies par l'utilisateur des operator new et operator delete globales
  • std::calloc, std::malloc, std::realloc, std::aligned_alloc (depuis C++17), std::free

Les appels à ces fonctions qui allouent ou libèrent une unité de stockage donnée se produisent selon un ordre total unique, et chaque appel de désallocation happens-before l'allocation suivante (le cas échéant) dans cet ordre.
