Tentent d'allouer le nombre d'octets demandé, et la demande d'allocation peut échouer (même si le nombre d'octets demandé est zéro). Ces fonctions d'allocation sont appelées par les expressions new pour allouer la mémoire dans laquelle le nouvel objet sera ensuite initialisé. Elles peuvent aussi être appelées avec la syntaxe habituelle d'appel de fonction.

  1. Appelée par new pour allouer le stockage requis pour un seul objet.

L'implémentation de la bibliothèque standard alloue count octets depuis le magasin libre.

En cas d'échec, l'implémentation de la bibliothèque standard appelle le pointeur de fonction renvoyé par std::get_new_handler et répète les tentatives d'allocation jusqu'à ce que le nouveau gestionnaire ne retourne pas ou devienne un pointeur nul, moment auquel elle lève std::bad_alloc.

Cette fonction doit renvoyer un pointeur convenablement aligné pour pointer vers un objet de la taille demandée.

  1. Appelée par new[] pour allouer tout le stockage requis pour un tableau (y compris le surcoût éventuel de l'expression new).

L'implémentation de la bibliothèque standard appelle la version (1).

  1. Appelée par new pour allouer le stockage requis pour un seul objet dont l'exigence d'alignement dépasse __STDCPP_DEFAULT_NEW_ALIGNMENT__.

  2. Appelée par new[] pour allouer tout le stockage requis pour un tableau d'objets dont l'exigence d'alignement dépasse __STDCPP_DEFAULT_NEW_ALIGNMENT__.

  3. Appelée par le new sans exception.

Paramètres

  • count — nombre d'octets à allouer
  • ptr — pointeur vers une zone mémoire où initialiser l'objet
  • tag — étiquette de désambiguïsation utilisée pour sélectionner les surcharges sans exception
  • al — alignement à utiliser, une valeur invalide entraîne un comportement indéfini

Valeur de retour

1-4) En cas de succès de l'allocation, un pointeur non nul p0 qui pointe vers une mémoire convenablement alignée d'une taille d'au moins size et différent de toute valeur précédemment renvoyée p1, sauf si cette valeur p1 a ensuite été passée à une fonction de désallocation remplaçable ; en cas d'échec de l'allocation, elle ne retourne pas (une exception est levée, voir ci-dessous).

5-8) Identique à (1-4), mais renvoie un pointeur nul si l'allocation échoue.

9,10) ptr

11-22) Identique à (1-4) si la fonction ne retourne pas en cas d'échec d'allocation, sinon identique à (5-8).

Exceptions

1-4) Lève une exception d'un type qui correspondrait à un gestionnaire de type std::bad_alloc en cas d'échec d'allocation de mémoire.

11-22) Identique à (1-4) si la fonction ne retourne pas en cas d'échec d'allocation, sinon identique à (5-8).

Remplacements globaux

Les versions (1-4) sont implicitement déclarées dans chaque unité de traduction même si l'en-tête <new> n'est pas inclus. Les versions (1-8) sont remplaçables : une fonction non membre fournie par l'utilisateur, de même signature et définie n'importe où dans le programme, dans n'importe quel fichier source, remplace la version par défaut. Sa déclaration n'a pas besoin d'être visible.

Le programme est mal formé, aucun diagnostic requis, si plus d'un remplacement est fourni dans le programme pour l'une quelconque des fonctions d'allocation remplaçables, ou si un remplacement est déclaré avec le spécificateur inline. Le programme est mal formé si un remplacement est défini dans un espace de noms autre que l'espace de noms global, ou s'il est défini comme fonction non membre statique à portée globale.

Les implémentations de la bibliothèque standard des versions nothrow (5-8) appellent directement les versions levant une exception correspondantes (1-4). L'implémentation de la bibliothèque standard des versions tableau levant une exception (2,4) appelle directement la version pour objet unique correspondante (1,3). Ainsi, remplacer les fonctions d'allocation d'objet unique levant une exception suffit à gérer toutes les allocations.

Sur les implémentations autonomes, il est défini par l'implémentation si les versions par défaut de (1-8) satisfont les comportements requis ci-dessus. Il est recommandé aux implémentations autonomes que, si l'une de ces versions par défaut satisfait les exigences d'une implémentation hébergée, elles le fassent toutes.

(depuis C++26)

Remplacement global des operators new/delete :

#include <cstdio>
#include <cstdlib>
#include <new>

// pas de inline, requis par [replacement.functions]/3
void* operator new(std::size_t sz)
{
    std::printf("1) new(size_t), size = %zu\n", sz);
    if (sz == 0)
        ++sz; // éviter std::malloc(0) qui peut renvoyer nullptr en cas de succès

    if (void *ptr = std::malloc(sz))
        return ptr;

    throw std::bad_alloc{}; // requis par [new.delete.single]/3
}

// pas de inline, requis par [replacement.functions]/3
void* operator new[](std::size_t sz)
{
    std::printf("2) new[](size_t), size = %zu\n", sz);
    if (sz == 0)
        ++sz; // éviter std::malloc(0) qui peut renvoyer nullptr en cas de succès

    if (void *ptr = std::malloc(sz))
        return ptr;

    throw std::bad_alloc{}; // requis par [new.delete.single]/3
}

void operator delete(void* ptr) noexcept
{
    std::puts("3) delete(void*)");
    std::free(ptr);
}

void operator delete(void* ptr, std::size_t size) noexcept
{
    std::printf("4) delete(void*, size_t), size = %zu\n", size);
    std::free(ptr);
}

void operator delete[](void* ptr) noexcept
{
    std::puts("5) delete[](void* ptr)");
    std::free(ptr);
}

void operator delete[](void* ptr, std::size_t size) noexcept
{
    std::printf("6) delete[](void*, size_t), size = %zu\n", size);
    std::free(ptr);
}

int main()
{
    int* p1 = new int;
    delete p1;

    int* p2 = new int[10]; // appel garanti du remplacement en C++11
    delete[] p2;
}

Les surcharges de operator new et operator new[] avec des paramètres supplémentaires définis par l'utilisateur (« formes de placement », versions (11-14)) peuvent être déclarées à portée globale comme d'habitude, et sont appelées par les formes de placement correspondantes des expressions new.

Les formes de placement sans allocation de la bibliothèque standard de operator new (9,10) ne peuvent pas être remplacées et ne peuvent être personnalisées que si l'expression de placement new n'a pas utilisé la syntaxe ::new, en fournissant une new (19,20) de placement spécifique à la classe avec une signature correspondante : void* T::operator new(std::size_t, void*) ou void* T::operator new[](std::size_t, void*).

La forme de placement void* operator new(std::size_t, std::size_t) n'est pas autorisée car la signature correspondante de la fonction de désallocation, void operator delete(void*, std::size_t), est une fonction de désallocation usuelle (et non de placement).

(depuis C++14)

Surcharges spécifiques à la classe

Les fonctions d'allocation pour objet unique et pour tableau peuvent toutes deux être définies comme fonctions membres statiques publiques d'une classe (versions (15-18)). Si elles sont définies, ces fonctions d'allocation sont appelées par les expressions new pour allouer de la mémoire pour des objets uniques et des tableaux de cette classe, sauf si l'expression new utilise la forme ::new qui contourne la recherche en portée de classe. Le mot-clé static est facultatif pour ces fonctions : qu'il soit utilisé ou non, la fonction d'allocation est une fonction membre statique.

L'expression new recherche d'abord le nom de la fonction d'allocation appropriée dans la portée de la classe, puis dans la portée globale. Notez que, selon les règles de recherche de noms, toute fonction d'allocation déclarée dans la portée de la classe masque toutes les fonctions d'allocation globales pour les expressions new qui tentent d'allouer des objets de cette classe.

Lors de l'allocation d'objets et de tableaux d'objets dont l'alignement dépasse __STDCPP_DEFAULT_NEW_ALIGNMENT__, la résolution de surcharge est effectuée deux fois : d'abord pour les signatures de fonctions sensibles à l'alignement, puis pour les signatures de fonctions insensibles à l'alignement. Cela signifie que si une classe à alignement étendu possède une fonction d'allocation spécifique à la classe insensible à l'alignement, c'est elle qui sera appelée, et non la fonction d'allocation globale sensible à l'alignement. C'est intentionnel : le membre de la classe est censé savoir mieux que quiconque comment gérer cette classe.

(depuis C++17)

Lors de l'allocation d'objets et de tableaux d'objets dont l'alignement ne dépasse pas __STDCPP_DEFAULT_NEW_ALIGNMENT__, la résolution de surcharge est effectuée deux fois : d'abord pour les signatures de fonctions insensibles à l'alignement, puis pour les signatures de fonctions sensibles à l'alignement.

(depuis C++20)

#include <cstddef>
#include <iostream>

// fonctions d'allocation spécifiques à la classe
struct X
{
    static void* operator new(std::size_t count)
    {
        std::cout << "custom new for size " << count << '\n';
        return ::operator new(count);
    }

    static void* operator new[](std::size_t count)
    {
        std::cout << "custom new[] for size " << count << '\n';
        return ::operator new[](count);
    }
};

int main()
{
    X* p1 = new X;
    delete p1;
    X* p2 = new X[10];
    delete[] p2;
}

Sortie possible :

custom new for size 1
custom new[] for size 10

Les surcharges de operator new et operator new[] avec des paramètres supplémentaires définis par l'utilisateur (« formes de placement »), peuvent aussi être définies comme membres de classe (19-22)). Lorsque l'expression de placement new avec la signature correspondante recherche la fonction d'allocation correspondante à appeler, la recherche commence dans la portée de la classe avant d'examiner la portée globale, et si la new de placement spécifique à la classe est fournie, elle est appelée.

Lors de l'allocation d'objets et de tableaux d'objets dont l'alignement dépasse __STDCPP_DEFAULT_NEW_ALIGNMENT__, la résolution de surcharge pour les formes de placement est effectuée deux fois, exactement comme pour les formes ordinaires : d'abord pour les signatures sensibles à l'alignement, puis pour les signatures insensibles à l'alignement.

(depuis C++17)

Lors de l'allocation d'objets et de tableaux d'objets dont l'alignement ne dépasse pas __STDCPP_DEFAULT_NEW_ALIGNMENT__, la résolution de surcharge pour les formes de placement est effectuée deux fois, exactement comme pour les formes ordinaires : d'abord pour les signatures insensibles à l'alignement, puis pour les signatures sensibles à l'alignement.

(depuis C++20)

#include <cstddef>
#include <iostream>
#include <stdexcept>

struct X
{
    X() { throw std::runtime_error(""); }

    // placement new personnalisé
    static void* operator new(std::size_t count, bool b)
    {
        std::cout << "custom placement new called, b = " << b << '\n';
        return ::operator new(count);
    }

    // placement delete personnalisé
    static void operator delete(void* ptr, bool b)
    {
        std::cout << "custom placement delete called, b = " << b << '\n';
        ::operator delete(ptr);
    }
};

int main()
{
    try
    {
        [[maybe_unused]] X* p1 = new (true) X;
    }
    catch (const std::exception&)
    {}
}

Output:

custom placement new called, b = 1
custom placement delete called, b = 1

Si la operator new au niveau de la classe est un modèle de fonction, elle doit avoir pour type de retour void*, pour premier argument std::size_t, et elle doit avoir deux paramètres ou plus. En d'autres termes, seules les formes de placement peuvent être des modèles.

Notes

Même si le placement new (9,10) sans allocation ne peut pas être remplacé, une fonction de même signature peut être définie à portée de classe comme décrit ci-dessus. De plus, les surcharges globales qui ressemblent à un placement new mais prennent un type de pointeur non void comme second argument sont autorisées ; ainsi, le code qui veut garantir que le véritable placement new est appelé (par exemple std::allocator::construct) doit utiliser ::new et aussi convertir le pointeur en void*.

Si le comportement d'une fonction de désallocation ne satisfait pas les contraintes par défaut, le comportement est indéfini.

Les fonctions suivantes doivent être thread-safe :

  • Les versions de la bibliothèque de operator new et de operator delete
  • Les versions de remplacement définies par l'utilisateur des operator new et operator delete globales
  • std::calloc, std::malloc, std::realloc, std::aligned_alloc (depuis C++17), std::free

Les appels à ces fonctions qui allouent ou libèrent une unité de stockage donnée se produisent selon un ordre total unique, et chaque appel de désallocation happens-before l'allocation suivante (le cas échéant) dans cet ordre.

(depuis C++11)

Il n'est pas spécifié si les versions de bibliothèque de operator new effectuent des appels à std::mallocou std::aligned_alloc (depuis C++17).

Pour charger un gros fichier, le mappage de fichier via des fonctions propres au système d'exploitation, par exemple mmap sous POSIX ou CreateFileMapping(A/W) avec MapViewOfFile sous Windows, est préférable à l'allocation d'un tampon pour la lecture du fichier.
