std::scoped_allocator_adaptor

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <scoped_allocator>

template< class OuterAlloc, class... InnerAllocs >
class scoped_allocator_adaptor
    : public OuterAlloc;  // (depuis C++11)

Le modèle de classe std::scoped_allocator_adaptor est un allocateur pouvant être utilisé avec des conteneurs multiniveaux (vector de set de list de tuple de map, etc.). Il est instancié avec un type d'allocateur externe OuterAlloc et zéro ou plusieurs types d'allocateurs internes InnerAlloc.... Un conteneur construit directement avec un scoped_allocator_adaptor utilise OuterAlloc pour allouer ses éléments, mais si un élément est lui-même un conteneur, il utilise le premier allocateur interne. Les éléments de ce conteneur, s'ils sont eux-mêmes des conteneurs, utilisent le deuxième allocateur interne, etc. S'il y a plus de niveaux de conteneurs que d'allocateurs internes, le dernier allocateur interne est réutilisé pour tous les conteneurs imbriqués suivants.

Le but de cet adaptateur est d'initialiser correctement les allocateurs à état dans les conteneurs imbriqués, par exemple lorsque tous les niveaux d'un conteneur imbriqué doivent être placés dans le même segment de mémoire partagée. Le constructeur de l'adaptateur prend les arguments de tous les allocateurs de la liste, et chaque conteneur imbriqué obtient l'état de son allocateur auprès de l'adaptateur selon les besoins.

Pour les besoins de scoped_allocator_adaptor, si l'allocateur interne suivant est A, toute classe T pour laquelle std::uses_allocator<T,A>::value == true participe à la récursion comme s'il s'agissait d'un conteneur. De plus, std::pair est traité comme un tel conteneur par des surcharges spécifiques de scoped_allocator_adaptor::construct.

Une implémentation typique détient une instance de std::scoped_allocator_adaptor<InnerAllocs...> en tant qu'objet membre.

Notez que les std::pmr::polymorphic_allocators se propagent aux conteneurs imbriqués à la suite de uses-allocator construction et n'ont pas besoin de (et ne fonctionnent pas avec) std::scoped_allocator_adaptor.

Exemple

#include <boost/interprocess/allocators/adaptive_pool.hpp>
#include <boost/interprocess/managed_shared_memory.hpp>
#include <scoped_allocator>
#include <vector>

namespace bi = boost::interprocess;

template<class T>
using alloc = bi::adaptive_pool<T, bi::managed_shared_memory::segment_manager>;

using ipc_row = std::vector<int, alloc<int>>;

using ipc_matrix = std::vector<ipc_row, std::scoped_allocator_adaptor<alloc<ipc_row>>>;

int main()
{
    bi::managed_shared_memory s(bi::create_only, "Demo", 65536);

    // créer un vector de vectors en mémoire partagée
    ipc_matrix v(s.get_segment_manager());

    // pour tous ces ajouts, les vectors internes obtiennent leurs arguments d'allocateur
    // à partir du scoped_allocator_adaptor du vector externe
    v.resize(1);
    v[0].push_back(1);
    v.emplace_back(2);
    std::vector<int> local_row = {1, 2, 3};
    v.emplace_back(local_row.begin(), local_row.end());

    bi::shared_memory_object::remove("Demo");
}
