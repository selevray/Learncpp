std::aligned_alloc

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <cstdlib>

void* aligned_alloc( std::size_t alignment, std::size_t size );  // (depuis C++17)

Alloue size octets de stockage non initialisé dont l'alignement est spécifié par alignment (création implicite d'objets dans la zone de destination). Le paramètre size doit être un multiple entier de alignment.

Les fonctions suivantes doivent être thread-safe :

  • Les versions de la bibliothèque de operator new et de operator delete
  • Les versions de remplacement définies par l'utilisateur des operator new et operator delete globales
  • std::calloc, std::malloc, std::realloc, std::aligned_alloc, std::free

Les appels à ces fonctions qui allouent ou libèrent une unité de stockage donnée se produisent selon un ordre total unique, et chaque appel de désallocation happens-before l'allocation suivante (le cas échéant) dans cet ordre.

Paramètres

  • alignment — spécifie l'alignement. Doit être un alignement valide pris en charge par l'implémentation.
  • size — nombre d'octets à allouer. Un multiple entier de alignment.

Valeur de retour

En cas de succès, retourne le pointeur vers le début de la mémoire nouvellement allouée. Pour éviter une fuite mémoire, le pointeur retourné doit être libéré avec std::free ou std::realloc.

En cas d'échec, retourne un pointeur nul.

Notes

Passer un size qui n'est pas un multiple entier de alignment ou un alignment qui n'est pas valide ou non pris en charge par l'implémentation fait échouer la fonction, qui renvoie un pointeur nul (en C11, tel que publié, cela spécifiait un comportement indéfini dans ce cas ; cela a été corrigé par DR460).

À titre d'exemple de l'exigence « pris en charge par l'implémentation », la fonction POSIX posix_memalign accepte tout alignment qui est une puissance de deux et un multiple de sizeof(void*), et les implémentations basées sur POSIX de aligned_alloc héritent de cette exigence.

Les alignements fondamentaux sont toujours pris en charge. Si alignment est une puissance de deux et n'est pas supérieur à alignof(std::max_align_t), aligned_alloc peut simplement appeler std::malloc.

std::malloc ordinaire aligne la mémoire adaptée à tout type d'objet ayant un alignement fondamental. Cette fonction est utile pour les allocations sur-alignées, comme celles alignées sur les frontières de SSE, de ligne de cache ou de page mémoire virtuelle.

Cette fonction n'est pas prise en charge dans la bibliothèque Runtime C de Microsoft, car son implémentation de std::free est incapable de gérer les allocations alignées, quelles qu'elles soient. À la place, MS CRT fournit _aligned_malloc (à libérer avec _aligned_free).

Exemple

#include <cstdio>
#include <cstdlib>

int main()
{
    int* p1 = static_cast<int*>(std::malloc(10 * sizeof *p1));
    std::printf("default-aligned address:   %p\n", static_cast<void*>(p1));
    std::free(p1);

    int* p2 = static_cast<int*>(std::aligned_alloc(1024, 1024));
    std::printf("1024-byte aligned address: %p\n", static_cast<void*>(p2));
    std::free(p2);
}

Sortie possible :

default-aligned address:   0x2221c20
1024-byte aligned address: 0x2222400
