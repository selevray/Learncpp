std::unique_ptr<T,Deleter>::operator=

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

unique_ptr& operator=( unique_ptr&& r ) noexcept;  // (1) (constexpr depuis C++23)

template< class U, class E >
unique_ptr& operator=( unique_ptr<U, E>&& r ) noexcept;  // (2) (constexpr depuis C++23)

unique_ptr& operator=( std::nullptr_t ) noexcept;  // (3) (constexpr depuis C++23)

unique_ptr& operator=( const unique_ptr& ) = delete;  // (4)
  1. Opérateur d'affectation par déplacement. Transfère la propriété de r vers *this comme si l'on appelait reset(r.release()) puis affectait get_deleter() à partir de std::forward<Deleter>(r.get_deleter()).

Cette surcharge ne participe à la résolution de surcharge que si std::is_move_assignable<Deleter>::value est true.

Si Deleter n'est pas un type référence, le comportement est indéfini si

  • Deleter n'est pas MoveAssignable, ou
  • l'affectation de get_deleter() à partir d'une rvalue de type Deleter lèverait une exception.

Sinon (Deleter est un type référence), le comportement est indéfini si

  • std::remove_reference<Deleter>::type n'est pas CopyAssignable, ou
  • l'affectation de get_deleter() à partir d'une lvalue de type Deleter lèverait une exception.
  1. Opérateur d'affectation de conversion. Transfère la propriété de r vers *this comme si l'on appelait reset(r.release()) puis affectait get_deleter() à partir de std::forward<E>(r.get_deleter()).

Cette surcharge ne participe à la résolution de surcharge que si toutes les conditions suivantes sont satisfaites :

  • std::is_assignable<Deleter&, E&&>::value is true.
  • Pour le modèle primaire, toutes les conditions suivantes sont satisfaites :
    • U n'est pas un type tableau.
    • unique_ptr<U, E>::pointer est implicitement convertible en pointer, et.
  • Pour la spécialisation pour tableaux (unique_ptr<T[]>), toutes les conditions suivantes sont satisfaites :
    • U est un type tableau.
    • pointer est le même type que element_type*.
    • unique_ptr<U, E>::pointer est le même type que unique_ptr<U, E>::element_type*.
    • unique_ptr<U, E>::element_type(*)[] est convertible en element_type(*)[].

Si E n'est pas un type référence, le comportement est indéfini si l'affectation de get_deleter() à partir d'une rvalue de type E est mal formée ou lèverait une exception.

Sinon (E est un type référence), le comportement est indéfini si l'affectation de get_deleter() à partir d'une lvalue de type E est mal formée ou lèverait une exception.

  1. Équivalent à l'appel de reset().

  2. L'opérateur d'affectation par copie est explicitement supprimé.

Paramètres

  • r — pointeur intelligent dont la propriété sera transférée

Valeur de retour

*this

Notes

En tant que type non copiable, l'opérateur d'affectation de unique_ptr n'accepte que des arguments rvalues (par exemple le résultat de std::make_unique ou une variable unique_ptr convertie avec std::move).

Exemple

#include <iostream>
#include <memory>

struct Foo
{
    int id;
    Foo(int id) : id(id) { std::cout << "Foo " << id << '\n'; }
    ~Foo() { std::cout << "~Foo " << id << '\n'; }
};

int main()
{
    std::unique_ptr<Foo> p1(std::make_unique<Foo>(1));

    {
        std::cout << "Creating new Foo...\n";
        std::unique_ptr<Foo> p2(std::make_unique<Foo>(2));
        // p1 = p2; // Erreur ! impossible de copier unique_ptr
        p1 = std::move(p2);
        std::cout << "About to leave inner block...\n";

        // L'instance Foo continuera d'exister,
        // bien que p2 sorte de sa portée
    }

    std::cout << "About to leave program...\n";
}

Output:

Foo 1
Creating new Foo...
Foo 2
~Foo 1
About to leave inner block...
About to leave program...
~Foo 2

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

LWG 2118 C++11 unique_ptr<T[]>::operator= conversions de qualification rejetées accepts
