std::out_ptr_t

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <memory>

template< class Smart, class Pointer, class... Args >
class out_ptr_t;  // (depuis C++23)

out_ptr_t est utilisé pour adapter des types tels que les pointeurs intelligents aux fonctions externes qui fournissent leurs résultats via un Pointer* (généralement T** pour un type d'objet T) ou un paramètre void**.

out_ptr_t capture des arguments supplémentaires lors de la construction, fournit un espace de stockage pour le résultat dans lequel la fonction externe mentionnée précédemment écrit, et enfin réinitialise l'objet Smart adapté avec le résultat et les arguments capturés lors de sa destruction.

out_ptr_t se comporte comme s'il possédait les membres de données non statiques suivants :

  • une référence Smart&, liée à l'objet adapté lors de la construction,
  • pour chaque T de Args..., un membre de type T, qui est un argument capturé lors de la construction et utilisé pour la réinitialisation lors de la destruction, et
  • un sous-objet membre adapté au stockage d'un Pointer en son sein et fournissant un objet void*, où l'objet Pointer ou void* est généralement exposé à une fonction externe pour réinitialisation.

L'utilisateur peut contrôler si chaque argument de réinitialisation est capturé par copie ou par référence, en spécifiant respectivement un type objet ou un type référence dans Args....

Paramètres de modèle

  • Smart — le type de l'objet (typiquement un pointeur intelligent) à adapter
  • Pointer — type de l'objet (généralement un pointeur brut) dans lequel une fonction externe écrit son résultat
  • Args... — type des arguments capturés utilisés pour réinitialiser l'objet adapté

Exigences sur les types

  • Pointer doit satisfaire aux exigences de NullablePointer.
  • Le programme est mal formé si Smart est une spécialisation de std::shared_ptr et sizeof...(Args) == 0.

Spécialisations

Contrairement à la plupart des modèles de classes de la bibliothèque standard, les spécialisations définies par le programme de out_ptr_t qui dépendent d'au moins un type défini par le programme n'ont pas besoin de respecter les exigences du modèle primaire.

Cette licence permet à une spécialisation définie par le programme d'exposer aux fonctions étrangères le pointeur brut stocké dans un pointeur intelligent non standard.

Fonctions membres

  • (constructeur) (C++23) — construit un out_ptr_t (fonction membre publique)
  • operator=[deleted] (C++23) — out_ptr_t n'est pas affectable (fonction membre publique)
  • (destructeur) (C++23) — réinitialise le pointeur intelligent adapté (fonction membre publique)
  • operator Pointer*operator void** (C++23) — convertit le out_ptr_t en l'adresse du stockage de la sortie (fonction membre publique)

Fonctions non membres

  • out_ptr (C++23) — crée un out_ptr_t avec un pointeur intelligent associé et des arguments de réinitialisation (modèle de fonction)

Notes

out_ptr_t suppose que les fonctions externes n'utilisent pas la valeur de l'objet Pointer pointé, et se contentent de le réinitialiser. La valeur du pointeur intelligent avant adaptation n'est pas utilisée.

L'usage typique de out_ptr_t consiste à créer ses objets temporaires au moyen de std::out_ptr, qui réinitialise immédiatement le pointeur intelligent adapté. Par exemple, étant donné une fonction setter et un pointeur intelligent de type approprié déclarés respectivement avec int foreign_setter(T**); et std::unique_ptr<T, D> up;,

int foreign_setter(T**);
std::unique_ptr<T, D> up;

if (int ec = foreign_setter(std::out_ptr(up)))
    return ec;

est à peu près équivalent à

int foreign_setter(T**);
std::unique_ptr<T, D> up;
T* raw_p{};

int ec = foreign_setter(&raw_p);
up.reset(raw_p);
if (ec != 0)
    return ec;

Il n'est pas recommandé de créer un objet out_ptr_t avec une durée de stockage autre que la durée de stockage automatique, car ce code risque de produire des références pendantes et d'entraîner un comportement indéfini à la destruction.

out_ptr_t interdit l'utilisation qui réinitialiserait un std::shared_ptr sans spécifier de suppresseur, car cela appellerait std::shared_ptr::reset et remplacerait ultérieurement un suppresseur personnalisé.

Les arguments capturés sont généralement regroupés dans un std::tuple<Args...>. Les implémentations peuvent utiliser un mécanisme différent pour fournir l'objet Pointer ou void* qu'elles doivent contenir.
