Inclusion de fichier source

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Inclut un autre fichier source dans le fichier source courant, à la ligne immédiatement après la directive.

Syntaxe

| | | | #include < h-char-sequence > new-line | (1) | | | | #include " q-char-sequence " new-line | (2) | | | | #include pp-tokens new-line | (3) | | | | __has_include ( " q-char-sequence " ) __has_include ( < h-char-sequence > ) | (4) | (depuis C++17) | | | __has_include ( string-literal ) __has_include ( < h-pp-tokens > ) | (5) | (depuis C++17) | |

  1. Recherche un en-tête identifié de manière unique par h-char-sequence et remplace la directive par le contenu complet de l'en-tête.

  2. Recherche un fichier source identifié par q-char-sequence et remplace la directive par le contenu complet du fichier source. Elle peut revenir à (1) et traiter q-char-sequence comme identifiant d'en-tête.

  3. Si ni (1) ni (2) ne correspondent, pp-tokens subit un remplacement de macro. La directive obtenue après remplacement est à nouveau comparée à (1) ou (2).

  4. Vérifie si un en-tête ou un fichier source est disponible pour l'inclusion.

  5. Si (4) ne correspond pas, h-pp-tokens subit un remplacement de macro. La directive obtenue après remplacement est à nouveau comparée à (4).

  • new-line — Le caractère de fin de ligne
  • h-char-sequence — Une séquence d'un ou plusieurs h-char, où l'apparition de l'un des éléments suivants est conditionnellement prise en charge, avec une sémantique définie par l'implémentation :
    • le caractère '
    • le caractère "
    • le caractère \
    • la séquence de caractères //
    • la séquence de caractères /*
  • h-char — Tout membre du [jeu de caractères source (jusqu'à C++23) | jeu de caractères de traduction (depuis C++23)] à l'exception du fin de ligne et de >
  • q-char-sequence — Une séquence d'un ou plusieurs q-char, où l'apparition de l'un des éléments suivants est conditionnellement prise en charge, avec une sémantique définie par l'implémentation :
    • le caractère '
    • le caractère \
    • la séquence de caractères //
    • la séquence de caractères /*
  • q-char — Tout membre du [jeu de caractères source (jusqu'à C++23) | jeu de caractères de traduction (depuis C++23)] à l'exception du fin de ligne et de "
  • pp-tokens — Une séquence d'un ou plusieurs unités lexicales de prétraitement
  • string-literal — Un littéral de chaîne
  • h-pp-tokens — Une séquence d'un ou plusieurs unités lexicales de prétraitement à l'exception de >

Explication

  1. Recherche une séquence d'emplacements définis par l'implémentation pour un en-tête identifié de manière unique par h-char-sequence, et provoque le remplacement de cette directive par le contenu complet de l'en-tête. La manière dont les emplacements sont spécifiés ou dont l'en-tête est identifié est définie par l'implémentation.

  2. Provoque le remplacement de cette directive par le contenu complet du fichier source identifié par q-char-sequence. Le fichier source nommé est recherché de manière définie par l'implémentation. Si cette recherche n'est pas prise en charge, ou si elle échoue, la directive est retraitée comme si elle avait la syntaxe (1) avec la séquence contenue identique (y compris les caractères > éventuels) de la directive d'origine.

  3. Les unités lexicales de prétraitement qui suivent include dans la directive sont traitées comme dans le texte normal (c'est-à-dire que chaque identifiant actuellement défini comme nom de macro est remplacé par sa liste de remplacement d'unités lexicales de prétraitement). Si la directive obtenue après tous les remplacements ne correspond à aucune des deux formes précédentes, le comportement est indéfini. La méthode par laquelle une séquence d'unités lexicales de prétraitement comprise entre une paire d'unités < et > ou une paire de caractères " est combinée en une seule unité lexicale de nom d'en-tête est définie par l'implémentation.

  4. L'en-tête ou le fichier source identifié par h-char-sequence ou q-char-sequence est recherché comme si cette séquence d'unités lexicales de prétraitement était le pp-tokens de la syntaxe (3), sauf qu'aucun autre développement de macro n'est effectué. Si une telle directive ne satisfait pas aux exigences syntaxiques d'une directive #include, le programme est mal formé. L'expression __has_include s'évalue à 1 si la recherche du fichier source réussit, et à 0 si la recherche échoue.

  5. Cette forme n'est prise en considération que si la syntaxe (4) ne correspond pas, auquel cas les unités lexicales de prétraitement sont traitées comme dans le texte normal.

Si l'en-tête identifié par header-name (c'est-à-dire < h-char-sequence > ou " q-char-sequence ") désigne un en-tête importable, il est défini par l'implémentation si la directive de prétraitement #include est remplacée à la place par une directive import de la forme

import header-name ; new-line

(depuis C++20)

__has_include peut être développé dans l'expression de #if et #elif. Il est traité comme une macro définie par #ifdef, #ifndef, #elifdef, #elifndef (depuis C++23) et defined, mais ne peut être utilisé nulle part ailleurs.

Notes

Les implémentations typiques ne recherchent que les répertoires d'inclusion standard pour la syntaxe (1). La bibliothèque standard C++ et la bibliothèque standard C sont implicitement incluses dans ces répertoires d'inclusion standard. Les répertoires d'inclusion standard peuvent généralement être contrôlés par l'utilisateur au moyen d'options du compilateur.

L'objectif de la syntaxe (2) est de rechercher les fichiers qui ne sont pas contrôlés par l'implémentation. Les implémentations typiques recherchent d'abord le répertoire où se trouve le fichier courant, puis reviennent à (1).

Lorsqu'un fichier est inclus, il est traité par les phases de traduction 1 à 4, ce qui peut inclure, de manière récursive, le développement des directives #include imbriquées, jusqu'à une limite d'imbrication définie par l'implémentation. Pour éviter l'inclusion répétée du même fichier et une récursion infinie lorsqu'un fichier s'inclut lui-même, éventuellement de manière transitive, des gardes d'en-tête sont couramment utilisées : l'en-tête entier est enveloppé dans

#ifndef FOO_H_INCLUDED /* any name uniquely mapped to file name */
#define FOO_H_INCLUDED
// le contenu du fichier est ici
#endif

De nombreux compilateurs implémentent aussi le pragma non standard pragma #pragma once, avec des effets similaires : il désactive le traitement d'un fichier si le même fichier (dont l'identité est déterminée de manière propre au système d'exploitation) a déjà été inclus.

Une séquence de caractères qui ressemble à une séquence d'échappement dans q-char-sequence ou h-char-sequence peut provoquer une erreur, être interprétée comme le caractère correspondant à la séquence d'échappement, ou avoir une signification totalement différente, selon l'implémentation.

Un résultat __has_include égal à 1 signifie seulement qu'un en-tête ou un fichier source portant le nom indiqué existe. Cela ne signifie pas que l'en-tête ou le fichier source, une fois inclus, ne provoquerait pas d'erreur ou ne contiendrait quelque chose d'utile. Par exemple, sur une implémentation C++ qui prend en charge les modes C++14 et C++17 (et fournit __has_include en mode C++14 comme extension conforme), __has_include(<optional>) peut valoir 1 en mode C++14, mais en réalité #include <optional> peut provoquer une erreur.

Exemple

#if __has_include(<optional>)
    #include <optional>
    #define has_optional 1
    template<class T>
    using optional_t = std::optional<T>;
#elif __has_include(<experimental/optional>)
    #include <experimental/optional>
    #define has_optional -1
    template<class T>
    using optional_t = std::experimental::optional<T>;
#else
    #define has_optional 0
    template<class V>
    class optional_t
    {
        V v{};
        bool has{};

    public:
        optional_t() = default;
        optional_t(V&& v) : v(v), has{true} {}
        V value_or(V&& alt) const&
        {
            return has ? v : alt;
        }
        // etc.
    };
#endif

#include <iostream>

int main()
{
    if (has_optional > 0)
        std::cout << "<optional> is present\n";
    else if (has_optional < 0)
        std::cout << "<experimental/optional> is present\n";
    else
        std::cout << "<optional> is not present\n";

    optional_t<int> op;
    std::cout << "op = " << op.value_or(-1) << '\n';
    op = 42;
    std::cout << "op = " << op.value_or(-1) << '\n';
}

Output:

<optional> is present
op = -1
op = 42
