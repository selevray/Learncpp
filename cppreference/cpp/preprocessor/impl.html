Contrôle du comportement défini par l'implémentation

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Le comportement défini par l'implémentation est contrôlé par la directive #pragma.

Syntaxe

| | | | #pragma pragma-params | (1) | | | | _Pragma( string-literal ) | (2) | (depuis C++11) | |

  1. Se comporte de manière définie par l'implémentation.

  2. Supprime le préfixe L (le cas échéant), les guillemets extérieurs et les espaces de début et de fin de string-literal, remplace chaque \" par " et chaque \\ par \, puis découpe le résultat en unités lexicales (comme dans la phase de traduction 3), et utilise enfin ce résultat comme si c'était l'entrée de #pragma dans (1).

Explication

La directive pragma contrôle le comportement spécifique à l'implémentation du compilateur, comme la désactivation des avertissements du compilateur ou la modification des exigences d'alignement. Tout pragma non reconnu est ignoré.

Pragmas non standard

La norme du langage ISO C++ n'impose pas aux compilateurs de prendre en charge des pragmas. Cependant, plusieurs pragmas non standard sont pris en charge par plusieurs implémentations :

#pragma STDC

La norme du langage ISO C impose aux compilateurs C de prendre en charge les trois pragmas suivants, et certains éditeurs de compilateurs C++ les prennent en charge, à des degrés divers, dans leurs frontaux C++ :

| | | | #pragma STDC FENV_ACCESS arg | (1) | | | | #pragma STDC FP_CONTRACT arg | (2) | | | | #pragma STDC CX_LIMITED_RANGE arg | (3) | | |

où arg est soit ON, soit OFF, soit DEFAULT.

  1. Si défini à ON, informe le compilateur que le programme accédera à ou modifiera l'environnement en virgule flottante, ce qui signifie que les optimisations susceptibles de contourner les tests de drapeaux et les changements de mode (par exemple l'élimination globale des sous-expressions communes, le déplacement de code et le pliage de constantes) sont interdites. La valeur par défaut est définie par l'implémentation, généralement OFF.

  2. Autorise la contraction des expressions en virgule flottante, c'est-à-dire les optimisations qui omettent les erreurs d'arrondi et les exceptions en virgule flottante qui seraient observées si l'expression était évaluée exactement telle qu'écrite. Par exemple, permet l'implémentation de (x * y) + z avec une seule instruction processeur d'multiplication-addition fusionnée. La valeur par défaut est définie par l'implémentation, généralement ON.

  3. Informe le compilateur que la multiplication, la division et la valeur absolue de nombres complexes peuvent utiliser des formules mathématiques simplifiées (x+iy)×(u+iv) = (xu-yv)+i(yu+xv), (x+iy)/(u+iv) = [(xu+yv)+i(yu-xv)]/(u2
    +v2
    ) et |x+iy| = √x2
    +y2
    , malgré la possibilité de dépassement de capacité intermédiaire. Autrement dit, le programmeur garantit que l'intervalle des valeurs transmises à ces fonctions est limité. La valeur par défaut est OFF.

Le comportement du programme est indéfini si l'un des trois pragmas ci-dessus apparaît dans un contexte autre que hors de toutes les déclarations externes ou avant toutes les déclarations et instructions explicites à l'intérieur d'une instruction composée.

Remarque : les compilateurs qui ne prennent pas en charge ces pragmas peuvent fournir des options de compilation équivalentes, comme -fcx-limited-range et -ffp-contract de gcc.

#pragma once

#pragma once est un pragma non standard pris en charge par la grande majorité des compilateurs modernes. S'il apparaît dans un fichier d'en-tête, il indique que celui-ci ne doit être analysé qu'une seule fois, même s'il est inclus (directement ou indirectement) plusieurs fois dans le même fichier source.

L'approche standard pour empêcher l'inclusion multiple d'un même en-tête consiste à utiliser des gardes d'inclusion :

#ifndef LIBRARY_FILENAME_H
#define LIBRARY_FILENAME_H
// contenu de l'en-tête
#endif /* LIBRARY_FILENAME_H */

Ainsi, toutes les inclusions de l'en-tête sauf la première dans une unité de traduction sont exclues de la compilation. Tous les compilateurs modernes enregistrent le fait qu'un fichier d'en-tête utilise une garde d'inclusion et ne le réanalysent pas lorsqu'ils le rencontrent à nouveau, tant que la garde est toujours définie (voir par exemple gcc).

Avec #pragma once, le même en-tête apparaît comme

#pragma once
// contenu de l'en-tête

Contrairement aux gardes d'en-tête, ce pragma rend impossible l'utilisation par erreur d'un même nom de macro dans plusieurs fichiers. En revanche, comme avec #pragma once les fichiers sont exclus en fonction de leur identité au niveau du système de fichiers, cela ne protège pas contre une double inclusion d'un en-tête qui existe à plusieurs emplacements d'un projet.

#pragma pack

Cette famille de pragmas contrôle l'alignement maximal des membres de classes et d'unions définis ensuite.

| | | | #pragma pack(arg) | (1) | | | | #pragma pack() | (2) | | | | #pragma pack(push) | (3) | | | | #pragma pack(push, arg) | (4) | | | | #pragma pack(pop) | (5) | | |

où arg est une petite puissance de deux et indique le nouvel alignement en octets.

  1. Définit l'alignement courant à la valeur arg.

  2. Définit l'alignement courant à la valeur par défaut (spécifiée par une option de ligne de commande).

  3. Empile la valeur de l'alignement courant sur une pile interne.

  4. Empile la valeur de l'alignement courant sur la pile interne, puis définit l'alignement courant à la valeur arg.

  5. Dépile l'élément au sommet de la pile interne, puis définit (restaure) l'alignement courant à cette valeur.

#pragma pack peut réduire l'alignement d'une classe, mais il ne peut pas la rendre suralignée.
