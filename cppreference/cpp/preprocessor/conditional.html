Inclusion conditionnelle

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Le préprocesseur prend en charge la compilation conditionnelle de parties de fichier source. Ce comportement est contrôlé par les directives #if, #else, #elif, #ifdef, #ifndef, #elifdef, #elifndef (depuis C++23) et #endif.

Syntaxe

| | | | #if expression | | | | | #ifdef identifier | | | | | #ifndef identifier | | | | | #elif expression | | | | | #elifdef identifier | | (depuis C++23) | | | #elifndef identifier | | (depuis C++23) | | | #else | | | | | #endif | | | |

Explication

Le bloc de préprocessing conditionnel commence par une directive #if, #ifdef ou #ifndef, puis comprend éventuellement un nombre quelconque de directives #elif, #elifdef ou #elifndef (depuis C++23), puis comprend éventuellement au plus une directive #else et se termine par une directive #endif. Les blocs de préprocessing conditionnel imbriqués sont traités séparément.

Chacune des directives #if, #ifdef, #ifndef, #elif, #elifdef, #elifndef (depuis C++23) et #else contrôle le bloc de code jusqu'à la première directive #elif, #elifdef, #elifndef (depuis C++23), #else ou #endif n'appartenant à aucun bloc de préprocessing conditionnel imbriqué.

Les directives #if, #ifdef et #ifndef testent la condition spécifiée (voir ci-dessous) et, si elle est évaluée à true, compilent le bloc de code contrôlé. Dans ce cas, les directives #else, #elifdef, #elifndef, (depuis C++23) et #elif suivantes sont ignorées. Sinon, si la condition spécifiée est évaluée à false, le bloc de code contrôlé est ignoré et la directive #else, #elifdef, #elifndef, (depuis C++23) ou #elif suivante (le cas échéant) est traitée. Si la directive suivante est #else, le bloc de code contrôlé par la directive #else est compilé inconditionnellement. Sinon, la directive #elif, #elifdef ou #elifndef (depuis C++23) agit comme si c'était une directive #if : elle vérifie la condition, compile ou ignore le bloc de code contrôlé selon le résultat, et dans ce dernier cas traite les directives #elif, #elifdef, #elifndef, (depuis C++23) et #else suivantes. Le bloc de préprocessing conditionnel se termine par la directive #endif.

Évaluation de la condition

#if, #elif

La expression peut contenir :

  • des opérateurs unaires de la forme defined identifier ou defined (identifier). Le résultat vaut 1 si le identifier a été défini comme nom de macro, sinon le résultat vaut 0. __has_­include et __has_cpp_attribute (depuis C++20) sont traités comme s'il s'agissait de noms de macros définies dans ce contexte. (depuis C++17)
  • (depuis C++17) expressions __has_include, qui détectent si un en-tête ou un fichier source existe.
  • (depuis C++20) expressions __has_cpp_attribute, qui détectent si un jeton d'attribut donné est pris en charge et sa version prise en charge.

Après toute expansion de macros et évaluation des expressions defined[, __has_include (depuis C++17) | , et __has_cpp_attribute (depuis C++20)], tout identifiant qui n'est pas un littéral booléen est remplacé par le nombre 0 (ceci inclut les identifiants qui sont lexicalement des mots-clés, mais pas les jetons de remplacement comme and).

L'expression est ensuite évaluée comme une expression constante entière.

Si la expression s'évalue à une valeur non nulle, le bloc de code contrôlé est inclus, sinon il est ignoré.

Remarque : jusqu'à la résolution du défaut CWG 1955, #if cond1 ... #elif cond2 diffère de #if cond1 ... #else suivi de #if cond2, car si cond1 est vrai, le second #if est ignoré et cond2 n'a pas besoin d'être bien formé, alors que cond2 de #elif doit être une expression valide. Depuis CWG 1955, #elif qui commence le bloc de code ignoré est également ignoré.

Directives combinées

Vérifie si l'identifiant a été défini comme nom de macro.

#ifdef identifier est essentiellement équivalent à #if defined identifier.

#ifndef identifier est essentiellement équivalent à #if !defined identifier.

#elifdef identifier est essentiellement équivalent à #elif defined identifier.

#elifndef identifier est essentiellement équivalent à #elif !defined identifier.

(depuis C++23)

Notes

Bien que les directives #elifdef et #elifndef ciblent C++23, les implémentations sont encouragées à les rétroporter vers les modes de langage plus anciens en tant qu'extensions conformes.

Exemple

#define ABCD 2
#include <iostream>

int main()
{

#ifdef ABCD
    std::cout << "1: yes\n";
#else
    std::cout << "1: no\n";
#endif

#ifndef ABCD
    std::cout << "2: no1\n";
#elif ABCD == 2
    std::cout << "2: yes\n";
#else
    std::cout << "2: no2\n";
#endif

#if !defined(DCBA) && (ABCD < 2*4-3)
    std::cout << "3: yes\n";
#endif

// Notez que si un compilateur ne prend pas en charge les directives #elifdef/#elifndef de C++23
// alors le bloc « inattendu » (voir ci-dessous) sera sélectionné.
#ifdef CPU
    std::cout << "4: no1\n";
#elifdef GPU
    std::cout << "4: no2\n";
#elifndef RAM
    std::cout << "4: yes\n"; // bloc attendu
#else
    std::cout << "4: no!\n"; // sélectionne de façon inattendue ce bloc en ignorant
                             // les directives inconnues et « saute » directement
                             // de « #ifdef CPU » vers ce bloc « #else »
#endif

// Pour corriger le problème ci-dessus, nous pouvons définir conditionnellement la
// macro ELIFDEF_SUPPORTED uniquement si les directives C++23
// #elifdef/#elifndef sont prises en charge.
#if 0
#elifndef UNDEFINED_MACRO
#define ELIFDEF_SUPPORTED
#else
#endif

#ifdef ELIFDEF_SUPPORTED
    #ifdef CPU
        std::cout << "4: no1\n";
    #elifdef GPU
        std::cout << "4: no2\n";
    #elifndef RAM
        std::cout << "4: yes\n"; // bloc attendu
    #else
        std::cout << "4: no3\n";
    #endif
#else // when #elifdef unsupported use old verbose `#elif defined`
    #ifdef CPU
        std::cout << "4: no1\n";
    #elif defined GPU
        std::cout << "4: no2\n";
    #elif !defined RAM
        std::cout << "4: yes\n"; // bloc attendu
    #else
        std::cout << "4: no3\n";
    #endif
#endif
}

Sortie possible :

1: yes
2: yes
3: yes
4: no!
4: yes
