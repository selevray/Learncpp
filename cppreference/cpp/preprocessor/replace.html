Remplacement de macros textuelles

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Le préprocesseur prend en charge le remplacement de macros textuelles. Le remplacement de macros textuelles de type fonction est également pris en charge.

Syntaxe

| | | | #define identifier replacement-list ﻿*(facultatif)* | (1) | | | | #define identifier ﻿(parameters ﻿) replacement-list ﻿*(facultatif)* | (2) | | | | #define identifier ﻿(parameters ﻿, ...) replacement-list ﻿*(facultatif)* | (3) | (depuis C++11) | | | #define identifier ﻿(...) replacement-list ﻿*(facultatif)* | (4) | (depuis C++11) | | | #undef identifier | (5) | | |

Explication

directives #define

Les directives #define définissent identifier comme macro, c'est-à-dire qu'elles demandent au compilateur de remplacer la plupart des occurrences successives de identifier par replacement-list, qui sera ensuite également traité. Des exceptions découlent des règles de analyse et de remplacement. Si l'identifiant est déjà défini comme macro de quelque type que ce soit, le programme est mal formé, sauf si les définitions sont identiques.

Macros de type objet

Les macros de type objet remplacent chaque occurrence de identifier définie par replacement-list. La version (1) de la directive #define se comporte exactement ainsi.

Macros de type fonction

Les macros de type fonction remplacent chaque occurrence de identifier définie par replacement-list, en prenant en plus un certain nombre d'arguments, qui remplacent alors les occurrences correspondantes de l'un quelconque des parameters dans replacement-list.

La syntaxe d'un appel de macro de type fonction est similaire à celle d'un appel de fonction : chaque occurrence du nom de la macro suivi d'une ( comme jeton de prétraitement suivant introduit la suite de jetons qui est remplacée par replacement-list. La suite se termine par le jeton ) correspondant, en ignorant les paires de parenthèses gauches et droites imbriquées.

Pour la version (2), le nombre d'arguments doit être égal au nombre de paramètres de la définition de macro. Pour les versions (3,4), le nombre d'arguments ne doit pas être inférieur au nombre de paramètres (ne (depuis C++20) compte pas ...). Sinon, le programme est mal formé. Si l'identifiant n'est pas en notation fonctionnelle, c'est-à-dire s'il n'est pas suivi de parenthèses, il n'est pas du tout remplacé.

La version (2) de la directive #define définit une macro de type fonction simple.

La version (3) de la directive #define définit une macro de type fonction à nombre variable d'arguments. Les arguments supplémentaires (appelés arguments variables) peuvent être accessibles à l'aide de l'identifiant __VA_ARGS__, qui est alors remplacé par les arguments fournis avec l'identifiant à remplacer.

La version (4) de la directive #define définit une macro de type fonction à nombre variable d'arguments, mais sans arguments ordinaires. Les arguments (appelés arguments variables) ne sont accessibles qu'à l'aide de l'identifiant __VA_ARGS__, qui est alors remplacé par les arguments fournis avec l'identifiant à remplacer.

Pour les versions (3,4), replacement-list peut contenir la suite de jetons __VA_OPT__(content ﻿), qui est remplacée par content si __VA_ARGS__ n'est pas vide, et se développe en rien dans le cas contraire.

#define F(...) f(0 __VA_OPT__(,) __VA_ARGS__)
F(a, b, c) // remplacé par f(0, a, b, c)
F()        // remplacé par f(0)

#define G(X, ...) f(0, X __VA_OPT__(,) __VA_ARGS__)
G(a, b, c) // remplacé par f(0, a, b, c)
G(a, )     // remplacé par f(0, a)
G(a)       // remplacé par f(0, a)

#define SDEF(sname, ...) S sname __VA_OPT__(= { __VA_ARGS__ })
SDEF(foo);       // remplacé par S foo;
SDEF(bar, 1, 2); // remplacé par S bar = { 1, 2 };

(depuis C++20)

Remarque : si un argument d'une macro de type fonction contient des virgules qui ne sont pas protégées par des paires de parenthèses gauches et droites correspondantes (cas le plus courant dans les listes d'arguments de modèle, comme assert(std::is_same_v<int, int>); ou BOOST_FOREACH(std::pair<int, int> p, m)), la virgule est interprétée comme séparateur d'arguments de macro, ce qui provoque une erreur de compilation due à un nombre d'arguments incorrect.

Analyse et remplacement

  • L'analyse garde la trace des macros qu'elle a remplacées. Si l'analyse trouve un texte correspondant à une telle macro, elle le marque « à ignorer » (toutes les analyses l'ignoreront). Cela empêche la récursion.
  • Si l'analyse a trouvé une macro de type fonction, les arguments sont analysés avant d'être placés dans replacement-list. Sauf les opérateurs # et ##, qui prennent l'argument sans l'analyser.
  • Une fois la macro remplacée, le texte résultant est analysé.

Remarque : il est possible de définir une macro pseudo-récursive :

#define EMPTY
#define SCAN(x)     x
#define EXAMPLE_()  EXAMPLE
#define EXAMPLE(n)  EXAMPLE_ EMPTY()(n-1) (n)
EXAMPLE(5)
SCAN(EXAMPLE(5))

Output:

EXAMPLE_ ()(5 -1) (5)
EXAMPLE_ ()(5 -1 -1) (5 -1) (5)

Noms de macros réservés

Une unité de traduction qui inclut un en-tête de la bibliothèque standard ne doit pas #define ni #undef des noms déclarés dans un en-tête de la bibliothèque standard.

Une unité de traduction qui utilise une partie quelconque de la bibliothèque standard ne doit pas #define ni #undef des noms lexicalement identiques à :

  • keywords
  • identifiants ayant une signification particulière
  • tout jeton d'attribut standard, à l'exception de likely et unlikely qui peuvent être définis comme macros de type fonction (depuis C++20)

(depuis C++11)

Dans le cas contraire, le comportement est indéfini.

Opérateurs # et ##

Dans les macros de type fonction, un opérateur # placé devant un identifiant de replacement-list applique le remplacement de paramètre à cet identifiant, puis entoure le résultat de guillemets, ce qui crée en pratique un littéral de chaîne. En outre, le préprocesseur ajoute des barres obliques inverses pour échapper les guillemets entourant les littéraux de chaîne éventuellement inclus, et double les barres obliques inverses à l'intérieur de la chaîne si nécessaire. Tous les espaces en début et en fin de texte sont supprimés, et toute suite d'espaces au milieu du texte (mais pas à l'intérieur des littéraux de chaîne inclus) est réduite à un seul espace. Cette opération est appelée « transformation en chaîne ». Si le résultat de la transformation n'est pas un littéral de chaîne valide, le comportement est indéfini.

Lorsque # apparaît devant __VA_ARGS__, l'intégralité de __VA_ARGS__ développé est entourée de guillemets :

#define showlist(...) puts(#__VA_ARGS__)
showlist();            // se développe en puts("")
showlist(1, "x", int); // se développe en puts("1, \"x\", int")

(depuis C++11)

Un opérateur ## placé entre deux identifiants successifs de replacement-list applique le remplacement de paramètre à ces deux identifiants (qui ne sont pas d'abord développés comme macros), puis concatène le résultat. Cette opération est appelée « concaténation » ou « collage de jetons ». Seuls les jetons qui forment ensemble un jeton valide peuvent être collés : des identifiants formant un identifiant plus long, des chiffres formant un nombre, ou les opérateurs + et = formant un +=. Un commentaire ne peut pas être créé en collant / et *, car les commentaires sont supprimés du texte avant que la substitution de macros ne soit considérée. Si le résultat de la concaténation n'est pas un jeton valide, le comportement est indéfini.

Remarque : certains compilateurs offrent une extension permettant à ## d'apparaître après une virgule et avant __VA_ARGS__, auquel cas ## ne fait rien lorsque les arguments variables sont présents, mais supprime la virgule lorsqu'ils ne le sont pas : cela permet de définir des macros telles que fprintf (stderr, format, ##__VA_ARGS__). Ceci peut aussi être obtenu de manière standard en utilisant __VA_OPT__, comme fprintf (stderr, format __VA_OPT__(, ) __VA_ARGS__). (depuis C++20)

directive #undef

La directive #undef annule la définition de identifier, c'est-à-dire supprime la définition précédente de identifier faite par la directive #define. Si l'identifiant n'a pas de macro associée, la directive est ignorée.

Macros prédéfinies

Les noms de macros suivants sont prédéfinis dans chaque unité de traduction :

  • __cplusplus — désigne la version de la norme C++ utilisée, se développe en la valeur
    • 199711L (jusqu'à C++11) ,
    • 201103L (C++11) ,
    • 201402L (C++14) ,
    • 201703L (C++17) ,
    • 202002L (C++20) , ou
    • 202302L (C++23) (constante de macro)
  • STDC_HOSTED (C++11) — se développe en la constante entière 1 si l'implémentation est hébergée (fonctionne sous un système d'exploitation), 0 si elle est autonome (fonctionne sans système d'exploitation) (constante de macro)
  • FILE — se développe en le nom du fichier courant, sous forme de littéral de chaîne de caractères ; peut être modifié par la directive #line (constante de macro)
  • LINE — se développe en le numéro de ligne de la ligne physique courante du code source, sous forme de constante entière ; peut être modifié par la directive #line (constante de macro)
  • DATE — se développe en la date de traduction, sous forme de littéral de chaîne de caractères de la forme "Mmm dd yyyy". Le premier caractère de "dd" est un espace si le jour du mois est inférieur à 10. Le nom du mois est celui généré comme par std::asctime() (constante de macro)
  • TIME — se développe en l'heure de traduction, sous forme de littéral de chaîne de caractères de la forme "hh:mm:ss" (constante de macro)
  • STDCPP_DEFAULT_NEW_ALIGNMENT (C++17) — se développe en un littéral std::size_t dont la valeur est l'alignement garanti par un appel à l'opérateur operator new non conscient de l'alignement (les alignements plus grands seront transmis à la surcharge consciente de l'alignement, telle que operator new(std::size_t, std::align_val_t)) (constante de macro)

Macros de test des fonctionnalités du langage

La norme définit un ensemble de macros de préprocesseur correspondant aux fonctionnalités du langage C++ introduites en C++11 ou ultérieurement. Elles permettent de détecter de manière simple et portable la présence de ces fonctionnalités.

Notes

La variable prédéfinie locale à la fonction __func__ n'est pas une macro prédéfinie, mais elle est généralement utilisée avec __FILE__ et __LINE__, par exemple par assert.

(depuis C++11)

Exemple

#include <iostream>

// Créer une fabrique de fonctions et l'utiliser
#define FUNCTION(name, a) int fun_##name() { return a; }

FUNCTION(abcd, 12)
FUNCTION(fff, 2)
FUNCTION(qqq, 23)

#undef FUNCTION
#define FUNCTION 34
#define OUTPUT(a) std::cout << "output: " #a << '\n'

// Utilisation d'une macro dans la définition d'une macro ultérieure
#define WORD "Hello "
#define OUTER(...) WORD #__VA_ARGS__

int main()
{
    std::cout << "abcd: " << fun_abcd() << '\n';
    std::cout << "fff: " << fun_fff() << '\n';
    std::cout << "qqq: " << fun_qqq() << '\n';

    std::cout << FUNCTION << '\n';
    OUTPUT(million); //remarquer l'absence de guillemets

    std::cout << OUTER(World) << '\n';
    std::cout << OUTER(WORD World) << '\n';
}

Output:

abcd: 12
fff: 2
qqq: 23
34
output: million
Hello World
Hello WORD World
