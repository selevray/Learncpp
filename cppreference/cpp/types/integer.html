Types entiers de largeur fixe (depuis C++11)

Types

Défini dans l'en-tête <cstdint>

  • int8_tint16_tint32_tint64_t(optional)** — type entier signé d'une largeur exacte de 8, 16, 32 et 64 bits respectivement sans bits de bourrage et utilisant le complément à deux pour les valeurs négatives (fourni si et seulement si l'implémentation prend directement en charge le type) (typedef)
  • int_fast8_tint_fast16_tint_fast32_tint_fast64_t — type entier signé le plus rapide d'une largeur d'au moins 8, 16, 32 et 64 bits respectivement (typedef)
  • int_least8_tint_least16_tint_least32_tint_least64_t — type entier signé le plus petit d'une largeur d'au moins 8, 16, 32 et 64 bits respectivement (typedef)
  • intmax_t — type entier signé de largeur maximale (typedef)
  • intptr_t(optional)** — type entier signé capable de contenir un pointeur vers void (typedef)
  • uint8_tuint16_tuint32_tuint64_t(optional)** — type entier non signé de largeur exactement 8, 16, 32 et 64 bits respectivement (fourni si et seulement si l'implémentation prend directement en charge le type) (typedef)
  • uint_fast8_tuint_fast16_tuint_fast32_tuint_fast64_t — type entier non signé le plus rapide de largeur d'au moins 8, 16, 32 et 64 bits respectivement (typedef)
  • uint_least8_tuint_least16_tuint_least32_tuint_least64_t — type entier non signé le plus petit de largeur d'au moins 8, 16, 32 et 64 bits respectivement (typedef)
  • uintmax_t — type entier non signé de largeur maximale (typedef)
  • uintptr_t(optional)** — type entier non signé capable de contenir un pointeur vers void (typedef)

L'implémentation peut définir les noms de typedef intN_t, int_fastN_t, int_leastN_t, uintN_t, uint_fastN_t et uint_leastN_t lorsque N n'est ni 8, 16, 32 ni 64. Les noms de typedef de la forme intN_t ne peuvent être définis que si l'implémentation prend en charge un type entier de cette largeur sans bits de remplissage. Ainsi, std::uint24_t désigne un type entier non signé d'une largeur exactement égale à 24 bits.

Chacune des macros listées ci-dessous est définie si et seulement si l'implémentation définit le nom de typedef correspondant. Les macros INTN_C et UINTN_C correspondent respectivement aux noms de typedef int_leastN_t et uint_leastN_t.

Notes

Comme C++ interprète un caractère placé immédiatement après un littéral de chaîne comme un littéral de chaîne défini par l'utilisateur, du code C tel que printf("%"PRId64"\n",n); est invalide en C++ et nécessite un espace avant PRId64.

La norme C99 suggère que les implémentations C++ ne définissent pas les macros de limites, de constantes ou de formats ci-dessus, sauf si les macros __STDC_LIMIT_MACROS, __STDC_CONSTANT_MACROS ou __STDC_FORMAT_MACROS (respectivement) sont définies avant l'inclusion de l'en-tête C correspondant (stdint.h ou inttypes.h). Cette recommandation n'a été adoptée par aucune norme C++ et a été supprimée en C11. Cependant, certaines implémentations (comme glibc 2.17) tentent d'appliquer cette règle, et il peut être nécessaire de définir les macros __STDC ; les compilateurs C++ peuvent tenter de contourner cela en les définissant automatiquement dans certaines circonstances.

std::int8_t peut être signed char et std::uint8_t peut être unsigned char, mais aucun des deux ne peut être char quel que soit son signe (car char n'est pas considéré comme un « type entier signé » ou « type entier non signé »).

Exemple

Voir aussi une note concernant les espaces avant les macros de format utilisées dans cet exemple.

#include <cinttypes>
#include <cstdio>

int main()
{
    std::printf("%zu\n", sizeof(std::int64_t));
    std::printf("%s\n", PRId64);
    std::printf("%+" PRId64 "\n", INT64_MIN);
    std::printf("%+" PRId64 "\n", INT64_MAX);

    std::int64_t n = 7;
    std::printf("%+" PRId64 "\n", n);
}
