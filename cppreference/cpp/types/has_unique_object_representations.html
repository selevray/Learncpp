std::has_unique_object_representations

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <type_traits>

template< class T >
struct has_unique_object_representations;  // (depuis C++17)

std::has_unique_object_representations est un UnaryTypeTrait.

Si T est TriviallyCopyable et si deux objets quelconques de type T de même valeur ont la même représentation objet, fournit la constante membre value égale à true. Pour tout autre type, value vaut false.

Pour les besoins de ce trait, deux tableaux ont la même valeur si leurs éléments ont les mêmes valeurs, deux classes non-union ont la même valeur si leurs sous-objets directs ont la même valeur, et deux unions ont la même valeur si elles ont le même membre actif et si la valeur de ce membre est la même.

Il est défini par l'implémentation quels types scalaires satisfont ce trait, mais les types entiers non signés (jusqu'à C++20) qui n'utilisent pas de bits de remplissage ont la garantie d'avoir des représentations objet uniques.

Le comportement est indéfini si T est un type incomplet autre que void (éventuellement qualifié cv) ou un tableau de borne inconnue.

Si le programme ajoute des spécialisations pour std::has_unique_object_representations ou std::has_unique_object_representations_v, le comportement est indéfini.

Paramètres de modèle

  • T — un type à vérifier

Modèle de variable auxiliaire

template< class T >
constexpr bool has_unique_object_representations_v =
    has_unique_object_representations<T>::value;  // (depuis C++17)

Hérité de std::integral_constant

Notes

Ce trait a été introduit pour permettre de déterminer si un type peut être correctement haché en hachant sa représentation objet comme un tableau d'octets.

Exemple

#include <cstdint>
#include <type_traits>

struct unpadded
{
    std::uint32_t a, b;
};

struct likely_padded
{
    std::uint8_t c;
    std::uint16_t st;
    std::uint32_t i;
};

int main()
{
    // Chaque valeur d'un char correspond à exactement une représentation d'objet.
    static_assert(std::has_unique_object_representations_v<char>);
    // Pour les flottants IEC 559, l'assertion réussit car la valeur NaN possède
    // plusieurs représentations d'objet.
    static_assert(!std::has_unique_object_representations_v<float>);

    // Devrait réussir dans toute implémentation raisonnable, car unpadded
    // n'est généralement pas complété, et std::uint32_t ne peut pas contenir de bits de remplissage.
    static_assert(std::has_unique_object_representations_v<unpadded>);
    // Échoue dans la plupart des implémentations, car des bits de remplissage sont insérés
    // entre les membres de données c et st afin d'aligner st sur 16 bits.
    static_assert(!std::has_unique_object_representations_v<likely_padded>);

    // Divergence architecturale notable :
    static_assert(std::has_unique_object_representations_v<bool>);  // x86
 // static_assert(!std::has_unique_object_representations_v<bool>); // ARM
}
