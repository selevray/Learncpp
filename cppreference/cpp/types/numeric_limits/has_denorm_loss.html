std::numeric_limits<T>::has_denorm_loss

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

static const bool has_denorm_loss;  // (jusqu'à C++11)

static constexpr bool has_denorm_loss;  // (depuis C++11) (obsolète en C++23)

La valeur de std::numeric_limits<T>::has_denorm_loss est true pour tous les types à virgule flottante T qui détectent la perte de précision lors de la création d'un nombre subnormal comme perte de dénormalisation plutôt que comme résultat inexact (voir ci-dessous).

  • double — défini par l'implémentation

Notes

Les implémentations conformes à la norme IEEE 754 des nombres subnormaux doivent détecter la perte de précision associée à la création de tels nombres, si elle survient, et peuvent le faire de l'une des deux manières distinctes suivantes :

  1. Perte de dénormalisation : le résultat fourni diffère de celui qui aurait été calculé si la plage des exposants était non bornée.
  2. Résultat inexact : le résultat fourni diffère de celui qui aurait été calculé si la plage des exposants et la précision étaient toutes deux non bornées.

Aucune implémentation du mécanisme de perte de dénormalisation n'existe (la perte de précision est détectée après arrondi, comme résultat inexact), et cette option a été supprimée dans la révision 2008 de IEEE Std 754.

libstdc++, libc++, libCstd et stlport4 définissent cette constante comme false pour tous les types à virgule flottante. Microsoft Visual Studio la définit comme true pour tous les types à virgule flottante.

Comme pour tout calcul à virgule flottante, une perte de précision peut lever FE_INEXACT.
