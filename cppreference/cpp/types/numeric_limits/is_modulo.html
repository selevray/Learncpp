std::numeric_limits<T>::is_modulo

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

static const bool is_modulo;  // (jusqu'à C++11)

static constexpr bool is_modulo;  // (depuis C++11)

La valeur de std::numeric_limits<T>::is_modulo est true pour tous les types arithmétiques T qui gèrent les dépassements par arithmétique modulo, c'est-à-dire que si le résultat de l'addition, de la soustraction, de la multiplication ou de la division de ce type tombe en dehors de l'intervalle [min(),max()], la valeur renvoyée par une telle opération diffère de la valeur attendue d'un multiple de max() - min() + 1.

is_modulo est false pour les types entiers signés, sauf si l'implémentation définit le dépassement d'entier signé comme un bouclage.

Spécialisations standard

T valeur de std::numeric_limits<T>::is_modulo

  • /* non spécialisé */ — false
  • bool — false
  • char — défini par l'implémentation
  • signed char — défini par l'implémentation
  • unsigned char — true
  • wchar_t — défini par l'implémentation
  • char8_t (depuis C++20) — true
  • char16_t (depuis C++11) — true
  • char32_t (depuis C++11) — true
  • short — défini par l'implémentation
  • unsigned short — true
  • int — défini par l'implémentation
  • unsigned int — true
  • long — défini par l'implémentation
  • unsigned long — true
  • long long (C++11) — défini par l'implémentation
  • unsigned long long (C++11) — true
  • float — false
  • double — false
  • long double — false

Notes

La norme indiquait « Sur la plupart des machines, cette valeur est true pour les entiers signés. » avant la résolution du LWG issue 2422. Voir GCC PR 22200 pour une discussion associée.

Exemple

Démontre le comportement des types modulo :

#include <iostream>
#include <type_traits>
#include <limits>

template<class T>
typename std::enable_if<std::numeric_limits<T>::is_modulo>::type
    check_overflow()
{
    std::cout << "max value is " << std::numeric_limits<T>::max() << '\n'
              << "min value is " << std::numeric_limits<T>::min() << '\n'
              << "max value + 1 is " << std::numeric_limits<T>::max()+1 << '\n';
}

int main()
{
    check_overflow<int>();
    std::cout << '\n';
    check_overflow<unsigned long>();
//  check_overflow<float>(); // erreur de compilation, pas un type modulo
}

Sortie possible :

max value is 2147483647
min value is -2147483648
max value + 1 is -2147483648

max value is 18446744073709551615
min value is 0
max value + 1 is 0

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 612 C++98 la définition de « gérer les dépassements par arithmétique modulo » était insuffisante[1] a fourni une meilleure définition
LWG 2422 C++98 is_modulo devait être true pour les types entiers signés sur la plupart des machines devait être false pour les types entiers signés sauf si le dépassement d'entier signé est défini comme un bouclage
  1. ↑ La définition est « l'addition de deux nombres positifs peut donner un résultat qui revient à un troisième nombre inférieur ». Elle pose les problèmes suivants :
    • Elle ne définit pas la valeur obtenue après bouclage.
    • Elle ne précise pas si le résultat est reproductible.
    • Elle n'exige pas que l'addition, la soustraction et les autres opérations sur toutes les valeurs aient un comportement défini.
