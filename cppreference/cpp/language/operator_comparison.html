Comparaison à deux voies

Les expressions de comparaison à deux voies ont la forme

Opérateurs relationnels

| | | | lhs < rhs | (1) | | | | lhs > rhs | (2) | | | | lhs <= rhs | (3) | | | | lhs >= rhs | (4) | | |

Opérateurs d'égalité

| | | | lhs == rhs | (5) | | | | lhs != rhs | (6) | | |

  1. Renvoie true si lhs est inférieur à rhs, false sinon.

  2. Renvoie true si lhs est supérieur à rhs, false sinon.

  3. Renvoie true si lhs est inférieur ou égal à rhs, false sinon.

  4. Renvoie true si lhs est supérieur ou égal à rhs, false sinon.

  5. Renvoie true si lhs est égal à rhs, false sinon.

  6. Renvoie true si lhs est différent de rhs, false sinon.

Opérateurs de comparaison à trois voies intégrés à deux voies

Pour les opérateurs de comparaison à deux voies intégrés, des conversions lvalue-vers-rvalue, conversions tableau-vers-pointeur (jusqu'à C++26) et des conversions fonction-vers-pointeur sont appliquées à lhs et rhs ﻿.

La comparaison est obsolète si lhs et rhs ont tous deux un type tableau avant l'application de ces conversions.

(depuis C++20) (jusqu'à C++26)

Pour les opérateurs relationnels intégrés, si l'un des opérandes est un pointeur, la conversion tableau-vers-pointeur est effectuée sur l'autre opérande.

Pour les opérateurs d'égalité intégrés, si l'un des opérandes est un pointeur ou une constante de pointeur nul, la conversion tableau-vers-pointeur est effectuée sur l'autre opérande.

(depuis C++26)

Pour les opérateurs de comparaison à deux voies intégrés, le résultat est une prvalue bool.

Comparaison arithmétique intégrée

Si les opérandes convertis ont tous deux un type arithmétique ou énumération (à portée ou non), les conversions arithmétiques usuelles sont effectuées sur les deux opérandes. Les valeurs sont comparées après conversions :

#include <iostream>

int main()
{
    static_assert(sizeof(unsigned char) < sizeof(int),
                  "Cannot compare signed and smaller unsigned properly");
    int a = -1;
    int b = 1;
    unsigned int c = 1;
    unsigned char d = 1;

    std::cout << std::boolalpha
              << "Comparing two signed values:\n"
                 " -1 == 1 ? " << (a == b) << "\n"
                 " -1 <  1 ? " << (a <  b) << "\n"
                 " -1 >  1 ? " << (a >  b) << "\n"
                 "Comparing signed and unsigned:\n"
                 // peut émettre un avertissement de signe différent :
                 " -1 == 1 ? " << (a == c) << "\n"
                 // peut émettre un avertissement de signe différent :
                 " -1 <  1 ? " << (a <  c) << "\n"
                 // peut émettre un avertissement de signe différent :
                 " -1 >  1 ? " << (a >  c) << "\n"
                 "Comparing signed and smaller unsigned:\n"
                 " -1 == 1 ? " << (a == d) << "\n"
                 " -1 <  1 ? " << (a <  d) << "\n"
                 " -1 >  1 ? " << (a >  d) << '\n';
}

Output:

Comparing two signed values:
 -1 == 1 ? false
 -1 <  1 ? true
 -1 >  1 ? false
Comparing signed and unsigned:
 -1 == 1 ? false
 -1 <  1 ? false
 -1 >  1 ? true
Comparing signed and smaller unsigned:
 -1 == 1 ? false
 -1 <  1 ? true
 -1 >  1 ? false

Comparaison intégrée d'égalité de pointeurs

Les opérandes convertis des opérateurs d'égalité == et != peuvent aussi avoirle type std::nullptr_t, (depuis C++11) un type pointeur ou un type pointeur vers membre.

La comparaison intégrée d'égalité de pointeurs a trois résultats possibles : égal, différent et non spécifié. Les valeurs produites par les opérateurs d'égalité pour la comparaison intégrée d'égalité de pointeurs sont listées ci-dessous :

Résultat de la comparaison
de p et q | Valeur produite par

p == q | p != q

equal | true | false

unequal | false | true

unspecified | valeur non spécifiée bool

Si au moins l'un des opérandes convertis lhs et rhs est un pointeur, des conversions de pointeurs, conversions de pointeurs de fonction (depuis C++17) et des conversions de qualification sont effectuées sur les deux opérandes convertis pour les amener à leur type pointeur composé. Les deux pointeurs du type pointeur composé sont comparés comme suit :

  • Si un pointeur représente l'adresse d'un objet complet, et un autre pointeur

    • représente l'adresse située juste après la fin d'un objet complet différent non tableau, ou
    • représente l'adresse située juste après le dernier élément d'un objet tableau complet différent, le résultat de la comparaison est non spécifié.

  • Sinon, si les pointeurs sont tous deux nuls, pointent tous deux vers la même fonction, ou représentent tous deux la même adresse (c.-à-d. qu'ils pointent vers le même objet ou juste après sa fin), ils sont égaux.

  • Sinon, les pointeurs sont différents.

Si au moins l'un des opérandes convertis lhs et rhs est un pointeur vers membre, des conversions de pointeurs vers membre, conversions de pointeurs de fonction (depuis C++17) et des conversions de qualification sont effectuées sur les deux opérandes convertis pour les amener à leur type pointeur composé. Les deux pointeurs vers membres du type pointeur composé sont comparés comme suit :

  • Si deux pointeurs vers membres sont tous deux la valeur de pointeur vers membre nul, ils sont égaux.
  • Si un seul des deux pointeurs vers membres est la valeur de pointeur vers membre nul, ils sont différents.
  • Si l'un d'eux est un pointeur vers une fonction membre virtuelle, le résultat est non spécifié.
  • Si l'un fait référence à un membre de la classe C1 et l'autre à un membre d'une classe différente C2, où aucune n'est une classe de base de l'autre, le résultat est non spécifié.
  • Si les deux font référence à des membres (éventuellement différents) de la même union, ils sont égaux.
  • Sinon, deux pointeurs vers membres sont égaux s'ils feraient référence au même membre du même objet le plus dérivé ou au même sous-objet si une indirection avec un objet hypothétique du type de classe associé était effectuée ; sinon ils sont différents.
struct P {};
struct Q : P { int x; };
struct R : P { int x; };

int P::*bx = (int(P::*)) &Q::x;
int P::*cx = (int(P::*)) &R::x;

bool b1 = (bx == cx); // unspecified

struct B
{
    int f();
};
struct L : B {};
struct R : B {};
struct D : L, R {};

int (B::*pb)() = &B::f;
int (L::*pl)() = pb;
int (R::*pr)() = pb;
int (D::*pdl)() = pl;
int (D::*pdr)() = pr;

bool x = (pdl == pdr); // false
bool y = (pb == pl);   // true

Deux opérandes de type std::nullptr_t ou un opérande de type std::nullptr_t et l'autre une constante de pointeur nul sont égaux.

(depuis C++11)

Comparaison relationnelle intégrée de pointeurs

Les opérandes convertis des opérateurs relationnels >, <, >= et <= peuvent aussi avoir un type pointeur.

La comparaison relationnelle intégrée de pointeurs sur des pointeurs différents p et q a trois résultats possibles : p est supérieur, q est supérieur et non spécifié. Les valeurs produites par les opérateurs relationnels pour la comparaison relationnelle intégrée de pointeurs sont listées ci-dessous :

Résultat de la comparaison
de p et q | Valeur produite par

p > q | p < q | p >= q | p <= q

equal | false | false | true | true

p est supérieur | true | false | true | false

q est supérieur | false | true | false | true

unspecified | valeur non spécifiée bool

Si lhs et rhs convertis sont tous deux des pointeurs, des conversions de pointeurs, conversions de pointeurs de fonction (depuis C++17) et des conversions de qualification sont effectuées sur les deux opérandes convertis pour les amener à leur type pointeur composé. Les deux pointeurs du type pointeur composé sont comparés comme suit :

  • Si les pointeurs sont égaux ou si le résultat de la comparaison d'égalité est non spécifié, le résultat de la comparaison relationnelle appartient à la même catégorie.

  • Sinon (les pointeurs sont différents), si l'un des pointeurs n'est pas un pointeur vers un objet, le résultat est non spécifié.

  • Sinon (les deux pointeurs pointent vers des objets), le résultat est défini par un ordre partiel conforme aux règles suivantes :

    • Étant donnés deux éléments différents high et low d'un tableau tels que high a un indice plus élevé que low, si un pointeur pointe vers high (ou un sous-objet de high) et l'autre pointeur pointe vers low (ou un sous-objet de low), le premier est supérieur au second.
    • Si un pointeur pointe vers un élément elem (ou vers un sous-objet de elem) d'un tableau, et l'autre pointeur est situé juste après la fin du même tableau, le pointeur situé après la fin est supérieur à l'autre pointeur.
    • Si un pointeur pointe vers un objet complet, un sous-objet de classe de base ou un sous-objet membre obj (ou vers un sous-objet de obj), et l'autre pointeur est situé après la fin de obj, le pointeur situé après la fin est supérieur à l'autre pointeur.

  • Si les pointeurs pointent vers des membres de données non statiques de taille non nulle (depuis C++20) différentsavec le même accès membre (jusqu'à C++23) du même objet d'une classe non union, ou vers des sous-objets de tels membres, récursivement, le pointeur vers le membre déclaré le plus tard est supérieur à l'autre pointeur.

  • Sinon, le résultat est non spécifié.

Ordre total des pointeurs

Il existe dans chaque programme un ordre total strict défini par l'implémentation sur les pointeurs. Cet ordre total strict est cohérent avec l'ordre partiel décrit ci-dessus : les résultats non spécifiés deviennent définis par l'implémentation, tandis que les autres résultats restent inchangés.

La comparaison de pointeurs selon l'ordre total strict est appliquée dans les cas suivants :

  • Appel de l'operator() des spécialisations de types pointeurs de std::less, std::greater, std::less_equal, et std::greater_equal.
  • Appel des opérateurs intégrés comparant des pointeurs de la operator() des spécialisations std::less<void>, std::greater<void>, std::less_equal<void>, et std::greater_equal<void>.

(depuis C++14)

  • Appel de l'operator<=> intégré comparant des pointeurs de la operator() de std::compare_three_way.
  • Appel de l'operator== intégré comparant des pointeurs de la operator() de std::ranges::equal_to et std::ranges::not_equal_to.
  • Appel de l'operator< intégré comparant des pointeurs de la operator() de std::ranges::less, std::ranges::greater, std::ranges::less_equal, et std::ranges::greater_equal.

(depuis C++20)

Surcharges

Dans la résolution de surcharge face aux opérateurs définis par l'utilisateur, pour chaque paire de types arithmétiques promus L et R, y compris les types énumération, les signatures de fonctions suivantes participent à la résolution de surcharge :

bool operator<(L, R);

bool operator>(L, R);

bool operator<=(L, R);

bool operator>=(L, R);

bool operator==(L, R);

bool operator!=(L, R);

Pour chaque type P qui est soit un pointeur vers objet, soit un pointeur vers fonction, les signatures de fonctions suivantes participent à la résolution de surcharge :

bool operator<(P, P);

bool operator>(P, P);

bool operator<=(P, P);

bool operator>=(P, P);

bool operator==(P, P);

bool operator!=(P, P);

Pour chaque type MP qui est un pointeur vers donnée membre ou un pointeur vers fonction membreou std::nullptr_t (depuis C++11), les signatures de fonctions suivantes participent à la résolution de surcharge :

bool operator==(MP, MP);

bool operator!=(MP, MP);

#include <iostream>

struct Foo
{
    int n1;
    int n2;
};

union Union
{
    int n;
    double d;
};

int main()
{
    std::cout << std::boolalpha;

    char a[4] = "abc";
    char* p1 = &a[1];
    char* p2 = &a[2];
    std::cout << "Pointers to array elements:\n"
              << "p1 == p2? " << (p1 == p2) << '\n'
              << "p1 <  p2? " << (p1 <  p2) << '\n';

    Foo f;
    int* p3 = &f.n1;
    int* p4 = &f.n2;
    std::cout << "Pointers to members of a class:\n"
              << "p3 == p4? " << (p3 == p4) << '\n'
              << "p3 <  p4? " << (p3 <  p4) << '\n';

    Union u;
    int* p5 = &u.n;
    double* p6 = &u.d;
    std::cout << "Pointers to members of a union:\n"
              << "p5 == (void*)p6? " << (p5 == (void*)p6) << '\n'
              << "p5 <  (void*)p6? " << (p5 <  (void*)p6) << '\n';
}

Output:

Pointers to array elements:
p1 == p2? false
p1 <  p2? true
Pointers to members of a class:
p3 == p4? false
p3 <  p4? true
Pointers to members of a union:
p5 == (void*)p6? true
p5 <  (void*)p6? false

Comparaison à trois voies

Les expressions de l'opérateur de comparaison à trois voies ont la forme

a <=> b

L'expression renvoie un objet tel que

  • (a <=> b) < 0 if a < b,
  • (a <=> b) > 0 if a > b,
  • (a <=> b) == 0 si a et b sont égaux/équivalents.

Si l'un des opérandes est de type bool et l'autre non, le programme est mal formé.

Si les deux opérandes ont des types arithmétiques, ou si l'un des opérandes a un type énumération sans portée et l'autre un type entier, les conversions arithmétiques usuelles sont appliquées aux opérandes, puis

  • Si une conversion restrictive est requise, autre qu'une conversion d'un type entier vers un type virgule flottante, le programme est mal formé.

  • Sinon, si les opérandes ont un type entier, l'opérateur produit une prvalue de type std::strong_ordering :

  • std::strong_ordering::equal si les deux opérandes sont arithmétiquement égaux,

  • std::strong_ordering::less si le premier opérande est arithmétiquement inférieur au second,

  • std::strong_ordering::greater sinon.

  • Sinon, les opérandes ont un type virgule flottante, et l'opérateur produit une prvalue de type std::partial_ordering. L'expression a <=> b donne

  • std::partial_ordering::less si a est inférieur à b,

  • std::partial_ordering::greater si a est supérieur à b,

  • std::partial_ordering::equivalent si a est équivalent à b (-0 <=> +0 est équivalent),

  • std::partial_ordering::unordered (NaN <=> anything est non ordonné).

Si les deux opérandes ont le même type énumération E, l'opérateur renvoie le résultat de la conversion des opérandes vers le type sous-jacent de E et de l'application de <=> aux opérandes convertis.

Si au moins l'un des opérandes est un pointeur vers objet ou un pointeur vers membre, des conversions tableau-vers-pointeur, des conversions de pointeurs et des conversions de qualification sont appliquées aux deux opérandes pour les amener à leur type pointeur composé.

Pour les opérandes pointeurs convertis p et q, p <=> q renvoie une prvalue de type std::strong_ordering :

  • std::strong_ordering::equal si ils comparent égaux,
  • std::strong_ordering::less si q compare supérieur à p,
  • std::strong_ordering::greater si p compare supérieur à q,
  • résultat non spécifié si le résultat de la comparaison à trois voies est non spécifié.

Sinon, le programme est mal formé.

Surcharges

Lors de la résolution de surcharge face aux opérateurs définis par l'utilisateur, pour un type pointeur ou énumération T, la signature de fonction suivante participe à la résolution de surcharge :

R operator<=>(T, T);

Où R est le type de catégorie d'ordre défini ci-dessus.

#include <compare>
#include <iostream>

int main()
{
    double foo = -0.0;
    double bar = 0.0;

    auto res = foo <=> bar;

    if (res < 0)
        std::cout << "-0 is less than 0";
    else if (res > 0)
        std::cout << "-0 is greater than 0";
    else if (res == 0)
        std::cout << "-0 and 0 are equal";
    else
        std::cout << "-0 and 0 are unordered";
}

Output:

-0 and 0 are equal

(depuis C++20)

Notes

Comme les opérateurs de comparaison se regroupent de gauche à droite, l'expression a < b < c est analysée comme (a < b) < c, et non comme a < (b < c) ou (a < b) && (b < c).

#include <iostream>

int main()
{
    int a = 3, b = 2, c = 1;

    std::cout << std::boolalpha
        << (a < b < c) << '\n' // true ; avertissement possible
        << ((a < b) < c) << '\n' // true
        << (a < (b < c)) << '\n' // false
        << ((a < b) && (b < c)) << '\n'; // false
}

Une exigence courante pour un operator< défini par l'utilisateur est un ordre faible strict. En particulier, cela est requis par les algorithmes standard et les conteneurs qui travaillent avec des types Compare : std::sort, std::max_element, std::map, etc.

Le résultat de comparaison de pointeurs vers différents membres de données non statiques d'une même classe implique que les membres de données non statiquesdans chacun des trois modes d'accès membres (jusqu'à C++23) sont positionnés en mémoire dans l'ordre de déclaration.

Bien que les résultats de la comparaison de pointeurs d'origine quelconque (par exemple, non tous pointant vers des membres d'un même tableau) soient non spécifiés, de nombreuses implémentations fournissent un ordre total strict des pointeurs, par exemple si elles sont implémentées comme des adresses dans un espace d'adressage virtuel continu. Les implémentations qui ne le font pas (par exemple lorsque tous les bits du pointeur ne font pas partie d'une adresse mémoire et doivent être ignorés pour la comparaison, ou lorsqu'un calcul supplémentaire est nécessaire, ou qu'autrement la relation entre pointeur et entier n'est pas biunivoque) fournissent une spécialisation de std::less pour les pointeurs qui offre cette garantie. Cela permet d'utiliser tous les pointeurs d'origine quelconque comme clés dans des conteneurs associatifs standard tels que std::set ou std::map.

Pour les types qui sont à la fois EqualityComparable et LessThanComparable, la bibliothèque standard C++ distingue l'égalité, qui est la valeur de l'expression a == b, et l'équivalence, qui est la valeur de l'expression !(a < b) && !(b < a).

La comparaison entre pointeurs et constantes de pointeur nul a été supprimée par la résolution du CWG issue 583 incluse dans N3624 :

void f(char* p)
{
    if (p > 0) { /*...*/ } // Erreur avec N3624, compilé avant N3624
    if (p > nullptr) { /*...*/ } // Erreur avec N3624, compilé avant N3624
}

int main() {}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 583 (N3624) C++98 les six opérateurs de comparaison pouvaient être utilisés pour comparer un pointeur avec une constante de pointeur nul seuls les opérateurs d'égalité étaient autorisés
CWG 661 C++98 la sémantique réelle des comparaisons arithmétiques (par exemple si 1 < 2 donne true ou false) était non spécifiée spécification ajoutée
CWG 879 C++98 les pointeurs vers des types fonctions et les pointeurs vers void ne disposaient pas de comparaisons intégrées ajout d'une spécification de comparaison pour ces pointeurs
CWG 1596 C++98 les objets non tableaux étaient considérés comme appartenant à des tableaux ayant un seul élément uniquement pour les besoins de l'arithmétique des pointeurs la règle est également appliquée à la comparaison
CWG 1598 C++98 deux pointeurs vers des membres de classes différentes et dont aucune n'est la classe de base de l'autre n'étaient pas égaux même si les décalages des membres pointés pouvaient être identiques le résultat est non spécifié dans ce cas
CWG 1858 C++98 il n'était pas clair si deux pointeurs vers des membres qui désignent des membres différents d'une même union étaient égaux comme s'ils désignaient le même membre ils sont égaux dans ce cas
CWG 2419 C++98 un pointeur vers un objet non tableau n'était traité comme un pointeur vers le premier élément d'un tableau de taille 1 dans la comparaison de pointeurs que si le pointeur est obtenu par & s'applique à tous les pointeurs vers des objets non tableau
CWG 2526 C++98 la définition de la comparaison relationnelle (>, >=, < et <=) des pointeurs vers void et des pointeurs de fonction a été supprimée par N3624 restored
CWG 2796 C++17 les conversions de pointeurs de fonction n'étaient pas effectuées sur les opérandes pointeurs convertis lors des comparaisons relationnelles intégrées de pointeurs effectue ces conversions dans ce cas
