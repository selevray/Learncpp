Adresse d'une fonction surchargée

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

En plus des expressions d'appel de fonction, où a lieu la résolution de surcharge, le nom d'une fonction surchargée peut apparaître dans les 7 contextes suivants :

Contexte Cible
initialiseur dans une déclaration d'un objet ou d'une référence l'objet ou la référence initialisé
à droite d'une expression d'affectation le côté gauche de l'affectation
en tant qu'argument d'appel de fonction le paramètre de la fonction
en tant qu'argument d'un opérateur défini par l'utilisateur le paramètre de l'opérateur
l'instruction return la valeur de retour d'une fonction ou d'une conversion
cast explicite ou argument static_cast le transtypage correspondant
argument de modèle non de type le paramètre de modèle correspondant

Dans chaque contexte, le nom d'une fonction surchargée peut être précédé de l'opérateur d'adresse & et peut être entouré d'un ensemble redondant de parenthèses.

Si le type cible contient un type substitut, la déduction du type substitut est effectuée, et la description suivante utilise le type déduit comme type cible.

(depuis C++26)

Sélection des fonctions

Lorsque l'adresse d'une fonction surchargée est prise, un ensemble S de fonctions est sélectionné dans l'ensemble de surcharge désigné par le nom de la fonction surchargée :

  • S'il n'y a pas de cible, toutes les fonctions non modèles portant ce nom sont sélectionnées.
  • Sinon, une fonction non modèle de type F est sélectionnée pour le type de fonction FT du type cible si F(après application éventuelle de la conversion de pointeur de fonction) (depuis C++17) est identique à FT.[1]
  • La spécialisation (le cas échéant) générée par la déduction d'arguments de modèle pour chaque modèle de fonction nommé est également ajoutée à S.

Si la cible est de type pointeur de fonction ou de type référence de fonction, S ne peut contenir que des fonctions non membres, des fonctions membres à objet explicite (depuis C++23) et des fonctions membres statiques. Si la cible est de type pointeur vers fonction membre, S ne peut contenir que des fonctions membres à objet implicite.

  1. ↑ Autrement dit, la classe dont la fonction est membre est ignorée si le type cible est un type pointeur vers fonction membre.

Élimination des fonctions

Après la formation de l'ensemble S, les fonctions sont éliminées dans l'ordre suivant :

  • Toutes les fonctions dont les contraintes associées ne sont pas satisfaites sont éliminées de S.

(depuis C++20)

  • Si plus d'une fonction de S subsiste, toutes les spécialisations de modèles de fonctions de S sont éliminées si S contient également une fonction non modèle.
  • Toute fonction non modèle donnée func est éliminée si S contient une seconde fonction non modèle qui est plus contrainte par ordre partiel que func.

(depuis C++20)

  • Toute spécialisation de modèle de fonction donnée spec est éliminée si S contient une seconde spécialisation de modèle de fonction dont le modèle de fonction est plus spécialisé que le modèle de fonction de spec.

Après ces éliminations (le cas échéant), exactement une fonction sélectionnée doit subsister dans S. Sinon, le programme est mal formé.

Exemple

int f(int) { return 1; }
int f(double) { return 2; }

void g(int(&f1)(int), int(*f2)(double)) { f1(0); f2(0.0); }

template<int(*F)(int)>
struct Templ {};

struct Foo
{
    int mf(int) { return 3; }
    int mf(double) { return 4; }
};

struct Emp
{
    void operator<<(int (*)(double)) {}
};

int main()
{
    // 1. initialization
    int (*pf)(double) = f; // sélectionne int f(double)
    int (&rf)(int) = f; // sélectionne int f(int)
    int (Foo::*mpf)(int) = &Foo::mf; // sélectionne int mf(int)

    // 2. assignment
    pf = nullptr;
    pf = &f; // sélectionne int f(double)

    // 3. argument de fonction
    g(f, f); // sélectionne int f(int) pour le 1er argument
             // et int f(double) pour le second

    // 4. opérateur défini par l'utilisateur
    Emp{} << f; //sélectionne int f(double)

    // 5. valeur de retour
    auto foo = []() -> int (*)(int)
    {
        return f; // sélectionne int f(int)
    };

    // 6. cast
    auto p = static_cast<int(*)(int)>(f); // sélectionne int f(int)

    // 7. argument de modèle
    Templ<f> t;  // sélectionne int f(int)

    // empêche les avertissements « variable inutilisée » comme si par [[maybe_unused]]
    [](...){}(pf, rf, mpf, foo, p, t);
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 202 C++98 l'argument de modèle non de type n'était pas un contexte de prise d'adresse d'une fonction surchargée c'est le cas
CWG 250 C++98 les spécialisations de modèles de fonctions générées avec des arguments de modèle non déduits n'étaient pas sélectionnées dans l'ensemble de surcharge également sélectionnée
CWG 1153 C++98 il n'était pas clair si un type de fonction donné correspondait au type cible rendu clair
CWG 1563 C++11 il n'était pas clair si l'initialisation par liste était un contexte de prise d'adresse d'une fonction surchargée rendu clair
