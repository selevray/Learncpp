Pack (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un pack est une entité C++ qui définit l'un des éléments suivants :

  • un pack de paramètres
    • un pack de paramètres de modèle
    • un pack de paramètres de fonction
  • pack de captures init de lambda

(depuis C++20)

  • pack de liaisons structurées

(depuis C++26)

Un pack de paramètres de modèle est un paramètre de modèle qui accepte zéro ou plusieurs arguments de modèle (non types, types ou modèles). Un pack de paramètres de fonction est un paramètre de fonction qui accepte zéro ou plusieurs arguments de fonction.

Un pack de captures init de lambda est une capture de lambda qui introduit une init-capture pour chacun des éléments de l'expansion de pack de son initialiseur.

(depuis C++20)

Un pack de liaisons structurées est un identifiant de la déclaration de liaison structurée qui introduit zéro ou plusieurs liaisons structurées.

(depuis C++26)

Le nombre d'éléments d'un pack est égal à :

  • le nombre d'arguments fournis pour le paramètre pack, si le pack est un pack de paramètres de modèle ou de fonction,
  • le nombre d'éléments de l'expansion de pack de son initialiseur, si le pack est un pack de captures init de lambda,

(depuis C++20)

  • la taille de liaison structurée de l'initialiseur moins le nombre d'éléments non-pack de la déclaration de liaison structurée, si le pack est un pack de liaisons structurées.

(depuis C++26)

Un modèle avec au moins un paramètre pack est appelé modèle variadique.

Explication

Un modèle de classe variadique peut être instancié avec un nombre quelconque d'arguments de modèle :

template<class... Types>
struct Tuple {};

Tuple<> t0;           // Types ne contient aucun argument
Tuple<int> t1;        // Types contient un argument : int
Tuple<int, float> t2; // Types contient deux arguments : int et float
Tuple<0> t3;          // erreur : 0 n'est pas un type

Un modèle de fonction variadique peut être appelé avec un nombre quelconque d'arguments de fonction (les arguments de modèle sont déduits par déduction d'arguments de modèle) :

template<class... Types>
void f(Types... args);

f();       // OK : args ne contient aucun argument
f(1);      // OK : args contient un argument : int
f(2, 1.0); // OK : args contient deux arguments : int et double

Dans un modèle de classe primaire, le pack de paramètres de modèle doit être le dernier paramètre de la liste des paramètres de modèle. Dans un modèle de fonction, le pack de paramètres de modèle peut apparaître plus tôt dans la liste, à condition que tous les paramètres suivants puissent être déduits des arguments de fonction, ou aient des arguments par défaut :

template<typename U, typename... Ts>    // OK : peut déduire U
struct valid;
// template<typename... Ts, typename U> // Erreur : Ts... n'est pas à la fin
// struct Invalid;

template<typename... Ts, typename U, typename=void>
void valid(U, Ts...);    // OK : peut déduire U
// void valid(Ts..., U); // Inutilisable : Ts... est un contexte non déductible à cette position

valid(1.0, 1, 2, 3);     // OK : déduit U comme double, Ts comme {int, int, int}

Si chaque spécialisation valide d'un modèle variadique requiert un pack de paramètres de modèle vide, le programme est mal formé, aucun diagnostic requis.

Expansion de pack

Un motif suivi d'une ellipse, dans lequel le nom d'au moins un pack apparaît au moins une fois, est développé en zéro ou plusieurs instanciations du motif, où le nom du pack est remplacé par chacun des éléments du pack, dans l'ordre. Les instanciations de spécificateurs d'alignement sont séparées par des espaces, les autres instanciations sont séparées par des virgules.

template<class... Us>
void f(Us... pargs) {}

template<class... Ts>
void g(Ts... args)
{
    f(&args...); // « &args... » est une expansion de pack
                 // « &args » est son motif
}

g(1, 0.2, "a"); // Ts... args se développe en int E1, double E2, const char* E3
                // &args... se développe en &E1, &E2, &E3
                // Us... pargs se développe en int* E1, double* E2, const char** E3

Si les noms de deux packs apparaissent dans le même motif, ils sont développés simultanément, et ils doivent avoir la même longueur :

template<typename...>
struct Tuple {};

template<typename T1, typename T2>
struct Pair {};

template<class... Args1>
struct zip
{
    template<class... Args2>
    struct with
    {
        typedef Tuple<Pair<Args1, Args2>...> type;
        // Pair<Args1, Args2>... est l'expansion de pack
        // Pair<Args1, Args2> est le motif
    };
};

typedef zip<short, int>::with<unsigned short, unsigned>::type T1;
// Pair<Args1, Args2>... se développe en
// Pair<short, unsigned short>, Pair<int, unsigned int>
// T1 est Tuple<Pair<short, unsigned short>, Pair<int, unsigned>>

// typedef zip<short>::with<unsigned short, unsigned>::type T2;
// error: l'expansion de pack contient des packs de longueurs différentes

Si une expansion de pack est imbriquée dans une autre expansion de pack, les packs qui apparaissent à l'intérieur de l'expansion la plus interne sont développés par celle-ci, et il doit y avoir un autre pack mentionné dans l'expansion englobante, mais pas dans la plus interne :

template<class... Args>
void g(Args... args)
{
    f(const_cast<const Args*>(&args)...);
    // const_cast<const Args*>(&args) est le motif, il développe deux packs
    // (Args et args) simultanément

    f(h(args...) + args...); // Expansion de pack imbriquée :
    // l'expansion de pack interne est « args... », elle est développée en premier
    // l'expansion de pack externe est h(E1, E2, E3) + args..., elle est développée
    // en second (comme h(E1, E2, E3) + E1, h(E1, E2, E3) + E2, h(E1, E2, E3) + E3)
}

Lorsque le nombre d'éléments d'un pack est nul (pack vide), l'instanciation d'une expansion de pack ne modifie pas l'interprétation syntaxique de la construction englobante, même dans les cas où omettre entièrement l'expansion de pack serait mal formé ou entraînerait une ambiguïté syntaxique. L'instanciation produit une liste vide.

template<class... Bases>
struct X : Bases... { };

template<class... Args>
void f(Args... args)
{
    X<Args...> x(args...);
}

template void f<>(); // OK, X<> n'a aucune classe de base
                     // x est une variable de type X<> initialisée par valeur

Lieux d'expansion

Selon l'endroit où l'expansion a lieu, la liste résultante séparée par des virgules (ou par des espaces pour les spécificateurs d'alignement) est un type de liste différent : liste de paramètres de fonction, liste d'initialisation de membres, liste d'attributs, etc. Voici la liste de tous les contextes autorisés :

Listes d'arguments de fonction

Une expansion de pack peut apparaître entre les parenthèses d'un opérateur d'appel de fonction, auquel cas la plus grande expression ou liste d'initialisation entre accolades située à gauche de l'ellipse est le motif développé :

f(args...);              // se développe en f(E1, E2, E3)
f(&args...);             // se développe en f(&E1, &E2, &E3)
f(n, ++args...);         // se développe en f(n, ++E1, ++E2, ++E3);
f(++args..., n);         // se développe en f(++E1, ++E2, ++E3, n);

f(const_cast<const Args*>(&args)...);
// f(const_cast<const E1*>(&X1), const_cast<const E2*>(&X2), const_cast<const E3*>(&X3))

f(h(args...) + args...); // se développe en
// f(h(E1, E2, E3) + E1, h(E1, E2, E3) + E2, h(E1, E2, E3) + E3)

Initialiseurs entre parenthèses

Une expansion de pack peut apparaître entre les parenthèses d'un initialiseur direct, d'une conversion de style fonctionnel, ainsi que dans d'autres contextes (initialiseur de membre, expression new, etc.) où les règles sont identiques à celles de l'expression d'appel de fonction ci-dessus :

Class c1(&args...);             // appelle Class::Class(&E1, &E2, &E3)
Class c2 = Class(n, ++args...); // appelle Class::Class(n, ++E1, ++E2, ++E3);

::new((void *)p) U(std::forward<Args>(args)...) // std::allocator::allocate

Initialiseurs entre accolades

Dans une liste d'initialisation entre accolades, une expansion de pack peut également apparaître :

template<typename... Ts>
void func(Ts... args)
{
    const int size = sizeof...(args) + 2;
    int res[size] = {1, args..., 2};

    // comme les listes d'initialisation garantissent l'ordre d'évaluation, cela peut être utilisé pour
    // appeler une fonction sur chaque élément d'un paquet, dans l'ordre :
    int dummy[sizeof...(Ts)] = {(std::cout << args, 0)...};
}

Listes d'arguments de modèle

Les expansions de pack peuvent être utilisées n'importe où dans une liste d'arguments de modèle, à condition que le modèle ait les paramètres correspondant à l'expansion :

template<class A, class B, class... C>
void func(A arg1, B arg2, C... arg3)
{
    container<A, B, C...> t1; // se développe en container<A, B, E1, E2, E3>
    container<C..., A, B> t2; // se développe en container<E1, E2, E3, A, B>
    container<A, C..., B> t3; // se développe en container<A, E1, E2, E3, B>
}

Liste des paramètres de fonction

Dans une liste de paramètres de fonction, si une ellipse apparaît dans une déclaration de paramètre (qu'elle nomme un pack de paramètres de fonction, comme dans Args... args, ou non), la déclaration de paramètre est le motif :

template<typename... Ts>
void f(Ts...) {}

f('a', 1); // Ts... se développe en void f(char, int)
f(0.1);    // Ts... se développe en void f(double)

template<typename... Ts, int... N>
void g(Ts (&...arr)[N]) {}

int n[1];

g<const char, int>("a", n); // Ts (&...arr)[N] se développe en
                            // const char (&)[2], int(&)[1]

Remarque : dans le motif Ts (&...arr)[N], l'ellipse est l'élément le plus interne, et non le dernier élément comme dans toutes les autres expansions de pack.

Remarque : Ts (&...)[N] n'est pas autorisé car la grammaire C++11 exige que l'ellipse entre parenthèses ait un nom : problème CWG 1488.

Liste des paramètres de modèle

Une expansion de pack peut apparaître dans une liste de paramètres de modèle :

template<typename... T>
struct value_holder
{
    template<T... Values> // se développe en un paramètre de modèle non typé
    struct apply {};      // liste, telle que <int, char, int(&)[5]>
};

Spécificateurs de base et listes d'initialisation des membres

Une expansion de pack peut désigner la liste des classes de base dans une déclaration de classe. En général, cela implique aussi que le constructeur doit utiliser une expansion de pack dans la liste d'initialisation des membres pour appeler les constructeurs de ces bases :

template<class... Mixins>
class X : public Mixins...
{
public:
    X(const Mixins&... mixins) : Mixins(mixins)... {}
};

Captures des lambdas

Une expansion de pack peut apparaître dans la clause de capture d'une expression lambda :

template<class... Args>
void f(Args... args)
{
    auto lm = [&, args...] { return g(args...); };
    lm();
}

L'opérateur sizeof...

L'opérateur sizeof... est lui aussi classé comme expansion de pack :

template<class... Types>
struct count
{
    static const std::size_t value = sizeof...(Types);
};

Spécifications d'exceptions dynamiques

La liste des exceptions d'une spécification d'exceptions dynamique peut aussi être une expansion de pack :

template<class... X>
void func(int arg) throw(X...)
{
    // ... lève différentes X selon les situations
}

(jusqu'à C++17)

Spécificateur d'alignement

Les expansions de pack sont autorisées dans les listes de types et les listes d'expressions utilisées par le mot-clé alignas. Les instanciations sont séparées par des espaces :

template<class... T>
struct Align
{
    alignas(T...) unsigned char buffer[128];
};

Align<int, short> a; // les spécificateurs d'alignement après développement sont
                     // alignas(int) alignas(short)
                     // (sans virgule entre eux)

Liste d'attributs

Les expansions de pack sont autorisées dans les listes d'attributs, si la spécification de l'attribut le permet. Par exemple :

template<int... args>
[[vendor::attr(args)...]] void* f();

Expressions de pliage

Dans les expressions de pliage, le motif est la sous-expression entière qui ne contient pas de pack non développé.

Déclarations using

Dans les déclarations using, une ellipse peut apparaître dans la liste des déclarateurs, ce qui est utile lors de la dérivation d'un pack de paramètres de modèle :

template<typename... bases>
struct X : bases...
{
    using bases::g...;
};
X<B, D> x; // OK : B::g et D::g introduits

(depuis C++17)

Indexation de packs

Dans l'indexation de pack, l'expansion de pack contient un pack non développé suivi d'une ellipse et d'un indice. Le motif de l'expression d'indexation de pack est un identifier, tandis que le motif du spécificateur d'indexation de pack est un typedef-name.

consteval auto first_plus_last(auto... args)
{
    return args...[0] + args...[sizeof...(args) - 1];
}

static_assert(first_plus_last(5) == 10);
static_assert(first_plus_last(5, 4) == 9);
static_assert(first_plus_last(5, 6, 2) == 7);

Déclarations d'amitié

Dans les déclarations d'amitié de classe, chaque spécificateur de type peut être suivi d'une ellipse :

struct C {};
struct E { struct Nested; };

template<class... Ts>
class R
{
    friend Ts...;
};

template<class... Ts, class... Us>
class R<R<Ts...>, R<Us...>>
{
    friend Ts::Nested..., Us...;
};

R<C, E> rce;           // les classes C et E sont amies de R<C, E>
R<R<E>, R<C, int>> rr; // E::Nested et C sont amis de R<R<E>, R<C, int>>

Contraintes d'expansion de pliage

Dans les contraintes à expansion de pliage, le motif est la contrainte de cette contrainte à expansion de pliage.

Une contrainte à expansion de pliage n'est pas instanciée.

(depuis C++26)

Exemple

L'exemple ci-dessous définit une fonction semblable à std::printf, qui remplace chaque occurrence du caractère % dans la chaîne de format par une valeur.

La première surcharge est appelée lorsque seule la chaîne de format est passée et qu'il n'y a pas d'expansion de paramètres.

La seconde surcharge contient un paramètre de modèle distinct pour la tête des arguments et un pack de paramètres, ce qui permet à l'appel récursif de ne passer que la queue des paramètres jusqu'à ce qu'elle soit vide.

Targs est le pack de paramètres de modèle et Fargs est le pack de paramètres de fonction.

#include <iostream>

void tprintf(const char* format) // fonction de base
{
    std::cout << format;
}

template<typename T, typename... Targs>
void tprintf(const char* format, T value, Targs... Fargs) // fonction variadique récursive
{
    for (; *format != '\0'; format++)
    {
        if (*format == '%')
        {
            std::cout << value;
            tprintf(format + 1, Fargs...); // appel récursif
            return;
        }
        std::cout << *format;
    }
}

int main()
{
    tprintf("% world% %\n", "Hello", '!', 123);
}

Output:

Hello world! 123
