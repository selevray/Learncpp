Déclaration de pointeur

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Déclare une variable de type pointeur ou pointeur vers membre.

Syntaxe

Une déclaration de pointeur est toute déclaration simple dont le déclarateur a la forme

| | | | * attr ﻿*(optionnel)* cv ﻿*(optionnel)* declarator | (1) | | | | nested-name-specifier * attr ﻿*(optionnel)* cv ﻿*(optionnel)* declarator | (2) | | |

  1. Déclarateur de pointeur : la déclaration S* D; déclare D comme un pointeur vers le type déterminé par la séquence de spécificateurs de déclaration S.

  2. Déclarateur de pointeur vers membre : la déclaration S C::* D; déclare D comme un pointeur vers un membre non statique de C de type déterminé par la séquence de spécificateurs de déclaration S.

  • nested-name-specifier — une séquence de noms et d'opérateurs de résolution de portée ::
  • attr — (depuis C++11) une liste d'attributs
  • cv — qualification const/volatile qui s'applique au pointeur déclaré (et non au type pointé, dont les qualifications font partie de la séquence de spécificateurs de déclaration)
  • declarator — tout déclarateur autre qu'un déclarateur de référence (il n'existe pas de pointeurs vers des références). Il peut s'agir d'un autre déclarateur de pointeur (les pointeurs vers pointeurs sont autorisés)

Il n'existe pas de pointeurs vers des références ni de pointeurs vers des champs de bits. En général, les mentions de « pointeurs » sans précision n'incluent pas les pointeurs vers membres (non statiques).

Pointeurs

Chaque valeur de type pointeur est l'une des suivantes :

  • un pointeur vers un objet ou une fonction (le pointeur est alors dit pointer vers l'objet ou la fonction), ou
  • un pointeur situé après la fin d'un objet, ou
  • la valeur de pointeur nul pour ce type, ou
  • une valeur de pointeur invalide.

Un pointeur qui pointe vers un objet représente l'adresse du premier octet en mémoire occupé par l'objet. Un pointeur situé après la fin d'un objet représente l'adresse du premier octet en mémoire suivant la fin de l'espace de stockage occupé par l'objet.

Notez que deux pointeurs représentant la même adresse peuvent néanmoins avoir des valeurs différentes.

struct C
{
    int x, y;
} c;

int* px = &c.x;   // la valeur de px est « pointeur vers c.x »
int* pxe= px + 1; // la valeur de pxe est « pointeur après la fin de c.x »
int* py = &c.y;   // la valeur de py est « pointeur vers c.y »

assert(pxe == py); // == teste si deux pointeurs représentent la même adresse
                   // peut ou non se déclencher

*pxe = 1; // comportement indéfini même si l'assertion ne se déclenche pas

L'indirection à travers une valeur de pointeur invalide, ainsi que le passage d'une valeur de pointeur invalide à une fonction de désallocation, ont un comportement indéfini. Toute autre utilisation d'une valeur de pointeur invalide a un comportement défini par l'implémentation. Certaines implémentations peuvent définir que la copie d'une valeur de pointeur invalide provoque une erreur d'exécution générée par le système.

Pointeurs vers des objets

Un pointeur vers objet peut être initialisé avec la valeur de retour de l'opérateur d'adresse appliqué à toute expression de type objet, y compris un autre type de pointeur :

int n;
int* np = &n;          // pointeur vers int
int* const* npp = &np; // pointeur non const vers pointeur const vers int non const

int a[2];
int (*ap)[2] = &a;     // pointeur vers tableau d'int

struct S { int n; };

S s = {1};
int* sp = &s.n;        // pointeur vers l'int qui est un membre de s

Les pointeurs peuvent apparaître comme opérandes de l'opérateur d'indirection intégré (unaire operator*), qui renvoie l'expression lvalue identifiant l'objet pointé :

int n;
int* p = &n;     // pointeur vers n
int& r = *p;     // la référence est liée à l'expression lvalue qui identifie n
r = 7;           // stocke l'int 7 dans n
std::cout << *p; // la conversion implicite lvalue-vers-rvalue lit la valeur de n

Les pointeurs vers des objets de classe peuvent aussi apparaître comme opérandes de gauche des opérateurs d'accès membre operator-> et operator->*.

En raison de la conversion implicite tableau vers pointeur, un pointeur vers le premier élément d'un tableau peut être initialisé avec une expression de type tableau :

int a[2];
int* p1 = a; // pointeur vers le premier élément a[0] (un int) du tableau a

int b[6][3][8];
int (*p2)[3][8] = b; // pointeur vers le premier élément b[0] du tableau b,
                     // qui est un tableau de 3 tableaux de 8 int

En raison de la conversion implicite dérivée vers base pour les pointeurs, un pointeur vers une classe de base peut être initialisé avec l'adresse d'une classe dérivée :

struct Base {};
struct Derived : Base {};

Derived d;
Base* p = &d;

Si Derived est polymorphe, un tel pointeur peut servir à effectuer des appels de fonctions virtuelles.

Certains opérateurs d'addition, de soustraction, d'incrémentation et de décrémentation sont définis pour les pointeurs vers les éléments de tableaux : de tels pointeurs satisfont aux exigences LegacyRandomAccessIterator et permettent aux algorithmes de la bibliothèque C++ de travailler avec des tableaux bruts.

Des opérateurs de comparaison sont définis pour les pointeurs vers des objets dans certains cas : deux pointeurs représentant la même adresse sont égaux, deux valeurs de pointeur nul sont égales, des pointeurs vers des éléments d'un même tableau se comparent comme les indices de tableau de ces éléments, et des pointeurs vers des membres de données non statiques ayant le même accès membre se comparent dans l'ordre de déclaration de ces membres.

Beaucoup d'implémentations fournissent aussi un ordre total strict sur des pointeurs d'origine quelconque, par exemple lorsqu'elles les implémentent comme des adresses dans un espace d'adressage virtuel continu. Celles qui ne le font pas (par exemple lorsque tous les bits du pointeur ne font pas partie de l'adresse mémoire et doivent être ignorés pour la comparaison, ou lorsqu'un calcul supplémentaire est nécessaire, ou lorsque pointeur et entier ne sont pas en relation biunivoque) fournissent une spécialisation de std::less pour les pointeurs qui offre cette garantie. Cela permet d'utiliser tous les pointeurs d'origine quelconque comme clés dans des conteneurs associatifs standard tels que std::set ou std::map.

Pointeurs vers void

Un pointeur vers un objet de type quelconque peut être implicitement converti en pointeur vers void (éventuellement qualifié cv) ; la valeur du pointeur est inchangée. La conversion inverse, qui nécessite static_cast ou un transtypage explicite, redonne la valeur de pointeur d'origine :

int n = 1;
int* p1 = &n;
void* pv = p1;
int* p2 = static_cast<int*>(pv);
std::cout << *p2 << '\n'; // prints 1

Si le pointeur d'origine pointe vers un sous-objet de classe de base à l'intérieur d'un objet d'un type polymorphe, dynamic_cast peut être utilisé pour obtenir un void* pointant vers l'objet complet de type le plus dérivé.

Les pointeurs vers void ont la même taille, la même représentation et le même alignement que les pointeurs vers char.

Les pointeurs vers void servent à passer des objets de type inconnu, ce qui est courant dans les interfaces C : std::malloc renvoie void*, std::qsort attend un rappel fourni par l'utilisateur qui accepte deux arguments const void*. pthread_create attend un rappel fourni par l'utilisateur qui accepte et renvoie void*. Dans tous les cas, il incombe à l'appelant de convertir le pointeur vers le bon type avant utilisation.

Pointeurs vers des fonctions

Un pointeur vers fonction peut être initialisé avec l'adresse d'une fonction non membre ou d'une fonction membre statique. En raison de la conversion implicite fonction vers pointeur, l'opérateur d'adresse est facultatif :

void f(int);
void (*p1)(int) = &f;
void (*p2)(int) = f; // identique à &f

Contrairement aux fonctions ou aux références vers des fonctions, les pointeurs vers des fonctions sont des objets et peuvent donc être stockés dans des tableaux, copiés, affectés, etc.

void (a[10])(int);  // Erreur : tableau de fonctions
void (&a[10])(int); // Erreur : tableau de références
void (*a[10])(int); // OK : tableau de pointeurs vers fonctions

Remarque : les déclarations impliquant des pointeurs vers des fonctions peuvent souvent être simplifiées à l'aide d'alias de types :

using F = void(int); // alias de type nommé pour simplifier les déclarations
F a[10];  // Erreur : tableau de fonctions
F& a[10]; // Erreur : tableau de références
F* a[10]; // OK : tableau de pointeurs vers fonctions

Un pointeur vers fonction peut servir d'opérande de gauche à l'opérateur d'appel de fonction ; cela invoque la fonction pointée :

int f(int n)
{
    std::cout << n << '\n';
    return n * n;
}

int main()
{
    int (*p)(int) = f;
    int x = p(7);
}

La déréférenciation d'un pointeur de fonction donne la lvalue identifiant la fonction pointée :

int f();
int (*p)() = f;  // le pointeur p pointe vers f
int (&r)() = *p; // la lvalue qui identifie f est liée à une référence
r();             // fonction f invoquée via une référence lvalue
(*p)();          // fonction f invoquée via la lvalue de fonction
p();             // fonction f invoquée directement via le pointeur

Un pointeur vers fonction peut être initialisé à partir d'un ensemble de surcharges pouvant comprendre des fonctions, des spécialisations de modèles de fonctions et des modèles de fonctions, si une seule surcharge correspond au type du pointeur (voir adresse d'une fonction surchargée pour plus de détails) :

template<typename T>
T f(T n) { return n; }

double f(double n) { return n; }

int main()
{
    int (*p)(int) = f; // instancie et sélectionne f<int>
}

Des opérateurs de comparaison d'égalité sont définis pour les pointeurs vers des fonctions (ils sont égaux s'ils pointent vers la même fonction).

Pointeurs vers des membres

Pointeurs vers des membres de données

Un pointeur vers un objet membre non statique m, qui est membre de la classe C, peut être initialisé exactement avec l'expression &C::m. Les expressions telles que &(C::m) ou &m à l'intérieur d'une fonction membre de C ne forment pas de pointeurs vers membres.

Un tel pointeur peut servir d'opérande de droite aux opérateurs d'accès à un membre via pointeur operator.* et operator->* :

struct C { int m; };

int main()
{
    int C::* p = &C::m;          // pointeur vers le membre de données m de la classe C
    C c = {7};
    std::cout << c.*p << '\n';   // prints 7
    C* cp = &c;
    cp->m = 10;
    std::cout << cp->*p << '\n'; // prints 10
}

Un pointeur vers un membre de données d'une classe de base non virtuelle accessible et non ambiguë peut être implicitement converti en pointeur vers le même membre de données d'une classe dérivée :

struct Base { int m; };
struct Derived : Base {};

int main()
{
    int Base::* bp = &Base::m;
    int Derived::* dp = bp;
    Derived d;
    d.m = 1;
    std::cout << d.*dp << ' ' << d.*bp << '\n'; // prints 1 1
}

La conversion dans le sens inverse, d'un pointeur vers un membre de données d'une classe dérivée vers un pointeur vers un membre de données d'une classe de base non virtuelle non ambiguë, est autorisée avec static_cast et un transtypage explicite, même si la classe de base n'a pas ce membre (mais que la classe la plus dérivée l'a, lorsque le pointeur est utilisé pour l'accès) :

struct Base {};
struct Derived : Base { int m; };

int main()
{
    int Derived::* dp = &Derived::m;
    int Base::* bp = static_cast<int Base::*>(dp);

    Derived d;
    d.m = 7;
    std::cout << d.*bp << '\n'; // correct : affiche 7

    Base b;
    std::cout << b.*bp << '\n'; // comportement indéfini
}

Le type pointé d'un pointeur vers membre peut lui-même être un pointeur vers membre : les pointeurs vers membres peuvent être à plusieurs niveaux et peuvent être qualifiés cv différemment à chaque niveau. Les combinaisons mixtes multi-niveaux de pointeurs et de pointeurs vers membres sont également autorisées :

struct A
{
    int m;
    // pointeur const vers membre non const
    int A::* const p;
};

int main()
{
    // pointeur non const vers membre de données qui est un pointeur const vers membre non const
    int A::* const A::* p1 = &A::p;

    const A a = {1, &A::m};
    std::cout << a.*(a.*p1) << '\n'; // prints 1

    // pointeur non const ordinaire vers un pointeur-vers-membre const
    int A::* const* p2 = &a.p;
    std::cout << a.**p2 << '\n'; // prints 1
}

Pointeurs vers des fonctions membres

Un pointeur vers fonction membre non statique f, qui est membre de la classe C, peut être initialisé exactement avec l'expression &C::f. Les expressions telles que &(C::f) ou &f à l'intérieur d'une fonction membre de C ne forment pas de pointeurs vers fonctions membres.

Un tel pointeur peut être utilisé comme opérande de droite des opérateurs d'accès via pointeur vers membre operator.* et operator->*. L'expression résultante ne peut être utilisée que comme opérande de gauche d'un opérateur d'appel de fonction :

struct C
{
    void f(int n) { std::cout << n << '\n'; }
};

int main()
{
    void (C::* p)(int) = &C::f; // pointeur vers la fonction membre f de la classe C
    C c;
    (c.*p)(1);                  // prints 1
    C* cp = &c;
    (cp->*p)(2);                // prints 2
}

Un pointeur vers fonction membre d'une classe de base peut être implicitement converti en pointeur vers la même fonction membre d'une classe dérivée :

struct Base
{
    void f(int n) { std::cout << n << '\n'; }
};
struct Derived : Base {};

int main()
{
    void (Base::* bp)(int) = &Base::f;
    void (Derived::* dp)(int) = bp;
    Derived d;
    (d.*dp)(1);
    (d.*bp)(2);
}

La conversion dans le sens inverse, d'un pointeur vers fonction membre d'une classe dérivée vers un pointeur vers fonction membre d'une classe de base non virtuelle et non ambiguë, est autorisée avec static_cast et transtypage explicite, même si la classe de base n'a pas cette fonction membre (mais la classe la plus dérivée l'a, lorsque le pointeur est utilisé pour l'accès) :

struct Base {};
struct Derived : Base
{
    void f(int n) { std::cout << n << '\n'; }
};

int main()
{
    void (Derived::* dp)(int) = &Derived::f;
    void (Base::* bp)(int) = static_cast<void (Base::*)(int)>(dp);

    Derived d;
    (d.*bp)(1); // correct : affiche 1

    Base b;
    (b.*bp)(2); // comportement indéfini
}

Les pointeurs vers fonctions membres peuvent être utilisés comme fonctions de rappel ou comme objets fonctions, souvent après application de std::mem_fn ou std::bind :

#include <algorithm>
#include <cstddef>
#include <functional>
#include <iostream>
#include <string>

int main()
{
    std::vector<std::string> v = {"a", "ab", "abc"};
    std::vector<std::size_t> l;
    transform(v.begin(), v.end(), std::back_inserter(l),
              std::mem_fn(&std::string::size));
    for (std::size_t n : l)
        std::cout << n << ' ';
    std::cout << '\n';
}

Output:

1 2 3

Pointeurs nuls

Les pointeurs de tout type ont une valeur spéciale appelée valeur de pointeur nul de ce type. Un pointeur dont la valeur est nulle ne pointe vers aucun objet ni aucune fonction (le déréférencement d'un pointeur nul provoque un comportement indéfini), et se compare égal à tous les pointeurs du même type dont la valeur est également nulle.

Une constante de pointeur nul peut servir à initialiser un pointeur à nul ou à affecter la valeur nulle à un pointeur existant ; c'est l'une des valeurs suivantes :

  • Un littéral entier de valeur zéro.
  • Une prvalue de type std::nullptr_t (généralement nullptr).

(depuis C++11)

La macro NULL peut également être utilisée ; elle se développe en une constante de pointeur nul définie par l'implémentation.

L'initialisation à zéro et l'initialisation de valeur initialisent également les pointeurs à leur valeur nulle.

Les pointeurs nuls peuvent servir à indiquer l'absence d'objet (par ex. std::function::target()), ou comme autres indicateurs de condition d'erreur (par ex. dynamic_cast). En général, une fonction qui reçoit un argument pointeur doit presque toujours vérifier si la valeur est nulle et traiter ce cas différemment (par exemple, l'expression delete ne fait rien lorsqu'un pointeur nul est passé).

Pointeurs invalides

Une valeur de pointeur p est valide dans le contexte de une évaluation e si l'une des conditions suivantes est satisfaite :

  • p est une valeur de pointeur nul.
  • p est un pointeur vers une fonction.
  • p est un pointeur vers un objet o ou au-delà de sa fin, et e se trouve dans la durée de la région de stockage de o.

Si une valeur de pointeur p est utilisée dans une évaluation e, et que p n'est pas valide dans le contexte de e, alors :

  • Si e est une indirection ou l'invocation d'une fonction de désallocation, le comportement est indéfini.
  • Sinon, le comportement est défini par l'implémentation.
int* f()
{
    int obj;
    int* local_ptr = new (&obj) int;

    *local_ptr = 1; // OK, l'évaluation de « *local_ptr » est
                    // dans la durée de stockage de « obj »

    return local_ptr;
}

int* ptr = f();  // la durée de stockage de « obj » est expirée,
                 // donc « ptr » est un pointeur invalide dans les contextes suivants

int* copy = ptr; // comportement défini par l'implémentation
*ptr = 2;        // comportement indéfini : indirection d'un pointeur invalide
delete ptr;      // comportement indéfini : désallocation du stockage à partir d'un pointeur invalide

Constance

  • Si cv apparaît avant * dans la déclaration du pointeur, il fait partie de la séquence de spécificateurs de déclaration et s'applique à l'objet pointé.
  • Si cv apparaît après * dans la déclaration du pointeur, il fait partie du déclarateur et s'applique au pointeur en cours de déclaration.
Syntaxe meaning

T const* pointeur vers objet constant
T* const pointeur constant vers objet
const T* const pointeur constant vers objet constant

En général, la conversion implicite d'un pointeur à plusieurs niveaux vers un autre suit les règles décrites dans conversions de qualification.

Type de pointeur composite

Lorsqu'un opérande d'un opérateur de comparaison ou l'un des deuxième et troisième opérandes d'un opérateur conditionnel est un pointeur ou un pointeur vers membre, un type de pointeur composite est déterminé comme étant le type commun de ces opérandes.

Étant donnés deux opérandes p1 et p2 de types T1 et T2 respectivement, p1 et p2 ne peuvent avoir un type de pointeur composite que si l'une des conditions suivantes est satisfaite :

  • p1 et p2 sont tous deux des pointeurs.
  • L'un de p1 et p2 est un pointeur et l'autre opérande est une constante de pointeur nul.
  • p1 et p2 sont tous deux des constantes de pointeur nul, et au moins l'un de T1 et T2 est un type non intégral.

(depuis C++11)

(jusqu'à C++14)

  • Au moins l'un de T1 et T2 est un type pointeur, un type pointeur vers membre ou std::nullptr_t.

(depuis C++14)

Le type de pointeur composite C de p1 et p2 est déterminé comme suit :

  • Si p1 est une constante de pointeur nul, C est T2.
  • Sinon, si p2 est une constante de pointeur nul, C est T1.

(jusqu'à C++11)

  • Si p1 et p2 sont tous deux des constantes de pointeur nul, C est std::nullptr_t.
  • Sinon, si p1 est une constante de pointeur nul, C est T2.
  • Sinon, si p2 est une constante de pointeur nul, C est T1.

(depuis C++11)

  • Sinon, si toutes les conditions suivantes sont satisfaites :
    • T1 ou T2 est « pointeur vers cv1 void ».
    • L'autre type est « pointeur vers cv2 T », où T est un type objet ou void. C est « pointeur vers cv12 void », où cv12 est l'union de cv1 et cv2.
  • Sinon, si toutes les conditions suivantes sont satisfaites :
  • T1 ou T2 est « pointeur vers type fonction F1 ».
  • L'autre type est « pointeur vers type fonction noexcept F2 ».
  • F1 et F2 sont identiques à l'exception de noexcept. C est « pointeur vers F1 ».

(depuis C++17)

  • Sinon, si toutes les conditions suivantes sont satisfaites :
    • T1 est « pointeur vers C1 ».
    • T2 est « pointeur vers C2 ».
    • L'un de C1 et C2 est lié par référence à l'autre. C is
    • le type combiné de qualification de T1 et T2, si C1 est lié par référence à C2, ou
    • le type combiné de qualification de T2 et T1, si C2 est lié par référence à C1.
  • Sinon, si toutes les conditions suivantes sont satisfaites :
  • T1 ou T2 est « pointeur vers membre de C1 de type fonction F1 ».
  • L'autre type est « pointeur vers membre de C2 de type fonction noexcept F2 ».
  • L'un de C1 et C2 est lié par référence à l'autre.
  • F1 et F2 sont identiques à l'exception de noexcept. C is
  • « pointeur vers membre de C2 de type F1 », si C1 est lié par référence à C2, ou
  • « pointeur vers membre de C1 de type F1 », si C2 est lié par référence à C1.

(depuis C++17)

  • Sinon, si toutes les conditions suivantes sont satisfaites :

    • T1 est « pointeur vers membre de C1 de type non fonction M1 ».
    • T2 est « pointeur vers membre de C2 de type non fonction M2 »
    • M1 et M2 sont identiques à l'exception des qualificateurs cv de premier niveau.
    • L'un de C1 et C2 est lié par référence à l'autre. C is
    • le type combiné de qualification de T2 et T1, si C1 est lié par référence à C2, ou
    • le type combiné de qualification de T1 et T2, si C2 est lié par référence à C1.

  • Sinon, si T1 et T2 sont des types similaires, C est le type combiné de qualification de T1 et T2.

  • Sinon, p1 et p2 n'ont pas de type pointeur composite ; un programme qui nécessite la détermination d'un tel type pour C est mal formé.

using p = void*;
using q = const int*;
// La détermination du type pointeur composite de « p » et « q »
// relève du cas [« pointeur vers cv1 void » et « pointeur vers cv2 T »] :
// cv1 = vide, cv2 = const, cv12 = const
// on substitue « cv12 = const » dans « pointeur vers cv12 void » :
// le type pointeur composite est « const void* »

using pi = int**;
using pci = const int**;
// La détermination du type pointeur composite de « pi » et « pci »
// relève du cas [pointeurs vers des types similaires « C1 » et « C2 »] :
// C1 = int*, C2 = const int*
// ce sont des types apparentés par référence (dans les deux sens) car ils sont similaires
// le type pointeur composite est le type combiné des qualificateurs

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 73 C++98 un pointeur vers un objet ne se compare jamais égal à un pointeur vers un élément au-delà de la fin d'un tableau pour les pointeurs non nuls et non fonctions, comparer les adresses qu'ils représentent
CWG 903 C++98 toute expression constante intégrale qui s'évalue à 0 était une constante de pointeur nul limité aux littéraux entiers de valeur 0
CWG 1438 C++98 le comportement de l'utilisation d'une valeur de pointeur invalide de quelque manière que ce soit était indéfini les comportements autres que l'indirection et le passage aux fonctions de désallocation sont définis par l'implémentation
CWG 1512 (N3624) C++98 la règle du type de pointeur composite était incomplète, et ainsi n'autorisait pas la comparaison entre int** et const int** rendue complète
CWG 2206 C++98 un pointeur vers void et un pointeur vers fonction avaient un type de pointeur composite ils n'ont pas un tel type
CWG 2381 C++17 les conversions de pointeurs de fonction n'étaient pas autorisées lors de la détermination du type de pointeur composite allowed
CWG 2822 C++98 atteindre la fin de la durée d'une région de stockage pouvait invalider des valeurs de pointeur la validité d'un pointeur dépend du contexte d'évaluation
CWG 2933 C++98 les pointeurs vers des fonctions étaient toujours invalides elles sont toujours valides
