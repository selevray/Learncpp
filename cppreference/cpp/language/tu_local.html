Entités locales à l'unité de traduction (depuis C++20)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les entités locales à l'unité de traduction (entités TU-local) sont introduites pour empêcher que des entités censées être locales (non utilisées dans aucune autre unité de traduction) soient exposées et utilisées dans d'autres unités de traduction.

Un exemple tiré de Understanding C++ Modules: Part 2 illustre le problème de l'absence de contrainte sur les expositions :

// Unité de module sans contraintes TU-local
export module Foo;

import <iostream>;

namespace
{
   class LolWatchThis {        // liaison interne, ne peut pas être exportée
       static void say_hello()
       {
           std::cout << "Hello, everyone!\n";
       }
   };
}

export LolWatchThis lolwut() { // LolWatchThis est exposé comme type de retour
    return LolWatchThis();
}

// main.cpp
import Foo;

int main()
{
    auto evil = lolwut();        // 'evil' a le type 'LolWatchThis'
    decltype(evil)::say_hello(); // la définition de 'LolWatchThis' n'est plus à liaison interne
}

Entités TU-local

Une entité est TU-local si elle est

  1. un type, une fonction, une variable ou un modèle qui
    1. a un nom à liaison interne, ou
    2. n'a pas de nom avec liaison et est déclaré, ou introduit par une expression lambda, dans la définition d'une entité TU-local,
  2. un type sans nom défini en dehors d'un class-specifier, d'un corps de fonction ou d'un initialiseur, ou introduit par un spécificateur de type définissant (type-specifier, class-specifier ou enum-specifier) utilisé pour ne déclarer que des entités TU-local,
  3. une spécialisation d'un modèle TU-local,
  4. une spécialisation d'un modèle avec un argument de modèle TU-local quelconque, ou
  5. une spécialisation d'un modèle dont la déclaration (éventuellement instanciée) est une exposition (définie ci-dessous).
// Entités TU-local à liaison interne
namespace { // tous les noms déclarés dans un espace de noms sans nom ont une liaison interne
    int tul_var = 1;                          // variable TU-local
    int tul_func() { return 1; }              // fonction TU-local
    struct tul_type { int mem; };             // type (classe) TU-local
}
template<typename T>
static int tul_func_temp() { return 1; }      // modèle TU-local

// spécialisation de modèle TU-local
template<>
static int tul_func_temp<int>() { return 3; } // spécialisation TU-local

// spécialisation de modèle avec argument de modèle TU-local
template <> struct std::hash<tul_type> {      // spécialisation TU-local
    std::size_t operator()(const tul_type& t) const { return 4u; }
};

Une valeur ou un objet est TU-local si l'une des conditions suivantes est vérifiée

  1. il est, ou est un pointeur vers, une fonction TU-local ou l'objet associé à une variable TU-local, ou
  2. il est un objet de type classe ou tableau dont l'un des sous-objets, ou l'un des objets ou fonctions désignés par ses membres non statiques de type référence, est TU-local et est utilisable dans des expressions constantes.
static int tul_var = 1;             // variable TU-local
static int tul_func() { return 1; } // fonction TU-local

int* tul_var_ptr = &tul_var;        // TU-local : pointeur vers une variable TU-local
int (* tul_func_ptr)() = &tul_func; // TU-local : pointeur vers une fonction TU-local

constexpr static int tul_const = 1; // variable TU-local utilisable dans des expressions constantes
int tul_arr[] = { tul_const };      // TU-local : tableau d'objet constexpr TU-local
struct tul_class { int mem; };
tul_class tul_obj{tul_const};       // TU-local : possède un membre objet constexpr TU-local

Expositions

Une déclaration D nomme une entité E si

  1. D contient une expression lambda dont le type de fermeture est E,
  2. E n'est ni une fonction ni un modèle de fonction, et D contient un id-expression, un type-specifier, un nested-name-specifier, un template-name ou un concept-name désignant E, ou
  3. E est une fonction ou un modèle de fonction, et D contient une expression qui nomme E ou un id-expression qui fait référence à un ensemble de surcharges contenant E.
// nommage par expression lambda
auto x = [] {}; // nomme decltype(x)

// nommage d'une entité non fonction (modèle)
int y1 = 1;                      // noms y1 (id-expression)
struct y2 { int mem; };
y2 y2_obj{1};                    // noms y2 (type-specifier)
struct y3 { int mem_func(); };
int y3::mem_func() { return 0; } // noms y3 (nested-name-specifier)
template<typename T> int y4 = 1;
int var = y4<y2>;                // noms y4 (template-name)
template<typename T> concept y5 = true;
template<typename T> void func(T&&) requires y5<T>; // noms y5 (concept-name)

// nommage de fonction (modèle)
int z1(int arg)    { std::cout << "no overload"; return 0; }
int z2(int arg)    { std::cout << "overload 1";  return 1; }
int z2(double arg) { std::cout << "overload 2";  return 2; }

int val1 = z1(0); // noms z1
int val2 = z2(0); // noms z2 ( int z2(int) )

Une déclaration est une exposition si elle nomme une entité TU-local, en ignorant

  1. le corps de fonction d'une fonction non inline ou d'un modèle de fonction non inline (mais pas le type de retour déduit pour une définition (éventuellement instanciée) d'une fonction à type de retour déclaré qui utilise un type substituable),
  2. l'initialiseur d'une variable ou d'un modèle de variable (mais pas le type de la variable),
  3. les déclarations d'amitié dans une définition de classe, et
  4. toute référence à un objet ou une référence const non volatile, à liaison interne ou sans liaison, initialisé avec une expression constante qui n'est pas une odr-use,

ou définit une variable constexpr initialisée à une valeur TU-local.

Contraintes TU-local

Si une déclaration (éventuellement instanciée) de, ou un guide de déduction pour, une entité non locale à l'unité de traduction dans une unité d'interface de module (en dehors de la private-module-fragment, le cas échéant) ou une partition de module constitue une exposition, le programme est mal formé. Une telle déclaration dans tout autre contexte est obsolète.

Si une déclaration apparaissant dans une unité de traduction nomme une entité TU-local déclarée dans une autre unité de traduction qui n'est pas une unité d'en-tête, le programme est mal formé. Une déclaration instanciée pour une spécialisation de modèle apparaît au point d'instanciation de la spécialisation.

Exemple

Unité de traduction #1 :

export module A;
static void f() {}
inline void it() { f(); }         // erreur : est une exposition de f
static inline void its() { f(); } // OK
template<int> void g() { its(); } // OK
template void g<0>();

decltype(f) *fp;                             // erreur : f (mais pas son type) est TU-local
auto &fr = f;                                // OK
constexpr auto &fr2 = fr;                    // erreur : est une exposition de f
constexpr static auto fp2 = fr;              // OK
struct S { void (&ref)(); } s{f};            // OK : la valeur est TU-local
constexpr extern struct W { S &s; } wrap{s}; // OK : la valeur n'est pas TU-local

static auto x = []{ f(); }; // OK
auto x2 = x;                // erreur : le type de fermeture est TU-local
int y = ([]{ f(); }(), 0);  // erreur : le type de fermeture n'est pas TU-local
int y2 = (x, 0);            // OK

namespace N
{
    struct A {};
    void adl(A);
    static void adl(int);
}
void adl(double);

inline void h(auto x) { adl(x); } // OK, mais une spécialisation pourrait être une exposition

Unité de traduction #2 :

module A;
void other()
{
    g<0>();                  // OK : la spécialisation est explicitement instanciée
    g<1>();                  // erreur : l'instanciation utilise its TU-local
    h(N::A{});               // erreur : l'ensemble de surcharge contient N::adl(int) qui est TU-local
    h(0);                    // OK : appelle adl(double)
    adl(N::A{});             // OK ; N::adl(int) non trouvé, appelle N::adl(N::A)
    fr();                    // OK : appelle f
    constexpr auto ptr = fr; // erreur : fr n'est pas utilisable dans des expressions constantes ici
}
