Spécialisation explicite (complète) de modèle

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Permet de personnaliser le code du modèle pour un ensemble donné d'arguments de modèle.

Syntaxe

| | | | template <> declaration | | | |

Chacun des éléments suivants peut être entièrement spécialisé :

  1. modèle de fonction
  2. modèle de classe
  3. modèle de variable (depuis C++14)
  4. fonction membre d'un modèle de classe
  5. membre de données statique d'un modèle de classe
  6. classe membre d'un modèle de classe
  7. énumération membre d'un modèle de classe
  8. modèle de classe membre d'une classe ou d'un modèle de classe
  9. modèle de fonction membre d'une classe ou d'un modèle de classe
  10. modèle de variable membre d'une classe ou d'un modèle de classe (depuis C++14)

Par exemple,

#include <type_traits>

template<typename T> // modèle primaire
struct is_void : std::false_type {};
template<>           // spécialisation explicite pour T = void
struct is_void<void> : std::true_type {};

int main()
{
    static_assert(is_void<char>::value == false,
        "for any type T other than void, the class is derived from false_type");
    static_assert(is_void<void>::value == true,
        "but when T is void, the class is derived from true_type");
}

En détail

Une spécialisation explicite peut être déclarée dans toute portée où son modèle primaire peut être défini (ce qui peut différer de la portée où le modèle primaire est défini ; par exemple, avec une spécialisation hors classe d'un modèle membre). Une spécialisation explicite doit apparaître après la déclaration du modèle non spécialisé.

namespace N
{
    template<class T> // modèle primaire
    class X { /*...*/ };
    template<>        // spécialisation dans le même espace de noms
    class X<int> { /*...*/ };

    template<class T> // modèle primaire
    class Y { /*...*/ };
    template<>        // déclaration anticipée de la spécialisation pour double
    class Y<double>;
}

template<> // OK : spécialisation dans le même espace de noms
class N::Y<double> { /*...*/ };

La spécialisation doit être déclarée avant la première utilisation qui entraînerait une instanciation implicite, dans chaque unité de traduction où une telle utilisation apparaît :

class String {};

template<class T>
class Array { /*...*/ };

template<class T> // modèle primaire
void sort(Array<T>& v) { /*...*/ }

void f(Array<String>& v)
{
    sort(v); // instancie implicitement sort(Array<String>&),
}            // en utilisant le modèle primaire pour sort()

template<> // ERREUR : spécialisation explicite de sort(Array<String>)
void sort<String>(Array<String>& v); // après l'instanciation implicite

Une spécialisation de modèle déclarée mais non définie peut être utilisée comme tout autre type incomplet (par exemple, des pointeurs et des références vers celle-ci peuvent être utilisés) :

template<class T> // modèle primaire
class X;
template<>        // spécialisation (déclarée, non définie)
class X<int>;

X<int>* p; // OK : pointeur vers un type incomplet
X<int> x;  // erreur : objet de type incomplet

Le fait qu'une spécialisation explicite d'un modèle de fonctionou de variable (depuis C++14) soit inline[/constexpr (depuis C++11) | /constinit/consteval (depuis C++20)] est déterminé par la spécialisation explicite elle-même, indépendamment du fait que le modèle primaire soit déclaré avec ce spécificateur.De même, les attributs figurant dans la déclaration d'un modèle n'ont aucun effet sur une spécialisation explicite de ce modèle : (depuis C++11)

template<class T>
void f(T) { /* ... */ }
template<>
inline void f<>(int) { /* ... */ } // OK, inline

template<class T>
inline T g(T) { /* ... */ }
template<>
int g<>(int) { /* ... */ }         // OK, non inline

template<typename>
[[noreturn]] void h([[maybe_unused]] int i);
template<> void h<int>(int i)
{
    // [[noreturn]] n'a aucun effet, mais [[maybe_unused]] en a un
}

Spécialisations explicites de modèles de fonctions

Lors de la spécialisation d'un modèle de fonction, ses arguments de modèle peuvent être omis si la déduction d'arguments de modèle peut les fournir à partir des arguments de la fonction :

template<class T>
class Array { /*...*/ };

template<class T> // modèle primaire
void sort(Array<T>& v);
template<>        // spécialisation pour T = int
void sort(Array<int>&);

// inutile à écrire
// template<> void sort<int>(Array<int>&);

Une fonction de même nom et de même liste d'arguments qu'une spécialisation n'est pas une spécialisation (voir surcharge de modèles dans modèle de fonction).

Des arguments par défaut de fonction ne peuvent pas être spécifiés dans les spécialisations explicites de modèles de fonctions, de modèles de fonctions membres et de fonctions membres de modèles de classe lorsque la classe est implicitement instanciée.

Une spécialisation explicite ne peut pas être une déclaration d'amitié.

Membres des spécialisations

Lors de la définition d'un membre d'un modèle de classe explicitement spécialisé en dehors du corps de la classe, la syntaxe template<> n'est pas utilisée, sauf s'il s'agit d'un membre d'un modèle de classe membre explicitement spécialisé, spécialisé comme modèle de classe, car sinon la syntaxe obligerait une telle définition à commencer par template<parameters> requis par le modèle imbriqué

template<typename T>
struct A
{
    struct B {};      // classe membre

    template<class U> // modèle de classe membre
    struct C {};
};

template<> // specialization
struct A<int>
{
    void f(int); // fonction membre d'une spécialisation
};
// template<> non utilisé pour un membre d'une spécialisation
void A<int>::f(int) { /* ... */ }

template<> // spécialisation d'une classe membre
struct A<char>::B
{
    void f();
};
// template<> non utilisé non plus pour un membre d'une classe membre spécialisée
void A<char>::B::f() { /* ... */ }

template<> // spécialisation d'un modèle de classe membre
template<class U>
struct A<char>::C
{
    void f();
};

// template<> est utilisé lors de la définition d'un membre d'un modèle de classe membre explicitement
// modèle de classe membre spécialisé, spécialisé comme modèle de classe
template<>
template<class U>
void A<char>::C<U>::f() { /* ... */ }

Une spécialisation explicite d'un membre de données statique d'un modèle est une définition si la déclaration comporte un initialiseur ; sinon, c'est une déclaration. Ces définitions doivent utiliser des accolades pour l'initialisation par défaut :

template<>
X Q<int>::x;    // déclaration d'un membre statique
template<>
X Q<int>::x (); // erreur : déclaration de fonction
template<>
X Q<int>::x {}; // définition d'un membre statique initialisé par défaut

Un membre ou un modèle membre d'un modèle de classe peut être explicitement spécialisé pour une instanciation implicite donnée du modèle de classe, même si le membre ou le modèle membre est défini dans la définition du modèle de classe.

template<typename T>
struct A
{
    void f(T);         // membre, déclaré dans le modèle primaire

    void h(T) {}       // membre, défini dans le modèle primaire

    template<class X1> // modèle de membre
    void g1(T, X1);

    template<class X2> // modèle de membre
    void g2(T, X2);
};

// spécialisation d'un membre
template<>
void A<int>::f(int);

// spécialisation de membre OK même si défini dans la classe
template<>
void A<int>::h(int) {}

// définition de modèle membre hors de la classe
template<class T>
template<class X1>
void A<T>::g1(T, X1) {}

// spécialisation de modèle membre
template<>
template<class X1>
void A<int>::g1(int, X1);

// spécialisation de modèle membre
template<>
template<>
void A<int>::g2<char>(int, char); // pour X2 = char

// idem, par déduction d'arguments de modèle (X1 = char)
template<>
template<>
void A<int>::g1(int, char);

Un membre ou un modèle membre peut être imbriqué dans plusieurs modèles de classes englobants. Dans une spécialisation explicite pour un tel membre, il y a un template<> pour chaque modèle de classe englobant qui est explicitement spécialisé.

template<class T1>
struct A
{
    template<class T2>
    struct B
    {
        template<class T3>
        void mf();
    };
};

template<>
struct A<int>;

template<>
template<>
struct A<char>::B<double>;

template<>
template<>
template<>
void A<char>::B<char>::mf<double>();

Dans une telle déclaration imbriquée, certains niveaux peuvent rester non spécialisés (sauf qu'il est impossible de spécialiser un modèle de classe membre en portée d'espace de noms si sa classe englobante n'est pas spécialisée). Pour chacun de ces niveaux, la déclaration nécessite template<arguments>, car ces spécialisations sont elles-mêmes des modèles :

template<class T1>
class A
{
    template<class T2>
    class B
    {
        template<class T3> // modèle de membre
        void mf1(T3);

        void mf2();        // membre non modèle
    };
};

// specialization
template<>        // pour le A spécialisé
template<class X> // pour le B non spécialisé
class A<int>::B
{
    template<class T>
    void mf1(T);
};

// specialization
template<>        // pour le A spécialisé
template<>        // pour le B spécialisé
template<class T> // pour le mf1 non spécialisé
void A<int>::B<double>::mf1(T t) {}

// ERREUR : B<double> est spécialisé et est un modèle membre, donc sa classe englobante A doit aussi être spécialisée
// doit aussi être spécialisée
template<class Y>
template<>
void A<Y>::B<double>::mf2() {}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 531 C++98 la syntaxe de définition des membres de spécialisations explicites en portée d'espace de noms n'était pas spécifiée specified
CWG 727 C++98 spécialisations partielles et complètes non autorisées dans la portée de classe autorisées dans n'importe quelle portée
CWG 730 C++98 les modèles membres de classes non modèles ne pouvaient pas être entièrement spécialisés allowed
CWG 2478 C++20 il n'était pas clair si le constinit et le consteval du modèle primaire étaient reportés dans ses spécialisations explicites non reportés
CWG 2604 C++11 il n'était pas clair si les attributs du modèle primaire étaient reportés dans ses spécialisations explicites non reportés
