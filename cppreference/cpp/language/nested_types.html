Classes imbriquées

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Une déclaration de class/struct ou de union peut apparaître à l'intérieur d'une autre classe. Une telle déclaration déclare une classe imbriquée.

Explication

Le nom de la classe imbriquée existe dans la portée de la classe englobante, et la recherche de noms depuis une fonction membre d'une classe imbriquée examine la portée de la classe englobante après celle de la classe imbriquée. Comme tout membre de sa classe englobante, la classe imbriquée a accès à tous les noms (privés, protégés, etc.) auxquels la classe englobante a accès, mais elle est par ailleurs indépendante et n'a aucun accès spécial au pointeur this de la classe englobante. Les déclarations d'une classe imbriquée peuvent utiliser tous les membres de la classe englobante, en suivant les règles d'usage habituelles pour les membres non statiques.

int x, y; // globals
class enclose // classe englobante
{
    // note : membres privés
    int x;
    static int s;
public:
    struct inner // classe imbriquée
    {
        void f(int i)
        {
            x = i; // Error : impossible d'écrire dans enclose::x non statique sans instance
            int a = sizeof x; // Error jusqu'à C++11,
                              // OK depuis C++11 : l'opérande de sizeof n'est pas évalué,
                              // cette utilisation de enclose::x non statique est autorisée.
            s = i;   // OK : affectation possible à enclose::s statique
            ::x = i; // OK : affectation possible à la variable globale x
            y = i;   // OK : affectation possible à la variable globale y
        }

        void g(enclose* p, int i)
        {
            p->x = i; // OK : affectation à enclose::x
        }
    };
};

Les fonctions amies définies dans une classe imbriquée n'ont aucun accès spécial aux membres de la classe englobante, même si la recherche de noms depuis le corps d'une fonction membre définie dans une classe imbriquée peut trouver les membres privés de la classe englobante.

Les définitions hors de la classe des membres d'une classe imbriquée apparaissent dans l'espace de noms de la classe englobante :

struct enclose
{
    struct inner
    {
        static int x;
        void f(int i);
    };
};

int enclose::inner::x = 1;       // definition
void enclose::inner::f(int i) {} // definition

Les classes imbriquées peuvent être déclarées par anticipation puis définies plus tard, soit dans le même corps de la classe englobante, soit en dehors de celui-ci :

class enclose
{
    class nested1;    // déclaration anticipée
    class nested2;    // déclaration anticipée
    class nested1 {}; // définition de la classe imbriquée
};

class enclose::nested2 {}; // définition de la classe imbriquée

Les déclarations de classes imbriquées respectent les spécificateurs d'accès aux membres : une classe membre privée ne peut pas être désignée en dehors de la portée de la classe englobante, bien que des objets de cette classe puissent être manipulés :

class enclose
{
    struct nested // membre privé
    {
        void g() {}
    };
public:
    static nested f() { return nested{}; }
};

int main()
{
    //enclose::nested n1 = enclose::f(); // erreur : 'nested' est privé

    enclose::f().g();       // OK : ne désigne pas 'nested'
    auto n2 = enclose::f(); // OK : ne désigne pas 'nested'
    n2.g();
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 45 C++98 les membres d'une classe imbriquée ne peuvent pas accéder à la classe englobante ni à ses amies ils ont les mêmes droits d'accès que les autres membres de la classe englobante (corrige aussi les problèmes CWG #8 et #10)
