Initialisation par copie

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Initialise un objet à partir d'un autre objet.

Syntaxe

T object = other; | (1)

T object = {other}; | (2) | (jusqu'à C++11)

f(other) | (3)

return other; | (4)

throw object;

catch (T object)

| (5)

T array[N] = {other-sequence}; | (6)

Explication

L'initialisation par copie est effectuée dans les situations suivantes :

  1. Lorsqu'une variable nommée (automatique, statique ou à durée de stockage thread) de type non référence T est déclarée avec un initialisateur constitué d'un signe égal suivi d'une expression.

  2. (jusqu'à C++11) Lorsqu'une variable nommée de type scalaire T est déclarée avec un initialisateur constitué d'un signe égal suivi d'une expression entre accolades (Remarque : depuis C++11, ce cas est classé comme initialisation par liste, et la conversion restrictive n'est pas autorisée).

  3. Lorsqu'on passe un argument à une fonction par valeur.

  4. Lorsqu'on renvoie une valeur depuis une fonction qui renvoie par valeur.

  5. Lorsqu'on lève ou intercepte une exception par valeur.

  6. Dans le cadre d'une initialisation d'agrégat, pour initialiser chaque élément pour lequel un initialisateur est fourni.

Les effets de l'initialisation par copie sont :

  • Tout d'abord, si T est un type de classe et que l'initialisateur est une expression prvalue dont le type sans qualification cv est la même classe que T, l'expression d'initialisation elle-même, plutôt qu'un temporaire matérialisé à partir de celle-ci, est utilisée pour initialiser l'objet de destination : voir élision de copie.

(depuis C++17)

  • Sinon, si T est un type de classe et que la version sans qualification cv du type de other est T ou une classe dérivée de T, les constructeurs non explicites de T sont examinés et le meilleur est sélectionné par résolution de surcharge. Ce constructeur est alors appelé pour initialiser l'objet.

  • Sinon, si T est un type de classe, et que la version sans qualification cv du type de other n'est pas T ni une classe dérivée de T, ou si T n'est pas un type de classe mais que le type de other en est un, les séquences de conversion définies par l'utilisateur capables de convertir du type de other vers T (ou vers un type dérivé de T si T est un type de classe et qu'une fonction de conversion est disponible) sont examinées et la meilleure est sélectionnée par résolution de surcharge. Le résultat de la conversion, qui est un [temporaire rvalue (jusqu'à C++11) | temporaire prvalue (depuis C++11) (jusqu'à C++17) | expression prvalue (depuis C++17)] de la version sans qualification cv de T si un constructeur convertisseur a été utilisé, sert ensuite à initialiser directement l'objet. La dernière étape est généralement éliminée et le résultat de la conversion est construit directement dans la mémoire allouée pour l'objet cible, mais le constructeur approprié (de déplacement ou de copie) doit être accessible même s'il n'est pas utilisé. (jusqu'à C++17)

  • Sinon (si ni T ni le type de other ne sont des types de classe), les conversions standard sont utilisées si nécessaire pour convertir la valeur de other vers la version sans qualification cv de T.

Notes

L'initialisation par copie est moins permissive que l'initialisation directe : les constructeurs explicites ne sont pas des constructeurs convertisseurs et ne sont pas pris en compte pour l'initialisation par copie.

struct Exp { explicit Exp(const char*) {} }; // non convertible depuis const char*
Exp e1("abc");  // OK
Exp e2 = "abc"; // Erreur, l'initialisation par copie ne considère pas le constructeur explicite

struct Imp { Imp(const char*) {} }; // convertible depuis const char*
Imp i1("abc");  // OK
Imp i2 = "abc"; // OK

De plus, la conversion implicite dans l'initialisation par copie doit produire directement T à partir de l'initialisateur, alors que, par exemple, l'initialisation directe attend une conversion implicite de l'initialisateur vers un argument du constructeur de T.

struct S { S(std::string) {} }; // implicitement convertible depuis std::string
S s("abc");   // OK : conversion de const char[4] vers std::string
S s = "abc";  // Erreur : pas de conversion de const char[4] vers S
S s = "abc"s; // OK : conversion de std::string vers S

Si other est une expression rvalue, un constructeur de déplacement est sélectionné par résolution de surcharge et appelé lors de l'initialisation par copie. Il s'agit toujours d'une initialisation par copie ; il n'existe aucun terme particulier (par exemple initialisation par déplacement) pour ce cas.

La conversion implicite est définie en termes d'initialisation par copie : si un objet de type T peut être initialisé par copie avec l'expression E, alors E est implicitement convertible en T.

Le signe égal, =, dans l'initialisation par copie d'une variable nommée n'a aucun rapport avec l'opérateur d'affectation. Les surcharges de l'opérateur d'affectation n'ont aucun effet sur l'initialisation par copie.

Exemple

#include <memory>
#include <string>
#include <utility>

struct A
{
    operator int() { return 12;}
};

struct B
{
    B(int) {}
};

int main()
{
    std::string s = "test";        // OK : le constructeur n'est pas explicite
    std::string s2 = std::move(s); // cette initialisation par copie effectue un déplacement

//  std::unique_ptr<int> p = new int(1); // erreur : le constructeur est explicite
    std::unique_ptr<int> p(new int(1));  // OK : initialisation directe

    int n = 3.14;    // conversion flottant-entier
    const int b = n; // const n'a pas d'importance
    int c = b;       // ...dans les deux cas

    A a;
    B b0 = 12;
//  B b1 = a;       // < erreur : conversion de 'A' vers le type non scalaire 'B' demandée
    B b2{a};        // < identique, appelant A::operator int(), puis B::B(int)
    B b3 = {a};     // <
    auto b4 = B{a}; // <

//  b0 = a;         // < erreur, surcharge de l'opérateur d'affectation nécessaire

    [](...){}(c, b0, b3, b4); // faire comme si ces variables étaient utilisées
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 5 C++98 la qualification cv du type de destination est appliquée à le temporaire initialisé par un constructeur convertisseur le temporaire n'est pas qualifié cv
CWG 177 C++98 la catégorie de valeur du temporaire créé lors de l'initialisation par copie d'un objet de classe est non spécifiée spécifiée comme rvalue
