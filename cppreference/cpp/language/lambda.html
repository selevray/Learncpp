Explication

  • captures — Une liste séparée par des virgules de zéro ou plusieurs captures, commençant éventuellement par un capture-default.

    Voir ci-dessous pour la description détaillée des captures.

    Une expression lambda peut utiliser une variable sans la capturer si la variable

    • est une variable non locale ou a une durée de stockage statique ou thread_local (auquel cas la variable ne peut pas être capturée), ou
    • est une référence initialisée avec une expression constante.

    Une expression lambda peut lire la valeur d'une variable sans la capturer si la variable

    • a un type entier ou énuméré const non volatile et a été initialisée avec une expression constante, ou
    • est constexpr et n'a aucun membre mutable.

  • tparams — Une liste non vide séparée par des virgules de paramètres de modèle, utilisée pour nommer les paramètres de modèle d'une lambda générique (voir ClosureType::operator() ci-dessous).

  • t-requires — Ajoute des contraintes à tparams.

    Si t-requires se termine par une séquence de spécificateurs d'attributs, les attributs de cette séquence sont traités comme des attributs de front-attr.

    (depuis C++23)

  • front-attr — (depuis C++23) Une séquence de spécificateurs d'attributs s'applique à operator() du type fermeture (et permet ainsi d'utiliser l'attribut [[noreturn]]).

  • params — La liste de paramètres de operator() du type fermeture.

    Elle peut avoir un paramètre objet explicite.

    (depuis C++23)

  • specs — Une liste des spécificateurs suivants ; chaque spécificateur est autorisé au plus une fois dans chaque séquence.

    Spécificateur | Effet

    mutable | Permet à body de modifier les objets capturés par copie et d'appeler leurs fonctions membres non const.

    • Ne peut pas être utilisé si un paramètre objet explicite est présent.

    (depuis C++23)

    constexpr
    (depuis C++17) | Indique explicitement que operator() est une fonction constexpr.

    • Si operator() satisfait toutes les exigences d'une fonction constexpr, operator() sera constexpr même si constexpr n'est pas présent.

    consteval
    (depuis C++20) | Indique que operator() est une fonction immédiate.

    • consteval et constexpr ne peuvent pas être spécifiés en même temps.

    static
    (depuis C++23) | Indique que operator() est une fonction membre statique.

    • static et mutable ne peuvent pas être spécifiés en même temps.
    • Ne peut pas être utilisé si captures n'est pas vide, ou si un paramètre objet explicite est présent.

  • exception — Fournitla spécification d'exception dynamique ou (jusqu'à C++20) le spécificateur noexcept pour operator() du type fermeture.

  • back-attr — Une séquence de spécificateurs d'attributs s'applique au type de operator() du type fermeture (et l'attribut [[noreturn]] ne peut donc pas être utilisé).

  • trailing-type — -> ret, où ret spécifie le type de retour.

  • requires — (depuis C++20) Ajoute des contraintes à operator() du type fermeture.

  • body — Le corps de la fonction.

Type fermeture

L'expression lambda est une expression prvalue de type classe unique, anonyme, non union et non agrégat, appelé type fermeture, déclaré (aux fins de ADL) dans la plus petite portée de bloc, portée de classe ou espace de noms qui contient l'expression lambda.

Le type fermeture est un type structurel si et seulement si captures est vide.

(depuis C++20)

Le type fermeture possède les membres suivants ; ils ne peuvent pas être instanciés explicitement, spécialisés explicitement, ou (depuis C++14) nommés dans une déclaration d'amitié :

ClosureType::operator()(params)

ret operator()(params) { body }  // (static et const peuvent être présents, voir ci-dessous)

template<template-params>
ret operator()(params) { body }  // (depuis C++14) (lambda générique, static et const peuvent être présents, voir ci-dessous)

Exécute le corps de l'expression lambda lors de son invocation. Lors de l'accès à une variable, accède à sa copie capturée (pour les entités capturées par copie), ou à l'objet d'origine (pour les entités capturées par référence).

La liste de paramètres de operator() est params si elle est fournie, sinon la liste de paramètres est vide.

Le type de retour de operator() est le type spécifié dans trailing-type.

Si trailing-type n'est pas fourni, le type de retour de operator() est automatiquement déduit.[1]

Sauf si le mot-clé mutable a été utilisé dans les spécificateurs de la lambda, ou si un paramètre objet explicite est présent (depuis C++23), le qualificateur cv de operator() est const et les objets capturés par copie ne sont pas modifiables depuis l'intérieur de ce operator(). Le qualificateur const explicite n'est pas autorisé. operator() n'est jamais virtuel et ne peut pas avoir le qualificateur volatile.

operator() est toujours constexpr si elle satisfait aux exigences d'une fonction constexpr. Elle est également constexpr si le mot-clé constexpr a été utilisé dans les spécificateurs de la lambda.

(depuis C++17)

operator() est une fonction immédiate si le mot-clé consteval a été utilisé dans les spécificateurs de la lambda.

(depuis C++20)

operator() est une fonction membre statique si le mot-clé static a été utilisé dans les spécificateurs de la lambda.

operator() est une fonction membre à paramètre objet explicite si params contient un paramètre objet explicite.

(depuis C++23)

Pour chaque paramètre de params dont le type est spécifié comme auto, un paramètre de modèle implicite est ajouté à template-params, dans l'ordre d'apparition. Le paramètre de modèle implicite peut être un pack de paramètres si le membre fonction correspondant de params est un pack de paramètres de fonction.

// lambda générique, operator() est un modèle avec deux paramètres
auto glambda = [](auto a, auto&& b) { return a < b; };
bool b = glambda(3, 3.14); // OK

// lambda générique, operator() est un modèle avec un paramètre
auto vglambda = [](auto printer)
{
    return [=](auto&&... ts) // lambda générique, ts est un pack de paramètres
    {
        printer(std::forward<decltype(ts)>(ts)...);
        // lambda nullaire (ne prend aucun paramètre) :
        return [=] { printer(ts...); };
    };
};

auto p = vglambda([](auto v1, auto v2, auto v3)
{
    std::cout << v1 << v2 << v3;
});

auto q = p(1, 'a', 3.14); // affiche 1a3.14
q();                      // affiche 1a3.14

(depuis C++14)

Si la définition de la lambda utilise une liste explicite de paramètres de modèle, cette liste est utilisée avec operator(). Pour chaque paramètre de params dont le type est spécifié comme auto, un paramètre de modèle implicite supplémentaire est ajouté à la fin de cette liste de paramètres de modèle :

// lambda générique, operator() est un modèle avec deux paramètres
auto glambda = []<class T>(T a, auto&& b) { return a < b; };

// lambda générique, operator() est un modèle avec un seul pack de paramètres
auto f = []<typename... Ts>(Ts&&... ts)
{
    return foo(std::forward<Ts>(ts)...);
};

(depuis C++20)

La spécification d'exception exception de l'expression lambda s'applique à operator().

Aux fins de la recherche de noms, de la détermination du type et de la valeur du pointeur this et de l'accès aux membres de classe non statiques, le corps de operator() du type fermeture est considéré dans le contexte de l'expression lambda.

struct X
{
    int x, y;
    int operator()(int);
    void f()
    {
        // le contexte de la lambda suivante est la fonction membre X::f
        [=]() -> int
        {
            return operator()(this->x + y); // X::operator()(this->x + (*this).y)
                                            // this a le type X*
        };
    }
};

Références pendantes

Si une entité non référence est capturée par référence, implicitement ou explicitement, et que operator() de l'objet fermeture est invoqué après la fin de la durée de vie de l'entité, un comportement indéfini se produit. Les fermetures C++ ne prolongent pas la durée de vie des objets capturés par référence.

La même règle s'applique à la durée de vie de l'objet *this courant capturé via this.

Cette fonction de conversion définie par l'utilisateur n'est définie que si la liste de capture de l'expression lambda est videet ne possède aucun paramètre d'objet explicite (depuis C++23). C'est une fonction membre publique, constexpr, (depuis C++17) non virtuelle, non explicite, const noexcept de l'objet fermeture.

Cette fonction est une fonction immédiate si l'opérateur d'appel de fonction (ou la spécialisation, pour les lambdas génériques) est une fonction immédiate.

Une lambda générique sans capture possède une fonction de conversion modèle définie par l'utilisateur avec la même liste de paramètres de modèle inventés que operator().

void f1(int (*)(int)) {}
void f2(char (*)(int)) {}
void h(int (*)(int)) {}  // #1
void h(char (*)(int)) {} // #2

auto glambda = [](auto a) { return a; };
f1(glambda); // OK
f2(glambda); // erreur : non convertible
h(glambda);  // OK : appelle #1 car #2 n'est pas convertible

int& (*fpi)(int*) = [](auto* a) -> auto& { return *a; }; // OK

(depuis C++14)

La valeur retournée par la fonction de conversion est un pointeur vers une fonction ayant la liaison de langage C++ qui, lorsqu'elle est invoquée, produit le même effet que l'invocation de l'opérateur d'appel de fonction du type fermeture sur une instance construite par défaut du type fermeture.

(jusqu'à C++14)

La valeur retournée par la fonction de conversion (modèle) est un pointeur vers une fonction ayant la liaison de langage C++ qui, lorsqu'elle est invoquée, produit le même effet que :

  • pour les lambdas non génériques, invoquer operator() du type fermeture sur une instance construite par défaut du type fermeture.
  • pour les lambdas génériques, invoquer la spécialisation correspondante operator() de la lambda générique sur une instance construite par défaut du type fermeture.

(depuis C++14) (jusqu'à C++23)

La valeur retournée par la fonction de conversion (modèle) est

  • si operator() est statique, un pointeur vers cette operator() ayant la liaison de langage C++,
  • sinon, un pointeur vers une fonction ayant la liaison de langage C++ qui, lorsqu'elle est invoquée, produit le même effet que :
  • pour les lambdas non génériques, invoquer operator() du type fermeture sur une instance construite par défaut du type fermeture.
  • pour les lambdas génériques, invoquer la spécialisation correspondante operator() de la lambda générique sur une instance construite par défaut du type fermeture.

(depuis C++23)

Cette fonction est constexpr si l'opérateur d'appel de fonction (ou la spécialisation, pour les lambdas génériques) est constexpr.

static_assert(Fwd(C, 3) == 3);  // OK

Si l'expression lambda capture quoi que ce soit par copie (soit implicitement avec la clause de capture [=], soit explicitement avec une capture qui ne comprend pas le caractère &, par ex. [a, b, c]), le type fermeture comprend des membres de données non statiques sans nom, déclarés dans un ordre non spécifié, qui contiennent des copies de toutes les entités ainsi capturées.

Les membres de données correspondant aux captures sans initialiseurs sont initialisés directement lors de l'évaluation de l'expression lambda. Ceux correspondant aux captures avec initialiseurs sont initialisés selon ce qu'exige l'initialiseur (il peut s'agir d'une initialisation par copie ou directe). Si un tableau est capturé, ses éléments sont initialisés directement dans l'ordre croissant des indices. L'ordre d'initialisation des membres de données est l'ordre de leur déclaration (qui est non spécifié).

Le type de chaque membre de données est le type de l'entité capturée correspondante, sauf si cette entité a un type référence (dans ce cas, les références vers des fonctions sont capturées comme références lvalue vers les fonctions référencées, et les références vers des objets sont capturées comme copies des objets référencés).

Pour les entités capturées par référence (avec le capture-default [&] ou en utilisant le caractère &, par ex. [&a, &b, &c]), il n'est pas spécifié si des membres de données supplémentaires sont déclarés dans le type fermeture, mais tout membre supplémentaire de ce type doit satisfaire LiteralType (depuis C++17).

Les expressions lambda ne sont pas autorisées dans les expressions non évaluées, les arguments de modèle, les déclarations d'alias, les déclarations typedef, ni nulle part dans une déclaration de fonction (ou de modèle de fonction), sauf dans le corps de la fonction et dans les arguments par défaut de la fonction.

(jusqu'à C++20)

Capture lambda

La captures est une liste, séparée par des virgules, de zéro ou plusieurs captures, pouvant commencer optionnellement par capture-default. La liste de capture définit les variables extérieures accessibles depuis le corps de la fonction lambda. Les seuls capture-defaults sont

  • & (capturer implicitement par référence les variables utilisées ayant une durée de stockage automatique) et
  • = (capturer implicitement par copie les variables utilisées ayant une durée de stockage automatique).

L'objet courant (*this) peut être capturé implicitement si l'un des capture-defaults est présent. S'il est capturé implicitement, il l'est toujours par référence, même si le capture-default est =. La capture implicite de *this lorsque le capture-default est = est obsolète. (depuis C++20)

La syntaxe d'une capture individuelle dans captures est :

| | | | identifier | (1) | | | | identifier ... | (2) | | | | identifier initializer | (3) | (depuis C++14) | | | & identifier | (4) | | | | & identifier ... | (5) | | | | & identifier initializer | (6) | (depuis C++14) | | | this | (7) | | | | * this | (8) | (depuis C++17) | | | ... identifier initializer | (9) | (depuis C++20) | | | & ... identifier initializer | (10) | (depuis C++20) | |

  1. capture simple par copie

  2. capture simple par copie qui est une expansion de paquet

  3. capture par copie avec un initialiseur

  4. capture simple par référence

  5. capture simple par référence qui est une expansion de paquet

  6. capture par référence avec un initialiseur

  7. capture simple par référence de l'objet courant

  8. capture simple par copie de l'objet courant

  9. capture par copie avec un initialiseur qui est une expansion de paquet

  10. capture par référence avec un initialiseur qui est une expansion de paquet

Si le capture-default est &, les captures simples suivantes ne doivent pas commencer par &.

struct S2 { void f(int i); };
void S2::f(int i)
{
    [&] {};          // OK : capture par référence par défaut
    [&, i] {};       // OK : capture par référence, sauf i capturé par copie
    [&, &i] {};      // Erreur : capture par référence lorsque la référence est le mode par défaut
    [&, this] {};    // OK, équivalent à [&]
    [&, this, i] {}; // OK, équivalent à [&, i]
}

Si le capture-default est =, les captures simples suivantes doivent commencer par &[ou être *this (depuis C++17) | ou this (depuis C++20)].

struct S2 { void f(int i); };
void S2::f(int i)
{
    [=] {};        // OK : capture par copie par défaut
    [=, &i] {};    // OK : capture par copie, sauf i capturé par référence
    [=, *this] {}; // jusqu'à C++17 : erreur : syntaxe invalide
                   // depuis C++17 : OK : capture la S2 englobante par copie
    [=, this] {};  // jusqu'à C++20 : erreur : this lorsque = est le mode par défaut
                   // depuis C++20 : OK, identique à [=]
}

Une capture ne peut apparaître qu'une seule fois, et son nom doit être différent de tout nom de paramètre :

struct S2 { void f(int i); };
void S2::f(int i)
{
    [i, i] {};        // Erreur : i répété
    [this, *this] {}; // Erreur : "this" répété (C++17)

    [i] (int i) {};   // Erreur : le paramètre et la capture ont le même nom
}

Seules les expressions lambda définies dans une portée de bloc ou dans un initialiseur de membre par défaut peuvent avoir un capture-default ou des captures sans initialiseur. Pour une telle expression lambda, la portée atteignable est définie comme l'ensemble des portées englobantes jusqu'à la fonction englobante la plus interne (y compris elle et ses paramètres). Cela inclut les portées de bloc imbriquées et les portées des lambdas englobantes si cette lambda est imbriquée.

Le identifier de toute capture sans initialiseur (autre que la capture this) est recherché par la recherche de nom non qualifiée habituelle dans la portée atteignable de la lambda. Le résultat de la recherche doit être une variable à durée de stockage automatique déclarée dans la portée atteignable, ou une liaison structurée dont la variable correspondante satisfait ces exigences (depuis C++20). L'entité est capturée explicitement.

Une capture avec initialiseur, appelée init-capture, agit comme si elle déclarait et capturait explicitement une variable déclarée avec le spécificateur de type auto et le même initialiseur, dont la région déclarative est le corps de l'expression lambda (c'est-à-dire qu'elle n'est pas dans la portée de son initialiseur), à l'exception de ce qui suit :

  • si la capture est par copie, le membre de données non statique introduit de l'objet fermeture est un autre moyen de désigner cette variable ;
  • autrement dit, la variable source n'existe pas réellement, et la déduction de type via auto ainsi que l'initialisation s'appliquent au membre de données non statique ;
  • si la capture est par référence, la durée de vie de la variable référence se termine lorsque la durée de vie de l'objet fermeture se termine.

Ceci sert à capturer des types non copiables avec une capture telle que x = std::move(x).

Cela permet aussi de capturer par référence const, avec &cr = std::as_const(x) ou similaire.

int x = 4;

auto y = [&r = x, x = x + 1]() -> int
{
    r += 2;
    return x * x;
}(); // met à jour ::x à 6 et initialise y à 25.

(depuis C++14)

Si une liste de capture possède un capture-default et ne capture pas explicitement l'objet englobant (comme this ou *this), ni une variable automatique qui est odr-utilisable dans le corps de la lambda, ni une liaison structurée dont la variable correspondante a une durée de stockage atomique (depuis C++20), elle capture l'entité implicitement si l'entité est nommée dans une expression potentiellement évaluée au sein d'une expression (y compris lorsque le this-> implicite est ajouté avant une utilisation d'un membre de classe non statique).

Pour la détermination des captures implicites, typeid n'est jamais considéré comme rendant ses opérandes non évalués.

Des entités peuvent être capturées implicitement même si elles ne sont nommées que dans une instruction écartée après l'instanciation du corps de la lambda.

(depuis C++17)

void f(int, const int (&)[2] = {}) {}   // #1
void f(const int&, const int (&)[1]) {} // #2

struct NoncopyableLiteralType
{
    constexpr explicit NoncopyableLiteralType(int n) : n_(n) {}
    NoncopyableLiteralType(const NoncopyableLiteralType&) = delete;

    int n_;
};

void test()
{
    const int x = 17;

    auto l0 = []{ f(x); };           // OK : appelle #1, ne capture pas x
    auto g0 = [](auto a) { f(x); };  // identique à ci-dessus

    auto l1 = [=]{ f(x); };          // OK : capture x (depuis P0588R1) et appelle #1
                                     // la capture peut être optimisée
    auto g1 = [=](auto a) { f(x); }; // identique à ci-dessus

    auto ltid = [=]{ typeid(x); };   // OK : capture x (depuis P0588R1)
                                     // même si x est non évalué
                                     // la capture peut être optimisée

    auto g2 = [=](auto a)
    {
        int selector[sizeof(a) == 1 ? 1 : 2] = {};
        f(x, selector); // OK : est une expression dépendante, donc capture x
    };

    auto g3 = [=](auto a)
    {
        typeid(a + x);  // capture x quelle que soit
                        // si a + x est un opérande non évalué
    };

    constexpr NoncopyableLiteralType w{42};
    auto l4 = []{ return w.n_; };      // OK : w n'est pas odr-used, la capture est inutile
    // auto l5 = [=]{ return w.n_; };  // erreur : w doit être capturé par copie
}

Si le corps d'une lambda odr-utilise une entité capturée par copie, c'est le membre du type fermeture qui est accédé. Si elle n'odr-utilise pas l'entité, l'accès se fait sur l'objet original :

void f(const int*);
void g()
{
    const int N = 10;
    [=]
    {
        int arr[N]; // non odr-use : fait référence à la constante const int N de g
        f(&N); // odr-use : provoque la capture de N (par copie)
               // &N est l'adresse du membre N de l'objet fermeture, et non du N de g
    }();
}

Si une lambda odr-utilise une référence capturée par référence, elle utilise l'objet désigné par la référence originale, et non la référence capturée elle-même :

#include <iostream>

auto make_function(int& x)
{
    return [&] { std::cout << x << '\n'; };
}

int main()
{
    int i = 3;
    auto f = make_function(i); // l'utilisation de x dans f se lie directement à i
    i = 5;
    f(); // OK : affiche 5
}

Dans le corps d'une lambda avec le capture-default =, le type de toute entité capturable est celui qu'elle aurait si elle était capturée (si bien qu'un qualificateur const est souvent ajouté si la lambda n'est pas mutable), même si l'entité figure dans un opérande non évalué et n'est pas capturée (par ex. dans decltype) :

void f3()
{
    float x, &r = x;
    [=]
    { // x et r ne sont pas capturés (l'apparition dans un opérande de decltype n'est pas un odr-use)
        decltype(x) y1;        // y1 a le type float
        decltype((x)) y2 = y1; // y2 a le type float const& car cette lambda
                               // n'est pas mutable et x est une lvalue
        decltype(r) r1 = y1;   // r1 a le type float& (la transformation n'est pas prise en compte)
        decltype((r)) r2 = y2; // r2 a le type float const&
    };
}

Toute entité capturée par une lambda (implicitement ou explicitement) est odr-utilisée par l'expression lambda (donc la capture implicite par une lambda imbriquée déclenche une capture implicite dans la lambda englobante).

Toutes les variables capturées implicitement doivent être déclarées dans la portée atteignable de la lambda.

Si une lambda capture l'objet englobant (comme this ou *this), soit la fonction englobante la plus proche doit être une fonction membre non statique, soit la lambda doit se trouver dans un initialiseur de membre par défaut :

struct s2
{
    double ohseven = .007;
    auto f() // fonction englobante la plus proche pour les deux lambdas suivantes
    {
        return [this]      // capture le s2 englobant par référence
        {
            return [*this] // capture le s2 englobant par copie (C++17)
            {
                return ohseven; // OK
            }
        }();
    }

    auto g()
    {
        return [] // ne capture rien
        {
            return [*this] {}; // erreur : *this non capturé par l'expression lambda externe
        }();
    }
};

Si une expression lambda (ou une spécialisation de l'opérateur d'appel de fonction d'une lambda générique) (depuis C++14) ODR-utilise *this ou toute variable à durée de stockage automatique, elle doit être capturée par l'expression lambda.

void f1(int i)
{
    int const N = 20;
    auto m1 = [=]
    {
        int const M = 30;
        auto m2 = [i]
        {
            int x[N][M]; // N et M ne sont pas odr-used
                         // (OK, ils ne sont pas capturés)
            x[0][0] = i; // i est capturé explicitement par m2
                         // et capturé implicitement par m1
        };
    };

    struct s1 // classe locale dans f1()
    {
        int f;
        void work(int n) // fonction membre non statique
        {
            int m = n * n;
            int j = 40;
            auto m3 = [this, m]
            {
                auto m4 = [&, j] // erreur : j n'est pas capturé par m3
                {
                    int x = n; // erreur : n est capturé implicitement par m4
                               // mais pas capturé par m3
                    x += m;    // OK : m est capturé implicitement par m4
                               // et capturé explicitement par m3
                    x += i;    // erreur : i est hors de la portée atteignable
                               // (qui se termine à work())
                    x += f;    // OK : this est capturé implicitement par m4
                               // et capturé explicitement par m3
                };
            };
        }
    };
}

Les membres de classe ne peuvent pas être capturés explicitement par une capture sans initialiseur (comme mentionné plus haut, seules les variables sont autorisées dans la liste de capture) :

class S
{
    int x = 0;

    void f()
    {
        int i = 0;
    //  auto l1 = [i, x] { use(i, x); };      // erreur : x n'est pas une variable
        auto l2 = [i, x = x] { use(i, x); };  // OK, capture par copie
        i = 1; x = 1; l2(); // appelle use(0,0)
        auto l3 = [i, &x = x] { use(i, x); }; // OK, capture par référence
        i = 2; x = 2; l3(); // appelle use(1,2)
    }
};

Lorsqu'une lambda capture un membre par capture implicite par copie, elle ne fait pas de copie de ce membre variable : l'utilisation d'un membre variable m est traitée comme une expression (*this).m, et *this est toujours capturé implicitement par référence :

class S
{
    int x = 0;

    void f()
    {
        int i = 0;

        auto l1 = [=] { use(i, x); }; // capture une copie de i et
                                      // une copie du pointeur this
        i = 1; x = 1; l1();           // appelle use(0, 1), comme si
                                      // i par copie et x par référence

        auto l2 = [i, this] { use(i, x); }; // identique à ci-dessus, rendu explicite
        i = 2; x = 2; l2();           // appelle use(1, 2), comme si
                                      // i par copie et x par référence

        auto l3 = [&] { use(i, x); }; // capture i par référence et
                                      // une copie du pointeur this
        i = 3; x = 2; l3();           // appelle use(3, 2), comme si
                                      // i et x sont tous deux par référence

        auto l4 = [i, *this] { use(i, x); }; // fait une copie de *this,
                                             // y compris une copie de x
        i = 4; x = 4; l4();           // appelle use(3, 2), comme si
                                      // i et x sont tous deux par copie
    }
};

Si une expression lambda apparaît dans un argument par défaut, elle ne peut rien capturer explicitement ou implicitement, sauf si toutes les captures ont des initialiseurs qui satisfont les contraintes d'une expression apparaissant dans un argument par défaut (depuis C++14) :

void f2()
{
    int i = 1;

    void g1( int = [i] { return i; }() ); // erreur : capture quelque chose
    void g2( int = [i] { return 0; }() ); // erreur : capture quelque chose
    void g3( int = [=] { return i; }() ); // erreur : capture quelque chose

    void g4( int = [=] { return 0; }() );       // OK : sans capture
    void g5( int = [] { return sizeof i; }() ); // OK : sans capture

    // C++14
    void g6( int = [x = 1] { return x; }() ); // OK : 1 peut apparaître
                                              //     dans un argument par défaut
    void g7( int = [x = i] { return x; }() ); // erreur : i ne peut pas apparaître
                                              //        dans un argument par défaut
}

Les membres des unions anonymes ne peuvent pas être capturés. Les champs de bits ne peuvent être capturés que par copie.

Si une lambda imbriquée m2 capture quelque chose qui est aussi capturé par la lambda englobante immédiate m1, alors la capture de m2 est transformée comme suit :

  • si la lambda englobante m1 capture par copie, m2 capture le membre non statique du type fermeture de m1, et non la variable originale ni *this ; si m1 n'est pas mutable, le membre de données non statique est considéré comme qualifié const.
  • si la lambda englobante m1 capture par référence, m2 capture la variable originale ou *this.
#include <iostream>

int main()
{
    int a = 1, b = 1, c = 1;

    auto m1 = [a, &b, &c]() mutable
    {
        auto m2 = [a, b, &c]() mutable
        {
            std::cout << a << b << c << '\n';
            a = 4; b = 4; c = 4;
        };
        a = 3; b = 3; c = 3;
        m2();
    };

    a = 2; b = 2; c = 2;

    m1();                             // appelle m2() et affiche 123
    std::cout << a << b << c << '\n'; // prints 234
}

Si une lambda capture quoi que ce soit, le type du paramètre d'objet explicite (s'il existe) de l'opérateur d'appel de fonction ne peut être que

  • le type de fermeture,
  • un type de classe dérivé publiquement et sans ambiguïté du type de fermeture, ou
  • une référence à un tel type éventuellement qualifié cv.
struct C
{
    template<typename T>
    C(T);
};

void func(int i)
{
    int x = [=](this auto&&) { return i; }();  // OK
    int y = [=](this C) { return i; }();       // error
    int z = [](this C) { return 42; }();       // OK

    auto lambda = [n = 42] (this auto self) { return n; };
    using Closure = decltype(lambda);
    struct D : private Closure {
        D(Closure l) : Closure(l) {}
        using Closure::operator();
        friend Closure;
    };
    D{lambda}(); // error
}

(depuis C++23)

La règle de capture implicite des lambdas est légèrement modifiée par le rapport de défaut P0588R1. En 2023-10, certaines grandes implémentations n'ont pas entièrement implémenté ce rapport, et l'ancienne règle, qui détecte les odr-use, est donc encore utilisée dans certains cas.

Ancienne règle avant P0588R1

Si une liste de capture comporte un capture-default et ne capture pas explicitement l'objet englobant (comme this ou *this), ni une variable automatique odr-usable dans le corps de la lambda, ni une liaison structurée dont la variable correspondante a une durée de stockage atomique (depuis C++20), elle capture implicitement l'entité implicitement si l'entité est

  • nommée dans une expression potentiellement évaluée au sein d'une expression qui dépend d'un paramètre de modèle d'une lambda générique, ou

(depuis C++14)

  • odr-used par le corps de la lambda.

Exemple

Cet exemple montre comment passer une lambda à un algorithme générique et comment les objets résultant d'une expression lambda peuvent être stockés dans des objets std::function.

#include <algorithm>
#include <functional>
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> c{1, 2, 3, 4, 5, 6, 7};
    int x = 5;
    c.erase(std::remove_if(c.begin(), c.end(), [x](int n) { return n < x; }), c.end());

    std::cout << "c: ";
    std::for_each(c.begin(), c.end(), [](int i) { std::cout << i << ' '; });
    std::cout << '\n';

    // le type d'une fermeture ne peut pas être nommé, mais peut être déduit avec auto
    // depuis C++14, une lambda pouvait aussi posséder des arguments par défaut
    auto func1 = [](int i = 6) { return i + 4; };
    std::cout << "func1: " << func1() << '\n';

    // comme tous les objets appelables, les fermetures peuvent être capturées dans std::function
    // (cela peut entraîner un surcoût inutile)
    std::function<int(int)> func2 = [](int i) { return i + 4; };
    std::cout << "func2: " << func2(6) << '\n';

    constexpr int fib_max {8};
    std::cout << "Emulate `recursive lambda` calls:\nFibonacci numbers: ";
    auto nth_fibonacci = [](int n)
    {
        std::function<int(int, int, int)> fib = [&](int n, int a, int b)
        {
            return n ? fib(n - 1, a + b, a) : b;
        };
        return fib(n, 0, 1);
    };

    for (int i{1}; i <= fib_max; ++i)
        std::cout << nth_fibonacci(i) << (i < fib_max ? ", " : "\n");

    std::cout << "Alternative approach to lambda recursion:\nFibonacci numbers: ";
    auto nth_fibonacci2 = [](auto self, int n, int a = 0, int b = 1) -> int
    {
        return n ? self(self, n - 1, a + b, a) : b;
    };

    for (int i{1}; i <= fib_max; ++i)
        std::cout << nth_fibonacci2(nth_fibonacci2, i) << (i < fib_max ? ", " : "\n");

#ifdef __cpp_explicit_this_parameter
    std::cout << "C++23 approach to lambda recursion:\n";
    auto nth_fibonacci3 = [](this auto self, int n, int a = 0, int b = 1) -> int
    {
         return n ? self(n - 1, a + b, a) : b;
    };

    for (int i{1}; i <= fib_max; ++i)
        std::cout << nth_fibonacci3(i) << (i < fib_max ? ", " : "\n");
#endif
}
