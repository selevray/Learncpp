Littéraux définis par l'utilisateur (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Permet aux littéraux entiers, à virgule flottante, de caractère et de chaîne de produire des objets de type défini par l'utilisateur, en définissant un suffixe défini par l'utilisateur.

Syntaxe

Un littéral défini par l'utilisateur est une expression de l'une des formes suivantes

| | | | decimal-literal ud-suffix | (1) | | | | octal-literal ud-suffix | (2) | | | | hex-literal ud-suffix | (3) | | | | binary-literal ud-suffix | (4) | | | | fractional-constant exponent-part ﻿*(facultatif)* ud-suffix | (5) | | | | digit-sequence exponent-part ud-suffix | (6) | | | | character-literal ud-suffix | (7) | | | | string-literal ud-suffix | (8) | | |

1-4) littéraux entiers définis par l'utilisateur, comme 12_km

5-6) littéraux à virgule flottante définis par l'utilisateur, comme 0.5_Pa

  1. littéral de caractère défini par l'utilisateur, comme 'c'_X

  2. littéral de chaîne défini par l'utilisateur, comme "abd"_L ou u"xyz"_M

  • decimal-literal — identique à littéral entier, un chiffre décimal non nul suivi de zéro ou plusieurs chiffres décimaux
  • octal-literal — identique à littéral entier, un zéro suivi de zéro ou plusieurs chiffres octaux
  • hex-literal — identique à littéral entier, 0x ou 0X suivi d'un ou plusieurs chiffres hexadécimaux
  • binary-literal — identique à littéral entier, 0b ou 0B suivi d'un ou plusieurs chiffres binaires
  • digit-sequence — identique à littéral flottant, une suite de chiffres décimaux
  • fractional-constant — identique à littéral flottant, soit un digit-sequence suivi d'un point (123.), soit un digit-sequence optionnel suivi d'un point et d'un autre digit-sequence (1.0 ou .12)
  • exponent-part — identique à littéral flottant, la lettre e ou la lettre E suivie d'un signe optionnel, puis de digit-sequence
  • character-literal — identique à littéral de caractère
  • string-literal — identique à celui de littéral de chaîne, y compris les littéraux de chaîne bruts
  • ud-suffix — un identifiant, introduit par une déclaration de opérateur littéral ou de modèle d'opérateur littéral (voir ci-dessous)

Dans les suites de chiffres des entiers et des nombres à virgule flottante, des séparateurs optionnels ' sont autorisés entre deux chiffres quelconques.

(depuis C++14)

Si un jeton correspond à la fois à la syntaxe d'un littéral défini par l'utilisateur et à celle d'un littéral ordinaire, il est considéré comme un littéral ordinaire (c'est-à-dire qu'il est impossible de surcharger LL dans 123LL).

Lorsque le compilateur rencontre un littéral défini par l'utilisateur avec ud-suffix X, il effectue une recherche de nom non qualifiée, en cherchant une fonction portant le nom operator""X. Si la recherche ne trouve aucune déclaration, le programme est mal formé. Sinon,

  1. Pour les littéraux entiers définis par l'utilisateur,

a) si l'ensemble de surcharge comprend un opérateur littéral dont le type de paramètre est unsigned long long, l'expression de littéral définie par l'utilisateur est traitée comme un appel de fonction operator ""X(n ﻿ULL), où n est le littéral sans ud-suffix ;

b) sinon, l'ensemble de surcharge doit comprendre soit un opérateur littéral brut, soit un modèle d'opérateur littéral numérique, mais pas les deux. Si l'ensemble de surcharge comprend un opérateur littéral brut, l'expression de littéral définie par l'utilisateur est traitée comme un appel de fonction operator""X("n ﻿") ;

c) sinon, si l'ensemble de surcharge comprend un modèle d'opérateur littéral numérique, l'expression de littéral définie par l'utilisateur est traitée comme un appel de fonction operator""X<'c1 ﻿', 'c2 ﻿', 'c3 ﻿'..., 'ck ﻿'>(), où c1..ck sont les caractères individuels de n et tous appartiennent au jeu de caractères de base.

  1. Pour les littéraux à virgule flottante définis par l'utilisateur,

a) Si l'ensemble de surcharge comprend un opérateur littéral dont le type de paramètre est long double, l'expression de littéral définie par l'utilisateur est traitée comme un appel de fonction operator ""X(f ﻿ ﻿L), où f est le littéral sans ud-suffix ;

b) sinon, l'ensemble de surcharge doit comprendre soit un opérateur littéral brut, soit un modèle d'opérateur littéral numérique, mais pas les deux. Si l'ensemble de surcharge comprend un opérateur littéral brut, l'expression de littéral définie par l'utilisateur est traitée comme un appel de fonction operator ""X("f ﻿ ﻿") ;

c) sinon, si l'ensemble de surcharge comprend un modèle d'opérateur littéral numérique, l'expression de littéral définie par l'utilisateur est traitée comme un appel de fonction operator""X<'c1 ﻿', 'c2 ﻿', 'c3 ﻿'..., 'ck ﻿'>(), où c1..ck sont les caractères individuels de f et tous appartiennent au jeu de caractères de base.

  1. Pour les littéraux de chaîne définis par l'utilisateur, soit str le littéral sans ud-suffix :

a) Si l'ensemble de surcharge comprend un modèle d'opérateur littéral de chaîne dont un paramètre de modèle non de type admet str comme argument de modèle bien formé, alors l'expression de littéral définie par l'utilisateur est traitée comme un appel de fonction operator ""X<str>() ;

(depuis C++20)

b) sinon, l'expression de littéral définie par l'utilisateur est traitée comme un appel de fonction operator ""X (str, len), où len est la longueur du littéral de chaîne, à l'exclusion du caractère nul de fin.

  1. Pour les littéraux de caractère définis par l'utilisateur, l'expression de littéral définie par l'utilisateur est traitée comme un appel de fonction operator ""X(ch), où ch est le littéral sans ud-suffix.
long double operator ""_w(long double);
std::string operator ""_w(const char16_t*, size_t);
unsigned    operator ""_w(const char*);

int main()
{
    1.2_w;    // appelle operator ""_w(1.2L)
    u"one"_w; // appelle operator ""_w(u"one", 3)
    12_w;     // appelle operator ""_w("12")
    "two"_w;  // erreur : aucun opérateur littéral applicable
}

Lorsque la concaténation de littéraux chaîne a lieu dans la phase de traduction 6, les littéraux chaîne définis par l'utilisateur sont également concaténés, et leurs ud-suffixes sont ignorés pour la concaténation, sauf qu'un seul suffixe peut apparaître sur l'ensemble des littéraux concaténés :

int main()
{
    L"A" "B" "C"_x;  // OK : identique à L"ABC"_x
    "P"_x "Q" "R"_y; // erreur : deux ud-suffixes différents (_x et _y)
}

Opérateurs littéraux

La fonction appelée par un littéral défini par l'utilisateur est connue sous le nom d'opérateur littéral (ou, s'il s'agit d'un modèle, modèle d'opérateur littéral). Elle est déclarée comme toute autre fonction ou modèle de fonction à portée d'espace de noms (elle peut aussi être une fonction amie, une instanciation ou spécialisation explicite d'un modèle de fonction, ou introduite par une déclaration using), à l'exception des restrictions suivantes :

Le nom de cette fonction peut avoir l'une des deux formes suivantes :

| | | | operator "" identifier | (1) | (obsolète) | | | operator user-defined-string-literal | (2) | | |

  • identifier — l'identifiant à utiliser comme ud-suffix pour les littéraux définis par l'utilisateur qui appelleront cette fonction
  • user-defined-string-literal — la séquence de caractères "" suivie, sans espace, de la séquence de caractères qui devient le ud-suffix

  1. Déclare un opérateur littéral.

  2. Déclare un opérateur littéral. Cette syntaxe permet d'utiliser des mots-clés du langage et des identifiants réservés comme ud-suffix, par exemple operator ""if de l'en-tête <complex>.

ud-suffix doit commencer par le tiret bas _ : les suffixes ne commençant pas par un tiret bas sont réservés aux opérateurs littéraux fournis par la bibliothèque standard. Il ne peut pas non plus contenir de doubles tirets bas __ : de tels suffixes sont également réservés.

Si l'opérateur littéral est un modèle, il doit avoir une liste de paramètres vide et ne peut avoir qu'un seul paramètre de modèle, qui doit être un pack de paramètres de modèle non typé dont le type d'élément est char (auquel cas il est connu sous le nom de modèle d'opérateur littéral numérique) :

template<char...>
double operator ""_x();

ou un paramètre de modèle non typé de type classe (auquel cas il est connu sous le nom de modèle d'opérateur littéral chaîne) :

struct A { constexpr A(const char*); };

template<A a>
A operator ""_a();

(depuis C++20)

Seules les listes de paramètres suivantes sont autorisées pour les opérateurs littéraux :

| | | | ( const char* ) | (1) | | | | ( unsigned long long int ) | (2) | | | | ( long double ) | (3) | | | | ( char ) | (4) | | | | ( wchar_t ) | (5) | | | | ( char8_t ) | (6) | (depuis C++20) | | | ( char16_t ) | (7) | | | | ( char32_t ) | (8) | | | | ( const char*, std::size_t ) | (9) | | | | ( const wchar_t*, std::size_t ) | (10) | | | | ( const char8_t*, std::size_t ) | (11) | (depuis C++20) | | | ( const char16_t*, std::size_t ) | (12) | | | | ( const char32_t*, std::size_t ) | (13) | | |

  1. Les opérateurs littéraux avec cette liste de paramètres sont les opérateurs littéraux bruts, utilisés comme solutions de repli pour les littéraux entiers et à virgule flottante définis par l'utilisateur (voir ci-dessus)

  2. Les opérateurs littéraux avec ces listes de paramètres sont le premier choix d'opérateur littéral pour les littéraux entiers définis par l'utilisateur

  3. Les opérateurs littéraux avec ces listes de paramètres sont le premier choix d'opérateur littéral pour les littéraux à virgule flottante définis par l'utilisateur

4-8) Les opérateurs littéraux avec ces listes de paramètres sont appelés par les littéraux caractère définis par l'utilisateur

9-13) Les opérateurs littéraux avec ces listes de paramètres sont appelés par les littéraux chaîne définis par l'utilisateur

Les arguments par défaut ne sont pas autorisés.

La liaison de langage C n'est pas autorisée.

Outre les restrictions ci-dessus, les opérateurs littéraux et les modèles d'opérateurs littéraux sont des fonctions (et modèles de fonctions) ordinaires : ils peuvent être déclarés inline ou constexpr, avoir une liaison interne ou externe, être appelés explicitement, leurs adresses peuvent être prises, etc.

#include <string>

void        operator ""_km(long double); // OK, sera appelé pour 1.0_km
void        operator "" _km(long double); // identique à ci-dessus, obsolète
std::string operator ""_i18n(const char*, std::size_t); // OK

template<char...>
double operator ""_pi(); // OK
float  operator ""_e(const char*); // OK

// erreur : le suffixe doit commencer par un tiret bas
float operator ""Z(const char*);

// erreur : tous les noms commençant par un tiret bas suivi d'une majuscule
// lettre sont réservés (NOTE : un espace entre "" et _).
double operator"" _Z(long double);

// OK. NOTE : pas d'espace entre "" et _.
double operator""_Z(long double);

// OK : les opérateurs littéraux peuvent être surchargés
double operator ""_Z(const char* args);

int main() {}

Notes

Depuis l'introduction des littéraux définis par l'utilisateur, le code utilisant des macros de format pour les constantes des types entiers à largeur fixe sans espace après le littéral chaîne qui précède est devenu invalide : std::printf("%"PRId64"\n",INT64_MIN); doit être remplacé par std::printf("%" PRId64"\n",INT64_MIN);.

En raison du maximal munch, les littéraux entiers et à virgule flottante définis par l'utilisateur se terminant par p, P, (depuis C++17) e et E, lorsqu'ils sont suivis des opérateurs + ou -, doivent être séparés de l'opérateur par un espace ou des parenthèses dans le source :

long double operator""_E(long double);
long double operator""_a(long double);
int operator""_p(unsigned long long);

auto x = 1.0_E+2.0;   // error
auto y = 1.0_a+2.0;   // OK
auto z = 1.0_E +2.0;  // OK
auto q = (1.0_E)+2.0; // OK
auto w = 1_p+2;       // error
auto u = 1_p +2;      // OK

Il en va de même pour l'opérateur point qui suit un littéral entier ou à virgule flottante défini par l'utilisateur :

#include <chrono>

using namespace std::literals;

auto a = 4s.count();   // Erreur
auto b = 4s .count();  // OK
auto c = (4s).count(); // OK

Sinon, un unique jeton de nombre de préprocesseur invalide (par exemple 1.0_E+2.0 ou 4s.count) est formé, ce qui provoque l'échec de la compilation.

Exemples

#include <algorithm>
#include <cstddef>
#include <iostream>
#include <numbers>
#include <string>

// utilisé pour la conversion des degrés (paramètre d'entrée) en radians (sortie retournée)
constexpr long double operator""_deg_to_rad(long double deg)
{
    long double radians = deg * std::numbers::pi_v<long double> / 180;
    return radians;
}

// utilisé avec un type personnalisé
struct mytype
{
    unsigned long long m;
};

constexpr mytype operator""_mytype(unsigned long long n)
{
    return mytype{n};
}

// utilisé pour les effets de bord
void operator""_print(const char* str)
{
    std::cout << str << '\n';
}

#if __cpp_nontype_template_args < 201911

std::string operator""_x2 (const char* str, std::size_t)
{
    return std::string{str} + str;
}

#else // C++20 string literal operator template

template<std::size_t N>
struct DoubleString
{
    char p[N + N - 1]{};

    constexpr DoubleString(char const(&pp)[N])
    {
        std::ranges::copy(pp, p);
        std::ranges::copy(pp, p + N - 1);
    }
};

template<DoubleString A>
constexpr auto operator""_x2()
{
    return A.p;
}

#endif // C++20

int main()
{
    double x_rad = 90.0_deg_to_rad;
    std::cout << std::fixed << x_rad << '\n';

    mytype y = 123_mytype;
    std::cout << y.m << '\n';

    0x123ABC_print;
    std::cout << "abc"_x2 << '\n';
}

Bibliothèque standard

Les opérateurs littéraux suivants sont définis dans la bibliothèque standard :

Défini dans l'espace de noms en ligne std::literals::complex_literals

  • operator""ifoperator""ioperator""il (C++14) — un littéral std::complex représentant un nombre purement imaginaire (fonction)

Défini dans l'espace de noms en ligne std::literals::chrono_literals

  • operator""h (C++14) — un littéral std::chrono::duration représentant des heures (fonction)
  • operator""min (C++14) — un littéral std::chrono::duration représentant des minutes (fonction)
  • operator""s (C++14) — un littéral std::chrono::duration représentant des secondes (fonction)
  • operator""ms (C++14) — un littéral std::chrono::duration représentant des millisecondes (fonction)
  • operator""us (C++14) — un littéral std::chrono::duration représentant des microsecondes (fonction)
  • operator""ns (C++14) — un littéral std::chrono::duration représentant des nanosecondes (fonction)
  • operator""y (C++20) — un littéral std::chrono::year représentant une année particulière (fonction)
  • operator""d (C++20) — un littéral std::chrono::day représentant un jour d'un mois (fonction)

Défini dans l'espace de noms en ligne std::literals::string_literals

  • operator""s (C++14) — convertit un littéral de tableau de caractères en basic_string (fonction)

Défini dans l'espace de noms en ligne std::literals::string_view_literals

  • operator""sv (C++17) — crée une vue de chaîne à partir d'un littéral de tableau de caractères (fonction)
