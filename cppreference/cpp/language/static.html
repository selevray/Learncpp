membres static

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Dans une définition de classe, le mot-clé static déclare des membres qui ne sont pas liés aux instances de classe.

En dehors d'une définition de classe, il a une signification différente : voir durée de stockage.

Syntaxe

Une déclaration d'un membre statique est une déclaration de membre dont les spécificateurs de déclaration contiennent le mot-clé static. Le mot-clé static apparaît généralement avant les autres spécificateurs (c'est pourquoi la syntaxe est souvent décrite informellement comme static data-member ou static member-function), mais il peut apparaître n'importe où dans la séquence de spécificateurs.

Le nom de tout membre de données statique et de toute fonction membre statique doit être différent du nom de la classe englobante.

Explication

Les membres statiques d'une classe ne sont pas associés aux objets de la classe : ce sont des variables indépendantes à durée de stockage statique ou thread (depuis C++11) durée de stockage ou des fonctions ordinaires.

Le mot-clé static n'est utilisé qu'avec la déclaration d'un membre statique, dans la définition de classe, mais pas avec la définition de ce membre statique :

class X { static int n; }; // déclaration (utilise « static »)
int X::n = 1;              // définition (n'utilise pas « static »)

La déclaration dans le corps de la classe n'est pas une définition et peut déclarer le membre comme étant de type incomplet (autre que void), y compris le type dans lequel le membre est déclaré :

struct Foo;

struct S
{
    static int a[]; // déclaration, type incomplet
    static Foo x;   // déclaration, type incomplet
    static S s;     // déclaration, type incomplet (à l'intérieur de sa propre définition)
};

int S::a[10]; // définition, type complet
struct Foo {};
Foo S::x;     // définition, type complet
S S::s;       // définition, type complet

Cependant, si la déclaration utilise le spécificateur constexprou inline (depuis C++17), le membre doit être déclaré de type complet.

(depuis C++11)

Pour désigner un membre statique m de la classe T, deux formes peuvent être utilisées : le nom qualifié T::m ou l'expression d'accès au membre E.m ou E->m, où E est une expression qui s'évalue en T ou T* respectivement. Lorsqu'on se trouve dans la même portée de classe, la qualification est inutile :

struct X
{
    static void f(); // declaration
    static int n;    // declaration
};

X g() { return X(); } // une fonction quelconque renvoyant X

void f()
{
    X::f();  // X::f est un nom qualifié de fonction membre statique
    g().f(); // g().f est une expression d'accès membre désignant une fonction membre statique
}

int X::n = 7; // definition

void X::f() // definition
{
    n = 1; // X::n est accessible simplement sous le nom n dans cette portée
}

Les membres statiques obéissent aux règles d'accès aux membres de classe (private, protected, public).

Fonctions membres statiques

Les fonctions membres statiques ne sont associées à aucun objet. Lorsqu'elles sont appelées, elles n'ont pas de pointeur this.

Les fonctions membres statiques ne peuvent pas être virtual, const, volatile ni qualifiées ref.

L'adresse d'une fonction membre statique peut être stockée dans un pointeur de fonction ordinaire, mais pas dans un pointeur de fonction membre.

Membres de données statiques

Les membres de données statiques ne sont associés à aucun objet. Ils existent même si aucun objet de la classe n'a été défini. Il n'existe qu'une seule instance du membre de données statique dans tout le programme, à durée de stockagestatique, sauf si le mot-clé thread_local est utilisé, auquel cas il existe un tel objet par thread, à durée de stockage thread (depuis C++11).

Les membres de données statiques ne peuvent pas être mutable.

Les membres de données statiques d'une classe dans une portée d'espace de noms ont une liaison externe si la classe elle-même a une liaison externe (n'est pas membre d'un espace de noms anonyme). Les classes locales (classes définies dans des fonctions) et les classes anonymes, y compris les classes membres de classes anonymes, ne peuvent pas avoir de membres de données statiques.

Un membre de données statique peut être déclaré inline. Un membre de données statique inline peut être défini dans la définition de classe et peut spécifier un initialiseur. Il n'a pas besoin de définition hors de la classe :

struct X
{
    inline static int fully_usable = 1; // Aucune définition hors de la classe n'est requise, utilisable en ODR
    inline static const std::string class_name{"X"}; // De même

    static const int non_addressable = 1; // Cf. constantes non inline, utilisables
                                          // pour leur valeur, mais non utilisables en ODR
    // static const std::string class_name{"X"}; // Déclaration non intégrale de ceci
                                                 // la forme est totalement interdite
};

(depuis C++17)

Membres statiques constants

Si un membre de données statique de type entier ou énumération est déclaré const (et non volatile), il peut être initialisé avec un initialiseur dont chaque expression est une expression constante, directement dans la définition de classe :

struct X
{
    const static int n = 1;
    const static int m{2}; // depuis C++11
    const static int k;
};
const int X::k = 3;

Si un membre de données statique de LiteralType est déclaré constexpr, il doit être initialisé avec un initialiseur dont chaque expression est une expression constante, directement dans la définition de classe :

struct X
{
    constexpr static int arr[] = { 1, 2, 3 };        // OK
    constexpr static std::complex<double> n = {1,2}; // OK
    constexpr static int k; // Error: constexpr static nécessite un initialiseur
};

(depuis C++11)

Si un membre de données statique non inline (depuis C++17) de type const ou un membre de données statique constexpr (depuis C++11) (jusqu'à C++17) est ODR-utilisé, une définition dans la portée d'espace de noms reste requise, mais elle ne peut pas avoir d'initialiseur.

Un membre de données statique constexpr est implicitement inline et n'a pas besoin d'être redéclaré dans la portée d'espace de noms. Cette redéclaration sans initialiseur (autrefois requise) reste permise, mais elle est obsolète.

(depuis C++17)

struct X
{
    static const int n = 1;
    static constexpr int m = 4;
};

const int *p = &X::n, *q = &X::m; // X::n et X::m sont utilisés en ODR
const int X::n;             // … donc une définition est nécessaire
constexpr int X::m;         // … (sauf pour X::m en C++17)
