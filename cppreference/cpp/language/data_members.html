Membres de données non statiques

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les membres de données non statiques sont déclarés dans une spécification de membres d'une classe.

class S
{
    int n;              // membre de données non statique
    int& r;             // membre de données non statique de type référence
    int a[2] = {1, 2};  // membre de données non statique avec initialiseur de membre par défaut (C++11)
    std::string s, *ps; // deux membres de données non statiques

    struct NestedS
    {
        std::string s;
    } d5;               // membre de données non statique de type imbriqué

    char bit : 2;       // champ de bits de deux bits
};

Toutes les déclarations simples sont autorisées, sauf

  • les spécificateurs de classe de stockage extern et register ne sont pas autorisés ;
  • le spécificateur de classe de stockage thread_local n'est pas autorisé (mais il l'est pour les membres de données static) ;

(depuis C++11)

  • les types incomplets, les types de classes abstraites et les tableaux de ceux-ci ne sont pas autorisés : en particulier, une classe C ne peut pas avoir de membre de données non statique de type C, bien qu'elle puisse avoir un membre de données non statique de type C& (référence vers C) ou C* (pointeur vers C) ;
  • un membre de données non statique ne peut pas porter le même nom que la classe si au moins un constructeur déclaré par l'utilisateur est présent ;
  • un spécificateur de type substitut (c'est-à-dire auto[, decltype(auto) (depuis C++14) | , un nom de modèle de classe soumis à la déduction (depuis C++17) | , un espace réservé contraint (depuis C++20)]) ne peut pas être utilisé dans une déclaration de membre de données non statique (bien qu'il soit autorisé pour les membres de données statiques qui sont initialisés dans la définition de la classe).

(depuis C++11)

En outre, les déclarations de champs de bits sont autorisées.

Disposition en mémoire

Lorsqu'un objet d'une classe C est créé, chaque membre de données non statique d'un type qui n'est pas une référence est alloué dans une partie de la représentation de l'objet de C. Le fait que les membres référence occupent ou non un espace de stockage est défini par l'implémentation, mais leur durée de stockage est la même que celle de l'objet dont ils sont membres.

Pour les types de classes qui ne sont pas des union, les membres [de taille non nulle (depuis C++20) | non séparés par un spécificateur d'accès (jusqu'à C++11) | ayant le même accès membre (depuis C++11)] sont toujours alloués de façon que les membres déclarés plus tard aient des adresses plus élevées au sein de l'objet de classe. Les membres [séparés par un spécificateur d'accès (jusqu'à C++11) | ayant un contrôle d'accès différent (depuis C++11)] sont alloués dans un ordre non spécifié (le compilateur peut les regrouper).

(jusqu'à C++23)

Pour les types de classes qui ne sont pas des union, les membres de taille non nulle sont toujours alloués de façon que les membres déclarés plus tard aient des adresses plus élevées au sein de l'objet de classe. Notez que le contrôle d'accès des membres affecte toujours la propriété de disposition standard (voir ci-dessous).

(depuis C++23)

Les exigences d'alignement peuvent imposer un rembourrage entre les membres, ou après le dernier membre d'une classe.

Disposition standard

Une classe est considérée comme ayant une disposition standard et les propriétés décrites ci-dessous si et seulement si c'est une classe POD.

(jusqu'à C++11)

Une classe dont tous les membres de données non statiques ont le même contrôle d'accès et dont certaines autres conditions sont satisfaites est appelée classe à disposition standard (voir classe à disposition standard pour la liste des exigences).

(depuis C++11)

La séquence initiale commune de deux types de classes non union à disposition standard est la plus longue séquence de membres de données non statiques et de champs de bits, dans l'ordre de déclaration, commençant par la première entité de chacune des classes, telle que

  • si __has_cpp_attribute(no_unique_address) n'est pas 0, aucune des deux entités n'est déclarée avec l'attribut [[no_unique_address]],

(depuis C++20)

  • les entités correspondantes ont des types compatibles en disposition,
  • les entités correspondantes ont les mêmes exigences d'alignement, et
  • soit les deux entités sont des champs de bits de même largeur, soit aucune n'est un champ de bits.
struct A { int a; char b; };
struct B { const int b1; volatile char b2; };
// la séquence initiale commune de A et B est A.a, A.b et B.b1, B.b2

struct C { int c; unsigned : 0; char b; };
// la séquence initiale commune de A et C est A.a et C.c

struct D { int d; char b : 4; };
// la séquence initiale commune de A et D est A.a et D.d

struct E { unsigned int e; char b; };
// la séquence initiale commune de A et E est vide

Deux types de classes non union à disposition standard sont dits compatibles en disposition s'ils sont le même type sans tenir compte des qualificateurs cv, s'ils sont des énumérations compatibles en disposition (c'est-à-dire des énumérations ayant le même type sous-jacent), ou si leur séquence initiale commune contient tous les membres de données non statiques et tous les champs de bits (dans l'exemple ci-dessus, A et B sont compatibles en disposition).

Deux unions à disposition standard sont dites compatibles en disposition si elles ont le même nombre de membres de données non statiques et si les membres de données non statiques correspondants (dans n'importe quel ordre) ont des types compatibles en disposition.

Les types à disposition standard ont les propriétés spéciales suivantes :

  • Dans une union à disposition standard dont le membre actif est de type classe non union T1, il est permis de lire un membre de données non statique m d'un autre membre de l'union, de type classe non union T2, à condition que m fasse partie de la séquence initiale commune de T1 et de T2 (sauf que la lecture d'un membre volatile via une glvalue non volatile est un comportement indéfini).
  • Un pointeur vers un objet de type classe à disposition standard peut être reinterpret_cast en pointeur vers son premier membre de données non statique non champ de bits (s'il en possède) ou, sinon, vers l'un de ses sous-objets de classe de base (s'il en possède), et inversement. En d'autres termes, aucun rembourrage n'est autorisé avant le premier membre de données d'un type à disposition standard. Notez que les règles d'alias strict s'appliquent toujours au résultat d'une telle conversion.
  • La macro offsetof peut être utilisée pour déterminer le décalage de tout membre par rapport au début d'une classe à disposition standard.

Initialisation des membres

Les membres de données non statiques peuvent être initialisés de deux façons :

  1. Dans la liste d'initialisation des membres du constructeur.
struct S
{
    int n;
    std::string s;
    S() : n(7) {} // initialise directement n, initialise par défaut s
};
  1. Par un initialisateur de membre par défaut, qui est un initialisateur entre accolades ou introduit par un signe égal, inclus dans la déclaration du membre et utilisé si le membre est omis de la liste d'initialisation des membres d'un constructeur.
struct S
{
    int n = 7;
    std::string s{'a', 'b', 'c'};
    S() {} // l'initialiseur de membre par défaut initialise n par copie, initialise s par liste
};

Si un membre possède un initialiseur de membre par défaut et apparaît aussi dans la liste d'initialisation des membres d'un constructeur, l'initialiseur de membre par défaut est ignoré pour ce constructeur.

#include <iostream>

int x = 0;
struct S
{
    int n = ++x;
    S() {}                 // utilise l'initialiseur de membre par défaut
    S(int arg) : n(arg) {} // utilise l'initialiseur de membre
};

int main()
{
    std::cout << x << '\n'; // prints 0
    S s1;                   // l'initialiseur par défaut a été exécuté
    std::cout << x << '\n'; // prints 1
    S s2(7);                // l'initialiseur par défaut n'a pas été exécuté
    std::cout << x << '\n'; // prints 1
}

Les initialiseurs de membres par défaut ne sont pas autorisés pour les membres champs de bits.

(jusqu'à C++20)

Les membres de type tableau ne peuvent pas déduire leur taille à partir des initialiseurs de membres :

struct X
{
    int a[] = {1, 2, 3};  // error
    int b[3] = {1, 2, 3}; // OK
};

Les initialiseurs de membres par défaut ne doivent pas provoquer la définition implicite d'un constructeur par défaut défini par défaut pour la classe englobante, ni la spécification d'exception de ce constructeur :

struct node
{
    node* p = new node; // erreur : utilisation de node::node() implicite ou par défaut
};

Les membres de type référence ne peuvent pas être liés à des temporaires dans un initialiseur de membre par défaut (note; la même règle existe pour les listes d'initialisation de membres):

struct A
{
    A() = default;     // OK
    A(int v) : v(v) {} // OK
    const int& v = 42; // OK
};

A a1;    // erreur : liaison mal formée d'un temporaire à une référence
A a2(1); // OK (l'initialiseur de membre par défaut est ignoré car v apparaît dans un constructeur)
         // cependant a2.v est une référence pendante

(depuis C++11)

Si [un membre référence est initialisé à partir de son initialiseur de membre par défaut (jusqu'à C++20) | un membre possède un initialiseur de membre par défaut (depuis C++20)] et qu'une sous-expression potentiellement évaluée de celui-ci est une initialisation d'agrégat qui utiliserait cet initialiseur de membre par défaut, le programme est mal formé :

struct A;
extern A a;

struct A
{
    const A& a1{A{a, a}}; // OK
    const A& a2{A{}};     // error
};

A a{a, a};                // OK

(depuis C++17)

Utilisation

Le nom d'un membre de données non statique ou d'une fonction membre non statique ne peut apparaître que dans les trois situations suivantes :

  1. Dans le cadre d'une expression d'accès à un membre de classe, où la classe possède ce membre ou dérive d'une classe qui le possède, y compris les expressions d'accès implicites this-> qui apparaissent lorsqu'un nom de membre non statique est utilisé dans l'un des contextes où this est autorisé (dans le corps des fonctions membres, dans les listes d'initialisation des membres, dans les initialiseurs de membres par défaut dans la classe).
struct S
{
    int m;
    int n;
    int x = m;            // OK : this-> implicite autorisé dans les initialiseurs par défaut (C++11)

    S(int i) : m(i), n(m) // OK : this-> implicite autorisé dans les listes d'initialisation des membres
    {
        this->f();        // expression d'accès explicite à un membre
        f();              // this-> implicite autorisé dans le corps des fonctions membres
    }

    void f();
};
  1. Pour former un pointeur vers membre non statique.
struct S
{
    int m;
    void f();
};

int S::*p = &S::m;       // OK : utilisation de m pour créer un pointeur vers membre
void (S::*fp)() = &S::f; // OK : utilisation de f pour créer un pointeur vers membre
  1. (pour les membres de données uniquement, pas les fonctions membres) Lorsqu'il est utilisé dans des opérandes non évalués.
struct S
{
    int m;
    static const std::size_t sz = sizeof m; // OK : m dans une opérande non évaluée
};

std::size_t j = sizeof(S::m + 42); // OK : bien que m n'ait pas d'objet « this »

Remarques : ces utilisations sont autorisées grâce à la résolution du CWG issue 613 dans N2253, qui est considérée comme une modification en C++11 par certains compilateurs (par ex. clang).
