Conversions arithmétiques usuelles

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

De nombreux opérateurs binaires qui attendent des opérandes de type arithmétique ou énumération effectuent des conversions et produisent des types de résultat de manière similaire. Le but est d'obtenir un type commun, qui est aussi le type du résultat. Ce mécanisme est appelé conversions arithmétiques usuelles.

Définition

Les conversions arithmétiques usuelles sont définies comme suit :

Étape 1

Applique la conversion lvalue-to-rvalue aux deux opérandes ; les prvalues obtenues remplacent les opérandes d'origine pour la suite du processus.

Étape 2

  • Si l'un des opérandes est de type énumération à portée, aucune conversion n'est effectuée ; si l'autre opérande n'a pas le même type, l'expression est mal formée.
  • Sinon, passer à l'étape suivante.

(depuis C++11)

Étape 3

  • Si l'un des opérandes est de type énumération, et que l'autre opérande est d'un type énumération différent ou d'un type à virgule flottante, l'expression est mal formée.
  • Sinon, passer à l'étape suivante.

(depuis C++26)

Étape 4

  • Si l'un des opérandes est de type à virgule flottante, les règles suivantes sont appliquées :
    • Si les deux opérandes ont le même type, aucune conversion supplémentaire ne sera effectuée.
    • Sinon, si l'un des opérandes est d'un type qui n'est pas à virgule flottante, cet opérande est converti vers le type de l'autre opérande.
    • Sinon, si les rangs de conversion en virgule flottante des types des opérandes sont ordonnés mais (depuis C++23) non égaux, alors l'opérande du type de rang de conversion inférieur est converti vers le type de l'autre opérande.
  • Sinon, si les rangs de conversion en virgule flottante des types des opérandes sont égaux, alors l'opérande ayant le sous-rang de conversion en virgule flottante inférieur est converti vers le type de l'autre opérande.
  • Sinon, l'expression est mal formée.

(depuis C++23)

  • Sinon, les deux opérandes sont de types entiers ; passer à l'étape suivante.

Étape 5

Les deux opérandes sont convertis vers un type commun C. En notant T1 et T2 les types promus (selon les règles des promotions entières) des opérandes, les règles suivantes sont appliquées pour déterminer C :

  • Si T1 et T2 sont du même type, C est ce type.
  • Sinon, si T1 et T2 sont tous deux des types entiers signés ou tous deux des types entiers non signés, C est le type de plus grand rang de conversion entier.
  • Sinon, l'un des types entre T1 et T2 est un type entier signé S, l'autre type est un type entier non signé U. Appliquer les règles suivantes :
    • Si le rang de conversion entier de U est supérieur ou égal au rang de conversion entier de S, C est U.
    • Sinon, si S peut représenter toutes les valeurs de U, C est S.
    • Sinon, C est le type entier non signé correspondant à S.

Si l'un des opérandes est de type énumération et que l'autre opérande est d'un type énumération différent ou d'un type à virgule flottante, ce comportement est obsolète.

(depuis C++20) (jusqu'à C++26)

Rang de conversion entier

Chaque type entier a un rang de conversion entier défini comme suit :

  • Deux types entiers signés, autres que char et signed char (si char est signé), n'ont jamais le même rang, même s'ils ont la même représentation.
  • Le rang d'un type entier signé est supérieur au rang de tout type entier signé de plus petite largeur.
  • Les rangs des types entiers suivants décroissent dans cet ordre :
  • long long

(depuis C++11)

  • long

  • int

  • short

  • signed char

  • Le rang de tout type entier non signé est égal au rang du type entier signé correspondant.

  • Le rang de tout type entier standard est supérieur au rang de tout type entier étendu de même largeur.

(depuis C++11)

  • Le rang de bool est inférieur au rang de tous les types entiers standard.
  • Les rangs des types de caractères d'encodage (char [, char8_t (depuis C++20) | , char16_t, char32_t, (depuis C++11)] et wchar_t) sont égaux à ceux de leurs types sous-jacents, ce qui signifie :
    • Le rang de char est égal au rang de signed char et de unsigned char.
  • Le rang de char8_t est égal au rang de unsigned char.

(depuis C++20)

  • Le rang de char16_t est égal au rang de std::uint_least16_t.
  • Le rang de char32_t est égal au rang de std::uint_least32_t.

(depuis C++11)

  • Le rang de wchar_t est égal au rang de son type sous-jacent défini par l'implémentation.
  • Le rang de tout type entier signé étendu par rapport à un autre type entier signé étendu de même largeur est défini par l'implémentation, mais reste soumis aux autres règles de détermination du rang de conversion entier.

(depuis C++11)

  • Pour tous les types entiers T1, T2 et T3, si T1 a un rang supérieur à T2 et T2 a un rang supérieur à T3, alors T1 a un rang supérieur à T3.

Le rang de conversion entier est aussi utilisé dans la définition de la promotion entière.

Rang et sous-rang de conversion en virgule flottante

Rang de conversion en virgule flottante

Chaque type à virgule flottante a un rang de conversion en virgule flottante défini comme suit :

  • Les rangs des types à virgule flottante standard décroissent dans cet ordre :
    • long double
    • double
    • float
  • Le rang d'un type à virgule flottante T est supérieur au rang de tout type à virgule flottante dont l'ensemble des valeurs est un sous-ensemble strict de l'ensemble des valeurs de T.
  • Deux types à virgule flottante étendus ayant le même ensemble de valeurs ont des rangs égaux.
  • Un type à virgule flottante étendu ayant le même ensemble de valeurs qu'exactement un type à virgule flottante standard non qualifié cv a un rang égal à celui de ce type à virgule flottante standard.
  • Un type à virgule flottante étendu ayant le même ensemble de valeurs que plusieurs types à virgule flottante standard non qualifiés cv a un rang égal au rang de double.

(depuis C++23)

Sous-rang de conversion en virgule flottante

Les types à virgule flottante ayant des rangs de conversion en virgule flottante égaux sont ordonnés par sous-rang de conversion en virgule flottante. Le sous-rang forme un ordre total parmi les types de même rang.

Les types std::float16_t, std::float32_t, std::float64_t et std::float128_t (types à virgule flottante de largeur fixe) ont un sous-rang de conversion supérieur à celui de tout type à virgule flottante standard de même rang de conversion. Sinon, l'ordre des sous-rangs de conversion est défini par l'implémentation.

(depuis C++23)

Utilisation

Le rang et le sous-rang de conversion en virgule flottante servent aussi à

  • déterminer si une conversion entre différents types à virgule flottante peut être implicite ou est une conversion restrictive,
  • distinguer les séquences de conversion lors de la résolution de surcharge,
  • déterminer le type réel extrait par std::num_get::get() lors de l'extraction d'un type à virgule flottante étendu à l'aide de std::basic_istream::operator>>,
  • déterminer le type réel inséré par std::num_put::put() lors de l'insertion d'un type à virgule flottante étendu à l'aide de std::basic_ostream::operator<<,

(depuis C++23)

  • déterminer si le constructeur de conversion de std::complex est explicite, ou
  • déterminer le type commun à virgule flottante si des arguments de types à virgule flottante différents sont passés aux fonctions mathématiques common ou spéciales.

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 1642 C++98 les conversions arithmétiques usuelles peuvent impliquer des lvalues applique d'abord les conversions lvalue-to-rvalue
CWG 2528 C++20 la comparaison à trois voies entre unsigned char et unsigned int est mal formée car de la promotion entière intermédiaire [1] détermine le type commun à partir des types promus, sans promouvoir réellement les opérandes [2]
CWG 2892 C++98 lorsque les deux opérandes sont du même type à virgule flottante, le sens de « aucune conversion supplémentaire n'est nécessaire » n'était pas clair modifié en « aucune conversion supplémentaire ne sera effectuée »
  1. ↑ Avant la résolution, unsigned char est promu en int au début de l'étape 5, puis il est converti en unsigned int. Cependant, cette dernière conversion est de rétrécissement, ce qui rend la comparaison à trois voies mal formée.
  2. ↑ Après la résolution, le type commun reste unsigned int. La différence est que unsigned char est directement converti en unsigned int sans la promotion entière intermédiaire. La conversion n'est pas de rétrécissement et la comparaison à trois voies est donc bien formée.
