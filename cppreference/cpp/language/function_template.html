Modèle de fonction

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un modèle de fonction définit une famille de fonctions.

Syntaxe

| | | | template < parameter-list > function-declaration | (1) | | | | template < parameter-list > requires constraint function-declaration | (2) | (depuis C++20) | | | function-declaration-with-placeholders | (3) | (depuis C++20) | | | export template < parameter-list > function-declaration | (4) | (supprimé en C++11) | |

Explication

  • parameter-list — une liste non vide, séparée par des virgules, de paramètres de modèle, chacun étant soit un paramètre non type, soit un paramètre de type, soit un paramètre de modèle, ou un paquet de paramètres de l'un quelconque de ces types (depuis C++11). Comme pour tout modèle, les paramètres peuvent être contraints (depuis C++20)
  • function-declaration — une déclaration de fonction. Le nom de fonction déclaré devient un nom de modèle.
  • constraint — une expression de contrainte qui restreint les paramètres de modèle acceptés par ce modèle de fonction
  • function-declaration-with-placeholders — une déclaration de fonction dont le type d'au moins un paramètre utilise le marqueur auto ou Concept auto : la liste de paramètres de modèle comportera un paramètre inventé pour chaque marqueur (voir Modèles de fonctions abrégés ci-dessous)

export était un modificateur optionnel qui déclarait le modèle comme exporté (utilisé avec un modèle de classe, il déclarait également tous ses membres exportés). Les fichiers qui instanciaient des modèles exportés n'avaient pas besoin d'inclure leurs définitions : la déclaration suffisait. Les implémentations de export étaient rares et ne s'accordaient pas entre elles sur les détails.

(jusqu'à C++11)

Modèle de fonction abrégé

Lorsque des types marqueurs (soit auto, soit Concept auto) apparaissent dans la liste de paramètres d'une déclaration de fonction ou d'une déclaration de modèle de fonction, la déclaration déclare un modèle de fonction, et un paramètre de modèle inventé pour chaque marqueur est ajouté à la liste de paramètres de modèle :

void f1(auto); // identique à template<class T> void f1(T)
void f2(C1 auto); // identique à template<C1 T> void f2(T), si C1 est un concept
void f3(C2 auto...); // équivalent à template<C2... Ts> void f3(Ts...), si C2 est un concept
void f4(const C3 auto*, C4 auto&); // équivalent à template<C3 T, C4 U> void f4(const T*, U&);

template<class T, C U>
void g(T x, U y, C auto z); // équivalent à template<class T, C U, C W> void g(T x, U y, W z);

Les modèles de fonctions abrégés peuvent être spécialisés comme tous les modèles de fonctions.

template<>
void f4<int>(const int*, const double&); // spécialisation de f4<int, const double>

(depuis C++20)

Signature du modèle de fonction

Chaque modèle de fonction possède une signature.

La signature d'un template-head est la liste de paramètres de modèle, à l'exclusion des noms de paramètres de modèle et des arguments par défaut, et de la clause requires (le cas échéant) (depuis C++20).

La signature d'un modèle de fonction contient le nom, la liste des types de paramètres, le type de retour, la clause requires finale (le cas échéant) (depuis C++20), et la signature de la template-head. Sauf dans les cas suivants, sa signature contient également l'espace de noms englobant.

Si le modèle de fonction est un membre de classe, sa signature contient la classe dont la fonction est membre à la place de l'espace de noms englobant. Sa signature contient également [la clause requires finale (le cas échéant) (depuis C++20) | , le qualificateur de référence (le cas échéant), et (depuis C++11)] les qualificateurs cv (le cas échéant).

Si le modèle de fonction est un friend avec une contrainte impliquant des paramètres de modèle englobants, sa signature contient la classe englobante à la place de l'espace de noms englobant.

(depuis C++20)

Instanciation de modèle de fonction

Un modèle de fonction n'est pas en soi un type, ni une fonction. Aucun code n'est généré à partir d'un fichier source qui ne contient que des définitions de modèles. Pour qu'un code apparaisse, un modèle doit être instancié : les arguments de modèle doivent être déterminés afin que le compilateur puisse générer une fonction réelle (ou une classe, à partir d'un modèle de classe).

Instanciation explicite

| | | | template return-type name < argument-list > ( parameter-list ) ; | (1) | | | | template return-type name ( parameter-list ) ; | (2) | | | | extern template return-type name < argument-list > ( parameter-list ) ; | (3) | (depuis C++11) | | | extern template return-type name ( parameter-list ) ; | (4) | (depuis C++11) | |

  1. Définition d'instanciation explicite (sans déduction d'argument de modèle si chaque paramètre de modèle non par défaut est spécifié explicitement)

  2. Définition d'instanciation explicite avec déduction d'argument de modèle pour tous les paramètres

  3. Déclaration d'instanciation explicite (sans déduction d'argument de modèle si chaque paramètre de modèle non par défaut est spécifié explicitement)

  4. Déclaration d'instanciation explicite avec déduction d'argument de modèle pour tous les paramètres

Une définition d'instanciation explicite force l'instanciation de la fonction ou de la fonction membre auxquelles elle fait référence. Elle peut apparaître dans le programme n'importe où après la définition du modèle, et pour une liste d'arguments donnée, elle ne peut apparaître qu'une seule fois dans le programme, aucun diagnostic requis.

Une déclaration d'instanciation explicite (un extern template) empêche les instanciations implicites : le code qui provoquerait autrement une instanciation implicite doit utiliser la définition d'instanciation explicite fournie ailleurs dans le programme.

(depuis C++11)

Un argument de modèle final peut ne pas être spécifié dans une instanciation explicite d'une spécialisation de modèle de fonction ou d'une spécialisation de fonction membre de modèle s'il peut être déduit du paramètre de fonction :

template<typename T>
void f(T s)
{
    std::cout << s << '\n';
}

template void f<double>(double); // instancie f<double>(double)
template void f<>(char);         // instancie f<char>(char), argument de modèle déduit
template void f(int);            // instancie f<int>(int), argument de modèle déduit

L'instanciation explicite d'un modèle de fonction ou d'une fonction membre d'un modèle de classe ne peut pas utiliser inline ni constexpr. Si la déclaration de l'instanciation explicite désigne une fonction membre spéciale déclarée implicitement, le programme est mal formé.

L'instanciation explicite d'un constructeur ne peut pas utiliser une liste de paramètres de modèle (syntaxe (1)), ce qui n'est d'ailleurs jamais nécessaire car ils peuvent être déduits (syntaxe (2)).

L'instanciation explicite d'un destructeur prospectif doit nommer le destructeur sélectionné de la classe.

(depuis C++20)

Les déclarations d'instanciation explicite ne suppriment pas l'instanciation implicite des fonctions inline, des déclarations auto, des références et des spécialisations de modèles de classes. (ainsi, lorsque la fonction inline qui fait l'objet d'une déclaration d'instanciation explicite est utilisée par ODR, elle est instanciée implicitement pour l'insertion en ligne, mais sa copie hors ligne n'est pas générée dans cette unité de traduction)

La définition d'instanciation explicite d'un modèle de fonction avec des arguments par défaut n'est pas une utilisation de ces arguments, et ne tente pas de les initialiser :

char* p = 0;

template<class T>
T g(T x = &p) { return x; }

template int g<int>(int); // OK bien que &p ne soit pas un int.

Instanciation implicite

Lorsque du code fait référence à une fonction dans un contexte qui exige l'existence de la définition de la fonction, ou si l'existence de la définition affecte la sémantique du programme (depuis C++11), et que cette fonction particulière n'a pas été explicitement instanciée, une instanciation implicite a lieu. La liste des arguments de modèle n'a pas à être fournie si elle peut être déduite du contexte.

#include <iostream>

template<typename T>
void f(T s)
{
    std::cout << s << '\n';
}

int main()
{
    f<double>(1); // instancie et appelle f<double>(double)
    f<>('a');     // instancie et appelle f<char>(char)
    f(7);         // instancie et appelle f<int>(int)
    void (*pf)(std::string) = f; // instancie f<string>(string)
    pf("∇");                     // appelle f<string>(string)
}

On considère que l'existence de la définition d'une fonction affecte la sémantique du programme si la fonction est nécessaire à l'évaluation constante d'une expression, même si l'évaluation constante de l'expression n'est pas requise ou si l'évaluation de l'expression constante n'utilise pas la définition.

template<typename T>
constexpr int f() { return T::value; }

template<bool B, typename T>
void g(decltype(B ? f<T>() : 0));
template<bool B, typename T>
void g(...);

template<bool B, typename T>
void h(decltype(int{B ? f<T>() : 0}));
template<bool B, typename T>
void h(...);

void x()
{
    g<false, int>(0); // OK : B ? f<T>() : 0 n'est pas potentiellement évaluée à la compilation
    h<false, int>(0); // erreur : instancie f<int> alors que B est évalué à false
                      // et l'initialisation par liste de int à partir de int ne peut pas être restrictive
}

(depuis C++11)

Remarque : omettre entièrement <> permet à la résolution de surcharge d'examiner à la fois les surcharges de modèles et les surcharges non modèles.

Déduction d'arguments de modèle

Pour instancier un modèle de fonction, chaque argument de modèle doit être connu, mais chaque argument de modèle n'a pas à être spécifié. Lorsque c'est possible, le compilateur déduit les arguments de modèle manquants à partir des arguments de la fonction. Cela se produit lorsqu'un appel de fonction est tenté et lorsque l'adresse d'un modèle de fonction est prise.

template<typename To, typename From>
To convert(From f);

void g(double d)
{
    int i = convert<int>(d);    // appelle convert<int,double>(double)
    char c = convert<char>(d);  // appelle convert<char,double>(double)
    int(*ptr)(float) = convert; // instancie convert<int, float>(float)
}

Ce mécanisme permet d'utiliser des opérateurs modèles, puisqu'il n'existe aucune syntaxe pour spécifier les arguments de modèle d'un opérateur autrement qu'en le réécrivant sous forme d'expression d'appel de fonction.

#include <iostream>

int main()
{
    std::cout << "Hello, world" << std::endl;
    // operator<< est recherché par ADL comme std::operator<<,
    // puis déduit comme operator<<<char, std::char_traits<char>> dans les deux cas
    // std::endl est déduit comme &std::endl<char, std::char_traits<char>>
}

La déduction d'arguments de modèle a lieu après la recherche de nom du modèle de fonction (qui peut impliquer une recherche dépendant des arguments) et avant la résolution de surcharge.

Voir déduction d'arguments de modèle pour plus de détails.

Arguments de modèle explicites

Les arguments de modèle d'un modèle de fonction peuvent être obtenus à partir de

  • la déduction d'arguments de modèle
  • les arguments de modèle par défaut
  • spécifiés explicitement, ce qui peut être fait dans les contextes suivants :
    • dans une expression d'appel de fonction
    • lorsque l'adresse d'une fonction est prise
    • lorsqu'une référence à une fonction est initialisée
    • lorsqu'un pointeur vers fonction membre est formé
    • dans une spécialisation explicite
    • dans une instanciation explicite
    • dans une déclaration friend

Il n'existe aucun moyen de spécifier explicitement des arguments de modèle pour les opérateurs surchargés, les fonctions de conversion et les constructeurs, car ils sont appelés sans utiliser de nom de fonction.

Les arguments de modèle spécifiés doivent correspondre aux paramètres de modèle par nature (c'est-à-dire type pour type, non-type pour non-type, et modèle pour modèle). Il ne peut pas y avoir plus d'arguments que de paramètres(sauf si un paramètre est un paquet de paramètres, auquel cas il faut un argument pour chaque paramètre autre que le paquet) (depuis C++11).

Les arguments non-type spécifiés doivent soit correspondre aux types des paramètres de modèle non-type correspondants, soit être convertibles vers eux.

Les paramètres de fonction qui ne participent pas à la déduction d'arguments de modèle (par exemple si les arguments de modèle correspondants sont spécifiés explicitement) sont soumis aux conversions implicites vers le type du paramètre de fonction correspondant (comme dans la résolution de surcharge habituelle).

Un paquet de paramètres de modèle spécifié explicitement peut être étendu par la déduction d'arguments de modèle s'il existe des arguments supplémentaires :

template<class... Types>
void f(Types... values);

void g()
{
    f<int*, float*>(0, 0, 0); // Types = {int*, float*, int}
}

(depuis C++11)

Substitution d'arguments de modèle

Lorsque tous les arguments de modèle ont été spécifiés, déduits ou obtenus à partir d'arguments de modèle par défaut, chaque utilisation d'un paramètre de modèle dans la liste de paramètres de la fonction est remplacée par l'argument de modèle correspondant.

Un échec de substitution (c'est-à-dire l'échec à remplacer les paramètres de modèle par les arguments de modèle déduits ou fournis) d'un modèle de fonction retire le modèle de fonction de l'ensemble de surcharge. Cela permet de manipuler des ensembles de surcharge de diverses manières à l'aide de la métaprogrammation par modèles : voir SFINAE pour plus de détails.

Après substitution, tous les paramètres de fonction de type tableau ou fonction sont ajustés en pointeurs et tous les qualificateurs cv de premier niveau sont supprimés des paramètres de fonction (comme dans une déclaration de fonction ordinaire).

La suppression des qualificateurs cv de premier niveau n'affecte pas le type du paramètre tel qu'il apparaît dans la fonction :

template<class T>
void f(T t);

template<class X>
void g(const X x);

template<class Z>
void h(Z z, Z* zp);

// deux fonctions différentes ayant le même type, mais
// dans la fonction, t a des qualifications cv différentes
f<int>(1);       // le type de fonction est void(int), t est int
f<const int>(1); // le type de fonction est void(int), t est const int

// deux fonctions différentes ayant le même type et le même x
// (les pointeurs vers ces deux fonctions ne sont pas égaux,
//  et les statiques locales à la fonction auraient des adresses différentes)
g<int>(1);       // le type de fonction est void(int), x est const int
g<const int>(1); // le type de fonction est void(int), x est const int

// seuls les qualificatifs cv de premier niveau sont supprimés :
h<const int>(1, NULL); // le type de fonction est void(int, const int*)
                       // z est const int, zp est const int*

Surcharge de modèles de fonctions

Les modèles de fonctions et les fonctions non modèles peuvent être surchargés.

Une fonction non modèle est toujours distincte d'une spécialisation de modèle ayant le même type. Les spécialisations de modèles de fonctions différents sont toujours distinctes les unes des autres même si elles ont le même type. Deux modèles de fonctions ayant le même type de retour et la même liste de paramètres sont distincts et peuvent être distingués par leur liste explicite d'arguments de modèle.

Lorsqu'une expression utilisant des paramètres de modèle de type ou non-type apparaît dans la liste de paramètres de la fonction ou dans le type de retour, cette expression reste une partie de la signature du modèle de fonction pour les besoins de la surcharge :

template<int I, int J>
A<I+J> f(A<I>, A<J>); // overload #1

template<int K, int L>
A<K+L> f(A<K>, A<L>); // identique à #1

template<int I, int J>
A<I-J> f(A<I>, A<J>); // overload #2

Deux expressions impliquant des paramètres de modèle sont dites équivalentes si deux définitions de fonctions contenant ces expressions seraient identiques au regard de la ODR, c'est-à-dire si les deux expressions contiennent la même suite de jetons dont les noms sont résolus vers les mêmes entités par recherche de noms, à ceci près que les paramètres de modèle peuvent être nommés différemment. Deux expressions lambda ne sont jamais équivalentes. (depuis C++20)

template<int I, int J>
void f(A<I+J>); // surcharge de modèle #1

template<int K, int L>
void f(A<K+L>); // équivalent à #1

Lorsqu'on détermine si deux expressions dépendantes sont équivalentes, seuls les noms dépendants impliqués sont pris en compte, et non les résultats de la recherche de nom. Si plusieurs déclarations d'un même modèle diffèrent par le résultat de la recherche de nom, la première de ces déclarations est utilisée :

template<class T>
decltype(g(T())) h(); // decltype(g(T())) est un type dépendant

int g(int);

template<class T>
decltype(g(T())) h()
{                  // la redéclaration de h() utilise une recherche antérieure
    return g(T()); // bien que la recherche ici trouve bien g(int)
}

int i = h<int>(); // la substitution de l'argument de modèle échoue ; g(int)
                  // n'était pas dans la portée à la première déclaration de h()

Deux modèles de fonctions sont considérés comme équivalents si

  • elles sont déclarées dans la même portée
  • elles ont le même nom
  • elles ont des listes de paramètres de modèle équivalentes, c'est-à-dire que les listes ont la même longueur et que, pour chaque couple de paramètres correspondants, toutes les conditions suivantes sont vraies :
    • les deux paramètres sont du même genre (tous deux des types, tous deux des non-types, ou tous deux des modèles)
  • ce sont soit tous deux des packs de paramètres, soit aucun des deux

(depuis C++11)

  • s'ils sont non-types, leurs types sont équivalents,
  • s'ils sont des modèles, leurs paramètres de modèle sont équivalents,
  • si l'un est déclaré avec un nom de concept, les deux le sont, et les noms de concept sont équivalents.

(depuis C++20)

  • les expressions impliquant des paramètres de modèle dans leurs types de retour et leurs listes de paramètres sont équivalentes
  • les expressions dans leurs clauses requires qui suivent les listes de paramètres de modèle, si elles sont présentes, sont équivalentes
  • les expressions dans leurs clauses requires qui suivent les déclarateurs de fonction, si elles sont présentes, sont équivalentes

(depuis C++20)

Deux expressions potentiellement évaluées (depuis C++20) impliquant des paramètres de modèle sont dites fonctionnellement équivalentes si elles ne sont pas équivalentes, mais que, pour tout ensemble donné d'arguments de modèle, l'évaluation des deux expressions produit la même valeur.

Deux modèles de fonction sont considérés comme fonctionnellement équivalents s'ils sont équivalents, à ceci près qu'une ou plusieurs expressions impliquant des paramètres de modèle dans leurs types de retour et leurs listes de paramètres sont fonctionnellement équivalentes.

De plus, deux modèles de fonction sont fonctionnellement équivalents mais non équivalents si leurs contraintes sont spécifiées différemment, mais qu'ils acceptent et sont satisfaits par le même ensemble de listes d'arguments de modèle.

(depuis C++20)

Si un programme contient des déclarations de modèles de fonction qui sont fonctionnellement équivalentes mais non équivalentes, le programme est mal formé ; aucun diagnostic n'est requis.

// equivalent
template<int I>
void f(A<I>, A<I+10>); // overload #1
template<int I>
void f(A<I>, A<I+10>); // redéclaration de la surcharge #1

// non équivalents
template<int I>
void f(A<I>, A<I+10>); // overload #1
template<int I>
void f(A<I>, A<I+11>); // overload #2

// fonctionnellement équivalents mais non équivalents
// Ce programme est mal formé, aucun diagnostic requis
template<int I>
void f(A<I>, A<I+10>);      // overload #1
template<int I>
void f(A<I>, A<I+1+2+3+4>); // fonctionnellement équivalents

Lorsque la même spécialisation de modèle de fonction correspond à plusieurs modèles de fonction surchargés (ce qui résulte souvent d'une déduction d'arguments de modèle), un ordonnancement partiel des modèles de fonction surchargés est effectué pour sélectionner la meilleure correspondance.

Plus précisément, l'ordonnancement partiel a lieu dans les situations suivantes :

  1. résolution de surcharge pour un appel à une spécialisation de modèle de fonction :
template<class X>
void f(X a);
template<class X>
void f(X* a);

int* p;
f(p);
  1. lorsque l'adresse d'une spécialisation de modèle de fonction est prise :
template<class X>
void f(X a);
template<class X>
void f(X* a);

void (*p)(int*) = &f;
  1. lorsqu'un operator delete de placement qui est une spécialisation de modèle de fonction est sélectionné pour correspondre à un operator new de placement :
Cette section est incomplète Raison : mini-exemple
  1. lorsqu'une déclaration de fonction amie, une instanciation explicite ou une spécialisation explicite fait référence à une spécialisation de modèle de fonction :
template<class X>
void f(X a);  // premier modèle f
template<class X>
void f(X* a); // second modèle f
template<>
void f<>(int *a) {} // spécialisation explicite

// la déduction d'argument de modèle donne deux candidats :
// f<int*>(int*) et f<int>(int*)
// le classement partiel sélectionne f<int>(int*) comme plus spécialisé

Informellement, « A est plus spécialisé que B » signifie « A accepte moins de types que B ».

Formellement, pour déterminer lequel de deux modèles de fonction est plus spécialisé, le processus d'ordonnancement partiel transforme d'abord l'un des deux modèles comme suit :

  • Pour chaque paramètre de type, de non-type et de modèle, y compris les packs de paramètres, (depuis C++11) un type, une valeur ou un modèle fictif unique est généré et substitué dans le type de fonction du modèle
  • Si un seul des deux modèles de fonction comparés est une fonction membre, et que ce modèle de fonction est une fonction membre non statique d'une classe A, un nouveau premier paramètre est inséré dans sa liste de paramètres. En notant cv les qualificateurs cv du modèle de fonctionet ref le qualificateur de référence du modèle de fonction (depuis C++11), le type du nouveau paramètre est cv A&sauf si ref vaut &&, ou si ref est absent et que le premier paramètre de l'autre modèle a un type de référence rvalue ; dans ce cas, le type est cv A&& (depuis C++11). Cela facilite l'ordonnancement des opérateurs, qui sont recherchés à la fois comme fonctions membres et non membres :
struct A {};

template<class T>
struct B
{
    template<class R>
    int operator*(R&); // #1
};

template<class T, class R>
int operator*(T&, R&); // #2

int main()
{
    A a;
    B<A> b;
    b * a; // la déduction d'argument de modèle pour int B<A>::operator*(R&) donne R=A
           //                             pour int operator*(T&, R&), T=B<A>, R=A

    // Pour le classement partiel, le modèle membre B<A>::operator*
    // est transformé en template<class R> int operator*(B<A>&, R&);

    // classement partiel entre
    //     int operator*(   T&, R&)  T=B<A>, R=A
    // et int operator*(B<A>&, R&)  R=A
    // sélectionne int operator*(B<A>&, A&) comme plus spécialisé
}

Après qu'un des deux modèles a été transformé comme décrit ci-dessus, la déduction d'arguments de modèle est exécutée en utilisant le modèle transformé comme modèle d'argument et le type de modèle original de l'autre modèle comme modèle de paramètre. Le processus est ensuite répété avec le second modèle (après transformations) comme argument et le premier modèle sous sa forme originale comme paramètre.

Les types utilisés pour déterminer l'ordre dépendent du contexte :

  • dans le contexte d'un appel de fonction, les types sont ceux des types de paramètres de fonction pour lesquels l'appel fournit des arguments (les arguments par défaut, les packs de paramètres, (depuis C++11) et les paramètres ellipsis ne sont pas pris en compte -- voir les exemples ci-dessous)
  • dans le contexte d'un appel à une fonction de conversion définie par l'utilisateur, les types de retour des modèles de fonction de conversion sont utilisés
  • dans les autres contextes, le type du modèle de fonction est utilisé

Chaque type de la liste ci-dessus, provenant du modèle de paramètre, est déduit. Avant le début de la déduction, chaque paramètre P du modèle de paramètre et l'argument correspondant A du modèle d'argument sont ajustés comme suit :

  • Si P et A sont tous deux des types référence avant cela, déterminer lequel est le plus qualifié cv (dans tous les autres cas, les qualificatifs cv sont ignorés pour l'ordonnancement partiel)
  • Si P est un type référence, il est remplacé par le type référencé
  • Si A est un type référence, il est remplacé par le type référencé
  • Si P est qualifié cv, P est remplacé par sa version non qualifiée cv
  • Si A est qualifié cv, A est remplacé par sa version non qualifiée cv

Après ces ajustements, la déduction de P à partir de A est effectuée selon la déduction d'arguments de modèle à partir d'un type.

Si P est un pack de paramètres de fonction, le type A de chaque type de paramètre restant du modèle d'argument est comparé au type P du declarator-id du pack de paramètres de fonction. Chaque comparaison déduit les arguments de modèle pour les positions suivantes dans les packs de paramètres de modèle développés par le pack de paramètres de fonction.

Si A a été transformé à partir d'un pack de paramètres de fonction, il est comparé à chaque type de paramètre restant du modèle de paramètre.

(depuis C++11)

Si l'argument A du modèle transformé 1 peut servir à déduire le paramètre correspondant P du modèle 2, mais pas l'inverse, alors ce A est plus spécialisé que P en ce qui concerne le ou les types déduits par cette paire P/A.

Si la déduction réussit dans les deux sens, et que les P et A originaux étaient des types référence, alors des tests supplémentaires sont effectués :

  • Si A était une référence lvalue et P une référence rvalue, A est considéré comme plus spécialisé que P
  • Si A était plus qualifié cv que P, A est considéré comme plus spécialisé que P

Dans tous les autres cas, aucun des deux modèles n'est plus spécialisé que l'autre en ce qui concerne le ou les types déduits par cette paire P/A.

Après avoir considéré chaque P et A dans les deux sens, si, pour chaque type qui a été considéré,

  • template-1 est au moins aussi spécialisé que template-2 pour tous les types
  • template-1 est plus spécialisé que template-2 pour certains types
  • template-2 n'est pas plus spécialisé que template-1 pour aucun type OU n'est pas au moins aussi spécialisé pour certains types

alors template-1 est plus spécialisé que template-2. Si les conditions ci-dessus sont vraies après inversion de l'ordre des modèles, alors template-2 est plus spécialisé que template-1. Sinon, aucun des deux modèles n'est plus spécialisé que l'autre.

En cas d'égalité, si l'un des modèles de fonction a un pack de paramètres final et l'autre non, celui dont le paramètre est omis est considéré comme plus spécialisé que celui ayant un pack de paramètres vide.

(depuis C++11)

Si, après avoir considéré toutes les paires de modèles surchargés, il en existe un qui est sans ambiguïté plus spécialisé que tous les autres, la spécialisation de ce modèle est sélectionnée, sinon la compilation échoue.

Dans les exemples suivants, les arguments fictifs seront appelés U1, U2 :

template<class T>
void f(T);        // template #1
template<class T>
void f(T*);       // template #2
template<class T>
void f(const T*); // template #3

void m()
{
    const int* p;
    f(p); // la résolution de surcharge retient : #1 : void f(T ) [T = const int *]
          //                            #2 : void f(T*) [T = const int]
          //                            #3 : void f(const T *) [T = int]

    // classement partiel :

    // #1 issu de la forme transformée #2 : void(T) à partir de void(U1*) : P=T A=U1* : déduction réussie : T=U1*
    // #2 issu de la forme transformée #1 : void(T*) à partir de void(U1) : P=T* A=U1 : déduction échouée
    // #2 est plus spécialisé que #1 par rapport à T

    // #1 issu de la forme transformée #3 : void(T) à partir de void(const U1*) : P=T, A=const U1* : réussie
    // #3 issu de la forme transformée #1 : void(const T*) à partir de void(U1) : P=const T*, A=U1 : échec
    // #3 est plus spécialisé que #1 par rapport à T

    // #2 issu de la forme transformée #3 : void(T*) à partir de void(const U1*) : P=T* A=const U1* : réussie
    // #3 issu de la forme transformée #2 : void(const T*) à partir de void(U1*) : P=const T* A=U1* : échec
    // #3 est plus spécialisé que #2 par rapport à T

    // résultat : #3 est sélectionné
    // en d'autres termes, f(const T*) est plus spécialisé que f(T) ou f(T*)
}

template<class T>
void f(T, T*);   // #1
template<class T>
void f(T, int*); // #2

void m(int* p)
{
    f(0, p); // déduction pour #1 : void f(T, T*) [T = int]
             // déduction pour #2 : void f(T, int*) [T = int]

    // classement partiel :

    // #1 à partir de #2 : void(T,T*) à partir de void(U1,int*) : P1=T, A1=U1 : T=U1
    //                                            P2=T*, A2=int* : T=int : échec

    // #2 à partir de #1 : void(T,int*) à partir de void(U1,U2*) : P1=T A1=U1 : T=U1
    //                                             P2=int* A2=U2* : échec

    // aucun des deux n'est plus spécialisé par rapport à T, l'appel est ambigu
}

template<class T>
void g(T);  // template #1
template<class T>
void g(T&); // template #2

void m()
{
    float x;
    g(x); // déduction à partir de #1 : void g(T ) [T = float]
          // déduction à partir de #2 : void g(T&) [T = float]

    // classement partiel :

    // #1 à partir de #2 : void(T) à partir de void(U1&) : P=T, A=U1 (après ajustement), réussie

    // #2 à partir de #1 : void(T&) à partir de void(U1) : P=T (après ajustement), A=U1 : réussie

    // aucun des deux n'est plus spécialisé par rapport à T, l'appel est ambigu
}

template<class T>
struct A { A(); };

template<class T>
void h(const T&); // #1
template<class T>
void h(A<T>&);    // #2

void m()
{
    A<int> z;
    h(z); // déduction à partir de #1 : void h(const T &) [T = A<int>]
          // déduction à partir de #2 : void h(A<T> &) [T = int]

    // classement partiel :

    // #1 à partir de #2 : void(const T&) à partir de void(A<U1>&) : P=T A=A<U1> : réussie, T=A<U1>

    // #2 à partir de #1 : void(A<T>&) à partir de void(const U1&) : P=A<T> A=const U1 : échec

    // #2 est plus spécialisé que #1 par rapport à T

    const A<int> z2;
    h(z2); // déduction à partir de #1 : void h(const T&) [T = A<int>]
           // déduction à partir de #2 : void h(A<T>&) [T = int], mais la substitution échoue

    // une seule surcharge au choix, le classement partiel n'est pas tenté, #1 est appelé
}

Comme un contexte d'appel ne considère que les paramètres pour lesquels il existe des arguments d'appel explicites, ces packs de paramètres de fonction, (depuis C++11), paramètres ellipsis et paramètres ayant des arguments par défaut, pour lesquels il n'existe aucun argument d'appel explicite, sont ignorés :

template<class T>
void f(T);         // #1
template<class T>
void f(T*, int = 1); // #2

void m(int* ip)
{
    int* ip;
    f(ip); // appelle #2 (T* est plus spécialisé que T)
}

template<class T>
void g(T);       // #1
template<class T>
void g(T*, ...); // #2

void m(int* ip)
{
    g(ip); // appelle #2 (T* est plus spécialisé que T)
}

template<class T, class U>
struct A {};

template<class T, class U>
void f(U, A<U, T>* p = 0); // #1
template<class U>
void f(U, A<U, U>* p = 0); // #2

void h()
{
    f<int>(42, (A<int, int>*)0); // calls #2
    f<int>(42);                  // erreur : ambigu
}

template<class T>
void g(T, T = T()); // #1
template<class T, class... U>
void g(T, U...);    // #2

void h()
{
    g(42); // erreur : ambigu
}

template<class T, class... U>
void f(T, U...); // #1
template<class T>
void f(T);       // #2

void h(int i)
{
    f(&i); // appelle #2 en raison de l'arbitrage entre pack de paramètres et absence de paramètre
           // (note : était ambigu entre DR692 et DR1395)
}

template<class T, class... U>
void g(T*, U...); // #1
template<class T>
void g(T);        // #2

void h(int i)
{
    g(&i); // OK : appelle #1 (T* est plus spécialisé que T)
}

template<class... T>
int f(T*...);    // #1
template<class T>
int f(const T&); // #2

f((int*)0); // OK : sélectionne #2 ; un modèle non variadique est plus spécialisé que
            // modèle variadique (était ambigu avant DR1395 car la déduction
            // échouait dans les deux sens)

template<class... Args>
void f(Args... args);        // #1
template<class T1, class... Args>
void f(T1 a1, Args... args); // #2
template<class T1, class T2>
void f(T1 a1, T2 a2);        // #3

f();        // calls #1
f(1, 2, 3); // calls #2
f(1, 2);    // appelle #3 ; le modèle non variadique #3 est plus
            // spécialisé que les modèles variadiques #1 et #2

Pendant la déduction d'arguments de modèle dans le processus d'ordonnancement partiel, les paramètres de modèle n'ont pas besoin d'être associés à des arguments si l'argument n'est utilisé dans aucun des types considérés pour l'ordonnancement partiel

template<class T>
T f(int); // #1
template<class T, class U>
T f(U);   // #2

void g()
{
    f<int>(1); // la spécialisation de #1 est explicite : T f(int) [T = int]
               // la spécialisation de #2 est déduite : T f(U) [T = int, U = int]

    // classement partiel (en ne considérant que le type de l'argument) :

    // #1 à partir de #2 : T(int) à partir de U1(U2) : échec
    // #2 à partir de #1 : T(U) à partir de U1(int) : réussie : U=int, T non utilisé

    // calls #1
}

L'ordonnancement partiel des modèles de fonction contenant des packs de paramètres de modèle est indépendant du nombre d'arguments déduits pour ces packs de paramètres de modèle.

template<class...>
struct Tuple {};

template<class... Types>
void g(Tuple<Types...>);      // #1
template<class T1, class... Types>
void g(Tuple<T1, Types...>);  // #2
template<class T1, class... Types>
void g(Tuple<T1, Types&...>); // #3

g(Tuple<>());            // calls #1
g(Tuple<int, float>());  // calls #2
g(Tuple<int, float&>()); // calls #3
g(Tuple<int>());         // calls #3

(depuis C++11)
Cette section est incomplète Raison : 14.8.3[temp.over]

Pour compiler un appel à un modèle de fonction, le compilateur doit choisir entre les surcharges non modèles, les surcharges modèles et les spécialisations des surcharges modèles.

template<class T>
void f(T);      // #1 : surcharge de modèle
template<class T>
void f(T*);     // #2 : surcharge de modèle

void f(double); // #3 : surcharge non template
template<>
void f(int);    // #4 : spécialisation de #1

f('a');        // calls #1
f(new int(1)); // calls #2
f(1.0);        // calls #3
f(1);          // calls #4

Surcharges de fonctions contre spécialisations de fonctions

Notez que seules les surcharges non modèles et les surcharges de modèles primaires participent à la résolution de surcharge. Les spécialisations ne sont pas des surcharges et ne sont pas prises en compte. Ce n'est qu'après que la résolution de surcharge a sélectionné le modèle de fonction primaire de meilleure correspondance que ses spécialisations sont examinées pour voir si l'une d'elles correspond mieux.

template<class T>
void f(T);    // #1 : surcharge pour tous les types
template<>
void f(int*); // #2 : spécialisation de #1 pour les pointeurs vers int
template<class T>
void f(T*);   // #3 : surcharge pour tous les types de pointeurs

f(new int(1)); // appelle #3, bien que la spécialisation de #1 soit une correspondance parfaite

Il est important de se souvenir de cette règle lors de l'ordonnancement des en-têtes d'une unité de traduction. Pour plus d'exemples de l'interaction entre surcharges de fonctions et spécialisations de fonctions, développez ci-dessous :

Exemples

Considérons d'abord quelques scénarios où la recherche dépendant des arguments n'est pas employée. Pour cela, nous utilisons l'appel (f)(t). Comme décrit dans ADL, placer le nom de la fonction entre parenthèses supprime la recherche dépendant des arguments.

  • Plusieurs surcharges de f() déclarées avant le point de référence (POR) dans g().
#include <iostream>

struct A {};

template<class T>
void f(T)  { std::cout << "#1\n"; } // surcharge #1 avant f() POR
template<class T>
void f(T*) { std::cout << "#2\n"; } // surcharge #2 avant f() POR

template<class T>
void g(T* t)
{
    (f)(t); // f() POR
}

int main()
{
    A* p = nullptr;
    g(p); // POR de g() et f()
}

// #1 et #2 sont tous deux ajoutés à la liste des candidats ;
// #2 est sélectionné car c'est une meilleure correspondance.

Output:

#2
  • Une surcharge de modèle de meilleure correspondance est déclarée après le POR.

    (f)(t); // f() POR

    A* p = nullptr;
