Instruction return

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Termine la fonction courante et renvoie la valeur spécifiée (le cas échéant) à l'appelant.

Syntaxe

| | | | attr ﻿*(facultatif)* return expression ﻿*(facultatif)* ; | (1) | | | | attr ﻿*(facultatif)* return braced-init-list ; | (2) | (depuis C++11) | | | attr ﻿*(facultatif)* co_return expression ﻿*(facultatif)* ; | (3) | (depuis C++20) | | | attr ﻿*(facultatif)* co_return braced-init-list ; | (4) | (depuis C++20) | |

  • attr — (depuis C++11) suite de un nombre quelconque d'attributs
  • expression — expression, convertible en le type de retour de la fonction
  • braced-init-list — liste d'initialisation entre accolades

Explication

  1. Évalue l'expression, termine la fonction courante et renvoie le résultat de l'expression à l'appelant, après conversion implicite vers le type de retour de la fonction. L'expression est facultatif dans les fonctions dont le type de retour est (éventuellement qualifié cv) void, et interdit dans les constructeurs et les destructeurs.

  2. Utilise l'initialisation par liste de copie pour construire la valeur de retour de la fonction.

3,4) Dans une coroutine, le mot-clé co_return doit être utilisé à la place de return pour le point de suspension final (voir coroutines pour plus de détails).

Il existe un point de séquence entre l'initialisation par copie du résultat de l'appel de fonction et la destruction de tous les temporaires à la fin de expression.

(jusqu'à C++11)

L'initialisation par copie du résultat de l'appel de fonction est séquencée avant la destruction de tous les temporaires à la fin de expression, laquelle est à son tour séquencée avant la destruction des variables locales du bloc englobant l'instruction return.

(depuis C++11)

Si le type de retour de la fonction est un type référence et qu'une instruction return (1,2) lie la référence retournée au résultat d'une expression temporaire, le programme est mal formé.

(depuis C++26)

Si le flot de contrôle atteint la fin

  • d'une fonction dont le type de retour est (éventuellement qualifié cv) void,
  • d'un constructeur,
  • d'un destructeur, ou
  • d'un bloc de fonction try pour une fonction dont le type de retour est (éventuellement qualifié cv) void

sans rencontrer d'instruction return, return; est exécuté.

Si le contrôle atteint la fin de la main fonction, return 0; est exécuté.

Sortir par la fin d'une fonction à valeur de retour, à l'exception de la fonction mainet de certaines coroutines (depuis C++20), sans instruction return, est un comportement indéfini.

Dans une fonction renvoyant void (éventuellement qualifié cv), l'instruction return avec expression peut être utilisée, si le type de l'expression est void (éventuellement qualifié cv).

Si le type de retour d'une fonction est spécifié comme un type substitut, il sera déduit de la valeur de retour.

(depuis C++14)

Notes

Renvoyer par valeur peut impliquer la construction et la copie/le déplacement d'un objet temporaire, sauf si une élision de copie est utilisée. Plus précisément, les conditions de copie/déplacement sont les suivantes :

Déplacement automatique depuis les variables locales et les paramètres

La expression est éligible au déplacement s'il s'agit d'une expression d'identifiant (éventuellement entre parenthèses) désignant une variable à durée de stockage automatique dont le type est

  • un type objet non volatile
  • ou une référence rvalue non volatile vers un type objet

(depuis C++20)

et que cette variable est déclarée

  • dans le corps ou
  • comme paramètre de la fonction ou de l'expression lambda englobante la plus interne.

Si la expression est éligible au déplacement, la résolution de surcharge pour sélectionner le constructeur utilisé pour initialiser la valeur de retour ou, pour co_return, pour sélectionner la surcharge de promise.return_value() (depuis C++20) est effectuée deux fois :

  • d'abord comme si expression était une expression rvalue (elle peut donc sélectionner le constructeur de déplacement), et
  • si la première résolution de surcharge échoue ou
  • qu'elle réussit mais ne sélectionne pas le constructeur de déplacement (formellement, le premier paramètre du constructeur sélectionné n'était pas une référence rvalue vers le type (éventuellement qualifié cv) de expression)

(jusqu'à C++20)

  • alors la résolution de surcharge est effectuée normalement, avec expression considéré comme une lvalue (elle peut donc sélectionner le constructeur de copie).

(jusqu'à C++23)

Si la expression est éligible au déplacement, elle est traitée comme une xvalue (la résolution de surcharge peut donc sélectionner le constructeur de déplacement).

(depuis C++23)

(depuis C++11)

Élision de copie garantie

Si expression est une prvalue, l'objet résultat est initialisé directement par cette expression. Cela n'implique ni constructeur de copie ni constructeur de déplacement lorsque les types correspondent (voir élision de copie).

(depuis C++17)

Mots-clés

return, co_return

Exemple

#include <iostream>
#include <string>
#include <utility>

void fa(int i)
{
    if (i == 2)
        return;
    std::cout << "fa("<< i << ")\n";
} // return; implicite

int fb(int i)
{
    if (i > 4)
        return 4;
    std::cout << "fb(" << i << ")\n";
    return 2;
}

std::pair<std::string, int> fc(const char* p, int x)
{
    return {p, x};
}

void fd()
{
    return fa(10); // fa(10) est une expression de type void
}

int main()
{
    fa(1); // affiche son argument, puis retourne
    fa(2); // ne fait rien lorsque i == 2, retourne simplement

    int i = fb(5); // returns 4
    i = fb(i);     // affiche son argument, retourne 2
    std::cout << "i = " << i << '\n'
              << "fc(~).second = " << fc("Hello", 7).second << '\n';

    fd();
}

struct MoveOnly
{
    MoveOnly() = default;
    MoveOnly(MoveOnly&&) = default;
};

MoveOnly move_11(MoveOnly arg)
{
    return arg; // OK. déplacement implicite
}

MoveOnly move_11(MoveOnly&& arg)
{
    return arg; // OK depuis C++20. déplacement implicite
}

MoveOnly&& move_23(MoveOnly&& arg)
{
    return arg; // OK depuis C++23. déplacement implicite
}

Output:

fa(1)
fb(4)
i = 2
fc(~).second = 7
fa(10)
