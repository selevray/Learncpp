Identifiants

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un identifiant est une séquence de longueur arbitraire de chiffres, de tirets bas, de lettres latines minuscules et majuscules, et de la plupart des caractères Unicode.

Le premier caractère d'un identifiant valide doit être l'un des suivants :

  • lettres latines majuscules A-Z
  • lettres latines minuscules a-z
  • underscore
  • tout caractère Unicode ayant la propriété Unicode XID_Start

Tout autre caractère d'un identifiant valide doit être l'un des suivants :

  • digits 0-9
  • lettres latines majuscules A-Z
  • lettres latines minuscules a-z
  • underscore
  • tout caractère Unicode ayant la propriété Unicode XID_Continue

Les listes de caractères ayant les propriétés XID_Start et XID_Continue se trouvent dans DerivedCoreProperties.txt.

Les identifiants sont sensibles à la casse (les lettres minuscules et majuscules sont distinctes), et chaque caractère est significatif. Chaque identifiant doit être conforme à la forme de normalisation C.

Remarque : la prise en charge des identifiants Unicode est limitée dans la plupart des implémentations, par exemple gcc (jusqu'à 10).

Dans les déclarations

Un identifiant peut être utilisé pour nommer des objets, références, fonctions, énumérateurs, types, membres de classes, espaces de noms, modèles, spécialisations de modèles,packs de paramètres (depuis C++11), étiquettes goto et d'autres entités, avec les exceptions suivantes :

  • Les identifiants qui sont des mots-clés ne peuvent pas être utilisés à d'autres fins.
  • Le seul endroit où ils peuvent être utilisés en tant que non-mots-clés est dans un attribute-token (par exemple [[private]] est un attribut valide).

(depuis C++11)

  • Les identifiants qui sont des représentations alternatives pour certains opérateurs et signes de ponctuation ne peuvent pas être utilisés à d'autres fins.
  • Les identifiants à signification particulière (final, import, module (depuis C++20) et override) sont utilisés explicitement dans un certain contexte plutôt que d'être des identifiants ordinaires.
  • Sauf indication contraire, toute ambiguïté quant au fait qu'un identifiant donné ait une signification particulière est résolue en interprétant le jeton comme un identifiant ordinaire.

(depuis C++11)

  • Les identifiants qui apparaissent comme un jeton ou un jeton de prétraitement (c'est-à-dire pas dans user-defined-string-literal comme operator ""id) (depuis C++11) sous l'une des formes suivantes sont réservés :
    • dans l'espace de noms global, les identifiants qui commencent par un tiret bas
    • les identifiants qui contiennent un double tiret bas ou qui commencent par un tiret bas suivi d'une lettre majuscule, à l'exception des identifiants suivants :
      • macros prédéfinies(y compris les macros de test de fonctionnalités du langage) (depuis C++20)
  • std::_Exit
  • __func__

(depuis C++11)

  • les macros suivantes définies dans la bibliothèque standard :
    • les macros de la bibliothèque d'E/S de style C _IOFBF, _IOLBF et _IONBF
  • les macros de compatibilité C __alignas_is_defined et __alignof_is_defined (définies dans <stdalign.h>)
  • la macro de compatibilité C __bool_true_false_are_defined (définie dans <stdbool.h>)

(depuis C++11)

  • macros de test de fonctionnalités de la bibliothèque

(depuis C++20)

« Réservé » signifie ici que les en-têtes de la bibliothèque standard #define ou déclarent de tels identifiants pour leurs besoins internes, que le compilateur peut prédéfinir des identifiants non standard de ce type, et que l'algorithme de décoration des noms peut supposer que certains de ces identifiants ne sont pas utilisés. Si le programmeur utilise de tels identifiants, le programme est mal formé, aucun diagnostic requis.

De plus, c'est un comportement indéfini de #define ou #undef certains noms dans une unité de traduction, voir noms de macros réservés pour plus de détails.

Identifiants zombies

Depuis C++14, certains identifiants ont été supprimés de la bibliothèque standard C++. Ils sont listés dans la liste des noms zombies.

Cependant, ces identifiants restent réservés pour une standardisation antérieure dans un certain contexte. Les noms de fonctions membres supprimés ne peuvent pas être utilisés comme noms de macros de type fonction, et d'autres noms de membres supprimés ne peuvent pas être utilisés comme noms de macros de type objet dans du code portable.

Dans les expressions

Un identifiant qui désigne une variable, une fonction, une spécialisation d'un concept, (depuis C++20) ou un énumérateur peut être utilisé comme une expression. Le résultat d'une expression constituée uniquement de l'identifiant est l'entité désignée par cet identifiant. La catégorie de valeur de l'expression est lvalue si l'identifiant désigne une fonction, une variable, un objet paramètre de modèle (depuis C++20), ou un membre de donnée, et [rvalue (jusqu'à C++11) | prvalue (depuis C++11)] sinon (par exemple un énumérateur est [une rvalue (jusqu'à C++11) | une prvalue (depuis C++11)] expression, une spécialisation de concept est une prvalue bool (depuis C++20)).

Type

Le type d'une expression d'identifiant est le même que le type de l'entité qu'il désigne.

Les exceptions suivantes existent :

  • Si l'entité désignée par l'identifiant (non qualifié) est une entité locale, et qu'elle donnerait lieu à une expression lambda intermédiaire la capturant par copie si elle était nommée en dehors d'un opérande non évalué dans la région déclarative où l'identifiant apparaît, alors le type de l'expression est le type d'une expression d'accès à un membre de classe désignant le membre de donnée non statique qui serait déclaré pour une telle capture dans l'objet fermeture de la plus interne de ces expressions lambda intermédiaires.
void f()
{
    float x, &r = x;

    [=]
    {
        decltype(x) y1;        // y1 a le type float
        decltype((x)) y2 = y1; // y2 a le type float const& car cette lambda
                               // n'est pas mutable et x est une lvalue
        decltype(r) r1 = y1;   // r1 a le type float&
        decltype((r)) r2 = y2; // r2 a le type float const&
    };
}
  • Si l'entité désignée est un objet paramètre de modèle pour un paramètre de modèle de type T, le type de l'expression est const T.

Identifiants non qualifiés

Outre les identifiants convenablement déclarés, les éléments suivants peuvent être utilisés dans les expressions au même titre :

  • un nom d'opérateur surchargé en notation fonctionnelle, tel que operator+ ou operator new ;
  • un nom de fonction de conversion définie par l'utilisateur, tel que operator bool ;
  • un nom d'opérateur littéral défini par l'utilisateur, tel que operator "" _km ;

(depuis C++11)

  • un nom de modèle suivi de sa liste d'arguments, tel que MyTemplate<int> ;
  • le caractère ~ suivi d'un nom de classe, tel que ~MyClass ;
  • le caractère ~ suivi d'un spécificateur decltype, comme ~decltype(str).

(depuis C++11)

  • le caractère ~ suivi d'un spécificateur d'indexation de paquet, comme ~pack...[0].

(depuis C++26)

Avec les identifiants, ils sont appelés expressions d'identifiant non qualifié.

Identifiants qualifiés

Une expression d'identifiant qualifié est un identifiant non qualifié précédé d'un opérateur de résolution de portée :: et, optionnellement, d'une séquence de l'un quelconque des éléments suivants, séparés par des opérateurs de résolution de portée :

  • un nom d'espace de noms ;
  • un nom de classe ;
  • un nom d'énumération ;
  • un decltype spécificateur désignant un type classe ou énumération.

(depuis C++11)

  • un spécificateur d'indexation de paquet désignant un type classe ou énumération.

(depuis C++26)

Par exemple, l'expression std::string::npos est une expression qui désigne le membre statique npos de la classe string dans l'espace de noms std. L'expression ::tolower désigne la fonction tolower dans l'espace de noms global. L'expression ::std::cout désigne la variable globale cout dans l'espace de noms std, qui est un espace de noms de premier niveau. L'expression boost::signals2::connection désigne le type connection déclaré dans l'espace de noms signals2, lui-même déclaré dans l'espace de noms boost.

Le mot-clé template peut apparaître dans les identifiants qualifiés si nécessaire pour lever l'ambiguïté des noms de modèles dépendants.

Voir recherche qualifiée pour les détails de la recherche de noms pour les identifiants qualifiés.

Transformation d'accès implicite aux membres

Si une expression d'identifiant E désigne un membre non statique et non type d'une classe C et que toutes les conditions suivantes sont satisfaites, E est transformée en l'expression d'accès au membre de classe this->E :

  • E n'est pas l'opérande de droite d'un opérateur d'accès au membre.
  • Si E est une expression d'identifiant qualifié, E n'est pas l'opérande non parenthésé d'un opérateur d'adresse.
  • L'une quelconque des conditions suivantes est satisfaite :
    • E est potentiellement évaluée.
    • C est la classe englobante la plus interne à E.
    • C est une classe de base de la classe englobante la plus interne à E.

Cette transformation ne s'applique pas dans le contexte de définition d'un modèle (voir noms dépendants).

struct X
{
    int x;
};

struct B
{
    int b;
};

struct D : B
{
    X d;

    void func()
    {
        d;   // OK, sera transformé en this->d
        b;   // OK, sera transformé en this->b
        x;   // Erreur : this->x est mal formé

        d.x; // OK, sera transformé en this->d.x
             // au lieu de d.this->x ou this->d.this->x
    }
};

Noms

Un nom est l'utilisation de l'un des éléments suivants pour désigner une entité :

  • un identifiant
  • un nom d'opérateur surchargé en notation fonctionnelle (operator+, operator new)
  • un nom de fonction de conversion définie par l'utilisateur (operator bool)
  • un nom d'opérateur de littéral défini par l'utilisateur (operator ""_km)

(depuis C++11)

  • un nom de modèle suivi de sa liste d'arguments (MyTemplate<int>)

Chaque nom est introduit dans le programme par une déclaration. Un nom utilisé dans plusieurs unités de traduction peut désigner la même entité ou des entités différentes, selon la liaison.

Lorsque le compilateur rencontre un nom inconnu dans un programme, il l'associe à la déclaration qui a introduit le nom au moyen de la recherche de noms, à l'exception des noms dépendants dans les déclarations et définitions de modèles (pour ces noms, le compilateur détermine s'ils désignent un type, un modèle ou une autre entité, ce qui peut nécessiter une levée d'ambiguïté explicite).
