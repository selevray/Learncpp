Spécificateurs de type substitut (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un spécificateur de type substitut désigne un type substitut qui sera remplacé plus tard, généralement par déduction à partir d'un initialiseur.

Syntaxe

| | | | type-constraint ﻿*(facultatif)* auto | (1) | | | | type-constraint ﻿*(facultatif)* decltype(auto) | (2) | (depuis C++14) | |

  • type-constraint — (depuis C++20) un nom de concept, éventuellement qualifié, éventuellement suivi d'une liste d'arguments de modèle entourée de <>

  1. Le type est déduit selon les règles de la déduction d'argument de modèle.

  2. Le type est decltype(expr), où expr est l'initialiseur ou ceux utilisés dans les instructions return.

Le substitut auto peut être accompagné de modificateurs, tels que const ou &, qui participeront à la déduction de type. Le substitut decltype(auto) doit être le seul constituant du type déclaré. (depuis C++14)

Si type-constraint est présent, soit T le type déduit pour le substitut, le type-constraint introduit une expression de contrainte comme suit :

  • Si type-constraint est Concept<A1, ..., An>, alors l'expression de contrainte est Concept<T, A1, ..., An> ;
  • sinon (type-constraint est Concept sans liste d'arguments), l'expression de contrainte est Concept<T>.

La déduction échoue si l'expression de contrainte est invalide ou renvoie false.

(depuis C++20)

Explication

Un spécificateur de type substitut peut apparaître dans les contextes suivants :

Déclarations de paramètres

Dans les déclarations de paramètres suivantes, le type du paramètre déclaré peut avoir la syntaxe (1) :

  • Si un paramètre d'une expression lambda a un type substitut, l'expression lambda est une lambda générique.

(depuis C++14)

  • Si un paramètre de modèle non-type a un type substitut, son type est déduit de l'argument de modèle correspondant.

(depuis C++17)

  • Si un paramètre d'une déclaration de fonction a un type substitut, un modèle de fonction abrégé est déclaré.

(depuis C++20)

Déclarations de fonctions

Un type substitut peut apparaître dans les spécificateurs de déclaration d'un déclarateur de fonction qui inclut un type de retour final.

Un type substitut peut apparaître dans les spécificateurs de déclaration ou les spécificateurs de type du type de retour déclaré d'un déclarateur de fonction. La déduction du type de retour sera appliquée dans ce cas.

(depuis C++14)

auto f() -> int; // OK : f renvoie int
auto g() { return 0.0; } // OK depuis C++14 : g renvoie double
auto h(); // OK depuis C++14 : le type de retour de h sera déduit lors de sa définition

Déclarations de variables

Le type d'une variable déclarée avec un type substitut est déduit de son initialiseur. Cet usage est autorisé dans une déclaration d'initialisation d'une variable.

Le type substitut ne peut apparaître que comme l'un des spécificateurs de déclaration de la séquence de spécificateurs de déclaration, ou comme l'un des spécificateurs de type d'un type de retour final qui spécifie le type remplaçant ce spécificateur de déclaration. Dans ce cas, la déclaration doit déclarer au moins une variable, et chaque variable doit avoir un initialiseur non vide.

// « auto » dans les spécificateurs de déclaration
auto x = 5; // OK : x a le type int
const auto *v = &x, u = 6; // OK : v a le type const int*, u a le type const int
static auto y = 0.0; // OK : y a le type double

auto f() -> int;
auto (*fp)() -> auto = f; // OK : le « auto » du type de retour final
                          // peut être déduit de f

Déclarations de liaison structurée

Le spécificateur auto peut être utilisé dans une déclaration de liaison structurée.

(depuis C++17)

expressions new

Un type substitut peut être utilisé dans la séquence de spécificateurs de type du type-id d'une expression new. Dans un tel type-id, le type substitut doit apparaître comme l'un des spécificateurs de type de la séquence, ou dans un type de retour final qui spécifie le type remplaçant ce spécificateur de type.

Transtypage de style fonctionnel

Le spécificateur de type auto peut être utilisé comme spécificateur de type d'un transtypage de style fonctionnel.

(depuis C++23)

Notes

Jusqu'à C++11, auto avait la sémantique d'un spécificateur de durée de stockage.

Un programme qui utilise un type substitut dans un contexte non explicitement mentionné ci-dessus est mal formé.

Si une déclaration déclare plusieurs entités, et que la séquence de spécificateurs de déclaration utilise un type substitut, le programme est mal formé si l'une des conditions suivantes est satisfaite :

  • Certaines entités déclarées ne sont pas des variables.
  • Le type qui remplace le type substitut n'est pas le même à chaque déduction.
auto f() -> int, i = 0; // Erreur : déclare une fonction et une variable avec « auto »
auto a = 5, b = {1, 2}; // Erreur : types différents pour « auto »

Le mot-clé auto peut aussi être utilisé dans un spécificateur de nom imbriqué. Un spécificateur de nom imbriqué de la forme auto:: est un substitut remplacé par un type classe ou énumération selon les règles de la déduction de substitut de type contraint.

(TS des concepts)

Macro de test de fonctionnalité Valeur Std Fonctionnalité
__cpp_decltype_auto 201304L (C++14) decltype(auto)

Mots-clés

auto, decltype

Exemple

#include <iostream>
#include <utility>

template<class T, class U>
auto add(T t, U u) { return t + u; } // le type de retour est le type de operator+(T, U)

// la transmission parfaite d'un appel de fonction doit utiliser decltype(auto)
// dans le cas où la fonction appelée renvoie par référence
template<class F, class... Args>
decltype(auto) PerfectForward(F fun, Args&&... args)
{
    return fun(std::forward<Args>(args)...);
}

template<auto n> // déclaration de paramètre auto en C++17
auto f() -> std::pair<decltype(n), decltype(n)> // auto ne peut pas déduire depuis une liste d'initialisation entre accolades
{
    return {n, n};
}

int main()
{
    auto a = 1 + 2;          // le type de a est int
    auto b = add(1, 1.2);    // le type de b est double
    static_assert(std::is_same_v<decltype(a), int>);
    static_assert(std::is_same_v<decltype(b), double>);

    auto c0 = a;             // le type de c0 est int, contenant une copie de a
    decltype(auto) c1 = a;   // le type de c1 est int, contenant une copie de a
    decltype(auto) c2 = (a); // le type de c2 est int&, un alias de a
    std::cout << "before modification through c2, a = " << a << '\n';
    ++c2;
    std::cout << " after modification through c2, a = " << a << '\n';

    auto [v, w] = f<0>(); //déclaration de liaison structurée

    auto d = {1, 2}; // OK : le type de d est std::initializer_list<int>
    auto n = {5};    // OK : le type de n est std::initializer_list<int>
//  auto e{1, 2};    // Erreur depuis le DR n3922, std::initializer_list<int> avant
    auto m{5};       // OK : le type de m est int depuis le DR n3922, initializer_list<int> avant
//  decltype(auto) z = { 1, 2 } // Erreur : {1, 2} n'est pas une expression

    // auto est couramment utilisé pour les types sans nom, comme les types des expressions lambda
    auto lambda = [](int x) { return x + 3; };

//  auto int x; // valide en C++98, erreur depuis C++11
//  auto x;     // valide en C, erreur en C++

    [](...){}(c0, c1, v, w, d, n, m, lambda); // supprime les avertissements « unused variable »
}

Sortie possible :

before modification through c2, a = 3
 after modification through c2, a = 4

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 1265 C++11 le spécificateur auto pouvait être utilisé pour déclarer une fonction avec un type de retour final et définir une variable dans une seule instruction de déclaration prohibited
CWG 1346 C++11 une liste d'expressions entre parenthèses ne pouvait pas être affectée à une variable auto allowed
CWG 1347 C++11 une déclaration avec le spécificateur auto pouvait définir deux variables de types T et std::initializer_list<T> respectivement prohibited
CWG 1852 C++14 le spécificateur auto dans decltype(auto) était aussi un substitut pas un substitut dans ce cas
CWG 1892 C++11 le type de retour d'un type-id de pointeur de fonction pouvait être auto prohibited
CWG 2476 C++11 la résolution de la CWG issue 1892 interdisait la déduction du type de retour des variables pointeurs de fonction à partir de leurs initialiseurs allowed
