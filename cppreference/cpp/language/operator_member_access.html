Notes

  • Comme pour la plupart des surcharges définies par l'utilisateur, les types de retour doivent correspondre aux types de retour fournis par les opérateurs intégrés afin que les opérateurs définis par l'utilisateur puissent être utilisés de la même manière que les opérateurs intégrés. Cependant, dans une surcharge d'opérateur définie par l'utilisateur, n'importe quel type peut être utilisé comme type de retour (y compris void). Une exception est operator->, qui doit renvoyer un pointeur ou une autre classe avec operator-> surchargé pour être réellement utilisable.

Explication

L'opérateur d'indexation intégré donne accès à un objet pointé par l'opérande pointeur ou tableau.

L'opérateur d'indirection intégré donne accès à un objet ou une fonction pointé par l'opérande pointeur.

L'opérateur d'adresse intégré crée un pointeur pointant vers l'objet ou la fonction opérande.

Les opérateurs membre d'un objet et pointeur vers membre d'un objet donnent accès à un membre de donnée ou à une fonction membre de l'objet opérande.

Les opérateurs membre d'un pointeur et pointeur vers membre d'un pointeur donnent accès à un membre de donnée ou à une fonction membre de la classe pointée par l'opérande pointeur.

Opérateur d'indexation intégré

Les expressions de l'opérateur d'indexation ont la forme

| | | | expr1 ﻿[expr2 ﻿] | (1) | | | | expr1 ﻿[{expr ﻿, ...}] | (2) | (depuis C++11) | | | expr1 ﻿[expr2 ﻿, expr ﻿, ...] | (3) | (depuis C++23) | |

  1. Pour l'opérateur intégré, l'une des expressions (soit expr1, soit expr2) doit être une glvalue de type « tableau de T » ou une prvalue de type « pointeur vers T », tandis que l'autre expression (expr2 ou expr1, respectivement) doit être une prvalue d'énumération non délimitée ou de type entier. Le résultat de cette expression a le type T. expr2 ne peut pas être une expression virgule non parenthésée. (depuis C++23)

  2. La forme avec une liste entre accolades à l'intérieur des crochets n'est utilisée que pour appeler un operator[] surchargé.

  3. La forme avec une liste d'expressions séparées par des virgules à l'intérieur des crochets n'est utilisée que pour appeler un operator[] surchargé.

L'expression d'indexation intégrée E1[E2] est exactement identique à l'expression *(E1 + E2), sauf pour sa catégorie de valeur (voir ci-dessous) et l'ordre d'évaluation (depuis C++17) : l'opérande pointeur (qui peut résulter d'une conversion tableau-vers-pointeur, et qui doit pointer vers un élément d'un tableau ou juste après la fin) est ajusté pour pointer vers un autre élément du même tableau, selon les règles de l'arithmétique des pointeurs, puis déréférencé.

Lorsqu'elle est appliquée à un tableau, l'expression d'indexation est une lvaluesi le tableau est une lvalue, et une xvalue sinon (depuis C++11).

Lorsqu'elle est appliquée à un pointeur, l'expression d'indexation est toujours une lvalue.

Le type T ne peut pas être un type incomplet, même si la taille ou la structure interne de T n'est jamais utilisée, comme dans &x[0].

Utiliser une expression virgule non parenthésée comme second argument (droit) d'un opérateur d'indexation est obsolète.

Par exemple, a[b, c] est obsolète et a[(b, c)] ne l'est pas.

(depuis C++20) (jusqu'à C++23)

Une expression virgule non parenthésée ne peut pas être le second argument (droit) d'un opérateur d'indexation. Par exemple, a[b, c] est soit mal formée, soit équivalente à a.operator[](b, c).

Des parenthèses sont nécessaires pour utiliser une expression virgule comme indice, par exemple a[(b, c)].

(depuis C++23)

Lors de la résolution de surcharge face aux opérateurs définis par l'utilisateur, pour tout type objet T (éventuellement qualifié cv), la signature de fonction suivante participe à la résolution de surcharge :

T& operator[](T*, std::ptrdiff_t);

T& operator[](std::ptrdiff_t, T*);

#include <iostream>
#include <map>
#include <string>

int main()
{
    int a[4] = {1, 2, 3, 4};
    int* p = &a[2];
    std::cout << p[1] << p[-1] << 1[p] << (-1)[p] << '\n';

    std::map<std::pair<int, int>, std::string> m;
    m[{1, 2}] = "abc"; // utilise la version [{...}]
}

Output:

4242

Opérateur d'indirection intégré

Les expressions de l'opérateur d'indirection ont la forme

| | | | *expr | | | |

L'opérande de l'opérateur d'indirection intégré doit être un pointeur vers un objet ou un pointeur vers une fonction, et le résultat est la lvalue désignant l'objet ou la fonction vers lequel expr pointe. Si expr ne pointe pas réellement vers un objet ou une fonction, le comportement est indéfini (sauf pour le cas spécifié par typeid).

Un pointeur vers void (éventuellement qualifié cv) ne peut pas être déréférencé. Les pointeurs vers d'autres types incomplets peuvent être déréférencés, mais la lvalue résultante ne peut être utilisée que dans des contextes qui autorisent une lvalue de type incomplet, par exemple lors de l'initialisation d'une référence.

Lors de la résolution de surcharge face aux opérateurs définis par l'utilisateur, pour tout type T qui est soit un type objet (éventuellement qualifié cv), soit un type fonction (non qualifié const ou ref), la signature de fonction suivante participe à la résolution de surcharge :

T& operator*(T*);

#include <iostream>

int f() { return 42; }

int main()
{
    int n = 1;
    int* pn = &n;

    int& r = *pn; // une lvalue peut être liée à une référence
    int m = *pn;  // indirection + conversion lvalue-to-rvalue

    int (*fp)() = &f;
    int (&fr)() = *fp; // une lvalue de fonction peut être liée à une référence

    [](...){}(r, m, fr); // supprime les éventuels avertissements « variable inutilisée »
}

Opérateur d'adresse intégré

Les expressions de l'opérateur d'adresse ont la forme

| | | | &expr | (1) | | | | &class ﻿::member | (2) | | |

  1. Si l'opérande est une expression lvalue d'un objet ou d'une fonction de type T, operator& crée et renvoie une prvalue de type T*, avec la même qualification cv, qui pointe vers l'objet ou la fonction désigné par l'opérande. Si l'opérande a un type incomplet, le pointeur peut être formé, mais si ce type incomplet est une classe qui définit son propre operator&, il n'est pas spécifié si la version intégrée ou la surcharge est utilisée. Pour les opérandes de type avec operator& défini par l'utilisateur, std::addressof peut être utilisé pour obtenir le vrai pointeur. Notez que, contrairement à C99 et aux versions ultérieures de C, il n'existe pas de cas particulier pour l'opérateur unaire operator& appliqué au résultat de l'opérateur unaire operator*.

Si l'opérande est le nom d'une fonction surchargée, l'adresse ne peut être prise que si la surcharge peut être résolue grâce au contexte. Voir Adresse d'une fonction surchargée pour plus de détails.

Si expr désigne une fonction membre à objet explicite, expr doit être un identificateur qualifié. Appliquer & à un identificateur non qualifié désignant une fonction membre à objet explicite est mal formé.

(depuis C++23)

  1. Si l'opérande est un nom qualifié d'un membre non statique ou variant autre qu'une fonction membre à objet explicite (depuis C++23), par exemple &C::member, le résultat est une prvalue pointeur vers fonction membre ou pointeur vers membre de données de type T dans la classe C. Notez que ni &member, ni C::member, ni même &(C::member) ne peuvent être utilisés pour initialiser un pointeur vers membre.

Dans la résolution de surcharge pour les opérateurs définis par l'utilisateur, cet opérateur n'introduit aucune signature de fonction supplémentaire : l'opérateur d'adresse intégré ne s'applique pas s'il existe un operator& surchargé qui est une fonction viable.

void f(int) {}
void f(double) {}

struct A { int i; };
struct B { void f(); };

int main()
{
    int n = 1;
    int* pn = &n;    // pointer
    int* pn2 = &*pn; // pn2 == pn

    int A::* mp = &A::i;      // pointeur vers membre de donnée
    void (B::*mpf)() = &B::f; // pointeur vers fonction membre

    void (*pf)(int) = &f; // résolution de surcharge due au contexte d'initialisation
//  auto pf2 = &f; // erreur : type de fonction surchargée ambigu
    auto pf2 = static_cast<void (*)(int)>(&f); // résolution de surcharge due à un cast
}

Opérateurs intégrés d'accès aux membres

Les expressions d'opérateur d'accès aux membres ont la forme

| | | | expr ﻿.template(facultatif) id-expr | (1) | | | | expr ﻿->template(facultatif) id-expr | (2) | | | | expr ﻿.pseudo-destructor | (3) | | | | expr ﻿->pseudo-destructor | (4) | | |

  1. L'expr doit être une expression de type classe complet T.

Si id-expr désigne un membre statique ou un énumérateur, expr est une expression à valeur rejetée.

  1. L'expr doit être une expression de type pointeur vers un type classe complet T*.

3,4) L'expr doit être une expression de type scalaire (voir ci-dessous).

id-expr est un nom (formellement, une expression d'identificateur qui désigne) un membre de données ou une fonction membre de T ou d'une classe de base non ambiguë et accessible B de T (par exemple E1.E2 ou E1->E2), éventuellement qualifié (par exemple E1.B::E2 ou E1->B::E2), éventuellement en utilisant template désambiguïsateur (par exemple E1.template E2 ou E1->template E2).

Si un operator-> défini par l'utilisateur est appelé, operator-> est appelé à nouveau sur la valeur obtenue, récursivement, jusqu'à ce qu'un operator-> renvoyant un pointeur ordinaire soit atteint. Ensuite, la sémantique intégrée est appliquée à ce pointeur.

L'expression E1->E2 est exactement équivalente à (*E1).E2 pour les types intégrés ; c'est pourquoi les règles suivantes ne traitent que E1.E2.

Dans l'expression E1.E2 :

  1. Si E2 est un membre de données statique :
  • Si E2 est de type référence T& ou T&& (depuis C++11), le résultat est une lvalue de type T désignant l'objet ou la fonction auquel la référence est liée.
  • Sinon, étant donné le type de E2 comme T, le résultat est une lvalue de type T désignant ce membre de données statique.

En substance, E1 est évaluée puis rejetée dans les deux cas.

  1. Si E2 est un membre de données non statique :
  • Si E2 est de type référence T& ou T&& (depuis C++11), le résultat est une lvalue de type T désignant l'objet ou la fonction auquel le membre référence correspondant de E1 est lié.
  • Sinon, si E1 est une lvalue, le résultat est une lvalue désignant ce membre de données non statique de E1.
  • Sinon (si E1 est une [rvalue (jusqu'à C++17) | xvalue (qui peut être matérialisée à partir d'une prvalue) (depuis C++17)]), le résultat est une [rvalue (jusqu'à C++11) | xvalue (depuis C++11)] désignant ce membre de données non statique de E1.

Si E2 n'est pas un membre mutable, la qualification cv du résultat est l'union des qualifications cv de E1 et de E2, sinon (si E2 est un membre mutable), c'est l'union des qualifications volatile de E1 et de E2.

  1. Si E2 est un ensemble de surcharges (d'une ou plusieurs fonctions membres statiques et fonctions membres non statiques), E1.E2 doit être l'opérande de gauche (éventuellement entre parenthèses) d'un opérateur d'appel de fonction membre, et la résolution de surcharge de fonctions est utilisée pour sélectionner la fonction à laquelle E2 fait référence, après quoi :
  • Si E2 est une fonction membre statique, le résultat est une lvalue désignant cette fonction membre statique. En substance, E1 est évaluée puis rejetée dans ce cas.
  • Sinon (E2 est une fonction membre non statique), le résultat est une prvalue désignant cette fonction membre non statique de E1.

  1. Si E2 est un énumérateur membre, étant donné le type de E2 comme T, le résultat est [une rvalue (jusqu'à C++11) | une prvalue (depuis C++11)] de type T dont la valeur est la valeur de l'énumérateur.

  2. Si E2 est un type imbriqué, le programme est mal formé.

  3. Si E1 a un ScalarType et E2 est un ~ suivi du nom de type ou du spécificateur decltype désignant le même type (sans les qualifications cv), éventuellement qualifié, le résultat est un genre particulier de prvalue qui ne peut être utilisé que comme opérande de gauche d'un opérateur d'appel de fonction, et à aucune autre fin

L'expression d'appel de fonction résultante est appelée appel de pseudo-destructeur. Elle ne prend aucun argument, renvoie void, évalue E1 et termine la durée de vie de son objet résultat. C'est le seul cas où l'opérande de gauche de operator. a un type non classe. Autoriser l'appel de pseudo-destructeur permet d'écrire du code sans avoir à savoir si un destructeur existe pour un type donné.

operator. ne peut pas être surchargé, et pour operator->, dans la résolution de surcharge pour les opérateurs définis par l'utilisateur, l'opérateur intégré n'introduit aucune signature de fonction supplémentaire : l'opérateur operator-> intégré ne s'applique pas s'il existe un operator-> surchargé qui est une fonction viable.

#include <cassert>
#include <iostream>
#include <memory>

struct P
{
    template<typename T>
    static T* ptr() { return new T; }
};

template<typename T>
struct A
{
    A(int n): n(n) {}

    int n;
    static int sn;

    int f() { return 10 + n; }
    static int sf() { return 4; }

    class B {};
    enum E {RED = 1, BLUE = 2};

    void g()
    {
        typedef int U;

        // mot-clé template nécessaire pour un membre modèle dépendant
        int* p = T().template ptr<U>();
        p->~U(); // U vaut int, appelle le pseudo-destructeur de int
        delete p;
    }
};

template<>
int A<P>::sn = 2;

struct UPtrWrapper
{
    std::unique_ptr<std::string> uPtr;
    std::unique_ptr<std::string>& operator->() { return uPtr; }
};

int main()
{
    A<P> a(1);
    std::cout << a.n << ' '
              << a.sn << ' '   // A::sn fonctionne aussi
              << a.f() << ' '
              << a.sf() << ' ' // A::sf() fonctionne aussi
//            << &a.f << ' '   // erreur : mal formé si a.f n'est pas
                               // l'opérande gauche de operator()
//            << a.B << ' '    // erreur : type imbriqué non autorisé
              << a.RED << ' '; // enumerator

    UPtrWrapper uPtrWrap{std::make_unique<std::string>("wrapped")};
    assert(uPtrWrap->data() == uPtrWrap.operator->().operator->()->data());
}

Output:

1 2 11 4 1

Si E2 est un membre non statique et que le résultat de E1 est un objet dont le type n'est pas similaire au type de E1, le comportement est indéfini :

struct A { int i; };
struct B { int j; };
struct D : A, B {};

void f()
{
    D d;
    static_cast<B&>(d).j;      // OK, l'expression d'objet désigne le sous-objet B de d
    reinterpret_cast<B&>(d).j; // comportement indéfini
}

Opérateurs intégrés d'accès aux pointeurs vers membres

Les expressions d'opérateur d'accès aux membres via des pointeurs vers membres ont la forme

| | | | lhs ﻿.*rhs | (1) | | | | lhs ﻿->*rhs | (2) | | |

  1. lhs doit être une expression de type classe T.

  2. lhs doit être une expression de type pointeur vers un type classe T*.

rhs doit être une rvalue de type pointeur vers membre (de données ou de fonction) de T ou pointeur vers membre d'une classe de base non ambiguë et accessible B de T.

L'expression E1->*E2 est exactement équivalente à (*E1).*E2 pour les types intégrés ; c'est pourquoi les règles suivantes ne traitent que E1.*E2.

Dans l'expression E1.*E2 :

  1. si E2 est un pointeur vers membre de données,
  • si E1 est une lvalue, le résultat est une lvalue désignant ce membre de données,
  • sinon (si E1 est une [rvalue (jusqu'à C++17) | xvalue (qui peut être matérialisée à partir d'une prvalue) (depuis C++17)]), le résultat est une [rvalue (jusqu'à C++11) | xvalue (depuis C++11)] désignant ce membre de données ;
  1. si E2 est un pointeur vers fonction membre, le résultat est une prvalue spéciale désignant cette fonction membre, qui ne peut être utilisée que comme opérande de gauche d'un opérateur d'appel de fonction membre, et à aucune autre fin ;

Les règles de qualification cv sont les mêmes que pour l'opérateur de membre d'objet, avec une règle supplémentaire : un pointeur vers membre qui désigne un membre mutable ne peut pas être utilisé pour modifier ce membre dans un objet const ; 3)

  1. si E2 est une valeur de pointeur vers membre nulle, le comportement est indéfini ;

  2. si le résultat E1 est un objet dont le type n'est pas similaire au type de E1, ou si son objet le plus dérivé ne contient pas le membre auquel E2 fait référence, le comportement est indéfini ;

  3. si E1 est une rvalue et que E2 pointe vers une fonction membre avec le qualificateur de référence &, le programme est mal formé sauf si la fonction membre a le qualificateur cv const mais pas volatile (depuis C++20) ;

  1. si E1 est une lvalue et que E2 pointe vers une fonction membre avec le qualificateur de référence &&, le programme est mal formé.

(depuis C++11)

Dans la résolution de surcharge pour les opérateurs définis par l'utilisateur, pour chaque combinaison de types D, B, R, où le type classe B est soit la même classe que D, soit une classe de base non ambiguë et accessible de D, et où R est soit un type objet soit un type fonction, la signature de fonction suivante participe à la résolution de surcharge :

R& operator->*(D*, R B::*);

où les deux opérandes peuvent être qualifiés cv, auquel cas la qualification cv du type de retour est l'union des qualifications cv des opérandes.

#include <iostream>

struct S
{
    S(int n) : mi(n) {}
    mutable int mi;
    int f(int n) { return mi + n; }
};

struct D : public S
{
    D(int n) : S(n) {}
};

int main()
{
    int S::* pmi = &S::mi;
    int (S::* pf)(int) = &S::f;

    const S s(7);
//  s.*pmi = 10; // erreur : impossible de modifier via mutable
    std::cout << s.*pmi << '\n';

    D d(7); // les pointeurs de base fonctionnent avec un objet dérivé
    D* pd = &d;
    std::cout << (d.*pf)(7) << ' '
              << (pd->*pf)(8) << '\n';
}

Output:

7
14 15

Bibliothèque standard

L'opérateur d'indexation est surchargé par de nombreuses classes de conteneurs standard :

  • operator[] — accède à un bit spécifique (fonction membre publique de std::bitset<N>)
  • operator[] — fournit un accès indexé au tableau géré (fonction membre publique de std::unique_ptr<T,Deleter>)
  • operator[] — accède au caractère spécifié (fonction membre publique de std::basic_string<CharT,Traits,Allocator>)
  • operator[] — accède à l'élément spécifié (fonction membre publique de std::array<T,N>)
  • operator[] — accède à l'élément spécifié (fonction membre publique de std::deque<T,Allocator>)
  • operator[] — accède à l'élément spécifié (fonction membre publique de std::vector<T,Allocator>)
  • operator[] — accède à un élément spécifié ou l'insère (fonction membre publique de std::map<Key,T,Compare,Allocator>)
  • operator[] — accède à un élément spécifié ou l'insère (fonction membre publique de std::unordered_map<Key,T,Hash,KeyEqual,Allocator>)
  • operator[] — accède à un élément par son indice (fonction membre publique de std::reverse_iterator<Iter>)
  • operator[] (C++11) — accède à un élément par son indice (fonction membre publique de std::move_iterator<Iter>)
  • operator[] — obtient ou définit un élément, une tranche ou un masque de valarray (fonction membre publique de std::valarray<T>)
  • operator[] — renvoie la sous-correspondance spécifiée (fonction membre publique de std::match_results<BidirIt,Alloc>)

Les opérateurs d'indirection et d'accès aux membres sont surchargés par de nombreuses classes d'itérateurs et de pointeurs intelligents :

  • operator*operator-> — déréférence le pointeur vers l'objet géré (fonction membre publique de std::unique_ptr<T,Deleter>)
  • operator*operator-> — déréférence le pointeur stocké (fonction membre publique de std::shared_ptr<T>)
  • operator*operator-> — accède à l'objet géré (fonction membre publique de std::auto_ptr<T>)
  • operator* — déréférence l'itérateur (fonction membre publique de std::raw_storage_iterator<OutputIt,T>)
  • operator*operator-> — déréférence l'itérateur sous-jacent décrémenté (fonction membre publique de std::reverse_iterator<Iter>)
  • operator* — opération sans effet (fonction membre publique de std::back_insert_iterator<Container>)
  • operator* — opération sans effet (fonction membre publique de std::front_insert_iterator<Container>)
  • operator* — opération sans effet (fonction membre publique de std::insert_iterator<Container>)
  • operator*operator-> (C++11) (C++11) (deprecated in C++20) — accède à l'élément pointé (fonction membre publique de std::move_iterator<Iter>)
  • operator*operator-> — renvoie l'élément courant (fonction membre publique de std::istream_iterator<T,CharT,Traits,Distance>)
  • operator* — opération sans effet (fonction membre publique de std::ostream_iterator<T,CharT,Traits>)
  • operator* — obtient une copie du caractère courant (fonction membre publique de std::istreambuf_iterator<CharT,Traits>)
  • operator* — opération sans effet (fonction membre publique de std::ostreambuf_iterator<CharT,Traits>)
  • operator*operator-> — accède à la correspondance courante (fonction membre publique de std::regex_iterator<BidirIt,CharT,Traits>)
  • operator*operator-> — accède à la sous-correspondance courante (fonction membre publique de std::regex_token_iterator<BidirIt,CharT,Traits>)

Aucune classe de la bibliothèque standard ne surcharge operator&. Le meilleur exemple connu d'operator& surchargé est la classe COM de Microsoft CComPtr, bien qu'il puisse aussi apparaître dans des EDSL tels que boost.spirit.

Aucune classe de la bibliothèque standard ne surcharge operator->*. Il a été suggéré qu'il pourrait faire partie de l'interface des pointeurs intelligents, et il est d'ailleurs utilisé dans ce rôle par les acteurs de boost.phoenix, mais il est plus courant dans des EDSL tels que cpp.react.
