Déclaration d'amitié

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

La déclaration d'amitié apparaît dans un corps de classe et accorde à une fonction ou à une autre classe l'accès aux membres privés et protégés de la classe dans laquelle la déclaration d'amitié apparaît.

Syntaxe

friend function-declaration | (1)

friend function-definition | (2)

friend elaborated-type-specifier ; | (3) | (jusqu'à C++26)

friend simple-type-specifier ;

friend typename-specifier ;

| (4) | (depuis C++11)
(jusqu'à C++26)

friend friend-type-specifier-list ; | (5) | (depuis C++26)

1,2) Une déclaration d'amitié de fonction.

3-5) Une déclaration d'amitié de classe.

  • function-declaration — une déclaration de fonction
  • function-definition — une définition de fonction
  • elaborated-type-specifier — un spécificateur de type élaboré
  • simple-type-specifier — un spécificateur de type simple
  • typename-specifier — le mot-clé typename suivi d'un identificateur qualifié ou d'un identificateur de modèle simple qualifié
  • friend-type-specifier-list — une liste non vide séparée par des virgules de simple-type-specifier, elaborated-type-specifier et typename-specifier﻿s, chaque spécificateur peut être suivi d'une ellipse (...)

Description

  1. Désigne une ou plusieurs fonctions comme amies de cette classe :
class Y
{
    int data; // membre privé

    // l'opérateur<< non membre aura accès aux membres privés de Y
    friend std::ostream& operator<<(std::ostream& out, const Y& o);
    friend char* X::foo(int); // les membres d'autres classes peuvent aussi être amis
    friend X::X(char), X::~X(); // les constructeurs et destructeurs peuvent être amis
};

// une déclaration d'amitié ne déclare pas une fonction membre
// cet opérateur<< doit encore être défini, en tant que non membre
std::ostream& operator<<(std::ostream& out, const Y& y)
{
    return out << y.data; // peut accéder au membre privé Y::data
}
  1. (uniquement autorisé dans les définitions de classes non locales) Définit une fonction non membre et la rend amie de cette classe en même temps. Cette fonction non membre est toujours inline, sauf si elle est rattachée à un module nommé (depuis C++20).
class X
{
    int a;

    friend void friend_set(X& p, int i)
    {
        p.a = i; // ceci est une fonction non membre
    }
public:
    void member_set(int i)
    {
        a = i; // ceci est une fonction membre
    }
};

3,4) Désigne une classe comme amie de cette classe. Cela signifie que les déclarations et définitions de membres de l'amie peuvent accéder aux membres privés et protégés de cette classe, et que l'amie peut aussi hériter des membres privés et protégés de cette classe.

  1. La classe est nommée par elaborated-type-specifier. Le nom de la classe utilisé dans cette déclaration d'amitié n'a pas besoin d'avoir été préalablement déclaré.

  2. La classe est nommée par simple-type-specifier ou typename-specifier. Si le type nommé n'est pas un type classe, cette déclaration d'amitié est ignorée. Cette déclaration ne déclare pas en avance un nouveau type.

  3. Désigne toutes les classes de friend-type-specifier-list comme amies de cette classe. Cela signifie que les déclarations et définitions de membres des amies peuvent accéder aux membres privés et protégés de cette classe, et que les amies peuvent aussi hériter des membres privés et protégés de cette classe. Si un type nommé n'est pas un type classe, il est ignoré dans cette déclaration d'amitié.

Chaque spécificateur de friend-type-specifier-list désigne une classe si le spécificateur n'est pas suivi d'une ellipse, sinon s'applique une expansion de paquet.

class Y {};

class A
{
    int data; // membre de données privé

    class B {}; // type imbriqué privé

    enum { a = 100 }; // énumérateur privé

    friend class X; // déclaration anticipée de classe amie (spécificateur de classe élaboré)
    friend Y; // déclaration de classe amie (spécificateur de type simple) (depuis C++11)

    // les deux déclarations d'amitié ci-dessus peuvent être fusionnées depuis C++26 :
    // friend class X, Y;
};

class X : A::B // OK : A::B accessible à l'ami
{
    A::B mx; // OK : A::B accessible au membre de l'ami

    class Y
    {
        A::B my; // OK : A::B accessible au membre imbriqué de l'ami
    };

    int v[A::a]; // OK : A::a accessible au membre de l'ami
};

Amis modèles

Les déclarations de modèle de fonction et de modèle de classe peuvent toutes deux apparaître avec le spécificateur friend dans toute classe ou modèle de classe non local (bien que seuls les modèles de fonction puissent être définis dans la classe ou le modèle de classe qui accorde l'amitié). Dans ce cas, chaque spécialisation du modèle devient une amie, qu'elle soit implicitement instanciée, partiellement spécialisée ou explicitement spécialisée.

class A
{
    template<typename T>
    friend class B; // chaque B<T> est un ami de A

    template<typename T>
    friend void f(T) {} // chaque f<T> est un ami de A
};

Les déclarations d'amitié ne peuvent pas désigner des spécialisations partielles, mais peuvent désigner des spécialisations complètes :

template<class T>
class A {};      // primary

template<class T>
class A<T*> {};  // partial

template<>
class A<int> {}; // full

class X
{
    template<class T>
    friend class A<T*>;  // Erreur

    friend class A<int>; // OK
};

Lorsqu'une déclaration d'amitié désigne une spécialisation complète d'un modèle de fonction, le mot-clé inline[, constexpr (depuis C++11) | , consteval (depuis C++20)] et les arguments par défaut ne peuvent pas être utilisés :

template<class T>
void f(int);

template<>
void f<int>(int);

class X
{
    friend void f<int>(int x = 1); // erreur : arguments par défaut non autorisés
};

Une déclaration d'amie de modèle peut désigner un membre d'un modèle de classe A, qui peut être soit une fonction membre soit un type membre (le type doit utiliser spécificateur de type élaboré). Une telle déclaration n'est bien formée que si le dernier composant de son spécificateur de nom imbriqué (le nom à gauche du dernier ::) est un simple-template-id (nom de modèle suivi d'une liste d'arguments entre chevrons) qui désigne le modèle de classe. Les paramètres de modèle de cette déclaration d'amie de modèle doivent pouvoir être déduits du simple-template-id.

Dans ce cas, le membre de toute spécialisation de A ou de toute spécialisation partielle de A devient un ami. Cela n'implique pas d'instancier le modèle primaire A ni ses spécialisations partielles : les seules exigences sont que la déduction des paramètres de modèle de A à partir de cette spécialisation réussisse, et que la substitution des arguments de modèle déduits dans la déclaration d'amitié produise une déclaration qui serait une redéclaration valide du membre de la spécialisation :

// modèle primaire
template<class T>
struct A
{
    struct B {};

    void f();

    struct D { void g(); };

    T h();

    template<T U>
    T i();
};

// spécialisation complète
template<>
struct A<int>
{
    struct B {};

    int f();

    struct D { void g(); };

    template<int U>
    int i();
};

// une autre spécialisation complète
template<>
struct A<float*>
{
    int *h();
};

// la classe non template qui accorde l'amitié aux membres du modèle de classe A
class X
{
    template<class T>
    friend struct A<T>::B; // tous les A<T>::B sont amis, y compris A<int>::B

    template<class T>
    friend void A<T>::f(); // A<int>::f() n'est pas un ami car sa signature
                           // ne correspond pas, mais par exemple A<char>::f() est un ami

//  template<class T>
//  friend void A<T>::D::g(); // mal formé, la dernière partie du nested-name-specifier,
//                            // D dans A<T>::D::, n'est pas un simple-template-id

    template<class T>
    friend int* A<T*>::h(); // tous les A<T*>::h sont amis :
                            // A<float*>::h(), A<int*>::h(), etc

    template<class T>
    template<T U>       // toutes les instanciations de A<T>::i() et A<int>::i() sont amies,
    friend T A<T>::i(); // et donc toutes les spécialisations de ces modèles de fonctions
};

Arguments de modèle par défaut ne sont autorisés dans les déclarations d'amis de modèle que si la déclaration est une définition et qu'aucune autre déclaration de ce modèle de fonction n'apparaît dans cette unité de traduction.

(depuis C++11)

Opérateurs amis de modèle

Un cas d'utilisation courant des amis de modèle est la déclaration d'une surcharge d'opérateur non membre agissant sur un modèle de classe, par exemple operator<<(std::ostream&, const Foo<T>&) pour un Foo<T> défini par l'utilisateur.

Un tel opérateur peut être défini dans le corps de la classe, ce qui a pour effet de générer une fonction non modèle distincte operator<< pour chaque T et fait de cette fonction non modèle operator<< un ami de son Foo<T> :

#include <iostream>

template<typename T>
class Foo
{
public:
    Foo(const T& val) : data(val) {}
private:
    T data;

    // génère un operator<< non template pour ce T
    friend std::ostream& operator<<(std::ostream& os, const Foo& obj)
    {
        return os << obj.data;
    }
};

int main()
{
    Foo<double> obj(1.23);
    std::cout << obj << '\n';
}

Output:

1.23

ou bien le modèle de fonction doit être déclaré comme modèle avant le corps de la classe, auquel cas la déclaration d'amitié dans Foo<T> peut désigner la spécialisation complète de operator<< pour son T :

#include <iostream>

template<typename T>
class Foo; // déclaration anticipée pour rendre possible la déclaration de la fonction

template<typename T> // declaration
std::ostream& operator<<(std::ostream&, const Foo<T>&);

template<typename T>
class Foo
{
public:
    Foo(const T& val) : data(val) {}
private:
    T data;

    // fait référence à une spécialisation complète pour ce T particulier
    friend std::ostream& operator<< <> (std::ostream&, const Foo&);

    // remarque : ceci repose sur la déduction d'arguments de modèle dans les déclarations
    // on peut aussi spécifier l'argument de modèle avec operator<< <T>"
};

// definition
template<typename T>
std::ostream& operator<<(std::ostream& os, const Foo<T>& obj)
{
    return os << obj.data;
}

int main()
{
    Foo<double> obj(1.23);
    std::cout << obj << '\n';
}

Liaison

Les spécificateurs de classe de stockage ne sont pas autorisés dans les déclarations d'amitié.

Si une fonction ou un modèle de fonction est d'abord déclaré et défini dans une déclaration d'amitié, et que la classe englobante est définie dans des déclarations d'exportation, son nom a la même liaison que le nom de la classe englobante.

(depuis C++20)

[Si (jusqu'à C++20) | Sinon, si (depuis C++20)] une fonction ou un modèle de fonction est déclaré dans une déclaration d'amitié, et qu'une déclaration correspondante qui n'est pas d'amitié est accessible, le nom a la liaison déterminée par cette déclaration antérieure.

Sinon, la liaison du nom introduit par une déclaration d'amitié est déterminée comme d'habitude.

Notes

L'amitié n'est pas transitive (un ami de votre ami n'est pas votre ami).

L'amitié n'est pas héritée (les enfants de votre ami ne sont pas vos amis, et vos amis ne sont pas les amis de vos enfants).

Les spécificateurs d'accès n'ont aucun effet sur la signification des déclarations d'amitié (elles peuvent apparaître dans les sections private: ou public:, sans différence).

Une déclaration de classe amie ne peut pas définir une nouvelle classe (friend class X {}; est une erreur).

Lorsqu'une classe locale déclare une fonction ou une classe non qualifiée comme amie, seules les fonctions et classes de la portée non classe la plus interne sont recherchées, et non les fonctions globales :

class F {};

int f();

int main()
{
    extern int g();

    class Local // Classe locale dans la fonction main()
    {
        friend int f(); // Erreur, aucune fonction de ce nom n'est déclarée dans main()
        friend int g(); // OK, il existe une déclaration de g dans main()
        friend class F; // est amie d'un F local (défini plus loin)
        friend class ::F; // est amie du F global
    };

    class F {}; // F local
}

Un nom déclaré pour la première fois dans une déclaration d'amitié au sein d'une classe ou d'un modèle de classe X devient un membre de l'espace de noms englobant le plus interne de X, mais n'est pas visible pour la recherche (sauf la recherche dépendant des arguments qui considère X) tant qu'une déclaration correspondante à portée d'espace de noms n'est pas fournie - voir espaces de noms pour plus de détails.

Exemple

Les opérateurs d'insertion et d'extraction de flux sont souvent déclarés comme amis non membres :

#include <iostream>
#include <sstream>

class MyClass
{
    int i;                   // les amis ont accès aux membres non publics et non statiques
    static inline int id{6}; // et statiques (éventuellement inline)

    friend std::ostream& operator<<(std::ostream& out, const MyClass&);
    friend std::istream& operator>>(std::istream& in, MyClass&);
    friend void change_id(int);
public:
    MyClass(int i = 0) : i(i) {}
};

std::ostream& operator<<(std::ostream& out, const MyClass& mc)
{
    return out << "MyClass::id = " << MyClass::id << "; i = " << mc.i;
}

std::istream& operator>>(std::istream& in, MyClass& mc)
{
    return in >> mc.i;
}

void change_id(int id) { MyClass::id = id; }

int main()
{
    MyClass mc(7);
    std::cout << mc << '\n';
//  mc.i = 333*2;  // erreur : i est un membre privé
    std::istringstream("100") >> mc;
    std::cout << mc << '\n';
//  MyClass::id = 222*3;  // erreur : id est un membre privé
    change_id(9);
    std::cout << mc << '\n';
}

Output:

MyClass::id = 6; i = 7
MyClass::id = 6; i = 100
MyClass::id = 9; i = 100
