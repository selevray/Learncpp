Expressions constantes

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Définit une expression pouvant être évaluée à la compilation.

Ces expressions peuvent être utilisées comme arguments de modèle non typés, tailles de tableaux, et dans d'autres contextes exigeant des expressions constantes, p. ex.

int n = 1;
std::array<int, n> a1;  // Erreur : « n » n'est pas une expression constante
const int cn = 2;
std::array<int, cn> a2; // OK : « cn » est une expression constante

Définition

Une expression appartenant à l'une des catégories d'expressions constantes listées ci-dessous est une expression constante.

Catégories d'expressions constantes de C++98

Expression constante intégrale (C++98)

Aux endroits suivants, C++ exige des expressions qui s'évaluent en une constante entière ou d'énumération :

  • bornes de tableaux (y compris les dimensions dans les expressions new autres que la première)
  • constantes d'étiquette case
  • longueurs de champs de bits
  • initialiseurs d'énumérateurs
  • initialiseurs de membres de données statiques
  • arguments de modèle non typés de type entier ou énumération

Une expression satisfaisant toutes les conditions suivantes est une expression constante entière :

  • Elle n'implique que les entités suivantes :

  • littéraux de types arithmétiques

  • enumerators

  • variables ou membres de données statiques satisfaisant toutes les conditions suivantes :

  • Elles sont qualifiées const.

  • Elles ne sont pas qualifiées volatile.

  • Elles sont de types entiers ou énumération.

  • Elles sont initialisées avec des expressions constantes.

  • paramètres de modèle non typés de types entiers ou énumération

  • sizeof expressions

  • Elle n'utilise aucun littéral à virgule flottante, sauf s'ils sont explicitement convertis en types entiers ou énumération.

  • Elle n'applique aucune conversion vers des types non entiers et non énumération.

  • Elle n'utilise aucune des entités suivantes, sauf dans les opérandes de sizeof :

  • function

  • objet de classe

  • pointer

  • reference

  • opérateur d'affectation

  • opérateur d'incrémentation

  • opérateur de décrémentation

  • opérateur d'appel de fonction

  • opérateur virgule

Autres catégories d'expressions constantes

Les autres expressions ne sont considérées comme constantes qu'aux fins de l'initialisation constante. Une telle expression constante doit être l'une des expressions suivantes :

  • une expression qui s'évalue en une valeur de pointeur nul
  • une expression qui s'évalue en une valeur de pointeur-vers-membre nul
  • une expression constante arithmétique
  • une expression constante d'adresse
  • une expression constante de référence
  • une expression constante d'adresse pour un type objet complet, plus ou moins une expression constante entière
  • une expression constante de pointeur-vers-membre

Une expression constante arithmétique est une expression satisfaisant les exigences d'une expression constante entière, avec les exceptions suivantes :

  • Les littéraux à virgule flottante peuvent être utilisés sans conversion explicite.
  • Des conversions vers des types à virgule flottante peuvent être appliquées.

Une expression constante d'adresse est une expression de type pointeur satisfaisant toutes les conditions suivantes :

  • Le pointeur pointe vers une lvalue désignant un objet de durée de stockage statique, un littéral de chaîne, ou une fonction. L'objet n'est pas un sous-objet d'un type classe non POD.

  • Le pointeur est créé par l'une des méthodes suivantes :

  • en utilisant explicitement l'opérateur d'adresse

  • en utilisant implicitement un paramètre de modèle non typé de type pointeur

  • en utilisant une expression de type tableau ou fonction

  • L'expression n'appelle aucune fonction.

  • L'expression utilise des conversions explicites de pointeurs (sauf dynamic_cast) et les opérateurs suivants sans accéder à l'objet résultat :

  • opérateur d'indexation

  • opérateur d'indirection

  • opérateur d'adresse

  • opérateur d'accès à un membre

  • Si l'opérateur d'indexation est utilisé, l'un de ses opérandes est une expression constante entière.

Une expression constante de référence est une expression de type référence satisfaisant toutes les conditions suivantes :

  • La référence désigne un objet de durée de stockage statique, un paramètre de modèle non typé de type référence, ou une fonction. La référence ne désigne pas un membre ou une classe de base d'un type classe non POD.

  • L'expression n'appelle aucune fonction.

  • L'expression utilise des conversions explicites de références (sauf dynamic_cast) et les opérateurs suivants sans accéder à l'objet résultat :

  • opérateur d'indexation

  • opérateur d'indirection

  • opérateur d'adresse

  • opérateur d'accès à un membre

  • Si l'opérateur d'indexation est utilisé, l'un de ses opérandes est une expression constante entière.

Une expression constante de pointeur vers membre est une expression de type pointeur vers membre où le pointeur est créé en appliquant l'opérateur d'adresse à un identifiant qualifié, éventuellement précédé d'une conversion explicite de pointeur vers membre.

(jusqu'à C++11)

Les expressions suivantes sont collectivement appelées expressions constantes ﻿ :

  • expressions constantes de cœur prvalue de type littéral non pointeur

  • expressions constantes de cœur lvalue désignant des objets de durée de stockage statique ou des fonctions

  • expressions constantes de cœur prvalue de type pointeur qui s'évaluent à l'une des valeurs suivantes :

  • l'adresse d'un objet de durée de stockage statique

  • l'adresse d'une fonction

  • une valeur de pointeur nul

  • expressions constantes de cœur prvalue de type std::nullptr_t

(depuis C++11) (jusqu'à C++14)

Les entités suivantes sont des résultats autorisés d'une expression constante ﻿ :

  • objets temporaires de durée de stockage statique
  • objets non temporaires de durée de stockage statique dont les valeurs satisfont les contraintes énumérées ci-dessous
  • fonctions non immédiates (depuis C++20)

Une expression constante est soit une glvalue expression constante de base qui fait référence à une entité constituant un résultat autorisé d'une expression constante, soit une prvalue expression constante de base dont la valeur satisfait les contraintes suivantes :

  • Si la valeur est un objet de type classe, chaque membre de donnée non statique de type référence fait référence à une entité qui est un résultat autorisé d'une expression constante.
  • Si la valeur est un objet de type scalaire, il n'a pas de valeur indéterminée.
  • Si la valeur est de type pointeur, elle correspond à l'une des valeurs suivantes :
  • l'adresse d'un objet de durée de stockage statique
  • l'adresse située après la fin d'un objet de durée de stockage statique
  • l'adresse d'une fonction non immédiate (depuis C++20)
  • une valeur de pointeur nul
  • Si la valeur est de type pointeur vers fonction membre, elle ne désigne pas une fonction immédiate.

(depuis C++20)

  • Si la valeur est un objet de type classe ou tableau, chaque sous-objet satisfait ces contraintes pour la valeur.

(depuis C++14) (jusqu'à C++26)

Une expression constante est soit une glvalue expression constante de base qui désigne un objet ou une fonction immédiate non, soit une prvalue expression constante de base dont la valeur satisfait les contraintes suivantes :

  • Chaque référence constituante fait référence à un objet ou à une fonction non immédiate.
  • Aucune valeur constituante de type scalaire n'est une valeur indéterminée ou erronée.
  • Aucune valeur constituante de type pointeur n'est un pointeur vers une fonction immédiate ni une valeur de pointeur invalide.
  • Aucune valeur constituante de type pointeur vers membre ne désigne une fonction immédiate.

(depuis C++26)

Pour déterminer si une expression est une expression constante, on suppose que l'élision de copie n'est pas effectuée.

La définition des expressions constantes de C++98 se trouve entièrement dans la boîte repliable. La description suivante s'applique à C++11 et aux versions ultérieures de C++.

Type littéral

Les types suivants sont collectivement appelés types littéraux ﻿ :

  • void éventuellement qualifié cv
  • type scalaire
  • type référence
  • un tableau de type littéral
  • type classe éventuellement qualifié cv satisfaisant toutes les conditions suivantes :
    • Il possède un [destructeur trivial (jusqu'à C++20) | constexpr destructeur (depuis C++20)].
    • Tous ses membres de donnée non statiques non variants et ses classes de base sont de types littéraux non volatils.
    • Il s'agit de l'un des types suivants :
  • un type fermeture

(depuis C++17)

  • un type union agrégat satisfaisant l'une des conditions suivantes :

    • Il n'a aucun membre variant.
    • Il possède au moins un membre variant de type littéral non volatil.

  • un type agrégat qui n'est pas une union, et chacun de ses membres union anonyme satisfait l'une des conditions suivantes :

    • Il n'a aucun membre variant.
    • Il possède au moins un membre variant de type littéral non volatil.

  • un type possédant au moins un constructeur (modèle de) constexpr qui n'est ni un constructeur de copie ni un constructeur de déplacement

Seuls des objets de types littéraux peuvent être créés au sein d'une expression constante.

Expression constante de cœur

Une expression constante de cœur est toute expression dont l'évaluation n'évaluerait pas l'une quelconque des constructions de langage suivantes :

Construction du langage Version Document(s)
le pointeur this, sauf dans une fonction constexpr en cours d'évaluation dans le cadre de l'expression, ou lorsqu'il apparaît dans une expression explicite ou implicite d'accès à un membre de classe N2235
un flux de contrôle qui traverse la déclaration d'une variable de bloc à durée de stockage statique ou de thread qui n'est pas utilisable dans les expressions constantes (depuis C++23) P2242R3

  1. une expression d'appel de fonction qui appelle une fonction (ou un constructeur) non déclaré constexpr

    constexpr int n = std::numeric_limits<int>::max(); // OK : max() est constexpr
constexpr int m = std::time(nullptr); // Erreur : std::time() n'est pas constexpr

  2. un appel à une fonction constexpr qui est déclarée mais non définie

  3. un appel à une instanciation de modèle de fonction/constructeur constexpr dont l'instanciation ne satisfait pas les exigences de fonction/constructeur constexpr.

  4. un appel à une fonction virtuelle constexpr, invoquée sur un objet dont le type dynamique est inconnu en constexpr

  5. une expression qui dépasserait les limites définies par l'implémentation

  6. une expression dont l'évaluation entraîne une forme quelconque de comportement indéfiniou erroné (depuis C++26) du langage de base, à l'exception de tout comportement indéfini potentiel introduit par les attributs standard.

    constexpr double d1 = 2.0 / 1.0; // OK
constexpr double d2 = 2.0 / 0.0; // Erreur : non définie
constexpr int n = std::numeric_limits<int>::max() + 1; // Erreur : dépassement de capacité
int x, y, z[30];
constexpr auto e1 = &y - &x;        // Erreur : indéfini
constexpr auto e2 = &z[20] - &z[3]; // OK
constexpr std::bitset<2> a;
constexpr bool b = a[2]; // comportement indéfini, mais non spécifié s'il est détecté

  7. (jusqu'à C++17) une expression lambda

  8. une conversion implicite de lvalue en rvalue, sauf si elle s'applique à...

    1. une glvalue de type (éventuellement qualifié cv) std::nullptr_t

    2. une glvalue non volatile de type littéral désignant un objet qui est utilisable dans des expressions constantes

      int main()
{
    const std::size_t tabsize = 50;
    int tab[tabsize]; // OK : tabsize est une expression constante
                      // car tabsize est utilisable dans les expressions constantes
                      // car il est de type entier qualifié const, et
                      // son initialiseur est un initialiseur constant

    std::size_t n = 50;
    const std::size_t sz = n;
    int tab2[sz]; // Erreur : sz n'est pas une expression constante
                  // car sz n'est pas utilisable dans les expressions constantes
                  // car son initialiseur n'était pas un initialiseur constant
}

    3. une glvalue non volatile de type littéral qui fait référence à un objet non volatile dont la durée de vie a commencé pendant l'évaluation de cette expression

  9. une conversion implicite de lvalue en rvalue ou une modification appliquée à un membre non actif d'une union ou à l'un de ses sous-objets (même s'il partage une séquence initiale commune avec le membre actif)

  10. une conversion implicite de lvalue en rvalue sur un objet dont la valeur est indéterminée

  11. un appel du constructeur de copie/déplacement ou de l'opérateur d'affectation par copie/déplacement implicite d'une union dont le membre actif est mutable (le cas échéant), dont la durée de vie a commencé en dehors de l'évaluation de cette expression

  12. (jusqu'à C++20) une expression d'affectation qui changerait le membre actif d'une union

  13. conversion d'un pointeur vers void en un type de pointeur vers objet T*sauf si le pointeur contient une valeur de pointeur nul ou pointe vers un objet dont le type est similaire à T (depuis C++26)

  14. dynamic_cast dont l'opérande est une glvalue qui fait référence à un objet dont le type dynamique est constexpr-unknown (depuis C++20)

  15. reinterpret_cast

  16. (jusqu'à C++20) appel d'un pseudo-destructeur

  17. (jusqu'à C++14) un opérateur d'incrémentation ou de décrémentation

  18. (depuis C++14) modification d'un objet, sauf si l'objet est de type littéral non volatile et que sa durée de vie a commencé pendant l'évaluation de l'expression

    constexpr int incr(int& n)
{
    return ++n;
}

constexpr int g(int k)
{
    constexpr int x = incr(k); // Erreur : incr(k) n'est pas une
                               // expression constante de base car la durée de vie de k
                               // a commencé en dehors de l'expression incr(k)
    return x;
}

constexpr int h(int k)
{
    int x = incr(k); // OK : x n'est pas tenu d'être initialisé
                     // avec une expression constante de base
    return x;
}

constexpr int y = h(1); // OK : initialise y avec la valeur 2
                        // h(1) est une expression constante de base car
                        // la durée de vie de k commence à l'intérieur de l'expression h(1)

  19. (depuis C++20) un appel de destructeur ou de pseudo-destructeur pour un objet dont la durée de vie n'a pas commencé pendant l'évaluation de cette expression

  20. une expression typeid appliquée à une glvalue de type polymorphe et cette glvalue fait référence à un objet dont le type dynamique est constexpr-unknown (depuis C++20)

  21. une expression new, sauf si l'une des conditions suivantes est remplie : (depuis C++20)

    • La fonction d'allocation sélectionnée est une fonction d'allocation globale remplaçable et le stockage alloué est désalloué pendant l'évaluation de cette expression.

    (depuis C++20)

    • La fonction d'allocation sélectionnée est une forme sans allocation avec un type alloué T, et l'argument de placement satisfait toutes les conditions suivantes :
    • Il pointe vers :
    • un objet dont le type est similaire à T, si T n'est pas un type tableau, ou
    • le premier élément d'un objet d'un type similaire à T, si T est un type tableau.
    • Il pointe vers un stockage dont la durée a commencé pendant l'évaluation de cette expression.

    (depuis C++26)

  22. une expression delete, sauf si elle désalloue une région de stockage allouée pendant l'évaluation de cette expression (depuis C++20)

  23. (depuis C++20) Coroutines : une expression await ou une expression yield

  24. (depuis C++20) une comparaison à trois voies lorsque le résultat est non spécifié

  25. un opérateur d'égalité ou relationnel dont le résultat est non spécifié

  26. (jusqu'à C++14) un opérateur d'affectation ou d'affectation composée

  27. (jusqu'à C++26) une expression throw

  28. (depuis C++26) une construction d'un objet d'exception, sauf si l'objet d'exception et toutes ses copies implicites créées par les invocations de std::current_exception ou std::rethrow_exception sont détruits pendant l'évaluation de cette expression

    constexpr void check(int i)
{
    if (i < 0)
        throw i;
}

constexpr bool is_ok(int i)
{
    try {
        check(i);
    } catch (...) {
        return false;
    }
    return true;
}

constexpr bool always_throw()
{
    throw 12;
    return true;
}

static_assert(is_ok(5)); // OK
static_assert(!is_ok(-1)); // OK depuis C++26
static_assert(always_throw()); // Erreur : exception non interceptée

  29. une déclaration asm

  30. un appel de la macro va_arg

  31. une instruction goto

  32. une expression dynamic_cast ou typeid ou une expression new (depuis C++26) qui lèverait une exception lorsqu'aucune définition du type d'exception n'est accessible (depuis C++26)

  33. à l'intérieur d'une expression lambda, une référence à this ou à une variable définie en dehors de cette lambda, si cette référence serait une odr-use

    void g()
{
    const int n = 0;

    constexpr int j = *&n; // OK : en dehors d'une lambda-expression

    [=]
    {
        constexpr int i = n;   // OK : 'n' n'est pas odr-utilisée et n'est pas capturée ici.
        constexpr int j = *&n; // Mal formé : '&n' serait une odr-utilisation de 'n'.
    };
}

    notez que si l'ODR-use a lieu dans un appel de fonction vers une fermeture, elle ne fait pas référence à this ni à une variable englobante, puisqu'elle accède à la place à un membre de données de la fermeture

    // OK : 'v' & 'm' sont odr-utilisées mais n'apparaissent pas dans une expression constante
// dans la lambda imbriquée
auto monad = [](auto v){ return [=]{ return v; }; };
auto bind = [](auto m){ return [=](auto fvm){ return fvm(m()); }; };

// Il est permis d'avoir des captures d'objets automatiques créés pendant l'évaluation d'une expression constante.
static_assert(bind(monad(2))(monad)() == monad(2)());

    (depuis C++17)

Exigences supplémentaires

Même si une expression E n'évalue rien de ce qui est indiqué ci-dessus, il est défini par l'implémentation de savoir si E est une expression constante de base si l'évaluation de E entraînerait un comportement indéfini à l'exécution.

Même si une expression E n'évalue rien de ce qui est indiqué ci-dessus, il est non spécifié de savoir si E est une expression constante de base si l'évaluation de E évaluerait l'un des éléments suivants :

  • Une opération au comportement indéfini dans la bibliothèque standard.
  • Un appel de la macro va_start.

Pour déterminer si une expression est une expression constante de base, l'évaluation du corps d'une fonction membre de std::allocator<T> est ignorée si T est un type littéral.

Pour déterminer si une expression est une expression constante de base, l'évaluation d'un appel à un constructeur de copie/déplacement trivial ou à un opérateur d'affectation par copie/déplacement trivial d'une union est considérée comme copiant/déplaçant le membre actif de l'union, s'il existe.

Pour déterminer si une expression est une expression constante de base, l'évaluation d'une expression d'identificateur désignant une liaison structurée bd a la sémantique suivante :

  • Si bd est une lvalue faisant référence à l'objet lié à une référence fictive ref, le comportement est comme si ref avait été désigné.
  • Sinon, si bd désigne un élément de tableau, le comportement est celui de l'évaluation de e[i], où e est le nom de la variable initialisée à partir de l'initialiseur de la déclaration de liaison structurée, et i est l'indice de l'élément référencé par bd.
  • Sinon, si bd désigne un membre de classe, le comportement est celui de l'évaluation de e.m, où e est le nom de la variable initialisée à partir de l'initialiseur de la déclaration de liaison structurée, et m est le nom du membre référencé par bd.

(depuis C++26)

Pendant l'évaluation de l'expression comme expression constante de base, toutes les expressions d'identificateurs et les utilisations de *this qui désignent un objet ou une référence dont la durée de vie a commencé en dehors de l'évaluation de l'expression sont traitées comme désignant une instance spécifique de cet objet ou de cette référence, dont la durée de vie et celle de tous les sous-objets (y compris tous les membres d'union) couvrent l'ensemble de l'évaluation constante.

  • Pour un tel objet qui n'est pas utilisable dans des expressions constantes (depuis C++20), le type dynamique de l'objet est constexpr-unknown.
  • Pour une telle référence qui n'est pas une expression constante utilisable (depuis C++20), la référence est traitée comme liée à un objet non spécifié du type référencé, dont la durée de vie et celle de tous ses sous-objets couvrent l'ensemble de l'évaluation constante et dont le type dynamique est constexpr-unknown.

Expression constante entière

Une expression constante entière est une expression de type entier ou énumération non délimitée, implicitement convertie en prvalue, où l'expression convertie est une expression constante de base.

Si une expression de type classe est utilisée là où une expression constante entière est attendue, l'expression est implicitement convertie contextuellement en un type entier ou énumération non délimitée.

Expression constante convertie

Une expression constante convertie de type T est une expression implicitement convertie en type T, où l'expression convertie est une expression constante, et la séquence de conversion implicite ne contient que :

  • conversions définies par l'utilisateur constexpr
  • conversions de lvalue en rvalue
  • promotions intégrales
  • conversions intégrales sans rétrécissement
  • promotions flottantes
  • conversions flottantes sans rétrécissement
  • conversions tableau-vers-pointeur
  • conversions fonction-vers-pointeur
  • conversions de pointeur de fonction
  • conversions de qualification
  • conversions de pointeur nul depuis std::nullptr_t
  • conversions de pointeur membre nul depuis std::nullptr_t

(depuis C++17)

Et si une liaison de référence a lieu, elle ne peut être qu'une liaison directe.

Les contextes suivants exigent une expression constante convertie :

  • le constant-expression des étiquettes case
  • initialiseurs d'énumérateurs lorsque le type sous-jacent est fixé
  • entiers et énumérations *(jusqu'à C++17)*non-types arguments de modèle
  • bornes de tableaux
  • les dimensions dans les expressions new autres que la première

(depuis C++14)

  • l'indice de expression d'indexation de pack et de spécificateur d'indexation de pack

(depuis C++26)

Une expression constante convertie contextuellement de type bool est une expression, convertie contextuellement en bool, où l'expression convertie est une expression constante et la séquence de conversion ne contient que les conversions ci-dessus.

Les contextes suivants exigent une expression constante convertie contextuellement de type bool :

  • spécifications de noexcept
  • déclarations de static_assert

(jusqu'à C++23)

  • instructions if constexpr

(depuis C++17) (jusqu'à C++23)

  • spécificateurs explicit conditionnels

(depuis C++20)

Entités constituantes

Les valeurs constitutives d'un objet obj sont définies comme suit :

  • Si obj a un type scalaire, la valeur constitutive est la valeur de obj.
  • Sinon, les valeurs constitutives sont les valeurs constitutives de tous les sous-objets directs de obj autres que les membres inactifs d'union.

Les références constitutives d'un objet obj comprennent les références suivantes :

  • tout membre direct de obj ayant un type référence
  • les références constitutives de tout sous-objet direct de obj autres que les membres inactifs d'union

Les valeurs constitutives et références constitutives d'une variable var sont définies comme suit :

  • Si var déclare un objet, les valeurs et références constitutives sont celles de cet objet.
  • Si var déclare une référence, la référence constitutive est cette référence.

Pour toute référence constitutive ref d'une variable var, si ref est liée à un objet temporaire ou à un sous-objet de celui-ci dont la durée de vie est prolongée jusqu'à celle de ref, les valeurs et références constitutives de cet objet temporaire sont aussi des valeurs et références constitutives de var, récursivement.

Entités représentables en constexpr

Les objets à durée de stockage statique sont référençables en constexpr en tout point du programme.

Un objet obj à durée de stockage automatique est référençable en constexpr depuis un point P si la plus petite portée englobant la variable var et la plus petite portée englobant P sont la même portée de paramètres de fonction qui n'est pas associée à la liste de paramètres d'une expression requires, où var est la variable correspondant à l'objet complet de obj ou la variable dont la durée de vie est celle de obj prolongée.

Un objet ou une référence x est représentable en constexpr en un point P si toutes les conditions suivantes sont satisfaites :

  • Pour chaque valeur constitutive de x qui pointe vers un objet obj, obj est référençable en constexpr depuis P.
  • Pour chaque valeur constitutive de x qui pointe juste après un objet obj, obj est référençable en constexpr depuis P.
  • Pour chaque référence constitutive de x qui fait référence à un objet obj, obj est référençable en constexpr depuis P.

(depuis C++26)

Entités initialisées par constante

Une variable ou un objet temporaire obj est initialisé par constante si toutes les conditions suivantes sont satisfaites :

  • Soit il possède un initialiseur, soit son type est constructible par défaut en const.
  • L'expression complète de son initialisation est une expression constante dans le contexte exigeant une expression constante, sauf que si obj est un objet, cette expression complète peut aussi appeler des constexpr constructeurs pour obj et ses sous-objets même si ces objets sont de types classe non littéraux.

(jusqu'à C++26)

Une variable var est initialisable par constante si toutes les conditions suivantes sont satisfaites :

  • L'expression complète de son initialisation est une expression constante dans le contexte exigeant une expression constante.
  • Immédiatement après la déclaration d'initialisation de var, l'objet ou la référence déclaré par var est représentable en constexpr.
  • Si l'objet ou la référence x déclaré par var a une durée de stockage statique ou thread, x est représentable en constexpr au point le plus proche dont la portée immédiate est une portée d'espace de noms et qui suit la déclaration d'initialisation de var.

Une variable initialisable par constante est initialisée par constante si elle possède un initialiseur, ou si son type est constructible par défaut en const.

(depuis C++26)

Utilisables dans les expressions constantes

Une variable est potentiellement constante si elle est une variable constexpr, ou si elle a un type référence ou un type entier ou énumération qualifié const non volatile.

Une variable var constante-initialisée et potentiellement constante est utilisable dans les expressions constantes en un point P si la déclaration d'initialisation D de var est atteignable depuis P et si l'une des conditions suivantes est satisfaite :

  • var est une variable constexpr.
  • var n'est pas initialisée avec une valeur locale à l'unité de traduction.
  • P est dans la même unité de traduction que D.

Un objet ou une référence est utilisable dans les expressions constantes en un point P s'il est l'une des entités suivantes :

  • une variable utilisable dans les expressions constantes en P
  • un objet temporaire de type littéral qualifié const non volatile dont la durée de vie est prolongée jusqu'à celle d'une variable utilisable dans les expressions constantes en P
  • un objet paramètre de modèle
  • un objet littéral de chaîne
  • un sous-objet non mutable de l'une des entités ci-dessus
  • un membre référence de l'une des entités ci-dessus

(jusqu'à C++26)

Un objet ou une référence est potentiellement utilisable dans les expressions constantes en un point P s'il est l'une des entités suivantes :

  • une variable utilisable dans les expressions constantes en P
  • un objet temporaire de type littéral qualifié const non volatile dont la durée de vie est prolongée jusqu'à celle d'une variable utilisable dans les expressions constantes en P
  • un objet paramètre de modèle
  • un objet littéral de chaîne
  • un sous-objet non mutable de l'une des entités ci-dessus
  • un membre référence de l'une des entités ci-dessus

Un objet ou une référence est utilisable dans les expressions constantes en un point P s'il s'agit d'un objet ou d'une référence potentiellement utilisable dans les expressions constantes en P et représentable en constexpr en P.

(depuis C++26)

Expressions manifestement évaluées de manière constante

Les expressions suivantes (y compris les conversions vers le type de destination) sont manifestement évaluées de manière constante ﻿:

  • bornes de tableaux
  • les dimensions dans les expressions new autres que la première
  • longueurs de champs de bits
  • initialiseurs de énumérations
  • alignments
  • le constant-expression des étiquettes case
  • arguments de modèle non de type
  • expressions dans les spécifications noexcept
  • expressions dans les déclarations static_assert
  • initialiseurs de variables constexpr
  • conditions des instructions constexpr if
  • expressions dans les spécificateurs conditionnels explicit
  • invocations immédiates
  • expressions de contrainte dans les définitions de concept, les exigences imbriquées et les clauses requires, lors de la détermination de la satisfaction des contraintes
  • initialiseurs de variables de type référence ou de type entier ou énumération qualifié const, mais uniquement si les initialiseurs sont des expressions constantes
  • initialiseurs de variables statiques et thread_local, mais uniquement si toutes les sous-expressions des initialiseurs (y compris les appels de constructeurs et les conversions implicites) sont des expressions constantes (c'est-à-dire si les initialiseurs sont des initialiseurs constants)

Le fait qu'une évaluation ait lieu dans un contexte manifestement évalué de manière constante peut être détecté par std::is_constant_evaluatedet if consteval (depuis C++23).

(depuis C++20)

Fonctions et variables nécessaires à l'évaluation constante

Les expressions ou conversions suivantes sont potentiellement évaluées de manière constante :

  • expressions manifestement évaluées de manière constante
  • expressions potentiellement évaluées
  • sous-expressions immédiates d'une liste d'initialisation entre accolades (l'évaluation constante peut être nécessaire pour déterminer si une conversion est restrictive)
  • expressions de prise d'adresse apparaissant dans une entité templatisée (l'évaluation constante peut être nécessaire pour déterminer si une telle expression est dépendante de la valeur)
  • sous-expressions de l'une des expressions ci-dessus qui ne sont pas une sous-expression d'un opérande non évalué imbriqué

Une fonction est nécessaire à l'évaluation constante si c'est une fonction constexpr et si elle est nommée par une expression potentiellement évaluée de manière constante.

Une variable est nécessaire à l'évaluation constante si c'est une variable constexpr, ou si elle est de type entier qualifié const non volatile ou de type référence, et si l'expression d'identificateur qui la désigne est potentiellement évaluée de manière constante.

La définition d'une fonction par défaut et l'instanciation d'une spécialisation de modèle de fonction ou d'une spécialisation de modèle de variable (depuis C++14) sont déclenchées si la fonction ou la variable (depuis C++14) est nécessaire à l'évaluation constante.

Sous-expression constante

Une sous-expression constante est une expression dont l'évaluation en tant que sous-expression d'une expression e n'empêcherait pas e d'être une expression constante de base, où e n'est aucune des expressions suivantes :

  • expression throw
  • expression yield

(depuis C++20)

  • expression d'affectation
  • expression virgule
