Modèles

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un modèle est une entité C++ qui définit l'une des entités suivantes :

  • une famille de classes (modèle de classe), qui peuvent être des classes imbriquées
  • une famille de fonctions (modèle de fonction), qui peuvent être des fonctions membres
  • un alias vers une famille de types (modèle d'alias)

(depuis C++11)

  • une famille de variables (modèle de variable)

(depuis C++14)

  • un concept (contraintes et concepts)

(depuis C++20)

Les modèles sont paramétrés par un ou plusieurs paramètres de modèle, de trois sortes : les paramètres de modèle de type, les paramètres de modèle non-type et les paramètres de modèle de modèle.

Lorsque des arguments de modèle sont fournis ou, pour les modèles de fonction et de classe (depuis C++17) uniquement, déduits, ils sont substitués aux paramètres de modèle pour obtenir une spécialisation du modèle, c'est-à-dire un type spécifique ou une lvalue de fonction spécifique.

Les spécialisations peuvent aussi être fournies explicitement : les spécialisations complètes sont autorisées pour les modèles de classe, de variable (depuis C++14) et de fonction, les spécialisations partielles ne sont autorisées que pour les modèles de classeet de variable (depuis C++14).

Lorsqu'une spécialisation de modèle de classe est référencée dans un contexte qui exige un type objet complet, ou qu'une spécialisation de modèle de fonction est référencée dans un contexte qui exige l'existence d'une définition de fonction, le modèle est instancié (son code est effectivement compilé), sauf si le modèle a déjà été explicitement spécialisé ou explicitement instancié. L'instanciation d'un modèle de classe n'instancie aucune de ses fonctions membres, sauf si elles sont aussi utilisées. À l'édition de liens, les instanciations identiques générées par différentes unités de traduction sont fusionnées.

La définition d'un modèle de classe doit être visible au point d'instanciation implicite, raison pour laquelle les bibliothèques de modèles fournissent généralement toutes les définitions de modèles dans les en-têtes (par ex. la plupart des bibliothèques boost sont uniquement composées d'en-têtes).

Identifiants de modèle

Un identifiant de modèle a l'une des syntaxes suivantes :

  1. Un identifiant de modèle simple.

  2. Un identifiant de modèle de fonction opérateur.

3,4) Un identifiant de modèle de fonction opérateur littéral.

  • template-name — un identifiant qui désigne un modèle
  • op — un opérateur surchargeable
  • identifier — un identifiant
  • user-defined-string-literal — "" suivi d'un identifiant

Un identifiant de modèle simple qui désigne une spécialisation de modèle de classe désigne une classe.

Un identifiant de modèle qui désigne une spécialisation d'alias désigne un type.

Un identifiant de modèle qui désigne une spécialisation de modèle de fonction désigne une fonction.

Si toutes les conditions suivantes sont satisfaites, un identifiant de modèle est valide ﻿:

  • Il y a au plus autant d'arguments que de paramètresou un paramètre est un pack de paramètres de modèle (depuis C++11).
  • Il existe un argument pour chaque paramètre non déductiblenon-pack (depuis C++11) qui n'a pas d'argument de modèle par défaut.
  • Chaque argument de modèle correspond au paramètre de modèle correspondant.
  • La substitution de chaque argument de modèle dans les paramètres de modèle suivants (s'il y en a) réussit.
  • Si l'identifiant de modèle est non dépendant, les contraintes associées sont satisfaites comme spécifié ci-dessous.

(depuis C++20)

Un identifiant de modèle simple invalide est une erreur de compilation, sauf s'il désigne une spécialisation de modèle de fonction (auquel cas SFINAE peut s'appliquer).

template<class T, T::type n = 0>
class X;

struct S
{
    using type = int;
};

using T1 = X<S, int, int>; // erreur : trop d'arguments
using T2 = X<>;            // erreur : pas d'argument par défaut pour le premier paramètre de modèle
using T3 = X<1>;           // erreur : la valeur 1 ne correspond pas au paramètre de type
using T4 = X<int>;         // erreur : échec de substitution pour le second paramètre de modèle
using T5 = X<S>;           // OK

Lorsque le template-name d'un identifiant de modèle simple désigne un modèle de non-fonction contraint ou un paramètre de modèle de modèle contraint, mais pas un modèle membre qui est membre d'une spécialisation inconnue, et que tous les arguments de modèle de l'identifiant de modèle simple sont non dépendants, les contraintes associées du modèle contraint doivent être satisfaites :

template<typename T>
concept C1 = sizeof(T) != sizeof(int);

template<C1 T>
struct S1 {};

template<C1 T>
using Ptr = T*;

S1<int>* p;                      // erreur : contraintes non satisfaites
Ptr<int> p;                      // erreur : contraintes non satisfaites

template<typename T>
struct S2 { Ptr<int> x; };       // erreur, aucun diagnostic requis

template<typename T>
struct S3 { Ptr<T> x; };         // OK, la satisfaction n'est pas requise

S3<int> x;                       // erreur : contraintes non satisfaites

template<template<C1 T> class X>
struct S4
{
    X<int> x;                    // erreur, aucun diagnostic requis
};

template<typename T>
concept C2 = sizeof(T) == 1;

template<C2 T> struct S {};

template struct S<char[2]>;      // erreur : contraintes non satisfaites
template<> struct S<char[2]> {}; // erreur : contraintes non satisfaites

(depuis C++20)

Si toutes les conditions suivantes sont satisfaites, deux identifiants de modèle sont identiques ﻿:

  • Leurs template-name ﻿ou opérateurs désignent le même modèle.
  • Leurs arguments de modèle de type correspondants sont le même type.
  • Les valeurs de paramètres de modèle déterminées par leurs arguments de modèle non-type correspondants sont équivalentes en tant qu'arguments de modèle.
  • Leurs arguments de modèle de modèle correspondants désignent le même modèle.

Deux identifiants de modèle identiques désignent la même variable, (depuis C++14) classe ou fonction.

Entité templatisée

Une entité templatisée (ou, dans certaines sources, « temploïde ») est toute entité définie(ou, pour une expression lambda, créée) (depuis C++11) dans une définition de modèle. Toutes les entités suivantes sont des entités templatisées :

  • un modèle de classe/fonction/variable (depuis C++14)
  • un concept

(depuis C++20)

  • un membre d'une entité templatisée (comme une fonction membre non template d'un modèle de classe)
  • un énumérateur d'une énumération qui est une entité templatisée
  • toute entité définie ou créée dans une entité templatisée : une classe locale, une variable locale, une fonction amie, etc.
  • le type fermeture d'une expression lambda qui apparaît dans la déclaration d'une entité templatisée

(depuis C++11)

Par exemple, dans

template<typename T>
struct A
{
    void f() {}
};

la fonction A::f n'est pas un modèle de fonction, mais elle est tout de même considérée comme templatisée.

Une fonction templatisée est un modèle de fonction ou une fonction qui est templatisée.

Une classe templatisée est un modèle de classe ou une classe qui est templatisée.

Une variable templatisée est un modèle de variable ou une variable qui est templatisée.

(depuis C++14)
