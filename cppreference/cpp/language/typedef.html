spécificateur typedef

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

  • typedef - crée un alias pouvant être utilisé partout à la place d'un nom de type (éventuellement complexe).

Explication

Le spécificateur typedef, lorsqu'il est utilisé dans une déclaration, indique que la déclaration est une déclaration typedef plutôt qu'une déclaration de variable ou de fonction.

En général, le spécificateur typedef apparaît au début de la déclaration, bien qu'il puisse aussi apparaître après les spécificateurs de type, ou entre deux spécificateurs de type. Le spécificateur typedef ne peut être combiné avec aucun autre spécificateur, à l'exception des spécificateurs de type.

Une déclaration typedef peut déclarer un ou plusieurs identifiants sur la même ligne (par ex. int et un pointeur vers int), elle peut déclarer des types tableau et fonction, des pointeurs et références, des types classe, etc. Chaque identifiant introduit dans cette déclaration devient un nom typedef, qui est un synonyme du type de l'objet ou de la fonction qu'il aurait si le mot-clé typedef était retiré.

Les noms typedef sont des alias de types existants et ne sont pas des déclarations de nouveaux types. typedef ne peut pas être utilisé pour modifier la signification d'un nom de type existant (y compris un nom typedef). Une fois déclaré, un nom typedef ne peut être redéclaré que pour désigner à nouveau le même type. Les noms typedef ne sont valables que dans la portée où ils sont visibles : différentes fonctions ou déclarations de classes peuvent définir des types de même nom avec des significations différentes.

Le spécificateur typedef ne peut pas apparaître dans la déclaration d'un paramètre de fonction ni dans le decl-specifier-seq d'une définition de fonction :

void f1(typedef int param); // mal formé
typedef int f2() {}         // mal formé

Le spécificateur typedef ne peut pas apparaître dans une déclaration qui ne contient pas de déclarateur :

typedef struct X {}; // mal formé

nom typedef à des fins de liaison

Si une déclaration typedef définit une classe ou une énumération sans nom, le premier nom typedef du type classe ou du type énumération déclaré par cette déclaration est le nom typedef à des fins de liaison de ce type.

Par exemple, dans typedef struct { /* ... */ } S;, S est un nom typedef à des fins de liaison. La classe ou le type énumération défini de cette manière a une liaison externe (sauf s'il se trouve dans un espace de noms sans nom).

Une classe sans nom définie de cette manière ne doit contenir que des constructions compatibles C. En particulier, elle ne doit pas

  • déclarer de membres autres que des membres de données non statiques, des énumérations membres ou des classes membres,
  • avoir de classes de base ni d'initialiseurs de membres par défaut, ou
  • contenir une expression lambda,

et toutes les classes membres doivent également satisfaire ces exigences (récursivement).

(depuis C++20)

Notes

Les alias de type offrent les mêmes fonctionnalités que les déclarations typedef avec une syntaxe différente, et s'appliquent aussi aux noms de modèles.

(depuis C++11)

Mots-clés

typedef

Exemple

// typedef simple
typedef unsigned long ulong;

// les deux objets suivants ont le même type
unsigned long l1;
ulong l2;

// typedef plus complexe
typedef int int_t, *intp_t, (&fp)(int, ulong), arr_t[10];

// les deux objets suivants ont le même type
int a1[10];
arr_t a2;

// attention : les deux objets suivants n'ont pas le même type
const intp_t p1 = 0; // int *const p1 = 0
const int *p2;

// idiome courant en C pour éviter d'avoir à écrire « struct S »
typedef struct { int a; int b; } S, *pS;

// les deux objets suivants ont le même type
pS ps1;
S* ps2;

// erreur : un spécificateur de classe de stockage ne peut pas apparaître dans une déclaration typedef
// typedef static unsigned int uint;

// typedef peut être utilisé n'importe où dans le decl-specifier-seq
long unsigned typedef int long ullong;
// écrit de manière plus conventionnelle « typedef unsigned long long int ullong; »

// std::add_const, comme beaucoup d'autres métafonctions, utilise des typedefs membres
template<class T>
struct add_const
{
    typedef const T type;
};

typedef struct Node
{
    struct listNode* next; // déclare un nouveau type struct (incomplet) nommé listNode
} listNode; // erreur : entre en conflit avec le nom de struct déclaré précédemment

// erreur C++20 : « struct avec un nom de typedef pour la liaison » possède des fonctions membres
typedef struct { void f() {} } C_Incompatible;
