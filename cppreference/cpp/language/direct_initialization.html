Initialisation directe

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Initialise un objet à partir d'un ensemble explicite d'arguments de constructeur.

Syntaxe

T object ( arg );

T object ( arg1, arg2, ... );

| (1)

T object { arg }; | (2) | (depuis C++11)

T ( other )

T ( arg1, arg2, ... )

| (3)

static_cast< T >( other ) | (4)

new T( args, ... ) | (5)

Class::Class() : member( args, ... ) { ... } | (6)

[arg]() { ... } | (7) | (depuis C++11)

Explication

L'initialisation directe est effectuée dans les situations suivantes :

  1. Initialisation avec une liste non vide d'expressions entre parenthèses ou de listes d'initialisation entre accolades (depuis C++11).

  2. Initialisation d'un objet de type non classe avec un seul initialiseur entre accolades (note : pour les types classe et les autres usages de liste d'initialisation entre accolades, voir initialisation par liste) (depuis C++11).

  3. Initialisation de [un temporaire prvalue (jusqu'à C++17) | l'objet résultat d'une prvalue (depuis C++17)] par conversion de style fonctionnel ou avec une liste d'expressions entre parenthèses.

  4. Initialisation de [un temporaire prvalue (jusqu'à C++17) | l'objet résultat d'une prvalue (depuis C++17)] par une expression static_cast.

  5. Initialisation d'un objet à durée de stockage dynamique par une expression new avec un initialiseur.

  6. Initialisation d'une base ou d'un membre non statique par liste d'initialisation du constructeur.

  7. Initialisation des membres d'objet fermeture à partir des variables capturées par copie dans une expression lambda.

Les effets de l'initialisation directe sont :

  • Si T est un type tableau,
  • le programme est mal formé.

(jusqu'à C++20)

  • le tableau est initialisé comme dans l'initialisation agrégative, sauf que les conversions restrictives sont autorisées et que les éléments sans initialiseur sont initialisés par valeur.
struct A
{
    explicit A(int i = 0) {}
};

A a[2](A(1)); // OK : initialise a[0] avec A(1) et a[1] avec A()
A b[2]{A(1)}; // error : initialisation par copie-liste implicite de b[1]
              //        depuis {} : le constructeur explicite a été sélectionné

(depuis C++20)

  • Si T est un type de classe,
  • si l'initialisateur est une expression prvalue dont le type est la même classe que T (sans tenir compte de la qualification cv), l'expression d'initialisation elle-même, plutôt qu'un temporaire matérialisé à partir de celle-ci, est utilisée pour initialiser l'objet de destination.
    (Avant C++17, le compilateur peut dans ce cas omettre la construction à partir du temporaire prvalue, mais le constructeur approprié doit tout de même être accessible : voir élision de copie)

(depuis C++17)

  • les constructeurs de T sont examinés et le meilleur candidat est sélectionné par résolution de surcharge. Le constructeur est alors appelé pour initialiser l'objet.
  • sinon, si le type de destination est une classe agrégat (éventuellement qualifiée cv), elle est initialisée comme décrit dans initialisation d'agrégat, sauf que les conversions avec rétrécissement sont autorisées, les initialisateurs désignés ne sont pas autorisés, un temporaire lié à une référence ne voit pas sa durée de vie prolongée, il n'y a pas d'élision d'accolades, et tous les éléments sans initialisateur sont initialisés par valeur.
struct B
{
    int a;
    int&& r;
};

int f();
int n = 10;

B b1{1, f()};            // OK, la durée de vie est prolongée
B b2(1, f());            // bien formé, mais référence pendante
B b3{1.0, 1};            // error : conversion avec rétrécissement
B b4(1.0, 1);            // bien formé, mais référence pendante
B b5(1.0, std::move(n)); // OK

(depuis C++20)

  • Sinon, si T est un type non classe mais que le type source est une classe, les fonctions de conversion du type source et de ses classes de base, le cas échéant, sont examinées et le meilleur candidat est sélectionné par résolution de surcharge. La conversion définie par l'utilisateur sélectionnée est alors utilisée pour convertir l'expression d'initialisation en l'objet initialisé.
  • Sinon, si T est bool et que le type source est std::nullptr_t, la valeur de l'objet initialisé est false.
  • Sinon, des conversions standard sont utilisées si nécessaire pour convertir la valeur de other vers la version sans qualification cv de T, et la valeur initiale de l'objet initialisé est la valeur (éventuellement convertie).

Notes

L'initialisation directe est plus permissive que l'initialisation par copie : l'initialisation par copie ne considère que les constructeurs non explicit et les fonctions de conversion définies par l'utilisateur non explicites, tandis que l'initialisation directe considère tous les constructeurs et toutes les fonctions de conversion définies par l'utilisateur.

En cas d'ambiguïté entre une déclaration de variable utilisant la syntaxe d'initialisation directe (1) (avec des parenthèses rondes) et une déclaration de fonction, le compilateur choisit toujours la déclaration de fonction. Cette règle de désambiguïsation est parfois contre-intuitive et a été appelée le most vexing parse.

#include <fstream>
#include <iterator>
#include <string>

int main()
{
    std::ifstream file("data.txt");

    // Ce qui suit est une déclaration de fonction :
    std::string foo1(std::istreambuf_iterator<char>(file),
                     std::istreambuf_iterator<char>());
    // Elle déclare une fonction nommée foo1, dont le type de retour est std::string,
    // le premier paramètre a pour type std::istreambuf_iterator<char> et le nom « file »,
    // le second paramètre n'a pas de nom et a pour type std::istreambuf_iterator<char>(),
    // qui est réécrit en le type de pointeur de fonction std::istreambuf_iterator<char>(*)()

    // Correctif pré-C++11 (pour déclarer une variable) : ajouter des parenthèses supplémentaires autour de l'un
    // des arguments :
    std::string str1((std::istreambuf_iterator<char>(file)),
                      std::istreambuf_iterator<char>());

    // Correctif post-C++11 (pour déclarer une variable) : utiliser l'initialisation par liste pour tout
    // des arguments :
    std::string str2(std::istreambuf_iterator<char>{file}, {});
}

Exemple

#include <iostream>
#include <memory>
#include <string>

struct Foo
{
    int mem;
    explicit Foo(int n) : mem(n) {}
};

int main()
{
    std::string s1("test"); // constructeur prenant un const char*
    std::string s2(10, 'a');

    std::unique_ptr<int> p(new int(1));  // OK : les constructeurs explicites sont autorisés
//  std::unique_ptr<int> p = new int(1); // erreur : le constructeur est explicite

    Foo f(2); // f est initialisé directement :
              // le paramètre de constructeur n est initialisé par copie à partir de la rvalue 2
              // f.mem est initialisé directement à partir du paramètre n
//  Foo f2 = 2; // erreur : le constructeur est explicite

    std::cout << s1 << ' ' << s2 << ' ' << *p << ' ' << f.mem  << '\n';
}

Output:

test aaaaaaaaaa 1 2
