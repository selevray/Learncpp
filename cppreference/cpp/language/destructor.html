Destructeurs

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un destructeur est une fonction membre spéciale appelée lorsque la durée de vie d'un objet prend fin. Le rôle du destructeur est de libérer les ressources que l'objet a pu acquérir pendant sa durée de vie.

Un destructeur ne peut pas être une coroutine.

(depuis C++20)

Les seuls spécificateurs autorisés dans les spécificateurs de déclaration d'une déclaration de destructeur prospectif (depuis C++20) sont constexpr, (depuis C++11) friend, inline et virtual (en particulier, aucun type de retour n'est autorisé).

L'expression d'identifiant de class-name-with-tilde doit avoir l'une des formes suivantes :

  • Dans une déclaration de membre qui appartient à la spécification de membres d'une classe ou d'un modèle de classe, mais qui n'est pas une déclaration d'amie :

    • Pour les classes, l'expression d'identifiant est ~ suivi du nom de classe injecté de la classe immédiatement englobante.
    • Pour les modèles de classe, l'expression d'identifiant est ~ suivi de [un nom de classe désignant la instanciation courante (jusqu'à C++20) | le nom de classe injecté (depuis C++20)] du modèle de classe immédiatement englobant.

  • Sinon, l'expression d'identifiant est un identifiant qualifié dont l'identifiant non qualifié terminal est ~ suivi du nom de classe injecté de la classe désignée par les parties non terminales de l'identifiant qualifié.

Explication

Le destructeur est invoqué implicitement chaque fois que la durée de vie d'un objet prend fin, ce qui inclut

  • fin du programme, pour les objets à durée de stockage statique
  • fin du thread, pour les objets à durée de stockage thread-local

(depuis C++11)

  • fin de portée, pour les objets à durée de stockage automatique et pour les temporaires dont la durée de vie a été prolongée par liaison à une référence
  • expression delete, pour les objets à durée de stockage dynamique
  • fin de la expression complète, pour les temporaires sans nom
  • déroulement de la pile, pour les objets à durée de stockage automatique lorsqu'une exception sort de leur bloc sans être capturée.

Le destructeur peut aussi être invoqué explicitement.

Destructeur potentiellement invoqué

Un destructeur d'une classe C est potentiellement invoqué dans les situations suivantes :

  • Il est invoqué explicitement ou implicitement.
  • Une new expression crée un tableau d'objets de type C.
  • L'objet résultat d'une return instruction est de type C.
  • Un tableau est sous initialisation agrégative, et son type d'élément est C.
  • Un objet de classe est sous initialisation agrégative et possède un membre de type C où C n'est pas un type union anonyme.
  • Un sous-objet potentiellement construit est de type C dans un constructeurnon-délégant (depuis C++11).
  • Un objet d'exception de type C est construit.

Si un destructeur potentiellement invoqué estsupprimé ou (depuis C++11) non accessible depuis le contexte de l'invocation, le programme est mal formé.

Destructeur prospectif

Une classe peut avoir un ou plusieurs destructeurs prospectifs, dont l'un est sélectionné comme destructeur de la classe.

Pour déterminer quel destructeur prospectif est le destructeur, à la fin de la définition de la classe, une résolution de surcharge est effectuée parmi les destructeurs prospectifs déclarés dans la classe avec une liste d'arguments vide. Si la résolution de surcharge échoue, le programme est mal formé. La sélection du destructeur n'effectue pas d'odr-use sur le destructeur sélectionné, et le destructeur sélectionné peut être supprimé.

Tous les destructeurs prospectifs sont des fonctions membres spéciales. Si aucun destructeur prospectif déclaré par l'utilisateur n'est fourni pour la classe T, le compilateur en déclarera toujours un (voir ci-dessous), et le destructeur prospectif implicitement déclaré est également le destructeur de T.

(depuis C++20)

Destructeur implicitement déclaré

Si aucun destructeurprospectif (depuis C++20) déclaré par l'utilisateur n'est fourni pour un type classe, le compilateur déclarera toujours un destructeur comme inline public membre de sa classe.

Comme pour toute fonction membre spéciale implicitement déclarée, la spécification d'exception du destructeur implicitement déclaré est non lançante, sauf si [le destructeur de tout sous-objet de base ou membre potentiellement construit est potentiellement lanceur (depuis C++17) | la définition implicite invoquerait directement une fonction avec une spécification d'exception différente (jusqu'à C++17)]. En pratique, les destructeurs implicites sont noexcept, sauf si la classe est « empoisonnée » par une base ou un membre dont le destructeur est noexcept(false).

Destructeur implicitement défini

Si un destructeur implicitement déclaré n'est pas supprimé, il est implicitement défini (c'est-à-dire qu'un corps de fonction est généré et compilé) par le compilateur lorsqu'il est utilisé en odr. Ce destructeur implicitement défini a un corps vide.

Si cela satisfait les exigences d'un [destructeur constexpr (jusqu'à C++23) | fonction constexpr (depuis C++23)], le destructeur généré est constexpr.

(depuis C++20)

Destructeur supprimé

Le destructeur implicitement déclaré ou explicitement défaut de la classe T est [non défini (jusqu'à C++11) | défini comme supprimé (depuis C++11)] si l'une des conditions suivantes est satisfaite :

  • T possède un sous-objet potentiellement construit de type classe M (ou éventuellement un tableau multidimensionnel de celui-ci) tel que M possède un destructeur qui

    • est supprimé ou non accessible depuis le destructeur de T, ou
    • dans le cas où le sous-objet est un membre variant, est non trivial.

  • Le destructeur est virtuel et la recherche de la fonction de désallocation aboutit à

    • une ambiguïté, ou
    • une fonction supprimée ou non accessible depuis le destructeur.

Un destructeur prospectif explicitement défaut pour T est défini comme supprimé s'il n'est pas le destructeur de T.

(depuis C++20)

Destructeur trivial

Le destructeur de la classe T est trivial si toutes les conditions suivantes sont vraies :

  • Le destructeur n'est pas fourni par l'utilisateur (c'est-à-dire qu'il est soit implicitement déclaré, soit explicitement défini comme défaut à sa première déclaration).
  • Le destructeur n'est pas virtuel (c'est-à-dire que le destructeur de la classe de base n'est pas virtuel).
  • Toutes les classes de base directes ont des destructeurs triviaux.
  • Tous les membres de données non statiques de type classe (ou de tableau de type classe) ont des destructeurs triviaux.

Un destructeur trivial est un destructeur qui n'effectue aucune action. Les objets dotés de destructeurs triviaux n'exigent pas d'expression delete et peuvent être éliminés en désallouant simplement leur stockage. Tous les types de données compatibles avec le langage C (types POD) sont trivialement destructibles.

Séquence de destruction

Pour les destructeurs définis par l'utilisateur ou implicitement définis, après l'exécution du corps du destructeur et la destruction des objets automatiques alloués dans le corps, le compilateur appelle les destructeurs de tous les membres de données non statiques non variants de la classe, dans l'ordre inverse de leur déclaration, puis appelle les destructeurs de toutes les classes de base directes non virtuelles dans l'ordre inverse de construction (qui appellent à leur tour les destructeurs de leurs membres et de leurs classes de base, etc.), puis, si cet objet est de la classe la plus dérivée, appelle les destructeurs de toutes les bases virtuelles.

Même lorsque le destructeur est appelé directement (par ex. obj.~Foo();), l'instruction return dans ~Foo() ne rend pas immédiatement le contrôle à l'appelant : elle appelle d'abord tous les destructeurs des membres et des bases.

Destructeurs virtuels

Supprimer un objet via un pointeur sur la base provoque un comportement indéfini, sauf si le destructeur de la classe de base est virtuel :

class Base
{
public:
    virtual ~Base() {}
};

class Derived : public Base {};

Base* b = new Derived;
delete b; // safe

Une règle courante veut qu'un destructeur d'une classe de base soit soit public et virtuel, soit protégé et non virtuel.

Destructeurs virtuels purs

Un destructeur prospectif (depuis C++20) peut être déclaré virtuel pur, par exemple dans une classe de base qui doit être rendue abstraite mais n'a pas d'autres fonctions appropriées qui pourraient être déclarées virtuelles pures. Un destructeur virtuel pur doit avoir une définition, car tous les destructeurs des classes de base sont toujours appelés lorsque la classe dérivée est détruite :

class AbstractBase
{
public:
    virtual ~AbstractBase() = 0;
};
AbstractBase::~AbstractBase() {}

class Derived : public AbstractBase {};

// AbstractBase obj; // erreur du compilateur
Derived obj;         // OK

Exceptions

Comme toute autre fonction, un destructeur peut se terminer en lançant une exception (cela exige généralement de le déclarer explicitement noexcept(false)) (depuis C++11), cependant si ce destructeur est appelé pendant le déroulement de la pile, std::terminate est appelée à la place.

Bien que std::uncaught_exceptions puisse parfois être utilisé pour détecter un déroulement de pile en cours, il est généralement considéré comme une mauvaise pratique de permettre à un destructeur de se terminer en lançant une exception. Cette fonctionnalité est néanmoins utilisée par certaines bibliothèques, telles que SOCI et Galera 3, qui reposent sur la capacité des destructeurs de temporaires sans nom à lancer des exceptions à la fin de l'expression complète qui construit le temporaire.

std::experimental::scope_success dans la TS Library fundamental v3 peut avoir un destructeur potentiellement lanceur, qui lance une exception lorsque la portée est quittée normalement et que la fonction de sortie lance une exception.

Notes

Appeler directement un destructeur pour un objet ordinaire, tel qu'une variable locale, provoque un comportement indéfini lorsque le destructeur est appelé de nouveau à la fin de la portée.

Dans des contextes génériques, la syntaxe d'appel de destructeur peut être utilisée avec un objet de type non classe ; c'est ce qu'on appelle un appel de pseudo-destructeur : voir opérateur d'accès membre.

Exemple

#include <iostream>

struct A
{
    int i;

    A(int num) : i(num)
    {
        std::cout << "ctor a" << i << '\n';
    }

    ~A()
    {
        std::cout << "dtor a" << i << '\n';
    }
};

A a0(0);

int main()
{
    A a1(1);
    A* p;

    { // portée imbriquée
        A a2(2);
        p = new A(3);
    } // a2 hors de portée

    delete p; // appelle le destructeur de a3
}

Output:

ctor a0
ctor a1
ctor a2
ctor a3
dtor a2
dtor a3
dtor a1
dtor a0
