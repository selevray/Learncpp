Conversion dynamic_cast

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Convertit en toute sécurité des pointeurs et des références vers des classes vers le haut, vers le bas et latéralement dans la hiérarchie d'héritage.

Syntaxe

| | | | dynamic_cast< target-type >( expression ) | | | |

  • target-type — pointeur vers un type de classe complet, référence vers un type de classe complet, ou pointeur vers void (éventuellement qualifié cv)
  • expression — [lvalue (jusqu'à C++11) | glvalue (depuis C++11)] d'un type de classe complet si target-type est une référence, prvalue d'un pointeur vers un type de classe complet si target-type est un pointeur

Explication

Pour la commodité de la description, « expression ou le résultat est une référence vers T » signifie que « c'est une glvalue de type T », ce qui suit la convention de decltype (depuis C++11).

Seules les conversions suivantes peuvent être effectuées avec dynamic_cast, sauf lorsque ces conversions supprimeraient la constness (ou la volatilité).

  1. Si le type de expression est exactement target-type ou une version moins qualifiée cv de target-type, le résultat est la valeur de expression de type target-type.[1]

  2. Si target-type est « pointeur vers Base (éventuellement qualifié cv) » et que le type de expression est « pointeur vers Derived (éventuellement qualifié cv) » tel que Base est une classe de base de Derived, le résultat est

  • une valeur de pointeur nulle si expression est une valeur de pointeur nulle, ou
  • sinon, un pointeur vers le sous-objet unique Base de l'objet Derived pointé par expression.[2]

  1. Si target-type est « référence vers Base (éventuellement qualifié cv) » et que le type de expression est « Derived (éventuellement qualifié cv) » tel que Base est une classe de base de Derived, le résultat est le sous-objet Base unique de l'objet Derived référencé par expression.[2]

  2. Sinon, expression est un pointeur ou une référence vers un type polymorphe.

a) Si expression est un pointeur :

i) Si expression est une valeur de pointeur nulle, le résultat est la valeur de pointeur nulle de type target-type.

ii) Sinon, si target-type est « pointeur vers void (éventuellement qualifié cv) », le résultat est un pointeur vers l'objet le plus dérivé pointé par expression.

iii) Sinon, si le type de expression est « pointeur vers U (éventuellement qualifié cv) », expression doit pointer vers un objet dont le type est similaire à U et qui se trouve dans sa durée de vie ou dans sa période de construction ou de destruction, sinon le comportement est indéfini.

b) Si le type de expression est « référence vers U (éventuellement qualifié cv) », expression doit désigner un objet dont le type est similaire à U et qui se trouve dans sa durée de vie ou dans sa période de construction ou de destruction, sinon le comportement est indéfini.

c) Sinon (expression pointe ou désigne un objet valide), une vérification à l'exécution est effectuée pour déterminer si l'objet pointé ou désigné par expression peut être converti vers le type pointé ou désigné par target-type.

Soit C le type de classe vers lequel target-type pointe ou qu'il désigne. La vérification à l'exécution s'effectue logiquement comme suit :

i) Si, dans l'objet le plus dérivé pointé ou désigné par expression, expression pointe ou désigne un sous-objet de classe de base publique d'un objet C, et si un seul objet de type C dérive du sous-objet pointé ou désigné par expression, le résultat pointe ou désigne cet objet C.[3]

ii) Sinon, si expression pointe ou désigne un sous-objet de classe de base publique de l'objet le plus dérivé, et que le type de l'objet le plus dérivé possède une classe de base publique et non ambiguë de type C, le résultat pointe ou désigne le sous-objet C de l'objet le plus dérivé.[4]

iii) Sinon, la vérification à l'exécution échoue.

  • Si target-type est un type pointeur, le résultat est la valeur de pointeur nulle de target-type.
  • Si target-type est un type référence, une exception d'un type correspondant à un gestionnaire de type std::bad_cast est levée.

Lorsque dynamic_cast est utilisé dans un constructeur ou un destructeur (directement ou indirectement), et que expression désigne l'objet en cours de construction ou de destruction, l'objet est considéré comme l'objet le plus dérivé. Si target-type n'est pas un pointeur ou une référence vers la classe propre du constructeur ou du destructeur, ou vers l'une de ses bases, le comportement est indéfini.

  1. ↑ Autrement dit, dynamic_cast permet d'ajouter la qualification const. Une conversion implicite et static_cast peuvent aussi effectuer cette conversion.
  2. ↑ 2.0 2.1 Une conversion implicite et static_cast peuvent aussi effectuer cette conversion.
  3. ↑ Ceci est appelé « downcast » (conversion descendante).
  4. ↑ Ceci est appelé « sidecast » (conversion latérale).

Comme pour les autres expressions de conversion, le résultat est :

  • une lvalue si target-type est un type référence
  • une rvalue si target-type est un type pointeur

(jusqu'à C++11)

  • une lvalue si target-type est un type référence lvalue (expression doit être une lvalue)
  • une xvalue si target-type est un type référence rvalue (expression [peut être une lvalue ou une rvalue (jusqu'à C++17) | doit être une glvalue (les prvalues sont matérialisées) (depuis C++17)] d'un type de classe complet)
  • une prvalue si target-type est un type pointeur

(depuis C++11)

Notes

Un downcast peut aussi être effectué avec static_cast, ce qui évite le coût de la vérification à l'exécution, mais il n'est sûr que si le programme peut garantir (par une autre logique) que l'objet pointé par expression est bien Derived.

Certaines formes de dynamic_cast reposent sur l'identification de type à l'exécution (RTTI), c'est-à-dire sur des informations concernant chaque classe polymorphe du programme compilé. Les compilateurs proposent généralement des options pour désactiver l'inclusion de ces informations.

Mots-clés

dynamic_cast

Exemple

#include <iostream>

struct V
{
    virtual void f() {} // doit être polymorphe pour utiliser dynamic_cast avec vérification à l'exécution
};

struct A : virtual V {};

struct B : virtual V
{
    B(V* v, A* a)
    {
        // conversions pendant la construction (voir l'appel dans le constructeur de D ci-dessous)
        dynamic_cast<B*>(v); // bien défini : v de type V*, V base de B, donne B*
        dynamic_cast<B*>(a); // comportement indéfini : a est de type A*, A n'étant pas une base de B
    }
};

struct D : A, B
{
    D() : B(static_cast<A*>(this), this) {}
};

struct Base
{
    virtual ~Base() {}
};

struct Derived : Base
{
    virtual void name() {}
};

int main()
{
    D d; // l'objet le plus dérivé
    A& a = d; // conversion ascendante, dynamic_cast peut être utilisé, mais est inutile

    [[maybe_unused]]
    D& new_d = dynamic_cast<D&>(a); // downcast
    [[maybe_unused]]
    B& new_b = dynamic_cast<B&>(a); // sidecast

    Base* b1 = new Base;
    if (Derived* d = dynamic_cast<Derived*>(b1); d != nullptr)
    {
        std::cout << "downcast from b1 to d successful\n";
        d->name(); // sûr à appeler
    }

    Base* b2 = new Derived;
    if (Derived* d = dynamic_cast<Derived*>(b2); d != nullptr)
    {
        std::cout << "downcast from b2 to d successful\n";
        d->name(); // sûr à appeler
    }

    delete b1;
    delete b2;
}

Output:

downcast from b2 to d successful
