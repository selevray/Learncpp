Opérateur d'affectation par déplacement

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un opérateur d'affectation par déplacement est une fonction membre non statique non modèle, portant le nom operator=, qui peut être appelée avec un argument du même type de classe et copie le contenu de l'argument, en le modifiant éventuellement.

Syntaxe

Pour la syntaxe formelle de l'opérateur d'affectation par déplacement, voir déclaration de fonction. La liste de syntaxes ci-dessous ne présente qu'un sous-ensemble de toutes les syntaxes valides de l'opérateur d'affectation par déplacement.

  • class-name — la classe dont l'opérateur d'affectation par déplacement est déclaré, le type de la classe est noté T dans les descriptions ci-dessous
  • parameter-list — une liste de paramètres ne comportant qu'un seul paramètre, de type T&&, const T&&, volatile T&& ou const volatile T&&
  • parameter-list-no-default — une liste de paramètres ne comportant qu'un seul paramètre, de type T&&, const T&&, volatile T&& ou const volatile T&&, et n'ayant pas d'argument par défaut
  • function-body — le corps de fonction de l'opérateur d'affectation par déplacement
  • return-type — tout type, mais T& est privilégié afin de rester cohérent avec les types scala

Explication

  1. Déclaration d'un opérateur d'affectation par déplacement à l'intérieur de la définition de classe.

2-4) Définition d'un opérateur d'affectation par déplacement à l'intérieur de la définition de classe.

  1. L'opérateur d'affectation par déplacement est explicitement défaut.

  2. L'opérateur d'affectation par déplacement est supprimé.

5,6) Définition d'un opérateur d'affectation par déplacement en dehors de la définition de classe (la classe doit contenir une déclaration (1)).

  1. L'opérateur d'affectation par déplacement est explicitement défaut.
struct X
{
    X& operator=(X&& other);    // opérateur d'affectation par déplacement
//  X operator=(const X other); // Erreur : type de paramètre incorrect
};

union Y
{
    // les opérateurs d'affectation par déplacement peuvent avoir des syntaxes non listées ci-dessus,
    // tant qu'ils respectent la syntaxe générale des déclarations de fonctions
    // et ne violent pas les restrictions listées ci-dessus
    auto operator=(Y&& other) -> Y&;       // OK : type de retour final
    Y& operator=(this Y&& self, Y& other); // OK : paramètre d'objet explicite
//  Y& operator=(Y&&, int num = 1);        // Erreur : possède d'autres paramètres qui ne sont pas des objets
};

L'opérateur d'affectation par déplacement est appelé chaque fois qu'il est sélectionné par la résolution de surcharge, par exemple lorsqu'un objet apparaît à gauche d'une expression d'affectation dont le membre droit est une rvalue du même type ou d'un type implicitement convertible.

Les opérateurs d'affectation par déplacement transfèrent généralement les ressources détenues par l'argument (par exemple des pointeurs vers des objets alloués dynamiquement, des descripteurs de fichiers, des sockets TCP, des handles de threads, etc.), plutôt que d'en faire des copies, et laissent l'argument dans un état valide mais par ailleurs indéterminé. Comme l'affectation par déplacement ne modifie pas la durée de vie de l'argument, le destructeur sera généralement appelé sur l'argument à un moment ultérieur. Par exemple, l'affectation par déplacement depuis un std::string ou depuis un std::vector peut avoir pour effet de laisser l'argument vide. Une affectation par déplacement est définie de manière moins, et non plus, restrictive que l'affectation ordinaire ; là où l'affectation ordinaire doit laisser deux copies des données à l'issue de l'opération, l'affectation par déplacement n'est tenue d'en laisser qu'une seule.

Opérateur d'affectation par déplacement implicitement déclaré

Si aucun opérateur d'affectation par déplacement défini par l'utilisateur n'est fourni pour un type classe, et que toutes les conditions suivantes sont vraies :

  • il n'existe aucun constructeur de copie déclaré par l'utilisateur ;
  • il n'existe aucun constructeur de déplacement déclaré par l'utilisateur ;
  • il n'existe aucun opérateur d'affectation par copie déclaré par l'utilisateur ;
  • il n'existe aucun destructeur déclaré par l'utilisateur,

alors le compilateur déclare un opérateur d'affectation par déplacement comme inline public membre de sa classe, avec la signature T& T::operator=(T&&).

Une classe peut posséder plusieurs opérateurs d'affectation par déplacement, par exemple à la fois T& T::operator=(const T&&) et T& T::operator=(T&&). Si certains opérateurs d'affectation par déplacement définis par l'utilisateur sont présents, l'utilisateur peut tout de même forcer la génération de l'opérateur d'affectation par déplacement déclaré implicitement à l'aide du mot-clé default.

L'opérateur d'affectation par déplacement déclaré implicitement possède une spécification d'exception décrite dans [spécification d'exception dynamique (jusqu'à C++17) | spécification noexcept (depuis C++17)].

Comme un opérateur d'affectation (par déplacement ou par copie) est toujours déclaré pour toute classe, l'opérateur d'affectation de la classe de base est toujours masqué. Si une déclaration using est utilisée pour importer l'opérateur d'affectation de la classe de base, et que le type de son argument pourrait être identique au type de l'argument de l'opérateur d'affectation implicite de la classe dérivée, la déclaration using est également masquée par la déclaration implicite.

Opérateur d'affectation par déplacement défini implicitement

Si l'opérateur d'affectation par déplacement déclaré implicitement n'est ni supprimé ni trivial, il est défini (c'est-à-dire qu'un corps de fonction est généré et compilé) par le compilateur si odr-usedou nécessaire à l'évaluation constante (depuis C++14).

Pour les types union, l'opérateur d'affectation par déplacement défini implicitement copie la représentation de l'objet (comme par std::memmove).

Pour les types classe qui ne sont pas des unions, l'opérateur d'affectation par déplacement effectue une affectation par déplacement membre par membre complète des sous-objets de base directs et des membres non statiques immédiats de l'objet, dans leur ordre de déclaration, en utilisant l'affectation intégrée pour les types scalaires, l'affectation par déplacement membre par membre pour les tableaux, et l'opérateur d'affectation par déplacement pour les types classe (appelé de manière non virtuelle).

L'opérateur d'affectation par déplacement défini implicitement pour une classe T est constexpr si

  • T est un type littéral, et
  • l'opérateur d'affectation sélectionné pour déplacer chaque sous-objet de base directe est une fonction constexpr, et
  • pour chaque membre de donnée non statique de T de type classe (ou tableau de ceux-ci), l'opérateur d'affectation sélectionné pour déplacer ce membre est une fonction constexpr.

(depuis C++14) (jusqu'à C++23)

L'opérateur d'affectation par déplacement défini implicitement pour une classe T est constexpr.

(depuis C++23)

Comme pour l'affectation par copie, il n'est pas spécifié si les sous-objets de classe de base virtuelle accessibles par plus d'un chemin dans le treillis d'héritage sont affectés plus d'une fois par l'opérateur d'affectation par déplacement défini implicitement :

struct V
{
    V& operator=(V&& other)
    {
        // celui-ci peut être appelé une ou deux fois
        // si appelé deux fois, 'other' est le sous-objet V tout juste déplacé
        return *this;
    }
};

struct A : virtual V {}; // operator= appelle V::operator=
struct B : virtual V {}; // operator= appelle V::operator=
struct C : B, A {};      // operator= appelle B::operator=, puis A::operator=
                         // mais ils ne peuvent appeler V::operator= qu'une seule fois

int main()
{
    C c1, c2;
    c2 = std::move(c1);
}

Opérateur d'affectation par déplacement supprimé

L'opérateur d'affectation par déplacement déclaré implicitement ou par défaut pour la classe T est défini comme supprimé si l'une des conditions suivantes est satisfaite :

  • T possède un membre de données non statique d'un type non classe qualifié const (ou d'un tableau multidimensionnel de ce type).
  • T possède un membre de données non statique de type référence.
  • T possède un sous-objet potentiellement construit de type classe M (ou tableau multidimensionnel de ceux-ci) tel que la résolution de surcharge appliquée pour trouver l'opérateur d'affectation par déplacement de M
    • ne produit aucun candidat utilisable, ou
    • dans le cas où le sous-objet est un membre variant, sélectionne une fonction non triviale.

Un opérateur d'affectation par déplacement déclaré implicitement et supprimé est ignoré par la résolution de surcharge.

Opérateur d'affectation par déplacement trivial

L'opérateur d'affectation par déplacement de la classe T est trivial si toutes les conditions suivantes sont vraies :

  • il n'est pas fourni par l'utilisateur (c'est-à-dire qu'il est défini implicitement ou par défaut) ;
  • T ne possède aucune fonction membre virtuelle ;
  • T ne possède aucune classe de base virtuelle ;
  • l'opérateur d'affectation par déplacement sélectionné pour chaque base directe de T est trivial ;
  • l'opérateur d'affectation par déplacement sélectionné pour chaque membre non statique de type classe (ou tableau de type classe) de T est trivial.

Un opérateur d'affectation par déplacement trivial effectue la même action qu'un opérateur d'affectation par copie trivial, c'est-à-dire qu'il copie la représentation de l'objet comme par std::memmove. Tous les types de données compatibles avec le langage C sont trivialement affectables par déplacement.

Opérateur d'affectation par déplacement éligible

Un opérateur d'affectation par déplacement est éligible s'il n'est pas supprimé.

(jusqu'à C++20)

Un opérateur d'affectation par déplacement est éligible si toutes les conditions suivantes sont satisfaites :

  • Il n'est pas supprimé.
  • Ses contraintes associées (le cas échéant) sont satisfaites.
  • Aucun opérateur d'affectation par déplacement dont les contraintes associées sont satisfaites n'est plus contraint.

(depuis C++20)

La trivialité des opérateurs d'affectation par déplacement éligibles détermine si la classe est un type trivialement copiable.

Notes

Si les opérateurs d'affectation par copie et par déplacement sont tous deux fournis, la résolution de surcharge sélectionne l'affectation par déplacement si l'argument est une rvalue (soit une prvalue comme un temporaire sans nom, soit une xvalue comme le résultat de std::move), et sélectionne l'affectation par copie si l'argument est une lvalue (objet nommé ou fonction/opérateur renvoyant une référence lvalue). Si seul l'opérateur d'affectation par copie est fourni, toutes les catégories d'arguments le sélectionnent (tant qu'il prend son argument par valeur ou par référence vers const, car les rvalues peuvent se lier à des références const), ce qui fait de l'affectation par copie le repli de l'affectation par déplacement lorsque le déplacement n'est pas disponible.

Il n'est pas spécifié si les sous-objets de classe de base virtuelle accessibles par plus d'un chemin dans le treillis d'héritage sont affectés plus d'une fois par l'opérateur d'affectation par déplacement défini implicitement (même règle pour l'affectation par copie).

Voir surcharge de l'opérateur d'affectation pour plus de détails sur le comportement attendu d'un opérateur d'affectation par déplacement défini par l'utilisateur.

Exemple

#include <iostream>
#include <string>
#include <utility>

struct A
{
    std::string s;

    A() : s("test") {}

    A(const A& o) : s(o.s) { std::cout << "move failed!\n"; }

    A(A&& o) : s(std::move(o.s)) {}

    A& operator=(const A& other)
    {
         s = other.s;
         std::cout << "copy assigned\n";
         return *this;
    }

    A& operator=(A&& other)
    {
         s = std::move(other.s);
         std::cout << "move assigned\n";
         return *this;
    }
};

A f(A a) { return a; }

struct B : A
{
    std::string s2;
    int n;
    // opérateur d'affectation par déplacement implicite B& B::operator=(B&&)
    // appelle l'opérateur d'affectation par déplacement de A
    // appelle l'opérateur d'affectation par déplacement de s2
    // et effectue une copie binaire de n
};

struct C : B
{
    ~C() {} // le destructeur empêche l'affectation par déplacement implicite
};

struct D : B
{
    D() {}
    ~D() {} // le destructeur empêcherait l'affectation par déplacement implicite
    D& operator=(D&&) = default; // forcer quand même une affectation par déplacement
};

int main()
{
    A a1, a2;
    std::cout << "Trying to move-assign A from rvalue temporary\n";
    a1 = f(A()); // affectation par déplacement depuis un temporaire rvalue
    std::cout << "Trying to move-assign A from xvalue\n";
    a2 = std::move(a1); // affectation par déplacement depuis une xvalue

    std::cout << "\nTrying to move-assign B\n";
    B b1, b2;
    std::cout << "Before move, b1.s = \"" << b1.s << "\"\n";
    b2 = std::move(b1); // appelle l'affectation par déplacement implicite
    std::cout << "After move, b1.s = \"" << b1.s << "\"\n";

    std::cout << "\nTrying to move-assign C\n";
    C c1, c2;
    c2 = std::move(c1); // appelle l'opérateur d'affectation par copie

    std::cout << "\nTrying to move-assign D\n";
    D d1, d2;
    d2 = std::move(d1);
}

Output:

Trying to move-assign A from rvalue temporary
move assigned
Trying to move-assign A from xvalue
move assigned

Trying to move-assign B
Before move, b1.s = "test"
move assigned
After move, b1.s = ""

Trying to move-assign C
copy assigned

Trying to move-assign D
move assigned
