Constructeurs par défaut

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un constructeur par défaut est un constructeur qui peut être appelé sans argument.

Syntaxe

  • class-name — la classe dont le constructeur par défaut est déclaré
  • parameter-list — une liste de paramètres dont tous les paramètres(sauf packs de paramètres) (depuis C++11) ont des arguments par défaut
  • function-body — le corps de fonction du constructeur par défaut

Explication

  1. Déclaration d'un constructeur par défaut à l'intérieur de la définition de classe.

2-4) Définition d'un constructeur par défaut à l'intérieur de la définition de classe.

  1. Le constructeur par défaut est explicitement defaulted.

  2. Le constructeur par défaut est supprimé.

5,6) Définition d'un constructeur par défaut en dehors de la définition de classe (la classe doit contenir une déclaration (1)).

  1. Le constructeur par défaut est explicitement defaulted.

Les constructeurs par défaut sont appelés lors des initialisations par défaut et des initialisations par valeur.

Constructeur par défaut déclaré implicitement

Si une classe ne possède aucun constructeur ni modèle de constructeur déclaré par l'utilisateur, le compilateur déclare implicitement un constructeur par défaut comme membre inline public de sa classe.

Le constructeur par défaut déclaré implicitement (ou defaulted lors de sa première déclaration) possède une spécification d'exception décrite dans [spécification d'exception dynamique (jusqu'à C++17) | spécification noexcept (depuis C++17)].

Constructeur par défaut défini implicitement

Si [le constructeur est déclaré implicitement (jusqu'à C++11) | le constructeur par défaut déclaré implicitement ou explicitement defaulted n'est pas défini comme supprimé (depuis C++11)], il est défini (c'est-à-dire qu'un corps de fonction est généré et compilé) par le compilateur si odr-usedou nécessaire à l'évaluation constante (depuis C++11), et il a le même effet qu'un constructeur défini par l'utilisateur avec un corps vide et une liste d'initialisation vide. Autrement dit, il appelle les constructeurs par défaut des bases et des membres non statiques de cette classe. Les types classes ayant un constructeur fourni par l'utilisateur vide peuvent être traités différemment de ceux ayant un constructeur par défaut défini implicitement lors de l'initialisation par valeur.

Si celui-ci satisfait aux exigences d'un [constructeur constexpr (jusqu'à C++23) | fonction constexpr (depuis C++23)], le constructeur généré est constexpr.

Si des constructeurs définis par l'utilisateur sont présents, l'utilisateur peut tout de même forcer la génération automatique d'un constructeur par défaut par le compilateur, qui aurait sinon été déclaré implicitement, à l'aide du mot-clé default.

(depuis C++11)

Constructeur par défaut supprimé

Le constructeur par défaut déclaré implicitementou explicitement defaulted (depuis C++11) de la classe T est [non défini (jusqu'à C++11) | défini comme supprimé (depuis C++11)] si l'une des conditions suivantes est remplie :

  • T est une union et tous ses membres variants sont de type qualifié const (ou éventuellement un tableau multidimensionnel de ce type).
  • T est une classe qui n'est pas une union et tous les membres de tout membre union anonyme sont de type qualifié const (ou éventuellement un tableau multidimensionnel de ce type).
  • T possède un membre de donnée non statique de type référencesans initialiseur par défaut (depuis C++11).
  • T possède un membre de donnée non statique, non variant, de type qualifié const (ou éventuellement un tableau multidimensionnel de ce type), qui n'est pas const-constructible par défautsans initialiseur de membre par défaut (depuis C++11).
  • T possède un sous-objet potentiellement construit de type classe M (ou éventuellement un tableau multidimensionnel de celui-ci) tel que
    • M possède un destructeur qui estsupprimé ou (depuis C++11) inaccessible depuis le constructeur par défaut, ou
    • toutes les conditions suivantes sont satisfaites :
  • Le sous-objet n'est pas un membre de donnée non statique avec un initialiseur par défaut.
  • Le sous-objet n'est pas un membre variant d'une union dont un autre membre de donnée non statique possède un initialiseur par défaut.

(depuis C++11)

  • La résolution de surcharge appliquée pour trouver le constructeur par défaut de M
    • ne produit aucun candidat utilisable, ou
    • dans le cas où le sous-objet est un membre variant, sélectionne une fonction non triviale.

Si aucun constructeur défini par l'utilisateur n'est présent et que le constructeur par défaut déclaré implicitement n'est pas trivial, l'utilisateur peut tout de même inhiber la génération automatique d'un constructeur par défaut défini implicitement par le compilateur à l'aide du mot-clé delete.

(depuis C++11)

Constructeur par défaut trivial

Le constructeur par défaut de la classe T est trivial (c'est-à-dire qu'il n'effectue aucune action) si toutes les conditions suivantes sont vraies :

  • Le constructeur n'est pas défini par l'utilisateur (c'est-à-dire qu'il est implicitement défini ou défini par défaut lors de sa première déclaration).
  • T n'a aucune fonction membre virtuelle.
  • T n'a aucune classe de base virtuelle.
  • T n'a aucun membre non statique avec des initialiseurs par défaut.

(depuis C++11)

  • Chaque base directe de T a un constructeur par défaut trivial.
  • Chaque membre non statique de type classe (ou tableau de ce type) a un constructeur par défaut trivial.

Un constructeur par défaut trivial est un constructeur qui n'effectue aucune action. Tous les types de données compatibles avec le langage C (types POD) sont trivialement constructibles par défaut.

Constructeur par défaut éligible

Un constructeur par défaut est éligible s'il est soit déclaré par l'utilisateur, soit à la fois implicitement déclaré et définissable.

(jusqu'à C++11)

Un constructeur par défaut est éligible s'il n'est pas supprimé.

(depuis C++11) (jusqu'à C++20)

Un constructeur par défaut est éligible si toutes les conditions suivantes sont satisfaites :

  • Il n'est pas supprimé.
  • Ses contraintes associées (le cas échéant) sont satisfaites.
  • Aucun constructeur par défaut dont les contraintes associées sont satisfaites n'est plus contraint.

(depuis C++20)

La trivialité des constructeurs par défaut éligibles détermine si la classe est un type à durée de vie implicite, et si la classe est un type trivial.

Exemple

struct A
{
    int x;
    A(int x = 1): x(x) {} // constructeur par défaut défini par l'utilisateur
};

struct B : A
{
    // B::B() est implicitement défini, appelle A::A()
};

struct C
{
    A a;
    // C::C() est implicitement défini, appelle A::A()
};

struct D : A
{
    D(int y) : A(y) {}
    // D::D() n'est pas déclaré car un autre constructeur existe
};

struct E : A
{
    E(int y) : A(y) {}
    E() = default; // défini explicitement par défaut, appelle A::A()
};

struct F
{
    int& ref; // membre référence
    const int c; // membre const
    // F::F() est implicitement défini comme supprimé
};

// constructeur de copie déclaré par l'utilisateur (défini par l'utilisateur, supprimé ou défini par défaut)
// empêche la génération implicite d'un constructeur par défaut

struct G
{
    G(const G&) {}
    // G::G() est implicitement défini comme supprimé
};

struct H
{
    H(const H&) = delete;
    // H::H() est implicitement défini comme supprimé
};

struct I
{
    I(const I&) = default;
    // I::I() est implicitement défini comme supprimé
};

int main()
{
    A a;
    B b;
    C c;
//  D d; // erreur de compilation
    E e;
//  F f; // erreur de compilation
//  G g; // erreur de compilation
//  H h; // erreur de compilation
//  I i; // erreur de compilation
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 1353 C++98 les conditions dans lesquelles les constructeurs par défaut implicitement déclarés sont indéfinis ne prenaient pas en compte les types tableaux multidimensionnels prendre en compte ces types
CWG 2084 C++11 les initialiseurs de membres par défaut n'avaient aucun effet sur le fait que un constructeur par défaut défini par défaut d'une union soit supprimé ils empêchent le constructeur par défaut défini par défaut d'être supprimé
CWG 2595 C++20 un constructeur par défaut n'était pas éligible s'il existait un autre constructeur par défaut plus contraint mais qui ne satisfaisait pas ses contraintes associées il peut être éligible dans ce cas
CWG 2871 C++98 un constructeur par défaut serait implicitement déclaré même s'il existe un modèle de constructeur déclaré par l'utilisateur aucune déclaration implicite dans ce cas
