noexcept spécificateur (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Précise si une fonction peut lever des exceptions.

Syntaxe

| | | | noexcept | (1) | | | | noexcept(expression) | (2) | | | | throw() | (3) | (obsolète en C++17) (supprimé en C++20) | |

  1. Identique à noexcept(true)

  2. Si expression s'évalue à true, la fonction est déclarée ne lever aucune exception. Un ( suivant noexcept fait toujours partie de cette forme (il ne peut jamais commencer un initialiseur).

  3. Identique à noexcept(true) (voir spécification dynamique d'exception pour sa sémantique avant C++17)

  • expression — expression constante convertie contextuellement de type bool

Explication

La spécification noexcept ne fait pas partie du type de fonction (tout comme la spécification dynamique d'exception) et ne peut apparaître que dans le cadre d'un déclarateur de lambda ou d'un déclarateur de fonction de niveau supérieur lors de la déclaration de fonctions, de variables, de membres de données non statiques de type fonction, de pointeurs vers fonction, de références vers fonction ou de pointeurs vers fonction membre, ainsi que lors de la déclaration d'un paramètre ou d'un type de retour dans l'une de ces déclarations qui se trouve être à son tour un pointeur ou une référence vers fonction. Elle ne peut pas apparaître dans une déclaration typedef ou d'alias de type.

void f() noexcept; // la fonction f() ne lève pas d'exception
void (*fp)() noexcept(false); // fp pointe vers une fonction qui peut lever une exception
void g(void pfa() noexcept);  // g prend un pointeur vers une fonction qui ne lève pas d'exception
// typedef int (*pf)() noexcept; // erreur

(jusqu'à C++17)

La spécification noexcept fait partie du type de fonction et peut apparaître dans n'importe quel déclarateur de fonction.

(depuis C++17)

Chaque fonction en C++ est soit ne levant pas d'exception, soit potentiellement levante :

  • les fonctions déclarées avec une spécification dynamique d'exception non vide

  • les fonctions déclarées sans le spécificateur noexcept, à l'exception de
    • destructeurs, sauf si le destructeur de toute base ou tout membre potentiellement construit est potentiellement levant (voir ci-dessous)
    • constructeurs par défaut, constructeurs de copie, constructeurs de déplacement implicitement déclarés ou défaut à leur première déclaration, sauf si
      • un constructeur d'une base ou d'un membre que la définition implicite du constructeur appellerait est potentiellement levant (voir ci-dessous)
      • une sous-expression de cette initialisation, comme une expression d'argument par défaut, est potentiellement levante (voir ci-dessous)
      • un initialiseur de membre par défaut (pour le constructeur par défaut uniquement) est potentiellement levant (voir ci-dessous)
    • les opérateurs d'affectation par copie, les opérateurs d'affectation par déplacement implicitement déclarés ou défaut à leur première déclaration, sauf si l'invocation de l'un des opérateurs d'affectation dans la définition implicite est potentiellement levante (voir ci-dessous)
  • les opérateurs de comparaison défaut à leur première déclaration, sauf si l'invocation de l'un des opérateurs de comparaison dans la définition implicite est potentiellement levante (voir ci-dessous)

  • les fonctions de désallocation

  • les fonctions qui ne lèvent pas d'exception sont toutes les autres (celles dont le spécificateur noexcept est expression dont l'expression true s'évalue à vrai, ainsi que les destructeurs, les fonctions membres spéciales par défaut et les fonctions de désallocation)

Les instanciations explicites peuvent utiliser le spécificateur noexcept, mais ce n'est pas obligatoire. Si elle est utilisée, la spécification d'exception doit être la même que pour toutes les autres déclarations. Un diagnostic n'est requis que si les spécifications d'exception ne sont pas identiques au sein d'une même unité de traduction.

Des fonctions ne différant que par leur spécification d'exception ne peuvent pas être surchargées (tout comme le type de retour, la spécification d'exception fait partie du type de fonction, mais non de la signature de fonction) (depuis C++17).

void f() noexcept;
void f(); // erreur : spécification d'exception différente
void g() noexcept(false);
void g(); // ok, les deux déclarations de g sont potentiellement lanceuses

Les pointeurs (y compris les pointeurs vers fonction membre) vers des fonctions ne levant pas d'exception [peuvent être affectés ou utilisés pour initialiser (jusqu'à C++17) | sont implicitement convertibles en (depuis C++17)] pointeurs vers des fonctions potentiellement levantes, mais pas l'inverse.

void ft(); // potentiellement lanceuse
void (*fn)() noexcept = ft; // error

Si une fonction virtuelle ne lève pas d'exception, toutes les déclarations, y compris la définition, de chaque redéfinition doivent également ne pas lever d'exception, à moins que la redéfinition ne soit définie comme supprimée :

struct B
{
    virtual void f() noexcept;
    virtual void g();
    virtual void h() noexcept = delete;
};

struct D: B
{
    void f();          // mal formé : D::f est potentiellement lanceuse, B::f ne l'est pas
    void g() noexcept; // OK
    void h() = delete; // OK
};

Les fonctions ne levant pas d'exception peuvent appeler des fonctions potentiellement levantes. Chaque fois qu'une exception est levée et que la recherche d'un gestionnaire atteint le bloc le plus externe d'une fonction ne levant pas d'exception, la fonction std::terminate est appelée :

extern void f(); // potentiellement lanceuse

void g() noexcept
{
    f();      // valide, même si f lève une exception
    throw 42; // valide, équivaut effectivement à un appel à std::terminate
}

La spécification d'exception d'une spécialisation de modèle de fonction n'est pas instanciée avec la déclaration de la fonction ; elle n'est instanciée que lorsqu'elle est nécessaire (comme défini ci-dessous).

La spécification d'exception d'une fonction membre spéciale implicitement déclarée n'est également évaluée que lorsqu'elle est nécessaire (en particulier, la déclaration implicite d'une fonction membre d'une classe dérivée n'exige pas que la spécification d'exception d'une fonction membre de base soit instanciée).

Lorsque la spécification noexcept d'une spécialisation de modèle de fonction est nécessaire, mais n'a pas encore été instanciée, les noms dépendants sont recherchés et tous les modèles utilisés dans expression sont instanciés comme pour la déclaration de la spécialisation.

Une spécification noexcept d'une fonction est considérée comme nécessaire dans les contextes suivants :

  • dans une expression, lorsque la fonction est sélectionnée par résolution de surcharge
  • la fonction est odr-used
  • la fonction serait odr-used mais apparaît dans un opérande non évalué
template<class T>
T f() noexcept(sizeof(T) < 4);

int main()
{
    decltype(f<void>()) *p; // f non évaluée, mais noexcept-spec est nécessaire
                            // erreur car l'instanciation de la spécification noexcept
                            // calcule sizeof(void)
}
  • la spécification est nécessaire pour être comparée à une autre déclaration de fonction (par exemple sur un remplaçant de fonction virtuelle ou sur une spécialisation explicite d'un modèle de fonction)
  • dans une définition de fonction
  • la spécification est nécessaire parce qu'une fonction membre spéciale par défaut doit la vérifier afin de décider de sa propre spécification d'exceptions (ce qui n'a lieu que lorsque la spécification de la fonction membre spéciale par défaut est, elle-même, nécessaire).

Définition formelle d'une expression potentiellement levante (utilisée pour déterminer la spécification d'exception par défaut des destructeurs, des constructeurs et des opérateurs d'affectation, comme décrit ci-dessus) :

Une expression e est potentiellement levante si :

  • e est un appel de fonction vers une fonction, un pointeur vers fonction ou un pointeur vers fonction membre potentiellement levant, sauf si e est une expression constante de cœur (jusqu'à C++17)
  • e effectue un appel implicite à une fonction potentiellement levante (comme un opérateur surchargé, une fonction d'allocation dans une expression new, un constructeur pour un argument de fonction, ou un destructeur si e est une expression complète)
  • e est une expression throw
  • e est une dynamic_cast qui convertit un type référence polymorphe
  • e est une expression typeid appliquée à un pointeur déréférencé vers un type polymorphe
  • e a une sous-expression immédiate potentiellement susceptible de lever une exception
struct A
{
    A(int = (A(5), 0)) noexcept;
    A(const A&) noexcept;
    A(A&&) noexcept;
    ~A();
};

struct B
{
    B() throw();
    B(const B&) = default; // la spécification d'exception implicite est noexcept(true)
    B(B&&, int = (throw Y(), 0)) noexcept;
    ~B() noexcept(false);
};

int n = 7;
struct D : public A, public B
{
    int * p = new int[n];
    // D::D() potentiellement lanceuse à cause de l'opérateur new
    // D::D(const D&) ne lève pas d'exception
    // D::D(D&&) potentiellement lanceuse : l'argument par défaut du constructeur de B peut lever une exception
    // D::~D() potentiellement lanceuse

    // note ; si A::~A() était virtuel, ce programme serait mal formé car un redéfinisseur
    // d'une fonction virtuelle non lanceuse ne peut pas être potentiellement lanceur
};

Notes

L'une des utilisations de la constante expression est (avec l'opérateur noexcept) de définir des modèles de fonctions qui déclarent noexcept pour certains types mais pas pour d'autres.

Notez qu'une spécification noexcept sur une fonction n'est pas une vérification à la compilation ; c'est simplement un moyen pour le programmeur d'indiquer au compilateur si une fonction doit ou non lever des exceptions. Le compilateur peut utiliser cette information pour activer certaines optimisations sur les fonctions non lanceuses, ainsi que pour activer l'opérateur noexcept, qui peut vérifier à la compilation si une expression particulière est déclarée lever des exceptions. Par exemple, les conteneurs comme std::vector déplaceront leurs éléments si le constructeur de déplacement de ces éléments est noexcept, et les copieront sinon (sauf si le constructeur de copie n'est pas accessible, mais qu'un constructeur de déplacement potentiellement lanceur l'est, auquel cas la garantie forte d'exception est abandonnée).

Obsolète

noexcept est une version améliorée de throw(), obsolète depuis C++11. Contrairement aux throw() antérieurs à C++17, noexcept n'appelle pas std::unexpected, peut ou non dérouler la pile, et appelle std::terminate, ce qui permet au compilateur d'implémenter noexcept sans la surcharge à l'exécution de throw(). Depuis C++17, throw() est redéfini comme un équivalent exact de noexcept(true).

Mots-clés

noexcept, throw (depuis C++17) (jusqu'à C++20)

Exemple

// que foo soit déclarée noexcept dépend de si l'expression
// T() lèvera-t-elle des exceptions
template<class T>
void foo() noexcept(noexcept(T())) {}

void bar() noexcept(true) {}
void baz() noexcept { throw 42; } // noexcept est équivalent à noexcept(true)

int main()
{
    foo<int>(); // noexcept(noexcept(int())) => noexcept(true), donc c'est correct

    bar(); // fine
    baz(); // compile, mais à l'exécution cela appelle std::terminate
}
