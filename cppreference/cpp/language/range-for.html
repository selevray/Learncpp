Boucle for basée sur un intervalle (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Exécute une boucle for sur un intervalle.

Utilisée comme équivalent plus lisible de la boucle for traditionnelle parcourant un intervalle de valeurs, comme tous les éléments d'un conteneur.

Syntaxe

| | | | attr ﻿*(facultatif)* for ( init-statement ﻿*(facultatif)* item-declaration : range-initializer ) statement | | | |

  • attr — un nombre quelconque d'attributs

  • init-statement — (depuis C++20) l'un des éléments suivants

    • une instruction d'expression (qui peut être une instruction nulle ;)
    • une déclaration simple (typiquement une déclaration de variable avec initialiseur), elle peut déclarer un nombre arbitraire de variables ou être une déclaration de liaison structurée
    • une déclaration d'alias

    (depuis C++23)

    Notez que toute init-statement doit se terminer par un point-virgule. C'est pourquoi on la décrit souvent informellement comme une expression ou une déclaration suivie d'un point-virgule.

  • item-declaration — une déclaration pour chaque élément de l'intervalle

  • range-initializer — une expression ou une liste d'initialisation entre accolades

  • statement — une instruction quelconque (typiquement une instruction composée)

Explication

La syntaxe ci-dessus produit un code équivalent au suivant à l'exception de l'extension de durée de vie des temporaires de range-initializer (voir ci-dessous) (depuis C++23) (les variables et expressions enveloppées dans /* */ sont uniquement à titre explicatif) :

for (auto /* begin */ = /* begin-expr */, /* end */ = /* end-expr */;
/* begin */ != /* end */; ++/* begin */)
{item-declaration = */* begin */;
statement
}

}

(depuis C++20)

range-initializer est évaluée pour initialiser la séquence ou l'intervalle à parcourir. Chaque élément de la séquence, à tour de rôle, est déréférencé et sert à initialiser la variable de type et de nom donnés dans item-declaration.

item-declaration peut être l'un des éléments suivants :

  • une déclaration simple avec les restrictions suivantes :
  • Elle n'a qu'un seul déclarateur.
  • Le déclarateur ne doit avoir aucun initialisateur.
  • La séquence de spécificateurs de déclaration ne peut contenir que des spécificateurs de type et constexpr, et elle ne peut pas définir de classe ni d'énumération.

Les expressions à titre explicatif /* begin-expr */ et /* end-expr */ sont définies comme suit :

  • Si le type de /* range */ est une référence à un type tableau R :

    • Si R est de borne N, /* begin-expr */ est /* range */ et /* end-expr */ est /* range */ + N.
    • Si R est un tableau de borne inconnue ou un tableau de type incomplet, le programme est mal formé.

  • Si le type de /* range */ est une référence à un type classe C, et que les recherches dans la portée de C pour les noms « begin » et « end » trouvent chacune au moins une déclaration, alors /* begin-expr */ est /* range */.begin() et /* end-expr */ est /* range */.end().

  • Sinon, /* begin-expr */ est begin(/* range */) et /* end-expr */ est end(/* range */), où « begin » et « end » sont trouvés via la recherche dépendante des arguments (la recherche non ADL n'est pas effectuée).

Si la boucle doit être interrompue à l'intérieur de statement, une instruction break peut être utilisée comme instruction de terminaison.

Si l'itération courante doit être interrompue à l'intérieur de statement, une instruction continue peut être utilisée comme raccourci.

Si un nom introduit dans init-statement est redéclaré dans le bloc le plus externe de statement, le programme est mal formé :

for (int i : {1, 2, 3})
    int i = 1; // error: redeclaration

Initialiseur d'intervalle temporaire

Si range-initializer renvoie un temporaire, sa durée de vie est prolongée jusqu'à la fin de la boucle, comme l'indique la liaison à la référence de transfert /* range */.

Les durées de vie de tous les temporaires dans range-initializer ne sont pas prolongéessauf s'ils devraient autrement être détruits à la fin de range-initializer (depuis C++23).

// si foo() renvoie par valeur
for (auto& x : foo().items()) { /* ... */ } // jusqu'à C++23 comportement indéfini

Ce problème peut être contourné en utilisant init-statement :

for (T thing = foo(); auto& x : thing.items()) { /* ... */ } // OK

(depuis C++20)

Notez que même en C++23, les paramètres non références des appels de fonction intermédiaires ne bénéficient pas d'une extension de durée de vie (car dans certaines ABI ils sont détruits dans l'appelé, et non dans l'appelant), mais cela ne pose problème que pour des fonctions de toute façon défectueuses :

using T = std::list<int>;
const T& f1(const T& t) { return t; }
const T& f2(T t)        { return t; } // renvoie toujours une référence pendante
T g();

void foo()
{
    for (auto e : f1(g())) {} // OK : durée de vie de la valeur de retour de g() prolongée
    for (auto e : f2(g())) {} // UB : durée de vie du paramètre par valeur de f2 se termine trop tôt
}

(depuis C++23)

Notes

Si le range-initializer est une liste d'initialisation entre accolades, /* range */ est déduit comme étant une référence à un std::initializer_list.

Il est sûr, et même préférable dans le code générique, d'utiliser la déduction vers une référence de transfert, for (auto&& var : sequence).

L'interprétation membre est utilisée si le type d'intervalle a un membre nommé « begin » et un membre nommé « end ». Cela se fait quel que soit le fait que le membre soit un type, un membre de données, une fonction ou un énumérateur, et quelle que soit son accessibilité. Ainsi, une classe comme class meow { enum { begin = 1, end = 2 }; /* reste de la classe */ }; ne peut pas être utilisée avec la boucle for basée sur un intervalle, même si les fonctions « begin »/« end » de portée d'espace de noms sont présentes.

Bien que la variable déclarée dans item-declaration soit généralement utilisée dans statement, cela n'est pas obligatoire.

Depuis C++17, les types de /* begin-expr */ et de /* end-expr */ n'ont pas besoin d'être identiques, et en fait le type de /* end-expr */ n'a pas besoin d'être un itérateur : il doit simplement pouvoir être comparé en inégalité avec un tel objet. Cela permet de délimiter un intervalle par un prédicat (par ex. « l'itérateur pointe sur un caractère nul »).

(depuis C++17)

Lorsqu'elle est utilisée avec un objet (non const) ayant une sémantique de copie sur écriture, la boucle for basée sur un intervalle peut déclencher une copie profonde par appel (implicite) de la fonction membre begin() non const.

Si cela est indésirable (par exemple parce que la boucle ne modifie pas réellement l'objet), cela peut être évité en utilisant std::as_const :

struct cow_string { /* ... */ }; // une chaîne à copie sur écriture
cow_string str = /* ... */;

// for (auto x : str) { /* ... */ } // peut provoquer une copie profonde

for (auto x : std::as_const(str)) { /* ... */ }

(depuis C++17)

Exemple

#include <iostream>
#include <vector>

int main()
{
    std::vector<int> v = {0, 1, 2, 3, 4, 5};

    for (const int& i : v) // accès par référence constante
        std::cout << i << ' ';
    std::cout << '\n';

    for (auto i : v) // accès par valeur, le type de i est int
        std::cout << i << ' ';
    std::cout << '\n';

    for (auto&& i : v) // accès par référence de transmission, le type de i est int&
        std::cout << i << ' ';
    std::cout << '\n';

    const auto& cv = v;

    for (auto&& i : cv) // accès par référence de transmission, le type de i est const int&
        std::cout << i << ' ';
    std::cout << '\n';

    for (int n : {0, 1, 2, 3, 4, 5}) // l'initialiseur peut être un
                                     // liste d'initialisation entre accolades
        std::cout << n << ' ';
    std::cout << '\n';

    int a[] = {0, 1, 2, 3, 4, 5};
    for (int n : a) // l'initialiseur peut être un tableau
        std::cout << n << ' ';
    std::cout << '\n';

    for ([[maybe_unused]] int n : a)
        std::cout << 1 << ' '; // la variable de boucle n'a pas besoin d'être utilisée
    std::cout << '\n';

    for (auto n = v.size(); auto i : v) // l'instruction d'initialisation (C++20)
        std::cout << --n + i << ' ';
    std::cout << '\n';

    for (typedef decltype(v)::value_type elem_t; elem_t i : v)
    // déclaration typedef comme instruction d'initialisation (C++20)
        std::cout << i << ' ';
    std::cout << '\n';

    for (using elem_t = decltype(v)::value_type; elem_t i : v)
    // déclaration d'alias comme instruction d'initialisation (C++23)
        std::cout << i << ' ';
    std::cout << '\n';
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 1442 C++11 il n'était pas spécifié si la recherche de « begin » et « end » non membres incluait la recherche habituelle non qualifiée pas de recherche habituelle non qualifiée
CWG 2220 C++11 les noms introduits dans init-statement pouvaient être redéclarés le programme est mal formé dans ce cas
CWG 2825 C++11 si range-initializer est une liste d'initialisation entre accolades, les fonctions non membres « begin » et « end » seront recherchées la recherche portera sur le membre « begin » et « end » dans ce cas
P0962R1 C++11 l'interprétation membre était utilisée si l'un ou l'autre membre « begin » et « end » est présent n'est utilisée que si les deux sont présents
