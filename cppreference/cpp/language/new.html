expression new

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Crée et initialise des objets à durée de stockage dynamique, c'est-à-dire des objets dont la durée de vie n'est pas nécessairement limitée à la portée dans laquelle ils ont été créés.

Syntaxe

1,2) Tente de créer un objet du type désigné par le type-id type, qui peut être un type tableau[, et peut inclure un spécificateur de type substitut (depuis C++11) | , ou inclure un nom de modèle de classe dont l'argument doit être déduit par la déduction des arguments de modèle de classe (depuis C++17)].

3,4) Identique à (1,2), mais fournit des arguments supplémentaires à la fonction d'allocation, voir placement new.

Explication

  • type — le type-id cible
  • new-initializer — une liste d'expressions entre parenthèsesou une liste d'initialisation entre accolades (depuis C++11)
  • placement-args — arguments de placement supplémentaires

L'expression new tente d'allouer du stockage, puis tente de construire et d'initialiser soit un unique objet anonyme, soit un tableau anonyme d'objets dans le stockage alloué. L'expression new renvoie un pointeur de type prvalue vers l'objet construit ou, si un tableau d'objets a été construit, un pointeur vers le premier élément du tableau.

La syntaxe (1) ou (3) est requise si type contient des parenthèses :

new int(*[10])();    // erreur : analysée comme (new int) (*[10]) ()
new (int (*[10])()); // correct : alloue un tableau de 10 pointeurs vers des fonctions

De plus, type est analysé de manière gourmande : il inclura chaque jeton pouvant faire partie d'un déclarateur :

new int + 1; // correct : analysée comme (new int) + 1, incrémente un pointeur renvoyé par new int
new int * 1; // erreur : analysée comme (new int*) (1)

new-initializer n'est pas facultatif si

  • type est un tableau de borne inconnue,
  • un placeholder est utilisé dans type, c'est-à-dire auto [ou decltype(auto) (depuis C++14) | , éventuellement combiné avec une contrainte de type (depuis C++20)],

(depuis C++11)

  • un modèle de classe est utilisé dans type dont les arguments doivent être déduits.

(depuis C++17)

double* p = new double[]{1, 2, 3}; // crée un tableau de type double[3]
auto p = new auto('c');            // crée un objet unique de type char. p est un char*

auto q = new std::integral auto(1);         // OK : q est un int*
auto q = new std::floating_point auto(true) // ERREUR : contrainte de type non satisfaite

auto r = new std::pair(1, true); // OK : r est un std::pair<int, bool>*
auto r = new std::vector;        // ERREUR : le type de l'élément ne peut pas être déduit

Tableaux dynamiques

Si type est un type tableau, toutes les dimensions autres que la première doivent être spécifiées comme [expressions constantes intégrales (jusqu'à C++14) | expression constante convertie de type std::size_t (depuis C++14)] positives, mais (uniquement lors de l'utilisation des syntaxes sans parenthèses (2) et (4)) la première dimension peut être [une expression de type entier, de type énumération, ou de type classe avec une unique fonction de conversion non explicite vers un type entier ou énumération (jusqu'à C++14) | toute expression convertible en std::size_t (depuis C++14)]. C'est le seul moyen de créer directement un tableau dont la taille est définie à l'exécution ; de tels tableaux sont souvent appelés tableaux dynamiques :

int n = 42;
double a[n][5]; // error
auto p1 = new  double[n][5];  // OK
auto p2 = new  double[5][n];  // erreur : seule la première dimension peut être non constante
auto p3 = new (double[n][5]); // erreur : la syntaxe (1) ne peut pas être utilisée pour les tableaux dynamiques

Le comportement est indéfini si la valeur de la première dimension (convertie en type entier ou énumération si nécessaire) est négative.

(jusqu'à C++11)

Dans les cas suivants, la valeur de l'expression spécifiant la première dimension est invalide :

  • l'expression est de type non classe et sa valeur avant conversion en std::size_t est négative ;
  • l'expression est de type classe et sa valeur après la fonction de conversion définie par l'utilisateur et avant la seconde conversion standard est négative ;
  • la valeur de l'expression est supérieure à une limite définie par l'implémentation ;
  • la valeur est inférieure au nombre d'éléments de tableau fournis dans la liste d'initialisation entre accolades (y compris le '\0' terminal d'un littéral de chaîne).

Si la valeur de la première dimension est invalide pour l'une de ces raisons,

  • si, après conversion en std::size_t, la première dimension est une expression constante du noyau et qu'elle est potentiellement évaluée, le programme est mal formé,
  • sinon, si la fonction d'allocation qui aurait été appelée ne lève pas d'exception (y compris les surcharges std::nothrow non déclarées noexcept), l'expression new renvoie le pointeur nul du type de résultat requis,
  • sinon, l'expression new n'appelle pas la fonction d'allocation et lève à la place une exception d'un type correspondant à un gestionnaire de type std::bad_array_new_length.

(depuis C++11)

Une dimension nulle est acceptable, et la fonction d'allocation est appelée.

Si new-initializer est une liste d'initialisation entre accolades, et que la première dimension est potentiellement évaluée et n'est pas une expression constante du noyau, les contraintes sémantiques de l'initialisation par copie d'un élément hypothétique du tableau à partir d'une liste d'initialisation vide sont vérifiées.

(depuis C++11)

Allocation

L'expression new alloue du stockage en appelant la fonction d'allocation appropriée. Si type est un type non tableau, le nom de la fonction est operator new. Si type est un type tableau, le nom de la fonction est operator new[].

Comme décrit dans fonction d'allocation, le programme C++ peut fournir des remplacements globaux et spécifiques à la classe pour ces fonctions. Si l'expression new commence par l'opérateur optionnel ::, comme dans ::new T ou ::new T[n], les remplacements spécifiques à la classe sont ignorés (la fonction est recherchée dans la portée globale). Sinon, si T est un type classe, la recherche commence dans la portée de classe de T.

Lors de l'appel de la fonction d'allocation, l'expression new passe le nombre d'octets demandé comme premier argument, de type std::size_t, qui vaut exactement sizeof(T) pour T non tableau.

L'allocation de tableau peut ajouter un surcoût non spécifié, qui peut varier d'un appel de new à l'autre, sauf si la fonction d'allocation choisie est la forme standard non allocatrice. Le pointeur renvoyé par l'expression new sera décalé de cette valeur par rapport au pointeur renvoyé par la fonction d'allocation. De nombreuses implémentations utilisent ce surcoût pour stocker le nombre d'objets du tableau, utilisé par l'expression delete[] pour appeler le bon nombre de destructeurs. De plus, si l'expression new est utilisée pour allouer un tableau de char, unsigned char, ou std::byte (depuis C++17), elle peut demander de la mémoire supplémentaire à la fonction d'allocation si nécessaire pour garantir un alignement correct des objets de tous les types non plus grands que la taille demandée du tableau, si l'un d'eux est ensuite placé dans le tableau alloué.

Les expressions new peuvent omettre ou combiner des allocations effectuées via des fonctions d'allocation remplaçables. En cas d'omission, le stockage peut être fourni par le compilateur sans appeler de fonction d'allocation (cela permet aussi d'optimiser une expression new inutilisée). En cas de combinaison, l'allocation effectuée par une expression new E1 peut être étendue pour fournir un stockage supplémentaire à une autre expression new E2 si toutes les conditions suivantes sont vraies :

  1. La durée de vie de l'objet alloué par E1 contient strictement la durée de vie de l'objet alloué par E2.

  2. E1 et E2 appelleraient la même fonction d'allocation globale remplaçable.

  3. Pour une fonction d'allocation pouvant lever une exception, les exceptions émises dans E1 et E2 seraient d'abord interceptées par le même gestionnaire.

Notez que cette optimisation n'est autorisée que lorsque des expressions new sont utilisées, et non d'autres méthodes d'appel d'une fonction d'allocation remplaçable : delete[] new int[10]; peut être optimisée, mais operator delete(operator new(10)); ne peut pas l'être.

(depuis C++14)

Lors de l'évaluation d'une expression constante, un appel à une fonction d'allocation est toujours omis. Seules les expressions new qui entraîneraient autrement un appel à une fonction d'allocation globale remplaçable peuvent être évaluées dans des expressions constantes.

(depuis C++20)

Placement new

Si placement-args sont fournis, ils sont transmis à la fonction d'allocation comme arguments supplémentaires. De telles fonctions d'allocation sont appelées « new de placement », d'après la fonction d'allocation standard void* operator new(std::size_t, void*), qui renvoie simplement son second argument sans modification. Ceci est utilisé pour construire des objets dans un espace de stockage alloué :

// à l'intérieur de n'importe quelle portée de bloc...
{
    // Allouer statiquement le stockage avec une durée de stockage automatique
    // qui est suffisamment grand pour n'importe quel objet de type « T ».
    alignas(T) unsigned char buf[sizeof(T)];

    T* tptr = new(buf) T; // Construire un objet « T », en le plaçant directement dans votre
                          // stockage pré-alloué à l'adresse mémoire « buf ».

    tptr->~T();           // Vous devez appeler **manuellement** le destructeur de l'objet
                          // si ses effets de bord sont utilisés par le programme.
}                         // Quitter cette portée de bloc désalloue automatiquement « buf ».

Remarque : cette fonctionnalité est encapsulée par les fonctions membres des classes Allocator.

Lors de l'allocation d'un objet dont l'exigence d'alignement dépasse __STDCPP_DEFAULT_NEW_ALIGNMENT__, ou d'un tableau de tels objets, l'expression new transmet l'exigence d'alignement (enveloppée dans std::align_val_t) comme second argument de la fonction d'allocation (pour les formes de placement, placement-arg apparaissent après l'alignement, comme troisième, quatrième, etc. arguments). Si la résolution de surcharge échoue (ce qui se produit lorsqu'une fonction d'allocation spécifique à la classe est définie avec une signature différente, car elle masque les globales), la résolution de surcharge est tentée une seconde fois, sans l'alignement dans la liste d'arguments. Cela permet aux fonctions d'allocation spécifiques à la classe, ignorantes de l'alignement, de prendre le pas sur les fonctions d'allocation globales tenant compte de l'alignement.

(depuis C++17)

new T;      // appelle operator new(sizeof(T))
            // (C++17) ou operator new(sizeof(T), std::align_val_t(alignof(T))))
new T[5];   // appelle operator new[](sizeof(T)*5 + overhead)
            // (C++17) ou operator new(sizeof(T)*5+overhead, std::align_val_t(alignof(T))))
new(2,f) T; // appelle operator new(sizeof(T), 2, f)
            // (C++17) ou operator new(sizeof(T), std::align_val_t(alignof(T)), 2, f)

Si une fonction d'allocation ne levant pas d'exception (par exemple celle sélectionnée par new(std::nothrow) T) renvoie un pointeur nul à cause d'un échec d'allocation, alors l'expression new retourne immédiatement : elle ne tente ni d'initialiser un objet ni d'appeler une fonction de désallocation. Si un pointeur nul est passé comme argument à une expression new de placement sans allocation, ce qui fait renvoyer un pointeur nul à la fonction d'allocation de placement standard sans allocation sélectionnée, le comportement est indéfini.

Initialisation

L'objet créé par une expression new est initialisé selon les règles suivantes.

Si type n'est pas un type tableau, l'objet unique est construit dans la zone mémoire acquise :

  • Si new-initializer est absent, l'objet est initialisé par défaut.
  • Si new-initializer est une liste d'expressions entre parenthèses, l'objet est initialisé directement.
  • Si new-initializer est une liste d'initialisation entre accolades, l'objet est initialisé par liste.

(depuis C++11)

Si type est un type tableau, un tableau d'objets est initialisé :

  • Si new-initializer est absent, chaque élément est initialisé par défaut.

    • Même si la première dimension est nulle, les contraintes sémantiques d'initialisation par défaut d'un élément hypothétique doivent toujours être respectées.

  • Si new-initializer est une paire de parenthèses, chaque élément est initialisé par valeur.

    • Même si la première dimension est nulle, les contraintes sémantiques d'initialisation par valeur d'un élément hypothétique doivent toujours être respectées.
  • Si new-initializer est une liste d'initialisation entre accolades, le tableau est initialisé en agrégat.

(depuis C++11)

  • Si new-initializer est une liste d'expressions non vide entre parenthèses, le tableau est initialisé en agrégat.

(depuis C++20)

Échec de l'initialisation

Si l'initialisation se termine par le lancement d'une exception (par exemple depuis le constructeur), le programme recherche une fonction de désallocation correspondante, puis :

  • Si une fonction de désallocation appropriée est trouvée, celle-ci est appelée pour libérer la mémoire dans laquelle l'objet était en cours de construction. Ensuite, l'exception continue de se propager dans le contexte de l'expression new.
  • Si aucune fonction de désallocation correspondante et non ambiguë n'est trouvée, la propagation de l'exception n'entraîne pas la libération de la mémoire de l'objet. Cela n'est approprié que si la fonction d'allocation appelée n'alloue pas de mémoire ; dans le cas contraire, cela risque de provoquer une fuite mémoire.

La portée de la recherche de la fonction de désallocation correspondante est déterminée comme suit :

  • Si l'expression new ne commence pas par ::, et que le type alloué est soit un type classe T, soit un tableau de type classe T, une recherche du nom de la fonction de désallocation est effectuée dans la portée de classe de T.
  • Sinon, ou si rien n'est trouvé dans la portée de classe de T, le nom de la fonction de désallocation est recherché dans la portée globale.

Pour une fonction d'allocation sans placement, la recherche normale de fonction de désallocation est utilisée pour trouver la fonction de désallocation correspondante (voir expression delete).

Pour une fonction d'allocation de placement, la fonction de désallocation correspondante doit avoir le même nombre de paramètres, et chaque type de paramètre, à l'exception du premier, doit être identique au type de paramètre correspondant de la fonction d'allocation (après transformations des paramètres).

  • Si la recherche trouve une seule fonction de désallocation correspondante, cette fonction sera appelée ; sinon, aucune fonction de désallocation ne sera appelée.
  • Si la recherche trouve une fonction de désallocation sans placement et que cette fonction, considérée comme une fonction de désallocation de placement, aurait été retenue comme correspondance pour la fonction d'allocation, le programme est mal formé.

Dans tous les cas, la fonction de désallocation correspondante (s'il y en a une) doit être non supprimée et (depuis C++11) accessible depuis le point où apparaît l'expression new.

struct S
{
    // Fonction d'allocation de placement :
    static void* operator new(std::size_t, std::size_t);

    // Fonction de désallocation sans placement :
    static void operator delete(void*, std::size_t);
};

S* p = new (0) S; // erreur : une fonction de désallocation sans placement correspond
                  //        fonction d'allocation de placement

Si une fonction de désallocation est appelée dans une expression new (suite à un échec d'initialisation), les arguments passés à cette fonction sont déterminés comme suit :

  • Le premier argument est la valeur (de type void*) renvoyée par l'appel à la fonction d'allocation.
  • Les autres arguments (uniquement pour les fonctions de désallocation de placement) sont les placement-args passés à la fonction d'allocation de placement.

Si l'implémentation est autorisée à introduire un objet temporaire ou à faire une copie de l'un des arguments lors de l'appel à la fonction d'allocation, il n'est pas spécifié si le même objet est utilisé dans l'appel aux fonctions d'allocation et de désallocation.

Fuites mémoire

Les objets créés par les expressions new (objets à durée de stockage dynamique) persistent jusqu'à ce que le pointeur renvoyé par l'expression new soit utilisé dans une expression delete correspondante. Si la valeur d'origine du pointeur est perdue, l'objet devient inaccessible et ne peut plus être désalloué : une fuite mémoire se produit.

Cela peut se produire si le pointeur est affecté à :

int* p = new int(7); // int alloué dynamiquement avec la valeur 7
p = nullptr; // fuite de mémoire

ou si le pointeur sort de sa portée :

void f()
{
    int* p = new int(7);
} // fuite de mémoire

ou à cause d'une exception :

void f()
{
    int* p = new int(7);
    g();      // peut lever une exception
    delete p; // correct si aucune exception
} // fuite de mémoire si g() lève une exception

Pour simplifier la gestion des objets alloués dynamiquement, le résultat d'une expression new est souvent stocké dans un pointeur intelligent : [std::auto_ptr (jusqu'à C++17) | std::unique_ptr, ou std::shared_ptr (depuis C++11)]. Ces pointeurs garantissent que l'expression delete est exécutée dans les situations présentées ci-dessus.

Notes

L'ABI Itanium C++ exige que le surcoût d'allocation d'un tableau soit nul si le type d'élément du tableau créé est trivialement destructible. MSVC le fait aussi.

Certaines implémentations (par exemple MSVC avant VS 2019 v16.7) exigent un surcoût d'allocation non nul pour une expression new de tableau de placement sans allocation si le type d'élément n'est pas trivialement destructible, ce qui n'est plus conforme depuis le problème CWG 2382.

Une expression new de tableau de placement sans allocation qui crée un tableau de unsigned char, ou std::byte (depuis C++17) peut être utilisée pour créer implicitement des objets dans une zone de stockage donnée : elle termine la durée de vie des objets chevauchant le tableau, puis crée implicitement des objets de types à durée de vie implicite dans le tableau.

std::vector offre une fonctionnalité similaire pour les tableaux dynamiques unidimensionnels.
