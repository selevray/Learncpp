Déduction des arguments de modèle de classe (CTAD) (depuis C++17)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Pour instancier un modèle de classe, chaque argument de modèle doit être connu, mais il n'est pas nécessaire de spécifier chaque argument de modèle. Dans les contextes suivants, le compilateur déduit les arguments de modèle à partir du type de l'initialiseur :

  • toute déclaration qui spécifie l'initialisation d'une variable et d'un modèle de variable, dont le type déclaré est le modèle de classe (éventuellement qualifié cv) :
std::pair p(2, 4.5);     // se déduit en std::pair<int, double> p(2, 4.5);
std::tuple t(4, 3, 2.5); // équivalent à auto t = std::make_tuple(4, 3, 2.5);
std::less l;             // équivalent à std::less<void> l;
  • expressions new :
template<class T>
struct A
{
    A(T, T);
};

auto y = new A{1, 2}; // le type alloué est A<int>
  • expressions de conversion de style fonctionnel :
auto lck = std::lock_guard(mtx);     // se déduit en std::lock_guard<std::mutex>
std::copy_n(vi1, 3,
    std::back_insert_iterator(vi2)); // se déduit en std::back_insert_iterator<T>,
                                     // où T est le type du conteneur vi2
std::for_each(vi.begin(), vi.end(),
    Foo([&](int i) {...}));          // se déduit en Foo<T>,
                                     // où T est le type unique de la lambda
  • le type d'un paramètre de modèle non-type :
template<class T>
struct X
{
    constexpr X(T) {}
};

template<X x>
struct Y {};

Y<0> y; // OK, Y<X<int>(0)>

(depuis C++20)

Déduction pour les modèles de classe

Guides de déduction générés implicitement

Lorsque, dans une conversion de style fonctionnel ou dans la déclaration d'une variable, le spécificateur de type consiste uniquement en le nom d'un modèle de classe primaire C (c'est-à-dire sans liste d'arguments de modèle qui l'accompagne), les candidats à la déduction sont formés comme suit :

  • Si C est défini, pour chaque constructeur (ou modèle de constructeur) Ci déclaré dans le modèle primaire nommé, un modèle de fonction fictif Fi est construit, de sorte que toutes les conditions suivantes soient satisfaites :
    • Les paramètres de modèle de Fi sont les paramètres de modèle de C, suivis (si Ci est un modèle de constructeur) des paramètres de modèle de Ci (les arguments de modèle par défaut sont également inclus).
  • Les contraintes associées de Fi sont la conjonction des contraintes associées de C et des contraintes associées de Ci.

(depuis C++20)

  • La liste de paramètres de Fi est la liste de paramètres de Ci.

  • Le type de retour de Fi est C suivi des paramètres de modèle du modèle de classe renfermé dans <>.

  • Si C n'est pas défini ou ne déclare aucun constructeur, un modèle de fonction fictif supplémentaire est ajouté, dérivé comme ci-dessus d'un constructeur hypothétique C().

  • Dans tous les cas, un modèle de fonction fictif supplémentaire, dérivé comme ci-dessus d'un constructeur hypothétique C(C), est ajouté ; il est appelé candidat de déduction par copie.

  • Pour chaque guide de déduction défini par l'utilisateur Gi, une fonction ou un modèle de fonction fictif Fi est construit, de sorte que toutes les conditions suivantes soient satisfaites :

    • La liste de paramètres de Fi est la liste de paramètres de Gi.
    • Le type de retour de Fi est l'identifiant de modèle simple de Gi.
    • Si Gi a des paramètres de modèle (syntaxe (2)), Fi est un modèle de fonction, et sa liste de paramètres de modèle est la liste de paramètres de modèle de Gi. Sinon, Fi est une fonction.
  • De plus, si
  • C est défini et satisfait les exigences d'un type agrégat, en supposant qu'aucune classe de base dépendante n'a de fonctions virtuelles ni de classes de base virtuelles,
  • il n'existe aucun guide de déduction défini par l'utilisateur pour C, et
  • la variable est initialisée à partir d'une liste non vide d'initialiseurs arg1, arg2, ..., argn (qui peut utiliser un initialiseur désigné), un candidat de déduction d'agrégat peut être ajouté. La liste de paramètres du candidat de déduction d'agrégat est produite à partir des types des éléments de l'agrégat, comme suit :
  • Soit ei le élément d'agrégat (éventuellement récursif) qui serait initialisé à partir de argi, où
  • l'élision d'accolades n'est pas prise en compte pour tout élément d'agrégat qui possède
  • un type non-tableau dépendant,
  • un type tableau dont la borne est dépendante de la valeur, ou
  • un type tableau dont le type des éléments est dépendant et argi est un littéral de chaîne
  • si C (ou son élément qui est lui-même un agrégat) possède une base qui est une expansion de paquet :
  • si l'expansion de paquet est un élément d'agrégat final, elle est considérée comme correspondant à tous les éléments restants de la liste d'initialiseurs ;
  • sinon, le paquet est considéré comme vide.
  • S'il n'existe pas un tel ei, le candidat de déduction d'agrégat n'est pas ajouté.
  • Sinon, déterminer la liste de paramètres T1, T2, ..., Tn du candidat de déduction d'agrégat comme suit :
  • Si ei est un tableau et argi est un braced-init-list ﻿, Ti est une référence rvalue vers le type déclaré de ei.
  • Si ei est un tableau et argi est un littéral de chaîne, Ti est une référence lvalue vers le type déclaré qualifié const de ei.
  • Sinon, Ti est le type déclaré de ei.
  • Si un paquet a été ignoré parce qu'il s'agit d'un élément d'agrégat non final, un paramètre paquet supplémentaire de la forme Pj ... est inséré à sa position d'origine dans l'agrégat. (Cela fera généralement échouer la déduction.)
  • Si un paquet est un élément d'agrégat final, la séquence finale de paramètres qui lui correspond est remplacée par un seul paramètre de la forme Tn .... Le candidat de déduction d'agrégat est un modèle de fonction fictif, dérivé comme ci-dessus d'un constructeur hypothétique C(T1, T2, ..., Tn). Pendant la déduction d'arguments de modèle pour le candidat de déduction d'agrégat, le nombre d'éléments d'un paquet de paramètres final n'est déduit du nombre d'arguments de fonction restants que s'il n'a pas été déduit autrement.
template<class T>
struct A
{
    T t;

    struct
    {
        long a, b;
    } u;
};

A a{1, 2, 3};
// candidat de déduction d'agrégat :
//   template<class T>
//   A<T> F(T, long, long);

template<class... Args>
struct B : std::tuple<Args...>, Args... {};

B b{std::tuple<std::any, std::string>{}, std::any{}};
// candidat de déduction d'agrégat :
//   template<class... Args>
//   B<Args...> F(std::tuple<Args...>, Args...);

// le type de b est déduit comme B<std::any, std::string>

(depuis C++20)

La déduction d'arguments de modèle et la résolution de surcharge sont ensuite effectuées pour l'initialisation d'un objet fictif d'un type de classe hypothétique, dont les signatures des constructeurs correspondent aux guides (à l'exception du type de retour) afin de former un ensemble de surcharges, l'initialiseur étant fourni par le contexte dans lequel la déduction d'arguments de modèle de classe a été effectuée, sauf que la première phase de l'initialisation par liste (prise en compte des constructeurs à liste d'initialiseurs) est omise si la liste d'initialiseurs consiste en une seule expression de type (éventuellement qualifié cv) U, où U est une spécialisation de C ou une classe dérivée d'une spécialisation de C.

Ces constructeurs fictifs sont des membres publics du type de classe hypothétique. Ils sont explicit si le guide a été formé à partir d'un constructeur explicit. Si la résolution de surcharge échoue, le programme est mal formé. Sinon, le type de retour de la spécialisation du modèle F sélectionné devient la spécialisation de modèle de classe déduite.

template<class T>
struct UniquePtr
{
    UniquePtr(T* t);
};

UniquePtr dp{new auto(2.0)};

// Un constructeur déclaré :
// C1: UniquePtr(T*);

// Ensemble de guides de déduction générés implicitement :

// F1: template<class T>
//     UniquePtr<T> F(T* p);

// F2: template<class T>
//     UniquePtr<T> F(UniquePtr<T>); // candidat de déduction de copie

// classe fictive à initialiser :
// struct X
// {
//     template<class T>
//     X(T* p);         // issu de F1
//
//     template<class T>
//     X(UniquePtr<T>); // issu de F2
// };

// initialisation directe d'un objet X
// avec "new double(2.0)" comme initialiseur
// sélectionne le constructeur qui correspond au guide F1 avec T = double
// Pour F1 avec T=double, le type de retour est UniquePtr<double>

// result:
// UniquePtr<double> dp{new auto(2.0)}

Ou, pour un exemple plus complexe (remarque : « S::N » ne compilerait pas : les qualificateurs de résolution de portée ne sont pas quelque chose qui peut être déduit) :

template<class T>
struct S
{
    template<class U>
    struct N
    {
        N(T);
        N(T, U);

        template<class V>
        N(V, U);
    };
};

S<int>::N x{2.0, 1};

// les guides de déduction générés implicitement sont (notez que T est déjà connu comme étant int)

// F1: template<class U>
//     S<int>::N<U> F(int);

// F2: template<class U>
//     S<int>::N<U> F(int, U);

// F3: template<class U, class V>
//     S<int>::N<U> F(V, U);

// F4: template<class U>
//     S<int>::N<U> F(S<int>::N<U>); (candidat de déduction de copie)

// Résolution de surcharge pour l'initialisation directe par liste avec "{2.0, 1}" comme initialiseur
// choisit F3 avec U=int et V=double.
// Le type de retour est S<int>::N<int>

// result:
// S<int>::N<int> x{2.0, 1};

Guides de déduction définis par l'utilisateur

La syntaxe d'un guide de déduction défini par l'utilisateur est la syntaxe d'une déclaration de fonction (modèle) avec un type de retour final, à ceci près qu'elle utilise le nom d'un modèle de classe comme nom de fonction :

| | | | explicit ﻿*(facultatif)* template-name ( parameter-list ) -> simple-template-id requires-clause ﻿*(facultatif)* ; | (1) | | | | template <template-parameter-list ﻿> requires-clause ﻿*(facultatif)* explicit ﻿*(facultatif)* template-name ( parameter-list ) -> simple-template-id requires-clause ﻿*(facultatif)* ; | (2) | | |

  • template-parameter-list — une liste non vide, séparée par des virgules, de paramètres de modèle
  • explicit — un spécificateur explicit
  • template-name — le nom du modèle de classe dont les arguments doivent être déduits
  • parameter-list — une liste de paramètres (éventuellement vide)
  • simple-template-id — un identifiant de modèle simple
  • requires-clause — (depuis C++20) une clause requires

Les paramètres des guides de déduction définis par l'utilisateur ne peuvent pas avoir de types d'espace réservé : la syntaxe de modèle de fonction abrégé n'est pas autorisée.

(depuis C++20)

Les guides de déduction définis par l'utilisateur doivent nommer un modèle de classe et doivent être introduits dans la même portée sémantique que le modèle de classe (qui peut être un espace de noms ou une classe englobante) et, pour un modèle de classe membre, doivent avoir le même accès, mais les guides de déduction ne deviennent pas membres de cette portée.

Un guide de déduction n'est pas une fonction et n'a pas de corps. Les guides de déduction ne sont pas trouvés par recherche de nom et ne participent pas à la résolution de surcharge, sauf pour la résolution de surcharge parmi d'autres guides de déduction lors de la déduction des arguments de modèle de classe. Les guides de déduction ne peuvent pas être redéclarés dans la même unité de traduction pour le même modèle de classe.

// déclaration du modèle
template<class T>
struct container
{
    container(T t) {}

    template<class Iter>
    container(Iter beg, Iter end);
};

// guide de déduction supplémentaire
template<class Iter>
container(Iter b, Iter e) -> container<typename std::iterator_traits<Iter>::value_type>;

// uses
container c(7); // OK : déduit T=int à l'aide d'un guide généré implicitement
std::vector<double> v = {/* ... */};
auto d = container(v.begin(), v.end()); // OK : déduit T=double
container e{5, 6}; // Error: il n'existe pas de std::iterator_traits<int>::value_type

Les constructeurs fictifs utilisés pour la résolution de surcharge (décrits ci-dessus) sont explicit s'ils correspondent à un guide de déduction généré implicitement à partir d'un constructeur explicit ou à un guide de déduction défini par l'utilisateur déclaré explicit. Comme toujours, ces constructeurs sont ignorés dans un contexte d'initialisation par copie :

template<class T>
struct A
{
    explicit A(const T&, ...) noexcept; // #1
    A(T&&, ...);                        // #2
};

int i;
A a1 = {i, i}; // error: impossible de déduire depuis une référence rvalue dans #2,
               // et #1 est explicit, et n'est pas pris en compte dans l'initialisation par copie.
A a2{i, i};    // OK, #1 se déduit en A<int> et initialise également
A a3{0, i};    // OK, #2 se déduit en A<int> et initialise également
A a4 = {0, i}; // OK, #2 se déduit en A<int> et initialise également

template<class T>
A(const T&, const T&) -> A<T&>; // #3

template<class T>
explicit A(T&&, T&&)  -> A<T>;  // #4

A a5 = {0, 1}; // error: #3 se déduit en A<int&>
               // #1 & #2 aboutissent à des constructeurs aux mêmes paramètres.
A a6{0, 1};    // OK, #4 se déduit en A<int> et #2 initialise
A a7 = {0, i}; // error: #3 se déduit en A<int&>
A a8{0, i};    // error: #3 se déduit en A<int&>

Utiliser un typedef membre ou un modèle d'alias dans la liste de paramètres d'un constructeur ou d'un modèle de constructeur ne rend pas, à lui seul, le paramètre correspondant du guide généré implicitement un contexte non déductible.

template<class T>
struct B
{
    template<class U>
    using TA = T;

    template<class U>
    B(U, TA<U>); // #1
};

// Le guide de déduction implicite généré à partir de #1 équivaut à
//     template<class T, class U>
//     B(U, T) -> B<T>;
// plutôt que
//     template<class T, class U>
//     B(U, typename B<T>::template TA<U>) -> B<T>;
// qui n'aurait pas pu être déduit

B b{(int*)0, (char*)0}; // OK, déduit B<char*>

Déduction pour les modèles d'alias

Lorsqu'une conversion de style fonctionnel ou la déclaration d'une variable utilise le nom d'un modèle d'alias A sans liste d'arguments comme spécificateur de type, où A est défini comme alias de B<ArgList>, la portée de B est non dépendante, et B est soit un modèle de classe, soit un modèle d'alias défini de manière similaire, la déduction procède de la même manière que pour les modèles de classe, à ceci près que les guides sont alors générés à partir des guides de B, comme suit :

  • Pour chaque guide f de B, déduire les arguments de modèle du type de retour de f à partir de B<ArgList> en utilisant la déduction d'arguments de modèle, à ceci près que la déduction n'échoue pas si certains arguments ne sont pas déduits. Si la déduction échoue pour une autre raison, poursuivre avec un ensemble vide d'arguments de modèle déduits.
  • Substituer le résultat de la déduction ci-dessus dans f ; si la substitution échoue, aucun guide n'est produit ; sinon, soit g le résultat de la substitution, un guide f' est formé, tel que
  • Les types de paramètres et le type de retour de f' sont les mêmes que ceux de g
  • Si f est un modèle, f' est un modèle de fonction dont la liste de paramètres de modèle se compose de tous les paramètres de modèle de A (y compris leurs arguments de modèle par défaut) qui apparaissent dans les déductions ci-dessus ou (récursivement) dans leurs arguments de modèle par défaut, suivis des paramètres de modèle de f qui n'ont pas été déduits (y compris leurs arguments de modèle par défaut) ; sinon (f n'est pas un modèle), f' est une fonction
  • Les contraintes associées de f' sont la conjonction des contraintes associées de g et d'une contrainte satisfaite si et seulement si les arguments de A sont déductibles à partir du type de résultat
template<class T>
class unique_ptr
{
    /* ... */
};

template<class T>
class unique_ptr<T[]>
{
    /* ... */
};

template<class T>
unique_ptr(T*) -> unique_ptr<T>;   // #1

template<class T>
unique_ptr(T*) -> unique_ptr<T[]>; // #2

template<class T>
concept NonArray = !std::is_array_v<T>;

template<NonArray A>
using unique_ptr_nonarray = unique_ptr<A>;

template<class A>
using unique_ptr_array = unique_ptr<A[]>;

// guide généré pour unique_ptr_nonarray :

// depuis #1 (la déduction de unique_ptr<T> à partir de unique_ptr<A> donne T = A) :
// template<class A>
//     requires(argument_of_unique_ptr_nonarray_is_deducible_from<unique_ptr<A>>)
// auto F(A*) -> unique_ptr<A>;

// depuis #2 (la déduction de unique_ptr<T[]> à partir de unique_ptr<A> ne donne rien) :
// template<class T>
//     requires(argument_of_unique_ptr_nonarray_is_deducible_from<unique_ptr<T[]>>)
// auto F(T*) -> unique_ptr<T[]>;

// où argument_of_unique_ptr_nonarray_is_deducible_from peut être défini comme

// template<class>
// class AA;

// template<NonArray A>
// class AA<unique_ptr_nonarray<A>> {};

// template<class T>
// concept argument_of_unique_ptr_nonarray_is_deducible_from =
//     requires { sizeof(AA<T>); };

// guide généré pour unique_ptr_array :

// depuis #1 (la déduction de unique_ptr<T> à partir de unique_ptr<A[]> donne T = A[]) :
// template<class A>
//     requires(argument_of_unique_ptr_array_is_deducible_from<unique_ptr<A[]>>)
// auto F(A(*)[]) -> unique_ptr<A[]>;

// depuis #2 (la déduction de unique_ptr<T[]> à partir de unique_ptr<A[]> donne T = A) :
// template<class A>
//     requires(argument_of_unique_ptr_array_is_deducible_from<unique_ptr<A[]>>)
// auto F(A*) -> unique_ptr<A[]>;

// où argument_of_unique_ptr_array_is_deducible_from peut être défini comme

// template<class>
// class BB;

// template<class A>
// class BB<unique_ptr_array<A>> {};

// template<class T>
// concept argument_of_unique_ptr_array_is_deducible_from =
//     requires { sizeof(BB<T>); };

// Use:
unique_ptr_nonarray p(new int); // déduit en unique_ptr<int>
// le guide de déduction généré à partir de #1 renvoie unique_ptr<int>
// le guide de déduction généré à partir de #2 renvoie unique_ptr<int[]>, qui est ignoré car
//   argument_of_unique_ptr_nonarray_is_deducible_from<unique_ptr<int[]>> n'est pas satisfait

unique_ptr_array q(new int[42]); // déduit en unique_ptr<int[]>
// le guide de déduction généré à partir de #1 échoue (impossible de déduire A dans A(*)[] à partir de new int[42])
// le guide de déduction généré à partir de #2 renvoie unique_ptr<int[]>

(depuis C++20)

Notes

La déduction d'arguments de modèle de classe n'est effectuée que si aucune liste d'arguments de modèle n'est présente. Si une liste d'arguments de modèle est spécifiée, la déduction n'a pas lieu.

std::tuple t1(1, 2, 3);                // OK : déduction
std::tuple<int, int, int> t2(1, 2, 3); // OK : tous les arguments sont fournis

std::tuple<> t3(1, 2, 3);    // Error : aucun constructeur correspondant dans tuple<>.
                             //        Aucune déduction effectuée.
std::tuple<int> t4(1, 2, 3); // Erreur

La déduction d'arguments de modèle de classe pour les agrégats nécessite généralement des guides de déduction définis par l'utilisateur :

template<class A, class B>
struct Agg
{
    A a;
    B b;
};
// les guides implicitement générés sont formés à partir des constructeurs par défaut, de copie et de déplacement

template<class A, class B>
Agg(A a, B b) -> Agg<A, B>;
// ^ Ce guide de déduction peut être généré implicitement en C++20

Agg agg{1, 2.0}; // déduit en Agg<int, double> à partir du guide défini par l'utilisateur

template<class... T>
array(T&&... t) -> array<std::common_type_t<T...>, sizeof...(T)>;
auto a = array{1, 2, 5u}; // déduit en array<unsigned, 3> à partir du guide défini par l'utilisateur

(jusqu'à C++20)

Les guides de déduction définis par l'utilisateur n'ont pas besoin d'être des modèles :

template<class T>
struct S
{
    S(T);
};
S(char const*) -> S<std::string>;

S s{"hello"}; // déduit en S<std::string>

Dans la portée d'un modèle de classe, le nom du modèle sans liste de paramètres est un nom de classe injecté, et peut être utilisé comme type. Dans ce cas, la déduction d'arguments de classe n'a pas lieu et les paramètres de modèle doivent être fournis explicitement :

template<class T>
struct X
{
    X(T) {}

    template<class Iter>
    X(Iter b, Iter e) {}

    template<class Iter>
    auto foo(Iter b, Iter e)
    {
        return X(b, e); // pas de déduction : X est le X<T> courant
    }

    template<class Iter>
    auto bar(Iter b, Iter e)
    {
        return X<typename Iter::value_type>(b, e); // doit préciser ce que nous voulons
    }

    auto baz()
    {
        return ::X(0); // pas le nom de classe injecté ; déduit en X<int>
    }
};

Lors de la résolution de surcharge, l'ordre partiel prime sur le fait qu'un modèle de fonction soit généré à partir d'un guide de déduction défini par l'utilisateur : si le modèle de fonction généré à partir du constructeur est plus spécialisé que celui généré à partir du guide de déduction défini par l'utilisateur, celui généré à partir du constructeur est choisi. Comme le candidat de déduction par copie est généralement plus spécialisé qu'un constructeur d'encapsulation, cette règle signifie que la copie est généralement préférée à l'encapsulation.

template<class T>
struct A
{
    A(T, int*);     // #1
    A(A<T>&, int*); // #2

    enum { value };
};

template<class T, int N = T::value>
A(T&&, int*) -> A<T>; //#3

A a{1, 0}; // utilise #1 pour déduire A<int> et s'initialise avec #1
A b{a, 0}; // utilise #2 (plus spécialisé que #3) pour déduire A<int> et s'initialise avec #2

Lorsque les départageurs précédents, y compris l'ordre partiel, n'ont pas permis de distinguer deux modèles de fonction candidats, les règles suivantes s'appliquent :

  • Un modèle de fonction généré à partir d'un guide de déduction défini par l'utilisateur est préféré à un modèle généré implicitement à partir d'un constructeur ou d'un modèle de constructeur.
  • Le candidat de déduction par copie est préféré à tous les autres modèles de fonction générés implicitement à partir d'un constructeur ou d'un modèle de constructeur.
  • Un modèle de fonction généré implicitement à partir d'un constructeur non template est préféré à un modèle de fonction généré implicitement à partir d'un modèle de constructeur.
template<class T>
struct A
{
    using value_type = T;

    A(value_type); // #1
    A(const A&);   // #2
    A(T, T, int);  // #3

    template<class U>
    A(int, T, U);  // #4
};                 // #5, le candidat de déduction de copie A(A);

A x(1, 2, 3); // utilise #3, généré à partir d'un constructeur non template

template<class T>
A(T) -> A<T>; // #6, moins spécialisé que #5

A a(42); // utilise #6 pour déduire A<int> et #1 pour l'initialisation
A b = a; // utilise #5 pour déduire A<int> et #2 pour l'initialisation

template<class T>
A(A<T>) -> A<A<T>>; // #7, aussi spécialisé que #5

A b2 = a; // utilise #7 pour déduire A<A<int>> et #1 pour l'initialisation

Une référence rvalue vers un paramètre de modèle non qualifié cv n'est pas une référence de transfert si ce paramètre est un paramètre de modèle de classe :

template<class T>
struct A
{
    template<class U>
    A(T&&, U&&, int*); // #1 : T&& n'est pas une référence de transfert
                       //     U&& est une référence de transfert

    A(T&&, int*);      // #2 : T&& n'est pas une référence de transfert
};

template<class T>
A(T&&, int*) -> A<T>; // #3 : T&& est une référence de transfert

int i, *ip;
A a{i, 0, ip};  // erreur, impossible de déduire à partir de #1
A a0{0, 0, ip}; // utilise #1 pour déduire A<int> et #1 pour l'initialisation
A a2{i, ip};    // utilise #3 pour déduire A<int&> et #2 pour l'initialisation

Lors de l'initialisation à partir d'un seul argument d'un type qui est une spécialisation du modèle de classe en question, la copie par déduction est généralement préférée à l'enveloppement par défaut :

std::tuple t1{1};  //std::tuple<int>
std::tuple t2{t1}; //std::tuple<int>, et non std::tuple<std::tuple<int>>

std::vector v1{1, 2};   // std::vector<int>
std::vector v2{v1};     // std::vector<int>, et non std::vector<std::vector<int>> (P0702R1)
std::vector v3{v1, v2}; // std::vector<std::vector<int>>

En dehors du cas particulier de la copie et de l'enveloppement, la forte préférence pour les constructeurs à liste d'initialiseurs dans l'initialisation par liste reste intacte.

std::vector v1{1, 2}; // std::vector<int>

std::vector v2(v1.begin(), v1.end()); // std::vector<int>
std::vector v3{v1.begin(), v1.end()}; // std::vector<std::vector<int>::iterator>

Avant l'introduction de la déduction des arguments de modèle de classe, une approche courante pour éviter de spécifier explicitement les arguments consiste à utiliser un modèle de fonction :

std::tuple p1{1, 1.0};             //std::tuple<int, double>, par déduction
auto p2 = std::make_tuple(1, 1.0); //std::tuple<int, double>, avant C++17
