L'opérateur d'appel de fonction fournit une sémantique de fonction à tout objet.

L'opérateur conditionnel (couramment appelé ternaire conditionnel) vérifie la valeur booléenne de la première expression et, selon la valeur obtenue, évalue et renvoie soit la deuxième, soit la troisième expression.

Opérateur d'appel de fonction intégré

Les expressions d'appel de fonction ont la forme suivante :

| | | | function ﻿(arg1, arg2, arg3,...) | | | |

  • function — une expression de type fonction ou de type pointeur de fonction
  • arg1, arg2, arg3,... — une liste éventuellement vide d'expressions arbitrairesou listes d'initialisateurs entre accolades (depuis C++11), sauf que l'opérateur virgule n'est pas autorisé au niveau supérieur afin d'éviter toute ambiguïté

Pour un appel à une fonction non membre ou à une fonction membre statique, function peut être une lvalue désignant une fonction (auquel cas la conversion fonction-vers-pointeur est supprimée), ou une prvalue de type pointeur de fonction.

Le nom de la fonction (ou du membre) spécifié par function peut être surchargé, les règles de résolution de surcharge déterminant la surcharge à appeler.

Si function désigne une fonction membre, elle peut être virtuelle, auquel cas le redéfinisseur final de cette fonction est appelé, par liaison dynamique à l'exécution.

Pour appeler la fonction,

L'expression function ainsi que toutes les expressions arg1, arg2, arg3, etc., fournies comme arguments sont évaluées dans un ordre arbitraire, non séquencées les unes par rapport aux autres.

(jusqu'à C++17)

function est séquencée avant chacune des expressions arg1, arg2, arg3 ainsi que des arguments par défaut, s'il y en a. Les expressions d'arguments sont évaluées dans un ordre arbitraire, séquencées de façon indéterminée les unes par rapport aux autres.

(depuis C++17)

Chaque paramètre de fonction est initialisé avec son argument correspondant, après une conversion implicite si nécessaire.

  • S'il n'existe pas d'argument correspondant, le argument par défaut correspondant est utilisé, et s'il n'y en a pas, le programme est mal formé.
  • Si l'appel est fait à une fonction membre, le pointeur this vers l'objet courant est converti comme par un cast explicite vers le pointeur this attendu par la fonction.
  • L'initialisation et la destruction de chaque paramètre ont lieu dans le contexte de l'expression complète où apparaît l'appel de fonction, ce qui signifie, par exemple, que si un constructeur ou un destructeur d'un paramètre lève une exception, les blocs function try de la fonction appelée ne sont pas pris en compte.

Si la fonction est variadique, les promotions d'arguments par défaut sont appliquées à tous les arguments couverts par le paramètre ellipse.

Il est défini par l'implémentation de savoir si un paramètre est détruit à la sortie de la fonction où il est défini ou à la fin de l'expression complète englobante. Les paramètres sont toujours détruits dans l'ordre inverse de leur construction.

Le type de retour d'une expression d'appel de fonction est le type de retour de la fonction choisie, déterminé par liaison statique (en ignorant le mot-clé virtual), même si la fonction redéfinissante effectivement appelée renvoie un type différent. Cela permet aux fonctions redéfinissantes de renvoyer des pointeurs ou des références vers des classes dérivées du type de retour de la fonction de base, c.-à-d. que C++ prend en charge les types de retour covariants. Si function désigne un destructeur, le type de retour est void.

Lorsqu'un objet de type classe X est passé à une fonction ou renvoyé par celle-ci, si chaque constructeur de copie, constructeur de déplacement et destructeur de X est soit trivial soit supprimé, et si X possède au moins un constructeur de copie ou de déplacement non supprimé, les implémentations peuvent créer un objet temporaire pour contenir le paramètre de la fonction ou l'objet résultat.

L'objet temporaire est construit à partir de l'argument de la fonction ou de la valeur de retour, respectivement, et le paramètre ou l'objet de retour de la fonction est initialisé comme en utilisant le constructeur trivial non supprimé pour copier le temporaire (même si ce constructeur est inaccessible ou ne serait pas sélectionné par la résolution de surcharge pour effectuer une copie ou un déplacement de l'objet).

Cela permet de passer à des fonctions ou de renvoyer par celles-ci dans des registres des objets de petits types classe, comme std::complex ou std::span.

(depuis C++17)

La catégorie de valeur d'une expression d'appel de fonction est lvalue si la fonction renvoie une référence lvalue ou une référence rvalue vers une fonction, est une xvalue si la fonction renvoie une référence rvalue vers un objet, et est une prvalue sinon. Si l'expression d'appel de fonction est une prvalue de type objet, elle doit avoir un type completsauf lorsqu'elle est utilisée comme opérande de decltype (ou comme opérande droit d'un opérateur virgule intégré qui est l'opérande de decltype) (depuis C++11).

L'expression d'appel de fonction est similaire par sa syntaxe à l'initialisation par valeur T(), à l'expression de cast de style fonctionnel T(A1), et à l'initialisation directe d'un temporaire T(A1, A2, A3, ...), où T est le nom d'un type.

#include <cstdio>

struct S
{
    int f1(double d)
    {
        return printf("%f \n", d); // appel de fonction à arguments variables
    }

    int f2()
    {
        return f1(7); // appel de fonction membre, équivalent à this->f1()
                      // argument entier converti en double
    }
};

void f()
{
    puts("function called"); // appel de fonction
}

int main()
{
    f();    // appel de fonction
    S s;
    s.f2(); // appel de fonction membre
}

Output:

function called
7.000000

Opérateur virgule intégré

Les expressions virgule ont la forme suivante :

| | | | E1 , E2 | | | |

Dans une expression virgule E1, E2, l'expression E1 est évaluée, son résultat est écarté (bien que, si elle est de type classe, elle ne soit pas détruite avant la fin de l'expression complète englobante), et ses effets de bord sont achevés avant que l'évaluation de l'expression E2 ne commence (notez qu'un operator, défini par l'utilisateur ne peut pas garantir le séquencement) (jusqu'à C++17).

Le type, la valeur et la catégorie de valeur du résultat de l'expression virgule sont exactement le type, la valeur et la catégorie de valeur du second opérande, E2. Si E2 est une expression (depuis C++17) temporaire, le résultat de l'expression est ce temporaire expression (depuis C++17). Si E2 est un champ de bits, le résultat est un champ de bits.

La virgule dans les différentes listes séparées par des virgules, telles que les listes d'arguments de fonction (f(a, b, c)) et les listes d'initialisation int a[] = {1, 2, 3}, n'est pas l'opérateur virgule. Si l'opérateur virgule doit être utilisé dans de tels contextes, il doit être mis entre parenthèses : f(a, (n++, n + b), c).

L'utilisation d'une expression virgule non parenthésée comme second (droit) argument d'un opérateur d'indexation est obsolète.

Par exemple, a[b, c] est obsolète et a[(b, c)] ne l'est pas.

(depuis C++20) (jusqu'à C++23)

Une expression virgule non parenthésée ne peut pas être le second (droit) argument d'un opérateur d'indexation. Par exemple, a[b, c] est soit mal formé, soit équivalent à a.operator[](b, c).

Des parenthèses sont nécessaires lorsqu'une expression virgule est utilisée comme indice, par exemple a[(b, c)].

(depuis C++23)

#include <iostream>

int main()
{
    // la virgule sert souvent à exécuter plusieurs expressions
    // là où la grammaire du langage n'autorise qu'une seule expression :

    // * dans la troisième composante de la boucle for
    for (int i = 0, j = 10; i <= j; ++i, --j)
    //            ^séparateur de liste ^opérateur virgule
        std::cout << "i = " << i << " j = " << j << '\n';

    // * dans une instruction return
    // return log("an error!"), -1;

    // * dans une expression d'initialisation
    // MyClass(const Arg& arg)
    // : member{ throws_if_bad(arg), arg }

    // etc.

    // les opérateurs virgule peuvent être enchaînés ; le résultat de la dernière
    // expression (la plus à droite) est le résultat de toute la chaîne :
    int n = 1;
    int m = (++n, std::cout << "n = " << n << '\n', ++n, 2 * n);

    // m vaut maintenant 6
    std::cout << "m = " << (++m, m) << '\n';
}

Output:

i = 0 j = 10
i = 1 j = 9
i = 2 j = 8
i = 3 j = 7
i = 4 j = 6
i = 5 j = 5
n = 2
m = 7

Opérateur conditionnel

Les expressions de l'opérateur conditionnel ont la forme

| | | | E1 ? E2 : E3 | | | |

Le premier opérande de l'opérateur conditionnel est évalué et converti contextuellement en bool. Après l'évaluation de la valeur et l'achèvement de tous les effets de bord du premier opérande, si le résultat est true, le second opérande est évalué. Si le résultat est false, le troisième opérande est évalué.

Le type et la catégorie de valeur de l'expression conditionnelle E1 ? E2 : E3 sont déterminés selon les règles suivantes :

  • Si E2 ou E3 a le type void :
    • Si E2 et E3 sont tous deux de type void, le résultat est une prvalue de type void.
    • Sinon, si l'opérande de type void est une expression throw (éventuellement entre parenthèses), le résultat a le type et la catégorie de valeur de l'autre expression. Si l'autre expression est un champ de bits, le résultat est un champ de bits.[1]
    • Sinon, le programme est mal formé.
2 + 2 == 4 ? throw 123 : throw 456;

std::string str = 2 + 2 == 4 ? "OK" : throw std::logic_error("2 + 2 != 4");

  • Sinon, si E2 ou E3 sont des [champs de bits lvalue (jusqu'à C++11) | champs de bits glvalue de même catégorie de valeur (depuis C++11)] et de types cv1 T et cv2 T, respectivement, les opérandes sont considérés comme étant de type cv T pour le reste de cette section, où cv est l'union de cv1 et cv2.

  • Sinon, si E2 et E3 ont des types différents, dont au moins un est un type classe (éventuellement qualifié cv), ou si les deux sont des [lvalues (jusqu'à C++11) | glvalues de même catégorie de valeur (depuis C++11)] et ont le même type à la qualification cv près, alors on tente de former une séquence de conversion implicite.[2] On tente de former une séquence de conversion implicite à partir d'une expression opérande X de type TX vers un type cible lié au type TY de l'expression opérande Y, comme suit :

    • Si Y est une lvalue, le type cible est TY&, mais une séquence de conversion implicite ne peut être formée que si la référence se lie directement à [une lvalue (jusqu'à C++11) | une glvalue (depuis C++11)].
  • Si Y est une xvalue, le type cible est TY&&, mais une séquence de conversion implicite ne peut être formée que si la référence se lie directement.

(depuis C++11)

  • Si Y est [une rvalue (jusqu'à C++11) | une prvalue (depuis C++11)] ou si aucune des séquences de conversion ci-dessus ne peut être formée, et qu'au moins l'un de TX et TY est un type classe (éventuellement qualifié cv) :

    • Si TX et TY sont le même type classe (en ignorant la qualification cv) :
      • Si TY est au moins aussi qualifié cv que TX, le type cible est TY.
      • Sinon, aucune séquence de conversion n'est formée.
    • Sinon, si TY est une classe de base de TX, le type cible est TY avec les qualificateurs cv de TX.
    • Sinon, le type cible est le type de Z, où Z est la valeur de Y après application des conversions standard lvalue-to-rvalue, array-to-pointer et function-to-pointer.

  • Sinon, aucune séquence de conversion n'est formée. Par ce processus, on détermine si une séquence de conversion implicite peut être formée de E2 vers le type cible déterminé pour E3, et réciproquement.

  • Si les deux séquences peuvent être formées, ou si l'une peut être formée mais qu'il s'agit de la séquence de conversion ambiguë, le programme est mal formé.

  • Si aucune séquence de conversion ne peut être formée, les opérandes restent inchangés.

  • Sinon, si exactement une séquence de conversion peut être formée, cette conversion est appliquée à l'opérande choisi et l'opérande converti est utilisé à la place de l'opérande d'origine pour le reste du processus.

struct A {};

struct B : A {};

using T = const B;

A a = true ? A() : T(); // Y = A(), TY = A, X = T(), TX = const B, Target = const A
  • Si E2 et E3 sont des lvalues du même type, alors le résultat est une lvalue de ce type, et c'est un champ de bits si l'un au moins de E2 et E3 est un champ de bits.

(jusqu'à C++11)

  • Si E2 et E3 sont des glvalues du même type et de la même catégorie de valeur, alors le résultat a le même type et la même catégorie de valeur, et c'est un champ de bits si l'un au moins de E2 et E3 est un champ de bits.

(depuis C++11)

  • Sinon, le résultat est [une rvalue (jusqu'à C++11) | une prvalue (depuis C++11)].
    • Si E2 et E3 n'ont pas le même type, et que l'un des deux a un type classe (éventuellement qualifié cv), une résolution de surcharge est effectuée en utilisant les candidats intégrés pour tenter de convertir les opérandes en types intégrés.
      • Si la résolution de surcharge échoue, le programme est mal formé.
      • Sinon, les conversions sélectionnées sont appliquées et les opérandes convertis sont utilisés à la place des opérandes d'origine pour le reste du processus.
    • Les conversions array-to-pointer et function-to-pointer sont appliquées à E2 et E3 (éventuellement convertis). Après ces conversions, au moins une des conditions suivantes doit être vérifiée, sinon le programme est mal formé :
      • E2 et E3 ont le même type. Dans ce cas, le résultat est de ce type et le résultat est initialisé par copie à partir de l'opérande sélectionné.
      • E2 et E3 ont tous deux un type arithmétique ou énumération. Dans ce cas, les conversions arithmétiques usuelles sont appliquées pour les amener à leur type commun, et le résultat est de ce type.
      • Au moins l'un de E2 et E3 est un pointeur. Dans ce cas, les conversions lvalue-to-rvalue, de pointeur, de pointeur de fonction (depuis C++17) et de qualification sont appliquées pour les amener à leur type pointeur composite, et le résultat est de ce type.
      • Au moins l'un de E2 et E3 est un pointeur vers membre. Dans ce cas, les conversions lvalue-to-rvalue, de pointeur vers membre, de pointeur de fonction (depuis C++17) et de qualification sont appliquées pour les amener à leur type pointeur composite, et le résultat est de ce type.
  • Les deux E2 et E3 sont des constantes de pointeur nul, et l'une au moins d'entre elles est de type std::nullptr_t. Dans ce cas, le résultat est de type std::nullptr_t.

(depuis C++11)

int* intPtr;

using Mixed = decltype(true ? nullptr : intPtr);

static_assert(std::is_same_v<Mixed, int*>); // nullptr devenant int*

struct A
{
    int* m_ptr;
} a;

int* A::* memPtr = &A::m_ptr; // memPtr est un pointeur vers le membre m_ptr de A

// memPtr fait de nullptr un type de pointeur vers le membre m_ptr de A
static_assert(std::is_same_v<decltype(false ? memPtr : nullptr), int*A::*>);

// a.*memPtr est maintenant simplement un pointeur vers int, et nullptr devient aussi un pointeur vers int
static_assert(std::is_same_v<decltype(false ? a.*memPtr : nullptr), int*>);

Surcharges

Pour chaque couple de types arithmétiques promus L et R et pour chaque type P, où P est un type pointeur, un type pointeur vers membre ou un type énumération à portée, les signatures de fonctions suivantes participent à la résolution de surcharge :

LR operator?:(bool, L, R);

P operator?:(bool, P, P);

où LR est le résultat des conversions arithmétiques usuelles effectuées sur L et R.

L'opérateur « ?: » ne peut pas être surchargé, ces signatures de fonctions n'existent que pour la résolution de surcharge.

Le type résultat d'un opérateur conditionnel est également accessible via le trait de type binaire std::common_type.

(depuis C++11)

#include <iostream>
#include <string>

struct Node
{
    Node* next;
    int data;

    // constructeur de copie avec copie profonde
    Node(const Node& other)
        : next(other.next ? new Node(*other.next) : NULL)
        , data(other.data)
    {}

    Node(int d) : next(NULL), data(d) {}

    ~Node() { delete next; }
};

int main()
{
    // exemple simple de rvalue
    int n = 1 > 2 ? 10 : 11;  // 1 > 2 est faux, donc n = 11

    // exemple simple de lvalue
    int m = 10;
    (n == m ? n : m) = 7; // n == m est faux, donc m = 7

    //afficher le résultat
    std::cout << "n = " << n << "\nm = " << m;
}

Output:

n = 11
m = 7
