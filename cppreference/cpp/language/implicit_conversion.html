Conversions implicites

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les conversions implicites sont effectuées chaque fois qu'une expression d'un type T1 est utilisée dans un contexte qui n'accepte pas ce type, mais accepte un autre type T2 ; en particulier :

  • lorsque l'expression est utilisée comme argument lors de l'appel d'une fonction déclarée avec T2 comme paramètre ;
  • lorsque l'expression est utilisée comme opérande d'un opérateur qui attend T2 ;
  • lors de l'initialisation d'un nouvel objet de type T2, y compris return instruction dans une fonction retournant T2 ;
  • lorsque l'expression est utilisée dans une instruction switch (T2 est de type entier) ;
  • lorsque l'expression est utilisée dans une instruction if ou une boucle (T2 est bool).

Le programme est bien formé (compile) seulement s'il existe une unique séquence de conversion implicite de T1 vers T2.

Si la fonction ou l'opérateur appelé a plusieurs surcharges, après que la séquence de conversion implicite a été construite de T1 vers chaque T2 disponible, les règles de résolution de surcharge décident quelle surcharge est compilée.

Remarque : dans les expressions arithmétiques, le type de destination des conversions implicites sur les opérandes des opérateurs binaires est déterminé par un ensemble distinct de règles : conversions arithmétiques usuelles.

Ordre des conversions

Une séquence de conversion implicite se compose de ce qui suit, dans cet ordre :

  1. zéro ou une séquence de conversion standard ;

  2. zéro ou une conversion définie par l'utilisateur ;

  3. zéro ou une séquence de conversion standard (uniquement si une conversion définie par l'utilisateur est utilisée).

Lorsqu'on considère l'argument d'un constructeur ou d'une fonction de conversion définie par l'utilisateur, une seule séquence de conversion standard est autorisée (sinon les conversions définies par l'utilisateur pourraient être enchaînées de fait). Lors de la conversion d'un type non classe vers un autre type non classe, seule une séquence de conversion standard est autorisée.

Une séquence de conversion standard se compose de ce qui suit, dans cet ordre :

  1. zéro ou une conversion parmi l'ensemble suivant :
  • conversion lvalue-to-rvalue,
  • conversion array-to-pointer, et
  • conversion function-to-pointer ;
  1. zéro ou une promotion numérique ou une conversion numérique ;
  1. zéro ou une conversion de pointeur de fonction ;

(depuis C++17)

  1. zéro ou une conversion de qualification.

Une conversion définie par l'utilisateur consiste en zéro ou un constructeur de conversion non explicite à un seul argument, ou en un appel à une fonction de conversion non explicite.

Une expression e est dite implicitement convertible en T2 si et seulement si T2 peut être initialisé par copie à partir de e, c'est-à-dire si la déclaration T2 t = e; est bien formée (peut être compilée), pour un certain temporaire fictif t. Notez que ceci diffère de l'initialisation directe (T2 t(e)), où les constructeurs explicites et les fonctions de conversion seraient en outre pris en compte.

Conversions contextuelles

Dans les contextes suivants, le type bool est attendu et la conversion implicite est effectuée si la déclaration bool t(e); est bien formée (c'est-à-dire qu'une fonction de conversion explicite telle que explicit T::operator bool() const; est prise en compte). Une telle expression e est dite convertie contextuellement en bool.

  • l'expression de contrôle de if, while, for ;
  • les opérandes des opérateurs logiques intégrés !, && et || ;
  • le premier opérande de l'opérateur conditionnel ?: ;
  • le prédicat d'une déclaration static_assert ;
  • l'expression d'un spécificateur noexcept ;
  • l'expression d'un spécificateur explicit ;

(depuis C++20)

(depuis C++11)

Dans les contextes suivants, un type spécifique au contexte T est attendu, et l'expression e de type classe E n'est autorisée que si

  • E possède une unique fonction de conversion définie par l'utilisateur (depuis C++11) non explicite vers un type autorisé.

(jusqu'à C++14)

  • il existe exactement un type T parmi les types autorisés tel que E possède des fonctions de conversion non explicites dont les types de retour sont (éventuellement qualifiés cv) T ou une référence vers (éventuellement qualifié cv) T, et
  • e est implicitement convertible en T.

(depuis C++14)

Une telle expression e est dite implicitement convertie contextuellement vers le type spécifié T. Notez que les fonctions de conversion explicites ne sont pas prises en compte, bien qu'elles le soient dans les conversions contextuelles vers bool. (depuis C++11)

  • l'argument de l'expression delete (T est un type quelconque de pointeur vers objet) ;
  • expression constante intégrale, lorsqu'un type littéral de classe est utilisé (T est un type entier quelconque ou une énumération non scopée, la fonction de conversion définie par l'utilisateur sélectionnée doit être constexpr) ;
  • l'expression de contrôle de l'instruction switch (T est un type entier quelconque ou un type énumération).
#include <cassert>

template<typename T>
class zero_init
{
    T val;
public:
    zero_init() : val(static_cast<T>(0)) {}
    zero_init(T val) : val(val) {}
    operator T&() { return val; }
    operator T() const { return val; }
};

int main()
{
    zero_init<int> i;
    assert(i == 0);

    i = 7;
    assert(i == 7);

    switch (i) {}     // erreur jusqu'à C++14 (plus d'une fonction de conversion)
                      // OK depuis C++14 (les deux fonctions convertissent vers le même type int)
    switch (i + 0) {} // toujours correct (conversion implicite)
}

Transformations de valeur

Les transformations de valeur sont des conversions qui modifient la catégorie de valeur d'une expression. Elles ont lieu chaque fois qu'une expression apparaît comme opérande d'un opérateur qui attend une expression d'une autre catégorie de valeur :

  • Chaque fois qu'une glvalue apparaît comme opérande d'un opérateur qui exige une prvalue pour cet opérande, les conversions standard conversion lvalue-vers-rvalue, conversion tableau-vers-pointeur ou conversion fonction-vers-pointeur sont appliquées pour convertir l'expression en prvalue.
  • Sauf indication contraire, chaque fois qu'une prvalue apparaît comme opérande d'un opérateur qui attend une glvalue pour cet opérande, la matérialisation temporaire est appliquée pour convertir l'expression en xvalue.

(depuis C++17)

Conversion lvalue-vers-rvalue

[Une lvalue (jusqu'à C++11) | Une glvalue (depuis C++11)] de tout type non fonction et non tableau T peut être implicitement convertie en [une rvalue (jusqu'à C++11) | une prvalue (depuis C++11)] :

  • Si T n'est pas un type classe, le type de la [rvalue (jusqu'à C++11) | prvalue (depuis C++11)] est la version non qualifiée cv de T.
  • Sinon, le type de la [rvalue (jusqu'à C++11) | prvalue (depuis C++11)] est T.

Si une conversion lvalue-vers-rvalue à partir d'un type incomplet est requise par un programme, ce programme est mal formé.

Étant donné l'objet auquel la [lvalue (jusqu'à C++11) | glvalue (depuis C++11)] fait référence, noté obj :

  • Lorsqu'une conversion lvalue-vers-rvalue intervient dans l'opérande de sizeof, la valeur contenue dans obj n'est pas accédée, puisque cet opérateur n'évalue pas son opérande.

  • Le résultat de la conversion est la valeur contenue dans obj. Si l'un parmi T et le type de obj est un type entier signé, et l'autre le type entier non signé correspondant, le résultat est la valeur de type T ayant la même représentation de valeur que obj.

(jusqu'à C++11)

  • Lorsqu'une conversion lvalue-vers-rvalue est appliquée à une expression E, la valeur contenue dans obj n'est pas accédée si :

  • E n'est pas potentiellement évaluée, ou

  • l'évaluation de E entraîne l'évaluation d'un membre Ex de l'ensemble des résultats potentiels de E, et Ex désigne une variable x qui n'est pas utilisée par odr dans Ex.

  • Le résultat de la conversion est déterminé comme suit :

  • Si T est (éventuellement qualifié cv) std::nullptr_t, le résultat est une constante de pointeur nul. obj n'est pas accédé par la conversion, il n'y a donc aucun effet de bord même si T est qualifié volatile, et la glvalue peut désigner un membre inactif d'une union.

  • Sinon, si T est un type classe :

  • La conversion initialise par copie un temporaire de type T à partir de la glvalue, et le résultat de la conversion est une prvalue pour ce temporaire.

(jusqu'à C++17)

  • La conversion initialise par copie l'objet résultat à partir de la glvalue.

(depuis C++17)

  • Sinon, si obj contient une valeur de pointeur invalide, le comportement est défini par l'implémentation.
  • Sinon, si les bits de la représentation de valeur de obj ne sont pas valides pour le type de obj, le comportement est indéfini.
  • Sinon, obj est lu, et (depuis C++20) le résultat est la valeur contenue dans obj. Si l'un parmi T et le type de obj est un type entier signé, et l'autre le type entier non signé correspondant, le résultat est la valeur de type T ayant la même représentation de valeur que obj.

(depuis C++11)

Cette conversion modélise l'action de lire une valeur depuis un emplacement mémoire vers un registre du processeur.

Conversion tableau-vers-pointeur

Une lvalue ou une rvalue de type « tableau de N T » ou « tableau de borne inconnue de T » peut être implicitement convertie en une prvalue de type « pointeur vers T ». Si le tableau est une prvalue, une matérialisation temporaire a lieu. (depuis C++17) Le pointeur obtenu désigne le premier élément du tableau (voir désintégration tableau-vers-pointeur pour les détails).

Conversion fonction-vers-pointeur

Une lvalue de type fonction peut être implicitement convertie en une prvalue de type pointeur vers cette fonction. Ceci ne s'applique pas aux fonctions membres non statiques, car les lvalues désignant des fonctions membres non statiques n'existent pas.

Matérialisation temporaire

Une prvalue de tout type complet T peut être convertie en une xvalue du même type T. Cette conversion initialise un objet temporaire de type T à partir de la prvalue, en évaluant la prvalue avec l'objet temporaire comme objet résultat, et produit une xvalue désignant l'objet temporaire.

Si T est une classe ou un tableau de type classe, il doit posséder un destructeur accessible et non supprimé.

struct S { int m; };
int i = S().m; // l'accès à un membre attend une glvalue à partir de C++17 ;
               // La prvalue S() est convertie en xvalue

La matérialisation temporaire a lieu dans les situations suivantes :

  • lors de la liaison d'une référence à une prvalue ;
  • lors de l'accès à un membre donnée non statique d'une prvalue de classe ;
  • lors de l'invocation d'une fonction membre à objet implicite d'une prvalue de classe ;
  • lors de l'exécution d'une conversion tableau-vers-pointeur (voir ci-dessus) ou d'un indexage sur une prvalue de tableau ;
  • lors de l'initialisation d'un objet de type std::initializer_list<T> à partir d'une liste d'initialisation entre accolades ;
  • lorsqu'une prvalue apparaît comme une expression de valeur ignorée.

Notez que la matérialisation temporaire n'a pas lieu lors de l'initialisation d'un objet à partir d'une prvalue du même type (par initialisation directe ou initialisation par copie) : un tel objet est initialisé directement à partir de l'initialiseur. Ceci garantit l'« élision de copie garantie ».

(depuis C++17)

Promotion entière

Les prvalues de petits types entiers (tels que char) et les types énumération non scopés peuvent être converties en prvalues de types entiers plus grands (tels que int). En particulier, les opérateurs arithmétiques n'acceptent pas comme arguments de types plus petits que int, et les promotions entières sont appliquées automatiquement après la conversion lvalue-vers-rvalue, le cas échéant. Cette conversion préserve toujours la valeur.

Les conversions implicites suivantes de cette section sont classées comme promotions entières.

Notez que, pour un type source donné, le type de destination de la promotion entière est unique, et que toutes les autres conversions ne sont pas des promotions. Par exemple, la résolution de surcharge choisit char -> int (promotion) plutôt que char -> short (conversion).

Promotion à partir des types entiers

Une prvalue de type bool peut être convertie en une prvalue de type int, false devenant 0 et true devenant 1.

Pour une prvalue val d'un type entier T sauf bool :

  1. Si val est le résultat d'une conversion lvalue-vers-rvalue appliquée à un champ de bits,
  • val peut être converti en une prvalue de type int si int peut représenter toutes les valeurs du champ de bits ;
  • sinon, val peut être converti en unsigned int si unsigned int peut représenter toutes les valeurs du champ de bits ;
  • sinon, val peut être converti selon les règles spécifiées au point (3).
  1. Sinon (val n'est pas converti à partir d'un champ de bits),
  • si T est [char8_t, (depuis C++20) | char16_t, char32_t ou (depuis C++11)]wchar_t, val peut être converti selon les règles spécifiées au point (3) ;
  • sinon, si le rang de conversion entière de T est inférieur au rang de int :
    • val peut être converti en une prvalue de type int si int peut représenter toutes les valeurs de T ;
    • sinon, val peut être converti en une prvalue de type unsigned int.
  1. Dans les cas spécifiés par le point (1) (un champ de bits converti ne rentrant pas dans unsigned int) ou le point (2) (T est l'un des types caractère donnés), val peut être converti en une prvalue du premier des types suivants pouvant représenter toutes les valeurs de son type sous-jacent :
  • int
  • unsigned int
  • long
  • unsigned long
  • long long
  • unsigned long long
  • le type sous-jacent de T

(depuis C++11)

Promotion à partir des types énumération

Une prvalue d'une énumération non scopée dont le type sous-jacent n'est pas fixé peut être convertie en une prvalue du premier type de la liste suivante capable de contenir toute son étendue de valeurs :

  • int
  • unsigned int
  • long
  • unsigned long
  • long long
  • unsigned long long
  • le type d'entier étendu tel que
  • son rang de conversion entier est supérieur au rang de long long,
  • son rang de conversion entier est le plus bas parmi tous les types d'entiers étendus, et
  • il est signé s'il existe deux types ayant le rang de conversion entier le plus bas parmi tous les types d'entiers étendus.

(depuis C++11)

Une prvalue d'un type énumération non scopé dont le type sous-jacent est fixe peut être convertie en son type sous-jacent. De plus, si le type sous-jacent est aussi soumis à la promotion intégrale, en le type sous-jacent promu. La conversion vers le type sous-jacent non promu est préférable pour les besoins de la résolution de surcharge.

(depuis C++11)

Promotion flottante

Une prvalue de type float peut être convertie en une prvalue de type double. La valeur ne change pas.

Cette conversion est appelée promotion flottante.

Conversions numériques

Contrairement aux promotions, les conversions numériques peuvent modifier les valeurs, avec une perte de précision potentielle.

Conversions entières

Une prvalue d'un type entier ou d'un type énumération non scopé peut être convertie en tout autre type entier. Si la conversion figure parmi les promotions intégrales, il s'agit d'une promotion et non d'une conversion.

  • Si le type de destination est non signé, la valeur résultante est la plus petite valeur non signée égale à la valeur source modulo 2n
    , où n est le nombre de bits utilisés pour représenter le type de destination.

    • Autrement dit, selon que le type de destination est plus large ou plus étroit, les entiers signés sont étendus par extension de signe[1] ou tronqués, et les entiers non signés sont étendus par des zéros ou tronqués, respectivement.

  • Si le type de destination est signé, la valeur ne change pas si l'entier source peut être représenté dans le type de destination. Sinon le résultat est [défini par l'implémentation (jusqu'à C++20) | la valeur unique du type de destination égale à la valeur source modulo 2n
    , où n est le nombre de bits utilisés pour représenter le type de destination (depuis C++20)] (notez que ceci diffère du dépassement de capacité arithmétique d'un entier signé, qui est un comportement indéfini).

  • Si le type source est bool, la valeur false est convertie en zéro et la valeur true est convertie en la valeur un du type de destination (notez que si le type de destination est int, il s'agit d'une promotion entière et non d'une conversion entière).

  • Si le type de destination est bool, il s'agit d'une conversion booléenne (voir ci-dessous).

  1. ↑ Ceci ne s'applique que si l'arithmétique est en complément à deux, ce qui n'est requis que pour les types entiers de largeur exacte. Notez toutefois qu'actuellement, toutes les plateformes disposant d'un compilateur C++ utilisent l'arithmétique en complément à deux.

Conversions flottantes

Une prvalue d'un type flottant peut être convertie en une prvalue de tout autre type flottant.

(jusqu'à C++23)

Une prvalue d'un type flottant peut être convertie en une prvalue de tout autre type flottant ayant un rang de conversion flottante supérieur ou égal.

Une prvalue d'un type flottant standard peut être convertie en une prvalue de tout autre type flottant standard.

static_cast peut être utilisé pour convertir explicitement une prvalue de type flottant en tout autre type flottant.

(depuis C++23)

Si la conversion figure parmi les promotions flottantes, il s'agit d'une promotion et non d'une conversion.

  • Si la valeur source peut être représentée exactement dans le type de destination, elle ne change pas.
  • Si la valeur source est comprise entre deux valeurs représentables du type de destination, le résultat est l'une de ces deux valeurs (lequel est défini par l'implémentation, bien que si l'arithmétique IEEE est supportée, l'arrondi se fasse par défaut au plus proche).
  • Dans le cas contraire, le comportement est indéfini.

Conversions flottant–entier

Une prvalue de type flottant peut être convertie en une prvalue de tout type entier. La partie fractionnaire est tronquée, c'est-à-dire qu'elle est supprimée.

  • Si la valeur tronquée ne peut pas tenir dans le type de destination, le comportement est indéfini (même lorsque le type de destination est non signé, l'arithmétique modulo ne s'applique pas).
  • Si le type de destination est bool, il s'agit d'une conversion booléenne (voir ci-dessous).

Une prvalue de type entier ou énumération non scopé peut être convertie en une prvalue de tout type flottant. Le résultat est exact si possible.

  • Si la valeur peut tenir dans le type de destination mais ne peut pas être représentée exactement, il est défini par l'implémentation de savoir si la valeur représentable immédiatement supérieure ou immédiatement inférieure sera choisie, bien que si l'arithmétique IEEE est supportée, l'arrondi se fasse par défaut au plus proche.
  • Si la valeur ne peut pas tenir dans le type de destination, le comportement est indéfini.
  • Si le type source est bool, la valeur false est convertie en zéro, et la valeur true est convertie en un.

Conversions de pointeurs

Une constante de pointeur nul peut être convertie en tout type pointeur, et le résultat est la valeur de pointeur nul de ce type. Cette conversion (connue sous le nom de conversion de pointeur nul) peut convertir vers un type qualifié cv en une seule conversion, c'est-à-dire qu'elle n'est pas considérée comme une combinaison de conversions numériques et de qualification.

Une prvalue pointeur vers tout type objet (éventuellement qualifié cv) T peut être convertie en une prvalue pointeur vers void (identiquement qualifié cv). Le pointeur résultant représente le même emplacement mémoire que la valeur de pointeur d'origine.

  • Si le pointeur d'origine est une valeur de pointeur nul, le résultat est une valeur de pointeur nul du type de destination.

Une prvalue ptr de type « pointeur vers Derived (éventuellement qualifié cv) » peut être convertie en une prvalue de type « pointeur vers Base (éventuellement qualifié cv) », où Base est une classe de base de Derived, et Derived est un type de classe complet. Si le Base est inaccessible ou ambigu, le programme est mal formé.

  • Si ptr est une valeur de pointeur nul, le résultat est également une valeur de pointeur nul.
  • Sinon, si Base est une classe de base virtuelle de Derived et que ptr ne pointe pas vers un objet dont le type est similaire à Derived et qui est dans sa durée de vie ou dans sa période de construction ou de destruction, le comportement est indéfini.
  • Sinon, le résultat est un pointeur vers le sous-objet de classe de base de l'objet de la classe dérivée.

Conversions de pointeurs vers membre

Une constante de pointeur nul peut être convertie en tout type pointeur vers membre, et le résultat est la valeur de pointeur vers membre nul de ce type. Cette conversion (connue sous le nom de conversion de pointeur vers membre nul) peut convertir vers un type qualifié cv en une seule conversion, c'est-à-dire qu'elle n'est pas considérée comme une combinaison de conversions numériques et de qualification.

Une prvalue de type « pointeur vers membre de Base de type (éventuellement qualifié cv) T » peut être convertie en une prvalue de type « pointeur vers membre de Derived de type (identiquement qualifié cv) T », où Base est une classe de base de Derived, et Derived est un type de classe complet. Si Base est inaccessible, ambigu, ou une base virtuelle de Derived, ou est une base d'une base virtuelle intermédiaire de Derived, le programme est mal formé.

  • Si Derived ne contient pas le membre d'origine et n'est pas une classe de base de la classe contenant le membre d'origine, le comportement est indéfini.
  • Sinon, le pointeur résultant peut être déréférencé avec un objet Derived, et il accédera au membre à l'intérieur du sous-objet de base Base de cet objet Derived.

Conversions booléennes

Une prvalue de types entier, flottant, énumération non scopée, pointeur et pointeur vers membre peut être convertie en une prvalue de type bool.

La valeur zéro (pour les types entier, flottant et énumération non scopée), ainsi que la valeur de pointeur nul et la valeur de pointeur vers membre nul, deviennent false. Toutes les autres valeurs deviennent true.

Dans le contexte d'une initialisation directe, un objet bool peut être initialisé à partir d'une prvalue de type std::nullptr_t, y compris nullptr. La valeur résultante est false. Cependant, ceci n'est pas considéré comme une conversion implicite.

(depuis C++11)

Conversions de qualification

De manière générale :

  • Une prvalue de type pointeur vers un type qualifié cv T peut être convertie en une prvalue pointeur vers le même type plus qualifié cv T (autrement dit, la constance et la volatilité peuvent être ajoutées).
  • Une prvalue de type pointeur vers membre de type qualifié cv T dans la classe X peut être convertie en une prvalue pointeur vers membre de type plus qualifié cv T dans la classe X.

La définition formelle de « conversion de qualification » est donnée ci-dessous.

Types similaires

Informellement, deux types sont similaires si, en ignorant la qualification cv de premier niveau :

  • ils sont le même type ; ou
  • ils sont tous deux des pointeurs, et les types pointés sont similaires ; ou
  • ils sont tous deux des pointeurs vers membre de la même classe, et les types des membres pointés sont similaires ; ou
  • ils sont tous deux des tableaux et les types des éléments de tableau sont similaires.

Par exemple :

  • const int* const * et int** sont similaires ;
  • int (*)(int*) et int (*)(const int*) ne sont pas similaires ;
  • const int (*)(int*) et int (*)(int*) ne sont pas similaires ;
  • int (*)(int* const) et int (*)(int*) sont similaires (ce sont le même type) ;
  • std::pair<int, int> et std::pair<const int, int> ne sont pas similaires.

Formellement, la similarité de types est définie en termes de décomposition de qualification.

Une décomposition de qualification d'un type T est une suite de composants cv_i et P_i telle que T est « cv_0 P_0 cv_1 P_1 ... cv_n−1 P_n−1 cv_n U » pour des n non négatifs, où

  • chaque cv_i est un ensemble de const et de volatile, et
  • chaque P_i est
    • « pointeur vers »,
    • « pointeur vers membre de la classe C_i de type »,
    • « tableau de N_i », ou
    • « tableau de borne inconnue de ».

Si P_i désigne un tableau, les qualificateurs cv cv_i+1 sur le type d'élément sont également pris comme qualificateurs cv cv_i du tableau.

// T est « pointeur vers pointeur vers const int », elle possède 3 décompositions de qualification :
// n = 0 -> cv_0 est vide, U est « pointeur vers pointeur vers const int »
// n = 1 -> cv_0 est vide, P_0 est « pointeur vers »,
//          cv_1 est vide, U est « pointeur vers const int »
// n = 2 -> cv_0 est vide, P_0 est « pointeur vers »,
//          cv_1 est vide, P_1 est « pointeur vers »,
//          cv_2 est « const », U est « int »
using T = const int**;

// remplacer U par l'un des types suivants donne l'une des décompositions :
// U = U0 -> la décomposition avec n = 0 : U0
// U = U1 -> la décomposition avec n = 1 : pointeur vers [U1]
// U = U2 -> la décomposition avec n = 2 : pointeur vers [pointeur vers [const U2]]
using U2 = int;
using U1 = const U2*;
using U0 = U1*;

Deux types T1 et T2 sont similaires s'il existe une décomposition de qualification pour chacun d'eux, où toutes les conditions suivantes sont satisfaites pour les deux décompositions de qualification :

  • Elles ont les mêmes n.
  • Les types désignés par U sont les mêmes.
  • Les composants P_i correspondants sont identiques ou l'un est « tableau de N_i » et l'autre est « tableau de borne inconnue de » (depuis C++20) pour tout i.
// la décomposition de qualification avec n = 2 :
// pointeur vers [pointeur volatile vers [const int]]
using T1 = const int* volatile *;

// la décomposition de qualification avec n = 2 :
// pointeur const vers [pointeur vers [int]]
using T2 = int** const;

// Pour les deux décompositions de qualification ci-dessus
// bien que cv_0, cv_1 et cv_2 soient tous différents,
// elles ont le même n, U, P_0 et P_1,
// donc les types T1 et T2 sont semblables.

Combinaison des qualifications cv

Dans la description ci-dessous, la décomposition de qualification la plus longue du type Tn est notée Dn, et ses composants sont notés cvn_i et Pn_i.

Une expression prvalue de type T1 peut être convertie en type T2 si toutes les conditions suivantes sont satisfaites :

  • T1 et T2 sont similaires.
  • Pour tout i non nul, si const est dans cv1_i, alors const est aussi dans cv2_i, et de même pour volatile.
  • Pour tout i non nul, si cv1_i et cv2_i sont différents, alors const est dans cv2_k pour chaque k dans [1,i).

Le type combiné de qualification de deux types T1 et T2 est un type T3 similaire à T1 tel que

  • cv3_0 est vide,
  • pour tout i non nul, cv3_i est l'union de cv1_i et cv2_i, et
  • si cv3_i est différent de cv1_i ou c2_i, alors const est ajouté à cv3_k pour chaque k dans [1,i).

(jusqu'à C++20)

Le type combiné de qualification de deux types T1 et T2 est un type T3 similaire à T1, où D3 satisfait toutes les conditions suivantes :

  • cv3_0 est vide.
  • Pour tout i non nul, cv3_i est l'union de cv1_i et cv2_i.
  • Si P1_i ou P2_i est « tableau de borne inconnue de », P3_i est « tableau de borne inconnue de », sinon il vaut P1_i.
  • Si cv3_i est différent de cv1_i ou cv2_i, ou si P3_i est différent de P1_i ou P2_i, alors const est ajouté à cv3_k pour chaque k dans [1,i).

Une prvalue de type T1 peut être convertie en type T2 si le type combiné de qualification de T1 et T2 est T2 non qualifié cv.

(depuis C++20)

// décomposition de qualification la plus longue de T1 (n = 2) :
// pointeur vers [pointeur vers [char]]
using T1 = char**;

// décomposition de qualification la plus longue de T2 (n = 2) :
// pointeur vers [pointeur vers [const char]]
using T2 = const char**;

// Détermination des composantes cv3_i et T_i de D3 (n = 2) :
// cv3_1 = vide (union de cv1_1 vide et cv2_1 vide)
// cv3_2 = « const » (union de cv1_2 vide et cv2_2 « const »)
// P3_0 = « pointeur vers » (pas de tableau de borne inconnue, utiliser P1_0)
// P3_1 = « pointeur vers » (pas de tableau de borne inconnue, utiliser P1_1)
// Toutes les composantes sauf cv_2 sont identiques, cv3_2 est différent de cv1_2,
// donc on ajoute « const » à cv3_k pour chaque k dans [1, 2) : cv3_1 devient « const ».
// T3 est « pointeur vers const pointeur vers const char », c'est-à-dire const char* const *.
using T3 = /* le type combiné de qualification de T1 et T2 */;

int main()
{
    const char c = 'c';
    char* pc;
    T1 ppc = &pc;
    T2 pcc = ppc; // Erreur : T3 n'est pas identique à T2 sans qualification cv,
                  //        aucune conversion implicite.

    *pcc = &c;
    *pc = 'C';    // Si l'affectation erronée ci-dessus était autorisée,
                  // l'objet const « c » pourrait être modifié.
}

Notez qu'en langage C, const/volatile ne peut être ajouté qu'au premier niveau :

char** p = 0;
char * const* p1 = p;       // OK en C et en C++
const char* const * p2 = p; // erreur en C, OK en C++

Conversions de pointeurs de fonction

  • Une prvalue de type pointeur vers fonction non lançante peut être convertie en prvalue de pointeur vers fonction potentiellement lançante.
  • Une prvalue de type pointeur vers fonction membre non lançante peut être convertie en prvalue de pointeur vers fonction membre potentiellement lançante.
void (*p)();
void (**pp)() noexcept = &p; // erreur : impossible de convertir en pointeur vers fonction noexcept

struct S
{
    typedef void (*p)();
    operator p();
};
void (*q)() noexcept = S(); // erreur : impossible de convertir en pointeur vers fonction noexcept

(depuis C++17)

Le problème du safe bool

Jusqu'à C++11, concevoir une classe devant être utilisable dans des contextes booléens (par ex. if (obj) { ... }) posait un problème : étant donnée une fonction de conversion définie par l'utilisateur, telle que T::operator bool() const;, la séquence de conversion implicite autorisait une conversion standard supplémentaire après cet appel de fonction, ce qui signifie que le bool résultant pouvait être converti en int, permettant du code tel que obj << 1; ou int i = obj;.

Une des premières solutions se trouve dans std::basic_ios, qui définit initialement operator void*, de sorte que du code tel que if (std::cin) {...} compile parce que void* est convertible en bool, mais int n = std::cout; ne compile pas parce que void* n'est pas convertible en int. Cela permet encore à du code absurde tel que delete std::cout; de compiler.

De nombreuses bibliothèques tierces antérieures à C++11 ont été conçues avec une solution plus élaborée, connue sous le nom d'idiome Safe Bool. std::basic_ios autorisait aussi cet idiome via LWG issue 468, et operator void* a été remplacé (voir notes).

Depuis C++11, la conversion explicite en bool peut aussi être utilisée pour résoudre le problème du safe bool.
