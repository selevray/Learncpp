Initialisation par défaut

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

C'est l'initialisation effectuée lorsqu'un objet est construit sans initialiseur.

Syntaxe

| | | | T object ﻿; | (1) | | | | new T | (2) | | |

Explication

L'initialisation par défaut est effectuée dans trois situations :

  1. lorsqu'une variable à durée de stockage automatique, statique ou thread_local est déclarée sans initialiseur ;

  2. lorsqu'un objet à durée de stockage dynamique est créé par une expression new sans initialiseur ;

  3. lorsqu'une base ou un membre de donnée non statique n'est pas mentionné dans une liste d'initialisation du constructeur et que ce constructeur est appelé.

Les effets de l'initialisation par défaut sont :

  • si T est un type classe non POD (jusqu'à C++11) (éventuellement qualifié cv), les constructeurs sont considérés et soumis à la résolution de surcharge avec la liste d'arguments vide. Le constructeur sélectionné (qui est l'un des constructeurs par défaut) est appelé pour fournir la valeur initiale du nouvel objet ;
  • si T est un type tableau, chaque élément du tableau est initialisé par défaut ;
  • sinon, aucune initialisation n'est effectuée (voir notes).

Seuls les types classe non POD (éventuellement qualifiés cv) (ou tableaux de ceux-ci) à durée de stockage automatique étaient considérés comme initialisés par défaut lorsqu'aucun initialiseur n'est utilisé. Les scalaires et les types POD à durée de stockage dynamique étaient considérés comme non initialisés (depuis C++11, cette situation a été reclassée comme une forme d'initialisation par défaut).
