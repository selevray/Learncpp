Constructeurs et listes d'initialisation des membres

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les constructeurs sont des fonctions membres non statiques déclarées avec une syntaxe de déclarateur particulière ; ils servent à initialiser les objets de leurs types de classe.

Un constructeur ne peut pas être une coroutine.

(depuis C++20)

Un constructeur ne peut pas avoir de paramètre d'objet explicite.

(depuis C++23)

Syntaxe

Les constructeurs sont déclarés à l'aide de déclarateurs de fonctions membres de la forme suivante :

| | | | class-name ( parameter-list ﻿*(optionnel)* ) except ﻿*(optionnel)* attr ﻿*(optionnel)* | | | |

  • class-name — une expression d'identifiant,éventuellement suivie d'une liste d'attributs, et (depuis C++11) éventuellement entourée d'une paire de parenthèses

  • parameter-list — liste de paramètres

  • except —

    spécification d'exceptions dynamique

    (jusqu'à C++11)

    soit une spécification d'exception dynamique
    ou une spécification noexcept

    (depuis C++11) (jusqu'à C++17)

    spécification noexcept

    (depuis C++17)

  • attr — (depuis C++11) une liste d'attributs

Les seuls spécificateurs autorisés dans les spécificateurs de déclaration d'une déclaration de constructeur sont friend, inline[, constexpr (depuis C++11) | , consteval (depuis C++20)], et explicit (en particulier, aucun type de retour n'est autorisé). Notez que les qualificateurs cv et de référence ne sont pas non plus autorisés : la sémantique const et volatile d'un objet en cours de construction ne s'applique qu'après la fin du constructeur le plus dérivé.

L'expression d'identifiant de class-name doit avoir l'une des formes suivantes :

  • Dans une déclaration d'amitié, l'expression d'identifiant est un identifiant qualifié qui désigne un constructeur.

  • Sinon, dans une déclaration de membre appartenant à la spécification de membres d'une classe ou d'un modèle de classe :

    • Pour les classes, l'expression d'identifiant est le nom de classe injecté de la classe englobante immédiate.
    • Pour les modèles de classes, l'expression d'identifiant est [un nom de classe qui désigne l'instanciation courante (jusqu'à C++20) | le nom de classe injecté (depuis C++20)] du modèle de classe englobant immédiat.

  • Sinon, l'expression d'identifiant est un identifiant qualifié dont l'identifiant non qualifié terminal est le nom de classe injecté de son contexte de recherche.

Liste d'initialisation des membres

Le corps de la définition de fonction de tout constructeur, avant l'accolade ouvrante de l'instruction composée, peut comprendre la liste d'initialisation des membres, dont la syntaxe est le caractère deux-points :, suivi de la liste, séparée par des virgules, d'un ou plusieurs member-initializers, chacun ayant la syntaxe suivante :

| | | | class-or-identifier ( expression-list ﻿*(facultatif)* ) | (1) | | | | class-or-identifier braced-init-list | (2) | (depuis C++11) | | | parameter-pack ... | (3) | (depuis C++11) | |

  1. Initialise la base ou le membre désigné par class-or-identifier en utilisant une initialisation directe ou, si expression-list est vide, une initialisation par valeur

  2. Initialise la base ou le membre désigné par class-or-identifier en utilisant une initialisation par liste (qui devient une initialisation par valeur si la liste est vide, et une initialisation d'agrégat lors de l'initialisation d'un agrégat)

  3. Initialise plusieurs bases à l'aide d'une expansion de paquet

  • class-or-identifier — tout identifiant désignant un membre de données non statique, ou tout nom de type désignant soit la classe elle-même (pour les constructeurs délégants), soit une base directe ou virtuelle.
  • expression-list — liste éventuellement vide, séparée par des virgules, des arguments à passer au constructeur de la base ou du membre
  • braced-init-list — liste d'initialisation entre accolades
  • parameter-pack — nom d'un paquet de paramètres de modèle variadique
struct S
{
    int n;

    S(int);       // déclaration de constructeur

    S() : n(7) {} // définition de constructeur :
                  // ": n(7)" est la liste d'initialisation
                  // ": n(7) {}" est le corps de la fonction
};

S::S(int x) : n{x} {} // définition de constructeur : ": n{x}" est la liste d'initialisation

int main()
{
    S s;      // appelle S::S()
    S s2(10); // appelle S::S(int)
}

Explication

Les constructeurs n'ont pas de nom et ne peuvent pas être appelés directement. Ils sont invoqués lorsqu'une initialisation a lieu, et ils sont sélectionnés selon les règles d'initialisation. Les constructeurs sans spécificateur explicit sont des constructeurs de conversion. Les constructeurs avec un spécificateur constexpr font de leur type un LiteralType. Les constructeurs pouvant être appelés sans argument sont des constructeurs par défaut. Les constructeurs qui prennent en argument un autre objet du même type sont des constructeurs de copie et des constructeurs de déplacement.

Avant que l'instruction composée formant le corps de la fonction du constructeur ne commence à s'exécuter, l'initialisation de toutes les bases directes, de toutes les bases virtuelles et de tous les membres de données non statiques est terminée. La liste d'initialisation des membres est l'endroit où l'initialisation non par défaut de ces sous-objets peut être spécifiée. Pour les bases qui ne peuvent pas être initialisées par défaut et pour les membres de données non statiques qui ne peuvent pas être initialisés par initialisation par défaut ou par leur initialiseur de membre par défaut, s'il existe (depuis C++11), comme les membres de types référence et qualifiés const, des initialiseurs de membres doivent être spécifiés. (Notez que les initialiseurs de membres par défaut des membres de données non statiques d'instanciations de modèles de classes peuvent être invalides si le type du membre ou l'initialiseur est dépendant.) (depuis C++11) Aucune initialisation n'est effectuée pour les unions anonymes ou les membres de variant qui n'ont pas d'initialiseur de membre ni d'initialiseur de membre par défaut (depuis C++11).

Les initialiseurs où class-or-identifier désigne une classe de base virtuelle sont ignorés lors de la construction de toute classe qui n'est pas la classe la plus dérivée de l'objet en cours de construction.

Les noms qui apparaissent dans expression-list ou braced-init-list sont évalués dans la portée du constructeur :

class X
{
    int a, b, i, j;
public:
    const int& r;
    X(int i)
      : r(a) // initialise X::r pour qu'il référence X::a
      , b{i} // initialise X::b avec la valeur du paramètre i
      , i(i) // initialise X::i avec la valeur du paramètre i
      , j(this->i) // initialise X::j avec la valeur de X::i
    {}
};

Les exceptions levées par les initialiseurs de membres peuvent être traitées par un bloc function-try-block try.

Les fonctions membres (y compris les fonctions membres virtuelles) peuvent être appelées depuis les initialiseurs de membres, mais le comportement est indéfini si toutes les bases directes ne sont pas initialisées à ce point.

Pour les appels virtuels (si les bases directes sont initialisées à ce point), les mêmes règles s'appliquent que pour les appels virtuels depuis les constructeurs et les destructeurs : les fonctions membres virtuelles se comportent comme si le type dynamique de *this était le type statique de la classe en cours de construction (la liaison dynamique ne se propage pas vers le bas de la hiérarchie d'héritage), et les appels virtuels (mais non les appels statiques) aux fonctions membres virtuelles pures constituent un comportement indéfini.

Si un membre de données non statique possède un initialiseur de membre par défaut et figure aussi dans une liste d'initialisation des membres, c'est l'initialiseur de membre qui est utilisé, et l'initialiseur de membre par défaut est ignoré :

struct S
{
    int n = 42;   // initialiseur de membre par défaut
    S() : n(7) {} // affectera 7 à n, et non 42
};

(depuis C++11)

Les membres de type référence ne peuvent pas être liés à des temporaires dans une liste d'initialisation des membres :

struct A
{
    A() : v(42) {} // Erreur
    const int& v;
};

Note : la même règle s'applique à l'initialiseur de membre par défaut.

Constructeur délégant

Si le nom de la classe elle-même apparaît comme class-or-identifier dans la liste d'initialisation des membres, cette liste doit ne consister qu'en cet unique initialiseur de membre ; un tel constructeur est appelé constructeur délégant, et le constructeur sélectionné par l'unique membre de la liste d'initialisation est le constructeur cible.

Dans ce cas, le constructeur cible est sélectionné par résolution de surcharge et exécuté en premier, puis le contrôle revient au constructeur délégant et son corps est exécuté.

Les constructeurs délégants ne peuvent pas être récursifs.

class Foo
{
public:
    Foo(char x, int y) {}
    Foo(int y) : Foo('a', y) {} // Foo(int) délègue à Foo(char, int)
};

Ordre d'initialisation

L'ordre des initialiseurs de membres dans la liste n'a pas d'importance : l'ordre réel d'initialisation est le suivant :

  1. Si le constructeur appartient à la classe la plus dérivée, les bases virtuelles sont initialisées dans l'ordre où elles apparaissent lors du parcours en profondeur de gauche à droite des déclarations de classes de base (de gauche à droite se réfère à l'ordre d'apparition dans les listes de spécificateurs de base).

  2. Puis, les bases directes sont initialisées de gauche à droite, dans l'ordre où elles apparaissent dans la liste de spécificateurs de base de cette classe.

  3. Puis, les membres de données non statiques sont initialisés dans l'ordre de leur déclaration dans la définition de la classe.

  4. Enfin, le corps du constructeur est exécuté.

(Note : si l'ordre d'initialisation était contrôlé par l'ordre d'apparition dans les listes d'initialisation des membres de différents constructeurs, le destructeur ne pourrait pas garantir que l'ordre de destruction est l'inverse de l'ordre de construction.)

Exemple

#include <fstream>
#include <string>
#include <mutex>

struct Base
{
    int n;
};

struct Class : public Base
{
    unsigned char x;
    unsigned char y;
    std::mutex m;
    std::lock_guard<std::mutex> lg;
    std::fstream f;
    std::string s;

    Class(int x) : Base{123}, // initialise la classe de base
        x(x),     // x (membre) est initialisé avec x (paramètre)
        y{0},     // y initialisé à 0
        f{"test.cc", std::ios::app}, // ceci a lieu après l'initialisation de m et lg
        s(__func__), // __func__ est disponible car la liste d'initialisation fait partie du constructeur
        lg(m),    // lg utilise m, qui est déjà initialisé
        m{}       // m est initialisé avant lg bien qu'il apparaisse en dernier ici
    {}            // instruction composée vide

    Class(double a) : y(a + 1),
        x(y), // x sera initialisé avant y, sa valeur ici est indéterminée
        lg(m)
    {} // l'initialiseur de la classe de base n'apparaît pas dans la liste, il est
       // initialisé par défaut (différent de Base() qui réalise une initialisation par valeur)

    Class()
    try // le bloc try de fonction commence avant le corps de la fonction, qui comprend la liste d'initialisation
      : Class(0.0) // constructeur délégant
    {
        // ...
    }
    catch (...)
    {
        // une exception s'est produite lors de l'initialisation
    }
};

int main()
{
    Class c;
    Class c1(1);
    Class c2(0.1);
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 194 C++98 la syntaxe de déclarateur d'un constructeur n'autorisait qu'au plus un spécificateur de fonction (par ex. un constructeur ne pouvait pas être déclaré inline explicit) plusieurs spécificateurs de fonction autorisés
CWG 257 C++98 il n'était pas précisé si une classe abstraite devait fournir des initialiseurs de membres pour ses classes de base virtuelles spécifié comme non requis et de tels initialiseurs de membres sont ignorés lors de l'exécution
CWG 263 C++98 la syntaxe de déclarateur d'un constructeur interdisait aux constructeurs d'être amis autorisé aux constructeurs d'être amis
CWG 1345 C++98 les membres d'union anonyme sans initialiseur de membre par défaut étaient initialisés par défaut ils ne sont pas initialisés
CWG 1435 C++98 le sens de « nom de classe » dans la syntaxe de déclarateur d'un constructeur était peu clair la syntaxe a été changée en une syntaxe de déclarateur de fonction spécialisée
