Séquence de spécificateurs d'attributs (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Introduit des attributs définis par l'implémentation pour les types, objets, code, etc.

Syntaxe

| | | | [[ attribute-list ]] | | (depuis C++11) | | | [[ using attribute-namespace : attribute-list ]] | | (depuis C++17) | |

où attribute-list est une liste séparée par des virgules de zéro ou plusieurs attribute (pouvant se terminer par une ellipse ... indiquant une expansion de paquet)

| | | | identifier | (1) | | | | attribute-namespace :: identifier | (2) | | | | identifier ( argument-list ﻿*(facultatif)* ) | (3) | | | | attribute-namespace :: identifier ( argument-list ﻿*(facultatif)* ) | (4) | | |

où attribute-namespace est un identifier et argument-list est une séquence de jetons où les parenthèses, crochets et accolades sont équilibrés (balanced-token-seq).

  1. Attribut simple, comme [[noreturn]].

  2. Attribut avec un espace de noms, comme [[gnu::unused]].

  3. Attribut avec arguments, comme [[deprecated("because")]].

  4. Attribut avec à la fois un espace de noms et une liste d'arguments.

Si using namespace: apparaît au début d'une liste d'attributs, aucun autre attribut de cette liste ne peut spécifier un espace de noms : l'espace de noms spécifié dans un using s'applique à tous :

[[using CC: opt(1), debug]] // identique à [[CC::opt(1), CC::debug]]
[[using CC: CC::opt(1)]] // erreur : impossible de combiner using et un attribut à portée

(depuis C++17)

Explication

Les attributs fournissent la syntaxe standard unifiée pour les extensions de langage définies par l'implémentation, comme les extensions de langage GNU et IBM __attribute__((...)), l'extension Microsoft __declspec(), etc.

Un attribut peut être utilisé presque partout dans le programme C++, et s'appliquer presque à tout : aux types, aux variables, aux fonctions, aux noms, aux blocs de code, à des unités de traduction entières, bien que chaque attribut particulier ne soit valide que là où l'implémentation le permet : [[expect_true]] pourrait être un attribut utilisable uniquement avec une if, et non avec une déclaration de classe. [[omp::parallel()]] pourrait être un attribut s'appliquant à un bloc de code ou à une boucle for, mais non au type int, etc. (notez que ces deux attributs sont des exemples fictifs, voir plus bas les attributs standard et certains attributs non standard).

Dans les déclarations, les attributs peuvent apparaître à la fois avant la déclaration entière et directement après le nom de l'entité déclarée, auquel cas ils sont combinés. Dans la plupart des autres situations, les attributs s'appliquent à l'entité qui les précède directement.

Le alignas spécificateur fait partie de la séquence de spécificateurs d'attributs, bien qu'il ait une syntaxe différente. Il peut apparaître là où apparaissent les attributs [[...]] et se mélanger avec eux (à condition d'être utilisé là où alignas est permis).

Deux jetons consécutifs de crochet gauche ([[) ne peuvent apparaître que lors de l'introduction d'un spécificateur d'attribut ou à l'intérieur d'un argument d'attribut.

void f()
{
    int y[3];
    y[[] { return 0; }()] = 1;  // error
    int i [[cats::meow([[]])]]; // OK
}

Outre les attributs standard listés ci-dessous, les implémentations peuvent prendre en charge des attributs non standard arbitraires au comportement défini par l'implémentation. Tous les attributs inconnus d'une implémentation sont ignorés sans provoquer d'erreur. (depuis C++17)

Un attribut sans attribute-namespace et sans attribute-namespace dont le nom est soit std soit std suivi d'un ou plusieurs chiffres est réservé pour une future standardisation. Autrement dit, chaque attribut non standard appartient à l'attribute-namespace fourni par l'implémentation, par exemple [[gnu::may_alias]], [[clang::trivial_abi]] et [[msvc::noop_dtor]].

(depuis C++20)

Attributs standard

Les attributs suivants sont définis par le standard C++.

Les attributs standard ne peuvent pas être ignorés syntaxiquement : ils ne peuvent pas contenir d'erreurs de syntaxe, doivent être appliqués à la bonne cible, et les entités figurant dans les arguments doivent être utilisées en ODR.

Les attributs standard ne peuvent pas non plus être ignorés sémantiquement : le comportement obtenu avec toutes les instances d'un attribut standard particulier supprimées aurait été un comportement conforme pour le programme original avec l'attribut présent.

  • [[noreturn]] (C++11) — indique que la fonction ne retourne pas (spécificateur d'attribut)
  • [[carries_dependency]] (C++11) — indique que la chaîne de dépendance dans release-consume std::memory_order se propage vers l'intérieur et vers l'extérieur de la fonction (spécificateur d'attribut)
  • [[deprecated]] (C++14)
    [[deprecated("reason")]] (C++14)     — indique que l'utilisation du nom ou de l'entité déclarée avec cet attribut est autorisée, mais déconseillée pour certains reason (spécificateur d'attribut)
  • [[fallthrough]] (C++17) — indique que le passage du label de cas précédent (fall-through) est intentionnel et ne doit pas être signalé par un compilateur qui avertit des fall-through (spécificateur d'attribut)
  • [[maybe_unused]] (C++17) — supprime les avertissements du compilateur sur les entités inutilisées, le cas échéant (spécificateur d'attribut)
  • [[nodiscard]] (C++17)
    [[nodiscard("reason")]] (C++20)     — encourage le compilateur à émettre un avertissement si la valeur de retour est ignorée (spécificateur d'attribut)
  • [[likely]] (C++20)
    [[unlikely]] (C++20)     — indique que le compilateur doit optimiser le cas où un chemin d'exécution à travers une instruction est plus ou moins probable que tout autre chemin d'exécution (spécificateur d'attribut)
  • [[no_unique_address]] (C++20) — indique qu'un membre de données non statique n'a pas besoin d'avoir une adresse distincte de tous les autres membres de données non statiques de sa classe (spécificateur d'attribut)
  • [[assume(expression)]] (C++23) — spécifie que l'expression s'évaluera toujours à true en un point donné (spécificateur d'attribut)
  • [[indeterminate]] (C++26) — spécifie qu'un objet a une valeur indéterminée s'il n'est pas initialisé (spécificateur d'attribut)
  • [[optimize_for_synchronized]] (TM TS) — indique que la définition de la fonction doit être optimisée pour un appel depuis une instruction synchronized (spécificateur d'attribut)

Notes

La présence de chaque attribut individuel sur une plateforme donnée peut être vérifiée avec la macro de prétraitement __has_cpp_attribute.

Macro de test de fonctionnalité Valeur Std Fonctionnalité
__cpp_attributes 200809L (C++11) Attributs
__cpp_namespace_attributes 201411L (C++17) Attributs pour les espaces de noms

Exemple

[[gnu::always_inline]] [[gnu::hot]] [[gnu::const]] [[nodiscard]]
inline int f(); // déclarer f avec quatre attributs

[[gnu::always_inline, gnu::const, gnu::hot, nodiscard]]
int f(); // identique à ci-dessus, mais utilise un seul spécificateur d'attribut qui contient quatre attributs

// C++17:
[[using gnu : const, always_inline, hot]] [[nodiscard]]
int f[[gnu::always_inline]](); // un attribut peut apparaître dans plusieurs spécificateurs

int f() { return 0; }

int main() {}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct

CWG 2538 C++11 il n'était pas clair si les attributs standard peuvent être ignorés syntaxiquement prohibited
CWG 2695 C++11 il n'était pas clair si les attributs standard peuvent être ignorés sémantiquement prohibited
