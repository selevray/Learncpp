Opérateur d'affectation par copie

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un opérateur d'affectation par copie est une fonction membre non statique non template dont le nom est operator=, qui peut être appelée avec un argument du même type de classe et qui copie le contenu de l'argument sans le modifier.

Syntaxe

Pour la syntaxe formelle de l'opérateur d'affectation par copie, voir déclaration de fonction. La liste de syntaxes ci-dessous ne présente qu'un sous-ensemble de toutes les syntaxes valides de l'opérateur d'affectation par copie.

| | | | return-type operator=(parameter-list ﻿); | (1) | | | | return-type operator=(parameter-list ﻿) function-body | (2) | | | | return-type operator=(parameter-list-no-default ﻿) = default; | (3) | (depuis C++11) | | | return-type operator=(parameter-list ﻿) = delete; | (4) | (depuis C++11) | | | return-type class-name ﻿::operator=(parameter-list ﻿) function-body | (5) | | | | return-type class-name ﻿::operator=(parameter-list-no-default ﻿) = default; | (6) | (depuis C++11) | |

  • class-name — la classe dont l'opérateur d'affectation par copie est déclaré ; le type de classe est noté T dans les descriptions ci-dessous
  • parameter-list — une liste de paramètres ne comportant qu'un seul paramètre, de type T, T&, const T&, volatile T& ou const volatile T&
  • parameter-list-no-default — une liste de paramètres ne comportant qu'un seul paramètre, de type T, T&, const T&, volatile T& ou const volatile T&, et n'ayant pas d'argument par défaut
  • function-body — le corps de fonction de l'opérateur d'affectation par copie
  • return-type — n'importe quel type, mais T& est privilégié afin de permettre l'enchaînement des affectations

Explication

  1. Déclaration d'un opérateur d'affectation par copie dans la définition de la classe.

2-4) Définition d'un opérateur d'affectation par copie dans la définition de la classe.

  1. L'opérateur d'affectation par copie est explicitement défini par défaut.

  2. L'opérateur d'affectation par copie est supprimé.

5,6) Définition d'un opérateur d'affectation par copie en dehors de la définition de la classe (la classe doit contenir une déclaration (1)).

  1. L'opérateur d'affectation par copie est explicitement défini par défaut.
struct X
{
    X& operator=(X& other);     // opérateur d'affectation par copie
    X operator=(X other);       // le passage par valeur est autorisé
//  X operator=(const X other); // Erreur : type de paramètre incorrect
};

union Y
{
    // les opérateurs d'affectation par copie peuvent avoir des syntaxes non listées ci-dessus,
    // tant qu'ils respectent la syntaxe générale des déclarations de fonctions
    // et ne violent pas les restrictions listées ci-dessus
    auto operator=(Y& other) -> Y&;       // OK : type de retour final
    Y& operator=(this Y& self, Y& other); // OK : paramètre d'objet explicite
//  Y& operator=(Y&, int num = 1);        // Erreur : possède d'autres paramètres non objets
};

L'opérateur d'affectation par copie est appelé chaque fois qu'il est sélectionné par la résolution de surcharge, par exemple lorsqu'un objet apparaît à gauche d'une expression d'affectation.

Opérateur d'affectation par copie implicitement déclaré

Si aucun opérateur d'affectation par copie défini par l'utilisateur n'est fourni pour un type classe, le compilateur en déclare toujours un comme membre inline public de la classe. Cet opérateur d'affectation par copie implicitement déclaré a la forme T& T::operator=(const T&) si toutes les conditions suivantes sont réunies :

  • chaque base directe B de T possède un opérateur d'affectation par copie dont les paramètres sont B, const B& ou const volatile B& ;
  • chaque membre de données non statique M de T, de type classe ou tableau de type classe, possède un opérateur d'affectation par copie dont les paramètres sont M, const M& ou const volatile M&.

Sinon, l'opérateur d'affectation par copie implicitement déclaré est déclaré comme T& T::operator=(T&).

En raison de ces règles, l'opérateur d'affectation par copie implicitement déclaré ne peut pas se lier à un argument lvalue volatile.

Une classe peut avoir plusieurs opérateurs d'affectation par copie, par exemple à la fois T& T::operator=(T&) et T& T::operator=(T). Si certains opérateurs d'affectation par copie définis par l'utilisateur sont présents, l'utilisateur peut tout de même forcer la génération de l'opérateur d'affectation par copie implicitement déclaré à l'aide du mot-clé default. (depuis C++11)

L'opérateur d'affectation par copie implicitement déclaré (ou défini par défaut lors de sa première déclaration) a une spécification d'exception décrite dans [spécification d'exception dynamique (jusqu'à C++17) | spécification noexcept (depuis C++17)]

Comme l'opérateur d'affectation par copie est toujours déclaré pour toute classe, l'opérateur d'affectation de la classe de base est toujours masqué. Si une déclaration using est utilisée pour importer l'opérateur d'affectation de la classe de base, et que son type d'argument pourrait être identique à celui de l'opérateur d'affectation implicite de la classe dérivée, la déclaration using est également masquée par la déclaration implicite.

Opérateur d'affectation par copie implicitement défini

Si l'opérateur d'affectation par copie implicitement déclaré n'est ni supprimé ni trivial, il est défini (c'est-à-dire qu'un corps de fonction est généré et compilé) par le compilateur si odr-usedou nécessaire à l'évaluation constante (depuis C++14). Pour les types union, l'opérateur d'affectation par copie implicitement défini copie la représentation de l'objet (comme par std::memmove). Pour les types classe non union, l'opérateur effectue une affectation par copie membre à membre des bases directes et des membres de données non statiques de l'objet, dans leur ordre d'initialisation, en utilisant l'affectation intégrée pour les scalaires, l'affectation par copie membre à membre pour les tableaux, et l'opérateur d'affectation par copie pour les types classe (appelé de manière non virtuelle).

L'opérateur d'affectation par copie implicitement défini pour une classe T est constexpr si

  • T est un type littéral, et
  • l'opérateur d'affectation sélectionné pour copier chaque sous-objet de base directe est une fonction constexpr, et
  • pour chaque membre de données non statique de T de type classe (ou tableau de ceux-ci), l'opérateur d'affectation sélectionné pour copier ce membre est une fonction constexpr.

(depuis C++14) (jusqu'à C++23)

L'opérateur d'affectation par copie implicitement défini pour une classe T est constexpr.

(depuis C++23)

La génération de l'opérateur d'affectation par copie implicitement défini est obsolète si T a un destructeur déclaré par l'utilisateur ou un constructeur de copie déclaré par l'utilisateur.

(depuis C++11)

Opérateur d'affectation par copie supprimé

L'opérateur d'affectation par copie implicitement déclaréou explicitement défini par défaut (depuis C++11) pour la classe T est [non défini (jusqu'à C++11) | défini comme supprimé (depuis C++11)] si l'une des conditions suivantes est satisfaite :

  • T possède un membre de données non statique d'un type non classe qualifié const (ou d'un tableau multidimensionnel de ce type).
  • T possède un membre de données non statique de type référence.
  • T possède un sous-objet potentiellement construit de type classe M (ou tableau multidimensionnel de ce type) tel que la résolution de surcharge appliquée pour trouver l'opérateur d'affectation par copie de M
    • ne produit aucun candidat utilisable, ou
    • dans le cas où le sous-objet est un membre variant, sélectionne une fonction non triviale.

L'opérateur d'affectation par copie implicitement déclaré pour la classe T est défini comme supprimé si T déclare un constructeur de déplacement ou un opérateur d'affectation par déplacement.

(depuis C++11)

Opérateur d'affectation par copie trivial

L'opérateur d'affectation par copie de la classe T est trivial si toutes les conditions suivantes sont vraies :

  • il n'est pas fourni par l'utilisateur (c'est-à-dire qu'il est implicitement défini ou défini par défaut) ;
  • T ne possède aucune fonction membre virtuelle ;
  • T ne possède aucune classe de base virtuelle ;
  • l'opérateur d'affectation par copie sélectionné pour chaque base directe de T est trivial ;
  • l'opérateur d'affectation par copie sélectionné pour chaque membre non statique de type classe (ou tableau de type classe) de T est trivial.

Un opérateur d'affectation par copie trivial copie la représentation de l'objet comme par std::memmove. Tous les types de données compatibles avec le langage C (types POD) sont trivialement affectables par copie.

Opérateur d'affectation par copie éligible

Un opérateur d'affectation par copie est éligible s'il est soit déclaré par l'utilisateur, soit à la fois implicitement déclaré et définissable.

(jusqu'à C++11)

Un opérateur d'affectation par copie est éligible s'il n'est pas supprimé.

(depuis C++11) (jusqu'à C++20)

Un opérateur d'affectation par copie est éligible si toutes les conditions suivantes sont satisfaites :

  • Il n'est pas supprimé.
  • Ses contraintes associées (le cas échéant) sont satisfaites.
  • Aucun opérateur d'affectation par copie dont les contraintes associées sont satisfaites n'est plus contraint.

(depuis C++20)

La trivialité des opérateurs d'affectation par copie éligibles détermine si la classe est un type trivialement copiable.

Notes

Si les opérateurs d'affectation par copie et par déplacement sont tous deux fournis, la résolution de surcharge sélectionne l'affectation par déplacement si l'argument est une rvalue (soit une prvalue telle qu'un temporaire sans nom, soit une xvalue telle que le résultat de std::move), et sélectionne l'affectation par copie si l'argument est une lvalue (objet nommé ou fonction/opérateur renvoyant une référence lvalue). Si seul l'opérateur d'affectation par copie est fourni, toutes les catégories d'arguments le sélectionnent (à condition qu'il prenne son argument par valeur ou par référence vers const, car les rvalues peuvent se lier à des références const), ce qui fait de l'affectation par copie le repli de l'affectation par déplacement lorsque celle-ci n'est pas disponible.

Il n'est pas spécifié si les sous-objets de classe de base virtuelle accessibles par plus d'un chemin dans le treillis d'héritage sont affectés plus d'une fois par l'opérateur d'affectation par copie défini implicitement (idem pour l'affectation par déplacement).

Voir surcharge de l'opérateur d'affectation pour plus de détails sur le comportement attendu d'un opérateur d'affectation par copie défini par l'utilisateur.

Exemple

#include <algorithm>
#include <iostream>
#include <memory>
#include <string>

struct A
{
    int n;
    std::string s1;

    A() = default;
    A(A const&) = default;

    // affectation par copie définie par l'utilisateur (idiome copy-and-swap)
    A& operator=(A other)
    {
        std::cout << "copy assignment of A\n";
        std::swap(n, other.n);
        std::swap(s1, other.s1);
        return *this;
    }
};

struct B : A
{
    std::string s2;
    // affectation par copie définie implicitement
};

struct C
{
    std::unique_ptr<int[]> data;
    std::size_t size;

    // affectation par copie définie par l'utilisateur (sans idiome copy-and-swap)
    // note : copy-and-swap réallouerait toujours les ressources
    C& operator=(const C& other)
    {
        if (this != &other) // pas une auto-affectation
        {
            if (size != other.size) // la ressource ne peut pas être réutilisée
            {
                data.reset(new int[other.size]);
                size = other.size;
            }
            std::copy(&other.data[0], &other.data[0] + size, &data[0]);
        }
        return *this;
    }
};

int main()
{
    A a1, a2;
    std::cout << "a1 = a2 calls ";
    a1 = a2; // affectation par copie définie par l'utilisateur

    B b1, b2;
    b2.s1 = "foo";
    b2.s2 = "bar";
    std::cout << "b1 = b2 calls ";
    b1 = b2; // affectation par copie définie implicitement

    std::cout << "b1.s1 = " << b1.s1 << "; b1.s2 = " << b1.s2 << '\n';
}

Output:

a1 = a2 calls copy assignment of A
b1 = b2 calls copy assignment of A
b1.s1 = foo; b1.s2 = bar
