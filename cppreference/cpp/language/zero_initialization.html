Initialisation à zéro

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Fixe la valeur initiale d'un objet à zéro.

Syntaxe

Notez qu'il ne s'agit pas de la syntaxe de l'initialisation à zéro, qui n'a pas de syntaxe dédiée dans le langage. Ce sont des exemples d'autres types d'initialisations, qui peuvent effectuer une initialisation à zéro.

static T object ; | (1)

T () ;

T t = {} ;

T {} ; (depuis C++11)

| (2)

CharT array [ n ] = " short-sequence "; | (3)

Explication

L'initialisation à zéro est effectuée dans les situations suivantes :

  1. Pour chaque variable nommée à durée de stockage statiqueou thread-local (depuis C++11) storage duration qui n'est pas soumise à une initialisation constante, avant toute autre initialisation.

  2. Dans le cadre de la séquence d'initialisation par valeur pour les types non classes et pour les membres des types classes initialisés par valeur qui n'ont pas de constructeurs, y compris l'initialisation par valeur des éléments d'agrégats pour lesquels aucun initialiseur n'est fourni.

  3. Lorsqu'un tableau de tout type caractère est initialisé avec un littéral de chaîne trop court, le reste du tableau est initialisé à zéro.

Les effets de l'initialisation à zéro sont :

  • Si T est un type scalaire, l'objet est initialisé à la valeur obtenue en convertissant explicitement le littéral entier 0 (zéro) en T.

  • Si T est un type classe non union :

    • tous les bits de remplissage sont initialisés à des bits zéro,
    • chaque membre de données non statique est initialisé à zéro,
    • chaque sous-objet de classe de base non virtuelle est initialisé à zéro, et
    • si l'objet n'est pas un sous-objet de classe de base, chaque sous-objet de classe de base virtuelle est initialisé à zéro.

  • Si T est un type union :

    • tous les bits de remplissage sont initialisés à des bits zéro, et
    • le premier membre de données nommé non statique de l'objet est initialisé à zéro.

  • Si T est un type tableau, chaque élément est initialisé à zéro.

  • Si T est un type référence, rien n'est fait.

Notes

Comme décrit dans l'initialisation non locale, les variables staticet thread-local (depuis C++11) qui ne sont pas initialisées par constante sont initialisées à zéro avant toute autre initialisation. Si la définition d'une variable non locale non classe n'a pas d'initialiseur, alors l'initialisation par défaut ne fait rien, laissant inchangé le résultat de l'initialisation à zéro précédente.

Un pointeur initialisé à zéro vaut la valeur de pointeur nul de son type, même si la valeur du pointeur nul n'est pas le zéro entier.

Exemple

#include <iostream>
#include <string>

struct A
{
    int a, b, c;
};

double f[3];   // initialisé à zéro en trois 0.0

int* p;        // initialisé à zéro avec la valeur de pointeur nul
               // (même si la valeur n'est pas l'entier 0)

std::string s; // initialisé à zéro avec une valeur indéterminée, puis
               // initialisé par défaut à "" par le constructeur par défaut de std::string

int main(int argc, char*[])
{
    delete p; // il est sûr de supprimer un pointeur nul

    static int n = argc; // initialisé à zéro à 0 puis initialisé par copie avec argc
    std::cout << "n = " << n << '\n';

    A a = A(); // l'effet est le même que : A a{}; ou A a = {};
    std::cout << "a = {" << a.a << ' ' << a.b << ' ' << a.c << "}\n";
}

Sortie possible :

n = 1
a = {0 0 0}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 277 C++98 des pointeurs pouvaient être initialisés avec une expression non constante de valeur 0, qui n'est pas une constante pointeur nul il fallait initialiser avec une expression constante entière de valeur 0
CWG 694 C++98 l'initialisation à zéro des types classes ignorait le remplissage le remplissage est initialisé à des bits zéro
CWG 903 C++98 l'initialisation à zéro des types scalaires fixait la valeur initiale à la valeur convertie depuis une expression constante entière de valeur 0 l'objet est initialisé à la valeur convertie depuis le littéral entier 0
CWG 2026 C++98 l'initialisation à zéro était spécifiée pour toujours se produire en premier, même avant l'initialisation constante pas d'initialisation à zéro si l'initialisation constante s'applique
CWG 2196 C++98 l'initialisation à zéro pour les types de classe ignorait les sous-objets de classe de base ils sont également initialisés à zéro
CWG 2253 C++98 on ne savait pas si l'initialisation à zéro s'appliquait aux champs de bits sans nom elle s'applique (tous les bits de remplissage sont initialisés à zéro)
