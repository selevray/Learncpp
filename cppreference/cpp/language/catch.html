Gestion des exceptions

  1. Un gestionnaire avec un paramètre nommé.

  2. Un gestionnaire avec un paramètre non nommé.

  3. Un gestionnaire capturant tous les types d'exceptions.

  • attr — (depuis C++11) un nombre quelconque d'attributs, s'applique au paramètre
  • type-specifier-seq — partie d'une déclaration de paramètre formel, identique à celle de la liste de paramètres d'une fonction
  • declarator — partie d'une déclaration de paramètre, identique à celle de la liste de paramètres d'une fonction
  • abstract-declarator — partie d'une déclaration de paramètre non nommé, identique à celle de la liste de paramètres d'une fonction
  • compound-statement — une instruction composée

La déclaration de paramètre d'un gestionnaire décrit le ou les types d'exceptions pouvant provoquer l'entrée dans ce gestionnaire.

Si le paramètre est déclaré avec l'un des types suivants, le programme est mal formé :

  • un type incomplet
  • un type classe abstraite
  • un type référence rvalue

(depuis C++11)

  • un pointeur vers un type incomplet autre que (éventuellement qualifié cv) void
  • une référence lvalue vers un type incomplet

Si le paramètre est déclaré avec le type « tableau de T » ou le type fonction T, le type est ajusté en « pointeur vers T ».

Un gestionnaire dont le type de paramètre est T peut être abrégé en « un gestionnaire de type T ».

Exceptions correspondantes

Chaque bloc try est associé à un certain nombre de gestionnaires, ces gestionnaires forment une séquence de gestionnaires. Lorsqu'une exception est lancée depuis un bloc try, les gestionnaires de la séquence sont essayés dans l'ordre d'apparition pour correspondre à l'exception.

Un gestionnaire correspond à un objet exception de type E si l'une des conditions suivantes est satisfaite :

  • Le gestionnaire est de type « éventuellement qualifié cv T » ou « référence lvalue vers éventuellement qualifié cv T », et l'une des conditions suivantes est satisfaite :

    • E et T sont le même type (en ignorant les qualificateurs cv de premier niveau).
    • T est une classe de base publique non ambiguë de E.

  • Le gestionnaire est de type « éventuellement qualifié cv T » ou const T& où T est un type pointeur ou pointeur vers membre, et l'une des conditions suivantes est satisfaite :

    • E est un type pointeur ou pointeur vers membre pouvant être converti en T par au moins l'une des conversions suivantes :
      • Une conversion de pointeur standard n'impliquant pas de conversions vers des pointeurs vers des classes privées, protégées ou ambiguës.
  • Une conversion de pointeur de fonction.

(depuis C++17)

  • Une conversion de qualification.
  • E is std::nullptr_t.

(depuis C++11)

Le gestionnaire catch (...) capture les exceptions de tout type. S'il est présent, il ne peut être que le dernier gestionnaire d'une séquence de gestionnaires. Ce gestionnaire peut être utilisé pour garantir qu'aucune exception non capturée ne peut s'échapper d'une fonction offrant une garantie d'exception nothrow.

try
{
    f();
}
catch (const std::overflow_error& e)
{} // ceci s'exécute si f() lève std::overflow_error (même règle de type)
catch (const std::runtime_error& e)
{} // ceci s'exécute si f() lève std::underflow_error (règle de classe de base)
catch (const std::exception& e)
{} // ceci s'exécute si f() lève std::logic_error (règle de classe de base)
catch (...)
{} // ceci s'exécute si f() lève std::string, int ou tout autre type sans rapport

Si aucun gestionnaire ne correspond pour un bloc try, la recherche d'un gestionnaire correspondant se poursuit dans un bloc try englobant dynamiquementdu même thread (depuis C++11).

Si aucun gestionnaire correspondant n'est trouvé, std::terminate est appelé ; le fait que la pile soit déroulée ou non avant cet appel de std::terminate est défini par l'implémentation.

Gestion des exceptions

Lorsqu'une exception est lancée, le contrôle est transféré au gestionnaire le plus proche de type correspondant ; « le plus proche » signifie le gestionnaire dont l'instruction composée ou la liste d'initialisation des membres (si présente) suivant le mot-clé try a été entrée en dernier par le fil d'exécution et n'a pas encore été quittée.

Initialisation du paramètre du gestionnaire

Le paramètre déclaré dans la liste des paramètres (le cas échéant), de type « T éventuellement qualifié cv » ou « référence lvalue vers T éventuellement qualifié cv », est initialisé à partir de l'objet d'exception, de type E, comme suit :

  • Si T est une classe de base de E, le paramètre est initialisé par copie à partir d'une lvalue de type T désignant le sous-objet de classe de base correspondant de l'objet d'exception.
  • Sinon, le paramètre est initialisé par copie à partir d'une lvalue de type E désignant l'objet d'exception.

La durée de vie du paramètre se termine lorsque le gestionnaire se termine, après la destruction de tous les objets à durée de stockage automatique initialisés dans le gestionnaire.

Lorsque le paramètre est déclaré comme un objet, toute modification de cet objet n'affecte pas l'objet d'exception.

Lorsque le paramètre est déclaré comme une référence à un objet, toute modification de l'objet référencé est une modification de l'objet d'exception et aura un effet si cet objet est relancé.

Activation du gestionnaire

Un gestionnaire est considéré comme actif lorsque l'initialisation du paramètre (le cas échéant) du gestionnaire est terminée.

De plus, un gestionnaire implicite est considéré comme actif lorsque std::terminate est entré suite à un lancer.

Un gestionnaire n'est plus considéré comme actif lorsqu'il se termine.

L'exception dont le gestionnaire activé le plus récemment est encore actif est appelée exception en cours de traitement. Une telle exception peut être relancée.

Flux de contrôle

L'compound-statement d'un gestionnaire est une instruction à flux de contrôle limité :

void f()
{
    goto label;     // error
    try
    {
        goto label; // error
    }
    catch (...)
    {
        goto label: // OK
        label: ;
    }
}

Notes

Le déroulement de la pile se produit pendant que le contrôle est transféré à un gestionnaire. Lorsqu'un gestionnaire devient actif, le déroulement de la pile est déjà terminé.

L'exception lancée par l'expression throw throw 0 ne correspond à aucun gestionnaire de type pointeur ou pointeur vers membre.

  • throw nullptr peut être utilisé à la place pour lancer un pointeur nul qui correspond à de tels gestionnaires.

(depuis C++11)

Les objets d'exception ne peuvent jamais avoir de type tableau ou fonction ; par conséquent, un gestionnaire de référence vers un type tableau ou fonction ne correspond jamais à un objet d'exception.

Il est possible d'écrire des gestionnaires qui ne peuvent jamais être exécutés, par exemple en plaçant un gestionnaire pour une classe dérivée finale après un gestionnaire pour une classe de base publique non ambiguë correspondante :

try
{
    f();
}
catch (const std::exception& e)
{} // sera exécuté si f() lève std::runtime_error
catch (const std::runtime_error& e)
{} // code mort !

De nombreuses implémentations étendent excessivement la résolution du CWG issue 388 aux gestionnaires de référence vers des types pointeurs non const :

int i;
try
{
    try
    {
        throw static_cast<float*>(nullptr);
    }
    catch (void*& pv)
    {
        pv = &i;
        throw;
    }
}
catch (const float* pf)
{
    assert(pf == nullptr); // devrait réussir, mais échoue sur MSVC et Clang
}

Exemple

L'exemple suivant présente plusieurs cas d'utilisation des gestionnaires :

#include <iostream>
#include <vector>

int main()
{
    try
    {
        std::cout << "Throwing an integer exception...\n";
        throw 42;
    }
    catch (int i)
    {
        std::cout << " the integer exception was caught, with value: " << i << '\n';
    }

    try
    {
        std::cout << "Creating a vector of size 5... \n";
        std::vector<int> v(5);
        std::cout << "Accessing the 11th element of the vector...\n";
        std::cout << v.at(10); // vector::at() lève std::out_of_range
    }
    catch (const std::exception& e) // attrapé par référence vers la base
    {
        std::cout << " a standard exception was caught, with message: '"
                  << e.what() << "'\n";
    }
}

Sortie possible :

Throwing an integer exception...
 the integer exception was caught, with value: 42
Creating a vector of size 5...
Accessing the 11th element of the vector...
 a standard exception was caught, with message: 'out_of_range'

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 98 C++98 une instruction switch peut transférer le contrôle dans un gestionnaire prohibited
CWG 210 C++98 les expressions throw étaient comparées aux gestionnaires les objets d'exception sont comparés aux gestionnaires
CWG 388 C++98 une exception de type pointeur ou pointeur vers membre ne pouvait pas être comparée à une référence const d'un type différent rendue comparable lorsque convertible
CWG 1166 C++98 le comportement était non spécifié lorsqu'un gestionnaire dont le type est une référence vers un type classe abstraite était comparé les types classe abstraits sont interdits pour les gestionnaires
CWG 1769 C++98 lorsque le type du gestionnaire est une base du type de l'objet d'exception, un constructeur de conversion peut être utilisé pour l'initialisation du paramètre du gestionnaire le paramètre est initialisé par copie à partir du sous-objet de classe de base correspondant de l'objet d'exception
CWG 2093 C++98 un objet d'exception de type pointeur vers type objet ne pouvait pas correspondre à un gestionnaire de type pointeur vers type objet par conversion de qualification allowed
