Constructeurs de copie

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un constructeur de copie est un constructeur qui peut être appelé avec un argument du même type de classe et qui copie le contenu de l'argument sans modifier cet argument.

Syntaxe

| | | | class-name ﻿(parameter-list ﻿); | (1) | | | | class-name ﻿(parameter-list ﻿) function-body | (2) | | | | class-name ﻿(single-parameter-list ﻿) = default; | (3) | (depuis C++11) | | | class-name ﻿(parameter-list ﻿) = delete; | (4) | (depuis C++11) | | | class-name ﻿::class-name ﻿(parameter-list ﻿) function-body | (5) | | | | class-name ﻿::class-name ﻿(single-parameter-list ﻿) = default; | (6) | (depuis C++11) | |

  • class-name — la classe dont le constructeur de copie est déclaré
  • parameter-list — une liste de paramètres non vide satisfaisant toutes les conditions suivantes :
    • étant donné le type de classe comme T, le premier paramètre est de type T&, const T&, volatile T& ou const volatile T&, et
    • soit il n'y a pas d'autres paramètres, soit tous les autres paramètres ont des arguments par défaut.
  • single-parameter-list — une liste de paramètres ne comportant qu'un seul paramètre, de type T&, const T&, volatile T& ou const volatile T&, et n'ayant pas d'argument par défaut
  • function-body — le corps de fonction du constructeur de copie

Explication

  1. Déclaration d'un constructeur de copie à l'intérieur de la définition de classe.

2-4) Définition d'un constructeur de copie à l'intérieur de la définition de classe.

  1. Le constructeur de copie est explicitement défaut.

  2. Le constructeur de copie est supprimé.

5,6) Définition d'un constructeur de copie en dehors de la définition de classe (la classe doit contenir une déclaration (1)).

  1. Le constructeur de copie est explicitement défaut.
struct X
{
    X(X& other); // constructeur de copie
//  X(X other);  // Erreur : type de paramètre incorrect
};

union Y
{
    Y(Y& other, int num = 1); // constructeur de copie avec plusieurs paramètres
//  Y(Y& other, int num);     // Erreur : `num` n'a pas d'argument par défaut
};

Le constructeur de copie est appelé chaque fois qu'un objet est initialisé (par initialisation directe ou initialisation par copie) à partir d'un autre objet du même type (sauf si la résolution de surcharge sélectionne une meilleure correspondance ou si l'appel est élidé), ce qui inclut

  • initialisation : T a = b; ou T a(b);, où b est de type T ;
  • passage d'arguments de fonction : f(a);, où a est de type T et f est void f(T t) ;
  • retour de fonction : return a; dans une fonction telle que T f(), où a est de type T, qui n'a pas de constructeur de déplacement.

Constructeur de copie déclaré implicitement

Si aucun constructeur de copie défini par l'utilisateur n'est fourni pour un type de classe, le compilateur déclare toujours un constructeur de copie comme membre non explicit inline public de sa classe. Ce constructeur de copie déclaré implicitement a la forme T::T(const T&) si toutes les conditions suivantes sont vraies :

  • chaque B de base directe et virtuelle de T possède un constructeur de copie dont les paramètres sont de type const B& ou const volatile B& ;
  • chaque M membre de données non statique de T de type classe ou de type tableau de classe possède un constructeur de copie dont les paramètres sont de type const M& ou const volatile M&.

Sinon, le constructeur de copie déclaré implicitement est T::T(T&).

En raison de ces règles, le constructeur de copie déclaré implicitement ne peut pas se lier à un argument lvalue volatile.

Une classe peut avoir plusieurs constructeurs de copie, par exemple à la fois T::T(const T&) et T::T(T&).

Même si certains constructeurs de copie définis par l'utilisateur sont présents, l'utilisateur peut tout de même forcer la déclaration implicite du constructeur de copie à l'aide du mot-clé default.

(depuis C++11)

Le constructeur de copie déclaré implicitement (ou défini par défaut lors de sa première déclaration) a une spécification d'exception décrite dans [spécification d'exception dynamique (jusqu'à C++17) | spécification noexcept (depuis C++17)].

Constructeur de copie défini implicitement

Si le constructeur de copie déclaré implicitement n'est pas supprimé, il est défini (c'est-à-dire qu'un corps de fonction est généré et compilé) par le compilateur si il est utilisé par ODRou nécessaire à l'évaluation constante (depuis C++11). Pour les types union, le constructeur de copie défini implicitement copie la représentation de l'objet (comme par std::memmove). Pour les types de classes non union, le constructeur effectue une copie membre à membre complète des sous-objets de base directs et des sous-objets membres de l'objet, dans leur ordre d'initialisation, en utilisant l'initialisation directe. Pour chaque membre de données non statique de type référence, le constructeur de copie lie la référence au même objet ou à la même fonction auquel la référence source est liée.

Si cela satisfait les exigences d'un [constructeur constexpr (jusqu'à C++23) | fonction constexpr (depuis C++23)], le constructeur de copie généré est constexpr.

La génération du constructeur de copie défini implicitement est obsolète si T possède un destructeur défini par l'utilisateur ou un opérateur d'affectation par copie défini par l'utilisateur.

(depuis C++11)

Constructeur de copie supprimé

Le constructeur de copie déclaré implicitement ou explicitement défaut (depuis C++11) de la classe T est [non défini (jusqu'à C++11) | défini comme supprimé (depuis C++11)] si l'une des conditions suivantes est satisfaite :

  • T possède un membre de données non statique de type référence rvalue.

(depuis C++11)

  • T possède un sous-objet potentiellement construit de type classe M (ou éventuellement un tableau multidimensionnel de celui-ci) tel que
    • M possède un destructeur qui estsupprimé ou (depuis C++11) inaccessible depuis le constructeur de copie, ou
    • la résolution de surcharge appliquée pour trouver le constructeur de copie de M
      • ne produit aucun candidat utilisable, ou
      • dans le cas où le sous-objet est un membre variant, sélectionne une fonction non triviale.

Le constructeur de copie déclaré implicitement pour la classe T est défini comme supprimé si T déclare un constructeur de déplacement ou un opérateur d'affectation par déplacement.

(depuis C++11)

Constructeur de copie trivial

Le constructeur de copie de la classe T est trivial si toutes les conditions suivantes sont vraies :

  • il n'est pas fourni par l'utilisateur (c'est-à-dire qu'il est défini implicitement ou défaut) ;
  • T ne possède aucune fonction membre virtuelle ;
  • T ne possède aucune classe de base virtuelle ;
  • le constructeur de copie sélectionné pour chaque base directe de T est trivial ;
  • le constructeur de copie sélectionné pour chaque membre de type classe non statique (ou de type tableau de classe) de T est trivial ;

Un constructeur de copie trivial pour une classe non union copie effectivement chaque sous-objet scalaire (y compris, récursivement, les sous-objets des sous-objets, et ainsi de suite) de l'argument et n'effectue aucune autre action. Cependant, les octets de remplissage n'ont pas besoin d'être copiés, et même les représentations d'objet des sous-objets copiés n'ont pas besoin d'être identiques tant que leurs valeurs sont identiques.

Les objets TriviallyCopyable peuvent être copiés en copiant manuellement leurs représentations d'objet, par exemple avec std::memmove. Tous les types de données compatibles avec le langage C (types POD) sont trivialement copiables.

Constructeur de copie éligible

Un constructeur de copie est éligible s'il est déclaré par l'utilisateur ou à la fois déclaré implicitement et définissable.

(jusqu'à C++11)

Un constructeur de copie est éligible s'il n'est pas supprimé.

(depuis C++11) (jusqu'à C++20)

Un constructeur de copie est éligible si toutes les conditions suivantes sont satisfaites :

  • Il n'est pas supprimé.
  • Ses contraintes associées (le cas échéant) sont satisfaites.
  • Aucun constructeur de copie dont les contraintes associées sont satisfaites n'est plus contraint.

(depuis C++20)

La trivialité des constructeurs de copie éligibles détermine si la classe est un type à durée de vie implicite, et si la classe est un type trivialement copiable.

Notes

Dans de nombreuses situations, les constructeurs de copie sont optimisés même s'ils pourraient produire des effets de bord observables, voir élision de copie.

Exemple

struct A
{
    int n;
    A(int n = 1) : n(n) {}
    A(const A& a) : n(a.n) {} // constructeur de copie défini par l'utilisateur
};

struct B : A
{
    // constructeur par défaut implicite B::B()
    // constructeur de copie implicite B::B(const B&)
};

struct C : B
{
    C() : B() {}
private:
    C(const C&); // non copiable, style C++98
};

int main()
{
    A a1(7);
    A a2(a1); // appelle le constructeur de copie

    B b;
    B b2 = b;
    A a3 = b; // conversion vers A& et constructeur de copie

    volatile A va(10);
    // A a4 = va; // erreur de compilation

    C c;
    // C c2 = c; // erreur de compilation
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 1353 C++98 les conditions dans lesquelles les constructeurs de copie déclarés implicitement sont non définis ne prenaient pas en compte les types de tableaux multidimensionnels prendre en compte ces types
CWG 2094 C++11 les membres volatils rendent la copie non triviale (CWG issue 496) la trivialité n'est pas affectée
CWG 2171 C++11 X(X&) = default était non trivial rendu trivial
CWG 2595 C++20 un constructeur de copie n'était pas éligible s'il existait un autre constructeur de copie plus contraint mais ne satisfaisant pas ses contraintes associées il peut être éligible dans ce cas
