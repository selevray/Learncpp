Recherche de nom non qualifiée

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Pour un nom non qualifié, c'est-à-dire un nom qui n'apparaît pas à droite d'un opérateur de résolution de portée ::, la recherche de nom examine les portées décrites ci-dessous, jusqu'à trouver au moins une déclaration de quelque nature que ce soit ; la recherche s'arrête alors et aucune autre portée n'est examinée. (Remarque : la recherche depuis certains contextes ignore certaines déclarations ; par exemple, la recherche d'un nom utilisé à gauche de :: ignore les déclarations de fonctions, de variables et d'énumérateurs, la recherche d'un nom utilisé comme spécificateur de classe de base ignore toutes les déclarations qui ne sont pas de type).

Pour la recherche de nom non qualifiée, toutes les déclarations d'un espace de noms désigné par une directive using apparaissent comme si elles étaient déclarées dans l'espace de noms englobant le plus proche qui contient, directement ou indirectement, à la fois la directive using et l'espace de noms désigné.

La recherche de nom non qualifiée du nom utilisé à gauche de l'opérateur d'appel de fonction (et, de manière équivalente, de l'opérateur dans une expression) est décrite dans la recherche dépendant des arguments.

Portée de fichier

Pour un nom utilisé dans la portée globale (espace de noms de plus haut niveau), en dehors de toute fonction, classe ou espace de noms défini par l'utilisateur, la portée globale située avant l'utilisation du nom est examinée :

int n = 1;     // déclaration de n
int x = n + 1; // OK : la recherche trouve ::n

int z = y - 1; // Error : la recherche échoue
int y = 2;     // déclaration de y

Portée d'espace de noms

Pour un nom utilisé dans un espace de noms défini par l'utilisateur, en dehors de toute fonction ou classe, cet espace de noms est recherché avant l'utilisation du nom, puis l'espace de noms englobant cet espace de noms avant la déclaration de celui-ci, etc., jusqu'à atteindre l'espace de noms global.

int n = 1; // declaration

namespace N
{
    int m = 2;

    namespace Y
    {
        int x = n; // OK, la recherche trouve ::n
        int y = m; // OK, la recherche trouve ::N::m
        int z = k; // Error : la recherche échoue
    }

    int k = 3;
}

Définition en dehors de son espace de noms

Pour un nom utilisé dans la définition d'une variable membre d'un espace de noms en dehors de celui-ci, la recherche procède de la même manière que pour un nom utilisé à l'intérieur de l'espace de noms :

namespace X
{
    extern int x; // déclaration, pas définition
    int n = 1;    // trouvé en 1er
}

int n = 2;        // trouvé en 2e
int X::x = n;     // trouve X::n, met X::x à 1

Définition d'une fonction non membre

Pour un nom utilisé dans la définition d'une fonction, que ce soit dans son corps ou dans un argument par défaut, lorsque la fonction est membre d'un espace de noms défini par l'utilisateur ou de l'espace de noms global, le bloc dans lequel le nom est utilisé est recherché avant l'utilisation du nom, puis le bloc englobant est recherché avant le début de ce bloc, etc., jusqu'à atteindre le bloc qui est le corps de la fonction. Ensuite, l'espace de noms dans lequel la fonction est déclarée est recherché jusqu'à la définition (et non nécessairement la déclaration) de la fonction qui utilise le nom, puis les espaces de noms englobants, etc.

namespace A
{
    namespace N
    {
        void f();
        int i = 3; // trouvé en 3e (si le 2e n'est pas présent)
    }

    int i = 4;     // trouvé en 4e (si le 3e n'est pas présent)
}

int i = 5;         // trouvé en 5e (si le 4e n'est pas présent)

void A::N::f()
{
    int i = 2;     // trouvé en 2e (si le 1er n'est pas présent)

    while (true)
    {
       int i = 1;  // trouvé en 1er : la recherche est terminée
       std::cout << i;
    }
}

// int i;          // non trouvé

namespace A
{
    namespace N
    {
        // int i;  // non trouvé
    }
}

Définition de classe

Pour un nom utilisé n'importe où dans la définition de classe (y compris les spécificateurs de classes de base et les définitions de classes imbriquées), sauf à l'intérieur du corps d'une fonction membre, d'un argument par défaut d'une fonction membre, d'une spécification d'exception d'une fonction membre ou d'un initialisateur de membre par défaut, lorsque le membre peut appartenir à une classe imbriquée dont la définition se trouve dans le corps de la classe englobante, les portées suivantes sont recherchées :

a) le corps de la classe dans laquelle le nom est utilisé, jusqu'au point d'utilisation,

b) le corps entier de sa ou ses classes de base, en poursuivant récursivement dans leurs bases lorsqu'aucune déclaration n'est trouvée,

c) si cette classe est imbriquée, le corps de la classe englobante jusqu'à la définition de cette classe, ainsi que le corps entier de la ou des classes de base de la classe englobante,

d) si cette classe est locale, ou imbriquée dans une classe locale, le bloc de portée dans lequel la classe est définie, jusqu'au point de définition,

e) si cette classe est membre d'un espace de noms, ou imbriquée dans une classe membre d'un espace de noms, ou est une classe locale dans une fonction membre d'un espace de noms, la portée de l'espace de noms est recherchée jusqu'à la définition de la classe, de la classe englobante ou de la fonction ; la recherche se poursuit dans les espaces de noms englobant celui-ci, jusqu'à la portée globale.

Pour une déclaration friend, la recherche permettant de déterminer si elle désigne une entité déclarée précédemment procède comme ci-dessus, sauf qu'elle s'arrête après l'espace de noms englobant le plus interne.

namespace M
{
    // const int i = 1; // jamais trouvé

    class B
    {
        // static const int i = 3;     // trouvé en 3e (mais ne passera pas le contrôle d'accès)
    };
}

// const int i = 5;                    // trouvé en 5e

namespace N
{
    // const int i = 4;                // trouvé en 4e

    class Y : public M::B
    {
        // static const int i = 2;     // trouvé en 2e

        class X
        {
            // static const int i = 1; // trouvé en 1er
            int a[i]; // utilisation de i
            // static const int i = 1; // jamais trouvé
        };

        // static const int i = 2;     // jamais trouvé
    };

    // const int i = 4;                // jamais trouvé
}

// const int i = 5;                    // jamais trouvé

Nom de classe injecté

Pour le nom d'une classe ou d'un modèle de classe utilisé dans la définition de cette classe ou de ce modèle, ou dérivé de l'un d'eux, la recherche de nom non qualifiée trouve la classe en cours de définition comme si le nom avait été introduit par une déclaration de membre (avec un accès membre public). Pour plus de détails, voir injected-class-name.

Définition de fonction membre

Pour un nom utilisé à l'intérieur du corps d'une fonction membre, d'un argument par défaut d'une fonction membre, d'une spécification d'exception d'une fonction membre ou d'un initialisateur de membre par défaut, les portées recherchées sont les mêmes que dans la définition de classe, sauf que la portée entière de la classe est prise en compte, et non seulement la partie précédant la déclaration qui utilise le nom. Pour les classes imbriquées, le corps entier de la classe englobante est recherché.

class B
{
    // int i;         // trouvé en 3e
};

namespace M
{
    // int i;         // trouvé en 5e

    namespace N
    {
        // int i;     // trouvé en 4e

        class X : public B
        {
            // int i; // trouvé en 2e
            void f();
            // int i; // trouvé aussi en 2e
        };

        // int i;     // trouvé en 4e
    }
}

// int i;             // trouvé en 6e

void M::N::X::f()
{
    // int i;         // trouvé en 1er
    i = 16;
    // int i;         // jamais trouvé
}

namespace M
{
    namespace N
    {
        // int i;     // jamais trouvé
    }
}

Dans tous les cas, lors de l'examen des classes de base dont la classe dérive, les règles suivantes, parfois appelées dominance dans l'héritage virtuel, sont appliquées :

Un nom de membre trouvé dans un sous-objet B masque le même nom de membre dans tout sous-objet A si A est un sous-objet de classe de base de B. (Notez que ceci ne masque pas le nom dans les copies supplémentaires non virtuelles de A présentes dans le treillis d'héritage qui ne sont pas des bases de B : cette règle n'a d'effet que pour l'héritage virtuel.) Les noms introduits par des déclarations using sont traités comme des noms de la classe contenant la déclaration. Après l'examen de chaque base, l'ensemble résultant doit soit inclure des déclarations d'un membre statique provenant de sous-objets du même type, soit des déclarations de membres non statiques provenant du même sous-objet.

(jusqu'à C++11)

Un ensemble de recherche est construit, composé des déclarations et des sous-objets dans lesquels ces déclarations ont été trouvées. Les déclarations using sont remplacées par les membres qu'elles désignent, et les déclarations de types, y compris les noms de classe injectés, sont remplacées par les types qu'elles désignent. Si C est la classe dans la portée de laquelle le nom a été utilisé, C est examinée en premier. Si la liste des déclarations dans C est vide, un ensemble de recherche est construit pour chacune de ses bases directes Bi (en appliquant récursivement ces règles si Bi possède ses propres bases). Une fois construits, les ensembles de recherche des bases directes sont fusionnés dans l'ensemble de recherche de C comme suit :

  • si l'ensemble de déclarations de Bi est vide, il est abandonné,
  • si l'ensemble de recherche de C construit jusqu'ici est vide, il est remplacé par l'ensemble de recherche de Bi,
  • si chaque sous-objet de l'ensemble de recherche de Bi est une base d'au moins un des sous-objets déjà ajoutés à l'ensemble de recherche de C, l'ensemble de recherche de Bi est abandonné,
  • si chaque sous-objet déjà ajouté à l'ensemble de recherche de C est une base d'au moins un sous-objet de l'ensemble de recherche de Bi, alors l'ensemble de recherche de C est abandonné et remplacé par l'ensemble de recherche de Bi,
  • sinon, si les ensembles de déclarations de Bi et de C sont différents, le résultat est une fusion ambiguë : le nouvel ensemble de recherche de C contient une déclaration invalide et une union des sous-objets précédemment fusionnés dans C et introduits depuis Bi. Cet ensemble de recherche invalide peut ne pas constituer une erreur s'il est abandonné par la suite,
  • sinon, le nouvel ensemble de recherche de C contient les ensembles de déclarations communs et l'union des sous-objets précédemment fusionnés dans C et introduits depuis Bi.

(depuis C++11)

struct X { void f(); };

struct B1: virtual X { void f(); };

struct B2: virtual X {};

struct D : B1, B2
{
    void foo()
    {
        X::f(); // OK, appelle X::f (recherche qualifiée)
        f(); // OK, appelle B1::f (recherche non qualifiée)
    }
};

// Règles C++98 : B1::f masque X::f, donc bien que X::f puisse être atteint depuis D
// via B2, il n'est pas trouvé par la recherche de nom depuis D.

// Règles C++11 : l'ensemble de recherche de f dans D ne trouve rien, on poursuit vers les bases
//  l'ensemble de recherche de f dans B1 trouve B1::f, et est complété
// la fusion remplace l'ensemble vide ; l'ensemble de recherche de f dans C contient maintenant B1::f dans B1
//  l'ensemble de recherche de f dans B2 ne trouve rien, on poursuit vers les bases
//    la recherche de f dans X trouve X::f
//  la fusion remplace l'ensemble vide ; l'ensemble de recherche de f dans B2 contient maintenant X::f dans X
// la fusion dans C constate que chaque sous-objet (X) de l'ensemble de recherche dans B2 est une base
// de chaque sous-objet (B1) déjà fusionné, donc l'ensemble de B2 est écarté
// C ne contient plus que B1::f trouvé dans B1
// (si struct D : B2, B1 avait été utilisé, la dernière fusion aurait *remplacé* l'ensemble de C
//  donc X::f déjà fusionné dans X, car chaque sous-objet déjà ajouté à C (soit X)
//  serait une base d'au moins un sous-objet du nouvel ensemble (B1), le résultat final
//  serait le même : l'ensemble de recherche dans C ne contient que B1::f trouvé dans B1)

La recherche de nom non qualifiée qui trouve des membres statiques de B, des types imbriqués de B et des énumérateurs déclarés dans B n'est pas ambiguë, même s'il existe plusieurs sous-objets de base non virtuels de type B dans l'arbre d'héritage de la classe examinée :

struct V { int v; };

struct B
{
    int a;
    static int s;
    enum { e };
};

struct B1 : B, virtual V {};
struct B2 : B, virtual V {};
struct D : B1, B2 {};

void f(D& pd)
{
    ++pd.v;       // OK : un seul v car il n'y a qu'un seul sous-objet de base virtuelle
    ++pd.s;       // OK : un seul B::s statique, bien que trouvé à la fois dans B1 et B2
    int i = pd.e; // OK : un seul énumérateur B::e, bien qu'il soit trouvé à la fois dans B1 et B2
    ++pd.a;       // erreur, ambiguë : B::a dans B1 et B::a dans B2
}

Définition de fonction amie

Pour un nom utilisé dans la définition d'une fonction friend à l'intérieur du corps de la classe qui accorde l'amitié, la recherche de nom non qualifiée procède de la même manière que pour une fonction membre. Pour un nom utilisé dans une fonction friend définie en dehors du corps d'une classe, la recherche de nom non qualifiée procède de la même manière que pour une fonction d'un espace de noms.

int i = 3;                     // trouvé en 3e pour f1, trouvé en 2e pour f2

struct X
{
    static const int i = 2;    // trouvé en 2e pour f1, jamais trouvé pour f2

    friend void f1(int x)
    {
        // int i;              // trouvé en 1er
        i = x;                 // trouve et modifie X::i
    }

    friend int f2();

    // static const int i = 2; // trouvé en 2e pour f1, n'importe où dans la portée de la classe
};

void f2(int x)
{
    // int i;                  // trouvé en 1er
    i = x;                     // trouve et modifie ::i
}

Déclaration de fonction amie

Pour un nom utilisé dans le déclarateur d'une déclaration de fonction friend qui accorde l'amitié à une fonction membre d'une autre classe, si le nom ne fait pas partie d'un argument de modèle dans l'identifiant du déclarateur, la recherche non qualifiée examine d'abord la portée entière de la classe de la fonction membre. Si rien n'est trouvé dans cette portée (ou si le nom fait partie d'un argument de modèle dans l'identifiant du déclarateur), la recherche continue comme pour une fonction membre de la classe qui accorde l'amitié.

template<class T>
struct S;

// la classe dont les fonctions membres sont déclarées amies
struct A
{
    typedef int AT;

    void f1(AT);
    void f2(float);

    template<class T>
    void f3();

    void f4(S<AT>);
};

// la classe qui accorde l'amitié à f1, f2 et f3
struct B
{
    typedef char AT;
    typedef float BT;

    friend void A::f1(AT);    // la recherche de AT trouve A::AT (AT trouvé dans A)
    friend void A::f2(BT);    // la recherche de BT trouve B::BT (BT non trouvé dans A)
    friend void A::f3<AT>();  // la recherche de AT trouve B::AT (pas de recherche dans A, car
                              //     AT se trouve dans l'identifiant du déclarateur A::f3<AT>)
};

// le modèle de classe qui accorde l'amitié à f4
template<class AT>
struct C
{
    friend void A::f4(S<AT>); // la recherche de AT trouve A::AT
                              // (AT ne se trouve pas dans l'identifiant du déclarateur A::f4)
};

Argument par défaut

Pour un nom utilisé dans un argument par défaut d'une déclaration de fonction, ou un nom utilisé dans la partie expression d'un member-initializer d'un constructeur, les noms des paramètres de la fonction sont trouvés en premier, avant que les portées du bloc, de la classe ou de l'espace de noms englobant ne soient examinées :

class X
{
    int a, b, i, j;
public:
    const int& r;

    X(int i): r(a),      // initialise X::r pour qu'il référence X::a
              b(i),      // initialise X::b avec la valeur du paramètre i
              i(i),      // initialise X::i avec la valeur du paramètre i
              j(this->i) // initialise X::j avec la valeur de X::i
    {}
};

int a;
int f(int a, int b = a); // erreur : la recherche de a trouve le paramètre a, et non ::a
                         // et les paramètres ne sont pas autorisés comme arguments par défaut

Définition de membre de donnée statique

Pour un nom utilisé dans la définition d'un membre de donnée statique, la recherche procède de la même manière que pour un nom utilisé dans la définition d'une fonction membre.

struct X
{
    static int x;
    static const int n = 1; // trouvé en 1er
};

int n = 2;                  // trouvé en 2e
int X::x = n;               // trouve X::n, affecte 1 à X::x, et non 2

Déclaration d'énumérateur

Pour un nom utilisé dans la partie initialisateur de la déclaration d'énumérateur, les énumérateurs déclarés précédemment dans la même énumération sont trouvés en premier, avant que la recherche de nom non qualifiée n'examine la portée englobante du bloc, de la classe ou de l'espace de noms.

const int RED = 7;

enum class color
{
    RED,
    GREEN = RED + 2, // RED trouve color::RED, et non ::RED, donc GREEN = 2
    BLUE = ::RED + 4 // la recherche qualifiée trouve ::RED, BLUE = 11
};

Gestionnaire d'un bloc try de fonction

Pour un nom utilisé dans le gestionnaire d'un bloc try de fonction, la recherche procède comme pour un nom utilisé au tout début du bloc le plus externe du corps de la fonction (en particulier, les paramètres de la fonction sont visibles, mais les noms déclarés dans ce bloc le plus externe ne le sont pas)

int n = 3;          // trouvé en 3e
int f(int n = 2)    // trouvé en 2e

try
{
    int n = -1;     // jamais trouvé
}
catch(...)
{
    // int n = 1;   // trouvé en 1er
    assert(n == 2); // la recherche de n trouve le paramètre de fonction f
    throw;
}

Opérateur surchargé

Pour un opérateur utilisé dans une expression (par exemple, operator+ utilisé dans a + b), les règles de recherche sont légèrement différentes de celles de l'opérateur utilisé dans une expression d'appel de fonction explicite telle que operator+(a, b) : lors de l'analyse d'une expression, deux recherches distinctes sont effectuées : une pour les surcharges d'opérateurs non membres et une pour les surcharges d'opérateurs membres (pour les opérateurs où les deux formes sont autorisées). Ces ensembles sont ensuite fusionnés avec les surcharges d'opérateurs intégrés, à égalité, comme décrit dans la résolution de surcharge. Si la syntaxe d'appel de fonction explicite est utilisée, la recherche de nom non qualifiée habituelle est effectuée :

struct A {};
void operator+(A, A);  // opérateur+ défini par l'utilisateur, non membre

struct B
{
    void operator+(B); // opérateur+ défini par l'utilisateur, membre
    void f();
};

A a;

void B::f() // définition d'une fonction membre de B
{
    operator+(a, a); // erreur : la recherche de nom ordinaire depuis une fonction membre
                     // trouve la déclaration de operator+ dans la portée de B
                     // et s'arrête là, sans jamais atteindre la portée globale

    a + a; // OK : la recherche de membre trouve B::operator+, la recherche non membre
           // trouve ::operator+(A, A), la résolution de surcharge sélectionne ::operator+(A, A)
}

Définition de modèle

Pour un nom non dépendant utilisé dans une définition de modèle, la recherche de nom non qualifiée a lieu au moment où la définition du modèle est examinée. La liaison aux déclarations faites à ce moment n'est pas affectée par les déclarations visibles au point d'instanciation. Pour un nom dépendant utilisé dans une définition de modèle, la recherche est reportée jusqu'à ce que les arguments de modèle soient connus ; à ce moment, l'ADL examine les déclarations de fonctions à liaison externe (jusqu'à C++11) visibles depuis le contexte de définition du modèle ainsi que depuis le contexte d'instanciation, alors que la recherche non ADL n'examine que les déclarations de fonctions à liaison externe (jusqu'à C++11) visibles depuis le contexte de définition du modèle (en d'autres termes, ajouter une nouvelle déclaration de fonction après la définition du modèle ne la rend visible que par l'ADL). Le comportement est indéfini s'il existe une meilleure correspondance à liaison externe dans les espaces de noms examinés par la recherche ADL, déclarée dans une autre unité de traduction, ou si la recherche aurait été ambiguë si ces unités de traduction avaient été examinées. Dans tous les cas, si une classe de base dépend d'un paramètre de modèle, sa portée n'est pas examinée par la recherche de nom non qualifiée (ni au point de définition, ni au point d'instanciation).

void f(char); // première déclaration de f

template<class T>
void g(T t)
{
    f(1);    // nom non dépendant : la recherche trouve ::f(char) et le lie immédiatement
    f(T(1)); // nom dépendant : la recherche est reportée
    f(t);    // nom dépendant : la recherche est reportée
//  dd++;    // nom non dépendant : la recherche ne trouve aucune déclaration
}

enum E { e };
void f(E);   // deuxième déclaration de f
void f(int); // troisième déclaration de f
double dd;

void h()
{
    g(e);  // instancie g<E>, moment où
           // les deuxième et troisième utilisations du nom 'f'
           // sont recherchées et trouvent ::f(char) (par recherche) et ::f(E) (par ADL)
           // puis la résolution de surcharge choisit ::f(E).
           // Ceci appelle f(char), puis f(E) deux fois

    g(32); // instancie g<int>, moment où
           // les deuxième et troisième utilisations du nom 'f'
           // sont recherchées et trouvent uniquement ::f(char)
           // puis la résolution de surcharge choisit ::f(char)
           // Ceci appelle f(char) trois fois
}

typedef double A;

template<class T>
class B
{
    typedef int A;
};

template<class T>
struct X : B<T>
{
    A a; // la recherche de A trouve ::A (double), et non B<T>::A
};

Note : voir règles de recherche des noms dépendants pour le raisonnement et les implications de cette règle.

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 490 C++98 tout nom dans un argument de modèle d'une déclaration de fonction membre amie n'a pas été recherché dans la portée de la classe de la fonction membre exclut seulement les noms figurant dans les arguments de modèle dans l'identifiant du déclarateur
CWG 514 C++98 tout nom non qualifié utilisé dans la portée d'un espace de noms était d'abord recherché dans cette portée les noms non qualifiés utilisés pour définir une variable membre d'un espace de noms en dehors de cet espace de noms sont d'abord recherchés dans cet espace de noms
