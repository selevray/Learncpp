Les opérateurs d'incrémentation/décrémentation incrémentent ou décrémentent la valeur de l'objet.

Nom de l'opérateur | Syntaxe | Surchargeables | Exemples de prototypes (pour class T)

Dans la définition de la classe | En dehors de la définition de la classe

pré-incrémentation | ++a | Oui | T& T::operator++(); | T& operator++(T& a);

pré-décrémentation | --a | Oui | T& T::operator--(); | T& operator--(T& a);

post-incrémentation | a++ | Oui | T T::operator++(int); | T operator++(T& a, int);

post-décrémentation | a-- | Oui | T T::operator--(int); | T operator--(T& a, int);

Notes

  • Les versions préfixées des opérateurs intégrés renvoient des références et les versions postfixées renvoient des valeurs, et les surcharges définies par l'utilisateur typiques suivent ce modèle afin que les opérateurs définis par l'utilisateur puissent être utilisés de la même manière que les opérateurs intégrés. Cependant, dans une surcharge d'opérateur définie par l'utilisateur, tout type peut être utilisé comme type de retour (y compris void).
  • Le paramètre int est un paramètre factice utilisé pour différencier les versions préfixée et postfixée des opérateurs. Lorsque l'opérateur postfixé défini par l'utilisateur est appelé, la valeur passée dans ce paramètre est toujours zéro, bien qu'elle puisse être modifiée en appelant l'opérateur avec la notation d'appel de fonction (par exemple, a.operator++(2) ou operator++(a, 2)).

Opérateurs préfixes

Les expressions d'incrémentation et de décrémentation préfixées ont la forme

| | | | ++ expression | | | | | -- expression | | | |

  1. incrémentation préfixée (pré-incrémentation)

  2. décrémentation préfixée (pré-décrémentation)

Opérateurs préfixes intégrés

  1. L'expression ++x est équivalente à x += 1, avec les exceptions suivantes :
  • Si le type de expression est (éventuellement volatile) bool, expression est défini à true. Une telle incrémentation est obsolète.

(jusqu'à C++17)

  • Si le type de expression est (éventuellement qualifié cv) bool, le programme est mal formé.

(depuis C++17)

  • Si le type de expression est qualifié volatile, l'incrémentation est obsolète.

(depuis C++20)

  1. L'expression --x est équivalente à x -= 1, avec les exceptions suivantes :
  • Si le type de expression est (éventuellement qualifié cv) bool, le programme est mal formé.
  • Si le type de expression est qualifié volatile, la décrémentation est obsolète.

(depuis C++20)

Surcharges

Lors de la résolution de surcharge face aux opérateurs définis par l'utilisateur, pour chaque type arithmétique éventuellement qualifié volatile A autre que bool, et pour chaque pointeur éventuellement qualifié volatile P vers un type objet éventuellement qualifié cv, les signatures de fonction suivantes participent à la résolution de surcharge :

A& operator++(A&)

bool& operator++(bool&)  // (obsolète) (jusqu'à C++17)

P& operator++(P&)

A& operator--(A&)

P& operator--(P&)

Opérateurs postfixes

Les expressions d'incrémentation et de décrémentation postfixées ont la forme

| | | | expression ++ | | | | | expression -- | | | |

  1. incrémentation postfixée (post-incrémentation)

  2. décrémentation postfixée (post-décrémentation)

Opérateurs postfixes intégrés

Le résultat de l'incrémentation ou de la décrémentation postfixée est la valeur obtenue en appliquant la conversion lvalue-vers-rvalue à expression (avant modification). Le type du résultat est la version non qualifiée cv du type de expression.

Si expression n'est pas une lvalue modifiable d'un type arithmétiqueautre que (éventuellement qualifié cv) bool (depuis C++17), ou un pointeur vers un type objet complet, le programme est mal formé.

Si le type de expression est qualifié volatile, l'incrémentation ou la décrémentation est obsolète.

(depuis C++20)

  1. La valeur de expression est modifiée comme si elle était l'opérande de l'opérateur préfixé ++.

  2. La valeur de expression est modifiée comme si elle était l'opérande de l'opérateur préfixé --.

La valeur calculée d'une incrémentation ou décrémentation postfixée est séquencée avant la modification de expression. Par rapport à un appel de fonction à séquencement indéterminé, l'opération d'incrémentation ou de décrémentation postfixée est une seule évaluation.

Surcharges

Lors de la résolution de surcharge face aux opérateurs définis par l'utilisateur, pour chaque type arithmétique éventuellement qualifié volatile A autre que bool, et pour chaque pointeur éventuellement qualifié volatile P vers un type objet éventuellement qualifié cv, les signatures de fonction suivantes participent à la résolution de surcharge :

A operator++(A&, int)

bool operator++(bool&, int)  // (obsolète) (jusqu'à C++17)

P operator++(P&, int)

A operator--(A&, int)

P operator--(P&, int)

Exemple

#include <iostream>

int main()
{
    int n1 = 1;
    int n2 = ++n1;
    int n3 = ++ ++n1;
    int n4 = n1++;
//  int n5 = n1++ ++;   // error
//  int n6 = n1 + ++n1; // comportement indéfini
    std::cout << "n1 = " << n1 << '\n'
              << "n2 = " << n2 << '\n'
              << "n3 = " << n3 << '\n'
              << "n4 = " << n4 << '\n';
}

Output:

n1 = 5
n2 = 2
n3 = 4
n4 = 4

Notes

En raison des effets de bord impliqués, les opérateurs d'incrémentation et de décrémentation intégrés doivent être utilisés avec précaution afin d'éviter un comportement indéfini dû à des violations des règles de séquencement.

Comme une copie temporaire de l'objet est construite lors de la post-incrémentation et de la post-décrémentation, les opérateurs de pré-incrémentation ou de pré-décrémentation sont généralement plus efficaces dans les contextes où la valeur retournée n'est pas utilisée.

Bibliothèque standard

Les opérateurs d'incrémentation et de décrémentation sont surchargés pour de nombreux types de la bibliothèque standard. En particulier, chaque LegacyIterator surcharge operator++ et chaque LegacyBidirectionalIterator surcharge operator--, même si ces opérateurs ne sont pas des opérations sans effet pour l'itérateur particulier.

##### surcharges pour les types arithmétiques {#overloads_for_arithmetic_types}

  • operator++operator++(int)operator--operator--(int) — incrémente ou décrémente la valeur atomique d'une unité (fonction membre publique de std::atomic<T>)
  • operator++operator++(int)operator--operator--(int) — incrémente ou décrémente le nombre de ticks (fonction membre publique de std::chrono::duration<Rep,Period>)

##### surcharges pour les types itérateurs {#overloads_for_iterator_types}

  • operator++operator++(int) — avance l'itérateur (fonction membre publique de std::raw_storage_iterator<OutputIt,T>)
  • operator++operator++(int)operator+=operator+operator--operator--(int)operator-=operator- — avance ou décrémente l'itérateur (fonction membre publique de std::reverse_iterator<Iter>)
  • operator++operator++(int)operator+=operator+operator--operator--(int)operator-=operator- (C++11) — avance ou décrémente l'itérateur (fonction membre publique de std::move_iterator<Iter>)
  • operator++operator++(int) — opération sans effet (fonction membre publique de std::front_insert_iterator<Container>)
  • operator++operator++(int) — opération sans effet (fonction membre publique de std::back_insert_iterator<Container>)
  • operator++operator++(int) — opération sans effet (fonction membre publique de std::insert_iterator<Container>)
  • operator++operator++(int) — avance l'itérateur (fonction membre publique de std::istream_iterator<T,CharT,Traits,Distance>)
  • operator++operator++(int) — opération sans effet (fonction membre publique de std::ostream_iterator<T,CharT,Traits>)
  • operator++operator++(int) — avance l'itérateur (fonction membre publique de std::istreambuf_iterator<CharT,Traits>)
  • operator++operator++(int) — opération sans effet (fonction membre publique de std::ostreambuf_iterator<CharT,Traits>)
  • operator++operator++(int) — avance l'itérateur jusqu'à la correspondance suivante (fonction membre publique de std::regex_iterator<BidirIt,CharT,Traits>)
  • operator++operator++(int) — avance l'itérateur jusqu'au sous-motif suivant (fonction membre publique de std::regex_token_iterator<BidirIt,CharT,Traits>)

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 2855 C++98 les conversions arithmétiques usuelles sont appliquées pour la pré-incrémentation et la pré-décrémentation intégrées, mais ne l'étaient pas pour leurs équivalents postfixés[1] désormais appliquées
CWG 2901 C++98 les conversions lvalue-to-rvalue n'étaient pas appliquées pour la post-incrémentation et la post-décrémentation intégrées applied
  1. ↑ Le préfixe ++x est équivalent à x += 1, et ce dernier est soumis aux conversions arithmétiques usuelles (c'est-à-dire qu'il produit un type commun entre decltype(x) et int). Cependant, l'effet du postfixe x++ est simplement « ajouter un à x » ; il n'y a aucun opérateur binaire présent, donc aucune conversion arithmétique usuelle n'a lieu.
