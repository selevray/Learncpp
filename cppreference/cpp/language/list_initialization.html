Initialisation par liste (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Initialise un objet à partir d'une liste d'initialisation entre accolades.

L'initialisation par liste est effectuée dans les situations suivantes :

  • initialisation directe par liste (les constructeurs explicites et non explicites sont tous deux pris en compte)

  1. : initialisation d'une variable nommée avec une liste d'initialisation entre accolades

  2. : initialisation d'un temporaire sans nom avec une liste d'initialisation entre accolades

  3. : initialisation d'un objet à durée de stockage dynamique avec une expression new, où l'initialiseur est une liste d'initialisation entre accolades

  4. : dans un initialiseur de membre de données non statique qui n'utilise pas le signe égal

  5. : dans une liste d'initialisation de membres d'un constructeur si une liste d'initialisation entre accolades est utilisée

  • initialisation par copie par liste (les constructeurs explicites et non explicites sont tous deux pris en compte, mais seuls les constructeurs non explicites peuvent être appelés)

  1. : initialisation d'une variable nommée avec une liste d'initialisation entre accolades après un signe égal

  2. : dans une expression d'appel de fonction, une liste d'initialisation entre accolades étant utilisée comme argument, l'initialisation par liste initialisant le paramètre de la fonction

  3. : dans une instruction return dont l'expression de retour est une liste d'initialisation entre accolades, l'initialisation par liste initialisant l'objet retourné

  4. : dans une expression d'indexation avec un operator[] défini par l'utilisateur, où l'initialisation par liste initialise le paramètre de l'opérateur surchargé

  5. : dans une expression d'affectation, où l'initialisation par liste initialise le paramètre de l'opérateur surchargé

  6. expression de cast fonctionnel ou autres invocations de constructeur, où une liste d'initialisation entre accolades est utilisée à la place d'un argument de constructeur. La copy-list-initialization initialise le paramètre du constructeur (note; le type U de cet exemple n'est pas le type initialisé par liste; c'est le paramètre du constructeur de U qui l'est)

  7. : dans un initialiseur de membre de données non statique qui utilise le signe égal

Explication

Les effets de l'initialisation par liste d'un objet de type (éventuellement qualifié cv) T sont :

  • Si la liste d'initialisation entre accolades contient une liste d'initialisation désignée et que T n'est pas un type référence, T doit être une classe agrégat. Les identifiants ordonnés dans les désignateurs de la liste d'initialisation désignée doivent former une sous-séquence des identifiants ordonnés des membres de données non statiques directs de T. Une initialisation d'agrégat est effectuée.

(depuis C++20)

  • Si T est une classe agrégat et que la liste d'initialisation entre accolades, qui ne contient pas de liste d'initialisation désignée, (depuis C++20) a une seule clause d'initialisation de même type ou d'un type dérivé (éventuellement qualifié cv), l'objet est initialisé à partir de cette clause d'initialisation (par initialisation par copie pour l'initialisation par copie par liste, ou par initialisation directe pour l'initialisation directe par liste).

  • Sinon, si T est un tableau de caractères et que la liste d'initialisation entre accolades a une seule clause d'initialisation qui est un littéral chaîne de type approprié, le tableau est initialisé à partir du littéral chaîne comme d'habitude.

  • Sinon, si T est un type agrégat, une initialisation d'agrégat est effectuée.

  • Sinon, si la liste d'initialisation entre accolades est vide et que T est un type classe avec un constructeur par défaut, une initialisation par valeur est effectuée.

  • Sinon, si T est une spécialisation de std::initializer_list, l'objet est initialisé comme décrit ci-dessous.

  • Sinon, si T est un type classe, les constructeurs de T sont examinés, en deux phases :

    • Tous les constructeurs qui prennent std::initializer_list comme seul argument, ou comme premier argument si les arguments restants ont des valeurs par défaut, sont examinés et retenus par résolution de surcharge contre un seul argument de type std::initializer_list.
    • Si l'étape précédente ne produit pas de correspondance, tous les constructeurs de T participent à la résolution de surcharge sur l'ensemble des arguments constitué des clauses d'initialisation de la liste d'initialisation entre accolades, avec la restriction que seules les conversions non rétrécissantes sont autorisées. Si cette étape produit un constructeur explicite comme meilleure correspondance pour une initialisation par copie par liste, la compilation échoue (note : dans une initialisation par copie simple, les constructeurs explicites ne sont pas du tout pris en compte).
  • Sinon, si T est un type énuméré à type sous-jacent fixe U, la liste d'initialisation entre accolades n'a qu'un seul initialiseur v, et toutes les conditions suivantes sont satisfaites, alors l'énumération est initialisée avec le résultat de la conversion de v en U :
  • L'initialisation est une initialisation directe par liste.
  • v est d'un type scalaire.
  • v est implicitement convertible en U.
  • La conversion de v vers U est non rétrécissante.

(depuis C++17)

  • Sinon (si T n'est pas un type classe), si la liste d'initialisation entre accolades n'a qu'une seule clause d'initialisation et que soit T n'est pas un type référence, soit c'est un type référence dont le type référencé est identique ou est une classe de base du type de la clause d'initialisation, T est initialisé directement (en initialisation directe par liste) ou initialisé par copie (en initialisation par copie par liste), à ceci près que les conversions rétrécissantes ne sont pas autorisées.

  • Sinon, si T est un type référence non compatible avec le type de la clause d'initialisation :

  • un temporaire prvalue du type référencé par T est initialisé par copie par liste, et la référence est liée à ce temporaire (cela échoue si la référence est une référence lvalue non const).

(jusqu'à C++17)

  • une prvalue est générée. La prvalue initialise son objet résultat par initialisation par copie par liste. La prvalue sert ensuite à initialiser directement la référence (cela échoue si la référence est une référence lvalue non const). Le type du temporaire est le type référencé par T, sauf si T est « référence vers un tableau de borne inconnue de U », auquel cas le type du temporaire est le type de x dans la déclaration U x[] H, où H est la liste d'initialisation (depuis C++20).

(depuis C++17)

  • Sinon, si la liste d'initialisation entre accolades n'a aucune clause d'initialisation, T est initialisé par valeur.

Initialisation par liste de std::initializer_list

Un objet de type std::initializer_list<E> est construit à partir d'une liste d'initialisation comme si le compilateur généraitet matérialisait (depuis C++17) une prvalue de type « tableau de N const E », où N est le nombre de clauses d'initialisation de la liste d'initialisation ; ce tableau est appelé le tableau de support de la liste d'initialisation.

Chaque élément du tableau de support est initialisé par copie avec la clause d'initialisation correspondante de la liste d'initialisation, et l'objet std::initializer_list<E> est construit pour référencer ce tableau. Un constructeur ou un opérateur de conversion sélectionné pour la copie doit être accessible dans le contexte de la liste d'initialisation. Si une conversion rétrécissante est nécessaire pour initialiser l'un des éléments, le programme est mal formé.

Le tableau de support a la même durée de vie que tout autre objet temporaire, sauf que l'initialisation d'un objet std::initializer_list à partir du tableau de support prolonge la durée de vie du tableau exactement comme la liaison d'une référence à un temporaire.

void f(std::initializer_list<double> il);

void g(float x)
{
   f({1, x, 3});
}

void h()
{
   f({1, 2, 3});
}

struct A { mutable int i; };

void q(std::initializer_list<A>);

void r()
{
    q({A{1}, A{2}, A{3}});
}

// L'initialisation ci-dessus sera implémentée d'une manière approximativement équivalente à celle ci-dessous,
// en supposant que le compilateur puisse construire un objet initializer_list à partir d'une paire de
// pointeurs, et en comprenant que `__b` ne survit pas à l'appel de `f`.

void g(float x)
{
    const double __a[3] = {double{1}, double{x}, double{3}}; // tableau de support
    f(std::initializer_list<double>(__a, __a + 3));
}

void h()
{
    static constexpr double __b[3] =
        {double{1}, double{2}, double{3}}; // tableau de support
    f(std::initializer_list<double>(__b, __b + 3));
}

void r()
{
    const A __c[3] = {A{1}, A{2}, A{3}}; // tableau de support
    q(std::initializer_list<A>(__c, __c + 3));
}

Le fait que tous les tableaux de support soient distincts (c'est-à-dire stockés dans des objets non chevauchants) est non spécifié :

bool fun(std::initializer_list<int> il1, std::initializer_list<int> il2)
{
    return il2.begin() == il1.begin() + 1;
}

bool overlapping = fun({1, 2, 3}, {2, 3, 4}); // le résultat n'est pas spécifié :
                                              // les tableaux de support peuvent partager
                                              // le stockage au sein de {1, 2, 3, 4}

Conversions rétrécissantes

L'initialisation par liste limite les conversions implicites autorisées en interdisant ce qui suit :

  • conversion d'un type à virgule flottante vers un type entier

  • conversion d'un type à virgule flottante T vers un autre type à virgule flottante dont le rang de conversion en virgule flottante n'est ni supérieur ni égal à celui de T, sauf lorsque le résultat de la conversion est une expression constante et qu'une des conditions suivantes est satisfaite :

    • La valeur convertie est finie, et la conversion ne provoque pas de dépassement.
    • Les valeurs avant et après la conversion ne sont pas finies.

  • conversion d'un type entier vers un type à virgule flottante, sauf lorsque la source est une expression constante dont la valeur peut être stockée exactement dans le type cible

  • conversion d'un type entier ou d'un type énuméré non scopé vers un type entier qui ne peut pas représenter toutes les valeurs de l'original, sauf lorsque

    • la source est un champ de bits dont la largeur w est inférieure à celle de son type (ou, pour un type énuméré, celle de son type sous-jacent) et que le type cible peut représenter toutes les valeurs d'un type entier étendu hypothétique de largeur w et de même signe que le type original, ou
    • la source est une expression constante dont la valeur peut être stockée exactement dans le type cible

  • conversion d'un type pointeur ou d'un type pointeur vers membre vers bool

Notes

Chaque clause d'initialisation est séquencée avant toute clause d'initialisation qui la suit dans la liste d'initialisation entre accolades. Cela contraste avec les arguments d'une expression d'appel de fonction, qui sont [non séquencés (jusqu'à C++17) | séquencés de façon indéterminée (depuis C++17)].

Une liste d'initialisation entre accolades n'est pas une expression et n'a donc pas de type, par exemple decltype({1, 2}) est mal formé. Ne pas avoir de type implique que la déduction de type de modèle ne peut pas déduire un type correspondant à une liste d'initialisation entre accolades ; ainsi, avec la déclaration template<class T> void f(T);, l'expression f({1, 2, 3}) est mal formée. Cependant, le paramètre de modèle peut être déduit autrement, comme c'est le cas pour std::vector<int> v(std::istream_iterator<int>(std::cin), {}), où le type d'itérateur est déduit du premier argument mais est aussi utilisé à la seconde position de paramètre. Une exception particulière est faite pour la déduction de type utilisant le mot-clé auto, qui déduit toute liste d'initialisation entre accolades en tant que std::initializer_list en initialisation par copie par liste.

De même, comme une liste d'initialisation entre accolades n'a pas de type, des règles particulières de résolution de surcharge s'appliquent lorsqu'elle est utilisée comme argument d'un appel de fonction surchargée.

Les agrégats sont initialisés par copie ou déplacement directement à partir d'une liste d'initialisation entre accolades d'une seule clause d'initialisation de même type, mais les non-agrégats considèrent d'abord les constructeurs std::initializer_list :

struct X {}; // aggregate

struct Q     // non-agrégat
{
    Q() = default;
    Q(Q const&) = default;
    Q(std::initializer_list<Q>) {}
};

int main()
{
    X x;
    X x2 = X{x}; // constructeur de copie (et non initialisation d'agrégat)

    Q q;
    Q q2 = Q{q}; // constructeur à liste d'initialisation (et non constructeur de copie)
}

Certains compilateurs (par exemple gcc 10) ne considèrent comme rétrécissante la conversion d'un pointeur ou d'un pointeur vers membre vers bool qu'en mode C++20.

Exemple

#include <iostream>
#include <map>
#include <string>
#include <vector>

struct Foo
{
    std::vector<int> mem = {1, 2, 3}; // initialisation par liste d'un membre non statique
    std::vector<int> mem2;

    Foo() : mem2{-1, -2, -3} {} // initialisation par liste d'un membre dans un constructeur
};

std::pair<std::string, std::string> f(std::pair<std::string, std::string> p)
{
    return {p.second, p.first}; // initialisation par liste dans une instruction return
}

int main()
{
    int n0{};  // initialisation par valeur (à zéro)
    int n1{1}; // initialisation par liste directe

    std::string s1{'a', 'b', 'c', 'd'}; // appel d'un constructeur à liste d'initialisation
    std::string s2{s1, 2, 2};           // appel d'un constructeur ordinaire
    std::string s3{0x61, 'a'}; // le constructeur à liste d'initialisation est préféré à (int, char)

    int n2 = {1}; // initialisation par copie-liste
    double d = double{1.2}; // initialisation par liste d'une prvalue, puis initialisation par copie
    auto s4 = std::string{"HelloWorld"}; // identique à ci-dessus, sans objet temporaire
                                         // créé depuis C++17

    std::map<int, std::string> m = // initialisation par liste imbriquée
    {
        {1, "a"},
        {2, {'a', 'b', 'c'}},
        {3, s1}
    };

    std::cout << f({"hello", "world"}).first // initialisation par liste dans un appel de fonction
              << '\n';

    const int (&ar)[2] = {1, 2}; // lie une référence lvalue à un tableau temporaire
    int&& r1 = {1}; // lie une référence rvalue à un int temporaire
//  int& r2 = {2}; // erreur : impossible de lier une rvalue à une référence lvalue non const

//  int bad{1.0}; // erreur : conversion restrictive
    unsigned char uc1{10}; // okay
//  unsigned char uc2{-1}; // erreur : conversion restrictive

    Foo f;

    std::cout << n0 << ' ' << n1 << ' ' << n2 << '\n'
              << s1 << ' ' << s2 << ' ' << s3 << '\n';
    for (auto p : m)
        std::cout << p.first << ' ' << p.second << '\n';
    for (auto n : f.mem)
        std::cout << n << ' ';
    for (auto n : f.mem2)
        std::cout << n << ' ';
    std::cout << '\n';

    [](...){}(d, ar, r1, uc1); // a le même effet que [[maybe_unused]]
}

Output:

world
0 1 1
abcd cd aa
1 a
2 abc
3 abcd
1 2 3 -1 -2 -3
