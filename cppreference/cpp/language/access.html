Spécificateurs d'accès

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Dans un member-specification d'une déclaration de classe/struct ou de union, définit l'accessibilité des membres suivants.

Dans un base-specifier d'une déclaration de classe dérivée, définit l'accessibilité des membres hérités de la classe de base suivante.

Syntaxe

| | | | public : member-declarations | (1) | | | | protected : member-declarations | (2) | | | | private : member-declarations | (3) | | | | public base-class | (4) | | | | protected base-class | (5) | | | | private base-class | (6) | | |

  1. Les membres déclarés après le spécificateur d'accès ont un accès public.

  2. Les membres déclarés après le spécificateur d'accès ont un accès protégé.

  3. Les membres déclarés après le spécificateur d'accès ont un accès privé.

  4. Héritage public : les membres publics et protégés de la classe de base listée après le spécificateur d'accès conservent leur accès dans la classe dérivée.

  5. Héritage protégé : les membres publics et protégés de la classe de base listée après le spécificateur d'accès deviennent des membres protégés de la classe dérivée.

  6. Héritage privé : les membres publics et protégés de la classe de base listée après le spécificateur d'accès deviennent des membres privés de la classe dérivée.

Les membres privés de la classe de base sont toujours inaccessibles à la classe dérivée, quel que soit l'héritage public, protégé ou privé.

Explication

Le nom de chaque membre de classe (statique, non statique, fonction, type, etc.) possède un « accès membre » associé. Lorsqu'un nom de membre est utilisé n'importe où dans un programme, son accès est vérifié, et s'il ne respecte pas les règles d'accès, le programme ne compile pas :

#include <iostream>

class Example
{
public:             // toutes les déclarations après ce point sont publiques
    void add(int x) // le membre « add » a un accès public
    {
        n += x;     // OK : le membre privé Example::n peut être accédé depuis Example::add
    }
private:            // toutes les déclarations après ce point sont privées
    int n = 0;      // le membre « n » a un accès privé
};

int main()
{
    Example e;
    e.add(1); // OK : le membre public Example::add peut être accédé depuis main
//  e.n = 7;  // erreur : le membre privé Example::n ne peut pas être accédé depuis main
}

Les spécificateurs d'accès permettent à l'auteur de la classe de décider quels membres de la classe sont accessibles aux utilisateurs de la classe (c'est-à-dire l'interface) et quels membres sont destinés à un usage interne de la classe (l'implémentation).

En détail

Tous les membres d'une classe (corps des fonctions membres, initialiseurs des objets membres et l'ensemble des définitions de classes imbriquées) ont accès à tous les noms auxquels la classe peut accéder. Une classe locale définie dans une fonction membre a accès à tous les noms auxquels la fonction membre peut accéder.

Une classe définie avec le mot-clé class a par défaut un accès privé pour ses membres et ses classes de base. Une classe définie avec le mot-clé struct a par défaut un accès public pour ses membres et ses classes de base. Une union a par défaut un accès public pour ses membres.

Pour accorder l'accès aux membres protégés ou privés à des fonctions ou classes supplémentaires, une déclaration d'amitié peut être utilisée.

Les règles d'accès s'appliquent à tous les noms, quelle que soit leur origine ; un nom introduit par un typedef ou par des déclarations using (sauf les constructeurs hérités) est donc vérifié, et non le nom auquel il fait référence :

class A : X
{
    class B {};   // B est privé dans A
public:
    typedef B BB; // BB est public
};

void f()
{
    A::B y;  // erreur : A::B est privé
    A::BB x; // OK : A::BB est public
}

Le contrôle d'accès aux membres n'affecte pas la visibilité : les noms des membres privés et des membres hérités de façon privée sont visibles et pris en compte par la résolution de surcharge, les conversions implicites vers des classes de base inaccessibles sont toujours prises en compte, etc. Le contrôle d'accès aux membres est la dernière étape, après l'interprétation de toute construction du langage donnée. Cette règle vise à garantir que remplacer n'importe quel private par public ne modifie jamais le comportement du programme.

La vérification d'accès pour les noms utilisés dans les arguments par défaut de fonction, ainsi que dans les paramètres de modèle par défaut, est effectuée au point de déclaration, et non au point d'utilisation.

Les règles d'accès pour les noms des fonctions virtuelles sont vérifiées au point d'appel, en utilisant le type de l'expression qui désigne l'objet pour lequel la fonction membre est appelée. L'accès du final overrider est ignoré :

struct B
{
    virtual int f(); // f est public dans B
};

class D : public B
{
private:
    int f(); // f est privé dans D
};

void f()
{
    D d;
    B& b = d;

    b.f(); // OK : B::f est public, D::f est invoqué bien qu'il soit privé
    d.f(); // erreur : D::f est privé
}

Un nom privé selon la recherche de nom non qualifiée peut être accessible par la recherche de nom qualifiée :

class A {};

class B : private A {};

class C : public B
{
    A* p;   // erreur : la recherche de nom non qualifiée trouve A comme base privée de B
    ::A* q; // OK : la recherche de nom qualifiée trouve la déclaration au niveau de l'espace de noms
};

Un nom accessible par plusieurs chemins dans le graphe d'héritage a l'accès du chemin le plus permissif :

class W
{
public:
    void f();
};

class A : private virtual W {};

class B : public virtual W {};

class C : public A, public B
{
    void f()
    {
        W::f(); // OK : W est accessible à C à travers B
    }
};

Un nombre quelconque de spécificateurs d'accès peut apparaître dans une classe, dans n'importe quel ordre.

Les spécificateurs d'accès aux membres peuvent affecter la disposition de la classe en mémoire : les adresses des membres de données non statiques ne sont garanties croissantes selon l'ordre de déclaration que pour les membres [non séparés par un spécificateur d'accès (jusqu'à C++11) | de même accès (depuis C++11)].

(jusqu'à C++23)

Pour les types à disposition standard, tous les membres de données non statiques doivent avoir le même accès.

(depuis C++11)

Lorsqu'un membre est redéclaré dans la même classe, il doit l'être avec le même accès aux membres :

struct S
{
    class A;    // S::A est public
private:
    class A {}; // erreur : impossible de modifier l'accès
};

Accès aux membres publics

Les membres publics font partie de l'interface publique d'une classe (les autres parties de l'interface publique sont les fonctions non membres trouvées par ADL).

Un membre public d'une classe est accessible partout :

class S
{
public:
    // n, E, A, B, C, U, f sont des membres publics
    int n;
    enum E {A, B, C};
    struct U {};
    static void f() {}
};

int main()
{
    S::f();     // S::f est accessible dans main

    S s;
    s.n = S::B; // S::n et S::B sont accessibles dans main

    S::U x;     // S::U est accessible dans main
}

Accès aux membres protégés

Les membres protégés forment l'interface d'une classe vis-à-vis de ses classes dérivées (interface distincte de l'interface publique de la classe).

Un membre protégé d'une classe n'est accessible que

  1. aux membres et amis de cette classe ;

  2. aux membres et amis de toute classe dérivée de cette classe, mais seulement lorsque la classe de l'objet par lequel le membre protégé est accédé est cette classe dérivée ou une classe dérivée de celle-ci :

struct Base
{
protected:
    int i;
private:
    void g(Base& b, struct Derived& d);
};

struct Derived : Base
{
    friend void h(Base& b, Derived& d);
    void f(Base& b, Derived& d) // fonction membre d'une classe dérivée
    {
        ++d.i;                  // OK : le type de d est Derived
        ++i;                    // OK : le type du '*this' implicite est Derived
//      ++b.i;                  // erreur : impossible d'accéder à un membre protégé à travers
                                // Base (sinon il serait possible de modifier
                                // d'autres classes dérivées, comme une hypothétique
                                // Derived2, l'implémentation de la base)
    }
};

void Base::g(Base& b, Derived& d) // fonction membre de Base
{
    ++i;                          // OK
    ++b.i;                        // OK
    ++d.i;                        // OK
}

void h(Base& b, Derived& d) // Amie de Derived
{
    ++d.i;                  // OK : une amie de Derived peut accéder à un membre protégé
                            // à travers un objet de Derived
//  ++b.i;                  // erreur : une amie de Derived n'est pas une amie de Base
}

void x(Base& b, Derived& d) // non membre et non amie
{
//  ++b.i;                  // erreur : aucun accès depuis un non-membre
//  ++d.i;                  // erreur : aucun accès depuis un non-membre
}

Lorsqu'un pointeur vers un membre protégé est formé, sa déclaration doit utiliser une classe dérivée :

struct Base
{
protected:
    int i;
};

struct Derived : Base
{
    void f()
    {
//      int Base::* ptr = &Base::i;    // erreur : doit nommer en utilisant Derived
        int Base::* ptr = &Derived::i; // OK
    }
};

Accès aux membres privés

Les membres privés forment l'implémentation d'une classe, ainsi que l'interface privée pour les autres membres de la classe.

Un membre privé d'une classe n'est accessible qu'aux membres et amis de cette classe, qu'ils agissent sur la même instance ou sur des instances différentes :

class S
{
private:
    int n; // S::n est privé
public:
    S() : n(10) {}                    // this->n est accessible dans S::S
    S(const S& other) : n(other.n) {} // other.n est accessible dans S::S
};

Le cast explicite (de style C et de style fonctionnel) permet de convertir une lvalue dérivée en référence vers sa base privée, ou un pointeur vers une classe dérivée en pointeur vers sa base privée.
