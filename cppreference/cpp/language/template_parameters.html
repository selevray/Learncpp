Paramètres de modèle

Chaque modèle est paramétré par un ou plusieurs paramètres de modèle, indiqués dans parameter-list de la syntaxe de déclaration de modèle :

| | | | template < parameter-list > declaration | (1) | | | | template < parameter-list > requires constraint declaration | (2) | (depuis C++20) | |

Chaque paramètre de parameter-list peut être :

  • un paramètre de modèle non de type ;
  • un paramètre de modèle de type ;
  • un paramètre de modèle template.

Paramètre de modèle non de type

| | | | type name ﻿*(facultatif)* | (1) | | | | type name ﻿*(facultatif)* = default | (2) | | | | type ... name ﻿*(facultatif)* | (3) | (depuis C++11) | |

  1. Un paramètre de modèle non de type.

  2. Un paramètre de modèle non de type avec un argument de modèle par défaut.

  3. Un pack de paramètres de modèle non de type.

  • type — l'un des types suivants :

    • un type structurel (voir ci-dessous)
    • un type qui contient un type substituable

    (depuis C++17)

    • un substitut pour un type de classe déduit

    (depuis C++20)

  • name — le nom du paramètre de modèle non de type

  • default — l'argument de modèle par défaut

Un type structurel est l'un des types suivants (éventuellement qualifié cv, les qualificateurs sont ignorés) :

  • type référence lvalue (vers un objet ou une fonction) ;
  • un type entier ;
  • un type pointeur (vers un objet ou une fonction) ;
  • un type pointeur vers membre (vers un objet membre ou une fonction membre) ;
  • un type énumération ;
  • std::nullptr_t;

(depuis C++11)

  • un type à virgule flottante ;
  • un type de fermeture de lambda dont l'expression lambda n'a aucune capture ;
  • un type classe littéral qui n'est pas une fermeture, avec les propriétés suivantes :
  • toutes les classes de base et tous les membres de données non statiques sont publics et non mutables, et
  • les types de toutes les classes de base et de tous les membres de données non statiques sont des types structurels, ou des tableaux (éventuellement multidimensionnels) de tels types.

(depuis C++20)

Les types tableau et fonction peuvent être écrits dans une déclaration de modèle, mais ils sont automatiquement remplacés par un pointeur vers objet ou un pointeur vers fonction, selon le cas.

Lorsque le nom d'un paramètre de modèle non de type est utilisé dans une expression, dans le corps du modèle de classe, il s'agit d'une prvalue non modifiable, sauf si son type est un type référence lvalue, ou si son type est un type classe (depuis C++20).

Un paramètre de modèle de la forme class Foo n'est pas un paramètre de modèle non de type sans nom de type Foo, même si par ailleurs class Foo est un spécificateur de type élaboré et que class Foo x; déclare x de type Foo.

Un identificateur qui désigne un paramètre de modèle non de type de type classe T désigne un objet à durée de stockage statique de type const T, appelé objet paramètre de modèle, qui est équivalent en argument de modèle à l'argument de modèle correspondant après sa conversion vers le type du paramètre de modèle. Deux objets paramètres de modèle ne sont jamais équivalents en argument de modèle.

struct A
{
    friend bool operator==(const A&, const A&) = default;
};

template<A a>
void f()
{
    &a;                       // OK
    const A& ra = a, &rb = a; // Les deux sont liées au même objet paramètre de modèle
    assert(&ra == &rb);       // passes
}

(depuis C++20)

Paramètre de modèle de type

| | | | type-parameter-key name ﻿*(facultatif)* | (1) | | | | type-parameter-key name ﻿*(facultatif)* = default | (2) | | | | type-parameter-key ... name ﻿*(facultatif)* | (3) | (depuis C++11) | | | type-constraint name ﻿*(facultatif)* | (4) | (depuis C++20) | | | type-constraint name ﻿*(facultatif)* = default | (5) | (depuis C++20) | | | type-constraint ... name ﻿*(facultatif)* | (6) | (depuis C++20) | |

  • type-parameter-key — soit typename, soit class. Il n'y a aucune différence entre ces mots-clés dans une déclaration de paramètre de modèle de type
  • type-constraint — soit le nom d'un concept, soit le nom d'un concept suivi d'une liste d'arguments de modèle (entre chevrons). Dans les deux cas, le nom du concept peut être qualifié facultativement
  • name — le nom du paramètre de modèle de type
  • default — l'argument de modèle par défaut
  1. Un paramètre de modèle de type sans valeur par défaut.
template<class T>
class My_vector { /* ... */ };
  1. Un paramètre de modèle de type avec valeur par défaut.
template<class T = void>
struct My_op_functor { /* ... */ };
  1. Un pack de paramètres de modèle de type.
template<typename... Ts>
class My_tuple { /* ... */ };
  1. Un paramètre de modèle de type contraint sans valeur par défaut.
template<My_concept T>
class My_constrained_vector { /* ... */ };
  1. Un paramètre de modèle de type contraint avec valeur par défaut.
template<My_concept T = void>
class My_constrained_op_functor { /* ... */ };
  1. Un pack de paramètres de modèle de type contraint.
template<My_concept... Ts>
class My_constrained_tuple { /* ... */ };

Le nom du paramètre est facultatif :

// Déclarations des modèles présentés ci-dessus :
template<class>
class My_vector;
template<class = void>
struct My_op_functor;
template<typename...>
class My_tuple;

Dans le corps de la déclaration de modèle, le nom d'un paramètre de type est un nom de typedef qui désigne le type fourni lors de l'instanciation du modèle.

Chaque paramètre contraint P dont type-constraint est Q désignant le concept C introduit une expression de contrainte E selon les règles suivantes :

  • si Q est C (sans liste d'arguments),

  • si P n'est pas un pack de paramètres, E est simplement C<P>

  • sinon, P est un pack de paramètres, E est une expression de pliage (C<P> && ...)

  • si Q est C<A1,A2...,AN>, alors E est C<P,A1,A2,...AN> ou (C<P,A1,A2,...AN> && ...), respectivement.

template<typename T>
concept C1 = true;
template<typename... Ts> // concept variadique
concept C2 = true;
template<typename T, typename U>
concept C3 = true;

template<C1 T>         struct s1; // constraint-expression est C1<T>
template<C1... T>      struct s2; // constraint-expression est (C1<T> && ...)
template<C2... T>      struct s3; // constraint-expression est (C2<T> && ...)
template<C3<int> T>    struct s4; // constraint-expression est C3<T, int>
template<C3<int>... T> struct s5; // constraint-expression est (C3<T, int> && ...)

(depuis C++20)

Paramètre de modèle template

| | | | template < parameter-list > type-parameter-key name ﻿*(facultatif)* | (1) | | | | template < parameter-list > type-parameter-key name ﻿*(facultatif)* = default | (2) | | | | template < parameter-list > type-parameter-key ... name ﻿*(facultatif)* | (3) | (depuis C++11) | |

  • type-parameter-key — class ou typename (depuis C++17)

  1. Un paramètre de modèle template avec nom facultatif.

  2. Un paramètre de modèle template avec nom facultatif et valeur par défaut.

  3. Un pack de paramètres de modèle template avec nom facultatif.

Dans le corps de la déclaration de modèle, le nom de ce paramètre est un nom de modèle (et nécessite des arguments pour être instancié).

template<typename T>
class my_array {};

// deux paramètres de type de modèle et un paramètre de modèle de modèle :
template<typename K, typename V, template<typename> typename C = my_array>
class Map
{
    C<K> key;
    C<V> value;
};

Résolution des noms pour les paramètres de modèle

Le nom d'un paramètre de modèle ne peut pas être redéclaré dans sa portée (y compris les portées imbriquées). Un paramètre de modèle ne peut pas porter le même nom que le modèle.

template<class T, int N>
class Y
{
    int T;      // erreur : paramètre de modèle redéclaré
    void f()
    {
        char T; // erreur : paramètre de modèle redéclaré
    }
};

template<class X>
class X; // erreur : paramètre de modèle redéclaré

Dans la définition d'un membre d'un modèle de classe qui apparaît en dehors de la définition de ce modèle de classe, le nom d'un membre du modèle de classe masque le nom d'un paramètre de modèle de tout modèle de classe englobant, mais pas un paramètre de modèle du membre si ce membre est un modèle de classe ou de fonction.

template<class T>
struct A
{
    struct B {};
    typedef void C;
    void f();

    template<class U>
    void g(U);
};

template<class B>
void A<B>::f()
{
    B b; // B de A, et non le paramètre de modèle
}

template<class B>
template<class C>
void A<B>::g(C)
{
    B b; // B de A, et non le paramètre de modèle
    C c; // le paramètre de modèle C, et non C de A
}

Dans la définition d'un membre d'un modèle de classe qui apparaît en dehors de l'espace de noms contenant la définition du modèle de classe, le nom d'un paramètre de modèle masque le nom d'un membre de cet espace de noms.

namespace N
{
    class C {};

    template<class T>
    class B
    {
        void f(T);
    };
}

template<class C>
void N::B<C>::f(C)
{
    C b; // C est le paramètre de modèle, et non N::C
}

Dans la définition d'un modèle de classe, ou dans la définition d'un membre d'un tel modèle apparaissant en dehors de la définition du modèle, pour chaque classe de base non dépendante, si le nom de la classe de base ou le nom d'un membre de la classe de base est identique au nom d'un paramètre de modèle, le nom de la classe de base ou du membre masque le nom du paramètre de modèle.

struct A
{
    struct B {};
    int C;
    int Y;
};

template<class B, class C>
struct X : A
{
    B b; // A's B
    C b; // erreur : C de A n'est pas un nom de type
};

Arguments de modèle

Pour qu'un modèle soit instancié, chaque paramètre de modèle (de type, non de type ou template) doit être remplacé par un argument de modèle correspondant. Pour les modèles de classe, les arguments sont soit fournis explicitement, déduits de l'initialiseur, (depuis C++17), soit par défaut. Pour les modèles de fonction, les arguments sont fournis explicitement, déduits du contexte, ou par défaut.

Si un argument peut être interprété à la fois comme un type-id et comme une expression, il est toujours interprété comme un type-id, même si le paramètre de modèle correspondant n'est pas de type :

template<class T>
void f(); // #1

template<int I>
void f(); // #2

void g()
{
    f<int()>(); // « int() » est à la fois un type et une expression,
                // appelle #1 car elle est interprétée comme un type
}

Arguments de modèle non de type

L'argument de modèle utilisable avec un paramètre de modèle non de type peut être toute expression évaluée manifestement de manière constante.

(jusqu'à C++11)

L'argument de modèle utilisable avec un paramètre de modèle non de type peut être toute clause d'initialisation. Si la clause d'initialisation est une expression, elle doit être évaluée manifestement de manière constante.

(depuis C++11)

Étant donné la type de la déclaration de paramètre de modèle non de type sous la forme T et l'argument de modèle fourni pour ce paramètre sous la forme E.

La déclaration T x = E; introduite doit satisfaire les contraintes sémantiques de la définition d'une constexpr variable avec durée de stockage statique.

(depuis C++26)

Si T contient un type substituable, ou est un substitut pour un type de classe déduit, le type du paramètre de modèle est le type déduit pour la variable x dans la déclaration inventée T x = E;.

Si un type de paramètre déduit n'est pas un type structurel, le programme est mal formé.

Pour les packs de paramètres de modèle non de type dont le type utilise un type substituable, le type est déduit indépendamment pour chaque argument de modèle et n'a pas besoin de correspondre.

(depuis C++17)

template<auto n>
struct B { /* ... */ };

B<5> b1;   // OK : le type du paramètre de modèle non de type est int
B<'a'> b2; // OK : le type du paramètre de modèle non de type est char
B<2.5> b3; // erreur (jusqu'à C++20) : le type d'un paramètre de modèle non de type ne peut pas être double

// C++20 espace réservé de type de classe déduit, les arguments de modèle de classe sont déduits au
// site d'appel
template<std::array arr>
void f();

f<std::array<double, 8>{}>();

template<auto...>
struct C {};

C<'C', 0, 2L, nullptr> x; // OK

La valeur d'un paramètre de modèle non de type P de type(éventuellement déduit) (depuis C++17) T est déterminée à partir de son argument de modèle A comme suit :

  • Si A est une expression constante convertie de type T, la valeur de P est A (après conversion).
  • Sinon, le programme est mal formé.

(jusqu'à C++11)

  • Si A est une expression :

  • Si A est une expression constante convertie de type T, la valeur de P est A (après conversion).

  • Sinon, le programme est mal formé.

  • Sinon (A est une liste d'initialisation entre accolades), une variable temporaire constexpr T v = A; est introduite. La valeur de P est celle de v.

  • La durée de vie de v prend fin immédiatement après son initialisation.

(depuis C++11) (jusqu'à C++20)

  • Si T n'est pas un type classe et que A est une expression :

  • Si A est une expression constante convertie de type T, la valeur de P est A (après conversion).

  • Sinon, le programme est mal formé.

  • Sinon (T est un type classe ou A est une liste d'initialisation entre accolades), une variable temporaire constexpr T v = A; est introduite.

  • Si T est un type classe, un objet paramètre de modèle existe (également désigné par P). P est initialisé par copie à partir d'un initialisateur candidat non spécifié, équivalent en argument de modèle à v.

  • La durée de vie de v prend fin immédiatement après son initialisation et P.

  • Si l'initialisation de P satisfait l'une des conditions suivantes, le programme est mal formé :

  • L'initialisation serait mal formée.

  • La expression complète d'une séquence d'initialisation de déclarateur-initialiseur inventée pour l'initialisation ne serait pas une expression constante lorsqu'elle est interprétée comme une expression manifestement évaluée de manière constante.

  • L'initialisation entraînerait que P ne soit pas équivalent en argument de modèle à v.

  • Sinon, la valeur de P est celle de v.

(depuis C++20)

template<int i>
struct C { /* ... */ };

C<{42}> c1; // OK

template<auto n>
struct B { /* ... */ };

struct J1
{
    J1* self = this;
};

B<J1{}> j1; // erreur : initialisation de l'objet de paramètre de modèle
            //        n'est pas une expression constante

struct J2
{
    J2 *self = this;
    constexpr J2() {}
    constexpr J2(const J2&) {}
};

B<J2{}> j2; // erreur : l'objet de paramètre de modèle n'est pas
            //        template-argument-equivalent à le temporaire introduit

Les limitations suivantes s'appliquent lors de l'instanciation de modèles ayant des paramètres de modèle non de type :

  • Pour les types entiers et arithmétiques, l'argument de modèle fourni lors de l'instanciation doit être une expression constante convertie du type du paramètre de modèle (une certaine conversion implicite s'applique donc).
  • Pour les pointeurs vers objets, les arguments de modèle doivent désigner l'adresse d'un objet complet à durée de stockage statique et à liaison (interne ou externe), ou une expression constante qui s'évalue à la valeur de pointeur nul appropriéeou std::nullptr_t (depuis C++11).
  • Pour les pointeurs vers fonctions, les arguments valides sont des pointeurs vers fonctions ayant une liaison (ou des expressions constantes s'évaluant à des valeurs de pointeur nul).
  • Pour les paramètres référence lvalue, l'argument fourni lors de l'instanciation ne peut pas être un temporaire, une lvalue sans nom, ou une lvalue nommée sans liaison (autrement dit, l'argument doit avoir une liaison).
  • Pour les pointeurs vers membres, l'argument doit être un pointeur vers membre exprimé sous la forme &Class::Member ou une expression constante qui s'évalue en valeur de pointeur nulou std::nullptr_t (depuis C++11).

En particulier, cela implique que les littéraux de chaîne, les adresses d'éléments de tableau et les adresses de membres non statiques ne peuvent pas être utilisés comme arguments de modèle pour instancier des modèles dont les paramètres de modèle non-type correspondants sont des pointeurs vers des objets.

(jusqu'à C++17)

Les paramètres de modèle non-type de type référence ou pointeur et les membres de données non statiques de type référence ou pointeur dans un paramètre de modèle non-type de type classe et ses sous-objets (depuis C++20) ne peuvent pas faire référence à, ni être l'adresse de

  • un objet temporaire (y compris celui créé lors de l'initialisation de référence) ;
  • un littéral de chaîne ;
  • le résultat de typeid ;
  • la variable prédéfinie __func__ ;
  • ou un sous-objet (y compris un membre de classe non statique, un sous-objet de base ou un élément de tableau)de l'un des éléments ci-dessus (depuis C++20).

(depuis C++17)

template<const int* pci>
struct X {};

int ai[10];
X<ai> xi; // OK : conversion tableau vers pointeur et conversion de qualification cv

struct Y {};

template<const Y& b>
struct Z {};

Y y;
Z<y> z;   // OK : aucune conversion

template<int (&pa)[5]>
struct W {};

int b[5];
W<b> w;   // OK : aucune conversion

void f(char);
void f(int);

template<void (*pf)(int)>
struct A {};

A<&f> a;  // OK : la résolution de surcharge sélectionne f(int)

template<class T, const char* p>
class X {};

X<int, "Studebaker"> x1; // erreur : chaîne littérale comme template-argument

template<int* p>
class X {};

int a[10];

struct S
{
    int m;
    static int s;
} s;

X<&a[2]> x3; // erreur (jusqu'à C++20) : adresse d'un élément de tableau
X<&s.m> x4;  // erreur (jusqu'à C++20) : adresse d'un membre non statique
X<&s.s> x5;  // OK : adresse d'un membre statique
X<&S::s> x6; // OK : adresse d'un membre statique

template<const int& CRI>
struct B {};

B<1> b2;     // erreur : un temporaire serait requis pour l'argument de modèle
int c = 1;
B<c> b1;     // OK

Arguments de type de modèle

Un argument de modèle pour un paramètre de modèle de type doit être un type-id, qui peut désigner un type incomplet :

template<typename T>
class X {}; // modèle de classe

struct A;            // type incomplet
typedef struct {} B; // alias de type vers un type sans nom

int main()
{
    X<A> x1;  // OK : « A » désigne un type
    X<A*> x2; // OK : « A* » désigne un type
    X<B> x3;  // OK : « B » désigne un type
}

Arguments de modèle template

Un argument de modèle pour un paramètre de modèle template doit être une id-expression désignant un modèle de classe ou un alias de modèle.

Lorsque l'argument est un modèle de classe, seul le modèle primaire est pris en compte lors de la correspondance avec le paramètre. Les spécialisations partielles, le cas échéant, ne sont prises en compte que lorsqu'une spécialisation fondée sur ce paramètre de modèle template est instanciée.

template<typename T> // modèle primaire
class A { int x; };

template<typename T> // spécialisation partielle
class A<T*> { long x; };

// modèle de classe avec un paramètre de modèle de modèle V
template<template<typename> class V>
class C
{
    V<int> y;  // utilise le modèle primaire
    V<int*> z; // utilise la spécialisation partielle
};

C<A> c; // c.y.x a le type int, c.z.x a le type long

Pour faire correspondre un argument de modèle template A à un paramètre de modèle template P, P doit être au moins aussi spécialisé que A (voir ci-dessous).Si la liste de paramètres de P comprend un pack de paramètres, zéro ou plusieurs paramètres de modèle (ou packs de paramètres) de la liste de paramètres de modèle de A lui correspondent. (depuis C++11)

Formellement, un paramètre de modèle template P est au moins aussi spécialisé qu'un argument de modèle template A si, étant donnée la réécriture suivante en deux modèles de fonctions, le modèle de fonction correspondant à P est au moins aussi spécialisé que le modèle de fonction correspondant à A selon les règles d'ordonnancement partiel pour les modèles de fonctions. Étant donné un modèle de classe inventé X ayant la liste de paramètres de modèle de A (y compris les arguments par défaut) :

  • Chacun des deux modèles de fonctions a respectivement les mêmes paramètres de modèle que P ou A.
  • Chaque modèle de fonction possède un unique paramètre de fonction dont le type est une spécialisation de X avec pour arguments de modèle les paramètres de modèle du modèle de fonction concerné, où, pour chaque paramètre de modèle PP de la liste de paramètres du modèle de fonction, un argument de modèle correspondant AA est formé.Si PP déclare un pack de paramètres, alors AA est l'expansion de pack PP... ; sinon, (depuis C++11) AA est l'id-expression PP.

Si la réécriture produit un type invalide, alors P n'est pas au moins aussi spécialisé que A.

template<typename T>
struct eval;                     // modèle primaire

template<template<typename, typename...> class TT, typename T1, typename... Rest>
struct eval<TT<T1, Rest...>> {}; // spécialisation partielle de eval

template<typename T1> struct A;
template<typename T1, typename T2> struct B;
template<int N> struct C;
template<typename T1, int N> struct D;
template<typename T1, typename T2, int N = 17> struct E;

eval<A<int>> eA;        // OK : correspond à la spécialisation partielle de eval
eval<B<int, float>> eB; // OK : correspond à la spécialisation partielle de eval
eval<C<17>> eC;         // erreur : C ne correspond pas à TT dans la spécialisation partielle
                        // car le premier paramètre de TT est un
                        // paramètre de type de modèle, alors que 17 ne désigne pas un type
eval<D<int, 17>> eD;    // erreur : D ne correspond pas à TT dans la spécialisation partielle
                        // car le second paramètre de TT est un
                        // pack de paramètres de type, alors que 17 ne désigne pas un type
eval<E<int, float>> eE; // erreur : E ne correspond pas à TT dans la spécialisation partielle
                        // car le troisième paramètre (par défaut) de E est un paramètre non de type

Avant l'adoption de P0522R0, chacun des paramètres de modèle de A devait correspondre exactement aux paramètres de modèle correspondants de P. Cela empêchait d'accepter de nombreux arguments de modèle template raisonnables.

Bien que le problème ait été signalé très tôt (CWG#150), au moment de sa résolution, les modifications avaient été appliquées au projet de travail C++17 et la résolution est devenue de facto une fonctionnalité de C++17. De nombreux compilateurs la désactivent par défaut :

  • GCC la désactive par défaut dans tous les modes de langage antérieurs à C++17 ; elle ne peut être activée que par un drapeau de compilation dans ces modes.
  • Clang la désactive par défaut dans tous les modes de langage ; elle ne peut être activée que par un drapeau de compilation.
  • Microsoft Visual Studio la traite comme une fonctionnalité normale de C++17 et ne l'active que dans les modes de langage C++17 et ultérieurs (c'est-à-dire sans prise en charge en mode C++14, qui est le mode par défaut).
template<class T> class A { /* ... */ };
template<class T, class U = T> class B { /* ... */ };
template<class... Types> class C { /* ... */ };

template<template<class> class P> class X { /* ... */ };
X<A> xa; // OK
X<B> xb; // OK après P0522R0
         // Erreur précédente : pas une correspondance exacte
X<C> xc; // OK après P0522R0
         // Erreur précédente : pas une correspondance exacte

template<template<class...> class Q> class Y { /* ... */ };
Y<A> ya; // OK
Y<B> yb; // OK
Y<C> yc; // OK

template<auto n> class D { /* ... */ };   // note: C++17
template<template<int> class R> class Z { /* ... */ };
Z<D> zd; // OK après P0522R0 : le paramètre de modèle
         // est plus spécialisé que l'argument de modèle

template<int> struct SI { /* ... */ };
template<template<auto> class> void FA(); // note: C++17
FA<SI>(); // Erreur

Arguments de modèle par défaut

Les arguments de modèle par défaut sont spécifiés dans les listes de paramètres après le signe =. Des valeurs par défaut peuvent être spécifiées pour tout type de paramètre de modèle (type, non-type ou template), mais pas pour les packs de paramètres (depuis C++11).

Si la valeur par défaut est spécifiée pour un paramètre de modèle d'un modèle de classe primaire, d'un modèle de variable primaire, (depuis C++14) ou d'un alias de modèle, chaque paramètre de modèle suivant doit avoir un argument par défaut, sauf que le tout dernier peut être un pack de paramètres de modèle (depuis C++11). Dans un modèle de fonction, il n'existe aucune restriction sur les paramètres qui suivent une valeur par défaut, et un pack de paramètres ne peut être suivi d'autres paramètres de type que s'ils ont des valeurs par défaut ou peuvent être déduits des arguments de fonction (depuis C++11).

Les paramètres par défaut ne sont pas autorisés

  • dans la définition hors classe d'un membre d'un modèle de classe (ils doivent être fournis dans la déclaration à l'intérieur du corps de la classe). Notez que les membres modèles de classes non template peuvent utiliser des paramètres par défaut dans leurs définitions hors classe (voir GCC bug 53856)
  • dans les déclarations de modèle de classe amie
  • dans toute déclaration ou définition de modèle de fonction

(jusqu'à C++11)

Dans la déclaration d'un modèle de fonction amie, les arguments de modèle par défaut ne sont autorisés que si la déclaration est une définition et qu'aucune autre déclaration de cette fonction n'apparaît dans cette unité de traduction.

(depuis C++11)

Les arguments de modèle par défaut figurant dans les déclarations sont fusionnés de manière similaire aux arguments par défaut de fonction :

template<typename T1, typename T2 = int> class A;
template<typename T1 = int, typename T2> class A;

// ce qui précède est identique à ce qui suit :
template<typename T1 = int, typename T2 = int> class A;

Mais un même paramètre ne peut pas recevoir deux arguments par défaut dans la même portée :

template<typename T = int> class X;
template<typename T = int> class X {}; // error

Lors de l'analyse d'un argument de modèle par défaut pour un paramètre de modèle non-type, le premier > non imbriqué est considéré comme la fin de la liste de paramètres de modèle plutôt qu'un opérateur supérieur à

template<int i = 3 > 4>   // erreur de syntaxe
class X { /* ... */ };

template<int i = (3 > 4)> // OK
class Y { /* ... */ };

Les listes de paramètres de modèle des paramètres de modèle template peuvent avoir leurs propres arguments par défaut, qui ne sont effectifs que là où le paramètre de modèle template lui-même est dans la portée :

// modèle de classe, avec un paramètre de type de modèle ayant une valeur par défaut
template<typename T = float>
struct B {};

// le paramètre de modèle de modèle T a une liste de paramètres, qui
// consiste en un paramètre de type de modèle ayant une valeur par défaut
template<template<typename = float> typename T>
struct A
{
    void f();
    void g();
};

// définitions de modèles de fonctions membres hors du corps de la classe

template<template<typename TT> class T>
void A<T>::f()
{
    T<> t; // erreur : TT n'a pas de valeur par défaut dans la portée
}

template<template<typename TT = char> class T>
void A<T>::g()
{
    T<> t; // OK : t est T<char>
}

L'accès membre aux noms utilisés dans un paramètre de modèle par défaut est vérifié à la déclaration, et non au point d'utilisation :

class B {};

template<typename T>
class C
{
protected:
    typedef T TT;
};

template<typename U, typename V = typename U::TT>
class D: public U {};

D<C<B>>* d; // erreur : C::TT est protégé

L'argument de modèle par défaut est instancié implicitement lorsque la valeur de cet argument par défaut est nécessaire, sauf si le modèle sert à désigner une fonction :

template<typename T, typename U = int>
struct S {};

S<bool>* p; // L'argument par défaut de U est instancié à ce point
            // le type de p est S<bool, int>*

(depuis C++14)

Équivalence des arguments de modèle

L'équivalence des arguments de modèle sert à déterminer si deux identificateurs de modèle sont identiques.

Deux valeurs sont template-argument-equivalent si elles sont du même type et si l'une des conditions suivantes est satisfaite :

  • Elles sont de type entier ou énumération et leurs valeurs sont identiques.
  • Elles sont de type pointeur et ont la même valeur de pointeur.
  • Elles sont de type pointeur vers membre et désignent le même membre de classe ou sont toutes deux la valeur de pointeur vers membre nul.
  • Elles sont de type référence lvalue et désignent le même objet ou la même fonction.
  • Elles sont de type std::nullptr_t.

(depuis C++11)

  • Elles sont de type virgule flottante et leurs valeurs sont identiques.
  • Elles sont de type tableau (auquel cas les tableaux doivent être des objets membres d'une classe/union) et leurs éléments correspondants sont template-argument-equivalent.
  • Elles sont de type union et soit elles n'ont aucun membre actif, soit elles ont le même membre actif et leurs membres actifs sont template-argument-equivalent.
  • Elles sont d'un type fermeture de lambda.
  • Elles sont de type classe non union et leurs sous-objets directs correspondants et membres référence sont template-argument-equivalent.

(depuis C++20)

Notes

Dans les paramètres de modèle, des contraintes de type peuvent être utilisées pour les paramètres de type comme pour les paramètres non-type, selon la présence de auto.

template<typename>
concept C = true;

template<C,     // paramètre de type
         C auto // paramètre non de type
        >
struct S{};

S<int, 0> s;

(depuis C++20)

Exemples

#include <array>
#include <iostream>
#include <numeric>

// paramètre de modèle non de type simple
template<int N>
struct S { int a[N]; };

template<const char*>
struct S2 {};

// exemple de paramètre non de type complexe
template
<
    char c,             // type entier
    int (&ra)[5],       // référence lvalue vers un objet (de type tableau)
    int (*pf)(int),     // pointeur vers fonction
    int (S<10>::*a)[10] // pointeur vers objet membre (de type int[10])
>
struct Complicated
{
    // appelle la fonction sélectionnée à la compilation
    // et stocke le résultat dans le tableau sélectionné à la compilation
    void foo(char base)
    {
        ra[4] = pf(c - base);
    }
};

//  S2<"fail"> s2;        // erreur : une chaîne littérale ne peut pas être utilisée
    char okay[] = "okay"; // objet statique avec liaison
//  S2<&okay[0]> s3;      // erreur : un élément de tableau n'a pas de liaison
    S2<okay> s4;          // works

int a[5];
int f(int n) { return n; }

// C++20 : un NTTP peut être un type classe littéral
template<std::array arr>
constexpr
auto sum() { return std::accumulate(arr.cbegin(), arr.cend(), 0); }

// C++20 : les arguments de modèle de classe sont déduits au site d'appel
static_assert(sum<std::array<double, 8>{3, 1, 4, 1, 5, 9, 2, 6}>() == 31.0);
// C++20 : déduction d'argument NTTP et CTAD
static_assert(sum<std::array{2, 7, 1, 8, 2, 8}>() == 28);

int main()
{
    S<10> s; // s.a est un tableau de 10 int
    s.a[9] = 4;

    Complicated<'2', a, f, &S<10>::a> c;
    c.foo('0');

    std::cout << s.a[9] << a[4] << '\n';
}
