Attribut C++ : carries_dependency (depuis C++11)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Indique que la chaîne de dépendance dans release-consume std::memory_order se propage vers l'intérieur et vers l'extérieur de la fonction, ce qui permet au compilateur d'omettre des instructions de barrière mémoire inutiles.

Syntaxe

| | | | [[carries_dependency]] | | | |

Explication

Cet attribut peut apparaître dans deux situations :

  1. il peut s'appliquer aux déclarations de paramètres d'une fonction ou d'expressions lambda, auquel cas il indique que l'initialisation du paramètre transmet la dépendance à la conversion lvalue-to-rvalue de cet objet.

  2. Il peut s'appliquer à la déclaration de fonction dans son ensemble, auquel cas il indique que la valeur de retour transmet la dépendance à l'évaluation de l'expression d'appel de fonction.

Cet attribut doit apparaître dans la première déclaration d'une fonction ou de l'un de ses paramètres dans toute unité de traduction. S'il n'est pas utilisé dans la première déclaration d'une fonction ou de l'un de ses paramètres dans une autre unité de traduction, le programme est mal formé ; aucun diagnostic requis.

Exemple

Adapté presque sans modification de SO.

#include <atomic>
#include <iostream>

void print(int* val)
{
    std::cout << *val << std::endl;
}

void print2(int* val [[carries_dependency]])
{
    std::cout << *val << std::endl;
}

int main()
{
    int x{42};
    std::atomic<int*> p = &x;
    int* local = p.load(std::memory_order_consume);

    if (local)
    {
        // La dépendance est explicite, donc le compilateur sait que local est
        // déréférencé, et qu'il doit garantir que la chaîne de dépendance
        // est préservée afin d'éviter une barrière (sur certaines architectures).
        std::cout << *local << std::endl;
    }

    if (local)
    {
        // La définition de print est opaque (en supposant qu'elle n'est pas en ligne),
        // donc le compilateur doit émettre une barrière afin de garantir que
        // la lecture de *p dans print renvoie la valeur correcte.
        print(local);
    }

    if (local)
    {
        // Le compilateur peut supposer que, bien que print2 soit également opaque,
        // la dépendance entre le paramètre et la valeur déréférencée est
        // préservée dans le flux d'instructions, et qu'aucune barrière n'est nécessaire (sur
        // certaines architectures). Évidemment, la définition de print2 doit réellement
        // préserver cette dépendance, donc l'attribut affectera aussi le
        // code généré pour print2.
        print2(local);
    }
}
