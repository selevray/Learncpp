Déduction d'arguments de modèle

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Pour instancier un modèle de fonction, chaque argument de modèle doit être connu, mais tous n'ont pas besoin d'être spécifiés. Lorsque c'est possible, le compilateur déduit les arguments de modèle manquants à partir des arguments de la fonction. Cela se produit lors d'un appel de fonction, lorsqu'on prend l'adresse d'un modèle de fonction, et dans certains autres contextes :

template<typename To, typename From>
To convert(From f);

void g(double d)
{
    int i = convert<int>(d);    // appelle convert<int, double>(double)
    char c = convert<char>(d);  // appelle convert<char, double>(double)
    int(*ptr)(float) = convert; // instancie convert<int, float>(float)
                                // et stocke son adresse dans ptr
}

Ce mécanisme permet d'utiliser des opérateurs modèles, puisqu'il n'existe pas de syntaxe pour spécifier les arguments de modèle d'un opérateur autrement qu'en le réécrivant sous la forme d'une expression d'appel de fonction :

#include <iostream>

int main()
{
    std::cout << "Hello, world" << std::endl;
    // operator<< est recherché par ADL comme std::operator<<,
    // puis déduit comme operator<<<char, std::char_traits<char>> dans les deux cas
    // std::endl est déduit comme &std::endl<char, std::char_traits<char>>
}

La déduction d'arguments de modèle a lieu après la recherche de nom du modèle de fonction (qui peut impliquer une recherche dépendante des arguments) et avant la substitution des arguments de modèle (qui peut impliquer SFINAE) et la résolution de surcharge.

La déduction d'arguments de modèle est aussi effectuée lorsque le nom d'un modèle de classe est utilisé comme type d'un objet en cours de construction :

std::pair p(2, 4.5);
std::tuple t(4, 3, 2.5);
std::copy_n(vi1, 3, std::back_insert_iterator(vi2));
std::for_each(vi.begin(), vi.end(), Foo([&](int i) {...}));
auto lck = std::lock_guard(foo.mtx);
std::lock_guard lck2(foo.mtx, ul);

La déduction d'arguments de modèle pour les modèles de classe a lieu dans les déclarations et dans les expressions de conversion explicites ; voir déduction d'arguments de modèle de classe pour plus de détails.

(depuis C++17)

Déduction à partir d'un appel de fonction

La déduction d'arguments de modèle tente de déterminer les arguments de modèle (types pour les paramètres de modèle de type Ti, modèles pour les paramètres de modèle de modèle TTi, et valeurs pour les paramètres de modèle non de type Ii), qui peuvent être substitués dans chaque paramètre P pour produire le type déduit A, qui est identique au type de l'argument A, après les ajustements listés ci-dessous.

S'il y a plusieurs paramètres, chaque couple P/A est déduit séparément, puis les arguments de modèle déduits sont combinés. Si la déduction échoue ou est ambiguë pour un couple P/A, ou si des couples différents donnent des arguments de modèle déduits différents, ou si un argument de modèle n'est ni déduit ni spécifié explicitement, la compilation échoue.

Si la suppression des références et des qualificateurs cv de P donne std::initializer_list<P'> et que A est une braced-init-list, alors la déduction est effectuée pour chaque élément de la liste d'initialisation, en prenant P' comme paramètre et l'élément de liste A' comme argument :

template<class T>
void f(std::initializer_list<T>);

f({1, 2, 3});  // P = std::initializer_list<T>, A = {1, 2, 3}
               // P'1 = T, A'1 = 1 : T déduit = int
               // P'2 = T, A'2 = 2 : T déduit = int
               // P'3 = T, A'3 = 3 : T déduit = int
               // OK : T déduit = int

f({1, "abc"}); // P = std::initializer_list<T>, A = {1, "abc"}
               // P'1 = T, A'1 = 1 : T déduit = int
               // P'2 = T, A'2 = "abc" : T déduit = const char*
               // erreur : la déduction échoue, T est ambigu

Si la suppression des références et des qualificateurs cv de P donne P'[N], et que A est une braced-init-list non vide, alors la déduction est effectuée comme ci-dessus, sauf que si N est un paramètre de modèle non de type, il est déduit de la longueur de la liste d'initialisation :

template<class T, int N>
void h(T const(&)[N]);
h({1, 2, 3}); // T déduit = int, N déduit = 3

template<class T>
void j(T const(&)[3]);
j({42}); // T déduit = int, la borne de tableau n'est pas un paramètre, non considérée

struct Aggr
{
    int i;
    int j;
};

template<int N>
void k(Aggr const(&)[N]);
k({1, 2, 3});       // erreur : la déduction échoue, pas de conversion de int vers Aggr
k({{1}, {2}, {3}}); // OK : N déduit = 3

template<int M, int N>
void m(int const(&)[M][N]);
m({{1, 2}, {3, 4}}); // M déduit = 2, N déduit = 2

template<class T, int N>
void n(T const(&)[N], T);
n({{1}, {2}, {3}}, Aggr()); // T déduit = Aggr, N déduit = 3

Si un pack de paramètres apparaît comme dernier P, alors le type P est confronté au type A de chacun des arguments restants de l'appel. Chaque correspondance déduit les arguments de modèle pour la position suivante de l'expansion du pack :

template<class... Types>
void f(Types&...);

void h(int x, float& y)
{
    const int z = x;
    f(x, y, z); // P = Types&..., A1 = x : premier membre de Types... déduit = int
                // P = Types&..., A2 = y : deuxième membre de Types... déduit = float
                // P = Types&..., A3 = z : troisième membre de Types... déduit = const int
                // appelle f<int, float, const int>
}

(depuis C++11)

Si P est un type fonction, un type pointeur vers fonction ou un type pointeur vers fonction membre, et si A est un ensemble de fonctions surchargées ne contenant pas de modèles de fonction, la déduction d'arguments de modèle est tentée avec chaque surcharge. Si une seule réussit, cette déduction réussie est utilisée. Si aucune ou plusieurs réussissent, le paramètre de modèle est un contexte non déductible (voir ci-dessous) :

template<class T>
int f(T(*p)(T));

int g(int);
int g(char);

f(g); // P = T(*)(T), A = ensemble de surcharges
      // P = T(*)(T), A1 = int(int) : T déduit = int
      // P = T(*)(T), A2 = int(char) : échec de la déduction de T
      // une seule surcharge fonctionne, la déduction réussit

Avant le début de la déduction, les ajustements suivants sont apportés à P et A :

  1. Si P n'est pas un type référence,

a) si A est un type tableau, A est remplacé par le type pointeur obtenu par la conversion tableau-vers-pointeur ;

b) sinon, si A est un type fonction, A est remplacé par le type pointeur obtenu par la conversion fonction-vers-pointeur ;

c) sinon, si A est un type qualifié cv, les qualificateurs cv de premier niveau sont ignorés pour la déduction :

template<class T>
void f(T);

int a[3];
f(a); // P = T, A = int[3], ajusté en int* : T déduit = int*

void b(int);
f(b); // P = T, A = void(int), ajusté en void(*)(int) : T déduit = void(*)(int)

const int c = 13;
f(c); // P = T, A = const int, ajusté en int : T déduit = int

  1. Si P est un type qualifié cv, les qualificateurs cv de premier niveau sont ignorés pour la déduction.

  2. Si P est un type référence, le type référencé est utilisé pour la déduction.

  3. Si P est une référence rvalue vers un paramètre de modèle non qualifié cv (appelées références de transmission), et que l'argument d'appel de fonction correspondant est une lvalue, le type référence lvalue vers A est utilisé à la place de A pour la déduction (Note : c'est la base du fonctionnement de std::forward. Note : dans la déduction d'arguments de modèle de classe, un paramètre de modèle d'un modèle de classe n'est jamais une référence de transmission (depuis C++17)) :

template<class T>
int f(T&&);       // P est une référence rvalue vers T non qualifié cv (référence de transfert)

template<class T>
int g(const T&&); // P est une référence rvalue vers T qualifié cv (pas de cas particulier)

int main()
{
    int i;
    int n1 = f(i); // l'argument est une lvalue : appelle f<int&>(int&) (cas particulier)
    int n2 = f(0); // l'argument n'est pas une lvalue : appelle f<int>(int&&)

//  int n3 = g(i); // erreur : déduit g<int>(const int&&), qui
                   // ne peut pas lier une référence rvalue à une lvalue
}

Après ces transformations, la déduction se poursuit comme décrit ci-dessous (voir la section déduction à partir d'un type) et tente de trouver des arguments de modèle tels que le A déduit (c'est-à-dire P après les ajustements énumérés ci-dessus et la substitution des paramètres de modèle déduits) soit identique au transformé A, c'est-à-dire A après les ajustements énumérés ci-dessus.

Si la déduction habituelle à partir de P et A échoue, les alternatives suivantes sont en outre considérées :

  1. Si P est un type référence, le A déduit (c'est-à-dire le type référencé par la référence) peut être davantage qualifié cv que le A transformé :
template<typename T>
void f(const T& t);

bool a = false;
f(a); // P = const T&, ajusté en const T, A = bool :
      // T déduit = bool, A déduit = const bool
      // A déduit est plus qualifié cv que A
  1. Le A transformé peut être un autre type pointeur ou pointeur vers membre pouvant être converti en A déduit via une conversion de qualificationou une conversion de pointeur de fonction (depuis C++17) :
template<typename T>
void f(const T*);

int* p;
f(p); // P = const T*, A = int* :
      // T déduit = int, A déduit = const int*
      // la conversion de qualification s'applique (de int* à const int*)
  1. Si P est une classe et que P a la forme simple-template-id, alors le A transformé peut être une classe dérivée du A déduit. De même, si P est un pointeur vers une classe de la forme simple-template-id, le A transformé peut être un pointeur vers une classe dérivée pointée par le A déduit :
template<class T>
struct B {};

template<class T>
struct D : public B<T> {};

template<class T>
void f(B<T>&) {}

void f()
{
    D<int> d;
    f(d); // P = B<T>&, ajusté en P = B<T> (un simple-template-id), A = D<int> :
          // T déduit = int, A déduit = B<int>
          // A dérive de A déduit
}

Contextes non déductibles

Dans les cas suivants, les types, modèles et valeurs non de type utilisés pour composer P ne participent pas à la déduction d'arguments de modèle, mais utilisent à la place les arguments de modèle déduits ailleurs ou explicitement spécifiés. Si un paramètre de modèle n'est utilisé que dans des contextes non déductibles et n'est pas explicitement spécifié, la déduction d'arguments de modèle échoue.

  1. Le nested-name-specifier (tout ce qui se trouve à gauche de l'opérateur de résolution de portée ::) d'un type spécifié à l'aide d'un qualified-id :
// le modèle d'identité, souvent utilisé pour exclure certains arguments de la déduction
// (disponible sous le nom std::type_identity depuis C++20)
template<typename T>
struct identity { typedef T type; };

template<typename T>
void bad(std::vector<T> x, T value = 1);

template<typename T>
void good(std::vector<T> x, typename identity<T>::type value = 1);

std::vector<std::complex<double>> x;

bad(x, 1.2);  // P1 = std::vector<T>, A1 = std::vector<std::complex<double>>
              // P1/A1 : T déduit = std::complex<double>
              // P2 = T, A2 = double
              // P2/A2 : T déduit = double
              // erreur : la déduction échoue, T est ambigu

good(x, 1.2); // P1 = std::vector<T>, A1 = std::vector<std::complex<double>>
              // P1/A1 : T déduit = std::complex<double>
              // P2 = identity<T>::type, A2 = double
              // P2/A2 : utilise le T déduit par P1/A1 car T se trouve à gauche de :: dans P2
              // OK : T = std::complex<double>
  1. Un spécificateur d'indexation de pack ou une expression d'indexation de pack :
template<typename... Ts>
void f(Ts...[0], std::tuple<Ts...>);

f(3, std::tuple(5, 'A'));
// P2 = std::tuple<Ts...>, A2 = std::tuple<int, char>
// P2/A2 : premier membre de Ts... déduit = int
// P2/A2 : second membre de Ts... déduit = char
// P1 = Ts...[0], A1 = int : Ts...[0] est un contexte non déductible

(depuis C++26)

  1. L'expression d'un spécificateur decltype :
template<typename T>
void f(decltype(*std::declval<T>()) arg);

int n;
f<int*>(n); // P = decltype(*declval<T>()), A = int : T est dans un contexte non déductible

(depuis C++11)

  1. Un argument de modèle non de type ou une borne de tableau dans lequel une sous-expression référence un paramètre de modèle :
template<std::size_t N>
void f(std::array<int, 2 * N> a);

std::array<int, 10> a;
f(a); // P = std::array<int, 2 * N>, A = std::array<int, 10> :
      // 2 * N est un contexte non déductible, N ne peut pas être déduit
      // note : f(std::array<int, N> a) pourrait déduire N
  1. Un paramètre de modèle utilisé dans le type d'un paramètre de fonction ayant un argument par défaut qui est utilisé dans l'appel pour lequel la déduction d'arguments est effectuée :
template<typename T, typename F>
void f(const std::vector<T>& v, const F& comp = std::less<T>());

std::vector<std::string> v(3);
f(v); // P1 = const std::vector<T>&, A1 = lvalue std::vector<std::string>
      // P1/A1 : T déduit = std::string
      // P2 = const F&, A2 = rvalue std::less<std::string>
      // P2 est un contexte non déductible pour F (paramètre de modèle) utilisé dans le
      // type de paramètre (const F&) du paramètre de fonction comp,
      // qui possède un argument par défaut utilisé dans l'appel f(v)
  1. Le paramètre P, dont A est une fonction ou un ensemble de surcharges tel que plus d'une fonction correspond à P ou aucune fonction ne correspond à P, ou que l'ensemble de surcharges comprend un ou plusieurs modèles de fonction :
template<typename T>
void out(const T& value) { std::cout << value; }

out("123");     // P = const T&, A = lvalue const char[4] : T déduit = char[4]
out(std::endl); // P = const T&, A = modèle de fonction : T est dans un contexte non déductible
  1. Le paramètre P, dont A est une braced-init-list, mais P n'est pas std::initializer_list, une référence vers une (éventuellement qualifiée cv), ou une référence vers un tableau}}:
template<class T>
void g1(std::vector<T>);

template<class T>
void g2(std::vector<T>, T x);

g1({1, 2, 3});     // P = std::vector<T>, A = {1, 2, 3} : T est dans un contexte non déductible
                   // erreur : T n'est pas spécifié explicitement ni déduit d'un autre couple P/A

g2({1, 2, 3}, 10); // P1 = std::vector<T>, A1 = {1, 2, 3} : T est dans un contexte non déductible
                   // P2 = T, A2 = int : T déduit = int
  1. Le paramètre P qui est un pack de paramètres et qui n'apparaît pas à la fin de la liste de paramètres :
template<class... Ts, class T>
void f1(T n, Ts... args);

template<class... Ts, class T>
void f2(Ts... args, T n);

f1(1, 2, 3, 4); // P1 = T, A1 = 1 : T déduit = int
                // P2 = Ts..., A2 = 2, A3 = 3, A4 = 4 : Ts déduit = [int, int, int]

f2(1, 2, 3, 4); // P1 = Ts... : Ts est un contexte non déductible
  1. La liste de paramètres de modèle qui apparaît dans le paramètre P, et qui comprend une expansion de pack qui n'est pas à la toute fin de la liste de paramètres de modèle :
template<int...>
struct T {};

template<int... Ts1, int N, int... Ts2>
void good(const T<N, Ts1...>& arg1, const T<N, Ts2...>&);

template<int... Ts1, int N, int... Ts2>
void bad(const T<Ts1..., N>& arg1, const T<Ts2..., N>&);

T<1, 2> t1;
T<1, -1, 0> t2;

good(t1, t2); // P1 = const T<N, Ts1...>&, A1 = T<1, 2> :
              // N déduit = 1, Ts1 déduit = [2]
              // P2 = const T<N, Ts2...>&, A2 = T<1, -1, 0> :
              // N déduit = 1, Ts2 déduit = [-1, 0]

bad(t1, t2);  // P1 = const T<Ts1..., N>&, A1 = T<1, 2> :
              // <Ts1..., N> est un contexte non déductible
              // P2 = const T<Ts2..., N>&, A2 = T<1, -1, 0> :
              // <Ts2..., N> est un contexte non déductible

(depuis C++11)

  1. Pour P de type tableau (mais non référence vers tableau ni pointeur vers tableau), la borne majeure du tableau :
template<int i>
void f1(int a[10][i]);

template<int i>
void f2(int a[i][20]);    // P = int[i][20], type tableau

template<int i>
void f3(int (&a)[i][20]); // P = int(&)[i][20], référence vers un tableau

void g()
{
    int a[10][20];
    f1(a);     // OK : i déduit = 20
    f1<20>(a); // OK
    f2(a);     // erreur : i est dans un contexte non déductible
    f2<10>(a); // OK
    f3(a);     // OK : i déduit = 10
    f3<10>(a); // OK
}

Dans tous les cas, si une partie d'un nom de type est non déduite, tout le nom de type constitue un contexte non déductible. Cependant, les types composés peuvent inclure à la fois des noms de type déduits et non déduits. Par exemple, dans A<T>::B<T2>, T est non déduit à cause de la règle #1 (spécificateur de nom imbriqué), et T2 est non déduit car il fait partie du même nom de type, mais dans void(*f)(typename A<T>::B, A<T>), le T dans A<T>::B est non déduit (à cause de la même règle), tandis que le T dans A<T> est déduit.

Déduction à partir d'un type

Étant donné un paramètre de fonction P qui dépend d'un ou plusieurs paramètres de modèle de type Ti, de paramètres de modèle template TTi, ou de paramètres de modèle non de type Ii, et l'argument correspondant A, la déduction a lieu si P a l'une des formes suivantes :
Cette section est incomplète Raison : possiblement un tableau avec de micro-exemples
  • cv(facultatif) T;
  • T*;
  • T&;
  • T&&;

(depuis C++11)

  • T(facultatif) [I(facultatif)];
  • T(facultatif) (U(facultatif));

(jusqu'à C++17)

  • T(facultatif) (U(facultatif)) noexcept(I(facultatif));

(depuis C++17)

  • T(facultatif) U(facultatif)::*;
  • TT(facultatif)<T>;
  • TT(facultatif)<I>;
  • TT(facultatif)<TU>;
  • TT(facultatif)<>.

Dans les formes ci-dessus,

  • T(facultatif) ou U(facultatif) représente un type ou parameter-type-list qui satisfait soit ces règles récursivement, soit est un contexte non déductible dans P ou A, soit est le même type non dépendant dans P et A.
  • TT(facultatif) ou TU(facultatif) représente soit un modèle de classe, soit un paramètre de modèle template.
  • I(facultatif) représente une expression qui est soit une I, est dépendante de la valeur dans P ou A, soit a la même valeur constante dans P et A.
  • noexcept(I(facultatif)) représente une spécification d'exception dans laquelle l'opérande du spécificateur noexcept possiblement implicite satisfait les règles pour un I(facultatif) ci-dessus.

(depuis C++17)

Si P a l'une des formes qui incluent une liste de paramètres de modèle <T> ou <I>, alors chaque élément Pi de cette liste d'arguments de modèle est comparé à l'argument de modèle correspondant Ai de son A. Si le dernier Pi est une expansion de pack, alors son motif est comparé à chaque argument restant de la liste d'arguments de modèle de A. Un paramètre pack final qui n'est pas autrement déduit est déduit comme un pack de paramètres vide.

Si P a l'une des formes qui incluent une liste de paramètres de fonction (T), alors chaque paramètre Pi de cette liste est comparé à l'argument correspondant Ai de la liste de paramètres de fonction de A. Si le dernier Pi est une expansion de pack, alors son déclarateur est comparé à chaque Ai restant dans la liste de types de paramètres de A.

Les formes peuvent être imbriquées et traitées récursivement :

  • X<int>(*)(char[6]) est un exemple de T*, où T est X<int>(char[6]) ;
  • X<int>(char[6]) est un exemple de T(facultatif) (U(facultatif)), où T est X<int> et U est char[6] ;

(jusqu'à C++17)

  • X<int>(char[6]) est un exemple de T(facultatif) (U(facultatif)) noexcept(I(facultatif)), où T est X<int>, U est char[6], et I dans le spécificateur noexcept implicite est false ;

(depuis C++17)

  • X<int> est un exemple de TT(facultatif)<T>, où TT est X et T est int, et
  • char[6] est un exemple de T(facultatif) [I(facultatif)], où T est char et I est std::size_t(6).

Un argument de modèle de type ne peut pas être déduit à partir du type d'un argument de modèle non de type :

template<typename T, T i>
void f(double a[10][i]);

double v[10][20];
f(v); // P = double[10][i], A = double[10][20] :
      // i peut être déduit égal à 20
      // mais T ne peut pas être déduit du type de i

(jusqu'à C++17)

Lorsque la valeur de l'argument correspondant à un paramètre de modèle non de type P, déclaré avec un type dépendant, est déduite d'une expression, les paramètres de modèle du type de P sont déduits à partir du type de la valeur.

template<long n>
struct A {};

template<class T>
struct C;

template<class T, T n>
struct C<A<n>> { using Q = T; };

typedef long R;

typedef C<A<2>>::Q R; // OK : T a été déduit comme long
                      // à partir de la valeur d'argument de modèle dans le type A<2>

template<auto X>
class bar {};

template<class T, T n>
void f(bar<n> x);

f(bar<3>{}); // OK: T a été déduit en int (et n en 3)
             // à partir de la valeur d'argument de modèle dans le type bar<3>

Le type de N dans le type T[N] est std::size_t.

template<class T, T i>
void f(int (&a)[i]);

int v[10];
f(v); // OK : T est std::size_t

Le type de B dans noexcept(B) spécificateur d'un type fonction est bool.

template<bool>
struct A {};

template<auto>
struct B;
template<auto X, void (*F)() noexcept(X)>
struct B<F> { A<X> ax; };

void f_nothrow() noexcept;
B<f_nothrow> bn; // OK : X est déduit comme true et le type de X est déduit comme bool.

(depuis C++17)

Si un paramètre de modèle non de type d'un modèle de fonction est utilisé dans la liste de paramètres de modèle d'un paramètre de fonction (qui est aussi un modèle), et que l'argument de modèle correspondant est déduit, le type de l'argument de modèle déduit (tel que spécifié dans sa liste de paramètres de modèle englobante, ce qui signifie que les références sont conservées) doit correspondre exactement au type du paramètre de modèle non de type, à l'exception près que les qualificateurs cv sont ignorés, et sauf lorsque l'argument de modèle est déduit d'une borne de tableau : dans ce cas, tout type entier est autorisé, même bool bien qu'il devienne toujours true :

template<int i>
class A {};

template<short s>
void f(A<s>); // le type du paramètre de modèle non type est short

void k1()
{
    A<1> a;  // le type du paramètre de modèle non type de a est int

    f(a);    // P = A<(short)s>, A = A<(int)1>
             // erreur : l'argument de modèle non type déduit n'a pas le même
             // type que l'argument de modèle correspondant

    f<1>(a); // OK : l'argument de modèle n'est pas déduit,
             // ceci appelle f<(short)1>(A<(short)1>)
}

template<int&>
struct X;

template<int& R>
void k2(X<R>&);

int n;
void g(X<n> &x)
{
    k2(x); // P = X<R>, A = X<n>
           // le type du paramètre est int&
           // le type de l'argument est int& dans la déclaration de modèle de struct X
           // OK (avec CWG 2091) : déduit R pour référencer n
}

Un paramètre de modèle de type ne peut pas être déduit à partir du type d'un argument par défaut de fonction :

template<typename T>
void f(T = 5, T = 7);

void g()
{
    f(1);     // OK : appelle f<int>(1, 7)
    f();      // erreur : impossible de déduire T
    f<int>(); // OK : appelle f<int>(5, 7)
}

La déduction d'un paramètre de modèle template peut utiliser le type employé dans la spécialisation de modèle utilisée dans l'appel de fonction :

template<template<typename> class X>
struct A {}; // A est un modèle avec un paramètre TT

template<template<typename> class TT>
void f(A<TT>) {}

template<class T>
struct B {};

A<B> ab;
f(ab); // P = A<TT>, A = A<B> : TT déduit = B, appelle f(A<B>)

Autres contextes

Outre les appels de fonction et les expressions d'opérateurs, la déduction d'arguments de modèle est utilisée dans les situations suivantes :

Déduction de type auto

La déduction d'arguments de modèle est utilisée dans les déclarations de variables, lors de la déduction de la signification du spécificateur auto à partir de l'initialiseur de la variable.

Le paramètre P est obtenu comme suit : dans T, le type déclaré de la variable qui comprend auto, chaque occurrence de auto est remplacée par un paramètre de modèle de type imaginaire U ou, si l'initialisation est une copy-list-initialization, par std::initializer_list<U>. L'argument A est l'expression d'initialisation. Après la déduction de U à partir de P et A selon les règles décrites ci-dessus, le U déduit est substitué dans P pour obtenir le type réel de la variable :

const auto& x = 1 + 2; // P = const U&, A = 1 + 2 :
                       // mêmes règles que pour l'appel de f(1 + 2) où f est
                       // template<class U> void f(const U& u)
                       // U déduit = int, le type de x est const int&

auto l = {13}; // P = std::initializer_list<U>, A = {13}:
               // U déduit = int, le type de l est std::initializer_list<int>

Dans une direct-list-initialization (mais non dans une copy-list-initialization), lors de la déduction de la signification de auto à partir d'une braced-init-list, la braced-init-list ne doit contenir qu'un seul élément, et le type de auto sera le type de cet élément :

auto x1 = {3}; // x1 est std::initializer_list<int>
auto x2{1, 2}; // erreur : pas un élément unique
auto x3{3};    // x3 est int
               // (avant N3922, x2 et x3 étaient tous deux std::initializer_list<int>)

(depuis C++11)

Fonctions à type de retour auto

La déduction d'arguments de modèle est utilisée dans les déclarations de fonctions, lors de la déduction de la signification du spécificateur auto dans le type de retour de la fonction, à partir de l'instruction return.

Pour les fonctions à type de retour auto, le paramètre P est obtenu comme suit : dans T, le type de retour déclaré de la fonction qui comprend auto, chaque occurrence de auto est remplacée par un paramètre de modèle de type imaginaire U. L'argument A est l'expression de l'instruction return, et si l'instruction return n'a pas d'opérande, A est void(). Après la déduction de U à partir de P et A selon les règles décrites ci-dessus, le U déduit est substitué dans T pour obtenir le type de retour réel :

auto f() { return 42; } // P = auto, A = 42 :
                        // U déduit = int, le type de retour de f est int

Si une telle fonction comporte plusieurs instructions return, la déduction est effectuée pour chaque instruction return. Tous les types obtenus doivent être identiques et deviennent le type de retour réel.

Si une telle fonction ne comporte aucune instruction return, A est void() lors de la déduction.

Note : la signification du marqueur decltype(auto) dans les déclarations de variables et de fonctions n'utilise pas la déduction d'arguments de modèle.

(depuis C++14)

Résolution de surcharge

La déduction d'arguments de modèle est utilisée lors de la résolution de surcharge, lors de la génération de spécialisations à partir d'un modèle de fonction candidat. P et A sont les mêmes que dans un appel de fonction ordinaire :

std::string s;
std::getline(std::cin, s);

// « std::getline » désigne 4 modèles de fonctions,
// dont 2 sont des fonctions candidates (nombre correct de paramètres)

// 1er modèle candidat :
// P1 = std::basic_istream<CharT, Traits>&, A1 = std::cin
// P2 = std::basic_string<CharT, Traits, Allocator>&, A2 = s
// la déduction détermine les paramètres de modèle de type CharT, Traits et Allocator
// spécialisation std::getline<char, std::char_traits<char>, std::allocator<char>>

// 2e modèle candidat :
// P1 = std::basic_istream<CharT, Traits>&&, A1 = std::cin
// P2 = std::basic_string<CharT, Traits, Allocator>&, A2 = s
// la déduction détermine les paramètres de modèle de type CharT, Traits et Allocator
// spécialisation std::getline<char, std::char_traits<char>, std::allocator<char>>

// la résolution de surcharge classe la liaison de référence depuis la lvalue std::cin
// et choisit la première des deux spécialisations candidates

Si la déduction échoue, ou si la déduction réussit mais que la spécialisation qu'elle produit serait invalide (par exemple, un opérateur surchargé dont les paramètres ne sont ni de type classe ni de type énumération), la spécialisation n'est pas incluse dans l'ensemble de surcharges, à l'instar de SFINAE.

Adresse d'un ensemble de surcharges

La déduction d'arguments de modèle est utilisée lors de la prise d'adresse d'un ensemble de surcharges, qui inclut des modèles de fonction.

Le type fonction du modèle de fonction est P. Le type cible est le type de A :

std::cout << std::endl;

// std::endl désigne un modèle de fonction
// type de P de endl =
// std::basic_ostream<CharT, Traits>& (std::basic_ostream<CharT, Traits>&)
// paramètre A de operator<< =
// std::basic_ostream<char, std::char_traits<char>>& (*)(
//   std::basic_ostream<char, std::char_traits<char>>&
// )
// (les autres surcharges de operator<< ne sont pas viables)
// la déduction détermine les paramètres de modèle de type CharT et Traits

Une règle supplémentaire s'applique à la déduction dans ce cas : lors de la comparaison des paramètres de fonction Pi et Ai, si Pi est une référence rvalue vers un paramètre de modèle non qualifié cv (une « référence de transmission ») et que le Ai correspondant est une référence lvalue, alors Pi est ajusté au type du paramètre de modèle (T&& devient T).

Si le type de retour du modèle de fonction est un marqueur (auto ou decltype(auto)), ce type de retour est un contexte non déductible et est déterminé à partir de l'instanciation.

(depuis C++14)

Modèle de fonction de conversion

La déduction d'arguments de modèle est utilisée lors de la sélection des arguments de modèle de fonction de conversion définie par l'utilisateur.

A est le type requis comme résultat de la conversion. P est le type de retour du modèle de fonction de conversion. Si P est un type référence, alors le type référencé est utilisé à la place de P pour les parties suivantes de la section.

Si A n'est pas un type référence :

a) si le P est un type tableau, alors le type pointeur obtenu par conversion tableau-vers-pointeur est utilisé à la place de P ;

b) si le P est un type fonction, alors le type pointeur de fonction obtenu par conversion fonction-vers-pointeur est utilisé à la place de P ;

c) si P est qualifié cv, les qualificateurs cv de premier niveau sont ignorés.

Si A est qualifié cv, les qualificateurs cv de premier niveau sont ignorés. Si A est un type référence, le type référencé est utilisé pour la déduction.

Si la déduction habituelle à partir de P et A (telle que décrite ci-dessus) échoue, les alternatives suivantes sont en plus considérées :

a) si A est un type référence, A peut être plus qualifié cv que le A déduit ;

b) si A est un type pointeur ou pointeur vers membre, le A déduit peut être tout pointeur convertible en A par conversion de qualification :

struct C
{
    template<class T>
    operator T***();
};
C c;

const int* const* const* p1 = c;

// P = T***, A = const int* const* const*
// déduction habituelle d'appel de fonction pour
// template<class T> void f(T*** p) comme si appelé avec l'argument
// de type const int* const* const* échoue
// une déduction supplémentaire pour les fonctions de conversion détermine T = int
// (A déduit int***, convertible en const int* const* const*)

c) si A est un type pointeur de fonction, le A déduit peut être un pointeur vers fonction noexcept, convertible en A par conversion de pointeur de fonction ;

d) si A est un pointeur vers fonction membre, le A déduit peut être un pointeur vers fonction membre noexcept, convertible en A par conversion de pointeur de fonction.

(depuis C++17)

Voir membre modèle pour les autres règles concernant les modèles de fonction de conversion.

Instanciation explicite

La déduction d'arguments de modèle est utilisée dans les instanciations explicites, les spécialisations explicites, et dans les déclarations d'amitié où le declarator-id désigne une spécialisation d'un modèle de fonction (par exemple, friend ostream& operator<< <> (...)) : si tous les arguments de modèle ne sont pas explicitement spécifiés ou par défaut, la déduction d'arguments de modèle sert à déterminer la spécialisation de quel modèle est désignée.

P est le type du modèle de fonction considéré comme correspondance potentielle, et A est le type fonction de la déclaration. S'il n'y a aucune correspondance ou plus d'une (après ordonnancement partiel), la déclaration de fonction est mal formée :

template<class X>
void f(X a);        // 1er modèle f
template<class X>
void f(X* a);       // 2e modèle f
template<>
void f<>(int* a) {} // spécialisation explicite de f

// P1 = void(X), A1 = void(int*) : X déduit = int*, f<int*>(int*)
// P2 = void(X*), A2 = void(int*) : X déduit = int, f<int>(int*)
// f<int*>(int*) et f<int>(int*) sont alors soumis au classement partiel
// qui sélectionne f<int>(int*) comme modèle le plus spécialisé

Une règle supplémentaire s'applique à la déduction dans ce cas : lors de la comparaison des paramètres de fonction Pi et Ai, si Pi est une référence rvalue vers un paramètre de modèle non qualifié cv (une « référence de transmission ») et que le Ai correspondant est une référence lvalue, alors Pi est ajusté au type du paramètre de modèle (T&& devient T).

Modèle de fonction de désallocation

La déduction d'arguments de modèle est utilisée pour déterminer si une spécialisation de fonction de désallocation correspond à une forme de placement donnée de operator new.

P est le type du modèle de fonction considéré comme correspondance potentielle, et A est le type fonction de la fonction de désallocation qui correspondrait à l'opérateur de placement new considéré. S'il n'y a aucune correspondance ou plus d'une (après résolution de surcharge), la fonction de désallocation de placement n'est pas appelée (une fuite mémoire peut se produire) :

struct X
{
    X() { throw std::runtime_error(""); }

    static void* operator new(std::size_t sz, bool b)   { return ::operator new(sz); }
    static void* operator new(std::size_t sz, double f) { return ::operator new(sz); }

    template<typename T>
    static void operator delete(void* ptr, T arg)
    {
        ::operator delete(ptr);
    }
};

int main()
{
    try
    {
        X* p1 = new (true) X; // lorsque X() lève une exception, operator delete est recherché
                              // P1 = void(void*, T), A1 = void(void*, bool) :
                              // T déduit = bool
                              // P2 = void(void*, T), A2 = void(void*, double) :
                              // T déduit = double
                              // la résolution de surcharge choisit operator delete<bool>
    }
    catch(const std::exception&) {}

    try
    {
        X* p1 = new (13.2) X; // même recherche, choisit operator delete<double>
    }
    catch(const std::exception&) {}
}

Modèles d'alias

Les modèles d'alias ne sont pas déduits, sauf dans la déduction d'arguments de modèle de classe (depuis C++20) :

template<class T>
struct Alloc {};

template<class T>
using Vec = vector<T, Alloc<T>>;
Vec<int> v;

template<template<class, class> class TT>
void g(TT<int, Alloc<int>>);
g(v); // OK : TT déduit = vector

template<template<class> class TT>
void f(TT<int>);
f(v); // erreur : TT ne peut pas être déduit comme « Vec » car Vec est un modèle d'alias

Conversions implicites

La déduction de type ne tient pas compte des conversions implicites (autres que les ajustements de type listés ci-dessus) : c'est le rôle de la résolution de surcharge, qui intervient plus tard. Cependant, si la déduction réussit pour tous les paramètres qui participent à la déduction d'arguments de modèle, et si tous les arguments de modèle non déduits sont explicitement spécifiés ou par défaut, alors les paramètres de fonction restants sont comparés aux arguments de fonction correspondants. Pour chaque paramètre restant P dont le type était non dépendant avant la substitution des arguments de modèle explicitement spécifiés, si l'argument correspondant A ne peut pas être implicitement converti en P, la déduction échoue.

Les paramètres de types dépendants auxquels aucun paramètre de modèle ne participe à la déduction d'arguments de modèle, ainsi que les paramètres devenus non dépendants suite à la substitution d'arguments de modèle explicitement spécifiés, seront vérifiés lors de la résolution de surcharge :

template<class T>
struct Z { typedef typename T::x xx; };

template<class T>
typename Z<T>::xx f(void*, T); // #1

template<class T>
void f(int, T);                // #2

struct A {} a;

int main()
{
    f(1, a); // pour #1, la déduction détermine T = struct A, mais l'argument restant 1
             // ne peut pas être converti implicitement en son paramètre void*: la déduction échoue
             // l'instanciation du type de retour n'est pas demandée
             // pour #2, la déduction détermine T = struct A, et l'argument restant 1
             // peut être converti implicitement en son paramètre int : la déduction réussit
             // l'appel de fonction compile comme un appel à #2 (l'échec de déduction est SFINAE)
}
