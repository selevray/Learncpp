expression delete

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Détruit le ou les objets précédemment alloués par la new-expression et libère la zone mémoire obtenue.

Syntaxe

| | | | ::(facultatif) delete expression | (1) | | | | ::(facultatif) delete[] expression | (2) | | |

  • expression — l'une des suivantes :
    • une expression de type classe implicitement convertible contextuellement en pointeur vers un type objet
    • une prvalue de type pointeur vers un type objet

  1. Détruit un objet non tableau créé par une new-expression.

  2. Détruit un tableau créé par une new[]-expression.

Explication

Étant donné le pointeur évalué à partir de expression (après conversions éventuelles) comme ptr.

  1. ptr doit être l'un des suivants
  • un pointeur nul,
  • un pointeur vers un objet non tableau créé par une new-expression, ou
  • un pointeur vers un sous-objet de base d'un objet non tableau créé par une new-expression.

Le type pointé par ptr doit être similaire au type de l'objet (ou du sous-objet de base). Si ptr est autre chose, y compris s'il s'agit d'un pointeur obtenu par la forme tableau de la new-expression, le comportement est indéfini.

  1. ptr doit être un pointeur nul ou un pointeur dont la valeur a été obtenue précédemment par une forme tableau de new-expression dont la fonction d'allocation n'était pas une forme sans allocation (c.-à-d. la surcharge (10)).

Le type pointé par ptr doit être similaire au type des éléments de l'objet tableau. Si ptr est autre chose, y compris s'il s'agit d'un pointeur obtenu par la forme non tableau de la new-expression, le comportement est indéfini.

Le résultat de la delete-expression a toujours le type void.

Si l'objet supprimé a un type classe incomplet au point de suppression, [et la classe complète a un destructeur non trivial ou une fonction de désallocation, le comportement est indéfini (jusqu'à C++26) | le programme est mal formé (depuis C++26)].

Si ptr n'est pas un pointeur nulet la fonction de désallocation n'est pas un destroying delete (depuis C++20), la delete-expression invoque le destructeur (s'il existe) de l'objet détruit, ou de chaque élément du tableau détruit (en allant du dernier élément au premier). Le destructeur doit être accessible depuis le point où apparaît la delete-expression.

Ensuite, qu'une exception ait été levée ou non par un destructeur, la delete-expression invoque la fonction de désallocation : soit operator delete (première version), soit operator delete[] (seconde version), sauf si la new-expression correspondante était combinée avec une autre new-expression (depuis C++14).

Le nom de la fonction de désallocation est recherché dans la portée du type dynamique de l'objet pointé par ptr, ce qui signifie que les fonctions de désallocation propres à la classe, si elles existent, sont trouvées avant les globales. Si :: est présent dans la delete-expression, seul l'espace de noms global est examiné par cette recherche. Dans tous les cas, toutes les déclarations autres que celles des fonctions de désallocation usuelles sont écartées.

Si une fonction de désallocation est trouvée, la fonction à appeler est sélectionnée comme suit (voir fonction de désallocation pour une description plus détaillée de ces fonctions et de leurs effets) :

  • Si au moins une des fonctions de désallocation est un destroying delete, tous les delete non destroying sont ignorés.

(depuis C++20)

  • Si l'exigence d'alignement du type dépasse __STDCPP_DEFAULT_NEW_ALIGNMENT__, les fonctions de désallocation sensibles à l'alignement (avec un paramètre de type std::align_val_t) sont préférées. Pour les autres types, les fonctions de désallocation insensibles à l'alignement (sans paramètre de type std::align_val_t) sont préférées.

  • Si plus d'une fonction préférée est trouvée, seules les fonctions préférées sont prises en compte à l'étape suivante.

  • Si aucune fonction préférée n'est trouvée, les fonctions non préférées sont prises en compte à l'étape suivante.

  • S'il ne reste qu'une seule fonction, cette fonction est sélectionnée.

(depuis C++17)

  • Si les fonctions de désallocation trouvées sont propres à la classe, la fonction de désallocation propre à la classe insensible à la taille (sans paramètre de type std::size_t) est préférée à celle sensible à la taille (avec paramètre de type std::size_t).
  • Sinon, la recherche a atteint la portée globale, et :
  • Si le type est complet et si, pour la forme tableau uniquement, l'opérande est un pointeur vers un type classe ayant un destructeur non trivial, ou un tableau (éventuellement multidimensionnel) de tels types, la fonction globale sensible à la taille (avec un paramètre de type std::size_t) est sélectionnée.
  • Sinon, il n'est pas spécifié si la fonction globale de désallocation sensible à la taille (avec un paramètre de type std::size_t) ou la fonction globale de désallocation insensible à la taille (sans paramètre de type std::size_t) est sélectionnée.

(depuis C++14)

La fonction de désallocation sélectionnée doit être accessible depuis le point où apparaît la delete-expression, sauf si la fonction de désallocation est sélectionnée au point de définition du destructeur virtuel du type dynamique.

Le pointeur vers le bloc de stockage à libérer est passé à la fonction de désallocation sélectionnée par le processus ci-dessus comme premier argument. La taille du bloc est passée comme argument optionnel std::size_t. L'exigence d'alignement est passée comme argument optionnel std::align_val_t. (depuis C++17)

Si ptr est une valeur de pointeur nul, aucun destructeur n'est appelé, et la fonction de désallocation peut ou non être appelée (c'est non spécifié), mais les fonctions de désallocation par défaut sont garanties de ne rien faire lorsqu'elles reçoivent un pointeur nul.

Si ptr est un pointeur vers un sous-objet de classe de base de l'objet alloué avec new, le destructeur de la classe de base doit être virtual, sinon le comportement est indéfini.

Notes

Un pointeur vers void ne peut pas être supprimé car ce n'est pas un pointeur vers un type objet.

Comme une paire de crochets suivant le mot-clé delete est toujours interprétée comme la forme tableau d'une delete-expression, une lambda-expression avec une liste de capture vide immédiatement après delete doit être entourée de parenthèses.

// delete []{ return new int; }(); // erreur d'analyse
delete ([]{ return new int; })();  // OK

(depuis C++11)

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 288 C++98 pour la première forme, le type statique de l'opérande était comparé à son type dynamique comparer le type statique de l'objet à supprimer avec son type dynamique
CWG 353 C++98 si la fonction de désallocation serait invoquée si le destructeur lève une exception était non spécifié toujours invoquée
CWG 599 C++98 la première forme pouvait recevoir un pointeur nul de tout type, y compris les pointeurs de fonction à l'exception des pointeurs vers des types objets, tous les autres types de pointeurs sont rejetés
CWG 1642 C++98 expression pouvait être une lvalue de pointeur non autorisé
CWG 2474 C++98 supprimer un pointeur vers un objet d'un type similaire mais différent entraînait un comportement indéfini rendue bien définie
CWG 2624 C++98 les pointeurs obtenus à partir de operator new[] sans allocation pouvaient être passés à delete[] prohibited
CWG 2758 C++98 on ne savait pas clairement comment le contrôle d'accès était effectué pour la fonction de désallocation et le destructeur rendu clair
