Notes

  • Les formes de type mot-clé (and,or,not) et les formes de type symbole (&&,||,!) peuvent être utilisées de manière interchangeable (voir représentations alternatives).
  • Tous les opérateurs intégrés renvoient bool, et la plupart des surcharges définies par l'utilisateur renvoient aussi bool afin que ces opérateurs puissent être utilisés de la même manière que les opérateurs intégrés. Cependant, dans une surcharge d'opérateur définie par l'utilisateur, n'importe quel type peut être utilisé comme type de retour (y compris void).
  • Les opérateurs intégrés && et || effectuent une évaluation en court-circuit (ils n'évaluent pas le second opérande si le résultat est connu après l'évaluation du premier), mais les opérateurs surchargés se comportent comme des appels de fonction ordinaires et évaluent toujours les deux opérandes.

Explication

Les expressions d'opérateurs logiques ont la forme

| | | | ! rhs | (1) | | | | lhs && rhs | (2) | | | | lhs || rhs | (3) | | |

  1. NON logique

  2. ET logique

  3. OU inclusif logique

Si l'opérande n'est pas bool, il est converti en bool par conversion contextuelle en bool : cela n'est bien formé que si la déclaration bool t(arg) est bien formée, pour un certain temporaire fictif t.

Le résultat est une prvalue de type bool.

Pour l'opérateur NON logique intégré, le résultat vaut true si l'opérande vaut false. Sinon, le résultat vaut false.

Pour l'opérateur ET logique intégré, le résultat vaut true si les deux opérandes valent true. Sinon, le résultat vaut false. Cet opérateur est à court-circuit : si le premier opérande vaut false, le second opérande n'est pas évalué.

Pour l'opérateur OU logique intégré, le résultat vaut true si le premier ou le second opérande (ou les deux) vaut true. Cet opérateur est à court-circuit : si le premier opérande vaut true, le second opérande n'est pas évalué.

Notez que les opérateurs logiques bit à bit n'effectuent pas de court-circuit.

Lors de la résolution de surcharge face aux opérateurs définis par l'utilisateur, les signatures de fonctions intégrées suivantes participent à la résolution de surcharge :

bool operator!(bool)

bool operator&&(bool, bool)

bool operator||(bool, bool)

Exemple

#include <iostream>
#include <sstream>
#include <string>

int main()
{
    int n = 2;
    int* p = &n;
    // les pointeurs sont convertibles en bool
    if (    p && *p == 2  // « *p » est sûr à utiliser après « p && »
        || !p &&  n != 2) // || a une priorité inférieure à &&
        std::cout << "true\n";

    // les flux sont également convertibles en bool
    std::stringstream cin;
    cin << "3...\n" << "2...\n" << "1...\n" << "quit";
    std::cout << "Enter 'quit' to quit.\n";
    for (std::string line;    std::cout << "> "
                           && std::getline(cin, line)
                           && line != "quit";)
        std::cout << line << '\n';
}

Output:

true
Enter 'quit' to quit.
> 3...
> 2...
> 1...
>

Bibliothèque standard

Comme les propriétés de court-circuit de operator&& et operator|| ne s'appliquent pas aux surcharges, et comme les types à sémantique booléenne sont peu courants, seules deux classes de la bibliothèque standard surchargent ces opérateurs :

  • operator! — applique un opérateur arithmétique unaire à chaque élément du valarray (fonction membre publique de std::valarray<T>)
  • operator&&operator|| — applique des opérateurs binaires à chaque élément de deux valarray, ou d'un valarray et d'une valeur (modèle de fonction)
  • operator! — vérifie si une erreur s'est produite (synonyme de fail()) (fonction membre publique de std::basic_ios<CharT,Traits>)

  • logical_and — objet fonction implémentant x && y (modèle de classe)
  • logical_or — objet fonction implémentant x || y (modèle de classe)
  • logical_not — objet fonction implémentant !x (modèle de classe)
