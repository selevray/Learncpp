Initialisation d'agrégat

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Initialise un agrégat à partir d'une liste d'initialisation. C'est une forme d'initialisation par liste (depuis C++11).

Syntaxe

| | | | T object= { arg1, arg2, ... }; | (1) | | | | T object { arg1, arg2, ... }; | (2) | (depuis C++11) | | | T object= { .des1=arg1 , .des2 { arg2 } ... }; | (3) | (depuis C++20) | | | T object { .des1=arg1 , .des2 { arg2 } ... }; | (4) | (depuis C++20) | |

1,2) Initialisation d'un agrégat avec une liste d'initialisation ordinaire.

3,4) Initialisation d'un agrégat avec initialisateurs désignés (classe agrégat uniquement).

Définitions

Agrégat

Un agrégat est l'un des types suivants :

  • types tableaux
  • types classe qui possèdent
  • aucun constructeur déclaré par l'utilisateur

(jusqu'à C++11)

  • aucun constructeur fourni par l'utilisateur, hérité ou explicite

(depuis C++11) (jusqu'à C++20)

  • aucun constructeur déclaré ou hérité par l'utilisateur

(depuis C++20)

  • aucun membre de données non statique direct privé ou protégé
  • aucune classe de base

(jusqu'à C++17)

  • aucune classe de base virtuelle
  • aucune classe de base directe privée ou protégée

(depuis C++17)

  • aucune fonction membre virtuelle
  • aucun initialisateur de membre par défaut

(depuis C++11) (jusqu'à C++14)

Élément

Les éléments d'un agrégat sont :

  • pour un tableau, les éléments du tableau dans l'ordre croissant des indices, ou
  • pour une classe, les membres de données non statiques qui ne sont pas des champs de bits anonymes, dans l'ordre de déclaration.

(jusqu'à C++17)

  • pour une classe, les classes de base directes dans l'ordre de déclaration, suivies des membres de données non statiques directs qui ne sont ni des champs de bits anonymes ni membres d'une union anonyme, dans l'ordre de déclaration.

(depuis C++17)

Rattachement

Chaque clause d'initialisation d'une liste d'initialisation entre accolades est dite se rattacher à un élément de l'agrégat en cours d'initialisation ou à un élément de l'un de ses sous-agrégats.

En considérant la séquence des clauses d'initialisation, et la séquence des éléments de l'agrégat initialement formée comme la séquence des éléments de l'agrégat en cours d'initialisation et potentiellement modifiée comme décrit ci-dessous :

  • Pour chaque clause d'initialisation, si l'une des conditions suivantes est satisfaite, elle se rattache à l'élément d'agrégat correspondant elem :

    • elem n'est pas un agrégat.
    • La clause d'initialisation commence par {.
    • La clause d'initialisation est une expression, et une séquence de conversions implicites peut être formée qui convertit l'expression vers le type de elem.
    • elem est un agrégat qui n'a lui-même aucun élément d'agrégat.

  • Sinon, elem est un agrégat, ce sous-agrégat est remplacé dans la liste des éléments d'agrégat par la séquence de ses propres éléments d'agrégat, et l'analyse de rattachement reprend avec le premier de ces éléments et la même clause d'initialisation. En d'autres termes, ces règles s'appliquent récursivement aux sous-agrégats de l'agrégat.

L'analyse est terminée lorsque toutes les clauses d'initialisation ont été épuisées. Si une clause d'initialisation subsiste sans se rattacher à un élément de l'agrégat ou de l'un de ses sous-agrégats, le programme est mal formé.

struct S1 { int a, b; };
struct S2 { S1 s, t; };

// Chaque sous-agrégat de « x » est associé à une clause d'initialisation commençant par {
S2 x[2] =
{
    // est associé à « x[0] »
    {
        {1, 2}, // est associé à « x[0].s »
        {3, 4}  // est associé à « x[0].t »
    },
    // est associé à « x[1] »
    {
        {5, 6}, // est associé à « x[1].s »
        {7, 8}  // est associé à « x[1].t »
    }
};

// « x » et « y » ont la même valeur (voir ci-dessous)
S2 y[2] = {1, 2, 3, 4, 5, 6, 7, 8};

// Processus d'analyse d'association de « y » :
// 1. Initialise la séquence d'éléments d'agrégat (x[0], x[1]) et
//    la séquence de clauses d'initialisation (1, 2, 3, 4, 5, 6, 7, 8).
// 2. En partant des premiers éléments de chaque séquence,
//    vérifie si 1 est associé à x[0] :
//    · x[0] est un agrégat.
//    · 1 ne commence pas par {.
//    · 1 est une expression, mais elle ne peut pas être implicitement convertie en S2.
//    · x[0] possède des éléments d'agrégat.
// 3. 0 ne peut pas être associé à x[0], donc x[0] est remplacé par x[0].s et x[0].t,
//    la séquence d'éléments d'agrégat devient (x[0].s, x[0].t, x[1]).
// 4. Reprend la vérification d'association, mais 1 ne peut pas non plus être associé à x[0].s.
// 5. La séquence d'éléments d'agrégat devient maintenant (x[0].s.a, x[0].s.b, x[0].t, x[1]).
// 6. Reprend à nouveau la vérification d'association :
//    1 est associé à x[0].s.a, et 2 est associé à x[0].s.b.
// 7. Le reste de l'analyse d'association fonctionne de manière similaire.

char cv[4] = {'a', 's', 'd', 'f', 0}; // Erreur : trop de clauses d'initialisation

Processus d'initialisation

Détermination du genre d'élément

Les effets de l'initialisation d'un agrégat sont :

  1. Déterminer les éléments initialisés explicitement de l'agrégat comme suit :
  • Si la liste d'initialisation est une liste d'initialisateurs désignés (l'agrégat ne peut être que de type classe), l'identifiant de chaque désignateur doit nommer un membre de données non statique direct de la classe, et les éléments initialisés explicitement de l'agrégat sont les éléments qui sont, ou contiennent, ces membres.

(depuis C++20)

  • Sinon, si la liste d'initialisation n'est pas vide, les éléments initialisés explicitement de l'agrégat sont les éléments auxquels se rattache une clause d'initialisation, ainsi que les éléments ayant un sous-agrégat auquel se rattache une clause d'initialisation.
  • Sinon, la liste d'initialisation doit être vide ({}), et il n'y a aucun élément initialisé explicitement. Le programme est mal formé si l'agrégat est une union et qu'il y a deux éléments initialisés explicitement ou plus :
union u { int a; const char* b; };

u a = {1};                   // OK : initialise explicitement le membre `a`
u b = {0, "asdf"};           // erreur : initialise explicitement deux membres
u c = {"asdf"};              // erreur : int ne peut pas être initialisé par "asdf"

// listes d'initialisateurs désignés de C++20
u d = {.b = "asdf"};         // OK : peut initialiser explicitement un membre qui n'est pas le premier
u e = {.a = 1, .b = "asdf"}; // erreur : initialise explicitement deux membres
  1. Initialiser chaque élément de l'agrégatdans l'ordre des éléments. C'est-à-dire que tous les calculs de valeurs et effets de bord associés à un élément donné sont séquencés avant ceux de tout élément qui le suit dans l'ordre (depuis C++11).

Éléments initialisés explicitement

Pour chaque élément initialisé explicitement :

  • Si l'élément est un membre d'union anonyme et que la liste d'initialisation est une liste d'initialisateurs désignés, l'élément est initialisé par la liste d'initialisateurs désignés {D}, où D est la clause d'initialisateur désigné qui nomme un membre de l'union anonyme. Il ne doit y avoir qu'une seule telle clause d'initialisateur désigné.
struct C
{
    union
    {
        int a;
        const char* p;
    };

    int x;
} c = {.a = 1, .x = 3}; // initialise c.a avec 1 et c.x avec 3
  • Sinon, si la liste d'initialisation est une liste d'initialisateurs désignés, l'élément est initialisé avec l'initialisateur de la clause d'initialisateur désigné correspondante.
  • Si cet initialisateur est de la syntaxe (1), et qu'une conversion restrictive est nécessaire pour convertir l'expression, le programme est mal formé.

(depuis C++20)

  • La liste d'initialisation est une liste d'initialisation entre accolades :

(jusqu'à C++20)

  • Sinon, la liste d'initialisation est une liste d'initialisation entre accolades sans désignateurs :

(depuis C++20)

  • Si une clause d'initialisation se rattache à l'élément d'agrégat, alors l'élément d'agrégat est initialisé par copie à partir de la clause d'initialisation.
  • Sinon, l'élément d'agrégat est initialisé par copie à partir d'une liste d'initialisation entre accolades constituée de toutes les clauses d'initialisation qui se rattachent aux sous-objets de l'élément d'agrégat, dans l'ordre d'apparition.
struct A
{
    int x;

    struct B
    {
        int i;
        int j;
    } b;
} a = {1, {2, 3}}; // initialise a.x avec 1, a.b.i avec 2, a.b.j avec 3

struct base1 { int b1, b2 = 42; };

struct base2
{
    base2()
    {
        b3 = 42;
    }

    int b3;
};

struct derived : base1, base2
{
    int d;
};

derived d1{{1, 2}, {}, 4}; // initialise d1.b1 avec 1, d1.b2 avec 2,
                           //             d1.b3 avec 42, d1.d avec 4
derived d2{{}, {}, 4};     // initialise d2.b1 avec 0, d2.b2 avec 42,
                           //             d2.b3 avec 42, d2.d avec 4

Éléments initialisés implicitement

Pour un agrégat qui n'est pas une union, chaque élément qui n'est pas un élément initialisé explicitement est initialisé comme suit :

  • Si l'élément possède un initialisateur de membre par défaut, l'élément est initialisé à partir de cet initialisateur.

(depuis C++11)

  • Sinon, si l'élément n'est pas une référence, l'élément est initialisé par copie à partir d'une liste d'initialisation vide.
  • Sinon, le programme est mal formé.
struct S
{
    int a;
    const char* b;
    int c;
    int d = b[a];
};

// initialise ss.a avec 1,
//             ss.b avec "asdf",
//             ss.c avec la valeur d'une expression de la forme int{} (c'est-à-dire 0),
//         et ss.d avec la valeur de ss.b[ss.a] (c'est-à-dire 's')
S ss = {1, "asdf"};

Si l'agrégat est une union et que la liste d'initialisation est vide, alors

  • Si un membre variant possède un initialisateur de membre par défaut, ce membre est initialisé à partir de son initialisateur de membre par défaut.

(depuis C++11)

  • Sinon, le premier membre de l'union (s'il existe) est initialisé par copie à partir d'une liste d'initialisation vide.

Tableaux à bornes inconnues

Le nombre d'éléments d'un tableau de borne inconnue initialisé avec une liste d'initialisation entre accolades est le nombre d'éléments initialisés explicitement du tableau. Un tableau de borne inconnue ne peut pas être initialisé avec {}.

int x[] = {1, 3, 5}; // x has 3 elements

struct Y { int i, j, k; };

Y y[] = {1, 2, 3, 4, 5, 6}; // y ne contient que 2 éléments :
                            // 1, 2 et 3 concernent y[0],
                            // 4, 5 et 6 concernent y[1]

int z[] = {} // Erreur : impossible de déclarer un tableau sans aucun élément

Initialisateurs désignés

Les formes syntaxiques (3,4) sont appelées initialisateurs désignés : chaque designator doit nommer un membre de données non statique direct de T, et tous les designator utilisés dans l'expression doivent apparaître dans le même ordre que les membres de données de T.

struct A { int x; int y; int z; };

A a{.y = 2, .x = 1}; // erreur ; l'ordre des désignateurs ne correspond pas à l'ordre de déclaration
A b{.x = 1, .z = 2}; // ok, b.y initialisé à 0

Chaque membre de données non statique direct nommé par l'initialisateur désigné est initialisé à partir de l'initialisateur brace-or-equals correspondant qui suit le désignateur. Les conversions restrictives sont interdites.

L'initialisateur désigné peut être utilisé pour initialiser une union dans un état autre que le premier. Un seul initialisateur peut être fourni pour une union.

union u { int a; const char* b; };

u f = {.b = "asdf"};         // OK, le membre actif de l'union est b
u g = {.a = 1, .b = "asdf"}; // Erreur, un seul initialiseur peut être fourni

Pour un agrégat qui n'est pas une union, les éléments pour lesquels aucun initialisateur désigné n'est fourni sont initialisés de la même manière que décrit ci-dessus pour le cas où le nombre de clauses d'initialisation est inférieur au nombre de membres (initialisateurs de membres par défaut lorsqu'ils sont fournis, sinon initialisation par liste vide) :

struct A
{
    string str;
    int n = 42;
    int m = -1;
};

A{.m = 21} // Initialise str avec {}, ce qui appelle le constructeur par défaut
           // puis initialise n avec = 42
           // puis initialise m avec = 21

Si l'agrégat initialisé avec une clause d'initialisateur désigné possède un membre d'union anonyme, l'initialisateur désigné correspondant doit nommer l'un des membres de cette union anonyme.

Remarque : l'initialisation désignée dans le désordre, l'initialisation désignée imbriquée, le mélange d'initialisateurs désignés et d'initialisateurs ordinaires, et l'initialisation désignée de tableaux sont tous pris en charge dans le langage de programmation C, mais ne sont pas autorisés en C++.

struct A { int x, y; };
struct B { struct A a; };

struct A a = {.y = 1, .x = 2}; // valid C, invalid C++ (out of order)
int arr[3] = {[1] = 5};        // valid C, invalid C++ (array)
struct B b = {.a.x = 0};       // valid C, invalid C++ (nested)
struct A a = {.x = 1, 2};      // valide en C, invalide en C++ (mixte)

(depuis C++20)

Tableaux de caractères

Les tableaux de types de caractères ordinaires (char, signed char, unsigned char)[, char8_t (depuis C++20) | , char16_t, char32_t (depuis C++11)], ou wchar_t peuvent être initialisés à partir de littéraux de chaîne[, de littéraux de chaîne UTF-8 (depuis C++20) | , de littéraux de chaîne UTF-16, de littéraux de chaîne UTF-32 (depuis C++11)], ou de littéraux de chaîne larges, respectivement, éventuellement entre accolades. De plus, un tableau de char ou de unsigned char peut être initialisé par un littéral de chaîne UTF-8, éventuellement entre accolades (depuis C++20). Les caractères successifs du littéral de chaîne (qui inclut le caractère nul de fin implicite) initialisent les éléments du tableau, avec une conversion intégrale si nécessaire pour la valeur source et destination (depuis C++20). Si la taille du tableau est spécifiée et est supérieure au nombre de caractères du littéral de chaîne, les caractères restants sont initialisés à zéro.

char a[] = "abc";
// équivalent à char a[4] = {'a', 'b', 'c', '\0'};

//  unsigned char b[3] = "abc"; // Error : chaîne d'initialisation trop longue
unsigned char b[5]{"abc"};
// équivalent à unsigned char b[5] = {'a', 'b', 'c', '\0', '\0'};

wchar_t c[] = {L"кошка"}; // accolades facultatives
// équivalent à wchar_t c[6] = {L'к', L'о', L'ш', L'к', L'а', L'\0'};

Notes

Un agrégat de classe ou un tableau peut inclure des classes de base publiques (depuis C++17) non agrégats, des membres ou des éléments, qui sont initialisés comme décrit ci-dessus (par exemple par initialisation par copie à partir de la clause d'initialisation correspondante).

Jusqu'à C++11, les conversions restrictives étaient autorisées dans l'initialisation d'agrégats, mais elles ne le sont plus.

Jusqu'à C++11, l'initialisation d'agrégats ne pouvait être utilisée que dans une définition de variable, et ne pouvait pas être utilisée dans une liste d'initialisation de constructeur, une expression new, ou la création d'un objet temporaire en raison de restrictions de syntaxe.

En C, un tableau de caractères de taille inférieure d'une unité à la taille du littéral de chaîne peut être initialisé à partir d'un littéral de chaîne ; le tableau résultant n'est pas terminé par un caractère nul. Ceci n'est pas autorisé en C++.

Exemple

#include <array>
#include <cstdio>
#include <string>

struct S
{
    int x;

    struct Foo
    {
        int i;
        int j;
        int a[3];
    } b;
};

int main()
{
    S s1 = {1, {2, 3, {4, 5, 6}}};
    S s2 = {1, 2, 3, 4, 5, 6}; // identique, mais avec élision des accolades
    S s3{1, {2, 3, {4, 5, 6}}}; // identique, en utilisant la syntaxe d'initialisation directe par liste
    S s4{1, 2, 3, 4, 5, 6}; // erreur jusqu'à CWG 1270 :
                            // élision des accolades autorisée uniquement avec le signe égal

    int ar[] = {1, 2, 3}; // ar est int[3]
//  char cr[3] = {'a', 'b', 'c', 'd'}; // trop de clauses d'initialisation
    char cr[3] = {'a'}; // tableau initialisé comme {'a', '\0', '\0'}

    int ar2d1[2][2] = {{1, 2}, {3, 4}}; // tableau 2D entièrement entre accolades : {1, 2}
                                        //                        {3, 4}
    int ar2d2[2][2] = {1, 2, 3, 4}; // élision des accolades : {1, 2}
                                    //                {3, 4}
    int ar2d3[2][2] = {{1}, {2}};   // uniquement la première colonne : {1, 0}
                                    //                    {2, 0}

    std::array<int, 3> std_ar2{{1, 2, 3}};  // std::array est un agrégat
    std::array<int, 3> std_ar1 = {1, 2, 3}; // élision des accolades valide

//  int ai[] = {1, 2.0}; // conversion restrictive de double vers int :
                         // erreur en C++11, valide en C++03

    std::string ars[] = {std::string("one"), // initialisation par copie
                         "two",              // conversion, puis initialisation par copie
                         {'t', 'h', 'r', 'e', 'e'}}; // initialisation par liste
    union U
    {
        int a;
        const char* b;
    };
    U u1 = {1};         // OK, premier membre de l'union
//  U u2 = {0, "asdf"}; // erreur : trop d'initialiseurs pour l'union
//  U u3 = {"asdf"};    // erreur : conversion invalide vers int

    [](...) { std::puts("Garbage collecting unused variables... Done."); }
    (
        s1, s2, s3, s4, ar, cr, ar2d1, ar2d2, ar2d3, std_ar2, std_ar1, u1
    );
}

// aggregate
struct base1 { int b1, b2 = 42; };

// non-agrégat
struct base2
{
    base2() : b3(42) {}

    int b3;
};

// agrégat en C++17
struct derived : base1, base2 { int d; };

derived d1{{1, 2}, {}, 4}; // d1.b1 = 1, d1.b2 = 2,  d1.b3 = 42, d1.d = 4
derived d2{{}, {}, 4};     // d2.b1 = 0, d2.b2 = 42, d2.b3 = 42, d2.d = 4

Output:

Garbage collecting unused variables... Done.

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.
