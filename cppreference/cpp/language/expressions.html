Expressions

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Une expression est une suite d'opérateurs et de leurs opérandes, qui spécifie un calcul.

L'évaluation d'une expression peut produire un résultat (par exemple, l'évaluation de 2 + 2 produit le résultat 4) et peut générer des effets de bord (par exemple, l'évaluation de std::printf("%d", 4) affiche le caractère '4' sur la sortie standard).

Chaque expression C++ est caractérisée par deux propriétés indépendantes : un type et une catégorie de valeur.

Généralités

  • les catégories de valeur (lvalue, rvalue, glvalue, prvalue, xvalue (depuis C++11)) classent les expressions selon leurs valeurs
  • l'ordre d'évaluation des arguments et des sous-expressions spécifie l'ordre dans lequel les résultats intermédiaires sont obtenus

Expressions primaires

Les opérandes de tout opérateur peuvent être d'autres expressions ou des expressions primaires (par exemple dans 1 + 2 * 3, les opérandes de operator+ sont la sous-expression 2 * 3 et l'expression primaire 1).

Les expressions primaires sont l'une des suivantes :

  • this
  • les littéraux (par exemple 2 ou "Hello, world")
  • les expressions d'identificateurs, y compris
    • les identificateurs non qualifiés convenablement déclarés (par exemple n ou cout),
    • les identificateurs qualifiés convenablement déclarés (par exemple std::string::npos), et
    • les identificateurs à déclarer dans des déclarateurs
  • expression d'indexation de paquet

(depuis C++26)

  • expressions lambda

(depuis C++11)

  • expressions de pliage

(depuis C++17)

  • expressions requires

(depuis C++20)

Toute expression entre parenthèses est également classée comme expression primaire : cela garantit que les parenthèses ont une priorité supérieure à tout opérateur. Les parenthèses préservent la valeur, le type et la catégorie de valeur.

Littéraux

Les littéraux sont les unités lexicales d'un programme C++ qui représentent des valeurs constantes incluses dans le code source.

  • Les littéraux entiers sont des nombres décimaux, octaux, hexadécimaux ou binaires de type entier.
  • Les littéraux de caractère sont des caractères individuels de type
    • char or wchar_t
  • char16_t or char32_t

(depuis C++11)

  • char8_t

(depuis C++20)

  • Les littéraux à virgule flottante sont des valeurs de type float, double ou long double
  • Les littéraux de chaîne sont des séquences de caractères de type
    • const char[] or const wchar_t[]
  • const char16_t[] or const char32_t[]

(depuis C++11)

  • const char8_t[]

(depuis C++20)

  • Les littéraux booléens sont des valeurs de type bool, à savoir true et false
  • nullptr est le littéral de pointeur qui désigne une valeur de pointeur nul
  • Les littéraux définis par l'utilisateur sont des valeurs constantes d'un type spécifié par l'utilisateur

(depuis C++11)

Expressions complètes

Une expression constituante est définie comme suit :

  • L'expression constituante d'une expression est cette expression.
  • Les expressions constituantes d'un braced-init-list ou d'une liste d'expressions (éventuellement entre parenthèses) sont les expressions constituantes des éléments de la liste respective.
  • Les expressions constituantes d'un brace-or-equal-initializer de la forme = initializer-clause sont les expressions constituantes de initializer-clause.
int num1 = 0;
num1 += 1; // Cas 1 : l'expression constituante de `num += 1` est `num += 1`

int arr2[2] = {2, 22} // Cas 2 : les expressions constituantes
                      //         de `{2, 22}` sont `2` et `22`
                      // Cas 3 : les expressions constituantes de ` = {2, 22}`
                      //         sont les expressions constituantes de `{2, 22}`
                      //         (c'est-à-dire aussi `2` et `22`)

Les sous-expressions immédiates d'une expression E sont

  • les expressions constituantes des opérandes de E,
  • si E crée un objet agrégat, les expressions constituantes de chaque initialiseur de membre par défaut utilisé dans l'initialisation,

(depuis C++14)

  • si E est une expression lambda, l'initialisation des entités capturées par copie et les expressions constituantes de l'initialiseur des captures,

(depuis C++11)

  • tout appel de fonction que E invoque implicitement, ou
  • si E est un appel de fonction ou invoque implicitement une fonction, les expressions constituantes de chaque argument par défaut utilisé dans l'appel.

Une sous-expression d'une expression E est une sous-expression immédiate de E ou une sous-expression d'une sous-expression immédiate de E. Notez que les expressions figurant dans le « corps de fonction » des expressions lambda ne sont pas des sous-expressions de l'expression lambda. (depuis C++11)

Une expression complète est

  • un opérande non évalué,
  • une expression constante,
  • une invocation immédiate,

(depuis C++20)

  • un déclarateur d'une déclaration simple ou d'un initialiseur de membre, y compris les expressions constituantes de l'initialiseur,
  • une invocation d'un destructeur générée à la fin de la durée de vie d'un objet autre qu'un objet temporaire dont la durée de vie n'a pas été prolongée, ou
  • une expression qui n'est pas une sous-expression d'une autre expression et qui ne fait pas partie autrement d'une expression complète.

Si une construction du langage est définie pour produire un appel implicite de fonction, l'utilisation de cette construction est considérée comme une expression au sens de cette définition. Les conversions appliquées au résultat d'une expression afin de satisfaire les exigences de la construction du langage dans laquelle l'expression apparaît sont également considérées comme faisant partie de l'expression complète.

Pour un initialiseur, l'exécution de l'initialisation de l'entité (y compris l'évaluation des initialiseurs de membres par défaut d'un agrégat) (depuis C++14) est également considérée comme faisant partie de l'expression complète.

Expressions potentiellement évaluées

Une expression est potentiellement évaluée sauf

  • si elle est l'opérande de l'opérateur sizeof, ou
  • si elle est l'opérande de l'opérateur typeid et ne désigne pas une lvalue de type de classe polymorphe.

(jusqu'à C++11)

Les opérandes suivants sont des opérandes non évalués, ils ne sont pas évalués :

  • les expressions auxquelles s'applique l'opérateur typeid, à l'exception des glvalues de types de classes polymorphes
  • les expressions qui sont opérandes de l'opérateur sizeof
  • les opérandes de l'opérateur noexcept
  • les opérandes du spécificateur decltype
  • constraint-expression des définitions de concepts
  • les expressions suivant le mot-clé requires des clauses requires
  • les expressions apparaissant dans requirement-seq des expressions requires

(depuis C++20)

Une expression est potentiellement évaluée sauf

  • elle est un opérande non évalué, ou
  • elle est une sous-expression d'un opérande non évalué.

(depuis C++11)

Les expressions potentiellement évaluées font l'objet d'une utilisation ODR.

Expressions à valeur ignorée

Une expression à valeur ignorée est une expression utilisée uniquement pour ses effets de bord. La valeur calculée à partir de cette expression est ignorée. Ces expressions incluent l'expression complète de toute instruction d'expression, l'opérande de gauche de l'opérateur virgule intégré, ou l'opérande d'une expression de conversion (cast) vers le type void.

Les conversions tableau-vers-pointeur et fonction-vers-pointeur ne sont jamais appliquées à la valeur calculée par une expression à valeur ignorée. La conversion lvalue-vers-rvalue est appliquée si et seulement si l'expression est une glvalue qualifiée volatile et a l'une des formes suivantes (sens intégré requis, éventuellement entre parenthèses) :

  • expression d'identificateur,
  • expression d'indexation de tableau,
  • expression d'accès à un membre de classe,
  • indirection,
  • opération sur pointeur vers membre,
  • expression conditionnelle dont les deuxième et troisième opérandes sont l'une de ces expressions,
  • expression virgule dont l'opérande de droite est l'une de ces expressions.

De plus, si la lvalue est d'un type de classe qualifié volatile, un constructeur de copie volatile est requis pour initialiser le temporaire rvalue résultant.

Si l'expression est une prvalue non void (après une éventuelle conversion lvalue-vers-rvalue), une matérialisation temporaire a lieu.

Les compilateurs peuvent émettre des avertissements lorsqu'une expression autre qu'un cast vers void ignore une valeur déclarée [[nodiscard]].

(depuis C++17)

Équivalence d'expressions

Plusieurs expressions e1, e2, ..., eN sont équivalentes en expression si toutes les conditions suivantes sont satisfaites :

  1. Elles ont les mêmes effets.
  2. Soit elles sont toutes des sous-expressions constantes, soit aucune ne l'est.
  3. Soit elles sont toutes noexcept, soit aucune ne l'est.

e1 est équivalente en expression à e2 si et seulement si e1 et e2 sont équivalentes en expression (ce qui signifie que e2 est aussi équivalente en expression à e1).

(depuis C++20)
