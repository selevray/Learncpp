void

void — type dont l'ensemble des valeurs est vide. C'est un type incomplet qui ne peut pas être complété (par conséquent, les objets de type void sont interdits). Il n'existe pas de tableaux de void, ni de références vers void. En revanche, les pointeurs vers void et les fonctions renvoyant le type void (procédures dans d'autres langages) sont autorisés.

std::nullptr_t

Défini dans l'en-tête <cstddef>

typedef decltype(nullptr) nullptr_t;  // (depuis C++11)

std::nullptr_t est le type du littéral pointeur nul, nullptr. C'est un type distinct qui n'est lui-même ni un type pointeur ni un type pointeur vers membre. Toutes ses prvalues sont des constantes pointeur nul.

sizeof(std::nullptr_t) est égal à sizeof(void*).

(depuis C++11)

Types entiers

Types entiers standard

int — type entier de base. Le mot-clé int peut être omis si l'un des modificateurs ci-dessous est utilisé. Si aucun modificateur de longueur n'est présent, il est garanti d'avoir une largeur d'au moins 16 bits. Cependant, sur les systèmes 32/64 bits, il est presque exclusivement garanti d'avoir une largeur d'au moins 32 bits (voir ci-dessous).

Modificateurs

Modifie le type entier de base. Peut être combiné dans n'importe quel ordre. Un seul élément de chaque groupe peut être présent dans le nom du type.

  • Signedness: signed — le type cible aura une représentation signée (c'est la valeur par défaut si omis) unsigned — le type cible aura une représentation non signée

  • Size: short — le type cible sera optimisé pour l'espace et aura une largeur d'au moins 16 bits. long — le type cible aura une largeur d'au moins 32 bits.

long long — le type cible aura une largeur d'au moins 64 bits.

(depuis C++11)

Remarque : comme pour tous les spécificateurs de type, n'importe quel ordre est permis : unsigned long long int et long int unsigned long désignent le même type.

Types entiers étendus

Les types entiers étendus sont définis par l'implémentation. Notez que les types entiers de largeur fixe sont généralement des alias des types entiers standard.

(depuis C++11)

Type booléen

bool — type entier pouvant contenir l'une des deux valeurs : true ou false. La valeur de sizeof(bool) est définie par l'implémentation et peut différer de 1.

Types de caractères

Les types de caractères sont des types entiers utilisés pour représenter un caractère.

signed char — type pour la représentation d'un caractère signé.unsigned char — type pour la représentation d'un caractère non signé. Il sert également à inspecter les représentations d'objets (mémoire brute).char — type pour la représentation d'un caractère pouvant être traité le plus efficacement sur le système cible (il a la même représentation et le même alignement que signed char ou unsigned char, mais c'est toujours un type distinct). Les chaînes de caractères multi-octets utilisent ce type pour représenter les unités de code. Pour toute valeur de type unsigned char dans l'intervalle [0,255], la conversion de la valeur en char, puis sa reconversion en unsigned char, produit la valeur d'origine. (depuis C++11) Le signe de char dépend du compilateur et de la plateforme cible : par défaut, il est typiquement non signé sur ARM et PowerPC, et typiquement signé sur x86 et x64.wchar_t — type pour la représentation d'un caractère large (voir chaînes larges). Il a la même taille, le même signe et le même alignement que l'un des types entiers, mais c'est un type distinct. En pratique, il fait 32 bits et contient de l'UTF-32 sous Linux et de nombreux autres systèmes non Windows, mais 16 bits et contient des unités de code UTF-16 sous Windows. La norme exigeait autrefois que wchar_t soit suffisamment grand pour représenter tout point de code de caractère pris en charge. Cependant, cette exigence ne peut pas être satisfaite sous Windows ; elle est donc considérée comme un défaut et a été supprimée.

char16_t — type pour la représentation de caractères UTF-16, devant être suffisamment grand pour représenter toute unité de code UTF-16 (16 bits). Il a la même taille, le même signe et le même alignement que std::uint_least16_t, mais c'est un type distinct.char32_t — type pour la représentation de caractères UTF-32, devant être suffisamment grand pour représenter toute unité de code UTF-32 (32 bits). Il a la même taille, le même signe et le même alignement que std::uint_least32_t, mais c'est un type distinct.

(depuis C++11)

char8_t — type pour la représentation de caractères UTF-8, devant être suffisamment grand pour représenter toute unité de code UTF-8 (8 bits). Il a la même taille, le même signe et le même alignement que unsigned char (et donc la même taille et le même alignement que char et signed char), mais c'est un type distinct.

(depuis C++20)

Outre les nombres de bits minimaux, la norme C++ garantit que

1 == sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long).

Note : cela autorise le cas extrême où les octets font 64 bits, où tous les types (y compris char) font 64 bits de large, et où sizeof renvoie 1 pour chaque type.

Types à virgule flottante

Types standard à virgule flottante

Les trois types suivants, ainsi que leurs versions qualifiées cv, sont appelés collectivement types standard à virgule flottante.

float — type à virgule flottante en simple précision. Généralement au format IEEE-754 binary32.double — type à virgule flottante en double précision. Généralement au format IEEE-754 binary64.long double — type à virgule flottante en précision étendue. Ne correspond pas nécessairement aux types prescrits par IEEE-754.

  • Le format IEEE-754 binary128 est utilisé par certaines implémentations sur HP-UX, SPARC, MIPS, ARM64 et z/OS.
  • Le format IEEE-754 binary64 étendu le plus connu est le format à précision étendue x87 sur 80 bits. Il est utilisé par de nombreuses implémentations x86 et x86-64 (une exception notable est MSVC, qui implémente long double dans le même format que double, c'est-à-dire binary64).
  • Sur PowerPC, double-double peut être utilisé.

Types à virgule flottante étendus

Les types à virgule flottante étendus sont définis par l'implémentation. Ils peuvent inclure des types à virgule flottante de largeur fixe.

(depuis C++23)

Propriétés

Les types à virgule flottante peuvent prendre en charge des valeurs spéciales :

  • infini (positif et négatif), voir INFINITY
  • le zéro négatif, -0.0. Il est égal au zéro positif lors d'une comparaison, mais il a un sens dans certaines opérations arithmétiques, par exemple 1.0 / 0.0 == INFINITY, mais 1.0 / -0.0 == -INFINITY), et pour certaines fonctions mathématiques, par exemple sqrt(std::complex)
  • not-a-number (NaN), qui n'est égal à rien (y compris à lui-même) lors d'une comparaison. Plusieurs motifs de bits représentent des NaN, voir std::nan, NAN. Notez que C++ ne prend pas de mesure particulière pour les NaN signalants autre que de détecter leur prise en charge par std::numeric_limits::has_signaling_NaN, et traite tous les NaN comme silencieux.

Les nombres à virgule flottante peuvent être utilisés avec les opérateurs arithmétiques +, -, / et *, ainsi qu'avec diverses fonctions mathématiques de <cmath>. Aussi bien les opérateurs intégrés que les fonctions de bibliothèque peuvent lever des exceptions de virgule flottante et modifier errno, comme décrit dans math errhandling.

Les expressions à virgule flottante peuvent avoir une plage et une précision supérieures à celles indiquées par leurs types, voir FLT_EVAL_METHOD. Les expressions à virgule flottante peuvent également être contractées, c'est-à-dire calculées comme si toutes les valeurs intermédiaires avaient une plage et une précision infinies, voir #pragma STDC FP_CONTRACT. Le C++ standard ne restreint pas la précision des opérations à virgule flottante.

Certaines opérations sur les nombres à virgule flottante sont affectées par l'environnement à virgule flottante et modifient son état (notamment le sens d'arrondi).

Des conversions implicites sont définies entre les types flottants et les types entiers.

Voir limites des types à virgule flottante et std::numeric_limits pour des détails, limites et propriétés supplémentaires des types à virgule flottante.

Intervalle des valeurs

Le tableau suivant fournit une référence pour les limites des représentations numériques courantes.

Avant C++20, la norme C++ autorisait toute représentation d'entier signé, et l'intervalle minimal garanti des entiers signés sur N bits allait de (\scriptsize -(2^{N-1}-1))-(2N-1
-1) à (\scriptsize +2^{N-1}-1)+2N-1
-1 (par exemple −127 à 127 pour un type signé sur 8 bits), ce qui correspond aux limites du complément à un ou de la représentation signe-et-valeur absolue.

Cependant, tous les compilateurs C++ utilisent la représentation en complément à deux et, depuis C++20, c'est la seule représentation autorisée par la norme, avec un intervalle garanti allant de (\scriptsize -2^{N-1})-2N-1
à (\scriptsize +2^{N-1}-1)+2N-1
-1 (par exemple −128 à 127 pour un type signé sur 8 bits).

Les représentations en complément à un et signe-et-valeur absolue sur 8 bits pour char sont interdites depuis C++11 (via la résolution du CWG issue 1759), car une unité de code UTF-8 de valeur 0x80 utilisée dans un littéral de chaîne UTF-8 doit pouvoir être stockée dans un objet de type char.

L'intervalle d'un type à virgule flottante T est défini comme suit :

  • L'intervalle minimal garanti va du plus grand nombre fini négatif à virgule flottante représentable dans T jusqu'au plus grand nombre fini positif à virgule flottante représentable dans T.
  • Si l'infini négatif est représentable dans T, l'intervalle de T est étendu à tous les nombres réels négatifs.
  • Si l'infini positif est représentable dans T, l'intervalle de T est étendu à tous les nombres réels positifs.

Comme les infinis négatif et positif sont représentables dans les formats ISO/IEC/IEEE 60559, tous les nombres réels se situent dans l'intervalle des valeurs représentables d'un type à virgule flottante conforme à ISO/IEC/IEEE 60559.

Modèles de données

Les choix faits par chaque implémentation concernant les tailles des types fondamentaux sont collectivement appelés modèle de données. Quatre modèles de données sont largement adoptés :

Systèmes 32 bits :

  • LP32 ou 2/4/4 (int est sur 16 bits, long et le pointeur sont sur 32 bits)

    • API Win16

  • ILP32 ou 4/4/4 (int, long et le pointeur sont sur 32 bits) ;

    • API Win32
    • Unix et systèmes de type Unix (Linux, macOS)

Systèmes 64 bits :

  • LLP64 ou 4/4/8 (int et long sont sur 32 bits, le pointeur sur 64 bits)

    • API Win32 (aussi appelée API Windows) avec une cible de compilation ARM 64 bits (AArch64) ou x86-64 (aussi appelée x64)

  • LP64 ou 4/8/8 (int est sur 32 bits, long et le pointeur sur 64 bits)

    • Unix et systèmes de type Unix (Linux, macOS)

Les autres modèles sont très rares. Par exemple, ILP64 (8/8/8 : int, long et le pointeur sont sur 64 bits) n'est apparu que dans certains premiers systèmes Unix 64 bits (par ex. UNICOS sur Cray).
