opérateur typeid

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Interroge les informations d'un type.

Utilisé lorsque le type dynamique d'un objet polymorphe doit être connu, ainsi que pour l'identification de type statique.

Syntaxe

| | | | typeid ( type ) | (1) | | | | typeid ( expression ) | (2) | | |

L'expression typeid est une expression lvalue qui désigne un objet ayant une durée de stockage statique, de la version qualifiée const du type polymorphe std::type_info ou d'un type dérivé de celui-ci.

Si la définition de la bibliothèque standard de std::type_info n'est pas visible lors de l'utilisation de typeid, le programme est mal formé.

Explication

Si type ou le type de expression est un type classe ou une référence à un type classe, alors ce type classe ne peut pas être un type incomplet.

  1. fait référence à un objet std::type_info représentant type. Si type est un type référence, le résultat fait référence à un objet std::type_info représentant la version sans qualificatifs cv du type référencé.

  2. examine expression ﻿ :

  • Si expression est [une lvalue (jusqu'à C++11) | une glvalue (depuis C++11)] expression qui identifie un objet de type polymorphe (c'est-à-dire une classe qui déclare ou hérite d'au moins une fonction virtuelle), l'expression typeid évalue l'expression puis fait référence à l'objet std::type_info qui représente le type dynamique de l'expression.

    • Si expression est une expression d'indirection et que son opérande s'évalue en une valeur de pointeur nul, une exception d'un type correspondant aux gestionnaires de type std::bad_typeid est lancée[1].

  • Sinon, typeid n'évalue pas l'expression, et l'objet std::type_info qu'il identifie représente le type statique de l'expression. Les conversions lvalue-vers-rvalue, tableau-vers-pointeur ou fonction-vers-pointeur ne sont pas effectuées.

  • La matérialisation temporaire est toutefois (formellement) effectuée pour les arguments prvalue : l'argument doit être destructible dans le contexte où l'expression typeid apparaît.

(depuis C++17)

Si type ou le type de expression est qualifié cv, le résultat de typeid fait référence à un objet std::type_info représentant le type sans qualificatifs cv (c'est-à-dire typeid(const T) == typeid(T)).

Si typeid est utilisé sur un objet en cours de construction ou de destruction (dans un destructeur ou dans un constructeur, y compris la liste d'initialisation du constructeur ou les initialiseurs de membres par défaut), alors l'objet std::type_info désigné par ce typeid représente la classe en cours de construction ou de destruction, même si ce n'est pas la classe la plus dérivée.

  1. ↑ Dans les autres contextes, l'évaluation d'un tel expression entraîne un comportement indéfini.

Notes

Appliquée à une expression de type polymorphe, l'évaluation d'une expression typeid peut entraîner un surcoût à l'exécution (une recherche dans la table virtuelle), sinon l'expression typeid est résolue à la compilation.

Il n'est pas spécifié si le destructeur de l'objet désigné par typeid est exécuté à la fin du programme.

Rien ne garantit que le même objet std::type_info sera désigné par toutes les évaluations de l'expression typeid sur le même type ; bien qu'ils se comparent égaux, std::type_info::hash_code de ces objets type_info seraient identiques, ainsi que leur std::type_index.

const std::type_info& ti1 = typeid(A);
const std::type_info& ti2 = typeid(A);

assert(&ti1 == &ti2); // non garanti
assert(ti1 == ti2); // guaranteed
assert(ti1.hash_code() == ti2.hash_code()); // guaranteed
assert(std::type_index(ti1) == std::type_index(ti2)); // guaranteed

Exemple

L'exemple montrant la sortie utilise l'une des implémentations où type_info::name renvoie les noms de types complets ; filtrez via c++filt -t si vous utilisez gcc ou similaire.

#include <iostream>
#include <string>
#include <typeinfo>

struct Base {}; // non polymorphe
struct Derived : Base {};

struct Base2 { virtual void foo() {} }; // polymorphic
struct Derived2 : Base2 {};

int main()
{
    int myint = 50;
    std::string mystr = "string";
    double *mydoubleptr = nullptr;

    std::cout << "myint has type: " << typeid(myint).name() << '\n'
              << "mystr has type: " << typeid(mystr).name() << '\n'
              << "mydoubleptr has type: " << typeid(mydoubleptr).name() << '\n';

    // std::cout << myint est une expression glvalue de type polymorphe ; elle est évaluée
    const std::type_info& r1 = typeid(std::cout << myint); // effet de bord : affiche 50
    std::cout << '\n' << "std::cout<<myint has type : " << r1.name() << '\n';

    // std::printf() n'est pas une expression glvalue de type polymorphe ; NON évaluée
    const std::type_info& r2 = typeid(std::printf("%d\n", myint));
    std::cout << "printf(\"%d\\n\",myint) has type : " << r2.name() << '\n';

    // Une lvalue non polymorphe est un type statique
    Derived d1;
    Base& b1 = d1;
    std::cout << "reference to non-polymorphic base: " << typeid(b1).name() << '\n';

    Derived2 d2;
    Base2& b2 = d2;
    std::cout << "reference to polymorphic base: " << typeid(b2).name() << '\n';

    try
    {
        // déréférencer un pointeur nul : acceptable pour une expression non polymorphe
        std::cout << "mydoubleptr points to " << typeid(*mydoubleptr).name() << '\n';
        // déréférencer un pointeur nul : non acceptable pour une lvalue polymorphe
        Derived2* bad_ptr = nullptr;
        std::cout << "bad_ptr points to... ";
        std::cout << typeid(*bad_ptr).name() << '\n';
    }
    catch (const std::bad_typeid& e)
    {
        std::cout << " caught " << e.what() << '\n';
    }
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 492 C++98 lorsque typeid est appliqué à une référence vers un type qualifié cv , le résultat représentait le type référencé le résultat représente le type référencé sans qualificatifs cv
CWG 1416 C++98 la formulation concernant la qualification cv de premier niveau pourrait être mal interprétée amélioration de la formulation
CWG 1431 C++98 typeid ne pouvait lever que std::bad_typeid autorisé à lever des classes dérivées pouvant être reconnues
CWG 1954 C++98 il n'était pas clair si le déréférencement d'un pointeur nul pouvait être vérifié dans les sous-expressions de expression vérifié uniquement au niveau le plus haut
