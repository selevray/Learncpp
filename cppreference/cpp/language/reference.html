Déclaration de référence

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Déclare une variable nommée comme référence, c'est-à-dire un alias vers un objet ou une fonction déjà existant.

Syntaxe

Une déclaration de variable référence est toute déclaration simple dont le déclarateur a la forme

| | | | & attr ﻿*(facultatif)* declarator | (1) | | | | && attr ﻿*(facultatif)* declarator | (2) | (depuis C++11) | |

  1. Déclarateur de référence lvalue : la déclaration S& D; déclare D comme référence lvalue vers le type déterminé par decl-specifier-seq S.

  2. Déclarateur de référence rvalue : la déclaration S&& D; déclare D comme référence rvalue vers le type déterminé par decl-specifier-seq S.

  • declarator — tout déclarateur sauf un autre déclarateur de référence (il n'existe pas de références vers des références)
  • attr — (depuis C++11) liste d'attributs

Une référence doit être initialisée pour désigner un objet ou une fonction valide : voir initialisation de référence.

Le type « référence vers void (éventuellement qualifié cv) » ne peut pas être formé.

Les types référence ne peuvent pas être qualifiés cv au niveau supérieur ; il n'existe pas de syntaxe pour cela dans une déclaration, et si une qualification est ajoutée à un nom de typedefou decltype spécificateur, (depuis C++11) ou paramètre de modèle de type, elle est ignorée.

Les références ne sont pas des objets ; elles n'occupent pas nécessairement de stockage, bien que le compilateur puisse allouer du stockage si cela est nécessaire pour implémenter la sémantique voulue (par exemple, un membre de donnée non statique de type référence augmente généralement la taille de la classe de la quantité nécessaire pour stocker une adresse mémoire).

Les références n'étant pas des objets, il n'existe ni tableaux de références, ni pointeurs vers des références, ni références vers des références :

int& a[3]; // error
int&* p;   // error
int& &r;   // error

Effondrement de références

Il est permis de former des références vers des références par manipulation de types dans les modèles ou les typedef, auquel cas les règles d'effondrement de références s'appliquent : une référence rvalue vers une référence rvalue se réduit à une référence rvalue, toutes les autres combinaisons forment une référence lvalue :

typedef int&  lref;
typedef int&& rref;
int n;

lref&  r1 = n; // le type de r1 est int&
lref&& r2 = n; // le type de r2 est int&
rref&  r3 = n; // le type de r3 est int&
rref&& r4 = 1; // le type de r4 est int&&

(Ceci, avec les règles spéciales de déduction d'argument de modèle lorsque T&& est utilisé dans un modèle de fonction, constitue les règles qui rendent std::forward possible.)

(depuis C++11)

Références lvalue

Les références lvalue peuvent servir d'alias vers un objet existant (éventuellement avec une qualification cv différente) :

#include <iostream>
#include <string>

int main()
{
    std::string s = "Ex";
    std::string& r1 = s;
    const std::string& r2 = s;

    r1 += "ample";           // modifie s
//  r2 += "!";               // erreur : impossible de modifier via une référence vers const
    std::cout << r2 << '\n'; // affiche s, qui contient désormais "Example"
}

Elles peuvent aussi servir à implémenter une sémantique de passage par référence dans les appels de fonction :

#include <iostream>
#include <string>

void double_string(std::string& s)
{
    s += s; // 's' est le même objet que 'str' de main()
}

int main()
{
    std::string str = "Test";
    double_string(str);
    std::cout << str << '\n';
}

Lorsque le type de retour d'une fonction est une référence lvalue, l'expression d'appel de fonction devient une expression lvalue :

#include <iostream>
#include <string>

char& char_number(std::string& s, std::size_t n)
{
    return s.at(n); // string::at() renvoie une référence vers char
}

int main()
{
    std::string str = "Test";
    char_number(str, 1) = 'a'; // l'appel de fonction est une lvalue, à laquelle on peut affecter une valeur
    std::cout << str << '\n';
}

Références rvalue

Les références rvalue peuvent servir à prolonger la durée de vie d'objets temporaires (remarque : les références lvalue vers const peuvent aussi prolonger la durée de vie d'objets temporaires, mais ils ne sont pas modifiables par leur intermédiaire) :

#include <iostream>
#include <string>

int main()
{
    std::string s1 = "Test";
//  std::string&& r1 = s1;           // erreur : impossible de lier à une lvalue

    const std::string& r2 = s1 + s1; // ok : une référence lvalue vers const prolonge la durée de vie
//  r2 += "Test";                    // erreur : impossible de modifier via une référence vers const

    std::string&& r3 = s1 + s1;      // ok : une référence rvalue prolonge la durée de vie
    r3 += "Test";                    // ok : on peut modifier via une référence vers non-const
    std::cout << r3 << '\n';
}

Plus important encore, lorsqu'une fonction possède à la fois une surcharge par référence rvalue et une surcharge par référence lvalue, la surcharge par référence rvalue se lie aux rvalues (prvalues et xvalues incluses), tandis que la surcharge par référence lvalue se lie aux lvalues :

#include <iostream>
#include <utility>

void f(int& x)
{
    std::cout << "lvalue reference overload f(" << x << ")\n";
}

void f(const int& x)
{
    std::cout << "lvalue reference to const overload f(" << x << ")\n";
}

void f(int&& x)
{
    std::cout << "rvalue reference overload f(" << x << ")\n";
}

int main()
{
    int i = 1;
    const int ci = 2;

    f(i);  // appelle f(int&)
    f(ci); // appelle f(const int&)
    f(3);  // appelle f(int&&)
           // appellerait f(const int&) si la surcharge f(int&&) n'était pas fournie
    f(std::move(i)); // appelle f(int&&)

    // les variables de référence rvalue sont des lvalues lorsqu'elles sont utilisées dans des expressions
    int&& x = 1;
    f(x);            // appelle f(int& x)
    f(std::move(x)); // appelle f(int&& x)
}

Cela permet de sélectionner automatiquement les constructeurs de déplacement, les opérateurs d'affectation par déplacement et les autres fonctions tenant compte du déplacement (par exemple std::vector::push_back()) lorsque cela est approprié.

Les références rvalue pouvant se lier à des xvalues, elles peuvent désigner des objets non temporaires :

int i2 = 42;
int&& rri = std::move(i2); // se lie directement à i2

Cela permet de déplacer un objet dans la portée qui n'est plus nécessaire :

std::vector<int> v{1, 2, 3, 4, 5};
std::vector<int> v2(std::move(v)); // lie une référence rvalue à v
assert(v.empty());

Références de transfert

Les références de transfert sont un type particulier de références qui préservent la catégorie de valeur d'un argument de fonction, ce qui permet de le transférer au moyen de std::forward. Les références de transfert sont soit :

  1. paramètre de fonction d'un modèle de fonction déclaré comme référence rvalue vers un paramètre de modèle de type sans qualificateur cv de ce même modèle de fonction :
template<class T>
int f(T&& x)                      // x est une référence de transfert
{
    return g(std::forward<T>(x)); // et peut donc être transmise
}

int main()
{
    int i;
    f(i); // l'argument est une lvalue, appelle f<int&>(int&), std::forward<int&>(x) est une lvalue
    f(0); // l'argument est une rvalue, appelle f<int>(int&&), std::forward<int>(x) est une rvalue
}

template<class T>
int g(const T&& x); // x n'est pas une référence de transfert : const T n'est pas non qualifié cv

template<class T>
struct A
{
    template<class U>
    A(T&& x, U&& y, int* p); // x n'est pas une référence de transfert : T n'est pas un
                             // paramètre de modèle de type du constructeur,
                             // mais y est une référence de transfert
};
  1. auto&& sauf lorsqu'il est déduit d'une liste d'initialisation entre accoladesou, lorsqu'il représente un paramètre de modèle d'un modèle de classe pendant la déduction d'argument de modèle de classe (depuis C++17) :
auto&& vec = foo();       // foo() peut être une lvalue ou une rvalue, vec est une référence de transfert
auto i = std::begin(vec); // fonctionne dans les deux cas
(*i)++;                   // fonctionne dans les deux cas

g(std::forward<decltype(vec)>(vec)); // transmet en préservant la catégorie de valeur

for (auto&& x: f())
{
    // x est une référence de transfert ; c'est une manière courante d'utiliser range for dans du code générique
}

auto&& z = {1, 2, 3}; // *pas* une référence de transfert (cas particulier pour les listes d'initialisation)

Voir aussi déduction d'argument de modèle et std::forward.

(depuis C++11)

Références pendantes

Bien que les références désignent toujours des objets ou fonctions valides lors de leur initialisation, il est possible de créer un programme où la durée de vie de l'objet référencé se termine, alors que la référence reste accessible (pendante).

Soit une expression expr de type référence, et soit target l'objet ou la fonction désigné par la référence :

  • Si un pointeur vers target serait valide dans le contexte de l'évaluation de expr, le résultat désigne target.
  • Dans le cas contraire, le comportement est indéfini.
std::string& f()
{
    std::string s = "Example";
    return s; // sort de la portée de s :
              // son destructeur est appelé et son stockage désalloué
}

std::string& r = f(); // référence pendante
std::cout << r;       // comportement indéfini : lit depuis une référence pendante
std::string s = f();  // comportement indéfini : effectue une initialisation par copie depuis une référence pendante

Notez que les références rvalue et les références lvalue vers const prolongent la durée de vie des objets temporaires (voir Initialisation de référence pour les règles et exceptions).

Si l'objet référencé a été détruit (par exemple par un appel explicite au destructeur), mais que son stockage n'a pas été désalloué, une référence vers l'objet hors de sa durée de vie peut être utilisée de façon limitée, et peut redevenir valide si l'objet est recréé dans le même stockage (voir Accès en dehors de la durée de vie pour les détails).

Références inaccessibles au type

Tenter de lier une référence à un objet dont l'initialiseur converti est [une lvalue (jusqu'à C++11) | une glvalue (depuis C++11)] à travers laquelle l'objet n'est pas accessible par type entraîne un comportement indéfini :

char x alignas(int);

int& ir = *reinterpret_cast<int*>(&x); // comportement indéfini :
                                       // l'initialiseur fait référence à un objet char

Références incompatibles avec l'appel

Tenter de lier une référence à une fonction dont l'initialiseur converti est [une lvalue (jusqu'à C++11) | une glvalue (depuis C++11)] dont le type n'est pas compatible à l'appel avec le type de la définition de la fonction entraîne un comportement indéfini :

void f(int);

using F = void(float);
F& ir = *reinterpret_cast<F*>(&f); // comportement indéfini :
                                   // l'initialiseur fait référence à la fonction void(int)
