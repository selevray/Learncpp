Initialisation

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

L'initialisation d'une variable fournit sa valeur initiale au moment de sa construction.

La valeur initiale peut être fournie dans la partie initialisateur d'un déclarateur ou d'une expression new. Elle intervient aussi lors des appels de fonctions : les paramètres de fonction et les valeurs de retour des fonctions sont également initialisés.

Initialisateurs

Pour chaque déclarateur, l'initialisateur (s'il existe) peut être l'une des formes suivantes :

| | | | = expression | (1) | | | | = {} = { initializer-list } = { designated-initializer-list } | (2) | (depuis C++20) | | | ( expression-list ) ( initializer-list ) | (3) | (jusqu'à C++11) (depuis C++11) | | | {} { initializer-list } { designated-initializer-list } | (4) | (depuis C++11) (depuis C++11) (depuis C++20) | |

  1. Syntaxe d'initialisation par copie.

  2. [Syntaxe d'initialisation d'agrégat. (jusqu'à C++11) | Syntaxe d'initialisation par liste. (depuis C++11)]

  3. Syntaxe d'initialisation directe.

  4. Syntaxe d'initialisation par liste.

  • expression — toute expression (sauf les expressions à virgule non parenthésées)
  • expression-list — une liste d'expressions séparées par des virgules (à l'exception des expressions virgule non parenthésées)
  • initializer-list — une liste de clauses d'initialisation séparées par des virgules (voir ci-dessous)
  • designated-initializer-list — une liste de clauses d'initialisation désignées séparées par des virgules

Une clause d'initialisation peut être l'une des formes suivantes :

| | | | expression | (1) | | | | {} | (2) | | | | { initializer-list } | (3) | | | | { designated-initializer-list } | (4) | (depuis C++20) | |

Les syntaxes (2-4) sont appelées collectivement liste d'initialisation entre accolades.

Sémantique des initialisateurs

Si aucun initialisateur n'est spécifié pour un objet, l'objet est initialisé par défaut. Si aucun initialisateur n'est spécifié pour une référence, le programme est mal formé.

Si l'initialisateur spécifié pour un objet est () (ne peut pas apparaître dans les déclarateurs en raison de la restriction syntaxique), l'objet est initialisé à zéro par valeur. Si l'initialisateur spécifié pour une référence est (), le programme est mal formé.

La sémantique des initialisateurs est la suivante :

  • Si l'entité initialisée est une référence, voir initialisation de référence.
  • Sinon, l'entité initialisée est un objet. En notant le type de l'objet T :
    • Si l'initialisateur est de syntaxe (1), l'objet est initialisé par copie.
  • Si l'initialisateur est de syntaxe (2) :
  • Si T est un agrégat, l'initialisation d'agrégat s'applique.
  • Si T est un type scalaire, T x = { a }; équivaut à T x = a;.
  • Sinon, le programme est mal formé.

(jusqu'à C++11)

  • Si l'initialisateur est de syntaxe (2) ou (4), l'objet est initialisé par liste.

(depuis C++11)

  • Si l'initialisateur est de syntaxe (3), l'objet est initialisé directement.
#include <string>

std::string s1;           // initialisation par défaut
std::string s2();         // PAS une initialisation !
                          // déclare en fait une fonction « s2 »
                          // sans paramètre et retournant std::string
std::string s3 = "hello"; // initialisation par copie
std::string s4("hello");  // initialisation directe
std::string s5{'a'};      // initialisation par liste (depuis C++11)

char a[3] = {'a', 'b'}; // initialisation d'agrégat
                        // (partie de l'initialisation par liste depuis C++11)
char& c = a[0];         // initialisation de référence

Variables non locales

Toutes les variables non locales à durée de stockage statique sont initialisées lors du démarrage du programme, avant que l'exécution de la fonction main ne commence (sauf si elles sont différées, voir ci-dessous). Toutes les variables non locales à durée de stockage thread_local sont initialisées lors du lancement du thread, séquencées avant le début de l'exécution de la fonction du thread. Pour ces deux catégories de variables, l'initialisation se déroule en deux étapes distinctes :

Initialisation statique

Il existe deux formes d'initialisation statique :

  1. Si possible, l'initialisation constante est appliquée.

  2. Sinon, les variables statiques et thread_local non locales sont initialisées à zéro.

En pratique :

  • L'initialisation constante est généralement appliquée à la compilation. Les représentations d'objets précalculées sont stockées dans l'image du programme. Si le compilateur ne le fait pas, il doit tout de même garantir que l'initialisation a lieu avant toute initialisation dynamique.
  • Les variables à initialiser à zéro sont placées dans le segment .bss de l'image du programme, qui n'occupe aucune place sur le disque et est remis à zéro par le système d'exploitation lors du chargement du programme.

Initialisation dynamique

Une fois toute l'initialisation statique terminée, l'initialisation dynamique des variables non locales a lieu dans les situations suivantes :

  1. Initialisation dynamique non ordonnée, qui s'applique uniquement aux membres de données statiques (statiques/thread_local) de modèles de classes membres de données statiques et aux modèles de variables (depuis C++14) qui ne sont pas explicitement spécialisés. L'initialisation de ces variables statiques est séquencée de manière indéterminée par rapport à toute autre initialisation dynamique sauf si le programme démarre un thread avant l'initialisation d'une variable, auquel cas son initialisation est non séquencée (depuis C++17). L'initialisation de ces variables thread_local est non séquencée par rapport à toute autre initialisation dynamique.
  1. Initialisation dynamique partiellement ordonnée, qui s'applique à toutes les variables inline qui ne sont pas une spécialisation implicitement ou explicitement instanciée. Si une variable V partiellement ordonnée est définie avant une variable W ordonnée ou partiellement ordonnée dans chaque unité de traduction, l'initialisation de V est séquencée avant l'initialisation de W (ou se produit avant, si le programme démarre un thread).

(depuis C++17)

  1. Initialisation dynamique ordonnée, qui s'applique à toutes les autres variables non locales : au sein d'une même unité de traduction, l'initialisation de ces variables est toujours séquencée dans l'ordre exact où leurs définitions apparaissent dans le code source. L'initialisation des variables statiques dans des unités de traduction différentes est séquencée de manière indéterminée. L'initialisation des variables thread_local dans des unités de traduction différentes est non séquencée.

Si l'initialisation d'une variable non locale à durée de stockage statique ou de thread se termine par une exception, std::terminate est appelée.

Initialisation dynamique anticipée

Les compilateurs sont autorisés à initialiser des variables à initialisation dynamique dans le cadre de l'initialisation statique (essentiellement, à la compilation), si les deux conditions suivantes sont vraies :

  1. la version dynamique de l'initialisation ne modifie la valeur d'aucun autre objet de portée d'espace de noms avant son initialisation

  2. la version statique de l'initialisation produit dans la variable initialisée la même valeur que celle qui serait produite par l'initialisation dynamique si toutes les variables non tenues d'être initialisées statiquement étaient initialisées dynamiquement.

En raison de la règle ci-dessus, si l'initialisation d'un objet o1 fait référence à un objet de portée d'espace de noms o2, qui nécessite potentiellement une initialisation dynamique, mais est défini plus loin dans la même unité de traduction, il n'est pas spécifié si la valeur de o2 utilisée sera la valeur entièrement initialisée de o2 (car le compilateur a avancé l'initialisation de o2 à la compilation) ou seulement la valeur de o2 initialisée à zéro.

inline double fd() { return 1.0; }

extern double d1;

double d2 = d1;   // unspecified:
                  // initialisée dynamiquement à 0.0 si d1 est initialisée dynamiquement, ou
                  // initialisée dynamiquement à 1.0 si d1 est initialisée statiquement, ou
                  // initialisée statiquement à 0.0 (car ce serait sa valeur
                  // si les deux variables étaient initialisées dynamiquement)

double d1 = fd(); // peut être initialisée statiquement ou dynamiquement à 1.0

Initialisation dynamique différée

Il est défini par l'implémentation de savoir si l'initialisation dynamique se produit avant la première instruction de la fonction main (pour les variables statiques) ou de la fonction initiale du thread (pour les variables thread_local), ou si elle est différée pour se produire après.

Si l'initialisation d'une variable non inline (depuis C++17) est différée pour se produire après la première instruction de la fonction main/du thread, elle se produit avant la première ODR-use de toute variable à durée de stockage statique ou thread définie dans la même unité de traduction que la variable à initialiser. Si aucune variable ni fonction n'est ODR-used depuis une unité de traduction donnée, les variables non locales définies dans cette unité de traduction peuvent ne jamais être initialisées (cela modélise le comportement d'une bibliothèque dynamique à la demande). Toutefois, tant qu'un élément d'une unité de traduction est ODR-used, toutes les variables non locales dont l'initialisation ou la destruction a des effets de bord seront initialisées, même si elles ne sont pas utilisées dans le programme.

Si l'initialisation d'une variable inline est différée, elle se produit avant le premier ODR-use de cette variable spécifique.

(depuis C++17)

// ============
// == File 1 ==

#include "a.h"
#include "b.h"

B b;
A::A() { b.Use(); }

// ============
// == File 2 ==

#include "a.h"

A a;

// ============
// == File 3 ==

#include "a.h"
#include "b.h"

extern A a;
extern B b;

int main()
{
    a.Use();
    b.Use();
}

// Si a est initialisée avant l'entrée dans main, b peut encore être non initialisée
// au point où A::A() l'utilise (car l'initialisation dynamique est
// séquencée de façon indéterminée entre les unités de traduction)

// Si a est initialisée à un moment après la première instruction de main (qui utilise en odr une
// fonction définie dans le Fichier 1, forçant l'exécution de son initialisation dynamique),
// alors b sera initialisée avant son utilisation dans A::A

Variables locales statiques

Pour l'initialisation des variables locales (c'est-à-dire à portée de bloc) statiques et thread_local, voir variables statiques de bloc.

Un initialisateur n'est pas autorisé dans une déclaration à portée de bloc d'une variable à liaison externe ou interne. Une telle déclaration doit apparaître avec extern et ne peut pas être une définition.

Membres de classe

Les membres de données non statiques peuvent être initialisés avec une liste d'initialisation de membres ou avec un initialisateur de membre par défaut.

Notes

L'ordre de destruction des variables non locales est décrit dans std::exit.

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 270 C++98 l'ordre d'initialisation des membres de données statiques de modèles de classes était non spécifié spécifié comme non ordonné, sauf pour les spécialisations explicites et les définitions
CWG 441 C++98 les références non locales à durée de stockage statique n'étaient pas toujours initialisées avant les initialisations dynamiques considérées comme une initialisation statique, toujours initialisées avant les initialisations dynamiques
CWG 1415 C++98 une déclaration de variable extern à portée de bloc pouvait être une définition interdit (aucun initialisateur n'est autorisé dans de telles déclarations)
CWG 2599 C++98 on ne savait pas si l'évaluation des fonction arguments dans l'initialisateur faisait partie de l'initialisation elle fait partie de l'initialisation
