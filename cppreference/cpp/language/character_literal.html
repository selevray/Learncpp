  • c-char — either
    • a basic-c-char,
    • une séquence d'échappement, telle que définie dans séquences d'échappement
    • un nom de caractère universel, tel que défini dans séquences d'échappement
  • basic-c-char — Un caractère du [jeu de caractères source de base (jusqu'à C++23) | jeu de caractères de traduction (depuis C++23)], à l'exception de l'apostrophe ', de la barre oblique inverse \ ou du caractère de fin de ligne
  • c-char-sequence — deux c-char ou plus

Explication

  1. Littéral de caractère ordinaire, par exemple 'a', '\n' ou '\13'. Un tel littéral a le type char et la valeur égale à [la représentation de c-char dans le jeu de caractères d'exécution (jusqu'à C++23) | le point de code correspondant de l'encodage des littéraux ordinaires (depuis C++23)].

  2. Littéral de caractère UTF-8, par exemple u8'a'. Un tel littéral a le type [char (jusqu'à C++20) | char8_t (depuis C++20)] et la valeur égale à la valeur du point de code ISO/IEC 10646 de c-char, à condition que cette valeur puisse être représentée par une seule unité de code UTF-8 (c'est-à-dire que c-char est dans l'intervalle 0x0-0x7F, bornes incluses).

  3. Littéral de caractère UTF-16, par exemple u'猫', mais pas u'🍌' (u'\U0001f34c'). Un tel littéral a le type char16_t et la valeur égale à la valeur du point de code ISO/IEC 10646 de c-char, à condition que cette valeur puisse être représentée par une seule unité de code UTF-16 (c'est-à-dire que c-char est dans l'intervalle 0x0-0xFFFF, bornes incluses).

  4. Littéral de caractère UTF-32, par exemple U'猫' ou U'🍌'. Un tel littéral a le type char32_t et la valeur égale à la valeur du point de code ISO/IEC 10646 de c-char.

  5. Littéral de caractère large, par exemple L'β' ou L'猫'. Un tel littéral a le type wchar_t et la valeur [égale à la valeur de c-char dans le jeu de caractères large d'exécution (jusqu'à C++23) | le point de code correspondant de l'encodage des littéraux larges (depuis C++23)].

  6. [Littéral multicaractère ordinaire (jusqu'à C++23) | Littéral multicaractère (depuis C++23)], par exemple 'AB', est pris en charge conditionnellement, a le type int et une valeur définie par l'implémentation.

  7. Littéral multicaractère large, par exemple L'AB', est pris en charge conditionnellement, a le type wchar_t et une valeur définie par l'implémentation.

Caractères non encodables

1-5) Étant donné que c-char n'est pas une séquence d'échappement numérique (voir ci-dessous), si c-char ne peut pas être représenté dans l'encodage de caractères associé au littéral ou ne peut pas être encodé comme une seule unité de code dans cet encodage (par exemple une valeur hors BMP sous Windows où wchar_t est sur 16 bits), le programme est mal formé.

  1. Si un c-char de c-char-sequence ne peut pas être encodé comme une seule unité de code dans l'encodage des littéraux ordinaires, le programme est mal formé.
  1. Si un c-char de c-char-sequence ne peut pas être encodé comme une seule unité de code dans l'encodage des littéraux larges, le programme est mal formé.

(jusqu'à C++23)

Séquences d'échappement numériques

Les séquences d'échappement numériques (octales et hexadécimales) peuvent être utilisées pour spécifier la valeur du caractère.

Si le littéral de caractère ne contient qu'une seule séquence d'échappement numérique, et que la valeur spécifiée par la séquence d'échappement est représentable par la version non signée de son type, le littéral de caractère a la même valeur que la valeur spécifiée (éventuellement après conversion vers le type caractère).

Un littéral de caractère UTF-N peut avoir toute valeur représentable par son type. Si la valeur ne correspond pas à un point de code Unicode valide, ou si son point de code correspondant n'est pas représentable comme une seule unité de code en UTF-N, elle peut tout de même être spécifiée par une séquence d'échappement numérique ayant cette valeur. Par exemple, u8'\xff' est bien formé et égal à char8_t(0xFF).

(depuis C++23)

Si la valeur spécifiée par une séquence d'échappement numérique utilisée dans un littéral de caractère ordinaire ou large n'est pas représentable par char ou wchar_t respectivement, la valeur du littéral de caractère est définie par l'implémentation.

(jusqu'à C++23)

Si la valeur spécifiée par une séquence d'échappement numérique utilisée dans un littéral de caractère ordinaire ou large avec un seul c-char est représentable par la version non signée du type sous-jacent de char ou wchar_t respectivement, la valeur du littéral est la valeur entière de ce type entier non signé et la valeur spécifiée convertie vers le type du littéral. Sinon, le programme est mal formé.

(depuis C++23)

Si la valeur spécifiée par une séquence d'échappement numérique utilisée dans un littéral de caractère UTF-N n'est pas représentable par le charN_t correspondant, [la valeur du littéral de caractère est définie par l'implémentation (jusqu'à C++17) | le programme est mal formé (depuis C++17)].

(depuis C++11)

Notes

Les littéraux multicaractères ont été hérités par C du langage de programmation B. Bien que non spécifiés par la norme C ou C++, la plupart des compilateurs (MSVC constitue une exception notable) les implémentent comme spécifié en B : les valeurs de chaque char du littéral initialisent les octets successifs de l'entier résultant, dans l'ordre big-endian, complété par des zéros et aligné à droite, par exemple la valeur de '\1' est 0x00000001 et la valeur de '\1\2\3\4' est 0x01020304.

En C, les constantes de caractères telles que 'a' ou '\n' ont le type int, et non char.

Exemple

#include <cstdint>
#include <iomanip>
#include <iostream>
#include <string_view>

template<typename CharT>
void dump(std::string_view s, const CharT c)
{
    const uint8_t* data{reinterpret_cast<const uint8_t*>(&c)};

    std::cout << s << " \t" << std::hex
              << std::uppercase << std::setfill('0');

    for (auto i{0U}; i != sizeof(CharT); ++i)
        std::cout << std::setw(2) << static_cast<unsigned>(data[i]) << ' ';

    std::cout << '\n';
}

void print(std::string_view str = "") { std::cout << str << '\n'; }

int main()
{
    print("Ordinary character literals:");
    char c1 = 'a'; dump("'a'", c1);
    char c2 = '\x2a'; dump("'*'", c2);

    print("\n" "Ordinary multi-character literals:");
    int mc1 = 'ab'; dump("'ab'", mc1);       // défini par l'implémentation
    int mc2 = 'abc'; dump("'abc'", mc2);     // défini par l'implémentation

    print("\n" "UTF-8 character literals:");
    char8_t C1 = u8'a'; dump("u8'a'", C1);
//  char8_t C2 = u8'¢'; dump("u8'¢'", C2);   // erreur : ¢ correspond à deux unités de code UTF-8
//  char8_t C3 = u8'猫'; dump("u8'猫'", C3); // erreur : 猫 correspond à trois unités de code UTF-8
//  char8_t C4 = u8'🍌'; dump("u8'🍌'", C4); // erreur : 🍌 correspond à quatre unités de code UTF-8

    print("\n" "UTF-16 character literals:");
    char16_t uc1 = u'a'; dump("u'a'", uc1);
    char16_t uc2 = u'¢'; dump("u'¢'", uc2);
    char16_t uc3 = u'猫'; dump("u'猫'", uc3);
//  char16_t uc4 = u'🍌'; dump("u'🍌'", uc4); // erreur : 🍌 correspond à deux unités de code UTF-16

    print("\n" "UTF-32 character literals:");
    char32_t Uc1 = U'a'; dump("U'a'", Uc1);
    char32_t Uc2 = U'¢'; dump("U'¢'", Uc2);
    char32_t Uc3 = U'猫'; dump("U'猫'", Uc3);
    char32_t Uc4 = U'🍌'; dump("U'🍌'", Uc4);

    print("\n" "Wide character literals:");
    wchar_t wc1 = L'a'; dump("L'a'", wc1);
    wchar_t wc2 = L'¢'; dump("L'¢'", wc2);
    wchar_t wc3 = L'猫'; dump("L'猫'", wc3);
    wchar_t wc4 = L'🍌'; dump("L'🍌'", wc4);  // non pris en charge sous Windows depuis C++23
}
