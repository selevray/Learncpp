Séquences d'échappement

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les séquences d'échappement servent à représenter certains caractères spéciaux dans les littéraux de chaîne et les littéraux de caractère.

Les séquences d'échappement suivantes sont disponibles :

\? | point d'interrogation | octet 0x3f en codage ASCII

\\ | backslash | octet 0x5c en codage ASCII

\a | sonnerie (bell) | octet 0x07 en codage ASCII

Le caractère c de chaque séquence d'échappement conditionnelle est un membre du [jeu de caractères source de base (jusqu'à C++23) | jeu de caractères de base (depuis C++23)] qui n'est pas le caractère suivant le \ dans aucune autre séquence d'échappement.

Plage des noms de caractères universels

Si un nom de caractère universel correspond à un point de code différent de 0x24 ($), 0x40 (@) et 0x60 ( ` ``) et inférieur à 0xA0, le programme est mal formé. En d'autres termes, les membres du jeu de caractères source de base et les caractères de contrôle (dans les plages 0x0-0x1F et 0x7F-0x9F) ne peuvent pas être exprimés par des noms de caractères universels.

(jusqu'à C++11)

Si un nom de caractère universel correspondant à un point de code d'un membre du jeu de caractères source de base ou à un caractère de contrôle apparaît en dehors d'un littéral de caractère ou d'un littéral de chaîne, le programme est mal formé.

Si un nom de caractère universel correspond à un point de code de substitution (la plage 0xD800-0xDFFF, bornes incluses), le programme est mal formé.

Si un nom de caractère universel utilisé dans un littéral de chaîne UTF-16/32 ne correspond pas à un point de code de ISO/IEC 10646 (la plage 0x0-0x10FFFF, bornes incluses), le programme est mal formé.

(depuis C++11) (jusqu'à C++20)

Si un nom de caractère universel correspondant à un point de code d'un membre du jeu de caractères source de base ou à un caractère de contrôle apparaît en dehors d'un littéral de caractère ou d'un littéral de chaîne, le programme est mal formé.

Si un nom de caractère universel ne correspond pas à un point de code de ISO/IEC 10646 (l'intervalle 0x0-0x10FFFF, bornes incluses) ou correspond à un point de code de substitution (l'intervalle 0xD800-0xDFFF, bornes incluses), le programme est mal formé.

(depuis C++20) (jusqu'à C++23)

Si un nom de caractère universel correspondant à une valeur scalaire d'un caractère du jeu de caractères de base ou d'un caractère de contrôle apparaît en dehors d'un littéral de caractère ou d'un littéral de chaîne, le programme est mal formé.

Si un nom de caractère universel ne correspond pas à une valeur scalaire d'un caractère du jeu de caractères de traduction, le programme est mal formé.

(depuis C++23)

Échappements de caractères universels nommés

\N{ n-char-sequence }

  • n-char-sequence — un ou plusieurs n-char
  • n-char — un caractère du jeu de caractères de traduction, à l'exception de l'accolade fermante } et du caractère de saut de ligne

Un nom de caractère universel de la syntaxe ci-dessus est un caractère universel nommé. Il désigne le caractère correspondant dans le standard Unicode (chapitre 4.8 Name) si n-char-sequence est égal à son nom de caractère ou à l'un de ses alias de nom de caractère de type « control », « correction » ou « alternate » ; sinon, le programme est mal formé.

Ces alias sont listés dans le fichier NameAliases.txt de la base de données de caractères Unicode. Aucun de ces noms ou alias ne comporte d'espace en début ou en fin.

Un n-char-sequence valide ne doit contenir que des lettres latines majuscules de A à Z, des chiffres, des espaces et des traits d'union (hyphen-minus). Les autres caractères n'apparaissent jamais dans un nom de caractère Unicode ; leur présence dans un n-char-sequence rend toujours le programme mal formé.

(depuis C++23)

Notes

\0 est la séquence d'échappement octale la plus couramment utilisée, car elle représente le caractère nul de fin dans les chaînes terminées par un caractère nul.

Le caractère de saut de ligne \n a une signification particulière lorsqu'il est utilisé dans les E/S en mode texte : il est converti en la représentation de fin de ligne propre au système d'exploitation, généralement un octet ou une suite d'octets. Certains systèmes marquent plutôt leurs lignes à l'aide de champs de longueur.

Les séquences d'échappement octales sont limitées à trois chiffres octaux, mais se terminent au premier caractère qui n'est pas un chiffre octal valide, si celui-ci apparaît plus tôt.

Les séquences d'échappement hexadécimales n'ont pas de limite de longueur et se terminent au premier caractère qui n'est pas un chiffre hexadécimal valide. Si la valeur représentée par une seule séquence d'échappement hexadécimale ne rentre pas dans l'intervalle de valeurs représenté par le type de caractère utilisé dans ce littéral de chaîne (char, [char8_t, (depuis C++20) | char16_t, char32_t, (depuis C++11)]ou wchar_t), le résultat est non spécifié.

Un nom de caractère universel dans un littéral de chaîne étroite ou un littéral de chaîne 16 bits peut correspondre à plusieurs unités de code, par exemple \U0001f34c correspond à 4 char unités de code en UTF-8 (\xF0\x9F\x8D\x8C) et à 2 char16_t unités de code en UTF-16 (\xD83C\xDF4C).

(depuis C++11)

La séquence d'échappement du point d'interrogation \? sert à empêcher l'interprétation des trigraphes à l'intérieur des littéraux de chaîne : une chaîne telle que "??/" est compilée comme "\", mais si le second point d'interrogation est échappé, comme dans "?\?/", elle devient "??/". Les trigraphes ayant été supprimés de C++, la séquence d'échappement du point d'interrogation n'est plus nécessaire. Elle est conservée pour la compatibilité avec C++14 (et les révisions antérieures) et C. (depuis C++17)

Exemple

#include <iostream>

int main()
{
    std::cout << "This\nis\na\ntest\n\n";
    std::cout << "She said, \"Sells she seashells on the seashore?\"\n";
}

This
is
a
test

She said, "Sells she seashells on the seashore?"
