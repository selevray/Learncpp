Une référence à T peut être initialisée avec un objet de type T, une fonction de type T, ou un objet implicitement convertible en T. Une fois initialisée, une référence ne peut plus être rattachée (changée) pour désigner un autre objet.

Les références sont initialisées dans les situations suivantes :

  1. Lorsqu'une variable nommée de référence lvalue est déclarée avec un initialiseur.

  2. Lorsqu'une variable nommée de référence rvalue est déclarée avec un initialiseur.

  3. Dans une expression d'appel de fonction, lorsque le paramètre de la fonction a un type référence.

  4. Dans l'instruction return, lorsque la fonction renvoie un type référence. Le programme est mal formé si la référence renvoyée est liée au résultat d'une expression temporaire. (depuis C++26)

  5. Lorsqu'un membre de données non statique de type référence est initialisé à l'aide d'un initialiseur de membre.

Explication

  • T — le type référencé
  • ref — la variable référence à initialiser
  • target — l'expression d'initialisation utilisée
  • func-refpar — une fonction dont un paramètre est de type référence (T ﻿&ou T ﻿&& (depuis C++11))
  • func-refret — une fonction dont le type de retour est un type référence (T ﻿&ou T ﻿&& (depuis C++11))
  • Class — un nom de classe
  • ref-member — un membre de données non statique de type référence (T ﻿&ou T ﻿&& (depuis C++11)) de Class
  • des1, des2, ... — designators
  • arg1, arg2, ... — les initialiseurs dans les listes d'initialisation

Définitions

Pour deux types T1 et T2 :

  • En notant les versions sans qualificateurs cv de T1 et T2 respectivement U1 et U2, si U1 est similaire à U2, ou si U1 est une classe de base de U2, T1 est liée par référence à T2.
  • Si une prvalue de type « pointeur vers T2 » peut être convertie en type « pointeur vers T1 » via une séquence de conversions standard, T1 est compatible en référence avec T2.

Règles d'initialisation

Si une initialisation de référence utilise une initialisation par liste ordinaireou désignée (depuis C++20), les règles de l'initialisation par liste sont appliquées.

(depuis C++11)

Pour une initialisation de référence qui n'est pas par liste, étant donné le type de target noté U, la référence soit se lie directement à target, soit se lie à une valeur de type T convertie depuis target. La liaison directe est envisagée en premier, suivie de la liaison indirecte ; si aucune de ces liaisons n'est possible, le programme est mal formé.

Dans tous les cas où la relation de compatibilité par référence entre deux types est utilisée pour établir la validité d'une liaison de référence et où la séquence de conversions standard serait mal formée, un programme qui nécessite une telle liaison est mal formé.

Liaison directe

Si toutes les conditions suivantes sont satisfaites :

  • La référence à initialiser est une référence lvalue.
  • target est une lvalue qui n'est pas un champ de bits.
  • T est compatible en référence avec U.

Alors la référence se lie à target, ou à son sous-objet de classe de base approprié :

double d = 2.0;
double& rd = d;        // rd fait référence à d
const double& rcd = d; // rcd fait référence à d

struct A {};
struct B : A {} b;

A& ra = b;             // ra fait référence au sous-objet A de b
const A& rca = b;      // rca fait référence au sous-objet A de b

Sinon, si toutes les conditions suivantes sont satisfaites :

  • La référence à initialiser est une référence lvalue.
  • U est un type classe.
  • T n'est pas liée par référence à U.
  • target peut être convertie en une lvalue de type V telle que T soit compatible en référence avec V.

Alors la référence se lie au résultat lvalue de la conversion, ou à son sous-objet de classe de base approprié :

struct A {};
struct B : A { operator int&(); };

int& ir = B(); // ir fait référence au résultat de B::operator int&

Sinon, si la référence à initialiser est une référence lvalue, et que T n'est pas qualifié const ou est qualifié volatile, le programme est mal formé :

double& rd2 = 2.0; // erreur : pas une lvalue et la référence n'est pas const
int i = 2;
double& rd3 = i;   // erreur : types incompatibles et la référence n'est pas const

Sinon, si toutes les conditions suivantes sont satisfaites :

  • target est une valeur de l'une des catégories suivantes :
  • rvalue

(jusqu'à C++11)

  • xvalue qui n'est pas un champ de bits
  • prvalue de classe
  • prvalue de tableau
  • lvalue de fonction

(depuis C++11) (jusqu'à C++17)

  • rvalue qui n'est pas un champ de bits
  • lvalue de fonction

(depuis C++17)

  • T est compatible en référence avec U.

Alors la référence se lie à target, ou à son sous-objet de classe de base approprié :

struct A {};
struct B : A {};
extern B f();

const A& rca2 = f(); // liée au sous-objet A de la rvalue B.
A&& rra = f();       // identique à ci-dessus

int i2 = 42;
int&& rri = static_cast<int&&>(i2); // liée directement à i2

Si target est une prvalue, une matérialisation temporaire lui est appliquée, en considérant le type de la prvalue comme le type ajusté P.

  • P est ajusté à partir du type de target (c.-à-d. U) en lui ajoutant le qualificateur cv de T.

Dans ce cas, la référence se lie à l'objet résultat, ou à son sous-objet de classe de base approprié.

(depuis C++17)

Sinon, si toutes les conditions suivantes sont satisfaites :

  • U est un type classe.
  • T n'est pas liée par référence à U.
  • target peut être convertie en une valeur v de type V telle que T soit compatible en référence avec V, où v est de l'une des catégories suivantes :
  • rvalue

(jusqu'à C++11)

  • xvalue
  • prvalue de classe
  • lvalue de fonction

(depuis C++11) (jusqu'à C++17)

  • rvalue
  • lvalue de fonction

(depuis C++17)

Alors la référence se lie au résultat de la conversion, ou à son sous-objet de classe de base approprié :

struct A {};
struct B : A {};
struct X { operator B(); } x;

const A& r = x; // liée au sous-objet A du résultat de la conversion
B&& rrb = x;    // liée directement au résultat de la conversion

Si le résultat de la conversion est une prvalue, une matérialisation temporaire lui est appliquée, en considérant le type de la prvalue comme le type ajusté P.

  • P est ajusté à partir du type du résultat de la conversion en lui ajoutant le qualificateur cv de T.

Dans ce cas, la référence se lie à l'objet résultat, ou à son sous-objet de classe de base approprié.

(depuis C++17)

Liaison indirecte

Si la liaison directe n'est pas possible, la liaison indirecte est envisagée. Dans ce cas, T ne peut pas être liée par référence à U.

Si T ou U est un type classe, les conversions définies par l'utilisateur sont envisagées selon les règles de l'initialisation par copie d'un objet de type T par conversion définie par l'utilisateur. Le programme est mal formé si l'initialisation par copie non référence correspondante serait mal formée. Le résultat de l'appel à la fonction de conversion, tel que décrit pour l'initialisation par copie non référence, sert ensuite à initialiser directement la référence. Pour cette initialisation directe, les conversions définies par l'utilisateur ne sont pas envisagées.

Sinon, un temporaire de type T est créé et initialisé par copie à partir de target. La référence est ensuite liée à ce temporaire.

(jusqu'à C++17)

Sinon, target est implicitement convertie en une prvalue de type « T sans qualificateur cv ». La matérialisation temporaire est appliquée, en considérant le type de la prvalue comme T, et la référence est liée à l'objet résultat.

(depuis C++17)

const std::string& rs = "abc"; // rs fait référence à un temporaire copy-initialisé à partir d'un tableau de char
const double& rcd2 = 2;        // rcd2 fait référence à un temporaire de valeur 2.0
int i3 = 2;
double&& rrd3 = i3;            // rrd3 fait référence à un temporaire de valeur 2.0

Durée de vie d'un temporaire

Chaque fois qu'une référence est liée à un objet temporaire ou à un sous-objet de celui-ci, la durée de vie de l'objet temporaire est prolongée pour correspondre à celle de la référence (voir exceptions à la durée de vie d'un objet temporaire), où l'objet temporaire ou son sous-objet est désigné par l'une des expressions suivantes :

  • une expression prvalue d'un type objet,

(jusqu'à C++17)

  • une conversion de matérialisation temporaire,

(depuis C++17)

  • une expression entre parenthèses (e), où e est l'une de ces expressions,
  • une expression d'indexation intégrée de la forme a[n] ou n[a], où a est un tableau et est l'une de ces expressions,
  • une expression d'accès à un membre de classe de la forme e.m, où e est l'une de ces expressions et m désigne un membre de données non statique de type objet,
  • une opération pointeur vers membre de la forme e.*mp, où e est l'une de ces expressions et mp est un pointeur vers membre de données,
  • une conversion const_cast, static_cast, dynamic_cast ou reinterpret_cast sans conversion définie par l'utilisateur, qui convertit l'une de ces expressions en glvalue désignant l'objet désigné par l'opérande, ou son objet complet ou un sous-objet de celui-ci (une expression de transtypage explicite est interprétée comme une suite de ces transtypages),
  • une expression conditionnelle de la forme cond ? e1 : e2 qui est une glvalue, où e1 ou e2 est l'une de ces expressions, ou
  • une expression virgule intégrée de la forme x, e qui est une glvalue, où e est l'une de ces expressions.

Cette règle de durée de vie connaît les exceptions suivantes :

  • un temporaire lié à une valeur de retour d'une fonction dans une instruction return n'est pas prolongé : il est détruit immédiatement à la fin de l'expression de retour. Une telle instruction return renvoie toujours une référence pendante.

(jusqu'à C++26)

  • un temporaire lié à un paramètre référence dans un appel de fonction existe jusqu'à la fin de l'expression complète contenant cet appel : si la fonction renvoie une référence qui survit à l'expression complète, elle devient une référence pendante.
  • un temporaire lié à une référence dans l'initialiseur utilisé dans une expression new existe jusqu'à la fin de l'expression complète contenant cette expression new, et non aussi longtemps que l'objet initialisé. Si l'objet initialisé survit à l'expression complète, son membre référence devient une référence pendante.

(depuis C++11)

  • un temporaire lié à une référence dans un élément référence d'un agrégat initialisé avec la syntaxe d'initialisation directe (parenthèses) existe jusqu'à la fin de l'expression complète contenant l'initialiseur, contrairement à la syntaxe d'initialisation par liste {accolades}.
struct A
{
    int&& r;
};

A a1{7}; // OK, la durée de vie est prolongée
A a2(7); // bien formé, mais référence pendante

(depuis C++20)

En général, la durée de vie d'un temporaire ne peut pas être prolongée davantage par « transmission » : une seconde référence, initialisée à partir de la variable référence ou du membre de données auquel le temporaire a été lié, n'affecte pas sa durée de vie.

Notes

Des références n'apparaissent sans initialiseur que dans les déclarations de paramètres de fonction, dans les déclarations de type de retour de fonction, dans la déclaration d'un membre de classe, et avec le spécificateur extern.

Jusqu'à la résolution de la CWG issue 1696, un temporaire était autorisé à être lié à un membre référence dans la liste d'initialisation d'un constructeur, et il persistait seulement jusqu'à la sortie du constructeur, et non aussi longtemps que l'objet existe. Une telle initialisation est mal formée depuis CWG 1696, bien que de nombreux compilateurs la prennent encore en charge (une exception notable est clang).

Exemple

#include <sstream>
#include <utility>

struct S
{
    int mi;
    const std::pair<int, int>& mp; // membre référence
};

void foo(int) {}

struct A {};

struct B : A
{
    int n;
    operator int&() { return n; }
};

B bar() { return B(); }

//int& bad_r;      // erreur : pas d'initialiseur
extern int& ext_r; // OK

int main()
{
//  Lvalues
    int n = 1;
    int& r1 = n;                    // référence lvalue vers l'objet n
    const int& cr(n);               // la référence peut être plus qualifiée cv
    volatile int& cv{n};            // toute syntaxe d'initialisation peut être utilisée
    int& r2 = r1;                   // une autre référence lvalue vers l'objet n
//  int& bad = cr;                  // erreur : moins qualifiée cv
    int& r3 = const_cast<int&>(cr); // un const_cast est nécessaire

    void (&rf)(int) = foo; // référence lvalue vers une fonction
    int ar[3];
    int (&ra)[3] = ar;     // référence lvalue vers un tableau

    B b;
    A& base_ref = b;        // référence vers un sous-objet de base
    int& converted_ref = b; // référence vers le résultat d'une conversion

//  Rvalues
//  int& bad = 1;        // erreur : impossible de lier une référence lvalue à une rvalue
    const int& cref = 1; // liée à une rvalue
    int&& rref = 1;      // liée à une rvalue

    const A& cref2 = bar(); // référence vers le sous-objet A d'un temporaire B
    A&& rref2 = bar();      // same

    int&& xref = static_cast<int&&>(n); // liée directement à n
//  int&& copy_ref = n;                 // erreur : impossible de lier à une lvalue
    double&& copy_ref = n;              // se lie à un temporaire de type rvalue de valeur 1.0

//  Restrictions sur la durée de vie des temporaires
//  std::ostream& buf_ref = std::ostringstream() << 'a';
                     // le temporaire ostringstream était lié à l'opérande gauche
                     // de operator<< mais sa durée de vie s'est terminée au point-virgule donc
                     // buf_ref est une référence pendante

    S a {1, {2, 3}}; // le temporaire pair {2, 3} lié au membre référence
                     // a.mp et sa durée de vie est prolongée pour correspondre
                     // la durée de vie de l'objet a

    S* p = new S{1, {2, 3}}; // le temporaire pair {2, 3} lié à la référence
                             // membre p->mp, mais sa durée de vie s'est terminée au point-virgule
                             // p->mp est une référence pendante
    delete p;

    // Imiter [[maybe_unused]] appliqué aux variables suivantes :
    [](...){}
    (
        cv, r2, r3, rf, ra, base_ref, converted_ref,
        a, cref, rref, cref2, rref2, copy_ref, xref
    );
}
