Déclaration de fonction

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Une déclaration de fonction introduit le nom de la fonction et son type. Une définition de fonction associe le nom/type de la fonction au corps de la fonction.

Déclaration de fonction

Les déclarations de fonctions peuvent apparaître dans n'importe quelle portée. Une déclaration de fonction de portée de classe introduit une fonction membre de classe (sauf si le spécificateur friend est utilisé), voir fonctions membres et fonctions amies pour plus de détails.

Comme mentionné dans Déclarations, le déclarateur peut être suivi d'une clause requires, qui déclare les contraintes associées à la fonction, lesquelles doivent être satisfaites pour que la fonction soit sélectionnée par la résolution de surcharge. (exemple : void f1(int a) requires true;) Notez que la contrainte associée fait partie de la signature de la fonction, mais non du type de la fonction.

(depuis C++20)

Les déclarateurs de fonctions peuvent être mélangés à d'autres déclarateurs, la séquence de spécificateurs de déclaration le permettant :

// déclare un int, un int*, une fonction et un pointeur vers une fonction
int a = 1, *p = NULL, f(), (*pf)(double);
// decl-specifier-seq est int
// le déclarateur f() déclare (mais ne définit pas)
//                une fonction ne prenant aucun argument et retournant int

struct S
{
    virtual int f(char) const, g(int) &&; // déclare deux fonctions membres non statiques
    virtual int f(char), x; // erreur à la compilation : virtual (dans decl-specifier-seq)
                            // n'est autorisé que dans les déclarations de fonctions membres non statiques
                            // Fonctions membres
};

Utiliser un type d'objet qualifié volatile comme type de paramètre ou type de retour est obsolète.

(depuis C++20)

Le type de retour d'une fonction ne peut pas être un type fonction ou un type tableau (mais peut être un pointeur ou une référence vers ceux-ci).

Comme pour toute déclaration, les attributs qui apparaissent avant la déclaration et les attributs qui apparaissent immédiatement après l'identifiant dans le déclarateur s'appliquent tous deux à l'entité déclarée ou définie (ici, à la fonction) :

[[noreturn]] void f [[noreturn]] (); // OK : les deux attributs s'appliquent à la fonction f

Cependant, les attributs qui apparaissent après le déclarateur (dans la syntaxe ci-dessus) s'appliquent au type de la fonction, et non à la fonction elle-même :

void f() [[noreturn]]; // Erreur : cet attribut n'a aucun effet sur la fonction elle-même

(depuis C++11)

Déduction du type de retour

Si le decl-specifier-seq de la déclaration de fonction contient le mot-clé auto, le type de retour final peut être omis et sera déduit par le compilateur à partir du type de l'expression utilisée dans l'instruction return. Si le type de retour n'utilise pas decltype(auto), la déduction suit les règles de la déduction d'arguments de modèle :

int x = 1;
auto f() { return x; }        // le type de retour est int
const auto& f() { return x; } // le type de retour est const int&

Si le type de retour est decltype(auto), le type de retour est celui qu'on obtiendrait si l'expression utilisée dans l'instruction return était enveloppée dans decltype :

int x = 1;
decltype(auto) f() { return x; }  // le type de retour est int, identique à decltype(x)
decltype(auto) f() { return(x); } // le type de retour est int&, identique à decltype((x))

(remarque : « const decltype(auto)& » est une erreur, decltype(auto) doit être utilisé seul)

S'il y a plusieurs instructions return, elles doivent toutes déduire le même type :

auto f(bool val)
{
    if (val) return 123; // déduit le type de retour int
    else return 3.14f;   // Erreur : déduit le type de retour float
}

S'il n'y a pas d'instruction return ou si l'argument de l'instruction return est une expression de type void, le type de retour déclaré doit être soit decltype(auto), auquel cas le type de retour déduit est void, soit (éventuellement qualifié cv) auto, auquel cas le type de retour déduit est alors void (qualifié cv de manière identique) :

auto f() {}              // renvoie void
auto g() { return f(); } // renvoie void
auto* x() {}             // Erreur : impossible de déduire auto* à partir de void

Une fois qu'une instruction return a été rencontrée dans une fonction, le type de retour déduit de cette instruction peut être utilisé dans le reste de la fonction, y compris dans d'autres instructions return :

auto sum(int i)
{
    if (i == 1)
        return i;              // le type de retour de sum est int
    else
        return sum(i - 1) + i; // OK : le type de retour de sum est déjà connu
}

Si l'instruction return utilise une liste d'initialisation entre accolades, la déduction n'est pas autorisée :

auto func() { return {1, 2, 3}; } // Erreur

Les fonctions virtuelleset coroutines (depuis C++20) ne peuvent pas utiliser la déduction du type de retour :

struct F
{
    virtual auto f() { return 2; } // Erreur
};

Les modèles de fonctions autres que les fonctions de conversion définies par l'utilisateur peuvent utiliser la déduction du type de retour. La déduction a lieu lors de l'instanciation même si l'expression de l'instruction return n'est pas dépendante. Cette instanciation ne se trouve pas dans un contexte immédiat au sens de SFINAE.

template<class T>
auto f(T t) { return t; }
typedef decltype(f(1)) fint_t;    // instancie f<int> pour déduire le type de retour

template<class T>
auto f(T* t) { return *t; }
void g() { int (*p)(int*) = &f; } // instancie les deux fs pour déterminer les types de retour,
                                  // choisit la deuxième surcharge de modèle

Les redéclarations ou spécialisations de fonctions ou de modèles de fonctions qui utilisent la déduction du type de retour doivent utiliser les mêmes marqueurs de type de retour :

auto f(int num) { return num; }
// int f(int num);            // Erreur : pas d'exigence de type de retour de substitution
// decltype(auto) f(int num); // Erreur : substitut différent

template<typename T>
auto g(T t) { return t; }
template auto g(int);     // OK : le type de retour est int
// template char g(char); // Erreur : pas une spécialisation du modèle primaire g

De même, les redéclarations ou spécialisations de fonctions ou de modèles de fonctions qui n'utilisent pas la déduction du type de retour ne doivent pas utiliser de marqueur :

int f(int num);
// auto f(int num) { return num; } // Erreur : pas une redéclaration de f

template<typename T>
T g(T t) { return t; }
template int g(int);      // OK : spécialise T en int
// template auto g(char); // Erreur : pas une spécialisation du modèle primaire g

Les déclarations d'instanciation explicite n'instancient pas elles-mêmes les modèles de fonctions qui utilisent la déduction du type de retour :

template<typename T>
auto f(T t) { return t; }
extern template auto f(int); // n'instancie pas f<int>

int (*p)(int) = f; // instancie f<int> pour déterminer son type de retour,
                   // mais une définition d'instanciation explicite
                   // reste requise quelque part dans le programme

(depuis C++14)

Liste de paramètres

La liste de paramètres détermine les arguments qui peuvent être spécifiés lors de l'appel de la fonction. C'est une liste de déclarations de paramètres séparées par des virgules, chacune ayant la syntaxe suivante :

Bien que decl-specifier-seq implique qu'il puisse exister des spécificateurs autres que les spécificateurs de type, le seul autre spécificateur autorisé est registerainsi que auto (jusqu'à C++11), et il n'a aucun effet.

(jusqu'à C++17)

Si l'un des paramètres de la fonction utilise un espace réservé (soit auto, soit un type de concept), la déclaration de la fonction est alors une déclaration de modèle de fonction abrégé :

void f1(auto);    // identique à template<class T> void f1(T)
void f2(C1 auto); // identique à template<C1 T> void f2(T), si C1 est un concept

(depuis C++20)

Une déclaration de paramètre avec le spécificateur this (syntaxe (2)/(5)) déclare un paramètre d'objet explicite.

Un paramètre d'objet explicite ne peut pas être un pack de paramètres de fonction, et il ne peut apparaître que comme premier paramètre de la liste de paramètres dans les déclarations suivantes :

  • une déclaration d'une fonction membre ou d'un modèle de fonction membre
  • une instanciation explicite ou spécialisation explicite d'une fonction membre de modèle
  • une déclaration de lambda

Une fonction membre avec un paramètre d'objet explicite a les restrictions suivantes :

  • La fonction n'est pas static.
  • La fonction n'est pas virtual.
  • Le déclarateur de la fonction ne contient pas cv ni ref.
struct C
{
    void f(this C& self);     // OK

    template<typename Self>
    void g(this Self&& self); // également valide pour les modèles

    void p(this C) const;     // Erreur : « const » non autorisé ici
    static void q(this C);    // Erreur : « static » non autorisé ici
    void r(int, this C);      // Erreur : un paramètre objet explicite
                              //        ne peut être que le premier paramètre
};

// void func(this C& self);   // Erreur : les fonctions non membres ne peuvent pas avoir
                              //        un paramètre objet explicite

(depuis C++23)

Les noms de paramètres déclarés dans les déclarations de fonctions ne servent généralement qu'à l'auto-documentation. Ils sont utilisés (mais restent facultatifs) dans les définitions de fonctions.

Une ambiguïté survient dans une liste de paramètres lorsqu'un nom de type est imbriqué entre parenthèses(y compris les expressions lambda) (depuis C++11). Dans ce cas, le choix se fait entre la déclaration d'un paramètre de type pointeur vers fonction et la déclaration d'un paramètre avec des parenthèses superflues autour de l'identifiant de declarator. La résolution consiste à considérer le nom de type comme un spécificateur de type simple (qui est le type pointeur vers fonction) :

class C {};

void f(int(C)) {} // void f(int(*fp)(C param)) {}
                  // PAS void f(int C) {}

void g(int *(C[10])); // void g(int *(*fp)(C param[10]));
                      // PAS void g(int *C[10]);

Le type d'un paramètre ne peut pas être un type incluant une référence ou un pointeur vers un tableau de borne inconnue, y compris les pointeurs ou tableaux à plusieurs niveaux de tels types, ni un pointeur vers des fonctions dont les paramètres sont de tels types.

Utilisation de points de suspension

Le dernier paramètre de la liste de paramètres peut être des points de suspension (...) ; cela déclare une fonction variadique. La virgule précédant les points de suspension peut être omise (obsolète en C++26) :

int printf(const char* fmt, ...); // une fonction variadique
int printf(const char* fmt...);   // identique à ci-dessus, mais obsolète depuis C++26

template<typename... Args>
void f(Args..., ...); // un modèle de fonction variadique avec un pack de paramètres

template<typename... Args>
void f(Args... ...);  // identique à ci-dessus, mais obsolète depuis C++26

template<typename... Args>
void f(Args......);   // identique à ci-dessus, mais obsolète depuis C++26

Type de fonction

Liste des types de paramètres

La liste des types de paramètres d'une fonction est déterminée comme suit :

  1. Le type de chaque paramètre(y compris les packs de paramètres de fonction) (depuis C++11) est déterminé à partir de sa propre déclaration de paramètre.
  2. Après détermination du type de chaque paramètre, tout paramètre de type « tableau de T » ou de type fonction T est ajusté pour devenir « pointeur vers T ».
  3. Après production de la liste des types de paramètres, tous les qualificateurs cv de premier niveau modifiant un type de paramètre sont supprimés lors de la formation du type de fonction.
  4. La liste résultante des types de paramètres transformés, ainsi que la présence ou l'absence des points de suspensionou d'un pack de paramètres de fonction (depuis C++11), constitue la liste des types de paramètres de la fonction.
void f(char*);         // #1
void f(char[]) {}      // defines #1
void f(const char*) {} // OK, autre surcharge
void f(char* const) {} // Erreur : redéfinit #1

void g(char(*)[2]);   // #2
void g(char[3][2]) {} // defines #2
void g(char[3][3]) {} // OK, autre surcharge

void h(int x(const int)); // #3
void h(int (*)(int)) {}   // defines #3

Qualificateurs finaux

Un type de fonction avec cv ﻿ou ref ﻿ ﻿ (depuis C++11) (y compris un type désigné par un nom typedef) ne peut apparaître que comme :

  • le type de fonction d'une fonction membre non statique,
  • le type de fonction auquel renvoie un pointeur vers membre,
  • le type de fonction de premier niveau d'une déclaration de fonction typedefou d'une déclaration d'alias (depuis C++11),
  • le type-id dans l'argument par défaut d'un paramètre de type de modèle, ou
  • le type-id d'un argument de modèle pour un paramètre de type de modèle.
typedef int FIC(int) const;
FIC f;     // Erreur : ne déclare pas une fonction membre

struct S
{
    FIC f; // OK
};

FIC S::*pm = &S::f; // OK

Signature de fonction

Chaque fonction possède une signature.

La signature d'une fonction est constituée de son nom et de sa liste des types de paramètres. Sa signature contient également l'espace de noms englobant, avec les exceptions suivantes :

  • Si la fonction est une fonction membre, sa signature contient la classe dont la fonction est membre à la place de l'espace de noms englobant. Sa signature contient également les composants suivants, s'ils existent :
    • cv
  • ref

(depuis C++11)

  • clause requires finale

  • Si la fonction est une fonction amie non modèle avec une clause requires finale, sa signature contient la classe englobante à la place de l'espace de noms englobant. La signature contient également la clause requires finale.

(depuis C++20)

exceptet attr (depuis C++11) n'interviennent pas dans la signature de fonction, bien que spécification noexcept affecte le type de fonction (depuis C++17).

Définition de fonction

Une définition de fonction non membre ne peut apparaître que dans un espace de noms (il n'existe pas de fonctions imbriquées). Une définition de fonction membre peut aussi apparaître dans le corps d'une définition de classe. Elles ont la syntaxe suivante :

| | | | attr ﻿*(facultatif)* decl-specifier-seq ﻿*(facultatif)* declarator virt-specifier-seq ﻿*(facultatif)* function-body | (1) | | | | attr ﻿*(facultatif)* decl-specifier-seq ﻿*(facultatif)* declarator requires-clause function-body | (2) | (depuis C++20) | |

  1. Une définition de fonction sans contraintes.

  2. Une définition de fonction avec contraintes.

  • attr — (depuis C++11) une liste d'attributs. Ces attributs sont combinés avec les attributs situés après l'identifiant dans declarator (voir le haut de cette page), le cas échéant.
  • decl-specifier-seq — le type de retour avec ses spécificateurs, comme dans la grammaire des déclarations
  • declarator — déclarateur de fonction, identique à celui de la grammaire des déclarations de fonctions ci-dessus (peut être entre parenthèses)
  • virt-specifier-seq — (depuis C++11) override, final, ou leur combinaison dans n'importe quel ordre
  • requires-clause — une requires clause
  • function-body — le corps de la fonction (voir ci-dessous)

function-body est l'une des formes suivantes :

| | | | ctor-initializer ﻿*(facultatif)* compound-statement | (1) | | | | function-try-block | (2) | | | | = default ; | (3) | (depuis C++11) | | | = delete ; | (4) | (depuis C++11) | | | = delete ( string-literal ); | (5) | (depuis C++26) | |

  1. Corps de fonction ordinaire.

  2. Bloc try de fonction.

  3. Définition de fonction explicitement défaut.

  4. Définition de fonction explicitement supprimée.

  5. Définition de fonction explicitement supprimée avec message d'erreur.

  • ctor-initializer — liste d'initialisation des membres, uniquement autorisée dans les constructeurs
  • compound-statement — la suite d'instructions entre accolades qui constitue le corps d'une fonction
  • function-try-block — un bloc try de fonction
  • string-literal — un littéral chaîne non évalué pouvant servir à expliquer la raison pour laquelle la fonction est supprimée
int max(int a, int b, int c)
{
    int m = (a > b) ? a : b;
    return (m > c) ? m : c;
}

// decl-specifier-seq est « int »
// le déclarateur est « max(int a, int b, int c) »
// le corps est { ... }

Le corps de la fonction est une instruction composée (suite de zéro ou plusieurs instructions entourées d'une paire d'accolades), qui est exécutée lors de l'appel de la fonction. De plus, le corps de fonction d'un constructeur comprend également ce qui suit :

  • Pour tous les membres de données non statiques dont les identifiants sont absents de la liste d'initialisation des membres du constructeur, les initialisateurs par défaut de membres ou (depuis C++11) initialisations par défaut utilisées pour initialiser les sous-objets membres correspondants.
  • Pour toutes les classes de base dont les noms de type sont absents de la liste d'initialisation des membres du constructeur, les initialisations par défaut utilisées pour initialiser les sous-objets de classe de base correspondants.

Si une définition de fonction contient un virt-specifier-seq, elle doit définir une fonction membre.

(depuis C++11)

Si une définition de fonction contient un requires-clause, elle doit définir une fonction modèle.

(depuis C++20)

void f() override {} // Erreur : pas une fonction membre

void g() requires (sizeof(int) == 4) {} // Erreur : pas une fonction templatée

Les types des paramètres, ainsi que le type de retour d'une définition de fonction, ne peuvent pas être des types incomplets de classe (éventuellement qualifiés cv)sauf si la fonction est définie comme supprimée (depuis C++11). La vérification de complétude n'est effectuée que dans le corps de la fonction, ce qui permet aux fonctions membres de renvoyer la classe dans laquelle elles sont définies (ou sa classe englobante), même si elle est incomplète au point de définition (elle est complète dans le corps de la fonction).

Les paramètres déclarés dans le declarator d'une définition de fonction sont dans la portée du corps. Si un paramètre n'est pas utilisé dans le corps de la fonction, il n'a pas besoin d'être nommé (il suffit d'utiliser un déclarateur abstrait) :

void print(int a, int) // le second paramètre n'est pas utilisé
{
    std::printf("a = %d\n", a);
}

Même si les qualificateurs cv de premier niveau des paramètres sont ignorés dans les déclarations de fonctions, ils modifient le type du paramètre tel qu'il apparaît dans le corps d'une fonction :

void f(const int n) // déclare une fonction de type void(int)
{
    // mais dans le corps, le type de « n » est const int
}

Fonctions par défaut

Si la définition de la fonction a la syntaxe (3), la fonction est définie comme explicitement défaut.

Une fonction explicitement défaut doit être une fonction membre spécialeou une fonction opérateur de comparaison (depuis C++20), et elle ne doit avoir aucun argument par défaut.

Une fonction membre spéciale explicitement défaut F1 peut différer de la fonction membre spéciale F2 qui aurait été déclarée implicitement, comme suit :

  • F1 et F2 peuvent avoir des ref et/ou except différents.
  • Si F2 a un paramètre non objet de type const C&, le paramètre non objet correspondant de F1 peut être de type C&.

(depuis C++11)

  • Si F2 a un paramètre objet implicite de type « référence vers C », F1 peut être une fonction membre à paramètre objet explicite dont le paramètre objet explicite est de type (éventuellement différent) « référence vers C », auquel cas le type de F1 diffère du type de F2 en ce que le type de F1 possède un paramètre supplémentaire.

(depuis C++23)

Si le type de F1 diffère du type de F2 d'une manière autre que celle permise par les règles précédentes, alors :

  • Si F1 est un opérateur d'affectation, et que le type de retour de F1 diffère du type de retour de F2 ou que le type du paramètre non objet de F1 n'est pas une référence, le programme est mal formé.
  • Sinon, si F1 est explicitement défaut à sa première déclaration, elle est définie comme supprimée.
  • Sinon, le programme est mal formé.

Une fonction explicitement défaut à sa première déclaration est implicitement inline, et est implicitement constexpr si elle peut être une fonction constexpr.

struct S
{
    S(int a = 0) = default;             // erreur : argument par défaut
    void operator=(const S&) = default; // erreur : type de retour non concordant
    ~S() noexcept(false) = default;     // OK, spécification d'exception différente
private:
    int i;
    S(S&);          // OK, constructeur de copie privé
};

S::S(S&) = default; // OK, définit le constructeur de copie

Les fonctions explicitement défaut et les fonctions déclarées implicitement sont collectivement appelées fonctions défaut. Leurs définitions effectives seront fournies implicitement, voir leurs pages correspondantes pour plus de détails.

Fonctions supprimées

Si la définition de la fonction est de la syntaxe (4)ou (5) (depuis C++26), la fonction est définie comme explicitement supprimée.

Toute utilisation d'une fonction supprimée est mal formée (le programme ne compilera pas). Cela inclut les appels, explicites (avec l'opérateur d'appel de fonction) et implicites (un appel à un opérateur surchargé supprimé, à une fonction membre spéciale, à une fonction d'allocation, etc.), la construction d'un pointeur ou d'un pointeur vers membre vers une fonction supprimée, et même l'utilisation d'une fonction supprimée dans une expression qui n'est pas potentiellement évaluée.

Une fonction membre virtuelle non pure peut être définie comme supprimée, même si elle est implicitement utilisée par la règle de définition unique (odr-used). Une fonction supprimée ne peut être redéfinie que par des fonctions supprimées, et une fonction non supprimée ne peut être redéfinie que par des fonctions non supprimées.

(depuis C++11)

Si string-literal est présent, l'implémentation est encouragée à inclure son texte dans le message de diagnostic résultant, qui indique la raison de la suppression ou suggère une alternative.

(depuis C++26)

Si la fonction est surchargée, la résolution de surcharge a lieu en premier, et le programme n'est mal formé que si la fonction supprimée a été sélectionnée :

struct T
{
    void* operator new(std::size_t) = delete;
    void* operator new[](std::size_t) = delete("new[] is deleted"); // depuis C++26
};

T* p = new T;    // Erreur : tente d'appeler T::operator new supprimé
T* p = new T[5]; // Erreur : tente d'appeler T::operator new[] supprimé,
                 //        émet un message de diagnostic « new[] is deleted »

La définition supprimée d'une fonction doit être la première déclaration dans une unité de traduction : une fonction déclarée précédemment ne peut pas être redéclarée comme supprimée :

struct T { T(); };
T::T() = delete; // Erreur : doit être supprimé dès la première déclaration

Fonctions fournies par l'utilisateur

Une fonction est fournie par l'utilisateur si elle est déclarée par l'utilisateur et n'est ni explicitement défaut ni supprimée à sa première déclaration. Une fonction explicitement défaut fournie par l'utilisateur (c'est-à-dire explicitement défaut après sa première déclaration) est définie au point où elle est explicitement défaut ; si une telle fonction est implicitement définie comme supprimée, le programme est mal formé. Déclarer une fonction comme défaut après sa première déclaration peut assurer une exécution efficace et une définition concise, tout en permettant une interface binaire stable pour une base de code évolutive.

// Toutes les fonctions membres spéciales de « trivial » sont
// par défaut à leurs premières déclarations respectives,
// elles ne sont pas fournies par l'utilisateur
struct trivial
{
    trivial() = default;
    trivial(const trivial&) = default;
    trivial(trivial&&) = default;
    trivial& operator=(const trivial&) = default;
    trivial& operator=(trivial&&) = default;
    ~trivial() = default;
};

struct nontrivial
{
    nontrivial(); // première déclaration
};

// non défini par défaut à la première déclaration,
// il est fourni par l'utilisateur et est défini ici
nontrivial::nontrivial() = default;

Résolution d'ambiguïté

En cas d'ambiguïté entre un corps de fonction et un initialisateur commençant par {ou = (depuis C++26), l'ambiguïté est levée en vérifiant le type de l'identificateur de déclarateur de noptr-declarator ﻿:

  • Si le type est un type de fonction, la séquence de jetons ambiguë est traitée comme un corps de fonction.
  • Sinon, la séquence de jetons ambiguë est traitée comme un initialisateur.
using T = void(); // type de fonction
using U = int;    // type non fonction

T a{}; // définit une fonction ne faisant rien
U b{}; // initialise par valeur un objet int

T c = delete("hello"); // définit une fonction comme supprimée
U d = delete("hello"); // initialise par copie un objet int avec
                       // le résultat d'une expression delete (mal formé)

func

Dans le corps de la fonction, la variable prédéfinie locale à la fonction __func__ est définie comme si par

static const char __func__[] = "function-name";

Cette variable a une portée de bloc et une durée de stockage statique :

struct S
{
    S(): s(__func__) {} // OK : initializer-list fait partie du corps de la fonction
    const char* s;
};
void f(const char* s = __func__); // Error : parameter-list fait partie du déclarateur

#include <iostream>

void Foo() { std::cout << __func__ << ' '; }

struct Bar
{
    Bar() { std::cout << __func__ << ' '; }
    ~Bar() { std::cout << __func__ << ' '; }
    struct Pub { Pub() { std::cout << __func__ << ' '; } };
};

int main()
{
    Foo();
    Bar bar;
    Bar::Pub pub;
}

Sortie possible :

Foo Bar Pub ~Bar

(depuis C++11)

En cas d'ambiguïté entre une déclaration de variable utilisant la syntaxe d'initialisation directe et une déclaration de fonction, le compilateur choisit toujours la déclaration de fonction ; voir initialisation directe.

#include <iostream>
#include <string>

// fonction simple avec un argument par défaut, ne retournant rien

{
    std::cout << "Hello, " << arg << '\n';
}

// (la définition est fournie plus loin)

// fonction retournant un pointeur vers f0, style antérieur à C++11
void (*fp03())(const std::string&)
{
    return f0;
}

// fonction retournant un pointeur vers f0, avec type de retour final de C++11
auto fp11() -> void(*)(const std::string&)
{
    return f0;
}

int main()
{
    f0();
    fp03()("test!");
    fp11()("again!");
    int f2(std::string) noexcept; // déclaration en portée de fonction
    std::cout << "f2(\"bad\"): " << f2("bad") << '\n';
    std::cout << "f2(\"42\"): " << f2("42") << '\n';
}

// fonction simple non membre retournant int
int f1()
{
    return 007;
}

{
    return std::stoi(str);
}
catch (const std::exception& e)
{

    return 0;

    ("reason")
#   endif
