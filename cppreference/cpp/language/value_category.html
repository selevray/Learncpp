Catégories de valeurs

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Chaque expression C++ (un opérateur avec ses opérandes, un littéral, un nom de variable, etc.) est caractérisée par deux propriétés indépendantes : un type et une catégorie de valeur. Chaque expression a un type qui n'est pas une référence, et chaque expression appartient à exactement une des trois catégories de valeurs primaires : prvalue, xvalue et lvalue.

  • une glvalue (lvalue « généralisée ») est une expression dont l'évaluation détermine l'identité d'un objet ou d'une fonction ;

  • une prvalue (rvalue « pure ») est une expression dont l'évaluation

    • calcule la valeur d'un opérande d'un opérateur intégré (une telle prvalue n'a pas d'objet résultat), ou
    • initialise un objet (une telle prvalue est dite avoir un objet résultat). L'objet résultat peut être une variable, un objet créé par une expression new, un temporaire créé par matérialisation temporaire, ou un membre de celui-ci. Notez que les expressions à valeur ignorée non void ont un objet résultat (le temporaire matérialisé). De plus, toute prvalue de classe ou de tableau a un objet résultat, sauf lorsqu'elle est l'opérande de decltype ;

  • une xvalue (valeur « expirante ») est une glvalue qui désigne un objet dont les ressources peuvent être réutilisées ;

  • une lvalue est une glvalue qui n'est pas une xvalue ;

Contenu étendu

Ainsi nommée historiquement, car les lvalues pouvaient apparaître à gauche d'une expression d'affectation. En général, ce n'est pas toujours le cas :

void foo();

void baz()
{
    int a; // L'expression `a` est une lvalue
    a = 4; // OK, peut apparaître à gauche d'une expression d'affectation

    int &b{a}; // L'expression `b` est une lvalue
    b = 5; // OK, peut apparaître à gauche d'une expression d'affectation

    const int &c{a}; // L'expression `c` est une lvalue
    c = 6;           // mal formé, affectation d'une référence en lecture seule

    // L'expression `foo` est une lvalue
    // l'adresse peut être prise par l'opérateur d'adresse intégré
    void (*p)() = &foo;

    foo = baz; // mal formé, affectation d'une fonction
}
  • une rvalue est une prvalue ou une xvalue ;

Contenu étendu

Ainsi nommée historiquement, car les rvalues pouvaient apparaître à droite d'une expression d'affectation. En général, ce n'est pas toujours le cas :

#include <iostream>

struct S
{
    S() : m{42} {}
    S(int a) : m{a} {}
    int m;
};

int main()
{
    S s;

    // L'expression `S{}` est une prvalue
    // Peut apparaître à droite d'une expression d'affectation
    s = S{};

    std::cout << s.m << '\n';

    // L'expression `S{}` est une prvalue
    // Peut aussi être utilisée à gauche
    std::cout << (S{} = S{7}).m << '\n';
}

Output:

42
7

Remarque : cette taxonomie a subi des changements importants au fil des révisions de la norme C++, voir Historique ci-dessous pour plus de détails.

Contenu étendu

Malgré leurs noms, ces termes classent des expressions, et non des valeurs.

#include <type_traits>
#include <utility>

template <class T> struct is_prvalue : std::true_type {};
template <class T> struct is_prvalue<T&> : std::false_type {};
template <class T> struct is_prvalue<T&&> : std::false_type {};

template <class T> struct is_lvalue : std::false_type {};
template <class T> struct is_lvalue<T&> : std::true_type {};
template <class T> struct is_lvalue<T&&> : std::false_type {};

template <class T> struct is_xvalue : std::false_type {};
template <class T> struct is_xvalue<T&> : std::false_type {};
template <class T> struct is_xvalue<T&&> : std::true_type {};

int main()
{
    int a{42};
    int& b{a};
    int&& r{std::move(a)};

    // L'expression `42` est une prvalue
    static_assert(is_prvalue<decltype((42))>::value);

    // L'expression `a` est une lvalue
    static_assert(is_lvalue<decltype((a))>::value);

    // L'expression `b` est une lvalue
    static_assert(is_lvalue<decltype((b))>::value);

    // L'expression `std::move(a)` est une xvalue
    static_assert(is_xvalue<decltype((std::move(a)))>::value);

    // Le type de la variable `r` est une référence rvalue
    static_assert(std::is_rvalue_reference<decltype(r)>::value);

    // Le type de la variable `b` est une référence lvalue
    static_assert(std::is_lvalue_reference<decltype(b)>::value);

    // L'expression `r` est une lvalue
    static_assert(is_lvalue<decltype((r))>::value);
}

Catégories principales

lvalue

Les expressions suivantes sont des expressions lvalue :

  • le nom d'une variable, d'une fonction, d'un objet de paramètre de modèle (depuis C++20), ou d'un membre de données, quel que soit son type, comme std::cin ou std::endl. Même si le type de la variable est une référence rvalue, l'expression constituée de son nom est une expression lvalue (voir toutefois Expressions éligibles au déplacement) ;

Contenu étendu

void foo() {}

void baz()
{
    // `foo` est une lvalue
    // l'adresse peut être prise par l'opérateur d'adresse intégré
    void (*p)() = &foo;
}

struct foo {};

template <foo a>
void baz()
{
    const foo* obj = &a;  // `a` est une lvalue, objet de paramètre de modèle
}
  • un appel de fonction ou une expression d'opérateur surchargé, dont le type de retour est une référence lvalue, comme std::getline(std::cin, str), std::cout << 1, str1 = str2 ou ++it ;

Contenu étendu

int& a_ref()
{
    static int a{3};
    return a;
}

void foo()
{
    a_ref() = 5;  // `a_ref()` est une lvalue, appel de fonction dont le type de retour est une référence lvalue
}
  • a = b, a += b, a %= b, et toutes les autres expressions d'affectation et d'affectation composée intégrées ;
  • ++a et --a, les expressions d'incrémentation et de décrémentation préfixes intégrées ;
  • *p, l'expression d'indirection intégrée ;
  • a[n] et p[n], les expressions d'indexation intégrées, où l'un des opérandes de a[n] est une lvalue de tableau (depuis C++11) ;
  • a.m, l'expression d'membre d'objet, sauf lorsque m est un énumérateur de membre ou une fonction membre non statique, ou lorsque a est une rvalue et m est un membre de données non statique de type objet ;

Contenu étendu

struct foo
{
    enum bar
    {
        m // énumérateur membre
    };
};

void baz()
{
    foo a;
    a.m = 42; // mal formé, une lvalue est requise comme opérande de gauche de l'affectation
}

struct foo
{
    void m() {} // fonction membre non statique
};

void baz()
{
    foo a;

    // `a.m` est une prvalue, donc l'adresse ne peut pas être prise par l'opérateur intégré
    // opérateur d'adresse
    void (foo::*p1)() = &a.m; // mal formé

    void (foo::*p2)() = &foo::m; // OK : pointeur vers fonction membre
}

struct foo
{
    static void m() {} // fonction membre statique
};

void baz()
{
    foo a;
    void (*p1)() = &a.m;     // `a.m` est une lvalue
    void (*p2)() = &foo::m;  // idem
}
  • p->m, l'expression intégrée de membre de pointeur, sauf lorsque m est un énumérateur de membre ou une fonction membre non statique ;
  • a.*mp, l'expression de pointeur vers membre d'objet, où a est une lvalue et mp est un pointeur vers membre de données ;
  • p->*mp, l'expression intégrée de pointeur vers membre de pointeur, où mp est un pointeur vers membre de données ;
  • a, b, l'expression intégrée d'opérateur virgule, où b est une lvalue ;
  • a ? b : c, l'expression conditionnelle ternaire pour certains b et c (par exemple lorsque les deux sont des lvalues de même type, mais voir la définition pour plus de détails) ;
  • un littéral de chaîne, comme "Hello, world!" ;
  • une expression de conversion vers un type référence lvalue, comme static_cast<int&>(x) ou static_cast<void(&)(int)>(x) ;
  • un paramètre de modèle non de type, de type référence lvalue ;
template <int& v>
void set()
{
    v = 5; // le paramètre de modèle est une lvalue
}

int a{3}; // variable statique, adresse fixe connue à la compilation

void foo()
{
    set<a>();
}
  • un appel de fonction ou une expression d'opérateur surchargé, dont le type de retour est une référence rvalue vers fonction ;
  • une expression de conversion vers un type référence rvalue vers fonction, comme static_cast<void(&&)(int)>(x).

(depuis C++11)

Properties:

  • Identique à glvalue (ci-dessous).
  • L'adresse d'une lvalue peut être obtenue par l'opérateur d'adresse intégré : &++i[1] et &std::endl sont des expressions valides.
  • Une lvalue modifiable peut être utilisée comme opérande gauche des opérateurs d'affectation et d'affectation composée intégrés.
  • Une lvalue peut être utilisée pour initialiser une référence lvalue ; cela associe un nouveau nom à l'objet identifié par l'expression.

prvalue

Les expressions suivantes sont des expressions prvalue :

  • un littéral (à l'exception du littéral de chaîne), comme 42, true ou nullptr ;
  • un appel de fonction ou une expression d'opérateur surchargé, dont le type de retour n'est pas une référence, comme str.substr(1, 2), str1 + str2 ou it++ ;
  • a++ et a--, les expressions d'incrémentation et de décrémentation postfixes intégrées ;
  • a + b, a % b, a & b, a << b, et toutes les autres expressions arithmétiques intégrées ;
  • a && b, a || b, !a, les expressions logiques intégrées ;
  • a < b, a == b, a >= b, et toutes les autres expressions de comparaison intégrées ;
  • &a, l'expression d'adresse de intégrée ;
  • a.m, l'expression de membre d'objet, où m est un énumérateur de membre ou une fonction membre non statique[2] ;
  • p->m, l'expression intégrée de membre de pointeur, où m est un énumérateur de membre ou une fonction membre non statique[2] ;
  • a.*mp, l'expression de pointeur vers membre d'objet, où mp est un pointeur vers fonction membre[2] ;
  • p->*mp, l'expression intégrée de pointeur vers membre de pointeur, où mp est un pointeur vers fonction membre[2] ;
  • a, b, l'expression intégrée d'opérateur virgule, où b est une prvalue ;
  • a ? b : c, l'expression conditionnelle ternaire pour certains b et c (voir la définition pour plus de détails) ;
  • une expression de conversion vers un type non référence, comme static_cast<double>(x), std::string{} ou (int)42 ;
  • le pointeur this ;
  • un énumérateur ;
  • un paramètre de modèle non de type, de type scalaire ;
template <int v>
void foo()
{
    // pas une lvalue, `v` est un paramètre de modèle de type scalaire int
    const int* a = &v; // mal formé

    v = 3; // mal formé : une lvalue est requise comme opérande de gauche de l'affectation
}
  • une expression lambda, comme [](int x){ return x * x; } ;

(depuis C++11)

  • une expression requires, comme requires (T i) { typename T::type; } ;
  • une spécialisation d'un concept, comme std::equality_comparable<int>.

(depuis C++20)

Properties:

  • Identique à rvalue (ci-dessous).
  • Une prvalue ne peut pas être polymorphe : le type dynamique de l'objet qu'elle désigne est toujours le type de l'expression.
  • Une prvalue qui n'est ni de type classe ni de type tableau ne peut pas être qualifiée cv, sauf si elle est matérialisée afin d'être liée à une référence vers un type qualifié cv (depuis C++17). (Remarque : un appel de fonction ou une expression de conversion peut produire une prvalue de type non classe qualifiée cv, mais le qualificateur cv est généralement supprimé immédiatement.)
  • Une prvalue ne peut pas avoir de type incomplet (sauf pour le type void, voir ci-dessous, ou lorsqu'elle est utilisée dans le spécificateur decltype).
  • Une prvalue ne peut pas avoir un type classe abstrait ni un tableau de tels types.

xvalue

Les expressions suivantes sont des expressions xvalue :

  • a.m, l'expression de membre d'objet, où a est une rvalue et m est un membre de données non statique de type objet ;
  • a.*mp, l'expression de pointeur vers membre d'objet, où a est une rvalue et mp est un pointeur vers membre de données ;
  • a, b, l'expression intégrée d'opérateur virgule, où b est une xvalue ;
  • a ? b : c, l'expression conditionnelle ternaire pour certains b et c (voir la définition pour plus de détails) ;
  • un appel de fonction ou une expression d'opérateur surchargé, dont le type de retour est une référence rvalue vers objet, comme std::move(x) ;
  • a[n], l'expression d'indexation intégrée, où l'un des opérandes est une rvalue de tableau ;
  • une expression de conversion vers un type référence rvalue vers type objet, comme static_cast<char&&>(x) ;

(depuis C++11)

  • toute expression désignant un objet temporaire, après matérialisation temporaire ;

(depuis C++17)

  • une expression éligible au déplacement.

(depuis C++23)

Properties:

  • Identique à rvalue (ci-dessous).
  • Identique à glvalue (ci-dessous).

En particulier, comme toutes les rvalues, les xvalues se lient aux références rvalue, et comme toutes les glvalues, les xvalues peuvent être polymorphes, et les xvalues de type non classe peuvent être qualifiées cv.

Contenu étendu

#include <type_traits>

template <class T> struct is_prvalue : std::true_type {};
template <class T> struct is_prvalue<T&> : std::false_type {};
template <class T> struct is_prvalue<T&&> : std::false_type {};

template <class T> struct is_lvalue : std::false_type {};
template <class T> struct is_lvalue<T&> : std::true_type {};
template <class T> struct is_lvalue<T&&> : std::false_type {};

template <class T> struct is_xvalue : std::false_type {};
template <class T> struct is_xvalue<T&> : std::false_type {};
template <class T> struct is_xvalue<T&&> : std::true_type {};

// Exemple tiré de la norme C++23 : 7.2.1 Catégorie de valeur [basic.lval]
struct A
{
    int m;
};

A&& operator+(A, A);
A&& f();

int main()
{
    A a;
    A&& ar = static_cast<A&&>(a);

    // Un appel de fonction dont le type de retour est une référence rvalue est une xvalue
    static_assert(is_xvalue<decltype( (f()) )>::value);

    // Membre d'une expression objet, l'objet est une xvalue, `m` est un membre de donnée non statique
    static_assert(is_xvalue<decltype( (f().m) )>::value);

    // Une expression de conversion vers une référence rvalue
    static_assert(is_xvalue<decltype( (static_cast<A&&>(a)) )>::value);

    // Expression d'opérateur, dont le type de retour est une référence rvalue vers un objet
    static_assert(is_xvalue<decltype( (a + a) )>::value);

    // L'expression `ar` est une lvalue, `&ar` est valide
    static_assert(is_lvalue<decltype( (ar) )>::value);
    [[maybe_unused]] A* ap = &ar;
}

Catégories mixtes

glvalue

Une expression glvalue est soit une lvalue, soit une xvalue.

Properties:

  • Une glvalue peut être implicitement convertie en prvalue par une conversion implicite lvalue-vers-rvalue, tableau-vers-pointeur ou fonction-vers-pointeur.
  • Une glvalue peut être polymorphe : le type dynamique de l'objet qu'elle identifie n'est pas nécessairement le type statique de l'expression.
  • Une glvalue peut avoir un type incomplet, lorsque l'expression le permet.

rvalue

Une expression rvalue est soit une prvalue, soit une xvalue.

Properties:

  • L'adresse d'une rvalue ne peut pas être obtenue par l'opérateur d'adresse intégré : &int(), &i++[3], &42 et &std::move(x) sont invalides.
  • Une rvalue ne peut pas être utilisée comme opérande gauche des opérateurs d'affectation et d'affectation composée intégrés.
  • Une rvalue peut être utilisée pour initialiser une référence lvalue const, auquel cas la durée de vie de l'objet temporaire identifié par la rvalue est prolongée jusqu'à la fin de la portée de la référence.
  • Une rvalue peut être utilisée pour initialiser une référence rvalue, auquel cas la durée de vie de l'objet temporaire identifié par la rvalue est prolongée jusqu'à la fin de la portée de la référence.
  • Lorsqu'elle est utilisée comme argument de fonction et que deux surcharges de la fonction sont disponibles, l'une prenant un paramètre référence rvalue et l'autre un paramètre référence lvalue vers const, une rvalue se lie à la surcharge à référence rvalue (ainsi, si les constructeurs de copie et de déplacement sont tous deux disponibles, un argument rvalue invoque le constructeur de déplacement, et de même avec les opérateurs d'affectation par copie et par déplacement).

(depuis C++11)

Catégories spéciales

Appel de fonction membre en attente

Les expressions a.mf et p->mf, où mf est une fonction membre non statique, ainsi que les expressions a.*pmf et p->*pmf, où pmf est un pointeur vers fonction membre, sont classées comme expressions prvalues, mais elles ne peuvent pas servir à initialiser des références, comme arguments de fonction, ni à aucune autre fin, sauf comme argument de gauche de l'opérateur d'appel de fonction, par exemple (p->*pmf)(args).

Expressions void

Les expressions d'appel de fonction renvoyant void, les expressions de conversion vers void et les expressions throw sont classées comme expressions prvalues, mais elles ne peuvent pas servir à initialiser des références ni comme arguments de fonction. Elles peuvent être utilisées dans des contextes de valeur ignorée (par exemple seules sur une ligne, comme opérande de gauche de l'opérateur virgule, etc.) et dans l'instruction return d'une fonction renvoyant void. De plus, les expressions throw peuvent être utilisées comme deuxième et troisième opérandes de l'opérateur conditionnel ?:.

Les expressions void n'ont pas d'objet résultat.

(depuis C++17)

Champs de bits

Une expression désignant un champ de bits (par exemple a.m, où a est une lvalue de type struct A { int m: 3; }) est une expression glvalue : elle peut être utilisée comme opérande de gauche de l'opérateur d'affectation, mais son adresse ne peut pas être prise et une référence lvalue non const ne peut pas lui être liée. Une référence lvalue const ou une référence rvalue peut être initialisée à partir d'un glvalue de champ de bits, mais une copie temporaire du champ de bits sera créée : elle ne se lie pas directement au champ de bits.

Expressions éligibles au déplacement

Bien qu'une expression constituée du nom d'une variable quelconque soit une expression lvalue, une telle expression peut être éligible au déplacement si elle apparaît comme opérande de

  • une instruction return
  • une instruction co_return (depuis C++20)
  • une expression throw (depuis C++17)

Si une expression est éligible au déplacement, elle est traitée [soit comme une rvalue, soit comme une lvalue (jusqu'à C++23) | comme une rvalue (depuis C++23)] pour les besoins de la résolution de surcharge (elle peut ainsi sélectionner le constructeur de déplacement). Voir Déplacement automatique des variables locales et des paramètres pour plus de détails.

(depuis C++11)

Historique

CPL

Le langage de programmation CPL a été le premier à introduire les catégories de valeurs pour les expressions : toutes les expressions CPL peuvent être évaluées en « mode droit », mais seuls certains types d'expressions ont un sens en « mode gauche ». En mode droit, une expression est considérée comme une règle de calcul d'une valeur (la valeur droite, ou rvalue). En mode gauche, une expression donne effectivement une adresse (la valeur gauche, ou lvalue). « Gauche » et « droit » désignaient ici « à gauche de l'affectation » et « à droite de l'affectation ».

C

Le langage de programmation C a suivi une taxonomie similaire, à ceci près que le rôle de l'affectation n'était plus significatif : les expressions C se répartissent entre « expressions lvalue » et les autres (fonctions et valeurs non objets), où « lvalue » désigne une expression qui identifie un objet, une « valeur de localisation »[4].

C++98

Le C++ antérieur à 2011 suivait le modèle du C, mais rétablissait le nom « rvalue » pour les expressions non lvalue, faisait des fonctions des lvalues, et ajoutait la règle selon laquelle les références peuvent se lier à des lvalues, mais seules les références const peuvent se lier à des rvalues. Plusieurs expressions C non lvalue sont devenues des expressions lvalue en C++.

C++11

Avec l'introduction de la sémantique de déplacement en C++11, les catégories de valeurs ont été redéfinies pour caractériser deux propriétés indépendantes des expressions[5] :

  • possède une identité : il est possible de déterminer si l'expression désigne la même entité qu'une autre expression, par exemple en comparant les adresses des objets ou des fonctions qu'elles identifient (obtenues directement ou indirectement) ;
  • peut être déplacée : un constructeur de déplacement, un opérateur d'affectation par déplacement, ou une autre surcharge de fonction implémentant la sémantique de déplacement peut se lier à l'expression.

En C++11, les expressions qui :

  • possèdent une identité et ne peuvent pas être déplacées sont appelées expressions lvalue ;
  • possèdent une identité et peuvent être déplacées sont appelées expressions xvalue ;
  • ne possèdent pas d'identité et peuvent être déplacées sont appelées expressions prvalue (« rvalue pure ») ;
  • ne possèdent pas d'identité et ne peuvent pas être déplacées ne sont pas utilisées[6].

Les expressions qui possèdent une identité sont appelées « expressions glvalue » (glvalue signifie « lvalue généralisée »). Les lvalues et les xvalues sont toutes deux des expressions glvalue.

Les expressions dont on peut déplacer la valeur sont appelées « expressions rvalue ». Les prvalues et les xvalues sont toutes deux des expressions rvalue.

C++17

En C++17, l'élision de copie est devenue obligatoire dans certaines situations, ce qui a nécessité de séparer les expressions prvalues des objets temporaires qu'elles initialisent, aboutissant au système actuel. Notons que, contrairement au schéma C++11, les prvalues ne sont plus déplacées.
