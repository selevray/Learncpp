surcharge d'opérateurs

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Personnalise les opérateurs C++ pour les opérandes de types définis par l'utilisateur.

Syntaxe

Les fonctions opérateurs sont des fonctions dont les noms sont particuliers :

| | | | operator op | (1) | | | | operator new operator new [] | (2) | | | | operator delete operator delete [] | (3) | | | | operator co_await | (4) | (depuis C++20) | |

  • op — l'un quelconque des opérateurs suivants :+ - * / % ^ & | ~ ! = < > += -= *= /= %= ^= &= |= << >> >>= <<= == != <= >= <=> (depuis C++20) && || ++ -- , ->* -> () []

  1. Un opérateur de ponctuation surchargé.

  2. Une fonction d'allocation.

  3. Une fonction de désallocation.

  4. Un opérateur co_await surchargé destiné à être utilisé dans des co_await expressions.

Le comportement des opérateurs autres que de ponctuation est décrit sur leurs pages respectives. Sauf indication contraire, le reste de la description de cette page ne s'applique pas à ces fonctions.

Explication

Lorsqu'un opérateur apparaît dans une expression, et qu'au moins l'un de ses opérandes a un type classe ou un type énumération, alors la résolution de surcharge sert à déterminer la fonction définie par l'utilisateur à appeler parmi toutes les fonctions dont les signatures correspondent à ce qui suit :

Expression | En tant que fonction membre | En tant que fonction non membre | Exemple

@a | (a).operator@ ( ) | operator@ (a) | !std::cin appelle std::cin.operator!()

a@b | (a).operator@ (b) | operator@ (a, b) | std::cout << 42 appelle std::cout.operator<<(42)

a=b | (a).operator= (b) | ne peut pas être non membre | Étant donné std::string s;, s = "abc"; appelle s.operator=("abc")

a(b...) | (a).operator()(b...) | ne peut pas être non membre | Étant donné std::random_device r;, auto n = r(); appelle r.operator()()

a[b...] | (a).operator | ne peut pas être non membre | Étant donné std::map<int, int> m;, m[1] = 2; appelle m.operator[](1)

a-> | (a).operator->( ) | ne peut pas être non membre | Étant donné std::unique_ptr<S> p;, p->bar() appelle p.operator->()

a@ | (a).operator@ (0) | operator@ (a, 0) | Étant donné std::vector<int>::iterator i;, i++ appelle i.operator++(0)

Dans ce tableau, @ est un marqueur représentant tous les opérateurs correspondants : tous les opérateurs préfixes dans @a, tous les opérateurs postfixes autres que -> dans a@, tous les opérateurs infixes autres que = dans a@b.

De plus, pour les opérateurs de comparaison ==, !=, <, >, <=, >=, <=>, la résolution de surcharge considère aussi les candidats réécrits operator== ou operator<=>.

(depuis C++20)

Les opérateurs surchargés (mais pas les opérateurs intégrés) peuvent être appelés en utilisant la notation fonctionnelle :

std::string str = "Hello, ";
str.operator+=("world");                      // équivalent à str += "world";
operator<<(operator<<(std::cout, str), '\n'); // équivalent à std::cout << str << '\n';
                                              // (depuis C++17) sauf pour le séquencement

Opérateurs surchargés statiques

Les opérateurs surchargés qui sont des fonctions membres peuvent être déclarés static. Cependant, cela n'est autorisé que pour operator() et operator[].

De tels opérateurs peuvent être appelés en utilisant la notation fonctionnelle. Toutefois, lorsque ces opérateurs apparaissent dans des expressions, ils nécessitent toujours un objet de type classe.

struct SwapThem
{
    template<typename T>
    static void operator()(T& lhs, T& rhs)
    {
        std::ranges::swap(lhs, rhs);
    }

    template<typename T>
    static void operator[](T& lhs, T& rhs)
    {
        std::ranges::swap(lhs, rhs);
    }
};
inline constexpr SwapThem swap_them{};

void foo()
{
    int a = 1, b = 2;

    swap_them(a, b); // OK
    swap_them[a, b]; // OK

    SwapThem{}(a, b); // OK
    SwapThem{}[a, b]; // OK

    SwapThem::operator()(a, b); // OK
    SwapThem::operator[](a, b); // OK

    SwapThem(a, b); // erreur, construction invalide
    SwapThem[a, b]; // error
}

(depuis C++23)

Restrictions

  • Une fonction opérateur doit avoir au moins un paramètre de fonction ou un paramètre objet implicite dont le type est une classe, une référence à une classe, une énumération ou une référence à une énumération.
  • Les opérateurs :: (résolution de portée), . (accès membre), .* (accès membre via pointeur vers membre) et ?: (conditionnel ternaire) ne peuvent pas être surchargés.
  • De nouveaux opérateurs tels que **, <> ou &| ne peuvent pas être créés.
  • Il n'est pas possible de modifier la priorité, le regroupement ou le nombre d'opérandes des opérateurs.
  • La surcharge de l'opérateur -> doit soit renvoyer un pointeur brut, soit renvoyer un objet (par référence ou par valeur) pour lequel l'opérateur -> est à son tour surchargé.
  • Les surcharges des opérateurs && et || perdent l'évaluation en court-circuit.
  • &&, || et , perdent leurs propriétés de séquencement particulières lorsqu'ils sont surchargés et se comportent comme des appels de fonction ordinaires, même lorsqu'ils sont utilisés sans la notation d'appel de fonction.

(jusqu'à C++17)

Implémentations canoniques

Outre les restrictions ci-dessus, le langage n'impose aucune autre contrainte sur ce que font les opérateurs surchargés, ni sur le type de retour (il ne participe pas à la résolution de surcharge), mais en général, les opérateurs surchargés doivent se comporter aussi semblablement que possible aux opérateurs intégrés : operator+ doit additionner, plutôt que multiplier ses arguments, operator= doit affecter, etc. Les opérateurs apparentés doivent se comporter de façon similaire (operator+ et operator+= effectuent la même opération de type addition). Les types de retour sont limités par les expressions dans lesquelles l'opérateur doit être utilisé : par exemple, les opérateurs d'affectation renvoient par référence pour permettre d'écrire a = b = c = d, ce que permettent les opérateurs intégrés.

Les surcharges d'opérateurs couramment utilisées ont les formes canoniques typiques suivantes :[1]

Opérateur d'affectation

L'opérateur d'affectation operator= possède des propriétés particulières : voir affectation par copie et affectation par déplacement pour plus de détails.

L'opérateur d'affectation par copie canonique doit être sûr en cas d'auto-affectation, et renvoyer le membre gauche par référence :

// affectation par copie
T& operator=(const T& other)
{
    // Protéger contre l'auto-affectation
    if (this == &other)
        return *this;

    // supposons que *this gère une ressource réutilisable, comme un tampon alloué sur le tas mArray
    if (size != other.size)           // la ressource de *this ne peut pas être réutilisée
    {
        temp = new int[other.size];   // alloue la ressource ; en cas d'exception, ne fait rien
        delete[] mArray;              // libérer la ressource de *this
        mArray = temp;
        size = other.size;
    }

    std::copy(other.mArray, other.mArray + other.size, mArray);
    return *this;
}

L'affectation par déplacement canonique doit laisser l'objet déplacé dans un état valide (c'est-à-dire un état dont les invariants de classe sont préservés), et soit ne rien faire, soit au moins laisser l'objet dans un état valide en cas d'auto-affectation, renvoyer le membre gauche par référence vers un objet non const, et être noexcept :

// affectation par déplacement
T& operator=(T&& other) noexcept
{
    // Protéger contre l'auto-affectation
    if (this == &other)
        return *this; // delete[]/size=0 serait également acceptable

    delete[] mArray;                               // libérer la ressource de *this
    mArray = std::exchange(other.mArray, nullptr); // laisser other dans un état valide
    size = std::exchange(other.size, 0);
    return *this;
}

(depuis C++11)

Dans les situations où l'affectation par copie ne peut pas bénéficier de la réutilisation des ressources (elle ne gère pas de tableau alloué sur le tas et n'a pas de membre (éventuellement transitif) qui en gère un, comme un membre std::vector ou std::string), il existe un raccourci pratique et populaire : l'opérateur d'affectation copie-et-échange, qui prend son paramètre par valeur (fonctionnant ainsi à la fois comme affectation par copie et par déplacement selon la catégorie de valeur de l'argument), échange avec le paramètre, et laisse le destructeur le nettoyer.

// affectation par copie (idiome copy-and-swap)
T& T::operator=(T other) noexcept // appeler le constructeur de copie ou de déplacement pour construire other
{
    std::swap(size, other.size); // échanger les ressources entre *this et other
    std::swap(mArray, other.mArray);
    return *this;
} // le destructeur de other est appelé pour libérer les ressources auparavant gérées par *this

Cette forme fournit automatiquement une garantie forte d'exception, mais interdit la réutilisation des ressources.

Extraction et insertion dans un flux

Les surcharges de operator>> et operator<< qui prennent un std::istream& ou std::ostream& comme argument de gauche sont connues sous le nom d'opérateurs d'insertion et d'extraction. Comme ils prennent le type défini par l'utilisateur comme argument de droite (b dans a @ b), ils doivent être implémentés comme non membres.

std::ostream& operator<<(std::ostream& os, const T& obj)
{
    // écrire obj dans le flux
    return os;
}

std::istream& operator>>(std::istream& is, T& obj)
{
    // lire obj depuis le flux
    if (/* T ne peut pas être construit */)
        is.setstate(std::ios::failbit);
    return is;
}

Ces opérateurs sont parfois implémentés comme des fonctions amies.

Opérateur d'appel de fonction

Lorsqu'une classe définie par l'utilisateur surcharge l'opérateur d'appel de fonction operator(), elle devient un type FunctionObject.

Un objet d'un tel type peut être utilisé dans une expression d'appel de fonction :

// Un objet de ce type représente une fonction linéaire d'une variable a * x + b.
struct Linear
{
    double a, b;

    double operator()(double x) const
    {
        return a * x + b;
    }
};

int main()
{
    Linear f{2, 1};  // Représente la fonction 2x + 1.
    Linear g{-1, 0}; // Représente la fonction -x.
    // f et g sont des objets utilisables comme une fonction.

    double f_0 = f(0);
    double f_1 = f(1);

    double g_0 = g(0);
}

De nombreux algorithmes de la bibliothèque standard acceptent des FunctionObjects pour personnaliser leur comportement. Il n'existe pas de formes canoniques particulièrement notables de operator(), mais pour illustrer l'usage :

#include <algorithm>
#include <iostream>
#include <vector>

struct Sum
{
    int sum = 0;
    void operator()(int n) { sum += n; }
};

int main()
{
    std::vector<int> v = {1, 2, 3, 4, 5};
    Sum s = std::for_each(v.begin(), v.end(), Sum());
    std::cout << "The sum is " << s.sum << '\n';
}

Output:

The sum is 15

Incrémentation et décrémentation

Lorsque l'opérateur d'incrémentation ou de décrémentation postfixé apparaît dans une expression, la fonction définie par l'utilisateur correspondante (operator++ ou operator--) est appelée avec un argument entier 0. Typiquement, elle est déclarée comme T operator++(int) ou T operator--(int), où l'argument est ignoré. Les opérateurs d'incrémentation et de décrémentation postfixés sont généralement implémentés à partir de leurs versions préfixées :

struct X
{
    // incrémentation préfixe
    X& operator++()
    {
        // l'incrémentation effective a lieu ici
        return *this; // renvoyer la nouvelle valeur par référence
    }

    // incrémentation postfixe
    X operator++(int)
    {
        X old = *this; // copier l'ancienne valeur
        operator++();  // incrémentation préfixe
        return old;    // renvoyer l'ancienne valeur
    }

    // décrémentation préfixe
    X& operator--()
    {
        // la décrémentation effective a lieu ici
        return *this; // renvoyer la nouvelle valeur par référence
    }

    // décrémentation postfixe
    X operator--(int)
    {
        X old = *this; // copier l'ancienne valeur
        operator--();  // décrémentation préfixe
        return old;    // renvoyer l'ancienne valeur
    }
};

Bien que les implémentations canoniques des opérateurs d'incrémentation et de décrémentation préfixés renvoient par référence, comme pour toute surcharge d'opérateur, le type de retour est défini par l'utilisateur ; par exemple, les surcharges de ces opérateurs pour std::atomic renvoient par valeur.

Opérateurs arithmétiques binaires

Les opérateurs binaires sont généralement implémentés comme non membres pour préserver la symétrie (par exemple, lors de l'addition d'un nombre complexe et d'un entier, si operator+ est une fonction membre du type complexe, alors seule complex + integer compilerait, et non integer + complex). Comme il existe pour chaque opérateur arithmétique binaire un opérateur d'affectation composée correspondant, les formes canoniques des opérateurs binaires sont implémentées à partir de leurs affectations composées :

class X
{
public:
    X& operator+=(const X& rhs) // affectation composée (n'a pas besoin d'être un membre,
    {                           // mais le plus souvent elle l'est, pour modifier les membres privés)
        /* l'addition de rhs à *this a lieu ici */
        return *this; // renvoyer le résultat par référence
    }

    // les amies définies dans le corps de la classe sont inline et sont masquées pour la recherche non ADL
    friend X operator+(X lhs,        // passer lhs par valeur aide à optimiser les chaînes a+b+c
                       const X& rhs) // sinon, les deux paramètres peuvent être des références const
    {
        lhs += rhs; // réutiliser l'affectation composée
        return lhs; // renvoyer le résultat par valeur (utilise le constructeur de déplacement)
    }
};

Opérateurs de comparaison

Les algorithmes de la bibliothèque standard tels que std::sort et les conteneurs tels que std::set attendent que operator< soit défini, par défaut, pour les types fournis par l'utilisateur, et attendent qu'il implémente un ordre faible strict (satisfaisant ainsi les exigences Compare). Une manière idiomatique d'implémenter un ordre faible strict pour une structure est d'utiliser la comparaison lexicographique fournie par std::tie :

struct Record
{
    std::string name;
    unsigned int floor;
    double weight;

    friend bool operator<(const Record& l, const Record& r)
    {
        return std::tie(l.name, l.floor, l.weight)
             < std::tie(r.name, r.floor, r.weight); // conserver le même ordre
    }
};

En général, une fois que operator< est fourni, les autres opérateurs relationnels sont implémentés à partir de operator<.

inline bool operator< (const X& lhs, const X& rhs) { /* effectuer la comparaison réelle */ }
inline bool operator> (const X& lhs, const X& rhs) { return rhs < lhs; }
inline bool operator<=(const X& lhs, const X& rhs) { return !(lhs > rhs); }
inline bool operator>=(const X& lhs, const X& rhs) { return !(lhs < rhs); }

De même, l'opérateur d'inégalité est généralement implémenté à partir de operator== :

inline bool operator==(const X& lhs, const X& rhs) { /* effectuer la comparaison réelle */ }
inline bool operator!=(const X& lhs, const X& rhs) { return !(lhs == rhs); }

Lorsqu'une comparaison à trois voies (comme std::memcmp ou std::string::compare) est fournie, les six opérateurs de comparaison à deux voies peuvent tous s'exprimer à partir de celle-ci :

inline bool operator==(const X& lhs, const X& rhs) { return cmp(lhs,rhs) == 0; }
inline bool operator!=(const X& lhs, const X& rhs) { return cmp(lhs,rhs) != 0; }
inline bool operator< (const X& lhs, const X& rhs) { return cmp(lhs,rhs) <  0; }
inline bool operator> (const X& lhs, const X& rhs) { return cmp(lhs,rhs) >  0; }
inline bool operator<=(const X& lhs, const X& rhs) { return cmp(lhs,rhs) <= 0; }
inline bool operator>=(const X& lhs, const X& rhs) { return cmp(lhs,rhs) >= 0; }

Opérateur d'indexation de tableau

Les classes définies par l'utilisateur qui fournissent un accès de type tableau permettant la lecture et l'écriture définissent généralement deux surcharges de operator[] : des variantes const et non const :

struct T
{
          value_t& operator[](std::size_t idx)       { return mVector[idx]; }
    const value_t& operator[](std::size_t idx) const { return mVector[idx]; }
};

Alternativement, elles peuvent être exprimées comme un unique modèle de fonction membre utilisant un paramètre objet explicite :

struct T
{
    decltype(auto) operator[](this auto& self, std::size_t idx)
    {
        return self.mVector[idx];
    }
};

(depuis C++23)

Si le type de valeur est connu comme étant un type scalaire, la variante const doit renvoyer par valeur.

Lorsque l'accès direct aux éléments du conteneur n'est pas souhaité ou pas possible, ou pour distinguer l'usage en lvalue c[i] = v; et en rvalue v = c[i];, operator[] peut renvoyer un mandataire. Voir par exemple std::bitset::operator[].

operator[] ne peut prendre qu'un seul indice. Pour fournir une sémantique d'accès à un tableau multidimensionnel, par exemple pour implémenter un accès à un tableau 3D a[i][j][k] = x;, operator[] doit renvoyer une référence vers un plan 2D, qui doit avoir son propre operator[] qui renvoie une référence vers une ligne 1D, qui doit avoir operator[] qui renvoie une référence vers l'élément. Pour éviter cette complexité, certaines bibliothèques choisissent de surcharger operator() à la place, de sorte que les expressions d'accès 3D aient la syntaxe de type Fortran a(i, j, k) = x;.

(jusqu'à C++23)

operator[] peut prendre un nombre quelconque d'indices. Par exemple, un operator[] d'une classe de tableau 3D déclarée comme T& operator[](std::size_t x, std::size_t y, std::size_t z); peut accéder directement aux éléments.

#include <array>
#include <cassert>
#include <iostream>

template<typename T, std::size_t Z, std::size_t Y, std::size_t X>
struct Array3d
{
    std::array<T, X * Y * Z> m{};

    constexpr T& operator[](std::size_t z, std::size_t y, std::size_t x) // C++23
    {
        assert(x < X and y < Y and z < Z);
        return m[z * Y * X + y * X + x];
    }
};

int main()
{
    Array3d<int, 4, 3, 2> v;
    v[3, 2, 1] = 42;
    std::cout << "v[3, 2, 1] = " << v[3, 2, 1] << '\n';
}

Output:

v[3, 2, 1] = 42

(depuis C++23)

Opérateurs arithmétiques binaires sur bits

Les classes et énumérations définies par l'utilisateur qui implémentent les exigences de BitmaskType doivent surcharger les opérateurs arithmétiques binaires sur bits operator&, operator|, operator^, operator~, operator&=, operator|= et operator^=, et peuvent facultativement surcharger les opérateurs de décalage operator<< operator>>, operator>>= et operator<<=. Les implémentations canoniques suivent généralement le schéma des opérateurs arithmétiques binaires décrit ci-dessus.

Opérateur de négation booléenne

L'opérateur operator! est couramment surchargé par les classes définies par l'utilisateur destinées à être utilisées dans des contextes booléens. Ces classes fournissent également une fonction de conversion définie par l'utilisateur vers le type booléen (voir std::basic_ios pour l'exemple de la bibliothèque standard), et le comportement attendu de operator! est de renvoyer la valeur opposée à celle de operator bool.

(jusqu'à C++11)

Comme l'opérateur natif ! effectue une conversion contextuelle vers bool, les classes définies par l'utilisateur destinées à être utilisées dans des contextes booléens peuvent fournir uniquement operator bool et n'ont pas besoin de surcharger operator!.

(depuis C++11)

Opérateurs rarement surchargés

Les opérateurs suivants sont rarement surchargés :

  • L'opérateur d'adresse, operator&. Si l'opérateur unaire & est appliqué à une lvalue de type incomplet et que le type complet déclare une operator& surchargée, il n'est pas spécifié si l'opérateur a la signification native ou si la fonction opérateur est appelée. Comme cet opérateur peut être surchargé, les bibliothèques génériques utilisent std::addressof pour obtenir les adresses des objets de types définis par l'utilisateur. L'exemple le plus connu d'une operator& surchargée canonique est la classe Microsoft CComPtrBase. Un exemple d'utilisation de cet opérateur dans un EDSL se trouve dans boost.spirit.
  • Les opérateurs logiques booléens, operator&& et operator||. Contrairement aux versions natives, les surcharges ne peuvent pas implémenter l'évaluation court-circuitée.Contrairement aux versions natives également, elles ne séquencent pas leur opérande gauche avant l'opérande droit. (jusqu'à C++17) Dans la bibliothèque standard, ces opérateurs ne sont surchargés que pour std::valarray.
  • L'opérateur virgule, operator,. Contrairement à la version native, les surcharges ne séquencent pas leur opérande gauche avant l'opérande droit. (jusqu'à C++17) Comme cet opérateur peut être surchargé, les bibliothèques génériques utilisent des expressions telles que a, void(), b au lieu de a, b pour séquencer l'exécution d'expressions de types définis par l'utilisateur. La bibliothèque Boost utilise operator, dans boost.assign, boost.spirit et d'autres bibliothèques. La bibliothèque d'accès aux bases de données SOCI surcharge également operator,.
  • L'accès membre via pointeur vers membre operator->*. La surcharge de cet opérateur n'a pas d'inconvénient spécifique, mais il est rarement utilisé en pratique. Il a été suggéré qu'il puisse faire partie d'une interface de pointeur intelligent, et il est d'ailleurs utilisé dans ce rôle par les acteurs de boost.phoenix. Il est plus courant dans des EDSL comme cpp.react.

Exemple

#include <iostream>

class Fraction
{
    // ou std::gcd de C++17
    constexpr int gcd(int a, int b) { return b == 0 ? a : gcd(b, a % b); }

    int n, d;
public:
    constexpr Fraction(int n, int d = 1) : n(n / gcd(n, d)), d(d / gcd(n, d)) {}

    constexpr int num() const { return n; }
    constexpr int den() const { return d; }

    constexpr Fraction& operator*=(const Fraction& rhs)
    {
        int new_n = n * rhs.n / gcd(n * rhs.n, d * rhs.d);
        d = d * rhs.d / gcd(n * rhs.n, d * rhs.d);
        n = new_n;
        return *this;
    }
};

std::ostream& operator<<(std::ostream& out, const Fraction& f)
{
   return out << f.num() << '/' << f.den();
}

constexpr bool operator==(const Fraction& lhs, const Fraction& rhs)
{
    return lhs.num() == rhs.num() && lhs.den() == rhs.den();
}

constexpr bool operator!=(const Fraction& lhs, const Fraction& rhs)
{
    return !(lhs == rhs);
}

constexpr Fraction operator*(Fraction lhs, const Fraction& rhs)
{
    return lhs *= rhs;
}

int main()
{
    constexpr Fraction f1{3, 8}, f2{1, 2}, f3{10, 2};
    std::cout << f1 << " * " << f2 << " = " << f1 * f2 << '\n'
              << f2 << " * " << f3 << " = " << f2 * f3 << '\n'
              <<  2 << " * " << f1 << " = " <<  2 * f1 << '\n';
    static_assert(f3 == f2 * 10);
}

Output:

3/8 * 1/2 = 3/16
1/2 * 5/1 = 5/2
2 * 3/8 = 3/4

Opérateurs spéciaux

static_cast convertit un type en un autre type apparenté
dynamic_cast convertit au sein des hiérarchies d'héritage
const_cast ajoute ou supprime des qualificateurs cv
reinterpret_cast convertit un type en un type sans rapport
Transtypage de style C convertit un type en un autre par un mélange de static_cast, const_cast et reinterpret_cast
new crée des objets à durée de stockage dynamique
delete détruit les objets précédemment créés par l'expression new et libère la zone mémoire obtenue
sizeof interroge la taille d'un type
sizeof... interroge la taille d'un pack (depuis C++11)
typeid interroge les informations de type d'un type
noexcept vérifie si une expression peut lever une exception (depuis C++11)
alignof interroge les exigences d'alignement d'un type (depuis C++11)
