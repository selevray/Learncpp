Coroutines (C++20)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Une coroutine est une fonction qui peut suspendre son exécution pour la reprendre plus tard. Les coroutines sont sans pile : elles suspendent l'exécution en revenant à l'appelant, et les données nécessaires à la reprise de l'exécution sont stockées séparément de la pile. Cela permet d'écrire du code séquentiel s'exécutant de manière asynchrone (par exemple pour gérer des E/S non bloquantes sans rappels explicites), et prend également en charge des algorithmes sur des suites infinies calculées de manière paresseuse, ainsi que d'autres usages.

Une fonction est une coroutine si sa définition contient l'un des éléments suivants :

  • l'expression co_await — pour suspendre l'exécution jusqu'à sa reprise
task<> tcp_echo_server()
{
    char data[1024];
    while (true)
    {
        std::size_t n = co_await socket.async_read_some(buffer(data));
        co_await async_write(socket, buffer(data, n));
    }
}
  • l'expression co_yield — pour suspendre l'exécution en renvoyant une valeur
generator<unsigned int> iota(unsigned int n = 0)
{
    while (true)
        co_yield n++;
}
  • l'instruction co_return — pour terminer l'exécution en renvoyant une valeur
lazy<int> f()
{
    co_return 7;
}

Toute coroutine doit avoir un type de retour satisfaisant un certain nombre d'exigences, indiquées ci-dessous.

Restrictions

Les coroutines ne peuvent pas utiliser des arguments variadiques, des instructions return simples, ni des types de retour substituables (auto ou Concept).

Les fonctions consteval, fonctions constexpr, constructeurs, destructeurs et la fonction main ne peuvent pas être des coroutines.

Exécution

Chaque coroutine est associée à

  • l'objet promesse, manipulé depuis l'intérieur de la coroutine. La coroutine transmet son résultat ou son exception par l'intermédiaire de cet objet. Les objets promesses n'ont aucun lien avec std::promise.
  • le descripteur de coroutine, manipulé depuis l'extérieur de la coroutine. Il s'agit d'un descripteur non propriétaire, utilisé pour reprendre l'exécution de la coroutine ou pour détruire le cadre de la coroutine.
  • l'état de la coroutine, qui est un espace de stockage interne alloué dynamiquement (sauf si l'allocation est optimisée), objet qui contient
    • l'objet promesse
    • les paramètres (tous copiés par valeur)
    • une représentation du point de suspension actuel, afin qu'une reprise sache où continuer et qu'une destruction sache quelles variables locales étaient dans la portée
    • les variables locales et les temporaires dont la durée de vie couvre le point de suspension actuel.

Lorsqu'une coroutine commence son exécution, elle effectue les opérations suivantes :

  • alloue l'objet d'état de la coroutine à l'aide de operator new.
  • copie tous les paramètres de la fonction dans l'état de la coroutine : les paramètres passés par valeur sont déplacés ou copiés, les paramètres passés par référence restent des références (ils peuvent donc devenir pendants si la coroutine est reprise après la fin de la durée de vie de l'objet référencé — voir ci-dessous pour des exemples).
  • appelle le constructeur de l'objet promesse. Si le type promesse possède un constructeur qui prend tous les paramètres de la coroutine, ce constructeur est appelé avec les arguments de la coroutine après copie. Sinon, le constructeur par défaut est appelé.
  • appelle promise.get_return_object() et conserve le résultat dans une variable locale. Le résultat de cet appel sera renvoyé à l'appelant lors de la première suspension de la coroutine. Toute exception levée jusqu'à cette étape incluse se propage vers l'appelant, sans être placée dans la promesse.
  • appelle promise.initial_suspend() et co_await son résultat. Les types Promise habituels renvoient soit un std::suspend_always, pour les coroutines à démarrage paresseux, soit std::suspend_never, pour les coroutines à démarrage immédiat.
  • lorsque co_await promise.initial_suspend() est repris, commence l'exécution du corps de la coroutine.

Quelques exemples de paramètre devenant pendant :

#include <coroutine>
#include <iostream>

struct promise;

struct coroutine : std::coroutine_handle<promise>
{
    using promise_type = ::promise;
};

struct promise
{
    coroutine get_return_object() { return {coroutine::from_promise(*this)}; }
    std::suspend_always initial_suspend() noexcept { return {}; }
    std::suspend_always final_suspend() noexcept { return {}; }
    void return_void() {}
    void unhandled_exception() {}
};

struct S
{
    int i;
    coroutine f()
    {
        std::cout << i;
        co_return;
    }
};

void bad1()
{
    coroutine h = S{0}.f();
    // S{0} détruit
    h.resume(); // la coroutine reprise exécute std::cout << i, utilise S::i après libération
    h.destroy();
}

coroutine bad2()
{
    S s{0};
    return s.f(); // la coroutine retournée ne peut pas être reprise sans commettre une utilisation après libération
}

void bad3()
{
    coroutine h = [i = 0]() -> coroutine // une lambda qui est aussi une coroutine
    {
        std::cout << i;
        co_return;
    }(); // invoquée immédiatement
    // lambda détruite
    h.resume(); // utilise (type lambda anonyme)::i après libération
    h.destroy();
}

void good()
{
    coroutine h = [](int i) -> coroutine // faire de i un paramètre de la coroutine
    {
        std::cout << i;
        co_return;
    }(0);
    // lambda détruite
    h.resume(); // aucun problème, i a été copié dans la coroutine
                // trame en tant que paramètre passé par valeur
    h.destroy();
}

Lorsqu'une coroutine atteint un point de suspension

  • l'objet de retour obtenu précédemment est renvoyé à l'appelant ou au repreneur, après conversion implicite vers le type de retour de la coroutine, si nécessaire.

Lorsqu'une coroutine atteint l'instruction co_return, elle effectue les opérations suivantes :

  • appelle promise.return_void() pour

    • co_return;
    • co_return expr; où expr a le type void

  • ou appelle promise.return_value(expr) pour co_return expr; où expr a un type non void

  • détruit toutes les variables à durée de stockage automatique, dans l'ordre inverse de leur création.

  • appelle promise.final_suspend() et co_await son résultat.

Atteindre la fin de la coroutine équivaut à co_return;, sauf que le comportement est indéfini si aucune déclaration de return_void ne peut être trouvée dans la portée de Promise. Une fonction dont le corps ne contient aucun des mots-clés de définition n'est pas une coroutine, quel que soit son type de retour, et atteindre la fin entraîne un comportement indéfini si le type de retour n'est pas void (éventuellement qualifié cv).

// en supposant que task est un type de tâche de coroutine quelconque
task<void> f()
{
    // pas une coroutine, comportement indéfini
}

task<void> g()
{
    co_return;  // OK
}

task<void> h()
{
    co_await g();
    // OK, co_return; implicite
}

Si la coroutine se termine par une exception non interceptée, elle effectue les opérations suivantes :

  • intercepte l'exception et appelle promise.unhandled_exception() depuis le bloc catch
  • appelle promise.final_suspend() et co_await son résultat (par exemple pour reprendre une continuation ou publier un résultat). Il est indéfini de reprendre une coroutine à partir de ce point.

Lorsque l'état de la coroutine est détruit, soit parce qu'elle s'est terminée via co_return ou une exception non interceptée, soit parce qu'elle a été détruite via son descripteur, elle effectue les opérations suivantes :

  • appelle le destructeur de l'objet promesse.
  • appelle les destructeurs des copies des paramètres de la fonction.
  • appelle operator delete pour libérer la mémoire utilisée par l'état de la coroutine.
  • transfère l'exécution à l'appelant ou au repreneur.

Allocation dynamique

L'état de la coroutine est alloué dynamiquement via operator new non tableau.

Si le type Promise définit un remplacement au niveau de la classe, il sera utilisé, sinon operator new global sera utilisé.

Si le type Promise définit une forme de placement de operator new qui prend des paramètres supplémentaires, et que ceux-ci correspondent à une liste d'arguments dont le premier argument est la taille demandée (de type std::size_t) et dont les suivants sont les arguments de la fonction coroutine, ces arguments seront passés à operator new (ce qui permet d'utiliser la convention d'allocateur en tête pour les coroutines).

L'appel à operator new peut être optimisé (même si un allocateur personnalisé est utilisé) si

  • La durée de vie de l'état de la coroutine est strictement imbriquée dans celle de l'appelant, et
  • la taille du cadre de la coroutine est connue au site d'appel.

Dans ce cas, l'état de la coroutine est intégré dans le cadre de pile de l'appelant (si l'appelant est une fonction ordinaire) ou dans l'état de la coroutine (si l'appelant est une coroutine).

Si l'allocation échoue, la coroutine lève std::bad_alloc, sauf si le type Promise définit la fonction membre Promise::get_return_object_on_allocation_failure(). Si cette fonction membre est définie, l'allocation utilise la forme nothrow de operator new et, en cas d'échec, la coroutine renvoie immédiatement à l'appelant l'objet obtenu à partir de Promise::get_return_object_on_allocation_failure(), par exemple :

struct Coroutine::promise_type
{
    /* ... */

    // garantir l'utilisation de operator new sans exception
    static Coroutine get_return_object_on_allocation_failure()
    {
        std::cerr << __func__ << '\n';
        throw std::bad_alloc(); // ou, return Coroutine(nullptr);
    }

    // surcharge personnalisée de new sans exception
    void* operator new(std::size_t n) noexcept
    {
        if (void* mem = std::malloc(n))
            return mem;
        return nullptr; // échec d'allocation
    }
};

Promesse

Le type Promise est déterminé par le compilateur à partir du type de retour de la coroutine à l'aide de std::coroutine_traits.

Formellement, soit

  • R et Args... désignent respectivement le type de retour et la liste des types de paramètres d'une coroutine,
  • ClassT désigne le type de classe auquel appartient la coroutine si elle est définie comme fonction membre non statique,
  • cv désigne le qualificateur cv déclaré dans la déclaration de fonction si elle est définie comme fonction membre non statique,

son type Promise est déterminé par :

  • std::coroutine_traits<R, Args...>::promise_type, si la coroutine n'est pas définie comme une fonction membre à objet implicite,
  • std::coroutine_traits<R,cvClassT&, Args...>::promise_type, si la coroutine est définie comme une fonction membre à objet implicite qui n'est pas qualifiée par référence rvalue,
  • std::coroutine_traits<R,cvClassT&&, Args...>::promise_type, si la coroutine est définie comme une fonction membre à objet implicite qualifiée par référence rvalue.

Par exemple :

Si la coroutine est définie comme ... alors son type Promise est ...
task<void> foo(int x); std::coroutine_traits<task<void>, int>::promise_type
task<void> Bar::foo(int x) const; std::coroutine_traits<task<void>, const Bar&, int>::promise_type
task<void> Bar::foo(int x) &&; std::coroutine_traits<task<void>, Bar&&, int>::promise_type

co_await

L'opérateur unaire co_await suspend une coroutine et rend le contrôle à l'appelant.

| | | | co_await expr | | | |

Une expression co_await ne peut apparaître que dans une expression potentiellement évaluée à l'intérieur d'un corps de fonction ordinaire (y compris le corps d'une expression lambda), et ne peut pas apparaître

  • dans un gestionnaire,
  • dans une déclaration, sauf si elle apparaît dans un initialiseur de cette déclaration,
  • dans la déclaration simple d'une init-statement (voir if, switch, for et boucle for basée sur un intervalle), sauf si elle apparaît dans un initialiseur de cette init-statement,
  • dans un argument par défaut, ou
  • dans l'initialiseur d'une variable de portée de bloc à durée de stockage statique ou de thread.

Tout d'abord, expr est converti en awaitable comme suit :

  • si expr est produit par un point de suspension initial, un point de suspension final ou une expression yield, l'awaitable est expr, tel quel.
  • sinon, si le type Promise de la coroutine courante possède la fonction membre await_transform, l'awaitable est promise.await_transform(expr).
  • sinon, l'awaitable est expr, tel quel.

Ensuite, l'objet awaiter est obtenu comme suit :

  • si la résolution de surcharge pour operator co_await donne une unique meilleure surcharge, l'awaiter est le résultat de cet appel :

    • awaitable.operator co_await() pour la surcharge membre,
    • operator co_await(static_cast<Awaitable&&>(awaitable)) pour la surcharge non membre.

  • sinon, si la résolution de surcharge ne trouve aucun opérateur co_await, l'awaiter est l'awaitable lui-même, tel quel.

  • sinon, si la résolution de surcharge est ambiguë, le programme est mal formé.

Si l'expression ci-dessus est une prvalue, l'objet awaiter est un temporaire matérialisé à partir de celle-ci. Sinon, si l'expression ci-dessus est une glvalue, l'objet awaiter est l'objet auquel elle fait référence.

Ensuite, awaiter.await_ready() est appelée (il s'agit d'un raccourci pour éviter le coût de la suspension si l'on sait que le résultat est prêt ou peut être complété de manière synchrone). Si son résultat, converti contextuellement en bool, vaut false, alors

La coroutine est suspendue (son état de coroutine est rempli avec les variables locales et le point de suspension courant).awaiter.await_suspend(handle) est appelée, où handle est le handle de coroutine représentant la coroutine courante. Dans cette fonction, l'état suspendu de la coroutine est observable via ce handle, et il incombe à cette fonction de planifier sa reprise sur un exécuteur quelconque, ou de la détruire (retourner false équivaut à une planification)

  • si await_suspend retourne void, le contrôle est immédiatement rendu à l'appelant/reprenant de la coroutine courante (cette coroutine reste suspendue), sinon

  • si await_suspend retourne bool,

    • la valeur retournée par true rend le contrôle à l'appelant/reprenant de la coroutine courante
    • la valeur retournée par false reprend la coroutine courante.

  • si await_suspend retourne un handle de coroutine pour une autre coroutine, ce handle est repris (par un appel à handle.resume()) (notez que cela peut s'enchaîner et finir par reprendre la coroutine courante).

  • si await_suspend lève une exception, l'exception est capturée, la coroutine est reprise, et l'exception est immédiatement relancée.

Enfin, awaiter.await_resume() est appelée (que la coroutine ait été suspendue ou non), et son résultat est le résultat de l'expression co_await expr complète.

Si la coroutine a été suspendue dans l'expression co_await, et est reprise plus tard, le point de reprise se situe immédiatement avant l'appel à awaiter.await_resume().

Notez que la coroutine est entièrement suspendue avant d'entrer dans awaiter.await_suspend(). Son handle peut être partagé avec un autre thread et repris avant que la fonction await_suspend() ne retourne. (Notez que les règles de sécurité mémoire par défaut s'appliquent toujours : si un handle de coroutine est partagé entre threads sans verrou, l'awaiter doit utiliser au minimum la sémantique de release et le reprenant doit utiliser au minimum la sémantique d'acquire.) Par exemple, le handle de coroutine peut être placé dans un callback, planifié pour s'exécuter sur un threadpool lorsque l'opération d'E/S asynchrone se termine. Dans ce cas, comme la coroutine courante peut avoir été reprise et donc avoir exécuté le destructeur de l'objet awaiter, pendant que await_suspend() poursuit son exécution sur le thread courant, await_suspend() doit considérer *this comme détruit et ne pas y accéder après que le handle a été publié vers d'autres threads.

Exemple

#include <coroutine>
#include <iostream>
#include <stdexcept>
#include <thread>

auto switch_to_new_thread(std::jthread& out)
{
    struct awaitable
    {
        std::jthread* p_out;
        bool await_ready() { return false; }
        void await_suspend(std::coroutine_handle<> h)
        {
            std::jthread& out = *p_out;
            if (out.joinable())
                throw std::runtime_error("Output jthread parameter not empty");
            out = std::jthread([h] { h.resume(); });
            // Comportement indéfini potentiel : accès à *this potentiellement détruit
            // std::cout << "New thread ID: " << p_out->get_id() << '\n';
            std::cout << "New thread ID: " << out.get_id() << '\n'; // ceci est OK
        }
        void await_resume() {}
    };
    return awaitable{&out};
}

struct task
{
    struct promise_type
    {
        task get_return_object() { return {}; }
        std::suspend_never initial_suspend() { return {}; }
        std::suspend_never final_suspend() noexcept { return {}; }
        void return_void() {}
        void unhandled_exception() {}
    };
};

task resuming_on_new_thread(std::jthread& out)
{
    std::cout << "Coroutine started on thread: " << std::this_thread::get_id() << '\n';
    co_await switch_to_new_thread(out);
    // awaiter détruit ici
    std::cout << "Coroutine resumed on thread: " << std::this_thread::get_id() << '\n';
}

int main()
{
    std::jthread out;
    resuming_on_new_thread(out);
}

Note : l'objet awaiter fait partie de l'état de la coroutine (en tant que temporaire dont la durée de vie traverse un point de suspension) et est détruit avant la fin de l'expression co_await. Il peut servir à conserver un état par opération, comme l'exigent certaines API d'E/S asynchrones, sans recourir à des allocations dynamiques supplémentaires.

Démonstration de promise_type::await_transform et d'un awaiter fourni par le programme

Exemple

#include <cassert>
#include <coroutine>
#include <iostream>

struct tunable_coro
{
    // Un awaiter dont la « disponibilité » est déterminée via le paramètre du constructeur.
    class tunable_awaiter
    {
        bool ready_;
    public:
        explicit(false) tunable_awaiter(bool ready) : ready_{ready} {}
        // Trois fonctions d'interface standard de l'awaiter :
        bool await_ready() const noexcept { return ready_; }
        static void await_suspend(std::coroutine_handle<>) noexcept {}
        static void await_resume() noexcept {}
    };

    struct promise_type
    {
        using coro_handle = std::coroutine_handle<promise_type>;
        auto get_return_object() { return coro_handle::from_promise(*this); }
        static auto initial_suspend() { return std::suspend_always(); }
        static auto final_suspend() noexcept { return std::suspend_always(); }
        static void return_void() {}
        static void unhandled_exception() { std::terminate(); }
        // Une fonction de transformation fournie par l'utilisateur qui retourne l'awaiter personnalisé :
        auto await_transform(std::suspend_always) { return tunable_awaiter(!ready_); }
        void disable_suspension() { ready_ = false; }
    private:
        bool ready_{true};
    };

    tunable_coro(promise_type::coro_handle h) : handle_(h) { assert(h); }

    // Pour simplifier, déclarez ces 4 fonctions spéciales comme supprimées :
    tunable_coro(tunable_coro const&) = delete;
    tunable_coro(tunable_coro&&) = delete;
    tunable_coro& operator=(tunable_coro const&) = delete;
    tunable_coro& operator=(tunable_coro&&) = delete;

    ~tunable_coro()
    {
        if (handle_)
            handle_.destroy();
    }

    void disable_suspension() const
    {
        if (handle_.done())
            return;
        handle_.promise().disable_suspension();
        handle_();
    }

    bool operator()()
    {
        if (!handle_.done())
            handle_();
        return !handle_.done();
    }
private:
    promise_type::coro_handle handle_;
};

tunable_coro generate(int n)
{
    for (int i{}; i != n; ++i)
    {
        std::cout << i << ' ';
        // L'awaiter passé à co_await est transmis à promise_type::await_transform qui
        // émet tunable_awaiter, qui provoque initialement une suspension (retour immédiat à
        // main à chaque itération), mais après un appel à disable_suspension, aucune suspension
        // n'a lieu et la boucle s'exécute jusqu'à sa fin sans retourner à main().
        co_await std::suspend_always{};
    }
}

int main()
{
    auto coro = generate(8);
    coro(); // n'émet qu'un seul premier élément == 0
    for (int k{}; k < 4; ++k)
    {
        coro(); // émet 1 2 3 4, un par itération
        std::cout << ": ";
    }
    coro.disable_suspension();
    coro(); // émet les derniers nombres 5 6 7 d'un seul coup
}

0 1 : 2 : 3 : 4 : 5 6 7

co_yield

L'expression co_yield renvoie une valeur à l'appelant et suspend la coroutine courante : c'est le bloc de construction courant des fonctions génératrices reprenables.

| | | | co_yield expr | | | | | co_yield braced-init-list | | | |

Elle est équivalente à

co_await promise.yield_value(expr)

Le yield_value typique d'un générateur stockerait (par copie/déplacement, ou simplement l'adresse, puisque la durée de vie de l'argument traverse le point de suspension à l'intérieur de co_await) son argument dans l'objet générateur et retournerait std::suspend_always, transférant le contrôle à l'appelant/reprenant.

#include <coroutine>
#include <cstdint>
#include <exception>
#include <iostream>

template<typename T>
struct Generator
{
    // Le nom de classe 'Generator' est notre choix et n'est pas requis pour la coroutine
    // magie. Le compilateur reconnaît une coroutine par la présence du mot-clé 'co_yield'.
    // Vous pouvez utiliser le nom 'MyGenerator' (ou tout autre nom) à la place, tant que vous incluez
    // une structure imbriquée promise_type avec la méthode 'MyGenerator get_return_object()'.
    // (Note : il est nécessaire d'adapter les déclarations des constructeurs et destructeurs
    //  lors du renommage.)

    struct promise_type;
    using handle_type = std::coroutine_handle<promise_type>;

    struct promise_type // required
    {
        T value_;
        std::exception_ptr exception_;

        Generator get_return_object()
        {
            return Generator(handle_type::from_promise(*this));
        }
        std::suspend_always initial_suspend() { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        void unhandled_exception() { exception_ = std::current_exception(); } // saving
                                                                              // exception

        template<std::convertible_to<T> From> // concept C++20
        std::suspend_always yield_value(From&& from)
        {
            value_ = std::forward<From>(from); // mise en cache du résultat dans promise
            return {};
        }
        void return_void() {}
    };

    handle_type h_;

    Generator(handle_type h) : h_(h) {}
    ~Generator() { h_.destroy(); }
    explicit operator bool()
    {
        fill(); // Le seul moyen fiable de savoir si nous avons terminé la coroutine,
                // et s'il va être généré une valeur suivante (co_yield)
                // dans la coroutine via le getter C++ (operator () ci-dessous) consiste à exécuter/reprendre
                // coroutine jusqu'au prochain point co_yield (ou la laisser atteindre la fin).
                // Ensuite, nous stockons/mettons en cache le résultat dans la promesse pour permettre au getter (operator() ci-dessous
                // de le récupérer sans exécuter la coroutine).
        return !h_.done();
    }
    T operator()()
    {
        fill();
        full_ = false; // nous allons déplacer hors du cache le résultat précédemment mis en cache
                       // résultat afin de rendre la promesse à nouveau vide
        return std::move(h_.promise().value_);
    }

private:
    bool full_ = false;

    void fill()
    {
        if (!full_)
        {
            h_();
            if (h_.promise().exception_)
                std::rethrow_exception(h_.promise().exception_);
            // propager l'exception de la coroutine dans le contexte appelant

            full_ = true;
        }
    }
};

Generator<std::uint64_t>
fibonacci_sequence(unsigned n)
{
    if (n == 0)
        co_return;

    if (n > 94)
        throw std::runtime_error("Too big Fibonacci sequence. Elements would overflow.");

    co_yield 0;

    if (n == 1)
        co_return;

    co_yield 1;

    if (n == 2)
        co_return;

    std::uint64_t a = 0;
    std::uint64_t b = 1;

    for (unsigned i = 2; i < n; ++i)
    {
        std::uint64_t s = a + b;
        co_yield s;
        a = b;
        b = s;
    }
}

int main()
{
    try
    {
        auto gen = fibonacci_sequence(10); // maximum 94 avant que uint64_t ne déborde

        for (int j = 0; gen; ++j)
            std::cout << "fib(" << j << ")=" << gen() << '\n';
    }
    catch (const std::exception& ex)
    {
        std::cerr << "Exception: " << ex.what() << '\n';
    }
    catch (...)
    {
        std::cerr << "Unknown exception.\n";
    }
}
