Type

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les objets, les références, les fonctions y compris les spécialisations de modèles de fonction, et les expressions possèdent une propriété appelée type, qui restreint les opérations autorisées sur ces entités et donne un sens sémantique aux séquences de bits par ailleurs génériques.

Classification des types

Le système de types de C++ se compose des types suivants :

  • types fondamentaux (voir aussi std::is_fundamental) :
    • le type void (voir aussi std::is_void) ;
  • le type std::nullptr_t (voir aussi std::is_null_pointer) ;

(depuis C++11)

  • types arithmétiques (voir aussi std::is_arithmetic) :
    • types entiers (y compris les versions qualifiées cv, voir aussi std::is_integral, un synonyme de type entier est « integer type ») :
      • le type bool ;
      • types caractères :
        • types de caractères étroits :
          • types de caractères ordinaires : char, signed char, unsigned char[1]
  • le type char8_t

(depuis C++20)

  • types de caractères larges : char16_t, char32_t, (depuis C++11)wchar_t ;

  • types entiers signés :

    • types entiers signés standard : signed char, short, int, long, long long ;
  • types entiers signés étendus (définis par l'implémentation) ;

(depuis C++11)

  • types entiers non signés :
    • types entiers non signés standard : unsigned char, unsigned short, unsigned, unsigned long, unsigned long long ;
  • types entiers non signés étendus (chacun correspond à un type entier signé étendu, et réciproquement) ;

(depuis C++11)

  • types à virgule flottante (voir aussi std::is_floating_point) :
    • types à virgule flottante standard : float, double, long double et leurs versions qualifiées cv ;
  • types à virgule flottante étendus (y compris les versions qualifiées cv) :
  • types à virgule flottante de largeur fixe ;
  • autres types à virgule flottante étendus définis par l'implémentation ;

(depuis C++23)

  • types composés (voir aussi std::is_compound) :
    • types référence (voir aussi std::is_reference) :
      • types référence lvalue (voir aussi std::is_lvalue_reference) :
        • référence lvalue vers des types objet ;
        • référence lvalue vers des types fonction ;
  • types référence rvalue (voir aussi std::is_rvalue_reference) :
  • référence rvalue vers des types objet ;
  • référence rvalue vers des types fonction ;

(depuis C++11)

  • types pointeur (voir aussi std::is_pointer) :

    • types pointeur vers objet ;
    • types pointeur vers fonction ;

  • types pointeur vers membre (voir aussi std::is_member_pointer) :

    • types pointeur vers membre donnée (voir aussi std::is_member_object_pointer) ;
    • types pointeur vers fonction membre (voir aussi std::is_member_function_pointer) ;

  • types tableau (voir aussi std::is_array) ;

  • types fonction (voir aussi std::is_function) ;

  • types énumération (voir aussi std::is_enum) ;

    • types énumérés non délimités;
  • types énumérés délimités (voir aussi std::is_scoped_enum);

(depuis C++11)

  • types classes :
    • types non-union (voir aussi std::is_class);
    • types union (voir aussi std::is_union).
  1. ↑ signed char et unsigned char sont des types caractères étroits, mais ce ne sont pas des types caractères. Autrement dit, l'ensemble des types caractères étroits n'est pas un sous-ensemble de l'ensemble des types caractères.

Pour chaque type non qualifié cv autre que référence et fonction, le système de types prend en charge trois versions qualifiées cv supplémentaires de ce type (const, volatile et const volatile).

Autres catégories

Un type objet (voir aussi std::is_object) est un type (éventuellement qualifié cv) qui n'est pas un type fonction, pas un type référence, et pas (éventuellement qualifié cv) void.

Les types suivants sont collectivement appelés types scalaires (voir aussi std::is_scalar) :

  • types arithmétiques
  • types énumérés
  • types pointeurs
  • types pointeur vers membre
  • std::nullptr_t

(depuis C++11)

  • versions qualifiées cv de ces types

Les types suivants sont collectivement appelés types à durée de vie implicite :

  • types scalaires
  • types classes à durée de vie implicite
  • types tableaux
  • versions qualifiées cv de ces types

Les types suivants sont collectivement appelés types trivialement copiables :

  • types scalaires
  • types classes trivialement copiables
  • tableaux de tels types
  • versions qualifiées cv de ces types

Les types suivants sont collectivement appelés types à disposition standard :

  • types scalaires
  • types classes à disposition standard
  • tableaux de tels types
  • versions qualifiées cv de ces types

(depuis C++11)

Type défini par le programme

Une spécialisation définie par le programme est une spécialisation explicite ou une spécialisation partielle qui ne fait pas partie de la bibliothèque standard C++ et qui n'est pas définie par l'implémentation.

Un type défini par le programme est l'un des types suivants :

  • Untype non-fermeture (depuis C++11) type classe ou type énumération qui ne fait pas partie de la bibliothèque standard C++ et n'est pas défini par l'implémentation.
  • Un type fermeture d'une expression lambda non fournie par l'implémentation.

(depuis C++11)

  • Une instanciation d'une spécialisation définie par le programme.

Nommage des types

Un nom peut être déclaré comme désignant un type au moyen :

  • d'une déclaration class ;
  • d'une déclaration union ;
  • d'une déclaration enum ;
  • d'une déclaration typedef ;
  • d'une déclaration d'alias de type.

Les types sans nom doivent souvent être désignés dans les programmes C++ ; la syntaxe pour cela est appelée type-id. La syntaxe du type-id qui désigne le type T est exactement la syntaxe d'une déclaration de variable ou de fonction de type T, l'identifiant étant omis, sauf que decl-specifier-seq de la grammaire de déclaration est restreint à type-specifier-seq, et que de nouveaux types ne peuvent être définis que si le type-id apparaît à droite d'une déclaration d'alias de type non modèle.

int* p;               // déclaration d'un pointeur vers int
static_cast<int*>(p); // type-id est « int* »

int a[3];   // déclaration d'un tableau de 3 int
new int[3]; // type-id est « int[3] » (appelé new-type-id)

int (*(*x[2])())[3];      // déclaration d'un tableau de 2 pointeurs vers des fonctions
                          // renvoyant un pointeur vers un tableau de 3 int
new (int (*(*[2])())[3]); // type-id est « int (*(*[2])())[3] »

void f(int);                    // déclaration d'une fonction prenant un int et renvoyant void
std::function<void(int)> x = f; // le paramètre de modèle de type est un type-id « void(int) »
std::function<auto(int) -> void> y = f; // same

std::vector<int> v;       // déclaration d'un vector d'int
sizeof(std::vector<int>); // type-id est « std::vector<int> »

struct { int x; } b;         // crée un nouveau type et déclare un objet b de ce type
sizeof(struct { int x; });   // erreur : impossible de définir de nouveaux types dans une expression sizeof
using t = struct { int x; }; // crée un nouveau type et déclare t comme alias de ce type

sizeof(static int); // erreur : les spécificateurs de classe de stockage ne font pas partie de type-specifier-seq
std::function<inline void(int)> f; // erreur : les spécificateurs de fonction non plus

La partie declarator de la grammaire de déclaration, sans le nom, est appelée abstract-declarator.

Le type-id peut être utilisé dans les situations suivantes :

  • pour spécifier le type cible dans les expressions de conversion ;
  • comme arguments de sizeof, alignof, alignas, new et typeid ;
  • à droite d'une déclaration d'alias de type ;
  • comme type de retour final d'une déclaration de fonction ;
  • comme argument par défaut d'un paramètre de type de modèle ;
  • comme argument de modèle pour un paramètre de type de modèle ;
  • dans une spécification d'exception dynamique.

(jusqu'à C++17)

Le type-id peut être utilisé avec quelques modifications dans les situations suivantes :

  • dans la liste de paramètres d'une fonction (lorsque le nom du paramètre est omis), le type-id utilise decl-specifier-seq au lieu de type-specifier-seq (en particulier, certains spécificateurs de classe de stockage sont autorisés) ;
  • dans le nom d'une fonction de conversion définie par l'utilisateur, le déclarateur abstrait ne peut pas comporter d'opérateurs de fonction ou de tableau.

Spécificateur de type élaboré

Les spécificateurs de type élaborés peuvent servir à désigner un nom de classe (class, struct ou union) déjà déclaré ou un nom d'énumération déjà déclaré, même si ce nom a été masqué par une déclaration de non-type. Ils peuvent aussi servir à déclarer de nouveaux noms de classes.

Voir spécificateur de type identifié pour plus de détails.

Type statique

Le type d'une expression résultant de l'analyse à la compilation du programme est appelé type statique de l'expression. Le type statique ne change pas pendant l'exécution du programme.

Type dynamique

Si une expression glvalue désigne un objet polymorphe, le type de son objet le plus dérivé est appelé type dynamique.

// given
struct B { virtual ~B() {} }; // type polymorphe
struct D : B {};               // type polymorphe

D d; // objet le plus dérivé
B* ptr = &d;

// le type statique de (*ptr) est B
// le type dynamique de (*ptr) est D

Pour les expressions prvalue, le type dynamique est toujours identique au type statique.

Type incomplet

Les types suivants sont des types incomplets :

  • le type void (éventuellement qualifié cv) ;
  • types objets incomplètement définis :
    • type classe qui a été déclaré (par exemple par une déclaration anticipée) mais non défini ;
    • tableau de borne inconnue ;
    • tableau d'éléments de type incomplet ;
    • type énumération depuis le point de déclaration jusqu'à ce que son type sous-jacent soit déterminé.

Tous les autres types sont complets.

Chacun des contextes suivants exige que le type T soit complet :

  • définition ou appel d'une fonction dont le type de retour est T ou dont le type d'argument est T ;
  • définition d'un objet de type T ;
  • déclaration d'un membre de donnée de classe non statique de type T ;
  • expression new pour un objet de type T ou pour un tableau dont le type d'élément est T ;
  • conversion lvalue-to-rvalue appliquée à une glvalue de type T ;
  • une conversion implicite ou explicite vers le type T;
  • une conversion standard, dynamic_cast, ou static_cast vers le type T* ou T&, sauf lors d'une conversion à partir de la constante de pointeur nulle ou d'un pointeur vers un type void éventuellement qualifié cv;
  • opérateur d'accès à un membre de classe appliqué à une expression de type T;
  • opérateur typeid, sizeof, ou alignof appliqué au type T;
  • opérateur arithmétique appliqué à un pointeur vers T;
  • définition d'une classe ayant pour classe de base T;
  • affectation à une lvalue de type T;
  • un gestionnaire de type T, T&, ou T*.

(En général, lorsque la taille et la disposition en mémoire de T doivent être connues.)

Si l'une de ces situations se produit dans une unité de traduction, la définition du type doit figurer dans la même unité de traduction. Sinon, ce n'est pas requis.

Un type d'objet incomplètement défini peut être complété :

  • Un type classe (tel que class X) peut être considéré comme incomplet à un endroit d'une unité de traduction et comme complet plus loin ; le type class X est le même type aux deux endroits :
struct X;            // déclaration de X, pas encore de définition fournie
extern X* xp;        // xp est un pointeur vers un type incomplet :
                     // la définition de X n'est pas accessible

void foo()
{
    xp++;            // mal formé : X est incomplet
}

struct X { int i; }; // définition de X
X x;                 // OK : la définition de X est accessible

void bar()
{
    xp = &x;         // OK : le type est « pointeur vers X »
    xp++;            // OK : X est complet
}
  • Le type déclaré d'un objet tableau peut être un tableau de type classe incomplet, et donc incomplet lui-même ; si le type classe est complété plus loin dans l'unité de traduction, le type tableau devient complet ; le type tableau à ces deux endroits est le même type.
  • Le type déclaré d'un objet tableau peut être un tableau de borne inconnue, et donc être incomplet à un endroit de l'unité de traduction et complet plus loin ; les types tableau à ces deux endroits (« tableau de borne inconnue de T » et « tableau de N T ») sont des types différents.

Le type d'un pointeur ou d'une référence vers un tableau de borne inconnue pointe ou fait référence en permanence à un type incomplet. Un tableau de borne inconnue nommé par une déclaration typedef fait en permanence référence à un type incomplet. Dans les deux cas, le type tableau ne peut pas être complété :

extern int arr[];   // le type de arr est incomplet
typedef int UNKA[]; // UNKA est un type incomplet

UNKA* arrp;         // arrp est un pointeur vers un type incomplet
UNKA** arrpp;

void foo()
{
    arrp++;         // erreur : UNKA est un type incomplet
    arrpp++;        // OK : sizeof UNKA* est connu
}

int arr[10];        // maintenant le type de arr est complet

void bar()
{
    arrp = &arr;    // OK : conversion de qualification (depuis C++20)
    arrp++;         // erreur : UNKA ne peut pas être complété
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 328 C++98 les membres de classe de type incomplet n'étaient pas interdits si aucun objet de ce type de classe n'a jamais été créé les membres de données de classe non statiques doivent être complets
CWG 977 C++98 le moment où un type énumération devient complet dans sa définition n'était pas clair le type est complet dès que le type sous-jacent est déterminé
CWG 1362 C++98 les conversions définies par l'utilisateur vers le type T* ou T& exigeaient que T soit complet non requis
CWG 2006 C++98 les types void qualifiés cv étaient des types objet et des types complets exclus des deux catégories
CWG 2448 C++98 seuls les types non qualifiés cv pouvaient être des types entiers et à virgule flottante autorise les types qualifiés cv
CWG 2630 C++98 il n'était pas clair si une classe est considérée comme complète en dehors de l'unité de traduction où la définition de la classe apparaît la classe est complète si sa définition est accessible dans ce cas
CWG 2643 C++98 le type d'un pointeur vers un tableau de borne inconnue ne pouvait pas être complété (mais il est déjà complet) le type tableau pointé ne peut pas être complété
LWG 2139 C++98 la signification de « type défini par l'utilisateur » n'était pas claire définit et utilise à la place « type défini par le programme »
LWG 3119 C++11 il n'était pas clair si les types de fermeture sont des types définis par le programme rendu clair
