Explication

  • s-char-seq — Une séquence d'un ou plusieurs s-char ﻿s
  • s-char — L'un des suivants
    • a basic-s-char
    • une séquence d'échappement, telle que définie dans séquences d'échappement
    • un nom de caractère universel, tel que défini dans séquences d'échappement
  • basic-s-char — Un caractère de l'ensemble de caractères de traduction, à l'exception du guillemet double ", de la barre oblique inverse \ ou du caractère de saut de ligne
  • d-char-seq — Une séquence d'un ou plusieurs d-char ﻿s, d'au plus 16 caractères
  • d-char — Un caractère de l'ensemble de caractères de base, à l'exception des parenthèses, de la barre oblique inverse et des espaces
  • r-char-seq — Une séquence d'un ou plusieurs r-char ﻿s, qui ne doit pas contenir la séquence de fermeture )d-char-seq"
  • r-char — Un caractère de l'ensemble de caractères de traduction

Dans les types listés dans le tableau ci-dessus, N est le nombre d'unités de code encodées, déterminé ci-dessous.

Les chaînes littérales ordinaires et UTF-8 (depuis C++11) sont collectivement désignées sous le nom de chaînes littérales étroites.

L'évaluation d'une chaîne littérale produit un objet chaîne littérale à durée de stockage statique. Le fait que toutes les chaînes littérales soient stockées dans des objets non chevauchants, et que des évaluations successives d'une même chaîne littérale produisent le même objet ou des objets différents, est non spécifié.

La tentative de modification d'un objet chaîne littérale a un comportement indéfini.

bool b = "bar" == 3 + "foobar"; // peut valoir true ou false, non spécifié

const char* pc = "Hello";
char* p = const_cast<char*>(pc);
p[0] = 'M'; // comportement indéfini

Littéraux de chaîne bruts

Les chaînes littérales brutes sont des chaînes littérales dont le préfixe contient R (syntaxes (2,4,6,8,10)). Elles n'échappent aucun caractère, ce qui signifie que tout ce qui se trouve entre les délimiteurs d-char-seq ﻿( et )d-char-seq fait partie de la chaîne. Le délimiteur de fin d-char-seq est la même séquence de caractères que le début d-char-seq.

// OK : contient une barre oblique inverse,
// équivalent à "\\"
R"(\)";

// OK : contient quatre paires \n,
// équivalent à "\\n\\n\\n\\n"
R"(\n\n\n\n)";

// OK : contient une parenthèse fermante, deux guillemets doubles et une parenthèse ouvrante,
// équivalent à ")\"\"("
R"-()""()-";

// OK : équivalent à "\n)\\\na\"\"\n"
R"a(
)\
a""
)a";

// OK : équivalent à "x = \"\"\\y\"\""
R"(x = ""\y"")";

// R"<<(-_-)>>"; // Erreur : les délimiteurs de début et de fin ne correspondent pas
// R"-()-"-()-"; // Erreur : )-" apparaît au milieu et termine le littéral

(depuis C++11)

Initialisation

Les objets chaîne littérale sont initialisés avec la séquence de valeurs d'unités de code correspondant à la séquence des s-char ﻿s de la chaîne littéraleet r-char ﻿s (depuis C++11), suivie d'un caractère nul de fin (U+0000), dans l'ordre suivant :

  1. Pour chaque séquence contiguë de basic-s-char ﻿s,r-char ﻿s, (depuis C++11) séquences d'échappement simples et noms de caractères universels, la séquence de caractères qu'elle désigne est encodée en une séquence d'unités de code à l'aide de l'encodage de caractères associé à la chaîne littérale. Si un caractère n'a pas de représentation dans l'encodage de caractères associé, le programme est mal formé.

Si l'encodage de caractères associé est à états, la première séquence est encodée à partir de l'état d'encodage initial, et chaque séquence suivante est encodée à partir de l'état d'encodage final de la séquence précédente.

  1. Pour chaque séquence d'échappement numérique, en notant v la valeur entière représentée par le nombre octal ou hexadécimal formé par la séquence de chiffres de la séquence d'échappement, et T le type d'élément du tableau de la chaîne littérale (voir le tableau ci-dessus) :
  • Si v ne dépasse pas la plage des valeurs représentables de T, alors la séquence d'échappement apporte une seule unité de code de valeur v.
  • Sinon, sila chaîne littérale est de syntaxe (1) ou (3), et (depuis C++11) v ne dépasse pas la plage des valeurs représentables du type non signé correspondant au type sous-jacent de T, alors la séquence d'échappement apporte une seule unité de code, d'une valeur unique de type T, congrue à v mod 2S
    , où S est la largeur de T.
  • Sinon, le programme est mal formé.

Si l'encodage de caractères associé est à états, toutes ces séquences n'ont aucun effet sur l'état d'encodage.

  1. Chaque séquence d'échappement conditionnelle apporte une séquence d'unités de code définie par l'implémentation.

Si l'encodage de caractères associé est à états, l'effet de ces séquences sur l'état d'encodage est défini par l'implémentation.

Concaténation

Les chaînes littérales adjacentes sont concaténées à la phase de traduction 6 (après le prétraitement) :

  • Si les deux chaînes littérales sont de même type, la chaîne littérale concaténée est aussi de ce type.
  • Si une chaîne littérale ordinaire est adjacente à une chaîne littérale large, le comportement est indéfini.

(jusqu'à C++11)

  • Si une chaîne littérale ordinaire est adjacente à une chaîne littérale non ordinaire, la chaîne littérale concaténée est du type de cette dernière.
  • Si une chaîne littérale UTF-8 est adjacente à une chaîne littérale large, le programme est mal formé.
  • Toute autre combinaison est conditionnellement prise en charge, avec une sémantique définie par l'implémentation.[1]

(jusqu'à C++23)

  • Toute autre combinaison est mal formée.

(depuis C++23)

Chaînes non évaluées

Les contextes suivants attendent une chaîne littérale, mais ne l'évaluent pas :

  • spécification de liaison de langage
  • static_assert
  • nom d'opérateur littéral

(depuis C++11)

  • [[deprecated]]

(depuis C++14)

  • [[nodiscard]]

(depuis C++20)

  • corps de fonction supprimée

(depuis C++26)

Il n'est pas spécifié si les chaînes littérales non ordinaires sont autorisées dans ces contextes, à l'exception du nom d'un opérateur littéral, qui doit utiliser une chaîne littérale ordinaire (depuis C++11).

(jusqu'à C++26)

Seules les chaînes littérales ordinaires sont autorisées dans ces contextes.

Chaque nom de caractère universel et chaque séquence d'échappement simple d'une chaîne non évaluée est remplacé par le membre de l'ensemble de caractères de traduction qu'il désigne. Une chaîne non évaluée qui contient une séquence d'échappement numérique ou une séquence d'échappement conditionnelle est mal formée.

(depuis C++26)

Notes

Les chaînes littérales peuvent être utilisées pour initialiser des tableaux de caractères. Si un tableau est initialisé comme char str[] = "foo";, str contiendra une copie de la chaîne "foo".

Les chaînes littérales sont convertibles et affectables en char* ou wchar_t* non const afin d'être compatibles avec C, où les chaînes littérales sont de types char[N] et wchar_t[N]. Une telle conversion implicite est obsolète.

(jusqu'à C++11)

Les chaînes littérales ne sont ni convertibles ni affectables en CharT* non const. Un transtypage explicite (par exemple const_cast) doit être utilisé si une telle conversion est souhaitée.

(depuis C++11)

Une chaîne littérale n'est pas nécessairement une séquence de caractères terminée par un caractère nul : si une chaîne littérale contient des caractères nuls internes, elle représente un tableau qui contient plusieurs chaînes.

const char* p = "abc\0def"; // std::strlen(p) == 3, mais le tableau a une taille de 8

Si un chiffre hexadécimal valide suit une séquence d'échappement hexadécimale dans une chaîne littérale, la compilation échouerait car il s'agirait d'une séquence d'échappement invalide. La concaténation de chaînes peut être utilisée comme solution de contournement :

//const char* p = "\xfff"; // erreur : séquence d'échappement hexadécimale hors limites
const char* p = "\xff""f"; // OK : le littéral est const char[3] contenant {'\xff','f','\0'}

// array1 et array2 contiennent les mêmes valeurs :
char array1[] = "Foo" "bar";
char array2[] = {'F', 'o', 'o', 'b', 'a', 'r', '\0'};

const char* s1 = R"foo(
Hello
  World
)foo";
// identique à
const char* s2 = "\nHello\n  World\n";
// identique à
const char* s3 = "\n"
                 "Hello\n"
                 "  World\n";

const wchar_t* s4 = L"ABC" L"DEF"; // OK, identique à
const wchar_t* s5 = L"ABCDEF";
const char32_t* s6 = U"GHI" "JKL"; // OK, identique à
const char32_t* s7 = U"GHIJKL";
const char16_t* s9 = "MN" u"OP" "QR"; // OK, identique à
const char16_t* sA = u"MNOPQR";

// const auto* sB = u"Mixed" U"Types";

        // l'implémentation ; mal formé depuis C++23

int main()
{
