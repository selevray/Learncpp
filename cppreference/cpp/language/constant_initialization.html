Initialisation constante

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Fixe les valeurs initiales des variables static à une constante de compilation.

Explication

L'initialisation constante est effectuée dans les cas suivants :

  • Initialisation d'une référence à durée de stockage statique avec une expression constante.

  • Initialisation d'un objet de type POD à durée de stockage statique avec une expression constante.

(jusqu'à C++11)

  • Initialisation d'une référence à durée de stockage statique ou thread, lorsque toutes les conditions suivantes sont satisfaites :

  • Chaque expression complète (y compris les conversions implicites) qui apparaît dans l'initialiseur est une expression constante.

  • La référence est liée à l'une des entités suivantes :

  • une lvalue désignant un objet à durée de stockage statique

  • un objet temporaire

  • un sous-objet d'un objet temporaire

  • une fonction

  • Initialisation d'un objet à durée de stockage statique ou thread, et l'une des conditions suivantes est satisfaite :

  • Si l'objet est initialisé par un appel de constructeur, où l'expression complète d'initialisation est une expression constante, sauf qu'elle peut aussi invoquer des constexpr constructeurs pour l'objet et ses sous-objets (même si ces objets sont de types classe non-littéraux).

  • Sinon, soit l'objet est initialisé par valeur, soit chaque expression complète qui apparaît dans son initialiseur est une expression constante.

(depuis C++11) (jusqu'à C++17)

  • Initialisation d'une variable ou d'un objet temporaire à durée de stockage static ou thread par un initialiseur dont l'expression complète est une expression constante, sauf que si l'entité initialisée est un objet, cet initialiseur peut aussi invoquer des constexpr constructeurs pour l'objet et ses sous-objets (même si ces objets sont de types classe non-littéraux).

(depuis C++17) (jusqu'à C++20)

  • Une variableou objet temporaire (jusqu'à C++26) à durée de stockage statique ou thread est initialisée de façon constante.

(depuis C++20)

Les effets de l'initialisation constante sont les mêmes que ceux de l'initialisation correspondante, sauf qu'il est garanti qu'elle est terminée avant que toute autre initialisation d'un objet statiqueou thread-local (depuis C++11) ne commence.

Notes

Le compilateur peut initialiser d'autres objets statiqueset thread-local (depuis C++11) par initialisation constante, s'il peut garantir que la valeur serait la même que si l'ordre standard d'initialisation avait été suivi.

L'initialisation constante a généralement lieu au chargement du programme en mémoire, dans le cadre de l'initialisation de l'environnement d'exécution du programme.

Exemple

#include <iostream>
#include <array>

struct S
{
    static const int c;
};

const int d = 10 * S::c; // pas une expression constante : S::c n'a pas de
                         // initialiseur précédent ; cette initialisation a lieu après l'
const int S::c = 5;      // initialisation constante, qui est garantie de se produire en premier

int main()
{
    std::cout << "d = " << d << '\n';
    std::array<int, S::c> a1; // OK : S::c est une expression constante
//  std::array<int, d> a2;    // erreur : d n'est pas une expression constante
}

Output:

d = 50

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 441 C++98 les références ne pouvaient pas être initialisées de façon constante rendues initialisables de façon constante
CWG 1489 C++11 il n'était pas clair si l'initialisation par valeur d'un objet peut être une initialisation constante il le peut
CWG 1747 C++11 lier une référence à une fonction ne pouvait pas être une initialisation constante il le peut
CWG 1834 C++11 lier une référence à une xvalue ne pouvait pas être une initialisation constante il le peut
