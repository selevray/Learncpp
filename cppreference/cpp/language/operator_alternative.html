Représentations alternatives des opérateurs

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Le code source C++ (et C) peut être écrit dans n'importe quel jeu de caractères 7 bits non ASCII incluant le jeu de caractères invariant ISO 646:1983. Cependant, plusieurs opérateurs et signes de ponctuation C++ requièrent des caractères situés en dehors du jeu de codes ISO 646 : {, }, [, ], #, \, ^, |, ~. Pour pouvoir utiliser des encodages de caractères où certains ou tous ces symboles n'existent pas (comme le DIN 66003 allemand), C++ définit les alternatives suivantes, composées de caractères compatibles ISO 646.

Jetons alternatifs

Il existe des graphies alternatives pour plusieurs opérateurs et autres jetons qui utilisent des caractères non ISO646. À tous égards dans le langage, chaque jeton alternatif se comporte exactement comme son jeton principal, sauf pour sa graphie (l'opérateur de stringification peut rendre la graphie visible). Les jetons alternatifs de deux lettres sont parfois appelés « digraphes ». Bien qu'il ait quatre lettres, %:%: est également considéré comme un digraphe.

Trigraphes (supprimés en C++17)

Les groupes de trois caractères suivants (trigraphes) sont analysés avant la reconnaissance des commentaires et des littéraux de chaîne, et chaque occurrence d'un trigraphe est remplacée par le caractère principal correspondant :

Principal Trigraphe
{ ??<
} ??>
[ ??(
] ??)
# ??=
\ ??/
^ ??'
` `
~ ??-

Comme les trigraphes sont traités tôt, un commentaire tel que // La ligne suivante sera-t-elle exécutée ?????/ commente effectivement la ligne suivante, et le littéral de chaîne tel que "Enter date ??/??/??" est analysé comme "Enter date \\??".

Notes

Les caractères & et ! sont invariants selon ISO-646, mais des alternatives sont tout de même prévues pour les jetons qui utilisent ces caractères, afin de s'adapter à des jeux de caractères historiques encore plus restrictifs.

Il n'existe pas de graphie alternative (telle que eq) pour l'opérateur d'égalité == car le caractère = était présent dans tous les jeux de caractères pris en charge.

Compatibilité avec C

Les mêmes mots sont définis dans le langage de programmation C dans le fichier d'en-tête <iso646.h> sous forme de macros. Comme en C++ ceux-ci sont intégrés au langage, la version C++ de <iso646.h>, ainsi que <ciso646>, ne définit rien. Les digraphes non alphabétiques (par ex. <%), en revanche, font partie du langage de base et peuvent être utilisés sans inclure d'en-tête (sinon ils seraient inutilisables sur tout jeu de caractères dépourvu de #).

Mots-clés

and, and_eq, bitand, bitor, compl, not, not_eq, or, or_eq, xor, xor_eq

Exemple

L'exemple suivant montre l'utilisation de plusieurs jetons alternatifs.

%:include <iostream>

struct X
<%
    compl X() <%%> // destructor
    X() <%%>
    X(const X bitand) = delete; // constructeur de copie
    // X(X and) = delete; // constructeur de déplacement

    bool operator not_eq(const X bitand other)
    <%
       return this not_eq bitand other;
    %>
%>;

int main(int argc, char* argv<::>)
<%
    // lambda avec capture par référence :
    auto greet = <:bitand:>(const char* name)
    <%
        std::cout << "Hello " << name
                  << " from " << argv<:0:> << '\n';
    %>;

    if (argc > 1 and argv<:1:> not_eq nullptr)
        greet(argv<:1:>);
    else
        greet("Anon");
%>

Hello Anon from ./a.out
