virtual spécificateur de fonction

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Le spécificateur virtual indique qu'une fonction membre non statique est virtuelle et prend en charge l'envoi dynamique. Il ne peut apparaître que dans le decl-specifier-seq de la déclaration initiale d'une fonction membre non statique (c'est-à-dire lorsqu'elle est déclarée dans la définition de la classe).

Explication

Les fonctions virtuelles sont des fonctions membres dont le comportement peut être redéfini dans les classes dérivées. Contrairement aux fonctions non virtuelles, ce comportement redéfini est conservé même en l'absence d'information à la compilation sur le type réel de la classe. Autrement dit, si une classe dérivée est manipulée via un pointeur ou une référence vers la classe de base, un appel à une fonction virtuelle redéfinie exécute le comportement défini dans la classe dérivée. Un tel appel de fonction est appelé appel de fonction virtuelle ou appel virtuel. L'appel virtuel est supprimé si la fonction est sélectionnée par recherche de nom qualifiée (c'est-à-dire si le nom de la fonction apparaît à droite de l'opérateur de résolution de portée ::).

#include <iostream>

struct Base
{
    virtual void f()
    {
        std::cout << "base\n";
    }
};

struct Derived : Base
{
    void f() override // « override » est facultatif
    {
        std::cout << "derived\n";
    }
};

int main()
{
    Base b;
    Derived d;

    // appel de fonction virtuelle via une référence
    Base& br = b; // le type de br est Base&
    Base& dr = d; // le type de dr est aussi Base&
    br.f(); // affiche "base"
    dr.f(); // affiche "derived"

    // appel de fonction virtuelle via un pointeur
    Base* bp = &b; // le type de bp est Base*
    Base* dp = &d; // le type de dp est aussi Base*
    bp->f(); // affiche "base"
    dp->f(); // affiche "derived"

    // appel de fonction non virtuel
    br.Base::f(); // affiche "base"
    dr.Base::f(); // affiche "base"
}

En détail

Si une fonction membre vf est déclarée comme virtual dans une classe Base, et qu'une classe Derived, dérivée directement ou indirectement de Base, contient une déclaration de fonction membre de même

  • name
  • liste de types de paramètres (mais pas type de retour)
  • qualificateurs cv
  • qualificateurs ref

Alors cette fonction de la classe Derived est également virtuelle (que le mot-clé virtual soit ou non utilisé dans sa déclaration) et redéfinit Base::vf (que le mot override soit ou non utilisé dans sa déclaration).

Base::vf n'a pas besoin d'être accessible ou visible pour être redéfinie. (Base::vf peut être déclarée private, ou Base peut être héritée par héritage privé. Les membres de même nom dans une classe de base de Derived qui hérite de Base n'entrent pas en compte dans la détermination de la redéfinition, même s'ils masquent Base::vf lors de la recherche de nom.)

class B
{
    virtual void do_f(); // membre privé
public:
    void f() { do_f(); } // interface publique
};

struct D : public B
{
    void do_f() override; // redéfinit B::do_f
};

int main()
{
    D d;
    B* bp = &d;
    bp->f(); // appelle en interne D::do_f();
}

Pour chaque fonction virtuelle, il existe la redéfinition finale, qui est exécutée lors d'un appel de fonction virtuelle. Une fonction membre virtuelle vf d'une classe de base Base est la redéfinition finale, sauf si la classe dérivée déclare ou hérite (par héritage multiple) une autre fonction qui redéfinit vf.

struct A { virtual void f(); };     // A::f est virtuelle
struct B : A { void f(); };         // B::f redéfinit A::f dans B
struct C : virtual B { void f(); }; // C::f redéfinit A::f dans C

struct D : virtual B {}; // D n'introduit pas de redéfinition, B::f est final dans D

struct E : C, D          // E n'introduit pas de redéfinition, C::f est final dans E
{
    using A::f; // ce n'est pas une déclaration de fonction, cela rend seulement A::f visible pour la recherche de nom
};

int main()
{
    E e;
    e.f();    // l'appel virtuel appelle C::f, le redéfinisseur final dans e
    e.E::f(); // l'appel non virtuel appelle A::f, qui est visible dans E
}

Si une fonction possède plus d'une redéfinition finale, le programme est mal formé :

struct A
{
    virtual void f();
};

struct VB1 : virtual A
{
    void f(); // redéfinit A::f
};

struct VB2 : virtual A
{
    void f(); // redéfinit A::f
};

// struct Error : VB1, VB2
// {
//     // Error: A::f possède deux redéfinitions finales dans Error
// };

struct Okay : VB1, VB2
{
    void f(); // OK: il s'agit de la redéfinition finale de A::f
};

struct VB1a : virtual A {}; // ne déclare pas de redéfinition

struct Da : VB1a, VB2
{
    // dans Da, la redéfinition finale de A::f est VB2::f
};

Une fonction de même nom mais de liste de paramètres différente ne redéfinit pas la fonction de base de même nom, mais la masque : lorsque la recherche de nom non qualifiée examine la portée de la classe dérivée, la recherche trouve la déclaration et n'examine pas la classe de base.

struct B
{
    virtual void f();
};

struct D : B
{
    void f(int); // D::f masque B::f (liste de paramètres incorrecte)
};

struct D2 : D
{
    void f(); // D2::f redéfinit B::f (peu importe qu'elle ne soit pas visible)
};

int main()
{
    B b;
    B& b_as_b = b;

    D d;
    B& d_as_b = d;
    D& d_as_d = d;

    D2 d2;
    B& d2_as_b = d2;
    D& d2_as_d = d2;

    b_as_b.f();  // appelle B::f()
    d_as_b.f();  // appelle B::f()
    d2_as_b.f(); // appelle D2::f()

    d_as_d.f();  // Error: la recherche dans D ne trouve que f(int)
    d2_as_d.f(); // Error: la recherche dans D ne trouve que f(int)
}

Si une fonction est déclarée avec le spécificateur override, mais ne redéfinit aucune fonction virtuelle, le programme est mal formé :

struct B
{
    virtual void f(int);
};

struct D : B
{
    virtual void f(int) override;  // OK, D::f(int) redéfinit B::f(int)
    virtual void f(long) override; // Error: f(long) ne redéfinit pas B::f(int)
};

Si une fonction est déclarée avec le spécificateur final, et qu'une autre fonction tente de la redéfinir, le programme est mal formé :

struct B
{
    virtual void f() const final;
};

struct D : B
{
    void f() const; // Error: D::f tente de redéfinir B::f final
};

(depuis C++11)

Les fonctions non membres et les fonctions membres statiques ne peuvent pas être virtuelles.

Les modèles de fonctions ne peuvent pas être déclarés virtual. Cela ne s'applique qu'aux fonctions qui sont elles-mêmes des modèles : une fonction membre ordinaire d'un modèle de classe peut être déclarée virtuelle.

Les fonctions virtuelles (qu'elles soient déclarées virtual ou qu'elles en redéfinissent une) ne peuvent avoir aucune contrainte associée.

struct A
{
    virtual void f() requires true; // Error: fonction virtuelle contrainte
};

Une fonction virtuelle consteval ne doit ni redéfinir ni être redéfinie par une fonction virtuelle non consteval.

(depuis C++20)

Les arguments par défaut des fonctions virtuelles sont substitués à la compilation.

Types de retour covariants

Si la fonction Derived::f redéfinit une fonction Base::f, leurs types de retour doivent être identiques ou être covariants. Deux types sont covariants s'ils satisfont toutes les exigences suivantes :

  • les deux types sont des pointeurs ou des références (lvalue ou rvalue) vers des classes. Les pointeurs ou références à plusieurs niveaux ne sont pas autorisés.
  • la classe référencée/pointée dans le type de retour de Base::f() doit être une classe de base directe ou indirecte, non ambiguë et accessible, de la classe référencée/pointée du type de retour de Derived::f().
  • le type de retour de Derived::f() doit être au même niveau ou moins qualifié cv que le type de retour de Base::f().

La classe du type de retour de Derived::f doit être soit Derived elle-même, soit un type complet au point de déclaration de Derived::f.

Lors d'un appel de fonction virtuelle, le type renvoyé par la redéfinition finale est implicitement converti vers le type de retour de la fonction redéfinie qui a été appelée :

class B {};

struct Base
{
    virtual void vf1();
    virtual void vf2();
    virtual void vf3();
    virtual B* vf4();
    virtual B* vf5();
};

class D : private B
{
    friend struct Derived; // dans Derived, B est une base accessible de D
};

class A; // la classe déclarée par anticipation est un type incomplet

struct Derived : public Base
{
    void vf1();    // virtuelle, redéfinit Base::vf1()
    void vf2(int); // non virtuelle, masque Base::vf2()
//  char vf3();    // Error: redéfinit Base::vf3, mais avec un type de retour différent
                   // et non covariant
    D* vf4();      // redéfinit Base::vf4() et a un type de retour covariant
//  A* vf5();      // Error: A est un type incomplet
};

int main()
{
    Derived d;
    Base& br = d;
    Derived& dr = d;

    br.vf1(); // appelle Derived::vf1()
    br.vf2(); // appelle Base::vf2()
//  dr.vf2(); // Error: vf2(int) masque vf2()

    B* p = br.vf4(); // appelle Derived::vf4() et convertit le résultat en B*
    D* q = dr.vf4(); // appelle Derived::vf4() et ne convertit pas le résultat en B*
}

Destructeur virtuel

Bien que les destructeurs ne soient pas hérités, si une classe de base déclare son destructeur virtual, le destructeur dérivé le redéfinit toujours. Cela permet de supprimer, par pointeur sur la base, des objets alloués dynamiquement de type polymorphe.

class Base
{
public:
    virtual ~Base() { /* libère les ressources de Base */ }
};

class Derived : public Base
{
    ~Derived() { /* libère les ressources de Derived */ }
};

int main()
{
    Base* b = new Derived;
    delete b; // Effectue un appel de fonction virtuelle vers Base::~Base()
              // comme elle est virtuelle, elle appelle Derived::~Derived() qui peut
              // libérer les ressources de la classe dérivée, puis appelle
              // Base::~Base() selon l'ordre habituel de destruction
}

De plus, si le destructeur de la classe de base n'est pas virtuel, supprimer un objet de classe dérivée via un pointeur sur la classe de base est un comportement indéfini, qu'il existe ou non des ressources qui seraient fuitées si le destructeur dérivé n'est pas invoqué, sauf si la fonction de désallocation sélectionnée est un operator delete destroying (depuis C++20).

Une règle pratique utile est que le destructeur de toute classe de base doit être public et virtuel ou protégé et non virtuel, dès lors que des expressions delete sont impliquées, par exemple lorsqu'elles sont utilisées implicitement dans std::unique_ptr (depuis C++11).

Pendant la construction et la destruction

Lorsqu'une fonction virtuelle est appelée directement ou indirectement depuis un constructeur ou un destructeur (y compris pendant la construction ou la destruction des membres de données non statiques de la classe, par exemple dans une liste d'initialisation de membres), et que l'objet concerné par l'appel est l'objet en cours de construction ou de destruction, la fonction appelée est la redéfinition finale dans la classe du constructeur ou du destructeur, et non celle qui la redéfinit dans une classe plus dérivée. Autrement dit, pendant la construction ou la destruction, les classes plus dérivées n'existent pas.

Lors de la construction d'une classe complexe à plusieurs branches, dans un constructeur appartenant à une branche, le polymorphisme est limité à cette classe et à ses bases : si elle obtient un pointeur ou une référence vers un sous-objet de base en dehors de cette sous-hiérarchie, et tente un appel de fonction virtuelle (par exemple via un accès explicite à un membre), le comportement est indéfini :

struct V
{
    virtual void f();
    virtual void g();
};

struct A : virtual V
{
    virtual void f(); // A::f est la redéfinition finale de V::f dans A
};

struct B : virtual V
{
    virtual void g(); // B::g est la redéfinition finale de V::g dans B
    B(V*, A*);
};

struct D : A, B
{
    virtual void f(); // D::f est la redéfinition finale de V::f dans D
    virtual void g(); // D::g est la redéfinition finale de V::g dans D

    // note : A est initialisée avant B
    D() : B((A*) this, this) {}
};

// le constructeur de B, appelé depuis le constructeur de D
B::B(V* v, A* a)
{
    f(); // appel virtuel à V::f (bien que D possède la redéfinition finale, D n'existe pas encore)
    g(); // appel virtuel à B::g, qui est la redéfinition finale dans B

    v->g(); // le type V de v est une base de B, l'appel virtuel appelle B::g comme précédemment

    a->f(); // le type A de a n'est pas une base de B. Il appartient à une autre branche de la
            // hiérarchie. Tenter un appel virtuel par cette branche provoque
            // un comportement indéfini, même si A était déjà entièrement construite dans ce
            // cas (elle a été construite avant B puisqu'elle apparaît avant B dans la liste
            // des bases de D). En pratique, l'appel virtuel à A::f sera
            // tenté en utilisant la table des fonctions membres virtuelles de B, puisque c'est
            // celle qui est active pendant la construction de B)
}
