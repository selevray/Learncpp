Nom de classe injecté

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Le nom de classe injecté est le nom non qualifié d'une classe dans la portée de ladite classe.

Dans un modèle de classe, le nom de classe injecté peut être utilisé soit comme nom de modèle désignant le modèle courant, soit comme nom de classe désignant l'instanciation courante.

Explication

Dans une portée de classe, le nom de la classe courante ou le nom de modèle du modèle de classe courant est traité comme s'il s'agissait d'un nom de membre public ; on parle de injected-class-name. Le point de déclaration de ce nom se situe immédiatement après l'accolade ouvrante de la définition de la classe (du modèle).

int X;

struct X
{
    void f()
    {
        X* p;   // OK, X est un nom de classe injecté
        ::X* q; // Erreur : la recherche de nom trouve un nom de variable, qui masque le nom de la struct
    }
};

template<class T>
struct Y
{
    void g()
    {
        Y* p;    // OK, Y est un nom de classe injecté
        Y<T>* q; // OK, Y est un nom de classe injecté, mais Y<T> ne l'est pas
    }
};

Comme les autres membres, les noms de classe injectés sont hérités. En présence d'un héritage privé ou protégé, le nom de classe injecté d'une classe de base indirecte peut se retrouver inaccessible dans une classe dérivée.

struct A {};
struct B : private A {};
struct C : public B
{
    A* p;   // Erreur : le nom de classe injecté A est inaccessible
    ::A* q; // OK, n'utilise pas le nom de classe injecté
};

Dans un modèle de classe

Le nom de classe injecté d'un modèle de classe peut être utilisé comme nom de modèle ou comme nom de type.

Dans les cas suivants, le nom de classe injecté est traité comme un nom de modèle du modèle de classe lui-même :

  • Il est suivi de <.
  • Il est utilisé comme argument de modèle de modèle.
  • C'est le dernier identifiant du spécificateur de classe élaboré d'une déclaration de modèle de classe amie.

Sinon, il est traité comme un nom de type, et équivaut au nom de modèle suivi des paramètres de modèle du modèle de classe, entre <>.

template<template<class, class> class>
struct A;

template<class T1, class T2>
struct X
{
    X<T1, T2>* p;   // OK, X est traité comme un nom de modèle

    using a = A<X>; // OK, X est traité comme un nom de modèle

    template<class U1, class U2>
    friend class X; // OK, X est traité comme un nom de modèle

    X* q;           // OK, X est traité comme un nom de type, équivalent à X<T1, T2>
};

Dans la portée d'une spécialisation ou d'une spécialisation partielle de modèle de classe, lorsque le nom de classe injecté est utilisé comme nom de type, il équivaut au nom de modèle suivi des arguments de modèle de la spécialisation ou spécialisation partielle, entre <>.

template<>
struct X<void, void>
{
    X* p; // OK, X est traité comme un nom de type, équivalent à X<void, void>

    template<class, class>
    friend class X; // OK, X est traité comme un nom de modèle (comme dans le modèle primaire)

    X<void, void>* q; // OK, X est traité comme un nom de modèle
};

template<class T>
struct X<char, T>
{
    X* p, q; // OK, X est traité comme un nom de type, équivalent à X<char, T>

    using r = X<int, int>; // OK, peut être utilisé pour désigner une autre spécialisation
};

Le nom de classe injecté d'un modèle de classe ou d'une spécialisation de modèle de classe peut être utilisé soit comme nom de modèle, soit comme nom de type, partout où il est dans la portée.

template<>
class X<int, char>
{
    class B
    {
        X a;            // signifie X<int, char>

        template<class, class>
        friend class X; // signifie ::X
    };
};

template<class T>
struct Base
{
    Base* p; // OK : Base signifie Base<T>
};

template<class T>
struct Derived : public Base<T*>
{
    typename Derived::Base* p; // OK : Derived::Base signifie Derived<T>::Base,
                               // soit Base<T*>
};

template<class T, template<class> class U = T::template Base>
struct Third {};

Third<Derived<int>> t; // OK : l'argument par défaut utilise le nom de classe injecté comme modèle

Une recherche qui trouve un nom de classe injecté peut produire une ambiguïté dans certains cas (par exemple, s'il est trouvé dans plus d'une classe de base). Si tous les noms de classe injectés trouvés désignent des spécialisations du même modèle de classe, et si le nom est utilisé comme nom de modèle, la référence désigne le modèle de classe lui-même et non une spécialisation, et elle n'est pas ambiguë.

template<class T>
struct Base {};

template<class T>
struct Derived: Base<int>, Base<char>
{
    typename Derived::Base b;         // erreur : ambigu
    typename Derived::Base<double> d; // OK
};

nom de classe injecté et constructeurs

Les constructeurs n'ont pas de nom, mais le nom de classe injecté de la classe englobante est considéré comme désignant un constructeur dans les déclarations et définitions de constructeurs.

Dans un nom qualifié C::D, si

  • la recherche de noms n'ignore pas les noms de fonctions, et
  • la recherche de D dans la portée de la classe C trouve son nom de classe injecté

le nom qualifié est toujours considéré comme désignant le constructeur de C. Un tel nom ne peut être utilisé que dans la déclaration d'un constructeur (par exemple dans une déclaration de constructeur ami, une spécialisation de modèle de constructeur, une instanciation de modèle de constructeur ou une définition de constructeur)ou pour hériter de constructeurs (depuis C++11).

struct A
{
    A();
    A(int);

    template<class T>
    A(T) {}
};
using A_alias = A;

A::A() {}
A_alias::A(int) {}
template A::A(double);

struct B : A
{
    using A_alias::A;
};

A::A a;         // Erreur : A::A est considéré comme désignant un constructeur, et non un type
struct A::A a2; // OK, identique à 'A a2;'
B::A b;         // OK, identique à 'A b;'

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 1004 C++98 un nom de classe injecté ne pouvait pas être un argument de modèle de modèle autorisé, il désigne dans ce cas le modèle de classe lui-même
CWG 2637 C++98 toute la template-id pouvait être un nom de classe injecté seul le nom de modèle le pouvait
