Espaces de noms

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les espaces de noms fournissent un moyen d'éviter les conflits de noms dans les grands projets.

Les entités déclarées à l'intérieur d'un bloc d'espace de noms sont placées dans une portée d'espace de noms, ce qui les empêche d'être confondues avec des entités de même nom dans d'autres portées.

Les entités déclarées en dehors de tout bloc d'espace de noms appartiennent à l'espace de noms global. L'espace de noms global appartient à la portée globale et peut être désigné explicitement par un :: initial. Bien qu'il n'ait pas de déclaration, l'espace de noms global n'est pas un espace de noms anonyme.

Plusieurs blocs d'espace de noms portant le même nom sont autorisés. Toutes les déclarations de ces blocs sont déclarées dans la même portée d'espace de noms.

Syntaxe

| | | | namespace ns-name { declarations } | (1) | | | | inline namespace ns-name { declarations } | (2) | (depuis C++11) | | | namespace { declarations } | (3) | | | | ns-name :: member-name | (4) | | | | using namespace ns-name ; | (5) | | | | using ns-name :: member-name ; | (6) | | | | namespace name = qualified-namespace ; | (7) | | | | namespace ns-name :: member-name { declarations } | (8) | (depuis C++17) | | | namespace ns-name :: inline member-name { declarations } | (9) | (depuis C++20) | |

  1. Définition d'espace de noms nommé pour l'espace de noms ns-name.

  2. Définition d'espace de noms en ligne pour l'espace de noms ns-name. Les déclarations situées dans ns-name seront visibles dans son espace de noms englobant.

  3. Définition d'espace de noms anonyme. Ses membres ont une portée potentielle allant de leur point de déclaration jusqu'à la fin de l'unité de traduction, et ont une liaison interne.

  4. Les noms d'espaces de noms (ainsi que les noms de classes) peuvent apparaître à gauche de l'opérateur de résolution de portée, dans le cadre d'une recherche de nom qualifié.

  5. Directive using : du point de vue de la recherche de nom non qualifié de tout nom situé après une directive using et jusqu'à la fin de la portée dans laquelle elle apparaît, chaque nom de ns-name est visible comme s'il était déclaré dans l'espace de noms englobant le plus proche qui contient à la fois la directive using et ns-name.

  6. Déclaration using : rend le symbole member-name de l'espace de noms ns-name accessible pour la recherche non qualifiée comme s'il était déclaré dans la même portée de classe, de bloc ou d'espace de noms que celle où apparaît cette déclaration using.

  7. namespace-alias-definition : fait de name un synonyme d'un autre espace de noms : voir alias d'espace de noms

  8. définition d'espace de noms imbriqué : namespace A::B::C { ... } équivaut à namespace A { namespace B { namespace C { ... } } }.

  9. définition d'espace de noms en ligne imbriqué : namespace A::B::inline C { ... } équivaut à namespace A::B { inline namespace C { ... } }. inline peut apparaître devant chaque nom d'espace de noms sauf le premier : namespace A::inline B::C {} équivaut à namespace A { inline namespace B { namespace C {} } }.

Explication

Espaces de noms

| | | | inline(facultatif) namespace attr ﻿*(facultatif)* identifier { namespace-body } | | | |

  • inline — (depuis C++11) si présent, fait de cet espace de noms un espace de noms en ligne (voir ci-dessous). Ne peut pas apparaître sur la définition d'espace de noms d'extension si la définition d'espace de noms originale n'utilisait pas inline
  • attr — (depuis C++17) séquence facultative d'un nombre quelconque d'attributs
  • identifier — either
    • un identifiant jusque-là inutilisé, auquel cas il s'agit de la définition d'espace de noms originale ;
    • le nom d'un espace de noms, auquel cas il s'agit de la définition d'espace de noms d'extension ;
    • une séquence de spécificateurs d'espaces de noms englobants séparés par ::, se terminant par identifier, auquel cas il s'agit d'une définition d'espace de noms imbriqué

    (depuis C++17)

  • namespace-body — séquence éventuellement vide de déclarations de tout type (y compris les définitions de classes et de fonctions ainsi que les espaces de noms imbriqués)

Les définitions d'espaces de noms ne sont autorisées que dans une portée d'espace de noms, y compris la portée globale.

Pour rouvrir un espace de noms existant (formellement, pour être une définition d'espace de noms d'extension), la recherche du identifier utilisé dans la définition d'espace de noms doit aboutir à un nom d'espace de noms (et non à un alias d'espace de noms), déclaré comme membre de l'espace de noms englobant ou d'un espace de noms en ligne situé dans un espace de noms englobant.

Le namespace-body définit une portée d'espace de noms, qui affecte la recherche de noms.

Tous les noms introduits par les déclarations figurant dans namespace-body (y compris les définitions d'espaces de noms imbriqués) deviennent membres de l'espace de noms identifier, que cette définition d'espace de noms soit la définition originale (qui a introduit identifier) ou une définition d'espace de noms d'extension (qui a « rouvert » l'espace de noms déjà défini)

Un membre d'espace de noms déclaré dans le corps d'un espace de noms peut être défini ou redéclaré en dehors de celui-ci, en utilisant une qualification explicite

namespace Q
{
    namespace V   // V est un membre de Q et est entièrement défini dans Q
    { // namespace Q::V { // variante C++17 équivalente aux lignes ci-dessus
        class C { void m(); }; // C est un membre de V et est entièrement défini dans V
                               // C::m n'est que déclaré
        void f(); // f est un membre de V, mais n'est ici que déclaré
    }

    void V::f() // définition du membre f de V en dehors de V
                // les espaces de noms englobant f sont toujours l'espace de noms global, Q et Q::V
    {
        extern void h(); // Ceci déclare ::Q::V::h
    }

    void V::C::m() // définition de V::C::m en dehors de l'espace de noms (et du corps de la classe)
                   // les espaces de noms englobants sont l'espace de noms global, Q et Q::V
    {}
}

Les définitions et redéclarations hors de l'espace de noms ne sont autorisées que

  • après le point de déclaration,
  • en portée d'espace de noms, et
  • dans les espaces de noms qui englobent l'espace de noms original (y compris l'espace de noms global).

De plus, elles doivent utiliser la syntaxe d'identifiant qualifié.

namespace Q
{
    namespace V    // définition d'espace de noms originale pour V
    {
        void f();  // déclaration de Q::V::f
    }

    void V::f() {} // OK
    void V::g() {} // Error: g() n'est pas encore un membre de V

    namespace V    // définition d'espace de noms d'extension pour V
    {
        void g();  // déclaration de Q::V::g
    }
}

namespace R           // pas un espace de noms englobant Q
{
    void Q::V::g() {} // Error: impossible de définir Q::V::g à l'intérieur de R
}

void Q::V::g() {}     // OK: l'espace de noms global englobe Q

Les noms introduits par des déclarations friend au sein d'une classe locale X deviennent membres de l'espace de noms englobant le plus interne de X, mais ils ne deviennent pas visibles pour la recherche de nom ordinaire (ni non qualifiée ni qualifiée), sauf si une déclaration correspondante est fournie en portée d'espace de noms, avant ou après la définition de la classe. Ce nom peut être trouvé par la ADL, qui considère à la fois les espaces de noms et les classes.

Seul l'espace de noms englobant le plus interne est pris en compte par une telle déclaration friend lorsqu'il s'agit de déterminer si le nom entre en conflit avec un nom déclaré précédemment.

void h(int);
namespace A
{
    class X
    {
        friend void f(X);       // A::f est un ami

        class Y
        {
            friend void g();    // A::g est un ami
            friend void h(int); // A::h est une amie, pas de conflit avec ::h
        };
    };
    // A::f, A::g et A::h ne sont pas visibles dans la portée de l'espace de noms
    // bien qu'elles soient membres de l'espace de noms A

    X x;
    void g()  // définition de A::g
    {
        f(x); // A::X::f est trouvée par ADL
    }

    void f(X) {}   // définition de A::f
    void h(int) {} // définition de A::h
    // A::f, A::g et A::h sont désormais visibles dans la portée de l'espace de noms
    // et elles sont aussi amies de A::X et A::X::Y
}

Espaces de noms en ligne

Un espace de noms en ligne est un espace de noms qui utilise le mot-clé facultatif inline dans sa définition d'espace de noms originale.

Les membres d'un espace de noms en ligne sont traités comme s'ils étaient membres de l'espace de noms englobant dans de nombreuses situations (listées ci-dessous). Cette propriété est transitive : si un espace de noms N contient un espace de noms en ligne M, lui-même contenant un espace de noms en ligne O, alors les membres de O peuvent être utilisés comme s'ils étaient membres de M ou de N.

  • Une directive using qui désigne l'espace de noms en ligne est implicitement insérée dans l'espace de noms englobant (de manière similaire à la directive using implicite pour l'espace de noms anonyme)
  • Dans la recherche dépendant des arguments, lorsqu'un espace de noms est ajouté à l'ensemble des espaces de noms associés, ses espaces de noms en ligne y sont aussi ajoutés, et lorsqu'un espace de noms en ligne est ajouté à la liste des espaces de noms associés, son espace de noms englobant y est aussi ajouté.
  • Chaque membre d'un espace de noms en ligne peut être partiellement spécialisé, explicitement instancié ou explicitement spécialisé comme s'il était membre de l'espace de noms englobant.
  • La recherche de nom qualifiée qui examine l'espace de noms englobant inclut les noms des espaces de noms en ligne, même si le même nom est présent dans l'espace de noms englobant.
// en C++14, std::literals et ses espaces de noms membres sont inline
{
    using namespace std::string_literals; // rend visible operator""s
                                          // depuis std::literals::string_literals
    auto str = "abc"s;
}

{
    using namespace std::literals; // rend visibles les deux
                                   // std::literals::string_literals::operator""s
                                   // et std::literals::chrono_literals::operator""s
    auto str = "abc"s;
    auto min = 60s;
}

{
    using std::operator""s; // rend visibles std::literals::string_literals::operator""s
                            // et std::literals::chrono_literals::operator""s
    auto str = "abc"s;
    auto min = 60s;
}

Remarque : la règle concernant les spécialisations permet la gestion de versions des bibliothèques : différentes implémentations d'un modèle de bibliothèque peuvent être définies dans différents espaces de noms en ligne, tout en permettant à l'utilisateur d'étendre l'espace de noms parent avec une spécialisation explicite du modèle primaire :

namespace Lib
{
    inline namespace Lib_1
    {
        template<typename T> class A;
    }

    template<typename T> void g(T) { /* ... */ }
}
/* ... */
struct MyClass { /* ... */ };
namespace Lib
{
    template<> class A<MyClass> { /* ... */ };
}

int main()
{
    Lib::A<MyClass> a;
    g(a);  // ok, Lib est un espace de noms associé de A
}

(depuis C++11)

Espaces de noms anonymes

La définition d'espace de noms anonyme est une définition d'espace de noms de la forme

| | | | inline(facultatif) namespace attr ﻿*(facultatif)* { namespace-body } | | | |

  • inline — (depuis C++11) s'il est présent, fait de cet espace de noms un espace de noms en ligne
  • attr — (depuis C++17) séquence facultative d'un nombre quelconque d'attributs

Cette définition est traitée comme la définition d'un espace de noms de nom unique, avec une using-directive dans la portée courante qui désigne cet espace de noms sans nom (Note : la using-directive ajoutée implicitement rend l'espace de noms accessible pour la recherche de nom qualifiée et la recherche de nom non qualifiée, mais pas pour la recherche dépendante des arguments). Le nom unique est unique dans tout le programme, mais, au sein d'une unité de traduction, chaque définition d'espace de noms sans nom correspond au même nom unique : plusieurs définitions d'espaces de noms sans nom dans la même portée désignent le même espace de noms sans nom.

namespace
{
    int i; // définit ::(unique)::i
}

void f()
{
    i++;   // incrémente ::(unique)::i
}

namespace A
{
    namespace
    {
        int i;        // A::(unique)::i
        int j;        // A::(unique)::j
    }

    void g() { i++; } // A::(unique)::i++
}

using namespace A; // introduit tous les noms de A dans l'espace de noms global

void h()
{
    i++;    // erreur : ::(unique)::i et ::A::(unique)::i sont tous deux dans la portée
    A::i++; // ok, incrémente ::A::(unique)::i
    j++;    // ok, incrémente ::A::(unique)::j
}

Bien que les noms d'un espace de noms sans nom puissent être déclarés avec une liaison externe, ils ne sont jamais accessibles depuis d'autres unités de traduction, car leur nom d'espace de noms est unique.

(jusqu'à C++11)

Les espaces de noms sans nom, ainsi que tous les espaces de noms déclarés directement ou indirectement dans un espace de noms sans nom, ont une liaison interne, ce qui signifie que tout nom déclaré dans un espace de noms sans nom a une liaison interne.

(depuis C++11)

Déclarations using

Introduit un nom défini ailleurs dans la région déclarative où apparaît cette déclaration using.

| | | | using typename(facultatif) nested-name-specifier unqualified-id ; | | (jusqu'à C++17) | | | using declarator-list ; | | (depuis C++17) | |

  • typename — le mot-clé typename peut être utilisé si nécessaire pour résoudre les noms dépendants, lorsque la déclaration using introduit un type membre d'une classe de base dans un modèle de classe
  • nested-name-specifier — une suite de noms et d'opérateurs de résolution de portée ::, se terminant par un opérateur de résolution de portée. Un :: seul désigne l'espace de noms global.
  • unqualified-id — un id-expression
  • declarator-list — une liste séparée par des virgules d'un ou plusieurs déclarateurs de la forme typename(facultatif) nested-name-specifier unqualified-id. Un déclarateur peut être suivi d'une ellipse pour indiquer une expansion de paquet, bien que cette forme n'ait de sens que dans les définitions de classes dérivées

Les déclarations using peuvent être utilisées pour introduire des membres d'espaces de noms dans d'autres espaces de noms et portées de bloc, ou pour introduire des membres de classe de base dans les définitions de classes dérivées, ou pour introduire des énumérateurs dans les portées d'espaces de noms, de blocs et de classes (depuis C++20).

Une déclaration using comportant plusieurs déclarateurs using est équivalente à une suite correspondante de déclarations using comportant chacune un seul déclarateur using.

(depuis C++17)

Pour l'utilisation dans les définitions de classes dérivées, voir déclaration using.

Les noms introduits dans une portée d'espace de noms par une déclaration using peuvent être utilisés exactement comme les autres noms, y compris par la recherche qualifiée depuis d'autres portées :

void f();
namespace A
{
    void g();
}

namespace X
{
    using ::f;        // la fonction globale f est désormais visible sous le nom ::X::f
    using A::g;       // A::g est désormais visible sous le nom ::X::g
    using A::g, A::g; // (C++17) OK : double déclaration autorisée dans la portée de l'espace de noms
}

void h()
{
    X::f(); // appelle ::f
    X::g(); // appelle A::g
}

Si, après qu'une déclaration using a été utilisée pour prendre un membre d'un espace de noms, cet espace de noms est étendu et que des déclarations supplémentaires pour le même nom sont introduites, ces déclarations supplémentaires ne deviennent pas visibles par l'intermédiaire de la déclaration using (contrairement à la using-directive). Une exception concerne le cas où une déclaration using désigne un modèle de classe : les spécialisations partielles introduites ultérieurement sont effectivement visibles, car leur recherche passe par le modèle primaire.

namespace A
{
    void f(int);
}
using A::f; // ::f est désormais un synonyme de A::f(int)

namespace A       // extension d'espace de noms
{
    void f(char); // ne modifie pas la signification de ::f
}

void foo()
{
    f('a'); // appelle f(int), bien que f(char) existe.
}

void bar()
{
    using A::f; // ce f est un synonyme à la fois de A::f(int) et de A::f(char)
    f('a');     // appelle f(char)
}

Les déclarations using ne peuvent pas désigner un template-id, ni un espace de noms, ni un énumérateur à portée (jusqu'à C++20). Chaque déclarateur d'une déclaration using introduit un seul et unique nom ; par exemple, une déclaration using pour une énumération n'introduit aucun de ses énumérateurs.

Toutes les restrictions applicables aux déclarations ordinaires des mêmes noms, ainsi que les règles de masquage et de surcharge, s'appliquent aux déclarations using :

namespace A
{
    int x;
}

namespace B
{
    int i;
    struct g {};
    struct x {};

    void f(int);
    void f(double);
    void g(char); // OK : le nom de fonction g masque la structure g
}

void func()
{
    int i;
    using B::i;   // erreur : i déclaré deux fois

    void f(char);
    using B::f;   // OK : f(char), f(int), f(double) sont des surcharges
    f(3.5);       // appelle B::f(double)

    using B::g;
    g('a');       // appelle B::g(char)
    struct g g1;  // déclare g1 de type struct B::g

    using B::x;
    using A::x;   // OK : masque la structure B::x
    x = 99;       // affecte A::x
    struct x x1;  // déclare x1 de type struct B::x
}

Si une fonction a été introduite par une déclaration using, déclarer une fonction de même nom et de même liste de paramètres est mal formé (sauf si la déclaration concerne la même fonction). Si un modèle de fonction a été introduit par une déclaration using, déclarer un modèle de fonction de même nom, même liste de types de paramètres, même type de retour et même liste de paramètres de modèle est mal formé. Deux déclarations using peuvent introduire des fonctions de même nom et de même liste de paramètres, mais si un appel à cette fonction est tenté, le programme est mal formé.

namespace B
{
    void f(int);
    void f(double);
}

namespace C
{
    void f(int);
    void f(double);
    void f(char);
}

void h()
{
    using B::f;  // introduit B::f(int), B::f(double)
    using C::f;  // introduit C::f(int), C::f(double) et C::f(char)
    f('h');      // appelle C::f(char)
    f(1);        // erreur : B::f(int) ou C::f(int) ?
    void f(int); // erreur : f(int) est en conflit avec C::f(int) et B::f(int)
}

Si une entité est déclarée, mais non définie, dans un espace de noms interne, puis déclarée par une déclaration using dans l'espace de noms externe, et si une définition apparaît ensuite dans l'espace de noms externe avec le même nom non qualifié, cette définition est un membre de l'espace de noms externe et entre en conflit avec la déclaration using :

namespace X
{
    namespace M
    {
        void g(); // déclare, mais ne définit pas X::M::g()
    }
    using M::g;

    void g();     // Erreur : tentative de déclarer X::g, en conflit avec X::M::g()
}

De manière plus générale, une déclaration qui apparaît dans une portée d'espace de noms quelconque et qui introduit un nom à l'aide d'un identifiant non qualifié introduit toujours un membre dans l'espace de noms où elle se trouve, et non dans un autre espace de noms. Les exceptions sont les instanciations explicites et les spécialisations explicites d'un modèle primaire défini dans un espace de noms en ligne : comme elles n'introduisent pas de nouveau nom, elles peuvent utiliser un unqualified-id dans un espace de noms englobant.

Directives using

Une using-directive est une block-declaration de la syntaxe suivante :

| | | | attr ﻿*(facultatif)* using namespace nested-name-specifier ﻿*(facultatif)* namespace-name ; | (1) | | |

  • attr — (depuis C++11) un nombre quelconque d'attributs s'appliquant à cette using-directive
  • nested-name-specifier — une suite de noms et d'opérateurs de résolution de portée ::, se terminant par un opérateur de résolution de portée. Un :: seul désigne l'espace de noms global. Lors de la recherche des noms de cette suite, la recherche ne prend en compte que les déclarations d'espaces de noms
  • namespace-name — un nom d'espace de noms. Lors de la recherche de ce nom, la recherche ne prend en compte que les déclarations d'espaces de noms

Les using-directives ne sont autorisées que dans une portée d'espace de noms et dans une portée de bloc. Du point de vue de la recherche de nom non qualifiée de tout nom situé après une using-directive et jusqu'à la fin de la portée où elle apparaît, chaque nom de namespace-name est visible comme s'il était déclaré dans l'espace de noms englobant le plus proche qui contient à la fois la using-directive et namespace-name.

Une using-directive n'ajoute aucun nom à la région déclarative dans laquelle elle apparaît (contrairement à la déclaration using), et n'empêche donc pas la déclaration de noms identiques.

Les using-directives sont transitives pour les besoins de la recherche non qualifiée : si une portée contient une using-directive désignant un namespace-name, qui contient lui-même une using-directive pour un namespace-name-2, l'effet est le même que si les using-directives du second espace de noms apparaissaient à l'intérieur du premier. L'ordre dans lequel ces espaces de noms transitifs apparaissent n'influence pas la recherche de noms.

namespace A
{
    int i;
}

namespace B
{
    int i;
    int j;

    namespace C
    {
        namespace D
        {
            using namespace A;
            // Les noms de A sont « injectés » dans D.
            // La recherche non qualifiée dans D considère ces noms comme ayant la même
            // portée que l'espace de noms global (par exemple pour le masquage de noms).
            // La recherche qualifiée faisant référence à D (D::name pour un nom donné)
            // trouvera le même nom que la recherche non qualifiée dans D.

            int j;
            int k;
            int a = i;   // i est B::i, car A::i est masqué par B::i
            int b = ::i; // erreur : il n'existe toujours pas de i dans l'espace de noms global
        }

        using namespace D; // les noms de D et A sont injectés dans C

        int k = 89; // OK de déclarer un nom identique à un nom introduit par un using
        int l = k;  // ambigu : C::k ou D::k
        int m = i;  // ok : B::i masque A::i
        int n = j;  // ok : D::j masque B::j
    }
}

// Ce sont toutes des définitions équivalentes :
int t0 = B::i;
int t1 = B::C::a;
int t2 = B::C::D::a;

Si, après qu'une using-directive a été utilisée pour désigner un espace de noms, cet espace de noms est étendu et que des membres supplémentaires et/ou des using-directives y sont ajoutés, ces membres supplémentaires et ces espaces de noms supplémentaires sont visibles par l'intermédiaire de la using-directive (contrairement à la déclaration using)

namespace D
{
    int d1;
    void f(char);
}
using namespace D; // introduit D::d1, D::f, D::d2, D::f,
                   // E::e et E::f dans l'espace de noms global !

int d1;            // OK : pas de conflit avec D::d1 lors de la déclaration de

namespace E
{
    int e;
    void f(int);
}

namespace D            // extension d'espace de noms
{
    int d2;
    using namespace E; // directive using transitive
    void f(int);
}

void f()
{
    d1++;    // erreur : ambigu ::d1 ou D::d1 ?
    ::d1++;  // OK
    D::d1++; // OK
    d2++;    // OK, d2 est D::d2

    e++;     // OK : e est E::e grâce à la directive using transitive

    f(1);    // erreur : ambigu : D::f(int) ou E::f(int) ?
    f('a');  // OK : le seul f(char) est D::f(char)
}

Notes

La using-directive using namespace std; placée dans une portée d'espace de noms quelconque introduit chaque nom de l'espace de noms std dans l'espace de noms global (puisque l'espace de noms global est l'espace de noms englobant le plus proche qui contient à la fois std et tout espace de noms déclaré par l'utilisateur), ce qui peut provoquer des collisions de noms indésirables. Celle-ci, comme d'autres using-directives, est généralement considérée comme une mauvaise pratique au niveau de la portée de fichier d'un en-tête (SF.7 : N'écrivez pas using namespace dans la portée globale d'un en-tête).

Macro de test de fonctionnalité Valeur Std Fonctionnalité
__cpp_namespace_attributes 201411L (C++17) Attributs pour les espaces de noms

Mots-clés

namespace, using, inline

Exemple

Cet exemple montre comment utiliser un espace de noms pour créer une classe qui a déjà été nommée dans l'espace de noms std.

#include <vector>

namespace vec
{
    template<typename T>
    class vector
    {
        // ...
    };
} // de vec

int main()
{
    std::vector<int> v1; // vector standard.
    vec::vector<int> v2; // vector défini par l'utilisateur.

    // v1 = v2;          // Erreur : v1 et v2 sont d'un type d'objet différent.

    {
        using namespace std;
        vector<int> v3;  // Identique à std::vector
        v1 = v3; // OK
    }

    {
        using vec::vector;
        vector<int> v4;  // Identique à vec::vector
        v2 = v4; // OK
    }
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
