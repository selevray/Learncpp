Déclarations en conflit

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Sauf indication contraire, deux déclarations ne peuvent pas (re)introduire la même entité. Le programme est mal formé si de telles déclarations existent.

Déclarations correspondantes

Deux déclarations correspondent si elles (re)introduisent le même nom, si elles déclarent toutes deux des constructeurs, ou toutes deux des destructeurs, sauf si

  • l'une est une déclaration using,
  • l'une déclare un type (et non un nom de typedef) et l'autre déclare une variable, un membre de données non statique autre qu'un membre d'une union anonyme, un énumérateur, une fonction ou un modèle de fonction, ou
  • chacune déclare une fonction ou un modèle de fonction et elles ne déclarent pas de surcharges correspondantes.

Surcharges de fonctions correspondantes

Deux déclarations de fonctions déclarent des surcharges correspondantes si toutes deux déclarent des fonctions satisfaisant toutes les conditions suivantes :

  • Elles ont la même liste de types de paramètres, en omettant les types des paramètres d'objet explicites (depuis C++23).
  • Elles ont des requires clauses finales équivalentes (le cas échéant, sauf les déclarations d'amitié).

(depuis C++20)

  • Si toutes deux sont des fonctions membres non statiques, elles doivent en outre satisfaire l'une des exigences suivantes :
  • Exactement l'une d'elles est une fonction membre à paramètre d'objet implicite sans qualificateur ref, et les types de leurs paramètres d'objet, après suppression des références de premier niveau, sont les mêmes.

(depuis C++23)

  • Leurs paramètres d'objet ont le même type.

Surcharges de modèles de fonctions correspondantes

Deux déclarations de modèles de fonctions déclarent des surcharges correspondantes si toutes deux déclarent des modèles de fonctions satisfaisant toutes les conditions suivantes :

  • Leurs listes de paramètres de modèle ont la même longueur.
  • Leurs paramètres de modèle correspondants sont équivalents.
  • Elles ont des listes de types de paramètres équivalentes, en omettant les types des paramètres d'objet explicites (depuis C++23).
  • Elles ont des types de retour équivalents.
  • Leurs paramètres de modèle correspondants sont soit tous deux déclarés sans contrainte, soit tous deux déclarés avec des contraintes équivalentes.
  • Elles ont des requires clauses finales équivalentes (le cas échéant).

(depuis C++20)

  • Si toutes deux sont des modèles de fonctions membres non statiques, elles doivent en outre satisfaire l'une des exigences suivantes :
  • Exactement l'un d'eux est un modèle de fonction membre à paramètre d'objet implicite sans qualificateur ref, et les types de leurs paramètres d'objet, après suppression de toutes les références, sont équivalents.

(depuis C++23)

  • Leurs paramètres d'objet ont des types équivalents.
struct A
{
    friend void c();   // #1
};

struct B
{
    friend void c() {} // correspond à #1 et le définit
};

typedef int Int;

enum E : int { a };

void f(int);   // #2
void f(Int) {} // defines #2
void f(E) {}   // OK, autre surcharge

struct X
{
    static void f();
    void f() const;   // error: redeclaration

    void g();
    void g() const;   // OK
    void g() &;       // error: redeclaration

    void h(this X&, int);
    void h(int) &&;   // OK, autre surcharge

    void j(this const X&);
    void j() const &; // error: redeclaration

    void k();
    void k(this X&);  // error: redeclaration
};

Déclarations multiples de la même entité

Une déclaration est indépendante du nom si son nom est _ et qu'elle déclare

  • une variable à durée de stockage automatique,
  • une liaison structurée sans spécificateur de classe de stockage et ne résidant pas dans une portée d'espace de noms,
  • la variable introduite par une capture de lambda avec un initialiseur, ou
  • un membre de données non statique autre qu'une union anonyme.

(depuis C++26)

Sauf indication contraire, deux déclarations d'entités déclarent la même entité si toutes les conditions suivantes sont satisfaites, en considérant que les déclarations de types sans nom introduisent leurs noms de typedef et leurs noms d'énumération à des fins de liaison (le cas échéant) :

  • Elles se correspondent.
  • Elles ont la même portée cible, qui n'est ni une portée de paramètre de fonction ni une portée de paramètre de modèle.
  • Aucune n'est une déclaration indépendante du nom.

(depuis C++26)

  • L'une des conditions suivantes est satisfaite :
    • Elles apparaissent dans la même unité de traduction.
  • Elles déclarent toutes deux des noms à liaison de module et sont rattachées au même module.

(depuis C++20)

  • Elles déclarent toutes deux des noms à liaison externe.

Une déclaration d'une entité ou d'un nom de typedef X est une redéclaration de X si une autre déclaration de X est accessible à partir d'elle.

Restrictions

Si deux déclarations quelconques d'une entité E violent la restriction correspondante ci-dessous, le programme est mal formé :

  • Si l'une déclare E comme une variable, l'autre doit aussi déclarer E comme une variable du même type.
  • Si l'une déclare E comme une fonction, l'autre doit aussi déclarer E comme une fonction du même type.
  • Si l'une déclare E comme un énumérateur, l'autre doit aussi déclarer E comme un énumérateur.
  • Si l'une déclare E comme un espace de noms, l'autre doit aussi déclarer E comme un espace de noms.
  • Si l'une déclare E comme un type classe, l'autre doit aussi déclarer E comme un type classe.
  • Si l'une déclare E comme un type énumération, l'autre doit aussi déclarer E comme un type énumération.
  • Si l'une déclare E comme un modèle de classe, l'autre doit aussi déclarer E comme un modèle de classe avec une liste de paramètres de modèle équivalente (voir surcharge de modèles de fonctions).
  • Si l'une déclare E comme un modèle de fonction, l'autre doit aussi déclarer E comme un modèle de fonction avec une liste de paramètres de modèle et un type équivalents.
  • Si l'une déclare E comme un modèle d'alias, l'autre doit aussi déclarer E comme un modèle d'alias avec une liste de paramètres de modèle équivalente et type-id.

(depuis C++11)

  • Si l'une déclare E comme un (spécialisation partielle de) modèle de variable, l'autre doit aussi déclarer E comme un (spécialisation partielle de) modèle de variable avec une liste de paramètres de modèle et un type équivalents.

(depuis C++14)

  • Si l'une déclare E comme un concept, l'autre doit aussi déclarer E comme un concept.

(depuis C++20)

Les types sont comparés après tous les ajustements de types (au cours desquels les typedefs sont remplacés par leurs définitions). Les déclarations d'un objet tableau peuvent spécifier des types tableau qui diffèrent par la présence ou l'absence d'une borne majeure de tableau. Aucun diagnostic n'est requis si aucune des deux déclarations n'est accessible depuis l'autre.

void g();      // #1
void g(int);   // OK, entité différente de #1 (elles ne se correspondent pas)
int g();       // Error: même entité que #1 avec un type différent

void h();      // #2
namespace h {} // Error: même entité que #2, mais pas une fonction

Si une déclaration H qui déclare un nom à liaison interne précède une déclaration D dans une autre unité de traduction U et déclarerait la même entité que D si elle apparaissait dans U, le programme est mal formé.

Déclarations potentiellement en conflit

Deux déclarations sont potentiellement en conflit si elles se correspondent mais déclarent des entités différentes.

Si, dans une portée quelconque, un nom est lié à deux déclarations A et B potentiellement en conflit, B n'est pas indépendante du nom (depuis C++26), et A précède B, le programme est mal formé :

void f()
{
    int x, y;
    void x(); // Error: entité différente pour x
    int y;    // Error: redéfinition
}

enum { f };   // Error: entité différente pour ::f

namespace A {}
namespace B = A;
namespace B = A; // OK, aucun effet
namespace B = B; // OK, aucun effet
namespace A = B; // OK, aucun effet
namespace B {}   // Error: entité différente pour B

void g()
{
    int _;
    _ = 0; // OK
    int _; // OK depuis C++26, déclaration indépendante du nom
    _ = 0; // Error: deux déclarations non fonctions dans l'ensemble de recherche
}

void h ()
{
    int _;        // #1
    _ ++;         // OK
    static int _; // Error: en conflit avec #1 car
                  // les variables statiques ne sont pas indépendantes du nom
}
