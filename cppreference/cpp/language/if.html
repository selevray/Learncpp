Instruction if

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Exécute conditionnellement une autre instruction.

Utilisé lorsque du code doit être exécuté selon une condition, ou selon que l'instruction if est évaluée dans un contexte manifestement évalué à la compilation (depuis C++23).

Condition

Une condition peut être soit une expression, soit une déclaration simple.

  • Si elle peut être syntaxiquement interprétée comme une déclaration de liaison structurée, elle est interprétée comme une déclaration de liaison structurée.

(depuis C++26)

  • Si elle peut être syntaxiquement interprétée comme une expression, elle est traitée comme une expression. Sinon, elle est traitée comme une déclarationqui n'est pas une déclaration de liaison structurée (depuis C++26).

Lorsque le contrôle atteint la condition, celle-ci fournit une valeur, utilisée pour déterminer vers quelle branche le contrôle se dirige.

Expression

Si condition est une expression, la valeur qu'elle produit est la valeur de l'expression convertie contextuellement en bool. Si cette conversion est mal formée, le programme est mal formé.

Déclaration

Si condition est une déclaration simple, la valeur qu'elle produit est la valeur de la variable de décision (voir ci-dessous) convertie contextuellement en bool. Si cette conversion est mal formée, le programme est mal formé.

Déclaration hors liaison structurée

La déclaration a les restrictions suivantes :

  • Se conforme syntaxiquement à la forme suivante :
  • type-specifier-seq declarator = assignment-expression

(jusqu'à C++11)

  • attribute-specifier-seq(facultatif) decl-specifier-seq declarator brace-or-equal-initializer

(depuis C++11)

  • Le déclarateur ne peut pas spécifier une fonction ni un tableau.
  • La [séquence de spécificateurs de type (jusqu'à C++11) | séquence de spécificateurs de déclaration ne peut contenir que des spécificateurs de type et constexpr, et elle (depuis C++11)] ne peut pas définir une classe ni une énumération.

La variable de décision de la déclaration est la variable déclarée.

Déclaration de liaison structurée

La déclaration a les restrictions suivantes :

  • La expression de son initialiseur ne peut pas être d'un type tableau.
  • La séquence de spécificateurs de déclaration ne peut contenir que des spécificateurs de type et constexpr.

La variable de décision de la déclaration est la variable inventée e introduite par la déclaration.

(depuis C++26)

Sélection de branche

Si condition donne true, statement-true est exécuté.

Si la partie else de l'instruction if est présente et que condition donne false, statement-false est exécuté.

Si la partie else de l'instruction if est présente et que statement-true est également une instruction if, alors cette instruction if interne doit également contenir une partie else (autrement dit, dans les instructions if imbriquées, le else est associé au if le plus proche qui n'a pas encore de else associé).

#include <iostream>

int main()
{
    // instruction if simple avec une clause else
    int i = 2;
    if (i > 2)
        std::cout << i << " is greater than 2\n";
    else
        std::cout << i << " is not greater than 2\n";

    // instruction if imbriquée
    int j = 1;
    if (i > 1)
        if (j > 2)
            std::cout << i << " > 1 and " << j << " > 2\n";
        else // ce else fait partie de if (j > 2), et non de if (i > 1)
            std::cout << i << " > 1 and " << j << " <= 2\n";

    // des déclarations peuvent être utilisées comme conditions avec dynamic_cast
    struct Base
    {
        virtual ~Base() {}
    };

    struct Derived : Base
    {
        void df() { std::cout << "df()\n"; }
    };

    Base* bp1 = new Base;
    Base* bp2 = new Derived;

    if (Derived* p = dynamic_cast<Derived*>(bp1)) // le cast échoue, retourne nullptr
        p->df(); // non exécuté

    if (auto p = dynamic_cast<Derived*>(bp2)) // le cast réussit
        p->df(); // executed
}

Output:

2 is not greater than 2
2 > 1 and 1 <= 2
df()

Constexpr if

L'instruction qui commence par if constexpr est appelée instruction constexpr if. Toutes les sous-instructions d'une instruction constexpr if sont des instructions à flux de contrôle limité.

Dans une instruction constexpr if, condition doit être [une expression constante convertie contextuellement en type bool (jusqu'à C++23) | une expression convertie contextuellement en bool, où la conversion est une expression constante (depuis C++23)].

Si condition vaut true, alors statement-false est ignorée (si présente), sinon, statement-true est ignorée.

Les instructions return d'une instruction ignorée ne participent pas à la déduction du type de retour de fonction :

template<typename T>
auto get_value(T t)
{
    if constexpr (std::is_pointer_v<T>)
        return *t; // déduit le type de retour int pour T = int*
    else
        return t;  // déduit le type de retour int pour T = int
}

L'instruction ignorée peut effectuer un ODR-use sur une variable qui n'est pas définie :

extern int x; // aucune définition de x requise

int f()
{
    if constexpr (true)
        return 0;
    else if (x)
        return x;
    else
        return -x;
}

En dehors d'un modèle, une instruction ignorée est entièrement vérifiée. if constexpr ne remplace pas la directive de préprocesseur #if :

void f()
{
    if constexpr(false)
    {
        int i = 0;
        int *p = i; // Erreur bien que dans une instruction ignorée
    }
}

Si une instruction constexpr if apparaît dans une entité templatisée, et si condition n'est pas dépendante de la valeur après instanciation, l'instruction ignorée n'est pas instanciée lorsque le modèle englobant est instancié.

template<typename T, typename ... Rest>
void g(T&& p, Rest&& ...rs)
{
    // ... gère p
    if constexpr (sizeof...(rs) > 0)
        g(rs...); // jamais instanciée avec une liste d'arguments vide
}

La condition reste dépendante de la valeur après instanciation dans un modèle imbriqué :

template<class T>
void g()
{
    auto lm = [=](auto p)
    {
        if constexpr (sizeof(T) == 1 && sizeof p == 1)
        {
            // cette condition reste dépendante de la valeur après instanciation de g<T>,
            // ce qui affecte les captures implicites de lambda
            // cette instruction composée ne peut être ignorée qu'après
            // instanciation du corps de la lambda
        }
    };
}

L'instruction ignorée ne peut pas être mal formée pour toute spécialisation possible :

template<typename T>
void f()
{
    if constexpr (std::is_arithmetic_v<T>)
        // ...
    else {
        using invalid_array = int[-1]; // mal formé : invalide pour tout T
        static_assert(false, "Must be arithmetic"); // mal formé avant CWG2518
    }
}

La solution de contournement courante avant l'implémentation de CWG issue 2518 pour une telle instruction fourre-tout est une expression dépendante du type qui vaut toujours false :

template<typename>
constexpr bool dependent_false_v = false;

template<typename T>
void f()
{
    if constexpr (std::is_arithmetic_v<T>)
        // ...
    else {
        // solution de contournement avant CWG2518
        static_assert(dependent_false_v<T>, "Must be arithmetic");
    }
}

Une déclaration typedef ou une déclaration d'alias (depuis C++23) peut être utilisée comme init-statement d'une instruction constexpr if pour réduire la portée de l'alias de type.

Consteval if

L'instruction qui commence par if consteval est appelée instruction consteval if. Toutes les sous-instructions d'une instruction consteval if sont des instructions à flux de contrôle limité.

statement doit être une instruction composée, et elle sera tout de même traitée comme faisant partie de l'instruction consteval if même si ce n'est pas une instruction composée (ce qui entraîne une erreur de compilation) :

constexpr void f(bool b)
{
    if (true)
        if consteval {}
        else ; // erreur : pas une instruction composée
               // else non associé au if externe
}

Si une instruction consteval if est évaluée dans un contexte d'évaluation constante manifeste, compound-statement est exécutée. Sinon, statement est exécutée si elle est présente.

Si l'instruction commence par if !consteval, les compound-statement et statement (le cas échéant) doivent tous deux être des instructions composées. De telles instructions ne sont pas considérées comme des instructions consteval if, mais sont équivalentes à des instructions consteval if :

  • if !consteval {/* stmt */ } est équivalent à
    if consteval {} else {/* stmt */}.

  • if !consteval {/* stmt-1 */} else {/* stmt-2 */} est équivalent à
    if consteval {/* stmt-2 */} else {/* stmt-1 */}.

compound-statement dans une instruction consteval if (ou statement sous forme négative) se trouve dans un contexte de fonction immédiate, dans lequel un appel à une fonction immédiate n'a pas besoin d'être une expression constante.

#include <cmath>
#include <cstdint>
#include <cstring>
#include <iostream>

constexpr bool is_constant_evaluated() noexcept
{
    if consteval { return true; } else { return false; }
}

constexpr bool is_runtime_evaluated() noexcept
{
    if not consteval { return true; } else { return false; }
}

consteval std::uint64_t ipow_ct(std::uint64_t base, std::uint8_t exp)
{
    if (!base) return base;
    std::uint64_t res{1};
    while (exp)
    {
        if (exp & 1) res *= base;
        exp /= 2;
        base *= base;
    }
    return res;
}

constexpr std::uint64_t ipow(std::uint64_t base, std::uint8_t exp)
{
    if consteval // utiliser un algorithme adapté à la compilation
    {
        return ipow_ct(base, exp);
    }
    else // utiliser une évaluation à l'exécution
    {
        return std::pow(base, exp);
    }
}

int main(int, const char* argv[])
{
    static_assert(ipow(0, 10) == 0 && ipow(2, 10) == 1024);
    std::cout << ipow(std::strlen(argv[0]), 3) << '\n';
}

(depuis C++23)

Notes

Si statement-true ou statement-false n'est pas une instruction composée, elle est traitée comme si elle l'était :

if (x)
    int i;
// i n'est plus dans la portée

est identique à

if (x)
{
    int i;
}
// i n'est plus dans la portée

La portée du nom introduit par condition, s'il s'agit d'une déclaration, est la portée combinée des corps des deux instructions :

if (int x = f())
{
    int x; // erreur : redéclaration de x
}
else
{
    int x; // erreur : redéclaration de x
}

Si statement-true est atteint par goto ou longjmp, condition n'est pas évaluée et statement-false n'est pas exécutée.

Les conversions intégrées ne sont pas autorisées dans la condition d'une instruction constexpr if, sauf les conversions non rétrécissantes entières vers bool.
