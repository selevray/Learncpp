Lancer des exceptions

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Lancer une exception transfère le contrôle à un gestionnaire.

Une exception peut être levée depuis des expressions throw, les contextes suivants pouvant également lever des exceptions :

  • fonctions d'allocation
  • dynamic_cast
  • typeid
  • expressions new
  • fonctions de la bibliothèque standard

Objet exception

Lever une exception initialise un objet à durée de stockage dynamique, appelé objet exception.

Si le type de l'objet exception est l'un des types suivants, le programme est mal formé :

  • un type incomplet
  • un type classe abstraite
  • un pointeur vers un type incomplet autre que (éventuellement qualifié cv) void

Construction et destruction des objets exception

Étant donné le type de l'objet exception comme T :

  • Soit obj une lvalue de type const T, l'initialisation par copie d'un objet de type T à partir de obj doit être bien formée.
  • Si T est un type classe :
    • Le constructeur sélectionné est odr-utilisé.
    • Le destructeur de T est potentiellement invoqué.

La mémoire de l'objet exception est allouée de manière non spécifiée. La seule garantie est que le stockage ne sera jamais alloué par des fonctions d'allocation globales.

Si un gestionnaire se termine par une relance, le contrôle passe à un autre gestionnaire pour le même objet exception. L'objet exception n'est pas détruit dans ce cas.

Lorsque le dernier gestionnaire actif de l'exception se termine par tout autre moyen que la relance, l'objet exception est détruit et l'implémentation peut désallouer la mémoire de l'objet temporaire de manière non spécifiée.

La destruction a lieu immédiatement après la destruction de l'objet déclaré dans la « liste de paramètres » du gestionnaire.

(jusqu'à C++11)

Les points de destruction potentielle de l'objet exception sont :

  • Lorsqu'un gestionnaire actif de l'exception se termine par tout autre moyen que la relance, immédiatement après la destruction de l'objet (le cas échéant) déclaré dans la « liste de paramètres » du gestionnaire.
  • Lorsqu'un objet de type std::exception_ptr qui fait référence à l'objet exception est détruit, avant que le destructeur de std::exception_ptr ne retourne.

Parmi tous les points de destruction potentielle de l'objet exception, il existe un dernier point non spécifié où l'objet exception est détruit. Tous les autres points se produisent avant ce dernier. L'implémentation peut ensuite désallouer la mémoire de l'objet exception de manière non spécifiée.

(depuis C++11)

expressions throw

| | | | throw expression | (1) | | | | throw | (2) | | |

  1. Lève une nouvelle exception.

  2. Relance l'exception en cours de traitement.

  • expression — l'expression utilisée pour construire l'objet exception

Lorsqu'une nouvelle exception est levée, son objet exception est déterminé comme suit :

  1. Les conversions standard array-to-pointer et function-to-pointer sont effectuées sur expression.
  2. Soit ex le résultat de la conversion :
    • Le type de l'objet exception est déterminé en retirant les qualificateurs cv de premier niveau du type de ex.
    • L'objet exception est initialisé par copie à partir de ex.

Si un programme tente de relancer une exception alors qu'aucune exception n'est en cours de traitement, std::terminate sera invoqué. Sinon, l'exception est réactivée avec l'objet exception existant (aucun nouvel objet exception n'est créé), et l'exception n'est plus considérée comme capturée.

try
{
    // lever une nouvelle exception 123
    throw 123;
}
catch (...) // intercepter toutes les exceptions
{
    // répondre (partiellement) à l'exception 123
    throw; // transmettre l'exception à un autre gestionnaire
}

Déroulement de la pile

Une fois l'objet exception construit, le flux de contrôle remonte (vers le haut de la pile d'appels) jusqu'à atteindre le début d'un bloc try, moment où les paramètres de tous les gestionnaires associés sont comparés, dans l'ordre d'apparition, au type de l'objet exception afin de trouver une correspondance. Si aucune correspondance n'est trouvée, le flux de contrôle continue de dérouler la pile jusqu'au prochain bloc try, et ainsi de suite. Si une correspondance est trouvée, le flux de contrôle saute au gestionnaire correspondant.

Lorsque le flux de contrôle remonte la pile d'appels, les destructeurs sont invoqués pour tous les objets à durée de stockage automatique qui ont été construits mais pas encore détruits depuis que le bloc try correspondant a été entré, dans l'ordre inverse de fin de leurs constructeurs. Si une exception est levée depuis le destructeur d'une variable locale ou d'un temporaire utilisé dans une instruction return, le destructeur de l'objet retourné par la fonction est également invoqué.

Si une exception est levée depuis un constructeur ou (rarement) depuis un destructeur d'un objet (quelle que soit sa durée de stockage), les destructeurs sont appelés pour tous les membres non statiques non variants entièrement construits et pour toutes les classes de base, dans l'ordre inverse de fin de leurs constructeurs. Les membres variants des classes de type union ne sont détruits qu'en cas de déroulement depuis un constructeur ; si le membre actif a changé entre l'initialisation et la destruction, le comportement est indéfini.

Si un constructeur délégant se termine par une exception après que le constructeur non délégant s'est terminé avec succès, le destructeur de cet objet est appelé.

(depuis C++11)

Si l'exception est levée depuis un constructeur invoqué par une expression new, la fonction de désallocation correspondante est appelée, si elle est disponible.

Ce processus est appelé déroulement de la pile.

Si une fonction appelée directement par le mécanisme de déroulement de la pile, après l'initialisation de l'objet exception et avant le début du gestionnaire d'exception, se termine par une exception, std::terminate est appelé. Ces fonctions incluent les destructeurs des objets à durée de stockage automatique dont la portée est quittée, et le constructeur de copie de l'objet exception qui est appelé (s'il n'est pas élidé) pour initialiser les arguments capturés par valeur.

Si une exception est levée et non capturée, y compris les exceptions qui s'échappent de la fonction initiale de std::thread, de la fonction main, ou du constructeur ou du destructeur d'un objet statique ou à durée de stockage thread_local, alors std::terminate est appelé. Il est défini par l'implémentation de savoir si un déroulement de la pile a lieu pour les exceptions non capturées.

Notes

Lors de la relance d'exceptions, la seconde forme doit être utilisée pour éviter le découpage d'objet (object slicing) dans le cas (typique) où les objets exception utilisent l'héritage :

try
{
    std::string("abc").substr(10); // lève std::out_of_range
}
catch (const std::exception& e)
{
    std::cout << e.what() << '\n';
//  throw e; // initialise par copie un nouvel objet exception de type std::exception
    throw;   // relance l'objet exception de type std::out_of_range
}

L'expression throw est classée comme expression prvalue de type void. Comme toute autre expression, elle peut être une sous-expression d'une autre expression, le plus souvent dans l'opérateur conditionnel :

double f(double d)
{
    return d > 1e7 ? throw std::overflow_error("too big") : d;
}

int main()
{
    try
    {
        std::cout << f(1e10) << '\n';
    }
    catch (const std::overflow_error& e)
    {
        std::cout << e.what() << '\n';
    }
}

Mots-clés

throw

Exemple

#include <iostream>
#include <stdexcept>

struct A
{
    int n;

    A(int n = 0): n(n) { std::cout << "A(" << n << ") constructed successfully\n"; }
    ~A() { std::cout << "A(" << n << ") destroyed\n"; }
};

int foo()
{
    throw std::runtime_error("error");
}

struct B
{
    A a1, a2, a3;

    B() try : a1(1), a2(foo()), a3(3)
    {
        std::cout << "B constructed successfully\n";
    }
    catch(...)
    {
        std::cout << "B::B() exiting with exception\n";
    }

    ~B() { std::cout << "B destroyed\n"; }
};

struct C : A, B
{
    C() try
    {
        std::cout << "C::C() completed successfully\n";
    }
    catch(...)
    {
        std::cout << "C::C() exiting with exception\n";
    }

    ~C() { std::cout << "C destroyed\n"; }
};

int main () try
{
    // crée le sous-objet de base A
    // crée le membre a1 de B
    // échoue à créer le membre a2 de B
    // le déroulement détruit le membre a1 de B
    // le déroulement détruit le sous-objet de base A
    C c;
}
catch (const std::exception& e)
{
    std::cout << "main() failed to create C with: " << e.what();
}

Output:

A(0) constructed successfully
A(1) constructed successfully
A(1) destroyed
B::B() exiting with exception
A(0) destroyed
C::C() exiting with exception
main() failed to create C with: error
