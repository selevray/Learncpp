Recherche de nom qualifié

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un nom qualifié est un nom qui apparaît à droite de l'opérateur de résolution de portée :: (voir aussi identificateurs qualifiés). Un nom qualifié peut désigner un

  • membre de classe (y compris les fonctions statiques et non statiques, les types, les modèles, etc.),
  • membre d'espace de noms (y compris un autre espace de noms),
  • enumerator.

Si rien ne se trouve à gauche de ::, la recherche ne considère que les déclarations de la portée de l'espace de noms global. Cela permet de désigner de tels noms même s'ils sont masqués par une déclaration locale :

#include <iostream>

namespace M {
    const char* fail = "fail\n";
}

using M::fail;

namespace N {
    const char* ok = "ok\n";
}

using namespace N;

int main()
{
    struct std {};

    std::cout << ::fail; // Erreur : la recherche non qualifiée de 'std' trouve la struct
    ::std::cout << ::ok; // OK : ::std trouve l'espace de noms std
}

Avant que la recherche de nom puisse être effectuée pour le nom à droite de ::, la recherche doit être achevée pour le nom à sa gauche (sauf si une expression decltype est utilisée, ou s'il n'y a rien à gauche). Cette recherche, qui peut être qualifiée ou non qualifiée selon qu'il existe un autre :: à gauche de ce nom, ne considère que les espaces de noms, les types de classe, les énumérations et les modèles dont les spécialisations sont des types. Si le nom trouvé à gauche ne désigne ni un espace de noms, ni une classe, une énumération ou un type dépendant, le programme est mal formé :

struct A
{
    static int n;
};

int main()
{
    int A;
    A::n = 42; // OK : la recherche non qualifiée de A à gauche de :: ignore la variable
    A b;       // Erreur : la recherche non qualifiée de A trouve la variable A
}

template<int>
struct B : A {};

namespace N
{
    template<int>
    void B();

    int f()
    {
        return B<0>::n; // Erreur : N::B<0> n'est pas un type
    }
}

Lorsqu'un nom qualifié est utilisé comme déclarateur, alors une recherche de nom non qualifié des noms utilisés dans le même déclarateur qui suivent ce nom qualifié, mais pas ceux qui le précèdent, est effectuée dans la portée de la classe ou de l'espace de noms du membre :

class X {};

constexpr int number = 100;

struct C
{
    class X {};
    static const int number = 50;
    static X arr[number];
};

X C::arr[number], brr[number];    // Erreur : la recherche de X trouve ::X, et non C::X
C::X C::arr[number], brr[number]; // OK : la taille de arr est 50, la taille de brr est 100

Si :: est suivi du caractère ~, lui-même suivi d'un identificateur (c'est-à-dire qu'il désigne un destructeur ou un pseudo-destructeur), cet identificateur est recherché dans la même portée que le nom à gauche de ::

struct C { typedef int I; };

typedef int I1, I2;

extern int *p, *q;

struct A { ~A(); };

typedef A AB;

int main()
{
    p->C::I::~I(); // Le nom I après ~ est recherché dans la même portée que I avant ::
                   // (c'est-à-dire dans la portée de C, donc il trouve C::I)

    q->I1::~I2();  // Le nom I2 est recherché dans la même portée que I1
                   // (c'est-à-dire depuis la portée courante, donc il trouve ::I2)

    AB x;
    x.AB::~AB();   // Le nom AB après ~ est recherché dans la même portée que AB avant ::
                   // (c'est-à-dire depuis la portée courante, donc il trouve ::AB)
}

Énumérateurs

Si la recherche du nom à gauche aboutit à une énumération (à portée ou sans portée), la recherche du membre de droite doit aboutir à un énumérateur appartenant à cette énumération, sinon le programme est mal formé.

(depuis C++11)

Membres de classe

Si la recherche du nom à gauche aboutit à un nom de classe/struct ou d'union, le nom à droite de :: est recherché dans la portée de cette classe (et peut donc trouver une déclaration d'un membre de cette classe ou de sa base), avec les exceptions suivantes :

  • Un destructeur est recherché comme décrit ci-dessus (dans la portée du nom à gauche de ::).
  • Un conversion-type-id dans le nom d'une fonction de conversion définie par l'utilisateur est d'abord recherché dans la portée de la classe. S'il n'est pas trouvé, le nom est alors recherché dans la portée courante.
  • Les noms utilisés dans les arguments de modèle sont recherchés dans la portée courante (et non dans la portée du nom du modèle).
  • Les noms dans les déclarations using prennent aussi en compte les noms de classes/énumérations masqués par le nom d'une variable, d'un membre de données, d'une fonction ou d'un énumérateur déclaré dans la même portée.

Si le côté droit de :: désigne la même classe que le côté gauche, le nom désigne le constructeur de cette classe. Un tel nom qualifié ne peut être utilisé que dans une déclaration de constructeur et dans la déclaration using d'un constructeur hérité. Dans les recherches où les noms de fonctions sont ignorés (c'est-à-dire lors de la recherche d'un nom à gauche de ::, lors de la recherche d'un nom dans un spécificateur de type elaboré, ou d'un spécificateur de base), la même syntaxe se résout en nom de classe injecté :

struct A { A(); };

struct B : A { B(); };

A::A() {} // A::A désigne un constructeur, utilisé dans une déclaration
B::B() {} // B::B désigne un constructeur, utilisé dans une déclaration

B::A ba;  // B::A désigne le type A (recherché dans la portée de B)
A::A a;   // Erreur : A::A ne désigne pas un type

struct A::A a2; // OK : la recherche dans un spécificateur de type elaboré ignore les fonctions
                // donc A::A désigne simplement la classe A telle que vue depuis la portée de A
                // (c'est-à-dire le nom de classe injecté)

La recherche de nom qualifié peut servir à accéder à un membre de classe masqué par une déclaration imbriquée ou par une classe dérivée. Un appel à une fonction membre qualifiée n'est jamais virtuel :

struct B { virtual void foo(); };

struct D : B { void foo() override; };

int main()
{
    D x;
    B& b = x;

    b.foo();    // Appelle D::foo (distribution virtuelle)
    b.B::foo(); // Appelle B::foo (distribution statique)
}

Membres d'espace de noms

Si le nom à gauche de :: désigne un espace de noms, ou s'il n'y a rien à gauche de :: (auquel cas il désigne l'espace de noms global), le nom qui apparaît à droite de :: est recherché dans la portée de cet espace de noms, sauf que

  • les noms utilisés dans les arguments de modèle sont recherchés dans la portée courante :
namespace N
{
    template<typename T>
    struct foo {};

    struct X {};
}

N::foo<X> x; // Erreur : X est recherché comme ::X, et non comme N::X

La recherche qualifiée dans la portée d'un espace de noms N considère d'abord toutes les déclarations situées dans N et toutes les déclarations situées dans les membres d'espace de noms en ligne de N (et, transitivement, dans leurs membres d'espace de noms en ligne). S'il n'y a aucune déclaration dans cet ensemble, elle considère alors les déclarations de tous les espaces de noms désignés par des directives using trouvées dans N et dans tous les membres d'espace de noms en ligne transitifs de N. Les règles s'appliquent récursivement :

int x;

namespace Y
{
    void f(float);
    void h(int);
}

namespace Z
{
    void h(double);
}

namespace A
{
    using namespace Y;
    void f(int);
    void g(int);
    int i;
}

namespace B
{
    using namespace Z;
    void f(char);
    int i;
}

namespace AB
{
    using namespace A;
    using namespace B;
    void g();
}

void h()
{
    AB::g();  // AB est parcouru, AB::g est trouvé par la recherche et est choisi : AB::g(void)
              // (A et B ne sont pas parcourus)

    AB::f(1); // D'abord, AB est parcouru. Il n'y a pas de f
              // Ensuite, A et B sont parcourus
              // A::f, B::f trouvés par la recherche
              // (mais Y n'est pas parcouru, donc Y::f n'est pas pris en compte)
              // La résolution de surcharge retient A::f(int)

    AB::x++;  // D'abord, AB est parcouru. Il n'y a pas de x
              // Ensuite A et B sont parcourus. Il n'y a pas de x
              // Ensuite Y et Z sont parcourus. Il n'y a toujours pas de x : c'est une erreur

    AB::i++;  // AB est parcouru. Il n'y a pas de i
              // Ensuite, A et B sont recherchés. A::i et B::i trouvés par la recherche : c'est une erreur

    AB::h(16.8); // Premièrement, AB est recherché. Il n'y a pas de h
                 // Ensuite, A et B sont recherchés. Il n'y a pas de h
                 // Ensuite, Y et Z sont recherchés
                 // La recherche trouve Y::h et Z::h. La résolution de surcharge retient Z::h(double)
}

Il est permis que la même déclaration soit trouvée plus d'une fois :

namespace A { int a; }

namespace B { using namespace A; }

namespace D { using A::a; }

namespace BD
{
    using namespace B;
    using namespace D;
}

void g()
{
    BD::a++; // OK : trouve le même A::a via B et via D
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 215 C++98 le nom précédant :: doit être un nom de classe ou un nom d'espace de noms , donc les paramètres de modèle n'étaient pas autorisés à cet endroit le nom doit désigner une classe, un espace de noms ou un type dépendant
CWG 318 C++98 si le côté droit de :: désigne la même classe que le côté gauche, le nom qualifié était toujours considéré comme désignant le constructeur de cette classe ne désigne le constructeur que lorsque c'est acceptable (par exemple pas dans un spécificateur de type elaboré)
