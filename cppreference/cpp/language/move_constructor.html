Constructeurs de déplacement

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Un constructeur de déplacement est un constructeur qui peut être appelé avec un argument du même type classe et qui copie le contenu de l'argument, en le modifiant éventuellement.

Syntaxe

| | | | class-name ﻿(parameter-list ﻿); | (1) | | | | class-name ﻿(parameter-list ﻿) function-body | (2) | | | | class-name ﻿(single-parameter-list ﻿) = default; | (3) | | | | class-name ﻿(parameter-list ﻿) = delete; | (4) | | | | class-name ﻿::class-name ﻿(parameter-list ﻿) function-body | (5) | | | | class-name ﻿::class-name ﻿(single-parameter-list ﻿) = default; | (6) | | |

  • class-name — la classe dont le constructeur de déplacement est déclaré
  • parameter-list — une liste de paramètres non vide satisfaisant toutes les conditions suivantes :
    • étant donné le type de classe comme T, le premier paramètre est de type T&&, const T&&, volatile T&& ou const volatile T&&, et
    • soit il n'existe aucun autre paramètre, soit tous les autres paramètres possèdent des arguments par défaut
  • single-parameter-list — une liste de paramètres ne comportant qu'un seul paramètre, de type T&&, const T&&, volatile T&& ou const volatile T&&, et n'ayant pas d'argument par défaut
  • function-body — le corps de fonction du constructeur de déplacement

Explication

  1. Déclaration d'un constructeur de déplacement à l'intérieur de la définition de classe.

2-4) Définition d'un constructeur de déplacement à l'intérieur de la définition de classe.

  1. Le constructeur de déplacement est explicitement défini par défaut.

  2. Le constructeur de déplacement est supprimé.

5,6) Définition d'un constructeur de déplacement en dehors de la définition de classe (la classe doit contenir une déclaration (1)).

  1. Le constructeur de déplacement est explicitement défini par défaut.
struct X
{
    X(X&& other); // constructeur de déplacement
//  X(X other);   // Erreur : type de paramètre incorrect
};

union Y
{
    Y(Y&& other, int num = 1); // constructeur de déplacement à plusieurs paramètres
//  Y(Y&& other, int num);     // Erreur : `num` n'a pas d'argument par défaut
};

Le constructeur de déplacement est généralement appelé lorsqu'un objet est initialisé (par initialisation directe ou initialisation par copie) à partir d'une [rvalue (xvalue ou prvalue) (jusqu'à C++17) | xvalue (depuis C++17)] du même type, y compris

  • initialisation : T a = std::move(b); ou T a(std::move(b));, où b est de type T ;
  • passage d'arguments de fonction : f(std::move(a));, où a est de type T et f est void f(T t) ;
  • retour de fonction : return a; dans une fonction telle que T f(), où a est de type T qui possède un constructeur de déplacement.

Lorsque l'initialiseur est une prvalue, l'appel au constructeur de déplacement est [souvent optimisé (jusqu'à C++17) | jamais effectué (depuis C++17)], voir élision de copie.

Les constructeurs de déplacement transfèrent généralement les ressources détenues par l'argument (par exemple des pointeurs vers des objets alloués dynamiquement, des descripteurs de fichiers, des sockets TCP, des handles de thread, etc.) au lieu d'en faire des copies, et laissent l'argument dans un état valide mais par ailleurs indéterminé. Comme le constructeur de déplacement ne modifie pas la durée de vie de l'argument, le destructeur sera généralement appelé sur l'argument plus tard. Par exemple, un déplacement depuis un std::string ou depuis un std::vector peut laisser l'argument vide. Pour certains types, comme std::unique_ptr, l'état après déplacement est entièrement spécifié.

Constructeur de déplacement déclaré implicitement

Si aucun constructeur de déplacement défini par l'utilisateur n'est fourni pour un type classe, et que toutes les conditions suivantes sont vraies :

  • il n'existe aucun constructeur de copie déclaré par l'utilisateur ;
  • il n'existe aucun opérateur d'affectation par copie déclaré par l'utilisateur ;
  • il n'existe aucun opérateur d'affectation par déplacement déclaré par l'utilisateur ;
  • il n'existe aucun destructeur déclaré par l'utilisateur.

Alors le compilateur déclare un constructeur de déplacement comme membre non-explicit inline public de sa classe, avec la signature T::T(T&&).

Une classe peut avoir plusieurs constructeurs de déplacement, par exemple à la fois T::T(const T&&) et T::T(T&&). Si certains constructeurs de déplacement définis par l'utilisateur sont présents, l'utilisateur peut tout de même forcer la génération du constructeur de déplacement déclaré implicitement avec le mot-clé default.

Le constructeur de déplacement déclaré implicitement (ou défini par défaut lors de sa première déclaration) possède une spécification d'exception décrite dans [spécification d'exception dynamique (jusqu'à C++17) | spécification noexcept (depuis C++17)].

Constructeur de déplacement défini implicitement

Si le constructeur de déplacement déclaré implicitement n'est ni supprimé ni trivial, il est défini (c'est-à-dire qu'un corps de fonction est généré et compilé) par le compilateur s'il est utilisé par ODR ou nécessaire à l'évaluation constante. Pour les types union, le constructeur de déplacement défini implicitement copie la représentation de l'objet (comme par std::memmove). Pour les types classe non-union, le constructeur de déplacement effectue un déplacement membre à membre complet des sous-objets de base directs et des sous-objets membres de l'objet, dans leur ordre d'initialisation, en utilisant l'initialisation directe avec un argument de type xvalue. Pour chaque membre de donnée non statique de type référence, le constructeur de déplacement lie la référence au même objet ou à la même fonction auquel la référence source est liée.

Si cela satisfait les exigences d'un [constexpr constructeur (jusqu'à C++23) | constexpr fonction (depuis C++23)], le constructeur de déplacement généré est constexpr.

Constructeur de déplacement supprimé

Le constructeur de déplacement déclaré implicitement ou défini explicitement par défaut pour la classe T est défini comme supprimé si T possède un sous-objet potentiellement construit de type classe M (ou tableau multidimensionnel de ce type) tel que

  • M possède un destructeur supprimé ou inaccessible depuis le constructeur de copie, ou
  • la résolution de surcharge appliquée pour trouver le constructeur de déplacement de M
    • ne produit aucun candidat utilisable, ou
    • dans le cas où le sous-objet est un membre variant, sélectionne une fonction non triviale.

Un tel constructeur est ignoré par la résolution de surcharge (sinon il empêcherait l'initialisation par copie à partir d'une rvalue).

Constructeur de déplacement trivial

Le constructeur de déplacement de la classe T est trivial si toutes les conditions suivantes sont vraies :

  • il n'est pas fourni par l'utilisateur (c'est-à-dire qu'il est implicitement défini ou défini par défaut) ;
  • T ne possède aucune fonction membre virtuelle ;
  • T ne possède aucune classe de base virtuelle ;
  • le constructeur de déplacement sélectionné pour chaque base directe de T est trivial ;
  • le constructeur de déplacement sélectionné pour chaque membre non statique de type classe (ou tableau de type classe) de T est trivial.

Un constructeur de déplacement trivial est un constructeur qui effectue la même action que le constructeur de copie trivial, c'est-à-dire qu'il copie la représentation de l'objet comme par std::memmove. Tous les types de données compatibles avec le langage C sont trivialement déplaçables.

Constructeur de déplacement éligible

Un constructeur de déplacement est éligible s'il n'est pas supprimé.

(jusqu'à C++20)

Un constructeur de déplacement est éligible si toutes les conditions suivantes sont satisfaites :

  • Il n'est pas supprimé.
  • Ses contraintes associées (le cas échéant) sont satisfaites.
  • Aucun constructeur de déplacement dont les contraintes associées sont satisfaites n'est plus contraint.

(depuis C++20)

La trivialité des constructeurs de déplacement éligibles détermine si la classe est un type à durée de vie implicite, et si la classe est un type trivialement copiable.

Notes

Pour rendre possible la garantie forte d'exception, les constructeurs de déplacement définis par l'utilisateur ne devraient pas lever d'exceptions. Par exemple, std::vector repose sur std::move_if_noexcept pour choisir entre déplacement et copie lorsque les éléments doivent être relocalisés.

Si les constructeurs de copie et de déplacement sont tous deux fournis et qu'aucun autre constructeur n'est viable, la résolution de surcharge sélectionne le constructeur de déplacement si l'argument est une rvalue du même type (une xvalue comme le résultat de std::moveou une prvalue comme un temporaire sans nom (jusqu'à C++17)), et sélectionne le constructeur de copie si l'argument est une lvalue (objet nommé ou fonction/opérateur renvoyant une référence lvalue). Si seul le constructeur de copie est fourni, toutes les catégories d'arguments le sélectionnent (à condition qu'il prenne une référence vers const, puisque les rvalues peuvent se lier à des références const), ce qui fait de la copie le repli du déplacement lorsque celui-ci n'est pas disponible.

Exemple

#include <iomanip>
#include <iostream>
#include <string>
#include <utility>

struct A
{
    std::string s;
    int k;

    A() : s("test"), k(-1) {}
    A(const A& o) : s(o.s), k(o.k) { std::cout << "move failed!\n"; }
    A(A&& o) noexcept :
        s(std::move(o.s)),       // déplacement explicite d'un membre de type classe
        k(std::exchange(o.k, 0)) // déplacement explicite d'un membre de type non classe
    {}
};

A f(A a)
{
    return a;
}

struct B : A
{
    std::string s2;
    int n;
    // constructeur de déplacement implicite B::(B&&)
    // appelle le constructeur de déplacement de A
    // appelle le constructeur de déplacement de s2
    // et effectue une copie binaire de n
};

struct C : B
{
    ~C() {} // le destructeur empêche le constructeur de déplacement implicite C::(C&&)
};

struct D : B
{
    D() {}
    ~D() {}           // le destructeur empêcherait le constructeur de déplacement implicite D::(D&&)
    D(D&&) = default; // force tout de même un constructeur de déplacement
};

int main()
{
    std::cout << "Trying to move A\n";
    A a1 = f(A()); // le retour par valeur construit la cible par déplacement
                   // à partir du paramètre de fonction

    std::cout << "Before move, a1.s = " << std::quoted(a1.s)
        << " a1.k = " << a1.k << '\n';

    A a2 = std::move(a1); // construit par déplacement à partir d'une xvalue
    std::cout << "After move, a1.s = " << std::quoted(a1.s)
        << " a1.k = " << a1.k << '\n';

    std::cout << "\nTrying to move B\n";
    B b1;

    std::cout << "Before move, b1.s = " << std::quoted(b1.s) << "\n";

    B b2 = std::move(b1); // appelle le constructeur de déplacement implicite
    std::cout << "After move, b1.s = " << std::quoted(b1.s) << "\n";

    std::cout << "\nTrying to move C\n";
    C c1;
    C c2 = std::move(c1); // appelle le constructeur de copie

    std::cout << "\nTrying to move D\n";
    D d1;
    D d2 = std::move(d1);
}

Output:

Trying to move A
Before move, a1.s = "test" a1.k = -1
After move, a1.s = "" a1.k = 0

Trying to move B
Before move, b1.s = "test"
After move, b1.s = ""

Trying to move C
move failed!

Trying to move D

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 1353 C++11 les conditions dans lesquelles les constructeurs de déplacement par défaut sont définis comme supprimés ne prenaient pas en compte les types tableaux multidimensionnels prendre en compte ces types
CWG 1402 C++11 un constructeur de déplacement par défaut qui appellerait un constructeur de copie non trivial était défini comme supprimé ; un constructeur de déplacement par défaut qui est supprimé participait tout de même à la résolution de surcharge permettait l'appel à un tel constructeur de copie ; rendu ignoré lors de la résolution de surcharge
CWG 1491 C++11 un constructeur de déplacement par défaut d'une classe possédant un membre de donnée non statique de type référence rvalue était défini comme supprimé non supprimé dans ce cas
CWG 2094 C++11 un sous-objet volatile rendait un constructeur de déplacement par défaut non trivial (problème CWG 496) la trivialité n'est pas affectée
CWG 2595 C++20 un constructeur de déplacement n'était pas éligible s'il existait un autre constructeur de déplacement plus contraint mais ne satisfaisant pas ses contraintes associées il peut être éligible dans ce cas
