"Substitution Failure Is Not An Error"

Cette règle s'applique lors de la résolution de surcharge des modèles de fonctions : lorsque la substitution du type explicitement spécifié ou déduit au paramètre de modèle échoue, la spécialisation est écartée de l'ensemble de surcharges au lieu de provoquer une erreur de compilation.

Cette fonctionnalité est utilisée dans la métaprogrammation par modèles.

Explication

Les paramètres de modèle de fonction sont substitués (remplacés par des arguments de modèle) deux fois :

  • les arguments de modèle explicitement spécifiés sont substitués avant la déduction des arguments de modèle
  • les arguments déduits et ceux obtenus à partir des valeurs par défaut sont substitués après la déduction des arguments de modèle

La substitution a lieu dans

  • tous les types utilisés dans le type de fonction (qui comprend le type de retour et les types de tous les paramètres)
  • tous les types utilisés dans les déclarations des paramètres de modèle
  • tous les types utilisés dans la liste d'arguments de modèle d'une spécialisation partielle
  • toutes les expressions utilisées dans le type de fonction
  • toutes les expressions utilisées dans une déclaration de paramètre de modèle
  • toutes les expressions utilisées dans la liste d'arguments de modèle d'une spécialisation partielle

(depuis C++11)

  • toutes les expressions utilisées dans le spécificateur explicit

(depuis C++20)

Un échec de substitution est toute situation où le type ou l'expression ci-dessus serait mal formé (avec un diagnostic requis), s'il était écrit avec les arguments substitués.

Seuls les échecs dans les types et expressions du contexte immédiat du type de fonction ou de ses types de paramètres de modèle ou de son spécificateur explicit (depuis C++20) sont des erreurs SFINAE. Si l'évaluation d'un type/expression substitué provoque un effet de bord tel que l'instanciation d'une spécialisation de modèle, la génération d'une fonction membre implicitement définie, etc., les erreurs de ces effets de bord sont traitées comme des erreurs fatales. Une expression lambda n'est pas considérée comme faisant partie du contexte immédiat. (depuis C++20)

La substitution procède dans l'ordre lexical et s'arrête dès qu'un échec est rencontré.

S'il existe plusieurs déclarations avec des ordres lexicaux différents (par exemple un modèle de fonction déclaré avec un type de retour final, à substituer après un paramètre, et redéclaré avec un type de retour ordinaire qui serait substitué avant le paramètre), et que cela provoquerait des instanciations de modèles dans un ordre différent ou ne les effectuerait pas du tout, alors le programme est mal formé ; aucun diagnostic requis.

(depuis C++11)

template<typename A>
struct B { using type = typename A::type; };

template<
    class T,
    class U = typename T::type,    // échec SFINAE si T n'a pas de type membre
    class V = typename B<T>::type> // erreur fatale si B n'a pas de type membre
                                   // (garanti de ne pas se produire grâce à CWG 1227 car
                                   // la substitution dans l'argument de modèle par défaut
                                   // de U échouerait d'abord)
void foo (int);

template<class T>
typename T::type h(typename B<T>::type);

template<class T>
auto h(typename B<T>::type) -> typename T::type; // redeclaration

template<class T>
void h(...) {}

using R = decltype(h<int>(0));     // mal formé, aucun diagnostic requis

SFINAE de type

Les erreurs de type suivantes sont des erreurs SFINAE :

  • tenter d'instancier une expansion de pack contenant plusieurs packs de longueurs différentes

(depuis C++11)

  • tenter de créer un tableau de void, un tableau de références, un tableau de fonctions, un tableau de taille négative, un tableau de taille non entière, ou un tableau de taille nulle :
template<int I>
void div(char(*)[I % 2 == 0] = nullptr)
{
    // cette surcharge est sélectionnée lorsque I est pair
}

template<int I>
void div(char(*)[I % 2 == 1] = nullptr)
{
    // cette surcharge est sélectionnée lorsque I est impair
}
  • tenter d'utiliser un type à gauche de l'opérateur de résolution de portée :: alors que ce n'est ni une classe ni une énumération :
template<class T>
int f(typename T::B*);

template<class T>
int f(T);

int i = f<int>(0); // utilise la seconde surcharge
  • tenter d'utiliser un membre d'un type, où
    • le type ne contient pas le membre spécifié
    • le membre spécifié n'est pas un type là où un type est requis
    • le membre spécifié n'est pas un modèle là où un modèle est requis
    • le membre spécifié n'est pas un non-type là où un non-type est requis
template<int I>
struct X {};

template<template<class T> class>
struct Z {};

template<class T>
void f(typename T::Y*) {}

template<class T>
void g(X<T::N>*) {}

template<class T>
void h(Z<T::template TT>*) {}

struct A {};
struct B { int Y; };
struct C { typedef int N; };
struct D { typedef int TT; };
struct B1 { typedef int Y; };
struct C1 { static const int N = 0; };
struct D1
{
    template<typename T>
    struct TT {};
};

int main()
{
    // La déduction échoue dans chacun de ces cas :
    f<A>(0); // A ne contient pas de membre Y
    f<B>(0); // Le membre Y de B n'est pas un type
    g<C>(0); // Le membre N de C n'est pas un non-type
    h<D>(0); // Le membre TT de D n'est pas un modèle

    // La déduction réussit dans chacun de ces cas :
    f<B1>(0);
    g<C1>(0);
    h<D1>(0);
}

  • tenter de créer un pointeur vers une référence
  • tenter de créer une référence vers void
  • tenter de créer un pointeur vers membre de T, où T n'est pas un type classe :
template<typename T>
class is_class
{
    typedef char yes[1];
    typedef char no[2];

    template<typename C>

    template<typename C>

public:

  • tenter de donner un type invalide à un paramètre de modèle non-type :
template<class T, T>
struct S {};

template<class T>
int f(S<T, T()>*);

struct X {};
int i0 = f<X>(0);

  • tenter d'effectuer une conversion invalide dans
    • dans une expression d'argument de modèle
    • dans une expression utilisée dans une déclaration de fonction :
template<class T, T*> int f(int);
int i2 = f<int, 1>(0); // impossible de convertir 1 en int*

  • tenter de créer un type de fonction avec un paramètre de type void
  • tenter de créer un type de fonction qui renvoie un type tableau ou un type fonction

SFINAE sur les expressions

Seules les expressions constantes utilisées dans des types (comme les bornes de tableaux) devaient être traitées comme SFINAE (et non comme des erreurs fatales) avant C++11.

(jusqu'à C++11)

Les erreurs d'expression suivantes sont des erreurs SFINAE

  • Expression mal formée utilisée dans un type de paramètre de modèle
  • Expression mal formée utilisée dans le type de fonction :
struct X {};
struct Y { Y(X){} }; // X est convertible en Y

template<class T>
auto f(T t1, T t2) -> decltype(t1 + t2); // overload #1

X f(Y, Y);                               // overload #2

X x1, x2;
X x3 = f(x1, x2); // la déduction échoue sur #1 (l'expression x1 + x2 est mal formée)
                  // seule #2 fait partie de l'ensemble de surcharge, et est appelée

(depuis C++11)

SFINAE dans les spécialisations partielles

La déduction et la substitution ont aussi lieu lors de la détermination de la génération d'une spécialisation d'un modèle de classe ou de variable (depuis C++14) par une spécialisation partielle ou par le modèle primaire. Un échec de substitution n'est pas traité comme une erreur fatale pendant cette détermination, mais rend la déclaration de spécialisation partielle correspondante ignorée, comme dans la résolution de surcharge impliquant des modèles de fonctions.

// le modèle primaire gère les types non référençables :
template<class T, class = void>
struct reference_traits
{
    using add_lref = T;
    using add_rref = T;
};

// la spécialisation reconnaît les types référençables :
template<class T>
struct reference_traits<T, std::void_t<T&>>
{
    using add_lref = T&;
    using add_rref = T&&;
};

template<class T>
using add_lvalue_reference_t = typename reference_traits<T>::add_lref;

template<class T>
using add_rvalue_reference_t = typename reference_traits<T>::add_rref;

Prise en charge par la bibliothèque

La composante std::enable_if de la bibliothèque standard permet de créer un échec de substitution afin d'activer ou de désactiver certaines surcharges selon une condition évaluée à la compilation.

De plus, de nombreux traits de type doivent être implémentés avec SFINAE si les extensions appropriées du compilateur ne sont pas disponibles.

(depuis C++11)

La composante std::void_t de la bibliothèque standard est une autre métafonction utilitaire qui simplifie les applications de SFINAE aux spécialisations partielles.

(depuis C++17)

Alternatives

Lorsque c'est applicable, la distribution par étiquette[, if constexpr (depuis C++17) | , et les concepts (depuis C++20)] sont généralement préférés au SFINAE.

static_assert est généralement préféré au SFINAE si l'on souhaite seulement une erreur de compilation conditionnelle.

(depuis C++11)

Exemples

Un idiome courant consiste à utiliser le SFINAE d'expression sur le type de retour, où l'expression utilise l'opérateur virgule, dont la sous-expression de gauche est celle examinée (convertie en void pour garantir que l'opérateur virgule défini par l'utilisateur sur le type renvoyé n'est pas sélectionné), et dont la sous-expression de droite a le type que la fonction est censée renvoyer.

#include <iostream>

// Cette surcharge est ajoutée à l'ensemble de surcharges si C est
// un type classe ou un type référence vers classe et F est un pointeur vers fonction membre de C
template<class C, class F>
auto test(C c, F f) -> decltype((void)(c.*f)(), void())
{
    std::cout << "(1) Class/class reference overload called\n";
}

// Cette surcharge est ajoutée à l'ensemble de surcharges si C est un
// type pointeur vers classe et F est un pointeur vers fonction membre de C
template<class C, class F>
auto test(C c, F f) -> decltype((void)((c->*f)()), void())
{
    std::cout << "(2) Pointer overload called\n";
}

// Cette surcharge est toujours présente dans l'ensemble de surcharges : ellipse
// le paramètre a la priorité la plus basse pour la résolution de surcharge
void test(...)
{
    std::cout << "(3) Catch-all overload called\n";
}

int main()
{
    struct X { void f() {} };
    X x;
    X& rx = x;
    test(x, &X::f);  // (1)
    test(rx, &X::f); // (1), crée une copie de x
    test(&x, &X::f); // (2)
    test(42, 1337);  // (3)
}

Output:

(1) Class/class reference overload called
(1) Class/class reference overload called
(2) Pointer overload called
(3) Catch-all overload called
