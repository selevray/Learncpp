Noms dépendants

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

À l'intérieur de la définition d'un modèle (aussi bien modèle de classe que modèle de fonction), la signification de certaines constructions peut différer d'une instanciation à l'autre. En particulier, les types et les expressions peuvent dépendre des types des paramètres de modèle de type et des valeurs des paramètres de modèle non-type.

template<typename T>
struct X : B<T> // « B<T> » dépend de T
{
    typename T::A* pa; // « T::A » dépend de T
                       // (voir ci-dessous la signification de cet usage de « typename »)

    void f(B<T>* pb)
    {
        static int i = B<T>::i; // « B<T>::i » dépend de T
        pb->j++; // « pb->j » dépend de T
    }
};

La recherche de noms et la liaison diffèrent pour les noms dépendants et les noms non dépendants.

Règles de liaison

Les noms non dépendants sont recherchés et liés au point de définition du modèle. Cette liaison est maintenue même si, au point d'instanciation, il existe une meilleure correspondance :

#include <iostream>

void g(double) { std::cout << "g(double)\n"; }

template<class T>
struct S
{
    void f() const
    {
        g(1); // « g » est un nom non dépendant, lié maintenant
    }
};

void g(int) { std::cout << "g(int)\n"; }

int main()
{
    g(1);  // appelle g(int)

    S<int> s;
    s.f(); // appelle g(double)
}

Si la signification d'un nom non dépendant change entre le contexte de définition et le point d'instanciation d'une spécialisation du modèle, le programme est mal formé, aucun diagnostic requis. Cela est possible dans les situations suivantes :

  • un type utilisé dans un nom non dépendant est incomplet au point de définition mais complet au point d'instanciation
  • la recherche d'un nom dans la définition du modèle a trouvé une déclaration using, mais la recherche dans la portée correspondante de l'instanciation ne trouve aucune déclaration, car la déclaration using était une expansion de paquet et le paquet correspondant est vide

(depuis C++17)

  • une instanciation utilise un argument par défaut ou un argument de modèle par défaut qui n'avait pas été défini au point de définition
  • une expression constante au point d'instanciation utilise la valeur d'un objet const de type entier ou énumération non scopée, la valeur d'un objet constexpr, la valeur d'une référence, ou la définition d'une fonction constexpr (depuis C++11), et cet objet/référence/fonction (depuis C++11) n'était pas défini au point de définition
  • le modèle utilise, au point d'instanciation, une spécialisation de modèle de classe non dépendante ou une spécialisation de modèle de variable (depuis C++14), et ce modèle qu'il utilise est soit instancié à partir d'une spécialisation partielle qui n'était pas définie au point de définition, soit désigne une spécialisation explicite qui n'était pas déclarée au point de définition

La liaison des noms dépendants est reportée jusqu'à ce que la recherche ait lieu.

Règles de recherche

La recherche d'un nom dépendant utilisé dans un modèle est reportée jusqu'à ce que les arguments de modèle soient connus, moment auquel

  • la recherche non ADL examine les déclarations de fonctions à liaison externe visibles depuis le contexte de définition du modèle
  • ADL examine les déclarations de fonctions à liaison externe visibles depuis le contexte de définition du modèle ou depuis le contexte d'instanciation du modèle

(en d'autres termes, ajouter une nouvelle déclaration de fonction après la définition du modèle ne la rend pas visible, sauf via ADL).

Le but de cette règle est d'aider à prévenir les violations de l'ODR pour les instanciations de modèles :

// une bibliothèque externe
namespace E
{
    template<typename T>
    void writeObject(const T& t)
    {
        std::cout << "Value = " << t << '\n';
    }
}

// unité de traduction 1 :
// Le programmeur 1 veut permettre à E::writeObject de fonctionner avec vector<int>
namespace P1
{
    std::ostream& operator<<(std::ostream& os, const std::vector<int>& v)
    {
        for (int n : v)
            os << n << ' ';
        return os;
    }

    void doSomething()
    {
        std::vector<int> v;
        E::writeObject(v); // Erreur : ne trouvera pas P1::operator<<
    }
}

// unité de traduction 2 :
// Le programmeur 2 veut permettre à E::writeObject de fonctionner avec vector<int>
namespace P2
{
    std::ostream& operator<<(std::ostream& os, const std::vector<int>& v)
    {
        for (int n : v)
            os << n << ':';
        return os << "[]";
    }

    void doSomethingElse()
    {
        std::vector<int> v;
        E::writeObject(v); // Erreur : ne trouvera pas P2::operator<<
    }
}

Dans l'exemple ci-dessus, si la recherche non ADL de operator<< était autorisée depuis le contexte d'instanciation, l'instanciation de E::writeObject<vector<int>> aurait deux définitions différentes : l'une utilisant P1::operator<< et l'autre utilisant P2::operator<<. Une telle violation de l'ODR pourrait ne pas être détectée par l'éditeur de liens, conduisant à l'utilisation de l'une ou l'autre dans les deux instances.

Pour que ADL examine un espace de noms défini par l'utilisateur, soit std::vector doit être remplacé par une classe définie par l'utilisateur, soit son type d'élément doit être une classe définie par l'utilisateur :

namespace P1
{
    // si C est une classe définie dans l'espace de noms P1
    std::ostream& operator<<(std::ostream& os, const std::vector<C>& v)
    {
        for (C n : v)
            os << n;
        return os;
    }

    void doSomething()
    {
        std::vector<C> v;
        E::writeObject(v); // OK : instancie writeObject(std::vector<P1::C>)
                           //     ce qui trouve P1::operator<< via ADL
    }
}

Remarque : cette règle rend impraticable la surcharge d'opérateurs pour les types de la bibliothèque standard :

#include <iostream>
#include <iterator>
#include <utility>
#include <vector>

// Mauvaise idée : opérateur dans l'espace de noms global, mais ses arguments sont dans std::
std::ostream& operator<<(std::ostream& os, std::pair<int, double> p)
{
    return os << p.first << ',' << p.second;
}

int main()
{
    typedef std::pair<int, double> elem_t;
    std::vector<elem_t> v(10);
    std::cout << v[0] << '\n'; // OK, la recherche ordinaire trouve ::operator<<
    std::copy(v.begin(), v.end(),
              std::ostream_iterator<elem_t>(std::cout, " "));
    // Erreur : à la fois la recherche ordinaire depuis le point de définition de
    // std::ostream_iterator et l'ADL ne considéreront que l'espace de noms std,
    // et trouvera de nombreuses surcharges de std::operator<<, donc la recherche sera effectuée.
    // La résolution de surcharge ne parviendra alors pas à trouver operator<< pour elem_t
    // dans l'ensemble trouvé par la recherche.
}

Remarque : une recherche limitée (mais pas la liaison) des noms dépendants a également lieu au moment de la définition du modèle, si nécessaire pour les distinguer des noms non dépendants et pour déterminer s'ils sont membres de l'instanciation courante ou membres d'une spécialisation inconnue. Les informations obtenues par cette recherche peuvent servir à détecter des erreurs, voir ci-dessous.

Types dépendants

Les types suivants sont des types dépendants﻿ :

  • paramètre de modèle
  • un membre d'une spécialisation inconnue (voir ci-dessous)
  • une classe/énumération imbriquée qui est un membre dépendant d'une spécialisation inconnue (voir ci-dessous)
  • une version qualifiée cv d'un type dépendant
  • un type composé construit à partir d'un type dépendant
  • un type tableau dont le type d'élément est dépendant ou dont la borne (si elle existe) est dépendante de la valeur
  • un type fonction dont les paramètres incluent un ou plusieurs paquets de paramètres de fonction

(depuis C++11)

  • un type fonction dont la spécification d'exception est dépendante de la valeur
  • un template-id où
    • le nom du modèle est un paramètre de modèle, ou
    • l'un des arguments de modèle est dépendant du type ou dépendant de la valeur, ou est une expansion de paquet (depuis C++11) (même si le template-id est utilisé sans sa liste d'arguments, comme nom de classe injecté)
  • le résultat de decltype appliqué à une expression dépendante du type

Le résultat de decltype appliqué à une expression dépendante du type est un type dépendant unique. Deux tels résultats désignent le même type seulement si leurs expressions sont équivalentes.

(depuis C++11)

  • le spécificateur d'indexation de paquet appliqué à une expression constante dépendante du type

Le spécificateur d'indexation de paquet appliqué à une expression constante dépendante du type est un type dépendant unique. Deux tels spécificateurs d'indexation de paquet désignent le même type seulement si leurs expressions constantes sont équivalentes. Sinon, deux tels spécificateurs désignent le même type seulement si leurs indices ont la même valeur.

(depuis C++26)

Remarque : un membre typedef d'une instanciation courante n'est dépendant que lorsque le type auquel il se réfère l'est.

Expressions dépendantes du type

Les expressions suivantes sont dépendantes du type :

  • une expression dont une sous-expression quelconque est une expression dépendante du type
  • this, si la classe est un type dépendant.
  • une expression d'identificateur qui n'est pas un concept-id et (depuis C++20)
    • contient un identificateur pour lequel la recherche de nom trouve au moins une déclaration dépendante
    • contient un template-id dépendant
  • contient l'identificateur spécial __func__ (si une fonction englobante est un modèle, une fonction membre non modèle d'un modèle de classe, ou une lambda générique (depuis C++14))

(depuis C++11)

  • contient le nom d'une fonction de conversion vers un type dépendant
  • contient un spécificateur de nom imbriqué ou un qualified-id qui est un membre d'une spécialisation inconnue
  • désigne un membre dépendant de l'instanciation courante qui est un membre donnée statique de type « tableau de borne inconnue »
  • contient un identificateur pour lequel la recherche de nom trouve une ou plusieurs déclarations de fonctions membres de l'instanciation courante déclarées avec déduction du type de retour

(depuis C++14)

  • contient un identificateur pour lequel la recherche de nom trouve une déclaration de liaison structurée dont l'initialiseur est dépendant du type
  • contient un identificateur pour lequel la recherche de nom trouve un paramètre de modèle non-type dont le type contient le type substitut auto
  • contient un identificateur pour lequel la recherche de nom trouve une variable déclarée avec un type contenant un type substitut (par exemple auto membre donnée statique), dont l'initialiseur est dépendant du type,

(depuis C++17)

  • contient un identificateur pour lequel la recherche de nom trouve un paquet

(depuis C++26)

  • toute expression de conversion vers un type dépendant
  • new expression qui crée un objet d'un type dépendant
  • expression d'accès à un membre qui désigne un membre de l'instanciation courante dont le type est dépendant
  • expression d'accès à un membre qui désigne un membre d'une spécialisation inconnue
  • expression de pliage

(depuis C++17)

  • expression d'indexation de paquet si son expression d'identifiant est une expression dépendante du type

(depuis C++26)

Les expressions suivantes ne sont jamais dépendantes du type, car les types de ces expressions ne peuvent pas l'être :

  • literals
  • appels de pseudo-destructeurs
  • sizeof
  • sizeof...
  • alignof
  • noexcept

(depuis C++11)

  • throw
  • typeid
  • delete
  • requires

(depuis C++20)

Expressions dépendantes de la valeur

Les expressions suivantes sont dépendantes de la valeur :

  • une expression utilisée dans un contexte où une expression constante est requise, et dont une sous-expression quelconque est dépendante de la valeur
  • une expression d'identifiant qui satisfait l'une des conditions suivantes :
  • Il s'agit d'un concept-id et au moins un de ses arguments est dépendant.

(depuis C++20)

  • Elle est dépendante du type.

  • Il s'agit du nom d'un paramètre de modèle non de type.

  • Elle désigne un membre donnée statique qui est un membre dépendant de l'instanciation courante et qui n'est pas initialisé.

  • Elle désigne une fonction membre statique qui est un membre dépendant de l'instanciation courante.

  • Il s'agit d'une constante de type [entier ou énumération (jusqu'à C++11) | littéral (depuis C++11)], initialisée à partir d'une expression dépendante de la valeur.

  • les expressions suivantes dont l'opérande est une expression dépendante du type :

    • sizeof
    • typeid
  • alignof

(depuis C++11)

  • les expressions suivantes dont l'opérande est un type-id dépendant :

    • sizeof
    • typeid

  • les expressions suivantes dont le type cible est dépendant ou dont l'opérande est une expression dépendante du type :

    • conversion de style C
    • static_cast
    • const_cast
    • reinterpret_cast
    • dynamic_cast

  • expression de conversion de style fonctionnel dont le type cible est dépendant ou dont une expression dépendante de la valeur est entourée de parenthèsesou d'accolades (depuis C++11)

  • sizeof... expressiondont l'opérande n'est pas un paquet de liaisons structurées (depuis C++26)

(depuis C++11)

  • expression de pliage

(depuis C++17)

  • expression d'adresse dont l'argument est un identifiant qualifié qui désigne un membre dépendant de l'instanciation courante
  • expression d'adresse dont l'argument est une expression quelconque qui, évaluée comme une expression constante de base, désigne une entité patron qui est un objet à durée de stockage statique ou thread (depuis C++11) ou une fonction membre.

Instanciation courante

Dans la définition d'un modèle de classe (y compris ses fonctions membres et ses classes imbriquées), certains noms peuvent être déduits comme désignant l'instanciation courante. Cela permet de détecter certaines erreurs au point de définition plutôt qu'à l'instanciation, et supprime l'obligation d'utiliser les désambiguïsateurs typename et template pour les noms dépendants, voir ci-dessous.

Seuls les noms suivants peuvent désigner l'instanciation courante :

  • dans la définition d'un modèle de classe, d'une classe imbriquée d'un modèle de classe, d'un membre d'un modèle de classe ou d'un membre d'une classe imbriquée d'un modèle de classe :
    • le nom injecté de la classe du modèle de classe ou de la classe imbriquée
  • dans la définition d'un modèle de classe primaire ou d'un membre d'un modèle de classe primaire :
    • le nom du modèle de classe suivi d'une liste d'arguments de modèle (ou d'une spécialisation de modèle d'alias équivalente) pour le modèle primaire, où chaque argument est équivalent (défini ci-dessous) à son paramètre correspondant.
  • dans la définition d'une classe imbriquée d'un modèle de classe :
    • le nom de la classe imbriquée utilisé comme membre de l'instanciation courante
  • dans la définition d'une spécialisation partielle de modèle de classe ou d'un membre d'une spécialisation partielle de modèle de classe :
    • le nom du modèle de classe suivi d'une liste d'arguments de modèle de la spécialisation partielle, où chaque argument est équivalent à son paramètre correspondant
  • dans la définition d'une fonction patron :
    • le nom d'une classe locale

Un argument de modèle est équivalent à un paramètre de modèle si

  • pour un paramètre de type, l'argument de modèle désigne le même type que le paramètre de modèle.
  • pour un paramètre non de type, l'argument de modèle est un identifiant qui désigne une variable équivalente au paramètre de modèle. Une variable est équivalente à un paramètre de modèle si
    • elle a le même type que le paramètre de modèle (sans tenir compte des qualificateurs cv) et
    • son initialiseur consiste en un identifiant unique qui désigne le paramètre de modèle ou, récursivement, une telle variable.
template<class T>
class A
{
    A* p1;      // A est l'instanciation courante
    A<T>* p2;   // A<T> est l'instanciation courante
    ::A<T>* p4; // ::A<T> est l'instanciation courante
    A<T*> p3;   // A<T*> n'est pas l'instanciation courante

    class B
    {
        B* p1;                 // B est l'instanciation courante
        A<T>::B* p2;           // A<T>::B est l'instanciation courante
        typename A<T*>::B* p3; // A<T*>::B n'est pas l'instanciation courante
    };
};

template<class T>
class A<T*>
{
    A<T*>* p1; // A<T*> est l'instanciation courante
    A<T>* p2;  // A<T> n'est pas l'instanciation courante
};

template<int I>
struct B
{
    static const int my_I = I;
    static const int my_I2 = I + 0;
    static const int my_I3 = my_I;
    static const long my_I4 = I;
    static const int my_I5 = (I);

    B<my_I>* b1;  // B<my_I> est l'instanciation courante :
                  //   my_I a le même type que I,
                  //   et il est initialisé avec uniquement I
    B<my_I2>* b2; // B<my_I2> n'est pas l'instanciation courante :
                  //   I + 0 n'est pas un identifiant unique
    B<my_I3>* b3; // B<my_I3> est l'instanciation courante :
                  //   my_I3 a le même type que I,
                  //   et il est initialisé avec uniquement my_I (ce qui équivaut à I)
    B<my_I4>* b4; // B<my_I4> n'est pas l'instanciation courante :
                  //   le type de my_I4 (long) n'est pas le même que le type de I (int)
    B<my_I5>* b5; // B<my_I5> n'est pas l'instanciation courante :
                  //   (I) n'est pas un identifiant unique
};

Notez qu'une classe de base peut être l'instanciation courante si une classe imbriquée dérive de son modèle de classe englobant. Les classes de base qui sont des types dépendants mais qui ne sont pas l'instanciation courante sont des classes de base dépendantes :

template<class T>
struct A
{
    typedef int M;

    struct B
    {
        typedef void M;

        struct C;
    };
};

template<class T>
struct A<T>::B::C : A<T>
{
    M m; // OK, A<T>::M
};

Un nom est classé comme membre de l'instanciation courante s'il s'agit

  • d'un nom non qualifié trouvé par recherche non qualifiée dans l'instanciation courante ou dans sa base non dépendante.
  • d'un nom qualifié, si le qualificateur (le nom à gauche de ::) désigne l'instanciation courante et que la recherche trouve le nom dans l'instanciation courante ou dans sa base non dépendante
  • d'un nom utilisé dans une expression d'accès à un membre de classe (y dans x.y ou xp->y), où l'expression d'objet (x ou *xp) désigne l'instanciation courante et que la recherche trouve le nom dans l'instanciation courante ou dans sa base non dépendante
template<class T>
class A
{
    static const int i = 5;

    int n1[i];       // i désigne un membre de l'instanciation courante
    int n2[A::i];    // A::i désigne un membre de l'instanciation courante
    int n3[A<T>::i]; // A<T>::i désigne un membre de l'instanciation courante

    int f();
};

template<class T>
int A<T>::f()
{
    return i; // i désigne un membre de l'instanciation courante
}

Les membres de l'instanciation courante peuvent être à la fois dépendants et non dépendants.

Si la recherche d'un membre de l'instanciation courante donne un résultat différent entre le point d'instanciation et le point de définition, la recherche est ambiguë. Notez toutefois que lorsqu'un nom de membre est utilisé, il n'est pas automatiquement converti en expression d'accès à un membre de classe ; seules les expressions d'accès explicites désignent des membres de l'instanciation courante :

struct A { int m; };
struct B { int m; };

template<typename T>
struct C : A, T
{
    int f() { return this->m; } // trouve A::m dans le contexte de définition du modèle
    int g() { return m; }       // trouve A::m dans le contexte de définition du modèle
};

template int C<B>::f(); // erreur : trouve à la fois A::m et B::m

template int C<B>::g(); // OK : transformation en syntaxe d'accès à un membre de classe
                        // n'apparaît pas dans le contexte de définition du modèle

Spécialisations inconnues

Dans une définition de modèle, certains noms sont considérés comme appartenant à une spécialisation inconnue, en particulier :

  • un nom qualifié, si un nom situé à gauche de :: est un type dépendant qui n'est pas un membre de l'instanciation courante
  • un nom qualifié dont le qualificateur est l'instanciation courante, dont le nom ne se trouve ni dans l'instanciation courante ni dans l'une de ses classes de base non dépendantes, et qu'il existe une classe de base dépendante
  • un nom de membre dans une expression d'accès à un membre de classe (le y dans x.y ou xp->y), si le type de l'expression d'objet (x ou *xp) est un type dépendant et n'est pas l'instanciation courante
  • un nom de membre dans une expression d'accès à un membre de classe (le y dans x.y ou xp->y), si le type de l'expression d'objet (x ou *xp) est l'instanciation courante, dont le nom ne se trouve ni dans l'instanciation courante ni dans l'une de ses classes de base non dépendantes, et qu'il existe une classe de base dépendante
template<typename T>
struct Base {};

template<typename T>
struct Derived : Base<T>
{
    void f()
    {
        // Derived<T> désigne l'instanciation courante
        // il n'existe pas de « unknown_type » dans l'instanciation courante
        // mais il existe une base dépendante (Base<T>)
        // Par conséquent, « unknown_type » est un membre d'une spécialisation inconnue
        typename Derived<T>::unknown_type z;
    }
};

template<>
struct Base<int> // cette spécialisation le fournit
{
    typedef int unknown_type;
};

Cette classification permet de détecter les erreurs suivantes au point de définition du modèle (et non à son instanciation) :

  • Si une définition de modèle contient un nom qualifié dont le qualificateur désigne l'instanciation courante et que le nom n'est ni un membre de l'instanciation courante ni un membre de spécialisation inconnue, le programme est mal formé (aucun diagnostic requis), même si le modèle n'est jamais instancié.
template<class T>
class A
{
    typedef int type;

    void f()
    {
        A<T>::type i; // OK : « type » est un membre de l'instanciation courante
        typename A<T>::other j; // Error:

        // « other » n'est pas un membre de l'instanciation courante
        // et ce n'est pas un membre d'une spécialisation inconnue
        // car A<T> (qui désigne l'instanciation courante),
        // n'a pas de bases dépendantes dans lesquelles « other » pourrait se cacher.
    }
};
  • Si une définition de modèle contient une expression d'accès à un membre dont l'expression d'objet est l'instanciation courante, mais que le nom n'est ni un membre de l'instanciation courante ni un membre de spécialisation inconnue, le programme est mal formé, même si le modèle n'est jamais instancié.

Les membres de spécialisation inconnue sont toujours dépendants, et sont recherchés et liés au point d'instanciation comme tous les noms dépendants (voir ci-dessus)

Le désambiguïsateur typename pour les noms dépendants

Dans une déclaration ou une définition de modèle, y compris de modèle d'alias, un nom qui n'est pas un membre de l'instanciation courante et qui dépend d'un paramètre de modèle n'est pas considéré comme un type, sauf si le mot-clé typename est utilisé ou s'il a déjà été établi comme un nom de type, par exemple avec une déclaration typedef ou en étant utilisé pour nommer une classe de base.

#include <iostream>
#include <vector>

int p = 1;

template<typename T>
void foo(const std::vector<T> &v)
{
    // std::vector<T>::const_iterator est un nom dépendant,
    typename std::vector<T>::const_iterator it = v.begin();

    // sans « typename », ce qui suit est analysé comme une multiplication
    // du membre de donnée « const_iterator », dépendant du type,
    // et d'une variable « p ». Comme il existe une « p » globale visible
    // à ce point, ce modèle de définition se compile.
    std::vector<T>::const_iterator* p;

    typedef typename std::vector<T>::const_iterator iter_t;
    iter_t * p2; // « iter_t » est un nom dépendant, mais on sait qu'il s'agit d'un nom de type
}

template<typename T>
struct S
{
    typedef int value_t; // membre de l'instanciation courante

    void f()
    {
        S<T>::value_t n{}; // S<T> est dépendant, mais « typename » n'est pas nécessaire
        std::cout << n << '\n';
    }
};

int main()
{
    std::vector<int> v;
    foo(v); // l'instanciation du modèle échoue : il n'existe pas de membre de donnée
            // nommé « const_iterator » dans le type std::vector<int>
    S<int>().f();
}

Le mot-clé typename ne peut être utilisé de cette manière que devant des noms qualifiés (par exemple T::x), mais ces noms n'ont pas besoin d'être dépendants.

La recherche de nom qualifié habituelle est utilisée pour l'identifiant précédé de typename. Contrairement au cas du spécificateur de type élaboré, les règles de recherche ne changent pas malgré le qualificateur :

struct A // A possède une variable membre X et un type imbriqué struct X
{
    struct X {};
    int X;
};

struct B
{
    struct X {}; // B possède un type imbriqué struct X
};

template<class T>
void f(T t)
{
    typename T::X x;
}

void foo()
{
    A a;
    B b;
    f(b); // OK : instancie f<B>, T::X désigne B::X
    f(a); // erreur : impossible d'instancier f<A> :
          // car la recherche de nom qualifiée de A::X trouve le membre de donnée
}

Le mot-clé typename peut être utilisé même en dehors des modèles.

#include <vector>

int main()
{
    // Les deux OK (après résolution de CWG 382)
    typedef typename std::vector<int>::const_iterator iter_t;
    typename std::vector<int> v;
}

Dans certains contextes, seuls des noms de types peuvent apparaître validement. Dans ces contextes, un nom qualifié dépendant est supposé désigner un type et aucun typename n'est requis :

  • Un nom qualifié utilisé comme spécificateur de déclaration dans le (niveau supérieur du) decl-specifier-seq de :

  • une déclaration simple ou une définition de fonction à portée d'espace de noms ;

  • une déclaration de membre de classe ;

  • une déclaration de paramètre dans une déclaration de membre de classe (y compris les déclarations d'amie de fonctions), en dehors des arguments par défaut ;

  • une déclaration de paramètre d'un déclarateur de fonction ou de modèle de fonction dont le nom est qualifié, en dehors des arguments par défaut ;

  • une déclaration de paramètre d'une expression lambda, en dehors des arguments par défaut ;

  • une déclaration de paramètre d'une expression requires ;

  • le type dans la déclaration d'un paramètre de modèle non de type ;

  • Un nom qualifié qui apparaît dans un type-id, lorsque le plus petit type-id englobant est :

  • le type dans une expression new qui ne met pas son type entre parenthèses ;

  • le type-id dans une déclaration d'alias ;

  • un type de retour de fin,

  • un argument par défaut d'un paramètre de modèle de type, ou

  • le type-id d'un static_cast, dynamic_cast, const_cast ou reinterpret_cast.

(depuis C++20)

Le désambiguïsateur template pour les noms dépendants

De même, dans la définition d'un modèle, un nom dépendant qui n'est pas membre de l'instanciation courante n'est pas considéré comme un nom de modèle, sauf si le mot-clé de désambiguïsation template est utilisé ou s'il a déjà été établi comme nom de modèle :

template<typename T>
struct S
{
    template<typename U>
    void foo() {}
};

template<typename T>
void bar()
{
    S<T> s;
    s.foo<T>();          // erreur : < analysé comme l'opérateur d'infériorité
    s.template foo<T>(); // OK
}

Le mot-clé template ne peut être utilisé de cette manière qu'après les opérateurs :: (résolution de portée), -> (accès membre via un pointeur) et . (accès membre) ; les exemples suivants sont tous valides :

  • T::template foo<X>();
  • s.template foo<X>();
  • this->template foo<X>();
  • typename T::template iterator<int>::value_type v;

Comme c'est le cas avec typename, le préfixe template est autorisé même si le nom n'est pas dépendant ou si l'utilisation n'apparaît pas dans la portée d'un modèle.

Même si le nom à gauche de :: désigne un espace de noms, le désambiguïsateur de modèle est autorisé :

template<typename>
struct S {};

::template S<void> q; // autorisé, mais inutile

En raison des règles spéciales de recherche de nom non qualifié pour les noms de modèles dans les expressions d'accès membre, lorsqu'un nom de modèle non dépendant apparaît dans une expression d'accès membre (après -> ou après .), le désambiguïsateur est inutile s'il existe un modèle de classe ou alias (depuis C++11) de même nom trouvé par la recherche ordinaire dans le contexte de l'expression. Toutefois, si le modèle trouvé par la recherche dans le contexte de l'expression diffère de celui trouvé dans le contexte de la classe, le programme est mal formé (jusqu'à C++11)

template<int>
struct A { int value; };

template<class T>
void f(T t)
{
    t.A<0>::value; // La recherche ordinaire de A trouve un modèle de classe.
                   // A<0>::value désigne un membre de la classe A<0>
    // t.A < 0;    // Erreur : « < » est traité comme le début d'une liste d'arguments de modèle
}

(jusqu'à C++23)

template, typename
