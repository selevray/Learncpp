Arguments variadiques

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Permet à une fonction d'accepter un nombre quelconque d'arguments supplémentaires.

Une fonction est variadique si le dernier paramètre de sa liste de paramètres est une ellipse (...).

La virgule précédant l'ellipse peut être omise.

(obsolète depuis C++26)

// la fonction déclarée comme suit
int printx(const char* fmt, ...);
int printx(const char* fmt...); // identique à ci-dessus, mais obsolète depuis C++26

// peut être appelée avec un ou plusieurs arguments :
printx("hello world");
printx("a=%d b=%d", a, b);

int printy(..., const char* fmt); // erreur : ... ne peut être que le dernier paramètre
int printz(...); // valide, mais les arguments ne peuvent pas être accédés de manière portable

Ceci est différent de l'expansion d'un pack de paramètres de fonction, indiquée par une ellipse faisant partie d'un déclarateur de paramètre, plutôt que par une ellipse seule en tant que paramètre. L'expansion d'un pack de paramètres et l'ellipse « variadique » peuvent toutes deux apparaître dans la déclaration d'un modèle de fonction, comme dans le cas de std::is_function.

(depuis C++11)

Promotions d'arguments par défaut

Lorsqu'une fonction variadique est appelée, après les conversions lvalue-vers-rvalue, tableau-vers-pointeur et fonction-vers-pointeur, chaque argument faisant partie de la liste d'arguments variables subit des conversions supplémentaires appelées promotions d'arguments par défaut :

  • std::nullptr_t est converti en void*.

(depuis C++11)

  • Les arguments float sont convertis en double comme dans la promotion flottante.
  • bool, char, short et les énumérations non scopées sont convertis en int ou en type entier plus large, comme dans la promotion entière.

[Types de classes non POD (jusqu'à C++11) | Les énumérations scopées et les types de classes ayant un constructeur de copie non trivial éligible, un constructeur de déplacement non trivial éligible, ou un destructeur non trivial (depuis C++11)] sont conditionnellement supportés dans les appels potentiellement évalués, avec une sémantique définie par l'implémentation (ces types sont toujours supportés dans les appels non évalués).

Comme les paramètres variadiques ont le rang le plus bas pour la résolution de surcharge, ils sont généralement utilisés comme solutions de repli universelles dans SFINAE.

Dans le corps d'une fonction utilisant des arguments variadiques, les valeurs de ces arguments peuvent être accédées à l'aide des fonctionnalités de la bibliothèque <cstdarg> :

Défini dans l'en-tête <cstdarg>

  • va_start — permet l'accès aux arguments d'une fonction variadique (macro de fonction)
  • va_arg — accède au prochain argument de la fonction variadique (macro de fonction)
  • va_copy (C++11) — crée une copie des arguments de la fonction variadique (macro de fonction)
  • va_end — termine le parcours des arguments de la fonction variadique (macro de fonction)
  • va_list — contient les informations nécessaires à va_start, va_arg, va_end et va_copy (typedef)

Le comportement de la macro va_start est indéfini si le dernier paramètre avant l'ellipse a un type référence, ou a un type non compatible avec le type résultant des promotions d'arguments par défaut.

Si un expansion de pack ou une entité résultant d'une capture de lambda est utilisé comme dernier paramètre dans va_start, le programme est mal formé, aucun diagnostic requis.

(depuis C++11)

Alternatives

  • Les modèles variadiques peuvent aussi être utilisés pour créer des fonctions acceptant un nombre variable d'arguments. Ils sont souvent le meilleur choix car ils n'imposent pas de restrictions sur les types des arguments, n'effectuent pas de promotions entières et flottantes, et sont sûrs en termes de types.
  • Si tous les arguments variables partagent un type commun, un std::initializer_list fournit un mécanisme pratique (bien que de syntaxe différente) pour accéder aux arguments variables. Dans ce cas, toutefois, les arguments ne peuvent pas être modifiés, car std::initializer_list ne peut fournir qu'un pointeur const vers leurs éléments.

(depuis C++11)

Notes

Dans le langage C jusqu'à C23, au moins un paramètre nommé doit apparaître avant le paramètre d'ellipse, donc R printz(...); n'est pas valide avant C23. En C++, cette forme est autorisée bien que les arguments passés à une telle fonction ne soient pas accessibles, et elle est couramment utilisée comme surcharge de repli dans SFINAE, en exploitant la priorité la plus basse de la conversion d'ellipse dans la résolution de surcharge.

Cette syntaxe des arguments variadiques a été introduite en C++ de 1983 sans la virgule avant l'ellipse. Lorsque C89 a adopté les prototypes de fonctions du C++, il a remplacé cette syntaxe par une syntaxe exigeant la virgule. Par compatibilité, C++98 accepte à la fois la forme de style C++ f(int n...) et la forme de style C f(int n, ...). La grammaire originale de style C++ est obsolète depuis C++26.

La virgule peut être utilisée dans les modèles de fonctions abrégés pour que l'ellipse désigne une fonction variadique au lieu d'un modèle variadique :

void f1(auto...); // équivalent à template<class... Ts> void f3(Ts...)void f2(auto, ...); // équivalent à template<class T> void f3(T, ...)

(depuis C++20)

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.
