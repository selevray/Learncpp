Comparaisons par défaut (depuis C++20)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Les fonctions d'opérateur de comparaison peuvent être explicitement défaut pour demander au compilateur de générer la comparaison par défaut correspondante pour une classe.

Définition

Une fonction d'opérateur de comparaison défaut est une fonction d'opérateur de comparaison non template (c'est-à-dire <=>, ==, !=, <, >, <= ou >=) satisfaisant toutes les conditions suivantes :

  • Elle est une fonction membre non statique ou un ami d'une classe C.
  • Elle est définie comme défaut dans C ou dans un contexte où C est complet.
  • Elle possède deux paramètres de type const C& ou deux paramètres de type C, où le paramètre objet implicite (le cas échéant) est considéré comme le premier paramètre.

Une telle fonction d'opérateur de comparaison est appelée une fonction d'opérateur de comparaison défaut pour la classe C.

struct X
{
    bool operator==(const X&) const = default; // OK
    bool operator==(const X&) = default;       // Error : l'objet implicite
                                               //        le type du paramètre est X&
    bool operator==(this X, X) = default;      // OK
};

struct Y
{
    friend bool operator==(Y, Y) = default;        // OK
    friend bool operator==(Y, const Y&) = default; // Error : types de paramètres différents
};

bool operator==(const Y&, const Y&) = default;     // Error : n'est pas un ami de Y

Les recherches de noms et les vérifications d'accès dans la définition implicite d'une fonction d'opérateur de comparaison sont effectuées depuis un contexte équivalent à son corps de fonction. Une définition d'une fonction d'opérateur de comparaison comme défaut qui apparaît dans une classe doit être la première déclaration de cette fonction.

Ordre de comparaison par défaut

Étant donnée une classe C, une liste de sous-objets est formée par les sujets suivants, dans l'ordre :

  • Les sous-objets de classes de base directes de C, dans l'ordre de déclaration.
  • Les membres de données non statiques de C, dans l'ordre de déclaration.
    • Si un sous-objet membre est de type tableau, il est développé en la séquence de ses éléments, dans l'ordre des indices croissants. Le développement est récursif : les éléments de tableau de types tableau sont développés à nouveau jusqu'à ce qu'il n'existe plus aucun sous-objet de type tableau.

Pour tout objet x de type C, dans les descriptions suivantes :

  • Soit n le nombre de sous-objets dans la liste de sous-objets (développée) de x.
  • Soit x_i le ie sous-objet de la liste de sous-objets (développée) de x, où x_i est formé par une suite de conversions dérivée vers base, de expressions d'accès à un membre de classe et de expressions d'indexation de tableau appliquées à x.
struct S {};

struct T : S
{
    int arr[2][2];
} t;

// La liste des sous-objets de « t » se compose des 5 sous-objets suivants, dans l'ordre :
// (S)t → t[0][0] → t[0][1] → t[1][0] → t[1][1]

Comparaison à trois voies

Un operator<=> pour un type classe peut être défini comme défaut avec n'importe quel type de retour.

Types de catégorie de comparaison

Il existe trois types de catégorie de comparaison :

  • std::strong_ordering
  • std::weak_ordering
  • std::partial_ordering
Type Les valeurs équivalentes sont.. Les valeurs incomparables sont..
std::strong_ordering indistinguishable non autorisé
std::weak_ordering distinguishable non autorisé
std::partial_ordering distinguishable allowed

Comparaison à trois voies synthétisée

La comparaison à trois voies synthétisée de type T entre les glvalues a et b de même type est définie comme suit :

  • Si la résolution de surcharge pour a <=> b aboutit à un candidat utilisable, et peut être explicitement convertie en T au moyen de static_cast, la comparaison synthétisée est static_cast<T>(a <=> b).

  • Sinon, si l'une des conditions suivantes est satisfaite, la comparaison synthétisée n'est pas définie :

    • La résolution de surcharge pour a <=> b trouve au moins un candidat viable.
    • T n'est pas un type de catégorie de comparaison.
    • La résolution de surcharge pour a == b n'aboutit à aucun candidat utilisable.
    • La résolution de surcharge pour a < b n'aboutit à aucun candidat utilisable.

  • Sinon, si T est std::strong_ordering, la comparaison synthétisée est

a == b ? std::strong_ordering::equal :
a < b  ? std::strong_ordering::less :
         std::strong_ordering::greater
  • Sinon, si T est std::weak_ordering, la comparaison synthétisée est
a == b ? std::weak_ordering::equivalent :
a < b  ? std::weak_ordering::less :
         std::weak_ordering::greater
  • Sinon (T est std::partial_ordering), la comparaison synthétisée est
a == b ? std::partial_ordering::equivalent :
a < b  ? std::partial_ordering::less :
b < a  ? std::partial_ordering::greater :
         std::partial_ordering::unordered

Type de retour substitué

Si le type de retour déclaré d'une fonction d'opérateur de comparaison à trois voies défaut (operator<=>) pour un type classe C est auto, le type de retour est déduit à partir des types de retour des comparaisons à trois voies entre les sous-objets correspondants d'un objet x de type C.

Pour chaque sous-objet x_i de la liste de sous-objets (développée) de x :

  1. Effectuer la résolution de surcharge pour x_i <=> x_i ; si la résolution de surcharge n'aboutit à aucun candidat utilisable, la fonction défaut operator<=> est définie comme supprimée.
  2. Notons la version sans qualificateur cv du type de x_i <=> x_i R_i ; si R_i n'est pas un type de catégorie de comparaison, la fonction défaut operator<=> est définie comme supprimée.

Si la fonction défaut operator<=> n'est pas définie comme supprimée, son type de retour est déduit comme std::common_comparison_category_t<R_1, R_2, ..., R_n>.

Type de retour non substitué

Si le type de retour déclaré de la operator<=> défaut n'est pas auto, il ne peut contenir aucun type substitué (par exemple decltype(auto)).

S'il existe un sous-objet x_i dans la liste de sous-objets (développée) de x tel que la comparaison à trois voies synthétisée du type de retour déclaré entre x_i et x_i n'est pas définie, la fonction défaut operator<=> est définie comme supprimée.

Résultat de la comparaison

Soient x et y les paramètres d'une operator<=> défaut, notons chaque sous-objet de la liste de sous-objets (développée) de x et de y respectivement x_i et y_i. La comparaison à trois voies par défaut entre x et y est effectuée en comparant les sous-objets correspondants x_i et y_i dans l'ordre croissant de i.

Soit R le type de retour (éventuellement déduit), le résultat de la comparaison entre x_i et y_i est le résultat de la comparaison à trois voies synthétisée de type R entre x_i et y_i.

  • Lors de la comparaison à trois voies par défaut entre x et y, si une comparaison sous-objet par sous-objet entre x_i et y_i produit un résultat v_i tel que la conversion contextuelle de v_i != 0 en bool donne true, la valeur de retour est une copie de v_i (les sous-objets restants ne sont pas comparés).
  • Sinon, la valeur de retour est static_cast<R>(std::strong_ordering::equal).
#include <compare>
#include <iostream>
#include <set>

struct Point
{
    int x;
    int y;
    auto operator<=>(const Point&) const = default;
    /* fonctions non comparatives */
};

int main()
{
    Point pt1{1, 1}, pt2{1, 2};
    std::set<Point> s; // OK
    s.insert(pt1);     // OK

    // les fonctions opérateurs de comparaison à deux voies ne sont pas obligatoirement définies explicitement :
    // operator== est déclaré implicitement (voir ci-dessous)
    // les résolutions de surcharge des autres candidats sélectionneront les candidats réécrits
    std::cout << std::boolalpha
        << (pt1 == pt2) << ' '  // false
        << (pt1 != pt2) << ' '  // true
        << (pt1 <  pt2) << ' '  // true
        << (pt1 <= pt2) << ' '  // true
        << (pt1 >  pt2) << ' '  // false
        << (pt1 >= pt2) << ' '; // false
}

Comparaison d'égalité

Déclaration explicite

Une operator== pour un type classe peut être déclarée par défaut (defaulted) avec le type de retour bool.

Étant donné une classe C et un objet x de type C, s'il existe un sous-objet x_i dans la liste des sous-objets (développée) de x tel que la résolution de surcharge pour x_i == x_i ne produit aucun candidat utilisable, la operator== defaulted est définie comme supprimée.

Soient x et y les paramètres d'un operator== defaulted, et notons chaque sous-objet de la liste des sous-objets (développée) de x et de y respectivement x_i et y_i. La comparaison d'égalité par défaut entre x et y est effectuée en comparant les sous-objets correspondants x_i et y_i dans l'ordre croissant de i.

Le résultat de la comparaison entre x_i et y_i est le résultat de x_i == y_i.

  • Lors de la comparaison d'égalité par défaut entre x et y, si une comparaison sous-objet par sous-objet entre x_i et y_i produit un résultat v_i tel que la conversion contextuelle de v_i en bool donne false, la valeur de retour est false (les sous-objets restants ne sont pas comparés).
  • Sinon, la valeur de retour est true.
#include <iostream>

struct Point
{
    int x;
    int y;
    bool operator==(const Point&) const = default;
    /* fonctions non comparatives */
};

int main()
{
    Point pt1{3, 5}, pt2{2, 5};
    std::cout << std::boolalpha
        << (pt1 != pt2) << '\n'  // true
        << (pt1 == pt1) << '\n'; // true

    struct [[maybe_unused]] { int x{}, y{}; } p, q;
    // if (p == q) {} // Erreur : operator== n'est pas défini
}

Déclaration implicite

Si une classe C ne déclare explicitement aucun membre ni aucune amitié nommé operator==, un opérateur est déclaré implicitement pour chaque operator<=> défini comme defaulted. Chaque operator== déclaré implicitement possède le même accès et la même définition de fonction, et se trouve dans la même portée de classe que le operator<=> defaulted correspondant, avec les modifications suivantes :

  • Le identifiant de déclarateur est remplacé par operator==.
  • Le type de retour est remplacé par bool.
template<typename T>
struct X
{
    friend constexpr std::partial_ordering operator<=>(X, X)
        requires (sizeof(T) != 1) = default;
    // déclare implicitement : friend constexpr bool operator==(X, X)
    //                          requires (sizeof(T) != 1) = default;

    [[nodiscard]] virtual std::strong_ordering operator<=>(const X&) const = default;
    // déclare implicitement : [[nodiscard]] virtual bool
    //                          operator==(const X&) const = default;
};

Comparaison secondaire

Une fonction opérateur de comparaison secondaire (!=, <, >, <= ou >=) pour un type classe peut être déclarée par défaut (defaulted) avec le type de retour bool.

Soit @ l'un des cinq opérateurs de comparaison secondaires ; pour chaque operator@ defaulted de paramètres x et y, jusqu'à deux résolutions de surcharge sont effectuées (sans considérer le operator@ defaulted comme candidat) pour déterminer s'il est défini comme supprimé.

  • La première résolution de surcharge est effectuée pour x @ y. Si la résolution de surcharge ne produit aucun candidat utilisable, ou si le candidat sélectionné n'est pas un candidat réécrit, la operator@ defaulted est définie comme supprimée. Il n'y a pas de seconde résolution de surcharge dans ces cas.
  • La seconde résolution de surcharge est effectuée pour le candidat réécrit sélectionné de x @ y. Si la résolution de surcharge ne produit aucun candidat utilisable, la operator@ defaulted est définie comme supprimée.

Si x @ y ne peut pas être implicitement converti en bool, la operator@ defaulted est définie comme supprimée.

Si le operator@ defaulted n'est pas défini comme supprimé, il produit x @ y.

struct HasNoRelational {};

struct C
{
    friend HasNoRelational operator<=>(const C&, const C&);
    bool operator<(const C&) const = default; // OK, la fonction est defaulted
};

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 2539 C++20 la comparaison à trois voies synthétisée choisirait static_cast même si la conversion explicite n'est pas disponible ne choisit pas static_cast dans ce cas
CWG 2546 C++20 la operator@ secondaire defaulted n'était pas définie comme supprimée si la résolution de surcharge de x @ y sélectionnait un candidat réécrit non utilisable définie comme supprimée dans ce cas
CWG 2547 C++20 il n'était pas clair si les fonctions opérateurs de comparaison pour des non-classes pouvaient être declarées par défaut elles ne peuvent pas être declarées par défaut
CWG 2568 C++20 l'implémentation implicite des fonctions opérateurs de comparaison pouvait violer les règles d'accès aux membres les vérifications d'accès sont effectuées depuis un contexte équivalent à leurs corps de fonction
