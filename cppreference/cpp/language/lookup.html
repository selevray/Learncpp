Recherche de noms

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

La recherche de noms est la procédure par laquelle un nom, lorsqu'il est rencontré dans un programme, est associé à la déclaration qui l'a introduit.

Par exemple, pour compiler std::cout << std::endl;, le compilateur effectue :

  • une recherche de nom non qualifiée pour le nom std, qui trouve la déclaration de l'espace de noms std dans l'en-tête <iostream>
  • une recherche de nom qualifiée pour le nom cout, qui trouve une déclaration de variable dans l'espace de noms std
  • une recherche de nom qualifiée pour le nom endl, qui trouve une déclaration de modèle de fonction dans l'espace de noms std
  • à la fois une recherche dépendante des arguments pour le nom operator<<, qui trouve plusieurs déclarations de modèles de fonctions dans l'espace de noms std, et une recherche de nom qualifiée pour le nom std::ostream::operator<<, qui trouve plusieurs déclarations de fonctions membres dans la classe std::ostream.

Pour les noms de fonctions et de modèles de fonctions, la recherche de noms peut associer plusieurs déclarations à un même nom, et peut obtenir des déclarations supplémentaires par recherche dépendante des arguments. La déduction d'arguments de modèle peut également s'appliquer, et l'ensemble des déclarations est transmis à la résolution de surcharge, qui sélectionne la déclaration utilisée. Les règles d'accès membre, si applicables, ne sont prises en compte qu'après la recherche de noms et la résolution de surcharge.

Pour tous les autres noms (variables, espaces de noms, classes, etc.), la recherche de noms ne peut associer plusieurs déclarations que si elles déclarent la même entité, sinon elle doit produire une déclaration unique pour que le programme compile. La recherche d'un nom dans une portée trouve toutes les déclarations de ce nom, avec une exception connue sous le nom de « struct hack » ou « masquage de type/non-type » : dans une même portée, certaines occurrences d'un nom peuvent désigner une déclaration de classe/struct/union/enum qui n'est pas un typedef, alors que toutes les autres occurrences du même nom désignent soit la même variable, le même membre de donnée non statique ou le même énumérateur, soit toutes des noms de fonctions ou de modèles de fonctions éventuellement surchargés. Dans ce cas, il n'y a pas d'erreur, mais le nom de type est masqué à la recherche (le code doit utiliser un spécificateur de type elaboré pour y accéder).

Types de recherche

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
CWG 2063 C++98 le « struct hack » ne s'appliquait pas en portée de classe (ce qui casse la compatibilité avec C) applied
CWG 2218 C++98 la recherche de noms non fonctionnels (modèles) ne pouvait pas associer plusieurs déclarations, même si elles déclaraient la même entité allowed
