qualificateurs de type cv (const et volatile)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Apparaissent dans tout spécificateur de type, y compris decl-specifier-seq de la grammaire des déclarations, pour spécifier la constance ou la volatilité de l'objet déclaré ou du type nommé.

  • const - indique que le type est constant.
  • volatile - indique que le type est volatile.

Explication

Tout type (éventuellement incomplet) autre qu'un type fonction ou un type référence est un type appartenant à un groupe de quatre types distincts mais liés :

  • Une version non qualifiée cv.
  • Une version qualifiée const.
  • Une version qualifiée volatile.
  • Une version qualifiée const volatile.

Ces quatre types du même groupe ont la même représentation et les mêmes exigences d'alignement.

Les types tableau sont considérés comme ayant la même qualification cv que leurs types d'éléments.

Objets const et volatile

Lorsqu'un objet est créé pour la première fois, les qualificateurs cv utilisés (qui peuvent faire partie de decl-specifier-seq ou d'un declarator dans une déclaration, ou faire partie de type-id dans une expression new) déterminent la constance ou la volatilité de l'objet, comme suit :

  • Un objet const est

    • un objet dont le type est qualifié const, ou
    • un sous-objet non mutable d'un objet const. Un tel objet ne peut pas être modifié : tenter de le faire directement est une erreur à la compilation, et tenter de le faire indirectement (par exemple en modifiant l'objet const à travers une référence ou un pointeur vers un type non const) entraîne un comportement indéfini.

  • Un objet volatile est

    • un objet dont le type est qualifié volatile,
    • un sous-objet d'un objet volatile, ou
    • un sous-objet mutable d'un objet const volatile. Chaque accès (opération de lecture ou d'écriture, appel de fonction membre, etc.) effectué à travers une expression glvalue de type qualifié volatile est traité comme un effet de bord visible pour les besoins de l'optimisation (c'est-à-dire que, au sein d'un même fil d'exécution, les accès volatiles ne peuvent être ni supprimés par l'optimisation ni réordonnés avec un autre effet de bord visible qui est séquencé avant ou après l'accès volatile. Cela rend les objets volatils adaptés à la communication avec un gestionnaire de signal, mais pas avec un autre fil d'exécution, voir std::memory_order). Toute tentative d'accès à un objet volatile à travers une glvalue de type non volatile (par exemple à travers une référence ou un pointeur vers un type non volatile) entraîne un comportement indéfini.

  • Un objet const volatile est

    • un objet dont le type est qualifié const volatile,
    • un sous-objet non mutable d'un objet const volatile,
    • un sous-objet const d'un objet volatile, ou
    • un sous-objet volatile non mutable d'un objet const. Se comporte à la fois comme un objet const et comme un objet volatile.

Chaque qualificateur cv (const et volatile) peut apparaître au plus une fois dans toute séquence de qualificateurs cv. Par exemple, const const et volatile const volatile ne sont pas des séquences de qualificateurs cv valides.

spécificateur mutable

  • mutable - permet la modification du membre de classe déclaré mutable même si l'objet englobant est déclaré const (c'est-à-dire que le membre de classe est mutable).

Peut apparaître dans la déclaration de membres de classe non statiques de classe de type non référence et non const :

class X
{
    mutable const int* p; // OK
    mutable int* const q; // mal formé
    mutable int&       r; // mal formé
};

mutable est utilisé pour indiquer que le membre n'affecte pas l'état visible de l'extérieur de la classe (comme c'est souvent le cas pour les mutex, les caches de mémoïsation, l'évaluation paresseuse et l'instrumentation d'accès).

class ThreadsafeCounter
{
    mutable std::mutex m; // La « règle M&M » : mutable et mutex vont ensemble
    int data = 0;
public:
    int get() const
    {
        std::lock_guard<std::mutex> lk(m);
        return data;
    }

    void inc()
    {
        std::lock_guard<std::mutex> lk(m);
        ++data;
    }
};

Conversions

Il existe un ordre partiel des qualificateurs cv selon l'ordre croissant des restrictions. On dit que le type est plus ou moins qualifié cv que :

  • non qualifié < const
  • non qualifié < volatile
  • non qualifié < const volatile
  • const < const volatile
  • volatile < const volatile

Les références et pointeurs vers des types qualifiés cv peuvent être implicitement convertis en références et pointeurs vers des types plus qualifiés cv, voir conversions de qualification pour plus de détails.

Pour convertir une référence ou un pointeur vers un type qualifié cv en une référence ou un pointeur vers un type moins qualifié cv, const_cast doit être utilisé.

Notes

Le qualificateur const utilisé dans la déclaration d'une variable non locale non volatile [non-modèle (depuis C++14) | non-inline (depuis C++17)] qui n'est pas déclarée extern lui donne une liaison interne. Cela diffère du C, où les variables const de portée fichier ont une liaison externe.

La grammaire du langage C++ traite mutable comme un spécificateur de classe de stockage, et non comme un qualificateur de type, mais elle n'affecte ni la classe de stockage ni la liaison.

Certaines utilisations de volatile sont obsolètes :

  • lvalue de type volatile en tant qu'opérande des opérateurs d'incrémentation/décrémentation intégrés ;
  • lvalue de type volatile en tant qu'opérande gauche d'une affectation directe intégrée, sauf si l'expression d'affectation directe apparaît dans un contexte non évalué ou est une expression à valeur ignorée ;
  • type d'objet volatile en tant que type de paramètre de fonction ou type de valeur de retour ;
  • qualificateur volatile dans une déclaration de liaison structurée.

(depuis C++20)

Mots-clés

const, volatile, mutable

Exemple

#include <cstdlib>

int main()
{
    int n1 = 0;          // objet non const
    const int n2 = 0;    // objet const
    int const n3 = 0;    // objet const (identique à n2)
    volatile int n4 = 0; // objet volatile

    const struct
    {
        int n1;
        mutable int n2;
    } x = {0, 0};        // objet const avec membre mutable

    n1 = 1;   // OK : objet modifiable
//  n2 = 2;   // error: non-modifiable object
    n4 = 3;   // OK : traité comme un effet de bord
//  x.n1 = 4; // error : un membre d'un objet const est const
    x.n2 = 4; // OK : un membre mutable d'un objet const n'est pas const

    const int& r1 = n1; // référence sur const liée à un objet non const
//  r1 = 2; // error : tentative de modification via une référence sur const
    const_cast<int&>(r1) = 2; // OK : modifie l'objet non const n1

    const int& r2 = n2; // référence sur const liée à un objet const
//  r2 = 2; // error : tentative de modification via une référence sur const
//  const_cast<int&>(r2) = 2; // comportement indéfini : tentative de modification de l'objet const n2

    [](...){}(n3, n4, x, r2); // voir aussi : [[maybe_unused]]

    std::system("g++ -O3 -Wa,-adhln ./main.cpp"); // peut générer de l'asm sur les systèmes POSIX
}

Sortie possible :

# typical machine code produced on an x86_64 platform
# (only the code that contributes to observable side-effects is emitted)
main:
    movl    $0, -4(%rsp) # volatile int n4 = 0;
    movl    $3, -4(%rsp) # n4 = 3;
    xorl    %eax, %eax   # return 0 (implicit)
    ret
