Déclaration d'union

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Une union est un type de classe particulier qui ne peut contenir qu'un seul de ses membres de données non statiques à la fois.

Syntaxe

Le spécificateur de classe d'une déclaration d'union est similaire à une déclaration class ou struct :

| | | | union attr class-head-name { member-specification } | | | |

  • attr — (depuis C++11) séquence optionnelle d'un nombre quelconque d'attributs
  • class-head-name — le nom de l'union définie. Peut être précédé optionnellement de nested-name-specifier (séquence de noms et d'opérateurs de résolution de portée, se terminant par un opérateur de résolution de portée). Le nom peut être omis, auquel cas l'union est sans nom
  • member-specification — liste de spécificateurs d'accès, de déclarations et définitions de membres objets et de fonctions membres.

Une union peut avoir des fonctions membres (y compris des constructeurs et des destructeurs), mais pas de fonctions virtuelles.

Une union ne peut pas avoir de classes de base et ne peut pas être utilisée comme classe de base.

Une union ne peut pas avoir de membres de données non statiques de types référence.

Les unions ne peuvent pas contenir de membre de données non statique dont la fonction membre spéciale n'est pas triviale (constructeur de copie, opérateur d'affectation par copie, ou destructeur).

(jusqu'à C++11)

Si une union contient un membre de données non statique dont la fonction membre spéciale n'est pas triviale (constructeur de copie/de déplacement, affectation par copie/par déplacement, ou destructeur), cette fonction est supprimée par défaut dans l'union et doit être définie explicitement par le programmeur.

Si une union contient un membre de données non statique ayant un constructeur par défaut non trivial, le constructeur par défaut de l'union est supprimé par défaut, sauf si un membre variant de l'union possède un initialisateur de membre par défaut.

Au plus un membre variant peut avoir un initialisateur de membre par défaut.

(depuis C++11)

Comme pour une déclaration struct, l'accès par défaut aux membres d'une union est public.

Explication

L'union a au moins la taille nécessaire pour contenir son plus grand membre de données, mais elle n'est généralement pas plus grande. Les autres membres de données sont destinés à être alloués dans les mêmes octets que ce plus grand membre. Les détails de cette allocation sont définis par l'implémentation, si ce n'est que tous les membres de données non statiques ont la même adresse. Lire le membre de l'union qui n'a pas été écrit en dernier est un comportement indéfini. De nombreux compilateurs implémentent, comme extension de langage non standard, la possibilité de lire les membres inactifs d'une union.

#include <cstdint>
#include <iostream>

union S
{
    std::int32_t n;     // occupe 4 octets
    std::uint16_t s[2]; // occupe 4 octets
    std::uint8_t c;     // occupe 1 octet
};                      // l'union entière occupe 4 octets

int main()
{
    S s = {0x12345678}; // initialise le premier membre, s.n est maintenant le membre actif
    // À ce stade, lire s.s ou s.c est un comportement indéfini,
    // mais la plupart des compilateurs le définissent.
    std::cout << std::hex << "s.n = " << s.n << '\n';

    s.s[0] = 0x0011; // s.s est maintenant le membre actif
    // À ce stade, lire s.n ou s.c est un comportement indéfini,
    // mais la plupart des compilateurs le définissent.
    std::cout << "s.c is now " << +s.c << '\n' // 11 ou 00, selon la plateforme
              << "s.n is now " << s.n << '\n'; // 12340011 or 00115678
}

Sortie possible :

s.n = 12345678
s.c is now 0
s.n is now 115678

Chaque membre est alloué comme s'il était le seul membre de la classe.

Si les membres d'une union sont des classes avec des constructeurs et destructeurs définis par l'utilisateur, pour changer le membre actif, un destructeur explicite et un placement new sont généralement nécessaires :

#include <iostream>
#include <string>
#include <vector>

union S
{
    std::string str;
    std::vector<int> vec;
    ~S() {} // a besoin de savoir quel membre est actif, possible uniquement dans une classe de type union
};          // l'union entière occupe max(sizeof(string), sizeof(vector<int>))

int main()
{
    S s = {"Hello, world"};
    // à ce stade, lire s.vec est un comportement indéfini
    std::cout << "s.str = " << s.str << '\n';
    s.str.~basic_string();
    new (&s.vec) std::vector<int>;
    // désormais, s.vec est le membre actif de l'union
    s.vec.push_back(10);
    std::cout << s.vec.size() << '\n';
    s.vec.~vector();
}

Output:

s.str = Hello, world
1

(depuis C++11)

Si deux membres d'union sont des types standard-layout, il est bien défini d'examiner leur sous-séquence commune sur n'importe quel compilateur.

Durée de vie des membres

La durée de vie d'un membre d'union commence lorsque ce membre devient actif. Si un autre membre était actif auparavant, sa durée de vie se termine.

Lorsque le membre actif d'une union est changé par une expression d'affectation de la forme E1 = E2 qui utilise soit l'opérateur d'affectation intégré, soit un opérateur d'affectation trivial, pour chaque membre X de l'union qui apparaît dans les sous-expressions d'accès au membre et d'indice de tableau de E1 et qui n'est pas une classe avec un constructeur par défaut non trivial ou supprimé, si la modification de X aurait un comportement indéfini selon les règles d'aliasing de types, un objet du type de X est implicitement créé dans le stockage désigné ; aucune initialisation n'est effectuée et le début de sa durée de vie est séquencé après le calcul de valeur des opérandes gauche et droit et avant l'affectation.

union A { int x; int y[4]; };
struct B { A a; };
union C { B b; int k; };

int f()
{
    C c;               // ne démarre la durée de vie d'aucun membre de l'union
    c.b.a.y[3] = 4;    // OK : "c.b.a.y[3]", désigne les membres d'union c.b et c.b.a.y ;
                       // Ceci crée des objets destinés à contenir les membres d'union c.b et c.b.a.y
    return c.b.a.y[3]; // OK : c.b.a.y désigne l'objet nouvellement créé
}

struct X { const int a; int b; };
union Y { X x; int k; };

void g()
{
    Y y = {{1, 2}}; // OK, y.x est le membre d'union actif
    int n = y.x.a;
    y.k = 4;   // OK : termine la durée de vie de y.x, y.k est le membre actif de l'union
    y.x.b = n; // comportement indéfini : y.x.b modifié en dehors de sa durée de vie,
               // "y.x.b" désigne y.x, mais le constructeur par défaut de X est supprimé,
               // donc la durée de vie du membre d'union y.x ne démarre pas implicitement
}

Le constructeur de déplacement, l'opérateur d'affectation par déplacement, *(depuis C++11)*constructeur de copie et l'opérateur d'affectation par copie triviaux des types union copient les représentations d'objets. Si la source et la destination ne sont pas le même objet, ces fonctions membres spéciales démarrent la durée de vie de chaque objet (sauf ceux qui ne sont ni sous-objets de la destination ni de type à durée de vie implicite) imbriqué dans la destination, correspondant à celui imbriqué dans la source avant la copie. Sinon, elles ne font rien. Deux objets union ont le même membre actif correspondant (le cas échéant) après construction ou affectation via des fonctions spéciales triviales.

Unions anonymes

Une union anonyme est une définition d'union sans nom qui ne définit simultanément aucune variable (y compris des objets du type union, des références ou des pointeurs vers l'union).

| | | | union { member-specification } ; | | | |

Les unions anonymes ont des restrictions supplémentaires : elles ne peuvent pas avoir de fonctions membres, ne peuvent pas avoir de membres de données statiques, et tous leurs membres de données doivent être publics. Les seules déclarations autorisées sont les membres de données non statiques et des déclarations static_assert (depuis C++11).

Les membres d'une union anonyme sont injectés dans la portée englobante (et ne doivent pas entrer en conflit avec d'autres noms qui y sont déclarés).

int main()
{
    union
    {
        int a;
        const char* p;
    };
    a = 1;
    p = "Jennifer";
}

Les unions anonymes de portée d'espace de noms doivent être déclarées static, sauf si elles apparaissent dans un espace de noms sans nom.

Classes de type union

Une classe de type union est soit une union, soit une classe (non union) qui possède au moins une union anonyme comme membre. Une classe de type union a un ensemble de membres variants :

  • les membres de données non statiques de ses unions anonymes membres ;
  • de plus, si la classe de type union est une union, ses membres de données non statiques qui ne sont pas des unions anonymes.

Les classes de type union peuvent être utilisées pour implémenter des unions étiquetées.

#include <iostream>

// S possède un membre de données non statique (tag), trois membres énumérateurs (CHAR, INT, DOUBLE),
// et trois membres variantes (c, i, d)
struct S
{
    enum{CHAR, INT, DOUBLE} tag;
    union
    {
        char c;
        int i;
        double d;
    };
};

void print_s(const S& s)
{
    switch(s.tag)
    {
        case S::CHAR: std::cout << s.c << '\n'; break;
        case S::INT: std::cout << s.i << '\n'; break;
        case S::DOUBLE: std::cout << s.d << '\n'; break;
    }
}

int main()
{
    S s = {S::CHAR, 'a'};
    print_s(s);
    s.tag = S::INT;
    s.i = 123;
    print_s(s);
}

Output:

a
123

La bibliothèque standard C++ inclut std::variant, qui peut remplacer de nombreux usages des unions et des classes de type union. L'exemple ci-dessus peut être réécrit ainsi

#include <iostream>
#include <variant>

int main()
{
    std::variant<char, int, double> s = 'a';
    std::visit([](auto x){ std::cout << x << '\n';}, s);
    s = 123;
    std::visit([](auto x){ std::cout << x << '\n';}, s);
}

Output:

a
123

(depuis C++17)
