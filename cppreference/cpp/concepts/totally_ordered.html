std::totally_ordered, std::totally_ordered_with

Défini dans l'en-tête <concepts>

template< class T >
concept totally_ordered =
    std::equality_comparable<T> && __PartiallyOrderedWith<T, T>;  // (1) (depuis C++20)

template< class T, class U >
concept totally_ordered_with =
    std::totally_ordered<T> &&
    std::totally_ordered<U> &&
    std::equality_comparable_with<T, U> &&
    std::totally_ordered<
        std::common_reference_t<
            const std::remove_reference_t<T>&,
            const std::remove_reference_t<U>&>> &&
    __PartiallyOrderedWith<T, U>;  // (2) (depuis C++20)

Concepts auxiliaires

template< class T, class U >
concept __PartiallyOrderedWith =
    requires(const std::remove_reference_t<T>& t,
             const std::remove_reference_t<U>& u) {
        { t <  u } -> boolean-testable;
        { t >  u } -> boolean-testable;
        { t <= u } -> boolean-testable;
        { t >= u } -> boolean-testable;
        { u <  t } -> boolean-testable;
        { u >  t } -> boolean-testable;
        { u <= t } -> boolean-testable;
        { u >= t } -> boolean-testable;
    };  // (3) ( exposition uniquement* )

  1. Le concept std::totally_ordered spécifie que les opérateurs de comparaison ==,!=,<,>,<=,>= sur un type produisent des résultats cohérents avec un ordre total strict sur ce type.

  2. Le concept std::totally_ordered_with spécifie que les opérateurs de comparaison ==,!=,<,>,<=,>= sur des opérandes (éventuellement de types mixtes) T et U produisent des résultats cohérents avec un ordre total strict. Comparer des opérandes mixtes produit des résultats équivalents à la comparaison des opérandes convertis en leur type commun.

  3. Le concept __PartiallyOrderedWith réservé à l'exposition spécifie qu'une valeur de type T et une valeur de type U peuvent être comparées dans un ordre partiel l'une avec l'autre (dans les deux sens) en utilisant <, >, <= et >=, et que les résultats des comparaisons sont cohérents.

Exigences sémantiques

Ces concepts ne sont modélisés que s'ils sont satisfaits et que tous les concepts qu'ils subsument sont modélisés.

  1. std::totally_ordered<T> n'est modélisé que si, étant donnés des lvalues a, b et c de type const std::remove_reference_t<T> :
  • Exactement une de bool(a < b), bool(a > b) et bool(a == b) est true ;
  • Si bool(a < b) et bool(b < c) sont tous deux true, alors bool(a < c) est true ;
  • bool(a > b) == bool(b < a)
  • bool(a >= b) == !bool(a < b)
  • bool(a <= b) == !bool(b < a)
  1. std::totally_ordered_with<T, U> n'est modélisé que si, étant donnés
  • t et t2, des lvalues désignant des objets égaux distincts de types const std::remove_reference_t<T> et std::remove_reference_t<T> respectivement, et
  • u et u2, des lvalues désignant des objets égaux distincts de types const std::remove_reference_t<U> et std::remove_reference_t<U> respectivement,

soit C égal à std::common_reference_t<const std::remove_reference_t<T>&, const std::remove_reference_t<U>&>, et, étant donnés une expression E et un type C, soit CONVERT_TO<C>(E) :

  • static_cast<C>(std::as_const(E)).

(jusqu'à C++23)

  • static_cast<const C&>(std::as_const(E)) si c'est une expression valide,
  • static_cast<const C&>(std::move(E)) sinon.

(depuis C++23)

les propositions suivantes sont vraies :

  • bool(t < u) == bool(CONVERT_TO<C>(t2) < CONVERT_TO<C>(u2))
  • bool(t > u) == bool(CONVERT_TO<C>(t2) > CONVERT_TO<C>(u2))
  • bool(t <= u) == bool(CONVERT_TO<C>(t2) <= CONVERT_TO<C>(u2))
  • bool(t >= u) == bool(CONVERT_TO<C>(t2) >= CONVERT_TO<C>(u2))
  • bool(u < t) == bool(CONVERT_TO<C>(u2) < CONVERT_TO<C>(t2))
  • bool(u > t) == bool(CONVERT_TO<C>(u2) > CONVERT_TO<C>(t2))
  • bool(u <= t) == bool(CONVERT_TO<C>(u2) <= CONVERT_TO<C>(t2))
  • bool(u >= t) == bool(CONVERT_TO<C>(u2) >= CONVERT_TO<C>(t2))
  1. __PartiallyOrderedWith<T, U> n'est modélisé que si, étant donné
  • toute lvalue t de type const std::remove_reference_t<T>, et
  • toute lvalue u de type const std::remove_reference_t<U>,

les propositions suivantes sont vraies :

  • t < u, t <= u, t > u, t >= u, u < t, u <= t, u > t et u >= t ont le même domaine ;
  • bool(t < u) == bool(u > t);
  • bool(u < t) == bool(t > u);
  • bool(t <= u) == bool(u >= t); and
  • bool(u <= t) == bool(t >= u).

Préservation de l'égalité

Les expressions déclarées dans les requires expressions des concepts de la bibliothèque standard doivent être préservant l'égalité (sauf mention contraire).

Variations d'expressions implicites

Une requires expression qui utilise une expression non modifiante pour un opérande lvalue constant quelconque nécessite également des variations d'expressions implicites.
