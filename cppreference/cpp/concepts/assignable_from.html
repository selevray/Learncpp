std::assignable_from

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <concepts>

template< class LHS, class RHS >
concept assignable_from =
    std::is_lvalue_reference_v<LHS> &&
    std::common_reference_with<
        const std::remove_reference_t<LHS>&,
        const std::remove_reference_t<RHS>&> &&
    requires(LHS lhs, RHS&& rhs) {
        { lhs = std::forward<RHS>(rhs) } -> std::same_as<LHS>;
    };  // (depuis C++20)

Le concept assignable_from<LHS, RHS> spécifie qu'une expression du type et de la catégorie de valeur spécifiés par RHS peut être affectée à une expression lvalue dont le type est spécifié par LHS.

Exigences sémantiques

Soient

  • lhs, une lvalue qui fait référence à un objet lcopy tel que decltype((lhs)) vaut LHS,
  • rhs, une expression telle que decltype((rhs)) est RHS,
  • rcopy, un objet distinct égal à rhs,

assignable_from<LHS, RHS> n'est modélisé que si

  • std::addressof(lhs = rhs) == std::addressof(lcopy) (c'est-à-dire que l'expression d'affectation produit une lvalue faisant référence à l'opérande de gauche) ;
  • Après évaluation de lhs = rhs :
    • lhs est égal à rcopy, sauf si rhs est une xvalue non const faisant référence à lcopy (c'est-à-dire si l'affectation est une auto-affectation par déplacement),
    • si rhs est une glvalue :
      • Si c'est une xvalue non const, l'objet auquel elle fait référence se trouve dans un état valide mais non spécifié ;
      • Sinon, l'objet auquel elle fait référence n'est pas modifié ;

Préservation de l'égalité

Les expressions déclarées dans les requires expressions des concepts de la bibliothèque standard doivent être préservant l'égalité (sauf mention contraire).

Notes

L'affectation n'a pas nécessairement à être une fonction totale. En particulier, si l'affectation à un objet x peut entraîner la modification d'un autre objet y, alors x = y n'est probablement pas dans le domaine de =. Cela se produit typiquement lorsque l'opérande de droite appartient directement ou indirectement à l'opérande de gauche (par exemple avec des pointeurs intelligents vers des nœuds d'une structure de données basée sur des nœuds, ou avec quelque chose comme std::vector<std::any>).

Exemple

#include <atomic>
#include <concepts>
#include <string>

int main()
{
    // Utilisation de base classique, vérifie l'affectation à une référence lvalue
    static_assert(std::is_assignable_v<int&, int>);
    static_assert(std::assignable_from<int&, int>);

    static_assert(std::is_assignable_v<std::string&, std::string>);
    static_assert(std::assignable_from<std::string&, std::string>);

    // Les types fondamentaux ne prennent pas en charge l'affectation à une rvalue
    static_assert(!std::is_assignable_v<int, int>);
    static_assert(!std::assignable_from<int, int>);

    // std::assignable_from n'accepte pas toutes les expressions d'affectation valides :

    // affectation à une référence rvalue
    static_assert(std::is_assignable_v<std::string&&, std::string>);
    static_assert(!std::assignable_from<std::string&&, std::string>);

    // affectation à une rvalue
    static_assert(std::is_assignable_v<std::string, std::string>);
    static_assert(!std::assignable_from<std::string, std::string>);

    // std::atomic::operator= renvoie par valeur
    static_assert(std::is_assignable_v<std::atomic<int>&, int>);
    static_assert(!std::assignable_from<std::atomic<int>&, int>);
}
