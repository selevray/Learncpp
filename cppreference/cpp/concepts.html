Bibliothèque des concepts (depuis C++20)

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

La bibliothèque des concepts fournit les définitions des concepts fondamentaux de la bibliothèque standard, utilisables pour valider à la compilation les arguments de modèle et réaliser une distribution de fonctions fondée sur les propriétés des types. Ces concepts fournissent une base pour le raisonnement équationnel dans les programmes.

La plupart des concepts de la bibliothèque standard imposent à la fois des exigences syntaxiques et sémantiques. On dit qu'un concept standard est satisfait si ses exigences syntaxiques sont respectées, et qu'il est modélisé s'il est satisfait et que ses exigences sémantiques (le cas échéant) le sont également.

En général, seules les exigences syntaxiques peuvent être vérifiées par le compilateur. Si la validité ou la signification d'un programme dépend du fait qu'une suite d'arguments de modèle modélise un concept, et que ce concept est satisfait mais non modélisé, ou si une exigence sémantique n'est pas respectée au point d'utilisation, le programme est mal formé, aucun diagnostic requis.

Préservation de l'égalité

Une expression est préservant l'égalité si elle produit des sorties égales pour des entrées égales, où

  • les entrées sont constituées de ses opérandes (ne rendant pas nécessairement l'expression sémantiquement valide), et
  • les sorties sont constituées de son résultat et de toutes les modifications apportées aux opérandes par l'expression, le cas échéant

où, pour la commodité de la formulation, ses « opérandes » désignent ses plus grandes sous-expressions constituées d'un id-expression ou d'appels de std::move, std::forward et std::declval.

La qualification cv et la catégorie de valeur de chaque opérande sont déterminées en supposant que chaque paramètre de modèle de type dans son type désigne un type d'objet complet non-tableau et non qualifié cv.

Toute expression devant préserver l'égalité doit en outre être stable, c'est-à-dire que deux évaluations de celle-ci avec les mêmes objets d'entrée doivent produire des sorties égales, sans aucune modification explicite intermédiaire de ces objets d'entrée.

Sauf indication contraire, toute expression utilisée dans une requires expression des concepts de la bibliothèque standard doit préserver l'égalité, et l'évaluation de l'expression ne peut modifier que ses opérandes non constants. Les opérandes constants ne doivent pas être modifiés.

Dans la bibliothèque standard, les concepts suivants peuvent avoir des expressions requires ne préservant pas l'égalité :

  • output_iterator
  • indirectly_writable
  • invocable
  • weakly_incrementable
  • range

Variations d'expressions implicites

Une requires expression qui utilise une expression non modifiante pour un opérande lvalue constant exige aussi implicitement des variantes supplémentaires de cette expression acceptant un opérande lvalue non constant ou rvalue (éventuellement constant) pour l'opérande donné, à moins qu'une telle variante ne soit explicitement exigée avec une sémantique différente.

Ces variantes d'expression implicites doivent satisfaire les mêmes exigences sémantiques que l'expression déclarée. La mesure dans laquelle une implémentation valide la syntaxe des variantes est non spécifiée.

template<class T>
concept C = requires(T a, T b, const T c, const T d)
{
    c == d;           // expression #1 : ne modifie pas les opérandes
    a = std::move(b); // expression #2 : modifie les deux opérandes
    a = c;            // expression #3 : modifie l'opérande de gauche `a`
};

// L'expression #1 exige implicitement des variantes d'expression supplémentaires qui
// satisfont aux exigences de c == d (y compris la non-modification),
// comme si les expressions suivantes avaient également été déclarées :

// ------ const == const ------- ------ const == non-const ---
//                                         c  ==           b;
//            c == std::move(d);           c  == std::move(b);
// std::move(c) ==           d;  std::move(c) ==           b;
// std::move(c) == std::move(d); std::move(c) == std::move(b);

// -- non-const == const ------- -- non-const == non-const ---
//           a  ==           d;            a  ==           b;
//           a  == std::move(d);           a  == std::move(b);
// std::move(a) ==           d;  std::move(a) ==           b;
// std::move(a) == std::move(d); std::move(a) == std::move(b);

// L'expression #3 exige implicitement des variantes d'expression supplémentaires qui
// satisfont aux exigences de a = c
// (y compris la non-modification du second opérande),
// comme si les expressions a = b (variante lvalue non constante)
// et a = std::move(c) (variante rvalue constante) avaient été déclarées.

// Note : puisque l'expression #2 exige déjà explicitement la variante rvalue non constante
// (a == std::move(b)), l'expression #3 n'exige plus implicitement celle-ci.

// Le type T satisfait aux exigences syntaxiques explicitement énoncées du
// concept C ci-dessus, mais ne satisfait pas aux exigences implicites supplémentaires
// (c'est-à-dire que T satisfait mais ne modélise pas C) :
// un programme qui exige C<T> est mal formé (aucun diagnostic requis).
struct T
{
    bool operator==(const T&) const { return true; }
    bool operator==(T&) = delete;
};

Concepts de la bibliothèque standard

Défini dans l'espace de noms std

##### Concepts du langage de base {#Core_language_concepts}

Défini dans l'en-tête <concepts>

  • same_as (C++20) — spécifie qu'un type est identique à un autre type (concept)
  • derived_from (C++20) — spécifie qu'un type dérive d'un autre type (concept)
  • convertible_to (C++20) — spécifie qu'un type est implicitement convertible en un autre type (concept)
  • common_reference_with (C++20) — spécifie que deux types partagent un type de référence commun (concept)
  • common_with (C++20) — spécifie que deux types partagent un type commun (concept)
  • integral (C++20) — spécifie qu'un type est un type entier (concept)
  • signed_integral (C++20) — spécifie qu'un type est un type entier signé (concept)
  • unsigned_integral (C++20) — spécifie qu'un type est un type entier non signé (concept)
  • floating_point (C++20) — spécifie qu'un type est un type à virgule flottante (concept)
  • assignable_from (C++20) — spécifie qu'un type est affectable à partir d'un autre type (concept)
  • swappableswappable_with (C++20) — spécifie qu'un type peut être échangé, ou que deux types peuvent être échangés entre eux (concept)
  • destructible (C++20) — spécifie qu'un objet du type peut être détruit (concept)
  • constructible_from (C++20) — spécifie qu'une variable du type peut être construite à partir de, ou liée à, un ensemble de types d'arguments (concept)
  • default_initializable (C++20) — spécifie qu'un objet d'un type peut être construit par défaut (concept)
  • move_constructible (C++20) — spécifie qu'un objet d'un type peut être construit par déplacement (concept)
  • copy_constructible (C++20) — spécifie qu'un objet d'un type peut être construit par copie et construit par déplacement (concept)

##### Concepts de comparaison {#Comparison_concepts}

Défini dans l'en-tête <concepts>

  • boolean-testable ﻿ (C++20) — spécifie qu'un type peut être utilisé dans des contextes booléens (concept exposé uniquement)*
  • equality_comparableequality_comparable_with (C++20) — spécifie que l'opérateur == est une relation d'équivalence (concept)
  • totally_orderedtotally_ordered_with (C++20) — spécifie que les opérateurs de comparaison du type définissent un ordre total (concept)

Défini dans l'en-tête <compare>

  • three_way_comparablethree_way_comparable_with (C++20) — spécifie que l'opérateur <=> produit un résultat cohérent sur les types donnés (concept)

##### Concepts d'objet {#Object_concepts}

Défini dans l'en-tête <concepts>

  • movable (C++20) — spécifie qu'un objet d'un type peut être déplacé et échangé (concept)
  • copyable (C++20) — spécifie qu'un objet d'un type peut être copié, déplacé et échangé (concept)
  • semiregular (C++20) — spécifie qu'un objet d'un type peut être copié, déplacé, échangé et construit par défaut (concept)
  • regular (C++20) — spécifie qu'un type est régulier, c'est-à-dire qu'il est à la fois semiregular et equality_comparable (concept)

##### Concepts d'objets appelables {#Callable_concepts}

Défini dans l'en-tête <concepts>

  • invocableregular_invocable (C++20) — spécifie qu'un type appelable peut être invoqué avec un ensemble donné de types d'arguments (concept)
  • predicate (C++20) — spécifie qu'un type appelable est un prédicat booléen (concept)
  • relation (C++20) — spécifie qu'un type appelable est une relation binaire (concept)
  • equivalence_relation (C++20) — spécifie qu'un relation impose une relation d'équivalence (concept)
  • strict_weak_order (C++20) — spécifie qu'un relation impose un ordre faible strict (concept)
