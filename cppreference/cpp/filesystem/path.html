class path;  // (depuis C++17)

Les objets de type path représentent des chemins sur un système de fichiers. Seuls les aspects syntaxiques des chemins sont traités : le nom de chemin peut représenter un chemin inexistant, voire un chemin qui n'est pas autorisé à exister sur le système de fichiers ou le système d'exploitation actuel.

La syntaxe du nom de chemin est la suivante :

  1. root-name(facultatif) : identifie la racine sur un système de fichiers possédant plusieurs racines (comme "C:" ou "//myserver"). En cas d'ambiguïté, la plus longue séquence de caractères formant un root-name valide est considérée comme le root-name. La bibliothèque standard peut définir des noms de racine supplémentaires, en plus de ceux reconnus par l'API du système d'exploitation.
  2. root-directory(facultatif) : un séparateur de répertoire qui, s'il est présent, marque ce chemin comme absolu. S'il est absent (et que le premier élément autre que le nom de racine est un nom de fichier), alors le chemin est relatif et nécessite un autre chemin comme emplacement de départ pour être résolu en nom de fichier.
  3. Zéro ou plusieurs des éléments suivants :
    • file-name : suite de caractères qui ne sont ni des séparateurs de répertoire ni des séparateurs de répertoire préférés (le système d'exploitation ou le système de fichiers peut imposer des limitations supplémentaires). Ce nom peut désigner un fichier, un lien physique, un lien symbolique ou un répertoire. Deux file-name particuliers sont reconnus :
      • dot : le nom de fichier constitué d'un seul caractère point . est un nom de répertoire qui désigne le répertoire courant.
      • dot-dot : le nom de fichier constitué de deux caractères point .. est un nom de répertoire qui désigne le répertoire parent.
    • directory-separator : le caractère barre oblique / ou le caractère alternatif fourni sous la forme path::preferred_separator. Si ce caractère est répété, il est traité comme un seul séparateur de répertoire : /usr///////lib est identique à /usr/lib.

Un chemin peut être normalisé en suivant cet algorithme :

  1. Si le chemin est vide, s'arrêter (la forme normale d'un chemin vide est un chemin vide).
  2. Remplacer chaque directory-separator (qui peut être composé de plusieurs barres obliques) par une seule path::preferred_separator.
  3. Remplacer chaque caractère barre oblique dans la root-name par path::preferred_separator.
  4. Supprimer chaque dot ainsi que toute directory-separator qui la suit immédiatement.
  5. Supprimer chaque nom de fichier qui n'est pas dot-dot, immédiatement suivi d'une directory-separator et d'un dot-dot, ainsi que toute directory-separator qui suit immédiatement.
  6. S'il existe une root-directory, supprimer toutes les dot-dot et toutes les directory-separator qui les suivent immédiatement.
  7. Si le dernier nom de fichier est dot-dot, supprimer toute directory-separator finale.
  8. Si le chemin est vide, ajouter un dot (la forme normale de ./ est .).

Le chemin peut être parcouru élément par élément à l'aide des itérateurs renvoyés par les fonctions begin() et end(), qui voient le chemin au format générique et itèrent sur le nom de racine, le répertoire racine, puis les éléments de nom de fichier suivants (les séparateurs de répertoires sont ignorés, à l'exception de celui qui identifie le répertoire racine). Si le tout dernier élément du chemin est un séparateur de répertoires, le dernier itérateur déréférencera un élément vide.

Appeler une fonction membre non constante de path invalide tous les itérateurs faisant référence aux éléments de cet objet.

Si le système d'exploitation utilise une syntaxe native différente de la syntaxe générique portable décrite ci-dessus, les fonctions de la bibliothèque définies pour accepter un « format détecté » acceptent les noms de chemin dans les deux formats : un argument au format détecté est considéré comme étant au format générique si et seulement s'il correspond au format générique sans être acceptable par le système d'exploitation comme chemin natif. Sur les systèmes où le format natif diffère entre les chemins de répertoires et les chemins de fichiers, un chemin générique est traité comme un chemin de répertoire s'il se termine par un séparateur de répertoires, et comme un fichier ordinaire sinon.

Dans tous les cas, la classe path se comporte comme si elle stockait un chemin au format natif et se convertissait automatiquement au format générique si nécessaire (chaque fonction membre précise le format dans lequel elle interprète le chemin).

Sur les systèmes POSIX, le format générique est le format natif et il n'est pas nécessaire de les distinguer ni de les convertir.

Les chemins sont implicitement convertibles vers et depuis les std::basic_string, ce qui permet de les utiliser avec d'autres API de fichiers.

Les opérateurs de flux utilisent std::quoted afin que les espaces ne provoquent pas de troncature lors d'une lecture ultérieure par l'opérateur d'extraction de flux.

Les fonctions membres de décomposition (par ex. extension) renvoient des objets filesystem::path au lieu d'objets string, contrairement à d'autres API.

Type Définition
