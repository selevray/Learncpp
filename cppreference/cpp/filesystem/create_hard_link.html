std::filesystem::create_hard_link

Défini dans l'en-tête <filesystem>

void create_hard_link( const std::filesystem::path& target,
                       const std::filesystem::path& link );  // (1) (depuis C++17)

void create_hard_link( const std::filesystem::path& target,
                       const std::filesystem::path& link,
                       std::error_code& ec ) noexcept;  // (2) (depuis C++17)

Crée un lien physique link dont la cible est définie à target comme si par POSIX link() : le chemin target doit exister.

Une fois créés, link et target sont deux noms logiques désignant le même fichier (ils sont equivalent). Même si le nom d'origine target est supprimé, le fichier continue d'exister et reste accessible sous le nom link.

Paramètres

  • target — chemin du fichier ou du répertoire vers lequel créer le lien
  • link — chemin du nouveau lien physique
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge ne levant pas d'exception

Valeur de retour

(aucune)

Exceptions

Toute surcharge non marquée noexcept peut lever std::bad_alloc si l'allocation mémoire échoue.

  1. Lève std::filesystem::filesystem_error en cas d'erreurs de l'API OS sous-jacente, construite avec target comme premier argument de chemin, link comme second argument de chemin, et le code d'erreur OS comme argument de code d'erreur.

  2. Affecte à un paramètre std::error_code& le code d'erreur de l'API système si un appel échoue, et exécute ec.clear() si aucune erreur ne survient.

Notes

Certains systèmes d'exploitation ne prennent pas en charge les liens physiques, ou ne les prennent en charge que pour les fichiers réguliers.

Certains systèmes de fichiers ne prennent pas en charge les liens physiques, quel que soit le système d'exploitation : par exemple le système de fichiers FAT utilisé sur les cartes mémoire et les clés USB.

Certains systèmes de fichiers limitent le nombre de liens par fichier.

La création de liens physiques vers des répertoires est généralement réservée au superutilisateur.

Les liens physiques ne peuvent généralement pas franchir les limites des systèmes de fichiers.

Le chemin spécial point (".") est un lien physique vers son répertoire parent. Le chemin spécial point-point ".." est un lien physique vers le répertoire parent de son propre parent.

Exemple

#include <filesystem>
#include <fstream>
#include <iostream>
namespace fs = std::filesystem;

int main()
{
    fs::create_directories("sandbox/subdir");
    std::ofstream("sandbox/a").put('a'); // créer un fichier régulier
    fs::create_hard_link("sandbox/a", "sandbox/b");
    fs::remove("sandbox/a");
    // lire depuis le fichier d'origine via le lien physique restant
    char c = std::ifstream("sandbox/b").get();
    std::cout << c << '\n';
    fs::remove_all("sandbox");
}

Output:

a
