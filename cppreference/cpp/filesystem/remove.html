std::filesystem::remove, std::filesystem::remove_all

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <filesystem>

bool remove( const std::filesystem::path& p );  // (1) (depuis C++17)

bool remove( const std::filesystem::path& p, std::error_code& ec ) noexcept;  // (2) (depuis C++17)

std::uintmax_t remove_all( const std::filesystem::path& p );  // (3) (depuis C++17)

std::uintmax_t remove_all( const std::filesystem::path& p, std::error_code& ec );  // (4) (depuis C++17)

1,2) Le fichier ou le répertoire vide identifié par le chemin p est supprimé comme le ferait POSIX remove. Les liens symboliques ne sont pas suivis (le lien symbolique est supprimé, et non sa cible).

3,4) Supprime le contenu de p (s'il s'agit d'un répertoire) ainsi que le contenu de tous ses sous-répertoires, récursivement, puis supprime p lui-même comme le ferait l'application répétée de POSIX remove. Les liens symboliques ne sont pas suivis (le lien symbolique est supprimé, et non sa cible).

Paramètres

  • p — chemin à supprimer
  • ec — paramètre de sortie pour le signalement d'erreurs dans la surcharge qui ne lève pas d'exception.

Valeur de retour

1,2) true si le fichier a été supprimé, false s'il n'existait pas. La surcharge qui prend l'argument error_code& renvoie false en cas d'erreur.

3,4) Renvoie le nombre de fichiers et de répertoires supprimés (qui peut être zéro si p n'existait pas à l'origine). La surcharge qui prend l'argument error_code& renvoie static_cast<std::uintmax_t>(-1) en cas d'erreur.

Exceptions

Toute surcharge non marquée noexcept peut lever std::bad_alloc si l'allocation mémoire échoue.

1,3) Lève std::filesystem::filesystem_error en cas d'erreur de l'API système sous-jacente, construite avec p comme premier argument de chemin et le code d'erreur du système comme argument de code d'erreur.

2,4) Affecte à un paramètre std::error_code& le code d'erreur de l'API système si un appel échoue, et exécute ec.clear() si aucune erreur ne survient.

Notes

Sur les systèmes POSIX, cette fonction appelle généralement unlink et rmdir si nécessaire, et sous Windows DeleteFileW et RemoveDirectoryW.

Si p n'existait pas, cette fonction renvoie false et ne signale pas d'erreur.

Exemple

#include <cstdint>
#include <filesystem>
#include <fstream>
#include <iostream>

int main()
{
    namespace fs = std::filesystem;
    std::cout << std::boolalpha;

    fs::path tmp{std::filesystem::temp_directory_path()};

    const auto O_O{"O_O"};
    std::ofstream{tmp / O_O} << O_O; // crée un fichier contenant O_O
    std::cout << "remove(): " << fs::remove(tmp / O_O) << '\n'; // success
    std::cout << "remove(): " << fs::remove(tmp / O_O) << '\n'; // fail

    std::filesystem::create_directories(tmp / "abcdef/example");
    const std::uintmax_t n{fs::remove_all(tmp / "abcdef")};
    std::cout << "remove_all(): " << n << " files or directories\n";
}

Sortie possible :

remove(): true
remove(): false
remove_all(): 2 files or directories
