Calcule le type de valeur associé de l'argument de modèle. Si le type de valeur associé existe, il est représenté par le type imbriqué value_type, sinon value_type n'est pas défini. Un programme peut spécialiser indirectly_readable_traits pour un type défini par le programme.

Explication

Les spécialisations ci-dessus peuvent être décrites informellement comme suit.

Étant donné un type T, son type de valeur associé V est déterminé comme suit :

  • Si T est qualifié const, V est le type de valeur associé de T non qualifié const.
  • Sinon, si T est un type tableau, V est le type d'élément du tableau non qualifié cv.
  • Sinon, un type de valeur conditionnel C est d'abord déterminé :
    • Si T est un type pointeur, C est le type pointé.
    • Sinon, si T possède les types imbriqués value_type et element_type :
      • Si ces types sont identiques (sans tenir compte du qualificatif cv), C est typename T::value_type.
      • Sinon, C est indéfini.
    • Sinon, si T possède le type imbriqué value_type mais pas element_type, C est typename T::value_type.
    • Sinon, si T possède le type imbriqué element_type mais pas value_type, C est typename T::element_type.
    • Sinon, C est indéfini. Puis V est déterminé à partir de C comme suit :
    • Si C est indéfini, ou si C n'est pas un type objet, V est indéfini.
    • Sinon, V est C non qualifié cv.

Notes

value_type est destiné à être utilisé avec des types indirectly_readable, comme les itérateurs. Il n'est pas destiné à être utilisé avec des plages.

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
