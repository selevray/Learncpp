Obtient une référence rvalue ou un temporaire prvalue à partir d'un itérateur donné.

Un ranges::iter_move(t) est équivalent à l'expression :

  1. iter_move(t), si t a un type classe ou énumération et que l'expression est bien formée lorsqu'elle est traitée comme un opérande non évalué, où la résolution de surcharge de iter_move n'est effectuée qu'avec les candidats trouvés par recherche dépendante des arguments.
  2. Sinon, std::move(*t) si *t est bien formé et est une lvalue.
  3. Sinon, *t si *t est bien formé et est une rvalue.

Dans tous les autres cas, un appel à ranges::iter_move est mal formé, ce qui peut entraîner un échec de substitution lorsque ranges::iter_move(e) apparaît dans le contexte immédiat d'une instanciation de modèle.

Si ranges::iter_move(e) n'est pas égal à *e, le programme est mal formé, aucun diagnostic requis.

Objets de point de personnalisation

Le nom ranges::iter_move désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __iter_move_fn.

Toutes les instances de __iter_move_fn sont égales. Les effets de l'invocation de différentes instances du type __iter_move_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, ranges::iter_move peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de ranges::iter_move ci-dessus, alors __iter_move_fn modélise

  • std::invocable<__iter_move_fn, Args...>,
  • std::invocable<const __iter_move_fn, Args...>,
  • std::invocable<__iter_move_fn&, Args...>, and
  • std::invocable<const __iter_move_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __iter_move_fn ne participe à la résolution de surcharge.
