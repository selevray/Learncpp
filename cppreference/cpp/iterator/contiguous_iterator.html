std::contiguous_iterator

Défini dans l'en-tête <iterator>

template< class I >
    concept contiguous_iterator =
        std::random_access_iterator<I> &&
        std::derived_from</*ITER_CONCEPT*/<I>, std::contiguous_iterator_tag> &&
        std::is_lvalue_reference_v<std::iter_reference_t<I>> &&
        std::same_as<
            std::iter_value_t<I>, std::remove_cvref_t<std::iter_reference_t<I>>
        > &&
        requires(const I& i) {
            { std::to_address(i) } ->
              std::same_as<std::add_pointer_t<std::iter_reference_t<I>>>;
        };  // (depuis C++20)

Le concept contiguous_iterator affine random_access_iterator en garantissant que les éléments désignés sont stockés de manière contiguë en mémoire.

Détermination du concept d'itérateur

La définition de ce concept est spécifiée via un alias de modèle d'exposé /*ITER_CONCEPT*/.

Pour déterminer /*ITER_CONCEPT*/<I>, soit ITER_TRAITS<I> désigner I si la spécialisation std::iterator_traits<I> est générée à partir du modèle primaire, ou std::iterator_traits<I> sinon :

  • Si ITER_TRAITS<I>::iterator_concept est valide et désigne un type, /*ITER_CONCEPT*/<I> désigne ce type.
  • Sinon, si ITER_TRAITS<I>::iterator_category est valide et désigne un type, /*ITER_CONCEPT*/<I> désigne ce type.
  • Sinon, si std::iterator_traits<I> est généré à partir du modèle primaire, /*ITER_CONCEPT*/<I> désigne std::random_access_iterator_tag.
  • Sinon, /*ITER_CONCEPT*/<I> ne désigne pas de type et entraîne un échec de substitution.

Exigences sémantiques

Soient a et b des itérateurs déréférençables et c un itérateur non déréférençable de type I tel que b soit atteignable depuis a et c soit atteignable depuis b. Le type I modélise contiguous_iterator seulement si tous les concepts qu'il subsume sont modélisés et que :

  • std::to_address(a) == std::addressof(*a),
  • std::to_address(b) == std::to_address(a) + std::iter_difference_t<I>(b - a), and
  • std::to_address(c) == std::to_address(a) + std::iter_difference_t<I>(c - a).

Préservation de l'égalité

Les expressions déclarées dans les requires expressions des concepts de la bibliothèque standard doivent être préservant l'égalité (sauf mention contraire).

Variations d'expressions implicites

Une requires expression qui utilise une expression non modifiante pour un opérande lvalue constant quelconque nécessite également des variations d'expressions implicites.

Notes

contiguous_iterator est modélisé par tout type pointeur vers un type objet complet.

Les types d'itérateurs de la bibliothèque standard qui doivent satisfaire aux exigences LegacyContiguousIterator en C++17 doivent aussi modéliser contiguous_iterator en C++20.
