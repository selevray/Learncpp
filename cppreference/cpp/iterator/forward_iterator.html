std::forward_iterator

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <iterator>

template< class I >
    concept forward_iterator =
        std::input_iterator<I> &&
        std::derived_from</*ITER_CONCEPT*/<I>, std::forward_iterator_tag> &&
        std::incrementable<I> &&
        std::sentinel_for<I, I>;  // (depuis C++20)

Ce concept affine std::input_iterator en exigeant que I modélise également std::incrementable (ce qui le rend adapté aux algorithmes à passes multiples), et garantit que deux itérateurs vers un même intervalle peuvent être comparés entre eux.

Détermination du concept d'itérateur

La définition de ce concept est spécifiée via un alias de modèle d'exposé /*ITER_CONCEPT*/.

Pour déterminer /*ITER_CONCEPT*/<I>, soit ITER_TRAITS<I> désigner I si la spécialisation std::iterator_traits<I> est générée à partir du modèle primaire, ou std::iterator_traits<I> sinon :

  • Si ITER_TRAITS<I>::iterator_concept est valide et désigne un type, /*ITER_CONCEPT*/<I> désigne ce type.
  • Sinon, si ITER_TRAITS<I>::iterator_category est valide et désigne un type, /*ITER_CONCEPT*/<I> désigne ce type.
  • Sinon, si std::iterator_traits<I> est généré à partir du modèle primaire, /*ITER_CONCEPT*/<I> désigne std::random_access_iterator_tag.
  • Sinon, /*ITER_CONCEPT*/<I> ne désigne pas de type et entraîne un échec de substitution.

Exigences sémantiques

I modélise std::forward_iterator si, et seulement si I modélise tous les concepts qu'il subsume, et que, étant donnés des objets i et j de type I :

  • La comparaison entre les itérateurs i et j a un résultat défini si

    • i et j sont des itérateurs vers la même séquence sous-jacente, ou
    • i et j sont tous deux initialisés par valeur, auquel cas ils sont égaux.

  • Les pointeurs et références obtenus à partir d'un itérateur de avant vers un intervalle restent valides tant que l'intervalle existe.

  • Si i et j sont déréférençables, ils offrent la garantie de passes multiples, c'est-à-dire :

    • i == j implique ++i == ++j, et
    • ((void)[](auto x){ ++x; }(i), *i) est équivalent à *i.

Notes

Contrairement aux exigences LegacyForwardIterator, le concept forward_iterator n'exige pas que le déréférencement retourne une référence.

Exemple

Un itérateur de avant minimal.

#include <cstddef>
#include <iterator>

struct SimpleForwardIterator
{
    using difference_type = std::ptrdiff_t;
    using value_type = int;

    int operator*() const;

    SimpleForwardIterator& operator++();

    SimpleForwardIterator operator++(int)
    {
        auto tmp = *this;
        ++*this;
        return tmp;
    }

    bool operator==(const SimpleForwardIterator&) const;
};

static_assert(std::forward_iterator<SimpleForwardIterator>);
