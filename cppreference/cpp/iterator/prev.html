std::prev

Défini dans l'en-tête <iterator>

template< class BidirIt >
BidirIt prev( BidirIt it, typename std::iterator_traits<BidirIt>::difference_type n = 1 );  // (depuis C++11) (jusqu'à C++17)

template< class BidirIt >
constexpr
BidirIt prev( BidirIt it, typename std::iterator_traits<BidirIt>::difference_type n = 1 );  // (depuis C++17)

Renvoie le ne prédécesseur (ou le -ne successeur si n est négatif) de l'itérateur it.

Paramètres

  • it — un itérateur
  • n — nombre d'éléments que it doit descendre

Exigences sur les types

  • BidirIt doit satisfaire aux exigences de LegacyBidirectionalIterator.

Valeur de retour

Un itérateur de type BidirIt qui contient le ne prédécesseur (ou le -ne successeur si n est négatif) de l'itérateur it.

Complexité

Linéaire.

Cependant, si BidirIt satisfait en plus les exigences de LegacyRandomAccessIterator, la complexité est constante.

Implémentation possible

template<class BidirIt>
constexpr // depuis C++17
BidirIt prev(BidirIt it, typename std::iterator_traits<BidirIt>::difference_type n = 1)
{
    std::advance(it, -n);
    return it;
}

Notes

Bien que l'expression --c.end() compile souvent, rien ne le garantit : c.end() est une expression rvalue, et aucune exigence sur les itérateurs ne précise que la décrémentation d'une rvalue fonctionne toujours. En particulier, lorsque les itérateurs sont implémentés par des pointeurs ou que leur operator-- est qualifié par référence lvalue, --c.end() ne compile pas, alors que std::prev(c.end()) compile.

Exemple

#include <iostream>
#include <iterator>
#include <vector>

int main()
{
    std::vector<int> v{3, 1, 4};

    auto it = v.end();
    auto pv = std::prev(it, 2);
    std::cout << *pv << '\n';

    it = v.begin();
    pv = std::prev(it, -2);
    std::cout << *pv << '\n';
}

Output:

1
4
