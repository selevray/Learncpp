Retourne un itérateur vers la fin (c'est-à-dire l'élément suivant le dernier élément) de l'intervalle donné.

1,2) Retourne c.end(), qui est généralement un itérateur situé juste après la fin de la séquence représentée par c.

  1. Si C est un Container standard, renvoie un objet C::iterator.

  2. Si C est un Container standard, renvoie un objet C::const_iterator.

  3. Retourne un pointeur vers la fin de array.

  4. Renvoie std::end(c), où c est toujours traité comme qualifié const.

Si C est un Container standard, renvoie un objet C::const_iterator.

Paramètres

  • c — un conteneur ou une vue avec une fonction membre end
  • array — un tableau de type quelconque

Valeur de retour

1,2) c.end()

  1. array + N

  2. c.end()

Exceptions

4)noexcept specification:noexcept(noexcept(std::end(c)))

Surcharges

Des surcharges personnalisées de end peuvent être fournies pour les classes et énumérations qui n'exposent pas de fonction membre end() appropriée, mais qui peuvent tout de même être parcourues. Les surcharges suivantes sont déjà fournies par la bibliothèque standard :

  • std::end(std::initializer_list) (C++11) — spécialise std::end (modèle de fonction)
  • std::end(std::valarray) (C++11) — spécialise std::end (modèle de fonction)
  • begin(std::filesystem::directory_iterator)end(std::filesystem::directory_iterator) (C++17) — prise en charge de la boucle for basée sur un intervalle (fonction)
  • begin(std::filesystem::recursive_directory_iterator)end(std::filesystem::recursive_directory_iterator) — prise en charge de la boucle for basée sur un intervalle (fonction)

Similaire à l'usage de swap (décrit dans Swappable), l'usage typique de la fonction end dans un contexte générique équivaut à using std::end; end(arg);, ce qui permet d'faire apparaître dans un même ensemble de surcharges à la fois les surcharges sélectionnées par ADL pour les types définis par l'utilisateur et les modèles de fonctions de la bibliothèque standard.

template<typename Container, typename Function>
void for_each(Container&& cont, Function f)
{
    using std::begin;
    auto it = begin(cont);
    using std::end;
    auto end_it = end(cont);

    for (; it != end_it; ++it)
        f(*it);
}

Les surcharges de end trouvées par recherche dépendante des arguments peuvent servir à personnaliser le comportement de std::ranges::end, std::ranges::cend et d'autres objets de point de personnalisation selon std::ranges::end.

(depuis C++20)

Notes

Les surcharges non tableau reflètent exactement le comportement de C::end(). Leurs effets peuvent être surprenants si la fonction membre n'a pas d'implémentation raisonnable.

std::cend est introduit pour unifier l'accès aux intervalles membres et non membres. Voir aussi LWG issue 2128.

Si C est une vue à const superficielle, std::cend peut renvoyer un itérateur modifiable. Un tel comportement est inattendu pour certains utilisateurs. Voir aussi P2276 et P2278.

Exemple

#include <algorithm>
#include <iostream>
#include <vector>

int main()
{
    std::vector<int> v = {3, 1, 4};
    if (std::find(std::begin(v), std::end(v), 5) != std::end(v))
        std::cout << "Found a 5 in vector v!\n";

    int w[] = {5, 10, 15};
    if (std::find(std::begin(w), std::end(w), 5) != std::end(w))
        std::cout << "Found a 5 in array w!\n";
}

Output:

Found a 5 in array w!
