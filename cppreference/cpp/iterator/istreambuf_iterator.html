std::istreambuf_iterator

Défini dans l'en-tête <iterator>

template< class CharT, class Traits = std::char_traits<CharT> >
class istreambuf_iterator
    : public std::iterator<std::input_iterator_tag,
                           CharT, typename Traits::off_type,
                           /* unspecified */, CharT>  // (jusqu'à C++17)

template< class CharT, class Traits = std::char_traits<CharT> >
class istreambuf_iterator;  // (depuis C++17)

std::istreambuf_iterator est un itérateur d'entrée à passage unique qui lit des caractères successifs depuis l'objet std::basic_streambuf pour lequel il a été construit.

L'itérateur construit par défaut std::istreambuf_iterator est appelé itérateur de fin de flux. Lorsqu'un std::istreambuf_iterator atteint la fin du flux sous-jacent, il devient égal à l'itérateur de fin de flux. Déréférencer ou incrémenter davantage un tel itérateur provoque un comportement indéfini.

std::istreambuf_iterator possède un constructeur de copie trivial, un constructeur par défaut constexpr et un destructeur trivial.

(depuis C++11)

Les types membres iterator_category, value_type, difference_type, pointer et reference doivent être obtenus par héritage de std::iterator<std::input_iterator_tag, CharT, typename Traits::off_type, /* unspecified */, CharT>.

(jusqu'à C++17)

Le type membre pointer est généralement CharT* (voir ci-dessous).

  • (destructeur)(implicitly declared) — détruit un istreambuf_iterator (fonction membre publique)

Notes

La résolution de LWG issue 659 a introduit operator->. On s'attend à ce que, pour un std::istreambuf_iterator i donné, les expressions (*i).m et i->m aient le même effet.

Cependant, la résolution ne fournit pas de spécification formelle de son comportement. Ainsi, elle est implémentée différemment, notamment en renvoyant nullptr, en renvoyant l'adresse d'un temporaire, ou en ne fournissant même pas le membre. Son comportement prévu peut difficilement être atteint, et il est supprimé par la résolution de LWG issue 2790.

La résolution de LWG issue 659 a également rendu le type membre pointer non spécifié afin de permettre à operator-> de renvoyer un mandataire. Cela permet à operator-> de compiler lorsque CharT n'est pas un type de classe.

Exemple

#include <iostream>
#include <iterator>
#include <sstream>
#include <string>

int main()
{
    // cas d'utilisation typique : un flux d'entrée représenté par une paire d'itérateurs
    std::istringstream in{"Hello, world"};
    std::istreambuf_iterator<char> it{in}, end;
    std::string ss{it, end};
    std::cout << "ss has " << ss.size() << " bytes; "
                 "it holds \"" << ss << "\"\n";

    // démonstration de la nature à passage unique
    std::istringstream s{"abc"};
    std::istreambuf_iterator<char> i1{s}, i2{s};
    std::cout << "i1 returns '" << *i1 << "'\n"
                 "i2 returns '" << *i2 << "'\n";

    ++i1;
    std::cout << "after incrementing i1, but not i2:\n"
                 "i1 returns '" << *i1 << "'\n"
                 "i2 returns '" << *i2 << "'\n";

    ++i2;
    std::cout << "after incrementing i2, but not i1:\n"
                 "i1 returns '" << *i1 << "'\n"
                 "i2 returns '" << *i2 << "'\n";
}

Output:

ss has 12 bytes; it holds "Hello, world"
i1 returns 'a'
i2 returns 'a'
after incrementing i1, but not i2:
i1 returns 'b'
i2 returns 'b'
after incrementing i2, but not i1:
i1 returns 'c'
i2 returns 'c'

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 659 C++98 1. std::istreambuf_iterator ne possédait pas operator-> 2. le type membre pointer était spécifié comme CharT* 1. ajouté 2. rendu non spécifié
