std::unordered_set

template<
    class Key,
    class Hash = std::hash<Key>,
    class KeyEqual = std::equal_to<Key>,
    class Allocator = std::allocator<Key>
> class unordered_set;  // (1) (depuis C++11)

namespace pmr {
    template<
        class Key,
        class Hash = std::hash<Key>,
        class Pred = std::equal_to<Key>
    > using unordered_set = std::unordered_set<Key, Hash, Pred,
                                std::pmr::polymorphic_allocator<Key>>;
}  // (2) (depuis C++17)

std::unordered_set est un conteneur associatif qui contient un ensemble d'objets uniques de type Key. La recherche, l'insertion et la suppression ont une complexité constante amortie en moyenne.

En interne, les éléments ne sont pas triés selon un ordre particulier, mais organisés en compartiments (buckets). Le compartiment dans lequel un élément est placé dépend entièrement du hachage de sa valeur. Cela permet un accès rapide aux éléments individuels, puisqu'une fois le hachage calculé, il désigne le compartiment exact dans lequel l'élément est placé.

Les éléments du conteneur ne peuvent pas être modifiés (même par des itérateurs non const), car une modification pourrait changer le hachage d'un élément et corrompre le conteneur.

std::unordered_set satisfait les exigences de Container, AllocatorAwareContainer, UnorderedAssociativeContainer.

Invalidation des itérateurs

Opérations Invalidés
Toutes les opérations en lecture seule, swap, std::swap Jamais
clear, rehash, reserve, operator= Toujours
insert, emplace, emplace_hint Seulement si cela provoque un rehachage
erase Seulement pour l'élément effacé

Notes

  • Les fonctions swap n'invalident aucun des itérateurs à l'intérieur du conteneur, mais elles invalident l'itérateur marquant la fin de la zone d'échange.

  • Les références et pointeurs vers les données stockées dans le conteneur ne sont invalidés que par l'effacement de cet élément, même lorsque l'itérateur correspondant est invalidé.

  • Après une affectation par déplacement du conteneur, à moins qu'une affectation par déplacement élément par élément ne soit imposée par des allocateurs incompatibles, les références, pointeurs et itérateurs (autres que l'itérateur past-the-end) vers le conteneur source restent valides, mais désignent désormais des éléments qui se trouvent dans *this.

Notes

Les types membres iterator et const_iterator peuvent être des alias du même type. Cela signifie que définir une paire de surcharges de fonctions utilisant ces deux types comme types de paramètres peut violer la règle de une seule définition. Comme iterator est convertible en const_iterator, une seule fonction ayant un const_iterator comme type de paramètre fonctionnera à la place.

Exemple

#include <iostream>
#include <unordered_set>

void print(const auto& set)
{
    for (const auto& elem : set)
        std::cout << elem << ' ';
    std::cout << '\n';
}

int main()
{
    std::unordered_set<int> mySet{2, 7, 1, 8, 2, 8}; // crée un ensemble d'entiers
    print(mySet);

    mySet.insert(5); // insère un élément 5 dans l'ensemble
    print(mySet);

    if (auto iter = mySet.find(5); iter != mySet.end())
        mySet.erase(iter); // supprime un élément désigné par iter
    print(mySet);

    mySet.erase(7); // supprime un élément 7
    print(mySet);
}
