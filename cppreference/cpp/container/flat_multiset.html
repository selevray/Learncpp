std::flat_multiset

Défini dans l'en-tête <flat_set>

template<
    class Key,
    class Compare = std::less<Key>,
    class KeyContainer = std::vector<Key>
> class flat_multiset;  // (depuis C++23)

Le flat multiset est un adaptateur de conteneur qui fournit les fonctionnalités d'un conteneur associatif stockant un ensemble trié d'objets de type Key. Contrairement à std::flat_set, plusieurs clés aux valeurs équivalentes sont autorisées. Le tri est effectué à l'aide de la fonction de comparaison de clés Compare.

Le modèle de classe flat_multiset sert d'enveloppe au conteneur trié sous-jacent passé en tant qu'objet de type KeyContainer.

Partout où la bibliothèque standard utilise les exigences Compare, l'unicité est déterminée à l'aide de la relation d'équivalence. Informellement, deux objets a et b sont considérés comme équivalents si aucun ne est strictement inférieur à l'autre : !comp(a, b) && !comp(b, a).

std::flat_multiset satisfait aux exigences de Container, ReversibleContainer, exigences optionnelles des conteneurs, et à toutes les exigences de AssociativeContainer (y compris la complexité logarithmique de recherche), à l'exception de ce qui suit :

  • les exigences relatives aux nœuds ne s'appliquent pas,
  • les exigences d'invalidation des itérateurs diffèrent,
  • la complexité des opérations d'insertion et de suppression est linéaire.

Un flat multiset prend en charge la plupart des opérations de AssociativeContainer qui utilisent des clés égales.

Paramètres de modèle

  • Key — Le type des éléments stockés. Le programme est mal formé si Key n'est pas du même type que KeyContainer::value_type.

  • Compare — Un type Compare fournissant un ordre faible strict.

  • KeyContainer — Le type du SequenceContainer sous-jacent qui stocke les éléments. Les itérateurs de ce conteneur doivent satisfaire LegacyRandomAccessIterator ou modéliser random_access_iterator.

    Les conteneurs standard std::vector et std::deque satisfont ces exigences.

Notes

Les types membres iterator et const_iterator peuvent être des alias du même type. Cela signifie que définir une paire de surcharges de fonctions utilisant ces deux types comme types de paramètres peut violer la règle de une seule définition. Comme iterator est convertible en const_iterator, une seule fonction ayant un const_iterator comme type de paramètre fonctionnera à la place.
