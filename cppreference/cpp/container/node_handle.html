Les conteneurs associatifs std::set, std::map, std::multiset, std::multimap, std::unordered_set, std::unordered_map, std::unordered_multiset, std::unordered_multimap sont des structures de données basées sur des nœuds, et leurs nœuds peuvent être extraits sous la forme d'un objet de type non spécifié appelé gestionnaire de nœud.

Un gestionnaire de nœud est un type à déplacement seul qui possède l'élément (le value_type) stocké dans le nœud et en donne l'accès, et fournit un accès non constant à la partie clé de l'élément (le key_type) et à la partie mappée de l'élément (le mapped_type). Si le gestionnaire de nœud est détruit alors qu'il détient le nœud, le nœud est correctement détruit à l'aide de l'allocateur approprié du conteneur. Le gestionnaire de nœud contient une copie de l'allocateur du conteneur. Cela est nécessaire afin que le gestionnaire de nœud puisse survivre au conteneur.

Le type exact du gestionnaire de nœud (représenté ici par /*node-handle*/) n'est pas spécifié, mais chaque conteneur expose son type de gestionnaire de nœud comme membre node_type.

Les gestionnaires de nœud peuvent être utilisés pour transférer la propriété d'un élément entre deux conteneurs associatifs ayant le même type de clé, de valeur et d'allocateur (sans tenir compte de la comparaison ou du hachage/égalité), sans invoquer aucune opération de copie ou de déplacement sur l'élément du conteneur (ce type d'opération est appelé « épissage »). Le transfert entre conteneurs uniques et non uniques est également permis : un gestionnaire de nœud provenant d'un std::map peut être inséré dans un std::multimap, mais pas dans std::unordered_map ni dans std::set.

Un gestionnaire de nœud peut être vide, auquel cas il ne contient ni élément ni allocateur. Le gestionnaire de nœud construit par défaut et le gestionnaire de nœud déplacé sont vides. En outre, un gestionnaire de nœud vide peut être produit par un appel échoué à la fonction membre extract du conteneur.

Les pointeurs et références vers un élément obtenus alors que celui-ci est possédé par un gestionnaire de nœud sont invalidés si l'élément est inséré avec succès dans un conteneur.

Pour tous les conteneurs de type map (std::map, std::multimap, std::unordered_map et std::unordered_multimap) dont key_type est K et dont mapped_type est T, le comportement des opérations impliquant des gestionnaires de nœud est indéfini si une spécialisation définie par l'utilisateur de std::pair existe pour std::pair<K, T> ou std::pair<const K, T>.

operator=

/*node-handle*/& operator=(/*node-handle*/&& nh);

  • Si le gestionnaire de nœud n'est pas vide,

    • détruit le sous-objet value_type de l'objet élément de conteneur géré par ce gestionnaire de nœud en appelant ator_traits::destroy ;
    • désalloue l'élément de conteneur en appelant ator_traits::rebind_traits</*container-node-type*/>::deallocate ;

  • acquiert la propriété de l'élément de conteneur depuis nh ;

Le comportement est indéfini si le nœud n'est pas vide, si ator_traits::propagate_on_container_move_assignment est false et si les allocateurs ne se comparent pas égaux.
