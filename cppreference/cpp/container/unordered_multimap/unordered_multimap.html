Construit un nouveau conteneur à partir de diverses sources de données. Utilise éventuellement bucket_count fourni par l'utilisateur comme nombre minimal de compartiments à créer, hash comme fonction de hachage, equal comme fonction de comparaison des clés et alloc comme allocateur.

1-5) Construit un conteneur vide. Définit max_load_factor() à 1.0. Pour le constructeur par défaut, le nombre de compartiments est non spécifié.

6-8) Construit le conteneur avec le contenu de l'intervalle [first,last). Définit max_load_factor() à 1.0.

9,10) Constructeur de copie. Construit le conteneur avec une copie du contenu de other, copie également le facteur de charge, le prédicat et la fonction de hachage. Si alloc n'est pas fourni, l'allocateur est obtenu en appelant std::allocator_traits<allocator_type>::select_on_container_copy_construction(other.get_allocator()).

Le paramètre de modèle Allocator n'est déduit qu'à partir du premier argument lorsqu'il est utilisé dans la déduction d'argument de modèle de classe.

(depuis C++23)

11,12) Constructeur de déplacement. Construit le conteneur avec le contenu de other en utilisant la sémantique de déplacement. Si alloc n'est pas fourni, l'allocateur est obtenu par construction par déplacement à partir de l'allocateur appartenant à other.

Le paramètre de modèle Allocator n'est déduit qu'à partir du premier argument lorsqu'il est utilisé dans la déduction d'argument de modèle de classe.

(depuis C++23)

13-15) Constructeur à partir de liste d'initialisation. Construit le conteneur avec le contenu de la liste d'initialisation init, identique à unordered_multimap(init.begin(), init.end()).

16-18) Construit le conteneur avec le contenu de rg.

Paramètres

  • alloc — allocateur à utiliser pour toutes les allocations mémoire de ce conteneur
  • bucket_count — nombre minimal de compartiments à utiliser lors de l'initialisation. S'il n'est pas spécifié, une valeur par défaut non spécifiée est utilisée
  • hash — fonction de hachage à utiliser
  • equal — fonction de comparaison à utiliser pour toutes les comparaisons de clés de ce conteneur
  • first, last — l'intervalle [first,last) à partir duquel copier les éléments
  • rg — un intervalle compatible avec le conteneur, c'est-à-dire un input_range dont les éléments sont convertibles en value_type
  • other — autre conteneur servant de source pour initialiser les éléments du conteneur
  • init — liste d'initialisation pour initialiser les éléments du conteneur

Exigences sur les types

  • InputIt doit satisfaire aux exigences de LegacyInputIterator.

Complexité

1-5) Constante.

6-8) Cas moyen linéaire (c'est-à-dire O(N), où N est std::distance(first, last)), pire cas quadratique, c'est-à-dire O(N2).

9,10) Linéaire en la taille de other.

11,12) Constante. Si alloc est donné et alloc != other.get_allocator(), alors linéaire.

13-15) Cas moyen O(N) (N est std::size(init)), pire cas O(N2).

16-18) Cas moyen O(N) (N est ranges::distance(rg)), pire cas O(N2).

Exceptions

Les appels à Allocator::allocate peuvent lever une exception.

Notes

Après la construction par déplacement du conteneur (surcharge (4)), les références, pointeurs et itérateurs (autres que l'itérateur de fin) vers other restent valides, mais désignent des éléments qui sont désormais dans *this. La norme actuelle fournit cette garantie via l'énoncé général de [container.reqmts]/67, et une garantie plus directe est à l'étude via LWG issue 2321.

Bien que non formellement requis avant C++23, certaines implémentations ont déjà placé le paramètre de modèle Allocator dans des contextes non déduits dans les modes antérieurs.
