std::unordered_map<Key,T,Hash,KeyEqual,Allocator>::operator[]

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

T& operator[]( const Key& key );  // (1) (depuis C++11)

T& operator[]( Key&& key );  // (2) (depuis C++11)

template< class K >
T& operator[]( K&& x );  // (3) (depuis C++26)

Renvoie une référence à la valeur associée à une clé équivalente à key ou x respectivement, en effectuant une insertion si cette clé n'existe pas déjà.

  1. Insère un objet value_type construit sur place à partir de std::piecewise_construct, std::forward_as_tuple(key), std::tuple<>() si la clé n'existe pas.

Équivalent à return this->try_emplace(key).first->second;. *(depuis C++17)*Lorsque l'allocateur par défaut est utilisé, la clé est construite par copie à partir de key et la valeur associée est initialisée par valeur.

  • value_type doit être EmplaceConstructible de std::piecewise_construct, std::forward_as_tuple(key), std::tuple<>(). Lorsque l'allocateur par défaut est utilisé, cela signifie que key_type doit être CopyConstructible et mapped_type doit être DefaultConstructible.
  1. Insère un objet value_type construit sur place à partir de std::piecewise_construct, std::forward_as_tuple(std::move(key)), std::tuple<>() si la clé n'existe pas.

Équivalent à return this->try_emplace(std::move(key)).first->second;. (depuis C++17)
Lorsque l'allocateur par défaut est utilisé, la clé est construite par déplacement à partir de key et la valeur associée est initialisée par valeur.

  • value_type doit être EmplaceConstructible de std::piecewise_construct, std::forward_as_tuple(std::move(key)), std::tuple<>(). Lorsque l'allocateur par défaut est utilisé, cela signifie que key_type doit être MoveConstructible et mapped_type doit être DefaultConstructible.
  1. Insère un objet value_type construit sur place s'il n'existe aucune clé transparemment équivalente à la valeur x.

Équivalent à return this->try_emplace(std::forward<K>(x)).first->second;. Cette surcharge ne participe à la résolution de surcharge que si Hash::is_transparent et KeyEqual::is_transparent sont valides et désignent chacun un type. Cela suppose que ce Hash est appelable avec les types K et Key, et que le KeyEqual est transparent, ce qui permet ensemble d'appeler cette fonction sans construire d'instance de Key.

Si après l'opération le nouveau nombre d'éléments est supérieur à l'ancien max_load_factor() * bucket_count(), une réorganisation (rehashing) a lieu.
Si une réorganisation se produit (due à l'insertion), tous les itérateurs sont invalidés. Sinon (pas de réorganisation), les itérateurs ne sont pas invalidés.

Paramètres

  • key — la clé de l'élément à rechercher
  • x — une valeur de n'importe quel type pouvant être comparée de façon transparente à une clé

Valeur de retour

1,2) Une référence à la valeur associée du nouvel élément si aucun élément de clé key n'existait. Sinon, une référence à la valeur associée de l'élément existant dont la clé est équivalente à key.

  1. Une référence à la valeur associée du nouvel élément si aucun élément dont la clé est équivalente à la valeur x n'existait. Sinon, une référence à la valeur associée de l'élément existant dont la clé est équivalente à x.

Exceptions

Si une exception est levée par une opération, l'insertion n'a aucun effet.

Complexité

Cas moyen : constant, pire cas : linéaire en la taille.

Notes

Dans les normes C++11 et C++14 publiées, cette fonction exigeait que mapped_type soit DefaultInsertable et que key_type soit CopyInsertable ou MoveInsertable dans *this. Cette spécification était défectueuse et a été corrigée par le problème LWG 2469, et la description ci-dessus intègre la résolution de ce problème.

Cependant, une implémentation (libc++) est connue pour construire les objets key_type et mapped_type via deux appels d'allocateur construct() séparés, comme le standard publié l'exige probablement, plutôt que de placer directement un objet value_type par emplacement.

operator[] n'est pas const car elle insère la clé si elle n'existe pas. Si ce comportement est indésirable ou si le conteneur est const, at peut être utilisé.

insert_or_assign renvoie plus d'informations que operator[] et ne nécessite pas que le type associé soit constructible par défaut.

Exemple

#include <iostream>
#include <string>
#include <unordered_map>

void println(auto const comment, auto const& map)
{
    std::cout << comment << '{';
    for (const auto& pair : map)
        std::cout << '{' << pair.first << ": " << pair.second << '}';
    std::cout << "}\n";
}

int main()
{
    std::unordered_map<char, int> letter_counts{{'a', 27}, {'b', 3}, {'c', 1}};

    println("letter_counts initially contains: ", letter_counts);

    letter_counts['b'] = 42; // met à jour une valeur existante
    letter_counts['x'] = 9;  // insère une nouvelle valeur

    println("after modifications it contains: ", letter_counts);

    // compte le nombre d'occurrences de chaque mot
    // (le premier appel à operator[] a initialisé le compteur à zéro)
    std::unordered_map<std::string, int>  word_map;
    for (const auto& w : {"this", "sentence", "is", "not", "a", "sentence",
                          "this", "sentence", "is", "a", "hoax"})
        ++word_map[w];
    word_map["that"]; // insère simplement la paire {"that", 0}

    for (const auto& [word, count] : word_map)
        std::cout << count << " occurrence(s) of word '" << word << "'\n";
}

after modifications it contains: {{a: 27}{b: 42}{c: 1}{x: 9}}

0 occurrence(s) of word 'that'
2 occurrence(s) of word 'this'
