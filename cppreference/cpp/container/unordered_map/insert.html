Insère un ou plusieurs éléments dans le conteneur, si celui-ci ne contient pas déjà un élément avec une clé équivalente.

1-3) Insère value.

La surcharge (3) est équivalente à emplace(std::forward<P>(value)) et ne participe à la résolution de surcharge que si std::is_constructible<value_type, P&&>::value == true.

4-6) Insère value, en utilisant hint comme suggestion non contraignante quant à l'endroit où la recherche doit commencer.

La surcharge (6) est équivalente à emplace_hint(hint, std::forward<P>(value)) et ne participe à la résolution de surcharge que si std::is_constructible<value_type, P&&>::value == true.

  1. Insère les éléments de l'intervalle [first,last). Si plusieurs éléments de l'intervalle ont des clés équivalentes, il n'est pas spécifié lequel est inséré (en attente de LWG2844).

Si [first,last) n'est pas un intervalle valide, ou si first et/ou last sont des itérateurs dans *this, le comportement est indéfini.

  1. Insère les éléments de la liste d'initialisation ilist. Si plusieurs éléments de l'intervalle ont des clés équivalentes, il n'est pas spécifié lequel est inséré (en attente de LWG2844).

  2. Si nh est un node handle vide, ne fait rien. Sinon, insère l'élément possédé par nh dans le conteneur , si celui-ci ne contient pas déjà un élément avec une clé équivalente à nh.key(). Le comportement est indéfini si nh n'est pas vide et que get_allocator() != nh.get_allocator().

  3. Si nh est un handle de nœud vide, ne fait rien et renvoie l'itérateur de fin. Sinon, insère dans le conteneur l'élément possédé par nh, si le conteneur ne contient pas déjà un élément dont la clé est équivalente à nh.key(), et renvoie l'itérateur pointant vers l'élément de clé équivalente à nh.key() (que l'insertion ait réussi ou échoué). Si l'insertion réussit, nh est déplacé, sinon il conserve la possession de l'élément. hint est utilisé comme suggestion non contraignante quant à l'endroit où la recherche doit commencer. Le comportement est indéfini si nh n'est pas vide et get_allocator() != nh.get_allocator().

Si après l'opération le nouveau nombre d'éléments est supérieur à l'ancien max_load_factor() * bucket_count(), une réorganisation (rehashing) a lieu.
Si une réorganisation se produit (due à l'insertion), tous les itérateurs sont invalidés. Sinon (pas de réorganisation), les itérateurs ne sont pas invalidés. Si l'insertion réussit, les pointeurs et références vers l'élément obtenus pendant qu'il est détenu par le handle de nœud sont invalidés, et les pointeurs et références obtenus vers cet élément avant son extraction redeviennent valides. (depuis C++17)

Paramètres

  • hint — itérateur, utilisé comme suggestion quant à l'endroit où insérer le contenu
  • value — valeur de l'élément à insérer
  • first, last — intervalle d'éléments à insérer
  • ilist — liste d'initialisation à partir de laquelle insérer les valeurs
  • nh — un node handle compatible

Exigences sur les types

  • InputIt doit satisfaire aux exigences de LegacyInputIterator.

Valeur de retour

1-3) Une paire composée d'un itérateur vers l'élément inséré (ou vers l'élément qui a empêché l'insertion) et d'une valeur bool égale à true si et seulement si l'insertion a eu lieu.

4-6) Un itérateur vers l'élément inséré, ou vers l'élément qui a empêché l'insertion.

7,8) (aucun)

  1. Un objet de insert_return_type dont les membres sont initialisés comme suit :
  • Si nh est vide, inserted vaut false, position vaut end(), et node est vide.
  • Sinon, si l'insertion a eu lieu, inserted vaut true, position pointe vers l'élément inséré, et node est vide.
  • Si l'insertion a échoué, inserted vaut false, node a la valeur précédente de nh, et position pointe vers un élément de clé équivalente à nh.key().
  1. Itérateur de fin si nh était vide, itérateur pointant vers l'élément inséré si l'insertion a eu lieu, et itérateur pointant vers un élément de clé équivalente à nh.key() en cas d'échec.

Exceptions

1-6) Si une exception est levée pour une raison quelconque, ces fonctions n'ont aucun effet (garantie forte d'exception).

7,8) Aucune garantie de sûreté en cas d'exception.

9,10) Si une exception est levée pour une raison quelconque, ces fonctions n'ont aucun effet (garantie forte d'exception).

Complexité

1-6) Cas moyen : O(1), cas le pire O(size()).

7,8) Cas moyen : O(N), où N est le nombre d'éléments à insérer. Cas le pire : O(N * size() + N).

9,10) Cas moyen : O(1), cas le pire O(size()).

Notes

L'insertion avec indication (4-6) ne renvoie pas de booléen afin d'avoir la même signature que l'insertion positionnelle des conteneurs séquentiels, tels que std::vector::insert. Cela permet de créer des insertion génériques comme std::inserter. Une façon de vérifier le succès d'une insertion avec indication consiste à comparer size() avant et après.

Exemple

#include <iostream>
#include <string>
#include <unordered_map>

int main ()
{
    std::unordered_map<int, std::string> dict = {{1, "one"}, {2, "two"}};
    dict.insert({3, "three"});
    dict.insert(std::make_pair(4, "four"));
    dict.insert({{4, "another four"}, {5, "five"}});

    const bool ok = dict.insert({1, "another one"}).second;
    std::cout << "inserting 1 => \"another one\" "
              << (ok ? "succeeded" : "failed") << '\n';

    std::cout << "contents:\n";
    for (auto& p : dict)
        std::cout << ' ' << p.first << " => " << p.second << '\n';
}

Sortie possible :

inserting 1 => "another one" failed
contents:
 5 => five
 1 => one
 2 => two
 3 => three
 4 => four
