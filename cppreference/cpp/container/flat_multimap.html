std::flat_multimap

Défini dans l'en-tête <flat_map>

template<
    class Key,
    class T,
    class Compare = std::less<Key>,
    class KeyContainer = std::vector<Key>,
    class MappedContainer = std::vector<T>
> class flat_multimap;  // (depuis C++23)

Le multimap plat est un adaptateur de conteneur qui offre les fonctionnalités d'un conteneur associatif contenant des paires clé-valeur, tout en permettant plusieurs entrées avec la même valeur de clé. Les clés sont triées à l'aide de la fonction de comparaison Compare.

Le modèle de classe flat_multimap sert d'enveloppe pour les deux conteneurs sous-jacents, passés en objets de type KeyContainer et MappedContainer respectivement. Le premier conteneur est trié, et pour chaque clé, sa valeur correspondante se trouve dans le second conteneur au même index (décalage). Le nombre d'éléments dans les deux conteneurs est identique.

Partout où la bibliothèque standard utilise les exigences Compare, l'unicité est déterminée à l'aide de la relation d'équivalence. Informellement, deux objets a et b sont considérés comme équivalents si aucun ne est strictement inférieur à l'autre : !comp(a, b) && !comp(b, a).

std::flat_multimap satisfait aux exigences de Container, ReversibleContainer, exigences optionnelles des conteneurs, et à toutes les exigences de AssociativeContainer (y compris la complexité logarithmique de recherche), à l'exception de ce qui suit :

  • les exigences relatives aux nœuds ne s'appliquent pas,
  • les exigences d'invalidation des itérateurs diffèrent,
  • la complexité des opérations d'insertion et de suppression est linéaire.

Un multimap plat prend en charge la plupart des opérations de AssociativeContainer qui utilisent des clés égales.

Paramètres de modèle

  • Key — Le type des clés. Le programme est mal formé si Key n'est pas le même type que KeyContainer::value_type.

  • T — Le type des valeurs mappées. Le programme est mal formé si T n'est pas le même type que MappedContainer::value_type.

  • Compare — Un type Compare fournissant un ordre faible strict.

  • KeyContainerMappedContainer — Les types des SequenceContainer sous-jacents destinés à stocker respectivement les clés et les valeurs mappées. Les itérateurs de ces conteneurs doivent satisfaire LegacyRandomAccessIterator ou modéliser random_access_iterator. Les invocations de leurs fonctions membres size et max_size ne doivent pas lever d'exception.

    Les conteneurs standard std::vector et std::deque satisfont ces exigences.

Notes

Les types membres iterator et const_iterator peuvent être des alias du même type. Cela signifie que définir une paire de surcharges de fonctions utilisant ces deux types comme types de paramètres peut violer la règle de une seule définition. Comme iterator est convertible en const_iterator, une seule fonction ayant un const_iterator comme type de paramètre fonctionnera à la place.
