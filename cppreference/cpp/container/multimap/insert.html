std::multimap<Key,T,Compare,Allocator>::insert

Insère un ou plusieurs éléments dans le conteneur.

1-3) Insère value. Si le conteneur contient des éléments à clé équivalente, insère à la borne supérieure de cet intervalle.

La surcharge (3) est équivalente à emplace(std::forward<P>(value)) et ne participe à la résolution de surcharge que si std::is_constructible<value_type, P&&>::value == true.

4-6) Insère value à la position la plus proche possible de la position juste avant pos.

La surcharge (6) est équivalente à emplace_hint(hint, std::forward<P>(value)) et ne participe à la résolution de surcharge que si std::is_constructible<value_type, P&&>::value == true.

  1. Insère les éléments de l'intervalle [first,last).

  2. Insère les éléments de la liste d'initialisation ilist.

  3. Si nh est un descripteur de nœud vide, ne fait rien. Sinon, insère l'élément possédé par nh dans le conteneur et renvoie un itérateur pointant vers l'élément inséré. Si un intervalle contenant des éléments à clés équivalentes à nh.key() existe dans le conteneur, l'élément est inséré à la fin de cet intervalle. Le comportement est indéfini si nh n'est pas vide et get_allocator() != nh.get_allocator().

  4. Si nh est un descripteur de nœud vide, ne fait rien et renvoie l'itérateur de fin. Sinon, insère l'élément possédé par nh dans le conteneur, et renvoie l'itérateur pointant vers l'élément dont la clé est équivalente à nh.key(). L'élément est inséré aussi près que possible de la position juste avant pos. Le comportement est indéfini si nh n'est pas vide et get_allocator() != nh.get_allocator().

Aucun itérateur ni aucune référence n'est invalidé. Si l'insertion réussit, les pointeurs et références vers l'élément obtenus pendant qu'il est détenu par le node handle sont invalidés, et les pointeurs et références obtenus vers cet élément avant son extraction redeviennent valides. (depuis C++17)

Paramètres

  • pos — itérateur vers la position avant laquelle le nouvel élément sera inséré
  • value — valeur de l'élément à insérer
  • first, last — intervalle d'éléments à insérer
  • ilist — liste d'initialisation à partir de laquelle insérer les valeurs
  • nh — un node handle compatible

Exigences sur les types

  • InputIt doit satisfaire aux exigences de LegacyInputIterator.

Valeur de retour

1-6) Un itérateur vers l'élément inséré.

7,8) (aucun)

9,10) Itérateur de fin si nh était vide, itérateur pointant vers l'élément inséré sinon.

Exceptions

1-6) Si une exception est levée par une opération quelconque, l'insertion n'a aucun effet.

7,8) Aucune garantie de sûreté en cas d'exception.

9,10) Si une exception est levée par une opération quelconque, l'insertion n'a aucun effet.

Complexité

1-3) O(log(size()))

4-6) Constant amorti si l'insertion a lieu à la position juste avant pos, O(log(size())) sinon.

7,8) O(N·log(size() + N)), où N est le nombre d'éléments à insérer.

  1. O(log(size()))

  2. Constant amorti si l'insertion a lieu à la position juste avant pos, O(log(size())) sinon.

Exemple

#include <functional>
#include <iostream>
#include <map>
#include <string>
#include <string_view>
#include <utility>

template<class M>
void print(const std::string_view rem, const M& mmap)
{
    std::cout << rem << ' ';
    for (const auto& e : mmap)
        std::cout << '{' << e.first << ',' << e.second << "} ";
    std::cout << '\n';
}

int main()
{
    // initialisation par liste
    std::multimap<int, std::string, std::greater<int>> mmap
        {{2, "foo"}, {2, "bar"}, {3, "baz"}, {1, "abc"}, {5, "def"}};
    print("#1", mmap);

    // insertion avec value_type
    mmap.insert(decltype(mmap)::value_type(5, "pqr"));
    print("#2", mmap);

    // insertion avec pair
    mmap.insert(std::pair{6, "uvw"});
    print("#3", mmap);

    mmap.insert({7, "xyz"});
    print("#4", mmap);

    // insertion avec initializer_list
    mmap.insert({{5, "one"}, {5, "two"}});
    print("#5", mmap);

    // insertion avec une paire d'itérateurs
    mmap.clear();
    const auto il = {std::pair{1, "ä"}, {2, "ё"}, {2, "ö"}, {3, "ü"}};
    mmap.insert(il.begin(), il.end());
    print("#6", mmap);
}

#3 {6,uvw} {5,def} {5,pqr} {3,baz} {2,foo} {2,bar} {1,abc}
#4 {7,xyz} {6,uvw} {5,def} {5,pqr} {3,baz} {2,foo} {2,bar} {1,abc}
#5 {7,xyz} {6,uvw} {5,def} {5,pqr} {5,one} {5,two} {3,baz} {2,foo} {2,bar} {1,abc}
#6 {3,ü} {2,ё} {2,ö} {1,ä}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 233 C++98 pos n'était qu'un indice, qui pouvait être entièrement ignoré l'insertion devait être à la position la plus proche possible de la position juste avant pos
LWG 264 C++98 la complexité de la surcharge (5) devait être linéaire si l'intervalle [first,last) est trié selon Compare suppression de l'exigence de linéarité dans ce cas particulier
LWG 371 C++98 l'ordre des éléments équivalents n'était pas garanti d'être préservé requis d'être préservé
LWG 2005 C++11 les surcharges (3,6) étaient mal décrites description améliorée
