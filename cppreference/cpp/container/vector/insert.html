std::vector<T,Allocator>::insert

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

iterator insert( const_iterator pos, const T& value );  // (1) (constexpr depuis C++20)

iterator insert( const_iterator pos, T&& value );  // (2) (depuis C++11) (constexpr depuis C++20)

iterator insert( const_iterator pos,
                 size_type count, const T& value );  // (3) (constexpr depuis C++20)

template< class InputIt >
iterator insert( const_iterator pos, InputIt first, InputIt last );  // (4) (constexpr depuis C++20)

iterator insert( const_iterator pos, std::initializer_list<T> ilist );  // (5) (depuis C++11) (constexpr depuis C++20)

Insère des éléments à la position spécifiée dans le conteneur.

  1. Insère une copie de value avant pos.

  2. Insère value avant pos, en utilisant éventuellement la sémantique de déplacement.

  3. Insère count copies de value avant pos.

  4. Insère les éléments de l'intervalle [first,last) avant pos.

Cette surcharge a le même effet que la surcharge (3) si InputIt est un type entier.

(jusqu'à C++11)

Cette surcharge ne participe à la résolution de surcharge que si InputIt satisfait LegacyInputIterator, afin d'éviter toute ambiguïté avec la surcharge (3).

(depuis C++11)

Si first et last sont des itérateurs dans *this, le comportement est indéfini.

  1. Insère les éléments de la liste d'initialisation ilist avant pos.

Si après l'opération la nouvelle size() est supérieure à l'ancienne capacity(), une réallocation a lieu, auquel cas tous les itérateurs (y compris l'itérateur end()) et toutes les références aux éléments sont invalidés. Sinon, seuls les itérateurs et références situés avant le point d'insertion restent valides.

Paramètres

  • pos — itérateur avant lequel le contenu sera inséré (pos peut être l'itérateur end())
  • value — valeur de l'élément à insérer
  • count — nombre d'éléments à insérer
  • first, last — l'intervalle d'éléments à insérer, ne peut pas être constitué d'itérateurs dans le conteneur sur lequel insert est appelé
  • ilist — std::initializer_list depuis lequel insérer les valeurs

Exigences sur les types

  • T doit satisfaire aux exigences de CopyAssignable et de CopyInsertable pour utiliser la surcharge (1).
  • T doit satisfaire aux exigences de MoveAssignable et de MoveInsertable pour utiliser la surcharge (2).
  • T doit satisfaire aux exigences de CopyAssignable et de CopyInsertable pour utiliser la surcharge (3).
  • T doit satisfaire aux exigences de EmplaceConstructible pour utiliser les surcharges (4,5).
  • T doit satisfaire aux exigences de MoveAssignable et MoveInsertable pour utiliser la surcharge (4). Requis uniquement si InputIt satisfait LegacyInputIterator mais pas LegacyForwardIterator. (jusqu'à C++17)
  • T doit satisfaire aux exigences de Swappable, MoveAssignable, MoveConstructible et MoveInsertable pour utiliser les surcharges (4,5). (depuis C++17)

Valeur de retour

1,2) Itérateur pointant vers l'value inséré.

  1. Itérateur pointant vers le premier élément inséré, ou pos si count == 0.

  2. Itérateur pointant vers le premier élément inséré, ou pos si first == last.

  3. Itérateur pointant vers le premier élément inséré, ou pos si ilist est vide.

Complexité

1,2) Constante plus linéaire en fonction de la distance entre pos et la fin du conteneur.

  1. Linéaire en count plus linéaire en la distance entre pos et la fin du conteneur.

  2. Linéaire en std::distance(first, last) plus linéaire en la distance entre pos et la fin du conteneur.

  3. Linéaire en ilist.size() plus linéaire en la distance entre pos et la fin du conteneur.

Exceptions

Si une exception est levée autrement que par

  • le constructeur de copie de T,
  • le constructeur de déplacement de T,

(depuis C++11)

  • l'opérateur d'affectation par copie de T,
  • l'opérateur d'affectation par déplacement de T,

(depuis C++11)

  • toute opération InputIt,

ces fonctions n'ont aucun effet (garantie forte d'exception).

Si une exception est levée lors de l'insertion d'un seul élément à la fin, et que T vaut CopyInsertable dans *this ou std::is_nothrow_move_constructible<T>::value vaut true, cette fonction n'a aucun effet (garantie forte d'exception). Sinon, si une exception est levée par le constructeur de déplacement d'un T non CopyInsertable, les effets sont non spécifiés.

(depuis C++11)

Exemple

#include <iostream>
#include <iterator>
#include <string_view>
#include <vector>

namespace stq {
void println(std::string_view rem, const std::vector<int>& container)
{
    std::cout << rem.substr(0, rem.size() - 2) << '[';
    bool first{true};
    for (const int x : container)
        std::cout << (first ? first = false, "" : ", ") << x;
    std::cout << "]\n";
}
}

int main()
{
    std::vector<int> c1(3, 100);
    stq::println("1. {}", c1);

    auto pos = c1.begin();
    pos = c1.insert(pos, 200); // overload (1)
    stq::println("2. {}", c1);

    c1.insert(pos, 2, 300); // overload (3)
    stq::println("3. {}", c1);

    // pos n'est plus valide, en obtenir un nouveau :
    pos = c1.begin();

    std::vector<int> c2(2, 400);
    c1.insert(std::next(pos, 2), c2.begin(), c2.end()); // overload (4)
    stq::println("4. {}", c1);

    int arr[] = {501, 502, 503};
    c1.insert(c1.begin(), arr, arr + std::size(arr)); // overload (4)
    stq::println("5. {}", c1);

    c1.insert(c1.end(), {601, 602, 603}); // overload (5)
    stq::println("6. {}", c1);
}

Output:

1. [100, 100, 100]
2. [200, 100, 100, 100]
3. [300, 300, 200, 100, 100, 100]
4. [300, 300, 400, 400, 200, 100, 100, 100]
5. [501, 502, 503, 300, 300, 400, 400, 200, 100, 100, 100]
6. [501, 502, 503, 300, 300, 400, 400, 200, 100, 100, 100, 601, 602, 603]

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 149 C++98 les surcharges (3) et (4) ne renvoyaient rien renvoie un itérateur
LWG 247 C++98 la complexité n'était spécifiée que pour la surcharge (3) spécifiée pour toutes les surcharges
LWG 406 C++98 la garantie forte d'exception s'appliquait aussi si l'exception est levée par une opération InputIt aucune garantie dans ce cas
