std::vector<T,Allocator>::reserve

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

void reserve( size_type new_cap );  // (constexpr depuis C++20)

Augmente la capacité du vecteur (le nombre total d'éléments que le vecteur peut contenir sans nécessiter de réallocation) à une valeur supérieure ou égale à new_cap. Si new_cap est supérieur à la capacity() actuelle, un nouvel espace de stockage est alloué, sinon la fonction ne fait rien.

reserve() ne modifie pas la taille du vecteur.

Si new_cap est supérieur à capacity(), tous les itérateurs (y compris l'itérateur end()) et toutes les références aux éléments sont invalidés. Sinon, aucun itérateur ni aucune référence n'est invalidé.

Après un appel à reserve(), les insertions ne déclencheront pas de réallocation sauf si l'insertion rendait la taille du vecteur supérieure à la valeur de capacity().

Paramètres

  • new_cap — nouvelle capacité du vecteur, en nombre d'éléments

Exigences sur les types

  • T doit satisfaire les exigences de MoveInsertable vers *this. (depuis C++11)

Valeur de retour

(aucune)

Exceptions

  • std::length_error if new_cap > max_size().
  • Toute exception levée par Allocator::allocate() (généralement std::bad_alloc).

Si une exception est levée, cette fonction n'a aucun effet (garantie forte d'exception).

Si le constructeur de déplacement de T n'est pas noexcept et que T n'est pas CopyInsertable dans *this, vector utilisera le constructeur de déplacement pouvant lever une exception. S'il lève une exception, la garantie est abandonnée et les effets sont non spécifiés.

(depuis C++11)

Complexité

Au plus linéaire en size() du conteneur.

Notes

Utiliser correctement reserve() peut éviter des réallocations inutiles, mais une utilisation inappropriée de reserve() (par exemple l'appeler avant chaque appel à push_back()) peut en fait augmenter le nombre de réallocations (en faisant croître la capacité linéairement plutôt qu'exponentiellement) et entraîner une complexité de calcul et une baisse de performance accrues. Par exemple, une fonction qui reçoit un vecteur arbitraire par référence et y ajoute des éléments ne devrait généralement pas appeler reserve() sur le vecteur, car elle ne connaît pas les caractéristiques d'utilisation du vecteur.

Lors de l'insertion d'un intervalle, la version pour intervalles de insert() est généralement préférable car elle préserve le comportement correct de croissance de la capacité, contrairement à reserve() suivi d'une série de push_back().

reserve() ne peut pas être utilisé pour réduire la capacité du conteneur ; à cet effet, shrink_to_fit() est fourni.

Exemple

#include <cstddef>
#include <iostream>
#include <new>
#include <vector>

// allocateur minimal C++11 avec sortie de débogage
template<class Tp>
struct NAlloc
{
    typedef Tp value_type;

    NAlloc() = default;
    template<class T>
    NAlloc(const NAlloc<T>&) {}

    Tp* allocate(std::size_t n)
    {
        n *= sizeof(Tp);
        Tp* p = static_cast<Tp*>(::operator new(n));
        std::cout << "allocating " << n << " bytes @ " << p << '\n';
        return p;
    }

    void deallocate(Tp* p, std::size_t n)
    {
        std::cout << "deallocating " << n * sizeof *p << " bytes @ " << p << "\n\n";
        ::operator delete(p);
    }
};

template<class T, class U>
bool operator==(const NAlloc<T>&, const NAlloc<U>&) { return true; }

template<class T, class U>
bool operator!=(const NAlloc<T>&, const NAlloc<U>&) { return false; }

int main()
{
    constexpr int max_elements = 32;

    std::cout << "using reserve: \n";
    {
        std::vector<int, NAlloc<int>> v1;
        v1.reserve(max_elements); // réserve au moins max_elements * sizeof(int) octets

        for (int n = 0; n < max_elements; ++n)
            v1.push_back(n);
    }

    std::cout << "not using reserve: \n";
    {
        std::vector<int, NAlloc<int>> v1;

        for (int n = 0; n < max_elements; ++n)
        {
            if (v1.size() == v1.capacity())
                std::cout << "size() == capacity() == " << v1.size() << '\n';
            v1.push_back(n);
        }
    }
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 329 C++98 une réallocation peut être déclenchée si une insertion rend la taille du vecteur supérieure à la taille spécifiée lors du dernier appel à reserve() ne se déclenche que si la taille du vecteur devient supérieure à capacity()
LWG 2033 C++11 T n'était pas tenu d'être MoveInsertable required
