std::vector<T,Allocator>::resize

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

void resize( size_type count );  // (1) (constexpr depuis C++20)

void resize( size_type count, const value_type& value );  // (2) (constexpr depuis C++20)

Redimensionne le conteneur pour qu'il contienne count éléments, ne fait rien si count == size().

Si la taille actuelle est supérieure à count, le conteneur est réduit à ses count premiers éléments.

Si la taille actuelle est inférieure à count, alors :

  1. Des éléments insérés par défaut supplémentaires sont ajoutés à la fin.

  2. Des copies supplémentaires de value sont ajoutées à la fin.

Paramètres

  • count — nouvelle taille du conteneur
  • value — la valeur avec laquelle initialiser les nouveaux éléments

Exigences sur les types

  • T doit satisfaire aux exigences de MoveInsertable et de DefaultInsertable pour utiliser la surcharge (1).
  • T doit satisfaire les exigences de CopyInsertable pour utiliser la surcharge (2).

Complexité

Linéaire en la différence entre la taille actuelle et count. Complexité supplémentaire possible due à la réallocation si la capacité est inférieure à count.

Exceptions

Si une exception est levée pour quelque raison que ce soit, ces fonctions n'ont aucun effet (garantie forte d'exception). Bien que non explicitement spécifié, std::length_error est levée si la capacité requise par le nouveau vector dépasserait max_size().

Dans la surcharge (1), si le constructeur de déplacement de T n'est pas noexcept et que T n'est pas CopyInsertable dans *this, vector utilisera le constructeur de déplacement pouvant lever une exception. Si celui-ci lève une exception, la garantie est abandonnée et les effets sont non spécifiés.

(depuis C++11)

Notes

Si l'initialisation par valeur dans la surcharge (1) est indésirable, par exemple si les éléments sont de type non classe et qu'une mise à zéro n'est pas nécessaire, elle peut être évitée en fournissant un allocateur personnalisé Allocator::construct.
La capacité du vector n'est jamais réduite lors d'un redimensionnement vers une taille inférieure, car cela invaliderait tous les itérateurs, et non seulement ceux qui seraient invalidés par la séquence équivalente d'appels à pop_back().

Exemple

#include <vector>
#include <iostream>

void print(auto rem, const std::vector<int>& c)
{
    for (std::cout << rem; const int el : c)
        std::cout << el << ' ';
    std::cout << '\n';
}

int main()
{
    std::vector<int> c = {1, 2, 3};
    print("The vector holds: ", c);

    c.resize(5);
    print("After resize up to 5: ", c);

    c.resize(2);
    print("After resize down to 2: ", c);

    c.resize(6, 4);
    print("After resize up to 6 (initializer = 4): ", c);
}

Output:

The vector holds: 1 2 3
After resize up to 5: 1 2 3 0 0
After resize down to 2: 1 2
After resize up to 6 (initializer = 4): 1 2 4 4 4 4

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 679 C++98 resize() passé value par valeur passe par référence const
LWG 1525 C++98 le comportement de resize(size()) n'était pas spécifié specified
LWG 2033 C++11 1. des éléments ont été supprimés en utilisant erase()[1] 2. les exigences sur les types de T étaient incorrectes 1. utilise pop_back() 2. corrigé
LWG 2066 C++11 la surcharge (1) n'avait pas la garantie de sécurité d'exception de la surcharge (2) added
LWG 2160 C++11 des éléments étaient supprimés en utilisant pop_back()[2] en raison de la résolution de LWG 2033 ne spécifie pas la méthode de suppression des éléments
  1. ↑ erase() peut supprimer des éléments au milieu d'un vector, donc le type de valeur doit être MoveAssignable afin que les éléments suivant la section supprimée puissent être déplacés vers l'avant pour combler le vide. Cependant, resize() ne peut supprimer que des éléments à la fin du vector, rendant MoveAssignable inutile.
  2. ↑ La suppression d'éléments en utilisant pop_back() implique que les éléments doivent être supprimés de l'arrière vers l'avant.
