guides de déduction pour std::stack

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <stack>

template< class Container >
stack( Container )
    -> stack<typename Container::value_type, Container>;  // (1) (depuis C++17)

template< class Container, class Alloc >
stack( Container, Alloc )
    -> stack<typename Container::value_type, Container>;  // (2) (depuis C++17)

template< class InputIt >
stack( InputIt, InputIt )
    -> stack<typename std::iterator_traits<InputIt>::value_type>;  // (3) (depuis C++23)

template< class InputIt, class Alloc >
stack( InputIt, InputIt, Alloc )
    -> stack<typename std::iterator_traits<InputIt>::value_type,
       std::deque<typename std::iterator_traits<InputIt>::value_type, Alloc>>;  // (4) (depuis C++23)

template< ranges::input_range R >
stack( std::from_range_t, R&& )
    -> stack<ranges::range_value_t<R>>;  // (5) (depuis C++23)

template< ranges::input_range R, class Allocator >
stack( std::from_range_t, R&&, Allocator )
    -> stack<ranges::range_value_t<R>,
       std::deque<ranges::range_value_t<R>, Allocator>>;  // (6) (depuis C++23)

Ces guides de déduction sont fournis pour stack afin de permettre la déduction à partir du type du conteneur sous-jacent.

  1. Déduit le type du conteneur sous-jacent à partir de l'argument.

  2. Identique à (1), sauf que l'allocateur est fourni.

  3. Déduit le type des éléments à partir de l'itérateur, en utilisant std::deque<typename std::iterator_traits<InputIt>::value_type> comme type de conteneur sous-jacent.

  4. Identique à (3), sauf que l'allocateur est fourni.

  5. Déduit le type des éléments à partir d'une étiquette std::from_range_t et d'un input_range.

  6. Identique à (5), sauf que l'allocateur est fourni.

Ces surcharges ne participent à la résolution de surcharge que si

  • InputIt (s'il existe) satisfait LegacyInputIterator,
  • Container (s'il existe) ne satisfait pas Allocator,
  • pour [(3) (jusqu'à C++23) | (4) (depuis C++23)], Alloc satisfait Allocator, et
  • std::uses_allocator_v<Container, Alloc> est true si Container et Alloc existent tous deux.

Remarque : la mesure dans laquelle la bibliothèque détermine qu'un type ne satisfait pas LegacyInputIterator n'est pas spécifiée, sauf qu'au minimum les types entiers ne sont pas qualifiés comme itérateurs d'entrée. De même, la mesure dans laquelle elle détermine qu'un type ne satisfait pas Allocator n'est pas spécifiée, sauf qu'au minimum le type membre Alloc::value_type doit exister et l'expression std::declval<Alloc&>().allocate(std::size_t{}) doit être bien formée lorsqu'elle est traitée comme opérande non évalué.

Exemple

#include <stack>
#include <vector>

int main()
{
    std::vector<int> v = {1, 2, 3, 4};
    std::stack s{v}; // le guide #1 déduit std::stack<int, vector<int>>
}
