Insère un ou plusieurs éléments dans le conteneur, si celui-ci ne contient pas déjà un élément avec une clé équivalente.

1-3) Insère value.

La surcharge (2) est équivalente à emplace(std::forward<P>(value)) et ne participe à la résolution de surcharge que si std::is_constructible<value_type, P&&>::value == true.

4-6) Insère value à la position la plus proche possible de la position juste avant pos.

La surcharge (5) est équivalente à emplace_hint(hint, std::forward<P>(value)) et ne participe à la résolution de surcharge que si std::is_constructible<value_type, P&&>::value == true.

  1. Insère les éléments de l'intervalle [first,last). Si plusieurs éléments de l'intervalle ont des clés équivalentes, il n'est pas spécifié lequel est inséré (en attente de LWG2844).

  2. Insère les éléments de la liste d'initialisation ilist. Si plusieurs éléments de l'intervalle ont des clés équivalentes, il n'est pas spécifié lequel est inséré (en attente de LWG2844).

  3. Si nh est un node handle vide, ne fait rien. Sinon, insère l'élément possédé par nh dans le conteneur , si celui-ci ne contient pas déjà un élément avec une clé équivalente à nh.key(). Le comportement est indéfini si nh n'est pas vide et que get_allocator() != nh.get_allocator().

  4. Si nh est un node handle vide, ne fait rien et renvoie l'itérateur de fin. Sinon, insère l'élément possédé par nh dans le conteneur, si celui-ci ne contient pas déjà un élément avec une clé équivalente à nh.key(), et renvoie l'itérateur pointant vers l'élément de clé équivalente à nh.key() (que l'insertion ait réussi ou échoué). Si l'insertion réussit, nh est déplacé, sinon il conserve la possession de l'élément. L'élément est inséré à la position la plus proche possible de la position juste avant pos. Le comportement est indéfini si nh n'est pas vide et que get_allocator() != nh.get_allocator().

Aucun itérateur ni aucune référence n'est invalidé. Si l'insertion réussit, les pointeurs et références vers l'élément obtenus pendant qu'il est détenu par le node handle sont invalidés, et les pointeurs et références obtenus vers cet élément avant son extraction redeviennent valides. (depuis C++17)

Paramètres

  • pos — itérateur vers la position avant laquelle le nouvel élément sera inséré
  • value — valeur de l'élément à insérer
  • first, last — intervalle d'éléments à insérer
  • ilist — liste d'initialisation à partir de laquelle insérer les valeurs
  • nh — un node handle compatible

Exigences sur les types

  • InputIt doit satisfaire aux exigences de LegacyInputIterator.

Valeur de retour

1-3) Une paire composée d'un itérateur vers l'élément inséré (ou vers l'élément qui a empêché l'insertion) et d'une valeur bool égale à true si et seulement si l'insertion a eu lieu.

4-6) Un itérateur vers l'élément inséré, ou vers l'élément qui a empêché l'insertion.

7,8) (aucun)

  1. Un objet de insert_return_type dont les membres sont initialisés comme suit :
  • Si nh est vide, inserted vaut false, position vaut end(), et node est vide.
  • Sinon, si l'insertion a eu lieu, inserted vaut true, position pointe vers l'élément inséré, et node est vide.
  • Si l'insertion a échoué, inserted vaut false, node a la valeur précédente de nh, et position pointe vers un élément de clé équivalente à nh.key().
  1. Itérateur de fin si nh était vide, itérateur pointant vers l'élément inséré si l'insertion a eu lieu, et itérateur pointant vers un élément de clé équivalente à nh.key() en cas d'échec.

Exceptions

1-6) Si une exception est levée par une opération quelconque, l'insertion n'a aucun effet.

Complexité

1-3) Logarithmique en la taille du conteneur, O(log(size())).

4-6) Constante amortie si l'insertion a lieu à la position juste [après (jusqu'à C++11) | avant (depuis C++11)] pos, logarithmique en la taille du conteneur sinon.

7,8) O(N·log(size() + N)), où N est le nombre d'éléments à insérer.

  1. Logarithmique en la taille du conteneur, O(log(size())).

  2. Constante amortie si l'insertion a lieu à la position juste avant pos, logarithmique en la taille du conteneur sinon.

Notes

L'insertion avec indication (4-6) ne renvoie pas de booléen afin d'avoir la même signature que l'insertion positionnelle des conteneurs séquentiels, tels que std::vector::insert. Cela permet de créer des insertion génériques comme std::inserter. Une façon de vérifier le succès d'une insertion avec indication consiste à comparer size() avant et après.

Exemple

#include <iomanip>
#include <iostream>
#include <map>
#include <string>
using namespace std::literals;

template<typename It>
void print_insertion_status(It it, bool success)
{
    std::cout << "Insertion of " << it->first
              << (success ? " succeeded\n" : " failed\n");
}

int main()
{
    std::map<std::string, float> heights;

    // Surcharge 3 : insertion depuis une référence rvalue
    const auto [it_hinata, success] = heights.insert({"Hinata"s, 162.8});
    print_insertion_status(it_hinata, success);

    {
        // Surcharge 1 : insertion depuis une référence lvalue
        const auto [it, success2] = heights.insert(*it_hinata);
        print_insertion_status(it, success2);
    }
    {
        // Surcharge 2 : insertion par redirection vers emplace
        const auto [it, success] = heights.insert(std::pair{"Kageyama", 180.6});
        print_insertion_status(it, success);
    }
    {
        // Surcharge 6 : insertion depuis une référence rvalue avec indice de position
        const std::size_t n = std::size(heights);
        const auto it = heights.insert(it_hinata, {"Azumane"s, 184.7});
        print_insertion_status(it, std::size(heights) != n);
    }
    {
        // Surcharge 4 : insertion depuis une référence lvalue avec indice de position
        const std::size_t n = std::size(heights);
        const auto it = heights.insert(it_hinata, *it_hinata);
        print_insertion_status(it, std::size(heights) != n);
    }
    {
        // Surcharge 5 : insertion par redirection vers emplace avec indice de position
        const std::size_t n = std::size(heights);
        const auto it = heights.insert(it_hinata, std::pair{"Tsukishima", 188.3});
        print_insertion_status(it, std::size(heights) != n);
    }

    auto node_hinata = heights.extract(it_hinata);
    std::map<std::string, float> heights2;

    // Surcharge 7 : insertion depuis un intervalle d'itérateurs
    heights2.insert(std::begin(heights), std::end(heights));

    // Surcharge 8 : insertion depuis initializer_list
    heights2.insert({{"Kozume"s, 169.2}, {"Kuroo", 187.7}});

    // Surcharge 9 : insertion d'un nœud
    const auto status = heights2.insert(std::move(node_hinata));
    print_insertion_status(status.position, status.inserted);

    node_hinata = heights2.extract(status.position);
    {
        // Surcharge 10 : insertion d'un nœud avec indice de position
        const std::size_t n = std::size(heights2);
        const auto it = heights2.insert(std::begin(heights2), std::move(node_hinata));
        print_insertion_status(it, std::size(heights2) != n);
    }

    // Afficher la map résultante
    std::cout << std::left << '\n';
    for (const auto& [name, height] : heights2)
        std::cout << std::setw(10) << name << " | " << height << "cm\n";
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 233 C++98 pos n'était qu'un indice, qui pouvait être entièrement ignoré l'insertion devait être à la position la plus proche possible de la position juste avant pos
LWG 264 C++98 la complexité de la surcharge (7) devait être linéaire si l'intervalle [first,last) est trié selon Compare suppression de l'exigence de linéarité dans ce cas particulier
LWG 316 C++98 dans la valeur de retour de la surcharge (1), il n'était pas spécifié quelle valeur de bool indique une insertion réussie le succès est indiqué par true
LWG 2005 C++11 les surcharges (2,5) étaient mal décrites description améliorée
