std::forward_list<T,Allocator>::splice_after

void splice_after( const_iterator pos, forward_list&& other );  // (2) (depuis C++11)

                   const_iterator first, const_iterator last );  // (5) (depuis C++11)

                   const_iterator first, const_iterator last );  // (6) (depuis C++11)

Déplace des éléments d'un autre forward_list vers *this. Les éléments sont insérés après l'élément désigné par pos.

Aucun élément n'est copié. Aucun itérateur ni aucune référence ne sont invalidés. Les itérateurs vers les éléments déplacés désignent désormais *this, et non other.

1,2) Déplace tous les éléments de other dans *this. Le conteneur other devient vide après l'opération.

3,4) Déplace l'élément désigné par l'itérateur suivant it de other vers *this. Sans effet si pos == it ou si pos == ++it.

5,6) Déplace les éléments de l'intervalle (first,last) de other vers *this. L'élément désigné par first n'est pas déplacé.

Le comportement est indéfini si

  • get_allocator() != other.get_allocator(),
  • pos n'est ni before_begin() ni un itérateur déréférençable dans [begin(),end()),
  • pour les surcharges (1,2), *this et other font référence au même objet,
  • pour les surcharges (3,4), l'itérateur suivant it n'est pas un itérateur déréférençable dans other, ou
  • pour les surcharges (5,6),
    • (first,last) n'est pas un intervalle valide dans other,
    • certains itérateurs de (first,last) ne sont pas déréférençables, ou
    • pos se trouve dans (first,last).

Paramètres

  • pos — élément après lequel le contenu sera inséré
  • other — autre conteneur duquel déplacer le contenu
  • it — itérateur précédant l'itérateur vers l'élément à déplacer de other vers *this
  • first, last — l'intervalle d'éléments à déplacer de other vers *this

Exceptions

Ne lève aucune exception.

Complexité

1,2) Linéaire en la taille de other.

3,4) Constante.

5,6) Linéaire en std::distance(first, last).

Exemple

#include <cassert>
#include <forward_list>

int main()
{
    using F = std::forward_list<int>;

    // Démontre le sens de l'intervalle ouvert (first, last)
    // dans la surcharge (5) : le premier élément de l1 n'est pas déplacé.
    F l1 = {1, 2, 3, 4, 5};
    F l2 = {10, 11, 12};

    l2.splice_after(l2.cbegin(), l1, l1.cbegin(), l1.cend());
    // Non équivalent à l2.splice_after(l2.cbegin(), l1);
    // qui est équivalent à
    // l2.splice_after(l2.cbegin(), l1, l1.cbefore_begin(), l1.end());

    assert((l1 == F{1}));
    assert((l2 == F{10, 2, 3, 4, 5, 11, 12}));

    // Surcharge (1)
    F x = {1, 2, 3, 4, 5};
    F y = {10, 11, 12};
    x.splice_after(x.cbegin(), y);
    assert((x == F{1, 10, 11, 12, 2, 3, 4, 5}));
    assert((y == F{}));

    // Surcharge (3)
    x = {1, 2, 3, 4, 5};
    y = {10, 11, 12};
    x.splice_after(x.cbegin(), y, y.cbegin());
    assert((x == F{1, 11, 2, 3, 4, 5}));
    assert((y == F{10, 12}));

    // Surcharge (5)
    x = {1, 2, 3, 4, 5};
    y = {10, 11, 12};
    x.splice_after(x.cbegin(), y, y.cbegin(), y.cend());
    assert((x == F{1, 11, 12, 2, 3, 4, 5}));
    assert((y == F{10}));
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 2045 C++11 La complexité O(1) de l'épissage ne pouvait pas être garantie si get_allocator() != other.get_allocator() le comportement est indéfini dans ce cas
LWG 2222 C++11 l'élément désigné par it n'est pas déplacé, mais les pointeurs, références et itérateurs qui le désignent désigneraient un élément de *this après l'épissage désignent toujours l'élément de other
