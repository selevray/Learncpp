template< class T >
std::complex<T> exp( const std::complex<T>& z );

Calcule l'exponentielle de base e de z, c'est-à-dire e (nombre d'Euler, 2.7182818) élevé à la puissance z.

Paramètres

  • z — valeur complexe

Valeur de retour

Si aucune erreur ne se produit, e élevé à la puissance de z, (\small e^z)ez
, est retourné.

Gestion des erreurs et valeurs spéciales

Les erreurs sont signalées de manière cohérente avec math_errhandling.

Si l'implémentation prend en charge l'arithmétique à virgule flottante IEEE,

  • std::exp(std::conj(z)) == std::conj(std::exp(z))
  • Si z vaut (±0,+0), le résultat est (1,+0)
  • Si z vaut (x,+∞) (pour tout x fini), le résultat est (NaN,NaN) et FE_INVALID est levée.
  • Si z vaut (x,NaN) (pour tout x fini), le résultat est (NaN,NaN) et FE_INVALID peut être levée.
  • Si z vaut (+∞,+0), le résultat est (+∞,+0)
  • Si z vaut (-∞,y) (pour tout y fini), le résultat est +0cis(y)
  • Si z vaut (+∞,y) (pour tout y fini non nul), le résultat est +∞cis(y)
  • Si z vaut (-∞,+∞), le résultat est (±0,±0) (les signes ne sont pas spécifiés)
  • Si z vaut (+∞,+∞), le résultat est (±∞,NaN) et FE_INVALID est levée (le signe de la partie réelle n'est pas spécifié)
  • Si z vaut (-∞,NaN), le résultat est (±0,±0) (les signes ne sont pas spécifiés)
  • Si z vaut (+∞,NaN), le résultat est (±∞,NaN) (le signe de la partie réelle n'est pas spécifié)
  • Si z vaut (NaN,+0), le résultat est (NaN,+0)
  • Si z vaut (NaN,y) (pour tout y non nul), le résultat est (NaN,NaN) et FE_INVALID peut être levée
  • Si z vaut (NaN,NaN), le résultat est (NaN,NaN)

où (\small{\rm cis}(y))cis(y) vaut (\small \cos(y)+{\rm i}\sin(y))cos(y) + i sin(y).

Notes

La fonction exponentielle complexe (\small e^z)ez
pour (\small z = x + {\rm i}y)z = x+iy est égale à (\small e^x {\rm cis}(y))ex
cis(y), ou encore (\small e^x (\cos(y)+{\rm i}\sin(y)))ex
(cos(y) + i sin(y)).

La fonction exponentielle est une fonction entière dans le plan complexe et n'a aucune coupure de branche.

Les expressions suivantes donnent des résultats équivalents lorsque la partie réelle vaut 0 :

  • std::exp(std::complex<float>(0, theta))
  • std::complex<float>(cosf(theta), sinf(theta))
  • std::polar(1.f, theta)

Dans ce cas, exp peut être environ 4,5 fois plus lent. Il faudrait utiliser l'une des autres formes au lieu d'appeler exp avec un argument dont la partie réelle vaut littéralement 0. Il n'y a cependant aucun intérêt à essayer d'éviter exp avec un test à l'exécution de z.real() == 0.

Exemple

#include <cmath>
#include <complex>
#include <iostream>

int main()
{
   const double pi = std::acos(-1.0);
   const std::complex<double> i(0.0, 1.0);

   std::cout << std::fixed << " exp(i * pi) = " << std::exp(i * pi) << '\n';
}

Output:

exp(i * pi) = (-1.000000,0.000000)
