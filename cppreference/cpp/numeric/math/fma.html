Surcharges supplémentaires

Défini dans l'en-tête <cmath>

template< class Arithmetic1, class Arithmetic2, class Arithmetic3 >
/* type à virgule flottante commun */
    fma( Arithmetic1 x, Arithmetic2 y, Arithmetic3 z );  // (A) (depuis C++11) (constexpr depuis C++23)

1-3) Calcule x * y + z comme si la précision était infinie, et n'arrondit qu'une seule fois pour tenir dans le type du résultat.La bibliothèque fournit des surcharges de std::fma pour tous les types à virgule flottante non qualifiés cv comme type des paramètres x, y et z. (depuis C++23)

4-6) Si les constantes macro FP_FAST_FMA, FP_FAST_FMAF ou FP_FAST_FMAL sont définies, la fonction std::fma s'exécute plus vite (en plus d'être plus précise) que l'expression x * y + z pour des arguments double, float et long double respectivement. Si elles sont définies, ces macros s'évaluent en 1 entiers.

A) Des surcharges supplémentaires sont fournies pour toutes les autres combinaisons de types arithmétiques.

Paramètres

  • x, y, z — valeurs à virgule flottante ou entières

Valeur de retour

En cas de succès, renvoie la valeur de x * y + z comme si elle était calculée avec une précision infinie et arrondie une seule fois pour tenir dans le type du résultat (ou, de manière équivalente, calculée comme une unique opération ternaire à virgule flottante).

Si une erreur d'intervalle due à un dépassement se produit, ±HUGE_VAL, ±HUGE_VALF ou ±HUGE_VALL est renvoyé.

Si une erreur de plage due à un sous-dépassement se produit, la valeur correcte (après arrondi) est renvoyée.

Gestion des erreurs

Les erreurs sont signalées comme spécifié dans math_errhandling.

Si l'implémentation prend en charge l'arithmétique à virgule flottante IEEE (CEI 60559),

  • Si x vaut zéro et y est infini, ou si x est infini et y vaut zéro, et
    • si z n'est pas un NaN, alors NaN est renvoyé et FE_INVALID est levé,
    • si z est un NaN, alors NaN est renvoyé et FE_INVALID peut être levé.
  • Si x * y est exactement un infini et z est un infini de signe opposé, NaN est renvoyé et FE_INVALID est levé.
  • Si x ou y valent NaN, NaN est renvoyé.
  • Si z vaut NaN, et x * y n'est ni 0 * Inf ni Inf * 0, alors NaN est renvoyé (sans FE_INVALID).

Notes

Cette opération est couramment implémentée au niveau matériel par l'instruction CPU multiplication-addition fusionnée. Si elle est prise en charge par le matériel, les macros FP_FAST_FMA? appropriées sont censées être définies, mais de nombreuses implémentations utilisent l'instruction CPU même lorsque les macros ne sont pas définies.

POSIX (fma, fmaf, fmal) précise en outre que les situations pour lesquelles FE_INVALID doit être renvoyé sont des erreurs de domaine.

En raison de sa précision intermédiaire infinie, std::fma est un élément de base courant d'autres opérations mathématiques à arrondi correct, comme std::sqrt ou même la division (lorsqu'elle n'est pas fournie par le CPU, par exemple Itanium).

Comme pour toutes les expressions à virgule flottante, l'expression x * y + z peut être compilée en multiplication-addition fusionnée, sauf si #pragma STDC FP_CONTRACT est désactivé.

Les surcharges supplémentaires ne sont pas tenues d'être fournies exactement comme (A). Elles doivent seulement être suffisantes pour garantir que pour leur premier argument num1, leur deuxième argument num2 et leur troisième argument num3 :

  • Si num1, num2 ou num3 a le type long double, alors std::fma(num1, num2, num3) a le même effet que std::fma(static_cast<long double>(num1), static_cast<long double>(num2), static_cast<long double>(num3)).
  • Sinon, si num1, num2 et/ou num3 a le type double ou un type entier, alors std::fma(num1, num2, num3) a le même effet que std::fma(static_cast<double>(num1), static_cast<double>(num2), static_cast<double>(num3)).
  • Sinon, si num1, num2 ou num3 a le type float, alors std::fma(num1, num2, num3) a le même effet que std::fma(static_cast<float>(num1), static_cast<float>(num2), static_cast<float>(num3)).

(jusqu'à C++23)

Si num1, num2 et num3 ont des types arithmétiques, alors std::fma(num1, num2, num3) a le même effet que std::fma(static_cast</*type à virgule flottante commun*/>(num1), static_cast</*type à virgule flottante commun*/>(num2), static_cast</*type à virgule flottante commun*/>(num3)), où /*type à virgule flottante commun*/ est le type à virgule flottante ayant le plus grand rang de conversion à virgule flottante et le plus grand sous-rang de conversion à virgule flottante parmi les types de num1, num2 et num3 ; les arguments de type entier sont considérés comme ayant le même rang de conversion à virgule flottante que double.

S'il n'existe aucun type à virgule flottante ayant le plus grand rang et sous-rang, alors la résolution de surcharge ne donne aucun candidat utilisable parmi les surcharges fournies.

(depuis C++23)

Exemple

#include <cfenv>
#include <cmath>
#include <iomanip>
#include <iostream>

#ifndef __GNUC__
#pragma STDC FENV_ACCESS ON
#endif

int main()
{
    // démontre la différence entre fma et les opérateurs intégrés
    const double in = 0.1;
    std::cout << "0.1 double is " << std::setprecision(23) << in
              << " (" << std::hexfloat << in << std::defaultfloat << ")\n"
              << "0.1*10 is 1.0000000000000000555112 (0x8.0000000000002p-3), "
              << "or 1.0 if rounded to double\n";

    const double expr_result = 0.1 * 10 - 1;
    const double fma_result = std::fma(0.1, 10, -1);
    std::cout << "0.1 * 10 - 1 = " << expr_result
              << " : 1 subtracted after intermediate rounding\n"
              << "fma(0.1, 10, -1) = " << std::setprecision(6) << fma_result << " ("
              << std::hexfloat << fma_result << std::defaultfloat << ")\n\n";

    // fma est utilisée dans l'arithmétique double-double
    const double high = 0.1 * 10;
    const double low = std::fma(0.1, 10, -high);
    std::cout << "in double-double arithmetic, 0.1 * 10 is representable as "
              << high << " + " << low << "\n\n";

    // gestion des erreurs
    std::feclearexcept(FE_ALL_EXCEPT);
    std::cout << "fma(+Inf, 10, -Inf) = " << std::fma(INFINITY, 10, -INFINITY) << '\n';
    if (std::fetestexcept(FE_INVALID))
        std::cout << "    FE_INVALID raised\n";
}

Sortie possible :

0.1 double is 0.10000000000000000555112 (0x1.999999999999ap-4)
0.1*10 is 1.0000000000000000555112 (0x8.0000000000002p-3), or 1.0 if rounded to double
0.1 * 10 - 1 = 0 : 1 subtracted after intermediate rounding
fma(0.1, 10, -1) = 5.55112e-17 (0x1p-54)

in double-double arithmetic, 0.1 * 10 is representable as 1 + 5.55112e-17

fma(+Inf, 10, -Inf) = -nan
    FE_INVALID raised
