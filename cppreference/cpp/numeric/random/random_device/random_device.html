std::random_device::random_device

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

random_device() : random_device( /*défini par l'implémentation*/ ) {}  // (1) (depuis C++11)

explicit random_device( const std::string& token );  // (2) (depuis C++11)

random_device( const random_device& ) = delete;  // (3) (depuis C++11)

  1. Construit par défaut un nouvel objet std::random_device avec un token défini par l'implémentation.

  2. Construit un nouvel objet std::random_device, en utilisant l'argument token de manière définie par l'implémentation.

  3. Le constructeur de copie est supprimé : std::random_device n'est ni copiable ni déplaçable.

Exceptions

Lève une exception définie par l'implémentation et dérivée de std::exception en cas d'échec.

Notes

L'implémentation dans libstdc++ attend que token désigne la source des octets aléatoires. Les valeurs de jeton possibles comprennent "default", "hw", "rand_s", "rdseed", "rdrand", "rdrnd", "/dev/urandom", "/dev/random", "mt19937", ainsi qu'une chaîne entière spécifiant la graine du moteur mt19937. (Les valeurs de jeton autres que "default" ne sont valides que pour certaines cibles.)

L'implémentation dans libc++, lorsqu'elle est configurée pour utiliser un périphérique caractère comme source, attend que token soit le nom d'un périphérique caractère qui produit des nombres aléatoires à la lecture ; sinon elle attend que token soit "/dev/urandom".

Libstdc++ et libc++ lèvent toutes deux une exception si un jeton non pris en charge est fourni. La bibliothèque standard de Microsoft ignore entièrement le jeton.

Exemple

Démontre les types couramment disponibles de std::random_device sous Linux.

#include <iostream>
#include <random>

void demo(std::random_device&& rd)
{
    static std::uniform_int_distribution<int> d(0, 9);
    for (int n = 0; n != 10; ++n)
        std::cout << d(rd) << ' ';
    std::cout << '\n';
}

int main()
{
    // Remarque : la manière dont le jeton fourni est traité est défini par l'implémentation !

    // Le jeton par défaut de random_device est généralement /dev/urandom sous Linux
    demo(std::random_device {});

    // Demande /dev/random, bloque lorsque l'entropie est épuisée
    // Fonctionne avec libstdc++, ignoré dans msvc++, peut lever une exception avec libc++ (en novembre 2022)
    demo(std::random_device {"/dev/random"});

    // Demande /dev/urandom non bloquant, garantit que RDRAND n'est pas utilisé
    // Fonctionne avec libstdc++ et libc++, ignoré dans msvc++ (en novembre 2022)
    demo(std::random_device {"/dev/urandom"});

    // Demande « hw », utilisera une génération aléatoire matérielle comme rdrand
    // Fonctionne avec libstdc++, ignoré dans msvc++, lève une exception avec libc++ (en novembre 2022)
    demo(std::random_device {"hw"});
}
