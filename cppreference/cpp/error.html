Gestion des exceptions

L'en-tête <exception> fournit plusieurs classes et fonctions liées à la gestion des exceptions dans les programmes C++.

Défini dans l'en-tête <exception>

  • exception — classe de base des exceptions levées par les composants de la bibliothèque standard (classe)

##### Capture et stockage des objets exception {#Capture_and_storage_of_exception_objects}

  • uncaught_exceptionuncaught_exceptions(removed in C++20) (C++17)* — vérifie si la gestion d'exception est actuellement en cours (fonction)
  • exception_ptr (C++11) — type de pointeur partagé pour la gestion des objets exception (typedef)
  • make_exception_ptr (C++11) — crée un std::exception_ptr à partir d'un objet exception (modèle de fonction)
  • current_exception (C++11) — capture l'exception courante dans un std::exception_ptr (fonction)
  • rethrow_exception (C++11) — lève l'exception depuis un std::exception_ptr (fonction)
  • nested_exception (C++11) — un type mixin pour capturer et stocker les exceptions courantes (classe)
  • throw_with_nested (C++11) — lève son argument avec std::nested_exception mélangé à (modèle de fonction)
  • rethrow_if_nested (C++11) — lève l'exception depuis un std::nested_exception (modèle de fonction)

##### Gestion des échecs de la gestion des exceptions {#Handling_of_failures_in_exception_handling}

Défini dans l'en-tête <exception>

  • terminate — fonction appelée lorsque la gestion des exceptions échoue (fonction)
  • terminate_handler — le type de la fonction appelée par std::terminate (typedef)
  • get_terminate (C++11) — obtient le terminate_handler courant (fonction)
  • set_terminate — modifie la fonction appelée par std::terminate (fonction)
  • bad_exception — exception levée lorsque std::current_exception échoue à copier l'objet exception (classe)

##### Gestion des violations de spécification d'exception (jusqu'à C++17) {#Handling_of_exception_specification_violations_.28until_C.2B.2B17.29}

  • unexpected (deprecated in C++11) (removed in C++17) — fonction appelée lorsque la spécification d'exception dynamique est violée (fonction)
  • unexpected_handler (deprecated in C++11) (removed in C++17) — le type de la fonction appelée par std::unexpected (typedef)
  • get_unexpected (deprecated in C++11) (removed in C++17) — obtient le unexpected_handler actuel (fonction)
  • set_unexpected (deprecated in C++11) (removed in C++17) — modifie la fonction appelée par std::unexpected (fonction)

Catégories d'exceptions

Plusieurs classes utilitaires sont prédéfinies dans l'en-tête <stdexcept> pour signaler des conditions d'erreur particulières. Ces classes se répartissent en deux catégories : erreurs de logique et erreurs d'exécution. Les erreurs de logique résultent d'une logique défaillante dans le programme et peuvent être évitées. Les erreurs d'exécution sont dues à des événements échappant à la portée du programme et ne peuvent pas être facilement prévues.

Défini dans l'en-tête <stdexcept>

  • logic_error — classe d'exception signalant la violation de préconditions logiques ou d'invariants de classe (classe)
  • invalid_argument — classe d'exception signalant des arguments invalides (classe)
  • domain_error — classe d'exception signalant des erreurs de domaine (classe)
  • length_error — classe d'exception signalant des tentatives de dépassement de la taille maximale autorisée (classe)
  • out_of_range — classe d'exception signalant des arguments hors de la plage attendue (classe)
  • runtime_error — classe d'exception signalant des conditions détectables uniquement à l'exécution (classe)
  • range_error — classe d'exception signalant des erreurs de plage dans des calculs internes (classe)
  • overflow_error — classe d'exception signalant des dépassements arithmétiques (classe)
  • underflow_error — classe d'exception signalant des dépassements inférieurs arithmétiques (classe)
  • tx_exception (TM TS) — classe d'exception permettant d'annuler des transactions atomiques (modèle de classe)

Numéros d'erreur

Défini dans l'en-tête <cerrno>

  • errno — macro qui se développe en variable de numéro d'erreur locale au thread, compatible POSIX (variable macro)
  • E2BIG, EACCES, ..., EXDEV — macros pour les conditions d'erreur standard compatibles POSIX (constante macro)

Erreur système (depuis C++11)

L'en-tête <system_error> définit des types et des fonctions utilisés pour signaler les conditions d'erreur provenant du système d'exploitation, des E/S de flux, std::future, ou d'autres API de bas niveau.

Défini dans l'en-tête <system_error>

  • error_category (C++11) — classe de base pour les catégories d'erreurs (classe)
  • generic_category (C++11) — identifie la catégorie d'erreur générique (fonction)
  • system_category (C++11) — identifie la catégorie d'erreur du système d'exploitation (fonction)
  • error_condition (C++11) — contient un code d'erreur portable (classe)
  • errc (C++11) — l'énumération std::error_condition listant toutes les constantes macro standard <cerrno> (classe)
  • error_code (C++11) — contient un code d'erreur dépendant de la plateforme (classe)
  • system_error (C++11) — classe d'exception utilisée pour signaler des conditions ayant un error_code (classe)

Assertions

Les assertions facilitent la vérification des préconditions dans les programmes.

Défini dans l'en-tête <cassert>

  • assert — interrompt le programme si la condition spécifiée par l'utilisateur n'est pas true. Peut être désactivée pour les versions de production. (macro de fonction)

Trace de pile (depuis C++23)

Défini dans l'en-tête <stacktrace>

  • stacktrace_entry (C++23) — représentation d'une évaluation dans une trace de pile (classe)
  • basic_stacktrace (C++23) — représentation approximative d'une séquence d'invocations constituée d'entrées de trace de pile (modèle de classe)

Prise en charge du débogage (depuis C++26)

Défini dans l'en-tête <debugging>

  • breakpoint (C++26) — suspend le programme en cours d'exécution lorsqu'il est appelé (fonction)
  • breakpoint_if_debugging (C++26) — appelle std::breakpoint si std::is_debugger_present renvoie true (fonction)
  • is_debugger_present (C++26) — vérifie si un programme s'exécute sous le contrôle d'un débogueur (fonction)
