Bibliothèque des conteneurs

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

La bibliothèque des conteneurs est une collection générique de modèles de classes et d'algorithmes qui permettent aux programmeurs d'implémenter facilement des structures de données courantes comme les files, les listes et les piles. Il existe [deux (jusqu'à C++11) | trois (depuis C++11)] classes de conteneurs :

  • conteneurs séquentiels,
  • conteneurs associatifs,
  • conteneurs associatifs non ordonnés,

(depuis C++11)

chacun étant conçu pour prendre en charge un ensemble d'opérations différent.

Le conteneur gère l'espace de stockage alloué à ses éléments et fournit des fonctions membres pour y accéder, soit directement, soit par l'intermédiaire d'itérateurs (objets dont les propriétés sont similaires à celles des pointeurs).

La plupart des conteneurs ont au moins plusieurs fonctions membres en commun et partagent certaines fonctionnalités. Le conteneur le mieux adapté à une application donnée dépend non seulement des fonctionnalités offertes, mais aussi de son efficacité selon les différentes charges de travail.

Conteneurs séquentiels

Les conteneurs séquentiels implémentent des structures de données accessibles de manière séquentielle.

  • array (C++11) — tableau contigu en place de taille fixe (modèle de classe)
  • vector — tableau dynamique contigu (modèle de classe)
  • inplace_vector (C++26) — tableau contigu redimensionnable à capacité fixe, en place (modèle de classe)
  • deque — file à double extrémité (modèle de classe)
  • forward_list (C++11) — liste simplement chaînée (modèle de classe)
  • list — liste doublement chaînée (modèle de classe)

Conteneurs associatifs

Les conteneurs associatifs implémentent des structures de données triées qui peuvent être recherchées rapidement (complexité O(log n)).

  • set — collection de clés uniques, triées par clés (modèle de classe)
  • map — collection de paires clé-valeur, triées par clés, les clés étant uniques (modèle de classe)
  • multiset — collection de clés, triées par clés (modèle de classe)
  • multimap — collection de paires clé-valeur, triées par clés (modèle de classe)

Conteneurs associatifs non ordonnés (depuis C++11)

Les conteneurs associatifs non ordonnés implémentent des structures de données non triées (à hachage) qui peuvent être rapidement recherchées (complexité O(1) en moyenne, O(n) au pire).

  • unordered_set (C++11) — collection de clés uniques, hachées par clés (modèle de classe)
  • unordered_map (C++11) — collection de paires clé-valeur, hachées par clés, les clés étant uniques (modèle de classe)
  • unordered_multiset (C++11) — collection de clés, hachées par clés (modèle de classe)
  • unordered_multimap (C++11) — collection de paires clé-valeur, hachée par clés (modèle de classe)

Adaptateurs de conteneurs

Les adaptateurs de conteneurs fournissent une interface différente pour les conteneurs séquentiels.

  • stack — adapte un conteneur pour fournir une pile (structure de données LIFO) (modèle de classe)
  • queue — adapte un conteneur pour fournir une file (structure de données FIFO) (modèle de classe)
  • priority_queue — adapte un conteneur pour fournir une file de priorité (modèle de classe)
  • flat_set (C++23) — adapte un conteneur pour fournir une collection de clés uniques, triées par clés (modèle de classe)
  • flat_map (C++23) — adapte deux conteneurs pour fournir une collection de paires clé-valeur, triées par clés uniques (modèle de classe)
  • flat_multiset (C++23) — adapte un conteneur pour fournir une collection de clés, triées par clés (modèle de classe)
  • flat_multimap (C++23) — adapte deux conteneurs pour fournir une collection de paires clé-valeur, triées par clés (modèle de classe)

Vues (depuis C++20)

Les vues fournissent des outils souples pour interagir avec des vues unidimensionnelles ou multidimensionnelles sur un tableau d'éléments non possédé.

  • span (C++20) — vue non possédante sur une séquence contiguë d'objets (modèle de classe)
  • mdspan (C++23) — une vue de tableau multidimensionnelle non propriétaire (modèle de classe)

Ici, insertion désigne toute méthode qui ajoute un ou plusieurs éléments au conteneur, et effacement désigne toute méthode qui retire un ou plusieurs éléments du conteneur.

  • Des exemples de méthodes d'insertion sont std::set::insert, std::map::emplace, std::vector::push_back et std::deque::push_front.
  • Notez que std::unordered_map::operator[] compte aussi, car il peut insérer un élément dans la map.

(depuis C++11)

  • Des exemples de méthodes d'effacement sont std::set::erase, std::vector::pop_back, std::deque::pop_front et std::map::clear.
    • clear invalide tous les itérateurs et toutes les références. Comme il efface tous les éléments, cela respecte techniquement les règles ci-dessus.

Sauf indication contraire (explicite ou en définissant une fonction à partir d'autres fonctions), le passage d'un conteneur en argument d'une fonction de la bibliothèque n'invalide jamais les itérateurs vers les objets de ce conteneur, et ne modifie jamais leurs valeurs.

L'itérateur past-the-end mérite une mention particulière. En général, cet itérateur est invalidé comme s'il s'agissait d'un itérateur normal vers un élément non effacé. Ainsi std::set::end n'est jamais invalidé, std::unordered_set::end n'est invalidé qu'au rehachage (depuis C++11), std::vector::end est toujours invalidé (puisqu'il se situe toujours après les éléments modifiés), et ainsi de suite.

Il existe une exception : un effacement qui supprime le dernier élément d'un std::deque invalide l'itérateur past-the-end, même s'il ne s'agit pas d'un élément effacé du conteneur (ni même d'un élément). Combinée aux règles générales pour les itérateurs std::deque, le résultat net est que la seule opération de modification qui n'invalide pas std::deque::end est un effacement qui supprime le premier élément, mais pas le dernier.

Sécurité des threads

  1. Toutes les fonctions des conteneurs peuvent être appelées simultanément par différents threads sur des conteneurs différents. Plus généralement, les fonctions de la bibliothèque standard C++ ne lisent pas les objets accessibles par d'autres threads, sauf si ces objets sont directement ou indirectement accessibles via les arguments de la fonction, y compris le pointeur this.
  2. Toutes les fonctions membres de const peuvent être appelées simultanément par différents threads sur le même conteneur. De plus, les fonctions membres begin(), end(), rbegin(), rend(), front(), back(), data(), find(), lower_bound(), upper_bound(), equal_range(), at() et, sauf dans les conteneurs associatifs, operator[], se comportent comme const du point de vue de la sécurité des threads (c'est-à-dire qu'elles peuvent aussi être appelées simultanément par différents threads sur le même conteneur). Plus généralement, les fonctions de la bibliothèque standard C++ ne modifient pas les objets sauf si ces objets sont accessibles, directement ou indirectement, via les arguments non const de la fonction, y compris le pointeur this.
  3. Différents éléments d'un même conteneur peuvent être modifiés simultanément par différents threads, sauf les éléments de std::vector<bool> (par exemple, un vector d'objets std::future peut recevoir des valeurs de plusieurs threads).
  4. Les opérations sur les itérateurs (par exemple l'incrémentation d'un itérateur) lisent mais ne modifient pas le conteneur sous-jacent, et peuvent être exécutées simultanément avec des opérations sur d'autres itérateurs du même conteneur, avec les fonctions membres const, ou avec des lectures des éléments. Les opérations sur le conteneur qui invalident des itérateurs modifient le conteneur et ne peuvent pas être exécutées simultanément avec une opération sur des itérateurs existants, même si ces itérateurs ne sont pas invalidés.
  5. Les éléments d'un même conteneur peuvent être modifiés simultanément avec les fonctions membres qui ne sont pas spécifiées pour accéder à ces éléments. Plus généralement, les fonctions de la bibliothèque standard C++ ne lisent pas les objets accessibles indirectement via leurs arguments (y compris d'autres éléments d'un conteneur), sauf si leur spécification l'exige.
  6. Dans tous les cas, les opérations sur les conteneurs (comme les algorithmes ou toute autre fonction de la bibliothèque standard C++) peuvent être parallélisées en interne, tant que cela ne modifie pas les résultats visibles par l'utilisateur (par exemple std::transform peut être parallélisé, mais pas std::for_each, dont la spécification impose de parcourir chaque élément d'une séquence dans l'ordre).

(depuis C++11)

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.
