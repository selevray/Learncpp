std::notify_all_at_thread_exit

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <condition_variable>

void notify_all_at_thread_exit( std::condition_variable& cond,
                                std::unique_lock<std::mutex> lk );  // (depuis C++11)

notify_all_at_thread_exit fournit un mécanisme pour notifier aux autres threads qu'un thread donné a complètement terminé, y compris la destruction de tous les objets thread_local. Il fonctionne comme suit :

  • La propriété du verrou lk précédemment acquis est transférée au stockage interne.

  • L'environnement d'exécution est modifié de sorte que, lorsque le thread courant se termine, la variable de condition cond soit notifiée comme si par lk.unlock();cond.notify_all();.

Le lk.unlock() implicite est séquencé après la destruction de tous les objets ayant une durée de stockage thread local associés au thread courant.

Si l'une des conditions suivantes est satisfaite, le comportement est indéfini :

  • lk n'est pas verrouillé par le thread appelant.
  • Si d'autres threads attendent également sur cond, lk.mutex() est différent du mutex déverrouillé par les fonctions d'attente (wait, wait_for et wait_until) appelées sur cond par ces threads.

Notes

Un effet équivalent peut être obtenu avec les fonctionnalités fournies par std::promise ou std::packaged_task.

Le verrou lk fourni est maintenu jusqu'à la fin du thread. Une fois cette fonction appelée, aucun autre thread ne peut acquérir le même verrou afin d'attendre sur cond. Si certains threads attendent sur cette variable de condition, assurez-vous que la condition attendue est satisfaite pendant que le verrou sur lk est détenu, et que ce verrou n'est pas relâché puis réacquis avant d'appeler notify_all_at_thread_exit, afin d'éviter toute confusion due aux réveils parasites dans d'autres threads.

Dans les cas d'utilisation typiques, cette fonction est la dernière appelée par un thread détaché.

Paramètres

  • cond — la variable de condition à notifier à la fin du thread
  • lk — le verrou associé à la variable de condition cond

Valeur de retour

(aucune)

Exemple

Ce fragment de code partiel illustre comment notify_all_at_thread_exit peut être utilisé pour éviter d'accéder à des données dépendant de variables thread_local pendant que ces variables sont en cours de destruction :

#include <cassert>
#include <condition_variable>
#include <mutex>
#include <string>
#include <thread>

std::mutex m;
std::condition_variable cv;

bool ready = false;
std::string result; // un type quelconque

void thread_func()
{
    thread_local std::string thread_local_data = "42";

    std::unique_lock<std::mutex> lk(m);

    // affecte une valeur à result en utilisant des données thread_local
    result = thread_local_data;
    ready = true;

    std::notify_all_at_thread_exit(cv, std::move(lk));

}   // 1. destroy thread_locals ;
    // 2. déverrouiller le mutex ;
    // 3. notifier cv.

int main()
{
    std::thread t(thread_func);
    t.detach();

    // effectuer d'autres tâches
    // ...

    // attendre le thread détaché
    std::unique_lock<std::mutex> lk(m);
    cv.wait(lk, []{ return ready; });

    // result est prêt et les destructeurs de thread_local ont terminé, pas de comportement indéfini
    assert(result == "42");
}
