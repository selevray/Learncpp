std::unique_lock<Mutex>::try_lock_for

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

template< class Rep, class Period >
bool try_lock_for( const std::chrono::duration<Rep, Period>& timeout_duration );  // (depuis C++11)

Tente de verrouiller (c.-à-d. d'en acquérir la propriété) le mutex associé. Bloque jusqu'à ce que la timeout_duration spécifiée soit écoulée ou que le verrou soit acquis, selon ce qui survient en premier. En cas d'acquisition réussie du verrou, retourne true, sinon retourne false. Appelle effectivement mutex()->try_lock_for(timeout_duration).

Cette fonction peut bloquer pendant une durée supérieure à timeout_duration en raison de retards d'ordonnancement ou de contention de ressources.

La norme recommande d'utiliser une horloge stable (steady clock) pour mesurer la durée. Si une implémentation utilise à la place une horloge système, le temps d'attente peut également être sensible aux ajustements de l'horloge.

std::system_error est levée s'il n'existe aucun mutex associé ou si le mutex est déjà verrouillé par ce std::unique_lock.

Paramètres

  • timeout_duration — durée maximale de blocage

Valeur de retour

true si la propriété du mutex a été acquise avec succès, false sinon.

Exceptions

  • Toute exception levée par mutex()->try_lock_for(timeout_duration).

  • S'il n'existe aucun mutex associé, lève std::system_error avec un code d'erreur de std::errc::operation_not_permitted.

  • Si le mutex est déjà verrouillé, lève std::system_error avec un code d'erreur de std::errc::resource_deadlock_would_occur.
