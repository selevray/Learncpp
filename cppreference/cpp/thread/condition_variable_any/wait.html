std::condition_variable_any::wait

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

template< class Lock >
void wait( Lock& lock );  // (1) (depuis C++11)

template< class Lock, class Predicate >
void wait( Lock& lock, Predicate pred );  // (2) (depuis C++11)

template< class Lock, class Predicate >
bool wait( Lock& lock, std::stop_token stoken, Predicate pred );  // (3) (depuis C++20)

wait bloque le thread courant jusqu'à ce que la variable de condition soit notifiée ou qu'un réveil fallacieux se produise. pred peut être fourni facultativement pour détecter un réveil fallacieux.

  1. Appelle atomiquement lock.unlock() et bloque sur *this.

Le thread sera débloqué lorsque notify_all() ou notify_one() sera exécuté. Il peut aussi être débloqué de façon fallacieuse.

Une fois débloqué, appelle lock.lock() (éventuellement en bloquant sur le verrou), puis retourne.

2,3) Attend qu'une condition particulière devienne vraie ; peut être utilisée pour ignorer les réveils parasites.

  1. Équivalent à

while (!pred()) wait(lock);

  1. Enregistre *this pour la durée de cet appel, afin d'être notifié si une demande d'arrêt est faite sur l'état d'arrêt associé à stoken ; il est alors équivalent à

while (!stoken.stop_requested()){ if (pred()) return true; wait(lock);}return pred();

Juste après le retour de wait, lock est verrouillé par le thread appelant. Si cette postcondition ne peut pas être satisfaite[1], appelle std::terminate.

  1. ↑ Cela peut se produire si le reverrouillage du mutex lève une exception.

Paramètres

  • lock — un lock qui doit être verrouillé par le thread appelant
  • stoken — un jeton d'arrêt pour lequel enregistrer l'interruption
  • pred — le prédicat permettant de vérifier si l'attente peut être terminée

Exigences sur les types

  • Lock doit satisfaire aux exigences de BasicLockable.
  • Predicate doit satisfaire aux exigences de FunctionObject.
  • pred() doit être une expression valide, et son type et sa catégorie de valeur doivent satisfaire les exigences BooleanTestable.

Valeur de retour

1,2) (aucun)

  1. La dernière valeur de pred() avant le retour à l'appelant.

Exceptions

  1. Ne lève pas d'exception.

2,3) Toute exception levée par pred.

Notes

La valeur de retour de la surcharge (3) indique si pred a été évalué à true, qu'une demande d'arrêt ait été faite ou non.

Les effets de notify_one()/notify_all() et de chacune des trois parties atomiques de wait()/wait_for()/wait_until() (déverrouillage+attente, réveil et verrouillage) ont lieu selon un ordre total unique qui peut être vu comme l'ordre de modification d'une variable atomique : cet ordre est propre à cette variable de condition. Il est ainsi impossible à notify_one() de, par exemple, être retardé et de débloquer un thread qui a commencé à attendre juste après l'appel à notify_one().

Exemple

#include <chrono>
#include <condition_variable>
#include <iostream>
#include <thread>

std::condition_variable_any cv;
std::mutex cv_m; // Ce mutex sert à trois choses :
                 // 1) synchroniser les accès à i
                 // 2) synchroniser les accès à std::cerr
                 // 3) pour la variable de condition cv
int i = 0;

void waits()
{
    std::unique_lock<std::mutex> lk(cv_m);
    std::cerr << "Waiting... \n";
    cv.wait(lk, []{ return i == 1; });
    std::cerr << "...finished waiting. i == 1\n";
}

void signals()
{
    std::this_thread::sleep_for(std::chrono::seconds(1));
    {
        std::lock_guard<std::mutex> lk(cv_m);
        std::cerr << "Notifying...\n";
    }
    cv.notify_all();

    std::this_thread::sleep_for(std::chrono::seconds(1));

    {
        std::lock_guard<std::mutex> lk(cv_m);
        i = 1;
        std::cerr << "Notifying again...\n";
    }
    cv.notify_all();
}

int main()
{
    std::thread t1(waits), t2(waits), t3(waits), t4(signals);
    t1.join();
    t2.join();
    t3.join();
    t4.join();
}

Sortie possible :

Waiting...
Waiting...
Waiting...
Notifying...
Notifying again...
...finished waiting. i == 1
...finished waiting. i == 1
...finished waiting. i == 1

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 2114 (P2167R3) C++11 la convertibilité vers bool était trop faible pour refléter les attentes des implémentations exigences renforcées
LWG 2135 C++11 le comportement était peu clair si lock.lock() lève une exception appelle std::terminate dans ce cas
