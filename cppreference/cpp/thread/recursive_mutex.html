std::recursive_mutex

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <mutex>

class recursive_mutex;  // (depuis C++11)

La classe recursive_mutex est une primitive de synchronisation qui peut être utilisée pour protéger des données partagées contre des accès simultanés de plusieurs threads.

recursive_mutex offre une sémantique de propriété exclusive et récursive :

  • Un thread appelant possède un recursive_mutex pendant une période qui commence lorsqu'il appelle avec succès soit lock, soit try_lock. Pendant cette période, le thread peut effectuer des appels supplémentaires à lock ou try_lock. La période de propriété se termine lorsque le thread effectue un nombre correspondant d'appels à unlock.
  • Lorsqu'un thread possède un recursive_mutex, tous les autres threads seront bloqués (lors des appels à lock) ou recevront une valeur de retour false (pour try_lock) s'ils tentent de revendiquer la propriété du recursive_mutex.
  • Le nombre maximal de fois qu'un recursive_mutex peut être verrouillé n'est pas spécifié, mais une fois ce nombre atteint, les appels à lock lèveront std::system_error et les appels à try_lock renverront false.

Le comportement d'un programme est indéfini si un recursive_mutex est détruit alors qu'il est encore possédé par un thread. La classe recursive_mutex satisfait à toutes les exigences de Mutex et de StandardLayoutType.

Fonctions membres

  • (constructeur) — construit le mutex (fonction membre publique)
  • (destructeur) — détruit le mutex (fonction membre publique)
  • operator=[deleted] — non copiable par affectation (fonction membre publique)

##### Verrouillage {#Locking}

  • lock — verrouille le mutex, bloque si le mutex n'est pas disponible (fonction membre publique)
  • try_lock — tente de verrouiller le mutex, retourne si le mutex n'est pas disponible (fonction membre publique)
  • unlock — déverrouille le mutex (fonction membre publique)

##### Descripteur natif {#Native_handle}

  • native_handle — retourne l'objet de descripteur natif sous-jacent défini par l'implémentation (fonction membre publique)

Exemple

Un cas d'utilisation de recursive_mutex est la protection d'un état partagé dans une classe dont les fonctions membres peuvent s'appeler mutuellement.

#include <iostream>
#include <mutex>
#include <thread>

class X
{
    std::recursive_mutex m;
    std::string shared;
public:
    void fun1()
    {
        std::lock_guard<std::recursive_mutex> lk(m);
        shared = "fun1";
        std::cout << "in fun1, shared variable is now " << shared << '\n';
    }
    void fun2()
    {
        std::lock_guard<std::recursive_mutex> lk(m);
        shared = "fun2";
        std::cout << "in fun2, shared variable is now " << shared << '\n';
        fun1(); // le verrou récursif devient utile ici
        std::cout << "back in fun2, shared variable is " << shared << '\n';
    }
};

int main()
{
    X x;
    std::thread t1(&X::fun1, &x);
    std::thread t2(&X::fun2, &x);
    t1.join();
    t2.join();
}

in fun2, shared variable is now fun2
in fun1, shared variable is now fun1
back in fun2, shared variable is fun1
