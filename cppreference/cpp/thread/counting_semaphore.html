std::counting_semaphore, std::binary_semaphore

Défini dans l'en-tête <semaphore>

template< std::ptrdiff_t LeastMaxValue = /* défini par l'implémentation */ >
class counting_semaphore;  // (1) (depuis C++20)

using binary_semaphore = std::counting_semaphore<1>;  // (2) (depuis C++20)

  1. Un counting_semaphore est une primitive de synchronisation légère qui peut contrôler l'accès à une ressource partagée. Contrairement à un std::mutex, un counting_semaphore autorise plusieurs accès concurrents à la même ressource, pour au moins LeastMaxValue accesseurs concurrents. Le programme est mal formé si LeastMaxValue est négatif.

  2. binary_semaphore est un alias pour la spécialisation de std::counting_semaphore avec LeastMaxValue égal à 1. Les implémentations peuvent implémenter binary_semaphore plus efficacement que l'implémentation par défaut de std::counting_semaphore.

Un counting_semaphore contient un compteur interne initialisé par le constructeur. Ce compteur est décrémenté par les appels à acquire() et aux méthodes associées, et incrémenté par les appels à release(). Lorsque le compteur vaut zéro, acquire() bloque jusqu'à ce que le compteur soit incrémenté, mais try_acquire() ne bloque pas ; try_acquire_for() et try_acquire_until() bloquent jusqu'à ce que le compteur soit incrémenté ou qu'un délai d'attente soit atteint.

Comme pour std::condition_variable::wait(), try_acquire() de counting_semaphore peut échouer de façon fallacieuse.

Les spécialisations de std::counting_semaphore ne sont pas DefaultConstructible, CopyConstructible, MoveConstructible, CopyAssignable ni MoveAssignable.

##### Opérations {#Operations}

  • release — incrémente le compteur interne et débloque les acquéreurs (fonction membre publique)
  • acquire — décrémente le compteur interne ou bloque jusqu'à pouvoir (fonction membre publique)
  • try_acquire — tente de décrémenter le compteur interne sans bloquer (fonction membre publique)
  • try_acquire_for — tente de décrémenter le compteur interne, en bloquant pendant au plus une durée (fonction membre publique)
  • try_acquire_until — tente de décrémenter le compteur interne, en bloquant jusqu'à un instant donné (fonction membre publique)

##### Constantes {#Constants}

  • max [statique] — renvoie la valeur maximale possible du compteur interne (fonction membre statique publique)

Notes

Comme l'indique son nom, LeastMaxValue est la valeur maximale minimale, et non la valeur maximale réelle. Ainsi max() peut renvoyer un nombre supérieur à LeastMaxValue.

Contrairement à std::mutex, un counting_semaphore n'est pas lié aux threads d'exécution : l'acquisition d'un sémaphore peut par exemple se produire sur un thread différent de celui de sa libération. Toutes les opérations sur counting_semaphore peuvent être effectuées de manière concurrente et sans lien avec des threads d'exécution spécifiques, à l'exception du destructeur, qui ne peut pas être exécuté de manière concurrente mais peut l'être sur un thread différent.

Les sémaphores sont aussi souvent utilisés pour la sémantique de signalement/notification plutôt que pour l'exclusion mutuelle, en initialisant le sémaphore avec 0 et en bloquant ainsi le ou les récepteurs qui tentent de acquire(), jusqu'à ce que le notifieur « signale » en invoquant release(n). À cet égard, les sémaphores peuvent être considérés comme des alternatives aux std::condition_variable, souvent avec de meilleures performances.

Exemple

#include <chrono>
#include <iostream>
#include <semaphore>
#include <thread>

// instances globales de sémaphores binaires
// les compteurs des objets sont mis à zéro
// les objets sont dans l'état non signalé
std::binary_semaphore
    smphSignalMainToThread{0},
    smphSignalThreadToMain{0};

void ThreadProc()
{
    // attendre un signal du processus principal
    // en tentant de décrémenter le sémaphore
    smphSignalMainToThread.acquire();

    // cet appel bloque jusqu'à ce que le compteur du sémaphore soit
    // augmenté par le processus principal

    std::cout << "[thread] Got the signal\n"; // message de réponse

    // attendre 3 secondes pour simuler un travail
    // effectué par le thread
    using namespace std::literals;
    std::this_thread::sleep_for(3s);

    std::cout << "[thread] Send the signal\n"; // message

    // signaler en retour au processus principal
    smphSignalThreadToMain.release();
}

int main()
{
    // créer un thread de travail
    std::thread thrWorker(ThreadProc);

    std::cout << "[main] Send the signal\n"; // message

    // signaler au thread de travail de commencer à travailler
    // en augmentant le compteur du sémaphore
    smphSignalMainToThread.release();

    // attendre que le thread de travail ait terminé le travail
    // en tentant de décrémenter le compteur du sémaphore
    smphSignalThreadToMain.acquire();

    std::cout << "[main] Got the signal\n"; // message de réponse
    thrWorker.join();
}
