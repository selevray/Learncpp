std::mutex

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <mutex>

class mutex;  // (depuis C++11)

La classe mutex est une primitive de synchronisation qui peut être utilisée pour protéger des données partagées contre des accès simultanés de plusieurs threads.

mutex offre une sémantique de propriété exclusive et non récursive :

  • Un thread appelant possède un mutex depuis le moment où il appelle avec succès soit lock, soit try_lock, jusqu'à ce qu'il appelle unlock.
  • Lorsqu'un thread possède un mutex, tous les autres threads seront bloqués (lors des appels à lock) ou recevront une valeur de retour false (pour try_lock) s'ils tentent de revendiquer la propriété du mutex.
  • Un thread appelant ne doit pas posséder le mutex avant d'appeler lock ou try_lock.

Le comportement d'un programme est indéfini si un mutex est détruit alors qu'il est encore possédé par un thread, ou si un thread se termine alors qu'il possède un mutex. La classe mutex satisfait toutes les exigences de Mutex et de StandardLayoutType.

std::mutex n'est ni copiable ni déplaçable.

Nom Définition

  • native_handle_type (optional)* — défini par l'implémentation

Fonctions membres

  • (constructeur) — construit le mutex (fonction membre publique)
  • (destructeur) — détruit le mutex (fonction membre publique)
  • operator=[deleted] — non copiable par affectation (fonction membre publique)

##### Verrouillage {#Locking}

  • lock — verrouille le mutex, bloque si le mutex n'est pas disponible (fonction membre publique)
  • try_lock — tente de verrouiller le mutex, retourne si le mutex n'est pas disponible (fonction membre publique)
  • unlock — déverrouille le mutex (fonction membre publique)

##### Descripteur natif {#Native_handle}

  • native_handle — retourne l'objet de descripteur natif sous-jacent défini par l'implémentation (fonction membre publique)

Notes

std::mutex n'est généralement pas utilisée directement : std::unique_lock, std::lock_guard, ou std::scoped_lock (depuis C++17) gèrent le verrouillage de manière plus sûre vis-à-vis des exceptions.

Exemple

Cet exemple montre comment un mutex peut être utilisé pour protéger un std::map partagé entre deux threads.

#include <chrono>
#include <iostream>
#include <map>
#include <mutex>
#include <string>
#include <thread>

std::map<std::string, std::string> g_pages;
std::mutex g_pages_mutex;

void save_page(const std::string& url)
{
    // simule une longue récupération de page
    std::this_thread::sleep_for(std::chrono::seconds(2));
    std::string result = "fake content";

    std::lock_guard<std::mutex> guard(g_pages_mutex);
    g_pages[url] = result;
}

int main()
{
    std::thread t1(save_page, "http://foo");
    std::thread t2(save_page, "http://bar");
    t1.join();
    t2.join();

    // il est désormais sûr d'accéder à g_pages sans verrou, car les threads ont été joints
    for (const auto& [url, page] : g_pages)
        std::cout << url << " => " << page << '\n';
}

Output:

http://bar => fake content
http://foo => fake content

Voir aussi

  • recursive_mutex (C++11) — fournit un mécanisme d'exclusion mutuelle pouvant être verrouillé récursivement par le même thread (classe)
  • lock_guard (C++11) — implémente un wrapper de propriété de mutex strictement basé sur la portée (modèle de classe)
  • unique_lock (C++11) — implémente un wrapper de propriété de mutex déplaçable (modèle de classe)
  • scoped_lock (C++17) — wrapper RAII évitant les interblocages pour plusieurs mutex (modèle de classe)
  • condition_variable (C++11) — fournit une variable de condition associée à un std::unique_lock (classe)
