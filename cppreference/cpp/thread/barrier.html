std::barrier

Défini dans l'en-tête <barrier>

template< class CompletionFunction = /* voir ci-dessous */ >
class barrier;  // (depuis C++20)

Le modèle de classe std::barrier fournit un mécanisme de coordination entre threads qui bloque un groupe de threads de taille connue jusqu'à ce que tous les threads de ce groupe aient atteint la barrière. Contrairement à std::latch, les barrières sont réutilisables : une fois qu'un groupe de threads arrivés est débloqué, la barrière peut être réutilisée. Contrairement à std::latch, les barrières exécutent un appelable éventuellement vide avant de débloquer les threads.

La durée de vie d'un objet barrière se compose d'une ou plusieurs phases. Chaque phase définit un point de synchronisation de phase où les threads en attente sont bloqués. Des threads peuvent arriver à la barrière, mais différer l'attente sur le point de synchronisation de phase en appelant arrive. Ces threads peuvent ensuite se bloquer sur le point de synchronisation de phase en appelant wait.

Une phase de barrière se compose des étapes suivantes :

  1. Le compteur attendu est décrémenté à chaque appel de arrive ou de arrive_and_drop.
  2. Lorsque le compteur attendu atteint zéro, l'étape de complétion de phase est exécutée, c'est-à-dire que completion est invoqué, et tous les threads bloqués sur le point de synchronisation de phase sont débloqués. La fin de l'étape de complétion arrive strictement avant le retour de tous les appels débloqués par cette étape.
    Exactement une fois après que le compteur attendu a atteint zéro, un thread exécute l'étape de complétion lors de son appel à arrive, arrive_and_drop ou wait, sauf qu'il est défini par l'implémentation de savoir si l'étape est exécutée lorsqu'aucun thread n'appelle wait.
  3. Lorsque l'étape de complétion se termine, le compteur attendu est réinitialisé à la valeur spécifiée à la construction, diminuée du nombre d'appels à arrive_and_drop effectués depuis, et la phase de barrière suivante commence.

Les invocations concurrentes des fonctions membres de barrier, à l'exception du destructeur, n'introduisent pas de courses de données.

Paramètres de modèle

  • CompletionFunction — un type d'objet fonction
  • CompletionFunction doit satisfaire les exigences de MoveConstructible et de Destructible. std::is_nothrow_invocable_v<CompletionFunction&> doit être true.

L'argument de modèle par défaut de CompletionFunction est un type d'objet fonction non spécifié qui satisfait en plus les exigences de DefaultConstructible. Appeler une lvalue de ce type sans arguments n'a aucun effet.

Types membres

Nom Définition

  • arrival_token — un type d'objet non spécifié satisfaisant les exigences de MoveConstructible, MoveAssignable et Destructible

Membres de données

Membre Définition

  • CompletionFunction completion — un objet fonction de complétion, appelé à chaque étape de complétion de phase (membre objet exposé uniquement)*

Fonctions membres

  • (constructeur) — construit un barrier (fonction membre publique)
  • (destructeur) — détruit le barrier (fonction membre publique)
  • operator=[deleted] — barrier n'est pas affectable (fonction membre publique)
  • arrive — arrive à la barrière et décrémente le compte attendu (fonction membre publique)
  • wait — bloque au point de synchronisation de phase jusqu'à ce que son étape de complétion de phase soit exécutée (fonction membre publique)
  • arrive_and_wait — arrive à la barrière et décrémente le compteur attendu d'une unité, puis bloque jusqu'à la fin de la phase courante (fonction membre publique)
  • arrive_and_drop — décrémente d'une unité à la fois le compteur initial attendu pour les phases suivantes et le compteur attendu pour la phase courante (fonction membre publique)

##### Constantes {#Constants}

  • max [statique] — la valeur maximale du compteur attendu prise en charge par l'implémentation (fonction membre statique publique)

Exemple

#include <barrier>
#include <iostream>
#include <string>
#include <syncstream>
#include <thread>
#include <vector>

int main()
{
    const auto workers = {"Anil", "Busara", "Carl"};

    auto on_completion = []() noexcept
    {
        // verrouillage non nécessaire ici
        static auto phase =
            "... done\n"
            "Cleaning up...\n";
        std::cout << phase;
        phase = "... done\n";
    };

    std::barrier sync_point(std::ssize(workers), on_completion);

    auto work = [&](std::string name)
    {
        std::string product = "  " + name + " worked\n";
        std::osyncstream(std::cout) << product;  // ok, l'appel à op<< est atomique
        sync_point.arrive_and_wait();

        product = "  " + name + " cleaned\n";
        std::osyncstream(std::cout) << product;
        sync_point.arrive_and_wait();
    };

    std::cout << "Starting...\n";
    std::vector<std::jthread> threads;
    threads.reserve(std::size(workers));
    for (auto const& worker : workers)
        threads.emplace_back(work, worker);
}
