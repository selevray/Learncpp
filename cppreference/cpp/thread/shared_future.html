std::shared_future

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <future>

template< class T > class shared_future;  // (1) (depuis C++11)

template< class T > class shared_future<T&>;  // (2) (depuis C++11)

template<> class shared_future<void>;  // (3) (depuis C++11)

Le modèle de classe std::shared_future fournit un mécanisme pour accéder au résultat d'opérations asynchrones, semblable à std::future, à ceci près que plusieurs threads peuvent attendre le même état partagé. Contrairement à std::future, qui n'est que déplaçable (de sorte qu'une seule instance peut faire référence à un résultat asynchrone donné), std::shared_future est copiable et plusieurs objets future partagés peuvent faire référence au même état partagé.

L'accès au même état partagé depuis plusieurs threads est sûr si chaque thread le fait via sa propre copie d'un objet shared_future.

Fonctions membres

  • (constructeur) — construit l'objet futur (fonction membre publique)
  • (destructeur) — détruit l'objet futur (fonction membre publique)
  • operator= — affecte le contenu (fonction membre publique)

##### Obtention du résultat {#Getting_the_result}

  • get — retourne le résultat (fonction membre publique)

##### État {#State}

  • valid — vérifie si le futur possède un état partagé (fonction membre publique)
  • wait — attend que le résultat devienne disponible (fonction membre publique)
  • wait_for — attend le résultat, retourne s'il n'est pas disponible pendant la durée de temporisation spécifiée (fonction membre publique)
  • wait_until — attend le résultat, retourne s'il n'est pas disponible avant que le point temporel spécifié soit atteint (fonction membre publique)

Exemple

Un shared_future peut être utilisé pour signaler simultanément plusieurs threads, de façon semblable à std::condition_variable::notify_all().

#include <chrono>
#include <future>
#include <iostream>

int main()
{
    std::promise<void> ready_promise, t1_ready_promise, t2_ready_promise;
    std::shared_future<void> ready_future(ready_promise.get_future());

    std::chrono::time_point<std::chrono::high_resolution_clock> start;

    auto fun1 = [&, ready_future]() -> std::chrono::duration<double, std::milli>
    {
        t1_ready_promise.set_value();
        ready_future.wait(); // attend le signal de main()
        return std::chrono::high_resolution_clock::now() - start;
    };

    auto fun2 = [&, ready_future]() -> std::chrono::duration<double, std::milli>
    {
        t2_ready_promise.set_value();
        ready_future.wait(); // attend le signal de main()
        return std::chrono::high_resolution_clock::now() - start;
    };

    auto fut1 = t1_ready_promise.get_future();
    auto fut2 = t2_ready_promise.get_future();

    auto result1 = std::async(std::launch::async, fun1);
    auto result2 = std::async(std::launch::async, fun2);

    // attendre que les threads soient prêts
    fut1.wait();
    fut2.wait();

    // les threads sont prêts, démarrer le chronomètre
    start = std::chrono::high_resolution_clock::now();

    // signaler aux threads de démarrer
    ready_promise.set_value();

    std::cout << "Thread 1 received the signal "
              << result1.get().count() << " ms after start\n"
              << "Thread 2 received the signal "
              << result2.get().count() << " ms after start\n";
}

Sortie possible :

Thread 1 received the signal 0.072 ms after start
Thread 2 received the signal 0.041 ms after start
