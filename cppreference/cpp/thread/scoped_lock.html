std::scoped_lock

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <mutex>

template< class... MutexTypes >
class scoped_lock;  // (depuis C++17)

La classe scoped_lock est un wrapper de mutex qui fournit un mécanisme pratique de style RAII pour posséder zéro ou plusieurs mutex pendant la durée d'un bloc délimité.

Lorsqu'un objet scoped_lock est créé, il tente de prendre la propriété des mutex qui lui sont donnés. Lorsque le contrôle quitte la portée dans laquelle l'objet scoped_lock a été créé, le scoped_lock est détruit et les mutex sont libérés. Si plusieurs mutex sont donnés, un algorithme d'évitement d'interblocage est utilisé comme par std::lock.

La classe scoped_lock n'est pas copiable.

Paramètres de modèle

  • MutexTypes — les types des mutex à verrouiller. Les types doivent satisfaire aux exigences Lockable sauf si sizeof...(MutexTypes) == 1, auquel cas le seul type doit satisfaire BasicLockable

Types membres

Type membre Définition

  • mutex_type
    (présent sous condition)     —

    Si sizeof...(MutexTypes) == 1, le type membre mutex_type est identique à Mutex, le seul type de MutexTypes.... Sinon, il n'existe aucun membre mutex_type.

Fonctions membres

  • (constructeur) — construit un scoped_lock, en verrouillant éventuellement les mutex donnés (fonction membre publique)
  • (destructeur) — détruit l'objet scoped_lock, déverrouille les mutex sous-jacents (fonction membre publique)
  • operator=[deleted] — non copiable par affectation (fonction membre publique)

Notes

Une erreur courante chez les débutants consiste à « oublier » de donner un nom à une variable scoped_lock, par exemple std::scoped_lock(mtx); (qui construit par défaut un objet scoped_lock nommé mtx) ou std::scoped_lock{mtx}; (qui construit un objet prvalue immédiatement détruit), ce qui fait qu'aucun verrou détenant un mutex n'est réellement construit pour le reste de la portée.

Exemple

L'exemple suivant utilise std::scoped_lock pour verrouiller des paires de mutex sans interblocage, de manière RAII.

#include <chrono>
#include <functional>
#include <iostream>
#include <mutex>
#include <string>
#include <thread>
#include <vector>
using namespace std::chrono_literals;

struct Employee
{
    std::vector<std::string> lunch_partners;
    std::string id;
    std::mutex m;
    Employee(std::string id) : id(id) {}
    std::string partners() const
    {
        std::string ret = "Employee " + id + " has lunch partners: ";
        for (int count{}; const auto& partner : lunch_partners)
            ret += (count++ ? ", " : "") + partner;
        return ret;
    }
};

void send_mail(Employee&, Employee&)
{
    // Simule une opération de messagerie longue
    std::this_thread::sleep_for(1s);
}

void assign_lunch_partner(Employee& e1, Employee& e2)
{
    static std::mutex io_mutex;
    {
        std::lock_guard<std::mutex> lk(io_mutex);
        std::cout << e1.id << " and " << e2.id << " are waiting for locks" << std::endl;
    }

    {
        // Utiliser std::scoped_lock pour acquérir deux verrous sans se soucier de
        // que d'autres appels à assign_lunch_partner ne nous bloquent
        // et il fournit aussi un mécanisme pratique de style RAII

        std::scoped_lock lock(e1.m, e2.m);

        // Code équivalent 1 (utilisant std::lock et std::lock_guard)
        // std::lock(e1.m, e2.m);
        // std::lock_guard<std::mutex> lk1(e1.m, std::adopt_lock);
        // std::lock_guard<std::mutex> lk2(e2.m, std::adopt_lock);

        // Code équivalent 2 (si des unique_locks sont nécessaires, par exemple pour les variables de condition)
        // std::unique_lock<std::mutex> lk1(e1.m, std::defer_lock);
        // std::unique_lock<std::mutex> lk2(e2.m, std::defer_lock);
        // std::lock(lk1, lk2);
        {
            std::lock_guard<std::mutex> lk(io_mutex);
            std::cout << e1.id << " and " << e2.id << " got locks" << std::endl;
        }
        e1.lunch_partners.push_back(e2.id);
        e2.lunch_partners.push_back(e1.id);
    }

    send_mail(e1, e2);
    send_mail(e2, e1);
}

int main()
{
    Employee alice("Alice"), bob("Bob"), christina("Christina"), dave("Dave");

    // Affecte en parallèle dans des threads car l'envoi des affectations de déjeuner aux utilisateurs
    // prend beaucoup de temps
    std::vector<std::thread> threads;
    threads.emplace_back(assign_lunch_partner, std::ref(alice), std::ref(bob));
    threads.emplace_back(assign_lunch_partner, std::ref(christina), std::ref(bob));
    threads.emplace_back(assign_lunch_partner, std::ref(christina), std::ref(alice));
    threads.emplace_back(assign_lunch_partner, std::ref(dave), std::ref(bob));

    for (auto& thread : threads)
        thread.join();
    std::cout << alice.partners() << '\n'  << bob.partners() << '\n'
              << christina.partners() << '\n' << dave.partners() << '\n';
}
