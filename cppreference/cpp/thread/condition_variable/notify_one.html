std::condition_variable::notify_one

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

void notify_one() noexcept;  // (depuis C++11)

Si des threads attendent sur *this, l'appel à notify_one débloque l'un des threads en attente.

Paramètres

(aucune)

Valeur de retour

(aucune)

Notes

Les effets de notify_one()/notify_all() et de chacune des trois parties atomiques de wait()/wait_for()/wait_until() (déverrouillage+attente, réveil et verrouillage) ont lieu selon un ordre total unique qui peut être vu comme l'ordre de modification d'une variable atomique : cet ordre est propre à cette variable de condition. Il est ainsi impossible à notify_one() de, par exemple, être retardé et de débloquer un thread qui a commencé à attendre juste après l'appel à notify_one().

Le thread qui notifie n'a pas besoin de détenir le verrou du même mutex que celui détenu par le ou les threads en attente ; en fait, le faire est une pessimisation, puisque le thread notifié se bloquerait immédiatement à nouveau, en attendant que le thread notifiant libère le verrou. Cependant, certaines implémentations (en particulier de nombreuses implémentations de pthreads) reconnaissent cette situation et évitent ce scénario « dépêche-toi d'attendre » en transférant le thread en attente de la file de la variable de condition directement vers la file du mutex lors de l'appel de notification, sans le réveiller.

Notifier en étant sous verrou peut néanmoins être nécessaire lorsqu'un ordonnancement précis des événements est requis, par exemple si le thread en attente quitte le programme lorsque la condition est satisfaite, entraînant la destruction de la variable de condition du thread notifiant. Un réveil fallacieux après le déverrouillage du mutex mais avant la notification entraînerait un appel de notify sur un objet détruit.

Exemple

#include <chrono>
#include <condition_variable>
#include <iostream>
#include <thread>
using namespace std::chrono_literals;

std::condition_variable cv;
std::mutex cv_m;
int i = 0;
bool done = false;

void waits()
{
    std::unique_lock<std::mutex> lk(cv_m);
    std::cout << "Waiting... \n";
    cv.wait(lk, []{ return i == 1; });
    std::cout << "...finished waiting; i == " << i << '\n';
    done = true;
}

void signals()
{
    std::this_thread::sleep_for(200ms);
    std::cout << "Notifying falsely...\n";
    cv.notify_one(); // le thread en attente est notifié avec i == 0.
                     // cv.wait se réveille, vérifie i, et retourne en attente

    std::unique_lock<std::mutex> lk(cv_m);
    i = 1;
    while (!done)
    {
        std::cout << "Notifying true change...\n";
        lk.unlock();
        cv.notify_one(); // le thread en attente est notifié avec i == 1, cv.wait retourne
        std::this_thread::sleep_for(300ms);
        lk.lock();
    }
}

int main()
{
    std::thread t1(waits), t2(signals);
    t1.join();
    t2.join();
}

Sortie possible :

Waiting...
Notifying falsely...
Notifying true change...
...finished waiting; i == 1
