Copie les éléments de l'intervalle [first,last) vers un autre intervalle commençant à d_first, en omettant les éléments qui satisfont des critères donnés.

  1. Ignore tous les éléments égaux à value (en utilisant operator==).

  2. Ignore tous les éléments pour lesquels le prédicat p renvoie true.

2,4) Identique à (1,3), mais exécuté selon policy.

Ces surcharges ne participent à la résolution de surcharge que si toutes les conditions suivantes sont satisfaites :

std::is_execution_policy_v<std::decay_t<ExecutionPolicy>> is true.

(jusqu'à C++20)

std::is_execution_policy_v<std::remove_cvref_t<ExecutionPolicy>> is true.

(depuis C++20)

Si [*d_first = *first est invalide (jusqu'à C++20) | *first n'est pas inscriptible vers d_first (depuis C++20)], le programme est mal formé.

Si les intervalles source et destination se chevauchent, le comportement est indéfini.

Paramètres

  • first, last — la plage des éléments à copier
  • d_first — le début de l'intervalle de destination
  • value — la valeur des éléments à ne pas copier
  • policy — la politique d'exécution à utiliser

Exigences sur les types

  • InputIt doit satisfaire aux exigences de LegacyInputIterator.
  • OutputIt doit satisfaire aux exigences de LegacyOutputIterator.
  • ForwardIt1, ForwardIt2 doit satisfaire aux exigences de LegacyForwardIterator.
  • UnaryPred doit satisfaire aux exigences de Predicate.

Valeur de retour

Itérateur vers l'élément suivant le dernier élément copié.

Complexité

Étant donné (\scriptsize N)N valant std::distance(first, last) :

1,2) Exactement (\scriptsize N)N comparaisons avec value en utilisant operator==.

3,4) Exactement (\scriptsize N)N applications du prédicat p.

Pour les surcharges avec un ExecutionPolicy, il peut y avoir un coût en performance si le value_type de ForwardIt1 n'est pas MoveConstructible.

Exceptions

Les surcharges avec un paramètre de modèle nommé ExecutionPolicy signalent les erreurs comme suit :

  • Si l'exécution d'une fonction invoquée dans le cadre de l'algorithme lève une exception et ExecutionPolicy est l'une des politiques standard, std::terminate est appelée. Pour toute autre ExecutionPolicy, le comportement est défini par l'implémentation.
  • Si l'algorithme échoue à allouer de la mémoire, std::bad_alloc est levée.

Implémentation possible

remove_copy (1)

template<class InputIt, class OutputIt,
         class T = typename std::iterator_traits<InputIt>::value_type>
constexpr OutputIt remove_copy(InputIt first, InputIt last,
                               OutputIt d_first, const T& value)
{
    for (; first != last; ++first)
        if (!(*first == value))
            *d_first++ = *first;
    return d_first;
}

remove_copy_if (3)

template<class InputIt, class OutputIt, class UnaryPred>
constexpr OutputIt remove_copy_if(InputIt first, InputIt last,
                                  OutputIt d_first, UnaryPred p)
{
    for (; first != last; ++first)
        if (!p(*first))
            *d_first++ = *first;
    return d_first;
}

Exemple

#include <algorithm>
#include <complex>
#include <iomanip>
#include <iostream>
#include <iterator>
#include <string>
#include <vector>

int main()
{
    // Supprime à la volée les caractères de hachage '#'.
    std::string str = "#Return #Value #Optimization";
    std::cout << "before: " << std::quoted(str) << '\n';

    std::cout << "after:  \"";
    std::remove_copy(str.begin(), str.end(),
                     std::ostream_iterator<char>(std::cout), '#');
    std::cout << "\"\n";

    // Supprime à la volée la valeur {1, 3}.
    std::vector<std::complex<double>> nums{{2, 2}, {1, 3}, {4, 8}, {1, 3}};
    std::remove_copy(nums.begin(), nums.end(),
                     std::ostream_iterator<std::complex<double>>(std::cout),
    #ifdef __cpp_lib_algorithm_default_value_type
                     {1, 3}); // T est déduit
    #else
                     std::complex<double>{1, 3});
    #endif
}

after:  "Return Value Optimization"
