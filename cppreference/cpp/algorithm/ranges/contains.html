  1. Algorithme fondé sur la recherche qui vérifie si un intervalle donné contient ou non une valeur, avec des paires itérateur-sentinelle.

  2. Identique à (1) mais utilise r comme intervalle source, comme si l'on utilisait ranges::begin(r) comme first et ranges::end(r) comme last.

  3. Algorithme fondé sur la recherche qui vérifie si un intervalle donné est ou non un sous-intervalle d'un autre intervalle, avec des paires itérateur-sentinelle.

  4. Identique à (3) mais utilise r1 comme premier intervalle source et r2 comme second intervalle source, comme si l'on utilisait ranges::begin(r1) comme first1, ranges::end(r1) comme last1, ranges::begin(r2) comme first2 et ranges::end(r2) comme last2.

Les entités de type fonction décrites sur cette page sont des objets fonctions d'algorithme (appelés de manière informelle niebloids), c'est-à-dire :

  • Les listes d'arguments de modèle explicites ne peuvent pas être spécifiées lors de l'appel de l'un d'entre eux.
  • Aucun d'entre eux n'est visible par la recherche dépendante des arguments.
  • Lorsque l'un d'entre eux est trouvé par la recherche non qualifiée normale comme nom situé à gauche de l'opérateur d'appel de fonction, la recherche dépendante des arguments est inhibée.

Paramètres

  • first, last — l'intervalle des éléments à examiner
  • r — l'intervalle des éléments à examiner
  • value — valeur à comparer aux éléments
  • pred — prédicat à appliquer aux éléments projetés
  • proj — projection à appliquer aux éléments

Valeur de retour

1,2) : ranges::find(std::move(first), last, value, proj) != last

3,4) : first2 == last2 || !ranges::search(first1, last1, first2, last2, pred, proj1, proj2).empty()

Complexité

Au plus last - first applications du prédicat et de la projection.

Notes

Jusqu'à C++20, il fallait écrire std::ranges::find(r, value) != std::ranges::end(r) pour déterminer si une valeur unique se trouve dans un intervalle. Et pour vérifier si un intervalle contient un sous-intervalle intéressant, on utilise not std::ranges::search(haystack, needle).empty(). Bien que cela soit exact, ce n'est pas forcément commode, et cela exprime difficilement l'intention (surtout dans le second cas). Pouvoir écrire std::ranges::contains(r, value) répond à ces deux points.

ranges::contains_subrange, identique à ranges::search, mais contrairement à std::search, ne donne pas accès à Searchers (tels que Boyer-Moore).

Implémentation possible

contains (1,2)

struct __contains_fn
{
    template<std::input_iterator I, std::sentinel_for<I> S,
             class Proj = std::identity,
             class T = std::projected_value_t<I, Proj>>
    requires std::indirect_binary_predicate<ranges::equal_to, std::projected<I, Proj>,
                                            const T*>
    constexpr bool operator()(I first, S last, const T& value, Proj proj = {}) const
    {
        return ranges::find(std::move(first), last, value, proj) != last;
    }

    template<ranges::input_range R,
             class Proj = std::identity,
             class T = std::projected_value_t<ranges::iterator_t<R>, Proj>>
    requires std::indirect_binary_predicate<ranges::equal_to,
                                            std::projected<ranges::iterator_t<R>, Proj>,
                                            const T*>
    constexpr bool operator()(R&& r, const T& value, Proj proj = {}) const
    {
        return (*this)(ranges::begin(r), ranges::end(r), std::move(value), proj);
    }
};

inline constexpr __contains_fn contains {};

contains_subrange (3,4)

struct __contains_subrange_fn
{
    template<std::forward_iterator I1, std::sentinel_for<I1> S1,
             std::forward_iterator I2, std::sentinel_for<I2> S2,
             class Pred = ranges::equal_to,
             class Proj1 = std::identity, class Proj2 = std::identity>
    requires std::indirectly_comparable<I1, I2, Pred, Proj1, Proj2>
    constexpr bool operator()(I1 first1, S1 last1,
                              I2 first2, S2 last2,
                              Pred pred = {},
                              Proj1 proj1 = {}, Proj2 proj2 = {}) const
    {
        return (first2 == last2) ||
               !ranges::search(first1, last1, first2, last2, pred, proj1, proj2).empty();
    }

    template<ranges::forward_range R1, ranges::forward_range R2,
             class Pred = ranges::equal_to,
             class Proj1 = std::identity, class Proj2 = std::identity>
    requires std::indirectly_comparable<ranges::iterator_t<R1>,
                                        ranges::iterator_t<R2>, Pred, Proj1, Proj2>
    constexpr bool operator()(R1&& r1, R2&& r2,
                              Pred pred = {},
                              Proj1 proj1 = {}, Proj2 proj2 = {}) const
    {
        return (*this)(ranges::begin(r1), ranges::end(r1),
                       ranges::begin(r2), ranges::end(r2), std::move(pred),
                       std::move(proj1), std::move(proj2));
    }
};

inline constexpr __contains_subrange_fn contains_subrange {};

Exemple

#include <algorithm>
#include <array>
#include <complex>

namespace ranges = std::ranges;

int main()
{
    constexpr auto haystack = std::array{3, 1, 4, 1, 5};
    constexpr auto needle = std::array{1, 4, 1};
    constexpr auto bodkin = std::array{2, 5, 2};

    static_assert(
        ranges::contains(haystack, 4) &&
       !ranges::contains(haystack, 6) &&
        ranges::contains_subrange(haystack, needle) &&
       !ranges::contains_subrange(haystack, bodkin)
    );

    constexpr std::array<std::complex<double>, 3> nums{{{1, 2}, {3, 4}, {5, 6}}};
    #ifdef __cpp_lib_algorithm_default_value_type
        static_assert(ranges::contains(nums, {3, 4}));
    #else
        static_assert(ranges::contains(nums, std::complex<double>{3, 4}));
    #endif
}
