Types auxiliaires

template< class I, class O >
using move_backward_result = ranges::in_out_result<I, O>;  // (3) (depuis C++20)

  1. Déplace les éléments de l'intervalle défini par [first,last) vers une autre plage [result - N,result), où N = ranges::distance(first, last). Les éléments sont déplacés dans l'ordre inverse (le dernier élément est déplacé en premier), mais leur ordre relatif est préservé. Le comportement est indéfini si result se trouve dans (first, last]. Dans ce cas, ranges::move peut être utilisé à la place.

  2. Identique à (1), mais utilise r comme intervalle source, comme si l'on utilisait ranges::begin(r) comme first, et ranges::end(r) comme last.

Les éléments de l'intervalle déplacé contiendront toujours des valeurs valides du type approprié, mais pas nécessairement les mêmes valeurs qu'avant le déplacement, comme si on utilisait *(result - n) = ranges::iter_move(last - n) pour chaque entier n, où 0 ≤ n < N.

Les entités de type fonction décrites sur cette page sont des objets fonctions d'algorithme (appelés de manière informelle niebloids), c'est-à-dire :

  • Les listes d'arguments de modèle explicites ne peuvent pas être spécifiées lors de l'appel de l'un d'entre eux.
  • Aucun d'entre eux n'est visible par la recherche dépendante des arguments.
  • Lorsque l'un d'entre eux est trouvé par la recherche non qualifiée normale comme nom situé à gauche de l'opérateur d'appel de fonction, la recherche dépendante des arguments est inhibée.

Paramètres

  • first — le début de la plage des éléments à déplacer
  • last — la fin de la plage des éléments à déplacer
  • r — l'intervalle des éléments à déplacer
  • result — la fin de la plage de destination

Valeur de retour

{last, result - N}.

Complexité

  1. Exactement N affectations par déplacement.

  2. Exactement ranges::distance(r) affectations par déplacement.

Notes

Lors du déplacement d'intervalles qui se chevauchent, ranges::move convient lorsqu'on déplace vers la gauche (le début de l'intervalle de destination est en dehors de l'intervalle source), tandis que ranges::move_backward convient lorsqu'on déplace vers la droite (la fin de l'intervalle de destination est en dehors de l'intervalle source).

Implémentation possible

struct move_backward_fn
{
    template<std::bidirectional_iterator I1, std::sentinel_for<I1> S1,
             std::bidirectional_iterator I2>
    requires std::indirectly_movable<I1, I2>
    constexpr ranges::move_backward_result<I1, I2>
        operator()(I1 first, S1 last, I2 result) const
    {
        auto i {last};
        for (; i != first; *--result = ranges::iter_move(--i))
        {}
        return {std::move(last), std::move(result)};
    }

    template<ranges::bidirectional_range R, std::bidirectional_iterator I>
    requires std::indirectly_movable<ranges::iterator_t<R>, I>
    constexpr ranges::move_backward_result<ranges::borrowed_iterator_t<R>, I>
        operator()(R&& r, I result) const
    {
        return (*this)(ranges::begin(r), ranges::end(r), std::move(result));
    }
};

inline constexpr move_backward_fn move_backward {};

Exemple

#include <algorithm>
#include <iostream>
#include <string>
#include <string_view>
#include <vector>

using Vec = std::vector<std::string>;

void print(std::string_view rem, Vec const& vec)
{
    std::cout << rem << "[" << vec.size() << "]: ";
    for (const std::string& s : vec)
        std::cout << (s.size() ? s : std::string{"·"}) << ' ';
    std::cout << '\n';
}

int main()
{
    Vec a{"▁", "▂", "▃", "▄", "▅", "▆", "▇", "█"};
    Vec b(a.size());

    print("Before move:\n" "a", a);
    print("b", b);

    std::ranges::move_backward(a, b.end());

    print("\n" "Move a >> b:\n" "a", a);
    print("b", b);

    std::ranges::move_backward(b.begin(), b.end(), a.end());
    print("\n" "Move b >> a:\n" "a", a);
    print("b", b);

    std::ranges::move_backward(a.begin(), a.begin()+3, a.end());
    print("\n" "Overlapping move a[0, 3) >> a[5, 8):\n" "a", a);
}
