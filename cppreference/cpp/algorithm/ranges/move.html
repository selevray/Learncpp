std::ranges::move, std::ranges::move_result

Signature d'appel

template< std::input_iterator I, std::sentinel_for<I> S, std::weakly_incrementable O >
requires std::indirectly_movable<I, O>
constexpr move_result<I, O>
    move( I first, S last, O result );  // (1) (depuis C++20)

template< ranges::input_range R, std::weakly_incrementable O >
requires std::indirectly_movable<ranges::iterator_t<R>, O>
constexpr move_result<ranges::borrowed_iterator_t<R>, O>
    move( R&& r, O result );  // (2) (depuis C++20)

Types auxiliaires

template< class I, class O >
using move_result = ranges::in_out_result<I, O>;  // (3) (depuis C++20)

  1. Déplace les éléments de l'intervalle défini par [first,last) vers une autre plage commençant à result. Le comportement est indéfini si result se trouve dans l'intervalle [first,last). Dans ce cas, ranges::move_backward peut être utilisé à la place.

  2. Identique à (1), mais utilise r comme intervalle source, comme si l'on utilisait ranges::begin(r) comme first, et ranges::end(r) comme last.

Les éléments de l'intervalle déplacé contiendront toujours des valeurs valides du type approprié, mais pas nécessairement les mêmes valeurs qu'avant le déplacement.

Les entités de type fonction décrites sur cette page sont des objets fonctions d'algorithme (appelés de manière informelle niebloids), c'est-à-dire :

  • Les listes d'arguments de modèle explicites ne peuvent pas être spécifiées lors de l'appel de l'un d'entre eux.
  • Aucun d'entre eux n'est visible par la recherche dépendante des arguments.
  • Lorsque l'un d'entre eux est trouvé par la recherche non qualifiée normale comme nom situé à gauche de l'opérateur d'appel de fonction, la recherche dépendante des arguments est inhibée.

Paramètres

  • first — le début de la plage des éléments à déplacer
  • last — la fin de la plage des éléments à déplacer
  • r — l'intervalle des éléments à déplacer
  • result — le début de l'intervalle de destination

Valeur de retour

{last, result + N}, où

  1. N = ranges::distance(first, last).

  2. N = ranges::distance(r).

Complexité

Exactement N affectations par déplacement.

Notes

Lors du déplacement d'intervalles qui se chevauchent, ranges::move convient lorsqu'on déplace vers la gauche (le début de l'intervalle de destination est en dehors de l'intervalle source), tandis que ranges::move_backward convient lorsqu'on déplace vers la droite (la fin de l'intervalle de destination est en dehors de l'intervalle source).

Implémentation possible

struct move_fn
{
    template<std::input_iterator I, std::sentinel_for<I> S, std::weakly_incrementable O>
    requires std::indirectly_movable<I, O>
    constexpr ranges::move_result<I, O>
        operator()(I first, S last, O result) const
    {
        for (; first != last; ++first, ++result)
            *result = ranges::iter_move(first);
        return {std::move(first), std::move(result)};
    }
    template<ranges::input_range R, std::weakly_incrementable O>
    requires std::indirectly_movable<ranges::iterator_t<R>, O>
    constexpr ranges::move_result<ranges::borrowed_iterator_t<R>, O>
        operator()(R&& r, O result) const
    {
        return (*this)(ranges::begin(r), ranges::end(r), std::move(result));
    }
};

inline constexpr move_fn move {};

Exemple

Le code suivant déplace des objets thread (qui sont eux-mêmes non copiables) d'un conteneur vers un autre.

#include <algorithm>
#include <chrono>
#include <iostream>
#include <iterator>
#include <list>
#include <thread>
#include <vector>
using namespace std::literals::chrono_literals;

void f(std::chrono::milliseconds n)
{
    std::this_thread::sleep_for(n);
    std::cout << "thread with n=" << n.count() << "ms ended" << std::endl;
}

int main()
{
    std::vector<std::jthread> v;
    v.emplace_back(f, 400ms);
    v.emplace_back(f, 600ms);
    v.emplace_back(f, 800ms);

    std::list<std::jthread> l;

    // std::ranges::copy() ne compilerait pas, car std::jthread est non copiable
    std::ranges::move(v, std::back_inserter(l));
}

Output:

thread with n=400ms ended
thread with n=600ms ended
thread with n=800ms ended
