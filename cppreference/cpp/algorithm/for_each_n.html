std::for_each_n

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <algorithm>

template< class InputIt, class Size, class UnaryFunc >
InputIt for_each_n( InputIt first, Size n, UnaryFunc f );  // (1) (depuis C++17) (constexpr depuis C++20)

template< class ExecutionPolicy,
          class ForwardIt, class Size, class UnaryFunc >
ForwardIt for_each_n( ExecutionPolicy&& policy,
                      ForwardIt first, Size n, UnaryFunc f );  // (2) (depuis C++17)

Applique l'objet fonction donné f au résultat de la déréférence de chaque itérateur de l'intervalle [first,first + n). Si f renvoie un résultat, ce résultat est ignoré.

  1. f est appliqué dans l'ordre à partir de first.

Si UnaryFunc n'est pas MoveConstructible, le comportement est indéfini.

  1. f peut ne pas être appliqué dans l'ordre. L'algorithme est exécuté selon policy.

Cette surcharge ne participe à la résolution de surcharge que si toutes les conditions suivantes sont satisfaites :

std::is_execution_policy_v<std::decay_t<ExecutionPolicy>> is true.

(jusqu'à C++20)

std::is_execution_policy_v<std::remove_cvref_t<ExecutionPolicy>> is true.

(depuis C++20)

Si UnaryFunc n'est pas CopyConstructible, le comportement est indéfini.

Si n >= 0 n'est pas true, le comportement est indéfini.

Si le type d'itérateur (InputIt/ForwardIt) est modifiable, f peut modifier les éléments de l'intervalle via l'itérateur déréférencé.

Contrairement aux autres algorithmes parallèles, for_each_n ne peut pas faire de copies des éléments de la séquence même s'ils sont TriviallyCopyable.

Paramètres

  • first — le début de l'intervalle auquel appliquer la fonction

  • n — le nombre d'éléments auxquels appliquer la fonction

  • policy — la politique d'exécution à utiliser

  • f — objet fonction, à appliquer au résultat de la déréférence de chaque itérateur de l'intervalle [first,first + n)

    La signature de la fonction doit être équivalente à la suivante :

    void fun(const Type &a);

    La signature n'a pas besoin de posséder const &.
    Le type Type doit être tel qu'un objet de type InputIt puisse être déréférencé puis implicitement converti en Type.

Exigences sur les types

  • InputIt doit satisfaire aux exigences de LegacyInputIterator.
  • ForwardIt doit satisfaire aux exigences de LegacyForwardIterator.
  • Size doit être convertible en un type entier.

Valeur de retour

Un itérateur égal à first + n, ou plus formellement, à std::advance(first, n).

Complexité

Exactement n applications de f.

Exceptions

La surcharge avec un paramètre de modèle nommé ExecutionPolicy signale les erreurs comme suit :

  • Si l'exécution d'une fonction invoquée dans le cadre de l'algorithme lève une exception et ExecutionPolicy est l'une des politiques standard, std::terminate est appelée. Pour toute autre ExecutionPolicy, le comportement est défini par l'implémentation.
  • Si l'algorithme échoue à allouer de la mémoire, std::bad_alloc est levée.

Implémentation possible

Voir aussi l'implémentation dans libstdc++, libc++ et MSVC stdlib.

template<class InputIt, class Size, class UnaryFunc>
InputIt for_each_n(InputIt first, Size n, UnaryFunc f)
{
    for (Size i = 0; i < n; ++first, (void) ++i)
        f(*first);

    return first;
}

Exemple

#include <algorithm>
#include <iostream>
#include <vector>

void println(auto const& v)
{
    for (auto count{v.size()}; const auto& e : v)
        std::cout << e << (--count ? ", " : "\n");
}

int main()
{
    std::vector<int> vi{1, 2, 3, 4, 5};
    println(vi);

    std::for_each_n(vi.begin(), 3, [](auto& n) { n *= 2; });
    println(vi);
}

Output:

1, 2, 3, 4, 5
2, 4, 6, 4, 5
