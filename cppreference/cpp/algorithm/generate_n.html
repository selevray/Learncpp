std::generate_n

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <algorithm>

template< class OutputIt, class Size, class Generator >
OutputIt generate_n( OutputIt first, Size count, Generator g );  // (1) (constexpr depuis C++20)

template< class ExecutionPolicy,
          class ForwardIt, class Size, class Generator >
ForwardIt generate_n( ExecutionPolicy&& policy,
                      ForwardIt first, Size count, Generator g );  // (2) (depuis C++17)

  1. Affecte des valeurs, générées par l'objet fonction donné g, aux count premiers éléments de l'intervalle commençant à first, si count > 0. Ne fait rien sinon.

  2. Identique à (1), mais exécuté selon policy.

Cette surcharge ne participe à la résolution de surcharge que si toutes les conditions suivantes sont satisfaites :

std::is_execution_policy_v<std::decay_t<ExecutionPolicy>> is true.

(jusqu'à C++20)

std::is_execution_policy_v<std::remove_cvref_t<ExecutionPolicy>> is true.

(depuis C++20)

Si Size n'est pas convertible en type entier, le programme est mal formé.

Paramètres

  • first — le début de l'intervalle d'éléments à générer

  • count — nombre d'éléments à générer

  • policy — la politique d'exécution à utiliser

  • g — objet fonction générateur qui sera appelé.

    La signature de la fonction doit être équivalente à la suivante :

    Ret fun();

    Le type Ret doit être tel qu'un objet de type OutputIt puisse être déréférencé et qu'on puisse lui affecter une valeur de type Ret.

Exigences sur les types

  • OutputIt doit satisfaire aux exigences de LegacyOutputIterator.
  • ForwardIt doit satisfaire aux exigences de LegacyForwardIterator.

Valeur de retour

Itérateur pointant juste après le dernier élément affecté si count > 0, first sinon.

Complexité

Exactement std::max(0, count) invocations de g() et affectations.

Exceptions

La surcharge avec un paramètre de modèle nommé ExecutionPolicy signale les erreurs comme suit :

  • Si l'exécution d'une fonction invoquée dans le cadre de l'algorithme lève une exception et ExecutionPolicy est l'une des politiques standard, std::terminate est appelée. Pour toute autre ExecutionPolicy, le comportement est défini par l'implémentation.
  • Si l'algorithme échoue à allouer de la mémoire, std::bad_alloc est levée.

Implémentation possible

template<class OutputIt, class Size, class Generator>
constexpr // depuis C++20
OutputIt generate_n(OutputIt first, Size count, Generator g)
{
    for (Size i = 0; i < count; ++i, ++first)
        *first = g();

    return first;
}

Exemple

#include <algorithm>
#include <functional>
#include <iostream>
#include <iterator>
#include <random>

int main()
{
    std::mt19937 rng; // construit par défaut, initialisé avec une graine fixe
    std::generate_n(std::ostream_iterator<std::mt19937::result_type>(std::cout, " "),
                    5, std::ref(rng));
    std::cout << '\n';
}

Output:

3499211612 581869302 3890346734 3586334585 545404204

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 426 C++98 l'exigence de complexité était « exactement count invocations ou affectations », qui est violée si count est négatif aucune invocation ni affectation si count est non positif
LWG 865 C++98 l'emplacement du premier élément suivant l'intervalle de génération n'était pas renvoyé returned
