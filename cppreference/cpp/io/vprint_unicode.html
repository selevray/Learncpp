void vprint_unicode( std::FILE* stream,
                     std::string_view fmt, std::format_args args );  // (1) (depuis C++23)

void vprint_unicode_buffered( std::FILE* stream,
                              std::string_view fmt, std::format_args args );  // (2) (depuis C++23)

void vprint_unicode_buffered( std::string_view fmt, std::format_args args );  // (3) (depuis C++23)

Formate args selon la chaîne de format fmt, et écrit le résultat dans le flux de sortie.

  1. Effectue les opérations suivantes dans l'ordre :
  1. Verrouille stream.
  2. Soit out la représentation sous forme de caractères des arguments de formatage fournis par args, formatés selon les spécifications données dans fmt.
  3. Écrit out dans stream :
    • Si stream désigne un terminal capable d'afficher de l'Unicode uniquement via une API Unicode native, vide stream et écrit out sur le terminal à l'aide de l'API Unicode native.
    • Sinon, écrit out non modifié dans stream.

Déverrouille inconditionnellement stream à la sortie de la fonction.

Si l'une des conditions suivantes est satisfaite, le comportement est indéfini :

  • stream n'est pas un pointeur valide vers un flux C de sortie.
  • out contient des unités de code Unicode invalides lorsque l'API Unicode native est utilisée.

  1. Équivalent à std::string out = std::vformat(fmt, args);std::vprint_unicode(stream, "{}", std::make_format_args(out));.

  2. Équivalent à std::vprint_unicode_buffered(stdout, fmt, args).

Paramètres

  • stream — flux de fichier de sortie dans lequel écrire

  • fmt — un objet représentant la chaîne de format. La chaîne de format est composée de

    • caractères ordinaires (sauf { et }), qui sont recopiés sans modification dans la sortie,
    • séquences d'échappement {{ et }}, qui sont remplacées respectivement par { et } dans la sortie, et
    • champs de remplacement.

    Chaque champ de remplacement a le format suivant :

    { arg-id (facultatif) } | (1)

    { arg-id (facultatif) : format-spec } | (2)

    1. champ de remplacement sans spécification de format

    2. champ de remplacement avec une spécification de format

    • arg-id — spécifie l'indice de l'argument dans args dont la valeur doit être utilisée pour le formatage ; s'il est omis, les arguments sont utilisés dans l'ordre.

      Les arg-id ﻿s dans une chaîne de format doivent tous être présents ou tous être omis. Mélanger l'indexation manuelle et automatique est une erreur.

    • format-spec — la spécification de format définie par la spécialisation std::formatter pour l'argument correspondant. Ne peut pas commencer par }.

    • Pour les types de base et les types de chaînes standard, la spécification de format est interprétée comme spécification de format standard.

    • Pour les types chrono, la spécification de format est interprétée comme spécification de format chrono.

    • Pour les types d'intervalles, la spécification de format est interprétée comme spécification de format d'intervalle.
    • Pour std::pair et std::tuple, la spécification de format est interprétée comme spécification de format de tuple.
    • Pour std::thread::id et std::stacktrace_entry, voir spécification de format de thread id et spécification de format d'entrée de stacktrace.
    • Pour std::basic_stacktrace, aucun spécificateur de format n'est autorisé.

    (depuis C++23)

    • Pour std::filesystem::path, voir spécification de format de chemin.

    (depuis C++26)

    • Pour les autres types formatables, la spécification de format est déterminée par les spécialisations formatter définies par l'utilisateur.

  • args — arguments à formater

Exceptions

  • std::bad_alloc en cas d'échec d'allocation.
  • std::system_error, si l'écriture dans le flux échoue.
  • Propage toute exception levée par les formateurs utilisés, par exemple std::format_error.

Notes

La norme C++ encourage les implémenteurs à produire un message de diagnostic si out contient des unités de code Unicode invalides.

Sous POSIX, l'écriture dans un terminal se fait à l'aide des fonctions d'E/S standard habituelles ; il n'est donc pas nécessaire de traiter un terminal différemment de tout autre flux de fichier.

Sous Windows, le flux désigne un terminal si GetConsoleMode(_get_osfhandle(_fileno(stream))) renvoie une valeur non nulle (voir la documentation Windows pour GetConsoleMode, _get_osfhandle et _fileno). L'API Unicode native sous Windows est WriteConsoleW.

Si l'appel de l'API Unicode native nécessite une transcodage, les unités de code invalides sont remplacées par U+FFFD le caractère de remplacement REPLACEMENT CHARACTER (voir « The Unicode Standard - Core Specification », chapitre 3.9).
