std::ios_base::failure

class failure;

La classe std::ios_base::failure définit un objet d'exception qui est levé en cas d'échec par les fonctions de la bibliothèque d'entrées/sorties.

std::ios_base::failure peut être défini soit comme classe membre de std::ios_base, soit comme synonyme (typedef) d'une autre classe ayant des fonctionnalités équivalentes.

  1. Constructeur de copie. Initialise le contenu avec celui de other. Si *this et other ont tous deux le type dynamique std::ios_base::failure, alors std::strcmp(what(), other.what()) == 0. (depuis C++11)

Paramètres

  • message — chaîne explicative
  • ec — code d'erreur permettant d'identifier la raison précise de l'échec
  • other — un autre failure à copier

Notes

Comme la copie de std::ios_base::failure n'est pas autorisée à lever d'exceptions, ce message est généralement stocké en interne sous forme de chaîne à comptage de références allouée séparément. C'est aussi pour cette raison qu'il n'existe aucun constructeur acceptant std::string&& : il devrait de toute façon copier le contenu.

std::ios_base::failure::what

virtual const char* what() const throw();  // (jusqu'à C++11)

virtual const char* what() const noexcept;  // (depuis C++11)

Renvoie la chaîne explicative.

Valeur de retour

Pointeur vers une chaîne terminée par un caractère nul, définie par l'implémentation, contenant des informations explicatives. La chaîne convient à une conversion et à un affichage en tant que std::wstring. Le pointeur est garanti valide au moins jusqu'à la destruction de l'objet d'exception dont il est obtenu, ou jusqu'à l'appel d'une fonction membre non const (par ex. l'opérateur d'affectation par copie) sur cet objet d'exception.

La chaîne renvoyée est encodée avec le codage ordinaire des littéraux lors de l'évaluation constante.

(depuis C++26)

Notes

Avant la résolution de LWG issue 331, std::ios_base::failure déclarait un destructeur sans throw(), où std::exception::~exception() était déclaré avec throw()[1]. Cela signifie que le std::ios_base::failure::~failure() avait une spécification d'exception plus faible. La résolution consiste à supprimer cette déclaration afin de conserver la spécification d'exception non levante.

LWG issue 363 vise le même défaut et sa résolution consiste à ajouter throw() à la déclaration de std::ios_base::failure::~failure(). Cette résolution n'a pas été appliquée en raison du conflit entre les deux résolutions.

  1. ↑ La spécification d'exception non levante est désormais appliquée à l'ensemble de la bibliothèque standard, de sorte que les destructeurs des classes de la bibliothèque standard ne sont pas déclarés avec throw() ni noexcept.

Exemple

#include <fstream>
#include <iostream>

int main()
{
    std::ifstream f("doesn't exist");

    try
    {
        f.exceptions(f.failbit);
    }
    catch (const std::ios_base::failure& e)
    {
        std::cout << "Caught an ios_base::failure.\n"
                  << "Explanatory string: " << e.what() << '\n'
                  << "Error code: " << e.code() << '\n';
    }
}

Sortie possible :

Caught an ios_base::failure.
Explanatory string: ios_base::clear: unspecified iostream_category error
Error code: iostream:1
