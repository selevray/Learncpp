assert

Défini dans l'en-tête <cassert>

Assertion désactivée

#define assert(condition) ((void)0)  // (jusqu'à C++26)

#define assert(...)       ((void)0)  // (depuis C++26)

Assertion activée

#define assert(condition) /* unspecified */  // (jusqu'à C++26)

#define assert(...)       /* unspecified */  // (depuis C++26)

La définition de la macro assert dépend d'une autre macro, NDEBUG, qui n'est pas définie par la bibliothèque standard.

  1. Si NDEBUG est défini comme nom de macro à l'endroit du code source où <cassert> ou <assert.h> est inclus, l'assertion est désactivée : assert ne fait rien.

  2. Sinon, l'assertion est activée :

assert vérifie son argument (qui doit être de type scalaire) :

  • Si l'argument est différent de zéro, il n'y a pas d'autre effet.
  • Sinon, assert crée un diagnostic sur le flux d'erreur standard et appelle std::abort().

(jusqu'à C++26)

assert insère un test de diagnostic dans les programmes et se développe en une expression de type void. __VA_ARGS__ est évaluée et convertie contextuellement en bool :

  • Si l'évaluation donne true, il n'y a pas d'autre effet.
  • Sinon, assert crée un diagnostic sur le flux d'erreur standard et appelle std::abort().

(depuis C++26)

Les informations de diagnostic ont un format défini par l'implémentation, mais incluent toujours les informations suivantes :

  • le texte de condition

(jusqu'à C++26)

  • #__VA_ARGS__

(depuis C++26)

  • le nom du fichier source (c.-à-d. __FILE__)
  • le numéro de ligne dans le source (c.-à-d. __LINE__)
  • le nom de la fonction englobante (c.-à-d. __func__)

L'expression assert(E) est garantie d'être une sous-expression constante, si l'une des conditions suivantes est vraie :

  • NDEBUG est défini au point où assert est défini ou redéfini en dernier, ou
  • E, converti contextuellement en bool, est une sous-expression constante qui s'évalue à true.

(depuis C++11)

Paramètres

  • condition — expression de type scalaire

Notes

Comme assert est une macro de type fonction, les virgules présentes dans l'argument qui ne sont pas protégées par des parenthèses sont interprétées comme des séparateurs d'arguments de macro. De telles virgules se trouvent souvent dans les listes d'arguments de modèle et l'initialisation par liste :

assert(std::is_same_v<int, int>);        // erreur : assert n'accepte pas deux arguments
assert((std::is_same_v<int, int>));      // OK : un argument
static_assert(std::is_same_v<int, int>); // OK : pas une macro

std::complex<double> c;
assert(c == std::complex<double>{0, 0});   // error
assert((c == std::complex<double>{0, 0})); // OK

(jusqu'à C++26)

Il n'existe pas d'interface standardisée pour ajouter un message supplémentaire aux erreurs de assert. Une manière portable de l'inclure consiste à utiliser un opérateur virgule à condition qu'il n'ait pas été surchargé, ou à utiliser && avec un littéral chaîne :

assert(("There are five lights", 2 + 2 == 5));
assert(2 + 2 == 5 && "There are five lights");

L'implémentation de assert dans la CRT Microsoft n'est pas conforme à C++11 et aux révisions ultérieures, car sa fonction sous-jacente (_wassert) ne prend ni __func__ ni un équivalent de remplacement.

Depuis C++20, les valeurs nécessaires au message de diagnostic peuvent aussi être obtenues depuis std::source_location::current().

Même si le changement de assert en C23/C++26 n'est pas formellement un rapport de défaut, le comité C recommande aux implémentations de le rétroporter dans les anciens modes.

Exemple

#include <iostream>
// décommenter pour désactiver assert()
// #define NDEBUG
#include <cassert>

// Utiliser (void) pour faire taire les avertissements de variable inutilisée.
#define assertm(exp, msg) assert((void(msg), exp))

int main()
{
    assert(2 + 2 == 4);
    std::cout << "Checkpoint #1\n";

    assert((void("void helps to avoid 'unused value' warning"), 2 * 2 == 4));
    std::cout << "Checkpoint #2\n";

    assert((010 + 010 == 16) && "Yet another way to add an assert message");
    std::cout << "Checkpoint #3\n";

    assertm((2 + 2) % 3 == 1, "Success");
    std::cout << "Checkpoint #4\n";

    assertm(2 + 2 == 5, "Failed"); // l'assertion échoue
    std::cout << "Execution continues past the last assert\n"; // Aucune sortie
}

Sortie possible :

Checkpoint #1
Checkpoint #2
Checkpoint #3
Checkpoint #4
main.cpp:23: int main(): Assertion `((void)"Failed", 2 + 2 == 5)' failed.
Aborted
