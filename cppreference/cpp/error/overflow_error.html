std::overflow_error

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <stdexcept>

class overflow_error;

Définit un type d'objet à lever comme exception. Il peut servir à signaler des erreurs de dépassement arithmétique (c'est-à-dire des situations où le résultat d'un calcul est trop grand pour le type de destination).

Le seul composant de la bibliothèque standard qui lève cette exception est std::bitset::to_ulong.

(jusqu'à C++11)

Les seuls composants de la bibliothèque standard qui lèvent cette exception sont std::bitset::to_ulong et std::bitset::to_ullong.

(depuis C++11)

Les fonctions mathématiques des composants de la bibliothèque standard ne lèvent pas cette exception (les fonctions mathématiques signalent les erreurs de dépassement comme spécifié dans math_errhandling). Les bibliothèques tierces, en revanche, l'utilisent. Par exemple, boost.math lève std::overflow_error si boost::math::policies::throw_on_error est activé (paramètre par défaut).

  1. Construit l'objet exception avec what_arg comme chaîne explicative. Après la construction, std::strcmp(what(), what_arg.c_str()) == 0.

  2. Construit l'objet exception avec what_arg comme chaîne explicative. Après la construction, std::strcmp(what(), what_arg) == 0.

  3. Constructeur de copie. Si *this et other ont tous deux pour type dynamique std::overflow_error, alors std::strcmp(what(), other.what()) == 0. Aucune exception ne peut être levée par le constructeur de copie.

Paramètres

  • what_arg — chaîne explicative
  • other — un autre objet exception à copier

Exceptions

1,2) Peut lever std::bad_alloc.

Notes

Comme la copie de std::overflow_error n'est pas autorisée à lever d'exceptions, ce message est généralement stocké en interne sous forme de chaîne à comptage de références allouée séparément. C'est aussi pour cette raison qu'il n'existe aucun constructeur acceptant std::string&& : il devrait de toute façon copier le contenu.

Avant la résolution du LWG issue 254, le constructeur autre que de copie ne pouvait accepter que std::string. Il rendait l'allocation dynamique obligatoire pour construire un objet std::string.

Après la résolution du LWG issue 471, une classe d'exception standard dérivée doit disposer d'un constructeur de copie accessible publiquement. Il peut être défini implicitement tant que les chaînes explicatives obtenues par what() sont identiques pour l'objet original et l'objet copié.

Exemple

#include <iostream>
#include <limits>
#include <stdexcept>
#include <utility>

template<typename T, int N>
    requires (N > 0) /*...*/
class Stack
{
    int top_{-1};
    T data_[N];

public:
    [[nodiscard]] bool empty() const { return top_ == -1; }

    void push(T x)
    {
        if (top_ == N - 1)
            throw std::overflow_error("Stack overflow!");
        data_[++top_] = std::move(x);
    }

    void pop()
    {
        if (empty())
            throw std::underflow_error("Stack underflow!");
        --top_;
    }

    T const& top() const
    {
        if (empty())
            throw std::overflow_error("Stack is empty!");
        return data_[top_];
    }
};

int main()
{
    Stack<int, 4> st;

    try
    {
        [[maybe_unused]] auto x = st.top();
    }
    catch (std::overflow_error const& ex)
    {
        std::cout << "1) Exception: " << ex.what() << '\n';
    }

    st.push(1337);
    while (!st.empty())
    	st.pop();

    try
    {
        st.pop();
    }
    catch (std::underflow_error const& ex)
    {
        std::cout << "2) Exception: " << ex.what() << '\n';
    }

    try
    {
        for (int i{}; i != 13; ++i)
            st.push(i);
    }
    catch (std::overflow_error const& ex)
    {
        std::cout << "3) Exception: " << ex.what() << '\n';
    }
}

Output:

1) Exception: Stack is empty!
2) Exception: Stack underflow!
3) Exception: Stack overflow!
