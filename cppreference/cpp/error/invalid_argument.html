std::invalid_argument

Défini dans l'en-tête <stdexcept>

class invalid_argument;

Définit un type d'objet à lever comme exception. Il signale des erreurs survenant parce qu'une valeur d'argument n'a pas été acceptée.

Cette exception est levée par std::bitset::bitset, ainsi que par les familles de fonctions std::stoi et std::stof.

std::invalid_argument::invalid_argument

invalid_argument( const std::string& what_arg );  // (1)

invalid_argument( const char* what_arg );  // (2)

invalid_argument( const invalid_argument& other );  // (3) (noexcept depuis C++11)

  1. Construit l'objet exception avec what_arg comme chaîne explicative. Après la construction, std::strcmp(what(), what_arg.c_str()) == 0.

  2. Construit l'objet exception avec what_arg comme chaîne explicative. Après la construction, std::strcmp(what(), what_arg) == 0.

  3. Constructeur de copie. Si *this et other ont tous deux pour type dynamique std::invalid_argument, alors std::strcmp(what(), other.what()) == 0. Aucune exception ne peut être levée par le constructeur de copie.

Paramètres

  • what_arg — chaîne explicative
  • other — un autre objet exception à copier

Exceptions

1,2) Peut lever std::bad_alloc.

Notes

Comme la copie de std::invalid_argument n'est pas autorisée à lever d'exceptions, ce message est généralement stocké en interne sous forme de chaîne à comptage de références allouée séparément. C'est aussi pour cette raison qu'il n'existe aucun constructeur acceptant std::string&& : il devrait de toute façon copier le contenu.

Avant la résolution du LWG issue 254, le constructeur autre que de copie ne pouvait accepter que std::string. Il rendait l'allocation dynamique obligatoire pour construire un objet std::string.

Après la résolution du LWG issue 471, une classe d'exception standard dérivée doit disposer d'un constructeur de copie accessible publiquement. Il peut être défini implicitement tant que les chaînes explicatives obtenues par what() sont identiques pour l'objet original et l'objet copié.

std::invalid_argument::operator=

invalid_argument& operator=( const invalid_argument& other );  // (noexcept depuis C++11)

Affecte le contenu de other. Si *this et other ont tous deux pour type dynamique std::invalid_argument, alors std::strcmp(what(), other.what()) == 0 après l'affectation. Aucune exception ne peut être levée par l'opérateur d'affectation par copie.

  • (destructeur) [virtuelle] — détruit l'objet d'exception (fonction membre publique virtuelle de std::exception)
  • what [virtuelle] — renvoie une chaîne explicative (fonction membre publique virtuelle de std::exception)

Notes

Cette exception a un rôle similaire à la condition d'erreur std::errc::invalid_argument (levée dans std::system_error par les fonctions membres de std::thread) et à la constante errno associée EINVAL.

Exemple

#include <bitset>
#include <iostream>
#include <stdexcept>
#include <string>

int main()
{
    try
    {
        std::bitset<4>{"012"}; // Lève : seul '0' ou '1' est attendu
    }
    catch (std::invalid_argument const& ex)
    {
        std::cout << "#1: " << ex.what() << '\n';
    }

    try
    {
        [[maybe_unused]] int f = std::stoi("ABBA"); // Lève : aucune conversion
    }
    catch (std::invalid_argument const& ex)
    {
        std::cout << "#2: " << ex.what() << '\n';
    }

    try
    {
        [[maybe_unused]] float f = std::stof("(3.14)"); // Lève : aucune conversion
    }
    catch (std::invalid_argument const& ex)
    {
        std::cout << "#3: " << ex.what() << '\n';
    }
}

Sortie possible :

#1: bitset string ctor has invalid argument
#2: stoi: no conversion
#3: stof: no conversion
