std::uncaught_exception, std::uncaught_exceptions

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <exception>

bool uncaught_exception() throw();  // (jusqu'à C++11)

bool uncaught_exception() noexcept;  // (depuis C++11) (obsolète en C++17) (supprimé en C++20)

int uncaught_exceptions() noexcept;  // (2) (depuis C++17) (constexpr depuis C++26)

  1. Détecte si le thread courant possède un objet exception actif, c'est-à-dire qu'une exception a été lancée ou relancée et n'a pas encore atteint une clause catch correspondante, std::terminate ou std::unexpected. En d'autres termes, std::uncaught_exception détecte si le déroulement de la pile est en cours.

  2. Détecte le nombre d'exceptions du thread courant qui ont été lancées ou relancées et n'ont pas encore atteint leurs clauses catch correspondantes.

Il est parfois sûr de lever une exception même pendant [std::uncaught_exception() == true (jusqu'à C++17) | std::uncaught_exceptions() > 0 (depuis C++17)]. Par exemple, si le déroulement de la pile entraîne la destruction d'un objet, le destructeur de cet objet peut exécuter du code qui lève une exception, à condition que celle-ci soit interceptée par un bloc catch avant de sortir du destructeur.

Paramètres

(aucune)

Valeur de retour

  1. true si un déroulement de la pile est en cours dans ce thread, false sinon.

  2. Le nombre d'objets exception non interceptés dans le thread courant.

Notes

Un exemple où uncaught_exceptions, qui renvoie un int, est utilisé est la bibliothèque boost.log : l'expression BOOST_LOG(logger) << foo(); crée d'abord un objet garde et enregistre le nombre d'exceptions non interceptées dans son constructeur. La sortie est effectuée par le destructeur de l'objet garde, sauf si foo() lève une exception (auquel cas le nombre d'exceptions non interceptées dans le destructeur est supérieur à celui observé par le constructeur).

std::experimental::scope_fail et std::experimental::scope_success dans LFTS v3 reposent sur la fonctionnalité de uncaught_exceptions, car leurs destructeurs doivent faire des choses différentes selon que l'appel a lieu pendant un déroulement de la pile.

Exemple

#include <exception>
#include <iostream>
#include <stdexcept>

struct Foo
{
    char id{'?'};
    int count = std::uncaught_exceptions();

    ~Foo()
    {
        count == std::uncaught_exceptions()
            ? std::cout << id << ".~Foo() called normally\n"
            : std::cout << id << ".~Foo() called during stack unwinding\n";
    }
};

int main()
{
    Foo f{'f'};

    try
    {
        Foo g{'g'};
        std::cout << "Exception thrown\n";
        throw std::runtime_error("test exception");
    }
    catch (const std::exception& e)
    {
        std::cout << "Exception caught: " << e.what() << '\n';
    }
}

Sortie possible :

Exception thrown
g.~Foo() called during stack unwinding
Exception caught: test exception
f.~Foo() called normally
