std::current_exception

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <exception>

std::exception_ptr current_exception() noexcept;  // (depuis C++11) (constexpr depuis C++26)

Si appelée pendant la gestion d'une exception (typiquement, dans une clause catch), capture l'objet exception courant et crée un std::exception_ptr qui contient soit une copie, soit une référence vers cet objet exception (selon l'implémentation). L'objet référencé reste valide au moins aussi longtemps qu'il existe un objet exception_ptr qui s'y réfère.

Si l'implémentation de cette fonction nécessite un appel à new et que cet appel échoue, le pointeur renvoyé contiendra une référence vers une instance de std::bad_alloc.

Si l'implémentation de cette fonction nécessite de copier l'objet exception capturé et que son constructeur de copie lève une exception, le pointeur renvoyé contiendra une référence vers l'exception levée. Si le constructeur de copie de l'objet exception levé lève aussi une exception, le pointeur renvoyé peut contenir une référence vers une instance de std::bad_exception pour rompre la boucle infinie.

Si la fonction est appelée alors qu'aucune exception n'est traitée, un std::exception_ptr vide est renvoyé.

Cette fonction peut être appelée dans un std::terminate_handler pour récupérer l'exception qui a provoqué l'invocation de std::terminate.

Valeur de retour

Une instance de std::exception_ptr contenant une référence vers l'objet exception, ou une copie de l'objet exception, ou vers une instance de std::bad_alloc ou vers une instance de std::bad_exception.

Notes

Sur les implémentations qui suivent l'ABI C++ Itanium (GCC, Clang, etc.), les exceptions sont allouées sur le tas lors du lancement (sauf std::bad_alloc dans certains cas), et cette fonction crée simplement le pointeur intelligent référençant l'objet précédemment alloué. Sur MSVC, les exceptions sont allouées sur la pile lors du lancement, et cette fonction effectue l'allocation sur le tas et copie l'objet exception.

Sous Windows dans les environnements CLR managés [1], l'implémentation stockera un std::bad_exception lorsque l'exception courante est une exception managée ([2]). Notez que catch(...) capture aussi les exceptions managées :

#include <exception>

int main()
{
    try
    {
        throw gcnew System::Exception("Managed exception");
    }
    catch (...)
    {
        std::exception_ptr ex = std::current_exception();
        try
        {
            std::rethrow_exception(ex);
        }
        catch (std::bad_exception const &)
        {
            // Ceci sera affiché.
            std::cout << "Bad exception" << std::endl;
        }
    }
}

Exemple

#include <exception>
#include <iostream>
#include <stdexcept>
#include <string>

void handle_eptr(std::exception_ptr eptr) // le passage par valeur est OK
{
    try
    {
        if (eptr)
            std::rethrow_exception(eptr);
    }
    catch(const std::exception& e)
    {
        std::cout << "Caught exception: '" << e.what() << "'\n";
    }
}

int main()
{
    std::exception_ptr eptr;

    try
    {
        [[maybe_unused]]
        char ch = std::string().at(1); // ceci génère un std::out_of_range
    }
    catch(...)
    {
        eptr = std::current_exception(); // capture
    }

    handle_eptr(eptr);

} // le destructeur de std::out_of_range est appelé ici, lorsque eptr est détruit
