  1. Fonction membre publique, appelle la fonction membre do_out de la classe la plus dérivée.

  2. Si cette facette codecvt définit une conversion, traduit les caractères internes de l'intervalle source [from,from_end) en caractères externes, en plaçant les résultats dans les positions suivantes à partir de to. Ne convertit pas plus de from_end - from caractères internes et n'écrit pas plus de to_end - to caractères externes. Laisse from_next et to_next pointant un élément après le dernier élément converti avec succès.

Si cette facette codecvt ne définit pas de conversion, aucun caractère n'est converti. to_next prend la valeur de to, state est inchangé et std::codecvt_base::noconv est renvoyé.

do_out(state, from, from + 1, from_next, to, to_end, to_next) doit renvoyer ok si

  • cette facette codecvt est utilisée par basic_filebuf, et
  • do_out(state, from, from_end, from_next, to, to_end, to_next) renverrait ok alors que from != from_end.

Valeur de retour

Une valeur de type std::codecvt_base::result, indiquant le statut de réussite comme suit :

  • ok — conversion terminée
  • partial — espace insuffisant dans le tampon de sortie ou fin inattendue du tampon source
  • error — rencontre d'un caractère qui ne peut pas être converti
  • noconv — cette facette est sans conversion, aucune sortie écrite

La spécialisation sans conversion std::codecvt<char, char, std::mbstate_t> renvoie toujours std::codecvt_base::noconv.

Notes

Exige que from <= from_end && to <= to_end et que state représentent soit l'état de décalage initial, soit l'état obtenu en convertissant les caractères précédents de la séquence.

Alors que codecvt prend en charge les conversions N:M (par exemple UTF-16 vers UTF-8, où deux caractères internes peuvent être nécessaires pour déterminer les caractères externes à produire), std::basic_filebuf ne peut utiliser que des facettes codecvt qui définissent une conversion 1:N, c'est-à-dire qu'elle doit pouvoir traiter un caractère interne à la fois lors de l'écriture dans un fichier.

Lors de conversions N:M, cette fonction peut renvoyer std::codecvt_base::partial après avoir consommé tous les caractères source (from_next == from_end). Cela signifie qu'un autre caractère interne est nécessaire pour terminer la conversion (par exemple lors de la conversion d'UTF-16 vers UTF-8, si le dernier caractère du tampon source est un substitut haut).

L'effet sur state est volontairement non spécifié. Dans les facettes standard, il sert à maintenir l'état de décalage, comme lors d'un appel à std::wcsrtombs, et est donc mis à jour pour refléter l'état de décalage après le dernier caractère converti avec succès, mais une facette définie par l'utilisateur est libre de l'utiliser pour maintenir tout autre état, par exemple pour compter le nombre de caractères spéciaux rencontrés.

Exemple

#include <iostream>
#include <locale>
#include <string>

int main()
{
    std::locale::global(std::locale("en_US.utf8"));
    auto& f = std::use_facet<std::codecvt<wchar_t, char, std::mbstate_t>>(std::locale());
    std::wstring internal = L"z\u00df\u6c34\U0001f34c"; // L"zß水🍌"

    // notez que ce qui suit peut être fait avec wstring_convert
    std::mbstate_t mb{}; // état de décalage initial
    std::string external(internal.size() * f.max_length(), '\0');
    const wchar_t* from_next;
    char* to_next;
    f.out(mb, &internal[0], &internal[internal.size()], from_next,
              &external[0], &external[external.size()], to_next);
    // vérification des erreurs omise par souci de concision
    external.resize(to_next - &external[0]);

    std::cout << "The string in narrow multibyte encoding: " << external << '\n';
}

Output:

The string in narrow multibyte encoding: zß水🍌

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
