  1. Fonction membre publique, appelle la fonction membre do_get de la classe la plus dérivée.

  2. Lit des caractères depuis l'itérateur d'entrée in et produit la valeur du type de v, en tenant compte des indicateurs de formatage du flux d'E/S de str.flags(), des règles de classification des caractères de std::use_facet<std::ctype<CharT>>(str.getloc()) et des caractères de ponctuation numérique de std::use_facet<std::numpunct<CharT>>(str.getloc()). Cette fonction est appelée par tous les opérateurs de flux d'entrée formatés, tels que std::cin >> n;.

La conversion s'effectue en trois étapes :

Étape 1 : sélection du spécificateur de conversion

  • Les indicateurs de format d'E/S sont obtenus, comme si par fmtflags basefield = (str.flags() & std::ios_base::basefield); fmtflags boolalpha = (str.flags() & std::ios_base::boolalpha);

  • Si le type de v est un type entier, le premier choix applicable parmi les cinq suivants est sélectionné : Si basefield == oct, utilise le spécificateur de conversion %o Si basefield == hex, utilise le spécificateur de conversion %X Si basefield == 0, utilise le spécificateur de conversion %i Si le type de v est signé, utilise le spécificateur de conversion %d Si le type de v est non signé, utilise le spécificateur de conversion %u

  • Pour les types entiers, le modificateur de longueur est ajouté à la spécification de conversion si nécessaire : h pour short et unsigned short, l pour long et unsigned long, ll pour long long et unsigned long long (depuis C++11)

  • Si le type de v est float, utilise le spécificateur de conversion %g

  • Si le type de v est double, utilise le spécificateur de conversion %lg

  • Si le type de v est long double, utilise le spécificateur de conversion %Lg

  • Si le type de v est void*, utilise le spécificateur de conversion %p

  • Si le type de v est bool et boolalpha == 0, procède comme si le type de v était long, à l'exception de la valeur à stocker dans v à l'étape 3.

  • Si le type de v est bool et boolalpha != 0, ce qui suit remplace les étapes 2 et 3 :

    • Les caractères successifs obtenus depuis l'itérateur d'entrée in sont comparés aux séquences de caractères obtenues de std::use_facet<std::numpunct<CharT>>(str.getloc()).falsename() et std::use_facet<std::numpunct<CharT>>(str.getloc()).truename(), uniquement si nécessaire pour identifier la correspondance unique. L'itérateur d'entrée in n'est comparé à end que lorsque cela est nécessaire pour obtenir un caractère.
    • Si la séquence cible est trouvée de manière unique, v est définie à la valeur bool correspondante. Sinon, false est stocké dans v et std::ios_base::failbit est affecté à err. Si aucune correspondance unique n'a pu être trouvée avant la fin de l'entrée (in == end), err |= std::ios_base::eofbit est exécuté.

Étape 2 : extraction des caractères

  • Si in == end, l'étape 2 se termine immédiatement, aucun autre caractère n'est extrait.
  • Le caractère suivant est extrait de in comme si par char_type ct = *in; :
    • Si le caractère correspond à l'un de ["0123456789abcdefxABCDEFX+-" (jusqu'à C++11) | "0123456789abcdefpxABCDEFPX+-" (depuis C++11)], élargi au char_type de la locale comme si par std::use_facet<std::ctype<CharT>>(str.getloc()).widen(), il est converti en char correspondant.
    • Si le caractère correspond au séparateur décimal (std::use_facet<std::numpunct<CharT>>(str.getloc()).decimal_point())), il est remplacé par '.'.
    • Si le caractère correspond au séparateur des milliers (std::use_facet<std::numpunct<CharT>>(str.getloc()).thousands_sep()) et que la séparation des milliers est utilisée (comme déterminé par std::use_facet<std::numpunct<CharT>>(str.getloc()).grouping().length() != 0), alors, si le point décimal '.' n'a pas encore été accumulé, la position du caractère est mémorisée, mais le caractère est sinon ignoré. Si le point décimal a déjà été accumulé, le caractère est écarté et l'étape 2 se termine.
    • Dans tous les cas, on vérifie si le char obtenu lors des étapes précédentes est autorisé dans le champ de saisie qui serait analysé par std::scanf compte tenu du spécificateur de conversion sélectionné à l'étape 1. S'il est autorisé, il est accumulé dans un tampon temporaire et l'étape 2 se répète. Sinon, l'étape 2 se termine.

Étape 3 : conversion et stockage

  • La séquence de char accumulés à l'étape 2 est convertie en valeur numérique :

L'entrée est analysée selon les règles de std::scanf.

(jusqu'à C++11)

L'entrée est analysée comme si par

  • std::strtoll pour un entier signé v,
  • std::strtoull pour un entier non signé v,
  • std::strtof for float v,
  • std::strtod pour double v, ou
  • std::strtold for long double v.

(depuis C++11)

  • Si la fonction de conversion ne parvient pas à convertir la totalité du champ, la valeur 0 est stockée dans v.
  • Si le type de v est un type entier signé et que la fonction de conversion produit une valeur positive ou négative trop grande pour y être stockée, la valeur représentable la plus grande ou la plus petite, respectivement, est stockée dans v.
  • Si le type de v est un type entier non signé et que la fonction de conversion produit une valeur qui ne peut y être stockée, la valeur représentable la plus grande est stockée dans v.
  • Dans tous les cas, si la fonction de conversion échoue, std::ios_base::failbit est affecté à err.
  • Sinon, le résultat numérique de la conversion est stocké dans v.
    • Si le type de v est bool et que boolalpha n'est pas activé, alors si la valeur à stocker est 0, false est stocké ; si la valeur à stocker est 1, true est stocké ; pour toute autre valeur, std::ios_base::failbit est affecté à err et true est stocké.
  • Après cela, le groupement des chiffres est vérifié. Si la position d'un des séparateurs de milliers écartés à l'étape 2 ne correspond pas au groupement fourni par std::use_facet<std::numpunct<CharT>>(str.getloc()).grouping(), std::ios_base::failbit est affecté à err.
  • Si l'étape 2 s'est terminée par le test in == end, err |= std::ios_base::eofbit est exécuté pour positionner le bit eof.

Valeur de retour

in

Notes

Avant les résolutions de LWG issue 23 et LWG issue 696, v restait inchangé si une erreur survenait.

Avant la résolution de LWG issue 221, les chaînes représentant des entiers hexadécimaux (par ex. "0xA0") étaient rejetées par do_get(int) même si elles constituent une entrée valide pour strtol, car l'étape 2 filtre les caractères 'X' et 'x'.

Avant la résolution de LWG issue 1169, la conversion d'une chaîne représentant un nombre négatif en entier non signé pouvait donner zéro (puisque la valeur représentée par la chaîne est inférieure à ce que le type cible peut représenter).

Avant la résolution de LWG issue 2381, les chaînes représentant des nombres à virgule flottante hexadécimaux avec exposants (par ex. "0x1.23p-10") étaient rejetées par do_get(double) même si elles constituent une entrée valide pour strtod, car l'étape 2 filtre les caractères 'P' et 'p'.

Les chaînes représentant l'infini ou un non-nombre (par ex. "NaN" et "inf") sont rejetées par do_get(double) même si elles constituent une entrée valide pour strtod, car l'étape 2 filtre des caractères tels que 'N' ou 'i'.

(depuis C++11)

Exemple

Une implémentation de operator>> pour un type défini par l'utilisateur.

#include <iostream>
#include <iterator>
#include <locale>

struct base { long x; };

template<class CharT, class Traits>
std::basic_istream<CharT, Traits>&
    operator >>(std::basic_istream<CharT, Traits>& is, base& b)
{
    std::ios_base::iostate err = std::ios_base::goodbit;

    try // la définition de err pouvait lever une exception
    {
        typename std::basic_istream<CharT, Traits>::sentry s(is);

        if (s) // si le flux est prêt pour la lecture
            std::use_facet<std::num_get<CharT>>(is.getloc()).get(is, {}, is, err, b.x);
    }
    catch (std::ios_base::failure& error)
    {
        // gérer l'exception
    }

    return is;
}

int main()
{
    base b;
    std::cin >> b;
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct

LWG 18 C++98 la surcharge de get prenant une valeur de type bool& était absente added
LWG 23 C++98 une entrée provoquant un dépassement a entraîné un comportement indéfini dépassement géré
LWG 154 C++98 le spécificateur de conversion pour double était %g (identique à float) modifié en %lg

LWG 275 C++98 get disposait d'une surcharge prenant une valeur short& au lieu de float& corrected
