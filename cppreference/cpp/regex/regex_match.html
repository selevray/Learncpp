Détermine si l'expression régulière e correspond à l'intégralité de la séquence de caractères cible. Le résultat détaillé de la correspondance est stocké dans m (s'il est présent).

1,2) La séquence de caractères cible est représentée par l'intervalle [first,last).

Si BidirIt ne satisfait pas aux exigences de LegacyBidirectionalIterator, le comportement est indéfini.

(jusqu'à C++23)

Si BidirIt ne modélise pas bidirectional_iterator, le comportement est indéfini.

(depuis C++23)

3,4) La séquence de caractères cible est représentée par l'intervalle [str,str + std::char_traits<CharT>::length(str)).

5,6) La séquence de caractères cible est représentée par la chaîne s.

  1. La séquence de caractères cible ne peut pas être représentée par une rvalue de type std::string.

Si la correspondance n'existe pas, les expressions suivantes impliquant m (si elle existe) doivent produire les valeurs indiquées :

Expression Valeur
m.ready() true
m.size() 0
m.empty() true

Si la correspondance existe, pour tout entier de (0,m.size()) utilisé comme n, les expressions suivantes impliquant m doivent produire les valeurs indiquées pour chaque surcharge listée ci-dessous :

Expression | Valeur

Surcharge (1) | Surcharge (3) | Surcharge (5)

m.ready() | true

m.size() | 1 + e.mark_count()

m.empty() | false

m.prefix().first | first | str | s.begin()

m.prefix().second

m.prefix().matched |     false[1]

m.suffix().first | last | std::char_traits<CharT>:: length(str) + str | s.end()

m.suffix().second

m.suffix().matched |     false[2]

m[0].first | first | str | s.begin()

m[0].second | last | std::char_traits<CharT>:: length(str) + str | s.end()

m[0].matched |     true[3]

m[n].first |

  • last si la sous-expression marquée n n'a pas participé à la correspondance
  • le début de la séquence sinon, correspondant à la sous-expression n sinon

m[n].second |

  • last si la sous-expression marquée n n'a pas participé à la correspondance
  • la fin de la séquence sinon, correspondant à la sous-expression n sinon

m[n].matched |

  • false si la sous-expression marquée n n'a pas participé à la correspondance
  • true sinon
  1. ↑ Le préfixe de correspondance est vide.
  2. ↑ Le suffixe de correspondance est vide.
  3. ↑ La séquence entière est mise en correspondance.

Paramètres

  • first, last — l'intervalle de caractères cible
  • str — la chaîne C terminée par un caractère nul cible
  • s — le std::basic_string cible
  • m — les résultats de correspondance
  • e — l'expression régulière
  • flags — indicateurs utilisés pour déterminer la manière dont la correspondance sera effectuée

Valeur de retour

Renvoie true si la séquence cible entière correspond à e, false sinon.

Notes

Comme regex_match ne considère que les correspondances complètes, la même expression régulière peut donner des correspondances différentes entre regex_match et std::regex_search :

std::regex re("Get|GetValue");
std::cmatch m;
std::regex_search("GetValue", m, re);  // renvoie true, et m[0] contient "Get"
std::regex_match ("GetValue", m, re);  // renvoie true, et m[0] contient "GetValue"
std::regex_search("GetValues", m, re); // renvoie true, et m[0] contient "Get"
std::regex_match ("GetValues", m, re); // renvoie false

Exemple

#include <cstddef>
#include <iostream>
#include <regex>
#include <string>

int main()
{
    // Correspondance simple d'expression régulière
    const std::string fnames[] = {"foo.txt", "bar.txt", "baz.dat", "zoidberg"};
    const std::regex txt_regex("[a-z]+\\.txt");

    for (const auto& fname : fnames)
        std::cout << fname << ": " << std::regex_match(fname, txt_regex) << '\n';

    // Extraction d'une sous-correspondance
    const std::regex base_regex("([a-z]+)\\.txt");
    std::smatch base_match;

    for (const auto& fname : fnames)
        if (std::regex_match(fname, base_match, base_regex))
            // La première sub_match est la chaîne entière ; la suivante
            // sub_match est la première expression entre parenthèses.
            if (base_match.size() == 2)
            {
                std::ssub_match base_sub_match = base_match[1];
                std::string base = base_sub_match.str();
                std::cout << fname << " has a base of " << base << '\n';
            }

    // Extraction de plusieurs sous-correspondances
    const std::regex pieces_regex("([a-z]+)\\.([a-z]+)");
    std::smatch pieces_match;

    for (const auto& fname : fnames)
        if (std::regex_match(fname, pieces_match, pieces_regex))
        {
            std::cout << fname << '\n';
            for (std::size_t i = 0; i < pieces_match.size(); ++i)
            {
                std::ssub_match sub_match = pieces_match[i];
                std::string piece = sub_match.str();
                std::cout << "  submatch " << i << ": " << piece << '\n';
            }
        }
}

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 2205 C++11 n pourrait être nul dans la postcondition ne peut être que positif
LWG 2273 C++11 on ne savait pas clairement si les correspondances partielles étaient prises en compte ne considère que les correspondances complètes
LWG 2329 C++11 la surcharge (5) acceptait des rvalues basic_string, ce qui pouvait entraîner des itérateurs pendants rejetée via la surcharge supprimée (7)
