std::regex_token_iterator

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <regex>

template<
    class BidirIt,
    class CharT = typename std::iterator_traits<BidirIt>::value_type,
    class Traits = std::regex_traits<CharT>
> class regex_token_iterator  // (depuis C++11)

std::regex_token_iterator est un LegacyForwardIterator en lecture seule qui accède aux sous-correspondances individuelles de chaque correspondance d'une expression régulière dans la séquence de caractères sous-jacente. Il peut également servir à accéder aux parties de la séquence qui ne correspondent pas à l'expression régulière donnée (par exemple, comme analyseur lexical).

À la construction, il construit un std::regex_iterator et à chaque incrémentation il parcourt les sous-correspondances demandées à partir du match_results courant, en incrémentant le std::regex_iterator sous-jacent lorsqu'il s'éloigne de la dernière sous-correspondance.

Le std::regex_token_iterator construit par défaut est l'itérateur de fin de séquence. Lorsqu'un std::regex_token_iterator valide est incrémenté après avoir atteint la dernière sous-correspondance de la dernière correspondance, il devient égal à l'itérateur de fin de séquence. Le déréférencer ou l'incrémenter davantage provoque un comportement indéfini.

Juste avant de devenir l'itérateur de fin de séquence, un std::regex_token_iterator peut devenir un itérateur de suffixe, si l'indice -1 (fragment non correspondant) figure dans la liste des indices de sous-correspondances demandés. Un tel itérateur, s'il est déréférencé, renvoie un match_results correspondant à la séquence de caractères comprise entre la dernière correspondance et la fin de la séquence.

Une implémentation typique de std::regex_token_iterator contient le std::regex_iterator sous-jacent, un conteneur (par exemple std::vector<int>) des indices de sous-correspondances demandés, le compteur interne égal à l'indice de la sous-correspondance, un pointeur vers std::sub_match, pointant sur la sous-correspondance courante de la correspondance courante, et un objet std::match_results contenant la dernière séquence de caractères non correspondante (utilisé en mode analyseur lexical).

Exigences de type

  • BidirIt doit satisfaire aux exigences de LegacyBidirectionalIterator.

Notes

Il incombe au programmeur de s'assurer que l'objet std::basic_regex passé au constructeur de l'itérateur survit à celui-ci. Comme l'itérateur stocke un std::regex_iterator qui contient un pointeur vers l'expression régulière, incrémenter l'itérateur après la destruction de l'expression régulière provoque un comportement indéfini.

Exemple

#include <algorithm>
#include <fstream>
#include <iostream>
#include <iterator>
#include <regex>

int main()
{
    // Analyse lexicale (fragments non correspondants)
    // Notez que l'expression régulière n'est appliquée que deux fois ; lorsque la troisième valeur est obtenue
    // l'itérateur est un itérateur de suffixe.
    const std::string text = "Quick brown fox.";
    const std::regex ws_re("\\s+"); // whitespace
    std::copy(std::sregex_token_iterator(text.begin(), text.end(), ws_re, -1),
              std::sregex_token_iterator(),
              std::ostream_iterator<std::string>(std::cout, "\n"));

    std::cout << '\n';

    // Parcours des premières sous-correspondances
    const std::string html = R"(<p><a href="http://google.com">google</a> )"
                             R"(< a HREF ="http://cppreference.com">cppreference</a>\n</p>)";
    const std::regex url_re(R"!!(<\s*A\s+[^>]*href\s*=\s*"([^"]*)")!!", std::regex::icase);
    std::copy(std::sregex_token_iterator(html.begin(), html.end(), url_re, 1),
              std::sregex_token_iterator(),
              std::ostream_iterator<std::string>(std::cout, "\n"));
}
