std::basic_string

template<
    class CharT,
    class Traits = std::char_traits<CharT>,
    class Allocator = std::allocator<CharT>
> class basic_string;  // (1)

namespace pmr {
template<
    class CharT,
    class Traits = std::char_traits<CharT>
> using basic_string =
    std::basic_string<CharT, Traits, std::pmr::polymorphic_allocator<CharT>>;
}  // (2) (depuis C++17)

Le modèle de classe basic_string stocke et manipule des séquences d'objets semblables à des caractères, qui sont des objets non tableaux de TrivialType et StandardLayoutType. La classe ne dépend ni du type de caractère ni de la nature des opérations sur ce type. Les définitions des opérations sont fournies via le paramètre de modèle Traits - une spécialisation de std::char_traits ou une classe de traits compatible.

Les éléments d'un basic_string sont stockés de manière contiguë, c'est-à-dire que, pour un basic_string s, &*(s.begin() + n) == &*s.begin() + n pour tout n dans [0,s.size()), et *(s.begin() + s.size()) a pour valeur CharT() (un terminateur nul) (depuis C++11) ; ou, de façon équivalente, un pointeur vers s[0] peut être passé aux fonctions attendant un pointeur vers le premier élément de [un tableau (jusqu'à C++11) | un tableau terminé par un caractère nul (depuis C++11)] de CharT.

std::basic_string satisfait aux exigences de AllocatorAwareContainer (sauf que les construct/destroy personnalisés ne sont pas utilisés pour la construction/destruction des éléments), SequenceContaineret ContiguousContainer (depuis C++17).

Si l'un de Traits::char_type et Allocator::char_type diffère de CharT, le programme est mal formé.

Les fonctions membres de std::basic_string sont constexpr : il est possible de créer et d'utiliser des objets std::string dans l'évaluation d'une expression constante.

Cependant, les objets std::string ne peuvent généralement pas être constexpr, car toute mémoire allouée dynamiquement doit être libérée dans la même évaluation d'expression constante.

Invalidation des itérateurs

Les références, pointeurs et itérateurs désignant les éléments d'un basic_string peuvent être invalidés par toute fonction de la bibliothèque standard prenant en argument une référence vers un basic_string non const, comme std::getline, std::swap, ou operator>>, et par l'appel de fonctions membres non const, à l'exception de operator[], at, data, front, back, begin, rbegin, end et rend.

Notes

Bien qu'il soit requis d'utiliser construct ou destroy personnalisé lors de la construction ou destruction d'éléments de std::basic_string jusqu'à C++23, toutes les implémentations n'utilisaient que le mécanisme par défaut. L'exigence est corrigée par P1072R10 pour correspondre à la pratique existante.

Exemple

#include <iostream>
#include <string>

int main()
{
    using namespace std::literals;

    // Création d'une chaîne à partir de const char*
    std::string str1 = "hello";

    // Création d'une chaîne à l'aide d'un littéral de chaîne
    auto str2 = "world"s;

    // Concaténation de chaînes
    std::string str3 = str1 + " " + str2;

    // Affichage du résultat
    std::cout << str3 << '\n';

    std::string::size_type pos = str3.find(" ");
    str1 = str3.substr(pos + 1); // la partie après l'espace
    str2 = str3.substr(0, pos);  // la partie jusqu'à l'espace

    std::cout << str1 << ' ' << str2 << '\n';

    // Accès à un élément à l'aide de l'opérateur d'indexation operator[]
    std::cout << str1[0] << '\n';
    str1[0] = 'W';
    std::cout << str1 << '\n';
}

Output:

hello world
world hello
w
World
