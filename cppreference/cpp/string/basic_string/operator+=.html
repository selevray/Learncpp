std::basic_string<CharT,Traits,Allocator>::operator+=

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

basic_string& operator+=( const basic_string& str );  // (1) (constexpr depuis C++20)

basic_string& operator+=( CharT ch );  // (2) (constexpr depuis C++20)

basic_string& operator+=( const CharT* s );  // (3) (constexpr depuis C++20)

basic_string& operator+=( std::initializer_list<CharT> ilist );  // (4) (depuis C++11) (constexpr depuis C++20)

template< class StringViewLike >
basic_string& operator+=( const StringViewLike& t );  // (5) (depuis C++17) (constexpr depuis C++20)

Ajoute des caractères supplémentaires à la chaîne.

  1. Ajoute la chaîne str.

  2. Ajoute le caractère ch.

  3. Ajoute la chaîne de caractères terminée par un caractère nul pointée par s.

  4. Ajoute les caractères de la liste d'initialisation ilist.

  5. Convertit implicitement t en string view sv comme par std::basic_string_view<CharT, Traits> sv = t;, puis ajoute les caractères de la string view sv comme par append(sv).

Cette surcharge ne participe à la résolution de surcharge que si std::is_convertible_v<const StringViewLike&, std::basic_string_view<CharT, Traits>> est true et std::is_convertible_v<const StringViewLike&, const CharT*> est false.

Paramètres

  • str — chaîne à ajouter
  • ch — valeur du caractère à ajouter
  • s — pointeur vers une chaîne de caractères terminée par un caractère nul à ajouter
  • ilist — std::initializer_list contenant les caractères à ajouter
  • t — objet (convertible en std::basic_string_view) contenant les caractères à ajouter

Valeur de retour

*this

Complexité

Il n'existe aucune garantie de complexité dans la norme ; les implémentations typiques se comportent de manière similaire à std::vector::insert().

Exceptions

Si l'opération devait faire dépasser size() à max_size(), lève std::length_error.

Si une exception est levée pour quelque raison que ce soit, cette fonction n'a aucun effet (garantie forte de sécurité d'exception).

Notes

La surcharge (2) peut accepter tous les types implicitement convertibles en CharT. Pour std::string, où CharT est char, l'ensemble des types acceptables inclut tous les types arithmétiques. Cela peut avoir des effets non désirés.

Exemple

#include <iomanip>
#include <iostream>
#include <string>

int main()
{
    std::string str;

    // réserver un espace de stockage suffisant pour éviter une réallocation de mémoire
    str.reserve(50);

    std::cout << std::quoted(str) << '\n'; // chaîne vide

    str += "This";
    std::cout << std::quoted(str) << '\n';

    str += std::string(" is ");
    std::cout << std::quoted(str) << '\n';

    str += 'a';
    std::cout << std::quoted(str) << '\n';

    str += {' ', 's', 't', 'r', 'i', 'n', 'g', '.'};
    std::cout << std::quoted(str) << '\n';

    str += 69.96; // Équivalent à str += static_cast<char>(69.96);
                  // 'E' (code ASCII 69) est ajouté par la surcharge (2),
                  // ce qui n'est peut-être pas l'intention.

    // Pour ajouter une valeur numérique, envisagez std::to_string() :
    str += std::to_string(1729);

    std::cout << std::quoted(str) << '\n';
}

Output:

""
"This"
"This is "
"This is a"
"This is a string."
"This is a string.E1729"

Rapports de défauts

Les rapports de défauts suivants modifiant le comportement ont été appliqués rétroactivement aux normes C++ publiées précédemment.

DR Appliqué à Comportement publié Comportement correct
LWG 847 C++98 il n'y avait aucune garantie de sécurité d'exception ajout de la garantie forte de sécurité d'exception
