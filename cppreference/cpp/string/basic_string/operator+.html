Renvoie une chaîne contenant les caractères de lhs suivis des caractères de rhs. Équivalent à :

1,2) std::basic_string<CharT, Traits, Allocator> r = lhs; r.append(rhs); return r;

  1. std::basic_string<CharT, Traits, Allocator> r = lhs; r.push_back(rhs); return r;

  2. std::basic_string<CharT, Traits, Allocator> r = lhs; r.append(rhs); return r;

  3. std::basic_string<CharT, Traits, Allocator> r = rhs; r.insert(0, lhs); return r;

  4. std::basic_string<CharT, Traits, Allocator> r = rhs; r.insert(r.begin(), lhs); return r;

  5. std::basic_string<CharT, Traits, Allocator> r = rhs; r.insert(0, lhs); return r;

  6. lhs.append(rhs); return std::move(lhs); sauf que lhs et rhs sont tous deux laissés dans un état valide mais non spécifié. Si lhs et rhs ont des allocateurs égaux, l'implémentation peut déplacer depuis l'un ou l'autre.

9,10) lhs.append(rhs); return std::move(lhs);

  1. lhs.push_back(rhs); return std::move(lhs);

  2. lhs.append(rhs); return std::move(lhs);

13,14) rhs.insert(0, lhs); return std::move(rhs);

  1. rhs.insert(rhs.begin(), lhs); return std::move(rhs);

  2. rhs.insert(0, lhs); return std::move(rhs);

L'allocateur utilisé pour le résultat est :

1-4) std::allocator_traits<Alloc>::select_on_container_copy_construction(lhs.get_allocator())

5-7) std::allocator_traits<Alloc>::select_on_container_copy_construction(rhs.get_allocator())

8-12) lhs.get_allocator()

13-16) rhs.get_allocator()

En d'autres termes :

  • Si un opérande est une rvalue basic_string, son allocateur est utilisé.
  • Sinon, select_on_container_copy_construction est utilisé sur l'allocateur de l'opérande lvalue basic_string.

Dans chaque cas, l'opérande de gauche est privilégié lorsque les deux sont des basic_string de même catégorie de valeur.

Pour (8-16), tous les opérandes basic_string rvalue sont laissés dans un état valide mais non spécifié.

(depuis C++11)

Paramètres

  • lhs — string, string view (depuis C++26), caractère, ou pointeur vers le premier caractère d'un tableau terminé par un caractère nul
  • rhs — string, string view (depuis C++26), caractère, ou pointeur vers le premier caractère d'un tableau terminé par un caractère nul

Valeur de retour

Une chaîne contenant les caractères de lhs suivis des caractères de rhs, en utilisant l'allocateur déterminé ci-dessus (depuis C++11).

Notes

operator+ doit être utilisé avec beaucoup de précautions lorsque des allocateurs à état sont impliqués(par exemple lorsque std::pmr::string est utilisé) (depuis C++17). Avant P1165R1, l'allocateur utilisé pour le résultat était déterminé par un accident historique et pouvait varier d'une surcharge à l'autre sans raison apparente. De plus, pour (1-5), le comportement de propagation de l'allocateur varie selon les grandes implémentations de la bibliothèque standard et diffère du comportement décrit dans la norme.

Comme l'allocateur utilisé par le résultat de operator+ dépend de la catégorie de valeur, operator+ n'est pas associatif en ce qui concerne la propagation de l'allocateur :

using my_string = std::basic_string<char, std::char_traits<char>, my_allocator<char>>;
my_string cat();
const my_string& dog();

my_string meow = /* ... */, woof = /* ... */;
meow + cat() + /* ... */; // utilise select_on_container_copy_construction sur l'allocateur de meow
woof + dog() + /* ... */; // utilise à la place l'allocateur de la valeur de retour de dog()

meow + woof + meow; // utilise select_on_container_copy_construction sur l'allocateur de meow
meow + (woof + meow); // utilise plutôt SOCCC sur l'allocateur de woof

Pour une chaîne d'invocations de operator+, l'allocateur utilisé pour le résultat final peut être contrôlé en plaçant devant une basic_string rvalue avec l'allocateur souhaité :

// utilise my_favorite_allocator pour le résultat final
my_string(my_favorite_allocator) + meow + woof + cat() + dog();

Pour un contrôle meilleur et portable des allocateurs, il faut utiliser des fonctions membres comme append, insert et operator+= sur une chaîne résultat construite avec l'allocateur souhaité.

(depuis C++11)

L'utilisation de std::type_identity_t comme paramètre dans les surcharges (4), (7), (12) et (16) garantit qu'un objet de type std::basic_string<CharT, Traits, Allocator> peut toujours être concaténé à un objet d'un type T avec une conversion implicite vers std::basic_string_view<CharT, Traits>, et réciproquement, conformément aux règles de résolution de surcharge.

Macro de test de fonctionnalité | Valeur | Std | Fonctionnalité

__cpp_lib_string_view | 202403 | (C++26) | Concaténation de chaînes et de string views, surcharges (4), (7), (12), (16)

(depuis C++26)

Exemple

#include <iostream>
#include <string>
#include <string_view>

int main()
{
    std::string s1 = "Hello";
    std::string s2 = "world";
    const char* end = "!\n";
    std::cout << s1 + ' ' + s2 + end;

    std::string_view water{" Water"};
    #if __cpp_lib_string_view >= 202403
    std::cout << s1 + water + s2 << end; // surcharge (4), puis (1)
    #else
    std::cout << s1 + std::string(water) + s2 << end; // OK, mais moins efficace
    #endif
}

Output:

Hello world!
Hello Waterworld!
