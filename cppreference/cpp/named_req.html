Les exigences nommées listées sur cette page sont les exigences nommées utilisées dans le texte normatif de la norme C++ pour définir les attentes de la bibliothèque standard.

Il incombe au programmeur de veiller à ce que les modèles de la bibliothèque soient instanciés avec des arguments de modèle satisfaisant ces exigences. Le non-respect peut entraîner des diagnostics du compilateur très complexes.

Certaines de ces exigences sont formalisées en C++20 à l'aide de la fonctionnalité de langage concepts.

### Basiques {#Basic}

  • DefaultConstructible — spécifie qu'un objet du type peut être construit par défaut (exigence nommée)
  • MoveConstructible (C++11) — spécifie qu'un objet du type peut être construit à partir d'une rvalue (exigence nommée)
  • CopyConstructible — spécifie qu'un objet du type peut être construit à partir d'une lvalue (exigence nommée)
  • MoveAssignable (C++11) — spécifie qu'un objet du type peut être affecté à partir d'une rvalue (exigence nommée)
  • CopyAssignable — spécifie qu'un objet du type peut être affecté à partir d'une lvalue (exigence nommée)
  • Destructible — spécifie qu'un objet du type peut être détruit (exigence nommée)

### Propriétés de types {#Type_properties}

Remarque : la norme ne définit pas d'exigences nommées portant les noms spécifiés dans cette sous-catégorie.
Ce sont des catégories de types définies par le langage de base. Elles sont incluses ici comme exigences nommées uniquement par cohérence.

  • ScalarType — types d'objets qui ne sont ni des types tableau ni des types classe (exigence nommée)
  • PODType (deprecated in C++20) — types POD (Plain Old Data), compatibles avec C struct (exigence nommée)
  • TriviallyCopyable (C++11) — des objets de ces types peuvent conserver leurs valeurs après la copie de leurs octets sous-jacents (exigence nommée)
  • TrivialType (C++11) (deprecated in C++26) — des objets de ces types peuvent être construits et copiés trivialement (exigence nommée)
  • StandardLayoutType (C++11) — ces types sont utiles pour communiquer avec du code écrit dans d'autres langages de programmation (exigence nommée)
  • ImplicitLifetimeType — des objets de ces types peuvent être créés implicitement, et leur durée de vie peut être démarrée implicitement (exigence nommée)

### Ensemble de la bibliothèque {#Library-wide}

  • BooleanTestable — les opérations booléennes (operator&&, operator|| et operator!) ont leur sémantique habituelle (exigence nommée)
  • EqualityComparable — operator== est une relation d'équivalence (exigence nommée)
  • LessThanComparable — operator< est une relation d'ordre faible strict (exigence nommée)
  • Swappable — peut être échangé par un appel de fonction non membre et non qualifié swap() (exigence nommée)
  • ValueSwappable (C++11) — un LegacyIterator qui se déréférence vers un type Swappable (exigence nommée)
  • NullablePointer (C++11) — un type de type pointeur prenant en charge une valeur nulle (exigence nommée)
  • Hash (C++11) — un FunctionObject qui, pour des entrées de valeurs différentes, a une faible probabilité de donner la même sortie (exigence nommée)
  • Allocator — un type classe contenant des informations d'allocation (exigence nommée)
  • FunctionObject — un objet pouvant être appelé avec la syntaxe d'appel de fonction (exigence nommée)
  • Callable — un type pour lequel l'opération d'invocation est définie (exigence nommée)
  • Predicate — un FunctionObject qui renvoie une valeur convertible en bool pour un argument, sans le modifier (exigence nommée)
  • BinaryPredicate — un FunctionObject qui renvoie une valeur convertible en bool pour deux arguments, sans les modifier (exigence nommée)
  • Compare — un BinaryPredicate qui établit une relation d'ordre (exigence nommée)

### Conteneur {#Container}

  • Container — structure de données permettant l'accès aux éléments à l'aide d'itérateurs (exigence nommée)
  • ReversibleContainer — conteneur utilisant des itérateurs bidirectionnels (exigence nommée)
  • AllocatorAwareContainer (C++11) — conteneur utilisant un allocateur (exigence nommée)
  • SequenceContainer — conteneur dont les éléments sont stockés linéairement (exigence nommée)
  • ContiguousContainer (C++17) — conteneur dont les éléments sont stockés à des adresses mémoire adjacentes (exigence nommée)
  • AssociativeContainer — conteneur qui stocke des éléments en les associant à des clés (exigence nommée)
  • UnorderedAssociativeContainer (C++11) — conteneur qui stocke des éléments répartis en compartiments en les associant à des clés (exigence nommée)

##### Élément de conteneur {#Container_element}

  • DefaultInsertable (C++11) — élément pouvant être construit par défaut dans un stockage non initialisé (exigence nommée)
  • CopyInsertable (C++11) — élément pouvant être construit par copie dans un stockage non initialisé (exigence nommée)
  • MoveInsertable (C++11) — élément pouvant être construit par déplacement dans un stockage non initialisé (exigence nommée)
  • EmplaceConstructible (C++11) — élément pouvant être construit dans un stockage non initialisé (exigence nommée)
  • Erasable (C++11) — élément pouvant être détruit à l'aide d'un allocateur (exigence nommée)

### Itérateur {#Iterator}

  • LegacyIterator — concept général permettant d'accéder aux données d'une structure de données (exigence nommée)
  • LegacyInputIterator — itérateur pouvant être utilisé pour lire des données (exigence nommée)
  • LegacyOutputIterator — itérateur pouvant être utilisé pour écrire des données (exigence nommée)
  • LegacyForwardIterator — itérateur pouvant être utilisé pour lire des données plusieurs fois (exigence nommée)
  • LegacyBidirectionalIterator — itérateur pouvant être à la fois incrémenté et décrémenté (exigence nommée)
  • LegacyRandomAccessIterator — itérateur pouvant avancer en temps constant (exigence nommée)
  • LegacyContiguousIterator (C++17) — itérateur vers des éléments alloués de manière contiguë (exigence nommée)
  • ConstexprIterator (C++20) — itérateur pouvant être utilisé pendant l'évaluation d'expressions constantes (exigence nommée)

### Fonctions d'E/S de flux {#Stream_I.2FO_functions}

  • UnformattedInputFunction — fonction d'entrée de flux qui ne saute pas les espaces blancs initiaux et compte les caractères traités (exigence nommée)
  • FormattedInputFunction — fonction d'entrée de flux qui saute les espaces blancs initiaux (exigence nommée)
  • UnformattedOutputFunction — fonction de sortie de flux de base (exigence nommée)
  • FormattedOutputFunction — fonction de sortie de flux qui positionne failbit en cas d'erreur et renvoie une référence au flux (exigence nommée)

### Formateurs {#Formatters}

  • BasicFormatter (C++20) — abstrait les opérations de formatage pour un type d'argument de formatage et un type de caractère donnés (exigence nommée)
  • Formatter (C++20) — définit les fonctions utilisées par la bibliothèque de formatage (exigence nommée)

### Génération de nombres aléatoires {#Random_Number_Generation}

  • SeedSequence (C++11) — consomme une séquence d'entiers et produit une séquence de valeurs non signées sur 32 bits (exigence nommée)
  • UniformRandomBitGenerator (C++11) — renvoie des entiers non signés aléatoires uniformément distribués (exigence nommée)
  • RandomNumberEngine (C++11) — un UniformRandomBitGenerator déterministe, défini par la graine (exigence nommée)
  • RandomNumberEngineAdaptor (C++11) — un RandomNumberEngine qui transforme la sortie d'un autre RandomNumberEngine (exigence nommée)
  • RandomNumberDistribution (C++11) — renvoie des nombres aléatoires distribués selon une fonction de densité de probabilité mathématique donnée (exigence nommée)

### Concurrence {#Concurrency}

  • BasicLockable (C++11) — fournit une sémantique de propriété exclusive pour les agents d'exécution (c.-à-d. les threads) (exigence nommée)
  • Lockable (C++11) — un BasicLockable qui prend en charge la tentative d'acquisition de verrou (exigence nommée)
  • TimedLockable (C++11) — un Lockable qui prend en charge l'acquisition de verrou avec délai (exigence nommée)
  • SharedLockable (C++14) — fournit la sémantique de propriété partagée pour les agents d'exécution (c'est-à-dire les threads) (exigence nommée)
  • SharedTimedLockable (C++14) — un SharedLockable qui prend en charge l'acquisition de verrou avec délai (exigence nommée)
  • Mutex (C++11) — un Lockable qui protège contre les courses de données et assure une synchronisation à cohérence séquentielle (exigence nommée)
  • TimedMutex (C++11) — un TimedLockable qui protège contre les courses de données et assure une synchronisation à cohérence séquentielle (exigence nommée)
  • SharedMutex (C++17) — un Mutex qui prend en charge la sémantique de propriété partagée (exigence nommée)
  • SharedTimedMutex (C++14) — un TimedMutex qui prend en charge la sémantique de propriété partagée (exigence nommée)

### Intervalles {#Ranges}

  • RangeAdaptorObject (C++20) — un FunctionObject qui crée un adaptateur d'intervalle à partir d'un viewable_range et d'arguments supplémentaires (exigence nommée)
  • RangeAdaptorClosureObject (C++20) — un FunctionObject qui prend en charge l'opérateur pipe (exigence nommée)

### Personnalisation de vue multidimensionnelle {#Multidimensional_View_Customization}

  • LayoutMapping (C++23) — contrôle la correspondance de l'indice multidimensionnel dans mdspan (exigence nommée)
  • LayoutMappingPolicy (C++23) — une politique qui contient les exigences LayoutMapping (exigence nommée)
  • AccessorPolicy (C++23) — une politique qui contrôle l'accès au handle de données dans mdspan (exigence nommée)
