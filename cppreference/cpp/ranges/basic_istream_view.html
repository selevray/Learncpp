  1. Une fabrique d'intervalles qui génère une séquence d'éléments en appelant répétitivement operator>>.

2,3) Modèles d'alias pratiques pour les types de caractères char et wchar_t.

  1. views::istream<T>(e) est équivalente en expression à ranges::basic_istream_view<T, typename U::char_type, typename U::traits_type>(e) pour toutes sous-expressions appropriées e, où U est std::remove_reference_t<decltype(e)>.

Le programme est mal formé si U n'est pas dérivé à la fois publiquement et sans ambiguïté de std::basic_istream<typename U::char_type, typename U::traits_type>, ce qui peut entraîner un échec de substitution.

  1. Le concept /*stream-extractable*/<Val, CharT, Traits> pour l'exposition uniquement est satisfait lorsqu'une lvalue de type Val peut être extraite d'une lvalue de type std::basic_istream<CharT, Traits>.

Le type d'itérateur de basic_istream_view est uniquement déplaçable : il ne respecte pas les exigences de LegacyIterator, et ne fonctionne donc pas avec les algorithmes antérieurs à C++20.

Objets de point de personnalisation

Le nom views::istream<T> désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __istream_fn<T>.

Toutes les instances de __istream_fn<T> sont égales. Les effets de l'invocation de différentes instances du type __istream_fn<T> sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, views::istream<T> peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de views::istream<T> ci-dessus, alors __istream_fn<T> modélise

  • std::invocable<__istream_fn<T>, Args...>,
  • std::invocable<const __istream_fn<T>, Args...>,
  • std::invocable<__istream_fn<T>&, Args...>, and
  • std::invocable<const __istream_fn<T>&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __istream_fn<T> ne participe à la résolution de surcharge.
