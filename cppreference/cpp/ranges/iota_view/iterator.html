  2. Calcule le type de différence pour les deux types d'itérateurs et les types semblables à des entiers.

  • Si I n'est pas un type entier, ou s'il s'agit d'un type entier et que sizeof(std::iter_difference_t<I>) est supérieur à sizeof(I), alors /*iota-diff-t*/<I> est std::iter_difference_t<I>.

  • Sinon, I est l'un des types entiers les plus larges, et /*iota-diff-t*/<I> est un type semblable à un entier signé non spécifié, de largeur non inférieure à celle de I. Il n'est pas spécifié si /*iota-diff-t*/<I> modélise weakly_incrementable dans ce cas.

  1. Spécifie qu'un type est incrementable, et les pré- et post- operator-- pour le type ont une signification commune.

  2. Spécifie qu'un type est à la fois decrementable et totally_ordered, et operator+=, operator-=, operator+ et operator- parmi le type et ses différents types ont une signification commune.

/*iterator*/ modélise

  • random_access_iterator si W modélise advanceable (4),
  • bidirectional_iterator si W modélise decrementable (3),
  • forward_iterator si W modélise incrementable, et
  • input_iterator sinon.

Cependant, il ne satisfait LegacyInputIterator que si W modélise incrementable, et ne satisfait pas LegacyInputIterator sinon.

Exigences sémantiques

  1. Le type I modélise decrementable uniquement si I satisfait decrementable et que tous les concepts qu'il subsume sont modélisés, et étant donné des objets égaux a et b de type I :
  • Si a et b sont dans le domaine des pré- et post- operator-- (c.-à-d. s'ils sont décrémentables), alors les suivants sont tous true :
    • std::addressof(--a) == std::addressof(a),
    • bool(a-- == b),
    • bool(((void)a--, a) == --b),
    • bool(++(--a) == b).
  • Si a et b sont dans le domaine des pré- et post- operator++ (c.-à-d. s'ils sont incrémentables), alors bool(--(++a) == b) est true.
  1. Soit D désignant /*iota-diff-t*/<I>. Le type I modélise advanceable uniquement si I satisfait advanceable et que tous les concepts qu'il subsume sont modélisés, et étant donné
  • des objets a et b de type I et
  • une valeur n de type D,

tel que b soit atteignable depuis a après n applications de ++a, toutes les conditions suivantes sont satisfaites :

  • (a += n) est égal à b.
  • std::addressof(a += n) est égal à std::addressof(a).
  • I(a + n) est égal à (a += n).
  • Pour toutes deux valeurs strictement positives x et y de type D, si I(a + D(x + y)) est bien défini, alors I(a + D(x + y)) est égal à I(I(a + x) + y).
  • I(a + D(0)) est égal à a.
  • Si I(a + D(n - 1)) est bien défini, alors I(a + n) est égal à [](I c) { return ++c; }(I(a + D(n - 1))).
  • (b += -n) est égal à a.
  • (b -= n) est égal à a.
  • std::addressof(b -= n) est égal à std::addressof(b).
  • I(b - n) est égal à (b -= n).
  • D(b - a) est égal à n.
  • D(a - b) est égal à D(-n).
  • bool(a <= b) is true.

iterator_concept est défini comme suit :

  • Si W modélise advanceable, iterator_concept désigne std::random_access_iterator_tag.
  • Sinon, si W modélise decrementable, iterator_concept désigne std::bidirectional_iterator_tag.
  • Sinon, si W modélise incrementable, iterator_concept désigne std::forward_iterator_tag.
  • Sinon, iterator_concept désigne std::input_iterator_tag.
