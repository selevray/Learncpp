template<class T>
concept view = ranges::range<T> && std::movable<T> && ranges::enable_view<T>;  // (1) (depuis C++20)

template<class T>
constexpr bool enable_view =
    std::derived_from<T, view_base> || /*is-derived-from-view-interface*/<T>;  // (2) (depuis C++20)

struct view_base { };  // (3) (depuis C++20)

  1. Le concept view spécifie les exigences d'un type range ayant des propriétés sémantiques adaptées à la construction de pipelines d'adaptateurs d'intervalles.

  2. La variable template enable_view permet d'indiquer si un range est une view. /*is-derived-from-view-interface*/<T> vaut true si et seulement si T possède exactement une classe de base publique ranges::view_interface<U> pour un certain type U, et T n'a aucune classe de base de type ranges::view_interface<V> pour un autre type quelconque V.
    Les utilisateurs peuvent spécialiser enable_view en true pour les types définis par le programme, non qualifiés cv, qui modélisent view, et en false pour les types qui ne le font pas. Ces spécialisations doivent être utilisables dans des expressions constantes et avoir le type const bool.

  3. Dériver de view_base permet aux types range de modéliser view.

Exigences sémantiques

  1. T modélise view seulement si :
  • la construction par déplacement de T a une complexité temporelle constante, et
  • si (\scriptsize N)N copies et/ou déplacements sont effectués à partir d'un objet T contenant (\scriptsize M)M éléments, alors ces (\scriptsize N)N objets ont une destruction en (\scriptsize \mathcal{O}{(N+M)})𝓞(N+M) (ce qui implique qu'un objet view déplacé depuis a une destruction en (\scriptsize \mathcal{O}{(1)})𝓞(1)), et
  • soit std::copy_constructible<T> est false, soit la construction par copie de T a une complexité temporelle constante, et
  • soit std::copyable<T> est false, soit l'affectation par copie de T n'a pas une complexité temporelle supérieure à celle d'une destruction suivie d'une construction par copie.

Spécialisations

Les spécialisations de enable_view pour toutes les spécialisations des modèles standard suivants sont définies comme true :

  • std::basic_string_view
  • std::span
  • std::optional

(depuis C++26)

Notes

Exemples de types view :

  • Un type range qui encapsule une paire d'itérateurs, par exemple std::ranges::subrange<I>.
  • Un type range qui détient ses éléments par std::shared_ptr et partage la propriété avec toutes ses copies.
  • Un type range qui génère ses éléments à la demande, par exemple std::ranges::iota_view.

Un conteneur copiable tel que std::vector<std::string> ne satisfait généralement pas les exigences sémantiques de view, car copier le conteneur copie tous les éléments, ce qui ne peut pas se faire en temps constant.

Bien que les vues aient été initialement décrites comme des intervalles peu coûteux à copier et ne possédant pas leurs éléments, un type n'a pas besoin d'être copiable ni non propriétaire pour modéliser view. Cependant, il doit tout de même être peu coûteux à copier (s'il est copiable), à déplacer, à affecter et à détruire, afin que les adaptateurs d'intervalles n'aient pas de complexité inattendue.

Par défaut, un type modélisant movable et range est considéré comme une vue s'il dérive publiquement et sans ambiguïté de view_base, ou d'exactement une spécialisation de std::ranges::view_interface.

Exemple

Une vue minimale.

#include <ranges>

struct ArchetypalView : std::ranges::view_interface<ArchetypalView>
{
    int* begin();
    int* end();
};

static_assert(std::ranges::view<ArchetypalView>);
