Renvoie un itérateur vers le premier élément de l'argument.

range-begin-end.svg

Si l'argument est une lvalue ou si ranges::enable_borrowed_range<std::remove_cv_t<T>> est true, alors un appel à ranges::begin est équivalent à l'expression suivante :

  1. t + 0 si t a un type tableau.
    • Si std::remove_all_extents_t<std::remove_reference_t<T>> est incomplet, alors l'appel à ranges::begin est mal formé, aucun diagnostic requis.
  2. Sinon, [decay-copy(t.begin()) (jusqu'à C++23) | auto(t.begin()) (depuis C++23)], si cette expression est valide et que son type modélise std::input_or_output_iterator.
  3. Sinon, [decay-copy(begin(t)) (jusqu'à C++23) | auto(begin(t)) (depuis C++23)], si T est un type classe ou énumération, cette expression est valide et son type modélise std::input_or_output_iterator, où la signification de begin est établie comme si seule une recherche dépendante de l'argument était effectuée.

Dans tous les autres cas, un appel à ranges::begin est mal formé, ce qui peut entraîner un échec de substitution lorsque l'appel apparaît dans le contexte immédiat d'une instanciation de modèle.

Objets de point de personnalisation

Le nom ranges::begin désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __begin_fn.

Toutes les instances de __begin_fn sont égales. Les effets de l'invocation de différentes instances du type __begin_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, ranges::begin peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de ranges::begin ci-dessus, alors __begin_fn modélise

  • std::invocable<__begin_fn, Args...>,
  • std::invocable<const __begin_fn, Args...>,
  • std::invocable<__begin_fn&, Args...>, and
  • std::invocable<const __begin_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __begin_fn ne participe à la résolution de surcharge.

Notes

Si l'argument est une rvalue (c'est-à-dire que T est un type objet) et que ranges::enable_borrowed_range<std::remove_cv_t<T>> est false, l'appel à ranges::begin est mal formé, ce qui entraîne également un échec de substitution.

Le type de retour modélise std::input_or_output_iterator dans tous les cas.

La norme C++20 exige que, si l'appel de fonction begin sous-jacent renvoie une prvalue, la valeur de retour soit construite par déplacement à partir de l'objet temporaire matérialisé. Toutes les implémentations renvoient directement la prvalue à la place. Cette exigence est corrigée par la proposition post-C++20 P0849R8 pour correspondre aux implémentations.

Exemple

#include <cassert>
#include <ranges>
#include <vector>

int main()
{
    std::vector v{3, 1, 4};
    auto vi = std::ranges::begin(v);
    auto vci = std::ranges::cbegin(v);
    assert(*vi == 3 and *vi == *vci);
    ++vi;
    ++vci; // OK : vci est un objet modifiable
    *vi = 42; // OK : vi pointe vers un élément modifiable
    // *vci = 13; // Erreur : vci pointe vers un élément non modifiable

    int a[]{-5, 10, 15};
    auto ai = std::ranges::begin(a); // fonctionne également avec les tableaux C
    assert(*ai == -5);
    *ai = 42; // OK
}
