Signature d'appel

template< class T >
    requires /* voir ci-dessous */
constexpr /* voir ci-dessous */ cdata( T&& t );  // (depuis C++20)

Renvoie un pointeur vers le premier élément de type constant (depuis C++23) d'un intervalle contigu désigné par un argument qualifié const (jusqu'à C++23).

Soit CT égal à

  • const std::remove_reference_t<T>& si l'argument est une lvalue (c.-à-d. T est un type de référence lvalue),
  • const T sinon.

Un appel à ranges::cdata est expression-equivalent à ranges::data(static_cast<CT&&>(t)).

Le type de retour est équivalent à std::remove_reference_t<ranges::range_reference_t<CT>>*.

(jusqu'à C++23)

Si l'argument est une lvalue ou si ranges::enable_borrowed_range<std::remove_cv_t<T>> est true, alors un appel à ranges::cdata est équivalent à l'expression suivante :

  • as-const-pointer(ranges::data(possibly-const-range(t))).

Le type de retour est équivalent à std::remove_reference_t<ranges::range_const_reference_t<T>>*.

Dans tous les autres cas, un appel à ranges::cdata est mal formé, ce qui peut entraîner un échec de substitution lorsque l'appel apparaît dans le contexte immédiat d'une instanciation de modèle.

(depuis C++23)

Si ranges::cdata(t) est valide, elle renvoie un pointeur vers un objet de type constant (depuis C++23).

Objets de point de personnalisation

Le nom ranges::cdata désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __cdata_fn.

Toutes les instances de __cdata_fn sont égales. Les effets de l'invocation de différentes instances du type __cdata_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, ranges::cdata peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de ranges::cdata ci-dessus, alors __cdata_fn modélise

  • std::invocable<__cdata_fn, Args...>,
  • std::invocable<const __cdata_fn, Args...>,
  • std::invocable<__cdata_fn&, Args...>, and
  • std::invocable<const __cdata_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __cdata_fn ne participe à la résolution de surcharge.

Exemple

#include <cstring>
#include <iostream>
#include <ranges>
#include <string>

int main()
{
    std::string src {"hello world!\n"};

//  std::ranges::cdata(src)[0] = 'H'; // error, src.data() est traité comme en lecture seule
    std::ranges::data(src)[0] = 'H'; // OK, src.data() est un stockage non const

    char dst[20]; // stockage pour une chaîne de caractères de style C
    std::strcpy(dst, std::ranges::cdata(src));
    // [data(src), data(src) + size(src)] est garanti être une NTBS

    std::cout << dst;
}

Output:

Hello world!
