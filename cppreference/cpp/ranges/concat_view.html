concat_view présente une fabrique view qui prend en argument un nombre quelconque d'intervalles sous forme de liste d'arguments, et fournit une vue qui commence au premier élément du premier intervalle, se termine au dernier élément du dernier intervalle, tous les éléments des intervalles étant enchaînés entre eux dans l'ordre donné en arguments ; elle concatène effectivement, ou chaîne, les intervalles passés en arguments.

  1. Le modèle de classe dont le paramètre de modèle est un paquet non vide de views, chacun modélisant au moins input_range et étant concatable (7).

  2. views::concat est un objet point de personnalisation.

Étant donné un paquet de sous-expressions exprs, l'expression views::concat(exprs...) est équivalente à une expression égale à

  • views::all(exprs...) si exprs est un paquet ne contenant qu'un seul élément dont le type modélise input_range,
  • concat_view(exprs...) sinon.

  1. Représente le type référence. Une contrainte supplémentaire est nécessaire pour s'assurer que chaque ranges::range_reference_t des intervalles sous-jacents est convertible en ranges::common_reference_t.

  2. Le iterator::value_type qui respecte en plus les value_type des intervalles sous-jacents afin de prendre en charge les cas où ceux-ci possèdent des itérateurs mandataires.

  3. La référence rvalue qui prend également correctement en charge les cas où les itérateurs sous-jacents personnalisent iter_move.

  4. Définit le concept indirectly-readable pour le iterator afin que concat_view puisse modéliser input_range.

Équivalent à :

  1. Détermine si deux intervalles différents ou plus peuvent être adaptés en une séquence qui modélise elle-même un intervalle. Équivalent à :
template< class... Rs >

concat_view modélise toujours input_range, et modélise forward_range, bidirectional_range, random_access_range, ou sized_range si chaque type view adapté modélise le concept correspondant.

concat_view peut être common_range si le dernier intervalle sous-jacent modélise common_range.

Objets de point de personnalisation

Le nom views::concat désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __concat_fn.

Toutes les instances de __concat_fn sont égales. Les effets de l'invocation de différentes instances du type __concat_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, views::concat peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de views::concat ci-dessus, alors __concat_fn modélise

  • std::invocable<__concat_fn, Args...>,
  • std::invocable<const __concat_fn, Args...>,
  • std::invocable<__concat_fn&, Args...>, and
  • std::invocable<const __concat_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __concat_fn ne participe à la résolution de surcharge.

Modèles auxiliaires

Il n'existe aucune spécialisation de ranges::enable_borrowed_range pour concat_view, car cela exigerait que l'implémentation de l'itérateur contienne en permanence une copie de tous les itérateurs et sentinelles de tous les intervalles sous-jacents.

Notes

Aucun argument views::concat() est mal formé, car il n'existe pas de moyen raisonnable de déterminer un type d'élément T. Un argument unique views::concat(r) est expression-équivalent à views::all(r).

Exemple

La version préliminaire peut être essayée sur Compiler Explorer.

#include <cassert>
#include <list>
#include <print>
#include <ranges>
#include <vector>

int main()
{
    std::vector<int> v0{1, 2, 3}, v1{4, 5};
    int a[]{6, 7};
    int i{8};
    auto ie{std::views::single(i)};

    auto con = std::views::concat(v0, v1, a, ie);
    assert(con.size() == v0.size() + v1.size() + std::size(a) + ie.size());
    std::println("con.size(): {}", con.size());
    std::println("con: {}", con);
    con[6] = 42; // si con est random_access_range, operator[] renvoie une référence
    assert(a[1] == 42); // a[1] a été modifié via con[6]
    std::println("con: {}", con);

    std::list<int> l{7, 8}; // list est un intervalle bidirectionnel
    auto cat = std::views::concat(v0, l);
    std::println("cat: {}", cat);
    // cat[0] = 13; // erreur de compilation : cat est bidirectionnel => pas d'operator[]
}

Output:

con.size(): 8
con: [1, 2, 3, 4, 5, 6, 7, 8]
con: [1, 2, 3, 4, 5, 6, 42, 8]
cat: [1, 2, 3, 7, 8]
