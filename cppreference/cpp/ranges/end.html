Renvoie un sentinel indiquant la fin d'un intervalle.

range-begin-end.svg

Si l'argument est une lvalue ou si ranges::enable_borrowed_range<std::remove_cv_t<T>> est true, alors un appel à ranges::end est équivalent à l'expression suivante :

  1. t + std::extent_v<T> si t a un type tableau de borne connue.
    • Si std::remove_all_extents_t<std::remove_reference_t<T>> est incomplet, alors l'appel à ranges::end est mal formé, aucun diagnostic requis.
  2. Sinon, [decay-copy(t.end()) (jusqu'à C++23) | auto(t.end()) (depuis C++23)], si cette expression est valide, et que son type modélise std::sentinel_for<ranges::iterator_t<T>>.
  3. Sinon, [decay-copy(end(t)) (jusqu'à C++23) | auto(end(t)) (depuis C++23)], si T est un type classe ou énumération, que cette expression est valide et que son type converti modélise std::sentinel_for<ranges::iterator_t<T>>, où le sens de end est établi comme si l'on effectuait uniquement une recherche dépendante des arguments.

Dans tous les autres cas, un appel à ranges::end est mal formé, ce qui peut entraîner un échec de substitution lorsque l'appel à ranges::end apparaît dans le contexte immédiat d'une instanciation de modèle.

Objets de point de personnalisation

Le nom ranges::end désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __end_fn.

Toutes les instances de __end_fn sont égales. Les effets de l'invocation de différentes instances du type __end_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, ranges::end peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de ranges::end ci-dessus, alors __end_fn modélise

  • std::invocable<__end_fn, Args...>,
  • std::invocable<const __end_fn, Args...>,
  • std::invocable<__end_fn&, Args...>, and
  • std::invocable<const __end_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __end_fn ne participe à la résolution de surcharge.

Notes

Si l'argument est une rvalue (c.-à-d. T est un type objet) et que ranges::enable_borrowed_range<std::remove_cv_t<T>> est false, ou s'il s'agit d'un type tableau de borne inconnue, l'appel à ranges::end est mal formé, ce qui entraîne également un échec de substitution.

Si ranges::end(std::forward<T>(t)) est valide, alors decltype(ranges::end(std::forward<T>(t))) et decltype(ranges::begin(std::forward<T>(t))) modélisent std::sentinel_for dans tous les cas, tandis que T modélise std::ranges::range.

La norme C++20 exige que, si l'appel de fonction end sous-jacent renvoie une prvalue, la valeur de retour soit construite par déplacement à partir de l'objet temporaire matérialisé. Toutes les implémentations renvoient directement la prvalue à la place. Cette exigence est corrigée par la proposition post-C++20 P0849R8 pour correspondre aux implémentations.

Exemple

#include <algorithm>
#include <iostream>
#include <ranges>
#include <vector>

int main()
{
    std::vector<int> vec{3, 1, 4};
    if (std::ranges::find(vec, 5) != std::ranges::end(vec))
        std::cout << "found a 5 in vector vec!\n";

    int arr[]{5, 10, 15};
    if (std::ranges::find(arr, 5) != std::ranges::end(arr))
        std::cout << "found a 5 in array arr!\n";
}

Output:

found a 5 in array arr!
