std::ranges::range

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

Défini dans l'en-tête <ranges>

template< class T >
concept range = requires( T& t ) {
    ranges::begin(t); // préservant l'égalité pour les itérateurs en avant
    ranges::end (t);
};  // (depuis C++20)

Le concept range définit les exigences d'un type qui permet l'itération sur ses éléments en fournissant un itérateur et une sentinelle qui désignent les éléments de l'intervalle.

Exigences sémantiques

Étant donnée une expression E telle que decltype((E)) soit T, T modélise range uniquement si

  • [ranges::begin(E),ranges::end(E)) désigne un intervalle, et
  • ranges::begin(E) et ranges::end(E) sont à temps constant amorti et ne modifient pas la valeur de E d'une manière observable par les expressions préservant l'égalité, et
  • si le type de ranges::begin(E) modélise forward_iterator, ranges::begin(E) est préservant l'égalité (autrement dit, les itérateurs en avant prennent en charge les algorithmes multi-passes).

Notes

Une classe range type n'a besoin de fournir que deux fonctions :

  1. Une fonction membre begin() dont le type de retour modélise input_or_output_iterator.
  2. Une fonction membre end() dont le type de retour modélise sentinel_for<It>, où It est le type de retour de begin().

Sinon, il peut s'agir de fonctions non membres, trouvées par recherche dépendante des arguments.

Exemple

#include <ranges>

// Un intervalle minimal
struct SimpleRange
{
    int* begin();
    int* end();
};
static_assert(std::ranges::range<SimpleRange>);

// Pas un intervalle : pas de begin/end
struct NotRange
{
    int t {};
};
static_assert(!std::ranges::range<NotRange>);

// Pas un intervalle : begin ne renvoie pas un input_or_output_iterator
struct NotRange2
{
    void* begin();
    int* end();
};
static_assert(!std::ranges::range<NotRange2>);

int main() {}
