Renvoie un itérateur vers le dernier élément de l'argument.

range-rbegin-rend.svg

Si T est un type tableau et std::remove_all_extents_t<std::remove_reference_t<T>> est incomplet, alors l'appel à ranges::rbegin est mal formé, aucun diagnostic requis.

Si l'argument est une lvalue ou si ranges::enable_borrowed_range<std::remove_cv_t<T>> est true, alors un appel à ranges::rbegin est équivalent à l'expression suivante :

  1. [decay-copy(t.rbegin()) (jusqu'à C++23) | auto(t.rbegin()) (depuis C++23)], si cette expression est valide et que son type modélise std::input_or_output_iterator.
  2. Sinon, [decay-copy(rbegin(t)) (jusqu'à C++23) | auto(rbegin(t)) (depuis C++23)], si T est un type classe ou énumération, cette expression est valide et son type modélise std::input_or_output_iterator, où la signification de rbegin est établie comme si seule une recherche dépendante de l'argument était effectuée.
  3. Sinon, std::make_reverse_iterator(ranges::end(t)) si ranges::begin(t) et ranges::end(t) sont des expressions valides, ont le même type, et que ce type modélise std::bidirectional_iterator.

Dans tous les autres cas, un appel à ranges::rbegin est mal formé, ce qui peut entraîner un échec de substitution lorsque ranges::rbegin(t) apparaît dans le contexte immédiat d'une instanciation de modèle.

Objets de point de personnalisation

Le nom ranges::rbegin désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __rbegin_fn.

Toutes les instances de __rbegin_fn sont égales. Les effets de l'invocation de différentes instances du type __rbegin_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, ranges::rbegin peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de ranges::rbegin ci-dessus, alors __rbegin_fn modélise

  • std::invocable<__rbegin_fn, Args...>,
  • std::invocable<const __rbegin_fn, Args...>,
  • std::invocable<__rbegin_fn&, Args...>, and
  • std::invocable<const __rbegin_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __rbegin_fn ne participe à la résolution de surcharge.

Notes

Si l'argument est une rvalue (c'est-à-dire que T est un type objet) et que ranges::enable_borrowed_range<std::remove_cv_t<T>> est false, l'appel à ranges::rbegin est mal formé, ce qui entraîne également un échec de substitution.

Le type de retour modélise std::input_or_output_iterator dans tous les cas.

La norme C++20 exige que, si l'appel de fonction rbegin sous-jacent renvoie une prvalue, la valeur de retour soit construite par déplacement à partir de l'objet temporaire matérialisé. Toutes les implémentations renvoient directement la prvalue à la place. Cette exigence est corrigée par la proposition post-C++20 P0849R8 pour correspondre aux implémentations.

Exemple

#include <iostream>
#include <ranges>
#include <span>
#include <vector>

int main()
{
    std::vector<int> v = {3, 1, 4};
    auto vi = std::ranges::rbegin(v);
    std::cout << *vi << '\n';
    *vi = 42; // OK

    int a[] = {-5, 10, 15};
    auto ai = std::ranges::rbegin(a);
    std::cout << *ai << '\n';
    *ai = 42; // OK

    // auto x_x = std::ranges::rbegin(std::vector{6, 6, 6});
    // mal formé : l'argument est une rvalue (voir Notes ↑)

    auto si = std::ranges::rbegin(std::span{a}); // OK
    static_assert(std::ranges::enable_borrowed_range<
        std::remove_cv_t<decltype(std::span{a})>>);
    *si = 42; // OK
}

Output:

4
15
