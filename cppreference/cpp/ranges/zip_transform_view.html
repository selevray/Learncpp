Signature d'appel

template< class F, ranges::viewable_range... Rs >
    requires /* voir ci-dessous */
constexpr auto zip_transform( F&& f, Rs&&... rs );  // (depuis C++23)

  1. zip_transform_view est un adaptateur d'intervalle qui prend un objet invocable et une ou plusieurs views, et produit un view dont le ie élément est le résultat de l'application de l'objet invocable aux ie éléments de toutes les vues.
    Un type T modélise le concept exposition-only /*can-reference*/ si et seulement si T& est un type valide.

  2. views::zip_transform est un objet point de personnalisation.

Lors d'un appel avec un argument f, soit FD égal à std::decay_t<decltype(f)>, si :

  • FD modélise copy_constructible,
  • FD& modélise regular_invocable, et
  • std::invoke_result_t<FD&> est un type objet,

alors views::zip_transform(f) est expression-équivalent à ((void)f, auto(views::empty<std::decay_t<std::invoke_result_t<FD&>>>)). Sinon, l'appel à views::zip_transform est mal formé.

Lors d'un appel avec plus d'un argument f et rs..., views::zip_transform(f, rs...) est expression-équivalent à ranges::zip_transform_view(f, rs...).

zip_transform_view modélise les concepts random_access_range, bidirectional_range, forward_range, input_range, common_range et sized_range lorsque le ranges::zip_view<Views...> sous-jacent modélise les concepts respectifs.

Objets de point de personnalisation

Le nom views::zip_transform désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __zip_transform_fn.

Toutes les instances de __zip_transform_fn sont égales. Les effets de l'invocation de différentes instances du type __zip_transform_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, views::zip_transform peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de views::zip_transform ci-dessus, alors __zip_transform_fn modélise

  • std::invocable<__zip_transform_fn, Args...>,
  • std::invocable<const __zip_transform_fn, Args...>,
  • std::invocable<__zip_transform_fn&, Args...>, and
  • std::invocable<const __zip_transform_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __zip_transform_fn ne participe à la résolution de surcharge.

Exemple

#include <array>
#include <iostream>
#include <list>
#include <ranges>
#include <vector>

void print(auto const rem, auto const& r)
{
    std::cout << rem << '{';
    for (char o[]{0,' ',0}; auto const& e : r)
        std::cout << o << e, *o = ',';
    std::cout << "}\n";
}

int main()
{
    auto v1 = std::vector<float>{1, 2, 3};
    auto v2 = std::list<short>{1, 2, 3, 4};
    auto v3 = std::to_array({1, 2, 3, 4, 5});

    auto add = [](auto a, auto b, auto c) { return a + b + c; };

    auto sum = std::views::zip_transform(add, v1, v2, v3);

    print("v1:  ", v1);
    print("v2:  ", v2);
    print("v3:  ", v3);
    print("sum: ", sum);
}

Output:

v1:  {1, 2, 3}
v2:  {1, 2, 3, 4}
v3:  {1, 2, 3, 4, 5}
sum: {3, 6, 9}
