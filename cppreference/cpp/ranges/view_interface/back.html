std::ranges::view_interface<D>::back

Traduction automatique (Claude Haiku 5.5) de cppreference.com, sous licence CC-BY-SA 3.0.

constexpr decltype(auto) back()
    requires ranges::bidirectional_range<D> && ranges::common_range<D>;  // (1) (depuis C++20)

constexpr decltype(auto) back() const
    requires ranges::bidirectional_range<const D> && ranges::common_range<const D>;  // (2) (depuis C++20)

L'implémentation par défaut de la fonction membre back() renvoie le dernier élément de la vue du type dérivé. Le fait que l'élément soit renvoyé par valeur ou par référence dépend de la operator* du type d'itérateur.

  1. Soit derived égal à static_cast<D&>(*this). Équivalent à return *ranges::prev(ranges::end(derived));. Le comportement est indéfini si empty() est true (c'est-à-dire si l'itérateur de début est égal à la sentinelle), même si l'itérateur obtenu de la même façon est déréférençable.

  2. Identique à (1), sauf que derived est static_cast<const D&>(*this).

Paramètres

(aucune)

Valeur de retour

Le dernier élément de la vue.

Notes

En C++20, aucun type dérivé de std::ranges::view_interface dans la bibliothèque standard ne fournit sa propre fonction membre back().

Cependant, les types dérivés suivants ne peuvent pas utiliser les implémentations par défaut, car ils ne satisfont jamais ni bidirectional_range ni common_range :

  • std::ranges::basic_istream_view
  • std::ranges::lazy_split_view
  • std::ranges::split_view
  • std::ranges::take_while_view

La fonction membre back() héritée est disponible pour std::ranges::empty_view, mais un appel à celle-ci entraîne toujours un comportement indéfini.
