  1. cartesian_product_view est un adaptateur d'intervalle qui prend n views, où n > 0, et produit une view de tuples calculée par le produit cartésien n-aire des intervalles fournis. La taille de la vue produite est un multiple des tailles des intervalles fournis, tandis que chaque élément est un tuple (de références) de taille n.

  2. views::cartesian_product est un objet point de personnalisation.

  • Lors d'un appel sans argument, views::cartesian_product() est expression-equivalent à views::single(std::tuple()).
  • Sinon, views::cartesian_product(rs...) est expression-equivalent à ranges::cartesian_product_view<views::all_t<decltype((rs))>...>(rs...).

  1. Détermine si cartesian_product est un intervalle à accès aléatoire (voir aussi random_access_range).

  2. Détermine si cartesian_product est un intervalle commun (voir aussi common_range).

  3. Détermine si cartesian_product est un intervalle bidirectionnel (voir aussi bidirectional_range).

  4. Détermine si cartesian_product satisfait le concept auxiliaire /*cartesian-product-is-common*/ (voir aussi common_range).

  5. Détermine si cartesian_product est un intervalle dimensionné (voir aussi sized_range).

  6. Détermine si cartesian_product utilise une sentinelle dimensionnée.

  7. Renvoie la fin de la view produite. Ne participe à la résolution de surcharge que si cartesian_product satisfait le concept auxiliaire /*cartesian-product-common-arg*/.

La First range passée à cartesian_product_view est traitée de manière particulière, puisqu'elle n'est transmise qu'une seule fois. Par conséquent, plusieurs contraintes sont assouplies à son égard :

  • First est un input_range au lieu de forward_range ;
  • First n'a pas besoin d'être un sized_range pour que cartesian_product_view soit random_access_range ou common_range ;
  • First n'a pas besoin d'être common_range pour que cartesian_product_view soit bidirectional_range.

Objets de point de personnalisation

Le nom views::cartesian_product désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __cartesian_product_fn.

Toutes les instances de __cartesian_product_fn sont égales. Les effets de l'invocation de différentes instances du type __cartesian_product_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, views::cartesian_product peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de views::cartesian_product ci-dessus, alors __cartesian_product_fn modélise

  • std::invocable<__cartesian_product_fn, Args...>,
  • std::invocable<const __cartesian_product_fn, Args...>,
  • std::invocable<__cartesian_product_fn&, Args...>, and
  • std::invocable<const __cartesian_product_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __cartesian_product_fn ne participe à la résolution de surcharge.

Exemple

#include <array>
#include <iostream>
#include <list>
#include <ranges>
#include <string>
#include <vector>

void print(std::tuple<char const&, int const&, std::string const&> t, int pos)
{
    const auto& [a, b, c] = t;
    std::cout << '(' << a << ' ' << b << ' ' << c << ')' << (pos % 4 ? " " : "\n");
}

int main()
{
    const auto x = std::array{'A', 'B'};
    const auto y = std::vector{1, 2, 3};
    const auto z = std::list<std::string>{"α", "β", "γ", "δ"};

    for (int i{1}; auto const& tuple : std::views::cartesian_product(x, y, z))
        print(tuple, i++);
}

Output:

(A 1 α) (A 1 β) (A 1 γ) (A 1 δ)
(A 2 α) (A 2 β) (A 2 γ) (A 2 δ)
(A 3 α) (A 3 β) (A 3 γ) (A 3 δ)
(B 1 α) (B 1 β) (B 1 γ) (B 1 δ)
(B 2 α) (B 2 β) (B 2 γ) (B 2 δ)
(B 3 α) (B 3 β) (B 3 γ) (B 3 δ)
