Signature d'appel

template< ranges::viewable_range... Rs >
    requires /* voir ci-dessous */
constexpr ranges::view auto zip( Rs&&... rs );  // (depuis C++23)

  1. zip_view est un adaptateur d'intervalle qui prend une ou plusieurs views et produit une view dont le ie élément est une valeur de type tuple constituée des ie éléments de toutes les vues. La taille de la vue produite est le minimum des tailles de toutes les vues adaptées.

  2. views::zip est un objet point de personnalisation.

Lorsqu'il est appelé sans argument, views::zip() est équivalent à une expression auto(views::empty<std::tuple<>>).

Sinon, views::zip(rs...) est expression-equivalent à ranges::zip_view<views::all_t<decltype((rs))>...>(rs...).

zip_view modélise toujours input_range, et modélise forward_range, bidirectional_range, random_access_range, ou sized_range si tous les types de view adaptés modélisent le concept correspondant.

zip_view modélise common_range si

  • sizeof...(Views) est égal à 1, et le seul type de vue adapté modélise common_range, ou
  • au moins un type de vue adapté ne modélise pas bidirectional_range, et chaque type de vue adapté modélise common_range, ou
  • chaque type de vue adapté modélise à la fois random_access_range et sized_range.

Objets de point de personnalisation

Le nom views::zip désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __zip_fn.

Toutes les instances de __zip_fn sont égales. Les effets de l'invocation de différentes instances du type __zip_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, views::zip peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de views::zip ci-dessus, alors __zip_fn modélise

  • std::invocable<__zip_fn, Args...>,
  • std::invocable<const __zip_fn, Args...>,
  • std::invocable<__zip_fn&, Args...>, and
  • std::invocable<const __zip_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __zip_fn ne participe à la résolution de surcharge.

Exemple

#include <array>
#include <iostream>
#include <list>
#include <ranges>
#include <string>
#include <tuple>
#include <vector>

void print(auto const rem, auto const& range)
{
    for (std::cout << rem; auto const& elem : range)
        std::cout << elem << ' ';
    std::cout << '\n';
}

int main()
{
    auto x = std::vector{1, 2, 3, 4};
    auto y = std::list<std::string>{"α", "β", "γ", "δ", "ε"};
    auto z = std::array{'A', 'B', 'C', 'D', 'E', 'F'};

    print("Source views:", "");
    print("x: ", x);
    print("y: ", y);
    print("z: ", z);

    print("\nzip(x,y,z):", "");

    for (std::tuple<int&, std::string&, char&> elem : std::views::zip(x, y, z))
    {
        std::cout << std::get<0>(elem) << ' '
                  << std::get<1>(elem) << ' '
                  << std::get<2>(elem) << '\n';

        std::get<char&>(elem) += ('a' - 'A'); // modifie l'élément de z
    }

    print("\nAfter modification, z: ", z);
}

Output:

Source views:
x: 1 2 3 4
y: α β γ δ ε
z: A B C D E F

zip(x,y,z):
1 α A
2 β B
3 γ C
4 δ D

After modification, z: a b c d E F
