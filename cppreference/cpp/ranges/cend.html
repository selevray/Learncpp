Renvoie une sentinelle pour l'itérateur constant (depuis C++23) indiquant la fin d'un intervalle qualifié const (jusqu'à C++23).

range-begin-end.svg

Soit CT égal à

  • const std::remove_reference_t<T>& si l'argument est une lvalue (c.-à-d. T est un type de référence lvalue),
  • const T sinon.

Un appel à ranges::cend est expression-equivalent à ranges::end(static_cast<CT&&>(t)).

(jusqu'à C++23)

Si l'argument est une lvalue ou si ranges::enable_borrowed_range<std::remove_cv_t<T>> est true, alors un appel à ranges::cend est équivalent à l'expression suivante :

  • std::const_sentinel<decltype(U)>(U) pour une expression U équivalente à ranges::end(possibly-const-range(t)).

Dans tous les autres cas, un appel à ranges::cend est mal formé, ce qui peut entraîner un échec de substitution lorsque l'appel apparaît dans le contexte immédiat d'une instanciation de modèle.

(depuis C++23)

Si ranges::cend(e) est valide pour une expression e, où decltype((e)) est T, alors CT modélise std::ranges::range, et (jusqu'à C++23) std::sentinel_for<S, I> est true dans tous les cas, où S est decltype(ranges::cend(e)), et I est decltype(ranges::cbegin(e)). De plus, S modélise constant-iterator s'il modélise input_iterator. (depuis C++23)

Objets de point de personnalisation

Le nom ranges::cend désigne un objet de point de personnalisation, qui est un objet fonction const d'un type de classe littéral semiregular. À des fins d'exposition, la version sans qualificateurs cv de son type est désignée par __cend_fn.

Toutes les instances de __cend_fn sont égales. Les effets de l'invocation de différentes instances du type __cend_fn sur les mêmes arguments sont équivalents, qu'il s'agisse ou non d'une lvalue ou d'une rvalue, et que l'expression désignant l'instance soit qualifiée const ou non (toutefois, une instance qualifiée volatile n'est pas tenue d'être invocable). Ainsi, ranges::cend peut être copié librement et ses copies peuvent être utilisées de manière interchangeable.

Étant donné un ensemble de types Args..., si std::declval<Args>()... satisfont aux exigences relatives aux arguments de ranges::cend ci-dessus, alors __cend_fn modélise

  • std::invocable<__cend_fn, Args...>,
  • std::invocable<const __cend_fn, Args...>,
  • std::invocable<__cend_fn&, Args...>, and
  • std::invocable<const __cend_fn&, Args...>.

Sinon, aucun opérateur d'appel de fonction de __cend_fn ne participe à la résolution de surcharge.

Exemple

#include <algorithm>
#include <cassert>
#include <ranges>
#include <vector>

int main()
{
    std::vector vec{3, 1, 4};
    int arr[]{5, 10, 15};

    assert(std::ranges::find(vec, 5) == std::ranges::cend(vec));
    assert(std::ranges::find(arr, 5) != std::ranges::cend(arr));
}
