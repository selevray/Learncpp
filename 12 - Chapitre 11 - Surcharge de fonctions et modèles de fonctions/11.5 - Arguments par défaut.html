11.5 — Arguments par défaut

Un argument par défaut (default argument) est une valeur par défaut fournie pour un paramètre de fonction. Par exemple :

void print(int x, int y=10) // 10 est l'argument par défaut
{
    std::cout << "x: " << x << '\n';
    std::cout << "y: " << y << '\n';
}

Lors d'un appel de fonction, l'appelant peut, s'il le souhaite, fournir un argument pour tout paramètre ayant un argument par défaut. Si l'appelant fournit un argument, c'est la valeur de cet argument dans l'appel qui est utilisée. Sinon, c'est la valeur de l'argument par défaut qui est utilisée.

Considérez le programme suivant :

#include <iostream>

void print(int x, int y=4) // 4 est l'argument par défaut
{
    std::cout << "x: " << x << '\n';
    std::cout << "y: " << y << '\n';
}

int main()
{
    print(1, 2); // y utilisera l'argument fourni par l'utilisateur, 2
    print(3); // y utilisera l'argument par défaut 4, comme si nous avions appelé print(3, 4)

    return 0;
}

Ce programme produit la sortie suivante :


x: 1
y: 2
x: 3
y: 4

Dans le premier appel de fonction, l'appelant a fourni des arguments explicites pour les deux paramètres, ce sont donc ces valeurs qui sont utilisées. Dans le second appel, l'appelant a omis le second argument, la valeur par défaut 4 est donc utilisée.

Notez que le signe égal est obligatoire pour spécifier un argument par défaut. Les notations avec parenthèses ou avec initialisation par accolades ne fonctionnent pas :

void foo(int x = 5);   // ok
void goo(int x ( 5 )); // erreur de compilation
void boo(int x { 5 }); // erreur de compilation

Chose peut-être surprenante, les arguments par défaut sont gérés par le compilateur au niveau de l'appel. Dans l'exemple ci-dessus, lorsque le compilateur rencontre print(3), il réécrit cet appel de fonction sous la forme print(3, 4), afin que le nombre d'arguments corresponde au nombre de paramètres. L'appel réécrit fonctionne ensuite normalement.

Point clé

Les arguments par défaut sont insérés par le compilateur à l'endroit de l'appel de fonction.

Les arguments par défaut sont très utilisés en C++, et vous en rencontrerez souvent dans le code que vous lirez (et dans les prochaines leçons).

Quand utiliser des arguments par défaut

Les arguments par défaut sont une excellente option lorsqu'une fonction a besoin d'une valeur qui possède une valeur par défaut raisonnable, mais que vous souhaitez laisser l'appelant la remplacer s'il le désire.

Par exemple, voici quelques prototypes de fonctions pour lesquels des arguments par défaut peuvent être couramment utilisés :

int rollDie(int sides=6);
void openLogFile(std::string filename="default.log");

Note de l'auteur

Parce que l'utilisateur peut choisir de fournir une valeur d'argument spécifique ou d'utiliser la valeur par défaut, un paramètre pour lequel une valeur par défaut est fournie est parfois appelé paramètre optionnel (optional parameter). Toutefois, le terme paramètre optionnel désigne aussi plusieurs autres types de paramètres (notamment les paramètres passés par adresse et les paramètres utilisant std::optional). Nous recommandons donc d'éviter ce terme.

Les arguments par défaut sont également utiles lorsque nous devons ajouter un nouveau paramètre à une fonction existante. Si nous ajoutons un nouveau paramètre sans argument par défaut, cela casse tous les appels existants de la fonction (qui ne fournissent pas d'argument pour ce paramètre). Il peut en résulter une mise à jour importante des appels existants (et cela peut même être impossible si vous ne possédez pas le code appelant). En revanche, si nous ajoutons un nouveau paramètre avec un argument par défaut, tous les appels existants continuent de fonctionner (ils utilisent la valeur par défaut du paramètre), tout en permettant aux nouveaux appels de fournir un argument explicite s'ils le souhaitent.

Plusieurs arguments par défaut

Une fonction peut avoir plusieurs paramètres dotés d'arguments par défaut :

#include <iostream>

void print(int x=10, int y=20, int z=30)
{
    std::cout << "Values: " << x << " " << y << " " << z << '\n';
}

int main()
{
    print(1, 2, 3); // tous les arguments explicites
    print(1, 2); // le dernier argument (le plus à droite) utilise sa valeur par défaut
    print(1); // les deux derniers arguments (les plus à droite) utilisent leur valeur par défaut
    print(); // tous les arguments utilisent leur valeur par défaut

    return 0;
}

Le programme produit la sortie suivante :


Values: 1 2 3
Values: 1 2 30
Values: 1 20 30
Values: 10 20 30

Le C++ ne prend pas en charge (jusqu'à C++23 inclus) une syntaxe d'appel telle que print(,,3) (qui permettrait de fournir une valeur explicite pour z tout en utilisant les arguments par défaut de x et y). Cela a trois conséquences importantes :

  1. Lors d'un appel de fonction, les arguments explicitement fournis doivent être les arguments les plus à gauche (les arguments dotés d'une valeur par défaut ne peuvent pas être sautés).

Par exemple :

void print(std::string_view sv="Hello", double d=10.0);

int main()
{
    print();           // correct : les deux arguments utilisent leur valeur par défaut
    print("Macaroni"); // correct : d utilise la valeur par défaut 10.0
    print(20.0);       // erreur : ne correspond à aucune fonction ci-dessus (impossible de sauter l'argument sv)

    return 0;
}
  1. Si un paramètre reçoit un argument par défaut, tous les paramètres suivants (à droite) doivent eux aussi recevoir un argument par défaut.

Ce qui suit n'est pas autorisé :

void print(int x=10, int y); // non autorisé

Règle

Si un paramètre reçoit un argument par défaut, tous les paramètres suivants (à droite) doivent eux aussi recevoir un argument par défaut.

  1. Si plusieurs paramètres ont un argument par défaut, le paramètre le plus à gauche devrait être celui que l'utilisateur est le plus susceptible de fournir explicitement.

Les arguments par défaut ne peuvent pas être redéclarés et doivent être déclarés avant leur utilisation

Une fois déclaré, un argument par défaut ne peut pas être redéclaré dans la même unité de traduction. Cela signifie que, pour une fonction disposant à la fois d'une déclaration anticipée (forward declaration) et d'une définition, l'argument par défaut peut être déclaré soit dans la déclaration anticipée, soit dans la définition, mais pas dans les deux.

#include <iostream>

void print(int x, int y=4); // déclaration anticipée

void print(int x, int y=4) // erreur de compilation : redéfinition de l'argument par défaut
{
    std::cout << "x: " << x << '\n';
    std::cout << "y: " << y << '\n';
}

L'argument par défaut doit également être déclaré dans l'unité de traduction avant de pouvoir être utilisé :

#include <iostream>

void print(int x, int y); // déclaration anticipée, sans argument par défaut

int main()
{
    print(3); // erreur de compilation : l'argument par défaut de y n'a pas encore été défini

    return 0;
}

void print(int x, int y=4)
{
    std::cout << "x: " << x << '\n';
    std::cout << "y: " << y << '\n';
}

La bonne pratique consiste à déclarer l'argument par défaut dans la déclaration anticipée et non dans la définition de la fonction, car la déclaration anticipée est plus susceptible d'être vue par d'autres fichiers et incluse avant l'utilisation (en particulier si elle se trouve dans un fichier d'en-tête).

Dans foo.h :

#ifndef FOO_H
#define FOO_H
void print(int x, int y=4);
#endif

Dans main.cpp :

#include "foo.h"
#include <iostream>

void print(int x, int y)
{
    std::cout << "x: " << x << '\n';
    std::cout << "y: " << y << '\n';
}

int main()
{
    print(5);

    return 0;
}

Notez que, dans l'exemple ci-dessus, nous pouvons utiliser l'argument par défaut de la fonction print() parce que main.cpp inclut foo.h, qui contient la déclaration anticipée définissant l'argument par défaut.

Bonne pratique

Si la fonction possède une déclaration anticipée (surtout si elle se trouve dans un fichier d'en-tête), placez-y l'argument par défaut. Sinon, placez l'argument par défaut dans la définition de la fonction.

Arguments par défaut et surcharge de fonctions

Les fonctions dotées d'arguments par défaut peuvent être surchargées. Par exemple, ce qui suit est autorisé :

#include <iostream>
#include <string_view>

void print(std::string_view s)
{
    std::cout << s << '\n';
}

void print(char c = ' ')
{
    std::cout << c << '\n';
}

int main()
{
    print("Hello, world"); // correspond à print(std::string_view)
    print('a');            // correspond à print(char)
    print();               // correspond à print(char)

    return 0;
}

L'appel de fonction print() appelle en réalité print(char), qui agit comme si l'utilisateur avait explicitement appelé print(' ').

Considérez maintenant ce cas :

void print(int x);                  // signature print(int)
void print(int x, int y = 10);      // signature print(int, int)
void print(int x, double y = 20.5); // signature print(int, double)

Les valeurs par défaut ne font pas partie de la signature d'une fonction. Ces déclarations de fonctions sont donc des surcharges distinctes.

Contenu connexe

Nous abordons la différenciation des surcharges de fonctions dans la leçon 11.2 -- Différenciation des surcharges de fonctions

Les arguments par défaut peuvent conduire à des correspondances ambiguës

Les arguments par défaut peuvent facilement conduire à des appels de fonctions ambigus :

void foo(int x = 0)
{
}

void foo(double d = 0.0)
{
}

int main()
{
    foo(); // appel de fonction ambigu

    return 0;
}

Dans cet exemple, le compilateur ne peut pas déterminer si foo() doit correspondre à foo(0) ou à foo(0.0).

Voici un exemple un peu plus complexe :

void print(int x);                  // signature print(int)
void print(int x, int y = 10);      // signature print(int, int)
void print(int x, double y = 20.5); // signature print(int, double)

int main()
{
    print(1, 2);   // correspond à print(int, int)
    print(1, 2.5); // correspond à print(int, double)
    print(1);      // appel de fonction ambigu

    return 0;
}

Pour l'appel print(1), le compilateur ne peut pas déterminer s'il doit correspondre à print(int), print(int, int) ou print(int, double).

Si nous voulons appeler print(int, int) ou print(int, double), nous pouvons toujours préciser explicitement le second paramètre. Mais que faire si nous voulons appeler print(int) ? Il n'est pas évident de savoir comment le faire.

Les arguments par défaut ne fonctionnent pas pour les fonctions appelées via des pointeurs de fonction (avancé)

Nous traitons ce sujet dans la leçon 20.1 -- Pointeurs de fonction. Les arguments par défaut n'étant pas pris en compte avec cette méthode, celle-ci offre aussi un moyen de contourner le problème pour appeler une fonction qui serait autrement ambiguë à cause des arguments par défaut.
