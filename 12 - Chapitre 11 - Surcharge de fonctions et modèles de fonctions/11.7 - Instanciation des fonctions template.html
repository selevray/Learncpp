11.7 — Instanciation des fonctions template

Dans la leçon précédente (11.6 -- Modèles de fonctions), nous avons présenté les fonctions template et transformé une fonction max() ordinaire en un modèle de fonction max<T> :

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

Dans cette leçon, nous allons nous concentrer sur l'utilisation des fonctions template.

Utiliser une fonction template

Les fonctions template ne sont pas vraiment des fonctions : leur code n'est pas compilé ni exécuté directement. Une fonction template a un seul rôle : générer des fonctions, qui, elles, sont compilées et exécutées.

Pour utiliser notre modèle de fonction max<T>, nous pouvons effectuer un appel de fonction avec la syntaxe suivante :


max<type_effectif>(arg1, arg2); // type_effectif est un type réel, comme int ou double

Cela ressemble beaucoup à un appel de fonction ordinaire. La différence principale est l'ajout, entre chevrons, du type (appelé argument template), qui indique le type réel à utiliser à la place du type template T.

Voyons cela dans un exemple simple :

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n'; // instancie et appelle la fonction max<int>(int, int)

    return 0;
}

Lorsque le compilateur rencontre l'appel max<int>(1, 2), il détermine qu'une définition de max<int>(int, int) n'existe pas encore. Il utilise alors implicitement notre modèle max<T> pour en créer une.

Le processus de création de fonctions (avec des types précis) à partir de fonctions template (avec des types template) s'appelle instanciation de fonction template (ou simplement instanciation). Lorsqu'une fonction est instanciée à cause d'un appel de fonction, on parle d'instanciation implicite. Une fonction instanciée à partir d'un modèle s'appelle techniquement une spécialisation, mais dans le langage courant on parle souvent d'instance de fonction. Le modèle à partir duquel une spécialisation est produite s'appelle un modèle primaire. Les instances de fonctions sont, à tous égards, des fonctions ordinaires.

Nomenclature

Le terme « spécialisation » est plus souvent utilisé pour désigner la spécialisation explicite, qui nous permet de définir explicitement une spécialisation (au lieu de la laisser être instanciée implicitement à partir du modèle primaire). Nous abordons la spécialisation explicite dans la leçon 26.3 -- Spécialisation de fonctions template.

Le processus d'instanciation d'une fonction est simple : le compilateur clone essentiellement le modèle primaire et remplace le type template (T) par le type réel que nous avons spécifié (int).

Ainsi, lorsque nous appelons max<int>(1, 2), la spécialisation instanciée ressemble à ceci :

template<> // ignorez cela pour l'instant
int max<int>(int x, int y) // la fonction générée max<int>(int, int)
{
    return (x < y) ? y : x;
}

Voici le même exemple que précédemment, montrant ce que le compilateur compile réellement une fois toutes les instanciations effectuées :

#include <iostream>

// une déclaration de notre modèle de fonction (nous n'avons plus besoin de la définition)
template <typename T>
T max(T x, T y);

template<>
int max<int>(int x, int y) // la fonction générée max<int>(int, int)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n'; // instancie et appelle la fonction max<int>(int, int)

    return 0;
}

Vous pouvez compiler ce programme vous-même et constater qu'il fonctionne. Un modèle de fonction n'est instancié que la première fois qu'un appel à la fonction est effectué dans chaque unité de traduction. Les appels suivants sont redirigés vers la fonction déjà instanciée.

Inversement, si aucun appel n'est fait à un modèle de fonction, celui-ci ne sera pas instancié dans cette unité de traduction.

Prenons un autre exemple :

#include <iostream>

template <typename T>
T max(T x, T y) // modèle de fonction pour max(T, T)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n';    // instancie et appelle la fonction max<int>(int, int)
    std::cout << max<int>(4, 3) << '\n';    // appelle la fonction max<int>(int, int) déjà instanciée
    std::cout << max<double>(1, 2) << '\n'; // instancie et appelle la fonction max<double>(double, double)

    return 0;
}

Cela fonctionne de manière similaire à l'exemple précédent, mais ici le modèle de fonction sert à générer deux fonctions : une fois en remplaçant T par int, et une autre fois en remplaçant T par double. Après toutes les instanciations, le programme ressemble à ceci :

#include <iostream>

// une déclaration de notre modèle de fonction (nous n'avons plus besoin de la définition)
template <typename T>
T max(T x, T y);

template<>
int max<int>(int x, int y) // la fonction générée max<int>(int, int)
{
    return (x < y) ? y : x;
}

template<>
double max<double>(double x, double y) // la fonction générée max<double>(double, double)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n';    // instancie et appelle la fonction max<int>(int, int)
    std::cout << max<int>(4, 3) << '\n';    // appelle la fonction max<int>(int, int) déjà instanciée
    std::cout << max<double>(1, 2) << '\n'; // instancie et appelle la fonction max<double>(double, double)

    return 0;
}

Une remarque supplémentaire : lorsque nous instancions max<double>, la fonction instanciée a des paramètres de type double. Comme nous avons fourni des arguments int, ces arguments sont implicitement convertis en double.

Déduction des arguments template

Dans la plupart des cas, les types réels que nous voulons utiliser pour l'instanciation correspondent au type de nos paramètres de fonction. Par exemple :

std::cout << max<int>(1, 2) << '\n'; // on précise que l'on veut appeler max<int>

Dans cet appel, nous avons indiqué que nous voulons remplacer T par int, et nous appelons aussi la fonction avec des arguments int.

Lorsque le type des arguments correspond au type réel souhaité, nous n'avons pas besoin de le préciser. Nous pouvons alors utiliser la déduction des arguments template (template argument deduction), qui permet au compilateur de déduire le type réel à utiliser à partir des types des arguments de l'appel.

Par exemple, au lieu d'écrire :

std::cout << max<int>(1, 2) << '\n'; // on précise que l'on veut appeler max<int>

Nous pouvons écrire l'une de ces deux formes :

std::cout << max<>(1, 2) << '\n';
std::cout << max(1, 2) << '\n';

Dans les deux cas, le compilateur constate que nous n'avons pas fourni de type réel. Il tente donc de déduire, à partir des arguments de la fonction, un type réel qui lui permet de générer une fonction max() dont tous les paramètres template correspondent au type des arguments fournis. Dans cet exemple, le compilateur déduit qu'utiliser le modèle de fonction max<T> avec le type réel int lui permet d'instancier max<int>(int, int), de sorte que le type des deux paramètres (int) corresponde au type des arguments fournis (int).

La différence entre les deux cas tient à la manière dont le compilateur résout l'appel de fonction parmi un ensemble de fonctions surchargées. Dans la première forme (avec les chevrons vides), le compilateur ne considère que les surcharges de fonctions template max<int> pour déterminer quelle fonction appeler. Dans la seconde forme (sans chevrons), le compilateur considère à la fois les surcharges template max<int> et les surcharges non-template max. Lorsque ce dernier cas aboutit à une fonction template et à une fonction non-template également viables, la fonction non-template est préférée.

Point clé

La syntaxe d'appel de fonction normale préfère une fonction non-template à une fonction instanciée à partir d'un modèle, lorsque les deux sont tout aussi viables.

Par exemple :

#include <iostream>

template <typename T>
T max(T x, T y)
{
    std::cout << "called max<int>(int, int)\n";
    return (x < y) ? y : x;
}

int max(int x, int y)
{
    std::cout << "called max(int, int)\n";
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max<int>(1, 2) << '\n'; // appelle max<int>(int, int)
    std::cout << max<>(1, 2) << '\n';    // déduit max<int>(int, int) (les fonctions non-template ne sont pas considérées)
    std::cout << max(1, 2) << '\n';      // appelle max(int, int)

    return 0;
}

Remarquez que la syntaxe de la seconde forme est identique à celle d'un appel de fonction normal ! Dans la plupart des cas, c'est cette syntaxe d'appel normale que nous utiliserons pour appeler des fonctions instanciées à partir d'un modèle de fonction.

Plusieurs raisons à cela :

  • La syntaxe est plus concise.
  • Il est rare d'avoir à la fois une fonction non-template correspondante et un modèle de fonction.
  • Si nous avons à la fois une fonction non-template et un modèle de fonction correspondants, nous préférerons généralement appeler la fonction non-template.

Ce dernier point peut ne pas sembler évident. Un modèle de fonction a une implémentation qui fonctionne pour plusieurs types, et il doit donc être générique. Une fonction non-template ne traite qu'une combinaison précise de types. Son implémentation peut être plus optimisée ou plus spécialisée pour ces types précis que la version template. Par exemple :

#include <iostream>

// Ce modèle de fonction peut traiter de nombreux types, donc son implémentation est générique
template <typename T>
void print(T x)
{
    std::cout << x; // affiche T de la manière habituelle
}

// Cette fonction n'a qu'à gérer l'affichage d'un bool, elle peut donc spécialiser
// l'affichage d'un bool
void print(bool x)
{
    std::cout << std::boolalpha << x; // affiche le bool sous la forme true ou false, et non 1 ou 0
}

int main()
{
    print<bool>(true); // appelle print<bool>(bool) -- affiche 1
    std::cout << '\n';

    print<>(true);     // déduit print<bool>(bool) (les fonctions non-template ne sont pas considérées) -- affiche 1
    std::cout << '\n';

    print(true);       // appelle print(bool) -- affiche true
    std::cout << '\n';

    return 0;
}

Bonne pratique

Privilégiez la syntaxe d'appel de fonction normale lorsque vous appelez une fonction instanciée à partir d'un modèle de fonction (sauf si vous avez besoin que la version template soit préférée à une fonction non-template correspondante).

Fonctions template avec des paramètres non-template

Il est possible de créer des modèles de fonctions qui ont à la fois des paramètres template et des paramètres non-template. Les paramètres de type peuvent correspondre à n'importe quel type, et les paramètres non-template fonctionnent comme les paramètres des fonctions ordinaires.

Par exemple :

// T est un paramètre template de type
// double est un paramètre non-template
// Nous n'avons pas besoin de nommer ces paramètres puisqu'ils ne sont pas utilisés
template <typename T>
int someFcn(T, double)
{
    return 5;
}

int main()
{
    someFcn(1, 3.4); // correspond à someFcn(int, double)
    someFcn(1, 3.4f); // correspond à someFcn(int, double) -- le float est promu en double
    someFcn(1.2, 3.4); // correspond à someFcn(double, double)
    someFcn(1.2f, 3.4); // correspond à someFcn(float, double)
    someFcn(1.2f, 3.4f); // correspond à someFcn(float, double) -- le float est promu en double

    return 0;
}

Ce modèle de fonction a un premier paramètre templatisé, tandis que le second paramètre est fixé au type double. Notez que le type de retour peut lui aussi être quelconque. Dans ce cas, notre fonction renvoie toujours une valeur int.

Les fonctions instanciées ne compilent pas toujours

Considérons le programme suivant :

#include <iostream>

template <typename T>
T addOne(T x)
{
    return x + 1;
}

int main()
{
    std::cout << addOne(1) << '\n';
    std::cout << addOne(2.3) << '\n';

    return 0;
}

Le compilateur compile et exécute effectivement ceci :

#include <iostream>

template <typename T>
T addOne(T x);

template<>
int addOne<int>(int x)
{
    return x + 1;
}

template<>
double addOne<double>(double x)
{
    return x + 1;
}

int main()
{
    std::cout << addOne(1) << '\n';   // appelle addOne<int>(int)
    std::cout << addOne(2.3) << '\n'; // appelle addOne<double>(double)

    return 0;
}

ce qui produit le résultat suivant :


2
3.3

Mais que se passe-t-il si nous essayons quelque chose comme ceci ?

#include <iostream>
#include <string>

template <typename T>
T addOne(T x)
{
    return x + 1;
}

int main()
{
    std::string hello { "Hello, world!" };
    std::cout << addOne(hello) << '\n';

    return 0;
}

Lorsque le compilateur tente de résoudre addOne(hello), il ne trouve pas de fonction non-template correspondant à addOne(std::string), mais il trouve notre modèle de fonction addOne(T) et détermine qu'il peut en générer une fonction addOne(std::string). Le compilateur génère donc et compile ceci :

#include <iostream>
#include <string>

template <typename T>
T addOne(T x);

template<>
std::string addOne<std::string>(std::string x)
{
    return x + 1;
}

int main()
{
    std::string hello{ "Hello, world!" };
    std::cout << addOne(hello) << '\n';

    return 0;
}

Cependant, cela produira une erreur de compilation, car x + 1 n'a pas de sens lorsque x est une std::string. La solution évidente consiste simplement à ne pas appeler addOne() avec un argument de type std::string.

Les fonctions instanciées n'ont pas toujours de sens sémantiquement

Le compilateur compilera avec succès une fonction template instanciée tant qu'elle est correcte syntaxiquement. Cependant, le compilateur n'a aucun moyen de vérifier qu'une telle fonction a un sens sur le plan sémantique.

Par exemple :

#include <iostream>

template <typename T>
T addOne(T x)
{
    return x + 1;
}

int main()
{
    std::cout << addOne("Hello, world!") << '\n';

    return 0;
}

Dans cet exemple, nous appelons addOne() sur un littéral de chaîne de style C. Qu'est-ce que cela signifie réellement sur le plan sémantique ? Qui sait !

Étonnamment, comme C++ autorise syntaxiquement l'addition d'une valeur entière à un littéral de chaîne (nous aborderons ce point dans la future leçon 17.9 -- Arithmétique des pointeurs et indexation), l'exemple ci-dessus compile et produit le résultat suivant :


ello, world!

Avertissement

Le compilateur instanciera et compilera des modèles de fonctions qui n'ont pas de sens sémantiquement, tant qu'ils sont syntaxiquement valides. C'est à vous de vous assurer d'appeler ces modèles de fonctions avec des arguments qui ont un sens.

Pour les lecteurs avancés

Nous pouvons indiquer au compilateur que l'instanciation de modèles de fonctions avec certains arguments doit être interdite. Pour cela, on utilise la spécialisation de fonctions template, qui permet de surcharger un modèle de fonction pour un ensemble précis d'arguments template, ainsi que = delete, qui indique au compilateur que toute utilisation de la fonction doit provoquer une erreur de compilation.

#include <iostream>
#include <string>

template <typename T>
T addOne(T x)
{
    return x + 1;
}

// Utilise la spécialisation de fonctions template pour indiquer au compilateur que addOne(const char*) doit provoquer une erreur de compilation
// const char* correspondra à un littéral de chaîne
template <>
const char* addOne(const char* x) = delete;

int main()
{
    std::cout << addOne("Hello, world!") << '\n'; // erreur de compilation

    return 0;
}

Nous abordons la spécialisation de fonctions template dans la leçon 26.3 -- Spécialisation de fonctions template.

Modèles de fonctions et arguments par défaut pour les paramètres non-template

Comme pour les fonctions ordinaires, les modèles de fonctions peuvent avoir des arguments par défaut pour leurs paramètres non-template. Chaque fonction instanciée à partir du modèle utilisera le même argument par défaut.

Par exemple :

#include <iostream>

template <typename T>
void print(T val, int times=1)
{
    while (times--)
    {
        std::cout << val;
    }
}

int main()
{
    print(5);      // affiche 5 une fois
    print('a', 3); // affiche 'a' trois fois

    return 0;
}

Ce programme affiche :


5aaa

Attention aux modèles de fonctions avec des variables statiques locales modifiables

Dans la leçon 7.11 -- Variables locales statiques, nous avons vu les variables locales statiques, c'est-à-dire des variables locales de durée statique (elles persistent pendant toute la durée du programme).

Lorsqu'une variable locale statique est utilisée dans un modèle de fonction, chaque fonction instanciée à partir de ce modèle possède sa propre version de la variable locale statique. Ce n'est en général pas un problème si la variable locale statique est const. Mais si la variable locale statique est modifiée, les résultats peuvent être inattendus.

Par exemple :

#include <iostream>

// Voici un modèle de fonction avec une variable locale statique qui est modifiée
template <typename T>
void printIDAndValue(T value)
{
    static int id{ 0 };
    std::cout << ++id << ") " << value << '\n';
}

int main()
{
    printIDAndValue(12);
    printIDAndValue(13);

    printIDAndValue(14.5);

    return 0;
}

Ce programme produit le résultat suivant :


1) 12
2) 13
1) 14.5

Vous vous attendiez peut-être à ce que la dernière ligne affiche 3) 14.5. Pourtant, voici ce que le compilateur compile et exécute réellement :

#include <iostream>

template <typename T>
void printIDAndValue(T value);

template <>
void printIDAndValue<int>(int value)
{
    static int id{ 0 };
    std::cout << ++id << ") " << value << '\n';
}

template <>
void printIDAndValue<double>(double value)
{
    static int id{ 0 };
    std::cout << ++id << ") " << value << '\n';
}

int main()
{
    printIDAndValue(12);   // appelle printIDAndValue<int>()
    printIDAndValue(13);   // appelle printIDAndValue<int>()

    printIDAndValue(14.5); // appelle printIDAndValue<double>()

    return 0;
}

Notez que printIDAndValue<int> et printIDAndValue<double> ont chacune leur propre variable statique locale nommée id, indépendante de l'autre, et qu'elles ne partagent pas la même variable.

Programmation générique

Comme les types template peuvent être remplacés par n'importe quel type réel, on qualifie parfois les types template de types génériques. Et comme les templates peuvent être écrits sans considération pour des types précis, la programmation avec des templates est parfois appelée programmation générique. Alors que C++ met typiquement l'accent sur les types et leur vérification, la programmation générique nous permet, à l'inverse, de nous concentrer sur la logique des algorithmes et la conception des structures de données, sans avoir à nous soucier autant des informations de type.

Conclusion

Une fois que vous serez habitué à écrire des modèles de fonctions, vous constaterez qu'ils ne demandent pas beaucoup plus de temps à écrire que des fonctions avec des types réels. Les modèles de fonctions peuvent réduire de façon significative la maintenance du code et le nombre d'erreurs, en minimisant la quantité de code à écrire et à maintenir.

Les modèles de fonctions ont tout de même quelques inconvénients, qu'il serait malvenu de passer sous silence. D'abord, le compilateur créera (et compilera) une fonction pour chaque appel avec un ensemble unique de types d'arguments. Ainsi, même si les modèles de fonctions sont compacts à écrire, ils peuvent se développer en une quantité de code démesurée, ce qui peut entraîner un gonflement du code (code bloat) et des temps de compilation plus longs. Le plus gros inconvénient des modèles de fonctions est qu'ils produisent des messages d'erreur étranges, à la limite de l'illisible, bien plus difficiles à déchiffrer que ceux des fonctions ordinaires. Ces messages peuvent être assez intimidants, mais une fois que vous comprenez ce qu'ils cherchent à vous dire, les problèmes qu'ils signalent sont souvent assez simples à résoudre.

Ces inconvénients sont relativement mineurs au regard de la puissance et de la sécurité que les templates apportent à votre boîte à outils de programmation. Utilisez donc les templates sans hésiter partout où vous avez besoin de flexibilité sur les types ! Une bonne règle empirique consiste à écrire d'abord des fonctions ordinaires, puis à les transformer en modèles de fonctions si vous constatez le besoin d'une surcharge pour différents types de paramètres.

Bonne pratique

Utilisez les modèles de fonctions pour écrire du code générique, capable de fonctionner avec une grande variété de types, chaque fois que le besoin se présente.
