11.x — Résumé du chapitre 11 et quiz

Bon travail. Les templates de fonctions peuvent sembler assez complexes, mais ce sont un moyen très puissant de faire fonctionner votre code avec des objets de types différents. Nous verrons beaucoup plus de choses sur les templates dans les prochains chapitres, alors accrochez-vous.

Révision du chapitre

La surcharge de fonctions (function overloading) nous permet de créer plusieurs fonctions portant le même nom, à condition que chacune d'elles ait un ensemble de types de paramètres différent (ou que les fonctions puissent être différenciées d'une autre manière). Une telle fonction est appelée fonction surchargée (overloaded function), ou plus simplement surcharge (overload). Les types de retour ne sont pas pris en compte pour les différencier.

Lors de la résolution des fonctions surchargées, si aucune correspondance exacte n'est trouvée, le compilateur privilégie les fonctions surchargées qui peuvent être appelées via des promotions numériques plutôt que celles qui nécessitent des conversions numériques. Lorsqu'un appel est effectué vers une fonction surchargée, le compilateur essaie de faire correspondre l'appel à la surcharge appropriée en fonction des arguments utilisés. C'est ce qu'on appelle la résolution de surcharge (overload resolution).

Une correspondance ambiguë (ambiguous match) se produit lorsque le compilateur trouve deux fonctions ou plus pouvant correspondre à un appel d'une fonction surchargée, et qu'il ne peut pas déterminer laquelle est la meilleure.

Un argument par défaut (default argument) est une valeur par défaut fournie pour un paramètre de fonction. Les paramètres ayant un argument par défaut doivent toujours être les paramètres les plus à droite, et ils ne sont pas utilisés pour différencier les fonctions lors de la résolution des fonctions surchargées.

Les templates de fonctions (function templates) nous permettent de créer une définition semblable à une fonction, qui sert de modèle pour créer des fonctions apparentées. Dans un template de fonction, nous utilisons des paramètres de type de template (type template parameters) comme espaces réservés pour les types que nous voulons spécifier plus tard. La syntaxe qui indique au compilateur que nous définissons un template et qui déclare les types du template s'appelle déclaration de paramètres de template (template parameter declaration).

Le processus de création de fonctions (avec des types concrets) à partir de templates de fonctions (avec des types de template) est appelé instanciation de template de fonction (function template instantiation), ou plus simplement instanciation (instantiation). Lorsque ce processus se produit suite à un appel de fonction, on parle d'instanciation implicite (implicit instantiation). Une fonction instanciée est appelée instance de fonction (function instance), ou plus simplement instance, ou parfois fonction template (template function).

La déduction d'arguments de template (template argument deduction) permet au compilateur de déduire le type réel à utiliser pour instancier une fonction à partir des arguments de l'appel de fonction. La déduction d'arguments de template ne réalise pas de conversion de type.

Les types de template sont parfois appelés types génériques (generic types), et la programmation utilisant des templates est parfois appelée programmation générique (generic programming).

En C++20, lorsque le mot-clé auto est utilisé comme type de paramètre dans une fonction normale, le compilateur convertit automatiquement la fonction en template de fonction, chaque paramètre auto devenant un paramètre de type de template indépendant. Cette méthode de création de template de fonction est appelée template de fonction abrégé (abbreviated function template).

Un paramètre de template non typé (non-type template parameter) est un paramètre de template de type fixe qui sert d'espace réservé pour une valeur constexpr passée en argument de template.

Quiz

Question n° 1

1a) Quelle est la sortie de ce programme, et pourquoi ?

#include <iostream>

void print(int x)
{
    std::cout << "int " << x << '\n';
}

void print(double x)
{
    std::cout << "double " << x << '\n';
}

int main()
{
    short s { 5 };
    print(s);

    return 0;
}
Solution

La sortie est int 5. La conversion d'un short en int est une promotion numérique, alors que la conversion d'un short en double est une conversion numérique. Le compilateur privilégie l'option qui est une promotion numérique plutôt que celle qui est une conversion numérique.

1b) Pourquoi le programme suivant ne compile-t-il pas ?

#include <iostream>

void print()
{
    std::cout << "void\n";
}

void print(int x=0)
{
    std::cout << "int " << x << '\n';
}

void print(double x)
{
    std::cout << "double " << x << '\n';
}

int main()
{
    print(5.0f);
    print();

    return 0;
}
Solution

Comme les paramètres ayant un argument par défaut ne sont pas pris en compte pour la résolution des fonctions surchargées, le compilateur ne peut pas savoir si l'appel print() doit correspondre à print() ou à print(int x=0).

1c) Pourquoi le programme suivant ne compile-t-il pas ?

#include <iostream>

void print(long x)
{
    std::cout << "long " << x << '\n';
}

void print(double x)
{
    std::cout << "double " << x << '\n';
}

int main()
{
    print(5);

    return 0;
}
Solution

Le littéral 5 est un int. La conversion d'un int en long ou en double est une conversion numérique, et le compilateur ne peut pas déterminer quelle fonction correspond le mieux.

Question n° 3

Quelle est la sortie de ce programme, et pourquoi ?

#include <iostream>

template <typename T>
int count(T) // This is the same as int count(T x), except we're not giving the parameter a name since we don't use the parameter
{
    static int c { 0 };
    return ++c;
}

int main()
{
    std::cout << count(1) << '\n';
    std::cout << count(1) << '\n';
    std::cout << count(2.3) << '\n';
    std::cout << count<double>(1) << '\n';

    return 0;
}
Solution 

1
2
1
2

Lors de l'appel count(1), le compilateur instancie la fonction count<int>(int) et l'appelle. Elle renvoie la valeur 1.

Lors du second appel count(1), le compilateur constate que count<int>(int) existe déjà, et l'appelle à nouveau. Elle renvoie la valeur 2.

Lors de l'appel count(2.3), le compilateur instancie la fonction de prototype count<double>(double) et l'appelle. Il s'agit d'une nouvelle fonction disposant de sa propre variable static c, donc elle renvoie la valeur 1.

Lors de l'appel count<double>(1), le compilateur constate que nous demandons explicitement la version double de count(). Cette fonction existe déjà grâce à l'instruction précédente, donc count<double>(double) est appelée et l'argument int est implicitement converti en double. Cette fonction renvoie la valeur 2.

Question n° 4

Quelle est la sortie de ce programme ?

#include <iostream>

int foo(int n)
{
    return n + 10;
}

template <typename T>
int foo(T n)
{
    return n;
}

int main()
{
    std::cout << foo(1) << '\n'; // #1

    short s { 2 };
    std::cout << foo(s) << '\n'; // #2

    std::cout << foo<int>(4) << '\n'; // #3

    std::cout << foo<int>(s) << '\n'; // #4

    std::cout << foo<>(6) << '\n'; // #5

    return 0;
}
Solution 

11
2
4
2
6

Dans le cas 1, foo(1) correspond exactement à foo(int), donc la fonction non template foo(int) est appelée.

Dans le cas 2, foo(s) ne correspond pas exactement à la fonction non template foo(int), mais l'argument s peut être converti en int, donc foo(int) est un candidat. Cependant, le compilateur préfère utiliser le template de fonction foo<T>(T) pour générer la correspondance exacte foo<short>(short). C'est donc foo<short>(short) qui est appelée.

Dans le cas 3, foo<int>(4) est un appel explicite à foo<int>, donc foo(int) n'est pas prise en compte. Le compilateur génère foo<int>(int) et l'appelle.

Dans le cas 4, il s'agit également d'un appel explicite à foo<int>. Le compilateur convertit (promeut) l'argument s en int pour correspondre au paramètre.

Dans le cas 5, cette syntaxe ne correspond qu'aux templates de fonctions, donc foo(int) n'est pas prise en compte. foo<int>(int) est appelée.
