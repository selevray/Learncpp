11.9 — Paramètres de modèle non-type

Dans les leçons précédentes, nous avons étudié la création de modèles de fonctions utilisant des paramètres de modèle de type. Un paramètre de modèle de type sert de substitut à un type réel, passé en argument de modèle.

Les paramètres de modèle de type sont de loin les plus courants, mais il existe un autre genre de paramètre de modèle qu'il est utile de connaître : le paramètre de modèle non-type.

Paramètres de modèle non-type

Un paramètre de modèle non-type est un paramètre de modèle de type fixe, qui sert de substitut à une valeur constexpr passée en argument de modèle.

Un paramètre de modèle non-type peut être de l'un des types suivants :

  • Un type entier
  • Un type énumération
  • std::nullptr_t
  • Un type à virgule flottante (depuis C++20)
  • Un pointeur ou une référence vers un objet
  • Un pointeur ou une référence vers une fonction
  • Un pointeur ou une référence vers une fonction membre
  • Un type classe littéral (depuis C++20)

Nous avons rencontré notre premier exemple de paramètre de modèle non-type lorsque nous avons parlé de std::bitset dans la leçon O.1 -- Bit flags and bit manipulation via std::bitset :

#include <bitset>

int main()
{
    std::bitset<8> bits{ 0b0000'0101 }; // Le <8> est un paramètre de modèle non-type

    return 0;
}

Dans le cas de std::bitset, le paramètre de modèle non-type indique à std::bitset le nombre de bits à stocker.

Définir nos propres paramètres de modèle non-type

Voici un exemple simple de fonction utilisant un paramètre de modèle non-type de type int :

#include <iostream>

template <int N> // déclare un paramètre de modèle non-type de type int nommé N
void print()
{
    std::cout << N << '\n'; // utilise la valeur de N ici
}

int main()
{
    print<5>(); // 5 est notre argument de modèle non-type

    return 0;
}

Cet exemple affiche :


5

À la ligne 3, nous déclarons notre paramètre de modèle. Entre les chevrons, nous définissons un paramètre de modèle non-type nommé N, qui sera un substitut pour une valeur de type int. Dans la fonction print(), nous utilisons la valeur de N.

À la ligne 11, nous appelons la fonction print() avec la valeur int 5 comme argument de modèle non-type. Lorsque le compilateur rencontre cet appel, il instancie une fonction qui ressemble à ceci :

template <>
void print<5>()
{
    std::cout << 5 << '\n';
}

À l'exécution, lorsque cette fonction est appelée depuis main(), elle affiche 5.

Puis le programme se termine. Assez simple, n'est-ce pas ?

De même que T est généralement utilisé comme nom du premier paramètre de modèle de type, N est couramment utilisé comme nom d'un paramètre de modèle non-type de type int.

Bonne pratique

Utilisez N comme nom d'un paramètre de modèle non-type de type int.

À quoi servent les paramètres de modèle non-type ?

À partir de C++20, les paramètres de fonction ne peuvent pas être constexpr. C'est vrai pour les fonctions ordinaires, pour les fonctions constexpr (ce qui est logique, puisqu'elles doivent pouvoir s'exécuter à l'exécution) et, de façon peut-être surprenante, même pour les fonctions consteval.

Supposons donc une fonction de ce type :

#include <cassert>
#include <cmath> // pour std::sqrt
#include <iostream>

double getSqrt(double d)
{
    assert(d >= 0.0 && "getSqrt(): d must be non-negative");

    // L'assert ci-dessus sera probablement supprimé dans les versions non-debug
    if (d >= 0)
        return std::sqrt(d);

    return 0.0;
}

int main()
{
    std::cout << getSqrt(5.0) << '\n';
    std::cout << getSqrt(-5.0) << '\n';

    return 0;
}

À l'exécution, l'appel getSqrt(-5.0) déclenchera un assert à l'exécution. C'est mieux que rien, mais comme -5.0 est un littéral (implicitement constexpr), il serait préférable d'utiliser static_assert pour détecter ce type d'erreur à la compilation. Cependant, static_assert exige une expression constante, et les paramètres de fonction ne peuvent pas être constexpr…

En revanche, si nous transformons le paramètre de fonction en paramètre de modèle non-type, nous pouvons faire exactement ce que nous voulons :

#include <cmath> // pour std::sqrt
#include <iostream>

template <double D> // nécessite C++20 pour les paramètres non-type à virgule flottante
double getSqrt()
{
    static_assert(D >= 0.0, "getSqrt(): D must be non-negative");

    if constexpr (D >= 0) // ignorez le constexpr ici pour cet exemple
        return std::sqrt(D); // étrangement, std::sqrt n'est pas une fonction constexpr (avant C++26)

    return 0.0;
}

int main()
{
    std::cout << getSqrt<5.0>() << '\n';
    std::cout << getSqrt<-5.0>() << '\n';

    return 0;
}

Cette version ne compile pas. Lorsque le compilateur rencontre getSqrt<-5.0>(), il instancie et appelle une fonction qui ressemble à ceci :

template <>
double getSqrt<-5.0>()
{
    static_assert(-5.0 >= 0.0, "getSqrt(): D must be non-negative");

    if constexpr (-5.0 >= 0) // ignorez le constexpr ici pour cet exemple
        return std::sqrt(-5.0);

    return 0.0;
}

La condition du static_assert est fausse, donc le compilateur émet une erreur.

Point clé

Les paramètres de modèle non-type servent principalement lorsque nous devons passer des valeurs constexpr à des fonctions (ou à des types classes), afin qu'elles puissent être utilisées dans des contextes exigeant une expression constante.

La classe std::bitset utilise un paramètre de modèle non-type pour définir le nombre de bits à stocker, car ce nombre doit être une valeur constexpr.

Note de l'auteur

Être obligé d'utiliser des paramètres de modèle non-type pour contourner l'interdiction de rendre constexpr les paramètres de fonction n'est pas idéal. Plusieurs propositions sont actuellement à l'étude pour résoudre ce genre de situation. Je m'attends à ce qu'une meilleure solution apparaisse dans une future norme du langage C++.

Conversions implicites pour les arguments de modèle non-type (facultatif)

Certains arguments de modèle non-type peuvent être convertis implicitement afin de correspondre à un paramètre de modèle non-type d'un autre type. Par exemple :

#include <iostream>

template <int N> // paramètre de modèle non-type de type int
void print()
{
    std::cout << N << '\n';
}

int main()
{
    print<5>();   // aucune conversion nécessaire
    print<'c'>(); // 'c' converti en type int, affiche 99

    return 0;
}

Ce programme affiche :


5
99

Dans l'exemple ci-dessus, 'c' est converti en int pour correspondre au paramètre de modèle non-type de la fonction modèle print(), qui affiche alors la valeur sous forme d'int.

Dans ce contexte, seuls certains types de conversions constexpr sont autorisés. Les plus courantes sont :

  • Les promotions entières (par exemple char vers int)
  • Les conversions entières (par exemple char vers long, ou int vers char)
  • Les conversions définies par l'utilisateur (par exemple d'une classe définie par le programme vers int)
  • Les conversions lvalue vers rvalue (par exemple d'une variable x vers la valeur de x)

Notez que cette liste est moins permissive que les conversions implicites autorisées pour l'initialisation par liste. Par exemple, vous pouvez initialiser par liste une variable de type double à l'aide d'un int constexpr, mais un argument de modèle non-type int constexpr ne sera pas converti vers un paramètre de modèle non-type double.

La liste complète des conversions autorisées se trouve ici, dans la sous-section « Converted constant expression ».

Contrairement aux fonctions ordinaires, l'algorithme qui associe un appel de fonction modèle à une définition de fonction modèle n'est pas très sophistiqué : certaines correspondances ne sont pas privilégiées par rapport à d'autres selon le type de conversion nécessaire (ou son absence). Cela signifie que si une fonction modèle est surchargée pour différents types de paramètres non-type, on peut très facilement obtenir une correspondance ambiguë :

#include <iostream>

template <int N> // paramètre de modèle non-type de type int
void print()
{
    std::cout << N << '\n';
}

template <char N> // paramètre de modèle non-type de type char
void print()
{
    std::cout << N << '\n';
}

int main()
{
    print<5>();   // correspondance ambiguë avec int N = 5 et char N = 5
    print<'c'>(); // correspondance ambiguë avec int N = 99 et char N = 'c'

    return 0;
}

Il est peut-être surprenant que ces deux appels de print() donnent lieu à des correspondances ambiguës.

Déduction de type pour les paramètres de modèle non-type à l'aide de auto (C++17)

Depuis C++17, les paramètres de modèle non-type peuvent utiliser auto pour que le compilateur déduise leur type à partir de l'argument de modèle :

#include <iostream>

template <auto N> // déduit le type du paramètre non-type à partir de l'argument de modèle
void print()
{
    std::cout << N << '\n';
}

int main()
{
    print<5>();   // N déduit comme int `5`
    print<'c'>(); // N déduit comme char `c`

    return 0;
}

Ce programme compile et produit le résultat attendu :


5
c

Pour les lecteurs avancés

Vous vous demandez peut-être pourquoi cet exemple ne produit pas de correspondance ambiguë, contrairement à l'exemple de la section précédente. Le compilateur recherche d'abord les correspondances ambiguës, puis instancie le modèle de fonction s'il n'en existe aucune. Dans cet exemple, il n'y a qu'un seul modèle de fonction, donc aucune ambiguïté n'est possible.

Après l'instanciation du modèle de fonction dans l'exemple ci-dessus, le programme ressemble à ceci :

#include <iostream>

template <auto N>
void print()
{
    std::cout << N << '\n';
}

template <>
void print<5>() // notez qu'il s'agit de print<5> et non de print<int>
{
    std::cout << 5 << '\n';
}

template <>
void print<'c'>() // notez qu'il s'agit de print<`c`> et non de print<char>
{
    std::cout << 'c' << '\n';
}

int main()
{
    print<5>();   // appelle print<5>
    print<'c'>(); // appelle print<'c'>

    return 0;
}

Temps du quiz

Question n° 1

Écrivez un modèle de fonction constexpr avec un paramètre de modèle non-type qui renvoie la factorielle de l'argument de modèle. Le programme suivant doit échouer à la compilation lorsqu'il atteint factorial<-3>() :

// définissez ici le modèle de fonction factorial()

int main()
{
    static_assert(factorial<0>() == 1);
    static_assert(factorial<3>() == 6);
    static_assert(factorial<5>() == 120);

    factorial<-3>(); // doit échouer à la compilation

    return 0;
}
Solution 
template <int N>
constexpr int factorial()
{
    static_assert(N >= 0);

    int product { 1 };
    for (int i { 2 }; i <= N; ++i)
        product *= i;

    return product;
}

int main()
{
    static_assert(factorial<0>() == 1);
    static_assert(factorial<3>() == 6);
    static_assert(factorial<5>() == 120);

    factorial<-3>(); // doit échouer à la compilation

    return 0;
}
