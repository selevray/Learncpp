11.1 — Introduction à la surcharge de fonctions

Considérez la fonction suivante :

int add(int x, int y)
{
    return x + y;
}

Cette fonction triviale additionne deux entiers et renvoie un résultat entier. Mais que faire si nous voulons aussi une fonction capable d'additionner deux nombres à virgule flottante ? Cette fonction add() ne convient pas : tout paramètre à virgule flottante serait converti en entier, et les arguments à virgule flottante perdraient leur partie fractionnaire.

Une façon de contourner ce problème consiste à définir plusieurs fonctions avec des noms légèrement différents :

int addInteger(int x, int y)
{
    return x + y;
}

double addDouble(double x, double y)
{
    return x + y;
}

Cependant, pour obtenir un bon résultat, cela impose de définir une convention de nommage cohérente pour des fonctions similaires dont les paramètres sont de types différents, de retenir le nom de chacune de ces fonctions et d'appeler effectivement la bonne.

Et que se passe-t-il lorsque nous voulons une fonction similaire qui additionne 3 entiers au lieu de 2 ? Gérer des noms uniques pour chaque fonction devient vite fastidieux.

Introduction à la surcharge de fonctions

Heureusement, le C++ propose une solution élégante pour ces cas. La surcharge de fonctions (function overloading) nous permet de créer plusieurs fonctions portant le même nom, à condition que chacune d'elles ait des types de paramètres différents (ou qu'elles puissent être distinguées d'une autre façon). Chaque fonction partageant un nom (dans une même portée) est appelée fonction surchargée (overloaded function), souvent abrégée en surcharge (overload).

Pour surcharger notre fonction add(), il suffit de déclarer une autre fonction add() qui prend des paramètres de type double :

double add(double x, double y)
{
    return x + y;
}

Nous avons maintenant deux versions de add() dans la même portée :

int add(int x, int y) // version entière
{
    return x + y;
}

double add(double x, double y) // version à virgule flottante
{
    return x + y;
}

int main()
{
    return 0;
}

Le programme ci-dessus compile. Bien que vous puissiez vous attendre à un conflit de noms, ce n'est pas le cas ici. Comme les types de paramètres de ces fonctions diffèrent, le compilateur est capable de les distinguer et les traite comme des fonctions séparées qui partagent simplement un nom.

Point clé

Des fonctions peuvent être surchargées tant que le compilateur peut distinguer chacune d'elles. Si une fonction surchargée ne peut pas être distinguée, une erreur de compilation se produit.

Contenu associé

Les opérateurs peuvent également être surchargés de manière similaire. Nous aborderons la surcharge d'opérateurs dans 21.1 -- Introduction à la surcharge d'opérateurs.

Introduction à la résolution de surcharge

De plus, lorsqu'un appel est effectué vers une fonction surchargée, le compilateur tente de faire correspondre cet appel à la surcharge appropriée, en se basant sur les arguments utilisés. C'est ce qu'on appelle la résolution de surcharge (overload resolution).

Voici un exemple simple qui l'illustre :

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

double add(double x, double y)
{
    return x + y;
}

int main()
{
    std::cout << add(1, 2); // appelle add(int, int)
    std::cout << '\n';
    std::cout << add(1.2, 3.4); // appelle add(double, double)

    return 0;
}

Le programme ci-dessus compile et produit le résultat suivant :


3
4.6

Lorsque nous fournissons des arguments entiers dans l'appel add(1, 2), le compilateur détermine que nous essayons d'appeler add(int, int). Et lorsque nous fournissons des arguments à virgule flottante dans l'appel add(1.2, 3.4), le compilateur détermine que nous essayons d'appeler add(double, double).

Faire en sorte que cela compile

Pour qu'un programme utilisant des fonctions surchargées compile, deux conditions doivent être remplies :

  1. Chaque fonction surchargée doit pouvoir être distinguée des autres. Nous expliquons comment les fonctions peuvent être distinguées dans la leçon 11.2 -- Distinction des fonctions surchargées.
  2. Chaque appel à une fonction surchargée doit correspondre à une fonction surchargée. Nous expliquons comment le compilateur associe les appels aux fonctions surchargées dans la leçon 11.3 -- Résolution de surcharge et correspondances ambiguës.

Si une fonction surchargée n'est pas distinguée, ou si un appel à une fonction surchargée ne peut pas être associé à une fonction surchargée, une erreur de compilation se produit.

Dans la prochaine leçon, nous verrons comment les fonctions surchargées peuvent être distinguées les unes des autres. Puis, dans la leçon suivante, nous verrons comment le compilateur résout les appels aux fonctions surchargées.

Conclusion

La surcharge de fonctions est un excellent moyen de réduire la complexité de votre programme, en diminuant le nombre de noms de fonctions que vous devez retenir. Elle peut et doit être utilisée largement.

Bonne pratique

Utilisez la surcharge de fonctions pour rendre votre programme plus simple.
