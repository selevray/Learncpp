F.1 — Fonctions constexpr

Dans la leçon 5.6 -- Variables constexpr, nous avons présenté le mot-clé constexpr, que nous avons utilisé pour créer des constantes symboliques évaluées à la compilation. Nous avons aussi présenté les expressions constantes, c'est-à-dire des expressions qui peuvent être évaluées à la compilation plutôt qu'à l'exécution.

Une difficulté avec les expressions constantes est qu'un appel à une fonction ordinaire n'est pas autorisé dans une expression constante. Nous ne pouvons donc pas utiliser un tel appel partout où une expression constante est requise.

Considérez le programme suivant :

#include <iostream>

int main()
{
    constexpr double radius { 3.0 };
    constexpr double pi { 3.14159265359 };
    constexpr double circumference { 2.0 * radius * pi };

    std::cout << "Our circle has circumference " << circumference << "\n";

    return 0;
}

Ce programme produit le résultat suivant :


Our circle has circumference 18.8496

Un initialisateur complexe pour circumference n'est pas idéal (et nous oblige à créer deux variables auxiliaires, radius et pi). Transformons donc ce calcul en fonction :

#include <iostream>

double calcCircumference(double radius)
{
    constexpr double pi { 3.14159265359 };
    return 2.0 * pi * radius;
}

int main()
{
    constexpr double circumference { calcCircumference(3.0) }; // erreur de compilation

    std::cout << "Our circle has circumference " << circumference << "\n";

    return 0;
}

Ce code est beaucoup plus propre, mais il ne compile pas. La variable constexpr circumference exige que son initialisateur soit une expression constante, et l'appel calcCircumference() n'en est pas une.

Dans ce cas précis, nous pourrions rendre circumference non constexpr, et le programme compilerait. Nous perdrions les avantages des expressions constantes, mais au moins le programme s'exécuterait.

Cependant, il existe d'autres cas en C++ (que nous présenterons plus tard) où nous n'avons pas d'autre option et où seule une expression constante convient. Dans ces cas, nous aimerions pouvoir utiliser des fonctions, mais les appels à des fonctions ordinaires ne fonctionnent tout simplement pas. Que faire alors ?

Les fonctions constexpr peuvent être utilisées dans les expressions constantes

Une fonction constexpr est une fonction autorisée à être appelée dans une expression constante.

Pour faire d'une fonction une fonction constexpr, il suffit de placer le mot-clé constexpr devant le type de retour de la fonction.

Point clé

Le mot-clé constexpr sert à signaler au compilateur et aux autres développeurs qu'une fonction peut être utilisée dans une expression constante.

Voici le même exemple que précédemment, mais utilisant une fonction constexpr :

#include <iostream>

constexpr double calcCircumference(double radius) // désormais une fonction constexpr
{
    constexpr double pi { 3.14159265359 };
    return 2.0 * pi * radius;
}

int main()
{
    constexpr double circumference { calcCircumference(3.0) }; // compile désormais

    std::cout << "Our circle has circumference " << circumference << "\n";

    return 0;
}

Comme calcCircumference() est désormais une fonction constexpr, elle peut être utilisée dans une expression constante, comme l'initialisateur de circumference.

Les fonctions constexpr peuvent être évaluées à la compilation

Dans la leçon 5.5 -- Expressions constantes, nous avons noté que, dans les contextes qui exigent une expression constante (comme l'initialisation d'une variable constexpr), cette expression constante doit être évaluée à la compilation. Si une expression constante requise contient un appel à une fonction constexpr, cet appel doit être évalué à la compilation.

Dans notre exemple ci-dessus, la variable circumference est constexpr et exige donc un initialisateur constant. Comme calcCircumference() fait partie de cette expression constante requise, calcCircumference() doit être évaluée à la compilation.

Lorsqu'un appel de fonction est évalué à la compilation, le compilateur calcule la valeur de retour de cet appel à la compilation, puis remplace l'appel de fonction par cette valeur.

Ainsi, dans notre exemple, l'appel calcCircumference(3.0) est remplacé par le résultat de la fonction, soit 18.8496. Autrement dit, le compilateur traite ceci :

#include <iostream>

constexpr double calcCircumference(double radius)
{
    constexpr double pi { 3.14159265359 };
    return 2.0 * pi * radius;
}

int main()
{
    constexpr double circumference { 18.8496 };

    std::cout << "Our circle has circumference " << circumference << "\n";

    return 0;
}

Pour qu'un appel soit évalué à la compilation, deux autres conditions doivent aussi être remplies :

  • L'appel à la fonction constexpr doit avoir des arguments connus à la compilation (c'est-à-dire des expressions constantes).
  • Toutes les instructions et expressions à l'intérieur de la fonction constexpr doivent pouvoir être évaluées à la compilation.

Lorsqu'une fonction constexpr (ou consteval) est évaluée à la compilation, toutes les autres fonctions qu'elle appelle doivent également être évaluées à la compilation (sinon la fonction initiale ne pourrait pas produire de résultat à la compilation).

Pour les lecteurs avancés

Il existe d'autres critères, moins fréquemment rencontrés. Vous pouvez les consulter ici.

Les fonctions constexpr peuvent aussi être évaluées à l'exécution

Les fonctions constexpr peuvent également être évaluées à l'exécution, auquel cas elles renvoient un résultat non constexpr. Par exemple :

#include <iostream>

constexpr int greater(int x, int y)
{
    return (x > y ? x : y);
}

int main()
{
    int x{ 5 }; // non constexpr
    int y{ 6 }; // non constexpr

    std::cout << greater(x, y) << " is greater!\n"; // sera évalué à l'exécution

    return 0;
}

Dans cet exemple, comme les arguments x et y ne sont pas des expressions constantes, la fonction ne peut pas être résolue à la compilation. Elle sera cependant résolue à l'exécution et renverra la valeur attendue, sous forme d'un int non constexpr.

Point clé

Lorsqu'une fonction constexpr est évaluée à l'exécution, elle se comporte exactement comme une fonction normale (non constexpr). Autrement dit, le constexpr n'a aucun effet dans ce cas.

Point clé

Le fait d'autoriser une fonction à type de retour constexpr à être évaluée soit à la compilation, soit à l'exécution permet à une seule fonction de servir dans les deux cas.

Sans cela, il faudrait disposer de deux fonctions distinctes (une fonction à type de retour constexpr et une fonction à type de retour non constexpr). Cela imposerait non seulement de dupliquer le code, mais aussi de donner deux noms différents aux deux fonctions !
