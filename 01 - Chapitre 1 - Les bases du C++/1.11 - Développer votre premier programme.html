1.11 — Développer votre premier programme

Les leçons précédentes ont introduit beaucoup de terminologie et de concepts que nous utiliserons dans presque tous les programmes que nous créerons. Dans cette leçon, nous allons parcourir le processus d'intégration de ces connaissances dans notre premier programme simple.

Multiplier par 2

Commençons par créer un programme qui demande à l'utilisateur de saisir un entier, attend qu'il le saisisse, puis lui indique le résultat de 2 fois ce nombre. Le programme doit produire la sortie suivante (supposons que j'ai saisi 4) :


Enter an integer: 4
Double that number is: 8

Comment aborder cela ? Étape par étape.

Bonne pratique

Les nouveaux programmeurs essaient souvent d'écrire un programme entier d'un seul coup, puis se retrouvent submergés lorsqu'il produit une multitude d'erreurs. Une meilleure stratégie consiste à ajouter un élément à la fois, à vérifier qu'il compile, et à le tester. Puis, lorsque vous êtes sûr qu'il fonctionne, passez à l'élément suivant.

Nous allons appliquer cette stratégie ici. À chaque étape, tapez (ne copiez-collez pas) chaque programme dans votre éditeur de code, compilez-le et exécutez-le.

Commencez par créer un nouveau projet console.

Maintenant, commençons par une structure de base. Nous savons que nous aurons besoin d'une fonction main() (puisque tout programme C++ doit en avoir une). Si votre IDE n'a pas créé de fonction vide lors de la création du projet, créons-la :

int main()
{
    return 0;
}

Nous savons que nous devons afficher du texte dans la console et lire du texte depuis le clavier de l'utilisateur. Nous devons donc inclure iostream pour accéder à std::cout et std::cin.

#include <iostream>

int main()
{
    return 0;
}

Indiquons maintenant à l'utilisateur qu'il doit saisir un entier :

#include <iostream>

int main()
{
    std::cout << "Enter an integer: ";

    return 0;
}

À ce stade, votre programme doit produire ce résultat :


Enter an integer:

puis se terminer.

Ensuite, nous allons récupérer la saisie de l'utilisateur. Nous utiliserons std::cin et operator>> pour cela. Mais nous devons aussi définir une variable pour stocker cette saisie et l'utiliser plus tard.

#include <iostream>

int main() // note : ce programme contient une erreur quelque part
{
    std::cout << "Enter an integer: ";

    int num{ }; // définit la variable num comme une variable entière
    std::cin << num; // lit un entier depuis le clavier de l'utilisateur

    return 0;
}

Il est temps de compiler nos modifications… et…

Oh oh ! Voici ce qu'a obtenu l'auteur sous Visual Studio 2017 :


1>------ Build started: Project: Double, Configuration: Release Win32 ------
1>Double.cpp
1>c:\vcprojects\double\double.cpp(8): error C2678: binary '<<': no operator found which takes a left-hand operand of type 'std::istream' (or there is no acceptable conversion)
1>c:\vcprojects\double\double.cpp: note: could be 'built-in C++ operator<<(bool, int)'
1>c:\vcprojects\double\double.cpp: note: while trying to match the argument list '(std::istream, int)'
1>Done building project "Double.vcxproj" -- FAILED.
========== Build: 0 succeeded, 1 failed, 0 up-to-date, 0 skipped ==========

Nous avons rencontré une erreur de compilation !

Premièrement, puisque le programme compilait avant cette dernière modification et ne compile plus maintenant, l'erreur doit se trouver dans le code que nous venons d'ajouter (lignes 7 et 8). Cela réduit considérablement la quantité de code à examiner pour trouver l'erreur. La ligne 7 est assez simple (il s'agit simplement d'une définition de variable), donc l'erreur ne s'y trouve probablement pas. Il reste la ligne 8 comme coupable probable.

Deuxièmement, ce message d'erreur n'est pas très facile à lire. Mais analysons quelques éléments clés : le compilateur nous indique qu'il a rencontré l'erreur à la ligne 8. Cela signifie que la vraie erreur se trouve probablement à la ligne 8, ou éventuellement à la ligne précédente, ce qui renforce notre évaluation précédente. Ensuite, le compilateur indique qu'il n'a pas trouvé d'opérateur '<<' dont l'opérande de gauche est de type std::istream (qui est le type de std::cin). Autrement dit, operator<< ne sait pas quoi faire avec std::cin, donc l'erreur se trouve forcément soit dans notre utilisation de std::cin, soit dans notre utilisation de operator<<.

Voyez-vous l'erreur maintenant ? Sinon, prenez un moment et essayez de la trouver.

Voici le programme contenant le code corrigé :

#include <iostream>

int main()
{
    std::cout << "Enter an integer: ";

    int num{ };
    std::cin >> num; // std::cin utilise operator >>, pas operator <<!

    return 0;
}

Maintenant, le programme compile et nous pouvons le tester. Le programme attendra que vous saisissiez un nombre, alors saisissons 4. La sortie devrait ressembler à ceci :


Enter an integer: 4

Nous y sommes presque ! La dernière étape consiste à doubler le nombre.

Une fois cette dernière étape terminée, notre programme compilera et s'exécutera avec succès, en produisant la sortie souhaitée.

Il existe (au moins) 3 façons de procéder. Allons de la pire à la meilleure.

La solution peu satisfaisante

#include <iostream>

// pire version
int main()
{
    std::cout << "Enter an integer: ";

    int num{ };
    std::cin >> num;

    num = num * 2; // double la valeur de num, puis réaffecte cette valeur à num

    std::cout << "Double that number is: " << num << '\n';

    return 0;
}

Dans cette solution, nous utilisons une expression pour multiplier num par 2, puis nous réaffectons cette valeur à num. À partir de ce point, num contiendra notre nombre doublé.

Pourquoi est-ce une mauvaise solution :

  • Avant l'instruction d'affectation, num contient la saisie de l'utilisateur. Après l'affectation, il contient une valeur différente. C'est déroutant.
  • Nous avons écrasé la saisie de l'utilisateur en affectant une nouvelle valeur à la variable d'entrée. Si nous voulions ensuite étendre notre programme pour faire autre chose avec cette valeur (par exemple la tripler), elle serait déjà perdue.

La solution presque bonne

#include <iostream>

// version moins mauvaise
int main()
{
    std::cout << "Enter an integer: ";

    int num{ };
    std::cin >> num;

    int doublenum{ num * 2 }; // définit une nouvelle variable et l'initialise avec num * 2
    std::cout << "Double that number is: " << doublenum << '\n'; // puis affiche la valeur de cette variable ici

    return 0;
}

Cette solution est assez simple à lire et à comprendre, et elle résout les deux problèmes rencontrés dans la pire solution.

Le principal inconvénient ici est que nous définissons une nouvelle variable (ce qui ajoute de la complexité) pour stocker une valeur que nous n'utilisons qu'une seule fois. Nous pouvons faire mieux.

La solution préférée

#include <iostream>

// version préférée
int main()
{
    std::cout << "Enter an integer: ";

    int num{ };
    std::cin >> num;

    std::cout << "Double that number is: " <<  num * 2 << '\n'; // utilise une expression pour multiplier num * 2 à l'endroit où l'on va l'afficher

    return 0;
}

C'est la solution préférée parmi celles présentées. Lorsque std::cout s'exécute, l'expression num * 2 est évaluée, et le résultat, qui est le double de la valeur de num, est affiché. La valeur de num elle-même n'est pas modifiée, nous pouvons donc la réutiliser plus tard si nous le souhaitons.

Cette version est notre solution de référence.

Note de l'auteur

Le premier et principal objectif de la programmation est de faire fonctionner votre programme. Un programme qui ne fonctionne pas n'est pas utile, quelle que soit la qualité de son écriture.

Cependant, il existe un dicton que j'apprécie : « Il faut écrire un programme une fois pour savoir comment on aurait dû l'écrire la première fois. » Cela traduit le fait que la meilleure solution n'est souvent pas évidente, et que nos premières solutions aux problèmes ne sont généralement pas aussi bonnes qu'elles pourraient l'être.

Lorsque nous nous concentrons sur la manière de faire fonctionner nos programmes, il n'est pas très judicieux d'investir beaucoup de temps dans du code que nous ne saurons peut-être même pas garder. Alors nous prenons des raccourcis. Nous omettons des choses comme la gestion des erreurs et les commentaires. Nous semons du code de débogage dans notre solution pour nous aider à diagnostiquer les problèmes et trouver les erreurs. Nous apprenons en avançant : des approches que nous pensions efficaces ne le sont pas finalement, et nous devons revenir en arrière et essayer une autre méthode.

Le résultat est que nos solutions initiales ne sont souvent ni bien structurées, ni robustes (à l'épreuve des erreurs), ni lisibles, ni concises. Une fois que votre programme fonctionne, votre travail n'est donc pas vraiment terminé (sauf si le programme est jetable ou ponctuel). L'étape suivante consiste à nettoyer votre code. Cela implique des choses comme : supprimer (ou mettre en commentaire) le code temporaire et de débogage, ajouter des commentaires, gérer les cas d'erreur, formater votre code et respecter les bonnes pratiques. Et même alors, votre programme n'est peut-être pas aussi simple qu'il pourrait l'être : il peut y avoir une logique redondante à regrouper, plusieurs instructions à combiner, des variables inutiles, ou mille autres petites choses à simplifier. Trop souvent, les nouveaux programmeurs se concentrent sur l'optimisation des performances alors qu'ils devraient viser la maintenabilité.

Très peu des solutions présentées dans ces tutoriels étaient excellentes dès la première fois. Elles sont plutôt le fruit d'un perfectionnement continu, jusqu'à ce qu'on ne puisse plus rien trouver à améliorer. Et dans de nombreux cas, les lecteurs trouvent encore beaucoup d'autres suggestions d'amélioration !

Tout cela pour dire : ne soyez pas frustré si vos solutions ne sont pas parfaitement optimisées dès le départ. C'est normal. La perfection en programmation est un processus itératif (qui demande plusieurs passages).

Note de l'auteur

Une dernière chose : vous vous demandez peut-être « C++ a tellement de règles et de concepts. Comment retenir tout cela ? ».

Réponse courte : vous ne le retenez pas. C++ consiste pour une part à utiliser ce que vous savez, et pour deux parts à chercher comment faire le reste.

Lorsque vous lisez ce site pour la première fois, concentrez-vous moins sur la mémorisation des détails et davantage sur la compréhension de ce qui est possible. Ensuite, lorsque vous aurez besoin de mettre en œuvre quelque chose dans un programme que vous écrivez, vous pourrez revenir ici (ou sur un site de référence) pour vous rafraîchir la mémoire.

Quiz

Question n° 1

Modifiez la solution « préférée » du programme ci-dessus afin qu'il produise la sortie suivante (en supposant que l'utilisateur saisit 4) :


Enter an integer: 4
Double 4 is: 8
Triple 4 is: 12
Solution 
#include <iostream>

int main()
{
    std::cout << "Enter an integer: ";

    int num{ };
    std::cin >> num;

    std::cout << "Double " << num << " is: " << num * 2 << '\n';
    std::cout << "Triple " << num << " is: " << num * 3 << '\n';

    return 0;
}
