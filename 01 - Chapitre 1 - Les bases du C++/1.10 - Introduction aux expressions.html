1.10 — Introduction aux expressions

Expressions

Considérons la série d'instructions suivante, qui définit chacune une variable et l'initialise :

// five() est une fonction qui renvoie la valeur 5
int five()
{
    return 5;
}

int main()
{
    int a{ 2 };             // initialise la variable a avec la valeur littérale 2
    int b{ 2 + 3 };         // initialise la variable b avec la valeur calculée 5
    int c{ (2 * 3) + 4 };   // initialise la variable c avec la valeur calculée 10
    int d{ b };             // initialise la variable d avec la valeur de la variable b, soit 5
    int e{ five() };        // initialise la variable e avec la valeur de retour de la fonction, soit 5

    return 0;
}

Notez que les initialisations ci-dessus utilisent différentes entités : des littéraux, des variables, des opérateurs et des appels de fonction. C++ convertit d'une façon ou d'une autre toutes ces entités en une seule valeur, qui peut ensuite servir de valeur initiale à la variable.

Qu'ont en commun toutes ces initialisations ? Elles utilisent toutes une expression.

En programmation générale, une expression est une séquence non vide de littéraux, de variables, d'opérateurs et d'appels de fonction, qui calcule une valeur. Le processus d'exécution d'une expression s'appelle l'évaluation, et la valeur résultante s'appelle le résultat de l'expression (parfois appelé aussi valeur de retour).

Pour les lecteurs avancés

En C++, le résultat d'une expression est l'un des suivants :

  • Une valeur (le cas le plus courant)
  • Un objet ou une fonction. Nous étudierons les expressions qui renvoient des objets dans la leçon 12.2 -- Catégories de valeurs (lvalues et rvalues).
  • Rien. C'est le cas des appels de fonctions sans valeur de retour (abordées dans la leçon 2.3 -- Fonctions sans valeur de retour (fonctions void)), appelées uniquement pour leurs effets de bord.

Pour l'instant, par souci de simplicité, nous supposerons que les expressions s'évaluent pour produire des valeurs.

Lors de l'évaluation d'une expression, chacun de ses termes est évalué, jusqu'à ce qu'il ne reste qu'une seule valeur. Voici quelques exemples de différents types d'expressions, avec des commentaires indiquant comment elles s'évaluent :

2               // 2 est un littéral qui s'évalue à la valeur 2
"Hello world!"  // "Hello world!" est un littéral qui s'évalue au texte "Hello world!"
x               // x est une variable qui s'évalue à la valeur contenue dans la variable x
2 + 3           // operator+ utilise les opérandes 2 et 3 pour s'évaluer à la valeur 5
five()          // s'évalue à la valeur de retour de la fonction five()

Comme vous pouvez le voir, les littéraux s'évaluent à leur propre valeur. Les variables s'évaluent à la valeur de la variable. Les opérateurs (comme operator+) utilisent leurs opérandes pour s'évaluer à une autre valeur. Nous n'avons pas encore abordé les appels de fonction, mais dans le contexte d'une expression, un appel de fonction s'évalue à la valeur que la fonction renvoie.

Pour les lecteurs avancés

Les expressions impliquant des opérateurs à effets de bord sont un peu plus délicates :

x = 5           // x = 5 a pour effet de bord d'affecter 5 à x, et s'évalue à x
x = 2 + 3       // a pour effet de bord d'affecter 5 à x, et s'évalue à x
std::cout << x  // a pour effet de bord d'afficher la valeur de x sur la console, et s'évalue à std::cout

Point clé

Partout où C++ attend une valeur unique, vous pouvez utiliser à la place une expression produisant une valeur ; cette expression sera évaluée pour produire une valeur unique.

Les expressions ne se terminent pas par un point-virgule et ne peuvent pas être compilées seules. Par exemple, si vous tentiez de compiler l'expression x = 5, votre compilateur se plaindrait (probablement d'un point-virgule manquant). Les expressions sont en fait toujours évaluées dans le cadre d'instructions.

Prenons par exemple cette instruction :

int x{ 2 + 3 }; // 2 + 3 est une expression sans point-virgule -- le point-virgule se trouve à la fin de l'instruction qui contient l'expression

Si l'on décompose cette instruction selon sa syntaxe, elle ressemble à ceci :

type identifiant { expression };

type peut être n'importe quel type valide (nous avons choisi int). identifiant peut être n'importe quel nom valide (nous avons choisi x). Et expression peut être n'importe quelle expression valide (nous avons choisi 2 + 3, qui utilise deux littéraux et un opérateur).

Instructions d'expression

Certaines expressions (comme x = 5) sont utilisées principalement pour leurs effets de bord (dans ce cas, affecter la valeur 5 à la variable x) plutôt que pour la valeur qu'elles produisent.

Contenu associé

Nous abordons les effets de bord dans la leçon 1.9 -- Introduction aux littéraux et aux opérateurs.

Cependant, nous avons mentionné plus haut que les expressions ne peuvent pas être exécutées seules : elles doivent faire partie d'une instruction. Heureusement, il est très simple de transformer n'importe quelle expression en une instruction équivalente. Une instruction d'expression est une instruction constituée d'une expression suivie d'un point-virgule. Lorsqu'une instruction d'expression est exécutée, l'expression est évaluée.

Ainsi, nous pouvons prendre n'importe quelle expression (comme x = 5) et en faire une instruction d'expression (x = 5;) qui se compile.

Lorsqu'une expression est utilisée dans une instruction d'expression, le résultat éventuellement produit par l'expression est ignoré (car il n'est pas utilisé). Par exemple, lorsque l'expression x = 5 est évaluée, la valeur de retour de operator= est ignorée. Et c'est très bien ainsi, car nous voulions simplement affecter 5 à x.

Instructions d'expression inutiles

Nous pouvons également écrire des instructions d'expression qui se compilent mais n'ont aucun effet. Par exemple, l'instruction d'expression (2 * 3;) a une expression qui s'évalue à la valeur 6, valeur qui est ensuite ignorée. Bien que syntaxiquement valides, ces instructions sont inutiles. Certains compilateurs (comme gcc et Clang) produisent des avertissements lorsqu'ils détectent qu'une instruction d'expression est inutile.

Sous-expressions, expressions complètes et expressions composées

Nous avons parfois besoin de parler de types particuliers d'expressions. Dans ce but, nous allons définir quelques termes associés.

Considérons les expressions suivantes :

2               // 2 est un littéral qui s'évalue à la valeur 2
2 + 3           // 2 + 3 utilise operator+ pour s'évaluer à la valeur 5
x = 4 + 5       // 4 + 5 s'évalue à la valeur 9, qui est ensuite affectée à la variable x

En simplifiant un peu, une sous-expression est une expression utilisée comme opérande. Par exemple, les sous-expressions de x = 4 + 5 sont x et 4 + 5. Les sous-expressions de 4 + 5 sont 4 et 5.

Une expression complète est une expression qui n'est pas une sous-expression. Les trois expressions ci-dessus (2, 2 + 3 et x = 4 + 5) sont toutes des expressions complètes.

Dans le langage courant, une expression composée est une expression qui contient deux utilisations d'opérateurs ou plus. x = 4 + 5 est une expression composée, car elle contient deux utilisations d'opérateurs (operator= et operator+). 2 et 2 + 3 ne sont pas des expressions composées.

Quiz

Question n° 1

Quelle est la différence entre une instruction et une expression ?

Solution

Les instructions servent lorsque nous voulons que le programme effectue une action. Les expressions servent lorsque nous voulons que le programme calcule une valeur.

Question n° 2

Indiquez si chacune des lignes suivantes est une instruction ne contenant pas d'expression, une instruction contenant une expression, ou une instruction d'expression.

a)

int x;
Solution

Instruction ne contenant pas d'expression. C'est une instruction de définition de variable. x n'est pas une expression dans ce contexte, car il est en train d'être défini, et non évalué.

b)

int x = 5;
Solution

Instruction contenant une expression. int x est une définition de variable. Le = fait partie de la syntaxe de l'initialisation par copie. L'initialiseur situé à droite du signe égal est une expression.

c)

x = 5;
Solution

Instruction d'expression. x = 5 est un appel à operator= avec deux opérandes : x et 5. Le point-virgule en fait une instruction d'expression.

d) Pour aller plus loin :

foo(); // foo est une fonction
Solution

Les appels de fonction font partie d'une expression, donc il s'agit d'une instruction d'expression.

e) Pour aller plus loin :

std::cout << x; // Indice : operator<< est un opérateur binaire.
Solution

operator<< est un opérateur binaire, donc std::cout doit être l'opérande de gauche et x l'opérande de droite. Comme il s'agit de toute l'instruction, c'est forcément une instruction d'expression.
