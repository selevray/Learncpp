Les mots-clés marqués (C++20) ont été ajoutés en C++20. Si votre compilateur n'est pas conforme à C++20 (ou s'il dispose des fonctionnalités de C++20 mais que celles-ci sont désactivées par défaut), ces mots-clés peuvent ne pas être fonctionnels.

C++ définit également des identificateurs spéciaux : override, final, import et module. Ils ont une signification précise lorsqu'ils sont utilisés dans certains contextes, mais ne sont pas réservés en dehors de ceux-ci.

Vous avez déjà rencontré certains de ces mots-clés, notamment int et return. Avec un ensemble d'opérateurs, ces mots-clés et identificateurs spéciaux définissent l'ensemble du langage C++ (directives du préprocesseur exclues). Comme les mots-clés et les identificateurs spéciaux ont une signification particulière, votre environnement de développement (IDE) changera probablement la couleur du texte de ces mots pour les faire ressortir des autres identificateurs.

À la fin de cette série de tutoriels, vous comprendrez la fonction de presque tous ces mots !

Règles de nommage des identificateurs

Pour rappel, le nom d'une variable (ou d'une fonction, d'un type ou d'un autre élément) s'appelle un identificateur. C++ vous laisse une grande liberté pour nommer vos identificateurs. Cependant, certaines règles doivent être respectées lors du nommage :

  • L'identificateur ne peut pas être un mot-clé. Les mots-clés sont réservés.
  • L'identificateur ne peut être composé que de lettres (minuscules ou majuscules), de chiffres et du caractère de soulignement. Cela signifie que le nom ne peut pas contenir de symboles (à l'exception du tiret bas) ni d'espaces (espaces ou tabulations).
  • L'identificateur doit commencer par une lettre (minuscule ou majuscule) ou par un tiret bas. Il ne peut pas commencer par un chiffre.
  • C++ est sensible à la casse : il distingue les lettres minuscules et majuscules. nvalue est différent de nValue, qui est lui-même différent de NVALUE.

Bonnes pratiques de nommage des identificateurs

Maintenant que vous savez comment vous pouvez nommer une variable, voyons comment vous devriez la nommer (ou nommer une fonction).

  1. En C++, il est d'usage que les noms de variables commencent par une lettre minuscule. Si le nom de la variable est un mot unique ou un acronyme, il doit être entièrement écrit en minuscules.
int value; // conventionnel

int Value; // non conventionnel (doit commencer par une lettre minuscule)
int VALUE; // non conventionnel (doit commencer par une lettre minuscule et être entièrement en minuscules)
int VaLuE; // non conventionnel (consultez votre psychiatre) ;)

Le plus souvent, les noms de fonctions commencent également par une lettre minuscule (bien qu'il y ait des désaccords sur ce point). Nous suivrons cette convention, puisque la fonction main (que tout programme doit posséder) commence par une lettre minuscule, tout comme l'ensemble des fonctions de la bibliothèque standard C++.

Les identificateurs commençant par une lettre majuscule sont généralement réservés aux types définis par l'utilisateur (tels que les structures, les classes et les énumérations, que nous aborderons plus tard).

Si le nom de la variable ou de la fonction est composé de plusieurs mots, deux conventions sont courantes : les mots séparés par des tirets bas (parfois appelée snake_case), ou la casse mixte (parfois appelée camelCase, car les lettres majuscules ressortent comme les bosses d'un chameau).

int my_variable_name;   // conventionnel (mots séparés par des tirets bas/snake_case)
int my_function_name(); // conventionnel (mots séparés par des tirets bas/snake_case)

int myVariableName;     // conventionnel (casse mixte/camelCase)
int myFunctionName();   // conventionnel (casse mixte/camelCase)

int my variable name;   // invalide (espaces non autorisés)
int my function name(); // invalide (espaces non autorisés)

int MyVariableName;     // non conventionnel (doit commencer par une lettre minuscule)
int MyFunctionName();   // non conventionnel (doit commencer par une lettre minuscule)

Dans ce tutoriel, nous utiliserons généralement la casse mixte, car elle est plus facile à lire (il est facile de confondre un tiret bas avec un espace dans des blocs de code denses). Mais on rencontre couramment les deux : la bibliothèque standard C++ utilise la méthode des tirets bas pour les variables comme pour les fonctions. Il arrive aussi de voir un mélange des deux : des tirets bas pour les variables et la casse mixte pour les fonctions.

Il est important de noter que si vous travaillez sur le code de quelqu'un d'autre, il est généralement préférable de respecter le style du code existant plutôt que de suivre rigidement les conventions de nommage décrites ci-dessus.

Bonne pratique

Lorsque vous travaillez dans un programme existant, utilisez les conventions de ce programme (même si elles ne respectent pas les bonnes pratiques modernes). Utilisez les bonnes pratiques modernes lorsque vous écrivez de nouveaux programmes.

  1. Évitez de nommer vos identificateurs en commençant par un tiret bas. Bien que syntaxiquement valides, ces noms sont généralement réservés à l'usage du système d'exploitation, de la bibliothèque et/ou du compilateur.
  2. Le nom de vos identificateurs doit indiquer clairement la signification de la valeur qu'ils contiennent (surtout si les unités ne sont pas évidentes). Les identificateurs doivent être nommés de manière à aider quelqu'un qui n'a aucune idée de ce que fait votre code à le comprendre le plus rapidement possible. Dans trois mois, lorsque vous relirez votre programme, vous aurez oublié son fonctionnement, et vous vous remercierez d'avoir choisi des noms de variables qui ont du sens.

Cependant, donner à un identificateur trivial un nom trop complexe nuit à la compréhension de ce que fait le programme, presque autant que donner un nom inadéquat à un identificateur non trivial. Une bonne règle empirique consiste à rendre la longueur d'un identificateur proportionnelle à la précision et à la portée de cet identificateur. Cela signifie que :

  • Un identificateur qui n'existe que pour quelques instructions (par exemple dans le corps d'une fonction courte) peut avoir un nom plus court.
  • Un identificateur accessible depuis n'importe où peut bénéficier d'un nom plus long.
  • Un identificateur qui représente un nombre non spécifique (par exemple tout ce que fournit l'utilisateur) peut avoir un nom plus court.
  • Un identificateur qui représente une valeur précise (par exemple la longueur d'une entrejambe en millimètres) doit avoir un nom plus long.

| int ccount | Mauvais | À quoi correspond le c devant « count » ? | | int customerCount | Bon | On comprend clairement ce qui est compté | | int i | Either | Acceptable si l'usage est trivial, mauvais sinon | | int index | Either | Acceptable s'il est évident ce qui est indexé | | int totalScore | Either | Acceptable s'il n'y a qu'une seule chose notée, sinon trop ambigu | | int _count | Mauvais | Ne commencez pas les noms par un tiret bas | | int count | Either | Acceptable s'il est évident ce qui est compté | | int data | Mauvais | Quel type de données ? | | int time | Mauvais | Est-ce en secondes, en minutes ou en heures ? | | int minutesElapsed | Either | Acceptable s'il est évident de quoi ce temps est écoulé | | int x1, x2 | Either | Acceptable si l'usage est trivial, mauvais sinon | | int userinput1, userinput2 | Mauvais | Difficile de les différencier à cause de la longueur du nom | | int numApples | Bon | Descriptif | | int monstersKilled | Bon | Descriptif |

  1. Évitez les abréviations, sauf lorsqu'elles sont courantes et sans ambiguïté (par exemple num, cm, idx).

Point clé

Le code est lu plus souvent qu'il n'est écrit ; le temps gagné à l'écriture est donc du temps que chaque lecteur, y compris votre « vous » futur, perdra à la lecture. Si vous cherchez à écrire du code plus vite, utilisez la fonction de complétion automatique de votre éditeur.

  1. Pour les déclarations de variables, il peut être utile d'employer un commentaire pour décrire à quoi servira la variable, ou pour expliquer tout ce qui pourrait ne pas être évident. Par exemple, supposons que nous ayons déclaré une variable destinée à stocker le nombre de caractères d'un texte. Le texte « Hello World! » compte-t-il 10, 11 ou 12 caractères ? Cela dépend de la prise en compte ou non des espaces et de la ponctuation. Plutôt que de nommer la variable numCharsIncludingWhitespaceAndPunctuation, ce qui est assez long, un commentaire bien placé sur la ligne de déclaration ou juste au-dessus aidera l'utilisateur à comprendre :
// nombre de caractères d'un texte, espaces et ponctuation inclus
int numChars {};
