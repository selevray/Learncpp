1.4 — Affectation et initialisation de variables

Dans la leçon précédente (1.3 -- Introduction aux objets et aux variables), nous avons vu comment définir une variable pour stocker des valeurs. Dans cette leçon, nous allons voir comment placer réellement des valeurs dans des variables.

Pour rappel, voici un court programme qui alloue d'abord une variable entière nommée x, puis deux autres variables entières nommées y et z :

int main()
{
    int x;    // définit une variable entière nommée x (à privilégier)
    int y, z; // définit deux variables entières, nommées y et z

    return 0;
}

Pour rappel, il est préférable de définir une seule variable par ligne. Nous reviendrons plus tard sur les cas où l'on définit plusieurs variables à la fois.

Affectation de variables

Une fois qu'une variable a été définie, vous pouvez lui donner une valeur (dans une instruction distincte) à l'aide de l'opérateur =. Ce processus s'appelle affectation (assignment), et l'opérateur = s'appelle opérateur d'affectation.

int width; // définit une variable entière nommée width
width = 5; // affecte la valeur 5 à la variable width

// la variable width a maintenant la valeur 5

Par défaut, l'affectation copie la valeur située à droite de l'opérateur = dans la variable située à gauche de cet opérateur. On parle alors d'affectation par copie (copy-assignment).

Une fois qu'une variable a reçu une valeur, cette valeur peut être affichée à l'aide de std::cout et de l'opérateur <<.

L'affectation peut être utilisée chaque fois que l'on souhaite modifier la valeur contenue dans une variable. Voici un exemple où nous utilisons deux fois l'affectation :

#include <iostream>

int main()
{
    int width; // définit une variable nommée width
    width = 5; // affectation par copie de la valeur 5 dans la variable width

    std::cout << width; // affiche 5

    width = 7; // remplace la valeur stockée dans la variable width par 7

    std::cout << width; // affiche 7

    return 0;
}

Ce programme affiche :


57

Lorsque ce programme est exécuté, l'exécution commence au début de la fonction main et se poursuit séquentiellement. Tout d'abord, la mémoire de la variable width est allouée. Nous affectons ensuite à width la valeur 5. Lorsque nous affichons la valeur de width, la console affiche 5. Lorsque nous affectons ensuite la valeur 7 à width, la valeur précédente (ici 5) est écrasée. Ainsi, lorsque nous affichons à nouveau width, la valeur affichée est 7.

Une variable ordinaire ne peut contenir qu'une seule valeur à la fois.

Attention

L'une des erreurs les plus courantes chez les nouveaux programmeurs consiste à confondre l'opérateur d'affectation (=) et l'opérateur d'égalité (==). L'affectation (=) sert à donner une valeur à une variable. L'égalité (==) sert à tester si deux opérandes ont la même valeur.

Initialisation de variables

L'un des inconvénients de l'affectation est que, pour donner une valeur à un objet qui vient d'être défini, il faut deux instructions : une pour définir la variable, et une autre pour lui affecter la valeur.

Ces deux étapes peuvent être combinées. Lorsqu'un objet est défini, vous pouvez facultativement lui fournir une valeur initiale. Le fait de spécifier une valeur initiale pour un objet s'appelle initialisation (initialization), et la syntaxe utilisée pour initialiser un objet s'appelle initialiseur (initializer). Dans le langage courant, la valeur initiale elle-même est aussi souvent appelée « initialiseur ».

Par exemple, l'instruction suivante définit à la fois une variable nommée width (de type int) et l'initialise avec la valeur 5 :

#include <iostream>

int main()
{
    int width { 5 };    // définit la variable width et l'initialise avec la valeur initiale 5
    std::cout << width; // affiche 5

    return 0;
}

Dans l'initialisation ci-dessus de la variable width, { 5 } est l'initialiseur, et 5 est la valeur initiale.

Point clé

L'initialisation fournit une valeur initiale à une variable. Pensez à « initial-isation ».

Différentes formes d'initialisation

Contrairement à l'affectation (qui est généralement simple), l'initialisation en C++ est étonnamment complexe. Nous en présentons donc ici une vue simplifiée pour commencer.

Il existe 5 formes courantes d'initialisation en C++ :

int a;         // initialisation par défaut (sans initialiseur)

// Formes d'initialisation traditionnelles :
int b = 5;     // initialisation par copie (valeur initiale après le signe égal)
int c ( 6 );   // initialisation directe (valeur initiale entre parenthèses)

// Formes d'initialisation modernes (à privilégier) :
int d { 7 };   // initialisation directe par liste (valeur initiale entre accolades)
int e {};      // initialisation par valeur (accolades vides)

Vous pourrez rencontrer les formes ci-dessus écrites avec d'autres espacements (par exemple int b=5;, int c(6);, int d{7};, int e{};). Ajouter des espaces pour la lisibilité ou non relève de la préférence personnelle.

À partir de C++17, l'initialisation par copie, l'initialisation directe et l'initialisation directe par liste se comportent de façon identique dans la plupart des cas. Nous verrons plus bas le cas le plus pertinent où elles diffèrent.

Contenu associé

Nous abordons le reste des différences entre l'initialisation par copie, l'initialisation directe et l'initialisation par liste dans la leçon 14.15 -- Initialisation des classes et élision de copie.

Pour les lecteurs avancés

Les autres formes d'initialisation comprennent :

  • L'initialisation d'agrégat (voir 13.8 -- Initialisation d'agrégats de structures).
  • L'initialisation par liste de copie (traitée plus bas).
  • L'initialisation de références (voir 12.3 -- Références lvalue).
  • L'initialisation statique, l'initialisation par constante et l'initialisation dynamique (voir 7.8 -- Pourquoi les variables globales (non const) sont un mal).
  • L'initialisation à zéro (traitée plus bas).

Initialisation par défaut

Lorsqu'aucun initialiseur n'est fourni (comme pour la variable a ci-dessus), on parle d'initialisation par défaut (default-initialization). Dans de nombreux cas, l'initialisation par défaut n'initialise rien et laisse la variable avec une valeur indéterminée (une valeur imprévisible, parfois appelée « valeur poubelle » ou « garbage value »).

Nous reviendrons sur ce cas dans la leçon (1.6 -- Variables non initialisées et comportement indéfini).

Initialisation par copie

Lorsqu'une valeur initiale est fournie après un signe égal, on parle d'initialisation par copie (copy-initialization). Cette forme d'initialisation est héritée du langage C.

int width = 5; // initialisation par copie de la valeur 5 dans la variable width

Comme pour l'affectation par copie, cela copie la valeur située à droite du signe égal dans la variable créée à gauche. Dans l'extrait ci-dessus, la variable width est initialisée avec la valeur 5.

L'initialisation par copie était tombée en désuétude en C++ moderne, car elle est moins efficace que d'autres formes d'initialisation pour certains types complexes. Cependant, C++17 a résolu la plupart de ces problèmes, et l'initialisation par copie retrouve aujourd'hui des partisans. Vous la rencontrerez aussi dans du code plus ancien (en particulier du code porté depuis C), ou chez des développeurs qui la trouvent simplement plus naturelle et plus facile à lire.

Pour les lecteurs avancés

L'initialisation par copie est aussi utilisée chaque fois que des valeurs sont copiées implicitement, par exemple lors du passage d'arguments à une fonction par valeur, lors du retour d'une valeur par une fonction, ou lors de la capture d'exceptions par valeur.

Initialisation directe

Lorsqu'une valeur initiale est fournie entre parenthèses, on parle d'initialisation directe (direct-initialization).

int width ( 5 ); // initialisation directe de la valeur 5 dans la variable width

L'initialisation directe a été introduite à l'origine pour permettre une initialisation plus efficace d'objets complexes (ceux de type classe, que nous verrons dans un chapitre ultérieur). Comme l'initialisation par copie, l'initialisation directe était tombée en désuétude en C++ moderne, en grande partie parce qu'elle a été supplantée par l'initialisation directe par liste. Cependant, l'initialisation directe par liste présente elle-même quelques particularités, et l'initialisation directe retrouve donc son utilité dans certains cas.

Pour les lecteurs avancés

L'initialisation directe est aussi utilisée lorsque des valeurs sont converties explicitement vers un autre type (par exemple via static_cast).

Initialisation par liste

La manière moderne d'initialiser des objets en C++ consiste à utiliser une forme d'initialisation qui fait appel aux accolades. On parle d'initialisation par liste (list-initialization), ou d'initialisation uniforme (uniform initialization) ou d'initialisation par accolades (brace initialization).

L'initialisation par liste existe sous deux formes :

int width { 5 };    // initialisation directe par liste de la valeur initiale 5 dans la variable width (à privilégier)
int height = { 6 }; // initialisation par copie de liste de la valeur initiale 6 dans la variable height (rarement utilisée)

Avant C++11, certains types d'initialisation nécessitaient l'initialisation par copie, et d'autres l'initialisation directe. L'initialisation par copie est difficile à distinguer de l'affectation par copie (car les deux utilisent un =). Et l'initialisation directe peut être difficile à distinguer des opérations liées aux fonctions (car les deux utilisent des parenthèses).

L'initialisation par liste a été introduite pour fournir une syntaxe d'initialisation qui fonctionne dans presque tous les cas, se comporte de manière cohérente, et dont la syntaxe non ambiguë permet de repérer facilement l'endroit où un objet est initialisé.

Point clé

Lorsque nous voyons des accolades, nous savons que nous sommes en train d'initialiser un objet par liste.

De plus, l'initialisation par liste permet aussi d'initialiser des objets avec une liste de valeurs plutôt qu'une seule valeur (c'est pourquoi on parle d'« initialisation par liste »). Nous en montrons un exemple dans la leçon 16.2 -- Introduction à std::vector et aux constructeurs par liste.

L'initialisation par liste interdit les conversions restrictives

L'un des principaux avantages de l'initialisation par liste pour les nouveaux programmeurs C++ est que les « conversions restrictives » (narrowing conversions) y sont interdites. Cela signifie que si vous essayez d'initialiser une variable par liste avec une valeur que cette variable ne peut pas stocker en toute sécurité, le compilateur est tenu de produire un diagnostic (erreur de compilation ou avertissement) pour vous le signaler. Par exemple :

int main()
{
    // Un entier ne peut contenir que des valeurs sans partie fractionnaire.
    // Initialiser un int avec la valeur fractionnaire 4.5 oblige le compilateur à convertir 4.5 en une valeur que int peut contenir.
    // Une telle conversion est restrictive, car la partie fractionnaire de la valeur sera perdue.

    int w1 { 4.5 }; // erreur de compilation : l'initialisation par liste n'autorise pas la conversion restrictive

    int w2 = 4.5;   // compile : w2 initialisée par copie avec la valeur 4
    int w3 (4.5);   // compile : w3 initialisée directement avec la valeur 4

    return 0;
}

À la ligne 7 du programme ci-dessus, nous utilisons une valeur (4.5) possédant une composante fractionnaire (.5) pour initialiser par liste une variable entière (qui ne peut contenir que des valeurs sans partie fractionnaire). Comme il s'agit d'une conversion restrictive, le compilateur est tenu de générer un diagnostic dans ce cas.

L'initialisation par copie (ligne 9) et l'initialisation directe (ligne 10) suppriment toutes deux silencieusement le .5 et initialisent la variable avec la valeur 4 (ce qui n'est probablement pas ce que nous voulons). Votre compilateur peut vous en avertir (puisque la perte de données est rarement souhaitable), mais il peut aussi ne rien signaler.

Notez que cette restriction sur les conversions restrictives ne s'applique qu'à l'initialisation par liste, et non aux affectations ultérieures de la variable :

int main()
{
    int w1 { 4.5 }; // erreur de compilation : l'initialisation par liste n'autorise pas la conversion restrictive de 4.5 en 4

    w1 = 4.5;       // correct : l'affectation par copie autorise la conversion restrictive de 4.5 en 4

    return 0;
}

Initialisation par valeur et initialisation à zéro

Lorsqu'une variable est initialisée avec un ensemble vide d'accolades, une forme particulière d'initialisation par liste appelée initialisation par valeur (value-initialization) a lieu. Dans la plupart des cas, l'initialisation par valeur initialise implicitement la variable à zéro (ou à la valeur la plus proche de zéro pour un type donné). Lorsque cette mise à zéro a lieu, on parle d'initialisation à zéro (zero-initialization).

int width {}; // initialisation par valeur / initialisation à zéro à la valeur 0

Pour les lecteurs avancés

Pour les types classes, l'initialisation par valeur (et l'initialisation par défaut) peut au contraire initialiser l'objet avec des valeurs par défaut prédéfinies, qui peuvent être non nulles.

L'initialisation par liste est la forme privilégiée en C++ moderne

L'initialisation par liste (y compris l'initialisation par valeur) est généralement préférée aux autres formes d'initialisation, car elle fonctionne dans la plupart des cas (et est donc la plus cohérente), elle interdit les conversions restrictives (que nous ne voulons normalement pas), et elle permet l'initialisation avec une liste de valeurs (sujet que nous aborderons dans une future leçon).

Bonne pratique

Privilégiez l'initialisation directe par liste ou l'initialisation par valeur pour initialiser vos variables.

Note de l'auteur

Bjarne Stroustrup (créateur du C++) et Herb Sutter (expert du C++) recommandent eux aussi d'utiliser l'initialisation par liste pour initialiser vos variables.

En C++ moderne, il existe certains cas où l'initialisation par liste ne fonctionne pas comme prévu. Nous en traitons un dans la leçon 16.2 -- Introduction à std::vector et aux constructeurs par liste. En raison de ces particularités, certains développeurs expérimentés préconisent désormais d'utiliser un mélange d'initialisations par copie, directe et par liste, selon les circonstances. Lorsque vous serez suffisamment familiarisé avec le langage pour comprendre les subtilités de chaque type d'initialisation et les raisons de ces recommandations, vous pourrez juger par vous-même si ces arguments vous semblent convaincants.

Q : Quand faut-il initialiser avec { 0 } ou avec {} ?

Utilisez l'initialisation directe par liste lorsque vous utilisez réellement la valeur initiale :

int x { 0 };    // initialisation directe par liste avec la valeur initiale 0
std::cout << x; // on utilise ici cette valeur 0

Utilisez l'initialisation par valeur lorsque la valeur de l'objet est temporaire et sera remplacée :

int x {};      // initialisation par valeur
std::cin >> x; // on remplace immédiatement cette valeur, donc un 0 explicite n'aurait aucun sens

Initialisez vos variables

Initialisez vos variables dès leur création. Vous rencontrerez peut-être un jour des cas où vous voudrez ignorer ce conseil pour une raison précise (par exemple une section de code critique en termes de performances qui utilise beaucoup de variables), et ce n'est pas grave, tant que ce choix est fait délibérément.

Instanciation

Le terme instanciation (instantiation) est un mot savant qui signifie qu'une variable a été créée (allouée) et initialisée (ce qui inclut l'initialisation par défaut). Un objet instancié est parfois appelé instance. Ce terme s'applique le plus souvent aux objets de type classe, mais il est parfois employé pour des objets d'autres types.

Initialisation de plusieurs variables

Dans la section précédente, nous avons indiqué qu'il est possible de définir plusieurs variables du même type dans une seule instruction, en séparant leurs noms par une virgule :

int a, b; // crée les variables a et b, mais ne les initialise pas

Nous avons également indiqué que la bonne pratique consiste à éviter complètement cette syntaxe. Cependant, comme vous pourriez rencontrer d'autres codes qui utilisent ce style, il est utile d'en parler un peu plus, ne serait-ce que pour renforcer certaines raisons de l'éviter.

Vous pouvez initialiser plusieurs variables définies sur la même ligne :

int a = 5, b = 6;          // initialisation par copie
int c ( 7 ), d ( 8 );      // initialisation directe
int e { 9 }, f { 10 };     // initialisation directe par liste
int i {}, j {};            // initialisation par valeur

Malheureusement, il existe ici un piège courant : le programmeur essaie par erreur d'initialiser les deux variables avec une seule instruction d'initialisation :

int a, b = 5;     // faux : a n'est pas initialisée à 5 !
int a = 5, b = 5; // correct : a et b sont initialisées à 5

Dans la première instruction, la variable a restera non initialisée, et le compilateur peut ou non le signaler. Si ce n'est pas le cas, c'est une excellente façon de faire planter votre programme de manière intermittente ou de produire des résultats aléatoires. Nous reviendrons bientôt sur ce qui se passe si vous utilisez des variables non initialisées.

Le plus simple pour retenir que c'est faux est de noter que chaque variable ne peut être initialisée que par son propre initialiseur :

int a = 4, b = 5; // correct : a et b ont chacune leur initialiseur
int a, b = 5;     // faux : a n'a pas son propre initialiseur

Avertissements pour les variables initialisées et inutilisées

Les compilateurs modernes génèrent généralement des avertissements lorsqu'une variable est initialisée mais jamais utilisée (car cela est rarement souhaitable). Et si l'option « traiter les avertissements comme des erreurs » est activée, ces avertissements deviennent des erreurs et font échouer la compilation.

Considérons le programme suivant, d'apparence inoffensive :

int main()
{
    int x { 5 }; // variable x définie

    // mais jamais utilisée nulle part

    return 0;
}

Si l'on compile ce programme avec GCC et l'option « traiter les avertissements comme des erreurs » activée, l'erreur suivante est générée :


prog.cc: In function 'int main()':
prog.cc:3:9: error: unused variable 'x' [-Werror=unused-variable]

et le programme ne compile pas.

Il existe quelques moyens simples de corriger cela.

  1. Si la variable est réellement inutile et que vous n'en avez pas besoin, la solution la plus simple est de supprimer la définition de x (ou de la commenter). Après tout, si elle n'est pas utilisée, la supprimer n'affectera rien.
  2. Une autre option consiste simplement à utiliser la variable quelque part :
#include <iostream>

int main()
{
    int x { 5 };

    std::cout << x; // la variable est maintenant utilisée quelque part

    return 0;
}

Mais cela demande un effort pour écrire du code qui l'utilise, et présente l'inconvénient de pouvoir modifier le comportement de votre programme.

L'attribut [[maybe_unused]] (C++17)

Dans certains cas, aucune des deux options ci-dessus n'est souhaitable. Considérons le cas où nous disposons d'un ensemble de valeurs mathématiques ou physiques que nous utilisons dans de nombreux programmes différents :

#include <iostream>

int main()
{
    // Voici quelques valeurs mathématiques/physiques que nous avons copiées-collées depuis ailleurs
    double pi { 3.14159 };
    double gravity { 9.8 };
    double phi { 1.61803 };

    std::cout << pi << '\n';  // pi est utilisée
    std::cout << phi << '\n'; // phi est utilisée

    // Le compilateur va probablement se plaindre que gravity est définie mais inutilisée

    return 0;
}

Si nous utilisons souvent ces valeurs, nous les avons probablement sauvegardées quelque part et nous les copions, collons ou importons toutes ensemble.

Cependant, dans tout programme où nous n'utilisons pas toutes ces valeurs, le compilateur risque de signaler chaque variable qui n'est pas réellement utilisée. Dans l'exemple ci-dessus, nous pourrions facilement supprimer la définition de gravity. Mais que faire s'il y avait 20 ou 30 variables au lieu de 3 ? Et si nous les utilisons à plusieurs endroits ? Parcourir la liste pour supprimer ou commenter les variables inutilisées demande du temps et de l'énergie. Et si nous avons ensuite besoin de l'une de celles que nous avons retirées, il faudra encore du temps et de l'énergie pour la rajouter ou la décommenter.

Pour répondre à ce type de situation, C++17 a introduit l'attribut [[maybe_unused]], qui nous permet d'indiquer au compilateur que nous acceptons qu'une variable soit inutilisée. Le compilateur ne générera alors pas d'avertissement pour les variables inutilisées de ce type.

Le programme suivant ne devrait générer aucun avertissement ni erreur :

#include <iostream>

int main()
{
    [[maybe_unused]] double pi { 3.14159 };  // Ne pas signaler si pi est inutilisée
    [[maybe_unused]] double gravity { 9.8 }; // Ne pas signaler si gravity est inutilisée
    [[maybe_unused]] double phi { 1.61803 }; // Ne pas signaler si phi est inutilisée

    std::cout << pi << '\n';
    std::cout << phi << '\n';

    // Le compilateur ne signalera plus que gravity n'est pas utilisée

    return 0;
}

De plus, le compilateur optimisera probablement ces variables et les retirera du programme, de sorte qu'elles n'ont aucun impact sur les performances.

L'attribut [[maybe_unused]] ne doit être appliqué que de façon sélective aux variables qui ont une raison précise et légitime d'être inutilisées (par exemple parce que vous avez besoin d'une liste de valeurs nommées, mais que les valeurs réellement utilisées dans un programme donné peuvent varier). Dans les autres cas, les variables inutilisées doivent être retirées du programme.

Note de l'auteur

Dans les prochaines leçons, nous définirons souvent des variables que nous n'utiliserons pas, afin de démontrer la syntaxe de certains concepts. L'utilisation de [[maybe_unused]] nous permet de le faire sans avertissements ni erreurs de compilation.

C'est l'heure du quiz

Question n° 1

Quelle est la différence entre l'initialisation et l'affectation ?

Solution

L'initialisation donne à une variable une valeur initiale au moment de sa création. L'affectation donne à une variable une valeur à un moment postérieur à sa création.

Question n° 2

Quelle forme d'initialisation faut-il privilégier lorsque vous voulez initialiser une variable avec une valeur précise ?

Solution

L'initialisation directe par liste (aussi appelée initialisation directe par accolades).

Question n° 3

Qu'est-ce que l'initialisation par défaut et l'initialisation par valeur ? Quel est le comportement de chacune ? Laquelle faut-il privilégier ?

Solution

L'initialisation par défaut a lieu lorsque l'initialisation d'une variable ne comporte aucun initialiseur (par exemple int x;). Dans la plupart des cas, la variable reste avec une valeur indéterminée.

L'initialisation par valeur a lieu lorsque l'initialisation d'une variable comporte un initialiseur formé d'accolades vides (par exemple int x{};). Dans la plupart des cas, cela réalise une initialisation à zéro.

Il faut privilégier l'initialisation par valeur, car elle initialise la variable à une valeur cohérente.
