6.6 — L'opérateur conditionnel

Opérateur Symbole Forme Signification
Conditionnel ?: c ? x : y Si la condition c vaut true, alors on évalue x, sinon on évalue y

L'opérateur conditionnel (?:), parfois appelé opérateur if arithmétique (arithmetic if), est un opérateur ternaire (un opérateur qui prend 3 opérandes). Comme il a historiquement été le seul opérateur ternaire de C++, on parle aussi parfois de « l'opérateur ternaire ».

L'opérateur ?: fournit une écriture abrégée pour un type particulier d'instruction if-else.

Contenu associé

Nous abordons les instructions if-else dans la leçon 4.10 -- Introduction aux instructions if.

Pour rappel, une instruction if-else prend la forme suivante :


if (condition)
    statement1;
else
    statement2;

Si condition vaut true, alors statement1 est exécutée, sinon statement2 est exécutée. Le else et statement2 sont facultatifs.

L'opérateur ?: prend la forme suivante :


condition ? expression1 : expression2;

Si condition vaut true, alors expression1 est évaluée, sinon expression2 est évaluée. Le : et expression2 ne sont pas facultatifs.

Considérons une instruction if-else de la forme suivante :

if (x > y)
    max = x;
else
    max = y;

Elle peut être réécrite ainsi :

max = ((x > y) ? x : y);

Dans de tels cas, l'opérateur conditionnel permet de rendre le code plus compact sans perdre en lisibilité.

Un exemple

Considérons l'exemple suivant :

#include <iostream>

int getValue()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    return x;
}

int main()
{
    int x { getValue() };
    int y { getValue() };
    int max { (x > y) ? x : y };
    std::cout << "The max of " << x <<" and " << y << " is " << max << ".\n";

    return 0;
}

Commençons par saisir 5 puis 7 (donc x vaut 5 et y vaut 7). Lors de l'initialisation de max, l'expression (5 > 7) ? 5 : 7 est évaluée. Comme 5 > 7 vaut false, on obtient false ? 5 : 7, qui s'évalue à 7. Le programme affiche :


The max of 5 and 7 is 7.

Saisissons maintenant 7 puis 5 (donc x vaut 7 et y vaut 5). On obtient alors (7 > 5) ? 7 : 5, c'est-à-dire true ? 7 : 5, qui s'évalue à 7. Le programme affiche :


The max of 7 and 5 is 7.

L'opérateur conditionnel est évalué dans le cadre d'une expression

Comme l'opérateur conditionnel est évalué dans le cadre d'une expression, il peut être utilisé partout où une expression est acceptée. Lorsque les opérandes de l'opérateur conditionnel sont des expressions constantes, il peut également être utilisé dans une expression constante.

Cela permet d'utiliser l'opérateur conditionnel là où des instructions ne peuvent pas être utilisées.

Par exemple, pour initialiser une variable :

#include <iostream>

int main()
{
    constexpr bool inBigClassroom { false };
    constexpr int classSize { inBigClassroom ? 30 : 20 };
    std::cout << "The class size is: " << classSize << '\n';

    return 0;
}

Il n'existe pas de remplacement direct par un if-else dans ce cas.

Vous pourriez être tenté d'essayer quelque chose comme ceci :

#include <iostream>

int main()
{
    constexpr bool inBigClassroom { false };

    if (inBigClassroom)
        constexpr int classSize { 30 };
    else
        constexpr int classSize { 20 };

    std::cout << "The class size is: " << classSize << '\n'; // Compile error: classSize not defined

    return 0;
}

Pourtant, cela ne compile pas, et vous obtiendrez un message d'erreur indiquant que classSize n'est pas défini. De la même manière que les variables définies à l'intérieur d'une fonction disparaissent à la fin de la fonction, les variables définies à l'intérieur d'une instruction if ou else disparaissent à la fin de cette instruction if ou else. Ainsi, classSize a déjà été détruite au moment où nous essayons de l'afficher.

Si vous voulez utiliser un if-else, il faut procéder ainsi :

#include <iostream>

int getClassSize(bool inBigClassroom)
{
    if (inBigClassroom)
        return 30;
    else
        return 20;
}

int main()
{
    const int classSize { getClassSize(false) };
    std::cout << "The class size is: " << classSize << '\n';

    return 0;
}

Cette version fonctionne, car getClassSize(false) est une expression, et la logique if-else se trouve dans une fonction (où l'on peut utiliser des instructions). Mais cela représente beaucoup de code supplémentaire, alors que nous pourrions simplement utiliser l'opérateur conditionnel.

Mettre l'opérateur conditionnel entre parenthèses

Comme C++ donne la priorité à l'évaluation de la plupart des opérateurs par rapport à l'opérateur conditionnel, il est assez facile d'écrire, avec l'opérateur conditionnel, des expressions qui ne s'évaluent pas comme prévu.

Contenu associé

Nous étudions la manière dont C++ hiérarchise l'évaluation des opérateurs dans la leçon future 6.1 -- Priorité et associativité des opérateurs.

Par exemple :

#include <iostream>

int main()
{
    int x { 2 };
    int y { 1 };
    int z { 10 - x > y ? x : y };
    std::cout << z;

    return 0;
}

Vous pourriez vous attendre à ce que cette expression s'évalue comme 10 - (x > y ? x : y) (ce qui donnerait 8), mais elle s'évalue en réalité comme (10 - x) > y ? x : y (ce qui donne 2).

Voici un autre exemple qui illustre une erreur courante :

#include <iostream>

int main()
{
    int x { 2 };
    std::cout << (x < 0) ? "negative" : "non-negative";

    return 0;
}

Vous pourriez vous attendre à ce que ce programme affiche non-negative, mais il affiche en fait 0.

Lecture facultative

Voici ce qui se passe dans l'exemple ci-dessus. Tout d'abord, x < 0 s'évalue à false. L'expression partiellement évaluée devient alors std::cout << false ? "negative" : "non-negative". Comme operator<< a une priorité plus élevée que operator?:, cette expression s'évalue comme si elle était écrite (std::cout << false) ? "negative" : "non-negative". Ainsi, std::cout << false est évalué, ce qui affiche 0 (et renvoie std::cout).

L'expression partiellement évaluée devient maintenant std::cout ? "negative" : "non-negative". Comme std::cout est tout ce qui reste comme condition, le compilateur essaie de le convertir en bool pour résoudre la condition. Chose surprenante, std::cout dispose d'une conversion définie vers bool, qui renvoie très probablement false. En supposant qu'elle renvoie false, nous obtenons false ? "negative" : "non-negative", qui s'évalue à "non-negative". L'instruction complètement évaluée est donc "non-negative";. Une instruction d'expression qui ne consiste qu'en un littéral (ici, un littéral de chaîne) n'a aucun effet, et l'affaire est close.

Pour éviter ces problèmes de priorité d'évaluation, l'opérateur conditionnel doit être mis entre parenthèses de la manière suivante :

  • Mettez entre parenthèses l'ensemble de l'opération conditionnelle (y compris ses opérandes) lorsqu'elle est utilisée dans une expression composée (une expression contenant d'autres opérateurs).
  • Pour la lisibilité, envisagez de mettre la condition entre parenthèses si elle contient des opérateurs (autres que l'opérateur d'appel de fonction).

Les opérandes de l'opérateur conditionnel n'ont pas besoin d'être mis entre parenthèses.

Examinons quelques instructions contenant l'opérateur conditionnel et la manière dont elles doivent être parenthésées :

return isStunned ? 0 : movesLeft;           // not used in compound expression, condition contains no operators
int z { (x > y) ? x : y };                  // not used in compound expression, condition contains operators
std::cout << (isAfternoon() ? "PM" : "AM"); // used in compound expression, condition contains no operators (function call operator excluded)
std::cout << ((x > y) ? x : y);             // used in compound expression, condition contains operators

Bonne pratique

Mettez entre parenthèses l'ensemble de l'opération conditionnelle (y compris ses opérandes) lorsqu'elle est utilisée dans une expression composée.

Pour la lisibilité, envisagez de mettre la condition entre parenthèses si elle contient des opérateurs (autres que l'opérateur d'appel de fonction).

Les types des expressions doivent correspondre ou être convertibles

Pour respecter les règles de vérification de types de C++, l'une des conditions suivantes doit être vraie :

  • Les types des deuxième et troisième opérandes doivent correspondre.
  • Le compilateur doit pouvoir trouver un moyen de convertir l'un des deuxième et troisième opérandes, ou les deux, vers des types correspondants. Les règles de conversion qu'utilise le compilateur sont assez complexes et peuvent produire des résultats surprenants dans certains cas.

Pour les lecteurs avancés

Par ailleurs, l'un des deuxième et troisième opérandes, ou les deux, peut être une expression throw. Nous abordons throw dans la leçon 27.2 -- Gestion de base des exceptions.

Par exemple :

#include <iostream>

int main()
{
    std::cout << (true ? 1 : 2) << '\n';    // okay: both operands have matching type int

    std::cout << (false ? 1 : 2.2) << '\n'; // okay: int value 1 converted to double

    std::cout << (true ? -1 : 2u) << '\n';  // surprising result: -1 converted to unsigned int, result out of range

    return 0;
}

En supposant des entiers de 4 octets, le programme ci-dessus affiche :


1
2.2
4294967295

En général, il est acceptable de mélanger des opérandes de types fondamentaux (à l'exception du mélange de valeurs signées et non signées). Si l'un des opérandes n'est pas d'un type fondamental, il est généralement préférable de convertir explicitement un ou les deux opérandes vers un type commun, afin de savoir exactement ce que vous obtiendrez.

Contenu associé

Le cas surprenant évoqué ci-dessus, qui concerne le mélange de valeurs signées et non signées, découle des règles de conversions arithmétiques, que nous abordons dans la leçon 10.5 -- Conversions arithmétiques.

Si le compilateur ne peut pas trouver de moyen de convertir les deuxième et troisième opérandes vers un type commun, une erreur de compilation se produit :

#include <iostream>

int main()
{
    constexpr int x{ 5 };
    std::cout << ((x != 5) ? x : "x is 5"); // compile error: compiler can't find common type for constexpr int and C-style string literal

    return 0;
}

Dans l'exemple ci-dessus, l'une des expressions est un entier et l'autre est une chaîne littérale de style C. Le compilateur ne peut pas trouver seul un type correspondant, et une erreur de compilation se produit donc.

Dans de tels cas, vous pouvez soit effectuer une conversion explicite, soit utiliser une instruction if-else :

#include <iostream>
#include <string>

int main()
{
    int x{ 5 }; // intentionally non-constexpr for this example

    // We can explicitly convert the types to match
    std::cout << ((x != 5) ? std::to_string(x) : std::string{"x is 5"}) << '\n';

    // Or use an if-else statement
    if (x != 5)
        std::cout << x << '\n';
    else
        std::cout << "x is 5" << '\n';

    return 0;
}

Pour les lecteurs avancés

Si x est constexpr, alors la condition x != 5 est une expression constante. Dans ce cas, il faut préférer if constexpr à if, et votre compilateur peut émettre un avertissement qui le signale (lequel deviendra une erreur si vous traitez les avertissements comme des erreurs).

Comme nous n'avons pas encore abordé if constexpr (nous le faisons dans la leçon 8.4 -- Instructions if constexpr), x n'est pas constexpr dans cet exemple, afin d'éviter cet avertissement éventuel du compilateur.

Alors, quand faut-il utiliser l'opérateur conditionnel ?

L'opérateur conditionnel est particulièrement utile dans les cas suivants :

  • Initialiser un objet avec l'une de deux valeurs.
  • Affecter à un objet l'une de deux valeurs.
  • Passer à une fonction l'une de deux valeurs.
  • Renvoyer depuis une fonction l'une de deux valeurs.
  • Afficher l'une de deux valeurs.

Les expressions compliquées doivent généralement éviter l'opérateur conditionnel, car elles sont sujettes aux erreurs et difficiles à lire.

Bonne pratique

Évitez de préférence l'opérateur conditionnel dans les expressions compliquées.
