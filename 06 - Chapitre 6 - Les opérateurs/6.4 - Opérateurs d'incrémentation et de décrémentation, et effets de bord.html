6.4 — Opérateurs d'incrémentation et de décrémentation, et effets de bord

Incrémenter et décrémenter des variables

Incrémenter (ajouter 1 à) et décrémenter (retrancher 1 à) une variable sont deux opérations si courantes qu'elles disposent chacune de leur propre opérateur.

| Opérateur | Symbole | Forme | Opération | | Pré-incrémentation (prefix increment) | ++ | ++x | Incrémente x, puis renvoie x | | Pré-décrémentation (prefix decrement) | –– | ––x | Décrémente x, puis renvoie x | | Post-incrémentation (postfix increment) | ++ | x++ | Copie x, incrémente x, puis renvoie la copie | | Post-décrémentation (postfix decrement) | –– | x–– | Copie x, décrémente x, puis renvoie la copie |

Notez qu'il existe deux versions de chaque opérateur : une version préfixe (où l'opérateur précède l'opérande) et une version postfixe (où l'opérateur suit l'opérande).

Pré-incrémentation et pré-décrémentation

Les opérateurs d'incrémentation et de décrémentation préfixes sont très simples. D'abord, l'opérande est incrémenté ou décrémenté, puis l'expression est évaluée à la valeur de l'opérande. Par exemple :

#include <iostream>

int main()
{
    int x { 5 };
    int y { ++x }; // x est incrémenté à 6, x est évalué à la valeur 6, et 6 est affecté à y

    std::cout << x << ' ' << y << '\n';
    return 0;
}

Cela affiche :


6 6

Post-incrémentation et post-décrémentation

Les opérateurs d'incrémentation et de décrémentation postfixes sont plus délicats. D'abord, une copie de l'opérande est faite. Ensuite, l'opérande (et non la copie) est incrémenté ou décrémenté. Enfin, la copie (et non l'original) est évaluée. Par exemple :

#include <iostream>

int main()
{
    int x { 5 };
    int y { x++ }; // x est incrémenté à 6, la copie de x d'origine est évaluée à la valeur 5, et 5 est affecté à y

    std::cout << x << ' ' << y << '\n';
    return 0;
}

Cela affiche :


6 5

Examinons plus en détail le fonctionnement de cette ligne 6. D'abord, une copie temporaire de x est créée, avec la même valeur que x (5). Ensuite, le x réel est incrémenté de 5 à 6. Puis la copie de x (qui vaut toujours 5) est renvoyée et affectée à y. Enfin, la copie temporaire est détruite.

Par conséquent, y finit avec la valeur 5 (la valeur avant incrémentation), et x finit avec la valeur 6 (la valeur après incrémentation).

Notez que la version postfixe demande beaucoup plus d'étapes et peut donc être moins performante que la version préfixe.

Exemples supplémentaires

Voici un autre exemple montrant la différence entre les versions préfixe et postfixe :

#include <iostream>

int main()
{
    int x { 5 };
    int y { 5 };
    std::cout << x << ' ' << y << '\n';
    std::cout << ++x << ' ' << --y << '\n'; // préfixe
    std::cout << x << ' ' << y << '\n';
    std::cout << x++ << ' ' << y-- << '\n'; // postfixe
    std::cout << x << ' ' << y << '\n';

    return 0;
}

Ce programme produit la sortie suivante :


5 5
6 4
6 4
6 4
7 3

À la 3e ligne de sortie (la 8e ligne du programme), nous effectuons une pré-incrémentation et une pré-décrémentation. Sur cette ligne, x et y sont incrémentés/décrémentés avant que leurs valeurs ne soient envoyées à std::cout, si bien que std::cout affiche leurs valeurs mises à jour.

À la 4e ligne de sortie (la 10e ligne du programme), nous effectuons une post-incrémentation et une post-décrémentation. Sur cette ligne, c'est la copie de x et y (avec les valeurs avant incrémentation et avant décrémentation) qui est envoyée à std::cout ; nous ne voyons donc pas les modifications ici. Elles n'apparaissent qu'à la ligne suivante, lorsque x et y sont de nouveau évalués.

Quand utiliser la forme préfixe ou postfixe

Dans de nombreux cas, les opérateurs préfixes et postfixes produisent le même comportement :

int main()
{
    int x { 0 };
    ++x; // incrémente x à 1
    x++; // incrémente x à 2

    return 0;
}

Lorsque le code peut être écrit avec la forme préfixe ou postfixe, préférez la forme préfixe, car elle est généralement plus performante et moins susceptible de causer des surprises.

Bonne pratique

Privilégiez les versions préfixes, car elles sont plus performantes et moins susceptibles de causer des surprises.

Utilisez les versions postfixes lorsque cela produit un code nettement plus concis ou plus compréhensible que le code équivalent écrit avec les versions préfixes.

Effets de bord

Une fonction ou une expression a un effet de bord (side effect) si elle produit un effet observable au-delà de la valeur qu'elle renvoie.

Les exemples courants d'effets de bord incluent la modification de la valeur d'objets, les entrées et sorties, ou la mise à jour d'une interface graphique (par exemple, activer ou désactiver un bouton).

La plupart du temps, les effets de bord sont utiles :

x = 5; // l'opérateur d'affectation a pour effet de bord de modifier la valeur de x
++x; // operator++ a pour effet de bord d'incrémenter x
std::cout << x; // operator<< a pour effet de bord de modifier l'état de la console

L'opérateur d'affectation de l'exemple ci-dessus a pour effet de bord de modifier durablement la valeur de x. Même après la fin de l'exécution de l'instruction, x vaut toujours 5. De même, avec operator++, la valeur de x est modifiée même après la fin de l'évaluation de l'instruction. L'affichage de x a également pour effet de bord de modifier l'état de la console, puisque vous pouvez maintenant voir la valeur de x affichée à l'écran.

Point clé

Les opérateurs d'affectation, l'opérateur préfixe et l'opérateur postfixe ont des effets de bord qui modifient durablement la valeur d'un objet.
Les autres opérateurs (comme les opérateurs arithmétiques) renvoient une valeur et ne modifient pas leurs opérandes.

Les effets de bord peuvent poser des problèmes d'ordre d'évaluation

Dans certains cas, les effets de bord peuvent entraîner des problèmes d'ordre d'évaluation. Par exemple :

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

int main()
{
    int x { 5 };
    int value{ add(x, ++x) }; // comportement indéfini : est-ce 5 + 6, ou 6 + 6 ?
    // Cela dépend de l'ordre dans lequel votre compilateur évalue les arguments de la fonction

    std::cout << value << '\n'; // value peut valoir 11 ou 12, selon la façon dont la ligne ci-dessus est évaluée !

    return 0;
}

La norme C++ ne définit pas l'ordre dans lequel les arguments de fonction sont évalués. Si l'argument de gauche est évalué en premier, cela revient à appeler add(5, 6), qui vaut 11. Si l'argument de droite est évalué en premier, cela revient à appeler add(6, 6), qui vaut 12 ! Notez que ce problème ne survient que parce qu'un des arguments de la fonction add() a un effet de bord.

En complément…

La norme C++ ne définit volontairement pas ces points, afin que les compilateurs puissent faire ce qui est le plus naturel (et donc le plus performant) pour une architecture donnée.

L'ordonnancement des effets de bord

Dans de nombreux cas, C++ ne précise pas non plus à quel moment les effets de bord des opérateurs doivent être appliqués. Cela peut conduire à un comportement indéfini lorsqu'un objet dont un effet de bord est appliqué est utilisé plus d'une fois dans la même instruction.

Par exemple, l'expression x + ++x a un comportement non spécifié. Lorsque x est initialisé à 1, Visual Studio et GCC l'évaluent comme 2 + 2, tandis que Clang l'évalue comme 1 + 2 ! Cela tient aux différences dans le moment où les compilateurs appliquent l'effet de bord qui consiste à incrémenter x.

Même lorsque la norme C++ précise clairement comment les choses doivent être évaluées, ce domaine a historiquement été le siège de nombreux bogues de compilateurs. Ces problèmes peuvent généralement tous être évités en veillant à ce qu'une variable ayant un effet de bord appliqué ne soit utilisée qu'au plus une fois dans une instruction donnée.

Attention

C++ ne définit pas l'ordre d'évaluation des arguments de fonction ni des opérandes des opérateurs.

Attention

N'utilisez pas plus d'une fois, dans une même instruction, une variable ayant un effet de bord appliqué. Si vous le faites, le résultat peut être indéfini.

Une exception concerne les expressions d'affectation simples comme x = x + y (qui est essentiellement équivalente à x += y).
