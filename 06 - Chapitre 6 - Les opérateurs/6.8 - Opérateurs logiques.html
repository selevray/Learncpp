6.8 — Opérateurs logiques

Les opérateurs relationnels (de comparaison) permettent de tester si une condition particulière est vraie ou fausse, mais ils ne testent qu'une seule condition à la fois. Or il faut souvent savoir si plusieurs conditions sont vraies simultanément. Par exemple, pour savoir si nous avons gagné au loto, il faut comparer chacun des nombres que nous avons choisis avec les numéros gagnants. Dans un loto à 6 numéros, cela représente 6 comparaisons, qui doivent toutes être vraies. Dans d'autres cas, il faut savoir si l'une quelconque de plusieurs conditions est vraie. Par exemple, nous pouvons décider de ne pas aller travailler aujourd'hui si nous sommes malades, ou trop fatigués, ou si nous avons gagné au loto dans notre exemple précédent. Il faut alors vérifier si l'une quelconque des 3 comparaisons est vraie.

Les opérateurs logiques nous permettent de tester plusieurs conditions.

C++ dispose de 3 opérateurs logiques :

Opérateur Symbole Exemple d'utilisation Opération
NON logique ! !x vrai si x est faux, faux si x est vrai
ET logique && x && y vrai si x et y sont tous deux vrais, faux sinon
OU logique || x || y vrai si x ou y (ou les deux) sont vrais, faux sinon

NON logique

Vous avez déjà rencontré l'opérateur unaire de NON logique dans la leçon 4.9 -- Valeurs booléennes. Nous pouvons résumer l'effet du NON logique ainsi :

NON logique (opérateur !)
Opérande Résultat
true false
false true

Si l'opérande du NON logique vaut true, le NON logique vaut false. Si l'opérande du NON logique vaut false, le NON logique vaut true. En d'autres termes, le NON logique inverse une valeur booléenne : de true à false, et inversement.

Le NON logique est souvent utilisé dans les conditions :

bool tooLarge { x > 100 }; // tooLarge vaut true si x > 100
if (!tooLarge)
    // faire quelque chose avec x
else
    // afficher une erreur

Il faut se méfier du fait que le NON logique a une priorité très élevée. Les nouveaux programmeurs commettent souvent l'erreur suivante :

#include <iostream>

int main()
{
    int x{ 5 };
    int y{ 7 };

    if (!x > y)
        std::cout << x << " is not greater than " << y << '\n';
    else
        std::cout << x << " is greater than " << y << '\n';

    return 0;
}

Ce programme affiche :


5 is greater than 7

Or x n'est pas supérieur à y, alors comment est-ce possible ? La réponse tient au fait que l'opérateur NON logique a une priorité plus élevée que l'opérateur supérieur à. L'expression ! x > y s'évalue donc en (!x) > y. Comme x vaut 5, !x vaut 0, et 0 > y est faux : c'est donc l'instruction else qui s'exécute !

La bonne façon d'écrire le code ci-dessus est :

#include <iostream>

int main()
{
    int x{ 5 };
    int y{ 7 };

    if (!(x > y))
        std::cout << x << " is not greater than " << y << '\n';
    else
        std::cout << x << " is greater than " << y << '\n';

    return 0;
}

Ainsi, x > y est évalué en premier, puis le NON logique inverse le résultat booléen.

Bonne pratique

Si le NON logique doit s'appliquer au résultat d'autres opérateurs, ces opérateurs et leurs opérandes doivent être entourés de parenthèses.

Les utilisations simples du NON logique, comme if (!value), n'ont pas besoin de parenthèses, car la priorité n'entre pas en jeu.

OU logique

L'opérateur OU logique sert à tester si l'une de deux conditions au moins est vraie. Si l'opérande de gauche vaut true, ou si l'opérande de droite vaut true, ou si les deux valent true, l'opérateur OU logique renvoie true. Dans le cas contraire, il renvoie false.

OU logique (opérateur ||)
Opérande de gauche Opérande de droite Résultat
false false false
false true true
true false true
true true true

Prenons par exemple le programme suivant :

#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    int value {};
    std::cin >> value;

    if (value == 0 || value == 1)
        std::cout << "You picked 0 or 1\n";
    else
        std::cout << "You did not pick 0 or 1\n";
    return 0;
}

Ici, nous utilisons l'opérateur OU logique pour tester si la condition de gauche (value == 0) ou la condition de droite (value == 1) est vraie. Si l'une des deux (ou les deux) est vraie, l'opérateur OU logique vaut true, ce qui fait exécuter l'instruction if. Si aucune n'est vraie, l'opérateur OU logique vaut false, ce qui fait exécuter l'instruction else.

Attention

Les nouveaux programmeurs essaient parfois ceci :

    if (value == 0 || 1) // incorrect : si value vaut 0, ou si 1

Lorsque 1 est évalué, il est implicitement converti en bool true. La condition vaut donc toujours true.

Si vous voulez comparer une variable à plusieurs valeurs, vous devez comparer la variable plusieurs fois :

    if (value == 0 || value == 1) // correct : si value vaut 0, ou si value vaut 1

Vous pouvez enchaîner plusieurs OU logiques :

if (value == 0 || value == 1 || value == 2 || value == 3)
     std::cout << "You picked 0, 1, 2, or 3\n";

Les nouveaux programmeurs confondent parfois l'opérateur OU logique (||) avec l'opérateur OU binaire (|) (présenté dans la leçon O.2 -- Opérateurs binaires). Bien que les deux contiennent OU dans leur nom, ils n'ont pas la même fonction. Les confondre conduira probablement à des résultats incorrects.

ET logique

L'opérateur ET logique sert à tester si les deux opérandes sont vrais. Si c'est le cas, il renvoie true. Dans le cas contraire, il renvoie false.

ET logique (opérateur &&)
Opérande de gauche Opérande de droite Résultat
false false false
false true false
true false false
true true true

Par exemple, nous pouvons vouloir savoir si la valeur de la variable x est comprise entre 10 et 20. Il s'agit en fait de deux conditions : il faut savoir si x est supérieur à 10, et aussi si x est inférieur à 20.

#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    int value {};
    std::cin >> value;

    if (value > 10 && value < 20)
        std::cout << "Your value is between 10 and 20\n";
    else
        std::cout << "Your value is not between 10 and 20\n";
    return 0;
}

Ici, nous utilisons l'opérateur ET logique pour tester si la condition de gauche (value > 10) ET la condition de droite (value < 20) sont toutes deux vraies. Si c'est le cas, l'opérateur ET logique vaut true et l'instruction if s'exécute. Si aucune des deux n'est vraie, ou si une seule l'est, l'opérateur ET logique vaut false et l'instruction else s'exécute.

Comme pour le OU logique, vous pouvez enchaîner plusieurs ET logiques :

if (value > 10 && value < 20 && value != 16)
    // faire quelque chose
else
    // faire autre chose

Si toutes ces conditions sont vraies, l'instruction if s'exécute. Si l'une d'elles est fausse, c'est l'instruction else qui s'exécute.

Comme pour le OU, les nouveaux programmeurs confondent parfois l'opérateur ET logique (&&) avec l'opérateur ET binaire (&).

Évaluation en court-circuit

Pour que le ET logique renvoie true, les deux opérandes doivent valoir true. Si l'opérande de gauche vaut false, le ET logique sait qu'il doit renvoyer false, quelle que soit la valeur de l'opérande de droite. Dans ce cas, l'opérateur ET logique renvoie false immédiatement, sans même évaluer l'opérande de droite ! C'est ce qu'on appelle l'évaluation en court-circuit, qui sert principalement à optimiser le programme.

De même, si l'opérande de gauche du OU logique vaut true, la condition OU entière doit valoir true, et l'opérande de droite n'est pas évaluée.

L'évaluation en court-circuit fournit une nouvelle occasion de montrer pourquoi les opérateurs qui provoquent des effets de bord ne doivent pas être utilisés dans des expressions composées. Considérons l'extrait suivant :

if (x == 1 && ++y == 2)
    // faire quelque chose

Si x est différent de 1, la condition entière doit être fausse, donc ++y n'est jamais évalué ! Ainsi, y n'est incrémenté que si x vaut 1, ce qui n'est probablement pas ce que le programmeur voulait !

Attention

L'évaluation en court-circuit peut faire que le OU logique et le ET logique n'évaluent pas leur opérande de droite. Évitez d'utiliser des expressions à effets de bord avec ces opérateurs.

Point clé

Le OU logique et le ET logique sont une exception à la règle selon laquelle les opérandes peuvent être évalués dans n'importe quel ordre, car la norme précise explicitement que l'opérande de gauche doit être évalué en premier.

Pour les lecteurs avancés

Seules les versions intégrées de ces opérateurs effectuent l'évaluation en court-circuit. Si vous surchargez ces opérateurs pour les faire fonctionner avec vos propres types, ces opérateurs surchargés n'effectueront pas l'évaluation en court-circuit.

Mélanger ET et OU

Il est souvent impossible d'éviter de mélanger ET logique et OU logique dans la même expression, mais c'est un domaine riche en pièges potentiels.

Comme le ET logique et le OU logique forment une paire, de nombreux programmeurs supposent qu'ils ont la même priorité (comme l'addition/soustraction ou la multiplication/division). Pourtant, le ET logique a une priorité plus élevée que le OU logique : les opérateurs ET logique sont donc évalués avant les opérateurs OU logique (sauf s'ils sont entourés de parenthèses).

Les nouveaux programmeurs écrivent souvent des expressions telles que value1 || value2 && value3. Comme le ET logique a la priorité la plus élevée, cette expression s'évalue en value1 || (value2 && value3), et non en (value1 || value2) && value3. Espérons que c'est ce que le programmeur voulait ! S'il supposait une associativité de gauche à droite (comme pour l'addition/soustraction ou la multiplication/division), il obtiendra un résultat inattendu !

Lorsque vous mélangez ET logique et OU logique dans la même expression, il est judicieux de mettre explicitement entre parenthèses chaque opérateur et ses opérandes. Cela évite les erreurs de priorité, rend le code plus lisible et définit clairement la façon dont vous souhaitez que l'expression soit évaluée. Par exemple, plutôt que d'écrire value1 && value2 || value3 && value4, il vaut mieux écrire (value1 && value2) || (value3 && value4).

Bonne pratique

Lorsque vous mélangez ET logique et OU logique dans une même expression, mettez explicitement entre parenthèses chaque opération pour garantir qu'elles s'évaluent comme vous le souhaitez.

Lois de De Morgan

De nombreux programmeurs commettent aussi l'erreur de penser que !(x && y) est équivalent à !x && !y. Malheureusement, on ne peut pas « distribuer » le NON logique de cette manière.

Les lois de De Morgan nous indiquent comment distribuer le NON logique dans ces cas :

!(x && y) est équivalent à !x || !y
!(x || y) est équivalent à !x && !y

En d'autres termes, lorsque vous distribuez le NON logique, vous devez aussi remplacer le ET logique par le OU logique, et inversement !

Cela peut parfois être utile pour rendre des expressions complexes plus lisibles.

Pour les lecteurs avancés

Nous pouvons démontrer que la première partie des lois de De Morgan est correcte en prouvant que !(x && y) est égal à !x || !y pour toutes les valeurs possibles de x et y. Pour cela, nous utiliserons un concept mathématique appelé table de vérité :

x y !x !y !(x && y) !x || !y
false false true true true true
false true true false true true
true false false true true true
true true false false false false

Dans cette table, les première et deuxième colonnes représentent nos variables x et y. Chaque ligne montre une permutation possible des valeurs de x et y. Comme x et y sont des valeurs booléennes, nous n'avons besoin que de 4 lignes pour couvrir toutes les combinaisons possibles.

Les autres colonnes représentent les expressions que nous voulons évaluer à partir des valeurs initiales de x et y. Les troisième et quatrième colonnes calculent respectivement les valeurs de !x et !y. La cinquième colonne calcule la valeur de !(x && y). Enfin, la sixième colonne calcule la valeur de !x || !y.

Vous remarquerez que, pour chaque ligne, la valeur de la cinquième colonne est identique à celle de la sixième. Cela signifie que, pour toutes les valeurs possibles de x et y, !(x && y) est égal à !x || !y, ce que nous voulions démontrer !

Nous pouvons faire de même pour la seconde partie des lois de De Morgan :

x y !x !y !(x || y) !x && !y
false false true true true true
false true true false false false
true false false true false false
true true false false false false

De même, pour toutes les valeurs possibles de x et y, la valeur de !(x || y) est égale à celle de !x && !y. Les deux expressions sont donc équivalentes.

Où est le OU exclusif logique (XOR) ?

Le XOR logique est un opérateur logique présent dans certains langages ; il sert à tester si un nombre impair de conditions est vrai :

XOR logique
Opérande de gauche Opérande de droite Résultat
false false false
false true true
true false true
true true false

C++ ne fournit pas d'opérateur XOR logique explicite (operator^ est un XOR binaire, et non un XOR logique). Contrairement au OU logique et au ET logique, le XOR logique ne peut pas être évalué en court-circuit. Il est donc difficile de construire un opérateur XOR logique à partir des opérateurs OU logique et ET logique.

Cependant, operator!= produit le même résultat qu'un XOR logique lorsqu'il reçoit des opérandes bool :

Opérande de gauche Opérande de droite XOR logique operator!=
false false false false
false true true true
true false true true
true true false false

On peut donc implémenter un XOR logique de la manière suivante :

if (a != b) ... // a XOR b, en supposant que a et b sont des bool

Cela se généralise à plusieurs opérandes :

if (a != b != c) ... // a XOR b XOR c, en supposant que a, b et c sont des bool

Cette expression vaut true si un nombre impair des opérandes (a, b et c) valent true.

Si les opérandes ne sont pas de type bool, utiliser operator!= pour implémenter un XOR logique ne fonctionnera pas comme prévu.

Pour les lecteurs avancés

Si vous avez besoin d'une forme de XOR logique qui fonctionne avec des opérandes non booléens, vous pouvez effectuer un static_cast de vos opérandes vers bool :

if (static_cast<bool>(a) != static_cast<bool>(b) != static_cast<bool>(c)) ... // a XOR b XOR c, pour tout type convertible en bool

Cette écriture est toutefois un peu verbeuse. L'astuce suivante fonctionne aussi et est un peu plus concise :

if (!!a != !!b != !!c) // a XOR b XOR c, pour tout type convertible en bool

Elle repose sur le fait que operator! (le NON logique) convertit implicitement son opérande en bool. Cependant, operator! inverse aussi le bool, de true à false ou inversement. Il faut donc appliquer operator! deux fois : la première fois pour effectuer la conversion implicite en bool et inverser le booléen, la seconde pour rétablir la valeur d'origine. Cette double inversion est nécessaire lorsque le XOR à plusieurs opérandes comporte un nombre impair d'opérandes ; sinon, le XOR produirait un résultat inversé.

Ces deux écritures ne sont pas très intuitives : documentez-les bien si vous les utilisez.

Représentations alternatives des opérateurs

De nombreux opérateurs C++ (comme l'opérateur ||) ont pour nom de simples symboles. Historiquement, tous les claviers et toutes les normes de langage ne prenaient pas en charge l'ensemble des symboles nécessaires pour saisir ces opérateurs. C++ propose donc un ensemble de mots-clés alternatifs pour les opérateurs qui utilisent des mots au lieu de symboles. Par exemple, au lieu de ||, vous pouvez utiliser le mot-clé or.

La liste complète se trouve ici. Trois d'entre eux sont particulièrement importants :

Nom de l'opérateur Mot-clé alternatif
&& and
|| or
! not

Cela signifie que les lignes suivantes sont identiques :

std::cout << !a && (b || c);
std::cout << not a and (b or c);

Bien que ces noms alternatifs puissent sembler plus faciles à comprendre pour le moment, la plupart des développeurs C++ expérimentés préfèrent utiliser les noms symboliques plutôt que les mots-clés. Nous vous recommandons donc d'apprendre et d'utiliser les noms symboliques, car c'est ce que vous trouverez le plus souvent dans le code existant.

(1 < 2 || 3 != 3) =>
(true || [3 != 3]) =>
(true) =>
true
signifie que nous avons évalué (1 < 2 || 3 != 3) pour obtenir (true || [3 != 3]), puis évalué celle-ci pour obtenir « true ». Le 3 != 3 n'a jamais été exécuté à cause du court-circuit.

Solution

(true && true) || false =>
true || [false] =>
true

b) (false && true) || true

Solution

(false && [true]) || true =>
false || true =>
true

Solution

(false && [true]) || false || true =>

true

Solution

Question n° 2

Dans la leçon 6.3 -- Reste et exponentiation, nous avons écrit une fonction permettant de déterminer si un nombre est pair, qui ressemble à ceci :

#include <iostream>

bool isEven(int x)
{
    // si x % 2 == 0, 2 divise exactement notre nombre, ce qui signifie qu'il est pair
    return (x % 2) == 0;
}

int main()
{
    std::cout << "Enter an integer: ";
    int x{};
    std::cin >> x;

    if (isEven(x))
        std::cout << x << " is even\n";
    else
        std::cout << x << " is odd\n";

    return 0;
}

Réécrivez cette fonction en utilisant operator! au lieu de operator==.

Solution 
#include <iostream>

bool isEven(int x)
{
    return !(x % 2);
}

int main()
{
    std::cout << "Enter an integer: ";
    int x{};
    std::cin >> x;

    if (isEven(x))
        std::cout << x << " is even\n";
    else
        std::cout << x << " is odd\n";

    return 0;
}
