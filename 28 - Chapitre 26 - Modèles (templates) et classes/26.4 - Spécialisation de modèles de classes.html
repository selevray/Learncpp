26.4 — Spécialisation de modèles de classes

Dans la leçon précédente 26.3 -- Spécialisation de modèles de fonctions, nous avons vu qu'il était possible de spécialiser des fonctions afin de fournir un comportement différent pour des types de données spécifiques. Il s'avère qu'il est possible de spécialiser non seulement des fonctions, mais aussi des classes !

Considérons le cas où vous voulez une classe qui stocke 8 objets. Voici un modèle de classe simplifié pour cela :

#include <iostream>

template <typename T>
class Storage8
{
private:
    T m_array[8];

public:
    void set(int index, const T& value)
    {
        m_array[index] = value;
    }

    const T& get(int index) const
    {
        return m_array[index];
    }
};

int main()
{
    // Définit un Storage8 pour les entiers
    Storage8<int> intStorage;

    for (int count{ 0 }; count < 8; ++count)
        intStorage.set(count, count);

    for (int count{ 0 }; count < 8; ++count)
        std::cout << intStorage.get(count) << '\n';

    // Définit un Storage8 pour les bool
    Storage8<bool> boolStorage;
    for (int count{ 0 }; count < 8; ++count)
        boolStorage.set(count, count & 3);

    std::cout << std::boolalpha;

    for (int count{ 0 }; count < 8; ++count)
    {
        std::cout << boolStorage.get(count) << '\n';
    }

    return 0;
}

Bien que cette classe soit entièrement fonctionnelle, il s'avère que l'implémentation de Storage8<bool> est plus inefficace qu'elle ne devrait l'être. Comme toutes les variables doivent avoir une adresse, et que le processeur ne peut pas adresser une unité plus petite qu'un octet, toutes les variables doivent occuper au moins un octet. En conséquence, une variable de type bool occupe un octet entier alors qu'elle n'a techniquement besoin que d'un seul bit pour stocker sa valeur vrai ou faux ! Un bool contient donc 1 bit d'information utile et 7 bits d'espace gaspillé. Notre classe Storage8<bool>, qui contient 8 bool, représente donc 1 octet d'information utile et 7 octets gaspillés.

Il s'avère qu'à l'aide d'une logique binaire élémentaire, il est possible de compresser les 8 booléens dans un seul octet, supprimant entièrement l'espace gaspillé. Cependant, pour y parvenir, il faut remanier la classe lorsqu'elle est utilisée avec le type bool, en remplaçant le tableau de 8 bool par une variable d'un seul octet. Bien que nous puissions créer une classe entièrement nouvelle pour cela, cela présente un inconvénient majeur : il faut lui donner un nom différent. Le programmeur doit alors se souvenir que Storage8<T> est destiné aux types autres que bool, tandis que Storage8Bool (ou quel que soit le nom choisi pour la nouvelle classe) est destiné à bool. C'est une complexité inutile que nous préférerions éviter. Heureusement, C++ nous offre une meilleure méthode : la spécialisation de modèles de classes (class template specialization).

Spécialisation de modèles de classes

La spécialisation de modèle de classe nous permet de spécialiser une classe template pour un type de données particulier (ou plusieurs types de données, s'il y a plusieurs paramètres template). Dans ce cas, nous allons utiliser la spécialisation de modèle de classe pour écrire une version personnalisée de Storage8<bool> qui prendra le pas sur la classe générique Storage8<T>.

Les spécialisations de modèles de classes sont traitées comme des classes entièrement indépendantes, même si elles sont instanciées de la même façon que la classe template. Cela signifie que nous pouvons modifier tout ce qui concerne notre classe spécialisée, y compris la façon dont elle est implémentée et même les fonctions qu'elle rend publiques, exactement comme s'il s'agissait d'une classe indépendante.

Comme pour tous les templates, le compilateur doit pouvoir voir la définition complète d'une spécialisation pour l'utiliser. De plus, la définition d'une spécialisation de modèle de classe exige que la classe non spécialisée soit définie au préalable.

Voici un exemple de classe Storage8<bool> spécialisée :

#include <cstdint>

// Définit d'abord notre modèle de classe non spécialisé
template <typename T>
class Storage8
{
private:
    T m_array[8];

public:
    void set(int index, const T& value)
    {
        m_array[index] = value;
    }

    const T& get(int index) const
    {
        return m_array[index];
    }
};

// Définit maintenant notre modèle de classe spécialisé
template <> // ce qui suit est une classe template sans paramètres template
class Storage8<bool> // nous spécialisons Storage8 pour bool
{
// Ce qui suit relève simplement des détails d'implémentation de la classe

private:
    std::uint8_t m_data{};

public:
    // Ne vous préoccupez pas des détails d'implémentation de ces fonctions
    void set(int index, bool value)
    {
        // Déterminer quel bit on définit ou on efface
        // Ceci met un 1 au bit qui nous intéresse, pour l'activer ou le désactiver
        auto mask{ 1 << index };

        if (value)  // Si l'on définit un bit
            m_data |= mask;   // utiliser le OU binaire pour activer ce bit
        else  // si l'on désactive un bit
            m_data &= ~mask;  // appliquer le ET binaire avec le masque inversé pour désactiver ce bit
    }

    bool get(int index)
    {
        // Déterminer quel bit on lit
        auto mask{ 1 << index };
        // ET binaire pour obtenir la valeur du bit qui nous intéresse
        // Puis conversion implicite en booléen
        return (m_data & mask);
    }
};

// Même exemple que précédemment
int main()
{
    // Définit un Storage8 pour les entiers (instancie Storage8<T>, avec T = int)
    Storage8<int> intStorage;

    for (int count{ 0 }; count < 8; ++count)
    {
        intStorage.set(count, count);
    }

    for (int count{ 0 }; count < 8; ++count)
    {
        std::cout << intStorage.get(count) << '\n';
    }

    // Définit un Storage8 pour les bool (instancie la spécialisation Storage8<bool>)
    Storage8<bool> boolStorage;

    for (int count{ 0 }; count < 8; ++count)
    {
        boolStorage.set(count, count & 3);
    }

    std::cout << std::boolalpha;

    for (int count{ 0 }; count < 8; ++count)
    {
        std::cout << boolStorage.get(count) << '\n';
    }

    return 0;
}

Remarquons d'abord que notre modèle de classe spécialisé commence par template<>. Le mot-clé template indique au compilateur que ce qui suit est un template, et les chevrons vides signifient qu'il n'y a aucun paramètre template. Ici, il n'y a aucun paramètre template parce que nous remplaçons le seul paramètre template (T) par un type précis (bool).

Ensuite, nous ajoutons <bool> au nom de la classe pour indiquer que nous spécialisons une version bool de class Storage8.

Toutes les autres modifications relèvent des détails d'implémentation de la classe. Vous n'avez pas besoin de comprendre le fonctionnement de la logique binaire pour utiliser la classe (vous pouvez toutefois consulter O.2 -- Opérateurs binaires si vous voulez le comprendre, mais avez besoin de revoir le fonctionnement des opérateurs binaires).

Notez que cette classe spécialisée utilise un std::uint8_t (un entier non signé d'un octet) au lieu d'un tableau de 8 bool (8 octets).

Désormais, lorsque nous instancions un objet de type Storage<T>, où T n'est pas un bool, nous obtenons une version générée à partir du modèle de classe générique Storage8<T>. Lorsque nous instancions un objet de type Storage8<bool>, nous obtenons la version spécialisée que nous venons de créer. Notez que nous avons conservé la même interface publique pour les deux classes : bien que C++ nous laisse toute liberté pour ajouter, supprimer ou modifier les fonctions de Storage8<bool>, conserver une interface cohérente permet au programmeur d'utiliser l'une ou l'autre classe exactement de la même manière.

Spécialisation de fonctions membres

Dans la leçon précédente, nous avons présenté cet exemple :

#include <iostream>

template <typename T>
class Storage
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

int main()
{
    // Définit quelques unités de stockage
    Storage i { 5 };
    Storage d { 6.7 };

    // Affiche quelques valeurs
    i.print();
    d.print();
}

Notre souhait est de spécialiser la fonction print() afin qu'elle affiche les nombres double en notation scientifique. En utilisant la spécialisation de modèle de classe, nous pourrions définir une classe spécialisée pour Storage<double> :

#include <iostream>

template <typename T>
class Storage
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

// Spécialisation explicite de modèle de classe pour Storage<double>
// Remarquez à quel point c'est redondant
template <>
class Storage<double>
{
private:
    double m_value {};
public:
    Storage(double value)
      : m_value { value }
    {
    }

    void print();
};

// Nous allons définir ceci en dehors de la classe pour des raisons qui deviendront évidentes plus loin
// Il s'agit d'une définition normale (non spécialisée) de la fonction membre print de la classe spécialisée Storage<double>
void Storage<double>::print()
{
    std::cout << std::scientific << m_value << '\n';
}

int main()
{
    // Définit quelques unités de stockage
    Storage i { 5 };
    Storage d { 6.7 }; // utilise la spécialisation explicite Storage<double>

    // Affiche quelques valeurs
    i.print(); // appelle Storage<int>::print (instanciée à partir de Storage<T>)
    d.print(); // appelle Storage<double>::print (appelée depuis la spécialisation explicite de Storage<double>)
}

Cependant, remarquez la quantité de redondance ici. Nous avons dupliqué une classe entière simplement pour modifier une seule fonction membre !

Heureusement, nous pouvons faire mieux. C++ ne nous oblige pas à spécialiser explicitement Storage<double> pour spécialiser explicitement Storage<double>::print(). Nous pouvons plutôt laisser le compilateur spécialiser implicitement Storage<double> à partir de Storage<T>, et fournir une spécialisation explicite de la seule fonction Storage<double>::print() ! Voici à quoi cela ressemble :

#include <iostream>

template <typename T>
class Storage
{
private:
    T m_value {};
public:
    Storage(T value)
      : m_value { value }
    {
    }

    void print()
    {
        std::cout << m_value << '\n';
    }
};

// Ceci est une définition de fonction membre spécialisée
// Les spécialisations explicites de fonctions ne sont pas implicitement inline ; il faut donc la déclarer inline si elle est placée dans un fichier d'en-tête
template<>
void Storage<double>::print()
{
    std::cout << std::scientific << m_value << '\n';
}

int main()
{
    // Définit quelques unités de stockage
    Storage i { 5 };
    Storage d { 6.7 }; // provoquera l'instanciation implicite de Storage<double>

    // Affiche quelques valeurs
    i.print(); // appelle Storage<int>::print (instanciée à partir de Storage<T>)
    d.print(); // appelle Storage<double>::print (appelée depuis la spécialisation explicite de Storage<double>::print())
}

C'est tout !

Comme indiqué dans la leçon précédente (26.3 -- Spécialisation de modèles de fonctions), les spécialisations explicites de fonctions ne sont pas implicitement inline. Nous devons donc marquer notre spécialisation de Storage<double>::print() comme inline si nous la définissons dans un fichier d'en-tête.

Où définir les spécialisations de modèles de classes

Pour utiliser une spécialisation, le compilateur doit pouvoir voir la définition complète à la fois de la classe non spécialisée et de la classe spécialisée. Si le compilateur ne peut voir que la définition de la classe non spécialisée, il utilisera celle-ci à la place de la spécialisation.

Pour cette raison, les classes et fonctions spécialisées sont souvent définies dans un fichier d'en-tête, juste sous la définition de la classe non spécialisée, de sorte qu'inclure un seul en-tête inclut à la fois la classe non spécialisée et toutes ses spécialisations. Cela garantit que la spécialisation est toujours visible lorsque la classe non spécialisée l'est aussi.

Si une spécialisation n'est nécessaire que dans une seule unité de traduction, elle peut être définie dans le fichier source de cette unité de traduction. Les autres unités de traduction ne pouvant pas voir la définition de la spécialisation, elles continueront d'utiliser la version non spécialisée.

Méfiez-vous de placer une spécialisation dans son propre fichier d'en-tête distinct, dans l'intention d'inclure cet en-tête dans chaque unité de traduction où la spécialisation est souhaitée. C'est une mauvaise idée que de concevoir du code dont le comportement change de façon transparente selon la présence ou l'absence d'un fichier d'en-tête. Par exemple, si vous comptez utiliser la spécialisation mais oubliez d'inclure son en-tête, vous risquez d'utiliser la version non spécialisée à la place. Si vous comptez utiliser la version non spécialisée, vous risquez tout de même d'utiliser la spécialisation si un autre en-tête l'inclut indirectement (inclusion transitive).
