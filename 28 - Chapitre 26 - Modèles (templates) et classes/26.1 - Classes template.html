26.1 — Classes template

Dans une leçon précédente, nous avons vu les fonctions template (11.6 -- Fonctions template), qui permettent de généraliser des fonctions pour qu'elles fonctionnent avec de nombreux types de données différents. C'est un excellent début sur la voie de la programmation générique, mais cela ne résout pas tous nos problèmes. Examinons un exemple de l'un de ces problèmes, et voyons ce que les templates peuvent encore faire pour nous.

Templates et classes conteneurs

Dans la leçon 23.6 -- Classes conteneurs, vous avez appris à utiliser la composition pour implémenter des classes qui contiennent plusieurs instances d'autres classes. Comme exemple de tel conteneur, nous avons examiné la classe IntArray. Voici une version simplifiée de cette classe :

#ifndef INTARRAY_H
#define INTARRAY_H

#include <cassert>

class IntArray
{
private:
    int m_length{};
    int* m_data{};

public:

    IntArray(int length)
    {
        assert(length > 0);
        m_data = new int[length]{};
        m_length = length;
    }

    // Nous ne voulons pas autoriser la création de copies de IntArray.
    IntArray(const IntArray&) = delete;
    IntArray& operator=(const IntArray&) = delete;

    ~IntArray()
    {
        delete[] m_data;
    }

    void erase()
    {
        delete[] m_data;
        // Nous devons nous assurer de mettre m_data à 0 ici, sinon il
        // resterait pointé vers de la mémoire désallouée !
        m_data = nullptr;
        m_length = 0;
    }

    int& operator[](int index)
    {
        assert(index >= 0 && index < m_length);
        return m_data[index];
    }

    int getLength() const { return m_length; }
};

#endif

Cette classe permet de créer facilement des tableaux d'entiers. Mais que faire si nous voulons créer un tableau de doubles ? Avec les méthodes de programmation traditionnelles, il faudrait créer une classe entièrement nouvelle ! Voici un exemple de DoubleArray, une classe de tableau destinée à contenir des doubles.

#ifndef DOUBLEARRAY_H
#define DOUBLEARRAY_H

#include <cassert>

class DoubleArray
{
private:
    int m_length{};
    double* m_data{};

public:

    DoubleArray(int length)
    {
        assert(length > 0);
        m_data = new double[length]{};
        m_length = length;
    }

    DoubleArray(const DoubleArray&) = delete;
    DoubleArray& operator=(const DoubleArray&) = delete;

    ~DoubleArray()
    {
        delete[] m_data;
    }

    void erase()
    {
        delete[] m_data;
        // Nous devons nous assurer de mettre m_data à 0 ici, sinon il
        // resterait pointé vers de la mémoire désallouée !
        m_data = nullptr;
        m_length = 0;
    }

    double& operator[](int index)
    {
        assert(index >= 0 && index < m_length);
        return m_data[index];
    }

    int getLength() const { return m_length; }
};

#endif

Bien que les listings de code soient longs, vous remarquerez que les deux classes sont presque identiques ! En fait, la seule différence substantielle est le type de données contenu (int ou double). Vous l'aurez sans doute deviné : c'est un autre domaine où les templates peuvent être très utiles, pour nous éviter de créer des classes liées à un type de données spécifique.

La création de classes template fonctionne à peu près de la même manière que celle de fonctions template, nous procéderons donc par l'exemple. Voici notre classe de tableau, en version template :

Array.h :

#ifndef ARRAY_H
#define ARRAY_H

#include <cassert>

template <typename T> // ajouté
class Array
{
private:
    int m_length{};
    T* m_data{}; // type modifié en T

public:

    Array(int length)
    {
        assert(length > 0);
        m_data = new T[length]{}; // allocation d'un tableau d'objets de type T
        m_length = length;
    }

    Array(const Array&) = delete;
    Array& operator=(const Array&) = delete;

    ~Array()
    {
        delete[] m_data;
    }

    void erase()
    {
        delete[] m_data;
        // Nous devons nous assurer de mettre m_data à 0 ici, sinon il
        // resterait pointé vers de la mémoire désallouée !
        m_data = nullptr;
        m_length = 0;
    }

    // operator[] template défini plus bas
    T& operator[](int index); // retourne maintenant un T&

    int getLength() const { return m_length; }
};

// Les fonctions membres définies en dehors de la classe ont besoin de leur propre déclaration template
template <typename T>
T& Array<T>::operator[](int index) // retourne maintenant un T&
{
    assert(index >= 0 && index < m_length);
    return m_data[index];
}

#endif

Comme vous pouvez le voir, cette version est presque identique à la version IntArray, à ceci près que nous avons ajouté la déclaration template et remplacé le type de données contenu, int, par T.

Notez que nous avons également défini la fonction operator[] en dehors de la déclaration de la classe. Ce n'est pas obligatoire, mais les nouveaux programmeurs trébuchent souvent lorsqu'ils essaient de le faire pour la première fois à cause de la syntaxe, ce qui rend un exemple instructif. Chaque fonction membre template définie en dehors de la déclaration de la classe a besoin de sa propre déclaration template. Notez aussi que le nom de la classe de tableau template est Array<T>, et non Array : Array désignerait une version non template de classe nommée Array, sauf si Array est utilisé à l'intérieur de la classe. Par exemple, le constructeur de copie et l'opérateur d'affectation par copie utilisent Array plutôt que Array<T>. Lorsque le nom de la classe est utilisé sans arguments template à l'intérieur de la classe, les arguments sont ceux de l'instanciation courante.

Voici un court exemple utilisant la classe de tableau template ci-dessus :

#include <iostream>
#include "Array.h"

int main()
{
    const int length { 12 };
    Array<int> intArray { length };
    Array<double> doubleArray { length };

    for (int count{ 0 }; count < length; ++count)
    {
        intArray[count] = count;
        doubleArray[count] = count + 0.5;
    }

    for (int count{ length - 1 }; count >= 0; --count)
        std::cout << intArray[count] << '\t' << doubleArray[count] << '\n';

    return 0;
}

Cet exemple affiche ce qui suit :


11     11.5
10     10.5
9       9.5
8       8.5
7       7.5
6       6.5
5       5.5
4       4.5
3       3.5
2       2.5
1       1.5
0       0.5

Les classes template sont instanciées de la même manière que les fonctions template : le compilateur découpe une copie à la demande, en remplaçant le paramètre template par le type de données réel dont l'utilisateur a besoin, puis compile cette copie. Si vous n'utilisez jamais une classe template, le compilateur ne la compilera même pas.

Les classes template sont idéales pour implémenter des classes conteneurs, car il est très souhaitable que les conteneurs fonctionnent avec une grande variété de types de données, et les templates vous permettent de le faire sans dupliquer le code. Même si la syntaxe est peu élégante et que les messages d'erreur peuvent être obscurs, les classes template sont vraiment l'une des fonctionnalités les plus utiles et les meilleures du C++.

Découper les classes template

Un template n'est ni une classe ni une fonction : c'est un patron (stencil) utilisé pour créer des classes ou des fonctions. À ce titre, il ne fonctionne pas tout à fait comme les fonctions ou les classes ordinaires. Dans la plupart des cas, cela ne pose pas de problème. Il existe cependant un domaine qui pose régulièrement des difficultés aux développeurs.

Avec les classes non template, la procédure courante consiste à placer la définition de la classe dans un fichier d'en-tête, et les définitions des fonctions membres dans un fichier de code portant un nom similaire. Ainsi, les définitions des fonctions membres sont compilées comme un fichier séparé du projet. En revanche, avec les templates, cela ne fonctionne pas. Considérons l'exemple suivant :

Array.h :

#ifndef ARRAY_H
#define ARRAY_H

#include <cassert>

template <typename T> // ajouté
class Array
{
private:
    int m_length{};
    T* m_data{}; // type modifié en T

public:

    Array(int length)
    {
        assert(length > 0);
        m_data = new T[length]{}; // allocation d'un tableau d'objets de type T
        m_length = length;
    }

    Array(const Array&) = delete;
    Array& operator=(const Array&) = delete;

    ~Array()
    {
        delete[] m_data;
    }

    void erase()
    {
        delete[] m_data;
        // Nous devons nous assurer de mettre m_data à 0 ici, sinon il
        // resterait pointé vers de la mémoire désallouée !
        m_data = nullptr;
        m_length = 0;
    }

    // operator[] template défini plus bas
    T& operator[](int index); // retourne maintenant un T&

    int getLength() const { return m_length; }
};

// La définition de Array<T>::operator[] a été déplacée dans Array.cpp ci-dessous

#endif

Array.cpp :

#include "Array.h"

// Les fonctions membres définies en dehors de la classe ont besoin de leur propre déclaration template
template <typename T>
T& Array<T>::operator[](int index) // retourne maintenant un T&
{
    assert(index >= 0 && index < m_length);
    return m_data[index];
}

main.cpp :

#include <iostream>
#include "Array.h"

int main()
{
    const int length { 12 };
    Array<int> intArray { length };
    Array<double> doubleArray { length };

    for (int count{ 0 }; count < length; ++count)
    {
        intArray[count] = count;
        doubleArray[count] = count + 0.5;
    }

    for (int count{ length - 1 }; count >= 0; --count)
        std::cout << intArray[count] << '\t' << doubleArray[count] << '\n';

    return 0;
}

Le programme ci-dessus se compile, mais provoque une erreur de l'éditeur de liens (linker) :


undefined reference to `Array<int>::operator[](int)'

Comme pour les fonctions template, le compilateur n'instancie une classe template que si elle est utilisée (par exemple comme type d'un objet comme intArray) dans une unité de traduction. Pour effectuer l'instanciation, le compilateur doit voir à la fois la définition complète de la classe template (et non seulement une déclaration) et le ou les types template spécifiques nécessaires.

Rappelez-vous également que le C++ compile les fichiers individuellement. Lorsque main.cpp est compilé, le contenu de l'en-tête Array.h (y compris la définition de la classe template) est copié dans main.cpp. Lorsque le compilateur constate que nous avons besoin de deux instances template, Array<int> et Array<double>, il les instancie et les compile dans le cadre de l'unité de traduction main.cpp. Comme la fonction membre operator[] possède une déclaration, le compilateur accepte un appel à celle-ci, en supposant qu'elle sera définie ailleurs.

Lorsque Array.cpp est compilé séparément, le contenu de l'en-tête Array.h est copié dans Array.cpp, mais le compilateur ne trouve dans Array.cpp aucun code nécessitant l'instanciation de la classe template Array ou de la fonction template Array<int>::operator[] : il n'instancie donc rien.

Ainsi, lors de l'édition des liens, nous obtenons une erreur de l'éditeur de liens, car main.cpp a appelé Array<int>::operator[], mais cette fonction template n'a jamais été instanciée !

Il existe plusieurs façons de contourner ce problème.

La solution la plus simple consiste à placer tout le code de la classe template dans le fichier d'en-tête (dans notre cas, placer le contenu de Array.cpp dans Array.h, sous la classe). Ainsi, lorsque vous incluez l'en-tête, tout le code template se trouve au même endroit. L'avantage de cette solution est sa simplicité. L'inconvénient est que si la classe template est utilisée dans de nombreux fichiers, vous obtiendrez de nombreuses instances locales de la classe template, ce qui peut allonger les temps de compilation et d'édition des liens (l'éditeur de liens devrait supprimer les définitions en double, donc il ne devrait pas alourdir l'exécutable). C'est notre solution privilégiée, tant que les temps de compilation ou d'édition des liens ne deviennent pas un problème.

Si vous estimez que placer le code de Array.cpp dans l'en-tête Array.h rend celui-ci trop long ou brouillon, une alternative consiste à déplacer le contenu de Array.cpp dans un nouveau fichier nommé Array.inl (.inl signifie inline), puis à inclure Array.inl au bas de l'en-tête Array.h (à l'intérieur de la garde d'en-tête). Cela produit le même résultat que de placer tout le code dans l'en-tête, mais aide à garder les choses un peu mieux organisées.

Astuce

Si vous utilisez la méthode .inl et obtenez ensuite une erreur de compilation concernant des définitions en double, votre compilateur compile très probablement le fichier .inl comme un fichier de code du projet. Le contenu du .inl est alors compilé deux fois : une fois lors de la compilation du .inl, et une fois lors de la compilation du fichier .cpp qui l'inclut. Si le fichier .inl contient des fonctions (ou des variables) non inline, nous enfreindrons la règle de définition unique (one definition rule). Dans ce cas, vous devrez exclure le fichier .inl de la compilation du projet.

Exclure le .inl de la compilation se fait généralement en effectuant un clic droit sur le fichier .inl dans la vue du projet, puis en choisissant Propriétés. Le réglage se trouve quelque part dans cette fenêtre. Dans Visual Studio, définissez « Exclure de la génération » (Exclude From Build) sur « Oui ». Dans Code::Blocks, décochez « Compile file » et « Link file ».

D'autres solutions consistent à inclure des fichiers .cpp avec #include, mais nous ne les recommandons pas, car cet usage de #include n'est pas standard.

Une autre alternative consiste à utiliser une approche en trois fichiers. La définition de la classe template va dans l'en-tête. Les fonctions membres de la classe template vont dans le fichier de code. Vous ajoutez ensuite un troisième fichier, qui contient toutes les classes instanciées dont vous avez besoin :

templates.cpp :

// S'assurer que la définition complète du template Array est visible
#include "Array.h"
#include "Array.cpp" // nous enfreignons les bonnes pratiques, mais uniquement à cet endroit

// Incluez ici les autres définitions de templates .h et .cpp dont vous avez besoin

template class Array<int>; // Instanciation explicite du template Array<int>
template class Array<double>; // Instanciation explicite du template Array<double>

// Instanciez ici les autres templates

La commande « template class » demande au compilateur d'instancier explicitement la classe template. Dans le cas ci-dessus, le compilateur génère les définitions de Array<int> et Array<double> dans templates.cpp. Les autres fichiers de code qui souhaitent utiliser ces types peuvent inclure Array.h (pour satisfaire le compilateur), et l'éditeur de liens reliera ces définitions de types explicites provenant de templates.cpp.

Cette méthode peut être plus efficace (selon la façon dont votre compilateur et votre éditeur de liens gèrent les templates et les définitions en double), mais elle impose de maintenir le fichier templates.cpp pour chaque programme.
