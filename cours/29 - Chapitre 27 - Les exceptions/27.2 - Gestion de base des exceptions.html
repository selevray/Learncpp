27.2 — Gestion de base des exceptions

Dans la leçon précédente sur la nécessité des exceptions, nous avons vu que l'utilisation de codes de retour mêle le flux de contrôle et le flux d'erreurs, ce qui contraint les deux. Les exceptions en C++ reposent sur trois mots-clés qui fonctionnent ensemble : throw, try et catch.

Lever des exceptions

Nous utilisons tout le temps des signaux dans la vie courante pour indiquer qu'un événement particulier s'est produit. Par exemple, pendant un match de football américain, lorsqu'un joueur a commis une faute, l'arbitre jette un drapeau sur le terrain et siffle l'arrêt du jeu. Une pénalité est alors signifiée puis appliquée. Une fois la pénalité traitée, le jeu reprend en général normalement.

En C++, une instruction throw (instruction de lancement) sert à signaler qu'une exception ou un cas d'erreur s'est produit (pensez au drapeau de pénalité jeté par l'arbitre). Signaler qu'une exception s'est produite s'appelle aussi lever une exception (raising en anglais).

Pour utiliser une instruction throw, il suffit d'écrire le mot-clé throw suivi d'une valeur de n'importe quel type de données que vous souhaitez utiliser pour signaler qu'une erreur s'est produite. En général, cette valeur sera un code d'erreur, une description du problème ou une classe d'exception personnalisée.

Voici quelques exemples :

throw -1; // lance une valeur entière littérale
throw ENUM_INVALID_INDEX; // lance une valeur d'énumération
throw "Can not take square root of negative number"; // lance une chaîne littérale de style C (const char*)
throw dX; // lance une variable double définie précédemment
throw MyException("Fatal Error"); // lance un objet de la classe MyException

Chacune de ces instructions agit comme un signal indiquant qu'un problème quelconque, qu'il faut traiter, s'est produit.

Surveiller les exceptions

Lever une exception ne constitue qu'une partie du processus de gestion des exceptions. Revenons à notre analogie avec le football américain : une fois que l'arbitre a jeté le drapeau de pénalité, que se passe-t-il ensuite ? Les joueurs remarquent qu'une pénalité a été sifflée et arrêtent le jeu. Le déroulement normal de la partie est interrompu.

En C++, on utilise le mot-clé try pour définir un bloc d'instructions (appelé bloc try). Le bloc try agit comme un observateur, à l'affût de toute exception lancée par l'une des instructions qu'il contient.

Voici un exemple de bloc try :

try
{
    // Les instructions susceptibles de lever des exceptions que vous voulez traiter vont ici
    throw -1; // voici une instruction throw triviale
}

Notez que le bloc try ne définit PAS comment l'exception va être traitée. Il indique simplement au programme : « Dis donc, si l'une des instructions à l'intérieur de ce bloc try lève une exception, attrape-la ! ».

Traiter les exceptions

Enfin, la fin de notre analogie avec le football américain : une fois la pénalité sifflée et le jeu arrêté, l'arbitre applique la pénalité. Autrement dit, la pénalité doit être traitée avant que le jeu normal puisse reprendre.

Le traitement effectif des exceptions revient aux blocs catch. Le mot-clé catch (attraper) sert à définir un bloc de code (appelé bloc catch) qui traite les exceptions d'un type de données donné.

Voici un exemple de bloc catch qui attrape les exceptions de type entier :

catch (int x)
{
    // Traite ici une exception de type int
    std::cerr << "We caught an int exception with value" << x << '\n';
}

Les blocs try et les blocs catch fonctionnent ensemble : un bloc try détecte les exceptions levées par les instructions qu'il contient et les achemine vers un bloc catch de type correspondant, qui les traite. Un bloc try doit être immédiatement suivi d'au moins un bloc catch, mais il peut en avoir plusieurs placés à la suite.

Une fois qu'une exception a été interceptée par le bloc try et acheminée vers un bloc catch correspondant pour être traitée, elle est considérée comme gérée. Après l'exécution du bloc catch correspondant, l'exécution reprend normalement, à partir de la première instruction qui suit le dernier bloc catch.

Les paramètres de catch fonctionnent exactement comme les paramètres de fonction : le paramètre est disponible dans le bloc catch qui le suit. Les exceptions de types fondamentaux peuvent être capturées par valeur, mais les exceptions de types non fondamentaux doivent être capturées par référence constante (const) afin d'éviter une copie inutile (et, dans certains cas, pour éviter le découpage, ou slicing).

Comme pour les fonctions, si le paramètre n'est pas utilisé dans le bloc catch, son nom peut être omis :

catch (double) // remarque : pas de nom de variable, car nous ne l'utilisons pas dans le bloc catch ci-dessous
{
    // Traite ici une exception de type double
    std::cerr << "We caught an exception of type double\n";
}

Cela permet d'éviter des avertissements du compilateur concernant des variables inutilisées.

Aucune conversion de type n'est effectuée pour les exceptions (ainsi, une exception de type int ne sera pas convertie pour correspondre à un bloc catch dont le paramètre est un double).

Assembler throw, try et catch

Voici un programme complet qui utilise throw, try et plusieurs blocs catch :

#include <iostream>
#include <string>

int main()
{
    try
    {
        // Les instructions susceptibles de lever des exceptions que vous voulez traiter vont ici
        throw -1; // voici un exemple trivial
    }
    catch (double) // pas de nom de variable, car nous n'utilisons pas l'exception elle-même dans le bloc catch ci-dessous
    {
        // Toute exception de type double levée dans le bloc try ci-dessus est envoyée ici
        std::cerr << "We caught an exception of type double\n";
    }
    catch (int x)
    {
        // Toute exception de type int levée dans le bloc try ci-dessus est envoyée ici
        std::cerr << "We caught an int exception with value: " << x << '\n';
    }
    catch (const std::string&) // on capture les classes par référence constante
    {
        // Toute exception de type std::string levée dans le bloc try ci-dessus est envoyée ici
        std::cerr << "We caught an exception of type std::string\n";
    }

    // L'exécution reprend ici, après que l'exception a été traitée par l'un des blocs catch ci-dessus
    std::cout << "Continuing on our merry way\n";

    return 0;
}

Sur la machine de l'auteur, l'exécution du bloc try/catch ci-dessus produit le résultat suivant :


We caught an int exception with value -1
Continuing on our merry way

Une instruction throw a été utilisée pour lever une exception de valeur -1, de type int. Cette exception a ensuite été interceptée par le bloc try englobant et acheminée vers le bloc catch approprié, qui traite les exceptions de type int. Ce bloc catch a affiché le message d'erreur correspondant.

Une fois l'exception traitée, le programme a repris normalement après les blocs catch, en affichant « Continuing on our merry way ».

Récapitulatif de la gestion des exceptions

La gestion des exceptions est en réalité assez simple, et les deux paragraphes suivants couvrent l'essentiel de ce qu'il faut retenir :

Lorsqu'une exception est levée (à l'aide de throw), le programme en cours d'exécution recherche le bloc try englobant le plus proche (en remontant la pile si nécessaire pour trouver un bloc try englobant, nous en reparlerons plus en détail dans la prochaine leçon) afin de vérifier si l'un des gestionnaires catch rattachés à ce bloc try peut traiter ce type d'exception. Si c'est le cas, l'exécution saute au début du bloc catch, et l'exception est considérée comme traitée.

Si aucun gestionnaire catch approprié n'existe dans le bloc try englobant le plus proche, le programme continue de chercher un gestionnaire catch dans les blocs try englobants suivants. Si aucun gestionnaire catch approprié ne peut être trouvé avant la fin du programme, celui-ci échouera avec une erreur d'exécution.

Notez que le programme n'effectue aucune conversion ou promotion implicite lorsqu'il fait correspondre les exceptions aux blocs catch ! Par exemple, une exception de type char ne correspondra pas à un bloc catch de type int. Une exception de type int ne correspondra pas à un bloc catch de type float. En revanche, les conversions d'une classe dérivée vers une de ses classes parentes sont effectuées.

C'est vraiment tout ce qu'il y a à savoir. Le reste de ce chapitre sera consacré à des exemples illustrant ces principes en action.

Les exceptions sont traitées immédiatement

Voici un court programme qui montre que les exceptions sont traitées immédiatement :

#include <iostream>

int main()
{
    try
    {
        throw 4.5; // lève une exception de type double
        std::cout << "This never prints\n";
    }
    catch (double x) // traite l'exception de type double
    {
        std::cerr << "We caught a double of value: " << x << '\n';
    }

    return 0;
}

Ce programme est à peu près le plus simple possible. Voici ce qui se passe : l'instruction throw est la première instruction exécutée, ce qui lève une exception de type double. L'exécution passe immédiatement au bloc try englobant le plus proche, qui est le seul bloc try de ce programme. Les gestionnaires catch sont alors examinés pour voir si l'un d'eux correspond. Notre exception est de type double, nous recherchons donc un gestionnaire catch de type double. Nous en avons un, il est donc exécuté.

Par conséquent, ce programme produit le résultat suivant :


We caught a double of value: 4.5

Notez que « This never prints » n'est jamais affiché, car l'exception a provoqué le saut immédiat du chemin d'exécution vers le gestionnaire d'exceptions de type double.

Un exemple plus réaliste

Examinons un exemple un peu moins théorique :

#include <cmath> // pour la fonction sqrt()
#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    double x {};
    std::cin >> x;

    try // Recherche les exceptions qui surviennent dans le bloc try et les achemine vers le ou les blocs catch rattachés
    {
        // Si l'utilisateur a saisi un nombre négatif, c'est une condition d'erreur
        if (x < 0.0)
            throw "Can not take sqrt of negative number"; // lève une exception de type const char*

        // Sinon, affiche le résultat
        std::cout << "The sqrt of " << x << " is " << std::sqrt(x) << '\n';
    }
    catch (const char* exception) // capture les exceptions de type const char*
    {
        std::cerr << "Error: " << exception << '\n';
    }
}

Dans ce code, on demande à l'utilisateur de saisir un nombre. S'il saisit un nombre positif, l'instruction if ne s'exécute pas, aucune exception n'est levée, et la racine carrée du nombre est affichée. Comme aucune exception n'est levée dans ce cas, le code du bloc catch ne s'exécute jamais. Le résultat ressemble à ceci :


Enter a number: 9
The sqrt of 9 is 3

Si l'utilisateur saisit un nombre négatif, nous levons une exception de type const char. Comme nous sommes dans un bloc try et qu'un gestionnaire d'exception correspondant est trouvé, le contrôle passe immédiatement au gestionnaire d'exception const char. Le résultat est :


Enter a number: -4
Error: Can not take sqrt of negative number

À ce stade, vous devriez avoir saisi l'idée de base des exceptions. Dans la prochaine leçon, nous verrons encore plusieurs exemples pour montrer à quel point les exceptions sont souples.

Ce que font habituellement les blocs catch

Si une exception est acheminée vers un bloc catch, elle est considérée comme « traitée », même si le bloc catch est vide. Cependant, vous voudrez généralement que vos blocs catch fassent quelque chose d'utile. Quand ils attrapent une exception, les blocs catch font généralement l'une de quatre choses :

Premièrement, un bloc catch peut afficher une erreur (dans la console ou dans un fichier journal), puis laisser la fonction poursuivre son exécution.

Deuxièmement, un bloc catch peut renvoyer une valeur ou un code d'erreur à l'appelant.

Troisièmement, un bloc catch peut lever une autre exception. Comme le bloc catch se situe en dehors du bloc try, l'exception nouvellement levée n'est pas traitée par le bloc try qui précède : elle est traitée par le bloc try englobant suivant.

Quatrièmement, un bloc catch dans main() peut servir à intercepter des erreurs fatales et à terminer le programme de manière propre.
