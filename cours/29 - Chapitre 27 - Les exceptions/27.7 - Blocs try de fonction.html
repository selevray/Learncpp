27.7 — Blocs try de fonction

Les blocs try et catch fonctionnent assez bien dans la plupart des cas, mais il existe un cas particulier pour lequel ils ne suffisent pas. Considérez l'exemple suivant :

#include <iostream>

class A
{
private:
    int m_x;
public:
    A(int x) : m_x{x}
    {
        if (x <= 0)
            throw 1; // Exception lancée ici
    }
};

class B : public A
{
public:
    B(int x) : A{x} // A initialisé dans la liste d'initialisation des membres de B
    {
        // Que se passe-t-il si la création de A échoue et que nous voulons la gérer ici ?
    }
};

int main()
{
    try
    {
        B b{0};
    }
    catch (int)
    {
        std::cout << "Oups\n";
    }
}

Dans l'exemple ci-dessus, la classe dérivée B appelle le constructeur de la classe de base A, qui peut lancer une exception. Comme la création de l'objet b a été placée dans un bloc try (dans la fonction main()), si A lance une exception, le bloc try de main la capturera. Par conséquent, ce programme affiche :


Oups

Mais que faire si nous voulons capturer l'exception à l'intérieur de B ? L'appel au constructeur de base A se produit via la liste d'initialisation des membres, avant que le corps du constructeur de B ne soit exécuté. Il n'existe aucun moyen d'entourer cet appel d'un bloc try standard.

Dans cette situation, nous devons utiliser un bloc try légèrement modifié, appelé bloc try de fonction (function try block).

Blocs try de fonction

Les blocs try de fonction permettent d'établir un gestionnaire d'exceptions autour du corps d'une fonction entière, plutôt qu'autour d'un bloc de code.

La syntaxe des blocs try de fonction est un peu difficile à décrire, nous allons donc la montrer par un exemple :

#include <iostream>

class A
{
private:
    int m_x;
public:
    A(int x) : m_x{x}
    {
        if (x <= 0)
            throw 1; // Exception lancée ici
    }
};

class B : public A
{
public:
    B(int x) try : A{x} // notez l'ajout du mot-clé try ici
    {
    }
    catch (...) // notez que ceci est au même niveau d'indentation que la fonction elle-même
    {
                // Les exceptions provenant de la liste d'initialisation des membres ou
                // du corps du constructeur sont capturées ici

                std::cerr << "Exception capturée\n";

                throw; // relance l'exception courante
    }
};

int main()
{
    try
    {
        B b{0};
    }
    catch (int)
    {
        std::cout << "Oups\n";
    }
}

Lorsque ce programme est exécuté, il produit la sortie suivante :


Exception capturée
Oups

Examinons ce programme plus en détail.

Tout d'abord, notez l'ajout du mot-clé try avant la liste d'initialisation des membres. Cela indique que tout ce qui suit ce point (jusqu'à la fin de la fonction) doit être considéré comme étant à l'intérieur du bloc try.

Ensuite, notez que le bloc catch associé est au même niveau d'indentation que la fonction entière. Toute exception lancée entre le mot-clé try et la fin du corps de la fonction pourra être capturée ici.

Lorsque le programme ci-dessus s'exécute, la variable b commence sa construction, ce qui appelle le constructeur de B (qui utilise un bloc try de fonction). Le constructeur de B appelle le constructeur de A, qui lance alors une exception. Comme le constructeur de A ne gère pas cette exception, celle-ci remonte la pile jusqu'au constructeur de B, où elle est capturée par le catch de niveau fonction de ce constructeur. Le bloc catch affiche « Exception capturée », puis relance l'exception courante vers le haut de la pile, où elle est capturée par le bloc catch de main(), qui affiche « Oups ».

Bonne pratique

Utilisez les blocs try de fonction lorsque vous avez besoin qu'un constructeur gère une exception lancée dans la liste d'initialisation des membres.

Limitations des blocs catch de fonction

Avec un bloc catch ordinaire (à l'intérieur d'une fonction), nous disposons de trois options : lancer une nouvelle exception, relancer l'exception courante, ou résoudre l'exception (en utilisant une instruction return, ou en laissant le contrôle atteindre la fin du bloc catch).

Un bloc catch de niveau fonction pour un constructeur doit soit lancer une nouvelle exception, soit relancer l'exception existante : il n'est pas permis de résoudre l'exception ! Les instructions return ne sont pas autorisées non plus, et atteindre la fin du bloc catch relance implicitement l'exception.

Un bloc catch de niveau fonction pour un destructeur peut lancer, relancer, ou résoudre l'exception courante via une instruction return. Atteindre la fin du bloc catch relance implicitement l'exception.

Un bloc catch de niveau fonction pour les autres fonctions peut lancer, relancer, ou résoudre l'exception courante via une instruction return. Atteindre la fin du bloc catch résout implicitement l'exception pour les fonctions ne renvoyant pas de valeur (void), et produit un comportement indéfini pour les fonctions renvoyant une valeur !

Le tableau suivant résume les limitations et le comportement des blocs catch de niveau fonction :

Type de fonction Peut résoudre l'exception via une instruction return Comportement en fin de bloc catch
Constructeur Non, doit lancer ou relancer Relance implicite
Destructeur Oui Relance implicite
Fonction ne renvoyant pas de valeur Oui Résolution de l'exception
Fonction renvoyant une valeur Oui Comportement indéfini

Comme ce comportement en fin de bloc catch varie fortement selon le type de fonction (et inclut un comportement indéfini dans le cas des fonctions renvoyant une valeur), nous recommandons de ne jamais laisser le contrôle atteindre la fin du bloc catch, et de toujours lancer, relancer ou retourner explicitement.

Bonne pratique

Évitez de laisser le contrôle atteindre la fin d'un bloc catch de niveau fonction. Lancez, relancez ou retournez plutôt explicitement.

Dans le programme ci-dessus, si nous n'avions pas relancé explicitement l'exception dans le bloc catch de niveau fonction du constructeur, le contrôle aurait atteint la fin de ce catch et, comme il s'agissait d'un constructeur, une relance implicite se serait produite à la place. Le résultat aurait été le même.

Bien que les blocs try de niveau fonction puissent aussi être utilisés avec des fonctions non membres, on ne le fait généralement pas, car il est rare que cela soit nécessaire. Ils sont presque exclusivement utilisés avec les constructeurs !

Les blocs try de fonction peuvent capturer les exceptions de la classe de base et de la classe courante

Dans l'exemple ci-dessus, si le constructeur de A ou celui de B lance une exception, elle sera capturée par le bloc try entourant le constructeur de B.

Nous pouvons le constater dans l'exemple suivant, où nous lançons une exception depuis la classe B au lieu de la classe A :

#include <iostream>

class A
{
private:
    int m_x;
public:
    A(int x) : m_x{x}
    {
    }
};

class B : public A
{
public:
    B(int x) try : A{x} // notez l'ajout du mot-clé try ici
    {
        if (x <= 0) // déplacé de A vers B
            throw 1; // et ceci aussi
    }
    catch (...)
    {
                std::cerr << "Exception capturée\n";

                // Si aucune exception n'est explicitement lancée ici,
                // l'exception courante sera relancée implicitement
    }
};

int main()
{
    try
    {
        B b{0};
    }
    catch (int)
    {
        std::cout << "Oups\n";
    }
}

On obtient la même sortie :


Exception capturée
Oups

Ne pas utiliser un bloc try de fonction pour libérer des ressources

Lorsque la construction d'un objet échoue, le destructeur de la classe n'est pas appelé. Vous pourriez donc être tenté d'utiliser un bloc try de fonction pour nettoyer une classe ayant partiellement alloué des ressources avant l'échec. Cependant, faire référence aux membres de l'objet ayant échoué constitue un comportement indéfini, puisque l'objet est « mort » avant l'exécution du bloc catch. Cela signifie que vous ne pouvez pas utiliser un bloc try de fonction pour nettoyer après une classe. Si vous souhaitez effectuer un nettoyage, suivez les règles standard de nettoyage des classes qui lancent des exceptions (voir la sous-section « Lorsque les constructeurs échouent » de la leçon 27.5 -- Exceptions, classes et héritage).

Les blocs try de fonction sont principalement utiles soit pour journaliser les échecs avant de transmettre l'exception vers le haut de la pile, soit pour changer le type de l'exception lancée.
