16.1 — Introduction aux conteneurs et aux tableaux

Le défi de la mise à l'échelle des variables

Considérons un scénario dans lequel nous voulons enregistrer les notes de 30 étudiants et calculer la moyenne de la classe. Pour cela, nous aurons besoin de 30 variables. Nous pourrions les définir ainsi :

// allouer 30 variables entières (chacune avec un nom différent)
int testScore1 {};
int testScore2 {};
int testScore3 {};
// ...
int testScore30 {};

C'est beaucoup de variables à définir ! Et pour calculer la moyenne de la classe, nous devrions faire quelque chose comme ceci :

int average { (testScore1 + testScore2 + testScore3 + testScore4 + testScore5
     + testScore6 + testScore7 + testScore8 + testScore9 + testScore10
     + testScore11 + testScore12 + testScore13 + testScore14 + testScore15
     + testScore16 + testScore17 + testScore18 + testScore19 + testScore20
     + testScore21 + testScore22 + testScore23 + testScore24 + testScore25
     + testScore26 + testScore27 + testScore28 + testScore29 + testScore30)
     / 30; };

Cela représente non seulement beaucoup de saisie, mais c'est aussi très répétitif (et il ne serait pas difficile de faire une faute de frappe sur l'un des numéros sans la remarquer). Et si nous voulons faire quelque chose avec chacune de ces valeurs (par exemple les afficher à l'écran), nous devrions saisir à nouveau chacun de ces noms de variables.

Supposons maintenant que nous devions modifier notre programme pour accueillir un nouvel étudiant qui vient d'être ajouté à la classe. Nous devrons parcourir l'intégralité du code source et ajouter manuellement testScore31 partout où c'est pertinent. Chaque fois que nous modifions du code existant, nous risquons d'introduire de nouveaux bogues. Par exemple, il ne serait pas difficile d'oublier de remplacer le diviseur du calcul de la moyenne, de 30 par 31 !

Et ce n'est que avec 30 variables. Imaginez le cas où nous avons des centaines ou des milliers d'objets. Lorsque nous avons besoin de plus de quelques objets du même type, définir des variables individuelles ne passe tout simplement pas à l'échelle.

Nous pourrions placer nos données dans une struct :

struct testScores
{
// allouer 30 variables entières (chacune avec un nom différent)
int score1 {};
int score2 {};
int score3 {};
// ...
int score30 {};
}

Bien que cela apporte une certaine organisation supplémentaire à nos notes (et permette de les passer plus facilement aux fonctions), cela ne résout pas le problème fondamental : nous devons toujours définir et accéder à chaque note individuellement.

Comme vous l'avez peut-être deviné, le C++ propose des solutions aux défis ci-dessus. Dans ce chapitre, nous présenterons l'une de ces solutions. Dans les chapitres suivants, nous explorerons d'autres variantes de cette solution.

Conteneurs

Lorsque vous allez au supermarché acheter une douzaine d'œufs, vous ne (probablement) sélectionnez pas 12 œufs un par un pour les mettre dans votre panier (ce n'est pas le cas, n'est-ce pas ?). Vous choisissez plutôt vraisemblablement une seule boîte d'œufs. La boîte est un type de conteneur, qui contient un nombre prédéfini d'œufs (probablement 6, 12 ou 24). Pensez maintenant aux céréales du petit-déjeuner, constituées de nombreux petits morceaux. Vous ne voudriez certainement pas ranger tous ces morceaux individuellement dans votre placard ! Les céréales sont souvent vendues dans une boîte, qui est un autre conteneur. Nous utilisons constamment des conteneurs dans la vie réelle, car ils facilitent la gestion d'une collection d'éléments.

Les conteneurs existent aussi en programmation, pour faciliter la création et la gestion de collections d'objets (potentiellement volumineuses). En programmation générale, un conteneur (container) est un type de données qui fournit un stockage pour une collection d'objets sans nom (appelés éléments).

Point clé

Nous utilisons généralement des conteneurs lorsque nous devons manipuler un ensemble de valeurs liées entre elles.

Il se trouve que vous avez déjà utilisé un type de conteneur : les chaînes de caractères ! Un conteneur de type chaîne fournit un stockage pour une collection de caractères, qui peuvent ensuite être affichés sous forme de texte :

#include <iostream>
#include <string>

int main()
{
    std::string name{ "Alex" }; // les chaînes sont un conteneur de caractères
    std::cout << name; // afficher notre chaîne sous forme de séquence de caractères

    return 0;
}

Les éléments d'un conteneur sont sans nom

Bien que l'objet conteneur lui-même ait généralement un nom (sinon, comment l'utiliserions-nous ?), les éléments d'un conteneur sont sans nom. Ainsi, nous pouvons mettre autant d'éléments que nous le souhaitons dans notre conteneur, sans avoir à donner à chaque élément un nom unique ! Cette absence de noms d'éléments est importante, et c'est ce qui distingue les conteneurs des autres types de structures de données. C'est pourquoi les structs simples (celles qui ne sont qu'une collection de membres de données, comme notre struct testScores ci-dessus) ne sont généralement pas considérées comme des conteneurs : leurs membres de données nécessitent des noms uniques.

Dans l'exemple ci-dessus, notre conteneur de type chaîne a un nom (name), mais les caractères contenus dans le conteneur ('A', 'l', 'e', 'x') n'en ont pas.

Mais si les éléments eux-mêmes sont sans nom, comment y accédons-nous ? Chaque conteneur fournit une ou plusieurs méthodes pour accéder à ses éléments, mais la manière exacte dépend du type de conteneur. Nous verrons un premier exemple dans la prochaine leçon.

Point clé

Les éléments d'un conteneur n'ont pas de noms propres, ce qui permet au conteneur de contenir autant d'éléments que nous le souhaitons sans avoir à donner un nom unique à chacun.

Chaque conteneur fournit une méthode pour accéder à ces éléments, mais la manière de le faire dépend du type spécifique de conteneur.

La longueur d'un conteneur

En programmation, le nombre d'éléments d'un conteneur est souvent appelé sa longueur (length) (ou parfois son nombre (count)).

Dans la leçon 5.7 -- Introduction à std::string, nous avons montré comment utiliser la fonction membre length de std::string pour obtenir le nombre d'éléments de type caractère du conteneur chaîne :

#include <iostream>
#include <string>

int main()
{
    std::string name{ "Alex" };
    std::cout << name << " has " << name.length() << " characters\n";

    return 0;
}

Ce programme affiche :

Alex has 4 characters

En C++, le terme taille (size) est également couramment utilisé pour désigner le nombre d'éléments d'un conteneur. C'est un choix de nomenclature malheureux, car le terme « taille » peut aussi désigner le nombre d'octets de mémoire utilisés par un objet (tel que renvoyé par l'opérateur sizeof).

Nous préférerons le terme « longueur » pour désigner le nombre d'éléments d'un conteneur, et utiliserons le terme « taille » pour désigner la quantité de stockage nécessaire à un objet.

Opérations sur les conteneurs

Revenons un instant à notre boîte d'œufs. Que peut-on faire avec une telle boîte ? Eh bien, tout d'abord, vous pouvez vous procurer une boîte d'œufs. Vous pouvez ouvrir la boîte, choisir un œuf, puis en faire ce que vous voulez. Vous pouvez retirer un œuf de la boîte ou en ajouter un dans un emplacement vide. Vous pouvez aussi compter le nombre d'œufs dans la boîte.

De même, les conteneurs implémentent généralement un sous-ensemble important des opérations suivantes :

  • Créer un conteneur (par exemple vide, avec un espace de stockage pour un nombre initial d'éléments, ou à partir d'une liste de valeurs).
  • Accéder aux éléments (par exemple obtenir le premier élément, le dernier élément, ou n'importe quel élément).
  • Insérer et retirer des éléments.
  • Obtenir le nombre d'éléments du conteneur.

Les conteneurs peuvent également proposer d'autres opérations (ou des variantes des opérations ci-dessus) qui facilitent la gestion de la collection d'éléments.

Les langages de programmation modernes proposent généralement plusieurs types de conteneurs différents. Ces types diffèrent par les opérations qu'ils prennent réellement en charge et par leurs performances. Par exemple, un type de conteneur peut offrir un accès rapide à n'importe quel élément, mais ne pas permettre l'insertion ou la suppression d'éléments. Un autre type peut offrir une insertion et une suppression rapides, mais n'autoriser l'accès aux éléments que dans l'ordre séquentiel.

Chaque conteneur a ses points forts et ses limites. Choisir le bon type de conteneur pour la tâche à résoudre peut avoir un impact considérable sur la maintenabilité du code et sur les performances globales. Nous reviendrons sur ce sujet dans une leçon ultérieure.

Types des éléments

Dans la plupart des langages de programmation (C++ compris), les conteneurs sont homogènes, c'est-à-dire que les éléments d'un conteneur doivent tous avoir le même type.

Certains conteneurs utilisent un type d'élément prédéfini (par exemple, une chaîne a généralement des éléments de type char), mais le plus souvent, le type d'élément peut être choisi par l'utilisateur du conteneur. En C++, les conteneurs sont généralement implémentés sous forme de modèles de classes (class templates), afin que l'utilisateur puisse fournir le type d'élément souhaité comme argument de type de modèle. Nous verrons un exemple dans la prochaine leçon.

Cela rend les conteneurs flexibles, car il n'est pas nécessaire de créer un nouveau type de conteneur pour chaque type d'élément différent. Il suffit d'instancier le modèle de classe avec le type d'élément souhaité, et c'est parti.

En passant…

Le contraire d'un conteneur homogène est un conteneur hétérogène, qui autorise des éléments de types différents. Les conteneurs hétérogènes sont généralement pris en charge par les langages de script (comme Python).

Les conteneurs en C++

La bibliothèque de conteneurs (Containers library) fait partie de la bibliothèque standard C++ et regroupe divers types de classes qui implémentent des types courants de conteneurs. Un type de classe qui implémente un conteneur est parfois appelé classe conteneur (container class). La liste complète des conteneurs de la bibliothèque de conteneurs est documentée ici.

En C++, la définition de « conteneur » est plus restrictive que la définition générale en programmation. Seuls les types de classes de la bibliothèque de conteneurs sont considérés comme des conteneurs en C++. Nous utiliserons le terme « conteneur » lorsque nous parlerons des conteneurs en général, et « classe conteneur » lorsque nous parlerons spécifiquement des types de classes conteneurs faisant partie de la bibliothèque de conteneurs.

Pour les lecteurs avancés

Les types suivants sont des conteneurs au sens général de la programmation, mais ne sont pas considérés comme des conteneurs par la norme C++ :

  • les tableaux de style C
  • std::string
  • std::vector<bool>

Pour être un conteneur en C++, un type doit satisfaire toutes les exigences listées ici. Notez que ces exigences incluent l'implémentation de certaines fonctions membres : cela implique que les conteneurs C++ doivent être des types de classes ! Les types listés ci-dessus n'implémentent pas toutes ces exigences.

Cependant, comme std::string et std::vector<bool> implémentent la plupart des exigences, ils se comportent comme des conteneurs dans la plupart des situations. Pour cette raison, on les appelle parfois des « pseudo-conteneurs ».

Parmi les classes conteneurs fournies, std::vector et std::array sont de loin les plus utilisées, et c'est sur elles que nous concentrerons l'essentiel de notre attention. Les autres classes conteneurs ne sont généralement utilisées que dans des situations plus spécialisées.

Introduction aux tableaux

Un tableau (array) est un type de données conteneur qui stocke une séquence de valeurs de manière contiguë (ce qui signifie que chaque élément est placé dans un emplacement mémoire adjacent, sans espace entre eux). Les tableaux permettent un accès direct et rapide à n'importe quel élément. Ils sont conceptuellement simples et faciles à utiliser, ce qui en fait le premier choix lorsque nous devons créer et manipuler un ensemble de valeurs liées entre elles.

Le C++ contient trois types de tableaux principaux : les tableaux (de style C), la classe conteneur std::vector et la classe conteneur std::array.

Les tableaux (de style C) ont été hérités du langage C. Pour des raisons de compatibilité ascendante, ces tableaux sont définis dans le cœur même du langage C++ (un peu comme les types fondamentaux). La norme C++ les appelle « tableaux », mais en C++ moderne on les désigne souvent par tableaux C ou tableaux de style C, afin de les distinguer du std::array au nom similaire. Les tableaux de style C sont aussi parfois appelés « tableaux nus » (naked arrays), « tableaux de taille fixe » (fixed-sized arrays), « tableaux fixes » (fixed arrays) ou « tableaux intégrés » (built-in arrays). Nous préférerons le terme « tableau de style C », et utiliserons « tableau » lorsque nous parlerons des types de tableaux en général. Selon les normes modernes, les tableaux de style C se comportent de manière étrange et sont dangereux. Nous expliquerons pourquoi dans un chapitre ultérieur.

Pour rendre les tableaux plus sûrs et plus faciles à utiliser en C++, la classe conteneur std::vector a été introduite avec C++03. std::vector est le plus souple des trois types de tableaux, et dispose de nombreuses fonctionnalités utiles que les autres types ne possèdent pas.

Enfin, la classe conteneur std::array a été introduite avec C++11 comme remplacement direct des tableaux de style C. Elle est plus limitée que std::vector, mais peut aussi être plus efficace, en particulier pour les petits tableaux.

Tous ces types de tableaux sont encore utilisés en C++ moderne, à des degrés divers, nous les étudierons donc tous les trois plus ou moins en détail.

Note de l'auteur

Une brève remarque sur la terminologie :

  • Nous utiliserons « classes conteneurs » lorsque nous parlerons de quelque chose qui s'applique à la plupart ou à l'ensemble des classes conteneurs de la bibliothèque standard.
  • Nous utiliserons « tableau » lorsque nous parlerons de quelque chose qui s'applique généralement à tous les types de tableaux, même ceux implémentés dans d'autres langages de programmation.

std::vector entre dans ces deux catégories : même si nous employons des termes différents, ce qui est dit reste applicable à std::vector.
