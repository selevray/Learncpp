16.9 — Indexation de tableaux et longueur à l'aide d'énumérateurs

L'un des gros problèmes de documentation des tableaux tient au fait que les indices entiers ne fournissent aucune information au programmeur sur la signification de l'indice.

Considérons un tableau contenant 5 notes de tests :

#include <vector>

int main()
{
    std::vector testScores { 78, 94, 66, 77, 14 };

    testScores[2] = 76; // qui cela représente-t-il ?
}

Quel est l'élève représenté par testScores[2] ? Ce n'est pas clair.

Utiliser des énumérateurs d'énumérations non délimitées pour l'indexation

Dans la leçon 16.3 -- std::vector et le problème de la longueur et de l'indice non signés, nous avons longuement discuté du fait que l'indice de std::vector<T>::operator[] (et des autres classes conteneurs C++ indexables) est de type size_type, qui est généralement un alias de std::size_t. Nos indices doivent donc être de type std::size_t, ou d'un type qui se convertit en std::size_t.

Comme les énumérations non délimitées se convertissent implicitement en std::size_t, nous pouvons utiliser des énumérations non délimitées comme indices de tableau pour documenter la signification de l'indice :

#include <vector>

namespace Students
{
    enum Names
    {
        kenny, // 0
        kyle, // 1
        stan, // 2
        butters, // 3
        cartman, // 4
        max_students // 5
    };
}

int main()
{
    std::vector testScores { 78, 94, 66, 77, 14 };

    testScores[Students::stan] = 76; // nous mettons maintenant à jour la note de stan

    return 0;
}

De cette façon, il est beaucoup plus clair de savoir ce que représente chaque élément du tableau.

Comme les énumérateurs sont implicitement constexpr, la conversion d'un énumérateur vers un type entier non signé n'est pas considérée comme une conversion restrictive (narrowing), ce qui évite les problèmes d'indexation liés au signe.

Utiliser une énumération non délimitée non constexpr pour l'indexation

Le type sous-jacent d'une énumération non délimitée est défini par l'implémentation (il peut donc s'agir d'un type entier signé ou non signé). Comme les énumérateurs sont implicitement constexpr, tant que nous nous en tenons à l'indexation avec des énumérateurs non délimités, nous ne rencontrerons pas de problème de conversion de signe.

En revanche, si nous définissons une variable non constexpr de type énumération, puis que nous tentons d'indexer notre std::vector avec elle, nous pouvons obtenir des avertissements de conversion de signe sur toute plateforme qui considère par défaut les énumérations non délimitées comme signées :

#include <vector>

namespace Students
{
    enum Names
    {
        kenny, // 0
        kyle, // 1
        stan, // 2
        butters, // 3
        cartman, // 4
        max_students // 5
    };
}

int main()
{
    std::vector testScores { 78, 94, 66, 77, 14 };
    Students::Names name { Students::stan }; // non constexpr

    testScores[name] = 76; // peut déclencher un avertissement de conversion de signe si Student::Names a un type sous-jacent signé par défaut

    return 0;
}

Dans ce cas particulier, nous pourrions rendre name constexpr (de sorte que la conversion depuis un type entier signé constexpr vers std::size_t soit non restrictive). Cependant, cela ne fonctionnera pas lorsque notre initialisation n'est pas une expression constante.

Une autre option consiste à spécifier explicitement que le type sous-jacent de l'énumération est un unsigned int :

#include <vector>

namespace Students
{
    enum Names : unsigned int // indique explicitement que le type sous-jacent est unsigned int
    {
        kenny, // 0
        kyle, // 1
        stan, // 2
        butters, // 3
        cartman, // 4
        max_students // 5
    };
}

int main()
{
    std::vector testScores { 78, 94, 66, 77, 14 };
    Students::Names name { Students::stan }; // non constexpr

    testScores[name] = 76; // pas de conversion de signe, car name est non signé

    return 0;
}

Dans l'exemple ci-dessus, comme name est désormais garanti d'être un unsigned int, il peut être converti en std::size_t sans problème de conversion de signe.

Utiliser un énumérateur de comptage

Notez que nous avons défini un énumérateur supplémentaire à la fin de la liste, nommé max_students. Si tous les énumérateurs précédents utilisent les valeurs par défaut (ce qui est recommandé), cet énumérateur aura une valeur par défaut égale au nombre d'énumérateurs qui le précèdent. Dans l'exemple ci-dessus, max_students vaut 5, car 5 énumérateurs sont définis avant lui. De manière informelle, nous appellerons cela un énumérateur de comptage, puisque sa valeur représente le nombre d'énumérateurs définis précédemment.

Cet énumérateur de comptage peut ensuite être utilisé partout où nous avons besoin du nombre d'énumérateurs précédents. Par exemple :

#include <iostream>
#include <vector>

namespace Students
{
    enum Names
    {
        kenny, // 0
        kyle, // 1
        stan, // 2
        butters, // 3
        cartman, // 4
        // ajoutez les futurs énumérateurs ici
        max_students // 5
    };
}

int main()
{
    std::vector<int> testScores(Students::max_students); // Crée un vector de 5 éléments

    testScores[Students::stan] = 76; // nous mettons maintenant à jour la note de stan

    std::cout << "The class has " << Students::max_students << " students\n";

    return 0;
}

Nous utilisons max_students à deux endroits : d'abord, nous créons un std::vector de longueur max_students, de sorte que le vector ait un élément par élève. Nous utilisons aussi max_students pour afficher le nombre d'élèves.

Cette technique est également pratique : si un autre énumérateur est ajouté plus tard (juste avant max_students), alors max_students augmentera automatiquement d'une unité, et tous nos tableaux utilisant max_students seront mis à jour avec la nouvelle longueur, sans autre modification.

#include <vector>
#include <iostream>

namespace Students
{
    enum Names
    {
        kenny, // 0
        kyle, // 1
        stan, // 2
        butters, // 3
        cartman, // 4
        wendy, // 5 (ajouté)
        // ajoutez les futurs énumérateurs ici
        max_students // maintenant 6
    };
}

int main()
{
    std::vector<int> testScores(Students::max_students); // allouera maintenant 6 éléments

    testScores[Students::stan] = 76; // fonctionne toujours

    std::cout << "The class has " << Students::max_students << " students\n";

    return 0;
}

Vérifier la longueur d'un tableau avec un énumérateur de comptage

Le plus souvent, nous créons un tableau à l'aide d'une liste d'initialisation de valeurs, dans l'intention d'indexer ce tableau avec des énumérateurs. Dans ce cas, il peut être utile d'affirmer (assert) que la taille du conteneur est égale à notre énumérateur de comptage. Si cette assertion échoue, soit notre liste d'énumérateurs est incorrecte, soit nous avons fourni un nombre incorrect d'initialisateurs. Cela arrive facilement lorsqu'un nouvel énumérateur est ajouté à l'énumération, sans qu'une nouvelle valeur d'initialisation soit ajoutée au tableau.

Par exemple :

#include <cassert>
#include <iostream>
#include <vector>

enum StudentNames
{
    kenny, // 0
    kyle, // 1
    stan, // 2
    butters, // 3
    cartman, // 4
    max_students // 5
};

int main()
{
    std::vector testScores { 78, 94, 66, 77, 14 };

    // Vérifie que le nombre de notes est identique au nombre d'élèves
    assert(std::size(testScores) == max_students);

    return 0;
}

Astuce

Si votre tableau est constexpr, utilisez plutôt static_assert. std::vector ne prend pas en charge constexpr, mais std::array (et les tableaux de style C) le font.

Nous reviendrons sur ce point dans la leçon 17.3 -- Passer et retourner des std::array.

Bonne pratique

Utilisez un static_assert pour vous assurer que la longueur de votre tableau constexpr correspond à votre énumérateur de comptage.
Utilisez un assert pour vous assurer que la longueur de votre tableau non constexpr correspond à votre énumérateur de comptage.

Tableaux et enum class

Comme les énumérations non délimitées polluent avec leurs énumérateurs l'espace de noms dans lequel elles sont définies, il est préférable d'utiliser des enum class lorsque l'énumération n'est pas déjà contenue dans une autre zone de portée (par exemple un espace de noms ou une classe).

Cependant, comme les enum class n'ont pas de conversion implicite vers les types entiers, nous rencontrons un problème lorsque nous essayons d'utiliser leurs énumérateurs comme indices de tableau :

#include <iostream>
#include <vector>

enum class StudentNames // désormais une enum class
{
    kenny, // 0
    kyle, // 1
    stan, // 2
    butters, // 3
    cartman, // 4
    max_students // 5
};

int main()
{
    // erreur de compilation : pas de conversion de StudentNames vers std::size_t
    std::vector<int> testScores(StudentNames::max_students);

    // erreur de compilation : pas de conversion de StudentNames vers std::size_t
    testScores[StudentNames::stan] = 76;

    // erreur de compilation : pas de conversion de StudentNames vers un type que operator<< peut afficher
    std::cout << "The class has " << StudentNames::max_students << " students\n";

    return 0;
}

Il existe plusieurs façons de résoudre ce problème. La plus évidente consiste à effectuer un static_cast de l'énumérateur vers un entier :

#include <iostream>
#include <vector>

enum class StudentNames
{
    kenny, // 0
    kyle, // 1
    stan, // 2
    butters, // 3
    cartman, // 4
    max_students // 5
};

int main()
{
    std::vector<int> testScores(static_cast<int>(StudentNames::max_students));

    testScores[static_cast<int>(StudentNames::stan)] = 76;

    std::cout << "The class has " << static_cast<int>(StudentNames::max_students) << " students\n";

    return 0;
}

Cependant, c'est non seulement fastidieux à écrire, mais cela alourdit aussi considérablement notre code.

Une meilleure option consiste à utiliser la fonction auxiliaire présentée dans la leçon 13.6 -- Énumérations délimitées (enum class), qui permet de convertir les énumérateurs des enum class en valeurs entières à l'aide de l'opérateur unaire operator+.

#include <iostream>
#include <type_traits> // pour std::underlying_type_t
#include <vector>

enum class StudentNames
{
    kenny, // 0
    kyle, // 1
    stan, // 2
    butters, // 3
    cartman, // 4
    max_students // 5
};

// Surcharge de l'opérateur unaire + pour convertir StudentNames vers le type sous-jacent
constexpr auto operator+(StudentNames a) noexcept
{
    return static_cast<std::underlying_type_t<StudentNames>>(a);
}

int main()
{
    std::vector<int> testScores(+StudentNames::max_students);

    testScores[+StudentNames::stan] = 76;

    std::cout << "The class has " << +StudentNames::max_students << " students\n";

    return 0;
}

Toutefois, si vous devez effectuer beaucoup de conversions d'énumérateurs en entiers, il est probablement préférable d'utiliser une énumération standard dans un espace de noms (ou une classe).

Quiz

Question n° 1

Créez une énumération définie par le programme (dans un espace de noms) contenant les noms des animaux suivants : chicken, dog, cat, elephant, duck et snake. Définissez un tableau ayant un élément pour chacun de ces animaux, et utilisez une liste d'initialisation pour initialiser chaque élément avec le nombre de pattes de cet animal. Vérifiez par une assertion que le tableau possède le bon nombre d'initialisateurs.

Écrivez une fonction main() qui affiche, à l'aide de l'énumérateur, le nombre de pattes d'un éléphant.

Solution 
#include <cassert>
#include <iostream>
#include <vector>

namespace Animals
{
    enum Animals
    {
        chicken,
        dog,
        cat,
        elephant,
        duck,
        snake,
        max_animals
    };

    const std::vector legs{ 2, 4, 4, 4, 2, 0 };
}

int main()
{
    // Vérifie que le nombre de pattes correspond au nombre d'animaux
    assert(std::size(Animals::legs) == Animals::max_animals);

    std::cout << "An elephant has " << Animals::legs[Animals::elephant] << " legs.\n";

    return 0;
}
