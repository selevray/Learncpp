16.4 — Passer un std::vector en paramètre

Un objet de type std::vector peut être passé à une fonction comme n'importe quel autre objet. Cela signifie que si nous passons un std::vector par valeur, une copie coûteuse est effectuée. Nous passons donc généralement les std::vector par référence (constante) afin d'éviter ces copies.

Avec un std::vector, le type des éléments fait partie des informations de type de l'objet. Par conséquent, lorsque nous utilisons un std::vector comme paramètre de fonction, nous devons préciser explicitement le type des éléments :

#include <iostream>
#include <vector>

void passByRef(const std::vector<int>& arr) // nous devons préciser explicitement <int> ici
{
    std::cout << arr[0] << '\n';
}

int main()
{
    std::vector primes{ 2, 3, 5, 7, 11 };
    passByRef(primes);

    return 0;
}

Passer des std::vector dont les éléments sont de types différents

Comme notre fonction passByRef() attend un std::vector<int>, nous ne pouvons pas lui passer des vecteurs dont les éléments sont d'un autre type :

#include <iostream>
#include <vector>

void passByRef(const std::vector<int>& arr)
{
    std::cout << arr[0] << '\n';
}

int main()
{
    std::vector primes{ 2, 3, 5, 7, 11 };
    passByRef(primes);  // ok : il s'agit d'un std::vector<int>

    std::vector dbl{ 1.1, 2.2, 3.3 };
    passByRef(dbl); // erreur de compilation : std::vector<double> n'est pas convertible en std::vector<int>

    return 0;
}

En C++17 ou plus récent, on pourrait essayer d'utiliser la déduction d'arguments de modèle de classe (CTAD) pour résoudre ce problème :

#include <iostream>
#include <vector>

void passByRef(const std::vector& arr) // erreur de compilation : le CTAD ne peut pas être utilisé pour déduire les paramètres de fonction
{
    std::cout << arr[0] << '\n';
}

int main()
{
    std::vector primes{ 2, 3, 5, 7, 11 }; // ok : utilisation du CTAD pour déduire std::vector<int>
    passByRef(primes);

    return 0;
}

Bien que le CTAD permette de déduire le type des éléments d'un vecteur à partir de ses initialiseurs lors de sa définition, le CTAD ne fonctionne pas (pour l'instant) avec les paramètres de fonction.

Nous avons déjà rencontré ce type de problème, où des fonctions surchargées ne diffèrent que par le type de leurs paramètres. C'est une excellente occasion d'utiliser les modèles de fonctions ! Nous pouvons créer un modèle de fonction paramétrant le type des éléments, puis le C++ utilisera ce modèle pour instancier des fonctions avec des types concrets.

Contenu connexe

Nous traitons des modèles de fonctions dans la leçon 11.6 -- Modèles de fonctions.

Nous pouvons créer un modèle de fonction utilisant la même déclaration de paramètre de modèle :

#include <iostream>
#include <vector>

template <typename T>
void passByRef(const std::vector<T>& arr)
{
    std::cout << arr[0] << '\n';
}

int main()
{
    std::vector primes{ 2, 3, 5, 7, 11 };
    passByRef(primes); // ok : le compilateur va instancier passByRef(const std::vector<int>&)

    std::vector dbl{ 1.1, 2.2, 3.3 };
    passByRef(dbl);    // ok : le compilateur va instancier passByRef(const std::vector<double>&)

    return 0;
}

Dans l'exemple ci-dessus, nous avons créé un unique modèle de fonction nommé passByRef() qui possède un paramètre de type const std::vector<T>&. T est défini dans la déclaration de paramètre de modèle de la ligne précédente : template <typename T. T est un paramètre de modèle de type standard qui permet à l'appelant de préciser le type des éléments.

Ainsi, lorsque nous appelons passByRef(primes) depuis main() (où primes est défini comme un std::vector<int>), le compilateur instancie et appelle void passByRef(const std::vector<int>& arr).

Lorsque nous appelons passByRef(dbl) depuis main() (où dbl est défini comme un std::vector<double>), le compilateur instancie et appelle void passByRef(const std::vector<double>& arr).

Nous avons donc créé un unique modèle de fonction capable d'instancier des fonctions traitant des arguments std::vector de n'importe quel type d'éléments et de n'importe quelle longueur !

Passer un std::vector à l'aide d'un modèle générique ou d'un modèle de fonction abrégé

Nous pouvons également créer un modèle de fonction qui accepte n'importe quel type d'objet :

#include <iostream>
#include <vector>

template <typename T>
void passByRef(const T& arr) // acceptera tout objet disposant d'un operator[] surchargé
{
    std::cout << arr[0] << '\n';
}

int main()
{
    std::vector primes{ 2, 3, 5, 7, 11 };
    passByRef(primes); // ok : le compilateur va instancier passByRef(const std::vector<int>&)

    std::vector dbl{ 1.1, 2.2, 3.3 };
    passByRef(dbl);    // ok : le compilateur va instancier passByRef(const std::vector<double>&)

    return 0;
}

En C++20, nous pouvons utiliser un modèle de fonction abrégé (via un paramètre auto) pour faire la même chose :

#include <iostream>
#include <vector>

void passByRef(const auto& arr) // modèle de fonction abrégé
{
    std::cout << arr[0] << '\n';
}

int main()
{
    std::vector primes{ 2, 3, 5, 7, 11 };
    passByRef(primes); // ok : le compilateur va instancier passByRef(const std::vector<int>&)

    std::vector dbl{ 1.1, 2.2, 3.3 };
    passByRef(dbl);    // ok : le compilateur va instancier passByRef(const std::vector<double>&)

    return 0;
}

Ces deux versions acceptent un argument de n'importe quel type qui compile. Cela peut être souhaitable lorsque nous écrivons des fonctions que nous pourrions vouloir utiliser sur autre chose qu'un std::vector. Par exemple, les fonctions ci-dessus fonctionneront également avec un std::array, un std::string, ou tout autre type auquel nous n'aurions peut-être même pas pensé.

L'inconvénient potentiel de cette méthode est qu'elle peut entraîner des bogues si la fonction reçoit un objet d'un type qui compile mais qui n'a pas de sens sémantiquement.

Vérifier la longueur d'un tableau avec une assertion

Considérons le modèle de fonction suivant, proche de celui présenté ci-dessus :

#include <iostream>
#include <vector>

template <typename T>
void printElement3(const std::vector<T>& arr)
{
    std::cout << arr[3] << '\n';
}

int main()
{
    std::vector arr{ 9, 7, 5, 3, 1 };
    printElement3(arr);

    return 0;
}

Bien que printElement3(arr) fonctionne correctement dans ce cas, ce programme recèle un bogue potentiel qui attend un programmeur peu attentif. Le voyez-vous ?

Le programme ci-dessus affiche la valeur de l'élément du tableau d'indice 3. Cela ne pose pas de problème tant que le tableau possède un élément valide d'indice 3. Cependant, le compilateur acceptera sans broncher des tableaux pour lesquels l'indice 3 est hors limites. Par exemple :

#include <iostream>
#include <vector>

template <typename T>
void printElement3(const std::vector<T>& arr)
{
    std::cout << arr[3] << '\n';
}

int main()
{
    std::vector arr{ 9, 7 }; // un tableau de 2 éléments (indices valides 0 et 1)
    printElement3(arr);

    return 0;
}

Ce code entraîne un comportement indéfini.

Une solution consiste à vérifier arr.size() à l'aide d'une assertion, ce qui détectera ces erreurs lors d'une exécution en configuration de débogage. Comme std::vector::size() n'est pas une fonction constexpr, nous ne pouvons faire qu'une assertion à l'exécution ici.

Astuce

Une meilleure solution consiste à éviter std::vector dans les cas où vous devez vérifier la longueur d'un tableau par une assertion. Utiliser un type qui prend en charge les tableaux constexpr (par exemple std::array) est probablement un meilleur choix, car vous pouvez utiliser static_assert sur la longueur d'un tableau constexpr. Nous aborderons ce point dans une prochaine leçon : 17.3 -- Passer et renvoyer un std::array.

La meilleure solution consiste à éviter, dès le départ, d'écrire des fonctions qui reposent sur le fait que l'utilisateur passe un vecteur d'une longueur minimale.

Temps du quiz

Question n° 1

Écrivez une fonction qui prend deux paramètres : un std::vector et un indice. Si l'indice est hors limites, affichez une erreur. Si l'indice est valide, affichez la valeur de l'élément.

Le programme d'exemple suivant doit compiler :

#include <iostream>
#include <vector>

// Écrivez votre fonction printElement ici

int main()
{
    std::vector v1 { 0, 1, 2, 3, 4 };
    printElement(v1, 2);
    printElement(v1, 5);

    std::vector v2 { 1.1, 2.2, 3.3 };
    printElement(v2, 0);
    printElement(v2, -1);

    return 0;
}

et produire le résultat suivant :


The element has value 2
Invalid index
The element has value 1.1
Invalid index
Solution 
#include <iostream>
#include <vector>

// index doit être un int et non un std::size_t, sinon nous ne pourrions pas détecter un indice négatif passé par l'utilisateur
template <typename T>
void printElement(const std::vector<T>& arr, int index)
{
    if (index < 0 || index >= static_cast<int>(arr.size())) // En C++20, on pourrait utiliser std::ssize(arr) pour éviter le cast
        std::cout << "Invalid index\n";
    else
        std::cout << "The element has value " << arr[static_cast<std::size_t>(index)] << '\n';  
}

int main()
{
    std::vector v1 { 0, 1, 2, 3, 4 };
    printElement(v1, 2);
    printElement(v1, 5);

    std::vector v2 { 1.1, 2.2, 3.3 };
    printElement(v2, 0);
    printElement(v2, -1);

    return 0;
}
