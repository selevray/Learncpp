16.3 — std::vector et le problème de la longueur non signée et des indices

Dans la leçon précédente 16.2 -- Introduction à std::vector et aux constructeurs à liste, nous avons présenté operator[], qui permet d'indexer un tableau pour accéder à un élément.

Dans cette leçon, nous verrons d'autres façons d'accéder aux éléments d'un tableau, ainsi que plusieurs manières d'obtenir la longueur d'une classe conteneur (le nombre d'éléments qu'elle contient à un instant donné).

Mais avant cela, nous devons évoquer une erreur majeure commise par les concepteurs du C++, et son impact sur toutes les classes conteneurs de la bibliothèque standard.

Le problème du signe de la longueur des conteneurs

Commençons par une affirmation : le type de données utilisé pour indexer un tableau doit correspondre au type de données utilisé pour stocker sa longueur. Ainsi, tous les éléments du plus grand tableau possible peuvent être indexés, et pas davantage.

Comme Bjarne Stroustrup le rappelle, lors de la conception des classes conteneurs de la bibliothèque standard (vers 1997), les concepteurs ont dû choisir entre une longueur (et des indices de tableau) signés ou non signés. Ils ont choisi non signés.

Les raisons invoquées étaient les suivantes : les indices des tableaux de la bibliothèque standard ne peuvent pas être négatifs ; un type non signé permet des tableaux plus longs grâce au bit supplémentaire (un point important à l'époque des systèmes 16 bits) ; et la vérification de la validité d'un indice ne nécessite qu'une seule condition au lieu de deux (puisqu'il n'y a pas besoin de vérifier que l'indice est supérieur ou égal à 0).

Avec le recul, ce choix est généralement considéré comme une erreur. On sait aujourd'hui que l'utilisation de valeurs non signées pour garantir la non-négativité ne fonctionne pas, à cause des règles de conversion implicite (un entier signé négatif se convertit implicitement en un grand entier non signé, ce qui produit un résultat aberrant). Le bit supplémentaire n'est en général pas nécessaire sur les systèmes 32 ou 64 bits (vous ne créerez probablement pas de tableaux de plus de 2 milliards d'éléments). Et l'opérateur operator[], couramment utilisé, n'effectue de toute façon aucune vérification de bornes.

Dans la leçon 4.5 -- Les entiers non signés, et pourquoi il faut les éviter, nous avons expliqué pourquoi nous préférons utiliser des valeurs signées pour représenter des quantités. Nous avons également souligné que mélanger des valeurs signées et non signées conduit à des comportements inattendus. Le fait que les classes conteneurs de la bibliothèque standard utilisent des valeurs non signées pour la longueur (et les indices) pose donc problème, car il devient impossible d'éviter les valeurs non signées lorsqu'on utilise ces types.

Pour l'instant, nous sommes contraints de vivre avec ce choix et la complexité inutile qu'il entraîne.

Rappel : les conversions de signe sont des conversions restrictives, sauf si elles portent sur une constexpr

Avant d'aller plus loin, rappelons brièvement certains points de la leçon 10.4 -- Conversions restrictives, initialisation par liste et initialisateurs constexpr concernant les conversions de signe (conversions entières d'un type signé vers un type non signé, ou inversement), car nous les rencontrerons beaucoup dans ce chapitre.

Les conversions de signe sont considérées comme des conversions restrictives, car un type signé ou non signé ne peut pas représenter toutes les valeurs de l'intervalle du type opposé. Lorsqu'une telle conversion est effectuée à l'exécution, le compilateur émet une erreur dans les contextes où les conversions restrictives sont interdites (comme l'initialisation par liste), et peut ou non émettre un avertissement dans les autres contextes où cette conversion a lieu.

Par exemple :

#include <iostream>

void foo(unsigned int)
{
}

int main()
{
    int s { 5 };

    [[maybe_unused]] unsigned int u { s }; // erreur de compilation : l'initialisation par liste interdit la conversion restrictive
    foo(s);                                // avertissement possible : l'initialisation par copie autorise la conversion restrictive

    return 0;
}

Dans l'exemple ci-dessus, l'initialisation de la variable u produit une erreur de compilation, car les conversions restrictives sont interdites lors d'une initialisation par liste. L'appel à foo() effectue une initialisation par copie, qui autorise les conversions restrictives, et peut produire ou non un avertissement selon le degré de sévérité du compilateur concernant les avertissements de conversion de signe. Par exemple, GCC et Clang produiront tous deux un avertissement dans ce cas si l'option de compilation -Wsign-conversion est utilisée.

En revanche, si la valeur à convertir est une constexpr et peut être convertie en une valeur équivalente dans le type opposé, la conversion de signe n'est pas considérée comme restrictive. En effet, le compilateur peut garantir que la conversion est sûre, ou interrompre la compilation.

#include <iostream>

void foo(unsigned int)
{
}

int main()
{
    constexpr int s { 5 };                 // désormais constexpr
    [[maybe_unused]] unsigned int u { s }; // ok : s est constexpr et peut être convertie en toute sécurité, ce n'est pas une conversion restrictive
    foo(s);                                // ok : s est constexpr et peut être convertie en toute sécurité, ce n'est pas une conversion restrictive

    return 0;
}

Dans ce cas, comme s est constexpr et que la valeur à convertir (5) peut être représentée par une valeur non signée, la conversion n'est pas considérée comme restrictive et peut être effectuée implicitement sans problème.

Cette conversion constexpr non restrictive (de constexpr int vers constexpr std::size_t) sera très souvent utilisée.

La longueur et les indices de std::vector sont de type size_type

Dans la leçon 10.7 -- Typedefs et alias de types, nous avons indiqué que les typedefs et les alias de types servent souvent à donner un nom à un type qui peut varier (par exemple parce qu'il dépend de l'implémentation). Par exemple, std::size_t est un typedef désignant un grand type entier non signé, généralement unsigned long ou unsigned long long.

Chacune des classes conteneurs de la bibliothèque standard définit un typedef membre imbriqué nommé size_type (parfois noté T::size_type), qui est un alias du type utilisé pour la longueur (et pour les indices, si le conteneur les supporte).

Vous rencontrerez généralement size_type dans la documentation et dans les messages d'avertissement ou d'erreur du compilateur. Par exemple, cette documentation de la fonction membre size() de std::vector indique que size() renvoie une valeur de type size_type.

Contenu associé

Nous abordons les typedefs imbriqués dans la leçon 15.3 -- Types imbriqués (types membres).

size_type est presque toujours un alias de std::size_t, mais il peut être modifié (dans de rares cas) pour utiliser un autre type.

Point clé

size_type est un typedef imbriqué défini dans les classes conteneurs de la bibliothèque standard, utilisé comme type pour la longueur (et les indices, si le conteneur les supporte).

size_type vaut par défaut std::size_t, et comme cette valeur est très rarement modifiée, on peut raisonnablement considérer que size_type est un alias de std::size_t.

Pour les lecteurs avancés

Tous les conteneurs de la bibliothèque standard, à l'exception de std::array, utilisent std::allocator pour allouer leur mémoire. Pour ces conteneurs, T::size_type est dérivé du size_type de l'allocateur utilisé. Comme std::allocator peut allouer jusqu'à std::size_t octets de mémoire, std::allocator<T>::size_type est défini comme std::size_t. Par conséquent, T::size_type vaut par défaut std::size_t.

Ce n'est que lorsqu'un allocateur personnalisé dont le T::size_type est défini autrement que par std::size_t est utilisé que le T::size_type d'un conteneur sera différent de std::size_t. Ce cas est rare et relève de choix propres à chaque application. On peut donc généralement supposer que T::size_type vaut std::size_t, sauf si votre application utilise un tel allocateur personnalisé (et vous le saurez si c'est le cas).

Lorsqu'on accède au membre size_type d'une classe conteneur, on doit le qualifier par le nom complet, avec les paramètres de modèle, de la classe conteneur. Par exemple, std::vector<int>::size_type.

Obtenir la longueur d'un std::vector avec la fonction membre size() ou std::size()

On peut demander la longueur d'un objet conteneur avec la fonction membre size(), qui renvoie la longueur sous forme de size_type non signé :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime { 2, 3, 5, 7, 11 };
    std::cout << "length: " << prime.size() << '\n'; // renvoie la longueur sous le type `size_type` (alias de `std::size_t`)
    return 0;
}

Ce programme affiche :


length: 5

Contrairement à std::string et std::string_view, qui possèdent à la fois une fonction membre length() et une fonction membre size() (qui font la même chose), std::vector (et la plupart des autres types conteneurs du C++) ne possède que size(). Vous comprenez maintenant pourquoi la longueur d'un conteneur est parfois appelée, de façon ambiguë, sa taille (size).

En C++17, on peut aussi utiliser la fonction non membre std::size() (qui, pour les classes conteneurs, appelle simplement la fonction membre size()).

#include <iostream>
#include <vector>

int main()
{
    std::vector prime { 2, 3, 5, 7, 11 };
    std::cout << "length: " << std::size(prime); // C++17, renvoie la longueur sous le type `size_type` (alias de `std::size_t`)

    return 0;
}

Pour les lecteurs avancés

Comme std::size() peut aussi s'appliquer aux tableaux de style C non dégénérés, cette méthode est parfois préférée à la fonction membre size() (en particulier lorsqu'on écrit des modèles de fonctions acceptant en argument soit une classe conteneur, soit un tableau de style C non dégénéré).

Nous aborderons la dégénérescence des tableaux de style C dans la leçon 17.8 -- Dégénérescence des tableaux de style C.

Si l'on souhaite utiliser l'une des méthodes précédentes pour stocker la longueur dans une variable de type signé, cela produira probablement un avertissement ou une erreur de conversion signé/non signé. La solution la plus simple consiste à effectuer un static_cast du résultat vers le type souhaité :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime { 2, 3, 5, 7, 11 };
    int length { static_cast<int>(prime.size()) }; // static_cast de la valeur de retour vers int
    std::cout << "length: " << length ;

    return 0;
}

Obtenir la longueur d'un std::vector avec std::ssize() (C++20)

Le C++20 introduit la fonction non membre std::ssize(), qui renvoie la longueur sous la forme d'un grand type entier signé (généralement std::ptrdiff_t, qui est le type utilisé habituellement comme équivalent signé de std::size_t) :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime{ 2, 3, 5, 7, 11 };
    std::cout << "length: " << std::ssize(prime); // C++20, renvoie la longueur sous la forme d'un grand type entier signé

    return 0;
}

C'est la seule des trois fonctions qui renvoie la longueur sous un type signé.

Si vous voulez utiliser cette méthode pour stocker la longueur dans une variable de type signé, vous avez plusieurs options.

Tout d'abord, comme le type int peut être plus petit que le type signé renvoyé par std::ssize(), si vous affectez la longueur à une variable int, vous devriez effectuer un static_cast du résultat vers int pour rendre la conversion explicite (sinon vous risquez un avertissement ou une erreur de conversion restrictive) :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime{ 2, 3, 5, 7, 11 };
    int length { static_cast<int>(std::ssize(prime)) }; // static_cast de la valeur de retour vers int
    std::cout << "length: " << length;

    return 0;
}

Vous pouvez également utiliser auto pour laisser le compilateur déduire le type signé correct à utiliser pour la variable :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime{ 2, 3, 5, 7, 11 };
    auto length { std::ssize(prime) }; // utilise auto pour déduire le type signé renvoyé par std::ssize()
    std::cout << "length: " << length;

    return 0;
}

Accéder aux éléments d'un tableau avec operator[] ne vérifie pas les bornes

Dans la leçon précédente, nous avons présenté l'opérateur d'indexation (operator[]) :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime{ 2, 3, 5, 7, 11 };

    std::cout << prime[3];  // affiche la valeur de l'élément d'indice 3 (7)
    std::cout << prime[9]; // indice invalide (comportement indéfini)

    return 0;
}

operator[] n'effectue pas de vérification de bornes. L'indice passé à operator[] peut être non constant. Nous reviendrons sur ce point dans une section ultérieure.

Accéder aux éléments d'un tableau avec la fonction membre at() effectue une vérification de bornes à l'exécution

Les classes conteneurs de tableaux proposent une autre méthode d'accès. La fonction membre at() permet d'accéder à un tableau avec une vérification de bornes à l'exécution :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime{ 2, 3, 5, 7, 11 };

    std::cout << prime.at(3); // affiche la valeur de l'élément d'indice 3
    std::cout << prime.at(9); // indice invalide (lève une exception)

    return 0;
}

Dans l'exemple ci-dessus, l'appel prime.at(3) vérifie que l'indice 3 est valide ; comme c'est le cas, il renvoie une référence à l'élément 3 du tableau, que nous pouvons afficher. En revanche, l'appel prime.at(9) échoue à l'exécution, car 9 n'est pas un indice valide pour ce tableau. Au lieu de renvoyer une référence, la fonction at() génère une erreur qui termine le programme.

Pour les lecteurs avancés

Lorsque la fonction membre at() rencontre un indice hors bornes, elle lève en réalité une exception de type std::out_of_range. Si l'exception n'est pas gérée, le programme est terminé. Nous abordons les exceptions et leur gestion dans le chapitre 27.

Comme pour operator[], l'indice passé à at() peut être non constant.

Parce qu'elle effectue une vérification de bornes à chaque appel, at() est plus lente (mais plus sûre) que operator[]. Bien qu'elle soit moins sûre, operator[] est généralement préférée à at(), principalement parce qu'il vaut mieux vérifier les bornes avant d'indexer, afin de ne pas tenter d'utiliser un indice invalide en premier lieu.

Indexer un std::vector avec une int signée constexpr

Lorsqu'on indexe un std::vector avec un int signé constexpr, on peut laisser le compilateur convertir implicitement cette valeur en std::size_t, sans qu'il s'agisse d'une conversion restrictive :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime{ 2, 3, 5, 7, 11 };

    std::cout << prime[3] << '\n';     // ok : 3 converti de int vers std::size_t, ce n'est pas une conversion restrictive

    constexpr int index { 3 };         // constexpr
    std::cout << prime[index] << '\n'; // ok : index constexpr converti implicitement en std::size_t, ce n'est pas une conversion restrictive

    return 0;
}

Indexer un std::vector avec une valeur non constexpr

Les indices utilisés pour indexer un tableau peuvent être non constants :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime{ 2, 3, 5, 7, 11 };

    std::size_t index { 3 };           // non constexpr
    std::cout << prime[index] << '\n'; // operator[] attend un indice de type std::size_t, aucune conversion n'est nécessaire

    return 0;
}

Cependant, conformément à nos bonnes pratiques (4.5 -- Les entiers non signés, et pourquoi il faut les éviter), nous voulons en général éviter d'utiliser des types non signés pour représenter des quantités.

Lorsque notre indice est une valeur signée non constexpr, nous rencontrons des problèmes :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime{ 2, 3, 5, 7, 11 };

    int index { 3 };                   // non constexpr
    std::cout << prime[index] << '\n'; // avertissement possible : index converti implicitement en std::size_t, conversion restrictive

    return 0;
}

Dans cet exemple, index est un int signé non constexpr. L'indice de operator[], défini dans std::vector, est de type size_type (alias de std::size_t). Par conséquent, lorsque nous appelons prime[index], notre int signé doit être converti en std::size_t.

Une telle conversion ne devrait pas être dangereuse (car l'indice d'un std::vector doit être positif ou nul, et une valeur signée positive ou nulle se convertit sans risque en valeur non signée). Mais lorsqu'elle est effectuée à l'exécution, elle est considérée comme une conversion restrictive, et votre compilateur devrait émettre un avertissement signalant cette conversion comme dangereuse (s'il ne le fait pas, vous devriez envisager de modifier vos paramètres d'avertissement pour qu'il le fasse).

Comme l'indexation de tableaux est très courante, et que chaque conversion de ce type génère un avertissement, cela peut facilement encombrer le journal de compilation d'avertissements inutiles. Ou, si vous avez activé l'option « traiter les avertissements comme des erreurs », cela interrompra votre compilation.

Il existe de nombreuses façons d'éviter ce problème (par exemple, faire un static_cast de votre int vers std::size_t à chaque indexation de tableau), mais toutes finissent par encombrer ou compliquer votre code d'une manière ou d'une autre. La solution la plus simple dans ce cas consiste à utiliser une variable de type std::size_t comme indice, et à ne pas utiliser cette variable pour autre chose que l'indexation. Vous éviterez ainsi d'emblée toute conversion non constexpr.

Astuce

Une autre bonne alternative consiste à indexer non pas le std::vector lui-même, mais le résultat de la fonction membre data() :

#include <iostream>
#include <vector>

int main()
{
    std::vector prime{ 2, 3, 5, 7, 11 };

    int index { 3 };                          // valeur signée non constexpr
    std::cout << prime.data()[index] << '\n'; // ok : aucun avertissement de conversion de signe

    return 0;
}

En interne, std::vector stocke ses éléments dans un tableau de style C. La fonction membre data() renvoie un pointeur vers ce tableau sous-jacent, que nous pouvons ensuite indexer. Comme les tableaux de style C acceptent l'indexation avec des types signés comme non signés, nous ne rencontrons aucun problème de conversion de signe. Nous étudierons plus en détail les tableaux de style C dans les leçons 17.7 -- Introduction aux tableaux de style C et 17.8 -- Dégénérescence des tableaux de style C.

Un moment de quiz

Question n° 1

Initialisez un std::vector avec les valeurs suivantes : 'h', 'e', 'l', 'l', 'o'. Affichez ensuite la longueur du tableau (utilisez std::size()). Enfin, affichez la valeur de l'élément d'indice 1 à l'aide de l'opérateur d'indexation, puis à l'aide de la fonction membre at().

Le programme doit afficher :


The array has 5 elements.
ee
Solution 
#include <iostream>
#include <vector>

int main()
{
    std::vector arr { 'h', 'e', 'l', 'l', 'o' };
    std::cout << "The array has " << std::size(arr) << " elements.\n";
    std::cout << arr[1] << arr.at(1) << '\n';

    return 0;
}

Question n° 2

a) Qu'est-ce que size_type et à quoi sert-il ?

Solution

size_type est un typedef imbriqué qui est un alias du type utilisé pour stocker la longueur (et les indices, si le conteneur les supporte) d'un conteneur de la bibliothèque standard.

b) Par défaut, à quel type size_type est-il égal ? Est-il signé ou non signé ?

Solution

std::size_t, qui est un type non signé.

c) Quelles fonctions permettant d'obtenir la longueur d'un conteneur renvoient un size_type ?

Solution

La fonction membre size() et std::size renvoient toutes deux un size_type.
