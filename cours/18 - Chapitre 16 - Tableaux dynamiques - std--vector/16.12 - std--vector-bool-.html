16.12 — std::vector

Dans la leçon O.1 -- Indicateurs de bits et manipulation de bits avec std::bitset, nous avons vu que std::bitset peut compacter 8 valeurs booléennes dans un octet. Ces bits peuvent ensuite être modifiés à l'aide des fonctions membres de std::bitset.

std::vector dispose d'une astuce intéressante. Il existe une implémentation spéciale pour std::vector<bool> qui peut être plus économe en espace mémoire pour les valeurs booléennes, en compactant de la même façon 8 valeurs booléennes dans un octet.

Pour les lecteurs avancés

Lorsqu'une classe template possède une implémentation différente pour un argument de template particulier, on parle de spécialisation de modèle de classe (class template specialization). Nous reviendrons sur ce sujet dans la leçon 26.4 -- Spécialisation de modèles de classes.

Contrairement à std::bitset, conçu pour la manipulation de bits, std::vector<bool> ne possède pas de fonctions membres dédiées à la manipulation de bits.

Utiliser std::vector<bool>

Pour l'essentiel, std::vector<bool> se comporte comme un std::vector ordinaire :

#include <iostream>
#include <vector>

int main()
{
    std::vector<bool> v { true, false, false, true, true };

    for (int i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    // Change the Boolean value with index 4 to false
    // Modifie la valeur booléenne d'indice 4 pour la passer à false
    v[4] = false;

    for (int i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    return 0;
}

Sur la machine 64 bits de l'auteur, ce programme affiche :


1 0 0 1 1
1 0 0 1 0

Les compromis de std::vector<bool>

Cependant, std::vector<bool> implique certains compromis que les utilisateurs doivent connaître.

Premièrement, std::vector<bool> a une surcharge assez importante (sizeof(std::vector<bool>) vaut 40 octets sur la machine de l'auteur). Vous n'économiserez donc pas de mémoire, sauf si vous allouez plus de valeurs booléennes que la surcharge de votre architecture.

Deuxièmement, les performances de std::vector<bool> dépendent fortement de l'implémentation (les implémentations ne sont même pas tenues d'effectuer des optimisations, encore moins de les réaliser correctement). D'après cet article, une implémentation fortement optimisée peut être nettement plus rapide que les alternatives. En revanche, une implémentation mal optimisée sera plus lente.

Troisièmement, et c'est le point le plus important, std::vector<bool> n'est pas un vector (il n'est pas obligatoirement contigu en mémoire), il ne contient pas de valeurs bool (il contient une collection de bits), et il ne respecte pas la définition d'un conteneur en C++.

Bien que std::vector<bool> se comporte comme un vector dans la plupart des cas, il n'est pas entièrement compatible avec le reste de la bibliothèque standard. Du code qui fonctionne avec d'autres types d'éléments peut ne pas fonctionner avec std::vector<bool>.

Par exemple, le code suivant fonctionne lorsque T est n'importe quel type sauf bool :

template<typename T>
void foo( std::vector<T>& v )
{
    T& first = v[0]; // get a reference to the first element
                     // obtient une référence vers le premier élément
    // Do something with first
    // Faire quelque chose avec first
}

Éviter std::vector<bool>

Le consensus moderne est que std::vector<bool> doit généralement être évité, car les gains de performance sont rarement suffisants pour compenser les problèmes d'incompatibilité liés au fait qu'il ne s'agit pas d'un véritable conteneur.

Malheureusement, cette version optimisée de std::vector<bool> est activée par défaut, et il n'existe aucun moyen de la désactiver au profit d'une version non optimisée qui soit réellement un conteneur. Des voix se sont élevées pour déprécier std::vector<bool>, et des travaux sont en cours pour déterminer à quoi pourrait ressembler un vector compacté de bool de remplacement (peut-être un futur std::dynamic_bitset).

Voici nos recommandations :

  • Utilisez std::bitset (en constexpr si possible) lorsque le nombre de bits nécessaires est connu à la compilation, que vous n'avez pas plus qu'un nombre modéré de valeurs booléennes à stocker (par exemple moins de 64 000), et que l'ensemble restreint d'opérateurs et de fonctions membres (par exemple l'absence de prise en charge des itérateurs) répond à vos besoins.
  • Préférez std::vector<char> lorsque vous avez besoin d'un conteneur redimensionnable de valeurs booléennes et que l'économie d'espace n'est pas indispensable. Ce type se comporte comme un conteneur ordinaire.
  • Privilégiez une implémentation tierce de bitset dynamique (comme boost::dynamic_bitset) lorsque vous avez besoin d'un bitset dynamique pour effectuer des opérations sur les bits. Ces types ne prétendent pas être des conteneurs de la bibliothèque standard lorsqu'ils ne le sont pas.

Bonne pratique

Préférez constexpr std::bitset, std::vector<char> ou un bitset dynamique tiers à std::vector<bool>.
