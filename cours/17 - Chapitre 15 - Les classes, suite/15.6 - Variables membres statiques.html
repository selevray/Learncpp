15.6 — Variables membres statiques

Dans la leçon 7.4 -- Introduction aux variables globales, nous avons présenté les variables globales, et dans la leçon 7.11 -- Variables locales statiques, nous avons présenté les variables locales statiques. Ces deux types de variables ont une durée statique, ce qui signifie qu'elles sont créées au début du programme et détruites à la fin du programme. Ces variables conservent leur valeur même lorsqu'elles sortent de leur portée.

Par exemple :

#include <iostream>

int generateID()
{
    static int s_id{ 0 }; // variable locale statique
    return ++s_id;
}

int main()
{
    std::cout << generateID() << '\n';
    std::cout << generateID() << '\n';
    std::cout << generateID() << '\n';

    return 0;
}

3

Remarquez que la variable locale statique s_id a conservé sa valeur d'un appel de fonction à l'autre.

Les types de classes apportent deux autres utilisations du mot-clé static : les variables membres statiques et les fonctions membres statiques. Heureusement, ces utilisations sont assez simples. Nous parlerons des variables membres statiques dans cette leçon, et des fonctions membres statiques dans la suivante.

Variables membres statiques

Avant d'aborder le mot-clé static appliqué aux variables membres, considérons d'abord la classe suivante :

#include <iostream>

struct Something
{
    int value{ 1 };
};

int main()
{
    Something first{};
    Something second{};

    first.value = 2;

    std::cout << first.value << '\n';
    std::cout << second.value << '\n';

    return 0;
}

Lorsque nous instancions un objet de classe, chaque objet reçoit sa propre copie de tous les membres variables normaux. Ici, comme nous avons déclaré deux objets Something, nous obtenons deux copies de value : first.value et second.value. first.value est distinct de second.value. Par conséquent, le programme ci-dessus affiche :


2
1

Les variables membres d'une classe peuvent être rendues statiques à l'aide du mot-clé static. Contrairement aux variables membres normales, les variables membres statiques sont partagées par tous les objets de la classe. Considérez le programme suivant, similaire au précédent :

#include <iostream>

struct Something
{
    static int s_value; // déclare s_value comme statique (initialisation déplacée ci-dessous)
};

int Something::s_value{ 1 }; // définit et initialise s_value à 1 (nous en discutons dans la section suivante)

int main()
{
    Something first{};
    Something second{};

    first.s_value = 2;

    std::cout << first.s_value << '\n';
    std::cout << second.s_value << '\n';
    return 0;
}

Ce programme produit la sortie suivante :


2
2

Comme s_value est une variable membre statique, s_value est partagée entre tous les objets de la classe. Par conséquent, first.s_value est la même variable que second.s_value. Le programme ci-dessus montre que la valeur que nous avons définie à l'aide de first peut être lue à l'aide de second !

Les membres statiques ne sont pas associés aux objets de la classe

Bien que vous puissiez accéder aux membres statiques via des objets de la classe (comme dans first.s_value et second.s_value de l'exemple ci-dessus), les membres statiques existent même si aucun objet de la classe n'a été instancié ! Cela est logique : ils sont créés au début du programme et détruits à la fin, donc leur durée de vie n'est pas liée à un objet de classe, contrairement à un membre normal.

En substance, les membres statiques sont des variables globales qui vivent à l'intérieur de la région de portée de la classe. Il existe très peu de différence entre un membre statique d'une classe et une variable normale à l'intérieur d'un espace de noms.

Point clé

Les membres statiques sont des variables globales qui vivent à l'intérieur de la région de portée de la classe.

Comme le membre statique s_value existe indépendamment de tout objet de la classe, il peut être accédé directement à l'aide du nom de la classe et de l'opérateur de résolution de portée (dans ce cas, Something::s_value) :

class Something
{
public:
    static int s_value; // déclare s_value comme statique
};

int Something::s_value{ 1 }; // définit et initialise s_value à 1 (nous en discutons dans la section suivante)

int main()
{
    // remarque : nous n'instancions aucun objet de type Something

    Something::s_value = 2;
    std::cout << Something::s_value << '\n';
    return 0;
}

Dans l'extrait ci-dessus, s_value est référencée par le nom de classe Something plutôt qu'à travers un objet. Remarquez que nous n'avons même pas instancié d'objet de type Something, mais nous pouvons tout de même accéder à Something::s_value et l'utiliser. C'est la méthode à privilégier pour accéder aux membres statiques.

Bonne pratique

Accédez aux membres statiques à l'aide du nom de la classe et de l'opérateur de résolution de portée (::).

Définition et initialisation des variables membres statiques

Lorsque nous déclarons une variable membre statique à l'intérieur d'un type de classe, nous indiquons au compilateur l'existence d'une variable membre statique, sans pour autant la définir (un peu comme une déclaration anticipée). Comme les variables membres statiques sont essentiellement des variables globales, vous devez explicitement les définir (et éventuellement les initialiser) en dehors de la classe, dans la portée globale.

Dans l'exemple ci-dessus, nous le faisons via cette ligne :

int Something::s_value{ 1 }; // définit et initialise s_value à 1

Cette ligne remplit deux rôles : elle instancie la variable membre statique (exactement comme une variable globale) et l'initialise. Ici, nous fournissons la valeur d'initialisation 1. Si aucune initialisation n'est fournie, les variables membres statiques sont par défaut initialisées à zéro.

Notez que cette définition du membre statique n'est pas soumise aux contrôles d'accès : vous pouvez définir et initialiser la valeur même si elle est déclarée privée (ou protégée) dans la classe, car une définition n'est pas considérée comme une forme d'accès.

Pour les classes non template, si la classe est définie dans un fichier d'en-tête (.h), la définition du membre statique est généralement placée dans le fichier de code associé à la classe (par exemple Something.cpp). Il est également possible de définir le membre comme inline et de le placer sous la définition de la classe, dans l'en-tête (ce qui est utile pour les bibliothèques ne reposant que sur des en-têtes). Si la classe est définie dans un fichier source (.cpp), la définition du membre statique est généralement placée directement sous la classe. Ne placez pas la définition d'un membre statique dans un fichier d'en-tête (tout comme une variable globale, si cet en-tête est inclus plus d'une fois, vous obtiendrez plusieurs définitions, ce qui provoquera une erreur de l'éditeur de liens).

Pour les classes template, la définition (templatisée) du membre statique est typiquement placée directement sous la définition de la classe template, dans le fichier d'en-tête (cela ne viole pas la règle de définition unique (ODR), car de telles définitions sont implicitement inline).

Initialisation des variables membres statiques dans la définition de la classe

Il existe quelques raccourcis par rapport à ce qui précède. Tout d'abord, lorsque le membre statique est d'un type entier constant (ce qui inclut char et bool) ou d'une énumération constante, le membre statique peut être initialisé dans la définition de la classe :

class Whatever
{
public:
    static const int s_value{ 4 }; // un static const int peut être défini et initialisé directement
};

Dans l'exemple ci-dessus, comme la variable membre statique est un const int, aucune ligne de définition explicite n'est nécessaire. Ce raccourci est autorisé car ces types const particuliers sont des constantes de compilation.

Dans la leçon 7.10 -- Partager des constantes globales entre plusieurs fichiers (à l'aide de variables inline), nous avons présenté les variables inline, c'est-à-dire des variables autorisées à avoir plusieurs définitions. C++17 permet aux membres statiques d'être des variables inline :

class Whatever
{
public:
    static inline int s_value{ 4 }; // une variable inline statique peut être définie et initialisée directement
};

De telles variables peuvent être initialisées dans la définition de la classe, qu'elles soient constantes ou non. C'est la méthode à privilégier pour définir et initialiser les membres statiques.

Comme les membres constexpr sont implicitement inline (à partir de C++17), les membres statiques constexpr peuvent également être initialisés dans la définition de la classe sans utiliser explicitement le mot-clé inline :

#include <string_view>

class Whatever
{
public:
    static constexpr double s_value{ 2.2 }; // ok
    static constexpr std::string_view s_view{ "Hello" }; // cela fonctionne même pour les classes qui supportent l'initialisation constexpr
};

Bonne pratique

Rendez vos membres statiques inline ou constexpr afin qu'ils puissent être initialisés dans la définition de la classe.

Un exemple de variables membres statiques

Pourquoi utiliser des variables statiques dans les classes ? Une utilisation consiste à attribuer un identifiant unique à chaque instance de la classe. Voici un exemple :

#include <iostream>

class Something
{
private:
    static inline int s_idGenerator { 1 };
    int m_id {};

public:
    // récupère la prochaine valeur du générateur d'identifiants
    Something() : m_id { s_idGenerator++ } 
    {    
    }

    int getID() const { return m_id; }
};

int main()
{
    Something first{};
    Something second{};
    Something third{};

    std::cout << first.getID() << '\n';
    std::cout << second.getID() << '\n';
    std::cout << third.getID() << '\n';
    return 0;
}

2
3

Comme s_idGenerator est partagé par tous les objets Something, lorsqu'un nouvel objet Something est créé, le constructeur initialise m_id avec la valeur courante de s_idGenerator, puis incrémente cette valeur pour l'objet suivant. Cela garantit que chaque objet Something instancié reçoit un identifiant unique (incrémenté dans l'ordre de création).

Donner un identifiant unique à chaque objet peut faciliter le débogage, car il permet de distinguer des objets qui ont par ailleurs des données identiques. C'est particulièrement vrai lorsque l'on travaille avec des tableaux de données.

Les variables membres statiques sont également utiles lorsque la classe doit utiliser une table de correspondance (par exemple, un tableau servant à stocker un ensemble de valeurs précalculées). En rendant la table statique, une seule copie existe pour tous les objets, au lieu d'une copie par objet instancié. Cela peut économiser une quantité substantielle de mémoire.

Seuls les membres statiques peuvent utiliser la déduction de type (auto et CTAD)

Un membre statique peut utiliser auto pour déduire son type à partir de son initialisateur, ou la déduction des arguments de modèle de classe (CTAD, Class Template Argument Deduction) pour déduire les arguments de type du modèle à partir de son initialisateur.

Les membres non statiques ne peuvent pas utiliser auto ni CTAD.

Les raisons de cette distinction sont assez complexes, mais se résument à l'existence de certains cas, pouvant survenir avec des membres non statiques, qui conduisent à des ambiguïtés ou à des résultats peu intuitifs. Ces cas ne se produisent pas pour les membres statiques. C'est pourquoi les membres non statiques sont limités dans l'utilisation de ces fonctionnalités, alors que les membres statiques ne le sont pas.

#include <utility> // pour std::pair<T, U>

class Foo
{
private:
    auto m_x { 5 };           // auto non autorisé pour les membres non statiques
    std::pair m_v { 1, 2.3 }; // CTAD non autorisé pour les membres non statiques

    static inline auto s_x { 5 };           // auto autorisé pour les membres statiques
    static inline std::pair s_v { 1, 2.3 }; // CTAD autorisé pour les membres statiques

public:
    Foo() {};
};

int main()
{
    Foo foo{};

    return 0;
}
