15.3 — Types imbriqués (types membres)

Considérez le programme court suivant :

#include <iostream>

enum class FruitType
{
    apple,
    banana,
    cherry
};

class Fruit
{
private:
    FruitType m_type { };
    int m_percentageEaten { 0 };

public:
    Fruit(FruitType type) :
        m_type { type }
    {
    }

    FruitType getType() { return m_type; }
    int getPercentageEaten() { return m_percentageEaten; }

    bool isCherry() { return m_type == FruitType::cherry; }

};

int main()
{
    Fruit apple { FruitType::apple };

    if (apple.getType() == FruitType::apple)
        std::cout << "I am an apple";
    else
        std::cout << "I am not an apple";

    return 0;
}

Il n'y a rien de faux dans ce programme. Mais comme enum class FruitType est destinée à être utilisée avec la classe Fruit, le fait qu'elle existe indépendamment de la classe nous oblige à deviner le lien entre les deux.

Types imbriqués (types membres)

Jusqu'ici, nous avons vu des classes avec deux sortes de membres : les membres données et les fonctions membres. La classe Fruit de l'exemple ci-dessus possède les deux.

Les classes peuvent aussi contenir une autre sorte de membre : les types imbriqués (aussi appelés types membres). Pour créer un type imbriqué, il suffit de définir le type à l'intérieur de la classe, sous le spécificateur d'accès approprié.

Voici le même programme que précédemment, réécrit pour utiliser un type imbriqué défini à l'intérieur de la classe Fruit :

#include <iostream>

class Fruit
{
public:
    // FruitType a été déplacé à l'intérieur de la classe, sous le spécificateur d'accès public
        // Nous l'avons aussi renommé Type et en avons fait une enum (et non une enum class)
    enum Type
    {
        apple,
        banana,
        cherry
    };

private:
    Type m_type {};
    int m_percentageEaten { 0 };

public:
    Fruit(Type type) :
        m_type { type }
    {
    }

    Type getType() { return m_type;  }
    int getPercentageEaten() { return m_percentageEaten;  }

    bool isCherry() { return m_type == cherry; } // Dans les membres de Fruit, nous n'avons plus besoin de préfixer les énumérateurs par FruitType::
};

int main()
{
    // Remarque : en dehors de la classe, nous accédons maintenant aux énumérateurs via le préfixe Fruit::
    Fruit apple { Fruit::apple };

    if (apple.getType() == Fruit::apple)
        std::cout << "I am an apple";
    else
        std::cout << "I am not an apple";

    return 0;
}

Il y a quelques points à souligner ici.

Premièrement, remarquez que FruitType est maintenant définie à l'intérieur de la classe, où elle a été renommée Type, pour des raisons que nous verrons bientôt.

Deuxièmement, le type imbriqué Type a été défini en haut de la classe. Les noms de types imbriqués doivent être entièrement définis avant d'être utilisés, c'est pourquoi on les définit généralement en premier.

Bonne pratique

Définissez les types imbriqués en haut de votre classe.

Troisièmement, les types imbriqués suivent les règles d'accès habituelles. Type est défini sous le spécificateur public, afin que le nom du type et les énumérateurs soient directement accessibles au public.

Quatrièmement, les classes forment une région de portée pour les noms qui y sont déclarés, tout comme les espaces de noms (namespaces). Ainsi, le nom complet de Type est Fruit::Type, et le nom complet de l'énumérateur apple est Fruit::apple.

Dans les membres de la classe, nous n'avons pas besoin d'utiliser le nom complet. Par exemple, dans la fonction membre isCherry(), nous accédons à l'énumérateur cherry sans le qualificatif de portée Fruit::.

En dehors de la classe, nous devons utiliser le nom complet (par exemple Fruit::apple). Nous avons renommé FruitType en Type afin de pouvoir y accéder par Fruit::Type (plutôt que par Fruit::FruitType, plus redondant).

Enfin, nous avons transformé notre type énuméré de « scoped » en « unscoped ». Comme la classe elle-même joue maintenant le rôle de région de portée, il est un peu redondant d'utiliser aussi un énumérateur à portée propre. Passer à une énumération non scopée nous permet d'accéder aux énumérateurs par Fruit::apple, plutôt que par la forme plus longue Fruit::Type::apple que nous aurions dû utiliser avec un énumérateur scopé.

Typedefs et alias de types imbriqués

Les classes peuvent aussi contenir des typedefs ou des alias de types imbriqués :

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
public:
    using IDType = int;

private:
    std::string m_name{};
    IDType m_id{};
    double m_wage{};

public:
    Employee(std::string_view name, IDType id, double wage)
        : m_name { name }
        , m_id { id }
        , m_wage { wage }
    {
    }

    const std::string& getName() { return m_name; }
    IDType getId() { return m_id; } // peut utiliser le nom non qualifié à l'intérieur de la classe
};

int main()
{
    Employee john { "John", 1, 45000 };
    Employee::IDType id { john.getId() }; // doit utiliser le nom complet en dehors de la classe

    std::cout << john.getName() << " has id: " << id << '\n';

    return 0;
}

Ce programme affiche :


John has id: 1

Remarquez qu'à l'intérieur de la classe nous pouvons simplement utiliser IDType, mais qu'en dehors de la classe nous devons utiliser le nom complet Employee::IDType.

Nous discutons des avantages des alias de types dans la leçon 10.7 -- Typedefs et alias de types, et ils servent ici le même objectif. Il est très courant que les classes de la bibliothèque standard C++ utilisent des typedefs imbriqués. Au moment où nous écrivons ces lignes, std::string définit pas moins de dix typedefs imbriqués !

Classes imbriquées et accès aux membres de la classe englobante

Il est assez rare que des classes aient d'autres classes comme types imbriqués, mais c'est possible. En C++, une classe imbriquée n'a pas accès au pointeur this de la classe englobante (externe). Une classe imbriquée ne peut donc pas accéder directement aux membres de la classe externe. En effet, une classe imbriquée peut être instanciée indépendamment de la classe externe (et, dans ce cas, il n'y aurait aucun membre de la classe externe à accéder !).

Cependant, comme les classes imbriquées sont des membres de la classe externe, elles peuvent accéder à tous les membres privés de la classe externe qui sont dans leur portée.

Illustrons cela avec un exemple :

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
public:
    using IDType = int;

    class Printer
    {
    public:
        void print(const Employee& e) const
        {
            // Printer ne peut pas accéder au pointeur this de Employee
            // donc nous ne pouvons pas afficher directement m_name et m_id
            // À la place, nous devons passer un objet Employee à utiliser
            // Comme Printer est un membre de Employee,
            // nous pouvons accéder directement aux membres privés e.m_name et e.m_id
            std::cout << e.m_name << " has id: " << e.m_id << '\n';
        }
    };

private:
    std::string m_name{};
    IDType m_id{};
    double m_wage{};

public:
    Employee(std::string_view name, IDType id, double wage)
        : m_name{ name }
        , m_id{ id }
        , m_wage{ wage }
    {
    }

    // fonctions d'accès supprimées dans cet exemple (car elles ne sont pas utilisées)
};

int main()
{
    const Employee john{ "John", 1, 45000 };
    const Employee::Printer p{}; // instancie un objet de la classe interne
    p.print(john);

    return 0;
}

Ce programme affiche :


John has id: 1

Il existe un cas où les classes imbriquées sont plus couramment utilisées. Dans la bibliothèque standard, la plupart des classes d'itérateurs sont implémentées comme classes imbriquées du conteneur qu'elles sont censées parcourir. Par exemple, std::string::iterator est implémenté comme classe imbriquée de std::string. Nous verrons les itérateurs dans un chapitre futur.

Types imbriqués et déclarations anticipées

Un type imbriqué peut faire l'objet d'une déclaration anticipée (forward declaration) à l'intérieur de la classe qui l'englobe. Le type imbriqué peut ensuite être défini plus tard, soit à l'intérieur de la classe englobante, soit à l'extérieur. Par exemple :

#include <iostream>

class outer
{
public:
    class inner1;   // ok : déclaration anticipée à l'intérieur de la classe englobante
    class inner1{}; // ok : définition du type déclaré à l'avance, à l'intérieur de la classe englobante
    class inner2;   // ok : déclaration anticipée à l'intérieur de la classe englobante
};

class inner2 // ok : définition du type déclaré à l'avance, à l'extérieur de la classe englobante
{
};

int main()
{
    return 0;
}

En revanche, un type imbriqué ne peut pas faire l'objet d'une déclaration anticipée avant la définition de la classe englobante.

#include <iostream>

class outer;         // ok : on peut déclarer à l'avance un type non imbriqué
class outer::inner1; // erreur : impossible de déclarer à l'avance un type imbriqué avant la définition de la classe outer

class outer
{
public:
    class inner1{}; // remarque : type imbriqué déclaré ici
};

class outer::inner1; // ok (mais redondant) puisque le type imbriqué a déjà été déclaré dans la définition de la classe outer

int main()
{
    return 0;
}

Bien que vous puissiez déclarer à l'avance un type imbriqué après la définition de la classe englobante, cela est redondant, puisque la classe englobante contient déjà une déclaration du type imbriqué.
