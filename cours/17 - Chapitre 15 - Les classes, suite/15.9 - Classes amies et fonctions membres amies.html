15.9 — Classes amies et fonctions membres amies

Classes amies

Une classe amie (friend class) est une classe qui peut accéder aux membres privés et protégés d'une autre classe.

Voici un exemple :

#include <iostream>

class Storage
{
private:
    int m_nValue {};
    double m_dValue {};
public:
    Storage(int nValue, double dValue)
       : m_nValue { nValue }, m_dValue { dValue }
    { }

    // Make the Display class a friend of Storage
    friend class Display;
};

class Display
{
private:
    bool m_displayIntFirst {};

public:
    Display(bool displayIntFirst)
         : m_displayIntFirst { displayIntFirst }
    {
    }

    // Because Display is a friend of Storage, Display members can access the private members of Storage
    void displayStorage(const Storage& storage)
    {
        if (m_displayIntFirst)
            std::cout << storage.m_nValue << ' ' << storage.m_dValue << '\n';
        else // display double first
            std::cout << storage.m_dValue << ' ' << storage.m_nValue << '\n';
    }

    void setDisplayIntFirst(bool b)
    {
         m_displayIntFirst = b;
    }
};

int main()
{
    Storage storage { 5, 6.7 };
    Display display { false };

    display.displayStorage(storage);

    display.setDisplayIntFirst(true);
    display.displayStorage(storage);

    return 0;
}

Comme la classe Display est une amie de Storage, les membres de Display peuvent accéder aux membres privés de tout objet Storage auquel ils ont accès.

Ce programme produit le résultat suivant :


6.7 5
5 6.7

Quelques remarques supplémentaires sur les classes amies.

Premièrement, même si Display est une amie de Storage, Display n'a pas accès au pointeur *this des objets Storage (car *this est en réalité un paramètre de fonction).

Deuxièmement, l'amitié n'est pas réciproque. Le fait que Display soit une amie de Storage ne signifie pas que Storage soit aussi une amie de Display. Si vous voulez que deux classes soient amies l'une de l'autre, chacune doit déclarer l'autre comme amie.

Note de l'auteur

Désolé si celui-ci touche un peu de près à la réalité !

L'amitié entre classes n'est pas non plus transitive. Si la classe A est une amie de B, et que B est une amie de C, cela ne signifie pas que A est une amie de C.

Pour les lecteurs avancés

L'amitié n'est pas non plus héritée. Si la classe A déclare B comme amie, les classes dérivées de B ne sont pas amies de A.

Une déclaration de classe amie agit comme une déclaration anticipée (forward declaration) de la classe déclarée amie. Cela signifie qu'il n'est pas nécessaire de déclarer à l'avance la classe qu'on déclare amie. Dans l'exemple ci-dessus, friend class Display joue à la fois le rôle de déclaration anticipée de Display et de déclaration d'amitié.

Fonctions membres amies

Plutôt que de faire d'une classe entière une amie, vous pouvez ne faire d'amie qu'une seule fonction membre. Cela se fait de manière similaire à la déclaration d'une fonction non membre comme amie, à ceci près qu'on utilise le nom de la fonction membre.

Toutefois, en pratique, cela peut être un peu plus délicat qu'on ne l'imagine. Transformons l'exemple précédent pour faire de Display::displayStorage une fonction membre amie. Vous pourriez essayer quelque chose comme ceci :

#include <iostream>

class Display; // forward declaration for class Display

class Storage
{
private:
    int m_nValue {};
    double m_dValue {};
public:
    Storage(int nValue, double dValue)
        : m_nValue { nValue }, m_dValue { dValue }
    {
    }

    // Make the Display::displayStorage member function a friend of the Storage class
    friend void Display::displayStorage(const Storage& storage); // error: Storage hasn't seen the full definition of class Display
};

class Display
{
private:
    bool m_displayIntFirst {};

public:
    Display(bool displayIntFirst)
        : m_displayIntFirst { displayIntFirst }
    {
    }

    void displayStorage(const Storage& storage)
    {
        if (m_displayIntFirst)
            std::cout << storage.m_nValue << ' ' << storage.m_dValue << '\n';
        else // display double first
            std::cout << storage.m_dValue << ' ' << storage.m_nValue << '\n';
    }
};

int main()
{
    Storage storage { 5, 6.7 };
    Display display { false };
    display.displayStorage(storage);

    return 0;
}

Malheureusement, cela ne fonctionne pas. Pour qu'une fonction membre unique soit déclarée amie, le compilateur doit avoir vu la définition complète de la classe à laquelle appartient cette fonction membre (et pas seulement une déclaration anticipée). Comme la classe Storage n'a pas encore vu la définition complète de la classe Display, le compilateur produira une erreur à l'endroit où nous essayons de déclarer la fonction membre comme amie.

Heureusement, il suffit de déplacer la définition de la classe Display avant celle de la classe Storage (soit dans le même fichier, soit en plaçant la définition de Display dans un fichier d'en-tête inclus avec #include avant la définition de Storage).

#include <iostream>

class Display
{
private:
    bool m_displayIntFirst {};

public:
    Display(bool displayIntFirst)
        : m_displayIntFirst { displayIntFirst }
    {
    }

    void displayStorage(const Storage& storage) // compile error: compiler doesn't know what a Storage is
    {
        if (m_displayIntFirst)
            std::cout << storage.m_nValue << ' ' << storage.m_dValue << '\n';
        else // display double first
            std::cout << storage.m_dValue << ' ' << storage.m_nValue << '\n';
    }
};

class Storage
{
private:
    int m_nValue {};
    double m_dValue {};
public:
    Storage(int nValue, double dValue)
        : m_nValue { nValue }, m_dValue { dValue }
    {
    }

    // Make the Display::displayStorage member function a friend of the Storage class
    friend void Display::displayStorage(const Storage& storage); // okay now
};

int main()
{
    Storage storage { 5, 6.7 };
    Display display { false };
    display.displayStorage(storage);

    return 0;
}

Cependant, nous rencontrons maintenant un autre problème. Comme la fonction membre Display::displayStorage() utilise Storage comme paramètre par référence, et que nous venons de placer la définition de Storage après celle de Display, le compilateur signale qu'il ne sait pas ce qu'est un Storage. Nous ne pouvons pas résoudre ce problème en réorganisant l'ordre des définitions, car nous annulerions alors la correction précédente.

Heureusement, ce problème se règle aussi en quelques étapes simples. D'abord, nous ajoutons class Storage comme déclaration anticipée, afin que le compilateur accepte une référence à Storage avant d'avoir vu la définition complète de la classe.

Ensuite, nous déplaçons la définition de Display::displayStorage() hors de la classe, après la définition complète de la classe Storage.

Voici ce que cela donne :

#include <iostream>

class Storage; // forward declaration for class Storage

class Display
{
private:
    bool m_displayIntFirst {};

public:
    Display(bool displayIntFirst)
        : m_displayIntFirst { displayIntFirst }
    {
    }

    void displayStorage(const Storage& storage); // forward declaration for Storage needed for reference here
};

class Storage // full definition of Storage class
{
private:
    int m_nValue {};
    double m_dValue {};
public:
    Storage(int nValue, double dValue)
        : m_nValue { nValue }, m_dValue { dValue }
    {
    }

    // Make the Display::displayStorage member function a friend of the Storage class
    // Requires seeing the full definition of class Display (as displayStorage is a member)
    friend void Display::displayStorage(const Storage& storage);
};

// Now we can define Display::displayStorage
// Requires seeing the full definition of class Storage (as we access Storage members)
void Display::displayStorage(const Storage& storage)
{
    if (m_displayIntFirst)
        std::cout << storage.m_nValue << ' ' << storage.m_dValue << '\n';
    else // display double first
        std::cout << storage.m_dValue << ' ' << storage.m_nValue << '\n';
}

int main()
{
    Storage storage { 5, 6.7 };
    Display display { false };
    display.displayStorage(storage);

    return 0;
}

Désormais, tout se compile correctement : la déclaration anticipée de class Storage suffit pour la déclaration de Display::displayStorage() dans la classe Display. La définition complète de Display permet de déclarer Display::displayStorage() comme amie de Storage. Et la définition complète de la classe Storage suffit pour la définition de la fonction membre Display::displayStorage().

Si tout cela vous paraît un peu confus, reportez-vous aux commentaires du programme ci-dessus. Les points clés sont qu'une déclaration anticipée de classe suffit pour les références à cette classe, mais que l'accès aux membres d'une classe exige que le compilateur ait vu la définition complète de cette classe.

Si cela vous semble contraignant, c'est en effet le cas. Heureusement, ce jeu de réorganisation n'est nécessaire que parce que nous faisons tout dans un seul fichier. Une meilleure solution consiste à placer chaque définition de classe dans un fichier d'en-tête séparé, et les définitions des fonctions membres dans les fichiers .cpp correspondants. Ainsi, toutes les définitions de classes seraient disponibles dans les fichiers .cpp, et aucune réorganisation des classes ou des fonctions ne serait nécessaire !

Quiz

Question n° 1

En géométrie, un point est une position dans l'espace. Nous pouvons définir un point dans l'espace à trois dimensions comme l'ensemble de ses coordonnées x, y et z. Par exemple, Point { 2.0, 1.0, 0.0 } est le point de coordonnées x=2.0, y=1.0 et z=0.0.

En physique, un vecteur est une grandeur qui possède une norme (longueur) et une direction (mais pas de position). Nous pouvons définir un vecteur dans l'espace à trois dimensions par une valeur x, y et z représentant la direction du vecteur selon les axes x, y et z (la longueur peut en être déduite). Par exemple, Vector { 2.0, 0.0, 0.0 } est un vecteur représentant une direction uniquement selon l'axe x positif, de longueur 2.0.

Un Vector peut être appliqué à un Point pour déplacer ce Point vers une nouvelle position. Cela se fait en ajoutant la direction du vecteur à la position du point pour obtenir une nouvelle position. Par exemple, Point { 2.0, 1.0, 0.0 } + Vector { 2.0, 0.0, 0.0 } donne Point { 4.0, 1.0, 0.0 }.

Ces points et vecteurs sont souvent utilisés en infographie (les points représentant les sommets d'une forme, et les vecteurs représentant le déplacement de cette forme).

Soit le programme suivant :

#include <iostream>

    {
        std::cout << "Point(" << m_x << ", " << m_y << ", " << m_z << ")\n";

    {
        // implement this function as a friend of class Vector3d
    }

Au lieu de faire de la classe Point3d une amie de la classe Vector3d, faites de la fonction membre Point3d::moveByVector une fonction amie de la classe Vector3d.

Solution 
#include <iostream>

class Vector3d; // first, we need to tell the compiler that a class named Vector3d exists

class Point3d
{
private:
    double m_x{};
    double m_y{};
    double m_z{};

public:
    Point3d(double x, double y, double z)
        : m_x{x}, m_y{y}, m_z{z}
    {

    }

    void print() const
    {
        std::cout << "Point(" << m_x << ", " << m_y << ", " << m_z << ")\n";
    }

    void moveByVector(const Vector3d& v); // so we can use Vector3d here
       // note: we can't define this function here, because Vector3d hasn't been defined yet (just forward declared)
};

class Vector3d
{
private:
    double m_x{};
    double m_y{};
    double m_z{};

public:
    Vector3d(double x, double y, double z)
        : m_x{x}, m_y{y}, m_z{z}
    {

    }

    void print() const
    {
        std::cout << "Vector(" << m_x << ", " << m_y << ", " << m_z << ")\n";
    }

    friend void Point3d::moveByVector(const Vector3d& v); // Point3d::moveByVector() is now a friend of class Vector3d
};

// Now that Vector3d has been defined, we can define the function Point3d::moveByVector()
void Point3d::moveByVector(const Vector3d& v)
{
    m_x += v.m_x;
    m_y += v.m_y;
    m_z += v.m_z;
}

    Vector3d v { 2.0, 2.0, -3.0 };

    p.print();
    p.moveByVector(v);
    p.print();

> Étape n° 3

Solution

Point3d.h :

// Header file that defines the Point3d class

#ifndef POINT3D_H
#define POINT3D_H

class Vector3d; // forward declaration for class Vector3d for function moveByVector()

class Point3d
{
    private:
        double m_x{};
        double m_y{};
        double m_z{};

    public:
        Point3d(double x, double y, double z);

        void print() const;
        void moveByVector(const Vector3d& v); // forward declaration above needed for this line
};

#endif

Point3d.cpp :

// Member functions of the Point3d class defined here

#include "Point3d.h" // Point3d class defined here
#include "Vector3d.h" // for the parameter of the function moveByVector()

#include <iostream>

Point3d::Point3d(double x, double y, double z)
  : m_x{x}, m_y{y}, m_z{z}
{}

void Point3d::moveByVector(const Vector3d& v)
{
    // Add the vector components to the corresponding point coordinates
    m_x += v.m_x;
    m_y += v.m_y;
    m_z += v.m_z;
}

void Point3d::print() const
{
    std::cout << "Point(" << m_x << ", " << m_y << ", " << m_z << ")\n";
}
