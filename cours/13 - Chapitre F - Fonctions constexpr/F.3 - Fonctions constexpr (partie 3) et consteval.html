F.3 — Fonctions constexpr (partie 3) et consteval

Forcer l'évaluation d'une fonction constexpr à la compilation

Il n'existe aucun moyen d'indiquer au compilateur qu'une fonction constexpr doit, si possible, être évaluée à la compilation (par exemple lorsque la valeur de retour d'une fonction constexpr est utilisée dans une expression non constante).

Cependant, nous pouvons forcer une fonction constexpr éligible à une évaluation à la compilation à être effectivement évaluée à la compilation, en veillant à ce que sa valeur de retour soit utilisée là où une expression constante est requise. Cela doit être fait appel par appel.

La façon la plus courante de procéder consiste à utiliser la valeur de retour pour initialiser une variable constexpr (c'est pour cette raison que nous avons utilisé la variable g dans les exemples précédents). Malheureusement, cela oblige à introduire une nouvelle variable dans notre programme uniquement pour garantir l'évaluation à la compilation, ce qui est peu élégant et réduit la lisibilité du code.

Pour les lecteurs avancés

Plusieurs astuces ont été proposées pour contourner le problème de la nécessité d'introduire une nouvelle variable constexpr à chaque fois que nous voulons forcer l'évaluation à la compilation. Voir ici et ici.

Cependant, en C++20, il existe une meilleure solution à ce problème, que nous présentons dans un instant.

Consteval (C++20)

C++20 introduit le mot-clé consteval, utilisé pour indiquer qu'une fonction doit être évaluée à la compilation, sans quoi une erreur de compilation est produite. Ces fonctions sont appelées fonctions immédiates (immediate functions).

#include <iostream>

consteval int greater(int x, int y) // la fonction est maintenant consteval
{
    return (x > y ? x : y);
}

int main()
{
    constexpr int g { greater(5, 6) };              // ok : sera évaluée à la compilation
    std::cout << g << '\n';

    std::cout << greater(5, 6) << " is greater!\n"; // ok : sera évaluée à la compilation

    int x{ 5 }; // non constexpr
    std::cout << greater(x, 6) << " is greater!\n"; // erreur : les fonctions consteval doivent être évaluées à la compilation

    return 0;
}

Dans l'exemple ci-dessus, les deux premiers appels à greater() seront évalués à la compilation. L'appel greater(x, 6) ne peut pas être évalué à la compilation, ce qui produit une erreur de compilation.

Bonne pratique

Utilisez consteval si vous avez une fonction qui doit impérativement être évaluée à la compilation pour une raison quelconque (par exemple parce qu'elle effectue une opération qui ne peut être réalisée qu'à la compilation).

Fait peut-être surprenant, les paramètres d'une fonction consteval ne sont pas constexpr (alors même que les fonctions consteval ne peuvent être évaluées qu'à la compilation). Cette décision a été prise par souci de cohérence.

Déterminer si un appel de fonction constexpr est évalué à la compilation ou à l'exécution

Le C++ ne fournit actuellement aucun mécanisme fiable pour le faire.

Qu'en est-il de std::is_constant_evaluated ou de if consteval ? (Avancé)

Ni l'une ni l'autre de ces fonctionnalités ne permet de savoir si un appel de fonction est évalué à la compilation ou à l'exécution.

std::is_constant_evaluated() (défini dans l'en-tête <type_traits>) renvoie un bool indiquant si la fonction courante s'exécute dans un contexte d'évaluation constante. Un contexte d'évaluation constante (appelé aussi contexte constant) est un contexte dans lequel une expression constante est requise (par exemple l'initialisation d'une variable constexpr). Ainsi, lorsque le compilateur est tenu d'évaluer une expression constante à la compilation, std::is_constant_evaluated() vaudra true, comme prévu.

Cela permet d'écrire quelque chose comme ceci :

#include <type_traits> // pour std::is_constant_evaluated()

constexpr int someFunction()
{
    if (std::is_constant_evaluated()) // si l'évaluation se fait dans un contexte constant
        doSomething();
    else
        doSomethingElse();
}

Cependant, le compilateur peut également choisir d'évaluer une fonction constexpr à la compilation dans un contexte qui ne requiert pas d'expression constante. Dans ce cas, std::is_constant_evaluated() renverra false alors que la fonction a bien été évaluée à la compilation. Ainsi, std::is_constant_evaluated() signifie réellement « le compilateur est contraint d'évaluer ceci à la compilation », et non « ceci est évalué à la compilation ».

Point clé

Bien que cela puisse sembler étrange, il y a plusieurs raisons à cela :

  1. Comme l'indique la proposition qui a introduit cette fonctionnalité, la norme ne fait en réalité pas de distinction entre « temps de compilation » et « temps d'exécution ». Définir un comportement reposant sur cette distinction aurait représenté une modification plus importante.
  2. Les optimisations ne doivent pas modifier le comportement observable d'un programme (sauf si la norme l'autorise explicitement). Si std::is_constant_evaluated() renvoyait true chaque fois qu'une fonction est évaluée à la compilation, quelle qu'en soit la raison, la décision de l'optimiseur d'évaluer une fonction à la compilation plutôt qu'à l'exécution pourrait modifier le comportement observable de cette fonction. Votre programme pourrait alors se comporter très différemment selon le niveau d'optimisation utilisé à la compilation !

Ce problème pourrait être résolu de diverses manières, mais celles-ci ajouteraient de la complexité à l'optimiseur et/ou limiteraient sa capacité à optimiser certains cas.

Introduit en C++23, if consteval remplace if (std::is_constant_evaluated()) avec une syntaxe plus agréable et corrige d'autres problèmes. Il fonctionne cependant de la même manière.

Utiliser consteval pour forcer l'exécution de constexpr à la compilation (C++20)

L'inconvénient des fonctions consteval est qu'elles ne peuvent pas être évaluées à l'exécution, ce qui les rend moins souples que les fonctions constexpr, qui peuvent faire les deux. Il serait donc toujours utile de disposer d'un moyen pratique de forcer l'évaluation à la compilation de fonctions constexpr (même lorsque la valeur de retour est utilisée là où une expression constante n'est pas requise), afin de pouvoir imposer explicitement l'évaluation à la compilation lorsque c'est possible, et l'évaluation à l'exécution lorsque ce n'est pas le cas.

Voici un exemple qui montre comment procéder :

#include <iostream>

#define CONSTEVAL(...) [] consteval { return __VA_ARGS__; }()               // version C++20 selon Jan Scultke (https://stackoverflow.com/a/77107431/460250)
#define CONSTEVAL11(...) [] { constexpr auto _ = __VA_ARGS__; return _; }() // version C++11 selon Justin (https://stackoverflow.com/a/63637573/460250)

// Cette fonction renvoie le plus grand des deux nombres si elle s'exécute dans un contexte constant
// et le plus petit des deux nombres sinon
constexpr int compare(int x, int y) // la fonction est constexpr
{
    if (std::is_constant_evaluated())
        return (x > y ? x : y);
    else
        return (x < y ? x : y);
}

int main()
{
    int x { 5 };
    std::cout << compare(x, 6) << '\n';                  // s'exécute à l'exécution et renvoie 5

    std::cout << compare(5, 6) << '\n';                  // peut ou non s'exécuter à la compilation, mais renverra toujours 5
    std::cout << CONSTEVAL(compare(5, 6)) << '\n';       // s'exécutera toujours à la compilation et renverra 6


    return 0;
}

Cet exemple utilise une macro préprocesseur variadique (le #define, ... et __VA_ARGS__) pour définir une lambda consteval immédiatement invoquée (par les parenthèses finales).

La solution suivante devrait également fonctionner (et elle est un peu plus propre, car elle n'utilise pas de macros du préprocesseur) :

Pour les utilisateurs de gcc

Un bogue présent dans GCC 14 et versions ultérieures fait produire à l'exemple suivant un mauvais résultat dès qu'un niveau d'optimisation quelconque est activé.

#include <iostream>

// Utilise un modèle de fonction abrégé (C++20) et un type de retour `auto` pour rendre cette fonction utilisable avec n'importe quel type de valeur
// Voir l'encadré « contenu associé » ci-dessous pour plus d'informations (il n'est pas nécessaire de comprendre leur fonctionnement pour utiliser cette fonction)
// Nous avons choisi un nom en majuscules ici par cohérence avec l'exemple précédent, mais cela facilite aussi la lecture de l'appel
consteval auto CONSTEVAL(auto value)
{
    return value;
}

// Cette fonction renvoie le plus grand des deux nombres si elle s'exécute dans un contexte constant
// et le plus petit des deux nombres sinon
constexpr int compare(int x, int y) // la fonction est constexpr
{
    if (std::is_constant_evaluated())
        return (x > y ? x : y);
    else
        return (x < y ? x : y);
}

int main()
{
    std::cout << CONSTEVAL(compare(5, 6)) << '\n';       // s'exécutera à la compilation

    return 0;
}

Les arguments des fonctions consteval étant toujours évalués de manière manifestement constante, si nous appelons une fonction constexpr comme argument d'une fonction consteval, cette fonction constexpr doit être évaluée à la compilation ! La fonction consteval renvoie ensuite le résultat de la fonction constexpr comme sa propre valeur de retour, afin que l'appelant puisse l'utiliser.

Notez que la fonction consteval renvoie sa valeur par copie. Bien que cela puisse être inefficace à l'exécution (si la valeur est d'un type coûteux à copier, par exemple std::string), dans un contexte de compilation cela n'a pas d'importance, car l'appel entier à la fonction consteval sera simplement remplacé par la valeur calculée.
