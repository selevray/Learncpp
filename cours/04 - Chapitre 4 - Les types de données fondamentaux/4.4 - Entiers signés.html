4.4 — Entiers signés

Un entier (integer) est un type intégral qui peut représenter des nombres entiers positifs et négatifs, y compris 0 (par exemple -2, -1, 0, 1, 2). C++ dispose de 4 types entiers fondamentaux principaux :

| Type | Taille minimale | Remarque | | short int | 16 bits | | | int | 16 bits | Généralement 32 bits sur les architectures modernes | | long int | 32 bits | | | long long int | 64 bits | |

La principale différence entre les différents types entiers réside dans leur taille : les entiers plus grands peuvent contenir des nombres plus grands.

Un rappel

C++ garantit seulement qu'un entier aura une taille minimale donnée, et non une taille précise. Consultez la leçon 4.3 -- Taille des objets et opérateur sizeof pour savoir comment déterminer la taille de chaque type sur votre machine.

En passant…

Techniquement, les types bool et char sont considérés comme des types intégraux (car ces types stockent leurs valeurs sous forme de valeurs entières). Pour les prochaines leçons, nous laisserons ces types de côté.

Entiers signés

Dans la vie courante, lorsque nous écrivons des nombres négatifs, nous utilisons un signe moins. Par exemple, -3 signifie « moins trois ». Nous reconnaissons aussi généralement +3 comme « plus trois » (bien que la convention courante consiste à omettre le préfixe plus).

Cette propriété d'être positif, négatif ou nul s'appelle le signe du nombre.

Par défaut, les entiers en C++ sont signés (signed), ce qui signifie que le signe du nombre est stocké dans la valeur. Un entier signé peut donc représenter à la fois des nombres positifs et négatifs (ainsi que 0).

Dans cette leçon, nous nous concentrerons sur les entiers signés. Nous aborderons les entiers non signés (qui ne peuvent représenter que des nombres positifs ou nuls) dans la prochaine leçon.

Définir des entiers signés

Voici la manière préférée de définir les quatre types d'entiers signés :

short s;      // préférer "short" à "short int"
int i;
long l;       // préférer "long" à "long int"
long long ll; // préférer "long long" à "long long int"

Bien que short int, long int ou long long int fonctionnent, nous préférons les noms courts pour ces types (qui n'utilisent pas le suffixe int). En plus d'être plus long à écrire, le suffixe int rend le type plus difficile à distinguer des variables de type int. Cela peut conduire à des erreurs si le modificateur short ou long est oublié par inadvertance.

Les types entiers peuvent aussi accepter le mot-clé optionnel signed, qui, par convention, est généralement placé avant le nom du type :

signed short ss;
signed int si;
signed long sl;
signed long long sll;

Cependant, ce mot-clé ne doit pas être utilisé, car il est redondant, les entiers étant signés par défaut.

Bonne pratique

Préférez les types abrégés qui n'utilisent ni le suffixe int ni le préfixe signed.

Plages des entiers signés

Comme vous l'avez appris dans la section précédente, une variable de n bits peut contenir 2n valeurs possibles. Mais lesquelles exactement ? On appelle plage (range) l'ensemble des valeurs spécifiques qu'un type de données peut contenir. La plage d'une variable entière dépend de deux facteurs : sa taille (en bits) et le fait qu'elle soit signée ou non.

Par exemple, un entier signé de 8 bits a une plage allant de -128 à 127. Cela signifie qu'un entier signé de 8 bits peut stocker en toute sécurité n'importe quelle valeur entière comprise entre -128 et 127 (inclus).

Voici un tableau présentant la plage des entiers signés de différentes tailles :

Taille / Type Plage
8 bits signé -128 à 127
16 bits signé -32 768 à 32 767
32 bits signé -2 147 483 648 à 2 147 483 647
64 bits signé -9 223 372 036 854 775 808 à 9 223 372 036 854 775 807

Pour les amateurs de mathématiques, une variable signée de n bits a une plage allant de -(2n-1) à (2n-1)-1.

Pour les autres… utilisez le tableau. :)

Pour les lecteurs avancés

Les plages ci-dessus supposent une représentation binaire en « complément à deux » (two's complement). Cette représentation est le standard de fait des architectures modernes (car elle est plus facile à implémenter en matériel), et elle est désormais exigée par la norme C++20. Nous abordons le complément à deux dans la leçon O.4 -- Conversion d'entiers entre représentations binaire et décimale.

Dans les normes précédentes, les représentations en valeur absolue et signe et en complément à un étaient autorisées pour des raisons historiques. Ces représentations produisent des valeurs dans la plage -(2n-1-1) à +(2n-1-1).

Dépassement de capacité

Que se passe-t-il si nous essayons d'affecter la valeur 140 à un entier signé de 8 bits ? Ce nombre est en dehors de la plage qu'un entier signé de 8 bits peut contenir. Le nombre 140 nécessite 9 bits pour être représenté (8 bits de valeur absolue et 1 bit de signe), alors que nous ne disposons que de 8 bits (7 bits de valeur absolue et 1 bit de signe) dans un entier signé de 8 bits.

La norme C++20 pose cette affirmation générale : « Si, pendant l'évaluation d'une expression, le résultat n'est pas défini mathématiquement ou ne se situe pas dans la plage des valeurs représentables pour son type, le comportement est indéfini ». Familièrement, on appelle cela un dépassement de capacité (overflow).

Par conséquent, l'affectation de la valeur 140 à un entier signé de 8 bits produira un comportement indéfini (undefined behavior).

Si une opération arithmétique (comme une addition ou une multiplication) tente de créer une valeur en dehors de la plage représentable, on parle de dépassement d'entier (integer overflow) ou dépassement arithmétique (arithmetic overflow). Pour les entiers signés, un dépassement d'entier produit un comportement indéfini.

#include <iostream>

int main()
{
    // supposons des entiers de 4 octets
    int x { 2'147'483'647 }; // la valeur maximale d'un entier signé de 4 octets
    std::cout << x << '\n';

    x = x + 1; // dépassement d'entier, comportement indéfini
    std::cout << x << '\n';

    return 0;
}

Sur la machine de l'auteur, le programme ci-dessus a affiché :


2147483647
-2147483648

Cependant, comme la seconde sortie est le résultat d'un comportement indéfini, la valeur affichée peut varier sur votre machine.

Pour les lecteurs avancés

Nous expliquons ce qui se passe lors du dépassement d'entiers non signés dans la leçon 4.5 -- Entiers non signés, et pourquoi les éviter.

En général, un dépassement de capacité entraîne une perte d'information, ce qui n'est presque jamais souhaitable. Si l'on soupçonne le moindre risque qu'un objet doive stocker une valeur en dehors de sa plage, utilisez un type ayant une plage plus grande !

Division entière

Lorsque l'on divise deux entiers, C++ fonctionne comme on pourrait s'y attendre lorsque le quotient est un nombre entier :

#include <iostream>

int main()
{
    std::cout << 20 / 4 << '\n';
    return 0;
}

Cela produit le résultat attendu :


5

Mais regardons ce qui se passe lorsque la division entière donne un résultat fractionnaire :

#include <iostream>

int main()
{
    std::cout << 8 / 5 << '\n';
    return 0;
}

Cela produit un résultat peut-être inattendu :


1

Lorsqu'on effectue une division de deux entiers (appelée division entière ou integer division), C++ produit toujours un résultat entier. Comme les entiers ne peuvent pas contenir de valeurs fractionnaires, la partie fractionnaire est simplement supprimée (et non arrondie !).

En examinant de plus près l'exemple ci-dessus, 8 / 5 produit la valeur 1,6. La partie fractionnaire (0,6) est supprimée, et le résultat reste 1. Autrement dit, 8 / 5 vaut 1 avec un reste de 3. Le reste est supprimé, ce qui laisse 1.

De même, -8 / 5 donne la valeur -1.

Attention

Soyez prudent lorsque vous utilisez la division entière, car vous perdrez toute partie fractionnaire du quotient. Cependant, si c'est ce que vous souhaitez, la division entière est sûre à utiliser, car ses résultats sont prévisibles.

Si des résultats fractionnaires sont souhaités, nous montrons une méthode pour y parvenir dans la leçon 6.2 -- Opérateurs arithmétiques.

Quiz

Question n° 1

Quelle serait la plage d'un entier signé de 5 bits ?

Solution

Un nombre de 5 bits peut représenter 25 = 32 valeurs uniques. Pour un entier signé, ces valeurs sont réparties presque équitablement entre les nombres positifs et négatifs, les nombres négatifs en recevant une de plus. La plage serait donc de -16 à 15.

Autre façon de voir les choses : 1 des 5 bits est nécessaire pour stocker le signe. Il reste donc 4 bits pour la valeur absolue. Avec 4 bits, on dispose de 16 valeurs uniques. Du côté négatif, ces bits de valeur absolue représentent les valeurs -1 à -16. Du côté non négatif, ils représentent les valeurs 0 à 15. Le côté non négatif a une valeur de moins dans sa plage parce qu'il inclut 0.

Question n° 2

a) Quel est le résultat de 13 / 5 ?

Solution

13 / 5 = 2 avec un reste de 3. Le reste est supprimé, ce qui laisse 2.

b) Quel est le résultat de -13 / 5 ?

Solution

-13 / 5 = -2 avec un reste de -3. Le reste est supprimé, ce qui laisse -2.
