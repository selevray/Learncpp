4.12 — Introduction à la conversion de type et à static_cast

Conversion de type implicite

Considérez le programme suivant :

#include <iostream>

void print(double x) // print prend un paramètre de type double
{
    std::cout << x << '\n';
}

int main()
{
    print(5); // que se passe-t-il quand on passe une valeur int ?

    return 0;
}

Dans cet exemple, la fonction print() a un paramètre de type double, mais l'appelant lui transmet la valeur 5, qui est de type int. Que se passe-t-il dans ce cas ?

Dans la plupart des cas, C++ nous permet de convertir les valeurs d'un type fondamental vers un autre type fondamental. Le processus qui consiste à convertir des données d'un type vers un autre s'appelle conversion de type (type conversion). L'argument int 5 est donc converti en valeur double 5.0, puis copié dans le paramètre x. La fonction print() affiche cette valeur, ce qui produit la sortie suivante :


5

Rappel

Par défaut, les valeurs à virgule flottante dont la partie décimale est nulle s'affichent sans décimales (par exemple, 5.0 s'affiche 5).

Lorsque le compilateur effectue une conversion de type à notre place, sans que nous la demandions explicitement, on parle de conversion de type implicite (implicit type conversion). L'exemple ci-dessus l'illustre : nous ne demandons nulle part au compilateur de convertir l'entier 5 en double 5.0. La fonction attend simplement une valeur double, et nous lui passons un argument entier. Le compilateur remarque la différence de type et convertit implicitement l'entier en double.

Voici un exemple similaire, où l'argument est une variable int au lieu d'un littéral int :

#include <iostream>

void print(double x) // print prend un paramètre de type double
{
    std::cout << x << '\n';
}

int main()
{
    int y { 5 };
    print(y); // y est de type int

    return 0;
}

Le fonctionnement est identique à celui de l'exemple précédent. La valeur contenue dans la variable int y (5) est convertie en valeur double 5.0, puis copiée dans le paramètre x.

La conversion de type d'une valeur produit une nouvelle valeur

Le processus de conversion de type ne modifie pas la valeur (ni l'objet) qui fournit les données à convertir. La conversion utilise ces données comme entrée et produit un résultat converti.

Point clé

La conversion de type d'une valeur vers un autre type se comporte à peu près comme un appel de fonction dont le type de retour correspond au type cible de la conversion. Les données à convertir sont passées en argument, et le résultat converti est renvoyé (dans un objet temporaire) pour être utilisé par l'appelant.

Dans l'exemple ci-dessus, la conversion ne change pas la variable y de type int en double, et ne change pas la valeur de y de 5 en 5.0. La conversion utilise la valeur de y (5) comme entrée et renvoie un objet temporaire de type double ayant la valeur 5.0. C'est cet objet temporaire qui est ensuite passé à la fonction print.

Pour les lecteurs avancés

Certaines conversions de type avancées (par exemple celles qui impliquent const_cast ou reinterpret_cast) ne renvoient pas d'objets temporaires, mais réinterprètent le type d'une valeur ou d'un objet existant.

Avertissements liés à la conversion de type implicite

Bien que la conversion implicite suffise dans la plupart des cas où une conversion de type est nécessaire, il existe quelques situations où elle ne suffit pas. Considérez le programme suivant, proche de l'exemple précédent :

#include <iostream>

void print(int x) // print prend maintenant un paramètre de type int
{
    std::cout << x << '\n';
}

int main()
{
    print(5.5); // avertissement : on passe une valeur double

    return 0;
}

Dans ce programme, nous avons modifié print() pour qu'elle prenne un paramètre int, et l'appel à print() transmet maintenant la valeur double 5.5. Comme précédemment, le compilateur utilise une conversion implicite pour convertir la valeur double 5.5 en valeur de type int, afin de pouvoir la passer à la fonction print().

Contrairement au premier exemple, la compilation de ce programme produit un avertissement concernant une perte de données possible. Et comme l'option « traiter les avertissements comme des erreurs » est activée (c'est bien le cas, n'est-ce pas ?), le compilateur interrompt le processus de compilation.

Astuce

Vous devrez désactiver temporairement l'option « traiter les avertissements comme des erreurs » si vous voulez compiler cet exemple. Consultez la leçon 0.11 — Configuration de votre compilateur : niveaux d'avertissement et d'erreur pour plus d'informations sur ce paramètre.

Lorsqu'il est compilé et exécuté, ce programme affiche :


5

Notez que, bien que nous ayons passé la valeur 5.5, le programme affiche 5. Comme les valeurs entières ne peuvent pas contenir de fractions, lorsque la valeur double 5.5 est convertie implicitement en int, la partie fractionnaire est supprimée et seule la partie entière est conservée.

Parce que la conversion d'une valeur à virgule flottante en valeur entière supprime toute partie fractionnaire, le compilateur nous avertit lorsqu'il effectue une conversion implicite d'un type à virgule flottante vers un type entier. Cela se produit même si nous passons une valeur à virgule flottante sans partie fractionnaire, comme 5.0. Dans ce cas précis, aucune perte de valeur n'a lieu lors de la conversion vers l'entier 5, mais le compilateur peut tout de même nous avertir que la conversion est risquée.

Point clé

Certaines conversions de type (comme celle d'un char vers un int) préservent toujours la valeur convertie, alors que d'autres (comme celle d'un double vers un int) peuvent modifier la valeur pendant la conversion. Les conversions implicites dangereuses génèrent généralement un avertissement du compilateur ou, dans le cas de l'initialisation avec accolades, une erreur.

C'est l'une des principales raisons pour lesquelles l'initialisation avec accolades est la forme d'initialisation à privilégier. Elle garantit que nous n'essayons pas d'initialiser une variable avec une valeur qui perdrait de l'information lors d'une conversion de type implicite :

int main()
{
    double d { 5 }; // correct : int vers double est sans risque
    int x { 5.5 }; // erreur : double vers int n'est pas sans risque

    return 0;
}

Contenu connexe

La conversion de type implicite est un sujet riche. Nous l'étudierons plus en détail dans les prochaines leçons, à commencer par la leçon 10.1 — Conversion de type implicite.

Introduction à la conversion de type explicite avec l'opérateur static_cast

Revenons à notre dernier exemple avec print(). Que faire si nous voulions intentionnellement passer une valeur double à une fonction qui prend un entier, en sachant que la valeur convertie perdra sa partie fractionnaire ? Désactiver l'option « traiter les avertissements comme des erreurs » juste pour que le programme compile est une mauvaise idée : nous aurions alors des avertissements à chaque compilation (que nous finirions vite par ignorer), et nous risquerions de passer à côté d'avertissements concernant des problèmes plus graves.

C++ prend en charge une seconde méthode de conversion de type, appelée conversion de type explicite (explicit type conversion). Une conversion de type explicite nous permet, en tant que programmeurs, de demander explicitement au compilateur de convertir une valeur d'un type vers un autre, et nous assumons alors toute la responsabilité du résultat. Si une telle conversion entraîne une perte de valeur, le compilateur ne nous en avertira pas.

Pour effectuer une conversion explicite, nous utilisons dans la plupart des cas l'opérateur static_cast. Sa syntaxe paraît un peu étrange :


static_cast<nouveau_type>(expression)

static_cast prend en entrée la valeur d'une expression et renvoie cette valeur convertie dans le type indiqué par nouveau_type (par exemple int, bool, char, double).

Point clé

Chaque fois que vous voyez une syntaxe C++ (hors préprocesseur) qui utilise des chevrons (<>), ce qui se trouve entre les chevrons est très probablement un type. C'est la manière habituelle pour C++ de traiter le code qui a besoin d'un paramètre de type.

Mettons à jour le programme précédent avec static_cast :

#include <iostream>

void print(int x)
{
    std::cout << x << '\n';
}

int main()
{
    print( static_cast<int>(5.5) ); // convertit explicitement la valeur double 5.5 en int

    return 0;
}

Comme nous demandons maintenant explicitement la conversion de la valeur double 5.5 en valeur int, le compilateur ne génère pas d'avertissement concernant une perte de données possible (ce qui signifie que nous pouvons laisser activée l'option « traiter les avertissements comme des erreurs »).

Contenu connexe

C++ prend en charge d'autres types de transtypage (cast). Nous en reparlerons dans la prochaine leçon 10.6 — Conversion de type explicite (transtypage) et static_cast.

Utiliser static_cast pour convertir un char en int

Dans la leçon sur les caractères 4.11 — Les char, nous avons vu qu'afficher une valeur char avec std::cout affiche la valeur sous forme de caractère :

#include <iostream>

int main()
{
    char ch{ 97 }; // 97 est le code ASCII de 'a'
    std::cout << ch << '\n';

    return 0;
}

Ce programme affiche :


a

Si nous voulons afficher la valeur entière au lieu du caractère, nous pouvons utiliser static_cast pour convertir la valeur de char en int :

#include <iostream>

int main()
{
    char ch{ 97 }; // 97 est le code ASCII de 'a'
    // affiche la valeur de la variable ch en tant qu'int
    std::cout << ch << " has value " << static_cast<int>(ch) << '\n';

    return 0;
}

Ce programme affiche :


a has value 97

Il est utile de noter que l'argument de static_cast est évalué comme une expression. Lorsque nous passons une variable, cette variable est évaluée pour produire sa valeur, puis cette valeur est convertie dans le nouveau type. La variable elle-même n'est pas affectée par la conversion de sa valeur. Dans le cas précédent, la variable ch est toujours un char et contient toujours la même valeur après avoir été convertie en int.

Conversions de signe avec static_cast

Les valeurs entières signées peuvent être converties en valeurs entières non signées, et inversement, à l'aide d'un static_cast.

Si la valeur convertie peut être représentée dans le type de destination, la valeur convertie reste inchangée (seul le type change). Par exemple :

#include <iostream>

int main()
{
    unsigned int u1 { 5 };
    // Convertit la valeur de u1 en int signé
    int s1 { static_cast<int>(u1) };
    std::cout << s1 << '\n'; // affiche 5

    int s2 { 5 };
    // Convertit la valeur de s2 en unsigned int
    unsigned int u2 { static_cast<unsigned int>(s2) };
    std::cout << u2 << '\n'; // affiche 5

    return 0;
}

Ce programme affiche :


5
5

La valeur 5 appartient à la fois à l'intervalle d'un int signé et à celui d'un unsigned int. Elle peut donc être convertie vers l'un ou l'autre type sans problème.

Si la valeur convertie ne peut pas être représentée dans le type de destination :

  • Si le type de destination est non signé, la valeur subit un enveloppement modulo (modulo wrapping). Nous traitons cet enveloppement dans la leçon 4.5 — Les entiers non signés et pourquoi les éviter.
  • Si le type de destination est signé, le résultat est défini par l'implémentation avant C++20, et subit un enveloppement modulo à partir de C++20.

Voici un exemple de conversion de deux valeurs qui ne sont pas représentables dans le type de destination (en supposant des entiers de 32 bits) :

#include <iostream>

int main()
{
    int s { -1 };
    std::cout << static_cast<unsigned int>(s) << '\n'; // affiche 4294967295 

    unsigned int u { 4294967295 }; // plus grand unsigned int 32 bits
    std::cout << static_cast<int>(u) << '\n'; // défini par l'implémentation avant C++20, -1 à partir de C++20

    return 0;
}

À partir de C++20, ce programme produit le résultat suivant :


4294967295
-1

La valeur int signée -1 ne peut pas être représentée en unsigned int. Le résultat subit un enveloppement modulo vers la valeur unsigned int 4294967295.

La valeur unsigned int 4294967295 ne peut pas être représentée en int signé. Avant C++20, le résultat est défini par l'implémentation (mais vaudra probablement -1). À partir de C++20, le résultat subit un enveloppement modulo vers -1.

Avertissement

Convertir une valeur entière non signée en valeur entière signée produit un comportement défini par l'implémentation avant C++20 si la valeur convertie ne peut pas être représentée dans le type signé.

std::int8_t et std::uint8_t se comportent probablement comme des char et non comme des entiers

Comme indiqué dans la leçon 4.6 — Les entiers de largeur fixe et size_t, la plupart des compilateurs définissent et traitent std::int8_t et std::uint8_t (ainsi que les types de largeur fixe rapides et minimaux correspondants) de manière identique aux types signed char et unsigned char. Maintenant que nous avons vu ce que sont les char, nous pouvons montrer où cela peut poser problème :

#include <cstdint>
#include <iostream>

int main()
{
    std::int8_t myInt{65};      // initialise myInt avec la valeur 65
    std::cout << myInt << '\n'; // vous vous attendez probablement à un affichage de 65

    return 0;
}

Comme std::int8_t se présente comme un entier, vous pourriez croire que ce programme affiche la valeur entière 65. Pourtant, sur la plupart des systèmes, ce programme affiche A (en traitant myInt comme un signed char). Ce comportement n'est toutefois pas garanti : sur certains systèmes, le programme peut effectivement afficher 65.

Si vous voulez vous assurer qu'un objet std::int8_t ou std::uint8_t est traité comme un entier, vous pouvez convertir la valeur en entier à l'aide de static_cast :

#include <cstdint>
#include <iostream>

int main()
{
    std::int8_t myInt{65};
    std::cout << static_cast<int>(myInt) << '\n'; // affichera toujours 65

    return 0;
}

Lorsque std::int8_t est traité comme un char, la saisie depuis la console peut aussi poser problème :

#include <cstdint>
#include <iostream>

int main()
{
    std::cout << "Enter a number between 0 and 127: ";
    std::int8_t myInt{};
    std::cin >> myInt;

    std::cout << "You entered: " << static_cast<int>(myInt) << '\n';

    return 0;
}

Exemple d'exécution de ce programme :


Enter a number between 0 and 127: 35
You entered: 51

Voici ce qui se passe. Lorsque std::int8_t est traité comme un char, les routines d'entrée interprètent notre saisie comme une suite de caractères, et non comme un entier. Ainsi, lorsque nous saisissons 35, nous saisissons en réalité deux caractères, '3' et '5'. Comme un objet char ne peut contenir qu'un seul caractère, le '3' est extrait (le '5' reste dans le flux d'entrée pour une extraction ultérieure éventuelle). Comme le caractère '3' a pour code ASCII 51, la valeur 51 est stockée dans myInt, que nous affichons ensuite sous forme d'entier.

En revanche, les autres types de largeur fixe s'affichent et se saisissent toujours comme des valeurs entières.

Quiz

Question n° 1

Écrivez un court programme qui demande à l'utilisateur de saisir un seul caractère. Affichez la valeur du caractère et son code ASCII, en utilisant static_cast.

La sortie du programme doit correspondre à ce qui suit :


Enter a single character: a
You entered 'a', which has ASCII code 97.
Solution 
#include <iostream>

int main()
{
    std::cout << "Enter a single character: ";
    char c{};
    std::cin >> c;
    std::cout << "You entered '" << c << "', which has ASCII code " << static_cast<int>(c) << ".\n";

    return 0;
}

Question n° 2

Modifiez le programme de la question n° 1 pour utiliser une conversion de type implicite au lieu de static_cast. Combien de façons différentes pouvez-vous imaginer pour le faire ?

Remarque : il est préférable de privilégier les conversions explicites aux conversions implicites. N'appliquez donc pas cela dans de vrais programmes : il s'agit simplement de vérifier votre compréhension des endroits où des conversions implicites peuvent se produire.

Solution

Il existe plusieurs façons simples de procéder.

Premièrement, nous pouvons créer une variable int et l'initialiser avec notre valeur char. La conversion implicite a alors lieu à l'initialisation.

#include <iostream>

int main()
{
    std::cout << "Enter a single character: ";
    char c{};
    std::cin >> c;

    int ascii{ c };
    std::cout << "You entered '" << c << "', which has ASCII code " << ascii << ".\n";

    return 0;
}

Nous pouvons aussi utiliser une fonction qui renvoie la valeur char sous forme d'int. La conversion implicite a alors lieu au moment du retour.

#include <iostream>

int charAsInt(char c)
{
    return c;
}

int main()
{
    std::cout << "Enter a single character: ";
    char c{};
    std::cin >> c;

    std::cout << "You entered '" << c << "', which has ASCII code " << charAsInt(c) << ".\n";

    return 0;
}

Nous pouvons également utiliser une fonction et faire en sorte que la conversion implicite ait lieu lors de la copie de l'argument dans le paramètre de la fonction :

#include <iostream>

int getInt(int c)
{
    return c;
}

int main()
{
    std::cout << "Enter a single character: ";
    char c{};
    std::cin >> c;

    std::cout << "You entered '" << c << "', which has ASCII code " << getInt(c) << ".\n";

    return 0;
}
