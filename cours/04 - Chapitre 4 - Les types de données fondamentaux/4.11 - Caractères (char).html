4.11 — Caractères (char)

Jusqu'à présent, les types de données fondamentaux que nous avons vus servaient à stocker des nombres (entiers et nombres à virgule flottante) ou des valeurs booléennes (vrai/faux). Mais que faire si nous voulons stocker des lettres ou des signes de ponctuation ?

#include <iostream>

int main()
{
    std::cout << "Would you like a burrito? (y/n)";

    // We want the user to enter a 'y' or 'n' character
    // How do we do this?

    return 0;
}

Le type de données char a été conçu pour contenir un seul caractère. Un caractère peut être une lettre, un chiffre, un symbole ou un espace blanc.

Le type char est un type entier, ce qui signifie que la valeur sous-jacente est stockée sous forme d'entier. De même que la valeur booléenne 0 est interprétée comme false et qu'une valeur non nulle est interprétée comme true, l'entier stocké dans une variable char est interprété comme un caractère ASCII.

ASCII est l'acronyme de American Standard Code for Information Interchange. Cette norme définit une manière particulière de représenter les caractères anglais (ainsi que quelques autres symboles) par des nombres entre 0 et 127 (appelés code ASCII ou point de code). Par exemple, le code ASCII 97 est interprété comme le caractère « a ».

Les littéraux de caractères sont toujours placés entre apostrophes (par exemple 'g', '1', ' ').

Les codes 0 à 31 et 127 sont appelés caractères non imprimables. Ces codes ont été conçus pour piloter des périphériques tels que les imprimantes (par exemple pour indiquer à l'imprimante comment déplacer la tête d'impression). La plupart d'entre eux sont aujourd'hui obsolètes. Si vous essayez d'afficher ces caractères, le résultat dépend de votre système d'exploitation (vous pouvez obtenir des caractères ressemblant à des emojis).

Les codes 32 à 126 sont appelés caractères imprimables. Ils représentent les lettres, les chiffres et la ponctuation que la plupart des ordinateurs utilisent pour afficher un texte anglais de base.

Si vous essayez d'afficher un caractère dont la valeur est en dehors de la plage ASCII, le résultat dépend également de votre système d'exploitation.

Initialisation des char

Vous pouvez initialiser des variables char à l'aide de littéraux de caractères :

char ch2{ 'a' }; // initialize with code point for 'a' (stored as integer 97) (preferred)

Vous pouvez aussi initialiser des char avec des entiers, mais cela doit être évité autant que possible :

char ch1{ 97 }; // initialize with integer 97 ('a') (not preferred)

Avertissement

Prenez garde à ne pas confondre les chiffres en tant que caractères avec les nombres entiers. Les deux initialisations suivantes ne sont pas identiques :

char ch{5}; // initialize with integer 5 (stored as integer 5)
char ch{'5'}; // initialize with code point for '5' (stored as integer 53)

Les chiffres sous forme de caractères servent à représenter des nombres sous forme de texte, et non des nombres sur lesquels effectuer des opérations mathématiques.

Affichage des char

Lorsque vous utilisez std::cout pour afficher un char, std::cout affiche la variable char comme un caractère ASCII :

#include <iostream>

int main()
{
    char ch1{ 'a' }; // (preferred)
    std::cout << ch1; // cout prints character 'a'

    char ch2{ 98 }; // code point for 'b' (not preferred)
    std::cout << ch2; // cout prints a character ('b')


    return 0;
}

Cela produit le résultat :


ab

Nous pouvons aussi afficher directement des littéraux de caractères :

std::cout << 'c';

Cela produit le résultat :


c

Saisie de char

Le programme suivant demande à l'utilisateur de saisir un caractère, puis affiche ce caractère :

#include <iostream>

int main()
{
    std::cout << "Input a keyboard character: ";

    char ch{};
    std::cin >> ch;
    std::cout << "You entered: " << ch << '\n';

    return 0;
}

Voici la sortie d'une exécution :


Input a keyboard character: q
You entered: q

Notez que std::cin vous permet de saisir plusieurs caractères. Cependant, la variable ch ne peut contenir qu'un seul caractère. Par conséquent, seul le premier caractère saisi est extrait dans la variable ch. Le reste de la saisie de l'utilisateur reste dans le tampon d'entrée utilisé par std::cin, et peut être extrait par des appels ultérieurs à std::cin.

Vous pouvez observer ce comportement dans l'exemple suivant :

#include <iostream>

int main()
{
    std::cout << "Input a keyboard character: "; // assume the user enters "abcd" (without quotes)

    char ch{};
    std::cin >> ch; // ch = 'a', "bcd" is left queued.
    std::cout << "You entered: " << ch << '\n';

    // Note: The following cin doesn't ask the user for input, it grabs queued input!
    std::cin >> ch; // ch = 'b', "cd" is left queued.
    std::cout << "You entered: " << ch << '\n';

    return 0;
}


Input a keyboard character: abcd
You entered: a
You entered: b

Si vous souhaitez lire plusieurs caractères à la fois (par exemple pour lire un nom, un mot ou une phrase), vous devrez utiliser une chaîne de caractères (string) plutôt qu'un char. Une chaîne est une suite de caractères consécutifs (elle peut donc contenir plusieurs symboles). Nous en parlerons dans la leçon à venir (5.7 -- Introduction à std::string).

Extraction des caractères d'espacement

Comme l'extraction ignore les espaces blancs en début de saisie, cela peut conduire à des résultats inattendus lorsque l'on tente d'extraire des caractères d'espacement dans une variable char :

#include <iostream>

int main()
{
    std::cout << "Input a keyboard character: "; // assume the user enters "a b" (without quotes)

    char ch{};
    std::cin >> ch; // extracts a, leaves " b\n" in stream
    std::cout << "You entered: " << ch << '\n';

    std::cin >> ch; // skips leading whitespace (the space), extracts b, leaves "\n" in stream
    std::cout << "You entered: " << ch << '\n';

    return 0;
}


Input a keyboard character: a b
You entered: a
You entered: b

Dans l'exemple ci-dessus, nous pouvions nous attendre à extraire l'espace, mais comme les espaces blancs en début de saisie sont ignorés, nous avons extrait le caractère b à la place.

Une façon simple de résoudre ce problème consiste à utiliser la fonction std::cin.get() pour effectuer l'extraction, car cette fonction n'ignore pas les espaces blancs en début de saisie :

#include <iostream>

int main()
{
    std::cout << "Input a keyboard character: "; // assume the user enters "a b" (without quotes)

    char ch{};
    std::cin.get(ch); // extracts a, leaves " b\n" in stream
    std::cout << "You entered: " << ch << '\n';

    std::cin.get(ch); // extracts space, leaves "b\n" in stream
    std::cout << "You entered: " << ch << '\n';

    return 0;
}


Input a keyboard character: a b
You entered: a
You entered:

Taille, plage et signe par défaut du type char

Le C++ définit le type char comme ayant toujours une taille de 1 octet. Par défaut, un char peut être signé ou non signé (bien qu'il soit généralement signé). Si vous utilisez des char pour contenir des caractères ASCII, vous n'avez pas besoin de préciser le signe (car les char signés et non signés peuvent tous deux contenir des valeurs entre 0 et 127).

Si vous utilisez un char pour stocker de petits entiers (ce que vous ne devriez pas faire, sauf si vous optimisez explicitement l'espace mémoire), vous devez toujours préciser s'il est signé ou non signé. Un char signé peut contenir un nombre entre -128 et 127. Un char non signé peut contenir un nombre entre 0 et 255.

Séquences d'échappement

Il existe certaines suites de caractères en C++ qui ont une signification particulière. Ces caractères sont appelés séquences d'échappement (escape sequences). Une séquence d'échappement commence par un caractère « \ » (antislash), suivi d'une lettre ou d'un chiffre.

Vous avez déjà vu la séquence d'échappement la plus courante : '\n', qui permet d'afficher un saut de ligne :

#include <iostream>

int main()
{
    int x { 5 };
    std::cout << "The value of x is: " << x << '\n'; // standalone \n goes in single quotes
    std::cout << "First line\nSecond line\n";        // \n can be embedded in double quotes
    return 0;
}

Ceci affiche :


The value of x is: 5
First line
Second line

Une autre séquence d'échappement couramment utilisée est '\t', qui insère une tabulation horizontale :

#include <iostream>

int main()
{
    std::cout << "First part\tSecond part";
    return 0;
}

Ce qui affiche :


First part  Second part

Trois autres séquences d'échappement notables sont :
\’ affiche une apostrophe
\” affiche un guillemet
\ affiche un antislash

Voici un tableau de toutes les séquences d'échappement :

Nom Symbole Signification
Alerte \a Émet une alerte, comme un bip
Retour arrière \b Déplace le curseur d'un espace vers l'arrière
Saut de page \f Déplace le curseur à la page logique suivante
Saut de ligne \n Déplace le curseur à la ligne suivante
Retour chariot \r Déplace le curseur au début de la ligne
Tabulation horizontale \t Affiche une tabulation horizontale
Tabulation verticale \v Affiche une tabulation verticale
Apostrophe \’ Affiche une apostrophe
Guillemet \” Affiche un guillemet
Antislash \ Affiche un antislash.
Point d'interrogation \? Affiche un point d'interrogation. Plus pertinent aujourd'hui : vous pouvez écrire les points d'interrogation sans échappement.
Nombre octal (number) Se traduit par le caractère représenté en octal

Voici quelques exemples :

#include <iostream>

int main()
{
    std::cout << "\"This is quoted text\"\n";
    std::cout << "This string contains a single backslash \\\n";
    std::cout << "6F in hex is char '\x6F'\n";
    return 0;
}

Affiche :


"This is quoted text"
This string contains a single backslash \
6F in hex is char 'o'

Avertissement

Les séquences d'échappement commencent par un antislash (), et non par une barre oblique (/). Si vous utilisez une barre oblique par erreur, le programme peut tout de même compiler, mais il ne produira pas le résultat souhaité.

Saut de ligne (\n) vs std::endl

Nous abordons ce sujet dans la leçon 1.5 -- Introduction à iostream : cout, cin et endl.

Quelle est la différence entre mettre des symboles entre apostrophes et entre guillemets ?

Un texte placé entre apostrophes est traité comme un littéral de type char, qui représente un seul caractère. Par exemple, 'a' représente le caractère a, '+' représente le caractère du signe plus, '5' représente le caractère 5 (et non le nombre 5), et '\n' représente le caractère de saut de ligne.

Un texte placé entre guillemets (par exemple « Hello, world! ») est traité comme un littéral de chaîne de style C, qui peut contenir plusieurs caractères. Nous étudierons les chaînes dans la leçon 5.2 -- Littéraux.

Bonne pratique

Un caractère isolé doit généralement être placé entre apostrophes, et non entre guillemets (par exemple 't' ou '\n', et non "t" ou "\n"). Une exception possible concerne l'affichage, où il peut être préférable de mettre tout entre guillemets par souci de cohérence (voir la leçon 1.5 -- Introduction à iostream : cout, cin et endl).

Éviter les littéraux multicaractères

Pour des raisons de compatibilité ascendante, de nombreux compilateurs C++ acceptent les littéraux multicaractères (multicharacter literals), c'est-à-dire des littéraux de caractères contenant plusieurs caractères (par exemple '56'). Lorsqu'ils sont pris en charge, ces littéraux ont une valeur définie par l'implémentation (ce qui signifie qu'elle varie selon le compilateur). Comme ils ne font pas partie de la norme C++ et que leur valeur n'est pas strictement définie, les littéraux multicaractères doivent être évités.

Bonne pratique

Évitez les littéraux multicaractères (par exemple '56').

La prise en charge des littéraux multicaractères pose souvent problème aux programmeurs débutants, qui ne se souviennent pas si les séquences d'échappement utilisent des barres obliques ou des antislashs :

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

int main()
{
    std::cout << add(1, 2) << '/n'; // we used a forward slash instead of a backslash here

    return 0;
}

Le programmeur s'attend à ce que ce programme affiche la valeur 3 suivie d'un saut de ligne. Or, sur la machine de l'auteur, il affiche en réalité ceci :


312142

Le problème vient du fait que le programmeur a écrit par erreur '/n' (un littéral multicaractère composé d'une barre oblique et du caractère 'n') au lieu de '\n' (la séquence d'échappement du saut de ligne). Le programme affiche d'abord correctement 3 (le résultat de add(1, 2)). Puis il affiche la valeur du littéral multicaractère '/n', qui, sur la machine de l'auteur, avait la valeur définie par l'implémentation 12142.

Avertissement

Assurez-vous que vos sauts de ligne utilisent la séquence d'échappement '\n', et non le littéral multicaractère '/n'.

Point clé

Notez que si nous avions mis la sortie "/n" entre guillemets, le programme aurait affiché 3/n, ce qui reste faux, mais beaucoup moins déroutant.

Voici un autre exemple. Partons du programme suivant :

#include <iostream>

int main()
{
    int x { 5 };
    std::cout << "The value of x is " << x << '\n'; 

    return 0;
}

Ce programme affiche exactement ce que vous attendez :


The value of x is 5

Mais ce résultat n'est pas assez passionnant. Nous décidons donc d'ajouter un point d'exclamation avant le saut de ligne :

#include <iostream>

int main()
{
    int x { 5 };
    std::cout << "The value of x is " << x << '!\n'; // added exclamation point

    return 0;
}

Nous nous attendons à ce qu'il affiche :


The value of x is 5!

Comme '!\n' est un littéral multicaractère, sur la machine de l'auteur, le programme a en réalité affiché :


The value of x is 58458

Non seulement c'est incorrect, mais cela peut être difficile à déboguer, car vous êtes susceptible de supposer que x a une mauvaise valeur.

Utiliser des guillemets (au lieu des apostrophes) pour afficher des littéraux de caractères permet soit de repérer plus facilement ce type de problème, soit de l'éviter complètement.

Qu'en est-il des autres types de caractères : wchar_t, char8_t, char16_t et char32_t ?

De même que l'ASCII associe les entiers 0 à 127 aux caractères de l'anglais américain, d'autres normes d'encodage de caractères existent pour associer des entiers (de tailles variables) à des caractères d'autres langues. La norme la plus connue au-delà de l'ASCII est Unicode, qui associe plus de 144 000 entiers à des caractères de nombreuses langues différentes. Comme Unicode contient autant de points de code, un seul point de code Unicode nécessite 32 bits pour représenter un caractère (on parle d'UTF-32). Cependant, les caractères Unicode peuvent aussi être encodés à l'aide de plusieurs caractères de 16 ou 8 bits (on parle respectivement d'UTF-16 et d'UTF-8).

char16_t et char32_t ont été ajoutés en C++11 pour offrir un support explicite des caractères Unicode de 16 et 32 bits. Ces types char ont la même taille que std::uint_least16_t et std::uint_least32_t respectivement (mais ce sont des types distincts). char8_t a été ajouté en C++20 pour prendre en charge l'Unicode sur 8 bits (UTF-8). C'est un type distinct qui utilise la même représentation que unsigned char.

Vous n'aurez pas besoin d'utiliser char8_t, char16_t ou char32_t, sauf si vous prévoyez de rendre votre programme compatible avec Unicode. wchar_t doit être évité dans presque tous les cas (sauf lors d'une interaction avec l'API Windows), car sa taille est définie par l'implémentation.

Unicode et la localisation sortent généralement du cadre de ces tutoriels, nous ne les approfondirons donc pas. En attendant, vous ne devriez utiliser que des caractères ASCII lorsque vous manipulez des caractères (et des chaînes). L'utilisation de caractères issus d'autres jeux de caractères peut entraîner un affichage incorrect.
