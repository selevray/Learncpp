13.13 — Modèles de classes

Dans la leçon 11.6 -- Modèles de fonctions, nous avons présenté le problème qui consiste à devoir créer une fonction surchargée distincte pour chaque ensemble de types avec lequel nous voulons travailler :

#include <iostream>

// fonction qui calcule le plus grand de deux valeurs int
int max(int x, int y)
{
    return (x < y) ? y : x;
}

// fonction presque identique pour calculer le plus grand de deux valeurs double
// la seule différence réside dans l'information de type
double max(double x, double y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(5, 6);     // appelle max(int, int)
    std::cout << '\n';
    std::cout << max(1.2, 3.4); // appelle max(double, double)

    return 0;
}

La solution consiste à créer un modèle de fonction que le compilateur peut utiliser pour instancier des fonctions normales pour n'importe quel ensemble de types dont nous avons besoin :

#include <iostream>

// un seul modèle de fonction pour max
template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(5, 6);     // instancie et appelle max<int>(int, int)
    std::cout << '\n';
    std::cout << max(1.2, 3.4); // instancie et appelle max<double>(double, double)

    return 0;
}

Contenu associé

Nous expliquons le fonctionnement de l'instanciation des modèles de fonctions dans la leçon 11.7 -- Instanciation des modèles de fonctions.

Les types agrégats posent des problèmes similaires

Nous rencontrons des difficultés similaires avec les types agrégats (structures, classes, unions et tableaux).

Par exemple, supposons que nous écrivions un programme qui doit manipuler des paires de valeurs int et déterminer laquelle des deux est la plus grande. Nous pourrions écrire un programme comme celui-ci :

#include <iostream>

struct Pair
{
    int first{};
    int second{};
};

constexpr int max(Pair p) // passage par valeur car Pair est petite
{
    return (p.first < p.second ? p.second : p.first);
}

int main()
{
    Pair p1{ 5, 6 };
    std::cout << max(p1) << " is larger\n";

    return 0;
}

Plus tard, nous découvrons que nous avons aussi besoin de paires de valeurs double. Nous modifions donc notre programme comme suit :

#include <iostream>

struct Pair
{
    int first{};
    int second{};
};

struct Pair // erreur de compilation : redéfinition erronée de Pair
{
    double first{};
    double second{};
};

constexpr int max(Pair p)
{
    return (p.first < p.second ? p.second : p.first);
}

constexpr double max(Pair p) // erreur de compilation : une fonction surchargée ne peut pas différer uniquement par le type de retour
{
    return (p.first < p.second ? p.second : p.first);
}

int main()
{
    Pair p1{ 5, 6 };
    std::cout << max(p1) << " is larger\n";

    Pair p2{ 1.2, 3.4 };
    std::cout << max(p2) << " is larger\n";

    return 0;
}

Malheureusement, ce programme ne compile pas et présente plusieurs problèmes qu'il faut résoudre.

Premièrement, contrairement aux fonctions, les définitions de types ne peuvent pas être surchargées. Le compilateur traitera la seconde définition de Pair comme une redéclaration erronée de la première. Deuxièmement, bien que les fonctions puissent être surchargées, nos fonctions max(Pair) ne diffèrent que par leur type de retour, et des fonctions surchargées ne peuvent pas être distinguées uniquement par leur type de retour. Troisièmement, il y a beaucoup de redondance : chaque structure Pair est identique (hormis le type de données), de même que nos fonctions max(Pair) (hormis le type de retour).

Nous pourrions résoudre les deux premiers problèmes en donnant à nos structures Pair des noms différents (par exemple PairInt et PairDouble). Mais il faudrait alors retenir notre convention de nommage, et recopier un bloc de code pour chaque type de paire supplémentaire, ce qui ne résout pas le problème de redondance.

Heureusement, nous pouvons faire mieux.

Note de l'auteur

Avant de continuer, veuillez relire les leçons 11.6 -- Modèles de fonctions et 11.7 -- Instanciation des modèles de fonctions si vous n'êtes pas sûr du fonctionnement des modèles de fonctions, des types templates ou de l'instanciation des modèles de fonctions.

Modèles de classes

Tout comme un modèle de fonction est une définition servant à instancier des fonctions, un modèle de classe (class template) est une définition servant à instancier des types classes.

Rappel

Un « type classe » est un type structure, classe ou union. Bien que nous illustrions les « modèles de classes » avec des structures par souci de simplicité, tout ce qui est présenté ici s'applique aussi bien aux classes.

Pour rappel, voici la définition de notre structure de paire d'int :

struct Pair
{
    int first{};
    int second{};
};

Réécrivons notre classe de paire sous forme de modèle de classe :

#include <iostream>

template <typename T>
struct Pair
{
    T first{};
    T second{};
};

int main()
{
    Pair<int> p1{ 5, 6 };        // instancie Pair<int> et crée l'objet p1
    std::cout << p1.first << ' ' << p1.second << '\n';

    Pair<double> p2{ 1.2, 3.4 }; // instancie Pair<double> et crée l'objet p2
    std::cout << p2.first << ' ' << p2.second << '\n';

    Pair<double> p3{ 7.8, 9.0 }; // crée l'objet p3 en utilisant la définition précédente de Pair<double>
    std::cout << p3.first << ' ' << p3.second << '\n';

    return 0;
}

Comme pour les modèles de fonctions, la définition d'un modèle de classe commence par une déclaration de paramètres template. Nous commençons par le mot-clé template. Ensuite, nous indiquons entre chevrons (<>) tous les types templates que notre modèle de classe utilisera. Pour chaque type template nécessaire, nous utilisons le mot-clé typename (à privilégier) ou class (moins recommandé), suivi du nom du type template (par exemple T). Ici, comme les deux membres ont le même type, un seul type template suffit.

Ensuite, nous définissons notre structure comme d'habitude, si ce n'est que nous pouvons utiliser notre type template (T) partout où nous voulons un type templaté qui sera remplacé par un type réel plus tard. C'est tout ! La définition du modèle de classe est terminée.

Dans main, nous pouvons instancier des objets Pair avec les types de notre choix. Tout d'abord, nous instancions un objet de type Pair<int>. Comme la définition de type Pair<int> n'existe pas encore, le compilateur utilise le modèle de classe pour instancier une définition de type structure nommée Pair<int>, dans laquelle toutes les occurrences du type template T sont remplacées par le type int.

Ensuite, nous instancions un objet de type Pair<double>, ce qui instancie une définition de structure nommée Pair<double> où T est remplacé par double. Pour p3, Pair<double> a déjà été instancié, donc le compilateur utilise la définition de type précédente.

Voici le même exemple que ci-dessus, montrant ce que le compilateur compile réellement une fois toutes les instanciations de modèles effectuées :

#include <iostream>

// Une déclaration pour notre modèle de classe Pair
// (la définition n'est plus nécessaire puisqu'elle n'est pas utilisée)
template <typename T>
struct Pair;

// Définit explicitement à quoi ressemble Pair<int>
template <> // indique au compilateur qu'il s'agit d'un type template sans paramètres template
struct Pair<int>
{
    int first{};
    int second{};
};

// Définit explicitement à quoi ressemble Pair<double>
template <> // indique au compilateur qu'il s'agit d'un type template sans paramètres template
struct Pair<double>
{
    double first{};
    double second{};
};

int main()
{
    Pair<int> p1{ 5, 6 };        // instancie Pair<int> et crée l'objet p1
    std::cout << p1.first << ' ' << p1.second << '\n';

    Pair<double> p2{ 1.2, 3.4 }; // instancie Pair<double> et crée l'objet p2
    std::cout << p2.first << ' ' << p2.second << '\n';

    Pair<double> p3{ 7.8, 9.0 }; // crée l'objet p3 en utilisant la définition précédente de Pair<double>
    std::cout << p3.first << ' ' << p3.second << '\n';

    return 0;
}

Vous pouvez compiler directement cet exemple et constater qu'il fonctionne comme prévu !

Pour les lecteurs avancés

L'exemple ci-dessus fait appel à une fonctionnalité appelée spécialisation de modèle de classe (abordée dans la leçon future 26.4 -- Spécialisation de modèles de classes). La connaissance du fonctionnement de cette fonctionnalité n'est pas requise à ce stade.

Utiliser notre modèle de classe dans une fonction

Revenons maintenant au problème consistant à rendre notre fonction max() utilisable avec différents types. Comme le compilateur traite Pair<int> et Pair<double> comme des types distincts, nous pourrions utiliser des fonctions surchargées distinguées par le type de paramètre :

constexpr int max(Pair<int> p)
{
    return (p.first < p.second ? p.second : p.first);
}

constexpr double max(Pair<double> p) // correct : fonction surchargée distinguée par le type de paramètre
{
    return (p.first < p.second ? p.second : p.first);
}

Bien que ce code compile, il ne résout pas le problème de redondance. Ce que nous voulons vraiment, c'est une fonction qui accepte une paire de n'importe quel type. Autrement dit, nous voulons une fonction qui prend un paramètre de type Pair<T>, où T est un paramètre de type template. Et cela nécessite un modèle de fonction !

Voici un exemple complet, où max() est implémentée sous forme de modèle de fonction :

#include <iostream>

template <typename T>
struct Pair
{
    T first{};
    T second{};
};

template <typename T>
constexpr T max(Pair<T> p)
{
    return (p.first < p.second ? p.second : p.first);
}

int main()
{
    Pair<int> p1{ 5, 6 };
    std::cout << max<int>(p1) << " is larger\n"; // appel explicite à max<int>

    Pair<double> p2{ 1.2, 3.4 };
    std::cout << max(p2) << " is larger\n"; // appel à max<double> par déduction d'argument template (à privilégier)

    return 0;
}

Le modèle de fonction max() est assez simple. Comme nous voulons passer un Pair<T>, le compilateur doit savoir ce qu'est T. Nous commençons donc la fonction par une déclaration de paramètre template qui définit le type template T. Nous pouvons alors utiliser T à la fois comme type de retour et comme type template de Pair<T>.

Lorsque la fonction max() est appelée avec un argument Pair<int>, le compilateur instancie la fonction int max<int>(Pair<int>) à partir du modèle de fonction, où le type template T est remplacé par int. L'extrait suivant montre ce que le compilateur instancie réellement dans ce cas :

template <>
constexpr int max(Pair<int> p)
{
    return (p.first < p.second ? p.second : p.first);
}

Comme pour tout appel à un modèle de fonction, nous pouvons être explicites sur l'argument de type template (par exemple max<int>(p1)) ou être implicites (par exemple max(p2)) et laisser le compilateur déduire l'argument de type template grâce à la déduction d'arguments template.

Modèles de classes avec des membres de type template et de type non template

Un modèle de classe peut avoir certains membres utilisant un type template et d'autres utilisant un type normal (non template). Par exemple :

template <typename T>
struct Foo
{
    T first{};    // first aura le type avec lequel T est remplacé
    int second{}; // second aura toujours le type int, quel que soit le type remplaçant T
};

Cela fonctionne exactement comme vous vous y attendez : first sera du type template T, et second sera toujours un int.

Modèles de classes avec plusieurs types templates

Un modèle de classe peut aussi avoir plusieurs types templates. Par exemple, si nous voulons que les deux membres de notre classe Pair puissent avoir des types différents, nous pouvons définir notre modèle de classe Pair avec deux types templates :

#include <iostream>

template <typename T, typename U>
struct Pair
{
    T first{};
    U second{};
};

template <typename T, typename U>
void print(Pair<T, U> p)
{
    std::cout << '[' << p.first << ", " << p.second << ']';
}

int main()
{
    Pair<int, double> p1{ 1, 2.3 }; // une paire contenant un int et un double
    Pair<double, int> p2{ 4.5, 6 }; // une paire contenant un double et un int
    Pair<int, int> p3{ 7, 8 };      // une paire contenant deux int

    print(p2);

    return 0;
}

Pour définir plusieurs types templates, dans la déclaration de paramètres template, nous séparons chacun des types souhaités par une virgule. Dans l'exemple ci-dessus, nous définissons deux types templates différents, l'un nommé T et l'autre nommé U. Les arguments de type template réels pour T et U peuvent être différents (comme pour p1 et p2 ci-dessus) ou identiques (comme pour p3).

Faire fonctionner un modèle de fonction avec plusieurs types de classes

Considérons la fonction template print() de l'exemple précédent :

template <typename T, typename U>
void print(Pair<T, U> p)
{
    std::cout << '[' << p.first << ", " << p.second << ']';
}

Comme nous avons explicitement défini le paramètre de fonction comme un Pair<T, U>, seuls les arguments de type Pair<T, U> (ou ceux qui peuvent être convertis en Pair<T, U>) correspondront. C'est idéal si nous voulons appeler notre fonction uniquement avec un argument Pair<T, U>.

Dans certains cas, nous pouvons écrire des modèles de fonctions que nous voulons utiliser avec n'importe quel type qui compile correctement. Pour cela, il suffit d'utiliser à la place un paramètre de type template comme paramètre de fonction.

Par exemple :

#include <iostream>

template <typename T, typename U>
struct Pair
{
    T first{};
    U second{};
};

struct Point
{
    int first{};
    int second{};
};

template <typename T>
void print(T p) // le paramètre de type template correspondra à n'importe quel type
{
    std::cout << '[' << p.first << ", " << p.second << ']'; // ne compilera que si le type possède des membres first et second
}

int main()
{
    Pair<double, int> p1{ 4.5, 6 };
    print(p1); // correspond à print(Pair<double, int>)

    std::cout << '\n';

    Point p2 { 7, 8 };
    print(p2); // correspond à print(Point)

    std::cout << '\n';

    return 0;
}

Dans l'exemple ci-dessus, nous avons réécrit print() avec un seul paramètre de type template (T), qui correspond à n'importe quel type. Le corps de la fonction compilera avec succès pour tout type classe possédant des membres first et second. Nous le démontrons en appelant print() avec un objet de type Pair<double, int>, puis avec un objet de type Point.

Un cas peut prêter à confusion. Considérons la version suivante de print() :

template <typename T, typename U>
struct Pair // définit un type classe nommé Pair
{
    T first{};
    U second{};
};

template <typename Pair> // définit un paramètre de type template nommé Pair (masque le type classe Pair)
void print(Pair p)       // ceci désigne le paramètre template Pair, et non le type classe Pair
{
    std::cout << '[' << p.first << ", " << p.second << ']';
}

On pourrait penser que cette fonction ne correspondra qu'à un argument de type classe Pair. Pourtant, cette version de print() est fonctionnellement identique à la version précédente dont le paramètre template se nommait T, et elle correspondra à n'importe quel type. Le problème vient de ce que, lorsque nous définissons Pair comme paramètre de type template, il masque les autres utilisations du nom Pair dans la portée globale. Ainsi, à l'intérieur du modèle de fonction, Pair désigne le paramètre template Pair et non le type classe Pair. Et comme un paramètre de type template correspond à n'importe quel type, ce Pair correspond à n'importe quel type d'argument, et pas seulement à ceux de type classe Pair !

C'est une bonne raison de s'en tenir à des noms de paramètres template simples, comme T, U ou N, qui risquent moins de masquer le nom d'un type classe.

std::pair

Les données par paires étant courantes, la bibliothèque standard C++ contient un modèle de classe nommé std::pair (dans l'en-tête <utility>), défini de manière identique à notre modèle de classe Pair à plusieurs types templates de la section précédente. En fait, nous pouvons remplacer la structure pair que nous avons développée par std::pair :

#include <iostream>
#include <utility>

template <typename T, typename U>
void print(std::pair<T, U> p)
{
    // les membres de std::pair portent les noms prédéfinis `first` et `second`
    std::cout << '[' << p.first << ", " << p.second << ']';
}

int main()
{
    std::pair<int, double> p1{ 1, 2.3 }; // une paire contenant un int et un double
    std::pair<double, int> p2{ 4.5, 6 }; // une paire contenant un double et un int
    std::pair<int, int> p3{ 7, 8 };      // une paire contenant deux int

    print(p2);

    return 0;
}

Nous avons développé notre propre classe Pair dans cette leçon pour montrer comment les choses fonctionnent, mais dans du code réel, vous devriez privilégier std::pair plutôt que d'écrire la vôtre.

Utiliser des modèles de classes dans plusieurs fichiers

Tout comme les modèles de fonctions, les modèles de classes sont généralement définis dans des fichiers d'en-tête afin de pouvoir être inclus dans tout fichier de code qui en a besoin. Les définitions de modèles et les définitions de types sont toutes deux exemptées de la règle de la définition unique (ODR), donc cela ne pose pas de problème :

pair.h :

#ifndef PAIR_H
#define PAIR_H

template <typename T>
struct Pair
{
    T first{};
    T second{};
};

template <typename T>
constexpr T max(Pair<T> p)
{
    return (p.first < p.second ? p.second : p.first);
}

#endif

foo.cpp :

#include "pair.h"
#include <iostream>

void foo()
{
    Pair<int> p1{ 1, 2 };
    std::cout << max(p1) << " is larger\n";
}

main.cpp :

#include "pair.h"
#include <iostream>

void foo(); // déclaration anticipée de la fonction foo()

int main()
{
    Pair<double> p2 { 3.4, 5.6 };
    std::cout << max(p2) << " is larger\n";

    foo();

    return 0;
}
