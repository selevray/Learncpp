13.1 — Introduction aux types définis par le programme (types définis par l'utilisateur)

Comme les types fondamentaux sont définis dans le cœur du langage C++, ils sont disponibles immédiatement. Par exemple, si nous voulons définir une variable de type int ou double, il nous suffit de le faire :

int x; // définit une variable de type fondamental 'int'
double d; // définit une variable de type fondamental 'double'

Cela vaut aussi pour les types composés qui sont de simples extensions des types fondamentaux (y compris les fonctions, pointeurs, références et tableaux) :

void fcn(int) {}; // définit une fonction de type void(int)
int* ptr; // définit une variable de type composé 'pointeur vers int'
int& ref { x }; // définit une variable de type composé 'référence vers int' (initialisée avec x)
int arr[5]; // définit un tableau de 5 entiers de type int[5] (nous verrons cela dans un chapitre ultérieur)

Cela fonctionne parce que le langage C++ connaît déjà la signification de ces noms de types (et symboles) : nous n'avons besoin de fournir ni d'importer aucune définition.

En revanche, considérons le cas d'un alias de type (présenté dans la leçon 10.7 -- Typedefs et alias de types), qui permet de définir un nouveau nom pour un type existant. Comme un alias de type introduit un nouvel identifiant dans le programme, il doit être défini avant d'être utilisé :

#include <iostream>

using Length = int; // définit un alias de type avec l'identifiant 'Length'

int main()
{
    Length x { 5 }; // nous pouvons utiliser 'Length' ici car nous l'avons défini plus haut
    std::cout << x << '\n';

    return 0;
}

Si nous omettions la définition de Length, le compilateur ne saurait pas ce qu'est un Length et signalerait une erreur lorsque nous tenterions de définir une variable de ce type. La définition de Length ne crée pas d'objet : elle indique seulement au compilateur ce qu'est un Length, afin qu'il puisse l'utiliser par la suite.

Qu'est-ce qu'un type défini par l'utilisateur / par le programme ?

Dans l'introduction du chapitre précédent (12.1 -- Introduction aux types composés de données), nous avons présenté le problème du stockage d'une fraction, dont le numérateur et le dénominateur sont conceptuellement liés. Dans cette leçon, nous avons vu certaines difficultés liées à l'utilisation de deux entiers séparés pour stocker indépendamment le numérateur et le dénominateur d'une fraction.

Si C++ disposait d'un type fraction intégré, ce serait parfait, mais ce n'est pas le cas. Et il existe des centaines d'autres types potentiellement utiles que C++ ne fournit pas, car il est tout simplement impossible d'anticiper tout ce dont quelqu'un pourrait avoir besoin (sans parler de les implémenter et de les tester).

C++ résout donc ce type de problème autrement : en permettant la création de types entièrement nouveaux et personnalisés, que nous pouvons utiliser dans nos programmes ! Ces types sont appelés types définis par l'utilisateur (user-defined types). Cependant, comme nous le verrons plus loin dans cette leçon, nous préférerons le terme types définis par le programme (program-defined types) pour désigner les types que nous créons pour nos propres programmes.

C++ possède deux catégories différentes de types composés permettant de créer des types définis par le programme :

  • Les types énumérés (y compris les énumérations non délimitées et délimitées)
  • Les types classes (y compris les structures, les classes et les unions).

Définir des types définis par le programme

Tout comme les alias de type, les types définis par le programme doivent aussi être définis et recevoir un nom avant de pouvoir être utilisés. La définition d'un type défini par le programme s'appelle une définition de type.

Point clé

Un type défini par le programme doit avoir un nom et une définition avant de pouvoir être utilisé. Les autres types composés n'en nécessitent aucun.

Les fonctions ne sont pas considérées comme des types définis par l'utilisateur (bien qu'elles nécessitent un nom et une définition avant d'être utilisées), car c'est la fonction elle-même qui reçoit un nom et une définition, et non son type. Les fonctions que nous définissons nous-mêmes sont appelées fonctions définies par l'utilisateur.

Bien que nous n'ayons pas encore expliqué ce qu'est une structure, voici un exemple montrant la définition d'un type personnalisé Fraction et l'instanciation d'un objet de ce type :

// Définit un type défini par le programme nommé Fraction afin que le compilateur sache ce qu'est une Fraction
// (nous expliquerons plus tard ce qu'est une struct et comment les utiliser dans ce chapitre)
// Cela définit seulement à quoi ressemble le type Fraction, cela ne crée pas de Fraction
struct Fraction
{
    int numerator {};
    int denominator {};
};

// Nous pouvons maintenant utiliser notre type Fraction
int main()
{
    Fraction f { 3, 4 }; // ceci instancie réellement un objet Fraction nommé f

    return 0;
}

Dans cet exemple, nous utilisons le mot-clé struct pour définir un nouveau type défini par le programme nommé Fraction (dans la portée globale, afin qu'il puisse être utilisé partout dans le reste du fichier). Cela n'alloue aucune mémoire : cela indique seulement au compilateur à quoi ressemble une Fraction, afin que nous puissions allouer des objets de type Fraction plus tard. Ensuite, dans main(), nous instancions et initialisons une variable de type Fraction nommée f.

Les définitions de types définis par le programme doivent se terminer par un point-virgule. Oublier ce point-virgule à la fin d'une définition de type est une erreur courante, et difficile à déboguer, car le compilateur peut signaler l'erreur sur la ligne suivant la définition du type.

Attention

N'oubliez pas de terminer vos définitions de types par un point-virgule.

Nous présenterons d'autres exemples de définition et d'utilisation de types définis par le programme dans la prochaine leçon (13.2 -- Énumérations non délimitées), et nous étudierons les structures à partir de la leçon 13.7 -- Introduction aux structures, aux membres et à la sélection de membres.

Nommer les types définis par le programme

Par convention, les types définis par le programme commencent par une majuscule et n'utilisent pas de suffixe (par exemple Fraction, et non fraction, fraction_t ou Fraction_t).

Bonne pratique

Nommez vos types définis par le programme en commençant par une majuscule, sans utiliser de suffixe.

Les nouveaux programmeurs trouvent parfois confuses des définitions de variables telles que celle-ci, à cause de la ressemblance entre le nom du type et celui de la variable :

Fraction fraction {}; // instancie une variable nommée fraction de type Fraction

Ce n'est pas différent de n'importe quelle autre définition de variable : le type (Fraction) vient en premier (et comme Fraction commence par une majuscule, nous savons qu'il s'agit d'un type défini par le programme), puis le nom de la variable (fraction), puis un éventuel initialisateur. Comme C++ distingue les majuscules des minuscules, il n'y a aucun conflit de noms ici !

Utiliser des types définis par le programme dans un programme multi-fichiers

Chaque fichier de code qui utilise un type défini par le programme doit voir la définition complète du type avant son utilisation. Une déclaration anticipée ne suffit pas. C'est nécessaire pour que le compilateur sache combien de mémoire allouer pour les objets de ce type.

Pour propager les définitions de types dans les fichiers de code qui en ont besoin, les types définis par le programme sont généralement définis dans des fichiers d'en-tête, puis inclus avec #include dans chaque fichier de code qui nécessite cette définition. Ces fichiers d'en-tête portent généralement le même nom que le type défini par le programme (par exemple, un type défini par le programme nommé Fraction serait défini dans Fraction.h).

Bonne pratique

Un type défini par le programme utilisé dans un seul fichier de code doit être défini dans ce fichier, aussi près que possible du premier point d'utilisation.

Un type défini par le programme utilisé dans plusieurs fichiers de code doit être défini dans un fichier d'en-tête portant le même nom que le type, puis inclus avec #include dans chaque fichier de code qui en a besoin.

Voici à quoi ressemblerait notre type Fraction s'il était déplacé dans un fichier d'en-tête (nommé Fraction.h) afin de pouvoir être inclus dans plusieurs fichiers de code :

Fraction.h :

#ifndef FRACTION_H
#define FRACTION_H

// Définit un nouveau type nommé Fraction
// Cela définit seulement à quoi ressemble une Fraction, cela n'en crée pas
// Notez qu'il s'agit d'une définition complète, et non d'une déclaration anticipée
struct Fraction
{
    int numerator {};
    int denominator {};
};

#endif

Fraction.cpp :

#include "Fraction.h" // inclut notre définition de Fraction dans ce fichier de code

// Nous pouvons maintenant utiliser notre type Fraction
int main()
{
    Fraction f{ 3, 4 }; // ceci crée réellement un objet Fraction nommé f

    return 0;
}

Les définitions de types sont partiellement exemptées de la règle de définition unique (ODR)

Dans la leçon 2.7 -- Déclarations anticipées et définitions, nous avons vu que la règle de définition unique impose que chaque fonction et chaque variable globale n'ait qu'une seule définition par programme. Pour utiliser une fonction ou une variable globale donnée dans un fichier qui ne contient pas sa définition, il nous faut une déclaration anticipée (que nous propageons généralement via un fichier d'en-tête). Cela fonctionne parce que les déclarations suffisent au compilateur pour les fonctions et les variables non constexpr, et l'éditeur de liens (linker) peut ensuite tout relier.

En revanche, utiliser des déclarations anticipées de la même manière ne fonctionne pas pour les types, car le compilateur doit généralement voir la définition complète d'un type pour l'utiliser. Nous devons pouvoir propager la définition complète du type vers chaque fichier de code qui en a besoin.

Pour cela, les types sont partiellement exemptés de la règle de définition unique : un type donné peut être défini dans plusieurs fichiers de code.

Vous avez déjà utilisé cette possibilité (probablement sans le réaliser) : si votre programme comporte deux fichiers de code qui incluent tous deux <iostream>, vous importez les définitions de types d'entrée/sortie dans les deux fichiers.

Il y a deux restrictions à connaître. Premièrement, vous ne pouvez avoir qu'une seule définition de type par fichier de code (ce qui n'est généralement pas un problème, car les gardes d'en-tête l'empêchent). Deuxièmement, toutes les définitions d'un même type doivent être identiques, sinon il en résulte un comportement indéfini.

Terminologie : types définis par l'utilisateur ou par le programme

Le terme « type défini par l'utilisateur » apparaît parfois dans le langage courant, et il est mentionné (sans être défini) dans la norme du langage C++. Dans le langage courant, ce terme désigne généralement « un type défini dans vos propres programmes » (comme le type Fraction de l'exemple ci-dessus).

La norme du langage C++ utilise le terme « type défini par l'utilisateur » de manière non conventionnelle. Dans la norme, un « type défini par l'utilisateur » est tout type classe ou type énuméré défini par vous, par la bibliothèque standard ou par l'implémentation (par exemple, les types définis par le compilateur pour prendre en charge des extensions du langage). Paradoxalement, cela signifie que std::string (un type classe défini dans la bibliothèque standard) est considéré comme un type défini par l'utilisateur !

Pour établir une distinction supplémentaire, la norme C++20 définit le terme « type défini par le programme » comme désignant les types classes et les types énumérés qui ne sont pas définis par la bibliothèque standard, l'implémentation ou le cœur du langage. Autrement dit, les « types définis par le programme » ne comprennent que les types classes et énumérés définis par nous (ou par une bibliothèque tierce).

En conséquence, lorsque nous parlerons uniquement des types classes et énumérés que nous définissons pour nos propres programmes, nous préférerons le terme « défini par le programme », car sa définition est plus précise.

Type Signification Exemples
Fondamental Un type de base intégré au cœur du langage C++ int, std::nullptr_t
Composé Un type défini en fonction d'autres types int&, double*, std::string, Fraction
Défini par l'utilisateur Un type classe ou un type énuméré (y compris ceux définis dans la bibliothèque standard ou l'implémentation) (dans l'usage courant, désigne généralement les types définis par le programme) std::string, Fraction
