13.14 — Déduction d'argument de modèle de classe (CTAD) et guides de déduction

Déduction d'argument de modèle de classe (CTAD) (C++17)

À partir de C++17, lorsque vous instanciez un objet à partir d'un modèle de classe, le compilateur peut déduire les types du modèle à partir des types de l'initialiseur de l'objet. On parle de déduction d'argument de modèle de classe (class template argument deduction, ou CTAD en abrégé). Par exemple :

#include <utility> // pour std::pair

int main()
{
    std::pair<int, int> p1{ 1, 2 }; // on spécifie explicitement le modèle de classe std::pair<int, int> (C++11 et versions ultérieures)
    std::pair p2{ 1, 2 };           // CTAD utilisée pour déduire std::pair<int, int> à partir des initialiseurs (C++17)

    return 0;
}

Le CTAD n'est effectué que si aucune liste d'arguments de modèle n'est présente. Par conséquent, les deux exemples suivants sont des erreurs :

#include <utility> // pour std::pair

int main()
{
    std::pair<> p1 { 1, 2 };    // erreur : trop peu d'arguments de modèle, les deux arguments ne sont pas déduits
    std::pair<int> p2 { 3, 4 }; // erreur : trop peu d'arguments de modèle, le second argument n'est pas déduit

    return 0;
}

Note de l'auteur

Beaucoup de leçons à venir sur ce site utilisent le CTAD. Si vous compilez ces exemples avec la norme C++14 (ou une version antérieure), vous obtiendrez une erreur indiquant des arguments de modèle manquants. Il vous faudra alors ajouter explicitement ces arguments pour que l'exemple compile.

Comme le CTAD est une forme de déduction de type, nous pouvons utiliser des suffixes littéraux pour modifier le type déduit :

#include <utility> // pour std::pair

int main()
{
    std::pair p1 { 3.4f, 5.6f }; // déduit en pair<float, float>
    std::pair p2 { 1u, 2u };     // déduit en pair<unsigned int, unsigned int>

    return 0;
}

Guides de déduction d'arguments de modèle (C++17)

Dans la plupart des cas, le CTAD fonctionne directement. Cependant, dans certains cas, le compilateur a besoin d'un peu d'aide pour déduire correctement les arguments de modèle.

Vous serez peut-être surpris de constater que le programme suivant (presque identique à l'exemple utilisant std::pair ci-dessus) ne compile pas en C++17 (uniquement) :

// définition de notre propre type Pair
template <typename T, typename U>
struct Pair
{
    T first{};
    U second{};
};

int main()
{
    Pair<int, int> p1{ 1, 2 }; // ok : nous spécifions explicitement les arguments de modèle
    Pair p2{ 1, 2 };           // erreur de compilation en C++17 (accepté en C++20)

    return 0;
}

Si vous compilez ce code en C++17, vous obtiendrez probablement une erreur du type « class template argument deduction failed », « cannot deduce template arguments » ou « No viable constructor or deduction guide ». En effet, en C++17, le CTAD ne sait pas déduire les arguments de modèle des classes modèles de type agrégat. Pour remédier à cela, nous pouvons fournir au compilateur un guide de déduction (deduction guide), qui lui indique comment déduire les arguments de modèle pour un modèle de classe donné.

Voici le même programme avec un guide de déduction :

template <typename T, typename U>
struct Pair
{
    T first{};
    U second{};
};

// Voici un guide de déduction pour notre Pair (nécessaire uniquement en C++17)
// Les objets Pair initialisés avec des arguments de type T et U doivent être déduits en Pair<T, U>
template <typename T, typename U>
Pair(T, U) -> Pair<T, U>;

int main()
{
    Pair<int, int> p1{ 1, 2 }; // on spécifie explicitement le modèle de classe Pair<int, int> (C++11 et versions ultérieures)
    Pair p2{ 1, 2 };           // CTAD utilisée pour déduire Pair<int, int> à partir des initialiseurs (C++17)

    return 0;
}

Cet exemple doit compiler en C++17.

Le guide de déduction de notre classe Pair est assez simple, mais examinons de plus près son fonctionnement.

// Voici un guide de déduction pour notre Pair (nécessaire uniquement en C++17)
// Les objets Pair initialisés avec des arguments de type T et U doivent être déduits en Pair<T, U>
template <typename T, typename U>
Pair(T, U) -> Pair<T, U>;

Tout d'abord, nous utilisons la même définition de paramètres de type que dans la classe Pair. Cela a du sens : si notre guide de déduction doit indiquer au compilateur comment déduire les types de Pair<T, U>, nous devons définir ce que sont T et U (paramètres de type du modèle). Ensuite, à droite de la flèche, se trouve le type que nous aidons le compilateur à déduire. Ici, nous voulons que le compilateur puisse déduire les arguments de modèle pour les objets de type Pair<T, U>, c'est donc exactement ce que nous écrivons. Enfin, à gauche de la flèche, nous indiquons au compilateur quel type de déclaration rechercher. Ici, nous lui demandons de chercher une déclaration d'un objet nommé Pair avec deux arguments (l'un de type T, l'autre de type U). Nous pourrions aussi écrire Pair(T t, U u) (où t et u sont les noms des paramètres), mais comme nous n'utilisons pas t ni u, il n'est pas nécessaire de les nommer.

En résumé, nous indiquons au compilateur que s'il rencontre la déclaration d'un Pair avec deux arguments (de types respectifs T et U), il doit déduire le type Pair<T, U>.

Ainsi, lorsque le compilateur rencontre la définition Pair p2{ 1, 2 }; dans notre programme, il se dit : « Ah, c'est la déclaration d'un Pair avec deux arguments de type int et int. D'après le guide de déduction, je dois donc déduire Pair<int, int> ».

Voici un exemple similaire pour un Pair qui ne prend qu'un seul paramètre de type :

template <typename T>
struct Pair
{
    T first{};
    T second{};
};

// Voici un guide de déduction pour notre Pair (nécessaire uniquement en C++17)
// Les objets Pair initialisés avec des arguments de type T et T doivent être déduits en Pair<T>
template <typename T>
Pair(T, T) -> Pair<T>;

int main()
{
    Pair<int> p1{ 1, 2 }; // on spécifie explicitement le modèle de classe Pair<int> (C++11 et versions ultérieures)
    Pair p2{ 1, 2 };      // CTAD utilisée pour déduire Pair<int> à partir des initialiseurs (C++17)

    return 0;
}

Dans ce cas, notre guide de déduction associe un Pair(T, T) (un Pair avec deux arguments de type T) à un Pair<T>.

Astuce

C++20 permet au compilateur de générer automatiquement des guides de déduction pour les agrégats. Les guides de déduction ne sont donc nécessaires que pour assurer la compatibilité avec C++17.

Pour cette raison, la version de Pair sans guides de déduction compile en C++20.

std::pair (et les autres types modèles de la bibliothèque standard) possèdent des guides de déduction prédéfinis, ce qui explique pourquoi notre exemple ci-dessus utilisant std::pair compile sans problème en C++17, sans que nous ayons à fournir nous-mêmes les guides de déduction.

Pour les lecteurs avancés

Les types non agrégats n'ont pas besoin de guides de déduction en C++17, car la présence d'un constructeur remplit le même rôle.

Paramètres de type de modèle avec valeurs par défaut

Tout comme les paramètres de fonction peuvent avoir des arguments par défaut, les paramètres de modèle peuvent recevoir des valeurs par défaut. Celles-ci sont utilisées lorsque le paramètre de modèle n'est pas spécifié explicitement et ne peut pas être déduit.

Voici une modification du programme précédent avec le modèle de classe Pair<T, U>, où les paramètres de type T et U ont pour valeur par défaut le type int :

template <typename T=int, typename U=int> // on fixe par défaut T et U au type int
struct Pair
{
    T first{};
    U second{};
};

template <typename T, typename U>
Pair(T, U) -> Pair<T, U>;

int main()
{
    Pair<int, int> p1{ 1, 2 }; // on spécifie explicitement le modèle de classe Pair<int, int> (C++11 et versions ultérieures)
    Pair p2{ 1, 2 };           // CTAD utilisée pour déduire Pair<int, int> à partir des initialiseurs (C++17)

    Pair p3;                   // utilise le Pair<int, int> par défaut

    return 0;
}

La définition de p3 ne spécifie explicitement aucun type pour les paramètres de type du modèle, et il n'existe aucun initialiseur à partir duquel ces types pourraient être déduits. Le compilateur utilise donc les types indiqués par défaut, ce qui signifie que p3 est de type Pair<int, int>.

Le CTAD ne fonctionne pas avec l'initialisation de membres non statiques

Lorsque vous initialisez un membre de type classe à l'aide de l'initialisation de membre non statique, le CTAD ne fonctionne pas dans ce contexte. Tous les arguments de modèle doivent être spécifiés explicitement :

#include <utility> // pour std::pair

struct Foo
{
    std::pair<int, int> p1{ 1, 2 }; // ok, arguments de modèle spécifiés explicitement
    std::pair p2{ 1, 2 };           // erreur de compilation, le CTAD ne peut pas être utilisé dans ce contexte
};

int main()
{
    std::pair p3{ 1, 2 };           // ok, le CTAD peut être utilisé ici
    return 0;
}

Le CTAD ne fonctionne pas avec les paramètres de fonction

Le CTAD signifie class template argument deduction (déduction des arguments de modèle de classe) et non class template parameter deduction : il ne déduit donc que le type des arguments de modèle, et non celui des paramètres de modèle.

Par conséquent, le CTAD ne peut pas être utilisé dans les paramètres de fonction.

#include <iostream>
#include <utility>

void print(std::pair p) // erreur de compilation, le CTAD ne peut pas être utilisé ici
{
    std::cout << p.first << ' ' << p.second << '\n';
}

int main()
{
    std::pair p { 1, 2 }; // p est déduit en std::pair<int, int>
    print(p);

    return 0;
}

Dans de tels cas, vous devez utiliser un modèle de fonction à la place :

#include <iostream>
#include <utility>

template <typename T, typename U>
void print(std::pair<T, U> p)
{
    std::cout << p.first << ' ' << p.second << '\n';
}

int main()
{
    std::pair p { 1, 2 }; // p est déduit en std::pair<int, int>
    print(p);

    return 0;
}
