20.7 — Captures de lambda

La clause de capture et la capture par valeur

Dans la leçon précédente (20.6 -- Introduction aux lambdas (fonctions anonymes)), nous avons présenté cet exemple :

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>

int main()
{
  std::array<std::string_view, 4> arr{ "apple", "banana", "walnut", "lemon" };

  auto found{ std::find_if(arr.begin(), arr.end(),
                           [](std::string_view str)
                           {
                             return str.find("nut") != std::string_view::npos;
                           }) };

  if (found == arr.end())
  {
    std::cout << "No nuts\n";
  }
  else
  {
    std::cout << "Found " << *found << '\n';
  }

  return 0;
}

Modifions maintenant cet exemple des noix et laissons l'utilisateur choisir la sous-chaîne à rechercher. Ce n'est pas aussi intuitif qu'on pourrait le penser.

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>
#include <string>

int main()
{
  std::array<std::string_view, 4> arr{ "apple", "banana", "walnut", "lemon" };

  // Demande à l'utilisateur ce qu'il veut chercher.
  std::cout << "search for: ";

  std::string search{};
  std::cin >> search;

  auto found{ std::find_if(arr.begin(), arr.end(), [](std::string_view str) {
    // Recherche @search au lieu de "nut".
    return str.find(search) != std::string_view::npos; // Erreur : search n'est pas accessible dans cette portée
  }) };

  if (found == arr.end())
  {
    std::cout << "Not found\n";
  }
  else
  {
    std::cout << "Found " << *found << '\n';
  }

  return 0;
}

Ce code ne compile pas. Contrairement aux blocs imbriqués, où tout identifiant accessible dans le bloc englobant est accessible dans le bloc imbriqué, les lambdas ne peuvent accéder qu'à certains types d'objets définis en dehors de la lambda. Il s'agit :

  • des objets à durée de stockage statique (ou à durée de stockage thread local), c'est-à-dire les variables globales et les variables locales statiques ;
  • des objets constexpr (explicitement ou implicitement).

Comme search ne remplit aucune de ces conditions, la lambda ne peut pas le voir.

Astuce

Les lambdas ne peuvent accéder qu'à certains types d'objets définis en dehors de la lambda, notamment ceux à durée de stockage statique (par exemple les variables globales et les variables locales statiques) et les objets constexpr.

Pour accéder à search depuis la lambda, nous devons utiliser une clause de capture.

La clause de capture

La clause de capture (capture clause) sert à donner (indirectement) à une lambda accès à des variables de la portée environnante auxquelles elle n'aurait normalement pas accès. Il suffit de lister, dans la clause de capture, les entités que nous voulons utiliser dans la lambda. Ici, nous voulons donner à notre lambda accès à la valeur de la variable search, nous l'ajoutons donc à la clause de capture :

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>
#include <string>

int main()
{
  std::array<std::string_view, 4> arr{ "apple", "banana", "walnut", "lemon" };

  std::cout << "search for: ";

  std::string search{};
  std::cin >> search;

  // Capture @search                                vvvvvv
  auto found{ std::find_if(arr.begin(), arr.end(), [search](std::string_view str) {
    return str.find(search) != std::string_view::npos;
  }) };

  if (found == arr.end())
  {
    std::cout << "Not found\n";
  }
  else
  {
    std::cout << "Found " << *found << '\n';
  }

  return 0;
}

L'utilisateur peut maintenant rechercher un élément de notre tableau.

Sortie


search for: nana
Found banana

Alors, comment fonctionnent réellement les captures ?

Bien qu'il semble que la lambda de l'exemple ci-dessus accède directement à la valeur de la variable search de main, ce n'est pas le cas. Les lambdas ressemblent à des blocs imbriqués, mais elles fonctionnent légèrement différemment (et cette distinction est importante).

Lorsque la définition d'une lambda est exécutée, une copie de chaque variable capturée est créée à l'intérieur de la lambda, avec le même nom. Ces variables clonées sont initialisées à partir des variables de même nom de la portée externe à ce moment-là.

Ainsi, dans l'exemple ci-dessus, lorsque l'objet lambda est créé, la lambda reçoit sa propre variable clonée nommée search. Ce search cloné a la même valeur que le search de main, si bien que son comportement ressemble à un accès au search de main, alors qu'il n'en est rien.

Bien que ces variables clonées portent le même nom, elles n'ont pas nécessairement le même type que la variable d'origine. Nous explorerons ce point dans les sections suivantes de cette leçon.

Point clé

Les variables capturées d'une lambda sont des copies des variables de la portée externe, et non les variables elles-mêmes.

Pour les lecteurs avancés

Bien que les lambdas ressemblent à des fonctions, ce sont en réalité des objets qui peuvent être appelés comme des fonctions (on parle de foncteurs (functors) : nous verrons comment créer vos propres foncteurs de zéro dans une leçon ultérieure).

Lorsque le compilateur rencontre la définition d'une lambda, il crée une définition d'objet personnalisée pour cette lambda. Chaque variable capturée devient un membre de données de cet objet.

À l'exécution, lorsque la définition de la lambda est atteinte, l'objet lambda est instancié, et ses membres sont initialisés à ce moment-là.

Les captures sont traitées comme const par défaut

Lorsqu'une lambda est appelée, son operator() est invoqué. Par défaut, cet operator() traite les captures comme const, ce qui signifie que la lambda n'a pas le droit de modifier ces captures.

Dans l'exemple suivant, nous capturons la variable ammo et tentons de la décrémenter.

#include <iostream>

int main()
{
  int ammo{ 10 };

  // Définit une lambda et la stocke dans une variable nommée "shoot".
  auto shoot{
    [ammo]() {
      // Illégal, ammo ne peut pas être modifié.
      --ammo;

      std::cout << "Pew! " << ammo << " shot(s) left.\n";
    }
  };

  // Appelle la lambda
  shoot();

  std::cout << ammo << " shot(s) left\n";

  return 0;
}

Le code ci-dessus ne compile pas, car ammo est traité comme const à l'intérieur de la lambda.

Captures mutables

Pour autoriser la modification des variables capturées, nous pouvons marquer la lambda comme mutable :

#include <iostream>

int main()
{
  int ammo{ 10 };

  auto shoot{
    [ammo]() mutable { // désormais mutable
      // Nous avons le droit de modifier ammo maintenant
      --ammo;

      std::cout << "Pew! " << ammo << " shot(s) left.\n";
    }
  };

  shoot();
  shoot();

  std::cout << ammo << " shot(s) left\n";

  return 0;
}

Sortie :


Pew! 9 shot(s) left.
Pew! 8 shot(s) left.
10 shot(s) left

Bien que ce code compile désormais, il reste une erreur de logique. Que s'est-il passé ? Lors de l'appel de la lambda, celle-ci a capturé une copie de ammo. Lorsque la lambda a décrémenté ammo de 10 à 9, puis à 8, elle a décrémenté sa propre copie, et non la valeur originale de ammo dans main().

Notez que la valeur de ammo est conservée d'un appel de la lambda à l'autre !

Attention

Comme les variables capturées sont des membres de l'objet lambda, leurs valeurs sont conservées d'un appel de la lambda à l'autre !

Capture par référence

Tout comme les fonctions peuvent modifier la valeur d'arguments passés par référence, nous pouvons aussi capturer des variables par référence afin que notre lambda puisse affecter la valeur de l'argument.

Pour capturer une variable par référence, nous faisons précéder son nom, dans la capture, d'une esperluette (&). Contrairement aux variables capturées par valeur, les variables capturées par référence ne sont pas const, sauf si la variable capturée elle-même est const. La capture par référence doit être préférée à la capture par valeur chaque fois que vous préféreriez passer un argument à une fonction par référence (par exemple pour les types non fondamentaux).

Voici le code précédent avec ammo capturé par référence :

#include <iostream>

int main()
{
  int ammo{ 10 };

  auto shoot{
    // Nous n'avons plus besoin de mutable
    [&ammo]() { // &ammo signifie que ammo est capturé par référence
      // Les modifications de ammo affecteront le ammo de main
      --ammo;

      std::cout << "Pew! " << ammo << " shot(s) left.\n";
    }
  };

  shoot();

  std::cout << ammo << " shot(s) left\n";

  return 0;
}

Cela produit le résultat attendu :


Pew! 9 shot(s) left.
9 shot(s) left

Utilisons maintenant une capture par référence pour compter le nombre de comparaisons effectuées par std::sort lors du tri d'un tableau.

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>

struct Car
{
  std::string_view make{};
  std::string_view model{};
};

int main()
{
  std::array<Car, 3> cars{ { { "Volkswagen", "Golf" },
                             { "Toyota", "Corolla" },
                             { "Honda", "Civic" } } };

  int comparisons{ 0 };

  std::sort(cars.begin(), cars.end(),
    // Capture @comparisons par référence.
    [&comparisons](const auto& a, const auto& b) {
      // Nous avons capturé comparisons par référence. Nous pouvons la modifier sans "mutable".
      ++comparisons;

      // Trie les voitures par marque.
      return a.make < b.make;
  });

  std::cout << "Comparisons: " << comparisons << '\n';

  for (const auto& car : cars)
  {
    std::cout << car.make << ' ' << car.model << '\n';
  }

  return 0;
}

Sortie possible :


Comparisons: 2
Honda Civic
Toyota Corolla
Volkswagen Golf

Capturer plusieurs variables

Plusieurs variables peuvent être capturées en les séparant par des virgules. Il peut s'agir d'un mélange de variables capturées par valeur et par référence :

int health{ 33 };
int armor{ 100 };
std::vector<CEnemy> enemies{};

// Capture health et armor par valeur, et enemies par référence.
[health, armor, &enemies](){};

Captures par défaut

Devoir lister explicitement les variables à capturer peut être fastidieux. Si vous modifiez votre lambda, vous risquez d'oublier d'ajouter ou de retirer des variables capturées. Heureusement, nous pouvons laisser le compilateur générer automatiquement la liste des variables à capturer.

Une capture par défaut (default capture, également appelée capture-default) capture toutes les variables mentionnées dans la lambda. Les variables non mentionnées dans la lambda ne sont pas capturées lorsqu'une capture par défaut est utilisée.

Pour capturer par valeur toutes les variables utilisées, utilisez la capture =. Pour capturer par référence toutes les variables utilisées, utilisez la capture &.

Voici un exemple de capture par défaut par valeur :

#include <algorithm>
#include <array>
#include <iostream>

int main()
{
  std::array areas{ 100, 25, 121, 40, 56 };

  int width{};
  int height{};

  std::cout << "Enter width and height: ";
  std::cin >> width >> height;

  auto found{ std::find_if(areas.begin(), areas.end(),
                           [=](int knownArea) { // capture par défaut de width et height par valeur
                             return width * height == knownArea; // car ils sont mentionnés ici
                           }) };

  if (found == areas.end())
  {
    std::cout << "I don't know this area :(\n";
  }
  else
  {
    std::cout << "Area found :)\n";
  }

  return 0;
}

Les captures par défaut peuvent être combinées avec des captures normales. Nous pouvons capturer certaines variables par valeur et d'autres par référence, mais chaque variable ne peut être capturée qu'une seule fois.

int health{ 33 };
int armor{ 100 };
std::vector<CEnemy> enemies{};

// Capture health et armor par valeur, et enemies par référence.
[health, armor, &enemies](){};

// Capture enemies par référence et tout le reste par valeur.
[=, &enemies](){};

// Capture armor par valeur et tout le reste par référence.
[&, armor](){};

// Illégal, nous avons déjà indiqué que nous voulons tout capturer par référence.
[&, &armor](){};

// Illégal, nous avons déjà indiqué que nous voulons tout capturer par valeur.
[=, armor](){};

// Illégal, armor apparaît deux fois.
[armor, &health, &armor](){};

// Illégal, la capture par défaut doit être le premier élément de la liste de captures.
[armor, &](){};

Définir de nouvelles variables dans la capture de la lambda

Il arrive que l'on veuille capturer une variable en la modifiant légèrement, ou déclarer une nouvelle variable visible uniquement dans la portée de la lambda. Nous pouvons le faire en définissant une variable dans la capture de la lambda sans préciser son type.

#include <array>
#include <iostream>
#include <algorithm>

int main()
{
  std::array areas{ 100, 25, 121, 40, 56 };

  int width{};
  int height{};

  std::cout << "Enter width and height: ";
  std::cin >> width >> height;

  // Nous stockons areas, mais l'utilisateur a saisi width et height.
  // Nous devons calculer l'aire avant de pouvoir la rechercher.
  auto found{ std::find_if(areas.begin(), areas.end(),
                           // Déclare une nouvelle variable visible uniquement par la lambda.
                           // Le type de userArea est automatiquement déduit en int.
                           [userArea{ width * height }](int knownArea) {
                             return userArea == knownArea;
                           }) };

  if (found == areas.end())
  {
    std::cout << "I don't know this area :(\n";
  }
  else
  {
    std::cout << "Area found :)\n";
  }

  return 0;
}

userArea n'est calculée qu'une seule fois, au moment de la définition de la lambda. L'aire calculée est stockée dans l'objet lambda et reste la même à chaque appel. Si une lambda mutable modifie une variable définie dans la capture, la valeur d'origine est remplacée.

Bonne pratique

N'initialisez des variables dans la capture que si leur valeur est courte et si leur type est évident. Sinon, il vaut mieux définir la variable en dehors de la lambda, puis la capturer.

Variables capturées pendantes

Les variables sont capturées au point où la lambda est définie. Si une variable capturée par référence cesse d'exister avant la lambda, la lambda se retrouve avec une référence pendante (dangling reference).

Par exemple :

#include <iostream>
#include <string>

// renvoie une lambda
auto makeWalrus(const std::string& name)
{
  // Capture name par référence et renvoie la lambda.
  return [&]() {
    std::cout << "I am a walrus, my name is " << name << '\n'; // Comportement indéfini
  };
}

int main()
{
  // Crée un nouveau morse dont le nom est Roofus.
  // sayName est la lambda renvoyée par makeWalrus.
  auto sayName{ makeWalrus("Roofus") };

  // Appelle la fonction lambda renvoyée par makeWalrus.
  sayName();

  return 0;
}

L'appel à makeWalrus() crée un std::string temporaire à partir du littéral de chaîne "Roofus". La lambda de makeWalrus() capture cette chaîne temporaire par référence. La chaîne temporaire cesse d'exister à la fin de l'expression complète contenant l'appel à makeWalrus(), mais la lambda sayName continue de la référencer au-delà de ce point. Ainsi, lorsque nous appelons sayName, la référence pendante est utilisée, ce qui provoque un comportement indéfini.

Notez que cela se produit aussi si "Roofus" est passé à makeWalrus() par valeur. Le paramètre name cesse d'exister à la fin de makeWalrus(), et la lambda se retrouve avec une référence pendante.

Attention

Soyez extrêmement prudent lorsque vous capturez des variables par référence, en particulier avec une capture par référence par défaut. Les variables capturées doivent survivre à la lambda.

Si nous voulons que name capturé reste valide lorsque la lambda est utilisée, nous devons le capturer par valeur (explicitement, ou à l'aide d'une capture par défaut par valeur).

Copies involontaires de lambdas mutables

Comme les lambdas sont des objets, elles peuvent être copiées. Dans certains cas, cela peut poser problème. Considérez le code suivant :

#include <iostream>

int main()
{
  int i{ 0 };

  // Crée une nouvelle lambda nommée count
  auto count{ [i]() mutable {
    std::cout << ++i << '\n';
  } };

  count(); // invoque count

  auto otherCount{ count }; // crée une copie de count

  // invoque count et sa copie
  count();
  otherCount();

  return 0;
}

Sortie :


1
2
2

Au lieu d'afficher 1, 2, 3, le code affiche deux fois 2. Lorsque nous avons créé otherCount comme copie de count, nous avons copié count dans son état actuel. Le i de count valait 1, donc le i de otherCount vaut également 1. Comme otherCount est une copie de count, chacune possède son propre i.

Examinons maintenant un exemple un peu moins évident :

#include <iostream>
#include <functional>

void myInvoke(const std::function<void()>& fn)
{
    fn();
}

int main()
{
    int i{ 0 };

    // Incrémente et affiche sa copie locale de @i.
    auto count{ [i]() mutable {
      std::cout << ++i << '\n';
    } };

    myInvoke(count);
    myInvoke(count);
    myInvoke(count);

    return 0;
}

Sortie :


1
1
1

Ce code présente le même problème que l'exemple précédent, sous une forme plus discrète.

Lorsque nous appelons myInvoke(count), le compilateur constate que count (qui a un type de lambda) ne correspond pas au type du paramètre par référence (std::function<void()>). Il convertit la lambda en un std::function temporaire afin que le paramètre par référence puisse s'y lier, et cela crée une copie de la lambda. Ainsi, notre appel à fn() est en réalité exécuté sur la copie de la lambda contenue dans le std::function temporaire, et non sur la lambda elle-même.

Si nous devons passer une lambda mutable, et que nous voulons éviter la création involontaire de copies, deux options s'offrent à nous. La première consiste à utiliser une lambda sans capture, en suivant l'état à l'aide d'une variable locale statique. Mais les variables locales statiques peuvent être difficiles à suivre et rendent le code moins lisible. Une meilleure option consiste à empêcher la création de copies de notre lambda. Mais comme nous ne pouvons pas modifier l'implémentation de std::function (ou d'autres fonctions ou objets de la bibliothèque standard), comment faire ?

Une solution (merci au lecteur Dck) consiste à placer immédiatement notre lambda dans un std::function. Ainsi, lorsque nous appelons myInvoke(), le paramètre par référence fn peut se lier à notre std::function, et aucune copie temporaire n'est créée :

#include <iostream>
#include <functional>

void myInvoke(const std::function<void()>& fn)
{
    fn();
}

int main()
{
    int i{ 0 };

    // Incrémente et affiche sa copie locale de @i.
    std::function count{ [i]() mutable { // objet lambda stocké dans un std::function
      std::cout << ++i << '\n';
    } };

    myInvoke(count); // ne crée pas de copie lors de l'appel
    myInvoke(count); // ne crée pas de copie lors de l'appel
    myInvoke(count); // ne crée pas de copie lors de l'appel

    return 0;
}

Une autre solution consiste à utiliser un wrapper de référence (reference wrapper). C++ fournit un type pratique (dans l'en-tête <functional>) appelé std::reference_wrapper, qui permet de passer un type ordinaire comme s'il s'agissait d'une référence. Pour plus de commodité, un std::reference_wrapper peut être créé à l'aide de la fonction std::ref(). En enveloppant notre lambda dans un std::reference_wrapper, chaque fois que quelqu'un tente de copier notre lambda, il copiera en réalité le reference_wrapper (sans copier la lambda elle-même).

Voici notre code mis à jour avec std::ref :

#include <iostream>
#include <functional> // inclut std::reference_wrapper et std::ref

void myInvoke(const std::function<void()>& fn)
{
    fn();
}

int main()
{
    int i{ 0 };

    // Incrémente et affiche sa copie locale de @i.
    auto count{ [i]() mutable {
      std::cout << ++i << '\n';
    } };

    // std::ref(count) fait en sorte que count soit traité comme une référence
    // ainsi, tout ce qui tente de copier count copiera en réalité la référence
    // ce qui garantit qu'un seul count existe
    myInvoke(std::ref(count));
    myInvoke(std::ref(count));
    myInvoke(std::ref(count));

    return 0;
}

Notre sortie est maintenant conforme aux attentes :


1
2
3

Ce qui est intéressant avec cette méthode, c'est qu'elle fonctionne même si myInvoke prend fn par valeur (au lieu de par référence) !

Règle

Les fonctions de la bibliothèque standard peuvent copier des objets fonctions (rappel : les lambdas sont des objets fonctions). Si vous voulez fournir à des lambdas des variables capturées mutables, passez-les par référence à l'aide de std::ref.

Bonne pratique

Essayez d'éviter les lambdas mutables. Les lambdas non mutables sont plus faciles à comprendre et ne souffrent pas des problèmes ci-dessus, ni des dangers plus graves qui apparaissent lorsqu'on ajoute une exécution parallèle.

Question n° 3

Nous allons écrire un petit jeu avec des nombres carrés (les nombres obtenus en multipliant un entier par lui-même : 1, 4, 9, 16, 25, …).

Pour préparer la partie :

  • Demandez à l'utilisateur de saisir un nombre de départ (par exemple 3).
  • Demandez à l'utilisateur combien de valeurs générer.
  • Choisissez un entier aléatoire entre 2 et 4. C'est le multiplicateur.
  • Générez le nombre de valeurs demandé par l'utilisateur. En partant du nombre de départ, chaque valeur doit être le carré suivant, multiplié par le multiplicateur.

Pour jouer :

  • L'utilisateur saisit une proposition.
  • Si la proposition correspond à une valeur générée, cette valeur est retirée de la liste et l'utilisateur peut proposer à nouveau.
  • Si l'utilisateur trouve toutes les valeurs générées, il gagne.
  • Si la proposition ne correspond à aucune valeur générée, l'utilisateur perd et le programme lui indique la valeur non devinée la plus proche.

Voici quelques exemples de parties pour mieux comprendre le fonctionnement du jeu :

Nice! 4 number(s) left.
> 72
Nice! 3 number(s) left.
> 50
Nice! 2 number(s) left.
> 126
126 is wrong! Try 128 next time.

  • Le programme a choisi 2 comme multiplicateur aléatoire, donc chaque carré est multiplié par 2 : 32, 50, 72, 98, 128.
  • Maintenant, l'utilisateur peut proposer.

#include <algorithm> // std::find, std::min_element
#include <cmath> // std::abs
#include <cstddef> // std::size_t
#include <iostream>
#include <vector>
#include "Random.h"

using Numbers = std::vector<int>;

namespace config
{
    constexpr int multiplierMin{ 2 };
    constexpr int multiplierMax{ 6 };
}

// Génère @count nombres à partir de @start*@start et multiplie
// chaque nombre carré par @multiplier.
Numbers generateNumbers(int start, int count, int multiplier)
{
    Numbers numbers(static_cast<std::size_t>(count));

    for (int index = 0; index < count; ++index)
    {
        std::size_t uindex{ static_cast<std::size_t>(index) };
        numbers[uindex] = (start + index) * (start + index) * multiplier;
    }

    return numbers;
}

// Demande à l'utilisateur le nombre de départ, puis génère le tableau de nombres
Numbers setupGame()
{
    int start{};
    std::cout << "Start where? ";
    std::cin >> start;

    int count{};
    std::cout << "How many? ";
    std::cin >> count;

    int multiplier{ Random::get(config::multiplierMin, config::multiplierMax) };

    std::cout << "I generated " << count
        << " square numbers. Do you know what each number is after multiplying it by "
        << multiplier << "?\n";

    return generateNumbers(start, count, multiplier);
}

// Renvoie la proposition de l'utilisateur
int getUserGuess()
{
    int guess{};

    std::cout << "> ";
    std::cin >> guess;

    return guess;
}

// Recherche la valeur @guess dans @numbers et la retire.
// Renvoie true si la valeur a été trouvée, false sinon.
bool findAndRemove(Numbers& numbers, int guess)
{
    auto found{ std::find(numbers.begin(), numbers.end(), guess) };

    if (found == numbers.end())
        return false;

    numbers.erase(found);
    return true;
}

// Trouve la valeur de @numbers la plus proche de @guess.
int findClosestNumber(const Numbers& numbers, int guess)
{
    return *std::min_element(numbers.begin(), numbers.end(),
        [=](int a, int b)
        {
            return std::abs(a - guess) < std::abs(b - guess);
        });
}


// Appelée lorsque l'utilisateur devine correctement un nombre.
void printSuccess(const Numbers& numbers)
{
    std::cout << "Nice! ";

    if (numbers.size() == 0)
    {
        std::cout << "You found all numbers, good job!\n";
    }
    else
    {
        std::cout << numbers.size() << " number(s) left.\n";
    }
}

// Appelée lorsque l'utilisateur propose un nombre qui ne figure pas dans numbers.
void printFailure(const Numbers& numbers, int guess)
{
    int closest{ findClosestNumber(numbers, guess) };

    std::cout << guess << " is wrong!\n";

    std::cout << "Try " << closest << " next time.\n";
}

int main()
{
    Numbers numbers{ setupGame() };

    while (true)
    {
        int guess{ getUserGuess() };

        if (!findAndRemove(numbers, guess))
        {
            printFailure(numbers, guess);
            break;
        }

        printSuccess(numbers);
        if (numbers.size() == 0)
            break;
    }

    return 0;
}
