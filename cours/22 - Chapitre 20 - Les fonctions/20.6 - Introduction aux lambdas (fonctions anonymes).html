20.6 — Introduction aux lambdas (fonctions anonymes)

Considérons ce bout de code que nous avons introduit dans la leçon 18.3 -- Introduction aux algorithmes de la bibliothèque standard :

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>

// Notre fonction renvoie true si l'élément correspond
bool containsNut(std::string_view str)
{
    // std::string_view::find renvoie std::string_view::npos s'il ne trouve pas
    // la sous-chaîne. Sinon, il renvoie l'indice où la sous-chaîne apparaît
    // dans str.
    return str.find("nut") != std::string_view::npos;
}

int main()
{
    constexpr std::array<std::string_view, 4> arr{ "apple", "banana", "walnut", "lemon" };

    // Parcourir notre tableau pour voir si un élément contient la sous-chaîne "nut"
    auto found{ std::find_if(arr.begin(), arr.end(), containsNut) };

    if (found == arr.end())
    {
        std::cout << "No nuts\n";
    }
    else
    {
        std::cout << "Found " << *found << '\n';
    }

    return 0;
}

Ce code parcourt un tableau de chaînes à la recherche du premier élément qui contient la sous-chaîne « nut ». Il produit donc le résultat suivant :


Found walnut

Ce code fonctionne, mais il peut être amélioré.

Le problème vient de ce que std::find_if exige qu'on lui passe un pointeur de fonction. Nous sommes donc obligés de définir une fonction qui ne sera utilisée qu'une seule fois, qui doit recevoir un nom et qui doit être placée dans la portée globale (car les fonctions ne peuvent pas être imbriquées !). De plus, la fonction est si courte qu'il est presque plus facile de comprendre ce qu'elle fait en lisant cette seule ligne de code qu'en lisant son nom et ses commentaires.

Les lambdas sont des fonctions anonymes

Une expression lambda (appelée aussi lambda ou fermeture, closure en anglais) permet de définir une fonction anonyme à l'intérieur d'une autre fonction. Cette imbrication est importante : elle permet à la fois d'éviter de polluer l'espace de noms et de définir la fonction aussi près que possible de l'endroit où elle est utilisée, ce qui apporte un contexte supplémentaire.

La syntaxe des lambdas est l'une des choses les plus étranges du C++ et demande un peu d'habitude. Une lambda prend la forme suivante :


[ captureClause ] ( parameters ) -> returnType
{
    statements;
}
  • La clause de capture peut être vide si aucune capture n'est nécessaire.
  • La liste de paramètres peut être vide si aucun paramètre n'est requis. Elle peut aussi être omise entièrement, sauf si un type de retour est spécifié.
  • Le type de retour est facultatif. S'il est omis, auto est supposé (la déduction de type sert alors à déterminer le type de retour). Nous avons indiqué précédemment qu'il fallait éviter la déduction de type pour les types de retour des fonctions, mais dans ce contexte, son utilisation est acceptable, car ces fonctions sont généralement très simples.

Notez également que les lambdas, étant anonymes, n'ont pas de nom, et nous n'avons donc pas besoin d'en fournir un.

En passant…

Cela signifie qu'une définition de lambda triviale ressemble à ceci :

#include <iostream>

int main()
{
  [] {}; // une lambda au type de retour omis, sans capture et sans paramètres.

  return 0;
}

Réécrivons l'exemple ci-dessus à l'aide d'une lambda :

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>

int main()
{
  constexpr std::array<std::string_view, 4> arr{ "apple", "banana", "walnut", "lemon" };

  // Définir la fonction exactement à l'endroit où nous l'utilisons.
  auto found{ std::find_if(arr.begin(), arr.end(),
                           [](std::string_view str) // voici notre lambda, sans clause de capture
                           {
                             return str.find("nut") != std::string_view::npos;
                           }) };

  if (found == arr.end())
  {
    std::cout << "No nuts\n";
  }
  else
  {
    std::cout << "Found " << *found << '\n';
  }

  return 0;
}

Cela fonctionne exactement comme le cas du pointeur de fonction et produit un résultat identique :


Found walnut

Remarquez à quel point notre lambda ressemble à la fonction containsNut. Elles ont des paramètres et des corps identiques. La lambda n'a pas de clause de capture (nous expliquerons ce qu'est une clause de capture dans la prochaine leçon) parce qu'elle n'en a pas besoin. Nous avons omis le type de retour final dans la lambda (par concision), mais comme operator!= renvoie un bool, notre lambda renvoie aussi un bool.

Bonne pratique

Conformément à la bonne pratique consistant à définir les choses dans la portée la plus petite et au plus près de leur première utilisation, les lambdas sont préférables aux fonctions ordinaires lorsque nous avons besoin d'une fonction triviale, à usage unique, à passer en argument à une autre fonction.

Type d'une lambda

Dans l'exemple ci-dessus, nous avons défini une lambda à l'endroit exact où elle était nécessaire. Cette utilisation d'une lambda est parfois appelée littéral de fonction (function literal).

Toutefois, écrire une lambda sur la même ligne que son utilisation peut parfois rendre le code plus difficile à lire. De même que nous pouvons initialiser une variable avec une valeur littérale (ou un pointeur de fonction) pour l'utiliser plus tard, nous pouvons aussi initialiser une variable lambda avec une définition de lambda, puis l'utiliser ultérieurement. Une lambda nommée, accompagnée d'un bon nom de fonction, peut rendre le code plus lisible.

Par exemple, dans l'extrait suivant, nous utilisons std::all_of pour vérifier si tous les éléments d'un tableau sont pairs :

// Mauvais : il faut lire la lambda pour comprendre ce qui se passe.
return std::all_of(array.begin(), array.end(), [](int i){ return ((i % 2) == 0); });

Nous pouvons améliorer la lisibilité de cette façon :

// Bien : nous pouvons plutôt stocker la lambda dans une variable nommée et la passer à la fonction.
auto isEven{
  [](int i)
  {
    return (i % 2) == 0;
  }
};

return std::all_of(array.begin(), array.end(), isEven);

Remarquez à quel point la dernière ligne se lit bien : « renvoyer si tous les éléments du tableau sont pairs ».

Point clé

Stocker une lambda dans une variable nous permet de donner à cette lambda un nom utile, ce qui peut rendre notre code plus lisible.

Stocker une lambda dans une variable nous permet aussi de l'utiliser plus d'une fois.

Mais quel est le type de la lambda isEven ?

Il s'avère que les lambdas n'ont pas de type que nous puissions utiliser explicitement. Lorsque nous écrivons une lambda, le compilateur génère un type unique, propre à cette lambda, qui ne nous est pas exposé.

Pour les lecteurs avancés

En réalité, les lambdas ne sont pas des fonctions (ce qui explique en partie comment elles contournent la limitation du C++ qui ne permet pas d'imbriquer des fonctions). Ce sont un type particulier d'objet appelé foncteur (functor). Un foncteur est un objet qui contient un operator() surchargé, ce qui le rend appelable comme une fonction.

Bien que nous ne connaissions pas le type d'une lambda, il existe plusieurs façons de stocker une lambda pour l'utiliser après sa définition. Si la lambda a une clause de capture vide (rien entre les crochets []), nous pouvons utiliser un pointeur de fonction ordinaire. std::function ou la déduction de type via le mot-clé auto fonctionnent aussi (même si la lambda a une clause de capture non vide).

#include <functional>

int main()
{
  // Un pointeur de fonction ordinaire. Ne fonctionne qu'avec une clause de capture vide ([]).
  double (*addNumbers1)(double, double){
    [](double a, double b) {
      return a + b;
    }
  };

  addNumbers1(1, 2);

  // Utilisation de std::function. La lambda peut avoir une clause de capture non vide (abordée dans la prochaine leçon).
  std::function addNumbers2{ // note : avant C++17, utilisez plutôt std::function<double(double, double)>
    [](double a, double b) {
      return a + b;
    }
  };

  addNumbers2(3, 4);

  // Utilisation de auto. Stocke la lambda avec son type réel.
  auto addNumbers3{
    [](double a, double b) {
      return a + b;
    }
  };

  addNumbers3(5, 6);

  return 0;
}

La seule façon d'utiliser le type réel de la lambda passe par auto. auto présente en outre l'avantage de ne rien coûter en surcharge, contrairement à std::function.

Et si nous voulons passer une lambda à une fonction ? Il existe 4 options :

#include <functional>
#include <iostream>

// Cas 1 : utiliser un paramètre de type std::function
void repeat1(int repetitions, const std::function<void(int)>& fn)
{
    for (int i{ 0 }; i < repetitions; ++i)
        fn(i);
}

// Cas 2 : utiliser un modèle de fonction avec un paramètre de modèle de type
template <typename T>
void repeat2(int repetitions, const T& fn)
{
    for (int i{ 0 }; i < repetitions; ++i)
        fn(i);
}

// Cas 3 : utiliser la syntaxe abrégée des modèles de fonction (C++20)
void repeat3(int repetitions, const auto& fn)
{
    for (int i{ 0 }; i < repetitions; ++i)
        fn(i);
}

// Cas 4 : utiliser un pointeur de fonction (uniquement pour une lambda sans capture)
void repeat4(int repetitions, void (*fn)(int))
{
    for (int i{ 0 }; i < repetitions; ++i)
        fn(i);   
}

int main()
{
    auto lambda = [](int i)
    {
        std::cout << i << '\n';
    };

    repeat1(3, lambda);
    repeat2(3, lambda);
    repeat3(3, lambda);
    repeat4(3, lambda);

    return 0;
}

Dans le cas 1, le paramètre de la fonction est un std::function. C'est pratique, car nous voyons explicitement les paramètres et le type de retour du std::function. Cependant, cela oblige la lambda à être convertie implicitement à chaque appel de la fonction, ce qui ajoute une certaine surcharge. Cette méthode a également l'avantage de pouvoir être séparée en une déclaration (dans un en-tête) et une définition (dans un fichier .cpp) si on le souhaite.

Dans le cas 2, nous utilisons un modèle de fonction avec le paramètre de modèle de type T. Lors de l'appel de la fonction, une fonction est instanciée où T correspond au type réel de la lambda. C'est plus efficace, mais les paramètres et le type de retour de T ne sont pas évidents.

Dans le cas 3, nous utilisons la fonctionnalité auto de C++20 pour employer la syntaxe abrégée des modèles de fonction. Cela génère un modèle de fonction identique au cas 2.

Dans le cas 4, le paramètre de la fonction est un pointeur de fonction. Comme une lambda sans capture se convertit implicitement en pointeur de fonction, nous pouvons passer une lambda sans capture à cette fonction.

Bonne pratique

Lorsque vous stockez une lambda dans une variable, utilisez auto comme type de la variable.

Lorsque vous passez une lambda à une fonction :

  • Si vous utilisez C++20, utilisez auto comme type du paramètre.
  • Sinon, utilisez une fonction avec un paramètre de type modèle ou un paramètre std::function (ou un pointeur de fonction si la lambda n'a pas de capture).

Lambdas génériques

Pour l'essentiel, les paramètres d'une lambda fonctionnent selon les mêmes règles que ceux d'une fonction ordinaire.

Une exception notable : depuis C++14, il est permis d'utiliser auto pour les paramètres (notez qu'en C++20, les fonctions ordinaires peuvent elles aussi utiliser auto pour leurs paramètres). Lorsqu'une lambda possède un ou plusieurs paramètres auto, le compilateur déduit les types de paramètres nécessaires à partir des appels de la lambda.

Comme les lambdas avec un ou plusieurs paramètres auto peuvent potentiellement travailler avec une grande variété de types, on les appelle lambdas génériques (generic lambdas).

Pour les lecteurs avancés

Dans le contexte d'une lambda, auto n'est qu'un raccourci pour un paramètre de modèle.

Examinons une lambda générique :

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>

int main()
{
  constexpr std::array months{ // avant C++17, utilisez std::array<const char*, 12>
    "January",
    "February",
    "March",
    "April",
    "May",
    "June",
    "July",
    "August",
    "September",
    "October",
    "November",
    "December"
  };

  // Rechercher deux mois consécutifs qui commencent par la même lettre.
  const auto sameLetter{ std::adjacent_find(months.begin(), months.end(),
                                      [](const auto& a, const auto& b) {
                                        return a[0] == b[0];
                                      }) };

  // Vérifier que deux mois ont bien été trouvés.
  if (sameLetter != months.end())
  {
    // std::next renvoie l'itérateur suivant sameLetter
    std::cout << *sameLetter << " and " << *std::next(sameLetter)
              << " start with the same letter\n";
  }

  return 0;
}

Sortie :


June and July start with the same letter

Dans l'exemple ci-dessus, nous utilisons des paramètres auto pour capturer nos chaînes par référence const. Comme tous les types de chaînes permettent d'accéder à leurs caractères individuels via operator[], nous n'avons pas à nous soucier de savoir si l'utilisateur passe un std::string, une chaîne de style C ou autre chose. Cela nous permet d'écrire une lambda qui accepte chacun de ces types ; si nous changeons plus tard le type de months, nous n'aurons pas à réécrire la lambda.

Cependant, auto n'est pas toujours le meilleur choix. Considérez :

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>

int main()
{
  constexpr std::array months{ // avant C++17, utilisez std::array<const char*, 12>
    "January",
    "February",
    "March",
    "April",
    "May",
    "June",
    "July",
    "August",
    "September",
    "October",
    "November",
    "December"
  };

  // Compter combien de mois comportent 5 lettres
  const auto fiveLetterMonths{ std::count_if(months.begin(), months.end(),
                                       [](std::string_view str) {
                                         return str.length() == 5;
                                       }) };

  std::cout << "There are " << fiveLetterMonths << " months with 5 letters\n";

  return 0;
}

Sortie :


There are 2 months with 5 letters

Dans cet exemple, utiliser auto aurait conduit à déduire le type const char*. Les chaînes de style C ne sont pas faciles à manipuler (à part avec operator[]). Dans ce cas, nous préférons définir explicitement le paramètre comme un std::string_view, ce qui nous permet de travailler beaucoup plus facilement avec les données sous-jacentes (par exemple, nous pouvons demander à la vue de chaîne sa longueur, même si l'utilisateur a passé un tableau de style C).

Lambdas constexpr

Depuis C++17, les lambdas sont implicitement constexpr si leur résultat satisfait les exigences d'une expression constante. Cela demande généralement deux choses :

  • La lambda ne doit avoir aucune capture, ou toutes ses captures doivent être constexpr.
  • Les fonctions appelées par la lambda doivent être constexpr. Notez que de nombreux algorithmes de la bibliothèque standard et fonctions mathématiques n'ont été rendus constexpr qu'en C++20 ou C++23.

Dans l'exemple ci-dessus, notre lambda ne serait pas implicitement constexpr en C++17, mais elle le serait en C++20 (puisque std::count_if est devenue constexpr en C++20). Cela signifie qu'en C++20, nous pouvons rendre fiveLetterMonths constexpr :

  constexpr auto fiveLetterMonths{ std::count_if(months.begin(), months.end(),
                                       [](std::string_view str) {
                                         return str.length() == 5;
                                       }) };

Lambdas génériques et variables statiques

Dans la leçon 11.7 -- Instanciation des modèles de fonctions, nous avons expliqué que lorsqu'un modèle de fonction contient une variable locale statique, chaque fonction instanciée à partir de ce modèle reçoit sa propre variable locale statique indépendante. Cela peut poser problème si ce comportement n'est pas attendu.

Les lambdas génériques fonctionnent de la même façon : une lambda unique est générée pour chaque type différent vers lequel auto se résout.

L'exemple suivant montre comment une lambda générique se transforme en deux lambdas distinctes :

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>

int main()
{
  // Afficher une valeur et compter combien de fois @print a été appelée.
  auto print{
    [](auto value) {
      static int callCount{ 0 };
      std::cout << callCount++ << ": " << value << '\n';
    }
  };

  print("hello"); // 0: hello
  print("world"); // 1: world

  print(1); // 0: 1
  print(2); // 1: 2

  print("ding dong"); // 2: ding dong

  return 0;
}

Sortie :


0: hello
1: world
0: 1
1: 2
2: ding dong

Dans l'exemple ci-dessus, nous définissons une lambda puis l'appelons avec deux paramètres différents (un paramètre littéral de chaîne et un paramètre entier). Cela génère deux versions différentes de la lambda (l'une avec un paramètre littéral de chaîne, l'autre avec un paramètre entier).

La plupart du temps, cela n'a pas de conséquence. Cependant, notez que si la lambda générique utilise des variables à durée de stockage statique, ces variables ne sont pas partagées entre les lambdas générées.

On le voit dans l'exemple ci-dessus : chaque type (littéraux de chaînes et entiers) possède son propre compteur ! Bien que nous n'ayons écrit la lambda qu'une seule fois, deux lambdas ont été générées, et chacune possède sa propre version de callCount. Pour avoir un compteur partagé entre les deux lambdas générées, il faudrait définir une variable globale ou une variable locale static en dehors de la lambda. Comme vous le savez depuis les leçons précédentes, les variables globales comme les variables locales statiques peuvent causer des problèmes et rendre le code plus difficile à comprendre. Nous pourrons nous passer de ces variables après avoir abordé les captures de lambdas dans la prochaine leçon.

Déduction du type de retour et types de retour finaux

Si la déduction du type de retour est utilisée, le type de retour d'une lambda est déduit des instructions return situées à l'intérieur de la lambda, et toutes les instructions return de la lambda doivent renvoyer le même type (sinon le compilateur ne saura pas lequel privilégier).

Par exemple :

#include <iostream>

int main()
{
  auto divide{ [](int x, int y, bool intDivision) { // note : aucun type de retour spécifié
    if (intDivision)
      return x / y; // le type de retour est int
    else
      return static_cast<double>(x) / y; // ERREUR : le type de retour ne correspond pas au type de retour précédent
  } };

  std::cout << divide(3, 2, true) << '\n';
  std::cout << divide(3, 2, false) << '\n';

  return 0;
}

Cela produit une erreur de compilation, car le type de retour de la première instruction return (int) ne correspond pas à celui de la seconde (double).

Lorsque nous renvoyons des types différents, nous avons deux options :

  1. Effectuer des conversions explicites pour que tous les types de retour correspondent, ou
  2. Spécifier explicitement un type de retour pour la lambda et laisser le compilateur effectuer les conversions implicites.

La seconde option est généralement le meilleur choix :

#include <iostream>

int main()
{
  // note : spécifier explicitement que cela renvoie un double
  auto divide{ [](int x, int y, bool intDivision) -> double {
    if (intDivision)
      return x / y; // effectuera une conversion implicite du résultat en double
    else
      return static_cast<double>(x) / y;
  } };

  std::cout << divide(3, 2, true) << '\n';
  std::cout << divide(3, 2, false) << '\n';

  return 0;
}

Ainsi, si vous décidez un jour de changer le type de retour, vous n'aurez (généralement) qu'à modifier le type de retour de la lambda, sans toucher à son corps.

Objets fonctions de la bibliothèque standard

Pour les opérations courantes (par exemple l'addition, la négation ou la comparaison), vous n'avez pas besoin d'écrire vos propres lambdas, car la bibliothèque standard fournit de nombreux objets appelables de base qui peuvent être utilisés à la place. Ils sont définis dans l'en-tête <functional>.

Dans l'exemple suivant :

#include <algorithm>
#include <array>
#include <iostream>

bool greater(int a, int b)
{
  // Place @a avant @b si @a est supérieur à @b.
  return a > b;
}

int main()
{
  std::array arr{ 13, 90, 99, 5, 40, 80 };

  // Passer greater à std::sort
  std::sort(arr.begin(), arr.end(), greater);

  for (int i : arr)
  {
    std::cout << i << ' ';
  }

  std::cout << '\n';

  return 0;
}

Sortie :


99 90 80 40 13 5

Plutôt que de transformer notre fonction greater en lambda (ce qui obscurcirait un peu son sens), nous pouvons utiliser std::greater :

#include <algorithm>
#include <array>
#include <iostream>
#include <functional> // pour std::greater

int main()
{
  std::array arr{ 13, 90, 99, 5, 40, 80 };

  // Passer std::greater à std::sort
  std::sort(arr.begin(), arr.end(), std::greater{}); // note : les accolades sont nécessaires pour instancier l'objet

  for (int i : arr)
  {
    std::cout << i << ' ';
  }

  std::cout << '\n';

  return 0;
}

Sortie :


99 90 80 40 13 5

Conclusion

Les lambdas et la bibliothèque d'algorithmes peuvent sembler inutilement compliquées par rapport à une solution utilisant une boucle. Pourtant, cette combinaison permet de réaliser des opérations très puissantes en quelques lignes de code, et peut être plus lisible que l'écriture de vos propres boucles. De plus, la bibliothèque d'algorithmes offre un parallélisme puissant et facile à utiliser, que les boucles ne permettent pas. Mettre à jour du code qui utilise des fonctions de la bibliothèque est aussi plus simple que mettre à jour du code qui utilise des boucles.

Les lambdas sont formidables, mais elles ne remplacent pas les fonctions ordinaires dans tous les cas. Privilégiez les fonctions ordinaires pour les cas non triviaux et réutilisables.

#include <algorithm>
#include <array>
#include <iostream>
#include <string_view>

struct Season
{
  std::string_view name{};
  double averageTemperature{};
};

int main()
{
  std::array<Season, 4> seasons{
    { { "Spring", 285.0 },
      { "Summer", 296.0 },
      { "Fall", 288.0 },
      { "Winter", 263.0 } }
  };

  // Nous pouvons comparer averageTemperature des deux arguments pour
  // trier le tableau.
  std::sort(seasons.begin(), seasons.end(),
            [](const auto& a, const auto& b) {
              return a.averageTemperature < b.averageTemperature;
            });

  for (const auto& season : seasons)
  {
    std::cout << season.name << '\n';
  }

  return 0;
}
