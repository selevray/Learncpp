5.x — Résumé du chapitre 5 et quiz

Résumé du chapitre

Une constante (constant) est une valeur qui ne peut pas être modifiée pendant l'exécution du programme. C++ prend en charge deux types de constantes : les constantes nommées (named constants) et les littéraux (literals).

Une constante nommée est une valeur constante associée à un identifiant. Une constante littérale (literal constant) est une valeur constante non associée à un identifiant.

Une variable dont la valeur ne peut pas être modifiée est appelée une variable constante (constant variable). Le mot-clé const permet de rendre une variable constante. Les variables constantes doivent être initialisées. Évitez d'utiliser const lors du passage par valeur ou du retour par valeur.

Un qualificateur de type (type qualifier) est un mot-clé appliqué à un type qui modifie son comportement. Depuis C++23, C++ ne prend en charge que const et volatile comme qualificateurs de type.

Une expression constante (constant expression) est une expression pouvant être évaluée à la compilation. Une expression qui n'est pas une expression constante est parfois appelée une expression d'exécution (runtime expression).

Une constante de compilation (compile-time constant) est une constante dont la valeur est connue à la compilation. Une constante d'exécution (runtime constant) est une constante dont la valeur d'initialisation n'est connue qu'à l'exécution.

Une variable constexpr doit être une constante de compilation, initialisée avec une expression constante. Les paramètres de fonction ne peuvent pas être constexpr.

Les littéraux (literals) sont des valeurs insérées directement dans le code. Les littéraux ont des types, et les suffixes littéraux peuvent être utilisés pour changer le type d'un littéral par rapport à son type par défaut.

Un nombre magique (magic number) est un littéral (généralement un nombre) dont la signification n'est pas claire ou qui peut devoir être modifié ultérieurement. N'utilisez pas de nombres magiques dans votre code. Utilisez plutôt des constantes symboliques.

Dans la vie courante, nous comptons avec des nombres décimaux (decimal), qui utilisent 10 chiffres. Les ordinateurs utilisent le binaire (binary), qui n'a que 2 chiffres. C++ prend aussi en charge l'octal (base 8) et l'hexadécimal (base 16). Ce sont tous des exemples de systèmes de numération (numeral systems), c'est-à-dire des ensembles de symboles (chiffres) servant à représenter des nombres.

Une chaîne de caractères (string) est une suite de caractères servant à représenter du texte (noms, mots, phrases). Les littéraux de chaîne sont toujours placés entre guillemets doubles. Les littéraux de chaîne en C++ sont des chaînes de style C (C-style strings), dont le type étrange est difficile à manipuler.

std::string offre un moyen simple et sûr de manipuler des chaînes de texte. std::string est défini dans l'en-tête <string>. std::string est coûteux à initialiser (ou à affecter) et à copier.

std::string_view fournit un accès en lecture seule à une chaîne existante (un littéral de chaîne de style C, une std::string ou un tableau de char) sans en faire une copie. Une std::string_view qui observe une chaîne détruite est parfois appelée une vue pendante (dangling). Lorsqu'une std::string est modifiée, toutes les vues sur cette std::string sont invalidées, c'est-à-dire qu'elles ne sont plus valides. Utiliser une vue invalidée (autrement que pour la revalider) produit un comportement indéfini (undefined behavior).

Comme les littéraux de chaîne de style C existent pendant toute la durée du programme, il est possible d'affecter un littéral de chaîne de style C à une std::string_view, et même de retourner une telle std::string_view depuis une fonction.

Une sous-chaîne (substring) est une suite contiguë de caractères au sein d'une chaîne existante.

Quiz

Question n° 1

Pourquoi les constantes nommées sont-elles souvent un meilleur choix que les constantes littérales ?

Solution

Utiliser des constantes littérales (autrement dit des nombres magiques) dans un programme le rend plus difficile à comprendre et à modifier. Les constantes symboliques permettent de documenter ce que représentent réellement les nombres, et modifier une constante symbolique à sa déclaration change la valeur partout où elle est utilisée.

Pourquoi les variables const/constexpr sont-elles généralement un meilleur choix que les constantes symboliques définies avec #define ?

Solution

Les constantes définies par #define n'apparaissent pas dans le débogueur et sont plus susceptibles de provoquer des conflits de noms.

Question n° 2

Trouvez 3 problèmes dans le code suivant :

#include <cstdint> // for std::uint8_t
#include <iostream>

int main()
{
  std::cout << "How old are you?\n";

  std::uint8_t age{};
  std::cin >> age;

  std::cout << "Allowed to drive a car in Texas: ";

  if (age >= 16)
      std::cout << "Yes";
  else
      std::cout << "No";

  std::cout << '.\n';

  return 0;
}

Exemple de sortie souhaitée :


How old are you?
6
Allowed to drive a car in Texas: No


How old are you?
19
Allowed to drive a car in Texas: Yes
Solution
  1. À la ligne 8, age est défini comme un std::uint8_t. Comme std::uint8_t est généralement défini comme un type char, cela fait que le programme se comporte comme s'il lisait et écrivait une valeur de type char plutôt qu'une valeur numérique. Par exemple, si l'utilisateur saisit son âge « 18 », seul le caractère '1' sera extrait. Comme '1' a pour valeur ASCII 49, l'utilisateur serait traité comme s'il avait 49 ans. Un int ordinaire devrait être utilisé pour stocker l'âge, car celui-ci n'exige pas une largeur entière minimale particulière. On peut aussi supprimer #include <cstdint>.
  2. À la ligne 13, nous utilisons le nombre magique 16. Bien que la signification de 16 soit claire dans le contexte où il est utilisé, il est préférable d'utiliser une variable constexpr de valeur 16.
  3. À la ligne 18, '.\n' est un littéral multicaractère qui affichera une valeur incorrecte. Il devrait être entre guillemets doubles (".\n").

Question n° 3

Quelles sont les principales différences entre std::string et std::string_view ?

Qu'est-ce qui peut mal se passer lors de l'utilisation d'une std::string_view ?

Solution

std::string fournit une chaîne modifiable. Elle est coûteuse à initialiser et à copier.

std::string_view fournit une vue en lecture seule d'une chaîne qui existe ailleurs. Elle est peu coûteuse à initialiser et à copier. std::string_view peut être dangereuse lorsque la chaîne observée est détruite avant la std::string_view qui l'observe.

Question n° 4

Écrivez un programme qui demande le nom et l'âge de deux personnes, puis affiche laquelle est la plus âgée.

Voici un exemple de sortie obtenue lors d'une exécution du programme :


Enter the name of person #1: John Bacon
Enter the age of John Bacon: 37
Enter the name of person #2: David Jenkins
Enter the age of David Jenkins: 44
David Jenkins (age 44) is older than John Bacon (age 37).
Indice

Indice : saisissez le nom de la personne à l'aide de std::getline()

Solution 
#include <iostream>
#include <string>
#include <string_view>

std::string getName(int num)
{
    std::cout << "Enter the name of person #" << num << ": ";
    std::string name{};
    std::getline(std::cin >> std::ws, name); // lit une ligne complète de texte dans name

    return name;
}

int getAge(std::string_view sv)
{
    std::cout << "Enter the age of " << sv << ": ";
    int age{};
    std::cin >> age;

    return age;
}

void printOlder(std::string_view name1, int age1, std::string_view name2, int age2)
{
    if (age1 > age2)
        std::cout << name1 << " (age " << age1 <<") is older than " << name2 << " (age " << age2 <<").\n";
    else
        std::cout << name2 << " (age " << age2 <<") is older than " << name1 << " (age " << age1 <<").\n";
}

int main()
{
    const std::string name1{ getName(1) };
    const int age1 { getAge(name1) };

    const std::string name2{ getName(2) };
    const int age2 { getAge(name2) };

    printOlder(name1, age1, name2, age2);

    return 0;
}

Question n° 5

Dans la solution de l'exercice précédent, pourquoi la variable age1 de main ne peut-elle pas être constexpr ?

Solution

Une variable constexpr exige un initialisateur qui soit une expression constante, et l'appel à getAge() n'est pas autorisé dans une expression constante. On ne peut donc la rendre que const.
