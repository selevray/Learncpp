5.6 — Variables constexpr

Dans la leçon précédente 5.5 -- Expressions constantes, nous avons défini ce qu'est une expression constante, expliqué pourquoi les expressions constantes sont souhaitables, et conclu en indiquant quand les expressions constantes sont réellement évaluées à la compilation.

Dans cette leçon, nous allons examiner de plus près la manière de créer des variables utilisables dans des expressions constantes en C++ moderne. Nous explorerons aussi notre première méthode pour garantir qu'un code s'exécute effectivement à la compilation.

Le défi du const à la compilation

Dans la leçon précédente, nous avons noté qu'une façon de créer une variable utilisable dans une expression constante consiste à employer le mot-clé const. Une variable const de type entier avec un initialisateur qui est une expression constante peut être utilisée dans une expression constante. Toutes les autres variables const ne peuvent pas être utilisées dans des expressions constantes.

Cependant, l'utilisation de const pour créer des variables utilisables dans des expressions constantes pose quelques difficultés.

Premièrement, l'emploi de const ne indique pas immédiatement si la variable est utilisable dans une expression constante. Dans certains cas, on peut le déterminer assez facilement :

int a { 5 };       // pas du tout const
const int b { a }; // clairement pas une expression constante (car l'initialisateur n'est pas constant)
const int c { 5 }; // clairement une expression constante (car l'initialisateur est une expression constante)

Dans d'autres cas, c'est beaucoup plus difficile :

const int d { someVar };    // pas évident de savoir si d est utilisable dans une expression constante
const int e { getValue() }; // pas évident de savoir si e est utilisable dans une expression constante

Dans l'exemple ci-dessus, les variables d et e peuvent ou non être utilisables dans des expressions constantes, selon la façon dont someVar et getValue() sont définis. Il faut donc examiner la définition de ces initialisateurs et en déduire le cas dans lequel on se trouve. Et cela peut même ne pas suffire : si someVar est const et initialisée avec une variable ou un appel de fonction, il faudra aussi examiner la définition de son propre initialisateur !

Deuxièmement, const ne permet pas d'indiquer au compilateur que nous avons besoin d'une variable utilisable dans une expression constante (et qu'il doit interrompre la compilation si ce n'est pas le cas). À la place, il crée silencieusement une variable qui ne peut être utilisée que dans des expressions à l'exécution.

Troisièmement, l'utilisation de const pour créer des variables constantes à la compilation ne s'applique pas aux variables de types non entiers. Or il existe de nombreux cas où nous aimerions que des variables non entières soient aussi des constantes de compilation.

Le mot-clé constexpr

Heureusement, nous pouvons demander l'aide du compilateur pour obtenir une variable constante à la compilation là où nous en voulons une. Pour cela, on utilise le mot-clé constexpr (abréviation de « constant expression ») à la place de const dans la déclaration de la variable. Une variable constexpr est toujours une constante de compilation. Par conséquent, une variable constexpr doit être initialisée avec une expression constante, faute de quoi une erreur de compilation se produit.

Par exemple :

#include <iostream>

// La valeur de retour d'une fonction non constexpr n'est pas constexpr
int five()
{
    return 5;
}

int main()
{
    constexpr double gravity { 9.8 }; // ok : 9.8 est une expression constante
    constexpr int sum { 4 + 5 };      // ok : 4 + 5 est une expression constante
    constexpr int something { sum };  // ok : sum est une expression constante

    std::cout << "Entrez votre âge : ";
    int age{};
    std::cin >> age;

    constexpr int myAge { age };      // erreur de compilation : age n'est pas une expression constante
    constexpr int f { five() };       // erreur de compilation : la valeur de retour de five() n'est pas constexpr

    return 0;
}

Comme les fonctions s'exécutent normalement à l'exécution, la valeur de retour d'une fonction n'est pas constexpr (même lorsque l'expression de retour est une expression constante). C'est pourquoi five() n'est pas une valeur d'initialisation légale pour constexpr int f.

Contenu connexe

Nous parlons des fonctions dont les valeurs de retour peuvent être utilisées dans des expressions constantes dans la leçon F.1 -- Fonctions constexpr.

De plus, constexpr fonctionne pour les variables de types non entiers :

constexpr double d { 1.2 }; // d peut être utilisée dans des expressions constantes !

Signification de const et constexpr pour les variables

Pour les variables :

  • const signifie que la valeur d'un objet ne peut pas être modifiée après l'initialisation. La valeur de l'initialisateur peut être connue à la compilation ou à l'exécution. L'objet const peut être évalué à l'exécution.
  • constexpr signifie que l'objet peut être utilisé dans une expression constante. La valeur de l'initialisateur doit être connue à la compilation. L'objet constexpr peut être évalué à l'exécution ou à la compilation.

Les variables constexpr sont implicitement const. Les variables const ne sont pas implicitement constexpr (sauf pour les variables const de type entier avec un initialisateur qui est une expression constante). Bien qu'une variable puisse être définie à la fois constexpr et const, dans la plupart des cas c'est redondant, et il suffit d'utiliser soit const, soit constexpr.

Contrairement à const, constexpr ne fait pas partie du type d'un objet. Ainsi, une variable déclarée constexpr int a en réalité le type const int (en raison du const implicite que constexpr apporte aux objets).

Bonne pratique

Toute variable constante dont l'initialisateur est une expression constante doit être déclarée constexpr.

Toute variable constante dont l'initialisateur n'est pas une expression constante (faisant d'elle une constante à l'exécution) doit être déclarée const.

Mise en garde : nous verrons plus tard que certains types ne sont pas entièrement compatibles avec constexpr (notamment std::string, std::vector, et les autres types qui utilisent l'allocation dynamique de mémoire). Pour les objets constants de ces types, utilisez soit const à la place de constexpr, soit un autre type compatible avec constexpr (par exemple std::string_view ou std::array).

Nomenclature

Le terme constexpr est un mot-valise formé à partir de « constant expression ». Ce nom a été choisi parce que les objets (et les fonctions) constexpr peuvent être utilisés dans des expressions constantes.

Formellement, le mot-clé constexpr ne s'applique qu'aux objets et aux fonctions. Par convention, le terme constexpr est employé comme abréviation pour toute expression constante (comme 1 + 2).

Pour les lecteurs avancés

En C et en C++, la déclaration d'un objet tableau (un objet pouvant contenir plusieurs valeurs) exige que la longueur du tableau (le nombre de valeurs qu'il peut contenir) soit connue à la compilation (afin que le compilateur puisse allouer la quantité de mémoire correcte pour les objets tableaux).

Comme les littéraux sont connus à la compilation, ils peuvent servir de longueur de tableau :

int arr[5]; // un tableau de 5 valeurs int, longueur de 5 connue à la compilation

Dans de nombreux cas, il serait préférable d'utiliser une constante symbolique comme longueur de tableau (par exemple pour éviter les nombres magiques et faciliter la modification de la longueur si elle est utilisée à plusieurs endroits). En C, cela peut se faire via une macro du préprocesseur, ou via un énumérateur, mais pas via une variable const (à l'exception des VLA, qui ont d'autres inconvénients). Le C++, cherchant à améliorer cette situation, voulait permettre l'utilisation de variables const à la place des macros. Mais la valeur des variables était généralement supposée connue uniquement à l'exécution, ce qui les rendait inéligibles à une utilisation comme longueur de tableau.

Pour résoudre ce problème, la norme du langage C++ a ajouté une exception : les types entiers const avec un initialisateur qui est une expression constante seraient traités comme des valeurs connues à la compilation, et pourraient donc servir de longueurs de tableau :

const int arrLen = 5;
int arr[arrLen]; // ok : tableau de 5 int

Lorsque C++11 a introduit les expressions constantes, il était logique qu'un const int avec un initialisateur qui est une expression constante soit admis dans cette définition par tolérance. Le comité a discuté de l'extension de cette règle à d'autres types, mais a finalement décidé de ne pas le faire.

Paramètres de fonction const et constexpr

Les appels de fonctions normaux sont évalués à l'exécution, les arguments fournis servant à initialiser les paramètres de la fonction. Comme l'initialisation des paramètres de fonction a lieu à l'exécution, cela entraîne deux conséquences :

  1. Les paramètres de fonction const sont traités comme des constantes à l'exécution (même lorsque l'argument fourni est une constante de compilation).
  2. Les paramètres de fonction ne peuvent pas être déclarés constexpr, puisque leur valeur d'initialisation n'est déterminée qu'à l'exécution.

Contenu connexe

Nous abordons ci-dessous les fonctions pouvant être évaluées à la compilation (et donc utilisées dans des expressions constantes).

Le C++ propose aussi un moyen de transmettre des constantes de compilation à une fonction. Nous en parlerons dans la leçon 11.9 -- Paramètres non-type des modèles.

Récapitulatif de la nomenclature

Terme Définition
Constante de compilation Une valeur ou un objet non modifiable dont la valeur doit être connue à la compilation (par exemple les littéraux et les variables constexpr).
Constexpr Mot-clé qui déclare des objets comme constantes de compilation (et des fonctions pouvant être évaluées à la compilation). Familièrement, abréviation de « constant expression ».
Expression constante Une expression qui ne contient que des constantes de compilation et des opérateurs/fonctions prenant en charge l'évaluation à la compilation.
Expression à l'exécution Une expression qui n'est pas une expression constante.
Constante à l'exécution Une valeur ou un objet non modifiable qui n'est pas une constante de compilation.

Brève introduction aux fonctions constexpr

Une fonction constexpr est une fonction qui peut être appelée dans une expression constante. Une fonction constexpr doit être évaluée à la compilation lorsque l'expression constante dont elle fait partie doit être évaluée à la compilation (par exemple dans l'initialisateur d'une variable constexpr). Sinon, une fonction constexpr peut être évaluée soit à la compilation (si elle y est éligible), soit à l'exécution. Pour être éligible à une exécution à la compilation, tous les arguments doivent être des expressions constantes.

Pour créer une fonction constexpr, le mot-clé constexpr est placé dans la déclaration de la fonction, avant le type de retour :

#include <iostream>

int max(int x, int y) // ceci est une fonction non constexpr
{
    if (x > y)
        return x;
    else
        return y;
}

constexpr int cmax(int x, int y) // ceci est une fonction constexpr
{
    if (x > y)
        return x;
    else
        return y;
}

int main()
{
    int m1 { max(5, 6) };            // ok
    const int m2 { max(5, 6) };      // ok
    constexpr int m3 { max(5, 6) };  // erreur de compilation : max(5, 6) n'est pas une expression constante

    int m4 { cmax(5, 6) };           // ok : peut être évaluée à la compilation ou à l'exécution
    const int m5 { cmax(5, 6) };     // ok : peut être évaluée à la compilation ou à l'exécution
    constexpr int m6 { cmax(5, 6) }; // ok : doit être évaluée à la compilation

    return 0;
}
