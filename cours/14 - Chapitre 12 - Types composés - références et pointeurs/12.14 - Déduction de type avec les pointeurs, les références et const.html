12.14 — Déduction de type avec les pointeurs, les références et const

Dans la leçon 10.8 -- Déduction de type pour les objets avec le mot-clé auto, nous avons vu comment le mot-clé auto permet au compilateur de déduire le type d'une variable à partir de son initialisation :

int main()
{
    int a { 5 };
    auto b { a }; // b est déduit comme int

    return 0;
}

Nous avons aussi indiqué que, par défaut, la déduction de type supprime le const des types :

int main()
{
    const double a { 7.8 }; // a a le type const double
    auto b { a };           // b a le type double (const supprimé)

    constexpr double c { 7.8 }; // c a le type const double (constexpr applique implicitement const)
    auto d { c };               // d a le type double (const supprimé)

    return 0;
}

On peut réappliquer const (ou constexpr) en ajoutant ce qualificateur à la définition du type déduit :

int main()
{
    double a { 7.8 };    // a a le type double
    const auto b { a };  // b a le type const double (const appliqué)

    constexpr double c { 7.8 }; // c a le type const double (constexpr applique implicitement const)
    const auto d { c };         // d est const double (const supprimé, const réappliqué)
    constexpr auto e { c };     // e est constexpr double (const supprimé, constexpr réappliqué)

    return 0;
}

La déduction de type supprime les références

En plus de supprimer const, la déduction de type supprime aussi les références :

#include <string>

std::string& getRef(); // une fonction qui renvoie une référence

int main()
{
    auto ref { getRef() }; // type déduit std::string (et non std::string&)

    return 0;
}

Dans l'exemple ci-dessus, la variable ref utilise la déduction de type. Bien que la fonction getRef() renvoie un std::string&, le qualificateur de référence est supprimé : le type de ref est donc déduit comme std::string.

Comme pour const supprimé, si vous voulez que le type déduit soit une référence, vous pouvez réappliquer la référence au moment de la définition :

#include <string>

std::string& getRef(); // une fonction qui renvoie une référence

int main()
{
    auto ref1 { getRef() };  // std::string (référence supprimée)
    auto& ref2 { getRef() }; // std::string& (référence supprimée, puis réappliquée)

    return 0;
}

const de haut niveau et const de bas niveau

Un const de haut niveau (top-level const) est un qualificateur const qui s'applique à l'objet lui-même. Par exemple :

const int x;    // ce const s'applique à x, il est donc de haut niveau
int* const ptr; // ce const s'applique à ptr, il est donc de haut niveau
// les références n'ont pas de syntaxe pour un const de haut niveau, car elles sont implicitement const de haut niveau

À l'inverse, un const de bas niveau (low-level const) est un qualificateur const qui s'applique à l'objet référencé ou pointé :

const int& ref; // ce const s'applique à l'objet référencé, il est donc de bas niveau
const int* ptr; // ce const s'applique à l'objet pointé, il est donc de bas niveau

Une référence à une valeur const est toujours un const de bas niveau. Un pointeur peut avoir un const de haut niveau, un const de bas niveau, ou les deux :

const int* const ptr; // le const de gauche est de bas niveau, celui de droite est de haut niveau

Lorsque nous disons que la déduction de type supprime les qualificateurs const, cela ne concerne que les const de haut niveau. Les const de bas niveau ne sont pas supprimés. Nous verrons des exemples dans un instant.

Déduction de type et références const

Si l'initialisation est une référence à const, la référence est d'abord supprimée (puis réappliquée si nécessaire), et ensuite tout const de haut niveau est supprimé du résultat.

#include <string>

const std::string& getConstRef(); // une fonction qui renvoie une référence à const

int main()
{
    auto ref1{ getConstRef() }; // std::string (référence supprimée, puis const de haut niveau supprimé du résultat)

    return 0;
}

Dans l'exemple ci-dessus, comme getConstRef() renvoie un const std::string&, la référence est d'abord supprimée, ce qui nous laisse un const std::string. Ce const est maintenant de haut niveau, il est donc aussi supprimé, et le type déduit est std::string.

Point clé

Supprimer une référence peut transformer un const de bas niveau en const de haut niveau : const std::string& est un const de bas niveau, mais supprimer la référence donne const std::string, qui est un const de haut niveau.

On peut réappliquer une référence et/ou const :

#include <string>

const std::string& getConstRef(); // une fonction qui renvoie une référence const

int main()
{
    auto ref1{ getConstRef() };        // std::string (référence et const de haut niveau supprimés)
    const auto ref2{ getConstRef() };  // const std::string (référence supprimée, const supprimé, const réappliqué)

    auto& ref3{ getConstRef() };       // const std::string& (référence supprimée puis réappliquée, const de bas niveau non supprimé)
    const auto& ref4{ getConstRef() }; // const std::string& (référence supprimée puis réappliquée, const de bas niveau non supprimé)

    return 0;
}

Nous avons déjà traité le cas de ref1 dans l'exemple précédent. Pour ref2, le cas est similaire à celui de ref1, sauf que nous réappliquons le qualificateur const, donc le type déduit est const std::string.

Le cas de ref3 est plus intéressant. Normalement la référence serait supprimée d'abord, mais comme nous l'avons réappliquée, elle n'est pas supprimée. Le type reste donc const std::string&. Et comme ce const est un const de bas niveau, il n'est pas supprimé. Le type déduit est donc const std::string&.

Le cas de ref4 fonctionne comme ref3, à la différence près que nous réappliquons aussi le qualificateur const. Comme le type est déjà déduit comme une référence à const, réappliquer const ici est redondant. Cela dit, l'utiliser rend explicite le fait que le résultat sera const (alors que, dans le cas de ref3, la constance du résultat est implicite et peu évidente).

Bonne pratique

Si vous voulez une référence const, réappliquez le qualificateur const même lorsqu'il n'est pas strictement nécessaire : cela rend votre intention claire et aide à éviter les erreurs.

Et les références constexpr ?

constexpr ne fait pas partie du type d'une expression : il n'est donc pas déduit par auto.

Rappel

Lorsqu'on définit une référence const (par exemple const int&), le const s'applique à l'objet référencé, et non à la référence elle-même.

Lorsqu'on définit une référence constexpr vers une variable const (par exemple constexpr const int&), il faut appliquer à la fois constexpr (qui s'applique à la référence) et const (qui s'applique au type référencé).

Ce point est traité dans la leçon 12.4 -- Références lvalue vers const.

#include <string_view>
#include <iostream>

constexpr std::string_view hello { "Hello" };   // implicitement const

constexpr const std::string_view& getConstRef() // la fonction est constexpr, elle renvoie un const std::string_view&
{
    return hello;
}

int main()
{
    auto ref1{ getConstRef() };                  // std::string_view (référence et const de haut niveau supprimés)
    constexpr auto ref2{ getConstRef() };        // constexpr const std::string_view (référence et const de haut niveau supprimés, constexpr appliqué, const implicite)

    auto& ref3{ getConstRef() };                 // const std::string_view& (référence réappliquée, const de bas niveau non supprimé)
    constexpr const auto& ref4{ getConstRef() }; // constexpr const std::string_view& (référence réappliquée, const de bas niveau non supprimé, constexpr appliqué)

    return 0;
}

Déduction de type et pointeurs

Contrairement aux références, la déduction de type ne supprime pas les pointeurs :

#include <string>

std::string* getPtr(); // une fonction qui renvoie un pointeur

int main()
{
    auto ptr1{ getPtr() }; // std::string*

    return 0;
}

On peut aussi utiliser un astérisque avec la déduction de type pour pointeur (auto*) afin de bien montrer que le type déduit est un pointeur :

#include <string>

std::string* getPtr(); // une fonction qui renvoie un pointeur

int main()
{
    auto ptr1{ getPtr() };  // std::string*
    auto* ptr2{ getPtr() }; // std::string*

    return 0;
}

Point clé

Si les références sont supprimées lors de la déduction de type alors que les pointeurs ne le sont pas, c'est parce que références et pointeurs n'ont pas la même sémantique.

Lorsque nous évaluons une référence, nous évaluons en réalité l'objet référencé. Il est donc logique, lors de la déduction de type, de déduire le type de la chose référencée, et non celui de la référence elle-même. De plus, comme on déduit un type non référence, il est très facile d'en faire une référence avec auto&. Si la déduction de type déduisait plutôt une référence, la syntaxe pour retirer la référence lorsqu'on n'en veut pas serait beaucoup plus compliquée.

En revanche, un pointeur contient l'adresse d'un objet. Lorsque nous évaluons un pointeur, nous évaluons le pointeur lui-même, et non l'objet pointé (si nous voulons cet objet, nous pouvons déréférencer le pointeur). Il est donc logique de déduire le type du pointeur, et non celui de la chose pointée.

La différence entre auto et auto* (facultatif)

Lorsqu'on utilise auto avec une initialisation de type pointeur, le type déduit pour auto inclut le pointeur. Ainsi, pour ptr1 ci-dessus, le type substitué à auto est std::string*.

Lorsqu'on utilise auto* avec une initialisation de type pointeur, le type déduit pour auto n'inclut pas le pointeur : celui-ci est réappliqué après la déduction. Ainsi, pour ptr2 ci-dessus, le type substitué à auto est std::string, puis le pointeur est réappliqué.

Dans la plupart des cas, l'effet pratique est le même (ptr1 et ptr2 se déduisent tous deux en std::string* dans l'exemple ci-dessus).

Cependant, auto et auto* présentent en pratique quelques différences. D'abord, auto* doit correspondre à une initialisation de type pointeur, sinon une erreur de compilation se produit :

#include <string>

std::string* getPtr(); // une fonction qui renvoie un pointeur

int main()
{
    auto ptr3{ *getPtr() };      // std::string (car nous avons déréférencé getPtr())
    auto* ptr4{ *getPtr() };     // ne compile pas (l'initialisation n'est pas un pointeur)

    return 0;
}

Cela a du sens : dans le cas de ptr4, auto se déduit en std::string, puis le pointeur est réappliqué. Ainsi ptr4 a le type std::string*, et on ne peut pas initialiser un std::string* avec une expression qui n'est pas un pointeur.

Ensuite, auto et auto* se comportent différemment lorsqu'on introduit const. Nous verrons cela ci-dessous.

Déduction de type et pointeurs const (facultatif)

Comme les pointeurs ne sont pas supprimés, nous n'avons pas à nous en soucier. Mais avec les pointeurs, il faut considérer à la fois le pointeur const et le pointeur vers const, ainsi que la différence entre auto et auto*. Comme pour les références, seul le const de haut niveau est supprimé lors de la déduction de type pour pointeur.

Commençons par un cas simple :

#include <string>

std::string* getPtr(); // une fonction qui renvoie un pointeur

int main()
{
    const auto ptr1{ getPtr() };  // std::string* const
    auto const ptr2 { getPtr() }; // std::string* const

    const auto* ptr3{ getPtr() }; // const std::string*
    auto* const ptr4{ getPtr() }; // std::string* const

    return 0;
}

Lorsqu'on utilise auto const ou const auto, on dit « fais du pointeur déduit un pointeur const ». Pour ptr1 et ptr2, le type déduit est donc std::string*, puis const est appliqué, ce qui donne le type final std::string* const. C'est comparable à const int et int const, qui signifient la même chose.

En revanche, avec auto*, la position du qualificateur const compte. Un const à gauche signifie « fais du pointeur déduit un pointeur vers const », tandis qu'un const à droite signifie « fais du type de pointeur déduit un pointeur const ». Ainsi ptr3 est un pointeur vers const, et ptr4 est un pointeur const.

Examinons maintenant un exemple où l'initialisation est un pointeur const vers const.

#include <string>

int main()
{
    std::string s{};
    const std::string* const ptr { &s };

    auto ptr1{ ptr };  // const std::string*
    auto* ptr2{ ptr }; // const std::string*

    auto const ptr3{ ptr };  // const std::string* const
    const auto ptr4{ ptr };  // const std::string* const

    auto* const ptr5{ ptr }; // const std::string* const
    const auto* ptr6{ ptr }; // const std::string*

    const auto const ptr7{ ptr };  // erreur : le qualificateur const ne peut pas être appliqué deux fois
    const auto* const ptr8{ ptr }; // const std::string* const

    return 0;
}

Les cas ptr1 et ptr2 sont directs. Le const de haut niveau (celui du pointeur lui-même) est supprimé. Le const de bas niveau sur l'objet pointé n'est pas supprimé. Dans les deux cas, le type final est donc const std::string*.

Les cas ptr3 et ptr4 sont également directs. Le const de haut niveau est supprimé, mais nous le réappliquons. Le const de bas niveau sur l'objet pointé n'est pas supprimé. Dans les deux cas, le type final est donc const std::string* const.

Les cas ptr5 et ptr6 sont analogues à ceux de l'exemple précédent. Dans les deux cas, le const de haut niveau est supprimé. Pour ptr5, auto* const réapplique le const de haut niveau, donc le type final est const std::string* const. Pour ptr6, const auto* applique const au type pointé (qui était déjà const), donc le type final est const std::string*.

Dans le cas de ptr7, nous appliquons deux fois le qualificateur const, ce qui est interdit et provoque une erreur de compilation.

Enfin, dans le cas de ptr8, nous appliquons const des deux côtés du pointeur (ce qui est permis, car auto* doit être un type pointeur) ; le type résultant est donc const std::string* const.

Bonne pratique

Si vous voulez un pointeur const, un pointeur vers const, ou un pointeur const vers const, réappliquez le ou les qualificateurs const même lorsqu'ils ne sont pas strictement nécessaires : cela rend votre intention claire et aide à éviter les erreurs.

Astuce

Pensez à utiliser auto* lorsque vous déduisez un type pointeur. Cela rend plus clair le fait qu'on déduit un type pointeur, fait appel au compilateur pour s'assurer que nous ne déduisons pas un type qui n'est pas un pointeur, et vous donne plus de contrôle sur const.

Résumé

Désolé d'apprendre que vous avez mal à la tête. Récapitulons rapidement les points les plus importants.

const de haut niveau et const de bas niveau :

  • Un const de haut niveau s'applique à l'objet lui-même (par exemple const int x ou int* const ptr).
  • Un const de bas niveau s'applique à l'objet accédé par une référence ou un pointeur (par exemple const int& ref, const int* ptr).

Ce que déduit la déduction de type :

  • La déduction de type supprime d'abord les références (sauf si le type déduit est défini comme une référence). Pour une référence const, supprimer la référence transforme le const (de bas niveau) en const de haut niveau.
  • La déduction de type supprime ensuite tout const de haut niveau (sauf si le type déduit est défini comme const ou constexpr).
  • constexpr ne fait pas partie du système de types : il n'est jamais déduit. Il doit toujours être appliqué explicitement au type déduit.
  • La déduction de type ne supprime pas les pointeurs.
  • Définissez toujours explicitement le type déduit comme référence, const ou constexpr (selon le cas), même lorsque ces qualificateurs seraient redondants car déduits. Cela aide à prévenir les erreurs et rend votre intention claire.

Déduction de type et pointeurs :

  • Avec auto, le type déduit est un pointeur uniquement si l'initialisation est un pointeur. Avec auto*, le type déduit est toujours un pointeur, même si l'initialisation n'en est pas un.
  • auto const et const auto rendent tous deux le pointeur déduit const. Il n'existe pas de moyen d'exprimer explicitement un const de bas niveau (pointeur vers const) avec auto.
  • auto* const rend aussi le pointeur déduit const. const auto* en fait un pointeur vers const. Si ces règles sont difficiles à retenir : int* const est un pointeur const (vers int), donc auto* const doit être un pointeur const ; const int* est un pointeur vers const (int), donc const auto* doit être un pointeur vers const.
  • Pensez à utiliser auto* plutôt que auto lorsque vous déduisez un type pointeur : il permet de réappliquer explicitement le const de haut niveau comme le const de bas niveau, et provoque une erreur si le type déduit n'est pas un pointeur.
