12.2 — Catégories de valeurs (lvalues et rvalues)

Avant de parler de notre premier type composé (les références lvalue), nous allons faire un petit détour pour expliquer ce qu'est une lvalue.

Dans la leçon 1.10 -- Introduction aux expressions, nous avons défini une expression comme « une combinaison de littéraux, de variables, d'opérateurs et d'appels de fonctions qui peut être exécutée pour produire une valeur unique ».

Par exemple :

#include <iostream>

int main()
{
    std::cout << 2 + 3 << '\n'; // L'expression 2 + 3 produit la valeur 5

    return 0;
}

Dans le programme ci-dessus, l'expression 2 + 3 est évaluée pour produire la valeur 5, qui est ensuite affichée à la console.

Dans la leçon 6.4 -- Opérateurs d'incrémentation/décrémentation et effets de bord, nous avons également remarqué que les expressions peuvent produire des effets de bord qui survivent à l'expression :

#include <iostream>

int main()
{
    int x { 5 };
    ++x; // Cette instruction d'expression a pour effet de bord d'incrémenter x
    std::cout << x << '\n'; // affiche 6

    return 0;
}

Dans le programme ci-dessus, l'expression ++x incrémente la valeur de x, et cette valeur reste modifiée même après la fin de l'évaluation de l'expression.

Outre la production de valeurs et d'effets de bord, les expressions peuvent faire une chose de plus : elles peuvent être évaluées en objets ou en fonctions. Nous explorerons ce point dans un instant.

Les propriétés d'une expression

Pour déterminer comment une expression doit être évaluée et où elle peut être utilisée, toutes les expressions en C++ possèdent deux propriétés : un type et une catégorie de valeur.

Le type d'une expression

Le type d'une expression est équivalent au type de la valeur, de l'objet ou de la fonction qui résulte de l'évaluation de l'expression. Par exemple :

int main()
{
    auto v1 { 12 / 4 }; // int / int => int
    auto v2 { 12.0 / 4 }; // double / int => double

    return 0;
}

Pour v1, le compilateur déterminera (à la compilation) qu'une division dont les deux opérandes sont des int produira un résultat de type int, donc int est le type de cette expression. Par déduction de type, int sera ensuite utilisé comme type de v1.

Pour v2, le compilateur déterminera (à la compilation) qu'une division dont un opérande est un double et l'autre un int produira un résultat double. Rappelez-vous que les opérateurs arithmétiques exigent des opérandes de types identiques : ici, l'opérande int est donc converti en double, et une division en virgule flottante est effectuée. Ainsi, double est le type de cette expression.

Le compilateur peut utiliser le type d'une expression pour déterminer si elle est valide dans un contexte donné. Par exemple :

#include <iostream>

void print(int x)
{
    std::cout << x << '\n';
}

int main()
{
    print("foo"); // erreur : print() attend un argument de type int, nous avons tenté de passer un littéral de chaîne

    return 0;
}

Dans le programme ci-dessus, la fonction print(int) attend un paramètre int. Cependant, le type de l'expression que nous passons (le littéral de chaîne "foo") ne correspond pas, et aucune conversion n'est possible. Il en résulte une erreur de compilation.

Notez que le type d'une expression doit pouvoir être déterminé à la compilation (sinon la vérification de type et la déduction de type ne fonctionneraient pas). En revanche, la valeur d'une expression peut être déterminée soit à la compilation (si l'expression est constexpr), soit à l'exécution (si l'expression n'est pas constexpr).

La catégorie de valeur d'une expression

Considérez maintenant le programme suivant :

int main()
{
    int x{};

    x = 5; // valide : nous pouvons affecter 5 à x
    5 = x; // erreur : impossible d'affecter la valeur de x au littéral 5

    return 0;
}

L'une de ces instructions d'affectation est valide (affecter la valeur 5 à la variable x) et l'autre ne l'est pas (que signifierait affecter la valeur de x au littéral 5 ?). Comment le compilateur sait-il alors quelles expressions peuvent légalement apparaître de chaque côté d'une affectation ?

La réponse réside dans la seconde propriété des expressions : la catégorie de valeur (value category). La catégorie de valeur d'une expression (ou d'une sous-expression) indique si cette expression correspond à une valeur, à une fonction ou à un objet d'un certain type.

Avant C++11, il n'existait que deux catégories de valeurs possibles : lvalue et rvalue.

En C++11, trois catégories de valeurs supplémentaires (glvalue, prvalue et xvalue) ont été ajoutées pour prendre en charge une nouvelle fonctionnalité appelée sémantique de déplacement (move semantics).

Note de l'auteur

Dans cette leçon, nous nous en tiendrons à la vision des catégories de valeurs antérieure à C++11, car elle constitue une introduction plus progressive aux catégories de valeurs (et c'est tout ce dont nous avons besoin pour le moment). Nous aborderons la sémantique de déplacement (ainsi que les trois catégories de valeurs supplémentaires) dans un chapitre ultérieur.

Expressions lvalue et rvalue

Une lvalue (prononcée « ell-value », abréviation de « left value » ou « locator value », et parfois écrite « l-value ») est une expression qui s'évalue en un objet ou une fonction identifiable (ou en un champ de bits).

Le terme « identité » est utilisé par la norme C++, mais il n'est pas rigoureusement défini. Une entité (comme un objet ou une fonction) qui possède une identité peut être distinguée d'autres entités similaires (généralement en comparant leurs adresses).

Les entités possédant une identité peuvent être accédées via un identifiant, une référence ou un pointeur, et ont généralement une durée de vie plus longue qu'une seule expression ou instruction.

int main()
{
    int x { 5 };
    int y { x }; // x est une expression lvalue

    return 0;
}

Dans le programme ci-dessus, l'expression x est une expression lvalue, car elle s'évalue en la variable x (qui possède un identifiant).

Depuis l'introduction des constantes dans le langage, les lvalues se déclinent en deux sous-types : une lvalue modifiable (modifiable lvalue) est une lvalue dont la valeur peut être modifiée. Une lvalue non modifiable (non-modifiable lvalue) est une lvalue dont la valeur ne peut pas être modifiée (parce que la lvalue est const ou constexpr).

int main()
{
    int x{};
    const double d{};

    int y { x }; // x est une expression lvalue modifiable
    const double e { d }; // d est une expression lvalue non modifiable

    return 0;
}

Une rvalue (prononcée « arr-value », abréviation de « right value », et parfois écrite r-value) est une expression qui n'est pas une lvalue. Les expressions rvalue s'évaluent en une valeur. Parmi les rvalues courantes figurent les littéraux (à l'exception des littéraux de chaîne de style C, qui sont des lvalues) et la valeur de retour des fonctions et opérateurs qui renvoient par valeur. Les rvalues ne sont pas identifiables (ce qui signifie qu'elles doivent être utilisées immédiatement) et n'existent que dans la portée de l'expression dans laquelle elles sont utilisées.

int return5()
{
    return 5;
}

int main()
{
    int x{ 5 }; // 5 est une expression rvalue
    const double d{ 1.2 }; // 1.2 est une expression rvalue

    int y { x }; // x est une expression lvalue modifiable
    const double e { d }; // d est une expression lvalue non modifiable
    int z { return5() }; // return5() est une expression rvalue (puisque le résultat est renvoyé par valeur)

    int w { x + 1 }; // x + 1 est une expression rvalue
    int q { static_cast<int>(d) }; // le résultat du transtypage statique de d en int est une expression rvalue

    return 0;
}

Vous vous demandez peut-être pourquoi return5(), x + 1 et static_cast<int>(d) sont des rvalues : la réponse est que ces expressions produisent des valeurs temporaires qui ne sont pas des objets identifiables.

Point clé

Les expressions lvalue s'évaluent en un objet identifiable.
Les expressions rvalue s'évaluent en une valeur.

Catégories de valeurs et opérateurs

Sauf indication contraire, les opérateurs attendent que leurs opérandes soient des rvalues. Par exemple, l'operator+ binaire attend que ses opérandes soient des rvalues :

#include <iostream>

int main()
{
    std::cout << 1 + 2; // 1 et 2 sont des rvalues, operator+ renvoie une rvalue

    return 0;
}

Les littéraux 1 et 2 sont tous deux des expressions rvalue. operator+ les utilise volontiers pour renvoyer l'expression rvalue 3.

Nous pouvons maintenant répondre à la question de savoir pourquoi x = 5 est valide alors que 5 = x ne l'est pas : une affectation exige que son opérande de gauche soit une expression lvalue modifiable. La seconde affectation (5 = x) échoue parce que l'opérande de gauche, l'expression 5, est une rvalue et non une lvalue modifiable.

int main()
{
    int x{};

    // L'affectation exige que l'opérande de gauche soit une expression lvalue modifiable et que l'opérande de droite soit une expression rvalue
    x = 5; // valide : x est une expression lvalue modifiable et 5 est une expression rvalue
    5 = x; // erreur : 5 est une expression rvalue et x est une expression lvalue modifiable

    return 0;
}

Conversion lvalue-vers-rvalue

Puisque les affectations attendent que l'opérande de droite soit une expression rvalue, vous vous demandez peut-être pourquoi ce qui suit fonctionne :

int main()
{
    int x{ 1 };
    int y{ 2 };

    x = y; // y n'est pas une rvalue, mais ceci est légal

    return 0;
}

Lorsqu'une rvalue est attendue mais qu'une lvalue est fournie, la lvalue subit une conversion lvalue-vers-rvalue afin de pouvoir être utilisée dans ce contexte. Cela signifie essentiellement que la lvalue est évaluée pour produire sa valeur, qui est une rvalue.

Dans l'exemple ci-dessus, l'expression lvalue y subit une conversion lvalue-vers-rvalue, qui évalue y pour produire une rvalue (2), laquelle est ensuite affectée à x.

Point clé

Une lvalue se convertit implicitement en rvalue. Cela signifie qu'une lvalue peut être utilisée partout où une rvalue est attendue.
Une rvalue, en revanche, ne se convertit pas implicitement en lvalue.

Considérez maintenant cet exemple :

int main()
{
    int x { 2 };

    x = x + 1;

    return 0;
}

Dans cette instruction, la variable x est utilisée dans deux contextes différents. À gauche de l'opérateur d'affectation (où une expression lvalue est requise), x est une expression lvalue qui s'évalue en la variable x. À droite de l'opérateur d'affectation, x subit une conversion lvalue-vers-rvalue et est alors évaluée afin que sa valeur (2) puisse être utilisée comme opérande de gauche de operator+. operator+ renvoie l'expression rvalue 3, qui est ensuite utilisée comme opérande de droite de l'affectation.

Comment différencier les lvalues et les rvalues

Vous pouvez encore hésiter sur les expressions qui relèvent d'une lvalue ou d'une rvalue. Par exemple, le résultat de operator++ est-il une lvalue ou une rvalue ? Nous allons présenter ici différentes méthodes permettant de répondre à ce genre de question.

Astuce

Une règle empirique pour identifier les expressions lvalue et rvalue :

  • Les expressions lvalue sont celles qui s'évaluent en des fonctions ou en des objets identifiables (y compris des variables) qui persistent au-delà de la fin de l'expression.
  • Les expressions rvalue sont celles qui s'évaluent en des valeurs, y compris les littéraux et les objets temporaires qui ne persistent pas au-delà de la fin de l'expression.

Pour une liste plus complète des expressions lvalue et rvalue, vous pouvez consulter la documentation technique.

Astuce

Une liste complète des expressions lvalue et rvalue se trouve ici. En C++11, les rvalues se répartissent en deux sous-types : les prvalues et les xvalues ; les rvalues dont nous parlons ici sont donc la somme de ces deux catégories.

Enfin, nous pouvons écrire un programme et demander au compilateur de nous indiquer de quel type d'expression il s'agit. Le code suivant présente une méthode permettant de déterminer si une expression est une lvalue ou une rvalue :

#include <iostream>
#include <string>

// T& est une référence lvalue, donc cette surcharge sera préférée pour les lvalues
template <typename T>
constexpr bool is_lvalue(T&)
{
    return true;
}

// T&& est une référence rvalue, donc cette surcharge sera préférée pour les rvalues
template <typename T>
constexpr bool is_lvalue(T&&)
{
    return false;
}

// Une macro d'aide (#expr affiche tel quel ce qui est passé pour expr, sous forme de texte)
#define PRINTVCAT(expr) { std::cout << #expr << " is an " << (is_lvalue(expr) ? "lvalue\n" : "rvalue\n"); }

int getint() { return 5; }

int main()
{
    PRINTVCAT(5);        // rvalue
    PRINTVCAT(getint()); // rvalue
    int x { 5 };
    PRINTVCAT(x);        // lvalue
    PRINTVCAT(std::string {"Hello"}); // rvalue
    PRINTVCAT("Hello");  // lvalue
    PRINTVCAT(++x);      // lvalue
    PRINTVCAT(x++);      // rvalue
}

Ce programme affiche :


5 is an rvalue
getint() is an rvalue
x is an lvalue
std::string {"Hello"} is an rvalue
"Hello" is an lvalue
++x is an lvalue
x++ is an rvalue

Cette méthode repose sur deux fonctions surchargées : l'une avec un paramètre de référence lvalue et l'autre avec un paramètre de référence rvalue. La version à référence lvalue sera préférée pour les arguments lvalue, et la version à référence rvalue sera préférée pour les arguments rvalue. On peut ainsi déterminer si l'argument est une lvalue ou une rvalue selon la fonction sélectionnée.

Comme vous pouvez le voir, le fait que operator++ produise une lvalue ou une rvalue dépend de son utilisation en préfixe (qui renvoie une lvalue) ou en postfixe (qui renvoie une rvalue) !

Pour les lecteurs avancés

Contrairement aux autres littéraux (qui sont des rvalues), un littéral de chaîne de style C est une lvalue, car les chaînes de style C (qui sont des tableaux de style C) se dégradent en pointeur. Cette dégradation (decay) ne fonctionne que si le tableau est une lvalue (et possède donc une adresse pouvant être stockée dans le pointeur). C++ a hérité de ce comportement pour des raisons de compatibilité ascendante.

Nous aborderons la dégradation des tableaux dans la leçon 17.8 -- Dégradation des tableaux de style C.
