12.4 — Références lvalue vers const

Dans la leçon précédente (12.3 -- Références lvalue), nous avons vu qu'une référence lvalue ne peut se lier qu'à une lvalue modifiable. Cela signifie que ce qui suit est illégal :

int main()
{
    const int x { 5 }; // x est une lvalue non modifiable (const)
    int& ref { x }; // erreur : ref ne peut pas se lier à une lvalue non modifiable

    return 0;
}

Ceci est interdit car cela nous permettrait de modifier une variable const (x) à travers la référence non const (ref).

Mais que faire si nous voulons créer une référence vers une variable const ? Une référence lvalue ordinaire (vers une valeur non const) ne convient pas.

Référence lvalue vers const

En utilisant le mot-clé const lors de la déclaration d'une référence lvalue, nous indiquons à cette référence de traiter l'objet qu'elle référence comme const. Une telle référence est appelée référence lvalue vers une valeur const (parfois appelée référence vers const ou référence const).

Les références lvalue vers const peuvent se lier à des lvalues non modifiables :

int main()
{
    const int x { 5 };    // x est une lvalue non modifiable
    const int& ref { x }; // ok : ref est une référence lvalue vers une valeur const

    return 0;
}

Comme les références lvalue vers const traitent l'objet qu'elles référencent comme const, elles peuvent servir à accéder à la valeur référencée, mais pas à la modifier :

#include <iostream>

int main()
{
    const int x { 5 };    // x est une lvalue non modifiable
    const int& ref { x }; // ok : ref est une référence lvalue vers une valeur const

    std::cout << ref << '\n'; // ok : nous pouvons accéder à l'objet const
    ref = 6;                  // erreur : nous ne pouvons pas modifier un objet à travers une référence const

    return 0;
}

Initialiser une référence lvalue vers const avec une lvalue modifiable

Les références lvalue vers const peuvent aussi se lier à des lvalues modifiables. Dans ce cas, l'objet référencé est traité comme const lorsqu'on y accède par la référence (bien que l'objet sous-jacent soit non const) :

#include <iostream>

int main()
{
    int x { 5 };          // x est une lvalue modifiable
    const int& ref { x }; // ok : nous pouvons lier une référence const à une lvalue modifiable

    std::cout << ref << '\n'; // ok : nous pouvons accéder à l'objet à travers notre référence const
    ref = 7;                  // erreur : nous ne pouvons pas modifier un objet à travers une référence const

    x = 6;                // ok : x est une lvalue modifiable, nous pouvons toujours la modifier via l'identifiant d'origine

    return 0;
}

Dans le programme ci-dessus, nous lions la référence const ref à la lvalue modifiable x. Nous pouvons alors utiliser ref pour accéder à x, mais comme ref est const, nous ne pouvons pas modifier la valeur de x à travers ref. En revanche, nous pouvons toujours modifier la valeur de x directement (en utilisant l'identifiant x).

Bonne pratique

Privilégiez les références lvalue vers const plutôt que les références lvalue vers non-const, sauf si vous devez modifier l'objet référencé.

Initialiser une référence lvalue vers const avec une rvalue

De façon peut-être surprenante, les références lvalue vers const peuvent aussi se lier à des rvalues :

#include <iostream>

int main()
{
    const int& ref { 5 }; // ok : 5 est une rvalue

    std::cout << ref << '\n'; // affiche 5

    return 0;
}

Dans ce cas, un objet temporaire est créé et initialisé avec la rvalue, et la référence vers const est liée à cet objet temporaire.

Contenu connexe

Nous avons abordé les objets temporaires dans la leçon 2.5 -- Introduction à la portée locale.

Initialiser une référence lvalue vers const avec une valeur d'un type différent

Les références lvalue vers const peuvent même se lier à des valeurs d'un autre type, à condition que ces valeurs puissent être implicitement converties vers le type de la référence :

#include <iostream>

int main()
{
    // cas 1
    const double& r1 { 5 };  // double temporaire initialisé avec la valeur 5, r1 se lie au temporaire

    std::cout << r1 << '\n'; // affiche 5

    // cas 2
    char c { 'a' };
    const int& r2 { c };     // int temporaire initialisé avec la valeur 'a', r2 se lie au temporaire

    std::cout << r2 << '\n'; // affiche 97 (car r2 est une référence vers un int)

    return 0;
}

Dans le cas 1, un objet temporaire de type double est créé et initialisé avec la valeur int 5. Puis const double& r1 est liée à cet objet temporaire double.

Dans le cas 2, un objet temporaire de type int est créé et initialisé avec la valeur char a. Puis const int& r2 est liée à cet objet temporaire int.

Dans les deux cas, le type de la référence et le type du temporaire correspondent.

Point clé

Si vous essayez de lier une référence lvalue const à une valeur d'un type différent, le compilateur crée un objet temporaire du même type que la référence, l'initialise avec la valeur, puis lie la référence à ce temporaire.

Notez également que lorsque nous affichons r2, il s'affiche comme un int et non comme un char. C'est parce que r2 est une référence vers un objet int (le int temporaire créé), et non vers le char c.

Bien qu'il puisse sembler étrange d'autoriser cela, nous verrons des exemples où c'est utile dans la leçon 12.6 -- Passage par référence lvalue const.

Attention

Nous supposons normalement qu'une référence est identique à l'objet auquel elle est liée. Cette hypothèse est mise en défaut lorsqu'une référence est liée à une copie temporaire de l'objet, ou à un temporaire résultant de la conversion de l'objet. Toute modification ultérieure de l'objet d'origine ne sera pas visible par la référence (puisqu'elle référence un objet différent), et inversement.

Voici un exemple absurde qui illustre cela :

#include <iostream>

int main()
{
    short bombs { 1 };         // J'ai une bombe ! (note : le type est short)

    const int& you { bombs };  // Vous aussi avez une bombe (note : le type est int&)
    --bombs;                   // Plus de bombe

    if (you)                   // Vous en avez encore ?
    {
        std::cout << "Bombs away!  Goodbye, cruel world.\n"; // Para bailar la bomba
    }

    return 0;
}

Dans l'exemple ci-dessus, bombs est un short et you est un const int&. Comme you ne peut se lier qu'à un objet int, lorsque you est initialisée avec bombs, le compilateur convertit implicitement bombs en int, ce qui crée un objet int temporaire (de valeur 1). you finit liée à ce temporaire plutôt qu'à bombs.

Lorsque bombs est décrémentée, you n'est pas affectée car elle référence un objet différent. Ainsi, bien que nous nous attendions à ce que if (you) soit évalué à false, il est en fait évalué à true.

Si vous pouviez arrêter de faire exploser le monde, ce serait parfait.

Les références const liées à des objets temporaires prolongent la durée de vie de ceux-ci

Les objets temporaires sont normalement détruits à la fin de l'expression dans laquelle ils sont créés.

Considérons l'instruction const int& ref { 5 };. Que se passerait-il si l'objet temporaire créé pour contenir la rvalue 5 était détruit à la fin de l'expression qui initialise ref ? La référence ref resterait pendante (elle référencerait un objet détruit), et nous obtiendrions un comportement indéfini lors de l'accès à ref.

Pour éviter des références pendantes dans de tels cas, le C++ possède une règle spéciale : lorsqu'une référence lvalue const est directement liée à un objet temporaire, la durée de vie de l'objet temporaire est prolongée pour correspondre à celle de la référence.

#include <iostream>

int main()
{
    const int& ref { 5 }; // La durée de vie de l'objet temporaire contenant la valeur 5 est prolongée jusqu'à celle de ref

    std::cout << ref << '\n'; // Nous pouvons donc l'utiliser en toute sécurité ici

    return 0;
} // ref et l'objet temporaire meurent ici

Dans l'exemple ci-dessus, lorsque ref est initialisée avec la rvalue 5, un objet temporaire est créé et ref est liée à cet objet. La durée de vie du temporaire correspond à celle de ref. Ainsi, nous pouvons afficher en toute sécurité la valeur de ref dans l'instruction suivante. Puis ref et l'objet temporaire sortent de portée et sont détruits à la fin du bloc.

Point clé

Les références lvalue ne peuvent se lier qu'à des lvalues modifiables.

Les références lvalue vers const peuvent se lier à des lvalues modifiables, à des lvalues non modifiables et à des rvalues. Cela en fait un type de référence beaucoup plus souple.

Pour les lecteurs avancés

La prolongation de durée de vie ne fonctionne que lorsqu'une référence const est directement liée à un temporaire. Les temporaires renvoyés par une fonction (même ceux renvoyés par référence const) ne bénéficient pas de cette prolongation.

Nous montrons un exemple de cela dans la leçon 12.12 -- Retour par référence et retour par adresse.

Pour les rvalues de type classe, lier une référence à un membre prolonge la durée de vie de l'objet entier.

Alors pourquoi le C++ autorise-t-il malgré tout une référence const à se lier à une rvalue ? Nous répondrons à cette question dans la prochaine leçon !

Références lvalue constexpr (Optionnel)

Appliqué à une référence, constexpr permet d'utiliser la référence dans une expression constante. Les références constexpr ont une limitation particulière : elles ne peuvent se lier qu'à des objets à durée de stockage statique (soit des globales, soit des variables statiques locales). En effet, le compilateur sait où les objets statiques seront placés en mémoire, il peut donc traiter cette adresse comme une constante à la compilation.

Une référence constexpr ne peut pas se lier à une variable locale (non statique). En effet, l'adresse des variables locales n'est connue qu'au moment où la fonction dans laquelle elles sont définies est effectivement appelée.

int g_x { 5 };

int main()
{
    [[maybe_unused]] constexpr int& ref1 { g_x }; // ok, peut se lier à une globale

    static int s_x { 6 };
    [[maybe_unused]] constexpr int& ref2 { s_x }; // ok, peut se lier à une statique locale

    int x { 6 };
    [[maybe_unused]] constexpr int& ref3 { x }; // erreur de compilation : ne peut pas se lier à un objet non statique

    return 0;
}

Lorsqu'on définit une référence constexpr vers une variable const, il faut appliquer à la fois constexpr (qui s'applique à la référence) et const (qui s'applique au type référencé).

int main()
{
    static const int s_x { 6 }; // un const int
    [[maybe_unused]] constexpr const int& ref2 { s_x }; // nécessite à la fois constexpr et const

    return 0;
}

Compte tenu de ces limitations, les références constexpr ne sont généralement pas très utilisées.
