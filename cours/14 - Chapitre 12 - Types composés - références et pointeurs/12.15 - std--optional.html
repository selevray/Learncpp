12.15 — std::optional

Dans la leçon 9.4 -- Détection et gestion des erreurs, nous avons vu les cas où une fonction rencontre une erreur qu'elle ne peut pas raisonnablement gérer elle-même. Prenons par exemple une fonction qui calcule et renvoie une valeur :

int doIntDivision(int x, int y)
{
    return x / y;
}

Si l'appelant passe une valeur sémantiquement invalide (comme y = 0), cette fonction ne peut pas calculer de valeur à renvoyer, puisque la division par 0 est mathématiquement indéfinie. Que faire dans ce cas ? Comme les fonctions qui calculent un résultat ne devraient pas avoir d'effets de bord, cette fonction ne peut pas raisonnablement résoudre l'erreur elle-même. Dans ces situations, la solution habituelle consiste à faire détecter l'erreur par la fonction, puis à la transmettre à l'appelant, qui la traitera de la manière appropriée au programme.

Dans la leçon citée précédemment, nous avons vu deux façons différentes pour une fonction de renvoyer une erreur à l'appelant :

  • Faire renvoyer un bool par une fonction de type void (indiquant succès ou échec).
  • Faire renvoyer une valeur sentinelle (une valeur particulière qui n'appartient pas à l'ensemble des valeurs que la fonction peut renvoyer normalement) par une fonction qui renvoie une valeur, pour signaler une erreur.

Pour illustrer le second cas, la fonction reciprocal() suivante renvoie la valeur 0.0 (qui ne peut jamais être renvoyée autrement) si l'utilisateur passe un argument x sémantiquement invalide :

#include <iostream>

// L'inverse de x vaut 1/x, renvoie 0.0 si x=0
double reciprocal(double x)
{
    if (x == 0.0) // si x est sémantiquement invalide
       return 0.0; // renvoie 0.0 comme valeur sentinelle pour signaler une erreur

    return 1.0 / x;
}

void testReciprocal(double d)
{
     double result { reciprocal(d) };
     std::cout << "The reciprocal of " << d << " is ";
     if (result != 0.0)
         std::cout << result << '\n';
     else
         std::cout << "undefined\n";
}

int main()
{
    testReciprocal(5.0);
    testReciprocal(-4.0);
    testReciprocal(0.0);

    return 0;
}

Cette solution est assez séduisante, mais elle présente plusieurs inconvénients potentiels :

  • Le programmeur doit connaître la valeur sentinelle utilisée par la fonction pour signaler une erreur (et cette valeur peut différer d'une fonction à l'autre qui utilise cette méthode).
  • Une version différente de la même fonction peut utiliser une autre valeur sentinelle.
  • Cette méthode ne fonctionne pas pour les fonctions dont toutes les valeurs possibles sont des valeurs de retour valides.

Reprenons notre fonction doIntDivision() ci-dessus. Quelle valeur pourrait-elle renvoyer si l'utilisateur passe 0 pour y ? Nous ne pouvons pas utiliser 0, car 0 divisé par n'importe quoi donne 0, qui est un résultat valide. En fait, il n'existe aucune valeur que nous pourrions renvoyer sans qu'elle puisse apparaître naturellement.

Que faire alors ?

Premièrement, nous pourrions choisir une valeur de retour (espérons-le) peu courante comme sentinelle et l'utiliser pour signaler une erreur :

#include <limits> // pour std::numeric_limits

// renvoie std::numeric_limits<int>::lowest() en cas d'échec
int doIntDivision(int x, int y)
{
    if (y == 0)
        return std::numeric_limits<int>::lowest();
    return x / y;
}

std::numeric_limits<T>::lowest() est une fonction qui renvoie la valeur la plus négative du type T. Elle est l'équivalent de la fonction std::numeric_limits<T>::max() (qui renvoie la plus grande valeur positive du type T) que nous avons présentée dans la leçon 9.5 -- std::cin et gestion des entrées invalides.

Dans l'exemple ci-dessus, si doIntDivision() ne peut pas poursuivre son calcul, elle renvoie std::numeric_limits<int>::lowest(), c'est-à-dire la valeur int la plus négative, pour indiquer à l'appelant que la fonction a échoué.

Cette méthode fonctionne globalement, mais elle présente deux inconvénients :

  • À chaque appel de cette fonction, nous devons comparer la valeur renvoyée à std::numeric_limits<int>::lowest() pour savoir si l'appel a échoué. C'est verbeux et peu élégant.
  • C'est un exemple du problème du semi-prédicat : si l'utilisateur appelle doIntDivision(std::numeric_limits<int>::lowest(), 1), la valeur renvoyée std::numeric_limits<int>::lowest() est ambiguë, car on ne peut pas savoir si la fonction a réussi ou échoué. Cela peut poser problème ou non selon l'usage réel de la fonction, mais c'est une difficulté de plus à gérer, et une nouvelle façon pour des erreurs de s'infiltrer dans le programme.

Deuxièmement, nous pourrions renoncer à utiliser les valeurs de retour pour signaler les erreurs et recourir à un autre mécanisme, par exemple les exceptions. Cependant, les exceptions ont leurs propres complications et coûts en performance, et elles ne sont pas forcément appropriées ou souhaitées. Dans un cas comme celui-ci, c'est probablement excessif.

Troisièmement, nous pourrions renoncer à renvoyer une seule valeur et en renvoyer deux : l'une (de type bool) indiquant si la fonction a réussi, et l'autre (du type de retour souhaité) contenant la valeur de retour réelle (si la fonction a réussi) ou une valeur indéterminée (si la fonction a échoué). C'est probablement la meilleure option du lot.

Avant C++17, pour choisir cette dernière option, il fallait l'implémenter soi-même. Or, même si C++ offre plusieurs moyens de le faire, toute solution maison finit inévitablement par introduire des incohérences et des erreurs.

Renvoyer un std::optional

C++17 introduit std::optional, un modèle de classe (class template) qui implémente une valeur optionnelle. Autrement dit, un std::optional<T> peut contenir une valeur de type T, ou ne rien contenir. Nous pouvons l'utiliser pour implémenter la troisième option ci-dessus :

#include <iostream>
#include <optional> // pour std::optional (C++17)

// Notre fonction renvoie maintenant optionnellement une valeur int
std::optional<int> doIntDivision(int x, int y)
{
    if (y == 0)
        return {}; // ou return std::nullopt
    return x / y;
}

int main()
{
    std::optional<int> result1 { doIntDivision(20, 5) };
    if (result1) // si la fonction a renvoyé une valeur
        std::cout << "Result 1: " << *result1 << '\n'; // récupère la valeur
    else
        std::cout << "Result 1: failed\n";

    std::optional<int> result2 { doIntDivision(5, 0) };

    if (result2)
        std::cout << "Result 2: " << *result2 << '\n';
    else
        std::cout << "Result 2: failed\n";

    return 0;
}

Ce programme affiche :


Result 1: 4
Result 2: failed

Utiliser std::optional est assez simple. On peut construire un std::optional<T> avec ou sans valeur :

std::optional<int> o1 { 5 };            // initialisation avec une valeur
std::optional<int> o2 {};               // initialisation sans valeur
std::optional<int> o3 { std::nullopt }; // initialisation sans valeur

Pour savoir si un std::optional contient une valeur, on peut utiliser l'une des méthodes suivantes :

if (o1.has_value()) // appel de has_value() pour vérifier si o1 contient une valeur
if (o2)             // conversion implicite en bool pour vérifier si o2 contient une valeur

Pour obtenir la valeur d'un std::optional, on peut utiliser l'une des méthodes suivantes :

std::cout << *o1;             // déréférencement pour obtenir la valeur stockée dans o1 (comportement indéfini si o1 n'a pas de valeur)
std::cout << o2.value();      // appel de value() pour obtenir la valeur stockée dans o2 (lève l'exception std::bad_optional_access si o2 n'a pas de valeur)
std::cout << o3.value_or(42); // appel de value_or() pour obtenir la valeur stockée dans o3 (ou la valeur `42` si o3 n'a pas de valeur)

Notez que la syntaxe d'utilisation de std::optional est pratiquement identique à celle d'un pointeur :

Comportement Pointeur std::optional
Ne contient aucune valeur initialisation/affectation avec {} ou std::nullptr initialisation/affectation avec {} ou std::nullopt
Contient une valeur initialisation/affectation avec une adresse initialisation/affectation avec une valeur
Vérifier la présence d'une valeur conversion implicite en bool conversion implicite en bool ou has_value()
Obtenir la valeur déréférencement déréférencement ou value()

Cependant, d'un point de vue sémantique, un pointeur et un std::optional sont très différents.

  • Un pointeur a une sémantique de référence : il désigne un autre objet, et l'affectation copie le pointeur, pas l'objet. Si nous renvoyons un pointeur par adresse, c'est le pointeur qui est copié vers l'appelant, pas l'objet pointé. Cela signifie qu'on ne peut pas renvoyer par adresse un objet local, car on renverrait l'adresse de cet objet, qui serait ensuite détruit, laissant le pointeur renvoyé pendant (dangling).
  • Un std::optional a une sémantique de valeur : il contient réellement sa valeur, et l'affectation copie la valeur. Si nous renvoyons un std::optional par valeur, le std::optional (y compris la valeur qu'il contient) est copié vers l'appelant. Cela signifie qu'on peut renvoyer une valeur depuis la fonction vers l'appelant grâce à std::optional.

Gardons cela en tête et regardons comment fonctionne notre exemple. Notre doIntDivision() renvoie maintenant un std::optional<int> au lieu d'un int. Dans le corps de la fonction, si nous détectons une erreur, nous renvoyons {}, ce qui renvoie implicitement un std::optional sans valeur. Si nous avons une valeur, nous la renvoyons, ce qui renvoie implicitement un std::optional contenant cette valeur.

Dans main(), nous utilisons une conversion implicite en bool pour vérifier si le std::optional renvoyé contient une valeur. Si oui, nous déréférençons l'objet std::optional pour obtenir la valeur. Sinon, nous traitons la condition d'erreur. C'est tout !

Avantages et inconvénients de renvoyer un std::optional

Renvoyer un std::optional présente plusieurs avantages :

  • Utiliser std::optional documente clairement le fait qu'une fonction peut renvoyer une valeur ou non.
  • Nous n'avons pas besoin de retenir quelle valeur sert de sentinelle.
  • La syntaxe d'utilisation de std::optional est pratique et intuitive.

Renvoyer un std::optional présente néanmoins quelques inconvénients :

  • Nous devons nous assurer que le std::optional contient une valeur avant de la récupérer. Si nous déréférençons un std::optional qui ne contient pas de valeur, nous obtenons un comportement indéfini.
  • std::optional ne permet pas de transmettre des informations sur la raison de l'échec de la fonction.

Sauf si votre fonction doit renvoyer des informations supplémentaires sur la raison de son échec (pour mieux comprendre l'erreur, ou pour distinguer différents types d'échec), std::optional est un excellent choix pour les fonctions qui peuvent renvoyer une valeur ou échouer.

Bonne pratique

Renvoyez un std::optional (plutôt qu'une valeur sentinelle) pour les fonctions susceptibles d'échouer, sauf si votre fonction doit renvoyer des informations supplémentaires sur la raison de son échec.

Contenu associé

std::expected (introduit en C++23) est conçu pour le cas où une fonction peut renvoyer soit une valeur attendue, soit un code d'erreur inattendu. Consultez la référence de std::expected pour plus d'informations.

Utiliser std::optional comme paramètre de fonction optionnel

Dans la leçon 12.11 -- Passage par adresse (partie 2), nous avons vu comment le passage par adresse permet à une fonction d'accepter un argument « optionnel » (l'appelant peut passer nullptr pour représenter « aucun argument », ou un objet). Cependant, cette approche présente un inconvénient : un argument non nul doit être une lvalue (pour que son adresse puisse être passée à la fonction).

Sans surprise (vu le nom), std::optional est une autre façon pour une fonction d'accepter un argument optionnel (utilisé uniquement comme paramètre d'entrée). Au lieu de ceci :

#include <iostream>

void printIDNumber(const int *id=nullptr)
{
    if (id)
        std::cout << "Your ID number is " << *id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printIDNumber(); // on ne connaît pas encore l'ID de l'utilisateur

    int userid { 34 };
    printIDNumber(&userid); // on connaît maintenant l'ID de l'utilisateur

    return 0;
}

Vous pouvez écrire ceci :

#include <iostream>
#include <optional>

void printIDNumber(std::optional<const int> id = std::nullopt)
{
    if (id)
        std::cout << "Your ID number is " << *id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printIDNumber(); // on ne connaît pas encore l'ID de l'utilisateur

    int userid { 34 };
    printIDNumber(userid); // on connaît maintenant l'ID de l'utilisateur

    printIDNumber(62); // on peut aussi passer une rvalue

    return 0;
}

Cette approche présente deux avantages :

  1. Elle documente clairement le fait que le paramètre est optionnel.
  2. On peut passer une rvalue (puisque std::optional fera une copie).

Cependant, comme std::optional copie son argument, cela devient problématique lorsque T est un type coûteux à copier (comme std::string). Avec les paramètres de fonction classiques, nous contournions ce problème en utilisant une référence lvalue constante, afin d'éviter la copie. Malheureusement, jusqu'à C++23 inclus, std::optional ne prend pas en charge les références.

Nous recommandons donc d'utiliser std::optional<T> comme paramètre optionnel uniquement lorsque T serait normalement passé par valeur. Dans le cas contraire, utilisez const T*.

Pour les lecteurs avancés

Bien que std::optional ne prenne pas directement en charge les références, vous pouvez utiliser std::reference_wrapper (que nous présentons dans la leçon 17.5 -- Tableaux de références via std::reference_wrapper) pour imiter une référence. Voyons à quoi ressemble le programme ci-dessus avec un identifiant de type std::string et std::reference_wrapper :

#include <functional>  // pour std::reference_wrapper
#include <iostream>
#include <optional>
#include <string>

struct Employee
{
    std::string name{}; // coûteux à copier
    int id;
};

void printEmployeeID(std::optional<std::reference_wrapper<Employee>> e=std::nullopt)
{
    if (e)
        std::cout << "Your ID number is " << e->get().id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printEmployeeID(); // on ne connaît pas encore l'Employee

    Employee e { "James", 34 };
    printEmployeeID(e); // on connaît maintenant l'ID de l'Employee

    return 0;
}

Et pour comparaison, la version avec pointeur :

#include <iostream>
#include <string>

struct Employee
{
    std::string name{}; // coûteux à copier
    int id;
};

void printEmployeeID(const Employee* e=nullptr)
{
    if (e)
        std::cout << "Your ID number is " << e->id << ".\n";
    else
        std::cout << "Your ID number is not known.\n";
}

int main()
{
    printEmployeeID(); // on ne connaît pas encore l'Employee

    Employee e { "James", 34 };
    printEmployeeID(&e); // on connaît maintenant l'ID de l'Employee

    return 0;
}

Ces deux programmes sont presque identiques. Nous estimons que le premier n'est ni plus lisible ni plus facile à maintenir que le second, et qu'il ne vaut pas la peine d'introduire deux types supplémentaires dans votre programme.

Dans de nombreux cas, la surcharge de fonctions offre une solution supérieure :

#include <iostream>
#include <string>

struct Employee
{
    std::string name{}; // coûteux à copier
    int id;
};

void printEmployeeID()
{
    std::cout << "Your ID number is not known.\n";
}

void printEmployeeID(const Employee& e)
{
    std::cout << "Your ID number is " << e.id << ".\n";
}

int main()
{
    printEmployeeID(); // on ne connaît pas encore l'Employee

    Employee e { "James", 34 };
    printEmployeeID(e); // on connaît maintenant l'ID de l'Employee

    printEmployeeID( { "Dave", 62 } ); // on peut même passer des rvalues

    return 0;
}

Bonne pratique

Privilégiez std::optional pour les types de retour optionnels.

Privilégiez la surcharge de fonctions pour les paramètres optionnels (lorsque c'est possible). Sinon, utilisez std::optional<T> pour les arguments optionnels lorsque T serait normalement passé par valeur. Préférez const T* lorsque T est coûteux à copier.
