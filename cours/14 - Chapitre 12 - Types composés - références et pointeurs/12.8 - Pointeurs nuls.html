12.8 — Pointeurs nuls

Dans la leçon précédente (12.7 -- Introduction aux pointeurs), nous avons vu les bases des pointeurs, des objets qui contiennent l'adresse d'un autre objet. Cette adresse peut être déréférencée à l'aide de l'opérateur de déréférencement (*) pour obtenir l'objet situé à cette adresse :

#include <iostream>

int main()
{
    int x{ 5 };
    std::cout << x << '\n'; // affiche la valeur de la variable x

    int* ptr{ &x }; // ptr contient l'adresse de x
    std::cout << *ptr << '\n'; // utilise l'opérateur de déréférencement pour afficher la valeur de l'objet situé à l'adresse contenue dans ptr (qui est l'adresse de x)

    return 0;
}

L'exemple ci-dessus affiche :


5
5

Dans la leçon précédente, nous avons également indiqué que les pointeurs n'ont pas besoin de pointer vers quoi que ce soit. Dans cette leçon, nous allons explorer plus en détail ces pointeurs (et les différentes conséquences de ne pointer vers rien).

Pointeurs nuls

Outre une adresse mémoire, un pointeur peut contenir une autre valeur : la valeur nulle. Une valeur nulle (souvent abrégée en null) est une valeur spéciale qui signifie qu'une chose n'a aucune valeur. Lorsqu'un pointeur contient une valeur nulle, cela signifie qu'il ne pointe sur rien. Un tel pointeur est appelé pointeur nul (null pointer).

La manière la plus simple de créer un pointeur nul consiste à utiliser l'initialisation par valeur :

int main()
{
    int* ptr {}; // ptr est maintenant un pointeur nul, et ne contient aucune adresse

    return 0;
}

Bonne pratique

Initialisez vos pointeurs par valeur (pour en faire des pointeurs nuls) si vous ne les initialisez pas avec l'adresse d'un objet valide.

Comme on peut utiliser l'affectation pour changer ce que pointe un pointeur, un pointeur initialement mis à null peut ensuite être modifié pour pointer vers un objet valide :

#include <iostream>

int main()
{
    int* ptr {}; // ptr est un pointeur nul, et ne contient aucune adresse

    int x { 5 };
    ptr = &x; // ptr pointe maintenant vers l'objet x (ce n'est plus un pointeur nul)

    std::cout << *ptr << '\n'; // affiche la valeur de x à travers le pointeur déréférencé ptr

    return 0;
}

Le mot-clé nullptr

De même que les mots-clés true et false représentent des littéraux booléens, le mot-clé nullptr représente le littéral de pointeur nul. Nous pouvons utiliser nullptr pour initialiser ou affecter explicitement une valeur nulle à un pointeur.

int main()
{
    int* ptr { nullptr }; // on peut utiliser nullptr pour initialiser un pointeur comme pointeur nul

    int value { 5 };
    int* ptr2 { &value }; // ptr2 est un pointeur valide
    ptr2 = nullptr; // on peut affecter nullptr pour faire de ce pointeur un pointeur nul

    someFunction(nullptr); // on peut aussi passer nullptr à une fonction dont un paramètre est un pointeur

    return 0;
}

Dans l'exemple ci-dessus, nous utilisons l'affectation pour donner à ptr2 la valeur nullptr, faisant de ptr2 un pointeur nul.

Bonne pratique

Utilisez nullptr lorsque vous avez besoin d'un littéral de pointeur nul pour une initialisation, une affectation ou pour passer un pointeur nul à une fonction.

Déréférencer un pointeur nul provoque un comportement indéfini

De même que le déréférencement d'un pointeur pendant (ou sauvage) conduit à un comportement indéfini, le déréférencement d'un pointeur nul conduit également à un comportement indéfini. Dans la plupart des cas, cela fera planter votre application.

Le programme suivant l'illustre, et risque fort de faire planter votre application ou de la terminer anormalement lorsque vous l'exécuterez (essayez, vous ne risquez rien pour votre machine) :

#include <iostream>

int main()
{
    int* ptr {}; // crée un pointeur nul
    std::cout << *ptr << '\n'; // déréférence le pointeur nul

    return 0;
}

Sur le plan conceptuel, cela a du sens. Déréférencer un pointeur signifie « aller à l'adresse que pointe ce pointeur et accéder à la valeur qui s'y trouve ». Un pointeur nul contient une valeur nulle, ce qui signifie sémantiquement que le pointeur ne pointe sur rien. Quelle valeur accéderait-il alors ?

Déréférencer par accident des pointeurs nuls ou pendants est l'une des erreurs les plus courantes chez les programmeurs C++, et c'est probablement la raison la plus fréquente des plantages de programmes C++ en pratique.

Avertissement

Lorsque vous utilisez des pointeurs, vous devez veiller particulièrement à ce que votre code ne déréférence pas de pointeur nul ou pendant, car cela provoquerait un comportement indéfini (probablement un plantage de l'application).

Vérifier les pointeurs nuls

De même que nous pouvons utiliser une condition pour tester des valeurs booléennes vraies ou fausses, nous pouvons utiliser une condition pour tester si un pointeur a la valeur nullptr ou non :

#include <iostream>

int main()
{
    int x { 5 };
    int* ptr { &x };

    if (ptr == nullptr) // test explicite d'égalité
        std::cout << "ptr est nul\n";
    else
        std::cout << "ptr est non nul\n";

    int* nullPtr {};
    std::cout << "nullPtr est " << (nullPtr==nullptr ? "nul\n" : "non nul\n"); // test explicite d'égalité

    return 0;
}

Le programme ci-dessus affiche :


ptr est non nul
nullPtr est nul

Dans la leçon 4.9 -- Valeurs booléennes, nous avons indiqué que les valeurs entières se convertissent implicitement en valeurs booléennes : la valeur entière 0 se convertit en valeur booléenne false, et toute autre valeur entière se convertit en valeur booléenne true.

De même, les pointeurs se convertissent implicitement en valeurs booléennes : un pointeur nul se convertit en valeur booléenne false, et un pointeur non nul se convertit en valeur booléenne true. Cela nous permet de nous passer d'un test explicite avec nullptr et d'utiliser simplement la conversion implicite en booléen pour savoir si un pointeur est nul. Le programme suivant est équivalent au précédent :

#include <iostream>

int main()
{
    int x { 5 };
    int* ptr { &x };

    // les pointeurs se convertissent en booléen false s'ils sont nuls, et en booléen true s'ils ne le sont pas
    if (ptr) // conversion implicite en booléen
        std::cout << "ptr est non nul\n";
    else
        std::cout << "ptr est nul\n";

    int* nullPtr {};
    std::cout << "nullPtr est " << (nullPtr ? "non nul\n" : "nul\n"); // conversion implicite en booléen

    return 0;
}

Avertissement

Les conditions ne permettent de distinguer que les pointeurs nuls des pointeurs non nuls. Il n'existe pas de moyen commode de déterminer si un pointeur non nul pointe vers un objet valide ou s'il est pendant (pointe vers un objet invalide).

Utiliser nullptr pour éviter les pointeurs pendants

Plus haut, nous avons mentionné que déréférencer un pointeur qui est soit nul, soit pendant entraîne un comportement indéfini. Nous devons donc veiller à ce que notre code ne fasse ni l'un ni l'autre.

Nous pouvons facilement éviter de déréférencer un pointeur nul en utilisant une condition pour nous assurer qu'un pointeur est non nul avant de tenter de le déréférencer :

// On suppose que ptr est un pointeur quelconque, qui peut ou non être nul
if (ptr) // si ptr n'est pas un pointeur nul
    std::cout << *ptr << '\n'; // déréférencement autorisé
else
    // faire autre chose qui n'implique pas de déréférencer ptr (afficher un message d'erreur, ne rien faire, etc.)

Mais qu'en est-il des pointeurs pendants ? Comme il n'existe aucun moyen de détecter qu'un pointeur est pendant, nous devons éviter d'avoir des pointeurs pendants dans notre programme dès le départ. Pour cela, nous veillons à ce que tout pointeur qui ne pointe pas vers un objet valide soit mis à nullptr.

Ainsi, avant de déréférencer un pointeur, il suffit de tester s'il est nul : s'il ne l'est pas, nous supposons qu'il n'est pas pendant.

Bonne pratique

Un pointeur doit soit contenir l'adresse d'un objet valide, soit être mis à nullptr. Ainsi, nous n'avons qu'à tester les pointeurs pour savoir s'ils sont nuls, et pouvons considérer tout pointeur non nul comme valide.

Malheureusement, éviter les pointeurs pendants n'est pas toujours facile : lorsqu'un objet est détruit, tous les pointeurs vers cet objet restent pendants. Ces pointeurs ne sont pas mis à null automatiquement ! Il incombe au programmeur de s'assurer que tous les pointeurs vers un objet qui vient d'être détruit sont correctement mis à nullptr.

Avertissement

Lorsqu'un objet est détruit, tous les pointeurs vers l'objet détruit restent pendants (ils ne sont pas automatiquement mis à nullptr). C'est à vous de détecter ces cas et de vous assurer que ces pointeurs sont ensuite mis à nullptr.

Littéraux de pointeur nul historiques : 0 et NULL

Dans du code plus ancien, vous pouvez rencontrer deux autres valeurs littérales utilisées à la place de nullptr.

La première est le littéral 0. Dans le contexte d'un pointeur, le littéral 0 a été spécialement défini pour signifier une valeur nulle, et c'est le seul cas où l'on peut affecter un littéral entier à un pointeur.

int main()
{
    float* ptr { 0 };  // ptr est maintenant un pointeur nul (à titre d'exemple seulement, ne faites pas cela)

    float* ptr2; // ptr2 n'est pas initialisé
    ptr2 = 0; // ptr2 est maintenant un pointeur nul (à titre d'exemple seulement, ne faites pas cela)

    return 0;
}

En passant…

Sur les architectures modernes, l'adresse 0 est généralement utilisée pour représenter un pointeur nul. Cependant, cette valeur n'est pas garantie par la norme C++, et certaines architectures utilisent d'autres valeurs. Le littéral 0, lorsqu'il est utilisé dans le contexte d'un pointeur nul, sera traduit par l'adresse que l'architecture utilise pour représenter un pointeur nul.

Par ailleurs, il existe une macro du préprocesseur nommée NULL (définie dans l'en-tête <cstddef>). Cette macro est héritée du C, où elle sert couramment à indiquer un pointeur nul.

#include <cstddef> // pour NULL

int main()
{
    double* ptr { NULL }; // ptr est un pointeur nul

    double* ptr2; // ptr2 n'est pas initialisé
    ptr2 = NULL; // ptr2 est maintenant un pointeur nul

    return 0;
}

Il faut éviter 0 comme NULL en C++ moderne (utilisez nullptr à la place). Nous expliquerons pourquoi dans la leçon 12.11 -- Passage par adresse (partie 2).

Préférer les références aux pointeurs dans la mesure du possible

Les pointeurs et les références nous permettent tous deux d'accéder indirectement à un autre objet.

Les pointeurs ont en plus la capacité de changer l'objet qu'ils pointent et de pouvoir être nuls. Toutefois, ces capacités sont intrinsèquement dangereuses : un pointeur nul risque d'être déréférencé, et la possibilité de changer ce vers quoi pointe un pointeur rend la création de pointeurs pendants plus facile :

int main()
{
    int* ptr { };

    {
        int x{ 5 };
        ptr = &x; // affecte au pointeur un objet qui sera détruit (impossible avec une référence)
    } // ptr est maintenant pendant et pointe vers un objet invalide

    if (ptr) // la condition est vraie car ptr n'est pas nullptr
        std::cout << *ptr; // comportement indéfini

    return 0;
}

Comme les références ne peuvent pas être liées à null, nous n'avons pas à nous soucier des références nulles. Et comme les références doivent être liées à un objet valide à leur création et ne peuvent pas être réaffectées vers un autre objet, les références pendantes sont plus difficiles à créer.

Parce qu'elles sont plus sûres, les références doivent être privilégiées par rapport aux pointeurs, sauf lorsque les capacités supplémentaires offertes par les pointeurs sont nécessaires.

Bonne pratique

Privilégiez les références aux pointeurs, sauf si les capacités supplémentaires offertes par les pointeurs sont nécessaires.

Une blague

Avez-vous entendu la blague sur le pointeur nul ?

Ce n'est pas grave, vous n'auriez pas compris le déréférencement.

Temps de quiz

Question n° 1

1a) Peut-on déterminer si un pointeur est nul ou non ? Si oui, comment ?

Solution

Oui, on peut utiliser une condition (instruction if ou opérateur conditionnel) sur le pointeur. Un pointeur se convertit en booléen false s'il est nul, et en true sinon.

1b) Peut-on déterminer si un pointeur non nul est valide ou pendant ? Si oui, comment ?

Solution

Il n'existe pas de moyen simple de le déterminer.

Question n° 3

Pourquoi devons-nous mettre à nullptr les pointeurs qui ne pointent pas vers un objet valide ?

Solution

Nous ne pouvons pas déterminer si un pointeur non nul est valide ou pendant, et accéder à un pointeur pendant entraîne un comportement indéfini. Nous devons donc nous assurer qu'il n'y a aucun pointeur pendant dans notre programme.

Si nous veillons à ce que tous les pointeurs pointent soit vers des objets valides, soit vers nullptr, alors nous pouvons utiliser une condition pour tester la nullité et éviter de déréférencer un pointeur nul, et considérer que tous les pointeurs non nuls pointent vers des objets valides.
