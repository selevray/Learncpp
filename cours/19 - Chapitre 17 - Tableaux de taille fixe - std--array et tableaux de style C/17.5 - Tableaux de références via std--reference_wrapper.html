17.5 — Tableaux de références via std::reference_wrapper

Dans la leçon précédente, nous avons mentionné que les tableaux peuvent contenir des éléments de n'importe quel type d'objet. Cela inclut les objets de types fondamentaux (par exemple int) et les objets de types composés (par exemple pointeur vers int).

#include <array>
#include <iostream>
#include <vector>

int main()
{
    int x { 1 };
    int y { 2 };

    [[maybe_unused]] std::array valarr { x, y };   // un tableau de valeurs int
    [[maybe_unused]] std::vector ptrarr { &x, &y }; // un vecteur de pointeurs vers int

    return 0;
}

Cependant, comme les références ne sont pas des objets, il est impossible de créer un tableau de références. Les éléments d'un tableau doivent aussi être assignables, et les références ne peuvent pas être réaffectées (reseated).

#include <array>
#include <iostream>

int main()
{
    int x { 1 };
    int y { 2 };

    [[maybe_unused]] std::array<int&, 2> refarr { x, y }; // erreur de compilation : impossible de définir un tableau de références

    int& ref1 { x };
    int& ref2 { y };
    [[maybe_unused]] std::array valarr { ref1, ref2 }; // ok : il s'agit en fait d'un std::array<int, 2>, et non d'un tableau de références

    return 0;
}

Dans cette leçon, nous utiliserons std::array dans les exemples, mais cela s'applique de la même façon à tous les types de tableaux.

Si vous voulez tout de même un tableau de références, il existe cependant une solution de contournement.

std::reference_wrapper

std::reference_wrapper est un modèle de classe (class template) de la bibliothèque standard, défini dans l'en-tête <functional>. Il prend un argument de modèle de type T, et se comporte ensuite comme une référence lvalue modifiable vers T.

Quelques points à noter au sujet de std::reference_wrapper :

  • operator= réaffecte un std::reference_wrapper (change l'objet référencé).
  • std::reference_wrapper<T> se convertit implicitement en T&.
  • La fonction membre get() permet d'obtenir un T&. Elle est utile lorsque nous voulons modifier la valeur de l'objet référencé.

Voici un exemple simple :

#include <array>
#include <functional> // pour std::reference_wrapper
#include <iostream>

int main()
{
    int x { 1 };
    int y { 2 };
    int z { 3 };

    std::array<std::reference_wrapper<int>, 3> arr { x, y, z };

    arr[1].get() = 5; // modifie l'objet stocké dans l'élément 1 du tableau

    std::cout << arr[1] << y << '\n'; // montre que nous avons modifié arr[1] et y, affiche 55

    return 0;
}

Cet exemple affiche :


55

Notez que nous devons écrire arr[1].get() = 5 et non arr[1] = 5. Cette dernière écriture est ambiguë, car le compilateur ne peut pas savoir si nous voulons réaffecter le std::reference_wrapper<int> à la valeur 5 (ce qui est de toute façon illégal) ou modifier la valeur référencée. L'utilisation de get() lève cette ambiguïté.

Lors de l'affichage de arr[1], le compilateur constate qu'il ne peut pas afficher un std::reference_wrapper<int>, il le convertit donc implicitement en int&, qu'il sait afficher. Nous n'avons donc pas besoin d'utiliser get() ici.

std::ref et std::cref

Avant C++17, la déduction d'arguments de modèle de classe (CTAD, class template argument deduction) n'existait pas, si bien que tous les arguments de modèle d'un type classe devaient être listés explicitement. Ainsi, pour créer un std::reference_wrapper<int>, vous pouviez procéder de l'une de ces deux manières :

    int x { 5 };

    std::reference_wrapper<int> ref1 { x };        // C++11
    auto ref2 { std::reference_wrapper<int>{ x }}; // C++11

Entre le nom long et l'obligation de lister explicitement les arguments de modèle, créer de nombreux wrappers de références pouvait vite devenir fastidieux.

Pour simplifier les choses, les fonctions std::ref() et std::cref() ont été fournies comme raccourcis pour créer des objets encapsulés de type std::reference_wrapper et const std::reference_wrapper. Notez que ces fonctions peuvent être utilisées avec auto, ce qui évite d'avoir à spécifier explicitement l'argument de modèle.

    int x { 5 };
    auto ref { std::ref(x) };   // C++11, déduit std::reference_wrapper<int>
    auto cref { std::cref(x) }; // C++11, déduit std::reference_wrapper<const int>

Bien sûr, maintenant que nous disposons de la CTAD en C++17, nous pouvons aussi écrire :

    std::reference_wrapper ref1 { x };        // C++17
    auto ref2 { std::reference_wrapper{ x }}; // C++17

Mais comme std::ref() et std::cref() sont plus courts à taper, ils restent largement utilisés pour créer des objets std::reference_wrapper.
