17.1 — Introduction à std::array

Dans la leçon 16.1 -- Introduction aux conteneurs et aux tableaux, nous avons présenté les conteneurs et les tableaux. En résumé :

  • Les conteneurs fournissent un espace de stockage pour une collection d'objets sans nom (appelés éléments).
  • Les tableaux allouent leurs éléments de manière contiguë en mémoire et permettent un accès rapide et direct à n'importe quel élément via l'opérateur d'indexation.
  • C++ dispose de trois types de tableaux couramment utilisés : std::vector, std::array et les tableaux de style C.

Dans la leçon 16.10 -- Redimensionnement et capacité de std::vector, nous avons mentionné que les tableaux se répartissent en deux catégories :

  • Les tableaux de taille fixe (aussi appelés tableaux de longueur fixe) exigent que leur longueur soit connue au moment de l'instanciation, et cette longueur ne peut plus être modifiée ensuite. Les tableaux de style C et std::array sont tous deux des tableaux de taille fixe.
  • Les tableaux dynamiques peuvent être redimensionnés à l'exécution. std::vector est un tableau dynamique.

Dans le chapitre précédent, nous nous sommes concentrés sur std::vector, car il est rapide, relativement facile à utiliser et polyvalent. C'est donc notre choix par défaut lorsque nous avons besoin d'un conteneur de type tableau.

Pourquoi ne pas utiliser les tableaux dynamiques partout ?

Les tableaux dynamiques sont puissants et pratiques, mais comme toute chose, ils impliquent des compromis en contrepartie des avantages qu'ils offrent.

  • std::vector est légèrement moins performant que les tableaux de taille fixe. Dans la plupart des cas, vous ne remarquerez probablement pas la différence (sauf si vous écrivez du code négligé qui provoque de nombreuses réallocations involontaires).
  • std::vector ne prend en charge constexpr que dans des contextes très limités.

En C++ moderne, c'est vraiment ce dernier point qui est important. Les tableaux constexpr permettent d'écrire du code plus robuste, que le compilateur peut également optimiser davantage. Chaque fois que nous pouvons utiliser un tableau constexpr, nous devrions le faire, et si nous avons besoin d'un tableau constexpr, std::array est la classe de conteneur à utiliser.

Bonne pratique

Utilisez std::array pour les tableaux constexpr, et std::vector pour les tableaux non constexpr.

Définir un std::array

std::array est défini dans l'en-tête <array>. Il est conçu pour fonctionner de manière similaire à std::vector, et comme vous le verrez, les ressemblances entre les deux sont plus nombreuses que les différences.

Une différence concerne la manière de déclarer un std::array :

#include <array>  // pour std::array
#include <vector> // pour std::vector

int main()
{
    std::array<int, 5> a {};  // un std::array de 5 int

    std::vector<int> b(5);    // un std::vector de 5 int (pour comparaison)

    return 0;
}

Notre déclaration de std::array possède deux arguments de modèle. Le premier (int) est un argument de modèle de type définissant le type des éléments du tableau. Le second (5) est un argument de modèle non-type entier définissant la longueur du tableau.

Contenu associé

Nous abordons les paramètres de modèle non-type dans la leçon 11.9 -- Paramètres de modèle non-type.

La longueur d'un std::array doit être une expression constante

Contrairement à un std::vector, qui peut être redimensionné à l'exécution, la longueur d'un std::array doit être une expression constante. Le plus souvent, la valeur fournie pour la longueur sera un littéral entier, une variable constexpr ou un énumérateur non scopé.

#include <array>

int main()
{
    std::array<int, 7> a {}; // Utilisation d'une constante littérale

    constexpr int len { 8 };
    std::array<int, len> b {}; // Utilisation d'une variable constexpr

    enum Colors
    {
         red,
         green,
         blue,
         max_colors
    };

    std::array<int, max_colors> c {}; // Utilisation d'un énumérateur

#define DAYS_PER_WEEK 7
    std::array<int, DAYS_PER_WEEK> d {}; // Utilisation d'une macro (à éviter, utilisez plutôt une variable constexpr)

    return 0;
}

Notez que les variables non constantes et les constantes d'exécution ne peuvent pas être utilisées pour la longueur :

#include <array>
#include <iostream>

void foo(const int length) // length est une constante d'exécution
{
    std::array<int, length> e {}; // erreur : length n'est pas une expression constante
}

int main()
{
    // utilisation d'une variable non const
    int numStudents{};
    std::cin >> numStudents; // numStudents est non constant

    std::array<int, numStudents> {}; // erreur : numStudents n'est pas une expression constante

    foo(7);

    return 0;
}

Avertissement

Chose peut-être surprenante, un std::array peut être défini avec une longueur de 0 :

#include <array>
#include <iostream>

int main()
{
    std::array<int, 0> arr {}; // crée un std::array de longueur nulle
    std::cout << arr.empty();  // true si arr est de longueur nulle

    return 0;
}

Un std::array de longueur nulle est un cas particulier de classe qui ne contient aucune donnée. Par conséquent, appeler une fonction membre qui accède aux données d'un std::array de longueur nulle (y compris operator[]) provoque un comportement indéfini.

Vous pouvez vérifier si un std::array est de longueur nulle à l'aide de la fonction membre empty(), qui renvoie true si le tableau est de longueur nulle, et false sinon.

Initialisation par agrégat d'un std::array

Chose peut-être surprenante, std::array est un agrégat. Cela signifie qu'il n'a pas de constructeurs et qu'il s'initialise par initialisation par agrégat. Pour rappel rapide, l'initialisation par agrégat nous permet d'initialiser directement les membres d'un agrégat. Pour cela, nous fournissons une liste d'initialisation, c'est-à-dire une liste de valeurs d'initialisation séparées par des virgules et entourées d'accolades.

Contenu associé

Nous avons vu l'initialisation par agrégat pour les structures dans la leçon 13.8 -- Initialisation par agrégat des structures.

#include <array>

int main()
{
    std::array<int, 6> fibonnaci = { 0, 1, 1, 2, 3, 5 }; // initialisation par copie avec liste entre accolades
    std::array<int, 5> prime { 2, 3, 5, 7, 11 };         // initialisation par liste avec accolades (à privilégier)

    return 0;
}

Chacune de ces formes d'initialisation initialise les membres du tableau dans l'ordre, en commençant par l'élément 0.

Si un std::array est défini sans initialiseur, ses éléments sont initialisés par défaut. Dans la plupart des cas, cela laisse les éléments non initialisés.

Comme nous voulons généralement que nos éléments soient initialisés, un std::array doit être initialisé par valeur (à l'aide d'accolades vides) lorsqu'il est défini sans initialiseur.

#include <array>
#include <vector>

int main()
{
    std::array<int, 5> a;   // Membres initialisés par défaut (les éléments int restent non initialisés)
    std::array<int, 5> b{}; // Membres initialisés par valeur (les éléments int sont initialisés à zéro) (à privilégier)

    std::vector<int> v(5);  // Membres initialisés par valeur (les éléments int sont initialisés à zéro) (pour comparaison)

    return 0;
}

Si la liste d'initialisation contient plus d'initialiseurs que la longueur du tableau défini, le compilateur signale une erreur. Si elle en contient moins, les éléments restants sans initialiseur sont initialisés par valeur :

#include <array>

int main()
{
    std::array<int, 4> a { 1, 2, 3, 4, 5 }; // erreur de compilation : trop d'initialiseurs
    std::array<int, 4> b { 1, 2 };          // b[2] et b[3] sont initialisés par valeur

    return 0;
}

std::array const et constexpr

Un std::array peut être const :

#include <array>

int main()
{
    const std::array<int, 5> prime { 2, 3, 5, 7, 11 };

    return 0;
}

Bien que les éléments d'un std::array const ne soient pas explicitement marqués comme const, ils sont tout de même traités comme tels (puisque le tableau entier est const).

std::array prend également pleinement en charge constexpr :

#include <array>

int main()
{
    constexpr std::array<int, 5> prime { 2, 3, 5, 7, 11 };

    return 0;
}

Cette prise en charge de constexpr est la raison principale d'utiliser std::array.

Bonne pratique

Définissez votre std::array comme constexpr chaque fois que c'est possible. Si votre std::array ne peut pas être constexpr, envisagez plutôt un std::vector.

Déduction d'arguments de modèle de classe (CTAD) pour std::array (C++17)

Grâce à la CTAD (class template argument deduction) introduite en C++17, nous pouvons laisser le compilateur déduire à la fois le type des éléments et la longueur d'un std::array à partir d'une liste d'initialiseurs :

#include <array>
#include <iostream>

int main()
{
    constexpr std::array a1 { 9, 7, 5, 3, 1 }; // Le type est déduit comme std::array<int, 5>
    constexpr std::array a2 { 9.7, 7.31 };     // Le type est déduit comme std::array<double, 2>

    return 0;
}

Nous privilégions cette syntaxe chaque fois que c'est possible. Si votre compilateur ne prend pas en charge C++17, vous devrez fournir explicitement les arguments de modèle de type et de longueur.

Bonne pratique

Utilisez la déduction d'arguments de modèle de classe (CTAD) pour que le compilateur déduise le type et la longueur d'un std::array à partir de ses initialiseurs.

La CTAD ne prend pas en charge l'omission partielle des arguments de modèle (jusqu'à C++23 inclus). Il n'existe donc aucun moyen d'omettre uniquement la longueur ou uniquement le type d'un std::array à l'aide de la fonctionnalité du langage :

#include <iostream>

int main()
{
    constexpr std::array<int> a2 { 9, 7, 5, 3, 1 };     // erreur : trop peu d'arguments de modèle (longueur manquante)
    constexpr std::array<5> a2 { 9, 7, 5, 3, 1 };       // erreur : trop peu d'arguments de modèle (type manquant)

    return 0;
}

Omettre uniquement la longueur du tableau avec std::to_array (C++20)

En revanche, la déduction d'arguments de modèle (TAD, utilisée pour la résolution des fonctions modèles) prend en charge l'omission partielle des arguments de modèle. Depuis C++20, il est possible d'omettre la longueur d'un std::array à l'aide de la fonction utilitaire std::to_array :

#include <array>
#include <iostream>

int main()
{
    constexpr auto myArray1 { std::to_array<int, 5>({ 9, 7, 5, 3, 1 }) }; // Spécifie le type et la taille
    constexpr auto myArray2 { std::to_array<int>({ 9, 7, 5, 3, 1 }) };    // Spécifie uniquement le type, déduit la taille
    constexpr auto myArray3 { std::to_array({ 9, 7, 5, 3, 1 }) };         // Déduit le type et la taille

    return 0;
}

Malheureusement, utiliser std::to_array coûte plus cher que de créer directement un std::array, car cela implique la création d'un std::array temporaire, qui sert ensuite à l'initialisation par copie du std::array souhaité. Pour cette raison, std::to_array ne doit être utilisé que lorsque le type ne peut pas être déterminé efficacement à partir des initialiseurs, et doit être évité lorsqu'un tableau est créé très souvent (par exemple dans une boucle).

Par exemple, comme il n'existe pas de moyen d'écrire un littéral de type short, vous pouvez utiliser le code suivant pour créer un std::array de valeurs short sans avoir à spécifier explicitement la longueur du std::array :

#include <array>
#include <iostream>

int main()
{
    constexpr auto shortArray { std::to_array<short>({ 9, 7, 5, 3, 1 }) };
    std::cout << sizeof(shortArray[0]) << '\n';

    return 0;
}

Accéder aux éléments d'un tableau avec operator[]

Comme pour std::vector, la manière la plus courante d'accéder aux éléments d'un std::array est l'opérateur d'indexation (operator[]) :

#include <array> // pour std::array
#include <iostream>

int main()
{
    constexpr std::array<int, 5> prime{ 2, 3, 5, 7, 11 };

    std::cout << prime[3]; // affiche la valeur de l'élément d'indice 3 (7)
    std::cout << prime[9]; // indice invalide (comportement indéfini)

    return 0;
}

Pour rappel, operator[] ne vérifie pas les bornes. Si un indice invalide est fourni, il en résulte un comportement indéfini.

Nous verrons quelques autres façons d'indexer un std::array dans la prochaine leçon.

Quiz

Question n° 1

Quel type d'initialisation std::array utilise-t-il ?

Solution

std::array est un agrégat, il utilise donc l'initialisation par agrégat.

Pourquoi devez-vous explicitement initialiser par valeur un std::array si vous ne fournissez pas de valeurs d'initialisation ?

Solution

Un std::array initialise par défaut ses membres si aucun initialiseur n'est fourni. Cela laisse non initialisés les éléments de la plupart des types.

Question n° 2

Définissez un std::array qui contiendra la température maximale de chaque jour de l'année (au dixième de degré près).

Solution 
#include <array>

std::array<double, 365> highTemp {};

Question n° 3

Initialisez un std::array avec les valeurs suivantes : 'h', 'e', 'l', 'l', 'o'. Affichez la valeur de l'élément d'indice 1.

Solution 
#include <array>
#include <iostream>

int main()
{
        constexpr std::array arr { 'h', 'e', 'l', 'l', 'o' };
        std::cout << arr[1] << '\n';

        return 0;
}
