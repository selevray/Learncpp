17.11 — Constantes symboliques de chaînes de style C

Dans la leçon précédente (17.10 -- Chaînes de style C), nous avons vu comment créer et initialiser des objets chaînes de style C :

#include <iostream>

int main()
{
    char name[]{ "Alex" }; // chaîne de style C
    std::cout << name << '\n';

    return 0;
}

C++ prend en charge deux manières différentes de créer des constantes symboliques de chaînes de style C :

#include <iostream>

int main()
{
    const char name[] { "Alex" };        // cas 1 : chaîne de style C constante initialisée avec un littéral de chaîne de style C
    const char* const color{ "Orange" }; // cas 2 : pointeur constant vers un littéral de chaîne de style C

    std::cout << name << ' ' << color << '\n';

    return 0;
}

Ce programme affiche :


Alex Orange

Bien que ces deux méthodes produisent le même résultat, C++ gère l'allocation mémoire de ces deux cas un peu différemment.

Dans le cas 1, « Alex » est placé quelque part en mémoire (probablement en lecture seule). Ensuite, le programme alloue un tableau de style C de longueur 5 (quatre caractères explicites plus le caractère de fin de chaîne nul) et initialise cette mémoire avec la chaîne « Alex ». Nous nous retrouvons donc avec 2 copies de « Alex » : une dans la mémoire globale, et l'autre appartenant à name. Comme name est constant (et ne sera jamais modifié), faire une copie est inefficace.

Dans le cas 2, la façon dont le compilateur procède dépend de l'implémentation. Ce qui se passe généralement est que le compilateur place la chaîne « Orange » en mémoire en lecture seule, puis initialise le pointeur avec l'adresse de cette chaîne.

À des fins d'optimisation, plusieurs littéraux de chaînes peuvent être regroupés en une seule valeur. Par exemple :

const char* name1{ "Alex" };
const char* name2{ "Alex" };

Ce sont deux littéraux de chaînes différents ayant la même valeur. Comme ces littéraux sont constants, le compilateur peut choisir d'économiser de la mémoire en les fusionnant en un seul littéral partagé, name1 et name2 pointant alors vers la même adresse.

Déduction de type avec les chaînes de style C constantes

La déduction de type à partir d'un littéral de chaîne de style C est assez simple :

    auto s1{ "Alex" };  // type déduit : const char*
    auto* s2{ "Alex" }; // type déduit : const char*
    auto& s3{ "Alex" }; // type déduit : const char(&)[5]

Affichage de pointeurs et de chaînes de style C

Vous avez peut-être remarqué quelque chose d'intéressant dans la manière dont std::cout traite les pointeurs de différents types.

Considérez l'exemple suivant :

#include <iostream>

int main()
{
    int narr[]{ 9, 7, 5, 3, 1 };
    char carr[]{ "Hello!" };
    const char* ptr{ "Alex" };

    std::cout << narr << '\n'; // narr se dégrade en type int*
    std::cout << carr << '\n'; // carr se dégrade en type char*
    std::cout << ptr << '\n'; // ptr est déjà de type char*

    return 0;
}

Sur la machine de l'auteur, ce programme a affiché :


003AF738
Hello!
Alex

Pourquoi le tableau d'entiers affiche-t-il une adresse, alors que les tableaux de caractères s'affichent comme des chaînes ?

La réponse est que les flux de sortie (par exemple std::cout) font certaines hypothèses sur vos intentions. Si vous leur transmettez un pointeur qui n'est pas de type char, ils affichent simplement le contenu de ce pointeur (l'adresse qu'il contient). En revanche, si vous leur transmettez un objet de type char* ou const char*, ils supposent que vous souhaitez afficher une chaîne. Par conséquent, au lieu d'afficher la valeur du pointeur (une adresse), ils affichent la chaîne pointée !

Bien que ce comportement soit souhaitable la plupart du temps, il peut conduire à des résultats inattendus. Considérez le cas suivant :

#include <iostream>

int main()
{
    char c{ 'Q' };
    std::cout << &c;

    return 0;
}

Dans ce cas, le programmeur souhaite afficher l'adresse de la variable c. Cependant, &c est de type char*, donc std::cout tente de l'afficher comme une chaîne ! Et comme c n'est pas terminée par un caractère nul, nous obtenons un comportement indéfini.

Sur la machine de l'auteur, ce programme a affiché :


Q╠╠╠╠╜╡4;¿■A

Pourquoi cela s'est-il produit ? Eh bien, il a d'abord supposé que &c (de type char*) était une chaîne de style C. Il a donc affiché le 'Q', puis a continué. Ensuite, en mémoire, se trouvaient des données aléatoires. Finalement, il a rencontré une zone mémoire contenant la valeur 0, qu'il a interprétée comme un caractère de fin de chaîne, et s'est arrêté. Ce que vous observerez peut être différent, selon le contenu de la mémoire située après la variable c.

Ce cas est assez peu probable dans la pratique (vous n'aurez sans doute pas réellement besoin d'afficher des adresses mémoire), mais il illustre le fonctionnement interne du langage et la façon dont un programme peut involontairement dérailler.

Si vous souhaitez réellement afficher l'adresse contenue dans un pointeur de caractères, effectuez un static_cast vers le type const void* :

#include <iostream>

int main()
{
    const char* ptr{ "Alex" };

    std::cout << ptr << '\n';                           // affiche ptr comme une chaîne de style C
    std::cout << static_cast<const void*>(ptr) << '\n'; // affiche l'adresse contenue dans ptr

    return 0;
}

Contenu associé

Nous abordons void* dans la leçon 19.5 -- Pointeurs void. Vous n'avez pas besoin de savoir comment il fonctionne pour l'utiliser ici.

Privilégier std::string_view pour les constantes symboliques de chaînes de style C

Il y a peu de raisons d'utiliser des constantes symboliques de chaînes de style C en C++ moderne. Privilégiez plutôt les objets constexpr std::string_view, qui sont généralement aussi rapides (voire plus) et se comportent de manière plus cohérente.

Bonne pratique

Évitez les constantes symboliques de chaînes de style C au profit de constexpr std::string_view.
