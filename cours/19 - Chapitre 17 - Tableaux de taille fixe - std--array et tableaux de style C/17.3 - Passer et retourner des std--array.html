17.3 — Passer et retourner des std::array

Un objet de type std::array peut être passé à une fonction comme n'importe quel autre objet. Cela signifie que si nous passons un std::array par valeur, une copie coûteuse sera effectuée. Nous passons donc typiquement les std::array par référence (constante) afin d'éviter ces copies.

Avec un std::array, le type de l'élément et la longueur du tableau font tous deux partie des informations de type de l'objet. Par conséquent, lorsque nous utilisons un std::array comme paramètre de fonction, nous devons spécifier explicitement à la fois le type des éléments et la longueur du tableau :

#include <array>
#include <iostream>

void passByRef(const std::array<int, 5>& arr) // nous devons spécifier explicitement <int, 5> ici
{
    std::cout << arr[0] << '\n';
}

int main()
{
    std::array arr{ 9, 7, 5, 3, 1 }; // la CTAD déduit le type std::array<int, 5>
    passByRef(arr);

    return 0;
}

La CTAD ne fonctionne pas (actuellement) avec les paramètres de fonction : nous ne pouvons donc pas simplement écrire std::array ici et laisser le compilateur déduire les arguments de modèle.

Utiliser des modèles de fonction pour passer des std::array de types d'éléments ou de longueurs différents

Pour écrire une fonction capable d'accepter un std::array avec n'importe quel type d'élément et n'importe quelle longueur, nous pouvons créer un modèle de fonction qui paramètre à la fois le type des éléments et la longueur de notre std::array. C++ utilisera alors ce modèle de fonction pour instancier des fonctions réelles avec des types et des longueurs concrets.

Contenu associé

Nous traitons des modèles de fonction dans la leçon 11.6 -- Modèles de fonctions.

Puisque std::array est défini ainsi :

template<typename T, std::size_t N> // N est un paramètre de modèle non‑type
struct array;

Nous pouvons créer un modèle de fonction qui utilise la même déclaration de paramètres de modèle :

#include <array>
#include <iostream>

template <typename T, std::size_t N> // notez que cette déclaration de paramètres de modèle correspond à celle de std::array
void passByRef(const std::array<T, N>& arr)
{
    static_assert(N != 0); // échoue si ce std::array est de longueur nulle

    std::cout << arr[0] << '\n';
}

int main()
{
    std::array arr{ 9, 7, 5, 3, 1 }; // utilise la CTAD pour déduire std::array<int, 5>
    passByRef(arr);  // ok : le compilateur instanciera passByRef(const std::array<int, 5>& arr)

    std::array arr2{ 1, 2, 3, 4, 5, 6 }; // utilise la CTAD pour déduire std::array<int, 6>
    passByRef(arr2); // ok : le compilateur instanciera passByRef(const std::array<int, 6>& arr)

    std::array arr3{ 1.2, 3.4, 5.6, 7.8, 9.9 }; // utilise la CTAD pour déduire std::array<double, 5>
    passByRef(arr3); // ok : le compilateur instanciera passByRef(const std::array<double, 5>& arr)

    return 0;
}

Dans l'exemple ci-dessus, nous avons créé un unique modèle de fonction nommé passByRef() qui possède un paramètre de type std::array<T, N>. T et N sont définis dans la déclaration de paramètres de modèle de la ligne précédente : template <typename T, std::size_t N>. T est un paramètre de modèle de type standard qui permet à l'appelant de spécifier le type des éléments. N est un paramètre de modèle non‑type de type std::size_t qui permet à l'appelant de spécifier la longueur du tableau.

Attention

Notez que le type du paramètre de modèle non‑type de std::array doit être std::size_t, et non int ! En effet, std::array est défini comme template<class T, std::size_t N> struct array;. Si vous utilisez int comme type du paramètre de modèle non‑type, le compilateur ne pourra pas faire correspondre l'argument de type std::array<T, std::size_t> avec le paramètre de type std::array<T, int> (et les modèles n'effectuent pas de conversions).

Ainsi, lorsque nous appelons passByRef(arr) depuis main() (où arr est défini comme un std::array<int, 5>), le compilateur instanciera et appellera void passByRef(const std::array<int, 5>& arr). Un processus similaire se produit pour arr2 et arr3.

Nous avons donc créé un unique modèle de fonction capable d'instancier des fonctions traitant des arguments std::array de n'importe quel type d'élément et de n'importe quelle longueur !

Si on le souhaite, il est également possible de ne paramétrer qu'un seul des deux paramètres de modèle. Dans l'exemple suivant, nous ne paramétrons que la longueur du std::array, tandis que le type des éléments est explicitement défini comme int :

#include <array>
#include <iostream>

template <std::size_t N> // note : seule la longueur est paramétrée ici
void passByRef(const std::array<int, N>& arr) // nous avons défini le type des éléments comme int
{
    static_assert(N != 0); // échoue si ce std::array est de longueur nulle

    std::cout << arr[0] << '\n';
}

int main()
{
    std::array arr{ 9, 7, 5, 3, 1 }; // utilise la CTAD pour déduire std::array<int, 5>
    passByRef(arr);  // ok : le compilateur instanciera passByRef(const std::array<int, 5>& arr)

    std::array arr2{ 1, 2, 3, 4, 5, 6 }; // utilise la CTAD pour déduire std::array<int, 6>
    passByRef(arr2); // ok : le compilateur instanciera passByRef(const std::array<int, 6>& arr)

    std::array arr3{ 1.2, 3.4, 5.6, 7.8, 9.9 }; // utilise la CTAD pour déduire std::array<double, 5>
    passByRef(arr3); // erreur : le compilateur ne trouve pas de fonction correspondante

    return 0;
}

Paramètres de modèle non‑type à auto (C++20)

Devoir se souvenir (ou rechercher) le type d'un paramètre de modèle non‑type afin de pouvoir l'utiliser dans la déclaration de paramètres de modèle de nos propres modèles de fonction est fastidieux.

En C++20, nous pouvons utiliser auto dans une déclaration de paramètres de modèle pour qu'un paramètre de modèle non‑type déduise son type à partir de l'argument :

#include <array>
#include <iostream>

template <typename T, auto N> // utilise désormais auto pour déduire le type de N
void passByRef(const std::array<T, N>& arr)
{
    static_assert(N != 0); // échoue si ce std::array est de longueur nulle

    std::cout << arr[0] << '\n';
}

int main()
{
    std::array arr{ 9, 7, 5, 3, 1 }; // utilise la CTAD pour déduire std::array<int, 5>
    passByRef(arr);  // ok : le compilateur instanciera passByRef(const std::array<int, 5>& arr)

    std::array arr2{ 1, 2, 3, 4, 5, 6 }; // utilise la CTAD pour déduire std::array<int, 6>
    passByRef(arr2); // ok : le compilateur instanciera passByRef(const std::array<int, 6>& arr)

    std::array arr3{ 1.2, 3.4, 5.6, 7.8, 9.9 }; // utilise la CTAD pour déduire std::array<double, 5>
    passByRef(arr3); // ok : le compilateur instanciera passByRef(const std::array<double, 5>& arr)

    return 0;
}

Si votre compilateur est compatible C++20, vous pouvez utiliser cette forme sans problème.

Vérifier la longueur du tableau avec static_assert

Considérons le modèle de fonction suivant, semblable à celui présenté ci-dessus :

#include <array>
#include <iostream>

template <typename T, std::size_t N>
void printElement3(const std::array<T, N>& arr)
{
    std::cout << arr[3] << '\n';
}

int main()
{
    std::array arr{ 9, 7, 5, 3, 1 };
    printElement3(arr);

    return 0;
}

Bien que printElement3() fonctionne parfaitement dans ce cas, ce programme contient un bogue potentiel qui attend un programmeur peu méfiant. Le voyez-vous ?

Le programme ci-dessus affiche la valeur de l'élément du tableau d'indice 3. C'est correct tant que le tableau possède un élément valide d'indice 3. Cependant, le compilateur acceptera sans broncher des tableaux pour lesquels l'indice 3 est hors limites. Par exemple :

#include <array>
#include <iostream>

template <typename T, std::size_t N>
void printElement3(const std::array<T, N>& arr)
{
    std::cout << arr[3] << '\n'; // indice invalide
}

int main()
{
    std::array arr{ 9, 7 }; // un tableau de 2 éléments (indices valides 0 et 1)
    printElement3(arr);

    return 0;
}

Cela conduit à un comportement indéfini. Idéalement, nous aimerions que le compilateur nous avertisse lorsque nous tentons ce genre de chose !

Un avantage que les paramètres de modèle ont sur les paramètres de fonction est que les paramètres de modèle sont des constantes de compilation. Nous pouvons donc tirer parti des fonctionnalités qui requièrent des expressions constantes.

Une solution consiste donc à utiliser std::get() (qui effectue une vérification des bornes à la compilation) au lieu de operator[] (qui n'effectue aucune vérification des bornes) :

#include <array>
#include <iostream>

template <typename T, std::size_t N>
void printElement3(const std::array<T, N>& arr)
{
    std::cout << std::get<3>(arr) << '\n'; // vérifie à la compilation que l'indice 3 est valide
}

int main()
{
    std::array arr{ 9, 7, 5, 3, 1 };
    printElement3(arr); // ok

    std::array arr2{ 9, 7 };
    printElement3(arr2); // erreur de compilation

    return 0;
}

Lorsque le compilateur rencontre l'appel printElement3(arr2), il instanciera la fonction printElement3(const std::array<int, 2>&). Dans le corps de cette fonction se trouve la ligne std::get<3>(arr). Comme la longueur du paramètre tableau est 2, il s'agit d'un accès invalide, et le compilateur émettra une erreur.

Une autre solution consiste à utiliser static_assert pour valider nous-mêmes une précondition sur la longueur du tableau :

Contenu associé

Nous traitons des préconditions dans la leçon 9.6 -- Assert et static_assert.

#include <array>
#include <iostream>

template <typename T, std::size_t N>
void printElement3(const std::array<T, N>& arr)
{
    // précondition : la longueur du tableau doit être supérieure à 3 pour que l'élément 3 existe
    static_assert (N > 3);

    // nous pouvons supposer que la longueur du tableau est supérieure à 3 au-delà de ce point

    std::cout << arr[3] << '\n';
}

int main()
{
    std::array arr{ 9, 7, 5, 3, 1 };
    printElement3(arr); // ok

    std::array arr2{ 9, 7 };
    printElement3(arr2); // erreur de compilation

    return 0;
}

Lorsque le compilateur rencontre l'appel printElement3(arr2), il instanciera la fonction printElement3(const std::array<int, 2>&). Dans le corps de cette fonction se trouve la ligne static_assert (N > 3). Comme le paramètre de modèle non‑type N a la valeur 2, et que 2 > 3 est faux, le compilateur émettra une erreur.

Point clé

Dans l'exemple ci-dessus, vous vous demandez peut-être pourquoi nous utilisons static_assert (N > 3); plutôt que static_assert (std::size(arr) > 3). Cette dernière forme ne compile pas avant C++23, à cause du défaut du langage mentionné dans la leçon précédente (17.2 -- Longueur et indexation de std::array).

Retourner un std::array

Mis à part la syntaxe, passer un std::array à une fonction est conceptuellement simple : on le passe par référence (constante). Mais que faire si une fonction doit retourner un std::array ? Les choses se compliquent un peu. Contrairement à std::vector, std::array n'est pas déplaçable (move-capable) : retourner un std::array par valeur produira donc une copie du tableau. Les éléments du tableau seront déplacés s'ils sont déplaçables, et copiés sinon.

Il existe deux options conventionnelles, et le choix dépend des circonstances.

Retourner un std::array par valeur

Il est acceptable de retourner un std::array par valeur lorsque toutes les conditions suivantes sont réunies :

  • Le tableau n'est pas énorme.
  • Le type des éléments est peu coûteux à copier (ou à déplacer).
  • Le code n'est pas utilisé dans un contexte sensible aux performances.

Dans de tels cas, une copie du std::array sera effectuée, mais si toutes les conditions ci-dessus sont vraies, le surcoût sera minime, et s'en tenir à la manière la plus conventionnelle de renvoyer des données à l'appelant peut être le meilleur choix.

#include <array>
#include <iostream>
#include <limits>

// retour par valeur
template <typename T, std::size_t N>
std::array<T, N> inputArray() // retour par valeur
{
    std::array<T, N> arr{};
    std::size_t index { 0 };
    while (index < N)
    {
        std::cout << "Entrez la valeur n° " << index << " : ";
        std::cin >> arr[index];

        if (!std::cin) // gère les entrées invalides
        {
            std::cin.clear();
            std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
            continue;
        }
        ++index;
    }

    return arr;
}

int main()
{
    std::array<int, 5> arr { inputArray<int, 5>() };

    std::cout << "La valeur de l'élément 2 est " << arr[2] << '\n';

    return 0;
}

Cette méthode présente plusieurs avantages :

  • Elle utilise la manière la plus conventionnelle de renvoyer des données à l'appelant.
  • Il est évident que la fonction retourne une valeur.
  • Nous pouvons définir un tableau et l'initialiser avec la fonction en une seule instruction.

Elle présente aussi quelques inconvénients :

  • La fonction retourne une copie du tableau et de tous ses éléments, ce qui n'est pas bon marché.
  • Lorsque nous appelons la fonction, nous devons fournir explicitement les arguments de modèle, puisqu'il n'existe aucun paramètre dont on pourrait les déduire.

Retourner un std::array via un paramètre de sortie

Lorsque le retour par valeur est trop coûteux, nous pouvons utiliser un paramètre de sortie à la place. Dans ce cas, c'est l'appelant qui est responsable de passer le std::array par référence non constante (ou par adresse), et la fonction peut alors modifier ce tableau.

#include <array>
#include <limits>
#include <iostream>

template <typename T, std::size_t N>
void inputArray(std::array<T, N>& arr) // passage par référence non constante
{
    std::size_t index { 0 };
    while (index < N)
    {
        std::cout << "Entrez la valeur n° " << index << " : ";
        std::cin >> arr[index];

        if (!std::cin) // gère les entrées invalides
        {
            std::cin.clear();
            std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
            continue;
        }
        ++index;
    }

}

int main()
{
    std::array<int, 5> arr {};
    inputArray(arr);

    std::cout << "La valeur de l'élément 2 est " << arr[2] << '\n';

    return 0;
}

Le principal avantage de cette méthode est qu'aucune copie du tableau n'est jamais effectuée, ce qui la rend efficace.

Elle présente aussi quelques inconvénients :

  • Cette manière de renvoyer des données est non conventionnelle, et il n'est pas facile de voir que la fonction modifie son argument.
  • Nous ne pouvons utiliser cette méthode que pour affecter des valeurs au tableau, et non pour l'initialiser.
  • Une telle fonction ne peut pas être utilisée pour produire des objets temporaires.

Retourner un std::vector à la place

std::vector est déplaçable et peut être retourné par valeur sans effectuer de copies coûteuses. Si vous retournez un std::array par valeur, votre std::array n'est probablement pas constexpr, et vous devriez envisager d'utiliser (et de retourner) un std::vector à la place.

Quiz

Question n° 1

Complétez le programme suivant :

#include <array>
#include <iostream>

int main()
{
    constexpr std::array arr1 { 1, 4, 9, 16 };
    printArray(arr1);

    constexpr std::array arr2 { 'h', 'e', 'l', 'l', 'o' };
    printArray(arr2);

    return 0;
}

À l'exécution, il doit afficher :


The array (1, 4, 9, 16) has length 4
The array (h, e, l, l, o) has length 5
Solution 
#include <array>
#include <iostream>

template <typename T, std::size_t N>
void printArray(const std::array<T, N>& arr)
{
    std::cout << "The array (";

    auto separator {""};
    for (const auto& e: arr)
    {
        std::cout << separator << e;
        separator = ", ";
    }

    std::cout << ") has length " << N << '\n';
}

int main()
{
    constexpr std::array arr1 { 1, 4, 9, 16 };
    printArray(arr1);

    constexpr std::array arr2 { 'h', 'e', 'l', 'l', 'o' };
    printArray(arr2);

    return 0;
}
