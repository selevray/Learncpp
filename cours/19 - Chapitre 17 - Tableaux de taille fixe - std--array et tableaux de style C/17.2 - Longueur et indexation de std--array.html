17.2 — Longueur et indexation de std::array

Dans la leçon 16.3 -- std::vector et le problème des entiers non signés pour la longueur et l'indexation, nous avons évoqué la décision malheureuse de faire utiliser aux classes conteneurs de la bibliothèque standard des valeurs non signées pour les longueurs et les indices. Comme std::array est une classe conteneur de la bibliothèque standard, elle est soumise aux mêmes problèmes.

Dans cette leçon, nous allons récapituler les façons d'indexer un std::array et d'obtenir sa longueur. Comme std::vector et std::array ont des interfaces similaires, cela reprendra ce que nous avons vu pour std::vector. Mais comme seul std::array gère pleinement constexpr, nous nous attarderons un peu plus sur ce point.

Avant de continuer, c'est le moment idéal pour revoir la règle « les conversions de signe sont des conversions restrictives, sauf en constexpr » (voir 16.3 -- std::vector et le problème des entiers non signés pour la longueur et l'indexation).

La longueur d'un std::array est de type std::size_t

std::array est implémenté comme une structure template dont la déclaration ressemble à ceci :

template<typename T, std::size_t N> // N est un paramètre template non-type
struct array;

Comme vous pouvez le voir, le paramètre template non-type représentant la longueur du tableau (N) est de type std::size_t. Et comme vous le savez probablement déjà, std::size_t est un grand type entier non signé.

Contenu associé

Nous traitons des templates de classes (ce qui inclut les templates de structures) dans la leçon 13.13 -- Templates de classes et des paramètres template non-type dans la leçon 11.9 -- Paramètres template non-type.

Ainsi, lorsque nous définissons un std::array, l'argument template non-type de longueur doit soit être de type std::size_t, soit être convertible en une valeur de type std::size_t. Comme cette valeur doit être constexpr, nous ne rencontrons pas de problème de conversion de signe lorsque nous utilisons une valeur entière signée, car le compilateur convertit volontiers une valeur entière signée en std::size_t à la compilation, sans que cela soit considéré comme une conversion restrictive.

En passant…

Avant C++23, C++ ne disposait même pas d'un suffixe littéral pour std::size_t, car la conversion implicite à la compilation de int vers std::size_t suffisait généralement dans les cas où nous avions besoin d'un std::size_t constexpr.

Ce suffixe a été ajouté principalement à des fins de déduction de type, car constexpr auto x { 0 } donne un int et non un std::size_t. Dans de tels cas, pouvoir distinguer 0 (int) de 0UZ (std::size_t) sans recourir à un static_cast explicite est utile.

La longueur et les indices de std::array sont de type size_type, qui est toujours std::size_t

Comme un std::vector, std::array définit un membre typedef imbriqué nommé size_type, qui est un alias du type utilisé pour la longueur (et les indices, si ceux-ci sont gérés) du conteneur. Dans le cas de std::array, size_type est toujours un alias de std::size_t.

Notez que le paramètre template non-type définissant la longueur du std::array est explicitement déclaré comme std::size_t plutôt que size_type. En effet, size_type est un membre de std::array et n'est pas encore défini à cet endroit. C'est le seul endroit où std::size_t est utilisé explicitement : partout ailleurs, on utilise size_type.

Obtenir la longueur d'un std::array

Il existe trois façons courantes d'obtenir la longueur d'un objet std::array.

Premièrement, nous pouvons demander la longueur à un objet std::array à l'aide de la fonction membre size() (qui renvoie la longueur sous la forme d'un size_type non signé) :

#include <array>
#include <iostream>

int main()
{
    constexpr std::array arr { 9.0, 7.2, 5.4, 3.6, 1.8 };
    std::cout << "length: " << arr.size() << '\n'; // renvoie la longueur sous le type `size_type` (alias de `std::size_t`)
    return 0;
}

Ce programme affiche :


length: 5

Contrairement à std::string et std::string_view, qui possèdent à la fois une fonction membre length() et une fonction membre size() (qui font la même chose), std::array (et la plupart des autres types conteneurs en C++) ne possède que size().

Deuxièmement, en C++17, nous pouvons utiliser la fonction non membre std::size() (qui, pour std::array, appelle simplement la fonction membre size(), renvoyant ainsi la longueur sous la forme d'un size_type non signé).

#include <array>
#include <iostream>

int main()
{
    constexpr std::array arr{ 9, 7, 5, 3, 1 };
    std::cout << "length: " << std::size(arr); // C++17, renvoie la longueur sous le type `size_type` (alias de `std::size_t`)

    return 0;
}

Enfin, en C++20, nous pouvons utiliser la fonction non membre std::ssize(), qui renvoie la longueur sous la forme d'un grand type entier signé (généralement std::ptrdiff_t) :

#include <array>
#include <iostream>

int main()
{
    constexpr std::array arr { 9, 7, 5, 3, 1 };
    std::cout << "length: " << std::ssize(arr); // C++20, renvoie la longueur sous la forme d'un grand type entier signé

    return 0;
}

C'est la seule des trois fonctions qui renvoie la longueur sous un type signé.

Obtenir la longueur d'un std::array sous forme de valeur constexpr

Comme la longueur d'un std::array est constexpr, chacune des fonctions ci-dessus renvoie la longueur d'un std::array sous forme de valeur constexpr (même lorsqu'elle est appelée sur un objet std::array non constexpr) ! Cela signifie que nous pouvons utiliser l'une de ces fonctions dans des expressions constantes, et que la longueur renvoyée peut être implicitement convertie en int sans que cela constitue une conversion restrictive :

#include <array>
#include <iostream>

int main()
{
    std::array arr { 9, 7, 5, 3, 1 }; // remarque : non constexpr pour cet exemple
    constexpr int length{ std::size(arr) }; // ok : la valeur renvoyée est un std::size_t constexpr et peut être convertie en int, ce n'est pas une conversion restrictive

    std::cout << "length: " << length << '\n';

    return 0;
}

Pour les utilisateurs de Visual Studio

Visual Studio déclenche à tort l'avertissement C4365 pour l'exemple ci-dessus. Le problème a été signalé à Microsoft.

Attention

En raison d'un défaut du langage, les fonctions ci-dessus renvoient une valeur non constexpr lorsqu'elles sont appelées sur un paramètre de fonction std::array passé par référence (constante) :

#include <array>
#include <iostream>

void printLength(const std::array<int, 5> &arr)
{
    constexpr int length{ std::size(arr) }; // erreur de compilation !
    std::cout << "length: " << length << '\n';
}

int main()
{
    std::array arr { 9, 7, 5, 3, 1 };
    constexpr int length{ std::size(arr) }; // fonctionne très bien
    std::cout << "length: " << length << '\n';

    printLength(arr);

    return 0;
}

Ce défaut a été corrigé en C++23 par P2280. Au moment de la rédaction, peu de compilateurs prennent en charge cette fonctionnalité.

Une solution de contournement consiste à faire de foo() un template de fonction dont la longueur du tableau est un paramètre template non-type. Ce paramètre template non-type peut alors être utilisé à l'intérieur de la fonction. Nous reviendrons sur ce point dans la leçon 17.3 -- Passer et renvoyer un std::array.

template <auto Length>
void printLength(const std::array<int, Length> &arr)
{
    std::cout << "length: " << Length << '\n';
}

Indexer un std::array à l'aide de operator[] ou de la fonction membre at()

Dans la leçon précédente 17.1 -- Introduction à std::array, nous avons vu que la façon la plus courante d'indexer un std::array est d'utiliser l'opérateur d'indexation (operator[]). Aucune vérification de bornes n'est effectuée dans ce cas, et passer un indice invalide entraîne un comportement indéfini.

Comme std::vector, std::array possède également une fonction membre at() qui effectue l'indexation avec une vérification des bornes à l'exécution. Nous recommandons d'éviter cette fonction, car nous voulons généralement vérifier les bornes avant l'indexation, ou effectuer une vérification des bornes à la compilation.

Ces deux fonctions attendent un indice de type size_type (std::size_t).

Si l'une ou l'autre de ces fonctions est appelée avec une valeur constexpr, le compilateur effectue une conversion constexpr vers std::size_t. Cette conversion n'est pas considérée comme restrictive, vous ne rencontrerez donc pas de problème de signe ici.

En revanche, si l'une ou l'autre de ces fonctions est appelée avec une valeur entière signée non constexpr, la conversion vers std::size_t est considérée comme restrictive et votre compilateur peut émettre un avertissement. Nous étudions ce cas plus en détail (avec std::vector) dans la leçon 16.3 -- std::vector et le problème des entiers non signés pour la longueur et l'indexation.

std::get() effectue une vérification des bornes à la compilation pour les indices constexpr

Comme la longueur d'un std::array est constexpr, si notre indice est également une valeur constexpr, le compilateur doit pouvoir vérifier à la compilation que notre indice constexpr se trouve dans les bornes du tableau (et arrêter la compilation si l'indice constexpr est hors bornes).

Cependant, operator[] n'effectue par définition aucune vérification de bornes, et la fonction membre at() ne fait qu'une vérification à l'exécution. De plus, les paramètres de fonction ne peuvent pas être constexpr (même pour les fonctions constexpr ou consteval) : comment passer un indice constexpr, alors ?

Pour obtenir une vérification des bornes à la compilation lorsque nous disposons d'un indice constexpr, nous pouvons utiliser le template de fonction std::get(), qui prend l'indice sous forme d'argument template non-type :

#include <array>
#include <iostream>

int main()
{
    constexpr std::array prime{ 2, 3, 5, 7, 11 };

    std::cout << std::get<3>(prime); // affiche la valeur de l'élément d'indice 3
    std::cout << std::get<9>(prime); // indice invalide (erreur de compilation)

    return 0;
}

À l'intérieur de l'implémentation de std::get(), un static_assert vérifie que l'argument template non-type est strictement inférieur à la longueur du tableau. Si ce n'est pas le cas, le static_assert interrompt le processus de compilation avec une erreur.

Comme les arguments template doivent être constexpr, std::get() ne peut être appelée qu'avec des indices constexpr.

Quiz

Question n° 1

Initialisez un std::array avec les valeurs suivantes : 'h', 'e', 'l', 'l', 'o'. Affichez la longueur du tableau, puis utilisez operator[], at() et std::get() pour afficher la valeur de l'élément d'indice 1.

Le programme doit afficher :


The length is 5
eee
Solution 
#include <array>
#include <iostream>

int main()
{
    constexpr std::array arr { 'h', 'e', 'l', 'l', 'o' };
    std::cout << "The length is " << std::size(arr) << '\n';
    std::cout << arr[1] << arr.at(1) << std::get<1>(arr) << '\n';

    return 0;
}
