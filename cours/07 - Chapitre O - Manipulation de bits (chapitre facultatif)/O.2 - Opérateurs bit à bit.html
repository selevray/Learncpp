O.2 — Opérateurs bit à bit

Les opérateurs bit à bit

C++ fournit 6 opérateurs de manipulation de bits, souvent appelés opérateurs bit à bit (bitwise) :

Opérateur Symbole Forme L'opération renvoie une valeur où :
décalage à gauche << x << n les bits de x sont décalés de n positions vers la gauche, les nouveaux bits valent 0.
décalage à droite >> x >> n les bits de x sont décalés de n positions vers la droite, les nouveaux bits valent 0.
NON bit à bit ~ ~x chaque bit de x est inversé.
ET bit à bit & x & y chaque bit vaut 1 lorsque les bits correspondants de x et y valent tous deux 1.
OU bit à bit x
OU exclusif bit à bit ^ x ^ y chaque bit vaut 1 lorsque les bits correspondants de x et y sont différents.

Ces opérateurs ne modifient pas leurs opérandes (ce sont des opérateurs non modifiants).

Note de l'auteur

Dans les exemples suivants, nous travaillerons surtout avec des valeurs binaires de 4 bits. C'est pour des raisons de commodité et pour garder les exemples simples. Dans les programmes réels, le nombre de bits utilisés dépend de la taille de l'objet (par exemple, un objet de 2 octets stocke 16 bits).

Pour améliorer la lisibilité, nous pouvons aussi omettre le préfixe 0b des littéraux binaires en dehors des exemples de code (par exemple, au lieu de 0b0101, nous pouvons écrire 0101).

Les opérateurs bit à bit sont définis pour les types entiers et pour std::bitset. Nous utiliserons std::bitset dans nos exemples car il est plus facile d'afficher le résultat en binaire.

Évitez d'utiliser les opérateurs bit à bit avec des opérandes entiers signés, car, avant C++20, de nombreux opérateurs renvoient des résultats dépendant de l'implémentation, ou présentent d'autres pièges faciles à éviter en utilisant des opérandes non signés (ou std::bitset).

Bonne pratique

Pour éviter les mauvaises surprises, utilisez les opérateurs bit à bit avec des opérandes entiers non signés ou avec std::bitset.

Décalage à gauche (<<) et décalage à droite (>>)

L'opérateur de décalage à gauche (<<) décale les bits vers la gauche. L'opérande de gauche est une expression qui fournit la séquence de bits initiale, et l'opérande de droite est un entier qui indique le nombre de positions dont les bits sont décalés. Par exemple, lorsque nous écrivons x << 2, nous disons « produire une valeur où les bits de x ont été décalés de 2 positions vers la gauche ».

L'opérande de gauche n'est pas modifié, et les nouveaux bits introduits par la droite valent 0.

Voici quelques exemples de décalage à gauche de la séquence de bits 0011 :


0011 \<\< 1 vaut 0110
0011 \<\< 2 vaut 1100
0011 \<\< 3 vaut 1000

Remarquez que, dans le troisième cas, nous avons fait sortir un bit 1 par l'extrémité du nombre ! Les bits qui sortent de la séquence sont perdus à jamais.

L'opérateur de décalage à droite (>>) fonctionne de manière similaire, mais décale les bits vers la droite.

Voici quelques exemples de décalage à droite de la séquence de bits 1100 :


1100 />/> 1 vaut 0110
1100 />/> 2 vaut 0011
1100 />/> 3 vaut 0001

Remarquez que, dans le troisième cas, nous avons fait sortir un bit par l'extrémité droite du nombre, il est donc perdu.

Voyons un exemple en C++ que vous pouvez compiler et exécuter :

#include <bitset>
#include <iostream>

int main()
{
    std::bitset<4> x { 0b1100 };

    std::cout << x << '\n';
    std::cout << (x >> 1) << '\n'; // décalage à droite de 1, donne 0110
    std::cout << (x << 1) << '\n'; // décalage à gauche de 1, donne 1000

    return 0;
}

Ce programme affiche :


1100
0110
1000

Pour les lecteurs avancés

Le décalage de bits en C++ est indépendant de l'endianness. Le décalage à gauche se fait toujours vers le bit de poids fort, et le décalage à droite vers le bit de poids faible.

Mais alors ! Les opérateurs operator<< et operator>> ne servent-ils pas aux entrées et sorties ?

Si, bien sûr.

Aujourd'hui, les programmes n'utilisent pas beaucoup les opérateurs de décalage à gauche et à droite pour décaler des bits. L'opérateur de décalage à gauche est plutôt utilisé avec std::cout (ou d'autres objets de flux de sortie) pour afficher du texte. Considérez le programme suivant :

#include <bitset>
#include <iostream>

int main()
{
    unsigned int x { 0b0100 };
    x = x << 1; // utilise operator<< pour le décalage à gauche
    std::cout << std::bitset<4>{ x } << '\n'; // utilise operator<< pour l'affichage

    return 0;
}

Ce programme affiche :


1000

Dans ce programme, comment operator<< sait-il qu'il doit décaler des bits dans un cas et afficher x dans l'autre ? La réponse est qu'il examine le type des opérandes. Si l'opérande de gauche est un type entier, operator<< effectue son comportement habituel de décalage de bits. Si l'opérande de gauche est un objet de flux de sortie comme std::cout, il sait qu'il doit faire une sortie à la place.

Il en va de même pour operator>>.

Contenu connexe

Cette capacité des opérateurs à modifier leur comportement selon le type des arguments repose sur une fonctionnalité appelée surcharge d'opérateurs (operator overloading), que nous présentons plus loin dans la leçon 13.5 -- Introduction à la surcharge des opérateurs d'entrée/sortie.

Notez que si vous utilisez operator<< à la fois pour la sortie et pour le décalage à gauche, il faut utiliser des parenthèses pour effectuer le décalage :

#include <bitset>
#include <iostream>

int main()
{
    std::bitset<4> x{ 0b0110 };

    std::cout << x << 1 << '\n'; // affiche la valeur de x (0110), puis 1
    std::cout << (x << 1) << '\n'; // affiche x décalé à gauche de 1 (1100)

    return 0;
}

Ce programme affiche :


01101
1100

La première ligne affiche la valeur de x (0110), puis le littéral 1. La deuxième ligne affiche la valeur de x décalée à gauche de 1 (1100).

NON bit à bit

L'opérateur NON bit à bit (~) est conceptuellement simple : il inverse chaque bit, de 0 à 1 ou de 1 à 0.


~0011 vaut 1100
~0000 0100 vaut 1111 1011

Pour les lecteurs avancés

Lorsqu'il est interprété comme un entier, le nombre de bits du résultat d'un NON bit à bit influe sur la valeur produite.

Le programme suivant l'illustre :

#include <bitset>
#include <iostream>

int main()
{
    std::bitset<4> b4{ 0b100 }; // b4 vaut 0100
    std::bitset<8> b8{ 0b100 }; // b8 vaut 0000 0100

    std::cout << "Valeurs initiales :\n";
    std::cout << "Bits : " << b4 << ' ' << b8 << '\n';
    std::cout << "Valeurs : " << b4.to_ulong() << ' ' << b8.to_ulong() << "\n\n";

    b4 = ~b4; // inverse b4 pour obtenir 1011
    b8 = ~b8; // inverse b8 pour obtenir 1111 1011

    std::cout << "Après le NON bit à bit :\n";
    std::cout << "Bits : " << b4 << ' ' << b8 << '\n';
    std::cout << "Valeurs : " << b4.to_ulong() << ' ' << b8.to_ulong() << '\n';

    return 0;
}

Ce programme affiche :


Valeurs initiales :
Bits : 0100 00000100
Valeurs : 4 4

Après le NON bit à bit :
Bits : 1011 11111011
Valeurs : 11 251

Au départ, b4 et b8 valent tous deux 0b100. Complétés par des zéros de tête, b4 devient 0100 et b8 devient 00000100, ce qui est affiché sur la ligne suivante.

Nous utilisons ensuite la fonction membre to_ulong() pour interpréter la valeur des bits comme un entier long. Vous constatez que b4 et b8 affichent tous deux la valeur 4. Malgré le nombre de bits différent, ils représentent la même valeur, car les zéros de tête n'apportent aucune valeur à l'entier interprété.

Ensuite, nous utilisons le NON bit à bit pour inverser les bits de chacun : b4 vaut maintenant 1011 et b8 vaut 1111 1011. Affichés comme des entiers, ces bits donnent les valeurs 11 et 251. Comme vous le voyez, ces valeurs ne sont plus identiques, car les uns de tête contribuent à la valeur de l'entier interprété, et b8 a plus de uns de tête que b4.

OU bit à bit

Le OU bit à bit (|) fonctionne à peu près comme son équivalent logique. Pour rappel, le OU logique s'évalue à true (1) si l'un de ses opérandes vaut true, et à false (0) sinon.

Cependant, alors que le OU logique s'applique à l'opérande entier (pour produire un seul résultat vrai ou faux), le OU bit à bit s'applique à chaque paire de bits des opérandes (pour produire un résultat vrai ou faux pour chaque bit).

Illustrons cela avec un exemple. Considérons l'expression 0b0101 | 0b0110.

Astuce

Pour effectuer à la main une opération bit à bit binaire, le plus simple est d'aligner les deux opérandes comme ceci :


0 1 0 1 OU (ou toute autre opération bit à bit)
0 1 1 0

Ensuite, appliquez l'opération à chaque colonne de bits, et écrivez le résultat en dessous.

Dans la première colonne, 0 OU 0 vaut 0, on écrit donc un 0 sous la ligne.


0 1 0 1 OU
0 1 1 0
-------
0

Deuxième colonne : 1 OU 1 vaut 1. Troisième colonne : 0 OU 1 vaut 1. Quatrième colonne : 1 OU 0 vaut 1.


0 1 0 1 OU
0 1 1 0
-------
0 1 1 1

Notre résultat est 0111 en binaire.

#include <bitset>
#include <iostream>

int main()
{
    std::cout << (std::bitset<4>{ 0b0101 } | std::bitset<4>{ 0b0110 }) << '\n';

    return 0;
}

Ce programme affiche :


0111

Nous pouvons faire la même chose avec des expressions OU bit à bit composées, comme 0b0111 | 0b0011 | 0b0001. Si l'un des bits d'une colonne vaut 1, le résultat de cette colonne vaut 1 :


0 1 1 1 OU
0 0 1 1 OU
0 0 0 1
--------
0 1 1 1

Voici le code correspondant :

#include <bitset>
#include <iostream>

int main()
{
    std::cout << (std::bitset<4>{ 0b0111 } | std::bitset<4>{ 0b0011 } | std::bitset<4>{ 0b0001 }) << '\n';

    return 0;
}

Ce programme affiche :


0111

ET bit à bit

Le ET bit à bit (&) fonctionne de manière similaire à ce qui précède, sauf qu'il utilise une logique ET au lieu d'une logique OU. C'est-à-dire que, pour chaque paire de bits des opérandes, le ET bit à bit donne au bit résultant la valeur true (1) si les deux bits de la paire valent 1, et false (0) sinon.

Considérons l'expression 0b0101 & 0b0110. On aligne les bits et on applique le ET bit à bit à chaque colonne :


0 1 0 1 ET
0 1 1 0
--------
0 1 0 0

#include <bitset>
#include <iostream>

int main()
{
    std::cout << (std::bitset<4>{ 0b0101 } & std::bitset<4>{ 0b0110 }) << '\n';

    return 0;
}

Ce programme affiche :


0100

De même, nous pouvons faire la même chose avec des expressions ET bit à bit composées, comme 0b0001 & 0b0011 & 0b0111. Si tous les bits d'une colonne valent 1, le résultat de cette colonne vaut 1.


0 0 0 1 ET
0 0 1 1 ET
0 1 1 1
--------
0 0 0 1

#include <bitset>
#include <iostream>

int main()
{
    std::cout << (std::bitset<4>{ 0b0001 } & std::bitset<4>{ 0b0011 } & std::bitset<4>{ 0b0111 }) << '\n';

    return 0;
}

Ce programme affiche :


0001

OU exclusif bit à bit

Le dernier opérateur est le OU exclusif bit à bit (^), aussi appelé XOR (exclusive or).

Pour chaque paire de bits des opérandes, le XOR bit à bit donne au bit résultant la valeur true (1) lorsque exactement un des bits de la paire vaut 1, et false (0) sinon. Autrement dit, le XOR bit à bit donne au bit résultant la valeur true lorsque les bits de la paire sont différents (l'un vaut 0 et l'autre 1).

Considérons l'expression 0b0110 ^ 0b0011 :


0 1 1 0 XOR
0 0 1 1
-------
0 1 0 1

Il est aussi possible d'évaluer une expression XOR composée colonne par colonne, comme 0b0001 ^ 0b0011 ^ 0b0111. S'il y a un nombre pair de bits 1 dans une colonne, le résultat est 0. S'il y a un nombre impair de bits 1 dans une colonne, le résultat est 1.


0 0 0 1 XOR
0 0 1 1 XOR
0 1 1 1
--------
0 1 0 1

Opérateurs d'affectation bit à bit

Comme les opérateurs d'affectation arithmétiques, C++ fournit des opérateurs d'affectation bit à bit. Ceux-ci modifient bien leur opérande de gauche.

Opérateur Symbole Forme L'opération modifie l'opérande de gauche où :
décalage à gauche << x <<= n les bits de x sont décalés de n positions vers la gauche, les nouveaux bits valent 0.
décalage à droite >> x >>= n les bits de x sont décalés de n positions vers la droite, les nouveaux bits valent 0.
ET bit à bit & x &= y chaque bit vaut 1 lorsque les bits correspondants de x et y valent tous deux 1.
OU bit à bit x
OU exclusif bit à bit ^ x ^= y chaque bit vaut 1 lorsque les bits correspondants de x et y sont différents.

Par exemple, au lieu d'écrire x = x >> 1;, vous pouvez écrire x >>= 1;.

#include <bitset>
#include <iostream>

int main()
{
    std::bitset<4> bits { 0b0100 };
    bits >>= 1;
    std::cout << bits << '\n';

    return 0;
}

Ce programme affiche :


0010

En passant…

Il n'existe pas d'opérateur d'affectation NON bit à bit. En effet, les autres opérateurs bit à bit sont binaires, alors que le NON bit à bit est unaire (que mettrait-on alors à droite d'un opérateur ~= ?). Si vous voulez inverser tous les bits d'un objet, utilisez une affectation ordinaire : x = ~x;

Les opérateurs bit à bit effectuent une promotion entière sur les petits types entiers (avancé)

Si le ou les opérandes d'un opérateur bit à bit sont d'un type entier plus petit qu'un int, ces opérandes sont promus (convertis) en int ou en unsigned int, et le résultat renvoyé est lui aussi un int ou un unsigned int. Par exemple, si nos opérandes sont de type unsigned short, ils sont promus (convertis) en unsigned int, et le résultat de l'opération est renvoyé sous la forme d'un unsigned int.

Dans de nombreux cas, cela n'a pas d'importance.

Contenu connexe

Nous abordons la promotion entière dans la leçon 10.2 -- Promotion flottante et entière.

Cependant, lorsque l'on utilise des opérateurs bit à bit sur des types entiers plus étroits que int ou unsigned int, deux cas demandent de la vigilance :

  • operator~ et operator<< dépendent de la largeur et peuvent produire des résultats différents selon la largeur de l'opérande.
  • L'initialisation ou l'affectation du résultat dans une variable du petit type entier constitue une conversion restrictive (puisque convertir un int ou un unsigned int en un type entier plus petit peut entraîner une perte de données). Ceci est interdit dans une initialisation par liste, et votre compilateur peut ou non signaler une affectation restrictive.

Le programme suivant présente ces problèmes (en supposant des int de 32 bits) :

#include <bitset>
#include <cstdint>
#include <iostream>

int main()
{
    std::uint8_t c { 0b00001111 };

    std::cout << std::bitset<32>(~c) << '\n';     // incorrect : affiche 11111111111111111111111111110000
    std::cout << std::bitset<32>(c << 6) << '\n'; // incorrect : affiche 0000000000000000001111000000
    std::uint8_t cneg { ~c };                     // erreur : conversion restrictive de unsigned int vers std::uint8_t
    c = ~c;                                       // avertissement possible : conversion restrictive de unsigned int vers std::uint8_t

    return 0;
}

Ces problèmes se règlent en utilisant static_cast pour convertir le résultat de l'opération bit à bit vers le type entier plus étroit. Le programme suivant produit les bons résultats :

#include <bitset>
#include <cstdint>
#include <iostream>

int main()
{
    std::uint8_t c { 0b00001111 };

    std::cout << std::bitset<32>(static_cast<std::uint8_t>(~c)) << '\n';     // correct : affiche 00000000000000000000000011110000
    std::cout << std::bitset<32>(static_cast<std::uint8_t>(c << 6)) << '\n'; // correct : affiche 0000000000000000000011000000
    std::uint8_t cneg { static_cast<std::uint8_t>(~c) };                     // compile
    c = static_cast<std::uint8_t>(~c);                                       // pas d'avertissement

    return 0;
}

Avertissement

Les opérateurs bit à bit promeuvent les opérandes de types entiers plus étroits en int ou unsigned int.

operator~ et operator<< dépendent de la largeur et peuvent produire des résultats différents selon la largeur de l'opérande. Utilisez static_cast pour reconvertir le résultat de ces opérations bit à bit vers le type entier plus étroit avant de l'utiliser, afin de garantir des résultats corrects.

Bonne pratique

Évitez autant que possible le décalage de bits sur les types entiers plus petits qu'un int.

Résumé

Voici comment évaluer les opérations bit à bit avec la méthode par colonnes :

Pour un OU bit à bit, si un bit d'une colonne vaut 1, le résultat de cette colonne vaut 1. Pour un ET bit à bit, si tous les bits d'une colonne valent 1, le résultat de cette colonne vaut 1. Pour un XOR bit à bit, s'il y a un nombre impair de bits 1 dans une colonne, le résultat de cette colonne vaut 1.

Dans la prochaine leçon, nous verrons comment ces opérateurs peuvent être utilisés conjointement avec des masques de bits pour faciliter la manipulation de bits.

Question n° 2

Une rotation bit à bit ressemble à un décalage bit à bit, sauf que les bits qui sortent d'un côté sont réinsérés de l'autre côté. Par exemple, 0b1001 << 1 vaut 0b0010, mais une rotation à gauche de 1 donne 0b0011. Implémentez une fonction qui effectue une rotation à gauche sur un std::bitset<4>. Pour cet exercice, il est permis d'utiliser test() et set().

Le code suivant doit s'exécuter :

#include <bitset>
#include <iostream>

// « rotl » signifie « rotate left » (rotation à gauche)
std::bitset<4> rotl(std::bitset<4> bits)
{
// Votre code ici
}

int main()
{
    std::bitset<4> bits1{ 0b0001 };
    std::cout << rotl(bits1) << '\n';

    std::bitset<4> bits2{ 0b1001 };
    std::cout << rotl(bits2) << '\n';

    return 0;
}

et afficher :


0010
0011
Solution 
#include <bitset>
#include <iostream>

std::bitset<4> rotl(std::bitset<4> bits)
{
    // mémorise si le bit de gauche valait 1
    const bool leftbit{ bits.test(3) };

    bits <<= 1; // décalage à gauche (ce qui fait sortir le bit de gauche par l'extrémité)

    // si le bit de gauche valait 1
    if (leftbit)
        bits.set(0); // met le bit de droite à 1

    return bits;
}

int main()
{
    std::bitset<4> bits1{ 0b0001 };
    std::cout << rotl(bits1) << '\n';

    std::bitset<4> bits2{ 0b1001 };
    std::cout << rotl(bits2) << '\n';

    return 0;
}

Nous avons nommé la fonction « rotl » plutôt que « rotateLeft », car « rotl » est un nom bien établi en informatique et aussi le nom de la fonction standard std::rotl.

Question n° 3

Exercice facultatif : refaites la question n° 2 sans utiliser les fonctions test et set (utilisez les opérateurs bit à bit).

Indice

Indice : comment pourrions-nous amener le bit de gauche à la position la plus à droite ?

Indice

Indice : essayez de considérer un « décalage » sous un autre angle.

Solution 
#include <bitset>
#include <iostream>

// merci au lecteur Chris pour cette solution
std::bitset<4> rotl(std::bitset<4> bits)
{
    // bits << 1 effectue le décalage à gauche
    // bits >> 3 gère la rotation du bit de gauche
    return (bits<<1) | (bits>>3);
}

int main()
{
    std::bitset<4> bits1{ 0b0001 };
    std::cout << rotl(bits1) << '\n';

    std::bitset<4> bits2{ 0b1001 };
    std::cout << rotl(bits2) << '\n';

    return 0;
}
