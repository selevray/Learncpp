21.1 — Introduction à la surcharge des opérateurs

Dans la leçon 11.1 -- Introduction à la surcharge de fonctions, vous avez découvert la surcharge de fonctions, un mécanisme qui permet de créer et de résoudre des appels à plusieurs fonctions portant le même nom, à condition que chacune ait un prototype unique. Cela vous permet de créer des variantes d'une fonction pour travailler avec différents types de données, sans avoir à inventer un nom unique pour chaque variante.

En C++, les opérateurs sont implémentés sous forme de fonctions. En utilisant la surcharge de fonctions sur les fonctions d'opérateurs, vous pouvez définir vos propres versions des opérateurs qui fonctionnent avec différents types de données (y compris les classes que vous avez écrites). Utiliser la surcharge de fonctions pour redéfinir des opérateurs s'appelle surcharge d'opérateurs (operator overloading).

Dans ce chapitre, nous examinerons les sujets liés à la surcharge d'opérateurs.

Les opérateurs en tant que fonctions

Considérez l'exemple suivant :

int x { 2 };
int y { 3 };
std::cout << x + y << '\n';

Le compilateur fournit une version intégrée de l'opérateur plus (+) pour les opérandes entiers : cette fonction additionne les entiers x et y et renvoie un résultat entier. Lorsque vous voyez l'expression x + y, vous pouvez la traduire mentalement en l'appel de fonction operator+(x, y) (où operator+ est le nom de la fonction).

Considérez maintenant cet extrait similaire :

double z { 2.0 };
double w { 3.0 };
std::cout << w + z << '\n';

Le compilateur fournit également une version intégrée de l'opérateur plus (+) pour les opérandes de type double. L'expression w + z devient l'appel de fonction operator+(w, z), et la surcharge de fonctions permet au compilateur de déterminer qu'il doit appeler la version double de cette fonction plutôt que la version entière.

Considérez maintenant ce qui se passe si l'on essaie d'additionner deux objets d'une classe définie par le programme :

Mystring string1 { "Hello, " };
Mystring string2 { "World!" };
std::cout << string1 + string2 << '\n';

Que vous attendez-vous à voir se produire dans ce cas ? Le résultat intuitif attendu est que la chaîne « Hello, World! » soit affichée à l'écran. Cependant, comme Mystring est un type défini par le programme, le compilateur ne dispose d'aucune version intégrée de l'opérateur plus pouvant s'appliquer à des opérandes de type Mystring. Dans ce cas, il produira donc une erreur. Pour que cela fonctionne comme souhaité, il faudrait écrire une fonction surchargée indiquant au compilateur comment l'opérateur + doit se comporter avec deux opérandes de type Mystring. Nous verrons comment faire dans la prochaine leçon.

Résolution des opérateurs surchargés

Lorsqu'il évalue une expression contenant un opérateur, le compilateur applique les règles suivantes :

  • Si tous les opérandes sont des types fondamentaux, le compilateur appelle une routine intégrée si elle existe. Si elle n'existe pas, le compilateur produit une erreur de compilation.
  • Si l'un des opérandes est un type défini par le programme (par exemple une de vos classes, ou un type énuméré), le compilateur utilise l'algorithme de résolution de surcharge de fonctions (décrit dans la leçon 11.3 -- Résolution de surcharge de fonctions et correspondances ambiguës) pour voir s'il peut trouver un opérateur surchargé qui corresponde de manière unique et optimale. Cela peut impliquer la conversion implicite d'un ou de plusieurs opérandes pour correspondre aux types des paramètres d'un opérateur surchargé. Cela peut également impliquer la conversion implicite de types définis par le programme en types fondamentaux (via une conversion de type surchargée, que nous verrons plus loin dans ce chapitre) afin de pouvoir correspondre à un opérateur intégré. Si aucune correspondance ne peut être trouvée (ou si une correspondance ambiguë est trouvée), le compilateur signale une erreur.

Quelles sont les limites de la surcharge d'opérateurs ?

Premièrement, presque tous les opérateurs existants en C++ peuvent être surchargés. Les exceptions sont : la conditionnelle (?:), sizeof, l'opérateur de portée (::), le sélecteur de membre (.), le sélecteur de membre par pointeur (.*), typeid, et les opérateurs de conversion de type (cast).

Deuxièmement, vous ne pouvez surcharger que les opérateurs qui existent. Vous ne pouvez pas créer de nouveaux opérateurs ni renommer les opérateurs existants. Par exemple, vous ne pourriez pas créer un operator** pour calculer des puissances.

Troisièmement, au moins un des opérandes d'un opérateur surchargé doit être un type défini par l'utilisateur. Cela signifie que vous pourriez surcharger operator+(int, Mystring), mais pas operator+(int, double).

Comme les classes de la bibliothèque standard sont considérées comme définies par l'utilisateur, cela signifie que vous pourriez définir operator+(double, std::string). Ce n'est toutefois pas une bonne idée, car une future norme du langage pourrait définir cette surcharge, ce qui pourrait casser les programmes qui utilisent la vôtre. Une bonne pratique consiste donc à faire en sorte que vos opérateurs surchargés opèrent sur au moins un type défini par le programme. Cela garantit qu'une future norme du langage ne cassera pas vos programmes.

Bonne pratique

Un opérateur surchargé doit opérer sur au moins un type défini par le programme (soit en tant que paramètre de la fonction, soit en tant qu'objet implicite).

Quatrièmement, il n'est pas possible de modifier le nombre d'opérandes qu'un opérateur accepte.

Enfin, tous les opérateurs conservent leur priorité et leur associativité par défaut (quel que soit leur usage), et cela ne peut pas être modifié.

Certains programmeurs débutants tentent de surcharger l'opérateur OU exclusif bit à bit (^) pour réaliser une exponentiation. Cependant, en C++, operator^ a une priorité inférieure à celle des opérateurs arithmétiques de base, ce qui fait que les expressions s'évaluent de manière incorrecte.

En mathématiques élémentaires, l'exponentiation est effectuée avant l'arithmétique de base, donc 4 + 3 ^ 2 se résout en 4 + (3 ^ 2) => 4 + 9 => 13. En revanche, en C++, les opérateurs arithmétiques ont une priorité supérieure à celle de operator^, donc 4 + 3 ^ 2 se résout en (4 + 3) ^ 2 => 7 ^ 2 => 49.

Il faudrait parenthéser explicitement la partie exposant (par exemple 4 + (3 ^ 2)) à chaque utilisation pour que cela fonctionne correctement, ce qui n'est pas intuitif et est potentiellement source d'erreurs.

En raison de ce problème de priorité, il est généralement judicieux de n'utiliser les opérateurs que d'une manière analogue à leur usage d'origine.

Bonne pratique

Lorsque vous surchargez des opérateurs, il est préférable de conserver la fonction des opérateurs aussi proche que possible de leur intention d'origine.

De plus, comme les opérateurs n'ont pas de noms descriptifs, il n'est pas toujours clair ce qu'ils sont censés faire. Par exemple, operator+ pourrait être un choix raisonnable pour une classe de chaîne de caractères qui concatène des chaînes. Mais qu'en est-il de operator- ? Que vous attendriez-vous à ce qu'il fasse ? C'est peu clair.

Bonne pratique

Si la signification d'un opérateur surchargé n'est pas claire et intuitive, utilisez plutôt une fonction nommée.

Enfin, les opérateurs surchargés doivent renvoyer des valeurs de manière cohérente avec les opérateurs d'origine. Les opérateurs qui ne modifient pas leurs opérandes (par exemple les opérateurs arithmétiques) doivent généralement renvoyer leurs résultats par valeur. Les opérateurs qui modifient leur opérande le plus à gauche (par exemple le pré-incrément, et tous les opérateurs d'affectation) doivent généralement renvoyer cet opérande le plus à gauche par référence.

Bonne pratique

Les opérateurs qui ne modifient pas leurs opérandes (par exemple les opérateurs arithmétiques) doivent généralement renvoyer leurs résultats par valeur.

Les opérateurs qui modifient leur opérande le plus à gauche (par exemple le pré-incrément, et tous les opérateurs d'affectation) doivent généralement renvoyer cet opérande le plus à gauche par référence.

Dans ces limites, vous trouverez tout de même de nombreuses fonctionnalités utiles à surcharger pour vos classes personnalisées ! Vous pouvez surcharger l'opérateur + pour concaténer votre propre classe de chaînes, ou additionner deux objets de la classe Fraction. Vous pouvez surcharger l'opérateur << pour afficher facilement votre classe à l'écran (ou dans un fichier). Vous pouvez surcharger l'opérateur d'égalité (==) pour comparer deux objets de classe. C'est pourquoi la surcharge d'opérateurs est l'une des fonctionnalités les plus utiles du C++ : elle vous permet simplement de manipuler vos classes de manière plus intuitive.
