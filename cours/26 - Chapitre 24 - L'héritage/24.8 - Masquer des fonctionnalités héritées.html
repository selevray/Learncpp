24.8 — Masquer des fonctionnalités héritées

Modifier le niveau d'accès d'un membre hérité

C++ nous permet de modifier le spécificateur d'accès d'un membre hérité dans la classe dérivée. Pour cela, on utilise une déclaration using qui désigne le membre de la classe de base (avec son qualificateur de portée) dont on veut changer l'accès, sous le nouveau spécificateur.

Par exemple, considérons la classe Base suivante :

#include <iostream>

class Base
{
private:
    int m_value {};

public:
    Base(int value)
        : m_value { value }
    {
    }

protected:
    void printValue() const { std::cout << m_value; }
};

Comme Base::printValue() a été déclarée protected, elle ne peut être appelée que par Base ou par ses classes dérivées. Le public ne peut pas y accéder.

Définissons une classe Derived qui change le spécificateur d'accès de printValue() en public :

class Derived: public Base
{
public:
    Derived(int value)
        : Base { value }
    {
    }

    // Base::printValue était héritée en protected, donc le public n'y a pas accès
    // Mais nous la passons en public grâce à une déclaration using
    using Base::printValue; // remarque : pas de parenthèses ici
};

Ainsi, le code suivant fonctionne désormais :

int main()
{
    Derived derived { 7 };

    // printValue est public dans Derived, donc c'est correct
    derived.printValue(); // affiche 7
    return 0;
}

Vous ne pouvez modifier l'accès que des membres de la base auxquels la classe dérivée aurait normalement accès. Vous ne pouvez donc jamais faire passer un membre de la base de private à protected ou public, car les classes dérivées n'ont pas accès aux membres private de la classe de base.

Masquer des fonctionnalités

En C++, il n'est pas possible de supprimer ou de restreindre une fonctionnalité de la classe de base autrement qu'en modifiant le code source. En revanche, dans une classe dérivée, il est possible de masquer une fonctionnalité existant dans la base, de sorte qu'elle ne soit plus accessible via la classe dérivée. Il suffit pour cela de modifier le spécificateur d'accès correspondant.

Par exemple, nous pouvons rendre private un membre public :

#include <iostream>

class Base
{
public:
    int m_value{};
};

class Derived : public Base
{
private:
    using Base::m_value;

public:
    Derived(int value) : Base { value }
    {
    }
};

int main()
{
    Derived derived{ 7 };
    std::cout << derived.m_value; // erreur : m_value est private dans Derived

    Base& base{ derived };
    std::cout << base.m_value; // correct : m_value est public dans Base

    return 0;
}

Cela nous a permis de prendre une classe de base mal conçue et d'encapsuler ses données dans notre classe dérivée. Autrement, plutôt que d'hériter publiquement des membres de Base et de rendre m_value private en redéfinissant son accès, nous aurions pu hériter de Base en privé, ce qui aurait fait hériter tous les membres de Base en private dès le départ.

Notons toutefois que, si m_value est private dans la classe Derived, elle reste public dans la classe Base. L'encapsulation de m_value dans Derived peut donc toujours être contournée en convertissant en Base& et en accédant directement au membre.

Pour les lecteurs avancés

Pour la même raison, si une classe Base possède une fonction virtuelle publique et que la classe Derived en change l'accès en private, le public peut tout de même appeler la fonction private de Derived en convertissant un objet Derived en Base& puis en appelant la fonction virtuelle. Le compilateur l'autorise, car la fonction est publique dans Base. Cependant, comme l'objet est en réalité un Derived, la résolution de la fonction virtuelle sélectionne (et appelle) la version (private) de Derived. Les contrôles d'accès ne sont pas appliqués à l'exécution.

#include <iostream>

class A
{
public:
    virtual void fun()
    {
        std::cout << "public A::fun()\n";
    }
};

class B : public A
{
private:
    virtual void fun()
    {
         std::cout << "private B::fun()\n";
   }
};

int main()
{
    B b {};
    b.fun();                  // erreur de compilation : interdit car B::fun() est private
    static_cast<A&>(b).fun(); // correct : A::fun() est public, se résout en B::fun() private à l'exécution

    return 0;
}

Il peut paraître surprenant, mais étant donné un ensemble de fonctions surchargées dans la classe de base, il n'existe pas de moyen de modifier le spécificateur d'accès d'une seule surcharge. Vous ne pouvez les modifier toutes ensemble :

#include <iostream>

class Base
{
public:
    int m_value{};

    int getValue() const { return m_value; }
    int getValue(int) const { return m_value; }
};

class Derived : public Base
{
private:
    using Base::getValue; // rend TOUTES les fonctions getValue private

public:
    Derived(int value) : Base { value }
    {
    }
};

int main()
{
    Derived derived{ 7 };
    std::cout << derived.getValue();  // erreur : getValue() est private dans Derived
    std::cout << derived.getValue(5); // erreur : getValue(int) est private dans Derived

    return 0;
}

Supprimer des fonctions dans la classe dérivée

Vous pouvez également marquer des fonctions membres comme supprimées (deleted) dans la classe dérivée, ce qui garantit qu'elles ne pourront pas être appelées du tout via un objet dérivé :

#include <iostream>
class Base
{
private:
    int m_value {};

public:
    Base(int value)
        : m_value { value }
    {
    }

    int getValue() const { return m_value; }
};

class Derived : public Base
{
public:
    Derived(int value)
        : Base { value }
    {
    }


    int getValue() const = delete; // marque cette fonction comme inaccessible
};

int main()
{
    Derived derived { 7 };

    // Ce qui suit ne fonctionnera pas, car getValue() a été supprimée !
    std::cout << derived.getValue();

    return 0;
}

Dans l'exemple ci-dessus, nous avons marqué la fonction getValue() comme supprimée. Cela signifie que le compilateur signalera une erreur lorsque nous tenterons d'appeler la version dérivée de la fonction. Notez que la version de getValue() de Base reste accessible. Nous pouvons appeler Base::getValue() de deux manières :

int main()
{
    Derived derived { 7 };

    // Nous pouvons appeler directement la fonction Base::getValue()
    std::cout << derived.Base::getValue();

    // Ou nous pouvons convertir Derived en référence Base, et getValue() se résoudra en Base::getValue()
    std::cout << static_cast<Base&>(derived).getValue();

    return 0;
}

Avec la méthode de conversion, nous convertissons vers un Base& plutôt que vers un Base afin d'éviter de copier la partie Base de derived.
