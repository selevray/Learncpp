24.7 — Appel de fonctions héritées et redéfinition du comportement

Par défaut, les classes dérivées héritent de tous les comportements définis dans une classe de base. Dans cette leçon, nous examinerons plus en détail la manière dont les fonctions membres sont sélectionnées, ainsi que la façon dont on peut exploiter ce mécanisme pour modifier le comportement d'une classe dérivée.

Lorsqu'une fonction membre est appelée sur un objet de classe dérivée, le compilateur vérifie d'abord si une fonction portant ce nom existe dans la classe dérivée. Si c'est le cas, toutes les surcharges de cette fonction sont prises en compte, et le processus de résolution de surcharge détermine s'il existe une meilleure correspondance. Sinon, le compilateur remonte la chaîne d'héritage et vérifie de la même manière chaque classe parente, l'une après l'autre.

Autrement dit, le compilateur sélectionne la meilleure correspondance parmi les fonctions de la classe la plus dérivée qui possède au moins une fonction de ce nom.

Appel d'une fonction de la classe de base

Examinons d'abord ce qui se passe lorsque la classe dérivée n'a aucune fonction correspondante, mais que la classe de base en possède une :

#include <iostream>

class Base
{
public:
    Base() { }

    void identify() const { std::cout << "Base::identify()\n"; }
};

class Derived: public Base
{
public:
    Derived() { }
};

int main()
{
    Base base {};
    base.identify();

    Derived derived {};
    derived.identify();

    return 0;
}

Ce programme affiche :


Base::identify()
Base::identify()

Lorsque base.identify() est appelée, le compilateur vérifie si une fonction nommée identify() est définie dans la classe Base. C'est le cas, il vérifie ensuite qu'elle correspond à l'appel. C'est le cas, elle est donc appelée.

Lorsque derived.identify() est appelée, le compilateur vérifie si une fonction nommée identify() est définie dans la classe Derived. Ce n'est pas le cas. Il passe donc à la classe parente (ici, Base) et recommence la recherche. Base définit une fonction identify(), c'est donc celle-ci qui est utilisée. En d'autres termes, Base::identify() est utilisée parce que Derived::identify() n'existe pas.

Cela signifie que, si le comportement fourni par la classe de base suffit, nous pouvons simplement utiliser ce comportement.

Redéfinition des comportements

En revanche, si nous avions défini Derived::identify() dans la classe Derived, c'est elle qui aurait été utilisée.

Cela signifie que nous pouvons faire fonctionner différemment les fonctions de nos classes dérivées en les redéfinissant dans ces classes !

Par exemple, supposons que nous souhaitions que derived.identify() affiche Derived::identify(). Il suffit d'ajouter la fonction identify() dans la classe Derived afin qu'elle renvoie la réponse voulue lorsque identify() est appelée sur un objet Derived.

Pour modifier le comportement, dans la classe dérivée, d'une fonction définie dans la classe de base, il suffit de redéfinir cette fonction dans la classe dérivée.

#include <iostream>

class Base
{
public:
    Base() { }

    void identify() const { std::cout << "Base::identify()\n"; }
};

class Derived: public Base
{
public:
    Derived() { }

    void identify() const { std::cout << "Derived::identify()\n"; }
};

int main()
{
    Base base {};
    base.identify();

    Derived derived {};
    derived.identify();

    return 0;
}

Ce programme affiche :


Base::identify()
Derived::identify()

Notez que lorsqu'une fonction est redéfinie dans la classe dérivée, la fonction dérivée n'hérite pas du spécificateur d'accès de la fonction de même nom de la classe de base. Elle utilise le spécificateur d'accès sous lequel elle est définie dans la classe dérivée. Par conséquent, une fonction définie comme privée dans la classe de base peut être redéfinie comme publique dans la classe dérivée, et inversement !

#include <iostream>

class Base
{
private:
    void print() const 
    {
        std::cout << "Base";
    }
};

class Derived : public Base
{
public:
    void print() const 
    {
        std::cout << "Derived ";
    }
};


int main()
{
    Derived derived {};
    derived.print(); // appelle Derived::print(), qui est publique
    return 0;
}

Ajout à la fonctionnalité existante

Il arrive que nous ne voulions pas remplacer complètement une fonction de la classe de base, mais plutôt lui ajouter des fonctionnalités lorsqu'elle est appelée sur un objet dérivé. Dans l'exemple ci-dessus, remarquez que Derived::identify() masque complètement Base::identify() ! Ce n'est pas forcément ce que nous voulons. Il est possible de faire en sorte que la fonction dérivée appelle la version de base de la fonction de même nom (afin de réutiliser du code), puis d'y ajouter des fonctionnalités supplémentaires.

Pour qu'une fonction dérivée appelle une fonction de base de même nom, il suffit d'effectuer un appel normal, en préfixant le nom de la fonction par le qualificateur de portée de la classe de base. Par exemple :

#include <iostream>

class Base
{
public:
    Base() { }

    void identify() const { std::cout << "Base::identify()\n"; }
};

class Derived: public Base
{
public:
    Derived() { }

    void identify() const
    {
        std::cout << "Derived::identify()\n";
        Base::identify(); // appel à Base::identify() ici
    }
};

int main()
{
    Base base {};
    base.identify();

    Derived derived {};
    derived.identify();

    return 0;
}

Ce programme affiche :


Base::identify()
Derived::identify()
Base::identify()

Lorsque derived.identify() est exécutée, elle correspond à Derived::identify(). Après avoir affiché Derived::identify(), elle appelle Base::identify(), qui affiche Base::identify().

Cela devrait paraître assez simple. Pourquoi faut-il utiliser l'opérateur de résolution de portée (::) ? Si nous avions défini Derived::identify() ainsi :

#include <iostream>

class Base
{
public:
    Base() { }

    void identify() const { std::cout << "Base::identify()\n"; }
};

class Derived: public Base
{
public:
    Derived() { }

    void identify() const
    {
        std::cout << "Derived::identify()\n";
        identify(); // sans résolution de portée, auto-appel et récursion infinie
    }
};

int main()
{
    Base base {};
    base.identify();

    Derived derived {};
    derived.identify();

    return 0;
}

Appeler la fonction identify() sans qualificateur de résolution de portée revient par défaut à appeler identify() de la classe courante, c'est-à-dire Derived::identify(). Cela ferait donc appeler Derived::identify() par elle-même, ce qui conduirait à une récursion infinie !

Il existe une difficulté lorsque l'on veut appeler des fonctions amies de la classe de base, comme operator<<. Comme les fonctions amies de la classe de base ne font pas réellement partie de cette classe, le qualificateur de résolution de portée ne fonctionne pas. Il nous faut alors un moyen de faire temporairement apparaître notre classe Derived comme une classe Base, afin que la bonne version de la fonction soit appelée.

Heureusement, c'est facile à faire à l'aide de static_cast. Voici un exemple :

#include <iostream>

class Base
{
public:
    Base() { }

    friend std::ostream& operator<< (std::ostream& out, const Base&)
    {
        out << "In Base\n";
        return out;
    }
};

class Derived: public Base
{
public:
    Derived() { }

    friend std::ostream& operator<< (std::ostream& out, const Derived& d)
    {
        out << "In Derived\n";
        // static_cast de Derived vers un objet Base, pour appeler la bonne version de operator<<
        out << static_cast<const Base&>(d); 
        return out;
    }
};

int main()
{
    Derived derived {};

    std::cout << derived << '\n';

    return 0;
}

Comme un Derived est aussi un Base, nous pouvons effectuer un static_cast de notre objet Derived vers une référence sur Base, afin que la version de operator<< qui prend un Base soit appelée.

Ce programme affiche :


In Derived
In Base

Résolution de surcharge dans les classes dérivées

Comme indiqué au début de la leçon, le compilateur sélectionne la meilleure correspondance parmi les fonctions de la classe la plus dérivée qui possède au moins une fonction de ce nom.

Commençons par un cas simple où les fonctions membres sont surchargées :

#include <iostream>

class Base
{
public:
    void print(int)    { std::cout << "Base::print(int)\n"; }
    void print(double) { std::cout << "Base::print(double)\n"; }
};

class Derived: public Base
{
public:
};


int main()
{
    Derived d{};
    d.print(5); // appelle Base::print(int)

    return 0;
}

Pour l'appel d.print(5), le compilateur ne trouve aucune fonction nommée print() dans Derived, il examine donc Base, où il trouve deux fonctions de ce nom. Le processus de résolution de surcharge détermine que Base::print(int) est une meilleure correspondance que Base::print(double). Base::print(int) est donc appelée, comme on pouvait s'y attendre.

Voyons maintenant un cas qui ne se comporte pas comme on pourrait le penser :

#include <iostream>

class Base
{
public:
    void print(int)    { std::cout << "Base::print(int)\n"; }
    void print(double) { std::cout << "Base::print(double)\n"; }
};

class Derived: public Base
{
public:
    void print(double) { std::cout << "Derived::print(double)"; } // cette fonction est ajoutée
};


int main()
{
    Derived d{};
    d.print(5); // appelle Derived::print(double), et non Base::print(int)

    return 0;
}

Pour l'appel d.print(5), le compilateur trouve une seule fonction nommée print() dans Derived. Il ne considère donc que les fonctions de Derived pour déterminer la fonction à appeler. Cette fonction est aussi la meilleure correspondance dans Derived pour cet appel. Par conséquent, c'est Derived::print(double) qui est appelée.

Comme Base::print(int) possède un paramètre qui correspond mieux à l'argument int 5 que Derived::print(double), on pourrait penser que l'appel se résoudra en Base::print(int). Mais comme d est un Derived, qu'il existe au moins une fonction print() dans Derived, et que Derived est plus dérivée que Base, les fonctions de Base ne sont même pas prises en compte.

Alors, si nous voulons vraiment que d.print(5) se résolve en Base::print(int) ? Une solution peu satisfaisante consiste à définir Derived::print(int) :

#include <iostream>

class Base
{
public:
    void print(int)    { std::cout << "Base::print(int)\n"; }
    void print(double) { std::cout << "Base::print(double)\n"; }
};

class Derived: public Base
{
public:
    void print(int n) { Base::print(n); } // fonctionne mais n'est pas idéal, car il faut définir
    void print(double) { std::cout << "Derived::print(double)"; }
};

int main()
{
    Derived d{};
    d.print(5); // appelle Derived::print(int), qui appelle Base::print(int)

    return 0;
}

Bien que cela fonctionne, ce n'est pas idéal : il faut ajouter à Derived une fonction pour chaque surcharge que l'on souhaite déléguer à Base. Cela peut représenter beaucoup de fonctions supplémentaires qui ne font, en substance, que transmettre les appels à Base.

Une meilleure option consiste à utiliser une déclaration using dans Derived pour rendre visibles, depuis Derived, toutes les fonctions de Base portant un certain nom :

#include <iostream>

class Base
{
public:
    void print(int)    { std::cout << "Base::print(int)\n"; }
    void print(double) { std::cout << "Base::print(double)\n"; }
};

class Derived: public Base
{
public:
    using Base::print; // rend toutes les fonctions Base::print() éligibles à la résolution de surcharge
    void print(double) { std::cout << "Derived::print(double)"; }
};


int main()
{
    Derived d{};
    d.print(5); // appelle Base::print(int), qui est la meilleure correspondance visible dans Derived

    return 0;
}

En plaçant la déclaration using using Base::print; dans Derived, nous indiquons au compilateur que toutes les fonctions Base nommées print doivent être visibles dans Derived, ce qui les rend éligibles à la résolution de surcharge. Par conséquent, Base::print(int) est sélectionnée plutôt que Derived::print(double).
