24.6 — Ajouter de nouvelles fonctionnalités à une classe dérivée

Dans la leçon introduction à l'héritage, nous avons mentionné que l'un des principaux avantages des classes dérivées est la possibilité de réutiliser du code déjà écrit. Vous pouvez hériter des fonctionnalités de la classe de base, puis ajouter de nouvelles fonctionnalités, modifier des fonctionnalités existantes ou masquer celles dont vous ne voulez pas. Dans cette leçon et les suivantes, nous allons examiner de plus près comment chacune de ces opérations s'effectue.

Commençons par une classe de base simple :

#include <iostream>

class Base
{
protected:
    int m_value {};

public:
    Base(int value)
        : m_value { value }
    {
    }

    void identify() const { std::cout << "I am a Base\n"; }
};

Créons maintenant une classe dérivée qui hérite de Base. Comme nous voulons que la classe dérivée puisse définir la valeur de m_value lors de l'instanciation des objets dérivés, le constructeur de Derived appellera le constructeur de Base dans la liste d'initialisation.

class Derived: public Base
{
public:
    Derived(int value)
        : Base { value }
    {
    }
};

Ajouter de nouvelles fonctionnalités à une classe dérivée

Dans l'exemple ci-dessus, comme nous avons accès au code source de la classe Base, nous pouvons, si nous le souhaitons, ajouter directement des fonctionnalités à Base.

Il peut arriver que nous ayons accès à une classe de base sans vouloir la modifier. Imaginons que vous venez d'acheter une bibliothèque de code auprès d'un éditeur tiers, mais que vous avez besoin de fonctionnalités supplémentaires. Vous pourriez ajouter votre code au code d'origine, mais ce n'est pas la meilleure solution. Que se passe-t-il si l'éditeur vous envoie une mise à jour ? Soit vos ajouts seront écrasés, soit vous devrez les reporter manuellement dans la nouvelle version, ce qui est long et risqué.

Il peut aussi arriver qu'il soit tout simplement impossible de modifier la classe de base. Prenons le cas du code de la bibliothèque standard : nous ne pouvons pas modifier ce code. Mais nous pouvons hériter de ces classes et ajouter nos propres fonctionnalités dans nos classes dérivées. Il en va de même pour les bibliothèques tierces dont vous disposez des en-têtes, mais dont le code est fourni déjà compilé.

Dans les deux cas, la meilleure solution consiste à dériver votre propre classe et à y ajouter les fonctionnalités souhaitées.

Un oubli évident dans la classe Base est l'absence d'un moyen pour le public d'accéder à m_value. Nous pourrions y remédier en ajoutant une fonction d'accès dans la classe Base, mais, pour les besoins de l'exemple, nous allons plutôt l'ajouter à la classe dérivée. Comme m_value est déclarée protected dans Base, Derived y a directement accès.

Pour ajouter de nouvelles fonctionnalités à une classe dérivée, il suffit de déclarer ces fonctionnalités dans la classe dérivée, comme d'habitude :

class Derived: public Base
{
public:
    Derived(int value)
        : Base { value }
    {
    }

    int getValue() const { return m_value; }
};

Désormais, le public pourra appeler getValue() sur un objet de type Derived pour accéder à la valeur de m_value.

int main()
{
    Derived derived { 5 };
    std::cout << "derived has value " << derived.getValue() << '\n';

    return 0;
}

Ce programme produit le résultat suivant :


derived has value 5

Bien que cela semble évident, les objets de type Base n'ont pas accès à la fonction getValue() de Derived. Le code suivant ne fonctionne pas :

int main()
{
    Base base { 5 };
    std::cout << "base has value " << base.getValue() << '\n';

    return 0;
}

En effet, il n'existe pas de fonction getValue() dans Base. La fonction getValue() appartient à Derived. Comme Derived est un Base, Derived a accès aux éléments de Base. En revanche, Base n'a pas accès aux éléments de Derived.
