24.4 — Constructeurs et initialisation des classes dérivées

Dans les deux leçons précédentes, nous avons exploré les bases de l'héritage en C++ et l'ordre d'initialisation des classes dérivées. Dans cette leçon, nous allons examiner de plus près le rôle des constructeurs dans l'initialisation des classes dérivées. Pour cela, nous reprendrons les classes simples Base et Derived que nous avons développées dans la leçon précédente :

class Base
{
public:
    int m_id {};

    Base(int id=0)
        : m_id{ id }
    {
    }

    int getId() const { return m_id; }
};

class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0)
        : m_cost{ cost }
    {
    }

    double getCost() const { return m_cost; }
};

Avec les classes non dérivées, les constructeurs n'ont à se soucier que de leurs propres membres. Par exemple, considérons Base. Nous pouvons créer un objet Base de cette façon :

int main()
{
    Base base{ 5 }; // utilise le constructeur Base(int)

    return 0;
}

Voici ce qui se passe réellement lorsque base est instancié :

  1. La mémoire pour base est réservée - Le constructeur Base approprié est appelé - La liste d'initialisation des membres initialise les variables - Le corps du constructeur s'exécute - Le contrôle est rendu à l'appelant

C'est assez simple. Avec les classes dérivées, les choses sont un peu plus complexes :

int main()
{
    Derived derived{ 1.3 }; // utilise le constructeur Derived(double)

    return 0;
}

Voici ce qui se passe réellement lorsque derived est instancié :

  1. La mémoire pour derived est réservée (suffisante pour les parties Base et Derived) - Le constructeur Derived approprié est appelé - L'objet Base est construit en premier, à l'aide du constructeur Base approprié. Si aucun constructeur de Base n'est spécifié, le constructeur par défaut sera utilisé. - La liste d'initialisation des membres initialise les variables - Le corps du constructeur s'exécute - Le contrôle est rendu à l'appelant

La seule véritable différence avec le cas non hérité est que, avant que le constructeur de Derived puisse faire quoi que ce soit de substantiel, le constructeur de Base est appelé en premier. Le constructeur de Base initialise la partie Base de l'objet, le contrôle revient au constructeur de Derived, qui peut alors terminer son travail.

Initialiser les membres de la classe de base

L'une des limites actuelles de notre classe Derived telle qu'elle est écrite est qu'il n'existe aucun moyen d'initialiser m_id lorsque nous créons un objet Derived. Que faire si nous voulons définir à la fois m_cost (issu de la partie Derived de l'objet) et m_id (issu de la partie Base de l'objet) lors de la création d'un objet Derived ?

Les nouveaux programmeurs tentent souvent de résoudre ce problème de la manière suivante :

class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0, int id=0)
        // ne fonctionne pas
        : m_cost{ cost }
        , m_id{ id }
    {
    }

    double getCost() const { return m_cost; }
};

C'est une bonne tentative, et l'idée est presque juste. Nous devons effectivement ajouter un autre paramètre à notre constructeur, sinon C++ n'aura aucun moyen de savoir à quelle valeur nous voulons initialiser m_id.

Cependant, C++ interdit aux classes d'initialiser les variables membres héritées dans la liste d'initialisation des membres d'un constructeur. En d'autres termes, la valeur d'une variable membre ne peut être définie que dans la liste d'initialisation des membres d'un constructeur appartenant à la même classe que cette variable.

Pourquoi C++ fait-il cela ? La réponse concerne les variables const et les références. Considérons ce qui se passerait si m_id était const. Comme les variables const doivent recevoir une valeur au moment de leur création, le constructeur de la classe de base doit définir leur valeur lors de la création de la variable. Cependant, une fois le constructeur de la classe de base terminé, les listes d'initialisation des membres du constructeur de la classe dérivée sont ensuite exécutées. Chaque classe dérivée aurait alors la possibilité d'initialiser cette variable, en modifiant potentiellement sa valeur ! En restreignant l'initialisation des variables au constructeur de la classe à laquelle elles appartiennent, C++ garantit que toutes les variables ne sont initialisées qu'une seule fois.

Le résultat est que l'exemple ci-dessus ne fonctionne pas, car m_id est hérité de Base, et seules les variables non héritées peuvent être initialisées dans la liste d'initialisation des membres.

Toutefois, les variables héritées peuvent toujours voir leur valeur modifiée dans le corps du constructeur, à l'aide d'une affectation. Par conséquent, les nouveaux programmeurs essaient aussi souvent ceci :

class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0, int id=0)
        : m_cost{ cost }
    {
        m_id = id;
    }

    double getCost() const { return m_cost; }
};

Bien que cela fonctionne réellement dans ce cas, cela ne fonctionnerait pas si m_id était const ou une référence (car les valeurs const et les références doivent être initialisées dans la liste d'initialisation des membres du constructeur). C'est aussi inefficace, car m_id reçoit une valeur deux fois : une fois dans la liste d'initialisation des membres du constructeur de la classe Base, puis à nouveau dans le corps du constructeur de la classe Derived. Enfin, que se passe-t-il si la classe Base a besoin d'accéder à cette valeur pendant la construction ? Elle n'a aucun moyen d'y accéder, puisqu'elle n'est définie qu'à l'exécution du constructeur de Derived (qui intervient en pratique en dernier).

Comment initialiser correctement m_id lors de la création d'un objet de classe Derived ?

Dans tous les exemples précédents, lorsque nous instancions un objet de classe Derived, la partie de la classe de base a été créée à l'aide du constructeur par défaut de Base. Pourquoi utilise-t-il toujours le constructeur par défaut de Base ? Parce que nous ne lui avons jamais demandé autre chose !

Heureusement, C++ nous permet de choisir explicitement le constructeur de la classe de base qui sera appelé ! Pour cela, il suffit d'ajouter un appel au constructeur de la classe de base dans la liste d'initialisation des membres de la classe dérivée :

class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0, int id=0)
        : Base{ id } // Appelle le constructeur Base(int) avec la valeur id !
        , m_cost{ cost }
    {
    }

    double getCost() const { return m_cost; }
};

Désormais, lorsque nous exécutons ce code :

#include <iostream>

int main()
{
    Derived derived{ 1.3, 5 }; // utilise le constructeur Derived(double, int)
    std::cout << "Id: " << derived.getId() << '\n';
    std::cout << "Cost: " << derived.getCost() << '\n';

    return 0;
}

Le constructeur de la classe de base Base(int) sera utilisé pour initialiser m_id à 5, et le constructeur de la classe dérivée sera utilisé pour initialiser m_cost à 1.3 !

Ainsi, le programme affichera :


Id: 5
Cost: 1.3

Plus en détail, voici ce qui se passe :

  1. La mémoire pour derived est allouée. - Le constructeur Derived(double, int) est appelé, avec cost = 1.3 et id = 5. - Le compilateur vérifie si nous avons demandé un constructeur de Base particulier. C'est le cas ! Il appelle donc Base(int) avec id = 5. - La liste d'initialisation des membres du constructeur de la classe de base définit m_id à 5. - Le corps du constructeur de la classe de base s'exécute, sans rien faire. - Le constructeur de la classe de base se termine. - La liste d'initialisation des membres du constructeur de la classe dérivée définit m_cost à 1.3. - Le corps du constructeur de la classe dérivée s'exécute, sans rien faire. - Le constructeur de la classe dérivée se termine.

Cela peut sembler quelque peu complexe, mais c'est en réalité très simple. Il se passe simplement que le constructeur de Derived appelle un constructeur de Base précis pour initialiser la partie Base de l'objet. Comme m_id réside dans la partie Base de l'objet, le constructeur de Base est le seul constructeur capable d'initialiser cette valeur.

Notez qu'il n'importe pas où, dans la liste d'initialisation des membres du constructeur de Derived, l'appel au constructeur de Base est placé : il sera toujours exécuté en premier.

Rendre maintenant nos membres privés

Maintenant que vous savez comment initialiser les membres de la classe de base, il n'est plus nécessaire de garder nos variables membres publiques. Nous les rendons à nouveau privées, comme elles devraient l'être.

Pour rappel, les membres publics peuvent être accédés par tout le monde. Les membres privés ne peuvent être accédés que par les fonctions membres de la même classe. Notez que cela signifie que les classes dérivées ne peuvent pas accéder directement aux membres privés de la classe de base ! Les classes dérivées doivent utiliser des fonctions d'accès pour accéder aux membres privés de la classe de base.

Considérons :

#include <iostream>

class Base
{
private: // notre membre est désormais privé
    int m_id {};

public:
    Base(int id=0)
        : m_id{ id }
    {
    }

    int getId() const { return m_id; }
};

class Derived: public Base
{
private: // notre membre est désormais privé
    double m_cost;

public:
    Derived(double cost=0.0, int id=0)
        : Base{ id } // Appelle le constructeur Base(int) avec la valeur id !
        , m_cost{ cost }
    {
    }

    double getCost() const { return m_cost; }
};

int main()
{
    Derived derived{ 1.3, 5 }; // utilise le constructeur Derived(double, int)
    std::cout << "Id: " << derived.getId() << '\n';
    std::cout << "Cost: " << derived.getCost() << '\n';

    return 0;
}

Dans le code ci-dessus, nous avons rendu m_id et m_cost privés. C'est acceptable, puisque nous utilisons les constructeurs appropriés pour les initialiser, et une fonction d'accès publique pour obtenir leurs valeurs.

Ce programme affiche, comme prévu :


Id: 5
Cost: 1.3

Nous reparlerons des spécificateurs d'accès dans la prochaine leçon.

Un autre exemple

Examinons une autre paire de classes avec lesquelles nous avons déjà travaillé :

#include <string>
#include <string_view>

class Person
{
public:
    std::string m_name;
    int m_age {};

    Person(std::string_view name = "", int age = 0)
        : m_name{ name }, m_age{ age }
    {
    }

    const std::string& getName() const { return m_name; }
    int getAge() const { return m_age; }
};

// BaseballPlayer héritant publiquement de Person
class BaseballPlayer : public Person
{
public:
    double m_battingAverage {};
    int m_homeRuns {};

    BaseballPlayer(double battingAverage = 0.0, int homeRuns = 0)
       : m_battingAverage{ battingAverage },
         m_homeRuns{ homeRuns }
    {
    }
};

Tel que nous l'avons écrit précédemment, BaseballPlayer n'initialise que ses propres membres et ne précise pas le constructeur de Person à utiliser. Cela signifie que chaque BaseballPlayer que nous créons utilisera le constructeur par défaut de Person, qui initialisera le nom à une chaîne vide et l'âge à 0. Comme il est logique de donner un nom et un âge à nos BaseballPlayer lors de leur création, nous devrions modifier ce constructeur pour ajouter ces paramètres.

Voici nos classes mises à jour, qui utilisent des membres privés, BaseballPlayer appelant le constructeur de Person approprié pour initialiser les membres hérités de Person :

#include <iostream>
#include <string>
#include <string_view>

class Person
{
private:
    std::string m_name;
    int m_age {};

public:
    Person(std::string_view name = "", int age = 0)
        : m_name{ name }, m_age{ age }
    {
    }

    const std::string& getName() const { return m_name; }
    int getAge() const { return m_age; }

};
// BaseballPlayer héritant publiquement de Person
class BaseballPlayer : public Person
{
private:
    double m_battingAverage {};
    int m_homeRuns {};

public:
    BaseballPlayer(std::string_view name = "", int age = 0,
        double battingAverage = 0.0, int homeRuns = 0)
        : Person{ name, age } // appelle Person(std::string_view, int) pour initialiser ces champs
        , m_battingAverage{ battingAverage }, m_homeRuns{ homeRuns }
    {
    }

    double getBattingAverage() const { return m_battingAverage; }
    int getHomeRuns() const { return m_homeRuns; }
};

Nous pouvons maintenant créer des joueurs de baseball de cette façon :

#include <iostream>

int main()
{
    BaseballPlayer pedro{ "Pedro Cerrano", 32, 0.342, 42 };

    std::cout << pedro.getName() << '\n';
    std::cout << pedro.getAge() << '\n';
    std::cout << pedro.getBattingAverage() << '\n';
    std::cout << pedro.getHomeRuns() << '\n';

    return 0;
}

Ceci affiche :


Pedro Cerrano
32
0.342
42

Comme vous pouvez le voir, le nom et l'âge provenant de la classe de base ont été correctement initialisés, de même que le nombre de home runs et la moyenne au bâton provenant de la classe dérivée.

Chaînes d'héritage

Les classes d'une chaîne d'héritage fonctionnent exactement de la même manière.

#include <iostream>

class A
{
public:
    A(int a)
    {
        std::cout << "A: " << a << '\n';
    }
};

class B: public A
{
public:
    B(int a, double b)
    : A{ a }
    {
        std::cout << "B: " << b << '\n';
    }
};

class C: public B
{
public:
    C(int a, double b, char c)
    : B{ a, b }
    {
        std::cout << "C: " << c << '\n';
    }
};

int main()
{
    C c{ 5, 4.3, 'R' };

    return 0;
}

Dans cet exemple, la classe C dérive de la classe B, qui dérive elle-même de la classe A. Que se passe-t-il donc lorsque nous instancions un objet de classe C ?

D'abord, main() appelle C(int, double, char). Le constructeur de C appelle B(int, double). Le constructeur de B appelle A(int). Comme A n'hérite de personne, c'est la première classe à être construite. A est construite, affiche la valeur 5, et rend le contrôle à B. B est construite, affiche la valeur 4.3, et rend le contrôle à C. C est construite, affiche le caractère 'R', et rend le contrôle à main(). Et voilà !

Ainsi, ce programme affiche :


A: 5
B: 4.3
C: R

Il est important de noter que les constructeurs ne peuvent appeler que les constructeurs de leur classe parente/de base immédiate. Par conséquent, le constructeur de C ne pourrait pas appeler ni transmettre de paramètres directement au constructeur de A. Le constructeur de C ne peut appeler que le constructeur de B (qui se charge d'appeler le constructeur de A).

Destructeurs

Lorsqu'une classe dérivée est détruite, chaque destructeur est appelé dans l'ordre inverse de la construction. Dans l'exemple ci-dessus, lorsque c est détruit, le destructeur de C est appelé en premier, puis celui de B, puis celui de A.

Attention

Si votre classe de base possède des fonctions virtuelles, votre destructeur doit également être virtuel, sinon un comportement indéfini peut se produire dans certains cas. Nous traitons ce cas dans la leçon 25.4 -- Destructeurs virtuels, affectation virtuelle et redéfinition de la virtualisation.

Résumé

Lors de la construction d'une classe dérivée, le constructeur de la classe dérivée est responsable de la détermination du constructeur de la classe de base appelé. Si aucun constructeur de classe de base n'est spécifié, le constructeur par défaut de la classe de base sera utilisé. Dans ce cas, si aucun constructeur par défaut de la classe de base ne peut être trouvé (ou généré par défaut), le compilateur affichera une erreur. Les classes sont ensuite construites dans l'ordre, de la plus à la moins dérivée.

À ce stade, vous connaissez suffisamment l'héritage en C++ pour créer vos propres classes héritées !

Quiz !

  1. Implémentons l'exemple des fruits que nous avons évoqué dans notre introduction à l'héritage. Créez une classe de base Fruit qui contient deux membres privés : un nom (std::string) et une couleur (std::string). Créez une classe Apple qui hérite de Fruit. Apple doit avoir un membre privé supplémentaire : fiber (double). Créez une classe Banana qui hérite également de Fruit. Banana n'a aucun membre supplémentaire.

Le programme suivant doit fonctionner :

#include <iostream>

int main()
{
    const Apple a{ "Red delicious", "red", 4.2 };
    std::cout << a << '\n';

    const Banana b{ "Cavendish", "yellow" };
    std::cout << b << '\n';

    return 0;
}

Et afficher ceci :


Apple(Red delicious, red, 4.2)
Banana(Cavendish, yellow)

Indice : comme a et b sont const, vous devez faire attention aux const. Assurez-vous que vos paramètres et fonctions sont correctement déclarés const.

Solution 
#include <iostream>
#include <string>
#include <string_view>

class Fruit
{
private:
    std::string m_name;
    std::string m_color;

public:
    Fruit(std::string_view name, std::string_view color)
        : m_name{ name }, m_color{ color }
    {
    }

    const std::string& getName() const { return m_name; }
    const std::string& getColor() const { return m_color; }

};

class Apple : public Fruit
{
private:
    double m_fiber;

public:
    Apple(std::string_view name, std::string_view color, double fiber)
        :Fruit{ name, color },
        m_fiber{ fiber }
    {
    }

    double getFiber() const { return m_fiber; }

};

std::ostream& operator<<(std::ostream& out, const Apple& a)
{
    out << "Apple(" << a.getName() << ", " << a.getColor() << ", " << a.getFiber() << ')';
    return out;
}

class Banana : public Fruit
{
public:
    Banana(std::string_view name, std::string_view color)
        :Fruit{ name, color }
    {
    }
};

std::ostream& operator<<(std::ostream& out, const Banana& b)
{
    out << "Banana(" << b.getName() << ", " << b.getColor() << ')';
    return out;
}

int main()
{
    const Apple a{ "Red delicious", "red", 4.2 };
    std::cout << a << '\n';

    const Banana b{ "Cavendish", "yellow" };
    std::cout << b << '\n';

    return 0;
}
