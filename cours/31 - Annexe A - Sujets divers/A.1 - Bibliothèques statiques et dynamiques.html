A.1 — Bibliothèques statiques et dynamiques

Une bibliothèque (library) est un ensemble de code destiné à être réutilisé par de nombreux programmes. En général, une bibliothèque C++ se présente sous deux formes :

  1. Un fichier d'en-tête (header) qui définit les fonctionnalités que la bibliothèque met à disposition des programmes qui l'utilisent.
  2. Un binaire précompilé qui contient l'implémentation de ces fonctionnalités, déjà traduite en langage machine.

Certaines bibliothèques peuvent être réparties sur plusieurs fichiers et/ou comporter plusieurs fichiers d'en-tête.

Les bibliothèques sont précompilées pour plusieurs raisons. D'abord, comme elles changent rarement, elles n'ont pas besoin d'être recompilées souvent. Ce serait une perte de temps de recompiler la bibliothèque à chaque fois que vous écrivez un programme qui l'utilise. Ensuite, comme les objets précompilés sont en langage machine, il est impossible d'accéder au code source ou de le modifier, ce qui est important pour les entreprises ou les personnes qui ne souhaitent pas rendre leur code source accessible pour des raisons de propriété intellectuelle.

Il existe deux types de bibliothèques : les bibliothèques statiques et les bibliothèques dynamiques.

Une bibliothèque statique (aussi appelée archive) est constituée de routines qui sont compilées et liées directement à votre programme. Lorsque vous compilez un programme qui utilise une bibliothèque statique, toutes les fonctionnalités de cette bibliothèque qu'il utilise deviennent partie intégrante de votre exécutable. Sous Windows, les bibliothèques statiques ont généralement l'extension .lib, alors que sous Linux, elles ont généralement l'extension .a (archive). Un avantage des bibliothèques statiques est que, pour que les utilisateurs puissent exécuter votre programme, il suffit de distribuer l'exécutable. Comme la bibliothèque fait partie du programme, cela garantit que la bonne version de la bibliothèque est toujours utilisée avec votre programme. De plus, comme elles font partie intégrante du programme, vous pouvez les utiliser exactement comme les fonctionnalités que vous avez écrites vous-même. En revanche, comme une copie de la bibliothèque est incluse dans chaque exécutable qui l'utilise, cela peut entraîner un important gaspillage d'espace. Les bibliothèques statiques ne sont pas non plus faciles à mettre à jour : pour actualiser la bibliothèque, il faut remplacer l'exécutable en entier.

Une bibliothèque dynamique (aussi appelée bibliothèque partagée, shared library) est constituée de routines qui sont chargées dans votre application au moment de l'exécution. Lorsque vous compilez un programme qui utilise une bibliothèque dynamique, la bibliothèque ne devient pas partie intégrante de l'exécutable : elle reste une unité distincte. Sous Windows, les bibliothèques dynamiques ont généralement l'extension .dll (dynamic link library), alors que sous Linux, elles ont généralement l'extension .so (shared object). Un avantage des bibliothèques dynamiques est que de nombreux programmes peuvent partager une même copie, ce qui permet d'économiser de l'espace. Un avantage peut-être plus important encore est que la bibliothèque dynamique peut être mise à niveau vers une version plus récente sans qu'il soit nécessaire de remplacer tous les exécutables qui l'utilisent.

Comme les bibliothèques dynamiques ne sont pas liées à votre programme, les programmes qui les utilisent doivent charger explicitement la bibliothèque et interagir avec elle. Ce mécanisme peut être déroutant et rend l'interaction avec une bibliothèque dynamique peu commode. Pour faciliter l'utilisation des bibliothèques dynamiques, on peut recourir à une bibliothèque d'importation.

Une bibliothèque d'importation (import library) est une bibliothèque qui automatise le processus de chargement et d'utilisation d'une bibliothèque dynamique. Sous Windows, il s'agit généralement d'une petite bibliothèque statique (.lib) portant le même nom que la bibliothèque dynamique (.dll). Cette bibliothèque statique est liée au programme lors de la compilation, et les fonctionnalités de la bibliothèque dynamique peuvent alors être utilisées comme si elles faisaient partie d'une bibliothèque statique. Sous Linux, le fichier de bibliothèque partagée (.so) joue à la fois le rôle de bibliothèque dynamique et de bibliothèque d'importation. La plupart des éditeurs de liens (linkers) peuvent générer une bibliothèque d'importation pour une bibliothèque dynamique au moment de la création de celle-ci.

Installer et utiliser des bibliothèques

Maintenant que vous connaissez les différents types de bibliothèques, voyons comment les utiliser concrètement dans votre programme. L'installation d'une bibliothèque en C++ implique généralement 4 étapes :

  1. Obtenir la bibliothèque. La meilleure option consiste à télécharger un paquet précompilé pour votre système d'exploitation (s'il existe), afin de ne pas avoir à compiler la bibliothèque vous-même. Si aucun paquet n'est proposé pour votre système, vous devrez télécharger un paquet contenant uniquement le code source et le compiler vous-même (ce qui sort du cadre de cette leçon). Sous Windows, les bibliothèques sont généralement distribuées sous forme de fichiers .zip. Sous Linux, elles sont généralement distribuées sous forme de paquets (par exemple .RPM). Votre gestionnaire de paquets propose peut-être déjà les bibliothèques les plus populaires (par exemple SDL) pour une installation facile, donc vérifiez-le en premier.
  2. Installer la bibliothèque. Sous Linux, cela consiste généralement à lancer le gestionnaire de paquets et à le laisser faire tout le travail. Sous Windows, il s'agit généralement de décompresser la bibliothèque dans le répertoire de votre choix. Nous vous recommandons de regrouper toutes vos bibliothèques au même endroit pour y accéder facilement. Par exemple, utilisez un répertoire nommé C:\Libs et placez chaque bibliothèque dans son propre sous-répertoire.
  3. Vérifier que le compilateur sait où trouver le ou les fichiers d'en-tête de la bibliothèque. Sous Windows, il s'agit généralement du sous-répertoire include du répertoire dans lequel vous avez installé la bibliothèque (par exemple, si vous avez installé votre bibliothèque dans C:\libs\SDL-1.2.11, les fichiers d'en-tête se trouvent probablement dans C:\libs\SDL-1.2.11\include). Sous Linux, les fichiers d'en-tête sont généralement installés dans /usr/include, qui fait déjà partie du chemin de recherche des fichiers d'en-tête. Toutefois, si les fichiers sont installés ailleurs, vous devrez indiquer au compilateur où les trouver.
  4. Indiquer à l'éditeur de liens où chercher le ou les fichiers de bibliothèque. Comme à l'étape 3, cela consiste généralement à ajouter un répertoire à la liste des emplacements où l'éditeur de liens recherche les bibliothèques. Sous Windows, il s'agit généralement du sous-répertoire /lib du répertoire dans lequel vous avez installé les fichiers de la bibliothèque. Sous Linux, les bibliothèques sont généralement installées dans /usr/lib, qui fait déjà partie du chemin de recherche des bibliothèques.

Une fois la bibliothèque installée et l'EDI informé de son emplacement, les 3 étapes suivantes doivent généralement être effectuées pour chaque projet qui souhaite utiliser la bibliothèque :

  1. Si vous utilisez des bibliothèques statiques ou d'importation, indiquer à l'éditeur de liens quels fichiers de bibliothèque lier.
  2. Inclure (#include) le ou les fichiers d'en-tête de la bibliothèque dans votre programme. Cela informe le compilateur de toutes les fonctionnalités que la bibliothèque met à disposition, afin que votre programme se compile correctement.
  3. Si vous utilisez des bibliothèques dynamiques, vérifier que le programme sait où les trouver. Sous Linux, les bibliothèques sont généralement installées dans /usr/lib, qui fait partie du chemin de recherche par défaut, après les chemins contenus dans la variable d'environnement LD_LIBRARY_PATH. Sous Windows, le chemin de recherche par défaut comprend le répertoire d'où le programme est lancé, les répertoires définis par l'appel à SetDllDirectory(), les répertoires Windows, System et System32, ainsi que les répertoires de la variable d'environnement PATH. Le moyen le plus simple d'utiliser une .dll consiste à copier la .dll à l'emplacement de l'exécutable. Comme vous distribuerez généralement la .dll avec votre exécutable, il est logique de les garder ensemble de toute façon.

Les étapes 3 à 5 impliquent de configurer votre EDI. Heureusement, presque tous les EDI fonctionnent de la même manière pour ces opérations. Malheureusement, chaque EDI ayant une interface différente, la partie la plus difficile de ce processus consiste simplement à trouver où effectuer chacune de ces étapes. C'est pourquoi, dans les prochaines leçons de cette section, nous verrons comment réaliser toutes ces étapes avec Visual Studio et Code::Blocks. Si vous utilisez un autre EDI, lisez tout de même ces leçons : à leur issue, vous devriez disposer des informations nécessaires pour faire de même avec votre propre EDI, moyennant un peu de recherche.
