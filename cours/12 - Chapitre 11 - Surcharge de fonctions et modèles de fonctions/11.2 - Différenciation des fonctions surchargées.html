11.2 — Différenciation des fonctions surchargées

Dans la leçon précédente (11.1 — Introduction à la surcharge de fonctions), nous avons présenté le concept de surcharge de fonctions, qui permet de créer plusieurs fonctions portant le même nom, à condition que chacune d'elles ait des types de paramètres différents (ou qu'elles puissent être différenciées d'une autre manière).

Dans cette leçon, nous allons examiner de plus près la manière dont les fonctions surchargées sont différenciées. Des fonctions surchargées qui ne sont pas correctement différenciées provoqueront une erreur de compilation.

Comment les fonctions surchargées sont différenciées

Propriété de la fonction Utilisée pour la différenciation Remarques
Nombre de paramètres Oui
Types des paramètres Oui Exclut les typedefs, les alias de types et le qualificateur const sur les paramètres passés par valeur. Inclut les points de suspension (ellipses).
Type de retour Non

Notez que le type de retour d'une fonction n'est pas utilisé pour différencier les fonctions surchargées. Nous en reparlerons un peu plus loin.

Pour les lecteurs avancés

Pour les fonctions membres, des qualificatifs de fonction supplémentaires sont également pris en compte :

Qualificatif de fonction Utilisé pour la surcharge
const ou volatile Oui
Qualificatifs de référence (ref-qualifiers) Oui

Par exemple, une fonction membre const peut être différenciée d'une fonction membre non const identique par ailleurs (même si elles ont le même ensemble de paramètres).

Contenu connexe

Nous abordons les points de suspension dans la leçon 20.5 — Points de suspension (et pourquoi les éviter).

Surcharge selon le nombre de paramètres

Une fonction surchargée est différenciée tant que chaque fonction surchargée possède un nombre de paramètres différent. Par exemple :

int add(int x, int y)
{
    return x + y;
}

int add(int x, int y, int z)
{
    return x + y + z;
}

Le compilateur peut facilement déterminer qu'un appel de fonction avec deux paramètres entiers doit cibler add(int, int), et qu'un appel avec trois paramètres entiers doit cibler add(int, int, int).

Surcharge selon le type des paramètres

Une fonction peut également être différenciée tant que la liste des types de paramètres de chaque fonction surchargée est distincte. Par exemple, toutes les surcharges suivantes sont différenciées :

int add(int x, int y); // version entière
double add(double x, double y); // version à virgule flottante
double add(int x, double y); // version mixte
double add(double x, int y); // version mixte

Comme les alias de types (ou typedefs) ne sont pas des types distincts, les fonctions surchargées utilisant des alias de types ne sont pas différenciées des surcharges utilisant le type aliasé. Par exemple, toutes les surcharges suivantes ne sont pas différenciées (et provoqueront une erreur de compilation) :

typedef int Height; // typedef
using Age = int; // alias de type

void print(int value);
void print(Age value); // non différencié de print(int)
void print(Height value); // non différencié de print(int)

Pour les paramètres passés par valeur, le qualificateur const n'est pas non plus pris en compte. Par conséquent, les fonctions suivantes ne sont pas considérées comme différenciées :

void print(int);
void print(const int); // non différencié de print(int)

Pour les lecteurs avancés

Nous n'avons pas encore abordé les points de suspension, mais les paramètres à points de suspension sont considérés comme un type de paramètre unique :

void foo(int x, int y);
void foo(int x, ...); // différencié de foo(int, int)

Ainsi, un appel foo(4, 5) correspondra à foo(int, int), et non à foo(int, ...).

Le type de retour d'une fonction n'est pas pris en compte pour la différenciation

Le type de retour d'une fonction n'est pas pris en compte lors de la différenciation des fonctions surchargées.

Considérons le cas où vous voulez écrire une fonction qui renvoie un nombre aléatoire, mais où vous avez besoin d'une version qui renvoie un int et d'une autre version qui renvoie un double. Vous pourriez être tenté d'écrire ceci :

int getRandomValue();
double getRandomValue();

Sur Visual Studio 2019, cela produit l'erreur de compilation suivante :


error C2556: 'double getRandomValue(void)': overloaded function differs only by return type from 'int getRandomValue(void)'

Cela se comprend. Si vous étiez le compilateur et que vous rencontriez cette instruction :

getRandomValue();

laquelle des deux fonctions surchargées appelleriez-vous ? Ce n'est pas clair.

En passant…

Ce choix a été fait délibérément : il garantit que le comportement d'un appel de fonction peut être déterminé indépendamment du reste de l'expression, ce qui rend les expressions complexes beaucoup plus faciles à comprendre. Autrement dit, nous pouvons toujours déterminer quelle version d'une fonction sera appelée uniquement à partir des arguments de l'appel. Si les valeurs de retour étaient utilisées pour la différenciation, nous n'aurions pas de moyen syntaxique simple de savoir quelle surcharge d'une fonction est appelée : il faudrait aussi comprendre comment la valeur de retour est utilisée, ce qui demande beaucoup plus d'analyse.

La meilleure solution consiste à donner aux fonctions des noms différents :

int getRandomInt();
double getRandomDouble();

Signature de type

La signature de type d'une fonction (généralement appelée signature) est définie comme les parties de l'en-tête de la fonction qui sont utilisées pour différencier la fonction. En C++, elle comprend le nom de la fonction, le nombre de paramètres, les types des paramètres et les qualificatifs de fonction. Elle n'inclut notamment pas le type de retour.

Décoration des noms (name mangling)

En passant…

Lorsque le compilateur compile une fonction, il effectue une décoration des noms (name mangling), ce qui signifie que le nom compilé de la fonction est modifié (« décoré ») selon différents critères, comme le nombre et le type des paramètres, afin que l'éditeur de liens dispose de noms uniques avec lesquels travailler.

Par exemple, une fonction de prototype int fcn() pourrait être compilée sous le nom décoré __fcn_v, tandis que int fcn(int) pourrait devenir __fcn_i. Ainsi, alors que dans le code source les deux fonctions surchargées partagent le nom fcn(), dans le code compilé les noms décorés sont uniques (__fcn_v contre __fcn_i).

Il n'existe aucune norme sur la manière de décorer les noms : différents compilateurs produiront donc des noms décorés différents.
