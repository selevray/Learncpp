11.10 — Utilisation de modèles de fonctions dans plusieurs fichiers

Considérons le programme suivant, qui ne fonctionne pas correctement :

main.cpp :

#include <iostream>

template <typename T>
T addOne(T x); // déclaration anticipée (forward declaration) du modèle de fonction

int main()
{
    std::cout << addOne(1) << '\n';
    std::cout << addOne(2.3) << '\n';

    return 0;
}

add.cpp :

template <typename T>
T addOne(T x) // définition du modèle de fonction
{
    return x + 1;
}

Si addOne était une fonction non template, ce programme fonctionnerait parfaitement : dans main.cpp, le compilateur se contenterait de la déclaration anticipée de addOne, et l'éditeur de liens (linker) relierait l'appel à addOne() dans main.cpp à la définition de la fonction dans add.cpp.

Mais comme addOne est un template, ce programme ne fonctionne pas, et nous obtenons une erreur de l'éditeur de liens :


1>Project6.obj : error LNK2019: unresolved external symbol "int __cdecl addOne<int>(int)" (??$addOne@H@@YAHH@Z) referenced in function _main
1>Project6.obj : error LNK2019: unresolved external symbol "double __cdecl addOne<double>(double)" (??$addOne@N@@YANN@Z) referenced in function _main

Dans main.cpp, nous appelons addOne<int> et addOne<double>. Cependant, comme le compilateur ne voit pas la définition du modèle de fonction addOne, il ne peut pas instancier ces fonctions dans main.cpp. Il voit en revanche la déclaration anticipée de addOne et supposera que ces fonctions existent ailleurs et seront liées plus tard.

Lorsque le compilateur compile add.cpp, il voit la définition du modèle de fonction addOne. Cependant, ce modèle n'est utilisé nulle part dans add.cpp, donc le compilateur n'instancie rien. Le résultat final est que l'éditeur de liens ne peut pas relier les appels à addOne<int> et addOne<double> dans main.cpp aux fonctions réelles, car ces fonctions n'ont jamais été instanciées.

En complément…

Si add.cpp avait instancié ces fonctions, le programme aurait été compilé et lié sans problème. Mais de telles solutions sont fragiles et doivent être évitées : si le code de add.cpp était ultérieurement modifié de sorte que ces fonctions ne soient plus instanciées, le programme ne serait de nouveau pas lié. De même, si main.cpp appelait une autre version de addOne (comme addOne<float>) qui n'a pas été instanciée dans add.cpp, on rencontrerait le même problème.

La manière la plus classique de résoudre ce problème consiste à placer tout le code de vos templates dans un fichier d'en-tête (.h) plutôt que dans un fichier source (.cpp) :

add.h :

#ifndef ADD_H
#define ADD_H

template <typename T>
T addOne(T x) // définition du modèle de fonction
{
    return x + 1;
}

#endif

main.cpp :

#include "add.h" // importe la définition du modèle de fonction
#include <iostream>

int main()
{
    std::cout << addOne(1) << '\n';
    std::cout << addOne(2.3) << '\n';

    return 0;
}

Ainsi, tout fichier ayant besoin du template peut #include l'en-tête correspondant, et la définition du template sera recopiée par le préprocesseur dans le fichier source. Le compilateur pourra alors instancier toutes les fonctions nécessaires.

Vous vous demandez peut-être pourquoi cela ne viole pas la règle de définition unique (ODR, One Definition Rule). La règle ODR indique que les types, les templates, les fonctions inline et les variables inline peuvent avoir des définitions identiques dans différents fichiers. Il n'y a donc aucun problème si la définition d'un template est recopiée dans plusieurs fichiers (à condition que chaque définition soit identique).

Contenu associé

Nous avons abordé la règle ODR dans la leçon 2.7 -- Déclarations anticipées et définitions.

Mais qu'en est-il des fonctions instanciées elles-mêmes ? Si une fonction est instanciée dans plusieurs fichiers, comment cela ne viole-t-il pas la règle ODR ? La réponse est que les fonctions instanciées implicitement à partir de templates sont implicitement inline. Or, comme vous le savez, les fonctions inline peuvent être définies dans plusieurs fichiers, à condition que la définition soit identique dans chacun.

Point clé

Les définitions de templates sont exemptées de la partie de la règle de définition unique qui exige une seule définition par programme. Il n'est donc pas problématique d'#include la même définition de template dans plusieurs fichiers source. De plus, les fonctions instanciées implicitement à partir de modèles de fonctions sont implicitement inline, elles peuvent donc être définies dans plusieurs fichiers, à condition que chaque définition soit identique.

Les templates eux-mêmes ne sont pas inline, car le concept d'inline ne s'applique qu'aux variables et aux fonctions.

Voici un autre exemple de modèle de fonction placé dans un fichier d'en-tête, afin de pouvoir être inclus dans plusieurs fichiers source :

max.h :

#ifndef MAX_H
#define MAX_H

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

#endif

foo.cpp :

#include "max.h" // importe la définition du template max<T>(T, T)
#include <iostream>

void foo()
{
    std::cout << max(3, 2) << '\n';
}

main.cpp :

#include "max.h" // importe la définition du template max<T>(T, T)
#include <iostream>

void foo(); // déclaration anticipée de la fonction foo

int main()
{
    std::cout << max(3, 5) << '\n';
    foo();

    return 0;
}

Dans l'exemple ci-dessus, main.cpp et foo.cpp font tous deux #include "max.h", de sorte que le code des deux fichiers peut utiliser le modèle de fonction max<T>(T, T).

Bonne pratique

Les templates nécessaires dans plusieurs fichiers doivent être définis dans un fichier d'en-tête, puis #includes partout où ils sont nécessaires. Cela permet au compilateur de voir la définition complète du template et d'instancier celui-ci lorsque c'est nécessaire.
