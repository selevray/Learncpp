11.8 — Modèles de fonctions avec plusieurs types de paramètres

Dans la leçon 11.6 -- Modèles de fonctions, nous avons écrit un modèle de fonction pour calculer le maximum de deux valeurs :

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(1, 2) << '\n';   // instanciera max(int, int)
    std::cout << max(1.5, 2.5) << '\n'; // instanciera max(double, double)

    return 0;
}

Considérons maintenant le programme suivant, très similaire :

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(2, 3.5) << '\n';  // erreur de compilation

    return 0;
}

Vous serez peut-être surpris de constater que ce programme ne compile pas. Le compilateur affiche plutôt une série de messages d'erreur (probablement étranges). Sous Visual Studio, l'auteur a obtenu ceci :


Project3.cpp(11,18): error C2672: 'max': no matching overloaded function found
Project3.cpp(11,28): error C2782: 'T max(T,T)': template parameter 'T' is ambiguous
Project3.cpp(4): message : see declaration of 'max'
Project3.cpp(11,28): message : could be 'double'
Project3.cpp(11,28): message : or       'int'
Project3.cpp(11,28): error C2784: 'T max(T,T)': could not deduce template argument for 'T' from 'double'
Project3.cpp(4): message : see declaration of 'max'

Dans l'appel de fonction max(2, 3.5), nous passons deux arguments de types différents : un int et un double. Comme nous appelons la fonction sans utiliser les chevrons pour préciser un type réel, le compilateur cherche d'abord s'il existe une correspondance non modèle pour max(int, double). Il n'en trouve pas.

Ensuite, le compilateur cherche si une correspondance avec un modèle de fonction est possible (en utilisant la déduction des arguments de modèle, que nous avons vue dans la leçon 11.7 -- Instanciation des modèles de fonctions). Cela échoue également, pour une raison simple : T ne peut représenter qu'un seul type. Il n'existe aucun type pour T qui permettrait au compilateur d'instancier le modèle max<T>(T, T) en une fonction acceptant deux types de paramètres différents. Autrement dit, comme les deux paramètres du modèle sont de type T, ils doivent correspondre au même type réel.

Comme ni une correspondance non modèle ni une correspondance avec un modèle n'ont pu être trouvées, l'appel de fonction ne peut pas être résolu, et nous obtenons une erreur de compilation.

Vous vous demandez peut-être pourquoi le compilateur n'a pas généré la fonction max<double>(double, double) et converti l'argument int en double par conversion numérique. La réponse est simple : la conversion de type n'est effectuée que lors de la résolution des surcharges, et non lors de la déduction des arguments de modèle.

Cette absence de conversion de type est intentionnelle, pour au moins deux raisons. D'abord, elle simplifie les choses : soit nous trouvons une correspondance exacte entre les arguments de l'appel et les paramètres de type du modèle, soit nous n'en trouvons pas. Ensuite, elle nous permet de créer des modèles de fonctions pour les cas où nous voulons garantir que deux paramètres ou plus ont le même type (comme dans l'exemple ci-dessus).

Nous devons donc trouver une autre solution. Heureusement, nous pouvons résoudre ce problème de (au moins) trois façons.

Utiliser static_cast pour convertir les arguments en types identiques

La première solution consiste à laisser à l'appelant la charge de convertir les arguments en types identiques. Par exemple :

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(static_cast<double>(2), 3.5) << '\n'; // convertit notre int en double pour pouvoir appeler max(double, double)

    return 0;
}

Maintenant que les deux arguments sont de type double, le compilateur peut instancier max(double, double) qui satisfait cet appel de fonction.

Cependant, cette solution est maladroite et peu lisible.

Fournir un argument de modèle de type explicite

Si nous avions écrit une fonction non modèle max(double, double), nous pourrions appeler max(int, double) et laisser les règles de conversion implicite transformer notre argument int en double, ce qui permettrait de résoudre l'appel :

#include <iostream>

double max(double x, double y)
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(2, 3.5) << '\n'; // l'argument int sera converti en double

    return 0;
}

Cependant, lorsque le compilateur effectue la déduction des arguments de modèle, il n'effectue aucune conversion de type. Heureusement, nous n'avons pas à utiliser la déduction des arguments de modèle si nous spécifions explicitement l'argument de type à utiliser :

#include <iostream>

template <typename T>
T max(T x, T y)
{
    return (x < y) ? y : x;
}

int main()
{
    // nous avons explicitement spécifié le type double, donc le compilateur n'utilisera pas la déduction des arguments de modèle
    std::cout << max<double>(2, 3.5) << '\n';

    return 0;
}

Dans l'exemple ci-dessus, nous appelons max<double>(2, 3.5). Comme nous avons explicitement précisé que T doit être remplacé par double, le compilateur n'utilise pas la déduction des arguments de modèle. Il instancie simplement la fonction max<double>(double, double), puis convertit tous les arguments qui ne correspondent pas. Notre paramètre int est donc implicitement converti en double.

Cette écriture est plus lisible que l'utilisation de static_cast, mais il serait encore plus agréable de ne même pas avoir à penser aux types lors de l'appel à max.

Modèles de fonctions avec plusieurs paramètres de type

La source de notre problème est que nous n'avons défini qu'un seul paramètre de type (T) pour notre modèle de fonction, puis nous avons imposé que les deux paramètres soient de ce même type.

La meilleure façon de résoudre ce problème est de réécrire notre modèle de fonction de sorte que nos paramètres puissent correspondre à des types différents. Plutôt qu'un seul paramètre de type T, nous en utiliserons maintenant deux (T et U) :

#include <iostream>

template <typename T, typename U> // nous utilisons deux paramètres de type nommés T et U
T max(T x, U y) // x peut correspondre au type T, et y au type U
{
    return (x < y) ? y : x; // attention, nous avons ici un problème de conversion restrictive
}

int main()
{
    std::cout << max(2, 3.5) << '\n'; // correspond à max<int, double>

    return 0;
}

Comme nous avons défini x avec le type de modèle T, et y avec le type de modèle U, x et y peuvent maintenant déterminer leur type indépendamment l'un de l'autre. Lorsque nous appelons max(2, 3.5), T peut être un int et U un double. Le compilateur instanciera volontiers max<int, double>(int, double) pour nous.

Point clé

Comme T et U sont des paramètres de modèle indépendants, ils déterminent leur type indépendamment l'un de l'autre. Cela signifie que T et U peuvent correspondre à des types différents, ou bien à un même type.

Cependant, cet exemple ne fonctionne pas correctement. Si vous compilez et exécutez le programme (avec l'option « traiter les avertissements comme des erreurs » désactivée), il produit le résultat suivant :


3

Que se passe-t-il ? Comment le maximum de 2 et 3.5 peut-il valoir 3 ?

L'opérateur conditionnel (?:) exige que ses opérandes (autres que la condition) aient le même type commun. Les règles arithmétiques habituelles (10.5 -- Conversions arithmétiques) déterminent quel sera ce type commun, et le résultat de l'opérateur conditionnel aura également ce type commun. Par exemple, le type commun de int et double est double, donc lorsque les opérandes (autres que la condition) de notre opérateur conditionnel sont un int et un double, la valeur produite par l'opérateur conditionnel sera de type double. Dans ce cas, il s'agit de la valeur 3.5, ce qui est correct.

Cependant, le type de retour déclaré de notre fonction est T. Lorsque T est un int et U un double, le type de retour de la fonction est int. Notre valeur 3.5 subit donc une conversion restrictive vers la valeur int 3, ce qui entraîne une perte de données (et éventuellement un avertissement du compilateur).

Comment résoudre ce problème ? Faire du type de retour un U ne suffit pas, car max(3.5, 2) a alors U égal à int et présente le même problème.

Dans de tels cas, la déduction du type de retour (via auto) peut être utile : nous laissons le compilateur déduire le type de retour à partir de l'instruction return :

#include <iostream>

template <typename T, typename U>
auto max(T x, U y) // demande au compilateur de déterminer le type de retour approprié
{
    return (x < y) ? y : x;
}

int main()
{
    std::cout << max(2, 3.5) << '\n';

    return 0;
}

Cette version de max fonctionne maintenant correctement avec des opérandes de types différents. Notez simplement qu'une fonction dont le type de retour est auto doit être entièrement définie avant d'être utilisée (une déclaration anticipée ne suffit pas), car le compilateur doit examiner l'implémentation de la fonction pour déterminer le type de retour.

Pour les lecteurs avancés

Si nous avons besoin d'une fonction pouvant être déclarée à l'avance, nous devons être explicites sur le type de retour. Comme notre type de retour doit être le type commun de T et U, nous pouvons utiliser std::common_type_t (présenté dans la leçon 10.5 -- Conversions arithmétiques) pour obtenir le type commun de T et U et l'utiliser comme type de retour explicite :

#include <iostream>
#include <type_traits> // pour std::common_type_t

template <typename T, typename U>
auto max(T x, U y) -> std::common_type_t<T, U>; // renvoie le type commun de T et U

int main()
{
    std::cout << max(2, 3.5) << '\n';

    return 0;
}

template <typename T, typename U>
auto max(T x, U y) -> std::common_type_t<T, U>
{
    return (x < y) ? y : x;
}

Modèles de fonctions abrégés (C++20)

C++20 introduit un nouvel usage du mot-clé auto : lorsque auto est utilisé comme type de paramètre dans une fonction ordinaire, le compilateur transforme automatiquement la fonction en modèle de fonction, chaque paramètre auto devenant un paramètre de type de modèle indépendant. Cette méthode de création d'un modèle de fonction s'appelle un modèle de fonction abrégé (abbreviated function template).

Par exemple :

auto max(auto x, auto y)
{
    return (x < y) ? y : x;
}

est, en C++20, une notation abrégée de :

template <typename T, typename U>
auto max(T x, U y)
{
    return (x < y) ? y : x;
}

qui est identique au modèle de fonction max écrit plus haut.

Lorsque vous voulez que chaque paramètre de type de modèle soit un type indépendant, cette forme est préférable, car la suppression de la ligne de déclaration des paramètres de modèle rend votre code plus concis et plus lisible.

Il n'existe pas de manière concise d'utiliser les modèles de fonctions abrégés lorsque vous voulez que plusieurs paramètres auto soient du même type. Autrement dit, il n'existe pas de modèle de fonction abrégé simple pour quelque chose comme ceci :

template <typename T>
T max(T x, T y) // deux paramètres de même type
{
    return (x < y) ? y : x;
}

Bonne pratique

N'hésitez pas à utiliser les modèles de fonctions abrégés lorsqu'il n'y a qu'un seul paramètre auto, ou lorsque chaque paramètre auto doit être un type indépendant (et que votre norme de langage est C++20 ou plus récente).

Les modèles de fonctions peuvent être surchargés

De même que les fonctions peuvent être surchargées, les modèles de fonctions peuvent aussi l'être. Ces surcharges peuvent avoir un nombre différent de paramètres de type et/ou un nombre ou des types de paramètres de fonction différents :

#include <iostream>

// Additionne deux valeurs de types identiques
template <typename T>
auto add(T x, T y)
{
    return x + y;
}

// Additionne deux valeurs de types différents
// Depuis C++20, nous pourrions aussi utiliser auto add(auto x, auto y)
template <typename T, typename U>
auto add(T x, U y)
{
    return x + y;
}

// Additionne trois valeurs de type quelconque
// Depuis C++20, nous pourrions aussi utiliser auto add(auto x, auto y, auto z)
template <typename T, typename U, typename V>
auto add(T x, U y, V z)
{
    return x + y + z;
}

int main()
{
    std::cout << add(1.2, 3.4) << '\n'; // instancie et appelle add<double>()
    std::cout << add(5.6, 7) << '\n';   // instancie et appelle add<double, int>()
    std::cout << add(8, 9, 10) << '\n'; // instancie et appelle add<int, int, int>()

    return 0;
}

Une remarque intéressante ici : pour l'appel add(1.2, 3.4), le compilateur préfère add<T>(T, T) à add<T, U>(T, U), alors que les deux pourraient correspondre.

Les règles qui déterminent lequel de plusieurs modèles de fonctions correspondants doit être préféré s'appellent « ordonnancement partiel des modèles de fonctions » (partial ordering of function templates). En bref, le modèle de fonction le plus restrictif ou le plus spécialisé est préféré. add<T>(T, T) est ici le modèle le plus restrictif (puisqu'il n'a qu'un seul paramètre de modèle), il est donc préféré.

Si plusieurs modèles de fonctions peuvent correspondre à un appel et que le compilateur ne peut pas déterminer lequel est le plus restrictif, le compilateur signale une correspondance ambiguë.
