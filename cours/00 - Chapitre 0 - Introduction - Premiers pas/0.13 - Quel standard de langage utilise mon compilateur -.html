0.13 — Quel standard de langage utilise mon compilateur ?

Le programme suivant affiche le nom du standard de langage que votre compilateur utilise actuellement. Vous pouvez copier/coller, compiler et exécuter ce programme pour vérifier que votre compilateur utilise bien le standard de langage attendu.

PrintStandard.cpp :

// Ce programme affiche le standard de langage C++ que votre compilateur utilise actuellement
// Distribution libre, offert par learncpp.com (https://www.learncpp.com/cpp-tutorial/what-language-standard-is-my-compiler-using/)

#include <iostream>

const int numStandards = 7;
// Le code stdCode de C++26 est un espace réservé, car le code exact ne sera déterminé qu'une fois le standard finalisé
const long stdCode[numStandards] = { 199711L, 201103L, 201402L, 201703L, 202002L, 202302L, 202612L};
const char* stdName[numStandards] = { "Pre-C++11", "C++11", "C++14", "C++17", "C++20", "C++23", "C++26" };

long getCPPStandard()
{
    // Visual Studio ne respecte pas la norme pour __cplusplus (sauf si vous définissez un indicateur de compilation spécifique, ce que vous n'avez probablement pas fait)
    // Dans Visual Studio 2015 ou plus récent, nous pouvons utiliser _MSVC_LANG à la place
    // Voir https://devblogs.microsoft.com/cppblog/msvc-now-correctly-reports-__cplusplus/
#if defined (_MSVC_LANG)
    return _MSVC_LANG;
#elif defined (_MSC_VER)
    // Si nous utilisons une ancienne version de Visual Studio, on abandonne
    return -1;
#else
    // __cplusplus est la méthode prévue pour interroger le code du standard de langage (tel que défini par les standards du langage)
    return __cplusplus;
#endif
}

int main()
{
    long standard = getCPPStandard();

    if (standard == -1)
    {
        std::cout << "Error: Unable to determine your language standard.  Sorry.\n";
        return 0;
    }

    for (int i = 0; i < numStandards; ++i)
    {
        // Si la version signalée correspond à l'un des codes de standard finalisés,
        // alors nous savons exactement quelle version le compilateur exécute
        if (standard == stdCode[i])
        {
            std::cout << "Your compiler is using " << stdName[i]
                << " (language standard code " << standard << "L)\n";
            break;
        }

        // Si la version signalée se situe entre deux codes de standard finalisés,
        // il s'agit forcément d'une prise en charge en avant-première ou expérimentale de la prochaine version
        if (standard < stdCode[i])
        {
            std::cout << "Your compiler is using a preview/pre-release of " << stdName[i]
                << " (language standard code " << standard << "L)\n";
            break;
        }
    }

    return 0;
}

Problèmes de compilation ou d'exécution

Si vous obtenez une erreur lors de la compilation, il se peut que votre projet soit mal configuré. Consultez 0.8 -- Quelques problèmes courants en C++ pour des conseils sur certains problèmes courants. Si cela ne suffit pas, reprenez les leçons à partir de 0.6 -- Installer un environnement de développement intégré (IDE).

Si le programme affiche « Error: Unable to determine your language standard », votre compilateur n'est peut-être pas conforme à la norme. Si vous utilisez un compilateur populaire et que c'est le cas, merci de laisser un commentaire ci-dessous avec les informations utiles (par exemple le nom et la version de votre compilateur).

Si ce programme affiche un standard de langage différent de celui que vous attendiez :

  • Vérifiez les paramètres de votre IDE pour vous assurer que votre compilateur est configuré pour utiliser le standard de langage attendu. Consultez 0.12 -- Configurer votre compilateur : choisir un standard de langage pour plus d'informations sur la manière de procéder avec certains des principaux compilateurs. Assurez-vous qu'il n'y a pas de fautes de frappe ou d'erreurs de format. Certains compilateurs exigent de définir le standard de langage pour chaque projet plutôt que globalement, donc si vous venez de créer un nouveau projet, cela peut être la cause.

  • Votre IDE ou votre compilateur ne lit peut-être pas le fichier de configuration que vous éditez (nous recevons parfois des retours de lecteurs à ce sujet avec VS Code). Si cela semble être le cas, consultez la documentation de votre IDE ou de votre compilateur.

Q : Si mon compilateur utilise une version en avant-première ou en pré-publication, dois-je revenir à la version précédente ?

Si vous êtes en train d'apprendre le langage, ce n'est pas nécessaire. Gardez simplement à l'esprit que certaines fonctionnalités de la prochaine version du langage peuvent être absentes, incomplètes, buggées ou légèrement modifiées.
