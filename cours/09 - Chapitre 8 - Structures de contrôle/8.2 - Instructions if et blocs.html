8.2 — Instructions if et blocs

La première catégorie d'instructions de contrôle de flux que nous allons étudier est celle des instructions conditionnelles. Une instruction conditionnelle indique si une ou plusieurs instructions associées doivent être exécutées ou non.

C++ prend en charge deux grands types de conditionnelles : les if statements (que nous avons introduites dans la leçon 4.10 -- Introduction aux instructions if et que nous allons approfondir ici) et les switch statements (que nous verrons dans quelques leçons).

Petit rappel sur l'instruction if

L'instruction conditionnelle la plus élémentaire en C++ est l'if statement. Elle s'écrit :


if (condition)
    true_statement;

ou, avec une else statement optionnelle :


if (condition)
    true_statement;
else
    false_statement;

Si la condition vaut true, la true_statement est exécutée. Si la condition vaut false et qu'une else statement est présente, la false_statement est exécutée.

Voici un programme simple qui utilise une instruction if avec sa else optionnelle :

#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;

    if (x > 10)
        std::cout << x << " is greater than 10\n";
    else
        std::cout << x << " is not greater than 10\n";

    return 0;
}

Ce programme fonctionne exactement comme on pourrait s'y attendre :


Enter a number: 15
15 is greater than 10


Enter a number: 4
4 is not greater than 10

if ou else avec plusieurs instructions conditionnelles

Les nouveaux programmeurs essaient souvent quelque chose comme ceci :

#include <iostream>

namespace constants
{
    constexpr int minRideHeightCM { 140 };
}

int main()
{
    std::cout << "Enter your height (in cm): ";
    int x{};
    std::cin >> x;

    if (x >= constants::minRideHeightCM)
        std::cout << "You are tall enough to ride.\n";
    else
        std::cout << "You are not tall enough to ride.\n";
        std::cout << "Too bad!\n"; // concentrez-vous sur cette ligne

    return 0;
}

Cependant, examinez l'exécution suivante du programme :


Enter your height (in cm): 180
You are tall enough to ride.
Too bad!

Ce programme ne fonctionne pas comme prévu, car la true_statement et la false_statement ne peuvent être constituées que d'une seule instruction. L'indentation nous induit ici en erreur : le programme ci-dessus s'exécute comme s'il avait été écrit ainsi :

#include <iostream>

namespace constants
{
    constexpr int minRideHeightCM { 140 };
}

int main()
{
    std::cout << "Enter your height (in cm): ";
    int x{};
    std::cin >> x;

    if (x >= constants::minRideHeightCM)
        std::cout << "You are tall enough to ride.\n";
    else
        std::cout << "You are not tall enough to ride.\n";

    std::cout << "Too bad!\n"; // concentrez-vous sur cette ligne

    return 0;
}

Il apparaît ainsi plus clairement que « Too bad! » s'affiche toujours.

Il est pourtant courant de vouloir exécuter plusieurs instructions selon une condition. Pour cela, on peut utiliser une instruction composée (bloc) :

#include <iostream>

namespace constants
{
    constexpr int minRideHeightCM { 140 };
}

int main()
{
    std::cout << "Enter your height (in cm): ";
    int x{};
    std::cin >> x;

    if (x >= constants::minRideHeightCM)
        std::cout << "You are tall enough to ride.\n";
    else
    { // notez l'ajout du bloc ici
        std::cout << "You are not tall enough to ride.\n";
        std::cout << "Too bad!\n";
    }

    return 0;
}

Rappelez-vous qu'un bloc est traité comme une seule instruction, le programme fonctionne donc désormais comme prévu :


Enter your height (in cm): 180
You are tall enough to ride.


Enter your height (in cm): 130
You are not tall enough to ride.
Too bad!

Blocs implicites

Si le programmeur ne déclare pas de bloc dans la partie instruction d'un if ou d'un else, le compilateur en déclare un implicitement. Ainsi :


if (condition)
    true_statement;
else
    false_statement;

équivaut en réalité à :


if (condition)
{
    true_statement;
}
else
{
    false_statement;
}

La plupart du temps, cela n'a pas d'importance. Cependant, les nouveaux programmeurs essaient parfois de définir des variables dans ce bloc implicite, comme ceci :

#include <iostream>

int main()
{
    if (true)
        int x{ 5 };
    else
        int x{ 6 };

    std::cout << x << '\n';

    return 0;
}

Cela ne compile pas : le compilateur génère une erreur indiquant que l'identifiant x n'est pas défini. En effet, l'exemple ci-dessus équivaut à :

#include <iostream>

int main()
{
    if (true)
    {
        int x{ 5 };
    } // x détruite ici
    else
    {
        int x{ 6 };
    } // x détruite ici

    std::cout << x << '\n'; // x n'est pas dans la portée ici

    return 0;
}

Dans ce contexte, il apparaît plus clairement que la variable x a une portée de bloc et qu'elle est détruite à la fin de ce bloc. Au moment où l'on atteint la ligne std::cout, x n'existe plus.

Mettre ou non des blocs autour des instructions simples

Au sein de la communauté des programmeurs, on débat de la question de savoir si les instructions simples qui suivent un if ou un else doivent être explicitement placées dans un bloc.

Plusieurs arguments sont avancés en faveur de l'utilisation de blocs.

  1. Ne pas utiliser de blocs facilite l'ajout involontaire d'instructions qui semblent conditionnelles mais ne le sont pas. Considérons :
if (age >= minDrinkingAge)
    purchaseBeer();

Supposons maintenant que nous soyons pressés et que nous modifiions ce programme pour ajouter une autre fonctionnalité :

if (age >= minDrinkingAge)
    purchaseBeer();
    gamble(); // s'exécutera toujours

Oups, nous venons de permettre à des mineurs de jouer à des jeux d'argent. Bon séjour en prison !

  1. Ne pas utiliser de blocs peut rendre les programmes plus difficiles à déboguer. Supposons que nous ayons l'extrait suivant :
if (age >= minDrinkingAge)
    addBeerToCart(); // s'exécute conditionnellement

checkout(); // s'exécute toujours

Supposons que nous soupçonnions un problème dans la fonction addBeerToCart(), et que nous la commentions :

if (age >= minDrinkingAge)
//    addBeerToCart();

checkout(); // s'exécute maintenant conditionnellement

Nous avons désormais rendu checkout() conditionnelle, ce que nous n'avions certainement pas voulu.

Aucun de ces deux problèmes ne se produit si vous utilisez toujours des blocs après un if ou un else.

  1. if constexpr (une variante de l'instruction if introduite en C++23) impose l'utilisation de blocs. Utiliser des blocs garantit donc la cohérence entre if et if constexpr.

Le meilleur argument contre l'utilisation de blocs autour des instructions simples est que l'ajout de blocs, en espaçant verticalement le code, permet d'en voir moins à la fois, ce qui réduit la lisibilité et peut conduire à d'autres erreurs, plus graves.

La communauté semble davantage favorable à l'utilisation systématique de blocs qu'au contraire, même si cette recommandation n'est pas unanime.

Bonne pratique

Pensez à placer les instructions simples associées à un if ou à un else dans des blocs (en particulier lorsque vous apprenez). Les développeurs C++ plus expérimentés délaissent parfois cette pratique au profit d'un espacement vertical plus compact.

Un compromis raisonnable consiste à placer les instructions simples sur la même ligne que le if ou le else :

if (age >= minDrinkingAge) purchaseBeer();
else std::cout << "No drinky for you\n".

Cette approche évite les deux inconvénients mentionnés ci-dessus, au prix d'une légère perte de lisibilité.

Une critique pertinente de la méthode sur une seule ligne est qu'elle produit un code plus difficile à déboguer :

  • Comme la condition et l'instruction associée s'exécutent au ccours de la même étape, il est plus difficile de savoir si l'instruction a réellement été exécutée ou ignorée.
  • Comme la condition et l'instruction associée se trouvent sur la même ligne, vous ne pouvez pas placer un point d'arrêt uniquement sur l'instruction associée (pour n'arrêter l'exécution que lorsque l'instruction est effectivement exécutée).

Toutefois, si l'un de ces points vous gêne lors du débogage, vous pouvez insérer un saut de ligne entre la condition et l'instruction (pour qu'elles se trouvent sur des lignes distinctes), effectuer votre débogage, puis supprimer ce saut de ligne ensuite.

If-else ou if-if

Les nouveaux programmeurs se demandent parfois quand utiliser un if-else (un if suivi d'une ou plusieurs instructions else) ou un if-if (un if suivi d'une ou plusieurs instructions if supplémentaires).

  • Utilisez if-else lorsque vous ne voulez exécuter le code que pour la première condition true.
  • Utilisez if-if lorsque vous voulez exécuter le code pour toutes les conditions true.

Voici un programme qui illustre cette différence :

#include <iostream>

void ifelse(bool a, bool b, bool c)
{
    if (a)      // est toujours évaluée
        std::cout << "a";
    else if (b) // n'est évaluée que si la condition du if précédent est fausse
        std::cout << "b";
    else if (c) // n'est évaluée que si la condition du if précédent est fausse
        std::cout << "c";
    std::cout << '\n';
}

void ifif(bool a, bool b, bool c)
{
    if (a) // est toujours évaluée
        std::cout << "a";
    if (b) // est toujours évaluée
        std::cout << "b";
    if (c) // est toujours évaluée
        std::cout << "c";
    std::cout << '\n';
}

int main()
{
    ifelse(false, true, true);
    ifif(false, true, true);

    return 0;
}

Lors de l'appel ifelse(false, true, true), a vaut false : l'instruction associée n'est donc pas exécutée et c'est le else associé qui l'est à la place. b vaut true, donc nous affichons b. Comme cette condition if était vraie, le else associé ne s'exécute pas (ni aucun des autres else qui le suivent immédiatement). Remarquez que nous n'avons exécuté que le code qui suit la première condition true (b).

Lors de l'appel ifif(false, true, true), a vaut false : nous n'exécutons pas l'instruction associée et passons au if suivant. b vaut true, donc nous affichons b et passons au if suivant. c vaut true, donc nous affichons c. Remarquez que nous avons exécuté le code qui suit toutes les conditions true (b et c).

Examinons maintenant cette fonction, assez semblable :

char getFirstMatchingChar(bool a, bool b, bool c)
{
    if (a) // est toujours évaluée
        return 'a';
    else if (b) // n'est évaluée que si la condition du if précédent est fausse
        return 'b';
    else if (c) // n'est évaluée que si la condition du if précédent est fausse
        return 'c';

    return 0;
}

Comme nous utilisons un if-else, il est clair que nous ne voulons exécuter le code que pour la première condition true. Mais lorsque chaque instruction associée retourne une valeur, nous pouvons écrire plutôt ceci :

char getFirstMatchingChar(bool a, bool b, bool c)
{
    if (a) // est toujours évaluée
        return 'a'; // retourne lorsque la condition du if est vraie
    if (b) // n'est évaluée que si la condition du if précédent est fausse
        return 'b'; // retourne lorsque la condition du if est vraie
    if (c) // n'est évaluée que si la condition du if précédent est fausse
        return 'c'; // retourne lorsque la condition du if est vraie

    return 0;
}

Bien que cela puisse superficiellement laisser penser que nous voulons exécuter le code après chaque condition true, dès que la première condition true est trouvée, l'instruction associée fait retourner la fonction. Les instructions if suivantes n'ont jamais l'occasion d'être évaluées. Cette version se comporte donc de manière équivalente à la précédente. Lorsque chaque instruction associée retourne une valeur, de nombreux programmeurs préfèrent omettre les mots-clés else, car cela évite un encombrement inutile et aligne mieux les conditions.

Point clé

Lorsque toutes les instructions associées retournent une valeur, vous pouvez toujours utiliser un if-if, puisque le else n'apporte alors rien.
