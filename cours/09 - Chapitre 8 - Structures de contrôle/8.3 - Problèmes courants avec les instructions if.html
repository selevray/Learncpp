8.3 — Problèmes courants avec les instructions if

Cette leçon fait suite à la leçon 8.2 -- Instructions if et blocs. Nous allons y examiner quelques problèmes courants liés aux instructions if.

Instructions if imbriquées et le problème du else pendant (dangling else)

Il est possible d'imbriquer des instructions if à l'intérieur d'autres instructions if :

#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;

    if (x >= 0) // instruction if externe
        // c'est un mauvais style de codage d'imbriquer les instructions if de cette façon
        if (x <= 20) // instruction if interne
            std::cout << x << " is between 0 and 20\n";

    return 0;
}

Considérez maintenant le programme suivant :

#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;

    if (x >= 0) // instruction if externe
        // c'est un mauvais style de codage d'imbriquer les instructions if de cette façon
        if (x <= 20) // instruction if interne
            std::cout << x << " is between 0 and 20\n";

    // à quelle instruction if ce else appartient-il ?
    else
        std::cout << x << " is negative\n";

    return 0;
}

Le programme ci-dessus introduit une source d'ambiguïté potentielle appelée problème du else pendant (dangling else). L'instruction else du programme ci-dessus est-elle associée à l'instruction if externe ou à l'instruction if interne ?

La réponse est qu'une instruction else est associée à la dernière instruction if non appariée du même bloc. Ainsi, dans le programme ci-dessus, l'instruction else est associée à l'instruction if interne, comme si le programme avait été écrit ainsi :

#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;

    if (x >= 0) // instruction if externe
    {
        if (x <= 20) // instruction if interne
            std::cout << x << " is between 0 and 20\n";
        else // rattaché à l'instruction if interne
            std::cout << x << " is negative\n";
    }

    return 0;
}

Cela fait produire au programme ci-dessus une sortie incorrecte :


Enter a number: 21
21 is negative

Pour éviter de telles ambiguïtés lorsque l'on imbrique des instructions if, il est recommandé d'enfermer explicitement l'instruction if interne dans un bloc. Cela nous permet de rattacher une instruction else soit à l'instruction if interne, soit à l'instruction if externe, sans ambiguïté :

#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;

    if (x >= 0)
    {
        if (x <= 20)
            std::cout << x << " is between 0 and 20\n";
        else // rattaché à l'instruction if interne
            std::cout << x << " is greater than 20\n";
    }
    else // rattaché à l'instruction if externe
        std::cout << x << " is negative\n";

    return 0;
}

L'instruction else située à l'intérieur du bloc se rattache à l'instruction if interne, tandis que l'instruction else située à l'extérieur du bloc se rattache à l'instruction if externe.

Aplatir les instructions if imbriquées

Les instructions if imbriquées peuvent souvent être aplaties, soit en restructurant la logique, soit en utilisant des opérateurs logiques (présentés dans la leçon 6.8 -- Opérateurs logiques). Un code moins imbriqué est moins sujet aux erreurs.

Par exemple, l'exemple ci-dessus peut être aplati de la manière suivante :

#include <iostream>

int main()
{
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;

    if (x < 0)
        std::cout << x << " is negative\n";
    else if (x <= 20) // ne s'exécute que si x >= 0
        std::cout << x << " is between 0 and 20\n";
    else // ne s'exécute que si x > 20
        std::cout << x << " is greater than 20\n";

    return 0;
}

Voici un autre exemple, qui utilise des opérateurs logiques pour tester plusieurs conditions dans une seule instruction if :

#include <iostream>

int main()
{
    std::cout << "Enter an integer: ";
    int x{};
    std::cin >> x;

    std::cout << "Enter another integer: ";
    int y{};
    std::cin >> y;

    if (x > 0 && y > 0) // && est le et logique -- vérifie si les deux conditions sont vraies
        std::cout << "Both numbers are positive\n";
    else if (x > 0 || y > 0) // || est le ou logique -- vérifie si l'une des conditions est vraie
        std::cout << "One of the numbers is positive\n";
    else
        std::cout << "Neither number is positive\n";

    return 0;
}

Instructions nulles

Une instruction nulle (null statement) est une instruction d'expression qui consiste uniquement en un point-virgule :

if (x > 10)
    ; // ceci est une instruction nulle

Les instructions nulles ne font rien. Elles sont généralement utilisées lorsque le langage exige qu'une instruction soit présente, alors que le programmeur n'en a pas besoin. Pour la lisibilité, les instructions nulles sont généralement placées sur leur propre ligne. Nous verrons plus tard, dans ce chapitre, des exemples d'instructions nulles volontaires lorsque nous aborderons les boucles.

Les instructions nulles sont rarement utilisées volontairement avec les instructions if. En revanche, elles peuvent causer involontairement des problèmes aux programmeurs débutants (ou peu attentifs). Considérez l'extrait suivant :

if (nuclearCodesActivated()); // remarquez le point-virgule à la fin de cette ligne
    blowUpTheWorld();

Dans l'extrait ci-dessus, le programmeur a accidentellement placé un point-virgule à la fin de l'instruction if (une erreur courante, car les points-virgules terminent de nombreuses instructions). Cette erreur anodine se compile sans problème, et fait exécuter l'extrait comme s'il avait été écrit ainsi :

if (nuclearCodesActivated())
    ; // le point-virgule agit comme une instruction nulle
blowUpTheWorld(); // et cette ligne est toujours exécutée !

Attention

Veillez à ne pas « terminer » votre instruction if par un point-virgule, sinon la ou les instructions que vous vouliez exécuter conditionnellement seront exécutées inconditionnellement (même si elles se trouvent à l'intérieur d'un bloc).

Astuce

En Python, le mot-clé pass joue le rôle d'instruction nulle. Il sert souvent de marqueur pour du code qui sera implémenté plus tard. Comme il s'agit d'un mot plutôt que d'un symbole, pass est moins sujet à une utilisation involontaire et plus facile à rechercher (ce qui permet de retrouver facilement ces marqueurs par la suite).


for x in [0, 1, 2]:
  pass               # À compléter plus tard

En C++, nous pouvons imiter pass en utilisant le préprocesseur :

#define PASS

void foo(int x, int y)
{
    if (x > y)
        PASS;
    else
        PASS;
}

int main()
{
    foo(4, 7);

    return 0;
}

Par cohérence avec les autres instructions C++, notre PASS nécessite un point-virgule final. PASS est supprimé par le préprocesseur, et le point-virgule final est interprété par le compilateur comme une instruction nulle.

Operator== et Operator= dans la condition

Dans une condition, vous devez utiliser operator== pour tester l'égalité, et non operator= (qui est l'affectation). Considérez le programme suivant :

#include <iostream>

int main()
{
    std::cout << "Enter 0 or 1: ";
    int x{};
    std::cin >> x;
    if (x = 0) // oups, nous avons utilisé une affectation ici au lieu d'un test d'égalité
        std::cout << "You entered 0\n";
    else
        std::cout << "You entered 1\n";

    return 0;
}

Ce programme se compile et s'exécute, mais produit un mauvais résultat dans certains cas :


Enter 0 or 1: 0
You entered 1

En fait, ce programme produira toujours le résultat You entered 1. Cela se produit parce que x = 0 affecte d'abord la valeur 0 à x, puis s'évalue à la valeur de x, qui vaut maintenant 0, c'est-à-dire le booléen false. La condition étant toujours false, l'instruction else s'exécute toujours.
