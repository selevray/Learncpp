8.12 — Arrêts (quitter le programme prématurément)

Le dernier type d'instruction de contrôle de flux que nous aborderons dans ce chapitre est l'arrêt. Un arrêt (halt) est une instruction de contrôle de flux qui termine le programme. En C++, les arrêts sont implémentés sous forme de fonctions (et non de mots-clés), donc nos instructions d'arrêt seront des appels de fonctions.

Faisons un bref détour et récapitulons ce qui se passe lorsqu'un programme se termine normalement. Lorsque la fonction main() retourne (soit en atteignant la fin de la fonction, soit via une instruction return), plusieurs choses se produisent.

Tout d'abord, puisque nous quittons la fonction, toutes les variables locales et tous les paramètres de la fonction sont détruits (comme d'habitude).

Ensuite, une fonction spéciale appelée std::exit() est invoquée, avec la valeur de retour de main() (le status code) passée en argument. Qu'est-ce que std::exit() ?

La fonction std::exit()

std::exit() est une fonction qui provoque la terminaison normale du programme. Terminaison normale signifie que le programme s'est arrêté de manière attendue. Notez que le terme « terminaison normale » n'indique rien quant à la réussite du programme (c'est le rôle du status code). Par exemple, supposons que vous écriviez un programme dans lequel vous attendez de l'utilisateur qu'il saisisse le nom d'un fichier à traiter. Si l'utilisateur saisit un nom de fichier invalide, votre programme renverra probablement un status code non nul pour indiquer l'échec, mais il se terminera tout de même normalement.

std::exit() effectue plusieurs opérations de nettoyage. Tout d'abord, les objets ayant une durée de stockage statique sont détruits. Ensuite, un autre nettoyage divers des fichiers est effectué si des fichiers ont été utilisés. Enfin, le contrôle est rendu au système d'exploitation, l'argument passé à std::exit() étant utilisé comme status code.

Appeler std::exit() explicitement

Bien que std::exit() soit appelée implicitement après le retour de la fonction main(), elle peut aussi être appelée explicitement pour arrêter le programme avant sa terminaison normale. Lorsque std::exit() est appelée de cette façon, vous devez inclure l'en-tête cstdlib.

Point clé

std::exit est appelée implicitement lorsque main() retourne.

Voici un exemple d'utilisation explicite de std::exit() :

#include <cstdlib> // pour std::exit()
#include <iostream>

void cleanup()
{
    // code ici pour effectuer tout type de nettoyage nécessaire
    std::cout << "cleanup!\n";
}

int main()
{
    std::cout << 1 << '\n';
    cleanup();

    std::exit(0); // termine et renvoie le status code 0 au système d'exploitation

    // Les instructions suivantes ne sont jamais exécutées
    std::cout << 2 << '\n';

    return 0;
}

Ce programme affiche :


1
cleanup!

Notez que les instructions après l'appel à std::exit() ne sont jamais exécutées, car le programme s'est déjà terminé.

Bien que dans le programme ci-dessus nous appelions std::exit() depuis la fonction main(), std::exit() peut être appelée depuis n'importe quelle fonction pour terminer le programme à cet endroit.

std::exit() ne nettoie pas les variables locales

Une remarque importante concernant l'appel explicite à std::exit() : std::exit() ne nettoie aucune variable locale (que ce soit dans la fonction courante ou dans les fonctions situées plus haut dans la pile d'appels). Cela signifie que l'appel à std::exit() peut être dangereux si votre programme repose sur la destruction automatique de certaines variables locales.

Attention

La fonction std::exit() ne nettoie pas les variables locales de la fonction courante ni celles des fonctions de la pile d'appels.

std::atexit

Comme std::exit() termine le programme immédiatement, vous pouvez vouloir effectuer manuellement un nettoyage avant la terminaison. Dans ce contexte, le nettoyage désigne des opérations telles que la fermeture des connexions à une base de données ou au réseau, la libération de la mémoire allouée, l'écriture d'informations dans un fichier journal, etc.

En passant…

Lorsqu'une application se termine, les systèmes d'exploitation modernes nettoient généralement la mémoire que l'application n'a pas correctement libérée elle-même. Cela soulève la question : « pourquoi se donner la peine de nettoyer à la sortie ? » Il y a (au moins) deux raisons :

  1. Libérer la mémoire allouée est une « bonne habitude » que vous devrez adopter pour éviter les fuites de mémoire pendant l'exécution de l'application. Nettoyer dans certains cas et pas dans d'autres est incohérent et peut conduire à des erreurs. Ne pas libérer correctement la mémoire peut aussi affecter le comportement de certains outils, comme les profileurs de mémoire (ils peuvent être incapables de distinguer la mémoire que vous ne libérez pas par inadvertance de celle que vous ne libérez pas volontairement parce que vous n'en avez pas besoin).
  2. D'autres types de nettoyage peuvent être nécessaires pour que votre programme se comporte de manière prévisible. Par exemple, si vous écrivez des données dans un fichier puis quittez de façon inattendue, ces données peuvent ne pas avoir encore été vidées (flushed) dans le fichier et être perdues à la fermeture du programme. Fermer le fichier avant l'arrêt permet de s'assurer que toutes les données en cache sont écrites au préalable. Ou vous pourriez vouloir envoyer à un serveur les données de la session de l'utilisateur, ou la raison de l'arrêt du programme, avant que l'arrêt n'ait réellement lieu.

Dans l'exemple ci-dessus, nous avons appelé la fonction cleanup() pour gérer nos tâches de nettoyage. Cependant, penser à appeler manuellement une fonction de nettoyage avant chaque appel à exit() alourdit la charge du programmeur et est une recette pour les erreurs.

Pour faciliter cela, le C++ propose la fonction std::atexit(), qui permet de spécifier une fonction qui sera automatiquement appelée à la terminaison du programme via std::exit().

Contenu associé

Nous abordons le passage de fonctions en tant qu'arguments dans la leçon 20.1 -- Pointeurs de fonctions.

Voici un exemple :

#include <cstdlib> // pour std::exit()
#include <iostream>

void cleanup()
{
    // code ici pour effectuer tout type de nettoyage nécessaire
    std::cout << "cleanup!\n";
}

int main()
{
    // enregistre cleanup() pour qu'elle soit appelée automatiquement lorsque std::exit() est invoquée
    std::atexit(cleanup); // remarque : on utilise cleanup et non cleanup() car nous n'appelons pas la fonction cleanup() à ce stade

    std::cout << 1 << '\n';

    std::exit(0); // termine et renvoie le status code 0 au système d'exploitation

    // Les instructions suivantes ne sont jamais exécutées
    std::cout << 2 << '\n';

    return 0;
}

Ce programme produit la même sortie que l'exemple précédent :


1
cleanup!

Notez que lorsque nous passons la fonction cleanup() en argument, nous utilisons cleanup (le nom de la fonction) et non cleanup() (ce qui appellerait réellement la fonction).

L'avantage de std::atexit() est que nous n'avons à l'appeler qu'une seule fois (probablement depuis la fonction main()). Comme std::atexit() est appelée automatiquement à la sortie, nous n'avons pas à penser à appeler quoi que ce soit avant std::exit().

Quelques remarques sur std::atexit() et la fonction de nettoyage : tout d'abord, comme std::exit() est appelée implicitement lorsque main() se termine, cela invoquera toutes les fonctions enregistrées par std::atexit() si le programme se termine de cette façon. Ensuite, la fonction enregistrée ne doit prendre aucun paramètre et ne doit rien retourner. Enfin, vous pouvez enregistrer plusieurs fonctions de nettoyage avec std::atexit(), et elles seront appelées dans l'ordre inverse de leur enregistrement (la dernière enregistrée sera appelée en premier).

Pour les lecteurs avancés

Dans les programmes multithreads, l'appel à std::exit() peut faire planter votre programme (car le thread qui appelle std::exit() détruira les objets statiques auxquels d'autres threads peuvent encore accéder). Pour cette raison, le C++ a introduit une autre paire de fonctions, analogues à std::exit() et std::atexit() : std::quick_exit() et std::at_quick_exit(). std::quick_exit() termine le programme normalement, mais ne détruit pas les objets statiques et peut ou non effectuer d'autres types de nettoyage. std::at_quick_exit() joue le même rôle que std::atexit() pour les programmes terminés avec std::quick_exit().

std::abort et std::terminate

Le C++ contient deux autres fonctions liées aux arrêts.

La fonction std::abort() provoque la terminaison anormale de votre programme. Terminaison anormale signifie que le programme a rencontré une erreur d'exécution inhabituelle et ne peut pas continuer à s'exécuter. Par exemple, tenter de diviser par 0 entraîne une terminaison anormale. std::abort() n'effectue aucun nettoyage.

#include <cstdlib> // pour std::abort()
#include <iostream>

int main()
{
    std::cout << 1 << '\n';
    std::abort();

    // Les instructions suivantes ne sont jamais exécutées
    std::cout << 2 << '\n';

    return 0;
}

Nous verrons dans la leçon 9.6 -- Assert et static_assert des cas où std::abort est appelée implicitement.

La fonction std::terminate() est généralement utilisée en conjonction avec les exceptions (que nous aborderons dans un chapitre ultérieur). Bien qu'elle puisse être appelée explicitement, elle est plus souvent appelée implicitement lorsqu'une exception n'est pas gérée (et dans quelques autres cas liés aux exceptions). Par défaut, std::terminate() appelle std::abort().

Quand faut-il utiliser un arrêt ?

La réponse courte est « presque jamais ». La destruction des objets locaux est un aspect important du C++ (en particulier lorsque nous aborderons les classes), et aucune des fonctions mentionnées ci-dessus ne nettoie les variables locales. Les exceptions constituent un mécanisme meilleur et plus sûr pour gérer les cas d'erreur.

Bonne pratique

N'utilisez un arrêt que s'il n'existe aucun moyen sûr ou raisonnable de revenir normalement depuis la fonction main. Si vous n'avez pas désactivé les exceptions, privilégiez leur utilisation pour gérer les erreurs de manière sûre.

Astuce

Bien que l'usage explicite des arrêts doive être minimisé, il existe de nombreuses autres façons pour un programme de s'arrêter de manière inattendue. Par exemple :

  • L'application peut planter à cause d'un bogue (auquel cas le système d'exploitation la fermera).
  • L'utilisateur peut tuer l'application de différentes manières.
  • L'utilisateur peut couper (ou perdre) l'alimentation de son ordinateur.
  • Le soleil pourrait devenir une supernova et consumer la Terre dans une énorme boule de feu.

Un programme bien conçu doit pouvoir supporter d'être arrêté à tout moment avec un minimum de conséquences.

Pour un exemple courant, les jeux modernes sauvegardent souvent automatiquement l'état du jeu et les paramètres de l'utilisateur à intervalles réguliers, de sorte que si le jeu est fermé de façon inattendue sans sauvegarde, l'utilisateur peut reprendre plus tard (à partir de la sauvegarde automatique précédente) sans perdre beaucoup de progression.
