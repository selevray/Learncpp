8.6 — Fallthrough et portée dans les switch

Cette leçon poursuit l'étude des instructions switch commencée dans la leçon précédente, 8.5 -- Bases de l'instruction switch. Nous avons indiqué qu'il faut terminer chaque groupe d'instructions placé sous une étiquette par une instruction break ou return.

Dans cette leçon, nous allons voir pourquoi, et aborder certains problèmes de portée des switch qui piègent souvent les programmeurs débutants.

Fallthrough

Lorsque l'expression du switch correspond à une étiquette case ou à l'étiquette default facultative, l'exécution commence à la première instruction qui suit l'étiquette correspondante. L'exécution se poursuit ensuite séquentiellement jusqu'à ce que l'une des conditions de fin suivantes se produise :

  • La fin du bloc switch est atteinte.
  • Une autre instruction de contrôle de flux (typiquement break ou return) fait sortir du bloc switch ou de la fonction.
  • Un événement extérieur interrompt le déroulement normal du programme (par exemple, le système d'exploitation arrête le programme, l'univers s'effondre, etc.).

Notez que la présence d'une autre étiquette case n'est pas l'une de ces conditions de fin : sans break ni return, l'exécution se poursuit dans les cas suivants.

Voici un programme qui illustre ce comportement :

#include <iostream>

int main()
{
    switch (2)
    {
    case 1: // Ne correspond pas
        std::cout << 1 << '\n'; // Ignorée
    case 2: // Correspondance !
        std::cout << 2 << '\n'; // L'exécution commence ici
    case 3:
        std::cout << 3 << '\n'; // Celle-ci est aussi exécutée
    case 4:
        std::cout << 4 << '\n'; // Celle-ci est aussi exécutée
    default:
        std::cout << 5 << '\n'; // Celle-ci est aussi exécutée
    }

    return 0;
}

Ce programme affiche :


2
3
4
5

Ce n'est probablement pas ce que nous voulions ! Lorsque l'exécution passe des instructions placées sous une étiquette aux instructions placées sous une étiquette suivante, on parle de fallthrough (passage à travers).

Attention

Une fois que les instructions placées sous une étiquette case ou default ont commencé à s'exécuter, elles se poursuivent (fallthrough) dans les cas suivants. Les instructions break ou return servent généralement à éviter ce comportement.

Comme le fallthrough est rarement souhaité ou intentionnel, de nombreux compilateurs et outils d'analyse de code le signalent par un avertissement.

L'attribut [[fallthrough]]

Commenter un fallthrough intentionnel est une convention courante pour indiquer aux autres développeurs que ce passage est voulu. Si cela fonctionne auprès des autres développeurs, le compilateur et les outils d'analyse ne savent pas interpréter les commentaires, et les avertissements ne disparaissent donc pas.

Pour résoudre ce problème, le C++17 ajoute un nouvel attribut appelé [[fallthrough]].

Les attributs sont une fonctionnalité du C++ moderne qui permet au programmeur de fournir au compilateur des informations supplémentaires sur le code. Pour spécifier un attribut, on place son nom entre doubles crochets. Les attributs ne sont pas des instructions : ils peuvent être utilisés presque partout où ils ont un sens dans le contexte.

L'attribut [[fallthrough]] s'applique à une instruction nulle (null statement) pour indiquer que le fallthrough est intentionnel (et qu'aucun avertissement ne doit être émis) :

#include <iostream>

int main()
{
    switch (2)
    {
    case 1:
        std::cout << 1 << '\n';
        break;
    case 2:
        std::cout << 2 << '\n'; // L'exécution commence ici
        [[fallthrough]]; // fallthrough intentionnel -- notez le point-virgule qui indique l'instruction nulle
    case 3:
        std::cout << 3 << '\n'; // Celle-ci est aussi exécutée
        break;
    }

    return 0;
}

Ce programme affiche :


2
3

Et il ne doit générer aucun avertissement concernant le fallthrough.

Bonne pratique

Utilisez l'attribut [[fallthrough]] (accompagné d'une instruction nulle) pour indiquer un fallthrough intentionnel.

Étiquettes case consécutives

Vous pouvez utiliser l'opérateur OU logique pour combiner plusieurs tests dans une seule instruction :

bool isVowel(char c)
{
    return (c=='a' || c=='e' || c=='i' || c=='o' || c=='u' ||
        c=='A' || c=='E' || c=='I' || c=='O' || c=='U');
}

Cela pose les mêmes difficultés que celles présentées dans l'introduction aux instructions switch : c est évalué plusieurs fois, et le lecteur doit s'assurer que c'est bien c qui est évalué à chaque fois.

Vous pouvez faire quelque chose de similaire avec un switch, en plaçant plusieurs étiquettes case les unes à la suite des autres :

bool isVowel(char c)
{
    switch (c)
    {
    case 'a': // si c vaut 'a'
    case 'e': // ou si c vaut 'e'
    case 'i': // ou si c vaut 'i'
    case 'o': // ou si c vaut 'o'
    case 'u': // ou si c vaut 'u'
    case 'A': // ou si c vaut 'A'
    case 'E': // ou si c vaut 'E'
    case 'I': // ou si c vaut 'I'
    case 'O': // ou si c vaut 'O'
    case 'U': // ou si c vaut 'U'
        return true;
    default:
        return false;
    }
}

Rappelez-vous que l'exécution commence à la première instruction qui suit une étiquette case correspondante. Les étiquettes case ne sont pas des instructions (ce sont des étiquettes), donc elles ne comptent pas.

La première instruction qui suit toutes les étiquettes case du programme ci-dessus est return true. Ainsi, si l'une des étiquettes correspond, la fonction renvoie true.

On peut donc « empiler » les étiquettes case pour qu'elles partagent le même ensemble d'instructions. Ce n'est pas considéré comme un fallthrough, il n'est donc pas nécessaire d'utiliser un commentaire ou l'attribut [[fallthrough]] ici.

Les étiquettes ne définissent pas une nouvelle portée

Avec les instructions if, une seule instruction peut suivre la condition du if, et cette instruction est considérée comme implicitement placée dans un bloc :

if (x > 10)
    std::cout << x << " is greater than 10\n"; // cette ligne est implicitement considérée comme étant dans un bloc

En revanche, avec les instructions switch, les instructions placées après les étiquettes appartiennent toutes à la portée du bloc switch. Aucun bloc implicite n'est créé.

switch (1)
{
case 1: // ne crée pas de bloc implicite
    foo(); // cette instruction fait partie de la portée du switch, et non d'un bloc implicite de case 1
    break; // cette instruction fait partie de la portée du switch, et non d'un bloc implicite de case 1
default:
    std::cout << "default case\n";
    break;
}

Dans l'exemple ci-dessus, les deux instructions situées entre case 1 et l'étiquette default font partie de la portée du bloc switch, et non d'un bloc implicite de case 1.

Déclaration et initialisation de variables dans les instructions case

Vous pouvez déclarer ou définir (mais pas initialiser) des variables à l'intérieur du switch, avant comme après les étiquettes case :

switch (1)
{
    int a; // correct : la définition est autorisée avant les étiquettes case
    int b{ 5 }; // illégal : l'initialisation n'est pas autorisée avant les étiquettes case

case 1:
    int y; // correct mais mauvaise pratique : la définition est autorisée dans un case
    y = 4; // correct : l'affectation est autorisée
    break;

case 2:
    int z{ 4 }; // illégal : l'initialisation n'est pas autorisée si des cas suivants existent
    y = 5; // correct : y a été déclarée plus haut, on peut donc l'utiliser ici aussi
    break;

case 3:
    break;
}

Bien que la variable y soit définie dans case 1, elle est aussi utilisée dans case 2. Toutes les instructions à l'intérieur du switch font partie de la même portée. Ainsi, une variable déclarée ou définie dans un case peut être utilisée dans un case ultérieur, même si le case où elle est définie n'est jamais exécuté (car le switch a sauté par-dessus) !

En revanche, l'initialisation d'une variable nécessite que sa définition soit exécutée. L'initialisation est donc interdite dans tout case qui n'est pas le dernier (car le switch pourrait sauter l'initialisation s'il existe un case suivant, auquel cas la variable ne serait pas initialisée et y accéder produirait un comportement indéfini). L'initialisation est également interdite avant le premier case, car ces instructions ne seraient jamais exécutées, le switch n'ayant aucun moyen de les atteindre.

Si un case doit définir et/ou initialiser une nouvelle variable, la bonne pratique consiste à le faire dans un bloc explicite placé sous l'instruction case :

switch (1)
{
case 1:
{ // notez l'ajout d'un bloc explicite ici
    int x{ 4 }; // correct, les variables peuvent être initialisées dans un bloc à l'intérieur d'un case
    std::cout << x;
    break;
}

default:
    std::cout << "default case\n";
    break;
}

Bonne pratique

Si vous définissez des variables utilisées dans un case, faites-le dans un bloc à l'intérieur du case.

Quiz

Question n° 1

Écrivez une fonction appelée calculate() qui prend deux entiers et un char représentant l'une des opérations mathématiques suivantes : +, -, *, / ou % (reste de la division). Utilisez une instruction switch pour effectuer l'opération appropriée sur les entiers, puis renvoyez le résultat. Si un opérateur invalide est passé à la fonction, la fonction doit afficher un message d'erreur. Pour l'opérateur de division, effectuez une division entière, et ne vous souciez pas de la division par zéro.

Indice : « operator » est un mot-clé, et les variables ne peuvent pas être nommées « operator ».

Solution 
#include <iostream>

int calculate(int x, int y, char op)
{
    switch (op)
    {
    case '+':
        return x + y;
    case '-':
        return x - y;
    case '*':
        return x * y;
    case '/':
        return x / y;
    case '%':
        return x % y;
    default:
        std::cout << "calculate(): Unhandled case\n";
        return 0;
    }
}

int main()
{
    std::cout << "Enter an integer: ";
    int x{};
    std::cin >> x;

    std::cout << "Enter another integer: ";
    int y{};
    std::cin >> y;

    std::cout << "Enter a mathematical operator (+, -, *, /, or %): ";
    char op{};
    std::cin >> op;

    // On appelle d'abord calculate pour qu'un opérateur invalide affiche son propre message d'erreur sur une ligne distincte
    int result{ calculate(x, y, op) };
    std::cout << x << ' ' << op << ' ' << y << " is " << result << '\n';

    return 0;
}
