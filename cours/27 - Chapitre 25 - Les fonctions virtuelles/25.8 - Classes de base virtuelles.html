25.8 — Classes de base virtuelles

Dans le chapitre précédent, dans la leçon 24.9 -- Héritage multiple, nous avons laissé de côté le « problème du diamant ». Dans cette section, nous reprenons cette discussion.

Note : cette section traite d'un sujet avancé. Vous pouvez la sauter ou la parcourir rapidement si vous le souhaitez.

Le problème du diamant

Voici notre exemple de la leçon précédente (avec quelques constructeurs) illustrant le problème du diamant :

#include <iostream>

class PoweredDevice
{
public:
    PoweredDevice(int power)
    {
        std::cout << "PoweredDevice: " << power << '\n';
    }
};

class Scanner: public PoweredDevice
{
public:
    Scanner(int scanner, int power)
        : PoweredDevice{ power }
    {
        std::cout << "Scanner: " << scanner << '\n';
    }
};

class Printer: public PoweredDevice
{
public:
    Printer(int printer, int power)
        : PoweredDevice{ power }
    {
        std::cout << "Printer: " << printer << '\n';
    }
};

class Copier: public Scanner, public Printer
{
public:
    Copier(int scanner, int printer, int power)
        : Scanner{ scanner, power }, Printer{ printer, power }
    {
    }
};

Comme vous pouvez le voir, PoweredDevice a été construit deux fois.

Ce comportement est parfois souhaité, mais il arrive aussi que vous vouliez qu'un seul exemplaire de PoweredDevice soit partagé par Scanner et Printer.

Classes de base virtuelles

Pour partager une classe de base, il suffit d'insérer le mot-clé « virtual » dans la liste d'héritage de la classe dérivée. On crée ainsi ce que l'on appelle une classe de base virtuelle (virtual base class), ce qui signifie qu'il n'existe qu'un seul objet de base. Cet objet de base est partagé par tous les objets de l'arbre d'héritage et n'est construit qu'une seule fois. Voici un exemple (sans constructeurs, par souci de simplicité) montrant comment utiliser le mot-clé virtual pour créer une classe de base partagée :

class PoweredDevice
{
};

class Scanner: virtual public PoweredDevice
{
};

class Printer: virtual public PoweredDevice
{
};

class Copier: public Scanner, public Printer
{
};

Désormais, lorsque vous créez un objet de classe Copier, vous n'obtenez qu'un seul exemplaire de PoweredDevice par Copier, partagé par Scanner et Printer.

Cela pose toutefois un problème supplémentaire : si Scanner et Printer partagent une classe de base PoweredDevice, qui est responsable de sa création ? La réponse est Copier. C'est le constructeur de Copier qui est chargé de créer PoweredDevice. C'est donc l'un des rares cas où Copier est autorisée à appeler directement le constructeur d'une classe qui n'est pas son parent immédiat :

#include <iostream>

class PoweredDevice
{
public:
    PoweredDevice(int power)
    {
        std::cout << "PoweredDevice: " << power << '\n';
    }
};

class Scanner: virtual public PoweredDevice // note : PoweredDevice est désormais une classe de base virtuelle
{
public:
    Scanner(int scanner, int power)
        : PoweredDevice{ power } // cette ligne est nécessaire pour créer des objets Scanner, mais elle est ignorée dans ce cas
    {
        std::cout << "Scanner: " << scanner << '\n';
    }
};

class Printer: virtual public PoweredDevice // note : PoweredDevice est désormais une classe de base virtuelle
{
public:
    Printer(int printer, int power)
        : PoweredDevice{ power } // cette ligne est nécessaire pour créer des objets Printer, mais elle est ignorée dans ce cas
    {
        std::cout << "Printer: " << printer << '\n';
    }
};

class Copier: public Scanner, public Printer
{
public:
    Copier(int scanner, int printer, int power)
        : PoweredDevice{ power }, // PoweredDevice est construit ici
        Scanner{ scanner, power }, Printer{ printer, power }
    {
    }
};

Cette fois, notre exemple précédent :

int main()
{
    Copier copier{ 1, 2, 3 };

    return 0;
}

produit le résultat suivant :


PoweredDevice: 3
Scanner: 1
Printer: 2

Comme vous pouvez le voir, PoweredDevice n'est construit qu'une seule fois.

Il reste quelques détails que nous aurions tort de passer sous silence.

Premièrement, pour le constructeur de la classe la plus dérivée, les classes de base virtuelles sont toujours créées avant les classes de base non virtuelles, ce qui garantit que toutes les bases sont créées avant leurs classes dérivées.

Deuxièmement, notez que les constructeurs de Scanner et de Printer contiennent toujours des appels au constructeur de PoweredDevice. Lors de la création d'une instance de Copier, ces appels sont simplement ignorés, car c'est Copier qui est responsable de la création de PoweredDevice, et non Scanner ni Printer. En revanche, si nous créons une instance de Scanner ou de Printer, ces appels sont utilisés et les règles d'héritage habituelles s'appliquent.

Troisièmement, si une classe hérite d'une ou plusieurs classes ayant des parents virtuels, la classe la plus dérivée est responsable de la construction de la classe de base virtuelle. Dans le cas présent, Copier hérite de Printer et de Scanner, qui ont tous deux une classe de base virtuelle PoweredDevice. Copier, la classe la plus dérivée, est responsable de la création de PoweredDevice. Notez que cela reste vrai même dans le cas d'un héritage simple : si Copier héritait simplement de Printer, et que Printer héritait virtuellement de PoweredDevice, Copier serait tout de même responsable de la création de PoweredDevice.

Quatrièmement, toutes les classes héritant d'une classe de base virtuelle possèdent une table virtuelle (virtual table), même si elles n'en auraient pas eu normalement, et les instances de ces classes sont donc plus grandes d'un pointeur.

Comme Scanner et Printer dérivent virtuellement de PoweredDevice, Copier ne contient qu'un seul sous-objet PoweredDevice. Scanner et Printer doivent tous deux savoir comment trouver ce sous-objet PoweredDevice unique, afin de pouvoir accéder à ses membres (puisqu'ils en dérivent). Cela se fait généralement à l'aide d'un mécanisme de tables virtuelles (qui stocke essentiellement le décalage de chaque sous-classe vers le sous-objet PoweredDevice).
