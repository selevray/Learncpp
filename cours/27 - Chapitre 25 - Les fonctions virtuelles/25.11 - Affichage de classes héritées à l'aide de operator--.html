25.11 — Affichage de classes héritées à l'aide de operator<<

Considérez le programme suivant, qui utilise une fonction virtuelle :

#include <iostream>

class Base
{
public:
    virtual void print() const { std::cout << "Base";  }
};

class Derived : public Base
{
public:
    void print() const override { std::cout << "Derived"; }
};

int main()
{
    Derived d{};
    Base& b{ d };
    b.print(); // appelle Derived::print()

    return 0;
}

Vous devez maintenant être à l'aise avec le fait que b.print() appelle Derived::print() (parce que b référence un objet de classe Derived, que Base::print() est une fonction virtuelle et que Derived::print() en est une surcharge redéfinie).

Appeler des fonctions membres de cette façon pour afficher des données est acceptable, mais ce style ne se marie pas bien avec std::cout :

#include <iostream>

int main()
{
    Derived d{};
    Base& b{ d };

    std::cout << "b is a ";
    b.print(); // peu lisible : nous devons interrompre l'instruction d'affichage pour appeler cette fonction
    std::cout << '\n';

    return 0;
}

Dans cette leçon, nous verrons comment surcharger operator<< pour des classes utilisant l'héritage, afin de pouvoir utiliser operator<< comme prévu, de cette façon :

std::cout << "b is a " << b << '\n'; // bien mieux

Les difficultés posées par operator<<

Commençons par surcharger operator<< de manière classique :

#include <iostream>

class Base
{
public:
    virtual void print() const { std::cout << "Base"; }

    friend std::ostream& operator<<(std::ostream& out, const Base& b)
    {
        out << "Base";
        return out;
    }
};

class Derived : public Base
{
public:
    void print() const override { std::cout << "Derived"; }

    friend std::ostream& operator<<(std::ostream& out, const Derived& d)
    {
        out << "Derived";
        return out;
    }
};

int main()
{
    Base b{};
    std::cout << b << '\n';

    Derived d{};
    std::cout << d << '\n';

    return 0;
}

Comme aucune résolution de fonction virtuelle n'est nécessaire ici, ce programme fonctionne comme prévu et affiche :


Base
Derived

Considérez maintenant la fonction main() suivante :

int main()
{
    Derived d{};
    Base& bref{ d };
    std::cout << bref << '\n';

    return 0;
}

Ce programme affiche :


Base

Ce n'est probablement pas ce que nous attendions. Cela vient du fait que notre version de operator<< qui traite les objets Base n'est pas virtuelle : std::cout << bref appelle donc la version de operator<< qui traite les objets Base, et non celle qui traite les objets Derived.

C'est là toute la difficulté.

Peut-on rendre operator<< virtuel ?

Si le problème vient du fait que operator<< n'est pas virtuel, ne peut-on pas simplement le rendre virtuel ?

La réponse courte est non. Il y a plusieurs raisons à cela.

Premièrement, seules les fonctions membres peuvent être virtuelles. C'est logique, puisque seules les classes peuvent hériter d'autres classes, et qu'il est impossible de redéfinir une fonction située en dehors d'une classe (vous pouvez surcharger des fonctions non membres, mais pas les redéfinir). Comme nous implémentons généralement operator<< comme fonction amie (friend), et que les fonctions amies ne sont pas considérées comme des fonctions membres, une version amie de operator<< ne peut pas être virtualisée. (Pour rappel des raisons pour lesquelles nous implémentons operator<< de cette façon, veuillez revoir la leçon 21.5 — Surcharge des opérateurs à l'aide de fonctions membres.)

Deuxièmement, même si nous pouvions virtualiser operator<<, les paramètres de Base::operator<< et de Derived::operator<< diffèrent (la version de Base prendrait un paramètre Base et la version de Derived un paramètre Derived). En conséquence, la version de Derived ne serait pas considérée comme une redéfinition de la version de Base, et ne serait donc pas éligible à la résolution des fonctions virtuelles.

Que doit faire le programmeur ?

Une solution

La réponse, il s'avère, est étonnamment simple.

Tout d'abord, nous déclarons operator<< comme fonction amie dans notre classe de base, comme d'habitude. Mais plutôt que de laisser operator<< déterminer ce qu'il faut afficher, nous lui faisons appeler une fonction membre ordinaire qui peut être virtualisée ! Cette fonction virtuelle se chargera de déterminer ce qu'il faut afficher pour chaque classe.

Dans cette première solution, notre fonction membre virtuelle (que nous appelons identify()) renvoie une std::string, que Base::operator<< affiche :

#include <iostream>

class Base
{
public:
    // Voici notre operator<< surchargé
    friend std::ostream& operator<<(std::ostream& out, const Base& b)
    {
        // Appelle la fonction virtuelle identify() pour obtenir la chaîne à afficher
        out << b.identify();
        return out;
    }

    // La fonction membre identify() renvoie la chaîne à afficher
    // Comme identify() est une fonction membre ordinaire, elle peut être virtualisée
    virtual std::string identify() const
    {
        return "Base";
    }
};

class Derived : public Base
{
public:
    // Voici notre identify() redéfinie pour le cas Derived
    std::string identify() const override
    {
        return "Derived";
    }
};

int main()
{
    Base b{};
    std::cout << b << '\n';

    Derived d{};
    std::cout << d << '\n'; // notez que cela fonctionne même sans operator<< traitant explicitement les objets Derived

    Base& bref{ d };
    std::cout << bref << '\n';

    return 0;
}

Ce programme affiche le résultat attendu :


Base
Derived
Derived

Examinons plus en détail le fonctionnement de ce code.

Dans le cas de Base b, operator<< est appelé avec le paramètre b, qui référence l'objet Base. L'appel de fonction virtuelle b.identify() se résout donc en Base::identify(), qui renvoie « Base » à afficher. Rien de spécial jusqu'ici.

Dans le cas de Derived d, le compilateur cherche d'abord un operator<< acceptant un objet Derived. Il n'en existe pas, car nous n'en avons pas défini. Ensuite, le compilateur cherche un operator<< acceptant un objet Base. Il en existe un : le compilateur effectue donc une conversion implicite ascendante (upcast) de notre objet Derived vers un Base& et appelle la fonction. (Nous aurions pu effectuer cette conversion nous-mêmes, mais le compilateur nous facilite la tâche.) Comme le paramètre b référence un objet Derived, l'appel de fonction virtuelle b.identify() se résout en Derived::identify(), qui renvoie « Derived » à afficher.

Notez que nous n'avons pas besoin de définir un operator<< pour chaque classe dérivée ! La version qui traite les objets Base fonctionne parfaitement pour les objets Base comme pour toute classe dérivée de Base !

Le troisième cas est un mélange des deux premiers. D'abord, le compilateur associe la variable bref à l'operator<< qui prend une référence Base. Comme le paramètre b référence un objet Derived, b.identify() se résout en Derived::identify(), qui renvoie « Derived ».

Problème résolu.

Une solution plus souple

La solution précédente fonctionne très bien, mais présente deux limitations potentielles :

  1. Elle suppose que le résultat souhaité peut être représenté par une seule std::string.
  2. Notre fonction membre identify() n'a pas accès à l'objet flux.

Cette seconde limitation pose problème lorsque nous avons besoin d'un objet flux, par exemple pour afficher la valeur d'une variable membre disposant d'un operator<< surchargé.

Heureusement, il est facile de modifier l'exemple précédent pour résoudre ces deux problèmes. Dans la version précédente, la fonction virtuelle identify() renvoyait une chaîne affichée par Base::operator<<. Dans cette version, nous définissons plutôt une fonction membre virtuelle print() et lui déléguons directement la responsabilité de l'affichage.

Voici un exemple qui illustre cette idée :

#include <iostream>

class Base
{
public:
    // Voici notre operator<< surchargé
    friend std::ostream& operator<<(std::ostream& out, const Base& b)
    {
        // Délègue la responsabilité de l'affichage à la fonction membre virtuelle print()
        return b.print(out);
    }

    // La fonction membre print() effectue l'affichage proprement dit
    // Comme print() est une fonction membre ordinaire, elle peut être virtualisée
    virtual std::ostream& print(std::ostream& out) const
    {
        out << "Base";
        return out;
    }
};

// Une classe ou structure disposant d'un operator<< surchargé
struct Employee
{
    std::string name{};
    int id{};

    friend std::ostream& operator<<(std::ostream& out, const Employee& e)
    {
        out << "Employee(" << e.name << ", " << e.id << ")";
        return out;
    }
};

class Derived : public Base
{
private:
    Employee m_e{}; // Derived possède désormais un membre de type Employee

public:
    Derived(const Employee& e)
        : m_e{ e }
    {
    }

    // Voici notre print() redéfinie pour le cas Derived
    std::ostream& print(std::ostream& out) const override
    {
        out << "Derived: ";

        // Affiche le membre Employee à l'aide de l'objet flux
        out << m_e;

        return out;
    }
};

int main()
{
    Base b{};
    std::cout << b << '\n';

    Derived d{ Employee{"Jim", 4}};
    std::cout << d << '\n'; // notez que cela fonctionne même sans operator<< traitant explicitement les objets Derived

    Base& bref{ d };
    std::cout << bref << '\n';

    return 0;
}

Ce programme affiche :


Base
Derived: Employee(Jim, 4)
Derived: Employee(Jim, 4)

Dans cette version, Base::operator<< n'effectue aucun affichage lui-même. Il se contente d'appeler la fonction membre virtuelle print() et de lui transmettre l'objet flux. La fonction print() utilise alors cet objet flux pour effectuer son propre affichage. Base::print() utilise l'objet flux pour afficher « Base ». Plus intéressant encore, Derived::print() utilise l'objet flux pour afficher à la fois « Derived: » et, en appelant Employee::operator<<, la valeur du membre m_e. Ce dernier point aurait été bien plus difficile à réaliser dans l'exemple précédent !
