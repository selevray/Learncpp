25.5 — Liaison précoce et liaison tardive

Dans cette leçon et la suivante, nous allons examiner de plus près la manière dont les fonctions virtuelles sont implémentées. Bien que ces informations ne soient pas strictement nécessaires pour utiliser efficacement les fonctions virtuelles, elles sont intéressantes. Vous pouvez néanmoins considérer ces deux sections comme une lecture facultative.

Lorsqu'un programme C++ est exécuté, il s'exécute séquentiellement, en commençant par le haut de main(). Lorsqu'un appel de fonction est rencontré, le point d'exécution saute au début de la fonction appelée. Comment le processeur sait-il qu'il doit faire cela ?

Lorsqu'un programme est compilé, le compilateur convertit chaque instruction de votre programme C++ en une ou plusieurs lignes de langage machine. Chaque ligne de langage machine reçoit sa propre adresse séquentielle unique. Il en va de même pour les fonctions : lorsqu'une fonction est rencontrée, elle est convertie en langage machine et reçoit la prochaine adresse disponible. Ainsi, chaque fonction possède une adresse unique.

Liaison (binding) et répartition (dispatching)

Nos programmes contiennent de nombreux noms (identificateurs, mots-clés, etc.). Chaque nom possède un ensemble de propriétés associées : par exemple, si le nom représente une variable, cette variable possède un type, une valeur, une adresse mémoire, etc.

Par exemple, lorsque nous écrivons int x, nous indiquons au compilateur d'associer le nom x au type int. Plus tard, si nous écrivons x = 5, le compilateur peut utiliser cette association pour vérifier le typage de l'affectation et s'assurer qu'elle est valide.

En programmation générale, la liaison (binding) est le processus qui associe des noms à de telles propriétés. La liaison de fonction (ou liaison de méthode, function binding / method binding) est le processus qui détermine quelle définition de fonction est associée à un appel de fonction. Le processus d'invocation effective d'une fonction liée est appelé répartition (dispatching).

En C++, le terme liaison est employé de manière plus informelle (et la répartition est généralement considérée comme faisant partie de la liaison). Nous explorerons ci-dessous l'usage des termes en C++.

Nomenclature

La liaison (binding) est un terme polysémique. Dans d'autres contextes, la liaison peut désigner :

  • La liaison d'une référence à un objet
  • std::bind
  • La liaison de langage (language binding)

Liaison précoce

La plupart des appels de fonction rencontrés par le compilateur seront des appels directs. Un appel direct est une instruction qui appelle directement une fonction. Par exemple :

#include <iostream>

struct Foo
{
    void printValue(int value)
    {
        std::cout << value;
    }
};

void printValue(int value)
{
    std::cout << value;
}

int main()
{
    printValue(5);   // appel direct à printValue(int)

    Foo f{};
    f.printValue(5); // appel direct à Foo::printValue(int)
    return 0;
}

En C++, lorsqu'un appel direct est effectué vers une fonction non membre ou vers une fonction membre non virtuelle, le compilateur peut déterminer quelle définition de fonction doit correspondre à l'appel. On parle parfois de liaison précoce (early binding) ou de liaison statique (static binding), car elle peut être réalisée à la compilation. Le compilateur (ou l'éditeur de liens) peut alors générer des instructions en langage machine qui indiquent au processeur de sauter directement à l'adresse de la fonction.

Pour les lecteurs avancés

Si nous examinons le code assembleur généré pour l'appel printValue(5) (avec clang x86-64), nous voyons quelque chose de ce genre :


        mov     edi, 5           ; copie l'argument 5 dans le registre edi en vue de l'appel de fonction
        call    printValue(int)  ; appelle directement printValue(int)

Vous voyez clairement qu'il s'agit d'un appel direct à printValue(int).

Les appels de fonctions surchargées et de modèles de fonctions peuvent également être résolus à la compilation :

#include <iostream>

template <typename T>
void printValue(T value)
{
    std::cout << value << '\n';
}

void printValue(double value)
{
    std::cout << value << '\n';
}

void printValue(int value)
{
    std::cout << value << '\n';
}

int main()
{
    printValue(5);   // appel direct à printValue(int)
    printValue<>(5); // appel direct à printValue<int>(int)

    return 0;
}

Examinons un programme de calculatrice simple qui utilise la liaison précoce :

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

int subtract(int x, int y)
{
    return x - y;
}

int multiply(int x, int y)
{
    return x * y;
}

int main()
{
    int x{};
    std::cout << "Enter a number: ";
    std::cin >> x;

    int y{};
    std::cout << "Enter another number: ";
    std::cin >> y;

    int op{};
    std::cout << "Enter an operation (0=add, 1=subtract, 2=multiply): ";
    std::cin >> op;

    int result {};
    switch (op)
    {
        // appelle directement la fonction cible par liaison précoce
        case 0: result = add(x, y); break;
        case 1: result = subtract(x, y); break;
        case 2: result = multiply(x, y); break;
        default:
            std::cout << "Invalid operator\n";
            return 1;
    }

    std::cout << "The answer is: " << result << '\n';

    return 0;
}

Comme add(), subtract() et multiply() sont des appels directs à des fonctions non membres, le compilateur associe ces appels à leurs définitions respectives à la compilation.

Notez qu'à cause de l'instruction switch, la fonction effectivement appelée n'est déterminée qu'à l'exécution. Toutefois, il s'agit d'un problème de chemin d'exécution, et non de liaison.

Liaison tardive

Dans certains cas, un appel de fonction ne peut être résolu qu'à l'exécution. En C++, on parle parfois de liaison tardive (late binding) ou, dans le cas de la résolution des fonctions virtuelles, de répartition dynamique (dynamic dispatch).

Note de l'auteur

En terminologie de programmation générale, le terme « liaison tardive » signifie généralement que la fonction appelée ne peut pas être déterminée uniquement à partir d'informations de type statiques, mais doit être résolue à l'aide d'informations de type dynamiques.

En C++, le terme est employé de manière plus lâche pour désigner tout appel de fonction dont la fonction réellement appelée n'est pas connue du compilateur ou de l'éditeur de liens au moment où l'appel est effectué.

En C++, une façon d'obtenir une liaison tardive est d'utiliser des pointeurs de fonction. Pour rappeler brièvement ce qu'est un pointeur de fonction : c'est un type de pointeur qui pointe vers une fonction plutôt que vers une variable. La fonction pointée peut être appelée en utilisant l'opérateur d'appel de fonction () sur le pointeur.

Par exemple, le code suivant appelle la fonction printValue() à travers un pointeur de fonction :

#include <iostream>

void printValue(int value)
{
    std::cout << value << '\n';
}

int main()
{
    auto fcn { printValue }; // crée un pointeur de fonction et le fait pointer vers la fonction printValue
    fcn(5);                  // invoque printValue indirectement via le pointeur de fonction

    return 0;
}

Un appel de fonction via un pointeur de fonction est aussi appelé appel de fonction indirect. Au moment où fcn(5) est effectivement appelé, le compilateur ne sait pas, à la compilation, quelle fonction est appelée. À l'exécution, un appel indirect est effectué vers la fonction se trouvant à l'adresse contenue dans le pointeur de fonction.

Pour les lecteurs avancés

Si nous examinons le code assembleur généré pour l'appel fcn(5) (avec clang x86-64), nous voyons quelque chose de ce genre :


        lea     rax, [rip + printValue(int)] ; détermine l'adresse de printValue et la place dans le registre rax
        mov     qword ptr [rbp - 8], rax     ; copie la valeur du registre rax dans la mémoire associée à la variable fcn

        mov     edi, 5                       ; copie l'argument 5 dans le registre edi en vue de l'appel de fonction
        call    qword ptr [rbp - 8]          ; invoque la fonction dont l'adresse est contenue dans la variable fcn

Vous voyez clairement qu'il s'agit d'un appel de fonction indirect à printValue(int) via son adresse.

Le programme de calculatrice suivant est fonctionnellement identique à l'exemple précédent, à ceci près qu'il utilise un pointeur de fonction au lieu d'un appel direct :

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

int subtract(int x, int y)
{
    return x - y;
}

int multiply(int x, int y)
{
    return x * y;
}

int main()
{
    int x{};
    std::cout << "Enter a number: ";
    std::cin >> x;

    int y{};
    std::cout << "Enter another number: ";
    std::cin >> y;

    int op{};
    std::cout << "Enter an operation (0=add, 1=subtract, 2=multiply): ";
    std::cin >> op;

    using FcnPtr = int (*)(int, int); // alias pour le type de pointeur de fonction peu lisible
    FcnPtr fcn { nullptr }; // crée un objet pointeur de fonction, initialisé à nullptr

    // Fait pointer fcn vers la fonction choisie par l'utilisateur
    switch (op)
    {
        case 0: fcn = add; break;
        case 1: fcn = subtract; break;
        case 2: fcn = multiply; break;
        default:
            std::cout << "Invalid operator\n";
            return 1;
    }

    // Appelle la fonction vers laquelle pointe fcn avec x et y comme paramètres
    std::cout << "The answer is: " << fcn(x, y) << '\n';

    return 0;
}

Dans cet exemple, au lieu d'appeler directement add(), subtract() ou multiply(), nous faisons pointer fcn vers la fonction que nous souhaitons appeler, puis nous appelons la fonction à travers le pointeur.

Le compilateur ne peut pas utiliser la liaison précoce pour résoudre l'appel fcn(x, y), car il ne peut pas savoir à la compilation vers quelle fonction fcn pointera !

La liaison tardive est légèrement moins efficace, car elle implique un niveau d'indirection supplémentaire. Avec la liaison précoce, le processeur peut sauter directement à l'adresse de la fonction. Avec la liaison tardive, le programme doit lire l'adresse contenue dans le pointeur, puis sauter à cette adresse. Cette étape supplémentaire rend l'exécution un peu plus lente. En revanche, l'avantage de la liaison tardive est qu'elle est plus souple que la liaison précoce, car les décisions quant à la fonction à appeler n'ont pas besoin d'être prises avant l'exécution.

Dans la prochaine leçon, nous verrons comment la liaison tardive est utilisée pour implémenter les fonctions virtuelles.
