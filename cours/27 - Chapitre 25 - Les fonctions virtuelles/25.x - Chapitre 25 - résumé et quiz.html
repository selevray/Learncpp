25.x — Chapitre 25 : résumé et quiz

Notre parcours à travers l'héritage et les fonctions virtuelles de C++ touche ainsi à sa fin. Ne vous inquiétez pas, cher lecteur : il reste de nombreux autres domaines de C++ à explorer.

Résumé du chapitre

C++ vous permet de faire pointer des pointeurs et référencer des références de classe de base vers un objet dérivé. C'est utile lorsque l'on veut écrire une fonction ou un tableau capable de travailler avec n'importe quel objet dérivé d'une classe de base.

Sans fonctions virtuelles, les pointeurs et références de classe de base vers une classe dérivée n'ont accès qu'aux membres variables et aux versions des fonctions de la classe de base.

Une fonction virtuelle est un type particulier de fonction qui se résout en la version la plus dérivée de la fonction (appelée redéfinition, ou override) qui existe entre la classe de base et la classe dérivée. Pour être considérée comme une redéfinition, la fonction de la classe dérivée doit avoir la même signature et le même type de retour que la fonction virtuelle de la classe de base. La seule exception concerne les types de retour covariants, qui permettent à une redéfinition de renvoyer un pointeur ou une référence vers une classe dérivée si la fonction de la classe de base renvoie un pointeur ou une référence vers la classe de base.

Une fonction destinée à être une redéfinition doit utiliser le spécificateur override pour s'assurer qu'elle redéfinit effectivement une fonction.

Le spécificateur final peut être utilisé pour empêcher la redéfinition d'une fonction ou l'héritage d'une classe.

Si vous comptez utiliser l'héritage, vous devriez rendre votre destructeur virtuel, afin que le bon destructeur soit appelé lorsqu'un pointeur vers la classe de base est supprimé.

Vous pouvez ignorer la résolution virtuelle en utilisant l'opérateur de résolution de portée pour spécifier directement la version de la fonction de la classe que vous voulez : par exemple base.Base::getName().

La liaison précoce (early binding) se produit lorsque le compilateur rencontre un appel direct de fonction. Le compilateur ou l'éditeur de liens (linker) peut résoudre directement ces appels. La liaison tardive (late binding) se produit lorsqu'un pointeur de fonction est appelé. Dans ces cas, la fonction qui sera appelée ne peut pas être déterminée avant l'exécution. Les fonctions virtuelles utilisent la liaison tardive et une table virtuelle (virtual table) pour déterminer la version de la fonction à appeler.

Utiliser des fonctions virtuelles a un coût : leur appel prend plus de temps, et la nécessité de la table virtuelle augmente la taille de chaque objet contenant une fonction virtuelle d'un pointeur.

Une fonction virtuelle peut être rendue virtuelle pure (pure virtual) ou abstraite en ajoutant « = 0 » à la fin du prototype de la fonction virtuelle. Une classe contenant une fonction virtuelle pure est appelée classe abstraite, et ne peut pas être instanciée. Une classe qui hérite de fonctions virtuelles pures doit les définir concrètement, sans quoi elle sera également considérée comme abstraite. Les fonctions virtuelles pures peuvent avoir un corps, mais elles restent abstraites.

Une classe interface est une classe sans membre variable et uniquement composée de fonctions virtuelles pures. Leur nom commence souvent par un I majuscule.

Une classe de base virtuelle (virtual base class) est une classe de base qui n'est incluse qu'une seule fois, quel que soit le nombre de fois où elle est héritée par un objet.

Lorsqu'un objet de classe dérivée est affecté à un objet de classe de base, la classe de base ne reçoit qu'une copie de la partie de base de la classe dérivée. C'est ce qu'on appelle le découpage (object slicing).

Le transtypage dynamique (dynamic cast) peut être utilisé pour convertir un pointeur vers un objet de classe de base en un pointeur vers un objet de classe dérivée. C'est ce qu'on appelle le downcasting. Une conversion qui échoue renvoie un pointeur nul.

La manière la plus simple de surcharger operator<< pour des classes héritées consiste à écrire un operator<< surchargé pour la classe la plus haute de la hiérarchie, puis à appeler une fonction membre virtuelle pour effectuer l'affichage.

Quiz

  1. Chacun des programmes suivants contient une sorte de défaut. Examinez chaque programme (visuellement, sans le compiler) et déterminez ce qui ne va pas. La sortie de chaque programme est censée être « Derived ».

1a)

#include <iostream>

class Base
{
protected:
    int m_value;

public:
    Base(int value)
        : m_value{ value }
    {
    }

    const char* getName() const { return "Base"; }
};

class Derived : public Base
{
public:
    Derived(int value)
        : Base{ value }
    {
    }

    const char* getName() const { return "Derived"; }
};

int main()
{
    Derived d{ 5 };
    Base& b{ d };
    std::cout << b.getName() << '\n';

    return 0;
}
Solution

Base::getName() n'a pas été rendue virtuelle, donc b.getName() ne se résout pas en Derived::getName().

2a) Créez une classe abstraite nommée Shape. Cette classe doit comporter trois fonctions : une fonction d'affichage virtuelle pure qui prend et renvoie un std::ostream&, un operator<< surchargé et un destructeur virtuel vide.

Solution 
class Shape
{
public:
    virtual std::ostream& print(std::ostream& out) const = 0;

    friend std::ostream& operator<<(std::ostream& out, const Shape& p)
    {
        return p.print(out);

    virtual ~Shape() = default;

#include <vector>
#include <iostream>
#include <algorithm> // for std::max

class Point
{
private:
    int m_x{};
    int m_y{};

public:
    Point(int x, int y)
        : m_x{ x }, m_y{ y }
    {

    }

    friend std::ostream& operator<<(std::ostream& out, const Point& p)
    {
        return out << "Point(" << p.m_x << ", " << p.m_y << ')';
    }
};

class Shape
{
public:
    virtual std::ostream& print(std::ostream& out) const = 0;

    friend std::ostream& operator<<(std::ostream& out, const Shape& p)
    {
        return p.print(out);
    }
    virtual ~Shape() = default;
};

class Triangle : public Shape
{
private:
    Point m_p1;
    Point m_p2;
    Point m_p3;

public:
    Triangle(const Point& p1, const Point& p2, const Point& p3)
        : m_p1{ p1 }, m_p2{ p2 }, m_p3{ p3 }
    {
    }

    std::ostream& print(std::ostream& out) const override
    {
        return out << "Triangle(" << m_p1 << ", " << m_p2 << ", " << m_p3 << ')';
    }
};


class Circle : public Shape
{
private:
    Point m_center;
    int m_radius{};

public:
    Circle(const Point& center, int radius)
        : m_center{ center }, m_radius{ radius }
    {
    }

    std::ostream& print(std::ostream& out) const override
    {
        out << "Circle(" << m_center << ", radius " << m_radius << ')';
        return out;
    }

    int getRadius() const { return m_radius; }
};

// h/t to reader Olivier for this updated solution
// assumes radiuses are >= 0
int getLargestRadius(const std::vector<Shape*>& v)
{
    int largestRadius{ 0 };

    // Loop through all the shapes in the vector
    for (const auto* element : v)
    {
        // // Ensure the dynamic cast succeeds by checking for a null pointer result
        if (auto* c { dynamic_cast<const Circle*>(element) })
        {
            largestRadius = std::max(largestRadius, c->getRadius());
        }
    }

    return largestRadius;
}
int main()
{
    std::vector<Shape*> v{
          new Circle{Point{ 1, 2 }, 7},
          new Triangle{Point{ 1, 2 }, Point{ 3, 4 }, Point{ 5, 6 }},
          new Circle{Point{ 7, 8 }, 3}
    };

    for (const auto* element : v) // element will be a Shape*
        std::cout << *element << '\n';

    std::cout << "The largest radius is: " << getLargestRadius(v) << '\n';

    for (const auto* element : v)
        delete element;

    return 0;
}

int getLargestRadius(const std::vector<std::unique_ptr<Shape>>& v)
{
    int largestRadius{ 0 };

    // Loop through all the shapes in the vector
    for (const auto& element : v)
