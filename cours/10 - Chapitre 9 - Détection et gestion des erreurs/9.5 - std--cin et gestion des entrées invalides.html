9.5 — std::cin et gestion des entrées invalides

La plupart des programmes qui disposent d'une interface utilisateur doivent traiter les saisies de l'utilisateur. Dans les programmes que vous avez écrits jusqu'ici, vous avez utilisé std::cin pour demander à l'utilisateur de saisir du texte. Comme la saisie de texte est très libre (l'utilisateur peut taper n'importe quoi), il est très facile qu'il saisisse une entrée inattendue.

Lorsque vous écrivez un programme, vous devez toujours considérer la manière dont les utilisateurs pourraient le mal utiliser, que ce soit involontairement ou non. Un programme bien écrit anticipe ces mauvais usages et soit gère ces cas avec élégance, soit les empêche de se produire (si c'est possible). On dit qu'un programme qui gère bien les cas d'erreur est robuste.

Dans cette leçon, nous examinerons spécifiquement les moyens par lesquels l'utilisateur peut saisir une entrée textuelle invalide via std::cin, et nous vous montrerons différentes façons de gérer ces cas.

Avant de discuter des échecs possibles de std::cin et de operator>>, rappelons leur fonctionnement. Nous avons vu cette matière dans la leçon 1.5 -- Introduction à iostream : cout, cin et endl.

Voici une vue simplifiée du fonctionnement de operator>> pour une saisie :

  1. Tout d'abord, les espaces de début (espaces, tabulations et retours à la ligne au début du tampon) sont supprimés du tampon d'entrée. Cela élimine tout caractère de retour à la ligne non extrait restant d'une saisie précédente.
  2. Si le tampon d'entrée est maintenant vide, operator>> attend que l'utilisateur saisisse davantage de données. Les espaces de début sont à nouveau supprimés.
  3. operator>> extrait ensuite autant de caractères consécutifs qu'il le peut, jusqu'à rencontrer soit un caractère de retour à la ligne (qui marque la fin de la ligne de saisie), soit un caractère qui n'est pas valide pour la variable à laquelle on affecte la valeur.

Le résultat de l'extraction est le suivant :

  • Si des caractères ont été extraits à l'étape 3 ci-dessus, l'extraction réussit. Les caractères extraits sont convertis en une valeur qui est ensuite affectée à la variable.
  • Si aucun caractère n'a pu être extrait à l'étape 3 ci-dessus, l'extraction échoue. L'objet vers lequel on extrayait reçoit la valeur 0 (depuis C++11), et toutes les extractions suivantes échoueront immédiatement (jusqu'à ce que std::cin soit réinitialisé).

Valider la saisie

Le processus qui consiste à vérifier si la saisie de l'utilisateur correspond à ce que le programme attend s'appelle validation de la saisie (input validation).

Il existe trois façons fondamentales de valider une saisie :

Au fil de la frappe (en ligne) :

  1. Empêcher l'utilisateur de taper une saisie invalide dès le départ.

Après la saisie (a posteriori) :

  1. Laisser l'utilisateur saisir ce qu'il veut dans une chaîne, puis vérifier si la chaîne est correcte et, si c'est le cas, convertir la chaîne dans le format final de la variable.
  2. Laisser l'utilisateur saisir ce qu'il veut, laisser std::cin et operator>> tenter d'extraire la valeur, puis gérer les cas d'erreur.

Certaines interfaces graphiques et certaines interfaces textuelles avancées permettent de valider la saisie au fur et à mesure qu'elle est tapée (caractère par caractère). En général, le programmeur fournit une fonction de validation qui accepte la saisie déjà effectuée par l'utilisateur et renvoie true si cette saisie est valide, et false sinon. Cette fonction est appelée à chaque frappe de touche. Si la fonction de validation renvoie true, la touche que l'utilisateur vient d'appuyer est acceptée. Si elle renvoie false, le caractère tapé est rejeté (et n'apparaît pas à l'écran). Avec cette méthode, vous pouvez garantir que toute saisie de l'utilisateur est valide, car les frappes invalides sont détectées et rejetées immédiatement. Malheureusement, std::cin ne prend pas en charge ce style de validation.

Comme les chaînes n'imposent aucune restriction sur les caractères saisis, l'extraction réussit toujours (mais gardez à l'esprit que std::cin s'arrête au premier caractère d'espacement qui n'est pas en début de saisie). Une fois qu'une chaîne est saisie, le programme peut ensuite l'analyser pour savoir si elle est valide ou non. Cependant, analyser des chaînes et convertir une saisie textuelle vers d'autres types (par exemple des nombres) peut être délicat, c'est pourquoi on ne le fait que dans de rares cas.

Le plus souvent, nous laissons std::cin et l'opérateur d'extraction faire le gros du travail. Avec cette méthode, nous laissons l'utilisateur saisir ce qu'il veut, nous demandons à std::cin et operator>> d'extraire la valeur, et nous gérons les conséquences en cas d'échec. C'est la méthode la plus simple, et celle dont nous parlerons davantage ci-dessous.

Un exemple de programme

Considérez le programme de calculatrice suivant, qui ne gère aucune erreur :

#include <iostream>

double getDouble()
{
    std::cout << "Enter a decimal number: ";
    double x{};
    std::cin >> x;
    return x;
}

char getOperator()
{
    std::cout << "Enter one of the following: +, -, *, or /: ";
    char op{};
    std::cin >> op;
    return op;
}

void printResult(double x, char operation, double y)
{
    std::cout << x << ' ' << operation << ' ' << y << " is ";

    switch (operation)
    {
    case '+':
        std::cout << x + y << '\n';
        return;
    case '-':
        std::cout << x - y << '\n';
        return;
    case '*':
        std::cout << x * y << '\n';
        return;
    case '/':
        std::cout << x / y << '\n';
        return;
    }
}

int main()
{
    double x{ getDouble() };
    char operation{ getOperator() };
    double y{ getDouble() };

    printResult(x, operation, y);

    return 0;
}

Ce programme simple demande à l'utilisateur de saisir deux nombres et un opérateur mathématique.


Enter a decimal number: 5
Enter one of the following: +, -, *, or /: *
Enter a decimal number: 7
5 * 7 is 35

Examinons maintenant les endroits où une saisie invalide pourrait faire échouer ce programme.

Tout d'abord, nous demandons à l'utilisateur de saisir des nombres. Que se passe-t-il s'il saisit autre chose qu'un nombre (par exemple « q ») ? Dans ce cas, l'extraction échoue.

Ensuite, nous demandons à l'utilisateur de saisir l'un des quatre symboles possibles. Que se passe-t-il s'il saisit un caractère différent de ceux que nous attendons ? Nous pourrons extraire la saisie, mais nous ne gérons pas actuellement ce qui se passe ensuite.

Enfin, que se passe-t-il si nous demandons à l'utilisateur de saisir un symbole et qu'il saisit une chaîne comme "*q hello" ? Bien que nous puissions extraire le caractère '*' dont nous avons besoin, il reste de la saisie dans le tampon, ce qui pourrait poser des problèmes par la suite.

Types de saisies textuelles invalides

On peut généralement classer les erreurs de saisie textuelle en quatre types :

  • L'extraction de la saisie réussit, mais la saisie n'a aucun sens pour le programme (par exemple, saisir « k » comme opérateur mathématique).
  • L'extraction de la saisie réussit, mais l'utilisateur saisit des données supplémentaires (par exemple, saisir « *q hello » comme opérateur mathématique).
  • L'extraction de la saisie échoue (par exemple, saisir « q » dans une saisie numérique).
  • L'extraction de la saisie réussit, mais l'utilisateur provoque un dépassement de capacité d'une valeur numérique.

Ainsi, pour rendre nos programmes robustes, chaque fois que nous demandons une saisie à l'utilisateur, nous devrions idéalement déterminer si chacun des cas ci-dessus peut se produire et, si c'est le cas, écrire du code pour les gérer.

Examinons chacun de ces cas et la manière de les gérer avec std::cin.

Cas d'erreur 1 : l'extraction réussit mais la saisie n'a pas de sens

C'est le cas le plus simple. Considérez l'exécution suivante du programme ci-dessus :


Enter a decimal number: 5
Enter one of the following: +, -, *, or /: k
Enter a decimal number: 7

Ici, nous avons demandé à l'utilisateur de saisir l'un des quatre symboles, mais il a saisi « k ». « k » est un caractère valide, donc std::cin l'extrait sans problème dans la variable op, et cette valeur est renvoyée à main. Mais notre programme ne s'attendait pas à cela, et il ne gère donc pas correctement ce cas. Par conséquent, il affiche :


5 k 7 is

La solution est simple : effectuer une validation de la saisie. Cela consiste généralement en trois étapes :

  1. Vérifier si la saisie de l'utilisateur correspond à ce que vous attendiez.
  2. Si oui, renvoyer la valeur à l'appelant.
  3. Si non, informer l'utilisateur que quelque chose s'est mal passé et lui demander de réessayer.

Voici une version mise à jour de la fonction getOperator() qui effectue une validation de la saisie.

char getOperator()
{
    while (true) // Loop until user enters a valid input
    {
        std::cout << "Enter one of the following: +, -, *, or /: ";
        char operation{};
        std::cin >> operation;

        // Check whether the user entered meaningful input
        switch (operation)
        {
        case '+':
        case '-':
        case '*':
        case '/':
            return operation; // return it to the caller
        default: // otherwise tell the user what went wrong
            std::cout << "Oops, that input is invalid.  Please try again.\n";
        }
    } // and try again
}

Comme vous pouvez le voir, nous utilisons une boucle while pour boucler en continu jusqu'à ce que l'utilisateur fournisse une saisie valide. S'il ne le fait pas, nous lui demandons de réessayer, jusqu'à ce qu'il nous donne une saisie valide, qu'il arrête le programme, ou qu'il détruise son ordinateur.

Cas d'erreur 2 : l'extraction réussit mais avec des données superflues

Considérez l'exécution suivante du programme ci-dessus :


Enter a decimal number: 5*7

Que pensez-vous qu'il se passe ensuite ?


Enter a decimal number: 5*7
Enter one of the following: +, -, *, or /: Enter a decimal number: 5 * 7 is 35

Le programme affiche la bonne réponse, mais la mise en forme est complètement désordonnée. Examinons de plus près la raison.

Lorsque l'utilisateur saisit 5*7, cette saisie est placée dans le tampon. Ensuite, operator>> extrait le 5 vers la variable x, laissant *7\n dans le tampon. Ensuite, le programme affiche « Enter one of the following: +, -, *, or /: ». Cependant, lors de l'appel de l'opérateur d'extraction, il voit *7\n en attente dans le tampon, il utilise donc cette valeur au lieu de demander davantage de saisie à l'utilisateur. Par conséquent, il extrait le caractère « * », laissant 7\n dans le tampon.

Après avoir demandé à l'utilisateur de saisir un autre nombre décimal, le 7 présent dans le tampon est extrait sans que l'utilisateur soit sollicité. Comme l'utilisateur n'a jamais eu l'occasion de saisir des données supplémentaires et d'appuyer sur Entrée (ce qui produit un retour à la ligne), les invites s'affichent les unes à la suite des autres sur la même ligne.

Bien que le programme ci-dessus fonctionne, son exécution est désordonnée. Il serait préférable que les caractères superflus saisis soient simplement ignorés. Heureusement, il est facile d'ignorer des caractères :

std::cin.ignore(100, '\n');  // clear up to 100 characters out of the buffer, or until a '\n' character is removed

Cet appel supprime jusqu'à 100 caractères, mais si l'utilisateur a saisi plus de 100 caractères, nous obtiendrons à nouveau un affichage désordonné. Pour ignorer tous les caractères jusqu'au prochain « \n », nous pouvons passer std::numeric_limits<std::streamsize>::max() à std::cin.ignore(). std::numeric_limits<std::streamsize>::max() renvoie la plus grande valeur pouvant être stockée dans une variable de type std::streamsize. Passer cette valeur à std::cin.ignore() désactive la vérification du nombre de caractères.

Pour ignorer tout jusqu'au caractère « \n » suivant inclus, nous appelons

std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');

Comme cette ligne est assez longue pour ce qu'elle fait, il est pratique de l'encapsuler dans une fonction que l'on peut appeler à la place de std::cin.ignore().

#include <limits> // for std::numeric_limits

void ignoreLine()
{
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
}

Comme le dernier caractère saisi par l'utilisateur est généralement un « \n », nous pouvons demander à std::cin d'ignorer les caractères du tampon jusqu'à trouver un caractère de retour à la ligne (qui est également supprimé).

Mettons à jour notre fonction getDouble() pour ignorer toute saisie superflue :

double getDouble()
{
    std::cout << "Enter a decimal number: ";
    double x{};
    std::cin >> x;

    ignoreLine();
    return x;
}

Désormais, notre programme fonctionnera comme prévu, même si nous saisissons 5*7 pour la première entrée : le 5 sera extrait, et les autres caractères seront supprimés du tampon d'entrée. Comme le tampon d'entrée est maintenant vide, l'utilisateur sera correctement sollicité lors de la prochaine opération d'extraction !

Astuce

Dans certains cas, il peut être préférable de traiter une saisie superflue comme un échec (plutôt que de simplement l'ignorer). On peut alors demander à l'utilisateur de ressaisir sa valeur.

Voici une variante de getDouble() qui demande à l'utilisateur de ressaisir sa valeur s'il a saisi des données superflues :

// returns true if std::cin has unextracted input on the current line, false otherwise
bool hasUnextractedInput()
{
    return !std::cin.eof() && std::cin.peek() != '\n';
}

double getDouble()
{
    while (true) // Loop until user enters a valid input
    {
        std::cout << "Enter a decimal number: ";
        double x{};
        std::cin >> x;

        // NOTE: YOU SHOULD CHECK FOR A FAILED EXTRACTION HERE (see section below)

        // If there is extraneous input, treat as failure case
        if (hasUnextractedInput())
        {
            ignoreLine(); // remove extraneous input
            continue;
        }

        return x;
    }
}

Le fragment ci-dessus utilise deux fonctions que nous n'avons pas encore vues :

  • La fonction std::cin.eof() renvoie true si la dernière opération de saisie (ici, l'extraction vers x) a atteint la fin du flux d'entrée.
  • La fonction std::cin.peek() permet de regarder le caractère suivant du flux d'entrée sans l'extraire.

Voici comment fonctionne cette fonction. Après que la saisie de l'utilisateur a été extraite vers x, il peut rester ou non des caractères non extraits dans std::cin.

Tout d'abord, nous appelons std::cin.eof() pour vérifier si l'extraction vers x a atteint la fin du flux d'entrée. Si c'est le cas, cela signifie que tous les caractères ont été extraits, ce qui constitue un succès.

Sinon, il reste forcément des caractères dans std::cin en attente d'extraction. Dans ce cas, nous appelons std::cin.peek() pour regarder le prochain caractère en attente sans l'extraire réellement. Si ce caractère suivant est un '\n', cela signifie que nous avons déjà extrait tous les caractères de cette ligne de saisie vers x. C'est également un succès.

En revanche, si le caractère suivant est différent de '\n', l'utilisateur a forcément saisi des données superflues qui n'ont pas été extraites vers x. C'est notre cas d'échec. Nous supprimons toutes ces données superflues, et continue nous renvoie au début de la boucle pour réessayer.

Si vous avez du mal à comprendre comment l'expression booléenne de hasUnextractedInput() s'évalue, ce n'est pas surprenant : les expressions booléennes avec des négations peuvent être difficiles à lire. Dans ce cas, la loi de De Morgan peut aider. Une expression équivalente est return !(std::cin.eof() || std::cin.peek() == '\n');. Cela rend plus clair le fait que nous testons la fin de fichier (EOF) ou un retour à la ligne. Si l'un des deux est vrai, alors nous avons extrait toute la saisie. Nous appliquons ensuite operator! pour savoir si nous n'avons pas extrait toute la saisie, c'est-à-dire s'il reste des données non extraites.

Cas d'erreur 3 : l'extraction échoue

L'extraction échoue lorsqu'aucune saisie ne peut être extraite vers la variable indiquée.

Considérez maintenant l'exécution suivante de notre programme de calculatrice mis à jour :


Enter a decimal number: a

Vous ne serez pas surpris que le programme ne fonctionne pas comme prévu, mais la manière dont il échoue est intéressante :


Enter a decimal number: a
Enter one of the following: +, -, *, or /: Oops, that input is invalid.  Please try again.
Enter one of the following: +, -, *, or /: Oops, that input is invalid.  Please try again.
Enter one of the following: +, -, *, or /: Oops, that input is invalid.  Please try again.

et cette dernière ligne continue de s'afficher jusqu'à la fermeture du programme.

Cela ressemble beaucoup au cas des données superflues, mais c'est un peu différent. Examinons-le de plus près.

Lorsque l'utilisateur saisit « a », ce caractère est placé dans le tampon. Ensuite, operator>> tente d'extraire « a » vers la variable x, qui est de type double. Comme « a » ne peut pas être converti en double, operator>> ne peut pas effectuer l'extraction. À ce moment, deux choses se produisent : « a » reste dans le tampon, et std::cin passe en « mode échec ».

Une fois en « mode échec », les demandes d'extraction suivantes échouent silencieusement. Ainsi, dans notre programme de calculatrice, les invites s'affichent toujours, mais toutes les demandes d'extraction ultérieures sont ignorées. Cela signifie qu'au lieu d'attendre que nous saisissions une opération, l'invite de saisie est sautée, et nous restons bloqués dans une boucle infinie, car il n'y a aucun moyen d'atteindre l'un des cas valides.

Pour remettre std::cin en état de fonctionnement normal, nous devons généralement faire trois choses :

  • Détecter qu'une extraction précédente a échoué.
  • Remettre std::cin en mode de fonctionnement normal.
  • Supprimer la saisie qui a provoqué l'échec (afin que la demande d'extraction suivante n'échoue pas de la même manière).

Voici ce que cela donne :

if (std::cin.fail()) // If the previous extraction failed
{
    // Let's handle the failure
    std::cin.clear(); // Put us back in 'normal' operation mode
    ignoreLine();     // And remove the bad input
}

Comme std::cin dispose d'une conversion booléenne indiquant si la dernière saisie a réussi, il est plus idiomatique d'écrire le code ci-dessus de la manière suivante :

if (!std::cin) // If the previous extraction failed
{
    // Let's handle the failure
    std::cin.clear(); // Put us back in 'normal' operation mode
    ignoreLine();     // And remove the bad input
}

Point clé

Une fois qu'une extraction a échoué, les demandes d'extraction suivantes (y compris les appels à ignore()) échouent silencieusement jusqu'à l'appel de la fonction clear(). Ainsi, après avoir détecté une extraction échouée, appeler clear() est généralement la première chose à faire.

Intégrons cela dans notre fonction getDouble() :

double getDouble()
{
    while (true) // Loop until user enters a valid input
    {
        std::cout << "Enter a decimal number: ";
        double x{};
        std::cin >> x;

        if (!std::cin) // If the previous extraction failed
        {
            // Let's handle the failure
            std::cin.clear(); // Put us back in 'normal' operation mode
            ignoreLine();     // And remove the bad input
            continue;
        }

        // Our extraction succeeded
        ignoreLine(); // Ignore any additional input on this line
        return x;     // Return the value we extracted
    }
}

Pour les types fondamentaux, une extraction échouée à cause d'une saisie invalide affecte à la variable la valeur 0 (ou la valeur que 0 donne une fois convertie dans le type de la variable).

Il n'y a aucun problème à appeler clear() même si l'extraction n'a pas échoué : cela ne fait rien. Dans les cas où nous allons appeler ignoreLine() dans tous les cas, qu'il y ait eu réussite ou échec, nous pouvons combiner les deux situations :

double getDouble()
{
    while (true) // Loop until user enters a valid input
    {
        std::cout << "Enter a decimal number: ";
        double x{};
        std::cin >> x;

        bool success { std::cin }; // Remember whether we had a successful extraction
        std::cin.clear();          // Put us back in 'normal' operation mode (in case we failed)
        ignoreLine();              // Ignore any additional input on this line (regardless)

        if (success)               // If we actually extracted a value
            return x;              // Return it (otherwise, we go back to top of loop)
    }
}

Vérifier la fin de fichier (EOF)

Il existe encore un autre cas à traiter.

La fin de fichier (EOF, pour end-of-file) est un état d'erreur particulier qui signifie « Plus aucune donnée disponible ». Il est généralement généré après qu'une opération de saisie a échoué faute de données disponibles. Par exemple, si vous lisez le contenu d'un fichier sur le disque et que vous tentez de lire davantage de données après avoir déjà atteint la fin du fichier, une EOF sera générée pour indiquer qu'il n'y a plus de données. Dans le cas d'une lecture de fichier, ce n'est pas un problème : il suffit de fermer le fichier et de continuer.

Considérons maintenant std::cin. Si nous essayons d'extraire une saisie de std::cin et qu'il n'y en a aucune, par conception, il ne générera pas d'EOF : il attendra simplement que l'utilisateur saisisse davantage de données. Cependant, std::cin peut générer une EOF dans certains cas, le plus souvent lorsque l'utilisateur appuie sur une combinaison de touches spéciale propre à son système d'exploitation. Unix (via ctrl-D) et Windows (via ctrl-Z suivi de ENTRÉE) prennent tous deux en charge la saisie d'un « caractère de fin de fichier » au clavier.

Point clé

En C++, EOF est un état d'erreur, pas un caractère. Les différents systèmes d'exploitation disposent de combinaisons de caractères spéciales qui sont traitées comme une « demande de fin de fichier » saisie par l'utilisateur. On les appelle parfois « caractères EOF ».

Lorsque des données sont extraites vers std::cin et que l'utilisateur saisit un caractère EOF, le comportement dépend du système d'exploitation. Voici ce qui se produit généralement :

  • Si l'EOF n'est pas le premier caractère de la saisie : toute la saisie précédant l'EOF sera vidée, et le caractère EOF est ignoré. Sous Windows, tous les caractères saisis après l'EOF sont ignorés, à l'exception du retour à la ligne.
  • Si l'EOF est le premier caractère saisi : l'erreur EOF est activée. Le flux d'entrée peut (ou non) être déconnecté.

Bien que std::cin.clear() efface une erreur EOF, si le flux d'entrée est déconnecté, la prochaine demande de saisie générera une autre erreur EOF. C'est problématique lorsque notre saisie se trouve dans une boucle while(true), car nous risquons de rester bloqués dans une boucle infinie d'erreurs EOF.

Comme l'intention d'un caractère EOF saisi au clavier est de mettre fin au flux d'entrée, le mieux est de détecter l'EOF (via std::cin.eof()) puis de terminer le programme.

Comme la remise à zéro d'un flux d'entrée en échec est une opération que nous serons amenés à vérifier très souvent, c'est un bon candidat pour une fonction réutilisable :

#include <limits> // for std::numeric_limits

void ignoreLine()
{
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
}

// returns true if extraction failed, false otherwise
bool clearFailedExtraction()
{
    // Check for failed extraction
    if (!std::cin) // If the previous extraction failed
    {
        if (std::cin.eof()) // If the user entered an EOF
        {
            std::exit(0); // Shut down the program now
        }

        // Let's handle the failure
        std::cin.clear(); // Put us back in 'normal' operation mode
        ignoreLine();     // And remove the bad input

        return true;
    }

    return false;
}

Cas d'erreur 4 : l'extraction réussit mais l'utilisateur provoque un dépassement de capacité d'une valeur numérique

Considérez l'exemple simple suivant :

#include <cstdint>
#include <iostream>

int main()
{
    std::int16_t x{}; // x is 16 bits, holds from -32768 to 32767
    std::cout << "Enter a number between -32768 and 32767: ";
    std::cin >> x;

    std::int16_t y{}; // y is 16 bits, holds from -32768 to 32767
    std::cout << "Enter another number between -32768 and 32767: ";
    std::cin >> y;

    std::cout << "The sum is: " << x + y << '\n';
    return 0;
}

Que se passe-t-il si l'utilisateur saisit un nombre trop grand (par exemple 40000) ?


Enter a number between -32768 and 32767: 40000
Enter another number between -32768 and 32767: The sum is: 32767

Dans le cas ci-dessus, std::cin passe immédiatement en « mode échec », mais il affecte aussi à la variable la valeur valide la plus proche. Lorsque la valeur saisie est supérieure à la plus grande valeur possible pour le type, la valeur valide la plus proche est la plus grande valeur possible pour ce type. Par conséquent, x reçoit la valeur affectée 32767. Les saisies suivantes sont sautées, laissant y avec la valeur initiale 0. Nous pouvons gérer ce type d'erreur de la même manière qu'une extraction échouée.

Tout assembler

Voici notre calculatrice d'exemple, mise à jour avec quelques vérifications d'erreurs supplémentaires :

#include <cstdlib> // for std::exit
#include <iostream>
#include <limits> // for std::numeric_limits

void ignoreLine()
{
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
}

// returns true if extraction failed, false otherwise
bool clearFailedExtraction()
{
    // Check for failed extraction
    if (!std::cin) // If the previous extraction failed
    {
        if (std::cin.eof()) // If the stream was closed
        {
            std::exit(0); // Shut down the program now
        }

        // Let's handle the failure
        std::cin.clear(); // Put us back in 'normal' operation mode
        ignoreLine();     // And remove the bad input

        return true;
    }

    return false;
}

double getDouble()
{
    while (true) // Loop until user enters a valid input
    {
        std::cout << "Enter a decimal number: ";
        double x{};
        std::cin >> x;

        if (clearFailedExtraction())
        {
            std::cout << "Oops, that input is invalid.  Please try again.\n";
            continue;
        }

        ignoreLine(); // Remove any extraneous input
        return x;     // Return the value we extracted
    }
}

char getOperator()
{
    while (true) // Loop until user enters a valid input
    {
        std::cout << "Enter one of the following: +, -, *, or /: ";
        char operation{};
        std::cin >> operation;

        if (!clearFailedExtraction()) // we'll handle error messaging if extraction failed below
             ignoreLine(); // remove any extraneous input (only if extraction succeded)

        // Check whether the user entered meaningful input
        switch (operation)
        {
        case '+':
        case '-':
        case '*':
        case '/':
            return operation; // Return the entered char to the caller
        default: // Otherwise tell the user what went wrong
            std::cout << "Oops, that input is invalid.  Please try again.\n";
        }
    }
}

void printResult(double x, char operation, double y)
{
    std::cout << x << ' ' << operation << ' ' << y << " is ";

    switch (operation)
    {
    case '+':
        std::cout << x + y << '\n';
        return;
    case '-':
        std::cout << x - y << '\n';
        return;
    case '*':
        std::cout << x * y << '\n';
        return;
    case '/':
        if (y == 0.0)
            break;

        std::cout << x / y << '\n';
        return;
    }

    std::cout << "???";  // Being robust means handling unexpected parameters as well, even though getOperator() guarantees operation is valid in this particular program
}

int main()
{
    double x{ getDouble() };
    char operation{ getOperator() };
    double y{ getDouble() };

    // Handle division by 0
    while (operation == '/' && y == 0.0) 
    {
        std::cout << "The denominator cannot be zero.  Try again.\n";
        y = getDouble();
    }

    printResult(x, operation, y);

    return 0;
}

Conclusion

Lorsque vous écrivez vos programmes, réfléchissez à la manière dont les utilisateurs pourraient mal utiliser votre programme, en particulier pour la saisie de texte. Pour chaque point de saisie textuelle, demandez-vous :

  • L'extraction pourrait-elle échouer ?
  • L'utilisateur pourrait-il saisir plus de données que prévu ?
  • L'utilisateur pourrait-il saisir des données dénuées de sens ?
  • L'utilisateur pourrait-il provoquer un dépassement de capacité d'une saisie ?

Vous pouvez utiliser des instructions if et la logique booléenne pour vérifier qu'une saisie est attendue et qu'elle a du sens.

Le code suivant supprime toute saisie superflue :

#include <limits> // for std::numeric_limits

void ignoreLine()
{
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
}

Le code suivant détecte et corrige les extractions échouées ou les dépassements de capacité (et supprime les données superflues) :

// returns true if extraction failed, false otherwise
bool clearFailedExtraction()
{
    // Check for failed extraction
    if (!std::cin) // If the previous extraction failed
    {
        if (std::cin.eof()) // If the stream was closed
        {
            std::exit(0); // Shut down the program now
        }

        // Let's handle the failure
        std::cin.clear(); // Put us back in 'normal' operation mode
        ignoreLine();     // And remove the bad input

        return true;
    }

    return false;
}

Nous pouvons vérifier s'il reste une saisie non extraite (autre qu'un retour à la ligne) de la manière suivante :

// returns true if std::cin has unextracted input on the current line, false otherwise
bool hasUnextractedInput()
{
    return !std::cin.eof() && std::cin.peek() != '\n';
}

Enfin, utilisez des boucles pour demander à l'utilisateur de ressaisir sa valeur si la saisie initiale était invalide.

Note de l'auteur

La validation de la saisie est importante et utile, mais elle rend aussi les exemples plus compliqués et plus difficiles à suivre. C'est pourquoi, dans les leçons suivantes, nous n'effectuerons généralement aucune validation de saisie, sauf si elle est pertinente pour ce que nous cherchons à enseigner.
