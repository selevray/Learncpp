9.2 — Couverture de code

Dans la leçon précédente 9.1 -- Introduction aux tests de votre code, nous avons vu comment écrire et conserver des tests simples. Dans cette leçon, nous allons examiner quel type de tests il est utile d'écrire pour vous assurer que votre code est correct.

Couverture de code

Le terme couverture de code (code coverage) désigne la proportion du code source d'un programme qui est exécutée pendant les tests. Il existe de nombreuses métriques différentes pour mesurer la couverture de code. Nous en présenterons quelques-unes parmi les plus utiles et les plus courantes dans les sections suivantes.

Couverture des instructions

Le terme couverture des instructions (statement coverage) désigne le pourcentage d'instructions de votre code qui ont été exécutées par vos routines de test.

Considérez la fonction suivante :

int foo(int x, int y)
{
    int z{ y };
    if (x > y)
    {
        z = x;
    }
    return z;
}

Appeler cette fonction avec foo(1, 0) vous donnera une couverture des instructions complète pour cette fonction, puisque chaque instruction de la fonction sera exécutée.

Pour notre fonction isLowerVowel() :

bool isLowerVowel(char c)
{
    switch (c) // instruction 1
    {
    case 'a':
    case 'e':
    case 'i':
    case 'o':
    case 'u':
        return true; // instruction 2
    default:
        return false; // instruction 3
    }
}

Cette fonction nécessite deux appels pour tester toutes les instructions, car il n'existe aucun moyen d'atteindre les instructions 2 et 3 au cours du même appel de fonction.

Bien que viser une couverture des instructions de 100 % soit une bonne chose, cela ne suffit souvent pas à garantir la correction du code.

Couverture des branches

La couverture des branches (branch coverage) désigne le pourcentage de branches qui ont été exécutées, chaque branche possible étant comptée séparément. Une instruction if possède deux branches : une branche qui s'exécute lorsque la condition est true, et une branche qui s'exécute lorsque la condition est false (même s'il n'existe pas de else correspondant à exécuter). Une instruction switch peut comporter de nombreuses branches.

int foo(int x, int y)
{
    int z{ y };
    if (x > y)
    {
        z = x;
    }
    return z;
}

L'appel précédent foo(1, 0) nous a donné une couverture des instructions de 100 % et a testé le cas où x > y, mais cela ne nous donne qu'une couverture des branches de 50 %. Il nous faut un appel de plus, foo(0, 1), pour tester le cas où l'instruction if ne s'exécute pas.

bool isLowerVowel(char c)
{
    switch (c)
    {
    case 'a':
    case 'e':
    case 'i':
    case 'o':
    case 'u':
        return true;
    default:
        return false;
    }
}

Dans la fonction isLowerVowel(), deux appels seront nécessaires pour obtenir une couverture des branches de 100 % : un (comme isLowerVowel('a')) pour tester les premiers cas, et un autre (comme isLowerVowel('q')) pour tester le cas default. Plusieurs cas qui mènent au même bloc n'ont pas besoin d'être testés séparément : si l'un fonctionne, tous devraient fonctionner.

Considérez maintenant la fonction suivante :

void compare(int x, int y)
{
    if (x > y)
        std::cout << x << " is greater than " << y << '\n'; // cas 1
    else if (x < y)
        std::cout << x << " is less than " << y << '\n'; // cas 2
    else
        std::cout << x << " is equal to " << y << '\n'; // cas 3
}

Il faut 3 appels pour obtenir une couverture des branches de 100 % ici : compare(1, 0) teste le cas positif de la première instruction if. compare(0, 1) teste le cas négatif de la première instruction if et le cas positif de la seconde instruction if. compare(0, 0) teste le cas négatif de la première et de la seconde instruction if et exécute le else. Ainsi, nous pouvons dire que cette fonction est testée de manière fiable avec 3 appels (ce qui est légèrement mieux que 18 trillions).

Bonne pratique

Visez une couverture des branches de 100 % de votre code.

Couverture des boucles

La couverture des boucles (loop coverage), appelée informellement le test 0, 1, 2, indique que si votre code contient une boucle, vous devez vous assurer qu'elle fonctionne correctement lorsqu'elle itère 0 fois, 1 fois et 2 fois. Si elle fonctionne correctement dans le cas de 2 itérations, elle devrait fonctionner correctement pour toute itération supérieure à 2. Ces trois tests couvrent donc toutes les possibilités (puisqu'une boucle ne peut pas s'exécuter un nombre négatif de fois).

Considérez :

#include <iostream>

void spam(int timesToPrint)
{
    for (int count{ 0 }; count < timesToPrint; ++count)
         std::cout << "Spam! ";
}

Pour tester correctement la boucle de cette fonction, vous devez l'appeler trois fois : spam(0) pour tester le cas de zéro itération, spam(1) pour tester le cas d'une itération, et spam(2) pour tester le cas de deux itérations. Si spam(2) fonctionne, alors spam(n) devrait fonctionner, où n > 2.

Bonne pratique

Utilisez le test 0, 1, 2 pour vous assurer que vos boucles fonctionnent correctement avec différents nombres d'itérations.

Tester différentes catégories d'entrées

Lorsque vous écrivez des fonctions qui acceptent des paramètres, ou lorsque vous acceptez une saisie utilisateur, considérez ce qui se passe avec différentes catégories d'entrées. Dans ce contexte, nous utilisons le terme « catégorie » pour désigner un ensemble d'entrées ayant des caractéristiques similaires.

Par exemple, si j'écrivais une fonction calculant la racine carrée d'un entier, avec quelles valeurs serait-il pertinent de la tester ? Vous commenceriez probablement par une valeur ordinaire, comme 4. Mais il serait aussi judicieux de tester avec 0 et avec un nombre négatif.

Voici quelques directives de base pour les tests par catégorie :

Pour les entiers, assurez-vous d'avoir considéré comment votre fonction gère les valeurs négatives, nulle et positives. Vérifiez aussi le dépassement de capacité (overflow) si cela est pertinent.

Pour les nombres à virgule flottante, assurez-vous d'avoir considéré comment votre fonction gère les valeurs qui posent des problèmes de précision (valeurs légèrement supérieures ou inférieures à celles attendues). De bonnes valeurs de type double pour les tests sont 0.1 et -0.1 (pour tester des nombres légèrement supérieurs à ce qui est attendu) ainsi que 0.7 et -0.7 (pour tester des nombres légèrement inférieurs à ce qui est attendu).

Pour les chaînes de caractères, assurez-vous d'avoir considéré comment votre fonction gère une chaîne vide, une chaîne alphanumérique, des chaînes contenant des espaces (en début, en fin et à l'intérieur), ainsi que des chaînes composées uniquement d'espaces.

Si votre fonction prend un pointeur, n'oubliez pas de tester également nullptr (ne vous inquiétez pas si cela n'a pas de sens pour le moment, nous n'avons pas encore abordé ce sujet).

Bonne pratique

Testez différentes catégories de valeurs d'entrée pour vous assurer que votre unité les gère correctement.

Place au quiz

Question n° 1

Qu'est-ce que la couverture des branches ?

Solution

La couverture des branches est le pourcentage de branches qui ont été exécutées, le cas affirmatif et le cas négatif étant comptés séparément.

Question n° 2

Combien de tests la fonction suivante nécessite-t-elle au minimum pour valider qu'elle fonctionne ?

bool isLowerVowel(char c, bool yIsVowel)
{
    switch (c)
    {
    case 'a':
    case 'e':
    case 'i':
    case 'o':
    case 'u':
        return true;
    case 'y':
        return yIsVowel;
    default:
        return false;
    }
}
Solution

4 tests. Un pour tester le cas a/e/i/o/u. Un pour tester le cas par défaut. Un pour tester isLowerVowel('y', true). Et un pour tester isLowerVowel('y', false).
