1.2 — Commentaires

Un commentaire (comment) est une note destinée au programmeur, insérée directement dans le code source du programme. Les commentaires sont ignorés par le compilateur et ne servent qu'au programmeur.

En C++, il existe deux styles de commentaires différents, qui ont le même objectif : aider le programmeur à documenter le code d'une manière ou d'une autre.

Commentaires sur une seule ligne

Le symbole // commence un commentaire C++ sur une seule ligne. Il indique au compilateur d'ignorer tout ce qui se trouve entre le symbole // et la fin de la ligne. Par exemple :

std::cout << "Hello world!"; // Everything from here to the end of the line is ignored

En général, le commentaire sur une seule ligne sert à faire une remarque rapide sur une seule ligne de code.

std::cout << "Hello world!\n"; // std::cout lives in the iostream library
std::cout << "It is very nice to meet you!\n"; // these comments make the code hard to read
std::cout << "Yeah!\n"; // especially when lines are different lengths

Placer des commentaires à droite d'une ligne peut rendre le code comme le commentaire difficiles à lire, surtout si la ligne est longue. Si les lignes sont assez courtes, les commentaires peuvent simplement être alignés (généralement sur une tabulation), comme ceci :

std::cout << "Hello world!\n";                 // std::cout lives in the iostream library
std::cout << "It is very nice to meet you!\n"; // this is much easier to read
std::cout << "Yeah!\n";                        // don't you think so?

Cependant, si les lignes sont longues, placer les commentaires à droite peut rendre vos lignes vraiment trop longues. Dans ce cas, les commentaires sur une seule ligne sont souvent placés au-dessus de la ligne qu'ils commentent :

// std::cout lives in the iostream library
std::cout << "Hello world!\n";

// this is much easier to read
std::cout << "It is very nice to meet you!\n";

// don't you think so?
std::cout << "Yeah!\n";

Note de l'auteur

Dans cette série de tutoriels, nos exemples entrent dans l'une des catégories suivantes :

  • Programmes complets (ceux qui possèdent une fonction main()). Ils sont prêts à être compilés et exécutés.
  • Extraits (petits morceaux) de code, comme les instructions ci-dessus. Nous les utilisons pour illustrer de façon concise des concepts précis.

Nous n'avons pas l'intention que vous compiliez les extraits. Mais si vous le souhaitez, vous devrez en faire un programme complet. En général, ce programme ressemblera à ceci :

#include <iostream>

int main()
{
    // Replace this line with the snippet(s) of code you'd like to compile

    return 0;
}

Commentaires sur plusieurs lignes

Le couple de symboles /* et */ désigne un commentaire multi-lignes de style C. Tout ce qui se trouve entre ces symboles est ignoré.

/* This is a multi-line comment.
   This line will be ignored.
   So will this one. */

Comme tout ce qui se trouve entre les symboles est ignoré, vous verrez parfois des programmeurs « embellir » leurs commentaires multi-lignes :

/* This is a multi-line comment.
 * the matching asterisks to the left
 * can make this easier to read
 */

Les commentaires de style multi-lignes ne peuvent pas être imbriqués. Par conséquent, le code suivant produira des résultats inattendus :

/* This is a multi-line /* comment */ this is not inside the comment */
// The above comment ends at the first */, not the second */

Lorsque le compilateur tente de compiler ceci, il ignore tout ce qui se trouve entre le premier /* et le premier */. Comme this is not inside the comment */ ne fait pas partie du commentaire, le compilateur essaie de le compiler. Cela provoquera inévitablement une erreur de compilation.

C'est un cas où l'utilisation d'un coloriseur syntaxique peut vraiment être utile, car la couleur différente des commentaires permet de voir clairement ce qui fait partie du commentaire et ce qui n'en fait pas partie.

Attention

N'utilisez pas de commentaires multi-lignes à l'intérieur d'autres commentaires multi-lignes. Il est en revanche acceptable d'inclure des commentaires sur une seule ligne à l'intérieur d'un commentaire multi-lignes.

Bon usage des commentaires

En général, les commentaires doivent servir à trois choses. Premièrement, pour une bibliothèque, un programme ou une fonction donnés, les commentaires servent au mieux à décrire ce que fait la bibliothèque, le programme ou la fonction. Ils sont généralement placés en haut du fichier ou de la bibliothèque, ou juste avant la fonction. Par exemple :

// This program calculates the student's final grade based on their test and homework scores.

// This function uses Newton's method to approximate the root of a given equation.

// The following lines generate a random item based on rarity, level, and a weight factor.

Tous ces commentaires donnent au lecteur une bonne idée de ce que la bibliothèque, le programme ou la fonction cherche à accomplir, sans qu'il ait besoin d'examiner le code lui-même. L'utilisateur (qui peut être quelqu'un d'autre, ou vous-même si vous réutilisez du code écrit auparavant) peut voir d'un coup d'œil si le code est pertinent pour ce qu'il cherche à faire. C'est particulièrement important lorsque l'on travaille en équipe, car tout le monde ne connaît pas l'ensemble du code.

Deuxièmement, à l'intérieur d'une bibliothèque, d'un programme ou d'une fonction décrits ci-dessus, les commentaires peuvent servir à décrire comment le code va atteindre son objectif.

/* To calculate the final grade, we sum all the weighted midterm and homework scores
    and then divide by the number of scores to assign a percentage, which is
    used to calculate a letter grade. */

// To generate a random item, we're going to do the following:
// 1) Put all of the items of the desired rarity on a list
// 2) Calculate a probability for each item based on level and weight factor
// 3) Choose a random number
// 4) Figure out which item that random number corresponds to
// 5) Return the appropriate item

Ces commentaires donnent à l'utilisateur une idée de la manière dont le code va atteindre son objectif, sans qu'il ait besoin de comprendre ce que fait chaque ligne de code individuellement.

Troisièmement, au niveau des instructions, les commentaires doivent servir à décrire pourquoi le code fait quelque chose. Un mauvais commentaire d'instruction explique ce que fait le code. Si vous écrivez un jour du code si complexe qu'il faut un commentaire pour expliquer ce que fait une instruction, vous devez probablement réécrire l'instruction plutôt que la commenter.

Voici quelques exemples de mauvais commentaires de ligne et de bons commentaires d'instruction.

Mauvais commentaire :

// Set sight range to 0
sight = 0;

Raison : on voit déjà que sight reçoit la valeur 0 en lisant l'instruction.

Bon commentaire :

// The player just drank a potion of blindness and can not see anything
sight = 0;

Raison : on sait désormais pourquoi la vue du joueur est fixée à 0.

Mauvais commentaire :

// Calculate the cost of the items
cost = quantity * 2 * storePrice;

Raison : on voit qu'il s'agit d'un calcul de coût, mais pourquoi multiplie-t-on quantity par 2 ?

Bon commentaire :

// We need to multiply quantity by 2 here because they are bought in pairs
cost = quantity * 2 * storePrice;

Raison : on comprend maintenant pourquoi cette formule est logique.

Les programmeurs doivent souvent faire un choix difficile entre résoudre un problème d'une façon ou d'une autre. Les commentaires sont un excellent moyen de vous rappeler (ou de dire à quelqu'un d'autre) la raison pour laquelle vous avez pris une décision plutôt qu'une autre.

Bons commentaires :

// We decided to use a linked list instead of an array because
// arrays do insertion too slowly.

// We're going to use Newton's method to find the root of a number because
// there is no deterministic way to solve these equations.

Enfin, les commentaires doivent être rédigés de façon à être compréhensibles pour quelqu'un qui ne sait pas du tout ce que fait le code. Il arrive souvent qu'un programmeur dise « C'est évident ce que fait ceci ! Je ne risque pas de l'oublier ». Devinez quoi ? Ce n'est pas évident, et vous serez surpris de la rapidité avec laquelle vous oubliez. :) Vous (ou quelqu'un d'autre) vous remercierez plus tard d'avoir consigné en langage humain le quoi, le comment et le pourquoi de votre code. Lire des lignes de code individuelles est facile. Comprendre quel objectif elles sont censées atteindre ne l'est pas.

Contenu connexe

Nous abordons la rédaction de commentaires pour les instructions de déclaration de variables dans la leçon 1.7 -- Mots-clés et nommage des identifiants.

Bonne pratique

Commentez abondamment votre code, et rédigez vos commentaires comme si vous vous adressiez à quelqu'un qui ne sait pas du tout ce que fait le code. Ne supposez pas que vous vous souviendrez pourquoi vous avez fait certains choix précis.

Note de l'auteur

Tout au long du reste de cette série de tutoriels, nous utiliserons des commentaires à l'intérieur des blocs de code pour attirer votre attention sur certains points, ou pour illustrer le fonctionnement de certaines choses (tout en veillant à ce que les programmes restent compilables). Les lecteurs attentifs remarqueront que, selon les critères ci-dessus, la plupart de ces commentaires sont épouvantables. :) Au fil de la lecture des prochains tutoriels, gardez à l'esprit que ces commentaires servent un objectif pédagogique intentionnel, et ne cherchent pas à montrer à quoi ressemblent de bons commentaires.

En passant…

Les programmes de génération de documentation, comme Doxygen, sont conçus pour aider à générer et à exploiter la documentation de diverses manières. Entre autres, ils peuvent :

  • Aider à standardiser la façon dont votre code est documenté.
  • Générer des diagrammes, des visualisations et des liens croisés pour faciliter la compréhension de la structure du code.
  • Exporter votre documentation dans d'autres formats (par exemple HTML) afin de la partager facilement avec d'autres personnes (par exemple les membres de votre équipe, ou les développeurs qui intègrent ce que vous écrivez).

Vous n'en aurez pas besoin pendant votre apprentissage du langage, mais vous pourrez en rencontrer ou les trouver utiles à l'avenir, en particulier dans un cadre professionnel.

Mettre du code en commentaire

Transformer une ou plusieurs lignes de code en commentaire s'appelle commenter votre code (commenting out). Cela permet d'exclure (temporairement) certaines parties de votre code du programme compilé.

Pour mettre une seule ligne de code en commentaire, utilisez simplement le commentaire de style // pour transformer temporairement la ligne en commentaire :

Avant commentaire :

    std::cout << 1;

Après commentaire :

//    std::cout << 1;

Pour mettre un bloc de code en commentaire, utilisez // sur plusieurs lignes, ou le commentaire de style /* */, afin de transformer temporairement le bloc en commentaire.

Avant commentaire :

    std::cout << 1;
    std::cout << 2;
    std::cout << 3;

Après commentaire :

//    std::cout << 1;
//    std::cout << 2;
//    std::cout << 3;

ou

/*
    std::cout << 1;
    std::cout << 2;
    std::cout << 3;
*/

Il existe plusieurs raisons de vouloir faire cela :

  1. Vous travaillez sur un nouveau morceau de code qui ne compile pas encore, et vous avez besoin d'exécuter le programme. Le compilateur ne vous laissera pas compiler le code tant qu'il contient des erreurs. Mettre en commentaire le code qui ne compile pas permettra au programme de se compiler afin que vous puissiez l'exécuter. Lorsque vous êtes prêt, vous pouvez retirer les commentaires et poursuivre votre travail.
  2. Vous avez écrit du nouveau code qui compile mais ne fonctionne pas correctement, et vous n'avez pas le temps de le corriger tout de suite. Mettre en commentaire le code défectueux garantira qu'il ne s'exécute pas et ne cause pas de problèmes avant que vous ne puissiez le corriger.
  3. Pour trouver la source d'une erreur. Si un programme ne produit pas les résultats attendus (ou plante), il peut être utile de désactiver certaines parties de votre code pour voir si vous pouvez isoler ce qui empêche son bon fonctionnement. Si vous mettez en commentaire une ou plusieurs lignes de code, et que votre programme se met à fonctionner comme prévu (ou cesse de planter), il y a de fortes chances que ce que vous venez de mettre en commentaire soit à l'origine du problème. Vous pouvez alors chercher pourquoi ces lignes de code posent problème.
  4. Vous voulez remplacer un morceau de code par un autre. Au lieu de simplement supprimer le code original, vous pouvez le mettre en commentaire et le conserver à titre de référence jusqu'à ce que vous soyez certain que votre nouveau code fonctionne correctement. Une fois que vous êtes sûr que le nouveau code fonctionne, vous pouvez supprimer l'ancien code commenté. Si vous n'arrivez pas à faire fonctionner le nouveau code, vous pouvez toujours supprimer le nouveau code et retirer les commentaires de l'ancien pour revenir à votre état précédent.

Mettre du code en commentaire est une pratique courante pendant le développement, c'est pourquoi de nombreux environnements de développement (IDE) proposent une fonctionnalité permettant de commenter une portion de code sélectionnée. La façon d'accéder à cette fonctionnalité varie selon l'IDE.

Pour les utilisateurs de Visual Studio

Vous pouvez commenter ou décommenter une sélection via le menu Édition > Avancé > Commenter la sélection (ou Décommenter la sélection).

Pour les utilisateurs de Code::Blocks

Vous pouvez commenter ou décommenter une sélection via le menu Edit > Comment (ou Uncomment, ou Toggle comment, ou n'importe lequel des autres outils de commentaire).

Pour les utilisateurs de VS Code

Vous pouvez commenter ou décommenter une sélection en appuyant sur Ctrl+/.

Astuce

Si vous utilisez toujours des commentaires sur une seule ligne pour vos commentaires habituels, vous pouvez toujours utiliser des commentaires multi-lignes pour mettre votre code en commentaire, sans conflit. Si vous utilisez des commentaires multi-lignes pour documenter votre code, la mise en commentaire de code devient plus délicate.

Si vous devez mettre en commentaire un bloc de code qui contient des commentaires multi-lignes, vous pouvez également envisager la directive du préprocesseur #if 0, que nous abordons dans la leçon 2.10 -- Introduction au préprocesseur.

Résumé

  • Au niveau de la bibliothèque, du programme ou de la fonction, utilisez les commentaires pour décrire ce que fait le code.
  • À l'intérieur de la bibliothèque, du programme ou de la fonction, utilisez les commentaires pour décrire comment le code procède.
  • Au niveau des instructions, utilisez les commentaires pour décrire pourquoi le code fait ce qu'il fait.
