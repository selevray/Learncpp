1.8 — Espaces blancs et mise en forme de base

Les espaces blancs (whitespace) désignent les caractères utilisés pour la mise en forme : principalement les espaces, les tabulations et les sauts de ligne. En C++, les espaces blancs servent essentiellement à trois choses : séparer certains éléments du langage, composer le texte entre guillemets et mettre en forme le code.

Certains éléments du langage doivent être séparés par des espaces blancs

La syntaxe du langage impose que certains éléments soient séparés par des espaces blancs. C'est surtout le cas lorsque deux mots-clés ou identificateurs doivent être placés l'un après l'autre, afin que le compilateur puisse les distinguer.

Par exemple, une déclaration de variable doit comporter des espaces blancs :

int x; // int et x doivent être séparés par des espaces blancs

Si nous écrivions intx à la place, le compilateur interpréterait cela comme un seul identificateur, puis signalerait qu'il ne connaît pas d'identificateur nommé intx.

Autre exemple : le type de retour et le nom d'une fonction doivent être séparés par des espaces blancs :

int main(); // int et main doivent être séparés par des espaces blancs

Lorsqu'un espace blanc est requis comme séparateur, le compilateur ne se soucie pas de la quantité utilisée, tant qu'il en existe au moins un.

Les définitions de variables suivantes sont toutes valides :

int x;
int                y;
            int 
z;

Dans certains cas, les sauts de ligne servent de séparateurs. Un commentaire sur une seule ligne se termine par un saut de ligne.

Par exemple, écrire quelque chose comme ceci vous causera des ennuis :

std::cout << "Hello world!"; // Ceci fait partie du commentaire et
this is not part of the comment

Les directives du préprocesseur (par exemple #include <iostream>) doivent être placées sur des lignes distinctes :

#include <iostream>
#include <string>

Le texte entre guillemets respecte la quantité d'espaces blancs à la lettre

À l'intérieur d'un texte entre guillemets, la quantité d'espaces blancs est prise littéralement.

std::cout << "Hello world!";

est différent de :

std::cout << "Hello          world!";

Les sauts de ligne ne sont pas autorisés dans un texte entre guillemets :

std::cout << "Hello
     world!"; // Non autorisé !

Des textes entre guillemets séparés uniquement par des espaces blancs (espaces, tabulations ou sauts de ligne) sont concaténés :

std::cout << "Hello "
     "world!"; // affiche "Hello world!"

Utiliser les espaces blancs pour mettre en forme le code

Les espaces blancs sont par ailleurs généralement ignorés. Nous pouvons donc les utiliser où bon nous semble pour mettre en forme notre code et le rendre plus lisible.

Par exemple, le code suivant est assez difficile à lire :

#include <iostream>
int main(){std::cout<<"Hello world";return 0;}

Le suivant est mieux (mais reste assez dense) :

#include <iostream>
int main() {
std::cout << "Hello world";
return 0;
}

Et le suivant est encore meilleur :

#include <iostream>

int main()
{
    std::cout << "Hello world";

    return 0;
}

Une instruction peut être répartie sur plusieurs lignes si on le souhaite :

#include <iostream>

int main()
{
    std::cout
        << "Hello world"; // fonctionne très bien
    return 0;
}

Cela peut être utile pour les instructions particulièrement longues.

Mise en forme de base

Contrairement à certains autres langages, le C++ n'impose aucune contrainte de mise en forme au programmeur. Pour cette raison, on dit que le C++ est un langage indépendant des espaces blancs (whitespace-independent).

C'est une arme à double tranchant. D'un côté, il est agréable d'avoir la liberté de faire comme bon nous semble. De l'autre, de nombreuses méthodes de mise en forme des programmes C++ ont été développées au fil des années, et vous trouverez (parfois des désaccords importants et déroutants) sur celles qui sont les meilleures. Notre règle empirique de base est que les meilleurs styles sont ceux qui produisent le code le plus lisible et offrent le plus de cohérence.

Voici nos recommandations de mise en forme de base :

  1. Il est permis d'utiliser indifféremment des tabulations ou des espaces pour l'indentation (la plupart des IDE disposent d'un paramètre permettant de convertir une pression sur la touche Tab en nombre d'espaces approprié). Les développeurs qui préfèrent les espaces le font généralement parce que cela garantit que le code est aligné exactement comme prévu, quel que soit l'éditeur ou les paramètres utilisés. Les partisans des tabulations se demandent pourquoi ne pas utiliser pour l'indentation le caractère conçu précisément pour cela, d'autant que vous pouvez régler sa largeur selon votre préférence. Il n'y a pas de bonne réponse ici : débattre de la question revient à se demander si le gâteau ou la tarte est meilleur. Tout se ramène finalement à une préférence personnelle.

Quoi qu'il en soit, nous vous recommandons de régler vos tabulations sur une indentation de 4 espaces. Certains IDE utilisent par défaut une indentation de 3 espaces, ce qui convient aussi.

  1. Il existe deux styles conventionnels pour les accolades de fonction.

Beaucoup de développeurs préfèrent placer l'accolade ouvrante sur la même ligne que l'instruction :

int main() {
    // instructions ici
}

La justification est que cela réduit la quantité d'espace vertical utilisé (puisqu'on ne consacre pas une ligne entière à une accolade ouvrante), ce qui permet de faire tenir davantage de code à l'écran. Cela améliore la compréhension du code, car vous n'avez pas besoin de faire défiler l'écran autant pour comprendre ce que fait le code.

Dans ce tutoriel, nous utiliserons toutefois l'alternative courante, où l'accolade ouvrante apparaît seule sur sa ligne :

int main()
{
    // instructions ici
}

Cela améliore la lisibilité et est moins sujet aux erreurs, car vos paires d'accolades doivent toujours être indentées au même niveau. Si vous obtenez une erreur de compilation due à un défaut d'appariement des accolades, il est très facile de voir où elle se trouve.

  1. Chaque instruction placée entre accolades doit être décalée d'une tabulation par rapport à l'accolade ouvrante de la fonction à laquelle elle appartient. Par exemple :
int main()
{
    std::cout << "Hello world!\n"; // décalé d'une tabulation (4 espaces)
    std::cout << "Nice to meet you.\n"; // décalé d'une tabulation (4 espaces)
}
  1. Les lignes ne doivent pas être trop longues. En pratique, 80 caractères constituent le standard de fait pour la longueur maximale d'une ligne. Si une ligne doit être plus longue, elle doit être coupée (à un endroit raisonnable) en plusieurs lignes. On peut le faire en indentant chaque ligne suivante d'une tabulation supplémentaire, ou, si les lignes se ressemblent, en l'alignant sur la ligne précédente (selon ce qui est le plus lisible).
int main()
{
    std::cout << "This is a really, really, really, really, really, really, really, " 
        "really long line\n"; // une indentation supplémentaire pour la ligne de suite

    std::cout << "This is another really, really, really, really, really, really, really, "
                 "really long line\n"; // texte aligné sur la ligne précédente pour la ligne de suite

    std::cout << "This one is short\n";
}

Cela rend vos lignes plus faciles à lire. Sur les écrans larges modernes, cela permet aussi de placer côte à côte deux fenêtres contenant un code similaire et de les comparer plus facilement.

Bonne pratique

Essayez de limiter vos lignes à 80 caractères au maximum.

Astuce

De nombreux éditeurs disposent d'une fonctionnalité intégrée (ou d'un plugin/extension) qui affiche une ligne (appelée « repère de colonne » ou « column guide ») à une colonne donnée (par exemple à 80 caractères), afin que vous voyiez facilement quand vos lignes deviennent trop longues. Pour savoir si votre éditeur prend en charge cette fonctionnalité, effectuez une recherche sur le nom de votre éditeur suivi de « Column guide ».

  1. Si une longue ligne est coupée à un opérateur (par exemple << ou +), l'opérateur doit être placé au début de la ligne suivante, et non à la fin de la ligne courante.
    std::cout << 3 + 4
        + 5 + 6
        * 7 * 8;

Cela permet de mieux voir que les lignes suivantes sont la suite des lignes précédentes, et permet d'aligner les opérateurs à gauche, ce qui facilite la lecture.

  1. Utilisez les espaces blancs pour rendre votre code plus lisible, en alignant des valeurs ou des commentaires, ou en ajoutant des espaces entre des blocs de code.

Plus difficile à lire :

cost = 57;
pricePerItem = 24;
value = 5;
numberOfItems = 17;

Plus facile à lire :

cost          = 57;
pricePerItem  = 24;
value         = 5;
numberOfItems = 17;

Plus difficile à lire :

std::cout << "Hello world!\n"; // cout se trouve dans la bibliothèque iostream
std::cout << "It is very nice to meet you!\n"; // ces commentaires rendent le code difficile à lire
std::cout << "Yeah!\n"; // surtout lorsque les lignes ont des longueurs différentes

Plus facile à lire :

std::cout << "Hello world!\n";                  // cout se trouve dans la bibliothèque iostream
std::cout << "It is very nice to meet you!\n";  // ces commentaires sont plus faciles à lire
std::cout << "Yeah!\n";                         // surtout lorsqu'ils sont alignés

Plus difficile à lire :

// cout se trouve dans la bibliothèque iostream
std::cout << "Hello world!\n";
// ces commentaires rendent le code difficile à lire
std::cout << "It is very nice to meet you!\n";
// surtout lorsqu'ils sont tous regroupés
std::cout << "Yeah!\n";

Plus facile à lire :

// cout se trouve dans la bibliothèque iostream
std::cout << "Hello world!\n";

// ces commentaires sont plus faciles à lire
std::cout << "It is very nice to meet you!\n";

// lorsqu'ils sont séparés par des espaces blancs
std::cout << "Yeah!\n";

Nous suivrons ces conventions tout au long de ce tutoriel, et elles deviendront naturelles pour vous. Au fur et à mesure que nous introduirons de nouveaux sujets, nous présenterons de nouvelles recommandations de style qui les accompagnent.

En définitive, le C++ vous laisse le choix du style qui vous convient le mieux ou que vous jugez le meilleur. Nous vous recommandons toutefois vivement d'adopter le même style que celui de nos exemples. Il a été éprouvé par des milliers de programmeurs sur des milliards de lignes de code, et il est conçu pour favoriser la réussite.

Une exception : si vous travaillez sur la base de code de quelqu'un d'autre, adoptez son style. Il vaut mieux privilégier la cohérence plutôt que vos préférences.

Bonne pratique

Lorsque vous travaillez sur un projet existant, respectez le style déjà adopté.

Mise en forme automatique

La plupart des IDE modernes vous aident à mettre en forme votre code au fur et à mesure que vous le saisissez (par exemple, lorsque vous créez une fonction, l'IDE indente automatiquement les instructions du corps de la fonction).

Cependant, lorsque vous ajoutez ou supprimez du code, modifiez le formatage par défaut de l'IDE ou collez un bloc de code dont la mise en forme diffère, le formatage peut se dégrader. Corriger la mise en forme d'une partie ou de la totalité d'un fichier peut être pénible. Heureusement, les IDE modernes disposent généralement d'une fonctionnalité de mise en forme automatique qui reformate soit une sélection (surlignée à la souris), soit un fichier entier.

Pour les utilisateurs de Visual Studio

Dans Visual Studio, les options de mise en forme automatique se trouvent sous Édition > Avancé > Mettre en forme le document et Édition > Avancé > Mettre en forme la sélection.

Pour les utilisateurs de Code::Blocks

Dans Code::Blocks, les options de mise en forme automatique se trouvent sous Clic droit > Format use AStyle.

Pour y accéder plus facilement, nous vous recommandons d'ajouter un raccourci clavier pour mettre automatiquement en forme le fichier actif.

Il existe aussi des outils externes permettant de mettre en forme le code automatiquement. clang-format est l'un des plus populaires.

Bonne pratique

L'utilisation de la mise en forme automatique est vivement recommandée pour conserver un style de code cohérent.

Guides de style

Un guide de style (style guide) est un document concis et tranché, contenant des conventions de programmation (parfois arbitraires), des consignes de mise en forme et des bonnes pratiques. Le but d'un guide de style est de garantir que tous les développeurs d'un projet programment de manière cohérente.

Parmi les guides de style C++ les plus souvent cités, on trouve :

  • C++ Core Guidelines, maintenues par Bjarne Stroustrup et Herb Sutter.
  • Google.
  • LLVM
  • GCC/GNU

Nous privilégions généralement les C++ Core Guidelines, car elles sont à jour et largement applicables.
