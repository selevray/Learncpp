2.7 — Déclarations anticipées et définitions

Examinez ce programme d'apparence anodine :

#include <iostream>

int main()
{
    std::cout << "The sum of 3 and 4 is: " << add(3, 4) << '\n';
    return 0;
}

int add(int x, int y)
{
    return x + y;
}

Vous vous attendriez à ce que ce programme produise le résultat suivant :


The sum of 3 and 4 is: 7

Mais en réalité, il ne compile pas du tout ! Visual Studio produit l'erreur de compilation suivante :


add.cpp(5) : error C3861: 'add': identifier not found

La raison pour laquelle ce programme ne compile pas est que le compilateur traite le contenu des fichiers de code séquentiellement. Lorsque le compilateur atteint l'appel de fonction add() à la ligne 5 de main, il ne sait pas ce qu'est add, car nous n'avons défini add qu'à la ligne 9 ! C'est ce qui produit l'erreur identifier not found (identifiant introuvable).

Les anciennes versions de Visual Studio produisaient une erreur supplémentaire :


add.cpp(9) : error C2365: 'add'; : redefinition; previous definition was 'formerly unknown identifier'

Ce message est quelque peu trompeur, puisque add n'a jamais été défini auparavant. Néanmoins, il est utile de retenir qu'il est assez courant qu'une seule erreur en produise plusieurs autres, redondantes ou liées. Il peut parfois être difficile de déterminer si une erreur ou un avertissement au-delà du premier est une conséquence du premier problème, ou s'il s'agit d'un problème indépendant qui doit être résolu séparément.

Bonne pratique

Lorsque vous corrigez des erreurs ou des avertissements de compilation dans vos programmes, résolvez le premier problème listé, puis recompilez.

Pour corriger ce problème, nous devons résoudre le fait que le compilateur ne sait pas ce qu'est add. Il existe deux manières courantes de traiter ce problème.

Option 1 : réordonner les définitions de fonctions

Une façon de résoudre le problème consiste à réordonner les définitions de fonctions afin que add soit défini avant main :

#include <iostream>

int add(int x, int y)
{
    return x + y;
}

int main()
{
    std::cout << "The sum of 3 and 4 is: " << add(3, 4) << '\n';
    return 0;
}

Ainsi, au moment où main appelle add, le compilateur connaît déjà add. Comme il s'agit d'un programme très simple, ce changement est relativement facile à réaliser. Cependant, dans un programme plus volumineux, il peut être fastidieux de déterminer quelles fonctions appellent quelles autres fonctions (et dans quel ordre) afin de pouvoir les déclarer séquentiellement.

De plus, cette option n'est pas toujours possible. Supposons que nous écrivions un programme comportant deux fonctions A et B. Si la fonction A appelle la fonction B, et que la fonction B appelle la fonction A, il n'existe aucun moyen d'ordonner les fonctions qui satisfasse le compilateur. Si vous définissez A en premier, le compilateur se plaindra qu'il ne connaît pas B. Si vous définissez B en premier, le compilateur se plaindra qu'il ne connaît pas A.

Option 2 : utiliser une déclaration anticipée

Nous pouvons également résoudre ce problème en utilisant une déclaration anticipée.

Une déclaration anticipée (forward declaration) nous permet d'informer le compilateur de l'existence d'un identifiant avant de définir réellement cet identifiant.

Dans le cas des fonctions, cela nous permet d'informer le compilateur de l'existence d'une fonction avant de définir le corps de cette fonction. Ainsi, lorsque le compilateur rencontre un appel à la fonction, il comprend qu'il s'agit d'un appel de fonction et peut vérifier que nous appelons correctement la fonction, même s'il ne sait pas encore comment ni où elle est définie.

Pour écrire une déclaration anticipée d'une fonction, nous utilisons une instruction de déclaration de fonction (également appelée prototype de fonction). La déclaration de fonction se compose du type de retour, du nom et des types des paramètres de la fonction, le tout suivi d'un point-virgule. Les noms des paramètres peuvent être facultativement inclus. Le corps de la fonction n'est pas inclus dans la déclaration.

Voici une déclaration de fonction pour la fonction add :

int add(int x, int y); // la déclaration de fonction comprend le type de retour, le nom, les paramètres et le point-virgule. Pas de corps de fonction !

Voici maintenant notre programme initial qui ne compilait pas, utilisant une déclaration de fonction comme déclaration anticipée de la fonction add :

#include <iostream>

int add(int x, int y); // déclaration anticipée de add() (à l'aide d'une déclaration de fonction)

int main()
{
    std::cout << "The sum of 3 and 4 is: " << add(3, 4) << '\n'; // ceci fonctionne car nous avons déclaré add() par anticipation ci-dessus
    return 0;
}

int add(int x, int y) // même si le corps de add() n'est défini qu'ici
{
    return x + y;
}

Désormais, lorsque le compilateur atteint l'appel à add dans main, il saura à quoi ressemble add (une fonction qui prend deux paramètres entiers et renvoie un entier), et il ne se plaindra pas.

Il est intéressant de noter que les déclarations de fonctions n'ont pas besoin de spécifier les noms des paramètres (ceux-ci ne sont pas considérés comme faisant partie de la déclaration de fonction). Dans le code ci-dessus, vous pouvez également déclarer votre fonction par anticipation de cette manière :

int add(int, int); // déclaration de fonction valide

Cependant, nous préférons nommer nos paramètres (en utilisant les mêmes noms que ceux de la fonction réelle). Cela permet de comprendre à quoi servent les paramètres de la fonction simplement en regardant la déclaration. Par exemple, si vous voyez la déclaration void doSomething(int, int, int), vous pourriez croire vous souvenir de la signification de chaque paramètre, mais vous pourriez aussi vous tromper.

De plus, de nombreux outils automatiques de génération de documentation produisent leur documentation à partir du contenu des fichiers d'en-tête, où les déclarations sont souvent placées. Nous abordons les fichiers d'en-tête et les déclarations dans la leçon 2.11 -- Fichiers d'en-tête.

Bonne pratique

Conservez les noms des paramètres dans vos déclarations de fonctions.

Astuce

Vous pouvez facilement créer des déclarations de fonctions en copiant/collant l'en-tête de votre fonction et en ajoutant un point-virgule.

Pourquoi des déclarations anticipées ?

Vous vous demandez peut-être pourquoi utiliser une déclaration anticipée si nous pouvons simplement réordonner les fonctions pour que nos programmes fonctionnent.

Le plus souvent, les déclarations anticipées servent à informer le compilateur de l'existence d'une fonction définie dans un autre fichier de code. Le réordonnancement n'est pas possible dans ce cas, car l'appelant et l'appelé se trouvent dans des fichiers complètement différents ! Nous aborderons cela plus en détail dans la leçon suivante (2.8 -- Programmes à plusieurs fichiers de code).

Les déclarations anticipées peuvent également servir à définir nos fonctions dans un ordre indifférent. Cela nous permet de définir les fonctions dans l'ordre qui optimise l'organisation (par exemple en regroupant les fonctions liées entre elles) ou la compréhension du lecteur.

Plus rarement, il arrive que deux fonctions s'appellent mutuellement. Le réordonnancement n'est pas possible non plus dans ce cas, car il n'existe aucun moyen de placer les fonctions de sorte que chacune soit placée avant l'autre. Les déclarations anticipées offrent un moyen de résoudre ces dépendances circulaires.

Oublier le corps de la fonction

Les programmeurs débutants se demandent souvent ce qui se passe s'ils déclarent une fonction par anticipation sans la définir.

La réponse est : cela dépend. Si une déclaration anticipée est faite, mais que la fonction n'est jamais appelée, le programme compilera et s'exécutera correctement. En revanche, si une déclaration anticipée est faite et que la fonction est appelée, mais que le programme ne définit jamais la fonction, le programme compilera sans problème, mais l'éditeur de liens (linker) signalera qu'il ne peut pas résoudre l'appel de fonction.

Considérez le programme suivant :

#include <iostream>

int add(int x, int y); // déclaration anticipée de add()

int main()
{
    std::cout << "The sum of 3 and 4 is: " << add(3, 4) << '\n';
    return 0;
}

// note : aucune définition de la fonction add

Dans ce programme, nous déclarons add par anticipation, nous appelons add, mais nous ne définissons add nulle part. Lorsque nous essayons de compiler ce programme, Visual Studio produit le message suivant :


Compiling...
add.cpp
Linking...
add.obj : error LNK2001: unresolved external symbol "int __cdecl add(int,int)" (?add@@YAHHH@Z)
add.exe : fatal error LNK1120: 1 unresolved externals

Comme vous pouvez le voir, le programme a bien compilé, mais il a échoué à l'étape de l'édition de liens parce que int add(int, int) n'a jamais été défini.

Autres types de déclarations anticipées

Les déclarations anticipées sont surtout utilisées avec les fonctions. Cependant, elles peuvent également servir avec d'autres identifiants en C++, comme les variables et les types. Les variables et les types ont une syntaxe différente pour la déclaration anticipée, nous les verrons donc dans de futures leçons.

Déclarations et définitions

En C++, vous entendrez fréquemment les mots « déclaration » et « définition », souvent utilisés de manière interchangeable. Que signifient-ils ? Vous disposez désormais des connaissances fondamentales nécessaires pour comprendre la différence entre les deux.

Une déclaration informe le compilateur de l'existence d'un identifiant et des informations de type qui lui sont associées. Voici quelques exemples de déclarations :

int add(int x, int y); // informe le compilateur de l'existence d'une fonction nommée « add » qui prend deux paramètres int et renvoie un int. Pas de corps !
int x;                 // informe le compilateur de l'existence d'une variable entière nommée x

Une définition est une déclaration qui implémente (pour les fonctions et les types) ou instancie (pour les variables) réellement l'identifiant.

Voici quelques exemples de définitions :

// comme cette fonction a un corps, c'est une implémentation de la fonction add()
int add(int x, int y)
{
    int z{ x + y };   // instancie la variable z

    return z;
}

int x;                // instancie la variable x

En C++, toutes les définitions sont des déclarations. Par conséquent, int x; est à la fois une définition et une déclaration.

Inversement, toutes les déclarations ne sont pas des définitions. Les déclarations qui ne sont pas des définitions sont appelées déclarations pures. Parmi les types de déclarations pures figurent les déclarations anticipées de fonctions, de variables et de types.

Nomenclature

Dans le langage courant, le terme « déclaration » désigne généralement « une déclaration pure », et « définition » désigne « une définition qui sert également de déclaration ». Ainsi, nous appellerions généralement int x; une définition, même s'il s'agit à la fois d'une définition et d'une déclaration.

Lorsque le compilateur rencontre un identifiant, il vérifie que l'utilisation de cet identifiant est valide (par exemple que l'identifiant est dans sa portée, qu'il est utilisé d'une manière syntaxiquement correcte, etc.).

Dans la plupart des cas, une déclaration suffit pour permettre au compilateur de vérifier qu'un identifiant est utilisé correctement. Par exemple, lorsque le compilateur rencontre l'appel de fonction add(5, 6), s'il a déjà vu la déclaration de add(int, int), alors il peut valider que add est bien une fonction qui prend deux paramètres int. Il n'a pas besoin d'avoir effectivement vu la définition de la fonction add (qui peut exister dans un autre fichier).

Cependant, il existe quelques cas où le compilateur doit pouvoir voir une définition complète pour utiliser un identifiant (comme pour les définitions de modèles (templates) et les définitions de types, que nous aborderons dans de futures leçons).

Voici un tableau récapitulatif :

Terme Signification technique Exemples
Déclaration Informe le compilateur de l'existence d'un identifiant et des informations de type qui lui sont associées. void foo(); // déclaration anticipée de fonction (sans corps) void goo() {}; // définition de fonction (avec corps) int x; // définition de variable
Définition Implémente une fonction ou instancie une variable. Les définitions sont aussi des déclarations. void foo() { } // définition de fonction (avec corps) int x; // définition de variable
Déclaration pure Une déclaration qui n'est pas une définition. void foo(); // déclaration anticipée de fonction (sans corps)
Initialisation Fournit une valeur initiale à un objet défini. int x { 2 }; // x est initialisé à la valeur 2

Le terme « déclaration » est couramment utilisé pour désigner une « déclaration pure », et le terme « définition » pour tout ce qui est à la fois une définition et une déclaration. Nous utilisons cette nomenclature courante dans les commentaires de la colonne des exemples.

La règle de la définition unique (ODR)

La règle de la définition unique (en anglais one definition rule, abrégée ODR) est une règle bien connue du C++. L'ODR comporte trois parties :

  1. Au sein d'un fichier, chaque fonction, variable, type ou modèle dans une portée donnée ne peut avoir qu'une seule définition. Les définitions situées dans des portées différentes (par exemple des variables locales définies dans des fonctions différentes, ou des fonctions définies dans des espaces de noms différents) ne violent pas cette règle.
  2. Au sein d'un programme, chaque fonction ou variable dans une portée donnée ne peut avoir qu'une seule définition. Cette règle existe parce qu'un programme peut comporter plusieurs fichiers (nous aborderons ce point dans la leçon suivante). Les fonctions et variables non visibles par l'éditeur de liens sont exclues de cette règle (nous en discuterons plus en détail dans la leçon 7.6 -- Liaison interne).
  3. Les types, les modèles, les fonctions en ligne (inline) et les variables en ligne sont autorisés à avoir des définitions dupliquées dans différents fichiers, à condition que chaque définition soit identique. Nous n'avons pas encore couvert la plupart de ces notions, ne vous en préoccupez donc pas pour l'instant : nous y reviendrons lorsque ce sera pertinent.

Contenu associé

Nous revenons plus en détail sur les exceptions de la partie 3 de l'ODR dans les leçons suivantes :

  • Types (13.1 -- Introduction aux types définis par le programme (types utilisateur)).
  • Modèles de fonctions (11.6 -- Modèles de fonctions et 11.7 -- Instanciation des modèles de fonctions).
  • Fonctions et variables en ligne (7.9 -- Fonctions et variables en ligne).

Violer la partie 1 de l'ODR entraîne une erreur de redéfinition signalée par le compilateur. Violer la partie 2 de l'ODR entraîne une erreur de redéfinition signalée par l'éditeur de liens. Violer la partie 3 de l'ODR entraîne un comportement indéfini.

Voici un exemple de violation de la partie 1 :

int add(int x, int y)
{
     return x + y;
}

int add(int x, int y) // violation de l'ODR, nous avons déjà défini la fonction add(int, int)
{
     return x + y;
}

int main()
{
    int x{};
    int x{ 5 }; // violation de l'ODR, nous avons déjà défini x
}

Dans cet exemple, la fonction add(int, int) est définie deux fois (dans la portée globale), et la variable locale int x est définie deux fois (dans la portée de main()). Le compilateur de Visual Studio produit donc les erreurs de compilation suivantes :


project3.cpp(9): error C2084: function 'int add(int,int)' already has a body
project3.cpp(3): note: see previous definition of 'add'
project3.cpp(16): error C2086: 'int x': redefinition
project3.cpp(15): note: see declaration of 'x'

En revanche, ce n'est pas une violation de la partie 1 de l'ODR que main() possède une variable locale définie comme int x et que add() possède également un paramètre de fonction défini comme int x. Ces définitions se trouvent dans des portées différentes (celle de chaque fonction), elles sont donc considérées comme des définitions distinctes de deux objets différents, et non comme une définition et une redéfinition du même objet.

Pour les lecteurs avancés

Les fonctions qui partagent un même identifiant mais possèdent des ensembles de paramètres différents sont également considérées comme des fonctions distinctes ; de telles définitions ne violent donc pas l'ODR. Nous en discutons davantage dans la leçon 11.1 -- Introduction à la surcharge de fonctions.

Quiz

Question n° 1

Qu'est-ce qu'un prototype de fonction ?

Solution

Un prototype de fonction est une instruction de déclaration qui comprend le nom de la fonction, son type de retour, les types de ses paramètres et, facultativement, les noms des paramètres. Il ne comprend pas le corps de la fonction. Il informe le compilateur de l'existence d'une fonction avant qu'elle ne soit définie.

Question n° 2

Qu'est-ce qu'une déclaration anticipée ?

Solution

Une déclaration anticipée informe le compilateur qu'un identifiant existe avant qu'il ne soit réellement défini.

Question n° 3

Comment déclarer par anticipation une fonction ?

Solution

Pour les fonctions, une déclaration de fonction (prototype) sert de déclaration anticipée.

Question n° 4

Écrivez la déclaration de fonction de cette fonction (utilisez la forme préférée avec les noms) :

int doMath(int first, int second, int third, int fourth)
{
     return first + second * third / fourth;
}
Solution 
// N'oubliez pas le point-virgule à la fin, car il s'agit d'instructions.
int doMath(int first, int second, int third, int fourth);

Question n° 5

Pour chacun des programmes suivants, indiquez s'il ne compile pas, ne se lie pas (ne s'édite pas), ou s'il compile et se lie avec succès. Si vous n'êtes pas sûr, essayez de les compiler !

a)

#include <iostream>
int add(int x, int y);

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}

int add(int x, int y)
{
    return x + y;
}
Solution

Ne compile pas. Le compilateur signalera qu'il ne trouve pas de fonction add() correspondante prenant 3 arguments. La déclaration anticipée de add() ne comporte que deux paramètres.

b)

#include <iostream>
int add(int x, int y);

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}

int add(int x, int y, int z)
{
    return x + y + z;
}
Solution

Ne compile pas. Le compilateur signalera qu'il ne trouve pas de fonction add() correspondante prenant 3 arguments. La déclaration anticipée de add() ne comporte que deux paramètres, et la définition de la fonction add() à 3 paramètres n'a pas encore été rencontrée.

c)

#include <iostream>
int add(int x, int y);

int main()
{
    std::cout << "3 + 4 = " << add(3, 4) << '\n';
    return 0;
}

int add(int x, int y, int z)
{
    return x + y + z;
}
Solution

Ne se lie pas. Le compilateur associe la déclaration anticipée de add à l'appel de add() dans main(). Cependant, aucune fonction add() prenant deux paramètres n'a jamais été implémentée (nous n'en avons implémenté qu'une prenant 3 paramètres), donc l'éditeur de liens signalera une erreur.

d)

#include <iostream>
int add(int x, int y, int z);

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}

int add(int z, int y, int x) // les noms ne correspondent pas à la déclaration
{
    return x + y + z;
}
Solution

Compile et se lie. Les types de l'appel à add() correspondent à la déclaration anticipée, et la définition de add() correspond également. Le fait que les noms ne correspondent pas à la déclaration n'a pas d'importance, car les noms dans une déclaration sont facultatifs (et, s'ils sont fournis, ignorés par le compilateur).

e)

#include <iostream>
int add(int, int, int); // pas de noms de paramètres

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}

int add(int x, int y, int z)
{
    return x + y + z;
}
Solution

Compile et se lie. C'est identique au cas précédent. Les déclarations de fonctions n'ont pas besoin de spécifier les noms des paramètres (même si nous préférons généralement les inclure).

f)

#include <iostream>

int add(int x, int y);

int add(int x, int y, int z)
{
    return x + y + z;
}

int main()
{
    std::cout << "3 + 4 + 5 = " << add(3, 4, 5) << '\n';
    return 0;
}
Solution

Compile et se lie. La déclaration anticipée de add() à deux paramètres n'est pas utilisée.
