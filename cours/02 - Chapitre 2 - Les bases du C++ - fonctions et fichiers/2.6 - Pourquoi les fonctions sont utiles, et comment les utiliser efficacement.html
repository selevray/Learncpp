2.6 — Pourquoi les fonctions sont utiles, et comment les utiliser efficacement

Maintenant que nous avons vu ce que sont les fonctions et quelques-unes de leurs capacités de base, examinons de plus près pourquoi elles sont utiles.

Pourquoi utiliser des fonctions ?

Les nouveaux programmeurs demandent souvent : « Ne peut-on pas simplement mettre tout le code dans la fonction main ? » Pour les programmes simples, c'est tout à fait possible. Cependant, les fonctions apportent un certain nombre d'avantages qui les rendent extrêmement utiles dans les programmes de longueur ou de complexité non triviales.

  • Organisation -- À mesure que les programmes gagnent en complexité, faire tenir tout le code dans la fonction main() devient de plus en plus compliqué. Une fonction est presque un mini-programme que nous pouvons écrire séparément du programme principal, sans avoir à penser au reste du programme pendant son écriture. Cela nous permet de décomposer un programme compliqué en morceaux plus petits et plus faciles à gérer, ce qui réduit la complexité globale de notre programme.
  • Réutilisabilité -- Une fois une fonction écrite, elle peut être appelée plusieurs fois depuis le programme. Cela évite la duplication de code (« Don't Repeat Yourself », ou DRY) et réduit la probabilité d'erreurs de copier-coller. Les fonctions peuvent aussi être partagées avec d'autres programmes, ce qui réduit la quantité de code à écrire à partir de zéro (et à retester) à chaque fois.
  • Tests -- Comme les fonctions réduisent la redondance du code, il y a moins de code à tester en premier lieu. De plus, parce que les fonctions sont autonomes, une fois qu'une fonction a été testée et que son bon fonctionnement est vérifié, nous n'avons plus besoin de la retester à moins de la modifier. Cela réduit la quantité de code à tester à la fois, ce qui facilite grandement la détection des bogues (ou leur évitement dès le départ).
  • Extensibilité -- Lorsque nous devons étendre notre programme pour gérer un cas qu'il ne gérait pas auparavant, les fonctions nous permettent d'effectuer la modification à un seul endroit, et cette modification prend effet à chaque appel de la fonction.
  • Abstraction -- Pour utiliser une fonction, il vous suffit de connaître son nom, ses entrées, ses sorties et l'endroit où elle se trouve. Vous n'avez pas besoin de savoir comment elle fonctionne, ni quel autre code elle utilise, pour l'employer. Cela réduit la somme de connaissances nécessaires pour utiliser le code d'autrui (y compris tout ce qui fait partie de la bibliothèque standard).

Utiliser efficacement les fonctions

L'un des plus grands défis rencontrés par les nouveaux programmeurs (outre l'apprentissage du langage lui-même) consiste à comprendre quand et comment utiliser les fonctions efficacement. Voici quelques consignes de base pour écrire des fonctions :

  • Les groupes d'instructions qui apparaissent plus d'une fois dans un programme devraient généralement être transformés en fonction. Par exemple, si nous lisons une saisie de l'utilisateur plusieurs fois de la même manière, c'est un excellent candidat pour une fonction. Si nous affichons quelque chose de la même façon à plusieurs endroits, c'est aussi un excellent candidat pour une fonction.
  • Le code dont les entrées et les sorties sont bien définies est un bon candidat pour une fonction, en particulier s'il est compliqué. Par exemple, si nous avons une liste d'éléments à trier, le code de tri ferait une excellente fonction, même s'il n'est utilisé qu'une seule fois. L'entrée est la liste non triée, et la sortie est la liste triée. Une autre bonne fonction potentielle serait le code qui simule le lancer d'un dé à 6 faces. Votre programme actuel n'en aura peut-être besoin qu'à un seul endroit, mais si vous en faites une fonction, elle sera prête à être réutilisée si vous étendez plus tard votre programme ou dans un programme futur.
  • Une fonction devrait généralement accomplir une seule tâche (et une seule).
  • Lorsqu'une fonction devient trop longue, trop complexe ou difficile à comprendre, elle peut être découpée en plusieurs sous-fonctions. C'est ce qu'on appelle le refactoring (remaniement du code). Nous reparlerons du refactoring dans la leçon 3.10 -- Détecter les problèmes avant qu'ils ne deviennent critiques.

En général, lorsque vous apprenez le C++, vous écrirez beaucoup de programmes qui impliquent 3 sous-tâches :

  1. Lire les saisies de l'utilisateur
  2. Calculer une valeur à partir des saisies
  3. Afficher la valeur calculée

Pour les programmes triviaux (par exemple, moins de 20 lignes de code), certaines ou toutes ces étapes peuvent être réalisées dans la fonction main. En revanche, pour les programmes plus longs (ou simplement pour s'entraîner), chacune de ces étapes est un bon candidat pour une fonction individuelle.

Les nouveaux programmeurs combinent souvent le calcul d'une valeur et l'affichage de cette valeur dans une seule fonction. Or, cela viole la règle de la « tâche unique » énoncée pour les fonctions. Une fonction qui calcule une valeur devrait renvoyer cette valeur à l'appelant et laisser celui-ci décider de ce qu'il en fait (par exemple, appeler une autre fonction pour afficher la valeur).
