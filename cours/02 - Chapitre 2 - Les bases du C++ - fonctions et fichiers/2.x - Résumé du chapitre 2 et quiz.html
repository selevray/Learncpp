2.x — Résumé du chapitre 2 et quiz

Résumé du chapitre

Une fonction (function) est une séquence d'instructions réutilisable, conçue pour accomplir une tâche particulière. Les fonctions que vous écrivez vous-même sont appelées fonctions définies par l'utilisateur (user-defined).

Un appel de fonction (function call) est une expression qui demande au processeur d'exécuter une fonction. La fonction qui effectue l'appel est l'appelante (caller), et la fonction appelée est la fonction appelée (callee ou called). N'oubliez pas d'inclure les parenthèses lors d'un appel de fonction.

Les accolades et les instructions d'une définition de fonction forment le corps de la fonction (function body).

Une fonction qui renvoie une valeur est appelée fonction à valeur de retour (value-returning function). Le type de retour (return type) d'une fonction indique le type de la valeur qu'elle renverra. L'instruction return détermine la valeur de retour (return value) spécifique renvoyée à l'appelant. Une valeur de retour est copiée de la fonction vers l'appelant : ce processus est appelé retour par valeur (return by value). Ne pas renvoyer de valeur depuis une fonction non-void entraîne un comportement indéfini (undefined behavior).

La valeur de retour de la fonction main est appelée code de statut (status code). Elle indique au système d'exploitation (et à tout autre programme ayant appelé le vôtre) si votre programme s'est exécuté correctement. Par convention, une valeur de retour de 0 signifie succès, et une valeur non nulle signifie échec.

Pratiquez la programmation DRY (Don't Repeat Yourself, « ne vous répétez pas »). Utilisez variables et fonctions pour supprimer le code redondant.

Les fonctions dont le type de retour est void ne renvoient pas de valeur à l'appelant. Une fonction qui ne renvoie pas de valeur est appelée fonction void (void function) ou fonction sans valeur de retour (non-value returning function). Une fonction void ne peut pas être appelée là où une valeur est requise.

Une instruction return qui n'est pas la dernière instruction d'une fonction est appelée retour anticipé (early return). Elle provoque le retour immédiat à l'appelant.

Un paramètre de fonction (function parameter) est une variable utilisée dans une fonction, dont la valeur est fournie par l'appelant. Un argument (argument) est la valeur précise transmise par l'appelant à la fonction. Lorsqu'un argument est copié dans le paramètre, on parle de passage par valeur (pass by value).

Les paramètres de fonction et les variables définies dans le corps de la fonction sont appelés variables locales (local variables). La période pendant laquelle une variable existe est appelée sa durée de vie (lifetime). Les variables sont créées et détruites à l'exécution (runtime), c'est-à-dire pendant que le programme s'exécute. La portée (scope) d'une variable détermine où elle peut être vue et utilisée. Lorsqu'une variable peut être vue et utilisée, on dit qu'elle est dans sa portée (in scope). Lorsqu'elle ne peut pas être vue, donc pas utilisée, on dit qu'elle est hors de portée (out of scope). La portée est une propriété de compilation (compile-time), c'est-à-dire qu'elle est appliquée à la compilation.

Les espaces blancs (whitespace) désignent les caractères utilisés pour la mise en forme. En C++, il s'agit des espaces, des tabulations et des retours à la ligne.

Une déclaration anticipée (forward declaration) permet d'informer le compilateur de l'existence d'un identifiant avant de le définir réellement. Pour écrire une déclaration anticipée de fonction, on utilise un prototype de fonction (function prototype), qui comprend le type de retour, le nom et les paramètres de la fonction, mais pas de corps, suivi d'un point-virgule.

Une définition (definition) implémente (pour les fonctions et les types) ou instancie (pour les variables) un identifiant. Une déclaration (declaration) est une instruction qui informe le compilateur de l'existence d'un identifiant. En C++, toutes les définitions servent aussi de déclarations. Les déclarations pures (pure declarations) sont des déclarations qui ne sont pas aussi des définitions (comme les prototypes de fonctions).

La plupart des programmes non triviaux contiennent plusieurs fichiers.

Lorsque deux identifiants sont introduits dans le même programme d'une façon que le compilateur ou l'éditeur de liens ne peut pas distinguer, ils provoquent une erreur de collision de noms (naming collision). Un espace de noms (namespace) garantit que tous les identifiants qu'il contient sont uniques. L'espace de noms std en est un exemple.

Le préprocesseur (preprocessor) est un processus qui s'exécute sur le code avant sa compilation. Les directives (directives) sont des instructions spéciales destinées au préprocesseur. Elles commencent par le symbole # et se terminent par un retour à la ligne. Une macro (macro) est une règle qui définit comment un texte d'entrée est converti en un texte de sortie de remplacement.

Les fichiers d'en-tête (header files) sont des fichiers conçus pour propager des déclarations vers les fichiers de code. Lors de l'utilisation de la directive #include, cette directive est remplacée par le contenu du fichier inclus. Pour inclure des en-têtes, utilisez les chevrons pour les en-têtes système (par exemple ceux de la bibliothèque standard C++), et les guillemets doubles pour les en-têtes définis par l'utilisateur (ceux que vous écrivez). Pour les en-têtes système, incluez les versions sans extension .h lorsqu'elles existent.

Les gardes d'en-tête (header guards) empêchent le contenu d'un en-tête d'être inclus plus d'une fois dans un même fichier de code. Elles n'empêchent pas le contenu d'un en-tête d'être inclus dans plusieurs fichiers de code différents.

Temps du quiz

Utilisez la fonctionnalité de mise en forme automatique de votre éditeur pour garder une mise en forme cohérente et rendre votre code plus lisible.

Question n° 1

Écrivez un programme monofichier (nommé main.cpp) qui lit deux entiers distincts saisis par l'utilisateur, les additionne, puis affiche le résultat. Le programme doit utiliser trois fonctions :

  • Une fonction nommée « readNumber » sert à obtenir (et à renvoyer) un entier saisi par l'utilisateur.
  • Une fonction nommée « writeAnswer » sert à afficher le résultat. Cette fonction doit prendre un seul paramètre et ne rien renvoyer.
  • Une fonction main() sert à assembler les fonctions précédentes.
Indice

Indice : Il n'est pas nécessaire d'écrire une fonction séparée pour l'addition (utilisez directement operator+).

Indice

Indice : Vous devrez appeler readNumber() deux fois.

Solution

main.cpp :

#include <iostream>

int readNumber()
{
    std::cout << "Enter a number to add: ";
    int x {};
    std::cin >> x;
    return x;
}

void writeAnswer(int x)
{
    std::cout << "The answer is " << x << '\n';
}

int main()
{
    int x { readNumber() };
    int y { readNumber() };
    writeAnswer(x + y); // utilisation de operator+ pour passer la somme de x et y à writeAnswer()
    return 0;
}

Question n° 2

Modifiez le programme écrit dans l'exercice n° 1 afin que readNumber() et writeAnswer() se trouvent dans un fichier séparé nommé « io.cpp ». Utilisez une déclaration anticipée pour y accéder depuis main().

Si vous rencontrez des problèmes, vérifiez que « io.cpp » est bien ajouté à votre projet afin d'être compilé.

Solution

io.cpp :

#include <iostream>

int readNumber()
{
    std::cout << "Enter a number to add: ";
    int x {};
    std::cin >> x;
    return x;
}

void writeAnswer(int x)
{
    std::cout << "The answer is " << x << '\n';
}

main.cpp :

// Nous n'avons pas besoin de #include <iostream> puisque main.cpp n'utilise aucune fonctionnalité d'entrée/sortie

// Ce sont les déclarations anticipées des fonctions de io.cpp
int readNumber();
void writeAnswer(int x);

int main()
{
    int x { readNumber() };
    int y { readNumber() };
    writeAnswer(x+y);
    return 0;
}

Question n° 3

Modifiez le programme écrit à la question n° 2 afin qu'il utilise un fichier d'en-tête (nommé io.h) pour accéder aux fonctions, au lieu d'utiliser directement des déclarations anticipées dans vos fichiers de code (.cpp). Assurez-vous que votre fichier d'en-tête utilise des gardes d'en-tête.

Solution

io.h :

#ifndef IO_H
#define IO_H

int readNumber();
void writeAnswer(int x);

#endif

io.cpp :

#include "io.h"
#include <iostream>

int readNumber()
{
    std::cout << "Enter a number to add: ";
    int x {};
    std::cin >> x;
    return x;
}

void writeAnswer(int x)
{
    std::cout << "The answer is " << x << '\n';
}

main.cpp :

#include "io.h"

int main()
{
    int x { readNumber() };
    int y { readNumber() };
    writeAnswer(x+y);
    return 0;
}

Bien que techniquement io.cpp n'ait pas besoin d'inclure io.h, c'est une bonne pratique pour les fichiers de code d'inclure leur fichier d'en-tête associé. Ceci est traité dans la leçon 2.11 -- Fichiers d'en-tête.

Si vous compilez votre programme et obtenez des erreurs du type de celles-ci :


unresolved external symbol "int __cdecl readNumber(void)" (?readNumber@@YAHXZ)
undefined reference to `readNumber()'

alors vous avez probablement oublié d'inclure io.cpp dans votre projet, de sorte que les définitions de readNumber() (et de writeAnswer()) ne sont pas compilées dans votre projet.
