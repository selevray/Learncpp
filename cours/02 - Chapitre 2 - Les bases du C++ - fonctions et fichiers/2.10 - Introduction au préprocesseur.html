2.10 — Introduction au préprocesseur

Lorsque vous compilez votre projet, vous pourriez vous attendre à ce que le compilateur compile chaque fichier de code exactement tel que vous l'avez écrit. Ce n'est en réalité pas le cas.

En effet, avant la compilation, chaque fichier de code (.cpp) passe par une phase de prétraitement. Durant cette phase, un programme appelé préprocesseur apporte diverses modifications au texte du fichier de code. Le préprocesseur ne modifie en aucune façon les fichiers de code originaux : toutes les modifications qu'il effectue se font soit temporairement en mémoire, soit à l'aide de fichiers temporaires.

En complément…

Historiquement, le préprocesseur était un programme distinct du compilateur, mais dans les compilateurs modernes, le préprocesseur peut être intégré directement au compilateur lui-même.

La plupart des tâches du préprocesseur sont assez peu passionnantes. Par exemple, il supprime les commentaires et s'assure que chaque fichier de code se termine par un saut de ligne. Cependant, le préprocesseur joue un rôle très important : c'est lui qui traite les directives #include (dont nous parlerons plus en détail dans un instant).

Une fois que le préprocesseur a fini de traiter un fichier de code, le résultat est appelé unité de traduction. C'est cette unité de traduction qui est ensuite compilée par le compilateur.

Contenu associé

L'ensemble du processus de prétraitement, de compilation et d'édition de liens est appelé traduction.

Si vous êtes curieux, voici la liste des phases de traduction. Au moment où ces lignes sont écrites, le prétraitement couvre les phases 1 à 4, et la compilation les phases 5 à 7.

Directives du préprocesseur

Lorsque le préprocesseur s'exécute, il parcourt le fichier de code (de haut en bas) à la recherche de directives du préprocesseur. Les directives du préprocesseur (souvent simplement appelées directives) sont des instructions qui commencent par le symbole # et se terminent par un saut de ligne (et NON par un point-virgule). Ces directives indiquent au préprocesseur d'effectuer certaines tâches de manipulation de texte. Notez que le préprocesseur ne comprend pas la syntaxe C++ : les directives ont leur propre syntaxe (qui, dans certains cas, ressemble à celle du C++, et dans d'autres cas, beaucoup moins).

Point clé

La sortie finale du préprocesseur ne contient aucune directive : seul le résultat du traitement des directives est transmis au compilateur.

En complément…

Les using directives (introduites dans la leçon 2.9 -- Collisions de noms et introduction aux espaces de noms) ne sont pas des directives du préprocesseur (et ne sont donc pas traitées par le préprocesseur). Ainsi, si le terme directive désigne généralement une directive du préprocesseur, ce n'est pas toujours le cas.

#include

Vous avez déjà vu la directive #include en action (généralement pour #include <iostream>). Lorsque vous #include un fichier, le préprocesseur remplace la directive #include par le contenu du fichier inclus. Le contenu inclus est ensuite prétraité (ce qui peut entraîner le traitement récursif d'autres #include), puis le reste du fichier est prétraité.

Considérez le programme suivant :

#include <iostream>

int main()
{
    std::cout << "Hello, world!\n";
    return 0;
}

Lorsque le préprocesseur traite ce programme, il remplace #include <iostream> par le contenu du fichier nommé « iostream », puis prétraite le contenu inclus ainsi que le reste du fichier.

Comme #include est presque exclusivement utilisée pour inclure des fichiers d'en-tête, nous étudierons #include plus en détail dans la prochaine leçon (consacrée aux fichiers d'en-tête).

Point clé

Chaque unité de traduction se compose généralement d'un seul fichier de code (.cpp) et de tous les fichiers d'en-tête qu'il #include (appliqué récursivement, car les fichiers d'en-tête peuvent eux-mêmes #include d'autres fichiers d'en-tête).

Définitions de macros avec #define

La directive #define peut être utilisée pour créer une macro. En C++, une macro est une règle qui définit comment un texte d'entrée est converti en un texte de sortie de remplacement.

Il existe deux types de base de macros : les macros de type objet et les macros de type fonction.

Les macros de type fonction se comportent comme des fonctions et servent un but similaire. Leur utilisation est généralement considérée comme dangereuse, et presque tout ce qu'elles peuvent faire peut être réalisé par une fonction normale.

Les macros de type objet peuvent être définies de deux façons :


#define IDENTIFIANT
#define IDENTIFIANT texte_de_substitution

La première définition n'a pas de texte de substitution, alors que la seconde en a un. Comme il s'agit de directives du préprocesseur (et non d'instructions), notez qu'aucune de ces formes ne se termine par un point-virgule.

L'identifiant d'une macro suit les mêmes règles de nommage que les identifiants ordinaires : il peut utiliser des lettres, des chiffres et des tirets bas, ne peut pas commencer par un chiffre, et ne devrait pas commencer par un tiret bas. Par convention, les noms de macros sont généralement entièrement en majuscules, les mots étant séparés par des tirets bas.

Bonne pratique

Les noms de macros doivent être écrits entièrement en majuscules, les mots étant séparés par des tirets bas.

Macros de type objet avec texte de substitution

Lorsque le préprocesseur rencontre cette directive, une association est créée entre l'identifiant de la macro et texte_de_substitution. Toutes les occurrences ultérieures de l'identifiant de la macro (en dehors de leur utilisation dans d'autres commandes du préprocesseur) sont remplacées par le texte_de_substitution.

Considérez le programme suivant :

#include <iostream>

#define MY_NAME "Alex"

int main()
{
    std::cout << "My name is: " << MY_NAME << '\n';

    return 0;
}

Le préprocesseur transforme le programme ci-dessus en le suivant :

// Le contenu de iostream est inséré ici

int main()
{
    std::cout << "My name is: " << "Alex" << '\n';

    return 0;
}

Une fois exécuté, il affiche la sortie My name is: Alex.

Les macros de type objet avec texte de substitution étaient utilisées (en C) pour donner des noms à des littéraux. Ce n'est plus nécessaire, car de meilleures méthodes sont disponibles en C++ (voir 7.10 -- Partager des constantes globales entre plusieurs fichiers (à l'aide de variables inline)). Les macros de type objet avec texte de substitution se rencontrent désormais surtout dans du code hérité, et nous recommandons de les éviter dans la mesure du possible.

Bonne pratique

Évitez les macros avec texte de substitution, sauf si aucune alternative viable n'existe.

Macros de type objet sans texte de substitution

Les macros de type objet peuvent aussi être définies sans texte de substitution.

Par exemple :

#define USE_YEN

Les macros de cette forme fonctionnent comme on pourrait s'y attendre : toutes les occurrences ultérieures de l'identifiant sont supprimées et remplacées par rien !

Cela peut sembler peu utile, et ça l'est effectivement pour faire de la substitution de texte. Toutefois, ce n'est pas à cela que sert généralement cette forme de la directive. Nous en verrons les usages dans un instant.

Contrairement aux macros de type objet avec texte de substitution, les macros de cette forme sont généralement considérées comme acceptables.

Compilation conditionnelle

Les directives de compilation conditionnelle vous permettent de préciser dans quelles conditions un élément sera ou ne sera pas compilé. Il existe de nombreuses directives de compilation conditionnelle, mais nous n'en verrons que quelques-unes parmi les plus utilisées : #ifdef, #ifndef et #endif.

La directive du préprocesseur #ifdef permet au préprocesseur de vérifier si un identifiant a été préalablement défini via #define. Si c'est le cas, le code compris entre #ifdef et le #endif correspondant est compilé. Sinon, le code est ignoré.

Considérez le programme suivant :

#include <iostream>

#define PRINT_JOE

int main()
{
#ifdef PRINT_JOE
    std::cout << "Joe\n"; // will be compiled since PRINT_JOE is defined
#endif

#ifdef PRINT_BOB
    std::cout << "Bob\n"; // will be excluded since PRINT_BOB is not defined
#endif

    return 0;
}

Comme PRINT_JOE a été défini avec #define, la ligne std::cout << "Joe\n" sera compilée. Comme PRINT_BOB n'a pas été défini avec #define, la ligne std::cout << "Bob\n" sera ignorée.

#ifndef est l'opposé de #ifdef : il permet de vérifier qu'un identifiant n'a PAS encore été défini avec #define.

#include <iostream>

int main()
{
#ifndef PRINT_BOB
    std::cout << "Bob\n";
#endif

    return 0;
}

Ce programme affiche « Bob », car PRINT_BOB n'a jamais été défini avec #define.

À la place de #ifdef PRINT_BOB et #ifndef PRINT_BOB, vous verrez également #if defined(PRINT_BOB) et #if !defined(PRINT_BOB). Ces formes sont équivalentes, mais utilisent une syntaxe un peu plus proche du style C++.

Vous verrez un usage pratique de cette fonctionnalité dans la leçon 0.13 -- Quel standard du langage mon compilateur utilise-t-il ?.

#if 0

Un autre usage courant de la compilation conditionnelle consiste à utiliser #if 0 pour exclure un bloc de code de la compilation (comme s'il était placé dans un bloc de commentaire) :

#include <iostream>

int main()
{
    std::cout << "Joe\n";

#if 0 // Don't compile anything starting here
    std::cout << "Bob\n";
    std::cout << "Steve\n";
#endif // until this point

    return 0;
}

Le code ci-dessus n'affiche que « Joe », car « Bob » et « Steve » sont exclus de la compilation par la directive du préprocesseur #if 0.

Cela offre un moyen pratique de « commenter » du code contenant des commentaires multilignes (qu'on ne peut pas commenter à l'aide d'un autre commentaire multiligne, car les commentaires multilignes ne sont pas imbriquables) :

#include <iostream>

int main()
{
    std::cout << "Joe\n";

#if 0 // Don't compile anything starting here
    std::cout << "Bob\n";
    /* Some
     * multi-line
     * comment here
     */
    std::cout << "Steve\n";
#endif // until this point

    return 0;
}

Pour réactiver temporairement du code enveloppé dans un #if 0, vous pouvez remplacer #if 0 par #if 1 :

#include <iostream>

int main()
{
    std::cout << "Joe\n";

#if 1 // always true, so the following code will be compiled
    std::cout << "Bob\n";
    /* Some
     * multi-line
     * comment here
     */
    std::cout << "Steve\n";
#endif

    return 0;
}

Substitution de macros dans les autres commandes du préprocesseur

Vous vous demandez peut-être, à propos du code suivant :

#define PRINT_JOE

int main()
{
#ifdef PRINT_JOE
    std::cout << "Joe\n"; // will be compiled since PRINT_JOE is defined
#endif

    return 0;
}

Puisque nous avons défini PRINT_JOE comme n'ayant aucun contenu, pourquoi le préprocesseur n'a-t-il pas remplacé PRINT_JOE dans #ifdef PRINT_JOE par rien, excluant ainsi l'instruction d'affichage de la compilation ?

Dans la plupart des cas, la substitution de macro ne se produit pas lorsqu'un identifiant de macro est utilisé à l'intérieur d'une autre commande du préprocesseur.

En complément…

Il existe au moins une exception à cette règle : la plupart des formes de #if et #elif effectuent une substitution de macro à l'intérieur de la commande du préprocesseur.

Voici un autre exemple :

#define FOO 9 // Here's a macro substitution

#ifdef FOO // This FOO does not get replaced with 9 because it’s part of another preprocessor directive
    std::cout << FOO << '\n'; // This FOO gets replaced with 9 because it's part of the normal code
#endif

La portée des #define

Les directives sont traitées avant la compilation, de haut en bas, fichier par fichier.

Considérez le programme suivant :

#include <iostream>

void foo()
{
#define MY_NAME "Alex"
}

int main()
{
    std::cout << "My name is: " << MY_NAME << '\n';

    return 0;
}

Bien qu'il semble que #define MY_NAME “Alex” soit défini à l'intérieur de la fonction foo, le préprocesseur ne comprend pas les concepts C++ comme les fonctions. Ce programme se comporte donc exactement comme un programme où #define MY_NAME “Alex” serait défini soit avant, soit immédiatement après la fonction foo. Pour éviter toute confusion, vous devriez généralement définir les identifiants en dehors des fonctions.

Comme une directive #include remplace la directive #include par le contenu du fichier inclus, un #include peut copier des directives du fichier inclus dans le fichier courant. Ces directives sont alors traitées dans l'ordre.

Par exemple, le code suivant se comporte également de manière identique aux exemples précédents :

Alex.h :

#define MY_NAME "Alex"

main.cpp :

#include "Alex.h" // copies #define MY_NAME from Alex.h here
#include <iostream>

int main()
{
    std::cout << "My name is: " << MY_NAME << '\n'; // preprocessor replaces MY_NAME with "Alex"

    return 0;
}

Une fois le préprocesseur terminé, tous les identifiants définis dans ce fichier sont abandonnés. Cela signifie que les directives ne sont valides que depuis le point de leur définition jusqu'à la fin du fichier dans lequel elles sont définies. Les directives définies dans un fichier n'ont aucun effet sur les autres fichiers (sauf s'ils sont #include dans un autre fichier). Par exemple :

function.cpp :

#include <iostream>

void doSomething()
{
#ifdef PRINT
    std::cout << "Printing!\n";
#endif
#ifndef PRINT
    std::cout << "Not printing!\n";
#endif
}

main.cpp :

void doSomething(); // forward declaration for function doSomething()

#define PRINT

int main()
{
    doSomething();

    return 0;
}

Le programme ci-dessus affichera :


Not printing!

Bien que PRINT ait été défini dans main.cpp, cela n'a aucun effet sur le code de function.cpp (PRINT n'est défini avec #define qu'à partir du point de définition jusqu'à la fin de main.cpp). Cela aura des conséquences lorsque nous aborderons les gardes d'inclusion dans une future leçon.
