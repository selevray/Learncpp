2.2 — Valeurs de retour des fonctions (fonctions renvoyant une valeur)

Considérez le programme suivant :

#include <iostream>

int main()
{
    // get a value from the user
    std::cout << "Enter an integer: ";
    int num{};
    std::cin >> num;

    // print the value doubled
    std::cout << num << " doubled is: " << num * 2 << '\n';

    return 0;
}

Ce programme se compose de deux parties conceptuelles : d'abord, nous obtenons une valeur de l'utilisateur, puis nous lui indiquons le double de cette valeur.

Bien que ce programme soit suffisamment simple pour ne pas nécessiter d'être découpé en plusieurs fonctions, que se passerait-il si nous voulions le faire ? Obtenir un entier de l'utilisateur est une tâche bien définie que notre programme doit accomplir, c'est donc un bon candidat pour une fonction.

Écrivons donc un programme qui fait cela :

// This program doesn't work
#include <iostream>

void getValueFromUser()
{
    std::cout << "Enter an integer: ";
    int input{};
    std::cin >> input;  
}

int main()
{
    getValueFromUser(); // Ask user for input

    int num{}; // How do we get the value from getValueFromUser() and use it to initialize this variable?

    std::cout << num << " doubled is: " << num * 2 << '\n';

    return 0;
}

Bien que ce programme soit une bonne tentative de solution, il ne fonctionne pas tout à fait.

Lorsque la fonction getValueFromUser est appelée, l'utilisateur est invité à saisir un entier, comme prévu. Mais la valeur saisie est perdue lorsque getValueFromUser se termine et que le contrôle revient à main. La variable num n'est jamais initialisée avec la valeur saisie par l'utilisateur, et le programme affiche donc toujours la réponse 0.

Ce qui nous manque, c'est un moyen pour getValueFromUser de renvoyer la valeur saisie par l'utilisateur à main, afin que main puisse utiliser cette donnée.

Valeurs de retour

Lorsque vous écrivez une fonction définie par l'utilisateur, vous décidez si cette fonction renverra ou non une valeur à l'appelant. Pour renvoyer une valeur à l'appelant, deux éléments sont nécessaires.

Premièrement, votre fonction doit indiquer le type de la valeur renvoyée. Cela se fait en définissant le type de retour de la fonction, c'est-à-dire le type qui précède le nom de la fonction. Dans l'exemple ci-dessus, la fonction getValueFromUser a un type de retour void (ce qui signifie qu'aucune valeur ne sera renvoyée à l'appelant), et la fonction main a un type de retour int (ce qui signifie qu'une valeur de type int sera renvoyée à l'appelant). Notez que cela ne détermine pas la valeur précise qui est renvoyée, mais seulement le type de la valeur renvoyée.

Contenu associé

Nous étudierons plus en détail les fonctions renvoyant void dans la leçon suivante (2.3 -- Fonctions void (fonctions ne renvoyant pas de valeur)).

Deuxièmement, à l'intérieur de la fonction qui renverra une valeur, nous utilisons une instruction return pour indiquer la valeur précise renvoyée à l'appelant. L'instruction return se compose du mot-clé return, suivi d'une expression (parfois appelée expression de retour), et se termine par un point-virgule.

Lorsque l'instruction return est exécutée :

  • L'expression de retour est évaluée pour produire une valeur.
  • La valeur produite par l'expression de retour est copiée vers l'appelant. Cette copie est appelée la valeur de retour de la fonction.
  • La fonction se termine et le contrôle revient à l'appelant.

Le processus de renvoi d'une valeur copiée à l'appelant est appelé retour par valeur (return by value).

Nomenclature

L'expression de retour produit la valeur à renvoyer. La valeur de retour est une copie de cette valeur.

Une fonction renvoyant une valeur retournera une valeur à chaque fois qu'elle est appelée.

Examinons une fonction simple qui renvoie une valeur entière, ainsi qu'un programme d'exemple qui l'appelle :

#include <iostream>

// int is the return type
// A return type of int means the function will return some integer value to the caller (the specific value is not specified here)
int returnFive()
{
    // the return statement provides the value that will be returned
    return 5; // return the value 5 back to the caller
}

int main()
{
    std::cout << returnFive() << '\n'; // prints 5
    std::cout << returnFive() + 2 << '\n'; // prints 7

    returnFive(); // okay: the value 5 is returned, but is ignored since main() doesn't do anything with it

    return 0;
}

Lors de son exécution, ce programme affiche :


5
7

L'exécution commence en haut de main. Dans la première instruction, l'appel de fonction returnFive() est évalué, ce qui entraîne l'appel de la fonction returnFive(). L'expression de retour 5 est évaluée pour produire la valeur 5, qui est renvoyée à l'appelant et affichée à la console via std::cout.

Lors du deuxième appel, l'appel à returnFive est évalué, ce qui entraîne à nouveau l'appel de la fonction returnFive. La fonction returnFive renvoie la valeur 5 à l'appelant. L'expression 5 + 2 est évaluée pour produire le résultat 7, qui est ensuite affiché à la console via std::cout.

Dans la troisième instruction, la fonction returnFive est de nouveau appelée, ce qui renvoie la valeur 5 à l'appelant. Cependant, la fonction main ne fait rien de cette valeur de retour, il ne se passe donc rien de plus (la valeur de retour est ignorée).

Remarque : les valeurs de retour ne sont affichées que si l'appelant les envoie à la console via std::cout. Dans le dernier cas ci-dessus, la valeur de retour n'est pas envoyée à std::cout, donc rien n'est affiché.

Astuce

Lorsqu'une fonction appelée renvoie une valeur, l'appelant peut décider d'utiliser cette valeur dans une expression ou une instruction (par exemple pour initialiser une variable, ou pour l'envoyer à std::cout) ou de l'ignorer (en ne faisant rien d'autre). Si l'appelant ignore la valeur de retour, elle est jetée (rien n'est fait avec elle).

Correction de notre programme d'exercice

Dans cet esprit, nous pouvons corriger le programme présenté au début de la leçon :

#include <iostream>

int getValueFromUser() // this function now returns an integer value
{
    std::cout << "Enter an integer: ";
    int input{};
    std::cin >> input;  

    return input; // return the value the user entered back to the caller
}

int main()
{
    int num { getValueFromUser() }; // initialize num with the return value of getValueFromUser()

    std::cout << num << " doubled is: " << num * 2 << '\n';

    return 0;
}

Lorsque ce programme s'exécute, la première instruction de main crée une variable int nommée num. Lorsque le programme s'apprête à initialiser num, il voit un appel à getValueFromUser() et exécute donc cette fonction. La fonction getValueFromUser demande à l'utilisateur de saisir une valeur, puis renvoie cette valeur à l'appelant (main()). Cette valeur de retour sert de valeur d'initialisation à la variable num. num peut ensuite être utilisée autant de fois que nécessaire dans main().

Astuce

Si vous devez utiliser la valeur de retour d'un appel de fonction plusieurs fois, initialisez une variable avec cette valeur de retour, puis utilisez cette variable autant de fois que nécessaire.

Compilez ce programme vous-même et exécutez-le quelques fois pour vous convaincre qu'il fonctionne.

Retour sur main()

Vous disposez maintenant des outils conceptuels pour comprendre le fonctionnement réel de la fonction main(). Lorsque le programme est exécuté, le système d'exploitation effectue un appel de fonction à main(). L'exécution saute alors au début de main(). Les instructions de main() sont exécutées séquentiellement. Enfin, main() renvoie une valeur entière (généralement 0), et votre programme se termine.

En C++, main() est soumise à deux exigences particulières :

  • main() doit obligatoirement renvoyer un int.
  • Les appels explicites à main() sont interdits.
void foo()
{
    main(); // Compile error: main not allowed to be called explicitly
}

void main() // Compile error: main not allowed to have non-int return type
{
    foo();
}

Point clé

Le C autorise les appels explicites à main(), donc certains compilateurs C++ l'autorisent également pour des raisons de compatibilité.

Pour le moment, définissez également votre fonction main() en bas de votre fichier de code, après les autres fonctions, et évitez de l'appeler explicitement.

Pour les lecteurs avancés

C'est une idée reçue courante que main est toujours la première fonction exécutée.

Les variables globales sont initialisées avant l'exécution de main. Si l'initialiseur d'une telle variable appelle une fonction, cette fonction s'exécutera avant main. Nous aborderons les variables globales dans la leçon 7.4 -- Introduction aux variables globales.

Codes de statut

Vous vous demandez peut-être pourquoi nous renvoyons 0 depuis main(), et quand nous pourrions renvoyer autre chose.

La valeur de retour de main() est parfois appelée code de statut (ou, plus rarement, code de sortie, ou très rarement code de retour). Le code de statut sert à signaler si votre programme s'est bien déroulé ou non.

Par convention, un code de statut de 0 signifie que le programme s'est exécuté normalement (c'est-à-dire que le programme s'est exécuté et a eu le comportement attendu).

Bonne pratique

Votre fonction main doit renvoyer la valeur 0 si le programme s'est exécuté normalement.

Un code de statut non nul est souvent utilisé pour indiquer une sorte d'échec (et bien que cela fonctionne sur la plupart des systèmes d'exploitation, strictement parlant, ce n'est pas garanti comme portable).

Pour les lecteurs avancés

La norme C++ ne définit la signification que de 3 codes de statut : 0, EXIT_SUCCESS et EXIT_FAILURE. 0 et EXIT_SUCCESS signifient tous deux que le programme s'est exécuté avec succès. EXIT_FAILURE signifie que le programme ne s'est pas exécuté avec succès.

EXIT_SUCCESS et EXIT_FAILURE sont des macros du préprocesseur définies dans l'en-tête <cstdlib> :

#include <cstdlib> // for EXIT_SUCCESS and EXIT_FAILURE

int main()
{
    return EXIT_SUCCESS;
}

Si vous souhaitez maximiser la portabilité, vous ne devez utiliser que 0 ou EXIT_SUCCESS pour indiquer une fin réussie, ou EXIT_FAILURE pour indiquer une fin en échec.

Nous aborderons le préprocesseur et ses macros dans la leçon 2.10 -- Introduction au préprocesseur.

En passant…

Le code de statut est transmis au système d'exploitation. Le système d'exploitation rend généralement ce code de statut disponible au programme qui a lancé le programme renvoyant ce code. Cela constitue un mécanisme rudimentaire permettant à un programme lançant un autre programme de déterminer si le programme lancé s'est exécuté avec succès ou non.

Une fonction renvoyant une valeur qui ne renvoie pas de valeur produit un comportement indéfini

Une fonction qui renvoie une valeur est appelée fonction renvoyant une valeur (value-returning function). Une fonction est dite renvoyant une valeur lorsque son type de retour est autre que void.

Une fonction renvoyant une valeur doit renvoyer une valeur de ce type (à l'aide d'une instruction return), sans quoi un comportement indéfini en résultera.

Contenu associé

Nous abordons le comportement indéfini dans la leçon 1.6 -- Variables non initialisées et comportement indéfini.

Voici un exemple de fonction qui produit un comportement indéfini :

#include <iostream>

int getValueFromUserUB() // this function returns an integer value
{
    std::cout << "Enter an integer: ";
    int input{};
    std::cin >> input;

    // note: no return statement
}

int main()
{
    int num { getValueFromUserUB() }; // initialize num with the return value of getValueFromUserUB()

    std::cout << num << " doubled is: " << num * 2 << '\n';

    return 0;
}

Un compilateur moderne devrait générer un avertissement, car getValueFromUserUB est définie comme renvoyant un int, mais aucune instruction return n'est fournie. Exécuter un tel programme produirait un comportement indéfini, car getValueFromUserUB() est une fonction renvoyant une valeur qui ne renvoie pas de valeur.

Dans la plupart des cas, les compilateurs détectent un oubli de retour de valeur. Cependant, dans certains cas complexes, le compilateur peut ne pas être capable de déterminer correctement si votre fonction renvoie une valeur dans tous les cas, vous ne devez donc pas vous y fier.

Bonne pratique

Assurez-vous que vos fonctions à type de retour non void renvoient une valeur dans tous les cas.

L'absence de retour de valeur depuis une fonction renvoyant une valeur provoque un comportement indéfini.

La fonction main renvoie implicitement 0 si aucune instruction return n'est fournie

La seule exception à la règle selon laquelle une fonction renvoyant une valeur doit retourner une valeur par une instruction return concerne la fonction main(). La fonction main() renvoie implicitement la valeur 0 si aucune instruction return n'est fournie. Cela dit, il est recommandé de renvoyer explicitement une valeur depuis main, à la fois pour montrer votre intention et par cohérence avec les autres fonctions (qui provoqueront un comportement indéfini si aucune valeur de retour n'est spécifiée).

Une fonction ne peut renvoyer qu'une seule valeur

Une fonction renvoyant une valeur ne peut renvoyer qu'une seule valeur à l'appelant à chaque appel.

Notez que la valeur fournie dans une instruction return n'a pas besoin d'être littérale : elle peut être le résultat de n'importe quelle expression valide, y compris une variable ou même un appel à une autre fonction renvoyant une valeur. Dans l'exemple getValueFromUser() ci-dessus, nous avons renvoyé une variable input, qui contenait le nombre saisi par l'utilisateur.

Il existe différentes façons de contourner la limitation selon laquelle une fonction ne peut renvoyer qu'une seule valeur, que nous verrons dans les leçons suivantes.

L'auteur de la fonction décide de la signification de la valeur de retour

La signification de la valeur renvoyée par une fonction est déterminée par l'auteur de cette fonction. Certaines fonctions utilisent leurs valeurs de retour comme codes de statut, pour indiquer si elles ont réussi ou échoué. D'autres fonctions renvoient une valeur calculée ou sélectionnée. D'autres encore ne renvoient rien (nous verrons des exemples de ces dernières dans la leçon suivante).

En raison de la grande diversité de ces possibilités, il est judicieux de documenter votre fonction avec un commentaire indiquant la signification des valeurs de retour. Par exemple :

// Function asks user to enter a value
// Return value is the integer entered by the user from the keyboard
int getValueFromUser()
{
    std::cout << "Enter an integer: ";
    int input{};
    std::cin >> input;  

    return input; // return the value the user entered back to the caller
}

Réutiliser des fonctions

Nous pouvons maintenant illustrer un bon cas de réutilisation de fonction. Considérez le programme suivant :

#include <iostream>

int main()
{
    int x{};
    std::cout << "Enter an integer: ";
    std::cin >> x; 

    int y{};
    std::cout << "Enter an integer: ";
    std::cin >> y; 

    std::cout << x << " + " << y << " = " << x + y << '\n';

    return 0;
}

Bien que ce programme fonctionne, il est un peu redondant. En effet, ce programme enfreint l'un des principes fondamentaux de la bonne programmation : Don't Repeat Yourself (souvent abrégé en DRY, soit « ne vous répétez pas »).

Pourquoi le code répété est-il mauvais ? Si nous voulions remplacer le texte « Enter an integer: » par autre chose, nous devrions le modifier à deux endroits. Et si nous voulions initialiser 10 variables au lieu de 2 ? Cela ferait beaucoup de code redondant (rallongeant nos programmes et les rendant plus difficiles à comprendre), et beaucoup de place pour que des coquilles s'y glissent.

Mettons à jour ce programme pour utiliser la fonction getValueFromUser que nous avons développée plus haut :

#include <iostream>

int getValueFromUser()
{
    std::cout << "Enter an integer: ";
    int input{};
    std::cin >> input;  

    return input;
}

int main()
{
    int x{ getValueFromUser() }; // first call to getValueFromUser
    int y{ getValueFromUser() }; // second call to getValueFromUser

    std::cout << x << " + " << y << " = " << x + y << '\n';

    return 0;
}

Ce programme produit la sortie suivante :


Enter an integer: 5
Enter an integer: 7
5 + 7 = 12

Dans ce programme, nous appelons getValueFromUser deux fois : une fois pour initialiser la variable x, et une fois pour initialiser la variable y. Cela nous évite de dupliquer le code permettant de récupérer la saisie utilisateur, et réduit les risques d'erreur. Une fois que nous savons que getValueFromUser fonctionne, nous pouvons l'appeler autant de fois que nous le souhaitons.

C'est l'essence même de la programmation modulaire : la capacité d'écrire une fonction, de la tester, de s'assurer qu'elle fonctionne, puis de savoir que nous pouvons la réutiliser autant de fois que nous le voulons en continuant de fonctionner (tant que nous ne la modifions pas, auquel cas il faudra la retester).

Bonne pratique

Appliquez le principe DRY : « Don't Repeat Yourself » (ne vous répétez pas). Si vous devez faire quelque chose plus d'une fois, réfléchissez à la manière de modifier votre code pour supprimer autant de redondance que possible. Les variables peuvent servir à stocker les résultats de calculs qui doivent être utilisés plus d'une fois (afin de ne pas répéter le calcul). Les fonctions peuvent servir à définir une séquence d'instructions que nous voulons exécuter plusieurs fois. Et les boucles (que nous verrons dans un chapitre ultérieur) peuvent servir à exécuter une instruction plusieurs fois.

Comme toutes les bonnes pratiques, DRY est destiné à être une ligne directrice, et non un absolu. Le lecteur Yariv a fait remarquer que DRY peut nuire à la compréhension globale lorsque le code est découpé en morceaux trop petits.

En passant…

Le contraire (sarcastique) de DRY est WET (« Write everything twice », soit « écrivez tout deux fois »).

Conclusion

Les valeurs de retour fournissent un moyen pour les fonctions de renvoyer une seule valeur à l'appelant de la fonction.

Les fonctions fournissent un moyen de minimiser la redondance dans nos programmes.

Supposez que l'option « traiter les avertissements comme des erreurs » est désactivée.

1a)

#include <iostream>

int return7()

    return 7;

int return9()
{

}

int main()
{

Ce programme affiche le nombre 16.

#include <iostream>

int return7()
{
    return 7;

    int return9()
    {
        return 9;
    }
}

int main()
{
    std::cout << return7() + return9() << '\n';

    return 0;
}
Solution

Ce programme ne compilera pas. Les fonctions imbriquées ne sont pas autorisées.

1c)

#include <iostream>

int return7()
{
    return 7;
}

int return9()
{
    return 9;
}

int main()
{
    return7();
    return9();

    return 0;
}
Solution

Ce programme compile mais ne produit aucune sortie. Les valeurs de retour des fonctions ne sont utilisées à rien (et sont donc jetées).

1d)

#include <iostream>

int getNumbers()
{
    return 5;
    return 7;
}

int main()
{
    std::cout << getNumbers() << '\n';
    std::cout << getNumbers() << '\n';

    return 0;
}
Solution

Ce programme affiche 5 deux fois (sur des lignes distinctes). À chaque appel de la fonction getNumbers(), l'instruction return 5; s'exécute, et le programme renvoie la valeur 5 à l'appelant. L'instruction return 7; ne s'exécute jamais.

int return 5()
{
    return 5;
}

int main()
{
    std::cout << return 5() << '\n';

    return 0;
}
Solution

Ce programme ne compilera pas, car la fonction a un nom invalide. Nous avons parlé des règles de nommage dans la leçon 1.7 -- Mots-clés et nommage des identifiants.

Question n° 2

Que signifie « DRY », et pourquoi est-il utile de suivre ce principe ?

Solution

DRY signifie « Don't Repeat Yourself » (ne vous répétez pas). C'est une pratique qui consiste à écrire votre code de manière à minimiser la redondance. Cela rend vos programmes plus concis, moins sujets aux erreurs et plus faciles à maintenir.
