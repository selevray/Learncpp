26.5 — Spécialisation partielle de modèles

Cette leçon et la suivante sont des lectures facultatives destinées à ceux qui souhaitent approfondir les modèles (templates) en C++. La spécialisation partielle de modèles n'est pas très utilisée (mais elle peut être utile dans des cas précis).

Dans la leçon 26.2 -- Paramètres non-type de modèles, vous avez appris que des paramètres d'expression pouvaient servir à paramétrer des classes modèles.

Reprenons la classe Static Array que nous avons utilisée dans l'un de nos exemples précédents :

template <typename T, int size> // size is the expression parameter
class StaticArray
{
private:
    // The expression parameter controls the size of the array
    T m_array[size]{};

public:
    T* getArray() { return m_array; }

    const T& operator[](int index) const { return m_array[index]; }
    T& operator[](int index) { return m_array[index]; }
};

Cette classe prend deux paramètres de modèle : un paramètre de type et un paramètre d'expression.

Supposons maintenant que nous voulions écrire une fonction affichant l'intégralité du tableau. Nous pourrions en faire une fonction membre, mais nous allons plutôt en faire une fonction non membre, car cela rendra les exemples suivants plus faciles à suivre.

Avec les modèles, nous pourrions écrire quelque chose comme ceci :

template <typename T, int size>
void print(const StaticArray<T, size>& array)
{
    for (int count{ 0 }; count < size; ++count)
        std::cout << array[count] << ' ';
}

Cela nous permet de faire ce qui suit :

#include <iostream>

template <typename T, int size> // size is a template non-type parameter
class StaticArray
{
private:
    T m_array[size]{};

public:
    T* getArray() { return m_array; }

    const T& operator[](int index) const { return m_array[index]; }
    T& operator[](int index) { return m_array[index]; }
};

template <typename T, int size>
void print(const StaticArray<T, size>& array)
{
    for (int count{ 0 }; count < size; ++count)
        std::cout << array[count] << ' ';
}

int main()
{
    // declare an int array
    StaticArray<int, 4> int4{};
    int4[0] = 0;
    int4[1] = 1;
    int4[2] = 2;
    int4[3] = 3;

    // Print the array
    print(int4);

    return 0;
}

et l'on obtient le résultat suivant :


0 1 2 3

Bien que cela fonctionne, cette approche présente un défaut de conception. Considérez le programme suivant :

#include <algorithm>
#include <iostream>
#include <string_view>

int main()
{
    // Declare a char array
    StaticArray<char, 14> char14{};

    // Copy some data into it
    constexpr std::string_view hello{ "Hello, world!" };
    std::copy_n(hello.begin(), hello.size(), char14.getArray());

    // Print the array
    print(char14);

    return 0;
}

(Nous avons abordé std::strcpy dans la leçon 17.10 -- Chaînes de style C si vous avez besoin d'un rappel)

Ce programme se compile, s'exécute et produit la valeur suivante (ou une valeur similaire) :


H e l l o ,   w o r l d !

Pour les types autres que char, il est logique de placer un espace entre chaque élément du tableau, afin qu'ils ne se confondent pas. En revanche, avec le type char, il est plus logique d'afficher tout d'un bloc, comme une chaîne de style C, ce que notre fonction print() ne fait pas.

Comment corriger cela ?

La spécialisation de modèle à la rescousse ?

On pourrait d'abord penser à utiliser la spécialisation de modèle. Le problème de la spécialisation complète de modèle est que tous les paramètres de modèle doivent être explicitement définis.

Considérez :

#include <algorithm>
#include <iostream>
#include <string_view>

template <typename T, int size> // size is the expression parameter
class StaticArray
{
private:
    // The expression parameter controls the size of the array
    T m_array[size]{};

public:
    T* getArray() { return m_array; }

    const T& operator[](int index) const { return m_array[index]; }
    T& operator[](int index) { return m_array[index]; }
};

template <typename T, int size>
void print(const StaticArray<T, size>& array)
{
    for (int count{ 0 }; count < size; ++count)
        std::cout << array[count] << ' ';
}

// Override print() for fully specialized StaticArray<char, 14>
template <>
void print(const StaticArray<char, 14>& array)
{
    for (int count{ 0 }; count < 14; ++count)
        std::cout << array[count];
}

int main()
{
    // Declare a char array
    StaticArray<char, 14> char14{};

    // Copy some data into it
    constexpr std::string_view hello{ "Hello, world!" };
    std::copy_n(hello.begin(), hello.size(), char14.getArray());

    // Print the array
    print(char14);

    return 0;
}

Comme vous pouvez le voir, nous avons maintenant fourni une surcharge de print pour StaticArray<char, 14> entièrement spécialisé. En effet, cela affiche :


Hello, world!

Bien que cela résolve le problème de l'appel de print() avec un StaticArray<char, 14>, cela pose un autre problème : la spécialisation complète oblige à définir explicitement la longueur du tableau que cette fonction acceptera ! Considérez l'exemple suivant :

int main()
{
    // Declare a char array
    StaticArray<char, 12> char12{};

    // Copy some data into it
    constexpr std::string_view hello{ "Hello, mom!" };
    std::copy_n(hello.begin(), hello.size(), char12.getArray());

    // Print the array
    print(char12);

    return 0;
}

Appeler print() avec char12 appellera la version de print() qui prend un StaticArray<T, size>, car char12 est de type StaticArray<char, 12>, et notre surcharge de print() ne sera appelée que pour un StaticArray<char, 14>.

Nous pourrions bien sûr copier print() pour gérer StaticArray<char, 12>, mais que se passera-t-il lorsque nous voudrons appeler print() avec un tableau de taille 5, ou 22 ? Il faudrait copier la fonction pour chaque taille différente. C'est redondant.

De toute évidence, la spécialisation complète de modèle est une solution trop restrictive ici. La solution que nous recherchons est la spécialisation partielle de modèle.

Spécialisation partielle de modèle

La spécialisation partielle de modèle permet de spécialiser des classes (mais pas des fonctions individuelles !) dans lesquelles certains, mais pas tous, les paramètres de modèle ont été explicitement définis. Pour notre problème ci-dessus, la solution idéale serait que notre surcharge de print fonctionne avec un StaticArray de type char, tout en laissant le paramètre d'expression de longueur templatisé afin qu'il puisse varier selon les besoins. La spécialisation partielle de modèle permet précisément cela !

Voici notre exemple avec une surcharge de la fonction print qui prend un StaticArray partiellement spécialisé :

// overload of print() function for partially specialized StaticArray<char, size>
template <int size> // size is still a template non-type parameter
void print(const StaticArray<char, size>& array) // we're explicitly defining type char here
{
    for (int count{ 0 }; count < size; ++count)
        std::cout << array[count];
}

Comme vous le voyez ici, nous avons explicitement déclaré que cette fonction ne fonctionnera que pour un StaticArray de type char, mais size est toujours un paramètre d'expression templatisé, donc elle fonctionnera pour des tableaux de caractères de n'importe quelle taille. C'est tout !

Voici un programme complet qui l'utilise :

#include <algorithm>
#include <iostream>
#include <string_view>

template <typename T, int size> // size is the expression parameter
class StaticArray
{
private:
    // The expression parameter controls the size of the array
    T m_array[size]{};

public:
    T* getArray() { return m_array; }

    const T& operator[](int index) const { return m_array[index]; }
    T& operator[](int index) { return m_array[index]; }
};

template <typename T, int size>
void print(const StaticArray<T, size>& array)
{
    for (int count{ 0 }; count < size; ++count)
        std::cout << array[count] << ' ';
}

// overload of print() function for partially specialized StaticArray<char, size>
template <int size>
void print(const StaticArray<char, size>& array)
{
    for (int count{ 0 }; count < size; ++count)
        std::cout << array[count];
}

int main()
{
    // Declare an char array of size 14
    StaticArray<char, 14> char14{};

    // Copy some data into it
    constexpr std::string_view hello14{ "Hello, world!" };
    std::copy_n(hello14.begin(), hello14.size(), char14.getArray());

    // Print the array
    print(char14);

    std::cout << ' ';

    // Now declare an char array of size 12
    StaticArray<char, 12> char12{};

    // Copy some data into it
    constexpr std::string_view hello12{ "Hello, mom!" };
    std::copy_n(hello12.begin(), hello12.size(), char12.getArray());

    // Print the array
    print(char12);

    return 0;
}

Ce programme affiche :


Hello, world! Hello, mom!

Exactement ce que nous attendions.

La spécialisation partielle de modèle ne peut être utilisée qu'avec des classes, et non avec des fonctions modèles (les fonctions doivent être entièrement spécialisées). Notre exemple void print(StaticArray<char, size> &array) fonctionne parce que la fonction print n'est pas partiellement spécialisée (c'est simplement une fonction modèle surchargée qui possède par hasard un paramètre de classe partiellement spécialisée).

Spécialisation partielle pour les fonctions membres

La limitation de la spécialisation partielle des fonctions peut poser des difficultés avec les fonctions membres. Par exemple, que se passerait-il si nous avions défini StaticArray ainsi ?

template <typename T, int size>
class StaticArray
{
private:
    T m_array[size]{};

public:
    T* getArray() { return m_array; }

    const T& operator[](int index) const { return m_array[index]; }
    T& operator[](int index) { return m_array[index]; }

    void print() const;
};

template <typename T, int size> 
void StaticArray<T, size>::print() const
{
    for (int i{ 0 }; i < size; ++i)
        std::cout << m_array[i] << ' ';
    std::cout << '\n';
}

print() est maintenant une fonction membre de la classe StaticArray<T, int>. Que se passe-t-il alors lorsque nous voulons spécialiser partiellement print(), pour qu'elle fonctionne différemment ? Vous pourriez essayer ceci :

// Doesn't work, can't partially specialize functions
template <int size>
void StaticArray<double, size>::print() const
{
    for (int i{ 0 }; i < size; ++i)
        std::cout << std::scientific << m_array[i] << ' ';
    std::cout << '\n';
}

Malheureusement, cela ne fonctionne pas, car nous essayons de spécialiser partiellement une fonction, ce qui est interdit.

Comment contourner cela ? Une solution évidente consiste à spécialiser partiellement la classe entière :

#include <iostream>

template <typename T, int size>
class StaticArray
{
private:
    T m_array[size]{};

public:
    T* getArray() { return m_array; }

    const T& operator[](int index) const { return m_array[index]; }
    T& operator[](int index) { return m_array[index]; }

    void print() const;
};

template <typename T, int size> 
void StaticArray<T, size>::print() const
{
    for (int i{ 0 }; i < size; ++i)
        std::cout << m_array[i] << ' ';
    std::cout << '\n';
}

// Partially specialized class
template <int size>
class StaticArray<double, size>
{
private:
    double m_array[size]{};

public:
    double* getArray() { return m_array; }

    const double& operator[](int index) const { return m_array[index]; }
    double& operator[](int index) { return m_array[index]; }

    void print() const;
};

// Member function of partially specialized class
template <int size>
void StaticArray<double, size>::print() const
{
    for (int i{ 0 }; i < size; ++i)
        std::cout << std::scientific << m_array[i] << ' ';
    std::cout << '\n';
}

int main()
{
    // declare an integer array with room for 6 integers
    StaticArray<int, 6> intArray{};

    // Fill it up in order, then print it
    for (int count{ 0 }; count < 6; ++count)
        intArray[count] = count;

    intArray.print();

    // declare a double buffer with room for 4 doubles
    StaticArray<double, 4> doubleArray{};

    for (int count{ 0 }; count < 4; ++count)
        doubleArray[count] = (4.0 + 0.1 * count);

    doubleArray.print();

    return 0;
}

Ce programme affiche :


0 1 2 3 4 5
4.000000e+00 4.100000e+00 4.200000e+00 4.300000e+00

Cela fonctionne parce que StaticArray<double, size>::print() n'est plus une fonction partiellement spécialisée : c'est un membre non spécialisé de la classe partiellement spécialisée StaticArray<double, size>.

Cependant, ce n'est pas une excellente solution, car nous devons dupliquer beaucoup de code de StaticArray<T, size> vers StaticArray<double, size>.

Si seulement il existait un moyen de réutiliser le code de StaticArray<T, size> dans StaticArray<double, size>. Cela ressemble à une tâche pour l'héritage !

Vous pourriez commencer par essayer d'écrire ce code ainsi :

template <int size> // size is the expression parameter
class StaticArray<double, size>: public StaticArray<T, size>

Mais cela ne fonctionne pas, car nous avons utilisé T sans l'avoir défini. Il n'existe aucune syntaxe permettant d'hériter de cette manière.

En passant…

Même si nous pouvions définir T comme paramètre de type de modèle, lorsque StaticArray<double, size> serait instancié, le compilateur devrait remplacer le T de StaticArray<T, size> par un type réel. Quel type réel utiliserait-il ? Le seul type qui ait du sens est T=double, mais cela ferait hériter StaticArray<double, size> de lui-même !

Heureusement, il existe une solution de contournement utilisant une classe de base commune :

#include <iostream>

template <typename T, int size>
class StaticArray_Base
{
protected:
    T m_array[size]{};

public:
    T* getArray() { return m_array; }

    const T& operator[](int index) const { return m_array[index]; }
    T& operator[](int index) { return m_array[index]; }

    void print() const
    {
        for (int i{ 0 }; i < size; ++i)
            std::cout << m_array[i] << ' ';
        std::cout << '\n';
    }

    // Don't forget a virtual destructor if you're going to use virtual function resolution
};

template <typename T, int size>
class StaticArray: public StaticArray_Base<T, size>
{
};

template <int size>
class StaticArray<double, size>: public StaticArray_Base<double, size>
{
public:

    void print() const
    {
        for (int i{ 0 }; i < size; ++i)
            std::cout << std::scientific << this->m_array[i] << ' ';
// note: The this-> prefix in the above line is needed.
// See https://stackoverflow.com/a/6592617 or https://isocpp.org/wiki/faq/templates#nondependent-name-lookup-members for more info on why.
        std::cout << '\n';
    }
};

int main()
{
    // declare an integer array with room for 6 integers
    StaticArray<int, 6> intArray{};

    // Fill it up in order, then print it
    for (int count{ 0 }; count < 6; ++count)
        intArray[count] = count;

    intArray.print();

    // declare a double buffer with room for 4 doubles
    StaticArray<double, 4> doubleArray{};

    for (int count{ 0 }; count < 4; ++count)
        doubleArray[count] = (4.0 + 0.1 * count);

    doubleArray.print();

    return 0;
}

Ce programme affiche le même résultat que précédemment, mais avec beaucoup moins de code dupliqué.
