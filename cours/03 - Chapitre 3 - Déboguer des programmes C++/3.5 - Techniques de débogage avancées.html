3.5 — Techniques de débogage avancées

Dans la leçon précédente (3.4 -- Techniques de débogage de base), nous avons commencé à explorer la manière de déboguer manuellement les problèmes. Dans cette leçon, nous avions formulé quelques critiques à l'égard de l'utilisation d'instructions d'affichage pour le débogage :

  1. Les instructions de débogage encombrent votre code.
  2. Les instructions de débogage encombrent la sortie de votre programme.
  3. Les instructions de débogage nécessitent de modifier votre code pour être ajoutées comme supprimées, ce qui peut introduire de nouveaux bogues.
  4. Les instructions de débogage doivent être supprimées une fois que vous n'en avez plus besoin, ce qui les rend non réutilisables.

Nous pouvons atténuer certains de ces problèmes. Dans cette leçon, nous allons explorer quelques techniques de base pour y parvenir.

Rendre votre code de débogage conditionnel

Considérons le programme suivant, qui contient quelques instructions de débogage :

#include <iostream>

int getUserInput()
{
std::cerr << "getUserInput() called\n";
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    return x;
}

int main()
{
std::cerr << "main() called\n";
    int x{ getUserInput() };
    std::cout << "You entered: " << x << '\n';

    return 0;
}

Lorsque vous avez fini avec les instructions de débogage, vous devrez soit les supprimer, soit les mettre en commentaire. Ensuite, si vous voulez les réutiliser plus tard, vous devrez les rajouter ou les décommenter.

Une façon de faciliter l'activation et la désactivation du débogage dans l'ensemble de votre programme consiste à rendre vos instructions de débogage conditionnelles à l'aide de directives du préprocesseur :

#include <iostream>

#define ENABLE_DEBUG // comment out to disable debugging

int getUserInput()
{
#ifdef ENABLE_DEBUG
std::cerr << "getUserInput() called\n";
#endif
    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    return x;
}

int main()
{
#ifdef ENABLE_DEBUG
std::cerr << "main() called\n";
#endif
    int x{ getUserInput() };
    std::cout << "You entered: " << x << '\n';

    return 0;
}

Désormais, nous pouvons activer le débogage simplement en mettant en commentaire ou en décommentant #define ENABLE_DEBUG. Cela nous permet de réutiliser les instructions de débogage déjà ajoutées, puis de simplement les désactiver lorsque nous n'en avons plus besoin, au lieu de devoir les supprimer du code. Si ce programme comportait plusieurs fichiers, la ligne #define ENABLE_DEBUG serait placée dans un fichier d'en-tête inclus dans tous les fichiers de code, afin de pouvoir la mettre en commentaire ou la décommenter à un seul endroit et que le changement se propage à tous les fichiers.

Cela règle le problème de la suppression des instructions de débogage et le risque qui y est associé, mais au prix d'un encombrement encore plus important du code. Un autre inconvénient de cette approche est que si vous faites une faute de frappe (par exemple en orthographiant mal « DEBUG ») ou si vous oubliez d'inclure l'en-tête dans un fichier de code, tout ou partie du débogage de ce fichier peut ne pas être activé. Cette méthode est donc meilleure que la version non conditionnelle, mais il reste une marge d'amélioration.

Utiliser un journal (logger)

Une alternative au débogage conditionnel par le préprocesseur consiste à envoyer vos informations de débogage vers un journal. Un journal (ou log) est un enregistrement séquentiel des événements survenus, généralement horodatés. Le processus de production d'un journal s'appelle journalisation (ou logging). En général, les journaux sont écrits dans un fichier sur disque (appelé fichier journal) afin de pouvoir être consultés plus tard. La plupart des applications et des systèmes d'exploitation écrivent des fichiers journaux qui permettent de diagnostiquer les problèmes survenus.

Les fichiers journaux présentent plusieurs avantages. Comme les informations écrites dans un fichier journal sont séparées de la sortie de votre programme, vous évitez l'encombrement causé par le mélange de votre sortie normale et de votre sortie de débogage. Les fichiers journaux peuvent aussi être facilement envoyés à d'autres personnes pour diagnostic : si un utilisateur de votre logiciel rencontre un problème, vous pouvez lui demander de vous envoyer le fichier journal, qui peut vous donner un indice sur l'origine du problème.

C++ contient un flux de sortie nommé std::clog, destiné à l'écriture d'informations de journalisation. Cependant, par défaut, std::clog écrit sur le flux d'erreur standard (comme std::cerr). Bien qu'il soit possible de le rediriger vers un fichier, c'est un domaine où il est généralement préférable d'utiliser l'un des nombreux outils tiers de journalisation existants. Le choix vous appartient.

À titre d'illustration, nous allons montrer à quoi ressemble une sortie vers un journal avec le journal de bord plog. Plog est implémenté sous la forme d'un ensemble de fichiers d'en-tête, il est donc facile à inclure partout où vous en avez besoin, et il est léger et simple d'utilisation.

#include <plog/Log.h> // Étape 1 : inclure les en-têtes du journal
#include <plog/Initializers/RollingFileInitializer.h>
#include <iostream>

int getUserInput()
{
    PLOGD << "getUserInput() called"; // PLOGD est défini par la bibliothèque plog

    std::cout << "Enter a number: ";
    int x{};
    std::cin >> x;
    return x;
}

int main()
{
    plog::init(plog::debug, "Logfile.txt"); // Étape 2 : initialiser le journal

    PLOGD << "main() called"; // Étape 3 : écrire dans le journal comme si vous écriviez dans la console

    int x{ getUserInput() };
    std::cout << "You entered: " << x << '\n';

    return 0;
}

Voici la sortie du journal précédent (dans le fichier Logfile.txt) :


2018-12-26 20:03:33.295 DEBUG [4752] [main@19] main() called
2018-12-26 20:03:33.296 DEBUG [4752] [getUserInput@7] getUserInput() called

La manière d'inclure, d'initialiser et d'utiliser un journal varie selon le journal choisi.

Notez que les directives de compilation conditionnelle ne sont pas non plus nécessaires avec cette méthode, car la plupart des journaux disposent d'un moyen de réduire ou de supprimer l'écriture dans le fichier. Le code est ainsi beaucoup plus lisible, puisque les lignes de compilation conditionnelle l'encombrent fortement. Avec plog, la journalisation peut être désactivée temporairement en modifiant l'instruction d'initialisation comme suit :

    plog::init(plog::none , "Logfile.txt"); // plog::none supprime l'écriture de la plupart des messages, ce qui désactive essentiellement la journalisation

Nous n'utiliserons pas plog dans les leçons suivantes, vous n'avez donc pas besoin de l'apprendre.

En passant…

Si vous voulez compiler vous-même l'exemple ci-dessus, ou utiliser plog dans vos propres projets, vous pouvez suivre ces instructions pour l'installer :

Commencez par récupérer la dernière version de plog :

  • Rendez-vous sur le dépôt plog.
  • Cliquez sur le bouton vert Code en haut à droite et choisissez « Download zip ».

Ensuite, décompressez l'intégralité de l'archive dans un emplacement de votre disque dur.

Enfin, pour chaque projet, définissez le répertoire emplacement\plog-master\include\ comme include directory dans votre IDE. Des instructions pour Visual Studio sont disponibles ici : A.2 -- Utiliser des bibliothèques avec Visual Studio, et pour Code::Blocks ici : A.3 -- Utiliser des bibliothèques avec Code::Blocks. Comme plog ne fournit pas de fichier de bibliothèque précompilé, vous pouvez ignorer les parties relatives aux fichiers de bibliothèque précompilés.

Le fichier journal est généralement créé dans le même répertoire que votre exécutable.

Astuce

Dans les projets plus volumineux ou sensibles aux performances, on pourra préférer des journaux plus rapides et plus riches en fonctionnalités, comme spdlog.
