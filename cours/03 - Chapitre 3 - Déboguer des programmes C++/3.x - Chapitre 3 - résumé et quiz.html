3.x — Chapitre 3 : résumé et quiz

Bilan du chapitre

Une erreur de syntaxe est une erreur qui se produit lorsque vous écrivez une instruction qui n'est pas valide selon la grammaire du langage C++. Le compilateur détecte ces erreurs.

Une erreur sémantique se produit lorsqu'une instruction est syntaxiquement valide, mais ne fait pas ce que le programmeur avait prévu.

Le processus qui consiste à trouver et à supprimer les erreurs d'un programme s'appelle le débogage (debugging).

Nous pouvons aborder le débogage en suivant un processus en cinq étapes :

  1. Trouver la cause première.
  2. Comprendre le problème.
  3. Déterminer une correction.
  4. Réparer le problème.
  5. Tester à nouveau.

Trouver une erreur est généralement la partie la plus difficile du débogage.

Les outils d'analyse statique (static analysis tools) sont des outils qui analysent votre code et recherchent des problèmes sémantiques pouvant indiquer des défauts dans votre code.

Être capable de reproduire un problème de manière fiable est la première étape, et la plus importante, du débogage.

Plusieurs tactiques permettent de faciliter la recherche des problèmes :

  • Mettre du code en commentaire.
  • Utiliser des instructions d'affichage pour valider le déroulement de votre code.
  • Afficher des valeurs.

Lorsque vous utilisez des instructions d'affichage pour déboguer, utilisez std::cerr au lieu de std::cout. Mais il est encore préférable d'éviter de déboguer avec des instructions d'affichage.

Un fichier journal (log file) est un fichier qui enregistre les événements survenant dans un programme. Le processus consistant à écrire des informations dans un fichier journal s'appelle la journalisation (logging).

Le processus qui consiste à restructurer votre code sans modifier son comportement s'appelle le remaniement (refactoring). Il est généralement effectué pour rendre votre programme plus organisé, plus modulaire ou plus performant.

Le test unitaire (unit testing) est une méthode de test logiciel par laquelle de petites unités de code source sont testées pour déterminer si elles sont correctes.

La programmation défensive (defensive programming) est une technique par laquelle le programmeur tente d'anticiper toutes les façons dont le logiciel pourrait être mal utilisé. Ces mauvaises utilisations peuvent souvent être détectées et atténuées.

L'ensemble des informations suivies dans un programme (valeurs des variables, fonctions appelées, point d'exécution courant) constitue l'état du programme (program state).

Un débogueur (debugger) est un outil qui permet au programmeur de contrôler le déroulement d'un programme et d'examiner son état pendant son exécution. Un débogueur intégré (integrated debugger) est un débogueur intégré à l'éditeur de code.

Le pas à pas (stepping) désigne un ensemble de fonctionnalités de débogage permettant de parcourir votre code instruction par instruction.

Entrer dans (step into) exécute la prochaine instruction du chemin d'exécution normal du programme, puis suspend l'exécution. Si l'instruction contient un appel de fonction, entrer dans fait sauter le programme au début de la fonction appelée.

Passer par-dessus (step over) exécute la prochaine instruction du chemin d'exécution normal du programme, puis suspend l'exécution. Si l'instruction contient un appel de fonction, passer par-dessus exécute la fonction en entier et vous rend la main une fois son exécution terminée.

Sortir de (step out) exécute tout le code restant de la fonction en cours d'exécution, puis vous rend la main une fois la fonction terminée.

Exécuter jusqu'au curseur (run to cursor) exécute le programme jusqu'à ce que l'exécution atteigne l'instruction sélectionnée par le curseur de la souris.

Continuer (continue) exécute le programme jusqu'à ce qu'il se termine ou qu'un point d'arrêt soit atteint. Démarrer (start) est identique à continuer, mais depuis le début du programme.

Un point d'arrêt (breakpoint) est un marqueur spécial qui indique au débogueur d'interrompre l'exécution du programme lorsqu'il est atteint.

La commande définir l'instruction suivante (set next statement) nous permet de modifier le point d'exécution vers une autre instruction (on parle parfois informellement de saut). Elle peut servir à faire avancer le point d'exécution pour sauter du code qui serait sinon exécuté, ou à revenir en arrière pour exécuter de nouveau une instruction déjà exécutée.

Surveiller une variable (watching a variable) vous permet d'inspecter la valeur d'une variable pendant l'exécution du programme en mode débogage. La fenêtre de surveillance (watch window) vous permet d'examiner la valeur de variables ou d'expressions.

La pile d'appels (call stack) est la liste de toutes les fonctions actives qui ont été exécutées pour atteindre le point d'exécution courant. La fenêtre de la pile d'appels (call stack window) est une fenêtre du débogueur qui affiche la pile d'appels.

Quiz

Question n° 1

Le programme suivant est censé additionner deux nombres, mais ne fonctionne pas correctement.

Utilisez le débogueur intégré pour exécuter ce programme pas à pas et surveiller la valeur de x. En vous appuyant sur les informations obtenues, corrigez le programme suivant :

#include <iostream>

int readNumber(int x)
{
    std::cout << "Please enter a number: ";
    std::cin >> x;
    return x;
}

void writeAnswer(int x)
{
    std::cout << "The sum is: " << x << '\n';
}

int main()
{
    int x {};
    readNumber(x);
    x = x + readNumber(x);
    writeAnswer(x);

    return 0;
}
Solution

Le problème majeur se situe à la deuxième ligne de la fonction main : la valeur de retour de readNumber n'est affectée à rien, elle est donc perdue. Un problème mineur est que readNumber prend un argument alors qu'elle devrait utiliser une variable locale.

#include <iostream>

int readNumber()
{
    std::cout << "Please enter a number: ";
    int x {};
    std::cin >> x;
    return x;
}

void writeAnswer(int x)
{
    std::cout << "The sum is: " << x << '\n';
}

int main()
{
    int x { readNumber() };
    x = x + readNumber();
    writeAnswer(x);

    return 0;
}

Question n° 2

Le programme suivant est censé diviser deux nombres, mais ne fonctionne pas correctement.

Utilisez le débogueur intégré pour exécuter ce programme pas à pas. Saisissez 8 et 4 comme valeurs d'entrée. En vous appuyant sur les informations obtenues, corrigez le programme suivant :

#include <iostream>

int readNumber()
{
    std::cout << "Please enter a number: ";
    int x {};
    std::cin >> x;
    return x;
}

void writeAnswer(int x)
{
    std::cout << "The quotient is: " << x << '\n';
}

int main()
{
    int x{ };
    int y{ };
    x = readNumber();
    x = readNumber();
    writeAnswer(x/y);

    return 0;
}
Solution

Le problème vient de ce que le second appel à readNumber affecte sa valeur à x au lieu de y. Il en résulte une division par 0, ce qui provoque un comportement indéfini.

#include <iostream>

int readNumber()
{
    std::cout << "Please enter a number: ";
    int x {};
    std::cin >> x;
    return x;
}

void writeAnswer(int x)
{
    std::cout << "The quotient is: " << x << '\n';
}

int main()
{
    int x{ readNumber() };
    int y{ readNumber() };
    writeAnswer(x/y);

    return 0;
}

Vous remarquerez peut-être que lorsque la seconde saisie ne divise pas exactement la première, ce programme semble produire un résultat incorrect. Lors d'une division entre entiers, C++ supprime la partie fractionnaire du quotient. Nous reviendrons plus en détail sur ce point dans la leçon 6.2 -- Opérateurs arithmétiques.

Question n° 3

À quoi ressemble la pile d'appels dans le programme suivant lorsque le point d'exécution se situe à la ligne 4 ? Seuls les noms des fonctions sont nécessaires pour cet exercice, pas les numéros de ligne indiquant le point de retour.

#include <iostream>

}

    c();
    d();
}

{

}

}

a

Question n° 4

Question bonus : le programme suivant est censé additionner deux nombres, mais ne fonctionne pas correctement.

Utilisez le débogueur intégré pour exécuter ce programme pas à pas. Saisissez 8 et 4 comme valeurs d'entrée. En vous appuyant sur les informations obtenues, corrigez le programme suivant :

#include <iostream>

int readNumber()
{
    std::cout << "Please enter a number: ";
    char x{};
    std::cin >> x;

    return x;
}

void writeAnswer(int x)
{
    std::cout << "The sum is: " << x << '\n';
}

int main()
{
    int x { readNumber() };
    int y { readNumber() };
    writeAnswer(x + y);

    return 0;
}
Solution

Le problème vient du type de données char à la ligne 6. Lorsque nous saisissons la valeur numérique 8, elle n'est pas stockée sous la valeur 8, mais sous la valeur 56. Lorsque nous saisissons la valeur numérique 4, elle n'est pas stockée sous la valeur 4, mais sous la valeur 52. La fonction readNumber() renvoie donc 56 et 52 au lieu de 8 et 4 comme prévu.

La solution consiste à remplacer le type de données de la ligne 6, char, par int.
