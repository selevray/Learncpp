22.4 — std::move

Une fois que vous commencez à utiliser régulièrement la sémantique de déplacement, vous rencontrerez des cas où vous voulez invoquer la sémantique de déplacement, alors que les objets dont vous disposez sont des l-values et non des r-values. Prenons la fonction d'échange suivante comme exemple :

#include <iostream>
#include <string>

template <typename T>
void mySwapCopy(T& a, T& b) 
{ 
    T tmp { a }; // invoque le constructeur de copie
    a = b; // invoque l'affectation par copie
    b = tmp; // invoque l'affectation par copie
}

int main()
{
    std::string x{ "abc" };
    std::string y{ "de" };

    std::cout << "x: " << x << '\n';
    std::cout << "y: " << y << '\n';

    mySwapCopy(x, y);

    std::cout << "x: " << x << '\n';
    std::cout << "y: " << y << '\n';

    return 0;
}

Reçue deux objets de type T (ici, std::string), cette fonction échange leurs valeurs en effectuant trois copies. Par conséquent, ce programme affiche :


x: abc
y: de
x: de
y: abc

Comme nous l'avons montré dans la leçon précédente, effectuer des copies peut être inefficace. Et cette version de l'échange effectue 3 copies. Cela entraîne une création et une destruction excessives de chaînes, ce qui est lent.

Cependant, il n'est pas nécessaire de faire des copies ici. Tout ce que nous cherchons vraiment à faire est d'échanger les valeurs de a et b, ce qui peut tout aussi bien être accompli en effectuant 3 déplacements ! Ainsi, si nous passons de la sémantique de copie à la sémantique de déplacement, nous pouvons rendre notre code plus performant.

Mais comment ? Le problème ici est que les paramètres a et b sont des références à des l-values et non des références à des r-values, de sorte que nous n'avons pas de moyen d'invoquer le constructeur de déplacement et l'opérateur d'affectation par déplacement à la place du constructeur de copie et de l'affectation par copie. Par défaut, nous obtenons le comportement du constructeur de copie et de l'affectation par copie. Que faire ?

std::move

En C++11, std::move est une fonction de la bibliothèque standard qui convertit (à l'aide de static_cast) son argument en une référence à une r-value, afin que la sémantique de déplacement puisse être invoquée. Ainsi, nous pouvons utiliser std::move pour convertir une l-value en un type qui préférera être déplacé plutôt que copié. std::move est définie dans l'en-tête utility.

Voici le même programme que précédemment, mais avec une fonction mySwapMove() qui utilise std::move pour convertir nos l-values en r-values afin de pouvoir invoquer la sémantique de déplacement :

#include <iostream>
#include <string>
#include <utility> // pour std::move

template <typename T>
void mySwapMove(T& a, T& b) 
{ 
    T tmp { std::move(a) }; // invoque le constructeur de déplacement
    a = std::move(b); // invoque l'affectation par déplacement
    b = std::move(tmp); // invoque l'affectation par déplacement
}

int main()
{
    std::string x{ "abc" };
    std::string y{ "de" };

    std::cout << "x: " << x << '\n';
    std::cout << "y: " << y << '\n';

    mySwapMove(x, y);

    std::cout << "x: " << x << '\n';
    std::cout << "y: " << y << '\n';

    return 0;
}

Ce programme affiche le même résultat que précédemment :


x: abc
y: de
x: de
y: abc

Mais il est beaucoup plus efficace. Lors de l'initialisation de tmp, au lieu de faire une copie de x, nous utilisons std::move pour convertir la variable l-value x en une r-value. Comme le paramètre est une r-value, la sémantique de déplacement est invoquée, et x est déplacée dans tmp.

Avec quelques échanges supplémentaires, la valeur de la variable x a été déplacée vers y, et la valeur de y a été déplacée vers x.

Un autre exemple

Nous pouvons également utiliser std::move lors du remplissage des éléments d'un conteneur, tel que std::vector, avec des l-values.

Dans le programme suivant, nous ajoutons d'abord un élément à un vector en utilisant la sémantique de copie. Puis nous ajoutons un élément au vector en utilisant la sémantique de déplacement.

#include <iostream>
#include <string>
#include <utility> // pour std::move
#include <vector>

int main()
{
    std::vector<std::string> v;

    // Nous utilisons std::string car elle est déplaçable (std::string_view ne l'est pas)
    std::string str { "Knock" };

    std::cout << "Copie de str\n";
    v.push_back(str); // appelle la version push_back à l-value, qui copie str dans l'élément du tableau

    std::cout << "str: " << str << '\n';
    std::cout << "vector: " << v[0] << '\n';

    std::cout << "\nDéplacement de str\n";

    v.push_back(std::move(str)); // appelle la version push_back à r-value, qui déplace str dans l'élément du tableau

    std::cout << "str: " << str << '\n'; // Le résultat de ceci est indéterminé
    std::cout << "vector:" << v[0] << ' ' << v[1] << '\n';

    return 0;
}

Sur la machine de l'auteur, ce programme affiche :


Copie de str
str: Knock
vector: Knock

Déplacement de str
str:
vector: Knock Knock

Dans le premier cas, nous avons passé à push_back() une l-value, de sorte qu'il a utilisé la sémantique de copie pour ajouter un élément au vector. Pour cette raison, la valeur de str reste inchangée.

Dans le second cas, nous avons passé à push_back() une r-value (en réalité une l-value convertie via std::move), de sorte qu'il a utilisé la sémantique de déplacement pour ajouter un élément au vector. C'est plus efficace, car l'élément du vector peut s'approprier la valeur de la chaîne au lieu de devoir la copier.

Les objets déplacés se trouvent dans un état valide, mais potentiellement indéterminé

Lorsque nous déplaçons la valeur d'un objet temporaire, la valeur dans laquelle se retrouve l'objet déplacé n'a pas d'importance, car l'objet temporaire sera de toute façon détruit immédiatement. Mais qu'en est-il des objets l-value sur lesquels nous avons utilisé std::move() ? Comme nous pouvons continuer à accéder à ces objets après que leurs valeurs ont été déplacées (par exemple, dans l'exemple ci-dessus, nous affichons la valeur de str après son déplacement), il est utile de savoir dans quel état ils se trouvent.

Il existe deux écoles de pensée à ce sujet. La première estime que les objets qui ont été déplacés doivent être remis à un état par défaut / nul, où l'objet ne possède plus de ressource. Nous en voyons un exemple ci-dessus, où str a été vidée et vaut donc la chaîne vide.

L'autre école estime qu'il faut faire ce qui est le plus pratique, sans nous contraindre à vider l'objet déplacé lorsque ce n'est pas commode.

Que fait donc la bibliothèque standard dans ce cas ? À ce sujet, la norme C++ indique : « Sauf indication contraire, les objets déplacés [de types définis dans la bibliothèque standard C++] doivent être placés dans un état valide mais non spécifié. »

Dans notre exemple ci-dessus, lorsque l'auteur a affiché la valeur de str après avoir appelé std::move dessus, la chaîne vide a été affichée. Cependant, ce n'est pas imposé : il aurait pu afficher n'importe quelle chaîne valide, y compris la chaîne vide, la chaîne d'origine ou toute autre chaîne valide. Nous devons donc éviter d'utiliser la valeur d'un objet déplacé, car les résultats dépendraient de l'implémentation.

Dans certains cas, nous voulons réutiliser un objet dont la valeur a été déplacée (plutôt que d'allouer un nouvel objet). Par exemple, dans l'implémentation de mySwapMove() ci-dessus, nous déplaçons d'abord la ressource hors de a, puis nous déplaçons une autre ressource dans a. Cela ne pose pas de problème, car nous n'utilisons jamais la valeur de a entre le moment où nous la déplaçons et celui où nous lui donnons une nouvelle valeur déterminée.

Avec un objet déplacé, il est sûr d'appeler toute fonction qui ne dépend pas de la valeur courante de l'objet. Cela signifie que nous pouvons définir ou redéfinir la valeur de l'objet déplacé (à l'aide de operator=, ou de toute fonction membre clear() ou reset()). Nous pouvons aussi tester l'état de l'objet déplacé (par exemple à l'aide de empty() pour savoir s'il possède une valeur). En revanche, nous devons éviter les fonctions comme operator[] ou front() (qui renvoie le premier élément d'un conteneur), car elles supposent que le conteneur possède des éléments, alors qu'un conteneur déplacé peut en avoir ou non.

Point clé

std::move() donne un indice au compilateur indiquant que le programmeur n'a plus besoin de la valeur d'un objet. N'utilisez std::move() que sur des objets persistants dont vous voulez déplacer la valeur, et ne faites aucune hypothèse sur la valeur de l'objet au-delà de ce point. Il est tout à fait correct de donner une nouvelle valeur à un objet déplacé (par exemple à l'aide de operator=) après que sa valeur courante a été déplacée.

Où d'autre std::move est-il utile ?

std::move peut aussi être utile lors du tri d'un tableau d'éléments. De nombreux algorithmes de tri (comme le tri par sélection et le tri à bulles) fonctionnent en échangeant des paires d'éléments. Dans les leçons précédentes, nous avons dû recourir à la sémantique de copie pour effectuer ces échanges. Nous pouvons désormais utiliser la sémantique de déplacement, qui est plus efficace.

Elle peut aussi être utile si nous voulons transférer le contenu géré par un pointeur intelligent vers un autre.

Contenu associé

Il existe une variante utile de std::move() appelée std::move_if_noexcept(), qui renvoie une r-value déplaçable si l'objet possède un constructeur de déplacement noexcept, sinon elle renvoie une l-value copiable. Nous la présentons dans la leçon 27.10 -- std::move_if_noexcept.

Conclusion

std::move peut être utilisé chaque fois que nous voulons traiter une l-value comme une r-value, afin d'invoquer la sémantique de déplacement au lieu de la sémantique de copie.
