22.2 — Références de r-value

Au chapitre 12, nous avons introduit le concept de catégories de valeurs (12.2 -- Catégories de valeurs (l-values et r-values)), une propriété des expressions qui permet de déterminer si une expression correspond à une valeur, une fonction ou un objet. Nous avons également introduit les l-values et les r-values afin de pouvoir parler des références de l-value.

Si vous avez un doute sur les l-values et les r-values, c'est le moment idéal pour revoir ce sujet, car nous en parlerons beaucoup dans ce chapitre.

Rappel sur les références de l-value

Avant C++11, il n'existait qu'un seul type de référence en C++, qui s'appelait simplement « référence ». Depuis C++11, on parle de référence de l-value. Une référence de l-value ne peut être initialisée qu'avec une l-value modifiable.

Référence de l-value Peut être initialisée avec Peut modifier
L-values modifiables Oui Oui
L-values non modifiables Non Non
R-values Non Non

Une référence de l-value vers un objet const peut être initialisée avec des l-values modifiables et non modifiables, ainsi qu'avec des r-values. En revanche, la valeur référencée ne peut pas être modifiée.

Référence de l-value vers const Peut être initialisée avec Peut modifier
L-values modifiables Oui Non
L-values non modifiables Oui Non
R-values Oui Non

Les références de l-value vers des objets const sont particulièrement utiles car elles permettent de passer n'importe quel type d'argument (l-value ou r-value) à une fonction sans copier cet argument.

Références de r-value

C++11 ajoute un nouveau type de référence, la référence de r-value (r-value reference). Une référence de r-value est conçue pour être initialisée uniquement avec une r-value. Alors qu'une référence de l-value se déclare avec une esperluette simple, une référence de r-value se déclare avec une double esperluette :

int x{ 5 };
int& lref{ x }; // référence de l-value initialisée avec la l-value x
int&& rref{ 5 }; // référence de r-value initialisée avec la r-value 5

Une référence de r-value ne peut pas être initialisée avec une l-value.

Référence de r-value Peut être initialisée avec Peut modifier
L-values modifiables Non Non
L-values non modifiables Non Non
R-values Oui Oui
Référence de r-value vers const Peut être initialisée avec Peut modifier
L-values modifiables Non Non
L-values non modifiables Non Non
R-values Oui Non

Les références de r-value ont deux propriétés utiles. Premièrement, une référence de r-value prolonge la durée de vie de l'objet avec lequel elle est initialisée, jusqu'à la fin de la durée de vie de la référence (les références de l-value vers des objets const le peuvent aussi). Deuxièmement, les références de r-value non const permettent de modifier la r-value !

Regardons quelques exemples :

#include <iostream>

class Fraction
{
private:
    int m_numerator { 0 };
    int m_denominator { 1 };

public:
    Fraction(int numerator = 0, int denominator = 1) :
        m_numerator{ numerator }, m_denominator{ denominator }
    {
    }

    friend std::ostream& operator<<(std::ostream& out, const Fraction& f1)
    {
        out << f1.m_numerator << '/' << f1.m_denominator;
        return out;
    }
};

int main()
{
    auto&& rref{ Fraction{ 3, 5 } }; // référence de r-value vers un Fraction temporaire

    // f1 de operator<< se lie au temporaire, aucune copie n'est créée.
    std::cout << rref << '\n';

    return 0;
} // rref (et le Fraction temporaire) sortent de portée ici

Ce programme affiche :


3/5

En tant qu'objet anonyme, Fraction(3, 5) sortirait normalement de portée à la fin de l'expression dans laquelle il est défini. Cependant, comme nous l'utilisons pour initialiser une référence de r-value, sa durée de vie est prolongée jusqu'à la fin du bloc. Nous pouvons alors utiliser cette référence de r-value pour afficher la valeur de la Fraction.

Voyons maintenant un exemple moins intuitif :

#include <iostream>

int main()
{
    int&& rref{ 5 }; // comme nous initialisons une référence de r-value avec un littéral, un temporaire de valeur 5 est créé ici
    rref = 10;
    std::cout << rref << '\n';

    return 0;
}

Ce programme affiche :


10

Il peut sembler étrange d'initialiser une référence de r-value avec une valeur littérale puis de pouvoir modifier cette valeur. Pourtant, lorsqu'on initialise une référence de r-value avec un littéral, un objet temporaire est construit à partir de ce littéral, de sorte que la référence désigne un objet temporaire et non la valeur littérale elle-même.

Les références de r-value ne sont pas très souvent utilisées de l'une ou l'autre des façons illustrées ci-dessus.

Références de r-value comme paramètres de fonction

Les références de r-value sont plus souvent utilisées comme paramètres de fonction. C'est particulièrement utile pour les surcharges de fonctions lorsque l'on souhaite avoir des comportements différents selon que l'argument est une l-value ou une r-value.

#include <iostream>

void fun(const int& lref) // les arguments l-value sélectionneront cette fonction
{
    std::cout << "référence de l-value vers const : " << lref << '\n';
}

void fun(int&& rref) // les arguments r-value sélectionneront cette fonction
{
    std::cout << "référence de r-value : " << rref << '\n';
}

int main()
{
    int x{ 5 };
    fun(x); // un argument l-value appelle la version de la fonction avec référence de l-value
    fun(5); // un argument r-value appelle la version de la fonction avec référence de r-value

    return 0;
}

Ce programme affiche :


référence de l-value vers const : 5
référence de r-value : 5

Comme vous pouvez le voir, lorsqu'on lui passe une l-value, la fonction surchargée se résout vers la version avec référence de l-value. Lorsqu'on lui passe une r-value, elle se résout vers la version avec référence de r-value (c'est considéré comme une meilleure correspondance qu'une référence de l-value vers const).

Pourquoi voudrait-on faire cela ? Nous en discuterons plus en détail dans la prochaine leçon. Il suffit de dire pour l'instant que c'est une partie importante de la sémantique de déplacement (move semantics).

Les variables de référence de r-value sont des l-values

Considérez l'extrait suivant :

    int&& ref{ 5 };
    fun(ref);

Laquelle des versions de fun pensez-vous que l'appel ci-dessus sélectionne : fun(const int&) ou fun(int&&) ?

La réponse pourrait vous surprendre : cela appelle fun(const int&).

Bien que la variable ref soit de type int&&, lorsqu'elle est utilisée dans une expression, c'est une l-value (comme toutes les variables nommées). Le type d'un objet et sa catégorie de valeur sont indépendants.

Vous savez déjà que le littéral 5 est une r-value de type int, et que int x est une l-value de type int. De même, int&& ref est une l-value de type int&&.

Ainsi, non seulement fun(ref) appelle fun(const int&), mais il ne correspond même pas à fun(int&&), car une référence de r-value ne peut pas se lier à une l-value.

Renvoyer une référence de r-value

Vous ne devriez presque jamais renvoyer une référence de r-value, pour la même raison que vous ne devriez presque jamais renvoyer une référence de l-value. Dans la plupart des cas, vous finiriez par renvoyer une référence pendante lorsque l'objet référencé sort de portée à la fin de la fonction.

Quiz

Question n° 1

Indiquez laquelle des instructions suivantes (identifiées par une lettre) ne compilera pas :

int main()
{
    int x{};

    // références de l-value
    int& ref1{ x }; // A
    int& ref2{ 5 }; // B

    const int& ref3{ x }; // C
    const int& ref4{ 5 }; // D

    // références de r-value
    int&& ref5{ x }; // E
    int&& ref6{ 5 }; // F

    const int&& ref7{ x }; // G
    const int&& ref8{ 5 }; // H

    return 0;
}
Solution

B, E et G ne compileront pas.

Récapitulatif des combinaisons de liaison :

  • Les références de l-value non const ne peuvent se lier qu'à des l-values non const.
  • Les références de l-value const peuvent se lier à des l-values non const, à des l-values const et à des r-values.
  • Les références de r-value ne peuvent se lier qu'à des r-values.

x est une l-value non const, on peut donc lier une référence de l-value non const (A) et une référence de l-value const (C) à x. On ne peut pas lier une référence de l-value non const à une r-value (B).
5 est une r-value, on peut donc lier une référence de l-value const (D) et des références de r-value (F et H) à 5. On ne peut pas lier une référence de r-value à une l-value (E et G).
