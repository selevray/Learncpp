22.x — Résumé du chapitre 22 et quiz

Un pointeur intelligent (smart pointer) est une classe de composition conçue pour gérer de la mémoire allouée dynamiquement et s'assurer que cette mémoire est libérée lorsque l'objet pointeur intelligent sort de sa portée.

La sémantique de copie (copy semantics) permet de copier nos classes. Cela se fait principalement via le constructeur de copie et l'opérateur d'affectation par copie.

La sémantique de déplacement (move semantics) signifie qu'une classe transfère la propriété de l'objet au lieu d'en faire une copie. Cela se fait principalement via le constructeur de déplacement et l'opérateur d'affectation par déplacement.

std::auto_ptr est déprécié et doit être évité.

Une référence de r-value (r-value reference) est une référence conçue pour être initialisée avec une r-value. Elle se crée avec un double esperluette. Il est tout à fait correct d'écrire des fonctions prenant des paramètres de type référence de r-value, mais vous ne devriez pratiquement jamais renvoyer une référence de r-value.

Si nous construisons un objet ou effectuons une affectation dont l'argument est une l-value, la seule chose raisonnable à faire est de copier cette l-value. Nous ne pouvons pas supposer qu'il est sûr de la modifier, car elle peut être utilisée à nouveau plus tard dans le programme. Dans l'expression « a = b », on ne s'attend raisonnablement pas à ce que b soit modifié de quelque façon que ce soit.

En revanche, si nous construisons un objet ou effectuons une affectation dont l'argument est une r-value, alors nous savons que cette r-value n'est qu'un objet temporaire d'une sorte ou d'une autre. Plutôt que de la copier (ce qui peut être coûteux), nous pouvons simplement transférer ses ressources (ce qui est peu coûteux) à l'objet que nous sommes en train de construire ou d'affecter. C'est une opération sûre, car le temporaire sera de toute façon détruit à la fin de l'expression, et nous savons donc qu'il ne sera plus jamais utilisé !

Vous pouvez utiliser le mot-clé delete pour désactiver la sémantique de copie des classes que vous créez, en supprimant le constructeur de copie et l'opérateur d'affectation par copie.

std::move vous permet de traiter une l-value comme une r-value. C'est utile lorsque nous voulons invoquer la sémantique de déplacement au lieu de la sémantique de copie sur une l-value.

std::unique_ptr est la classe de pointeur intelligent que vous devriez probablement utiliser. Elle gère une seule ressource non partageable. std::make_unique() (en C++14) doit être privilégiée pour créer de nouveaux std::unique_ptr. std::unique_ptr désactive la sémantique de copie.

std::shared_ptr est la classe de pointeur intelligent utilisée lorsque plusieurs objets doivent accéder à la même ressource. La ressource ne sera pas détruite tant que le dernier std::shared_ptr qui la gère n'aura pas été détruit. std::make_shared() doit être privilégiée pour créer de nouveaux std::shared_ptr. Avec std::shared_ptr, on utilise la sémantique de copie pour créer des std::shared_ptr supplémentaires pointant vers le même objet.

std::weak_ptr est la classe de pointeur intelligent utilisée lorsque vous avez besoin d'un ou plusieurs objets capables de voir et d'accéder à une ressource gérée par un std::shared_ptr, mais contrairement à std::shared_ptr, std::weak_ptr n'est pas pris en compte pour déterminer si la ressource doit être détruite.

Il est temps de faire le quiz

  1. Expliquez quand vous devriez utiliser chacun des types de pointeurs suivants.

1a) std::unique_ptr

Solution

std::unique_ptr doit être utilisé lorsque vous voulez qu'un pointeur intelligent gère un objet dynamique qui ne sera pas partagé.

1b) std::shared_ptr

Solution

std::shared_ptr doit être utilisé lorsque vous voulez qu'un pointeur intelligent gère un objet dynamique susceptible d'être partagé. L'objet ne sera pas désalloué tant que tous les std::shared_ptr le détenant n'auront pas été détruits.

1c) std::weak_ptr

Solution

std::weak_ptr doit être utilisé lorsque vous voulez accéder à un objet géré par un std::shared_ptr, sans que la durée de vie du std::shared_ptr soit liée à celle du std::weak_ptr.

1d) std::auto_ptr

Solution

std::auto_ptr a été déprécié et a été supprimé en C++17. Il ne doit plus être utilisé.

  1. Expliquez pourquoi la sémantique de déplacement repose sur les r-values.
Solution

Parce que les r-values sont temporaires, nous savons qu'elles seront détruites après leur utilisation. Lorsqu'on passe ou renvoie une r-value par valeur, il est inutile de faire une copie puis de détruire l'original. À la place, on peut simplement déplacer (voler) les ressources de la r-value, ce qui est en général plus efficace.

  1. Qu'est-ce qui ne va pas dans le code suivant ? Modifiez le programme pour qu'il respecte les bonnes pratiques.

3a)

#include <iostream>
#include <memory> // for std::shared_ptr

class Resource
{
public:
    Resource() { std::cout << "Resource acquired\n"; }
    ~Resource() { std::cout << "Resource destroyed\n"; }
};

int main()
{
    auto* res{ new Resource{} };
    std::shared_ptr<Resource> ptr1{ res };
    std::shared_ptr<Resource> ptr2{ res };

    return 0;
}
Solution

ptr2 a été créé à partir de res au lieu de ptr1. Cela signifie que vous avez maintenant deux std::shared_ptr tentant chacun de gérer indépendamment la Resource (ils ne se connaissent pas). Lorsque l'un sort de sa portée, l'autre se retrouve avec un pointeur pendouillant (dangling pointer).

ptr2 devrait plutôt être initialisé à partir de ptr1 et non de res. Ainsi, ptr1 et ptr2 partagent la propriété de res. std::make_shared() doit être utilisé à la place de l'allocation dynamique manuelle.

#include <iostream>
#include <memory> // pour std::shared_ptr

class Resource
{
public:
    Resource() { std::cout << "Resource acquired\n"; }
    ~Resource() { std::cout << "Resource destroyed\n"; }
};

int main()
{
    auto ptr1{ std::make_shared<Resource>() };
    auto ptr2{ ptr1 };

    return 0;
}
