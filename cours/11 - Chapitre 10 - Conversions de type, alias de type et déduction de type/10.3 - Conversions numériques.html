10.3 — Conversions numériques

Dans la leçon précédente (10.2 -- Promotion des nombres à virgule flottante et entiers), nous avons vu les promotions numériques, qui sont des conversions de types numériques plus étroits vers des types numériques plus larges (généralement int ou double) qui peuvent être traités efficacement.

C++ prend en charge une autre catégorie de conversions de types numériques, appelées conversions numériques. Ces conversions couvrent des conversions de types supplémentaires entre types fondamentaux.

Point clé

Toute conversion de type couverte par les règles de promotion numérique (10.2 -- Promotion des nombres à virgule flottante et entiers) est appelée promotion numérique, et non conversion numérique.

Il existe cinq types de base de conversions numériques.

  1. Conversion d'un type entier vers n'importe quel autre type entier (hors promotions entières) :
short s = 3; // convertit un int en short
long l = 3; // convertit un int en long
char ch = s; // convertit un short en char
unsigned int u = 3; // convertit un int en unsigned int
  1. Conversion d'un type à virgule flottante vers n'importe quel autre type à virgule flottante (hors promotions à virgule flottante) :
float f = 3.0; // convertit un double en float
long double ld = 3.0; // convertit un double en long double
  1. Conversion d'un type à virgule flottante vers n'importe quel type entier :
int i = 3.5; // convertit un double en int
  1. Conversion d'un type entier vers n'importe quel type à virgule flottante :
double d = 3; // convertit un int en double
  1. Conversion d'un type entier ou à virgule flottante vers un bool :
bool b1 = 3; // convertit un int en bool
bool b2 = 3.0; // convertit un double en bool

En complément…

Comme l'initialisation par accolades interdit strictement certains types de conversions numériques (nous y reviendrons dans la leçon suivante), nous utilisons dans cette leçon l'initialisation par copie (qui ne présente pas de telles limitations) afin de garder les exemples simples.

Conversions sûres et dangereuses

Contrairement aux promotions numériques (qui préservent toujours la valeur et sont donc « sûres »), de nombreuses conversions numériques sont dangereuses. Une conversion dangereuse est une conversion où au moins une valeur du type source ne peut pas être convertie en une valeur égale du type destination.

Les conversions numériques se répartissent en trois grandes catégories de sécurité :

  1. Les conversions préservant la valeur sont des conversions numériques sûres où le type destination peut représenter exactement toutes les valeurs possibles du type source.

Par exemple, int vers long et short vers double sont des conversions sûres, car la valeur source peut toujours être convertie en une valeur égale du type destination.

int main()
{
    int n { 5 };
    long l = n; // correct, produit la valeur long 5

    short s { 5 };
    double d = s; // correct, produit la valeur double 5.0

    return 0;
}

Les compilateurs n'émettent généralement pas d'avertissement pour les conversions implicites préservant la valeur.

Une valeur convertie par une conversion préservant la valeur peut toujours être reconvertie vers le type source, ce qui donne une valeur équivalente à la valeur d'origine :

#include <iostream>

int main()
{
    int n = static_cast<int>(static_cast<long>(3)); // convertit l'int 3 en long puis le reconvertit
    std::cout << n << '\n';                         // affiche 3

    char c = static_cast<char>(static_cast<double>('c')); // convertit 'c' en double puis le reconvertit
    std::cout << c << '\n';                               // affiche 'c'

    return 0;
}
  1. Les conversions réinterprétatives sont des conversions numériques dangereuses où la valeur convertie peut être différente de la valeur source, mais aucune donnée n'est perdue. Les conversions signé/non signé entrent dans cette catégorie.

Par exemple, lors de la conversion d'un signed int en unsigned int :

int main()
{
    int n1 { 5 };
    unsigned int u1 { n1 }; // correct : sera converti en unsigned int 5 (valeur préservée)

    int n2 { -5 };
    unsigned int u2 { n2 }; // mauvais : donnera un grand entier hors de l'intervalle de signed int

    return 0;
}

Dans le cas de u1, la valeur 5 de type signed int est convertie en la valeur 5 de type unsigned int. La valeur est donc préservée dans ce cas.

Dans le cas de u2, la valeur -5 de type signed int est convertie en unsigned int. Comme un unsigned int ne peut pas représenter de nombres négatifs, le résultat est ramené modulo à une grande valeur entière située hors de l'intervalle d'un signed int. La valeur n'est pas préservée dans ce cas.

De tels changements de valeur sont généralement indésirables et provoquent souvent un comportement inattendu ou dépendant de l'implémentation.

Contenu associé

Nous expliquons comment les valeurs hors intervalle sont converties entre types signés et non signés dans la leçon 4.12 -- Introduction à la conversion de types et static_cast.

Attention

Bien que les conversions réinterprétatives soient dangereuses, la plupart des compilateurs désactivent par défaut les avertissements pour les conversions implicites signé/non signé.

En effet, dans certains domaines du C++ moderne (par exemple lorsqu'on travaille avec les tableaux de la bibliothèque standard), les conversions signé/non signé sont difficiles à éviter. Et en pratique, la majorité de ces conversions ne modifient pas réellement la valeur. Activer ces avertissements produirait donc de nombreux avertissements parasites pour des conversions acceptables, noyant les avertissements légitimes.

Si vous choisissez de laisser ces avertissements désactivés, soyez particulièrement vigilant face aux conversions involontaires entre ces types (en particulier lors du passage d'un argument à une fonction dont le paramètre est de signe opposé).

Les valeurs converties par une conversion réinterprétative peuvent être reconverties vers le type source, ce qui donne une valeur équivalente à la valeur d'origine (même si la conversion initiale a produit une valeur hors de l'intervalle du type source). Ainsi, les conversions réinterprétatives ne font perdre aucune donnée au cours du processus.

#include <iostream>

int main()
{
    int u = static_cast<int>(static_cast<unsigned int>(-5)); // convertit '-5' en non signé puis le reconvertit
    std::cout << u << '\n'; // affiche -5

    return 0;
}

Pour les lecteurs avancés

Avant C++20, la conversion d'une valeur non signée hors de l'intervalle de la valeur signée était techniquement un comportement dépendant de l'implémentation (en raison de la possibilité que les entiers signés utilisent une représentation binaire différente de celle des entiers non signés). En pratique, ce point ne posait pas de problème sur les systèmes modernes.

C++20 impose désormais que les entiers signés utilisent le complément à deux. En conséquence, les règles de conversion ont été modifiées : le cas ci-dessus est désormais bien défini en tant que conversion réinterprétative (une conversion hors intervalle produit un repliement modulo).

Notez que, bien que ces conversions soient bien définies, le dépassement de capacité arithmétique sur les entiers signés (qui se produit lorsqu'une opération arithmétique produit une valeur en dehors de l'intervalle représentable) reste un comportement indéfini.

  1. Les conversions avec perte sont des conversions numériques dangereuses où des données peuvent être perdues au cours de la conversion.

Par exemple, la conversion de double vers int peut entraîner une perte de données :

int i = 3.0; // correct : sera converti en int 3 (valeur préservée)
int j = 3.5; // perte de données : sera converti en int 3 (la partie fractionnaire 0.5 est perdue)

La conversion de double vers float peut également entraîner une perte de données :

float f = 1.2;        // correct : sera converti en float 1.2 (valeur préservée)
float g = 1.23456789; // perte de données : sera converti en float 1.23457 (précision perdue)

Reconvertir vers le type source une valeur ayant perdu des données donne une valeur différente de la valeur d'origine :

#include <iostream>

int main()
{
    double d { static_cast<double>(static_cast<int>(3.5)) }; // convertit le double 3.5 en int puis le reconvertit
    std::cout << d << '\n'; // affiche 3

    double d2 { static_cast<double>(static_cast<float>(1.23456789)) }; // convertit le double 1.23456789 en float puis le reconvertit
    std::cout << d2 << '\n'; // affiche 1.23457

    return 0;
}

Par exemple, si la valeur double 3.5 est convertie en valeur int 3, la composante fractionnaire 0.5 est perdue. Lorsque 3 est reconverti en double, le résultat est 3.0, et non 3.5.

Les compilateurs émettent généralement un avertissement (ou, dans certains cas, une erreur) lorsqu'une conversion implicite avec perte serait effectuée à l'exécution.

Attention

Certaines conversions peuvent appartenir à des catégories différentes selon la plateforme.

Par exemple, la conversion de int vers double est généralement une conversion sûre, car int occupe habituellement 4 octets et double 8 octets, et sur de tels systèmes, toutes les valeurs possibles de int peuvent être représentées en double. Cependant, certaines architectures ont à la fois int et double sur 8 octets. Sur ces architectures, la conversion de int vers double est une conversion avec perte !

Nous pouvons le démontrer en convertissant une valeur long long (qui doit comporter au moins 64 bits) en double, puis en la reconvertissant :

#include <iostream>

int main()
{
    std::cout << static_cast<long long>(static_cast<double>(10000000000000001LL));

    return 0;
}

Ce programme affiche :


10000000000000000

Notez que notre dernier chiffre a été perdu !

Les conversions dangereuses doivent être évitées autant que possible. Toutefois, ce n'est pas toujours possible. Lorsque l'on utilise des conversions dangereuses, c'est le plus souvent dans les cas suivants :

  • Nous pouvons restreindre les valeurs à convertir à celles qui peuvent être converties en valeurs égales. Par exemple, un int peut être converti en toute sécurité en unsigned int lorsque nous pouvons garantir que cet int est positif ou nul.
  • Nous ne sommes pas gênés par la perte de certaines données parce qu'elles ne sont pas pertinentes. Par exemple, convertir un int en bool entraîne une perte de données, mais cela nous convient généralement, car nous voulons simplement savoir si la valeur de l'int est 0 ou non.

Compléments sur les conversions numériques

Les règles précises des conversions numériques sont complexes et nombreuses. Voici donc les points les plus importants à retenir.

  • Dans tous les cas, convertir une valeur vers un type dont l'intervalle ne permet pas de représenter cette valeur produira probablement des résultats inattendus. Par exemple :
int main()
{
    int i{ 30000 };
    char c = i; // les char vont de -128 à 127

    std::cout << static_cast<int>(c) << '\n';

    return 0;
}

Dans cet exemple, nous avons affecté un grand entier à une variable de type char (dont l'intervalle va de -128 à 127). Cela provoque un dépassement de capacité du char et produit un résultat inattendu :


48
  • Rappelez-vous que le dépassement de capacité est bien défini pour les valeurs non signées, mais produit un comportement indéfini pour les valeurs signées.
  • Convertir un entier ou un nombre à virgule flottante d'un type plus grand vers un type plus petit de la même famille fonctionnera généralement, tant que la valeur tient dans l'intervalle du type plus petit. Par exemple :
    int i{ 2 };
    short s = i; // conversion de int vers short
    std::cout << s << '\n';

    double d{ 0.1234 };
    float f = d;
    std::cout << f << '\n';

Cela produit le résultat attendu :


2
0.1234
  • Dans le cas des valeurs à virgule flottante, un arrondi peut se produire en raison d'une perte de précision dans le type plus petit. Par exemple :
    float f = 0.123456789; // la valeur double 0.123456789 a 9 chiffres significatifs, mais float n'en supporte qu'environ 7
    std::cout << std::setprecision(9) << f << '\n'; // std::setprecision est défini dans l'en-tête iomanip

Dans ce cas, nous observons une perte de précision, car le float ne peut pas contenir autant de précision qu'un double :


0.123456791
  • La conversion d'un entier vers un nombre à virgule flottante fonctionne généralement tant que la valeur tient dans l'intervalle du type à virgule flottante. Par exemple :
    int i{ 10 };
    float f = i;
    std::cout << f << '\n';

Cela produit le résultat attendu :


10
  • La conversion d'un nombre à virgule flottante vers un entier fonctionne tant que la valeur tient dans l'intervalle de l'entier, mais les valeurs fractionnaires sont perdues. Par exemple :
    int i = 3.5;
    std::cout << i << '\n';

Dans cet exemple, la valeur fractionnaire (.5) est perdue, ce qui donne le résultat suivant :


3

Bien que les règles de conversion numérique puissent sembler effrayantes, en pratique le compilateur vous avertira généralement si vous tentez quelque chose de dangereux (à l'exception de certaines conversions signé/non signé).
