10.6 — Conversion explicite de type (cast) et static_cast

Dans la leçon 10.1 -- Conversion implicite de type, nous avons vu que le compilateur peut utiliser une conversion implicite de type pour convertir une valeur d'un type de données vers un autre. Lorsque vous voulez promouvoir numériquement une valeur vers un type de données plus large, utiliser la conversion implicite ne pose pas de problème.

De nombreux nouveaux programmeurs C++ essaient quelque chose de ce genre :

double d = 10 / 4; // effectue une division entière, initialise d avec la valeur 2.0

Comme 10 et 4 sont tous deux de type int, une division entière est effectuée, et l'expression s'évalue en la valeur int 2. Cette valeur subit ensuite une conversion numérique en la valeur double 2.0 avant d'être utilisée pour initialiser la variable d. Très probablement, ce n'est pas ce qui était voulu.

Lorsque vous utilisez des opérandes littéraux, remplacer un ou les deux littéraux entiers par des littéraux double provoque une division en virgule flottante à la place :

double d = 10.0 / 4.0; // effectue une division en virgule flottante, initialise d avec la valeur 2.5

Mais que se passe-t-il si vous utilisez des variables au lieu de littéraux ? Considérez ce cas :

int x { 10 };
int y { 4 };
double d = x / y; // effectue une division entière, initialise d avec la valeur 2.0

Comme une division entière est utilisée ici, la variable d finira avec la valeur 2.0. Comment indiquer au compilateur que nous voulons utiliser une division en virgule flottante plutôt qu'une division entière dans ce cas ? Les suffixes littéraux ne peuvent pas être utilisés avec des variables. Nous avons besoin d'un moyen de convertir l'un (ou les deux) des opérandes variables vers un type à virgule flottante, afin que la division en virgule flottante soit utilisée.

Heureusement, C++ fournit plusieurs opérateurs de conversion de type (plus communément appelés casts) que le programmeur peut utiliser pour demander au compilateur d'effectuer une conversion de type. Comme les casts sont des demandes explicites du programmeur, cette forme de conversion de type est souvent appelée conversion explicite de type (par opposition à la conversion implicite de type, où le compilateur effectue automatiquement la conversion).

Conversion de type par cast

C++ prend en charge 5 types de casts différents : static_cast, dynamic_cast, const_cast, reinterpret_cast, et les casts de style C. Les quatre premiers sont parfois appelés casts nommés (named casts).

Pour les lecteurs avancés

Cast Description Sûr ?
static_cast Effectue des conversions de type à la compilation entre types apparentés. Oui
dynamic_cast Effectue des conversions de type à l'exécution sur des pointeurs ou des références dans une hiérarchie polymorphe (héritage) Oui
const_cast Ajoute ou supprime const. Seulement pour ajouter const
reinterpret_cast Réinterprète la représentation binaire d'un type comme si elle était d'un autre type Non
Casts de style C Effectue une combinaison de static_cast, const_cast ou reinterpret_cast. Non

Chaque cast fonctionne de la même manière. En entrée, le cast prend une expression (qui s'évalue en une valeur ou un objet) et un type cible. En sortie, le cast renvoie le résultat de la conversion.

Comme ce sont les plus couramment utilisés, nous couvrirons les casts de style C et static_cast dans cette leçon.

Contenu connexe

Nous abordons dynamic_cast dans la leçon 25.10 -- Conversion dynamique (dynamic cast), après avoir couvert d'autres sujets préalables.

const_cast et reinterpret_cast doivent généralement être évités, car ils ne sont utiles que dans de rares cas et peuvent être nuisibles s'ils sont mal utilisés.

Attention

Évitez const_cast et reinterpret_cast, sauf si vous avez une très bonne raison de les utiliser.

Cast de style C

En programmation C standard, le cast s'effectue via operator(), avec le nom du type de conversion placé entre parenthèses, et la valeur à convertir placée immédiatement à droite de la parenthèse fermante. En C++, ce type de cast s'appelle cast de style C (C-style cast). Vous pourrez encore en voir dans du code qui a été converti depuis le C.

Par exemple :

#include <iostream>

int main()
{
    int x { 10 };
    int y { 4 };

    std::cout << (double)x / y << '\n'; // cast de style C de x en double

    return 0;
}

Dans le programme ci-dessus, nous utilisons un cast de style C pour demander au compilateur de convertir x en double. Comme l'opérande de gauche de operator/ s'évalue désormais en une valeur à virgule flottante, l'opérande de droite sera également convertie en valeur à virgule flottante, et la division sera effectuée en virgule flottante plutôt qu'en division entière.

C++ fournit aussi une forme alternative de cast de style C appelée cast de style fonctionnel (function-style cast), qui ressemble à un appel de fonction :

    std::cout << double(x) / y << '\n'; // cast de style fonctionnel de x en double

Le cast de style fonctionnel permet de voir un peu plus facilement ce qui est converti (car il ressemble à un argument de fonction standard).

Il existe plusieurs raisons importantes pour lesquelles les casts de style C sont généralement évités en C++ moderne.

Premièrement, bien qu'un cast de style C semble être un cast unique, il peut en fait effectuer différentes conversions selon son utilisation. Cela peut inclure un static cast, un const cast ou un reinterpret cast (les deux derniers étant ceux que nous avons mentionnés plus haut et qu'il faut éviter). Un cast de style C ne précise pas clairement quel(s) cast(s) sera (seront) effectivement réalisé(s), ce qui rend non seulement votre code bien plus difficile à comprendre, mais ouvre aussi la porte à une utilisation abusive involontaire (où vous pensez effectuer un simple cast et finissez par faire quelque chose de dangereux). Cela peut souvent produire une erreur qui n'est découverte qu'à l'exécution.

De plus, comme les casts de style C ne sont constitués que d'un nom de type, de parenthèses et d'une variable ou valeur, ils sont à la fois difficiles à repérer (ce qui rend votre code plus difficile à lire) et encore plus difficiles à rechercher.

En revanche, les casts nommés sont faciles à repérer et à rechercher, font clairement apparaître ce qu'ils font, ont des capacités limitées, et provoqueront une erreur de compilation si vous tentez de les utiliser de manière incorrecte.

Bonne pratique

Évitez d'utiliser les casts de style C.

Pour les lecteurs avancés

Un cast de style C tente d'effectuer les casts C++ suivants, dans cet ordre :

  • const_cast
  • static_cast
  • static_cast, suivi de const_cast
  • reinterpret_cast
  • reinterpret_cast, suivi de const_cast

Il existe une chose que vous pouvez faire avec un cast de style C et que vous ne pouvez pas faire avec les casts C++ : les casts de style C peuvent convertir un objet dérivé en classe de base inaccessible (par exemple parce qu'elle a été héritée en privé).

static_cast doit être utilisé pour convertir la plupart des valeurs

De loin, le cast le plus utilisé en C++ est l'opérateur static cast, accessible via le mot-clé static_cast. static_cast s'utilise lorsque nous voulons convertir explicitement une valeur d'un type en une valeur d'un autre type.

Vous avez déjà vu static_cast utilisé pour convertir un char en int afin que std::cout l'affiche sous forme d'entier plutôt que de caractère :

#include <iostream>

int main()
{
    char c { 'a' };
    std::cout << static_cast<int>(c) << '\n'; // affiche 97 et non a

    return 0;
}

Pour effectuer un static cast, on commence par le mot-clé static_cast, puis on place le type de conversion entre chevrons. Ensuite, entre parenthèses, on place l'expression dont la valeur sera convertie. Remarquez à quel point la syntaxe ressemble à un appel de fonction nommée static_cast<type>() avec l'expression à convertir fournie en argument ! Convertir statiquement une valeur en un autre type renvoie un objet temporaire initialisé directement avec la valeur convertie.

Voici comment utiliser static_cast pour résoudre le problème présenté au début de cette leçon :

#include <iostream>

int main()
{
    int x { 10 };
    int y { 4 };

    // convertit statiquement x en double pour obtenir une division en virgule flottante
    std::cout << static_cast<double>(x) / y << '\n'; // affiche 2.5

    return 0;
}

static_cast<double>(x) renvoie un objet double temporaire contenant la valeur convertie 10.0. Ce temporaire est ensuite utilisé comme opérande de gauche de la division en virgule flottante.

Il y a deux propriétés importantes à connaître pour static_cast.

Premièrement, static_cast effectue une vérification de type à la compilation. Si nous essayons de convertir une valeur vers un type que le compilateur ne sait pas convertir, nous obtiendrons une erreur de compilation.

    // une chaîne littérale de style C ne peut pas être convertie en int, donc ce qui suit est une conversion invalide
    int x { static_cast<int>("Hello") }; // invalide : provoquera une erreur de compilation

Deuxièmement, static_cast est (volontairement) moins puissant qu'un cast de style C, car il empêche certains types de conversions dangereuses (comme celles qui nécessitent une réinterprétation ou la suppression de const).

Bonne pratique

Privilégiez static_cast lorsque vous devez convertir une valeur d'un type vers un autre type.

Pour les lecteurs avancés

Comme static_cast utilise l'initialisation directe, tous les constructeurs explicites du type de classe cible seront pris en compte lors de l'initialisation de l'objet temporaire à renvoyer. Nous aborderons les constructeurs explicites dans la leçon 14.16 -- Constructeurs de conversion et le mot-clé explicit.

Utiliser static_cast pour rendre explicites les conversions restrictives

Les compilateurs émettent souvent des avertissements lorsqu'une conversion implicite potentiellement dangereuse (restrictive) est effectuée. Par exemple, considérez l'extrait suivant :

int i { 48 };
char ch = i; // conversion restrictive implicite

Convertir un int (2 ou 4 octets) en char (1 octet) est potentiellement dangereux (car le compilateur ne peut pas savoir si la valeur entière va dépasser l'intervalle du char ou non), et le compilateur affichera donc généralement un avertissement. Si nous utilisions l'initialisation par liste, le compilateur produirait une erreur.

Pour contourner cela, nous pouvons utiliser un static cast afin de convertir explicitement notre entier en char :

int i { 48 };

// conversion explicite de int vers char, afin qu'un char soit affecté à la variable ch
char ch { static_cast<char>(i) };

Ce faisant, nous indiquons explicitement au compilateur que cette conversion est voulue, et nous acceptons la responsabilité de ses conséquences (par exemple un dépassement de l'intervalle d'un char si cela se produit). Comme la sortie de ce static cast est de type char, l'initialisation de la variable ch ne génère aucune incompatibilité de types, et donc aucun avertissement ni erreur.

Voici un autre exemple où le compilateur se plaindra généralement que la conversion d'un double en int peut entraîner une perte de données :

int i { 100 };
i = i / 2.5;

Pour indiquer au compilateur que nous voulons explicitement faire cela :

int i { 100 };
i = static_cast<int>(i / 2.5);

Cast ou initialisation d'un objet temporaire

Supposons que nous ayons une variable x que nous devons convertir en int. Il existe deux manières conventionnelles de le faire :

  1. static_cast<int>(x), qui renvoie un objet int temporaire initialisé directement avec x.
  2. int { x }, qui crée un objet int temporaire initialisé directement par liste avec x.

Nous devrions éviter int ( x ), qui est un cast de style C. Cela renverra un int temporaire initialisé directement avec la valeur de x (comme on pourrait s'y attendre d'après la syntaxe), mais il présente aussi les autres inconvénients mentionnés dans la section sur les casts de style C (notamment la possibilité d'effectuer une conversion dangereuse).

Il existe (au moins) trois différences notables entre le static_cast et le temporaire initialisé directement par liste :

  1. int { x } utilise l'initialisation par liste, qui interdit les conversions restrictives. C'est très bien lors de l'initialisation d'une variable, car nous avons rarement l'intention de perdre des données dans ce cas. Mais avec un cast, on présume que nous savons ce que nous faisons, et si nous voulons effectuer un cast pouvant entraîner une perte de données, nous devrions pouvoir le faire. La restriction sur les conversions restrictives peut alors être un obstacle.

Montrons un exemple de cela, y compris la manière dont il peut conduire à des problèmes dépendant de la plateforme :

#include <iostream>

int main()
{
    int x { 10 };
    int y { 4 };

    // Nous voulons effectuer une division en virgule flottante, donc l'un des opérandes doit être de type à virgule flottante
    std::cout << double{x} / y << '\n'; // correct si int est sur 32 bits, restrictif si x est sur 64 bits
}

Dans cet exemple, nous avons décidé de convertir x en double pour pouvoir effectuer une division en virgule flottante plutôt qu'une division entière. Sur une architecture 32 bits, cela fonctionne très bien (car un double peut représenter toutes les valeurs qui peuvent être stockées dans un int 32 bits, il ne s'agit donc pas d'une conversion restrictive). Mais sur une architecture 64 bits, ce n'est pas le cas : la conversion d'un int 64 bits en double est alors une conversion restrictive. Et comme l'initialisation par liste interdit les conversions restrictives, cela ne compilera pas sur les architectures où int fait 64 bits.

  1. static_cast indique plus clairement que nous avons l'intention d'effectuer une conversion. Bien que static_cast soit plus verbeux que l'alternative initialisée directement par liste, dans ce cas c'est une bonne chose, car cela rend la conversion plus facile à repérer et à rechercher. Cela rend finalement votre code plus sûr et plus facile à comprendre.
  2. L'initialisation directe par liste d'un temporaire n'accepte que les noms de type d'un seul mot. En raison d'une bizarrerie de syntaxe, il existe plusieurs endroits en C++ où seuls les noms de type d'un seul mot sont autorisés (la norme C++ appelle ces noms « spécificateurs de type simples » (simple type specifiers)). Ainsi, alors que int { x } est une syntaxe de conversion valide, unsigned int { x } ne l'est pas.

Vous pouvez le constater par vous-même avec l'exemple suivant, qui produit une erreur de compilation :

#include <iostream>

int main()
{
    unsigned char c { 'a' };
    std::cout << unsigned int { c } << '\n';

    return 0;
}

Il existe des moyens simples de contourner ce problème, le plus facile étant d'utiliser un alias de type d'un seul mot :

#include <iostream>

int main()
{
    unsigned char c { 'a' };
    using uint = unsigned int;
    std::cout << uint { c } << '\n';

    return 0;
}

Mais pourquoi se donner cette peine alors que vous pouvez simplement utiliser static_cast ?

Pour toutes ces raisons, nous préférons généralement static_cast à l'initialisation directe par liste d'un temporaire.

Bonne pratique

Préférez static_cast à l'initialisation d'un objet temporaire lorsqu'une conversion est souhaitée.

Quiz

Question n° 1

Quelle est la différence entre la conversion de type implicite et la conversion de type explicite ?

Solution

La conversion implicite de type est effectuée automatiquement chaque fois qu'un type de données est attendu alors qu'un autre type de données est fourni.
La conversion explicite se produit lorsque le programmeur utilise un cast de type pour convertir explicitement une valeur d'un type vers un autre type.
