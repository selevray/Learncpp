7.7 — Liaison externe et déclarations anticipées de variables

Dans la leçon précédente (7.6 -- Liaison interne), nous avons vu comment la liaison interne limite l'utilisation d'un identifiant à un seul fichier. Dans cette leçon, nous allons explorer le concept de liaison externe.

Un identifiant ayant une liaison externe (external linkage) peut être vu et utilisé à la fois depuis le fichier dans lequel il est défini et depuis d'autres fichiers de code (via une déclaration anticipée (forward declaration)). En ce sens, les identifiants ayant une liaison externe sont véritablement « globaux », puisqu'ils peuvent être utilisés n'importe où dans votre programme !

Point clé

Les identifiants ayant une liaison externe sont visibles par l'éditeur de liens (linker). Cela permet à celui-ci de faire deux choses :

  • Relier un identifiant utilisé dans une unité de traduction à la définition appropriée située dans une autre unité de traduction.
  • Dédupliquer les identifiants inline afin qu'il ne reste qu'une seule définition canonique. Nous étudierons les variables et fonctions inline dans la leçon 7.9 -- Fonctions et variables inline.

Les fonctions ont une liaison externe par défaut

Dans la leçon 2.8 -- Programmes composés de plusieurs fichiers de code, vous avez appris qu'il est possible d'appeler une fonction définie dans un fichier depuis un autre fichier. C'est parce que les fonctions ont une liaison externe par défaut.

Pour appeler une fonction définie dans un autre fichier, vous devez placer une déclaration anticipée (forward declaration) de cette fonction dans tous les autres fichiers qui souhaitent l'utiliser. La déclaration anticipée indique au compilateur l'existence de la fonction, et l'éditeur de liens relie les appels de fonction à la définition effective de celle-ci.

Voici un exemple :

a.cpp :

#include <iostream>

void sayHi() // this function has external linkage, and can be seen by other files
{
    std::cout << "Hi!\n";
}

main.cpp :

void sayHi(); // forward declaration for function sayHi, makes sayHi accessible in this file

int main()
{
    sayHi(); // call to function defined in another file, linker will connect this call to the function definition

    return 0;
}

Le programme ci-dessus affiche :


Hi!

Dans cet exemple, la déclaration anticipée de la fonction sayHi() dans main.cpp permet à main.cpp d'accéder à la fonction sayHi() définie dans a.cpp. La déclaration anticipée satisfait le compilateur, et l'éditeur de liens est alors en mesure de relier l'appel de fonction à la définition de la fonction.

Si la fonction sayHi() avait plutôt une liaison interne, l'éditeur de liens ne pourrait pas relier l'appel à la définition, et une erreur de l'éditeur de liens en résulterait.

Variables globales à liaison externe

Les variables globales ayant une liaison externe sont parfois appelées variables externes. Pour rendre une variable globale externe (et donc accessible depuis d'autres fichiers), nous pouvons utiliser le mot-clé extern :

int g_x { 2 }; // non-constant globals are external by default (no need to use extern)

extern const int g_y { 3 }; // const globals can be defined as extern, making them external
extern constexpr int g_z { 3 }; // constexpr globals can be defined as extern, making them external (but this is pretty useless, see the warning in the next section)

int main()
{
    return 0;
}

Les variables globales non constantes sont externes par défaut, il n'est donc pas nécessaire de les marquer avec extern.

Déclarations anticipées de variables via le mot-clé extern

Pour utiliser effectivement une variable globale externe définie dans un autre fichier, vous devez également placer une déclaration anticipée (forward declaration) de cette variable globale dans tous les autres fichiers qui souhaitent l'utiliser. Pour les variables, la création d'une déclaration anticipée se fait également à l'aide du mot-clé extern (sans valeur d'initialisation).

Voici un exemple d'utilisation de déclarations anticipées de variables :

main.cpp :

#include <iostream>

extern int g_x;       // this extern is a forward declaration of a variable named g_x that is defined somewhere else
extern const int g_y; // this extern is a forward declaration of a const variable named g_y that is defined somewhere else

int main()
{
    std::cout << g_x << ' ' << g_y << '\n'; // prints 2 3

    return 0;
}

Voici les définitions de ces variables :

a.cpp :

// global variable definitions
int g_x { 2 };              // non-constant globals have external linkage by default
extern const int g_y { 3 }; // this extern gives g_y external linkage

Dans cet exemple, a.cpp et main.cpp font tous deux référence à la même variable globale nommée g_x. Ainsi, bien que g_x soit définie et initialisée dans a.cpp, nous pouvons utiliser sa valeur dans main.cpp grâce à la déclaration anticipée de g_x.

Notez que le mot-clé extern a des significations différentes selon le contexte. Dans certains contextes, extern signifie « donner à cette variable une liaison externe ». Dans d'autres, extern signifie « ceci est une déclaration anticipée d'une variable externe définie ailleurs ». Oui, c'est déroutant ; nous récapitulons tous ces usages dans la leçon 7.12 -- Récapitulatif sur la portée, la durée de vie et la liaison.

Attention

Si vous souhaitez définir une variable globale non constante et non initialisée, n'utilisez pas le mot-clé extern, sans quoi C++ croira que vous essayez de créer une déclaration anticipée de cette variable.

Attention

Bien que des variables constexpr puissent recevoir une liaison externe via le mot-clé extern, elles ne peuvent pas faire l'objet d'une déclaration anticipée en tant que constexpr. En effet, le compilateur doit connaître la valeur de la variable constexpr (à la compilation). Si cette valeur est définie dans un autre fichier, le compilateur n'a aucun moyen de connaître la valeur qui y a été définie.

En revanche, vous pouvez déclarer par anticipation une variable constexpr comme const, que le compilateur traitera comme une constante à l'exécution. Ce n'est pas particulièrement utile.

Notez que les déclarations anticipées de fonctions n'ont pas besoin du mot-clé extern : le compilateur peut distinguer la définition d'une nouvelle fonction d'une déclaration anticipée selon que vous fournissez ou non un corps de fonction. En revanche, les déclarations anticipées de variables ont besoin du mot-clé extern pour les distinguer des définitions de variables non initialisées (elles sont par ailleurs identiques en apparence) :

// non-constant 
int g_x;        // variable definition (no initializer)
int g_x { 1 };  // variable definition (w/ initializer)
extern int g_x; // forward declaration (no initializer)

// constant
extern const int g_y { 1 }; // variable definition (const requires initializers)
extern const int g_y;       // forward declaration (no initializer)

Éviter d'utiliser extern sur une variable globale non constante avec initialisation

Les deux lignes suivantes sont sémantiquement équivalentes :

int g_x { 1 };        // extern by default
extern int g_x { 1 }; // explicitly extern (may cause compiler warning)

Toutefois, votre compilateur peut émettre un avertissement au sujet de la seconde instruction, bien qu'elle soit techniquement valide.

Vous vous souvenez que nous avons dit que les compilateurs ont la liberté d'émettre un diagnostic pour ce qu'ils jugent suspect ? C'est un de ces cas. Par convention, extern s'applique à une variable non constante lorsque nous voulons une déclaration anticipée. Or, ajouter une initialisation transforme l'instruction en définition. Le compilateur vous signale que quelque chose semble anormal. Pour corriger cela, supprimez soit l'initialisation (si vous vouliez une déclaration anticipée), soit le extern (si vous vouliez une définition).

Bonne pratique

N'utilisez extern que pour les déclarations anticipées de variables globales ou pour les définitions de variables globales constantes.
N'utilisez pas extern pour les définitions de variables globales non constantes (elles sont implicitement extern).

Résumé rapide

// Global variable forward declarations (extern w/ no initializer):
extern int g_y;                 // forward declaration for non-constant global variable
extern const int g_y;           // forward declaration for const global variable
extern constexpr int g_y;       // not allowed: constexpr variables can't be forward declared

// External global variable definitions (no extern)
int g_x;                        // defines non-initialized external global variable (zero initialized by default)
int g_x { 1 };                  // defines initialized external global variable

// External const global variable definitions (extern w/ initializer)
extern const int g_x { 2 };     // defines initialized const external global variable
extern constexpr int g_x { 3 }; // defines initialized constexpr external global variable

Quiz

Question n° 1

Quelle est la différence entre la portée, la durée de vie et la liaison d'une variable ? Quels types de portée, de durée de vie et de liaison les variables globales ont-elles ?

Solution

La portée détermine où une variable est accessible. La durée de vie détermine quand une variable est créée et détruite. La liaison détermine si la variable peut être exportée vers un autre fichier ou non.

Les variables globales ont une portée globale (aussi appelée portée de fichier), ce qui signifie qu'elles sont accessibles depuis le point de déclaration jusqu'à la fin du fichier dans lequel elles sont déclarées.

Les variables globales ont une durée de vie statique, ce qui signifie qu'elles sont créées au démarrage du programme et détruites à sa fin.

Les variables globales peuvent avoir soit une liaison interne, soit une liaison externe, via respectivement les mots-clés static et extern.
