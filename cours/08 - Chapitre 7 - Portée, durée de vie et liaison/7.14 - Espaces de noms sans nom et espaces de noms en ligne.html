7.14 — Espaces de noms sans nom et espaces de noms en ligne

C++ prend en charge deux variantes des espaces de noms (namespaces) qui valent au moins la peine d'être connues. Nous ne nous appuierons pas sur celles-ci, vous pouvez donc considérer cette leçon comme facultative pour le moment.

Espaces de noms sans nom (anonymes)

Un espace de noms sans nom (ou espace de noms anonyme, unnamed namespace / anonymous namespace) est un espace de noms défini sans nom, comme ceci :

#include <iostream>

namespace // espace de noms sans nom
{
    void doSomething() // n'est accessible que dans ce fichier
    {
        std::cout << "v1\n";
    }
}

int main()
{
    doSomething(); // nous pouvons appeler doSomething() sans préfixe d'espace de noms

    return 0;
}

Ce programme affiche :


v1

Tout le contenu déclaré dans un espace de noms sans nom est traité comme s'il faisait partie de l'espace de noms parent. Ainsi, même si la fonction doSomething() est définie dans l'espace de noms sans nom, elle reste accessible depuis l'espace de noms parent (qui est ici l'espace de noms global), ce qui explique que nous puissions appeler doSomething() depuis main() sans aucun qualificatif.

Cela pourrait faire paraître les espaces de noms sans nom inutiles. Mais leur autre effet est que tous les identifiants déclarés à l'intérieur d'un espace de noms sans nom reçoivent une liaison interne (internal linkage), ce qui signifie que le contenu d'un espace de noms sans nom n'est pas visible en dehors du fichier dans lequel il est défini.

Pour les fonctions, cela revient effectivement à définir toutes les fonctions dans l'espace de noms sans nom comme des fonctions static. Le programme suivant est en pratique identique au précédent :

#include <iostream>

static void doSomething() // n'est accessible que dans ce fichier
{
    std::cout << "v1\n";
}

int main()
{
    doSomething(); // nous pouvons appeler doSomething() sans préfixe d'espace de noms

    return 0;
}

Les espaces de noms sans nom sont généralement utilisés lorsque l'on dispose de nombreux éléments que l'on veut garder locaux à une unité de traduction donnée, car il est plus facile de regrouper ces éléments dans un seul espace de noms sans nom que de marquer individuellement chaque déclaration avec static. Les espaces de noms sans nom permettent aussi de garder locaux à l'unité de traduction les types définis par le programme (un sujet que nous aborderons dans une leçon ultérieure), ce pour quoi il n'existe aucun autre mécanisme équivalent.

Astuce

Si vous êtes un adepte du « hardcore », vous pouvez adopter l'approche inverse : placer dans un espace de noms sans nom tout le contenu qui n'est pas explicitement destiné à être exporté ou externe.

Les espaces de noms sans nom ne devraient généralement pas être utilisés dans les fichiers d'en-tête. SEI CERT (règle DCL59-CPP) fournit de bons exemples expliquant pourquoi.

Bonne pratique

Privilégiez les espaces de noms sans nom lorsque vous avez du contenu que vous souhaitez garder local à une unité de traduction.

Évitez les espaces de noms sans nom dans les fichiers d'en-tête.

Espaces de noms en ligne (inline)

Considérons maintenant le programme suivant :

#include <iostream>

void doSomething()
{
    std::cout << "v1\n";
}

int main()
{
    doSomething();

    return 0;
}

Ce programme affiche :


v1

Assez simple, n'est-ce pas ?

Mais supposons que vous ne soyez pas satisfait de doSomething() et que vous vouliez l'améliorer d'une manière qui modifie son comportement. Or, si vous le faites, vous risquez de casser les programmes existants qui utilisent l'ancienne version. Comment gérer cela ?

Une solution consiste à créer une nouvelle version de la fonction avec un nom différent. Mais après de nombreuses modifications, vous pourriez vous retrouver avec tout un ensemble de fonctions aux noms presque identiques (doSomething, doSomething_v2, doSomething_v3, etc.).

Une autre possibilité consiste à utiliser un espace de noms en ligne. Un espace de noms en ligne (inline namespace) est un espace de noms généralement utilisé pour versionner du contenu. Comme un espace de noms sans nom, tout ce qui est déclaré à l'intérieur d'un espace de noms en ligne est considéré comme faisant partie de l'espace de noms parent. Cependant, contrairement aux espaces de noms sans nom, les espaces de noms en ligne n'affectent pas la liaison.

Pour définir un espace de noms en ligne, on utilise le mot-clé inline :

#include <iostream>

inline namespace V1 // déclare un espace de noms en ligne nommé V1
{
    void doSomething()
    {
        std::cout << "V1\n";
    }
}

namespace V2 // déclare un espace de noms normal nommé V2
{
    void doSomething()
    {
        std::cout << "V2\n";
    }
}

int main()
{
    V1::doSomething(); // appelle la version V1 de doSomething()
    V2::doSomething(); // appelle la version V2 de doSomething()

    doSomething(); // appelle la version en ligne de doSomething() (c'est-à-dire V1)

    return 0;
}

Ce programme affiche :


V1
V2
V1

Dans l'exemple ci-dessus, les appels à doSomething() obtiennent la version V1 (la version en ligne) de doSomething(). Les appelants qui souhaitent utiliser la version plus récente peuvent appeler explicitement V2::doSomething(). Cela préserve le fonctionnement des programmes existants tout en permettant aux nouveaux programmes de profiter des variantes plus récentes et meilleures.

Alternativement, si vous voulez privilégier la version la plus récente :

#include <iostream>

namespace V1 // déclare un espace de noms normal nommé V1
{
    void doSomething()
    {
        std::cout << "V1\n";
    }
}

inline namespace V2 // déclare un espace de noms en ligne nommé V2
{
    void doSomething()
    {
        std::cout << "V2\n";
    }
}

int main()
{
    V1::doSomething(); // appelle la version V1 de doSomething()
    V2::doSomething(); // appelle la version V2 de doSomething()

    doSomething(); // appelle la version en ligne de doSomething() (c'est-à-dire V2)

    return 0;
}

Ce programme affiche :


V1
V2
V2

Dans cet exemple, tous les appels à doSomething() obtiennent par défaut la version v2 (la version plus récente et meilleure). Les utilisateurs qui souhaitent encore l'ancienne version de doSomething() peuvent appeler explicitement V1::doSomething() pour accéder à l'ancien comportement. Cela signifie que les programmes existants qui veulent la version V1 devront remplacer globalement doSomething par V1::doSomething, mais cela ne pose généralement pas de problème si les fonctions sont bien nommées.

Mélange d'espaces de noms en ligne et sans nom (facultatif)

Un espace de noms peut être à la fois en ligne et sans nom :

#include <iostream>

namespace V1 // déclare un espace de noms normal nommé V1
{
    void doSomething()
    {
        std::cout << "V1\n";
    }
}

inline namespace // déclare un espace de noms en ligne sans nom
{
    void doSomething() // a une liaison interne
    {
        std::cout << "V2\n";
    }
}

int main()
{
    V1::doSomething(); // appelle la version V1 de doSomething()
    // il n'existe pas de V2 dans cet exemple, nous ne pouvons donc pas utiliser V2:: comme préfixe d'espace de noms

    doSomething(); // appelle la version en ligne de doSomething() (celle qui est anonyme)

    return 0;
}

Dans de tels cas, il est toutefois préférable d'imbriquer un espace de noms anonyme à l'intérieur d'un espace de noms en ligne. Cela produit le même effet (toutes les fonctions de l'espace de noms anonyme ont une liaison interne par défaut) tout en vous fournissant un nom d'espace de noms explicite que vous pouvez utiliser :

#include <iostream>

namespace V1 // déclare un espace de noms normal nommé V1
{
    void doSomething()
    {
        std::cout << "V1\n";
    }
}

inline namespace V2 // déclare un espace de noms en ligne nommé V2
{
    namespace // espace de noms sans nom
    {
        void doSomething() // a une liaison interne
        {
            std::cout << "V2\n";
        }

    }
}

int main()
{
    V1::doSomething(); // appelle la version V1 de doSomething()
    V2::doSomething(); // appelle la version V2 de doSomething()

    doSomething(); // appelle la version en ligne de doSomething() (c'est-à-dire V2)

    return 0;
}
