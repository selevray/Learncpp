7.3 — Variables locales

Dans la leçon 2.5 -- Introduction à la portée locale, nous avons présenté les variables locales, c'est-à-dire les variables définies à l'intérieur d'une fonction (y compris les paramètres de fonction).

En réalité, C++ ne dispose pas d'un attribut unique qui définisse une variable comme locale. Les variables locales possèdent plutôt plusieurs propriétés qui les distinguent des autres variables (non locales). Nous les explorerons dans cette leçon et dans les suivantes.

Dans la leçon 2.5 -- Introduction à la portée locale, nous avons aussi introduit la notion de portée. La portée (scope) d'un identifiant détermine les endroits du code source où cet identifiant peut être utilisé. Lorsqu'un identifiant peut être utilisé, on dit qu'il est dans sa portée. Lorsqu'il ne peut pas être utilisé, on dit qu'il est hors de sa portée. La portée est une propriété déterminée à la compilation : tenter d'utiliser un identifiant hors de sa portée provoque une erreur de compilation.

Les variables locales ont une portée de bloc

Les variables locales ont une portée de bloc (block scope), ce qui signifie qu'elles sont dans leur portée depuis le point de leur définition jusqu'à la fin du bloc dans lequel elles sont définies.

Contenu associé

Veuillez revoir la leçon 7.1 -- Instructions composées (blocs) si vous avez besoin de rappels sur les blocs.

int main()
{
    int i { 5 }; // i entre dans sa portée ici
    double d { 4.0 }; // d entre dans sa portée ici

    return 0;
} // d et i sortent de leur portée ici

Bien que les paramètres de fonction ne soient pas définis dans le corps de la fonction, ils peuvent, pour les fonctions habituelles, être considérés comme faisant partie de la portée du bloc du corps de la fonction.

int max(int x, int y) // x et y entrent dans leur portée ici
{
    // affecte le plus grand de x et y à max
    int max{ (x > y) ? x : y }; // max entre dans sa portée ici

    return max;
} // max, y et x sortent de leur portée ici

Tous les noms de variables d'une même portée doivent être uniques

Les noms de variables doivent être uniques dans une portée donnée, sans quoi toute référence à ce nom serait ambiguë. Considérons le programme suivant :

void someFunction(int x)
{
    int x{}; // échec de la compilation à cause d'un conflit de nom avec le paramètre de la fonction
}

int main()
{
    return 0;
}

Le programme ci-dessus ne compile pas, car la variable x définie dans le corps de la fonction et le paramètre x portent le même nom et se trouvent tous deux dans la même portée de bloc.

Les variables locales ont une durée de stockage automatique

La durée de stockage (storage duration, souvent simplement appelée durée) d'une variable détermine les règles qui régissent le moment et la manière dont cette variable est créée (instanciée) et détruite. Dans la plupart des cas, la durée de stockage d'une variable détermine directement sa durée de vie.

Contenu associé

Nous expliquons ce qu'est la durée de vie dans la leçon 2.5 -- Introduction à la portée locale.

Par exemple, les variables locales ont une durée de stockage automatique (automatic storage duration), ce qui signifie qu'elles sont créées au point de leur définition et détruites à la fin du bloc dans lequel elles sont définies. Par exemple :

int main()
{
    int i { 5 }; // i créée et initialisée ici
    double d { 4.0 }; // d créée et initialisée ici

    return 0;
} // d et i sont détruites ici

Pour cette raison, les variables locales sont parfois appelées variables automatiques (automatic variables).

Variables locales dans des blocs imbriqués

Des variables locales peuvent être définies à l'intérieur de blocs imbriqués. Cela fonctionne exactement comme pour les variables locales du bloc du corps d'une fonction :

int main() // bloc externe
{
    int x { 5 }; // x entre dans sa portée et est créée ici

    { // bloc imbriqué
        int y { 7 }; // y entre dans sa portée et est créée ici
    } // y sort de sa portée et est détruite ici

    // y ne peut pas être utilisée ici, car elle est hors de sa portée dans ce bloc

    return 0;
} // x sort de sa portée et est détruite ici

Dans l'exemple ci-dessus, la variable y est définie dans un bloc imbriqué. Sa portée est limitée depuis son point de définition jusqu'à la fin du bloc imbriqué, et sa durée de vie est la même. Comme la portée de la variable y se limite au bloc interne dans lequel elle est définie, elle n'est accessible nulle part dans le bloc externe.

Notez que les blocs imbriqués font partie de la portée du bloc externe dans lequel ils sont définis. Par conséquent, les variables définies dans le bloc externe peuvent être vues à l'intérieur d'un bloc imbriqué :

#include <iostream>

int main()
{ // bloc externe

    int x { 5 }; // x entre dans sa portée et est créée ici

    { // bloc imbriqué
        int y { 7 }; // y entre dans sa portée et est créée ici

        // x et y sont toutes deux dans leur portée ici
        std::cout << x << " + " << y << " = " << x + y << '\n';
    } // y sort de sa portée et est détruite ici

    // y ne peut pas être utilisée ici, car elle est hors de sa portée dans ce bloc

    return 0;
} // x sort de sa portée et est détruite ici

Les variables locales n'ont pas de liaison

Les identifiants possèdent une autre propriété, appelée liaison (linkage). La liaison d'un identifiant détermine si une déclaration de ce même identifiant dans une portée différente désigne le même objet (ou la même fonction).

Les variables locales n'ont pas de liaison. Chaque déclaration d'un identifiant sans liaison désigne un objet ou une fonction unique.

Par exemple :

int main()
{
    int x { 2 }; // variable locale, sans liaison

    {
        int x { 3 }; // cette déclaration de x désigne un objet différent du x précédent
    }

    return 0;
}

La portée et la liaison peuvent sembler quelque peu similaires. Cependant, la portée détermine où la déclaration d'un identifiant unique peut être vue et utilisée dans le code. La liaison détermine si plusieurs déclarations d'un même identifiant désignent ou non le même objet.

Contenu associé

Nous expliquons ce qui se passe lorsque des variables de même nom apparaissent dans des blocs imbriqués dans la leçon 7.5 -- Masquage de variables (name hiding).

La liaison n'est pas très intéressante dans le contexte des variables locales, mais nous en parlerons davantage dans les prochaines leçons.

Les variables doivent être définies dans la portée la plus restreinte

Si une variable n'est utilisée qu'à l'intérieur d'un bloc imbriqué, elle doit être définie à l'intérieur de ce bloc imbriqué :

#include <iostream>

int main()
{
    // ne définissez pas y ici

    {
        // y n'est utilisée que dans ce bloc, donc la définir ici
        int y { 5 };
        std::cout << y << '\n';
    }

    // sinon y pourrait encore être utilisée ici, alors qu'elle n'en a pas besoin

    return 0;
}

En limitant la portée d'une variable, vous réduisez la complexité du programme, car le nombre de variables actives diminue. De plus, cela facilite la lecture de l'endroit où les variables sont utilisées (ou ne le sont pas). Une variable définie à l'intérieur d'un bloc ne peut être utilisée que dans ce bloc (ou dans les blocs qu'il contient). Cela peut rendre le programme plus facile à comprendre.

Si une variable est nécessaire dans un bloc externe, elle doit être déclarée dans ce bloc externe :

#include <iostream>

int main()
{
    int y { 5 }; // nous déclarons y ici parce que nous en avons besoin plus tard dans ce bloc externe

    {
        int x{};
        std::cin >> x;

        // si nous déclarions y ici, juste avant sa première utilisation réelle...
        if (x == 4)
            y = 4;
    } // ... elle serait détruite ici

    std::cout << y; // et nous avons besoin que y existe encore ici

    return 0;
}

L'exemple ci-dessus illustre l'un des rares cas où il peut être nécessaire de déclarer une variable bien avant sa première utilisation.

Les nouveaux développeurs se demandent parfois s'il vaut la peine de créer un bloc imbriqué dans le seul but de limiter volontairement la portée d'une variable (et de forcer sa sortie de portée / sa destruction anticipée). Cela rend effectivement cette variable plus simple, mais la fonction dans son ensemble devient plus longue et plus complexe. Ce compromis n'en vaut généralement pas la peine. Si la création d'un bloc imbriqué semble utile pour limiter volontairement la portée d'une portion de code, il vaut peut-être mieux placer ce code dans une fonction séparée.

Bonne pratique

Définissez les variables dans la portée existante la plus restreinte. Évitez de créer de nouveaux blocs dont le seul but est de limiter la portée de variables.

Quiz

Question n° 1

Écrivez un programme qui demande à l'utilisateur de saisir deux entiers, l'un nommé smaller, l'autre nommé larger. Si l'utilisateur saisit une valeur plus petite pour le second entier, utilisez un bloc et une variable temporaire pour échanger les valeurs. Affichez ensuite les valeurs des variables smaller et larger. Ajoutez des commentaires dans votre code indiquant où chaque variable meurt. Remarque : lorsque vous affichez les valeurs, smaller doit contenir la plus petite saisie et larger la plus grande, quel que soit l'ordre de saisie.

La sortie du programme doit correspondre à ce qui suit :


Enter an integer: 4
Enter a larger integer: 2
Swapping the values
The smaller value is 2
The larger value is 4
Solution 
#include <iostream>

int main()
{
    std::cout << "Enter an integer: ";
    int smaller{};
    std::cin >> smaller;

    std::cout << "Enter a larger integer: ";
    int larger{};
    std::cin >> larger;

    // si l'utilisateur s'est trompé
    if (smaller > larger)
    {
        // échange les valeurs de smaller et larger
        std::cout << "Swapping the values\n";

        int temp{ larger };
        larger = smaller;
        smaller = temp;
    } // temp meurt ici

    std::cout << "The smaller value is: " << smaller << '\n';
    std::cout << "The larger value is: " << larger << '\n';

    return 0;
} // smaller et larger meurent ici

À l'avenir, vous pourrez utiliser std::swap() de l'en-tête <utility> pour échanger les valeurs de deux variables. Par exemple :

int temp{ larger };
larger = smaller;
smaller = temp;

// est équivalent à
std::swap(larger, smaller);

Question n° 2

Quelle est la différence entre la portée, la durée de stockage et la durée de vie d'une variable ? Par défaut, quel type de portée et de durée de stockage ont les variables locales (et que signifient-ils) ?

Solution

La portée d'une variable détermine l'endroit où la variable est accessible dans le code source. La durée de stockage définit les règles qui régissent le moment où une variable est créée et détruite. La durée de vie d'une variable est le temps réel écoulé entre sa création et sa destruction.

Les variables locales ont une portée de bloc, ce qui signifie qu'elles sont accessibles depuis leur point de définition jusqu'à la fin du bloc dans lequel elles sont définies.

Les variables locales ont une durée de stockage automatique, ce qui signifie qu'elles sont créées au point de leur définition et détruites à la fin du bloc dans lequel elles sont définies.
