7.12 — Résumé sur la portée, la durée et la liaison

Les notions de portée, de durée et de liaison prêtent souvent à confusion. Nous consacrons donc une leçon supplémentaire à les récapituler. Certaines de ces notions n'ont pas encore été abordées. Elles sont présentes ici à titre de référence pour plus tard.

Résumé sur la portée

La portée (scope) d'un identificateur détermine l'endroit du code source où cet identificateur peut être utilisé.

  • Les variables à portée de bloc (locale) ne sont accessibles qu'à partir de leur point de déclaration jusqu'à la fin du bloc dans lequel elles sont déclarées (blocs imbriqués inclus). Cela comprend :

  • Les variables locales

  • Les paramètres de fonction

  • Les définitions de types définis par le programme (comme les énumérations et les classes) déclarées à l'intérieur d'un bloc

  • Les variables et les fonctions à portée globale sont accessibles à partir de leur point de déclaration jusqu'à la fin du fichier. Cela comprend :

  • Les variables globales

  • Les fonctions
  • Les définitions de types définis par le programme (comme les énumérations et les classes) déclarées dans un espace de noms (namespace) ou dans la portée globale

Résumé sur la durée

La durée de vie (duration) d'une variable détermine le moment où elle est créée et détruite.

  • Les variables à durée automatique sont créées au point de leur définition et détruites lorsque le bloc auquel elles appartiennent est quitté. Cela comprend :

  • Les variables locales

  • Les paramètres de fonction

  • Les variables à durée statique sont créées au démarrage du programme et détruites à sa fin. Cela comprend :

  • Les variables globales

  • Les variables locales statiques

  • Les variables à durée dynamique sont créées et détruites à la demande du programmeur. Cela comprend :

  • Les variables allouées dynamiquement

Résumé sur la liaison

La liaison (linkage) d'un identificateur détermine si une déclaration de ce même identificateur dans une portée différente désigne la même entité (objet, fonction, référence, etc.) ou non.

Les variables locales n'ont pas de liaison. Chaque déclaration d'un identificateur sans liaison désigne un objet ou une fonction unique.

  • Un identificateur sans liaison signifie qu'une autre déclaration du même identificateur désigne une entité unique. Les entités dont les identificateurs n'ont pas de liaison comprennent :

  • Les variables locales

  • Les identificateurs de types définis par le programme (comme les énumérations et les classes) déclarés à l'intérieur d'un bloc

  • Un identificateur à liaison interne signifie qu'une déclaration du même identificateur au sein de la même unité de traduction désigne le même objet ou la même fonction. Les entités dont les identificateurs ont une liaison interne comprennent :

  • Les variables globales statiques (initialisées ou non)

  • Les fonctions statiques
  • Les variables globales constantes

  • Les espaces de noms anonymes (unnamed namespaces) et tout ce qui y est défini

  • Un identificateur à liaison externe signifie qu'une déclaration du même identificateur dans l'ensemble du programme désigne le même objet ou la même fonction. Les entités dont les identificateurs ont une liaison externe comprennent :

  • Les fonctions non statiques

  • Les variables globales non constantes (initialisées ou non)
  • Les variables globales constantes déclarées avec extern
  • Les variables globales constantes inline
  • Les espaces de noms

Les identificateurs à liaison externe provoquent généralement une erreur de l'éditeur de liens (linker) pour définition multiple si leurs définitions sont compilées dans plusieurs fichiers .cpp (ce qui viole la règle de définition unique, ODR). Il existe quelques exceptions à cette règle (pour les types, les modèles (templates), ainsi que les fonctions et variables inline) : nous les verrons plus en détail dans des leçons ultérieures, lorsque nous aborderons ces sujets.

Notez également que les fonctions ont une liaison externe par défaut. Elles peuvent devenir à liaison interne grâce au mot-clé static.

Résumé sur la portée, la durée et la liaison des variables

Puisque les variables ont une portée, une durée et une liaison, résumons-les dans un tableau :

| Type | Exemple | Portée | Durée | Liaison | Remarques | | Variable locale | int x; | Bloc | Automatique | Aucune | | | Variable locale statique | static int s_x; | Bloc | Statique | Aucune | | | Variable locale dynamique | int* x { new int{} }; | Bloc | Dynamique | Aucune | | | Paramètre de fonction | void foo(int x) | Bloc | Automatique | Aucune | | | Variable globale non constante à liaison interne | static int g_x; | Globale | Statique | Interne | Initialisée ou non | | Variable globale non constante à liaison externe | int g_x; | Globale | Statique | Externe | Initialisée ou non | | Variable globale non constante inline (C++17) | inline int g_x; | Globale | Statique | Externe | Initialisée ou non | | Variable globale constante à liaison interne | constexpr int g_x { 1 }; | Globale | Statique | Interne | Doit être initialisée | | Variable globale constante à liaison externe | extern const int g_x { 1 }; | Globale | Statique | Externe | Doit être initialisée | | Variable globale constante inline (C++17) | inline constexpr int g_x { 1 }; | Globale | Statique | Externe | Doit être initialisée |

Résumé sur les déclarations anticipées

Vous pouvez utiliser une déclaration anticipée (forward declaration) pour accéder à une fonction ou à une variable définie dans un autre fichier. La portée de la variable déclarée est celle habituelle (portée globale pour les variables globales, portée de bloc pour les variables locales).

| Type | Exemple | Remarques | | Déclaration anticipée de fonction | void foo(int x); | Prototype seulement, sans corps de fonction | | Déclaration anticipée de variable non constante | extern int g_x; | Doit ne pas être initialisée | | Déclaration anticipée de variable constante | extern const int g_x; | Doit ne pas être initialisée | | Déclaration anticipée de variable constexpr | extern constexpr int g_x; | Non autorisée : une variable constexpr ne peut pas être déclarée à l'avance |

Une variable constexpr (qui est implicitement const) peut être déclarée à l'avance à l'aide d'une déclaration anticipée de variable const. Lorsqu'elle est utilisée à travers cette déclaration anticipée, la variable est considérée comme const (et non comme constexpr).

Qu'est-ce qu'un spécificateur de classe de stockage ?

Lorsqu'ils font partie de la déclaration d'un identificateur, les mots-clés static et extern sont appelés spécificateurs de classe de stockage (storage class specifiers). Dans ce contexte, ils définissent la durée de stockage et la liaison de l'identificateur.

C++ prend en charge 4 spécificateurs de classe de stockage actifs :

| Spécificateur | Signification | Remarque | | extern | Durée de stockage statique (ou thread_local) et liaison externe | | | static | Durée de stockage statique (ou thread_local) et liaison interne | | | thread_local | Durée de stockage par thread | | | mutable | Objet pouvant être modifié même si la classe qui le contient est const | | | auto | Durée de stockage automatique | Déprécié depuis C++11 | | register | Durée de stockage automatique et indication au compilateur de placer la variable dans un registre | Déprécié depuis C++17 |

Le terme spécificateur de classe de stockage n'est généralement utilisé que dans la documentation formelle.
