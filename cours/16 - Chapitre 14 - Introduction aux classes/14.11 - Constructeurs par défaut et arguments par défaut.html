14.11 — Constructeurs par défaut et arguments par défaut

Un constructeur par défaut (default constructor) est un constructeur qui n'accepte aucun argument. En général, il s'agit d'un constructeur défini sans paramètre.

Voici un exemple de classe disposant d'un constructeur par défaut :

#include <iostream>

class Foo
{
public:
    Foo() // constructeur par défaut
    {
        std::cout << "Foo default constructed\n";
    }
};

int main()
{
    Foo foo{}; // Aucune valeur d'initialisation, appelle le constructeur par défaut de Foo

    return 0;
}

Lorsque le programme ci-dessus s'exécute, un objet de type Foo est créé. Comme aucune valeur d'initialisation n'est fournie, le constructeur par défaut Foo() est appelé, ce qui affiche :


Foo default constructed

Initialisation par valeur et initialisation par défaut pour les types classe

Si un type classe possède un constructeur par défaut, l'initialisation par valeur (value initialization) et l'initialisation par défaut (default initialization) appellent toutes deux ce constructeur. Ainsi, pour une classe comme Foo de l'exemple précédent, les deux écritures suivantes sont pratiquement équivalentes :

    Foo foo{}; // initialisation par valeur, appelle le constructeur par défaut Foo()
    Foo foo2;  // initialisation par défaut, appelle le constructeur par défaut Foo()

Cependant, comme nous l'avons vu dans la leçon 13.9 -- Initialisation par défaut des membres, l'initialisation par valeur est plus sûre pour les agrégats. Comme il est difficile de dire si un type classe est un agrégat ou non, le plus sûr est d'utiliser l'initialisation par valeur dans tous les cas, sans vous poser la question.

Bonne pratique

Préférez l'initialisation par valeur à l'initialisation par défaut pour tous les types classe.

Constructeurs avec arguments par défaut

Comme pour toutes les fonctions, les paramètres les plus à droite d'un constructeur peuvent avoir des arguments par défaut.

Contenu associé

Nous traitons des arguments par défaut dans la leçon 11.5 -- Arguments par défaut.

Par exemple :

#include <iostream>

class Foo
{
private:
    int m_x { };
    int m_y { };

public:
    Foo(int x=0, int y=0) // possède des arguments par défaut
        : m_x { x }
        , m_y { y }
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ") constructed\n";
    }
};

int main()
{
    Foo foo1{};     // appelle le constructeur Foo(int, int) avec les arguments par défaut
    Foo foo2{6, 7}; // appelle le constructeur Foo(int, int)

    return 0;
}

Ce programme affiche :


Foo(0, 0) constructed
Foo(6, 7) constructed

Si tous les paramètres d'un constructeur ont des arguments par défaut, ce constructeur est un constructeur par défaut (car il peut être appelé sans argument).

Nous verrons des exemples où cela peut être utile dans la prochaine leçon (14.12 -- Constructeurs délégués).

Constructeurs surchargés

Comme les constructeurs sont des fonctions, ils peuvent être surchargés. Autrement dit, nous pouvons avoir plusieurs constructeurs afin de construire des objets de différentes manières :

#include <iostream>

class Foo
{
private:
    int m_x {};
    int m_y {};

public:
    Foo() // constructeur par défaut
    {
        std::cout << "Foo constructed\n";
    }

    Foo(int x, int y) // constructeur non par défaut
        : m_x { x }, m_y { y }
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ") constructed\n";
    }
};

int main()
{
    Foo foo1{};     // Appelle le constructeur Foo()
    Foo foo2{6, 7}; // Appelle le constructeur Foo(int, int)

    return 0;
}

Il en découle qu'une classe ne devrait posséder qu'un seul constructeur par défaut. Si plusieurs constructeurs par défaut sont fournis, le compilateur ne pourra pas déterminer lequel utiliser :

#include <iostream>

class Foo
{
private:
    int m_x {};
    int m_y {};

public:
    Foo() // constructeur par défaut
    {
        std::cout << "Foo constructed\n";
    }

    Foo(int x=1, int y=2) // constructeur par défaut
        : m_x { x }, m_y { y }
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ") constructed\n";
    }
};

int main()
{
    Foo foo{}; // erreur de compilation : appel de constructeur ambigu

    return 0;
}

Dans l'exemple ci-dessus, nous instancions foo sans argument, le compilateur cherche donc un constructeur par défaut. Il en trouve deux et ne peut pas déterminer lequel utiliser. Il en résulte une erreur de compilation.

Un constructeur par défaut implicite

Si un objet de type classe qui n'est pas un agrégat ne possède aucun constructeur déclaré par l'utilisateur, le compilateur génère un constructeur par défaut public (afin que la classe puisse être initialisée par valeur ou par défaut). Ce constructeur est appelé constructeur par défaut implicite (implicit default constructor).

Considérons l'exemple suivant :

#include <iostream>

class Foo
{
private:
    int m_x{};
    int m_y{};

    // Remarque : aucun constructeur déclaré
};

int main()
{
    Foo foo{};

    return 0;
}

Cette classe ne possède aucun constructeur déclaré par l'utilisateur, le compilateur génère donc pour nous un constructeur par défaut implicite. C'est ce constructeur qui sera utilisé pour instancier foo{}.

Le constructeur par défaut implicite équivaut à un constructeur sans paramètre, sans liste d'initialisation de membres et sans instruction dans le corps du constructeur. Autrement dit, pour la classe Foo ci-dessus, le compilateur génère l'équivalent de ceci :

public:
    Foo() // constructeur par défaut généré implicitement
    {
    }

Le constructeur par défaut implicite est surtout utile pour les classes qui n'ont aucun membre de données. Si une classe possède des membres de données, nous voudrons probablement qu'ils puissent être initialisés avec des valeurs fournies par l'utilisateur, et le constructeur par défaut implicite ne suffit pas pour cela.

Utiliser = default pour générer un constructeur par défaut explicitement défini

Lorsque nous aurions écrit un constructeur par défaut équivalent au constructeur par défaut implicite, nous pouvons demander au compilateur de le générer à notre place. Ce constructeur est appelé constructeur par défaut explicitement défini (explicitly defaulted default constructor) et il se génère avec la syntaxe = default :

#include <iostream>

class Foo
{
private:
    int m_x {};
    int m_y {};

public:
    Foo() = default; // génère un constructeur par défaut explicitement défini

    Foo(int x, int y)
        : m_x { x }, m_y { y }
    {
        std::cout << "Foo(" << m_x << ", " << m_y << ") constructed\n";
    }
};

int main()
{
    Foo foo{}; // appelle le constructeur par défaut Foo()

    return 0;
}

Dans l'exemple ci-dessus, comme nous avons un constructeur déclaré par l'utilisateur (Foo(int, int)), un constructeur par défaut implicite ne serait normalement pas généré. Cependant, comme nous avons demandé au compilateur de générer un tel constructeur, il le fait. Ce constructeur sera ensuite utilisé pour l'instanciation foo{}.

Bonne pratique

Préférez un constructeur par défaut explicitement défini (= default) à un constructeur par défaut dont le corps est vide.

Constructeur par défaut explicitement défini ou constructeur vide défini par l'utilisateur

Il existe au moins deux cas où le constructeur par défaut explicitement défini se comporte différemment d'un constructeur vide défini par l'utilisateur.

  1. Lors de l'initialisation par valeur d'une classe, si la classe possède un constructeur par défaut défini par l'utilisateur, l'objet est initialisé par défaut. En revanche, si la classe possède un constructeur par défaut qui n'est pas fourni par l'utilisateur (c'est-à-dire un constructeur par défaut implicite ou défini avec = default), l'objet est mis à zéro (zero-initialized) avant d'être initialisé par défaut.
#include <iostream>

class User
{
private:
    int m_a; // remarque : pas de valeur d'initialisation par défaut
    int m_b {};

public:
    User() {} // constructeur vide défini par l'utilisateur

    int a() const { return m_a; }
    int b() const { return m_b; }
};

class Default
{
private:
    int m_a; // remarque : pas de valeur d'initialisation par défaut
    int m_b {};

public:
    Default() = default; // constructeur par défaut explicitement défini

    int a() const { return m_a; }
    int b() const { return m_b; }
};

class Implicit
{
private:
    int m_a; // remarque : pas de valeur d'initialisation par défaut
    int m_b {};

public:
    // constructeur par défaut implicite

    int a() const { return m_a; }
    int b() const { return m_b; }
};

int main()
{
    User user{}; // initialisé par défaut
    std::cout << user.a() << ' ' << user.b() << '\n';

    Default def{}; // mis à zéro, puis initialisé par défaut
    std::cout << def.a() << ' ' << def.b() << '\n';

    Implicit imp{}; // mis à zéro, puis initialisé par défaut
    std::cout << imp.a() << ' ' << imp.b() << '\n';

    return 0;
}

Sur la machine de l'auteur, ce programme affiche :


782510864 0
0 0
0 0

Remarquez que user.a n'a pas été mis à zéro avant d'être initialisé par défaut, et qu'il est donc resté non initialisé.

En pratique, cela ne devrait pas avoir d'importance, car vous devriez fournir des initialiseurs par défaut pour tous les membres de données !

Astuce

Pour une classe qui ne possède pas de constructeur par défaut fourni par l'utilisateur, l'initialisation par valeur commence par mettre la classe à zéro, alors que l'initialisation par défaut ne le fait pas. Dans ces conditions, l'initialisation par défaut peut être plus performante que l'initialisation par valeur (au prix d'une moindre sécurité). Si vous cherchez à gagner le maximum de performances dans une section de code qui initialise un grand nombre d'objets sans constructeur par défaut fourni par l'utilisateur, il peut valoir la peine de les initialiser par défaut. Vous pouvez aussi essayer de donner à la classe un constructeur par défaut au corps vide. Cela évite la mise à zéro lors d'une initialisation par valeur, mais peut empêcher d'autres optimisations.

  1. Avant C++20, une classe possédant un constructeur par défaut défini par l'utilisateur (même à corps vide) n'était pas un agrégat, alors qu'un constructeur par défaut explicitement défini ne l'empêchait pas. Si la classe était par ailleurs un agrégat, la première version la faisait donc utiliser l'initialisation par liste au lieu de l'initialisation d'agrégat. À partir de C++20, cette incohérence a été corrigée : les deux cas font de la classe un non-agrégat.

Ne créer un constructeur par défaut que lorsque cela a du sens

Un constructeur par défaut permet de créer des objets d'un type classe qui n'est pas un agrégat sans fournir de valeurs d'initialisation. Une classe ne devrait donc fournir un constructeur par défaut que lorsqu'il a du sens de créer ses objets avec toutes les valeurs par défaut.

Par exemple :

#include <iostream>

class Fraction
{
private:
    int m_numerator{ 0 };
    int m_denominator{ 1 };

public:
    Fraction() = default;
    Fraction(int numerator, int denominator)
        : m_numerator{ numerator }
        , m_denominator{ denominator }
    {
    }

    void print() const
    {
        std::cout << "Fraction(" << m_numerator << ", " << m_denominator << ")\n";
    }
};

int main()
{
    Fraction f1 {3, 5};
    f1.print();

    Fraction f2 {}; // obtient la fraction 0/1
    f2.print();

    return 0;
}

Pour une classe représentant une fraction, il est logique de permettre à l'utilisateur de créer des objets Fraction sans initialiseurs (auquel cas l'utilisateur obtient la fraction 0/1).

Considérons maintenant cette classe :

#include <iostream>
#include <string>
#include <string_view>

class Employee
{
private:
    std::string m_name{ };
    int m_id{ };

public:
    Employee(std::string_view name, int id)
        : m_name{ name }
        , m_id{ id }
    {
    }

    void print() const
    {
        std::cout << "Employee(" << m_name << ", " << m_id << ")\n";
    }
};

int main()
{
    Employee e1 { "Joe", 1 };
    e1.print();

    Employee e2 {}; // erreur de compilation : aucun constructeur correspondant
    e2.print();

    return 0;
}

Pour une classe représentant un employé, il n'a pas de sens de permettre la création d'employés sans nom. Une telle classe ne devrait donc pas avoir de constructeur par défaut, afin qu'une erreur de compilation se produise si l'utilisateur de la classe tente de le faire.
