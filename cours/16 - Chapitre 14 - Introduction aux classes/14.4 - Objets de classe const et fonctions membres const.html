14.4 — Objets de classe const et fonctions membres const

Dans la leçon 5.1 -- Constant variables (named constants), vous avez appris que les objets de types fondamentaux (int, double, char, etc.) peuvent être rendus constants à l'aide du mot-clé const. Toutes les variables const doivent être initialisées au moment de leur création.

const int x;      // erreur de compilation : non initialisée
const int y{};    // ok : initialisée à la valeur par défaut
const int z{ 5 }; // ok : initialisée par liste

De même, les objets de types classe (struct, classes et unions) peuvent également être rendus const à l'aide du mot-clé const. Ces objets doivent eux aussi être initialisés au moment de leur création.

struct Date
{
    int year {};
    int month {};
    int day {};
};

int main()
{
    const Date today { 2020, 10, 14 }; // objet de type classe const

    return 0;
}

Comme pour les variables ordinaires, vous voudrez généralement rendre const (ou constexpr) vos objets de types classe lorsque vous devez garantir qu'ils ne sont pas modifiés après leur création.

La modification des membres de données d'un objet const est interdite

Une fois qu'un objet de type classe const a été initialisé, toute tentative de modifier ses membres de données est interdite, car cela violerait la constance de l'objet. Cela concerne aussi bien la modification directe des variables membres (si elles sont publiques) que l'appel de fonctions membres qui modifient la valeur des variables membres.

struct Date
{
    int year {};
    int month {};
    int day {};

    void incrementDay()
    {
        ++day;
    }
};

int main()
{
    const Date today { 2020, 10, 14 }; // const

    today.day += 1;        // erreur de compilation : impossible de modifier un membre d'un objet const
    today.incrementDay();  // erreur de compilation : impossible d'appeler une fonction membre qui modifie un membre d'un objet const

    return 0;
}

Un objet const ne peut pas appeler de fonction membre non-const

Vous serez peut-être surpris de constater que ce code provoque également une erreur de compilation :

#include <iostream>

struct Date
{
    int year {};
    int month {};
    int day {};

    void print()
    {
        std::cout << year << '/' << month << '/' << day;
    }
};

int main()
{
    const Date today { 2020, 10, 14 }; // const

    today.print();  // erreur de compilation : impossible d'appeler une fonction membre non-const

    return 0;
}

Bien que print() ne tente pas de modifier une variable membre, notre appel today.print() viole tout de même la constance. Cela vient du fait que la fonction membre print() elle-même n'est pas déclarée const. Le compilateur ne nous laisse pas appeler une fonction membre non-const sur un objet const.

Fonctions membres const

Pour résoudre le problème ci-dessus, nous devons faire de print() une fonction membre const. Une fonction membre const est une fonction membre qui garantit qu'elle ne modifiera pas l'objet et n'appellera aucune fonction membre non-const (car celles-ci pourraient modifier l'objet).

Rendre print() const est facile : il suffit d'ajouter le mot-clé const à la déclaration de la fonction, après la liste des paramètres mais avant le corps de la fonction :

#include <iostream>

struct Date
{
    int year {};
    int month {};
    int day {};

    void print() const // désormais une fonction membre const
    {
        std::cout << year << '/' << month << '/' << day;
    }
};

int main()
{
    const Date today { 2020, 10, 14 }; // const

    today.print();  // ok : un objet const peut appeler une fonction membre const

    return 0;
}

Dans l'exemple ci-dessus, print() est devenue une fonction membre const, ce qui signifie que nous pouvons l'appeler sur des objets const (comme today).

Pour les lecteurs avancés

Pour les fonctions membres définies en dehors de la définition de la classe, le mot-clé const doit être utilisé à la fois dans la déclaration de la fonction dans la définition de la classe et dans la définition de la fonction en dehors de celle-ci. Nous montrons un exemple de ceci dans la leçon 15.2 -- Classes and header files.

Les constructeurs ne peuvent pas être rendus const, car ils doivent initialiser les membres de l'objet, ce qui nécessite de les modifier. Nous abordons les constructeurs dans la leçon 14.9 -- Introduction to constructors.

Une fonction membre const qui tente de modifier une variable membre ou d'appeler une fonction membre non-const provoquera une erreur de compilation. Par exemple :

struct Date
{
    int year {};
    int month {};
    int day {};

    void incrementDay() const // rendue const
    {
        ++day; // erreur de compilation : une fonction const ne peut pas modifier un membre
    }
};

int main()
{
    const Date today { 2020, 10, 14 }; // const

    today.incrementDay();

    return 0;
}

Dans cet exemple, incrementDay() a été marquée comme fonction membre const, mais elle tente de modifier day. Cela provoquera une erreur de compilation.

Les fonctions membres const peuvent modifier des objets qui ne sont pas membres (comme des variables locales ou des paramètres de fonction) et appeler des fonctions non membres comme d'habitude. Le qualificatif const ne s'applique qu'aux membres.

Point clé

Une fonction membre const ne peut pas : modifier l'objet implicite, appeler des fonctions membres non-const.
Une fonction membre const peut : modifier des objets qui ne sont pas l'objet implicite, appeler des fonctions membres const, appeler des fonctions non membres.

Les fonctions membres const peuvent être appelées sur des objets non-const

Les fonctions membres const peuvent aussi être appelées sur des objets non-const :

#include <iostream>

struct Date
{
    int year {};
    int month {};
    int day {};

    void print() const // const
    {
        std::cout << year << '/' << month << '/' << day;
    }
};

int main()
{
    Date today { 2020, 10, 14 }; // non-const

    today.print();  // ok : une fonction membre const peut être appelée sur un objet non-const

    return 0;
}

Comme les fonctions membres const peuvent être appelées à la fois sur des objets const et non-const, si une fonction membre ne modifie pas l'état de l'objet, elle doit être rendue const.

Bonne pratique

Une fonction membre qui ne modifie pas (et ne modifiera jamais) l'état de l'objet doit être rendue const, afin de pouvoir être appelée sur des objets const comme non-const.

Soyez prudent quant aux fonctions membres auxquelles vous appliquez const. Une fois qu'une fonction membre est const, elle peut être appelée sur des objets const. Retirer ultérieurement le const d'une fonction membre cassera tout code qui appelle cette fonction membre sur un objet const.

Objets const via le passage par référence const

Bien qu'instancier des variables locales const soit une façon de créer des objets const, un moyen plus courant d'obtenir un objet const consiste à le passer à une fonction par référence const.

Dans la leçon 12.5 -- Pass by lvalue reference, nous avons vu l'intérêt de passer les arguments de types classe par référence const plutôt que par valeur. Pour rappel, passer un argument de type classe par valeur entraîne la création d'une copie de la classe (ce qui est lent) : la plupart du temps, nous n'avons pas besoin d'une copie, et une référence vers l'argument original convient parfaitement et évite la copie. On rend généralement la référence const afin que la fonction puisse accepter des arguments lvalue const ainsi que des arguments rvalue (par exemple des littéraux et des objets temporaires).

Pouvez-vous voir ce qui ne va pas dans le code suivant ?

#include <iostream>

struct Date
{
    int year {};
    int month {};
    int day {};

    void print() // non-const
    {
        std::cout << year << '/' << month << '/' << day;
    }
};

void doSomething(const Date& date)
{
    date.print();
}

int main()
{
    Date today { 2020, 10, 14 }; // non-const
    today.print();

    doSomething(today);

    return 0;
}

La réponse est que, à l'intérieur de la fonction doSomething(), date est traité comme un objet const (puisqu'il a été passé par référence const). Or, avec ce date const, nous appelons la fonction membre non-const print(). Comme nous ne pouvons pas appeler une fonction membre non-const sur un objet const, cela provoque une erreur de compilation.

La correction est simple : rendre print() const :

#include <iostream>

struct Date
{
    int year {};
    int month {};
    int day {};

    void print() const // désormais const
    {
        std::cout << year << '/' << month << '/' << day;
    }
};

void doSomething(const Date& date)
{
    date.print();
}

int main()
{
    Date today { 2020, 10, 14 }; // non-const
    today.print();

    doSomething(today);

    return 0;
}

Désormais, dans la fonction doSomething(), le date const peut appeler avec succès la fonction membre const print().

Surcharge const et non-const des fonctions membres

Enfin, bien que cela ne soit pas très fréquent, il est possible de surcharger une fonction membre avec une version const et une version non-const de la même fonction. Cela fonctionne car le qualificatif const fait partie de la signature de la fonction : deux fonctions qui ne diffèrent que par leur constance sont donc considérées comme distinctes.

#include <iostream>

struct Something
{
    void print()
    {
        std::cout << "non-const\n";
    }

    void print() const
    {
        std::cout << "const\n";
    }
};

int main()
{
    Something s1{};
    s1.print(); // appelle print()

    const Something s2{};
    s2.print(); // appelle print() const

    return 0;
}

Ce programme affiche :

non-const
const

La surcharge d'une fonction par une version const et une version non-const se fait typiquement lorsque la valeur de retour doit différer selon la constance. C'est assez rare.
