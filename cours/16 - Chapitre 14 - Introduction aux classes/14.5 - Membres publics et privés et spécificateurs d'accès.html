14.5 — Membres publics et privés et spécificateurs d'accès

Imaginez que vous marchez dans la rue par une fraîche journée d'automne, en mangeant un burrito. Vous cherchez un endroit où vous asseoir et vous regardez autour de vous. À votre gauche se trouve un parc, avec une pelouse tondue et des arbres qui procurent de l'ombre, quelques bancs peu confortables et des enfants bruyants sur l'aire de jeux voisine. À votre droite se trouve la résidence d'un inconnu. À travers la fenêtre, vous apercevez un fauteuil inclinable bien confortable et une cheminée où crépite un feu.

En soupirant profondément, vous choisissez le parc.

Ce qui détermine votre choix, c'est que le parc est un espace public, alors que la résidence est privée. Vous (et n'importe qui d'autre) avez le droit d'accéder librement aux espaces publics. En revanche, seuls les occupants de la résidence (ou les personnes ayant reçu une autorisation explicite d'entrer) peuvent accéder à la résidence privée.

Accès aux membres

Un concept semblable s'applique aux membres d'un type classe. Chaque membre d'un type classe possède une propriété appelée niveau d'accès, qui détermine qui peut accéder à ce membre.

C++ dispose de trois niveaux d'accès différents : public, privé et protégé. Dans cette leçon, nous étudierons les deux niveaux d'accès couramment utilisés : public et privé.

Contenu associé

Nous abordons le niveau d'accès protégé dans le chapitre consacré à l'héritage (leçon 24.5 -- Héritage et spécificateurs d'accès).

Chaque fois qu'un membre est accédé, le compilateur vérifie si le niveau d'accès du membre autorise cet accès. Si l'accès n'est pas autorisé, le compilateur génère une erreur de compilation. Ce système de niveaux d'accès est parfois appelé informellement contrôles d'accès (access controls).

Les membres d'une struct sont publics par défaut

Les membres dont le niveau d'accès est public sont appelés membres publics. Les membres publics sont des membres d'un type classe qui ne font l'objet d'aucune restriction quant à leur accès. Tout comme le parc de notre analogie introductive, les membres publics peuvent être accédés par n'importe qui (à condition d'être dans leur portée).

Les membres publics peuvent être accédés par les autres membres de la même classe. Notamment, les membres publics peuvent aussi être accédés par le public, nom donné au code qui se trouve en dehors des membres d'un type classe donné. Parmi le public figurent les fonctions non membres, ainsi que les membres d'autres types classes.

Point clé

Les membres d'une struct sont publics par défaut. Les membres publics peuvent être accédés par les autres membres du type classe, ainsi que par le public.

Le terme « le public » désigne le code qui se trouve en dehors des membres d'un type classe donné. Cela comprend les fonctions non membres, ainsi que les membres d'autres types classes.

Par défaut, tous les membres d'une struct sont des membres publics.

Considérons la struct suivante :

#include <iostream>

struct Date
{
    // struct members are public by default, can be accessed by anyone
    int year {};       // public by default
    int month {};      // public by default
    int day {};        // public by default

    void print() const // public by default
    {
        // public members can be accessed in member functions of the class type
        std::cout << year << '/' << month << '/' << day;
    }
};

// non-member function main is part of "the public"
int main()
{
    Date today { 2020, 10, 14 }; // aggregate initialize our struct

    // public members can be accessed by the public
    today.day = 16; // okay: the day member is public
    today.print();  // okay: the print() member function is public

    return 0;
}

Dans cet exemple, les membres sont accédés à trois endroits :

  • Dans la fonction membre print(), nous accédons aux membres year, month et day de l'objet implicite.
  • Dans main(), nous accédons directement à today.day pour lui attribuer une valeur.
  • Dans main(), nous appelons la fonction membre today.print().

Ces trois accès sont autorisés, car les membres publics peuvent être accédés depuis n'importe où.

Comme main() n'est pas un membre de Date, elle est considérée comme faisant partie de le public. Or, le public a accès aux membres publics : main() peut donc accéder directement aux membres de Date (ce qui inclut l'appel à today.print()).

Les membres d'une classe sont privés par défaut

Les membres dont le niveau d'accès est privé sont appelés membres privés. Les membres privés sont des membres d'un type classe qui ne peuvent être accédés que par les autres membres de la même classe.

Considérons l'exemple suivant, presque identique au précédent :

#include <iostream>

class Date // now a class instead of a struct
{
    // class members are private by default, can only be accessed by other members
    int m_year {};     // private by default
    int m_month {};    // private by default
    int m_day {};      // private by default

    void print() const // private by default
    {
        // private members can be accessed in member functions
        std::cout << m_year << '/' << m_month << '/' << m_day;
    }
};

int main()
{
    Date today { 2020, 10, 14 }; // compile error: can no longer use aggregate initialization

    // private members can not be accessed by the public
    today.m_day = 16; // compile error: the m_day member is private
    today.print();    // compile error: the print() member function is private

    return 0;
}

Dans cet exemple, les membres sont accédés aux mêmes trois endroits :

  • Dans la fonction membre print(), nous accédons aux membres m_year, m_month et m_day de l'objet implicite.
  • Dans main(), nous accédons directement à today.m_day pour lui attribuer une valeur.
  • Dans main(), nous appelons la fonction membre today.print().

Cependant, si vous compilez ce programme, vous remarquerez que trois erreurs de compilation sont générées.

Dans main(), les instructions today.m_day = 16 et today.print() génèrent désormais des erreurs de compilation. En effet, main() fait partie du public, et le public n'est pas autorisé à accéder directement aux membres privés.

Dans print(), l'accès aux membres m_year, m_month et m_day est autorisé. En effet, print() est un membre de la classe, et les membres de la classe sont autorisés à accéder aux membres privés.

D'où vient alors la troisième erreur de compilation ? De manière peut-être surprenante, l'initialisation de today provoque désormais une erreur de compilation. Dans la leçon 13.8 -- Initialisation agrégée des structs, nous avons indiqué qu'un agrégat ne peut pas avoir de « membres de données non statiques privés ou protégés ». Notre classe Date possède des membres de données privés (puisque les membres des classes sont privés par défaut) : elle ne répond donc pas à la définition d'un agrégat. Par conséquent, nous ne pouvons plus utiliser l'initialisation agrégée pour l'initialiser.

Nous verrons comment initialiser correctement les classes (qui sont généralement des non-agrégats) dans la prochaine leçon 14.9 -- Introduction aux constructeurs.

Point clé

Les membres d'une classe sont privés par défaut. Les membres privés peuvent être accédés par les autres membres de la classe, mais pas par le public.

Une classe possédant des membres privés n'est plus un agrégat ; elle ne peut donc plus utiliser l'initialisation agrégée.

Nommer vos variables membres privées

En C++, la convention courante consiste à nommer les membres de données privés en commençant par le préfixe « m_ ». Cela répond à quelques raisons importantes.

Considérons la fonction membre suivante d'une classe quelconque :

// Some member function that sets private member m_name to the value of the name parameter
void setName(std::string_view name)
{
    m_name = name;
}

Premièrement, le préfixe « m_ » permet de distinguer facilement les membres de données des paramètres de fonction ou des variables locales au sein d'une fonction membre. On voit immédiatement que « m_name » est un membre, et que « name » n'en est pas un. Cela indique clairement que cette fonction modifie l'état de la classe. C'est important, car lorsque l'on modifie la valeur d'un membre de données, cette modification persiste au-delà de la portée de la fonction membre (alors que les modifications apportées aux paramètres de fonction ou aux variables locales ne persistent généralement pas).

C'est la même raison qui nous conduit à recommander le préfixe « s_ » pour les variables statiques locales, et le préfixe « g_ » pour les variables globales.

Deuxièmement, le préfixe « m_ » aide à éviter les collisions de noms entre les variables membres privées, et les noms des variables locales, des paramètres de fonction et des fonctions membres.

Si nous avions nommé notre membre privé name au lieu de m_name, alors :

  • Notre paramètre de fonction name aurait masqué le membre de données privé name (on parle d'occultation, ou shadowing).
  • Si nous avions eu une fonction membre nommée name, nous aurions obtenu une erreur de compilation due à une redéfinition de l'identifiant name.

Bonne pratique

Envisagez de nommer vos membres de données privés en commençant par le préfixe « m_ », afin de les distinguer des noms des variables locales, des paramètres de fonction et des fonctions membres.

Les membres publics des classes peuvent également suivre cette convention si vous le souhaitez. En revanche, les membres publics des structs n'utilisent généralement pas ce préfixe, car les structs ont généralement peu de fonctions membres (voire aucune).

Définir les niveaux d'accès à l'aide des spécificateurs d'accès

Par défaut, les membres des structs (et des unions) sont publics, et ceux des classes sont privés.

Toutefois, nous pouvons définir explicitement le niveau d'accès de nos membres à l'aide d'un spécificateur d'accès (access specifier). Un spécificateur d'accès définit le niveau d'accès de tous les membres qui le suivent. C++ fournit trois spécificateurs d'accès : public:, private: et protected:.

Dans l'exemple suivant, nous utilisons le spécificateur public: pour que la fonction membre print() puisse être utilisée par le public, et le spécificateur private: pour rendre nos membres de données privés.

class Date
{
// Any members defined here would default to private

public: // here's our public access specifier

    void print() const // public due to above public: specifier
    {
        // members can access other private members
        std::cout << m_year << '/' << m_month << '/' << m_day;
    }

private: // here's our private access specifier 

    int m_year { 2020 };  // private due to above private: specifier
    int m_month { 14 }; // private due to above private: specifier
    int m_day { 10 };   // private due to above private: specifier
};

int main()
{
    Date d{};
    d.print();  // okay, main() allowed to access public members

    return 0;
}

Cet exemple se compile. Comme print() est un membre public grâce au spécificateur public:, main() (qui fait partie du public) est autorisée à y accéder.

Comme nous avons des membres privés, nous ne pouvons pas initialiser d par agrégation. Pour cet exemple, nous utilisons à la place l'initialisation par défaut des membres (solution provisoire).

Puisque les classes sont privées par défaut, vous pouvez omettre le spécificateur private: en début de classe :

class Foo
{
// private access specifier not required here since classes default to private members
    int m_something {};  // private by default
};

Toutefois, comme les classes et les structs n'ont pas les mêmes niveaux d'accès par défaut, de nombreux développeurs préfèrent être explicites :

class Foo
{
private: // redundant, but makes it clear that what follows is private
    int m_something {};  // private by default
};

Bien que cela soit techniquement redondant, l'utilisation explicite du spécificateur private: indique clairement que les membres qui suivent sont privés, sans qu'il soit nécessaire de déduire le niveau d'accès par défaut selon que Foo a été définie comme une classe ou comme une struct.

Résumé des niveaux d'accès

Voici un tableau récapitulatif des différents niveaux d'accès :

Niveau d'accès Spécificateur d'accès Accès par les membres Accès par les classes dérivées Accès public
Public public: oui oui oui
Protégé protected: oui oui non
Privé private: oui non non

Un type classe peut utiliser autant de spécificateurs d'accès qu'il le souhaite, dans n'importe quel ordre, et ils peuvent être répétés (par exemple, vous pouvez avoir des membres publics, puis des membres privés, puis à nouveau des membres publics).

La plupart des classes utilisent à la fois les spécificateurs private et public pour différents membres. Nous en verrons un exemple dans la section suivante.

Bonnes pratiques concernant les niveaux d'accès pour les structs et les classes

Maintenant que nous avons vu ce que sont les niveaux d'accès, voyons comment les utiliser.

Les structs devraient éviter complètement les spécificateurs d'accès : tous leurs membres seront alors publics par défaut. Nous voulons que nos structs soient des agrégats, et les agrégats ne peuvent avoir que des membres publics. Utiliser le spécificateur public: serait redondant avec la valeur par défaut, tandis qu'utiliser private: ou protected: ferait de la struct un non-agrégat.

Les classes ne devraient généralement avoir que des membres de données privés (ou protégés), soit grâce au niveau d'accès privé par défaut, soit grâce au spécificateur private: (ou protected:). Nous discuterons de la justification de ce point dans la prochaine leçon 14.6 -- Fonctions d'accès.

Les classes possèdent normalement des fonctions membres publiques (afin que ces fonctions puissent être utilisées par le public une fois l'objet créé). Toutefois, il arrive que certaines fonctions membres soient rendues privées (ou protégées) lorsqu'elles ne sont pas destinées à être utilisées par le public.

Bonne pratique

Les classes devraient généralement rendre leurs variables membres privées (ou protégées), et leurs fonctions membres publiques.

Les structs devraient généralement éviter d'utiliser les spécificateurs d'accès (tous leurs membres sont publics par défaut).

Les niveaux d'accès s'appliquent par classe

Une subtilité des niveaux d'accès en C++, souvent omise ou mal comprise, est que l'accès aux membres est défini par classe, et non par objet.

Vous savez déjà qu'une fonction membre peut accéder directement aux membres privés (de l'objet implicite). Mais, comme les niveaux d'accès sont définis par classe et non par objet, une fonction membre peut également accéder directement aux membres privés de N'IMPORTE QUEL autre objet du même type classe qui est dans sa portée.

Illustrons cela par un exemple :

#include <iostream>
#include <string>
#include <string_view>

class Person
{
private:
    std::string m_name{};

public:
    void kisses(const Person& p) const
    {
        std::cout << m_name << " kisses " << p.m_name << '\n';
    }

    void setName(std::string_view name)
    {
        m_name = name;
    }
};

int main()
{
    Person joe;
    joe.setName("Joe");

    Person kate;
    kate.setName("Kate");

    joe.kisses(kate);

    return 0;
}

Ce programme affiche :


Joe kisses Kate

Plusieurs points sont à remarquer ici.

Premièrement, m_name a été rendu privé ; il ne peut donc être accédé que par les membres de la classe Person (et non par le public).

Deuxièmement, comme notre classe possède des membres privés, elle n'est pas un agrégat, et nous ne pouvons pas utiliser l'initialisation agrégée pour initialiser nos objets Person. En attendant une solution appropriée à ce problème (que nous verrons plus tard), nous avons créé une fonction membre publique nommée setName() qui permet d'attribuer un nom à nos objets Person.

Troisièmement, comme kisses() est une fonction membre, elle a un accès direct au membre privé m_name. Vous serez peut-être surpris de constater qu'elle a également un accès direct à p.m_name ! Cela fonctionne parce que p est un objet Person, et que kisses() peut accéder aux membres privés de n'importe quel objet Person dans sa portée !

Nous verrons d'autres exemples d'utilisation de ce mécanisme dans le chapitre consacré à la surcharge d'opérateurs.

La différence technique et pratique entre structs et classes

Maintenant que nous avons vu les niveaux d'accès, nous pouvons enfin aborder les différences techniques entre les structs et les classes. Prêt ?

Une classe rend ses membres privés par défaut, alors qu'une struct rend les siens publics par défaut.

…

Oui, c'est tout.

Note de l'auteur

Pour être pointilleux, il existe une autre petite différence : les structs héritent publiquement des autres types classes, tandis que les classes héritent de manière privée. Nous verrons ce que cela signifie dans le chapitre sur l'héritage, mais ce point est en pratique sans importance, car vous ne devriez de toute façon pas vous appuyer sur les valeurs par défaut pour l'héritage.

En pratique, nous utilisons les structs et les classes différemment.

En règle générale, utilisez une struct lorsque toutes les conditions suivantes sont réunies :

  • Vous avez une simple collection de données qui ne tire pas profit d'une restriction d'accès.
  • L'initialisation agrégée suffit.
  • Vous n'avez ni invariants de classe, ni besoins d'initialisation ou de nettoyage particuliers.

Quelques exemples d'utilisation de structs : des données globales de programme constexpr, une struct de point (une simple collection de membres int qui ne gagnent pas à être privés), ou des structs servant à renvoyer un ensemble de données depuis une fonction.

Dans les autres cas, utilisez une classe.

Nous voulons que nos structs soient des agrégats. Ainsi, si vous utilisez une fonctionnalité qui fait de votre struct un non-agrégat, vous devriez probablement utiliser une classe à la place (en suivant toutes les bonnes pratiques relatives aux classes).

Quiz

Question n° 1

a) Qu'est-ce qu'un membre public ?

Solution

Un membre public est un membre d'une classe qui peut être accédé par n'importe qui, y compris par les autres membres de la même classe et par le public.

b) Qu'est-ce qu'un membre privé ?

Solution

Un membre privé est un membre d'une classe qui ne peut être accédé que par les autres membres de la classe.

c) Qu'est-ce qu'un spécificateur d'accès ?

Solution

Un spécificateur d'accès détermine qui a accès aux membres qui suivent le spécificateur.

d) Combien existe-t-il de spécificateurs d'accès, et quels sont-ils ?

Solution

Il en existe trois : public, privé et protégé.

Question n° 2

a) Écrivez une classe nommée Point3d. Cette classe doit contenir :

  • Trois variables membres privées de type int nommées m_x, m_y et m_z ;
  • Une fonction membre publique nommée setValues() qui permet de définir les valeurs de m_x, m_y et m_z ;
  • Une fonction membre publique nommée print() qui affiche le point selon le format suivant : <m_x, m_y, m_z>

Assurez-vous que le programme suivant s'exécute correctement :

int main()
{
    Point3d point;
    point.setValues(1, 2, 3);

    point.print();
    std::cout << '\n';

    return 0;
}

Cela doit afficher :


<1, 2, 3>
Solution 
#include <iostream>

class Point3d
{
private:
    int m_x {};
    int m_y {};
    int m_z {};

public:
    void setValues(int x, int y, int z)
    {
        m_x = x;
        m_y = y;
        m_z = z;
    }

    void print() const
    {
        std::cout << '<' << m_x << ", " << m_y << ", " << m_z << '>';
    }
};

int main()
{
    Point3d point;
    point.setValues(1, 2, 3);

    point.print();
    std::cout << '\n';

    return 0;
}

b) Ajoutez à votre classe Point3d une fonction nommée isEqual(). Le code suivant doit s'exécuter correctement :

int main()
{
    Point3d point1{};
    point1.setValues(1, 2, 3);

    Point3d point2{};
    point2.setValues(1, 2, 3);

    std::cout << "point 1 and point 2 are" << (point1.isEqual(point2) ? "" : " not") << " equal\n";

    Point3d point3{};
    point3.setValues(3, 4, 5);

    std::cout << "point 1 and point 3 are" << (point1.isEqual(point3) ? "" : " not") << " equal\n";

    return 0;
}

Cela doit afficher :


point 1 and point 2 are equal
point 1 and point 3 are not equal
Solution 
#include <iostream>

class Point3d
{
private:
    int m_x {};
    int m_y {};
    int m_z {};

public:
    void setValues(int x, int y, int z)
    {
        m_x = x;
        m_y = y;
        m_z = z;
    }

    void print() const
    {
        std::cout << '<' << m_x << ", " << m_y << ", " << m_z << '>';
    }

    // We can use the fact that access controls work on a per-class basis here
    // to directly access the private members of Point3d parameter p
    bool isEqual(const Point3d& p) const
    {
        return (m_x == p.m_x) && (m_y == p.m_y) && (m_z == p.m_z);
    }
};

int main()
{
    Point3d point1{};
    point1.setValues(1, 2, 3);

    Point3d point2{};
    point2.setValues(1, 2, 3);

    std::cout << "point 1 and point 2 are" << (point1.isEqual(point2) ? "" : " not") << " equal\n";

    Point3d point3{};
    point3.setValues(3, 4, 5);

    std::cout << "point 1 and point 3 are" << (point1.isEqual(point3) ? "" : " not") << " equal\n";

    return 0;
}
