14.1 — Introduction à la programmation orientée objet

La programmation procédurale

Dans la leçon 1.3 -- Introduction aux objets et aux variables, nous avons défini un objet en C++ comme « une zone de mémoire pouvant servir à stocker des valeurs ». Un objet portant un nom est appelé une variable. Nos programmes C++ ont jusqu'ici consisté en des listes séquentielles d'instructions destinées à l'ordinateur, qui définissent des données (à travers des objets) et les opérations effectuées sur ces données (à travers des fonctions contenant des instructions et des expressions).

Jusqu'à présent, nous avons pratiqué un type de programmation appelé programmation procédurale. Dans la programmation procédurale, l'accent est mis sur la création de « procédures » (qui sont appelées fonctions en C++) qui implémentent la logique de notre programme. Nous transmettons des objets de données à ces fonctions, celles-ci effectuent des opérations sur les données, puis renvoient éventuellement un résultat à utiliser par l'appelant.

En programmation procédurale, les fonctions et les données sur lesquelles elles opèrent sont des entités distinctes. Le programmeur est chargé de combiner les fonctions et les données pour obtenir le résultat souhaité. Cela conduit à du code qui ressemble à ceci :

eat(you, apple);

Regardez maintenant autour de vous : partout se trouvent des objets, des livres, des bâtiments, de la nourriture, et même vous. Ces objets ont deux composantes majeures : 1) un certain nombre de propriétés associées (par exemple le poids, la couleur, la taille, la solidité, la forme, etc.), et 2) un certain nombre de comportements qu'ils peuvent présenter (par exemple être ouvert, faire chauffer quelque chose d'autre, etc.). Ces propriétés et ces comportements sont indissociables.

En programmation, les propriétés sont représentées par des objets, et les comportements par des fonctions. La programmation procédurale représente donc assez mal la réalité, puisqu'elle sépare les propriétés (objets) et les comportements (fonctions).

Qu'est-ce que la programmation orientée objet ?

Dans la programmation orientée objet (souvent abrégée POO), l'accent est mis sur la création de types de données définis par le programme, qui contiennent à la fois des propriétés et un ensemble de comportements bien définis. Le terme « objet » en POO désigne les objets que l'on peut instancier à partir de ces types.

Cela conduit à du code qui ressemble davantage à ceci :

you.eat(apple);

Cela rend plus clair le sujet (you), le comportement invoqué (eat()) et les objets qui accompagnent ce comportement (apple).

Comme les propriétés et les comportements ne sont plus séparés, les objets sont plus faciles à modulariser, ce qui rend nos programmes plus faciles à écrire et à comprendre, et offre également un plus haut degré de réutilisabilité du code. Ces objets fournissent aussi une manière plus intuitive de manipuler nos données, en nous permettant de définir comment nous interagissons avec eux, et comment ils interagissent avec d'autres objets.

Nous verrons comment créer de tels objets dans la prochaine leçon.

Un exemple procédural et un exemple de type POO

Voici un court programme écrit dans un style procédural, qui affiche le nom et le nombre de pattes d'un animal :

#include <iostream>
#include <string_view>

enum AnimalType
{
    cat,
    dog,
    chicken,
};

constexpr std::string_view animalName(AnimalType type)
{
    switch (type)
    {
    case cat: return "cat";
    case dog: return "dog";
    case chicken: return "chicken";
    default:  return "";
    }
}

constexpr int numLegs(AnimalType type)
{
    switch (type)
    {
    case cat: return 4;
    case dog: return 4;
    case chicken: return 2;
    default:  return 0;
    }
}


int main()
{
    constexpr AnimalType animal{ cat };
    std::cout << "A " << animalName(animal) << " has " << numLegs(animal) << " legs\n";

    return 0;
}

Dans ce programme, nous avons écrit des fonctions qui nous permettent par exemple d'obtenir le nombre de pattes d'un animal, ou le nom d'un animal.

Cela fonctionne très bien, mais considérez ce qui se passe lorsque nous voulons modifier ce programme pour que notre animal devienne un snake. Pour ajouter un serpent à notre code, il faudrait modifier AnimalType, numLegs() et animalName(). Si cette base de code était plus grande, il faudrait aussi mettre à jour toute autre fonction utilisant AnimalType : si AnimalType était employé à de nombreux endroits, il pourrait y avoir beaucoup de code à toucher (et potentiellement à casser).

Écrivons maintenant le même programme (produisant la même sortie) avec un état d'esprit plus orienté objet :

#include <iostream>
#include <string_view>

struct Cat
{
    std::string_view name{ "cat" };
    int numLegs{ 4 };
};

struct Dog
{
    std::string_view name{ "dog" };
    int numLegs{ 4 };
};

struct Chicken
{
    std::string_view name{ "chicken" };
    int numLegs{ 2 };
};

int main()
{
    constexpr Cat animal;
    std::cout << "a " << animal.name << " has " << animal.numLegs << " legs\n";

    return 0;
}

Dans cet exemple, chaque animal est un type défini par le programme, et ce type gère tout ce qui concerne cet animal (ce qui, dans le cas présent, se limite à mémoriser le nom et le nombre de pattes).

Considérons maintenant le cas où nous voulons remplacer notre animal par un serpent. Il suffit de créer un type Snake et de l'utiliser à la place de Cat. Très peu de code existant doit être modifié, ce qui signifie beaucoup moins de risques de casser quelque chose qui fonctionne déjà.

Tel qu'il est présenté, notre exemple avec Cat, Dog et Chicken contient beaucoup de répétitions (chacun définit exactement le même ensemble de membres). Dans ce cas, il pourrait être préférable de créer une structure commune Animal et de créer une instance pour chaque animal. Mais que faire si nous voulons ajouter à Chicken un membre qui ne s'applique pas aux autres animaux (par exemple wormsPerDay) ? Avec une structure Animal commune, tous les animaux recevraient ce membre. Avec notre modèle orienté objet, nous pouvons restreindre ce membre aux objets Chicken.

La POO apporte d'autres avantages

À l'école, lorsque vous rendez vos devoirs de programmation, votre travail est pour l'essentiel terminé. Votre professeur ou l'assistant de votre enseignant exécutera votre code pour vérifier qu'il produit le bon résultat. Il le produit ou ne le produit pas, et vous êtes noté en conséquence. Votre code est probablement jeté à ce stade.

En revanche, lorsque vous soumettez votre code dans un dépôt utilisé par d'autres développeurs, ou dans une application utilisée par de vrais utilisateurs, c'est une tout autre affaire. Une nouvelle version du système d'exploitation ou d'un logiciel cassera votre code. Des utilisateurs trouveront une erreur de logique que vous avez commise. Un partenaire commercial exigera une nouvelle fonctionnalité. D'autres développeurs devront étendre votre code sans le casser. Votre code doit pouvoir évoluer, parfois de façon importante, et il doit le faire avec un investissement de temps minimal, un minimum de maux de tête et un minimum de régressions.

La meilleure façon d'y parvenir est de garder votre code aussi modulaire (et aussi peu redondant) que possible. Pour cela, la POO apporte également plusieurs autres concepts utiles : l'héritage, l'encapsulation, l'abstraction et le polymorphisme.

Note de l'auteur

Les concepteurs de langages ont une philosophie : ne jamais utiliser un petit mot là où un grand fera l'affaire.

Et pourquoi le mot abbreviation est-il si long ?

Nous couvrirons tous ces concepts en temps voulu, et verrons comment ils peuvent aider à rendre votre code moins redondant et plus facile à modifier et à étendre. Une fois que vous serez bien familiarisé avec la POO et que le déclic se sera produit, vous ne voudrez probablement plus jamais revenir à la programmation purement procédurale.

Cela dit, la POO ne remplace pas la programmation procédurale : elle vous fournit simplement des outils supplémentaires dans votre boîte à outils pour gérer la complexité lorsque c'est nécessaire.

Le terme « objet »

Notez que le terme « objet » est un peu surchargé, ce qui cause une certaine confusion. En programmation traditionnelle, un objet est une zone de mémoire servant à stocker des valeurs. Et c'est tout. En programmation orientée objet, un « objet » désigne à la fois un objet au sens traditionnel et un élément qui combine propriétés et comportements. Dans ces tutoriels, nous privilégierons le sens traditionnel du terme objet, et nous utiliserons l'expression « objet de classe » lorsque nous ferons spécifiquement référence aux objets de la POO.

Question n° 1

Mettez à jour l'exemple procédural des animaux ci-dessus et instanciez un serpent à la place d'un chat.

#include <iostream>
#include <string_view>

enum AnimalType
{
    cat,
    dog,
    chicken,
    snake,
};

constexpr std::string_view animalName(AnimalType type)
{
    switch (type)
    {
    case cat: return "cat";
    case dog: return "dog";
    case chicken: return "chicken";
    case snake: return "snake";
    default:  return "";
    }
}

constexpr int numLegs(AnimalType type)
{
    switch (type)
    {
    case cat: return 4;
    case dog: return 4;
    case chicken: return 2;
    case snake: return 0;

    default:  return 0;
    }
