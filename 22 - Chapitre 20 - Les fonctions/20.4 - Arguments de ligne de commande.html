20.4 — Arguments de ligne de commande

Le besoin d'arguments de ligne de commande

Comme vous l'avez appris dans la leçon 0.5 -- Introduction au compilateur, à l'éditeur de liens et aux bibliothèques, lorsque vous compilez et liez votre programme, le résultat est un fichier exécutable. Lorsqu'un programme est lancé, l'exécution commence au début de la fonction appelée main(). Jusqu'à présent, nous avons déclaré main de cette façon :

int main()

Remarquez que cette version de main() ne prend aucun paramètre. Pourtant, de nombreux programmes ont besoin d'une forme d'entrée pour fonctionner. Par exemple, imaginons que vous écriviez un programme nommé Thumbnail qui lit un fichier image, puis produit une miniature (une version plus petite de l'image). Comment Thumbnail saurait-il quelle image lire et traiter ? L'utilisateur doit disposer d'un moyen d'indiquer au programme le fichier à ouvrir. Pour cela, vous pourriez procéder ainsi :

// Programme : Thumbnail
#include <iostream>
#include <string>

int main()
{
    std::cout << "Veuillez saisir le nom d'un fichier image pour créer une miniature : ";
    std::string filename{};
    std::cin >> filename;

    // ouvrir le fichier image
    // créer la miniature
    // afficher la miniature
}

Cette approche présente cependant un problème potentiel. À chaque exécution, le programme attend que l'utilisateur saisisse une entrée. Ce n'est pas forcément gênant si vous lancez ce programme manuellement, une fois, depuis la ligne de commande. Mais c'est problématique dans d'autres cas, par exemple lorsque vous voulez exécuter ce programme sur de nombreux fichiers, ou lorsqu'il doit être lancé par un autre programme.

Examinons ces cas plus en détail.

Considérons le cas où vous souhaitez créer des miniatures de toutes les images d'un répertoire donné. Comment faire ? Vous pourriez exécuter ce programme autant de fois qu'il y a d'images dans le répertoire, en tapant chaque nom de fichier à la main. Mais s'il y a des centaines d'images, cela pourrait prendre une journée entière ! Une bonne solution consisterait à écrire un programme qui parcourt chaque nom de fichier du répertoire, en appelant Thumbnail une fois pour chaque fichier.

Considérons maintenant le cas où vous exploitez un site web et souhaitez créer une miniature à chaque fois qu'un utilisateur envoie une image sur votre site. Ce programme n'est pas conçu pour recevoir des entrées depuis le web : comment l'utilisateur pourrait-il alors saisir un nom de fichier ? Une bonne solution consisterait à faire appeler automatiquement Thumbnail par votre serveur web après l'envoi.

Dans ces deux cas, nous avons réellement besoin d'un moyen pour un programme externe de transmettre le nom de fichier à notre programme Thumbnail au moment de son lancement, plutôt que de faire attendre Thumbnail que l'utilisateur saisisse le nom de fichier une fois démarré.

Les arguments de ligne de commande (command line arguments) sont des arguments de type chaîne, optionnels, que le système d'exploitation transmet au programme lors de son lancement. Le programme peut alors les utiliser comme entrées (ou les ignorer). De même que les paramètres de fonction permettent à une fonction de recevoir des entrées d'une autre fonction, les arguments de ligne de commande permettent à des personnes ou à des programmes de fournir des entrées à un programme.

Passer des arguments de ligne de commande

Les programmes exécutables peuvent être lancés depuis la ligne de commande en invoquant leur nom. Par exemple, pour lancer l'exécutable « WordCount » situé dans le répertoire courant d'une machine Windows, vous pourriez taper :


WordCount

La commande équivalente sur un système d'exploitation de type Unix serait :


./WordCount

Pour transmettre des arguments de ligne de commande à WordCount, il suffit de les lister après le nom de l'exécutable :


WordCount Myfile.txt

Lorsque WordCount est exécuté, Myfile.txt est alors fourni comme argument de ligne de commande. Un programme peut avoir plusieurs arguments de ligne de commande, séparés par des espaces :


WordCount Myfile.txt Myotherfile.txt

Si vous exécutez votre programme depuis un EDI, celui-ci devrait proposer un moyen de saisir les arguments de ligne de commande.

Dans Microsoft Visual Studio, faites un clic droit sur votre projet dans l'explorateur de solutions, puis choisissez Propriétés. Ouvrez l'élément de l'arborescence « Propriétés de configuration » et choisissez « Débogage ». Dans le volet de droite, se trouve une ligne intitulée « Arguments de commande ». Vous pouvez y saisir vos arguments de ligne de commande pour vos tests : ils seront automatiquement transmis à votre programme lors de son exécution.

Dans Code::Blocks, choisissez « Project -> Set program's arguments ».

Utiliser les arguments de ligne de commande

Maintenant que vous savez comment transmettre des arguments de ligne de commande à un programme, l'étape suivante consiste à y accéder depuis notre programme C++. Pour cela, nous utilisons une forme de main() différente de celles vues jusqu'ici. Cette nouvelle forme de main() prend deux arguments (nommés argc et argv par convention) :

int main(int argc, char* argv[])

Vous verrez parfois aussi cette écriture :

int main(int argc, char** argv)

Bien que ces deux écritures soient traitées de manière identique, nous préférons la première, car elle est intuitivement plus facile à comprendre.

argc est un paramètre entier contenant le nombre d'arguments transmis au programme (pensez à argc = argument count, le nombre d'arguments). argc vaut toujours au moins 1, car le premier argument est toujours le nom du programme lui-même. Chaque argument de ligne de commande fourni par l'utilisateur fait augmenter argc de 1.

argv est l'endroit où sont stockées les valeurs réelles des arguments (pensez à argv = argument values, les valeurs des arguments, même si le nom correct est « argument vectors », vecteurs d'arguments). Bien que la déclaration de argv soit intimidante, argv est en réalité simplement un tableau de style C de pointeurs sur char (chacun pointant vers une chaîne de style C). La longueur de ce tableau est argc.

Écrivons un court programme nommé « MyArgs » qui affiche la valeur de tous les paramètres de ligne de commande :

// Programme : MyArgs
#include <iostream>

int main(int argc, char* argv[])
{
    std::cout << "Il y a " << argc << " arguments :\n";

    // Parcourir chaque argument et afficher son numéro et sa valeur
    for (int count{ 0 }; count < argc; ++count)
    {
        std::cout << count << ' ' << argv[count] << '\n';
    }

    return 0;
}

Maintenant, lorsque nous invoquons ce programme (MyArgs) avec les arguments de ligne de commande « Myfile.txt » et « 100 », la sortie est la suivante :


There are 3 arguments:
0 C:\MyArgs
1 Myfile.txt
2 100

L'argument 0 correspond au chemin et au nom du programme en cours d'exécution. Les arguments 1 et 2 sont dans ce cas les deux paramètres de ligne de commande que nous avons transmis.

Notez que nous ne pouvons pas utiliser une boucle for basée sur un intervalle pour parcourir argv, car les boucles for basées sur un intervalle ne fonctionnent pas avec les tableaux de style C dégradés en pointeurs.

Traiter les arguments numériques

Les arguments de ligne de commande sont toujours transmis sous forme de chaînes, même lorsque la valeur fournie est de nature numérique. Pour utiliser un argument de ligne de commande comme nombre, vous devez le convertir de chaîne en nombre. Malheureusement, C++ rend cette opération un peu plus difficile qu'elle ne devrait l'être.

La méthode C++ pour cela est la suivante :

#include <iostream>
#include <sstream> // pour std::stringstream
#include <string>

int main(int argc, char* argv[])
{
    if (argc <= 1)
    {
        // Sur certains systèmes d'exploitation, argv[0] peut être une chaîne vide au lieu du nom du programme.
        // Nous adaptons notre réponse selon que argv[0] est vide ou non.
        if (argv[0])
            std::cout << "Utilisation : " << argv[0] << " <nombre>" << '\n';
        else
            std::cout << "Utilisation : <nom du programme> <nombre>" << '\n';

        return 1;
    }

    std::stringstream convert{ argv[1] }; // crée une variable stringstream nommée convert, initialisée avec la valeur de argv[1]

    int myint{};
    if (!(convert >> myint)) // effectue la conversion
        myint = 0; // si la conversion échoue, myint reçoit une valeur par défaut

    std::cout << "Entier obtenu : " << myint << '\n';

    return 0;
}

Lorsqu'il est exécuté avec l'entrée « 567 », ce programme affiche :


Got integer: 567

std::stringstream fonctionne à peu près comme std::cin. Ici, nous l'initialisons avec la valeur de argv[1], afin de pouvoir utiliser operator>> pour extraire la valeur dans une variable entière (de la même façon que nous le ferions avec std::cin).

Nous reviendrons plus en détail sur std::stringstream dans un chapitre ultérieur.

Le système d'exploitation analyse d'abord les arguments de ligne de commande

Lorsque vous saisissez quelque chose dans la ligne de commande (ou lancez votre programme depuis l'EDI), c'est au système d'exploitation de traduire et de router cette requête de manière appropriée. Cela implique non seulement l'exécution du programme, mais aussi l'analyse des arguments pour déterminer comment ils doivent être traités et transmis à l'application.

En général, les systèmes d'exploitation ont des règles particulières concernant le traitement des caractères spéciaux comme les guillemets doubles et les barres obliques inverses.

Par exemple :

MyArgs Hello world!

affiche :


There are 3 arguments:
0 C:\MyArgs
1 Hello
2 world!

En général, les chaînes placées entre guillemets doubles sont considérées comme faisant partie d'une même chaîne :

MyArgs "Hello world!"

affiche :


There are 2 arguments:
0 C:\MyArgs
1 Hello world!

La plupart des systèmes d'exploitation permettent d'inclure un guillemet double littéral en le précédant d'une barre oblique inverse :

MyArgs \"Hello world!\"

affiche :


There are 3 arguments:
0 C:\MyArgs
1 "Hello
2 world!"

D'autres caractères peuvent également nécessiter une barre oblique inverse ou un échappement selon la façon dont votre système d'exploitation les interprète.

Conclusion

Les arguments de ligne de commande offrent un excellent moyen pour les utilisateurs ou d'autres programmes de transmettre des données d'entrée à un programme au moment de son démarrage. Envisagez de faire de toute donnée d'entrée nécessaire au démarrage d'un programme un paramètre de ligne de commande. Si la ligne de commande n'est pas fournie, vous pouvez toujours le détecter et demander la saisie à l'utilisateur. Ainsi, votre programme peut fonctionner dans les deux cas.
