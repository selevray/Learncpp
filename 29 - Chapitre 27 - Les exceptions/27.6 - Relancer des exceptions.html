27.6 — Relancer des exceptions

Il arrive parfois que vous souhaitiez attraper une exception sans pouvoir la traiter complètement à l'endroit où vous la capturez, ou sans en avoir le droit. C'est courant lorsque vous voulez journaliser une erreur, mais laisser l'appelant se charger réellement de la traiter.

Lorsqu'une fonction peut utiliser un code de retour, la situation est simple. Considérez l'exemple suivant :

Database* createDatabase(std::string filename)
{
    Database* d {};

    try
    {
        d = new Database{};
        d->open(filename); // on suppose que ceci lève une exception de type int en cas d'échec
        return d;
    }
    catch (int exception)
    {
        // La création de la base de données a échoué
        delete d;
        // Écrire une erreur dans un fichier journal global
        g_log.logError("Creation of Database failed");
    }

    return nullptr;
}

Dans le code ci-dessus, la fonction doit créer un objet Database, ouvrir la base de données et renvoyer l'objet Database. Si quelque chose se passe mal (par exemple si l'on passe un mauvais nom de fichier), le gestionnaire d'exception journalise une erreur, puis renvoie raisonnablement un pointeur nul.

Considérez maintenant la fonction suivante :

int getIntValueFromDatabase(Database* d, std::string table, std::string key)
{
    assert(d);

    try
    {
        return d->getIntValue(table, key); // lève une exception de type int en cas d'échec
    }
    catch (int exception)
    {
        // Écrire une erreur dans un fichier journal global
        g_log.logError("getIntValueFromDatabase failed");

        // Cependant, nous n'avons pas réellement traité cette erreur
        // Que faire alors ici ?
    }
}

Lorsque cette fonction réussit, elle renvoie une valeur entière : n'importe quelle valeur entière peut être valide.

Mais que se passe-t-il si quelque chose échoue dans getIntValue() ? Dans ce cas, getIntValue() lève une exception de type int, qui est capturée par le bloc catch de getIntValueFromDatabase(), lequel journalise l'erreur. Mais comment indiquer à l'appelant de getIntValueFromDatabase() que quelque chose s'est mal passé ? Contrairement à l'exemple précédent, il n'existe pas de bon code de retour que nous puissions utiliser ici (car n'importe quelle valeur de retour entière peut être valide).

Lever une nouvelle exception

Une solution évidente consiste à lever une nouvelle exception.

int getIntValueFromDatabase(Database* d, std::string table, std::string key)
{
    assert(d);

    try
    {
        return d->getIntValue(table, key); // lève une exception de type int en cas d'échec
    }
    catch (int exception)
    {
        // Écrire une erreur dans un fichier journal global
        g_log.logError("getIntValueFromDatabase failed");

        // Lever l'exception de type char 'q' vers la pile d'appels, pour qu'elle soit traitée par l'appelant
        throw 'q';
    }
}

Dans l'exemple ci-dessus, le programme capture l'exception de type int lancée par getIntValue(), journalise l'erreur, puis lève une nouvelle exception de valeur char 'q'. Bien qu'il puisse sembler étrange de lever une exception depuis un bloc catch, c'est autorisé. Rappelez-vous que seules les exceptions levées dans un bloc try peuvent être capturées. Cela signifie qu'une exception levée dans un bloc catch ne sera pas capturée par le bloc catch dans lequel elle se trouve. Elle sera au contraire propagée vers la pile d'appels, jusqu'à l'appelant.

L'exception levée depuis le bloc catch peut être d'un type quelconque : elle n'a pas besoin d'être du même type que l'exception qui vient d'être capturée.

Relancer une exception (de la mauvaise manière)

Une autre option consiste à relancer la même exception. Une façon de procéder est la suivante :

int getIntValueFromDatabase(Database* d, std::string table, std::string key)
{
    assert(d);

    try
    {
        return d->getIntValue(table, key); // lève une exception de type int en cas d'échec
    }
    catch (int exception)
    {
        // Écrire une erreur dans un fichier journal global
        g_log.logError("getIntValueFromDatabase failed");

        throw exception;
    }
}

Bien que cela fonctionne, cette méthode présente quelques inconvénients. D'abord, elle ne lève pas exactement la même exception que celle capturée : elle lève une copie, initialisée par copie, de la variable exception. Même si le compilateur est libre de supprimer cette copie, il pourrait ne pas le faire, ce qui peut nuire aux performances.

Mais surtout, considérez ce qui se passe dans le cas suivant :

int getIntValueFromDatabase(Database* d, std::string table, std::string key)
{
    assert(d);

    try
    {
        return d->getIntValue(table, key); // lève une exception de type Derived en cas d'échec
    }
    catch (Base& exception)
    {
        // Écrire une erreur dans un fichier journal global
        g_log.logError("getIntValueFromDatabase failed");

        throw exception; // Danger : ceci lève un objet Base, et non un objet Derived
    }
}

Dans ce cas, getIntValue() lève un objet Derived, mais le bloc catch capture une référence sur Base. Ce n'est pas un problème, puisque nous savons qu'une référence Base peut désigner un objet Derived. En revanche, lorsque nous levons l'exception, l'exception levée est initialisée par copie à partir de la variable exception. La variable exception a le type Base, donc l'exception copiée a également le type Base (et non Derived !). Autrement dit, notre objet Derived a été tronqué (sliced) !

Vous pouvez le constater avec le programme suivant :

#include <iostream>
class Base
{
public:
    Base() {}
    virtual void print() { std::cout << "Base"; }
};

class Derived: public Base
{
public:
    Derived() {}
    void print() override { std::cout << "Derived"; }
};

int main()
{
    try
    {
        try
        {
            throw Derived{};
        }
        catch (Base& b)
        {
            std::cout << "Caught Base b, which is actually a ";
            b.print();
            std::cout << '\n';
            throw b; // l'objet Derived est tronqué ici
        }
    }
    catch (Base& b)
    {
        std::cout << "Caught Base b, which is actually a ";
        b.print();
        std::cout << '\n';
    }

    return 0;
}

Ce programme affiche :


Caught Base b, which is actually a Derived
Caught Base b, which is actually a Base

Le fait que la seconde ligne indique que b est en réalité un Base et non un Derived prouve que l'objet Derived a été tronqué.

Relancer une exception (de la bonne manière)

Heureusement, C++ fournit un moyen de relancer exactement la même exception que celle qui vient d'être capturée. Pour cela, utilisez simplement le mot-clé throw à l'intérieur du bloc catch, sans variable associée :

#include <iostream>
class Base
{
public:
    Base() {}
    virtual void print() { std::cout << "Base"; }
};

class Derived: public Base
{
public:
    Derived() {}
    void print() override { std::cout << "Derived"; }
};

int main()
{
    try
    {
        try
        {
            throw Derived{};
        }
        catch (Base& b)
        {
            std::cout << "Caught Base b, which is actually a ";
            b.print();
            std::cout << '\n';
            throw; // remarque : nous relançons ici l'objet
        }
    }
    catch (Base& b)
    {
        std::cout << "Caught Base b, which is actually a ";
        b.print();
        std::cout << '\n';
    }

    return 0;
}

Ce programme affiche :


Caught Base b, which is actually a Derived
Caught Base b, which is actually a Derived

Ce mot-clé throw, qui ne semble lever rien de particulier, relance en réalité exactement la même exception que celle qui vient d'être capturée. Aucune copie n'est faite, de sorte que nous n'avons pas à craindre des copies coûteuses pour les performances, ni la troncature.

Si vous devez relancer une exception, cette méthode doit être privilégiée par rapport aux alternatives.

Règle

Pour relancer la même exception, utilisez le mot-clé throw seul
