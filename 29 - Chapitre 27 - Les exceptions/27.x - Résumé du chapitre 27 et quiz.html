27.x — Résumé du chapitre 27 et quiz

Revue du chapitre

La gestion des exceptions fournit un mécanisme qui découple le traitement des erreurs ou d'autres circonstances exceptionnelles du flux de contrôle habituel de votre code. Vous disposez ainsi d'une plus grande liberté pour traiter les erreurs quand et comme cela est le plus utile pour une situation donnée, ce qui supprime une bonne partie (sinon la totalité) des complications qu'entraînent les codes de retour.

Une instruction throw sert à lever une exception. Les blocs try recherchent les exceptions lancées par le code écrit ou appelé à l'intérieur de ces blocs. Ces exceptions sont acheminées vers les blocs catch, qui interceptent les exceptions de types particuliers (s'ils correspondent) et les traitent. Par défaut, une exception interceptée est considérée comme traitée.

Les exceptions sont traitées immédiatement. Si une exception est levée, le contrôle saute au bloc try englobant le plus proche, à la recherche d'un gestionnaire catch capable de la traiter. Si un bloc try correspondant est trouvé, la pile est déroulée jusqu'au bloc catch, et l'exécution reprend au début du catch correspondant. Si aucun bloc try n'est trouvé, ou si aucun bloc catch ne correspond, le programme appelle std::terminate, ce qui met fin au programme avec une erreur d'exception non traitée.

Des exceptions de n'importe quel type de données peuvent être lancées, y compris des classes.

Les blocs catch peuvent être configurés pour intercepter les exceptions d'un type de données particulier, ou un gestionnaire universel peut être mis en place à l'aide de points de suspension (…). Un bloc catch qui intercepte une référence à une classe de base interceptera également les exceptions d'une classe dérivée. Toutes les exceptions lancées par la bibliothèque standard dérivent de la classe std::exception (définie dans l'en-tête exception), si bien que l'interception d'un std::exception par référence permet d'intercepter toutes les exceptions de la bibliothèque standard. La fonction membre what() permet de déterminer le type de std::exception qui a été lancé.

À l'intérieur d'un bloc catch, une nouvelle exception peut être lancée. Comme cette nouvelle exception est lancée en dehors du bloc try associé à ce bloc catch, elle ne sera pas interceptée par le bloc catch dans lequel elle a été lancée. Une exception peut être relancée depuis un bloc catch à l'aide du mot-clé throw seul. Ne relancez pas une exception à l'aide de la variable d'exception interceptée, sous peine de provoquer un découpage d'objet (object slicing).

Les blocs try de fonction vous permettent d'intercepter toute exception survenant dans une fonction ou dans la liste d'initialisation des membres qui lui est associée. Ils ne sont généralement utilisés qu'avec les constructeurs de classes dérivées.

Vous ne devez jamais lancer une exception depuis un destructeur.

Le spécificateur d'exception noexcept peut être utilisé pour indiquer qu'une fonction ne lance pas d'exception et ne peut pas échouer.

std::move_if_noexcept renvoie une valeur r déplaçable si l'objet possède un constructeur de déplacement noexcept, sinon il renvoie une valeur l copiable. Nous pouvons utiliser le spécificateur noexcept conjointement avec std::move_if_noexcept pour n'utiliser la sémantique de déplacement que lorsqu'une garantie forte d'exception existe (et utiliser la sémantique de copie dans le cas contraire).

Enfin, la gestion des exceptions a un coût. Dans la plupart des cas, le code qui utilise des exceptions s'exécute un peu plus lentement, et le coût du traitement d'une exception est très élevé. Vous ne devez utiliser les exceptions que pour les circonstances exceptionnelles, et non pour les cas courants de gestion d'erreurs (par exemple une saisie invalide).

Quiz du chapitre

  1. Écrivez une classe Fraction dotée d'un constructeur qui prend un numérateur et un dénominateur. Si l'utilisateur passe un dénominateur égal à 0, lancez une exception de type std::runtime_error (incluse dans l'en-tête stdexcept). Dans votre programme principal, demandez à l'utilisateur de saisir deux entiers. Si la Fraction est valide, affichez la fraction. Si la Fraction est invalide, interceptez un std::exception et indiquez à l'utilisateur qu'il a saisi une fraction invalide.

Voici ce que devrait afficher une exécution du programme :


Enter the numerator: 5
Enter the denominator: 0
Invalid denominator
Solution 
#include <iostream>
#include <stdexcept> // pour std::runtime_error
#include <exception> // pour std::exception

class Fraction
{
private:
    int m_numerator = 0;
    int m_denominator = 1;

public:
    Fraction(int numerator = 0, int denominator = 1)
        : m_numerator{ numerator }
        , m_denominator{ denominator }
    {
        if (m_denominator == 0)
            throw std::runtime_error("Invalid denominator");
    }

    friend std::ostream& operator<<(std::ostream& out, const Fraction& f1);

};

std::ostream& operator<<(std::ostream& out, const Fraction& f1)
{
    out << f1.m_numerator << '/' << f1.m_denominator;
    return out;
}

int main()
{
    std::cout << "Enter the numerator: ";
    int numerator{};
    std::cin >> numerator;

    std::cout << "Enter the denominator: ";
    int denominator{};
    std::cin >> denominator;

    try
    {
        Fraction f{ numerator, denominator };
        std::cout << "Your fraction is: " << f << '\n';
    }
    catch (const std::exception& e)
    {
        std::cerr << e.what() << '\n';
    }

    return 0;
}
