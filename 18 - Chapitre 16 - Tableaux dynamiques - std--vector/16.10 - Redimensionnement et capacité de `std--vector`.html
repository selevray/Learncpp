16.10 — Redimensionnement et capacité de std::vector

Dans les leçons précédentes de ce chapitre, nous avons présenté les conteneurs, les tableaux et std::vector. Nous avons aussi abordé la manière d'accéder aux éléments d'un tableau, d'obtenir sa longueur et de le parcourir. Bien que nous ayons utilisé std::vector dans nos exemples, les notions étudiées s'appliquent en général à tous les types de tableaux.

Dans les leçons restantes de ce chapitre, nous allons nous concentrer sur ce qui distingue vraiment std::vector de la plupart des autres types de tableaux : la capacité à se redimensionner après sa création.

Tableaux de taille fixe et tableaux dynamiques

La plupart des types de tableaux ont une limitation importante : la longueur du tableau doit être connue au moment de sa création, et elle ne peut ensuite plus être modifiée. Ces tableaux sont appelés tableaux de taille fixe (fixed-size arrays) ou tableaux de longueur fixe (fixed-length arrays). std::array et les tableaux de style C sont tous deux des types de tableaux de taille fixe. Nous les étudierons plus en détail dans le prochain chapitre.

En revanche, std::vector est un tableau dynamique. Un tableau dynamique (aussi appelé tableau redimensionnable, resizable array) est un tableau dont la taille peut être modifiée après sa création. C'est cette capacité à être redimensionné qui rend std::vector si particulier.

Redimensionner un std::vector à l'exécution

Un std::vector peut être redimensionné après sa création en appelant la fonction membre resize() avec la nouvelle longueur souhaitée :

#include <iostream>
#include <vector>

int main()
{
    std::vector v{ 0, 1, 2 }; // crée un vecteur de 3 éléments
    std::cout << "The length is: " << v.size() << '\n';

    v.resize(5);              // redimensionne à 5 éléments
    std::cout << "The length is: " << v.size() << '\n';

    for (auto i : v)
        std::cout << i << ' ';

    std::cout << '\n';

    return 0;
}

Ce programme affiche :


The length is: 3
The length is: 5
0 1 2 0 0

Il y a deux points à noter ici. Premièrement, lorsque nous avons redimensionné le vecteur, les valeurs des éléments existants ont été conservées ! Deuxièmement, les nouveaux éléments sont initialisés par valeur (ce qui réalise une initialisation par défaut pour les types classe, et une initialisation à zéro pour les autres types). Ainsi, les deux nouveaux éléments de type int ont été initialisés à zéro, avec la valeur 0.

Un vecteur peut aussi être redimensionné à une taille plus petite :

#include <iostream>
#include <vector>

void printLength(const std::vector<int>& v)
{
    std::cout << "The length is: "  << v.size() << '\n';
}

int main()
{
    std::vector v{ 0, 1, 2, 3, 4 }; // la longueur est initialement de 5
    printLength(v);

    v.resize(3);                    // redimensionne à 3 éléments
    printLength(v);

    for (int i : v)
        std::cout << i << ' ';

    std::cout << '\n';

    return 0;
}

Ce programme affiche :


The length is: 5
The length is: 3
0 1 2

La longueur et la capacité d'un std::vector

Considérons une rangée de 12 maisons. Nous dirions que le nombre de maisons (ou la longueur de la rangée) est de 12. Si nous voulions savoir lesquelles de ces maisons sont actuellement occupées, il faudrait le déterminer autrement (par exemple en sonnant à la porte pour voir si quelqu'un répond). Quand nous ne disposons que d'une longueur, nous savons seulement combien d'éléments existent.

Considérons maintenant une boîte d'œufs qui contient actuellement 5 œufs. Nous dirions que le nombre d'œufs est de 5. Mais dans ce contexte, il existe une autre dimension qui nous intéresse : le nombre d'œufs que la boîte pourrait contenir si elle était pleine. Nous dirions que la capacité de la boîte est de 12. La boîte a de la place pour 12 œufs, et seuls 5 sont utilisés. Nous pourrions donc ajouter 7 œufs de plus sans déborder. Lorsque nous disposons à la fois d'une longueur et d'une capacité, nous pouvons distinguer le nombre d'éléments qui existent réellement du nombre d'éléments pour lesquels il y a de la place.

Jusqu'ici, nous n'avons parlé que de la longueur d'un std::vector. Mais std::vector possède aussi une capacité. Dans le contexte d'un std::vector, la capacité (capacity) correspond au nombre d'éléments pour lesquels le std::vector a alloué de l'espace de stockage, et la longueur (length) correspond au nombre d'éléments actuellement utilisés.

Un std::vector d'une capacité de 5 a alloué de la place pour 5 éléments. Si le vecteur contient 2 éléments réellement utilisés, sa longueur (size) est de 2. Les 3 éléments restants ont de la mémoire allouée, mais ils ne sont pas considérés comme étant en cours d'utilisation. Ils pourront être utilisés plus tard sans dépasser la capacité du vecteur.

Point clé

La longueur d'un vecteur correspond au nombre d'éléments « en cours d'utilisation ».
La capacité d'un vecteur correspond au nombre d'éléments qui ont été alloués en mémoire.

Obtenir la capacité d'un std::vector

Nous pouvons demander à un std::vector sa capacité grâce à la fonction membre capacity().

Par exemple :

#include <iostream>
#include <vector>

void printCapLen(const std::vector<int>& v)
{
    std::cout << "Capacity: " << v.capacity() << " Length:" << v.size() << '\n';
}

int main()
{
    std::vector v{ 0, 1, 2 }; // la longueur est initialement de 3

    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    v.resize(5); // redimensionne à 5 éléments

    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    return 0;
}

Sur la machine de l'auteur, ce programme affiche le résultat suivant :


Capacity: 3  Length: 3
0 1 2
Capacity: 5  Length: 5
0 1 2 0 0

Tout d'abord, nous avons initialisé le vecteur avec 3 éléments. Cela amène le vecteur à allouer de l'espace de stockage pour 3 éléments (capacité de 3), et les 3 éléments sont considérés comme étant en cours d'utilisation (longueur de 3).

Nous appelons ensuite resize(5), ce qui signifie que nous voulons maintenant un vecteur de longueur 5. Comme le vecteur n'a de l'espace que pour 3 éléments, alors qu'il en faut 5, il doit obtenir davantage de stockage pour contenir les éléments supplémentaires.

Une fois l'appel à resize() terminé, nous constatons que le vecteur dispose désormais de la place pour 5 éléments (capacité de 5), et que les 5 éléments sont maintenant considérés comme utilisés (longueur de 5).

La plupart du temps, vous n'aurez pas besoin d'utiliser la fonction capacity(), mais nous nous en servirons beaucoup dans les exemples suivants afin de voir ce qui se passe avec le stockage du vecteur.

Réallocation du stockage, et pourquoi elle est coûteuse

Lorsqu'un std::vector modifie la quantité de stockage qu'il gère, ce processus est appelé réallocation (reallocation). Informellement, le processus de réallocation se déroule à peu près ainsi :

  • Le std::vector acquiert une nouvelle zone mémoire ayant la capacité nécessaire pour le nombre d'éléments souhaité. Ces éléments sont initialisés par valeur.
  • Les éléments de l'ancienne zone mémoire sont copiés (ou déplacés, si c'est possible) dans la nouvelle. L'ancienne zone mémoire est ensuite rendue au système.
  • La capacité et la longueur du std::vector sont fixées à leurs nouvelles valeurs.

De l'extérieur, on a l'impression que le std::vector a été redimensionné. Mais en interne, la mémoire (et tous les éléments) ont en réalité été remplacés !

Contenu associé

Le processus d'acquisition de nouvelle mémoire à l'exécution s'appelle l'allocation dynamique de mémoire. Nous le traitons dans la leçon 19.1 -- Allocation dynamique de mémoire avec new et delete.

Comme la réallocation exige généralement de copier chaque élément du tableau, elle est coûteuse. Il faut donc éviter autant que raisonnablement possible de réallouer la mémoire.

Point clé

La réallocation est généralement coûteuse. Évitez les réallocations inutiles.

Pourquoi distinguer longueur et capacité ?

Un std::vector réalloue son stockage si nécessaire, mais, à l'image de Bartleby de Melville, il préfère éviter de le faire, car la réallocation est coûteuse en calcul.

Si un std::vector ne gardait la trace que de sa longueur, chaque demande de resize() entraînerait une réallocation coûteuse vers la nouvelle longueur. Séparer longueur et capacité permet au std::vector d'être plus intelligent quant au moment où une réallocation est réellement nécessaire.

L'exemple suivant l'illustre :

#include <iostream>
#include <vector>

void printCapLen(const std::vector<int>& v)
{
    std::cout << "Capacity: " << v.capacity() << " Length:" << v.size() << '\n';
}

int main()
{
    // Crée un vecteur de longueur 5
    std::vector v{ 0, 1, 2, 3, 4 };
    v = { 0, 1, 2, 3, 4 }; // correct, la longueur du tableau est de 5
    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    // Redimensionne le vecteur à 3 éléments
    v.resize(3); // on pourrait aussi affecter une liste de 3 éléments ici
    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    // Redimensionne le vecteur à nouveau à 5 éléments
    v.resize(5);
    printCapLen(v);

    for (auto i : v)
        std::cout << i << ' ';
    std::cout << '\n';

    return 0;
}

Ce programme produit le résultat suivant :


Capacity: 5  Length: 5
0 1 2 3 4
Capacity: 5  Length: 3
0 1 2
Capacity: 5  Length: 5
0 1 2 0 0

Lorsque nous avons initialisé notre vecteur avec 5 éléments, la capacité a été fixée à 5, ce qui indique que notre vecteur a initialement alloué de la place pour 5 éléments. La longueur a elle aussi été fixée à 5, ce qui indique que tous ces éléments sont en cours d'utilisation.

Après l'appel v.resize(3), la longueur a été ramenée à 3 pour satisfaire notre demande de tableau plus petit. Notons toutefois que la capacité vaut toujours 5, ce qui signifie que le vecteur n'a pas effectué de réallocation !

Enfin, nous avons appelé v.resize(5). Comme le vecteur disposait déjà d'une capacité de 5, il n'a pas eu besoin de réallouer. Il a simplement rétabli la longueur à 5 et initialisé par valeur les deux derniers éléments.

En séparant longueur et capacité, nous avons évité, dans cet exemple, 2 réallocations qui se seraient produites autrement. Dans la prochaine leçon, nous verrons des exemples où l'on ajoute des éléments à un vecteur un par un. Dans de tels cas, la capacité à ne pas réallouer à chaque changement de longueur est encore plus importante.

Point clé

Suivre la capacité séparément de la longueur permet au std::vector d'éviter certaines réallocations lorsque la longueur change.

L'indexation d'un vecteur est basée sur la longueur, pas sur la capacité

Vous pourriez être surpris de constater que les indices valides pour l'opérateur d'indexation (operator[]) et la fonction membre at() sont basés sur la longueur du vecteur, et non sur sa capacité.

Dans l'exemple ci-dessus, lorsque v a une capacité de 5 et une longueur de 3, seuls les indices allant de 0 à 2 sont valides. Bien que les éléments dont les indices vont de la longueur 3 (incluse) à la capacité 5 (exclue) existent, leurs indices sont considérés comme hors limites.

Attention

Un indice n'est valide que s'il est compris entre 0 et la longueur du vecteur (et non sa capacité) !

Réduire un std::vector

Redimensionner un vecteur à une taille plus grande augmente sa longueur, et augmente aussi sa capacité si nécessaire. En revanche, redimensionner un vecteur à une taille plus petite ne fait que diminuer sa longueur, et non sa capacité.

Réallouer un vecteur uniquement pour récupérer la mémoire occupée par un petit nombre d'éléments devenus inutiles est un mauvais choix. En revanche, si un vecteur contient un grand nombre d'éléments dont nous n'avons plus besoin, le gaspillage de mémoire peut devenir important.

Pour répondre à cette situation, std::vector possède une fonction membre appelée shrink_to_fit(), qui demande au vecteur de réduire sa capacité pour qu'elle corresponde à sa longueur. Cette demande n'est pas contraignante : l'implémentation est libre de l'ignorer. Selon ce que l'implémentation juge le plus approprié, elle peut accéder à la demande, la satisfaire partiellement (par exemple en réduisant la capacité sans aller jusqu'au bout) ou l'ignorer complètement.

Voici un exemple :

#include <iostream>
#include <vector>

void printCapLen(const std::vector<int>& v)
{
    std::cout << "Capacity: " << v.capacity() << " Length:" << v.size() << '\n';
}

int main()
{

    std::vector<int> v(1000); // alloue de la place pour 1000 éléments
    printCapLen(v);

    v.resize(0); // redimensionne à 0 élément
    printCapLen(v);

    v.shrink_to_fit();
    printCapLen(v);

    return 0;
}

Sur la machine de l'auteur, ce programme produit le résultat suivant :


Capacity: 1000  Length: 1000
Capacity: 1000  Length: 0
Capacity: 0  Length: 0

Comme vous pouvez le voir, lorsque v.shrink_to_fit() a été appelée, le vecteur a réalloué sa capacité à 0, libérant ainsi la mémoire prévue pour 1000 éléments.

Quiz

Question n° 1

Que représentent la longueur et la capacité d'un std::vector ?

Solution

La longueur est le nombre d'éléments actuellement utilisés.
La capacité est le nombre d'éléments pour lesquels un espace de stockage a été alloué.

Pourquoi la longueur et la capacité sont-elles deux valeurs distinctes ?

Solution

La capacité est suivie séparément afin que le vecteur puisse éviter certaines réallocations lorsque la longueur change.

Les indices valides de std::vector sont-ils basés sur la longueur ou sur la capacité ?

Solution

Sur la longueur.
