16.7 — Tableaux, boucles et solutions du défi sur le signe

Dans la leçon 4.5 -- Les entiers non signés, et pourquoi il faut les éviter, nous avons indiqué que nous préférons généralement utiliser des valeurs signées pour représenter des quantités, car les valeurs non signées peuvent se comporter de façon surprenante. Cependant, dans la leçon 16.3 -- std::vector et le problème de la longueur et des indices non signés, nous avons expliqué que std::vector (et les autres classes conteneurs) utilise le type entier non signé std::size_t pour la longueur et les indices.

Cela peut conduire à des problèmes comme celui-ci :

#include <iostream>
#include <vector>

template <typename T>
void printReverse(const std::vector<T>& arr)
{
    for (std::size_t index{ arr.size() - 1 }; index >= 0; --index) // index est non signé
    {
        std::cout << arr[index] << ' ';
    }

    std::cout << '\n';
}

int main()
{
    std::vector arr{ 4, 6, 7, 3, 8, 2, 1, 9 };

    printReverse(arr);

    return 0;
}

Ce code commence par afficher le tableau à l'envers :


9 1 2 8 3 7 6 4

Puis il provoque un comportement indéfini. Il peut afficher des valeurs aberrantes ou faire planter l'application.

Il y a deux problèmes ici. Premièrement, notre boucle s'exécute tant que index >= 0 (autrement dit, tant que index est positif), ce qui est toujours vrai lorsque index est non signé. La boucle ne se termine donc jamais.

Deuxièmement, lorsque nous décrémentons index alors qu'il vaut 0, il revient à une grande valeur positive, que nous utilisons ensuite pour indexer le tableau à l'itération suivante. Cet indice est hors limites et provoque un comportement indéfini. Nous rencontrons le même problème si notre vecteur est vide.

Bien qu'il existe de nombreuses façons de contourner ces problèmes précis, ce genre de situation est un véritable aimant à bogues.

Utiliser un type signé pour la variable de boucle évite plus facilement ces problèmes, mais pose ses propres difficultés. Voici une version du problème ci-dessus qui utilise un indice signé :

#include <iostream>
#include <vector>

template <typename T>
void printReverse(const std::vector<T>& arr)
{
    for (int index{ static_cast<int>(arr.size()) - 1}; index >= 0; --index) // index est signé
    {
        std::cout << arr[static_cast<std::size_t>(index)] << ' ';
    }

    std::cout << '\n';
}

int main()
{
    std::vector arr{ 4, 6, 7, 3, 8, 2, 1, 9 };

    printReverse(arr);

    return 0;
}

Cette version fonctionne comme prévu, mais le code est encombré par deux conversions statiques (static_cast). arr[static_cast<std::size_t>(index)] est particulièrement difficile à lire. Dans ce cas, nous avons amélioré la sécurité au prix d'une lisibilité nettement réduite.

Voici un autre exemple utilisant un indice signé :

#include <iostream>
#include <vector>

// Modèle de fonction calculant la valeur moyenne d'un std::vector
template <typename T>
T calculateAverage(const std::vector<T>& arr)
{
    int length{ static_cast<int>(arr.size()) };

    T average{ 0 };
    for (int index{ 0 }; index < length; ++index)
        average += arr[static_cast<std::size_t>(index)];
    average /= length;

    return average;
}

int main()
{
    std::vector testScore1 { 84, 92, 76, 81, 56 };
    std::cout << "The class 1 average is: " << calculateAverage(testScore1) << '\n';

    return 0;
}

L'encombrement du code par les conversions statiques est franchement pénible.

Que faire alors ? Il n'existe pas de solution idéale dans ce domaine.

Plusieurs options sont envisageables ; nous les présentons de ce que nous jugeons la moins bonne à la meilleure. Vous rencontrerez probablement toutes ces options dans du code écrit par d'autres.

Note de l'auteur

Bien que nous en parlions dans le contexte de std::vector, tous les conteneurs de la bibliothèque standard (par exemple std::array) fonctionnent de façon similaire et posent les mêmes difficultés. La discussion qui suit s'applique à chacun d'eux.

Désactiver les avertissements de conversion signé/non signé

Si vous vous demandiez pourquoi les avertissements de conversion signé/non signé sont souvent désactivés par défaut, ce sujet en est l'une des raisons principales. Chaque fois que nous indexons un conteneur de la bibliothèque standard avec un indice signé, un avertissement de conversion de signe est généré. Cela remplit rapidement le journal de compilation de faux avertissements, noyant ceux qui sont réellement légitimes.

Une façon d'éviter de devoir gérer de nombreux avertissements de conversion signé/non signé consiste donc simplement à les laisser désactivés.

C'est la solution la plus simple, mais nous ne la recommandons pas, car elle supprime aussi les avertissements légitimes de conversion de signe, susceptibles de causer des bogues s'ils ne sont pas traités.

Utiliser une variable de boucle non signée

Beaucoup de développeurs pensent que, puisque les types de tableaux de la bibliothèque standard ont été conçus pour utiliser des indices non signés, nous devrions nous aussi utiliser des indices non signés ! C'est une position tout à fait raisonnable. Il faut simplement être particulièrement attentif à ne pas rencontrer de discordances signé/non signé lorsqu'on procède ainsi. Si possible, n'utilisez la variable d'indice de boucle que pour indexer.

Si nous décidons d'adopter cette approche, quel type non signé devrions-nous réellement utiliser ?

Dans la leçon 16.3 -- std::vector et le problème de la longueur et des indices non signés, nous avons indiqué que les classes conteneurs de la bibliothèque standard définissent un typedef imbriqué size_type, qui est un type entier non signé utilisé pour les longueurs et les indices de tableaux. La fonction membre size() renvoie un size_type, et operator[] utilise un size_type comme indice. Utiliser size_type comme type de votre indice est donc techniquement le type non signé le plus cohérent et le plus sûr (il fonctionnera dans tous les cas, même dans le cas extrêmement rare où size_type serait autre chose que size_t). Par exemple :

#include <iostream>
#include <vector>

int main()
{
    std::vector arr { 1, 2, 3, 4, 5 };

    for (std::vector<int>::size_type index { 0 }; index < arr.size(); ++index)
        std::cout << arr[index] << ' ';

    return 0;
}

Cependant, size_type a un inconvénient majeur : comme c'est un type imbriqué, pour l'utiliser nous devons préfixer explicitement le nom par le nom complet, avec ses arguments de modèle, du conteneur (ce qui signifie qu'il faut écrire std::vector<int>::size_type plutôt que simplement std::size_type). Cela demande beaucoup de frappe, est difficile à lire et varie selon le conteneur et le type des éléments.

Lorsqu'on l'utilise à l'intérieur d'un modèle de fonction, on peut employer T pour les arguments de modèle. Mais il faut aussi préfixer le type par le mot-clé typename :

#include <iostream>
#include <vector>

template <typename T>
void printArray(const std::vector<T>& arr)
{
    // le préfixe typename est requis pour un type dépendant
    for (typename std::vector<T>::size_type index { 0 }; index < arr.size(); ++index)
        std::cout << arr[index] << ' ';
}

int main()
{
    std::vector arr { 9, 7, 5, 3, 1 };

    printArray(arr);

    return 0;
}

Si vous oubliez le mot-clé typename, votre compilateur vous rappellera probablement de l'ajouter.

Pour les lecteurs avancés

Tout nom qui dépend d'un type contenant un paramètre de modèle est appelé un nom dépendant (dependent name). Les noms dépendants doivent être préfixés par le mot-clé typename pour être utilisés comme types.

Dans l'exemple ci-dessus, std::vector<T> est un type avec un paramètre de modèle ; le type imbriqué std::vector<T>::size_type est donc un nom dépendant, et doit être préfixé par typename pour être utilisé comme type.

Vous pourrez parfois voir le type du tableau aliasé pour rendre la boucle plus lisible :

    using arrayi = std::vector<int>;
    for (arrayi::size_type index { 0 }; index < arr.size(); ++index)

Une solution plus générale consiste à laisser le compilateur déterminer le type de l'objet tableau à notre place, afin de ne pas avoir à préciser explicitement le type du conteneur ni ses arguments de modèle. Pour cela, on peut utiliser le mot-clé decltype, qui renvoie le type de son paramètre.

    // arr est un type non référence
    for (decltype(arr)::size_type index { 0 }; index < arr.size(); ++index) // decltype(arr) se résout en std::vector<int>

Cependant, si arr est un type référence (par exemple un tableau passé par référence), ce qui précède ne fonctionne pas. Il faut d'abord retirer la référence de arr :

template <typename T>
void printArray(const std::vector<T>& arr)
{
    // arr peut être un type référence ou non référence
    for (typename std::remove_reference_t<decltype(arr)>::size_type index { 0 }; index < arr.size(); ++index)
        std::cout << arr[index] << ' ';
}

Malheureusement, ce n'est plus très concis ni facile à retenir.

Comme size_type est presque toujours un typedef de size_t, beaucoup de programmeurs se passent de size_type et utilisent directement std::size_t, plus facile à retenir et à taper :

    for (std::size_t index { 0 }; index < arr.size(); ++index)

Sauf si vous utilisez des allocateurs personnalisés (ce qui est probablement votre cas), nous estimons que cette approche est raisonnable.

Utiliser une variable de boucle signée

Bien qu'elle rende le travail avec les types conteneurs de la bibliothèque standard un peu plus difficile, l'utilisation d'une variable de boucle signée est cohérente avec les bonnes pratiques appliquées dans le reste de notre code (privilégier les valeurs signées pour les quantités). Et plus nous pouvons appliquer nos bonnes pratiques de façon cohérente, moins nous aurons d'erreurs au total.

Si nous décidons d'utiliser des variables de boucle signées, trois points doivent être traités :

  • Quel type signé utiliser ?
  • Obtenir la longueur du tableau sous forme de valeur signée
  • Convertir la variable de boucle signée en indice non signé

Quel type signé utiliser ?

Il existe trois options (parfois quatre) valables.

  1. Sauf si vous travaillez avec un très grand tableau, int devrait convenir (en particulier sur les architectures où int occupe 4 octets). int est le type entier signé par défaut que nous utilisons pour tout lorsque le type précis importe peu, et il y a peu de raisons de faire autrement ici.
  2. Si vous manipulez de très grands tableaux, ou si vous voulez être un peu plus défensif, vous pouvez utiliser le type au nom étrangement formé std::ptrdiff_t. Ce typedef sert souvent de contrepartie signée à std::size_t.
  3. Comme std::ptrdiff_t a un nom peu intuitif, une autre bonne approche consiste à définir votre propre alias de type pour les indices :
using Index = std::ptrdiff_t;

// Exemple de boucle utilisant Index
for (Index index{ 0 }; index < static_cast<Index>(arr.size()); ++index)

Nous montrerons un exemple complet de cela dans la section suivante.

Définir votre propre alias de type présente aussi un avantage potentiel pour l'avenir : si la bibliothèque standard C++ publie un jour un type conçu pour être utilisé comme indice signé, il suffira de modifier Index pour qu'il désigne ce type, ou de remplacer Index par le nom de ce type.

  1. Lorsque le type de la variable de boucle peut être déduit de son initialiseur, vous pouvez utiliser auto pour laisser le compilateur le déduire :
    for (auto index{ static_cast<std::ptrdiff_t>(arr.size())-1 }; index >= 0; --index)

En C++23, le suffixe Z peut être utilisé pour définir un littéral du type qui est la contrepartie signée de std::size_t (probablement std::ptrdiff_t) :

    for (auto index{ 0Z }; index < static_cast<std::ptrdiff_t>(arr.size()); ++index)

Obtenir la longueur d'un tableau sous forme de valeur signée

  1. Avant C++20, la meilleure option consiste à faire un static_cast de la valeur renvoyée par la fonction membre size() ou par std::size() vers un type signé :
#include <iostream>
#include <vector>

using Index = std::ptrdiff_t;

int main()
{
    std::vector arr{ 9, 7, 5, 3, 1 };

    for (auto index{ static_cast<Index>(arr.size())-1 }; index >= 0; --index)
        std::cout << arr[static_cast<std::size_t>(index)] << ' ';

    return 0;
}

Ainsi, la valeur non signée renvoyée par arr.size() est convertie en type signé, et notre opérateur de comparaison a deux opérandes signés. Et comme les indices signés ne débordent pas lorsqu'ils deviennent négatifs, nous n'avons pas le problème de retour à l'extrême rencontré avec les indices non signés.

L'inconvénient de cette approche est qu'elle encombre la boucle et la rend moins lisible. Nous pouvons remédier à cela en sortant la longueur de la boucle :

#include <iostream>
#include <vector>

using Index = std::ptrdiff_t;

int main()
{
    std::vector arr{ 9, 7, 5, 3, 1 };

    auto length{ static_cast<Index>(arr.size()) };
    for (auto index{ length-1 }; index >= 0; --index)
        std::cout << arr[static_cast<std::size_t>(index)] << ' ';

    return 0;
}
  1. En C++20, utilisez std::ssize() :

Si vous voulez davantage de preuves que les concepteurs du C++ considèrent désormais que les indices signés sont la bonne voie, pensez à l'introduction de std::ssize() en C++20. Cette fonction renvoie la taille d'un tableau sous forme de type signé (probablement ptrdiff_t).

#include <iostream>
#include <vector>

int main()
{
    std::vector arr{ 9, 7, 5, 3, 1 };

    for (auto index{ std::ssize(arr)-1 }; index >= 0; --index) // std::ssize introduit en C++20
        std::cout << arr[static_cast<std::size_t>(index)] << ' ';

    return 0;
}

Convertir la variable de boucle signée en indice non signé

Une fois que nous disposons d'une variable de boucle signée, nous allons rencontrer des avertissements de conversion de signe implicite chaque fois que nous essaierons de l'utiliser comme indice. Nous avons donc besoin d'un moyen de convertir la variable de boucle signée en valeur non signée partout où nous voulons l'utiliser comme indice.

  1. L'option évidente consiste à faire un static_cast de la variable de boucle signée vers un indice non signé. Nous l'avons montré dans l'exemple précédent. Malheureusement, il faut le faire à chaque fois que nous indexons le tableau, et cela rend les indices de tableau difficiles à lire.
  2. Utiliser une fonction de conversion au nom court :
#include <iostream>
#include <type_traits> // pour std::is_integral et std::is_enum
#include <vector>

using Index = std::ptrdiff_t;

// Fonction utilitaire convertissant `value` en objet de type std::size_t
// UZ est le suffixe des littéraux de type std::size_t.
template <typename T>
constexpr std::size_t toUZ(T value)
{
    // s'assurer que T est un type entier
    static_assert(std::is_integral<T>() || std::is_enum<T>());

    return static_cast<std::size_t>(value);
}

int main()
{
    std::vector arr{ 9, 7, 5, 3, 1 };

    auto length { static_cast<Index>(arr.size()) };  // en C++20, préférez std::ssize()
    for (auto index{ length-1 }; index >= 0; --index)
        std::cout << arr[toUZ(index)] << ' '; // utilise toUZ() pour éviter l'avertissement de conversion de signe

    return 0;
}

Dans l'exemple ci-dessus, nous avons créé une fonction nommée toUZ() destinée à convertir des valeurs entières en valeurs de type std::size_t. Cela nous permet d'indexer notre tableau par arr[toUZ(index)], ce qui est assez lisible.

  1. Utiliser une vue personnalisée

Dans les leçons précédentes, nous avons vu que std::string possède une chaîne, alors que std::string_view est une vue sur une chaîne existant ailleurs. L'un des avantages de std::string_view est qu'elle peut visualiser différents types de chaînes (littéraux de chaîne de style C, std::string et d'autres std::string_view) tout en offrant une interface cohérente.

Bien que nous ne puissions pas modifier les conteneurs de la bibliothèque standard pour qu'ils acceptent un indice entier signé, nous pouvons créer notre propre classe de vue personnalisée pour « visualiser » une classe conteneur de la bibliothèque standard. Ce faisant, nous pouvons définir notre propre interface et la faire fonctionner comme bon nous semble.

Dans l'exemple suivant, nous définissons une classe de vue personnalisée capable de visualiser tout conteneur de la bibliothèque standard prenant en charge l'indexation. Notre interface fera deux choses :

  • Permettre d'accéder aux éléments avec operator[] à l'aide d'un type entier signé.
  • Obtenir la longueur du conteneur sous forme de type entier signé (puisque std::ssize() n'est disponible qu'en C++20).

Cela utilise la surcharge d'opérateurs (que nous avons brièvement introduite dans la leçon 13.5 -- Introduction à la surcharge des opérateurs d'entrée/sortie) pour implémenter operator[]. Vous n'avez pas besoin de savoir comment SignedArrayView est implémentée pour l'utiliser.

SignedArrayView.h :

#ifndef SIGNED_ARRAY_VIEW_H
#define SIGNED_ARRAY_VIEW_H

#include <cstddef> // pour std::size_t et std::ptrdiff_t

// SignedArrayView fournit une vue sur un conteneur prenant en charge l'indexation,
// ce qui nous permet de manipuler ces types à l'aide d'indices signés
template <typename T>
class SignedArrayView // nécessite C++17
{
private:
    T& m_array;

public:
    using Index = std::ptrdiff_t;

    SignedArrayView(T& array)
        : m_array{ array } {}

    // Surcharge de operator[] pour accepter un indice signé
    constexpr auto& operator[](Index index) { return m_array[static_cast<typename T::size_type>(index)]; }
    constexpr const auto& operator[](Index index) const { return m_array[static_cast<typename T::size_type>(index)]; }
    constexpr auto ssize() const { return static_cast<Index>(m_array.size()); }
};

#endif

main.cpp :

#include <iostream>
#include <vector>
#include "SignedArrayView.h"

int main()
{
    std::vector arr{ 9, 7, 5, 3, 1 };
    SignedArrayView sarr{ arr }; // Crée une vue signée de notre std::vector

    for (auto index{ sarr.ssize() - 1 }; index >= 0; --index)
        std::cout << sarr[index] << ' '; // indexe à l'aide d'un type signé

    return 0;
}

Indexer plutôt le tableau de style C sous-jacent

Dans la leçon 16.3 -- std::vector et le problème de la longueur et des indices non signés, nous avons indiqué qu'au lieu d'indexer le conteneur de la bibliothèque standard, nous pouvons appeler la fonction membre data() et indexer le résultat. Comme data() renvoie les données du tableau sous forme de tableau de style C, et que les tableaux de style C acceptent l'indexation avec des valeurs signées comme non signées, cela évite les problèmes de conversion de signe.

int main()
{
    std::vector arr{ 9, 7, 5, 3, 1 };

    auto length { static_cast<Index>(arr.size()) };  // en C++20, préférez std::ssize()
    for (auto index{ length - 1 }; index >= 0; --index)
        std::cout << arr.data()[index] << ' ';       // utilise data() pour éviter l'avertissement de conversion de signe

    return 0;
}

Nous pensons que cette méthode est la meilleure des options d'indexation :

  • Nous pouvons utiliser des variables de boucle et des indices signés.
  • Nous n'avons pas besoin de définir de types personnalisés ni d'alias de type.
  • La perte de lisibilité due à l'utilisation de data() est très faible.
  • Il ne devrait pas y avoir de perte de performance dans le code optimisé.

Le seul choix raisonnable : éviter complètement l'indexation !

Toutes les options présentées ci-dessus ont leurs inconvénients, il est donc difficile de recommander l'une plutôt qu'une autre. Il existe cependant un choix bien plus sensé que les autres : éviter complètement l'indexation par des valeurs entières.

C++ propose plusieurs autres méthodes de parcours de tableaux qui n'utilisent pas du tout d'indices. Et sans indices, nous ne rencontrons plus tous ces problèmes de conversion signé/non signé.

Deux méthodes courantes de parcours de tableau sans indices sont les boucles basées sur intervalle (range-based for loops) et les itérateurs.

Nous traitons des itérateurs dans la prochaine leçon 18.2 -- Introduction aux itérateurs.

Si vous n'utilisez la variable d'indice que pour parcourir le tableau, privilégiez une méthode qui n'utilise pas d'indices.

Bonne pratique

Évitez autant que possible d'indexer un tableau par des valeurs entières.
