13.3 — Conversions intégrales des énumérateurs sans portée

Dans la leçon précédente (13.2 -- Énumérations sans portée), nous avons indiqué que les énumérateurs sont des constantes symboliques. Ce que nous n'avons pas dit à ce moment-là, c'est que ces énumérateurs ont des valeurs de type entier.

C'est comparable au cas des char (4.11 -- Les char). Considérez :

char ch { 'A' };

Un char est en réalité une simple valeur entière de 1 octet : le caractère 'A' est converti en une valeur entière (ici 65), puis stocké.

Lorsque nous définissons une énumération, chaque énumérateur est automatiquement associé à une valeur entière, déterminée par sa position dans la liste des énumérateurs. Par défaut, le premier énumérateur reçoit la valeur entière 0, et chaque énumérateur suivant a une valeur supérieure de un à celle du précédent :

enum Color
{
    black,   // 0
    red,     // 1
    blue,    // 2
    green,   // 3
    white,   // 4
    cyan,    // 5
    yellow,  // 6
    magenta, // 7
};

int main()
{
    Color shirt{ blue }; // shirt stocke en fait la valeur entière 2

    return 0;
}

Il est possible de définir explicitement la valeur des énumérateurs. Ces valeurs entières peuvent être positives ou négatives, et peuvent être identiques à celles d'autres énumérateurs. Les énumérateurs non définis explicitement reçoivent une valeur supérieure de un à celle de l'énumérateur précédent.

enum Animal
{
    cat = -3,    // les valeurs peuvent être négatives
    dog,         // -2
    pig,         // -1
    horse = 5,
    giraffe = 5, // même valeur que horse
    chicken,     // 6
};

Notez que horse et giraffe ont reçu la même valeur. Dans ce cas, les énumérateurs ne sont plus distincts : horse et giraffe sont interchangeables. Bien que C++ l'autorise, il faut généralement éviter d'attribuer la même valeur à deux énumérateurs d'une même énumération.

La plupart du temps, les valeurs par défaut des énumérateurs correspondent exactement à ce que vous voulez. Ne fournissez donc vos propres valeurs que si vous avez une raison précise de le faire.

Bonne pratique

Évitez d'attribuer des valeurs explicites à vos énumérateurs, sauf si vous avez une raison impérieuse de le faire.

Initialisation par valeur d'une énumération

Si une énumération est initialisée à zéro (ce qui se produit lorsque nous utilisons l'initialisation par valeur), elle reçoit la valeur 0, même s'il n'existe aucun énumérateur correspondant à cette valeur.

#include <iostream>

enum Animal
{
    cat = -3,    // -3
    dog,         // -2
    pig,         // -1
    // note : aucun énumérateur de valeur 0 dans cette liste
    horse = 5,   // 5
    giraffe = 5, // 5
    chicken,     // 6
};

int main()
{
    Animal a {}; // l'initialisation par valeur met a à zéro (valeur 0)
    std::cout << a; // affiche 0

    return 0;
}

Cela a deux conséquences sémantiques :

  • S'il existe un énumérateur de valeur 0, l'initialisation par valeur donne à l'énumération la signification de cet énumérateur. Par exemple, avec l'énumération Color vue précédemment, un Color initialisé par valeur vaudra black. C'est pourquoi il est judicieux de faire en sorte que l'énumérateur de valeur 0 représente la meilleure signification par défaut de votre énumération.

Un code comme celui-ci risque de poser problème :

enum UniverseResult
{
    destroyUniverse, // valeur par défaut (0)
    saveUniverse
};
  • S'il n'existe aucun énumérateur de valeur 0, l'initialisation par valeur peut facilement créer une énumération sémantiquement invalide. Dans ce cas, nous recommandons d'ajouter un énumérateur « invalide » ou « inconnu » de valeur 0, afin de documenter la signification de cet état et de disposer d'un nom pour cet état que vous pouvez traiter explicitement.
enum Winner
{
    winnerUnknown, // valeur par défaut (0)
    player1,
    player2,
};

// quelque part plus loin dans votre code
if (w == winnerUnknown) // traiter le cas de façon appropriée

Bonne pratique

Faites en sorte que l'énumérateur représentant 0 soit celui qui correspond à la meilleure signification par défaut de votre énumération. Si aucune bonne valeur par défaut n'existe, envisagez d'ajouter un énumérateur « invalide » ou « inconnu » de valeur 0, afin que cet état soit explicitement documenté et puisse être traité explicitement lorsque c'est approprié.

Les énumérations sans portée se convertissent implicitement en valeurs entières

Même si les énumérations stockent des valeurs entières, elles ne sont pas considérées comme un type entier (ce sont des types composés). Cependant, une énumération sans portée se convertit implicitement en valeur entière. Comme les énumérateurs sont des constantes à la compilation, il s'agit d'une conversion constexpr (nous les abordons dans la leçon 10.4 -- Conversions restrictives, initialisation par liste et initialiseurs constexpr).

Considérez le programme suivant :

#include <iostream>

enum Color
{
    black, // valeur 0
    red, // valeur 1
    blue, // valeur 2
    green, // valeur 3
    white, // valeur 4
    cyan, // valeur 5
    yellow, // valeur 6
    magenta, // valeur 7
};

int main()
{
    Color shirt{ blue };

    std::cout << "Your shirt is " << shirt << '\n'; // que fait cette ligne ?

    return 0;
}

Comme les types énumérés contiennent des valeurs entières, on pourrait s'attendre à ce que ce programme affiche :


Your shirt is 2

Lorsqu'un type énuméré est utilisé dans un appel de fonction ou avec un opérateur, le compilateur essaie d'abord de trouver une fonction ou un opérateur correspondant à ce type énuméré. Par exemple, lorsque le compilateur tente de compiler std::cout << shirt, il cherche d'abord si operator<< sait afficher un objet de type Color (puisque shirt est de type Color) sur std::cout. Ce n'est pas le cas.

Comme le compilateur ne trouve aucune correspondance, il vérifie ensuite si operator<< sait afficher un objet du type entier vers lequel l'énumération sans portée se convertit. C'est le cas : la valeur de shirt est donc convertie en valeur entière et affichée sous la forme de l'entier 2.

Contenu associé

Nous montrons comment convertir une énumération en chaîne de caractères dans la leçon 13.4 -- Convertir une énumération vers et depuis une chaîne de caractères.
Nous apprenons à std::cout à afficher un énumérateur dans la leçon 13.5 -- Introduction à la surcharge des opérateurs d'entrée/sortie.

Taille de l'énumération et type sous-jacent (base)

Les énumérateurs ont des valeurs de type entier. Mais quel type entier ? Le type entier précis utilisé pour représenter la valeur des énumérateurs s'appelle le type sous-jacent (ou base) de l'énumération.

Pour les énumérations sans portée, la norme C++ ne précise pas le type entier à utiliser comme type sous-jacent : ce choix dépend de l'implémentation. La plupart des compilateurs utilisent int comme type sous-jacent (ce qui signifie qu'une énumération sans portée a la même taille qu'un int), sauf si un type plus grand est nécessaire pour stocker les valeurs des énumérateurs. Mais vous ne devez pas supposer que cela sera vrai pour tous les compilateurs ni toutes les plateformes.

Il est possible de spécifier explicitement un type sous-jacent pour une énumération. Ce type doit être un type entier. Par exemple, si vous travaillez dans un contexte sensible à la bande passante (par exemple l'envoi de données sur un réseau), vous pouvez vouloir spécifier un type plus petit pour votre énumération :

#include <cstdint>  // pour std::int8_t
#include <iostream>

// Utilise un entier de 8 bits comme type sous-jacent de l'énumération
enum Color : std::int8_t
{
    black,
    red,
    blue,
};

int main()
{
    Color c{ black };
    std::cout << sizeof(c) << '\n'; // affiche 1 (octet)

    return 0;
}

Bonne pratique

Ne spécifiez le type de base d'une énumération que lorsque cela est nécessaire.

Attention

Comme std::int8_t et std::uint8_t sont généralement des alias de types char, utiliser l'un de ces types comme base d'une énumération fera très probablement afficher les énumérateurs comme des caractères plutôt que comme des entiers.

Conversion d'un entier vers un énumérateur sans portée

Si le compilateur convertit implicitement une énumération sans portée en entier, il ne convertit pas implicitement un entier en énumération sans portée. Le code suivant provoque une erreur de compilation :

enum Pet // pas de base spécifiée
{
    cat, // valeur 0
    dog, // valeur 1
    pig, // valeur 2
    whale, // valeur 3
};

int main()
{
    Pet pet { 2 }; // erreur de compilation : la valeur entière 2 ne se convertit pas implicitement en Pet
    pet = 3;       // erreur de compilation : la valeur entière 3 ne se convertit pas implicitement en Pet

    return 0;
}

Il existe deux façons de contourner ce problème.

Premièrement, vous pouvez convertir explicitement un entier en énumérateur sans portée à l'aide de static_cast :

enum Pet // pas de base spécifiée
{
    cat, // valeur 0
    dog, // valeur 1
    pig, // valeur 2
    whale, // valeur 3
};

int main()
{
    Pet pet { static_cast<Pet>(2) }; // convertit l'entier 2 en Pet
    pet = static_cast<Pet>(3);       // notre cochon s'est transformé en baleine !

    return 0;
}

Nous verrons un exemple d'utilisation de ceci dans la leçon 13.4 -- Convertir une énumération vers et depuis une chaîne de caractères.

Il est sûr d'utiliser static_cast sur toute valeur entière représentée par un énumérateur de l'énumération cible. Comme notre énumération Pet contient des énumérateurs de valeurs 0, 1, 2 et 3, appliquer static_cast aux valeurs entières 0, 1, 2 et 3 pour obtenir un Pet est valide.

Il est également sûr d'utiliser static_cast sur toute valeur entière comprise dans les limites du type sous-jacent de l'énumération cible, même si aucun énumérateur ne représente cette valeur. Appliquer static_cast à une valeur en dehors des limites du type sous-jacent provoque un comportement indéfini.

Pour les lecteurs avancés

Si l'énumération a un type sous-jacent explicitement défini, l'intervalle de valeurs de l'énumération est identique à celui de son type sous-jacent.

Si l'énumération n'a pas de type sous-jacent explicite, les choses sont un peu plus compliquées. Dans ce cas, c'est le compilateur qui choisit le type sous-jacent, et il peut choisir n'importe quel type signé ou non signé, à condition que les valeurs de tous les énumérateurs tiennent dans ce type. Dès lors, il n'est sûr d'appliquer static_cast qu'aux valeurs entières qui tiennent dans le plus petit nombre de bits capable de contenir les valeurs de tous les énumérateurs.

Prenons deux exemples pour illustrer ce point :

  • Avec des énumérateurs de valeurs 2, 9 et 12, ces énumérateurs peuvent tenir dans un type entier non signé de 4 bits, dont l'intervalle est de 0 à 15. Il n'est donc sûr d'appliquer static_cast qu'aux valeurs entières de 0 à 15 pour ce type énuméré.
  • Avec des énumérateurs de valeurs -28, 2 et 6, ces énumérateurs peuvent tenir dans un type entier signé de 6 bits, dont l'intervalle est de -32 à 31. Il n'est donc sûr d'appliquer static_cast qu'aux valeurs entières de -32 à 31 pour ce type énuméré.

Deuxièmement, depuis C++17, si une énumération sans portée a une base explicitement spécifiée, le compilateur vous permet de l'initialiser par liste à l'aide d'une valeur entière :

enum Pet: int // nous avons spécifié une base
{
    cat, // valeur 0
    dog, // valeur 1
    pig, // valeur 2
    whale, // valeur 3
};

int main()
{
    Pet pet1 { 2 }; // ok : on peut initialiser avec des accolades une énumération sans portée à base spécifiée avec un entier (C++17)
    Pet pet2 (2);   // erreur de compilation : impossible d'initialiser directement avec un entier
    Pet pet3 = 2;   // erreur de compilation : impossible d'initialiser par copie avec un entier

    pet1 = 3;       // erreur de compilation : impossible d'affecter un entier

    return 0;
}

Solution

Vrai. Les énumérateurs auxquels aucune valeur explicite n'est attribuée reçoivent implicitement la valeur entière de l'énumérateur précédent + 1. S'il n'existe pas d'énumérateur précédent, l'énumérateur reçoit la valeur 0.

  • Recevoir une valeur à virgule flottante

Solution

Vrai

  • Recevoir une valeur non unique
Solution

Vrai

  • Recevoir la valeur d'un énumérateur précédent (par exemple magenta = red)
Solution

Vrai. Les énumérateurs ne sont pas obligatoirement uniques. Comme les énumérateurs se convertissent implicitement en entiers, et que des entiers peuvent leur être attribués, les énumérateurs peuvent être initialisés avec d'autres énumérateurs (même si cela a rarement un intérêt !).

Faux. Comme les énumérateurs sont constexpr, leurs valeurs doivent aussi être constexpr.
