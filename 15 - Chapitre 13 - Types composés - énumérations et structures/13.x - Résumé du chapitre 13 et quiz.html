13.x — Résumé du chapitre 13 et quiz

Bravo ! Vous avez terminé un chapitre de plus. Les connaissances acquises sur les structures (struct) vous seront utiles lorsque nous aborderons le sujet le plus important du C++ : les classes !

Révision rapide

Un type défini par le programme (aussi appelé type défini par l'utilisateur) est un type personnalisé que nous pouvons créer pour l'utiliser dans nos propres programmes. Les types énumérés et les types classes (y compris les structures (struct), les classes (class) et les unions) permettent de créer des types définis par le programme. Ces types doivent être définis avant d'être utilisés. La définition d'un type défini par le programme s'appelle une définition de type. Les définitions de type sont exemptées de la règle de définition unique (one-definition rule).

Une énumération (aussi appelée type énuméré ou enum) est un type de données composé dans lequel chaque valeur possible est définie comme une constante symbolique (appelée énumérateur). Les énumérations sont des types distincts, ce qui signifie que le compilateur peut les différencier des autres types (contrairement aux alias de types).

Les énumérations non délimitées (unscoped) portent ce nom parce qu'elles placent leurs noms d'énumérateurs dans la même portée que la définition de l'énumération elle-même (contrairement à un espace de noms, qui crée une nouvelle région de portée). Les énumérations non délimitées fournissent tout de même une région de portée nommée pour leurs énumérateurs. Elles se convertissent implicitement en valeurs entières.

Les énumérations délimitées (scoped) fonctionnent de manière similaire aux énumérations non délimitées, mais ne se convertissent pas implicitement en entiers, et leurs énumérateurs ne sont placés que dans la région de portée de l'énumération (et non dans la région de portée où l'énumération est définie).

Une structure (struct, abréviation de structure) est un type de données défini par le programme qui nous permet de regrouper plusieurs variables en un seul type. Les variables qui font partie de la structure (ou de la classe) sont appelées membres de données (ou variables membres). Pour accéder à une variable membre spécifique, nous utilisons l'opérateur de sélection de membre (operator.) entre le nom de la variable de structure et le nom du membre (pour les structures normales et les références vers des structures), ou l'opérateur de sélection de membre à partir d'un pointeur (operator->) (pour les pointeurs vers des structures).

En programmation générale, un type agrégat (aussi appelé agrégat) est tout type pouvant contenir plusieurs membres de données. En C++, les tableaux et les structures ne contenant que des membres de données sont des agrégats.

Les agrégats utilisent une forme d'initialisation appelée initialisation d'agrégat (aggregate initialization), qui nous permet d'initialiser directement les membres des agrégats. Pour cela, nous fournissons une liste d'initialisation (initializer list) comme initialiseur, c'est-à-dire simplement une liste de valeurs séparées par des virgules. L'initialisation d'agrégat effectue une initialisation membre à membre (memberwise initialization), ce qui signifie que chaque membre de la structure est initialisé dans l'ordre de déclaration.

En C++20, les initialiseurs désignés (designated initializers) permettent d'indiquer explicitement quelle valeur d'initialisation correspond à quel membre. Les membres doivent être initialisés dans l'ordre où ils sont déclarés dans la structure, sinon une erreur se produit.

Lorsque nous définissons un type structure (ou classe), nous pouvons fournir une valeur d'initialisation par défaut pour chaque membre dans la définition du type. Ce processus s'appelle initialisation non statique des membres (non-static member initialization), et la valeur d'initialisation s'appelle un initialiseur de membre par défaut (default member initializer).

Pour des raisons de performance, le compilateur ajoute parfois des espaces vides dans les structures (c'est ce qu'on appelle le remplissage, ou padding), de sorte que la taille d'une structure peut être supérieure à la somme des tailles de ses membres.

Un modèle de classe (class template) est une définition de modèle permettant d'instancier des types classes (structures, classes ou unions). La déduction d'argument de modèle de classe (CTAD) est une fonctionnalité du C++17 qui permet au compilateur de déduire les arguments de type du modèle à partir d'un initialiseur.

Question n° 1

Lors de la conception d'un jeu, nous décidons d'ajouter des monstres, car tout le monde aime combattre des monstres. Déclarez une structure qui représente votre monstre. Le monstre doit avoir un type pouvant être l'un des suivants : un ogre, un dragon, un orc, une araignée géante ou une gelée (slime).

Chaque monstre doit également avoir un nom (utilisez un std::string), ainsi qu'une quantité de points de vie représentant les dégâts qu'il peut encaisser avant de mourir. Écrivez une fonction nommée printMonster() qui affiche tous les membres de la structure. Instanciez un ogre et un slime, initialisez-les à l'aide d'une liste d'initialisation, et passez-les à printMonster().

Votre programme doit produire le résultat suivant :


This Ogre is named Torg and has 145 health.
This Slime is named Blurp and has 23 health.
Solution 
#include <iostream>
#include <string>
#include <string_view> // C++17

// Notre structure monstre représente un monstre unique

struct Monster
{
    // Définit nos différents types de monstres sous forme d'enum
    enum Type
    {
        ogre,
        dragon,
        orc,
        giant_spider,
        slime,
    };

    Type type{};
    std::string name{}; // le Monster doit être propriétaire de son nom
    int health{};
};

// Renvoie le nom du type du monstre sous forme de chaîne
// Comme cela pourrait être utilisé ailleurs, il est préférable d'en faire une fonction à part
constexpr std::string_view getMonsterTypeString(Monster::Type type)
{
    switch (type)
    {
    case Monster::ogre:          return "Ogre";
    case Monster::dragon:        return "Dragon";
    case Monster::orc:           return "Orc";
    case Monster::giant_spider:  return "Giant Spider";
    case Monster::slime:         return "Slime";
    }

    return "Unknown";
}

// Affiche les caractéristiques de notre monstre
void printMonster(const Monster& monster)
{
    std::cout << "This " << getMonsterTypeString(monster.type) <<
        " is named " << monster.name <<
        " and has " << monster.health << " health.\n";
}

int main()
{
    Monster ogre{ Monster::ogre, "Torg", 145 };
    Monster slime{ Monster::slime, "Blurp", 23 };

    printMonster(ogre);
    printMonster(slime);

    return 0;
}

Question n° 2

Indiquez si les objets de chacun des types donnés doivent être passés par valeur, par adresse constante ou par référence constante. Vous pouvez supposer que la fonction qui prend ces types en paramètres ne les modifie pas.

a) char

Solution

char est un type fondamental, il doit donc être passé par valeur.

b) std::string

Solution

std::string doit créer une copie de la chaîne à chaque copie. Passez-la par référence constante.

c) unsigned long

Solution

unsigned long est un type fondamental, il doit donc être passé par valeur.

d) bool

Solution

bool est un type fondamental, il doit donc être passé par valeur.

e) Un type énuméré

Solution

Les types énumérés contiennent des valeurs entières (généralement de type int). Comme les valeurs entières sont passées par valeur, les types énumérés doivent également être passés par valeur.

f)

struct Position
{
  double x{};
  double y{};
  double z{};
};
Solution

Position est un type structure et doit être passé par référence constante.

g)

struct Player
{
  int health{};
  // La structure Player est encore en cours de développement. D'autres membres seront ajoutés.
};
Solution

Bien que Player ne contienne qu'un seul int dans son état actuel, ce qui le rendrait rapide à passer par valeur, d'autres membres seront ajoutés à l'avenir. Nous ne voulons pas modifier chaque utilisation de Player lorsque cela se produira, nous le passons donc par référence constante.

h) int (lorsque la valeur nulle est un argument valide)

Solution

Normalement, nous passerions un int par valeur, mais si nous voulons également pouvoir passer une valeur nulle, le passage par adresse est un bon choix, car nous pouvons passer soit l'adresse de l'int, soit nullptr.

i) std::string_view

Solution

std::string_view ne crée pas de copie de la chaîne qu'il désigne, et il est peu coûteux à copier. Passez-le par valeur.

Question n° 3

Créez un modèle de classe nommé Triad qui possède 3 membres du même type modèle. Créez également un modèle de fonction nommé print capable d'afficher un Triad. Le programme suivant doit se compiler :

int main()
{
    Triad t1{ 1, 2, 3 }; // note : utilise la CTAD pour déduire les arguments de modèle
    print(t1);

    Triad t2{ 1.2, 3.4, 5.6 }; // note : utilise la CTAD pour déduire les arguments de modèle
    print(t2);

    return 0;
}

et produire le résultat suivant :


[1, 2, 3][1.2, 3.4, 5.6]

Si vous utilisez le C++17, vous devrez fournir un guide de déduction pour que la CTAD fonctionne (voir 13.14 -- Déduction d'argument de modèle de classe (CTAD) et guides de déduction pour plus d'informations à ce sujet).

Solution 
#include <iostream>

template <typename T>
struct Triad
{
    T first {};
    T second {};
    T third {};
};

// En C++17, nous devons fournir un guide de déduction (non nécessaire en C++20)
// Un Triad avec trois arguments du même type doit se déduire en Triad<T>
template <typename T>
Triad(T, T, T) -> Triad<T>;

template <typename T>
void print(const Triad<T>& t)
{
    std::cout << '[' << t.first << ", " << t.second << ", " << t.third << ']';
}

int main()
{
    Triad t1{ 1, 2, 3 };
    print(t1);

    Triad t2{ 1.2, 3.4, 5.6 };
    print(t2);

    return 0;
}
