13.8 — Initialisation par agrégat des structures

Dans la leçon précédente (13.7 -- Introduction aux structures, aux membres et à la sélection de membre), nous avons vu comment définir des structures, instancier des objets de type structure et accéder à leurs membres. Dans cette leçon, nous allons voir comment les structures sont initialisées.

Les membres de données ne sont pas initialisés par défaut

Tout comme les variables ordinaires, les membres de données ne sont pas initialisés par défaut. Considérons la structure suivante :

#include <iostream>

struct Employee
{
    int id; // remarque : pas d'initialiseur ici
    int age;
    double wage;
};

int main()
{
    Employee joe; // remarque : pas d'initialiseur ici non plus
    std::cout << joe.id << '\n';

    return 0;
}

Comme nous n'avons fourni aucun initialiseur, lorsque joe est instancié, joe.id, joe.age et joe.wage sont tous non initialisés. Nous obtenons alors un comportement indéfini lorsque nous essayons d'afficher la valeur de joe.id.

Cependant, avant de vous montrer comment initialiser une structure, faisons un bref détour.

Qu'est-ce qu'un agrégat ?

En programmation générale, un type de données agrégat (aussi appelé agrégat) est tout type pouvant contenir plusieurs membres de données. Certains agrégats autorisent des membres de types différents (par exemple les structures), tandis que d'autres exigent que tous les membres soient du même type (par exemple les tableaux).

En C++, la définition d'un agrégat est plus restrictive et sensiblement plus complexe.

Note de l'auteur

Dans cette série de tutoriels, lorsque nous utilisons le terme « agrégat » (ou « non-agrégat »), nous désignons la définition C++ d'agrégat.

Pour les lecteurs avancés

Pour simplifier un peu, un agrégat en C++ est soit un tableau de style C (17.7 -- Introduction aux tableaux de style C), soit un type classe (struct, class ou union) qui possède :

  • Aucun constructeur déclaré par l'utilisateur (14.9 -- Introduction aux constructeurs)
  • Aucun membre de données non statique privé ou protégé (14.5 -- Membres publics et privés et spécificateurs d'accès)
  • Aucune fonction virtuelle (25.2 -- Fonctions virtuelles et polymorphisme)

Le type populaire std::array (17.1 -- Introduction à std::array) est également un agrégat.

Vous pouvez trouver la définition précise d'un agrégat C++ ici.

Le point essentiel à retenir à ce stade est que les structures ne contenant que des membres de données sont des agrégats.

Initialisation par agrégat d'une structure

Comme une variable ordinaire ne peut contenir qu'une seule valeur, nous n'avons besoin que d'un seul initialiseur :

int x { 5 };

Cependant, une structure peut avoir plusieurs membres :

struct Employee
{
    int id {};
    int age {};
    double wage {};
};

Lorsque nous définissons un objet de type structure, nous avons besoin d'un moyen d'initialiser plusieurs membres au moment de l'initialisation :

Employee joe; // comment initialiser joe.id, joe.age et joe.wage ?

Les agrégats utilisent une forme d'initialisation appelée initialisation par agrégat, qui nous permet d'initialiser directement les membres des agrégats. Pour cela, nous fournissons une liste d'initialisation comme initialiseur ; il s'agit simplement d'une liste de valeurs séparées par des virgules et entourées d'accolades.

Il existe 2 formes principales d'initialisation par agrégat :

struct Employee
{
    int id {};
    int age {};
    double wage {};
};

int main()
{
    Employee frank = { 1, 32, 60000.0 }; // initialisation par copie avec liste entre accolades
    Employee joe { 2, 28, 45000.0 };     // initialisation par liste avec accolades (à privilégier)

    return 0;
}

Chacune de ces formes d'initialisation effectue une initialisation membre à membre, ce qui signifie que chaque membre de la structure est initialisé dans l'ordre de déclaration. Ainsi, Employee joe { 2, 28, 45000.0 }; initialise d'abord joe.id avec la valeur 2, puis joe.age avec la valeur 28, et enfin joe.wage avec la valeur 45000.0.

Bonne pratique

Privilégiez la forme à liste entre accolades (sans copie) pour initialiser des agrégats.

En C++20, nous pouvons aussi initialiser (certains) agrégats à l'aide d'une liste de valeurs entre parenthèses :

    Employee robert ( 3, 45, 62500.0 );  // initialisation directe avec liste entre parenthèses (C++20)

Nous recommandons d'éviter autant que possible cette dernière forme, car elle ne fonctionne pas actuellement avec les agrégats utilisant l'élision d'accolades (notamment std::array).

Initialiseurs manquants dans une liste d'initialisation

Si un agrégat est initialisé mais que le nombre de valeurs d'initialisation est inférieur au nombre de membres, chaque membre sans initialiseur explicite est initialisé de la manière suivante :

  • Si le membre possède un initialiseur de membre par défaut, celui-ci est utilisé.
  • Sinon, le membre est initialisé par copie à partir d'une liste d'initialisation vide. Dans la plupart des cas, cela réalise une initialisation par valeur de ces membres (pour les types classe, cela invoque le constructeur par défaut, même si un constructeur de liste existe).
struct Employee
{
    int id {};
    int age {};
    double wage { 76000.0 };
    double whatever;
};

int main()
{
    Employee joe { 2, 28 }; // joe.whatever sera initialisé par valeur à 0.0

    return 0;
}

Dans l'exemple ci-dessus, joe.id est initialisé avec la valeur 2 et joe.age avec la valeur 28. Comme joe.wage n'a pas reçu d'initialiseur explicite mais possède un initialiseur de membre par défaut, joe.wage est initialisé à 76000.0. Enfin, comme joe.whatever n'a pas reçu d'initialiseur explicite, il est initialisé par valeur à 0.0.

Astuce

Cela signifie que nous pouvons généralement utiliser une liste d'initialisation vide pour initialiser par valeur tous les membres de la structure :

Employee joe {}; // initialise par valeur tous les membres

Surcharger operator<< pour afficher une structure

Dans la leçon 13.5 -- Introduction à la surcharge des opérateurs d'entrée/sortie, nous avons montré comment surcharger operator<< pour afficher une énumération. Il est également utile de surcharger operator<< pour les structures.

Voici le même exemple que dans la section précédente, maintenant avec un operator<< surchargé :

#include <iostream>

struct Employee
{
    int id {};
    int age {};
    double wage {};
};

std::ostream& operator<<(std::ostream& out, const Employee& e)
{
    out << e.id << ' ' << e.age << ' ' << e.wage;
    return out;
}

int main()
{
    Employee joe { 2, 28 }; // joe.wage sera initialisé par valeur à 0.0
    std::cout << joe << '\n';

    return 0;
}

Ce programme affiche :


2 28 0

Nous constatons que joe.wage a bien été initialisé par valeur à 0.0 (ce qui s'affiche comme 0).

Contrairement à une énumération, une structure peut contenir plusieurs valeurs. La manière de formater la sortie (par exemple pour séparer les valeurs) vous appartient entièrement.

Les trois valeurs affichées par notre operator<< surchargé ci-dessus ne sont pas intuitives, car rien n'indique ce que ces valeurs signifient. Refaisons le même exemple, mais modifions la fonction d'affichage pour la rendre un peu plus descriptive :

#include <iostream>

struct Employee
{
    int id {};
    int age {};
    double wage {};
};

std::ostream& operator<<(std::ostream& out, const Employee& e)
{
    out << "id: " << e.id << " age: " << e.age << " wage: " << e.wage;
    return out;
}

int main()
{
    Employee joe { 2, 28 }; // joe.wage sera initialisé par valeur à 0.0
    std::cout << joe << '\n';

    return 0;
}

Ce programme affiche maintenant :


id: 2 age: 28 wage: 0

C'est un peu plus facile à comprendre.

Structures constantes

Les variables de type structure peuvent être const (ou constexpr) et, comme toutes les variables const, elles doivent être initialisées.

struct Rectangle
{
    double length {};
    double width {};
};

int main()
{
    const Rectangle unit { 1.0, 1.0 };
    const Rectangle zero { }; // initialise par valeur tous les membres

    return 0;
}

Initialiseurs désignés (C++20)

Lorsqu'on initialise une structure à partir d'une liste de valeurs, les initialiseurs sont appliqués aux membres dans l'ordre de déclaration.

struct Foo
{
    int a {};
    int c {};
};

int main()
{
    Foo f { 1, 3 }; // f.a = 1, f.c = 3

    return 0;
}

Examinons maintenant ce qui se passerait si l'on modifiait cette définition de structure pour ajouter un nouveau membre qui n'est pas le dernier :

struct Foo
{
    int a {};
    int b {}; // vient d'être ajouté
    int c {};
};

int main()
{
    Foo f { 1, 3 }; // désormais, f.a = 1, f.b = 3, f.c = 0

    return 0;
}

Toutes vos valeurs d'initialisation sont alors décalées et, pire encore, le compilateur peut ne pas signaler cela comme une erreur (après tout, la syntaxe reste valide).

Pour éviter cela, le C++20 ajoute une nouvelle manière d'initialiser les membres d'une structure, appelée initialiseurs désignés (designated initializers). Les initialiseurs désignés vous permettent de définir explicitement quelle valeur d'initialisation correspond à quel membre. Les membres peuvent être initialisés par initialisation de liste ou par copie, et doivent être initialisés dans le même ordre que celui de leur déclaration dans la structure, faute de quoi un avertissement ou une erreur sera produit. Les membres qui ne reçoivent pas d'initialiseur désigné sont initialisés par valeur.

struct Foo
{
    int a{ };
    int b{ };
    int c{ };
};

int main()
{
    Foo f1{ .a{ 1 }, .c{ 3 } }; // ok : f1.a = 1, f1.b = 0 (initialisé par valeur), f1.c = 3
    Foo f2{ .a = 1, .c = 3 };   // ok : f2.a = 1, f2.b = 0 (initialisé par valeur), f2.c = 3
    Foo f3{ .b{ 2 }, .a{ 1 } }; // erreur : l'ordre d'initialisation ne correspond pas à l'ordre de déclaration dans la structure

    return 0;
}

Pour les utilisateurs de Clang

Lors de l'utilisation d'initialiseurs désignés de valeurs simples avec des accolades, Clang émet à tort l'avertissement « braces around scalar initializer ». Espérons que cela sera corrigé prochainement.

Les initialiseurs désignés sont pratiques, car ils offrent un certain niveau d'auto-documentation et aident à éviter de mélanger par inadvertance l'ordre de vos valeurs d'initialisation. Cependant, ils alourdissent aussi considérablement la liste d'initialisation ; nous ne les recommandons donc pas comme bonne pratique pour le moment.

De plus, comme rien n'impose d'utiliser les initialiseurs désignés de façon systématique partout où un agrégat est initialisé, il est préférable d'éviter d'ajouter de nouveaux membres au milieu d'une définition d'agrégat existante, afin de limiter le risque de décalage des initialiseurs.

Bonne pratique

Lorsque vous ajoutez un nouveau membre à un agrégat, le plus sûr est de l'ajouter en bas de la liste de définition, afin que les initialiseurs des autres membres ne soient pas décalés.

Affectation avec une liste d'initialisation

Comme vu dans la leçon précédente, nous pouvons affecter des valeurs aux membres d'une structure individuellement :

struct Employee
{
    int id {};
    int age {};
    double wage {};
};

int main()
{
    Employee joe { 1, 32, 60000.0 };

    joe.age  = 33;      // Joe a fêté son anniversaire
    joe.wage = 66000.0; // et a obtenu une augmentation

    return 0;
}

Cela convient pour un seul membre, mais devient peu pratique lorsque nous voulons mettre à jour plusieurs membres. De manière similaire à l'initialisation d'une structure avec une liste d'initialisation, vous pouvez aussi affecter des valeurs à une structure à l'aide d'une liste d'initialisation (ce qui réalise une affectation membre à membre) :

struct Employee
{
    int id {};
    int age {};
    double wage {};
};

int main()
{
    Employee joe { 1, 32, 60000.0 };
    joe = { joe.id, 33, 66000.0 }; // Joe a fêté son anniversaire et a obtenu une augmentation

    return 0;
}

Notez que, puisque nous ne voulions pas modifier joe.id, nous avons dû fournir la valeur actuelle de joe.id dans notre liste comme valeur de remplacement, afin que l'affectation membre à membre affecte joe.id à joe.id. C'est un peu laid.

Affectation avec initialiseurs désignés (C++20)

Les initialiseurs désignés peuvent aussi être utilisés dans une affectation par liste :

struct Employee
{
    int id {};
    int age {};
    double wage {};
};

int main()
{
    Employee joe { 1, 32, 60000.0 };
    joe = { .id = joe.id, .age = 33, .wage = 66000.0 }; // Joe a fêté son anniversaire et a obtenu une augmentation

    return 0;
}

Tous les membres qui ne sont pas désignés dans une telle affectation reçoivent la valeur qui serait utilisée pour l'initialisation par valeur. Si nous n'avions pas spécifié d'initialiseur désigné pour joe.id, joe.id aurait reçu la valeur 0.

Initialiser une structure avec une autre structure du même type

Une structure peut aussi être initialisée à partir d'une autre structure du même type :

#include <iostream>

struct Foo
{
    int a{};
    int b{};
    int c{};
};

std::ostream& operator<<(std::ostream& out, const Foo& f)
{
    out << f.a << ' ' << f.b << ' ' << f.c;
    return out;
}

int main()
{
    Foo foo { 1, 2, 3 };

    Foo x = foo; // initialisation par copie
    Foo y(foo);  // initialisation directe
    Foo z {foo}; // initialisation directe par liste

    std::cout << x << '\n';
    std::cout << y << '\n';
    std::cout << z << '\n';

    return 0;
}

Le programme ci-dessus affiche :


1 2 3
1 2 3
1 2 3

Remarquez que cela utilise les formes classiques d'initialisation que nous connaissons (par copie, directe ou directe par liste) plutôt que l'initialisation par agrégat.

Ce cas se rencontre le plus souvent lorsqu'on initialise une structure avec la valeur de retour d'une fonction qui renvoie une structure du même type. Nous traitons ce point plus en détail dans la leçon 13.10 -- Passage et retour de structures.
