13.5 — Introduction à la surcharge des opérateurs d'entrée et de sortie

Dans la leçon précédente (13.4 -- Conversion d'une énumération vers et depuis une chaîne de caractères), nous avons montré cet exemple, dans lequel nous utilisions une fonction pour convertir une énumération en une chaîne équivalente :

#include <iostream>
#include <string_view>

enum Color
{
    black,
    red,
    blue,
};

constexpr std::string_view getColorName(Color color)
{
    switch (color)
    {
    case black: return "black";
    case red:   return "red";
    case blue:  return "blue";
    default:    return "???";
    }
}

int main()
{
    constexpr Color shirt{ blue };

    std::cout << "Your shirt is " << getColorName(shirt) << '\n';

    return 0;
}

Bien que cet exemple fonctionne parfaitement, il présente deux inconvénients :

  1. Nous devons nous souvenir du nom de la fonction que nous avons créée pour obtenir le nom de l'énumérateur.
  2. Appeler une telle fonction alourdit notre instruction d'affichage.

Idéalement, il serait agréable de pouvoir d'une manière ou d'une autre apprendre à operator<< à afficher une énumération, afin de pouvoir écrire quelque chose comme std::cout << shirt et obtenir le résultat attendu.

Introduction à la surcharge d'opérateurs

Dans la leçon 11.1 -- Introduction à la surcharge de fonctions, nous avons présenté la surcharge de fonctions, qui permet de créer plusieurs fonctions portant le même nom, à condition que chacune ait un prototype unique. Grâce à la surcharge de fonctions, nous pouvons créer des variantes d'une fonction qui travaillent avec différents types de données, sans avoir à inventer un nom unique pour chaque variante.

De la même manière, C++ prend également en charge la surcharge d'opérateurs (operator overloading), qui permet de définir des surcharges d'opérateurs existants, afin de faire fonctionner ces opérateurs avec nos propres types de données.

La surcharge d'opérateurs de base est assez simple :

  • Définissez une fonction dont le nom est celui de l'opérateur que vous voulez surcharger.
  • Ajoutez un paramètre du type approprié pour chaque opérande (de gauche à droite). L'un de ces paramètres doit être un type défini par l'utilisateur (un type classe ou un type énumération), sinon le compilateur produira une erreur.
  • Choisissez le type de retour qui a du sens.
  • Utilisez une instruction return pour renvoyer le résultat de l'opération.

Lorsque le compilateur rencontre l'utilisation d'un opérateur dans une expression, et qu'au moins un des opérandes est un type défini par l'utilisateur, il vérifie s'il existe une fonction d'opérateur surchargée qu'il peut utiliser pour résoudre cet appel. Par exemple, pour une expression x + y, le compilateur utilisera la résolution de surcharge de fonctions pour voir s'il existe un appel operator+(x, y) qu'il peut utiliser pour évaluer l'opération. Si une fonction operator+ non ambiguë est trouvée, elle est appelée et le résultat de l'opération est renvoyé comme valeur de retour.

Surcharger operator<< pour afficher un énumérateur

Avant de continuer, rappelons rapidement comment fonctionne operator<< lorsqu'il est utilisé pour l'affichage.

Considérons une expression simple comme std::cout << 5. std::cout a pour type std::ostream (qui est un type défini par l'utilisateur de la bibliothèque standard), et 5 est un littéral de type int.

Lorsque cette expression est évaluée, le compilateur recherche une fonction operator<< surchargée capable de traiter des arguments de types std::ostream et int. Il trouve une telle fonction (également définie dans la bibliothèque standard d'entrées/sorties) et l'appelle. À l'intérieur de cette fonction, std::cout est utilisé pour afficher x sur la console (la manière exacte de le faire dépend de l'implémentation). Enfin, la fonction operator<< renvoie son opérande de gauche (qui, dans ce cas, est std::cout), afin que d'autres appels à operator<< puissent être enchaînés.

Gardant cela à l'esprit, implémentons une surcharge de operator<< pour afficher un Color :

#include <iostream>
#include <string_view>

enum Color
{
    black,
    red,
    blue,
};

constexpr std::string_view getColorName(Color color)
{
    switch (color)
    {
    case black: return "black";
    case red:   return "red";
    case blue:  return "blue";
    default:    return "???";
    }
}

// Apprend à operator<< comment afficher un Color
// std::ostream est le type de std::cout, std::cerr, etc...
// Le type de retour et le type du paramètre sont des références (pour éviter la création de copies)
std::ostream& operator<<(std::ostream& out, Color color)
{
    out << getColorName(color); // affiche le nom de notre couleur sur le flux de sortie out
    return out;                 // par convention, operator<< renvoie son opérande de gauche

    // Ce qui précède peut être condensé en une seule ligne :
    // return out << getColorName(color)
}

int main()
{
    Color shirt{ blue };
    std::cout << "Your shirt is " << shirt << '\n'; // ça fonctionne !

    return 0;
}

Cela affiche :


Your shirt is blue

Détaillons un peu notre fonction d'opérateur surchargée. Tout d'abord, le nom de la fonction est operator<<, puisque c'est le nom de l'opérateur que nous surchargeons. operator<< possède deux paramètres. Le paramètre de gauche (qui sera associé à l'opérande de gauche) est notre flux de sortie, de type std::ostream. Nous utilisons ici un passage par référence non constante, car nous ne voulons pas copier un objet std::ostream lors de l'appel de la fonction, mais l'objet std::ostream doit être modifié pour pouvoir effectuer l'affichage. Le paramètre de droite (qui sera associé à l'opérande de droite) est notre objet Color. Comme operator<< renvoie par convention son opérande de gauche, le type de retour correspond au type de l'opérande de gauche, soit std::ostream&.

Examinons maintenant l'implémentation. Un objet std::ostream sait déjà afficher une std::string_view à l'aide de operator<< (cela fait partie de la bibliothèque standard). Ainsi, out << getColorName(color) récupère simplement le nom de notre couleur sous forme de std::string_view, puis l'affiche sur le flux de sortie.

Notez que notre implémentation utilise le paramètre out au lieu de std::cout, car nous voulons laisser l'appelant décider sur quel flux de sortie il écrit (par exemple, std::cerr << color doit écrire sur std::cerr, et non sur std::cout).

Renvoyer l'opérande de gauche est également simple. L'opérande de gauche est le paramètre out, il suffit donc de renvoyer out.

En résumé : lorsque nous appelons std::cout << shirt, le compilateur voit que nous avons surchargé operator<< pour travailler avec des objets de type Color. Notre fonction operator<< surchargée est alors appelée avec std::cout comme paramètre out, et notre variable shirt (dont la valeur est blue) comme paramètre color. Comme out est une référence à std::cout, et color est une copie de l'énumérateur blue, l'expression out << getColorName(color) affiche "blue" sur la console. Enfin, out est renvoyé à l'appelant, au cas où l'on voudrait enchaîner d'autres affichages.

Surcharger operator>> pour saisir un énumérateur

De la même manière que nous avons pu apprendre à operator<< à afficher une énumération ci-dessus, nous pouvons aussi apprendre à operator>> à saisir une énumération :

#include <iostream>
#include <limits>
#include <optional>
#include <string>
#include <string_view>

enum Pet
{
    cat,   // 0
    dog,   // 1
    pig,   // 2
    whale, // 3
};

constexpr std::string_view getPetName(Pet pet)
{
    switch (pet)
    {
    case cat:   return "cat";
    case dog:   return "dog";
    case pig:   return "pig";
    case whale: return "whale";
    default:    return "???";
    }
}

constexpr std::optional<Pet> getPetFromString(std::string_view sv)
{
    if (sv == "cat")   return cat;
    if (sv == "dog")   return dog;
    if (sv == "pig")   return pig;
    if (sv == "whale") return whale;

    return {};
}

// pet est un paramètre d'entrée/sortie
std::istream& operator>>(std::istream& in, Pet& pet)
{
    std::string s{};
    in >> s; // lit la chaîne saisie par l'utilisateur

    std::optional<Pet> match { getPetFromString(s) };
    if (match) // si nous avons trouvé une correspondance
    {
        pet = *match; // déréférence le std::optional pour obtenir l'énumérateur correspondant
        return in;
    }

    // Nous n'avons trouvé aucune correspondance, la saisie était donc invalide
    // Nous plaçons donc le flux d'entrée dans un état d'échec
    in.setstate(std::ios_base::failbit);

    // En cas d'échec d'extraction, operator>> initialise à zéro les types fondamentaux
    // Décommentez la ligne suivante pour que cet opérateur fasse de même
    // pet = {};

    return in;
}

int main()
{
    std::cout << "Enter a pet: cat, dog, pig, or whale: ";
    Pet pet{};
    std::cin >> pet;

    if (std::cin) // si nous avons trouvé une correspondance
        std::cout << "You chose: " << getPetName(pet) << '\n';
    else
    {
        std::cin.clear(); // remet le flux d'entrée à l'état correct
        std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
        std::cout << "Your pet was not valid\n";
    }

    return 0;
}

Il convient de noter quelques différences par rapport au cas de l'affichage. Premièrement, std::cin est de type std::istream, nous utilisons donc std::istream& comme type du paramètre de gauche et de la valeur de retour, au lieu de std::ostream&. Deuxièmement, le paramètre pet est une référence non constante. Cela permet à notre operator>> de modifier la valeur de l'opérande de droite transmis, si l'extraction aboutit à une correspondance.

Point clé

Notre opérande de droite (pet) est un paramètre de sortie. Nous abordons les paramètres de sortie dans la leçon 12.13 -- Paramètres d'entrée et de sortie.

Si pet était un paramètre passé par valeur plutôt que par référence, notre operator>> affecterait une nouvelle valeur à une copie de l'opérande de droite, et non à l'opérande de droite lui-même. Or, dans ce cas, nous voulons que l'opérande de droite soit modifié.

À l'intérieur de la fonction, nous utilisons operator>> pour lire une std::string (une opération qu'il sait déjà effectuer). Si la valeur saisie par l'utilisateur correspond à l'un de nos animaux, nous pouvons affecter à pet l'énumérateur approprié et renvoyer l'opérande de gauche (in).

Si l'utilisateur n'a pas saisi un animal valide, nous traitons ce cas en plaçant std::cin dans un « mode d'échec ». C'est l'état dans lequel std::cin se place généralement lorsqu'une extraction échoue. L'appelant peut alors vérifier std::cin pour savoir si l'extraction a réussi ou échoué.
