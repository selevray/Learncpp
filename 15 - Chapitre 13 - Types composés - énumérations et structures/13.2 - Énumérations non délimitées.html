13.2 — Énumérations non délimitées

C++ contient de nombreux types de données fondamentaux et composés utiles (que nous avons présentés dans les leçons 4.1 -- Introduction aux types de données fondamentaux et 12.1 -- Introduction aux types de données composés). Mais ces types ne suffisent pas toujours pour ce que nous voulons faire.

Par exemple, supposons que vous écriviez un programme qui doit savoir si une pomme est rouge, jaune ou verte, ou quelle est la couleur d'une chemise (parmi une liste prédéfinie de couleurs). Si seuls les types fondamentaux étaient disponibles, comment procéderiez-vous ?

Vous pourriez stocker la couleur sous forme d'une valeur entière, en utilisant une sorte de correspondance implicite (0 = rouge, 1 = vert, 2 = bleu) :

int main()
{
    int appleColor{ 0 }; // ma pomme est rouge
    int shirtColor{ 1 }; // ma chemise est verte

    return 0;
}

Mais ce n'est pas du tout intuitif, et nous avons déjà expliqué pourquoi les nombres magiques sont néfastes (5.2 -- Littéraux). Nous pouvons nous débarrasser des nombres magiques en utilisant des constantes symboliques :

constexpr int red{ 0 };
constexpr int green{ 1 };
constexpr int blue{ 2 };

int main()
{
    int appleColor{ red };
    int shirtColor{ green };

    return 0;
}

C'est un peu plus lisible, mais le programmeur doit encore deviner que appleColor et shirtColor (qui sont de type int) sont censés contenir l'une des valeurs définies dans l'ensemble des constantes symboliques de couleur (qui sont probablement définies ailleurs, sans doute dans un fichier séparé).

Nous pouvons rendre ce programme un peu plus clair en utilisant un alias de type :

using Color = int; // définit un alias de type nommé Color

// Les valeurs de couleur suivantes doivent être utilisées pour un Color
constexpr Color red{ 0 };
constexpr Color green{ 1 };
constexpr Color blue{ 2 };

int main()
{
    Color appleColor{ red };
    Color shirtColor{ green };

    return 0;
}

Nous nous rapprochons du but. Quelqu'un qui lit ce code doit encore comprendre que ces constantes symboliques de couleur sont destinées à être utilisées avec des variables de type Color, mais au moins ce type possède désormais un nom unique : quelqu'un qui cherche Color pourra trouver l'ensemble des constantes symboliques associées.

Cependant, comme Color n'est qu'un alias de int, le problème persiste : rien n'impose un usage correct de ces constantes symboliques de couleur. On peut toujours écrire :

Color eyeColor{ 8 }; // syntaxiquement valide, sémantiquement absurde

De plus, si nous déboguons l'une de ces variables avec notre débogueur, nous ne verrons que la valeur entière de la couleur (par exemple 0), et non sa signification symbolique (red), ce qui peut rendre plus difficile la vérification de l'exactitude du programme.

Heureusement, nous pouvons faire mieux.

Prenons le type bool comme inspiration. Ce qui rend bool particulièrement intéressant, c'est qu'il ne possède que deux valeurs définies : true et false. Nous pouvons utiliser true ou false directement (comme littéraux), ou instancier un objet bool qui contiendra l'une de ces deux valeurs. De plus, le compilateur sait distinguer bool des autres types. Cela signifie que nous pouvons surcharger des fonctions et personnaliser leur comportement lorsqu'elles reçoivent une valeur bool.

Si nous pouvions définir nos propres types, en définissant nous-mêmes l'ensemble des valeurs nommées associées à ce type, nous disposerions de l'outil idéal pour résoudre élégamment le problème exposé ci-dessus…

Énumérations

Une énumération (aussi appelée type énuméré ou enum) est un type de données composé dont les valeurs sont restreintes à un ensemble de constantes symboliques nommées (appelées énumérateurs).

C++ prend en charge deux sortes d'énumérations : les énumérations non délimitées (que nous allons voir maintenant) et les énumérations délimitées (que nous verrons plus tard dans ce chapitre).

Les énumérations étant des types définis par le programme 13.1 -- Introduction aux types définis par le programme (types utilisateur), chaque énumération doit être entièrement définie avant d'être utilisée (une déclaration anticipée ne suffit pas).

Énumérations non délimitées

Les énumérations non délimitées se définissent à l'aide du mot-clé enum.

Les types énumérés s'apprennent mieux par l'exemple. Définissons donc une énumération non délimitée capable de contenir quelques valeurs de couleur. Nous expliquerons ensuite son fonctionnement.

// Définit une nouvelle énumération non délimitée nommée Color
enum Color
{
    // Voici les énumérateurs
    // Ces constantes symboliques définissent toutes les valeurs que ce type peut contenir
    // Chaque énumérateur est séparé par une virgule, et non par un point-virgule
    red,
    green,
    blue, // la virgule finale est facultative mais recommandée
}; // la définition de l'énumération doit se terminer par un point-virgule

int main()
{
    // Définit quelques variables de type énuméré Color
    Color apple { red };   // ma pomme est rouge
    Color shirt { green }; // ma chemise est verte
    Color cup { blue };    // ma tasse est bleue

    Color socks { white }; // erreur : white n'est pas un énumérateur de Color
    Color hat { 2 };       // erreur : 2 n'est pas un énumérateur de Color

    return 0;
}

Nous commençons notre exemple en utilisant le mot-clé enum pour indiquer au compilateur que nous définissons une énumération non délimitée, que nous avons nommée Color.

Entre une paire d'accolades, nous définissons les énumérateurs du type Color : red, green et blue. Ces énumérateurs définissent les valeurs précises auxquelles le type Color est restreint. Chaque énumérateur doit être séparé par une virgule (et non par un point-virgule) : une virgule finale après le dernier énumérateur est facultative, mais recommandée par souci de cohérence.

Il est très courant de définir un énumérateur par ligne, mais dans les cas simples (peu d'énumérateurs et pas de commentaires nécessaires), ils peuvent tous être définis sur une seule ligne.

La définition du type Color se termine par un point-virgule. Nous avons maintenant entièrement défini le type énuméré Color !

Dans main(), nous instancions trois variables de type Color : apple est initialisée avec la couleur red, shirt avec green, et cup avec blue. De la mémoire est allouée pour chacun de ces objets. Notez que l'initialiseur d'un type énuméré doit être l'un des énumérateurs définis pour ce type. Les variables socks et hat provoquent des erreurs de compilation, car les initialiseurs white et 2 ne sont pas des énumérateurs de Color.

Les énumérateurs sont implicitement constexpr.

Petit rappel

Pour résumer la terminologie :

  • Une énumération ou type énuméré est le type défini par le programme lui-même (par exemple Color).
  • Un énumérateur est une valeur nommée précise appartenant à l'énumération (par exemple red).

Nommer les énumérations et leurs énumérateurs

Par convention, les noms des types énumérés commencent par une majuscule (comme tous les types définis par le programme).

Attention

Les énumérations n'ont pas besoin d'avoir un nom, mais les énumérations anonymes doivent être évitées en C++ moderne.

Les énumérateurs doivent aussi recevoir un nom. Malheureusement, il n'existe pas de convention de nommage commune pour les énumérateurs. Les choix courants incluent une initiale minuscule (par exemple red), une initiale majuscule (Red), tout en majuscules (RED), tout en majuscules avec un préfixe (COLOR_RED), ou un préfixe k suivi de mots en casse mixte (kColorRed).

Les recommandations du C++ moderne évitent généralement les noms entièrement en majuscules, car ces noms sont habituellement réservés aux macros du préprocesseur et peuvent entrer en conflit avec elles. Nous recommandons également d'éviter les conventions commençant par une majuscule, car les noms débutant par une majuscule sont généralement réservés aux types définis par le programme.

Bonne pratique

Nommez vos types énumérés en commençant par une majuscule. Nommez vos énumérateurs en commençant par une minuscule.

Les types énumérés sont des types distincts

Chaque type énuméré que vous créez est considéré comme un type distinct, ce qui signifie que le compilateur peut le distinguer des autres types (contrairement aux typedefs ou alias de types, qui ne sont pas distincts des types qu'ils désignent).

Comme les types énumérés sont distincts, les énumérateurs définis dans un type énuméré ne peuvent pas être utilisés avec des objets d'un autre type énuméré :

enum Pet
{
    cat,
    dog,
    pig,
    whale,
};

enum Color
{
    black,
    red,
    blue,
};

int main()
{
    Pet myPet { black }; // erreur de compilation : black n'est pas un énumérateur de Pet
    Color shirt { pig }; // erreur de compilation : pig n'est pas un énumérateur de Color

    return 0;
}

De toute façon, vous ne vouliez sans doute pas d'une chemise cochon.

Utiliser les énumérations

Les énumérateurs étant descriptifs, ils améliorent la documentation et la lisibilité du code. Les types énumérés sont particulièrement adaptés lorsque vous disposez d'un ensemble assez restreint de constantes liées entre elles, et que les objets n'ont besoin de contenir qu'une seule de ces valeurs à la fois.

Parmi les énumérations courantes figurent les jours de la semaine, les points cardinaux et les couleurs d'un jeu de cartes :

enum DaysOfWeek
{
    sunday,
    monday,
    tuesday,
    wednesday,
    thursday,
    friday,
    saturday,
};

enum CardinalDirections
{
    north,
    east,
    south,
    west,
};

enum CardSuits
{
    clubs,
    diamonds,
    hearts,
    spades,
};

Il arrive qu'une fonction renvoie à l'appelant un code d'état indiquant si son exécution s'est bien déroulée ou si une erreur s'est produite. Traditionnellement, de petits entiers négatifs servaient à représenter les différents codes d'erreur possibles. Par exemple :

int readFileContents()
{
    if (!openFile())
        return -1;
    if (!readFile())
        return -2;
    if (!parseFile())
        return -3;

    return 0; // succès
}

Cependant, utiliser des nombres magiques de cette façon n'est pas très descriptif. Une meilleure méthode consiste à utiliser un type énuméré :

enum FileReadResult
{
    readResultSuccess,
    readResultErrorFileOpen,
    readResultErrorFileRead,
    readResultErrorFileParse,
};

FileReadResult readFileContents()
{
    if (!openFile())
        return readResultErrorFileOpen;
    if (!readFile())
        return readResultErrorFileRead;
    if (!parseFile())
        return readResultErrorFileParse;

    return readResultSuccess;
}

L'appelant peut alors comparer la valeur de retour de la fonction à l'énumérateur approprié, ce qui est plus facile à comprendre que de tester une valeur entière précise.

if (readFileContents() == readResultSuccess)
{
    // faire quelque chose
}
else
{
    // afficher un message d'erreur
}

Les types énumérés sont également utiles dans les jeux vidéo, pour identifier différents types d'objets, de monstres ou de terrains. En somme, tout ce qui constitue un petit ensemble d'objets liés entre eux.

Par exemple :

enum ItemType
{
    sword,
    torch,
    potion,
};

int main()
{
    ItemType holding{ torch };

    return 0;
}

Les types énumérés peuvent aussi servir de paramètres de fonction utiles lorsque l'utilisateur doit choisir entre deux options ou plus :

enum SortOrder
{
    alphabetical,
    alphabeticalReverse,
    numerical,
};

void sortData(SortOrder order)
{
    switch (order)
    {
        case alphabetical:
            // trier les données par ordre alphabétique croissant
            break;
        case alphabeticalReverse:
            // trier les données par ordre alphabétique décroissant
            break;
        case numerical:
            // trier les données numériquement
            break;
    }
}

De nombreux langages utilisent les énumérations pour définir les booléens : après tout, un booléen n'est essentiellement qu'une énumération à 2 énumérateurs, false et true ! Cependant, en C++, true et false sont définis comme des mots-clés et non comme des énumérateurs.

Les énumérations étant petites et peu coûteuses à copier, il est tout à fait acceptable de les passer (et de les renvoyer) par valeur.

Dans la leçon O.1 -- Drapeaux de bits et manipulation de bits via std::bitset, nous avons abordé les drapeaux de bits. Les énumérations peuvent aussi servir à définir un ensemble de positions de drapeaux liées entre elles, pour une utilisation avec std::bitset :

#include <bitset>
#include <iostream>

namespace Flags
{
    enum State
    {
        isHungry,
        isSad,
        isMad,
        isHappy,
        isLaughing,
        isAsleep,
        isDead,
        isCrying,
    };
}

int main()
{
    std::bitset<8> me{};
    me.set(Flags::isHappy);
    me.set(Flags::isLaughing);

    std::cout << std::boolalpha; // affiche les bool sous forme true/false

    // Interroge quelques états (nous utilisons la fonction any() pour voir si des bits restent à 1)
    std::cout << "Je suis heureux ? " << me.test(Flags::isHappy) << '\n';
    std::cout << "Je ris ? " << me.test(Flags::isLaughing) << '\n';

    return 0;
}

Si vous vous demandez comment un énumérateur peut être utilisé là où une valeur entière est attendue, sachez que les énumérateurs des énumérations non délimitées se convertissent implicitement en valeurs entières. Nous explorerons ce point plus en détail dans la leçon suivante (13.3 -- Conversions entières des énumérateurs non délimités).

La portée des énumérations non délimitées

Les énumérations non délimitées tirent leur nom du fait que leurs énumérateurs sont placés dans la même portée que la définition de l'énumération elle-même (contrairement à un espace de noms, qui crée une nouvelle région de portée).

Par exemple, dans le programme suivant :

enum Color // cette énumération est définie dans l'espace de noms global
{
    red, // donc red est placé dans l'espace de noms global
    green,
    blue,
};

int main()
{
    Color apple { red }; // ma pomme est rouge

    return 0;
}

L'énumération Color est définie dans la portée globale. Par conséquent, tous ses noms d'énumérateurs (red, green et blue) se retrouvent également dans la portée globale. Cela pollue la portée globale et augmente considérablement le risque de collisions de noms.

Une conséquence est qu'un nom d'énumérateur ne peut pas être utilisé dans plusieurs énumérations au sein de la même portée :

enum Color
{
    red,
    green,
    blue, // blue est placé dans l'espace de noms global
};

enum Feeling
{
    happy,
    tired,
    blue, // erreur : collision de noms avec le blue ci-dessus
};

int main()
{
    Color apple { red }; // ma pomme est rouge
    Feeling me { happy }; // je suis heureux en ce moment (même si mon programme ne compile pas)

    return 0;
}

Dans l'exemple ci-dessus, les deux énumérations non délimitées (Color et Feeling) placent dans la portée globale des énumérateurs portant le même nom blue. Cela provoque une collision de noms et, par conséquent, une erreur de compilation.

Les énumérations non délimitées fournissent également une région de portée nommée pour leurs énumérateurs (à la manière d'un espace de noms qui sert de région de portée nommée aux noms qu'il déclare). Nous pouvons donc accéder aux énumérateurs d'une énumération non délimitée de la façon suivante :

enum Color
{
    red,
    green,
    blue, // blue est placé dans l'espace de noms global
};

int main()
{
    Color apple { red }; // correct, accès à l'énumérateur depuis l'espace de noms global
    Color raspberry { Color::red }; // également correct, accès à l'énumérateur depuis la portée de Color

    return 0;
}

Le plus souvent, les énumérateurs non délimités sont utilisés sans l'opérateur de résolution de portée.

Éviter les collisions de noms d'énumérateurs

Il existe plusieurs méthodes courantes pour éviter les collisions de noms d'énumérateurs non délimités.

Une première option consiste à préfixer chaque énumérateur par le nom de l'énumération elle-même :

enum Color
{
    color_red,
    color_blue,
    color_green,
};

enum Feeling
{
    feeling_happy,
    feeling_tired,
    feeling_blue, // plus de collision avec color_blue
};

int main()
{
    Color paint { color_blue };
    Feeling me { feeling_blue };

    return 0;
}

Cette méthode pollue toujours l'espace de noms, mais réduit le risque de collision en rendant les noms plus longs et plus uniques.

Une meilleure option consiste à placer le type énuméré dans une entité qui fournit une région de portée distincte, comme un espace de noms :

namespace Color
{
    // Les noms Color, red, blue et green sont définis dans l'espace de noms Color
    enum Color
    {
        red,
        green,
        blue,
    };
}

namespace Feeling
{
    enum Feeling
    {
        happy,
        tired,
        blue, // Feeling::blue n'entre pas en collision avec Color::blue
    };
}

int main()
{
    Color::Color paint{ Color::blue };
    Feeling::Feeling me{ Feeling::blue };

    return 0;
}

Il faut donc désormais préfixer les noms de l'énumération et de ses énumérateurs par le nom de la région de portée.

Pour les lecteurs avancés

Les classes fournissent elles aussi une région de portée, et il est courant de placer les types énumérés liés à une classe dans la région de portée de cette classe. Nous en parlerons dans la leçon 15.3 -- Types imbriqués (types membres).

Une option connexe consiste à utiliser une énumération délimitée (qui définit sa propre région de portée). Nous en parlerons bientôt (13.6 -- Énumérations délimitées (enum class)).

Bonne pratique

Préférez placer vos énumérations dans une région de portée nommée (comme un espace de noms ou une classe) afin que leurs énumérateurs ne polluent pas l'espace de noms global.

Par ailleurs, si une énumération n'est utilisée que dans le corps d'une seule fonction, elle doit être définie à l'intérieur de cette fonction. Cela limite la portée de l'énumération et de ses énumérateurs à cette seule fonction. Les énumérateurs d'une telle énumération masquent alors les énumérateurs de même nom définis dans la portée globale.

Comparer des valeurs aux énumérateurs

Nous pouvons utiliser les opérateurs d'égalité (operator== et operator!=) pour tester si une énumération possède la valeur d'un énumérateur donné.

#include <iostream>

enum Color
{
    red,
    green,
    blue,
};

int main()
{
    Color shirt{ blue };

    if (shirt == blue) // si la chemise est bleue
        std::cout << "Votre chemise est bleue !";
    else
        std::cout << "Votre chemise n'est pas bleue !";

    return 0;
}

Dans l'exemple ci-dessus, nous utilisons une instruction if pour tester si shirt est égal à l'énumérateur blue. Cela nous permet de conditionner le comportement du programme selon l'énumérateur que contient l'énumération.

Nous en ferons davantage usage dans la prochaine leçon.

Quiz

Question n° 1

Définissez un type énuméré non délimité nommé MonsterType permettant de choisir parmi les races de monstres suivantes : orc, goblin, troll, ogre et skeleton.

Solution 
enum MonsterType
{
    orc,
    goblin,
    troll,
    ogre,
    skeleton,
};

Question n° 2

Placez l'énumération MonsterType dans un espace de noms. Créez ensuite une fonction main() et instanciez un troll. Le programme doit compiler.

Solution 
namespace Monster
{
    enum MonsterType
    {
        orc,
        goblin,
        troll,
        ogre,
        skeleton,
    };
}

int main()
{
    // Nous utilisons [[maybe_unused]] pour éviter les avertissements concernant les variables inutilisées
    // Vous pourriez aussi afficher le monstre à la place
    [[maybe_unused]] Monster::MonsterType monster{ Monster::troll };

    return 0;
}

Comme MonsterType est une énumération non délimitée, ses énumérateurs (par exemple troll) sont placés dans l'espace de noms de l'énumération elle-même (ici namespace Monster). Nous pouvons donc accéder à troll sous la forme Monster::troll.

Comme les énumérations non délimitées placent aussi leurs énumérateurs dans leur propre région de portée, troll peut également être désigné par Monster::MonsterType::troll. Cependant, cela n'apporte aucun avantage réel.
