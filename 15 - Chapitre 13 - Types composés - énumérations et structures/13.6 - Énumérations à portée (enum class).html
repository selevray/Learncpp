13.6 — Énumérations à portée (enum class)

Bien que les énumérations sans portée soient des types distincts en C++, elles ne sont pas sûres du point de vue des types. Dans certains cas, elles permettent de faire des choses qui n'ont pas de sens. Considérons le cas suivant :

#include <iostream>

int main()
{
    enum Color
    {
        red,
        blue,
    };

    enum Fruit
    {
        banana,
        apple,
    };

    Color color { red };
    Fruit fruit { banana };

    if (color == fruit) // Le compilateur compare color et fruit comme des entiers
        std::cout << "color and fruit are equal\n"; // et constate qu'ils sont égaux !
    else
        std::cout << "color and fruit are not equal\n";

    return 0;
}

Ce programme affiche :


color and fruit are equal

Lorsque color et fruit sont comparés, le compilateur vérifie s'il sait comparer un Color avec un Fruit. Ce n'est pas le cas. Il essaie alors de convertir Color et/ou Fruit en entiers pour trouver une correspondance. Finalement, le compilateur constate que, une fois les deux convertis en entiers, la comparaison est possible. Comme color et fruit valent tous deux l'énumérateur qui se convertit en la valeur entière 0, color est égal à fruit.

Cela n'a aucun sens sur le plan sémantique, puisque color et fruit appartiennent à des énumérations différentes et ne sont pas censés être comparables. Avec les énumérateurs standard, il n'existe pas de moyen simple d'empêcher cela.

Face à ces difficultés, ainsi qu'au problème de pollution de l'espace de noms (les énumérations sans portée définies dans la portée globale placent leurs énumérateurs dans l'espace de noms global), les concepteurs du C++ ont jugé utile de disposer d'une solution plus propre pour les énumérations.

Énumérations à portée

Cette solution est l'énumération à portée (souvent appelée enum class en C++, pour des raisons qui deviendront évidentes sous peu).

Les énumérations à portée fonctionnent de façon similaire aux énumérations sans portée (13.2 -- Énumérations sans portée), mais présentent deux différences principales : elles ne se convertissent pas implicitement en entiers, et leurs énumérateurs sont placés uniquement dans la région de portée de l'énumération (et non dans la région de portée où l'énumération est définie).

Pour créer une énumération à portée, on utilise les mots-clés enum class. Le reste de la définition est identique à celui d'une énumération sans portée. Voici un exemple :

#include <iostream>
int main()
{
    enum class Color // "enum class" définit une énumération à portée plutôt qu'une énumération sans portée
    {
        red, // red fait partie de la région de portée de Color
        blue,
    };

    enum class Fruit
    {
        banana, // banana fait partie de la région de portée de Fruit
        apple,
    };

    Color color { Color::red }; // remarque : red n'est pas directement accessible, il faut utiliser Color::red
    Fruit fruit { Fruit::banana }; // remarque : banana n'est pas directement accessible, il faut utiliser Fruit::banana

    if (color == fruit) // erreur de compilation : le compilateur ne sait pas comparer les types différents Color et Fruit
        std::cout << "color and fruit are equal\n";
    else
        std::cout << "color and fruit are not equal\n";

    return 0;
}

Ce programme produit une erreur de compilation à la ligne 19, car l'énumération à portée ne se convertit vers aucun type pouvant être comparé à un autre type.

En passant…

Le mot-clé class (ainsi que le mot-clé static) est l'un des mots-clés les plus surchargés du langage C++ : il peut avoir des significations différentes selon le contexte. Bien que les énumérations à portée utilisent le mot-clé class, elles ne sont pas considérées comme un « type classe » (réservé aux structures, classes et unions).

enum struct fonctionne aussi dans ce contexte et se comporte exactement comme enum class. Cependant, l'usage de enum struct n'est pas idiomatique ; évitez-le.

Les énumérations à portée définissent leur propre région de portée

Contrairement aux énumérations sans portée, qui placent leurs énumérateurs dans la même portée que l'énumération elle-même, les énumérations à portée placent leurs énumérateurs uniquement dans la région de portée de l'énumération. En d'autres termes, les énumérations à portée agissent comme un espace de noms pour leurs énumérateurs. Cette séparation intégrée aide à réduire la pollution de l'espace de noms global et les risques de conflits de noms lorsque ces énumérations sont utilisées dans la portée globale.

Pour accéder à un énumérateur d'une énumération à portée, on procède comme s'il appartenait à un espace de noms portant le même nom que l'énumération :

#include <iostream>

int main()
{
    enum class Color // "enum class" définit une énumération à portée plutôt qu'une énumération sans portée
    {
        red, // red fait partie de la région de portée de Color
        blue,
    };

    std::cout << red << '\n';        // erreur de compilation : red n'est pas défini dans cette région de portée
    std::cout << Color::red << '\n'; // erreur de compilation : std::cout ne sait pas afficher ceci (pas de conversion implicite en int)

    Color color { Color::blue }; // correct

    return 0;
}

Comme les énumérations à portée offrent leur propre espace de noms implicite pour leurs énumérateurs, il n'est pas nécessaire de placer une énumération à portée dans une autre région de portée (comme un espace de noms), sauf raison impérieuse, car cela serait redondant.

Les énumérations à portée ne se convertissent pas implicitement en entiers

Contrairement aux énumérateurs sans portée, les énumérateurs à portée ne se convertissent pas implicitement en entiers. Dans la plupart des cas, c'est une bonne chose, car cette conversion a rarement un sens et permet d'éviter des erreurs sémantiques, comme comparer des énumérateurs de jeux d'énumérations différents, ou écrire des expressions telles que red + 5.

Notez que vous pouvez tout de même comparer des énumérateurs appartenant à la même énumération à portée (puisqu'ils sont du même type) :

#include <iostream>
int main()
{
    enum class Color
    {
        red,
        blue,
    };

    Color shirt { Color::red };

    if (shirt == Color::red) // cette comparaison Color à Color est correcte
        std::cout << "The shirt is red!\n";
    else if (shirt == Color::blue)
        std::cout << "The shirt is blue!\n";

    return 0;
}

Il arrive parfois qu'il soit utile de traiter un énumérateur à portée comme une valeur entière. Dans ce cas, vous pouvez convertir explicitement un énumérateur à portée en entier à l'aide d'un static_cast. Depuis C++23, un meilleur choix consiste à utiliser std::to_underlying() (défini dans l'en-tête <utility>), qui convertit un énumérateur en une valeur de type sous-jacent de l'énumération.

#include <iostream>
#include <utility> // pour std::to_underlying() (C++23)

int main()
{
    enum class Color
    {
        red,
        blue,
    };

    Color color { Color::blue };

    std::cout << color << '\n'; // ne fonctionne pas, car il n'y a pas de conversion implicite en int
    std::cout << static_cast<int>(color) << '\n';   // conversion explicite en int, affichera 1
    std::cout << std::to_underlying(color) << '\n'; // conversion vers le type sous-jacent, affichera 1 (C++23)

    return 0;
}

Inversement, vous pouvez aussi utiliser static_cast pour convertir un entier en énumérateur à portée, ce qui peut être utile lors de la saisie utilisateur :

#include <iostream>

int main()
{
    enum class Pet
    {
        cat, // reçoit 0
        dog, // reçoit 1
        pig, // reçoit 2
        whale, // reçoit 3
    };

    std::cout << "Enter a pet (0=cat, 1=dog, 2=pig, 3=whale): ";

    int input{};
    std::cin >> input; // saisie d'un entier

    Pet pet{ static_cast<Pet>(input) }; // conversion de notre entier en Pet par static_cast

    return 0;
}

Depuis C++17, vous pouvez initialiser une énumération à portée par liste à l'aide d'une valeur entière, sans static_cast (et, contrairement à une énumération sans portée, vous n'avez pas besoin de spécifier de type de base) :

   // utilise enum class Pet de l'exemple précédent
   Pet pet { 1 }; // correct

Bonne pratique

Privilégiez les énumérations à portée aux énumérations sans portée, sauf raison impérieuse de faire autrement.

Malgré les avantages qu'offrent les énumérations à portée, les énumérations sans portée restent couramment utilisées en C++, car il existe des situations où l'on souhaite la conversion implicite en int (multiplier les static_cast devient vite pénible) et où l'espace de noms supplémentaire n'est pas nécessaire.

Faciliter la conversion des énumérateurs à portée en entiers (avancé)

Les énumérations à portée sont très utiles, mais l'absence de conversion implicite en entiers peut parfois être gênante. Si nous devons convertir souvent une énumération à portée en entiers (par exemple lorsque nous voulons utiliser des énumérateurs à portée comme indices de tableau), écrire static_cast à chaque conversion peut alourdir considérablement le code.

Si vous vous trouvez dans une telle situation et souhaitez faciliter la conversion des énumérateurs à portée en entiers, une astuce utile consiste à surcharger l'opérateur unaire operator+ pour effectuer cette conversion :

#include <iostream>
#include <type_traits> // pour std::underlying_type_t

enum class Animals
{
    chicken, // 0
    dog, // 1
    cat, // 2
    elephant, // 3
    duck, // 4
    snake, // 5

    maxAnimals,
};

// Surcharge de l'opérateur unaire + pour convertir une énumération en son type sous-jacent
// adapté de https://stackoverflow.com/a/42198760, merci à Pixelchemist pour l'idée
// En C++23, vous pouvez #include <utility> et renvoyer std::to_underlying(a) à la place
template <typename T>
constexpr auto operator+(T a) noexcept
{
    return static_cast<std::underlying_type_t<T>>(a);
}

int main()
{
    std::cout << +Animals::elephant << '\n'; // convertit Animals::elephant en entier à l'aide de l'opérateur unaire +

    return 0;
}

Ce programme affiche :


3

Cette méthode empêche les conversions implicites non voulues vers un type entier, tout en offrant un moyen pratique de demander explicitement ces conversions lorsque c'est nécessaire.

Instructions using enum (C++20)

Introduite en C++20, l'instruction using enum importe tous les énumérateurs d'une énumération dans la portée courante. Appliquée à un type enum class, elle nous permet d'accéder à ses énumérateurs sans avoir à faire précéder chacun du nom de l'énumération.

Cela peut être utile lorsque nous aurions autrement de nombreux préfixes identiques et répétés, par exemple dans une instruction switch :

#include <iostream>
#include <string_view>

enum class Color
{
    black,
    red,
    blue,
};

constexpr std::string_view getColor(Color color)
{
    using enum Color; // importe tous les énumérateurs de Color dans la portée courante (C++20)
    // Nous pouvons maintenant accéder aux énumérateurs de Color sans le préfixe Color::

    switch (color)
    {
    case black: return "black"; // remarque : black au lieu de Color::black
    case red:   return "red";
    case blue:  return "blue";
    default:    return "???";
    }
}

int main()
{
    Color shirt{ Color::blue };

    std::cout << "Your shirt is " << getColor(shirt) << '\n';

    return 0;
}

Dans l'exemple ci-dessus, Color est une enum class ; nous devrions donc normalement accéder à ses énumérateurs par leur nom complet (par exemple Color::blue). Cependant, dans la fonction getColor(), nous avons ajouté l'instruction using enum Color;, qui nous permet d'accéder à ces énumérateurs sans le préfixe Color::.

Cela nous évite des préfixes multiples, redondants et évidents à l'intérieur de l'instruction switch.

Quiz

Question n° 1

Définissez une enum class nommée Animal qui contient les animaux suivants : pig, chicken, goat, cat, dog, duck. Écrivez une fonction nommée getAnimalName() qui prend un paramètre Animal et utilise une instruction switch pour renvoyer le nom de cet animal sous forme de std::string_view (ou de std::string si vous utilisez C++14). Écrivez une autre fonction nommée printNumberOfLegs() qui utilise une instruction switch pour afficher le nombre de pattes sur lesquelles chaque animal marche. Assurez-vous que les deux fonctions possèdent un cas default qui affiche un message d'erreur. Appelez printNumberOfLegs() depuis main() avec un cat et un chicken. Votre sortie doit ressembler à ceci :


A cat has 4 legs.
A chicken has 2 legs.
Solution 
#include <iostream>
#include <string_view> // C++17
//#include <string> // pour C++14

enum class Animal
{
    pig,
    chicken,
    goat,
    cat,
    dog,
    duck,
};

constexpr std::string_view getAnimalName(Animal animal) // C++17
// const std::string getAnimalName(Animal animal) // C++14
{
    // Si vous êtes en C++20, vous pouvez utiliser `using enum Animal` ici pour réduire la redondance du préfixe Animal
    switch (animal)
    {
        case Animal::chicken:
            return "chicken";
        case Animal::duck:
            return "duck";
        case Animal::pig:
            return "pig";
        case Animal::goat:
            return "goat";
        case Animal::cat:
            return "cat";
        case Animal::dog:
            return "dog";

        default:
            return "???";
    }
}

void printNumberOfLegs(Animal animal)
{
    std::cout << "A " << getAnimalName(animal) << " has ";

    // Si vous êtes en C++20, vous pouvez utiliser `using enum Animal` ici pour réduire la redondance du préfixe Animal
    switch (animal)
    {
        case Animal::chicken:
        case Animal::duck:
            std::cout << 2;
            break;

        case Animal::pig:
        case Animal::goat:
        case Animal::cat:
        case Animal::dog:
            std::cout << 4;
            break;

        default:
            std::cout << "???";
            break;
    }

    std::cout << " legs.\n";
}

int main()
{
    printNumberOfLegs(Animal::cat);
    printNumberOfLegs(Animal::chicken);

    return 0;
}
