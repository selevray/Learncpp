2.5 — Introduction à la portée locale

Variables locales

Les variables définies à l'intérieur du corps d'une fonction sont appelées variables locales (par opposition aux variables globales, que nous verrons dans un chapitre ultérieur) :

int add(int x, int y)
{
    int z{ x + y }; // z est une variable locale

    return z;
}

Les paramètres de fonction sont également considérés en général comme des variables locales, et nous les inclurons dans cette catégorie :

int add(int x, int y) // les paramètres de fonction x et y sont des variables locales
{
    int z{ x + y };

    return z;
}

Dans cette leçon, nous allons examiner plus en détail certaines propriétés des variables locales.

Durée de vie d'une variable locale

Dans la leçon 1.3 -- Introduction aux objets et aux variables, nous avons vu qu'une définition de variable telle que int x; entraîne l'instanciation de la variable lorsque cette instruction est exécutée. Les paramètres de fonction sont créés et initialisés lors de l'entrée dans la fonction, et les variables du corps de la fonction sont créées et initialisées au point de leur définition.

Par exemple :

int add(int x, int y) // x et y sont créés et initialisés ici
{
    int z{ x + y };   // z est créé et initialisé ici

    return z;
}

La question qui vient naturellement est : « quand une variable instanciée est-elle détruite ? » Les variables locales sont détruites dans l'ordre inverse de leur création, à la fin du bloc d'accolades dans lequel elles sont définies (ou, pour un paramètre de fonction, à la fin de la fonction).

int add(int x, int y)
{
    int z{ x + y };

    return z;
} // z, y et x sont détruits ici

De même que la durée de vie d'une personne s'étend de sa naissance à sa mort, la durée de vie (lifetime) d'un objet s'étend de sa création à sa destruction. Notez que la création et la destruction des variables ont lieu pendant l'exécution du programme (on parle de runtime), et non à la compilation. La durée de vie est donc une propriété d'exécution.

Pour les lecteurs avancés

Les règles ci-dessus concernant la création, l'initialisation et la destruction sont des garanties. Autrement dit, les objets doivent être créés et initialisés au plus tard au point de leur définition, et détruits au plus tôt à la fin du bloc d'accolades dans lequel ils sont définis (ou, pour les paramètres de fonction, à la fin de la fonction).

En réalité, la spécification du C++ laisse aux compilateurs une grande latitude pour déterminer le moment où les variables locales sont créées et détruites. Les objets peuvent être créés plus tôt, ou détruits plus tard, à des fins d'optimisation. Le plus souvent, les variables locales sont créées à l'entrée de la fonction et détruites, dans l'ordre inverse de leur création, à la sortie de celle-ci. Nous reviendrons sur ce point en détail dans une leçon ultérieure, lorsque nous parlerons de la pile d'appels (call stack).

Voici un programme un peu plus complexe qui illustre la durée de vie d'une variable nommée x :

#include <iostream>

void doSomething()
{
    std::cout << "Hello!\n";
}

int main()
{
    int x{ 0 };    // la durée de vie de x commence ici

    doSomething(); // x est toujours en vie pendant cet appel de fonction

    return 0;
} // la durée de vie de x se termine ici

Dans le programme ci-dessus, la durée de vie de x s'étend du point de sa définition jusqu'à la fin de la fonction main. Cela inclut le temps d'exécution de la fonction doSomething.

Que se passe-t-il lorsqu'un objet est détruit ?

Dans la plupart des cas, rien. L'objet détruit devient simplement invalide.

Pour les lecteurs avancés

Si l'objet est d'un type classe, une fonction spéciale appelée destructeur (destructor) est invoquée avant sa destruction. Dans de nombreux cas, le destructeur ne fait rien, auquel cas aucun coût n'est engendré. Nous présentons les destructeurs dans la leçon 15.4 -- Introduction aux destructeurs.

Toute utilisation d'un objet après sa destruction entraîne un comportement indéfini.

À un moment donné après la destruction, la mémoire utilisée par l'objet sera désallouée (libérée pour être réutilisée).

Portée locale (portée de bloc)

La portée (scope) d'un identifiant détermine les endroits du code source où cet identifiant est visible et utilisable. Lorsqu'un identifiant est visible et utilisable, on dit qu'il est dans la portée (in scope). Lorsqu'un identifiant n'est pas visible, on ne peut pas l'utiliser, et on dit qu'il est hors de portée (out of scope). La portée est une propriété de compilation, et tenter d'utiliser un identifiant hors de sa portée produit une erreur de compilation.

L'identifiant d'une variable locale a une portée locale. Un identifiant de portée locale (techniquement appelée portée de bloc, block scope) est utilisable depuis le point de sa définition jusqu'à la fin du bloc d'accolades le plus interne contenant cet identifiant (ou, pour un paramètre de fonction, jusqu'à la fin de la fonction). Cela garantit qu'une variable locale ne peut pas être utilisée avant son point de définition (même si le compilateur choisit de la créer plus tôt) ni après sa destruction. Les variables locales définies dans une fonction ne sont pas non plus visibles dans les autres fonctions appelées.

Voici un programme qui illustre la portée d'une variable nommée x :

#include <iostream>

// x n'est dans la portée nulle part dans cette fonction
void doSomething()
{
    std::cout << "Hello!\n";
}

int main()
{
    // x ne peut pas être utilisé ici car il n'est pas encore dans la portée

    int x{ 0 }; // x entre dans la portée ici et peut maintenant être utilisé dans cette fonction

    doSomething();

    return 0;
} // x sort de la portée ici et ne peut plus être utilisé

Dans le programme ci-dessus, la variable x entre dans la portée au point de sa définition. x sort de la portée à la fin du bloc d'accolades le plus interne contenant l'identifiant, c'est-à-dire l'accolade fermante de la fonction main(). Notez que la variable x n'est dans la portée nulle part à l'intérieur de la fonction doSomething. Le fait que la fonction main appelle la fonction doSomething n'a aucune importance dans ce contexte.

« Hors de portée » ou « sortir de la portée »

Les expressions « hors de portée » et « sortir de la portée » peuvent prêter à confusion pour les programmeurs débutants.

Un identifiant est hors de portée partout où il ne peut pas être accédé dans le code. Dans l'exemple ci-dessus, l'identifiant x est dans la portée depuis son point de définition jusqu'à la fin de la fonction main. L'identifiant x est hors de portée en dehors de cette zone de code.

L'expression « sortir de la portée » s'applique en général aux objets plutôt qu'aux identifiants. On dit qu'un objet sort de la portée à la fin de la portée (l'accolade fermante) dans laquelle il a été instancié. Dans l'exemple ci-dessus, l'objet nommé x sort de la portée à la fin de la fonction main.

La durée de vie d'une variable locale prend fin au moment où elle sort de la portée ; c'est donc à ce moment qu'elle est détruite.

Notez que tous les types de variables ne sont pas détruits lorsqu'ils sortent de la portée. Nous verrons des exemples de ces cas dans des leçons ultérieures.

Un autre exemple

Voici un exemple un peu plus complexe. Rappelez-vous que la durée de vie est une propriété d'exécution, et que la portée est une propriété de compilation ; bien que nous parlions des deux dans le même programme, elles s'appliquent à des moments différents.

#include <iostream>

int add(int x, int y) // x et y sont créés et entrent dans la portée ici
{
    // x et y ne sont utilisables que dans add()
    return x + y;
} // y et x sortent de la portée et sont détruits ici

int main()
{
    int a{ 5 }; // a est créé, initialisé et entre dans la portée ici
    int b{ 6 }; // b est créé, initialisé et entre dans la portée ici

    // a et b ne sont utilisables que dans main()

    std::cout << add(a, b) << '\n'; // appelle add(5, 6), avec x=5 et y=6

    return 0;
} // b et a sortent de la portée et sont détruits ici

Les paramètres x et y sont créés lorsque la fonction add est appelée, ne peuvent être vus et utilisés que dans la fonction add, et sont détruits à la fin de add. Les variables a et b sont créées dans la fonction main, ne peuvent être vues et utilisées que dans la fonction main, et sont détruites à la fin de main.

Pour mieux comprendre comment tout cela s'articule, suivons ce programme un peu plus en détail. Les événements suivants se produisent, dans cet ordre :

  • L'exécution commence au début de main.
  • La variable a de main est créée et reçoit la valeur 5.
  • La variable b de main est créée et reçoit la valeur 6.
  • La fonction add est appelée avec les valeurs d'arguments 5 et 6.
  • Les paramètres x et y de add sont créés et initialisés avec les valeurs 5 et 6 respectivement.
  • L'expression x + y est évaluée et produit la valeur 11.
  • add copie la valeur 11 vers l'appelant main.
  • Les paramètres y et x de add sont détruits.
  • main affiche 11 dans la console.
  • main renvoie 0 au système d'exploitation.
  • Les variables b et a de main sont détruites.

Et voilà, c'est terminé.

Notez que si la fonction add était appelée deux fois, ses paramètres x et y seraient créés et détruits deux fois, une fois pour chaque appel. Dans un programme comportant de nombreuses fonctions et de nombreux appels de fonctions, les variables sont créées et détruites très souvent.

Séparation fonctionnelle

Dans l'exemple ci-dessus, il est facile de voir que les variables a et b sont différentes des variables x et y.

Considérons maintenant le programme suivant, très similaire :

#include <iostream>

int add(int x, int y) // x et y de add sont créés et entrent dans la portée ici
{
    // x et y de add sont visibles et utilisables uniquement dans cette fonction
    return x + y;
} // y et x de add sortent de la portée et sont détruits ici

int main()
{
    int x{ 5 }; // x de main est créé, initialisé et entre dans la portée ici
    int y{ 6 }; // y de main est créé, initialisé et entre dans la portée ici

    // x et y de main ne sont utilisables que dans cette fonction
    std::cout << add(x, y) << '\n'; // appelle la fonction add() avec x=5 et y=6

    return 0;
} // y et x de main sortent de la portée et sont détruits ici

Dans cet exemple, nous avons simplement changé le nom des variables a et b de la fonction main en x et y. Ce programme se compile et s'exécute de la même manière, bien que les fonctions main et add aient toutes deux des variables nommées x et y. Pourquoi cela fonctionne-t-il ?

Tout d'abord, il faut reconnaître que, même si les fonctions main et add ont toutes deux des variables nommées x et y, ces variables sont distinctes. Les x et y de la fonction main n'ont rien à voir avec les x et y de la fonction add : ils portent simplement les mêmes noms.

Ensuite, à l'intérieur de la fonction main, les noms x et y désignent les variables locales x et y de main. Ces variables ne sont visibles (et utilisables) qu'à l'intérieur de main. De même, à l'intérieur de la fonction add, les noms x et y désignent les paramètres de fonction x et y, qui ne sont visibles (et utilisables) qu'à l'intérieur de add.

En bref, ni add ni main ne savent que l'autre fonction possède des variables portant les mêmes noms. Comme les portées ne se chevauchent pas, le compilateur sait toujours à tout moment à quels x et y on fait référence.

Point clé

Les noms des paramètres de fonction ou des variables déclarées dans le corps d'une fonction ne sont visibles qu'à l'intérieur de la fonction qui les déclare. Cela signifie que les variables locales d'une fonction peuvent être nommées sans tenir compte des noms des variables des autres fonctions. Cela contribue à maintenir l'indépendance des fonctions.

Nous reparlerons de la portée locale, ainsi que des autres types de portée, dans un chapitre ultérieur.

Où définir les variables locales

En C++ moderne, la bonne pratique consiste à définir les variables locales du corps d'une fonction le plus près possible de leur première utilisation :

#include <iostream>

int main()
{
    std::cout << "Enter an integer: ";
    int x{};       // x est défini ici
    std::cin >> x; // et utilisé ici

    std::cout << "Enter another integer: ";
    int y{};       // y est défini ici
    std::cin >> y; // et utilisé ici

    int sum{ x + y }; // sum peut être initialisé avec la valeur voulue
    std::cout << "The sum is: " << sum << '\n';

    return 0;
}

Dans l'exemple ci-dessus, chaque variable est définie juste avant sa première utilisation. Il n'est pas nécessaire d'être trop strict à ce sujet : si vous préférez inverser les lignes 5 et 6, c'est tout à fait acceptable.

Bonne pratique

Définissez vos variables locales le plus près possible de leur première utilisation.

En passant…

En raison des limitations des compilateurs plus anciens et plus rudimentaires, le langage C exigeait autrefois que toutes les variables locales soient définies en haut de la fonction. Le programme C++ équivalent dans ce style ressemblerait à ceci :

#include <iostream>

int main()
{
    int x{}, y{}, sum{}; // comment sont-elles utilisées ?

    std::cout << "Enter an integer: ";
    std::cin >> x;

    std::cout << "Enter another integer: ";
    std::cin >> y;

    sum = x + y;
    std::cout << "The sum is: " << sum << '\n';

    return 0;
}

Ce style est sous-optimal pour plusieurs raisons :

  • L'usage prévu de ces variables n'est pas apparent au point de leur définition. Il faut parcourir toute la fonction pour déterminer où et comment chaque variable est utilisée.
  • La valeur d'initialisation prévue n'est peut-être pas disponible en haut de la fonction (par exemple, nous ne pouvons pas initialiser sum à sa valeur prévue, car nous ne connaissons pas encore les valeurs de x et y).
  • Il peut y avoir de nombreuses lignes entre l'initialisation d'une variable et sa première utilisation. Si nous ne nous souvenons plus de la valeur d'initialisation, il faut remonter en haut de la fonction, ce qui est fastidieux.

Cette restriction a été levée dans la norme C99.

Quand utiliser des paramètres de fonction ou des variables locales

Comme les paramètres de fonction et les variables locales peuvent tous deux être utilisés dans le corps d'une fonction, les programmeurs débutants ont parfois du mal à comprendre quand utiliser l'un ou l'autre. Un paramètre de fonction doit être utilisé lorsque l'appelant va fournir la valeur d'initialisation sous forme d'argument. Dans le cas contraire, on utilise une variable locale.

Utiliser un paramètre de fonction alors qu'une variable locale serait appropriée conduit à un code de ce type :

#include <iostream>

int getValueFromUser(int val) // val est un paramètre de fonction
{
    std::cout << "Enter a value: ";
    std::cin >> val;
    return val;
}

int main()
{
    int x {};
    int num { getValueFromUser(x) }; // main doit passer x comme argument

    std::cout << "You entered " << num << '\n';

    return 0;
}

Dans l'exemple ci-dessus, getValueFromUser() a défini val comme paramètre de fonction. Par conséquent, main() doit définir x afin de disposer de quelque chose à passer en argument. Cependant, la valeur réelle de x n'est jamais utilisée, et la valeur avec laquelle val est initialisé n'est jamais utilisée non plus. Obliger l'appelant à définir et passer une variable qui n'est jamais utilisée ajoute une complexité inutile.

La bonne façon d'écrire ce code est la suivante :

#include <iostream>

int getValueFromUser()
{
    int val {}; // val est une variable locale
    std::cout << "Enter a value: ";
    std::cin >> val;
    return val;
}

int main()
{
    int num { getValueFromUser() }; // main n'a rien besoin de passer

    std::cout << "You entered " << num << '\n';

    return 0;
}

Dans cet exemple, val est désormais une variable locale. main() est plus simple, car il n'a pas besoin de définir ni de passer une variable pour appeler getValueFromUser().

Bonne pratique

Lorsqu'une variable est nécessaire à l'intérieur d'une fonction :

  • Utilisez un paramètre de fonction lorsque l'appelant fournira la valeur d'initialisation de la variable sous forme d'argument.
  • Utilisez une variable locale dans le cas contraire.

Introduction aux objets temporaires

Un objet temporaire (parfois appelé aussi objet anonyme) est un objet sans nom, utilisé pour contenir une valeur qui n'est nécessaire que pendant une courte période. Les objets temporaires sont générés par le compilateur lorsque c'est nécessaire.

Il existe de nombreuses façons de créer des valeurs temporaires, mais en voici une courante :

#include <iostream>

int getValueFromUser()
{
    std::cout << "Enter an integer: ";
    int input{};
    std::cin >> input;

    return input; // renvoie la valeur de input à l'appelant
}

int main()
{
    std::cout << getValueFromUser() << '\n'; // où la valeur renvoyée est-elle stockée ?

    return 0;
}

Dans le programme ci-dessus, la fonction getValueFromUser() renvoie à l'appelant la valeur stockée dans la variable locale input. Comme input sera détruite à la fin de la fonction, l'appelant reçoit une copie de la valeur, afin de disposer d'une valeur utilisable même après la destruction de input.

Mais où est stockée la valeur copiée vers l'appelant ? Nous n'avons défini aucune variable dans main(). La réponse est que la valeur de retour est stockée dans un objet temporaire. Cet objet temporaire est ensuite passé à std::cout pour être affiché.

Point clé

Le retour par valeur renvoie à l'appelant un objet temporaire (contenant une copie de la valeur de retour).

Les objets temporaires n'ont pas du tout de portée (cela a du sens, puisque la portée est une propriété d'un identifiant, et que les objets temporaires n'ont pas d'identifiant).

Les objets temporaires sont détruits à la fin de l'expression complète dans laquelle ils sont créés. Cela signifie que les objets temporaires sont toujours détruits avant l'exécution de l'instruction suivante.

Dans notre exemple ci-dessus, l'objet temporaire créé pour contenir la valeur de retour de getValueFromUser() est détruit après l'exécution de std::cout << getValueFromUser() << '\n'.

Lorsqu'un objet temporaire sert à initialiser une variable, l'initialisation a lieu avant la destruction du temporaire.

En C++ moderne (en particulier depuis C++17), le compilateur dispose de nombreuses astuces pour éviter de générer des temporaires là où il aurait autrefois été obligé de le faire. Par exemple, lorsque nous utilisons une valeur de retour pour initialiser une variable, cela entraînerait normalement la création d'un temporaire contenant la valeur de retour, puis l'utilisation de ce temporaire pour initialiser la variable. Cependant, en C++ moderne, le compilateur évite souvent de créer le temporaire et initialise directement la variable avec la valeur de retour.

De même, dans l'exemple ci-dessus, comme la valeur de retour de getValueFromUser() est affichée immédiatement, le compilateur peut éviter la création et la destruction du temporaire dans main(), et utiliser directement la valeur de retour de getValueFromUser() pour initialiser le paramètre de operator<<.

Quiz

Question n° 1

Qu'affiche le programme suivant ?

#include <iostream>

void doIt(int x)
{
    int y{ 4 };
    std::cout << "doIt: x = " << x << " y = " << y << '\n';

    x = 3;
    std::cout << "doIt: x = " << x << " y = " << y << '\n';
}

int main()
{
    int x{ 1 };
    int y{ 2 };

    std::cout << "main: x = " << x << " y = " << y << '\n';

    doIt(x);

    std::cout << "main: x = " << x << " y = " << y << '\n';

    return 0;
}
Solution 

main: x = 1 y = 2
doIt: x = 1 y = 4
doIt: x = 3 y = 4
main: x = 1 y = 2

Voici ce qui se passe dans ce programme :

  • l'exécution commence au début de main
  • la variable x de main est créée et initialisée avec la valeur 1
  • la variable y de main est créée et initialisée avec la valeur 2
  • std::cout affiche main: x = 1 y = 2
  • doIt est appelée avec l'argument 1
  • le paramètre x de doIt est créé et initialisé avec la valeur 1
  • la variable y de doIt est créée et initialisée avec la valeur 4
  • doIt affiche doIt: x = 1 y = 4
  • la variable x de doIt reçoit la nouvelle valeur 3
  • std::cout affiche doIt: x = 3 y = 4
  • y et x de doIt sont détruits
  • std::cout affiche main: x = 1 y = 2
  • main renvoie 0 au système d'exploitation
  • y et x de main sont détruits

Notez que, même si les variables x et y de doIt ont reçu une valeur d'initialisation ou d'affectation différente de celles de main, les x et y de main n'ont pas été modifiés, car ce sont des variables différentes.
