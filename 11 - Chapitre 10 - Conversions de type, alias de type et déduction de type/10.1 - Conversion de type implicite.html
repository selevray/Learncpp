10.1 — Conversion de type implicite

Nous avons introduit la conversion de type dans la leçon 4.12 -- Introduction à la conversion de type et static_cast. Pour rappeler les points les plus importants de cette leçon :

  • Le processus de conversion de données d'un type vers un autre type est appelé « conversion de type ».
  • La conversion de type implicite est effectuée automatiquement par le compilateur lorsqu'un type de données est requis, mais qu'un autre type de données est fourni.
  • La conversion de type explicite est demandée à l'aide d'un opérateur de conversion, tel que static_cast.
  • Les conversions ne modifient pas les données converties. Le processus de conversion utilise plutôt ces données en entrée et produit le résultat converti.
  • Lorsqu'une valeur est convertie vers un autre type de valeur, le processus de conversion produit un objet temporaire du type cible, qui contient le résultat de la conversion.

Dans la première moitié de ce chapitre, nous allons approfondir le fonctionnement de la conversion de type. Nous commencerons par les conversions implicites dans cette leçon, puis nous verrons les conversions de type explicites (transtypage) dans la prochaine leçon 10.6 -- Conversion de type explicite (transtypage) et static_cast. Comme la conversion de type est utilisée partout, il est important de comprendre ce qui se passe en coulisses lorsqu'une conversion est nécessaire. Ces connaissances sont également utiles pour comprendre le fonctionnement des fonctions surchargées (fonctions pouvant porter le même nom que d'autres fonctions).

Note de l'auteur

Dans ce chapitre, nous nous concentrerons sur la conversion de valeurs vers d'autres types de valeurs. Nous aborderons les autres types de conversions une fois que nous aurons présenté les sujets préalables (tels que les pointeurs, les références, l'héritage, etc.).

Pourquoi des conversions sont nécessaires

La valeur d'un objet est stockée sous la forme d'une suite de bits, et le type de données de l'objet indique au compilateur comment interpréter ces bits pour en tirer des valeurs significatives. Des types de données différents peuvent représenter une même « valeur » de façons différentes. Par exemple, la valeur entière 3 peut être stockée sous la forme binaire 0000 0000 0000 0000 0000 0000 0000 0011, tandis que la valeur à virgule flottante 3.0 peut être stockée sous la forme binaire 0100 0000 0100 0000 0000 0000 0000 0000.

Que se passe-t-il donc lorsque nous écrivons ceci ?

float f{ 3 }; // initialise une variable à virgule flottante avec l'entier 3

Dans ce cas, le compilateur ne peut pas simplement copier les bits utilisés pour représenter l'int 3 dans la mémoire allouée à la variable float f. S'il le faisait, lorsque f (de type float) serait évaluée, ces bits seraient interprétés comme un float et non comme un int, et Dieu sait quelle valeur float nous obtiendrions !

En passant…

Le programme suivant affiche en réalité la valeur int 3 comme si elle était un float :

#include <iostream>
#include <cstring>

int main()
{
    int n { 3 };                        // voici la valeur int 3
    float f {};                         // voici notre variable float
    std::memcpy(&f, &n, sizeof(float)); // copie les bits de n dans f
    std::cout << f << '\n';             // affiche f (contenant les bits de n)

    return 0;
}

Ce programme produit le résultat suivant :


4.2039e-45

Il faut donc plutôt convertir la valeur entière 3 en la valeur à virgule flottante équivalente 3.0, qui peut alors être stockée dans la mémoire allouée à f (en utilisant la représentation binaire du float 3.0).

Quand une conversion de type implicite se produit

La conversion de type implicite (également appelée conversion de type automatique ou coercition) est effectuée automatiquement par le compilateur lorsqu'une expression d'un certain type est fournie dans un contexte où un autre type est attendu. La grande majorité des conversions de type en C++ sont des conversions implicites. Par exemple, une conversion implicite se produit dans tous les cas suivants :

Lors de l'initialisation (ou de l'affectation d'une valeur) d'une variable avec une valeur d'un type de données différent :

double d{ 3 }; // la valeur int 3 est convertie implicitement en double
d = 6; // la valeur int 6 est convertie implicitement en double

Lorsque le type d'une valeur de retour est différent du type de retour déclaré de la fonction :

float doSomething()
{
    return 3.0; // la valeur double 3.0 est convertie implicitement en float
}

Lors de l'utilisation de certains opérateurs binaires avec des opérandes de types différents :

double division{ 4.0 / 3 }; // la valeur int 3 est convertie implicitement en double

Lors de l'utilisation d'une valeur non booléenne dans une instruction if :

if (5) // la valeur int 5 est convertie implicitement en bool
{
}

Lorsqu'un argument passé à une fonction est d'un type différent de celui du paramètre de la fonction :

void doSomething(long l)
{
}

doSomething(3); // la valeur int 3 est convertie implicitement en long

Les conversions standard

Dans le cadre du langage de base, la norme C++ définit un ensemble de règles de conversion appelées « conversions standard ». Les conversions standard précisent comment les différents types fondamentaux (ainsi que certains types composés, notamment les tableaux, les références, les pointeurs et les énumérations) se convertissent vers d'autres types du même groupe.

En C++23, il existe 14 conversions standard différentes. Elles peuvent être regroupées grossièrement en 5 catégories générales :

Catégorie Signification Lien
Promotions numériques Conversions de petits types entiers en int ou unsigned int, et de float en double. 10.2 -- Promotion des nombres à virgule flottante et des entiers
Conversions numériques Autres conversions entières et à virgule flottante qui ne sont pas des promotions. 10.3 -- Conversions numériques
Conversions de qualification Conversions qui ajoutent ou retirent const ou volatile.
Transformations de valeur Conversions qui modifient la catégorie de valeur d'une expression. 12.2 -- Catégories de valeurs (lvalues et rvalues)
Conversions de pointeurs Conversions de std::nullptr vers des types pointeurs, ou de types pointeurs vers d'autres types pointeurs.

Par exemple, la conversion d'une valeur int en valeur float relève de la catégorie des conversions numériques : pour effectuer cette conversion, le compilateur doit simplement appliquer les règles de conversion numérique de int vers float.

Les conversions numériques et les promotions numériques sont les plus importantes de ces catégories, et nous les détaillerons dans les prochaines leçons.

La conversion de type peut échouer

Lorsqu'une conversion de type est invoquée (implicitement ou explicitement), le compilateur détermine s'il peut convertir la valeur du type actuel vers le type souhaité. Si une conversion valide est trouvée, le compilateur produit une nouvelle valeur du type souhaité.

Si le compilateur ne trouve aucune conversion acceptable, la compilation échoue avec une erreur de compilation. Les conversions de type peuvent échouer pour diverses raisons. Par exemple, le compilateur ne sait peut-être pas comment convertir une valeur entre le type d'origine et le type souhaité.

Par exemple :

int main()
{
    int x { "14" };

    return 0;
}

Comme il n'existe pas de conversion standard de la chaîne littérale « 14 » vers int, le compilateur produit une erreur. Par exemple, GCC produit l'erreur : prog.cc:3:13: error: invalid conversion from 'const char*' to 'int' [-fpermissive].

Dans d'autres cas, certaines fonctionnalités interdisent certaines catégories de conversions. Par exemple :

int x { 3.5 }; // l'initialisation avec accolades interdit les conversions qui entraînent une perte de données

Bien que le compilateur sache convertir une valeur double en valeur int, les conversions réductrices sont interdites lors d'une initialisation avec accolades.

Il existe aussi des cas où le compilateur ne parvient pas à déterminer laquelle de plusieurs conversions possibles est la meilleure à utiliser. Nous en verrons des exemples dans la leçon 11.3 -- Résolution de la surcharge de fonctions et correspondances ambiguës.

L'ensemble complet des règles décrivant le fonctionnement des conversions de type est à la fois long et complexe ; dans la plupart des cas, la conversion de type « fonctionne tout simplement ». Dans le prochain ensemble de leçons, nous verrons les points les plus importants à connaître sur les conversions standard. Si un détail plus fin est nécessaire pour un cas peu courant, les règles complètes sont détaillées dans la documentation de référence technique sur les conversions implicites.
