10.5 — Conversions arithmétiques usuelles

Dans la leçon 6.1 -- Priorité et associativité des opérateurs, nous avons vu comment les expressions sont évaluées selon la priorité et l'associativité de leurs opérateurs.

Considérez l'expression suivante :

int x { 2 + 3 };

L'opérateur binaire operator+ reçoit deux opérandes, tous deux de type int. Comme les deux opérandes sont du même type, ce type sera utilisé pour effectuer le calcul, et la valeur renvoyée sera elle aussi de ce même type. Ainsi, 2 + 3 s'évalue à la valeur int 5.

Mais que se passe-t-il lorsque les opérandes d'un opérateur binaire sont de types différents ?

??? y { 2 + 3.5 };

Dans ce cas, operator+ reçoit un opérande de type int et un autre de type double. Le résultat de l'opérateur doit-il être renvoyé sous forme de int, de double, ou peut-être d'un autre type ?

En C++, certains opérateurs exigent que leurs opérandes soient du même type. Si l'un de ces opérateurs est appelé avec des opérandes de types différents, un ou les deux opérandes seront implicitement convertis vers des types identiques, en suivant un ensemble de règles appelé conversions arithmétiques usuelles (usual arithmetic conversions). Le type commun obtenu à l'issue de ces règles est appelé type commun (common type) des opérandes.

Les opérateurs qui exigent des opérandes de même type

Les opérateurs suivants exigent que leurs opérandes soient du même type :

  • Les opérateurs arithmétiques binaires : +, -, *, /, %
  • Les opérateurs relationnels binaires : <, >, <=, >=, ==, !=
  • Les opérateurs binaires de manipulation de bits : &, ^, |
  • L'opérateur conditionnel ?: (à l'exclusion de la condition, qui doit être de type bool)

Pour les lecteurs avancés

Les opérateurs surchargés ne sont pas soumis aux règles des conversions arithmétiques usuelles.

Les règles des conversions arithmétiques usuelles

Les règles des conversions arithmétiques usuelles sont assez complexes, nous allons donc les simplifier un peu. Le compilateur dispose d'une liste ordonnée de types qui ressemble à ceci :

  • long double (rang le plus élevé)
  • double
  • float
  • long long
  • long
  • int (rang le plus bas)

Les règles suivantes sont appliquées pour trouver un type commun :

Étape 1 :

  • Si un opérande est de type entier et l'autre de type à virgule flottante, l'opérande entier est converti vers le type de l'opérande à virgule flottante (aucune promotion entière n'a lieu).
  • Sinon, les opérandes entiers sont promus numériquement (voir 10.2 -- Promotion des flottants et des entiers).

Étape 2 :

  • Après promotion, si un opérande est signé et l'autre non signé, des règles spéciales s'appliquent (voir ci-dessous).
  • Sinon, l'opérande de rang inférieur est converti vers le type de l'opérande de rang supérieur.

Pour les lecteurs avancés

Les règles spéciales de correspondance pour les opérandes entiers de signes différents :

  • Si le rang de l'opérande non signé est supérieur ou égal au rang de l'opérande signé, l'opérande signé est converti vers le type de l'opérande non signé.
  • Si le type de l'opérande signé peut représenter toutes les valeurs du type de l'opérande non signé, l'opérande non signé est converti vers le type de l'opérande signé.
  • Sinon, les deux opérandes sont convertis vers le type non signé correspondant au type signé.

Quelques exemples

Dans les exemples suivants, nous utiliserons l'opérateur typeid (inclus dans l'en-tête <typeinfo>) pour afficher le type résultant d'une expression.

Commençons par additionner un int et un double :

#include <iostream>
#include <typeinfo> // pour typeid()

int main()
{
    int i{ 2 };
    std::cout << typeid(i).name() << '\n'; // affiche le nom du type de i

    double d{ 3.5 };
    std::cout << typeid(d).name() << '\n'; // affiche le nom du type de d

    std::cout << typeid(i + d).name() << ' ' << i + d << '\n'; // affiche le type de i + d

    return 0;
}

Dans ce cas, l'opérande de type double est prioritaire, donc l'opérande de priorité inférieure (de type int) est converti en la valeur double 2.0. Les valeurs double 2.0 et 3.5 sont alors additionnées pour produire le résultat double 5.5.

Sur la machine de l'auteur, cela affiche :


int
double
double 5.5

Notez que votre compilateur peut afficher quelque chose de légèrement différent, car les noms produits par typeid.name() dépendent de l'implémentation.

Ajoutons maintenant deux valeurs de type short :

#include <iostream>
#include <typeinfo> // pour typeid()

int main()
{
    short a{ 4 };
    short b{ 5 };
    std::cout << typeid(a + b).name() << ' ' << a + b << '\n'; // affiche le type de a + b

    return 0;
}

Comme aucun des deux opérandes ne figure dans la liste de priorité, les deux subissent une promotion entière vers le type int. Le résultat de l'addition de deux int est un int, comme vous pouvez vous y attendre :


int 9

Problèmes liés aux types signés et non signés

Cette hiérarchie de priorité et ces règles de conversion peuvent provoquer des problèmes lorsqu'on mélange des valeurs signées et non signées. Par exemple, regardez le code suivant :

#include <iostream>
#include <typeinfo> // pour typeid()

int main()
{
    std::cout << typeid(5u-10).name() << ' ' << 5u - 10 << '\n'; // 5u signifie que 5 est traité comme un entier non signé

    return 0;
}

Vous pourriez vous attendre à ce que l'expression 5u - 10 s'évalue à -5, puisque 5 - 10 = -5. Pourtant, voici ce qui se produit réellement :


unsigned int 4294967291

En raison des règles de conversion, l'opérande int est converti en unsigned int. Et comme la valeur -5 est hors de l'intervalle d'un unsigned int, nous obtenons un résultat inattendu.

Voici un autre exemple présentant un résultat contre-intuitif :

#include <iostream>

int main()
{
    std::cout << std::boolalpha << (-3 < 5u) << '\n';

    return 0;
}

Il est évident pour nous que 5 est supérieur à -3, mais lors de l'évaluation de cette expression, -3 est converti en un grand unsigned int, supérieur à 5. Ainsi, le code ci-dessus affiche false au lieu du résultat attendu true.

C'est l'une des principales raisons d'éviter les entiers non signés : lorsque vous les mélangez avec des entiers signés dans des expressions arithmétiques, vous risquez des résultats inattendus. Et le compilateur ne émettra probablement même pas d'avertissement.

std::common_type et std::common_type_t

Dans les leçons à venir, nous rencontrerons des cas où il sera utile de connaître le type commun de deux types. std::common_type et l'alias de type pratique std::common_type_t (tous deux définis dans l'en-tête <type_traits>) peuvent servir précisément à cela.

Par exemple, std::common_type_t<int, double> renvoie le type commun de int et double, et std::common_type_t<unsigned int, long> renvoie le type commun de unsigned int et long.

Nous montrerons un exemple d'utilisation dans la leçon 11.8 -- Fonctions modèles avec plusieurs types de modèle.
