10.7 — Alias de types et typedef

Alias de types

En C++, using est un mot-clé qui permet de créer un alias pour un type de données existant. Pour créer un tel alias de type, on utilise le mot-clé using, suivi du nom de l'alias, d'un signe égal, puis d'un type de données existant. Par exemple :

using Distance = double; // définit Distance comme un alias du type double

Une fois défini, un alias de type peut être utilisé partout où un type est nécessaire. Par exemple, nous pouvons créer une variable en utilisant le nom de l'alias comme type :

Distance milesToDestination{ 3.4 }; // définit une variable de type double

Lorsque le compilateur rencontre le nom d'un alias de type, il remplace ce nom par le type désigné. Par exemple :

#include <iostream>

int main()
{
    using Distance = double; // définit Distance comme un alias du type double

    Distance milesToDestination{ 3.4 }; // définit une variable de type double

    std::cout << milesToDestination << '\n'; // affiche une valeur de type double

    return 0;
}

Ce programme affiche :


3.4

Dans le programme ci-dessus, nous définissons d'abord Distance comme un alias du type double.

Ensuite, nous définissons une variable nommée milesToDestination de type alias Distance. Comme le compilateur sait que Distance est un alias de type, il utilise le type désigné, c'est-à-dire double. La variable milesToDestination est donc en réalité compilée comme une variable de type double, et elle se comporte en tous points comme un double.

Enfin, nous affichons la valeur de milesToDestination, qui s'affiche comme une valeur double.

Pour les lecteurs avancés

Les alias de types peuvent aussi être des modèles (templates). Nous aborderons ce point dans la leçon 13.14 -- Déduction d'arguments de modèle de classe (CTAD) et guides de déduction.

Nommer les alias de types

Historiquement, la manière de nommer les alias de types n'a pas toujours été cohérente. Il existe trois conventions de nommage courantes (et vous les rencontrerez toutes) :

  • Les alias de types qui se terminent par le suffixe « _t » (« _t » est l'abréviation de « type »). Cette convention est souvent utilisée par la bibliothèque standard pour les noms de types à portée globale (comme size_t et nullptr_t).

Cette convention est héritée du C. Elle était autrefois la plus populaire pour définir ses propres alias de types (et parfois d'autres types), mais elle est tombée en désuétude en C++ moderne. Notez que POSIX réserve le suffixe « _t » aux noms de types à portée globale ; utiliser cette convention peut donc provoquer des conflits de noms sur les systèmes POSIX.

  • Les alias de types qui se terminent par le suffixe « _type ». Cette convention est utilisée par certains types de la bibliothèque standard (comme std::string) pour nommer des alias de types imbriqués (par exemple std::string::size_type).

Cependant, beaucoup d'alias de types imbriqués n'ont aucun suffixe (par exemple std::string::iterator), si bien que cet usage est au mieux incohérent.

  • Les alias de types sans suffixe.

En C++ moderne, la convention consiste à nommer les alias de types (ou tout autre type) que vous définissez vous-même en commençant par une majuscule, et sans suffixe. La majuscule permet de distinguer les noms de types des noms de variables et de fonctions (qui commencent par une minuscule), et évite les collisions de noms entre eux.

Avec cette convention, on rencontre souvent l'usage suivant :

void printDistance(Distance distance); // Distance est un type défini

Ici, Distance est le type, et distance est le nom du paramètre. C++ est sensible à la casse, donc cela ne pose aucun problème.

Bonne pratique

Nommez vos alias de types en commençant par une majuscule, sans suffixe (sauf si vous avez une raison particulière de faire autrement).

Note de l'auteur

Certaines leçons à venir de ce tutoriel utilisent encore les suffixes « _t » ou « _type ». N'hésitez pas à laisser un commentaire sur ces leçons afin que nous les harmonisions avec les bonnes pratiques.

Les alias de types ne sont pas des types distincts

Un alias ne définit pas réellement un nouveau type distinct (considéré comme séparé des autres types) : il introduit simplement un nouvel identifiant pour un type existant. Un alias de type est totalement interchangeable avec le type qu'il désigne.

Cela nous permet de faire des choses syntaxiquement valides mais dénuées de sens sur le plan sémantique. Par exemple :

int main()
{
    using Miles = long; // définit Miles comme un alias du type long
    using Speed = long; // définit Speed comme un alias du type long

    Miles distance { 5 }; // distance est en réalité juste un long
    Speed mhz  { 3200 };  // mhz est en réalité juste un long

    // Ce qui suit est syntaxiquement valide (mais dénué de sens sur le plan sémantique)
    distance = mhz;

    return 0;
}

Bien que nous ayons conceptuellement l'intention que Miles et Speed aient des significations distinctes, ce sont tous deux de simples alias du type long. Cela signifie en pratique que Miles, Speed et long peuvent être utilisés de manière interchangeable. D'ailleurs, lorsque nous affectons une valeur de type Speed à une variable de type Miles, le compilateur voit seulement l'affectation d'une valeur de type long à une variable de type long, et il ne signale aucune erreur.

Comme le compilateur n'empêche pas ce genre d'erreurs sémantiques avec les alias de types, on dit que les alias ne sont pas sûrs au regard des types (type safe). Malgré cela, ils restent utiles.

Attention

Il faut veiller à ne pas mélanger des valeurs d'alias qui sont destinés à avoir des sémantiques distinctes.

En passant…

Certains langages prennent en charge le concept de typedef fort (ou alias de type fort). Un typedef fort crée en réalité un nouveau type qui possède toutes les propriétés du type d'origine, mais le compilateur signale une erreur si l'on mélange des valeurs du type désigné et du typedef fort. Jusqu'à C++20 inclus, C++ ne prend pas directement en charge les typedefs forts (bien que les enum class, traitées dans la leçon 13.6 -- Énumérations à portée (enum class), en soient proches), mais il existe de nombreuses bibliothèques tierces en C++ qui implémentent un comportement similaire à celui d'un typedef fort.

La portée d'un alias de type

La portée étant une propriété d'un identifiant, les identifiants d'alias de types suivent les mêmes règles de portée que les identifiants de variables : un alias de type défini à l'intérieur d'un bloc a une portée de bloc et n'est utilisable que dans ce bloc, alors qu'un alias de type défini dans l'espace de noms global a une portée globale et est utilisable jusqu'à la fin du fichier. Dans l'exemple ci-dessus, Miles et Speed ne sont utilisables que dans la fonction main().

Si vous devez utiliser un ou plusieurs alias de types dans plusieurs fichiers, ils peuvent être définis dans un fichier d'en-tête, puis inclus avec #include dans les fichiers de code qui en ont besoin :

mytypes.h :

#ifndef MYTYPES_H
#define MYTYPES_H

    using Miles = long;
    using Speed = long;

#endif

Les alias de types inclus de cette manière sont importés dans l'espace de noms global et ont donc une portée globale.

Typedefs

Un typedef (abréviation de « type definition », définition de type) est une ancienne manière de créer un alias pour un type. Pour créer un alias typedef, on utilise le mot-clé typedef :

// Les alias suivants sont identiques
typedef long Miles;
using Miles = long;

Les typedefs sont toujours présents en C++ pour des raisons de compatibilité ascendante, mais ils ont été largement remplacés par les alias de types en C++ moderne.

Les typedefs posent quelques problèmes de syntaxe. Premièrement, il est facile d'oublier si le nom du typedef ou le nom du type à alias vient en premier. Lequel est correct ?

typedef Distance double; // incorrect (nom du typedef en premier)
typedef double Distance; // correct (nom du type à alias en premier)

Il est facile de se tromper. Heureusement, dans ce cas, le compilateur signale une erreur.

Deuxièmement, la syntaxe des typedefs peut devenir peu lisible avec des types plus complexes. Par exemple, voici un typedef difficile à lire, ainsi qu'un alias de type équivalent (et un peu plus lisible) :

typedef int (*FcnType)(double, char); // FcnType difficile à repérer
using FcnType = int(*)(double, char); // FcnType plus facile à repérer

Dans la définition typedef ci-dessus, le nom du nouveau type (FcnType) est enfoui au milieu de la définition, alors que dans l'alias de type, le nom du nouveau type et le reste de la définition sont séparés par un signe égal.

Troisièmement, le nom « typedef » suggère qu'un nouveau type est défini, ce qui n'est pas vrai. Un typedef n'est qu'un alias.

Bonne pratique

Préférez les alias de types aux typedefs.

Nomenclature

La norme C++ utilise le terme « typedef names » pour désigner à la fois les noms de typedefs et les noms d'alias de types.

Dans le langage courant, le terme « typedef » désigne souvent « un typedef ou un alias de type », car ils font en pratique la même chose.

Quand devons-nous utiliser les alias de types ?

Maintenant que nous avons vu ce que sont les alias de types, parlons de leur utilité.

Utiliser les alias de types pour un code indépendant de la plateforme

L'une des principales utilisations des alias de types est de masquer les détails propres à une plateforme. Sur certaines plateformes, un int occupe 2 octets, et sur d'autres, 4 octets. Ainsi, utiliser int pour stocker plus de 2 octets d'information peut être potentiellement dangereux dans du code indépendant de la plateforme.

Comme char, short, int et long ne donnent aucune indication sur leur taille, il est assez courant que les programmes multiplateformes utilisent des alias de types incluant la taille du type en bits. Par exemple, int8_t désigne un entier signé de 8 bits, int16_t un entier signé de 16 bits, et int32_t un entier signé de 32 bits. Utiliser des alias de types de cette manière aide à éviter les erreurs et rend plus clair le type d'hypothèses faites sur la taille de la variable.

Afin de garantir que chaque type aliasé correspond bien à un type de la bonne taille, les alias de types de ce genre sont généralement utilisés avec des directives du préprocesseur :

#ifdef INT_2_BYTES
using int8_t = char;
using int16_t = int;
using int32_t = long;
#else
using int8_t = char;
using int16_t = short;
using int32_t = int;
#endif

Sur les machines où les entiers ne font que 2 octets, INT_2_BYTES peut être défini (via un paramètre du compilateur ou du préprocesseur), et le programme sera compilé avec le premier jeu d'alias. Sur les machines où les entiers font 4 octets, si INT_2_BYTES n'est pas défini, c'est le second jeu d'alias qui sera utilisé. Ainsi, tant que INT_2_BYTES est défini correctement, int8_t correspondra à un entier de 1 octet, int16_t à un entier de 2 octets, et int32_t à un entier de 4 octets (en utilisant la combinaison de char, short, int et long appropriée à la machine sur laquelle le programme est compilé).

Les types entiers de largeur fixe (comme std::int16_t et std::uint32_t) et le type size_t (tous deux présentés dans la leçon 4.6 -- Entiers de largeur fixe et size_t) sont en réalité de simples alias de types fondamentaux.

C'est aussi pour cela que lorsque vous affichez un entier de largeur fixe de 8 bits avec std::cout, vous obtenez probablement un caractère. Par exemple :

#include <cstdint> // pour les entiers de largeur fixe
#include <iostream>

int main()
{
    std::int8_t x{ 97 }; // int8_t est généralement un typedef de signed char
    std::cout << x << '\n';

    return 0;
}

Ce programme affiche :


a

Comme std::int8_t est généralement un typedef de signed char, la variable x sera probablement définie comme un signed char. Or les types de caractères affichent leur valeur sous forme de caractères ASCII plutôt que sous forme de valeurs entières.

Utiliser les alias de types pour rendre les types complexes plus lisibles

Bien que nous n'ayons traité jusqu'ici que des types de données simples, en C++ avancé les types peuvent être complexes et longs à saisir au clavier. Par exemple, vous pourriez rencontrer une fonction et une variable définies ainsi :

#include <string> // pour std::string
#include <vector> // pour std::vector
#include <utility> // pour std::pair

bool hasDuplicates(std::vector<std::pair<std::string, int>> pairlist)
{
    // du code ici
    return false;
}

int main()
{
     std::vector<std::pair<std::string, int>> pairlist;

     return 0;
}

Saisir std::vector<std::pair<std::string, int>> à chaque fois que vous devez utiliser ce type est fastidieux, et il est facile de faire une erreur de frappe. Il est bien plus simple d'utiliser un alias de type :

#include <string> // pour std::string
#include <vector> // pour std::vector
#include <utility> // pour std::pair

using VectPairSI = std::vector<std::pair<std::string, int>>; // fait de VectPairSI un alias de ce type compliqué

bool hasDuplicates(VectPairSI pairlist) // utilise VectPairSI comme type de paramètre
{
    // du code ici
    return false;
}

int main()
{
     VectPairSI pairlist; // instancie une variable de type VectPairSI

     return 0;
}

Bien mieux ! Il nous suffit maintenant de taper VectPairSI au lieu de std::vector<std::pair<std::string, int>>.

Ne vous inquiétez pas si vous ne savez pas encore ce que sont std::vector, std::pair, ni toutes ces chevrons. Il vous suffit de comprendre que les alias de types permettent de donner un nom plus simple à un type complexe, ce qui rend le code plus lisible et fait gagner de la frappe.

C'est probablement le meilleur usage des alias de types.

Utiliser les alias de types pour documenter le sens d'une valeur

Les alias de types peuvent aussi aider à documenter le code et à en faciliter la compréhension.

Pour les variables, l'identifiant de la variable aide à documenter son rôle. Mais considérons le cas de la valeur de retour d'une fonction. Des types comme char, int, long, double et bool décrivent le type de valeur que renvoie une fonction, mais ce qui nous intéresse plus souvent, c'est le sens de cette valeur de retour.

Par exemple, avec la fonction suivante :

int gradeTest();

On voit que la valeur de retour est un entier, mais que signifie cet entier ? Une note en lettres ? Le nombre de questions manquées ? Le numéro d'identification de l'étudiant ? Un code d'erreur ? Impossible à dire ! Le type de retour int ne nous apprend pas grand-chose. Si nous avons de la chance, une documentation de la fonction existe quelque part où nous pouvons la consulter. Sinon, il faut lire le code et déduire son rôle.

Voyons maintenant une version équivalente utilisant un alias de type :

using TestScore = int;
TestScore gradeTest();

Le type de retour TestScore indique un peu plus clairement que la fonction renvoie un type représentant un score de test.

D'après notre expérience, créer un alias de type uniquement pour documenter le type de retour d'une seule fonction n'en vaut pas la peine (utilisez plutôt un commentaire). Mais si plusieurs fonctions passent ou renvoient un tel type, créer un alias de type peut en valoir la peine.

Utiliser les alias de types pour faciliter la maintenance du code

Les alias de types permettent aussi de changer le type sous-jacent d'un objet sans avoir à mettre à jour de nombreux types écrits en dur. Par exemple, si vous utilisiez un short pour stocker le numéro d'identification d'un étudiant, mais que vous décidiez plus tard d'utiliser un long, vous devriez parcourir beaucoup de code et remplacer short par long. Il serait sans doute difficile de déterminer quels objets de type short servaient à stocker des numéros d'identification et lesquels servaient à autre chose.

En revanche, si vous utilisez des alias de types, changer de type devient aussi simple que de modifier l'alias (par exemple, passer de using StudentId = short; à using StudentId = long;).

Si cet avantage semble intéressant, il faut rester prudent à chaque changement de type, car le comportement du programme peut aussi changer. C'est particulièrement vrai lorsque le type d'un alias est changé pour un type d'une autre famille (par exemple, un entier devenant un nombre à virgule flottante, ou une valeur signée devenant non signée) ! Le nouveau type peut poser des problèmes de comparaison ou de division entière ou flottante, ou d'autres problèmes que l'ancien type ne posait pas. Si vous remplacez un type existant par un autre, votre code doit être soigneusement retesté.

Inconvénients et conclusion

Si les alias de types offrent certains avantages, ils introduisent aussi un identifiant supplémentaire dans votre code, qu'il faut comprendre. Si cela n'est pas compensé par un gain en lisibilité ou en compréhension, l'alias de type fait plus de mal que de bien.

Un alias de type mal utilisé peut prendre un type familier (comme std::string) et le cacher derrière un nom personnalisé qu'il faut aller chercher. Dans certains cas (comme pour les pointeurs intelligents, que nous aborderons dans un chapitre ultérieur), masquer les informations sur le type peut aussi nuire à la compréhension de la manière dont le type doit fonctionner.

Pour cette raison, les alias de types doivent être utilisés principalement lorsqu'ils apportent un bénéfice clair pour la lisibilité ou la maintenance du code. C'est autant un art qu'une science. Les alias de types sont surtout utiles lorsqu'ils peuvent être employés à de nombreux endroits de votre code, plutôt qu'à peu d'endroits.

Bonne pratique

Utilisez les alias de types avec discernement, lorsqu'ils apportent un bénéfice clair pour la lisibilité ou la maintenance du code.

Quiz

Question n° 1

Étant donné le prototype de fonction suivant :

int printData();

Convertissez la valeur de retour int en un alias de type nommé PrintError. Incluez à la fois l'instruction de définition de l'alias de type et le prototype de fonction mis à jour.

Solution 
using PrintError = int;

PrintError printData();
