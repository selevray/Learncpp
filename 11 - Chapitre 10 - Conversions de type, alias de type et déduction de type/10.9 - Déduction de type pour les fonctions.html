10.9 — Déduction de type pour les fonctions

Considérez le programme suivant :

int add(int x, int y)
{
    return x + y;
}

Lorsque cette fonction est compilée, le compilateur détermine que x + y s'évalue en un int, puis vérifie que le type de la valeur de retour correspond au type de retour déclaré de la fonction (ou que ce type peut être converti vers le type de retour déclaré).

Déduction du type de retour avec auto

Comme le compilateur doit déjà déduire le type de retour à partir de l'instruction return (afin de vérifier que la valeur peut être convertie vers le type de retour déclaré de la fonction), le mot-clé auto a été étendu en C++14 pour effectuer la déduction du type de retour d'une fonction. Cela consiste à utiliser auto à la place du type de retour de la fonction.

Par exemple :

auto add(int x, int y)
{
    return x + y;
}

Comme l'instruction return renvoie une valeur de type int, le compilateur déduit que le type de retour de cette fonction est int.

Lorsqu'on utilise un type de retour auto, toutes les instructions return de la fonction doivent renvoyer des valeurs de même type, sinon une erreur est produite. Par exemple :

auto someFcn(bool b)
{
    if (b)
        return 5; // type de retour int
    else
        return 6.7; // type de retour double
}

Dans la fonction ci-dessus, les deux instructions return renvoient des valeurs de types différents, le compilateur produira donc une erreur.

Si un tel cas est souhaité pour une raison quelconque, vous pouvez soit spécifier explicitement un type de retour pour votre fonction (auquel cas le compilateur tentera de convertir implicitement toute expression de retour non conforme vers le type de retour explicite), soit convertir explicitement toutes vos instructions return vers un même type. Dans l'exemple ci-dessus, la seconde solution pourrait être réalisée en remplaçant 5 par 5.0, mais static_cast peut aussi être utilisé pour les types qui ne sont pas des littéraux.

Avantages de la déduction du type de retour

Le principal avantage de la déduction du type de retour est que, en laissant le compilateur déterminer le type de retour de la fonction, on élimine le risque d'un type de retour incohérent (en évitant des conversions inattendues).

Cela peut être particulièrement utile lorsque le type de retour d'une fonction est fragile (cas où ce type est susceptible de changer si l'implémentation évolue). Dans de tels cas, le fait d'être explicite sur le type de retour oblige à mettre à jour tous les types de retour concernés lorsqu'une modification affectant l'implémentation est effectuée. Si nous avons de la chance, le compilateur produira une erreur jusqu'à ce que nous mettions à jour les types de retour concernés. Sinon, nous obtiendrons des conversions implicites là où nous ne les souhaitons pas.

Dans d'autres cas, le type de retour d'une fonction peut être long et complexe, ou peu évident. Dans ces situations, auto peut être utilisé pour simplifier :

// laisse le compilateur déterminer le type du résultat de unsigned short + char
auto add(unsigned short x, char y)
{
    return x + y;
}

Nous revenons un peu plus en détail sur ce cas (et sur la manière d'exprimer le type de retour réel d'une telle fonction) dans la leçon 11.8 -- Modèles de fonctions à plusieurs types de modèle.

Inconvénients de la déduction du type de retour

La déduction du type de retour présente deux inconvénients majeurs :

  1. Les fonctions dont le type de retour est auto doivent être entièrement définies avant d'être utilisées (une déclaration anticipée ne suffit pas). Par exemple :
#include <iostream>

auto foo();

int main()
{
    std::cout << foo() << '\n'; // le compilateur n'a vu qu'une déclaration anticipée à ce stade

    return 0;
}

auto foo()
{
    return 5;
}

Sur la machine de l'auteur, cela produit l'erreur de compilation suivante :


error C3779: 'foo': a function that returns 'auto' cannot be used before it is defined.

Cela se comprend : une déclaration anticipée ne fournit pas au compilateur assez d'informations pour déduire le type de retour de la fonction. Cela signifie que les fonctions ordinaires dont le type de retour est auto ne peuvent généralement être appelées qu'à partir du fichier dans lequel elles sont définies.

  1. Lorsqu'on utilise la déduction de type avec des objets, l'initialiseur est toujours présent dans la même instruction, il n'est donc généralement pas trop contraignant de déterminer le type qui sera déduit. Avec la déduction de type pour les fonctions, ce n'est pas le cas : le prototype de la fonction n'indique pas le type que la fonction renvoie réellement. Un bon environnement de développement devrait faire apparaître clairement le type déduit de la fonction, mais en l'absence d'un tel outil, un utilisateur devrait examiner le corps même de la fonction pour déterminer le type renvoyé. Les risques d'erreur sont alors plus élevés. D'une manière générale, nous préférons être explicites sur les types qui font partie d'une interface (la déclaration d'une fonction est une interface).

Contrairement à la déduction de type pour les objets, il n'existe pas de consensus aussi net sur les bonnes pratiques concernant la déduction du type de retour des fonctions. Nous recommandons d'éviter, de manière générale, la déduction du type de retour pour les fonctions.

Bonne pratique

Préférez les types de retour explicites à la déduction du type de retour (sauf dans les cas où le type de retour est peu important, difficile à exprimer ou fragile).

Syntaxe de type de retour déporté

Le mot-clé auto peut également être utilisé pour déclarer des fonctions avec une syntaxe de type de retour déporté (trailing return syntax), où le type de retour est spécifié après le reste du prototype de la fonction.

Considérez la fonction suivante :

int add(int x, int y)
{
  return (x + y);
}

En utilisant la syntaxe de type de retour déporté, cette fonction peut être écrite de manière équivalente ainsi :

auto add(int x, int y) -> int
{
  return (x + y);
}

Dans ce cas, auto n'effectue pas de déduction de type : il fait simplement partie de la syntaxe permettant d'utiliser un type de retour déporté.

Pourquoi voudriez-vous faire cela ? Voici quelques raisons :

  1. Pour les fonctions dont le type de retour est complexe, un type de retour déporté peut rendre la fonction plus lisible :
#include <type_traits> // pour std::common_type

std::common_type_t<int, double> compare(int, double);         // plus difficile à lire (où se trouve le nom de la fonction dans ce fouillis ?)
auto compare(int, double) -> std::common_type_t<int, double>; // plus facile à lire (nous n'avons pas à lire le type de retour sauf si cela nous intéresse)
  1. La syntaxe de type de retour déporté peut être utilisée pour aligner les noms de vos fonctions, ce qui rend plus lisibles les déclarations de fonctions consécutives :
auto add(int x, int y) -> int;
auto divide(double x, double y) -> double;
auto printSomething() -> void;
auto generateSubstring(const std::string &s, int start, int len) -> std::string;

Pour les lecteurs avancés

  1. Si nous avons une fonction dont le type de retour doit être déduit à partir du type de ses paramètres, un type de retour classique ne suffira pas, car le compilateur n'a pas encore vu les paramètres à ce stade.
#include <type_traits>
// note : decltype(x) s'évalue au type de x

std::common_type_t<decltype(x), decltype(y)> add(int x, double y);         // Erreur de compilation : le compilateur n'a pas encore vu les définitions de x et y
auto add(int x, double y) -> std::common_type_t<decltype(x), decltype(y)>; // ok
  1. La syntaxe de type de retour déporté est également requise pour certaines fonctionnalités avancées du C++, comme les lambdas (que nous abordons dans la leçon 20.6 -- Introduction aux lambdas (fonctions anonymes)).

Pour l'instant, nous recommandons de continuer à utiliser la syntaxe de retour traditionnelle des fonctions, sauf dans les situations qui exigent la syntaxe de type de retour déporté.

La déduction de type ne peut pas être utilisée pour les types de paramètres de fonction

Beaucoup de nouveaux programmeurs qui découvrent la déduction de type essaient quelque chose comme ceci :

#include <iostream>

void addAndPrint(auto x, auto y)
{
    std::cout << x + y << '\n';
}

int main()
{
    addAndPrint(2, 3); // cas 1 : appel de addAndPrint avec des paramètres int
    addAndPrint(4.5, 6.7); // cas 2 : appel de addAndPrint avec des paramètres double

    return 0;
}

Malheureusement, la déduction de type ne fonctionne pas pour les paramètres de fonction, et avant C++20, le programme ci-dessus ne compile pas (vous obtiendrez une erreur indiquant que les paramètres de fonction ne peuvent pas avoir un type auto).

En C++20, le mot-clé auto a été étendu de sorte que le programme ci-dessus compile et fonctionne correctement. Cependant, auto n'invoque pas ici la déduction de type. Il déclenche plutôt une fonctionnalité différente, appelée modèles de fonctions (function templates), conçue précisément pour gérer de tels cas.
