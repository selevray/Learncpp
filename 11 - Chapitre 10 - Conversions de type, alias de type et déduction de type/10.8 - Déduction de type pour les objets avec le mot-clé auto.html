10.8 — Déduction de type pour les objets avec le mot-clé auto

Il existe une redondance subtile dans cette définition de variable simple :

double d{ 5.0 };

En C++, nous sommes obligés de fournir un type explicite pour tous les objets. Nous avons donc spécifié que la variable d est de type double.

Cependant, la valeur littérale 5.0 utilisée pour initialiser d est également de type double (déterminé implicitement par le format du littéral).

Contenu associé

Nous expliquons comment les types des littéraux sont déterminés dans la leçon 5.2 -- Littéraux.

Lorsque nous voulons qu'une variable et son initialiseur aient le même type, nous fournissons en réalité deux fois la même information de type.

Déduction de type pour les variables initialisées

La déduction de type (parfois appelée inférence de type) est une fonctionnalité qui permet au compilateur de déduire le type d'un objet à partir de son initialiseur. Lors de la définition d'une variable, la déduction de type peut être invoquée en utilisant le mot-clé auto à la place du type de la variable :

int main()
{
    auto d { 5.0 }; // 5.0 est un littéral de type double, donc d sera déduit comme double
    auto i { 1 + 2 }; // 1 + 2 s'évalue en int, donc i sera déduit comme int
    auto x { i }; // i est un int, donc x sera déduit comme int

    return 0;
}

Dans le premier cas, comme 5.0 est un littéral double, le compilateur déduira que la variable d doit être de type double. Dans le deuxième cas, l'expression 1 + 2 produit un résultat de type int, donc la variable i sera de type int. Dans le troisième cas, i a été précédemment déduit comme int, donc x sera également déduit comme int.

Attention

Avant C++17, auto d{ 5.0 }; déduisait d comme std::initializer_list<double> plutôt que comme double. Ceci a été corrigé en C++17, et de nombreux compilateurs (comme gcc et Clang) ont rétroporté ce changement aux normes de langage précédentes.

Si vous utilisez C++14 ou une version antérieure, et que l'exemple ci-dessus ne compile pas avec votre compilateur, utilisez plutôt l'initialisation par copie avec auto (auto d = 5.0).

Comme les appels de fonction sont des expressions valides, nous pouvons même utiliser la déduction de type lorsque notre initialiseur est un appel de fonction non-void :

int add(int x, int y)
{
    return x + y;
}

int main()
{
    auto sum { add(5, 6) }; // add() renvoie un int, donc le type de sum sera déduit comme int

    return 0;
}

La fonction add() renvoie une valeur int, donc le compilateur déduira que la variable sum doit avoir le type int.

Les suffixes littéraux peuvent être utilisés en combinaison avec la déduction de type pour spécifier un type particulier :

int main()
{
    auto a { 1.23f }; // le suffixe f fait que a est déduit comme float
    auto b { 5u };    // le suffixe u fait que b est déduit comme unsigned int

    return 0;
}

Les variables utilisant la déduction de type peuvent également employer d'autres spécificateurs/qualificateurs, comme const ou constexpr :

int main()
{
    int a { 5 };            // a est un int

    const auto b { 5 };     // b est un const int
    constexpr auto c { 5 }; // c est un constexpr int

    return 0;
}

La déduction de type a besoin de quelque chose à déduire

La déduction de type ne fonctionnera pas pour les objets qui n'ont pas d'initialiseur ou dont l'initialiseur est vide. Elle ne fonctionne pas non plus lorsque l'initialiseur est de type void (ou tout autre type incomplet). Ainsi, ce qui suit n'est pas valide :

#include <iostream>

void foo()
{
}

int main()
{
    auto a;           // Le compilateur est incapable de déduire le type de a
    auto b { };       // Le compilateur est incapable de déduire le type de b
    auto c { foo() }; // Invalide : c ne peut pas avoir le type incomplet void

    return 0;
}

Bien que l'utilisation de la déduction de type pour les types fondamentaux ne permette d'économiser que quelques frappes (voire aucune), nous verrons dans de futures leçons des exemples où les types deviennent complexes et longs (et parfois difficiles à déterminer). Dans ces cas, utiliser auto peut faire économiser beaucoup de saisie (et de fautes de frappe).

Contenu associé

Les règles de déduction de type pour les pointeurs et les références sont un peu plus complexes. Nous les expliquons dans la leçon 12.14 -- Déduction de type avec les pointeurs, les références et const.

La déduction de type supprime const du type déduit

Dans la plupart des cas, la déduction de type supprime le const des types déduits. Par exemple :

int main()
{
    const int a { 5 }; // a a le type const int
    auto b { a };      // b a le type int (const supprimé)

    return 0;
}

Dans l'exemple ci-dessus, a a le type const int, mais lorsqu'on déduit le type de la variable b à partir de a comme initialiseur, la déduction de type obtient int, et non const int.

Si vous voulez qu'un type déduit soit const, vous devez fournir vous-même le const dans la définition :

int main()
{
    const int a { 5 };  // a a le type const int
    const auto b { a }; // b a le type const int (const supprimé puis réappliqué)


    return 0;
}

Dans cet exemple, le type déduit à partir de a sera int (le const est supprimé), mais comme nous avons réajouté un qualificateur const lors de la définition de la variable b, celle-ci aura le type const int.

La déduction de type pour les chaînes littérales

Pour des raisons historiques, les chaînes littérales en C++ ont un type étrange. Par conséquent, ce qui suit ne fonctionnera probablement pas comme prévu :

auto s { "Hello, world" }; // s sera de type const char*, et non std::string

Si vous voulez que le type déduit d'une chaîne littérale soit std::string ou std::string_view, vous devrez utiliser les suffixes littéraux s ou sv (présentés dans les leçons 5.7 -- Introduction à std::string et 5.8 -- Introduction à std::string_view) :

#include <string>
#include <string_view>

int main()
{
    using namespace std::literals; // la manière la plus simple d'accéder aux suffixes s et sv

    auto s1 { "goo"s };  // "goo"s est un littéral std::string, donc s1 sera déduit comme std::string
    auto s2 { "moo"sv }; // "moo"sv est un littéral std::string_view, donc s2 sera déduit comme std::string_view

    return 0;
}

Mais dans de tels cas, il peut être préférable de ne pas utiliser la déduction de type.

La déduction de type et constexpr

Comme constexpr ne fait pas partie du système de types, il ne peut pas être déduit dans le cadre de la déduction de type. Cependant, une variable constexpr est implicitement const, et ce const sera supprimé lors de la déduction de type (et peut être réappliqué si besoin) :

int main()
{
    constexpr double a { 3.4 };  // a a le type const double (constexpr ne fait pas partie du type, const est implicite)

    auto b { a };                // b a le type double (const supprimé)
    const auto c { a };          // c a le type const double (const supprimé puis réappliqué)
    constexpr auto d { a };      // d a le type const double (const supprimé mais réappliqué implicitement par constexpr)

    return 0;
}

Avantages et inconvénients de la déduction de type

La déduction de type n'est pas seulement pratique, elle présente également d'autres avantages.

Premièrement, si deux variables ou plus sont définies sur des lignes successives, leurs noms seront alignés, ce qui améliore la lisibilité :

// plus difficile à lire
int a { 5 };
double b { 6.7 };

// plus facile à lire
auto c { 5 };
auto d { 6.7 };

Deuxièmement, la déduction de type ne fonctionne que sur les variables ayant un initialiseur ; si vous avez l'habitude d'utiliser la déduction de type, cela peut aider à éviter des variables non initialisées par inadvertance :

int x; // oups, nous avons oublié d'initialiser x, mais le compilateur ne se plaindra peut-être pas
auto y; // le compilateur produira une erreur car il ne peut pas déduire de type pour y

Troisièmement, on est assuré qu'il n'y aura pas de conversions involontaires ayant un impact sur les performances :

std::string_view getString();   // une fonction qui renvoie un std::string_view

std::string s1 { getString() }; // mauvais : conversion coûteuse de std::string_view vers std::string (en supposant que vous ne vouliez pas cela)
auto s2 { getString() };        // bien : aucune conversion nécessaire

La déduction de type présente aussi quelques inconvénients.

Premièrement, la déduction de type masque les informations de type d'un objet dans le code. Bien qu'un bon IDE devrait pouvoir vous montrer le type déduit (par exemple en survolant une variable), il est tout de même un peu plus facile de commettre des erreurs liées au type lorsqu'on utilise la déduction de type.

Par exemple :

auto y { 5 }; // oups, nous voulions un double ici mais nous avons accidentellement fourni un littéral int

Dans le code ci-dessus, si nous avions explicitement spécifié que y est de type double, y aurait été un double même si nous avions accidentellement fourni un initialiseur littéral int. Avec la déduction de type, y sera déduit comme étant de type int.

Voici un autre exemple :

#include <iostream>

int main()
{
     auto x { 3 };
     auto y { 2 };

     std::cout << x / y << '\n'; // oups, nous voulions une division en virgule flottante ici

     return 0;
}

Dans cet exemple, il est moins évident que nous effectuons une division entière plutôt qu'une division en virgule flottante.

Des cas similaires se produisent lorsqu'une variable est unsigned. Comme nous ne voulons pas mélanger des valeurs signées et non signées, le fait de savoir explicitement qu'une variable a un type non signé ne devrait généralement pas être masqué.

Deuxièmement, si le type d'un initialiseur change, le type d'une variable utilisant la déduction de type changera également, peut-être de manière inattendue. Considérons :

auto sum { add(5, 6) + gravity };

Si le type de retour de add passe de int à double, ou si gravity passe de int à double, sum changera également de type, passant de int à double.

Dans l'ensemble, le consensus moderne est que la déduction de type est généralement sûre à utiliser pour les objets, et qu'elle peut rendre votre code plus lisible en atténuant l'importance des informations de type, afin que la logique de votre code ressorte mieux.

Bonne pratique

Utilisez la déduction de type pour vos variables lorsque le type de l'objet n'a pas d'importance.

Privilégiez un type explicite lorsque vous avez besoin d'un type précis différent du type de l'initialiseur, ou lorsque votre objet est utilisé dans un contexte où rendre le type évident est utile.

Note de l'auteur

Dans les prochaines leçons, nous continuerons à utiliser des types explicites plutôt que la déduction de type lorsque nous jugerons que montrer l'information de type aide à comprendre un concept ou un exemple.
