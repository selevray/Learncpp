19.3 — Destructeurs

Un destructeur (destructor) est un autre type spécial de fonction membre de classe, exécuté lorsqu'un objet de cette classe est détruit. Alors que les constructeurs sont conçus pour initialiser une classe, les destructeurs sont conçus pour aider au nettoyage.

Lorsqu'un objet sort normalement de sa portée, ou lorsqu'un objet alloué dynamiquement est explicitement supprimé à l'aide du mot-clé delete, le destructeur de la classe est automatiquement appelé (s'il existe) pour effectuer le nettoyage nécessaire avant que l'objet ne soit retiré de la mémoire. Pour les classes simples (celles qui se contentent d'initialiser les valeurs de membres de données ordinaires), un destructeur n'est pas nécessaire, car le C++ nettoiera automatiquement la mémoire à votre place.

Cependant, si l'objet de votre classe détient des ressources (par exemple de la mémoire dynamique, ou un descripteur de fichier ou de base de données), ou si vous devez effectuer une quelconque opération de maintenance avant la destruction de l'objet, le destructeur est l'endroit idéal pour le faire, car c'est généralement la dernière chose qui se produit avant la destruction de l'objet.

Nommage des destructeurs

Comme pour les constructeurs, les destructeurs obéissent à des règles de nommage spécifiques :

  1. Le destructeur doit porter le même nom que la classe, précédé d'un tilde (~).
  2. Le destructeur ne peut pas prendre d'arguments.
  3. Le destructeur n'a pas de type de retour.

Une classe ne peut posséder qu'un seul destructeur.

En général, vous ne devriez pas appeler un destructeur explicitement (puisqu'il sera appelé automatiquement lorsque l'objet sera détruit), car il est rarement utile de nettoyer un objet plus d'une fois. Cependant, un destructeur peut sans danger appeler d'autres fonctions membres, puisque l'objet n'est détruit qu'après l'exécution du destructeur.

Un exemple de destructeur

Examinons une classe simple qui utilise un destructeur :

#include <iostream>
#include <cassert>
#include <cstddef>

class IntArray
{
private:
    int* m_array{};
    int m_length{};

public:
    IntArray(int length) // constructeur
    {
        assert(length > 0);

        m_array = new int[static_cast<std::size_t>(length)]{};
        m_length = length;
    }

    ~IntArray() // destructeur
    {
        // Supprime dynamiquement le tableau alloué précédemment
        delete[] m_array;
    }

    void setValue(int index, int value) { m_array[index] = value; }
    int getValue(int index) { return m_array[index]; }

    int getLength() { return m_length; }
};

int main()
{
    IntArray ar ( 10 ); // alloue 10 entiers
    for (int count{ 0 }; count < ar.getLength(); ++count)
        ar.setValue(count, count+1);

    std::cout << "The value of element 5 is: " << ar.getValue(5) << '\n';

    return 0;
} // ar est détruit ici, donc la fonction destructeur ~IntArray() est appelée ici

Astuce

Si vous compilez l'exemple ci-dessus et obtenez l'erreur suivante :


error: 'class IntArray' has pointer data members [-Werror=effc++]|
error:   but does not override 'IntArray(const IntArray&)' [-Werror=effc++]|
error:   or 'operator=(const IntArray&)' [-Werror=effc++]|

vous pouvez soit retirer le drapeau « -Weffc++ » de vos paramètres de compilation pour cet exemple, soit ajouter les deux lignes suivantes à la classe :

    IntArray(const IntArray&) = delete;
    IntArray& operator=(const IntArray&) = delete;

Nous abordons =delete pour les membres dans la leçon 14.14 -- Introduction au constructeur de copie

Ce programme produit le résultat suivant :


The value of element 5 is: 6

À la première ligne de main(), nous instancions un nouvel objet de classe IntArray nommé ar, et nous lui passons une longueur de 10. Cela appelle le constructeur, qui alloue dynamiquement la mémoire du membre tableau. Nous devons utiliser l'allocation dynamique ici car nous ne connaissons pas la longueur du tableau à la compilation (c'est l'appelant qui la détermine).

À la fin de main(), ar sort de sa portée. Cela provoque l'appel du destructeur ~IntArray(), qui supprime le tableau que nous avons alloué dans le constructeur !

Un rappel

Dans la leçon 16.2 -- Introduction aux constructeurs de std::vector et de list, nous indiquons qu'une initialisation avec parenthèses doit être utilisée lorsqu'on initialise une classe de type tableau/conteneur/liste avec une longueur (par opposition à une liste d'éléments). C'est pour cette raison que nous initialisons IntArray avec IntArray ar ( 10 );.

Moment d'appel du constructeur et du destructeur

Comme mentionné précédemment, le constructeur est appelé lorsqu'un objet est créé, et le destructeur lorsqu'un objet est détruit. Dans l'exemple suivant, nous utilisons des instructions cout à l'intérieur du constructeur et du destructeur pour le montrer :

#include <iostream>

class Simple
{
private:
    int m_nID{};

public:
    Simple(int nID)
        : m_nID{ nID }
    {
        std::cout << "Constructing Simple " << nID << '\n';
    }

    ~Simple()
    {
        std::cout << "Destructing Simple" << m_nID << '\n';
    }

    int getID() { return m_nID; }
};

int main()
{
    // Alloue un Simple sur la pile
    Simple simple{ 1 };
    std::cout << simple.getID() << '\n';

    // Alloue un Simple dynamiquement
    Simple* pSimple{ new Simple{ 2 } };

    std::cout << pSimple->getID() << '\n';

    // Nous avons alloué pSimple dynamiquement, nous devons donc le supprimer.
    delete pSimple;

    return 0;
} // simple sort de sa portée ici

Ce programme produit le résultat suivant :


Constructing Simple 1
1
Constructing Simple 2
2
Destructing Simple 2
Destructing Simple 1

Notez que « Simple 1 » est détruit après « Simple 2 » car nous avons supprimé pSimple avant la fin de la fonction, alors que simple n'a été détruit qu'à la fin de main().

Les variables globales sont construites avant main() et détruites après main().

RAII

RAII (Resource Acquisition Is Initialization, « l'acquisition de ressource est l'initialisation ») est une technique de programmation dans laquelle l'utilisation d'une ressource est liée à la durée de vie d'objets à durée de stockage automatique (par exemple des objets non alloués dynamiquement). En C++, RAII est implémenté à l'aide de classes dotées de constructeurs et de destructeurs. Une ressource (telle que de la mémoire, un descripteur de fichier ou de base de données, etc.) est généralement acquise dans le constructeur de l'objet (bien qu'elle puisse être acquise après la création de l'objet si cela a du sens). Cette ressource peut ensuite être utilisée tant que l'objet existe. La ressource est libérée dans le destructeur, lorsque l'objet est détruit. Le principal avantage de RAII est qu'il aide à prévenir les fuites de ressources (par exemple de la mémoire non désallouée), puisque tous les objets détenant des ressources sont nettoyés automatiquement.

La classe IntArray présentée en haut de cette leçon est un exemple de classe qui implémente RAII : allocation dans le constructeur, désallocation dans le destructeur. std::string et std::vector sont des exemples de classes de la bibliothèque standard qui suivent RAII : la mémoire dynamique est acquise à l'initialisation et nettoyée automatiquement à la destruction.

Un avertissement concernant la fonction std::exit()

Notez que si vous utilisez la fonction std::exit(), votre programme se termine et aucun destructeur n'est appelé. Soyez prudent si vous comptez sur vos destructeurs pour effectuer un travail de nettoyage nécessaire (par exemple écrire quelque chose dans un fichier journal ou une base de données avant de quitter).

Résumé

Comme vous pouvez le constater, lorsque constructeurs et destructeurs sont utilisés ensemble, vos classes peuvent s'initialiser et se nettoyer elles-mêmes sans que le programmeur ait à faire quoi que ce soit de particulier ! Cela réduit la probabilité de commettre une erreur et rend les classes plus faciles à utiliser.
