19.5 — Pointeurs void

Le pointeur void (void pointer), aussi appelé pointeur générique, est un type particulier de pointeur qui peut pointer vers des objets de n'importe quel type de données ! Un pointeur void se déclare comme un pointeur normal, en utilisant le mot-clé void comme type du pointeur :

void* ptr {}; // ptr est un pointeur void

Un pointeur void peut pointer vers des objets de n'importe quel type de données :

int nValue {};
float fValue {};

struct Something
{
    int n;
    float f;
};

Something sValue {};

void* ptr {};
ptr = &nValue; // valide
ptr = &fValue; // valide
ptr = &sValue; // valide

Cependant, comme le pointeur void ne sait pas vers quel type d'objet il pointe, le déréférencer est illégal. Il faut d'abord convertir le pointeur void vers un autre type de pointeur avant de pouvoir effectuer le déréférencement.

int value{ 5 };
void* voidPtr{ &value };

// std::cout << *voidPtr << '\n'; // illégal : déréférencement d'un pointeur void

int* intPtr{ static_cast<int*>(voidPtr) }; // en revanche, si nous convertissons notre pointeur void en pointeur sur int...

std::cout << *intPtr << '\n'; // alors nous pouvons déréférencer le résultat

Ce programme affiche :


5

La question suivante qui vient naturellement est : si un pointeur void ne sait pas vers quoi il pointe, comment savoir vers quel type le convertir ? En définitive, c'est à vous de garder cette information.

Voici un exemple d'utilisation d'un pointeur void :

#include <cassert>
#include <iostream>

enum class Type
{
    tInt, // remarque : nous ne pouvons pas utiliser "int" ici car c'est un mot-clé, nous utiliserons donc "tInt" à la place
    tFloat,
    tCString
};

void printValue(void* ptr, Type type)
{
    switch (type)
    {
    case Type::tInt:
        std::cout << *static_cast<int*>(ptr) << '\n'; // conversion en pointeur sur int puis déréférencement
        break;
    case Type::tFloat:
        std::cout << *static_cast<float*>(ptr) << '\n'; // conversion en pointeur sur float puis déréférencement
        break;
    case Type::tCString:
        std::cout << static_cast<char*>(ptr) << '\n'; // conversion en pointeur sur char (sans déréférencement)
        // std::cout traitera char* comme une chaîne de style C
        // si nous effectuions un déréférencement sur le résultat, nous n'afficherions que le caractère unique pointé par ptr
        break;
    default:
        std::cerr << "printValue(): type invalide fourni\n";
        assert(false && "type non trouvé");
        break;
    }
}

int main()
{
    int nValue{ 5 };
    float fValue{ 7.5f };
    char szValue[]{ "Mollie" };

    printValue(&nValue, Type::tInt);
    printValue(&fValue, Type::tFloat);
    printValue(szValue, Type::tCString);

    return 0;
}

Ce programme affiche :


5
7.5
Mollie

Divers sur les pointeurs void

Les pointeurs void peuvent recevoir la valeur nulle :

void* ptr{ nullptr }; // ptr est un pointeur void actuellement nul

Comme un pointeur void ne sait pas vers quel type d'objet il pointe, supprimer (delete) un pointeur void provoque un comportement indéfini. Si vous devez supprimer un pointeur void, effectuez d'abord un static_cast vers le type approprié.

Il n'est pas possible d'effectuer de l'arithmétique de pointeurs sur un pointeur void. En effet, l'arithmétique de pointeurs requiert que le pointeur connaisse la taille de l'objet pointé, afin de pouvoir l'incrémenter ou le décrémenter correctement.

Notez qu'il n'existe pas de référence void. En effet, une référence void serait de type void & et ne saurait pas quel type de valeur elle référence.

Conclusion

En général, il est préférable d'éviter les pointeurs void sauf en cas de nécessité absolue, car ils permettent en pratique de contourner la vérification de types. Vous pouvez alors faire par inadvertance des choses dénuées de sens, sans que le compilateur ne proteste. Par exemple, le code suivant serait valide :

    int nValue{ 5 };
    printValue(&nValue, Type::tCString);

Mais qui sait quel serait le résultat réel !

Bien que la fonction ci-dessus semble être un moyen élégant de faire gérer plusieurs types de données par une seule fonction, C++ propose en fait une bien meilleure façon d'y parvenir (via la surcharge de fonctions), qui conserve la vérification de types et aide à prévenir les mauvaises utilisations. De nombreux autres cas où l'on utilisait autrefois des pointeurs void pour gérer plusieurs types de données sont désormais mieux traités à l'aide des modèles (templates), qui offrent également une vérification de types stricte.

Il arrive cependant très occasionnellement de trouver une utilisation raisonnable du pointeur void. Assurez-vous simplement qu'il n'existe pas, au préalable, un moyen meilleur (et plus sûr) d'accomplir la même chose à l'aide d'autres mécanismes du langage !

Quiz

Question n° 1

Quelle est la différence entre un pointeur void et un pointeur nul ?

Solution

Un pointeur void est un pointeur qui peut pointer vers n'importe quel type d'objet, mais qui ne sait pas vers quel type d'objet il pointe. Un pointeur void doit être explicitement converti en un autre type de pointeur pour effectuer un déréférencement. Un pointeur nul est un pointeur qui ne pointe vers aucune adresse. Un pointeur void peut être un pointeur nul.

Ainsi, un pointeur void se rapporte au type du pointeur, alors qu'un pointeur nul se rapporte à la valeur (adresse) du pointeur.
