5.8 — Introduction à std::string_view

Considérons le programme suivant :

#include <iostream>

int main()
{
    int x { 5 }; // x fait une copie de son initialisateur
    std::cout << x << '\n';

    return 0;
}

Lorsque la définition de x est exécutée, la valeur d'initialisation 5 est copiée dans la mémoire allouée pour la variable int x. Pour les types fondamentaux, initialiser et copier une variable est rapide.

Considérons maintenant ce programme similaire :

#include <iostream>
#include <string>

int main()
{
    std::string s{ "Hello, world!" }; // s fait une copie de son initialisateur
    std::cout << s << '\n';

    return 0;
}

Lorsque s est initialisée, la chaîne littérale de style C "Hello, world!" est copiée dans la mémoire allouée pour std::string s. Contrairement aux types fondamentaux, initialiser et copier un std::string est lent.

Dans le programme ci-dessus, nous ne faisons qu'afficher la valeur à la console, puis s est détruite. Nous avons donc essentiellement fait une copie de « Hello, world! » uniquement pour l'afficher puis détruire cette copie. C'est inefficace.

Nous observons quelque chose de similaire dans cet exemple :

#include <iostream>
#include <string>

void printString(std::string str) // str fait une copie de son initialisateur
{
    std::cout << str << '\n';
}

int main()
{
    std::string s{ "Hello, world!" }; // s fait une copie de son initialisateur
    printString(s);

    return 0;
}

Cet exemple fait deux copies de la chaîne de style C « Hello, world! » : une lorsque nous initialisons s dans main(), et une autre lorsque nous initialisons le paramètre str dans printString(). C'est beaucoup de copies inutiles juste pour afficher une chaîne !

std::string_view (C++17)

Pour résoudre le problème du coût élevé de l'initialisation (ou de la copie) d'un std::string, C++17 a introduit std::string_view (qui se trouve dans l'en-tête <string_view>). std::string_view fournit un accès en lecture seule à une chaîne existante (une chaîne de style C, un std::string ou un autre std::string_view) sans en faire une copie. En lecture seule signifie que nous pouvons accéder à la valeur observée et l'utiliser, mais que nous ne pouvons pas la modifier.

L'exemple suivant est identique au précédent, sauf que nous avons remplacé std::string par std::string_view.

#include <iostream>
#include <string_view> // C++17

// str fournit un accès en lecture seule à l'argument passé
void printSV(std::string_view str) // désormais un std::string_view
{
    std::cout << str << '\n';
}

int main()
{
    std::string_view s{ "Hello, world!" }; // désormais un std::string_view
    printSV(s);

    return 0;
}

Ce programme produit la même sortie que le précédent, mais aucune copie de la chaîne « Hello, world! » n'est faite.

Lorsque nous initialisons std::string_view s avec la chaîne littérale de style C "Hello, world!", s fournit un accès en lecture seule à « Hello, world! » sans en faire une copie. Lorsque nous passons s à printSV(), le paramètre str est initialisé à partir de s. Cela nous permet d'accéder à « Hello, world! » via str, là encore sans copier la chaîne.

Bonne pratique

Préférez std::string_view à std::string lorsque vous avez besoin d'une chaîne en lecture seule, en particulier pour les paramètres de fonction.

std::string_view peut être initialisé avec de nombreux types de chaînes différents

L'une des bonnes choses avec std::string_view est sa grande flexibilité. Un objet std::string_view peut être initialisé avec une chaîne de style C, un std::string ou un autre std::string_view :

#include <iostream>
#include <string>
#include <string_view>

int main()
{
    std::string_view s1 { "Hello, world!" }; // initialisation avec une chaîne littérale de style C
    std::cout << s1 << '\n';

    std::string s{ "Hello, world!" };
    std::string_view s2 { s };  // initialisation avec un std::string
    std::cout << s2 << '\n';

    std::string_view s3 { s2 }; // initialisation avec un std::string_view
    std::cout << s3 << '\n';

    return 0;
}

Les paramètres std::string_view acceptent de nombreux types d'arguments chaînes différents

Une chaîne de style C comme un std::string se convertissent implicitement en std::string_view. Par conséquent, un paramètre std::string_view accepte des arguments de type chaîne de style C, std::string ou std::string_view :

#include <iostream>
#include <string>
#include <string_view>

void printSV(std::string_view str)
{
    std::cout << str << '\n';
}

int main()
{
    printSV("Hello, world!"); // appel avec une chaîne littérale de style C

    std::string s2{ "Hello, world!" };
    printSV(s2); // appel avec un std::string

    std::string_view s3 { s2 };
    printSV(s3); // appel avec un std::string_view

    return 0;
}

std::string_view ne se convertit pas implicitement en std::string

Comme std::string fait une copie de son initialisateur (ce qui est coûteux), C++ n'autorise pas la conversion implicite d'un std::string_view en std::string. Cela permet d'éviter de passer accidentellement un argument std::string_view à un paramètre std::string, et de créer involontairement une copie coûteuse là où elle n'est peut-être pas nécessaire.

Cependant, si c'est voulu, nous disposons de deux options :

  1. Créer explicitement un std::string avec un initialisateur std::string_view (ce qui est autorisé, car cela se fait rarement involontairement)
  2. Convertir un std::string_view existant en std::string à l'aide de static_cast

L'exemple suivant montre les deux options :

#include <iostream>
#include <string>
#include <string_view>

void printString(std::string str)
{
    std::cout << str << '\n';
}

int main()
{
    std::string_view sv{ "Hello, world!" };

    // printString(sv);   // erreur de compilation : pas de conversion implicite de std::string_view en std::string

    std::string s{ sv }; // correct : nous pouvons créer un std::string avec un initialisateur std::string_view
    printString(s);      // et appeler la fonction avec le std::string

    printString(static_cast<std::string>(sv)); // correct : nous pouvons convertir explicitement un std::string_view en std::string

    return 0;
}

L'affectation modifie la chaîne observée par le std::string_view

Affecter une nouvelle chaîne à un std::string_view fait que le std::string_view observe la nouvelle chaîne. Cela ne modifie en rien la chaîne précédemment observée.

L'exemple suivant l'illustre :

#include <iostream>
#include <string>
#include <string_view>

int main()
{
    std::string name { "Alex" };
    std::string_view sv { name }; // sv observe désormais name
    std::cout << sv << '\n'; // affiche Alex

    sv = "John"; // sv observe désormais "John" (ne modifie pas name)
    std::cout << sv << '\n'; // affiche John

    std::cout << name << '\n'; // affiche Alex

    return 0;
}

Dans l'exemple ci-dessus, sv = "John" fait que sv observe désormais la chaîne "John". Cela ne modifie pas la valeur détenue par name (qui vaut toujours "Alex").

Littéraux pour std::string_view

Les chaînes littérales entre guillemets doubles sont par défaut des chaînes littérales de style C. Nous pouvons créer des chaînes littérales de type std::string_view en ajoutant le suffixe sv après la chaîne littérale entre guillemets doubles. Le sv doit être en minuscules.

#include <iostream>
#include <string>      // pour std::string
#include <string_view> // pour std::string_view

int main()
{
    using namespace std::string_literals;      // accède au suffixe s
    using namespace std::string_view_literals; // accède au suffixe sv

    std::cout << "foo\n";   // sans suffixe, il s'agit d'une chaîne littérale de style C
    std::cout << "goo\n"s;  // le suffixe s désigne une chaîne littérale std::string
    std::cout << "moo\n"sv; // le suffixe sv désigne une chaîne littérale std::string_view

    return 0;
}

Contenu associé

Nous abordons cette utilisation de using namespace dans la leçon 5.7 -- Introduction à std::string. Le même conseil s'applique ici.

Il est permis d'initialiser un objet std::string_view avec une chaîne littérale de style C (vous n'avez pas besoin de l'initialiser avec un littéral std::string_view).

Cela dit, initialiser un std::string_view avec un littéral std::string_view ne pose pas de problème (car ces littéraux sont en réalité des chaînes littérales de style C déguisées).

std::string_view constexpr

Contrairement à std::string, std::string_view est entièrement compatible avec constexpr :

#include <iostream>
#include <string_view>

int main()
{
    constexpr std::string_view s{ "Hello, world!" }; // s est une constante symbolique de chaîne
    std::cout << s << '\n'; // s sera remplacée par "Hello, world!" à la compilation

    return 0;
}

Cela fait de constexpr std::string_view le choix privilégié lorsqu'il faut des constantes symboliques de chaîne.
