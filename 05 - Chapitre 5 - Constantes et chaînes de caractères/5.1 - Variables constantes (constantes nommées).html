5.1 — Variables constantes (constantes nommées)

Introduction aux constantes

En programmation, une constante est une valeur qui ne peut pas être modifiée pendant l'exécution du programme.

C++ prend en charge deux sortes de constantes :

  • Les constantes nommées sont des valeurs constantes associées à un identificateur. On les appelle aussi parfois constantes symboliques.
  • Les constantes littérales sont des valeurs constantes qui ne sont pas associées à un identificateur.

Nous commencerons par les constantes nommées. Nous aborderons ensuite les constantes littérales (dans la prochaine leçon 5.2 -- Littéraux).

Types de constantes nommées

Il existe trois façons de définir une constante nommée en C++ :

  • Les variables constantes (traitées dans cette leçon).
  • Les macros de type objet avec texte de substitution (introduites dans la leçon 2.10 -- Introduction au préprocesseur, et approfondies dans cette leçon).
  • Les constantes énumérées (traitées dans la leçon 13.2 -- Énumérations non délimitées).

Les variables constantes sont le type de constante nommée le plus courant ; commençons donc par elles.

Variables constantes

Jusqu'à présent, toutes les variables que nous avons vues étaient non constantes, c'est-à-dire que leur valeur peut être modifiée à tout moment (généralement par une affectation). Par exemple :

int main()
{
    int x { 4 }; // x est une variable non constante
    x = 5; // change la valeur de x à 5 à l'aide de l'opérateur d'affectation

    return 0;
}

Cependant, il existe de nombreux cas où il est utile de définir des variables dont la valeur ne peut pas être modifiée. Prenons par exemple la pesanteur terrestre (près de la surface) : 9,8 mètres par seconde carrée. Cette valeur ne risque pas de changer de sitôt (et si elle changeait, vous auriez probablement des problèmes bien plus graves que d'apprendre le C++). Définir cette valeur comme constante permet de garantir qu'elle ne sera pas modifiée par accident. Les constantes présentent d'autres avantages que nous explorerons dans les leçons suivantes.

Bien que ce soit un oxymore bien connu, une variable dont la valeur ne peut plus être modifiée après son initialisation est appelée variable constante.

Déclarer une variable const

Pour déclarer une variable constante, on place le mot-clé const (appelé « qualificateur const ») à côté du type de l'objet :

const double gravity { 9.8 };  // usage préféré : const avant le type
int const sidesInSquare { 4 }; // style « east const », acceptable mais non préféré

Bien que C++ accepte le qualificateur const avant ou après le type, il est beaucoup plus courant de placer const avant le type, car cela respecte mieux la convention de la langue anglaise, où les modificateurs précèdent l'objet modifié (on dit « a green ball », un « ballon vert », et non « a ball green »).

En passant…

En raison de la manière dont le compilateur analyse les déclarations plus complexes, certains développeurs préfèrent placer const après le type (c'est légèrement plus cohérent). Ce style est appelé « east const ». Bien qu'il ait ses défenseurs (et quelques arguments raisonnables), il ne s'est pas vraiment imposé.

Bonne pratique

Placez const avant le type (c'est la convention la plus répandue).

Point clé

Le type d'un objet inclut le qualificateur const. Ainsi, lorsque nous définissons const double gravity { 9.8 };, le type de gravity est const double.

Les variables const doivent être initialisées

Les variables const doivent être initialisées lors de leur définition, et cette valeur ne peut ensuite plus être modifiée par affectation :

int main()
{
    const double gravity; // erreur : les variables const doivent être initialisées
    gravity = 9.9;        // erreur : les variables const ne peuvent pas être modifiées

    return 0;
}

Notez qu'une variable const peut être initialisée à partir d'autres variables (y compris des variables non constantes) :

#include <iostream>

int main()
{
    std::cout << "Enter your age: ";
    int age{};
    std::cin >> age;

    const int constAge { age }; // initialise une variable const à partir d'une valeur non constante

    age = 5;      // ok : age n'est pas const, nous pouvons donc changer sa valeur
    constAge = 6; // erreur : constAge est const, nous ne pouvons donc pas changer sa valeur

    return 0;
}

Dans l'exemple ci-dessus, nous initialisons la variable const constAge avec la variable non constante age. Comme age reste non constante, nous pouvons modifier sa valeur. En revanche, constAge étant const, nous ne pouvons pas modifier la valeur qu'elle possède après son initialisation.

Point clé

L'initialiseur d'une variable const peut être une valeur non constante.

Nommer vos variables const

Il existe plusieurs conventions de nommage pour les variables const.

Les programmeurs venant du C préfèrent souvent des noms en majuscules avec des tirets bas (par exemple EARTH_GRAVITY). En C++, on utilise plus couramment des noms en casse mixte précédés du préfixe « k » (par exemple kEarthGravity).

Cependant, comme les variables const se comportent comme des variables normales (si ce n'est qu'on ne peut pas leur affecter de valeur), rien ne justifie une convention de nommage particulière. C'est pourquoi nous préférons utiliser la même convention que pour les variables non constantes (par exemple earthGravity).

Paramètres const des fonctions

Les paramètres de fonction peuvent être rendus constants grâce au mot-clé const :

#include <iostream>

void printInt(const int x)
{
    std::cout << x << '\n';
}

int main()
{
    printInt(5); // 5 sera utilisé comme initialiseur de x
    printInt(6); // 6 sera utilisé comme initialiseur de x

    return 0;
}

Notez que nous n'avons pas fourni d'initialiseur explicite pour le paramètre const x : la valeur de l'argument passé lors de l'appel de fonction sera utilisée comme initialiseur de x.

Rendre un paramètre de fonction constant permet au compilateur de s'assurer que sa valeur n'est pas modifiée à l'intérieur de la fonction. Cependant, en C++ moderne, nous ne mettons pas les paramètres par valeur en const, car nous ne nous soucions généralement pas que la fonction modifie la valeur du paramètre (puisqu'il ne s'agit que d'une copie qui sera de toute façon détruite à la fin de la fonction). Le mot-clé const ajoute aussi un peu de encombrement inutile à la déclaration de la fonction.

Bonne pratique

N'utilisez pas const pour les paramètres passés par valeur.

Plus tard dans cette série de tutoriels, nous verrons deux autres façons de passer des arguments aux fonctions : le passage par référence et le passage par adresse. Avec ces méthodes, un usage correct de const est important.

Valeurs de retour const

La valeur de retour d'une fonction peut également être const :

#include <iostream>

const int getValue()
{
    return 5;
}

int main()
{
    std::cout << getValue() << '\n';

    return 0;
}

Pour les types fondamentaux, le qualificateur const appliqué à un type de retour est simplement ignoré (votre compilateur peut générer un avertissement).

Pour les autres types (que nous verrons plus tard), il n'est généralement pas utile de renvoyer des objets const par valeur, car ce sont des copies temporaires qui seront de toute façon détruites. Renvoyer une valeur const peut également empêcher certaines optimisations du compilateur (liées à la sémantique de déplacement), ce qui peut entraîner des performances moindres.

Bonne pratique

N'utilisez pas const pour une valeur de retour passée par valeur.

Pourquoi rendre les variables constantes

Si une variable peut être rendue constante, elle doit généralement l'être. Cela est important pour plusieurs raisons :

  • Cela réduit le risque de bugs. En rendant une variable constante, vous vous assurez que sa valeur ne peut pas être modifiée par accident.
  • Cela donne au compilateur davantage de possibilités d'optimiser le programme. Lorsque le compilateur peut supposer qu'une valeur ne change pas, il peut appliquer davantage de techniques d'optimisation, ce qui produit un programme compilé plus petit et plus rapide. Nous en reparlerons plus loin dans ce chapitre.
  • Surtout, cela réduit la complexité globale de nos programmes. Lorsque nous essayons de comprendre ce que fait une section de code ou de déboguer un problème, nous savons qu'une variable const ne peut pas voir sa valeur changer : nous n'avons donc pas à nous demander si sa valeur change réellement, vers quelle valeur elle change, ni si cette nouvelle valeur est correcte.

Point clé

Chaque élément mobile d'un système augmente la complexité et le risque de défaut ou de panne. Les variables non constantes sont des éléments mobiles, alors que les variables constantes ne le sont pas.

Bonne pratique

Rendez les variables constantes chaque fois que c'est possible. Les exceptions incluent les paramètres passés par valeur et les types de retour par valeur, qui ne doivent généralement pas être rendus constants.

Macros de type objet avec texte de substitution

Dans la leçon 2.10 -- Introduction au préprocesseur, nous avons abordé les macros de type objet avec texte de substitution. Par exemple :

#include <iostream>

#define MY_NAME "Alex"

int main()
{
    std::cout << "My name is: " << MY_NAME << '\n';

    return 0;
}

Lorsque le préprocesseur traite le fichier contenant ce code, il remplace MY_NAME (à la ligne 7) par "Alex". Notez que MY_NAME est un nom et que le texte de substitution est une valeur constante : les macros de type objet avec texte de substitution sont donc, elles aussi, des constantes nommées.

Préférer les variables constantes aux macros du préprocesseur

Pourquoi, alors, ne pas utiliser les macros du préprocesseur pour les constantes nommées ? Il existe (au moins) trois problèmes majeurs.

Le plus important est que les macros ne respectent pas les règles de portée normales du C++. Une fois qu'une macro a été définie avec #define, toutes les occurrences ultérieures de son nom dans le fichier courant sont remplacées. Si ce nom est utilisé ailleurs, une substitution de macro se produira là où vous ne la souhaitez pas. Cela entraînera très probablement d'étranges erreurs de compilation. Par exemple :

#include <iostream>

void someFcn()
{
// Même si gravity est défini à l'intérieur de cette fonction,
// le préprocesseur remplacera toutes les occurrences ultérieures de gravity dans le reste du fichier
#define gravity 9.8
}

void printGravity(double gravity) // y compris celle-ci, ce qui provoque une erreur de compilation
{
    std::cout << "gravity: " << gravity << '\n';
}

int main()
{
    printGravity(3.71);

    return 0;
}

À la compilation, GCC a produit cette erreur déroutante :


prog.cc:7:17: error: expected ',' or '...' before numeric constant
    5 | #define gravity 9.8
      |                 ^~~
prog.cc:10:26: note: in expansion of macro 'gravity'

Deuxièmement, il est souvent plus difficile de déboguer du code qui utilise des macros. Bien que votre code source contienne le nom de la macro, le compilateur et le débogueur ne voient jamais la macro, car elle a déjà été remplacée avant leur exécution. De nombreux débogueurs ne peuvent pas inspecter la valeur d'une macro, et leurs capacités sont souvent limitées lorsqu'ils travaillent avec des macros.

Troisièmement, la substitution de macro se comporte différemment de tout le reste en C++. Des erreurs d'inattention peuvent donc facilement se produire.

Les variables constantes n'ont aucun de ces problèmes : elles respectent les règles de portée normales, sont visibles par le compilateur et le débogueur, et se comportent de manière cohérente.

Bonne pratique

Préférez les variables constantes aux macros de type objet avec texte de substitution.

Utiliser des variables constantes dans un programme composé de plusieurs fichiers

Dans de nombreuses applications, une constante nommée donnée doit être utilisée dans l'ensemble de votre code (et pas seulement dans un fichier). Il peut s'agir de constantes physiques ou mathématiques qui ne changent pas (par exemple pi ou le nombre d'Avogadro), ou de valeurs de « réglage » propres à l'application (par exemple des coefficients de frottement ou de gravité). Plutôt que de les redéfinir chaque fois qu'elles sont nécessaires, il est préférable de les déclarer une seule fois à un emplacement centralisé, puis de les utiliser partout où c'est nécessaire. Ainsi, si vous devez les modifier, il suffit de le faire à un seul endroit.

C++ offre plusieurs moyens d'y parvenir. Nous traitons ce sujet en détail dans la leçon 7.10 -- Partager des constantes globales entre plusieurs fichiers (à l'aide de variables inline).

Terminologie : qualificateurs de type

Un qualificateur de type (parfois appelé simplement qualificateur) est un mot-clé appliqué à un type, qui modifie la manière dont ce type se comporte. Le const utilisé pour déclarer une variable constante est appelé qualificateur de type const (ou simplement qualificateur const).

Depuis C++23, C++ ne compte que deux qualificateurs de type : const et volatile.

Lecture facultative

Le qualificateur volatile sert à indiquer au compilateur qu'un objet peut voir sa valeur modifiée à tout moment. Ce qualificateur rarement utilisé désactive certains types d'optimisations.

Dans la documentation technique, les qualificateurs const et volatile sont souvent désignés par le terme qualificateurs cv. Les termes suivants sont également employés dans la norme C++ :

  • Un type sans qualificateur cv est un type sans aucun qualificateur de type (par exemple int).
  • Un type avec qualificateur cv est un type auquel on a appliqué un ou plusieurs qualificateurs de type (par exemple const int).
  • Un type éventuellement qualifié cv est un type qui peut être sans qualificateur cv ou avec qualificateur cv.

Ces termes sont peu utilisés en dehors de la documentation technique ; ils sont donc listés ici à titre de référence, et non pour que vous les reteniez.
