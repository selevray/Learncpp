5.2 — Littéraux

Les littéraux (literals) sont des valeurs insérées directement dans le code. Par exemple :

return 5;                     // 5 est un littéral entier
bool myNameIsAlex { true };   // true est un littéral booléen
double d { 3.4 };             // 3.4 est un littéral de type double
std::cout << "Hello, world!"; // "Hello, world!" est un littéral de chaîne de style C

Les littéraux sont parfois appelés constantes littérales (literal constants) parce que leur signification ne peut pas être redéfinie (5 signifie toujours la valeur entière 5).

Le type d'un littéral

De même que les objets ont un type, tous les littéraux ont un type. Le type d'un littéral est déduit de sa valeur. Par exemple, un littéral qui est un nombre entier (par exemple 5) est déduit de type int.

Par défaut :

Valeur du littéral Exemples Type par défaut du littéral Remarque
valeur entière 5, 0, -3 int
valeur booléenne true, false bool
valeur à virgule flottante 1.2, 0.0, 3.4 double (pas float !)
caractère ‘a’, ‘\n’ char
chaîne de style C “Hello, world!” const char[14] voir la section sur les littéraux de chaîne de style C ci-dessous

Suffixes de littéraux

Si le type par défaut d'un littéral ne convient pas, vous pouvez changer son type en ajoutant un suffixe. Voici quelques-uns des suffixes les plus courants :

Type de données Suffixe Signification
entier u ou U unsigned int
entier l ou L long
entier ul, uL, Ul, UL, lu, lU, Lu, LU unsigned long
entier ll ou LL long long
entier ull, uLL, Ull, ULL, llu, llU, LLu, LLU unsigned long long
entier z ou Z La version signée de std::size_t (C++23)
entier uz, uZ, Uz, UZ, zu, zU, Zu, ZU std::size_t (C++23)
virgule flottante f ou F float
virgule flottante l ou L long double
chaîne s std::string
chaîne sv std::string_view

Nous reviendrons dans un instant sur les littéraux entiers et à virgule flottante ainsi que sur leurs suffixes.

Dans la plupart des cas, les suffixes ne sont pas nécessaires (sauf f).

Contenu connexe

Les suffixes s et sv nécessitent une ligne de code supplémentaire pour être utilisés. Nous les étudions plus en détail dans les leçons 5.7 -- Introduction à std::string et 5.8 -- Introduction à std::string_view.

D'autres suffixes (rarement utilisés) existent pour les nombres complexes et les littéraux de temps (chrono). Ils sont documentés ici.

Pour les lecteurs avancés

À l'exception du suffixe f, les suffixes sont surtout utilisés lorsqu'une déduction de type intervient. Voir 10.8 -- Déduction de type pour les objets avec le mot-clé auto et 13.14 -- Déduction d'arguments de modèle de classe (CTAD) et guides de déduction.

Casse des suffixes

La plupart des suffixes ne sont pas sensibles à la casse. Les exceptions sont :

  • s et sv doivent être en minuscules.
  • Deux caractères l ou L consécutifs doivent avoir la même casse (lL et Ll ne sont pas acceptés).

Comme le l minuscule peut ressembler au chiffre 1 dans certaines polices, certains développeurs préfèrent utiliser des littéraux en majuscules. D'autres utilisent des suffixes en minuscules, à l'exception de L.

Bonne pratique

Préférez le suffixe L (majuscule) au suffixe l (minuscule).

Littéraux entiers

Vous n'aurez généralement pas besoin de suffixes pour les littéraux entiers, mais voici quelques exemples :

#include <iostream>

int main()
{
    std::cout << 5 << '\n';  // 5 (sans suffixe) est de type int (par défaut)
    std::cout << 5L << '\n'; // 5L est de type long
    std::cout << 5u << '\n'; // 5u est de type unsigned int

    return 0;
}

Dans la plupart des cas, il est correct d'utiliser des littéraux int sans suffixe, même pour initialiser des types autres que int :

int main()
{
    int a { 5 };          // ok : les types correspondent
    unsigned int b { 6 }; // ok : le compilateur convertit la valeur int 6 en valeur unsigned int 6
    long c { 7 };         // ok : le compilateur convertit la valeur int 7 en valeur long 7

    return 0;
}

Dans de tels cas, le compilateur convertit le littéral int vers le type approprié.

Dans le premier cas, 5 est déjà un int par défaut, donc le compilateur peut utiliser directement cette valeur pour initialiser la variable int a. Dans le deuxième cas, la valeur int 6 ne correspond pas au type de unsigned int b. Le compilateur convertit la valeur int 6 en valeur unsigned int 6, puis utilise celle-ci pour initialiser b. Dans le troisième cas, la valeur int 7 ne correspond pas au type de long c. Le compilateur convertit la valeur int 7 en valeur long 7, puis utilise celle-ci pour initialiser c.

Littéraux à virgule flottante

Par défaut, les littéraux à virgule flottante sont de type double. Pour en faire des littéraux float, il faut utiliser le suffixe f (ou F) :

#include <iostream>

int main()
{
    std::cout << 5.0 << '\n';  // 5.0 (sans suffixe) est de type double (par défaut)
    std::cout << 5.0f << '\n'; // 5.0f est de type float

    return 0;
}

Les nouveaux programmeurs se demandent souvent pourquoi le code suivant provoque un avertissement du compilateur :

float f { 4.1 }; // avertissement : 4.1 est un littéral double, et non un littéral float

Comme 4.1 n'a pas de suffixe, le littéral est de type double, et non float. Lorsque le compilateur détermine le type d'un littéral, il ne se soucie pas de ce que vous faites avec celui-ci (dans ce cas, initialiser une variable float). Comme le type du littéral (double) ne correspond pas au type de la variable qu'il sert à initialiser (float), la valeur du littéral doit être convertie en float avant de pouvoir initialiser la variable f. La conversion d'une valeur de double en float peut entraîner une perte de précision, c'est pourquoi le compilateur émet un avertissement.

La solution consiste à faire l'une des deux choses suivantes :

float f { 4.1f }; // utilisez le suffixe 'f' pour que le littéral soit un float et corresponde au type float de la variable
double d { 4.1 }; // changez le type de la variable en double pour qu'il corresponde au type double du littéral

Notation scientifique pour les littéraux à virgule flottante

Il existe deux façons d'écrire les littéraux à virgule flottante.

  1. En notation standard, on écrit un nombre avec un point décimal :
double pi { 3.14159 }; // 3.14159 est un littéral double en notation standard
double d { -1.23 };    // le littéral peut être négatif
double why { 0. };     // syntaxiquement correct, mais à éviter car le point décimal est difficile à voir (préférez 0.0)
  1. En notation scientifique, on ajoute un e pour représenter l'exposant :
double avogadro { 6.02e23 }; // 6.02 x 10^23 est un littéral double en notation scientifique
double protonCharge { 1.6e-19 }; // la charge d'un proton est 1.6 x 10^-19

Littéraux de chaîne

En programmation, une chaîne de caractères (string) est une suite de caractères utilisée pour représenter du texte (comme des noms, des mots ou des phrases).

Le tout premier programme C++ que vous avez écrit ressemblait probablement à ceci :

#include <iostream>

int main()
{
    std::cout << "Hello, world!";
    return 0;
}

"Hello, world!" est un littéral de chaîne. Les littéraux de chaîne sont placés entre guillemets doubles pour les identifier comme des chaînes (par opposition aux littéraux de caractère, placés entre apostrophes).

Comme les chaînes sont couramment utilisées dans les programmes, la plupart des langages de programmation modernes incluent un type de chaîne fondamental. Pour des raisons historiques, les chaînes ne sont pas un type fondamental en C++. Elles ont plutôt un type étrange et compliqué, difficile à manipuler (nous verrons comment et pourquoi dans une leçon ultérieure, une fois les notions fondamentales nécessaires à leur explication couvertes). Ces chaînes sont souvent appelées chaînes C (C strings) ou chaînes de style C (C-style strings), car elles sont héritées du langage C.

Il y a deux points non évidents à connaître au sujet des littéraux de chaîne de style C.

  1. Tous les littéraux de chaîne de style C possèdent un terminateur nul implicite. Prenons une chaîne telle que "hello". Bien que cette chaîne de style C semble ne comporter que cinq caractères, elle en comporte en réalité six : 'h', 'e', 'l', 'l', 'o', et '\0' (un caractère de code ASCII 0). Ce caractère '\0' final est un caractère spécial appelé terminateur nul (null terminator), et il sert à indiquer la fin de la chaîne. Une chaîne qui se termine par un terminateur nul est appelée chaîne terminée par un caractère nul (null-terminated string).

Pour les lecteurs avancés

C'est la raison pour laquelle la chaîne "Hello, world!" est de type const char[14] et non const char[13] : le terminateur nul caché compte comme un caractère.

La raison du terminateur nul est également historique : il permet de déterminer où la chaîne se termine.

  1. Contrairement à la plupart des autres littéraux (qui sont des valeurs, et non des objets), les littéraux de chaîne de style C sont des objets const créés au démarrage du programme, dont l'existence est garantie pendant toute la durée du programme. Ce point deviendra important dans quelques leçons, lorsque nous aborderons std::string_view.

Point clé

Les littéraux de chaîne de style C sont des objets const créés au démarrage du programme, dont l'existence est garantie pendant toute la durée du programme.

Contrairement aux littéraux de chaîne de style C, les littéraux std::string et std::string_view créent des objets temporaires. Ces objets temporaires doivent être utilisés immédiatement, car ils sont détruits à la fin de l'expression complète dans laquelle ils sont créés.

Contenu connexe

Nous étudions les littéraux std::string et std::string_view respectivement dans les leçons 5.7 -- Introduction à std::string et 5.8 -- Introduction à std::string_view.

Nombres magiques

Un nombre magique (magic number) est un littéral (généralement un nombre) dont la signification n'est pas claire ou qui peut devoir être modifié ultérieurement.

Voici deux instructions qui illustrent des exemples de nombres magiques :

const int maxStudentsPerSchool{ numClassrooms * 30 };
setMax(30);

Que signifient les littéraux 30 dans ces contextes ? Dans le premier cas, vous pouvez probablement deviner qu'il s'agit du nombre d'élèves par classe, mais ce n'est pas immédiatement évident. Dans le second, qui sait ? Il faudrait aller examiner la fonction pour savoir ce qu'elle fait.

Dans les programmes complexes, il peut être très difficile de deviner ce que représente un littéral, à moins qu'un commentaire ne l'explique.

L'utilisation de nombres magiques est généralement considérée comme une mauvaise pratique, car, en plus de ne pas indiquer à quoi ils servent, ils posent problème si la valeur doit changer. Supposons que l'école achète de nouveaux bureaux permettant de porter la taille des classes de 30 à 35 élèves, et que notre programme doive le refléter.

Pour cela, nous devons remplacer un ou plusieurs littéraux 30 par 35. Mais lesquels ? Le 30 dans l'initialisation de maxStudentsPerSchool semble évident. Mais qu'en est-il du 30 passé en argument à setMax() ? Ce 30 a-t-il la même signification que l'autre ? Si oui, il doit être mis à jour. Sinon, il doit rester tel quel, faute de quoi nous risquerions de casser notre programme ailleurs. Si vous effectuez un remplacement global, vous risquez de modifier par inadvertance l'argument de setMax() alors qu'il ne devait pas changer. Il faut donc parcourir tout le code à la recherche de chaque occurrence du littéral 30 (il peut y en avoir des centaines), puis décider individuellement si chacune doit changer ou non. Cela peut prendre énormément de temps (et être source d'erreurs).

Heureusement, le manque de contexte et les difficultés de mise à jour peuvent être facilement résolus en utilisant des constantes symboliques :

const int maxStudentsPerClass { 30 };
const int totalStudents{ numClassrooms * maxStudentsPerClass }; // il est maintenant évident de savoir ce que représente ce 30

const int maxNameLength{ 30 };
setMax(maxNameLength); // il est maintenant évident que ce 30 est utilisé dans un autre contexte

Le nom de la constante fournit le contexte, et il suffit de modifier la valeur à un seul endroit pour la changer dans l'ensemble du programme.

Notez que les nombres magiques ne sont pas toujours des nombres : ils peuvent aussi être du texte (par exemple des noms) ou d'autres types :

int main()
{
    printAppWelcome("MyCalculator"); // mauvais : le nom de l'application peut être utilisé à d'autres endroits ou changer à l'avenir
}

Les littéraux utilisés dans des contextes évidents, peu susceptibles de changer, ne sont généralement pas considérés comme magiques. Les valeurs -1, 0, 0.0 et 1 sont souvent utilisées dans de tels contextes :

int idGenerator { 0 };         // ok : nous initialisons notre générateur d'identifiants à la valeur 0
idGenerator = idGenerator + 1; // ok : nous ne faisons qu'incrémenter notre générateur

D'autres nombres peuvent aussi être évidents dans leur contexte (et donc ne pas être considérés comme magiques) :

int kmtoM(int km)
{
    return km * 1000; // ok : il est évident que 1000 est un facteur de conversion
}

Les identifiants entiers séquentiels ne sont généralement pas non plus considérés comme magiques :

int main()
{
    // ok : il ne s'agit que d'identifiants/compteurs séquentiels
    printPlayerInfo(1); // `1` ne gagnerait pas vraiment à être nommé `player1` à la place
    printPlayerInfo(2);
}

Bonne pratique

Évitez les nombres magiques dans votre code (utilisez plutôt des variables constexpr, voir la leçon 5.6 -- Variables constexpr).
