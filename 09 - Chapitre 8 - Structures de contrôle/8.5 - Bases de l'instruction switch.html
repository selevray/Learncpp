8.5 — Bases de l'instruction switch

Il est possible d'enchaîner de nombreuses instructions if-else, mais cela est à la fois difficile à lire et inefficace. Considérez le programme suivant :

#include <iostream>

void printDigitName(int x)
{
    if (x == 1)
        std::cout << "One";
    else if (x == 2)
        std::cout << "Two";
    else if (x == 3)
        std::cout << "Three";
    else
        std::cout << "Unknown";
}

int main()
{
    printDigitName(2);
    std::cout << '\n';

    return 0;
}

La variable x de printDigitName() sera évaluée jusqu'à trois fois selon la valeur passée (ce qui est inefficace), et le lecteur doit s'assurer qu'il s'agit bien de x évaluée à chaque fois (et non d'une autre variable).

Comme tester une variable ou une expression pour l'égalité avec un ensemble de valeurs différentes est courant, C++ fournit une instruction conditionnelle alternative, appelée instruction switch, spécialisée pour cet usage. Voici le même programme que ci-dessus, écrit avec un switch :

#include <iostream>

void printDigitName(int x)
{
    switch (x)
    {
    case 1:
        std::cout << "One";
        return;
    case 2:
        std::cout << "Two";
        return;
    case 3:
        std::cout << "Three";
        return;
    default:
        std::cout << "Unknown";
        return;
    }
}

int main()
{
    printDigitName(2);
    std::cout << '\n';

    return 0;
}

L'idée derrière une instruction switch est simple : une expression (parfois appelée la condition) est évaluée pour produire une valeur.

Ensuite, l'un des cas suivants se produit :

  • Si la valeur de l'expression est égale à la valeur d'un des labels case, les instructions placées après le label case correspondant sont exécutées.
  • Si aucune valeur correspondante n'est trouvée et qu'un label default existe, les instructions placées après le label default sont exécutées.
  • Si aucune valeur correspondante n'est trouvée et qu'il n'existe pas de label default, le switch est ignoré.

Examinons chacun de ces concepts plus en détail.

Démarrer un switch

On commence une instruction switch avec le mot-clé switch, suivi de parenthèses contenant l'expression conditionnelle à évaluer. Souvent, cette expression se réduit à une seule variable, mais il peut s'agir de n'importe quelle expression valide.

La condition d'un switch doit être évaluée à un type entier (voir la leçon 4.1 -- Introduction aux types fondamentaux si vous avez besoin de rappeler quels types fondamentaux sont considérés comme entiers) ou à un type énuméré (traités dans les leçons à venir 13.2 -- Énumérations non délimitées et 13.6 -- Énumérations délimitées (enum class)), ou être convertible en l'un de ces types. Les expressions qui s'évaluent en nombres à virgule flottante, en chaînes de caractères et la plupart des autres types non entiers ne peuvent pas être utilisées ici.

Pour les lecteurs avancés

Pourquoi le type du switch n'autorise-t-il que les types entiers (ou énumérés) ? La réponse est que les instructions switch sont conçues pour être hautement optimisées. Historiquement, la façon la plus courante pour les compilateurs d'implémenter les switch est via des tables de sauts, et les tables de sauts ne fonctionnent qu'avec des valeurs entières.

Pour ceux d'entre vous qui connaissent déjà les tableaux, une table de sauts fonctionne à peu près comme un tableau : une valeur entière sert d'indice de tableau pour « sauter » directement vers un résultat. Cela peut être bien plus efficace que de nombreuses comparaisons séquentielles.

Bien sûr, les compilateurs ne sont pas obligés d'implémenter les switch avec des tables de sauts, et parfois ils ne le font pas. Il n'y a techniquement aucune raison pour que C++ ne puisse pas assouplir cette restriction afin d'autoriser d'autres types, mais cela n'a pas encore été fait (en date de C++23).

Après l'expression conditionnelle, on déclare un bloc. Dans ce bloc, on utilise des labels pour définir toutes les valeurs que l'on souhaite tester pour l'égalité. Il existe deux sortes de labels utilisés avec les instructions switch, que nous verrons ensuite.

Les labels case

Le premier type de label est le label case, déclaré avec le mot-clé case et suivi d'une expression constante. L'expression constante doit être du même type que la condition ou être convertible vers ce type.

Si la valeur de l'expression conditionnelle est égale à l'expression placée après un label case, l'exécution commence à la première instruction qui suit ce label case et se poursuit ensuite séquentiellement.

Voici un exemple où la condition correspond à un label case :

#include <iostream>

void printDigitName(int x)
{
    switch (x) // x est évaluée pour produire la valeur 2
    {
    case 1:
        std::cout << "One";
        return;
    case 2: // qui correspond au label case ici
        std::cout << "Two"; // donc l'exécution commence ici
        return; // puis on retourne à l'appelant
    case 3:
        std::cout << "Three";
        return;
    default:
        std::cout << "Unknown";
        return;
    }
}

int main()
{
    printDigitName(2);
    std::cout << '\n';

    return 0;
}

Ce code affiche :


Two

Dans le programme ci-dessus, x est évaluée pour produire la valeur 2. Comme il existe un label case de valeur 2, l'exécution saute à l'instruction située sous ce label case correspondant. Le programme affiche Two, puis l'instruction return est exécutée, ce qui retourne à l'appelant.

Il n'y a pas de limite pratique au nombre de labels case que l'on peut utiliser, mais tous les labels case d'un switch doivent être uniques. Vous ne pouvez donc pas écrire ceci :

switch (x)
{
case 54:
case 54:  // erreur : la valeur 54 est déjà utilisée !
case '6': // erreur : '6' se convertit en la valeur entière 54, qui est déjà utilisée
}

Si l'expression conditionnelle ne correspond à aucun des labels case, aucun cas n'est exécuté. Nous montrerons bientôt un exemple de ce comportement.

Le label default

Le second type de label est le label default (souvent appelé cas default), déclaré avec le mot-clé default. Si l'expression conditionnelle ne correspond à aucun label case et qu'un label default existe, l'exécution commence à la première instruction qui suit le label default.

Voici un exemple où la condition correspond au label default :

#include <iostream>

void printDigitName(int x)
{
    switch (x) // x est évaluée pour produire la valeur 5
    {
    case 1:
        std::cout << "One";
        return;
    case 2:
        std::cout << "Two";
        return;
    case 3:
        std::cout << "Three";
        return;
    default: // qui ne correspond à aucun label case
        std::cout << "Unknown"; // donc l'exécution commence ici
        return; // puis on retourne à l'appelant
    }
}

int main()
{
    printDigitName(5);
    std::cout << '\n';

    return 0;
}

Ce code affiche :


Unknown

Le label default est facultatif, et il ne peut y avoir qu'un seul label default par instruction switch. Par convention, le cas default est placé en dernier dans le bloc switch.

Bonne pratique

Placez le cas default en dernier dans le bloc switch.

Aucun label case correspondant et pas de cas default

Si la valeur de l'expression conditionnelle ne correspond à aucun des labels case, et qu'aucun cas default n'est fourni, alors aucun cas du switch n'est exécuté. L'exécution se poursuit après la fin du bloc switch.

#include <iostream>

void printDigitName(int x)
{
    switch (x) // x est évaluée pour produire la valeur 5
    {
    case 1:
        std::cout << "One";
        return;
    case 2:
        std::cout << "Two";
        return;
    case 3:
        std::cout << "Three";
        return;
    // aucun cas correspondant n'existe et il n'y a pas de cas default
    }

    // donc l'exécution continue ici
    std::cout << "Hello";
}

int main()
{
    printDigitName(5);
    std::cout << '\n';

    return 0;
}

Dans l'exemple ci-dessus, x vaut 5, mais aucun label case ne correspond à 5, et il n'y a pas non plus de cas default. Par conséquent, aucun cas n'est exécuté. L'exécution se poursuit après le bloc switch, en affichant Hello.

Faire une pause

Dans les exemples précédents, nous avons utilisé des instructions return pour arrêter l'exécution des instructions situées après nos labels. Cependant, cela quitte aussi entièrement la fonction.

Une instruction break (déclarée avec le mot-clé break) indique au compilateur que nous avons fini d'exécuter les instructions du switch, et que l'exécution doit se poursuivre avec l'instruction placée après la fin du bloc switch. Cela permet de sortir d'une instruction switch sans quitter toute la fonction.

Voici un exemple légèrement modifié, réécrit avec break au lieu de return :

#include <iostream>

void printDigitName(int x)
{
    switch (x) // x vaut 3
    {
    case 1:
        std::cout << "One";
        break;
    case 2:
        std::cout << "Two";
        break;
    case 3:
        std::cout << "Three"; // l'exécution commence ici
        break; // saut à la fin du bloc switch
    default:
        std::cout << "Unknown";
        break;
    }

    // l'exécution continue ici
    std::cout << " Ah-Ah-Ah!";
}

int main()
{
    printDigitName(3);
    std::cout << '\n';

    return 0;
}

L'exemple ci-dessus affiche :


Three Ah-Ah-Ah!

Bonne pratique

Chaque ensemble d'instructions placé sous un label doit se terminer par une instruction break ou une instruction return. Cela vaut aussi pour les instructions situées sous le dernier label du switch.

Que se passe-t-il donc si l'on ne termine pas un ensemble d'instructions sous un label par break ou return ? Nous explorerons ce sujet, et d'autres, dans la prochaine leçon.

Les labels ne sont conventionnellement pas indentés

Dans la leçon 2.9 -- Collisions de noms et introduction aux espaces de noms, nous avons indiqué que le code est généralement indenté d'un niveau pour signaler qu'il fait partie d'une région de portée imbriquée. Comme les accolades du switch définissent une nouvelle région de portée, on indenterait normalement tout ce qui se trouve à l'intérieur des accolades d'un niveau.

Un label, en revanche, ne définit pas de portée imbriquée. Par conséquent, le code qui suit un label n'est conventionnellement pas indenté.

Cependant, si l'on indente à la fois les labels et les instructions qui les suivent au même niveau, on obtient quelque chose comme ceci :

// Version illisible
void printDigitName(int x)
{
    switch (x)
    {
        case 1:
        std::cout << "One";
        return;
        case 2:
        std::cout << "Two";
        return;
        case 3:
        std::cout << "Three";
        return;
        default:
        std::cout << "Unknown";
        return;
    }
}

Il devient alors très difficile de déterminer où commence et où se termine chaque cas.

Nous avons ici deux choix. Premièrement, on peut tout de même indenter les instructions qui suivent les labels :

// Version acceptable mais non préférée
void printDigitName(int x)
{
    switch (x)
    {
        case 1: // indenté par rapport au bloc switch
            std::cout << "One"; // indenté par rapport au label (trompeur)
            return;
        case 2:
            std::cout << "Two";
            return;
        case 3:
            std::cout << "Three";
            return;
        default:
            std::cout << "Unknown";
            return;
    }
}

Bien que ce soit certainement plus lisible que la version précédente, cela laisse penser que les instructions sous chaque label se trouvent dans une portée imbriquée, ce qui n'est pas le cas (nous verrons des exemples de cela dans la prochaine leçon, où une variable définie dans un cas peut être utilisée dans un autre cas). Ce formatage est considéré comme acceptable (car lisible), mais il n'est pas préféré.

Conventionnellement, les labels ne sont tout simplement pas indentés :

// Version préférée
void printDigitName(int x)
{
    switch (x)
    {
    case 1: // non indenté par rapport à l'instruction switch
        std::cout << "One";
        return;
    case 2:
        std::cout << "Two";
        return;
    case 3:
        std::cout << "Three";
        return;
    default:
        std::cout << "Unknown";
        return;
    }
}

Cela permet d'identifier facilement chaque label. Et comme les instructions ne sont indentées que d'un niveau par rapport au bloc switch, cela indique correctement qu'elles font toutes partie de la portée du bloc switch.

Dans les leçons à venir, nous rencontrerons d'autres types de labels : eux aussi ne sont conventionnellement pas indentés, pour la même raison.

Bonne pratique

Préférez ne pas indenter les labels. Cela leur permet de se distinguer du code environnant sans laisser penser qu'ils définissent une région de portée imbriquée.

Switch ou if-else

Les instructions switch sont plus adaptées lorsqu'on dispose d'une expression unique (de type entier non booléen ou de type énuméré) que l'on souhaite comparer à l'égalité avec un petit nombre de valeurs. Si le nombre de labels case devient trop grand, le switch peut devenir difficile à lire.

Comparé aux instructions if-else équivalentes, un switch peut être plus lisible, indique plus clairement qu'il s'agit de la même expression testée pour l'égalité dans chaque cas, et présente l'avantage de n'évaluer l'expression qu'une seule fois (ce qui le rend plus efficace).

Cependant, if-else est nettement plus souple. Voici quelques cas où if ou if-else est généralement préférable :

  • Tester une expression avec des comparaisons autres que l'égalité (par exemple x > 5)
  • Tester plusieurs conditions (par exemple x == 5 && y == 6)
  • Déterminer si une valeur se situe dans un intervalle (par exemple x >= 5 && x <= 10)
  • L'expression a un type que switch ne prend pas en charge (par exemple d == 4.0)
  • L'expression s'évalue en bool.

Bonne pratique

Préférez une instruction switch aux instructions if-else lorsque vous testez une expression unique (de type entier non booléen ou de type énuméré) pour l'égalité avec un petit ensemble de valeurs.
