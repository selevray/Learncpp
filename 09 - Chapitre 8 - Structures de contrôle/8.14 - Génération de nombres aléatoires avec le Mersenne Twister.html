8.14 — Génération de nombres aléatoires avec le Mersenne Twister

Dans la leçon précédente 8.13 -- Introduction à la génération de nombres aléatoires, nous avons présenté le concept de génération de nombres aléatoires et expliqué comment les algorithmes de PRNG sont généralement utilisés pour simuler le hasard dans les programmes.

Dans cette leçon, nous allons voir comment générer des nombres aléatoires dans vos programmes. Pour accéder aux fonctionnalités de randomisation de C++, on inclut l'en-tête <random> de la bibliothèque standard.

Générer des nombres aléatoires en C++ avec le Mersenne Twister

Le PRNG Mersenne Twister, en plus d'avoir un nom formidable, est probablement le PRNG le plus populaire, tous langages confondus. Bien qu'il soit un peu ancien selon les standards actuels, il produit généralement des résultats de bonne qualité et possède des performances correctes. La bibliothèque random prend en charge deux types Mersenne Twister :

  • mt19937 est un Mersenne Twister qui génère des entiers non signés de 32 bits
  • mt19937_64 est un Mersenne Twister qui génère des entiers non signés de 64 bits

Utiliser le Mersenne Twister est simple :

#include <iostream>
#include <random> // for std::mt19937

int main()
{
    std::mt19937 mt{}; // Instancie un Mersenne Twister 32 bits

    // Affiche une série de nombres aléatoires
    for (int count{ 1 }; count <= 40; ++count)
    {
        std::cout << mt() << '\t'; // génère un nombre aléatoire

        // Si nous avons affiché 5 nombres, on commence une nouvelle ligne
        if (count % 5 == 0)
            std::cout << '\n';
    }

    return 0;
}

Tout d'abord, nous incluons l'en-tête <random>, car c'est là que se trouvent toutes les fonctionnalités liées aux nombres aléatoires. Ensuite, nous instancions un moteur Mersenne Twister 32 bits avec l'instruction std::mt19937 mt. Puis, chaque fois que nous voulons générer un entier non signé aléatoire de 32 bits, nous appelons mt().

En passant…

Puisque mt est une variable, vous vous demandez peut-être ce que signifie mt().

Dans la leçon 5.7 -- Introduction à std::string, nous avons montré un exemple où nous appelions la fonction name.length(), ce qui invoquait la fonction length() sur la variable std::string name.

mt() est une syntaxe concise pour appeler la fonction mt.operator(), qui, pour ces types de PRNG, a été définie pour renvoyer le prochain résultat de la séquence. L'avantage d'utiliser operator() plutôt qu'une fonction nommée est que nous n'avons pas besoin de nous souvenir du nom de la fonction, et que la syntaxe concise demande moins de frappe.

Lancer un dé avec le Mersenne Twister

Un PRNG 32 bits génère des nombres aléatoires compris entre 0 et 4 294 967 295, mais nous ne voulons pas toujours des nombres dans cet intervalle. Si notre programme simule un jeu de plateau ou un jeu de dés, nous voudrons probablement simuler le lancer d'un dé à 6 faces en générant des nombres aléatoires entre 1 et 6. Si notre programme est un donjon d'aventure, et que le joueur possède une épée infligeant entre 7 et 11 points de dégâts aux monstres, nous voudrons générer des nombres aléatoires entre 7 et 11 chaque fois que le joueur touche un monstre.

Malheureusement, les PRNG ne peuvent pas faire cela : ils ne peuvent générer que des nombres sur l'intervalle complet. Ce dont nous avons besoin, c'est d'un moyen de convertir un nombre produit par notre PRNG en une valeur dans l'intervalle plus petit souhaité (avec une probabilité égale pour chaque valeur). Bien que nous puissions écrire nous-mêmes une fonction pour cela, le faire de manière non biaisée n'est pas trivial.

Heureusement, la bibliothèque random peut nous aider ici, sous la forme de distributions de nombres aléatoires. Une distribution de nombres aléatoires convertit la sortie d'un PRNG en une autre distribution de nombres.

En passant…

Pour les amateurs de statistiques : une distribution de nombres aléatoires est simplement une distribution de probabilité conçue pour prendre en entrée les valeurs d'un PRNG.

La bibliothèque random propose de nombreuses distributions de nombres aléatoires, dont la plupart ne vous serviront jamais, sauf si vous faites de l'analyse statistique. Mais il existe une distribution très utile : la distribution uniforme est une distribution de nombres aléatoires qui produit des valeurs comprises entre deux nombres X et Y (inclus) avec une probabilité égale.

Voici un programme semblable au précédent, utilisant une distribution uniforme pour simuler le lancer d'un dé à 6 faces :

#include <iostream>
#include <random> // for std::mt19937 and std::uniform_int_distribution

int main()
{
    std::mt19937 mt{};

    // Crée un générateur de nombres aléatoires réutilisable, produisant des nombres uniformes entre 1 et 6
    std::uniform_int_distribution die6{ 1, 6 }; // for C++14, use std::uniform_int_distribution<> die6{ 1, 6 };

    // Affiche une série de nombres aléatoires
    for (int count{ 1 }; count <= 40; ++count)
    {
        std::cout << die6(mt) << '\t'; // génère un lancer de dé ici

        // Si nous avons affiché 10 nombres, on commence une nouvelle ligne
        if (count % 10 == 0)
            std::cout << '\n';
    }

    return 0;
}

Ce programme produit le résultat suivant :


3       1       3       6       5       2       6       6       1       2
2       6       1       1       6       1       4       5       2       5
6       2       6       2       1       3       5       4       5       6
1       4       2       3       1       2       2       6       2       1

Il n'y a que deux différences notables avec l'exemple précédent. Premièrement, nous avons créé une variable de distribution uniforme (nommée die6) pour générer des nombres entre 1 et 6. Deuxièmement, au lieu d'appeler mt() pour générer des entiers non signés aléatoires de 32 bits, nous appelons maintenant die6(mt) pour obtenir une valeur entre 1 et 6.

Le programme ci-dessus n'est pas aussi aléatoire qu'il y paraît

Bien que les résultats de notre exemple de lancer de dé soient assez aléatoires, le programme présente un défaut majeur. Exécutez le programme 3 fois et essayez de trouver lequel. Allez-y, nous attendons.

Musique de jeopardy

Si vous exécutez le programme plusieurs fois, vous remarquerez qu'il affiche les mêmes nombres à chaque fois ! Si chaque nombre de la séquence est aléatoire par rapport au précédent, la séquence entière n'est absolument pas aléatoire ! Chaque exécution de notre programme produit exactement le même résultat.

Imaginez que vous écriviez un jeu de « plus ou moins », où l'utilisateur dispose de 10 essais pour deviner un nombre choisi au hasard, et où l'ordinateur indique si la proposition est trop haute ou trop basse. Si l'ordinateur choisit le même nombre aléatoire à chaque fois, le jeu ne sera plus intéressant après la première partie. Examinons donc plus en détail pourquoi cela se produit et comment y remédier.

Dans la leçon précédente (8.13 -- Introduction à la génération de nombres aléatoires), nous avons vu que chaque nombre d'une séquence de PRNG est produit de manière déterministe, et que l'état du PRNG est initialisé à partir de la valeur de graine (seed). Ainsi, pour une graine de départ donnée, un PRNG génère toujours la même séquence de nombres.

Comme nous initialisons notre Mersenne Twister par valeur, il est initialisé avec la même graine à chaque exécution du programme. Et comme la graine est identique, les nombres aléatoires générés sont eux aussi identiques.

Pour que toute la séquence soit différente à chaque exécution, nous devons choisir une graine qui ne soit pas un nombre fixe. La première idée qui vient probablement à l'esprit est d'utiliser un nombre aléatoire comme graine ! C'est une bonne pensée, mais si nous avons besoin d'un nombre aléatoire pour générer des nombres aléatoires, nous tournons en rond. En fait, nous n'avons pas vraiment besoin que la graine soit aléatoire : il suffit de choisir quelque chose qui change à chaque exécution du programme. Nous pouvons alors utiliser notre PRNG pour générer une séquence unique de nombres pseudo-aléatoires à partir de cette graine.

Deux méthodes sont couramment utilisées pour cela :

  • Utiliser l'horloge système
  • Utiliser le périphérique aléatoire du système

Initialiser la graine avec l'horloge système

Qu'est-ce qui change à chaque exécution de votre programme ? À moins de parvenir à lancer deux fois votre programme exactement au même instant, la réponse est : l'heure actuelle. Par conséquent, si nous utilisons l'heure courante comme valeur de graine, notre programme produira un ensemble différent de nombres aléatoires à chaque exécution. C et C++ ont une longue tradition d'initialisation des PRNG avec l'heure courante (à l'aide de la fonction std::time()), vous en verrez donc probablement dans beaucoup de code existant.

Heureusement, C++ dispose de la bibliothèque chrono, qui contient plusieurs horloges utilisables pour générer une valeur de graine. Pour minimiser la probabilité que deux valeurs temporelles soient identiques si le programme est lancé rapidement à plusieurs reprises, nous voulons utiliser une mesure de temps qui change le plus vite possible. Pour cela, nous demanderons à l'horloge le temps écoulé depuis le plus ancien instant qu'elle puisse mesurer. Ce temps est mesuré en « ticks », une unité de temps très petite (généralement des nanosecondes, mais parfois des millisecondes).

#include <iostream>
#include <random> // for std::mt19937
#include <chrono> // for std::chrono

int main()
{
    // Initialise notre Mersenne Twister avec steady_clock
    std::mt19937 mt{ static_cast<std::mt19937::result_type>(
        std::chrono::steady_clock::now().time_since_epoch().count()
        ) };

    // Crée un générateur de nombres aléatoires réutilisable, produisant des nombres uniformes entre 1 et 6
    std::uniform_int_distribution die6{ 1, 6 }; // for C++14, use std::uniform_int_distribution<> die6{ 1, 6 };

    // Affiche une série de nombres aléatoires
    for (int count{ 1 }; count <= 40; ++count)
    {
        std::cout << die6(mt) << '\t'; // génère un lancer de dé ici

        // Si nous avons affiché 10 nombres, on commence une nouvelle ligne
        if (count % 10 == 0)
            std::cout << '\n';
    }

    return 0;
}

Ce programme ne diffère du précédent que sur deux points. Premièrement, nous incluons <chrono>, qui nous donne accès à l'horloge. Deuxièmement, nous utilisons l'heure courante fournie par l'horloge comme valeur de graine pour notre Mersenne Twister.

Les résultats produits par ce programme devraient maintenant être différents à chaque exécution, ce que vous pouvez vérifier expérimentalement en l'exécutant plusieurs fois.

L'inconvénient de cette approche est que, si le programme est lancé plusieurs fois en succession rapide, les graines générées pour chaque exécution ne seront pas très différentes, ce qui peut nuire à la qualité statistique des résultats aléatoires. Pour les programmes ordinaires, cela n'a pas d'importance, mais pour les programmes qui exigent des résultats indépendants de haute qualité, cette méthode d'initialisation peut être insuffisante.

Astuce

std::chrono::high_resolution_clock est un choix populaire à la place de std::chrono::steady_clock. std::chrono::high_resolution_clock est l'horloge qui utilise l'unité de temps la plus fine, mais elle peut utiliser l'horloge système pour l'heure courante, laquelle peut être modifiée ou ramenée en arrière par les utilisateurs. std::chrono::steady_clock peut avoir une résolution de tick moins fine, mais c'est la seule horloge garantissant que les utilisateurs ne peuvent pas la modifier.

Initialiser la graine avec le périphérique aléatoire

La bibliothèque random contient un type appelé std::random_device, qui est un PRNG dépendant de l'implémentation. Normalement, nous évitons les fonctionnalités dépendant de l'implémentation, car elles ne garantissent ni qualité ni portabilité, mais c'est l'un des cas d'exception. En général, std::random_device demande au système d'exploitation un nombre pseudo-aléatoire (la manière de procéder dépend du système).

#include <iostream>
#include <random> // for std::mt19937 and std::random_device

int main()
{
    std::mt19937 mt{ std::random_device{}() };

    // Crée un générateur de nombres aléatoires réutilisable, produisant des nombres uniformes entre 1 et 6
    std::uniform_int_distribution die6{ 1, 6 }; // for C++14, use std::uniform_int_distribution<> die6{ 1, 6 };

    // Affiche une série de nombres aléatoires
    for (int count{ 1 }; count <= 40; ++count)
    {
        std::cout << die6(mt) << '\t'; // génère un lancer de dé ici

        // Si nous avons affiché 10 nombres, on commence une nouvelle ligne
        if (count % 10 == 0)
            std::cout << '\n';
    }

    return 0;
}

Dans le programme ci-dessus, nous initialisons notre Mersenne Twister avec un nombre aléatoire généré par une instance temporaire de std::random_device. Si vous exécutez ce programme plusieurs fois, il devrait lui aussi produire des résultats différents à chaque fois.

Un problème potentiel avec std::random_device : rien n'impose qu'il soit non déterministe, ce qui signifie qu'il pourrait, sur certains systèmes, produire la même séquence à chaque exécution du programme, précisément ce que nous cherchons à éviter. Il existait un bogue dans MinGW (corrigé dans GCC 9.2) qui produisait exactement ce comportement, rendant std::random_device inutilisable.

Cependant, les versions récentes des compilateurs les plus populaires (GCC/MinGW, Clang, Visual Studio) proposent des implémentations correctes de std::random_device.

Bonne pratique

Utilisez std::random_device pour initialiser vos PRNG (sauf si celui-ci n'est pas correctement implémenté pour votre compilateur ou architecture cible).

Q : Que signifie std::random_device{}() ?

std::random_device{} crée un objet temporaire de type std::random_device, initialisé par valeur. Les () appellent ensuite operator() sur cet objet temporaire, qui renvoie une valeur aléatoire (que nous utilisons pour initialiser notre Mersenne Twister).

C'est l'équivalent de l'appel de la fonction suivante, qui utilise une syntaxe plus familière :

unsigned int getRandomDeviceValue()
{
   std::random_device rd{}; // crée un objet std::random_device initialisé par valeur
   return rd(); // renvoie le résultat de operator() à l'appelant
}

Utiliser std::random_device{}() nous permet d'obtenir le même résultat sans créer de fonction ni de variable nommée, ce qui est beaucoup plus concis.

Q : Si std::random_device est déjà aléatoire, pourquoi ne pas l'utiliser directement au lieu du Mersenne Twister ?

Parce que std::random_device dépend de l'implémentation, on ne peut pas supposer grand-chose à son sujet. Son accès peut être coûteux, ou bien il peut suspendre notre programme le temps que d'autres nombres aléatoires deviennent disponibles. Le réservoir de nombres dans lequel il puise peut aussi s'épuiser rapidement, ce qui affecterait les résultats aléatoires des autres applications demandant des nombres par la même méthode. Pour cette raison, std::random_device est plus utile pour initialiser d'autres PRNG que comme PRNG lui-même.

N'initialisez un PRNG qu'une seule fois

De nombreux PRNG peuvent être réinitialisés après l'initialisation initiale. Cela réinitialise essentiellement l'état du générateur, qui produit alors des résultats à partir du nouvel état de graine. La réinitialisation doit généralement être évitée, sauf si vous avez une raison précise de la faire, car elle peut rendre les résultats moins aléatoires, voire non aléatoires du tout.

Bonne pratique

N'initialisez un générateur pseudo-aléatoire donné qu'une seule fois, et ne le réinitialisez pas.

Voici un exemple d'erreur courante chez les programmeurs débutants :

#include <iostream>
#include <random>

int getCard()
{
    std::mt19937 mt{ std::random_device{}() }; // ceci est créé et initialisé à chaque appel de la fonction
    std::uniform_int_distribution card{ 1, 52 };
    return card(mt);
}

int main()
{
    std::cout << getCard() << '\n';

    return 0;
}

Dans la fonction getCard(), le générateur de nombres aléatoires est créé et initialisé à chaque appel de la fonction. C'est au mieux inefficace, et cela risque fortement de produire de mauvais résultats aléatoires.

Mersenne Twister et problèmes de sous-initialisation

L'état interne d'un Mersenne Twister nécessite 19937 bits (2493 octets), soit 624 valeurs de 32 bits ou 312 valeurs de 64 bits. Par conséquent, std::mt19937 alloue 624 entiers, tandis que std::mt19937_64 en alloue 312.

En passant…

Les entiers alloués par std::mt19937 sont définis comme étant de type std::uint_fast32_t, qui peut représenter des entiers de 32 ou 64 bits selon l'architecture. Si std::uint_fast32_t correspond à un entier de 64 bits, std::mt19937 utilisera 624 entiers de 64 bits, soit deux fois la taille nécessaire.

Dans les exemples ci-dessus, où nous initialisons notre std::mt19937 à partir de l'horloge ou de std::random_device, la graine est un seul entier. Cela signifie que nous initialisons en fait 624 entiers à partir d'un seul entier, ce qui constitue une sous-initialisation importante du PRNG Mersenne Twister. La bibliothèque random fait de son mieux pour remplir les 623 valeurs restantes avec des données « aléatoires »… mais elle ne peut pas faire de miracles. Un PRNG sous-initialisé peut produire des résultats insuffisants pour les applications exigeant la plus haute qualité. Par exemple, initialiser std::mt19937 avec une valeur unique de 32 bits ne produira jamais le nombre 42 comme première sortie.

Comment y remédier ? Jusqu'à C++20, il n'existe pas de solution simple, mais nous pouvons proposer quelques pistes.

Commençons par std::seed_seq (qui signifie « séquence de graines »). Dans la leçon précédente, nous avons mentionné qu'idéalement, les données de graine devraient avoir autant de bits que l'état de notre PRNG, faute de quoi le PRNG sera sous-initialisé. Mais dans de nombreux cas (surtout lorsque l'état du PRNG est grand), nous n'avons pas autant de bits de graine aléatoire.

std::seed_seq a été conçu pour nous aider dans ce cas. On peut lui passer autant de valeurs aléatoires que l'on possède, et il génère ensuite autant de valeurs de graine supplémentaires non biaisées que nécessaire pour initialiser l'état d'un PRNG. Si l'on initialise std::seed_seq avec une seule valeur (par exemple issue de std::random_device) puis qu'on initialise un Mersenne Twister avec cet objet std::seed_seq, ce dernier génère 623 valeurs de graine supplémentaires. Cela n'ajoute pas d'aléa, mais offre un meilleur mélange de bits 0 et 1. Cependant, plus on fournit de données aléatoires à std::seed_seq, meilleur sera le résultat. L'idée la plus simple consiste donc à utiliser std::random_device pour fournir davantage de données à std::seed_seq. Si nous initialisons std::seed_seq avec 8 valeurs issues de std::random_device au lieu d'une seule, les valeurs restantes générées par std::seed_seq seront bien meilleures :

#include <iostream>
#include <random>

int main()
{
    std::random_device rd{};
    std::seed_seq ss{ rd(), rd(), rd(), rd(), rd(), rd(), rd(), rd() }; // obtient 8 entiers aléatoires de std::random_device pour notre graine
    std::mt19937 mt{ ss }; // initialise notre Mersenne Twister avec le std::seed_seq

    // Crée un générateur de nombres aléatoires réutilisable, produisant des nombres uniformes entre 1 et 6
    std::uniform_int_distribution die6{ 1, 6 }; // for C++14, use std::uniform_int_distribution<> die6{ 1, 6 };

    // Affiche une série de nombres aléatoires
    for (int count{ 1 }; count <= 40; ++count)
    {
        std::cout << die6(mt) << '\t'; // génère un lancer de dé ici

        // Si nous avons affiché 10 nombres, on commence une nouvelle ligne
        if (count % 10 == 0)
            std::cout << '\n';
    }

    return 0;
}

C'est assez simple, il n'y a donc guère de raison de ne pas le faire, au minimum.

Q : Pourquoi ne pas donner 624 valeurs de std::random_device à std::seed_seq ?

Vous le pouvez, mais cela risque d'être lent et d'épuiser le réservoir de nombres aléatoires utilisé par std::random_device.

Vous pouvez aussi utiliser d'autres entrées « aléatoires » pour std::seed_seq. Nous vous avons déjà montré comment obtenir une valeur depuis l'horloge, que vous pouvez donc ajouter facilement. D'autres éléments parfois utilisés incluent l'identifiant du thread courant, l'adresse de certaines fonctions, l'identifiant de l'utilisateur, l'identifiant du processus, etc. Cela dépasse le cadre de cet article, mais cet article présente le contexte et un lien vers randutils.hpp, qui implémente cette approche.

Une autre voie consiste à utiliser un PRNG différent, dont l'état est plus petit. De nombreux bons PRNG utilisent 64 ou 128 bits d'état, qui peuvent facilement être initialisés à l'aide d'un std::seed_seq rempli par 8 appels à std::random_device.

Préchauffer un PRNG

Lorsqu'un PRNG reçoit une graine de mauvaise qualité (ou sous-initialisée), ses premiers résultats peuvent ne pas être de haute qualité. Pour cette raison, certains PRNG bénéficient d'un « préchauffage », une technique qui consiste à écarter les N premiers résultats produits par le PRNG. Cela permet de mélanger l'état interne du PRNG de sorte que les résultats suivants soient de meilleure qualité. On écarte généralement quelques centaines à quelques milliers de premiers résultats. Plus la période du PRNG est longue, plus il faut écarter de résultats initiaux.

En passant…

L'implémentation de rand() de Visual Studio présentait (ou présente peut-être encore ?) un bogue : le premier résultat généré n'était pas suffisamment aléatoire. Vous pourrez voir d'anciens programmes utilisant rand() écarter un seul résultat pour éviter ce problème.

L'initialisation par seed_seq utilisée par std::mt19937 effectue un préchauffage, nous n'avons donc pas besoin de préchauffer explicitement les objets std::mt19937.

Déboguer des programmes utilisant des nombres aléatoires

Les programmes utilisant des nombres aléatoires peuvent être difficiles à déboguer, car ils peuvent se comporter différemment à chaque exécution. Dans ce cas, l'erreur peut se produire ou non. Cela peut vous faire perdre beaucoup de temps. Lors du débogage, il est utile de s'assurer que le programme s'exécute toujours de la même (mauvaise) manière. Ainsi, vous pouvez relancer le programme autant de fois que nécessaire pour isoler l'origine de l'erreur.

Pour cette raison, pendant le débogage, il est judicieux d'initialiser votre PRNG avec une valeur fixe précise (par exemple 5) qui provoque le comportement erroné. Si une graine donnée ne fait pas apparaître l'erreur, augmentez la valeur de la graine jusqu'à en trouver une qui la provoque. Cela garantit que votre programme produit les mêmes résultats à chaque exécution, ce qui facilite le débogage. Une fois l'erreur trouvée, vous pouvez revenir à votre méthode d'initialisation habituelle pour générer à nouveau des résultats aléatoires.

FAQ sur les nombres aléatoires

Q : Au secours ! Mon générateur de nombres aléatoires produit toujours la même séquence de nombres.

Si votre générateur produit la même séquence de nombres aléatoires à chaque exécution du programme, vous ne l'avez probablement pas initialisé correctement (ou pas du tout). Assurez-vous de l'initialiser avec une valeur qui change à chaque exécution du programme.

Q : Au secours ! Mon générateur de nombres aléatoires ne cesse de produire le même nombre.

Si votre générateur produit le même nombre à chaque demande, vous réinitialisez probablement le générateur avant de générer un nombre aléatoire, ou vous créez un nouveau générateur pour chaque nombre aléatoire.
