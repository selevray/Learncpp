8.7 — Instructions goto

Le prochain type d'instruction de contrôle de flux que nous allons étudier est le saut inconditionnel. Un saut inconditionnel fait passer l'exécution à un autre endroit du code. Le terme « inconditionnel » signifie que le saut a toujours lieu, contrairement à une instruction if ou switch, où le saut n'a lieu que selon le résultat d'une expression.

En C++, les sauts inconditionnels sont réalisés à l'aide d'une instruction goto, et l'endroit où l'on saute est identifié par un label d'instruction. Comme pour les labels case d'un switch, les labels d'instruction ne sont traditionnellement pas indentés.

Voici un exemple d'instruction goto et de label d'instruction :

#include <iostream>
#include <cmath> // pour la fonction sqrt()

int main()
{
    double x{};
tryAgain: // ceci est un label d'instruction
    std::cout << "Enter a non-negative number: ";
    std::cin >> x;

    if (x < 0.0)
        goto tryAgain; // ceci est l'instruction goto

    std::cout << "The square root of " << x << " is " << std::sqrt(x) << '\n';
    return 0;
}

Dans ce programme, l'utilisateur est invité à saisir un nombre positif ou nul. Cependant, si un nombre négatif est saisi, le programme utilise une instruction goto pour revenir au label tryAgain. L'utilisateur est alors invité à saisir à nouveau un nombre. Ainsi, nous pouvons demander en continu à l'utilisateur une saisie jusqu'à ce qu'il entre une valeur valide.

Voici un exemple d'exécution de ce programme :


Enter a non-negative number: -4
Enter a non-negative number: 4
The square root of 4 is 2

Les labels d'instruction ont une portée de fonction

Dans le chapitre sur la portée des objets (chapitre 7), nous avons vu deux types de portée : la portée locale (de bloc) et la portée de fichier (globale). Les labels d'instruction utilisent un troisième type de portée : la portée de fonction, ce qui signifie que le label est visible dans toute la fonction, y compris avant son point de déclaration. L'instruction goto et son label d'instruction correspondant doivent se trouver dans la même fonction.

Alors que l'exemple ci-dessus montre une instruction goto qui saute en arrière (vers un point précédent de la fonction), les instructions goto peuvent aussi sauter en avant :

#include <iostream>

void printCats(bool skip)
{
    if (skip)
        goto end; // saut en avant ; le label 'end' est visible ici grâce à sa portée de fonction

    std::cout << "cats\n";
end:
    ; // un label d'instruction doit être associé à une instruction
}

int main()
{
    printCats(true);  // saute par-dessus l'instruction d'affichage, donc n'affiche rien
    printCats(false); // affiche "cats"

    return 0;
}

Ce programme affiche :


cats

Outre le saut en avant, le programme ci-dessus présente quelques points intéressants.

Tout d'abord, notez qu'un label d'instruction doit être associé à une instruction (d'où son nom : il étiquette une instruction). Comme la fin de la fonction ne contenait aucune instruction, nous avons dû utiliser une instruction nulle pour avoir une instruction à étiqueter. Ensuite, nous avons pu sauter vers l'instruction étiquetée par end alors que nous n'avions pas encore déclaré end, grâce à la portée de fonction des labels d'instruction. Aucune déclaration anticipée des labels d'instruction n'est nécessaire. Enfin, il convient de préciser explicitement que le programme ci-dessus est de mauvaise facture : il aurait été préférable d'utiliser une instruction if pour sauter l'instruction d'affichage plutôt qu'une instruction goto.

Les sauts sont soumis à deux limitations principales : vous ne pouvez sauter qu'à l'intérieur d'une même fonction (vous ne pouvez pas sortir d'une fonction pour entrer dans une autre), et si vous sautez en avant, vous ne pouvez pas sauter par-dessus l'initialisation d'une variable qui est encore dans sa portée à l'endroit où l'on saute. Par exemple :

int main()
{
    goto skip;   // erreur : ce saut est illégal car...
    int x { 5 }; // cette variable initialisée est encore dans sa portée au label 'skip'
skip:
    x += 3;      // que donnerait ceci si x n'était pas initialisée ?
    return 0;
}

Notez que vous pouvez sauter en arrière par-dessus l'initialisation d'une variable : la variable sera alors réinitialisée lors de l'exécution de son initialisation.

Éviter d'utiliser goto

L'utilisation de goto est mal vue en C++ (comme dans les autres langages de haut niveau modernes). Edsger W. Dijkstra, informaticien renommé, a exposé les raisons d'éviter goto dans un article célèbre mais difficile à lire, intitulé Go To Statement Considered Harmful (L'instruction Go To considérée comme nuisible). Le principal problème de goto est qu'il permet au programmeur de sauter n'importe où dans le code. Cela crée ce que l'on appelle, avec peu d'affection, du code en spaghettis. Le code en spaghettis désigne un code dont le chemin d'exécution ressemble à un bol de spaghettis (emmêlé et tordu), ce qui rend extrêmement difficile la compréhension de sa logique.

Comme Dijkstra le dit avec un certain humour : « la qualité des programmeurs est une fonction décroissante de la densité des instructions go to dans les programmes qu'ils produisent ».

Presque tout code écrit avec une instruction goto peut être écrit plus clairement à l'aide d'autres constructions du C++, comme les instructions if et les boucles. Une exception notable est le cas où vous devez sortir d'une boucle imbriquée sans quitter la fonction entière : dans ce cas, un goto juste après les boucles est probablement la solution la plus propre.

Pour les lecteurs avancés

Voici un exemple artificiel d'utilisation de goto pour sortir d'une boucle imbriquée sans quitter la fonction :

#include <iostream>

int main()
{
    for (int i = 1; i < 5; ++i)
    {
        for (int j = 1; j < 5; ++j)
        {
            std::cout << i << " * " << j << " is " << i*j << '\n';

            // Si le produit est divisible par 9, on saute au label "end"
            if (i*j % 9 == 0)
            {
                std::cout << "Found product divisible by 9.  Ending early.\n";
                goto end;
            }
        }

        std::cout << "Incrementing the first factor.\n";
    }

end:
    std::cout << "And we're done." << '\n';

    return 0;
}
