17.7 — Introduction aux tableaux de style C

Maintenant que nous avons vu std::vector et std::array, nous allons compléter notre étude des tableaux en présentant le dernier type de tableau : les tableaux de style C.

Comme indiqué dans la leçon 16.1 -- Introduction aux conteneurs et aux tableaux, les tableaux de style C ont été hérités du langage C et sont intégrés au noyau du langage C++ (contrairement aux autres types de tableaux, qui sont des classes conteneurs de la bibliothèque standard). Cela signifie que nous n'avons pas besoin d'inclure un fichier d'en-tête pour les utiliser.

En complément…

Étant le seul type de tableau pris en charge nativement par le langage, les types de conteneurs de tableaux de la bibliothèque standard (par exemple std::array et std::vector) sont généralement implémentés à l'aide d'un tableau de style C.

Déclarer un tableau de style C

Comme ils font partie du noyau du langage, les tableaux de style C possèdent leur propre syntaxe de déclaration. Dans une déclaration de tableau de style C, on utilise des crochets ([]) pour indiquer au compilateur qu'un objet déclaré est un tableau de style C. À l'intérieur des crochets, on peut éventuellement fournir la longueur du tableau, une valeur entière de type std::size_t qui indique au compilateur le nombre d'éléments du tableau.

La définition suivante crée une variable de tableau de style C nommée testScore qui contient 30 éléments de type int :

int main()
{
    int testScore[30] {};      // Définit un tableau de style C nommé testScore contenant 30 éléments int initialisés par valeur (aucun include requis)

//  std::array<int, 30> arr{}; // Pour comparaison, voici un std::array de 30 éléments int initialisés par valeur (nécessite #include <array>)

    return 0;
}

La longueur d'un tableau de style C doit être au moins égale à 1. Le compilateur produit une erreur si la longueur du tableau est nulle, négative ou non entière.

Pour les lecteurs avancés

Les tableaux de style C alloués dynamiquement sur le tas peuvent avoir une longueur de 0.

La longueur d'un tableau de style C doit être une expression constante

Comme pour std::array, lors de la déclaration d'un tableau de style C, sa longueur doit être une expression constante (de type std::size_t, bien que cela n'ait généralement pas d'importance).

Remarque

Certains compilateurs peuvent autoriser la création de tableaux dont la longueur n'est pas constexpr, pour assurer la compatibilité avec une fonctionnalité du C99 appelée tableaux à longueur variable (VLA, variable-length arrays).

Les tableaux à longueur variable ne sont pas valides en C++ et ne doivent pas être utilisés dans les programmes C++. Si votre compilateur accepte ces tableaux, vous avez probablement oublié de désactiver les extensions du compilateur (voir 0.10 -- Configurer votre compilateur : extensions du compilateur).

Indexer un tableau de style C

Comme avec un std::array, on peut indexer un tableau de style C à l'aide de l'opérateur d'indexation (operator[]) :

#include <iostream>

int main()
{
    int arr[5]; // définit un tableau de 5 valeurs int

    arr[1] = 7; // utilise l'opérateur d'indexation pour accéder à l'élément 1 du tableau
    std::cout << arr[1]; // affiche 7

    return 0;
}

Contrairement aux classes conteneurs de la bibliothèque standard (qui n'utilisent que des indices non signés de type std::size_t), l'indice d'un tableau de style C peut être une valeur de n'importe quel type entier (signé ou non signé) ou une énumération non scopée. Cela signifie que les tableaux de style C ne posent pas les problèmes de conversion de signe liés à l'indexation que rencontrent les classes conteneurs de la bibliothèque standard !

#include <iostream>

int main()
{
    const int arr[] { 9, 8, 7, 6, 5 };

    int s { 2 };
    std::cout << arr[s] << '\n'; // utilisation d'un indice signé : correct

    unsigned int u { 2 };
    std::cout << arr[u] << '\n'; // utilisation d'un indice non signé : correct

    return 0;
}

Remarque

Les tableaux de style C acceptent des indices signés ou non signés (ou des énumérations non scopées).

operator[] ne effectue aucune vérification des bornes, et passer un indice hors bornes entraîne un comportement indéfini.

En complément…

Lors de la déclaration d'un tableau (par exemple int arr[5]), l'utilisation de [] fait partie de la syntaxe de déclaration et ne constitue pas un appel à l'opérateur d'indexation operator[].

Initialisation par agrégat des tableaux de style C

Comme std::array, les tableaux de style C sont des agrégats, ce qui signifie qu'ils peuvent être initialisés par initialisation d'agrégat.

Pour rappel, l'initialisation d'agrégat permet d'initialiser directement les membres d'un agrégat. Pour cela, on fournit une liste d'initialisation, c'est-à-dire une liste de valeurs d'initialisation séparées par des virgules et entourées d'accolades.

int main()
{
    int fibonnaci[6] = { 0, 1, 1, 2, 3, 5 }; // initialisation par copie de liste à l'aide d'une liste entre accolades
    int prime[5] { 2, 3, 5, 7, 11 };         // initialisation de liste à l'aide d'une liste entre accolades (à privilégier)

    return 0;
}

Chacune de ces formes d'initialisation initialise les éléments du tableau dans l'ordre, en commençant par l'élément 0.

Si vous ne fournissez pas d'initialiseur pour un tableau de style C, ses éléments sont initialisés par défaut. Dans la plupart des cas, cela laisse les éléments non initialisés. Comme nous voulons généralement que nos éléments soient initialisés, les tableaux de style C doivent être initialisés par valeur (à l'aide d'accolades vides) lorsqu'ils sont définis sans initialiseurs.

int main()
{
    int arr1[5];    // Éléments initialisés par défaut (les éléments int restent non initialisés)
    int arr2[5] {}; // Éléments initialisés par valeur (les éléments int valent zéro) (à privilégier)

    return 0;
}

Si la liste d'initialisation contient plus d'initialiseurs que la longueur du tableau, le compilateur produit une erreur. Si elle en contient moins, les éléments restants sans initialiseur sont initialisés par valeur :

int main()
{
    int a[4] { 1, 2, 3, 4, 5 }; // erreur de compilation : trop d'initialiseurs
    int b[4] { 1, 2 };          // arr[2] et arr[3] sont initialisés par valeur

    return 0;
}

Un inconvénient des tableaux de style C est que le type des éléments doit être spécifié explicitement. La déduction d'argument de modèle de classe (CTAD) ne fonctionne pas, car les tableaux de style C ne sont pas des modèles de classe. De même, utiliser auto pour tenter de déduire le type des éléments d'un tableau à partir de la liste d'initialiseurs ne fonctionne pas non plus :

int main()
{
    auto squares[5] { 1, 4, 9, 16, 25 }; // erreur de compilation : impossible d'utiliser la déduction de type sur des tableaux de style C

    return 0;
}

Longueur omise

La définition de tableau suivante contient une redondance subtile. La voyez-vous ?

int main()
{
    const int prime[5] { 2, 3, 5, 7, 11 }; // prime a pour longueur 5

    return 0;
}

Nous indiquons explicitement au compilateur que le tableau a une longueur de 5, puis nous l'initialisons aussi avec 5 éléments. Lorsqu'on initialise un tableau de style C avec une liste d'initialisation, on peut omettre la longueur (dans la définition du tableau) et laisser le compilateur la déduire du nombre d'initialiseurs.

Les définitions de tableaux suivantes se comportent de manière identique :

int main()
{
    const int prime1[5] { 2, 3, 5, 7, 11 }; // prime1 défini explicitement avec une longueur de 5
    const int prime2[] { 2, 3, 5, 7, 11 };  // prime2 : longueur déduite par le compilateur à 5

    return 0;
}

Cela ne fonctionne que lorsque des initialiseurs sont explicitement fournis pour tous les membres du tableau.

int main()
{
    int bad[] {}; // erreur : le compilateur déduirait une longueur nulle, ce qui est interdit !

    return 0;
}

Lorsqu'on utilise une liste d'initialisation pour initialiser tous les éléments d'un tableau de style C, il est préférable d'omettre la longueur et de laisser le compilateur la calculer. Ainsi, si des initialiseurs sont ajoutés ou retirés, la longueur du tableau s'adapte automatiquement, et nous ne risquons pas de décalage entre la longueur définie et le nombre d'initialiseurs fournis.

Bonne pratique

Privilégiez l'omission de la longueur d'un tableau de style C lorsque vous initialisez explicitement chaque élément avec une valeur.

Tableaux de style C const et constexpr

Comme std::array, les tableaux de style C peuvent être const ou constexpr. Comme les autres variables const, les tableaux const doivent être initialisés, et la valeur de leurs éléments ne peut plus être modifiée par la suite.

#include <iostream>

namespace ProgramData
{
    constexpr int squares[5] { 1, 4, 9, 16, 25 }; // un tableau de int constexpr
}

int main()
{
    const int prime[5] { 2, 3, 5, 7, 11 }; // un tableau de int const
    prime[0] = 17; // erreur de compilation : impossible de modifier un int const

    return 0;
}

La taille d'un tableau de style C avec sizeof

Dans les leçons précédentes, nous avons utilisé l'opérateur sizeof() pour obtenir la taille d'un objet ou d'un type en octets. Appliqué à un tableau de style C, sizeof() renvoie le nombre d'octets occupés par l'ensemble du tableau :

#include <iostream>

int main()
{
    const int prime[] { 2, 3, 5, 7, 11 }; // le compilateur déduit que prime a pour longueur 5

    std::cout << sizeof(prime); // affiche 20 (en supposant des int de 4 octets)

    return 0;
}

En supposant des int de 4 octets, le programme ci-dessus affiche 20. Le tableau prime contient 5 éléments int de 4 octets chacun, soit 5 * 4 = 20 octets.

Notez qu'il n'y a aucun surcoût ici. Un objet tableau de style C ne contient que ses éléments, rien de plus.

Obtenir la longueur d'un tableau de style C

En C++17, on peut utiliser std::size() (défini dans l'en-tête <iterator>), qui renvoie la longueur du tableau sous forme de valeur entière non signée (de type std::size_t). En C++20, on peut aussi utiliser std::ssize(), qui renvoie la longueur du tableau sous forme de valeur entière signée (d'un grand type entier signé, probablement std::ptrdiff_t).

#include <iostream>
#include <iterator> // pour std::size et std::ssize

int main()
{
    const int prime[] { 2, 3, 5, 7, 11 };   // le compilateur déduit que prime a pour longueur 5

    std::cout << std::size(prime) << '\n';  // C++17, renvoie une valeur entière non signée 5
    std::cout << std::ssize(prime) << '\n'; // C++20, renvoie une valeur entière signée 5

    return 0;
}

Remarque

L'en-tête canonique de définition de std::size() et std::ssize() est <iterator>. Cependant, comme ces fonctions sont très utiles, de nombreux autres en-têtes les rendent également disponibles, notamment <array> et <vector>. Lorsque vous utilisez std::size() ou std::ssize() sur un tableau de style C, il se peut que vous n'ayez pas déjà inclus l'un de ces autres en-têtes. Dans ce cas, l'en-tête <iterator> est celui qu'on inclut par convention.

La liste complète des en-têtes définissant ces fonctions est disponible dans la documentation cppreference sur les fonctions size.

Obtenir la longueur d'un tableau de style C (C++14 ou antérieur)

Avant C++17, il n'existait aucune fonction de la bibliothèque standard pour obtenir la longueur d'un tableau de style C.

Si vous utilisez C++11 ou C++14, vous pouvez utiliser cette fonction à la place :

#include <cstddef> // pour std::size_t
#include <iostream>

template <typename T, std::size_t N>
constexpr std::size_t length(const T(&)[N]) noexcept
{
    return N;
}

int main() {

    int array[]{ 1, 1, 2, 3, 5, 8, 13, 21 };
    std::cout << "The array has: " << length(array) << " elements\n";

    return 0;
}

Cette fonction est un modèle de fonction qui prend un tableau de style C par référence et renvoie le paramètre de modèle non-type représentant la longueur du tableau.

Dans des bases de code bien plus anciennes, vous pourrez voir la longueur d'un tableau de style C déterminée en divisant la taille de tout le tableau par la taille d'un élément :

#include <iostream>

int main()
{
    int array[8] {};
    std::cout << "The array has: " << sizeof(array) / sizeof(array[0]) << " elements\n";

    return 0;
}

Ce programme affiche :


The array has: 8 elements

Comment cela fonctionne-t-il ? Tout d'abord, notez que la taille du tableau entier est égale à sa longueur multipliée par la taille d'un élément. Plus concisément : taille du tableau = longueur * taille d'un élément.

En algèbre, on peut réarranger cette équation : longueur = taille du tableau / taille d'un élément. On utilise généralement sizeof(array[0]) pour la taille d'un élément. Par conséquent, longueur = sizeof(array) / sizeof(array[0]). On peut aussi rencontrer occasionnellement l'écriture sizeof(array) / sizeof(*array), qui fait exactement la même chose.

Cependant, comme nous le montrerons dans la leçon suivante, cette formule peut facilement échouer (lorsqu'elle est appliquée à un tableau ayant subi une dégradation (decay)), ce qui peut rendre le programme défaillant de manière inattendue. Le std::size() de C++17 et la fonction modèle length() présentée ci-dessus provoquent tous deux une erreur de compilation dans ce cas, et sont donc sûrs à utiliser.

Contenu connexe

Nous traitons de la dégradation des tableaux dans la leçon suivante 17.8 -- Dégradation des tableaux de style C.

Les tableaux de style C ne supportent pas l'affectation

De façon peut-être surprenante, les tableaux C++ ne supportent pas l'affectation :

int main()
{
    int arr[] { 1, 2, 3 }; // correct : l'initialisation est valide
    arr[0] = 4;            // l'affectation à des éléments individuels est valide
    arr = { 5, 6, 7 };     // erreur de compilation : affectation de tableau non valide

    return 0;
}

Techniquement, cela ne fonctionne pas parce que l'affectation exige que l'opérande de gauche soit une lvalue modifiable, et les tableaux de style C ne sont pas considérés comme des lvalues modifiables.

Si vous devez affecter une nouvelle liste de valeurs à un tableau de style C, il est préférable d'utiliser un std::vector. Sinon, vous pouvez affecter de nouvelles valeurs élément par élément, ou utiliser std::copy pour copier un tableau de style C existant :

#include <algorithm> // pour std::copy

int main()
{
    int arr[] { 1, 2, 3 };
    int src[] { 5, 6, 7 };

    // Copie src dans arr
    std::copy(std::begin(src), std::end(src), std::begin(arr));

    return 0;
}

Temps de quiz

Question n° 1

Convertissez la définition de std::array suivante en une définition équivalente de tableau de style C constexpr :

constexpr std::array<int, 3> a{}; // alloue 3 int
Solution 
    constexpr int a[3] {}; // alloue 3 int

Question n° 2

Quelles sont les trois erreurs du programme suivant ?

#include <iostream>

int main()
{
    int length{ 5 };
    const int arr[length] { 9, 7, 5, 3, 1 };

    std::cout << arr[length];
    arr[0] = 4;

    return 0;
}
Solution
  1. Lors de la définition d'un tableau, sa longueur doit être une constante de compilation. Dans le programme ci-dessus, length n'est pas const, donc la définition const int arr[length] n'est pas autorisée.
  2. Les indices des tableaux vont de 0 à longueur - 1. Par conséquent, arr[length] est un indice hors bornes, ce qui entraîne un comportement indéfini.
  3. Les éléments du tableau sont de type « const int », et arr[0] ne peut donc pas être modifié par affectation.

Question n° 3

Un « carré parfait » est un entier naturel dont la racine carrée est un entier. On obtient des carrés parfaits en multipliant un entier naturel (zéro inclus) par lui-même. Les 4 premiers carrés parfaits sont : 0, 1, 4, 9.

Utilisez un tableau de style C global constexpr pour contenir les carrés parfaits compris entre 0 et 9 (inclus). Demandez de façon répétée à l'utilisateur de saisir un entier à un seul chiffre, ou -1 pour quitter. Affichez si le chiffre saisi par l'utilisateur est un carré parfait.

La sortie doit correspondre à ce qui suit :


Enter a single digit integer, or -1 to quit: 4
4 is a perfect square

Enter a single digit integer, or -1 to quit: 5
5 is not a perfect square

Enter a single digit integer, or -1 to quit: -1
Bye

Indices : utilisez une boucle for basée sur un intervalle pour parcourir le tableau de style C et rechercher une correspondance.

Solution 
#include <iostream>

namespace ProgramData
{
    constexpr int squares[] { 0, 1, 4, 9 };
}

bool matchSquare(int input)
{
    for (const auto& e : ProgramData::squares)
    {
        if (input == e)
            return true;
    }

    return false;
}

int main()
{
    while (true)
    {
        std::cout << "Enter a single digit integer, or -1 to quit: ";
        int input{};
        std::cin >> input;

        if (input == -1)
            break;

        if (matchSquare(input))
            std::cout << input << " is a perfect square\n";
        else
            std::cout << input << " is not a perfect square\n";
    }

    std::cout << "Bye\n";

    return 0;
}
