17.9 — Arithmétique des pointeurs et indexation

Dans la leçon 16.1 -- Introduction aux conteneurs et aux tableaux, nous avons mentionné que les tableaux sont stockés séquentiellement en mémoire. Dans cette leçon, nous allons examiner de plus près le calcul d'indexation des tableaux.

Bien que nous n'utilisions pas ce calcul d'indexation dans les leçons suivantes, les notions abordées ici vous aideront à comprendre le fonctionnement interne des boucles basées sur une plage (range-based for loops), et seront utiles plus tard lorsque nous aborderons les itérateurs.

Qu'est-ce que l'arithmétique des pointeurs ?

L'arithmétique des pointeurs (pointer arithmetic) est une fonctionnalité qui permet d'appliquer certains opérateurs arithmétiques entiers (addition, soustraction, incrémentation ou décrémentation) à un pointeur pour produire une nouvelle adresse mémoire.

Étant donné un pointeur ptr, ptr + 1 renvoie l'adresse du prochain objet en mémoire (en fonction du type pointé). Ainsi, si ptr est un int* et qu'un int occupe 4 octets, ptr + 1 renverra l'adresse située 4 octets après ptr, et ptr + 2 renverra l'adresse située 8 octets après ptr.

#include <iostream>

int main()
{
    int x {};
    const int* ptr{ &x }; // en supposant des int de 4 octets

    std::cout << ptr << ' ' << (ptr + 1) << ' ' << (ptr + 2) << '\n';

    return 0;
}

Sur la machine de l'auteur, ce programme a affiché :


00AFFD80 00AFFD84 00AFFD88

Notez que chaque adresse mémoire est supérieure de 4 octets à la précédente.

Bien que moins courante, l'arithmétique des pointeurs fonctionne également avec la soustraction. Étant donné un pointeur ptr, ptr - 1 renvoie l'adresse de l'objet précédent en mémoire (en fonction du type pointé).

#include <iostream>

int main()
{
    int x {};
    const int* ptr{ &x }; // en supposant des int de 4 octets

    std::cout << ptr << ' ' << (ptr - 1) << ' ' << (ptr - 2) << '\n';

    return 0;
}

Sur la machine de l'auteur, ce programme a affiché :


00AFFD80 00AFFD7C 00AFFD78

Dans ce cas, chaque adresse mémoire est inférieure de 4 octets à la précédente.

Point clé

L'arithmétique des pointeurs renvoie l'adresse de l'objet suivant ou précédent (en fonction du type pointé), et non l'adresse suivante ou précédente en octets.

Appliquer les opérateurs d'incrémentation (++) et de décrémentation (--) à un pointeur revient respectivement à une addition et une soustraction de pointeur, mais modifie directement l'adresse contenue dans le pointeur.

Étant donné un entier x, ++x est l'abréviation de x = x + 1. De même, étant donné un pointeur ptr, ++ptr est l'abréviation de ptr = ptr + 1, ce qui effectue une arithmétique des pointeurs et réaffecte le résultat à ptr.

#include <iostream>

int main()
{
    int x {};
    const int* ptr{ &x }; // en supposant des int de 4 octets

    std::cout << ptr << '\n';

    ++ptr; // ptr = ptr + 1
    std::cout << ptr << '\n';

    --ptr; // ptr = ptr - 1
    std::cout << ptr << '\n';

    return 0;
}

Sur la machine de l'auteur, ce programme a affiché :


00AFFD80 00AFFD84 00AFFD80

Avertissement

Techniquement, ce qui précède constitue un comportement indéfini. Selon la norme C++, l'arithmétique des pointeurs n'est un comportement défini que lorsque le pointeur et le résultat se situent dans le même tableau (ou juste après sa fin). Cependant, les implémentations C++ modernes n'appliquent généralement pas cette règle et n'interdisent en général pas l'arithmétique des pointeurs en dehors des tableaux.

L'indexation est implémentée via l'arithmétique des pointeurs

Dans la leçon précédente (17.8 -- Décroissance d'un tableau de style C), nous avons indiqué que l'opérateur operator[] peut être appliqué à un pointeur :

#include <iostream>

int main()
{
    const int arr[] { 9, 7, 5, 3, 1 };

    const int* ptr{ arr }; // un pointeur ordinaire contenant l'adresse de l'élément 0
    std::cout << ptr[2];   // indexe ptr pour obtenir l'élément 2, affiche 5

    return 0;
}

Examinons de plus près ce qui se passe ici.

En fait, l'opération d'indexation ptr[n] est une syntaxe concise équivalente à l'expression plus verbeuse *((ptr) + (n)). Vous remarquerez qu'il s'agit simplement d'arithmétique des pointeurs, avec des parenthèses supplémentaires pour garantir l'ordre d'évaluation correct, et d'un déréférencement implicite pour obtenir l'objet situé à cette adresse.

Tout d'abord, nous initialisons ptr avec arr. Lorsque arr est utilisé comme initialiseur, il se transforme (décroît) en un pointeur contenant l'adresse de l'élément d'indice 0. Ainsi, ptr contient désormais l'adresse de l'élément 0.

Ensuite, nous affichons ptr[2]. ptr[2] est équivalent à *((ptr) + (2)), soit *(ptr + 2). ptr + 2 renvoie l'adresse de l'objet situé deux objets après ptr, c'est-à-dire l'élément d'indice 2. L'objet situé à cette adresse est alors renvoyé à l'appelant.

Voyons un autre exemple :

#include <iostream>

int main()
{
    const int arr[] { 3, 2, 1 };

    // Commençons par utiliser l'indexation pour obtenir les adresses et les valeurs des éléments du tableau
    std::cout << &arr[0] << ' ' << &arr[1] << ' ' << &arr[2] << '\n';
    std::cout << arr[0] << ' ' << arr[1] << ' ' << arr[2] << '\n';

    // Faisons maintenant la même chose avec l'arithmétique des pointeurs
    std::cout << arr<< ' ' << (arr+ 1) << ' ' << (arr+ 2) << '\n';
    std::cout << *arr<< ' ' << *(arr+ 1) << ' ' << *(arr+ 2) << '\n';

    return 0;
}

Sur la machine de l'auteur, ce programme a affiché :


00AFFD80 00AFFD84 00AFFD88
3 2 1
00AFFD80 00AFFD84 00AFFD88
3 2 1

Vous remarquerez que arr contient l'adresse 00AFFD80, que (arr + 1) renvoie une adresse située 4 octets plus loin, et que (arr + 2) renvoie une adresse située 8 octets plus loin. Nous pouvons déréférencer ces adresses pour obtenir les éléments qui s'y trouvent.

Comme les éléments d'un tableau sont toujours séquentiels en mémoire, si arr est un pointeur vers l'élément 0 d'un tableau, *(arr + n) renverra le n-ième élément du tableau.

C'est la principale raison pour laquelle les tableaux sont indexés à partir de 0 plutôt que de 1. Cela rend le calcul plus efficace, car le compilateur n'a pas à soustraire 1 à chaque indexation !

En passant…

Petite anecdote : comme le compilateur convertit ptr[n] en *((ptr) + (n)) lors de l'indexation d'un pointeur, nous pouvons aussi écrire n[ptr] ! Le compilateur le convertit en *((n) + (ptr)), ce qui a exactement le même comportement que *((ptr) + (n)). Ne le faites toutefois pas, car c'est confus.

L'arithmétique des pointeurs et l'indexation sont des adresses relatives

Lorsque l'on découvre l'indexation des tableaux, il est naturel de supposer que l'indice désigne un élément fixe du tableau : l'indice 0 est toujours le premier élément, l'indice 1 est toujours le deuxième, et ainsi de suite.

C'est une illusion. Les indices de tableau sont en réalité des positions relatives. Ils semblent fixes simplement parce que nous indexons presque toujours à partir du début (élément 0) du tableau !

Rappelez-vous : étant donné un pointeur ptr, *(ptr + 1) et ptr[1] renvoient tous deux le prochain objet en mémoire (en fonction du type pointé). « Prochain » est un terme relatif, non absolu. Ainsi, si ptr pointe sur l'élément 0, alors *(ptr + 1) et ptr[1] renverront l'élément 1. Mais si ptr pointe plutôt sur l'élément 3, alors *(ptr + 1) et ptr[1] renverront l'élément 4 !

L'exemple suivant illustre ce point :

#include <array>
#include <iostream>

int main()
{
    const int arr[] { 9, 8, 7, 6, 5 };
    const int *ptr { arr }; // arr se transforme en un pointeur vers l'élément 0

    // Vérifions que nous pointons sur l'élément 0
    std::cout << *ptr << ptr[0] << '\n'; // affiche 99
    // Vérifions que ptr[1] est l'élément 1
    std::cout << *(ptr+1) << ptr[1] << '\n'; // affiche 88

    // Faisons maintenant pointer ptr sur l'élément 3
    ptr = &arr[3];

    // Vérifions que nous pointons sur l'élément 3
    std::cout << *ptr << ptr[0] << '\n'; // affiche 66
    // Vérifions que ptr[1] est l'élément 4 !
    std::cout << *(ptr+1) << ptr[1] << '\n'; // affiche 55

    return 0;
}

Cependant, vous remarquerez aussi que notre programme devient beaucoup plus difficile à comprendre si nous ne pouvons pas supposer que ptr[1] est toujours l'élément d'indice 1. Pour cette raison, nous recommandons d'utiliser l'indexation uniquement lorsque l'on part du début du tableau (élément 0). Utilisez l'arithmétique des pointeurs uniquement pour un positionnement relatif.

Bonne pratique

Privilégiez l'indexation lorsque vous partez du début du tableau (élément 0), afin que les indices du tableau correspondent à la position de l'élément.

Privilégiez l'arithmétique des pointeurs pour un positionnement relatif à partir d'un élément donné.

Indices négatifs

Dans la dernière leçon, nous avons mentionné que (contrairement aux classes conteneurs de la bibliothèque standard) l'indice d'un tableau de style C peut être un entier non signé ou signé. Ce n'est pas seulement une question de commodité : il est en fait possible d'indexer un tableau de style C avec un indice négatif. Cela peut sembler étrange, mais c'est logique.

Nous venons de voir que *(ptr+1) renvoie le prochain objet en mémoire, et que ptr[1] est une syntaxe pratique pour faire la même chose.

Au début de cette leçon, nous avons indiqué que *(ptr-1) renvoie l'objet précédent en mémoire. Devinez quelle est la forme indexée équivalente ? Eh oui, ptr[-1].

#include <array>
#include <iostream>

int main()
{
    const int arr[] { 9, 8, 7, 6, 5 };

    // Faisons pointer ptr sur l'élément 3
    const int* ptr { &arr[3] };

    // Vérifions que nous pointons sur l'élément 3
    std::cout << *ptr << ptr[0] << '\n'; // affiche 66
    // Vérifions que ptr[-1] est l'élément 2 !
    std::cout << *(ptr-1) << ptr[-1] << '\n'; // affiche 77

    return 0;
}

L'arithmétique des pointeurs peut servir à parcourir un tableau

L'une des utilisations les plus courantes de l'arithmétique des pointeurs consiste à parcourir un tableau de style C sans indexation explicite. L'exemple suivant illustre cette technique :

#include <iostream>

int main()
{
    constexpr int arr[]{ 9, 7, 5, 3, 1 };

    const int* begin{ arr };                // begin pointe sur l'élément de début
    const int* end{ arr + std::size(arr) }; // end pointe sur l'élément situé juste après la fin

    for (; begin != end; ++begin)           // parcourt de begin jusqu'à end (exclu)
    {
        std::cout << *begin << ' ';     // déréférence la variable de boucle pour obtenir l'élément courant
    }

    return 0;
}

Dans l'exemple ci-dessus, nous commençons le parcours à l'élément pointé par begin (c'est-à-dire l'élément 0 du tableau dans ce cas). Comme begin != end est vrai, le corps de la boucle s'exécute. Dans la boucle, nous accédons à l'élément courant via *begin, ce qui n'est qu'un déréférencement de pointeur. À la fin du corps de la boucle, nous effectuons ++begin, qui utilise l'arithmétique des pointeurs pour faire pointer begin sur l'élément suivant. Comme begin != end est à nouveau vrai, le corps de la boucle s'exécute de nouveau. Cela se poursuit jusqu'à ce que begin != end soit false, c'est-à-dire lorsque begin == end.

Ainsi, le programme ci-dessus affiche :


9 7 5 3 1

Notez que end est positionné juste après la fin du tableau. Il est correct que end contienne cette adresse (à condition de ne jamais le déréférencer, car il n'y a pas d'élément valide à cette adresse). Nous procédons ainsi parce que cela rend nos calculs et nos comparaisons aussi simples que possible (pas besoin d'ajouter ou de soustraire 1 quelque part).

Conseil

Pour un pointeur qui pointe sur un élément d'un tableau de style C, l'arithmétique des pointeurs est valide tant que l'adresse obtenue est celle d'un élément valide du tableau, ou celle situé juste après le dernier élément. Si l'arithmétique des pointeurs produit une adresse en dehors de ces limites, il s'agit d'un comportement indéfini (même si le résultat n'est pas déréférencé).

Dans la leçon précédente 17.8 -- Décroissance d'un tableau de style C, nous avons mentionné que la décroissance des tableaux complique la refactorisation des fonctions, car certaines opérations fonctionnent avec un tableau non décru mais pas avec un tableau décru (comme std::size). Un avantage intéressant de cette façon de parcourir un tableau est que nous pouvons extraire la partie boucle de l'exemple ci-dessus dans une fonction distincte, telle quelle, et elle fonctionnera toujours :

#include <iostream>

void printArray(const int* begin, const int* end)
{
    for (; begin != end; ++begin)   // parcourt de begin jusqu'à end (exclu)
    {
        std::cout << *begin << ' '; // déréférence la variable de boucle pour obtenir l'élément courant
    }

    std::cout << '\n';
}

int main()
{
    constexpr int arr[]{ 9, 7, 5, 3, 1 };

    const int* begin{ arr };                // begin pointe sur l'élément de début
    const int* end{ arr + std::size(arr) }; // end pointe sur l'élément situé juste après la fin

    printArray(begin, end);

    return 0;
}

Notez que ce programme se compile et produit le bon résultat, alors que nous ne passons jamais explicitement le tableau à la fonction ! Et comme nous ne passons pas arr, nous n'avons pas à gérer un tableau décru dans printArray(). À la place, begin et end contiennent toutes les informations nécessaires pour parcourir le tableau.

Dans les leçons à venir (lorsque nous aborderons les itérateurs et les algorithmes), nous verrons que la bibliothèque standard regorge de fonctions qui utilisent une paire begin et end pour définir sur quels éléments d'un conteneur la fonction doit opérer.

Les boucles basées sur une plage sur les tableaux de style C sont implémentées avec l'arithmétique des pointeurs

Considérons la boucle basée sur une plage suivante :

#include <iostream>

int main()
{
    constexpr int arr[]{ 9, 7, 5, 3, 1 };

    for (auto e : arr)         // parcourt de `begin` jusqu'à `end` (exclu)
    {
        std::cout << e << ' '; // déréférence la variable de boucle pour obtenir l'élément courant
    }

    return 0;
}

Si vous consultez la documentation des boucles basées sur une plage, vous verrez qu'elles sont généralement implémentées de la manière suivante :


{
    auto __begin = begin-expr;
    auto __end = end-expr;

    for ( ; __begin != __end; ++__begin)
    {
        range-declaration = *__begin;
        loop-statement;
    }
}

Remplaçons la boucle basée sur une plage de l'exemple précédent par cette implémentation :

#include <iostream>

int main()
{
    constexpr int arr[]{ 9, 7, 5, 3, 1 };

    auto __begin = arr;                // arr est notre begin-expr
    auto __end = arr + std::size(arr); // arr + std::size(arr) est notre end-expr

    for ( ; __begin != __end; ++__begin)
    {
        auto e = *__begin;         // e est notre range-declaration
        std::cout << e << ' ';     // ici se trouve notre loop-statement
    }

    return 0;
}

Remarquez à quel point ceci ressemble à l'exemple de la section précédente ! La seule différence est que nous affectons *__begin à e et utilisons e, au lieu d'utiliser directement *__begin !

Quiz

Question n° 1

a) Pourquoi arr[0] est-il équivalent à *arr ?

Solution

arr[0] est l'abréviation de *((arr) + (0)), ce qui équivaut à *(arr + 0), qui vaut *arr.
