17.4 — std::array de types classes, et élision d'accolades

Un std::array n'est pas limité aux éléments de types fondamentaux. En réalité, les éléments d'un std::array peuvent être de n'importe quel type objet, y compris des types composés. Cela signifie que vous pouvez créer un std::array de pointeurs, ou un std::array de structures (ou de classes).

Cependant, l'initialisation d'un std::array de structures ou de classes déroute souvent les programmeurs débutants. Nous allons donc consacrer une leçon à ce sujet précis.

Note de l'auteur

Nous utiliserons des structures pour illustrer nos propos dans cette leçon. Le contenu s'applique tout aussi bien aux classes.

Définir et affecter un std::array de structures

Commençons par une structure simple :

struct House
{
    int number{};
    int stories{};
    int roomsPerStory{};
};

Définir un std::array de House et affecter ses éléments fonctionne comme vous pourriez vous y attendre :

#include <array>
#include <iostream>

struct House
{
    int number{};
    int stories{};
    int roomsPerStory{};
};

int main()
{
    std::array<House, 3> houses{};

    houses[0] = { 13, 1, 7 };
    houses[1] = { 14, 2, 5 };
    houses[2] = { 15, 2, 4 };

    for (const auto& house : houses)
    {
        std::cout << "House number " << house.number
                  << " has " << (house.stories * house.roomsPerStory)
                  << " rooms.\n";
    }

    return 0;
}

Le programme ci-dessus affiche ce qui suit :


House number 13 has 7 rooms.
House number 14 has 10 rooms.
House number 15 has 8 rooms.

Initialiser un std::array de structures

Initialiser un tableau de structures fonctionne également comme vous pourriez vous y attendre, à condition de préciser explicitement le type des éléments :

#include <array>
#include <iostream>

struct House
{
    int number{};
    int stories{};
    int roomsPerStory{};
};

int main()
{
    constexpr std::array houses { // utilisation de CTAD pour déduire les arguments de modèle <House, 3>
            House{ 13, 1, 7 },
            House{ 14, 2, 5 },
            House{ 15, 2, 4 }
        };

    for (const auto& house : houses)
    {
        std::cout << "House number " << house.number
            << " has " << (house.stories * house.roomsPerStory)
            << " rooms.\n";
    }

    return 0;
}

Dans l'exemple ci-dessus, nous utilisons CTAD pour déduire le type du std::array comme std::array<House, 3>. Nous fournissons ensuite 3 objets House comme initialisateurs, ce qui fonctionne parfaitement.

Initialisation sans préciser le type d'élément pour chaque initialisateur

Dans l'exemple précédent, vous remarquerez que chaque initialisateur oblige à citer le type d'élément :

    constexpr std::array houses {
            House{ 13, 1, 7 }, // on mentionne House ici
            House{ 14, 2, 5 }, // et ici
            House{ 15, 2, 4 }  // et ici
        };

Mais nous n'avons pas eu à faire de même dans le cas de l'affectation :

    // Le compilateur sait que chaque élément de houses est un House
    // il convertira donc implicitement le membre droit de chaque affectation en House
    houses[0] = { 13, 1, 7 };
    houses[1] = { 14, 2, 5 };
    houses[2] = { 15, 2, 4 };

On pourrait donc être tenté d'écrire quelque chose comme ceci :

    // ne fonctionne pas
    constexpr std::array<House, 3> houses { // on indique au compilateur que chaque élément est un House
            { 13, 1, 7 }, // mais on ne le mentionne pas ici
            { 14, 2, 5 },
            { 15, 2, 4 }
        };

Et, peut-être de manière surprenante, cela ne fonctionne pas. Voyons pourquoi.

Un std::array est défini comme une structure qui contient un unique membre de tableau de style C (dont le nom est défini par l'implémentation), de la façon suivante :

template<typename T, std::size_t N>
struct array
{
    T implementation_defined_name[N]; // un tableau de style C de N éléments de type T
}

Note de l'auteur

Nous n'avons pas encore abordé les tableaux de style C, mais pour les besoins de cette leçon, il vous suffit de savoir que T implementation_defined_name[N]; est un tableau de taille fixe de N éléments de type T (tout comme std::array<T, N> implementation_defined_name;).

Nous aborderons les tableaux de style C dans la prochaine leçon 17.7 -- Introduction aux tableaux de style C.

Ainsi, lorsque nous essayons d'initialiser houses comme ci-dessus, le compilateur interprète l'initialisation de cette façon :

// Ne fonctionne pas
constexpr std::array<House, 3> houses { // initialisateur de houses
    { 13, 1, 7 }, // initialisateur du membre tableau de style C nommé implementation_defined_name
    { 14, 2, 5 }, // ?
    { 15, 2, 4 }  // ?
};

Le compilateur interprète { 13, 1, 7 } comme l'initialisateur du premier membre de houses, qui est le tableau de style C au nom défini par l'implémentation. Cela initialise l'élément 0 de ce tableau avec { 13, 1, 7 }, et les autres membres sont initialisés à zéro. Puis le compilateur constate que nous avons fourni deux valeurs d'initialisation supplémentaires ({ 14, 2, 5 } et { 15, 2, 4 }) et produit une erreur de compilation indiquant que nous avons fourni trop de valeurs d'initialisation.

La bonne façon d'initialiser ce tableau consiste à ajouter un jeu d'accolades supplémentaire, comme suit :

// Cela fonctionne comme attendu
constexpr std::array<House, 3> houses { // initialisateur de houses
    { // accolades supplémentaires pour initialiser le membre tableau de style C nommé implementation_defined_name
        { 13, 4, 30 }, // initialisateur de l'élément 0 du tableau
        { 14, 3, 10 }, // initialisateur de l'élément 1 du tableau
        { 15, 3, 40 }, // initialisateur de l'élément 2 du tableau
     }
};

Notez les accolades supplémentaires nécessaires (pour commencer l'initialisation du membre tableau de style C à l'intérieur de la structure std::array). À l'intérieur de ces accolades, nous pouvons ensuite initialiser chaque élément individuellement, chacun entre ses propres accolades.

C'est pourquoi vous verrez des initialisateurs de std::array avec un jeu d'accolades supplémentaire lorsque le type d'élément nécessite une liste de valeurs et que nous ne précisons pas explicitement le type d'élément dans l'initialisateur.

Point clé

Lorsque vous initialisez un std::array avec une structure, une classe ou un tableau, sans préciser le type d'élément dans chaque initialisateur, vous avez besoin d'une paire d'accolades supplémentaire pour que le compilateur interprète correctement ce qu'il doit initialiser.

Ceci est une conséquence de l'initialisation agrégée, et les autres types de conteneurs de la bibliothèque standard (qui utilisent des constructeurs à liste) n'ont pas besoin de double accolade dans ces cas.

Voici un exemple complet :

#include <array>
#include <iostream>

struct House
{
    int number{};
    int stories{};
    int roomsPerStory{};
};

int main()
{
    constexpr std::array<House, 3> houses {{ // notez la double accolade
        { 13, 1, 7 },
        { 14, 2, 5 },
        { 15, 2, 4 }
    }};

    for (const auto& house : houses)
    {
        std::cout << "House number " << house.number
                  << " has " << (house.stories * house.roomsPerStory)
                  << " rooms.\n";
    }

    return 0;
}

Élision d'accolades pour les agrégats

Compte tenu de l'explication précédente, vous vous demandez peut-être pourquoi le cas ci-dessus nécessite une double accolade, alors que tous les autres cas vus jusqu'ici n'exigent qu'une seule accolade :

#include <array>
#include <iostream>

int main()
{
    constexpr std::array<int, 5> arr { 1, 2, 3, 4, 5 }; // accolade simple

    for (const auto n : arr)
        std::cout << n << '\n';

    return 0;
}

Il se trouve que vous pouvez aussi fournir une double accolade pour ces tableaux :

#include <array>
#include <iostream>

int main()
{
    constexpr std::array<int, 5> arr {{ 1, 2, 3, 4, 5 }}; // double accolade

    for (const auto n : arr)
        std::cout << n << '\n';

    return 0;
}

Cependant, les agrégats en C++ prennent en charge un concept appelé élision d'accolades (brace elision), qui définit des règles indiquant quand plusieurs accolades peuvent être omises. En général, vous pouvez omettre les accolades lorsque vous initialisez un std::array avec des valeurs scalaires (simples), ou lorsque vous initialisez avec des types classes ou des tableaux dont le type est explicitement nommé pour chaque élément.

Il n'y a aucun inconvénient à toujours initialiser un std::array avec une double accolade, car cela évite de vous demander si l'élision d'accolades s'applique ou non dans un cas donné. Sinon, vous pouvez essayer une initialisation à accolade simple : le compilateur signalera généralement une erreur s'il ne parvient pas à interpréter le code. Dans ce cas, il vous suffit d'ajouter rapidement un jeu d'accolades supplémentaire.

Un autre exemple

Voici un exemple supplémentaire où nous initialisons un std::array avec des structures Student.

#include <array>
#include <iostream>
#include <string_view>

// Chaque étudiant possède un identifiant et un nom
struct Student
{
    int id{};
    std::string_view name{};
};

// Notre tableau de 3 étudiants (accolade simple, car nous mentionnons Student avec chaque initialisateur)
constexpr std::array students{ Student{0, "Alex"}, Student{ 1, "Joe" }, Student{ 2, "Bob" } };

const Student* findStudentById(int id)
{
    // Parcourir tous les étudiants
    for (auto& s : students)
    {
        // Renvoyer l'étudiant dont l'identifiant correspond
        if (s.id == id) return &s;
    }

    // Aucun identifiant correspondant n'a été trouvé
    return nullptr;
}

int main()
{
    constexpr std::string_view nobody { "nobody" };

    const Student* s1 { findStudentById(1) };
    std::cout << "You found: " << (s1 ? s1->name : nobody) << '\n';

    const Student* s2 { findStudentById(3) };
    std::cout << "You found: " << (s2 ? s2->name : nobody) << '\n';

    return 0;
}

Ce programme affiche :


You found: Joe
You found: nobody

Notez que, puisque std::array students est constexpr, notre fonction findStudentById() doit renvoyer un pointeur constant, ce qui signifie que les pointeurs Student dans main() doivent également être constants.

Quiz

Question n° 1

Définissez une structure nommée Item contenant deux membres : std::string_view name et int gold. Définissez un std::array et initialisez-le avec 4 objets Item. Utilisez CTAD pour déduire le type d'élément et la taille du tableau.

Indice

Indice : vous devrez préciser explicitement le type d'élément pour chaque initialisateur.

Le programme doit afficher :


A sword costs 5 gold.
A dagger costs 3 gold.
A club costs 2 gold.
A spear costs 7 gold.
Solution 
#include <array>
#include <iostream>
#include <string_view>

struct Item
{
    std::string_view name {};
    int gold {};
};

template <std::size_t N>
void printStore(const std::array<Item, N>& arr)
{
    for (const auto& item: arr)
    {
        std::cout << "A " << item.name << " costs " << item.gold << " gold.\n";
    }
}

int main()
{
    constexpr std::array store { // CTAD, accolades simples grâce à l'élision d'accolades
        Item { "sword",    5 },
        Item { "dagger",   3 },
        Item { "club",     2 },
        Item { "spear",    7 } };
    printStore(store);

    return 0;
}

Comme nous précisons explicitement le type d'élément pour chaque initialisateur, nous pouvons ici utiliser CTAD et des accolades simples (grâce à l'élision d'accolades).

Question n° 2

Modifiez votre solution de la question 1 pour ne pas préciser explicitement le type d'élément pour chaque initialisateur.

Solution 
#include <array>
#include <iostream>
#include <string_view>

struct Item
{
    std::string_view name {};
    int gold {};
};

template <std::size_t N>
void printStore(const std::array<Item, N>& arr)
{
    for (const auto& item: arr)
    {
        std::cout << "A " << item.name << " costs " << item.gold << " gold.\n";
    }
}

int main()
{
    constexpr std::array<Item, 4> store {{ // Pas de CTAD, il faut utiliser une double accolade
        { "sword",    5 },
        { "dagger",   3 },
        { "club",     2 },
        { "spear",    7 }
    }};
    printStore(store);

    return 0;
}

Comme nous ne précisons pas explicitement le type d'élément pour chaque initialisateur, nous ne pouvons utiliser ni CTAD ni l'élision d'accolades. Nous devons donc utiliser une double accolade.
