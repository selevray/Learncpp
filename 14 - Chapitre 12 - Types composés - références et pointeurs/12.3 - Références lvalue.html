12.3 — Références lvalue

En C++, une référence est un alias pour un objet existant. Une fois une référence définie, toute opération sur la référence s'applique à l'objet référencé. Nous pouvons donc utiliser une référence pour lire ou modifier l'objet référencé.

Bien que les références puissent sembler inutiles, superflues ou redondantes au premier abord, elles sont utilisées partout en C++ (nous en verrons des exemples dans quelques leçons).

Point clé

Une référence est essentiellement identique à l'objet référencé.

Vous pouvez aussi créer des références à des fonctions, bien que cela soit moins courant.

Le C++ moderne contient deux types de références : les références lvalue et les références rvalue. Dans ce chapitre, nous étudierons les références lvalue.

Contenu connexe

Comme nous parlerons de lvalues et de rvalues dans cette leçon, veuillez revoir 12.2 -- Catégories de valeurs (lvalues et rvalues) si vous avez besoin de rafraîchir ces notions avant de continuer. Les références rvalue sont traitées dans le chapitre sur la sémantique de déplacement (chapitre 22).

Types de références lvalue

Une référence lvalue (appelée couramment simplement « référence », car avant C++11 il n'existait qu'un seul type de référence) agit comme un alias pour une lvalue existante (comme une variable).

Tout comme le type d'un objet détermine le genre de valeur qu'il peut contenir, le type d'une référence détermine le type d'objet qu'elle peut référencer. Les types de références lvalue se reconnaissent à l'esperluette (&) unique présente dans le spécificateur de type :

// types ordinaires
int        // un type int normal (pas une référence)
int&       // une référence lvalue vers un objet int
double&    // une référence lvalue vers un objet double
const int& // une référence lvalue vers un objet const int

Par exemple, int& est le type d'une référence lvalue vers un objet int, et const int& est le type d'une référence lvalue vers un objet const int.

Un type qui spécifie une référence (par exemple int&) est appelé type référence. Le type qui peut être référencé (par exemple int) est appelé type référencé.

Nomenclature

Il existe deux sortes de références lvalue :

  • Une référence lvalue vers un objet non-const est couramment appelée simplement « référence lvalue », mais peut aussi être désignée par référence lvalue vers non-const ou référence lvalue non-const (puisqu'elle n'est pas définie avec le mot-clé const).
  • Une référence lvalue vers un objet const est couramment appelée référence lvalue vers const ou référence lvalue const.

Dans cette leçon, nous nous concentrerons sur les références lvalue non-const, et sur les références lvalue const dans la leçon suivante (12.4 -- Références lvalue vers const).

Variables de référence lvalue

L'une des choses que nous pouvons faire avec un type de référence lvalue est de créer une variable de référence lvalue. Une variable de référence lvalue est une variable qui agit comme une référence à une lvalue (généralement une autre variable).

Pour créer une variable de référence lvalue, il suffit de définir une variable avec un type de référence lvalue :

#include <iostream>

int main()
{
    int x { 5 };    // x est une variable entière ordinaire
    int& ref { x }; // ref est une variable de référence lvalue qui peut maintenant servir d'alias pour la variable x

    std::cout << x << '\n';  // affiche la valeur de x (5)
    std::cout << ref << '\n'; // affiche la valeur de x via ref (5)

    return 0;
}

Dans l'exemple ci-dessus, le type int& définit ref comme une référence lvalue vers un int, que nous initialisons avec l'expression lvalue x. Par la suite, ref et x peuvent être utilisés de façon synonyme. Ce programme affiche donc :


5
5

Du point de vue du compilateur, il importe peu que l'esperluette soit « collée » au nom du type (int& ref) ou au nom de la variable (int &ref) ; le choix relève du style. Les programmeurs C++ modernes ont tendance à coller l'esperluette au type, car cela montre plus clairement que la référence fait partie de l'information de type, et non de l'identifiant.

Bonne pratique

Lors de la définition d'une référence, placez l'esperluette à côté du type (et non à côté du nom de la variable de référence).

Pour les lecteurs avancés

Pour ceux d'entre vous qui connaissent déjà les pointeurs, l'esperluette dans ce contexte ne signifie pas « adresse de », mais « référence lvalue vers ».

Modification de valeurs via une référence lvalue non-const

Dans l'exemple précédent, nous avons montré que nous pouvons utiliser une référence pour lire la valeur de l'objet référencé. Nous pouvons également utiliser une référence non-const pour modifier la valeur de l'objet référencé :

#include <iostream>

int main()
{
    int x { 5 }; // variable entière ordinaire
    int& ref { x }; // ref est maintenant un alias de la variable x

    std::cout << x << ref << '\n'; // affiche 55

    x = 6; // x a maintenant la valeur 6

    std::cout << x << ref << '\n'; // affiche 66

    ref = 7; // l'objet référencé (x) a maintenant la valeur 7

    std::cout << x << ref << '\n'; // affiche 77

    return 0;
}

Ce code affiche :


55
66
77

Dans l'exemple ci-dessus, ref est un alias de x, nous pouvons donc modifier la valeur de x aussi bien via x que via ref.

Initialisation d'une référence

Tout comme les constantes, toutes les références doivent être initialisées. Les références sont initialisées au moyen d'une forme d'initialisation appelée initialisation de référence.

int main()
{
    int& invalidRef;   // erreur : les références doivent être initialisées

    int x { 5 };
    int& ref { x }; // correct : la référence vers int est liée à la variable int

    return 0;
}

Lorsqu'une référence est initialisée avec un objet (ou une fonction), on dit qu'elle est liée (bound) à cet objet (ou cette fonction). Le processus par lequel une telle référence est liée est appelé liaison de référence (reference binding). L'objet (ou la fonction) référencé est parfois appelé le référent.

Les références lvalue non-const ne peuvent être liées qu'à une lvalue modifiable.

int main()
{
    int x { 5 };
    int& ref { x };         // correct : référence lvalue non-const liée à une lvalue modifiable

    const int y { 5 };
    int& invalidRef { y };  // invalide : une référence lvalue non-const ne peut pas se lier à une lvalue non modifiable
    int& invalidRef2 { 0 }; // invalide : une référence lvalue non-const ne peut pas se lier à une rvalue

    return 0;
}

Point clé

Si les références lvalue non-const pouvaient être liées à des lvalues non modifiables (const) ou à des rvalues, il serait possible de modifier ces valeurs par l'intermédiaire de la référence, ce qui violerait leur caractère constant.

Les références lvalue vers void sont interdites (quel en serait l'intérêt ?).

Bien que le type de la référence (par exemple int&) ne corresponde pas exactement au type de l'objet lié (par exemple int), aucune conversion n'est appliquée ici (pas même une conversion triviale) : la différence de types est gérée dans le cadre du processus d'initialisation de la référence.

Une référence ne se lie (en général) qu'à un objet correspondant à son type référencé

Dans la plupart des cas, une référence ne se lie qu'à un objet dont le type correspond au type référencé (il existe quelques exceptions à cette règle, que nous aborderons lorsque nous étudierons l'héritage).

Si vous essayez de lier une référence à un objet dont le type ne correspond pas au type référencé, le compilateur tentera de convertir implicitement l'objet vers le type référencé, puis de lier la référence à ce résultat.

Point clé

Comme le résultat d'une conversion est une rvalue, et qu'une référence lvalue non-const ne peut pas se lier à une rvalue, tenter de lier une référence lvalue non-const à un objet dont le type ne correspond pas au type référencé provoque une erreur de compilation.

int main()
{
    int x { 5 };
    int& ref { x };            // correct : le type référencé (int) correspond au type de l'initialisateur

    double d { 6.0 };
    int& invalidRef { d };     // invalide : la conversion de double en int est une conversion restrictive, interdite par l'initialisation par liste
    double& invalidRef2 { x }; // invalide : une référence lvalue non-const ne peut pas se lier à une rvalue (résultat de la conversion de x en double)

    return 0;
}

Les références ne peuvent pas être réaffectées (changées pour référencer un autre objet)

Une fois initialisée, une référence en C++ ne peut pas être réaffectée (reseated), c'est-à-dire modifiée pour référencer un autre objet.

Les nouveaux programmeurs C++ tentent souvent de réaffecter une référence en utilisant l'affectation pour lui fournir une autre variable à référencer. Cela compile et s'exécute, mais ne fonctionne pas comme prévu. Considérez le programme suivant :

#include <iostream>

int main()
{
    int x { 5 };
    int y { 6 };

    int& ref { x }; // ref est maintenant un alias de x

    ref = y; // affecte 6 (la valeur de y) à x (l'objet référencé par ref)
    // La ligne ci-dessus ne transforme PAS ref en une référence vers la variable y !

    std::cout << x << '\n'; // l'utilisateur s'attend à ce que cela affiche 5

    return 0;
}

Étonnamment peut-être, cela affiche :


6

Lorsqu'une référence est évaluée dans une expression, elle se résout en l'objet qu'elle référence. Ainsi, ref = y ne change pas ref pour qu'elle référence maintenant y. En fait, comme ref est un alias de x, l'expression s'évalue comme si elle était écrite x = y : comme y a pour valeur 6, x reçoit la valeur 6.

Portée et durée de vie des références

Les variables de référence suivent les mêmes règles de portée et de durée de vie que les variables ordinaires :

#include <iostream>

int main()
{
    int x { 5 }; // entier ordinaire
    int& ref { x }; // référence vers la variable valeur

     return 0;
} // x et ref sont détruits ici

Les références et leurs référents ont des durées de vie indépendantes

À une exception près (que nous verrons dans la prochaine leçon), la durée de vie d'une référence et celle de son référent sont indépendantes. Autrement dit, les deux affirmations suivantes sont vraies :

  • Une référence peut être détruite avant l'objet qu'elle référence.
  • L'objet référencé peut être détruit avant la référence.

Lorsqu'une référence est détruite avant son référent, le référent n'est pas affecté. Le programme suivant le démontre :

#include <iostream>

int main()
{
    int x { 5 };

    {
        int& ref { x };   // ref est une référence vers x
        std::cout << ref << '\n'; // affiche la valeur de ref (5)
    } // ref est détruite ici -- x n'en sait rien

    std::cout << x << '\n'; // affiche la valeur de x (5)

    return 0;
} // x est détruite ici

Ce qui précède affiche :


5
5

Lorsque ref disparaît, la variable x poursuit son existence normalement, ignorant avec sérénité qu'une référence vers elle a été détruite.

Références pendantes

Lorsqu'un objet référencé est détruit avant une référence vers lui, la référence reste liée à un objet qui n'existe plus. Une telle référence est appelée référence pendante (dangling reference). Accéder à une référence pendante conduit à un comportement indéfini.

Les références pendantes sont assez faciles à éviter, mais nous montrerons un cas où cela peut se produire en pratique dans la leçon 12.12 -- Renvoi par référence et renvoi par adresse.

Les références ne sont pas des objets

Étonnamment peut-être, les références ne sont pas des objets en C++. Une référence n'est pas obligée d'exister ni d'occuper un espace de stockage. Lorsque c'est possible, le compilateur optimise les références en remplaçant toutes leurs occurrences par le référent. Cependant, ce n'est pas toujours possible, et dans ces cas, les références peuvent nécessiter un espace de stockage.

Cela signifie également que l'expression « variable de référence » est un peu un abus de langage, car les variables sont des objets nommés, alors que les références ne sont pas des objets.

Comme les références ne sont pas des objets, elles ne peuvent pas être utilisées partout où un objet est requis (par exemple, vous ne pouvez pas avoir de référence vers une référence, puisqu'une référence lvalue doit référencer un objet identifiable). Lorsque vous avez besoin d'une référence qui soit un objet, ou d'une référence qui puisse être réaffectée, std::reference_wrapper (que nous présentons dans la leçon 23.3 -- Agrégation) fournit une solution.

En passant…

Considérez les variables suivantes :

int var{};
int& ref1{ var };  // une référence lvalue liée à var
int& ref2{ ref1 }; // une référence lvalue liée à var

Comme ref2 (une référence) est initialisée avec ref1 (une référence), on pourrait être tenté de conclure que ref2 est une référence vers une référence. Ce n'est pas le cas. Comme ref1 est une référence vers var, lorsqu'elle est utilisée dans une expression (comme un initialisateur), ref1 s'évalue en var. Ainsi, ref2 est simplement une référence lvalue ordinaire (comme l'indique son type int&), liée à var.

Une référence vers une référence (vers un int) aurait pour syntaxe int&&, mais comme le C++ ne prend pas en charge les références vers des références, cette syntaxe a été réutilisée en C++11 pour désigner une référence rvalue (que nous étudierons dans la leçon 22.2 -- Références rvalue).

Note de l'auteur

Si les références vous semblent un peu inutiles à ce stade, ne vous inquiétez pas. Les références sont très utilisées, et nous verrons bientôt l'une des principales raisons de leur existence, dans les leçons 12.5 -- Passage par référence lvalue et 12.6 -- Passage par référence lvalue vers const.
