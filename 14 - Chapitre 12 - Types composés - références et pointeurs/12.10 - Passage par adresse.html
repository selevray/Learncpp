12.10 — Passage par adresse

Dans les leçons précédentes, nous avons vu deux façons de passer un argument à une fonction : le passage par valeur (2.4 -- Introduction aux paramètres et arguments de fonction) et le passage par référence (12.5 -- Passage par référence lvalue).

Voici un programme d'exemple qui montre un objet std::string passé par valeur et par référence :

#include <iostream>
#include <string>

void printByValue(std::string val) // Le paramètre de la fonction est une copie de str
{
    std::cout << val << '\n'; // affiche la valeur via la copie
}

void printByReference(const std::string& ref) // Le paramètre de la fonction est une référence qui se lie à str
{
    std::cout << ref << '\n'; // affiche la valeur via la référence
}

int main()
{
    std::string str{ "Hello, world!" };

    printByValue(str); // passe str par valeur, crée une copie de str
    printByReference(str); // passe str par référence, ne crée pas de copie de str

    return 0;
}

Lorsque nous passons l'argument str par valeur, le paramètre val reçoit une copie de l'argument. Comme le paramètre est une copie de l'argument, toute modification de val porte sur la copie et non sur l'argument d'origine.

Lorsque nous passons l'argument str par référence, le paramètre de type référence ref est lié à l'argument réel. Cela évite de copier l'argument. Comme notre paramètre de référence est const, nous ne sommes pas autorisés à modifier ref. Mais si ref n'était pas const, toute modification de ref modifierait str.

Dans les deux cas, l'appelant fournit l'objet réel (str) à passer en argument à l'appel de fonction.

Passage par adresse

Le C++ propose une troisième façon de transmettre des valeurs à une fonction, appelée passage par adresse. Avec le passage par adresse (pass by address), au lieu de fournir un objet comme argument, l'appelant fournit l'adresse de l'objet (sous forme de pointeur). Ce pointeur (qui contient l'adresse de l'objet) est copié dans un paramètre pointeur de la fonction appelée (qui contient désormais également l'adresse de l'objet). La fonction peut alors déréférencer ce pointeur pour accéder à l'objet dont l'adresse a été transmise.

Voici une version du programme précédent qui ajoute une variante avec passage par adresse :

#include <iostream>
#include <string>

void printByValue(std::string val) // Le paramètre de la fonction est une copie de str
{
    std::cout << val << '\n'; // affiche la valeur via la copie
}

void printByReference(const std::string& ref) // Le paramètre de la fonction est une référence qui se lie à str
{
    std::cout << ref << '\n'; // affiche la valeur via la référence
}

void printByAddress(const std::string* ptr) // Le paramètre de la fonction est un pointeur qui contient l'adresse de str
{
    std::cout << *ptr << '\n'; // affiche la valeur via le pointeur déréférencé
}

int main()
{
    std::string str{ "Hello, world!" };

    printByValue(str); // passe str par valeur, crée une copie de str
    printByReference(str); // passe str par référence, ne crée pas de copie de str
    printByAddress(&str); // passe str par adresse, ne crée pas de copie de str

    return 0;
}

Remarquez à quel point ces trois versions se ressemblent. Explorons plus en détail la version avec passage par adresse.

Tout d'abord, puisque nous voulons que notre fonction printByAddress() utilise le passage par adresse, nous avons fait de son paramètre un pointeur nommé ptr. Comme printByAddress() ne fait qu'utiliser ptr en lecture seule, ptr est un pointeur vers une valeur const.

void printByAddress(const std::string* ptr)
{
    std::cout << *ptr << '\n'; // affiche la valeur via le pointeur déréférencé
}

Dans la fonction printByAddress(), nous déréférençons le paramètre ptr pour accéder à la valeur de l'objet pointé.

Ensuite, lorsque la fonction est appelée, nous ne pouvons pas simplement passer l'objet str : il faut passer l'adresse de str. La façon la plus simple de le faire est d'utiliser l'opérateur d'adresse (&) pour obtenir un pointeur contenant l'adresse de str :

printByAddress(&str); // utilise l'opérateur d'adresse (&) pour obtenir un pointeur contenant l'adresse de str

Lorsque cet appel est exécuté, &str crée un pointeur contenant l'adresse de str. Cette adresse est ensuite copiée dans le paramètre ptr dans le cadre de l'appel de fonction. Comme ptr contient désormais l'adresse de str, lorsque la fonction déréférence ptr, elle obtient la valeur de str, qu'elle affiche dans la console.

C'est tout.

Bien que nous utilisions l'opérateur d'adresse dans l'exemple ci-dessus pour obtenir l'adresse de str, si nous disposions déjà d'une variable pointeur contenant l'adresse de str, nous pourrions l'utiliser à la place :

int main()
{
    std::string str{ "Hello, world!" };

    printByValue(str); // passe str par valeur, crée une copie de str
    printByReference(str); // passe str par référence, ne crée pas de copie de str
    printByAddress(&str); // passe str par adresse, ne crée pas de copie de str

    std::string* ptr { &str }; // définit une variable pointeur contenant l'adresse de str
    printByAddress(ptr); // passe str par adresse, ne crée pas de copie de str

    return 0;
}

Nomenclature

Lorsque nous passons l'adresse d'une variable comme argument en utilisant operator&, nous disons que la variable est passée par adresse.

Lorsque nous disposons d'une variable pointeur contenant l'adresse d'un objet, et que nous passons ce pointeur comme argument à un paramètre du même type, nous disons que l'objet est passé par adresse, et que le pointeur est passé par valeur.

Le passage par adresse ne copie pas l'objet pointé

Considérons les instructions suivantes :

std::string str{ "Hello, world!" };
printByAddress(&str); // utilise l'opérateur d'adresse (&) pour obtenir un pointeur contenant l'adresse de str

Comme nous l'avons noté dans 12.5 -- Passage par référence lvalue, copier un std::string est coûteux, c'est donc quelque chose que nous voulons éviter. Lorsque nous passons un std::string par adresse, nous ne copions pas l'objet std::string lui-même : nous copions seulement le pointeur (contenant l'adresse de l'objet) de l'appelant vers la fonction appelée. Une adresse occupe généralement 4 ou 8 octets, donc un pointeur ne fait que 4 ou 8 octets, et copier un pointeur est toujours rapide.

Ainsi, tout comme le passage par référence, le passage par adresse est rapide et évite de copier l'objet argument.

Le passage par adresse permet à la fonction de modifier la valeur de l'argument

Lorsque nous passons un objet par adresse, la fonction reçoit l'adresse de l'objet transmis, à laquelle elle peut accéder par déréférencement. Comme il s'agit de l'adresse de l'objet argument réel (et non d'une copie de celui-ci), si le paramètre de la fonction est un pointeur vers une valeur non const, la fonction peut modifier l'argument via le paramètre pointeur :

#include <iostream>

void changeValue(int* ptr) // remarque : ptr est un pointeur vers une valeur non const dans cet exemple
{
    *ptr = 6; // change la valeur en 6
}

int main()
{
    int x{ 5 };

    std::cout << "x = " << x << '\n';

    changeValue(&x); // nous passons l'adresse de x à la fonction

    std::cout << "x = " << x << '\n';

    return 0;
}

Ce programme affiche :


x = 5
x = 6

Comme vous pouvez le voir, l'argument est modifié, et cette modification persiste même après la fin de l'exécution de changeValue().

Si une fonction n'est pas censée modifier l'objet transmis, le paramètre de la fonction doit être un pointeur vers une valeur const :

void changeValue(const int* ptr) // remarque : ptr est maintenant un pointeur vers une valeur const
{
    *ptr = 6; // erreur : impossible de modifier une valeur const
}

Pour beaucoup des mêmes raisons pour lesquelles nous ne mettons généralement pas const sur les paramètres de fonction ordinaires (ni pointeurs, ni références) (expliquées dans 5.1 -- Variables constantes (constantes nommées)), nous ne mettons généralement pas non plus const sur les paramètres de fonction de type pointeur. Formulons deux affirmations :

  • Un mot-clé const utilisé pour faire d'un paramètre pointeur un pointeur constant apporte peu de valeur (car il n'a aucun impact sur l'appelant, et sert surtout de documentation indiquant que le pointeur ne changera pas).
  • Un mot-clé const utilisé pour distinguer un pointeur vers une valeur const d'un pointeur vers une valeur non const pouvant modifier l'objet transmis est significatif (car l'appelant doit savoir si la fonction pourrait modifier la valeur de l'argument).

Si nous n'utilisons que des paramètres pointeurs non const, alors toutes les utilisations de const sont significatives. Dès que nous commençons à utiliser const pour des paramètres pointeurs constants, il devient plus difficile de déterminer si une utilisation donnée de const est significative ou non. Plus grave encore, il devient plus difficile de repérer les paramètres pointeurs vers des valeurs non const. Par exemple :

void foo(const char* source, char* dest, int count);             // Avec des pointeurs non const, tous les const sont significatifs.
void foo(const char* const source, char* const dest, int count); // Avec des pointeurs const, `dest` étant un pointeur vers une valeur non const peut passer inaperçu parmi la mer de const superflus.

Dans le premier cas, il est facile de voir que source est un pointeur vers une valeur const et que dest est un pointeur vers une valeur non const. Dans le second cas, il est beaucoup plus difficile de voir que dest est un pointeur constant vers une valeur non const, dont l'objet pointé peut être modifié par la fonction !

Bonne pratique

Préférez les paramètres de fonction pointeurs vers des valeurs const aux paramètres pointeurs vers des valeurs non const, sauf si la fonction doit modifier l'objet transmis.
Ne rendez pas les paramètres de fonction des pointeurs constants, sauf raison particulière.

Vérification de la valeur nulle

Considérons maintenant ce programme en apparence anodin :

#include <iostream>

void print(int* ptr)
{
    std::cout << *ptr << '\n';
}

int main()
{
    int x{ 5 };
    print(&x);

    int* myPtr {};
    print(myPtr);

    return 0;
}

Lorsque ce programme est exécuté, il affiche la valeur 5, puis plante très probablement.

Lors de l'appel print(myPtr), myPtr est un pointeur nul, donc le paramètre ptr de la fonction sera également un pointeur nul. Lorsque ce pointeur nul est déréférencé dans le corps de la fonction, il en résulte un comportement indéfini.

Lorsqu'on passe un paramètre par adresse, il faut veiller à ce que le pointeur ne soit pas nul avant de le déréférencer. Une façon de le faire est d'utiliser une instruction conditionnelle :

#include <iostream>

void print(int* ptr)
{
    if (ptr) // si ptr n'est pas un pointeur nul
    {
        std::cout << *ptr << '\n';
    }
}

int main()
{
    int x{ 5 };

    print(&x);
    print(nullptr);

    return 0;
}

Dans le programme ci-dessus, nous testons ptr pour nous assurer qu'il n'est pas nul avant de le déréférencer. Bien que cela convienne pour une fonction aussi simple, dans des fonctions plus complexes cela peut conduire à une logique redondante (tester plusieurs fois que ptr n'est pas nul) ou à l'imbrication de la logique principale de la fonction (si elle est contenue dans un bloc).

Dans la plupart des cas, il est plus efficace de faire l'inverse : tester si le paramètre de la fonction est nul en tant que précondition (9.6 -- Assert et static_assert) et traiter le cas négatif immédiatement :

#include <iostream>

void print(int* ptr)
{
    if (!ptr) // si ptr est un pointeur nul, retour anticipé à l'appelant
        return;

    // si nous avons atteint ce point, nous pouvons considérer que ptr est valide
    // donc aucun test ni imbrication supplémentaire n'est nécessaire

    std::cout << *ptr << '\n';
}

int main()
{
    int x{ 5 };

    print(&x);
    print(nullptr);

    return 0;
}

Si un pointeur nul ne devrait jamais être passé à la fonction, un assert (que nous avons présenté dans la leçon 9.6 -- Assert et static_assert) peut être utilisé à la place (ou en complément), car les assertions servent à documenter ce qui ne devrait jamais se produire :

#include <iostream>
#include <cassert>

void print(const int* ptr) // désormais un pointeur vers un int const
{
    assert(ptr); // fait échouer le programme en mode débogage si un pointeur nul est passé (puisque cela ne devrait jamais arriver)

    // (optionnellement) traite ce cas comme une erreur en mode production afin de ne pas planter si cela se produit
    if (!ptr)
        return;

    std::cout << *ptr << '\n';
}

int main()
{
    int x{ 5 };

    print(&x);
    print(nullptr);

    return 0;
}

Préférer le passage par référence (const)

Notez que la fonction print() de l'exemple ci-dessus ne gère pas très bien les valeurs nulles : elle se contente en pratique d'interrompre la fonction. Dans ces conditions, pourquoi autoriser un utilisateur à passer une valeur nulle ? Le passage par référence offre les mêmes avantages que le passage par adresse, sans le risque de déréférencer par inadvertance un pointeur nul.

Le passage par référence const présente également quelques autres avantages par rapport au passage par adresse.

Tout d'abord, comme un objet passé par adresse doit avoir une adresse, seules les lvalues peuvent être passées par adresse (les rvalues n'ont pas d'adresse). Le passage par référence const est plus souple, car il peut accepter aussi bien des lvalues que des rvalues :

#include <iostream>

void printByValue(int val) // Le paramètre de la fonction est une copie de l'argument
{
    std::cout << val << '\n'; // affiche la valeur via la copie
}

void printByReference(const int& ref) // Le paramètre de la fonction est une référence qui se lie à l'argument
{
    std::cout << ref << '\n'; // affiche la valeur via la référence
}

void printByAddress(const int* ptr) // Le paramètre de la fonction est un pointeur qui contient l'adresse de l'argument
{
    std::cout << *ptr << '\n'; // affiche la valeur via le pointeur déréférencé
}

int main()
{
    printByValue(5);     // valide (mais crée une copie)
    printByReference(5); // valide (car le paramètre est une référence const)
    printByAddress(&5);  // erreur : impossible de prendre l'adresse d'une rvalue

    return 0;
}

Ensuite, la syntaxe du passage par référence est naturelle, puisque nous pouvons simplement passer des littéraux ou des objets. Avec le passage par adresse, notre code se retrouve encombré d'esperluettes (&) et d'astérisques (*).

En C++ moderne, la plupart des choses réalisables avec le passage par adresse sont mieux accomplies par d'autres moyens. Retenez cette maxime courante : « Passez par référence quand vous le pouvez, passez par adresse quand vous le devez ».

Bonne pratique

Préférez le passage par référence au passage par adresse, sauf si vous avez une raison spécifique d'utiliser le passage par adresse.
