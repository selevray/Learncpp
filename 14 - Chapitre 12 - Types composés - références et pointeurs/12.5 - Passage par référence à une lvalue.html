12.5 — Passage par référence à une lvalue

Dans les leçons précédentes, nous avons présenté les références lvalue (12.3 -- Références lvalue) et les références lvalue vers const (12.4 -- Références lvalue vers const). Prises isolément, elles peuvent sembler peu utiles : pourquoi créer un alias vers une variable alors que vous pouvez utiliser la variable elle-même ?

Dans cette leçon, nous allons enfin montrer ce qui rend les références utiles. À partir de la fin de ce chapitre, vous verrez les références utilisées régulièrement.

Commençons par un peu de contexte. Dans la leçon 2.4 -- Introduction aux paramètres et aux arguments de fonction, nous avons présenté le passage par valeur, où un argument passé à une fonction est copié dans le paramètre de cette fonction :

#include <iostream>

void printValue(int y)
{
    std::cout << y << '\n';
} // y est détruit ici

int main()
{
    int x { 2 };

    printValue(x); // x est passé par valeur (copié) dans le paramètre y (peu coûteux)

    return 0;
}

Dans le programme ci-dessus, lors de l'appel printValue(x), la valeur de x (2) est copiée dans le paramètre y. Puis, à la fin de la fonction, l'objet y est détruit.

Cela signifie que, lors de l'appel, nous avons fait une copie de la valeur de l'argument, pour ne l'utiliser que brièvement avant de la détruire ! Heureusement, comme les types fondamentaux sont peu coûteux à copier, ce n'est pas un problème.

Certains objets sont coûteux à copier

La plupart des types fournis par la bibliothèque standard (comme std::string) sont des types classe. Les types classe sont généralement coûteux à copier. Chaque fois que c'est possible, nous voulons éviter de faire des copies inutiles d'objets coûteux à copier, surtout lorsque nous allons détruire ces copies presque immédiatement.

Considérez le programme suivant, qui illustre ce point :

#include <iostream>
#include <string>

void printValue(std::string y)
{
    std::cout << y << '\n';
} // y est détruit ici

int main()
{
    std::string x { "Hello, world!" }; // x est un std::string

    printValue(x); // x est passé par valeur (copié) dans le paramètre y (coûteux)

    return 0;
}

Ce programme affiche :


Hello, world!

Bien que ce programme se comporte comme nous l'attendons, il est aussi inefficace. Exactement comme dans l'exemple précédent, lors de l'appel de printValue(), l'argument x est copié dans le paramètre y de printValue(). Cependant, dans cet exemple, l'argument est un std::string au lieu d'un int, et std::string est un type classe coûteux à copier. Et cette copie coûteuse est faite à chaque appel de printValue() !

Nous pouvons faire mieux.

Passage par référence

Une façon d'éviter une copie coûteuse d'un argument lors de l'appel d'une fonction consiste à utiliser le passage par référence plutôt que le passage par valeur. Avec le passage par référence, nous déclarons un paramètre de fonction avec un type référence (ou un type référence vers const) plutôt qu'avec un type normal. Lors de l'appel de la fonction, chaque paramètre référence est lié à l'argument correspondant. Comme la référence agit comme un alias de l'argument, aucune copie de l'argument n'est faite.

Voici le même exemple que précédemment, mais avec un passage par référence au lieu d'un passage par valeur :

#include <iostream>
#include <string>

void printValue(std::string& y) // type changé en std::string&
{
    std::cout << y << '\n';
} // y est détruit ici

int main()
{
    std::string x { "Hello, world!" };

    printValue(x); // x est maintenant passé par référence dans le paramètre référence y (peu coûteux)

    return 0;
}

Ce programme est identique au précédent, sauf que le type du paramètre y est passé de std::string à std::string& (une référence lvalue). Désormais, lors de l'appel printValue(x), le paramètre référence lvalue y est lié à l'argument x. Lier une référence est toujours peu coûteux, et aucune copie de x n'est nécessaire. Comme une référence agit comme un alias de l'objet référencé, lorsque printValue() utilise la référence y, elle accède à l'argument réel x (et non à une copie de x).

Point clé

Le passage par référence nous permet de transmettre des arguments à une fonction sans faire de copie de ces arguments à chaque appel de la fonction.

Le programme suivant montre qu'un paramètre passé par valeur est un objet distinct de l'argument, alors qu'un paramètre référence est traité comme s'il était l'argument lui-même :

#include <iostream>

void printAddresses(int val, int& ref)
{
    std::cout << "The address of the value parameter is: " << &val << '\n';
    std::cout << "The address of the reference parameter is: " << &ref << '\n';
}

int main()
{
    int x { 5 };
    std::cout << "The address of x is: " << &x << '\n';
    printAddresses(x, x);

    return 0;
}

Une exécution de ce programme a produit la sortie suivante :


The address of x is: 0x7ffd16574de0
The address of the value parameter is: 0x7ffd16574de4
The address of the reference parameter is: 0x7ffd16574de0

Nous constatons que l'argument a une adresse différente de celle du paramètre passé par valeur, ce qui signifie que ce paramètre est un objet différent. Comme ils ont des adresses mémoire distinctes, pour que le paramètre passé par valeur ait la même valeur que l'argument, la valeur de l'argument doit être copiée dans la mémoire occupée par le paramètre.

En revanche, nous constatons que l'adresse du paramètre référence est identique à celle de l'argument. Cela signifie que le paramètre référence est traité comme s'il s'agissait du même objet que l'argument.

Le passage par référence permet de modifier la valeur d'un argument

Lorsqu'un objet est passé par valeur, le paramètre de la fonction reçoit une copie de l'argument. Cela signifie que toute modification de la valeur du paramètre est faite sur la copie de l'argument, et non sur l'argument lui-même :

#include <iostream>

void addOne(int y) // y est une copie de x
{
    ++y; // ceci modifie la copie de x, et non l'objet x réel
}

int main()
{
    int x { 5 };

    std::cout << "value = " << x << '\n';

    addOne(x);

    std::cout << "value = " << x << '\n'; // x n'a pas été modifié

    return 0;
}

Dans le programme ci-dessus, comme le paramètre passé par valeur y est une copie de x, lorsque nous incrémentons y, cela n'affecte que y. Ce programme affiche :


value = 5
value = 5

En revanche, comme une référence se comporte exactement comme l'objet référencé, avec le passage par référence, toute modification faite sur le paramètre référence affectera l'argument :

#include <iostream>

void addOne(int& y) // y est lié à l'objet x réel
{
    ++y; // ceci modifie l'objet x réel
}

int main()
{
    int x { 5 };

    std::cout << "value = " << x << '\n';

    addOne(x);

    std::cout << "value = " << x << '\n'; // x a été modifié

    return 0;
}

Ce programme affiche :


value = 5
value = 6

Dans l'exemple ci-dessus, x vaut initialement 5. Lors de l'appel addOne(x), la référence paramètre y est liée à l'argument x. Lorsque la fonction addOne() incrémente la référence y, elle incrémente en réalité l'argument x de 5 à 6 (et non une copie de x). Cette valeur modifiée persiste même après la fin de l'exécution de addOne().

Point clé

Passer des valeurs par référence vers un non-const nous permet d'écrire des fonctions qui modifient la valeur des arguments transmis.

La capacité d'une fonction à modifier la valeur des arguments qu'elle reçoit peut être utile. Imaginez que vous avez écrit une fonction qui détermine si un monstre a réussi à attaquer le joueur. Si c'est le cas, le monstre doit infliger une certaine quantité de dégâts à la santé du joueur. Si vous passez l'objet joueur par référence, la fonction peut modifier directement la santé de l'objet joueur réel qui a été transmis. Si vous passez l'objet joueur par valeur, vous ne pourriez modifier que la santé d'une copie de cet objet, ce qui est moins utile.

Le passage par référence n'accepte que des arguments lvalue modifiables

Une référence vers une valeur non-const ne peut se lier qu'à une lvalue modifiable (en pratique, une variable non-const). Cela signifie que le passage par référence vers un non-const ne fonctionne qu'avec des arguments qui sont des lvalues modifiables. Concrètement, cela limite nettement l'utilité du passage par référence vers un non-const, car nous ne pouvons pas passer de variables const ni de littéraux. Par exemple :

#include <iostream>

void printValue(int& y) // y n'accepte que des lvalues modifiables
{
    std::cout << y << '\n';
}

int main()
{
    int x { 5 };
    printValue(x); // ok : x est une lvalue modifiable

    const int z { 5 };
    printValue(z); // erreur : z est une lvalue non modifiable

    printValue(5); // erreur : 5 est une rvalue

    return 0;
}

Heureusement, il existe un moyen simple de contourner ce problème, que nous verrons dans la prochaine leçon. Nous examinerons aussi quand utiliser le passage par valeur et quand utiliser le passage par référence.
