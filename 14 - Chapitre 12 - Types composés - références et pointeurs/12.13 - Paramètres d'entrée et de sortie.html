12.13 — Paramètres d'entrée et de sortie

Une fonction et son appelant communiquent entre eux par deux mécanismes : les paramètres et les valeurs de retour. Lorsqu'une fonction est appelée, l'appelant fournit des arguments, que la fonction reçoit par l'intermédiaire de ses paramètres. Ces arguments peuvent être passés par valeur, par référence ou par adresse.

En général, nous passerons les arguments par valeur ou par référence constante. Mais il arrive que nous devions faire autrement.

Paramètres d'entrée

Dans la plupart des cas, un paramètre de fonction sert uniquement à recevoir une entrée de l'appelant. Les paramètres qui ne servent qu'à recevoir des données de l'appelant sont parfois appelés paramètres d'entrée (in parameters).

#include <iostream>

void print(int x) // x est un paramètre d'entrée
{
    std::cout << x << '\n';
}

void print(const std::string& s) // s est un paramètre d'entrée
{
    std::cout << s << '\n';
}

int main()
{
    print(5);
    std::string s { "Hello, world!" };
    print(s);

    return 0;
}

Les paramètres d'entrée sont généralement passés par valeur ou par référence constante.

Paramètres de sortie

Un argument de fonction passé par référence non constante (ou par pointeur vers un objet non constant) permet à la fonction de modifier la valeur de l'objet passé en argument. Cela offre à une fonction un moyen de renvoyer des données à l'appelant lorsque l'utilisation d'une valeur de retour ne suffit pas pour une raison ou une autre.

Un paramètre de fonction qui ne sert qu'à renvoyer des informations à l'appelant est appelé paramètre de sortie (out parameter).

Par exemple :

#include <cmath>    // pour std::sin() et std::cos()
#include <iostream>

// sinOut et cosOut sont des paramètres de sortie
void getSinCos(double degrees, double& sinOut, double& cosOut)
{
    // sin() et cos() prennent des radians, et non des degrés, il faut donc convertir
    constexpr double pi { 3.14159265358979323846 }; // la valeur de pi
    double radians = degrees * pi / 180.0;
    sinOut = std::sin(radians);
    cosOut = std::cos(radians);
}

int main()
{
    double sin { 0.0 };
    double cos { 0.0 };

    double degrees{};
    std::cout << "Entrez le nombre de degrés : ";
    std::cin >> degrees;

    // getSinCos renverra le sinus et le cosinus dans les variables sin et cos
    getSinCos(degrees, sin, cos);

    std::cout << "Le sinus vaut " << sin << '\n';
    std::cout << "Le cosinus vaut " << cos << '\n';

    return 0;
}

Cette fonction possède un paramètre degrees (dont l'argument est passé par valeur) en entrée, et « renvoie » deux paramètres (par référence) en sortie.

Nous avons nommé ces paramètres de sortie avec le suffixe « out » pour indiquer qu'il s'agit de paramètres de sortie. Cela rappelle à l'appelant que la valeur initiale passée à ces paramètres n'a pas d'importance, et que nous devons nous attendre à ce qu'elle soit écrasée. Par convention, les paramètres de sortie sont généralement les paramètres les plus à droite.

Examinons plus en détail le fonctionnement de ce mécanisme. Tout d'abord, la fonction main crée les variables locales sin et cos. Celles-ci sont passées à la fonction getSinCos() par référence (et non par valeur). Cela signifie que la fonction getSinCos() accède aux variables sin et cos de main() elles-mêmes, et non à de simples copies. getSinCos() affecte donc de nouvelles valeurs à sin et cos (par l'intermédiaire des références sinOut et cosOut respectivement), ce qui écrase les anciennes valeurs de sin et cos. La fonction main() affiche ensuite ces valeurs mises à jour.

Si sin et cos avaient été passées par valeur au lieu de par référence, getSinCos() aurait modifié des copies de sin et cos, et toutes les modifications auraient été perdues à la fin de la fonction. Mais comme sin et cos ont été passées par référence, toute modification apportée à sin ou cos (par l'intermédiaire des références) persiste au-delà de la fonction. Nous pouvons donc utiliser ce mécanisme pour renvoyer des valeurs à l'appelant.

Les paramètres de sortie ont une syntaxe d'utilisation peu naturelle

Les paramètres de sortie, bien que fonctionnels, présentent quelques inconvénients.

Premièrement, l'appelant doit instancier (et initialiser) des objets et les passer en arguments, même s'il n'a pas l'intention de les utiliser. Ces objets doivent pouvoir recevoir une affectation, ce qui signifie qu'ils ne peuvent pas être const.

Deuxièmement, comme l'appelant doit fournir des objets, ces valeurs ne peuvent pas être utilisées comme temporaires, ni facilement intégrées dans une seule expression.

L'exemple suivant illustre ces deux inconvénients :

#include <iostream>

int getByValue()
{
    return 5;
}

void getByReference(int& x)
{
    x = 5;
}

int main()
{
    // retour par valeur
    [[maybe_unused]] int x{ getByValue() }; // peut servir à initialiser un objet
    std::cout << getByValue() << '\n';      // la valeur de retour temporaire peut être utilisée dans une expression

    // retour par paramètre de sortie
    int y{};                // il faut d'abord créer un objet modifiable
    getByReference(y);      // puis le passer à la fonction pour y affecter la valeur voulue
    std::cout << y << '\n'; // et ce n'est qu'ensuite que l'on peut utiliser cette valeur

    return 0;
}

Comme vous pouvez le constater, la syntaxe d'utilisation des paramètres de sortie est un peu peu naturelle.

Les paramètres de sortie passés par référence ne rendent pas évident que les arguments seront modifiés

Lorsque nous affectons la valeur de retour d'une fonction à un objet, il est clair que la valeur de cet objet est modifiée :

x = getByValue(); // il est évident que x est modifié

C'est une bonne chose, car cela indique clairement que nous devons nous attendre à un changement de valeur de x.

Revenons cependant à l'appel de fonction getSinCos() de l'exemple précédent :

    getSinCos(degrees, sin, cos);

Il n'est pas évident, à la lecture de cet appel, que degrees est un paramètre d'entrée alors que sin et cos sont des paramètres de sortie. Si l'appelant ne se rend pas compte que sin et cos vont être modifiés, cela entraînera probablement une erreur sémantique.

Passer par adresse plutôt que par référence peut, dans certains cas, rendre les paramètres de sortie plus évidents, car l'appelant est obligé de passer l'adresse des objets en arguments.

Considérez l'exemple suivant :

void foo1(int x);  // passage par valeur
void foo2(int& x); // passage par référence
void foo3(int* x); // passage par adresse

int main()
{
    int i{};

    foo1(i);  // ne peut pas modifier i
    foo2(i);  // peut modifier i (pas évident)
    foo3(&i); // peut modifier i

    int *ptr { &i };
    foo3(ptr); // peut modifier i (pas évident)

    return 0;
}

Remarquez que, dans l'appel foo3(&i), nous devons passer &i et non i, ce qui indique plus clairement que i va être modifié.

Cependant, ce n'est pas infaillible, car foo3(ptr) permet à foo3() de modifier i sans que l'appelant ait besoin d'utiliser l'opérateur d'adresse sur ptr.

L'appelant peut également croire qu'il peut passer nullptr ou un pointeur nul comme argument valide, alors que cela est interdit. De plus, la fonction doit alors vérifier et gérer les pointeurs nuls, ce qui ajoute de la complexité. Cette gestion supplémentaire des pointeurs nuls pose souvent plus de problèmes que de s'en tenir au passage par référence.

Pour toutes ces raisons, les paramètres de sortie doivent être évités, sauf lorsqu'aucune autre bonne solution n'existe.

Bonne pratique

Évitez les paramètres de sortie (sauf dans le rare cas où aucune meilleure solution n'existe).

Préférez le passage par référence pour les paramètres de sortie non optionnels.

Paramètres d'entrée-sortie

Dans de rares cas, une fonction utilise effectivement la valeur d'un paramètre de sortie avant d'en écraser la valeur. Un tel paramètre est appelé paramètre d'entrée-sortie (in-out parameter). Les paramètres d'entrée-sortie fonctionnent de manière identique aux paramètres de sortie et présentent les mêmes difficultés.

Quand passer par référence non constante

Si vous passez par référence afin d'éviter de copier l'argument, vous devriez presque toujours passer par référence constante.

Note de l'auteur

Dans les exemples suivants, nous utiliserons Foo pour représenter un type qui nous intéresse. Pour l'instant, vous pouvez considérer Foo comme un alias de type pour le type de votre choix (par exemple std::string).

Il existe cependant deux cas principaux dans lesquels le passage par référence non constante peut être le meilleur choix.

Premièrement, utilisez le passage par référence non constante lorsqu'un paramètre est un paramètre d'entrée-sortie. Comme nous transmettons déjà l'objet que nous devons récupérer, il est souvent plus simple et plus performant de simplement le modifier.

void someFcn(Foo& inout)
{
    // modifier inout
}

int main()
{
    Foo foo{};
    someFcn(foo); // foo est modifié après cet appel, ce qui n'est peut-être pas évident

    return 0;
}

Un bon nom de fonction peut aider :

void modifyFoo(Foo& inout)
{
    // modifier inout
}

int main()
{
    Foo foo{};
    modifyFoo(foo); // foo est modifié après cet appel, ce qui est un peu plus évident

    return 0;
}

L'alternative consiste à passer l'objet par valeur ou par référence constante (comme d'habitude) et à renvoyer un nouvel objet par valeur, que l'appelant peut ensuite réaffecter à l'objet d'origine :

Foo someFcn(const Foo& in)
{
    Foo foo { in }; // copie ici
    // modifier foo
    return foo;
}

int main()
{
    Foo foo{};
    foo = someFcn(foo); // il est évident que foo est modifié, mais une copie supplémentaire est faite ici

    return 0;
}

Cette approche a l'avantage d'utiliser une syntaxe de retour plus conventionnelle, mais elle nécessite 2 copies supplémentaires (le compilateur peut parfois en supprimer une).

Deuxièmement, utilisez le passage par référence non constante lorsqu'une fonction devrait sinon renvoyer un objet par valeur, mais que copier cet objet est extrêmement coûteux. C'est particulièrement vrai si la fonction est appelée très souvent dans une section de code critique pour les performances.

void generateExpensiveFoo(Foo& out)
{
    // modifier out
}

int main()
{
    Foo foo{};
    generateExpensiveFoo(foo); // foo est modifié après cet appel

    return 0;
}

Pour les lecteurs avancés

L'exemple le plus courant de ce cas est celui où une fonction doit remplir avec des données un grand tableau de style C ou un std::array dont le type d'élément est coûteux à copier. Nous étudierons les tableaux dans un chapitre ultérieur.

Cela dit, les objets sont rarement assez coûteux à copier pour que le recours à des méthodes non conventionnelles de renvoi de ces objets en vaille la peine.
